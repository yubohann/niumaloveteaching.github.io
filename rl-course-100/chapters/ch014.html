第一篇 · 策略梯度与 PPO

第 014 章：PPO的对抗性扰动鲁棒性

训练两个 CartPole 策略（标准版与噪声增强版），再用高斯噪声与 FGSM 对抗扰动两套"体检"测出各自的脆弱边界：一次把鲁棒性从形容词变成数字。

  • 主题：鲁棒性评估 / 对抗攻击
  • 关键公式：ℓ = −log πθ(a*|o)，δ = ε·sign(∇oℓ)
  • 预计学时：60 分钟
  • 前置章节：第 013 章

学习目标

  • 理解"干净环境成绩"与"扰动环境成绩"的差距：策略对观测的敏感度就是鲁棒性边界。
  • 实现高斯观测噪声评估与 FGSM 风格对抗评估，量化两种扰动的杀伤力。
  • 实现噪声增强训练（训练时给观测加高斯噪声），观察它对干净成绩与扰动成绩的双向影响。
  • 对比随机噪声与梯度对抗扰动的破坏效率，理解"最坏情况"评估的意义。
  • 建立交付习惯：上线前做鲁棒性体检，报告"损失 100 分对应的扰动档位"这类可比较指标。

背景与动机

仿真里训练、现实里部署，观测永远会有传感器噪声、标定误差、甚至恶意扰动。一个在 CartPole 上考 500 分的策略，可能被幅度只有 0.05 的观测噪声打回 300 分，高分不等于可靠。更麻烦的是，随机噪声还不是最坏情况：攻击者可以顺着策略的梯度方向扰动观测，用同样甚至更小的幅度造成更大的破坏，这就是对抗攻击。

本章做一件事：把"鲁棒性"变成一张体检表。先训练两个策略，一个标准、一个在观测噪声下训练（数据增强式防御），然后对两者扫两套扰动档位。你会看到三个规律：随机噪声的破坏随 σ 平滑增长；对抗扰动的破坏效率高一个档次；噪声增强训练用一点干净成绩换取大量鲁棒性。这套评估方法可以直接迁移到 SAC（第 058、059 章还会回到这个话题）。

核心原理

1. 策略敏感度

策略是从观测到动作分布的映射，鲁棒性描述的是它在输入扰动下的稳定性：

干净成绩：J(θ) = 𝔼[G | o]，　扰动成绩：Jδ(θ) = 𝔼[G | o + δ]，　‖δ‖ ≤ ε

δ 有两种来源：随机（传感器噪声，各维独立高斯）与对抗（攻击者选择的最坏方向）。同一幅度 ε 下，两者的破坏力完全不是一个量级，因为对抗扰动沿着"最容易改变动作"的方向走。评估时要分开测，不能互相替代。

幅度 ε 的含义要按观测尺度校对（以 CartPole-v1 为例）：

维度观测范围ε=0.05 的占比物理含义
小车位置 x±4.8约 1.0%小位移误差
小车速度实际约 ±2～3约 2%～3%轻微测速误差
杆角 θ±0.418 rad（±24°）12.0%0.05 rad ≈ 2.9°，约为倾角容差 12° 的四分之一
角速度实际约 ±3约 1.7%轻微陀螺噪声

同一句"ε=0.05"，在位置维度是 1% 的小扰动，在角度维度却接近终止容差的四分之一。每步独立重抽噪声时，θ 上的扰动会叠加在真实角度上，把尚未到终止角的回合提前推过 12° 门槛。这一行账解释了为什么 0.05 能把未防御策略从 500 分打到 300 分以下，也解释了为什么跨环境比较前必须做观测归一化。

把扰动放到归一化空间里记账，结论会更干净：按第 008 章的归一化（除以观测空间上界），θ 除以 0.418 后，原始 0.05 rad 相当于归一化空间的 0.12；而位置维的 0.05 只相当于 0.010。也就是说"每维都加 0.05"在归一化视角下其实是"角度维 0.12、位置维 0.01"的不均匀攻击。写体检报告时，建议同时给出原始单位与归一化单位两条刻度，跨环境、跨传感器比较只认后者。

2. FGSM 对抗扰动

做一步梯度上升、让策略对"当前贪心动作"更不自信：

ℓ(o) = − log πθ(a* | o)，　δ = ε · sign( ∇o ℓ(o) )，　a″ = argmax πθ(· | o + δ) a* 是未扰动时的贪心动作；评估用 argmax 保持确定性口径

这是最经典的快速梯度符号法（Fast Gradient Sign Method, FGSM）。注意它是白盒攻击：需要策略参数和梯度。评估白盒攻击衡量的是"最坏情况上界"，业务上对"黑盒扰动"（如传感器漂移）更关心随机噪声档位。本章两种都测。

FGSM 可以从一阶展开直接推出来。取损失 ℓ(o)，在 o 处线性化：ℓ(o+δ) ≈ ℓ(o) + ⟨∇ℓ, δ⟩，最大化时只需管第二项。两个常用约束各有标准答案：‖δ‖∞ ≤ ε（每维独立限幅）下最优方向是 δ = ε·sign(∇ℓ)；‖δ‖2 ≤ ε（总长度受限）下最优方向是 δ = ε·∇ℓ/‖∇ℓ‖。观测各维单位不同，工程默认采用 L∞ 形式，每维都走满 ε，这就是 sign 的来历。

数值算例：同一决策边界下两种扰动的命中率

抽象成一个二选一决策：动作由差值 z1 − z0 = w·o 的符号决定，取 w = [1, 2]、当前边界间距 m = 0.05（"微弱领先"的临界状态）。对抗扰动：ε=0.05 的 L∞ 扰动最多能把 w·o 改变 ε‖w‖1 = 0.05×3 = 0.15，超过 0.05 的间距，所以 FGSM 在这个点上保证翻转动作。一般地，只要 m ≤ ε‖w‖1，FGSM 就能把决策推过边界。

随机扰动：δ ~ N(0, 0.05²I) 时间距的改变量服从 N(0, σ²‖w‖²)，标准差 0.05×√5 ≈ 0.112；翻转概率 = Φ(−0.05/0.112) = Φ(−0.447) ≈ 0.327。同样的幅度预算，对抗扰动在这个点每步必中，随机噪声只有约三分之一的概率改变这一步的决策，下一秒抽到的是新方向、不做累积。这个最小算例就是"对抗破坏力高一档"的可复现版本。

维度随机噪声FGSM 对抗扰动
扰动方向各向同性随机沿降低贪心动作概率的梯度符号
所需信息仅需统计分布策略参数与梯度（白盒）
同幅度破坏（算例）每步约 33% 概率翻转间距不超过 ε‖w‖1 时保证翻转
多步累积方向独立、互相抵消每步重新定向，持续朝弱点推进
防御主力噪声增强训练对抗训练（PGD）配合噪声增强

3. 噪声增强训练为什么有效

训练时给观测加噪声，等于在每个观测点附近强制策略输出一致的动作：

maxθ 𝔼o, δ~N(0,σ²)[ J(θ; o+δ) ]

这在函数空间里是"平滑化"：决策边界远离数据点，策略对局部扰动不敏感。代价是干净环境的精细度下降，把边界从"贴着数据切"推远，必然牺牲一点最优性。这就是鲁棒性与性能的经典权衡。本章用 σ=0.05 的中等噪声：干净成绩通常掉 10～40 分，但噪声档位下的成绩能提升 100 分以上。

噪声增强也有失效模式：σ 越加越大时，策略面临一个两难，信观测则被噪声牵着走，不信观测则等于放弃状态信息。当 σ 超过任务可辨识的尺度后，策略会被推向"忽略输入"的退化解，表现为两条曲线同时下沉：干净成绩崩掉，扰动成绩也不再上升。判据很直接：把 σtrain 从小到大排开，找"扰动档位成绩开始回落"的位置，训练噪声取在该点之前；本章 0.05 处于安全区间，0.2 就在危险边缘。

4. FGSM 的适用边界与更细的度量

FGSM 建立在一阶线性化上，有两条边界。其一，ε 太大时线性近似失效，sign 方向不再是真正的最坏方向（对 4 维 CartPole，小到中档 ε 下近似质量足够，这也是本章用它做体检的原因）；其二，ε 小到不能翻转动作时，FGSM 的破坏体现在"置信度下降"与多步偏移上，单看单步回报可能没有差别。所以体检表除了回报曲线，还应带一条动作翻转率：扰动前后贪心动作不一致的步占比。它对小 ε 更灵敏，也能把"攻击在起作用"与"环境正常终止"分开。威胁模型也要交代清楚：FGSM 假设攻击者拿得到策略梯度；拿不到梯度的场景里，随机噪声档位才是正确的评估口径，两条曲线各有各的回答，不能互相替代。

5. 对抗训练与随机噪声的边界

对抗训练（用 FGSM/PGD 生成的对抗样本训练）能把最坏情况也压下去，但计算成本高、且容易过拟合到特定攻击算法。实践中常组合使用：随机噪声增强为主（便宜），对抗训练用于关键安全场景。第 059 章会回到对抗防御的系统方法。

两条体检曲线最终要合成一张决策表：

部署场景主要威胁验收线（示例）训练侧动作
实验室复现无扰动干净成绩为准标准训练
常规传感器环境随机噪声 σ≤0.03σ=0.03 档损失不超过 50 分标准训练即可，上线前跑体检
噪声较大的现场随机噪声 σ≤0.1σ=0.1 档仍达标定成绩的七成噪声增强训练（σtrain=0.03～0.05）
安全敏感、对手可控输入白盒对抗 ε≤0.05ε=0.05 档翻转率低于阈值对抗训练 + 随机噪声增强

表的用法是"先定威胁模型，再选训练方案，最后用对应档位验收"，顺序反了就会出现两种典型错误：对小噪声场景做昂贵对抗训练（白付干净成绩），或对可控输入场景只做随机噪声体检（漏掉最坏情况）。

数据流

每个 arm 一条完整训练：重设种子 → 采样 2048 步（noisy 臂在"喂网络前"加高斯噪声，存入 buffer 的是策略看到的加噪观测）→ GAE → 10 epochs 更新 → 跑满 8 万步、保存权重。随后进入体检：对每个权重依次跑噪声曲线（σ 六档）与对抗曲线（ε 五档），最后输出"损失 100 分对应的档位"。

评估与训练共享一条管线，但噪声来源不同

训练时的噪声是"数据增强"，进入 buffer、参与梯度；评估时的噪声只是"体检"，不进入任何更新。两者的代码都在加噪声，但一个在 collect_rollout、一个在 evaluate_noise，互不干扰。把这两条路径写混（比如评估噪声被存进 buffer）会静默污染训练，务必分清。

评估回合数与统计噪声

体检数字本身带采样噪声，先算一次换算：若单回合回报的标准差按 100 分计，10 个回合的均值标准误约为 32 分（100/√10）。这意味着两条曲线相差不足 30 分的档位比较不可靠，低档位（0.01、0.03）尤其如此；要把分辨做到 10 分以内，评估回合数需要约 100 个。实用做法：粗扫曲线用 10 回合抓大趋势，写进结论的"损失 100 分对应档位"用 30～50 回合复测，并固定同一批评估回合的种子。报告里同时给出训练末期成绩与干净评估成绩，两者不一致时先查评估口径再下结论。

关键代码与解读

片段 1：噪声增强，策略看到什么，就学什么

    for _ in range(steps):
        if noise_sigma > 0.0:
            noise = rng.normal(0.0, noise_sigma, size=obs_t.shape).astype(np.float32)
            net_in = obs_t + torch.as_tensor(noise, device=device)   # 策略看到加噪观测

解读：（1）加噪的位置在"环境交互"与"网络前向"之间：环境用真实观测推进（env.step 拿到的还是真实状态），网络只看到加噪版本，这模拟"传感器有噪声但世界是真的"。（2）buffer 里存 net_in（策略看到的加噪观测），不存原始观测：更新时用同一加噪观测重算 log π，比率才自洽（与第 008 章"存网络输入"的原则一致）。（3）噪声用 rng（NumPy 的独立随机流）：与 torch 的全局随机流分开，保证"训练噪声的抽法"可独立复现，也避免污染动作采样的随机性。（4）换法会怎样：如果加噪加在"存 buffer 之后"（存干净观测），更新时网络看到的分布与采样时不同，比率被拉偏；如果给 env.step 也加噪（改变环境），那就是另一类问题了。

片段 2：随机噪声体检

@torch.no_grad()
def evaluate_noise(env, net, episodes, device, sigma, rng):
    """在观测上叠加高斯噪声，检验统计意义上的鲁棒性。"""
    returns = []
    for _ in range(episodes):
        obs, _ = env.reset()
        done = False
        ep_ret = 0.0
        while not done:
            obs_t = to_tensor(obs, device)
            if sigma > 0.0:
                noise = rng.normal(0.0, sigma, size=obs_t.shape).astype(np.float32)
                obs_t = obs_t + torch.as_tensor(noise, device=device)
            logits, _ = net(obs_t)
            action = int(torch.argmax(logits, dim=-1).item())
            obs, r, terminated, truncated, _ = env.step(action)
            ep_ret += r
            done = terminated or truncated
        returns.append(ep_ret)
    return float(np.mean(returns))

解读：（1）噪声加在每一步的观测上：同一回合内每个状态都是独立扰动，这正是"传感器噪声"的统计模型。（2）动作取 argmax（贪婪）：评估必须确定性，否则 σ 的噪声会与动作采样的噪声混在一起，无法归因。（3）传入的 rng 在 arm 循环外按 seed+99 重建：两个策略遇到"形状相同"的噪声序列（不完全是逐值相同，因为各档位调用次数不同），成绩差异更接近策略本身的差异。（4）@torch.no_grad()：纯前向，不需要梯度；这也是与下一个片段（对抗评估）的对比点。

片段 3：FGSM 对抗体检，评估也要梯度

        while not done:
            obs_t = torch.as_tensor(obs, dtype=torch.float32, device=device).unsqueeze(0)
            obs_t.requires_grad_(True)          # 对观测开梯度：白盒攻击的关键
            logits, _ = net(obs_t)
            with torch.no_grad():
                greedy = int(torch.argmax(logits, dim=-1).item())   # 未扰动时的贪心动作
            loss = -F.log_softmax(logits, dim=-1)[0, greedy]   # 想让该动作概率下降
            grad = torch.autograd.grad(loss, obs_t)[0]         # ∂loss/∂obs
            with torch.no_grad():
                obs_adv = obs_t + eps * torch.sign(grad)       # FGSM：沿 sign 方向走 ε
                logits_adv, _ = net(obs_adv)
                action = int(torch.argmax(logits_adv, dim=-1).item())
            obs, r, terminated, truncated, _ = env.step(action)
            ep_ret += r
            done = terminated or truncated

解读：（1）这个函数没有 @torch.no_grad()，它需要一次真正的反向：requires_grad_(True) 开在观测上（不是参数上），torch.autograd.grad(loss, obs_t) 只求观测梯度，不建参数梯度。（2）loss 的设计目标是"降低已选贪心动作的对数概率"：log_softmax(logits)[0, greedy] 取的是贪心动作的对数概率，取负号后上升方向就是"让策略动摇"的方向。（3）扰动只看 sign(grad)：每维只取正负号、幅度统一为 ε，这是 FGSM 的"符号法"，在 ‖δ‖∞ ≤ ε 约束下走一步最强的方向。（4）求完梯度绝不要 optimizer.step()：这里只是评估，参数一个都不能动（常见坑里会强调）。决策用扰动后观测的 argmax，与干净评估同一口径。（5）它是白盒：需要策略梯度；这也是理解"对抗扰动为什么强"的关键，攻击者比随机噪声更"聪明"。

        adv_curve = []
        for eps in adv_levels:
            r = evaluate_adversarial(gym.make("CartPole-v1"), net, args.eval_episodes,
                                     torch.device("cpu"), eps)
            adv_curve.append((eps, r))
        report[arm] = {"noise": noise_curve, "adv": adv_curve,
                       "train_tail": float(np.mean(train_tail))}

        os.makedirs(args.save_dir, exist_ok=True)
        torch.save(net.state_dict(), os.path.join(args.save_dir, f"{arm}.pt"))

解读：（1）每个 arm 依次扫完所有档位：噪声曲线回答"传感器漂移多大时策略会崩"，对抗曲线回答"攻击者有多容易打崩它"。两条曲线共同构成体检表。（2）每档评估现场 gym.make 一个新环境：避免评估之间共享状态；评估回合数（默认 10）是效率与噪声的折中。（3）report 同时带 train_tail（训练末期成绩）：报告里"干净成绩"与"训练成绩"可能略有差异，两者都保留才诚实。（4）权重保存成 plain.pt / noisy.pt：体检结论要可复现，拿到模型文件，任何人都能重跑这段评估核对数字。

完整可运行脚本（附录）：code/ch014.py

python code/ch014.py                 # 2 个训练 × 两套体检，CPU 约 4–7 分钟
python code/ch014.py --quick         # 各 1 万步、少量档位，约 30–60 秒
python code/ch014.py --train-noise 0.1   # 加大训练噪声，看权衡的极端

预期结论（以实跑为准）：plain 策略在 σ=0.05 随机噪声下掉到 350～450、在 ε=0.05 对抗扰动下掉到 100～300，同幅度下对抗扰动的破坏力是随机噪声的数倍；noisy 策略干净成绩低 10～40 分，但中高扰动档位普遍高出 100 分以上，损失 100 分对应的 σ 从约 0.05 推到 0.1～0.2。若 noisy 的干净成绩掉超过 60 分，说明训练噪声偏大，可降到 0.02～0.03 再权衡。别把 CartPole 的具体数字外推，高维观测下对抗破坏通常更严重，本章的目标是学会"如何测"。

常见坑

  • 对抗评估里调用 optimizer.step 或忘了切断参数更新：求观测梯度的同时更新了策略参数，评估会"边测边学"。只对 obs_t 求导、绝不调用 optimizer。
  • 评估口径不一致：干净用贪婪、对抗用采样（或反之），两个数字不可比。全章统一 argmax。
  • 把 ε 当成各维等价的幅度：CartPole 观测的四维尺度不同（位置到 ±4.8、速度到 ±2），在原始空间里 uniform 的 ε 实际更偏向大尺度维度。跨环境比较前先做观测归一化（第 008 章）。
  • 训练噪声直接照搬评估档位：评估想测 σ=0.2 就用 0.2 训练，会导致干净成绩崩掉。训练噪声建议取"目标鲁棒档位的一半或更低"，逐步加码。
  • 把评估噪声写进 buffer：噪声增强只在 collect_rollout 里做，评估噪声绝不进训练数据；写混了训练被静默污染，而且很难从日志发现。

练习与思考

  1. 把 --train-noise 依次设为 0.0 / 0.02 / 0.05 / 0.1，画出"干净成绩 vs 鲁棒成绩"的权衡曲线。★
    提示
    只需改命令行、记录报告的干净列与 σ=0.1 列。预期是一条向下倾斜的权衡曲线：噪声越大，干净成绩越低、扰动成绩越高，会有一个"性价比"拐点。
  2. 实现"动作翻转率"指标：统计对抗扰动前后贪心动作发生改变的比例，观察 ε 与翻转率、回报的关系。★
    提示
    在 evaluate_adversarial 内同时记录干净贪心与扰动后贪心的差异。翻转率是比回报更细的攻击效果度量，低 ε 时更灵敏。
  3. 把单步 FGSM 换成正弦迭代的多步 PGD（2～4 步、每步 ε/步数），比较同样的总扰动预算下的破坏力。★★
    提示
    每一步都重新求梯度、累加 sign、投影回 ε 球（clip(delta, -eps, eps)）。PGD 更强，会进一步拉大 plain 与 noisy 的差距，但 noisy 的优势依然存在。
  4. 实现对抗训练：采样时用一次 FGSM 生成扰动观测加入 buffer（替换随机噪声增强），再对比它与随机噪声增强的鲁棒/干净权衡。★★★
    提示
    在 collect_rollout 里对 net_in 求一次对抗扰动（需要保留梯度），成本约翻倍。注意求完梯度后 zero_grad()，别污染训练；对抗训练通常能压低最坏情况，但干净成绩掉得更多。
  5. 用 10 行以内的脚本验证本节的翻转概率公式：构造 o0 使 w·o0 = 0.05（w=[1,2]），重复 10000 次加入 σ=0.05 高斯噪声统计翻转率，应接近 0.327；对同一点做一次 ε=0.05 的 FGSM（线性模型梯度就是 w），翻转率应为 1。★★
    提示
    翻转判据就是 sign(w@o) 变号；FGSM 扰动是 eps*sign(w)。若实测随机翻转率偏离 0.33，检查是否把噪声加在了两个维度上（‖w‖ 的定义含两维）以及 o0 的间距是否精确为 0.05。

小结

  • 鲁棒性是可测量的：固定贪婪口径，扫描随机噪声 σ 与对抗扰动 ε，得到两条退化曲线。
  • FGSM 对抗扰动沿着降低贪心动作概率的梯度方向走一步（sign·ε），同幅度下破坏力远大于随机噪声。
  • 噪声增强训练用 10～40 分的干净成绩换取中高扰动档位 100 分以上的提升；损失 100 分对应的 σ 可被推远 2～4 倍。
  • 部署建议：训练时加入适量观测噪声；上线前把两张体检表写进报告；关键场景再用对抗训练加固。
  • 下一章从"抗扰动"转向"学更快"：先在小任务上预训练，再把表征迁移到更难的任务，验证迁移学习能省下多少样本。
