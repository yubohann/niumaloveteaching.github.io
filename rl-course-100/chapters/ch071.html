第 071 章：多智能体PPO：通信机制

把队友的可见半径压到 0.4，"看不见"的时候怎么避让？本章给共享策略加一条会说话的通道：每个智能体广播一个 2 维意图消息，队友把它拼进自己的输入，消息头用位移预测自监督训练。

  • 主题：多智能体通信 / 意图消息
  • 关键公式：mt = fθ(ot, mt−1−i)；Lmsg = ‖mti − (pt+1i − pti)‖2
  • 预计学时：55 分钟
  • 前置章节：第 070 章

学习目标

  • 理解通信在多智能体系统中的作用：把"当前看不见的信息"以低成本提前传给队友。
  • 设计并实现一个最小可用的通信协议：每个智能体输出动作的同时广播低维意图消息。
  • 掌握消息头的一种训练方式，自监督位移预测，并理解它与端到端可微通信的差别。
  • 在受限感知环境下对照有通信与无通信两种配置，重点比较碰撞次数与末距。
  • 认识通信的工程约束：带宽（消息维度）、可靠性（丢包）与训练方式（谁来监督消息）。

背景与动机

第 070 章里每个智能体能看到所有队友的相对位置，避让只需要"看"。但如果传感器有范围限制，机器人只有前向摄像头、无人机通信距离有限，远处的队友就成了"隐身的障碍物"：你看不见它，它也不知道你要往哪走，碰撞往往发生在彼此进入视野之前的那一瞬间。

人类解决这类问题的办法是打手势、按喇叭、喊一声：提前把意图广播出去，让对方预判。多智能体强化学习里的通信机制就是这一思想的算法版本：每个智能体输出动作的同时，附带发出一条低维消息；队友把收到的消息拼进自己的输入。本章刻意选择"意图消息"（我下一步准备往哪走）作为内容，因为在这类避障任务里，意图比身份、坐标更有价值，队友需要的是"预判你"：提前知道你的去向，避让才有依据。

本章沿用第 070 章的共享策略，只加一条消息通道：两种配置（off / on）除通信外完全一致，感知半径统一压到 0.4，用碰撞与末距的变化衡量消息的价值。

核心原理

1. 通信的形式化

带通信的策略输入从"只有自己的观测"扩展为"自己的观测 + 收到的队友消息"：

ati ∼ πθ(· | oti, mt−1−i)    广播：mti = fθ(oti, mt−1−i) mt−1−i 表示第 t 步时手上持有的、其他智能体在上一步发出的消息；动作与消息在同一时刻产生，消息由共享网络的另一个头输出

消息与动作由同一个网络躯干产生（多一个消息头），因此消息天然是"策略对自己行为的摘要"，与动作一致。因为所有智能体同时行动，第 t 步收到的必然是 t−1 步广播的消息，这一点在实现里表现为"消息延迟一步使用"：先收集，下一步再用。初值与回合开始时的消息用零向量填充。

2. 消息头怎么训练：自监督位移预测

理想情况下，消息对回报的贡献应该通过"影响队友动作"这条路径端到端回传。但那需要把梯度沿时间展开（类似 RNN 的 BPTT），而 PPO 的比率损失只覆盖单步，消息头拿不到有效梯度，这条路径在教学规模内不好实现。本章采用一个工程上常用的替代方案：让消息预测自己下一步的真实位移，用监督信号训练消息头：

Lmsg = ‖ mti − (pt+1i − pti) ‖2 p 是智能体位置；pt+1−pt 是本步实际发生的位移，环境里天然可得，不需要额外标注

这样消息在语义上被固定为"我接下来会往哪移动"（这也是队友最需要的信息），消费端（把消息拼进输入后如何使用）则由策略梯度自由学习。两边分工明确：消息内容靠自监督，消息用途靠强化学习。由于消息头与策略共享躯干，位移预测的梯度也会塑造特征表示，但主损失仍是 PPO，--comm-coef 控制两者的权重。

3. 感知缺口与消息价值

队友在感知半径之外时，本地观测里的相对位置被置零，这不属于"有噪声"的情形，它代表的是信息的永久缺失。消息通道不受距离限制（本章假设理想信道），因此消息的价值随感知半径缩小而上升：半径越小，本地观测的盲区越大，消息的边际价值越高；如果半径足够大（比如 3.0 覆盖整个方格），通信几乎没有增量价值，甚至因为多了一个需要训练的模块而略微更差。这个单调关系会在练习里被验证。

4. 消息与动作为什么要"同时"产生

如果先决定动作、再让消息去"解释"动作，消息就只是冗余的动作编码；本章让两者从同一个隐藏层 h 分支出来：动作头管"做什么"，消息头管"告诉别人我要做什么（位移形式）"。这样既保持了信息充分，又让消息的语义被自监督锚定在"位移"上。消息经过 tanh 压缩再乘 msg_scale=0.4，量级与常见单步位移匹配（随机策略下 95% 的位移在 0.28 以内、实测最大约 0.5），避免监督目标长期"够不着"；持续加速滑行时位移会超过 0.4，MSE 因此留有一个小的截断下限。

实现思路与设计

数据流

采样一步：build_policy_input(obs, messages) 拼出输入 → 共享策略一次性输出动作、logp、新消息 → 环境步进 → 记录本步位移 disp = p′ − p 作为监督目标 → messages = msg（延迟一步交给下一轮）。更新时：中央批评家照旧；策略大损失 = PPO 裁剪损失 + comm_coef × 消息 MSE。两者共享同一组参数，一次反传。

与第 070 章的差异点

① 环境加入感知半径制造信息缺口；② 策略输入增加队友消息（无通信时输入不变）；③ 新增消息头与自监督损失；④ 采样/评估都要维护"消息延迟一步"的时序。--comm off 的路径与第 070 章等价的共享策略，保证对照公平。第 072 章去掉消息，转而研究策略对"角色置换"的对称性。

关键代码与解读

片段 1：感知半径，把队友"隐身"

    def _obs(self):
        obs = np.zeros((self.n_agents, self.obs_dim), np.float32)
        for i in range(self.n_agents):
            rel_land = (self.landmarks - self.pos[i]).ravel()   # 地标始终全可见
            rel_others = []
            for j in range(self.n_agents):
                if j == i:
                    continue
                d = self.pos[j] - self.pos[i]
                if float(np.linalg.norm(d)) > self.sense_radius:
                    d = np.zeros(2, np.float32)   # 超出感知半径：队友"隐身"
                rel_others.append(d)
            others = np.concatenate(rel_others) if rel_others else np.zeros(0, np.float32)
            obs[i] = np.concatenate([self.pos[i], self.vel[i], rel_land, others])
        return obs

解读：只有三行与第 068 章不同，但它们制造了整个章节的动机。（1）判断条件 norm(d) > sense_radius 把远队友的相对位置置零，不保留距离、不保留方向，等于告诉网络"这里什么都没有"。置零是为了制造干净的、可对照的"信息缺口"；加噪声只会让信息变模糊，缺口范围无法同等控制。（2）地标保持全可见：任务主体（去地标）仍然可解，通信只影响协调（避让、分工），这样两种配置的回报差距才归因于协调能力。（3）感知半径 0.4 在 1×1 方格里相当苛刻：两个智能体平均距离约 0.3~0.4，意味着大量时间步里队友是"隐身"的，信息缺口真实存在，通信才有戏可唱。

片段 2：带消息头的共享策略

class SharedPolicy(nn.Module):
    """共享策略：输入=局部观测(+收到的队友消息)，输出=动作分布 + 意图消息。"""

    def __init__(self, obs_dim, act_dim, n_agents, hidden=64,
                 use_comm=True, msg_dim=2, msg_scale=0.4):
        super().__init__()
        self.use_comm = use_comm
        self.msg_dim = msg_dim
        self.msg_scale = msg_scale
        in_dim = obs_dim + (n_agents - 1) * msg_dim if use_comm else obs_dim
        self.in_dim = in_dim
        self.body = nn.Sequential(nn.Linear(in_dim, hidden), nn.Tanh(),
                                  nn.Linear(hidden, hidden), nn.Tanh())
        self.mean = nn.Linear(hidden, act_dim)
        self.log_std = nn.Parameter(torch.full((act_dim,), -0.7))
        if use_comm:
            self.msg_head = nn.Linear(hidden, msg_dim)   # 消息头与动作头共享躯干

    def forward(self, x):
        h = self.body(x)
        mean = self.mean(h)
        log_std = torch.clamp(self.log_std, -4.0, 0.5).expand_as(mean)
        msg = torch.tanh(self.msg_head(h)) * self.msg_scale if self.use_comm else None
        return mean, log_std, msg

解读：共享策略的"多出来的部分"只有这几行。（1）输入宽度 = obs_dim + (N−1)×msg_dim：每个智能体收 N−1 条消息（不含自己的）。无通信时 in_dim = obs_dim，网络结构与第 070 章逐位一致，两种配置共享同一份模型代码。（2）消息头 msg_head 从隐藏层 h 分支，与动作头平级：动作和消息"同源不同枝"，这就是"消息是策略对自身行为的摘要"的结构保证。（3）tanh(·) × msg_scale 把消息限制在 ±0.4：监督目标是单步位移，其量级由动力学决定（速度有上限），若不压缩，MSE 训练会先跟量纲搏斗。0.4 是对"单步最大位移"的数量级估计，练习里你可以把它调到 0.2 或 0.8 观察训练初期的 MSE。（4）无通信时 forward 返回 msg=None，调用方（act_step/update）用 None 判断走哪条分支，避免为 off 版本写两套代码。

片段 3：拼接输入与"消息延迟一步"

def build_policy_input(obs, messages, use_comm, n_agents):
    """把"自己的观测 + 收到的队友消息"拼成策略输入。"""
    if not use_comm:
        return obs.astype(np.float32)
    rows = []
    for i in range(n_agents):
        parts = [obs[i]]
        for j in range(n_agents):
            if j != i:
                parts.append(messages[j])   # 只收别人的消息，回避自身
        rows.append(np.concatenate(parts))
    return np.asarray(rows, dtype=np.float32)

    # ---- 采样循环中的时序（取自 collect，逐行连续）----
    for _ in range(steps_agent // n):
        global_state = env.global_state()
        x, actions, logps_i, value, msg = mgr.act_step(obs, messages, global_state)
        next_obs, per_r, team_r, done, _ = env.step(actions)
        disp = next_obs[:, :2] - obs[:, :2]   # 本步实际位移（消息的监督目标）
        xs.append(x)
        acts.append(actions)
        logps.append(logps_i)
        msgs_pred.append(msg)
        disps.append(disp)
        states.append(global_state)
        team_rews.append(team_r)
        values.append(value)
        cuts.append(float(done))
        messages = msg                        # 本步广播的消息，下一步才被使用

解读：两段代码合起来回答"消息从哪来、到哪去"。（1）build_policy_input 按智能体逐个拼接：第 i 行 = 自己的观测 + 其他每人的一条消息，顺序与输入宽度公式严格对应。拼接顺序（j 从 0 到 N−1、跳过 i）必须与网络训练时保持一致，它是隐式的"协议约定"，写错不会报错但会破坏消息语义。（2）消息不含自己：发给自己的消息没有信息量，省一个 msg_dim 的输入宽度。（3）时序是通信实现里最烧脑的部分：messages = msg 让本步产生的消息在下一轮拼接时生效，与"所有智能体同时行动、只能收到上一步消息"的物理设定一致。回合结束时消息清零（脚本中 messages = np.zeros((n, msg_dim))），避免把上一回合的意图带进新回合。（4）disp 在环境步进后立刻计算，是唯一一处"消息监督目标"的产生地，消息预测的就是它。

片段 4：策略损失与消息自监督损失的合流

                mean, log_std, msg = self.policy(x_flat[mb])   # 一次前向同时出动作与消息
                dist = Normal(mean, log_std.exp())
                logp = dist.log_prob(act_flat[mb]).sum(-1)
                ratio = torch.exp(logp - logp_flat[mb])
                surr1 = ratio * adv_flat[mb]
                surr2 = torch.clamp(ratio, 1 - args.clip, 1 + args.clip) * adv_flat[mb]
                policy_loss = -torch.min(surr1, surr2).mean()
                if self.use_comm:
                    aux_loss = F.mse_loss(msg, disp_flat[mb])  # 消息 vs 真实位移
                    loss = policy_loss + args.comm_coef * aux_loss
                else:
                    aux_loss = torch.tensor(0.0)
                    loss = policy_loss
                self.policy_opt.zero_grad()
                loss.backward()                                # 两类梯度一起回传
                nn.utils.clip_grad_norm_(self.policy.parameters(), 0.5)

解读：这是"消息内容靠自监督、消息用途靠强化学习"落到代码上的样子。（1）注意 x_flat：拼好的输入被展平成 (T×N, in_dim)，时间维与智能体维合并，共享策略不需要区分"这条转移属于哪个智能体"，这正是参数共享的美感；adv_flat 由团队优势按时间重复 N 次得到，与第 070 章的 np.tile 口径一致。（2）一次前向同时产出 mean 与 msg，两类损失共享同一个躯干：消息 MSE 的梯度会塑造特征表示，但量级由 comm_coef 平衡。默认 1.0 是"消息和策略各占一张票"，若策略学习被拖慢可以降到 0.2~0.5。（3）无通信分支里 aux_loss 记 0：日志格式不变，两种配置可直接并排读。（4）梯度裁剪作用于整个 self.policy.parameters()（含消息头与动作头），防止任一头的偶发大步污染共享躯干，参数共享的风险在此同样适用。

常见坑

  • 消息没有延迟一步：同一时刻用"刚产生还没发出去的消息"，等于让智能体偷看队友的当下决策，训练指标虚高、物理上不可能实现。本脚本用 messages = msg 的时序切断这次偷看。
  • 回合边界忘了清零消息：新回合沿用旧回合最后一步的消息，会把无关意图带进来。重置环境时同步 messages = zeros。
  • 消息拼接顺序与训练不一致：build_policy_input 里 j 的顺序、跳过自己、拼接位置必须固定；抖动顺序会让消息语义漂移，且很难通过日志发现。
  • 把无通信版输入宽度也加宽：off 配置必须保持 in_dim = obs_dim，否则两种配置的网络容量不同，对照失去意义。
  • 以为消息能突破任务上限：消息只传递"预判"，不改变可观测的任务要素。期望值要放在"更少碰撞、更平滑的协调"上；回报暴涨并不现实。

  4. 把消息的监督目标从"位移"改成"下一步动作"（disp 换成 act），比较两种消息语义下的协调表现。为什么位移可能更好？★★
    提示
    动作是策略的输出、位移是环境的结果；在有惯性（damping=0.9）的系统里，位移更接近"你会去哪"的事实。改动点在 collect 的 disp 一行。
  5. 设计一个"丢包"实验：以概率 p 把收到的消息随机置零（如 p=0.3），看通信的鲁棒性。训练与评估都要加同样的噪声吗？为什么？★★★
    提示
    在 build_policy_input 里对 messages[j] 以概率置零；训练与评估必须一致（否则评估分布外）。讨论：理想信道假设被打破后，策略是否会学会"不依赖消息"的退化，这与带宽、成本的设计问题相连。

小结

  • 通信把"看不见的信息"提前传给队友；本章协议：动作与消息同源产生，队友消息拼进输入，延迟一步生效。
  • 消息头用自监督位移预测训练：Lmsg = MSE(消息, 真实位移)，内容靠监督、用途靠 RL。
  • 感知半径制造信息缺口，消息的价值随之上升；半径大到全覆盖时通信无增益甚至略负。
  • 实现要点：输入宽度随通信开关变化、拼接顺序固定、回合边界清零消息、评估与训练时序一致。
  • 本章预期：通信主要降低碰撞、平滑协调，回报上限的抬升有限，这是"信息型机制"的合理预期。
  • 下一章拆掉消息，研究另一种对称性：策略对"角色置换"是否等价，把智能体编号打乱，性能会掉吗？
