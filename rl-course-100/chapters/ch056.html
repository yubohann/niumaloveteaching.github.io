第二篇 · 离策略方法与 SAC

第 056 章：SAC的元学习

用 Reptile 在五个重力参数（g = 6～14）的摆杆任务上训练"元初始参数"，然后在没见过的 g=9 上比较"从元参数微调"与"从随机初始化微调"的适应曲线，看元学习能不能把"已经会了"和"几步就会"区分开。

  • 主题：元学习（Meta-Learning）/ Reptile 算法
  • 关键公式：θ ← θ + β·(θ′ − θ)，其中 θ′ 是内循环解
  • 预计学时：60 分钟
  • 前置章节：第 055 章

学习目标

  • 理解元学习的核心口径：优化目标是"在任务分布上快速适应后的回报"，考核对象是一批任务。
  • 掌握 Reptile 算法：内循环短程训练 + 元参数朝内循环解方向移动，只使用一阶信息。
  • 实现参数复制、按名字对齐的 Reptile 更新，以及留出任务上的适应曲线评估。
  • 区分三个相邻概念：迁移学习（一对任务）、多任务学习（同时服务）、元学习（快速适应新任务）。
  • 会判断元学习"买到了哪一段"：先验价值看 0 步、适应速度看曲线斜率、最终解看长跑是否反超。

背景与动机

普通的 RL 训练回答"这个任务怎么解"；元学习回答"怎么才能快速学会新任务"。工程价值很直接：真实系统面对的是任务流，每个新任务都从零训练不现实，你需要一个"几步微调就能上手"的起点。

Reptile 是实现这个目标最俭省的算法：从元参数出发，在某任务上做一小段普通 SAC 训练，然后把元参数朝着"训练后的参数"方向挪一步。反复多次后，元参数会漂到一个"到各任务解距离都较短"的位置。它不需要像 MAML 那样求二阶梯度，用现成的 SAC 训练循环就能实现，这正是它能写进一个脚本的原因。

核心原理

1. 元学习的形式化

给定任务分布 p(𝒯)，元学习希望找到一个初始化 θ，使得对任何采样任务做 k 步适应后，回报最大：

θ* = argmaxθ 𝔼𝒯~p[ J𝒯( 适应k(θ, 𝒯) ) ] 适应算子 = 在任务 𝒯 上做 k 步梯度更新；目标是适应算子作用后的结果，θ 只作为起点

符号说明：𝒯 是任务（某个 g 的摆杆），J𝒯 是该任务的回报，适应k 是在任务上训练 k 步后的参数。对比普通训练（在单一任务上最大化 J），元学习把"适应过程"放进了目标里。MAML 直接对嵌套目标求导；Reptile 的近似是：让 θ 朝着各个任务适应后的解的加权中心移动。

2. Reptile 更新规则

每次元迭代采样一个任务，从当前 θ 出发训练得到 θ′，然后：

θ ← θ + β·( θ′ − θ ) β 是元步长；展开看，θ′ − θ 近似指向"该任务解"的梯度累积方向

如果内循环是 SGD 且步长很小，θ′ − θ 正比于该任务的梯度；多任务平均下来，Reptile 更新近似"对任务分布的期望梯度"，但用完整训练过程替代了单步梯度，能捕捉更远的结构。实践上 β 取 0.3～1.0、内循环几百到几千步。

数值例子：两任务轮换时元参数怎么走

把参数空间压缩成一维便于演示：设元参数初始 θ=0.5。任务 A 的解在 0.8 附近，任务 B 的解在 0.2 附近。每次内循环从当前元参数出发训练，假设内循环能把参数带到"元参数与任务解的中点"（只走一半，因为短程训练不充分）。取 β=0.5：

迭代 1（任务 A）：θ′ = (0.5+0.8)/2 = 0.65，θ ← 0.5 + 0.5×(0.65−0.5) = 0.575。

迭代 2（任务 B）：θ′ = (0.575+0.2)/2 = 0.3875，θ ← 0.575 + 0.5×(0.3875−0.575) = 0.481。

继续轮换，θ 会在两个任务解之间来回微调，逐渐稳定在接近 0.5 的"加权中心"附近。若把 β 改成 1.0：迭代 1 后 θ 直接跳到 0.65，迭代 2 后跳到 0.3875，元参数随任务顺序大幅摆动，最终位置被"最后一个任务"主导。

解读：Reptile 的几何含义就是"朝各任务解的中心移动"，β 是移动的急切程度。β 小则稳但汇聚慢，β 大则快但受任务顺序影响大；这也解释了练习 1 里 β=1.0 时元参数可能"只在最后一个任务上好"的现象。

3. 三个概念的边界

  • 迁移学习（第 054 章）：已知源与目标两个任务，把参数搬过去继续训练；
  • 多任务学习（第 055 章）：一套参数同时服务固定的一组任务，任务标识告诉网络"现在是谁"；
  • 元学习（本章）：优化"适应过程"本身，目标是见到新任务后几步微调就能用；元参数不追求单个任务最优，恰恰要避免过拟合某个任务。

这也解释了本章为什么不给观测拼 one-hot：留出的 g=9 在训练分布里根本没有标识，元学习靠的是参数先验，不是输入条件。三个概念的对照如下：

维度迁移学习（054）多任务学习（055）元学习（056）
任务数量一对（源、目标）固定一组，同时服务分布，留出任务测试
任务身份来源不需要（参数就是先验）one-hot 输入不需要（参数先验）
优化目标目标任务的最终回报全部任务的回报之和适应 k 步后的回报
对未见任务不适用（目标已知）不适用（任务集固定）核心场景：快速适应
训练结构两段式顺序训练单循环、任务轮换嵌套循环（内循环 + 元更新）

读表的关键是"优化目标"一行：迁移与多任务优化的是参数在具体任务上的表现，元学习优化的是"从参数出发、短程训练之后"的表现，因此元参数可以看起来单任务成绩平平，却在适应曲线上全面领先。

实现思路与设计

数据流

流程分两段。元训练：循环 meta_iters 次，每次按顺序取一个训练任务（g 从列表里轮换）→ 新建内循环智能体并从元参数复制 → 在任务上短程训练 → 元参数朝内循环解移动 β 步，目标网络跟随。适应实验：对 g=9 的留出任务，meta 与 scratch 各跑 adapt_steps 步，评估点在 0、500、1000、2000 步，输出对比曲线。

模块划分

组件职责关键点
named_trainable()返回"名字→张量"的可训练参数（策略、双 Q、温度）名字对齐保证元更新与内循环结构一致
copy_from(other)把元参数完整复制给内循环智能体含目标网络与 log_alpha，就地复制
reptile_perturb(inner, β)θ ← θ + β(θ′ − θ)，并同步目标网络只更新可训练参数；目标网络直接跟随主网络
train_short(...)短程训练 + 可选评估点内循环与适应实验共用，训练逻辑一致
适应实验meta 与 scratch 各在 g=9 上跑相同步数两者使用相同环境种子与评估点

关键超参数

参数默认值作用与取值理由
--train-gs6,8,10,12,14元训练任务分布；留出 g=9 测试插值泛化
--meta-iters8元迭代次数（每次一个任务）；太少元参数还没汇聚
--inner-steps1500内循环步数；太短学不到任务的解，太长元更新代价高
--reptile-beta0.5元步长；较大收敛快但更抖、更易被末尾任务主导
--adapt-steps2000留出任务的适应预算；每 500 步记录一个评估点
--inner-start200短程训练的随机探索步数（内循环与适应一致）

与前一章的差异点

  • 第 055 章的"任务条件"是网络输入；本章的任务身份不外露，新任务没有 one-hot，靠的是初始参数本身。
  • 新增参数复制、按名字对齐的 Reptile 更新、目标网络同步。
  • 训练流程从"一次完整训练"改成"多次短程训练 + 元更新"的嵌套结构。
  • 评估指标从"最终回报"变成"适应曲线"（0 步、500 步、1000 步……的整条曲线）。

关键代码与解读

片段 1：元参数接口，按名字对齐的打包与更新

    def named_trainable(self):
        """返回 (名字, 张量) 列表：策略 + 双 Q + 温度系数。"""
        out = []
        for name, p in self.policy.named_parameters():
            out.append(("policy." + name, p))    # 加前缀避免与 Q 网络重名
        for name, p in self.q1.named_parameters():
            out.append(("q1." + name, p))
        for name, p in self.q2.named_parameters():
            out.append(("q2." + name, p))
        out.append(("log_alpha", self.log_alpha))
        return out

    def copy_from(self, other: "SAC") -> None:
        """把另一个智能体的全部参数复制过来（含目标网络，就地复制）。"""
        with torch.no_grad():
            self.policy.load_state_dict(other.policy.state_dict())
            self.q1.load_state_dict(other.q1.state_dict())
            self.q2.load_state_dict(other.q2.state_dict())
            self.q1_target.load_state_dict(other.q1_target.state_dict())
            self.q2_target.load_state_dict(other.q2_target.state_dict())
            self.log_alpha.copy_(other.log_alpha)

    def reptile_perturb(self, inner: "SAC", beta: float) -> None:
        """Reptile 元更新：theta_meta <- theta_meta + beta * (theta_inner - theta_meta)。"""
        with torch.no_grad():
            meta_map = dict(self.named_trainable())
            for name, p_inner in inner.named_trainable():
                p_meta = meta_map[name]                       # 按名字配对，杜绝错位
                p_meta.add_(beta * (p_inner.data - p_meta.data))
            # 目标网络跟随主网络（避免元参数与目标网络失配）
            self.q1_target.load_state_dict(self.q1.state_dict())
            self.q2_target.load_state_dict(self.q2.state_dict())

解读：（1）named_trainable 返回形如 ("policy.body.0.weight", tensor) 的列表并加前缀：元更新按名字配对。直接按列表顺序 zip 也能工作（两个网络构造顺序相同），但一旦以后给策略加了一层，元更新会悄悄错配参数，按名字对齐是低成本的正确性保险。（2）copy_from 必须连目标网络一起复制：内循环的 bootstrap 依赖目标网络，只复制主网络会让第一次更新建立在"新旧混合"的目标上。log_alpha 同样用 copy_ 就地写，优化器引用不变。（3）reptile_perturb 对元参数做 add_：就地更新，不重建张量；p_inner.data − p_meta.data 是"内循环解与元参数的差"，乘 β 后加到元参数上。（4）更新完元参数后让目标网络直接跟随主网络：Reptile 平均过的目标网络与主网络会失配，直接同步牺牲一点平滑性、换来状态一致。

片段 2：短程训练，内循环与适应实验共用的同一段逻辑

def train_short(agent: SAC, g: float, steps: int, seed: int, args,
                eval_env=None, eval_points=None, tag: str = ""):
    """从 current 参数出发，在指定 g 的任务上训练 steps 步。

    eval_points 给定时，在这些步数处评估（含 0 步）并打印。
    返回 [(步数, 评估回报)] 列表。
    """
    env = make_pendulum(seed, g)
    buffer = ReplayBuffer(args.buffer_size, env.observation_space.shape[0],
                          env.action_space.shape[0])
    eval_history = []
    if eval_env is not None and eval_points is not None and 0 in eval_points:
        ret = evaluate(agent, eval_env, args.eval_episodes)
        eval_history.append((0, ret))                # 0 步 = 先验的直接读数
        print(f"    [{tag}] 适应步数     0 | 评估 {ret:8.1f}")

    obs, _ = env.reset()
    ep_ret = 0.0
    for step in range(1, steps + 1):
        if step <= args.inner_start:
            action = env.action_space.sample()       # 短程也要预热，保证有数据可学
        else:
            action = agent.act(obs, deterministic=False)
        next_obs, rew, terminated, truncated, _ = env.step(action)
        buffer.add(obs, action, rew, next_obs, float(terminated))
        obs = next_obs
        ep_ret += rew
        if terminated or truncated:
            ep_ret = 0.0
            obs, _ = env.reset()
        if buffer.size >= min(args.inner_start, 200):
            agent.update(buffer.sample(args.batch_size), args)
        if eval_env is not None and eval_points is not None and step in eval_points:
            ret = evaluate(agent, eval_env, args.eval_episodes)
            eval_history.append((step, ret))
            print(f"    [{tag}] 适应步数 {step:5d} | 评估 {ret:8.1f}")
    return eval_history

解读：（1）评估点包含 0 步：对 meta 是"元参数的直接成绩"（先验价值），对 scratch 是随机策略成绩；两者之差就是元学习买到的起点。（2）每段训练都新建回放池并从零填充：短程训练的数据绝不能跨任务保留，否则旧任务的 (s,a,r,s′) 会污染新任务的回归目标。（3）inner_start 预热在每段都执行：短程训练也需要初始多样性，不然前几百步梯度来源太少。（4）内循环与适应实验走同一个函数：元训练里的"任务解"和测试里的"适应过程"口径完全一致，如果两处用不同的训练细节，0 步评估的可比性就无从谈起。

片段 3：元训练主循环与适应实验

    meta_agent = SAC(obs_dim, act_dim, action_scale, args)
    for it in range(args.meta_iters):
        g = train_gs[it % len(train_gs)]              # 任务轮换：覆盖整个分布
        inner = SAC(obs_dim, act_dim, action_scale, args)   # 新对象 = 干净优化器
        inner.copy_from(meta_agent)                   # 从元参数出发
        train_short(inner, g, args.inner_steps, args.seed + 1000 * it, args, tag=f"内{it}")
        # 元参数朝内循环解移动
        meta_agent.reptile_perturb(inner, args.reptile_beta)

    adapt_env = make_pendulum(args.seed + 777, args.test_g)
    meta_agent_adapt = SAC(obs_dim, act_dim, action_scale, args)
    meta_agent_adapt.copy_from(meta_agent)            # meta 分支：从元参数微调
    curve_meta = train_short(meta_agent_adapt, args.test_g, args.adapt_steps,
                             args.seed + 9000, args,
                             eval_env=adapt_env, eval_points=adapt_points, tag="meta")

    scratch_agent = SAC(obs_dim, act_dim, action_scale, args)
    curve_scratch = train_short(scratch_agent, args.test_g, args.adapt_steps,
                                args.seed + 9000, args,
                                eval_env=adapt_env, eval_points=adapt_points, tag="scratch")

解读：（1）每次元迭代都新建 inner 智能体：Adam 动量不能跨内循环累积，否则等于"接着上一个任务训练"，Reptile 的"任务解"就不是从元参数出发的了。（2）train_gs[it % len(train_gs)] 按顺序轮换任务：保证有限元迭代里覆盖整个分布；随机采样也可以，顺序轮换更易复现（练习）。（3）适应实验里 meta 与 scratch 用同一个训练种子（seed+9000）与同一个评估环境（seed+777）：两条曲线只差初始参数，差值才是元学习的净贡献。（4）adapt_points = [0] + range(eval_every, adapt_steps+1, eval_every)：0 步是"先验价值"，之后每 500 步一个点画斜率，元学习真正的卖点在前 500～1000 步。

适应步数scratchmeta差值含义

500约 −700约 −300约 +400适应初期：优势仍明显

常见坑

  • 元更新把目标网络也当成可学习参数参与平均：目标网络是"慢副本"，参与 Reptile 平均会与主网络失配。正确做法是元更新后让目标网络直接跟随主网络。
  • 内循环复用同一智能体而不重置优化器状态：Adam 的动量跨内循环累积，等于"接着上一次任务训练"。每次内循环都要新建智能体并从元参数复制。
  • 适应实验结果被评估方差淹没：Pendulum 的 3 回合评估噪声大，0 步差值可能只有 ±50。把 --eval-episodes 提到 5～10，或多跑几个种子看均值。
  • 把元学习与多任务混淆：给 meta 网络拼任务 one-hot 就变成了多任务做法；留在分布外的测试任务没有可靠标识，结论会失真。元学习靠参数先验，不靠输入条件。

练习与思考

  1. 把 --reptile-beta 改成 0.1 与 1.0 各跑一次，比较 0 步评估与适应曲线。β 太大时元参数会发生什么？★
    提示
    β=1.0 时元参数直接跳到"最后一个内循环解"，被采样顺序主导，可能接近"只在最后一个任务上好"的参数。看 0 步评估与各任务的稳定性。
  2. 把内循环步数从 1500 砍到 400，重跑。元参数的质量（0 步评估）变好还是变差？为什么？★★
    提示
    内循环太短时任务解未成形，θ′−θ 主要是随机噪声。这是"内循环要够长"的直接证据。
  3. 把留出任务从 g=9（插值）换成 g=20（外推），重跑适应曲线。元学习在分布外的表现如何？★★
    提示
    元参数只在 g=6～14 上平均过，g=20 的难度远超分布，初期优势会明显缩小。对比两次运行的 0 步与 500 步差值。
  4. 在适应实验里让 meta 使用更小的学习率（例如 lr/3），它能否保住优势更久？解释学习率与"元先验"的相互作用。★★★
    提示
    学习率过大会迅速抹掉先验，过小则适应太慢。给 train_short 加 lr_scale 参数试试。
  5. 把 Reptile 换成"FOMAML 近似"：元更新直接用内循环最后一次的梯度方向（替代参数差的做法）。比较两者的 0 步评估。★★★
    提示
    需要在内循环保存最后一步的梯度（update 里留下主要参数的 .grad），元更新改为 θ ← θ + β·(−grad)。对比实现复杂度与效果，体会 Reptile 的"免二阶"优势。

小结

  • 元学习优化的是"适应后的回报"，目标是"快速上手新任务"的初始参数；任何单任务的最终成绩只算副产品。
  • Reptile 用"θ ← θ + β(θ′ − θ)"近似元梯度，只需一阶信息，配合现成的 SAC 训练循环即可实现，实现成本远低于二阶方法。
  • 本章在 g ∈ {6,…,14} 的分布上元训练、留出 g=9 测试：meta 的 0 步评估比随机初始化高出数百，优势随适应步数递减。
  • 实现要点：按名字对齐参数、内循环独立优化器、目标网络跟随主网络、内循环与适应实验共用同一训练逻辑。
  • Reptile 的几何含义是"朝各任务解的中心移动"：两任务算例里元参数在 0.5 附近来回微调并稳定；β=1.0 时会被最后一个任务主导，这解释了元步长为什么不宜过大。
  • 适应曲线要分段读：0 步差值衡量先验，前 500 步斜率衡量适应速度，末端衡量最终解；三段读数支持不同的改进方向。
  • 元训练的总环境步数约等于 元迭代数 × 内循环步数（本章 8×1500 = 1.2 万），它买到的是"未来每次适应省下的几百步"，任务越多、复用次数越多，这笔投资越划算。
  • 下一章换一条"更直接"的提升初期表现路径：用专家示范初始化回放池并加行为克隆损失，让 SAC 从第一刻就有像样的动作。
