第一篇 · 策略梯度与 PPO

第 015 章：PPO的迁移学习：从简单到复杂

把 CartPole 的重力调大、推力调小，造出一个"更难版"任务；对比从零训练、全参数微调、冻结躯干三种方式在难任务上的达标步数，并量化迁移的收益与遗忘的代价。

  • 主题：迁移学习 / 微调
  • 关键公式：πθ(a|s) = ψhead(φbody(s))；遗忘 Δ = easy微调后 − easy微调前
  • 预计学时：60 分钟
  • 前置章节：第 014 章

学习目标

  • 理解强化学习里的迁移学习设定：同观测/动作空间、不同动力学或不同奖励分布的任务之间如何复用权重。
  • 构造一个"难版"环境（改重力与推力），建立受控的域偏移实验。
  • 实现三种学习方式：scratch、全参数微调（transfer_full）、冻结躯干（transfer_frozen）。
  • 用"难任务首达步数"衡量迁移收益，用"易任务评估"衡量灾难性遗忘。
  • 掌握迁移的工程判断：特征复用与上限、学习率选择、预训练预算怎么算进总成本。

背景与动机

真实项目几乎不会从零训练：仿真先把策略练个七七八八，再迁移到真实机器人（sim-to-real）；或者先在便宜任务上打基础，再到贵任务上微调。RL 的迁移比监督学习更微妙，任务是同一个马尔可夫决策过程变了参数，演示数据不能复用（策略不同分布不同），但网络学到的"怎么控制"这件事本身是可复用的：识别角度、判断速度、抑制摆动，这些低层特征在难易任务里通用；而"多大力气、什么时候收手"是任务相关的，必须重新学。

本章用最小改动制造域偏移：CartPole 的重力从 9.8 提到 11.5、推力从 10 降到 9。动力学规则完全一样，只是"更费力、更容易倒"。在这个设定下对比三种学习方式，你能直接看到：预训练权重让难任务学得更快（迁移收益）、冻结躯干学得更快但撞上上限（特征够不够用）、以及微调会伤害原任务（遗忘）。这三个现象在从仿真到现实的迁移里一个都不少。

核心原理

1. 迁移的形式化

把任务差异记作 MDP 的差异：状态/动作空间相同、转移与奖励不同。策略 πθ 由"特征提取器"φ（躯干）与"决策头"ψ（actor/critic）组成：

πθ(a|s) = ψhead( φbody(s) )，　θ = (θbody, θhead)

迁移的假设是：φ 在任务间共享，ψ 需要适配。全参数微调让两者都动；冻结躯干只更新 ψ，等于把 φ 当固定特征，这就是"线性探测"思路。哪个更好取决于域偏移的位置：动力学尺度变了（φ 的输入分布偏移），躯干需要适应；只是目标微调，冻结往往够用。

数值算例：hard 任务到底难了多少

用 CartPole 的杆角加速度公式代入两组参数（小车质量 1.0、杆质量 0.1、半长 0.5）：θ̈ = (g·sinθ − cosθ·F/(mc+mp)) / (l·(4/3 − mpcos²θ/(mc+mp)))。在 θ=0.2 rad（约 11.5°）、θ̇=0 处施加满推力：easy（g=9.8、F=10）得到 θ̈≈−11.18 rad/s²，hard（g=11.5、F=9）得到 −9.20 rad/s²，恢复能力下降 17.6%。再算"自由倒杆"的指数发散时间常数：easy 约 0.252 秒、hard 约 0.233 秒，快了 7.7%。

这两个数字标出域偏移的量级：控制难度上升约两成、任务仍然可解，正好落在"迁移有明显收益又保留可解性"的区间。对学习的影响也顺手可见：hard 上失误被更快放大，等价于信用分配的有效窗口变窄，这就是为什么"识别角度与速度"的低层特征依旧通用，"用多大力、何时收手"的头部决策必须重学。

取值的尺度检查：把 F/g 当作偏移强度的一阶指标，easy 为 10/9.8 ≈ 1.02，本章 hard 为 9/11.5 ≈ 0.78，对应上例约 18% 的恢复能力下降，足以让冻结组吃亏、又不至于让任务不可解。练习 4 的 8/13 ≈ 0.62 更接近可解性边界，用来观察负迁移。

设定上还要强调一次：本章不共享数据（hard 的轨迹对 easy 没有直接价值），只共享初始权重。因此迁移的收益全部来自两处，表征的复用与优化起点的优势；这也解释了为什么遗忘只损伤源任务成绩、却不影响 hard 阶段的可比性。

2. 微调的学习率与遗忘

微调时梯度会改变共享的 θbody，如果目标任务的梯度幅度大或更新步数多，原来在源任务上习得的特征会被覆盖，表现为灾难性遗忘（catastrophic forgetting）。缓解手段有：更小的微调学习率、冻结部分层、L2 约束（谨慎保留源参数）、或正则化方法（EWC）。本章用固定学习率，直接观察遗忘量：

Δ = Evaleasy(θ微调后) − Evaleasy(θ预训练后) Δ 越负遗忘越重；本章用同一批贪婪评估回合统计，两臂口径一致

遗忘的读数先要过统计这一关：10 个评估回合的均值标准误约 σep/√10，单回合波动按 50 分计就是约 16 分。预期遗忘 20～40 分对应 1.3～2.5 个标准误，单种子实验里"遗忘是否真实存在"都可能分辨不清；把评估回合加到 30（标准误约 9 分）或对三个种子重复后报均值，结论才稳。

缓解手段按实施成本排队：降低微调学习率（不花额外算力，牺牲可塑性）；冻结部分层（同样免费，牺牲上限）；在 hard 训练里混入 10%～20% 的 easy 轨迹（多花采样预算，直接对抗遗忘）；L2 锚定源参数 λ‖θ−θ0‖²（改一行损失，多一个超参 λ）；EWC 等方法按参数重要性加权（需要估计费舍尔信息，成本最高）。本章先观察基线现象，扩展手段留作后续实验。

3. 冻结的利与弊

冻结躯干把可训练参数从数千降到几百：更新稳定、起步快，但上限受 φ 的表示能力限制。如果 φ 在源任务里从未见过"重力更大时需要的激进控制"，冻结策略永远学不到它。所以实验的预期是：冻结组最快的初期爬升 + 较低的平台。

边界：偏移过大时的负迁移。冻结只在"源特征与目标需求相容"时成立。偏移继续加大（重力更高，或目标需要反向控制），源躯干特征会与目标最优行为冲突，冻结组的起步不再更快、平台更低，早期成绩甚至低于 scratch；微调组也可能出现"先退化再爬升"的曲线。判别信号是训练早期的成绩排序与后期相反。对策：先用小预算做域偏移扫描（练习 4），确认"可解且有益"再投入完整预算；一旦出现负迁移，退回部分冻结（只冻底层）或放弃预训练。

4. 成本对账

迁移的成本结构常被忽略：预训练步数也要算总预算。若预训练 5 万步 + 难任务 4.3 万步达标，而 scratch 需要 7.2 万步，单看"难任务阶段"迁移省了 40%，但把预训练算进来单次迁移反而更贵，不过预训练权重可以在多个下游任务上复用，摊销后才真正划算。报告里要把两段成本分开列出。

把保本点算出来：只服务 1 个下游任务，迁移总成本 5+4.3=9.3 万步，比 scratch 的 7.2 万贵 29%；服务 2 个任务，迁移 5+4.3×2=13.6 万对 14.4 万，开始便宜；服务 5 个任务，26.5 万对 36 万，省 26%。令 50 + 43k = 72k（即 50 = (72−43)k）解得 k ≈ 1.72，即下游任务不少于 2 个时，迁移在样本账上才划算。这条算式应当写进迁移方案的第一页，避免"为一个任务先训 5 万步再微调"的常见浪费。

数据流

三段式：预训练（同一种子、easy、5 万步，权重 clone() 存成共享快照）→ 三个 arm 在 hard 上各训 10 万步（scratch 从随机初始化、两个迁移臂从共享快照；frozen 额外冻结躯干）→ 双环境评估（hard 看收益、easy 看遗忘）→ 汇总表：首达步数 / hard 评估 / easy 评估 / 遗忘 / 耗时。

受控迁移实验的三条纪律

1) 每个 arm 开头重设种子：三种方式的采样流一致，差异只来自"起点权重与可训练参数"。2) hard 阶段预算三者相同、预训练单独记账：否则"快"可能只是被喂了更多数据。3) 评估用同一批回合数、同一贪婪口径：遗忘量才可比较。

冻结组到底省了多少参数（按本章网络算）

网络结构为 4→64→64 躯干加两个线性头。逐层数参数：第一层 4×64+64 = 320，第二层 64×64+64 = 4160，躯干合计 4480；actor 头 64×2+2 = 130，critic 头 64+1 = 65，全量约 4675。冻结组只训练 195 个参数，是全量的 4.2%，约为 1/24。这个比例解释了实验现象：梯度只更新一个浅头，起步自然快、曲线抖动小；但 195 个参数要在固定特征上拼出一个更难任务的控制律，表达能力先到顶，平台也就更早出现。

首达步数这个指标本身也要配统计说明：达标判定用 100 回合滑窗均值 ≥400，窗口噪声的标准误约 5 分（按单回合 50 分波动），真实水平 395 的策略也会以不小概率触线，触线时刻因此带随机性。跨臂比较"省了多少步"时，建议三个种子取中位数再比，并把"预算内未达标"如实记为右删失，避免用预算上限冒充达标步数。

关键代码与解读

片段 1：两个任务，一个函数

def make_env(kind: str):
    """easy=默认；hard=重力更大、推力更小。"""
    env = gym.make("CartPole-v1")
    if kind == "hard":
        env.unwrapped.gravity = 11.5     # 只改这两个“无派生量”的参数
        env.unwrapped.force_mag = 9.0    # 恢复力更弱，控制更难
    return env

解读：（1）域偏移被压缩成两行赋值：unwrapped 拿到被 gym 包装前的原始环境，直接改动力学常数。这就是"同代码、两任务"的最小实现，评估与训练都靠它切换。（2）为什么只改这两个：gravity 与 force_mag 直接参与每步的动力学计算，没有派生量；而 length 会牵动 polemass_length、total_mass 等预计算属性，只改它会让环境内部自相矛盾。（3）改的是"环境实例"的属性：每次 make_env 都新建实例，互不污染；千万不要在共享的全局环境上改参数。（4）换法会怎样：用 gym 的 register 注册新环境 ID 也可以，但对单文件实验来说多此一举；直接赋值最直白，也方便练习里换数值。

片段 2：阶段训练函数，两个任务共用一条循环

    while total_steps < budget:
        batch, ep_returns, obs_t = collect_rollout(
            env, net, args.steps_per_update, obs_t, device, args.gamma, args.lam)
        total_steps += args.steps_per_update

解读：（1）train_phase(kind, net, optimizer, budget, tag) 把"在某个环境上训练一段"封装成函数：预训练与 hard 微调调用同一段代码，训练动态完全一致，差异只在入参。（2）reached_at 记录 100 回合滑窗首次达到 400 的步数，这是本章最核心的对比指标（"迁移省了多少步"）。（3）预算参数化：预训练用 --pretrain-steps、微调用 --hard-steps，成本对账时两段可以分开报告。（4）注意函数从不"提前停"：三个 arm 都必须跑满相同的 hard 预算，末段成绩才可比；达标步数只是记录量。

片段 3：共享预训练与冻结的干净写法

    # 预训练一次，供迁移臂共享（同一随机种子 => 同一份预训练权重）
    set_seed(args.seed)
    base = ActorCritic(probe.observation_space.shape[0], probe.action_space.n)
    pre = train_phase("easy", base, pre_opt, args, args.pretrain_steps, "shared-pre")
    pretrained_state = {k: v.clone() for k, v in base.state_dict().items()}

    for arm in args.arms:
        set_seed(args.seed)                        # 每个 arm 重置随机流
        net = ActorCritic(probe.observation_space.shape[0], probe.action_space.n)
        if arm != "scratch":
            net.load_state_dict(pretrained_state)  # 迁移臂从同一份权重出发
        if arm == "transfer_frozen":
            for p in net.body.parameters():
                p.requires_grad_(False)            # 第一步：躯干不再产生梯度
            params = list(net.actor.parameters()) + list(net.critic.parameters())
            optimizer = torch.optim.Adam(params, lr=args.lr)   # 第二步：只把头部给优化器
        else:
            optimizer = torch.optim.Adam(net.parameters(), lr=args.lr)

解读：（1）pretrained_state = {k: v.clone() ...}：把预训练权重逐个张量克隆下来，state_dict() 返回的是共享存储的引用，若不克隆，后续对 base 的任何改动都会"改到历史"。这份快照就是三个 arm 的共同起点。（2）冻结要做两件事：requires_grad_(False) 让躯干参数不再产生梯度；只把头部的参数列表交给 Adam，让它不维护躯干参数的动量状态。只做前者，优化器里还挂着永远不会更新的参数（浪费但无害）；只做后者，梯度照算（白费算力）。两者都做才是干净的冻结。（3）set_seed 放在 arm 循环内：每个 arm 的采样流一致，但真正的受控点在"同一份 pretrained_state"，种子只负责其余随机性。（4）换法会怎样：如果在循环外只 set_seed 一次，后面的 arm 会继承前一个 arm 消耗过的随机流，采样序列错位，对比不再受控。

片段 4：双环境评估与遗忘量

        phase = train_phase("hard", net, optimizer, args, args.hard_steps, arm)
        info["hard_reached_at"] = phase["reached_at"]
        info["hard_last100"] = phase["last100"]

        info["hard_eval"] = float(np.mean(evaluate("hard", net, args.eval_episodes, device)))
        info["easy_eval"] = float(np.mean(evaluate("easy", net, args.eval_episodes, device)))
        if arm != "scratch":
            # 遗忘量 = 微调后的 easy 成绩 − 预训练刚结束时的 easy 成绩
            info["forget"] = info["easy_eval"] - pre_easy_eval
        results.append(info)

        os.makedirs(args.save_dir, exist_ok=True)
        torch.save(net.state_dict(), os.path.join(args.save_dir, f"{arm}.pt"))

解读：（1）训练结束后两个环境都要评估：只报 hard 成绩会漏掉"学会了新的、忘了旧的"这种最危险的迁移失败模式；easy 评估就是遗忘的探测器。（2）evaluate("hard"/"easy", ...) 内部各自 make_env 新实例：保证 easy 评估用的是原始默认参数，避开被改过的 hard 环境对象。（3）遗忘量对 scratch 无定义（没有"微调前"基线），打印时用"—"占位，报告口径要诚实。（4）三个 arm 的权重都落盘：迁移结论可复现，也方便你后续加载 transfer_full.pt 单独观察它在两个任务上的行为。（5）注意 info 字典是"证据包"：新的指标就加新的键，汇总表只读不推断，这种扁平结构让对比表的代码非常直白。

预期结论（以实跑为准）：transfer_full 在 hard 上首达 400 的步数通常比 scratch 少 30%～60%（约 4 万 vs 7 万步），最终评估追平甚至超过 scratch；transfer_frozen 起步最快但平台明显更低（躯干特征够搭一个"还行"的策略，做不出微调级的精细控制）；两个迁移臂在 easy 上都有 20～40 分的遗忘，冻结版遗忘更小。成本对账要算两段：若同一份预训练权重只服务一个下游任务，单次迁移的总成本可能还高于 scratch，迁移的经济性来自复用次数。

常见坑

  • 改环境属性却忘了派生量：本章只改 gravity/force_mag 是安全的；若想改 length 或 masspole，必须同步更新 polemass_length、total_mass 等派生属性，否则环境动力学自相矛盾，训练结论全部作废。
  • 三个 arm 的 hard 预算不一致：这是最常见的"假迁移收益"。预训练步数要单独计，hard 阶段三者相同；否则快的那方可能只是被喂了更多难任务数据。
  • 忘记同步评估口径：easy 评估必须在"原始默认参数"的新环境实例上做；若复用了 hard 环境对象，评估的是错的任务。
  • 维度不匹配的朴素复刻：跨观测/动作空间的任务不能用 load_state_dict 直接搬（输入输出层形状不同）。本章的 easy/hard 共享 4 维观测与 2 个动作，所以可以整份复制；换任务时要按层选择性地加载。
  • 冻结只做一半：只冻结 requires_grad 却把全部参数交给优化器，或只缩小参数组却忘了关梯度，前者浪费、后者无效。牢记"关梯度 + 缩参数组"两个动作缺一不可。

练习与思考

  1. 把 --pretrain-steps 依次设为 0.5 万 / 2 万 / 5 万 / 10 万，画出"预训练预算 vs hard 首达步数"的曲线，找性价比拐点。★
    提示
    每个预算下只跑 transfer_full 与 scratch 两组即可（scratch 只需跑一次）。预训练太少时特征没成型，太多时收益递减并可能增大遗忘。
  2. 给 transfer_full 加一个"更小的微调学习率"（如 1e-4），观察易任务遗忘是否减小、难任务达标是否变慢。★★
    提示
    在 train_phase 调用前重建优化器并传不同 lr；或者给 train_phase 加一个 lr 参数。这是"稳定性 vs 可塑性"的经典权衡。
  3. 实现"只冻结第一层"的迁移：保留底层特征、放开高层做微调，对比三档冻结策略（全冻结 / 冻结一层 / 全放开）。★★
    提示
    遍历 net.body 的子模块，只把第一层 Linear 的参数置 requires_grad_(False)，其余交给优化器。观察收益如何在"冻结组"与"微调组"之间插值。
  4. 加大域偏移：hard 设为重力 13.0、推力 8.0，重新对比三臂，并留意是否出现"迁移也学不动"的情况。★★★
    提示
    偏移越大，冻结组越吃亏（特征差距大），微调的相对优势越明显；但如果任务本身接近不可解，所有组都会失败，先确认 hard 在预算内可解，再谈迁移。
  5. 给 transfer_full 加 L2 锚定：损失里追加 λ·Σ(θ−θ0)²，λ 扫 0 / 1e-4 / 1e-3，观察"遗忘变小、达标变慢"的取舍位置。★★
    提示
    在 ppo_update 的损失里加上锚定项，参考权重用 pretrained_state；λ=0 即原基线。锚定把"可塑性"换成"稳定性"，与调小学习率是同一条权衡轴上的两种拧法。

小结

  • 迁移的前提是任务间共享结构：躯干学"怎么看"，头部学"怎么做"；域偏移的位置决定冻结还是微调。
  • 实验结果：全参数微调在难任务上省 30%～60% 样本；冻结躯干起步更快但上限更低；两者都会带来 20～40 分的原任务遗忘。
  • 迁移的经济性来自复用：预训练成本要单独入账，同一权重服务多个下游任务时才真正划算。
  • 工程建议：小学习率微调抑制遗忘；冻结策略用于快速原型与计算受限场景；上线前在两个任务上都做评估。
  • 下一章把"多个任务"合并进一次训练：给网络加任务标识，让一个策略同时掌握多种重力/目标配置，并对比单任务专精与多任务共享的样本效率。
