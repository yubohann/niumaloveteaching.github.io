第二篇 · 离策略方法与 SAC

第 043 章：SAC的样本复用与经验回放

把 SAC 的数据管道摆上实验台：大回放池、小回放池、"只吃最新一个 batch"的伪在线模式，在 Pendulum-v1 上同种子对照，量化经验回放带来的样本效率，并用数据年龄与保留率解释差异从哪里来。

  • 主题：SAC 数据管道 / 经验回放机制
  • 关键公式：每条经验平均使用次数 ≈ batch_size × 驻留期更新次数 / 池内样本数
  • 预计学时：50 分钟
  • 前置章节：第 042 章

学习目标

  • 理解 off-policy 学习的核心资产，回放池（replay buffer），如何把一条经验的价值放大到成百上千次梯度更新。
  • 掌握带"存入时刻"记录的回放池实现，会统计采样批次的平均年龄与数据保留率。
  • 设计并运行三组对照（replay / small / noreplay），比较样本效率与训练曲线噪声。
  • 会解释回放池容量的权衡：大池子样本多样但陈旧，小池子新鲜但容易"遗忘"。
  • 会用"达标步数、保留率、平均年龄"三列数据写出可复现的实验结论。

背景与动机

PPO 每批数据用几个 epoch 就必须丢掉，而 SAC 可以把每条经验放进"仓库"反复取用。这个差别直接决定样本效率：把 2 万步交互榨出成千上万次梯度更新的 SAC，往往比"数据用一次就扔"的算法快一个量级学会任务。反过来说，如果回放池配置不当，太小、采样有偏、存储出错，它也会悄悄变成性能瓶颈。

本章不动算法，只动数据管道：把数据年龄与保留率两个指标变成日志里可读的数字，看清"容量"这个参数到底买到了什么、又付出了什么。三组对照的预期是：大池最快且最平滑，伪在线最慢且最抖，小池居中；如果实验跑完发现排序不是这样，先检查数据年龄与保留率两列是否符合预期，再讨论算法层面的原因。

核心原理

1. 为什么回放能提高样本效率

SAC 的每个梯度步骤只需要一个 mini-batch (s, a, r, s′)。与环境交互获得一条新经验要花一次物理仿真（昂贵），而从池中抽样几乎免费。设一条经验在池中驻留期间被抽中的平均次数为 k，则同样的环境交互量下，梯度更新次数放大了约 k 倍，这就是"样本复用"的字面含义。

每条经验的平均使用次数 ≈ batch_size × 驻留期内更新次数 ÷ 池内驻留样本数 池子越大、更新频率越高，同一批交互被榨出的梯度越多；容量与更新频率是复用倍数的两个杠杆

符号说明：batch_size 是每次更新抽取的样本数（本章 256）。可以直观估算：容量 10 万、每步更新一次、跑 2 万步，平均每条交互被用到数百次。把公式在稳态下算精确：一条经验存入后会在池中停留 C 步（C 为容量），期间共发生 C 次更新、每次抽取 256 条，总抽取 256C 次，而池内正好有 C 条样本，因此每条经验的期望使用次数 ≈ 256C / C = batch_size。也就是说，在"每步更新一次 + 均匀采样"的配置下，复用倍数约等于批量大小（本章约 256 次），容量并不改变复用次数，它改变的是这些复用发生在多新、多多样的数据上。

把复用倍数与第 030 章的 PPO 摆在一起，数字会更有体感。PPO 每次采样 2048 步、更新 10 个 epoch，每条样本在每个 epoch 被消费一次，复用倍数约 10；SAC 在本章配置下约 256，两者相差约 26 倍。这就是"同样一次环境交互能换出多少次梯度更新"的差距，也是第二篇开头"off-policy 用更少交互量达到更好水平"的账面来源。

2. 回放还修正了数据分布

RL 数据强相关：连续的 200 步来自同一条轨迹，如果直接用"最近一批"数据做 SGD，梯度噪声里混着"轨迹偏置"，更新方向会随最近几个回合剧烈摇摆。随机抽样近似还原独立同分布（i.i.d.）批次，这是回放池的第一动机：

LQ = 𝔼(s,a,r,s′)~𝒟[ ( Q(s,a) − ( r + γ·minj=1,2 Q̄j(s′,a′) − α·log π(a′|s′) ) )2 ] 𝒟 是回放池；池子越大，𝒟 越接近策略的长期访问分布

符号说明：Q̄j 是第 j 个目标网络，a′ 是策略在 s′ 上的采样动作，α 是温度系数。可以看到梯度更新的所有素材都来自 𝒟，𝒟 的质量（多样性、新鲜度）直接决定训练的稳定性。noreplay 模式把 𝒟 压缩到"最近 256 条"，两种性质都变差。

把"强相关"具体化：一条 200 步轨迹里相邻状态的观测差异很小，价值也接近，用连续 256 条数据算出的梯度，有效信息量远小于 256 条独立样本。统计学上，强相关序列的等效独立样本数要乘以一个小于 1 的因子，相关长度越长因子越小；均匀随机抽样把相关长度压到接近零，让 256 条的批量真正发挥 256 条的作用。这个因子可以算：对一阶自回归结构（相邻步相关系数 ρ），样本均值的有效样本数约为 n(1−ρ)/(1+ρ)。取 ρ=0.9，256 条连续数据的等效独立样本约 256×0.1/1.9≈13.5 条；ρ=0.99 时只剩约 1.3 条。换句话说，noreplay 名义上批量 256，实际信息量可能只有十几条独立样本，而回放池均匀抽样把批内相关长度压到接近零。这一项差异比"重复抽取 94 条"更本质：重复抽取损失的是计算效率，相关性损失的是梯度的有效信息量。这也是经验回放被称为"离策略学习第一性组件"的原因：它同时解决复用与去相关两个问题。

3. 数据年龄与保留率：给数据管道装两个仪表

定义一个样本的年龄为"被抽中时的环境步数 − 存入时的环境步数"。均匀采样且池满时，年龄平均值约为容量的一半：256 池约 128 步、2000 池约 1000 步。大池（容量 10 万）在 2 万步预算内不会被写满，年龄随训练线性增长，2 万步结束时约为池内样本数的一半、一万步量级，前几个评估点上还只是几千步。保留率 = 池内样本数 ÷ 累计收集数，度量"记忆长度"：noreplay 只保留 256 / 20000 ≈ 1.3%，意味着 98% 以上的交互用一次就被丢弃。年龄衡量新鲜度，保留率衡量记忆，二者合起来解释了容量的全部代价与收益。

把容量放进更长的预算里，还能看到"大池"的失效场景：若预算放大到 100 万步、容量仍是 10 万，保留率稳定在约 10%，平均年龄约 5 万步，相当于批次里混着"250 个回合之前"的数据。任务分布固定时，这些数据仍然有价值；一旦任务非平稳（课程学习、环境参数漂移），旧数据记录的是旧策略下的回报，Q 回归会被系统性拖偏，典型症状是前期学得快、后期停滞甚至回退。判断方法依旧是年龄列：当平均年龄超过你估计的"策略明显改进的间隔步数"时，就该考虑缩小容量或做数据淘汰。

数值例子：2 万步预算下三个模式的账本

统一条件：预算 20000 环境步、每步一次更新、批量 256。总抽取次数 = 20000 × 256 = 512 万次；累计收集 20000 条经验；按上节推导，每条经验平均被使用约 256 次，三种模式在这项上一致。

指标replay（10 万）small（2000）noreplay（256）
池内样本数（训练末）200002000256
保留率100%（未写满）10%约 1.3%
采样平均年龄（训练末）约 10000 步约 1000 步约 128 步
批次内数据的来源跨度横跨几乎整场训练最近约 10 个回合最近 1.3 个回合

解读：复用次数相同，三者的差别集中在"批次里的数据来自多宽的时间跨度"。replay 的每个批次混合了早期探索与近期改进的样本，接近策略的长期访问分布；noreplay 的批次几乎全部来自最近一两个回合，连续性强相关，梯度方向随回合内容摇摆。这也解释了为什么 noreplay 的保留率只有约 1.3%：98% 以上的交互在写入后 256 步内就被覆盖，历史信息被彻底丢弃。

把"多样性"再精确一格：从容量为 n 的池子里均匀抽 256 条，期望抽到的不同样本数为 n·(1−(1−1/n)256)。代入三档容量：n=256 时约 162 条，即一个批次里有约 94 条是重复样本；n=2000 时约 240 条；n=20000 时约 254.4 条。noreplay 批次的近四成抽取是同一条数据的重复消费，这也是它梯度噪声大的结构性原因，与抽样运气无关。

实现思路与设计

三种模式的定义

模式池容量行为与预期表现
replay100000标准经验回放，约 500 个回合历史；样本多样、曲线平滑，达标最快
small2000小池，只记住最近约 10 个回合；前期快，后期受遗忘与多样性不足拖累
noreplay256伪在线：只保留最近一个 batch，数据高度相关、用一次即扔，最慢且抖

容量取值的说明：replay 的 10 万容量在 2 万步预算内不会被写满，它实际提供的是"全历史保留"；若把预算放大到 20 万步以上，同一容量就会开始环形覆盖，年龄停止增长、保留率降到 50% 附近，行为从"记住一切"切换为"记住最近 10 万步"。small 的 2000 对应约 10 个回合，刚好覆盖一个策略改进周期，用来观察"遗忘开始拖后腿"的临界点；noreplay 的 256 等于一个 batch，是"有池子但等于没有"的极限对照。

数据流

每个模式的完整流程：环境步进 → buffer.add(..., step) 写入（带出生时刻）→ 每步从池中均匀抽样并做一次 SAC 更新，同时记录该批次的平均年龄 → 每 4000 步评估并打印近 20 回合回报、评估回报、保留率、数据年龄四列 → 首次评估回报达到阈值 −400 时记录达标步数。三种模式共用随机种子与全部超参数，只有池容量不同。

复用倍数的两个杠杆与口径

把公式再推一遍，可以厘清两个容易混淆的杠杆。均匀采样、稳态下，一条经验的期望使用次数等于"批量 × 每步更新次数"，与容量无关：update_every=1 时约 256 次，改成 2 时约 512 次，三种模式同步变化。容量决定的是另一件事，经验在池里停留多少步：环形覆盖一轮需要写入 C 条新数据，所以驻留步数约等于容量。大池的样本被反复取用但发生在很长的时间窗里，小池的取用密集但样本很快消失。两个杠杆在日志上的表现也不同：把 update_every 翻倍，保留率与年龄不变（容量与写入速率都没变），更新次数与训练耗时翻倍；把容量翻倍，更新次数不变，年龄分布整体后移。

模块划分

与前一章的差异点

  • 第 042 章改的是 Q 值组合方式，数据管道全线共用；本章反过来，算法保持标准 min 双 Q，只改回放池容量。
  • 回放池新增 stamp 与 sample(current_step)，把"数据新鲜度"变成可观测量。
  • 主流程从"依次训练三种估计器"改为"依次训练三种回放模式"，汇总达标步数、保留率、平均年龄。

关键代码与解读

片段 1：给回放池装上"出生时刻"

class ReplayBuffer:
    """定长回放池；额外记录每条经验存入时的环境步数，便于统计数据新鲜度。"""

    def __init__(self, capacity: int, obs_dim: int, act_dim: int):
        self.capacity = capacity
        self.obs = np.zeros((capacity, obs_dim), dtype=np.float32)
        self.next_obs = np.zeros((capacity, obs_dim), dtype=np.float32)
        self.act = np.zeros((capacity, act_dim), dtype=np.float32)
        self.rew = np.zeros((capacity, 1), dtype=np.float32)
        self.done = np.zeros((capacity, 1), dtype=np.float32)
        self.stamp = np.zeros(capacity, dtype=np.int64)  # 存入时的环境步数
        self.ptr = 0
        self.size = 0

    def add(self, obs, act, rew, next_obs, done, step: int) -> None:
        i = self.ptr                         # 环形指针：写到哪、下一轮先覆盖谁
        self.obs[i] = obs
        self.act[i] = act
        self.rew[i] = rew
        self.next_obs[i] = next_obs
        self.done[i] = done                  # 只记录真实终止，截断不入库
        self.stamp[i] = step                 # 记下"出生时刻"，供年龄统计
        self.ptr = (self.ptr + 1) % self.capacity
        self.size = min(self.size + 1, self.capacity)

    def sample(self, batch_size: int, current_step: int = 0) -> dict:
        """均匀采样；current_step 用于计算被采样数据的平均年龄。"""
        idx = np.random.randint(0, self.size, size=batch_size)
        age = float(np.mean(current_step - self.stamp[idx])) if current_step else 0.0
        return {
            "obs": torch.as_tensor(self.obs[idx]),
            "act": torch.as_tensor(self.act[idx]),
            "rew": torch.as_tensor(self.rew[idx]),
            "next_obs": torch.as_tensor(self.next_obs[idx]),
            "done": torch.as_tensor(self.done[idx]),
            "age": age,
        }

解读：三个设计点值得记住。（1）预分配 numpy 数组 + 环形指针 ptr：add 是 O(1) 的纯内存写入，ptr 回绕后自动覆盖最旧样本，"遗忘"就发生在这一行。容量 256 的 noreplay 模式因此只保留最近一个 batch。（2）done 只写 float(terminated)：时间截断不入库，bootstrap 语义才正确。（3）sample 用 current_step − stamp[idx] 的均值算年龄：一行代码把"数据新鲜度"变成可观测量；返回 dict 里带 age，训练循环顺手就能把它记进日志。

片段 2：三种模式只差一个容量

def train_mode(mode: str, args):
    """mode: replay（大池）/ small（小池）/ noreplay（只用最新 batch）。"""
    set_seed(args.seed)                      # 三种模式同种子，做控制变量对比
    if mode == "replay":
        capacity = args.buffer_size          # 大池：约 500 个回合的历史，样本多样
    elif mode == "small":
        capacity = args.small_capacity       # 小池：只记住最近约 10 个回合
    else:
        capacity = args.batch_size           # 伪在线：容量恰好一个 batch

    env = make_env(args.env, args.seed)
    eval_env = make_env(args.env, args.seed + 100)   # 评估环境独立，互不干扰
    obs_dim = env.observation_space.shape[0]
    act_dim = env.action_space.shape[0]
    action_scale = float(env.action_space.high[0])
    agent = SAC(obs_dim, act_dim, action_scale, args)
    buffer = ReplayBuffer(capacity, obs_dim, act_dim)

    min_size = args.start_steps if mode != "noreplay" else args.batch_size
    obs, _ = env.reset(seed=args.seed)
    solved_at = None

解读：（1）三种模式的差异全部集中在这一个 if/elif 里，这正是本章想证明的观点：数据管道是纯工程改动，算法一行不动。（2）noreplay 把容量设成 batch_size，环形缓冲自动退化成"只装最新 256 条"；min_size 也跟着放宽到 batch_size，因为池子小、必须尽早开始更新。（3）评估环境用 seed + 100 独立种子：训练环境每回合被重置和扰动，评估环境保持固定初始分布，两条数据流互不污染。

片段 3：训练循环里的采样、年龄与保留率

    for step in range(1, args.max_steps + 1):
        if step <= args.start_steps:
            action = env.action_space.sample()            # 预热期纯随机，铺开状态覆盖
        else:
            action = agent.act(obs, deterministic=False)
        next_obs, rew, terminated, truncated, _ = env.step(action)
        buffer.add(obs, action, rew, next_obs, float(terminated), step)
        collected += 1
        obs = next_obs
        ep_ret += rew

        if terminated or truncated:                       # 两种结束都重置环境
            ep_returns.append(ep_ret)
            ep_ret = 0.0
            obs, _ = env.reset()

        if step % args.update_every == 0 and buffer.size >= min_size:
            batch = buffer.sample(args.batch_size, step)  # 采样带上 step 才能算年龄
            agent.update(batch, args)
            n_updates += 1
            ages.append(batch["age"])                     # 年龄序列留给评估点打印

        if step % args.eval_every == 0:
            eval_ret = evaluate(agent, eval_env, args.eval_episodes)
            mean_age = float(np.mean(ages[-200:])) if ages else 0.0
            history.append((step, eval_ret, mean_age))
            recent20 = np.mean(ep_returns[-20:]) if ep_returns else float("nan")
            retention = buffer.size / max(collected, 1)   # 保留率 = 驻留 / 累计收集

解读：这几行的逻辑是"每环境步一条数据、一次更新"，update_every=1 意味着数据被复用的机会最大。（1）buffer.add 与 buffer.sample 都传了 step：前者记出生时刻，后者算年龄，两个参数串起整套新鲜度统计。（2）ages[-200:] 取最近 200 次更新的平均年龄，避免受早期波动干扰。（3）保留率用"当前池内样本 ÷ 累计收集"计算，随训练单调下降并稳定在容量与总步数的比值附近，noreplay 稳定在约 1.3%，小池约 10%，大池继续走低。想知道另外两个模式谁达标更快，看 solved_at 与评估列即可。

python code/ch043.py --quick    # 快速跑通：4000 步/模式，约 1 分钟
python code/ch043.py --modes replay,noreplay --small-capacity 1000   # 自定义对照

预期：replay 达标最快、曲线最平滑；noreplay 最慢甚至跑不到阈值，近 20 回合回报抖动明显更大；small 居中。年龄一栏近似恒定：256 池约 128 步、2000 池约 1000 步、大池随训练线性增长到几千步。达标步数以实跑为准，换种子时绝对回报有 ±50 左右波动，相对次序通常稳定。

常见坑

  • 把 truncated 写进 done：Pendulum 每回合 200 步是时间截断。若把它当终止写入回放池，所有回合边界的目标值都被砍成单步奖励，Q 值系统性偏低，策略会"怕结束"而不做长程规划。修复：只存 float(terminated)。
  • 容量小于 batch_size：采样反复抽到同几条数据，多样性名存实亡。修复：保证容量至少是一个 batch。
  • 以为回放池越大越好：容量翻倍意味着平均年龄线性增长，在非平稳任务（课程、迁移）里会大量使用"旧策略下的次优数据"，表现为前期快、后期停滞。修复：先看年龄指标，再决定容量。
  • 三组对照其实不同种子：改了容量却忘了固定种子，"结论"可能只是随机波动。修复：像 train_mode 这样每次训练开头 set_seed，并保持预算一致。

练习与思考

  1. 把 --small-capacity 依次设为 500、5000、20000 跑 --modes small，找出"容量-样本效率"曲线的拐点大约在哪。★
    提示
    只改一个参数，看达标步数与最终评估。容量小到不足一两个回合（400 步/回合）的数据量时，轨迹多样性会先成为瓶颈。
  2. 把 --update-every 从 1 改成 2，三种模式再跑一次。noreplay 的相对劣势变大还是变小？预测并验证。★★
    提示
    更新频率减半后，noreplay 里一条经验的"寿命"也翻倍（平均被用到两次）。先写清楚：更新次数少了，每次更新依据的数据分布没变，猜想再跑。
  3. 为什么 eval_env 要用 seed + 100、与训练环境分开？如果训练和评估共用环境实例，日志会出现什么异常？★★
    提示
    评估时的 env.reset() 会打断训练轨迹的连续性，训练统计（ep_returns）与评估互相污染；从"数据流隔离"的角度分析。
  4. 在 ReplayBuffer.sample() 里改成"只保留最近 50% 数据再均匀采样"，重跑 replay 模式，比较达标步数与平均年龄，讨论有偏采样的利弊。★★
    提示
    最简单的实现：池满时用 (self.ptr + k) % capacity 推算最新半区起点再采样。年龄应减半，注意环形指针下"最新的一半"是 ptr 附近的索引。
  5. 把对比口径从"固定环境步数"换成"固定总梯度更新次数"（例如 8000 次），重新对比 replay 与 noreplay。说明两种口径下结论的差别，以及为什么真实工程里更常用"固定环境步数"。★★★
    提示
    把两种模式的 max_steps 换算到更新次数一致。思考：梯度计算的边际成本几乎为零，样本效率应以谁为分母。

小结

  • 经验回放把一条交互放大的梯度次数可以提高一到两个数量级，是 SAC 样本效率的主要来源。
  • 容量的收益是"多样性 + 不遗忘"，代价是"数据变旧"；本章用保留率与数据年龄两个仪表把它量化。
  • 伪在线（noreplay）实现简单、样本新鲜，但数据强相关且历史全扔，达标更慢、曲线更抖。
  • 回放池是纯数据结构改动，换容量不改算法即可复现全部结论，这是 off-policy 方法的工程魅力。
  • 复用倍数在稳态下约等于批量大小（每步更新、均匀采样时约 256 次），容量真正改变的是数据的时间跨度与多样性。
  • 保留率与年龄是一对互补仪表：保留率说明"历史被丢了多少"，年龄说明"手上数据有多旧"，两者都要看才能解释训练曲线。
  • 下一章给回放池装上"优先级"：把均匀抽样换成"TD 误差大的样本获得更高被抽中概率"，用同样的计算量换更快的收敛。
