第二篇 · 离策略方法与 SAC

第 035 章：SAC的奖励尺度敏感性

把 Pendulum 的奖励整体乘 0.1、1、10，其他一切不变。你会看到 Q 值随尺度等比缩放、alpha 被自动温度调节拉向两边，原来"奖励缩放等价于改熵的价格"。

  • 主题：奖励尺度 / 熵的相对价格
  • 关键公式：Jc(π) = c·𝔼[ Q(s,a) − (α/c)·log π(a|s) ]（奖励乘 c ⟺ 温度除 c）
  • 预计学时：45 分钟
  • 前置章节：第 034 章

学习目标

  • 推导"奖励乘常数 c 等价于把温度系数除以 c"这一核心结论，理解奖励尺度为什么重要。
  • 实现训练奖励缩放（训练端乘 scale、评估端保持原始奖励）的干净口径。
  • 在 Pendulum-v1 上对比 scale = 0.1 / 1 / 10 的评估回报、|Q| 幅度与 alpha 轨迹。
  • 理解自动温度调节对奖励尺度的"部分补偿"能力，以及这种补偿的边界。

背景与动机

你可能已经见过这样的建议："把奖励除以 100"或"把奖励乘 10 训练更稳"。在多环境、多任务的项目里，不同环境的奖励量纲差异巨大：CartPole 每步 +1，Pendulum 每步 −0.1 到 −16，MountainCarContinuous 撞到目标一次 +100。如果算法对奖励尺度敏感，你就得为每个环境单独调参，这正是工程里最烦人的成本。

SAC 号称对奖励尺度比较鲁棒，原因是它有一个自适应温度的旋钮。但"鲁棒"到什么程度、边界在哪里，光看论文的一句话不够。本章把 scale 当成唯一的自变量，把 SAC 对它的响应拆成三个可观测量：回报（任务学得怎么样）、|Q|（价值量纲缩了多少）、alpha（熵的相对价格变了多少）。做完这一章，你会知道什么时候该调奖励尺度、什么时候调了也是白调。

核心原理

1. 奖励缩放与熵价格的等价变换

把训练的每一步奖励乘以常数 c，最优 Q 函数也等比缩放 c 倍（Bellman 方程是线性的）。把它代入 SAC 的策略目标：

Jc(π) = 𝔼[c·Q(s,a) − α·log π(a|s)] = c · 𝔼[ Q(s,a) − (α/c)·log π(a|s) ] 提出常数 c 后：奖励缩放 c 倍 ⟺ 温度系数变成 α/c

这意味着 scale=0.1 相当于把 alpha 放大 10 倍（熵变得更"贵"，策略倾向随机）；scale=10 相当于把 alpha 缩小 10 倍（策略倾向贪婪）。如果你的 alpha 是固定常数，奖励尺度就绝不是无关紧要的细节，这解释了为什么"换个任务就要重调 alpha"是常态。推导只有两步：Bellman 方程对奖励是线性的，设原始最优价值为 Q*，则缩放后的最优价值 Qc = c·Q*（可以逐层代入验证：奖励线性的期望也是线性的）；把它代入 SAC 目标并提取公因子 c，就得到等价形式。第三个推论是：把奖励乘 c 且把温度除 c 之后，策略的驻点完全相同，也就是说这一对操作对固定温度模式属于"重参数化"，问题的最优解并未改变。这一推论可以直接当自检使用：在固定温度模式下，用 (c=10, α=0.02) 与 (c=1, α=0.2) 两组配置、同一随机种子各训一遍，两条评估曲线应当逐点接近；若明显分叉，说明缩放或温度至少有一处没有按预期进入目标值。注意自动温度模式不满足这条精确等价，只保证同一个驻点集合，轨迹会因反馈回路而不同。

数值例子：三个尺度下各量纲的对账

取训练中期的典型读数：原始尺度 |Q| ≈ 42，策略熵 ≈ 1.5（logp ≈ −1.5），alpha ≈ 0.2。逐个尺度计算：

scale=1：|Q| ≈ 42；策略损失里 Q 项 ≈ 42，熵项 ≈ 0.2×1.5 = 0.3，熵项占比约 0.7%。

scale=0.1：|Q| ≈ 4.2；熵项仍是 0.3（它不含奖励），占比升到约 6.7%，熵的相对话语权放大约 10 倍，策略更随机，熵高于目标后 alpha 被压低，实测约 0.11。

scale=10：|Q| ≈ 420；熵项占比降到约 0.07%，Q 项几乎垄断策略更新，策略更确定，熵低于目标后 alpha 被抬高，实测约 0.38。

解读：三行的 |Q| 呈 4.2 → 42 → 420 的等比数列（可用作缩放生效的自检），而熵项的绝对数值纹丝不动，占比却横跨约 100 倍。奖励缩放真正改变的是两项目标的相对权重；alpha 的自动调节只能改变熵项这一侧，无法把 Q 的量纲拉回来。把三行折成一句话：|Q| 等比缩放、熵项保持定值、α 反向小幅补偿，三条轨迹拼起来就是本章的全部结论。

2. 自动温度如何"部分补偿"

自动温度调节的损失只依赖 log π 与目标熵，不直接看奖励数值：

L(α) = −𝔼[ log α · ( log π(a|s) + H̄ ) ]，α 只追"熵缺口"

于是出现一个有趣的负反馈：奖励被压小（scale=0.1）时，策略损失里熵项相对占优、策略变随机，熵高于目标，alpha 被压低去恢复平衡；奖励被放大（scale=10）时，Q 项占优、策略变确定，熵低于目标，alpha 被抬高。所以自动模式下 alpha 会部分抵消奖励缩放的影响，但作用在"熵"这一侧，Q 的量纲和梯度尺度仍然实实在在地缩放了 c 倍，这才是尺度改变后训练手感变化的主因。

把"部分补偿"说清楚一点：固定温度时，"奖励乘 c、温度除 c"是精确等价；自动温度时，温度本身会随熵缺口移动，等价变换里的 (α/c) 不再是一个可控常数，因此两边的策略不会完全相同。反馈回路能恢复的只是"熵水平回到目标附近"这件事，它不改变 Q 的量纲，也不改变梯度随 c 缩放的事实。所以正确的表述是：自动温度只是把 SAC 可训练的尺度范围拓宽，尺度本身仍然要紧。想验证这一点，可以把同一个训练好的策略分别在三种尺度的目标函数上评估其策略损失，Q 项的差异会直接暴露出来。

3. 可预测的三个签名

  • |Q| 幅度 ∝ c：scale=10 时收敛后的 |Q| 约为基线的 10 倍，scale=0.1 约为 1/10。
  • alpha 方向：scale=0.1 压低 alpha，scale=10 抬高 alpha（如上节的负反馈）。
  • 学习速度：过大或过小都会变慢，太小则有效梯度小（信噪比差），太大则优化更"脆"（有效学习率被放大）。

关于第三条签名，用 Adam 时有一个容易误解的地方：Adam 把参数位移大致归一化到学习率的量级，Q 损失的绝对梯度大小并不会直接决定 Q 网络的步长。尺度的真实影响走两条通道。其一，策略损失里 Q 项与熵项的配比被 c 改变，Adam 归一化的是两者之和，不会修复配比，策略更新方向因此被尺度左右。其二，TD 目标的数值幅度随 c 放大，而网络容量与参数空间不变，等价于目标的信噪比发生变化：同样的相对误差在 scale=10 时带来 10 倍的绝对扰动。这两条通道合起来解释了"两端都变慢"：c 太小，策略方向被熵项接管；c 太大，目标扰动被放大，训练手感变脆。

三者都可以在日志里直接读出来，这就是本章实验设计的意义：把"敏感性"翻译成可测量的数字。把三个签名的预期值整理成表：

读数scale=0.1scale=1（基线）scale=10
收敛后的 |Q|约 4，基线的 1/10约 42约 420，基线的 10 倍
alpha 终值约 0.11，被压低约 0.2约 0.38，被抬高
策略随机性偏高：熵项话语权大基准偏低：Q 项主导更新
评估回报（原始口径）明显落后通常最好接近或略差，更脆

这张表同时是实验的检查清单：跑完三组后逐行核对，任何一行方向不符，优先怀疑缩放位置或评估口径出了问题。

4. 极端尺度的失效模式与安全区间

用上面的量纲算术可以给"尺度多大算安全"划一条线。策略损失里两项目标的相对大小是 α·|logπ| 与 c·|Q|，令两者相等得到临界尺度 c* = α·|log π| / |Q|。代入典型读数（α=0.2、|log π|≈1.5、|Q|≈42）得 c*≈0.0071。三个默认档位中，0.1 约为 c* 的 14 倍，1 与 10 更高，都站在"Q 主导"的一侧，熵项占比只从 6.7% 递减到 0.07%。公式还提示：α 越大或 |Q| 越小，临界值越高、安全区越窄，这解释了为什么小奖励环境对尺度变化更敏感。

当 c 远低于 c*（例如 1e-4），失效模式是熵奖励压倒任务信号。此时单步奖励量级约 1e-4，而熵项在 TD 目标里的贡献是 α·|log π|≈0.3，大三个数量级。把数代入固定点计算：Q ≈ (r̄ + γ·α·H)/(1−γ) ≈ (−0.0001 + 0.99×0.3)/0.01 ≈ 29.7，奖励项自己的贡献只有 |r̄|/(1−γ) ≈ 0.01。价值函数编码的主要是"策略有多随机"，奖励差异被淹没，策略退回接近均匀随机的行为，评估回报停在随机基线附近。另一端把 c 放大到 100 时，|Q| 平台约 4200，TD 目标里 1% 的相对误差就是 42 的绝对扰动，与基线档位的整个 Q 值同量级，这就是"更脆"的算术解释：同样的相对噪声对应成倍放大的绝对扰动。合理的应对方式是换到更稳的机制；继续在原地调整尺度收益有限，第 040 章的奖励归一化就是为此准备的。

实现思路与设计

数据流

每种尺度：set_seed → 采样时把环境奖励乘 scale 后才入回放池（原始奖励另行累计用于呈现）→ 每步一次 SAC 更新（Q 与熵项的量纲差异在这里产生）→ 每 3000 步在原始环境上评估并记录 |Q|、alpha、熵 → 保存模型、打印 |Q| 轨迹汇总。三组唯一的不同就是训练端的那个乘数。

与前一章的差异点

  • 第 034 章改的是"什么时候更新"；本章不动网络与调度，只把训练奖励乘一个常数。
  • 缓冲区存缩放后的奖励，评估端使用原始奖励，这套"训练/评估口径分离"是本章新增的实现约束。
  • 日志改为同时打印原始回报与训练回报，方便交叉验证缩放是否正确生效。
  • 实验输出新增"|Q| 轨迹"和"alpha 轨迹"两组读数，用于验证第 2、3 节的预测。
训练端缩放、评估端原始，口径分离是硬约定

缩放必须作用到数据流的最前端（入池之前），这样 TD 目标、Q 损失、策略损失全部看到同一个尺度的数值；评估则永远在未缩放环境上进行。两个口径混用的后果：要么"10 倍关系"自检失效（缩放没真正进入训练），要么回报曲线被数值假象污染（评估也缩放了）。日志里两列并存（近 20 训练回报 vs 评估原始回报），就是给这套约定上的保险。若两列在同一尺度下长期无法互相解释（例如训练回报很好而评估极差），应当立刻停训检查缩放位置与评估环境；继续加预算无助于解决口径问题。

关键代码与解读

片段 1：缩放发生在哪里，入池前的一行乘法

        next_obs, rew_raw, terminated, truncated, _ = env.step(action)
        rew = rew_raw * scale              # 训练奖励按尺度缩放（唯一改动点）
        buf.add(obs, action, rew, next_obs, float(terminated))
        obs = next_obs
        ep_ret_raw += rew_raw              # 原始回报：用于对照与呈现
        ep_ret_scaled += rew               # 训练回报：反映实际喂给算法的信号

        if terminated or truncated:
            ep_returns_raw.append(ep_ret_raw)
            ep_returns_scaled.append(ep_ret_scaled)
            ep_ret_raw, ep_ret_scaled = 0.0, 0.0
            obs, _ = env.reset()

解读：整章的实验设计浓缩在这一行乘法里。（1）缩放的位置至关重要：必须在 buf.add 之前。放进回放池的奖励会一路进入 TD 目标与 Q 损失，三个尺度的差异就是这么"长"出来的；如果只在日志里乘、忘了入池，训练行为完全不变，这正是最廉价的自检（|Q| 是否呈 10 倍间距）能抓出的错误。（2）两套回合累计并存：ep_ret_raw 记录真实成绩，ep_ret_scaled 就是算法眼里的数字。三组之间比较必须用前者，观察"信号强度"用后者。（3）环境本身不修改：rew_raw 来自未包装的 Pendulum，缩放是纯训练侧行为，评估环境完全独立。

片段 2：三个量纲在一段更新里相遇

        # 评论家：目标值里的奖励已经是缩放后的数值
        with torch.no_grad():
            next_act, next_logp = self.policy.sample(next_obs)
            q_next = torch.min(self.q1_target(next_obs, next_act),
                               self.q2_target(next_obs, next_act))
            target = rew + self.gamma * (1.0 - done) * (
                q_next - self.current_alpha * next_logp)

        q1_pred = self.q1(obs, act)
        q2_pred = self.q2(obs, act)
        q_loss = F.mse_loss(q1_pred, target) + F.mse_loss(q2_pred, target)

        self.q_optimizer.zero_grad()
        q_loss.backward()
        self.q_optimizer.step()

        # 演员：Q 项随奖励尺度缩放，熵项的相对价格因此改变
        new_act, logp = self.policy.sample(obs)
        q_new = torch.min(self.q1(obs, new_act), self.q2(obs, new_act))
        policy_loss = (self.current_alpha * logp - q_new).mean()

解读：把这段当"电路图"读，就能理解三个签名的来源。（1）TD 目标 rew + γ·(q_next − α·logπ)：rew 与 q_next 都随 c 缩放，而 α·logπ 只随 α 变，奖励尺度的一部分差别被"稀释"在熵项里。（2）Q 损失回归的靶子整体缩放了 c 倍，因此收敛后的 |Q| 必然 ∝ c（第一条签名）。（3）策略损失 α·logπ − q_new：Q 项随 c 缩放、熵项不缩放，两者的相对权重被尺度改变，这就是"奖励缩放等价于改熵价格"在代码里的模样。温度损失完全不碰奖励，所以 α 只能通过"熵缺口"间接感知尺度（第二条签名）。注意 alpha_loss 未在此片段中，但它的输入只有 logp，与 c 无关，三行组合起来，负反馈回路才成立。

片段 3：评估必须用原始奖励

@torch.no_grad()
def evaluate(env, agent, episodes):
    """统一在原始（未缩放）奖励上进行评估，保证三组可比。"""
    returns = []
    for _ in range(episodes):
        obs, _ = env.reset()
        done = False
        ep_ret = 0.0
        while not done:
            action = agent.act(obs, deterministic=True)
            obs, r, terminated, truncated, _ = env.step(action)
            ep_ret += r                     # 原始奖励，绝不乘 scale
            done = terminated or truncated
        returns.append(ep_ret)
    return float(np.mean(returns))

解读：评估函数与训练循环共用代码越多，越容易把缩放"泄漏"进来，本章干脆让评估走一条完全独立的路径。（1）env 是专门创建的评估环境，从头到尾不接触 scale；ep_ret += r 累加的永远是原始奖励。（2）若评估也乘了 scale，scale=10 的组会"看起来赢了 10 倍"，纯数值假象，还会让读者误判尺度对任务表现的影响方向。（3）注意评估用 deterministic=True：与前面章节一致，成绩单只反映策略的确定性水平，不混入采样噪声。

片段 4：日志，让三个签名同框出现

        if step % args.eval_every == 0 or step == args.max_steps:

            recent_scaled = float(np.mean(ep_returns_scaled[-20:])) \

                  f"alpha {agent.current_alpha:.3f} | 熵 {last_stats['entropy']:.3f}")

解读：一行日志承载本章全部证据链。（1）"近 20 训练回报"用的是缩放后的数字（recent_scaled），它回答"算法看到的信号有多大"；"评估(原始)"用未缩放的数字，它回答"策略真实水平如何"。两列并列，任何口径泄漏都会立刻露馅。（2）|Q| 与 alpha 的轨迹被存进 history：前者验证"|Q| ∝ c"的第一签名，后者验证"alpha 反向补偿"的第二签名。（3）训练结束后的汇总再打印各组 |Q| 的后三点，三行数字摆在一起（例如 4 / 42 / 423），缩放的等比关系一目了然；这就是"10 倍关系自检"的最终落点。

完整可运行脚本（附录）：code/ch035.py

python code/ch035.py           # scale = 0.1 / 1 / 10：CPU 约 6–10 分钟
python code/ch035.py --quick   # 快速跑通：约 1 分钟
python code/ch035.py --scales 0.1,1.0 --max-steps 30000   # 只对比被压缩的两档

以实跑为准：|Q| 近似按比例缩放（典型 4 / 42 / 423）；alpha 在 scale=0.1 时被压低（约 0.11）、scale=10 时被抬高（约 0.38）；最终评估以 scale=1 最好，0.1 明显落后（有效梯度太小），10 略差或接近但更"脆"。方向性结论通常稳定复现，具体数值随种子波动。

常见坑

  • 评估也乘了 scale：三组回报变成不同量纲，看不出真实差异。修复：训练端缩放、评估端原始，这是本章的硬约定。
  • 只有日志乘了 scale，目标值没乘：TD 目标仍是原尺度，Q 会收敛到错误量级。修复：自检就用"10 倍关系"，|Q| 不呈等比缩放说明缩放没进入数据流。
  • 以为自动温度能完全吸收尺度变化：alpha 只追熵目标，Q 的量纲与梯度尺度不归它管。scale 极端时任务表现仍会明显变化。
  • 缩放后忘了看 alpha 的上界：scale=10 时 alpha 可能一路爬升。修复：若 alpha 超过 1 还在涨，说明熵目标相对奖励已经过高，考虑调整 --target-entropy。
  • 在环境包装层缩放后又重复乘一次：某些人会同时在 env wrapper 与主循环里缩放，结果实际尺度是 c²。修复：缩放只保留一个位置（本章：入池前一行）。

练习与思考

  1. 把固定温度模式（把 alpha_loss 那段去掉并冻结 alpha=0.2）跑一遍三个尺度，对比自动温度下差别有多大。★
    提示
    最省事的做法是把 self.log_alpha 换成 torch.tensor(math.log(alpha)) 且不建优化器。固定 alpha 时 scale=0.1 预计明显更差，没有补偿机制了。
  2. 把尺度序列改为 0.01,0.1,1.0,10,100，找出"回报明显掉队"的两个端点区间。★★
    提示
    每端多跑两个种子，否则分不清"掉队"与"运气"。注意观察 |Q| 掉到个位数以下或涨到几百以上时，训练是否开始发散或停滞。
  3. 给 scale=10 的组做一次"等价换算"：保持奖励不缩放，把 --alpha 初值改为 0.02 并且关掉自动温度，看看评估回报是否接近 scale=10 的表现。这个实验验证了什么？★★
    提示
    验证第 1 节的等价性 α/c。等价换算只在"固定 alpha"下严格成立；自动温度会额外调整，因此两组不会完全一致。
  4. 实现 reciprocal 缩放：scale = 1 / (|近期回合回报| 的滑动均值 + 1e-6)，每 500 步更新一次。与固定 scale=1 对比收敛速度与 |Q| 稳定性。★★★
    提示
    相当于第 040 章奖励归一化的雏形。注意缩放值要 clamp 到 [0.01, 100] 防止早期回报接近 0 时数值爆炸。
  5. 把"|Q| 呈等比缩放"写成自动检查：训练 5000 步后比较三组的 |Q|，断言 |Q|10 / |Q|1 落在 [5, 20]，|Q|1 / |Q|0.1 同理。断言失败时你会先排查哪一行代码？★
    提示
    先查入池前的那行乘法，再查 TD 目标里是否误用了未缩放奖励。这个断言比肉眼看曲线更早发现问题。

小结

  • 奖励乘 c 等价于把温度系数除以 c：SAC 目标可以写成 c·𝔼[Q − (α/c)·log π]。
  • 自动温度会沿"熵"这一侧反向补偿：scale 小则 alpha 被压低，scale 大则 alpha 被抬高。
  • |Q| 幅度与奖励尺度成正比，这是判断缩放是否生效的最快自检。
  • Pendulum 上 scale=1 通常最好；0.1 因有效梯度太小而明显落后；10 虽然能学但更脆。
  • 训练端缩放与评估端原始的口径分离是本章的硬约定：回报用原始奖励比较，|Q| 用缩放后数值自检，两者缺一不可。
  • 下一章回到策略网络内部：重参数化梯度与得分函数梯度（似然比）的方差对比，看看连续动作 SAC 为什么非用重参数化不可。
