第 088 章：多智能体环境：捕食者-猎物

在 12×12 的网格世界里放 3 个会学习的捕食者和 2 个会逃跑的脚本猎物：捕食者用共享网络的独立 Q 学习训练，看它们能不能从"追不上"进步到"包抄围堵"，全歼率从随机基线的接近 0 抬到 0.3 以上。

  • 主题：环境设计 / 网格世界与独立 Q 学习（IQL）
  • 关键公式：ri,t = −0.02 − 0.05·dmin + 1.0·𝟙[本步有猎物被捕获]
  • 预计学时：55 分钟
  • 前置章节：第 087 章

学习目标

  • 理解"学习体 vs 脚本对手"的混合环境设计：捕食者学习、猎物按确定性逃逸策略移动，以及脚本对手在基线与课程中的价值。
  • 掌握共享网络的独立 Q 学习（Independent Q-Learning, IQL）：ε-贪婪逐智能体探索、共享回放池、目标网络、平滑 L1 损失。
  • 掌握网格环境的观测设计：相对坐标归一化、被捕获实体的占位编码、切比雪夫距离（Chebyshev distance）的用法。
  • 用"全歼率、平均捕获数、首次捕获步数"三个指标衡量围捕行为的进化，并与随机基线对照。
  • 解释共享捕获奖励如何把"各追各的"改造成"分头包抄"。

背景与动机

捕食者-猎物（predator-prey）是多智能体研究的元老级任务：它同时包含协作（捕食者要合围）、对抗（猎物要逃跑）、稀疏奖励（只有捕获那一刻有大分）与长时序规划（把猎物逼向墙角）。第 087 章的粒子环境奖励是稠密的势函数，本章第一次把稀疏的成功信号放到主角位置，这正是检验"探索能力"的场景。

为什么猎物用脚本策略、不一起学？两个原因：其一，学习对手会让训练变成非平稳博弈，收敛性讨论复杂，不适合当作环境入门；其二，脚本对手行为可复现，可以放心比较"训练 1 万步"与"训练 5 万步"的差距。等到第 089、100 章再引入会学习的对手与自博弈。另一个新元素是离散动作：网格世界里"上下左右"比连续推力更自然，算法也随之从 PPO 换成 Q 学习家族，后面第 090、092 章会继续用它。

核心原理

1. 独立 Q 学习与参数共享

每个捕食者 i 维护自己的动作价值函数，目标是标准的 Bellman 最优方程：

Qi(oi, a) ← Qi(oi, a) + η·[ ri + γ·maxa′ Qitarget(o′i, a′) − Qi(oi, a) ]

符号：η 是学习率、γ=0.95 折扣、Qtarget 是周期性同步的目标网络（每 200 次更新同步一次）。从其他捕食者的视角看，队友的策略在变化，环境是非平稳的，IQL 用"经验回放 + 目标网络"缓解偏差，但无法根治；本章任务规模小、回合短，这个简化版本足够跑出分工行为。工程上再把三个捕食者的网络参数共享：观测是相对坐标、动作与奖励结构同构，一个网络服务全队，训练数据直接 ×3。

2. 脚本猎物的逃逸策略

猎物在 8 邻域里选择"离最近捕食者最远"的格子，加一点均匀噪声打破对称：

cell* = argmaxc∈N8 [ mini dist∞(c, pi) + ξ ], ξ ∼ U(0, 0.4)

dist∞ 是切比雪夫距离（行差与列差的较大者），它同时覆盖水平、垂直与对角移动，与捕获判定用同一把尺子，避免"视觉上贴着却不算抓到"的挫败感。噪声 ξ 的作用是防止猎物在两个等价方向间来回抖动，也避免捕食者面对一个完全确定性的对手过拟合。注意猎物不会主动远离边界，这正是"逼向墙角"战术成立的前提。

3. 奖励设计：共享捕获 + 聚集塑形

ri,t = −0.02 − 0.05·dmin(i, 存活猎物) + 1.0·𝟙[本步有猎物被捕获]

捕获奖励发给所有捕食者：只要队友咬住猎物，你也能加分。这是把"个人英雄主义"改造成"团队围堵"的关键，若只奖励抓到的那一个，策略会退化成三个捕食者各自追逐。第二项 −0.05·dmin 提供稠密梯度，把"随便走"引导成"朝猎物走"；每步固定成本 −0.02 催促尽快结束战斗。两项配合时，捕食者学会的不只是靠近，还有"从远处绕后把猎物赶向墙角"。

4. 为什么需要随机基线

网格任务的回报数值没有绝对意义，唯一可靠的锚点是随机策略基线：随机捕食者偶尔也能撞上猎物。训练前先测 20 局随机基线的全歼率，训练后再测一次，两者的差才是学习带来的真实增量。报告里"全歼率 0.55"永远应该配上"随机基线 0.00"一起读，这是环境实验的书面礼仪。

与前一章的差异

第 087 章的粒子环境是连续控制 + 稠密势函数奖励，算法用 PPO；本章是离散网格 + 稀疏捕获事件，算法换成 Q 学习。技术要点也换了：ε-贪婪探索、目标网络、回放池这些"价值型"工具箱登场。后面第 090、092 章继续用 Q 学习家族，你会看到它们与 PPO/SAC 在不同任务形态下的分工。

两个让实验"可读"的设计

1) 首次捕获步数：全歼率是长链条指标、前期长期为 0；首次捕获步数会先动（59 → 40 → 20），让你在曲线还趴在 0 时就能判断学习是否发生。

2) 随机基线内建在脚本里：训练开始前先打印一次随机基线的三个指标，最后再做一次"基线 → 训练后"的对照打印，结论写在日志里，不靠记忆。

关键代码与解读

片段 1：观测构造，相对坐标与"死亡占位"

def _obs(self) -> np.ndarray:
    scale = float(self.size - 1)
    obs = []
    for i in range(self.n_predators):
        others = [self.pred_pos[j] - self.pred_pos[i]      # 队友相对坐标
                  for j in range(self.n_predators) if j != i]
        prey_rel = []
        for j in range(self.n_preys):
            if self.prey_alive[j]:
                prey_rel.append(self.prey_pos[j] - self.pred_pos[i])
            else:
                # 被捕获的猎物用角落 (size,size) 占位：与任何合法相对坐标都不同
                prey_rel.append(np.array([self.size, self.size]))
        o = np.concatenate([
            self.pred_pos[i] / scale,               # 自己坐标归一化到 [0,1]
            np.asarray(prey_rel[0]) / scale,
            np.asarray(prey_rel[1]) / scale,
            np.asarray(others).reshape(-1) / scale,
        ])
        obs.append(o.astype(np.float32))
    return np.stack(obs)

解读：网格观测的设计有两处小巧思。（1）全部除以 size−1=11 归一化：原始坐标是 0～11 的整数，直接喂网络会让输入尺度远大于权重初始化尺度，早期学习非常慢；除以最大值是零成本修复。（2）"死亡占位"：被捕获的猎物相对坐标置为 (size, size)/scale = (1,1)，归一化后正好是坐标上界，与任何"活猎物可能的相对坐标"（范围 −1～1）都不同。若用 (0,0) 占位，网络会把"猎物就在我身上"与"猎物已消失"混为一谈。（3）相对坐标让三个捕食者共享同一个网络：每个捕食者看到的都是"以我为原点"的世界，输入分布一致；（4）维度账：2（自己）+ 2+2（两只猎物）+ 4（两个队友）= 10 维，猎物数变化时占位逻辑自动适配。

片段 2：脚本猎物的逃逸与噪声

def _move_preys(self):
    """脚本猎物：在 8 邻域里选"离最近捕食者最远"的格子，带少量随机。"""
    for j in range(self.n_preys):
        if not self.prey_alive[j]:
            continue                                     # 已捕获的猎物不再移动
        best_score, best_cell = -1e9, tuple(self.prey_pos[j])
        for dr, dc in self.prey_delta:                   # 8 邻域（含对角）
            r = int(np.clip(self.prey_pos[j][0] + dr, 0, self.size - 1))
            c = int(np.clip(self.prey_pos[j][1] + dc, 0, self.size - 1))
            d_min = min(self._chebyshev([r, c], p) for p in self.pred_pos)
            score = d_min + self.rng.uniform(0.0, 0.4)   # 打破对称的噪声
            if score > best_score:
                best_score, best_cell = score, (r, c)
        self.prey_pos[j] = np.asarray(best_cell, dtype=np.int64)

解读：二十行不到，但猎物的"性格"全在这里。（1）目标是 max min-distance，最大化"到最近捕食者"的距离，等价于"别让任何人靠近我"，这是最朴素的逃逸理性。（2）噪声 U(0, 0.4) 的意义：当两个候选格子的距离相同时（比如两侧对称的空当），纯确定性规则会原地抖动；噪声让猎物"随机挑一边"，行为更自然，也让捕食者面对一个有随机性的对手而不至于过度拟合。（3）边界处理 np.clip：猎物撞墙就贴着墙走，它不会主动远离墙角，这正是捕食者"逼墙角"战术的物理基础。（4）用切比雪夫距离：网格上"斜对角移动一步"与"直走一步"耗时相同，切比雪夫才是这个动作系统下的真实距离，距离度量必须与移动模型一致。

片段 3：一步之内的顺序与共享奖励

def step(self, actions: np.ndarray):
    # 1) 捕食者移动：动作 0 是"原地"，1~4 对应上下左右；越界位置夹回场内
    for i in range(self.n_predators):
        dr, dc = self.move_delta[int(actions[i])] if int(actions[i]) > 0 else (0, 0)
        self.pred_pos[i, 0] = int(np.clip(self.pred_pos[i, 0] + dr, 0, self.size - 1))
        self.pred_pos[i, 1] = int(np.clip(self.pred_pos[i, 1] + dc, 0, self.size - 1))
    # 2) 猎物逃跑（脚本策略）
    self._move_preys()
    # 3) 捕获判定：捕食者动完、猎物逃完后，谁贴着谁就算抓住（切比雪夫 ≤ 1）
    captured_now = 0
    for j in range(self.n_preys):
        if not self.prey_alive[j]:
            continue
        for p in self.pred_pos:
            if self._chebyshev(p, self.prey_pos[j]) <= self.capture_dist:
                self.prey_alive[j] = False
                captured_now += 1
                break
    self.captures += captured_now
    self.steps += 1
    # 4) 奖励：聚集塑形 + 全队共享的捕获奖励
    rewards = np.zeros(self.n_predators, dtype=np.float32)
    alive = [self.prey_pos[j] for j in range(self.n_preys) if self.prey_alive[j]]
    if alive:
        for i in range(self.n_predators):
            d_min = min(self._chebyshev(self.pred_pos[i], q) for q in alive)
            rewards[i] = -0.02 - 0.05 * d_min
    rewards += 1.0 * captured_now    # 谁抓的都一样：全队 +1，合作信号的核心

解读：这段是环境的"时序骨架"，三处顺序设计值得单独记。（1）顺序是"捕食者先动 → 猎物后动 → 最后判定"：若先判定再逃跑，猎物永远能在判定与移动之间"偷跑"；若猎物先动，捕食者的追捕永远慢半拍、难度失衡。环境语义的公平性往往就藏在这样的顺序里。（2）捕获用切比雪夫距离 ≤1：意味着"贴身或斜对角"都算抓住，与 8 邻域移动匹配，避免"对角贴着却抓不到"的怪异体验。（3）共享奖励 rewards += 1.0 * captured_now 直接加给三个捕食者：这是协作激励的全部来源；注意 captured_now 可能等于 2（一步抓到两只），奖励会叠两份，这是有意保留的团队效率信号。（4）塑形项只在还有猎物存活时生效（if alive），全歼后不再有距离分，回合立即以 terminated 结束。

片段 4：逐智能体的 ε-贪婪

@torch.no_grad()
def act(self, obs_np: np.ndarray, epsilon: float, rng: np.random.Generator):
    """逐智能体的 ε-贪婪：每个捕食者独立决定是否随机探索。"""
    n = obs_np.shape[0]
    actions = rng.integers(0, self.args.n_actions, size=n).astype(np.int64)
    explore = rng.uniform(size=n) < epsilon      # 每个个体独立抛硬币
    if not explore.all():
        obs = torch.as_tensor(obs_np, dtype=torch.float32, device=self.device)
        greedy = np.argmax(self.q(obs).cpu().numpy(), axis=1).astype(np.int64)
        actions[~explore] = greedy[~explore]     # 不探索的行用网络贪心补齐
    return actions

解读：这个小函数定义了探索的行为模式。（1）"逐智能体"独立抛硬币：同一时刻可能一个捕食者在探索、两个在执行，进池的数据里既有稳健动作也有随机扰动，探索多样性更高。（2）实现上先整体采样随机动作，再用掩码决定"哪些行换成贪心"，比循环逐个判断快得多，也让随机数的消费顺序与个体数无关。（3）@torch.no_grad() 小优化：动作选择不需要梯度，省显存也省计算图。（4）评估时不走这个函数（直接 argmax），避免残留的 ε 噪声污染评估，这是下一节"坑"里最容易犯的错误之一。

常见坑

  • ε 衰减与预算量级脱节：把 --eps-decay-steps 设成 10 万而总预算只有 6 万，训练结束时 ε 还大于 0.4，评估自然好不了。保持衰减段与总步数同量级（默认 2.5 万 vs 6 万）。
  • 评估复用带 ε 的动作函数：最终 ε 是 0.05，如果评估也走 agent.act，曲线会永远压着 5% 的随机噪声、上限被压低。评估必须直接 argmax。
  • done 语义混乱：60 步截断时环境会 reset，回放池里的 done 若只写 terminated，下一局的状态会污染本局边界的目标估计。本实现选择"截断不切断"，因为全歼前捕获后仍有剩余步数可继续抓；换成别的语义也可以，关键是代码注释与实现一致、且你知道自己选了哪种。
  • 观测没归一化：坐标 0～11 直接喂网络会让输入尺度与权重初始化不匹配，早期训练极慢。除以 size−1 是零成本修复。
  • 忘掉"死亡占位"的尺度：捕获后猎物相对坐标置为 (size, size) 再归一化，得 (1,1)；若只置 size 忘了除以 scale，或用了别的常数，网络会把"已死"误当"就在旁边"。改占位编码时记得对齐归一化。

  3. 把距离塑形系数从 −0.05 调到 −0.2 和 0（去掉塑形）各跑一次，先解释两种极端各自会出什么问题，再验证全歼率。★★
    提示
    塑形为 0 靠稀疏奖励起步极慢，可把 ε 衰减拉长到 4 万步帮助探索；塑形过强时捕食者可能学会"贴着猎物绕圈"刷距离分。
  4. 把猎物换成"随机游走"（取消逃跑逻辑），先分析学习信号会怎么变，再比较两种情况的全歼率，这个对照有什么工程启示？★★
    提示
    把 _move_preys 的选格准则换成均匀随机即可。预期全歼率明显更高：对手越弱、学习信号越"稠密"。这正是课程学习从易到难的逻辑。
  5. 给猎物加"体力"：每回合只能连续移动 40 步，之后每 3 步才能动一次；先预测全歼率上限的变化，再重跑验证。★★★
    提示
    在 env 里维护 prey_fatigue 计数，_move_preys 里按规则跳过移动。反过来限制捕食者来调难度也可以，这就是手工版课程学习。

小结

  • 捕食者-猎物把稀疏奖励放进多智能体协作：捕获是全队事件，距离塑形提供稠密引导，每步成本催促效率。
  • 共享网络的 IQL 在小规模任务里性价比很高：一个网络、一个回放池训练 3 个捕食者，逐智能体 ε-贪婪保证探索多样性。
  • 脚本猎物让实验可复现，也给难度提供固定锚点；随机基线是评估"是否真的学到"的必要对照。
  • 指标分级看：先看首次捕获步数（短期信号），再看全歼率（长期目标）；距离度量（切比雪夫）要与移动模型匹配。
