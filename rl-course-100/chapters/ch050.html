第二篇 · 离策略方法与 SAC

第 050 章：SAC的自动超参数搜索

把"调参"做成流水线：在学习率、批大小、软更新系数、温度初值构成的网格上随机采样 6 组配置，每组用 5000 步短跑打分，再让冠军配置跑完整预算，对比试跑得分与重训得分的差距，理解短预算的偏差从哪来。

  • 主题：随机搜索（Random Search）/ 实验编排
  • 关键公式：得分 = mean(中途评估, 结束评估)
  • 预计学时：55 分钟
  • 前置章节：第 049 章

学习目标

  • 理解超参数搜索的三要素：搜索空间、预算分配、评分函数。
  • 实现随机搜索流程：离散网格采样、短预算试跑、排名、冠军重训。
  • 认识"短跑评分"的系统性偏差：哪些超参数在短预算下被高估或低估。
  • 把最优配置与全部试跑记录落盘为 JSON，让调参结果可复现、可复核。
  • 会把"配置"从代码里抽成字典，让训练逻辑与超参数完全解耦。

背景与动机

SAC 对超参数比 PPO 宽容，但"宽容"不等于"随便"：学习率跨一个数量级、批大小从 64 到 1024，最终回报可能差两三百。真机实验里，工程师花在调参上的时间往往比写算法还多。更麻烦的是手动调参不可复现，"试了十几次取最好的那次"本质上是在人肉做搜索，却没有把搜索过程记录下来。

本章把调参流程化：给定一个离散搜索空间，随机采样若干配置、用短预算试跑打分、选出冠军重训、结果落盘。流程本身比任何单次结果都重要，它让"调参"变成可审计的工程步骤。

核心原理

1. 随机搜索 vs 网格搜索

网格搜索在每维取固定几个值并做笛卡尔积。它有一个隐藏假设：每个超参数都同等重要。实际上 RL 的灵敏度极不均匀（学习率通常最敏感，τ 次之），网格搜索会把大量预算花在不重要维度的组合上。随机搜索从同样的网格上独立采样，用更少的试跑覆盖重要维度的所有取值：

网格：预算 N = kd（d 维各取 k 个值），每维只覆盖 k 个点
随机：预算 N 时每维期望覆盖 ≈ k·(1 − e−N/k) 同样的试跑次数，随机搜索让每个重要维度看到更多取值

符号说明：k 是每维的候选值个数，d 是维度数，N 是总试跑预算。直观结论：只要有一两个维度真正重要，随机搜索的期望最优值就优于网格搜索，这一结论在 RL 调参里被反复验证。

数值例子：同样预算下两种搜索的覆盖对比

取本章的搜索空间：4 个维度、每维 3 个候选值（k=3，d=4），完整网格需要 34 = 81 组。

网格搜索，预算 9 组：只能做成 3×3 的二维网格，把两个维度完整覆盖，另外两个维度各自固定在一个值上，覆盖率为 2/4 维度。

随机搜索，预算 6 组：每个维度被覆盖的期望档位数 = k(1 − e−N/k) = 3(1 − e−2) ≈ 3×0.865 ≈ 2.59。也就是每个维度都看到了约 2.6 个档位，覆盖率约为 86%。

解读：6 组随机试跑在每个维度上都接近全覆盖，而 9 组网格试跑有两个维度完全没有变化。如果真正敏感的只有 lr 与 tau 两个维度（RL 里常见），随机搜索在 6 组预算内几乎必然扫到最优组合附近，网格搜索却可能把敏感维度固定在错误档位。这就是"预算有限时优先随机"的定量依据。

2. 评分函数的选择

试跑结束时如何打分？常用的有三种：

  • 最终评估：只看最后一次评估，反映"够不够稳"；
  • 最好评估：取过程中的峰值，反映"潜力上限"，但对随机尖峰敏感；
  • 多次评估均值（本章采用）：取中途与结束两次评估的平均，兼顾潜力与稳定性，是抑制评估噪声最简单的手段。

注意 Pendulum 的评估方差很大（5 回合的均值波动可达 ±100），单次评估排名经常落在噪声内。把 --eval-episodes 提高后再看排名，稳定性会明显改善（见练习）。

评分噪声可以粗略估算：设单次评估（5 回合均值）的标准差约为 s，两次评估取均值后噪声降为 s/√2 ≈ 0.71s；把评估回合数从 5 提到 15，单次评估的标准差按回合数平方根缩小到约 s·√(5/15) ≈ 0.58s，与两次平均叠加后总噪声约为 0.41s。两个手段都很便宜：评估只占训练时间的一小部分，却直接决定排名是否可信。反过来，如果某次搜索的前三名得分彼此相差不到 20 分，而评估噪声在 70 分以上，那么"冠军"与"并列"没有本质区别，应该按更稳的默认配置优先。

3. 短预算的偏差

短跑评分天然偏向"斜率型"配置：大学习率早期进步快，在 5000 步时领先；但长跑后可能因震荡或平台被反超。因此搜索流程必须包含冠军重训，用更长预算复核冠军，同时观察"试跑得分 → 重训得分"的抬升幅度。"重训得分不低于试跑"是稳定规律，而"谁拿第一"通常不稳定；把这两件事分开看，是理解自动搜索价值的关键。

实现思路与设计

数据流

主流程四步：构造搜索空间（lr × batch × tau × alpha_init 共 3×3×2×2 = 36 种组合，第一组固定为默认配置做基准）→ 逐组试跑（每组 5000 步，中途与结束各评估一次，得分取均值）→ 排名并选出冠军 → 冠军重训（15000 步）并把最优配置与全部试跑记录写入 runs/ch050/best_config.json。所有试跑共用同一随机种子，把"配置差异"变成主变量。

模块划分

组件职责关键点
space离散搜索网格：lr × batch × tau × alpha_init36 种组合，随机采样保证不重复
SAC(cfg)从配置字典构造，网络与优化器全部吃 cfg学习率分别用于 Q、策略、温度三个优化器
run_config(cfg, steps)训练一整组配置并打分中途与结束各评估一次，得分取均值
排名与重训按得分排序，冠军用长预算重跑所有试跑共用同一种子，减少组间噪声
JSON 落盘保存最优配置与全部试跑记录best_config.json 可复现、可自动对比

关键超参数

参数默认值作用与取值理由
--trials6试跑组数（第一组固定为默认配置，便于对照）
--trial-steps5000每组短跑预算，约 25 个回合
--final-steps15000冠军重训预算，约为试跑的 3 倍
--eval-episodes5评分回合数；提到 10 会让排名更稳但评估更贵
--seed0同时控制配置采样与训练种子

预算分配的取舍值得单独说明：试跑 5000 步、重训 15000 步，比例约为 1:3。试跑太短（如 1000 步），所有配置都还在随机探索期，得分几乎不区分；试跑太长（如 12000 步），6 组预算会吃掉大量时间，搜索的"广度"被牺牲。经验上取最终预算的四分之一到三分之一，既能看出配置间的斜率差异，又能在同一总时长里比较足够多的组合。组数不少于 6 的理由与噪声有关：评估噪声约 70 分时，6 组的排名至少能把差距在 100 分以上的配置分层，而 3 组时噪声足以淹没大多数真实差异。

与前一章的差异点

  • 第 049 章改系统架构；本章回到单线程训练，但把整组超参数变成流程变量。
  • SAC 的构造从"读 args"改成"读 cfg 字典"，超参数与代码路径解耦。
  • 新增两段式流程：试跑排名 + 冠军重训；上一章没有"多次实验的编排"。
  • 产物从日志扩展为 JSON 记录（配置、得分、排名），支持后续复现与自动对比。

关键代码与解读

片段 1：搜索空间与不重复采样

    # 搜索空间：离散网格上做随机采样（组合数 3*3*2*2 = 36）
    space = {
        "lr": [1e-4, 3e-4, 1e-3],
        "batch": [64, 128, 256],
        "tau": [0.005, 0.01],
        "alpha_init": [0.1, 0.2],
    }
    default_cfg = {"lr": 3e-4, "batch": 256, "tau": 0.005, "alpha_init": 0.2,
                   "hidden": args.hidden}
    rng = random.Random(args.seed)           # 配置采样独立成流，可复现

    # 采样不重复的配置；第一组固定为默认配置
    seen = set()
    configs = [default_cfg]
    seen.add((default_cfg["lr"], default_cfg["batch"], default_cfg["tau"],
              default_cfg["alpha_init"]))
    while len(configs) < args.trials:
        cfg = {
            "lr": rng.choice(space["lr"]),
            "batch": rng.choice(space["batch"]),
            "tau": rng.choice(space["tau"]),
            "alpha_init": rng.choice(space["alpha_init"]),
            "hidden": args.hidden,
        }
        key = (cfg["lr"], cfg["batch"], cfg["tau"], cfg["alpha_init"])
        if key not in seen:                  # 去重：避免预算浪费在重复配置上
            seen.add(key)
            configs.append(cfg)

解读：（1）搜索空间采用"离散档位"：档位来自工程经验（lr 取 1e-4/3e-4/1e-3，跨一个数量级），组合数有限使"随机采样 + 去重"成为最简单的实现。（2）第一组固定为默认配置，是搜索流程的"对照组"，如果冠军还跑不过默认配置，说明这个任务的默认参数已经够好。（3）random.Random(args.seed) 单独建随机流：配置采样与训练种子解耦、又都可靠种子复现；若直接用全局 random，搜索顺序会与训练框架里的其他随机调用互相纠缠。（4）用元组 key 做去重：36 种组合里抽 6 组，碰撞概率不低，去重保证每组预算都花在新配置上。

片段 2：run_config，一次试跑的评分闭环

def run_config(cfg: dict, steps: int, args, tag: str, verbose: bool = False):
    """训练一个配置；每隔一半预算评估一次，返回 (得分, 最好评估)。"""
    set_seed(args.seed)  # 所有试跑同种子，减少配置间噪声
    env = make_env(args.env, args.seed)
    eval_env = make_env(args.env, args.seed + 100)   # 评估环境独立于试跑
    obs_dim = env.observation_space.shape[0]
    act_dim = env.action_space.shape[0]
    action_scale = float(env.action_space.high[0])
    agent = SAC(obs_dim, act_dim, action_scale, cfg)
    buffer = ReplayBuffer(args.buffer_size, obs_dim, act_dim)

    obs, _ = env.reset(seed=args.seed)
    ep_ret = 0.0
    ep_returns = []
    evals = []
    start_steps = min(args.start_steps, steps // 5)  # 短跑时预热也按比例缩短
    t_start = time.time()

    for step in range(1, steps + 1):
        if step <= start_steps:
            action = env.action_space.sample()
        else:
            action = agent.act(obs, deterministic=False)
        next_obs, rew, terminated, truncated, _ = env.step(action)
        buffer.add(obs, action, rew, next_obs, float(terminated))
        obs = next_obs
        ep_ret += rew
        if terminated or truncated:
            ep_returns.append(ep_ret)
            ep_ret = 0.0
            obs, _ = env.reset()

        if buffer.size >= start_steps and step % args.update_every == 0:
            agent.update(buffer.sample(cfg["batch"]), args.gamma, cfg["tau"])

        if step % max(steps // 2, 1) == 0:
            evals.append(evaluate(agent, eval_env, args.eval_episodes))
            if verbose:
                print(f"    [{tag}] 步数 {step} | 评估 {evals[-1]:.1f}")

    score = float(np.mean(evals))            # 两次评估的均值：降噪评分
    best = max(evals) if evals else score
    return score, best, time.time() - t_start

解读：（1）函数开头 set_seed + 重建环境/网络/回放池：每个配置都是一次干净实验，环境随机流完全一致，配置差异是唯一变量。（2）start_steps = min(args.start_steps, steps // 5)：短跑时预热也要按比例缩，否则 5000 步里 1000 步纯随机会拖累所有配置的得分且毫无区分度。（3）评估只做两次（过半与结束）：score = mean(evals) 兼顾潜力与稳定性，且成本可控；注意它不用训练滑动回报，那会把随机探索期的低分算进去，对探索激进的配置不公平。（4）batch 与 tau 在循环里从 cfg 读取：超参数真正进入了训练路径，没有停在日志层面。

    results.sort(key=lambda r: r["score"], reverse=True)
    print("\n" + "=" * 92)
    print("随机搜索排名（得分 = 试跑中途与结束两次评估的均值）")

    out = {

解读：（1）排序后立刻打印全表：名次、四维配置、均分、最好分，这张表就是整个搜索的原始证据，比"最优配置是 XXX"一句话信息量大得多。（2）冠军重训复用同一个 run_config，只换 steps：保证评分口径完全一致，两端得分可以直接相减讨论"预算收益"。（3）落盘内容里同时保存 trial_score 与 final_score：下次实验或换机器复现时，能看出冠军是否"吃预算"。ensure_ascii=False 让中文可读，indent=2 便于人工检查。（4）如果重训得分反而低于试跑，说明该配置在长预算下出现震荡或平台，这个对比本身就是搜索流程最有价值的诊断，不能当成程序错误。

预期：短预算下 1e-3 的大学习率通常领先（早期斜率陡），3e-4 默认配置常在试跑排名的中游；冠军重训后得分普遍比试跑高 40～100（预算从 5000 步加到 15000 步）。但要警惕：大学习率组合在个别种子上后期震荡，重训得分可能反低于试跑。以实跑为准，"重训得分不低于试跑"稳定成立，"谁拿第一"并不稳定。

常见坑

  • 用训练滑动回报评分：训练回报包含随机探索期的低分，偏向"探索保守"的配置，与最终性能目标不一致。修复：统一用确定性策略、固定回合数的评估协议。
  • 试跑共用评估环境而不重置：评估环境若跨试跑共享，某些配置会"继承"上一组的随机状态。修复：每个 run_config 内部重新 gym.make 并固定种子。
  • 把搜索结论当成跨种子真理：单种子搜索的冠军可能只是运气的产物。修复：重要配置至少 2～3 个种子复验，或把种子作为搜索维度。
  • 预算分配头重脚轻：每组试跑太长会让组数太少，太短又噪声太大。经验比例：试跑预算约为最终预算的 1/3～1/4，组数不少于 6。

练习与思考

  1. 把 --eval-episodes 从 5 提到 15，重跑搜索。排名变化大吗？这说明什么？★
    提示
    评估回合越多，单次评估方差越小，排名应更稳定。对比两次运行的前三名配置是否一致。
  2. 给 run_config 加多种子支持：每个配置跑 --seeds 3 个种子取平均。在总预算不变的前提下步数怎么分配？★★
    提示
    总预算 = 种子数 × 每种子步数。要么接受试跑变短，要么增加总时间。把 set_seed 的种子参数化，得分改为跨种子均值，观察排名与单种子的差异。
  3. 把评分函数从"两次评估均值"改成"最好评估"，重跑并对比冠军配置。哪种评分更接近重训结果？★★
    提示
    最好评估容易选中"早期偶然高分"的配置。对比两次运行的冠军重训得分，讨论评分函数与最终目标的一致性。
  4. 把 hidden 固定值改成搜索维度 [128, 256, 512]，重跑。参数量与得分是单调关系吗？★★
    提示
    在 space 里加一行、采样时读取即可。512 宽度在 Pendulum 上通常没有回报、只增加训练时间，说明"容量不是瓶颈"。
  5. 把搜索从"纯随机"改成"两阶段局部细化"：用前几组结果锁定 lr 与 batch 的冠军档位，在其周围 ±一个档位再采样 3 组。比较两阶段总预算下的最优得分。★★★
    提示
    按对数网格找最近邻档位生成候选。重点在于体会"利用已有结果缩小范围"与"纯随机"的预算效率差，不必写出完整的贝叶斯优化。

小结

  • 超参数搜索 = 搜索空间 + 预算分配 + 评分函数；随机搜索在同等预算下比网格搜索覆盖更有效。
  • 本章实现了"6 组短跑 + 冠军长跑"的两段式流程，配置与训练逻辑通过字典解耦，结果落盘为 JSON。
  • 短预算排名存在系统性偏差（大学习率早期占优），冠军重训是必须的验证步骤。
  • 评分函数要用统一评估协议；Pendulum 上单次 5 回合评估噪声大，增加评估回合数是廉价有效的降噪手段。
  • 覆盖效率的定量对比：4 维各 3 档时，6 组随机试跑每维覆盖约 2.6 档，而 9 组网格只能完整覆盖其中 2 个维度，预算有限时随机搜索明显占优。
  • 评分噪声的估算：单次评估标准差 s 经两次平均降为 0.71s，再把回合数从 5 提到 15 可进一步降到约 0.41s；排名差距小于噪声量级时，冠军与并列没有本质区别。
