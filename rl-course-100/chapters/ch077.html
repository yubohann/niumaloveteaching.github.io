第 077 章：多智能体SAC：集中Q函数

独立 SAC 的批评家是"井底之蛙"：只看得到自己的观测与动作。本章把它的视野打开，Qi(s, a1, …, aN) 同时看到全局状态与所有人的联合动作，策略依然只用局部观测执行。

  • 主题：集中 Q 函数 / MASAC 风格 CTDE
  • 关键公式：yi = ri + γ(1−d)[minkQk,itgt(s′,a′1:N) − αilog πi(a′i|o′i)]
  • 预计学时：55 分钟
  • 前置章节：第 076 章

学习目标

  • 理解集中 Q 函数的形式 Qi(sglobal, a1:N) 与它解决的问题。
  • 掌握集中 Q 的两个实现要点：下一状态的动作由各当前策略采样；策略梯度只对自己的动作求导（队友动作 detach）。
  • 看懂同一份 Learner.update 如何用 mode 分支承载独立/集中两种批评家。
  • 理解"局部观测是否充分"决定集中 Q 的收益：信息充足的简单任务上差距有限。
  • 把集中 Q 与第 069 章的集中价值 V(s) 联系起来，形成 CTDE 在 PPO/SAC 两个谱系里的完整图景。

背景与动机

独立 SAC 的批评家目标里有一处"盲区"：智能体 i 的 Q 只看到 oi 与 ai，而它的收益其实取决于队友此刻在做什么。三个智能体同时挤向同一个地标时，任何单独一个人的观测都无法解释"为什么回报变差了"，信息在别人手里。集中 Q 函数（MASAC / MADDPG 的核心组件）把批评家的输入扩展为全局状态与所有人的动作：

Qi(s, a1, …, aN)   训练与备份用它；  但执行时 ai ∼ πi(·|oi) s 是全局状态；a1:N 是联合动作；执行期策略依然只吃局部观测 oi，训练-执行不对称再次出现

这又是 CTDE 的思路：训练期允许"开后门"看全局，部署时严格只用本地信息。它与第 069 章的集中价值 V(s) 遥相呼应，V(s) 集中了状态却不知道动作，Q(s, a) 把联合动作也纳入输入。评价"协调得好不好"需要知道每个人做了什么，这就是 Q 版本存在的理由。本章的对照实验：同一份 SAC 代码，只切换批评家的输入结构，看简单任务上集中化的收益有多少。

核心原理

1. 集中 Q 的软 Bellman 备份

对智能体 i，备份目标里包含所有人的下一动作，而"下一动作"由各智能体当前策略采样：

yi = ri + γ(1−d)·[ mink Qk,itgt(s′, a′1:N) − αi log πi(a′i|o′i) ]
a′j ∼ πj(·|o′j)，j = 1…N Qk,itgt 是智能体 i 的第 k 个目标 Q（双 Q 取小）；熵项只与自己的 log πi 有关，温度优化的是自己的探索强度

下一动作为什么由当前策略现采？在 SAC 里策略本身没有"目标策略"，探索的温度与分布由当前策略决定，Q 的目标网络只用于稳定价值估计。这是 SAC 与 DDPG 系方法的一个习惯差异，两种实现都存在，本章遵循 SAC 的惯例。每个智能体有自己的双 Q 与目标网络（共 2N 个 Q 网络），输入都是同一份 (s, a1:N)。

2. 策略梯度：只对自己的动作求导

策略更新时，智能体 i 最大化由自己的动作带来的 Q 值：

∇θi J ≈ 𝔼[ ∇θi ( mink Qk,i(s, a−i, ai(oi)) − αi log πi ) ] a−i 是队友动作，在求导时视作常数（detach）；只有 ai 的重参数化路径携带梯度

这一步容易写错：如果队友动作没有 detach，梯度会穿过"队友的策略"回传到别的网络参数，等于让智能体 i 去"操纵队友"。也有人特意设计共享梯度的版本（练习 3），但那属于另一个算法方向的取舍，标准 MASAC 只对自家人求导。

3. 什么情况下集中 Q 才明显有用

集中 Q 的信息优势取决于局部观测"缺了多少"：

  • 信息充分（本章任务：每个智能体都能看到所有地标与队友的相对位置），oi 已接近全局状态的"相对副本"，加不加联合动作收益有限；
  • 信息受限（比如第 071 章的感知半径 0.4、看不到远处队友），Q 能看到别人在干什么，价值估计的偏差大幅降低；
  • 协调密集（多个好解需要精确同步），Q(s, a) 能区分"我先走还是你先走"这类差异，而 Q(oi, ai) 不能。

所以本章的预期是"更准的价值、未必更高的分数"：诊断量应盯住 Q 的学习质量与曲线方差，而回报差距可能落在噪声里。这也再次印证第 069 章的结论，机制的有效性永远相对于任务的信息结构而言。

4. 与集中价值 V(s) 的分工

回看第 069 章：集中 V(s) 让所有智能体共享同一套优势，快但不区分动作；集中 Qi(s, a1:N) 保留动作信息，能做信用分配与更精细的策略梯度，代价是每个智能体一套双 Q（参数量与计算量翻倍）。PPO 谱系用 critic 估 V 配合 GAE；SAC 谱系直接用 Q 的软 Bellman，两个谱系在这里完成闭环：CTDE 是贯穿整个多智能体部分的范式，集中 Q 只是它在 SAC 谱系的又一次落地。

实现思路与设计

模块划分

组件职责关键点
JointReplayBuffer额外存储全局状态与下一状态集中 Q 需要 (s, s′) 两列
LocalTwinQ独立批评家 (oi, ai)indep 模式使用
JointTwinQ集中批评家 (s, a1:N)central 模式；输入维 = state_dim + N·act_dim
Learner.update批评家 / 策略 / 温度更新两种模式共用一套方法，用 mode 分支
策略梯度细节队友动作 detach只让 ai 的重参数化路径携带梯度

关键超参数

参数默认值作用与取值理由
--modebothindep 与 central 各训一遍，其余全部对齐
--max-steps20000环境步预算；两配置共 4 万步
--batch-size128集中 Q 输入更宽，批量保持不变以控制时间
--hidden64两种批评家宽度相同，区别只在输入内容
--update-every1每个环境步触发 N 个学习器各一次更新

数据流

环境步进前后各取一次 global_state()，与联合转移一起入池。更新时对每个智能体：central 分支从 batch 里取 state/next_state，下一动作由所有学习器的当前策略分别采样后拼接；批评家吃 (s, a1:N)；策略梯度里队友动作 detach。indep 分支只取自己那一列，其余与第 076 章一致。

与第 076 章的差异点

第 076 章每个智能体只取自己那一列数据更新；本章 central 模式把 (s, a1:N, s′) 整行交给批评家，下一动作需要批量采样所有智能体的策略。学习器代码用同一个 update 方法承载两种模式，便于逐行对照差异。第 078 章会把三个策略网络合并成一个共享网络。

关键代码与解读

片段 1：两种批评家的唯一差别是输入

class LocalTwinQ(nn.Module):
    """独立 Q：输入单个智能体的观测与动作。"""

    def __init__(self, obs_dim, act_dim, hidden=64):
        super().__init__()
        def make():
            return nn.Sequential(nn.Linear(obs_dim + act_dim, hidden), nn.ReLU(),
                                 nn.Linear(hidden, hidden), nn.ReLU(),
                                 nn.Linear(hidden, 1))
        self.q1, self.q2 = make(), make()

    def forward(self, obs, act):
        x = torch.cat([obs, act], dim=-1)
        return self.q1(x), self.q2(x)


class JointTwinQ(nn.Module):
    """集中 Q：输入全局状态与所有智能体的联合动作。"""

    def __init__(self, state_dim, n_agents, act_dim, hidden=64):
        super().__init__()
        in_dim = state_dim + n_agents * act_dim      # 19 + 3×2 = 25 维输入
        def make():
            return nn.Sequential(nn.Linear(in_dim, hidden), nn.ReLU(),
                                 nn.Linear(hidden, hidden), nn.ReLU(),
                                 nn.Linear(hidden, 1))
        self.q1, self.q2 = make(), make()

    def forward(self, state, joint_act):
        x = torch.cat([state, joint_act], dim=-1)
        return self.q1(x), self.q2(x)

解读：把两个类并排看，本章改动一目了然。（1）LocalTwinQ 输入 obs_dim + act_dim = 14 + 2 = 16；JointTwinQ 输入 state_dim + N×act_dim = 19 + 6 = 25。多出来的 9 维正是"别人在哪、别人在做什么"的信息。（2）def make() 在各自 __init__ 内定义并调用两次：q1、q2 得到独立初始化的两个网络（每次调用都执行一次网络构造），如果写成共享同一个实例，双 Q 退化成单 Q，过估计抑制失效。（3）网络宽度相同（hidden=64）：对照实验只改变输入内容，容量对齐。（4）forward 里 cat([state, joint_act]) 拼接顺序固定：拼接顺序必须与构造 target 时的顺序一致（先状态后动作），这种"隐式协议"写错不会有报错，只能靠训练结果发现。

片段 2：回放池多存两列状态

        self.state = np.zeros((capacity, state_dim), np.float32)       # 全局状态
        self.next_state = np.zeros((capacity, state_dim), np.float32)  # 下一全局状态
        self.done = np.zeros((capacity,), np.float32)

    def add(self, obs, act, per_rew, team_rew, next_obs, state, next_state, done):
        i = self.ptr
        self.obs[i] = obs
        self.act[i] = act
        self.rew[i] = per_rew
        self.team_rew[i] = team_rew
        self.next_obs[i] = next_obs
        self.state[i] = state                 # 集中 Q 的输入需要它
        self.next_state[i] = next_state       # 自举目标也需要它
        self.done[i] = done
        self.ptr = (self.ptr + 1) % self.capacity
        self.size = min(self.size + 1, self.capacity)

解读：数据结构的改动能反过来提醒你算法的需求。（1）独立 Q 时代只需要"自己那一列"和局部观测，团队状态无处安放；集中 Q 一来，state/next_state 必须入池，训练时批评家每次前向都要用。（2）状态在环境步进前后各取一次，与 (o′, r, d) 严格对时：state 对应决策时刻、next_state 对应自举时刻。如果偷懒复用同一个状态，Bellman 目标就错了一帧。（3）采样字典同步扩展：sample 里增加 "state" 与 "next_state" 两个键（脚本第 150-151 行），两种模式共用同一批索引，indep 模式拿到多余键也无妨，不用它们。（4）存储成本：状态 19 维 × 两条 × 容量 20 万 × 4 字节 ≈ 30 MB，与观测/动作同量级，完全可接受。

片段 3：集中备份，为所有人采样下一动作

        # ---- 批评家目标 ----
        with torch.no_grad():
            next_act_i, next_logp_i = self.policy.sample(next_obs_i)   # 自己：当前策略采样
            if self.mode == "central":
                # 下一状态上，所有智能体的动作都由各自当前策略采样
                next_acts = [next_act_i] * len(peers)
                for j, peer in enumerate(peers):
                    if j == i:
                        continue
                    a_j, _ = peer.policy.sample(batch["next_obs"][:, j])
                    next_acts[j] = a_j
                joint_next = torch.cat(next_acts, dim=-1)              # (B, N*act_dim)
                q1t, q2t = self.q_target(batch["next_state"], joint_next)
            else:
                q1t, q2t = self.q_target(next_obs_i, next_act_i)
            target = batch["rew"][:, i].unsqueeze(-1) + self.gamma * (1.0 - done).unsqueeze(-1) * (
                torch.min(q1t, q2t) - self.alpha * next_logp_i)

        # ---- 批评家更新 ----
        if self.mode == "central":
            joint_cur = batch["act"].reshape(batch["act"].shape[0], -1)   # (B, N*act_dim)
            q1, q2 = self.q(batch["state"], joint_cur)
        else:
            q1, q2 = self.q(obs_i, act_i)
        q_loss = F.mse_loss(q1, target) + F.mse_loss(q2, target)
        self.q_opt.zero_grad()
        q_loss.backward()
        self.q_opt.step()

解读：集中 Q 的目标构造里藏着四处细节。（1）下一动作全员当下采样：循环里对每个队友 peer.policy.sample(...)，注意用当前策略现采，这是 SAC 惯例；队友动作不经 detach 也没关系，因为整段在 no_grad 里。（2）next_acts = [next_act_i] * len(peers) 先占位再替换：列表里第 i 项是自己的动作，循环跳过 j == i。若用 enumerate 直接 append 会错位，顺序必须与 batch["act"] 的智能体顺序严格一致。（3）熵项只减 self.alpha * next_logp_i：soft Bellman 里的熵正则属于"自己的探索"，队友的熵不出现在自己的目标里。（4）当前状态的动作不再采样，直接用回放池里的真实 joint_cur（reshape 展平 N×act_dim）：行为数据里就是当时实际发生的联合动作，无需重算。

片段 4：策略梯度只对"自己的动作"求导

        # ---- 策略更新：只对自己的动作求梯度，队友动作 detach ----
        if self.mode == "central":
            own_act, logp = self.policy.sample(obs_i)        # 自己的动作：重参数化，带梯度
            others = []
            for j, peer in enumerate(peers):
                if j == i:
                    others.append(own_act)
                else:
                    a_j, _ = peer.policy.sample(batch["obs"][:, j])
                    others.append(a_j.detach())               # 队友动作：切断梯度
            joint_cur2 = torch.cat(others, dim=-1)
            q1n, q2n = self.q(batch["state"], joint_cur2)
        else:
            own_act, logp = self.policy.sample(obs_i)
            q1n, q2n = self.q(obs_i, own_act)
        policy_loss = (self.alpha.detach() * logp - torch.min(q1n, q2n)).mean()
        self.policy_opt.zero_grad()
        policy_loss.backward()
        self.policy_opt.step()

解读：detach 的位置决定了"谁为谁的决策负责"。（1）自己的动作走 sample（内部 rsample）→ 带梯度；队友动作同样采样后立刻 .detach() → 成为常数。反传时梯度只能沿"我的动作 → 我的 Q 值"这条路径走。（2）detach 是必须的：否则同一批 Q 输出会向多个策略网络同时反传，每个学习器的更新还会互相干扰（并列梯度），而且语义上变成"我优化 Q 时顺便改写队友"，那不是本章的算法。（3）注意 others 与 next_acts 都用量词 peers（所有学习器列表），第 i 项放自己的新动作：顺序协议与备份端完全一致。（4）温度更新只用 logp（自己的对数概率），与队友无关，alpha.detach() 防止策略损失污染温度。

常见坑

  • 队友动作忘了 detach：策略梯度会穿到别的网络，训练变得不稳定且语义错误。检查方法：确认 others.append(a_j.detach()) 里的 detach 没有被顺手删掉。
  • 联合动作顺序错位：备份与策略更新两处都按智能体索引拼动作；如果两处顺序不一致（比如一处按 peers 顺序、另一处按 batch 列顺序），Q 的输入对应错人，训练崩溃。
  • next_state 用成了当前 state：Bellman 自举错一帧，价值目标系统性偏差。取状态时要严格遵守"步进前 state、步进后 next_state"。
  • 两模式共享批评家参数：indep 与 central 必须各自独立的网络实例（分别在各自 run_training 里构造），串跑时不能复用对象。
  • 期待集中 Q 在充分观测任务上大幅提升：信息结构决定收益上限；看不到差距不是代码错，换信息受限的任务或看 Q 诊断量再下结论。

练习与思考

  1. 把两种模式的日志并排比较：central 的 Q 损失是否更低、α 曲线是否更整齐？解释为什么"看得更多"会让 α 更平稳。★
    2. 提示
    价值估计更准 → 策略更新目标更稳定 → 策略熵的波动更小 → α 更少大起大落。看两者 α 均值曲线的标准差。
  2. 把 --mode central 跑两个种子，检查最终回报的种子间波动；再跑 indep 两次。哪种模式的方差更小？★
    提示
    种子波动里混着"个体初始化差异"；central 批评家共享全局视角，通常减小但不会消除波动。2 个种子只能看趋势，至少 3 个。
  3. 尝试"共享策略梯度"变体：策略更新时不 detach 队友动作，观察训练是否还稳定。★★
    提示
    这近似让每个智能体把队友当作"可微分的环境"，梯度会互相缠绕；短期可能更快，但容易出现震荡或共谋式塌缩。记录并对比曲线。
  4. 把观测削贫（比如删掉队友相对位置），重跑 indep 与 central，预测差距变化并验证。★★
    提示
    局部观测缺了自己看不到的信息时，集中 Q 的价值凸显。观测维度变化后要同步改 obs_dim 与网络输入。
  5. 实现"集中 Q + 分离的头"：Q 输入中把"自己的动作块"与"队友动作块"拼接后分别编码再融合，讨论这种结构相对朴素拼接的优势与成本。★★★
    提示
    分离编码允许网络学习"我的动作×队友动作"的交互项而不只是线性拼接；成本是多一个编码器。与注意力式 Q（如 QMIX 的单调混合）的思路一脉相承。

小结

  • 集中 Q：Qi(s, a1:N) 训练期看全局；策略执行仍只用局部观测，CTDE 在 SAC 谱系的落地。
  • 备份要点：目标里的下一动作由各当前策略采样；熵项只属于自己；当前状态动作直接用池里的真实联合动作。
  • 策略梯度要点：队友动作 detach，梯度只沿自己的重参数化路径走。
  • 实现改动集中在"输入维度 + 数据池多两列 + 拼动作的顺序协议"，学习器否则与第 076 章同构。
