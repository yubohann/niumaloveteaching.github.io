第四篇 · 多智能体强化学习

第 068 章：多智能体PPO：独立PPO

从单智能体跨入多智能体：先用纯 numpy 写一个三智能体合作导航环境，再实现最朴素的基线，每个智能体各学各的独立 PPO，看看"互不理会"会带来什么。

  • 主题：多智能体基础 / 独立 PPO（IPPO）
  • 关键公式：联合动作 (a1,…,aN) 与对称匹配奖励 r = −(1/N)·minσ Σ‖pi−lσ(i)‖
  • 预计学时：55 分钟
  • 前置章节：第 067 章

学习目标

  • 理解多智能体强化学习（Multi-Agent RL, MARL）的基本设定：联合动作、共享奖励、局部观测与策略集合。
  • 看懂纯 numpy 合作导航环境的观测、动作、奖励与动力学，理解"二分匹配奖励"为什么是对称的。
  • 掌握独立 PPO（Independent PPO, IPPO）的数据流：每个智能体一套 Actor-Critic、各自估计优势、各自更新。
  • 认识非平稳性：其他智能体持续学习，使每个智能体面对的"环境"一直在变。
  • 学会读多智能体日志的三个指标：团队回报、平均末距、每回合碰撞次数。

背景与动机

现实世界里很少有"独自完成任务"的智能体：仓库里的多台机器人要绕开彼此、球队里的每个球员要配合传球、无人机编队要共享空域。多智能体强化学习比单智能体难在三点：环境对其他智能体而言不是静止的（它们也在学习）、奖励无法直接归因到单个智能体（信用分配难题）、观测通常是局部的（看不到全局状态）。

整个多智能体 PPO 部分（第 068～075 章）共用本章搭好的合作导航环境，每章引入一个机制改进：独立 PPO → 集中训练分散执行（CTDE）→ 参数共享 → 通信 → 角色对称 → 信用分配 → 对手建模 → 混合合作竞争。本章是整个链条的起点：先把最朴素的独立 PPO 跑通，看清楚它的强项（实现简单）与短板（协调靠运气），后面每一章都从这里出发做单点改进。

核心原理

1. 多智能体的数学设定

N 个智能体各自根据局部观测决定动作，联合动作决定环境转移，团队拿到共享奖励：

oti = Oi(st)，ati ∼ πθi(· | oti)，at = (at1, …, atN)
st+1 ∼ P(· | st, at)，rt 由全体共享 s 是全局状态；oi 是智能体 i 的局部观测（上标表示智能体编号）；πθi 是其策略；P 是转移函数。这是 Dec-POMDP（分散式部分可观测马尔可夫决策过程）的简化表述

"独立 PPO"的做法是：把其他智能体当作环境的一部分，每个智能体独立地最大化自己的期望回报。它的优点是实现几乎等同于单智能体 PPO；缺点是非平稳性，智能体 i 的策略改进会改变智能体 j 面对的转移分布，双方同时学习时，各自的"最优反应"在不断漂移。经典的多智能体博弈"石头剪刀布"就是这个问题的极端例子：对手一变，最优策略就变。

2. 合作导航环境的动力学与奖励

每个智能体的位置 pi、速度 vi 在单位方格内演化，动作为 2 维力 ai：

vi ← 0.9·vi + 0.2·ai，  pi ← clip(pi + vi, 0, 1) 0.9 是阻尼（速度自然衰减）、0.2 是加速度系数；clip 把位置限制在单位方格内，越界即贴边

奖励使用二分匹配：枚举 N! 种"智能体—地标"配对，取总距离最小的一种，团队奖励为负的平均距离：

rt = −(1/N)·minσ∈SN Σi ‖pi − lσ(i)‖ − 碰撞惩罚 σ 是智能体到地标的排列（一种配对方案）；SN 是全部 N! 种排列；l 是地标位置。N=3 时只有 6 种配对，枚举开销可忽略；该奖励对"谁去哪个地标"完全对称

对称奖励的意义：任务不存在"一号智能体必须去一号地标"的规定，任何无冲突配对都是好解。这为后面的参数共享与角色对称章节（第 070、072 章）埋下伏笔。碰撞惩罚发生在两个智能体距离小于 0.1 时，双方各扣 0.3，这是环境里唯一的"协调压力"：如果大家都走直线不避让，就会互相撞上。

3. 每个智能体一套 GAE

独立 PPO 的优势估计仍然是 GAE，只是每个智能体用自己的奖励、自己的价值函数：

Âti = Σl≥0 (γλ)l δt+li，  δti = rti + γVi(ot+1i) − Vi(oti) δi 是智能体 i 的 TD 残差；Vi 是它自己的价值函数；ri 是它实际收到的奖励（共享距离项 + 自己的碰撞罚分）

注意 rti 里既包含共享的匹配距离项，也包含智能体自己的碰撞惩罚，因此不同智能体的优势并不相同，这正是"独立"二字的含义。第 073 章会讨论更精细的信用分配方案。

4. 预算为什么按"智能体步"计

一次 env.step 产生 N 条转移。如果把预算按环境步计，换一个智能体数量就等于悄悄换了训练规模，4 智能体环境跑 5 万环境步会得到 20 万条数据，和 3 智能体的 15 万条不可比。本章统一按智能体步（transition 条数）计量：--max-steps 180000 不管几个智能体，产生的新数据总量都一致。这是多智能体实验里最容易被忽略的公平性问题。

实现思路与设计

模块划分

组件职责关键点
CooperativeNavEnv纯 numpy 合作导航环境观测 14 维、动作 2 维、固定 50 步回合；附集中式 global_state() 备用
ActorCritic单智能体网络共享躯干 + 高斯策略 + 价值头，与单智能体篇一致
IPPO.act_all所有智能体批量前向逐智能体循环前向，避免构造复杂批量
collect_rollout采集"智能体步"并分智能体存桶每步推进环境一次，N 个智能体同时产生数据

evaluate确定性评估返回回报、平均末距、平均碰撞三个指标

参数默认值作用与取值理由

数据流

采样阶段：act_all 让 N 个网络各自对自己的那一行观测前向 → 拼成联合动作 → env.step → 每条转移写进对应智能体的桶（奖励用 per_r[i]）。GAE 阶段：每个智能体用自己的批评家对当前最新观测估计 bootstrap 价值，各自反推优势与回报。更新阶段：逐智能体做优势标准化与 8 轮小批量裁剪更新。

与第 067 章的差异点

第 067 章还在单智能体世界（Pendulum）；本章跨入多智能体：① 环境换成自研合作导航，观测/动作/奖励全部重新定义；② 网络从"一个"变成"每个智能体一个"，用列表管理；③ 采样按"智能体步"计数，一次环境步产生 N 条转移；④ 评估输出团队回报、末距、碰撞三件套。这个环境将在第 068～080 章反复出现。

关键代码与解读

片段 1：观测的两种视角

    def _obs(self):
        obs = np.zeros((self.n_agents, self.obs_dim), np.float32)
        for i in range(self.n_agents):
            rel_land = (self.landmarks - self.pos[i]).ravel()   # 各地标相对自己的偏移
            rel_others = [(self.pos[j] - self.pos[i]) for j in range(self.n_agents) if j != i]
            others = np.concatenate(rel_others) if rel_others else np.zeros(0, np.float32)
            obs[i] = np.concatenate([self.pos[i], self.vel[i], rel_land, others])
        return obs

    def global_state(self) -> np.ndarray:
        """集中式观察：所有智能体位置/速度 + 所有地标位置 + 归一化时间。"""
        return np.concatenate([self.pos.ravel(), self.vel.ravel(),
                               self.landmarks.ravel(),
                               [self.t / self.episode_len]]).astype(np.float32)

解读：环境同时提供两套"看世界的方式"，本段代码的对比是理解多智能体的关键。（1）局部观测 _obs 共 14 维：自身位置(2)+速度(2)+三个地标相对位置(6)+另外两个智能体相对位置(4)。所有坐标都是相对自己的，没有全局绝对坐标，这让策略自动具备平移等变性（把自己和全场平移 0.1，最优动作不变）。（2）别小看"看到其他智能体"这一项：它是协调的唯一信息来源。若删掉它，智能体只能靠碰撞惩罚的即时反馈学习避让，学习会更慢。（3）global_state 返回 19 维集中式状态：所有位置、速度、地标加上归一化时间。本章的独立 PPO 完全用不到它，它在这里出现，是给第 069 章的 CTDE 预留接口：届时批评家会换用它做输入。

片段 2：动力学与对称的匹配奖励

    def _min_matching_distance(self) -> float:
        """枚举全部配对，返回最小总距离的平均值（任务对称的奖励核心）。"""
        best = np.inf
        for perm in self._perms:
            total = 0.0
            for i, j in enumerate(perm):
                total += float(np.linalg.norm(self.pos[i] - self.landmarks[j]))
            if total < best:
                best = total
        return best / self.n_agents

    def step(self, actions):
        actions = np.clip(np.asarray(actions, dtype=np.float32), -1.0, 1.0)
        self.vel = self.damping * self.vel + self.accel * actions
        self.pos = np.clip(self.pos + self.vel, 0.0, 1.0)
        self.t += 1

        mean_dist = self._min_matching_distance()
        per_reward = np.full(self.n_agents, -mean_dist, dtype=np.float32)
        collisions = 0
        for i in range(self.n_agents):
            for j in range(i + 1, self.n_agents):
                if np.linalg.norm(self.pos[i] - self.pos[j]) < self.collision_dist:
                    per_reward[i] -= self.collision_penalty     # 碰撞双方各扣分
                    per_reward[j] -= self.collision_penalty
                    collisions += 1
        done = self.t >= self.episode_len
        info = {"mean_dist": mean_dist, "collisions": collisions}
        return self._obs(), per_reward, float(per_reward.mean()), done, info

解读：这段是环境的全部"规则"，每一行都直接影响学习难度。（1）匹配距离枚举 N! 种配对取最小：这告诉智能体"谁去哪都行，只要总距离最短"。如果用固定配对（智能体 1 必须去地标 1），三个智能体会被迫互相穿越，碰撞惩罚会把任务变成自相矛盾，对称奖励也是"公平难度"的来源。（2）动力学里 damping=0.9 意味着速度有惯性：松手后还会滑行，智能体必须学会"提前刹车"，这类二阶动力学比直接位置控制更接近真实机器人。（3）碰撞检测用 O(N²) 的朴素两两循环：N=3 时只有 3 对，完全够用；这是刻意的"可读性优先"写法。（4）step 返回 per_reward 数组：每个智能体的奖励里共享同一个距离项，但碰撞罚分只属于当事双方，这就是"共享 + 个体"的混合结构，第 073 章的信用分配实验将围绕它展开。

片段 3：按"智能体步"采样并分桶做 GAE

def collect_rollout(env, agents, steps_agent, args, device, obs):
    """采样 steps_agent 个"智能体步"（即 steps_agent / N 个环境步）。"""
    n = env.n_agents
    buf = [{"obs": [], "act": [], "logp": [], "rew": [], "val": [], "cut": []}
           for _ in range(n)]                       # 每个智能体一个数据桶
    team_rets = []
    ep_team_ret = 0.0
    env_steps = steps_agent // n                    # 预算按智能体步折算环境步
    for _ in range(env_steps):
        actions, logps, values = agents.act_all(obs)
        next_obs, per_r, team_r, done, _ = env.step(actions)
        for i in range(n):                          # 一次环境步给 N 个桶各写一条
            buf[i]["obs"].append(obs[i])
            buf[i]["act"].append(actions[i])
            buf[i]["logp"].append(logps[i])
            buf[i]["rew"].append(per_r[i])          # 每个智能体存自己的奖励
            buf[i]["val"].append(values[i])
            buf[i]["cut"].append(float(done))
        ep_team_ret += team_r
        obs = next_obs
        if done:
            team_rets.append(ep_team_ret)
            ep_team_ret = 0.0
            obs = env.reset()

    # 每个智能体用自己的批评家估计 bootstrap 价值，再做 GAE
    obs_t = torch.as_tensor(obs, dtype=torch.float32, device=device)
    batches = []
    for i in range(n):
        last_value = float(agents.nets[i].value(obs_t[i:i + 1]).item())
        adv, ret = compute_gae(buf[i]["rew"], buf[i]["val"], buf[i]["cut"],
                               last_value, args.gamma, args.lam)
        batches.append({
            "obs": torch.as_tensor(np.asarray(buf[i]["obs"]), dtype=torch.float32, device=device),
            "act": torch.as_tensor(np.asarray(buf[i]["act"]), dtype=torch.float32, device=device),
            "logp_old": torch.as_tensor(np.asarray(buf[i]["logp"]), dtype=torch.float32, device=device),
            "adv": torch.as_tensor(adv, device=device),
            "ret": torch.as_tensor(ret, device=device),
        })
    return batches, team_rets, obs

解读：这是 IPPO 数据流的全景，四个设计点值得展开。（1）env_steps = steps_agent // n：预算以智能体步为口径，换算回环境步再循环。无论 3 个还是 4 个智能体，一次更新的新数据量不变，跨配置比较才有意义。（2）一次 env.step 给 N 个桶各写一条：rew 存 per_r[i]（各智能体自己的奖励），cut 用同一个 done（回合对全体同步结束）。（3）GAE 按桶独立计算，last_value 也是各智能体用自己的批评家估计，这是"独立"的准确含义：共享同一段环境历史，但价值估计与优势各算各的。（4）done 在 50 步处自然截断，回合内没有早期终止，所以 cut 全 0、只有末端为 1，与本课程其他环境一样，截断处理统一走"切断自举"的路线。

片段 4：每智能体一套网络的批量前向

    @torch.no_grad()
    def act_all(self, obs: np.ndarray):
        """整批前向：一次算出所有智能体的动作、对数概率与价值。"""
        obs_t = torch.as_tensor(obs, dtype=torch.float32, device=self.device)
        actions, logps, values = [], [], []
        for i, net in enumerate(self.nets):
            a, lp, v = net.act(obs_t[i:i + 1])       # 只切出第 i 行的观测喂给第 i 个网络
            actions.append(a.squeeze(0).cpu().numpy())
            logps.append(float(lp.item()))
            values.append(float(v.item()))
        return np.asarray(actions, np.float32), logps, values

    @torch.no_grad()
    def mean_actions_all(self, obs: np.ndarray):
        obs_t = torch.as_tensor(obs, dtype=torch.float32, device=self.device)
        acts = []
        for i, net in enumerate(self.nets):
            acts.append(net.mean_action(obs_t[i:i + 1]).squeeze(0).cpu().numpy())
        return np.asarray(acts, np.float32)

解读：网络管理方式一目了然，self.nets 是个列表，第 i 个网络只处理第 i 行观测。（1）obs_t[i:i+1] 保持二维形状（1, obs_dim），因为网络按批量输入设计；如果用 obs_t[i] 会变成一维，Linear 层仍能前向但形状语义混乱，后续 .squeeze(0) 也不统一。（2）逐智能体循环处理，不把 N 行堆成一个大 batch：本环境 N=3，循环的 Python 开销可忽略，换来的是逻辑直白，想查哪个智能体的行为，直接看 nets[i]。（3）训练用 act_all（采样）、评估用 mean_actions_all（确定性），两个函数都带 @torch.no_grad()：采样不需要梯度，也防止计算图泄漏。（4）第 070 章会把 self.nets 变成"一个共享网络"，这两个函数的签名不变，参数共享在代码层面就是列表里放同一个网络。

常见坑

  • 把"环境步"与"智能体步"混着算：一次 env.step 产生 N 条转移。本脚本全部按智能体步计量；如果你按环境步设预算，实际数据量差 N 倍，跨智能体数量的对比就失真了。
  • 用同一个价值函数裁剪所有智能体：独立 PPO 每个智能体有自己的 Vi，GAE 必须按智能体分别计算。把团队奖励与某个智能体的 value 混用会造成优势系统性偏差。
  • 评估用采样动作：N 个随机源叠加会让评估方差爆炸。评估统一用 mean_actions_all 的确定性动作。
  • 把非平稳性当成实现 bug：训练中某个智能体回报突然下降，可能是另一个智能体学会了新行为、改变了整个数据分布。多智能体实验要接受"此消彼长"，看团队总指标。
  • 忘了回合重置时的观测衔接：回合在 done 时重置，但采样循环要在写桶之后再重置，否则会丢掉最后一步的转移，或把新回合的观测接到旧轨迹上。

  2. 把 --n-agents 改成 4 再训练（预算不变），预测并观察末距与碰撞的变化，解释难度上升的原因。★
    提示
    智能体变多后：空间更拥挤、碰撞概率更高、每个智能体分到的数据占比下降。可先把 --max-steps 提高再对比，避免预算不足干扰结论。
  3. 把碰撞惩罚设为 0（改 CooperativeNavEnv 的 collision_penalty），训练后观察末距与碰撞。还有没有避让行为？★★
    提示
    没有惩罚，躲车不再有任何回报，最优策略退化为"各走直线"。这也说明奖励设计决定了会出现什么协调行为。
  4. 把其他智能体的动作估计拼进观测（把上一步所有智能体的动作向量追加到本地观测末尾），看能否缓解非平稳性。★★
    提示
    在 _obs 基础上追加 self.last_actions.ravel()，并在 step 里保存动作；obs_dim 的公式也要同步加上 2N。
  5. 把奖励从"平均匹配距离"改成"总距离"（乘 N），观察价值函数尺度、KL 与训练稳定性有什么变化。奖励尺度与价值学习之间是什么关系？★★★
    提示
    总距离奖励量级是原来的 3 倍，价值回归目标的 MSE 增大，梯度裁剪与学习率可能需要同步调整。对比改动前后的 KL 与裁剪比例。

小结

  • 多智能体问题 = 联合动作 + 共享奖励 + 局部观测；独立 PPO 把其他智能体当环境，实现最简单。
  • 合作导航环境：14 维局部观测、2 维动作、对称的二分匹配奖励，是后续八章的共同底座。
  • 每个智能体有自己的价值函数与 GAE，优势包含自己的碰撞惩罚，"独立"体现在数据流层面，环境本身由全体共享。
  • 预算按智能体步计：一次环境步产生 N 条转移，计量口径不对会让跨配置比较失真。
  • 本环境随机基线约 −25 分，独立 PPO 能把评估回报压到 −6 ~ −3，末距降到 0.05~0.12。
  • 下一章引入 CTDE：执行时各用各的局部观测，训练时共享一个看得到全局状态的批评家。
