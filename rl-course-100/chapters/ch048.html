第二篇 · 离策略方法与 SAC

第 048 章：SAC的梯度裁剪

给 SAC 的 Q 网络与策略网络装上可调阈值的"保险丝"：统计每次更新前的梯度范数分布（均值 / p95 / 最大值），对比不裁剪、0.5、5.0 三种阈值下的触发率与学习曲线，学会让数据决定裁剪阈值，不再凭直觉拍板。

  • 主题：训练稳定化 / 按范数梯度裁剪
  • 关键公式：g ← g · min(1, τ / ‖g‖2)
  • 预计学时：45 分钟
  • 前置章节：第 047 章

学习目标

  • 理解为什么自举式时序差分学习比监督学习更容易出现梯度尖峰。
  • 掌握按范数裁剪（clip_grad_norm_）的数学效果：只缩放幅度、不改变方向。
  • 实现裁剪前梯度范数的逐次记录，会统计均值 / p95 / 最大值与触发率。
  • 对比三种阈值下的达标步数与曲线稳定性，建立"阈值应对齐梯度分布 p95～max"的工程准则。
  • 会区分"裁剪真实生效"与"裁剪形同虚设/过度压制"两种状态，并用触发率判断。

背景与动机

时序差分学习的回归目标里含着自举项 γ·Q̄(s′,a′)，而 Q̄ 又由 Q 的旧参数构成。当某批样本的回报异常大（比如 Pendulum 里罕见的连续高分轨迹）、或目标网络刚经历一次大幅更新时，Q 损失对参数求导后会出现比平时大得多的梯度。Adam 虽然做逐参数尺度归一化，但范数极大的整个参数块仍可能让一次更新把网络推离舒适区，表现为评估回报的断崖式下跌。

梯度裁剪就是给这种尖峰兜底：把超过阈值 τ 的梯度整体缩放到范数 τ。它不改变更新方向，只限制步幅。但裁剪不是免费的保险，阈值选小了，每一次正常更新都会被压缩，等价于偷偷调低学习率；选大了又形同虚设。本章先跑出一次完整的梯度范数分布，再让数据决定阈值该落在哪里。

尖峰的来源可以再拆细一点，便于判断何时该上裁剪：一是目标网络刚经历大幅更新，自举项 γ·Q̄ 突然变化，平方损失的误差放大；二是罕见的高回报轨迹进入 batch，TD 目标比同批其他样本大出一个量级；三是策略与 Q 交替改进的"追逐"阶段，两者误差互相放大。监督学习里标签是固定的，损失曲面也相对平稳；RL 的标签由网络自己产生，这是"右尾梯度"的结构性来源。判据也很直接：如果训练日志里出现过评估回报断崖、随后又缓慢爬回，多半是这类尖峰留下的痕迹。

核心原理

1. 按范数裁剪的公式

设参数梯度向量为 g（把所有参数梯度拼成一个大向量），阈值 τ 大于 0，裁剪后的梯度为：

g ← g · min( 1, τ / ‖g‖2 ) ‖g‖ ≤ τ 时保持原样；‖g‖ 大于 τ 时整体缩放到范数恰好为 τ

符号说明：‖g‖2 是梯度的 L2 总范数（所有参数平方和开根），τ 是裁剪阈值。关键性质：缩放因子是对整段梯度统一的标量，所以梯度方向完全不变，只把步长掐到上限。这与"逐元素按值裁剪"不同，后者会改变方向，还要单独讨论（见练习）。

数值例子：一次裁剪的全过程

把全部参数梯度看成一个二维向量便于展示。设 g = [3, 4]，则 ‖g‖ = √(9+16) = 5，方向为 atan2(4,3) ≈ 53.13°。

阈值 τ=2.5（小于范数，触发裁剪）：缩放因子 = 2.5/5 = 0.5，裁剪后 g′ = [1.5, 2.0]，‖g′‖ = √(2.25+4) = 2.5，方向仍是 53.13°。幅度被掐到上限，方向分毫未动。

阈值 τ=8（大于范数，不触发）：min(1, 8/5) = 1，梯度保持原样，这正是"只在异常时出手"的含义。

对比逐元素按值裁剪（±1.5）：结果 [1.5, 1.5]，方向变成 45°，与原来差约 8°。解读：按范数裁剪是"等比缩放的绳子"，按值裁剪是"逐维上限的笼子"；后者在个别参数梯度爆炸时更精准，但会引入方向偏差，两者的适用场景不同。另有一个近似换算：设学习率 η=3e-4，裁剪后单步位移上限约为 η·τ = 3e-4×2.5 = 7.5e-4，这就是"步长被钉在 η·τ"的量化含义。

2. 为什么用范数统计来选阈值

阈值应该"只在异常时才出手"。把每次更新的梯度总范数记录下来，就得到一条分布：

τ合理 ≈ p95(‖g‖) ~ max(‖g‖) 触发率（‖g‖ 大于 τ 的比例）应控制在 1%～10% 量级；长期高于 50% 说明阈值在常态区内

如果触发率接近 1，说明阈值比绝大多数更新的梯度都小，裁剪变成"统一把梯度压到 τ"，学习率被隐式改写；如果触发率接近 0，则完全没有起到保险作用。工程上先用一两万步的基线跑出 p95 与 max，再把阈值设在略低于 p95 的位置，这样只削右尾、不影响主分布。

3. 与学习率的关系

裁剪阈值 τ 与学习率 η 共同决定有效步长：常态下步长约为 η·‖g‖；被裁剪时步长被钉在 η·τ。因此降低学习率和降低裁剪阈值在"步子变小"这件事上有替代性，但机制不同：前者对所有更新一视同仁，后者只压异常的右尾。这也是"调小 lr"不能完全替代裁剪的原因，裁剪切掉的是分布的右尾，保留高概率区域的分辨率。

4. 三档阈值的预期对照

档位触发率有效步长达标步数曲线特征
none（不裁剪）0完全由 ‖g‖ 决定基准偶发尖峰带来的评估波动
5.0（温和）约 3%～6%仅右尾被削与基准接近与 none 几乎重合，异常点被兜住
0.5（激进）90% 以上长期被钉在 η·0.5明显变大学习整体变慢，等价于隐式调低学习率

三档的读法是"看触发率定位状态"：5.0 档触发率在 10% 以内，属于正常的保险丝；0.5 档触发率超过 90%，说明阈值压进了梯度分布的常态区，裁剪已经变成一种持续的学习率削减。汇总表把"阈值 − 触发率 − 达标步数"三列并排，就是为了让这种"隐式改学习率"的现象直接可见。

实现思路与设计

数据流

训练闭环与第 047 章相同，只在优化器更新之前插入裁剪与统计：Q 反传后先算裁剪前的 Q 梯度总范数 → 对 Q1、Q2 分别裁剪并合并触发标志 → step()；策略反传后同样统计并裁剪。每 2000 步评估时打印最近 2000 次更新的范数均值、p95 与触发率。三种阈值（none / 0.5 / 5.0）同种子、同步数、同学习率。这样安排让"裁剪是否改变训练"与"裁剪是否被触发"两件事在日志里同时可见：性能曲线回答前者，触发率回答后者，两者不一致时优先检查统计是否发生在裁剪之前。

模块划分

组件职责关键点
grad_norm(module)求参数梯度 L2 总范数在 backward() 之后、step() 之前调用
apply_clip(module, clip)按阈值调用 clip_grad_norm_ 并返回触发标志返回 norm > clip，用于统计触发率
SAC.update(batch, args, clip)Q 与策略两次反传分别记录、分别裁剪Q1、Q2 都要裁；布尔值先算再合并
train_clip(clip)按阈值训练并汇总范数统计0 表示不裁剪，作为基线

关键超参数

参数默认值作用与取值理由
--clipsnone,0.5,5.0基线 + 激进 + 温和三个档位；脚本把 none 解析成 0
--max-steps16000每种策略的预算，三组共 4.8 万步
--eval-every2000评估点同时打印最近 2000 次更新的范数均值、p95 与触发率
--lr3e-4标准学习率；调大它梯度尖峰问题会更突出
--tau / --batch-size0.005 / 256与前面章节保持一致，避免引入新变量

统计窗口取"最近 2000 次更新"有两个原因：一是单次范数的波动极大，瞬时值无法判断趋势；二是 2000 次恰好等于一个评估间隔（2000 步、每步更新一次）的更新量，与训练阶段对齐，读到的分布反映"当前阶段"，整场平均由汇总统计承担。汇总时的 p95 与 max 则用全历史统计，因为阈值决策关心的是"最坏情况有多坏"，历史极值不能被窗口平滑掉。两个口径分工明确：窗口看状态，全量定阈值。

与前一章的差异点

  • 第 047 章改网络内部结构（归一化层）；本章网络结构不变，只在优化器更新前插入裁剪。
  • 新增 grad_norm 与 apply_clip 两个工具函数，Q 网络与策略网络分别裁剪。
  • update() 返回 q_grad_norm / p_grad_norm / clipped 三个诊断量，供逐点统计。
  • 汇总口径变成"阈值 − 触发率 − 达标步数"的关系表。

关键代码与解读

片段 1：两个小工具，量范数与裁剪

def grad_norm(module: nn.Module) -> float:
    """参数梯度总范数（L2），在优化器 step 之前调用。"""
    total = 0.0
    for p in module.parameters():
        if p.grad is not None:               # 未参与计算的参数 grad 为 None
            total += float((p.grad ** 2).sum())   # float() 断开计算图，纯记数
    return float(np.sqrt(total))


def apply_clip(module: nn.Module, clip: float) -> bool:
    """按阈值裁剪梯度范数，返回是否触发了裁剪。"""
    norm = grad_norm(module)                 # 先量后裁：量到的是"裸"范数
    if clip > 0.0:
        nn.utils.clip_grad_norm_(module.parameters(), clip)
    return clip > 0.0 and norm > clip        # 触发 = 阈值有效 且 裸范数超限

解读：（1）统计必须发生在裁剪之前，如果先裁再量，得到的范数恒不超过 τ，分布统计失去意义。p.grad is not None 的判断不能省：某些参数若这一步没有参与计算，grad 为 None。（2）float(...) 把张量转成 Python 数，顺带断开与计算图的联系，保证统计不干扰反传。（3）apply_clip 返回布尔触发标志，这是触发率的原始信号；clip=0 表示不裁剪，返回 False。（4）PyTorch 的 clip_grad_norm_ 内部就是"算总范数 → 缩放"，与手写公式一致，但实现经过优化、就地修改，不要自己重写。

片段 2：update 里的"先统计、再裁剪"

        q1 = self.q1(obs, act)
        q2 = self.q2(obs, act)
        q_loss = F.mse_loss(q1, backup) + F.mse_loss(q2, backup)
        self.opt_q.zero_grad()

            if p.grad is not None:
                q_raw += float((p.grad ** 2).sum())
        q_raw = float(np.sqrt(q_raw))
        c1 = apply_clip(self.q1, clip)       # 先各自裁剪、各自返回标志
        c2 = apply_clip(self.q2, clip)
        q_clipped = c1 or c2                 # 合并成"本次更新是否触发过"
        self.opt_q.step()

        new_act, logp = self.policy.sample(obs)
        q_pi = torch.minimum(self.q1(obs, new_act), self.q2(obs, new_act))
        policy_loss = (self.alpha.detach() * logp - q_pi).mean()
        self.opt_policy.zero_grad()
        policy_loss.backward()

        apply_clip(self.policy, clip)

解读：（1）Q 网络把 Q1、Q2 的参数合并计算"总范数"：两个网络共享一个优化器，范数应作为整体看待；但裁剪要对两个模块分别调用（各自拥有自己的梯度张量）。（2）c1 = ... 与 c2 = ... 先算好再合并，若写成 apply_clip(q1, clip) or apply_clip(q2, clip)，Python 的短路求值会在 q1 触发时跳过 q2 的裁剪，留下"只裁了一半"的网络，这是非常隐蔽的 bug。（3）策略网络单独统计 p_raw 并用同一阈值裁剪：策略损失的梯度也可能突然变大，保险丝要覆盖两个优化器。（4）温度系数 log_alpha 的更新幅度天然很小，不裁剪。

解读：（1）均值、p95、max 三个数回答三个问题：均值说"常态梯度多大"，p95 说"多数尖峰到哪"，max 说"最坏情况多糟"，阈值选择就夹在 p95 与 max 之间。（2）触发率用滑窗（最近 2000 次）统计：它是"阈值合适度"的仪表，不是训练曲线，长期高于 0.5 就说明阈值压进了常态区。（3）注意对裁剪档位来说，这里统计的范数始终是裁剪前的（q_norms 里存的是 q_grad_norm），否则被压到 τ 的读数会让分布看起来完全健康，那是自欺欺人。（4）最后把四个统计量与达标步数、后期评估 std 一起进汇总表，形成"阈值 − 触发率 − 性能"的三列对照。

常见坑

  • 在 step() 之后统计梯度：优化器与 zero_grad 会清空或覆盖 grad，量到 0 或旧值。统计与裁剪都必须在 backward() 与 step() 之间完成。
  • zero_grad 顺序颠倒：必须在反传前清零。若梯度跨更新累积，范数统计偏大、裁剪频繁误触发。
  • 用 or 合并两次裁剪调用：Python 短路求值会跳过第二个网络的裁剪，留下半裁剪状态。先把两个布尔值各算出来再合并。
  • 把裁剪阈值当成"试出来就行"的参数：阈值应参照梯度分布 p95 来定；触发率是现成的反馈信号，比反复试回报高效得多。修复：先跑一轮 none 档记录分布，再按 p95 设阈值并复跑核对触发率。
  • 只裁 Q 网络忘了策略网络：Q 的尖峰更常见，但策略损失的梯度同样会爆；本章对两个优化器都装了保险丝，统计时应分开看 q_grad_norm 与 p_grad_norm，它们的尺度天然不同。

  5. 在 MountainCarContinuous-v0 上重复实验，找出该环境的梯度范数 p95，并据此给出一个阈值建议。★★★
    提示
    --env MountainCarContinuous-v0 --max-steps 30000。该环境成功回报 +100，早期 TD 目标波动更大，p95 通常显著高于 Pendulum，先跑 none 档看分布，再定建议值。

小结

  • 自举目标与平方损失让 TD 学习天然带右尾梯度；裁剪用 g ← g·min(1, τ/‖g‖) 只压幅度、不改方向，是"等比缩放的绳子"，逐维的笼子留给按值裁剪。
  • 阈值选择的工程准则是看梯度范数分布：p95 附近设阈值、"偶尔触发"最好；触发率长期高于 50% 等于偷偷改学习率，低于 1% 则保险丝形同虚设。
  • 本章实现了逐次梯度范数统计（均值 / p95 / max）与触发率指标，把裁剪从"保险丝"变成可测量、可调优的组件，阈值决策因此有了数据依据，手感让位给统计。
  • Pendulum 上裁剪很难看出好处（任务温和）；真正需要它的是大学习率、深网络、稀疏奖励等梯度尖峰更频繁、右尾更长的场景。
  • 裁剪的数值本质：g=[3,4]、τ=2.5 时缩放到 [1.5,2.0]，范数恰好 2.5、方向保持 53.13°；逐元素按值裁剪则会引入约 8° 的方向偏差。
  • 统计口径有一条铁律：所有范数都必须是裁剪前的读数，否则分布被自身修改，触发率与 p95 全部失真、阈值决策失去依据。
