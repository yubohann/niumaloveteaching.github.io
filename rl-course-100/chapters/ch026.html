第 026 章：PPO的信任域约束可视化

把"裁剪半径"翻译成看得见的证据：裁剪目标数值表、KL 轨迹火花线、策略比率文本直方图，以及四档信任域（0.1 / 0.2 / 0.5 / KL 早停）的稳定性与计算量对比。

  • 主题：信任域 / 诊断与可视化
  • 关键公式：LCLIP = 𝔼[min(r·Â, clip(r, 1−ε, 1+ε)·Â)]；KL 早停：𝔼[log πold−log πθ] > KLtarget

学习目标

  • 从"比率空间"与"概率空间"两个角度理解 PPO 信任域约束的含义。
  • 实现带诊断输出的 ppo_update：比率统计、裁剪比例、按 epoch 的 KL 早停。
  • 用纯文本图表呈现 KL 轨迹与策略比率分布，理解"越界即停"的几何图像。
  • 对比裁剪半径 0.1 / 0.2 / 0.5 与 KL 早停四档配置，说明信任域半径、稳定性与计算开销的三角关系。
  • 掌握判断一次 PPO 更新"是否过火"的指标组合：平均 KL、最大 KL、裁剪比例、比率标准差。

背景与动机

PPO 的理论出发点是一句话：策略更新不能离旧策略太远。TRPO 用 KL 约束把这个直觉写成了带约束的优化问题，PPO 则用一次裁剪近似它。前几章你一直在用裁剪，但它到底约束了什么、越界之后梯度去哪了、半径 0.1 和 0.5 的差别长什么样，这些问题在没有"证据"时只能靠背结论。

本章换一种讲法：把信任域画出来。不依赖任何绘图库也能完成，裁剪目标做成数值表，KL 做成火花线，比率做成文本直方图。再配四档配置的对照实验：半径 0.1 有多保守、0.5 有多激进、按 KL 早停如何"按需分配计算量"。做完这一章，你再看训练日志里的 KL 与裁剪比例，脑子里会有一幅具体的图。

核心原理

1. 信任域的两种表述

TRPO 的约束写在概率空间：每次更新后的策略与旧策略的平均 KL 不超过 δ：

maxθ 𝔼[ rt(θ) Ât ]   s.t.   𝔼s[ KL(πθ_old(·|s) ‖ πθ(·|s)) ] ≤ δ

PPO 的裁剪写在比率空间：单个样本的重要性比率被限制在 [1−ε, 1+ε] 内：

LCLIP = 𝔼[ min( rtÂt, clip(rt, 1−ε, 1+ε) Ât ) ] 对 Â>0：比率冲到 1+ε 之后梯度为 0；对 Â<0 镜像成立

两种表述描述同一件事：单步更新允许的概率变化要有界。区别是 KL 在"整批样本的平均意义"上有界，而裁剪是"逐样本"的有界，这也是 PPO 实现便宜的原因。

裁剪半径的两个极端也要看清：ε→0 时几乎没有样本的比率落在 [1−ε, 1+ε] 内，目标函数接近常数、梯度趋近 0，训练直接停摆；ε≥1 时裁剪区间覆盖了常见比率范围，裁剪不再触发，PPO 退化成无约束的策略梯度。可用的半径大致在 0.05～0.3 之间：低于 0.05 相当于给每次更新上重锁，高于 0.3 约束基本失效（练习 1 的 1.0 档就是这条边界的实测）。实践起点建议沿用 0.2，再按裁剪比例微调：比例长期低于 2% 就收窄半径，长期高于 30% 就放宽或降学习率。

2. "越界即停"的数值形态

把 min 拆开看：当 Â>0 且 r 超过 1+ε，min 选中的是常数 clip 项，对 θ 的导数为零；r 位于区间内时选中未裁剪项，正常上升。于是裁剪目标关于 r 的图像是"先升后平"的折线：折点就是信任域边界。程序开头打印的数值表会把这根折线逐行展示出来，包括每个 r 对应的 A=+1 / A=−1 两列取值。这是理解 PPO 稳定性的第一张图。

取 ε=0.2 走几个点，边界的手感就出来了：r=1.0 时两列都是 1.0，在界内、梯度正常；r=1.2 恰好落在边界；r=1.3 时未裁剪列 1.3、裁剪列 1.2，min 取 1.2，r 再大这个值也不变，梯度为零。Â<0 一侧镜像：r=0.7 时 −max(0.7, 0.8) = −0.8，梯度同样归零；r=0.8 恰在边界。也就是说每个样本的"有效约束"是单侧的：正优势样本只被上界管住，负优势样本只被下界管住。这个细节在解读裁剪比例统计时会再次出现。

3. KL 早停：自适应半径

固定 epochs 的 PPO 在同一批数据上反复更新，比率会随轮次逐渐发散，数据"越来越旧"。KL 早停给它装上刹车：每个 epoch 结束时测一次当前策略相对采样快照的平均 KL，超过目标就停止本批更新：

if   𝔼[ log πθ_old − log πθ ] > KLtarget  →  结束本批 epochs

它实现的是"按需分配计算量"：容易的批次几轮就够，困难的批次允许用满 10 轮，但永远不越线。本章的 klstop 臂会记录平均用掉的 epochs，这就是它的直接成本。

KL 的估计形式也值得记两笔。本章用的是 k1 估计 E[log πold − log πθ]；另一个常用形式是 k3 估计 E[(r−1) − log r]。两者在旧策略分布下取期望都恰好等于真实 KL（用到 E[r]=1 与 E[log r]=−KL 两条恒等式），但逐样本行为不同：r=1.5 时 k1 给出 −0.405、k3 给出 +0.095；r=0.8 时 k1 是 +0.223、k3 是 +0.023。k1 会出现负值，无法逐样本解释为"距离"；k3 恒非负、方差更小，很多实现用它做早停判据。小 KL 区间两者数值接近，换估计形式对阈值的影响通常在 10% 以内，但读数口径要在实验报告里注明。

把刹车省下的计算量算成账：某批数据的逐轮 KL 为 0.005、0.011、0.018、0.027，阈值 0.02 在第 4 个 epoch 越线，本批只用 4/10 轮、省下 60% 的更新计算；若整场训练平均 6.5 轮，更新开销是固定 10 轮基线的 65%，省 35%。省下的部分不免费，它换成"同一批数据少榨几轮"，最终成绩是否受损要看回报曲线；直觉判断在这里不可靠。

4. 三个诊断指标怎么配合

  • 平均 KL：0.005～0.02 是健康区间；单次更新飙到 0.05 以上说明步子太大；
  • 裁剪比例：被裁剪样本占比。长期接近 0 说明半径太宽（约束没起作用），长期很高说明更新过猛或半径太窄；
  • 比率标准差：分布宽度。σ 很大说明旧数据与新策略分歧巨大，训练信号大量落在平坦区里被浪费。

三者一起看，就能在回报还没崩之前判断信任域是否失守。读数时补两个细节：其一，clip_frac 统计的是两侧越界的总比例，但每侧只对特定符号的优势生效（正优势越上界、负优势越下界才产生零梯度），一个偏高的裁剪比例可能全部来自一侧，配合优势符号分布才能解读；其二，平均 KL 小不等于安全，平均被大量小值拉低时，少数 r 爆大的样本仍会贡献大块零梯度区域，所以最大 KL 与比率 σ 要和平均值一起看，三个数落在同一档才叫稳定。

两种信任域表述的差异也在这里显形：TRPO 约束的是整批平均的 KL，PPO 裁剪的是逐样本的比率。一批数据平均 KL 很小、但存在少量极端比率样本时，TRPO 的约束不会触发，PPO 的裁剪已经在丢弃那部分的梯度；反过来，整批样本都均匀地偏一点，PPO 会把它们全部裁掉，而平均 KL 可能还在约束之内。同样是"稳"，两种机制的触发条件并不重合，这就是本章要把直方图与裁剪边界画出来的原因。

把三件套组合起来看，常见形态可以列成一张排查表：

平均 KL裁剪比例比率 σ常见解读与动作
低低小健康收敛；若长期如此且回报不动，检查半径是否过宽
低高小半径太窄：梯度被大面积削掉，放宽 ε 或降低 epochs
高高大更新过猛：先降学习率，再考虑收紧半径或提前刹车
均值正常但最大 KL 尖峰偶发高偶发放大个别批次失稳：看对应数据，启用 KL 刹车兜底

与第 025 章的差异点

  • 回到单环境：本章不研究吞吐，回到最朴素的采样-更新循环，把注意力放在更新侧。
  • 更新函数升级：ppo_update 现在返回 10 个诊断量，并支持 KL 刹车。
  • 可视化产出：每个臂结束都会打印 KL 火花线与比率直方图；加 --plot 才出 PNG。
  • 实验目标：比较"信任域半径带来的稳定性特征"，不再追求"谁分高"。
早停写在 epoch 层，不写在 minibatch 层

内层 minibatch 的瞬时 KL 噪声很大，按它刹车容易误触发；本实现把整轮 32 个 minibatch 的 KL 求平均后才与 target_kl 比较。这个平均也更接近"这批数据已经被榨干了"的真实状态。另外，损失里的 clamp 与统计裁剪比例必须用同一个 clip 变量，否则日志会彻底误导你。

关键代码与解读

片段 1：裁剪目标的数值表，把折线打印出来

def print_surrogate_table(clip):
    """打印裁剪目标的数值表，直观展示"越界即常数"的机制。"""
    print(f"\n裁剪目标 L = min(r*A, clip(r, 1-clip, 1+clip)*A) 的数值表：")
    print(f"{'ratio r':>9}{'A=+1: 未裁剪':>14}{'A=+1: 裁剪后':>14}"
          f"{'A=+1: min':>11}{'A=-1: min':>11}")
    low, high = 1.0 - clip, 1.0 + clip
    for r in np.arange(0.5, 1.51, 0.1):
        r = round(float(r), 2)
        surr_r = r
        clipped_r = min(max(r, low), high)   # 把比率夹在 [1-c, 1+c]
        a_pos = min(surr_r, clipped_r)       # A>0：min 在两列中取小
        a_neg = -max(surr_r, clipped_r)      # A<0：镜像（取负后较大者胜出）
        note = "  <-梯度0" if (r > 1.0 + clip) else ""
        print(f"{r:>9.2f}{surr_r:>14.2f}{clipped_r:>14.2f}{a_pos:>11.2f}{a_neg:>11.2f}{note}")
    print("解读：A>0 时 r 超过上界后 min 停在裁剪值上（斜率 0）；"
          "A<0 时镜像成立。这就是'越界即停'的信任域。")

解读：这段 15 行的打印函数是本章的第一张"理论图"，不训练就能看懂裁剪的本质。（1）min(max(r, low), high) 是"把 r 夹进 [1−ε, 1+ε]"的手写版 clamp，与 PyTorch 的 torch.clamp 一一对应。（2）a_pos = min(surr_r, clipped_r) 复现了损失里的 min 逻辑：r 在界内两列相等，越界后 clipped 列为常数，于是该行的"min"列不再随 r 变化，导数为 0。（3）a_neg = -max(surr_r, clipped_r) 是 Â<0 的镜像写法（取负之后"取小"变成"取大"），对照着看两列，你会确信两边的边界都关得住。理解了这个表，后面一切裁剪现象都有了锚点。

片段 2：诊断统计与 KL 刹车

        for start in range(0, N, args.batch_size):
            mb = idx[start:start + args.batch_size]
            logits, value = net(obs[mb])
            dist = Categorical(logits=logits)
            logp = dist.log_prob(act[mb])

            ratio = torch.exp(logp - logp_old[mb])
            surr1 = ratio * adv[mb]
            surr2 = torch.clamp(ratio, 1.0 - clip, 1.0 + clip) * adv[mb]
            policy_loss = -torch.min(surr1, surr2).mean()
            value_loss = F.mse_loss(value, ret[mb])
            entropy = dist.entropy().mean()
            loss = policy_loss + args.vf_coef * value_loss - args.ent_coef * entropy

            optimizer.zero_grad()
            loss.backward()
            nn.utils.clip_grad_norm_(net.parameters(), 0.5)
            optimizer.step()

            with torch.no_grad():                        # 诊断统计：不产梯度
                approx_kl = (logp_old[mb] - logp).mean().item()
                r = ratio.detach()
                sum_r_std += r.std().item() if r.numel() > 1 else 0.0
                if ratio_sink is not None and len(ratio_sink) < 6000:
                    ratio_sink.extend(r.cpu().numpy().tolist())   # 留给直方图
            sum_kl += approx_kl
            epoch_kl += approx_kl

        epochs_used += 1                      # 实际用掉的 epoch 数（klstop 的成本指标）
        epoch_kl /= max(epoch_mb, 1)
        if target_kl is not None and epoch_kl > target_kl:
            stopped_by_kl = 1.0
            break                             # 本批数据"榨够了"：刹车

解读：与 001 章的更新循环相比，这里多了三层监测。（1）所有统计都在 no_grad 下做：ratio.detach() 切断计算图，防止诊断代码偷偷延长反向传播的链路。（2）ratio_sink 是"可选副作用"设计：传 None 时不收集（零开销），传 list 时把比率样本追加进去、上限 6000 条防内存膨胀，只为画一张直方图服务。（3）KL 判定发生在内层循环全部结束之后：epoch_kl /= max(epoch_mb, 1) 求本轮平均，超过 target_kl 就置标志并 break。为什么不用 minibatch 瞬时值？瞬时 KL 抖动大，容易误触发；按轮平均才是"这批数据是否已被榨干"的可靠判据。（4）epochs_used 单独计数，即使中途 break 也能得到真实的轮数，它就是这个配置的"计算量账单"。

片段 3：比率直方图，文本版分布图

def ascii_hist(values, lo=0.3, hi=1.7, bins=28, mark=(0.8, 1.2), title=""):
    """把一批比率画成文本直方图；mark 给出要标注的裁剪边界。"""
    v = np.asarray(values, dtype=np.float64)
    v = np.clip(v, lo, hi)                     # 截断：先看主体形态，尾部不展开
    counts, edges = np.histogram(v, bins=bins, range=(lo, hi))
    scale = max(1, counts.max())               # 用峰值归一化，条长相对可比
    lines = [title + f"（样本 {len(v)}，{lo:.2f}~{hi:.2f}，每行一个区间）"]
    mark_bins = [int((m - lo) / (hi - lo) * bins) for m in mark if lo <= m <= hi]
    for i, c in enumerate(counts):
        bar = "#" * int(round(c / scale * 48))  # 最长 48 格的横条
        flag = "  <-- 裁剪边界" if i in mark_bins else ""
        lines.append(f"  {edges[i]:.2f} |{bar:<48}{flag}")
    return "\n".join(lines)

解读：十几行代码把"比率分布"变成终端里能直接看的东西。（1）np.clip(v, lo, hi) 是刻意的可视化取舍：把超出 [0.3, 1.7] 的极端值折进边缘桶，防止一根超长拖尾毁掉整张图的可读性，但心里要记住它不是精确分布。（2）counts.max() 归一化让条长代表相对质量，不同臂的图可以直接对照。（3）mark_bins 把裁剪上下界换算成桶号，命中就标"裁剪边界"，一眼就能看出有多少比例的质量落在边界之外（那部分就是"梯度为零"的部分）。对比 clip0.1 与 clip0.5 的两张图，信任域半径的物理意义立刻可见。

健康直方图长什么样：主体集中在 1.0 附近、左右大致对称、越界质量占比小。三种异常形态各有含义：整体偏向 1.0 右侧说明新策略对被采样动作的概率普遍上调，若同时裁剪比例高，说明更新正在被大量截断；分布过宽、左右拖长尾，说明这批数据与新策略分歧过大，应减小 epochs 或收紧半径；主体整体平移离开 1.0，通常意味着 logp 基准被写错（例如误用了噪声分布的 logp），值得优先排查实现；调参解决不了这类问题。

        update_idx += 1

        if solved_at is None and len(all_returns) >= 100 and \
                np.mean(all_returns[-100:]) >= args.target_reward:
            solved_at = total_steps

    # 文本可视化：KL 轨迹 + 最后一次更新的比率分布
    print("    " + ascii_sparkline(kl_series, width=min(len(kl_series), 72), label="KL "))
    print(ascii_hist(last_ratios, lo=0.3, hi=1.7, bins=28,
                     mark=(1.0 - clip, 1.0 + clip), title=f"  比率直方图 {tag} "))

解读：单臂循环本身与 001 章几乎一致，多了三条"证据流水线"。（1）每轮新建 sink 并只在循环结束后把最后一次的 sink 赋给 last_ratios：直方图展示的是训练末期（策略已稳定）的比率形态；被早期随机策略污染的分布不进入展示。（2）三个序列 kl_series / clip_series / epoch_series 逐轮追加，训练结束后直接交给可视化函数；epoch_series 的均值就是汇总表里的"平均 epochs"。（3）ascii_sparkline 控制宽度 min(len, 72)：短训练不拉伸、长训练等宽重采样，任何预算下曲线形态都可读。四臂的图并列摆在输出里，稳定性差异一目了然。

完整可运行脚本（附录）：code/ch026.py

python code/ch026.py            # 四臂：0.1/0.2/0.5/klstop，各 5 万步，CPU 约 2–4 分钟
python code/ch026.py --quick    # 快速跑通：30–60 秒
python code/ch026.py --arms klstop --target-kl 0.01 --plot   # 更严刹车 + 可选 PNG

以实跑为准：裁剪半径越大，平均/最大 KL 越高、比率分布越宽；clip0.1 最稳但首达 475 通常最慢，clip0.5 早期快、KL 波动大。klstop 的最大 KL 通常被压在 0.025 以内，平均 epochs 落在 5～8，用约三分之一到一半的计算量达到与固定半径相近的最终水平。四臂贪婪评估通常都在 470～500 之间。四档的"特征"可以整理成一张对照表：

配置平均 KL最大 KL裁剪比例平均 epochs首达 475
clip=0.1最低低偏高（半径窄）10（固定）最慢
clip=0.2居中居中中10居中
clip=0.5最高高、波动大接近 0（约束名存实亡）10早期快
klstop（0.02）被压在目标附近不超过约 0.025中5～8与固定半径相近

表的读法：前两列是"约束是否起作用"，中间两列是"代价"，最后一列是"结果"。任何一档如果平均 KL 长期低于 0.005 且裁剪比例接近 0，说明信任域过宽，等于没开；如果裁剪比例长期高于一半，说明半径或学习率需要收紧。把这张表和直方图放在一起，就是一次更新"是否过火"的完整证据链。

常见坑

  • 按 minibatch 瞬时 KL 做早停：单个小批量的 KL 抖动可能超过 0.05，容易误触发刹车、把训练拖慢。修复：在 epoch 级别取平均，或对最近若干个 minibatch 做滑动平均。
  • 损失裁剪与统计裁剪用不同的半径：如果 clamp 里的 epsilon 和 clip_frac 统计用的阈值不是同一个变量，日志会彻底误导你。修复：半径作为参数统一传入，不要另开一份。
  • 把直方图当作精确分布：样本来自"最后一次更新、陆续演化的策略"，而且被截断在 [0.3, 1.7]，它只用于观察形态趋势，不能推断比率的真实尾部。
  • 忽略终端编码：文本火花线依赖 Unicode 方块字符，老控制台可能直接报编码错误。修复：保留 _spark_chars() 的 ASCII 降级逻辑。
  • 把 KL 早停当免费午餐：刹车越早，同一批数据的利用越不充分。阈值过小时训练会变慢，要同时记录平均 epochs，评估"省下的计算量"与"延迟的收敛"哪个更贵。

练习与思考

  1. 运行 --arms 0.02,0.2,1.0，比较三档的火花线形态与首达步数，指出哪一档的裁剪比例长期低于 5%（说明约束名存实亡）。★
    提示
    半径 1.0 时裁剪几乎不触发，等价于去掉信任域。看汇总表的"平均裁剪比例"一列。
  2. 把 --target-kl 设为 0.005 与 0.05 各跑一次 klstop 臂，记录平均 epochs 与 KL 轨迹，解释刹车阈值如何变成"计算量分配器"。★
    提示
    阈值越小刹车越频繁，平均 epochs 明显下降；观察回报是否同步变慢，还是"少干活也够用"。
  3. 实现"自适应裁剪半径"：每次更新后按 clip ← clip × (target_kl / 实测KL)0.5 调整半径（限幅 [0.05, 0.5]），与固定半径对比 KL 轨迹的平坦程度。★★
    提示
    在 run_arm 的循环里维护一个可变 clip_now，每轮用上一轮的 stats["approx_kl"] 更新它，再传给 ppo_update。这就是第 021 章 σ 自适应在裁剪半径上的镜像。
  4. 统计"同一批数据在 10 个 epoch 中比率标准差的变化"：每个 epoch 把 ratio.std() 记进列表并打印文本曲线，验证"多轮更新让分布越来越宽"的假设。★★
    提示
    在 ppo_update 里按 epoch 累计 r.std() 的平均并返回序列；预期 σ 随 epoch 单调上升，klstop 臂在刹车处截断。
  5. 实现"越界回滚"：每个 epoch 开始时克隆一份参数，若该轮结束的 KL 超过硬上限（如 2×target）就恢复克隆参数并终止本批更新。对比 klstop 的"提前停"与"回滚"两种保护方式。★★★
    提示
    用 copy.deepcopy(net.state_dict()) 或逐参数 clone() 保存；回滚后优化器状态（Adam 动量）要不要一起回滚是值得讨论的细节，先试试只回滚参数会发生什么。

小结

  • 信任域有两种表述：TRPO 用概率空间的 KL 约束，PPO 用比率空间的裁剪区间，两者都在限制"单步更新走多远"。
  • 裁剪目标的数值形态是"先升后平"：折点位于 1±ε，越界后梯度为零，这就是 PPO 不需要二阶优化的原因。
  • KL 早停把固定轮数换成自适应刹车：klstop 臂平均只用 5～8 个 epoch，就把 KL 压在目标附近。
  • 训练诊断三件套：平均 KL、裁剪比例、比率 σ；配合比率直方图能提前发现"更新过火"或"约束失效"。
