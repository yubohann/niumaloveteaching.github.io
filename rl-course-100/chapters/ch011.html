第一篇 · 策略梯度与 PPO

第 011 章：PPO的连续动作空间的高斯策略

把策略从 Categorical 换成高斯，在 Pendulum-v1 上比较"共享 σ"与"状态相关 σ"两种参数化，并对比 clamp 与 tanh 两种动作边界处理，连续控制的三个核心工程问题一次讲清。

  • 主题：连续控制 / 高斯策略
  • 关键公式：log π = −(a−μ)²/(2σ²) − log σ − ½log(2π)；tanh 修正 −log|g′(u)|
  • 预计学时：60 分钟
  • 前置章节：第 010 章

学习目标

  • 理解连续动作空间的策略分布：π(a|s) = N(μθ(s), σ²)，以及均值与标准差各自的职责。
  • 实现两种 σ 参数化（共享参数 vs 状态相关头），并记录训练中的 σ 轨迹。
  • 实现 clamp 与 tanh 两种动作边界处理，掌握 tanh 变换的对数概率雅可比修正。
  • 在 Pendulum-v1 上完成受控对比，按回报、σ 轨迹、KL 与达标步数评价两种参数化。
  • 建立连续控制的评估习惯：确定性评估直接取分布均值，不再采样。

背景与动机

CartPole 的策略输出两个 logits、按概率采样；而机械臂关节扭矩、无人机推力、摆杆力矩都是连续量。连续策略的标准形状是高斯：网络输出均值 μ(s)，再加一个标准差 σ 控制探索。这个 σ 看似只是一个"噪声旋钮"，却决定了训练的性格，它太大，动作随机、学习信号被稀释；它太小，策略很快变确定、错过改进机会。

两个工程问题随之而来。第一，σ 要不要与状态相关：共享一组 σ 参数最少、最稳；让 σ 也由网络输出，理论上能在不同状态自动调节探索，但数值更易失控。第二，动作有界怎么办：高斯是无界的，而 Pendulum 的力矩必须在 [−2, 2]。直接裁剪简单，但边界处概率质量被"折叠"；用 tanh 压缩则必须补偿雅可比项，否则对数概率全错。本章把这两个问题都做成可以跑的对比。

核心原理

1. 高斯策略与对数概率

对一维动作：

πθ(a|s) = N(a; μθ(s), σθ(s)2)，　log π = −(a−μ)2/(2σ2) − log σ − ½log(2π)

μ 决定动作的"意图"，σ 决定"抖动幅度"。PPO 用得分函数估计梯度（不需要重参数化：那是 SAC 的做法，第 036 章会讲），所以采样得到的动作必须连同它的对数概率一起存下来，更新时用同一组参数重新计算 log π 得到比率。高斯分布的微分熵也在分母里出现 σ：

H = ½ log(2πe σ²)　（一维；σ→0 时熵 → −∞） 这就是连续控制里熵正则的物理含义：奖励"保持一定抖动"

把熵按 σ 逐档列出（nats 量纲，动作上限 L=2）：

σ微分熵 H动作抖动幅度
1.001.42约占动作范围的 ±0.5L
0.500.73约占 ±0.25L
0.300.22约占 ±0.15L
0.10−0.88约占 ±0.05L，接近确定

读取方式：H(σ) = H(1) + ln σ，σ 每减半熵减少 ln 2 ≈ 0.693；当 σ 小于 1/√(2πe) ≈ 0.242 后熵转为负数，σ→0 时趋向 −∞。把 σ 从 1.0 压到 0.3，熵从 1.42 掉到 0.22：探索几乎关闭，若此时策略尚未学好，后续改进的空间同步关闭。这条曲线是下一节"σ 为什么会自己收缩"与"塌缩为何危险"的共同背景。

数值例子：同一组参数下的对数概率

取 μ=0.5、σ=1、动作上限 L=2，逐个代入公式（其中 −½log(2π) ≈ −0.919）：

基准：u=0.5 时 log N(u) = −(0.5−0.5)2/2 − 0.919 = −0.919。

tanh，u=0.5：动作 a = 2·tanh(0.5) ≈ 0.924，导数 g′(0.5) = 2(1−tanh20.5) ≈ 1.573，修正项 log g′ ≈ 0.453。log π(a) = −0.919 − 0.453 = −1.372，比基准低，因为变换在这里把区间拉长了。

tanh，u=2.0：a ≈ 1.928，g′(2.0) = 2(1−tanh22.0) ≈ 0.141，修正项 ≈ −1.957；log N(2.0) = −(2.0−0.5)2/2 − 0.919 ≈ −2.044。log π(a) = −2.044 + 1.957 = −0.087，比基准高，因为饱和区间被压缩、密度在动作空间被抬升。

clamp，u=3.0：动作被压到 a=2.0，代码记录的 logp 仍是 log N(3.0) = −(3.0−0.5)2/2 − 0.919 ≈ −4.044。但此时"动作 2.0"实际承载的是 u≥2 的全部概率质量，按正态分布计算约为 0.067，二者的口径并不一致。

解读：雅可比修正既可能拉低也可能抬高对数概率，取决于 g′ 大于 1 还是小于 1；它是对"换元"的严格补偿。把 u=2.0 这一档翻成密度倍数：漏掉修正时该点的密度被低估 e1.957 ≈ 7.1 倍。更新时新旧 logp 用同一套错算部分抵消，策略一移动抵消就不再对称，KL 与裁剪统计会最先报警。而 clamp 在边界处把连续密度折叠成点质量，记录的 logp 与真实动作分布存在系统性偏差，这正是它只适合"很少打满边界"任务的原因。

2. σ 的两种参数化

  • 共享 σ：σ 是一个独立可学习参数（整个任务一套），梯度由所有样本共同决定。它变化慢、方差小，是大多数 PPO 连续控制实现的默认。
  • 状态相关 σ：网络额外输出 log σ(s)，逐状态调探索。表达能力强，但要限制输出范围（本实现 clamp 到 [−5, 2]，即 σ ∈ [0.007, 7.4]），否则个别状态的巨大 σ 会污染优势估计。

两种参数化共享同一个"策略改进"逻辑，差别只是 σ 的自由度；本章用同种子对照，观察 σ 轨迹与训练稳定性。

σ 为什么会自己收缩，可以用得分函数算清楚。对 log π = −(a−μ)2/(2σ2) − log σ − ½log(2π) 求偏导，两支梯度是 ∇μlog π = (a−μ)/σ2 与 ∂log π/∂log σ = (a−μ)2/σ2 − 1。第一支说明均值方向的梯度噪声按 1/σ2 放大：σ=0.3 时是 σ=1 时的 11 倍，这是 σ 不能取太小的直接原因。第二支在固定策略下的期望为 0，乘以优势之后，靠近均值（|a−μ|<σ）且优势为正的样本给 log σ 负梯度，远离均值的样本给正梯度；训练早期多数正优势样本落在均值附近，净效果就是 σ 缓慢下降，直到继续收紧会损失回报的平衡点。共享版与状态相关版的差别，只在第二支梯度是全任务平均还是逐状态平均。

维度共享 σ状态相关 σ
参数量仅 act_dim 个参数额外一个线性头（hidden×act_dim + act_dim）
探索调节全局统一，一处变化影响所有状态逐状态自适应：困难状态保持探索、熟悉状态收紧
梯度来源所有样本共同决定，更新慢而稳各状态样本分别驱动，更新快但波动大
数值风险低高：个别状态的 log σ 可能冲出边界，需要 clamp 保护
典型表现稳，收敛稍慢前期下降更快，最终回报高 20～60 分，KL 略高

失效边界：σ 塌缩与梯度爆炸互为因果。σ 的下界由 log σ 的 clamp 决定：−5 对应 σ≈0.0067，此时 1/σ2≈2.2×104，均值方向的梯度被放大约两万倍，一点优势噪声就能变成巨大更新。典型症状是损失尖峰、KL 瞬间冲高、随后 σ 贴死下界，策略退化为确定输出后回报不再上升。判别信号就是"σ 轨迹贴住 clamp 下界且回报停滞"。修复按优先级排列：把 log σ 下界放宽到 −2（σ≈0.135）、保留一个很小的熵正则（如 1e-3）防止熵无界下降、或在优势标准化之后再计算更新。反向失效同样存在：σ 贴上界（log σ=2，σ≈7.4）且长期不降，说明优势信号弱到推不动探索收缩，先检查奖励尺度与优势标准化，调 σ 边界属于后续步骤。

3. 动作边界：clamp 与 tanh

设动作上限 L（Pendulum 的 L=2）。两种做法：

clamp：a = clip(u, −L, L)，　log π(a) = log N(u)
tanh ：a = L·tanh(u)，　log π(a) = log N(u) − log( L·(1 − tanh²u) + ε )

为什么 tanh 要加最后一项：换元公式 a = g(u) 时，概率密度要乘 |dg/du|−1，取对数就是减去 log|g′(u)|。g′(u) = L(1−tanh²u)，当 u 靠近两端时它趋近 0、log 项趋向 +∞，正好抵消高斯在远端的低密度。不加这项就等于用错的概率训练策略梯度，实践中表现为"接近边界时更新方向抖动"。

clamp 的代价则是概率折叠：u 落在区间外的样本全被压到边界，密度在端点堆成尖峰，比率 rt 的估计有偏。Pendulum 的力矩通常用不满 ±2，所以 clamp 也能工作；对"必须打满边界"的任务，tanh 更稳。两种处理的对比可以归纳成表：

维度clamptanh
动作映射a = clip(u, −L, L)，区间外全部落边界a = L·tanh(u)，区间内平滑压缩，永不越界
logp 计算直接用 log N(u)，无需修正log N(u) − log|g′(u)|，必须成对修改
边界处密度多个 u 折叠到同一 a，密度口径不一致换元严格成立，密度在动作空间连续
实现风险低，代码简单中：修正符号、1e-6 稳定项、logp 与动作配对都要正确
适用场景极少打满边界的任务需要精确贴边（打满力矩、推满推力）的任务

无论选哪种边界处理，实验时都要固定同一组种子与预算，动笔比较前先确认 act() 与 log_prob_from_u() 的 squash 分支一致，这是最容易出现静默错误的接口对。

σ 轨迹的读法可以提前约定好判据：健康曲线是"前段快降、后段走平"，共享版通常在 2～4 万步内从 1.0 降到 0.4 附近，随后在 0.3～0.6 之间缓慢移动；状态相关版的均值更低、分布更宽（不同状态分化）。两类异常都有明确信号：两万步内跌破 0.2 并继续下探，说明优势噪声大或熵项为零，策略提前变确定；十步更新内跳到 2 以上并稳在高位，说明优势尺度太小或奖励未缩放，探索失控在加剧。把这条判据写进日志检查清单，比事后翻曲线高效得多。

4. 多维动作的扩展

Pendulum 只有一维动作，很多写法里"逐维独立"与"整体"看不出差别，换成推杆、机械臂就会暴露。若各维独立，联合对数概率是求和：log π(a|s) = Σd log N(ad; μd, σd2)，微分熵等于各维熵之和，σ 向量的形状与动作维数一致。tanh 变换逐维独立时，雅可比修正也逐维相加：Σd log|g′(ud)|；漏掉任何一维，整个批量样本的 logp 都会带固定偏差，比率随之整体偏移。实现上这提醒两件事：log_std 与 act_limit 要按维维护（标量广播在对称环境中能用，换环境就错），以及熵统计要除以动作维数再做跨任务比较，否则动作越多的任务熵读数越大。

5. 评估用均值

连续控制的确定性评估取 a = clip(μ(s), ±L)，不再采样。用采样动作评估会把 σ 的噪声算进成绩，让不同参数化的对比失真。用数字感受噪声的量级：训练中期 σ 通常在 0.5 附近，一次 200 步的评估回合里，每步动作都在均值附近抖动；与取均值的评估相比，采样评估的回报波动可达几十点量级，而本章关心的 arm 间差异往往只有 20～60 分，信噪比不足时结论会被来回翻转。评估口径必须固定为确定性版本，这一点与离散任务中的贪婪评估完全对应。

数据流

每个 arm 一条完整训练：重设种子 → 采样 2048 步（存储预变换样本 u 与对应 logp，环境只收到变换后的动作）→ GAE → 10 epochs 更新（用存储的 u 重算 logp 得到比率，统计 σ 均值）→ 记录 σ 前 5 轮/后 5 轮 → 跑满 15 万步 → 用分布均值做贪婪评估 → 汇总回报、σ 轨迹与 KL。

连续 PPO 的结构核心：存 u 不存 a

比率的分母是采样时刻的 log π。对连续动作，log π 必须在预变换样本 u 上计算（clamp 前、tanh 前的原始高斯样本）。如果 rollout 里存的是变换后的动作 a，更新时就再也拿不回 u：clamp 会把多个 u 映射到同一个 a，tanh 非单射，两者都让"重建 log π"变成不可能。所以 act() 返回四元组、buffer 存 u，这是本章最重要的实现约束。排查这类错误时有一个快速信号：若更新日志里的比率长期精确等于 1，或者裁剪比例恒为 0，往往说明 logp 用了错误的变量计算，优先检查 buffer 里存的是 u 还是 a。

关键代码与解读

片段 1：策略头与分布构造

    def __init__(self, obs_dim, act_dim, act_limit, state_std, hidden=64, squash="clamp"):
        super().__init__()
        self.act_limit = act_limit      # 动作边界 L（Pendulum 为 2）
        self.state_std = state_std      # True：log σ 由状态决定；False：共享参数
        self.squash = squash            # "clamp" 或 "tanh"
        self.body = nn.Sequential(
            nn.Linear(obs_dim, hidden), nn.Tanh(),
            nn.Linear(hidden, hidden), nn.Tanh(),
        )
        self.actor_mean = nn.Linear(hidden, act_dim)     # 均值头
        if state_std:
            self.actor_log_std = nn.Linear(hidden, act_dim)
            nn.init.orthogonal_(self.actor_log_std.weight, gain=0.01)  # 初始 σ≈1
            nn.init.zeros_(self.actor_log_std.bias)
        else:
            self.log_std = nn.Parameter(torch.zeros(act_dim))  # 一组共享参数
        self.critic = nn.Linear(hidden, 1)

    def distribution(self, obs):
        h = self.body(obs)
        mean = self.actor_mean(h)
        if self.state_std:
            log_std = self.actor_log_std(h)
        else:
            log_std = self.log_std.expand_as(mean)   # 广播到批量形状
        log_std = torch.clamp(log_std, -5.0, 2.0)    # σ 的硬边界
        return Normal(mean, log_std.exp())

解读：（1）共享版的 log_std 是 nn.Parameter：它和网络权重一起被优化，但形状固定为 (act_dim,)，expand_as 只是广播到批量形状，不是复制参数，所以整个任务只有这一组 σ。（2）状态相关版用一个小增益（0.01）的线性头输出 log σ：初始权重小时输出接近 0，即 σ≈1，与共享版初值一致，保证两种参数化"从同一起点出发"的对比公平性。（3）clamp(log_std, −5, 2) 是硬边界：上限 2 对应 σ≈7.4 挡住爆炸，下限 −5 对应 σ≈0.007 防止进入数值死区（太小的 σ 会让 log π 出现 −inf 级数值）。（4）注意 Normal(mean, std) 的第二个参数是标准差，不是方差，这里 log_std.exp() 完成还原，是连续控制最常见的形状/语义错误点之一。

片段 2：tanh 雅可比修正与变换

    def log_prob_from_u(self, u: torch.Tensor, dist: Normal) -> torch.Tensor:
        """由预变换样本 u 计算（可能带 tanh 修正的）对数概率。"""
        logp = dist.log_prob(u)
        if self.squash == "tanh":
            # 雅可比修正：log π(a) = log N(u) − log|dg/du|，g(u)=L·tanh(u)
            corr = torch.log(self.act_limit * (1.0 - torch.tanh(u) ** 2) + 1e-6)
            logp = logp - corr
        return logp

    def transform(self, u: torch.Tensor) -> torch.Tensor:
        if self.squash == "tanh":
            return self.act_limit * torch.tanh(u)      # 无界高斯 → 有界动作
        return torch.clamp(u, -self.act_limit, self.act_limit)

解读：（1）接口约定是"永远先算 dist.log_prob(u)"：无论哪种边界处理，基座都是 u 上的高斯密度；tanh 只追加修正项。（2）+ 1e-6 防止在 tanh(u) → ±1（u 远离 0，比如 |u|>6）时 log(0) = −inf：这是数值保险，量级上可忽略。（3）修正项的符号是减：密度换元要乘 |dg/du|−1，取对数变成"减去 log|g′|"。写成加号是本段最经典的错误，后果是概率密度在边界处被低估、比率系统性偏移。（4）transform 与 log_prob_from_u 是配对的：一个负责产生环境动作、一个负责产生用于比率的 logp；两者的 squash 分支必须同时改，只改一处会出现"动作被 tanh、logp 却按 clamp 记录"的静默错误。

片段 3：采样返回四元组，把 u 带回来

    @torch.no_grad()
    def act(self, obs: torch.Tensor):
        """返回 (环境动作, 对 logp, 价值, 预变换样本 u)。"""
        dist, value = self.forward(obs)
        u = dist.sample()                       # 先采样“原始”样本 u
        logp = self.log_prob_from_u(u, dist)    # logp 对应 u 的密度（含修正）
        action = self.transform(u)              # 再变换成环境动作
        return (action.squeeze(0).cpu().numpy().astype(np.float32),
                float(logp.item()), float(value.item()),
                u.squeeze(0).cpu().numpy().astype(np.float32))

解读：（1）顺序固定：先采样 u → 算 logp → 再变换出动作。若反过来先变换、再对动作求 log 概率，得到的既不是"u 的密度"也不是"a 的密度"，训练从一开始就错。（2）u 用 numpy 返回（astype(np.float32)）：它要存进 rollout buffer，保持与其它字段一致的格式；squeeze(0) 去掉单环境批维度。（3）环境只收到 action，永远不会看到 u，u 纯粹是策略内部坐标系，被存下来只为了更新时重算比率。（4）这是与离散策略最直观的差别：离散版 act() 返回三元组（动作编号、logp、价值），连续版必须多带回 u，采样管线里 act_u_buf.append(u) 替换了原来的 act_buf.append(a)。

片段 4：更新时用 u 重算 logp

            dist, value = net.forward(obs[mb])
            logp = net.log_prob_from_u(u[mb], dist)      # 用存储的 u 重算（不用动作）

            ratio = torch.exp(logp - logp_old[mb])
            surr1 = ratio * adv[mb]
            surr2 = torch.clamp(ratio, 1.0 - args.clip, 1.0 + args.clip) * adv[mb]
            policy_loss = -torch.min(surr1, surr2).mean()
            value_loss = F.mse_loss(value, ret[mb])
            entropy = dist.entropy().mean()      # 高斯微分熵（nats 量纲）
            loss = policy_loss + args.vf_coef * value_loss - args.ent_coef * entropy

解读：（1）更新循环与离散版的唯一结构差别就在第二行：log_prob_from_u(u[mb], dist) 替代了 dist.log_prob(act[mb])，新策略分布刚刚重新构造，用同一批 u 重算密度，比率才有意义。（2）其余部分（clip、min、价值损失、熵）与离散版逐字相同：说明"策略分布换高斯"这件事被封装在了网络接口里，训练目标本身不变。（3）dist.entropy() 是高斯微分熵 ½log(2πeσ²) 的逐样本值，mean() 后进入统计；本章 ent_coef=0.0 所以它只作诊断，不改变损失。（4）注意 dist.stddev.mean() 的统计进 std_mean：这是 σ 轨迹的来源，用逐 minibatch 的 σ 均值拼出整场训练的探索曲线。

python code/ch011.py --quick            # 两个 arm 各 1.2 万步，约 30–60 秒
python code/ch011.py --squash tanh      # 比较 tanh 变换 + 雅可比修正

预期结论（以实跑为准）：两个 arm 都会把 σ 从 1.0 压向 0.3～0.6，说明回报梯度在主动收缩探索；state 版前期下降更快、最终回报通常高 20～60 分（困难状态保持探索、熟悉状态收紧），代价是 KL 与裁剪比例略高、曲线更抖；tanh 变体与 clamp 在前 10 万步差别不大，当策略学会"打满力矩"后 tanh 的更新更平滑，回报上常见 10～30 分优势。若 15 万步没到 −250 属正常范围，Pendulum 的 PPO 常需要 20 万步以上，本实验以相对比较为准。

常见坑

  • tanh 变换忘记雅可比修正：log π(a) 直接用 Normal.log_prob(tanh后的动作) 是双重错误（既丢了修正，又用了错的变量）。正确做法是永远对预变换样本 u 求 log 概率，再按需要修正。
  • 不限制 log σ 的范围：σ 在梯度驱动下可能指数级增长或塌缩到浮点下溢；[−5, 2] 这类硬边界是必要的，配合 +1e-6 的稳定项。
  • 评估时还按分布采样：σ 大的策略会被评估噪声惩罚，导致"训练回报高、评估回报低"的错觉。连续控制评估取均值。
  • 把熵系数从离散任务照搬到连续任务：高斯熵是无界的，ent_coef=0.01 在连续控制里可能大到主导损失。先设 0，需要时从 1e-4 量级试起。
  • Normal 的第二个参数写成方差：Normal(mean, log_std.exp()) 才是标准差；Normal(mean, log_std.exp()**2) 会让探索幅度差出一个量级，训练曲线会明显异常。

练习与思考

  1. 把共享 σ 的初值改为 log_std = -2（σ=0.14），观察前 2 万步的学习速度与 σ 轨迹。★
    提示
    在 GaussianActorCritic.__init__ 里把 torch.zeros(act_dim) 改成 torch.full((act_dim,), -2.0)。初始探索太小，前期回报会明显更差，且可能被局部最优困住。
  2. 故意去掉 tanh 变体的雅可比修正（把 logp = logp - corr 改成直接返回 logp），跑 5 万步观察训练是否退化，并解释原因。★★
    提示
    这是经典的"错误点虽小、后果不小"实验：概率密度在边界处被低估，比率系统性偏离 1，KL 曲线会出现异常。跑完记得改回来。
  3. 记录"σ 与状态的关系"：固定 32 个 Pendulum 状态（覆盖不同角度与角速度），在训练中每 10 次更新打印 state 版在这些状态上的 σ，观察 σ(s) 如何分化。★★
    提示
    预先用 np.linspace 构造状态矩阵，net.distribution(torch.tensor(...)).stddev 一次拿到全部；对比不同角速度区间上的 σ 均值。
  4. 实现"逐维独立界限"的 tanh：把标量 act_limit 换成向量，对每维分别变换与修正，然后用 MountainCarContinuous-v0（力范围 ±1）跑一次对比。★★★
    提示
    Pendulum 是一维动作，看不出差别；换环境时读取 action_space.high/low 组成向量。MountainCarContinuous 的奖励结构与 Pendulum 完全不同，注意 γ 和步数预算要一起调整。
  5. 写一个数值自检：构造 μ=0.5、σ=1、u=0.5 与 u=2.0 两组输入，分别调用 log_prob_from_u 与手算结果（−1.372 与 −0.087）对照，误差应在 1e-4 量级。★
    提示
    手算要点：基准项 −(u−μ)2/2 − log σ − 0.5·log(2π)，再减 log(2(1−tanh2u))。若对不上，先检查实现里是否误用了变换后的动作 a；这里应当用 u。

小结

  • 连续策略用高斯：μ(s) 承担"意图"、σ 承担探索；PPO 用得分函数估计梯度，因此必须保存采样时的对数概率（以及预变换样本 u）。
  • 共享 σ 更稳、状态相关 σ 表达力更强：核心实验里 state 版收敛更快、最终回报略高，但 KL 与波动也更大。
  • 有界动作有两种处理：clamp 简单但概率折叠；tanh 变换需要雅可比修正 −log|g′(u)|，在打满边界的任务上更健康。
  • σ 轨迹是连续 PPO 最重要的探索诊断：突然塌缩或长期高企都意味着学习信号出了问题。
  • 下一章回到离散动作，但换一个更硬的问题：动作掩码（invalid action masking），当某些动作在特定状态下非法时，分类策略怎么正确屏蔽它们。
