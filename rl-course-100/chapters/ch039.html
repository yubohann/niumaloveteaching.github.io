第二篇 · 离策略方法与 SAC

第 039 章：SAC的观测归一化

Pendulum 的角速度跨度是 ±8，角度却在 ±1，同一个网络第一层要同时吃下两种量纲。用 Welford 在线统计把观测逐维标准化，看看早期学习能快多少。

  • 主题：输入预处理 / 在线统计
  • 关键公式：zi = clip( (xi − μi) / σi, −c, c )；Welford：μ ← μ + δ/n，M₂ ← M₂ + δ(x−μ)
  • 预计学时：50 分钟
  • 前置章节：第 038 章

学习目标

  • 理解输入特征尺度不一致为什么拖慢神经网络训练：第一层权重的梯度尺度与输入量级成正比。
  • 实现基于 Welford 递推的在线均值/方差统计，把观测逐维标准化并裁剪。
  • 掌握"回放池存原始观测、采样时用当前统计量归一化"的干净数据流，避免旧数据的尺度污染。
  • 在 Pendulum-v1 上对比原始观测与归一化观测的评估回报、|Q| 与 theta_dot 维度估计标准差。

背景与动机

神经网络的输入尺度会直接影响训练动力学。考虑第一层 h = Wx + b：如果某个输入维度 |x| 常常在 8 左右，而另一个在 1 左右，那么 W 对应大尺度的那部分列梯度天然大 8 倍，同一个学习率下，大尺度维度先学、小尺度维度迟迟学不动。Pendulum 的 [cosθ, sinθ, θ̇] 正好落在 [−1,1]、[−1,1]、[−8,8]。

理论上的解法很朴素：让每一维减均值、除标准差，把分布压到均值为 0、方差为 1。但强化学习里统计量不能提前算，你没有一批预先给定的数据，状态的分布还会随着策略改变。于是做法变成"边训练边统计"：用一条条观测在线更新均值与方差（Welford 递推），再用最新统计量归一化。

第 038 章改策略结构对付信息缺失；本章回到全观测 Pendulum，动的是数据进入网络之前的尺度，喂给网络的数值应该长什么样。

核心原理

1. 标准化公式与裁剪

对第 i 维观测 xi，用当前运行统计量 μi、σi 做标准化：

ẑi = (xi − μi) / σi，  zi = clip(ẑi, −c, c) c 取 10：标准化后超过 10 倍标准差的值属于分布尾部，裁剪防止单点异常值冲击网络

μ 与 σ 由训练中见到的所有观测递推估计，因此它们反映的是"策略当前访问到的状态分布"。这也是一个提醒：归一化的统计量带着策略的偏置，早期访问得少的状态，估计自然粗糙。裁剪系数 c 取 10 是一个宽松阈值：标准化后的真实数据几乎都落在 ±5 以内，c=10 只拦截真正的异常值，同时又比"不裁剪"多一层保护。

2. Welford 递推：为什么不用"累加再除"

直接维护 Σx 与 Σx² 再算方差，在长训练里会遇到灾难性抵消（大数相减）。Welford 递推逐条更新，数值稳定且只需均值/方差两个数组：

n ← n + 1
δ = x − μ
μ ← μ + δ / n
M₂ ← M₂ + δ·(x − μ)   （σ² = M₂ / n）

实现里把 var 存成"平方和 M₂"，读取时再除 n，这样每条观测只做几次向量运算，开销可以忽略。初始 n 取一个很小的常数（1e-4），避免第一步除以 0。

数值例子：手推三步 Welford

取一维序列 x = [0.4, 0.6, 0.8]，从 μ=0、M₂=0、n=0 起步：

第 1 条：n=1，δ=0.4，μ=0+0.4/1=0.4，M₂=0+0.4×(0.4−0.4)=0。此时 σ=0，实现里的 1e-8 兜底项在此刻起作用。

第 2 条：n=2，δ=0.6−0.4=0.2，μ=0.4+0.2/2=0.5，M₂=0+0.2×(0.6−0.5)=0.02，σ²=0.01，σ=0.1。

第 3 条：n=3，δ=0.8−0.5=0.3，μ=0.5+0.3/3=0.6，M₂=0.02+0.3×(0.8−0.6)=0.08，σ²=0.08/3≈0.0267，σ≈0.163。

核对：三条数据的均值确实为 0.6，总体标准差 (0.04+0+0.04)/3 开根号 ≈ 0.163，递推结果与"整批计算"完全一致。解读：每一步的计算量与一条观测成正比，不需要保存历史数据，这是在线统计能在几十万步训练里使用的根本原因。实际代码把 M₂ 初始化为 1、n 初始化为 1e-4，让最早期的 σ 落在 1 附近，起"保守估计"的作用，后续数据会迅速覆盖它。

数值例子：梯度尺度失衡有多大

第一层对权重 Wij 的梯度是 ∂L/∂Wij = δj·xi，与输入值成正比。Pendulum 的观测里：cosθ、sinθ 取值在 [−1, 1]，典型绝对值约 0.7；θ̇ 取值在 [−8, 8]，训练中期典型绝对值为 3～4。两类的梯度尺度比约为 4 : 0.7 ≈ 5.7 倍，极端时刻可以到 8 : 0.1 的量级。

标准化后，cosθ、sinθ 分布本就在 ±1 附近（μ≈0、σ≈0.7，标准化后典型值约 1），θ̇ 的估计标准差从 1 收敛到 2～3，标准化后同样落在约 ±1。解读：所有输入维度的典型尺度被拉平到同一量级，同一个学习率对每一维都"够用但不过猛"。这也解释了收益为什么集中在训练早期：后期网络能从数据里把尺度差异吸收进权重，归一化的相对优势随之缩小。

3. 归一化放在数据流的哪个位置

两种常见方案：(a) 入池前归一化，存进回放池的就是已标准化的观测，但池里混着不同时期统计量处理过的数据，口径不一致；(b) 采样后归一化（本章采用），池里始终是原始观测，训练时用"最新统计量"统一处理整批数据，口径一致。方案 (b) 的另一个好处是评估时可以复用同一份统计量，训练与评估的输入分布严格一致。

两种方案的取舍可以列成表：

维度(a) 入池前归一化(b) 采样后归一化（本章）
池内数据的口径不同时期统计量混合，含义不一致始终为原始值，含义唯一
统计量更新时的语义旧数据无法用新统计量重新解释旧数据按当前统计量重新解释
评估复用需要额外保存"入池时"的统计量直接复用训练统计量，口径天然一致
实现成本低，但口径问题隐蔽略高，职责边界清晰

4. 预期收益的边界

归一化优化的是优化景观的条件数，不是信息量。它让早期梯度不再被大尺度维度垄断，所以学习曲线前半段明显变陡；后期网络能把尺度自己学进权重，两种设置最终水平靠近。它是"加速器"，最终上限仍由算法本身决定。

5. 条件数视角：归一化把优化椭圆的轴比压回 1

把第一层看成一个线性回归问题，梯度下降的收敛速度由输入协方差矩阵的特征值分布决定：最大特征值限制可用学习率的上界，最陡方向与最平方向的收敛步数之比约等于特征值之比。Pendulum 的三个观测维度里，cosθ 与 sinθ 的方差都在 0.5 上下，θ̇ 的标准差训练中期约 3～4，对应方差 9～16；协方差矩阵的条件数因此约为 18～32，等高线椭圆的长短轴之比约 4.2～5.7。学习率被大尺度方向卡住上限时，最平方向每步的收敛因子明显更慢，需要十几到数十倍的步数才能达到同等精度，这就是"小尺度维度学不动"的几何解释。逐维标准化把各方差都归到 1 附近，条件数降向 1，椭圆接近圆形，同一个学习率对每个方向都合适。这条推理也预告了收益的时间分布：早期条件数差异最突出，所以曲线前半段受益最明显。

6. 数值边界：裁剪阈值与朴素算法的对照

裁剪阈值 c=10 的宽松程度可以直接算：标准化后的数据近似服从标准正态，|z|>1 的概率约 31.7%，也就是说 c=1 会截掉三成以上的数据，输入被大面积压扁；c=3 截掉约 0.27%；c=5 约 5.7×10−7；c=10 的截断概率约 1.5×10−23，工程上等于不截断，只拦真正的异常值。练习第 1 题里 clip=1 造成的明显劣化，就来自那三成数据的失真，而 clip=100 与 c=10 的实际表现基本相同。

Welford 的必要性也能用一组极端数字演示：取 x=[1000000.1, 1000000.2, 1000000.3]，真实方差约 0.00667。用 float32 按"平方的均值减均值的平方"计算，两个 1012 量级的数相减，结果得到 65536，是真实值的近一千万倍；换 float64 朴素算法，误差缩到约 2.5%；而用 float64 保存 μ 与 M₂ 的 Welford 递推，得到 0.0066667，与真值逐位一致。实现里把统计量容器定为 float64，正是为了守住这条数值底线。

与前一章的差异点

  • 第 038 章动策略结构（MLP → GRU）；本章策略结构不变，只改观测进入网络前的数值处理。
  • 新增 RunningObsNormalizer 类与"原始入池、采样归一化"的数据流。
  • 回放池接口从 sample() 改为 sample_raw()，强调职责边界。
  • 评估函数新增归一化参数；模型保存时连统计量一起存，否则加载模型后无法复现输入口径。

与批归一化（第 047 章）的分工

本章处理的是网络输入层之前的尺度，统计量来自环境观测的运行均值与方差；第 047 章的批归一化处理的是网络内部激活的尺度，统计量来自每个批次内的样本。共同点是让数据尺度更整齐，差别在统计口径与作用位置：观测归一化跨时间累计、口径稳定，适合消除"不同维度量纲差"；批归一化按批统计、随训练波动，适合稳定深层网络的激活分布。两者可以叠加使用，但在本课程这种小网络上叠加收益有限，因为输入已经整齐，隐藏层激活的漂移本来就小。还有一处实践差别：观测归一化的统计量必须随模型一起保存，批归一化的统计由每批数据现算、不携带跨会话状态。

统计量的"所有权"要唯一

训练循环里的那一份 normalizer 是所有消费方的唯一真相：决策、训练、评估都从它读。评估函数只读不写（不调用 observe），防止评估回合的观测污染统计量；enabled=False 时所有入口原样透传，于是 none 组根本不需要第二套代码路径。

关键代码与解读

片段 1：Welford 归一化器，整个实验的心脏

class RunningObsNormalizer:
    """在线统计观测的均值与方差，逐维标准化后裁剪。"""

    def __init__(self, dim, clip=10.0, enabled=True):
        self.clip = clip
        self.enabled = enabled
        self.mean = np.zeros(dim, dtype=np.float64)
        self.var = np.ones(dim, dtype=np.float64)   # 存的是 M2（平方和）
        self.count = 1e-4          # 从极小值起步：防止第一步除以 0

    def observe(self, obs):
        """用一条新观测更新统计量（Welford 递推，数值稳定）。"""
        if not self.enabled:
            return
        x = np.asarray(obs, dtype=np.float64)
        self.count += 1.0
        delta = x - self.mean
        self.mean += delta / self.count             # 均值增量更新
        self.var += delta * (x - self.mean)         # M2 增量更新（注意用的是新均值）

    def std(self):
        return np.sqrt(self.var / self.count + 1e-8)   # 1e-8 兜底：方差为 0 时不炸

    def normalize(self, obs):
        """标准化并裁剪；enabled=False 时原样返回。"""
        if not self.enabled:
            return np.asarray(obs, dtype=np.float32)
        z = (np.asarray(obs, dtype=np.float64) - self.mean) / self.std()
        return np.clip(z, -self.clip, self.clip).astype(np.float32)

    def normalize_tensor(self, obs):
        if not self.enabled:
            return obs
        mean = torch.as_tensor(self.mean, dtype=torch.float32)
        std = torch.as_tensor(self.std(), dtype=torch.float32)
        return torch.clamp((obs - mean) / std, -self.clip, self.clip)

解读：把三十行拆成四个关注点看。（1）observe 的 Welford 递推：delta 用的是更新前的均值算，var 的更新用的是更新后的均值，这个顺序是 Welford 公式的精确写法，写反了数值会漂。float64 累加也是刻意的：统计量要走几万步，精度值这点开销。（2）std() 每次现算：var/count + 1e-8 开根号，兜底项保证观测接近常数时不会除零。（3）两个归一化入口：normalize() 服务单条 numpy（决策与评估），normalize_tensor() 服务批次张量（训练），同一组 μ、σ，两种容器，为性能分工。（4）enabled 的透传：none 组整个类退化为"原样返回"，实验对比因此只差一个开关，两套代码分支被一并消掉。

片段 2：原始入池，回放池的职责边界

    def sample_raw(self, batch_size):
        """返回未经归一化的张量；归一化交给智能体按当前统计量处理。"""
        idx = np.random.randint(0, self.size, size=batch_size)
        return {
            "obs": torch.as_tensor(self.obs[idx]),          # 原始观测，不是标准化后的
            "act": torch.as_tensor(self.act[idx]),
            "rew": torch.as_tensor(self.rew[idx]),
            "next_obs": torch.as_tensor(self.next_obs[idx]),
            "done": torch.as_tensor(self.done[idx]),
        }

解读：十行代码里没有任何算法，但方法名本身就是设计文档。（1）为什么返回原始观测？如果入池前就归一化，10 万条容量里会同时存在"用 3000 步统计量处理过"和"用 15000 步统计量处理过"的数据，同一维在不同条目里含义不同，网络学到的输入分布自相矛盾。（2）方法名特意选择 sample_raw：任何后续读代码的人都会停下来问"谁负责归一化"，答案是调用方（agent 用当前统计量）。（3）归一化的唯一时机是"消费时刻"，于是同一批原始数据在不同训练阶段会被赋予与当时统计量匹配的标准化值，这正是在线归一化想要的语义。

片段 3：update 入口，obs 与 next_obs 必须同口径

    def update(self, batch, normalizer):
        # 用当前统计量归一化观测（回放池里的原始观测不受影响）
        obs = normalizer.normalize_tensor(batch["obs"])
        next_obs = normalizer.normalize_tensor(batch["next_obs"])
        act, rew, done = batch["act"], batch["rew"], batch["done"]

        with torch.no_grad():
            next_act, next_logp = self.policy.sample(next_obs)
            q_next = torch.min(self.q1_target(next_obs, next_act),
                               self.q2_target(next_obs, next_act))
            target = rew + self.gamma * (1.0 - done) * (
                q_next - self.current_alpha * next_logp)

解读：归一化在 batch 进入计算图之前一次性完成，两个细节决定正确性。（1）obs 与 next_obs 用同一个 normalizer 处理：TD 目标里 Q(s′)、策略在 s′ 上采样、Q(s,a) 回归必须处在同一坐标系；若 s′ 用旧统计量、s 用新统计量，等价于把两个不同尺度的状态混在一张 Bellman 方程里。（2）归一化放在 no_grad 之外、图的起点：它是纯前处理，不引入任何可学习参数。（3）临时变量命名刻意区分 obs（归一化）与 batch["obs"]（原始），回放池里的数据始终没被改动。（4）注意动作、奖励、done 不需要归一化：动作空间的尺度由 tanh/act_scale 管理，奖励尺度在第 035 章的框架里讨论过，本章只动观测。

片段 4：主循环，更新统计量先于入池

    for step in range(1, args.max_steps + 1):
        if step <= args.start_steps:
            action = env.action_space.sample()
        else:
            obs_norm = normalizer.normalize(obs)          # 决策用最新统计量
            action = agent.act(obs_norm, deterministic=False)

        next_obs, rew, terminated, truncated, _ = env.step(action)
        # 先更新统计量再存原始观测；采样时再按最新统计量归一化
        normalizer.observe(next_obs)
        buf.add(obs, action, rew, next_obs, float(terminated))
        obs = next_obs
        ep_ret += rew

        if buf.size >= args.batch_size:
            last_stats = agent.update(buf.sample_raw(args.batch_size), normalizer)

        if step % args.eval_every == 0 or step == args.max_steps:
            eval_ret = evaluate(eval_env, agent, args.eval_episodes, normalizer)
            history["eval_return"].append(eval_ret)
            history["std_tail"].append(float(normalizer.std()[-1]))   # theta_dot 的 σ 估计

解读：采样侧的三行顺序就是本章数据的"通关文牒"。（1）normalizer.observe(next_obs) 在 buf.add 之前：统计量先看到新数据，再存原始值。这个顺序对结果影响极小，但保证"任何时刻用到的统计量都包含最近观测"。（2）注意 observe 只统计训练环境的观测；评估函数里的归一化只读不写，评估是"观察者"，数据不回流入训练。（3）std_tail 记录 theta_dot 维度的估计标准差：它是 run 组独有的"体检指标"，从初值 1.0 上升到 2～3 之间并稳定，说明统计量在正常收敛；若长期停在 1.0，说明 observe 根本没执行。（4）none 组的 normalizer 处于 disabled 状态，上述所有调用都是透传，两组的控制变量保持唯一。

完整可运行脚本（附录）：code/ch039.py

python code/ch039.py           # none vs run：CPU 约 5–8 分钟
python code/ch039.py --quick   # 快速跑通：约 1 分钟
python code/ch039.py --obs-norms run --max-steps 30000   # 只跑归一化组

以实跑为准：run 组在 3000～6000 步的早期评估明显领先（差距常在 200～400 分）；15000 步后两组逐步靠近，最终差距缩小到几十以内。theta_dot 估计std 从 1.0 升到 2～3 并趋稳。归一化买的是早期速度，最终上限由算法本身决定。

常见坑

  • 训练归一化、评估不归一化（或反过来）：输入口径不一致，评估回报会突然崩掉。修复：把 normalizer 显式传入评估函数。
  • 用整批观测算统计量再归一化同一批：批统计引入批内相关性，正确做法是逐条递推（本章）。
  • 忘了保存统计量：重新加载模型推理时没有 μ/σ，输入尺度对不上，动作全错。修复：保存 state_dict 时一并存 obs_mean / obs_std。
  • 把归一化用在本来就有界的观测上并期待大收益：CartPole 这类小尺度环境收益有限，别把实验结论无脑外推。
  • Welford 的更新顺序写反：var 更新用的必须是更新后的均值；用旧均值会缓慢漂移，长训练里偏差累积。修复：对照递推公式逐行核对，并用小序列的解析结果做断言。

练习与思考

  1. 只跑 run，并试 --clip 1.0 与 --clip 100.0，观察裁剪范围对训练的影响。★
    提示
    clip=1 会把标准化后的观测大面积截断，等于往网络里灌失真信息；clip=100 等于不裁剪。对比 3000 步处的评估回报。
  2. 把归一化改成"入池前归一化"：在 buf.add 之前调用 normalizer.normalize，训练时不再处理。跑一次并解释为什么两种方案在训练早期表现不同。★★
    提示
    回放池容量 10 万条，早期统计量与后期差异大，池子里会混着两种口径。观察 |Q| 曲线是否更抖。
  3. 给归一化器加一个"冻结开关"：训练到 --max-steps 的一半时停止 observe（统计量固定）。评估回报会变好还是变差？★★
    提示
    后期状态分布变化不大时，冻结统计量往往没有明显损失；可以据此判断"统计量是否已经收敛"。
  4. 把归一化迁移到第 038 章的部分可观测环境：被遮挡维度恒为 0，归一化后是常数 (0−μ)/σ。做一个"只归一化前两维"的变体并与全维对比。★★★
    提示
    常数维度对 GRU 相当于无信息输入，但门控仍会给它分配权重；观察屏蔽维度归一化与否是否影响收敛速度。
  5. 把 Welford 的三步手推结果写成断言测试：构造 0.4/0.6/0.8 三条观测，断言 μ=0.6、σ≈0.163（容差 1e-6）。这个小测试能防止后续重构改坏递推顺序。★
    提示
    注意实现里的初始 M₂=1、n=1e-4 会轻微影响前几步结果，测试时可以先把初始值调成 0 与真实 n，或者把容差放宽到 1e-3 并在注释里说明原因。

小结

  • 输入维度尺度不一让第一层梯度尺度失衡，归一化把各维压到同量纲，改善优化条件数。
  • 在线统计用 Welford 递推：逐条更新、数值稳定、开销可忽略，三条观测的手算结果与整批公式完全一致。
  • 做法：原始观测入池、采样时用最新统计量归一化；训练与评估共用统计量并随模型保存。
  • Pendulum 上归一化主要买早期速度：前几千步评估回报常领先 200～400 分，最终差距缩小。
  • 统计量要到"消费时刻"才参与计算：原始观测入池、采样归一化，同一批数据在不同训练阶段被赋予与当时统计量匹配的解释。
  • 裁判归一化是否生效只需两个信号：theta_dot 维度的估计标准差从 1 升到 2～3；前 5000 步的评估回报明显高于对照组。
  • 下一章把同一套思路从观测搬到奖励：用回报运行统计标准化奖励，并与第 035 章的固定缩放做对照，说明两者的分工。
