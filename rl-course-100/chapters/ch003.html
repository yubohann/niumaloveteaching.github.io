第一篇 · 策略梯度与 PPO

第 003 章：PPO的裁剪目标与KL惩罚对比

把 PPO 的两种信任域实现，裁剪（clip）与自适应 KL 惩罚（kl），放进同一套训练框架，同种子、同预算各跑一遍，用样本效率、KL 波动和 β 漂移三条证据回答"到底该用哪个"。

  • 主题：信任域实现 / 目标函数对比
  • 关键公式：LCLIP = 𝔼[min(r·Â, clip(r,1−ε,1+ε)·Â)]；LKL = 𝔼[r·Â] − β·KL
  • 预计学时：55 分钟
  • 前置章节：第 002 章

学习目标

  • 理解裁剪目标与 KL 惩罚目标各自的数学形式，以及它们在"限制新旧策略距离"上的不同方式。
  • 实现原论文式的自适应 β 规则：KL 超过目标 1.5 倍则加倍，低于目标 1.5 分之一则减半。
  • 在同一训练框架下对两种模式做受控对比，记录样本效率、平均/最大 KL、熵与评估回报。
  • 观察 KL 模式中 β 的漂移轨迹，理解"自适应系数省心但难复现"这句话的具体含义。
  • 能根据任务特征做选择：何时用裁剪、何时用 KL 惩罚、何时两者叠加（第 010、026 章会继续这个主题）。

背景与动机

PPO 论文里其实给了两个版本的损失：一个是大家熟悉的裁剪目标，另一个是"策略梯度减去 KL 惩罚"，后者继承自 TRPO 的思想，把信任域写成罚项形式的软约束。工程实现里裁剪版本流行，原因是少一个自适应系数 β：KL 惩罚版本必须让 β 随训练动态调整，设小了约束不住策略、设大了学不动。

但"流行"不等于"永远更好"。裁剪只对"比率越界且方向正确"的样本掐梯度，是单侧、局部的约束；KL 惩罚则是把整批数据的新旧 KL 直接顶在损失里，约束更强但会持续挤压更新。本章不争论谁对，目标在于把两种目标放在同一份代码里，用同一随机种子和同样 12 万步预算跑给你看：刚度、KL 水平、β 的漂移、到达 475 所需的步数，各自长什么样。

核心原理

1. 裁剪目标：单侧、局部的硬约束

裁剪目标在第 001 章已经推导过，这里只强调它的"局部性"：

LCLIP = 𝔼t[ min( rt Ât, clip(rt, 1−ε, 1+ε) Ât ) ] rt = πθ(at|st) / πθ_old(at|st)；只有当 rt·Ât 还想继续变大时，梯度才被截断

注意一个容易被忽略的事实：裁剪并不直接控制 KL。它约束的是"每个样本带来多少收益改进"，KL 只是被间接压住。所以训练日志里 KL 偶尔跳到 0.03 以上是完全可能的，只要大多数样本没越界。判断裁剪是否起作用，要看 clip_frac（被裁剪样本比例）而不只是 KL。

2. KL 惩罚目标：持续的软约束

KL 版本去掉裁剪，在策略目标上直接加罚项：

LKL = 𝔼t[ rt Ât ] − β · KL(πθ_old ‖ πθ) β：自适应系数（罚的力度）；KL(πθ_old ‖ πθ)：旧策略到新策略的 KL 距离

在 θ = θ_old 处 KL 的值为零但曲率非零，所以它是"越走远、拉得越狠"的软墙：一开始几乎没有阻力，走远了惩罚线性增长。软墙的性质可以从梯度里直接看出来：单样本 KL 估计是 logpold − logp，对 θ 求导得 −∂logp/∂θ = πθ − 1a（softmax 对数概率的梯度等于"概率向量减 one-hot"）。对所有样本取期望，注意动作来自旧策略，得到

∇θ KL(πθ_old ‖ πθ) = πθ − πθ_old 偏差为零时拉力为零、曲率非零：这是"起点无阻力"的严格来源

这个恒等式的工程含义：KL 惩罚项提供的是一股"恢复力"，方向与新策略偏离旧策略的方向相反，大小正比于偏差；裁剪提供的则是离散门控，没有恢复力。两类失效模式由此分开：KL 模式被恢复力拴住，合格但更新慢、更依赖 β 的整定；裁剪模式放任未越界样本自由更新，平均漂移没有显式预算，KL 尖峰只能靠事后诊断发现。实践中用单样本估计：

KL̂ = (1/N) Σ [ log πθ_old(at|st) − log πθ(at|st) ] 无偏但方差大；本章用它是因为它可以和裁剪模式共用同一个诊断量

3. 自适应 β：把 KL 拉回目标附近

β 不能让用户手调，否则每换一个任务都要重新试。PPO 论文给出的规则是：每完成一轮更新，看当前 KL 相对于目标 KLtgt 的位置，

KL̂ > 1.5 · KLtgt ⟹ β ← 2β
KL̂ < KLtgt / 1.5 ⟹ β ← β / 2

这形成一个负反馈回路：更新太猛 → KL 偏高 → β 加倍 → 下一步被拉住；更新太怂 → KL 偏低 → β 减半 → 放开步子。代价是 β 会在训练中大幅漂移（常见跨两个数量级），于是"复现实验"必须连同 β 的轨迹一起记录，本章的对比表就包含 β 初值、终值与过程最大值。如果 β 长期顶在上限或下限，说明目标 KL 和任务根本不匹配。

回路的两个设计细节值得用数字体会。第一，"加倍/减半"是指数搜索：从偏大 100 倍回到目标附近，按每 epoch 减半需要约 7 个 epoch（27=128），对 10 epochs 一批的节奏来说速度刚好；换成线性调整（比如 β ← β − 0.1·KL），在 KL 尺度变化时要重新设计步长，这就是比值+倍率设计更通用的原因。第二，目标 KL 不能任意设小，因为估计量有噪声地板：单样本估计 KL̂ = (1/N)Σ(logpold − logp) 虽然在动作来自旧策略时对 KL(πold‖πθ) 无偏，但方差不为零，标准误差约为 std(logpold − logp)/√N。取每个样本对数差的标准差 0.1、批大小 2048，标准误差约 0.1/√2048 ≈ 0.0022。

拿它对照本章默认 --target-kl 0.01：0.01 是噪声的约 4.5 倍，反馈回路分辨得出真实偏差；若把目标设成 0.002，上下阈值 0.003 与 0.0013 都埋在噪声里，β 会被随机波动推着走，出现"β 每轮乱跳、KL 却不受控"的失效模式。经验判据：目标 KL 至少取估计标准误差的 3～5 倍；估算不出噪声水平时，先以 0.01 为起点上下试。补充一个估计量的性质：单样本估计对个别样本可以是负数（该动作概率被提高时 logpold−logp<0），这是无偏估计的正常现象；参考文献里常用的 k3 估计 ratio−1−log(ratio) 恒非负，ratio=1.2 时等于 0.0177、ratio=0.8 时等于 0.0231，代价是计算稍贵，练习 4 会做替换对比。

数值算例：β 在七个 epoch 里的完整轨迹

设 KLtgt=0.01，滞后带为 [0.01/1.5, 0.01×1.5] = [0.0067, 0.015]，β 初值 1.0。假设连续七轮的 epoch 平均 KL 依次是 0.042、0.040、0.038、0.020、0.011、0.008、0.005，按规则逐轮推演：

0.042 > 0.015 → β 加倍到 2；0.040 → 4；0.038 → 8；0.020 → 16；0.011 落在带内 → 保持 16；0.008 仍在带内 → 保持 16；0.005 < 0.0067 → 减半到 8。

解读：KL 偏高时 β 连续四轮翻倍，从 1 冲到 16，把"更新太猛"压回带内；进入滞后带后回路停止动作，这是"1.5 倍带"的设计目的，避免 β 每轮都抖动；最后 KL 掉到带下限之下，β 才回落到 8。整个过程 β 跨越 16 倍且没有人工干预。把它和"用最终 β=8 直接当手调初值"对比：初值 8 会让前期 KL 被过早压住、学习变慢，同一任务换一组超参数就推不出这份轨迹，这就是"复现要记录 β 曲线"的具体含义。

4. 两种约束的本质差别

把两式对照看：裁剪的作用点在样本级，谁越界谁没梯度，步长限制是离散的、不对称的；KL 惩罚的作用点在批次级，整批数据的平均距离都在损失里，步长限制是连续的、对称的。这带来两个可检验的推论：裁剪模式的 KL 波动上限更宽（尖峰可能漏过），KL 模式的 KL 均值更贴近目标但更容易被 β 的漂移主导。本章的 max_kl 指标就是为验证第一条设计的。

批次级平均还有一个容易忽略的盲区，用数字构造一例：假设一批数据里 5% 的样本对数差为 +0.5、5% 为 −0.5、其余 90% 只有 +0.001，则平均 KL̂ = 0.05×(−0.5) + 0.05×(+0.5) + 0.9×0.001 = 0.0009，看起来"健康得过分"；但 10% 的样本位移都超过了裁剪窗口 0.18/0.22，策略在两个方向上都发生了大位移。均值可以互相抵消，极值不会：这正是要同时记录 approx_kl（均值）与 max_kl（单次极值）的原因，只看均值会把这类"双向大位移"误判成稳定训练。裁剪模式同样有盲区，但方向相反：5% 的越界样本被掐掉梯度后，批均值可能很小，策略却在其余 95% 的样本上被连续推了很多轮。

维度裁剪（clip）KL 惩罚（kl）
约束粒度逐样本：越界样本失活批次级：平均距离进损失
步长限制形状离散、单侧（只掐改进方向）连续、对称（双向都在损失里）
需要手调的参数ε 一个，默认 0.2 通常够用目标 KL 与 β 初值，缺一不可
训练中的额外状态无β 随 epoch 更新，必须回传与记录
监控指标裁剪比例 + KL 均值/极值KL 均值 + β 轨迹
典型失效签名裁剪比例长期 > 30%、KL 尖峰β 贴上下限、KL 在带外漂移
适合场景通用默认；批量大、更新次数多需要显式控制平均位移；异步/分布式更新

读表的方法：先用裁剪跑通（它只有一个旋钮），当训练日志显示"KL 极值反复失控但裁剪比例不高"时，再考虑换成 KL 惩罚获得显式的均值控制；反过来，如果团队需要为异步更新设置严格的平均漂移预算，KL 惩罚的形式更直接。两种机制在第 010 章还会各自叠加早停，构成三层停止体系。

实现思路与设计

模块划分

组件职责与第 002 章的关系
ppo_update(mode, beta)按模式组合策略损失：clip 用 min/clamp；kl 用未裁剪比率加 β·KL核心改动：一个函数两条损失路径
β 自适应每个 epoch 末按 KL 与目标的比值加倍/减半新增：只在 kl 模式下生效
KL 诊断每个 minibatch 记录 approx_kl，并跟踪单次最大值 max_kl由 002 的平均 KL 扩展为均值 + 极值双指标
train_one(mode)封装一种模式的完整训练，记录 β 轨迹把 002 的 λ 轴换成"目标函数"轴
main依次训练两种模式，输出对比表和 β 漂移摘要对比表新增 β 列与最大 KL 列

关键超参数

参数默认值作用与取值理由
--modesclip kl两种模式各训练一次；也可只跑一种
--clip0.2仅 clip 模式使用，PPO 默认值
--target-kl0.01kl 模式的目标 KL。取偏小值让 β 的调整更活跃，便于观察反馈回路
--kl-init1.0β 初值。故意选得偏大：观察自适应回路如何把它压回去
--max-steps120000每种模式各自 12 万步；默认达标（475）即提前结束并记录步数
--epochs10与 001 一致；KL 模式中 β 每 epoch 调整一次

数据流

每个更新周期：采样 2048 步 → GAE 估计优势与回报（快照逻辑与 002 相同）→ 批内标准化优势 → 10 epochs × 32 个 minibatch：每个 minibatch 同时算 ratio 与 KL 估计，然后按 mode 分叉：clip 路径取 min/clamp，kl 路径用未裁剪比率加 beta * kl → 每个 epoch 结束时，kl 模式按反馈规则更新 β → 记录 approx_kl 与 max_kl → 达标则 break。

公平对比的两条纪律

1) 同一种子重设：train_one 开头调用 set_seed(args.seed)，两种模式的初始化与采样序列一致，差异只来自损失函数。

2) 达标即停的意义：--stop-at-solved 默认打开，把"首达 475 的回合数"当作样本效率的读数。想比较 KL 波动与最终稳定性时用 --no-early-stop 跑满预算，两种玩法各有用途，不要混用结论。

关键代码与解读

片段 1：一个更新函数，两条损失分支

    for _ in range(args.epochs):
        idx = torch.randperm(N, device=obs.device)
        for start in range(0, N, args.batch_size):
            mb = idx[start:start + args.batch_size]
            logits, value = net(obs[mb])
            dist = Categorical(logits=logits)
            logp = dist.log_prob(act[mb])
            ratio = torch.exp(logp - logp_old[mb])

            # KL 估计：KL̂ = E[logp_old − logp]，两种模式共用这个诊断量
            kl = (logp_old[mb] - logp).mean()

            if mode == "clip":
                # 裁剪目标：越界样本梯度归零，约束是单侧、局部的
                surr1 = ratio * adv[mb]
                surr2 = torch.clamp(ratio, 1.0 - args.clip, 1.0 + args.clip) * adv[mb]
                policy_loss = -torch.min(surr1, surr2).mean()
            else:
                # KL 惩罚目标：比率不裁剪，改由 β·KL 把整批更新拉住
                policy_loss = -(ratio * adv[mb]).mean() + beta * kl

            value_loss = F.mse_loss(value, ret[mb])
            entropy = dist.entropy().mean()
            loss = policy_loss + args.vf_coef * value_loss - args.ent_coef * entropy

解读：两条分支只差三行，但行为完全不同。（1）clip 分支里 min/clamp 让越界的样本梯度归零；kl 分支里比率永远不裁剪，如果把 clamp 也留在 kl 分支，就等于同时用了两种约束，对比就不纯净了。（2）kl 只从 logp 一侧反向传播：logp_old 是采样快照，当作常数；若误把两个 logp 都从当前网络重算，KL 恒为 0，惩罚项失效，这是本章最隐蔽的 bug。（3）kl 的符号约定是 logp_old − logp，即"新策略对已发生动作的平均对数概率下降量"；它近似 KL 且与裁剪模式共用，但注意它是无偏估计、方差大，不能当精确 KL 用。

片段 2：自适应 β 的负反馈回路

            epoch_kl += kl.item()
            epoch_cnt += 1

        # kl 模式：每个 epoch 结束后按 KL 反馈调整 β
        # 按 epoch 粒度调整；逐 minibatch 调整会让 β 高频震荡
        if mode == "kl":
            mean_epoch_kl = epoch_kl / max(epoch_cnt, 1)
            hi = args.target_kl * 1.5
            lo = args.target_kl / 1.5
            if mean_epoch_kl > hi:
                beta *= 2.0          # KL 超目标 1.5 倍：更新太猛，拉紧约束
            elif mean_epoch_kl < lo:
                beta /= 2.0          # KL 低于目标 1/1.5：步子太怂，放开一点
            beta = float(np.clip(beta, 1e-6, 1e6))   # 防数值爆炸的地板与天花板
            epoch_kl = 0.0           # 计数器清零，下一轮重新累计
            epoch_cnt = 0

解读：这就是 PPO 论文公式 (9) 的实现。（1）判断用的是 epoch 均值：minibatch 的 KL 噪声大，逐批调 β 会让系数抖动，KL 反而更不稳定（练习 2 会让你亲眼看到）。（2）加倍/减半是"指数搜索"：即使 β 偏了 100 倍，十几个 epoch 内也能拉回目标附近；这也是它比手调参数省心的原因。（3）np.clip 的上下限是保险丝，正常训练不会碰到；如果日志显示 β 贴着 1e6 或 1e-6 不动，说明 target_kl 与任务不适配。（4）换种写法，比如按 KL 的绝对差值线性调整 β，回路的收敛速度会依赖 KL 的尺度，换个环境就得重新设计，而"比值 + 倍率"是尺度无关的。

片段 3：达标即停与 β 轨迹记录

    beta = args.kl_init
    kls, betas = [], []
    solved_at = None
    while total_steps < args.max_steps:
        batch, ep_returns, obs_t = collect_rollout(
            env, net, args.steps_per_update, obs_t, device, args.gamma, args.lam)
        total_steps += args.steps_per_update
        all_returns.extend(ep_returns)

        stats, beta = ppo_update(net, optimizer, batch, args, mode, beta)
        kls.append(stats["approx_kl"])
        betas.append(beta)          # 记录 β 轨迹：复现实验必须能看到它

        if solved_at is None and len(all_returns) >= 100 and np.mean(all_returns[-100:]) >= args.target_reward:
            solved_at = len(all_returns)
        if solved_at is not None and args.stop_at_solved:
            break                    # 达标即停：首达回合数就是样本效率指标

解读：（1）beta 从 ppo_update 里返回后回传给下一轮，β 是随训练变化的"训练状态"，漏接这个返回值会让自适应静默失效（β 永远停在初值），这是把状态放在函数外的经典陷阱。（2）betas 列表与 kls 一起进入结果字典，最后打印"初值 → 终值、过程最大"三件套。没有这个轨迹，写论文或对比实验时无法解释"为什么这次结果和上次不同"。（3）早停只对达标触发：用首达回合数衡量样本效率，同时避免两种模式跑不同预算导致的 KL 统计不可比，不过想看最终稳定性时记得关掉它（--no-early-stop），否则达标模式的数据被截断，KL 统计会偏乐观。

典型日志：[clip] 步数 40960 | 回合 1100 | 近20均 431.7 | KL 0.0066 | 最大KL 0.0190 | 裁剪比例 0.079；[ kl] 步数 40960 | 回合 1180 | 近20均 372.5 | KL 0.0095 | 最大KL 0.0252 | β 2.0000。

跨模式比较诊断量时有两处口径差异要留意：clip 模式的 max_kl 来自全体样本（包括被裁的），它不因梯度被掐而不涨；但用均值比较时，越界样本的位移对拟合的贡献已经停止，读数会显得"更稳"。因此报告里不要把两种模式的 KL 直接排序、宣称谁更稳，先写清口径，再给各自的绝对水平。另一处细节是 KL 的批内平均方式：按 minibatch 先平均再汇总，与把全部样本拼起来一次平均，最后一批不满时两者不严格相等；本实现按 minibatch 计数平均（分母 stats["n_updates"]），对比表中的数字都遵循同一口径。

β 的终值单独看没有意义，要和 KL 水平连读：β 抬到 16 而 KL 停在 0.012，是回路正常工作的证据；β 同样在 16 但 KL 长期 0.05，说明约束失效，多半是目标 KL 设得过宽或学习率过大，反馈回路追不上参数步长。读 runs/ch003/ 下的结果文件时，把 β 初值、终值、最大值与平均 KL 当成一组四个数字一起看，才能判断这次训练是"回路在控"还是"回路在漂"。

预期结论（以实跑为准）：两种模式通常都能到达 475，但路径不同，clip 的 KL 稳定在 0.005～0.015、裁剪比例 5%～15%；kl 的 β 先被抬升、中段可能回落，终值常在 0.05～4 数量级。把 --target-kl 缩到 0.002 时 kl 模式明显变慢（首达 475 的回合数多 30%～100%）。更准确的结论是"裁剪几乎不用调参、KL 惩罚更依赖目标 KL 的设定"。

常见坑

  • KL 惩罚项里带上 logp_old 的梯度：logp_old 是采样快照，必须当常数。若误用当前网络重新算两遍 logp 再相减，KL 恒为 0，惩罚项失效。症状：kl 模式与无约束策略梯度没有区别、KL 上升无阻力。正确做法是只对 logp 的反向路径求导。
  • β 调整方向写反：KL 高于目标要增大 β（拉紧约束），低于目标才减半。方向反了会形成正反馈，几步之后 KL 飙到 0.1 以上、策略崩溃。症状：KL 单调上升、近 20 均断崖。
  • 用两种模式各自不同的种子做对比：本章在 train_one 内重设同一种子。换种子后排序可能变化，所以结论要基于多个种子；单次运行的排序不足以支撑结论。
  • 把裁剪模式的 clip_frac 当成 KL 的替代指标：裁剪比例低不代表 KL 小，它只说明"少数样本越界"；kl 模式下这个量没有控制作用，仅作观察。
  • 忘了回传 β 或搞错调整粒度：ppo_update 返回的新 β 必须赋回循环变量；粒度选 epoch，逐 minibatch 调整会让 β 高频震荡、KL 更不稳。

练习与思考

  1. 用 --target-kl 0.05 重跑 kl 模式，与默认 0.01 对比 β 轨迹与学习速度，解释目标 KL 变大后 β 的行为。★
    提示
    target 变大意味着"允许走得更远"，β 会因为反馈回路长期停在低位甚至不断减半；观察结果文件里的 beta_final 和日志中的 KL 水平。
  2. 把 β 的调整粒度改成"每个 minibatch 调一次"，运行后对比 β 曲线与 KL 的波动，说明粒度的影响。★
    提示
    把 epoch_kl 的统计改到 minibatch 循环内并在那里调整 β 即可。你会看到 β 高频抖动，KL 反而更不稳定。
  3. 在 clip 模式里加"KL 早停"：当某个 epoch 的平均 KL 超过 3 * target_kl 时跳过本批剩余的 epoch。对比开启前后 12 万步内的最大 KL 与近 100 均。★★
    提示
    在 epoch 循环里判断并 break。这相当于给硬约束加了一道安全阀，与第 010 章的早停主题相关。
  4. 实现 k3 形式的 KL 估计 kl = (ratio - 1 - log(ratio)).mean()，与当前的采样估计对比在同一批数据上的方差（多训练几个 epoch 看日志波动）。★★★
    提示
    k3 估计非负且方差更低。替换 kl 的计算行即可，注意它和 (logp_old - logp) 在数值上不等价，需要在日志里同时打印两者观察差异。比较时固定种子。

小结

  • 裁剪目标是单侧局部约束：只掐掉"还想继续变大"的越界样本，KL 只是被间接限制；KL 惩罚是软墙，用 β 把整批数据的新旧距离顶在损失里。
  • 自适应 β 规则（KL > 1.5·目标则加倍，< 目标/1.5 则减半）让 KL 模式几乎不用手调 β，代价是 β 随训练漂移两个数量级，复现时要记录轨迹。
  • 受控实验显示：两者在 CartPole 上都能达标；裁剪默认参数直接可用，KL 模式对 target_kl 明显更敏感。
  • 推荐实践：从裁剪开始，需要更细的步长控制、或想做分布式/异步更新（第 024、025 章）时再考虑 KL 惩罚。
