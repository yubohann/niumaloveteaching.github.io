第一篇 · 策略梯度与 PPO

第 012 章：PPO的离散动作空间的分类策略

在带障碍的 6×6 迷宫里对比"普通分类策略"与"无效动作掩码"：非法动作的 logits 被压到 −1e8，采样与更新都只在合法动作上做概率，一个在游戏 AI 与 LLM 对齐里天天用到的技巧。

  • 主题：离散策略 / 无效动作掩码
  • 关键公式：log π(a|s) = za − logsumexp(z)；z̃a = za − (1−Ma)·C
  • 预计学时：55 分钟
  • 前置章节：第 011 章

学习目标

  • 理解离散分类策略的完整实现要点：logits、softmax、log_prob、熵的数值稳定写法。
  • 掌握无效动作掩码（invalid action masking）：在 logits 层屏蔽非法动作，并保持采样/更新两处分布一致。
  • 实现一个带障碍与非法动作的自定义网格环境，量化"无效动作率"这一诊断指标。
  • 对照 nomask 与 mask 两组的成功率、样本效率与熵，说明掩码为什么提高学习效率。
  • 记住掩码的三个一致性要求：采样、更新重算、评估（贪婪）都必须使用同一掩码。

背景与动机

离散动作策略的标准写法（Categorical(logits=...)）里，每个动作永远都有非零概率，但在真实任务中，有些动作在特定状态是非法的：棋盘上不能走到被占的格、卡牌游戏里不能在费用不足时出牌、LLM 解码时不能生成越界的 token。普通策略把非法动作也放进采样分布，于是探索的一部分预算被浪费在"撞墙"上，甚至在高维动作空间里永远学不会规避。

动作掩码是工业界的标准解法：在 logits 上把非法位置压成 −1e8，softmax 之后这些动作概率为 0。它不改变策略的表示能力（合法动作内部仍然完整学习），只删掉不可能的分支。本章用带障碍的迷宫把这个收益做成可量化的对比：mask 版的无效动作率恒为 0，nomask 版要靠负奖励辛苦地学"别撞墙"。理解并写对掩码，是离散策略从玩具走向产品的分水岭。

核心原理

1. 分类策略的数值稳定写法

动作概率来自 softmax，实际实现用 Categorical(logits=...) 内部做 log-softmax，避免先指数后除法造成的溢出：

π(a|s) = exp(za) / Σa′ exp(za′)　，　log π(a|s) = za − logsumexp(z)

熵 H = −Σ π log π 也在分布上直接计算。注意：永远直接用 logits，不要手算 probs，后者会在 logits 幅度稍大时出现 0/0 或 log(0)。

logsumexp 的写法本身值得一推：logsumexp(z) = m + log Σa exp(za − m)，其中 m = maxa za。把最大项移到指数 0，指数函数不再溢出；掩码把非法 logits 压到 −1e8 之后，这个公式自动只在合法动作上求和，其余项 exp(−1e8 − m) 直接下溢为 0。下溢阈值可以算出来：float32 的最小次正规数约 1.4×10−45，指数低于约 −104 就精确归零；float64 的阈值约 −745。−1e8 远超两者，所以无论哪种精度都能得到精确的零概率，这就是"大负数在效果上等价于 −inf、但处处保持有限"的来历。梯度一支也顺手写下：∂log π̃(a|s)/∂zj = 1[j=a] − π̃(j)，非法动作的 π̃≈0，梯度不会流向被屏蔽的位置。

2. 无效动作掩码

设状态 s 上合法动作集合的 0/1 掩码为 M(s)，采样分布改为：

z̃a = za − (1 − Ma)·C　⟹　π̃(a|s) = softmax(z̃)
log π̃(a|s) = z̃a − logsumexp(z̃)，　H(π̃) 只在合法动作上求和 C 取 1e8 量级：非法动作概率 exp(−1e8)≈0，同时避免 −inf 引发的 NaN

为什么用 −1e8、不用 −inf：当概率为 0 时，熵里会出现 0·log0 = 0·(−∞) 的未定义形式，反向传播可能产生 NaN。大负数既保证数值上概率为 0，又保持所有表达式有限。掩码只依赖状态（不依赖策略参数），所以训练时可以用同一条函数从观测重建。

数值算例：墙角状态的掩码前后概率与熵

取某状态下 4 个动作的 logits z = [2.0, 1.0, 0.5, 0.1]，其中后两个非法（墙角只有两个方向可走）。未掩码：softmax 概率为 0.5745 / 0.2114 / 0.1282 / 0.0859，非法动作占总概率 21.4%，熵 1.1211。硬掩码：给后两个 logits 压上 −1e8，概率变成 0.7311 / 0.2689 / 0 / 0，非法质量为 0，熵 0.5822（合法动作只剩两个时，熵的上限是 ln2 ≈ 0.6931）。

再算"三处不一致"的代价：同一组 logits 下，掩码分布与未掩码分布对合法动作的对数概率相差 logsumexp(z) − logsumexp(z̃) = ln(12.861/10.107) ≈ 0.241，比值整体带 e0.241 ≈ 1.27 倍的固定乘数。采样用掩码、更新用未掩码（或反过来），每个样本的比率都被这个乘数扰动，且乘数随状态变化，裁剪抹掉一部分、其余混进梯度，这就是要求三处一致的原因。软掩码（非法 logits 减 5）作为中间档：非法质量约 0.0018，把三档排开更直观。

方案非法动作概率（上述算例）实现复杂度适用场景
无掩码0.2141最低非法动作代价低、约束稀疏
软掩码（−5）0.0018低希望保留少量探索、约束偏软
硬掩码（−1e8）0中：三处一致、掩码入库非法动作零容忍（游戏 AI、LLM 解码）

3. 一致性：三处必须用同一张掩码

PPO 的比率 rt = πnew/πold 要求分子分母是同一分布族下的两次评估。因此：采样时用掩码分布采动作、记录 log π̃；更新时对同一状态重新构造掩码分布、重算 log π̃；评估时贪婪动作也在掩码后的 logits 上取 argmax。任何一处漏掉掩码，都会引入系统性偏差，采样掩码、更新不掩码会让比率整体偏移，训练看似正常但学习信号被扭曲。

4. 三个必须显式处理的边界情形

其一，全掩码状态：若某状态所有动作都非法（死胡同设计出错，或语义上"只能原地终止"），掩码后全部 logits 都是 −1e8，softmax 的归一化失去意义，实现会得到均匀分布或 NaN。求解方法是在环境层保证"至少一个合法动作"的不变量，把"无路可走"定义为终止条件，不当作非法动作处理。其二，掩码依赖动作历史：合法掩码必须只是状态的函数（本章 action_mask 只看位置）。若约束依赖上一步动作（例如"不能连续两次反向"），必须把这段历史编码进观测，否则同一观测会配上不同掩码，比率 rt = πnew/πold 的分子分母不再指同一分布。其三，从 obs 反推掩码的漂移：重建掩码要求两份实现永久同步，任何一处边界条件改动都可能悄然失配；本章坚持"掩码随 batch 存储"，反推版本只用于评估与部署（那时没有 batch 可查）。

5. 掩码为什么真的更快

nomask 策略面对的是一个"额外任务"：在优化回报的同时学习每个状态的行动约束。它有两个成本：探索预算被非法动作消耗（撞墙浪费步数并吃负奖励）；梯度要同时解决"约束学习"和"回报优化"，在约束密集的状态上样本效率下降。掩码把这个隐式约束变成结构先验，让策略容量与样本全部用于合法动作之间的取舍。本章的无效动作率指标会直接量化这部分浪费。

参数取值依据

三个数字都值得算一遍。

为什么步惩罚取 −0.01。若最短路径约 12 步，任务的最优回报约 1 − 12×0.01 = 0.88；随机策略走满 60 步上限时回报约 −0.6，两者相差约 1.5。惩罚太小（例如 −1e−4）会让绕路几乎没有成本，成功信号被淹没；惩罚太大（例如 −0.1）会让 12 步与 60 步的回报相差 4.8，超过成功奖励本身，策略会为了省步数而回避探索。

为什么回合上限取 60 步。6×6 共 36 格，起点到终点的最短路径在 10～18 步之间（曼哈顿距离 10 加上绕障碍的额外步数）。60 步约为它的 3～5 倍：训练初期随机游走也有不小概率撞到目标，正样本不至于稀缺；上限再小（如 20 步）会让随机探索几乎无法成功，学习根本启动不了；再大（如 200 步）则让失败回合的步惩罚总量接近成功奖励，回报信号被稀释。60 是"给探索留余量、又让失败有代价"的折中。

无效动作率为什么实测约 10%、低于算例的 21%。算例的 21.4% 来自墙角状态（4 个动作 2 个非法）。逐类状态看：开阔格 4 个动作全合法（无效率 0）、贴一面墙（外边界或障碍旁）为 25%、外墙角为 50%、死角为 75%。按状态访问频率加权（开阔格与贴墙格占多数），总体无效率自然落回 10% 一带。这条加权逻辑同时给出诊断判据：nomask 的无效率长期高于 30%，说明策略连基本避障都没学稳，应检查奖励尺度与更新健康度；迷宫结构本身（开阔格占多数）解释不了这个数字。

数据流

每个 arm 一条完整训练：重设种子 → 采样 1024 步，每步先取 env.action_mask()（mask 版送入网络，nomask 版仅用于统计）→ 记录动作/logp/掩码/奖励/价值/终止 → GAE → 8 epochs 更新（mask 版用存储的掩码重算 logp）→ 统计无效动作率与近 20 回合成功率 → 跑满 5 万步 → 带掩码的贪婪评估（同时统计非法次数）。

为什么掩码随数据存储、不在更新时重建

理论上更新时可以从 obs 用 mask_from_obs 重建掩码，但一旦 step 与反推函数的边界条件有一处不一致，重建出的分布就不是采样时的分布，比率 rt 立刻失真。把采样时的掩码原样存进 batch，让"采样与更新一致"从推理变成事实，这是可靠性设计，代价只是每步多存 4 个浮点数。

两个快速自检信号也记住：masked 版的熵读数一旦超过 ln(合法动作数) 的上界，或者评估期的非法动作计数不为 0，说明存在"掩码没生效"的位置，按采样、更新、评估三处顺序排查即可定位。

关键代码与解读

片段 1：掩码的生成与应用，两行核心

    def action_mask(self):
        """返回长度 4 的 0/1 掩码（1=可执行）。掩码只依赖当前状态。"""
        deltas = [(-1, 0), (0, 1), (1, 0), (0, -1)]     # 上右下左
        mask = np.zeros(4, dtype=np.float32)
        for a, (dr, dc) in enumerate(deltas):
            nr, nc = self.pos[0] + dr, self.pos[1] + dc
            in_bounds = 0 <= nr < self.size and 0 <= nc < self.size
            blocked = (nr, nc) in self.obstacles
            mask[a] = 1.0 if (in_bounds and not blocked) else 0.0
        return mask

def apply_mask(logits, mask):
    """把非法动作的 logits 置为 −1e8（用大负数代替 −inf，避免 NaN）。"""
    return logits.masked_fill(mask < 0.5, -1e8)

解读：（1）action_mask 逐动作检查"是否越界、是否撞障碍"：它只依赖位置（状态），不依赖策略参数，这是它能被安全复用（采样、更新、评估）的前提。（2）apply_mask 是全部改动里最核心的两行：masked_fill 把掩码为 0 的位置填成 −1e8。softmax 之后 exp(−1e8) 在 float32 里下溢为 0，非法动作的概率恰好是 0。（3）阈值写成 mask < 0.5（不用 mask == 0）：浮点掩码可能因运算变成 0.9999… 之类的近似值，用阈值比较更稳。（4）为什么不用 float("-inf")：熵计算里 0·log 0 是 0·(−∞)，反向传播一路 NaN（练习 1 会让你复现）。−1e8 保持全部表达式有限，是行业惯例。

片段 2：采样，masked 与 nomask 的分叉

    for _ in range(steps):
        mask_i = env.action_mask()                            # 掩码是状态的函数
        mask_t = torch.as_tensor(mask_i, dtype=torch.float32, device=device).unsqueeze(0)
        if use_mask:
            a, logp, v = net.act(obs_t, mask_t)
        else:
            logits, value = net(obs_t)                        # 非掩码路径保持原样
            dist = Categorical(logits=logits)
            action = dist.sample()
            a, logp, v = action.item(), dist.log_prob(action).item(), value.item()

        next_obs, r, terminated, truncated, info = env.step(a)

        obs_buf.append(obs_t.squeeze(0).cpu().numpy())
        act_buf.append(a)
        logp_buf.append(logp)
        mask_buf.append(mask_i)   # 掩码随数据存储：更新与采样一致的证明
        rew_buf.append(r)
        val_buf.append(v)
        term_buf.append(float(terminated))

解读：（1）两种 arm 在采样入口分叉，但记录格式完全一致：无论用不用掩码，mask_buf 都存下当前掩码，统计无效动作率需要它，未来调试也需要它。（2）注意 logp 的来源：mask 版来自掩码分布、nomask 版来自原始分布，两条路径的 logp 必须各自对应"实际采样用的分布"，这样更新重算时才能对上。（3）env.step(a) 之后 info["invalid_action"] 告诉我们这一步是否撞墙：这是"浪费"的直接度量，按 batch 聚合即无效动作率。（4）无论走哪条路径，动作值域都合法（0..3），差异只在分布，这让对比的其余代码（GAE、更新、日志）可以完全共用。

片段 3：更新重算，同一张掩码，同一个分布

            mb = idx[start:start + args.batch_size]
            logits, value = net(obs[mb])
            if use_mask:
                # 更新重算 logp 时必须用“采样时的同一张掩码”，否则比率失真
                dist = Categorical(logits=apply_mask(logits, mask[mb]))
            else:
                dist = Categorical(logits=logits)
            logp = dist.log_prob(act[mb])

            ratio = torch.exp(logp - logp_old[mb])
            surr1 = ratio * adv[mb]
            surr2 = torch.clamp(ratio, 1.0 - args.clip, 1.0 + args.clip) * adv[mb]
            policy_loss = -torch.min(surr1, surr2).mean()
            value_loss = F.mse_loss(value, ret[mb])
            entropy = dist.entropy().mean()

解读：（1）这是掩码一致性要求最集中的地方：mask[mb] 就是采样时存下来的掩码，apply_mask 与采样路径调用同一个函数。只改采样不改更新，比率 rt 分母是掩码分布、分子是原始分布，训练会缓慢发散或停滞，而且很难从日志里看出来。（2）熵也来自同一个 dist：masked 分布的熵只在合法动作上定义，与采样一致；如果熵另算（比如用未掩码 logits），正则项会把非法动作的"不确定性"也算进去，方向就偏了。（3）nomask 分支保留未掩码的 dist：两条路径的代码形状对称，便于逐行对照，也避免"为了复用而强行套掩码"的扭曲。（4）换种写法：把掩码逻辑塞进网络 forward（网络自己拿掩码）也是一种设计，但会让"网络输出"与"环境约束"耦合；本章保持网络输出原始 logits、掩码在策略调用处施加，职责更清晰。

片段 4：评估，贪婪动作也必须掩码

        while not done:
            logits, _ = net(to_tensor(obs, device))
            if use_mask:
                mask_t = torch.as_tensor(env.action_mask(), dtype=torch.float32,
                                         device=device).unsqueeze(0)
                logits = apply_mask(logits, mask_t)     # 贪婪选择同样先掩码
            action = int(torch.argmax(logits, dim=-1).item())
            obs, r, terminated, truncated, info = env.step(action)
            ep_ret += r
            ok = ok or bool(info["success"])
            invalid += int(info["invalid_action"])      # 评估期非法动作计数
            done = terminated or truncated

解读：（1）贪婪评估在未掩码 logits 上 argmax，完全可能选出一个非法动作，这是"训练看着不错、评估分数很低"的经典原因，而且容易被误诊为训练问题。（2）掩码在评估时从环境实时获取（env.action_mask()）：评估环境是新的实例，没有训练时的 batch 可查，状态函数的价值在部署场景里就体现出来了。（3）invalid 计数是验证手段：mask 版应恒为 0，如果非 0 说明掩码应用位置有遗漏；nomask 版则量化"部署期还要吃多少撞墙惩罚"。（4）评估直接执行 action（不是掩码前的采样动作），保证口径与部署一致。

预期结论（以实跑为准）：mask 版在 1 万步左右把近 100 回合成功率推过 90%、无效动作率恒为 0；nomask 版更慢，平均无效动作率收敛到约 10% 后很难继续下降，评估期仍有若干次非法动作，成功率通常低 5～15 个百分点。熵值不要跨组直接比较：mask 版分布只在 1～4 个合法动作上定义，名义熵天然更低（墙角只有 2 个合法动作时上限为 ln2 ≈ 0.693）。若两组差距不明显，说明迷宫约束压力不够，加障碍或加重步惩罚会放大差距（练习 2）。

常见坑

  • 只在采样时掩码、更新时忘了掩码：比率的分母来自掩码分布、分子来自未掩码分布，rt 被系统性拉偏，训练会缓慢发散或停滞。把掩码随数据一起存下来是防呆做法。
  • 在概率层做掩码（应当在 logits 层做）：先 softmax 再把非法位置置零、再重新归一化，看似等价，但重新归一化后 log_prob 必须手动加 log 归一化常数，容易写错；直接在 logits 层掩码才是干净做法。
  • 用 -inf 当掩码值：熵、KL、反向传播在 0 概率上做乘除时出现 NaN。固定大负数（−1e8）是行业惯例。
  • 评估/推理漏掉掩码：部署时分布在训练环境之外，很容易忘记掩码，结果是推理动作非法。把"掩码来源"封装成环境/规则层的统一接口，训练推理共用。
  • 把两组熵值当同一把尺子：掩码改变了分布的支撑集，熵的"满值"随合法动作数变化。跨组比较应看成功率、无效率与 KL，熵只做组内趋势观察。

练习与思考

  1. 把 apply_mask 里的 −1e8 改成 float("-inf")，运行几十次更新，观察是否出现 NaN 或熵异常，并解释。★
    提示
    常见现象是第一次更新正常、第二次熵变 nan 或参数变 nan（0×∞）。用 torch.isnan 检查 loss 或参数即可定位。跑完记得改回 −1e8。
  2. 把障碍数量翻倍（修改 MaskedMaze.obstacles），重跑两组对比，观察无效动作率与首达步数的差距如何变化。★
    提示
    约束越密，nomask 的"浪费"越大，mask 的优势越明显。注意别让迷宫变得不可达（保留一条通路）。
  3. 实现"软掩码"：给非法 logits 减去固定惩罚 −5.0（把 −1e8 换成这个数），并比较它对成功率与无效率的影响。★★
    提示
    软掩码仍会给非法动作留出非零概率，理论上"可学习但代价更高"，可以视为硬掩码与 nomask 的中间态。观察它能否达到零无效率。
  4. 记录"贴墙状态"上的动作分布：固定几个紧邻障碍的位置，在训练中每 5 次更新打印 mask 与 nomask 两版策略在这些位置的动作概率，观察非法动作概率被压到多少。★★★
    提示
    构造状态矩阵后走一次 net(obs)，mask 版再套 apply_mask，打印 softmax 的概率即可。注意用同一套障碍坐标对照两版策略的行为差异。
  5. 写一个小脚本验证 −1e8 的下溢：在 float32 与 float64 下分别计算 exp(-104)、exp(-745)、exp(-1e8)，找出两种精度"精确归零"的分界，并解释为什么固定大负数在两个精度上都能给出零概率。★
    提示
    用 np.float32(x) 强制精度。float32 的分界在 −104 附近，float64 在 −745 附近；两者都远小于 1e8，所以结论不依赖精度选择。

小结

  • 离散分类策略的稳定实现基于 logits 的 log-softmax；概率与熵都从 logits 计算，永远不要手算 softmax。
  • 无效动作掩码在 logits 层把非法动作压到 −1e8，softmax 后概率为 0，同时避免 −inf 的 NaN 风险。
  • 掩码必须在采样、更新重算、评估三处一致；把掩码随数据存入 batch 是防呆的结构设计。
  • 实验结论：mask 版首达 90% 成功约 1 万步、无效动作率为 0；nomask 版慢 2 倍以上且保留约 10% 的无效探索。
  • 下一章处理"部分可观测"：当观测只是真实状态的一部分时，MLP 策略失效，需要循环神经网络把历史压进隐状态，用 T 型迷宫验证记忆的作用。
