第五篇 · 多智能体环境与实践

第 100 章：多智能体环境：游戏AI

压轴实验：2v2 竞技场对战，4 名斗士共享一张策略网络进行自博弈，看对脚本对手的胜率如何从 0 爬到 1、自博弈得分率如何在噪声中围绕 50% 波动，并收束整门课 100 章的技术地图。

  • 主题：环境设计 / 对抗游戏与自博弈（Self-Play）
  • 关键公式：自博弈对称性检验 P(A 胜) ≈ 0.5；奖励 = 命中 +0.5 / 击杀 +2 / 获胜 +2 / 每步 −0.005
  • 预计学时：60 分钟
  • 前置章节：第 099 章

学习目标

  • 实现一个完整的对抗游戏环境：移动、攻击、冷却、生命值与队伍胜负的闭环。
  • 理解自博弈（self-play）训练范式：同一张策略网络同时扮演四个角色，对手随自己一起进步。
  • 掌握"对称性检验"：自博弈得分率应围绕 50% 波动（单次评估噪声不小），长期系统性偏离才是环境偏置的证据。
  • 用对脚本对手的胜率作为真实强度的度量，区分"自我感觉良好"与"真的变强"。
  • 完成全课程回顾：把从 PPO、SAC 到多智能体与 14 个环境的 100 章内容串成一张技术地图。

背景与动机

游戏 AI 是强化学习最著名的舞台：AlphaGo、OpenAI Five、AlphaStar 走的都是同一条路线，没有现成的高手指路，就让智能体从与自己的对战中成长。自博弈的魔力在于对手永远"恰好比你强一点点"：胜率短暂冲破 50% 后，旧行为被追上，重新回到平衡；策略就在这条自我追逐的阶梯上不断变强。

作为压轴章，这个环境几乎用到了前面全部零件：离散动作设计（第 090/096 章）、参数共享（第 070/087 章）、GAE 与裁剪目标（第 001–003 章）、对抗与对手建模（第 074/082 章）、多目标评估与对称性检验（第 084 章）。读它等于把全课骨架再走一遍，也正好是收官前最后一次系统性复习。

核心原理

1. 游戏规则的形式化

4 名斗士分为 A（0/1 号）、B（2/3 号）两队，每人 3 点生命。每一步：

  • 选择 10 个动作之一：5 个移动方向 × {不出手, 出手}，向该方向位移 0.09；
  • 出手若在 0.3 射程内且冷却为 0，对最近的敌人造成 1 点伤害并进入 3 步冷却；
  • 一方全员生命归零即落败（双方同时归零算平局），120 步未分胜负算截断。

奖励分解为四项：命中 +0.5、击杀 +2、获胜方存活者 +2、每步时间成本 −0.005。时间成本抑制"绕圈逃跑"，击杀奖励给"换命"一个明确的价码，获胜奖励把团队目标写进每个人的收益。

2. 为什么 4 人共享一张网络

两队完全对称，对 A 队有利的行为对 B 队同样有利。把 4 名斗士的经验合并进同一个 PPO 批次、参数共享：

θ ← θ − η·∇θ LCLIP（对全部 4×T 个样本求平均）

两个直接好处：样本效率 ×4；策略不会出现"只会在左边出生点打"的过拟合。训练信号里混着"我打人"与"人打我"两种视角，对对称游戏而言这正是资产：攻防经验互为对手数据。

3. 自博弈的对称性检验

自博弈中没有固定对手，更新会同时改变双方实力。健康的自博弈应满足：

评估时 P(A 胜) ≈ 0.5（同一策略对同一策略，座位无优势）

如果这个数字长期偏离 0.5，先检查环境是否对称（出生位置、伤害结算顺序），再检查是否有"左手倒右手"的信息泄漏。它是比胜率上升更基础的实现正确性检验：先证明环境无偏，再谈强度。注意区分，自博弈胜率永远在 0.5 附近，只有对脚本（或对旧版本）的胜率才度量真实强度。

4. 对脚本对手的胜率

脚本对手策略是"追最近敌人、进射程就出手"，有攻击性但不会走位、不会包夹的基准。学习策略的收益点是拉扯与集火：拉距离躲冷却、与队友在同一窗口攻击同一目标。对脚本胜率从初始的 0（未训练策略连脚本都打不过）升到什么水平，直接量化了这些高级行为的价值；如果训练很久仍停在 0 附近，多半是熵正则过高或奖励太稀疏。

5. 稀疏事件与冷却节奏

命中与击杀是稀疏事件，靠时间成本与命中奖励提供梯度。冷却 3 步让"每一击的时机价值"随局势变化：血量优势该保守拉扯、劣势该拼输出，而观测里显式提供了双方血量与冷却状态，策略可以从这些数字里读出"谁现在能出手、谁在冷却真空期"。观察日志里"回合长度随训练下降"，就是策略学会抓住真空期进攻的信号。

与前面章节的关系

自博弈把第 082 章"对手建模"的思路推到极限：与其预测一个会学习的对手，不如让对手就是过去/现在的自己。它同时复用第 086 章"共享池"的思想（这里共享的是网络与经验）与第 088 章"脚本基线"的评估纪律。作为收官实验，它把"环境设计、参数共享、对抗训练、诚实评估"四条主线拧成一个闭环。

自博弈的两个必须先做的检查

1) 对称性：A/B 出生点、结算顺序、观测内容必须严格对称；任何偏置都会让自博弈胜率系统性偏离 0.5，从此"强度"与"座位优势"再也分不开。另外留意静默的类型错误：若把队伍标签写成 Python 元组再拿去做 numpy 布尔索引（如 hp[teams == 0]），取到的是空数组，所有对局会瞬间判成"双灭平局"；日志表现为回合长度恒为 1、胜率恒为 0.5，看到这种组合先查环境，别怀疑训练。

2) 评估流独立：每种对手模式用不同的随机流（seed+111/777/999），且评估用贪婪动作；训练用的采样流与评估流分离，否则胜率数字会被探索噪声污染。

关键代码与解读

片段 1：13 维观测，一个斗士的战场视野

def _obs(self) -> np.ndarray:
    obs = []
    for i in range(4):
        mate = self.teammates[i]
        enemies = [j for j in range(4) if self.teams[j] != self.teams[i]]
        e0, e1 = enemies
        # 最近对手的生命值：残血目标优先集火，需要显式给出
        nearest_hp = self.hp[e0] if (self.hp[e0] <= self.hp[e1] and self.hp[e0] > 0) \
            else (self.hp[e1] if self.hp[e1] > 0 else self.hp[e0])
        o = np.concatenate([
            self.pos[i],                            # 自己位置（场地边界感知）
            [self.hp[i] / self.max_hp],             # 自己的血量
            [self.cd[i] / self.cooldown],           # 冷却进度：能否出手
            self.pos[mate] - self.pos[i],           # 队友相对位置
            [self.hp[mate] / self.max_hp],          # 队友血量
            self.pos[e0] - self.pos[i],             # 两个对手的相对位置
            self.pos[e1] - self.pos[i],
            [nearest_hp / self.max_hp],             # 最近对手的血量
            [self.steps / self.max_steps],          # 回合进度
        ])
        obs.append(o.astype(np.float32))
    return np.stack(obs)

解读：观测是"斗士能感知的一切"，每一项都对应一种战术。（1）自己位置给绝对坐标（用于边界判断），其余全是相对量，两队对称，参数共享的前提。（2）自己的冷却进度 cd/cooldown：出手机会是稀缺资源，策略必须知道"我这一击能不能打出去"。（3）队友的血量与位置：脆皮队友在场意味着需要掩护或换线，团队配合的信息基础。（4）nearest_hp 的写法值得细看：在两敌人中选活着且血量较低的那个；若都被打光则退回 e0。残血信息支持"集火收割"，也避免策略对着一具"尸体"空挥，注意阵亡者仍占据观测槽位（位置照给），策略要看血量才能识别"谁是死的"。（5）维度账：2+1+1+2+1+4+1+1 = 13。

片段 2：动作解码、移动与冷却

actions = actions.astype(np.int64)
moves = actions // 2            # 0..4：停/上/下/左/右
attacks = actions % 2           # 0/1：本步是否出手
alive = self._alive()
rewards = np.full(4, -self.time_cost, dtype=np.float32)   # 每步时间成本

# 1) 移动（阵亡者不动）：先移动、后结算攻击，走位影响本步的射程判定
for i in range(4):
    if alive[i]:
        self.pos[i] = np.clip(
            self.pos[i] + self.move_step * self.move_vecs[moves[i]],
            -self.bound, self.bound)

# 2) 冷却递减：每步恢复一格，为下一步的攻击权做准备
self.cd = np.maximum(self.cd - 1, 0)

解读：动作编码与结算顺序共同定义了游戏的手感。（1）编码 a = 移动×2 + 出手：除法取移动、取模取出击，无需查表；10 个动作 = 5 移动 × 2 状态，紧凑且语义清晰。（2）顺序是"先移动、后攻击"：本步走进射程就能出手，这给了"移动攻击"一个步内的时间结构，也是脚本对手能"边追边打"的实现基础。（3）阵亡者跳过移动但仍在数组里（hp≤0）：保留槽位让张量形状恒定，各智能体索引不变；"死人不行动"由 alive 掩码统一处理。（4）冷却在攻击结算之前递减：本轮攻击判定里读到的 cd 已经减过 1，所以"3 步冷却"的节奏是打一发、等两拍、再打，节奏清晰可读。奖励先铺一层时间成本，后续命中/击杀/获胜在其上叠加。

片段 3：攻击结算，射程、冷却与最近目标

for i in range(4):
    if not alive[i] or attacks[i] == 0 or self.cd[i] > 0:
        continue                    # 死了、没按攻击、或还在冷却：这一击作废
    enemies = [j for j in range(4)
               if self.teams[j] != self.teams[i] and self.hp[j] > 0]
    if not enemies:
        continue                    # 对方全灭：没有可打的目标
    dists = [np.linalg.norm(self.pos[j] - self.pos[i]) for j in enemies]
    k = int(np.argmin(dists))       # 自动锁定最近的敌人（不做目标选择）
    if dists[k] <= self.attack_range:
        self.cd[i] = self.cooldown  # 出手成功才进入冷却；空挥不惩罚
        target = enemies[k]
        self.hp[target] -= 1
        self.hits_total += 1
        rewards[i] += self.hit_reward
        if self.hp[target] <= 0:    # 这一击造成了击杀
            rewards[i] += self.kill_reward
            self.kills[self.teams[i]] += 1

解读：十几行把"战斗"的物理写得干净利落。（1）三重门槛 alive / attacks / cd：死人不打、没按不打、冷却不打；本实现里"空挥"（按了攻击但目标不在射程）不进入冷却也不扣费，让"乱按攻击"没有直接代价，压力全在时间成本上。若想惩罚浮躁的攻击，可以给空挥加冷却（练习可以试）。（2）目标选取是自动的（最近的活敌人）：动作空间里没有"选择目标"的维度，集火只能靠"站得离谁近"来间接实现，这正是观测里要给最近对手血量、以及团队配合能涌现的原因。（3）命中 +0.5、击杀再 +2：击杀奖励是命中的 4 倍，鼓励"收人头"，"雨露均沾"的均摊输出收益更低；奖励在同一处即时结算，信用分配简单直接。（4）伤害结算按斗士下标顺序逐个处理：前两人的攻击可能让后两人"打不出去"（目标已死会自动换最近目标），顺序在对称的游戏里没有可利用的偏置，但如果你今后加"先手技能"，这里的顺序必须重新审计。

片段 4：胜负判定与团队奖励

team_alive = [bool(np.any(self.hp[self.teams == t] > 0)) for t in (0, 1)]
terminated = False
winner = None
if not team_alive[0] and not team_alive[1]:
    terminated = True               # 双灭：平局（winner 为 None）
elif not team_alive[0] or not team_alive[1]:
    terminated = True
    winner = 0 if team_alive[0] else 1
    for i in range(4):
        if self.teams[i] == winner and self.hp[i] > 0:
            rewards[i] += self.win_reward   # 只发给获胜队的存活者

truncated = (not terminated) and self.steps >= self.max_steps
info = {"winner": winner, "hp": self.hp.copy(), "hits": self.hits_total}

解读：终局逻辑同时承担"裁决"与"标注"两种职责。（1）三路分支：双灭 → 平局终止；单方团灭 → 另一方获胜；其余情况继续（直到 120 步截断）。平局是一种真实结果的建模，评估里平局按半分处理，避免把"势均力敌"错算成失败。（2）获胜奖励只发给存活者：一个队赢了但你自己先倒了，拿不到 +2。这条设计让"活着赢"比"换命赢"更值，战术上鼓励自保与拉扯，抑制"一换一"式的莽夫打法。（3）terminated 与 truncated 严格分开：团灭是任务终止（GAE 切断 bootstrap），120 步是时间截断（继续 bootstrap），这条纪律从第 001 章贯穿到最后一章，一次都没破例。（4）info 把 winner/hp/hits 交给评估层：胜率、回合长度、命中总量三个指标全部由此加工，环境只提供"事实"，解释权留给评估。

常见坑

  • 用非对称的出生点或判定顺序：A 队先结算、或出生位置微偏，自博弈胜率会系统性偏离 50%，从此分不清"策略强"与"座位优势"。新环境第一件事就是对称性检验。
  • 把阵亡斗士的转移照常入批：死后观测不变、动作无效，会把"死后的世界"混进训练；更严谨的做法是给 done 加阵亡掩码（本实现按局统一终止，属于可接受的简化）。
  • 评估局数太少：胜负是伯努利变量，20 局胜率的标准误约 0.11；默认 40 局仍有 0.08。重要结论至少跑两个种子。
  • 把自博弈胜率当强度指标：它永远在 50% 附近，只检验对称性；强度看对脚本或对旧版本快照的胜率。
  • 训练/评估共用随机流：采样探索与胜率评估必须分流（本实现用 111/777/999 三组），否则评估数字会被探索噪声与采样顺序污染。

    提示

  3. 把击杀奖励从 +2 调到 +5，先预测策略的风险偏好变化（回合是否变短、对脚本胜率是否反而下降），再自博弈验证。★★
    提示
    击杀奖励是风险旋钮。冒进策略对脚本可能赢更快，但面对会走位的对手容易送命，用自博弈的命中/被命中比来观察。
  4. 实现"历史对手池"：每 N 次更新保存一份策略快照，训练时随机抽取旧快照作为 B 队（AlphaStar 风格），先设计快照的采样与更新接口，再比较它与即时自博弈的稳定性。★★★
    提示
    为 B 队维护独立的观测-动作流与旧策略前向；从"最多 5 份、每 8 次更新入池"做起，旧策略只采样不更新，这是 League 训练的迷你版。
  5. 给竞技场加"技能"：每 20 步可释放一次范围攻击（邻域 1 点伤害，需扩大动作空间到 20），先论证动作维度翻倍对学习速度的影响，再做实验。★★★
    提示
    在编码里加一位技能标志并在观测里加技能冷却；动作翻倍后建议把预算提到 15 万步再看结论，这是"动作空间大小直接决定样本需求"的实测。

小结

  • 2v2 竞技场把移动、攻击冷却、生命值与胜负判定组织成完整的对抗闭环；10 元离散动作编码让 PPO 直接可训。
  • 自博弈让对手与策略共同进化；共享网络利用游戏的对称性，把 4 名斗士的经验合并训练，样本效率 ×4。
  • 对称性检验（自博弈胜率 ≈ 0.5）是正确性底线，对脚本胜率才是强度；冷却、击杀奖励、评估局数分别控制节奏、风险偏好与统计可靠性。
