第五篇 · 多智能体环境与实践

第 096 章：多智能体环境：自动驾驶

把 6 辆车放进周长归一化的双车道环形公路：每步同时决定加速/刹车与变道，奖励速度、惩罚跟车过近与碰撞，用共享网络的离散 PPO 训练，看车队能否在几乎零碰撞的前提下把平均速度从匀速基线的 0.08 拉到 0.12 以上。

  • 主题：环境设计 / 环形交通流与跟车-变道决策
  • 关键公式：ri = 5vi − 2·𝟙[间距<0.03] − 4·𝟙[间距<0.015] − 0.1·𝟙[变道]
  • 预计学时：60 分钟
  • 前置章节：第 095 章

学习目标

  • 把自动驾驶抽象成"跟车 + 变道"的最小模型：环形公路、速度档位、车道选择、间距约束。
  • 设计同时覆盖纵向与横向的离散动作（3×3=9 个），并处理"变道被拒"这种局部动作失效。
  • 用共享网络的离散 PPO 训练 6 辆车，理解局部观测（前车/后车/邻道间距）如何支撑分布式决策。
  • 把"速度"与"安全"写进同一份奖励并调平：跟车罚款、碰撞重罚、变道成本各自的作用。
  • 用匀速基线给学习结果定标：不看速度提升百分比，就不知道训练到底有没有产生价值。

背景与动机

自动驾驶是多智能体研究里"安全关键"的旗舰场景：每辆车都想快，但快的前提是不撞、不堵、不逼停别人。与前面章节的差别在于奖励冲突是逐车的局部冲突：前车留出空当，你能多拿速度分；跟车过近，随时可能付出 4 倍罚款。策略必须在每一刻权衡"再快一点"与"保守一点"。

环形公路（ring road）是交通流理论的标准实验台：没有红绿灯、没有交叉口，纯粹考察跟车与变道。把它离散成"每步 0.02 的速度档 + 三档变道"后，问题规模刚好能让 PPO 在几万步内学出看得见的行为：默认设置下是"全员加速到上限并保持零碰撞巡航"；在更拥挤（车数加到 10）或引入慢车（匝道练习）的变体里，才会出现择机超车、堵车降速这类更丰富的行为。本章也是第五篇里唯一同时包含"纵向控制 + 横向决策"的环境，动作空间是二维的，变道时机与安全约束的相互作用是本章最有意思的观察点。

核心原理

1. 环形运动学

周长归一化为 1，车 i 的位置 pi ∈ [0,1) 环形推进，速度每步最多改变 0.02：

vt+1 = clip(vt + 0.02·at, 0.02, 0.2)，pt+1 = (pt + vt+1) mod 1

速度范围 [0.02, 0.2] 让"最慢"与"最快"相差 10 倍。注意每步速度变化只有 0.02（约一个档位），而位置推进量就是当前速度，速度即是位移，这个简化把"加速度积分"这一层拿掉了，保留了交通流的核心机制：间距与速度的相互约束。

2. 横向动作与变道拒绝

动作空间是纵向 {−1,0,+1} 与横向 {−1,0,+1} 的笛卡尔积（9 个）。变道不是无条件生效的：如果目标车道在当前位置 ±0.03 内已有车辆，变道被静默拒绝（车留在原车道）。这种"动作部分失效"是真实驾驶的写照，也迫使策略在观测里关注邻道间距，盲目变道只会浪费动作预算。注意"静默"两个字：被拒的动作仍会消耗一次决策，日志里看不出失败，只有变道次数统计能反映实际生效的次数。

3. 奖励结构：速度与安全写在一张账单上

ri = 5vi − 2·𝟙[前车间距 < 0.03] − 4·𝟙[前车间距 < 0.015] − 0.1·𝟙[变道生效]

速度项每步贡献 0.1～1.0，是唯一正收益；跟车罚款让"贴前车"变成负和游戏；碰撞重罚相当于四步满速收益；变道成本抑制"来回横跳"。注意罚款是每步重复计算的，持续贴车会持续扣分，因此最优策略是稳定保持安全间距，"偶尔贴一下"的占便宜思路会被持续扣分修正。两级阈值 0.03/0.015 形成"警告—事故"的双层结构：策略有 0.015 的缓冲带可以在不撞的前提下体验警告信号。

4. 为什么局部观测就够了

观测只含：本车道前车间距与前车速度、邻道前车间距与速度、本车道后车间距。环形结构的妙处在于：任何全局拥堵都会通过"前车慢 → 我跟车罚款"的链条传导到每辆车的局部观测里。参数共享的 6 辆车各自做局部最优反应，整体交通流就可能逼近高效均衡，这正是分布式交通控制的核心假设，也是本章想验证的事。

5. 评价口径

三个指标：平均速度（效率）、碰撞次数（安全）、变道次数（稳定性）。匀速基线（v=0.08、不变道）给出 0 碰撞的参考点；学习策略必须同时满足"速度明显提升"与"碰撞保持接近 0"，否则没有工程价值。安全指标不达标的策略不值得优化速度，这是全章的第一纪律。

与前一章的差异

第 095 章是"资源-生态"耦合（采集影响存量、存量影响未来收益），本章是"车辆-交通流"耦合（自己的速度影响别人的间距、别人的间距反过来制约你）。两者的共同点是局部观测 + 全局耦合；差别是 095 的奖励是团队或个体的采集量，而本章奖励里写进了显式的安全约束，"不要撞"成为奖励设计的目标，环境规则不设硬约束。

"稳态跟车"是本章要观察的第一行为

奖励里没有"保持车距"的正项，只有贴太近的罚款，但速度项只在前方有空间时才能兑现。策略的理性路径是：找到与前车的可持续间距，用不触发罚款的速度稳定巡航，遇到慢车才择机变道。这就是交通流理论里的"稳态跟车"（car-following equilibrium）。注意默认设置里所有车都能加速到上限、彼此不干扰，这个行为会淡化成平凡解；加车或引入慢车后它才会显出分量。

关键代码与解读

片段 1：环形间距，取模如何消灭"队首队尾"

def _gap_ahead(self, i, lane):
    """返回 (环形前方最近车的间距, 该车速度)，没有车时返回 (1.0, 0)。"""
    best_gap, best_v = 1.0, 0.0
    for j in range(self.n_cars):
        if j == i or self.lane[j] != lane:
            continue                           # 只看同车道的其他车
        gap = (self.pos[j] - self.pos[i]) % 1.0   # 取模：环形上"前方"的通用定义
        if gap < best_gap:
            best_gap, best_v = gap, float(self.v[j])
    return best_gap, best_v

解读：十行函数，但取模那一行是环线环境的命门。（1）(pos[j] − pos[i]) % 1.0：在圆环上，j 如果在 i 前方 0.1 处，差值可能为负（比如 j=0.05、i=0.95 时差 −0.9），取模后变成 0.1，"前方"在任何坐标位置都有正确定义。（2）初始值 (1.0, 0.0)：环上最长间距不超过 1，没有前车时返回"无限远、速度零"，观测与奖励都能安全消费这个哨兵值。（3）取最小 gap：跟车安全只由最近的障碍决定，这是"min 聚合"在交通场景里的自然复现（回忆第 087 章地标覆盖的 min）。（4）顺带返回前车速度：跟车不仅要看距离，还要看前车快慢，同样是 0.03 的间距，前车 0.2 与 0.05，策略的最优反应完全不同。（5）用不取模的差值，位置回绕时"刚超过我的车"会被误判成远处来车，这类 bug 只在高密度下偶发，很难查，所以每个环线间距都必须走这一个函数。

片段 2：9 维局部观测的构造

def _obs(self) -> np.ndarray:
    obs = []
    for i in range(self.n_cars):
        other = 1 - self.lane[i]                       # 另一条车道
        fg, fv = self._gap_ahead(i, self.lane[i])      # 本道前车：间距 + 速度
        og, ov = self._gap_ahead(i, other)             # 邻道前车：判断能不能变过去
        rg = self._gap_behind(i, self.lane[i])         # 本道后车：知道谁在贴我
        lane_onehot = np.zeros(2, dtype=np.float32)
        lane_onehot[self.lane[i]] = 1.0                # 自己在哪条道
        o = np.concatenate([
            [self.v[i] / self.v_max],
            lane_onehot,
            [min(fg, self.gap_cap) / self.gap_cap, fv / self.v_max],
            [min(og, self.gap_cap) / self.gap_cap, ov / self.v_max],
            [min(rg, self.gap_cap) / self.gap_cap],
            [0.0],                                     # 预留位：留给后续实验扩展
        ])
        obs.append(o.astype(np.float32))
    return np.stack(obs)

解读：9 维观测是"够用就好"的典范。（1）前车信息分两条：本道前车（决定我能不能加速）与邻道前车（决定我值不值得变道），变道决策的全部依据就是后者，这也是"变道被拒"机制留给策略的线索。（2）后车间距进观测：被追尾的风险属于自己，策略需要知道"后面贴了多近"，否则永远学不会"被贴时别急刹"。（3）间距截断到 gap_cap=0.3 再归一化：环上距离超过 0.3 就算"很远"，截断避免远距离噪声稀释有效信息，也让输入尺度与速度项一致。（4）速度除以 v_max=0.2、间距除以 0.3，所有输入都在 [0,1] 附近，离散 PPO 的输入尺度纪律和前面章节一致。（5）最后预留的恒 0 维：保持观测维度为 9 是为了记忆方便，同时给"变道中标记"之类的扩展留了口子；真正起作用的是前 8 维，这份诚实比凑数维度更有价值。

片段 3：变道判定，让"横向动作"有条件生效

accel_idx = actions // 3          # 0,1,2 -> 对应 -1,0,+1 档加速度
lane_pref = actions % 3 - 1       # -1,0,+1：向左/保持/向右
self.steps += 1

# 1) 变道：目标车道在当前位置附近（±0.03）有车则婉拒
changed = np.zeros(self.n_cars, dtype=bool)
for i in range(self.n_cars):
    if lane_pref[i] == 0:
        continue                                   # 不换道：跳过
    target = int(np.clip(self.lane[i] + lane_pref[i], 0, 1))
    if target == self.lane[i]:
        continue                                   # 已在边界车道，向外变无效
    blocked = False
    for j in range(self.n_cars):
        if j == i or self.lane[j] != target:
            continue
        d = min((self.pos[j] - self.pos[i]) % 1.0,
                (self.pos[i] - self.pos[j]) % 1.0)  # 环形双向距离：前后都要查
        if d < 0.03:
            blocked = True                         # 目标车道附近有车：拒绝变道
            break
    if not blocked:
        self.lane[i] = target
        changed[i] = True

解读：动作解码与变道安全是两个必须分开理解的层次。（1）解码用整数除法与取模：actions//3 得纵向档、actions%3−1 得横向偏好，9 个动作与 (纵向,横向) 一一对应，不需要查表。（2）变道只检查"目标车道 ±0.03 内是否有车"，前后都要查（min 两个方向的环形距离）：真实驾驶里变道既要看盲区（后方）也要看前方。（3）被拒的变道不报错、不惩罚：车留在原车道，横向动作静默失效，策略只能通过观测（邻道间距）学会预测何时会被拒。（4）边界车道向外变道（target == self.lane[i]）直接跳过：动作合法但语义无效，不需要拒绝逻辑。（5）变道在纵向更新之前处理：判断用的是当前时刻的车辆位置，避免"同一帧内先变道的人改变间距、后变道的人按旧间距判断"的顺序歧义，多智能体环境的动作结算"要么同时、要么有明确顺序"，这里是后者。

片段 4：纵向动力学与奖励结算

# 2) 纵向动力学：速度在 [v_min, v_max] 内加减，位置环形推进
dv = (accel_idx - 1).astype(np.float32) * self.dv     # 档位 -1/0/+1 → −0.02/0/+0.02
self.v = np.clip(self.v + dv, self.v_min, self.v_max)
self.pos = (self.pos + self.v) % 1.0                  # 位置即位移：速度直接累加

# 3) 奖励：速度收益 + 安全罚款（逐车、逐项结算）
rewards = 5.0 * self.v.copy()
for i in range(self.n_cars):
    fg, _ = self._gap_ahead(i, self.lane[i])
    if fg < self.safe_gap:                            # 跟车过近：警告圈
        rewards[i] -= 2.0
    if fg < self.crash_gap:                           # 进入碰撞圈：重罚并计数
        rewards[i] -= 4.0
        self.collisions += 1
    if changed[i]:                                    # 变道生效：摩擦成本
        rewards[i] -= 0.1

解读：这是"效率与安全"在同一步里被定价的地方。（1）纵向动力学两行：速度被限制在 [0.02, 0.2]，低于最低速也不行，现实里车不能停死（环线没有红灯）；位置推进 (pos+v)%1 里速度就是每步位移。（2）奖励先给所有人发速度分，再逐车扣安全账：5.0·v 的量级（0.1～1.0）明显大于变道成本（0.1），小于碰撞重罚（4.0），三档量级对应三种优先级。（3）两级阈值可以同时触发（间距 < 0.015 时两项都扣）：越危险罚得越狠，形成连续的惩罚梯度。（4）collisions 是回合内的累计计数器，随每局 reset 清零，用于统计"每局碰撞次数"；训练中段探索导致的零星碰撞是正常的，最终评估必须压到 0。（5）注意"撞了不终止"：环线没有自然终局，碰撞只是持续负奖励。如果一撞就 reset，策略会学到"反正重开"的短视投机，真实事故的代价必须大于换一局的便宜。

常见坑

  • 环形间距用不取模的差值：环上"前面的车"可能位于坐标另一端。不取模时位置回绕会让策略把"刚超过我的车"误判成远处来车，且只在高密度下偶发、极难排查。
  • 变道拒绝对动作空间形成"死区"：若观测缺邻道间距信号，策略无法学会"先等空位再变道"，会白占大量样本；本实现把 og, ov 放进观测就是为了堵这个洞。
  • 把碰撞当"回合结束"处理：环线没有自然终局，碰撞应只是持续负奖励；一撞就 reset 会让车学会"反正重开"，扭曲安全行为。
  • 只调速度奖励不调罚款：把速度系数从 5 提到 20，单步罚款相对变小，策略立刻"油门焊死"。奖励是一个整体尺度，改任何一项都要检查其余项的量级。
  • 变道判定用单向距离：目标车道只查前方不查后方（或反之），会让策略贴脸变道而系统不拒绝，随后碰撞，真实的变道安全检查必须双向。

    提示
    罚款过重时策略保持巨大车距，平均速度反而下降。观察"安全"与"效率"的跷跷板如何在数字上表现。
  3. 把碰撞罚款拆成"给后车 −4、给前车 −1"，先分析被追尾车的行为应如何改变，再观察它是否学会"向后看"。★★
    提示
    在 step 的 fg < crash_gap 分支里给前车也加一份小罚款。后视信息已在观测里，这个实验检验"责任分担是否改变行为"。
  4. 把匀速基线换成"激进基线"（所有车恒速 0.2），先预测它的碰撞与速度，再讨论"什么才是合理的对照"。★★
    提示
    初始速度改 0.2、基线动作恒为纵向 +1。激进基线速度虽高但碰撞爆表，它让你直观看到"没有安全的效率"没有意义。
  5. 给环境加"上下匝道"：每隔 50 步插入一辆低速新车（0.06），先设计"如何在不改车辆数的前提下模拟进出流"，再观察策略的恢复能力。★★★
    提示
    动态增删会改变 n_agents，最省事的做法是维持 6 辆、让某辆"离线"一段时间再以低速回归；统计回归后多少步速度恢复到旧水平。

小结

  • 环形公路把自动驾驶简化成"跟车 + 变道"：环形间距（取模）、速度档位、两级安全阈值是该场景的最小要素。
  • 9 元离散动作（纵向×横向）让 PPO 直接处理变道决策；"变道被拒"机制要求策略具备邻道感知。
  • 奖励把速度收益与安全成本写在一起：稳定保持间距优于反复贴车，变道成本抑制抖动；碰撞不终止而持续罚。
  • 评估三指标（速度、碰撞、变道次数）缺一不可；匀速基线把"提升多少"变成可计量的数字。
