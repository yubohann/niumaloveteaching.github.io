第二篇 · 离策略方法与 SAC

第 055 章：SAC的多任务学习

让一个 SAC 同时服务三个重力参数不同（g = 8 / 12 / 16）的摆杆：把任务 one-hot 拼进观测，训练时按任务轮流采样。与"每任务一个专用策略"在相同总步数下对比回报与参数量，并用"错误任务标识"检验策略是否真的在用任务信息。

  • 主题：多任务学习 / 任务条件（task conditioning）
  • 关键公式：s̃ = [s ; et]；敏感性 = J(π,t,et) − J(π,t,et′)
  • 预计学时：55 分钟
  • 前置章节：第 054 章

学习目标

  • 理解多任务学习的两种基本形态：共享参数 + 任务条件与每任务专用网络。
  • 实现任务 one-hot 观测拼接、按任务轮换的训练循环，以及同一策略在多任务间的评估。
  • 用"参数量"与"每任务回报"两个维度对比 multi 与 single，理解容量与效率的交换。
  • 学会用"任务标识敏感性"诊断策略是否真正利用了任务条件；读数贴零，意味着策略把任务平均成了折中策略。
  • 会分析共享容量的边界：任务数增加、任务冲突加剧时，multi 的偏科从哪来。

背景与动机

现实系统很少只服务一个任务：同一个机械臂要抓不同形状的物体、同一套控制策略要适配不同的负载与摩擦系数。为每个任务训练一个策略意味着参数量与维护成本随任务数线性增长；多任务学习的诱饵是一套网络服务所有任务，共享的特征提取器让数据与计算复用，任务间还能互相正则化。

但"共享"不是免费的午餐：网络容量被摊薄，任务之间的梯度可能互相拉扯。本章用三个重力不同的摆杆把这种取舍量化：参数量省了多少、每个任务损失了多少、任务条件到底有没有被网络用起来，第三个问题用"错误标识"实验回答。

核心原理

1. 任务条件的数学形式

把任务 t 的观测扩展为：

s̃ = [ s ; et ]，其中 et ∈ {0,1}n 是任务 t 的 one-hot 向量
πθ(a | s̃)  →  Qθ(s̃, a)（策略与 Q 网络共享同一种条件方式）

符号说明：s 是原始观测（Pendulum 为 3 维），et 是长度为 n 的任务标识向量，s̃ 是拼接后的输入。one-hot 只增加 n 个输入维度，网络其余结构不变。训练数据按任务轮换产生：回放池里混合了所有任务的 transition，策略必须从 et 推断"现在是哪个动力学"。需要强调的是 Q 网络也必须条件化：如果只有策略吃 one-hot、Q 仍按无标识输入训练，同一条状态在三个任务下对应三个不同的真实价值，而 Q 只能给出一个折中预测，价值回归的残差永远消不掉，策略拿到的梯度方向也会被平均掉。条件信息必须对策略与评论家对称提供，这一点与第 047 章"归一化要两边同步加"的道理相同。

2. 共享与专用的取舍

设单个策略参数量为 P，任务数为 n。专用方案总参数 n·P，共享方案约 P（只多了输入维度）。在数据侧，共享方案把同一份网络容量摊到 n 个任务的数据上：

每个任务可用数据量：multi 与 single 相同（都占约 1/n 预算）
每个任务的可用容量：multi ≈ P/n（且受任务间干扰影响），single = P multi 的回报通常略低于 single，但总参数少约 n 倍，这就是它的价值所在

任务越相似，multi 与 single 的差距越小；任务差异越大（例如把摆杆和到达目标混在一起），共享的代价越大。本章三个任务的 g 只差 2 倍以内，属于"高相似度"情形，适合共享。

数值例子：一套网络到底省了多少参数

网络配置：策略与双 Q 三个网络，各自带两层 256 宽隐藏层；策略头（均值 + log_std）与双 Q 各接一个标量输出。先算单任务（观测 3 维）：

策略网络：躯干 3×256+256 = 1024 与 256×256+256 = 65792，两个头各 257，小计 67330；每个 Q 网络：躯干 4×256+256 = 1280 与 65792，输出 257，小计 67329。一组（策略 + 双 Q）合计 67330 + 2×67329 = 201988 ≈ 20.2 万参数。

三套 single 共约 60.6 万参数。multi 的观测是 3+3 = 6 维：三个网络各自的第一层各多出 3 个输入维度，合计多 3×768 = 2304 个参数；其余结构完全相同，一组约 20.4 万参数。

解读：multi 用约 20.4/60.6 ≈ 1/3 的参数量覆盖三个任务，代价是每个任务被摊到的容量约为单任务方案的 1/3，且还受任务间梯度干扰。one-hot 的开销可以忽略（三个网络的首层共多 2304 个参数），真正的取舍是"共享主干是否够表达三个任务"。任务相似度越高，这个"1/3 容量"越够用，本章的结论（multi 略逊但接近）正建立在此。

3. 任务标识敏感性

若策略学成了任务无关的折中策略，把 one-hot 换成错误标识对性能影响很小；反之，性能会明显下滑。定义：

敏感性 = J(π, t, et) − J(π, t, et′)，其中 t′ ≠ t 正值越大，说明策略的行为越依赖任务标识

它是诊断"多任务到底有没有发生"的最便宜手段：不需要额外训练，只需在评估时喂错的 one-hot。注意它只证明"条件被使用"，不证明"条件用得好"，最终还是要看每任务回报。把两种方案的预期读数整理成对照表：

维度multi（共享 + 任务条件）single（每任务专用）
参数量（三任务）约 20.4 万（一组）约 60.6 万（三组）
每任务回报略低，差距约 10～40 分基准，每任务最高
任务标识敏感性200～400 分，条件被真正使用不适用（无任务条件）
偏科风险有，最难任务（g=16）最先掉队无，各任务独立
维护成本一个模型、一条训练管线模型与管线随任务数线性增长

读表的方法：先核对参数量（确认 one-hot 只增加极少开销），再看"每任务回报"的偏科分布，最后用敏感性确认条件机制生效。若敏感性接近 0 而回报尚可，说明网络学成了任务无关的折中策略，检查 one-hot 是否随数据入池。

实现思路与设计

数据流

multi 模式：三个任务依次各训练 6000 步（总预算 18000），每个任务训练段开始时先执行 1000 步随机预热。观测在环境交互层拼接 one-hot，拼接后的 obs_in 与 next_in 一起入池；更新从混合池里采样。训练结束后对每个任务评估两次：正确标识与错误标识，差值就是敏感性。single 模式：每个任务一个独立策略（观测 3 维、无 one-hot），用相同的任务环境种子与每任务步数。最后汇总对比回报、参数量与敏感性。

模块划分

组件职责关键点
onehot(i, n)生成任务标识拼到观测时训练与评估必须用同一个函数
train_multi单策略、按任务轮换训练每个任务连续训练 1/n 预算；回放池混合全部任务数据
train_single_task每任务独立策略与 multi 使用相同的环境种子与每任务步数
eval_on_task支持 one-hot 覆盖的评估override_id 把任务标识换成错误值，测敏感性
汇总表每任务回报、参数量、标识敏感性multi 参数量与 single×n 的对比是结论核心

关键超参数

参数默认值作用与取值理由
--gs8,12,16任务的重力集合；三个任务覆盖"易-中-难"，但动力学结构一致
--max-steps18000总预算；multi 与 single 各任务均分相同的 6000 步
--start-steps1000随机探索步数；multi 中每个任务训练段开始时生效
--eval-episodes5每任务评估回合数；敏感性实验会再跑一轮错标识评估
--buffer-size100000远大于总步数，保证早任务样本不被覆盖

任务轮换的顺序也有讲究。本章按 g=8 → 12 → 16 的"由易到难"顺序各训练 6000 步，这个安排的优点是每个新任务开始前，网络已经积累了相似结构的经验；缺点是最后训练的任务（g=16）在回放池里"最新鲜"，早任务（g=8）的样本被采样到的概率虽与容量无关，但策略参数最近更多被 g=16 的梯度塑造。若把顺序倒过来（16 → 12 → 8），预期 g=8 的表现会变好、g=16 略差，平均分接近。练习 2 的"每回合随机抽任务"则消除顺序效应：任务分布在整个训练期均匀，偏科程度通常更小，代价是每回合都要重置环境、任务切换更频繁。

与前一章的差异点

  • 第 054 章是"顺序迁移"（源 → 目标一次）；本章是同时训练多个任务、一套参数。
  • 观测从 3 维扩展到 6 维（状态 + one-hot），Q 网络与策略同步扩展。
  • 评估新增 override_id 机制与任务标识敏感性指标。
  • 汇总表从"两模式对比"变成"多任务×多方案矩阵 + 参数量核算"。

关键代码与解读

片段 1：任务条件拼接在交互层完成

def onehot(i: int, n: int) -> np.ndarray:
    v = np.zeros(n, dtype=np.float32)
    v[i] = 1.0
    return v


def train_multi(gs, args):
    set_seed(args.seed)
    n_tasks = len(gs)
    envs = [make_pendulum(args.seed + 11 * i, g) for i, g in enumerate(gs)]
    eval_envs = [make_pendulum(args.seed + 100 + 11 * i, g) for i, g in enumerate(gs)]
    obs_dim = envs[0].observation_space.shape[0] + n_tasks  # 状态 + one-hot
    act_dim = envs[0].action_space.shape[0]
    action_scale = float(envs[0].action_space.high[0])
    agent = SAC(obs_dim, act_dim, action_scale, args)
    buffer = ReplayBuffer(args.buffer_size, obs_dim, act_dim)

    steps_per_task = args.max_steps // n_tasks
    for task_i, (g, env) in enumerate(zip(gs, envs)):
        obs, _ = env.reset()
        ep_ret = 0.0
        ep_returns = []
        for step in range(1, steps_per_task + 1):
            obs_in = np.concatenate([np.asarray(obs, dtype=np.float32),
                                     onehot(task_i, n_tasks)])
            if step <= args.start_steps:
                action = env.action_space.sample()
            else:
                action = agent.act(obs_in, deterministic=False)
            next_obs, rew, terminated, truncated, _ = env.step(action)
            next_in = np.concatenate([np.asarray(next_obs, dtype=np.float32),
                                      onehot(task_i, n_tasks)])
            buffer.add(obs_in, action, rew, next_in, float(terminated))

解读：（1）拼接发生在环境交互层：输入网络的 obs_in 与存进回放池的 next_in 都带 one-hot，网络内部完全不用知道"任务"这个概念。（2）Q 网络的输入维度跟着 obs_dim + n_tasks 扩展，策略网络同理，两处必须同步，否则 update 里的 bootstrap 会算错。（3）同一个回合内任务标识不变，obs_in 与 next_in 用同一个 task_i：若 next 用了别的任务标识，Q 的目标值会跨任务污染，这是本实验最隐蔽的 bug。（4）回放池混合三个任务的数据：因为观测里带 one-hot，网络可以区分动力学，Q 回归不会混淆；容量 10 万远大于 1.8 万总步数，早任务样本不会被覆盖。若容量不足，最后一轮实际只练最后一个任务（症状：g=16 好、g=8 崩）。

片段 2：eval_on_task，正确标识与错误标识的分叉

@torch.no_grad()
def eval_on_task(agent: SAC, env, task_id, n_tasks: int, episodes: int,
                 override_id=None) -> float:
    """在指定任务上评估；override_id 可以把 one-hot 换成错误任务标识。"""
    returns = []
    for _ in range(episodes):
        obs, _ = env.reset()
        done = False
        ep_ret = 0.0
        while not done:
            if task_id is None:
                obs_in = np.asarray(obs, dtype=np.float32)   # single 模式：无 one-hot
            else:
                tid = task_id if override_id is None else override_id
                obs_in = np.concatenate([np.asarray(obs, dtype=np.float32),
                                         onehot(tid, n_tasks)])
            action = agent.act(obs_in, deterministic=True)
            obs, rew, terminated, truncated, _ = env.step(action)
            ep_ret += rew
            done = terminated or truncated
        returns.append(ep_ret)
    return float(np.mean(returns))

    # train_multi 里对每个任务评估两次：
    for task_i, (g, env) in enumerate(zip(gs, eval_envs)):
        ret = eval_on_task(agent, env, task_i, n_tasks, args.eval_episodes)
        ret_wrong = eval_on_task(agent, env, task_i, n_tasks, args.eval_episodes,
                                 override_id=(task_i + 1) % n_tasks)
        print(f"[multi] 评估任务 g={g}：正确标识 {ret:8.1f} | "
              f"错误标识 {ret_wrong:8.1f} | 差值 {ret - ret_wrong:+7.1f}")

解读：（1）task_id is None 分支让 single 模式复用同一个评估函数（无 one-hot 输入），两种方案的评估协议因此完全一致，不会出现"给 multi 和 single 喂不同维度输入还强行比较"的口径错误。（2）override_id 只改标识、不改环境：同一个 g 的摆杆上看"标签说错话"的后果。（3）错标识取 (task_i + 1) % n_tasks：相邻难度的任务（g 差 4）比极端错配更能暴露问题，如果网络连相邻任务都分不清，说明任务条件几乎无效。（4）评估用确定性策略（deterministic=True），敏感性差值不是采样噪声。

片段 3：参数量核算与最终对比

    def n_params(self) -> int:
        total = sum(p.numel() for p in self.policy.parameters())
        total += sum(p.numel() for p in self.q1.parameters())
        total += sum(p.numel() for p in self.q2.parameters())
        return int(total)

    # main 里的汇总：
    print("多任务 vs 单任务（每任务评估回报，越高越好）")
    print(f"{'任务(g)':>9}{'multi':>10}{'single':>10}{'差值(m-s)':>11}")
    for i, g in enumerate(gs):
        print(f"{g:>9.0f}{multi['per_task'][i]:>10.1f}{singles[i]:>10.1f}"
              f"{multi['per_task'][i] - singles[i]:>11.1f}")
    print(f"{'平均':>9}{np.mean(multi['per_task']):>10.1f}{np.mean(singles):>10.1f}"
          f"{np.mean(multi['per_task']) - np.mean(singles):>11.1f}")
    print(f"参数量：multi {multi['params']}（1 套网络） vs single {single_params * n_tasks}"
          f"（{n_tasks} 套网络，每套 {single_params}）")

解读：（1）n_params 只统计策略与双 Q（不含目标网络副本与优化器状态）：这是"部署时要保存的参数量"口径，也是 multi 与 single 对比的公平基准。（2）汇总表先列每任务、再列均值：multi 的弱点通常集中在最难任务（g=16），均值会掩盖偏科，所以两个层次都要看。（3）参数量对比的呈现方式（1 套 vs n 套）比相对数字更直观：multi 用约 1/3 的参数达到接近的回报，这就是本章的核心结论。（4）敏感性数值单独一行打印，它是"任务条件被使用"的证据，和回报表互为补充。

预期：single 在每个任务上略优（差距 10～40 分），multi 用约 1/3 的参数量把平均回报做到接近；任务标识敏感性一律为正（200～400 分），说明 one-hot 被真正使用，策略不是折中。三个任务里 g=16 最难、回报最低。不同种子下 multi 与 single 的差距在 ±30 分内波动，但"multi 略逊、参数大省"的结论稳定。以实跑为准。

常见坑

  • 训练时拼 one-hot、评估时忘拼：输入维度对不上会直接报错；如果凑巧维度兼容（形状凑出来了），会得到毫无意义的低分。两处必须走同一个拼接函数。
  • next_obs 拼接用了错误的任务标识：任务标识在一个回合内不变，但实现时要确保 obs_in 与 next_in 用同一任务的标识，否则 Q 的目标值跨任务污染。
  • 把 multi 的经验存成 3 维观测：任务信息丢失后网络无法区分动力学，训练退化成"折中策略"，敏感性实验也会失效。任务上下文必须随数据一起入池。
  • 评估口径不一致：multi 与 single 必须用相同的环境种子、相同的评估回合数与确定性策略；single 的策略不需要 one-hot，别给两者喂不同维度的输入还强行比较。

练习与思考

  1. 把 --gs 改成五个任务 6,8,10,12,16，每任务步数降到 3600。multi 的偏科（最难任务）会加剧吗？★
    提示
    任务越多，共享容量摊得越薄。观察 g=16 的 multi 与 single 回报差距是否随任务数扩大，以及平均分的下降幅度。
  2. 把训练轮换改成"每个回合随机选任务"（替换按任务顺序跑完的做法），重跑 multi。它与顺序版有什么差别？★★
    提示
    随机切换让回放池里的任务分布更均匀，不易被最后一个任务主导。改动集中在 train_multi 的循环结构，按总步数循环、每回合开始抽任务。
  3. 先预测再验证：给 multi 增加第 4 个"困难"任务 g=20，原有三个任务的回报会升还是降？★★
    提示
    困难任务会产生高 TD 误差样本，可能干扰其他任务的价值学习（负迁移）；但也可能充当正则。对比加任务前后 g=8/12/16 的 multi 回报。
  4. 实现"任务嵌入"替代 one-hot：用 nn.Embedding(3, 8) 把任务 ID 映射成 8 维向量再拼接。比较参数量与回报。★★★
    提示
    需要把任务 ID 也存进回放池（或用 argmax 从 one-hot 反推）。嵌入更紧凑，但训练初期嵌入未收敛时任务条件更弱，观察早期评估点的差别。
  5. 做一次"完全敏感性"实验：对每个任务测试全部三个 one-hot 取值（9 组评估），画出 3×3 的回报矩阵。对角线与非对角线的差距如何？★★★
    提示
    把 eval_on_task 的 override_id 循环使用即可，评估预算加 3 倍但每次只要 3 回合。矩阵形式最直观：对角线是正确标识，非对角线是错配。

小结

  • 多任务学习用一套共享参数服务多个任务，核心机制是任务条件（one-hot/嵌入）让网络在共享主干上切换行为模式，避免为每个任务复制整套网络。
  • 本章实现中 one-hot 拼在观测层、随数据存进回放池；训练按任务轮换，评估对每个任务独立进行，策略与评论家的条件输入保持对称。
  • 对比结果：multi 略逊于 single（差距约 10～40 分），但参数量约为 1/3；任务标识敏感性 200～400 分，证明任务条件被真正使用。
  • 任务相似度越高、共享越划算；任务冲突越大，越需要"专用头"或梯度手术等更复杂的结构（留作后续练习方向）。
  • 参数量的账：单任务一组（策略 + 双 Q）约 20.2 万参数，三套约 60.6 万；multi 一组约 20.4 万（one-hot 让三个网络的首层共多 2304 个参数），用约 1/3 的参数覆盖三个任务。
  • 敏感性读数的典型量级是 200～400 分：正确标识与相邻任务标识的评估差。它接近 0 时应优先检查 one-hot 是否随数据入池；网络容量属于最后才排查的嫌疑项。
  • 下一章把"多任务"推向"快速适应"：元学习，用一组任务的训练经验换一个"几步微调就能上手新任务"的初始参数。
