第 064 章：PPO与SAC的稳定性对比

一次跑得好不算好。换四个随机种子重新训练，看看 PPO 和 SAC 谁的成绩单更整齐：跨种子标准差、曲线波动、最大回撤、崩溃点，把"稳不稳"变成四个可测的数字。

  • 主题：多种子重复实验 / 稳定性量化
  • 关键公式：最大回撤 = maxt[maxk≤tRk − Rt]；崩溃点 = 低于历史最佳 Δ 的评估次数
  • 预计学时：50 分钟
  • 前置章节：第 063 章

学习目标

  • 理解"稳定性"在强化学习里的两层含义：跨种子方差（换环境会不会重来）与单次运行内的曲线抖动（会不会冲高回落）。
  • 掌握四个可量化指标：跨种子标准差、曲线波动率、最大回撤、崩溃点计数，以及各自的适用场景。
  • 看懂多种子实验框架：为什么要把训练封装成"一次运行"，种子需要同时对齐哪三处随机源。
  • 从算法机制上解释 SAC 更稳（目标网络、双 Q、熵最大化、每步小更新）与 PPO 波动更大（on-policy 耦合、批量总步长不受限）的原因。
  • 学会用 min-max 区间图展示种子分散度，并识别"评估噪声"与"训练不稳定"的区别。

背景与动机

你大概见过这样的场面：论文里 PPO 在某个环境上曲线漂亮，你照着实现跑一遍，第一次还行，换一个随机种子直接崩盘，再换一个又卡在低分不动。这并不说明你写错了：单次实验的结论本来就不可靠。强化学习的随机性来自四个地方：环境初始状态、动作采样、网络初始化、小批量打乱顺序。只跑一次，你看到的是"这一个种子的运气"，不是算法属性。

稳定性还有另一层含义：就算最终分数一样，一条平稳爬升的曲线和一条"冲到高点又摔下来"的曲线，工程价值完全不同。机器人训练中途崩溃、线上模型回退，代价都极高。上一章只跑了单个种子，这一章把每个算法在 4 个种子上重复训练，把两种不稳定都变成数字：前者用跨种子标准差，后者用波动率、最大回撤和崩溃点。

核心原理

1. 为什么 off-policy 的 SAC 更稳

SAC 有四个"减震器"。① 目标网络：把 Bellman 目标从"移动的靶子"变成慢速移动的靶子，软更新系数 τ=0.005 意味着目标网络每步只向在线网络移动 0.5%，价值回归的目标短期内几乎不动。② 双 Q 取最小：抑制过估计，避免价值被虚高带飞。③ 熵最大化：策略不会突然塌缩成确定性动作，探索强度由自动温度平滑调节。④ 每环境步一次小批量更新（批量 256，一个样本平均只被更新几次），参数单步移动幅度有界。

把四个机制放在一起看：SAC 的每步更新都发生在大批量、慢目标、有熵约束的条件下，单步扰动小、连续多步之间相关性强，曲线自然不容易大起大落。这也解释了为什么它敢"一边收集数据一边更新"，稳定性是设计出来的，不是运气。

2. 为什么 PPO 的方差更大

PPO 的更新幅度由优势估计的尺度（随批次变化）与新旧策略比率共同决定。裁剪看起来是保险丝，但请注意它限制的是什么：

Δθ ∝ 𝔼[ ∇θ rt(θ)Ât ]，clip 只在单个样本上截断梯度，不限制批量平均后的总步长 rt 是重要性采样比率；Ât 是优势；一个 minibatch 里所有样本同向时，裁剪挡不住合力的累积

一批数据里如果优势同号且较大（训练早期常见），10 个 epoch 的连续更新会把策略推得很远；log_std 是被共享梯度优化出来的参数，熵和回报的拉锯可能让它在中途突然变化，探索强度随之跳变。再叠加环境重置带来的分布切换（每次重置观测分布剧变，奖励尺度也跟着变），PPO 更容易出现两种不稳定：种子之间的分化（某个种子冲到高分、某个卡死）与曲线上的锯齿与回撤。

3. 四个稳定性指标的定义

波动率 = std( 后半程各次评估回报 )
最大回撤 = maxt[ maxk≤t Rk − Rt ]
崩溃点 = 评估回报低于"历史最佳 − Δ"的次数（Δ 默认 150 分） Rt 是第 t 次评估的平均回报；跨种子标准差是对"各次运行最后三次评估均值"求 std

解读口径很重要。波动率只统计后半程：前期的爬升属于学习过程的一部分，混进来会把"学得快"误判成"抖得凶"。最大回撤借用金融里的概念：从历史最高点往下的最大落差，刻画"最坏时你会亏掉多少已得成果"。崩溃点用固定差值 150 分：Pendulum 的分数跨度从 −1200 到 −150，固定差比百分比更好解释；它的含义是"有多少个评估点落在深坑里"，冲刺型曲线一次深坑可能贡献多个点。跨种子标准差回答的是另一个问题："敢不敢把这个算法交给别人换个种子重跑？"

4. 为什么固定每个种子的预算

有人喜欢"跑到达标就停"，这会让不同种子消耗的步数不同，稳定性指标失去可比性，你无法判断差异来自算法还是来自运行长度。本章固定每个种子跑满 --max-steps，评估点在相同环境步处对齐，跨种子的曲线才能逐点比较、求均值画区间。

实现思路与设计

模块划分

组件职责关键点
train_ppo_once / train_sac_once单种子完整训练，返回评估曲线把上一章的循环封装成可重复调用的函数，种子内部对齐
within_run_metrics计算波动率、最大回撤、崩溃点一次从左到右扫描完成，避免多次遍历
run_and_report多种子调度与汇总打印逐种子明细 + 汇总表（标准差/最小/达标率）
save_plotmin-max 区间图 + 种子平均曲线灰色细线画每个种子，蓝色粗线画均值

关键超参数

参数默认值作用与取值理由
--seeds / --seed4 / 0种子个数与起始值；4 个是"能看出分化"的下限，8 个以上统计更可靠
--max-steps30000每个种子的环境步预算，固定不随达标提前终止
--eval-every2500每条曲线 12 个评估点，密到回撤指标有意义
--crash-drop150相对历史最佳的回撤阈值，超过记一个崩溃点
--threshold−400达标率参考线，与第 063 章一致
其余算法参数同第 063 章保持与上一章实验的可比性

数据流

每个种子：set_seed → 训练循环（与上一章相同）→ 每 2500 步评估一次 → 得到一条 (环境步, 回报) 曲线。所有种子跑完后：逐种子算 within_run_metrics（运行内指标）→ 收集各次"最后三次评估均值"求跨种子统计 → 打印汇总并画 min-max 区间图。

与第 063 章的差异点

① 单次运行 → 多种子重复：新增跨种子标准差、最小值、达标率；② 新增 within_run_metrics 三个运行内指标；③ 评估点密度提高（每 2500 步一次），让回撤与崩溃点可测；④ min-max 区间图直观显示种子分散度。下一章沿用这套框架扫描学习率。

关键代码与解读

片段 1：把训练封装成"一次运行"

def train_ppo_once(seed, args, device):
    """训练一次 PPO，返回（评估曲线, 用时）。"""
    set_seed(seed)                       # 一份种子同时决定：网络初始化 + 小批量顺序
    env = gym.make("Pendulum-v1")
    eval_env = gym.make("Pendulum-v1")
    obs, _ = env.reset(seed=seed)        # 环境初始状态也用同一粒种子，三处随机源对齐
    net = PPOActorCritic(env.observation_space.shape[0], env.action_space.shape[0],
                         args.hidden).to(device)
    optimizer = torch.optim.Adam(net.parameters(), lr=args.lr)
    obs_buf, act_buf, logp_buf, rew_buf, val_buf, cut_buf = [], [], [], [], [], []
    curve = []
    total_steps = 0
    next_eval = args.eval_every
    t0 = time.time()

解读：多种子实验的最小单元是"一次完整运行"。set_seed(seed) 统一了 Python 随机数、NumPy 随机数（回放采样）与 PyTorch 初始化；env.reset(seed=seed) 让环境的初始状态序列也由同一粒种子决定。三处随机源对齐后，"换种子"改变的是一整条独立的数据流。若忘了重置环境种子，你会看到超低的跨种子方差，那是在自欺。curve 是 (环境步, 评估回报) 列表，是所有指标的唯一数据源，函数不做任何打印，保持可组合。

片段 2：运行内三指标的一次扫描

def within_run_metrics(curve, crash_drop):
    """单次运行的稳定性指标：波动率、最大回撤、崩溃次数。"""
    rets = [r for _, r in curve]
    half = rets[len(rets) // 2:]              # 只统计后半程：前期爬升不算"不稳"
    volatility = float(np.std(half)) if len(half) > 1 else 0.0
    best_so_far = -np.inf                     # 从左到右维护"历史最佳"
    max_drawdown = 0.0
    crashes = 0
    for r in rets:
        best_so_far = max(best_so_far, r)     # 先更新最佳，再算本轮差距
        max_drawdown = max(max_drawdown, best_so_far - r)
        if r < best_so_far - crash_drop:       # 掉出最佳 150 分即记一次崩溃点
            crashes += 1
    return volatility, max_drawdown, crashes

解读：三个指标一趟循环算完。（1）half 截取后半程：训练前期的爬升是预期行为，纳入波动率会把"学得快"误判成"抖得凶"。（2）回撤用一个前缀最大值维护：best_so_far 单调不减，于是 best_so_far − r 就是"当前距历史最好成绩的落差"，取 max 即最大回撤。这个技巧 O(T) 完成统计，不需要回溯找历史最高点。（3）崩溃点用固定差值 crash_drop：Pendulum 回报从 −1200 到 −150，用百分比会随基线漂移，固定差更好解释。注意它是"落在深坑里的评估点数"，一个持续多点的低谷会被记多次，这正是你要的：坑越深越久，长期无人敢用。

片段 3：跨种子汇总

for seed in seed_list:                                   # 每个种子独立训练一次
    curve, dt = train_once(seed, args, device)
    curves.append(curve)
    time_sum += dt
    final = float(np.mean([r for _, r in curve[-3:]]))   # 最后三次评估取均值，抗评估噪声
    vol, dd, cr = within_run_metrics(curve, args.crash_drop)
    finals.append(final)
    vols.append(vol)
    dds.append(dd)
    crash_list.append(cr)

finals = np.array(finals)
print(f"  最终性能: 均值 {finals.mean():8.1f} | 标准差 {finals.std():7.1f} | "
      f"最小 {finals.min():8.1f} | 最大 {finals.max():8.1f}")
print(f"  达标率(≥{args.threshold:.0f}): {np.mean(finals >= args.threshold) * 100:.0f}% | "
      f"平均曲线波动率 {np.mean(vols):6.1f} | 平均最大回撤 {np.mean(dds):6.1f} | "
      f"崩溃点合计 {int(np.sum(crash_list))}")

解读：汇总表里每个数字回答不同的问题。（1）final 用最后三次评估的均值：单次评估带 ±100 分噪声，平均三次更稳，也是"最终性能"的常用口径。（2）finals.std() 是跨种子标准差，本章最重要的指标，它不关心均值高低，只回答"各次运行的结局散不散"。（3）同时打印 min 与达标率：标准差小但最小值差，说明"整体偏下但一致"；标准差大而最大值高，说明"有种子中彩票"。（4）运行内指标在种子维度取平均，得到"平均波动率/平均回撤/崩溃点合计"，与跨种子指标互补。

片段 4：min-max 区间图

xs = [s for s, _ in curves[0]]
arr = np.array([[r for _, r in c] for c in curves])   # 行=种子，列=评估点
for i, c in enumerate(curves):
    ax.plot(xs, [r for _, r in c], color="gray", alpha=0.35, linewidth=1,
            label="各次运行" if i == 0 else None)      # 细灰线：每个种子一条
ax.plot(xs, arr.mean(axis=0), color="tab:blue", linewidth=2,
        marker="o", label="种子平均")                  # 粗蓝线：逐点均值
ax.fill_between(xs, arr.min(axis=0), arr.max(axis=0), color="tab:blue", alpha=0.12,
                label="min-max 区间")                  # 阴影：每个评估点的分散范围

解读：区间图比汇总表更直观：arr 的第二维必须与 xs 对齐，这依赖所有种子在同一批环境步上评估（固定预算的又一个理由）。灰色细线保留每个种子的"人格"，有时均值曲线平平无奇，但细线里有种子冲到了 −150，也有种子卡在 −1000，阴影带宽度直接告诉你分化程度。fill_between 画出每个评估点的 min-max 范围：它是"最坏情况"的可视化，工程上比均值更有参考价值。

常见坑

  • 用单种子结论下判断：这是本章存在的全部理由。哪怕换个种子后结论反转也不奇怪，至少 3～4 个种子，最好 8 个以上。
  • 评估回合太少：10 个回合的平均回报仍带约 ±100 分的统计噪声，回撤指标会被评估噪声放大。提高 --eval-episodes 或降低评估频率都行，但不能不处理。
  • 不同种子用了不同预算：跑到达标就停会让各次运行长度不同，跨种子曲线无法逐点对齐。稳定性实验必须固定每个种子的环境步预算。
  • 只对齐 torch 种子、忘了环境种子：set_seed 管不到 gymnasium，env.reset(seed=seed) 需要显式传入。少了这步，换种子时环境轨迹不变，跨种子方差被人为压小。
  • 把达标率与最终性能混着看：预算不足时达标率全是 0，不代表算法差。先确认预算足以让两个算法接近收敛，否则结论要限定在"该预算下"。

练习与思考

  1. 把 --seeds 提高到 8，检查结论是否保持不变。★
    提示
    只看汇总表的标准差、最小值和达标率三行即可。种子越多，标准差的估计越可靠；如果 4 种子的结论与 8 种子相悖，说明 4 个还不够。
  2. 把 PPO 的 --lr 调到 1e-3 再跑一次，观察崩溃点与最大回撤的变化；再把 SAC 的 --lr 也调到 1e-3。预测并验证两者反应是否一样。★
    提示
    这是下一章"超参数敏感性"的预演。SAC 有大批量、目标网络与熵约束兜底，通常对学习率的容忍度更高，重点看崩溃点与最小种子的变化。
  3. 给 PPO 加上"近似 KL 早停"：某个 epoch 的平均 KL 超过阈值就跳出本轮更新。预测稳定性指标会怎么变，再跑实验验证。★★
    提示
    在 epoch 循环里统计 (logp_old − logp).mean()，超过 0.02 就 break。预期：KL 峰值被压平、崩溃点减少，但样本利用率略降。
  4. 把 SAC 的 --tau 分别设为 0.001 与 0.02，比较曲线波动与收敛速度。解释 τ 在"稳定"与"跟踪"之间的取舍。★★
    提示
    τ 小：目标网络更新慢，稳定但可能滞后于在线网络；τ 大：目标追得快，但 Bellman 目标漂移大。关注波动率与最终性能的变化方向是否相反。
  5. 自定义一个"恢复时间"指标：一次回撤后需要多少次评估才能回到回撤前水平；把它加进 within_run_metrics 并比较两种算法。★★★
    提示
    一次扫描即可：当 Rt 低于历史最佳时进入回撤状态，追平历史最佳时记录评估点差；取所有回撤事件的中位数。它衡量的是"摔了能不能爬回来"。

小结

  • 稳定性有两个面：跨种子方差（换环境会不会重来）与运行内抖动（曲线抖不抖、会不会崩）。
  • 四个指标：跨种子标准差、波动率、最大回撤、崩溃点计数；前一个用于种子间比较，后三个用于单次运行。
  • 本章配置下 SAC 通常稳定得多：标准差小几倍、崩溃点接近 0、达标率高；PPO 的分化与回撤都更大。
  • 机制来源：SAC 的目标网络、双 Q、熵最大化与每步小更新把单步扰动关进了盒子；PPO 的裁剪只限制单点梯度，挡不住批量合力和 log_std 漂移。
  • 实验纪律：固定每种子预算、对齐三处随机源（Python/NumPy/PyTorch 与环境）、评估回合要够多。
  • 下一章把"稳定性"换成"敏感性"：同一算法对不同学习率的表现差异有多大，谁对超参数更挑剔。
