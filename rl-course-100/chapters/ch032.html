第二篇 · 离策略方法与 SAC

第 032 章：SAC的自动温度系数调整

把 SAC 里最像"玄学"的超参数 alpha 交给梯度自己学：在 Pendulum-v1 上对比固定温度与自动温度调节，看 alpha 如何随"熵缺口"先升后降。

  • 主题：自动熵调节 / 温度系数
  • 关键公式：L(α) = −𝔼[ log α · ( log π(a|s) + H̄ ) ]，H̄ = −dim(A)
  • 预计学时：50 分钟
  • 前置章节：第 031 章

学习目标

  • 理解温度系数 alpha 在 SAC 目标函数中的角色：它把"探索值多少钱"从一个超参数变成可优化的量。
  • 推导自动温度调节的损失函数，说清 log_alpha 的梯度方向为什么由"熵缺口"决定。
  • 实现固定与自动两种 alpha 模式，共用同一套双 Q、重参数化与软更新代码。
  • 在 Pendulum-v1 上对比两条评估曲线，读出 alpha 轨迹的典型形状（先升后降/稳）。
  • 掌握目标熵 = −动作维度的启发式，并知道它什么时候不适用。

背景与动机

SAC 的目标是"回报加上 α 倍的熵"：策略既要拿高 Q 值，又要保持足够的随机性。alpha 就是这两者的汇率，alpha 偏大，策略不敢收敛，回报上不去；alpha 偏小，策略早早坍缩成一个确定性动作，遇不到更好的轨迹。第 031 章里 alpha 是手写的常数，而 Pendulum 的奖励尺度、回合长度一换，同一个常数就未必合适。

更麻烦的是，训练不同阶段需要的探索强度本来就不同：早期要多探索（策略还差，熵值应该高），后期要精调（策略接近最优，熵值应该降下来）。一个好的自动机制应该让 alpha 随"当前熵离目标熵有多远"实时调整；整场一个常数的做法在奖励尺度变化时就会失效。本章就把这件事实现出来，并用同种子对照实验证明：自动模式几乎不损失性能，却省掉了调参。

核心原理

1. alpha 在损失里的位置

SAC 的策略更新最大化软目标：

J(π) = 𝔼s∼𝒟, a∼π[ Q(s,a) − α·log π(a|s) ] 等价写法：最大化 Q 的同时最大化熵 H(π(·|s))，因为 H = −𝔼[log π]

本章代码里的策略损失是 (alpha * logp - q_new).mean()，正是把上式取了负号。α 越大，同样的熵梯度被放大得越狠，固定 α 时，这个"汇率"只能靠人工试。

2. 把 α 变成可学习参数

直接优化 α 会撞上"熵是策略演化的结果、不是 α 的单调函数"这个问题。SAC 原文的做法是：构造一个关于 log α 的替代损失（surrogate objective），让 α 去弥补"当前熵"与"目标熵"的缺口：

L(α) = −𝔼a∼π[ log α · ( log π(a|s) + H̄ ) ]
其中 log π 的梯度被 detach 掉，H̄ = target_entropy

求导看方向是最直观的：对 log α 求梯度，得到 −( log π + H̄ ) 的均值。把 E[log π] 与 −H̄ 比较即可判断方向：若 E[log π] > −H̄（等价于熵 H = E[−log π] 低于目标 H̄），括号为正、梯度为负，梯度下降抬升 log α（α 增大、探索被加强）；若 E[log π] < −H̄（熵高于目标），α 被压低。平衡条件是 E[log π] = −H̄，即熵 H 收敛到 H̄ = −dim(A)。也就是说，α 永远朝"减少熵缺口"的方向走，缺口越大步子越急，缺口闭合后梯度均值趋近零。α = exp(log α) 保证了非负。

这个替代损失有严格来路，它来自带约束的对偶问题。把 SAC 的目标写成"在保持平均熵不低于 H̄ 的前提下最大化 Q 值"：

maxπ 𝔼[Q(s,a)]　s.t.　𝔼[−log π(a|s)] ≥ H̄
ℒ(π, α) = 𝔼[Q(s,a)] + α · ( 𝔼[−log π(a|s)] − H̄ )，α ≥ 0 固定 α 时对 π 求最大，正好还原出策略损失；外层再对 α 求最小

对偶函数 g(α) = maxπℒ 的梯度由包络定理给出：dg/dα = 𝔼[−log π] − H̄ = H − H̄。而实现里用的替代损失对 log α 的梯度恰好也是 H − H̄（推导：∂[−log α·(log π + H̄)]/∂log α = −(log π + H̄) = H − H̄ 的均值），两者方向与尺度一致，因此可以直接用一波样本的 log π 估计这个梯度，不需要显式求解约束问题。

3. 目标熵怎么定

连续动作的常用启发式是 H̄ = −dim(A)。Pendulum 动作 1 维，H̄ = −1。它的直觉是"每维动作保留约 1 nat 量级的随机性"；这并不保证最优，但在不同环境与奖励尺度上表现稳定。注意 log π 是 tanh 压缩后的对数密度、可以取正值，所以 H̄ 为负并不奇怪。

使用这个启发式时有三个边界要留意。其一，动作维度按"独立控制量"计数：二维动作 H̄ = −2，若两维高度相关（例如机械臂的成对关节），照搬 −2 会让策略偏随机，此时可以适当调高（如 −1.2）。其二，动作尺度被 act_scale 放大时，密度在动作空间的平移不改变熵，因此不需要按尺度换算。其三，奖励尺度变化不影响 H̄ 的定义，这正是自动温度相对固定 α 的优势场景：Pendulum 的奖励在 −16～0 之间，若换到奖励放大十倍的变体，固定 α=0.2 的探索强度相对回报会显得过小，而自动模式的平衡点仍由熵缺口决定。把奖励整体放大 c 倍，软目标 Q+αH 中的 Q 被放大 c 倍，要保持相同的探索权重，α 也近似乘 c；固定 α 若不跟着调整，相对探索强度就缩水到原来的 1/c，第 035 章的奖励尺度实验会把这个比例关系放在两条曲线里直接对照。

数值例子：两次温度更新的方向

设 α=0.2（log α ≈ −1.609）、alpha_lr=3e-4、H̄=−1，观察两次相隔较远的更新：

早期策略很随机，E[−log π] = 2.0，高于目标 −1 → E[log π] = −2.0，E[log π] + H̄ = −3.0。更新量 ≈ 3e-4 × (−3.0) = −9e-4，α ≈ 0.2 × e−0.0009 ≈ 0.1998，方向向下、步子很小。

后期策略过度确定，E[−log π] = −1.5，低于目标 −1 → E[log π] = 1.5，E[log π] + H̄ = 0.5。更新量 ≈ 3e-4 × 0.5 = +1.5e-4，α ≈ 0.20003，方向向上。

解读：单次更新只动约 1e-4 量级，几千次更新后 α 平滑地增减，这就是 alpha 轨迹"先升后降/稳"的微观来源。alpha_lr 越大，追赶缺口越快，也越容易冲过平衡点形成震荡；若观测到 α 在两个评估点之间大幅跳动，优先调小 alpha_lr；改目标熵解决不了震荡问题。

4. 固定与自动的公平对比

两种模式必须只差 alpha 的处理方式：网络结构、双 Q、软更新、经验回放、随机种子全部相同，这样回报差异才能归因到 alpha 机制本身。代码里用同一个 train_mode() 加 --mode 开关实现这个设计；每个模式开头重新 set_seed，连初始回放池的随机轨迹都一致。

5. 温度翻倍需要多少步：一个可算的时间尺度

把更新式写成连续近似，可以估算温度变化的时间尺度。设每一步的熵缺口 g = 𝔼[log π + H̄] 保持不变，n 次更新后 log α 累积变化 n·lr·g（g 为正表示熵低于目标、α 上升），α 变为 α0·en·lr·g。代入 lr=3e-4 得到几组参考数字：g=1.5 时 α 翻倍约需 1540 次更新；g=0.5 时约 4621 次；g=0.1 时约 2.3 万次。课程脚本每 4000 步评估一次，因此只有当早期缺口接近 1 nat 时，第一个评估点附近才能看到 α 明显上探；缺口小的时候曲线看似"没有反应"属于正常现象，与自动调节是否失效无关。反过来核对单步幅度：g=1 时每次更新移动 3e-4，4000 步累计约 1.2 的对数变化，足以让 α 从 0.2 升到 0.66，与"前 4000 步上探到 0.3～0.6"的观测一致。

这段估算还给出两条调参直觉。（1）alpha_lr 放大 10 倍，所有时间尺度等比缩短，超调风险也等比放大：一旦 α 冲过平衡点，缺口符号翻转，下一阶段又朝反方向冲回去，在评估序列上表现为低频震荡。（2）目标熵设置偏离时，缺口永远不闭合，α 会一路漂到极端值；若日志里 α 长期单调爬升而回报没有改善，先核对目标熵的数量级（例如是否把 −1 误设成 2），再检查 alpha_lr 是否过大。

与前一章的差异点

  • 第 031 章的 alpha 是固定常数；本章把 log_alpha 提升为可学习变量，新增 alpha_loss 与独立优化器。
  • 新增 --mode 控制变量框架：同一份训练代码跑两种 alpha 机制，输出可直接对比。
  • 新增诊断量：每次评估时记录 alpha、平均熵、|Q|，用于解释"回报为什么变好/变差"。
  • 主流程从"训练一次"变为"训练两种模式并打印对比汇总"。

诊断三件套：alpha / 熵 / |Q| 怎么读

每次评估记录的三个量拼在一起是一份训练体检报告，单独看任何一个都容易被误导，配成组合才有诊断力：

观察到的组合含义处置
回报停滞、熵高于目标、α 持续下降探索仍过剩，价值还没被压到可收敛的程度训练早期属正常形态；若持续到后半段，检查奖励尺度是否过小
回报停滞、熵低于目标、α 持续上升策略过早确定，Q 估计卡住，温度在尝试补偿探索观察 |Q| 是否同步停滞；必要时提高 alpha_lr 让补偿更快到位
回报改善、|Q| 异常放大自举在放大价值，与温度机制无关转入第 033、042 章的过估计检查（双 Q 与目标网络）
α 在相邻评估点之间大幅跳动alpha_lr 过大，或目标熵与熵读数的量纲不匹配先把 alpha_lr 降一个数量级，再核对目标熵设置

用法可以归纳成一句话：回报决定训练好不好，熵与 α 的配合决定探索预算对不对，|Q| 决定价值估计有没有失控。三者交叉读，才能把归因落到具体组件上，避免笼统地归罪于超参数没调好。

detach 的边界就是"谁在学习"的边界

温度损失里 (logp + target_entropy).detach() 是本章的地基：梯度只流向 log_alpha，策略不会"为了让温度好过"而被扭曲。反过来，策略损失里 logp 必须带梯度（策略靠它调整随机性），而 current_alpha 是标量、天然无梯度。三个损失的梯度归属理清楚了，这套代码就不会出现"两个参数互相带偏"的怪现象。验证方法也简单：在温度损失反向传播后用 log_alpha.grad 打印一次梯度，它应当等于 −(logp + H̄) 的均值，只与熵读数有关。

关键代码与解读

片段 1：alpha 分支，一个参数、两种模式

        # 自动模式下：log_alpha 是可学习参数，用独立优化器更新
        if self.mode == "auto":
            self.log_alpha = torch.tensor(math.log(alpha), requires_grad=True)
            self.alpha_optimizer = torch.optim.Adam([self.log_alpha], lr=alpha_lr)

    @property
    def current_alpha(self) -> float:
        """对外统一暴露当前温度：auto 读 log_alpha，fixed 读常数。"""
        if self.mode == "auto":
            return float(self.log_alpha.exp().item())
        return self.alpha

解读：整个"自动温度"开关就藏在这十行里。（1）参数化用 log_alpha：exp 保证温度恒为正，而参数本身可以在整个实数轴上自由移动（负数、小数都合法），直接优化 alpha 会在接近零处出现"一步跨过负号"的灾难。（2）只给 log_alpha 建了一个单参数优化器：Adam 的动量只影响温度，不与其他网络混淆。（3）current_alpha 作为 property 统一了两种模式对外的接口（fixed 返回常数），于是 TD 目标、策略损失、日志三处都写 agent.current_alpha，不需要任何 if。这是"把差异收进一个角落"的典型写法。

片段 2：温度损失的梯度方向

        # ---------------- 2) 演员：最大化 Q - alpha * log pi ----------------
        new_act, logp = self.policy.sample(obs)
        q_new = torch.min(self.q1(obs, new_act), self.q2(obs, new_act))
        policy_loss = (self.current_alpha * logp - q_new).mean()

        self.policy_optimizer.zero_grad()
        policy_loss.backward()
        self.policy_optimizer.step()

        # ---------------- 3) 温度系数：本章的核心差异 ----------------
        alpha_loss_val = 0.0
        if self.mode == "auto":
            # logp 视为常数（detach），只把 log_alpha 往"熵缺口"方向推：
            # 对 log_alpha 的梯度 = -(logp + H̄) 的均值；熵不足则抬升 α
            alpha_loss = -(self.log_alpha * (logp + self.target_entropy).detach()).mean()
            self.alpha_optimizer.zero_grad()
            alpha_loss.backward()
            self.alpha_optimizer.step()
            alpha_loss_val = float(alpha_loss.item())

解读：两段损失共用同一批前向的 logp，但梯度去向完全不同。（1）策略损失 (α·logp − Q).mean()：logp 带梯度（策略靠它调整分布的随机性），current_alpha 是不带梯度的标量（float），对策略来说它只是一个权重。（2）温度损失里 (logp + H̄) 整体 detach：把策略的当前熵状态当成"观测量"，梯度不会因此流回策略。梯度只剩 −(logp + H̄) 的均值，熵不足（logp 高于 H̄）时梯度为负，Adam 抬升 log α；熵过剩时压低。方向分析在这一行代码里完成闭合。（3）两段损失的顺序不能换：温度用的必须是与策略损失同一批 logp（同一时刻的熵读数），否则读数与决策错位。diagnostics 里的 alpha_loss_val 在 fixed 模式为 0，日志格式不需要分支。

片段 3：评分子系统，采样与雅可比修正

    def sample(self, obs, deterministic=False):
        """返回 (动作, log 概率)。确定性模式下只返回动作与 None。"""
        mean, log_std = self.forward(obs)
        if deterministic:
            return torch.tanh(mean) * self.act_scale, None   # 评估用，无随机性
        std = log_std.exp()
        dist = torch.distributions.Normal(mean, std)
        x = dist.rsample()                      # 重参数化：梯度可穿过采样
        y = torch.tanh(x)
        action = y * self.act_scale
        # tanh 变换后的对数概率，减去雅可比修正项 log(1 - y^2)
        log_prob = dist.log_prob(x) - torch.log(1.0 - y.pow(2) + 1e-6)
        log_prob = log_prob.sum(dim=-1)         # 各动作维度求和成一个标量
        return action, log_prob

解读：sample() 是温度损失的数据源头，三个细节直接决定 alpha 学得对不对。（1）deterministic=True 时返回 tanh(mean)·scale，评估走这条无噪路径，评估曲线才能反映"策略的真实水平"，不受采样噪声干扰。（2）rsample() 让 log_prob 对 μ、σ 可导：温度损失要读它、策略损失也要读它。（3）雅可比项 −log(1 − y² + 1e-6)：tanh 压缩会改变密度的体积，缺了这项，logp + H̄ 的"熵读数"整体失真，温度会朝着错误的目标追。1e-6 防止 y 饱和时 log(0)。

            action = agent.act(obs, deterministic=False)

        next_obs, rew, terminated, truncated, _ = env.step(action)
        buf.add(obs, action, rew, next_obs, float(terminated))   # 只记真终止
        obs = next_obs
        ep_ret += rew

        if terminated or truncated:
            ep_returns.append(ep_ret)
            ep_ret = 0.0
            obs, _ = env.reset()

        if buf.size >= args.batch_size:
            last_stats = agent.update(buf.sample(args.batch_size))  # 每步一次更新

        if step % args.eval_every == 0 or step == args.max_steps:
            eval_ret = evaluate(eval_env, agent, args.eval_episodes)
            history["eval_return"].append(eval_ret)
            history["alpha"].append(agent.current_alpha)   # alpha 轨迹也是产出

解读：fixed 与 auto 共用的主循环，公平对比的载体就在这里。（1）前 start_steps 步纯随机：两种模式看到的是同一批填充数据，alpha 的差异不可能来自"初始经验不同"。（2）buf.add(..., float(terminated)) 再次强调终止语义；Pendulum 的 200 步上限是截断，这些样本照常 bootstrap。（3）agent.update() 内部通过 self.mode 分派行为，循环本身零分支，要做差异实验时，改动被约束在 SACAgent 内部，循环统计口径永远一致。（4）history["alpha"] 每 4000 步记一次 agent.current_alpha：对 auto 而言这是学习出来的轨迹，对 fixed 则是常数参照线，两条线叠在一起，才能看出"自动调节到底干了什么"。

完整可运行脚本（附录）：code/ch032.py

python code/ch032.py           # fixed 与 auto 依次训练：CPU 约 4–8 分钟
python code/ch032.py --quick   # 快速跑通：约 1 分钟
python code/ch032.py --mode auto --max-steps 40000   # 只跑自动模式

以实跑为准：两种模式最终评估都在 −300 ~ −150 附近；auto 的 alpha 轨迹通常先升后降/稳（前 4000 步熵缺口大、α 上探 0.3～0.6，后期回落到 0.2 附近）。--target-entropy 越低，α 稳态越低；一路飙到 2 以上降不下来，多半是目标熵设得过高。

常见坑

  • 忘记 detach 温度损失里的 logp：(logp + target_entropy) 若参与反传，alpha 的梯度会顺着 log_alpha 一路污染策略参数，策略会被"为了让 alpha 好过"而扭曲。修复：必须 .detach()。
  • 直接用 alpha 当参数：直接优化 alpha 无法保证非负，一步更新就可能把它推成负数，熵奖励符号翻转。修复：参数化 alpha = exp(log_alpha)。
  • 把 auto 模式的初值当成"随便"：初值太极端（如 1e-3）时早期熵缺口巨大，log_alpha 需要很多步才爬上来，白白浪费样本。修复：0.1～0.2 起步。
  • 对比实验没有共享种子：固定与自动模式若各自随机初始化，差异里混入初始化噪声，无法归因。修复：每个模式开头重新 set_seed(args.seed)。
  • 策略损失里的 alpha 带了梯度：若用未 detach 的 log_alpha.exp() 乘 logp，策略梯度里会混入温度路径。修复：策略损失用 current_alpha 标量缓存。

练习与思考

  1. 把 --target-entropy 分别改成 -3 和 -0.2，各跑一次 auto 模式。解释 alpha 轨迹与最终熵为什么朝相反方向变化。★
    提示
    目标熵越低，需要保留的随机性越小，alpha 应该越小。只看日志中的 alpha 与熵两列，10 次评估点足够看出方向。
  2. 把 fixed 模式的 --alpha 改成 0.02 和 1.0 各跑一次，找出"太小"和"太大"各自的失败形态（回报卡住 / 熵压不下来）。★
    提示
    alpha=0.02 时策略很早变确定，Pendulum 容易卡在 −800 以上；alpha=1.0 时策略过于随机，Q 学不动。对比评估回报与熵列。
  3. 把 --alpha-lr 从 3e-4 改成 3e-3，观察 alpha 轨迹的抖动。这个实验说明 log_alpha 的学习率主要影响什么？★★
    提示
    学习率大 → alpha 追缺口的步子大 → 轨迹震荡甚至超调。关注相邻两次评估之间 alpha 的变化幅度；终值不是重点。
  4. 修改 update()，在 auto 模式下把 target_entropy 也随训练时间线性降低（例如从 0 降到 −2）。跑训练并解释这与第 041 章"熵系数调度"的关系。★★★
    提示
    在 SACAgent 里加一个 set_target_entropy() 方法，训练循环里按步数比例调用。这里改的是 alpha 追踪的目标，alpha 参数本身不动。
  5. 把评估频率从 4000 步改成 1000 步，画出更密的 alpha 曲线，观察它在两次评估之间是否单调。把曲线与 alpha_loss_val 的符号对照，验证"损失为正时 α 在下降"的推论。★★
    提示
    只改 --eval-every，评估本身耗时很小。alpha_loss 为负意味着 (logp + H̄) 均值为正，即熵低于目标、α 正在被抬升。

小结

  • 自动温度调节把 alpha 从超参数变成可学习量：损失 −log_alpha·(logp + H̄) 的梯度指向"缩小熵缺口"的方向。
  • 关键实现细节有三个：参数用 log_alpha、logp 要 detach、目标熵取负的动作维度。三者缺一，温度就会朝错误方向漂移。
  • 在 Pendulum-v1 上，auto 模式的 alpha 典型轨迹是"先升后稳/降"，最终评估回报与手调的 0.2 相当，但不需要人工搜索。
  • 诊断三件套 alpha / 熵 / |Q| 能解释大多数"回报不动"的原因：熵压不下来看 alpha 上界，Q 学不起来看 alpha 下界。
  • 替代损失的梯度 H − H̄ 与对偶问题的梯度一致，因此"按熵缺口调 α"既有直观解释，也有约束优化的依据；替代损失只是把这个梯度做成了一行可求导的表达式。
