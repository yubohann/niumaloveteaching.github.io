第三篇 · 算法对比与集成

第 063 章：PPO与SAC性能对比

把 PPO 和 SAC 放进同一个 Pendulum 环境，给同样的环境步数预算，用同一套评估协议跑一遍，回答一个朴素但重要的问题：同样的交互量，谁先把回报拉上去。

  • 主题：on-policy 与 off-policy 的样本效率对照
  • 关键公式：数据复用率 R = 更新消耗样本 / 采样总量；PPO 的 LCLIP 与 SAC 的软 Bellman 目标
  • 预计学时：50 分钟
  • 前置章节：第 062 章

学习目标

  • 理解 on-policy 与 off-policy 在数据复用方式上的差异，以及它如何决定样本效率。
  • 掌握"公平对比"的三条纪律：同环境同种子、同环境步预算、同评估协议，并知道缺一条会怎样扭曲结论。
  • 看懂同一脚本里的连续动作 PPO 与 SAC：高斯策略、GAE、裁剪更新、双 Q、自动温度各承担什么角色。
  • 在 Pendulum-v1 上读出两条学习曲线，用"首次达到 −400 分所需步数"量化样本效率。
  • 学会区分样本效率与计算效率：SAC 用更少交互、更多梯度计算换性能，PPO 反之。

背景与动机

训练强化学习智能体，真正的成本往往是环境交互：机器人磨损、用户等待、仿真机时。样本效率因此成为算法选型的核心指标。PPO 与 SAC 是两类学派的代表，PPO 严格 on-policy，每批数据只允许有限次复用，稳定但要不断采新数据；SAC 把数据存进回放池反复使用，把每一份交互榨干。

但"样本效率高"不等于"一定更快"：SAC 每个环境步都做一次梯度更新，单步计算量远高于 PPO。到底怎么选？只能跑一个受控对比，用数字说话。上一章你已经在同一份 SAC 里对齐过在线与离线；这一章把这个方法用在两个不同算法上：两条曲线横轴都是环境步数，网络宽度一致，随机种子一致，评估方法一致。

把变量严格控制之后，曲线差异才能归因给算法本身，排除实现细节、网络容量与运气的干扰。这也让本章成为第三篇的基准：后面的稳定性、超参数敏感性、探索策略对比，都建立在这套实验框架上。

核心原理

1. 数据复用率：两种算法的分水岭

设一次参数更新消耗的样本批量为 B，到当前为止采样总量为 S，则数据复用率 R = 更新次数 × B / S。PPO 的复用率由 epochs 决定：采样 2048 步、训 10 轮，每条数据平均被看 10 次；SAC 每个环境步更新一次，且从容量二十万的回放池里随机采样，同一条旧数据会被反复抽中。可用一句话概括：

RPPO ≈ epochs = 10     RSAC ∝ 池容量 × 更新频率 / 采样速率 ≫ 10 复用率越高，单份样本被"榨"得越干，样本效率越好；但也越容易过拟合旧数据、越依赖对分布偏移的纠正

这条公式解释了本章的核心预期：在交互预算相同的前提下，SAC 因为复用率高，通常能更早把回报拉起来。但复用不是白拿的，旧数据上的价值估计会与当前策略脱节，所以 SAC 才需要双 Q、目标网络、软更新这一整套装置去稳住它；PPO 的"少食多餐"换来的是实现简单与更新稳定。

2. 两种算法各自的目标函数

PPO 直接最大化裁剪替代目标，优势由 GAE 估计：

LCLIP = 𝔼[ min( rtÂt, clip(rt, 1−ε, 1+ε)Ât ) ]，rt = πθ(at|st) / πold(at|st) rt 是新旧策略在同一动作上的概率比；Ât 是条件优势；ε=0.2 是裁剪半径

SAC 最大化"回报 + 熵"的软目标，用软 Bellman 备份训练双 Q：

J(π) = Σt 𝔼[ rt + α·H(π(·|st)) ]
y = r + γ(1−d) · [ mini Qθ̄,i(s′,a′) − α·log π(a′|s′) ] α 是自动调整的温度；H 是策略熵；第二式是批评家的回归目标：双 Q 取小再减熵项

两者都用熵维持探索，但机制不同：PPO 的熵系数是常数、探索噪声由状态无关的 log_std 参数控制；SAC 的温度 α 自动调整，把平均熵拉向目标熵 −dim(A)。这决定了它们在探索章节（第 066 章）会有不同表现，也是你读日志时最直观的差异：PPO 那行显示"熵"，SAC 那行显示"α"。

3. 为什么按环境步数对齐（墙钟时间只用于读计算效率）

如果用墙钟时间对齐，CPU 线程数、实现效率、批量大小都会混进来。本实验的规则是：两种算法各自跑 --max-steps 个环境步，每 5000 步用 10 个回合的确定性策略评估一次，画在同一张图上。墙钟时间照实打印，但只用于读"计算效率"，不用于判定胜负。

样本效率 = 达标所需环境步数  |  计算效率 = 达标所需墙钟秒数 两者可以给出相反的排名：SAC 样本效率高但在 CPU 上每步要多算几个网络

这样你看到的第一条结论，SAC 在样本效率上通常领先 PPO 约 2～4 倍，才站得住。反过来，如果延长预算到 20 万步，PPO 最终也能收敛到 −200 附近：差距主要在"效率"，不在"上限"。

4. 达标步数：把曲线变成数字

光看图容易被噪声骗。本章用 cur_steps_to 从评估曲线里提取"首次达到 −400 分时消耗的环境步数"作为量化指标。−400 是 Pendulum 上"基本学会控制"的参考线：随机策略约 −1200，能持续泵能量但不稳定的策略在 −800 左右，像样的摆动平衡在 −300 以内。两个算法都在同一横坐标、同一阈值下取数，比较才有意义。

数据流

PPO 侧：采样固定 2048 步（含回合重置）→ GAE 反推优势与回报目标 → 优势标准化 → 10 epochs × 小批量的裁剪更新 → 整批数据丢弃。每采满若干轮检查一次评估点。SAC 侧：每环境步先选动作（预热期随机，之后策略采样）→ 写回放池 → 立刻做一次梯度更新 → 定期评估。两条流水线的交汇点是 evaluate 和 cur_steps_to：评估协议同源，指标计算同源。

公平比对的三条纪律

1) 同一环境、同一随机种子：环境初始状态序列一致，比较才不是掷骰子；2) 同一环境步预算：横轴对齐交互量；3) 同一评估协议：都是确定性动作、10 个回合、同样的评估频率。缺任何一条，结论都会被质疑。
与第 062 章的差异：那章对照"数据来源"，这章对照"算法"；本章新增完整连续动作 PPO、统一评估接口和达标步数指标。

关键代码与解读

片段 1：PPO 的高斯策略与 logp 一致性

class PPOActorCritic(nn.Module):
    def __init__(self, obs_dim: int, act_dim: int, hidden: int = 64):
        super().__init__()
        self.body = nn.Sequential(
            nn.Linear(obs_dim, hidden), nn.Tanh(),
            nn.Linear(hidden, hidden), nn.Tanh(),
        )
        self.actor_mean = nn.Linear(hidden, act_dim)
        # 状态无关的对数标准差，是 PPO 探索强度的直接旋钮
        self.actor_log_std = nn.Parameter(torch.full((act_dim,), -0.5))
        self.critic = nn.Linear(hidden, 1)

    def forward(self, obs: torch.Tensor):
        h = self.body(obs)
        mean = self.actor_mean(h)
        log_std = torch.clamp(self.actor_log_std, -4.0, 0.5).expand_as(mean)
        value = self.critic(h).squeeze(-1)
        return mean, log_std, value

    @torch.no_grad()
    def act(self, obs: torch.Tensor):
        """采样动作并做边界裁剪；存裁剪后动作的对数概率，保证训练时一致。"""
        mean, log_std, value = self.forward(obs)
        dist = Normal(mean, log_std.exp())
        raw = dist.sample()
        action = torch.clamp(raw, -ACT_LIMIT, ACT_LIMIT)   # Pendulum 力矩限幅
        logp = dist.log_prob(action).sum(-1)               # 对"裁剪后"动作求 logp
        return action.squeeze(0).cpu().numpy(), float(logp.item()), float(value.item())

解读：连续动作 PPO 有三个容易踩的点。（1）actor_log_std 是独立于状态的参数：它不随观测变化，训练中会被熵项或裁剪梯度慢慢调节，是探索强度的直接旋钮。做成状态相关（SAC 那样）更灵活，但在 PPO 里状态无关更稳定、也是常见默认。（2）动作裁剪到 [−2, 2] 后，logp 必须按裁剪后的动作计算，更新时对新旧策略都用同一种方式重算，比率才有一致口径。如果采样时存未裁剪动作的概率、训练时却按裁剪后动作算，比率会系统性偏离 1，更新悄悄失真。（3）高斯熵 entropy().sum(-1) 按维度求和，动作维度为 1 时与标量熵等价，写成求和是为了将来换高维动作空间不改代码。

片段 2：GAE 的回合端点处理

def compute_gae(rewards, values, cuts, last_value, gamma: float, lam: float):
    """广义优势估计；cuts[t]=1 表示该步是回合端点（终止或时间截断）。"""
    T = len(rewards)
    adv = np.zeros(T, dtype=np.float32)
    last_gae = 0.0
    for t in reversed(range(T)):
        next_value = last_value if t == T - 1 else values[t + 1]
        non_terminal = 1.0 - cuts[t]        # 回合端点切断自举，不把两段轨迹连起来
        delta = rewards[t] + gamma * next_value * non_terminal - values[t]
        last_gae = delta + gamma * lam * non_terminal * last_gae
        adv[t] = last_gae
    returns = adv + np.asarray(values, dtype=np.float32)
    return adv, returns

解读：与第 001 章骨架一致，但这里的 cuts 把真实终止与 200 步时间截断统一处理为价值切断点。好处是实现简单且不会把两个回合的价值错误地连接起来；代价是回合末端自举缺失、价值略有高估（本任务回报恒为负，截断点的真实续值是负值，丢掉它会让估值偏乐观）。对 Pendulum 这种固定长度任务，这个选择稳定可靠，本章正文里把它作为示例写进对比脚本，练习里你会被要求改成"截断时自举"再比较。注意 returns = adv + values：价值网络回归的是"优势反推回报"，它比蒙特卡洛回报方差更小。

片段 3：PPO 的裁剪更新核心

for _ in range(args.epochs):                          # 同一批数据复用 epochs=10 轮
    idx = torch.randperm(N, device=obs.device)        # 每轮重打乱，消除顺序偏置
    for start in range(0, N, args.batch_size):
        mb = idx[start:start + args.batch_size]
        mean, log_std, value = net(obs[mb])
        dist = Normal(mean, log_std.exp())
        logp = dist.log_prob(act[mb]).sum(-1)         # 新策略对同一批动作的 logp
        ratio = torch.exp(logp - logp_old[mb])        # 对数差取指数，数值更稳
        surr1 = ratio * adv[mb]
        surr2 = torch.clamp(ratio, 1.0 - args.clip, 1.0 + args.clip) * adv[mb]
        policy_loss = -torch.min(surr1, surr2).mean() # 悲观下界，越界梯度归零
        value_loss = F.mse_loss(value, ret[mb])
        entropy = dist.entropy().sum(-1).mean()       # 连续动作熵：按维求和
        loss = policy_loss + args.vf_coef * value_loss - args.ent_coef * entropy
        optimizer.zero_grad()
        loss.backward()
        nn.utils.clip_grad_norm_(net.parameters(), 0.5)
        optimizer.step()
        with torch.no_grad():                          # 诊断统计，不参与反传
            stats["approx_kl"] += (logp_old[mb] - logp).mean().item()
            stats["clip_frac"] += ((ratio - 1.0).abs() > args.clip).float().mean().item()
            stats["n"] += 1

解读：这就是 PPO 一边复数据、一边防跑偏的全部机制。（1）ratio = exp(logp − logp_old) 用对数差保证数值稳定；logp_old 是采样时存下的快照，训练中绝不重算。（2）min(surr1, surr2) 是悲观下界：比率超出 [0.8, 1.2] 后梯度归零，一批数据可以安全地过 10 遍。（3）诊断项 approx_kl 与 clip_frac 是健康仪表盘：KL 长期偏高或裁剪比例长期高于 0.3，说明更新过猛，该降学习率或缩小 clip。（4）熵系数 --ent-coef 本章默认 0，Pendulum 用状态无关 log_std 已经能维持足够探索，避免多一个需要调的超参数。

片段 4：SAC 的采样与更新循环（对齐预算的关键）

for step in range(1, args.max_steps + 1):
    if step <= args.start_steps:                       # 预热期用均匀随机动作填池
        action = np.random.uniform(-ACT_LIMIT, ACT_LIMIT, size=(act_dim,)).astype(np.float32)
    else:
        with torch.no_grad():
            action = agent.policy.sample(obs_tensor(obs, device))[0]
            action = action.squeeze(0).cpu().numpy()
    next_obs, reward, terminated, truncated, _ = env.step(action)
    done = terminated or truncated
    buffer.add(obs, action, (reward,), next_obs, (float(done),))
    obs = next_obs
    if done:
        obs, _ = env.reset()

    if step > args.start_steps:                        # 每个环境步一次梯度更新
        stats = agent.update(buffer.sample(args.sac_batch_size, device))

    if step % args.eval_every == 0:                    # 与 PPO 同一评估频率
        ret = evaluate(eval_env, agent.policy.mean_action, args.eval_episodes, device)
        curve.append((step, ret))

解读：args.max_steps 是两种算法共享的预算旋钮，横轴因此完全对齐。（1）预热期用均匀随机动作把池子填出足够覆盖度，2000 步后切换成策略采样；预热期不做梯度更新，避免用贫瘠数据启动学习。（2）step > args.start_steps 之后每个环境步更新一次，这是 SAC 单步计算量大的来源，也是它样本效率高的来源。（3）评估调用的是 agent.policy.mean_action（tanh 后确定性动作），与 PPO 的 net.mean_action 走同一个 evaluate，协议零差异。（4）注意 curve 记录的是 (step, ret)：横轴是环境步，不是更新次数，这样 SAC 的"每步更新"与 PPO 的"批量更新"才能画在一张图上。

以实跑为准的预期：SAC 通常在 2 万～4 万环境步内越过 −400；PPO 在 6 万步预算内一般只到 −650 ~ −250，样本效率落后约 2～4 倍。PPO 的墙钟时间未必更长，它每步梯度计算更少；若把预算加到 20 万步，PPO 最终也能收敛到 −200 附近。不同种子会有明显波动。

常见坑

  • 存了未裁剪动作的 logp：动作被裁剪到边界，logp 却按未裁剪采样计算，更新时口径不一致，比率系统性偏离 1，训练悄悄变慢。要么两端都按裁剪后动作算，要么两端都不裁剪，绝不能一半一半。
  • 用梯度步数对齐两种算法：PPO 和 SAC 的梯度步语义完全不同（一个反复复用、一个持续新数据），用梯度步对齐等于偏袒其中一方。对齐的是环境交互预算。
  • 评估用随机动作：Pendulum 单回合回报方差可达几百，评估时还采样动作会把运气算进成绩，足以颠倒结论。评估一律用确定性 mean_action，并跑 10 个回合取均值。
  • 忽略时间截断的 GAE 处理：Pendulum 每 200 步截断，若把截断当"继续"，GAE 会把跨回合价值连起来，早期价值估计异常。统一把回合端点标记为切断点。
  • 只看终点、不看达标步数：两条曲线在预算末端可能只差几十点，但"首次越过 −400 的步数"可能差 2～3 倍。样本效率的结论要建立在达标步数上，终点值只作参考。

  3. 把 PPO 的 --ent-coef 从 0 调到 0.01，观察评估曲线与"熵"列的变化。预测：探索变多会加快还是拖慢达标？★★
    提示
    熵项给 log_std 一个持续增大的梯度。看"熵"列走向与评估回报起飞的时点：探索更强但学习更晚，通常两件事同时发生。
  4. 给两种算法分别记录"回报 vs 墙钟时间"的打点（在评估处存 time.time() − t0），比较两张图与"回报 vs 环境步"图的结论差异，解释样本效率与计算效率为何不等价。★★
    提示
    SAC 每个环境步都有更新，墙钟时间增长更快；在 CPU 上两者可能互有胜负，在 GPU 上差距又不同，这正是"效率"必须说明口径的原因。
  5. 算一算两种算法的参数量（sum(p.numel() for p in net.parameters())）。PPO 的 actor 与 critic 共享躯干，SAC 是策略 + 双 Q 共三套网络。讨论："网络容量对齐"在这种对比里应该怎么定义才算公平？★★★
    提示
    先打印参数量再讨论：到底是总参数对齐、单网络宽度对齐，还是每类网络各自对齐？不同定义会给出不同的"公平"，写清楚你的口径。

小结

  • PPO 与 SAC 的本质区别在数据复用：PPO 复用约 10 次就丢弃数据，SAC 把回放池反复采样，复用率高出几个数量级。
  • 公平对比三条纪律：同环境同种子、同环境步预算、同评估协议；横轴比样本效率，墙钟只比计算效率。
  • 标准配置下，SAC 通常 2 万～4 万步越过 −400，PPO 在 6 万步内落后约 2～4 倍，但单步计算更省、延长预算也能收敛。
  • 连续动作 PPO 的两个实现细节：动作裁剪与 logp 的一致性、回合截断作为价值切断点。
  • 达标步数（cur_steps_to）比终点回报更能反映样本效率，是后续所有对比章节的统一指标。
