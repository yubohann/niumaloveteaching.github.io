第一篇 · 策略梯度与 PPO

第 018 章：PPO的模仿学习初始化

先训练一个 PPO 专家，把它的轨迹做成示范数据做行为克隆（BC），再从 BC 权重出发微调 PPO，对照从零训练，量化"先看专家怎么做"能省下多少样本。

  • 主题：模仿学习 / 行为克隆初始化
  • 关键公式：LBC = −𝔼(s,a)~D[log πθ(a|s)]；闭环成功率 ≈ (1−ε)T
  • 预计学时：60 分钟
  • 前置章节：第 017 章

学习目标

  • 理解行为克隆（Behavior Cloning, BC）的目标函数与它在 RL 中的定位：为 PPO 微调提供一个"还不错"的起点，最终答案仍由在线训练给出。
  • 实现专家训练、示范采集、BC 有监督训练、以及从 BC 权重出发的 PPO 微调完整管线。
  • 理解复合误差（compounding error）：BC 的训练精度高不代表闭环成绩好，分布偏移是根因。
  • 对比 bc 与 scratch 两臂的首达 475 步数与最终评估，量化初始化收益。
  • 掌握示范数据的采集口径：按专家策略分布采样，状态覆盖比贪婪采集更广。

背景与动机

上一章的"先验"来自任务分布本身；现实中更常见的先验是人，专家演示、遥操作记录、其他系统的日志。把这些数据利用起来的最低成本方法就是行为克隆：把"状态 → 动作"当成一个监督学习问题。BC 便宜、稳定、训练预算小，但它有个著名弱点：它只保证在"专家走过的状态"上动作正确，一旦策略自己走偏，就进入训练数据没覆盖的区域，错误会累积。

所以 BC 的最佳用法是给 RL 当初始化；把它当作 RL 的替代品，就会被复合误差限制住：BC 策略已经"会一半"，PPO 从它出发微调，天然在好状态的邻域里探索，避免从随机策略开始漫无目的地撞墙；RL 的在线数据又恰好修补 BC 的分布偏移。本章把这条"模仿 → 微调"链路完整跑一遍，并给出一个可比较的数字：BC 初始化把达标步数缩短了多少。

核心原理

1. 行为克隆：把 RL 暂时当成分类

给定专家示范数据集 D = {(si, ai)}，BC 最小化负对数似然：

LBC(θ) = − E(s,a)~D[ log πθ(a | s) ] 离散动作就是交叉熵；连续动作对应高斯的回归 + 方差项（第 011 章的 logp 形式）

它优化的目标与 RL 不同：BC 不考虑"我的错误会把我带到哪里"。动作错误会改变后续状态分布，而训练分布是专家的，于是误差越滚越大，这就是复合误差。

2. 复合误差的量化视角

假设单步动作错误率 ε，回合长度 T。若错误独立，闭环成功率约为：

P成功 ≈ (1 − ε)T ε：单步动作错误率；T：回合长度；错误引发分布外状态时实际还会更快衰减

更糟的是错误会引发"分布外状态"，此时策略的错误率上升，形成正反馈。CartPole 的 T 可以到 500，所以95% 的 BC 精度也可能只换来几百步的存活。这也是为什么本实验里 BC 的闭环评估（200～450）通常明显低于专家（475+），却依然远好于随机策略（约 20）。

数值算例：把 (1−ε)T 与实测闭环对上账

单步错误率 ε=0.05、回合长度 T=500 时，最悲观口径 (1−ε)T = 0.95500 ≈ 7.3×10−12，等于说"每步都不能错，错一次就结束"。但实测 BC 策略能存活 200～450 步，说明实际情况远没有这么悲观：CartPole 对多数动作错误是容错的，错一步只把状态推偏一点，后续正确动作还能把轨迹拉回来，真正致命的是"临界区里的错"。

反过来从实测反推等效致命错误率：若策略以 50% 概率活到 300 步，则 (1−εeff)300 = 0.5，解得 εeff = 1 − 0.51/300 ≈ 0.23%。训练精度里 5% 的错误，只有约 0.23% 落在"会引发不可恢复偏移"的位置，相差 20 倍。这 20 倍就是任务对错误的容忍度，它随任务变化：杆越短、角度容差越小的任务，容忍度越低，(1−ε)T 的悲观口径就越接近现实，复合误差的破坏也越早出现。

3. 示范数据怎么采

用专家的随机策略采样有两个好处（对照做法是确定性贪婪）：1) 动作分布本身包含专家对边界情况的犹豫，BC 能学到"不那么自信"的输出；2) 状态覆盖更广，降低分布外区域的比例。代价是示范质量有波动，本章同时打印专家采样回合的平均回报，如果低于 400，说明专家本身不稳，示范会带偏。

复合误差的破坏力由三个因子共同决定，逐个看能对应到不同的对策：其一，单步错误率 ε 在分布外会上升，形成正反馈，对策是 DAgger 类方法把越界状态补进训练集；其二，回合长度 T 越长，连乘的指数越可怕，对策是在长回合任务上额外加大示范覆盖或使用带恢复能力的专家数据；其三，任务的稳定裕度越小（容错窗口越窄），同样 ε 下更早失稳，对策有限，通常只能接受"BC 闭环上限较低"并依赖微调补齐。把任务按这三条拆开评估，就能预判 BC 初始化值不值。

示范量的账可以先算：30 个回合、每回合约 400 步，得到约 1.2 万条 (状态, 动作) 对；BC 训练 80 epochs，总样本呈现约 96 万次，相对 4675 个网络参数是每个参数约 205 次更新的量级，属于"数据够用、接近饱和"的区间。这也解释了练习 1 的预期形态：示范从 5 回合增加到 30 回合，精度与闭环都会明显改善；继续加到 100 回合，收益开始递减，因为覆盖率已经接近专家自己的状态分布。

BC 的天花板由示范决定：BC 学到的是示范动作的统计规律，示范者的水平就是它的近似上限。若专家的随机策略采样平均回报只有 420，BC 的闭环成绩不会系统性超过这条线；碰到"BC 怎么调都不行"时，先回头看示范质量这一环，不要继续加 BC 轮数。采集函数顺手打印平均回报，就是为了让这一步检查接近零成本。

复合误差还有一个标准的修补方向：DAgger 类方法。它反复用"当前策略自己走出的状态分布"去问专家要标注，把策略实际会到的状态补进训练集，越界的区域被逐步填上。代价是需要专家在线可用（人可以，训练好的 PPO 专家也可以），以及多轮"采集-标注-重训"的循环；练习 3 会实现一轮最小版本。

4. 微调时价值头的冷启动

BC 只训练策略头（动作交叉熵不涉及价值）。价值头仍是随机初始化，微调最开始几个更新里价值损失会很大、优势估计粗糙。这是正常现象，通常几千步内价值头就追上；如果想更平滑，可以先用一批专家数据把价值头也做一轮回归预热（练习 4）。

策略侧的数值特征也可以提前预判。随机初始化时两个动作的概率各约 0.5，策略熵接近 ln2 ≈ 0.693；BC 之后在示范状态上的精度通常在 85%～95%，对应熵只有约 0.42 到 0.20。同样的优势尺度下，低熵策略的对数概率对参数变化更敏感，比率 rt 更容易越界、被裁剪的比例更高，所以"从 BC 出发"的微调期常见 KL 尖峰。这不是初始化坏了，属于探索幅度缩小后的正常现象；对策是把微调学习率降到 1e-4 量级或减少每批 epoch 数，无需回退到随机初始化。

最后把成本的两种情况分清楚：若示范已经存在（历史日志、他人标注、遥操作记录），BC 只付监督训练的钱，本例约 96 万次样本呈现，几乎白捡；若示范依赖现训专家，则总投入是专家 12 万步加微调约 3.5 万步，对比 scratch 的 7.4 万步并不便宜，只有当同一批示范（或同一个专家）能服务多个下游任务时才划算。把这笔账写进方案，能避免"越省越贵"的循环。

阶段数据来源优化目标典型数字（本章设置）

示范采集专家随机策略无（只记录）30 回合约 1.2 万条样本，回报 475 上下
BC固定示范数据动作负对数似然精度 85%～95%，闭环 200～450
微调在线交互（PPO）回合回报首达步数比 scratch 少 30%～60%
为什么 BC 的闭环成绩注定低于专家

BC 的训练目标是"在专家状态上预测对动作"，而闭环执行时策略自己产生状态分布：只要有一步偏差，后续状态就开始偏离专家轨迹，预测精度随之下降，这就是分布偏移 + 复合误差。所以本章把 BC 的定位说清楚：它是微调的起点，闭环评估低不丢人；真正的成绩是"微调把它带到了哪里，比从零快多少"。

三种"补数据"的路线也顺带对比：BC 只用固定示范（离线、最便宜、误差会累积）；DAgger 用策略自己的状态分布反复向专家提问（在线专家、逐步修补偏移、需要多轮循环）；纯 PPO 只用奖励信号（不需要专家、样本最贵）。三者的样本成本从低到高，对专家或奖励的依赖各不相同，选哪条取决于你手里有什么。

关键代码与解读

片段 1：示范采集，按专家分布采样

def collect_demos(env, expert, episodes: int, device):
    """用专家的随机策略采样，记录 (obs, action) 对；同时记录专家实际回合回报。"""
    obs_list, act_list = [], []
    ep_returns = []
    for _ in range(episodes):
        obs, _ = env.reset()
        done = False
        ep_ret = 0.0
        while not done:
            obs_t = to_tensor(obs, device)
            a, _, _ = expert.act(obs_t)          # 按专家分布采样，增加状态覆盖
            obs_list.append(obs_t.squeeze(0).cpu().numpy())
            act_list.append(a)
            obs, r, terminated, truncated, _ = env.step(a)
            ep_ret += r
            done = terminated or truncated
        ep_returns.append(ep_ret)
    return np.asarray(obs_list, dtype=np.float32), np.asarray(act_list, dtype=np.int64), ep_returns

解读：（1）expert.act() 内部是 dist.sample()：示范来自专家的随机策略动作分布，而 argmax 贪婪采集会得到"太干净"的示范：轨迹高度重复，BC 在偏离后的状态上更没准备。用分布采样带来两种收益：动作里保留专家"犹豫"的边界样本，且状态覆盖更广。（2）记录的是"动作前的观测 + 专家动作"，与 BC 的监督学习格式一一对应；to_tensor 后的 numpy 转换保持与训练管线一致的 dtype。（3）额外返回 ep_returns：它是示范质量的体检，若平均回报低于 400，说明专家还没训好，采出来的示范会带偏 BC。（4）不记录 logp：BC 训练只用 (obs, act)，replay 里那些 PPO 专用字段在这里没有位置，这条数据管线与 RL 管线彻底解耦。

片段 2：行为克隆，一次朴素但有效的监督训练

def behavior_clone(net, obs, act, args, device):
    """有监督训练策略头（价值头不参与 BC）。"""
    obs_t = torch.as_tensor(obs, dtype=torch.float32, device=device)
    act_t = torch.as_tensor(act, dtype=torch.long, device=device)
    optimizer = torch.optim.Adam(net.parameters(), lr=args.bc_lr)
    n = obs_t.shape[0]
    for epoch in range(args.bc_epochs):
        idx = torch.randperm(n, device=device)
        total_loss, correct = 0.0, 0
        for start in range(0, n, args.bc_batch):
            mb = idx[start:start + args.bc_batch]
            logits, _ = net(obs_t[mb])
            loss = F.cross_entropy(logits, act_t[mb])   # 交叉熵 = 负对数似然
            optimizer.zero_grad()
            loss.backward()
            optimizer.step()
            with torch.no_grad():
                total_loss += loss.item() * mb.shape[0]
                correct += (logits.argmax(dim=-1) == act_t[mb]).sum().item()
        if (epoch + 1) % 20 == 0 or epoch == args.bc_epochs - 1:
            print(f"  [BC] epoch {epoch + 1:3d} | 损失 {total_loss / n:.4f} | 精度 {correct / n:.3f}")
    return total_loss / n, correct / n

解读：（1）F.cross_entropy(logits, act) 正是 LBC 的离散形式：内部做 log-softmax + 负对数似然，数值稳定且与 PPO 的策略头一一对应。（2）优化器传入 net.parameters()，注意损失只经过策略头，价值头参数拿到的梯度是零，所以"整网优化"在效果上等价于"只训练策略头"；注释里那句"价值头不参与"语义上成立。（3）精度用 (logits.argmax(-1) == act) 统计：这是 batching 里最直观的诊断；80 个 epoch 后通常在 0.85～0.95。（4）累计 loss 时乘 mb.shape[0] 再加总、最后除以 n：这样"按样本数加权"的平均才是正确口径（最后一个 minibatch 可能不满）。（5）没有验证集：本章的数据量小、任务单一，用"闭环评估"当验证信号更直接，这也是 RL 里 BC 的常见做法。

片段 3：通用的两臂训练函数

def train_ppo(arm: str, init_state, args, budget: int):
    set_seed(args.seed)                          # 两臂同一随机流，差异只来自起点
    device = torch.device("cpu")
    env = gym.make("CartPole-v1")
    obs, _ = env.reset(seed=args.seed)
    net = ActorCritic(env.observation_space.shape[0], env.action_space.n)
    if init_state is not None:
        net.load_state_dict(init_state)          # bc 臂加载 BC 权重；scratch 臂传 None
    optimizer = torch.optim.Adam(net.parameters(), lr=args.lr)

    all_returns, kls = [], []
    total_steps, n_updates, obs_t = 0, 0, to_tensor(obs, device)
    reached_at = None
    initial_eval = float(np.mean(evaluate(gym.make("CartPole-v1"), net, args.eval_episodes, device)))

    while total_steps < budget:
        batch, ep_returns, obs_t = collect_rollout(
            env, net, args.steps_per_update, obs_t, device, args.gamma, args.lam)
        total_steps += args.steps_per_update
        n_updates += 1
        all_returns.extend(ep_returns)

        stats = ppo_update(net, optimizer, batch, args)
        kls.append(stats["approx_kl"])

        if reached_at is None and len(all_returns) >= 100 and \
                np.mean(all_returns[-100:]) >= args.target_reward:
            reached_at = total_steps              # 首达阈值：两臂比较的核心指标
            print(f"  [{arm}] 达到 {args.target_reward}：步数 {reached_at}")
            break                                 # 达标即停

解读：（1）init_state 参数是两臂对照的全部机关：专家臂传 None（从随机初始化开始）、bc 臂传 BC 权重；其余逻辑一字不差。（2）set_seed(args.seed) 在函数开头：两臂从同一条随机流出发，环境重置与动作采样序列一致，首达步数的差异只能归因于起点。（3）initial_eval 在训练前评估一次"起点质量"：bc 臂这一栏会显示 BC 的闭环成绩（几百），scratch 臂约 20，它让"起点差异"在报告里可见。（4）达标即停用 100 回合滑窗：两臂打印出的 reached_at 直接相减就是"节省的达标步数"；若某臂未完赛则跳过该对比。（5）注意本函数被专家训练也复用：专家臂就是 init_state=None + 12 万步预算，一个函数、三种用途。

    bc_state = {k: v.clone() for k, v in bc_net.state_dict().items()}

    # 4) 两臂微调：同一预算、不同起点
    scratch_result = train_ppo("scratch", None, args, args.finetune_budget)
    bc_result = train_ppo("bc", bc_state, args, args.finetune_budget)

解读：（1）阶段划分清晰、每段产物明确：专家网络 → 示范数组 → BC 权重 → 两个微调结果。出问题时能快速定位是哪一段的锅。（2）bc_state = {k: v.clone() ...}：先把 BC 权重做快照再进微调；不 clone 的话，bc 臂训练会直接改掉 bc_net，"BC 初始评估"这个数字就再也不是"起点"了。（3）两臂微调用相同预算、相同种子：唯一变量是 init_state。（4）最后脚本打印"节省的达标步数（百分比）"，把三段证据（BC 精度、BC 闭环、微调增益）串成一条完整的因果链：数据质量决定起点，起点决定省多少样本。

完整可运行脚本（附录）：code/ch018.py

python code/ch018.py                    # 完整四阶段流水线，CPU 约 5–9 分钟
python code/ch018.py --quick            # 专家 1.2 万步、微调 1 万步，约 30–60 秒
python code/ch018.py --demo-episodes 100   # 用更多示范数据

预期结论（以实跑为准）：BC 训练精度通常 85%～95%，闭环评估 200～450，精度漂亮、闭环差一截，这就是复合误差的可见代价；bc 臂首达 475 的步数一般比 scratch 少 30%～60%（典型约 3.5 万 vs 7.4 万），最终评估持平或略高，KL 相当。若 BC 精度低于 70%，优先把示范回合加到 60～100；若 bc 臂微调早期出现 KL 尖峰，把 --lr 降到 1e-4 试试（BC 策略的熵偏低，需要更温和的更新）。

常见坑

  • 用 BC 精度判断策略可用性：精度是"在专家状态分布上"的指标，闭环执行时分布会漂移。要报闭环评估，两者一起看。
  • 示范质量不稳定：专家还没训好就采集，BC 会把坏动作学进去且难以识别。先确认专家评估 ≥ 450，再采示范。
  • BC 后直接部署、不做微调：在安全要求高的任务上尤其危险，因为分布外状态的动作没有被约束。BC + PPO 微调是标准配方。
  • 微调学习率沿用从零训练的值：BC 策略的熵通常低于随机初始化，同样学习率下比率摆动更大。出现 KL 尖峰时先降学习率或减小 epochs。
  • 没克隆 BC 权重就进微调：bc 臂会直接改掉 bc_net，导致"起点评估"与"起点权重"对不上；先 clone() 快照再复用。

练习与思考

  1. 把 --demo-episodes 设为 5 / 30 / 100，画"示范量 → BC 精度 → 微调达标步数"的关系，找出本任务的饱和点。★
    提示
    专家只需训练一次（结果可复用），变化的是示范采集与 BC。样本少时精度和闭环都掉得快，样本多时收益递减。
  2. 把示范采集从"专家分布采样"改成"贪婪动作"，对比 BC 精度与闭环评估，解释差异。★
    提示
    贪婪示范覆盖的状态分布更窄，精度可能更高但闭环更容易在边界状态出错，典型的高精度低鲁棒。
  3. 实现一轮 DAgger：用当前 BC 策略采集 20 个回合并让专家对其中的状态标注动作，把这批数据加入训练集再训练 BC，观察闭环评估是否提升。★★
    提示
    关键是"到哪问专家"，DAgger 的价值在于用策略自己诱导的状态分布提问。本实验中专家就是训练好的 PPO，可直接对任意状态输出动作。
  4. 给价值头做"回归预热"：用专家示范的状态跑一次价值拟合（目标用专家回报或蒙特卡洛回报），再开始 PPO 微调，比较微调前 1 万步的价值损失与回报曲线。★★★
    提示
    用示范轨迹计算折扣回报作为回归目标，对 critic 做几轮 MSE 训练。这会显著压低早期价值损失，让优势估计更快可用。
  5. 统计 BC 判错样本的状态分布：把示范集的预测错误样本按"杆角绝对值"分桶（如 <0.05、0.05～0.1、>0.1 rad），看错误集中在哪个区间，并与闭环回合中失稳前的状态对照。★★
    提示
    在 behavior_clone 里顺手记录错误索引与状态即可。若错误集中在角度较大的边界区，说明这正是复合误差的起爆点，加采样覆盖或一轮 DAgger 收益最大。

小结

  • 行为克隆把 RL 暂时变成监督分类：最小化专家动作的负对数似然；训练快、稳定，但只对专家分布内的状态有效。
  • 复合误差让 BC 的闭环成绩远低于训练精度；本章实验里 90% 左右精度对应 200～450 的闭环回报。
  • 按专家分布采样示范能扩大状态覆盖、提升边界鲁棒性；贪婪采集的覆盖更窄。
  • BC 初始化 + PPO 微调把达标步数缩短 30%～60%，是把示范数据"变现"的最佳路径。
  • 下一章研究课程学习：当目标任务很难时，主动安排"由易到难"的任务序列，让策略逐步爬升，这是另一种加速训练的手段。
