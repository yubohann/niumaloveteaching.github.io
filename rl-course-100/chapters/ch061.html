第二篇 · 离策略方法与 SAC

第 061 章：SAC的离线强化学习

拔掉环境接口：用"随机 + 脚本专家"的混合行为策略预采 5 万条数据，然后完全离线地训练三种策略，纯行为克隆、朴素离线 SAC、带保守惩罚的 CQL 风格 SAC，看谁能在没有新交互的前提下学到能用的控制器，以及朴素离线 SAC 的 Q 值如何失控膨胀。

  • 主题：离线强化学习（Offline RL）/ 保守 Q 学习（CQL）
  • 关键公式：LCQL = λ·𝔼s[ logsumexpa′ Q(s,a′) − Q(s,adata) ]
  • 预计学时：60 分钟
  • 前置章节：第 060 章

学习目标

  • 理解离线强化学习的设定与核心难点：数据分布固定、策略更新会走向数据之外的"外推区"。
  • 通过实验观察朴素离线 SAC 的 Q 值虚假膨胀，以及它如何导致策略在评估时崩坏。
  • 实现 CQL 风格的保守惩罚：在数据动作上抬高 Q、在策略与均匀采样的 OOD 动作上压低 Q。
  • 把行为克隆作为下界基线，建立"离线学习至少不能差于数据质量"的评估习惯。
  • 会用"固定探针 Q 均值"追踪 Q 尺度，把"膨胀 → 崩坏"的因果链条变成可观测的曲线。

背景与动机

真实项目里，与环境交互往往是最贵的环节：医疗试验不能反复试错、自动驾驶不能随便撞、工业设备不允许冒险。离线强化学习（Offline RL）回答的就是这个场景：手头只有一批历史数据，没有模拟器也没有真机权限，能不能只靠这些数据训练出好策略？

本章把第 057 章的脚本专家复用作"行为策略"来生成历史数据，然后训练阶段完全禁用环境交互，环境只在评估时打开。这是与前面所有章节都不同的数据范式：数据一旦采完就冻结，样本会被反复采样几千次。

核心原理

1. 离线 RL 的困境：外推误差

数据由行为策略 πβ 产生，记其状态-动作分布为 ρβ。训练时的 TD 目标需要查询 (s′, a′) 的 Q 值，但策略 π 会访问 πβ 从未覆盖的动作：

minθ 𝔼(s,a)∼ρβ[ ( Qθ(s,a) − ( r + γ·minjQ̄j(s′, a′) − α·log π(a′|s′) ) )2 ] 问题出在 a′：它由当前策略采样，可能落在 ρβ 之外，Q̄ 的估计没有数据支撑

外推误差有两个来源：函数逼近（神经网络在无数据区域随意外插）与自举（目标值里的 Q̄ 本身就带误差）。两者叠加，再被策略的最大化倾向放大，Q 估计会系统性偏高：本实验里探针 Q 全程为负，但与真实回报的差距会从几十点扩大到数百点，而评估回报毫无同步改善。这就是"离线 SAC 必须先解决保守化"的原因。

2. CQL 保守惩罚

保守 Q 学习（Conservative Q-Learning, CQL）的解法直接：给 Q 加一个惩罚项，把 OOD 动作的价值压低、把数据动作的价值抬起来：

LCQL = λ · 𝔼s∼𝒟[ logsumexpa′ Q(s, a′) − Q(s, adata) ] 第一项压低策略动作族；第二项抬高数据动作；logsumexp 是"软最大值"，比 max 更平滑

符号说明：adata 是数据集里的真实动作，a′ 是 OOD 候选（策略采样 + 均匀采样），λ 是惩罚强度。这样 Q 值会形成一个"数据动作高、OOD 动作低"的保守下界。策略更新时，唯一能获得高 Q 的区域就贴着数据分布，自然限制在 ρβ 附近。logsumexp 的梯度覆盖所有 OOD 动作，比取 max 只在单个动作上给梯度更稳定。

3. 行为克隆下界

行为克隆（Behavior Cloning, BC）只做监督回归 min ‖π(s) − adata‖²，完全不碰奖励与 Q。它没有外推问题，但也学不过数据的平均水平。把它放进对比表的意义是：离线 RL 算法只有明显超过 BC，才证明它真的在"利用奖励结构"；没超过这条线，它做的事与更花哨的模仿无法区分。

实现思路与设计

数据流

主流程两步。采集：混合行为策略（70% 专家动作加 σ=0.5 噪声 + 30% 随机动作）在环境中采集 5 万条转移，连同行为策略回报一起定格。训练：三种方法（bc / sac / cql）同种子各做 8000 次梯度更新，每 2000 次更新评估一次；sac 与 cql 还额外记录固定 512 条探针的 min(Q1,Q2) 均值。评估环境与训练完全隔离。

模块划分

组件职责关键点
collect_dataset混合行为策略采集固定数据集70% 专家动作（σ=0.5）+ 30% 随机动作，兼顾质量与覆盖
SAC.bc_update纯模仿学习基线只优化策略均值动作的 MSE；不构造 Q 更新
SAC.update(..., cql_coef=0)朴素离线 SAC 与 CQL 共用一条路径cql_coef=0 时退化为标准 SAC；大于 0 时叠加保守惩罚

评估协议每 2000 次更新评估 5 回合环境只在评估中使用，绝不给训练补充数据

关键超参数

  • 新增离线数据集采集器、BC 更新、CQL 惩罚与 Q 值探针。
  • 指标从"回报 + 耗时"扩展为"回报 + Q 尺度"的联合诊断。

关键代码与解读

片段 1：混合行为策略与固定数据集

def collect_dataset(n_transitions: int, seed: int, noise: float, random_frac: float):
    """用混合行为策略采集固定数据集，返回 (ReplayBuffer, 行为策略平均回报)。"""
    env = make_pendulum(seed)
    obs_dim = env.observation_space.shape[0]
    act_dim = env.action_space.shape[0]
    buffer = ReplayBuffer(n_transitions, obs_dim, act_dim)
    rng = np.random.default_rng(seed)
    obs, _ = env.reset()
    ep_ret = 0.0
    ep_returns = []
    while buffer.size < n_transitions:
        if rng.random() < random_frac:
            action = env.action_space.sample()            # 30% 随机：保证覆盖
        else:
            action = expert_action(obs) + rng.normal(0.0, noise, size=1).astype(np.float32)
            action = np.clip(action, -2.0, 2.0).astype(np.float32)   # 70% 专家：保证质量
        next_obs, rew, terminated, truncated, _ = env.step(action)
        buffer.add(obs, action, rew, next_obs, float(terminated))
        obs = next_obs
        ep_ret += rew
        if terminated or truncated:
            ep_returns.append(ep_ret)
            ep_ret = 0.0
            obs, _ = env.reset()
    return buffer, float(np.mean(ep_returns[-30:]))

解读：（1）行为策略是"质量与覆盖"的折中：纯专家数据回报高，但状态分布窄，CQL 的保守惩罚会过度收紧；纯随机数据覆盖广，但 BC 的下界太低。30% 随机 + 70% 带噪专家是教学版的甜点。（2）采集用的 ReplayBuffer 与训练时共用同一个结构：训练时只读、采样反复取批，add() 再也不会被调用，这正是"离线"的含义。（3）返回行为策略的平均回报（最后 30 回合）：它是数据集质量的口径，也是后面判断"算法有没有超过数据"的基准线。（4）数据一旦采完就冻结，样本会被反复采样几千次，同一批 transition 的误差被反复自举放大，这是离线问题的病根。

片段 2：CQL 保守惩罚，压低 OOD、抬高数据动作

        if cql_coef > 0.0:
            # 保守惩罚：抬高数据动作的 Q、压低 OOD（策略采样+均匀采样）的 Q
            n_ood = args.cql_samples
            # 策略采样：对每个状态采 n_ood 个动作
            obs_rep = obs.repeat_interleave(n_ood, dim=0)  # (B*n, obs)
            policy_actions, _ = self.policy.sample(obs_rep)
            uniform_actions = (torch.rand_like(policy_actions) * 2.0 - 1.0) \
                * self.policy.act_scale
            ood_actions = torch.cat([policy_actions, uniform_actions], dim=0)
            obs_rep2 = obs.repeat_interleave(2 * n_ood, dim=0)
            q1_ood = self.q1(obs_rep2, ood_actions).view(obs.shape[0], 2 * n_ood)
            q2_ood = self.q2(obs_rep2, ood_actions).view(obs.shape[0], 2 * n_ood)
            cql1 = torch.logsumexp(q1_ood, dim=1) - q1
            cql2 = torch.logsumexp(q2_ood, dim=1) - q2
            q_loss = q_loss + cql_coef * (cql1 + cql2).mean()

解读：（1）OOD 动作用两个来源：策略采样（覆盖策略当前会去的区域）与均匀采样（覆盖整个动作空间，包括策略还没去过的角落）。只有策略采样时惩罚范围会随策略漂移，均匀采样补上"盲区"。（2）repeat_interleave 把每个状态复制 2n 份、与 OOD 动作一一对齐：形状必须严格匹配（B×N），错位会让惩罚打在错误的 (s,a) 上，效果从"保守"变成"随机扰动"。（3）logsumexp(q_ood, dim=1) 是"软最大值"：数值上比 max 稳定、梯度覆盖所有 OOD 动作；减去数据动作的 Q（q1 是当前批里真实动作的估计）形成"数据高、OOD 低"的挤压。（4）惩罚对两个 Q 都施加：min 与 max 的一致保守，避免"一个网络守规矩、另一个偷偷乐观"。

片段 3：探针 Q 与三种方法的训练节奏

    @torch.no_grad()
    def probe_q(self, probe: dict) -> float:
        """固定探针批次的 min(Q1,Q2) 均值：诊断 Q 值是否虚假膨胀。"""
        q = torch.minimum(self.q1(probe["obs"], probe["act"]),
                          self.q2(probe["obs"], probe["act"]))
        return float(q.mean().item())

    def bc_update(self, batch: dict, args) -> dict:
        """纯行为克隆：只回归数据集里的动作（不使用奖励与 Q）。"""
        mean_action = self.policy.mean_action(batch["obs"])
        loss = F.mse_loss(mean_action, batch["act"])
        self.opt_policy.zero_grad()
        loss.backward()
        self.opt_policy.step()
        return {"bc_loss": loss.item()}

    # train_offline 的训练循环：
    for step in range(1, args.train_steps + 1):
        batch = dataset.sample(args.batch_size)       # 数据源永远固定
        if mode == "bc":
            stats = agent.bc_update(batch, args)
        elif mode == "sac":
            stats = agent.update(batch, args, cql_coef=0.0)
        else:  # cql
            stats = agent.update(batch, args, cql_coef=args.cql_coef)

        if step % args.eval_every == 0:
            eval_ret = evaluate(agent, eval_env, args.eval_episodes)
            eval_history.append((step, eval_ret))
            q_mean = agent.probe_q(probe) if mode != "bc" else float("nan")

解读：（1）探针批次在训练前固定（512 条数据里的 (s,a)）：每次测量的输入不变，Q 均值的变化只归因于网络本身，这是"看穿膨胀"的关键设计。（2）真实数据的 Q 应在 −1000～0 之间（Pendulum 的折扣回报尺度）；涨到正几百甚至上千，说明 Q 网络在"赌"未来，朴素离线 SAC 的典型病征。（3）bc_update 只走策略优化器：不进 Q、不进温度，它不认识奖励，因此没有外推问题，也没有"超越数据"的可能。（4）训练循环里没有任何 env.step：评估用独立的 eval_env，训练与评估完全隔离。三种方法同种子、同数据、同预算，只是损失函数不同，这是控制变量最干净的形态。

读表顺序：先看 BC 这一行确立"数据质量的下界"，对比朴素 SAC 的"最好点与最终点的落差"（过估计造成的失稳），再看 CQL 的探针 Q 与真实回报是否同步（本运行里两者基本贴合，这正是保守惩罚想要的效果）。

常见坑

  • 训练时偷偷用环境补充数据：那就不再是离线实验。本章的 collect_dataset 只在开头调用一次，训练循环里没有任何 env.step；评估用的环境与训练隔离。
  • 把"最好评估"当成离线算法的成绩：朴素离线 SAC 的最好分数出现在崩坏之前，拿它比较会严重高估方法。报告离线结果必须用稳定后的最终值或多点平均。
  • CQL 的 OOD 动作没有对齐状态：repeat_interleave 与 view 的形状必须严格匹配（B×N），错位会让惩罚打在错误的 (s,a) 上。
  • BC 基线用采样动作训练，未取均值动作：采样噪声让回归目标自带方差，BC 学不准；监督项必须用确定性输出（mean_action）。
  • 以为 Q 膨胀是"学习太快"：它是结构性问题（外推 + 自举），调小学习率只能延迟而不能根治；解法是保守化（CQL）或策略约束（TD3+BC）。

练习与思考

  1. 把 --random-frac 改成 0.1 与 0.6，重跑三种方法。数据质量与覆盖面如何影响 BC 与 CQL？★
    提示
    random_frac 越低，行为策略平均回报越高、BC 上限越高，但状态覆盖变窄。观察数据多样性对 CQL 保守惩罚效果的影响。
  2. 把 --cql-coef 从 1.0 调到 0.1 与 4.0，观察探针 Q 与最终评估的变化。保守惩罚的"过犹不及"体现在哪？★★
    提示
    λ=0.1 时 Q 是否仍缓慢膨胀？λ=4.0 时评估是否落后于 BC？把运行结果与 BC 基线对比即可判断方向。
  3. 把离线 SAC 的更新次数从 8000 提到 20000，观察崩坏发生的时机。是"更新太多"导致的，还是数据外推导致的？★★
    提示
    崩坏与更新次数强相关，说明外推误差在反复自举中积累。记录探针 Q 超过 0 的首次更新次数，比较两次运行该数字是否一致。
  4. 把 CQL 的均匀采样去掉（只用策略采样），重跑。惩罚的覆盖范围变化如何影响结果？★★★
    提示
    把 uniform_actions 一行去掉、2*n_ood 改为 n_ood。策略采样只覆盖当前策略附近，均匀采样覆盖整个动作空间，后者对"策略还没去过的区域"更有效。
  5. 给离线 SAC 加一个简单的"策略约束"替代 CQL：策略损失里加 λ·MSE(π(s), adata)（类似 TD3+BC）。比较它与 CQL 的最终评估与训练成本。★★★
    提示
    把 BC 损失直接加到策略损失上（用数据动作做正则），Q 侧不做惩罚。训练便宜，但 λ 很敏感；对比它的探针 Q 曲线是否比朴素版更平。

小结

  • 离线 RL 的困难来自外推误差：策略查询数据分布外的动作，Q 的估计无约束且被最大化倾向放大。
  • 本章实现了纯 BC、朴素离线 SAC、CQL 三种方法，用固定探针的 Q 均值把"Q 膨胀 → 策略崩坏"的链条量化。
  • CQL 的保守惩罚 λ·(logsumexp Q(s,a′) − Q(s,adata)) 把 Q 压回数据支撑的区域，训练成本约为朴素版的 2～3 倍。
  • BC 是评估离线算法的必要基线：只有显著超过行为数据的平均水平，算法才算"用上了奖励信号"。
  • 下一章把战线拉齐：同一任务、同一评估协议下对比在线 SAC 与离线 SAC，看看省下的交互量到底值多少性能。
