第四篇 · 多智能体强化学习

第 075 章：多智能体PPO：混合合作竞争

两个追捕者合作围堵一个逃跑者，逃跑者拼命反抗，队内合作、队间竞争，奖励零和。本章对照"单方学习"与"双方同时学习"（self-play），亲眼看一遍多智能体最真实的动力学：此消彼长。

  • 主题：混合合作竞争 / self-play 与非平稳性
  • 关键公式：零和奖励 r追 = −d、r逃 = +d；目标 J(θ) 随对手策略漂移
  • 预计学时：60 分钟
  • 前置章节：第 074 章

学习目标

  • 理解混合合作竞争（mixed cooperative-competitive）设定：队内共享利益、队间利益对立。
  • 掌握零和奖励设计：追捕队的收益严格等于逃跑者的损失，"账本守恒"是合法博弈的前提。
  • 看懂 self-play 训练循环：两个阵营的策略同时更新，各自用独立的中央批评家估计价值。
  • 观察并解释非平稳性：对手在学习，你的最优策略在漂移，学习曲线不再单调。
  • 学会用"泛化矩阵"代替单一分数：对脚本随机、脚本逃跑、学习逃跑者分别评估捕获率。

背景与动机

纯合作环境（第 068～073 章）里所有人上同一条船；纯竞争环境（第 074 章的追与逃）里只有一个学习者。但现实中的多智能体系统大多是混合的：足球里队友合作、对手对抗；竞拍里同行竞价、联盟又互为对手；公司里部门协作、部门又抢资源。多智能体强化学习最迷人也最难的部分，就是在这种"半合作半竞争"结构里训练。

本章把第 074 章的追捕升级成 2v1：两个追捕者要合作围堵，逃跑者要一个人活下去。两个阵营同时学习，意味着每个阵营面对的环境因对方的进步而持续变化。你会看到捕获率曲线像波浪一样起伏：这是博弈的本来面目，代码没有问题。训练的最后，用一个固定对手矩阵评估双方，只报告"对谁赢多少"，单个分数说明不了问题。这也是多智能体 PPO 部分的收官实验。

核心原理

1. 零和奖励：账本必须守恒

设追捕队到逃跑者的最小距离为 dt，捕获时给 ±5 的终局奖励。每步奖励定义为：

rchasert = −dt，  rrunnert = +dt，  捕获终局：+5 / −5 dt 是两追捕者到逃跑者的最小距离；任意时刻两阵营的奖励之和严格为 0

零和设计保证"没有免费的午餐"：追捕者的任何收益都来自逃跑者的损失，双方不可能合谋。若符号写错（比如给逃跑者也奖励"被逼近"），训练会收敛到一个奇怪的合作均衡，这类 bug 在多智能体代码里非常隐蔽，因为双方确实都在"进步"，只是进步的方向错了。工程上验证零和性的办法很直接：把每步两边的奖励打印出来相加，除浮点误差外必须是 0。

2. 非平稳性：对手在动，你的梯子在抖

追捕者优化的其实是"对抗当前逃跑者策略"的期望回报：

Jchaser(θ) = 𝔼[ R | πθ vs πφk ]， 但 πφk 每经过一轮更新就变成 πφk+1 θ 是追捕者参数、φ 是逃跑者参数；目标函数本身在随时间变化，这就是多智能体非平稳性（non-stationarity）的数学形式

结果之一是策略循环：追捕者学会封左边，逃跑者改走右边；追捕者补右边，逃跑者又回左边。你观察到的捕获率波动大多来自这种相互适应，训练本身没有崩溃。工程上通常配合"快照对手""策略池""联赛"等手段（练习 3 是一个最小版本），单靠标准的 PPO 很难得到单调曲线。评价 self-play 结果时要用"对各类对手的矩阵"，某一段曲线的高度说明不了问题。

3. 按阵营做 CTDE + 队内参数共享

两个阵营各维护一个中央批评家 Vchaser(s)、Vrunner(s)，都用全局状态（13 维）估计价值；追捕队内两个成员共享同一个策略网络与同一套优势，第 070 章的参数共享与第 069 章的 CTDE 在这里复用。逃跑者只有一个智能体、一套策略。每次更新时，追捕队的优势向量被复制两份（两个成员），逃跑者的优势独立计算。评估时所有策略都用确定性动作，保证公平。

4. 两种训练模式的对照意义

frozen：逃跑者固定为脚本"远离"策略，只有追捕队学习。它近似一个"静态环境"，曲线平滑、单调，衡量追捕者学习能力的上限。selfplay：双方都学，非平稳性全面登场。预期你会看到：selfplay 的曲线更抖、对脚本逃跑者的捕获率可能更低，但对"学习逃跑者"的适应能力只能靠 selfplay 获得。两者互为补充，构成"专用 vs 通用"的权衡，这正是混合合作竞争问题的教学价值所在。

与第 074 章的差异点

第 074 章是"一个学习者 + 脚本对手"；本章：① 追捕者变成 2 个并共享策略；② 逃跑者也用 PPO 学习（selfplay）；③ 奖励改成零和；④ 评估矩阵加入"学习逃跑者"一列。训练骨架（GAE、裁剪更新、中央批评家、采样器结构）与前面章节保持一致。

关键代码与解读

片段 1：两方的观测，每个人都只看局部

    def _obs(self):
        obs_c = np.zeros((2, self.obs_dim), np.float32)
        rel_runner = self.runner_p - self.chaser_p           # 每个追捕者看逃跑者的相对位置
        for i in range(2):
            rel_teammate = self.chaser_p[1 - i] - self.chaser_p[i]   # 队友的相对位置
            obs_c[i] = np.concatenate([
                self.chaser_p[i], self.chaser_v[i],
                rel_runner[i], self.runner_v - self.chaser_v[i],
                rel_teammate, self.chaser_v[1 - i] - self.chaser_v[i]])
        obs_r = np.concatenate([
            self.runner_p, self.runner_v,
            self.chaser_p[0] - self.runner_p, self.chaser_v[0] - self.runner_v,
            self.chaser_p[1] - self.runner_p, self.chaser_v[1] - self.runner_v])
        return obs_c, obs_r.astype(np.float32)

解读：观测设计里藏着任务的全部"信息结构"。（1）追捕者 12 维 = 自身位置/速度 + 逃跑者相对位置/速度 + 队友相对位置/速度。队友信息必须存在：否则两个追捕者不知道对方在哪，围堵无从谈起（对照第 071 章的"隐身"实验）。（2）逃跑者 12 维 = 自身位置/速度 + 两个追捕者各自的相对位置/速度。逃跑者能看到两个追击者的完整状态、且顺序固定（追捕者 1 在前），而追捕者的观测是按"自己优先"对称组织的，两支队伍的信息量对等，结构各自适配。（3）所有坐标都是相对的、无绝对帧，策略对平移等变；1 - i 的下标技巧表示"另一位追捕者"，只在 N=2 时成立，这是本章为 2v1 量身定制的写法。（4）观测不含"谁是谁"的身份信息，两个追捕者完全同质（配合共享策略），这也是任务对称性的体现。

片段 2：零和奖励的落点

    def step(self, chaser_actions, runner_action):
        chaser_actions = np.clip(np.asarray(chaser_actions, np.float32), -1.0, 1.0)
        runner_action = np.clip(np.asarray(runner_action, np.float32), -1.0, 1.0)
        self.chaser_v = self.damping * self.chaser_v + self.accel * chaser_actions
        self.runner_v = self.damping * self.runner_v + self.accel * runner_action
        self.chaser_p = np.clip(self.chaser_p + self.chaser_v, 0.0, 1.0)
        self.runner_p = np.clip(self.runner_p + self.runner_v, 0.0, 1.0)
        self.t += 1

        dists = np.linalg.norm(self.chaser_p - self.runner_p, axis=1)
        min_dist = float(dists.min())                # 两个追捕者中最近者的距离
        caught = min_dist < self.catch_dist
        # 零和奖励：追捕队拿 -距离，逃跑者拿 +距离；捕获给 ±5
        team_reward = -min_dist + (5.0 if caught else 0.0)
        runner_reward = min_dist + (-5.0 if caught else 0.0)
        done = caught or self.t >= self.episode_len
        info = {"min_dist": min_dist, "caught": bool(caught)}
        obs_c, obs_r = self._obs()
        return obs_c, obs_r, team_reward, runner_reward, done, info

解读：零和结构拆开看有三层。（1）每步的"距离项"互为相反数：team_reward = -min_dist 与 runner_reward = min_dist，两者相加恒为 0；捕获的 ±5 同理。任务里不存在"双赢步"或"双输步"，任何一方的进步都严格以对方为代价。（2）距离用两个追捕者的最小值：合作围堵的收益由"最近的那个人"决定，一个堵住、一个包抄，捕获判定的口径天然鼓励分工。（3）捕获即终止：终局奖励 ±5 相对每步 −0.1~−1 的距离项是"大奖"，双方都会为它冒险或避险，这是博弈张力的来源。（4）验证实验：把两个奖励打印出来求和，若非零就一定有实现 bug；练习里会先做这个"账本检查"。

解读：这段循环回答"self-play 的数据从哪来"。（1）双方的动作在同一个环境步里产生（都用当前策略采样），随后 env.step 同时给出两套观测与两份零和奖励，这就是自博弈数据的同步性；如果先更新一方再采另一方，就变成了交替更新的不同算法。（2）追捕队的奖励 np.full(2, r_c) 复制两份：团队奖励对两个成员相同，配合共享策略与共享优势（下一片段）。（3）frozen 模式下逃跑者动作来自脚本，runner_logp=0.0 只是占位，它的缓冲根本不会进 PPO（更新时直接跳过）。（4）两个缓冲各存一份"全局状态 + 各自中央批评家的 V(s)"：价值估计按阵营分开，这与第 073 章"两队各自的 Q"精神一致，每个阵营对自己的胜负负责。（5）done 时双方观测同时重置，catches_hist 记录胜负；共享的 gs 保证两侧 GAE 的 bootstrap 状态一致。

解读：共享策略的 GAE 与更新。"（1）GAE 按时间维计算一次（adv_c 长度 T），再 np.stack([adv_c, adv_c]) 复制成 (T,2)，最后 reshape(-1) 展平，顺序与 cb["obs"] 的 (T,2,obs_dim) 展平完全对齐。老规矩：先看拼接顺序再谈 broadcast，错位不会报错但会毁训练。（2）cb["rew"] 存的是 (2,) 向量，取 [0] 即团队奖励，两个成员的奖励相同，取谁都一样。（3）中央批评家稍后用整段状态的 MSE 更新（见脚本），与 PPO 更新分离：价值网络先站稳，策略才动。（4）逃跑者的更新只在 mode == "selfplay" 分支里执行（脚本后半段），结构与追捕队完全镜像，两队的公平性靠代码对称来保证。

常见坑

  • 零和符号写反或不对称：任何一步两方奖励之和不为 0，都会悄悄改变博弈性质。训练前先打印若干步的奖励和做"账本检查"。
  • 两队共享同一个批评家或优势：追捕者与逃跑者的回报相反，共享价值会让 GAE 的自举方向混乱。每个阵营必须有自己的 V(s) 与优势。
  • selfplay 里只更新一方：忘了逃跑者的 ppo_update（或忘了把它的数据写进缓冲），就退化成 frozen，结论完全不同。
  • 用曲线末端给 selfplay 判分：非平稳性意味着曲线在波动，任何单点都可能是相位差。结论要看评估矩阵与多时段平均。
  • 双方不对称调参：learning rate、epochs、网络宽度必须两队相同；某一队超配会制造"被让子"的假象，selfplay 结论不可信。

练习与思考

  1. 在环境里加一个"账本检查"：每步断言 abs(team_reward + runner_reward) < 1e-6，跑 1000 步验证零和性。为什么这个性质对博弈合法性如此重要？★
    提示
    零和排除了"合谋抬高双方收益"的可能；非零和的奖励结构需要额外机制（如内部惩罚）来防止联盟，这正是混合合作竞争研究的一部分。
  2. 把捕获终局奖励从 ±5 调到 ±2 与 ±10，观察捕获率与曲线波动。终局奖励与"围堵冒险程度"是什么关系？★
    提示
    ±10 会让双方为终局孤注一掷，早期训练波动更大；±2 时接近"只靠距离项磨"的温和博弈，收敛慢但不激进。
  3. 实现一个最小"对手池"：保存逃跑者的 3 个历史快照，每回合以 1/3 概率随机选一个作为对手；追捕者仍只打当前对手。它能平滑捕获率曲线吗？★★
    提示
    在 run_training 里维护快照列表，采样前随机挑选一个逃跑者策略执行；快照每 N 次更新刷新。这是 League/策略池思想的骨架。
  4. 对比同一训练时长下，frozen 与 selfplay 两版追捕者互为对手时的表现（把 frozen 的追捕者拿去打 selfplay 的逃跑者，反之亦然）。解释"专才 vs 通才"的差异。★★
    提示
    把两版策略都保存下来，手工做交叉评估。frozen 追捕者大概率打不过 selfplay 逃跑者，它从未面对过"会躲的学习者"。
  5. 给逃跑者加一个"假动作"惩罚项：连续两步方向反转时给 −0.2 的奖励惩罚，观察追捕者的策略是否被"骗"得更容易。博弈奖励设计如何影响行为风格？★★★
    提示
    在逃跑者奖励里加方向反转检测；预期逃跑者会更"忠实"地执行一个方向，追捕者的拦截策略学到的是"直线预测"，双方的行为都更干净，但这改动了零和性，需要重新论证账本。

小结

  • 混合合作竞争 = 队内合作 + 队间竞争；零和奖励（±d、±5）是合法博弈的账本基石。
  • self-play 让两个阵营同时学习：每个阵营的目标 J(θ) 随对手策略漂移，非平稳性的数学形式。
  • 实现骨架 = 按阵营的 CTDE（各自中央批评家）+ 队内参数共享与共享优势；数据在同一环境步同步产生。
  • frozen（打脚本）曲线平滑、对脚本强；selfplay 曲线波动、泛化更广，两者是"专用 vs 通用"的权衡。
  • 评估用对手矩阵：random / flee / learned 三列捕获率，比任何单点分数都更能说明博弈实力。
  • 多智能体 PPO 部分到此结束；接下来换上 SAC 骨架，从"独立 SAC"开始重走一遍多智能体机制谱系。
