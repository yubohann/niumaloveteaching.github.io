第 072 章：多智能体PPO：角色对称性

队友和地标在观测向量里排成一列，但"谁排第一"是任意的，好策略不应该在乎顺序。本章让环境每回合洗牌槽位，对比普通 MLP 与置换不变的 Deep Sets 编码器，看结构先验值多少数据。

  • 主题：置换对称性 / 集合编码器（Deep Sets）
  • 关键公式：f(π·{x1,…,xM}) = f({x1,…,xM})；h = meanj φ(xj)
  • 预计学时：50 分钟
  • 前置章节：第 071 章

学习目标

  • 理解多智能体里的置换对称性（permutation symmetry）：同质智能体之间交换身份不改变任务，策略应对"队友列表的顺序"不敏感。
  • 掌握 Deep Sets 风格编码器：先对集合中的每个元素单独编码，再做均值池化。
  • 看懂对比实验的结构：环境每回合随机洗牌槽位，把对称性从隐含假设变成显式变量。
  • 对比"结构上保证对称"与"靠数据学习对称"两条路线的训练效率差异。
  • 学会用一个直接的探针检验置换不变性：把观测槽位打乱，看输出动作漂移多少。

背景与动机

合作导航里的三个智能体是同质的：相同的观测结构、相同的动作能力、相同的奖励函数。但实现上总得把 14 维观测排成一个向量：自身位置、速度、地标 1、地标 2、地标 3、队友 1、队友 2。这个排列顺序是人为约定的，物理世界里并没有"地标 1 必须在队伍最前面"这条规律。

普通 MLP 把观测当作"带固定槽位的表"：第二个槽位与第三个槽位可以有不同的权重。如果训练数据里槽位顺序总是固定，它可能学出依赖顺序的"捷径"（比如更关注队友 2 的位置）。一旦环境改变顺序，换一批编号方式、换一个仿真器实现，这种策略就失灵了。本章做两件事：① 让环境每回合随机洗牌槽位，让"顺序无关"成为任务的事实要求；② 把网络换成置换不变的编码器，让结构直接满足这条要求。这既是一个表征学习实验，也是多智能体系统里"角色对称"的最常见工程实践。

核心原理

1. 置换不变性：把输入当作集合

队友和地标在数学上是集合，不是有序序列。设 π 是任意置换，一个对集合建模的函数 f 应满足：

f(π · {x1, …, xM}) = f({x1, …, xM})   等价于   池化(π·x) = 池化(x) 均值、最大值、求和这类池化天然满足该性质；固定槽位的全连接层不满足

Deep Sets 用"逐元素编码 + 对称池化"构造这类函数：先对每个队友的相对位置用同一个编码器 φ 得到特征，再对 M 个特征求均值：

hothers = (1/(N−1)) · Σj≠i φ(pj − pi)，  hland = (1/N) · Σl ψ(ll − pi) φ、ψ 是两个共享的小编码器；pj−pi 是队友 j 相对智能体 i 的位移；l 是地标位置。均值池化对顺序不敏感，因此任意置换都不改变 h

最后的策略头只看到"自身特征 + 队友集合摘要 + 地标集合摘要"三块。注意 Deep Sets 的经典结论：逐元素编码 + 对称池化是置换不变函数的一般形式（在足够宽的编码器下可以逼近任意对称函数），这是有理论保证的构造性结论。

2. 结构先验 vs 数据学习

普通 MLP 理论上也能学出置换不变的函数（把每组槽位的权重学成相同），但这是从数据里发现对称性的过程：每见一个新顺序就要修正一次权重，样本效率低，而且容易被有限数据带偏。把对称性写进结构，相当于把"这个任务关于置换不变"的知识免费送给网络，归纳偏置与任务结构匹配时，学习速度与泛化都会更好（第 070 章的参数共享也是同一哲学）。代价是表达能力受限：如果任务本来就有序（比如"队友 1 是队长、必须最后到"），强行池化会丢掉信息。

3. 洗牌槽位：让对称性可测

本章的环境在每个回合 reset 时抽取两个随机置换：队友顺序 πagent 与地标顺序 πland，按置换后的顺序排列观测槽位。物理状态不变、奖励不变，唯有槽位顺序在变。于是：

  • sym 编码器：输入置换在数学上等价于恒等变换，性能不受影响；
  • naive 编码器：必须把不同顺序映射到相同行为，只能靠数据慢慢逼近。

关闭洗牌（--no-shuffle）后槽位固定，naive 的"背槽位"问题不存在，这个开关用于验证"干扰源到底存不存在"，也是本章的第二组对照。

4. 一个直接的探针：置换一致性

除了看训练曲线，还可以直接检验不变性：取一条观测，人工打乱它的队友与地标槽位，比较两次输出动作的距离。对 sym 编码器，漂移应恰好为 0（浮点误差级别）；对 naive 编码器，漂移是一个正数，且通常随训练数据里的顺序多样性下降。这个探针把"结构保证"与"数据近似"的区别从间接指标变成直接测量，练习里会让你亲手实现。

实现思路与设计

模块划分

组件职责关键点
CooperativeNavEnv每回合随机洗牌槽位顺序地标顺序与队友顺序独立置换，奖励不变
NaiveActor普通 MLP 策略直接吃 14 维拼接向量，槽位敏感
SymmetricActor置换不变策略own/land/other 三个编码器 + 集合均值池化
Manager.update共享 Actor + 中央批评家更新两种编码器共用同一套训练流程
--no-shuffle对照开关关闭洗牌后槽位固定，观察 naive 是否更容易

关键超参数

参数默认值作用与取值理由
--encoderboth先 naive 后 sym，同预算对照
--no-shuffle关闭（即默认洗牌）用于验证"顺序干扰是否存在"的对照条件

--max-steps120000每种配置的智能体步预算

数据流

环境侧：reset 抽两个置换 → _obs 按置换后的顺序拼观测 → 奖励与动力学完全不变。网络侧：naive 直接把拼接向量过 MLP；sym 先 _split 把向量拆回 own/land/other 三块，各自编码后均值池化，再进共享躯干。两种网络共用同一份采样、中央批评家与更新流程，单变量对照。

与第 071 章的差异点

第 071 章给策略加消息通道；本章去掉消息：① 环境新增槽位洗牌；② 策略网络扩展为两种结构候选（平坦 MLP 与集合编码器）；③ 训练流程不变。第 073 章会回到"每个智能体贡献多少"的问题，信用分配。

关键代码与解读

片段 1：每回合洗牌槽位

    def reset(self):
        self.pos = self._rng.uniform(0.15, 0.85, (self.n_agents, 2)).astype(np.float32)
        self.vel = np.zeros((self.n_agents, 2), np.float32)
        self.landmarks = self._rng.uniform(0.10, 0.90, (self.n_agents, 2)).astype(np.float32)
        if self.shuffle_slots:
            self.agent_order = list(self._rng.permutation(self.n_agents))    # 队友槽位顺序
            self.landmark_order = list(self._rng.permutation(self.n_agents)) # 地标槽位顺序
        else:
            self.agent_order = list(range(self.n_agents))
            self.landmark_order = list(range(self.n_agents))
        self.t = 0
        return self._obs()

    def _obs(self):
        obs = np.zeros((self.n_agents, self.obs_dim), np.float32)
        for i in range(self.n_agents):
            rel_land = np.concatenate([self.landmarks[j] - self.pos[i]
                                       for j in self.landmark_order])           # 按洗牌后的顺序
            rel_others = [self.pos[j] - self.pos[i] for j in self.agent_order if j != i]
            others = np.concatenate(rel_others) if rel_others else np.zeros(0, np.float32)
            obs[i] = np.concatenate([self.pos[i], self.vel[i], rel_land, others])
        return obs

解读：洗牌全部发生在"观测的拼装方式"上，物理状态与奖励一行未改。（1）两个置换独立抽取：地标顺序与队友顺序各自被打乱，甚至可以出现"某个队友排在自己后面"的顺序，观测的结构信息（谁在前谁在后）每回合都在变。（2）置换的"物理含义"是重新编号：如果任务真的有角色（一号位必须去一号地标），这种洗牌会直接破坏任务；而本章的二分匹配奖励对编号对称，洗牌只影响策略的输入表征，不影响最优解。（3）注意 agent_order 里跳过 j == i：自己永远不出现在"其他智能体"列表里，这个"自己"的定位由观测最前面的 4 维（自身位置+速度）承担。（4）关闭洗牌时两个 order 都是恒等排列，环境退化为第 068 章的样子，对照实验的另一半。

片段 2：槽位敏感的普通 MLP

class NaiveActor(nn.Module):
    """普通 MLP：直接把 14 维拼接向量喂进去。"""

    def __init__(self, obs_dim, act_dim, hidden=64):
        super().__init__()
        self.net = mlp(obs_dim, act_dim, hidden)     # 第一层对每个槽位有独立权重
        self.log_std = nn.Parameter(torch.full((act_dim,), -0.7))

    def forward(self, obs):
        mean = self.net(obs)
        log_std = torch.clamp(self.log_std, -4.0, 0.5).expand_as(mean)
        return mean, log_std

解读：naive 的代码短得"无辜"，但问题藏在第一层 Linear(obs_dim, hidden) 里。（1）对输入的第 5、6 个槽位（地标 1 的坐标）与第 9、10 个槽位（地标 3 的坐标），网络拥有不同的权重列。交换两格的数值，输出会变，除非权重列恰好被训练成相同，而这需要数据反复教育它。（2）洗牌环境里每个回合顺序都在变，naive 必须对所有顺序"一视同仁"，等于不断把已学到的顺序模板推倒重来；它当然学得会，只是把本可以免费的对称性又交了一遍学费。（3）两种编码器的参数量刻意接近（同 hidden=64），如果 naive 反而更好，先怀疑任务真的存在顺序信息，或训练噪声掩盖了差异。

片段 3：置换不变的集合编码器

class SymmetricActor(nn.Module):
    """置换不变编码器：自身编码 + 地标均值池化 + 队友均值池化。

    池化把每个地标（或队友）的相对位置先单独编码，再对集合取均值，
    因此输出对槽位顺序完全不敏感；"角色对称"由结构直接保证，无需从数据里学。
    """

    def __init__(self, obs_dim, act_dim, n_agents, hidden=64):
        super().__init__()
        self.n = n_agents
        self.own_enc = mlp(4, hidden, hidden)      # 自身 4 维（位置+速度）
        self.land_enc = mlp(2, hidden, hidden)     # 单个地标相对位置 2 维
        self.other_enc = mlp(2, hidden, hidden)    # 单个队友相对位置 2 维
        self.trunk = nn.Sequential(nn.Linear(3 * hidden, hidden), nn.Tanh(),
                                   nn.Linear(hidden, hidden), nn.Tanh())
        self.mean = nn.Linear(hidden, act_dim)
        self.log_std = nn.Parameter(torch.full((act_dim,), -0.7))

    def _split(self, obs):
        own = obs[:, :4]
        land = obs[:, 4:4 + 2 * self.n].reshape(-1, self.n, 2)          # 地标分槽
        other = obs[:, 4 + 2 * self.n:].reshape(-1, self.n - 1, 2)      # 队友分槽
        return own, land, other

    def forward(self, obs):
        own, land, other = self._split(obs)
        h_own = self.own_enc(own)
        h_land = self.land_enc(land).mean(dim=1)   # 对地标集合取均值：与顺序无关
        h_other = self.other_enc(other).mean(dim=1)  # 对队友集合取均值：与顺序无关
        h = self.trunk(torch.cat([h_own, h_land, h_other], dim=-1))
        mean = self.mean(h)
        log_std = torch.clamp(self.log_std, -4.0, 0.5).expand_as(mean)
        return mean, log_std

解读：这是 Deep Sets 思想的完整落地，四个设计点值得细看。（1）_split 把 14 维向量按"位置块 + 地标块 + 队友块"切开，再 reshape(-1, n, 2) 拆成 M 个 2 维元素。这个结构假设来自环境定义的槽位布局，如果观测布局变了，这里必须同步改，结构先验的"接口"就是这些固定边界。（2）三个编码器分别处理自己、地标、队友：它们输入含义不同，不共享参数；但同一类内的 所有元素共享同一个编码器（land_enc 吃整个 (B, n, 2) 张量，等价于对每个地标独立编码）。（3）.mean(dim=1) 是置换不变性的来源：均值不关心元素次序。换成 max 或 sum 同样不变，练习里可以对比三种池化。（4）池化后每类只剩一个 hidden 向量，"集合大小"的信息被压缩掉；对固定 N=3 的本章任务无所谓，但若队友数量可变动（战斗减员、动态加入），需要额外把计数拼进特征，这是 Deep Sets 在变长场景的标准补丁。

python code/ch072.py --quick   # 快速跑通：约 1 分钟

以实跑为准的预期：洗牌条件下 sym 通常在前 1/3 训练窗口学习更快、曲线更稳；两者最终可能接近（约 −5 ~ −3），因为 naive 有足够样本也能学近似对称。把 --no-shuffle 打开后差距进一步缩小，这本身验证了"顺序干扰确实存在"。

常见坑

  • 以为 sym 是严格更优：对称性写进结构会损失表达能力。任务里有真实角色/顺序信息时，池化会把有用信息平均掉，naive 反而更好。
  • 两种编码器参数量没对齐：比较结构差异时要让容量接近，否则测的是"参数更多"，结构差异无从比较。本脚本两种网络 hidden 相同，参数量打印在日志第一行。
  • 洗牌只洗了一部分槽位：地标与队友的置换要独立、完整；只洗队友不洗地标，或洗牌后忘记在 _obs 里用新顺序，都会让实验半途失效。
  • 评估环境忘了同样洗牌：训练洗、评估不洗，sym 的优势会被评估集"固定顺序"掩盖。本脚本 train/eval 两个环境都按 --no-shuffle 统一设置。
  • 用"最终回报"下结论：结构先验的价值通常体现在早期窗口（前 1/3 训练）与方差上。只看终点数值，两个编码器可能看起来一样。

练习与思考

  1. 实现"置换一致性探针"：取一批观测，人工打乱地标与队友槽位，比较两次前向输出的动作差异（mean |Δa|）。对两种编码器各跑一次，预测漂移量的差距。★
    提示
    sym 的漂移应在 1e-6 浮点误差级；naive 的漂移是个正数。探针不需要训练，随机初始化的网络就能看出结构差异。
  2. 把 --hidden 做大（如 256）再跑 naive，预测它能否追上 sym。容量换对称性，代价是多少？★
    提示
    更大容量能让 naive 的"顺序模板"学得更细腻，但每个回合顺序都在变，泛化到新顺序仍要靠数据。对比训练时间与最终指标。
  3. 把均值池化分别换成求和与最大值池化（改 .mean(dim=1)），三者都保持置换不变，训练表现有差别吗？解释可能的原因。★★
    提示
    数量固定时 sum 与 mean 只差常数缩放（会被后续层吸收）；max 强调最显著元素（如最近的地标），在某些任务上更有效。这是"不变但不同"的表征差异。
  4. 造一个"有角色"的变体任务：让智能体 0 的速度上限是别人一半，观察 sym 与 naive 的排名是否反转。解释结构先验何时变成枷锁。★★
    提示
    改环境的 accel 按智能体取不同值。此时"谁在槽位 0"有物理含义，强行池化会抹掉身份信息，naive 或"条件共享"更合适。
  5. 把 sym 编码器升级为"注意力池化"：对队友编码后做 softmax 加权求和（权重由自己的编码与队友编码的点积决定）。它在置换不变的同时能表达"更关注最近的队友"，跑一组对照看是否更好。★★★
    提示
    先算注意力分数 αj = softmax(xiᵀW xj)，再 h = Σ αj φ(xj)。这已经接近 Set Transformer 的最小版本。

小结

  • 同质智能体与地标在数学上是集合：交换身份不应改变任务，策略对槽位顺序应不敏感（置换不变）。
  • Deep Sets 结构 = 逐元素编码 + 对称池化（均值/求和/最大），是置换不变函数的一般形式。
  • 两种路线对比：sym 把对称性写进结构（免费先验）；naive 靠数据学习对称（每个新顺序都要学费）。
  • 环境每回合洗牌槽位，把"顺序无关"变成事实要求；--no-shuffle 验证干扰源的存在。
  • 结构先验的收益通常出现在早期训练窗口与方差上；角色真实存在时，池化会伤害性能。
