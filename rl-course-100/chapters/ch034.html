第二篇 · 离策略方法与 SAC

第 034 章：SAC的延迟策略更新

让演员"等一等再动"：评论家每步更新，策略每隔 k 步才更新一次。在 Pendulum-v1 上对比 k=1 / 2 / 4 三种节奏，量一量更新频率到底买到了什么、又付出了什么。

  • 主题：更新节奏 / TD3 式延迟
  • 关键公式：∇θJ(π) ≈ 𝔼[∇θlog πθ·(α−Q(s,a))] + 𝔼[∇θ(−Q(s,aθ(s)))]，Q=Q*+ε
  • 预计学时：50 分钟
  • 前置章节：第 033 章

学习目标

  • 理解"评论家估值尚不准确时，策略更新过频"会带来什么风险，以及延迟更新如何缓解它。
  • 把 SAC 的更新拆成 update_critic() 与 update_actor() 两个可独立调度的函数。
  • 实现 --delays 控制变量实验，对比 k=1、2、4 的评估回报、演员更新次数与 |Q| 幅度。
  • 认识到延迟更新是更保守的节奏，收益在高噪声估计的环境里更大。

背景与动机

策略梯度的方向由评论家给出：Q 说哪个动作好，策略就往哪走。但训练早期 Q 本身还没学准，此时每一步都让策略去追一个抖动很大的 Q，等于把估计噪声直接灌进策略参数里；策略一抖，它采出来的数据分布也跟着抖，评论家又得重新适应，形成"两个网络互相拖后腿"的循环。

TD3 给过一个简单有效的答案：让演员慢一点。评论家每步更新、演员每隔若干步更新一次，等价值估计在最近一段时间"站稳"再让策略吸收它。SAC 的原始论文没有采用延迟，但在很多工程实现里它是个便宜好用的稳定性旋钮。

第 033 章我们保住了双 Q 与目标网络，本章在这两个稳定器之上加第三个旋钮：更新节奏。同时你也会看到延迟的代价，同一段训练预算里演员更新的次数变少了，学习是否还追得上。

核心原理

1. 为什么评论家误差会"传染"给策略

SAC 的策略损失对参数的梯度近似为：

∇θJ(π) ≈ 𝔼[ ∇θlog πθ(a|s) · ( α − Q(s,a) ) ] + 𝔼[ ∇θ(−Q(s,aθ(s))) ] 第二项来自重参数化：Q 对动作的梯度直接进入策略参数

把 Q 写成真值加误差 Q = Q* + ε，则梯度里多出 ∇θ(−ε) 一项。误差 ε 变化越快、方差越大，这项"噪声梯度"越主导更新。延迟更新的直觉就是：拉长评论家两次被消费之间的时间差，让 ε 的抖动平均掉一部分，再让策略吸收。

式子里的两条通道值得拆开看：第一项是得分函数估计，权重 (α − Q) 可以理解为"软优势"的负值，Q 的误差直接乘在 ∇log π 上；第二项是路径导数，Q 先对动作求导、再经过动作对策略参数求导。两项都以 Q 为输入，因此 ε 会从权重和动作路径两个方向同时注入策略。完整展开的重参数化梯度还会多出 α∇alog π 经动作路径的一项，本章关心误差传播，采用上面的简化形式即可。

数值例子：三种节奏下的更新次数对账

预算 15000 步、前 1000 步纯随机热身，因此评论家从第 1001 步才开始更新，总次数约 14000。按调度逻辑 critic_steps % delay == 0 触发演员更新，三种节奏得到的演员更新次数分别约为：delay=1 时 14000 次；delay=2 时 7000 次；delay=4 时 3500 次。

换算成比例：delay=2 的演员更新量是基线的 50%，delay=4 只有 25%，也就是少了约 75%。每一次演员更新对应一次策略优化器的 step()，所以"策略参数被优化的总步数"以同样的比例缩小；如果评论家已经足够准，这就是纯粹的效率损失，在曲线上表现为达到同一回报水平需要更多环境步。

解读：记账时要把三种计数分开：环境步数完全相同，评论家更新次数也相同（都约 14000 次），差的是"策略消费这些样本的次数"与它带来的计算量。日志里的 actor_updates 就是这笔账的明细。

把这场实验换算成"样本消费量"更直观：每次更新抽取 256 条，评论家共消费约 14000×256=358.4 万次样本使用，演员部分 delay=1 为 358.4 万、delay=2 为 179.2 万、delay=4 为 89.6 万。整个训练只产生 15000 条转移，折合每条转移被评论家平均取用约 239 次，而演员在 delay=4 时只取用 60 次。延迟节约的是演员侧的前向与反传，评论家侧的算力开销一分未省。

2. 延迟与其他稳定手段的关系

  • 双 Q 取 min 处理的是误差的偏差方向（把乐观压成保守）；
  • 目标网络处理的是自举目标的时间错位（把追尾巴变成追慢靶）；
  • 延迟更新处理的是策略对误差的消费节奏（降低消费频率、平均噪声）。

三者互补，因此可以把 delay 理解成 SAC 稳定化工具箱里的第三个旋钮。

延迟还有一个容易忽略的连带效果：温度系数与演员绑定，演员少更新 k 倍，alpha 的有效更新次数同样缩到 1/k。第 032 章算过，α 的对数步长量级是每步约 3e-4×熵缺口，需要上千步累积才有可见移动；delay=4 把可用步数砍到四分之一，早期"α 上探"段会被明显拉长。对比三种延迟的回报曲线时，如果 alpha 轨迹也整体滞后，这是绑定设计的直接后果，并不说明温度学习出了故障。

3. 代价：单位预算里演员更新变少

设总评论家更新 N 次，delay=k 时演员只更新 N/k 次。策略参数的有效优化步数下降 k 倍，若评论家已经足够好，这就是纯粹的浪费，学习会更慢。所以 k 不是越大越稳就越好，存在一个"够用"的折中；本章用 1/2/4 三档让你在曲线上看到这个折中。

有一处容易混淆的等价性需要澄清：delay=k 与"把演员学习率除以 k"近似但不相同。若 Adam 每步的参数位移大致归一化到 lr 量级，两者总位移量级相当；差别在于延迟版用的是 k 步之后的新鲜梯度，相邻两次演员更新的梯度相关性更低，噪声方向不会在连续多步里重复叠加，因此延迟通常比同等折扣更"稳"，代价是对快速变化的价值目标反应更迟钝。区分两者的实验判据：若曲线形状相似、只是整体平移，更像学习率折扣；若延迟版在评估点上更平顺、毛刺更少，则说明延迟特有的平滑效应在起作用。

4. 实现上的口径问题

延迟实现最容易犯的错是评论家与演员复用同一批数据。本章让两者各自独立采样一个 batch：演员更新时评论家参数已经变化，独立采样让三种 delay 的诊断口径完全一致，也避免策略损失带上"评论家刚记住这批数据"的偏差。

5. 三种节奏的取舍对照

delay=k演员更新比例预计收益预计代价适用情形
1（基线）100%无策略直接消费每步的 Q 噪声Q 估计已较稳、追求最快学习
250%噪声被轻度平滑，通常与基线成绩相当少一半演员优化步默认折中，多数任务可先用它
425%更强的平滑，曲线上更少毛刺学习速度明显偏慢，同预算下回报偏低Q 噪声极大的任务才值得

读表的方法与第 033 章一致：先在固定预算下比较评估回报，再比较actor_updates 对账，最后换几个种子确认排序稳定。只有在"延迟档位成绩不掉、曲线更平"同时成立时，才可以说这个任务从延迟中获得了稳定性收益。

什么时候值得开启延迟，可以看三个信号：评估曲线在相邻两次记录之间来回大幅摆动，说明策略在各版 Q 估计之间被来回拉扯；|Q| 的均值增长快但不稳定，说明价值估计本身尚未收敛；策略损失的量级与 Q 损失量级相差悬殊，说明梯度被 Q 的噪声主导。三个信号出现两个以上，把 delay 调到 2 试一次是合理动作；都不明显时保持 delay=1，把学习速度放在第一位。

6. 三层时间尺度的叠加

延迟更新的"慢"来自三层时间尺度的叠乘。第一层是目标网络的惯性：τ=0.005 时半衰期约 138 次评论家更新；第二层是演员节拍：每 k 次评论家更新才消费一次价值估计；第三层是熵修正：策略目标里始终带着 −α·log π，让策略不会一步贴死当前 Q 的峰值。取 k=4，两层惯性叠乘后的滞后窗口约 552 次更新（138×4），在 15000 步、约 14000 次更新的预算里，这一窗口约占训练全程的百分之四，因此 delay=4 的前几个评估点（3000、6000、9000 步）回报爬升明显更缓，属于时间常数变大的必然后果，与算法正确性无关。

这段分析也解释了收益侧：平均窗口越长，高频噪声被吃掉的成分越多，k=4 在 Q 噪声极大的任务上换来的是更平滑的曲线；但在 Pendulum 这种估计噪声有限的环境里，窗口再长也只吃掉了本就很小的抖动，收益自然观察不到。用同一套时间尺度算术可以预先估计任何 k 的后果：滞后窗口 ≈ 138k 次更新，超过总预算的十分之一时，就要准备好接受"同预算回报偏低"这个代价。

实现思路与设计

模块划分

组件职责关键点
update_critic()Bellman 残差 + 双 Q + 目标网络软更新每步调用；返回 |Q| 与 Q 损失
update_actor()策略损失 + 温度系数损失由训练循环按 critic_steps % delay == 0 触发；内部计数 actor_updates
train_delay()单种延迟的训练与日志日志同时打印演员更新次数，方便核对"少更新了多少"
critic_steps 计数器按评论家有效更新次数计节奏随机探索阶段不更新，二者不同步；用评论家次数计更准确

关键超参数

参数默认值作用与取值理由
--delays1,2,4本章唯一自变量：演员相对评论家的更新比
--max-steps15000每种延迟的步数预算，三种共享
--batch-size256评论家与演员各自独立采样 256 条
--alpha / --target-entropy0.2 / −1.0温度自动调节保持不变，隔离出延迟这一个变量
--tau0.005目标网络软更新，跟随评论家步执行

数据流

每种延迟：set_seed → 随机探索 1000 步垫池 → 之后每步先 update_critic（含软更新）、critic_steps 加一 → 当 critic_steps % delay == 0 时再 update_actor（用新采的 batch）→ 每 3000 步评估并记录评估回报、演员更新次数、|Q|、alpha → 保存模型并进汇总表。

与前一章的差异点

  • 前几章每步调用一个整体的 update()；本章把它拆成评论家与演员两个函数，这是实现延迟的前提。
  • 训练循环新增 critic_steps 与 policy_delay 的调度逻辑；温度系数更新跟随演员一起延迟。
  • 实验变量从"双 Q / 目标网络的存废"换成"更新频率比 k"。
  • 新增 actor_updates 轨迹：直观展示 delay=4 时演员少更新了约 75%。
为什么温度要和演员一起延迟

alpha 损失的输入是当前策略的 logp。策略没更新的那些步里，logp 分布原封不动，alpha 每步都去追同一个"熵缺口"只会反复超调。把温度绑定在演员的同一次调用里，策略变、温度才跟着变，两者共享同一份新信息。这一条会在第 041 章的"熵系数调度"里再次出现。

关键代码与解读

片段 1：update_critic，每步都跑的那一半

    def update_critic(self, batch):
        """评论家更新：每步都调用；同时做目标网络软更新。"""
        obs, act, rew = batch["obs"], batch["act"], batch["rew"]
        next_obs, done = batch["next_obs"], batch["done"]

        with torch.no_grad():
            # 目标动作来自"当前策略"的最新前向：评论家学习不受延迟影响
            next_act, next_logp = self.policy.sample(next_obs)
            q_next = torch.min(self.q1_target(next_obs, next_act),
                               self.q2_target(next_obs, next_act))
            target = rew + self.gamma * (1.0 - done) * (
                q_next - self.current_alpha * next_logp)

        q1_pred = self.q1(obs, act)
        q2_pred = self.q2(obs, act)
        q_loss = F.mse_loss(q1_pred, target) + F.mse_loss(q2_pred, target)

        self.q_optimizer.zero_grad()
        q_loss.backward()
        self.q_optimizer.step()

        # 目标网络软更新跟着评论家走（与 actor 延迟无关）
        with torch.no_grad():
            for p, tp in zip(self.q1.parameters(), self.q1_target.parameters()):
                tp.mul_(1.0 - self.tau).add_(self.tau * p)
            for p, tp in zip(self.q2.parameters(), self.q2_target.parameters()):
                tp.mul_(1.0 - self.tau).add_(self.tau * p)

        return {"q_loss": float(q_loss.item()),
                "mean_abs_q": float(q1_pred.abs().mean().item())}

解读：从原来的整体 update() 里切出的前半段，切分的位置很有讲究。（1）评论家段包含"算目标 → 双 Q 回归 → 软更新"三件事：无论策略是否延迟，评论家都要每步推进，这是"等评论家站稳"策略的前提，落后的那一端才需要等待。（2）目标里的 next_act 来自当前策略的最新前向（不是冻结副本、更不是延迟前的旧策略）：如果这里也"延迟"，价值目标会与真实策略脱节，软贝尔曼方程就不再成立。（3）软更新放在函数内部：目标网络的节奏与评论家完全绑定，调用者不需要操心。（4）返回值只带 q_loss 与 mean_abs_q：模块化的同时保持日志字段最小化。

片段 2：update_actor，按节奏才跑的那一半

    def update_actor(self, batch):
        """演员 + 温度系数更新：由调用方按 policy_delay 控制频率。"""
        obs = batch["obs"]
        new_act, logp = self.policy.sample(obs)
        q_new = torch.min(self.q1(obs, new_act), self.q2(obs, new_act))
        policy_loss = (self.current_alpha * logp - q_new).mean()

        self.policy_optimizer.zero_grad()
        policy_loss.backward()
        self.policy_optimizer.step()

        # 温度与演员共用同一批 logp：策略变，温度才跟着变
        alpha_loss = -(self.log_alpha * (logp + self.target_entropy).detach()).mean()
        self.alpha_optimizer.zero_grad()
        alpha_loss.backward()
        self.alpha_optimizer.step()

        self.actor_updates += 1
        return {"policy_loss": float(policy_loss.item()),
                "alpha_loss": float(alpha_loss.item()),
                "mean_logp": float(logp.mean().item())}

解读：切出的后半段负责"策略 + 温度"，两处细节承载本章的设计。（1）函数只接收 obs，为"独立采样"留出空间：调用者传入另一批数据，演员看到的是与评论家不同的样本，避免"评论家刚记过这批数据"的偏差。（2）温度损失用与策略损失同一次前向的 logp：两件事共享同一份"熵读数"，并且一起被延迟。这就是 box 里说的绑定关系在代码上的落点。（3）self.actor_updates += 1 是本章的诊断核心：训练结束后对比三种 delay 的计数（约 N、N/2、N/4），是"代价"最直白的证据。（4）返回 mean_logp 供日志观察策略熵水平的变化。

片段 3：主循环，采样仍是每步做

    for step in range(1, args.max_steps + 1):
        if step <= args.start_steps:
            action = env.action_space.sample()          # 纯随机垫池
        else:
            action = agent.act(obs, deterministic=False)

        next_obs, rew, terminated, truncated, _ = env.step(action)
        buf.add(obs, action, rew, next_obs, float(terminated))
        obs = next_obs
        ep_ret += rew

        if terminated or truncated:
            ep_returns.append(ep_ret)
            ep_ret = 0.0
            obs, _ = env.reset()

解读：采样侧与第 033 章完全一致，延迟只动更新侧，不动数据侧。（1）每步都采样、入池：缓冲区要持续获得新鲜数据，训练才不缺氧；延迟的是"策略消费数据的频率"，不是"环境产生数据的频率"。（2）float(terminated) 的终止语义再次出现；截断样本照常 bootstrap。（3）回合结束时重置环境、累计回报入 ep_returns，三种 delay 的采样侧行为逐字相同，实验的自变量因此只有一个。

片段 4：调度，用评论家计数做节拍器

        # 更新节奏：评论家每步更新；演员每 delay 次评论家更新一次
        if buf.size >= args.batch_size:

            history["actor_updates"].append(agent.actor_updates)   # 少更新了多少，一目了然
            history["alpha"].append(agent.current_alpha)

解读：本章的"新东西"全在这十行里。（1）节拍器用 critic_steps（评论家更新计数），不按环境步计时：热身阶段（前 1000 步）不产生任何更新，若按环境步计时，delay=2/4 的第一个触发点会与 delay=1 错位，用评论家更新次数计，三种 delay 的第一次演员更新都精确落在第 delay 次评论家更新上，口径干净。（2）演员的 batch 是新采样的：buf.sample() 被调用两次，两次结果不同。若图省事复用 `last_critic` 的那批，delay 越大评论家在这批数据上走的步子越多，策略损失就越偏向"评论家刚拟合的数据"。（3）actor_updates 每 3000 步记一次：跑完三种 delay 你会看到它约为 N、N/2、N/4，少更新的量被完整记账，这是理解"节奏代价"的直接证据。

完整可运行脚本（附录）：code/ch034.py

python code/ch034.py           # delay = 1 / 2 / 4：CPU 约 6–10 分钟
python code/ch034.py --quick   # 快速跑通：约 1 分钟
python code/ch034.py --delays 1,2 --max-steps 30000   # 只比较 1 与 2

以实跑为准：delay=1 与 delay=2 最终评估接近（差值常在 ±60 内），delay=4 学习速度偏慢；三种设置的 |Q| 幅度都不发散。单次排序会随种子翻转，结论要建立在多种子的均值上。延迟的主要意义是稳定性，不是速度。

常见坑

  • 用环境步数计时（应当用评论家更新次数）：热身阶段不产生更新，两种计时的相位差会让不同 delay 的第一批演员更新错位，实验对比失真。修复：用 critic_steps % delay。
  • 延迟了策略却忘记延迟 alpha：策略没变时 alpha 的梯度是"旧信息"，每步都更新会让 alpha 抖动放大。修复：把两者绑定在同一次调用里。
  • 以为 delay 能提升最终上限：延迟只改变"到达上限的路径"；在 Pendulum 这种估计噪声较小的环境里，三种节奏最终高度接近，别用单次实验下强结论。修复：把结论限定在"稳定性与速度的交换"上，并用多种子的均值支撑。
  • 评论家自举里的 next_act 用了旧策略：目标里的 next_act 必须来自当前策略的最新前向（本章如此），否则价值目标会与真实策略脱节。
  • 演员复用评论家的那批数据：delay 越大评论家在这批上走得越深，策略损失会带偏。修复：两次独立 sample()。

练习与思考

  1. 把 --delays 1,2,4 跑三遍，每次用不同 --seed，比较三种延迟的排序是否稳定。★
    提示
    单种子排序不可靠。整理成 3×3 的表格（行=delay，列=种子）观察排名翻转的幅度。
  2. 让温度系数不跟随延迟：把 alpha_optimizer.step() 那一段挪到每步都执行的逻辑里（例如放进 update_critic，用当前策略重新采样 logp）。解释可能出现的问题。★★
    提示
    策略没更新时 logp 分布不变，alpha 每步追同一个缺口容易冲过头。注意对比 alpha 轨迹的抖动与第 041 章"熵系数调度"的动机。
  3. 把 delay 序列扩展到 8,16，观察回报在哪个档位开始明显掉队；再用 --max-steps 60000 看掉队属于"慢"还是"学不动"。★★
    提示
    比较相同评估点（如 15000 步）与相同预算末尾两条曲线：前者衡量速度，后者衡量上限。
  4. 给 update_actor() 加一个替代调度：用"距离上次演员更新后评论家损失下降超过阈值"作为触发条件（自适应节奏）。★★★
    提示
    维护一个 Q 损失的滑动均值，只有当前损失低于均值一定比例才更新演员。记录每次触发的步距，看看它是否随训练自动变小。
  5. 给 update_critic() 与 update_actor() 分别包一层计时（time.perf_counter），跑三种 delay 各 3000 步，比较总墙钟时间与 actor_updates 的关系。★
    提示
    演员更新包含两次 Q 前向与一次采样，通常比评论家更新贵。预期 delay=4 的总时间略短，但回报也略低，把两者并列报告才公平。

小结

  • 延迟更新让演员等待评论家"站稳"再吸收其估计，降低策略参数被估计噪声带偏的程度。
  • 实现的关键是把整体更新拆成 update_critic() 与 update_actor()，并用评论家更新计数做调度。
  • 代价很明确：delay=k 时演员有效更新少 k 倍，学习速度可能下降；Pendulum 上 k=2 通常与 k=1 相当，k=4 偏慢。
  • 三种稳定手段各司其职：双 Q 管偏差、目标网络管错位、延迟管节奏。三者可以叠加使用，互不冲突。
