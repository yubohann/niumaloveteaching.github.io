第 078 章：多智能体SAC：参数共享

三个同质智能体，为什么要开三份 SAC 的工资？本章把它们合并成一套共享的 Actor、双 Q 与温度参数，把三份经验拼成一个大 batch，与"各管各的"版本正面比样本效率。

  • 主题：参数共享 / off-policy 批次池化
  • 关键公式：LQ(φ) = (1/N)Σi𝔼[(Qφ(oi,ai) − yi)2]，一套参数服务所有智能体
  • 预计学时：50 分钟
  • 前置章节：第 077 章

学习目标

  • 理解参数共享在 off-policy 学习里的意义：把 N 个智能体的转移池化进同一个更新。
  • 掌握共享 SAC 的实现三个要点：展平联合批次、按 N 重复 done 掩码、共享单一温度参数。
  • 对比共享与独立的参数量、样本效率与最终成绩，解释差异来源。
  • 理解共享的适用边界：同质任务编码对称先验；异质团队需要条件共享。
  • 把"共享"与第 077 章的"集中"区分开：前者省参数、增数据；后者加视野。两者正交可组合。

背景与动机

合作导航里的三个智能体是完全同质的：同样的观测结构、同样的动作权限、同样的动力学，任务奖励也对称。让它们各自维护一套 SAC，相当于把同一道题的三份答案分开学，每份只见到自己经历的数据。参数共享（parameter sharing）把这件事反过来：一个策略网络、一对 Q 网络、一个温度，服务所有智能体；每个环境步产生的 N 条转移全都进同一个回放池，采样后拼成一个大 batch 一次更新。

收益有两层：数据层面，同一套参数每个更新看到约 N 倍的经验，批评家回归更稳；模型层面，参数量降到约 1/N，部署与内存都更省。第 070 章在 PPO 上验证过这条路线，本章看看在 off-policy 的 SAC 上是否同样成立，如果成立，后面的通信、对称、信用分配章节都会默认采用共享版作为底座。

核心原理

1. 共享 SAC 的更新目标

共享意味着一组参数同时服务 N 个智能体，其目标函数是所有智能体软 Q 目标的平均（或求和）：

LQ(φ) = (1/N) Σi 𝔼[ ( Qφ(oi, ai) − yi )2 ]，  yi = ri + γ(1−d)[ mink Qktgt(o′i, a′i) − α log πθ(a′i|o′i) ] φ 是共享 Q 参数、θ 是共享策略参数；i 遍历智能体。实现上把 (B, N, ·) 展平成 (B·N, ·) 即可，无需真的写平均

注意温度 α 也是共享的一份：目标熵 −dim(A) 对每个智能体一样，共享没有明显副作用（练习 5 会让你验证这一点）。误差被平均后，单个智能体的异常批次对参数的冲击也变小，这是"方差分摊"的又一体现。

2. 样本效率的账本

独立模式：每个智能体每次更新采样 B 条自己的数据，参数只见到 B 条，但 N 个学习器各算一次梯度。共享模式：一次采样 B 个时刻 × N 个智能体，共 B·N 条数据进同一个优化器，同样的梯度步数，共享网络看到 N 倍样本。代价是梯度混合了不同智能体的状态分布：如果它们的分布差异很大（异质任务），共享会引入干扰；同质任务里这不构成问题。

把两个模式的计算量也摆出来：独立模式一次更新做 N 次前向/反传（每次 B 条）；共享模式做 1 次（B·N 条）。总的样本-梯度工作量级相当，但共享的批次更大、更稳，且每个 epoch 只有一次优化器步，这也是它收敛曲线更平滑的原因之一。

3. 共享与集中的区别

第 077 章的集中 Q 回答"批评家能看到什么"；本章的参数共享回答"有多少套参数"。两者正交，可以自由组合：

  • 集中 + 独立：每个智能体一套参数，Q 看全局（第 077 章 central）；
  • 共享 + 独立：一套参数、Q 只看局部（本章 shared）；
  • 集中 + 共享：一套参数、Q 看全局，这正是第 084 章对比时最常用的组合。

把这张二维表记住，多智能体 SAC 的后续章节就是在这两个维度上继续添加机制（通信、对称、信用分配）。

4. 实现上的两处"对账"

展平 (B, N, ·) → (B·N, ·) 时有两处必须同步：done 掩码要按 N 重复（一个时刻的 done 对所有智能体一致，但展平后需要 N 份）；奖励用个体奖励 rew[:, i] 展平（本章统一用个体奖励，与第 076 章 own 模式口径一致）。少做任何一处，Bellman 目标的自举就会张冠李戴。

实现思路与设计

模块划分

组件职责关键点
sac_update抽出的通用 SAC 更新函数批评家 → 策略 → 温度 → 软更新；两种模式共用
IndependentLearner独立模式：一套参数 × N从联合批次取自己那一列
SharedLearner.update共享模式：展平后单次更新reshape(B·N, ·)；done 按 N 重复
evaluate评估接口传入策略列表；共享模式下列表元素是同一个对象

关键超参数

参数默认值作用与取值理由
--modeboth同预算对照独立与共享
--batch-size128采样 B 个时刻；共享模式实际更新样本 B·N=384 条
--max-steps20000环境步预算
--hidden / --lr64 / 3e-4共享单网络容量与学习率
参数量对照—共享约为独立的 1/3（策略与 Q 都只留一份）

数据流

采样与存储与第 076 章一致。更新时：shared 模式把 batch 里所有列展平后调用一次 sac_update；indep 模式循环 N 次、每次喂 [:, i] 列。评估函数接收"策略列表"：共享模式用 [learner.policy] * n 填列表，同一个对象出现 N 次，评估接口无需分叉。

与第 077 章的差异点

第 077 章改的是批评家视野（集中 Q）；本章把独立模式的 N 套参数合并为 1 套（批评家仍是局部观测版本），数据拼成大批次。代码上新增 SharedLearner，并把 SAC 更新抽成 sac_update 公共函数，保证两种模式的更新语义逐字一致。

关键代码与解读

片段 1：抽出通用 SAC 更新函数

def sac_update(policy, q, q_target, policy_opt, q_opt, log_alpha, alpha_opt,
               obs, act, rew, next_obs, done, gamma, tau, target_entropy):
    """通用单网络 SAC 更新：批评家 -> 策略 -> 温度 -> 软更新。"""
    alpha = log_alpha.exp()
    with torch.no_grad():
        next_act, next_logp = policy.sample(next_obs)
        q1t, q2t = q_target(next_obs, next_act)
        target = rew.unsqueeze(-1) + gamma * (1.0 - done).unsqueeze(-1) * (
            torch.min(q1t, q2t) - alpha * next_logp)
    q1, q2 = q(obs, act)
    q_loss = F.mse_loss(q1, target) + F.mse_loss(q2, target)
    q_opt.zero_grad()
    q_loss.backward()
    q_opt.step()

    new_act, logp = policy.sample(obs)
    q1n, q2n = q(obs, new_act)
    policy_loss = (alpha.detach() * logp - torch.min(q1n, q2n)).mean()
    policy_opt.zero_grad()
    policy_loss.backward()
    policy_opt.step()

    alpha_loss = -(log_alpha * (logp.detach() + target_entropy)).mean()
    alpha_opt.zero_grad()
    alpha_loss.backward()
    alpha_opt.step()

    with torch.no_grad():
        for p, p_t in zip(q.parameters(), q_target.parameters()):
            p_t.data.mul_(1.0 - tau).add_(tau * p.data)
    return {"q_loss": q_loss.item(), "policy_loss": policy_loss.item(),
            "alpha": float(alpha.item())}

解读：函数化的第一个好处就在眼前，"独立与共享"的差异被完全压缩到调用方，算法语义只有这一份实现。（1）签名里网络、优化器、温度以参数传入：policy/q/q_target 加三个优化器，任何一个学习器实例都能复用。（2）广播形状约定：rew、done 传进来是 (M,) 一维，函数里 unsqueeze(-1) 对齐 Q 输出的 (M,1)。两个模式只要在调用前把数据整理成一维即可。（3）alpha 在批评家目标里直接用（无梯度）、在策略损失里 .detach()：与单智能体篇完全一致。（4）软更新在函数内部完成：调用一次更新一次目标网络，共享模式下每个环境步只有一次软更新，而独立模式有 N 次；这是两者在"目标网络新鲜度"上的隐性差异，写实验结论时可以提一句。

片段 2：共享学习器，展平批次

    def update(self, batch):
        """把 (B, N, ·) 展平成 (B·N, ·) 后做一次大更新。"""
        B, N = batch["obs"].shape[0], batch["obs"].shape[1]
        obs = batch["obs"].reshape(B * N, -1)
        act = batch["act"].reshape(B * N, -1)
        rew = batch["rew"].reshape(B * N)                       # 个体奖励展平
        next_obs = batch["next_obs"].reshape(B * N, -1)
        done = batch["done"].unsqueeze(1).repeat(1, N).reshape(B * N)  # 按 N 重复
        return sac_update(self.policy, self.q, self.q_target, self.policy_opt,
                          self.q_opt, self.log_alpha, self.alpha_opt,
                          obs, act, rew, next_obs, done,
                          self.gamma, self.tau, self.target_entropy)

解读：十二行代码，三处形状对账。（1）reshape(B*N, -1) 把"时刻 × 智能体"两个维度合并：展平顺序是"时刻优先"（先列出一个时刻的 N 个智能体，再到下一时刻），与 done 的重复方式必须一致。（2）done 原始形状 (B,)，用 unsqueeze(1).repeat(1, N) 变成 (B,N) 再展平，这样第 t 个时刻的 N 条样本拿到同一个 done 值。如果偷懒用 repeat 直接重复整段（变成长度 B·N 的"块状"序列），与"时刻优先"的展平顺序错位，掩码会张冠李戴。正确的做法也可以用 np.repeat(done, N)（逐元素重复），关键是"每个时刻重复 N 次"，"整段复制 N 遍"会错位。（3）奖励同样展平后一次性回归：共享 Q 的损失自动等于"对所有智能体求平均"的形式化目标，不需要手工加权。

片段 3：独立学习器的对照实现

    def update(self, i, batch):
        # 只取第 i 个智能体的列：观测、动作、奖励、下一观测
        return sac_update(self.policy, self.q, self.q_target, self.policy_opt,
                          self.q_opt, self.log_alpha, self.alpha_opt,
                          batch["obs"][:, i], batch["act"][:, i], batch["rew"][:, i],
                          batch["next_obs"][:, i], batch["done"],
                          self.gamma, self.tau, self.target_entropy)

解读：与共享版对照着看，差异只有"数据切片"这一步。（1）[:, i] 取第 i 个智能体在所有时刻的列：形状 (B, ·)，与单智能体 SAC 完全一致。（2）done 直接用 (B,) 原样（不重复）：因为它本来就对应"每个时刻"，而这一列也只有 B 条。（3）每个智能体有独立的 policy/q/q_target/温度与三个优化器，参数量是共享版的 N 倍，数据量只有 1/N。（4）同一时刻的联合数据被 N 个学习器各自使用：训练信号上的"数据共享"仍然存在（同一个池子），但参数不共享，这正是两章的本质区别。

片段 4：主流程的两种组织方式

    if mode == "shared":
        learner = SharedLearner(env.obs_dim, env.act_dim, args, device)
        learners, policies = [learner], [learner.policy] * n      # 同一对象重复 N 次
        n_params = sum(p.numel() for m in [learner.policy, learner.q]
                       for p in m.parameters())
    else:
        learners = [IndependentLearner(env.obs_dim, env.act_dim, args, device)
                    for _ in range(n)]
        policies = [l.policy for l in learners]                    # N 个不同对象
        n_params = sum(p.numel() for m in
                       [l.policy for l in learners] + [l.q for l in learners]
                       for p in m.parameters())
    label = "SHARED" if mode == "shared" else "INDEP"
    print(f"[{label}] 可训练参数量 {n_params}")

解读：这段代码用 Python 的"对象引用"把共享语义变得极其直白。（1）共享模式下 [learner.policy] * n 创建长度为 N 的列表，但所有元素指向同一个策略对象，采样、评估循环里 policies[i] 无论如何取都是同一套参数，共享自动生效。（2）参数量统计：共享版统计 [policy, q] 两份模块；独立版统计 N 个 policy + N 个 q，日志里的数字会直观显示约 1/3（Q 与 policy 各占一部分参数）。（3）训练循环里的调用差异只有一行（learners[0].update(batch) vs 循环 learners[i].update(i, batch)），其余采样、存储、评估完全共享代码。（4）评估接口 policies 列表因此"形似而神不同"：共享模式列表里是同一个对象，评估逻辑无需区分两种模式，这是设计上的小优雅。

以实跑为准的预期：shared 版早期评估点通常领先（约 8000 步内到 −8 附近），参数量约为 indep 的 1/3；最终两者接近（约 −8 ~ −4）。任务对称时共享几乎无副作用；曲线更平滑来自更大 batch 与单一优化器。以实跑为准。

常见坑

  • done 掩码的重复方式与展平顺序不匹配：正确是"每时刻重复 N 次"（unsqueeze(1).repeat(1,N)），错误是"整段复制 N 遍"。两者长度一样、形状合法，只有 Bellman 语义不同，最阴险的一类 bug。
  • 共享模式下评估还在用 N 个不同对象：如果 policies 列表误建成 N 个独立拷贝（例如深拷贝了 policy），训练仍是共享、评估却用了"过期副本"，行为对不上。
  • 奖励口径与第 076 章不统一：本章统一用个体奖励；若混用团队奖励，两章结果无法横向比较。写报告时标明口径。
  • 把共享当万能药：异质任务上，共享网络被迫折中不同角色的最优行为，可能显著变差。先检查任务是否真的同质。
  • 比参数量时忘了 Q 网络：参数量节省既包括 policy 也包括 Q；只统计 policy 会低估节省的总参数量（Q 一般占大头）。

练习与思考

  1. 对比日志第一行的参数量：shared 是 indep 的几分之一？手算验证：3 层 MLP 的参数量公式与 hidden=64、输入维数代入。★
    提示
    policy：(14→64)+(64→64)+(64→2)；Q：(16→64)+(64→64)+(64→1)×2（双 Q）。分开算再对总数。
  2. 把 --batch-size 从 128 改到 64 与 256，观察两种模式的收敛速度和曲线噪声。共享模式对 batch 大小更敏感还是更不敏感？★
    提示
    共享模式的实际更新样本是 B·N：B=64 时已经相当于独立模式的 192；它可以承受更小的采样 B。注意比较"总样本量"；"采样时刻数"会低估共享版的实际更新量。
  3. 造一个异质任务：给智能体 0 的加速度减半（改环境），比较 shared 与 indep。共享的代价有多大？★★
    提示
    共享策略对"自己是谁"没有概念，只能在两套最优行为之间折中。预期 shared 明显变差；这为"条件共享"（身份输入）的需求提供证据。
  4. 给共享策略加身份输入（one-hot ID 拼进观测），在异质任务上重跑，比较它与无条件共享、独立版的成绩与参数量。★★
    提示
    这即第 072 章"条件共享"的 SAC 版。参数量仍远小于独立版，但表达能力恢复了角色区分。
  5. 实验验证"共享温度"是否合理：比较共享单温度与应用三个独立温度（每个智能体一份 α）的版本，在异质任务上看 α 的收敛值与性能差异。★★★
    提示
    需要把 log_alpha 改成 (N,) 并按智能体索引取用；若某个智能体的状态分布更难，它的最优 α 会显著不同，这能帮你理解"共享哪些参数"本身就是一个设计问题。

小结

  • 参数共享 = 一套 Actor + 一对 Q + 一个温度服务全部智能体；数据池化进同一次更新，样本效率约 ×N、参数量约 ÷N。
  • 实现三步：展平 (B,N,·)→(B·N,·)；done 按 N 重复（逐时刻重复，整段复制会错位）；个体奖励展平回归。
  • sac_update 公共函数保证独立/共享两种模式的算法语义逐字一致，差异只在调用方。
  • 共享与集中正交："省参数、增数据" vs "加视野"；集中+共享是后续章节的常用底座。
  • 适用边界：同质任务共享几乎免费；异质团队需要条件共享（身份输入），否则性能折中。
  • 下一章给共享策略加通信通道：智能体在动作之外广播消息，SAC 版的消息头如何训练、消息如何进入 critic，是新的实现问题。
