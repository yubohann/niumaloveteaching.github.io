第一篇 · 策略梯度与 PPO

第 016 章：PPO的多任务学习

让一个共享网络（观测拼任务 one-hot）同时学会轻/标准/重三种重力的 CartPole，对照三个独立专精网络：用同样的总环境步数，比较每任务成绩、参数量与训练时间。

  • 主题：多任务学习 / 条件策略
  • 关键公式：πθ(a|s,z)，Vθ(s,z)，z = one-hot(task)；∇L = Σtask∇Ltask
  • 预计学时：60 分钟
  • 前置章节：第 015 章

学习目标

  • 理解多任务强化学习的两种基本架构：共享网络 + 任务标识（条件策略）与每任务独立网络。
  • 实现任务 one-hot 观测包装器与按回合轮换的任务采样，构造多任务训练管线。
  • 正确处理多任务数据的回合边界：按整回合采样、用回合末观测做 bootstrap，避免跨任务串台。
  • 对比共享与专精两种方案：参数量、每任务达标步数、最终评估与总耗时。
  • 理解负迁移与任务干扰的来源，知道什么时候该共享、什么时候该分开。

背景与动机

上一章你学会把"会做的事"迁移到新任务；但如果下游任务有一打呢？为每个任务单独训一个网络既费参数又费训练时间。多任务学习给出一条捷径：一个网络接收"任务标识"作为额外输入，所有任务共享同一套权重，网络把"怎么看状态"的通用特征复用，把任务差异交给输入里的条件信号。

这条路径有两面性。正面是参数效率与特征共享：本实验里共享网络只用约 1/3 的参数，且轻任务与标准任务几乎不输专精网络。反面是任务干扰：不同任务对同一组权重提出的梯度方向可能相反，重任务可能被轻任务"拖后腿"（负迁移）。本章用三种重力刻意制造"同结构、不同难度"的任务族群，把这两个面都量化出来。多任务思想在后面无处不在，第 069 章的多智能体 CTDE、第 075 章的混合合作竞争，用的都是同一套"条件化 + 共享"逻辑。

核心原理

1. 条件策略：把任务变成输入

多任务的目标是学习一个条件策略与条件价值：

πθ(a | s, z)，　Vθ(s, z)，　z = one-hot(task) z 也可以是目标点、语言指令、对手特征等任意条件信号

共享参数让不同任务的数据共同塑造特征提取器，每个任务的有效样本量因此"看起来"翻了几倍；但条件信号必须正确区分任务，把 z 拼进观测是最简单、对本实验完全够用的做法（因为它不改变动力学，只改变可观察到的标识）。

条件策略有一个隐蔽的失效模式：网络可能学会忽略 z。若任务间差异不够大，"平均策略"在三个任务上都能拿分，梯度会把 z 方向的权重压到接近无用，表现为三个任务的策略输出几乎一样。检测很便宜：评估时把 z 换成错误任务的 one-hot 再测一次，若成绩不变，说明标识未被利用；若成绩崩掉，说明策略过度依赖标识。健康状态介于两者之间，评估表最好常设"错标识压力测试"这一列。

2. 干扰与负迁移

梯度是多任务损失之和；两个任务是否"拔河"，可以直接看它们梯度内积的符号：

∇L = Σtask ∇Ltask，　⟨ ∇LA, ∇LB ⟩ < 0 ⇒ 梯度冲突 内积为负意味着提高一个任务的损失会压低另一个，共享权重只能妥协

出现冲突时，共享权重会牺牲其中一个（通常是更难的）来迁就另一个。判断干扰是否发生的方法很直接：与专精网络对比同预算下的每任务成绩。共享版明显更差的那些任务，就是被干扰的一方。缓解手段包括：任务采样加权（给难任务更多样本）、共享躯干 + 任务专属头（部分解耦）、以及梯度手术类方法（如 PCGrad，本章不展开）。

数值算例：梯度冲突到什么程度会互相拖累

把两个任务的躯干梯度简化成二维向量。温和冲突：gA=[1.0, 0.5]、gB=[0.2, −1.0]，内积 −0.30、夹角余弦约 −0.26。共享权重按 gA+gB 更新时，沿 A 方向每步推进从 1.118 降到 0.850（少 24%），沿 B 方向从 1.020 降到 0.726（少 29%），两个任务都被拉慢，谁都没有倒退。

激烈冲突：gA=[1, 0]、gB=[−1.8, 0.87]，内积 −1.80、余弦 −0.90。此时共享更新沿 A 方向的推进量是 −0.80，A 的损失在共享更新下不降反升。判据可以记下来：当 ⟨gA, gB⟩ < −‖gA‖² 时，A 每步都在吃亏。本章 T2（重任务）比 T0（轻任务）更容易落进这个区间，这就是负迁移的数学形态；练习 4 会教你实测这对梯度并报出余弦值。

3. 采样与数据组织

on-policy 多任务没有"数据集"，任务调度就是数据分布。本章采用回合级轮换：每个回合结束后切换到下一个任务，保证长期上各任务样本数均衡；同时每轮更新混入不同任务的轨迹，梯度是对多种动力学的平均。另一个常见方案是每轮固定从某任务采一整批（交替更新），会引入"批间分布漂移"，本章不用。

调度只影响训练数据的分布，不影响评估口径：评估必须逐任务单独做、回合数固定，任何"三任务平均分"的汇总都会把单任务的退化藏起来，而退化恰恰是干扰最需要暴露的信号。

4. 回合级轮换的真实步数分布

"每回合切换任务"保证的是回合数均衡，步数均衡却会随学习进度漂移。举一组具体数字：训练早期三个任务的典型回合长度是 150、160、100 步，步数份额为 150/410 ≈ 0.37、0.39、0.24，已经偏离 1/3；训练后期轻任务先学会，回合变长到 300 步，而重任务仍在 100 步附近，份额变成 300/560 ≈ 0.54、0.29、0.18。学得越好的任务拿到越多梯度步，这与"给难任务更多样本"的直觉相反，也是负迁移的一个放大器。对策有两类：按步数配额采样（每轮从任务池里抽到配额用完为止），或显式加权轮换（难任务一份样本抵两倍），后者正是练习 3。报告三种任务的累计步数份额，是检查采样是否失衡的最低成本手段。

5. 任务扩展的边际成本

每多一个任务，共享臂只需在输入里多一维 one-hot，第一层多 64 个权重（hidden=64）；专精方案要多一整套 4675 个参数，两者相差约 73 倍。部署侧同理：共享臂线上只装一份权重、按任务标识切换，专精臂要装 n 份权重并管理其版本。三档方案的参数账（本章网络，逐层数出）：全共享 4867、共享躯干加三个任务头 5065、全专精 14025。共享躯干加任务头的方案参数只比全共享多约 200 个（三个头部相对一个头部的增量），却换来各任务独立决策头，是实践中优先尝试的中间档。

6. 回合边界必须按任务隔离

多任务采样最容易出错的地方是 GAE：如果多个任务各自在 500 步被截断，把它们的转移首尾相接、用下一个任务的首状态做 bootstrap，优势估计就会跨任务串台。本章的解法是按完整回合收集、每回合用自己最后观测的价值做 bootstrap，这也是对第 001 章"截断处理"细节的一次正式修补。

数据流

共享臂：一个网络 + 三个 TaskObsWrapper 环境 → collect_episodes 按回合轮换采样（每批含多任务轨迹），每回合独立算 GAE → 10 epochs 更新 → 循环到总预算 3×5 万步。专精臂：三个网络依次各训 5 万步（每个只用单任务环境、4 维输入）。最后每任务贪婪评估，并报告参数与耗时。

耗时的口径要说清楚：两臂的总环境步数相同（各 15 万），单步成本也接近（共享臂观测多 3 维，可忽略），所以"墙钟时间"的差异主要来自实现方式。共享臂一次训练循环同时产出三个任务，省下的是三次独立训练的启动、评估、调参与配套管理开销；专精臂若串行跑，纯训练段耗时与共享臂相当，若并行到三台机器则墙钟更短，但总算力消耗反而更高。报告里建议把"纯训练用时"与"含工程迭代的总用时"分开写，两者给出的结论可能不同。

评估数字的粒度也要对齐：每任务 10 个贪婪回合的均值标准误约 16 分（单回合波动按 50 分计），而共享与专精的典型差距常在 10～20 分，正好落在噪声量级。报告这类小差距时，把评估回合加到 30（标准误约 9 分），或用三个种子取均值，避免"谁更好"的结论随种子翻转。

为什么按"完整回合"收集、不拼一条长序列

多任务/多环境采样有两种写法：把所有环境的转移拼成一条长序列统一算 GAE，或按回合分段各自计算。前者在"哪个时刻属于哪个任务"上极易出错：截断处用错 V(st+1) 就等于跨任务串台。本章选择更笨但更稳的做法，每个回合自带一次 compute_gae，回合末观测 net.value(obs_t) 做 bootstrap。实现多几行，正确性高一个数量级。

关键代码与解读

片段 1：任务标识包装器，4 维观测变 7 维

class TaskObsWrapper(gym.ObservationWrapper):
    def __init__(self, env, task_id: int, n_tasks: int):
        super().__init__(env)
        self.task_id = task_id
        self.onehot = np.zeros(n_tasks, dtype=np.float32)
        self.onehot[task_id] = 1.0                     # 任务标识：固定值
        low = np.concatenate([env.observation_space.low, np.zeros(n_tasks, dtype=np.float32)])
        high = np.concatenate([env.observation_space.high, np.ones(n_tasks, dtype=np.float32)])
        self.observation_space = gym.spaces.Box(low=low, high=high, dtype=np.float32)

    def observation(self, obs):
        return np.concatenate([obs, self.onehot]).astype(np.float32)   # 拼在尾部

解读：（1）one-hot 在包装时一次算好、之后不变：任务是"外部条件"，不需要环境动态提供，评估时用同一个包装器，标识值与训练完全一致。（2）必须同步更新 observation_space：新维度的上下界是 [0,1]（one-hot），拼在原始界之后。忘了更新会让网络构建时用错 obs_dim，报形状错误还算好事，用错维度才难查。（3）observation() 每次返回新数组（np.concatenate 复制）：不要试图原地修改观测，gym 的观测可能被环境复用。（4）为什么用 one-hot、不用一个整数 ID：整数会让"任务 0 与任务 2 的距离是任务 1 的两倍"这种无意义的序关系进入网络；one-hot 让三个任务在输入空间里完全等价、互不干扰（网络自己学怎么区分）。

片段 2：按回合收集，跨任务隔离的正确姿势

    while total_steps < steps_target:
        env = envs[task]                      # 取出“当前任务”的环境
        obs, _ = env.reset()
        obs_t = to_tensor(obs, device)

        obs_l, act_l, logp_l, rew_l, val_l, term_l = [], [], [], [], [], []
        ep_ret = 0.0
        done = False
        while not done:                       # 完整跑完一个回合
            a, logp, v = net.act(obs_t)
            next_obs, r, terminated, truncated, _ = env.step(a)
            obs_l.append(obs_t.squeeze(0).cpu().numpy())
            act_l.append(a)
            logp_l.append(logp)
            rew_l.append(r)
            val_l.append(v)
            term_l.append(float(terminated))
            ep_ret += r
            obs_t = to_tensor(next_obs, device)
            done = terminated or truncated

        # 用“本回合结束时”的观测做 bootstrap：截断有效、终止时被掩码置零
        last_value = net.value(obs_t)
        adv, ret = compute_gae(rew_l, val_l, term_l, last_value, gamma, lam)
        obs_buf.extend(obs_l)
        act_buf.extend(act_l)
        logp_buf.extend(logp_l)
        adv_buf.append(adv)                   # GAE 结果按回合分段保存
        ret_buf.append(ret)
        ep_returns[task].append(ep_ret)

        total_steps += len(obs_l)
        task = (task + 1) % len(envs)         # 回合级轮换：长期均衡各任务样本

解读：（1）回合循环的结构是"取任务 → 跑完整回合 → 单独算 GAE → 切任务"：每个回合的优势只由自己那些步和自己的末端观测决定，绝不跟其他任务的转移混在一条序列里。这是本章与第 001–015 章在数据组织上最大的区别。（2）last_value = net.value(obs_t)：用回合真正结束时（或截断时）的观测估值。CartPole 的 500 步上限是 truncated，掩码不会置零，bootstrap 用的就是它；真终止时掩码把它清零。（3）adv_buf.append/concatenate 与 obs_buf.extend 的顺序必须一致：都是"回合 0、回合 1、…"的客观顺序，更新时两者才对齐。（4）task = (task + 1) % len(envs)：简单轮换保证长期各任务样本均衡；练习 3 会把它改成加权调度（难任务出现 2 倍），观察取舍。

片段 3：共享臂的主循环，预算与首达统计

解读：（1）ep_returns 是从 collect_episodes 返回的"按任务分组的回合回报"字典：网络是全共享的，但账要分任务记，否则无法比较哪个任务学得好。（2）step_share 的均摊是估算：批次里的步数并不严格三等分（回合长度随机），长期轮换下误差可忽略；报告里注明口径即可。（3）每个任务独立维护 reached_at / spent_steps：达标步数用"该任务名下累计的步数"衡量，才与专精臂的按步数口径可比。（4）共享臂更新用的批数据天然混合多任务（每批约 4～10 个回合覆盖不同任务）：一次梯度步同时服务三个任务，这就是"干扰"发生的物理现场，冲突任务的梯度在这里直接相加。

解读：（1）评估函数接收"环境列表"，逐任务跑贪婪策略：共享臂传同一网络 + 三个环境；专精臂传三对（环境、网络）。接口统一，报告格式也统一。（2）n_params 是单网络的参数量；total_params 分口径：共享臂 = 1 份，专精臂 = 3 份（部署时要装三套权重）。（3）对比表用的 total_params：共享臂 4867 对专精臂 14025，比例 0.35，参数量是本章新增的"第三维度"（成绩、时间之外的效率）。（4）逐层核对这两个数：4 维网络第一层 4×64+64 = 320、第二层 64×64+64 = 4160、actor 头 130、critic 头 65，合计 4675；共享臂的 7 维输入让第一层多 3×64 = 192，合计 4867。对比时共享臂必须用 4867，拿不加标识的 4675 当共享臂会低估；逐层加一遍是核对参数量数字的唯一可靠办法。

预期结论（以实跑为准）：共享网络用约 1/3 参数，在 T0（轻）/T1（标准）上接近专精网络（差距常在 10～20 分内），在 T2（重）上通常最吃亏，达标更晚、评估低 20～40 分，这就是任务干扰的代价；专精网络的墙钟时间更长（三份网络串行训练），但每个任务拿到 100% 容量。结论不是"共享一定好"：任务相似、参数预算紧 → 全共享；冲突明显 → 共享躯干 + 任务头；成绩优先 → 专精。

常见坑

  • 多任务 GAE 跨任务串台：把多个环境的转移拼成一条序列（或依赖 values[t+1] 的隐式 bootstrap）会在截断处用错状态估值。按回合收集、每回合用自己的末观测 bootstrap。
  • 评估时任务标识不一致：训练用 7 维（one-hot 激活），评估用 4 维或错位 one-hot，策略会输出垃圾动作。评估环境必须用同一套包装器。
  • 任务采样失衡：某任务回合特别长（学得越好回合越长），按"回合数"均衡会让它的样本占比悄悄膨胀；按"步数"预算或加权调度更可控。
  • 参数量口径混乱：比较共享与专精时，要么都报"可训练参数量"，要么都报"部署时需要的参数量"；专精方案部署三套网络，参数量必须 ×3。
  • 忘更新 observation_space：包装后观测变 7 维但空间定义还是 4 维，网络构建、评估与日志会用错维度；包装器的空间更新必须和拼接逻辑一起改。

练习与思考

  1. 把任务集合改成"重力 7.0 与 14.0"两个极端，观察共享网络的成绩与专精的差距是否扩大，解释负迁移。★
    提示
    改 GRAVITIES 即可（注意任务数变化会自动传播到 one-hot 维度）。难度差越大，梯度冲突越强，共享版在难任务上的劣势越明显。
  2. 实现"共享躯干 + 任务专属头"：躯干共享、策略/价值头按任务分裂，对比它与全共享、全专精的三档结果。★★
    提示
    把 actor/critic 换成 ModuleList，用任务 id 索引对应头。参数量介于两者之间（躯干 1 份 + 头 3 份），成绩通常也介于两者之间。
  3. 给任务采样加权重：让 T2（重）以 2 倍频率出现，观察它是否能追上专精网络，以及 T0 是否被牺牲。★★
    提示
    在 collect_episodes 里把简单轮换改成加权调度（如 [0,1,2,2]）。这是"难任务优先"的经典取舍，观察两个方向的代价。
  4. 测量任务间的梯度冲突：分别取 T0 与 T2 的一批数据，计算策略损失对躯干参数的梯度，报告两个梯度夹角的余弦。★★★
    提示
    分别 backward 两次并把梯度展平求余弦（中间要 zero_grad）。余弦为负说明存在拔河；可以对照本讲的判据 ⟨gA, gB⟩ < −‖gA‖² 判断是否已经到"损失反升"的激烈区间，并在训练早期与后期各测一次。
  5. 实现"错标识压力测试"：把每个环境的 one-hot 换成其他任务的标识，重新评估三任务成绩，比较共享臂与专精臂对错误条件的敏感度。★★
    提示
    给 TaskObsWrapper 加一个 override_id 参数即可，评估时按组合遍历。专精臂没有标识输入，作为不受影响的对照组；共享臂的成绩下滑幅度就是"条件依赖度"。

小结

  • 多任务 RL = 条件策略 π(a|s,z)：任务标识作为输入，共享权重复用特征、提升参数效率。
  • 任务干扰真实存在：共享网络在难度跨度大的任务上会出现负迁移，实验里重任务评估比专精低 20～40 分。
  • 按回合轮换采样 + 回合末 bootstrap 是保证多任务数据正确隔离的关键；拼批实现必须按环境分段处理 GAE。
  • 选型框架：任务相似、预算紧 → 全共享；冲突明显 → 共享躯干 + 任务头；成绩优先 → 专精。
  • 下一章把"共享"推进到"快速适配"：用元学习（Reptile）训练一个初始化，让新任务用几次梯度更新就能达标。
