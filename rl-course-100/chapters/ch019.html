第一篇 · 策略梯度与 PPO

第 019 章：PPO的课程学习

目标任务太重（重力 13）就先把难度降下来：从重力 7 起步，达标后再逐步加重。对照一直死磕目标任务的直训臂，看"由易到难"的课程能否更早把目标成绩推上去。

  • 主题：课程学习 / 难度调度
  • 关键公式：g1 < g2 < … < gK；mean(近20回合) ≥ 350 且距上次推进 ≥ 2 次更新 ⇒ g ← min(13, g+0.5)
  • 预计学时：60 分钟
  • 前置章节：第 018 章

学习目标

  • 理解课程学习（Curriculum Learning）的核心思想：把"难任务缺乏有效梯度"的问题转化为一串"刚好够难"的子任务。
  • 实现基于表现的自动推进课程：用近 20 回合均值作为升级条件，配合耐心窗口防止抖动推进。
  • 搭建公平的对比框架：两种方式都只在目标环境上评估，避免用不同难度的回报互相比较。
  • 读难度推进轨迹（重力随时间的变化），诊断课程推进太快或太慢。
  • 掌握课程学习与迁移/模仿的区别：它不注入外部知识，只改变任务出现的顺序。

背景与动机

第 015 到 018 章都在解决"起点"问题：迁移给权重、元学习给初始化、模仿给示范。这一章换了个完全不同的杠杆，给任务排序。目标任务（重力 13 的 CartPole）直接学也能学会，但前期大量样本都耗在"勉强站稳"上，有效梯度少、进展慢；如果早期先学重力 7 的轻任务，策略先掌握"平衡"这个通用技能，再来应付更重的负担，学习曲线会陡得多。

课程学习不改变算法、不增加数据、不需要专家，只改变训练时任务的出现顺序，是性价比极高的加速手段。难点在推进策略：升得太快，策略在新难度上表现崩盘，等于回到直训；升得太慢，预算全耗在简单任务上，最终落后于直训。本章用"近 20 回合均值 ≥ 350 且至少间隔 2 次更新"作为升级条件，把难度推进做成一个可控的反馈回路，并给出诊断它的方法。

核心原理

1. 课程是一串任务分布

把课程形式化为任务序列 (M1, M2, ..., MK)，难度参数从易到难（本章是重力）：

g1 = 7.0 < g2 = 7.5 < … < gK = 13.0，　训练数据 ~ Mk(t) k(t) 是难度调度；本章用"表现阈值 + 耐心"自适应调度

直观解释：策略的梯度信号强度取决于"当前能力与任务难度的差距"。差距太大（任务太难），奖励几乎总是同一水平，优势信号被噪声淹没；差距太小（任务太简单），策略已经没有改进空间。让难度始终跟在能力后面半步，是课程学习有效的核心机制。

2. 升级条件与耐心

本章的推进规则是：

若　mean(最近 20 回合回报) ≥ 350　且　距上次推进 ≥ 2 次更新　⇒　g ← min(13, g + 0.5)

两个门限各有用处：阈值保证策略已适应当前难度；耐心窗口防止"刚升级还没跑几步、旧窗口里还留着简单任务的回报"导致的连锁升级。升级后立刻重建环境并重置观测，环境对象持有动力学参数，必须重建或重新赋值后再 reset。

3. 为什么必须统一评估口径

课程臂的训练回报是"当前难度下的回报"，直训臂是"目标难度下的回报"。两者直接比较毫无意义：课程臂在重力 7 上拿 450 分不代表它在目标上也能拿 450。本章每 6 次更新在目标环境上跑一次贪婪评估，两条评估曲线才是同一把尺子。

4. 课程的边界与代价

三种情况下课程收益会消失甚至为负：任务族之间没有可共享的技能（纯随机难度切换）；推进条件设置得太松（等价于直训但少了目标环境的样本）；预算非常充裕（直训最终也能达到同样成绩，课程只影响曲线形状）。此外课程臂会"遗忘"简单任务的表现，如果部署时要覆盖全难度，需要在课程后期把难度分布混合回去。

5. 难度台阶的数值依据：反应窗口被压缩了多少

把直立点附近的 CartPole 线性化，可以得到"重力每加一级，反应窗口缩短多少"的定量答案。极角 θ 的动力学在 θ≈0 处近似为 θ¨ ≈ λ²θ，其中不稳定增长率 λ = √( g / [ l·(4/3 − mp/(mc+mp)) ] )。取标准参数 mc=1.0 kg、mp=0.1 kg、l=0.5 m，分母 l·(4/3 − mp/1.1) ≈ 0.6212，于是：g=7.0 时 λ≈3.36 /s；g=9.8 时 λ≈3.97 /s；g=13.0 时 λ≈4.57 /s。

无控制时θ按 cosh(λt) 增长。初始角按最不利的 0.05 rad 算，漂到终止阈值 12°（0.2095 rad）所需时间：g=7.0 约 0.63 秒，50 Hz 下约 31 个环境步；g=13.0 约 0.46 秒，约 23 个环境步。每升 0.5 的重力，可用的纠错时间平均少约 0.7 个环境步；十二级台阶累计压缩约 8 步，反应窗口缩小约四分之一。这组数字说明：目标难度并没有改变观测与动作空间，它压缩的是"策略犯一次错还能救回来"的余量，这正是直训臂前期大量样本消耗在"勉强站稳"上的物理原因。

同一套推算也解释了起始重力取 7.0 的依据：取值更轻会怎样？若从重力 4.0 起步，λ≈2.54 /s，同样的 0.05 rad 初始偏差给出约 0.83 秒、约 42 个环境步的反应窗口，极点几乎接近"中立稳定"，策略学到的纠错节奏与目标任务相差 44%（42 步对 23 步）。起始难度越高，技能的时序结构与目标越接近，迁移越顺；起始难度越低，前期越好学但学到的"慢动作"越需要重学。7.0 的取值在两个极端之间：相比目标压缩 27% 的窗口，仍在同一套动力学模式下，属于"半步之后"的合理起点。

6. 预算账：一条课程要吃掉多少更新配额

15 万步预算、每次更新 2048 步，共约 73 次更新。从 7.0 爬到 13.0 需要升 12 级，按"升级后至少等 2 次更新"的耐心窗口，仅冷却阶段就要花掉 24 次更新，约占预算的三分之一。再算升级判据的"新鲜度"：判据是最近 20 回合的均值，窗口的时间跨度约等于 20 × 平均回合长度 个环境步。回合长度约 200 步时，窗口只跨 2 次更新，2 次冷却足以让窗口基本翻新；回合长度约 350 步（恰在升级阈值附近时的典型值）时，窗口跨约 3.4 次更新，冷却 2 次之后仍有约四成回合来自旧难度。另外 len(all_returns) >= 20 的门限意味着前两三次更新不可能触发推进，这是滑窗统计意义的最小样本量要求，也让课程臂起步阶段的轨迹稳定可预期。耐心窗口只能降低连锁升级的概率，不能彻底消除它：2 次更新约带来 4096 步新数据，按 350 步/回合折算约 11.7 个新回合，窗口翻新约六成；更严格的做法是把耐心与实时观测的回合长度挂钩；固定更新次数的写法只是一个近似。

把连锁升级的最坏情形算一遍：升级后某次判定时窗口 20 回合中有 12 个新难度回合（回报 300）与 8 个旧难度回合（回报 450），均值 = (8×450 + 12×300) / 20 = 360，仍然越过 350 的阈值，于是课程会多升一级；再过 2 次更新，窗口变成 18 个新回合加 2 个旧回合，均值 = (2×450 + 18×300) / 20 = 315，判定失败，链条终止。耐心 2 允许的最坏情形是短时间内连升两级，随后被更新后的窗口自动纠正，这就是"冷却计数清零"在数值上的意义：它把无限制的连锁升级压缩成一次可恢复的过冲。

反向的失效同样有判据：课程停滞的表现是 gravity_trace 长时间没有新条目。若超过约 1.5 万步（约 7 次更新）难度未推进，先检查阈值是否高于当前难度的可达水平（例如在重力 12 之上仍要求 450），再把 --advance-reward 下调 50 或把起始重力调回一档重跑。

7. 评估频率决定"首达步数"的分辨率

每 6 次更新评估一次，73 次更新只有约 12 个评估点，评估间隔约 1.2 万步。这意味着首达 400 的步数带有约 ±6 千步的量化误差：真实的穿越时刻可能落在两次评估之间，日志只能记录靠后的那个点。报告课程收益时有一条经验判据：两臂首达差距若小于一个评估间隔（本例约 1.2 万步），应当视为分辨率不足，把 --eval-every 减半后重测再下结论。贪婪评估不影响训练轨迹，加密评估只是线性增加评估回合的计算量，属于低风险操作。

8. 三种难度调度方式的取舍

调度方式推进依据优点典型失效方式
固定时间表每 1 万步 +0.5完全可复现，无额外判断与学习速度脱钩：学得快就浪费、学得慢就崩盘
表现阈值（本章）近 20 均值 ≥ 350 且冷却 2 次跟随实际能力，自动调速阈值过高会停滞；冷却不足会连锁升级
阈值 + 回退（练习 3）跌破 150 时回退 0.5能从过冲中恢复，适合噪声大的任务双向阈值过密会造成难度震荡，轨迹难以解读

三种方式的对照口径相同：都在目标环境上评估。时间表课程常作为分布外泛化研究里的基线，它的价值在于"推进节奏与模型无关"，便于做可复现的对照。

实现思路与设计

模块划分

组件职责与第 018 章的关系
make_env(gravity)按重力制造环境（含推力统一为 9.0）复用并参数化
难度调度近 20 回合均值 + 耐心窗口触发重力 +0.5新增：课程控制器
环境热替换推进后重建 env 并重置观测新增：训练中切换任务
evaluate_target固定目标重力的贪婪评估，两臂共用新增：统一口径
轨迹记录评估曲线 + 难度推进轨迹 + 首达 400 步数新增课程诊断输出

关键超参数

参数默认值作用与取值理由
--start-gravity7.0起始难度：明显轻于目标，保证早期能收获高分
--target-gravity13.0目标任务：直训比较吃力，课程收益有空间
--gravity-step0.5每级增量：约 12 级台阶，精细度与推进次数的折中
--advance-reward350升级阈值：低于它说明还没适应当前难度
--advance-patience2升级后的冷却窗口，防止连锁误升
--eval-every6目标环境评估频率；73 次更新的预算下约 12 个评估点
--max-steps150000两臂相同的环境步数预算

数据流

两臂共享同一套循环：采样 2048 步 → 10 epochs 更新 → （课程臂）检查推进条件，达标则 gravity += 0.5、重建环境、重置观测、清冷却计数 → 每 6 次更新在目标环境上贪婪评估一次 → 记录评估曲线与首达 400 的步数 → 跑满 15 万步。课程臂额外输出 gravity_trace（步数 → 难度）用于诊断。

课程学习不注入知识，只重排任务

与第 015–018 章相比，本章没有任何"外部信息"：没有预训练权重、没有专家数据。策略最终能学会，靠的仍是同一个 PPO，课程只做一件事：在早期把训练分布调到"策略刚好能拿高分"的区域，让优势信号始终清晰。这也解释了它的局限：任务之间必须共享技能（比如不同重力下的平衡），否则排序毫无意义。

关键代码与解读

片段 1：环境工厂，难度即参数

def make_env(gravity: float):
    """按重力制造环境：每一级难度都是一个新的 gym 实例。"""
    env = gym.make("CartPole-v1")
    env.unwrapped.gravity = gravity     # 难度参数
    env.unwrapped.force_mag = 9.0       # 推力统一调小：目标更吃力
    return env

# 推进时：env = make_env(gravity)；旧实例直接丢弃（经典控制环境无外部资源）

解读：（1）"难度"被抽象成一个浮点参数：从 7.0 到 13.0 的每一级都是一个合法的任务，课程调度器只需改这个数。（2）force_mag 固定 9.0：让"重力"成为唯一变化的难度轴，如果同时改推力，难度就不单调了。（3）每次调用都返回新实例：这是"热替换"安全的前提；旧的环境对象连同它的内部状态一起被丢弃，不会出现"两个环境混用"的尴尬。（4）返回值是未解包的 gym.Env；观测空间与动作空间在每一级上都一致（4 维、2 动作），网络不需要因难度变化而重建。

片段 2：训练臂的初始化与轨迹容器

def train_one(arm: str, args):
    set_seed(args.seed)
    device = torch.device("cpu")

    curriculum = (arm == "curriculum")
    gravity = args.start_gravity if curriculum else args.target_gravity
    env = make_env(gravity)                     # 课程臂从易起步；直训臂直接用目标
    obs, _ = env.reset(seed=args.seed)
    obs_t = to_tensor(obs, device)

    net = ActorCritic(env.observation_space.shape[0], env.action_space.n)
    optimizer = torch.optim.Adam(net.parameters(), lr=args.lr)

    all_returns, kls = [], []
    eval_curve = []                 # (步数, 目标环境评估)
    gravity_trace = [(0, gravity)]
    eval_at_400 = None
    total_steps, n_updates = 0, 0
    updates_since_advance = 0

解读：（1）两臂的差异压缩成一行：gravity = start if curriculum else target，其余代码完全共享，保证对比公平。（2）三个诊断容器各司其职：eval_curve（目标评估曲线，两臂可比）、gravity_trace（难度轨迹，只课程臂增长）、updates_since_advance（冷却计数）。（3）set_seed 在函数开头（两臂同一随机流）；reset(seed=args.seed) 让初始状态也一致。（4）gravity_trace 初始就放进 (0, gravity)：轨迹的第一个点必须是起点，否则后面画图/分析会缺一段。

片段 3：课程推进，三行核心 + 两个必须动作

        # 课程推进：当前难度表现达标且距上次推进至少 2 次更新
        if curriculum and gravity < args.target_gravity and updates_since_advance >= args.advance_patience:
            if len(all_returns) >= 20 and np.mean(all_returns[-20:]) >= args.advance_reward:
                gravity = min(args.target_gravity, gravity + args.gravity_step)
                gravity_trace.append((total_steps, gravity))
                env = make_env(gravity)              # 热替换：旧环境直接丢弃
                reset_obs, _ = env.reset()           # 必须重置观测
                obs_t = to_tensor(reset_obs, device)
                updates_since_advance = 0            # 冷却窗口重新计时
                print(f"  [curriculum] 推进难度：重力 → {gravity:.1f}（步数 {total_steps}）")

解读：（1）外层条件的三个子句各挡一类错误：curriculum 让直训臂跳过整段；gravity < target 到顶即停；updates_since_advance >= patience 保证推进后至少再跑 2 次更新，因为升级后 all_returns 里还残留着旧难度的高分回合，立即再判会触发"连锁误升"。（2）内层条件用近 20 回合滑窗（不用单回合）：单回合噪声大，滑窗才代表稳定适应水平。（3）env = make_env(gravity) 与 obs_t = to_tensor(reset_obs) 是推进的"两个必须动作"：新环境的动力学不同，旧观测与新任务不匹配；忘记重置会让后续几步在"错误状态"上决策，日志里表现为莫名其妙的低谷。（4）updates_since_advance = 0 与 gravity_trace.append：前者清冷却、后者留证据，轨迹既是诊断也是练习 3（回退机制）的基础。

片段 4：目标环境评估，两臂共用的一把尺子

        # 目标环境评估：无论训练难度如何，都用同一把尺子
        if n_updates % args.eval_every == 0 or total_steps >= args.max_steps:
            ev = evaluate_target(net, args.eval_episodes, device, args.target_gravity)
            eval_curve.append((total_steps, ev))
            if eval_at_400 is None and ev >= 400.0:
                eval_at_400 = total_steps
            print(f"  [{arm:10}] 步数 {total_steps:6d} | 训练难度 g={gravity:.1f} | "
                  f"近20均 {np.mean(all_returns[-20:]):7.1f} | 目标评估 {ev:6.1f} | "
                  f"KL {stats['approx_kl']:.4f}")

解读：（1）evaluate_target 每次都现场创建目标重力的全新环境：训练难度在课程臂里是变化的，但评估口径恒定，这是本章公平性的全部来源。（2）评估用贪婪策略、固定回合数；eval_at_400 记录"目标评估首次 ≥ 400"的步数，就是"课程收益"的量化指标。（3）or total_steps >= args.max_steps 的尾巴保证训练结束前总有最后一次评估，终值不会缺。（4）日志一行为两臂共用：同时打印训练难度与目标评估，提醒你"近 20 均"列在不同难度间不可比，只有"目标评估"列能横向看。

预期结论（以实跑为准）：课程臂在目标环境上的评估曲线通常比直训臂早 3 万～8 万步穿过 400，最终评估高 20～60 分；难度轨迹呈"先快后慢"（前期每 1～2 万步升一级，后期同一难度要 3 万步以上）。若课程臂没有优势，先检查推进条件：阈值太高（如 450）会让课程卡在简单任务上，阈值太低（如 250）则形同虚设；把 --advance-reward 调回 350 附近再试。两种方式的多余预算最终都会收敛到相近水平，课程的价值集中在"用更少步数达到目标"。

常见坑

  • 拿训练回报跨难度比较：课程臂的"近 20 均"和直训臂不在同一任务上，唯一公平口径是目标环境评估。日志里同时打印训练难度就是提醒这件事。
  • 升级后忘记重置观测：新环境的动力学与旧环境不同，继续用旧观测会让策略在"错误的状态"上决策，前期表现骤降。推进后立即 reset()。
  • 用单回合回报当升级判据：噪声会导致误升级；用 20 回合以上的滑窗，并加耐心窗口。
  • 任务族不共享技能时硬套课程：如果难度之间没有迁移结构（例如随机的奖励函数），"由易到难"不会产生任何帮助，甚至浪费预算。课程的前提是技能可复用。
  • 耐心窗口忘了清零：升级后必须把 updates_since_advance 置 0，否则旧窗口里的高分回合会触发连锁升级，课程一夜之间跳到目标难度。

练习与思考

  1. 把 --advance-reward 设为 250 / 350 / 450，对比首达 400 的步数，找出本任务的最优阈值。★
    提示
    阈值太低升级过快、策略在新难度上崩；太高则课程停滞。观察难度轨迹的斜率与目标评估曲线的交叉点。
  2. 实现"时间表课程"：不看表现，直接按训练步数线性加重力（例如每 1 万步 +0.5），对比自适应课程。★★
    提示
    把推进条件替换成 total_steps >= next_advance 即可。时间表简单但不适应学习速度，通常略差，但它是分布外泛化研究里的常用基线。
  3. 实现"难度回退"：如果当前难度的近 20 回合均值跌破 150，把重力回退 0.5，观察是否更稳。★★
    提示
    在推进判断后加一个回退分支，并用独立的冷却计数器。回退能缓解"升太快崩盘"，但可能造成难度震荡，记录重力轨迹观察。
  4. 测量"半步差"假设：在课程结束后，用保存的重力轨迹固定一系列检查点，分别评测策略在"当前难度"与"难度 +1 级"上的成绩差，验证策略是否总在难度前沿游走。★★★
    提示
    在每个评估点用两个环境各跑一次贪婪评估，记录差值。理想课程中"当前难度成绩"与"下一级成绩"的差距应稳定在可控范围（如 100～200 分）。

小结

  • 课程学习通过安排任务顺序加速训练：让难度始终停在"能力前沿半步"，保证梯度信号既不过强也不过弱。
  • 自适应调度 = 表现阈值 + 耐心窗口 + 小步推进；本章实现里阈值为 350、耐心 2 次更新、每级 +0.5 重力。
  • 对比必须统一在目标环境评估；实验显示课程臂更早越过 400，最终成绩也略高。
  • 课程的收益集中在前期，且依赖任务间技能可复用；推进太慢或太快都会让收益消失。
