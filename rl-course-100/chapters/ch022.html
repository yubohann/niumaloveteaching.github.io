第一篇 · 策略梯度与 PPO

第 022 章：PPO的探索策略：动作空间噪声

把随机性加在"选动作"这一步：ε-贪心覆盖与 logits 高斯噪声两种动作层探索，和 PPO 默认的 softmax 采样同种子、同预算对比，并用"偏离率"与"状态覆盖"两把尺子量化探索行为。

  • 主题：探索机制 / 行为策略与重要性比率
  • 关键公式：logits′ = logits + σ·ξ，ξ ~ N(0, I)；a ~ softmax(logits′)
  • 预计学时：60 分钟
  • 前置章节：第 021 章

学习目标

  • 理解动作空间噪声的两种形式（ε-贪心、logits 噪声），以及它们与第 021 章参数空间噪声的本质区别。
  • 能把"行为策略 μ"与"目标策略 πθ"的角色分清：噪声改的是数据从哪来，不改优化目标。
  • 掌握 PPO 实现铁律，logp_old 永远是干净策略对所选动作的对数概率，并用实验验证写错的后果。
  • 学会用偏离率与状态覆盖桶两个诊断量横向比较不同探索方案。
  • 在 CartPole-v1 上完成三臂对比（默认采样 / ε-贪心 / logits 噪声），读懂噪声退火对收敛的影响。

背景与动机

第 005 章用熵正则化在"目标函数层面"鼓励探索，第 021 章在"参数层面"加噪声让行为成片变化。本章处理第三种、也是最直觉的一种：直接在动作上做手脚，随机换动作（ε-贪心）或者抖动动作偏好（logits 噪声）。它的优点是实现极简、不碰网络内部、对离散与连续动作都适用，很多工程代码库默认就带一个 ε 退火；缺点同样明显：噪声与策略"各干各的"，行为连贯性差，还会让价值函数看到策略本来不会选的动作。

本章把两种动作噪声放进同一份 PPO 代码里做对照实验，并引入两个能量化"探索行为"的指标。本章的落点在于方法论本身：探索强度要能调度、能度量，探索与利用的切换必须显式管理，第 023 章将在此基础上叠加熵正则化做系统对比。

核心原理

1. 目标策略、行为策略与重要性比率

PPO 默认的动作来自目标策略 πθ 自身：

at ~ πθ(·|st) = softmax(logitsθ(st))

动作噪声则引入一个行为策略（behavior policy） μ：数据由 μ 产生，但优化目标仍是 πθ。二者不一致时，正确的梯度要带重要性权重：

∇θJ = 𝔼a~μ[ (πθ(a|s) / μ(a|s)) · ∇θlog πθ(a|s) · Â(s,a) ] PPO 的比率只用 πθ_old 当分母，相当于假设 μ = πθ_old；μ 偏离越远，偏差越大

这就是动作噪声必须退火（annealing）的原因：训练早期允许 μ 偏离来拓宽覆盖面，训练后期把噪声降回 0，让 μ 重新与 πθ 重合，PPO 恢复成无偏的 on-policy 更新。反过来，如果噪声一直不衰减，数据分布永远带着"策略之外的偏差"，价值函数学的是带噪行为的回报，评估（干净策略）与训练就对不上了。

还有一条被否决的路线要说清：既然数据来自 μ，理论上也可以保留 μ 的 logp、把重要性权重 π/μ 乘进损失做严格纠正。工程上很少有人这么做：权重的方差大、需要额外的裁剪与归一化，而 PPO 的比率与裁剪本来就在处理分布差异，两层纠正叠在一起容易互相打架。通行路线是"噪声退火 + 干净 logp"：让 μ 随退火逐步回归 π，权重纠正用得很少。

2. 两种离散动作噪声

ε-贪心覆盖：以概率 εt 把动作换成均匀随机动作，否则按策略采样：

at = 均匀随机动作（概率 εt）；  at ~ πθ(·|st)（概率 1−εt）

logits 噪声：先给动作偏好加高斯抖动，再按抖动后的分布采样：

logits′ = logitsθ(st) + σt · ξ，  ξ ~ N(0, I)，  at ~ softmax(logits′) σt 很大时分布趋近均匀；σt = 0 时退化为标准采样

两者的差别值得细品：ε-贪心会完全丢弃策略信息，随机出来的动作可能恰恰是当前状态下最差的动作；而 logits 噪声只是把偏好"拍平"，被抽中的动作仍与策略相关（原本 logits 高的动作即使被抖动也更容易胜出），因此噪声的破坏性更温和。两者都采用线性退火：在前 anneal_frac 比例的训练预算内从初值降到终值。线性退火公式为：

level(t) = start + (end − start) · min(1, t / (anneal_frac · T)) t 为已用环境步数，T 为总预算；前 60% 预算退火，后 40% 留给干净策略收敛

把本章默认值代入，退火段是前 0.6×80000 = 48000 步，斜率 (0.02−0.3)/48000 ≈ −5.83×10⁻⁶ 每步；每次更新 2048 步，ε 每轮下降约 0.012。抽查各更新点的 ε：第 0 轮 0.300、第 5 轮 0.240、第 10 轮 0.181、第 15 轮 0.121、第 20 轮 0.061、第 23 轮 0.025，约第 24 轮（47104 步之后）退火结束并停在 0.020。前 1 万步里 ε 仍在 0.24 以上，探索量最大的窗口恰好覆盖"策略最不成熟"的阶段；若把 --anneal-frac 调大到 0.8，末期只剩 1.6 万步的干净收敛期，往往不够用，这是 0.6 这个默认值的由来。

两种噪声的"破坏力"还有一个可计算的差别。设当前策略在两个动作上的 logits 差为 d、logits 噪声尺度为 σ，噪声把较差动作顶上来的概率是 Φ(−d/(σ√2))：翻盘条件等价于噪声差超过确定性的差距，而噪声差服从 N(0, 2)。取 σ=1：策略尖锐（d=3）时翻盘概率约 1.7%，策略平坦（d=0.2）时约 44%。logits 噪声的破坏性会随策略变尖自动衰减；ε-贪心的完全随机注入只看 ε，策略再尖也恒定存在（n=2 时随机分支就贡献 ε/2 的翻盘概率），这就是"退火终点"对后者更关键的原因。

3. 关键约定：logp_old 属于谁

无论动作是怎么选出来的，存进 rollout 的 logp_old 必须是干净策略 πθ 对该动作的对数概率；噪声后分布的 log 概率不能充当这个基准。原因回到比率的定义：

rt(θ) = πθ(at|st) / πθ_old(at|st)

分母 πθ_old 是"更新前策略的概率"。采样那一刻 θ 还没变，所以干净策略对该动作的 logp 恰好就是 πθ_old 的 logp，用它做分母，rt 的起点才是 1。如果误用噪声分布 μ 的 logp 当分母，rt 在第一步就不等于 1，更新会被系统性削弱或放大，KL 统计也跟着失真。这是动作噪声实现里最容易犯的错，本章代码把它固定成一条"铁律"。

数值例子：分母写错后比率偏离 1 多少

取两动作、干净策略 π=(0.9, 0.1)、ε=0.3 的 ε-贪心臂，行为分布 μ = 0.7π + 0.3×(0.5,0.5) = (0.78, 0.22)。两步算清后果：

第一步，比率的起点。用干净 logp 当分母时，更新起点处每个样本的 r=1（分子分母同分布），方差为零。若误存 μ 的 logp，r 的取值变成 π(a)/μ(a)：抽中动作 1 时 r=0.9/0.78≈1.154，抽中动作 2 时 r=0.1/0.22≈0.455。均值仍是 1（因为 Σμ·(π/μ)=1），但每个样本都偏离 1，标准差约 0.29。裁剪区间 [0.8, 1.2] 会立刻削掉动作 2 的那部分样本（0.455 被夹到 0.8），而对动作 1 的样本不动作，信任域从第一步就左右不对称。

第二步，更新方向的偏置。PPO 的比率本应衡量"新策略相对更新起点"的变化，写错分母后衡量的是"策略相对行为分布"的差距，梯度里混入了重要性纠正的成分。训练仍会动，但裁剪比例与 KL 读数全部失真，任何"看起来正常"的日志都不能证明实现是对的。这也是练习 3 能用一个指标（近似 KL 系统性偏大或偏小）抓出这个 bug 的原因。

4. 度量：偏离率与状态覆盖

把 argmaxaπθ(a|s) 当作"策略当前最想做的动作"，偏离率定义为执行动作不等于它的比例：

偏离率 = count(at ≠ argmaxaπθ(a|st)) / 总步数

它对三臂都可比：默认采样也会有偏离（熵高时接近 50%），ε-贪心和 logits 噪声则把偏离率显著推高。另一个量是状态覆盖：把 4 维观测按常用范围离散成 64=1296 个桶，统计训练中累计访问过的桶数，衡量探索"走过多少地方"。两个指标合起来看：偏离率描述"行为有多野"，覆盖桶描述"野出了多少新地盘"。在 CartPole 上两者会一起读：偏离率高而覆盖桶不增，说明在重复踩同一片区域；覆盖桶持续增长时，偏离率往往也同步抬高。

三臂的偏离率各有解析形状，写下来便于解释日志。两动作情形下，默认臂的期望偏离率等于 1 − pmax，就是"策略对自己选的动作为何自信"的直接读数：logits 差 d 时约等于 1 − σ(d)，d=1 时约 0.27、d=3 时约 0.047。ε-贪心臂的期望偏离率是 ε(1−1/n) + (1−ε)(1−pmax)：n=2 时随机分支贡献 ε/2，再加上策略分支的残余；p=0.9、ε=0.3 时约 0.22，ε 降到 0.02 后约 0.11，仍高于默认臂的 0.10，因为那 2% 的纯随机永远在贡献偏离。logits 噪声没有闭式，退火段可用翻转概率 Φ(−d/(σ√2)) 近似：σ=1 时 d=0.5 约 36%、d=1 约 24%、d=2 约 8%，与"策略越尖、噪声破坏越小"的判断一致。三条式子合起来读日志：默认臂看策略置信度、ε-贪心臂看 ε 叠加置信度、噪声臂看两者随 σ 的混合。

数据流

每个更新周期：按当前进度算噪声水平（ε 或 σ）→ 采样 2048 步，动作由行为分布决定、logp 由干净策略记录 → 统计本轮的偏离率、累计覆盖桶 → GAE 估计优势 → 标准 PPO 更新（10 epochs × 32 minibatch）→ 打印日志 → 近 100 回合滑窗 ≥ 475 则早停。一条臂跑完做 10 回合贪婪评估并保存模型，三条臂跑完打印汇总表。

与第 021 章的差异点

  • 噪声位置：021 扰动网络参数、采样后恢复；本章完全不碰权重，只在动作选择处注入噪声，因此没有"恢复参数 / 重算 logp"的步骤。
  • 行为分布的形态：参数噪声是整批共享一个扰动（行为成片变化）；动作噪声是每步独立注入（行为跳变、连贯性差）。
  • 探索调度：021 用 KL 自适应调 σ；本章用训练进度线性退火 ε 与 σ，节奏可预测。
  • 对照指标：新增偏离率 + 累计覆盖桶，用于横向比较三臂的探索行为，成为回报曲线之外的第二把尺子。
三臂共用同一条学习管道

网络、GAE、裁剪损失、评估协议全部原样复用，唯一的变量是 sample_action 里选动作的方式。实验对照的公平性来自两点：每臂开头都调用 set_seed(--seed) 重置初始条件；每臂的预算都是 --max-steps 步。随机动作也统一用 np.random.randint 抽取，不用 env.action_space.sample()，因为它走环境内部的独立随机源，不受 set_seed 控制，实验会变得不可复现。

关键代码与解读

片段 1：三种行为分布的唯一入口

@torch.no_grad()
def sample_action(net, obs_t, arm, level, n_actions):
    """按指定探索臂选动作；返回 (action, logp, value, greedy)。"""
    logits, value = net(obs_t)                          # 一次干净前向：策略偏好 + 价值
    greedy = int(torch.argmax(logits, dim=-1).item())   # 干净策略的最优动作（统计偏离率用）

    if arm == "logitnoise" and level > 0.0:
        # logits 加高斯噪声：σ 越大分布越接近均匀；σ=0 时退化为标准采样
        noisy_logits = logits + level * torch.randn_like(logits)
        action = Categorical(logits=noisy_logits).sample()
    elif arm == "egreedy" and random.random() < level:
        # 以概率 ε 直接换成均匀随机动作，绕开策略分布（探索最"硬"的方式）
        action = torch.tensor([np.random.randint(n_actions)], device=logits.device)
    else:
        # 默认：按策略自身的 softmax 分布采样
        action = Categorical(logits=logits).sample()

    # 关键行：logp 永远用"干净 logits"计算，它是 PPO 比率的基准。
    # 若改用噪声分布的 logp，r_t 的起点不再是 1，更新被系统性扭曲。
    logp = Categorical(logits=logits).log_prob(action)
    return int(action.item()), logp.item(), value.item(), greedy

解读：函数先做一次干净前向拿到 logits 与 greedy（argmax），随后按臂分派采样方式，这就是"行为策略 μ"的三种形态。（1）logitnoise 直接给 logits 加 level * torch.randn_like(logits)，σ 控制"拍平"程度，实现只有两行；（2）egreedy 用 np.random.randint 抽均匀动作，随机源受 set_seed 控制，可复现；（3）最后一行是整章的灵魂：logp 统一从干净 logits 计算。注意 level=0 时 logitnoise 分支不触发，直接走标准采样，退火到 0 后行为完全等价于默认臂，这个细节让"退火到底"在实现上无缝。

片段 2：线性退火与状态覆盖桶

def anneal_level(progress, start, end, anneal_frac):
    """线性退火：前 anneal_frac 段预算内从 start 降到 end，之后保持 end。"""
    if anneal_frac <= 0.0:
        return end                                     # 关闭退火：直接用终值
    p = min(1.0, max(0.0, progress / anneal_frac))     # 进度归一化并截断到 [0,1]
    return start + (end - start) * p

def obs_to_bins(obs, n_bins=6):
    """把一批观测映射到 n_bins^4 个桶，返回访问过的桶集合（状态覆盖统计）。"""
    x = np.clip((obs - COVER_LOW) / (COVER_HIGH - COVER_LOW), 0.0, 0.9999)
    idx = (x * n_bins).astype(np.int64)                # 每维取 0..n_bins-1 的桶号
    return {tuple(int(v) for v in row) for row in idx} # 集合去重：只关心访问过没有

解读：anneal_level 把"已用预算比例"映射成噪声强度，前 60% 退火、后 40% 恒为终值。进度用预算比例、不用绝对步数，好处是 --quick 快速模式下退火节奏与完整模式一致，日志曲线可直接对比。max(0.0, …) 防负进度、min(1.0, …) 防超界，两个截断让函数在任意输入下都返回 [end, start] 区间内的值。obs_to_bins 里 clip 到 0.9999 是关键：保证桶号最大恰好是 n_bins-1，边界观测不会溢出成第 7 个桶；返回的是集合，覆盖统计只关心"到没到过"，去重后跨步求并集即可。

片段 3：采样循环里的"行为特征"

    for _ in range(steps):
        a, logp, v, greedy = sample_action(net, obs_t, arm, level, n_actions)
        if a != greedy:                          # 偏离率：执行动作 ≠ 干净策略 argmax
            n_deviate += 1

        rew_buf.append(r)
        val_buf.append(v)

        term_buf.append(float(terminated))

        obs_after = obs_t                        # 循环结束用于 bootstrap 的最后观测

            reset_obs, _ = env.reset()
            obs_t = to_tensor(reset_obs, device)

解读：这段循环比 001 章多了两个东西。（1）逐行比较 a != greedy 累计偏离计数，注意它对三条臂都有意义：默认臂在熵高时也会大量偏离，所以三臂数字直接可比。（2）term_buf 只记 terminated，截断不置零，CartPole 的 500 步上限是时间限制，必须继续 bootstrap，这个处理与 001 章一致。（3）logp_buf 存的仍是干净策略 logp（片段 1 决定的），即使动作来自 ε-贪心或噪声分布，缓冲区的语义没变，PPO 更新逻辑就完全不用改。

片段 4：单臂训练循环，从进度到早停

    while total_steps < args.max_steps and solved_at is None:
        # 1) 按训练进度把探索强度换算成当前 level（默认臂恒为 0）
        progress = total_steps / max(1, args.max_steps)
        if arm == "egreedy":
            level = anneal_level(progress, args.eps_start, args.eps_end, args.anneal_frac)
        elif arm == "logitnoise":
            level = anneal_level(progress, args.sigma_start, args.sigma_end, args.anneal_frac)
        else:
            level = 0.0

        # 2) 采样一批经验；deviate_rate / cover_bins 是本臂的"行为特征"
        batch, ep_returns, obs_t, deviate_rate, cover_bins = collect_rollout(
            env, net, arm, level, args.steps_per_update, obs_t, device,
            args.gamma, args.lam, n_actions)
        total_steps += args.steps_per_update
        all_returns.extend(ep_returns)
        dev_iter.append(deviate_rate)
        cover_all |= cover_bins                  # 覆盖桶按并集累计，只增不减

        # 3) PPO 更新（与默认 PPO 完全一致：噪声只改数据来源，不改算法）
        stats = ppo_update(net, optimizer, batch, args)
        update_idx += 1

        # 4) 近 100 回合滑窗达标即早停，三臂同一标准，预算公平
        if solved_at is None and len(all_returns) >= 100 and \
                np.mean(all_returns[-100:]) >= args.target_reward:
            solved_at = total_steps

解读：循环体就是本章的实验骨架，四步节奏值得记住。（1）进度用 total_steps / max_steps（不按"第几次更新"）：更新次数会随 --steps-per-update 变化，步数才是不随配置漂移的公平标尺。（2）collect_rollout 返回值里的 deviate_rate 与 cover_bins 只用于统计与日志，不影响更新，它们和回报一起构成对探索行为的完整描述。（3）cover_all |= cover_bins 是集合并集，天然单调不减，斜率变平即探索饱和。（4）早停条件是"近 100 回合滑窗 ≥ 475"，未达标的臂老老实实跑完 8 万步；每个臂开头都 set_seed，保证网络初始化、环境 reset、噪声随机数三条流都从同一起点出发。

完整可运行脚本（附录）：code/ch022.py

python code/ch022.py            # 三臂各 8 万步：CPU 约 2–5 分钟
python code/ch022.py --quick    # 快速跑通：30–60 秒，只验证流程
python code/ch022.py --arms stochastic,egreedy   # 只对比两臂

以实跑为准：三臂通常都能在 2.5 万～7 万步内越过 475 的滑窗门槛，最终评估在 470～500 之间。稳定的差异在行为列，logits 噪声臂平均偏离率最高（典型 0.15～0.30），ε-贪心次之，默认采样最低（随策略变尖衰减到 0.05～0.15）；覆盖桶数通常是 logitnoise ≥ egreedy ≥ stochastic（典型相差 10%～35%）。

常见坑

  • logp_old 写成噪声分布的 log 概率：比率的分子分母必须同属目标策略。行为分布 μ 的 logp 只能用于重要性纠正，不能当 PPO 的基准；症状是 KL 系统性偏大/偏小、裁剪比例异常，更新幅度被扭曲。修复：统一从干净 logits 重算 log_prob。
  • 噪声不退火：持续高 ε / 高 σ 让行为分布永远偏离策略，价值网络长期拟合带噪回报，贪婪评估与训练成绩脱节，滑窗均值震荡不收敛。修复：把 --anneal-frac 控制在 0.5～0.7，并检查末期偏离率是否降下来。
  • 随机动作的随机源不受控：用 env.action_space.sample() 抽随机动作时，随机数来自环境内部独立 RNG，与 set_seed 不一致，实验不可复现。修复：统一用 np.random.randint(n_actions)。
  • 评估时忘了关噪声：评估必须用干净策略的 argmax、不注入任何噪声。带噪评估分数偏低且方差大，容易误判某臂"更差"。修复：evaluate() 里只用 argmax，与噪声代码完全隔离。
  • 只跑一个种子就下结论：CartPole 太简单，单次运行的臂间差异大多落在随机波动里。修复：固定同一份代码多跑 --seed 0/1/2，只在"偏离率与覆盖桶"这类稳定行为差异上做判断。

练习与思考

  1. 把 --eps-end 从 0.02 改成 0.3 各跑一次，观察末期偏离率与近 100 回合均值的变化，解释"为什么不退火会拖累收敛"。★
    提示
    不用改代码。重点看日志末尾的偏离率是否仍高、KL 是否虚高，以及早停是否迟迟不触发。
  2. 把 --sigma-start 分别设为 0.5 与 2.0 跑 logitnoise 臂，对比早期覆盖桶数与首达目标步数，找出"探索过多"的迹象。★
    提示
    σ=2 时早期动作接近均匀，覆盖涨得快但近 20 回合均值长期在低位；σ=0.5 时偏离率上升幅度有限。对比两条日志前 10 次更新。
  3. 故意把 sample_action 返回的 logp 改成"噪声分布 μ 的 logp"（对 noisy_logits 求 log_prob），跑到 2 万步左右观察 KL 与裁剪比例的异常，解释为什么比率的基准不能是行为分布。★★
    提示
    改动集中在 logp = Categorical(logits=logits).log_prob(action) 一行。你会看到近似 KL 系统性偏大或偏小，因为 rt 的起点不再是 1。
  4. 实现"偏离率闭环"探索：不按步数退火，改为每 5 次更新根据实测偏离率调整 σ（高于目标就减小、低于目标就增大），把平均偏离率稳定在 0.2 附近。★★
    提示
    仿照第 021 章的 σ 自适应结构：在 run_arm 里保存最近几次的偏离率，按 1.1 倍步长调整 σ，并给 σ 设上下界 [0, 3]。观察回报曲线是否比线性退火更平滑。
  5. 把同一套动作噪声思路迁移到连续动作：在 Pendulum-v1 上给动作加高斯噪声 a = clip(μ(s) + σt·ξ)，logp_old 记录高斯策略对该动作的对数密度，比较与离散 logits 噪声的行为差异。★★★
    提示
    需要先有一个高斯策略的 PPO 实现（可参考第 011 / 030 章的骨架）。注意动作加噪后仍要 clip 到环境动作边界，logp 用未裁剪的采样值计算。

小结

  • 动作空间噪声 = 显式修改行为分布 μ：ε-贪心完全丢弃策略信息，logits 噪声只拍平动作偏好，两者都需要线性退火回到 on-policy。
  • 实现铁律：logp_old 永远记录干净策略 πθ 对所选动作的 log 概率，噪声只影响"动作怎么选"，不影响比率的基准。
  • 偏离率量化"行为有多野"，覆盖桶量化"探索走了多远"；两把尺子让探索方案对比不再只靠回报曲线。
  • CartPole 上三臂都能达标；动作噪声把覆盖推高 10%～35%，但没有换来更快的收敛，探索是有代价的。
  • 下一章把动作噪声与熵正则化叠成 2×3 网格系统对比：外加强制的探索与目标函数内的熵奖励，谁更划算、什么时候必须同时用。
