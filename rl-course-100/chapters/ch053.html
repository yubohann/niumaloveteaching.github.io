第二篇 · 离策略方法与 SAC

第 053 章：SAC的课程学习

把山地车的引擎功率当作"难度旋钮"：课程组先在 4 倍功率下学会来回蓄力的动作模式，再一路降回真实功率；对照组直接啃最难版本。两者都在真实 MountainCarContinuous-v0 上评估，看课程能省多少样本。

  • 主题：课程学习（Curriculum Learning）/ 难度参数化
  • 关键公式：v ← v + a·power − 0.0025·cos(3x)；课程 power 0.006 → 0.0015
  • 预计学时：55 分钟
  • 前置章节：第 052 章

学习目标

  • 理解课程学习的核心假设：难度递增的任务序列能让智能体复用已学会的行为模式。
  • 掌握"难度参数化"的设计方法，本章用引擎功率把同一个任务连续地调难调易。
  • 实现可调功率的 PowerMountainCar 环境与四阶段课程训练循环，切换阶段时保留策略与回放池。
  • 对比课程组与直接训练组的首个成功回合、评估成功率与最终回报。
  • 会解释课程生效的前提条件，以及"训练环境可以变、评估协议不能变"的公平底线。

背景与动机

稀疏奖励任务的困难在于"第一条成功轨迹"很难随机撞出来。课程学习换一个角度：先在一个简单到"撞出成功"很容易的版本上学会基本技能，再逐步把难度调回目标水平。人学骑车、滑雪都是这么学的：从辅助轮和缓坡开始，直接冲下黑道属于跨级练习，摔跤概率极高。

第 052 章用塑形把奖励信号变稠密；本章不动奖励，改的是任务动力学本身，两者是互补的稀疏奖励手段。难点在于设计"难度参数"：它必须让简单版本仍然保留目标技能的结构，否则学了半天是另一件事。本章的功率旋钮之所以合格，是因为它只压缩"蓄能时间"、不改变"先退后进"的解法结构；换一个不合格的参数（比如把目标位置挪近），简单版本学到的就是完全不同的行为，迁移无从谈起。

核心原理

1. 难度参数化与课程序列

把任务写成一个带难度参数 ρ 的族 M(ρ)：本章 ρ 就是引擎功率 p。课程是一条从易到难的序列：

p: 0.006 → 0.004 → 0.0025 → 0.0015（目标） 每阶段占预算的 1/4；切换时策略、回放池、目标网络全部保留

符号说明：power 是每单位动作力产生的加速度（真实环境为 0.0015）。功率越大，小车越容易获得动能翻过山谷，成功所需的"蓄能循环"越少，但这不改变最优策略的形态（先退后进、对称摆动）。好的难度参数只改变"多难"，不改变"解法长什么样"，这是技能可迁移的前提。

数值例子：功率如何改变蓄能效率

速度更新式为 v ← v + a·power − 0.0025·cos(3x)，全推力（a=±1）时每步的速度增量就是 power。速度上限同为 0.07，于是"从静止推到满速"所需步数约为 0.07 / power：

power=0.006（课程第一段）：0.07 / 0.006 ≈ 12 步即可达到速度上限。

power=0.0015（目标功率）：0.07 / 0.0015 ≈ 47 步，是前者的约 4 倍。

解读：最大速度相同、加速能力差 4 倍，意味着目标功率下"攒一次可用动能"需要更长的蓄力过程，翻过山谷所需的往返次数也大致按同样的比例放大。这就是同一套"先退后进"策略在两种功率下的难度差异：动作模式不变，时间尺度变了约 4 倍。课程组先在 12 步级的动力学里把摆动模式学熟，再迁移到 47 步级的目标动力学，需要重新适应的是节奏，摆动结构本身保持不变。

2. 为什么技能可以迁移

动作序列的价值结构在功率变化下保持定性一致：低谷处继续摆动、接近目标时持续加速。差异主要在"周期长度"（低功率需要更多次摆动）。策略网络学的是状态到动作的映射，宏观模式（何时反向、如何保持节奏）可以直接复用；需要重新适应的是时间尺度。因此课程提供的是行为初始化，不是"作弊"，最终评估仍用真实动力学把关：

评估协议：所有模式统一在 gym 的 MountainCarContinuous-v0（power=0.0015）上跑 训练环境可以改，裁判标准不能改，这是课程学习实验的公平底线

2.1 两种模式的预期对照

指标direct（直接目标功率）curriculum（四段课程）
首个成功回合常熬到 2 万步附近，部分种子不出现第一阶段内即可出现（简单功率下容易撞出）
评估成功率（目标环境）预算内常低于 0.3进入目标功率后常在 10%～25% 预算内升到 0.6 以上
训练回合数少（回合长、成功难）多（成功快、回合短），效率的直接体现
最终评估回报明显更低更高，且随课程推进稳步上升
机制解释探索稀疏信号，依赖运气先获得行为初始化，再对齐时间尺度

对照的判据是"先看训练动力学内的表现，再看目标环境的成绩"：课程组在简单阶段的训练成功率会很高，这部分成绩不算数；真正说明问题的是评估成功率随阶段推进的爬升曲线，以及它与训练成功率的差距是否收缩。

3. 课程失效的典型情形

  • 阶段切换太晚：在简单任务上练到过熟，策略对它的动力学过拟合，反而需要更长时间"忘记"；
  • 难度参数改变了最优策略：如果简单版本的最优解与目标任务是两回事（例如把目标位置挪到容易的位置），学到的技能无法迁移；
  • 最后一段没对齐目标：课程最后一关与目标任务差一点，会造成系统性策略偏移，评估成绩骤降，这也是必须用官方环境评估的原因。

实现思路与设计

数据流

两种模式的训练闭环完全相同，差异只有功率序列：direct 全程用 0.0015；curriculum 按 --powers 四段递减，每段占 max_steps / 4 步。阶段边界只重建训练环境并 reset，agent、优化器、回放池、评估环境全部保留。每 5000 步在官方目标环境上评估一次（回报 + 成功率 + 最大位置），并打印训练成功率供对照。

模块划分

组件职责关键点
PowerMountainCar与官方动力学同构、功率可调的环境速度更新式 v += a·power − 0.0025·cos(3x)；成功条件与官方一致
make_target_env创建官方评估环境评估永远不看训练动力学
阶段调度按步数切换训练环境（direct 只有一个阶段）切换时保留 agent 与回放池，重置环境与回合统计
evaluate目标环境上的回报 / 成功率 / 最大位置两种模式共用，口径一致

关键超参数

参数默认值作用与取值理由
--powers0.006,0.004,0.0025,0.0015四段课程；最后一段必须等于目标功率，才能无缝对齐
--max-steps30000两种模式总预算相同，课程内部按阶段均分
--start-steps2000随机探索预算；课程组只在第一阶段消耗（步数全局计）
--eval-every5000评估点覆盖各阶段边界，能看到切换的即时影响
--seed0两种模式同种子，控制变量

阶段长度的设计与切换成本也值得说明：每段 7500 步（3 万步除以四段）是一个折中，太短则每段还没形成稳定策略就切走，回放池里混着多段动力学的数据，价值估计持续被扰动；太长则简单阶段浪费预算、还可能让策略对简单动力学过拟合。切换瞬间有一个可以预期的现象：评估成功率会短暂回落，因为策略的动作节奏仍按上一段的动力学安排。回落幅度与恢复速度是判断"课程是否过陡"的直接读数，日志里把每个评估点的成功率连起来看，就能看到"阶梯状上升"的健康形态。

与前一章的差异点

  • 第 052 章改奖励（塑形），本章不动奖励，改任务动力学：两者是互补的稀疏奖励手段。
  • 新增内联环境 PowerMountainCar（第 052 章用的是官方环境的奖励包装）。
  • 训练循环第一次出现"分段调度"：按步数切换环境、跨阶段保留学习状态。
  • 评估环节从"当前环境的成功率"升级为"始终在目标环境上评估"的公平协议。

关键代码与解读

片段 1：把难度写成一个构造参数

class PowerMountainCar(gym.Env):
    """actor: 连续力 [-1,1]；目标：position >= 0.45 且 velocity >= 0。"""

    def __init__(self, power: float = 0.0015, max_speed: float = 0.07):
        super().__init__()
        self.power = power               # 唯一的难度旋钮：真实环境为 0.0015
        self.max_speed = max_speed
        self.min_position, self.max_position = -1.2, 0.6
        self.goal_position = 0.45
        low = np.array([self.min_position, -max_speed], dtype=np.float32)
        high = np.array([self.max_position, max_speed], dtype=np.float32)
        self.observation_space = gym.spaces.Box(low, high, dtype=np.float32)
        self.action_space = gym.spaces.Box(-1.0, 1.0, shape=(1,), dtype=np.float32)

    def reset(self, seed=None, options=None):
        super().reset(seed=seed)
        if seed is not None:
            self.rng = np.random.default_rng(seed)
        self.state = np.array([self.rng.uniform(-0.6, -0.4), 0.0], dtype=np.float32)
        return self.state.copy(), {}

    def step(self, action):
        position, velocity = float(self.state[0]), float(self.state[1])
        force = float(np.clip(np.asarray(action, dtype=np.float32)[0], -1.0, 1.0))
        velocity += force * self.power - 0.0025 * math.cos(3 * position)   # 功率在这里起作用
        velocity = float(np.clip(velocity, -self.max_speed, self.max_speed))
        position += velocity
        position = float(np.clip(position, self.min_position, self.max_position))
        if position == self.min_position and velocity < 0:
            velocity = 0.0                # 撞左墙清速度，与官方一致
        terminated = bool(position >= self.goal_position and velocity >= 0.0)
        reward = (100.0 if terminated else 0.0) - 0.1 * force ** 2
        self.state = np.array([position, velocity], dtype=np.float32)
        return self.state.copy(), float(reward), terminated, False, {}

解读：（1）动力学逐行复刻官方实现：力裁剪到 ±1、速度加 a·power − 0.0025·cos(3x) 并裁剪到 ±0.07、位置积分并裁剪、撞左墙清速度；成功条件是 position ≥ 0.45 且 velocity ≥ 0；奖励是成功 100 减动作代价。（2）power 是唯一的构造参数差异：0.0015 时与官方环境逐位同构，更大时任务变简单。（3）难度参数只影响"获得动能的效率"，不改变解法结构，先蓄力摆动、再冲刺的模式在所有功率下都成立，这正是技能可迁移的物理依据。（4）成功条件保留了速度非负的要求：注意力矩方向也要正确。注意 truncated 恒为 False，此处没有时间截断（训练循环靠预算控制步数）。

解读：（1）stage_idx = min((step−1)//stage_len, ...) 一行完成"步数 → 阶段"的映射，无需维护额外的计时器。（2）切换时只重建训练环境（新功率、新种子）并重置 obs 与 ep_ret：agent、优化器、目标网络、回放池全部保留，这是课程学习"复用技能"的机制。若把 agent 一起重建，那就变成"先训一个没用的模型再扔掉"。（3）回放池里的旧经验帮价值函数平滑过渡，也可能带来短暂偏差；想实验"清池"的净影响见练习。（4）start_steps 是全局计数的：课程组只在第一阶段的前 2000 步消耗随机探索，之后所有阶段都用策略采样。

片段 3：公平评估，训练可以变、裁判不能变

def make_target_env(seed: int):
    """真实目标环境：gymnasium 的 MountainCarContinuous-v0。"""
    env = gym.make("MountainCarContinuous-v0")   # 评估永远用官方环境
    env.reset(seed=seed)
    env.action_space.seed(seed)
    return env


@torch.no_grad()
def evaluate(agent: SAC, env, episodes: int):
    """在目标环境上评估：返回 (平均回报, 成功率, 平均最大位置)。"""
    returns, successes, max_positions = [], [], []
    for _ in range(episodes):
        obs, _ = env.reset()
        done = False
        ep_ret = 0.0
        max_pos = -1.2
        success = False
        while not done:
            action = agent.act(obs, deterministic=True)   # 确定性策略，可复现
            obs, rew, terminated, truncated, _ = env.step(action)
            ep_ret += rew
            max_pos = max(max_pos, float(env.unwrapped.state[0]))
            success = success or terminated
            done = terminated or truncated
        returns.append(ep_ret)
        successes.append(float(success))
        max_positions.append(max_pos)
    return float(np.mean(returns)), float(np.mean(successes)), float(np.mean(max_positions))

解读：（1）评估环境固定为官方 MountainCarContinuous-v0，与训练用的 PowerMountainCar 隔离，课程组在简单环境上的高分到这里立刻现原形，公平性由协议保证。（2）返回三元组：回报（最终目标）、成功率（稳定性）、最大位置（连续进度），与第 052 章口径一致，便于跨章对比。（3）评估用确定性策略（deterministic=True）并固定种子：结果可复现。（4）日志里同时打印"训练末 50 回合成功率"（训练动力学）与"评估成功率"（目标动力学）：两者在课程早期必然有差距，差距收缩到接近 0 说明技能迁移完成，这个对比本身就是课程质量的仪表。

常见坑

  • 在课程环境上评估并报告成绩：简单环境的高分没有意义。评估必须固定目标环境与固定协议，否则课程组会"自欺欺人"。
  • 最后一段功率与目标不一致：最后一关必须就是目标任务；差一点功率会造成系统性策略偏移，评估成绩骤降。用官方环境评估能立刻暴露问题。
  • 切换阶段时连 agent 一起重建：这就偏离了课程学习，变成"先训一个没用的模型再扔掉"。技能复用要求策略与 Q 网络跨阶段保留。
  • 阶段时长过短：每个阶段还没站稳就切走，前面积累的价值估计全是噪声。max_steps // 段数 至少给数千步，具体取决于任务复杂度。

    给训练奖励加 γΦ(s′)−Φ(s) 项并随阶段调整系数（Φ=50·position）。观察"撤掉引导后"策略是否更贴近原始目标，这是多手段组合的标准套路。

小结

  • 课程学习先把任务调简单、再逐步恢复难度，依赖的是可迁移的技能模式；难度参数化方式决定迁移是否成立。
  • 本章用引擎功率作为难度旋钮，实现四段递减课程，切换时保留策略与回放池。
  • 课程组在首个成功回合、评估成功率、最终评估三项上全面领先直接训练组，稀疏成功信号被"简单版本"提前破解，效率差在训练回合数上同步可见。
  • 公平性的关键：训练环境可以变，评估协议不能变；最后一段课程必须对齐目标动力学。
  • 功率的数值账：满推力下速度增量等于 power，达到速度上限 0.07 分别需要约 12 步（0.006）与 47 步（0.0015），时间尺度差约 4 倍，动作结构不变。
  • 阶段切换允许短期成绩回落：动作节奏需要重新适应，回落幅度与恢复速度是课程坡度是否合适的直接读数。
  • 下一章把"跨任务复用"再推一步：先在源任务上训练，再把参数迁移到动力学不同的目标任务上微调，量化迁移学习省下的样本。
