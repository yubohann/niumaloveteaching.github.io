第二篇 · 离策略方法与 SAC

第 051 章：SAC的连续控制基准测试

让同一套 SAC 超参数依次挑战三个连续控制任务，Pendulum、MountainCarContinuous，以及本章内联实现的二维到达环境 Reach2D，用随机基线与专家参考把回报归一化，横向比较样本效率、达标步数与最终得分。

  • 主题：基准测试设计 / 多环境评估协议
  • 关键公式：scorenorm = (Jπ − Jrandom) / (Jexpert − Jrandom)
  • 预计学时：55 分钟
  • 前置章节：第 050 章

学习目标

  • 理解连续控制基准测试的三要素：统一超参数、统一评估协议、可比的归一化指标。
  • 实现一个纯 numpy 的轻量自定义环境 Reach2D，掌握把自定义任务接入统一训练循环的方法。
  • 用随机策略基线测出每个任务的"地板"，用专家参考把回报归一化到可比较的区间。
  • 对比三个任务的达标步数与归一化得分，解释稀疏成功信号（MountainCar）为何更耗样本。
  • 会判断一个基准结论在什么条件下才具有可迁移性（种子、预算、评估回合数）。

背景与动机

"这个算法在 Pendulum 上能跑"不等于"这个算法可靠"。不同连续控制任务的回报尺度、回合长度、奖励密度差异巨大：Pendulum 每步都有稠密反馈，回报在 −1200 到 −150 之间；MountainCarContinuous 的奖励几乎全部来自"到达山顶"的 +100，观测尺度还跨越两个数量级；二维到达任务则介于两者之间。如果不做归一化，直接把三条回报曲线画在一起，结论会被尺度掩盖。

本章搭建一个最小的基准测试台：固定超参数、固定评估协议，变化任务，把"哪里难"从感觉变成数字。三个任务不是随机选的，它们分别代表稠密奖励、稀疏成功信号、中等难度，正好覆盖连续控制的典型分布。

核心原理

1. 归一化得分

不同任务的回报范围无法直接比较，标准做法是把它映射到"比随机好多少"的比例：

scorenorm = ( Jπ − Jrandom ) / ( Jexpert − Jrandom ) J_random 用随机策略实测；J_expert 是任务的经验上界参考值

符号说明：Jπ 是训练后策略的评估回报，Jrandom 是随机策略的回报，Jexpert 是专家水平参考。scorenorm = 0 表示"和白随机没区别"，= 1 表示"达到专家参考"。分母用实测随机基线，固定数字不可靠：不同任务随机策略的回报差别很大（Pendulum 约 −1200，MountainCar 只有 −30 上下）。脚本把得分裁剪到 [−1, 1]，避免某个任务的极端值主导横向对比。

数值例子：三个任务的归一化得分

取量级示意数字（以实跑为准），逐个代入 scorenorm = (Jπ − Jrandom) / (Jexpert − Jrandom)：

Pendulum：Jrandom ≈ −1200，Jexpert = −150，训练后 Jπ ≈ −250。score = (−250 + 1200) / (−150 + 1200) = 950 / 1050 ≈ 0.90。

MountainCarContinuous：Jrandom ≈ −30，Jexpert = 95，训练后 Jπ ≈ 40。score = (40 + 30) / (95 + 30) = 70 / 125 ≈ 0.56。

Reach2D：Jrandom ≈ 3，Jexpert = 24，训练后 Jπ ≈ 20。score = (20 − 3) / (24 − 3) = 17 / 21 ≈ 0.81。

解读：三个原始回报分别是 −250、40、20，量纲完全不同，直接比较毫无意义；归一化之后差距被压到同一坐标下：0.90 / 0.56 / 0.81。它回答的问题也随之改变：焦点从"谁的分高"转到"离专家参考还有多远、比随机强多少"。注意随机基线必须实测：如果 MountainCar 的基线换一个环境版本变成 −50，同一个 Jπ 的得分会变成 90/145 ≈ 0.62，可见分母的稳定性直接决定结论的可比性。

2. 统一协议的三条硬规则

  • 同一套超参数：任何任务专属的调参都会污染"算法在哪里吃力"的结论。本章 lr、batch、τ、目标熵全部固定。
  • 同一评估协议：确定性策略、相同回合数（10）、相同评估间隔（2000 步）。评估回合数从第 050 章的 5 提到 10，因为基准结论要更稳。
  • 动作范围自适应：策略的 act_scale 从 action_space.high[0] 读取，Pendulum 是 2.0、另外两个是 1.0。这是唯一随环境变化的数值，且它是环境定义的一部分，不是调参。

评估回合数从 5 提到 10 的依据是标准误：n 个回合的均值标准误约为 σ/√n（σ 为单回合回报的标准差）。回合数从 5 增到 10，标准误降为约 0.71 倍；若从 10 增到 30，再降为约 0.58 倍。基准结论要写进报告，宁可评估贵一点也要把噪声压下去；练习 4 会把最终评估加到 30 回合，读者可以对照两次评估数值的差异，体会"报评估回合数"为什么是基准协议的必要信息。

3. 三个任务难在哪

把任务的"探索难度"与"优化难度"分开看，这两个维度比"难/易"的笼统说法有用得多：探索难度决定策略能否找到好轨迹，优化难度决定找到之后能否稳定逼近。同一个算法在两种难度上的短板完全不同，分开标注才能解释实验现象。

Pendulum：稠密奖励 + 平滑动力学 → 优化难、探索易
MountainCarContinuous：稀疏成功信号 + 需要"先退后进" → 探索难
Reach2D：稠密距离奖励 + 到达终止奖励 → 优化与探索都中等

这决定了它们的样本效率：Pendulum 两万步能到 −200 以内；MountainCarContinuous 在两万步里常常只能接近阈值（个别种子直接成功）；Reach2D 在数千步内就能学会"直线冲刺 + 停在目标"。这正是基准测试要呈现的分布，同一算法的样本效率在不同任务上可以差一个量级，报告单任务结果时必须注明任务特性。把三个任务的协议参数与预期表现整理成对照表：

任务奖励结构随机基线专家参考达标阈值主要难点两万步内的预期
Pendulum-v1稠密、负值为主约 −1200−150−400优化：需要精细的力矩控制稳定达标，归一化得分 0.85～0.95
MountainCarContinuous-v0稀疏成功信号约 −309590探索：需要发现"先退后进"通常达不到阈值，得分 0.4～0.7
Reach2D稠密距离项 + 到达奖励约 32412优化与探索都中等数千步内达标，得分 0.7～0.9

读表方法：先看"主要难点"列确定任务性格，再对照"两万步内的预期"判断自己的实现是否正常。若 Pendulum 都跑不进 −400，问题多半在实现层面，任务本身的嫌疑排在其后；若 Reach2D 迟迟不达标，优先检查 reset 的返回格式与动作裁剪。

实现思路与设计

数据流

三个环境串行跑同一套流程：建环境并测随机基线（10 个随机回合，作为归一化下界）→ 训练 20000 步（预热 1000 步，每步一次更新）→ 每 2000 步评估 10 回合，达到阈值记录达标步数 → 结束后补一次评估，计算归一化得分。三个任务的 SOLVE_THRESHOLD 与 EXPERT_REF 集中声明成两张表，主流程按名称查表。

模块划分

组件职责关键点
Reach2DEnv内联二维点质量环境实现 reset/step，用 gym.spaces.Box 声明空间即可被训练循环复用
make_env(name, seed)按名称创建环境（含自定义）统一执行 reset(seed) 与 action_space.seed
SOLVE_THRESHOLD / EXPERT_REF每任务的达标阈值与专家参考集中声明，避免散落在逻辑里
evaluate_random随机策略基线训练前测一次，作为归一化下界
benchmark_env(name)单环境完整训练与评估同种子、同超参数，逐个环境串行跑
maybe_plot可选图表：归一化得分柱状图 + 评估曲线惰性导入 matplotlib，Agg 后端存文件

关键超参数

参数默认值作用与取值理由
--envsPendulum-v1,MountainCarContinuous-v0,Reach2D基准任务列表；可替换成白名单内环境
--max-steps20000每个任务的步数预算（统一，不因任务难易而变）
--eval-episodes10基准结论要求更稳的评估，回合数翻倍
--eval-every2000统一评估节拍，便于比较达标步数
--seed0三个任务共用同一种子，控制变量

三个任务选择串行执行（不并行），原因与结论的可读性有关：串行运行时每个任务独享全部 CPU，评估节拍与训练吞吐不受互相干扰，达标步数的口径干净；并行会把 CPU 竞争引入时间轴，虽然总时长可能更短，但"哪个任务更吃力"的判断会被调度噪声污染。串行的代价是总耗时约为三个任务之和，本章 20000 步预算下总时长仍在可接受范围内。若未来要扩展到十个任务，正确做法是先保证每个任务内部的协议稳定，再考虑用多进程并行、每进程独占一个任务，单进程里交错运行的做法应当避免。

与前一章的差异点

  • 第 050 章在单一任务上搜索超参数；本章固定超参数、变化任务，问题从"怎么调"变成"在哪难"。
  • 新增内联环境 Reach2D 与"环境注册表"式的 make_env。
  • 新增随机基线测量与归一化得分，评估回合数从 5 提到 10。
  • 主流程从"试跑 + 重训"变成"三任务串行基准 + 汇总表 + 可选图表"。

关键代码与解读

片段 1：内联环境 Reach2D，四个接口就能接入

class Reach2DEnv(gym.Env):
    """状态 = [x, y, vx, vy, gx, gy]，动作 = 二维加速度。

    每步奖励 1.5·exp(-2·dist) - 0.05 - 0.02·|a|²，到达目标（dist < 0.1）
    额外奖励 +10 并终止；超过 max_steps 截断。
    """

    def __init__(self, dt: float = 0.1, max_steps: int = 80):
        super().__init__()
        self.dt = dt
        self.max_steps = max_steps
        high = np.array([3.0, 3.0, 3.0, 3.0, 3.0, 3.0], dtype=np.float32)
        self.observation_space = gym.spaces.Box(-high, high, dtype=np.float32)
        self.action_space = gym.spaces.Box(-1.0, 1.0, shape=(2,), dtype=np.float32)
        self.rng = np.random.default_rng(0)
        self.state = np.zeros(6, dtype=np.float32)
        self.steps = 0

    def reset(self, seed=None, options=None):
        super().reset(seed=seed)
        if seed is not None:
            self.rng = np.random.default_rng(seed)   # reset 时的种子独立可复现
        goal = self.rng.uniform(-1.2, 1.2, size=2)
        self.state = np.zeros(6, dtype=np.float32)
        self.state[4:] = goal                        # 后两维是目标坐标
        self.steps = 0
        return self.state.copy(), {}                 # gymnasium 要求 (obs, info)

    def step(self, action):
        a = np.clip(np.asarray(action, dtype=np.float32), -1.0, 1.0)
        self.steps += 1
        # 一阶动力学：速度带 0.1 阻尼，位置积分速度
        self.state[2:4] += (a - 0.1 * self.state[2:4]) * self.dt
        self.state[0:2] += self.state[2:4] * self.dt
        dist = float(np.linalg.norm(self.state[0:2] - self.state[4:6]))
        reward = 1.5 * math.exp(-2.0 * dist) - 0.05 - 0.02 * float(np.sum(a ** 2))
        terminated = dist < 0.1
        truncated = self.steps >= self.max_steps
        if terminated:
            reward += 10.0
        return self.state.copy(), float(reward), bool(terminated), bool(truncated), {}

解读：（1）训练循环只用到环境的四个接口：observation_space.shape、action_space.shape、action_space.high[0]、reset/step。用 gym.spaces.Box 把前三个补全，Reach2D 就与 gymnasium 原生环境没有区别，训练代码不需要知道环境是内置还是自定义。（2）reset 返回 (obs, info) 二元组：这是 gymnasium 的 API 约定，返回单个 obs 会让训练循环第一次 reset 就崩溃。（3）动力学两步走：先更新速度（含 0.1 阻尼）再积分位置，保证可控又不失控。（4）奖励三段式：距离指数项 1.5·exp(−2·dist) 稠密平滑（远离目标时梯度弱）、固定代价 −0.05 催促尽快完成、动作代价 −0.02·|a|² 鼓励节能；到达 +10 并终止。这个设计让"策略质量"可被连续信号区分，跳出了"只有成败两档"的限制。

片段 2：任务注册表，阈值与专家参考集中管理

# 每个任务的"专家参考回报"（用于归一化），数值为经验量级
EXPERT_REF = {
    "Pendulum-v1": -150.0,
    "MountainCarContinuous-v0": 95.0,
    "Reach2D": 24.0,
}
# 每个任务的达标阈值（评估回报 >= 阈值算达标）
SOLVE_THRESHOLD = {
    "Pendulum-v1": -400.0,
    "MountainCarContinuous-v0": 90.0,
    "Reach2D": 12.0,
}


def make_env(name: str, seed: int):
    """按名称创建环境：内置自定义环境或 gymnasium 环境。"""
    if name == "Reach2D":
        env = Reach2DEnv()               # 内联环境走专属构造
    else:
        env = gym.make(name)             # 其余交给 gymnasium 注册表
    env.reset(seed=seed)                 # 统一锁定随机种子
    env.action_space.seed(seed)          # 动作采样流也固定
    return env

解读：（1）两个常量表是"基准协议"的物化：阈值决定"达标步数"的判定线，专家参考决定归一化的上界。集中声明的意义是，改协议只改一处，不会出现某个任务用了旧阈值的错位。（2）make_env 用名称分派：自定义环境与 gymnasium 环境走不同构造，但出口接口完全一致（都经过 reset(seed) + action_space.seed）。这是"注册表模式"的最小实现，加第四个任务只需加一个分支和两张表的一行。（3）注意这里不以任何方式调整超参数：动作范围通过返回值 action_space.high[0] 被上层读取，属于环境定义的一部分。

片段 3：随机基线与归一化得分

@torch.no_grad()
def evaluate_random(env, episodes: int) -> float:
    """随机策略基线：归一化得分的下界参考。"""
    returns = []
    for _ in range(episodes):
        obs, _ = env.reset()
        done = False
        ep_ret = 0.0
        while not done:
            action = env.action_space.sample()       # 直接用环境动作空间采样
            obs, rew, terminated, truncated, _ = env.step(action)
            ep_ret += rew
            done = terminated or truncated
        returns.append(ep_ret)
    return float(np.mean(returns))

    random_baseline = evaluate_random(eval_env, args.eval_episodes)

    expert_ref = EXPERT_REF[name]
    final_eval = evaluate(agent, eval_env, args.eval_episodes)
    all_evals = eval_returns + [final_eval]
    best_eval = max(all_evals)
    norm = (final_eval - random_baseline) / max(expert_ref - random_baseline, 1e-9)
    norm = float(np.clip(norm, -1.0, 1.0))           # 裁剪只影响展示，不改变原始回报

解读：（1）基线测量放在训练开始前（同一评估环境、相同种子），保证可复现；随机策略直接用 env.action_space.sample()，不经过网络，避免初始化策略带来偏差。（2）归一化分母加 max(..., 1e-9) 防除零：极端情况下专家参考可能等于随机基线。（3）np.clip(norm, −1, 1) 只是防止某个任务的极端值主导图表；分析时必须回到原始评估回报，裁剪不该被用来掩盖数值问题。（4）all_evals 同时保留过程评估与最终评估：best_eval 用于看潜力上限，final_eval 用于算归一化得分，两个口径分开报告。

常见坑

  • 用固定数字当随机基线：不同机器/版本的随机策略回报会变，基线必须实测。本章训练前用评估环境现测一次，保证归一化分母可信。
  • 给简单任务少预算、难任务多预算：这样比较的是"你花了多少时间"，任务难度被置于比较之外。基准协议的预算必须统一，即使某个任务明显吃不饱。
  • 自定义环境 reset 忘记返回 (obs, info)：gymnasium 与旧版 gym 的 API 不同，返回单个 obs 会让训练循环第一次 reset 就崩溃。
  • 归一化得分越界后不报告原始值：裁剪只影响显示，分析必须回到原始评估回报。MountainCar 的随机基线本身波动大，得分 0.5 与 0.7 的差别可能并不显著。
  • 拿离散动作环境直接跑：如 Acrobot-v1 的 Discrete 空间没有 high 属性，脚本会在读取 action_space.high[0] 时报错，连续 SAC 与离散环境需要第 037 章的适配。

练习与思考

  1. 把 --envs 改成 Acrobot-v1 试试会发生什么，然后解释为什么连续 SAC 需要额外的适配。★
    提示
    Acrobot 是离散动作环境，action_space.high 不存在，脚本会直接报错。这正是第 037 章离散 SAC 存在的意义。
  2. 把 --max-steps 提到 40000 只跑 MountainCarContinuous，观察达标步数与归一化得分。它需要多少步跨过 90 分？★★
    提示
    临界点在于能否偶然发现到达山顶的轨迹；一旦发现，SAC 会迅速利用。多跑几个种子看"发现时刻"的分布，这是稀疏成功信号的典型行为。
  3. 给 Reach2D 增加一个目标半径参数，分别取 0.05 与 0.3，比较达标步数。任务变简单后得分还能拉开差距吗？★★
    提示
    半径越大越容易终止、越容易吃到 +10，但距离奖励的形状不变。观察"最好评估"与"最终评估"的差距是否变小，奖励的稠密部分仍在区分策略质量。
  4. 把评估协议改成"训练中每 2000 步评估 10 回合、最终评估 30 回合"，对比最终评估数值的变化。为什么基准测试必须报告评估回合数？★★
    提示
    回合数越多估计的标准误越小（与 √n 成反比）。30 回合评估的 Pendulum 回报通常比 10 回合低一点，因为剔除了运气好的回合。
  5. 给 benchmark_env 加多种子支持（每任务 3 个种子），报告归一化得分的均值与标准差。哪些任务的种子方差最大？★★★
    提示
    把训练包在 set_seed(args.seed + k) 的循环里，汇总用 np.mean/np.std。预计 MountainCar 方差最大、Pendulum 最小，这才是可靠的"任务难度"排序依据。

小结

  • 连续控制基准测试的三要素：统一超参数、统一评估协议、归一化指标；三者缺一项，横向结论就不可比。
  • 本章用随机基线 + 专家参考把回报归一化，给出三任务的可比分数与达标步数，量纲差异被坐标变换吸收。
  • Pendulum 优化友好但奖励稠密，MountainCarContinuous 卡在稀疏成功信号的探索效率上，Reach2D 介于两者之间，探索与优化两个维度要分开标注。
  • 内联自定义环境只需实现 reset/step 与三个空间属性，就能无缝接入既有训练循环，这是"环境接口即协议"的最小验证。
  • 归一化得分的三个算例（量级示意）：−250/−1200/−150 的组合得 0.90，40/−30/95 得 0.56，20/3/24 得 0.81；原始回报不可比，归一化后才在同一坐标下讨论。
  • 评估回合数必须写进协议：回合均值标准误按 1/√n 收缩，10 回合相比 5 回合把噪声降到 0.71 倍，30 回合再降到 0.58 倍，这是报告基准结果时的必备信息。
  • 下一章正面处理基准测试暴露出的最痛问题：稀疏奖励，用"稀疏 MountainCarContinuous"对照带势函数塑形的版本，量化塑形带来的样本效率收益，并讨论塑形奖励的偏置风险。
