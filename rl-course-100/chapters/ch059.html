第二篇 · 离策略方法与 SAC

第 059 章：SAC的对抗攻击防御

把第 058 章的随机噪声升级成"最坏方向"的对手：用 PGD 在 L∞ 球内搜索能让动作偏离最大的观测扰动，评估谁是纸老虎；再用对抗训练与动作平滑两条防线，看它们各自能挽回多少性能。

  • 主题：对抗攻击 / 对抗训练防御
  • 关键公式：max‖δ‖∞≤ε ‖π̄(s+δ) − π̄(s)‖²；Ãt=0.5at+0.5Ãt−1
  • 预计学时：60 分钟
  • 前置章节：第 058 章

学习目标

  • 理解对抗攻击与随机扰动的区别：前者沿损失梯度构造最坏输入，是更强的威胁模型。
  • 实现针对策略网络的 PGD（Projected Gradient Descent）观测攻击：最大化"被攻击观测的动作与干净动作的偏离"。
  • 实现对抗训练防御：交互时把攻击后的观测喂给策略与回放池，让训练分布覆盖最坏情况。
  • 对比干净策略与对抗训练策略在 ε ∈ {0.02, 0.05, 0.10} 攻击下的保持率和动作偏离。
  • 会评估动作平滑这一零成本防御，理解它"缓解不根治"的边界。

背景与动机

第 058 章的观测噪声是"上帝掷骰子"：扰动均匀地撒在球内，多半被策略的容错吸收。但现实里的威胁未必随机，传感器故障、信号干扰乃至恶意攻击者，都会朝着"让控制器犯错"的方向构造输入。这类威胁的评测方法来自对抗样本研究：对手知道网络权重，用梯度上升搜索一个小到不易察觉的扰动，让输出偏离最大。控制策略一旦被这样扰动，动作会突然反向或抖动，摆杆应声倒地。

本章沿用第 058 章的两个策略设定，但把评估换成"最坏方向攻击"，并把防御方法换成对抗训练与动作平滑，一个改训练、一个改部署，成本与效果各不相同。

核心原理

1. PGD 攻击的构造

给定干净观测 s、策略的确定性输出 a = π̄(s)，攻击目标是找一个扰动 δ，使得扰动后的动作尽量偏离：

max‖δ‖∞ ≤ ε   ‖ π̄(s + δ) − π̄(s) ‖2 PGD 迭代：δ ← clip[−ε,ε]( δ + α·sign(∇δ‖π̄(s+δ) − π̄(s)‖²) )

符号说明：ε 是扰动上限（L∞ 球半径），α 是每步步长，通常取 2.5ε/步数；每步沿梯度符号方向走一小步，再投影回 ε 球。动作偏离量就是攻击强度的物理指标，它解释了回报为什么下降：偏离 0.05 时策略还能校正，偏离 0.5 以上时力矩符号都可能被翻转。

2. 对抗训练的机制

对抗训练把"攻击 → 响应"的对应关系编进训练数据：每个交互步先用当前策略生成攻击观测 s̃ = s + δ*，策略对 s̃ 输出动作，环境照常执行，回放池里存的是 s̃。这样策略学的是"在干净分布 ∪ 攻击分布上的最优响应"：

minθ 𝔼s~ρ, δ∈Δ[ −Q(s + δ, πθ(s + δ)) ] 内层最大化破坏、外层最小化损失，与生成对抗训练的 minimax 结构同源

代价：训练里策略的输入永远带扰动，干净条件下的动作精度会略降；而且防御只对训练时使用的 ε 有效，攻击者加大 ε 就绕过了。这就是"用一点干净性能换鲁棒"的具体含义。

3. 动作平滑防御

攻击的典型效应是让动作高频抖动。给输出加一阶低通滤波：

ãt = 0.5·at + 0.5·ãt−1 等价于把攻击引入的部分高频分量衰减一半

平滑不需要重训、不需要知道攻击方式，但对强攻击只能缓解不能根治，它牺牲的是响应速度（等效增加一个采样周期的惯性）。系数越大越平滑、响应越慢，在 Pendulum 上干净性能的损失也更明显（练习里验证）。

实现思路与设计

数据流

流程两步。训练：clean 与 adv 两个策略同种子各训练 12000 步；adv 把每步观测先经 3 步 PGD 攻击再喂策略，next_obs 用 1 步攻击近似（控制成本），回放池存的是被攻击的观测链。评估矩阵：两个受害者 ×（干净基线 + 三档 ε 攻击 + 中档 ε 攻击加平滑），记录回报、保持率与动作偏离。评估攻击用 10 步 PGD，"训练弱、评测强"。

与前一章的差异点

  • 第 058 章评估四类随机扰动；本章只攻观测一维，但把"随机噪声"换成最坏方向攻击。
  • 新增 PGD 攻击函数与动作偏离诊断；评估函数内置攻击循环。
  • 防御从"观测噪声增强"换成"对抗训练 + 动作平滑"两种新机制。
  • 汇总表从保持率矩阵变成"攻击强度 × 防御组合"的评估矩阵。

关键代码与解读

片段 1：PGD 攻击，在 ε 球内追着动作偏离走

def pgd_attack(agent: SAC, obs, eps: float, steps: int) -> np.ndarray:
    """对观测做 PGD 攻击，目标是让确定性动作偏离干净动作最多。

    返回被攻击后的观测（numpy）。eps <= 0 时原样返回。
    """
    if eps <= 0:
        return np.asarray(obs, dtype=np.float32)
    obs_t = torch.as_tensor(np.asarray(obs, dtype=np.float32)).unsqueeze(0)
    with torch.no_grad():
        base_action = agent.policy.mean_action(obs_t)   # 基准动作只算一次并冻结
    delta = torch.zeros_like(obs_t, requires_grad=True)
    alpha = 2.5 * eps / max(steps, 1)                   # 总行程 2.5ε，从零到满球
    for _ in range(steps):
        adv_action = agent.policy.mean_action(obs_t + delta)
        loss = -((adv_action - base_action) ** 2).sum()  # 最小化负偏离 = 最大化偏离
        grad = torch.autograd.grad(loss, delta)[0]
        delta = (delta + alpha * grad.sign()).detach()   # FGSM 步：只用符号方向
        delta = delta.clamp(-eps, eps)                   # 投影回 L∞ 球
        delta.requires_grad_(True)
    return (obs_t + delta.detach()).squeeze(0).numpy()

解读：（1）base_action 在循环外计算并冻结：否则每步都在优化的目标会"追着自己跑"，攻击方向漂移。（2）目标函数取偏离平方和的负值，梯度上升最大化偏离，是被攻击目标最直观的选择。（3）步长 alpha = 2.5ε/steps：从零出发、步数走满后正好可以覆盖 2.5ε 的总行程，几轮内到达球内最优附近。（4）clamp(-eps, eps) 是 L∞ 投影：漏掉这步扰动会无界增长，评测出的"鲁棒性"毫无意义。（5）用 torch.autograd.grad(loss, delta) 只对 δ 求梯度，不污染网络参数的 .grad，评估阶段绝不能给网络留下训练副作用。

片段 2：攻击评估，回报与动作偏离一起看

def evaluate_attack(agent: SAC, eps: float, smooth: bool, episodes: int,
                    attack_steps: int, seed: int):
    """在攻击下评估：返回 (平均回报, 平均动作偏离)。"""
    env = make_pendulum(seed)
    returns, devs = [], []
    for _ in range(episodes):
        obs, _ = env.reset()
        done = False
        ep_ret = 0.0
        prev_action = np.zeros(env.action_space.shape, dtype=np.float32)
        while not done:
            if eps > 0:
                obs_t = torch.as_tensor(np.asarray(obs, dtype=np.float32)).unsqueeze(0)
                with torch.no_grad():
                    a_clean = agent.policy.mean_action(obs_t)
                adv_obs = pgd_attack(agent, obs, eps, attack_steps)
                with torch.no_grad():
                    a_adv = agent.policy.mean_action(
                        torch.as_tensor(adv_obs).unsqueeze(0))
                devs.append(float((a_adv - a_clean).abs().mean().item()))
                action = a_adv.squeeze(0).numpy()
            else:
                action = agent.act(obs, deterministic=True)
            if smooth:
                action = 0.5 * action + 0.5 * prev_action   # 一阶低通滤波
                prev_action = action.astype(np.float32)
            obs, rew, terminated, truncated, _ = env.step(action)
            ep_ret += rew
            done = terminated or truncated
        returns.append(ep_ret)
    return float(np.mean(returns)), float(np.mean(devs)) if devs else 0.0

解读：（1）每个环境步都记录"被攻击动作与干净动作的 |Δa|"：动作偏离随 ε 的增长曲线是比回报更直接的机理证据，也是本章的辅助诊断量。（2）威胁模型是"传感器被欺骗"：adv_obs 只喂给策略，env.step 收到的仍是正常动作，环境真实状态不变，别把 δ 也传进动力学（那样任务语义就变了）。（3）平滑用 0.5a + 0.5·prev：prev_action 在回合内累积、回合间重置为 0。平滑对攻击是缓解：它衰减高频抖动量，但延迟补偿永远无法恢复原始响应速度。（4）eps=0 分支走干净的 agent.act：同一函数既能做基线评估又能做攻击评估，口径统一。

片段 3：对抗训练，把攻击写进数据链

    for step in range(1, args.max_steps + 1):
        if step <= args.start_steps:
            action = env.action_space.sample()
            obs_in = obs
        else:
            if adversarial:
                # 对抗训练：策略看到的是被攻击后的观测
                obs_in = pgd_attack(agent, obs, args.adv_eps, args.adv_steps)
            else:
                obs_in = obs
            action = agent.act(obs_in, deterministic=False)
        next_obs, rew, terminated, truncated, _ = env.step(action)
        next_in = next_obs
        if adversarial and step > args.start_steps:
            # next_obs 也用同样强度的攻击，保持数据分布一致
            next_in = pgd_attack(agent, next_obs, args.adv_eps, 1)  # 单步近似，降低开销
        buffer.add(obs_in, action, rew, next_in, float(terminated))
        obs = next_obs

解读：（1）对抗训练与第 058 章噪声增强的结构同构：策略输入与回放池都用被攻击的观测，只是"噪声"换成了"最坏方向的扰动"。（2）训练攻击只用 3 步（adv_steps）：每一步交互都要做攻击，成本是 PGD 步数的倍数；3 步的弱攻击已能把扰动方向引进来，学会稳健响应。（3）评测用 10 步完整攻击，"训练弱、评测强"能避免虚高的安全感。（4）next_in 用 1 步攻击近似：完整做法是对 next_obs 也跑 3 步，但收益有限、成本翻倍；教学版明确记录这个取舍，练习里可以替换成完整版。（5）预热期不攻击：随机动作阶段没有策略参与，攻击无意义。

常见坑

  • 把扰动施加到环境上，未施加到策略输入上：本章的威胁模型是"传感器被欺骗"，环境真实状态不变。把 δ 也传进 env.step 的动力学，任务语义就变了。
  • 忘记投影回 ε 球：PGD 每步必须 clamp(-eps, eps)。漏掉后扰动无界增长，评测出的"鲁棒性"毫无意义。
  • 用采样动作做攻击目标：动作里的探索噪声会稀释攻击方向，且每次前向的噪声不同、梯度不可比。攻击与诊断统一使用确定性均值动作。
  • 对抗训练时干净观测与攻击观测混存错位：存进回放池的 obs 与 next_obs 必须来自同一条被攻击的观测链，否则 Q 目标基于混合分布、价值估计失配。
  • 把训练攻击步数当作评测强度：用 3 步攻击去评估会让保持率虚高（攻击更弱）。评测务必用比训练更强的攻击（本章 10 步）。

练习与思考

  1. 把 --adv-eps 调到 0.1，重跑评估矩阵。防御半径变大后，干净基线损失多少、0.10 攻击下的保持率提升多少？★
    提示
    防御与攻击半径匹配时收益最大。对比两次运行中 adv 的干净基线与 ε=0.10 行，看"换"得值不值。
  2. 把评估攻击从 10 步减到 3 步（--attack-steps 3），保持率会虚高还是虚低？解释 PGD 步数与攻击强度的关系。★★
    提示
    步数少 → 攻击弱 → 策略看起来更鲁棒，这是"评测过松"的典型隐患。对比两次矩阵中 clean 的 ε=0.05 行差值。
  3. 把动作平滑系数从 0.5 改成 0.2 与 0.8，观察攻击与干净基线的平衡。预测哪一端损失更大再验证。★★
    提示
    系数越大越平滑、抗抖动越好，但响应越慢，干净条件下也会丢分。找"攻击收益 ÷ 干净损失"的平衡点。
  4. 把攻击目标从"动作偏离"换成"最小化 Q(s, π(s+δ))"，重跑 clean 的评估。两种攻击对策略的破坏方式有区别吗？★★★
    提示
    把 pgd_attack 的 loss 改为 agent.q1(obs_t, adv_action).mean()（最小化即取负）。攻击 Q 会让策略走向"低价值"的状态-动作，破坏可能更隐蔽。
  5. 把对抗训练与噪声增强叠加（先加高斯噪声再攻击），检验"组合防御"是否优于单一手段。★★★
    提示
    在对抗分支里先加噪再 PGD，两种扰动叠加会扩大训练分布。评估协议不变、只改训练；对比 adv 与 combined 两个策略的矩阵行。

小结

  • 对抗攻击把"随机噪声"升级为"最坏方向扰动"：PGD 在 L∞ 球内搜索能最大化动作偏离的观测欺骗。
  • 对抗训练把攻击分布纳入训练数据，用少量干净性能换取攻击下的保持率；防御半径决定换取的比例。
  • 动作平滑是零成本防御，通过低通滤波衰减攻击引起的高频抖动，但会牺牲响应速度。
  • 评测要"训练弱、测评强"：用 3 步攻击训练、10 步攻击评估，避免虚高的鲁棒性结论。
  • 下一章换一个更"主动"的思路：不只用价值函数决策，还训练一个动力学模型做多步预测，SAC 与模型预测控制（MPC）结合。
