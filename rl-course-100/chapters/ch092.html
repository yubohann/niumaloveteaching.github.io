第 092 章：多智能体环境：仓储机器人

在 10×10 的仓库里放 3 台机器人：取货、送货、别撞队友，用共享网络的双重 DQN 训练整支车队，看每 1000 步订单数能否从随机基线的接近 0 追到脚本贪心水平，同时冲突更少。

  • 主题：环境设计 / 网格仓储与双重 DQN（Double DQN）
  • 关键公式：y = r + γ·Qθ⁻(s′, argmaxa′ Qθ(s′, a′))
  • 预计学时：60 分钟
  • 前置章节：第 091 章

学习目标

  • 把真实物流场景（拣货—送达）抽象成网格 MDP：状态、动作、携带/空载两种模式、动态补货。
  • 掌握网格多机器人特有的冲突消解：同格冲突、对穿冲突与级联等待，理解为什么"轮流走"比"硬挤"效率高。
  • 用共享网络 + 双重 DQN 训练 3 台机器人，理解双重 DQN 相比朴素 Q 学习如何抑制过估计。
  • 构建可比基线：随机策略与脚本贪心（最近任务目标优先），用"每 1000 步订单数 / 单耗步数 / 冲突频率"三指标评估。
  • 观察任务分配如何从个体贪心中自动涌现（不同机器人自然扑向不同货物），以及"等待"动作的独立价值。

背景与动机

仓储机器人是"多智能体 + 空间 + 任务流"的组合：机器人可以主动接单（取货）也可以被动等待（让路），任务随补货不断产生，评价指标是整支车队的吞吐量。它比纯追逐任务多了一层任务分配问题，三台机器人不需要开会，但必须避免都扑向同一个货物、又不该都堵在同一条通道上。

这也是网格 DQN 再次登场的场景：离散动作天然对应"上下左右 + 等待"，而"等待"这个动作在多机器人环境里有独立价值（让路），单人任务里几乎用不到。观察日志里"冲突/步"的下降，你会看到学习策略如何学会用"等待"兑换整体效率，这是协调行为从个体奖励中涌现的直接证据。后续第 095 章资源收集会把"分配"主题做得更细。

核心原理

1. 任务流与奖励

场上始终保持 3 个待取货物；机器人踩到货物格即取货（进入携带状态），货物立刻在别处重生。奖励为：

ri,t = −0.01 − 0.02·di任务 − 0.02·𝟙[被堵] + 1.0·𝟙[完成一单]

其中 d任务 是"到当前任务目标的曼哈顿距离"：未携带时目标为最近货物，携带时目标为最近发货站。这个塑形项等价于给机器人装了一个"方向指南针"，把稀疏的订单事件变成稠密信号；−0.02 的堵车惩罚鼓励绕行，但量级远小于订单奖励（1.0），避免机器人变成"胆小怕事"。

2. 冲突消解的三层判定

多机器人网格世界最容易被低估的是移动合法性。本章按三层判定每一步：

  • 同格冲突：两台机器人期望进入同一格 → 双方都不动；
  • 对穿冲突：A 想进 B 的格子、同时 B 想进 A 的格子 → 双方都不动（否则会互相穿过）；
  • 级联等待：被上面两条判定堵住的机器人会停在原地，其他想进它格子的机器人也必须等待，这是迭代收敛过程，代码用 while changed 循环处理。

没有第三层，就会出现"机器人 A 因冲突站着不动、机器人 B 一头撞进 A 身体"的幽灵现象，单耗步数会突然变短（穿了捷径），但物理世界不接受这种捷径。

3. 为什么用双重 DQN

朴素 DQN 用同一个网络既选动作又评估价值，max 操作会把估计噪声放大成系统性过估计；双重 DQN 让在线网络选动作、目标网络评估：

y = r + γ(1−d)·Qθ⁻( s′, argmaxa′ Qθ(s′, a′) )

符号：θ 是在线网络、θ⁻ 是目标网络、d 是终止掩码。在本任务里过估计的直接后果是"以为挤一下也能拿分"，然后学会抱团；双重 DQN 的抑制恰好对应冲突频率的改善，算法的一个小改动，行为上表现为"礼貌"。

4. 观测与参数共享

观测里既有绝对坐标（自己位置）也有相对坐标（货物、站点、队友），因为任务分配必须知道自己在网格里的位置（判断"哪边更近"）。三台机器人共享一个网络：网格对称、任务对称，经验可以流通；"携带状态"作为一维输入，让策略在同一网络内区分两种行为模式（空载找货/满载找站）。

5. 评价指标的口径

"每 1000 步订单数"把吞吐量归一化到时间尺度；"平均单耗步数"衡量单次任务效率；"冲突/步"衡量协调质量。三者可能此消彼长：单耗短但冲突高说明策略激进；冲突低但单耗长说明策略畏缩。只看一个都会误判，这是本章评测协议的核心。

与前一章的差异

第 091 章是连续三维跟踪、IDDPG、逐机独立奖励；本章回到网格离散动作，算法换成双重 DQN，同时引入任务流与硬约束防撞两个新机制。评价口径从"编队误差"变成"吞吐量 + 冲突率"，从"保持阵型"到"多拉快跑"，多智能体环境的设计维度明显变宽了。

"等待"为什么值得作为独立动作

在四方向移动的网格里，"原地不动"通常被当作无效动作删掉；但多机器人环境里它是协调资源：让路、错峰、避开对穿都要靠等待实现。保留它，策略才有"礼让"这个选项；删掉它，冲突只能靠绕远解决，最优解空间被无谓地缩小。日志里学习策略冲突率低于贪心，一半功劳在"学会了用等待换效率"。

关键代码与解读

片段 1：货物重生，避开一切占用

def _spawn_item(self):
    """随机找一个没有被占用的格子生成货物。"""
    for _ in range(200):
        cell = self.rng.integers(0, self.size, size=2)
        if any((cell == self.stations).all(axis=1)):
            continue                     # 不能落在发货站上
        if any((cell == p).all() for p in self.pos):
            continue                     # 不能落在机器人脚下
        if any((cell == it).all() for it in self.items):
            continue                     # 不能和其他货物重叠
        return cell.astype(np.int64)
    return self.rng.integers(0, self.size, size=2).astype(np.int64)

解读：小函数，但堵住了一个会污染训练信号的漏洞。（1）三条排他检查对应三类占用：站点（业务规则）、机器人（否则"白捡"订单，塑形信号直接失真）、已有货物（否则两件货叠在一格）。（2）重试上限 200 次后兜底返回纯随机格：在 10×10 网格上 200 次几乎必然成功，兜底只是防御性写法，不要写 while True，环境重置卡死会毁掉整个训练循环。（3）(cell == self.stations).all(axis=1) 是"整行相等"的惯用写法：先广播比较得到 (n,2) 布尔矩阵，再按行取 all。（4）货物数与位置构成任务流：重生是即时的，场上始终 3 个货物，这保证"每 1000 步订单数"指标不被任务枯竭干扰，是吞吐量评测的前提。

片段 2：三层冲突消解，网格多机器人的灵魂

# 1) 计算期望位置：动作 0 是原地等待，其余为四方向移动
desired = self.pos.copy()
for i in range(self.n_agents):
    act = int(actions[i])
    if act > 0:
        dr, dc = self.move_delta[act - 1]
        desired[i, 0] = int(np.clip(self.pos[i, 0] + dr, 0, self.size - 1))
        desired[i, 1] = int(np.clip(self.pos[i, 1] + dc, 0, self.size - 1))

# 2) 第一层：同格冲突与对穿冲突，双方都被判阻塞
blocked = np.zeros(self.n_agents, dtype=bool)
for i in range(self.n_agents):
    for j in range(i + 1, self.n_agents):
        if (desired[i] == desired[j]).all():
            blocked[i] = blocked[j] = True         # 想进同一格：都不许动
        if (desired[i] == self.pos[j]).all() and (desired[j] == self.pos[i]).all():
            blocked[i] = blocked[j] = True         # 对穿：交换位置也不行
# 3) 第三层：级联等待，被堵者的当前格变成别人的"禁入区"
changed = True
while changed:
    changed = False
    for i in range(self.n_agents):
        if blocked[i]:
            continue
        for j in range(self.n_agents):
            if i == j:
                continue
            target_j = self.pos[j] if blocked[j] else desired[j]
            if (desired[i] == target_j).all():
                blocked[i] = True                  # 撞向等待者：自己也必须停
                changed = True
                break
self.conflicts += int(blocked.sum())

解读：这段 30 行左右的代码是"移动合法性"的完整语义，也是全章最值得反复读的实现。（1）期望位置独立计算（先谁都不动），所有冲突判定基于"大家同时想动"的瞬间快照，顺序依赖会让先动者占便宜，多机器人环境不能有这种偏袒。（2）对穿判定必须成对检查 (desired[i]==pos[j]) and (desired[j]==pos[i])：单向检查会把"我撞向你"误判，而漏掉对穿则两台机器人会互换位置，网格世界的"穿模"事故。（3）级联循环的语义：blocked 的机器人"事实上停在原地"，它的当前格就是本步的新障碍；其他人撞向障碍同样被堵。用 target_j 三元表达式统一处理"等待者用当前位置、正常者用期望位置"。（4）收敛性有保证：blocked 集合只增不减，最多 N 轮；conflicts 累计被堵机器人数，它是"协调质量"指标，学习目标里没有直接最小化它，但通过"被堵 −0.02"的惩罚间接传递。

片段 3：取货、送货与双向塑形

rewards = np.full(self.n_agents, -0.01, dtype=np.float32)   # 每步时间成本
for i in range(self.n_agents):
    if blocked[i]:
        rewards[i] -= 0.02                       # 被堵：返工惩罚
    if not self.carrying[i] and len(self.items):
        k = int(np.argmin(np.abs(self.items - self.pos[i]).sum(axis=1)))
        if (self.items[k] == self.pos[i]).all():
            self.carrying[i] = 1                 # 踩到货物格：取货
            self.items[k] = self._spawn_item()   # 原处立即补生一件
    if self.carrying[i]:
        if any((self.pos[i] == s).all() for s in self.stations):
            self.carrying[i] = 0
            rewards[i] += 1.0                    # 送达：全局唯一的稀疏大奖励
            self.deliveries += 1

# 4) 塑形：朝"任务目标"靠近（携带→站点；空载→货物），曼哈顿距离
for i in range(self.n_agents):
    if self.carrying[i]:
        target, d = self._nearest(self.stations, self.pos[i])
    else:
        target, d = self._nearest(self.items, self.pos[i])
    rewards[i] -= 0.02 * d

解读：任务语义与奖励的"两段式"都在这里。（1）取货与送货的顺序：先判取（本步刚到位就能拿），再判送，如果一台机器人本步同时踩在货物格和站点上（理论可能），先取后送会让它当步完成，行为合理。（2）订单奖励只发给送达者本人（rewards[i] += 1.0）：这是本章的"个人绩效"设计，与 088 章的团队共享形成对照，任务分配型环境里，个体奖励更能鼓励吞吐。（3）塑形项依赖携带状态选择目标：空载时朝货物、满载时朝站点；用曼哈顿距离（abs().sum()）：它与四方向移动模型一致，换欧氏会造成"斜对角更近却一步走不到"的塑形偏差，这是网格环境最常见的错误之一。（4）量级对照：−0.01（时间）+ −0.02·d（方向）+ −0.02（堵）+ 1.0（订单）。订单奖励约等于 15 步的塑形总额，保证"完成任务"始终压倒"原地磨蹭"。

片段 4：双重 DQN 的目标计算

with torch.no_grad():
    # 双重 DQN 的关键两行：在线网络选动作、目标网络评估价值
    next_actions = self.q(next_obs).argmax(dim=1, keepdim=True)
    q_next = self.q_target(next_obs).gather(1, next_actions)
    y = rew + args.gamma * (1.0 - done) * q_next
q = self.q(obs).gather(1, act)                   # 当前状态-动作的 Q 值
loss = F.smooth_l1_loss(q, y)                    # 平滑 L1：对离群 TD 误差更稳健
self.optimizer.zero_grad()
loss.backward()
nn.utils.clip_grad_norm_(self.q.parameters(), 5.0)   # 梯度裁剪防偶发大步
self.optimizer.step()
self.updates += 1
if self.updates % args.target_update == 0:       # 硬更新：每 200 次同步一次
    self.q_target.load_state_dict(self.q.state_dict())

解读：与第 088 章单 Q 版本相比，只差一行 argmax 的位置，效果却差在稳定性上。（1）朴素版 q_target(next_obs).max(...) 让同一个网络既选最大又评最大，argmax 的噪声放大了高估；双重版让在线网络挑"哪个动作好"，目标网络回答"它值多少"，两个网络的估计误差不再同源。（2）gather(1, next_actions) 的用法值得记住：先得到形状 (B,1) 的动作索引，再沿维度 1 收集对应的 Q 值，避免手工循环。（3）smooth_l1_loss（Huber）对离群 TD 误差更稳健，仓储任务里偶尔出现"送达瞬间的大 TD"，MSE 会被它带偏。（4）目标网络用硬更新（每 200 次整表复制），与 SAC 的软更新不同：DQN 家族在离散动作任务上硬更新更常见，周期够短就不会造成明显的目标漂移。

常见坑

  • 只做同格/对穿判定：不做级联等待，会出现两台机器人重叠的幽灵状态。日志表现为单耗突然变短，不是学好了，是穿模了。
  • 货物重生不检查占用：货物撒在机器人脚下会"白捡"订单，学习信号被污染。重生必须回避机器人、站点与已有货物。
  • 曼哈顿与欧氏距离混用：网格移动是曼哈顿几何，塑形与最近目标都必须用它；欧氏会出现"斜对角更近却走不到"的偏差。
  • 发货站设在越界坐标：站必须是合法格子（本实现为 (0,0) 与 (0,9)）。越界站永远到达不了，订单率卡在 0，而日志只显示"塑形分数还不错"。
  • 期望位置就地覆盖 self.pos：冲突判定需要"旧位置快照"，若边算边写，对穿判定会读到半新半旧的坐标。先全部算进 desired、判定完再写回，顺序不能颠倒。

练习与思考

  1. 把常驻货物数从 3 改成 5，先预测学习策略与贪心的吞吐差距会怎么变，再重新训练对比。★
    提示
    任务变多后，贪心的"各自最近"会出现局部冲突与重复指派，学习策略的分配优势开始显现。注意评估用的环境也要同步改参数。
  2. 把被堵惩罚从 −0.02 加到 −0.2，先预测冲突频率与单耗的走向，再观察"礼貌"与"效率"的权衡。★
    提示
    惩罚过重时机器人会绕远路躲避一切潜在冲突，单耗上升；用三个指标的组合判断甜点位置，只看冲突率容易误判。
  3. 去掉观测里的站点相对坐标（11 维变 9 维），先论证策略还能不能定位发货站，再训练验证。★★
    提示
    站点是固定角落，理论上可从绝对坐标推断，但归一化后的自己位置信息不充分。实验后讨论：哪些状态量可以省，哪些必须显式给。
  4. 把双重 DQN 退化成朴素版（目标计算改为 self.q_target(next_obs).max(...)），先预测冲突频率与损失曲线会怎么变，再实跑比较。★★
    提示
    只改一行。看损失噪声变大多少、冲突率是否上升，这是双重 DQN 论文核心论点的迷你复现。
  5. 给环境加"电量"：每步耗 1 格电，电量归零必须去充电站（新增一个），先设计状态与奖励的改动方案，再实现并观察任务分配如何被改变。★★★
    提示
    状态加电量维度（归一化），奖励加低电惩罚，step 里加充电判定。有意思的是观察"电量低的机器人主动让出远单"这类行为，资源约束重塑任务分配。

小结

  • 仓储任务 = 动态任务分配 + 硬约束防撞：常驻货物流提供稳定供给，三层冲突消解保证移动合法。
  • 双重 DQN 通过"在线选动作、目标评价值"抑制过估计，直接收益是策略不再靠硬挤抢路。
  • 共享网络的三个前提在本环境同时满足：观测可统一、角色对称、经验可流通；"携带状态"一维输入切换行为模式。
  • 评估用三个指标（每 1000 步订单、单耗、冲突率）互相校验；只报吞吐量会掩盖协调问题。
