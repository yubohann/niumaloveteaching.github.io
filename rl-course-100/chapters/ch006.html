第一篇 · 策略梯度与 PPO

第 006 章：PPO的神经网络架构设计

宽度、深度、激活函数、初始化，四个结构变量放在 CartPole 上做受控对比：参数量、首达 400 的步数、秒/万步三条数据一起看，回答"网络多大才够用"。

  • 主题：网络结构 / 容量与成本权衡
  • 关键公式：P ≈ Σl(nl−1·nl + nl)；策略头 gain 0.01 正交初始化
  • 预计学时：50 分钟
  • 前置章节：第 005 章

学习目标

  • 理解 Actor-Critic 网络容量（宽度/深度）与样本效率、计算成本之间的权衡。
  • 实现可配置隐藏层与激活函数的网络工厂，并统计参数量与"秒/万步"成本。
  • 对比四种架构：32-32-tanh、64-64-tanh、128-128-128-tanh、64-64-relu，给出选择依据。
  • 理解策略头小增益正交初始化（gain=0.01）为什么能让 PPO 早期更稳。
  • 掌握"先小后大"的架构调参顺序：小网络能通就先降成本，再按需扩容。

背景与动机

前面几章一直用同一个默认网络：两个 64 维 tanh 隐藏层、共享躯干。它够用，但没人告诉你它是不是最优，也许 32 维更快且效果一样，也许更深的网络学得更快，也许 ReLU 在 CartPole 上更合适。这些问题的答案决定了达到同样的回报水平需要付出多少计算成本，差距可达数倍。

这一章把"架构"从背景里拎出来做主变量：隐藏层怎么配、用什么激活、参数怎么初始化。我们同时记录三个维度的指标，参数量（模型复杂度）、首达 400 的步数（样本效率）、秒/万步（计算成本）。很多教程只比较回报，但在实际项目里，"同样的分，用一半时间"往往比"多 5% 的分，用两倍时间"更值钱。本章的实验会给你一个可迁移到后续章节的判断框架。

核心原理

1. 容量、样本复杂度与计算成本

一个 MLP 的参数量大致是：

P ≈ Σl (nl−1 · nl + nl) n0 为观测维度；末尾的 +nl 是偏置；最后一层分别接策略头与价值头

参数越多，函数逼近能力越强，但也意味着：1) 每个 epoch 的矩阵乘更贵；2) 更容易拟合"这一批数据"的噪声，on-policy 数据被丢弃后这种拟合会变成不稳定来源。CartPole 的观测只有 4 维、动力学接近线性，理论上 32×2 就有富余；128×3 的容量对它来说是浪费。反过来，如果换成图像输入或高维连续控制，结论会反过来，所以本章结论要连同任务一起记。

数值例子：三种架构的参数量手算

公式 P = Σ(nl−1·nl + nl) 的来源：一层 Linear(nin, nout) 有 nin·nout 个权重与 nout 个偏置，逐层求和即可。观测维度 4、动作维度 2 时：

32-32-tanh：躯干 (4→32) 得 4×32+32 = 160，(32→32) 得 32×32+32 = 1056；策略头 32×2+2 = 66；价值头 32×1+1 = 33。合计 160+1056+66+33 = 1315。

64-64-tanh：(4→64) 得 320，(64→64) 得 4160，策略头 130，价值头 65。合计 320+4160+130+65 = 4675。

128-128-128-tanh：第一层 640，第二、三层各 128×128+128 = 16512，策略头 258，价值头 129。合计 640+16512+16512+258+129 = 34051，约为 64-64 的 7.3 倍。而 64-64-relu 与 64-64-tanh 的参数量完全相同，都是 4675，两者表现的差异只能归因于激活函数。

解读：7.3 倍的参数量换算到每步计算量上接近线性放大，但实测"秒/万步"通常只高出 50%～80%，原因是环境交互、数据搬运等固定开销摊薄了矩阵乘的占比。这提醒我们：参数量是复杂度的下界指标，真实成本还要看测量。

2. 激活函数的差别在哪里

tanh 的输出有界、在 0 附近近似线性，深层堆叠时梯度较平稳；ReLU 计算便宜、开通区域梯度恒为 1，但负半轴梯度为零、输出无界，在小网络里对初始化更敏感。经验上连续控制任务里 tanh 更常见，部分离散任务 ReLU 也能持平。本章把 64-64 的激活从 tanh 换成 ReLU，其他全部固定，直接量化这个选择。两个注意点：一是两者参数量完全相同，差异只能来自数值性质；二是网络深度增加时 ReLU 的"死神经元"问题会放大，层数越多越需要谨慎选择。

把"梯度较平稳"这句话定量化：当输入近似标准正态分布时，tanh 的导数 1−tanh2x 的期望约为 0.606（对 200 万个样本做蒙特卡洛即可复现，估计误差在千分之一以内）。每穿过一层 tanh，正向信号与反向梯度平均衰减到约 0.61 倍：两层堆叠剩 0.37，三层剩 0.22。ReLU 的导数在正半轴恒为 1、负半轴为 0，若输入零均值对称，约一半神经元导通，等效衰减量级相近，但这是"一次性截断"，没有逐层平滑衰减的过程，且被截断的单元可能永久死亡。这组数字给深度选择的直觉：正向信号与梯度穿过每一层都在按 0.6 量级打折，容量增加与优化难度是同时到来的。CartPole 的观测只有 4 维、动力学近似线性，加深网络换来的表达力很难抵消这一层打折，实验里 128-128-128 不更快是这一规律的自然结果。

3. 正交初始化与策略头小增益

小增益到底把初始 logits 压到多小，可以手算估个量级：正交初始化让策略头每一行的范数等于增益 0.01；躯干最后一层的 64 维输出 h 由 tanh 构成，输入近似零均值时 E[tanh2] ≈ 0.394，于是 ‖h‖ ≈ √(64 × 0.394) ≈ 5.02。logits 的量级约为 0.01 × 5.02 ≈ 0.05，两个动作的概率差约 2.5%，动作分布几乎就是均匀的（熵约 0.6928）。同一笔账用到价值头：增益 1 时初始 V(s) 的量级约 ±5，与 CartPole 早期回报（几十步的存活奖励）同量级；若策略头也用 √2 增益，初始 logits 量级会到约 7.1，softmax 直接进入饱和区，策略"出生即自信"，此时早期比率大面积越界，KL 与裁剪比例都压不住。

PPO 参考实现常用的初始化是正交初始化（orthogonal initialization）：权重矩阵用正交阵初始化并按层增益缩放。关键细节是策略头增益取 0.01：

Wbody ~ Orthogonal(gain = √2)，Wcritic ~ Orthogonal(gain = 1)，Wactor ~ Orthogonal(gain = 0.01)

小增益让初始 logits 接近 0，动作分布接近均匀（熵≈0.693），训练早期不会因为"瞎自信"而产生巨大的比率、触发大面积裁剪。价值头增益保持 1 是为了让 V(s) 的初始尺度能匹配回报量级。它属于一种廉价的稳定性保险；本任务没有它也能训练，它的价值在于压低早期波动，适合配合第 010 章的早停策略一起理解。

部位增益初始输出的作用取值理由
共享躯干√2 ≈ 1.414保持特征幅度在激活前不衰减正交矩阵保范数，√2 补偿 tanh/ReLU 对幅度的小幅压缩
价值头1.0初始 V(s) 与回报量级可比CartPole 回报最高 500，v(s) 起步就在同一量级，价值损失不会异常放大
策略头0.01初始 logits 接近 0，动作分布接近均匀让早期正负优势都有，比率不易越界，KL 与裁剪比例更平稳

4. 共享躯干还是双网络

共享躯干让策略与价值共享特征、省参数，常被小任务采用；双网络（actor/critic 完全独立）避免两个目标的梯度互相干扰，在复杂任务中更常见。CartPole 上两者差别很小，本章保持共享结构，把它留作练习。

5. 四种架构的横向对照

把参数量、效率与成本三个维度整合成一张对照表，方便在选择时直接查用：

架构参数量首达 400 的典型步数秒/万步结论
32-32-tanh13151 万～3 万最低本任务的最小可用配置，性价比最高
64-64-tanh46751 万～3 万低与 32-32 效率持平，默认基线的稳妥选择
128-128-128-tanh340511 万～4 万，未必更快高 50%～80%容量过剩，步数效率不升反降，不推荐
64-64-relu4675约 2 万～4 万与 64-64-tanh 接近可用但略有劣势，差异来自激活函数，与容量无关

读表方法：先看参数量确认容量层级，再看首达步数确认效率，最后用秒/万步确认成本。若某个架构"效率相同但成本更低"，它就是更优选择；"效率更差且成本更高"则直接淘汰，无需再跑多次。

把容量曲线再延伸两档，成本与收益的错位更清楚。按同一公式计算两层躯干：48-48 是 2739、96-96 是 10083、128-128 是 17539（均含两个头部的偏置）。宽度从 32 翻到 128（4 倍），参数量涨约 13.3 倍，接近平方关系，躯干项 n² 占绝对主导。而本章实验显示，这条曲线在 32→64 一段几乎没有换来首达步数的改善。落到选型上：参数量买到的是容量记账，不是性能承诺；在低维任务上，把同样的算力预算投给采样步数与调参，回报通常大过扩大网络。

这张对照表的适用边界也要交代清楚：结论"小网络够用"绑定在 CartPole 的观测维度与近似线性动力学上，换任务必须重新测量。两类任务会让结论反转：观测为图像或原始传感器阵列时，需要卷积或更宽的层做特征提取，32×2 会因容量不足卡住；奖励稀疏、需要长程规划的任务（如迷宫类）对价值函数的拟合精度要求高，略深的价值网络常能换回样本效率。可迁移的经验只有一条：先跑最小可用容量，确认曲线形状正常，再按"缺的是容量还是样本"决定往哪加预算，每次只动一个结构变量。

数据流

每个架构一条完整训练：parse_arch 解析字符串 → 构造网络并统计参数 → 重设种子、采样 2048 步 → GAE 与标准化 → 10 epochs 更新 → 记录首达 400 的步数 → 跑满 6 万步 → 贪婪评估 → 汇总"参数量 / 首达步数 / 近 100 均 / 评估 / KL / 秒 / 秒每万步"。

三个数字，一次完整权衡

参数量：模型复杂度，影响显存与每步计算；首达步数：样本效率，"学得多快"；秒/万步：计算成本，"每步多贵"。三者缺一，结论就不完整，只看参数量会忽视训练动态，只看回报会忽视成本，只看时间会忽视它需要多少步。再补一个第四维度：稳定性。同一架构在两个种子下的首达步数如果相差一倍以上，即便单次成绩漂亮，也不适合作为后续章节的固定基线；本章默认每个架构只跑一个种子做趋势判断，如果要把结论写进报告，至少补跑两个种子核对波动范围。

关键代码与解读

片段 1：架构字符串 → 动态堆叠的网络

def parse_arch(spec: str):
    """把 "128-128-128-tanh" 解析成 ([128,128,128], nn.Tanh)。"""
    parts = spec.split("-")
    act_name = parts[-1].lower()             # 最后一段是激活名
    sizes = [int(x) for x in parts[:-1]]     # 其余段是隐藏层尺寸
    act_cls = {"tanh": nn.Tanh, "relu": nn.ReLU, "elu": nn.ELU}.get(act_name)
    if act_cls is None or len(sizes) == 0:
        raise ValueError(f"无法解析架构: {spec}（示例：64-64-tanh）")
    return sizes, act_cls

class ActorCritic(nn.Module):
    def __init__(self, obs_dim, act_dim, hidden_sizes, act_cls, init="default"):
        super().__init__()
        layers, last = [], obs_dim
        for h in hidden_sizes:                  # 按尺寸列表动态堆叠
            layers += [nn.Linear(last, h), act_cls()]   # Linear + 激活成对出现
            last = h
        self.body = nn.Sequential(*layers)
        self.actor = nn.Linear(last, act_dim)   # 策略头：输出 logits
        self.critic = nn.Linear(last, 1)        # 价值头：共享同一躯干
        if init == "ortho":
            self._orthogonal_init()

解读：（1）parse_arch 把"结构"变成数据：命令行写 --archs 16-16-tanh 256-256-tanh 就能扩展实验，不用改一行网络代码。这类"配置驱动"的小设计是后面迁移学习、多任务章节都会复用的模式。（2）堆叠循环里 Linear + 激活 成对出现：计数时容易把激活层算进参数量，注意 sum(p.numel()) 只统计参数张量，激活不算。（3）策略头与价值头都接在 last 上，同一个躯干输出两路头。想换双网络时，要同时改 forward、act、value 三处（练习 3 会做）。（4）act_cls 用字典查表完成选择，不走 if-else 链：加新激活（比如 ELU）只需在字典里加一项。

片段 2：小增益正交初始化

    def _orthogonal_init(self) -> None:
        """PPO 常用初始化：躯干 gain=√2，价值头 gain=1，策略头 gain=0.01。"""
        for m in self.body:
            if isinstance(m, nn.Linear):
                nn.init.orthogonal_(m.weight, gain=math.sqrt(2.0))
                nn.init.zeros_(m.bias)
        nn.init.orthogonal_(self.critic.weight, gain=1.0)   # 价值尺度匹配回报量级
        nn.init.zeros_(self.critic.bias)
        nn.init.orthogonal_(self.actor.weight, gain=0.01)   # 小增益：初始策略接近均匀
        nn.init.zeros_(self.actor.bias)

解读：（1）躯干 gain=√2 是"ReLU 网络常用值"的正交版本，用于补偿激活压缩带来的幅度衰减；（2）价值头 gain=1 让初始 V(s) 的量级和回报（CartPole 最高 500）可比，价值损失不会一上来就巨大；（3）策略头 gain=0.01 是这段的灵魂：它让初始 logits 接近 0，动作分布接近均匀，相当于让策略从"探索态"出发，远离"随机自信"的起点。这样做早期一批数据里正负优势都有，比率不容易大幅越界，KL 与裁剪比例更平稳。（4）换法会怎样：若策略头也用 √2 增益，早期 logits 偏大、动作分布一开始就偏确定，越界更新反而更多，"初始化更稳"的预期落空，这也是练习 2 要对照验证的。

片段 3：把成本折算成"秒/万步"

    eval_returns = evaluate(gym.make("CartPole-v1"), net, args.eval_episodes, device)
    tail = all_returns[-100:] if len(all_returns) >= 100 else all_returns
    sec = time.time() - t0                              # 墙钟总耗时
    return {
        "spec": spec,
        "params": n_params,                             # 复杂度
        "reached_at": reached_at,                       # 样本效率
        "last100": float(np.mean(tail)),
        "eval": float(np.mean(eval_returns)),
        "mean_kl": float(np.mean(kls)),
        "seconds": sec,
        "seconds_per_10k": sec / (total_steps / 10000.0),  # 成本：折算到每万步
    }

解读：（1）n_params 在 train_one 开头用 sum(p.numel() for p in net.parameters()) 统计，包含偏置；它和 hidden_sizes 一起回答"容量有多大"。（2）seconds_per_10k 是成本归一化：如果拿"总墙钟秒数"直接比较，预算不同就不可比；折算到每万步之后，任何预算下都能横向对照。（3）注意这个折算同时包含环境交互与梯度更新的时间，CartPole 的环境步非常便宜，所以参数量差异主要落在梯度更新上，这正是"大网络在低维任务上不划算"的证据来源。（4）换法会怎样：只报总秒数，你会把"预算大"误读成"模型慢"；只报参数量，你会忽略梯度更新的实际开销差异。成本口径要显式写出来。

              f"{r['eval']:>7.1f} | {r['mean_kl']:>8.4f} | {r['seconds']:>8.1f} | "
              f"{r['seconds_per_10k']:>8.2f}")

解读：（1）表格把参数量、首达步数、秒/万步放在同一行，读表时三者并排看，才能得出"32-32 够用且便宜""128×3 多花 60% 时间却没变快"这类结论。（2）'秒/万步'列是跨预算可比的成本指标，'用时'列是本次实验的实际读数，两者分工不同。（3）'未达到'分支和前面章节一致：短预算下有的架构可能到不了 400，如实打印比 None 好。（4）结果同时写入 runs/ch006/arch_compare_default.txt（ortho 模式写另一个文件），文件名带初始化方式，避免两次实验互相覆盖。

完整可运行脚本（附录）：code/ch006.py

python code/ch006.py                     # 4 种架构各 6 万步，CPU 约 3–6 分钟
python code/ch006.py --quick             # 3 种架构各 8000 步，约 30–60 秒

预期结论（以实跑为准）：四种架构都能在 3 万步内越过 400，说明 CartPole 不需要大容量；32-32 与 64-64 的步数效率基本持平，但 32-32 每万步更便宜；128-128-128 参数量约是 64-64 的 7 倍（约 3.4 万 vs 4700），步数效率不升反略降，秒/万步高 50%～80%；ReLU 版本通常可用但略慢、评估回报略低。--init ortho 后早期 KL 与裁剪比例一般更低更平。

常见坑

  • 把"大网络更聪明"当默认前提：参数量与样本效率不是单调关系。低维任务上，超额容量会拟合批次噪声；判断标准永远是"同预算下的步数效率 + 计算成本"；参数越多越好的直觉在这里不成立。
  • 比较时忘了控制变量：结构对比必须固定随机种子、采样批量、epoch、学习率。本章在 train_one 里重设种子并让其他参数走同一份 args，这是公平比较的最低要求。
  • 正交初始化只换躯干、忘了策略头增益：如果策略头也用 √2 增益，初始 logits 偏大、动作分布一开始就偏确定，早期 KL 与裁剪比例反而更高，"更稳"的预期落空。三个增益的作用要分开记。
  • 用墙钟时间直接比较不同架构的"学习速度"：秒/万步是成本指标，首达步数是效率指标，二者不能相互替代。一个网络可能每步便宜但需要两倍步数，另一个相反，结论要写清在哪种口径下成立。
  • 忘记录参数量就下结论：只写"64-64-relu 比 tanh 慢一点"没有意义；把参数量（4675 = 4675，相同）与首达步数、KL 一起报出来，才能说明差异来自激活函数，与容量无关。

练习与思考

  1. 把 32-32 换成 16-16 再跑一次，看看"更小"在哪里开始拖慢学习。★
    提示
    直接改 --archs。关注首达 400 的步数是否突破 3 万，以及评估回报是否还能到 450+；如果 16-16 也能达标，说明 CartPole 的容量下限比想象低。
  2. 运行 --init ortho，与默认初始化对比第一轮更新的 KL 与裁剪比例。★
    提示
    策略头 gain=0.01 使初始动作分布接近均匀，早期 KL 通常更低（0.005 上下），裁剪比例也更小。对比日志前两行即可。
  3. 实现"双网络"版本：actor 与 critic 各自独立的 MLP，不用共享躯干；对比参数量与学习曲线的形态。★★
    提示
    把 ActorCritic 的 body 拆成两份，forward 分别调用。注意 act() 与 value() 都要改；参数量会翻倍，观察 KL 波动是否变小。
  4. 给躯干加一层 nn.LayerNorm（在每层 Linear 之后、激活之前），在 64-64-tanh 上对比训练稳定性。★★★
    提示
    在 parse_arch 返回的结构里插入 LayerNorm，或直接在 ActorCritic.__init__ 的循环里加。LayerNorm 让特征尺度不受批内统计影响，关注 KL 波动与评估回报方差。
  5. 按公式手算 16-16-tanh 的参数量（提示：别忘了两个头部的偏置），再用脚本打印的实际值核对，两者一致说明你对参数统计的理解正确。★
    提示
    躯干 4×16+16=80、16×16+16=272；策略头 16×2+2=34；价值头 16×1+1=17。合计 403。若与脚本输出不同，先检查是否把激活层或环境参数算进去了。

小结

  • CartPole 这类低维任务上，32×2 到 64×2 的 MLP 已经够用；容量过剩只增加成本，步数效率不变甚至变差。
  • 激活函数是次要但真实的选择：本任务里 tanh 略优于 ReLU；大网络需要配套的初始化与归一化才值得上。
  • 正交初始化 + 策略头 0.01 增益能让初始策略接近均匀，降低早期越界更新，是低成本的稳定性保险。
  • 架构决策要同时报告参数量、首达步数、秒/万步三个量；只报回报的对比不完整。
  • 下一章开始处理"输入尺度"问题：奖励的尺度在不同任务间差异巨大，先看朴素 PPO 在奖励量级剧烈变化时会发生什么，再实现奖励归一化修复它。
