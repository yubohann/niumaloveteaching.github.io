第二篇 · 离策略方法与 SAC

第 062 章：SAC的在线与离线对比

用同一份 SAC 代码做控制变量实验：一边与环境交互一边训练，还是先冻结一份数据集再反复学习？在 Pendulum 上你会看到离线训练的上限被行为策略锁死，以及 Q 值如何悄悄虚高。

  • 主题：离线强化学习 / 分布偏移诊断
  • 关键公式：y = r + γ(1−d)·[miniQθ̄,i(s′,a′) − α·log π(a′|s′)]
  • 预计学时：50 分钟
  • 前置章节：第 061 章

学习目标

  • 理解在线强化学习与离线强化学习（offline RL）在数据来源上的根本区别，以及 SAC 为什么看上去"天然适合"改造成离线算法。
  • 掌握分布偏移（distribution shift）导致 Q 值过估计的机制，能推导外推误差被 Bellman 备份反复放大的过程。
  • 看懂一份同时支持 online / offline 两种模式的 SAC 实现：网络、学习率、批大小、梯度更新次数怎么对齐。
  • 在 Pendulum-v1 上跑出两条对照曲线，解释离线训练为什么停在行为策略附近。
  • 掌握"平均 Q 估计 vs 真实评估回报"这个过估计诊断量，以及固定探测批次、确定性评估两条评估纪律。

背景与动机

在线强化学习假设你可以随时与真实系统交互：机器人摔倒了重来，游戏输了重开。但医疗、金融、工业控制里试错代价极高，很多场景只留给你一份历史日志，这正是离线强化学习（offline RL）的用武之地。本章要回答的问题很具体：把一个训练好的在线 SAC 直接换成"只读日志"，它还能学吗？

SAC 是 off-policy 算法，经验回放池让它看上去天生适合离线：把历史数据灌进池子，反复采样更新不就行了？问题出在它的 Bellman 备份里，下一状态的动作由当前策略生成，与产生数据的行为策略无关。当数据分布没有覆盖当前策略偏爱的动作时，Q 网络对这些动作的估值只能靠外推（extrapolation），通常虚高；策略又被训练去追这些虚高的 Q，于是越走越偏。

本章用控制变量法把这个差距变成你日志里的两行数字：除数据来源外，两种模式的网络、优化器、批大小、梯度步数全部相同。它向上承接第 061 章的离线流程，也为第三篇 PPO × SAC 对比做铺垫，你会更清楚不同算法的数据假设意味着什么。

核心原理

1. 两种模式唯一的不同：数据从哪来

在线模式的数据流是"策略 → 环境 → 缓冲池 → 更新 → 新策略"，数据分布跟着策略持续刷新；离线模式的数据流是"行为策略 β 与环境交互一次 → 数据集冻结 → 反复梯度更新"，训练期间数据分布不再变化。除数据来源外的一切都相同，两条曲线的差异才可以归因到数据本身。

2. SAC 的备份目标与外推误差

SAC 更新 Q 时，目标值对当前策略 π 在下一状态上的动作取期望：

y = r + γ(1 − d) · [ mini=1,2 Qθ̄,i(s′, a′) − α · log π(a′|s′) ],  a′ ∼ π(·|s′) r 是即时奖励；γ 是折扣因子；d 是终止标志（终止则未来项归零）；Qθ̄,i 是第 i 个目标网络输出；α 是温度系数；log π(a′|s′) 是策略对 a′ 的对数概率

把离线数据集想象成 (s, a, r, s′) 的一个窄分布：里面只可能出现行为策略 β 走过的轨迹。而目标里的 a′ 是从 π 里采样的，训练早期 π 尚可，几轮更新后就可能与 β 明显分叉。对数据从未覆盖的 (s′, a′)，Q 网络给出的值没有任何监督信号约束，只能外推；这个错误估值又通过 Bellman 备份进入上一状态的目标，误差沿着时间轴和状态轴反复自我放大。

𝔼[Qθ(s′, a′)] ≫ Vπ(s′) 的可能：a′ 越远离数据分布，虚高越严重

在线模式里这个问题被自动修补：策略一旦挪向某片区域，环境立刻产生那里的数据，Q 的猜测马上被真实回报纠正。离线模式没有这个反馈回路，于是出现两个典型症状，Q 估计持续升高，而真实评估回报停滞甚至下降。本章把这两个量并排打印，你会在日志里看到它们越拉越开。

3. 行为策略的质量决定离线上限

如果行为策略是均匀随机的，数据集里几乎没有连贯控制的数据，任何方法都学不出好策略。本章的 β 混合两种成分：55% 的粗能量泵浦启发式（能把摆从下垂摆到接近直立、并做部分平衡）与 45% 的均匀随机力矩。它模拟现实中最常见的"中等质量日志"：包含有用行为，但远达不到最优。离线 SAC 的期望上限就是这份日志里"可被模仿到的水平"，大约 −700 ~ −400，而在线 SAC 能到 −250 ~ −150。

4. 诊断量：真实回报减去平均 Q

过估计是看不见的，除非你构造一个固定的对照。本章在每个评估点做两件事：用确定性（均值）策略跑若干回合得到真实回报；在数据集上固定一批探测样本（probe），计算平均 min(Q1, Q2) 作为平均 Q 估计。两者相减（真实回报 − 平均 Q）越负，说明 Q 越虚高。在线模式这个差值通常是几十到一百多；离线模式往往达到几百，那就是分布偏移在数值上的形状。

实现思路与设计

模块划分

组件职责关键点
ReplayBuffer固定容量环形缓冲，存 numpy 数组在线模式持续写入；离线模式一次性写满后冻结
GaussianPolicy对角高斯 + tanh 压缩策略sample() 用于训练，mean_action() 用于评估

关键超参数

数据流

在线：每一步先选动作（前 start_steps 步用行为策略预热，之后用当前策略采样）→ 写池 → 从池中采一个 batch 做一次梯度更新 → 每 2500 次更新评估一次。离线：阶段一用行为策略把池子填到 dataset_size；阶段二进入纯更新循环，循环体内没有任何 env.step，只有评估用的 eval_env 会被调用，而评估不产生训练数据。

与第 061 章的差异点

① 用 --mode 开关复用同一套网络与更新代码，数据来源是唯一变量；② 梯度更新次数对齐，"各跑一段凭感觉比"得不到可比结果；③ 新增固定探测批次上的平均 Q 诊断，把过估计从猜测变成数字；④ 行为策略的混合比例可调，方便做数据集质量实验。

关键代码与解读

片段 1：SAC 更新的四步顺序

def update(self, batch):
    """一次完整更新：批评家 -> 演员 -> 温度 -> 软更新目标网络。"""
    obs, act = batch["obs"], batch["act"]
    rew, next_obs, done = batch["rew"], batch["next_obs"], batch["done"]

    # 1) 双 Q 的 Bellman 回归；下一动作与熵项都由当前策略给出
    with torch.no_grad():                                    # 目标值不参与梯度
        next_act, next_logp = self.policy.sample(next_obs)   # a' 由当前策略生成（离线风险的源头）
        q1_t, q2_t = self.q_target(next_obs, next_act)       # 目标网络提供稳定估值
        target = rew + self.gamma * (1.0 - done) * (
            torch.min(q1_t, q2_t) - self.alpha * next_logp)  # 双 Q 取小 + 熵项修正
    q1, q2 = self.q(obs, act)                                # 两份预测回归同一目标
    q_loss = F.mse_loss(q1, target) + F.mse_loss(q2, target)
    self.q_opt.zero_grad()
    q_loss.backward()
    self.q_opt.step()

    # 2) 策略：最大化 Q 减熵，重参数化梯度穿过采样
    new_act, logp = self.policy.sample(obs)                  # rsample 保证梯度可回传
    q1_n, q2_n = self.q(obs, new_act)                        # 用"刚更新过"的在线 Q 评价新动作
    policy_loss = (self.alpha.detach() * logp - torch.min(q1_n, q2_n)).mean()
    self.policy_opt.zero_grad()
    policy_loss.backward()
    self.policy_opt.step()

    # 3) 自动温度：把平均熵拉向目标熵
    alpha_loss = -(self.log_alpha * (logp.detach() + self.target_entropy)).mean()
    self.alpha_opt.zero_grad()
    alpha_loss.backward()
    self.alpha_opt.step()

    # 4) 软更新目标网络
    with torch.no_grad():
        for p, p_t in zip(self.q.parameters(), self.q_target.parameters()):
            p_t.data.mul_(1.0 - self.tau).add_(self.tau * p.data)

解读：顺序是"批评家 → 演员 → 温度 → 软更新"，每一步都依赖上一步刚算出的量。（1）目标里的 next_act 来自当前策略，在线模式这是优点（策略改进的方向与数据同步），离线模式这是病灶：策略一旦漂出数据覆盖区，目标值就变成网络的自洽猜测。（2）torch.min(q1_t, q2_t) 是悲观估计，双 Q 取小能压住一部分虚高，但压不住系统性外推。（3）演员损失里 alpha.detach() 让温度不接收策略梯度；温度损失里 logp.detach() 让策略不接收温度梯度，两边的 detach 互相隔离，避免两个损失互相拉扯。（4）软更新放在最后，目标网络总是用"本轮最新"的批评家参数做插值。

片段 2：固定行为策略 πβ

def behavior_action(obs, rng) -> np.ndarray:
    """固定行为策略 pi_beta：55% 粗能量泵浦启发式，45% 均匀随机力矩。"""
    cos_t, sin_t, thdot = float(obs[0]), float(obs[1]), float(obs[2])
    if rng.random() < 0.55:
        # 摆动阶段满力泵浦；能量够了就滑行等 PD 捕捉直立
        energy = 0.5 * thdot * thdot + 15.0 * cos_t   # 系数 15 与 3g/2 项对应
        if cos_t < 0.9:
            u = 2.0 * (1.0 if thdot >= 0 else -1.0) if energy < 15.0 else 0.0
        else:
            u = -6.0 * sin_t - 1.5 * thdot   # PD 平衡：增益 6 高于静态所需的 5
        u += rng.normal(0.0, 0.5)          # 叠加小噪声，模拟人类的"手抖"
    else:
        u = rng.uniform(-2.0, 2.0)          # 随机探索项：保证数据覆盖一部分状态空间
    return np.array([np.clip(u, -2.0, 2.0)], dtype=np.float32)

解读：这份 β 的设计目标是真实且可控，不刻意追求"好"。启发式部分满力泵浦、能量接近上限（E=15）后交给 PD 稳住近似直立的姿态，说明数据里存在"接近最优"的片段（离线上限因此高于纯随机）；PD 比例增益取 6 略高于静态平衡所需的 5，泵浦以能量 15 为停止线，避免过冲后高速掠过顶端。随机部分保证状态覆盖不至于太窄。为什么不用纯随机？纯随机的数据集在任何方法下都学不出好控制，实验会退化成"大家都学不会"，失去对比意义。改 0.55 这个比例就是改数据集质量，练习里会让你做这个实验。

片段 3：离线训练的两个阶段

# 阶段一：用行为策略收集固定数据集（此后数据分布冻结）
buffer = ReplayBuffer(args.dataset_size, obs_dim, act_dim)
while buffer.size < args.dataset_size:
    action = behavior_action(obs, np.random)     # 与在线预热同源，保证可比
    next_obs, reward, terminated, truncated, _ = env.step(action)
    done = terminated or truncated               # 截断也切断自举，与在线处理一致
    buffer.add(obs, action, (reward,), next_obs, (float(done),))
    obs = next_obs
    if done:
        obs, _ = env.reset()

# 阶段二：只做梯度更新，循环体内没有任何 env.step
for grad_steps in range(1, args.grad_steps + 1):
    stats = agent.update(buffer.sample(args.batch_size, device))
    if grad_steps % args.eval_every == 0:
        ret = evaluate(eval_env, agent, args.eval_episodes, device)
        q_mean = probe_q(agent, buffer, probe_idx, device)
        curve.append((grad_steps, ret, q_mean))  # 同一横轴：梯度更新次数

解读：阶段一是唯一的"数据生产"环节，用与在线预热完全相同的行为策略，保证两种模式看到的数据同源可比；阶段二彻底断开环境，没有 env.step，也就绝无"偷偷补数据"的可能。横轴用"梯度更新次数"：离线模式的环境步数固定在数据集大小上，秒数又受机器与调度影响，只有梯度更新次数能反映真实计算预算。评估调用的 eval_env 只计算回报、不写回放池、不产生梯度，这是离线协议的一部分。

片段 4：固定探测批次与过估计诊断

def make_probe_idx(buffer: ReplayBuffer, n: int, seed: int) -> np.ndarray:
    """在数据集上固定一批探测样本，用于追踪 Q 估计的漂移。"""
    rng = np.random.RandomState(seed)
    return rng.randint(0, buffer.size, size=n)   # 只采一次，之后诊断复用同一批索引

@torch.no_grad()
def probe_q(agent, buffer: ReplayBuffer, idx: np.ndarray, device) -> float:
    """计算固定探测批次上的平均 min(Q1, Q2)。"""
    obs = torch.as_tensor(buffer.obs[idx], device=device)
    act = torch.as_tensor(buffer.act[idx], device=device)
    q1, q2 = agent.q(obs, act)
    return float(torch.min(q1, q2).mean().item())

解读：诊断的意义在于"同一批数据上的估计漂移"。make_probe_idx 在数据集建好后只随机一次，之后每次评估都复用这批索引：Q 均值的变化里不再混入"样本不同"的噪声，曲线呈现的就是网络估值的真实漂移。如果每轮重新随机采样，即便网络毫无变化，Q 均值也会上下跳，趋势就看不出来了。这也是评估协议里最容易被忽略的一条纪律。

常见坑

  • 把评估交互算成训练交互：离线模式里 eval_env.step 被调用了，但它只产生回报数字、不写回放池、无梯度进入网络。如果你顺手把评估数据也 buffer.add 进去，离线就"偷看"了环境，结论全毁。
  • 探测批次每轮重新采样：Q 诊断的意义是"同一批数据上的估计漂移"。用随机索引会让 Q 均值曲线混入采样噪声，看不出过估计趋势，先固定 probe_idx，再谈观察。
  • 忘记 done 掩码：Pendulum 有 200 步时间截断，terminated 恒为 False 但 truncated 会触发。写 1 − done 时必须用 terminated or truncated，否则自举会把跨回合的价值错误地连接起来。
  • 两种模式预算不对齐：只比"跑了多少秒"或"看了多少步"都不公平，本章对齐的是梯度更新次数，因为计算量由它决定。改动 --grad-steps 时若与在线更新数不一致，对照实验就不成立。
  • 期望离线曲线超过在线上限：离线 SAC 的性能天花板由数据集质量决定：β 没做过的连贯控制，π 几乎不可能仅靠外推学会。看到离线卡住先检查数据集覆盖，加长训练解决不了这个问题。

  4. 把温度改为固定值（令 --alpha 0.05 且跳过第 3 步更新），比较在线与离线在新设定下的差距指标。哪一种模式对温度更敏感？★★
    提示
    把 self.log_alpha.requires_grad 设为 False 并注释掉温度更新即可。离线模式下小温度会加速策略外推，Q 差距通常更大。
  5. 给离线模式加一个最小"保守性"措施：采样一批随机动作 a_rand，在 Q 损失里加上 lambda * q(obs, a_rand).mean()（系数从 0.1 试起），逼低数据外区域的 Q 值。讨论它与 CQL（Conservative Q-Learning）的异同。★★★
    提示
    CQL 的核心思想正是在数据分布外压低 Q、在数据分布内抬高 Q；你的最小实现只做了"压低"这一半，因此对系数更敏感，系数太大可能压塌有用估值。

小结

  • 在线与离线的唯一变量是数据来源：一个持续刷新、一个冻结不动；网络、优化器与梯度预算全部对齐才能公平比较。
  • SAC 的 Bellman 目标用当前策略选下一动作，数据没覆盖的区域只能外推，误差经 Bellman 备份反复放大，这是离线训练失效的根本原因。
  • 诊断过估计最直接的量是"真实评估回报 − 平均 Q 估计"的差距，用固定探测批次追踪它的漂移。
  • 行为策略质量决定离线上限：本章的中等质量数据集把离线 SAC 锁在约 −700 ~ −400，在线 SAC 可到 −250 ~ −150。
  • 评估交互不产生训练数据、探测索引只采一次、梯度步数对齐，三条纪律缺一不可。
