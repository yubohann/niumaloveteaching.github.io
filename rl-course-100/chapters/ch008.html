第一篇 · 策略梯度与 PPO

第 008 章：PPO的观测归一化与向量化环境

在 MountainCar-v0 上同时验证两个工程手段：用在线均值/标准差把尺度差 17 倍的两维观测拉齐，用单进程 4 环境轮转把数据打散，对比 single / vec / vecnorm 三组的样本效率与墙钟时间。

  • 主题：输入尺度 / 向量化采样
  • 关键公式：x̃ = clip((x − μ̂)/(σ̂+1e-8), −10, 10)；逐维 Welford 更新
  • 预计学时：60 分钟
  • 前置章节：第 007 章

学习目标

  • 理解观测各维尺度不一致为什么伤害神经网络：输入信号被淹没、权重梯度失衡。
  • 实现逐维在线归一化（Welford）：用训练过程中收集的统计量标准化观测，评估时冻结使用。
  • 实现单进程向量化采样：n 个环境轮转、一次批量前向、每个环境独立计算 GAE 与 bootstrap。
  • 在 MountainCar-v0 上对比 single / vec / vecnorm 三组的样本效率、最佳 100 回合均值与耗时。
  • 认识向量化采样的两个收益：数据相关性下降、为第 024 章的并行采样打基础。

背景与动机

MountainCar 的观测是 [位置, 速度]：位置范围约 1.8，速度范围约 0.14，尺度相差约 17 倍。直接喂给 MLP，第一层权重的更新会被位置维度主导，速度维度的信息被稀释，而速度恰恰是判断"该不该继续往山上冲"的关键。这不是算法问题，是输入尺度问题，工程师用一行 (x−μ)/σ 就能解决，前提是你知道统计量从哪来：训练中在线收集。

第二个问题是数据相关性。on-policy 方法对同一策略的顺序轨迹做更新，同一条轨迹里的样本高度相关，梯度估计的方差偏大。解法是并行跑 n 个环境，一步轮转各自采样再拼成一批。真正的工程实现用多进程；本章用单进程循环模拟同样的数据分布（教学简化），把接口与统计逻辑写对，第 024 章再换成并发版本。

核心原理

1. 输入尺度为什么重要

MLP 第一层的输出是 Σ wixi + b。若某一维 xi 的量级只有另一维的 1/17，在初始权重同分布的前提下，它对隐藏层激活的贡献也只有 1/17，梯度同样小 17 倍。把两个口径都写出来：按极值比，位置维端点约 1.2、速度维约 0.07，比值约 17；按取值范围比，1.8 对 0.14 约 13 倍。两个口径指向同一量级，第一层对速度维的敏感度只有位置维的十几分之一。学习率是一个全局常数，网络就只能在"位置维合适"和"速度维合适"之间二选一。逐维标准化让各维都落到均值 0、方差 1：

x̃ = clip( (x − μ̂) / (σ̂ + 1e-8), −10, 10 ) μ̂、σ̂ 为训练过程中在线统计的逐维均值与标准差；裁剪防止离群观测导致爆炸

2. Welford 在线统计

不能先把所有数据存下来再统计，PPO 是流式的。Welford 算法用常数内存维护均值与平方和，逐维更新：

n ← n + m，　μ̂′ ← μ̂ + (x̄batch − μ̂)·m / n，　M2 ← M2 + Σ (x − μ̂)(x − μ̂′)，　σ̂ = √(M2/(n−1)) m 为本次批量观测个数；μ̂、μ̂′ 为更新前后的均值；数值稳定性优于"累加再相减"的朴素写法

两个实现要点：统计只对原始观测做一次（不要把归一化后的观测再喂回统计，否则方差会自我压缩）；评估时冻结统计量，否则贪婪评估也会"在线漂移"，成绩无法比较。

数值算例：两维观测的三步 Welford 更新

用 MountainCar 量级的两个观测手算一遍（位置 ∈ [−1.2, 0.6]、速度 ∈ [−0.07, 0.07]）：第一批是 x₁=(0.60, 0.07) 与 x₂=(−1.20, −0.07)，初始 mean=(0,0)、m2=(0,0)、n=0。

批量均值 x̄=(−0.30, 0)；n 更新为 2；delta = x̄ − mean = (−0.30, 0)；mean += delta×2/2，得到 (−0.30, 0)；m2 += Σ(x−mean)²：位置维 (0.60+0.30)²+(−1.20+0.30)² = 0.81+0.81 = 1.62，速度维 0.07²+0.07² = 0.0098。标准差是 √(m2/1) = (1.273, 0.0990)。归一化后 x₁ 变成 (0.707, 0.707)，x₂ 变成 (−0.707, −0.707)：位置维从 ±1.2 量级压到 ±0.71，速度维从 ±0.07 拉到 ±0.71，两维进入同一尺度。

再来第三个观测 x₃=(0.40, 0.035)：delta=(0.70, 0.035)，mean 更新为 (−0.0667, 0.0117)，m2 更新为 (1.9467, 0.01062)，标准差变为 (0.987, 0.0729)，x₃ 归一化后是 (0.473, 0.320)。解读：三个样本之后均值还在从 0 明显移动，早期网络看到的输入是"逐步归位"的序列。这也是为什么要求"先统计、后归一化"且本批观测必须计入统计：如果顺序反过来（先归一化再统计），方差会向 1 自我压缩，后期观测的细微结构被抹掉；如果早期数据不计入统计，统计量永远追不上真实分布。

归一化的适用边界同样要看清。它的隐含假设是"观测分布相对稳定"，一旦策略变化导致状态分布漂移（本就常见），历史统计量表示的是"过去策略走过的状态"，新策略访问的状态会被用旧尺子度量；在 on-policy 训练里这种漂移是渐进的，影响有限，但换到 SAC 这类回放缓冲区混入大量旧数据的场景，统计口径不匹配的问题会放大，第 039 章会专门处理。另一个边界是"冻结统计量做评估"：如果训练后期分布已经明显移动，用最初统计量评估会低估输入范围，评估环境与部署环境的一致性需要单独验证。可靠的检查方法是记录统计量的漂移轨迹：每 1 万步把 mean/std 各维打印一次，若某维均值还在单调移动，说明训练尚未进入稳态，此时的评估成绩都只能当参考。

3. 向量化采样：一次前向，n 条轨迹

n 个环境的轮转循环如下：每一步把 n 个当前观测堆成 (n, obs_dim) 张量，一次前向得到 n 组动作/logp/价值；依次执行 env[i].step，谁结束就单独 reset。一个采样周期产出 n 条转移，steps_per_env 个周期后得到 n × steps_per_env 的批次。

关键在 bootstrap 与 GAE 必须按环境分段：环境 i 的最后一步之后要用它自己的 sT 估值，不能用别的环境的价值；终止掩码也按环境各自维护。把 n 条轨迹首尾相连当成一条算 GAE，优势会在环境边界处串台。

4. 向量化带来的两个收益

其一是数据相关性下降：同一时刻的 n 个状态来自不同轨迹，批次内的经验分布更接近"策略的状态访问分布"，梯度方差更小。其二是吞吐：n 个环境的动作由一次批量矩阵乘算出；当 n 继续增大并配合多进程时，环境交互与网络计算可以重叠。单进程版在这里的加速有限，主要是数据分布的收益。

相关性下降的收益可以粗略量化。假设某任务上相隔 1 步的观测相关系数约 0.99、自相关衰减到 0.5 需要约 70 步（保守的示例参数），那么一条 512 步的连续序列折算下来只有 512/70 ≈ 7 个"独立样本"；4 环境轮转后，同一批 512 步来自四条并行轨迹，批内相邻样本的相关性立刻接近 0，有效独立样本数上到几十的量级。这就是"批次梯度方差下降"的直接来源，也是第 024 章并行采样继续提升吞吐的前提。注意轮转只削弱了样本之间的相关性，GAE 的递归仍按各环境自己的序列进行，两份机制互不替代。

把"串台"的代价算个量级，就知道分环境 GAE 为什么不能妥协：假设环境 A 的末尾观测估值 V(sT)=50，而相邻拼接位置误用了环境 B 的开局估值 −100，错误拼接会让 A 的末段样本拿到 −100 做 bootstrap，单步残差 δ 的误差约 γ×(50−(−100)) ≈ 148。这个误差经 GAE 向前传播，A 段靠后的十几个样本优势被污染上百点，而正常优势的尺度只有个位数到十几；一个边界错误足以让整批梯度的方向由少数被污染的样本主导。修复方式只有一种：每个环境的转移段独立调用 compute_gae，用各自的末观测估值收尾。

环境数 n 的选择也有一条定量边界：n 越大批内相关性越低，但每环境步数 = 2048/n 越短；一旦短于典型回合长度，每个环境段的尾部都要靠 bootstrap 收尾，优势估计的偏差项占比上升。本任务取 n=4（每环境 512 步），让每个轨迹段至少覆盖两个以上终止事件；练习 1 的 n=8（每环境 256 步）就是逼近这条边界的实验，若观察到 GAE 语义下标准差上升、最佳 100 均值波动变大，说明已经越过合理区间。

数据流

每个变体一条完整训练：按 VARIANT_SPECS 决定环境数 n 与是否归一化 → 每个采样周期：堆 n 环境观测 → （可选）更新统计量并归一化 → 批量前向采样 → 逐环境 step 并记录 → 每个环境单独算 GAE 与 bootstrap → 拼接成一批 → 8 epochs × minibatch=64 更新 → 记录最佳 100 回合均值 → 跑满 25 万步 → 用冻结统计量做贪婪评估。

为什么用一个 "single 是 n=1 特例" 的实现

VARIANT_SPECS 只定义（环境数，是否归一化）两个字段：single 就是 n=1 的向量化代码，不需要单独的采样函数。这样做的好处是对比严格受控，三组走同一条代码路径，差异只来自配置，排除实现不同带来的噪声；加"8 环境"也只改一行配置。你在自己项目里也应该把"是否向量化"做成开关；维护两份代码会让对比失去意义。

关键代码与解读

片段 1：逐维 Welford 统计与归一化

class RunningStats:
    """对多元素张量做逐维 Welford 在线统计。"""
    def __init__(self, dim: int, clip: float = 10.0):
        self.dim = dim
        self.n = 0.0
        self.mean = np.zeros(dim, dtype=np.float64)   # 逐维均值
        self.m2 = np.zeros(dim, dtype=np.float64)     # 逐维二阶中心矩
        self.clip = clip

    def update(self, x):
        x = np.asarray(x, dtype=np.float64).reshape(-1, self.dim)
        if x.shape[0] == 0:
            return                                    # 空批次直接跳过
        m = x.shape[0]
        delta = x.mean(axis=0) - self.mean            # 批量均值与当前均值的差
        self.n += m
        mean_new = self.mean + delta * m / self.n     # 按样本数加权地移动均值
        # Welford 合并式：每个样本对“旧均值”“新均值”各差一次再相乘
        self.m2 += ((x - self.mean) * (x - mean_new)).sum(axis=0)
        self.mean = mean_new

    def normalize(self, x):
        # 逐维仿射变换 + 裁剪：±10 是防离群观测的保险丝
        return np.clip((x - self.mean) / (self.std + 1e-8), -self.clip, self.clip)

解读：（1）与第 007 章的标量版不同，这里 mean/m2 都是长度 dim 的数组：位置与速度分开统计，各归各的尺度。（2）update 接收的是"批量观测"（一次 n 个），单个样本只是它的特例：均值按 m/n 加权移动，M₂ 的增量则对"旧均值"与"新均值"各差一次再相乘累加，这正是 Welford 合并式的向量化版本，数值上比"先存所有数据再算"稳定（两个均值一新一旧，写反是流式统计最常见的抄写错误）。（3）normalize 里 1e-8 防止除零、clip 防止偶发离群把输入推到 ±50 这类不可控区间。MountainCar 的正常范围不超过 ±3，所以裁剪在正常训练里几乎不触发（练习 2 会验证）。（4）注意 std 属性在 n < 2 时返回全 1，与标量版一致：统计量没准备好之前，归一化等价于"只减均值"，不会引入噪声。

再补两个口径上的细节。其一，Welford 的 mean/m2 用 float64 累加，进网络前才转 float32：统计量要跨整个训练累计，float32 的十进制有效位数约 7 位，累计到百万级步数时，和值 106 量级的绝对精度只剩约 0.1，小于此的增量会被静默丢弃；float64 把同样的误差压到 1e-10 量级，代价只是几 KB 内存。其二，拼接 batch 前后值得加三行断言：4 环境 × 512 步 = 2048 条转移，all_obs 的长度与 np.concatenate(all_adv) 的长度都必须等于 2048，且前 512 条应全部来自环境 0。形状对得上但配对错位的问题不会抛异常，只在训练曲线上表现为莫名退化，断言能在源头拦住。

片段 2：批量动作采样，一次前向服务 n 个环境

    @torch.no_grad()
    def act_batch(self, obs: torch.Tensor):
        """对形状 (n, obs_dim) 的批量观测采样，返回 numpy 数组（动作, logp, 价值）。"""
        logits, values = self.forward(obs)        # 一次矩阵乘：n 个环境共享
        dist = Categorical(logits=logits)
        actions = dist.sample()
        return (actions.cpu().numpy(),            # 转 numpy：循环里逐个 env.step 用
                dist.log_prob(actions).cpu().numpy(),
                values.cpu().numpy())

    @torch.no_grad()
    def act(self, obs: torch.Tensor):
        a, logp, v = self.act_batch(obs)          # 单环境是 n=1 的特例
        return int(a[0]), float(logp[0]), float(v[0])

解读：（1）接口升级的要点是形状：obs 从 (1, obs_dim) 变成 (n, obs_dim)，前向、采样、返回全部保持批量维度。Categorical 对批量 logits 天然支持逐行采样，不需要循环。（2）返回 numpy 数组，不返回张量：主循环里要给 env.step() 传单个整数动作，numpy 标量转换最省事，也避免在循环里碰计算图。（3）act() 复用 act_batch() 后取第 0 个元素，单环境路径仍然走同一段代码，保证两条路径行为完全一致（这也是"single 是 n=1 特例"的实现基础）。（4）换种写法：如果对每个环境单独调用 act()，n 次前向的矩阵乘 size 很小，Python 开销占比上升；批量前向在 n=4 时差距不大，n 增大后越来越明显。

片段 3：向量化轮转与逐环境记录

    for _ in range(steps_per_env):
        raw = np.stack(obs_raw).astype(np.float32)          # (n, obs_dim)
        if stats is not None:
            stats.update(raw)                                # 只统计原始观测
            net_in = stats.normalize(raw).astype(np.float32)
        else:
            net_in = raw
        obs_t = torch.as_tensor(net_in, dtype=torch.float32, device=device)
        acts, logps, vals = net.act_batch(obs_t)             # 一次前向服务 n 个环境

        for i in range(n):
            next_raw, r, terminated, truncated, _ = envs[i].step(int(acts[i]))
            obs_bufs[i].append(net_in[i])                    # 存网络输入（已归一化）
            act_bufs[i].append(int(acts[i]))
            logp_bufs[i].append(float(logps[i]))
            rew_bufs[i].append(float(r))
            val_bufs[i].append(float(vals[i]))
            term_bufs[i].append(float(terminated))           # 只记真终止

            ep_ret[i] += r
            obs_raw[i] = next_raw
            if terminated or truncated:
                ep_returns.append(ep_ret[i])                 # 回合计分不区分终止/截断
                ep_ret[i] = 0.0
                reset_obs, _ = envs[i].reset()
                obs_raw[i] = reset_obs

解读：（1）顺序是关键：先 stats.update(raw) 再 normalize，统计只吃原始观测，且本次观测先被统计再被使用，口径一致；如果反过来先归一化再统计，方差会自我压缩到 1。（2）每条数据分环境存进 obs_bufs[i] 等六个列表：环境维度的账必须分开记，后面 GAE 才可能分段。obs_bufs[i] 存的是 net_in（归一化后）：训练时网络看到的输入应与采样时完全一致。（3）term_bufs[i] 只记 terminated，truncated 只用于触发 reset，MountainCar 的 200 步上限是时间截断，若当终止处理，价值函数学不到"再坚持一下就能到山顶"的长期收益，爬坡行为根本无法出现。（4）为什么不用 for i, env in enumerate(envs) 直接循环但不存分环境缓冲：那样只需要一份列表，但 GAE 分段时就得靠"记录边界索引"来切，两种写法等价，分环境缓冲更直观，代价是 n 倍的小列表。

片段 4：分段 GAE 与拼接

    # 每个环境单独计算 GAE，再按环境顺序拼接
    all_obs, all_act, all_logp, all_adv, all_ret = [], [], [], [], []
    for i in range(n):
        raw_last = np.asarray(obs_raw[i], dtype=np.float32).reshape(1, -1)
        if stats is not None:
            net_last = stats.normalize(raw_last).astype(np.float32)   # 同一把尺子
        else:
            net_last = raw_last
        last_value = net.value(torch.as_tensor(net_last, dtype=torch.float32, device=device))
        adv_i, ret_i = compute_gae(rew_bufs[i], val_bufs[i], term_bufs[i], last_value, gamma, lam)
        all_obs.extend(obs_bufs[i])
        all_act.extend(act_bufs[i])
        all_logp.extend(logp_bufs[i])
        all_adv.append(adv_i)
        all_ret.append(ret_i)

    batch = {
        "obs": torch.as_tensor(np.asarray(all_obs), dtype=torch.float32, device=device),
        "act": torch.as_tensor(np.asarray(all_act), dtype=torch.long, device=device),
        "logp_old": torch.as_tensor(np.asarray(all_logp), dtype=torch.float32, device=device),
        "adv": torch.as_tensor(np.concatenate(all_adv), dtype=torch.float32, device=device),
        "ret": torch.as_tensor(np.concatenate(all_ret), dtype=torch.float32, device=device),
    }

解读：（1）循环体是"每个环境一个 compute_gae"：环境 i 的 last_value 用它自己的当前观测估值，这就是"bootstrap 按环境分段"的实现，也是向量化最容易被偷懒写错的地方。（2）bootstrap 观测也要过 stats.normalize：网络只认识归一化后的输入，如果这里忘了转换，环境边界处的价值估计会失真。（3）优势与回报用 np.concatenate 拼接；换成 asarray 会把 n 个数组当成"对象数组"处理，形状问题会一路传到 adv.mean() 才爆出来，报错信息还很难懂。（4）拼接顺序与 all_obs.extend 的顺序必须一致（都是环境 0..n−1 的段顺序），否则 obs 与 adv 对不上号，这属于"拼错了也能跑、但训练会诡异变差"的隐性 bug。

完整可运行脚本（附录）：code/ch008.py

python code/ch008.py                       # single / vec / vecnorm 各 25 万步，CPU 约 5–12 分钟
python code/ch008.py --quick               # single 与 vecnorm 各 1.5 万步，约 30–60 秒
python code/ch008.py --variants vec vecnorm  # 只比较归一化的贡献

预期结论（以实跑为准）：25 万步内 single 与 vec 通常都到不了 −135，但 vec 的最佳 100 均值比 single 高 10～25 分；vecnorm 是三组里唯一有机会接近 −135 的，最佳 100 均值通常比 vec 再高 15～30 分且价值损失更平稳；三组用时接近（总步数相同），说明归一化的成本可以忽略。若 25 万步后仍无人达标，不要急着怀疑实现，MountainCar 需要动量探索，PPO 常要 50 万步以上，本实验的意义在相对排名。把环境数提到 8（每环境 256 步）再看一遍是个好习惯：MountainCar 的回合常在 150～200 步上下，256 步的环境段只相当于"一条完整轨迹加一小截"，bootstrap 的语义变重；若 vec8 的最佳 100 均值反而低于 vec4，就亲眼看到"环境数不是越大越好"这条边界。

常见坑

  • 用归一化后的观测回喂统计量：方差会被逐步压缩到 1 附近后停止变化，后期观测的细微结构全被抹掉。统计只吃原始观测，且"先统计后归一化"的顺序不能反。
  • 把 n 条环境轨迹拼成一条算 GAE：环境边界处的 bootstrap 会串台（用别人的 V(sT)），优势被污染。必须每个环境单独递推。
  • 评估时忘了传训练统计量：训练用归一化观测、评估用原始观测，策略见到的输入分布完全不同，评估成绩会凭空掉一大截。评估函数要接收并冻结 stats。
  • MountainCar 的 200 步上限当成终止：它是 truncated，必须 bootstrap；误当终止会让价值函数学不到长期收益，爬坡行为根本无法出现。
  • 批次拼接顺序错位：obs 按环境顺序 extend、adv 用 concatenate 却按别的顺序，数据和标签对不上；程序不报错，但训练曲线会莫名变差。拼接前用一个 print 核对两边的长度与起点最保险。

练习与思考

  1. 把环境数从 4 加到 8（在 VARIANT_SPECS 里加一项 "vec8": (8, True)），保持每次更新总步数 2048 不变，比较与 vecnorm 的差异。★
    提示
    每环境步数会降到 256，环境交互的 Python 循环总次数不变；观察 KL 与最佳 100 的变化，以及每轮更新内轨迹段更短带来的 GAE 行为差异。
  2. 把裁剪上限从 ±10 改成 ±3，观察 vecnorm 的学习曲线是否变化，并解释原因。★
    提示
    MountainCar 的观测常态不会超过 ±3（位置 −1.2～0.6、速度 ±0.07），所以几乎无影响；可以断言"裁剪只对异常观测起作用"。
  3. 给评估函数写一个"统计量漂移"实验：用训练 1 万步时的统计量评估，与用最终统计量评估，比较成绩。★★
    提示
    在训练循环里保存 stats.mean.copy() 的前几个快照，评估时切换。MountainCar 的观测分布会随着策略改变（到达过不同的位置），漂移量值得观察。
  4. 把单进程向量化改成"每个环境独立采样整段（串行）"：先让环境 0 连续走 512 步、再让环境 1 走 512 步，比较两种数据组织下 KL 与最佳 100 的差异。★★★
    提示
    串行版把"轮转"改成外层循环环境、内层循环步数；两种方式总步数相同、批次内容不同。比较批次内优势的相关性（比如相邻样本优势的协方差），理解"数据相关性"的实际含义。

小结

  • 观测各维尺度不一致会稀释小尺度维度的梯度；逐维 (x−μ)/σ 标准化是代价极低的修复，Welford 在线统计适合流式训练。
  • 统计只吃原始观测、评估冻结统计量，是归一化正确性的两个关键细节。
  • 向量化采样把 n 个环境的数据拼成一批，降低相关性；GAE 与 bootstrap 必须按环境分段。
  • MountainCar 上的对比：vec 略优于 single，vecnorm 明显优于两者；尺度问题优先于采样架构问题。
  • 下一章回到优势估计本身：把 TD(0)、固定 n 步回报与蒙特卡洛放在同一批数据上，量化它们的偏差-方差差异，并与 GAE 的混合方式对照。
