第 074 章：多智能体PPO：对手建模

追捕一个会逃跑的对手，只靠"它现在在哪"够吗？本章给追捕者加一个预测头：先猜对手下一步要往哪走，再决定自己怎么追。用三种对手检验这份额外的"读心术"值不值。

  • 主题：对手建模 / 预测头与泛化缺口
  • 关键公式：Lmodel = ‖Δp̂opp − Δpopp‖2；泛化缺口 = 捕获率(训练对手) − 捕获率(未见对手)
  • 预计学时：55 分钟
  • 前置章节：第 073 章

学习目标

  • 理解对手建模（opponent modeling）的动机：在博弈型任务里，对手的行为模式是环境的一部分。
  • 实现一个最小对手模型：预测对手下一步位移，用监督损失训练，把预测注入策略与价值网络的输入。
  • 掌握"泛化缺口"的评估协议：在训练见过的对手与未见过的对手上分别测捕获率。
  • 理解预测为何提供前瞻信息：当前速度是"过去"，位移预测是"下一步"，追捕本质上是拦截未来位置。
  • 学会诊断对手模型的健康度：预测 MSE 是否下降、注入后策略是否真的利用它。

背景与动机

第 068～073 章都是纯合作场景，所有智能体在同一个目标下学习。但只要环境里存在立场不同的参与者，追捕与逃跑、攻防、竞价，每个智能体的"环境"里就多了一个会思考的组件：对手。对手不归你管，还会因为你的行为而改变策略，这正是多智能体非平稳性的根源之一。

传统做法是"把对手当成噪声"：多训练、多对抗、靠策略的鲁棒性覆盖。更聪明的做法是显式建模对手：既然对手的动作影响你的回报，那就先预测它要做什么，再把预测作为决策的输入。人类踢球时盯着对方球员的跑动方向提前卡位，就是这个逻辑。本章在"追捕 vs 逃跑"的最小任务上实现这层建模，并用三种对手检验它的泛化价值，训练时只见过"逃跑"策略，测试时还有"随机"和"折线"两个没见过的对手。

核心原理

1. 追捕是一个"拦截未来"的问题

追捕者的观测里有对手的相对位置与相对速度，但速度只能告诉你它"刚走过什么路"。要抓到一个正在转向的对手，你需要的是它下一步会出现在哪里：

预测：Δp̂opp ≈ Δpopp = popp(t+1) − popp(t)，  注入：at ∼ πθ(· | ot, Δp̂opp)，Vθ(ot, Δp̂opp) Δp̂ 是对手位移的预测（2 维）；把它拼进策略与价值的输入，保证"决策"和"估值"看到同一份前瞻信息

预测头与策略共享躯干特征 h，输出 2 维位移（经 tanh 限制在 ±0.4，与单步位移量级匹配），辅助损失是真实位移的均方误差：

Lmodel = ‖ Δp̂opp − Δpopp ‖2

真实位移不需要额外标注：环境里对手位置的变化就是标签，用相邻两步的观测相减即可（Δ自身位置 + Δ相对位置），不需要给环境加任何接口。

2. 为什么预测有价值：信息前瞻

对手是反应式策略（比如"远离追捕者"）时，它的下一步动作由当前相对位置决定，理论上可以从观测里推出来，但普通 MLP 需要很多样本才能隐式学到这条规律。预测头把这个规律显式化：用监督损失直接逼迫网络学会"对手会往哪走"，再把结果喂给策略。监督信号比回报信号密集得多（每一步都有标签），所以学得快。对训练中没见过的对手（折线、随机），预测可能不准，但"先预测再决策"的架构至少让策略有机会权衡，预测可信时加大利用，不可信时忽略。

还有一个副作用值得注意：预测的梯度会回流进共享躯干 h，因此躯干特征被迫编码"对手行为模式"的信息。即便预测头本身输出不完美，这份表征也可能让下游的策略/价值受益，这是辅助任务（auxiliary task）的通用效应。

3. 泛化缺口的度量

泛化缺口 = 捕获率(训练对手) − 捕获率(未见对手) 捕获率 = 一局中成功抓到对手的回合比例；缺口越小，说明策略对对手类型的依赖越少

注意评估用的是同一批评估回合（固定环境种子），三种对手共用一个评估环境、只切换对手策略，保证比较公平。模型版的理想目标是"换对手时掉得更少"；只抬高单点成绩、泛化缺口反而扩大的模型，工程上价值有限。

4. 对手建模的三种层次

本章实现的是最浅的一层：行为预测（对手下一步做什么）。更深的两层是：策略建模（显式估计对手的策略 π̂opp(a|o)，甚至用它强化学习中的转移模型）、目标/类型建模（推断对手的目标、类型或理性程度，维护对对手的信念）。三者难度递增、所需假设递增。教学任务里行为预测已经足够产生可测的差异，而且它是唯一不需要"对手也在同一模型空间里"假设的一层。

实现思路与设计

模块划分

关键超参数

数据流

采样：8 维观测 → ChaserNet.forward 先算躯干特征 h → 预测头输出 Δp̂ → 拼进 Actor/Critic 的输入 → 返回动作、logp、价值、预测（预测本身不参与动作采样，只影响输入）。记录相邻观测供 opponent_displacement 计算标签。更新：PPO 损失 + model_coef × 预测 MSE，一并反传。

与第 073 章的差异点

第 073 章：合作团队 + 信用分配；本章：① 改成"一个学习者 vs 一个脚本对手"的单学习者设定；② 引入预测头与自监督损失；③ 评估协议从"一个环境"扩展为"三种对手的泛化矩阵"。前三章建立的 PPO 采样/更新骨架保持不变。

关键代码与解读

片段 1：三个脚本对手

    def _runner_action(self):
        rng = self._rng
        if self.opponent == "random":
            return rng.uniform(-1.0, 1.0, 2).astype(np.float32)
        if self.opponent == "flee":
            d = self.runner_p - self.chaser_p                 # 远离追捕者的方向
            norm = np.linalg.norm(d) + 1e-6
            action = d / norm + rng.normal(0.0, 0.15, 2)      # 加噪声避免轨迹太"机械"
            return np.clip(action, -1.0, 1.0).astype(np.float32)
        # zigzag：沿垂直于"追捕者视线"的方向移动，每隔一段时间换向
        d = self.runner_p - self.chaser_p
        norm = np.linalg.norm(d) + 1e-6
        perp = np.array([-d[1], d[0]], np.float32) / norm     # 视线方向的垂线
        if int(self.t) % 8 == 0:
            self.zigzag_sign *= -1.0                           # 每 8 步折一次
        action = self.zigzag_sign * perp + 0.2 * (d / norm) + rng.normal(0.0, 0.1, 2)
        return np.clip(action, -1.0, 1.0).astype(np.float32)

解读：对手策略都是"可读的几行"，但行为复杂度差别很大，正好覆盖三种泛化压力。（1）random：无信息的最难预测对手，但也不会主动远离，预测头在此收益最低。（2）flee：确定性反应式策略（方向 = 离追捕者远的方向），是训练对手；它的转移规律可以被显式学到，预测头最有用。（3）zigzag：垂直于视线方向折返，它利用了"追捕者的速度惯性"制造绕圈，训练时完全没见过。三种对手共享同一套环境动力学与评估种子，切换只改 opponent 字段。（4）注意 flee 与 zigzag 都加高斯噪声：纯确定性对手容易让追捕者过拟合"直线追击"，加噪声后对手的行为分布更真实。

片段 2：预测头的注入点

class ChaserNet(nn.Module):
    """追捕者网络；use_model=True 时增加位移预测头，并把预测拼进策略/价值输入。"""

    def __init__(self, obs_dim, act_dim, hidden=64, use_model=True):
        super().__init__()
        self.use_model = use_model
        self.body = nn.Sequential(nn.Linear(obs_dim, hidden), nn.Tanh(),
                                  nn.Linear(hidden, hidden), nn.Tanh())
        head_in = hidden + (2 if use_model else 0)      # 有模型时输入多 2 维预测
        self.actor = nn.Sequential(nn.Linear(head_in, hidden), nn.Tanh(),
                                   nn.Linear(hidden, act_dim))
        self.critic = nn.Sequential(nn.Linear(head_in, hidden), nn.Tanh(),
                                    nn.Linear(hidden, 1))
        self.log_std = nn.Parameter(torch.full((act_dim,), -0.7))
        if use_model:
            self.pred_head = nn.Linear(hidden, 2)

    def forward(self, obs):
        h = self.body(obs)
        if self.use_model:
            pred = torch.tanh(self.pred_head(h)) * 0.4      # 预测对手下一步位移
            feat = torch.cat([h, pred], dim=-1)
        else:
            pred = None
            feat = h
        mean = self.actor(feat)
        log_std = torch.clamp(self.log_std, -4.0, 0.5).expand_as(mean)
        value = self.critic(feat).squeeze(-1)
        return mean, log_std, value, pred

解读：三段式结构（躯干 → 预测头 → 策略/价值头）是本章的核心设计。（1）注入点唯一：预测拼在头的输入端（feat = cat([h, pred])），Actor 与 Critic 共享同一份 feat，如果只给 Actor 不给 Critic，价值函数会低估"有前瞻"的收益，优势估计被污染。（2）head_in 随开关变化：无模型版本的结构与普通 PPO 完全一致，两种变体参数量只差一个预测头 + 2 列输入权重，对照干净。（3）预测输出乘 0.4，与单步位移量级匹配；这个常数不是玄学，环境单步位移受速度上限约束，超量程的预测会让 MSE 天真地先拟合量纲。（4）pred 被一路返回：训练用它算辅助损失，诊断（日志）也可以打印它的均值观察学习情况；评估时忽略返回的 pred，只取动作。

片段 3：从观测里"抠出"位移标签

def opponent_displacement(obs, next_obs):
    """从相邻观测推算对手的真实位移：Δ(自身位置) + Δ(相对位置)。"""
    d_own = next_obs[:, 0:2] - obs[:, 0:2]
    d_rel = next_obs[:, 4:6] - obs[:, 4:6]
    return d_own + d_rel

    # ---- 采样时把标签存进 batch（取自 collect）----
    if net.use_model:
        disp_target = opponent_displacement(np.asarray(obs_buf), np.asarray(next_obs_buf))
        batch["disp"] = torch.as_tensor(disp_target, dtype=torch.float32, device=device)

解读：位移标签的推导只用初等代数，却省掉了整个环境接口的改动。（1）对手绝对位置 popp 不可见，可见的是相对位置 popp−pself；要算对手位移 Δp_opp = Δ(相对位置) + Δ(自身位置)，两项都在相邻观测里。（2）这个恒等式依赖"观测按固定槽位排列"（第 0:2 自身位置、第 4:6 相对位置），若观测定义改变，此处必须同步，好在环境与网络在同一个脚本里，接口是封闭的。（3）标签在采样时一次算好、存进 batch，训练时直接取用；如果"训练时重算"，还需要保存 next_obs，显存和逻辑都更重。（4）注意 obs_buf 里最后一条对应的 next_obs 是回合重置后的新观测，对它算出的位移跨越了回合边界，是一个噪声标签。量级不大（两条噪声样本 vs 数千条），但严谨做法是给跨回合样本打掩码；练习里可以试着修这个细节。

片段 4：辅助损失的合流

                mean, log_std, value, pred = net(obs[mb])
                dist = Normal(mean, log_std.exp())
                logp = dist.log_prob(act[mb]).sum(-1)
                ratio = torch.exp(logp - logp_old[mb])

                policy_loss = -torch.min(surr1, surr2).mean()

                loss = policy_loss + args.vf_coef * value_loss
                if net.use_model:
                    aux_loss = F.mse_loss(pred, batch["disp"][mb])   # 预测 vs 真实位移
                    loss = loss + args.model_coef * aux_loss
                else:
                    aux_loss = torch.tensor(0.0)
                optim.zero_grad()
                loss.backward()

解读：辅助任务进入训练的方式就是这么朴素。（1）注意 pred 在这次前向里是重新计算的（不是采样时存的旧值）：它现在带着梯度，供 MSE 更新预测头与躯干。采样时返回的 pred 只用于诊断。（2）model_coef=1.0 的量级需要感受一下：预测 MSE 大约是 0.01~0.1 量级，而策略损失在 0.1~1 量级，默认权重下辅助损失的贡献温和，不会喧宾夺主；如果把系数调到 10，预测塌了但策略可能被拖慢，练习里可测。（3）无模型分支里 aux_loss=0 只为了日志格式一致，没有反向路径。（4）梯度裁剪放在 loss.backward() 之后对全部参数生效，预测头的梯度与策略梯度共享同一个 0.5 的范数预算，这是共享躯干架构的又一处耦合，值得在调参时留心。

常见坑

  • 预测只注入 Actor、不注入 Critic：价值函数看不到前瞻信息，优势估计与策略的输入空间不一致，学习会出现"知道要追但不知道追得值不值"的割裂。
  • 位移标签跨了回合边界：相邻观测若来自重置前后，标签是噪声。样本占比小但语义错误；严谨做法是给跨回合样本打掩码或跳过。
  • 把 model_coef 调得过大：预测头喧宾夺主，策略学习被拖慢。先看日志里 aux_loss 与 policy_loss 的量级再定系数。
  • 用预测 MSE 单独证明"对手建模有效"：MSE 降了只说明预测头在学，不代表策略用得上。有效性要看捕获率与泛化缺口，MSE 是辅助诊断。
  • 评估不打乱对手顺序：三种对手若共用同一批评估种子，没问题；但如果为对齐"难度"手动挑种子，就不再是配对比较了。保持脚本的评估协议不动。

练习与思考

  1. 跑完整对照，记录三种对手的捕获率，计算 model 与 plain 的泛化缺口。模型版缩小了缺口吗？★
    提示
    缺口 = flee 捕获率 − zigzag 捕获率。关注的是"换对手掉多少"，单点成绩参考价值有限。
  2. 把 --model-coef 设为 0、0.5、5 各跑一次，观察预测 MSE 与捕获率。辅助损失的甜点区在哪里？★
    提示
    系数为 0 时预测头只有间接梯度（几乎不学），MSE 不降；系数过大时 aux_loss 压低但策略可能变慢。5 大概率已过大。
  3. 把预测目标从"位移"改成"下一状态的相对位置"，比较收敛速度。哪种目标更好学？为什么？★★
    提示
    预测绝对相对位置比预测位移多了一层"当前已知量"的拟合负担；位移减去的是已知量，学习信号更聚焦，通常收敛更快。
  4. 把对手换成"两套策略随机切换"的混合体（如 60% flee + 40% zigzag），评估 model 与 plain 的表现。部分可预测的对手上，探针价值如何变化？★★
    提示
    改动 _runner_action：按概率选择分支。混合对手的转移规律是"多模态"的，预测头会输出近似期望位移，策略得到的是"平均去向"，效果介于两者之间。
  5. 设计一个"预测置信度"机制：把预测 MSE 的在线估计作为特征拼进策略输入，让策略自己决定何时信任预测。它能收窄泛化缺口吗？★★★
    提示
    可以维护预测误差的滑动平均，作为一维特征随观测注入。这是在向"元认知"（知道自己在什么时候不可信）迈一小步，对未见对手可能有用。

小结

  • 博弈任务里对手是环境的动态组件；对手建模 = 显式预测对手行为，再把预测作为决策输入。
  • 最小实现：共享躯干 + 2 维位移预测头 + 自监督 MSE；预测同时注入 Actor 与 Critic。
  • 位移标签从相邻观测推导（Δ自身位置 + Δ相对位置），不需要环境接口；但要处理跨回合样本。
  • 评估用泛化矩阵：对训练对手（flee）、未见对手（zigzag/random）分别测捕获率，关注缺口，单点成绩只作参考。
  • 预期：对可预测对手收益明显，对未见对手收益收窄；预测 MSE 是学习健康度但仍需用捕获率验证价值。
