第一篇 · 策略梯度与 PPO

第 005 章：PPO的熵正则化系数影响

把熵正则系数从 0 扫到 0.05，跟踪策略熵从 0.693（均匀分布）开始的下降轨迹，看"熵崩溃"怎么发生、代价是什么，以及 0.01 这个默认值到底稳在哪里。

  • 主题：探索机制 / 熵正则化
  • 关键公式：H(π(·|s)) = −Σ π(a|s) ln π(a|s)；loss = Lclip + cvfLV − centH
  • 预计学时：50 分钟
  • 前置章节：第 004 章

学习目标

  • 理解熵正则项在 PPO 总损失中的位置，以及"最大化回报 + 保持随机性"的双目标含义。
  • 实现熵系数扫描实验，记录每轮更新的策略熵、熵项占损失比例、KL 与回报。
  • 识别熵崩溃（entropy collapse）：熵快速塌到 0.1 以下意味着什么、什么时候是良性收敛、什么时候是过早锁定。
  • 掌握用"训练熵 + 评估熵 + 评估回报"三件套判断熵系数是否合适。
  • 为后续探索主题（第 021–023 章）建立参照基线：熵正则只是众多探索机制中的一种。

背景与动机

PPO 的损失由三块组成：策略损失、价值损失和熵奖励。前两块的目标很直观，第三块经常被当成"照抄默认值 0.01"的仪式。其实熵系数是直接控制策略随机性的旋钮：设为 0，策略会迅速收敛到"某个动作概率接近 1"的确定形态；设大，策略长期保持高熵，梯度里探索的成分压过利用的成分。

这个旋钮的风险在于两个方向都会出事。熵太低时，softmax 输出接近 one-hot，被压死的动作梯度几乎为零，如果压错方向，策略就锁死在次优解上；熵太高时，价值/优势信号被大量随机动作稀释，CartPole 这种简单任务迟迟学不到位。本章用一个受控扫描把两端都演示出来，并给出一个量化工具：熵项在总损失中的相对占比，它告诉你熵项从什么时候开始"接管"梯度。

核心原理

1. 熵的定义与取值范围

策略在状态 s 的熵衡量动作分布的"平坦程度"：

H(π(·|s)) = − Σa π(a|s) ln π(a|s) 两个动作时最大熵为 ln2 ≈ 0.693（各 0.5）；最小熵为 0（某个动作概率为 1）

PPO 优化的目标是"期望回报 + cent·熵"的折中，熵项梯度会把 logits 往"更平"的方向推。cent 越大，推得越狠，策略变确定的时点被推迟得越晚。总损失里它带负号：

L = LCLIP + cvf · LV − cent · H 最小化 L 等价于最大化"回报 − cvf·价值误差 + cent·熵"

熵对 logits 的梯度有闭式解，把它写出来才能理解"熵项什么时候推不动策略"：

∂H/∂zi = − πi ( ln πi + H ) 推导：softmax 的雅可比为 ∂πj/∂zi = πj(δij − πi)，代入 H = −Σj πj ln πj 后求导、合并同类项即得

代入具体数字体会这个梯度：π=(0.8, 0.2) 时 H ≈ 0.500，错动作对应的梯度分量 −0.2×(ln0.2+0.500) ≈ +0.222，把它的 logit 向上推；π=(0.99, 0.01) 时 H ≈ 0.056，对应分量 −0.01×(ln0.01+0.056) ≈ +0.045，推的力量小了一个量级。极端情况下 π→(1, 0)，H→0 且 ln πi→0，梯度整体趋于 0：策略一旦接近 one-hot，熵项自身也失去把分布推平的能力，这就是后面"熵崩溃难以逆转"的数学根源。

熵的数值对照：π=(0.5, 0.5) 时 H=0.693；π=(0.9, 0.1) 时 H≈0.325；π=(0.99, 0.01) 时 H≈0.056；π=(0.999, 0.001) 时 H≈0.008。从 0.9 到 0.99 只差一次"看起来不大"的概率变化，熵却掉了 5.8 倍，这解释了为什么日志里熵会以肉眼可见的速度塌到 0.1 以下。

把熵值与梯度分量并排列表，能看清熵项"什么时候推得动、什么时候推不动"（第二个动作是被压制的那个，梯度 ∂H/∂z2 就是把它推起来的力）：

π(动作1, 动作2)H（nats）∂H/∂z2解读
(0.5, 0.5)0.6930.000均匀分布是熵的最大点，一阶梯度为零
(0.6, 0.4)0.6730.097轻微不平衡，推力很小
(0.7, 0.3)0.6110.178进入推力较大的区间
(0.8, 0.2)0.5000.222接近峰值
(0.9, 0.1)0.3250.198越过峰值，开始回落
(0.99, 0.01)0.0560.046接近饱和，推力约为峰值的五分之一
(0.999, 0.001)0.0080.007数值死区，熵项几乎失效

三个结构性事实从表里读出来。其一，梯度在 π=(0.5,0.5) 处恰好为零：均匀分布是熵函数的最大点，一阶导数必为零，所以"熵项把策略推向均匀"这个说法只在策略已经偏离均匀时才成立，对已经均匀的策略它无事可做。其二，推起被压制动作的力在 π错≈0.2 附近达到峰值约 0.22，之后随 π错→0 掉头下降，熵项最有效的区间是"已经有点偏、还没偏死"的中间地带；表中 0.99 档的推力只有峰值的约五分之一，0.999 档只剩 3%，这就是"熵崩溃难以逆转"的数量表述。其三，两个分量的梯度恒等相反：g1+g2 = 0，因为 softmax 对全体 logits 加同一常数不变，熵的梯度必与全 1 方向正交，熵项只能改变 logits 的差，不能改变它们的绝对水平。

2. 熵项什么时候开始主导

熵项的梯度尺度是"常数级"的（对每个状态都推动分布变平），而策略损失的梯度尺度正比于优势 Â 的大小。训练早期优势大，策略损失主导；训练后期策略接近最优，优势缩小，熵项的相对权重上升。用比值来观察：

熵项占比 ≈ cent · H / ( |Lpolicy| + ε ) 持续大于 1 意味着策略几乎不再向优势方向更新，只是在"变平"

注意 Â 在更新前被标准化过，所以 |Lpolicy| 的绝对值被压到 1 附近量级；这解释了为什么 cent=0.05 时熵项很容易抢占主导，0.05 乘上接近 0.7 的熵，本身就是 0.035 量级的位移，和策略损失同量级。

把占比公式代入几组参数感受量级。设训练后期的策略损失量级 |Lpolicy|=0.1、熵 H=0.4：cent 取 0.001 / 0.01 / 0.05 / 0.2 时，熵项占比分别是 0.004 / 0.04 / 0.2 / 0.8。占比 0.8 意味着熵项的梯度接近策略损失项的八成，两者在总损失里几乎等权；若处在训练早期（H≈0.69）而 cent=0.2 且策略损失只有 0.1，占比达到 1.38，熵项在损失里占主导，参数更新的主要成分变成了"把分布变平"，"把好动作选出来"只占小头。这份换算的用途是判读：对照日志里两项的规模，就能判断当前处于探索主导还是利用主导，再决定是降低 cent 还是延长训练。

顺带统一度量单位：代码中的熵按自然对数计算，单位是 nats（奈特），二元均匀分布的 0.6932 nats 恰好等于 1 bit；文献表格常以 bit 为单位，换算系数是 1 nat ≈ 1.4427 bit。本章表格统一用 nats，读到论文里的熵数值时先确认单位再比较。

用数字走一遍这件事：训练第 1 轮，熵 0.69、策略损失量级约 1.0，cent=0.01 时熵项占比约 0.01×0.69/1.0 ≈ 0.007，可以忽略；训练后期，熵降到 0.34、优势变小让策略损失量级降到 0.1 附近，熵项占比变成 0.01×0.34/0.1 ≈ 0.034；若把系数换成 0.05，同样的 0.34 熵得到 0.05×0.34/0.1 = 0.17，权重提高约 5 倍。三个时刻的对比说明：同一个 cent，在训练不同阶段的相对权重并不相同，读数时必须结合当时的策略损失一起看。

3. 熵崩溃与恢复成本

当 cent=0 且优势持续为正时，正确动作的 logit 单调增大，softmax 进入饱和区：π(错动作) 指数级变小，对应 log π 的梯度虽然理论上仍非零，但数值上被指数压缩，策略几乎不可能再翻身。这就是熵崩溃。它在两类情况下发生：良性，策略已经学会全部任务，锁死高分动作；恶性，早期偶然把错动作推高，随后被困在低分策略上。区分方法：同时看熵与回报，熵低但回报高是前者，熵低且回报停滞是后者。

把区分方法写成可执行的三条规则：评估熵 < 0.05 且评估回报明显低于任务水平（CartPole 上低于 300），判为恶性锁定，优先提高 cent 或改用第 021 章的噪声探索；评估熵 < 0.05 但评估回报稳定在高位，判为良性收敛，不做干预；评估熵落在 0.05～0.2 的灰区时，用多种子重跑再下结论，单次运行在这个区间最容易给出误导性的判断。再补一条量级参照：评估熵 0.69 附近表示策略在评估轨迹上接近均匀随机，0.3～0.5 是本任务默认系数下的健康区间，只有掉进 0.05 以下才触发上面两条规则。

4. 熵正则不是万能的探索

熵奖励鼓励"动作概率均等"，它不度量"状态空间覆盖率"。在稀疏奖励或需要长程记忆的任务里，均匀随机动作并不能提供有效探索信号，这会由第 020 章的稀疏奖励处理、第 021 章的参数空间噪声分别应对。评估一个探索机制是否有效，标准是"它是否提高了找到高回报区域的速度"，熵值本身只是随机性的度量。本章先把它作为默认机制，把适用边界研究清楚。

为什么要在评估时单独算熵

训练日志里的熵是"采样批数据的动作分布熵"，它受两个因素影响：策略本身有多确定、以及这批状态落在分布的什么位置。评估熵把第二个因素固定住：在同一条贪婪轨迹上逐个状态计算策略的熵。这样得到的数字才真正回答"策略现在有多确定"。当评估熵 < 0.05 而评估回报却不高时，就是过早锁定的铁证。

解读：（1）dist.entropy() 直接给出当前 minibatch 动作分布的熵，.mean() 后参与损失，它既是正则项也是诊断量。（2）符号是本章最不能错的地方：目标是最大化熵，所以损失里是 − ent_coef * entropy；写成加号会把策略推向均匀随机（练习里会看到它熵停在 0.693、回报上不去）。（3）ent_ratio 的分母取 abs(policy_loss)：策略损失在优势为负的样本上可能是负数，比值只是量级比较。（4）统计放在 no_grad() 里且用 .item() 转成标量：它只用于日志，绝不参与反向图。（5）ent_coef 走函数入参传入，没有从 args 直接取，这是为了让 train_one 能把"当前系数"传进来，也为练习里的"系数调度"留了接口。

片段 2：评估熵，把策略的确定性单独量出来

    @torch.no_grad()
    def policy_entropy(self, obs: torch.Tensor) -> float:
        """当前策略在给定观测上的熵，用于评估阶段的“纯策略熵”诊断。"""
        logits, _ = self.forward(obs)
        return float(Categorical(logits=logits).entropy().item())

@torch.no_grad()
def evaluate(env, net, episodes, device):
    returns, entropies = [], []
    for _ in range(episodes):
        obs, _ = env.reset()
        done = False
        ep_ret = 0.0
        while not done:
            entropies.append(net.policy_entropy(to_tensor(obs, device)))
            logits, _ = net(to_tensor(obs, device))
            action = int(torch.argmax(logits, dim=-1).item())
            obs, r, terminated, truncated, _ = env.step(action)
            ep_ret += r
            done = terminated or truncated
        returns.append(ep_ret)
    return returns, float(np.mean(entropies))

解读：（1）policy_entropy 是网络上的一个独立方法：它只前向、不采样，返回该状态下策略分布的熵。注意它和训练时 dist.entropy() 用的是同一个函数，只是作用点不同。（2）评估用贪婪动作（argmax），执行的动作不带随机性，但收集的"熵"是策略分布的熵，两者互不矛盾：策略可以很确定（低熵）也可以很随机（高熵），评估动作的选择方式不影响策略本身的形态。（3）为什么不在评估里直接用采样策略？因为评估回报要可比：贪婪评估排除了动作随机性的噪声，同一策略的两次评估才稳定；否则回报的波动会让人误判策略质量。（4）只把 entropies 的均值返回，是为了表格展示；如果你要做练习里的"分布直方图"，可以在这里顺手扩展成返回列表。

解读：（1）三个列表各司其职：entropies 看下降速度，ent_ratios 看熵项权重，kl_list 做交叉验证。（2）"前 5 轮 / 后 5 轮"是本章的信息浓缩手法：完整曲线在日志里，对比表只留首尾，首尾差告诉你下降多快，末值告诉你最后多确定。（3）仍然只记录不提前停：如果 0.0 组在 3 万步达标就停，你就看不到它后 5 轮的熵了，而这正是本章要研究的东西。（4）评估生成新的环境实例（gym.make 再传一次），避免评估回合把训练环境的随机状态搅乱，训练环境的 reset 序列属于"受控随机流"的一部分，不能污染。

典型日志：c_ent=0.0 | 近20均 462.8 | 熵 0.083 | 熵项占比 0.000 | KL 0.0041；c_ent=0.01 | 近20均 438.5 | 熵 0.336 | 熵项占比 0.121；c_ent=0.05 | 近20均 330.6 | 熵 0.601 | 熵项占比 0.482。预期结论（以实跑为准）：c_ent=0 的熵掉得最快（后 5 轮常在 0.05～0.2），CartPole 简单时它常常"赌对"高分，但在稍难任务上这种运气会变成风险；c_ent=0.01 的熵平滑滑向 0.3～0.5、综合最稳；c_ent=0.05 的熵长期停在 0.55～0.65、学习明显变慢，近 100 均可能低 50～150 分。评估熵一列会清晰展示三档的差别。

常见坑

  • 熵项符号写反：目标是最大化回报与熵，损失里必须是 − ent_coef * entropy。若写成加号，训练会把策略推向均匀随机，熵停在 0.693 且回报上不去。症状：熵曲线从不下降。
  • 把采样策略的熵当成最终策略的熵：评估用贪婪动作时不再有随机性，评价"探索保住了多少"要看评估轨迹上的策略分布熵（本章的 eval_entropy）；训练日志里的平均熵受采样状态分布影响，口径不同。
  • 跨任务比较 c_ent：动作数不同，熵上限不同（二元 0.693，四元 1.386）。跨任务比较应看"熵 / ln(动作数)"的归一化值。
  • 忽略优势标准化对熵项相对权重的影响：优势被标准化后策略损失量级固定，熵项占比只由 c_ent 和熵决定；如果哪天把标准化去掉，同样的 c_ent 效果会完全不同。
  • 看到熵下降就以为是坏事：熵下降是训练的正常结果，坏的是"熵下降 + 回报停滞"。只看熵不看回报容易把良性收敛误判成崩溃，反向误判同样常见。
  • 在评估里统计采样动作的熵：评估用 argmax 执行动作，动作本身没有随机性，但"策略分布的熵"仍然可以逐状态计算。把二者混起来会得到恒为 0 的假熵。修复：用 policy_entropy(obs) 在评估轨迹上单独统计，与执行动作解耦。

练习与思考

  1. 把 --ent-coefs 改成 0.0 0.2，跑完比较评估回报与熵项占比，解释为什么 0.2 会在早期就"压住"学习。★
    提示
    0.2 × 熵(0.69) ≈ 0.14，比标准化后的策略损失量级还大。观察日志里熵项占比何时超过 1，以及近 20 均曲线的斜率。
  2. 把熵正则改成线性衰减：前一半训练用 0.02，后一半线性降到 0.001。与固定 0.01 对比曲线。★★
    提示
    在 train_one 里按 total_steps / max_steps 计算当前系数并传给 ppo_update。直觉是"先探索后收敛"，注意后段熵是否真的降下来。
  3. 固定一组观测（从一次 rollout 里取 256 个状态），每次更新后统计动作概率的分布直方图，观察 c_ent=0 时分布何时变成尖峰。★★
    提示
    用 torch.softmax(net(obs)[0], dim=-1) 统计 π(动作0) 的均值与最大值占比；c_ent=0 且回报不高时，若 π 已经接近 one-hot，说明已经锁死。
  4. 用三个种子分别跑 c_ent=0.0 与 0.01，比较"首达 400 步数"的均值和方差，判断哪个更稳。★★★
    提示
    外层循环种子、内层循环系数，各跑 6 次，汇总到一张表。你会发现 c_ent=0 的方差通常更大，单次跑得好不代表稳。

小结

  • 熵奖励把"保持随机性"写进目标，cent 越大策略越晚变确定；二元动作的熵上限是 ln2 ≈ 0.693。
  • 熵项的相对权重随训练上升：早期策略损失主导，后期若熵项占比持续大于 1，更新方向基本被"变平"接管。
  • 扫描结果：c_ent=0 熵掉得最快、有时"赌对"高分；c_ent=0.01 综合最稳；c_ent=0.05 明显拖慢学习。
  • 良性熵崩溃与恶性熵锁定的区分靠"熵 + 回报"一起看；后者需要熵正则或更彻底的探索机制。
  • 熵对 logits 的梯度为 −πi(ln πi + H)，概率越接近 one-hot 梯度越小：熵项只能延缓锁定、不能逆转锁定，这是"预防优先"的原因。
