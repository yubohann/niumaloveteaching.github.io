第 069 章：多智能体PPO：集中训练分散执行（CTDE）

执行时大家只用各自的局部观测，训练时却共享一个"上帝视角"的中央批评家。本章在同一个合作导航环境里对照 IPPO 与 CTDE，并用"批评家解释方差"来解释差别从何而来。

  • 主题：CTDE 范式 / 中央批评家
  • 关键公式：Ât ← GAE(rteam, V(sglobal))；解释方差 EV = 1 − Var(R−V)/Var(R)
  • 预计学时：55 分钟
  • 前置章节：第 068 章

学习目标

  • 理解 CTDE 范式：训练期集中、执行期分散，以及它为什么能缓和部分可观测性问题。
  • 掌握共享中央批评家 V(sglobal) 的实现：用团队回报训练，把同一套优势广播给所有智能体。
  • 理解并计算"批评家解释方差（explained variance, EV）"，用它判断价值学习质量。
  • 看懂同一脚本里 IPPO 与 CTDE 的单变量对照：预算、网络、评估协议完全一致，只换批评家。
  • 学会解释"为什么本任务上两种模式差距不大"，任务复杂度与观测同质程度决定 CTDE 的收益大小。

背景与动机

第 068 章的独立 PPO 每个智能体用自己的局部观测估计价值：智能体 A 看不到其他地方发生了什么，却要对"团队奖励"负责。它的优势估计因此带着一层"我不知道队友在干什么"的噪声。CTDE（Centralized Training with Decentralized Execution，集中训练分散执行）提出一个聪明的折中：训练时可以作弊，执行时必须独立。

训练阶段，我们拥有仿真器的一切信息：中央批评家可以看全局状态 sglobal；而执行阶段，每个智能体仍然只依赖自己的局部观测 oi 选择动作，因为部署时队友的动作与全局状态往往拿不到（带宽、隐私、时序都有限制）。这一"训练与执行不对称"的设计是 MAPPO、MADDPG 等主流多智能体算法的共同骨架，也是多智能体领域这些年最重要的工程范式之一。

本章与第 068 章构成标准对照：环境、策略网络、更新规则、预算、评估协议全部不动，只把批评家从"每智能体一个局部 V"换成"一个中央 V(s_global)"，差值就归因于这一处改动。

核心原理

1. 两种价值函数的分工

分散执行要求策略只依赖局部观测，但训练期的价值估计可以拥有更多信息：

执行：ati ∼ πθi(· | oti)     训练：Âti ← GAE(rtteam, V(stglobal)) 策略输入始终是 oi（执行期合法）；价值输入换成全局状态 s_global（训练期特权信息）；两种模式的策略网络完全同构

IPPO 用 Vi(oi) 估计优势，其误差来源是"局部观测不是马尔可夫充分统计量"，同一局部观测对应的全局局势可能千差万别：队友在左侧还是右侧、地标有没有被别人抢先、剩余时间够不够。这些隐藏变量会直接决定回报，却不在 oi 里。中央批评家用 sglobal 消除这种多义性，价值目标更接近真实回报，优势的噪声随之下降。

2. 团队回报 + 共享优势

CTDE 模式下所有智能体用同一份团队回报、同一个中央价值，于是每个智能体拿到的优势完全相同：

δt = rtteam + γ·V(st+1global) − V(stglobal)，  Ât1 = Ât2 = … = ÂtN rtteam 是 step 返回的 per_reward 均值（碰撞惩罚被平均进团队回报）；δ 是 TD 残差；V 是中央批评家

注意这与第 068 章的差异：IPPO 每个智能体的奖励含自己的碰撞惩罚，各自的价值也不同，优势彼此独立；CTDE 里"团队好就是好"，碰撞罚分被平摊。共享优势不代表共享策略，三个策略仍然各自用自己的数据更新，只是不再各自估计价值。集中式价值把"信用分配"问题暂时搁置（第 073 章专门处理）：队友带来的涨分会被记到每个智能体头上，这是它的局限也是它的简单之处。

3. 解释方差：批评家的体检报告

训练中无法直接观察"价值估计准不准"，但可以看它对回报的解释能力：

EV = 1 − Var(R − V(s)) / Var(R) R 是价值回归目标（GAE 反推的回报）；V(s) 是预测；分子是残差方差。EV≈1 表示价值预测几乎无误差；EV≤0 表示还不如直接用回报均值去猜；训练早期常在 0.2~0.6 之间

EV 的美妙之处是它与奖励尺度无关：无论是 −25 分还是乘了三倍的 −75 分，只要价值预测的相对质量一样，EV 就一样。中央批评家看到更多信息，通常能在更少样本内把 EV 拉高。本章日志每轮打印 批评家EV：IPPO 是三个局部批评家的平均值，CTDE 是单个中央批评家的值，这条曲线往往比回报曲线更早地显示两种模式的差别。

4. 为什么这个任务上差距可能不大

CTDE 的收益来自"局部观测的多义性"。本环境的观测其实相当"厚"：14 维里包含了自己的位置/速度、所有地标相对位置、所有队友相对位置，离全局状态只差"绝对坐标系"和"时间"。换句话说，oi 已经很接近 s 的充分统计量，中央批评家能多看到的信息有限。任务又是低维、确定性的合作导航，IPPO 局部批评家也够用。因此预期是：CTDE 的 EV 更高、曲线更稳，但最终回报与 IPPO 可能接近，"差距不大"是正确结论，不是实验失败。想看 CTDE 大显身手，要换观测更贫瘠、队友行为更关键的任务。

数据流

CTDE 采样：每环境步先取 global_state() → 中央批评家算一个 V(s) → 三个 Actor 各自采动作 → 环境步进 → 存局部转移（obs/act/logp）、全局状态、团队回报与 V。更新时：中央批评家用（状态，回报目标）做 MSE 回归 → 同一套优势广播给三个 Actor → 每个 Actor 独立做裁剪更新。

与第 068 章的差异点

唯一的结构性改动是批评家：从"每智能体一个局部 Vi"换成"一个中央 V(sglobal)"；采样器相应记录全局状态与团队回报；优势从"每人一套"变成"全队一套"。策略网络、更新算法、预算、评估协议全部不动，这是标准的单变量对照。第 070 章会在此基础上继续改第二个变量：策略网络是否共享。

关键代码与解读

片段 1：两个批评家的唯一差别是输入

class LocalCritic(nn.Module):
    """IPPO 的局部批评家：输入单个智能体的观测。"""

    def __init__(self, obs_dim, hidden=64):
        super().__init__()
        self.net = nn.Sequential(nn.Linear(obs_dim, hidden), nn.Tanh(),
                                 nn.Linear(hidden, hidden), nn.Tanh(),
                                 nn.Linear(hidden, 1))

    def forward(self, obs):
        return self.net(obs).squeeze(-1)


class CentralCritic(nn.Module):
    """CTDE 的中央批评家：输入全局状态，输出团队价值。"""

    def __init__(self, state_dim, hidden=64):
        super().__init__()
        self.net = nn.Sequential(nn.Linear(state_dim, hidden), nn.Tanh(),
                                 nn.Linear(hidden, hidden), nn.Tanh(),
                                 nn.Linear(hidden, 1))

    def forward(self, state):
        return self.net(state).squeeze(-1)

解读：把两个类并排看，你会看到 CTDE 的全部秘密其实只有一行之差，Linear 的输入维度。（1）LocalCritic 输入 14 维局部观测，每个智能体一个实例；CentralCritic 输入 19 维全局状态，全队一个实例。网络结构（两层 64 宽 Tanh MLP）完全相同，排除了容量差异。（2）squeeze(-1) 把 (B,1) 压成 (B,)，让价值可以直接与回报目标（一维向量）对齐做 MSE；两种批评家统一这个约定，更新代码才能共用。（3）为什么中央批评家能"作弊"？因为它只在训练时使用，输出优势后，执行期完全不需要它，部署包里只有 Actor。这就是 CTDE "训练-执行不对称"的落地方式。（4）注意没有"全局状态专属网络结构"的讲究：19 维输入仍然是小 MLP 足够处理的任务；如果状态维度很大（如多机视觉），这里会变成 CNN+注意力等结构，但差别仍是"输入什么"。

片段 2：中央批评家与共享优势的完整更新

    def update(self, buf, args) -> dict:
        device = self.device
        agent_bufs = buf["agents"]
        states = torch.as_tensor(np.asarray(buf["states"]), dtype=torch.float32, device=device)
        team_rew = buf["team_rew"]
        cuts = buf["cuts"]
        last_state = torch.as_tensor(buf["last_state"], dtype=torch.float32,
                                     device=device).unsqueeze(0)
        with torch.no_grad():
            last_value = float(self.central(last_state).item())   # 中央批评家做 bootstrap
        adv, ret = compute_gae(team_rew, buf["val"], cuts, last_value, args.gamma, args.lam)
        adv_t = torch.as_tensor(adv, device=device)
        ret_t = torch.as_tensor(ret, device=device)

        # 中央批评家：用团队回报训练，整套优势只算一次
        for _ in range(args.epochs):
            pred = self.central(states)
            loss = F.mse_loss(pred, ret_t)
            self.central_opt.zero_grad()
            loss.backward()
            self.central_opt.step()
        with torch.no_grad():
            ev = explained_variance(self.central(states), ret_t)

        # 所有智能体共享同一套优势（团队奖励 + 中央价值）
        stats = {"policy_loss": 0.0, "approx_kl": 0.0, "clip_frac": 0.0, "ev": ev}
        for i in range(self.n):
            obs = torch.as_tensor(np.asarray(agent_bufs[i]["obs"]), dtype=torch.float32,
                                  device=device)
            act = torch.as_tensor(np.asarray(agent_bufs[i]["act"]), dtype=torch.float32,
                                  device=device)
            logp_old = torch.as_tensor(np.asarray(agent_bufs[i]["logp"]), dtype=torch.float32,
                                       device=device)
            ps = ppo_actor_update(self.actors[i], self.actor_opts[i], obs, act,
                                  logp_old, adv_t, args)     # adv_t 对三个 Actor 是同一份
            stats["policy_loss"] += ps["policy_loss"]
            stats["approx_kl"] += ps["approx_kl"]
            stats["clip_frac"] += ps["clip_frac"]
        stats["policy_loss"] /= self.n
        stats["approx_kl"] /= self.n
        stats["clip_frac"] /= self.n
        return stats

解读：这段代码是 CTDE 与 IPPO 在更新路径上的全部差异。（1）GAE 只算一次：输入是团队回报 team_rew 与中央价值 buf["val"]，last_value 也由中央批评家给出。IPPO 那边这个位置是"三个批评家各算一遍"，计算量和方差都更大。（2）批评家训练用 F.mse_loss(pred, ret_t) 回归 GAE 反推的回报，与单智能体 PPO 的做法完全一致，批大小就是整段采样（全局状态最多 1000 条），不再分子批，因为批评家只有一个、数据量也不大。（3）adv_t 在 Actor 循环外构造一次，循环里三个 Actor 拿到的是同一份张量，"共享优势"在代码里就是这行注释所指的事实。第 073 章会讨论这带来的信用分配偏差，以及如何用个体奖励修正。（4）诊断统计按智能体平均（/= self.n），与 IPPO 的汇总口径一致，两种模式的日志可以直接对照。（5）顺序上"先更新批评家、再更新 Actor"很重要：Actor 用的优势来自刚说过几步的批评家，价值越准，策略梯度方向越可靠。

片段 3：CTDE 采样器，多记两样东西

def collect_ctde(env, agents, steps_agent, args, obs):
    n = env.n_agents
    agent_bufs = [{"obs": [], "act": [], "logp": []} for _ in range(n)]  # 不再存 per-agent 奖励
    states, team_rews, values, cuts = [], [], [], []
    team_rets = []
    ep_team_ret = 0.0
    for _ in range(steps_agent // n):
        global_state = env.global_state()             # 每步取一次全局状态
        actions, logps, value = agents.act_all(obs, global_state)
        next_obs, per_r, team_r, done, _ = env.step(actions)
        for i in range(n):
            agent_bufs[i]["obs"].append(obs[i])
            agent_bufs[i]["act"].append(actions[i])
            agent_bufs[i]["logp"].append(logps[i])
        states.append(global_state)                   # 中央批评家的输入
        team_rews.append(team_r)                      # 团队回报（per_r 的均值）
        values.append(value)                          # 中央价值（每步只算一次）
        cuts.append(float(done))
        ep_team_ret += team_r
        obs = next_obs
        if done:
            team_rets.append(ep_team_ret)
            ep_team_ret = 0.0
            obs = env.reset()
    buf = {"agents": agent_bufs, "states": states, "team_rew": team_rews,
           "val": values, "cuts": cuts, "last_state": env.global_state()}
    return buf, team_rets, obs

解读：与第 068 章的 IPPO 采样器对比，这里有四处值得注意。（1）每智能体的桶里不再存奖励：CTDE 的 GAE 只用团队回报，per-agent 奖励没有登场机会，数据结构跟着机制走，这是好代码的标志。（2）global_state() 每步取一次，既喂给中央批评家估 V(s)，也原样存进 states 供训练回归，两条路径用的是同一份状态，不重算不漂移。（3）values 每步只有一个值（中央批评家）；局部版需要 N 次前向、这里只需 1 次，采样循环直接省掉 N−1 次。（4）last_state 记录采样结束时的新状态，用来给 GAE 提供 bootstrap 价值；它与 states 的时序衔接必须准确，否则优势末端会有系统性偏差。

片段 4：解释方差的实现与用法

def explained_variance(y_pred: torch.Tensor, y_true: torch.Tensor) -> float:
    """批评家解释方差：越接近 1 说明价值预测越可靠。"""
    var_y = y_true.var()
    if float(var_y.item()) < 1e-8:                    # 回报方差近零时直接返回 0
        return 0.0
    return float((1.0 - (y_true - y_pred).var() / var_y).item())

    # 两种模式里的用法（取自各自 update 的诊断段）：
    ev = explained_variance(self.central(states), ret_t)             # CTDE：中央批评家
    stats["ev"] += explained_variance(self.critics[i](obs), ret_t)   # IPPO：逐个局部批评家

解读：六行函数，两个边界条件值得记住。（1）分母是 y_true.var()：回报目标的方差。当采样窗口里回报几乎是常数（例如训练早期奖励都被截到同一范围）时方差趋零，必须提前返回 0，否则除零出 nan 并污染整条日志。（2）分子是残差方差 (y_true − y_pred).var()：注意用的是方差比值，这正是 EV 与奖励尺度无关的原因：乘 3 倍奖励，分子分母同步放大，EV 不变。（3）"不如均值"的含义：若价值网络恒等于回报均值，残差方差=回报方差，EV=0；预测比常数还差，EV 为负。日志里 EV 长期为负，说明批评家没学到东西，先检查学习率和目标构造；这点上调策略解决不了问题。（4）两种模式的调用点只差在"谁来预测"：中央 or 局部，这正是本章对照实验的落脚点。

常见坑

  • 执行期偷用全局状态：策略网络与执行代码必须只用局部观测。如果把 s_global 喂给 Actor，训练指标会很漂亮，但部署时拿不到全局状态，模型直接失效。
  • 团队回报与个体回报混用：CTDE 的 GAE 输入必须是 team_rew，且与中央价值配套；混入 per-agent 奖励会让 TD 残差的尺度对不上批评家的预测目标。
  • 忘了 last_state 的时序：bootstrap 价值必须取自采样窗口结束后最新的全局状态。如果误用窗口内最后一个状态，末端优势会有一步的系统性偏差。
  • 把 EV 当性能指标：EV 衡量的是价值预测质量，不是策略好坏。EV 高而回报低，可能是批评家拟合了一个平庸策略的回报分布，两者要一起读。
  • 两种模式没对齐超参数：单变量对照的意义在于只改批评家。若 CTDE 顺手换了批量或学习率，结论就无法归因；本章用同一份 args 保证对齐。

  2. 把 --mode 只跑 CTDE 两次（种子 0 与 1），观察最终回报与 EV 的波动。预测多种子下两种模式的差距是否稳定。★
    提示
    单次运行的排名可能是噪声。把两种模式各跑 3 个种子，比较"平均回报 ± 标准差"再下结论。
  3. 把观测里的"其他智能体相对位置"删掉（改 _obs，只留自己和地标），让局部观测真正贫瘠，再对照 IPPO 与 CTDE。预测差距会变大还是变小？★★
    提示
    删掉队友信息后，o_i 的多义性大增：你不知道别人会不会来撞你、地标会不会被抢。这正是 CTDE 的主场，中央批评家的信息优势被放大。
  4. 把中央批评家的输入从 19 维全局状态换成"三个局部观测的拼接"（信息量介于两者之间），重新对照 EV 与回报。CTDE 的收益随批评家信息量怎么变化？★★
    提示
    拼接局部观测缺少了绝对坐标与时间，但保留了队友信息。做法：在采样时存 np.concatenate(obs)，改 CentralCritic 的输入维度即可。
  5. 把共享优势拆回"每个智能体用自己的折现回报估计优势"（即 CTDE 结构 + IPPO 的信用口径），观察 EV 与回报怎么变。讨论：集中批评家与信用分配到底是两个问题还是一个？★★★
    提示
    可以给每个智能体保留个体奖励，用中央 V 预测团队价值、再手工做差值。这个练习会把你引向第 073 章，集中训练只是手段，信用分配才是目的。

小结

  • CTDE = 训练期集中（批评家可看全局状态）+ 执行期分散（策略只吃局部观测）；部署包里只有 Actor。
  • 与 IPPO 的唯一差别是批评家：一个共享 V(s_global) vs 每智能体一个 Vi(oi)；其余全部对齐。
  • CTDE 的 GAE 用团队回报、只算一次；共享优势广播给所有 Actor，但策略仍各自更新。
  • 解释方差 EV = 1 − Var(R−V)/Var(R) 是价值学习的体检报告，与奖励尺度无关；中央批评家通常 EV 更高。
  • 本任务观测较"厚"（已含队友信息），CTDE 的收益主要在价值质量与稳定性的边角，别再期待它扭转回报；换贫瘠观测任务差距会放大。
