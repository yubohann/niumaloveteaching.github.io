第 082 章：多智能体SAC：对手建模

在连续空间的追逐-逃逸博弈中给每个 SAC 智能体配一个"对手模型"：评论家改为先预测对手的动作再评估自己的价值，不再假设对手静止，看它能否把追获率抬上去。

  • 主题：多智能体机制 / 对手建模与非平稳性
  • 关键公式：Qi(si, ai, μ̂φ(o−i)) 与 detach 的监督对手模型
  • 预计学时：50 分钟
  • 前置章节：第 081 章

学习目标

  • 理解多智能体环境中的非平稳性（non-stationarity）：为什么"环境转移随对手的学习而变"会破坏单智能体 SAC 的价值估计。
  • 掌握对手模型的监督学习形式：从对手观测预测对手动作，梯度只进模型本身、不进策略与评论家。
  • 理解"评论家输入拼接对手动作"的三种模式：off（独立基线）、pred（预测动作）、true（真实动作上界），并说清各自可用性。
  • 学会用 pending_idx 按回合边界回填"下一状态的对手动作"，让 Bellman 目标在时间上保持自洽。
  • 在零和追逐-逃逸环境上对比三种模式的贴获率与回报曲线，会读对手模型 MSE 与性能增益的对应关系。

背景与动机

独立 SAC（第 076 章）把每个智能体都当成"单智能体 RL"来训练：自己的评论家只看自己的状态和动作。但在博弈场景里，你下一步能拿到多少回报，很大程度取决于对手会怎么动。对手的策略在训练中一直在变，评论家学到的 Q(s,a) 实际上在追踪一个移动目标，这就是多智能体里的非平稳性。

第 081 章的信用分配解决"团队回报怎么分"，本章处理另一个方向：对手怎么动。一个自然的补救办法是让评论家"看见"对手的动作。训练时我们能拿到对手的真实动作（数据是联合采集的），但执行时拿不到，所以要么用真实动作当上界（MADDPG 式集中评论家），要么训练一个对手模型，只从对手的观测推断其动作。后者更接近"预测对手"的本意，也是本章主角。追逃环境还自带一个好处：每个智能体的观测里天然包含对手的位置与速度，预测任务的信息基础是现成的。

核心原理

1. 非平稳性如何伤害评论家

单智能体 SAC 的 Bellman 目标假设环境转移 p(s′|s,a) 固定，同一个 (s,a) 总能得到相近回报。博弈中转移里隐含了对手策略 π−i：

p(s′ | s, ai) = Σa−i π−i(a−i | s) · p(s′ | s, ai, a−i)

其中 ai 是自己的动作、a−i 是除自己外所有对手的动作，π−i 是对手策略。当 π−i 随对手训练而改变时，p(s′|s,a) 也在变，Q 值回归目标就带着"对手版本号"的漂移。把对手动作显式放进评论家（哪怕只是预测值），等价于把这份漂移资产化：Q 网络至少知道"我评估的这对 (s,a) 是在对手做了 â−i 的前提下"。

2. 对手模型的监督学习

每个智能体 i 维护一个对手模型 μ̂φ，输入对手自己的观测 o−i，输出对对手动作的预测 â−i，训练就是普通的 MSE 回归：

Lopp(φ) = ½ · 𝔼[ ‖ μ̂φ(o−i) − a−i ‖2 ]

关键约束：评论家使用预测值时必须 detach()。否则策略梯度会"为了让 Q 看起来高"而去篡改对手模型，模型就不再是对手行为的无偏估计，MSE 可能不降反升。只有当 a−i 是真实数据、φ 只被上面这个监督损失驱动时，预测才可信。

3. 三种评论家输入构成信息阶梯

off  : Qi( si, ai )
pred : Qi( si, ai, μ̂φ(o−i) )
true : Qi( si, ai, a−i )

true 只在集中训练时可用，是"知道对手下一步会怎么做"的信息上界；pred 执行阶段也能持续预测，是真正可部署的方案；off 是所有对比的基线。预期排序是 true ≥ pred ≥ off，但差距取决于预测准不准，对手模型 MSE 居高不下时，pred 的增益会明显缩水。

4. 零和奖励：让"军备竞赛"成为实验装置

追者每步拿 −dt（当前双方距离），逃者拿 +dt，两人之和恒为 0；追者贴上逃者时一次性 +10 / −10 并终止。每步都有塑形信号，避免了稀疏奖励冷启动；零和结构又让"两个 SAC 同时学习"变成一场军备竞赛，正好检验对手建模对非平稳性的缓解效果。注意距离本身的量级：场地边长 2.4，最长对角距离约 3.4，所以每步塑形项在 −3.4～0 之间，与 +10 的一次性奖励差一个量级，这正是后面"奖励尺度"坑的来源。

数据流

每个联合步：双方策略各出动作 → 环境推进一次 → 两个智能体各自存转移（自己的 obs/act/rew 加上对手的观测与动作）→ 每 2 步各做一次 SAC 更新 → 每 250 步各做 2 次对手模型监督训练 → 回合结束重置。off 模式不训练也不使用对手模型，true 模式直接用采样时的对手动作，两者共用同一套主循环。

与前一章的差异

第 081 章改动的是回报归属：用反事实基线把团队回报拆到每个智能体头上，回答"功劳算谁的"。本章不改变回报归属，追逃是零和的，每个智能体的回报就是自己的回报；改动发生在评论家的输入端：从只看自己，到显式建模对手动作。两者共同点是都保留"每个智能体一个独立 SAC"的骨架，区别是 081 处理"钱怎么分"、本章处理"对手怎么动"。

两个容易忽略的实现细节

1) 下一状态的对手动作：Bellman 目标里的 Q(s′, a′) 也需要对手动作。样本按时间顺序存储时，可以在存入下一条转移时"回填"上一条的 next_opp_act（代码里的 pending_idx）；真实终止处不回填，因为 bootstrap 已被切断。

2) 预测动作必须 detach：否则策略学习会通过对手模型产生梯度，把对手模型带偏成"让 Q 值好看"的样子，模型越训越离真相远。

关键代码与解读

片段 1：环境动力学与零和奖励

def step(self, actions: np.ndarray):
    """动作 shape=(2,2)。返回 obs, rewards, terminated, truncated, info。"""
    a = np.clip(actions, -1.0, 1.0).astype(np.float32)
    # 一阶惯性动力学：速度先按摩擦衰减，再叠加加速度；动作是"推力"，位移由速度积分而来
    self.vel = np.clip(self.friction * self.vel + self.accel * a,
                       -self.v_max, self.v_max)
    # 位置积分速度并夹在场地内；边界硬截断，防止飞出观测分布
    self.pos = np.clip(self.pos + self.vel, -self.bound, self.bound)
    self.steps += 1

    dist = float(np.linalg.norm(self.pos[0] - self.pos[1]))
    # 零和塑形奖励：追者每步 -d、逃者 +d，逐帧有信号，双方目标完全相反
    rewards = np.array([-dist, dist], dtype=np.float32)
    terminated = False
    if dist <= self.tag_radius:          # 追者贴住逃者：一次性 ±10 并立即终止
        rewards[0] += 10.0
        rewards[1] -= 10.0
        terminated = True
    # 80 步上限只是时间截断，不能当"真终止"；Bellman 目标仍要 bootstrap
    truncated = (not terminated) and self.steps >= self.max_steps
    return self._obs(), rewards, terminated, truncated, {"dist": dist}

解读：这段环境代码决定了实验的"物理规则"。（1）速度用一阶惯性（旧速度×0.8 + 加速度×0.12），意味着策略不能瞬移，必须提前规划减速与转向，这正是连续控制该有的手感。（2）摩擦与加速度的比例决定机动能力：满输入时单轴稳态速度为 0.12/(1−0.8) = 0.6，约 10 步达到其九成，追者的"转向半径"由此确定；声明中的 v_max=1.2 是安全夹断，正常动作幅度下不会触发。（3）奖励每步 −d / +d，量级 0～3.4，比贴获的 ±10 小一个数量级：塑形负责"引导"，终局奖励负责"宣判"。（4）truncated 与 terminated 分开返回，后面入缓冲时才只把真终止写进 done。

片段 2：存转移与"下一状态对手动作"的回填

def store(self, obs, act, rew, next_obs, terminated, opp_obs, next_opp_obs, opp_act):
    """存一条转移；并把上一条转移的 next_opp_act 补齐（回合内相邻）。"""
    entry = {
        "obs": obs, "act": act, "rew": rew, "next_obs": next_obs,
        "done": float(terminated),   # 只把"真终止"写进 done，截断回合要保留 bootstrap
        "opp_obs": opp_obs, "next_opp_obs": next_opp_obs,
        "opp_act": opp_act, "next_opp_act": None,
    }
    self.buffer.append(entry)
    if len(self.buffer) > self.args.buffer_size:
        del self.buffer[: len(self.buffer) // 2]  # 满了删最早一半，近似 FIFO
        self.pending_idx = None                   # 下标失效，放弃这次回填
    if self.pending_idx is not None:
        # 上一条转移的"下一状态对手动作"就是本步刚采到的对手动作，按时间回填
        self.buffer[self.pending_idx]["next_opp_act"] = opp_act
    # 真终止处断开 pending：跨回合的两步不属于同一轨迹，回填会张冠李戴
    self.pending_idx = None if terminated else len(self.buffer) - 1
    self.opp_data.append((opp_obs, opp_act))      # 同时攒监督数据，喂给对手模型

解读：这是本章最"不起眼但最容易写错"的一段。（1）Bellman 目标 Q(s,a) ← r + γ·Q(s′, a′) 里，a′ 既包含自己的下一动作（由目标策略现算），也包含对手的下一动作，后者在采样时还不知道，只能等下一步采样发生后再"回填"。（2）回填的前提是两次采样在同一条轨迹上：pending_idx 在真终止处清空，防止把上一回合末尾的样本和下一回合开头的对手动作错误配对。（3）缓冲区删除一半时下标整体失效，代码直接放弃这次回填，受影响的只有极少数边界样本，对训练无影响，比维护"下标平移"简单得多。（4）顺手攒 opp_data，一个环境步喂两路数据，零额外采样成本。

片段 3：评论家输入的三种拼法

def _critic_input(self, obs, act, opp_obs, opp_act, next_opp_act=None):
    """按模式拼装评论家输入：off=[obs,act]；pred=+预测对手动作；true=+真实对手动作。"""
    if self.args.opp_model == "off":
        return torch.cat([obs, act], dim=-1)     # 基线：评论家对对手一无所知
    if self.args.opp_model == "true":
        # 训练期上界：Bellman 目标缺未来动作时用零向量占位（bootstrap 边界，占比极小）
        oat = opp_act if next_opp_act is None else next_opp_act
        return torch.cat([obs, act, oat], dim=-1)
    pred = self.opp_model(opp_obs).detach()      # detach：策略梯度绝不能流进对手模型
    return torch.cat([obs, act, pred], dim=-1)

解读：一个函数切换三种实验条件，评估对象完全一致，只换"评论家看到多少对手信息"。（1）输入维度在 SACAgent.__init__ 里按模式算好（obs_dim + act_dim + extra），网络结构不变，所以对照实验不受模型容量差异干扰。（2）detach() 是红线：对手模型只接受 train_opp_model 里的监督梯度。（3）true 模式的占位零向量只出现在"目标 Q 的未来动作未知"这一种边界情况（缓冲区截断处），量级极小，不会把 Q 值带偏。（4）想换成"拼对手观测"做消融，只改这一个函数即可，这正是把开关集中到一处的好处。

片段 4：SAC 更新里的 Bellman 目标

alpha = self.log_alpha.exp().detach()            # 温度以常数出现，不参与 Q 的梯度
# 1) 双 Q 的 Bellman 回归目标：目标动作由"当前策略"重采样，对手动作来自回填
with torch.no_grad():
    next_a, next_logp = self.actor(next_obs)
    q_in = self._critic_input(next_obs, next_a, next_opp_obs, opp_act, next_opp_act)
    q1_next = self.q1_target(q_in)
    q2_next = self.q2_target(q_in)
    # 最小双 Q 抑制过估计；减去 alpha*logp 是 SAC 最大熵项的体现
    y = rew + self.args.gamma * (1.0 - done) * (
        torch.min(q1_next, q2_next) - alpha * next_logp)
# 2) 双 Q 都向同一个目标回归；取 min 用于目标值，更新本身是两条独立 MSE
q_in = self._critic_input(obs, act, opp_obs, opp_act)
critic_loss = F.mse_loss(self.q1(q_in), y) + F.mse_loss(self.q2(q_in), y)

解读：这段是 086 章之前所有多智能体 SAC 的公共骨架，本章只动了 _critic_input 的拼接。（1）未来动作 next_a 由当前策略重采样（SAC 的 on-policy 味道），next_logp 进入目标里的熵项。（2）目标里的对手动作分两路：评估当前对 (s,a) 时用本步的 opp_act；评估未来对 (s′,a′) 时要的是下一步的对手动作 next_opp_act，没有回填机制的话这三行就是错的。（3）(1.0 - done) 掩码保证真终止后未来价值归零；截断不置零，因为环境只是被时间打断。（4）Q 目标全程在 no_grad 里计算，只有在线双 Q 的参数收到梯度，这是"目标网络"能稳定回归的前提。

常见坑

  • 忘记 detach 预测动作：_critic_input 里漏掉 .detach()，策略梯度会流进对手模型，把它训练成"讨好评论家"的假预测器，MSE 可能不降反升。
  • 把 terminated 和 truncated 混用：追逃的 80 步上限是时间截断，Q 目标仍应 bootstrap；只有贴到（terminated=True）才切断。代码里入缓冲的 done 用 float(terminated)，别手滑混用。
  • 预测输入用错观测：对手模型要预测"对手会做什么"，输入必须是对手自己的观测；用自己观测去预测对手动作，对称环境里也许勉强能学，对手策略一变就立刻失效。
  • 忘记回填 next_opp_act：图省事把 next_opp_act 恒置为零，Bellman 目标里的对手动作就失真了，true 模式会退化成"半个 off"，pred 模式则报错或学歪。症状：MSE 正常但贴获率不涨。
  • 奖励尺度失衡：一次性 ±10 远大于每步 ±d（最大约 3.4）。如果把塑形项再放大 10 倍，Q 值会被稀疏大奖励主导，逃者在前 2 万步几乎学不到"拉开距离"的中间信号。

练习与思考

  1. 把 --opp-model 三种取值各跑一遍，记录评估贴获率与对手模型 MSE，画出"预测精度 vs 性能增益"的对应关系。★
    提示
    命令只是换参数，不用改代码。注意 off 模式没有对手模型 MSE 输出（日志里是 nan），对比时只比贴获率。结论至少用 3 个种子验证。
  2. 把对手模型训练频率从 250 步改成 50 步（--opp-train-every 50），先预测 MSE 下降速度会怎么变，再实跑验证。★
    提示
    更频繁的监督训练能让模型追上对手最新策略，但每步计算量增加 5 倍。看日志里"最近 512 条"数据的 MSE 是否更贴合当前分布，过时数据是 MSE 居高不下的主因之一。
  3. 给对手模型加一个"预测对手下一步位置"的辅助任务（多一个头，回归 next_opp_obs 里的对手位置）。它能否换来更低的动作预测 MSE？★★
    提示
    在 OpponentModel 加第二个输出头，在 train_opp_model 里对 next_opp_obs 的位置部分做 MSE，总损失是两项之和。这是"多任务辅助监督"，动作预测通常是受益方。
  4. 把 off 模式的评论家输入改成拼接"对手观测"（opp_obs），先从信息量角度分析它和 pred 的本质区别，再改代码验证。★★
    提示
    预测动作相当于让独立的小模型学"对手观测→动作"，直接拼观测则把这份映射工作扔给评论家，还引入了本步与未来的信息泄漏问题（未来的 opp_obs 在 Bellman 目标里同样缺失）。
  5. 把追者的速度限幅改成比逃者快 15%（给 PursuitEvaderEnv.step 加一个按智能体下标的限幅数组），先预测平衡被打破后"对手建模增益"会变大还是变小，再实跑验证。★★★
    提示
    最省事的改法：加 self.v_max_agent = np.array([v_max*1.15, v_max])，clip 时按行广播。思考方向：追者优势越大，"预测对手动向"的边际价值是升高（赢得更轻松）还是降低（已经随便赢）？用 off / pred 两条曲线的间距说话。

小结

  • 多智能体博弈的非平稳性来自"对手策略在变"，独立 SAC 的评论家本质上是在追一个移动的 Q 目标。
  • 对手建模的最简形式是监督回归：从对手观测预测对手动作；评论家输入拼接该预测（detach），执行阶段也能用。
  • 三种模式构成清晰的信息阶梯：off 基线、pred 可部署、true 训练期上界，共享同一套训练代码。
  • 实现上两处硬细节：预测动作必须 detach；Bellman 目标里"下一状态的对手动作"要按回合边界正确回填（pending_idx）。
  • 下一章把博弈结构变得更复杂：同一批智能体里既有组内合作也有组间竞争（混合任务），用团队内共享回报 + 团队间对抗来检验多智能体 SAC 的表现。
