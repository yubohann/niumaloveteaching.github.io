第一篇 · 策略梯度与 PPO

第 023 章：PPO的探索策略：熵正则化与噪声结合

把"目标函数里的熵奖励"与"行为层的外加噪声"放进一张 2×3 网格做对照：两种探索燃料谁留下持久底线、谁只在早期起作用、叠加使用会不会过度探索。

  • 主题：探索机制 / 熵正则化与动作噪声的协同
  • 关键公式：L = −LCLIP + cvf·𝔼[(V−R)2] − cent·H(πθ)
  • 预计学时：60 分钟
  • 前置章节：第 022 章

学习目标

  • 从梯度角度理解熵奖励如何在策略变尖的过程中形成"熵底线"。
  • 实现熵系数 × 噪声模式的 2×3 网格实验，在完全相同的数据管道上扫描 6 个配置。
  • 掌握"末段熵"与"末段偏离率"两个过程指标，区分目标函数层的探索与行为层的外加探索。
  • 理解两种探索的互补关系与叠加风险，能用它解释训练回报与贪婪评估回报的背离。
  • 完成 CartPole-v1 上的网格实验并给出可复述的结论。

背景与动机

第 022 章验证了动作噪声"把探索撒在动作上"，但噪声一旦退火就什么都不剩；而熵正则化（entropy regularization）从第 005 章起一直是 PPO 的标配项，它在总损失里加一份"保持随机性"的奖励，持续性完全不同。如果把两者看成探索的两种燃料，至少有三个工程问题要回答：噪声能不能替代熵奖励？两者叠加是双保险还是双浪费？一个配置"训练回报低"，到底是被探索拖的，还是策略真的差？

本章用一个 2×3 网格系统回答：熵系数取 {0, 0.01, 0.05}，噪声取 {无, logits 噪声退火}，六格同种子同预算。CartPole 本身足够简单，因此结论不靠"谁分数高"来定，而靠末段熵、末段偏离率、覆盖桶这些稳定可见的过程量。

核心原理

1. 熵奖励为什么形成"底线"

PPO 的总损失含一项熵奖励（H 越大越好）：

L = −LCLIP + cvf · 𝔼[(V−R)2] − cent · H(πθ(·|s))
H(π) = −Σa π(a|s) log π(a|s)，  两动作时上限为 ln 2 ≈ 0.693

其中 cent 是熵系数，控制"鼓励随机"的力度。策略项想把好动作概率推向 1（熵自然下降），熵项以 cent 的力度把分布往均匀推（熵上升）。两者在训练后期达到平衡：策略越接近确定，熵项的反拉越明显，因此熵不会轻易掉到 0，会停在一个由 cent 决定的水平，这就是"熵底线"。cent=0 时没有这个对抗力，熵一路下滑，策略会收敛成几乎确定性的动作选择。

把熵的两种读法都算出来，日志才好解释。两动作策略的熵由首选概率 p 唯一决定：p=0.5 → H=0.693（均匀）、0.7 → 0.611、0.8 → 0.500、0.9 → 0.325、0.95 → 0.199、0.99 → 0.056。于是"末段熵 0.2"就是"以 95% 概率选同一动作"，与第 022 章偏离率 0.05 的读数严丝合缝；"末段熵 0.6"对应约 70% 的首选率，训练回报被稀释的原因就落在这一行。再看熵项的反拉力度：|dH/dz| = p(1−p)|ln((1−p)/p)|，从 p=0.5 处的 0 上升，在 p≈0.83 附近达到峰值约 0.224，之后随 p→1 回落。"越尖拉得越狠"只在中等尖锐区间成立：推向 0.99 后熵项几乎拉不动；底线的维持靠平衡点落在峰值左侧，熵项救不回已经坍缩的策略。

2. 两种探索的作用层次不同

把数据来源写成行为分布 μ，两种探索改变 μ 的方式完全不同：

熵奖励：θ 本身变了 → μ = πθ′（新策略自带更高的熵）
动作噪声：logits′ = logitsθ + σt·ξ → μ 偏离 πθ，但 θ 不变

熵奖励是把策略改造得更随机，随机性写在参数里、跟着策略走，更新目标本身就偏好高熵解；动作噪声是在采样瞬间制造偏离，与参数无关、可以随时关掉。于是就有了本章要验证的两个推论：噪声退火到 0 后不留残留（末段偏离率回落），熵系数则留下与 cent 同向的持久底线（末段熵被抬高）。

工程上可以把熵奖励理解成"软性的可学习温度"：给 softmax 除以温度 τ 会同时改变尖锐度与熵，熵奖励做的方向与降温相反，而且逐状态自适应。若改成"钉住一个目标熵"（练习 4 的 H*=0.35），两动作下由 H(p)=0.35 解出首选概率约 89%，自动温度会把这个水平锁住；固定的 cent 做不到"钉住"，它只提供与系数同向的软约束，实际底线会随任务与优势尺度漂移。这也是 SAC 采用自动温度的原因（第 032 章会展开）。

手段作用位置持久性对价值函数调度方式
参数噪声（021）权重由 σ 自适应决定数据来自扰动策略，价值跟随行为分布KL 自适应
动作噪声（022）采样瞬间退火后归零偏差随噪声关闭而消失线性退火
熵奖励（023）目标函数持久底线策略本身更随机，价值拟合的就是它常数系数

3. 叠加风险：探索不是越多越好

探索的代价体现在两处。其一，训练回报被采样噪声稀释：策略熵 0.6 时，规定动作有很大概率被换成别的动作，滑窗回报自然低于贪婪水平；其二，价值学习被污染：价值网络在拟合"带噪行为"的回报，优势估计的偏差变大。所以过度组合（高 cent + 高 σ）会在网格里表现为"覆盖桶最高、首达目标最慢"。反过来，低 cent + 早期噪声是一种错峰配置：用噪声买早期覆盖面，用低熵系数买后期锐度。

叠加的幅度可以用带噪 softmax 模型粗算（logits 差 d、噪声 σ=1，偏离率定义为执行动作不等于原首选的频率）：尖策略（p=0.95，d≈2.94）单开噪声约 0.09；软策略（cent=0.05 对应的 p≈0.7，d≈0.85）不开噪声约 0.30，叠加噪声后升到约 0.35（噪声差服从 N(0,2)，蒙特卡洛复核）；完全干净的尖策略只约 0.05。两股随机性同时打开时，偏离率处在所有配置的最高档，价值网络同时要拟合带噪回报，这就是"高 cent + 不退火噪声"组合在网格里最慢的机制。需要说明一点：模型假设策略概率 p 固定、噪声差独立同分布；实际训练中策略会随噪声一并演化，绝对读数可能小幅出入，但"两股随机性叠加把偏离率推到最高档"的排序不变。

"错峰配置"为什么划算，用网格数字说清：噪声格在前 3.6 万步（60% 预算）里把覆盖桶推高 15%～30%，这些新状态恰好在策略最不成熟时进入训练分布；退火结束后末段偏离率只比无噪声格高 0.02～0.03，收敛几乎不受影响。熵底线则是"全天候"的：它把末段偏离率抬到 0.3 量级，连收敛期也在稀释训练回报。同样是探索投入，"阶段性买覆盖、持续性买锐度"的账在 CartPole 上更容易算正；反过来，任务奖励稀疏、早期几乎没有梯度信号时，阶段性的覆盖买不到有效学习，这时才轮到熵底线出场（练习 5 的检验点）。

4. 网格与度量

6 个配置共享同一套网络、GAE、裁剪损失与评估协议，唯一变量是 (cent, noise)。每个配置记录：首达 475 滑窗门槛的步数、末段训练回报（后 100 回合均值）、贪婪评估回报、末段熵（最后 5 次更新的均值）、末段偏离率（最后 5 次 rollout 的均值）、累计覆盖桶。末段熵与末段偏离率是本章的"显影液"：早期所有配置都靠高熵/高噪声起步，差别只在后段才显影。

末段熵读数的可信度先算一笔：单步熵落在 [0, ln2] 区间，按最保守的波动上界 ln2/2≈0.347 估计，2048 步小批量的均值标准误约 0.008；再对 5 次更新取平均，标准误降到约 0.003。换算成结论口径：汇总表里相差 0.01 以上的末段熵是真实配置差异，0.005 以下的小差别不要当结论写。偏离率的同类换算更容易做：它以 2048 步为单位统计，单轮标准误最坏为 0.5/√2048≈0.011，末段 5 轮平均后约 0.005。

实现思路与设计

模块划分

组件职责与第 022 章的关系
run_config训练一个 (ent_coef, noise) 配置，记录过程指标新增：网格实验的最小单元
ppo_update裁剪损失 + 价值 + −cent·H；熵系数按配置传入改动：从 args 改成显式参数
sample_action标准采样 + 可选 logits 噪声；logp 始终来自干净策略沿用 022，去掉 ε-贪心臂
anneal_levelσ 线性退火；熵系数不随进度变化沿用
entropy_hist / dev_hist每次更新的熵、每次 rollout 的偏离率序列新增：末段指标的来源

关键超参数

参数默认值作用与取值理由
--ent-coefs0.0, 0.01, 0.05熵系数的三个档位：无 / 常用 / 强探索
--noisesnone,logitnoise无噪声 / σ 从 1.0 退火到 0 的 logits 噪声
--sigma-start / --sigma-end1.0 / 0.0与第 022 章相同的强探索起点、干净收敛终点
--anneal-frac0.6前 60% 预算退火，后 40% 留给确定性收敛
--max-steps60000（每格）6 格总预算约 36 万步，CPU 可承受
steps_per_update / epochs2048 / 10与前两章一致，保证差异只来自探索配置

数据流

外层双循环遍历 ent_coefs × noises，每个组合调用一次 run_config。配置内每个更新周期：按进度算 σ（熵系数是常数，不随进度变）→ 采样 2048 步并按 logits 噪声决定行为 → PPO 更新时把 ent_coef 显式传进损失 → 把本轮的熵与偏离率追加进历史序列 → 达标早停。结束后做贪婪评估，取最后 5 项历史算出末段熵与末段偏离率，保存模型并打印汇总表。

与第 022 章的差异点

  • 从"选臂"到"网格"：022 比三种噪声方案；本章固定噪声为 logitnoise，与熵系数交叉成 6 格。
  • 熵系数成为自变量：ppo_update 显式接收 ent_coef，扫描时不再依赖全局参数。
  • 过程指标升级：新增"末段熵"（更新日志的熵序列）与"末段偏离率"（rollout 统计），用它们回答"探索残留多少"。
  • 结论口径不同：022 看探索行为的广度；本章看两种机制的持久性与叠加效应。
公平对比的两个前提

其一，每格开头都 set_seed(args.seed)，让 6 格从同一个初始网络、同一条环境轨迹出发，否则配置间的差异会被初始条件的运气掩盖。其二，ent_coef=0 时损失里熵项直接消失，但代码路径与其他格完全一致，保证网格对比不存在实现层面的偏差。

关键代码与解读

片段 1：熵项落在哪一行

    for _ in range(args.epochs):
        idx = torch.randperm(N, device=obs.device)
        for start in range(0, N, args.batch_size):
            mb = idx[start:start + args.batch_size]
            logits, value = net(obs[mb])
            dist = Categorical(logits=logits)
            logp = dist.log_prob(act[mb])

            ratio = torch.exp(logp - logp_old[mb])   # 与 001 章完全相同的比率
            surr1 = ratio * adv[mb]
            surr2 = torch.clamp(ratio, 1.0 - args.clip, 1.0 + args.clip) * adv[mb]
            policy_loss = -torch.min(surr1, surr2).mean()

            value_loss = F.mse_loss(value, ret[mb])
            entropy = dist.entropy().mean()          # 当前策略的熵（可导！）

            # 总损失：策略 + 价值 − 熵奖励；ent_coef=0 时该项消失
            loss = policy_loss + args.vf_coef * value_loss - ent_coef * entropy

            optimizer.zero_grad()
            loss.backward()
            nn.utils.clip_grad_norm_(net.parameters(), 0.5)
            optimizer.step()

解读：整段与 001 章的 PPO 更新几乎一样，唯一的新变量是最后一行里的 ent_coef。（1）entropy = dist.entropy().mean() 取自当前小批量的策略分布，它是可导的，反传会同时调整 logits 的"平坦程度"，这正是熵底线的成因：策略项把概率推向 0/1，熵项把它们拉回中间，拉锯出的平衡点由 cent 决定。（2）符号是减号：− ent_coef * entropy，因为损失是"越小越好"，而熵是"越大越好"。写反成加号等于惩罚随机性，策略会迅速坍缩。（3）熵系数作为函数参数显式传入，让网格的每个格子用各自的系数、共享同一份代码。

熵项对 logits 的梯度有闭式，写出来更能看清它在做什么：∂H/∂za = −πa(ln πa + H)。对首选动作，πa 大而 ln πa 接近 0，括号内为正，梯度为负，效果是把首选动作的 logit 往下压；对次选动作括号内为负，梯度为正，效果是把它往上抬。整支梯度的尺度正是上一节算过的 |dH/dz|（两动作时 p=0.9 处约 0.198）。一行闭式把"熵奖励怎样对抗策略尖锐化"讲完了：它压头部、抬尾部，力度在中等尖锐区间最大。

还有一个容易踩的耦合：熵项加在总损失上，它与策略项的相对权重取决于优势的尺度。同一个 cent，换到奖励尺度大十倍的任务上，熵项的相对影响就小了十倍，探索会明显变弱。所以 cent 不是能跨任务照搬的超参：换环境时先检查优势是否标准化，再按"末段熵落在哪个档位"重新扫一遍系数。

片段 2：采样处的噪声是"临时扰动"

@torch.no_grad()
def sample_action(net, obs_t, noise_mode, sigma):
    """返回 (action, logp, value, greedy)。logp 始终来自干净策略。"""
    logits, value = net(obs_t)
    greedy = int(torch.argmax(logits, dim=-1).item())

    if noise_mode == "logitnoise" and sigma > 0.0:
        # 给 logits 加高斯抖动再采样：σ 控制"拍平"程度，退火后自然消失
        noisy_logits = logits + sigma * torch.randn_like(logits)
        action = Categorical(logits=noisy_logits).sample()
    else:
        # 无噪声配置（或 σ 已退火到 0）：标准 softmax 采样
        action = Categorical(logits=logits).sample()

    # 与 022 章同一条铁律：logp 用干净 logits 计算，噪声不改变比率基准
    logp = Categorical(logits=logits).log_prob(action)
    return int(action.item()), logp.item(), value.item(), greedy

解读：对比熵奖励"改参数"的路径，噪声路径完全不动网络：noisy_logits 只是采样时的临时副本，反传永远看不到它。（1）sigma > 0.0 这个守卫条件很关键，σ 退火到 0 后分支不再触发，行为与无噪声格完全一致，于是"噪声退火"在实现上等价于"把噪声关掉"，不会留下任何残余。（2）logp 依然从干净 logits 出发计算：噪声只决定动作怎么被选出来，不改变 PPO 比率的基准。这一行和 022 章完全一致，是两章共享的铁律。

片段 3：单格训练循环，两种探索的调度方式不同

    while total_steps < args.max_steps and solved_at is None:
        progress = total_steps / max(1, args.max_steps)
        # 噪声强度线性退火；熵系数是常数（它开在目标函数里，不随进度变化）
        sigma = anneal_level(progress, args.sigma_start, args.sigma_end, args.anneal_frac) \
            if noise_mode == "logitnoise" else 0.0

        batch, ep_returns, obs_t, deviate, cover_bins = collect_rollout(
            env, net, noise_mode, sigma, args.steps_per_update, obs_t, device,
            args.gamma, args.lam, n_actions)
        total_steps += args.steps_per_update
        all_returns.extend(ep_returns)
        cover_all |= cover_bins
        dev_hist.append(deviate)                 # 偏离率历史：末段偏离率的来源

        stats = ppo_update(net, optimizer, batch, args, ent_coef)
        entropy_hist.append(stats["entropy"])    # 熵历史：末段熵的来源
        update_idx += 1

        if solved_at is None and len(all_returns) >= 100 and \
                np.mean(all_returns[-100:]) >= args.target_reward:
            solved_at = total_steps

解读：循环体把两种探索的"调度逻辑"摆在一起，对比鲜明。（1）sigma 每轮按进度重算，它是时间的函数；ent_coef 从头到尾是常数，它是目标函数的固定偏置。这一行之差就是两种探索的本质差别。（2）dev_hist 与 entropy_hist 逐轮追加，训练结束后直接从尾部取均值得到末段指标，无需额外的统计框架。（3）早停条件（近 100 回合滑窗 ≥ 475）六格同一标准；由于强探索格的训练回报被稀释，它们往往需要更多步数才触发早停，这个"慢"本身就是本章要观察的结论之一。

    dev_last = float(np.mean(dev_hist[-k:])) if k else 0.0
    last100 = float(np.mean(all_returns[-100:])) if all_returns else 0.0

解读：为什么取"最后 5 项"？因为早期所有配置都靠高熵/高噪声起步，全程平均会把各格的差距抹平；后段才是两种探索机制显影的窗口。k = min(5, len(...)) 防的是快速模式或极短训练下切片越界；贪婪评估在这里还承担一个诊断作用，当某个高熵格的训练近 100 均值难看时，评估成绩却可能接近满分，这条分叉说明"训练回报低"和"策略差"是两回事。

python code/ch023.py --quick    # 快速跑通：40–80 秒，只验证流程
python code/ch023.py --ent-coefs 0.0,0.05 --noises none   # 只看熵系数的影响

以实跑为准：末段熵随 cent 单调抬升（0 档约 0.2，0.05 档约 0.55～0.65）；噪声退火后不留底噪（同熵档下末段偏离率只比无噪声格高 0.02～0.03，但覆盖桶多 15%～30%）；cent=0.05 的行首达步数普遍慢 1 万～2 万步，训练近 100 均偏低，而贪婪评估仍能到 475 以上。六格的读数预期可以整理成一张速查表：

常见坑

  • 熵项符号写反：总损失里熵必须是减号（− ent_coef * entropy）。写成加号等于惩罚随机性，策略迅速坍缩成确定性输出，且非常难恢复。
  • 把"训练回报低"当成"策略差"：高熵配置的采样行为包含大量随机动作，训练滑窗天然偏低；判断策略能力要看贪婪评估。汇报实验时两条线都要给。
  • 网格实验忘记重置种子：若 6 格不共享初始条件，配置间差异可能被初始网络/初始轨迹的运气盖过。每个配置开头都要 set_seed(seed)。
  • 熵与噪声同时调到最大还不退火：策略被"双重探索"锁住，KL 与裁剪比例长期偏高、价值损失下不去，跑再久也不会收敛。至少让一个探索源头可退火。
  • 用全程平均熵汇报"熵底线"：早期熵都被初始化的近均匀分布拉高，全程平均看不出配置差别。末段窗口（最后 5 次）才有区分度。

练习与思考

  1. 单独跑 --ent-coefs 0.0 --noises none，观察末段熵能掉到多低；再换成 0.1 跑一次，解释为什么过大的熵奖励会让训练回报常年停留在低位。★
    提示
    看汇总表"末段熵"一列。c_ent=0.1 时熵会稳定在 0.65 以上（接近均匀），训练近 100 均很难超过 400，但评估（argmax）仍可能不错。
  2. 比较 ent=0.05,none 与 ent=0.0,logitnoise 两格：谁首达更快、谁覆盖更广、谁的评估更高？用"持续性 vs 阶段性"解释差异。★
    提示
    把两行的四列放在一起读：末段偏离率、覆盖桶、首达步数、评估均。噪声格通常覆盖更广且收敛不慢，熵格则相反。
  3. 给噪声加上"双段退火"：前 30% 预算保持 σ=1.0 不退火，后 30% 线性降到 0，最后 40% 保持 0。对比线性退火，观察覆盖桶与首达步数的变化。★★
    提示
    改 anneal_level 的调用方式或写一个新的分段函数，在 run_config 里替换。重点是"先探索、后收敛"的节奏是否比匀速退火更有效。
  4. 实现"自适应熵系数"：把 cent 变成可学习的 log α（类似自动温度），损失为 −log α·(E[log π] + Htarget)，目标熵取 0.35，观察末段熵是否稳定在目标附近。★★
    提示
    在 run_config 里额外建 alpha = torch.tensor([0.01], requires_grad=True) 并加入优化器；每次更新用熵的统计量调整它（无需网络反传）。注意把 α 下界设为 1e-4 防止归零。
  5. 把整张网格搬到 MountainCar-v0（稀疏奖励）重跑每格 6 万步：统计各格的成功率与"首次成功所需步数"，检验"熵底线在稀疏任务里更重要"这一假设。★★★
    提示
    只需改环境名与成功判定（MountainCar 的 terminated=True 表示到达山顶），并把 --target-reward 调成 −110 左右。CartPole 的覆盖范围常量不适用，可以先退回只统计偏离率与回报。

小结

  • 熵奖励作用在目标函数上，训练出一个与 cent 同向的"熵底线"；动作噪声作用在采样瞬间，退火后不留残留。
  • 2×3 网格的稳定观察：末段熵随 cent 单调抬升；同熵档下噪声格覆盖多 15%～30%，但末段偏离率只略高。
  • 过度探索的直接代价是首达步数变慢与训练回报被稀释，但贪婪评估可能仍然接近满分。
  • 工程配方：稠密奖励用"低熵系数 + 退火噪声"；稀疏奖励用"小熵底线 + 早期强噪声"。
