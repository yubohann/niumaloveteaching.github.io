第四篇 · 多智能体强化学习

第 080 章：多智能体SAC：角色对称

槽位顺序是人为约定，好策略不该在乎它。本章把"置换不变"写进共享 SAC 的结构里，并在训练结束后用置换探针实测：打乱观测顺序，动作会漂多少？

  • 主题：置换对称性 / 集合编码器（SAC 版）
  • 关键公式：π(πperm·o) = π(o) 且 Q(πperm·o, a) = Q(o, a)；探针偏差 = |π(o) − π(πperm·o)|1/dim(A)
  • 预计学时：50 分钟
  • 前置章节：第 079 章

学习目标

  • 在 off-policy 框架里理解置换对称性：策略与 Q 的输入都包含集合（地标、队友），顺序不应影响输出。
  • 实现 Deep Sets 风格的对称编码器，并把它同时接到策略与双 Q 上，保证整套价值估计也是置换不变的。
  • 掌握"置换探针"：固定物理状态、只打乱槽位，直接测量输出偏差，用数字证明不变性。
  • 对比"结构不变"与"数据学习不变"的训练效率差异。
  • 把第 072 章（PPO 版）的结论迁移到 SAC 版，并观察两者证据的一致性。

背景与动机

第 072 章让 PPO 环境每回合洗牌观测槽位，验证了"对称结构学得更快"。这个思想与算法家族无关：只要输入里包含集合（多个地标、多个队友），就存在"顺序敏感"的伪特征风险。SAC 版本有一个额外的细节：不仅策略要对称，Q 网络也要对称。如果 Q 对槽位顺序敏感、而策略不变，那么同一个物理状态下 Q 值会随"队友列表顺序"抖动，价值目标与策略梯度都会变噪。本章的实验把二者一起处理：同一风格的编码器分别接到策略与 Q（以及目标 Q）上。

本章还多了一个上一章没有的东西：置换探针。训练曲线只能告诉你"谁学得快"，探针能直接回答"到底变没变"。方法很朴素：取一个状态，把它观测里的地标与队友槽位随机重排，分别喂给策略，比较输出动作。结构对称的策略偏差应为 0；普通 MLP 会有可见偏差。

核心原理

1. 置换不变性的两个作用点

策略：π(πperm · oi) = π(oi)，   价值：Q(πperm · oi, ai) = Q(oi, ai) πperm 表示任意重排地标/队友槽位；两式同时成立，价值估计才不随顺序抖动

对称编码器的构造是"先编码、后池化"：

hland = (1/N) Σl ψ(ll − pi)，  hother = (1/(N−1)) Σj≠i φ(pj − pi)，  h = [hown, hland, hother] ll 是第 l 个地标位置；p 是智能体位置；ψ、φ 是两个共享编码器（同类元素共用）。均值池化对顺序不敏感，因此任意置换都不改变 h

集合元素的编码器共享权重（ψ、φ 各一个），池化用均值，这两条保证任意置换都不改变 h。Q 网络只需在 h 后面接上自己的动作 ai，不变性自动继承：编码器对称 → 下游任何头都对称。这也是为什么实现里 Q 的编码器必须换成正版的 SymmetricEncoder，只改策略不改 Q 是半吊子工程。

2. 置换探针的定义

偏差 = | π(o) − π(πperm·o) |1 / dim(A) 对多个状态与多种置换取平均与最大值；探针只重排槽位，不改变物理状态本身，重排后的输入描述的是同一个世界

注意"只重排槽位"这一点：如果把队友位置也换掉（真的把两个队友对调），那是不同的物理状态，偏差不一定为 0。探针测的是"网络对描述顺序的敏感度"，因此严格的实验控制是必须的：同一个物理状态、只动描述的排列。脚本里对每个状态跑 n_perms=10 次随机置换，报告平均与最大偏差。

3. 数据学会的对称性可靠吗

普通 MLP 在洗牌数据上也能把偏差压小，它每次看到不同顺序，被数据逼着学出近似对称。但"近似"的代价是：① 需要更多样本；② 对称性是统计意义上的，长尾状态（比如两个队友恰好对称的位形）仍可能露馅；③ 每换一批数据分布就要重新"说服"它。结构对称则一步到位，代价是表达能力受限（若顺序真有意义，比如"一号队友是队长"，池化就会丢信息）。第 072 章在 PPO 上给出的结论，收益主要在早期窗口、最终可能趋同，本章在 SAC + off-policy 的设定下做交叉验证。

实现思路与设计

模块划分

数据流

训练：共享 SAC 的采样/存储/更新与第 078 章一致；只有编码器风格在变（策略、Q、目标 Q 三处同步换）。训练结束后：跑 200 步收集状态 → 随机抽 100 个 → 每个状态做 10 次随机槽位置换 → 比较策略输出的平均/最大偏差。

与第 072 章、第 079 章的差异点

相对第 072 章（PPO 版）：对称编码器接到 SAC 的策略与双 Q 上，配套替换目标 Q；对称性同时约束动作与价值。相对第 079 章：去掉消息通道，回到观测结构本身。训练流程与共享 SAC 一致，单变量对照干净。

关键代码与解读

片段 1：两种编码器并排看

class NaiveEncoder(nn.Module):
    def __init__(self, obs_dim, hidden=64):
        super().__init__()
        self.net = nn.Sequential(nn.Linear(obs_dim, hidden), nn.Tanh(),
                                 nn.Linear(hidden, hidden), nn.Tanh())

    def forward(self, obs):
        return self.net(obs)


class SymmetricEncoder(nn.Module):
    """置换不变编码器：自身向量单独编码，地标/队友集合分别均值池化。"""

    def __init__(self, n_agents, hidden=64):
        super().__init__()
        self.n = n_agents
        self.own_enc = nn.Sequential(nn.Linear(4, hidden), nn.Tanh(),
                                     nn.Linear(hidden, hidden), nn.Tanh())
        self.land_enc = nn.Sequential(nn.Linear(2, hidden), nn.Tanh(),
                                      nn.Linear(hidden, hidden), nn.Tanh())
        self.other_enc = nn.Sequential(nn.Linear(2, hidden), nn.Tanh(),
                                       nn.Linear(hidden, hidden), nn.Tanh())
        self.trunk = nn.Sequential(nn.Linear(3 * hidden, hidden), nn.Tanh(),
                                   nn.Linear(hidden, hidden), nn.Tanh())

    def forward(self, obs):
        own = obs[:, :4]
        land = obs[:, 4:4 + 2 * self.n].reshape(-1, self.n, 2)
        other = obs[:, 4 + 2 * self.n:].reshape(-1, self.n - 1, 2)
        h_own = self.own_enc(own)
        h_land = self.land_enc(land).mean(dim=1)      # 对地标集合均值池化
        h_other = self.other_enc(other).mean(dim=1)   # 对队友集合均值池化
        return self.trunk(torch.cat([h_own, h_land, h_other], dim=-1))

解读：两个编码器的输出都是 hidden 维、接口完全一致，因此可以插到同一套策略/Q 头上，这是"可插拔"设计的关键。（1）NaiveEncoder 的第一层对每个槽位有独立权重，顺序敏感；SymmetricEncoder 把输入切成 own(4)/land(N×2)/other((N−1)×2) 三块，集合元素通过 reshape 还原成"每个元素一行"。（2）land_enc(land) 输入 (B, N, 2)，输出 (B, N, hidden)：同一个编码器对所有地标逐元素处理（广播语义），.mean(dim=1) 把集合压缩成 (B, hidden)。（3）三类编码器不共享参数（输入的语义不同），但同一类内所有元素共享一个编码器，这正是 Deep Sets 要求的"逐元素同函数"。（4）trunk 把三块拼成 3×hidden 再融合；池化后集合大小信息丢失，对固定 N=3 的任务无碍。

片段 2：把对称性延伸到 Q 网络

class EncoderTwinQ(nn.Module):
    def __init__(self, encoder, act_dim, hidden=64):
        super().__init__()
        self.encoder = encoder          # 传入哪一种编码器，Q 就是指哪种对称性

        def make():
            return nn.Sequential(nn.Linear(hidden + act_dim, hidden), nn.ReLU(),
                                 nn.Linear(hidden, hidden), nn.ReLU(),
                                 nn.Linear(hidden, 1))
        self.q1, self.q2 = make(), make()

    def forward(self, obs, act):
        h = self.encoder(obs)                       # 集合池化发生在这里
        x = torch.cat([h, act], dim=-1)             # 动作是"自己的"，不参与池化
        return self.q1(x), self.q2(x)

解读：Q 的"对称化"只做了一件事，把编码器换成可传入的模块。（1）编码器作为构造参数替你决定对称性：传 SymmetricEncoder 则 Q 对槽位不变；传 NaiveEncoder 则由数据学习。Q 头本身完全不关心输入是怎么编码的。（2）动作 act 在池化之后拼接：ai 是智能体 i 自己的动作，不属于任何集合，不参与均值池化，这一步顺序不能反。（3）Q 网络拥有自己的编码器实例（不是从策略借用的）：策略编码器与 Q 编码器分别训练、参数独立，否则两个目标的梯度会互相污染。（4）目标 Q 的编码器又各自独立（见片段 4），软更新只搬参数不共享对象，这是第 078 章"目标网络用独立实例"惯例的自然延伸。

片段 3：置换探针，把"不变"变成数字

def permute_obs_row(row, n_agents, rng):
    """打乱单个智能体观测里的地标槽位与队友槽位顺序。"""
    head = row[:4]
    land = row[4:4 + 2 * n_agents].reshape(n_agents, 2)
    other = row[4 + 2 * n_agents:].reshape(n_agents - 1, 2)
    land_p = land[rng.permutation(n_agents)].ravel()
    other_p = other[rng.permutation(n_agents - 1)].ravel()
    return np.concatenate([head, land_p, other_p]).astype(np.float32)


@torch.no_grad()
def permutation_probe(env, policy, device, n_states=100, n_perms=10, seed=0):
    """对同一状态施加随机槽位置换，测量策略输出的最大与平均偏差。"""
    rng = np.random.RandomState(seed)
    obs = env.reset()
    states = []
    for _ in range(200):                              # 先随机走 200 步收集状态
        states.append(obs.copy())
        actions = rng.uniform(-1.0, 1.0, (env.n_agents, env.act_dim)).astype(np.float32)
        obs, _, _, done, _ = env.step(actions)
        if done:
            obs = env.reset()
    states = [states[i] for i in rng.choice(len(states), size=n_states, replace=False)]

    max_dev, mean_dev = 0.0, 0.0
    for state in states:
        base = policy.mean_action(torch.as_tensor(
            state, dtype=torch.float32, device=device)).cpu().numpy()
        for _ in range(n_perms):
            perm_state = np.stack([permute_obs_row(state[i], env.n_agents, rng)
                                   for i in range(env.n_agents)])
            out = policy.mean_action(torch.as_tensor(
                perm_state, dtype=torch.float32, device=device)).cpu().numpy()
            dev = float(np.abs(out - base).mean())    # 同一物理状态、两种描述的差异
            max_dev = max(max_dev, dev)
            mean_dev += dev
    mean_dev /= (len(states) * n_perms)
    return mean_dev, max_dev

解读：探针的全部逻辑就是"控制变量 + 重复测量"。（1）permute_obs_row 只接受"一行观测"：切开头部（自身 4 维不动）、地标块、队友块，分别用随机重排打乱，排的是描述顺序，物理状态原封不动。（2）收集 200 个训练分布内的状态再随机抽 100 个：探针要在"策略实际会遇到的状态"上测，否则测的可能是它从没见过的区域，偏差没有代表性。（3）base 是原始顺序的输出，每次置换记一个 dev = |out − base|.mean()：平均绝对偏差（L1），按动作维度归一。（4）同时报告 max_dev 与 mean_dev：均值说明总体敏感度，最大值暴露长尾，naive 编码器经常是"平均还行、个别状态崩掉"，最大值能抓住这种隐患。

片段 4：把编码器插进学习器

class SharedLearner:
    def __init__(self, obs_dim, act_dim, n_agents, args, device, encoder_type):
        if encoder_type == "sym":
            encoder_p = SymmetricEncoder(n_agents, args.hidden)    # 策略编码器
            encoder_q = SymmetricEncoder(n_agents, args.hidden)    # 在线 Q 编码器
            encoder_q_t = SymmetricEncoder(n_agents, args.hidden)  # 目标 Q 编码器
        else:
            encoder_p = NaiveEncoder(obs_dim, args.hidden)
            encoder_q = NaiveEncoder(obs_dim, args.hidden)
            encoder_q_t = NaiveEncoder(obs_dim, args.hidden)
        self.policy = EncoderPolicy(encoder_p, act_dim, args.hidden).to(device)
        self.q = EncoderTwinQ(encoder_q, act_dim, args.hidden).to(device)
        # 目标网络使用独立的编码器实例，避免与在线网络共享参数导致软更新互相干扰
        self.q_target = EncoderTwinQ(encoder_q_t, act_dim, args.hidden).to(device)
        self.q_target.load_state_dict(self.q.state_dict())

解读：四个编码器实例（策略 1、Q 1、目标 Q 1，加上 Q 里的 q1/q2 头部）构成完整配置。（1）三处编码器风格必须一致：只把策略换成 sym、Q 保持 naive，会出现"策略对顺序不变、价值对顺序敏感"的错配，优势估计继续抖动，这是最隐蔽的半吊子改法。（2）每个编码器都是独立实例：策略与 Q 的编码器不共享参数（它们的学习目标不同）；目标 Q 的编码器独立于在线 Q（软更新对象独立）。（3）load_state_dict 只做初始拷贝，之后软更新逐步同步，独立实例 + 参数拷贝，惯例与第 078 章一致。（4）切换编码器的代码路径只有这个 if/else：训练、采样、评估全都不感知编码器种类，对照实验"只动一个变量"在代码层面成立。

常见坑

  • 只对称策略、不对称 Q：价值随槽位抖动，优势信号变噪，训练表现反而可能不如全 naive。三处编码器（策略、Q、目标 Q）必须同步。
  • 池化顺序放错：动作必须在池化后拼接，自己与集合的归位不能混淆；把 act 提前拼进集合做池化会把"自己的动作"当成集合元素平均掉。
  • 探针改变了物理状态：探针只应重排槽位；若顺手把队友位置换了、或旋转了坐标，测出来的偏差没有意义。
  • 评估环境没开洗牌：训练洗、评估不洗时，naive 的成绩会被"固定顺序"的评估集抬高，sym 的优势被掩盖。两个环境按同一开关设置。
  • 拿均值偏差下结论：naive 的均值可能不大，但最大偏差（长尾）才是安全隐患，报告两个数字。

练习与思考

  1. 跑完两种编码器，读取探针输出：sym 的偏差是多少？naive 是多少？为什么 sym 不是"严格的 0.0"？★
    提示
    浮点运算次序不同（求和顺序变了）会带来 1e-7 级的误差；这就是"浮点误差级"的含义。
  2. 把 --no-shuffle 打开重跑，比较两种编码器的曲线差距。解释"干扰源消失"后结论怎么变。★
    提示
    槽位固定时 naive 无需对抗顺序变化，差距通常缩小；这说明 sym 的收益来自"顺序在变"这一事实要求。
  3. 把均值池化换成求和与最大值，三者都保持不变性，比较训练与探针结果。哪种池化更适合"最近的地标"这类任务？★★
    提示
    max 强调最显著元素（如最近地标），可能更契合导航；sum/mean 在数量固定时只差常数缩放。探针的偏差都应是浮点级。
  4. 把探针从策略扩展到 Q 网络：对同一 (o, a) 置换槽位后比较 Q 值。naive 与 sym 的差距是否比策略端更大？★★
    提示
    Q 的输入还多了动作拼接，槽位敏感会直接污染价值回归目标；预期 naive 的 Q 偏差更明显。需要写一个针对 Q 的小探针函数。
  5. 设计"部分对称"任务：让一个地标是"特殊目标"（奖励加倍），使顺序中包含真实信息，再比较 naive 与 sym。结构先验何时变成伤害？★★★
    提示
    改动 _min_matching_distance 给特定索引的地标加权。此时"谁排第一"有意义，池化会丢掉它，需要条件编码（把特殊标记作为额外输入）才能两全。

小结

  • 对称性在 SAC 里要贯穿两层：策略置换不变 + Q（含目标 Q）置换不变，缺一不可。
  • Deep Sets 编码器：own/land/other 分块编码 + 集合均值池化；同一类元素共享编码器，池化保证顺序无关。
  • 实现要点：编码器可插拔、三处实例独立、参数量对齐；切换只发生在学习器构造处。
  • 置换探针把"不变性"变成数字：固定物理状态、只重排槽位，报告平均与最大偏差；sym 应为浮点级，naive 可见。
