第五篇 · 多智能体环境与实践

第 089 章：多智能体环境：足球

搭一个 2v2 简化足球场：球有独立物理，A 队两名球员用参数共享的独立 PPO 学习，B 队由"绕后推进 + 留守补位"的脚本策略驱动，看学习方能否把对脚本对手的胜率从随机基线的接近 0 抬到 0.5 附近。

  • 主题：环境设计 / 连续球类对抗与三层奖励
  • 关键公式：r = −0.005 − 0.05·‖球−对方门‖ + 0.03·𝟙[控球] + 5·𝟙[进球] − 5·𝟙[失球]
  • 预计学时：60 分钟
  • 前置章节：第 088 章

学习目标

  • 掌握一套最小的球类运动物理：球的速度惯性、球员接触时的动量传递、边界反弹与门线判定的区分处理。
  • 理解"学习队 vs 脚本队"的对抗评测协议：随机基线、胜/平/负、控球率、场均进球。
  • 用参数共享的独立 PPO 训练一支 2 人球队，观察同队球员如何自发形成"一人带球、一人接应"的行为。
  • 设计把球"推"向目标的团队奖励：推进塑形、控球奖励与进球大奖励的三层结构。
  • 识别攻防转换的难点：奖励塑形在防守端几乎无引导，失球只能靠 −5 的教训缓慢学到。

背景与动机

球类任务是多智能体环境里"连续性 + 对抗性 + 事件稀疏性"三重属性的集合体：球员和球都是连续动力学，攻防随球权实时切换，而得分是稀疏事件。它与捕食者-猎物最大的不同是有一个可操控的共享物体（球），智能体的动作不再只影响自己与对手，还会通过球间接影响全局：一次触球可能同时改变双方的计划。

本章选 2v2：两人制保留了足球的全部核心结构（推进、传球、射门、补位），训练预算压到 4 万步；11v11 的战术自由度远超这个预算。对手用脚本策略，让"学习方是否变强"有稳定参照物。你会发现，即便规则如此简单，学到的策略也会表现出可辨识的战术：边路带球、门前补射、回追护门，这就是环境结构塑造行为的最好例证。

核心原理

1. 球物理：惯性 + 接触传递

球比球员"更自由"：球员有动作加速度，球只受摩擦与接触影响：

vballt+1 = clip( 0.96·vballt + Σi∈接触 [ 0.6·vi + 0.1·ûi→ball ], −1.3, 1.3 )
pballt+1 = pballt + vballt+1

符号：vi 是接触球员的速度、ûi→ball 是从球员指向球的单位向量、Σ 对所有距离小于 0.16 的球员求和。两段构成：0.6·vi 把球员动量传给球（跑向球就自然推球），0.1·û 是径向冲量（防止球黏在球员身上）。这样"带球"就是反复轻触：球被推出去、摩擦减速、你再追上，主观手感很像真实足球。

2. 边界与球门的两套处理

球出边线是反射（速度反向并衰减 0.5），而球越过门线且在 ±0.35 半宽内是进球。两者必须先判门、再判反弹：如果先做边界钳制，球永远进不了门，训练日志会显示进球率恒为 0 而塑形分照涨。这是球类环境最经典的顺序错误，代码里用 if x > field_x 的嵌套分支显式区分。

3. 三层奖励结构

rt = −0.005 − 0.05·‖pball − goalopp‖ + 0.03·𝟙[控球] + 5·𝟙[进球] − 5·𝟙[失球]

第一层 −0.005 是时间成本，压节奏；第二层 −0.05·距离把球持续往对方球门赶，全场最远距离约 2.9（球在己方底线角落），对应最重罚 −0.15；第三层 +0.03 控球奖励鼓励靠近球（否则最优策略是"站门前等球"）；最后的 ±5 大奖励决定胜负。注意防守没有塑形项：把球踢远、守住门这些行为只能通过失球时的 −5 学到，这是本章的难点之一，也是练习里让你补的一项。

4. 脚本对手的分工

B 队的 2 号球员绕到"球的后方"（相对 B 的进攻方向）再向球门推进，一个位置控制器；3 号球员站在球与自家球门连线的 35% 处补位。两段策略没有学习，但形成了最基础的"一攻一守"，足以给学习方制造压力。actions = clip((目标 − 位置)×4, −1, 1) 是通用的 P 控制器写法：目标越远、动作越大，靠近后自然减速。

5. 控球率：比进球稠密得多的诊断量

控球率 = 回合内"至少一名 A 队球员与球距离小于控球半径"的步数占比。它在训练早期就会动，是判断"学习是否启动"的仪表：如果控球率不动而进球率动，多半是塑形项在起作用，策略并没有真的学会组织进攻。胜率 + 控球率两个数要搭配读，后面的"坑"一节会给出三种组合的诊断表。

与前一章的差异

第 088 章是离散网格、单点追击、稀疏捕获；本章升级为连续空间、共享物体（球）、带惯性的对抗，奖励从"两项"变成"三层 + 胜负事件"。算法虽然都是 PPO/价值型家族，但环境侧的工程量明显加大：球的物理、门线顺序、脚本行为，每个都可能成为"学不动"的根因。后面第 096 章自动驾驶会复用本章的"连续对抗 + 相对观测"模式。

为什么观测里放"对方球门中心"

18 维观测里最后两维是对方球门中心的相对位置。它不提供新信息（球门位置固定），但它让策略网络少学一步"从球的相对坐标反推球门方向"的几何运算，把环境的先验直接喂给网络，是加速收敛最便宜的手法。第 091 章无人机编队会用同样的套路放"编队中心"。

关键代码与解读

片段 1：18 维相对观测

def _obs(self) -> np.ndarray:
    obs = []
    opponent_goal = np.array([self.field_x, 0.0], dtype=np.float32)
    for i in range(self.n_learners):
        mate = 1 - i                                 # 队友编号：0 的队友是 1，反之亦然
        opps = [2, 3]
        o = np.concatenate([
            self.pos[i], self.vel[i],                # 自己
            self.pos[mate] - self.pos[i], self.vel[mate],   # 队友相对位置+队友速度
            self.ball_pos - self.pos[i], self.ball_vel,     # 球的相对位置+球速度
            self.pos[opps[0]] - self.pos[i],         # 对手 1 相对位置
            self.pos[opps[1]] - self.pos[i],         # 对手 2 相对位置
            opponent_goal - self.pos[i],             # 对方球门中心相对位置（先验）
        ])
        obs.append(o.astype(np.float32))
    return np.stack(obs)

解读：观测设计决定了策略能"看见"什么，也决定了参数共享是否成立。（1）除了自己位置，其余全部是相对量：队友、球、对手、球门，每个球员眼中的世界以自己为原点，两人共享一个网络才不会因输入分布不同而互相干扰。（2）球速 ball_vel 给的是绝对值：速度是向量，无论谁看都一样；相对化的是位置。（3）队友速度 vel[mate] 也入了观测，接应传球需要预判队友的移动方向，这个信息不可省。（4）最后两维"球门相对位置"是把几何先验直接喂给网络：球门固定，但让网络自己从球的位置反推方向需要额外的样本；显式给出省下的正是这部分学习成本。（5）维度账：4+4+4+4+2 = 18，与 obs_dim 一致。

片段 2：脚本对手，两行位置控制器撑起一支队伍

def _scripted_opponent(self) -> np.ndarray:
    """B 队脚本策略：2 号绕后推进，3 号留守在球与自家球门之间。"""
    target_goal = np.array([-self.field_x, 0.0], dtype=np.float32)  # B 队进攻目标
    own_goal = np.array([self.field_x, 0.0], dtype=np.float32)
    actions = np.zeros((2, 2), dtype=np.float32)

    # 2 号：站到"球的后方"（相对目标球门而言），朝球门方向推
    d = self.ball_pos - target_goal
    approach = self.ball_pos + d / (np.linalg.norm(d) + 1e-8) * 0.18
    actions[0] = np.clip((approach - self.pos[2]) * 4.0, -1.0, 1.0)

    # 3 号：占住球与自家球门连线的 35% 处
    guard = self.ball_pos + (own_goal - self.ball_pos) * 0.35
    actions[1] = np.clip((guard - self.pos[3]) * 4.0, -1.0, 1.0)
    return actions

解读：脚本对手不需要学习，但必须"像个运动员"。（1）2 号的站位点算法：d = ball − target_goal 是从球门指向球的方向，把该方向延长 0.18 就是"球背后相对球门的一侧"，站到这里向球门方向推，球才会朝正确的门走。这是球类脚本的经典几何：站位点在球的背门侧。（2）3 号的 guard 点取"球 → 自家门连线"的 35% 处：比直接站在门线前更主动，能拦截向门的传球路线。（3）动作统一用 clip((目标−位置)×4, −1, 1)：比例控制器，距离越远输出越大、接近目标自动减速，配合环境的加速度动力学形成平滑接近。（4）注意两个角色都只依赖可观测信息（球、门、位置），脚本策略不"作弊"，学习方与它在信息上是对等的。

片段 3：球物理与接触动量传递

# 2) 球物理：摩擦 + 球员接触传递动量
self.ball_vel *= self.ball_friction              # 先衰减：0.96 让球"滑"一段，不会急停
for i in range(4):
    d = self.ball_pos - self.pos[i]
    dist = float(np.linalg.norm(d)) + 1e-8
    if dist < self.control_radius:               # 任何球员贴到球：双方球队都算接触
        # 0.6×球员速度 = 把动量传给球；d/dist×0.1 = 沿"球员→球"方向的径向冲量
        self.ball_vel = (self.ball_vel + 0.6 * self.vel[i]
                         + (d / dist) * self.kick)
self.ball_vel = np.clip(self.ball_vel, -self.ball_v_max, self.ball_v_max)
self.ball_pos = self.ball_pos + self.ball_vel

解读：十行不到，定义了整场比赛的"手感"。（1）0.6 * vel[i] 是动量传递的核心：跑得越快，推球越狠，"带球"在物理上就是"用自己的速度不断喂给球"。（2）径向冲量 (d/dist)·kick 保证球有"离开脚"的趋势，否则球会停在球员身上黏住；0.1 的量级让轻触即可启动。（3）接触判定对全部 4 人开放：队友、对手碰球都有效，这符合足球规则，也让"抢断"成为可能；物理面前人人平等。（4）顺序细节：先摩擦、后接触、再限速、最后积分位置，self.ball_pos = self.ball_pos + self.ball_vel 用的是本步修正完的速度，避免同一帧出现"球员穿过球"的伪影。球的限速 1.3 比球员上限 1.0 高：球必须跑得比人快，否则永远传不出去。

片段 4：门线判定与三层奖励

reward_a = 0.0
terminated = False
if self.ball_pos[0] > self.field_x:              # 球越过对方门线（先判门！）
    if abs(self.ball_pos[1]) < self.goal_y_half:
        self.goals[0] += 1                       # 在门框范围内：进球
        reward_a = 5.0
        terminated = True
    else:
        # 越线但在门框外：按反射处理，位置镜像回场内、速度反向衰减
        self.ball_pos[0] = 2 * self.field_x - self.ball_pos[0]
        self.ball_vel[0] *= -0.5
elif self.ball_pos[0] < -self.field_x:           # 另一侧对称：失球分支
    if abs(self.ball_pos[1]) < self.goal_y_half:
        self.goals[1] += 1
        reward_a = -5.0
        terminated = True
    else:
        self.ball_pos[0] = -2 * self.field_x - self.ball_pos[0]
        self.ball_vel[0] *= -0.5

# 4) 学习方奖励：推进塑形 + 控球 + 时间成本（三层，量级递减）
dist_to_goal = float(np.linalg.norm(
    self.ball_pos - np.array([self.field_x, 0.0], dtype=np.float32)))
controls = any(np.linalg.norm(self.ball_pos - self.pos[i]) < self.control_radius
               for i in range(2))
reward = -0.005 - 0.05 * dist_to_goal + (0.03 if controls else 0.0)
reward += reward_a

解读：这段处理的是球类环境最"物理正确"的部分。（1）先判门、后反弹：if x > field_x 进入后先检查 |y| < 0.35，命中门框就进球，否则才走镜像反射 2·field_x − x。顺序颠倒（先反射再判门）会让进球永远不可能，这是最贵的一课。（2）反射公式 pos = 2·field_x − pos 把球"弹"回场内并保留超出量，配合速度翻转 ×0.5 模拟能量损失，比直接 clip 位置更自然。（3）上下边界（|y| > field_y）只有反射没有门，简化为速度翻转。（4）奖励组装体现"三层 + 事件"结构：时间成本 −0.005、推进塑形 −0.05·距离、控球 +0.03，最后叠加进球/失球的 ±5；两部分相加后复制成两人共享的 [reward, reward]。注意 controls = any(...)：只要任一 A 队球员在控球半径内就算控球，"团队控球"的判定口径与团队奖励一致。

常见坑

  • 先钳制边界后判进球：处理球越界时先把 x 钳回场内，门线判定就永远不成立，日志表现为"进球率恒为 0、只有塑形分在涨"。判门必须在钳制/反弹之前。
  • 接触冲量对队友也生效引发误判：代码对所有 4 名球员做接触检测，队友碰球同样改变球速，这是有意设计（可以做球），但你要清楚团队奖励之外还有这条共享机制；做"只允许触球"的实验时需显式豁免。
  • 控球奖励过大导致"贴球不动"：0.03 乘 50 步约 1.5，已经接近进球奖励的三分之一；若调到 0.3，策略会带球原地打转刷分。稠密奖励必须与稀疏大奖励保持量级差。
  • 评估忘记对比基线：随机动作偶尔也能蒙进一球，"胜率 0.1"看着还行。没有随机基线（通常 0.0～0.1）作锚点，就无法判断训练后的 0.45 里有多少是学习的贡献。
  • 球限速低于球员限速：若把 ball_v_max 调到 1.0 以下，球永远跑不过追它的防守球员，"传球"概念失效、任务变得不可能。球必须比人快，这是球类环境的物理铁律。

  2. 把球摩擦 ball_friction 从 0.96 降到 0.85，先预测"推进塑形被钻空子"的新方式，再实跑验证。★
    提示
    球减速快意味着一次触碰只能前进一点，需要更频繁的带球；如果控球奖励偏大，策略可能学会"原地反复碰球"刷分，适当调大时间成本可以压掉这种钻空子。
  3. 给防守加塑形：在奖励里加上 −0.05×‖球−自家球门‖ 或"失球风险"项，先分析量级怎么配，再看胜率是否更稳定。★★
    提示
    在 step 组装 reward 时加一项，量级要与推进塑形对称；否则策略会一味缩在后场保平，胜率不升反降。
  4. 把脚本对手的 3 号从补位改成"贴住最近的 A 球员"的盯人策略，先预测学习难度的变化，再重跑比较。★★
    提示
    修改 _scripted_opponent 第二段：guard 点换成"离 3 号最近的 A 球员位置"。盯人让带球突破变难，但可能露出身后空当，正好检验学习方能否利用。
  5. 把 2v2 扩成 3v3（各加一名球员），先论证"A 队三人共享一个网络"的对称性条件是否仍然成立，再观察训练步数的变化。★★★
    提示
    需要同时改球员数组、观测拼接与脚本逻辑；脚本第三人可以复用 2 号策略。样本数随人数增加，学习所需步数大约线性上涨，多智能体的"人数税"。

小结

  • 球类环境的核心新增实体是"球"：惯性 + 接触动量传递 + 门线/边界两套判定的正确顺序，缺一不可。
  • 奖励三层结构（时间成本 / 推进塑形 / 控球）加上进球失球的 ±5，是让连续足球任务可学的最小配方；防守端没有塑形是它的先天弱点。
  • 参数共享让同队球员用一份经验学习；观测全相对量（外加球门先验）保证策略与球员身份无关。
  • 评测三件套：随机基线、胜/平/负、控球率；三个数要搭配解读，避免把"长传冲吊"误判成"没学会"。
  • 下一章离开体育场，进入城市路口：多路口信号灯协同控制，以等待车队长度作团队成本，比较学习策略与固定配时基线。
