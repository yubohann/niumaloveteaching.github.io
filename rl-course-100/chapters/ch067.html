第三篇 · 算法对比与集成

第 067 章：PPO与SAC的集成学习

两个不同优化路径学出来的策略，动作经常不一致，这种"分歧"可以是对冲误差的机会。本章训练一个 PPO 与一个 SAC，把它们的动作加权融合、用批评家仲裁，并在固定评估回合上系统比较六种组合。

  • 主题：模型集成 / 动作融合与仲裁
  • 关键公式：a = w·aPPO + (1−w)·aSAC；仲裁 a* = argmax候选 min(Q1,Q2)
  • 预计学时：55 分钟
  • 前置章节：第 066 章

学习目标

  • 理解集成学习在强化学习里的价值与边界：不同来源的误差若不完全相关，平均能降低方差，但不保证提升均值。
  • 掌握动作级凸组合融合 a = w·aPPO + (1−w)·aSAC 的写法与权重语义。
  • 看懂基于 Q 值的动作仲裁：候选集、裁判网络与分布外评分的风险。
  • 实现"固定评估回合"协议：所有策略在同一批环境种子上比较，排除回合间运气差异。
  • 用动作分歧 |aPPO − aSAC| 与回合回报的相关性分析"分歧何时出现"。

背景与动机

PPO 与 SAC 用完全不同的方式学策略：一个直接在策略空间做近端更新，一个先学好价值再从中诱导策略。即使最终回报接近，它们在每个状态下选择的动作往往不同：一个更保守，一个更大胆。如果两种策略的误差有一部分是"不相关的噪声"，组合起来就能把噪声平分掉，这正是集成学习（ensemble learning）的基本逻辑。

在监督学习里，把多个模型的预测取平均几乎总是划算的；在强化学习里没这么简单：动作的"平均"可能落在两个策略都不擅长的位置，而用某个批评家仲裁又会引入它自己的偏差。本章不预设"集成就一定更好"，改为把几种组合方式放进同一张表，用同一批评估回合测出各自真实水平，让数据说话。这也是第三篇（算法对比与集成）的收尾实验，之后课程将进入多智能体世界。

核心原理

1. 为什么平均能降低方差

设两个策略在状态 s 下的动作相对"理想动作"的偏差分别为 e1、e2。加权平均后的偏差是 w·e1+(1−w)·e2，其平方期望可展开为：

𝔼[(w·e1+(1−w)·e2)2] = w2𝔼[e12] + (1−w)2𝔼[e22] + 2w(1−w)𝔼[e1e2] e1、e2 是两个策略的动作偏差；w 是 PPO 的权重。当偏差不相关（𝔼[e1e2]≈0）且方差相近时，w=0.5 处的误差方差约为单模型的一半

这就是"融合权重取中间值时有时略超单模型"的来源。若两个策略系统性偏在同一方向（高相关），平均无效；若它们互补，平均就是免费的方差折价。Pendulum 上两种算法的动作映射风格不同，属于部分相关，所以收益通常是温和的、不是颠覆性的。凸组合还有一个前提：两个动作都要在合法动作域内、融合后仍在域内，本章两模型输出都已被各自裁剪到 [−2, 2]。

2. 动作仲裁：让批评家当裁判

a* = argmaxa ∈ {aPPO, aSAC, amix}  min( Q1(s,a), Q2(s,a) ) 候选集由三个动作组成；裁判是 SAC 的双 Q，取 min 延续 SAC 的悲观估计口径；amix 是 0.5 融合动作

仲裁不动动作本身，只在候选里挑"批评家认为最好"的那个。它有一个明显的软肋：Q 网络只见过 SAC 策略产生的动作分布，对 PPO 的动作属于分布外输入，评分可能虚高也可能虚低。所以仲裁表现偏向 SAC 并不奇怪，本章会打印三种动作被选中的比例，你大概率会看到仲裁沦为"翻版 SAC"。正确的心态是：仲裁是一种启发式，不是理论保证；报告成绩时必须同时报告占比。

3. 分歧本身是信息

逐状态计算 |aPPO − aSAC|，再按回合平均，得到"分歧度"。如果分歧大的回合回报也差，说明两个策略在困难状态上"各说各话"，融合会把这些状态推向中庸动作，收益有限甚至有害；如果分歧与回报无关，说明分歧更接近随机噪声，平均就有降方差的价值。本章用 np.corrcoef 给出两者的相关系数，但只该把它当趋势提示：30 个回合的样本量不足以支撑强结论。

4. 固定评估回合：配对比较的底线

Pendulum 的回报高度依赖初始角：同样的策略，初始角好可以 −100，差可以 −800。如果每个策略各随机跑 30 个回合，你测的是"策略 + 运气"，上百点的运气差异会淹没策略差异。本章的做法是 make_eval_seeds 生成一批固定环境种子，所有策略、所有权重、仲裁全都在同一批初始状态上评估，策略 A 与策略 B 的均值差异因此只来自策略本身。配对评估是所有模型比较实验的通用纪律。

实现思路与设计

模块划分

组件职责关键点
train_ppo / train_sac训练两个基模型与第 066 章相同实现，同预算同种子，先 PPO 后 SAC
make_eval_seeds固定评估回合种子所有策略面对同一批初始状态
run_episode_blend单回合加权融合评估同时返回动作分歧的回合均值
run_episode_arbitration单回合动作仲裁统计三种候选被选中的次数
summarize_strategy汇总均值/标准差/极值统一口径，避免选择性报告
save_plot柱状图（均值 ± 标准差）一眼看出融合与单模型的相对位置

关键超参数

参数默认值作用与取值理由

--weights0,0.25,0.5,0.75,1含两个端点（纯模型）与三个融合点；w 是 PPO 权重
--final-episodes30固定 30 个回合，把评估均值噪声压到可接受范围

数据流

第一步：顺序训练两个基模型（PPO 的 actor-critic 与 SAC 的 policy + 双 Q 全部保留，不丢弃）。第二步：生成固定评估种子，对每个权重 w 跑一遍 30 个回合的融合评估；再跑一遍仲裁评估并汇总占比。第三步：把 w=0.5 回合的"分歧度"与"回报"配对求相关系数，最后汇总柱状图。

与第 066 章的差异点

第 066 章研究单个算法内部的探索；本章把两个算法都留下当"组件"：① 训练完不再丢弃模型，改为进入组合评估阶段；② 新增固定回合评估协议与两种组合算子；③ 增加仲裁占比与分歧统计。第 068 章起进入多智能体，本章的"多模型组合"思路会以另一种形式回来：多智能体本身就是"多个策略的集成"。

关键代码与解读

片段 1：加权融合评估回合

def run_episode_blend(env, ppo_net, sac_agent, weight, seed, device):
    """一次评估回合：返回（回合回报, 平均动作分歧）。"""
    obs, _ = env.reset(seed=seed)                  # 固定种子：所有策略共用同一起点
    done = False
    ep_ret = 0.0
    disagreements = []
    while not done:
        obs_t = obs_tensor(obs, device)
        a_ppo = ppo_net.mean_action(obs_t).squeeze(0).cpu().numpy()
        a_sac = sac_agent.policy.mean_action(obs_t).squeeze(0).cpu().numpy()
        disagreements.append(float(np.mean(np.abs(a_ppo - a_sac))))  # 逐状态分歧
        action = np.clip(weight * a_ppo + (1.0 - weight) * a_sac, -ACT_LIMIT, ACT_LIMIT)
        obs, r, terminated, truncated, _ = env.step(action)
        ep_ret += r
        done = terminated or truncated
    return ep_ret, float(np.mean(disagreements))

解读：融合评估的全部逻辑。（1）两种策略都取 mean_action（确定性动作）：评估阶段不接受采样噪声，否则分歧里混着随机性。（2）凸组合 w·a_ppo + (1−w)·a_sac 对动作逐维生效；w=1 退化为纯 PPO、w=0 退化为纯 SAC，因此"纯模型"不需要另写评估代码，直接用端点权重即可。（3）np.clip 是防御式写法：两模型输出已被裁剪到 [−2, 2]，凸组合必然在域内；但如果将来面向未压缩动作或"对冲"权重（w 为负），clip 是最后一次保险。（4）分歧在同一个状态上计算（同一次前向、同一步交互），逐回合取均值。这个数据会被主流程拿去和回合回报做相关分析。

片段 2：动作仲裁，让 SAC 批评家当裁判

def run_episode_arbitration(env, ppo_net, sac_agent, seed, device):
    """动作仲裁：在 {a_ppo, a_sac, 0.5 融合} 中选 SAC 批评家 Q 值最高者。"""
    obs, _ = env.reset(seed=seed)
    done = False
    ep_ret = 0.0
    picks = {"ppo": 0, "sac": 0, "mix": 0}
    while not done:
        obs_t = obs_tensor(obs, device)
        a_ppo = ppo_net.mean_action(obs_t).squeeze(0).cpu().numpy()
        a_sac = sac_agent.policy.mean_action(obs_t).squeeze(0).cpu().numpy()
        a_mix = 0.5 * a_ppo + 0.5 * a_sac              # 融合候选，防止仲裁只会在两端跳
        candidates = {"ppo": a_ppo, "sac": a_sac, "mix": a_mix}
        best_name, best_q = None, -np.inf
        for name, a in candidates.items():
            q = sac_agent.q_value(obs_t, torch.as_tensor(a, dtype=torch.float32,
                                                         device=device).unsqueeze(0))
            if q > best_q:                              # 平局时保留先出现的候选
                best_name, best_q = name, q
        picks[best_name] += 1                           # 记录胜者，供占比统计
        action = np.clip(candidates[best_name], -ACT_LIMIT, ACT_LIMIT)
        obs, r, terminated, truncated, _ = env.step(action)
        ep_ret += r
        done = terminated or truncated
    return ep_ret, picks

解读：仲裁的裁判只读不写，q_value 用 @torch.no_grad() 封装。（1）候选集包含 0.5 融合动作：如果只放两端动作，仲裁的输出只会在两个端点跳变，动作序列不平滑；加入 mix 候选后，仲裁至少有一半概率输出折中动作。（2）评分用 min(Q1,Q2)，与 SAC 自身的悲观估计口径一致；用 SAC 的 Q 给 PPO 动作打分属于分布外推断，它的分数只有相对排序意义，绝对数值不可信。（3）平局规则（用 q > best_q，不用 >=）会保留先出现的候选：字典顺序是 ppo → sac → mix，因此严格平局时偏向 PPO。若要更公平，可以在候选前先打乱顺序，或用微小随机扰动。（4）picks 的统计是本实验最重要的诊断：占比告诉你是"真仲裁"还是"披着仲裁外衣的 SAC"。

片段 3：主流程的融合评估循环

    eval_env = gym.make("Pendulum-v1")
    eval_seeds = make_eval_seeds(args.seed, args.final_episodes)
    names, means, stds = [], [], []
    strategy_returns = {}
    disagreement_per_ep = None
    for w in weights:
        returns, dis = [], []
        for s in eval_seeds:                           # 同一批种子：配对比较
            ret, d = run_episode_blend(eval_env, ppo_net, sac_agent, w, s, device)
            returns.append(ret)
            dis.append(d)
        label = f"融合 w={w:.2f}" if 0 < w < 1 else ("纯 PPO" if w == 1 else "纯 SAC")
        m, sd = summarize_strategy(label, returns)
        names.append(label)
        means.append(m)
        stds.append(sd)
        strategy_returns[label] = np.asarray(returns)
        if abs(w - 0.5) < 1e-9:                        # 记住中点权重的分歧，供相关分析
            disagreement_per_ep = np.asarray(dis)

解读：三层循环，权重、种子、步。这里有几个设计决定值得展开。（1）端点权重直接复用融合代码：w=1 时融合式退化为纯 PPO，w=0 退化为纯 SAC，这保证了"纯模型基线"与"融合策略"走的是同一条代码路径、同一批种子，排除实现差异。（2）标签用 0 < w < 1 判断是否真融合，端点标成"纯 PPO/纯 SAC"，汇总与绘图直接读这个标签。（3）只有中点权重（w=0.5）那轮的逐回合分歧被留下（abs(w - 0.5) < 1e-9），因为它最接近"两模型对等投票"的情形，相关分析用它最有代表性。（4）每一档权重都完整跑一遍 30 个种子，所有档位共享同一批起点，均值之间可以直接相减比较。

片段 4：仲裁占比与分歧相关性

    total_picks = sum(picks_total.values())
    pick_str = "、".join(f"{k} {v / total_picks * 100:.0f}%" for k, v in picks_total.items())
    m, sd = summarize_strategy("仲裁（SAC 批评家）", arb_returns, extra=f"[占比: {pick_str}]")

    if disagreement_per_ep is not None:
        mid_returns = strategy_returns.get("融合 w=0.50")
        if mid_returns is None:
            mid_returns = np.asarray(arb_returns)
        if np.std(disagreement_per_ep) > 1e-6:          # 分歧几乎是常数时不谈相关
            corr = float(np.corrcoef(disagreement_per_ep, mid_returns)[0, 1])
            print(f"动作分歧 |a_ppo − a_sac| 的回合均值 {disagreement_per_ep.mean():.3f}，"
                  f"与回合回报的相关系数 {corr:+.2f}")

解读：两段小代码各自守住一个报告纪律。（1）仲裁成绩与占比同屏打印：只报"仲裁 −208.9"而不报"sac 占 61%、mix 占 35%"会让读者误以为仲裁有额外价值。这是实验诚实性的要求，不是排版偏好。（2）相关分析前先检查 np.std(disagreement_per_ep) > 1e-6：如果分歧在所有回合里几乎是同一个常数（比如两策略输出永远差 0.4），相关系数在数值上无意义，直接跳过并打印说明。（3）np.corrcoef(...)[0, 1] 取的是两列之间的相关系数；30 个样本给出 ±0.3 以内的系数都应视为噪声范围，结论只能写成趋势。

以实跑为准的预期：同预算下 SAC 单独明显优于 PPO；融合权重偏 SAC 一侧（0.25~0.5）时均值与 SAC 相当或略好、标准差更小；仲裁基本复刻 SAC（sac 占比过半）。如果 PPO 训练预算足够大（如 10 万步），融合曲线会向中间移动，"融合超过两端"的概率随之下降，集成收益来自互补，不来自神奇。

常见坑

  • 评估回合不固定：如果每个策略各随机 30 个回合，回合难度的差异会淹没策略差异。固定评估种子是集成实验的底线。
  • 把仲裁当成免费提升：Q 网络对分布外动作的评分不可靠，仲裁可能只是"用批评家的偏好筛选动作"。报告仲裁成绩时必须同时报告候选占比。
  • 两个基模型训练预算不同：如果 PPO 只训了 1 万步、SAC 训了 5 万步，融合实验测的是"强模型带弱模型"，不是算法互补。预算必须一致。
  • 只看均值不看方差：集成的价值常体现在方差降低上。汇报时把标准差一并给出，别只挑好看的均值。
  • 把相关系数当因果结论：30 个回合的相关系数在 ±0.3 以内都可能只是噪声，只能当趋势提示；要下结论得扩到多种子、上百回合。

练习与思考

  1. 把 --weights 细化到 0.1 间隔，找出均值最好的权重点。它和 0.5 差多少？★
    提示
    不训练新模型，只跑评估，开销很小。注意观察最优权重点是否稳定，对 30 个回合的评估噪声来说，权重曲线很可能是"平底"的。
  2. 训练两个 SAC（不同种子）组成委员会，动作取平均，与单个 SAC 比较。为什么"同算法不同种子"的集成往往比"PPO+SAC"的集成更可靠？★★
    提示
    把 train_sac 跑两次（改 --seed），再用同样的融合评估代码把两个 SAC 的动作平均。同算法误差结构相似但初始条件不同，平均更"安全"。
  3. 把仲裁裁判从 SAC 批评家换成"多批评家"：用 SAC 的 Q 给 SAC 动作打分、用各自动作对应的价值或优势信号给 PPO 动作打分，再比较。预测仲裁占比会怎么变，验证你的预测。★★
    提示
    PPO 的价值头是 V(s)，没有现成的 Q(s,a)：最简做法是用优势函数的符号给 PPO 动作打分，再与 SAC 的 Q 归一化后比较。这是"多批评家仲裁"的雏形。
  4. 做一个"蒸馏集成"：把融合策略在状态网格上的动作作为监督标签，训练一个小策略网络拟合它，并让这个小网络直接控制环境。它和直接切换两个模型相比优缺点是什么？★★★
    提示
    在 6×6 状态网格（或随机 500 个状态）上生成融合动作，MSE 回归即可。蒸馏后推理只用一个网络，但融合的互补性被压缩成单一函数。
  5. 把分歧-回报相关性研究扩展到多种子：训练 3 对 PPO/SAC，收集 90 个回合样本，重算相关系数。结论会稳定吗？★★★
    提示
    需要外层种子循环，训练成本翻 3 倍（可缩短 --max-steps 控制）。这正是强化学习实证研究的常态：结论要在多种子上重复验证。

小结

  • 集成学习在 RL 里依然成立，但收益取决于两个策略的误差是否互补；平均能降方差，不保证提升均值。
  • 动作级融合用凸组合实现，端点权重就是纯模型基线；本章配置下 w=0.25~0.5 与 SAC 相当且标准差更低。
  • 仲裁由 Q 值做裁判，受分布外评分影响大，通常退化为"翻版 SAC"，要如实报告占比。
  • 固定评估回合、统一预算、报告方差与占比，是这类对比实验的四条底线。
  • 第三篇到此收尾：你已系统对比了 PPO 与 SAC 的性能、稳定性、敏感性、探索与融合，知道"选算法"要结合任务与调试成本。
  • 下一章进入第四篇：多智能体强化学习。第一个基线是"独立 PPO"，每个智能体各学各的，互不理会，看看合作任务里会发生什么。
