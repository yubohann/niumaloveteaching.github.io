第三篇 · 算法对比与集成

第 066 章：PPO与SAC的探索策略对比

PPO 用固定系数的熵奖励推着策略保持随机，SAC 用自动温度把熵"锁定"在目标值。本章在训练全程记录状态覆盖率、策略噪声 σ 与温度 α，让两种探索方式的差别变成三条可看的曲线。

  • 主题：探索机制对比 / 训练期插桩观测
  • 关键公式：J(π) = Σt 𝔼[rt + α·H(π(·|st))]，目标熵 Htarget = −dim(A)
  • 预计学时：50 分钟
  • 前置章节：第 065 章

学习目标

  • 理解探索与利用的权衡，以及 PPO 的固定熵正则与 SAC 的最大熵目标在机制上的区别。
  • 掌握三个探索度量：状态覆盖率（6×6 网格）、策略噪声 σ、SAC 的温度 α。
  • 看懂训练期插桩的写法：如何在不改变训练动力学的前提下记录覆盖率与噪声轨迹。
  • 对比两种算法的"探索持续性"：谁在训练中段之后还保留对新状态的访问与足够的动作随机性。
  • 能解释自动温度如何把平均熵拉向 −dim(A)，以及这一机制对探索稳定性的意义。

背景与动机

强化学习的一半难题是探索：智能体必须先"见过"足够多的状态，才有可能学到好策略。探索不足会卡在局部最优，Pendulum 里只会来回轻摆、永远凑不到直立附近的策略；探索过度则每次动作都在抖，回报永远上不去。

PPO 压注在固定系数的熵奖励上：ent_coef 是常数，熵项会推高 log_std，但一旦回报梯度变强、σ 还是会被压下去，探索强度在训练中段往往悄悄衰减。SAC 则把探索写进目标函数：每步都最大化"回报 + α·熵"，α 自动调整，把平均熵维持在目标值附近。一个像"固定油门"，一个像"定速巡航"。

上一章比的是对超参数的敏感度，本章第一次把镜头对准训练过程本身：把回报、覆盖率、σ、α 一起打进日志，看两种探索风格差在哪里、又分别付出什么代价。

核心原理

1. PPO 的熵奖励：固定系数的"油门"

PPO 的损失里有 −cent·H(π) 一项，它给状态无关的 log_std 一个常数级的推力：

Δ log σ ≈ cent · ∂H/∂ log σ − (来自回报的梯度)，其中 H 随 log σ 单调增 cent 固定 ⇒ σ 的最终水平由"熵推力"与"回报拉力"的平衡决定；一旦回报梯度占上风，σ 就持续收缩

默认 ent_coef=0.0 时，σ 完全由回报梯度决定：Pendulum 上早期优势尺度大，σ 会一路收缩，探索随之减少；如果 cent 设得太大，σ 又降不下来，动作永远在抖，回报上不去。一个常数要同时管住训练全程的探索强度，本身就是个两难。它还有第二个隐患：熵奖励只看策略分布的随机程度，不看智能体到底去过哪里，噪声大不等于探索有效。

2. SAC 的自动温度：把熵当约束

SAC 的目标函数显式包含熵，并让 α 自己动：

J(π) = Σt 𝔼[ rt + α·H(π(·|st)) ]，   Htarget = −dim(A) α 是温度（探索的相对价格）；H 是策略熵；目标熵取动作维度的相反数，连续版 SAC 的常用设定

温度损失 J(α) = 𝔼[ −α·(log π(a|s) + Htarget) ] 的含义是：当策略熵低于目标，梯度推 α 上升、加强探索；高于目标则 α 下降。于是 SAC 的探索强度自校准：刚开始策略本就随机，α 自动压低以免浪费探索预算；策略开始收敛、熵下滑时，α 又顶住不让探索断崖式消失。这就是"定速巡航"的出处：它跟踪的是一条熵的轨道，噪声大小只是跟随该轨道变化的结果。

3. 怎么"看见"探索：三个代理量

探索本身不可直接观测，本章用三个代理量拼出全貌：

  • 状态覆盖率：把 (cos θ, sin θ) 切成 6×6 网格，训练轨迹每访问一个新格子就 +1，上限 36。它回答"去过哪些状态"。
  • 策略噪声 σ：PPO 是状态无关的 exp(log_std)；SAC 是状态相关的，在一个固定探测状态集上取平均。两者在同一批状态上取值才有可比性。
  • 温度 α：SAC 专属。看它随训练的变化方向，上升说明熵不足、探索被加强；下降说明策略正在变确定。
覆盖率不是越高越好

Pendulum 上只要力矩够大，任何策略都会把摆扫过全部角度，覆盖率很快饱和到 30/36 以上。真正有区分度的是早期覆盖率（前 9000 步谁更快铺开）与中后期噪声水平（谁在收敛后还保留探索余地）。别把覆盖率当唯一指标。

4. 插桩原则：只观测，不改动力学

想比较探索，就不能同时改变学习过程。本章的插桩遵守两条纪律：① 覆盖率与 σ 的计算都是只读的，@torch.no_grad()、不写回放池、不参与损失；② 记录发生在训练交互上，不统计评估回合，因为评估用确定性动作、轨迹分布与训练完全不同。混进评估会系统性高估探索。

实现思路与设计

模块划分

组件职责关键点
CoverageTracker6×6 网格访问统计每步喂入 obs，累计非零格子数；边界要 clip
sigma_probe_states生成固定探测状态集网格中心 + 角速度为 0，供两种算法统一比较

summarize / save_plot阶段性对比与双面板图早期覆盖率与 σ 轨迹是主读点

关键超参数

参数默认值作用与取值理由
--max-steps30000足够看到收敛后的探索衰减
--eval-every3000每条曲线 10 个点，密度够看趋势

其余参数同第 065 章保持与前两章实验的可比性

数据流

每个训练步：tracker.add(obs) 记录覆盖 → 选动作、与环境交互 → 累计本窗口的动作幅度。到了评估点：跑确定性评估得到回报 → 读 σ（PPO 一行 / SAC 探测集）→ 读覆盖率与 α → 追加一行 history → 重置窗口计数。训练结束后 summarize 打印早期覆盖与 σ 中末段对比，save_plot 画覆盖率和 σ 的双面板曲线。

与第 065 章的差异点

训练流程与超参数框架不变，变化在两处：① 两个训练循环加入 CoverageTracker 与噪声读取，每个评估点记录一行 history；② 汇总与绘图换成覆盖率 / σ / α 视角。这是"零改动策略、只加观测"的插桩实验。

关键代码与解读

片段 1：状态覆盖率追踪器

class CoverageTracker:
    """统计 (cos θ, sin θ) 平面上被访问过的网格，衡量探索覆盖。"""

    def __init__(self, bins=BINS):
        self.bins = bins
        self.counts = np.zeros((bins, bins), dtype=np.int64)

    def add(self, obs) -> None:
        # 把 [-1, 1] 线性映射到 [0, bins-1]；clip 防止边界值越界
        c = int(np.clip((obs[0] + 1.0) / 2.0 * self.bins, 0, self.bins - 1))
        s = int(np.clip((obs[1] + 1.0) / 2.0 * self.bins, 0, self.bins - 1))
        self.counts[c, s] += 1            # 只统计"到没到过"，不关心停留多久

    @property
    def covered(self) -> int:
        return int((self.counts > 0).sum())     # 非零格子数 = 已覆盖状态数

    @property
    def total(self) -> int:
        return self.bins * self.bins

解读：覆盖率统计故意做得"粗"。（1）只取 obs 的前两维 (cos θ, sin θ)，摆角本身就是 Pendulum 的核心状态，把它们离散成 6×6 网格，36 个格子的大小刚好让一次成功的摆动扫过十几个格子，形状变化肉眼可辨。若把角速度也切进来（3D 网格），格子数暴涨到几百，早期覆盖率会一直贴着 0，反而看不出差异。（2）线性映射 (x+1)/2×bins 把 [−1,1] 映到 [0,6)；clip 是必须的保险，cos/sin 理论上不超过 ±1，但浮点误差可能让 obs[0]=1.0000001 映射出 6，直接索引越界。（3）covered 由布尔数组求和得到：随时可以从 counts 重算，不怕逻辑错位。附加代价可忽略，36 个元素的比较。

片段 2：统一 σ 的观测口径

def sigma_probe_states(device):
    """固定探测状态集：6×6 网格中心（角速度为 0），用于比较策略噪声。"""
    cs = np.linspace(-0.85, 0.85, BINS)
    ss = np.linspace(-0.85, 0.85, BINS)
    grid_c, grid_s = np.meshgrid(cs, ss)
    states = np.stack([grid_c.ravel(), grid_s.ravel(),
                       np.zeros(BINS * BINS)], axis=1).astype(np.float32)
    return torch.as_tensor(states, device=device)

解读：这段回答"怎么让两种完全不同的 σ 可比"。PPO 的 σ 是一个数（状态无关参数）；SAC 的 σ 是状态相关的网络输出，每个状态都不一样。办法是挑一组固定、覆盖典型状态的探测点：网格中心 ±0.85、角速度置 0，共 36 个状态。（1）±0.85 取在网格中心：贴住 ±1 边界会让探测点卡在最外侧格子的边缘，代表性差。（2）角速度置 0：让"噪声与状态的关系"这部分差异最小化，聚焦比较噪声的整体水平。（3）常数种子、无采样、无随机，任何时刻对同一探测集求平均，得到的是一条确定、可复现的曲线。SACAgent.policy_sigma 只有三行：前向探测集、取 log_std.exp()、求均值；PPO 那边则直接对参数取 exp，两边的单位都是"动作空间中的标准差"。

解读：插桩的全部代码都在评估分支里，训练动力学一行未动。（1）history 五元组统一为 (步数, 回报, 覆盖, σ, α)，PPO 没有 α 就记 None，数据格式统一让汇总与绘图函数可以两种算法共用。（2）覆盖率打印成"累计值 + 增量"：covered - last_covered 增量归零的那一次，说明这一窗口没有到过任何新格子，探索已经停滞，这比累计值更能暴露问题。（3）动作幅度 mean_abs 每个窗口清零重算，显示"最近 2048 步的平均 |动作|"：全程平均会把早期的大动作一直带在身上，掩盖后期动作变小的趋势。（4）mean_abs 区分"动作在抖"与"动作在推进"：σ 大但平均 |a| 小，说明抖动多而推进少。

解读：SAC 侧的插桩与 PPO 只差两处。（1）agent.policy_sigma(probe) 传入共享的探测集，这是两种 σ 可比的另一半保证；probe 在训练开始时构造一次，之后不变。（2）温度只在预热结束后读取（step > start_steps），预热期没有梯度更新、α 也未启用，记成 None 并显示"预热"，避免曲线起点出现无意义的点。（3）读 α 只是 .item() 的只读操作，不参与任何反传，插桩铁律再次出现。日志里的 α 从约 0.07 缓慢下降，σ 从 0.5 缓降到 0.35 左右，两条线一起解释"定速巡航"：α 顶住熵的下滑，σ 因此不会断崖。

常见坑

  • 把两种 σ 当同一个量直接比：PPO 的 σ 是常数、SAC 的 σ 是状态相关均值。本章已在探测集上统一口径；若你改用单点状态取值，务必对两种算法取同一状态。
  • 在评估回合里统计覆盖率：评估用确定性动作，轨迹分布与训练完全不同，混进来会高估探索。只在训练交互中统计。
  • 以为格子越细越好：Pendulum 的核心状态只有 θ（cos/sin 两维），网格太细时覆盖率很快饱和到满格、失去分辨力。先跑默认 6×6，需要更细粒度时再升级到 3D 网格。
  • ent_coef 调大就等于"探索更多"：熵奖励推高的是动作噪声，不是有计划的状态访问。σ 过大时策略连当前最优动作都执行不准；噪声只是探索的手段，不是探索本身。
  • 用全程平均动作幅度判断当下行为：早期大动作会把均值一直拉高。用窗口清零重算的 mean_abs，它显示的才是"最近一段"。

练习与思考

  1. 把 PPO 的 --ent-coef 设为 0.01 与 0.05 各跑一次，比较 σ 曲线与最终评估回报。预测：熵奖励的"最优值"存在吗？★
    提示
    看 σ 是否被顶在某个水平、回报是否变差。0.05 时 σ 可能大到动作一直在抖，回报反而下降，两个目标在拉锯。
  2. 把 SAC 的目标熵从 −1 改成 −0.25 与 −2（在 SACAgent.__init__ 改 self.target_entropy），观察 α、σ 与回报的变化。★★
    提示
    目标熵更小 ⇒ α 被压低 ⇒ 策略更快变确定；目标熵更大 ⇒ 探索更持久但回报上得慢。记录 α 最终收敛到的稳定值。
  3. 把覆盖率网格改成 12×12，并给角速度加 3 档（3D 覆盖率，共 432 格）。分辨率提高后两种算法的差异是否更明显？★★
    提示
    只需改 CoverageTracker：把 counts 扩成三维数组，第三维用 clip((θ̇+8)/16×3) 映射。格子多了以后，早期分米级差异更容易看出来。
  4. 把"早期覆盖率"当自变量：对 3 个随机种子分别记录前 9000 步覆盖率与 30000 步最终回报，画散点图，讨论探索与最终性能的相关性有多强。★★
    提示
    需要外层种子循环并收集 history。每算法只有 3 个点，结论只能当定性参考，这正是强化学习实验的现实。
  5. 给 PPO 实现最简单的"计数探索奖励"：访问新格子时给当前奖励加 +0.5，把 tracker 的增量接进 reward。重跑并比较覆盖与回报曲线。★★★
    提示
    在采样循环里先记 before = tracker.covered，add 后判断是否增加，再把 reward + bonus 存入缓冲区。注意奖励尺度变化会影响价值学习，bonus 从小值试起。

小结

  • PPO 用固定系数的熵奖励维持探索，σ 由"熵推力"与"回报拉力"的平衡决定，容易在训练中段衰减；熵奖励只管噪声大小，不管状态访问。
  • SAC 把熵写进目标函数，自动温度把平均熵拉向 −dim(A)，探索强度自校准，如同"定速巡航"自动补油。
  • 三个探索观测：状态覆盖率（去过哪）、策略噪声 σ（动作多随机）、温度 α（探索在加强还是收缩）。
  • 本章配置下 SAC 的中后期 σ 明显高于 PPO（约 0.37 vs 0.21），这是它持续改进的原因之一；但覆盖率不等于一切，要结合回报解读。
  • 插桩纪律：只读观测、不碰训练动力学、不统计评估回合、探测量口径统一。
