第三篇 · 算法对比与集成

第 065 章：PPO与SAC的超参数敏感性对比

只拧一个旋钮：学习率。从 1e-4 扫到 1e-3，各跑一次 PPO 与 SAC，用"极差"和"相对敏感度"量化谁更怕你把超参数调错。

  • 主题：超参数敏感性 / 学习率扫描
  • 关键公式：有效步长 ≈ η × epochs × 梯度尺度；相对敏感度 = 极差 / |最优性能|
  • 预计学时：45 分钟
  • 前置章节：第 064 章

学习目标

  • 理解敏感性实验的设计原则：一次只动一个旋钮，环境、种子、预算、评估协议全部冻结。
  • 掌握两个敏感度指标：极差与相对敏感度，以及它们与真实项目里"调参成本"的关系。
  • 从机制上解释 PPO 为什么比 SAC 更依赖学习率：有效步长由 η、复用轮数与优势尺度三者相乘。
  • 看懂学习率扫描框架：配置浅拷贝、固定种子、结果汇总成对数横轴曲线。
  • 学会诚实报告实验局限：单种子扫描的结论边界在哪里，怎么扩展成可靠版本。

背景与动机

强化学习被吐槽最多的一点是"调参玄学"：同一份算法，学习率差三倍，结果一个在天上一个在地下。对工程师来说，这直接决定调试成本，一个对超参数不敏感的算法，能让你在没见过的新任务上少烧几天机时。上一章换种子测稳定性，这一章换旋钮测敏感性，两者合起来回答同一个工程问题："把算法交出去，它靠不靠得住？"

敏感性实验的难点不在跑，而在控制变量：环境、种子、网络、预算、评估协议全部冻结，只改学习率。本章沿用前两章的两种算法实现，把每个算法的学习率分别设为 1e-4、3e-4、1e-3（相隔一个数量级），各训练一次，用最终性能的极差体现"怕不怕调错"。结果往往会告诉你：SAC 的可调区间宽得多，PPO 则有一个窄的"甜点区"，且两侧的惩罚不对称。

核心原理

1. 学习率决定"每一步走多远"

梯度下降的表观更新量是 Δθ = −η·g，但强化学习里的有效步长还要乘上梯度尺度和复用次数：

单次策略移动 ≈ η × epochs × |𝔼[∇θ log πθ(a|s) · Â]| η 是学习率；epochs 是同一批数据的复用轮数；Â 是优势，其尺度随批次波动；三者相乘才是策略真正走出的距离

三项里任何一项偏大都会让策略"一步跨太远"：跨越信任域、掉出好策略的吸引盆、甚至退化成永远输出同一动作。PPO 的裁剪只限制比率偏离 1 的程度，不限制批量平均后的总步长，因此 η 必须与优势尺度、复用轮数配合使用；调 η 时你实际上在同时改三个因素里的一个乘数。SAC 截然相反：策略梯度来自重参数化路径，批评家先收敛再带动策略，单步扰动还有目标网络与大批量做缓冲。

2. 两个算法对 lr 的不同依赖

  • PPO：优势标准化后尺度约为 1，梯度尺度由 log_std 与策略均值决定。η 太大（1e-3）时，早期优势同号、10 轮连续复用，策略熵可能骤降、价值网络被大目标带飞，表现为"先涨后崩"或全程低分；η 太小（1e-4）则 2 万步预算内基本看不到进步。两端都罚，中间有个甜点区。
  • SAC：每环境步只更新一次、批量 256、双 Q 取最小、目标网络 τ=0.005，四个因素把单步扰动压得很小。学习率在 1e-4 ~ 1e-3 之间主要影响收敛速度，对最终水平影响相对小；自动温度还会在策略过确定时加探索，缓解"学崩"。

用一句直觉话总结：PPO 的稳定性靠"外部剪裁"，剪裁对步长的约束是局部的；SAC 的稳定性靠"内部结构"，结构对步长的约束是全局的。这解释了下面第 3 节的度量为什么值得单独讲。

3. 敏感度的度量

极差 = maxη R(η) − minη R(η)      相对敏感度 = 极差 / |maxη R(η)| R(η) 是学习率 η 下的最终评估回报（最后三次评估的均值）；相对敏感度把极差按最优性能归一化，方便跨任务比较

选用"极差"是因为问题关心最坏情况：调到最差的 lr 会损失多少。标准差刻画平均离散程度，回答的是另一个问题。相对敏感度消除量纲：例如 PPO 最优 −500、最差 −1100，极差 600、相对敏感度 120%；SAC 最优 −200、最差 −350，极差 150、相对敏感度 75%，后者明显更抗调。注意本章扫的是单种子：极差里混着种子噪声，结论用于看趋势；要拿到可靠的数字，需按练习 4 扩成多种子平均。

4. 为什么甜点区通常在 3e-4 附近

对 PPO 而言，有效步长还受更新频率影响：本实现每次采样 2048 步、复用 10 轮。learning rate 3e-4 是大量实现的默认起点，因为它在这个"每批 2048×10 次更新"的组合下恰好让每轮 KL 落在 0.005～0.02 的健康区间。将 --steps-per-update 或 --epochs 翻倍，相当于放大有效步长，最优 η 会相应下移；调参本质上调的是"一组乘积"，单看某一个数字没有意义。

实现思路与设计

模块划分

组件职责关键点
train_ppo_once / train_sac_once单配置训练，返回评估曲线与第 064 章逐字相同，学习率从 args 读取，保证只有一处变量
run_sweep遍历学习率列表，收集最终性能用 Namespace(**vars(args)) 浅拷贝配置，只改 lr
极差 / 相对敏感度敏感度量化用最终性能（最后三次均值），不取单点最佳
save_plot对数横轴敏感度图x 轴 log 刻度，两条线放同一张图

关键超参数

参数默认值作用与取值理由
--lrs1e-4,3e-4,1e-3相隔一个数量级的三个点，覆盖"太小 / 常用 / 太大"
--max-steps20000每个配置固定预算；6 个配置总成本可控
--seed0所有配置共用同一种子，控制噪声来源
--eval-episodes10评估噪声足够小，能分辨百点级别差异
SAC 的温度学习率跟随 --lr本实现里 α 与策略共用学习率，扫描时一起变化，表述结论时要知道这一点

数据流

对每个学习率：浅拷贝配置 → 设 run_args.lr → 用同一种子调用训练函数 → 得到评估曲线 → 取最后三次均值作为最终性能。全部扫完后：极差 = max − min，最优 lr = argmax，相对敏感度 = 极差 / |最优|。绘图时横轴对数刻度，两种算法叠加。

与第 064 章的差异点

第 064 章固定超参数、变种子（测稳定性）；本章固定种子、变学习率（测敏感性）。代码层面新增 run_sweep 调度器与对数坐标图，训练函数本身一字不改，复用同一套实现是对比可信的前提。下一章继续换旋钮：这次是"探索"这个维度。

关键代码与解读

片段 1：扫描调度器 run_sweep

def run_sweep(name, lr_list, train_once, args, device):
    """对一组学习率各训练一次，返回 {lr: (final, curve, 用时)}。"""
    results = {}
    for lr in lr_list:
        run_args = argparse.Namespace(**vars(args))   # 浅拷贝配置：原 args 不被污染
        run_args.lr = lr                              # 唯一变量：学习率
        curve, dt = train_once(args.seed, run_args, device)  # 种子固定，只换配置
        final = float(np.mean([r for _, r in curve[-3:]]))   # 最后三次均值，抗评估噪声
        best = max(r for _, r in curve)
        results[lr] = (final, curve, dt)
        print(f"[{name} lr={lr:.0e}] 最终 {final:8.1f} | 最佳 {best:8.1f} | "
              f"用时 {dt:6.1f}s")
    finals = [results[lr][0] for lr in lr_list]
    span = max(finals) - min(finals)                  # 极差：最坏情况损失
    best_lr = lr_list[int(np.argmax(finals))]
    rel = span / max(abs(max(finals)), 1e-6)          # 相对敏感度：归一化后可跨任务比较
    print(f"---- {name} 敏感度 ----")
    print(f"  最优 lr={best_lr:.0e}（最终 {max(finals):.1f}）；"
          f"极差 {span:.1f}；相对敏感度 {rel * 100:.0f}%")
    return results, span, rel

解读：这段二十来行的调度器是"控制变量"落到代码上的样子。（1）Namespace(**vars(args)) 做浅拷贝：所有字段复制一份，只覆盖 lr。若直接改 args.lr，循环结束后原始配置被污染，你再也说不清每个结果对应的完整配置，这是调参脚本最常见的 bug。（2）种子固定为 args.seed：每个学习率面对完全相同的初始条件与数据顺序，差异只能来自 η。（3）final 取 curve[-3:] 均值：评估噪声约 ±100 分，单点读数的可比性差。同时保留 best 打印出来做交叉验证，但不作为汇总口径。（4）相对敏感度的分母有 max(·, 1e-6) 保护：Pendulum 回报全为负，abs() 后不会除零，但保险起见仍加上下限。

片段 2：PPO 的更新内循环（η 如何被放大）

        N = batch["obs"].shape[0]
        for _ in range(args.epochs):                 # 有效步长随复用轮数放大
            idx = torch.randperm(N, device=device)
            for start in range(0, N, args.batch_size):
                mb = idx[start:start + args.batch_size]
                mean, log_std, value = net(batch["obs"][mb])
                dist = Normal(mean, log_std.exp())
                logp = dist.log_prob(batch["act"][mb]).sum(-1)
                ratio = torch.exp(logp - batch["logp_old"][mb])
                surr1 = ratio * adv_t[mb]
                surr2 = torch.clamp(ratio, 1 - args.clip, 1 + args.clip) * adv_t[mb]
                loss = (-torch.min(surr1, surr2).mean()
                        + args.vf_coef * F.mse_loss(value, batch["ret"][mb]))
                optimizer.zero_grad()
                loss.backward()
                nn.utils.clip_grad_norm_(net.parameters(), 0.5)
                optimizer.step()                     # 每次 step 都按 η 走一步

解读：注意上游一行 optimizer = torch.optim.Adam(net.parameters(), lr=args.lr)，args.lr 就是这样进入训练的。这段循环解释了为什么 η 在 PPO 里的杠杆效应这么大：（1）同一批 2048 条数据被 args.epochs=10 轮反复更新，每轮约 32 个 minibatch，每个 minibatch 都走一步；一个数据批次对应约 320 次参数更新。η 偏大一档，这 320 步会把策略推得远超信任域。（2）裁剪只给单个样本的比率封顶（surr2），但 64 个样本同向时，平均后的梯度依然很大，clip_grad_norm_ 也只是把梯度的范数截到 0.5，不能替代合理的学习率。（3）价值项与策略项共享同一个优化器：η 太大时价值网络也会被大目标带飞，反哺出更糟的优势估计，形成恶性循环，这就是"先涨后崩"的机制。

片段 3：SAC 的学习率联动与内部缓冲

        self.policy_opt = torch.optim.Adam(self.policy.parameters(), lr=args.lr)
        self.q_opt = torch.optim.Adam(self.q.parameters(), lr=args.lr)
        self.log_alpha = torch.tensor(np.log(args.alpha), requires_grad=True, device=device)
        self.alpha_opt = torch.optim.Adam([self.log_alpha], lr=args.lr)  # α 随扫描联动

    # 更新时的目标值：对未观测区域外推有界（双 Q 取小），且熵项把动作朝高熵拉
    def update(self, batch):
        with torch.no_grad():
            next_act, next_logp = self.policy.sample(batch["next_obs"])
            q1t, q2t = self.q_target(batch["next_obs"], next_act)
            target = batch["rew"] + self.gamma * (1.0 - batch["done"]) * (
                torch.min(q1t, q2t) - self.alpha * next_logp)

解读：读这段要抓两个事实。（1）扫描 --lr 时，SAC 的策略、双 Q、温度三个优化器同步变化，这是实现约定，不是巧合；报告结论时应表述为"整套优化配置"的敏感度。反过来说，SAC 对 lr 的宽容也来自这套结构：目标网络把 Bellman 目标平滑成慢变量，双 Q 取小压住外推，这两件事都发生在更新路径上，与 η 无关，等于给大步长装了减震器。（2）对比片段 2 可以看到本质差异：PPO 的 η 每批只能通过裁剪做"事后补救"，而 SAC 的每步更新都穿过一层结构化的平滑，η 更接近纯粹的收敛速度参数。

片段 4：对数横轴的敏感度图

    for results, label, marker in ((ppo_results, "PPO", "o"), (sac_results, "SAC", "s")):
        if results:
            xs = [lr for lr in lr_list if lr in results]
            ys = [results[lr][0] for lr in xs]
            ax.plot(xs, ys, marker=marker, label=label)
    ax.set_xscale("log")                    # 学习率按数量级取点，横轴必须对数刻度
    ax.set_xlabel("learning rate")
    ax.set_ylabel("final eval return (last 3 means)")

解读：学习率天然按数量级变化（1e-4 → 3e-4 → 1e-3），线性横轴会把它们挤成一团，对数刻度才能看出形状：是单调上升、倒 U 形的甜点区，还是左侧陡降。两条算法画同一张图时，y 轴范围会被 PPO 的差配置拉大，反而衬托出 SAC 曲线的平坦，"平坦"本身就是结论。曲线形状（而不只是极差数字）告诉你甜点区在哪、往哪个方向调更安全。

以实跑为准的预期：PPO 的极差通常是 SAC 的 3～5 倍，学习率调错时 PPO 付出成百点代价，SAC 的波动明显更小。2 万步预算下 PPO 本就没充分收敛，1e-4 的"差"有一部分来自预算不足；把 --max-steps 提到 6 万再跑，1e-4 的排名会上升，但 1e-3 的崩坏通常仍在。所有数字以实跑为准。

常见坑

  • 把单种子扫描当铁证：单次运行的结果里混着种子噪声。本章明确声明这一点：结论用于看趋势；要拿可靠数字，按练习 4 扩成多种子平均。
  • 不同配置用不同预算：不能因为"1e-4 太慢就多跑一会儿"，那会把敏感度实验变成"耐心实验"。每个配置的环境步数必须一致。
  • 忘记 SAC 的 α 学习率跟着变：本实现里温度优化器用的也是 --lr。扫描学习率时 α 的调整速度同时改变，结论应表述为"整套优化配置"的敏感度。
  • 用"最佳评估点"代替"最终性能"：最佳点是单一时刻的运气值，不同配置之间可比性差。统一用最后三次评估的均值。
  • 直接改 args.lr 而不拷贝配置：循环里原地修改会让所有配置共享同一份被污染的 args，事后无法还原每个结果对应的完整配置。用 Namespace(**vars(args)) 复制。

练习与思考

  1. 把扫描点扩到 5 个（如 5e-5,1e-4,3e-4,1e-3,3e-3），观察两种算法的敏感度曲线形状有什么不同。★
    提示
    只看极差是否变化、最优 lr 是否漂移。点多之后曲线形状（单调上升还是倒 U）比单个数字信息量更大，尤其看 PPO 在 3e-3 处会不会直接崩。
  2. 固定 --lrs 1e-3，把 PPO 的 --epochs 从 10 调到 4 再跑一次，预测并观察性能变化。为什么减少复用轮数能救回一些性能？★
    提示
    有效步长 ≈ η × epochs × 梯度尺度，epochs 从 10 减到 4 相当于学习率乘以 0.4。可以再对比 1e-3/4 轮与 4e-4/10 轮的两组结果是否接近。
  3. 对 SAC 再扫一个旋钮：把 --tau 设为 0.001、0.005、0.02（保持学习率最优），比较极差。SAC 对学习率更敏感还是对 τ 更敏感？★★
    提示
    把 run_sweep 的循环变量从 lr 换成 tau，或手动跑三次抄结果。τ 影响目标网络平滑度，与学习率的作用机制不同，预期 SAC 对 τ 比对 lr 更敏感。
  4. 把单种子扫描扩展成 3 个种子平均：每个配置跑 seed 0/1/2，用平均最终性能重算极差。极差会变大还是变小？为什么？★★
    提示
    在 run_sweep 里再套一层种子循环，最终性能取所有种子均值。种子间方差被平均掉后，剩下的才是真正的"配置差异"，极差通常变小且更可信。
  5. 为 PPO 实现"KL 自适应学习率"：每次更新后监控近似 KL，超过目标值就把学习率乘 0.8、低于目标一半就乘 1.05，并设上下限。重新扫描，看敏感度是否下降。★★★
    提示
    在 train_ppo_once 的更新循环里统计 KL 后修改 optimizer.param_groups[0]["lr"]。这是许多 PPO 实现中"KL 自适应调度"的简化版，能把你从"选 η"变成"选 KL 目标"。

小结

  • 敏感性实验 = 控制变量 + 单旋钮扫描；本章只动学习率，其余全部冻结，训练函数与上一章逐字相同。
  • 有效步长 ≈ η × epochs × 优势梯度尺度；PPO 的裁剪不限制批量总步长，因此对 η 更挑剔，η 一大，320 次每批更新会把策略推离信任域。
  • 两个指标：极差（最坏情况损失）与相对敏感度（归一化后的抗调能力）；口径统一用最后三次评估均值。
  • 本章配置下 PPO 的极差通常数倍于 SAC；SAC 在 1e-4 ~ 1e-3 内表现稳定，调试成本更低，但注意 α 的学习率也在联动。
  • 单种子扫描只用于看趋势；可靠结论需要多种子平均，这是所有调参实验的通用纪律。
  • 下一章换第三个旋钮：探索。PPO 的熵正则与固定噪声对比 SAC 的最大熵与自动温度，谁的探索更"持久"。
