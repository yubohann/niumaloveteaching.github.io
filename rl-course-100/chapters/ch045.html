第二篇 · 离策略方法与 SAC

第 045 章：SAC的探索与利用平衡

把 SAC 的探索旋钮拧到三个位置，几乎不探索、标准探索、强探索，在 Pendulum-v1 上对比评估回报、策略动作标准差与摆角覆盖熵，看清"探索得越广"与"考分越高"为什么不是一回事。

  • 主题：最大熵目标 / 自动温度与行为指标
  • 关键公式：J(π) = Σ 𝔼[r(st,at) + α·H(π(·|st))]
  • 预计学时：50 分钟
  • 前置章节：第 044 章

学习目标

  • 理解 SAC"最大熵"目标里温度系数 α 的角色：探索被写进优化目标，不再依赖外挂噪声。
  • 掌握目标熵（target entropy）与 log_std 的关系，能说清 α 自动调节的反馈回路。
  • 实现三种探索配置（exploit / balanced / explore），用动作标准差与覆盖熵两个行为指标量化探索水平。
  • 会解释评估回报与探索广度之间的"倒 U 型"关系，以及不同任务该往哪边偏。
  • 掌握"确定性策略评估性能、随机策略诊断行为"的两套口径，不把它们混为一谈。

背景与动机

探索与利用的取舍是所有 RL 算法的核心矛盾：探索不足会卡在局部最优（永远不敢尝试更快的那条轨迹）；探索过度则策略永远在抖动，学到的分布用不上。传统做法是手工给动作加噪声（如 DDPG 的 OU 噪声），效果全凭调参直觉：噪声加在动作上，策略本身还是确定性的，探索与利用在时间上是"分时复用"的关系，训练后期关噪声、训练前期开噪声，两者无法共存。

SAC 换了一个更优雅的写法：把策略熵直接加进目标函数，并让温度系数 α 自动匹配一个目标熵。探索成为优化的一部分，不再是外部工件。本章把三个环节（目标熵、α、策略随机度）分开操作，用同一套 SAC 跑三组对照。你会看到一个反直觉但重要的事实：训练时的探索量与最终考分并不成正比，拉高探索往往先让评估回报变差，而探索不足又会在更晚的时候决定性能上限。

核心原理

1. 最大熵目标

SAC 优化的目标是"回报 + 熵"的加权和，期望回报只是其中的一项：

J(π) = Σt 𝔼[ r(st, at) + α · H( π(·|st) ) ] H 是策略分布的熵；α 越大，策略越愿意随机

符号说明：r(st,at) 是单步奖励，H(π(·|st)) 是策略在该状态下的微分熵，α 是温度系数（trade-off 权重）。这个目标的解落在"回报与随机性的最优点"：在回报相同的情况下，熵越高的策略越被偏好，最优确定性动作要等 α 降到 0 才会出现。好处是策略天然保持一定随机性，采样数据覆盖更广，价值函数不易在单一路径上过拟合。

把它写成软价值的形式更能看清 α 的去向：V(s) = 𝔼a~π[Q(s,a) − α·log π(a|s)]。展开后，这个定义对策略取最大时恰好给出"softmax 形式的策略"，温度 α 越小分布越尖锐、越大越平坦。这个结论解释了两件事：其一，最大熵策略天然带有探索性，不需要外挂噪声；其二，α 同时扮演"熵在价值里的价格"与"策略分布的平滑程度"两个角色，这正是第 035 章"奖励缩放等价于改熵价格"的来源。

2. 自动温度与目标熵

α 手工调很痛苦，SAC 的自动调节把 α 的更新方向与"当前熵 − 目标熵"的差距挂钩：

L(α) = −𝔼[ log α · ( log π(a|s) + H̄ ) ] 策略太随机时 α 下降；太确定时 α 上升。标准目标熵 H̄ = −dim(A)

符号说明：log π(a|s) 是采样动作的对数概率（熵的负估计），H̄ 是目标熵（一维动作取 −1.0）。当策略熵高于目标，括号里的项为正，梯度方向让 α 变小；反之 α 变大，形成负反馈回路。目标熵 H̄ = −0.1 意味着"几乎不需要随机性"，α 会被压到接近 0；H̄ = −1.0 是论文的经验配置，在 Pendulum 这类一维动作任务上表现均衡。另一条更粗暴的控制路径是固定 α 不学习：温度锁死，探索水平由你指定。

3. 用行为指标量化探索

"探索了多少"不能只看训练回报，本章用两个行为量：

动作标准差 σ̄ = means[ exp(log_std(s)) ]   ·   覆盖熵 Hcov = −Σb pb·log pb 后者把摆角划成 12 个扇区，统计随机策略在各扇区的访问分布

σ̄ 度量"策略自己有多随机"（直接来自网络的 log_std 输出）；Hcov 度量"状态空间被踩过多少"。把两个读数放在一起看才能区分"随机但原地打转"与"系统性地扩大覆盖"，这正是行为诊断存在的意义。覆盖熵的上限是 ln 12 ≈ 2.48（均匀盖满全部扇区），只会小幅摆动的策略通常在 0.5～1.2 之间。

数值例子：两种摆角分布的覆盖熵

把摆角划成 12 个扇区，统计随机策略访问各扇区的频率，再套 H = −Σp·ln p：

均匀盖满：12 个扇区各占 1/12，H = ln12 ≈ 2.485，这是本指标的理论上限。

集中在四个扇区：访问比例 p = [0.4, 0.3, 0.2, 0.1]，H = 0.4×0.916 + 0.3×1.204 + 0.2×1.609 + 0.1×2.303 ≈ 0.37 + 0.36 + 0.32 + 0.23 = 1.28。注意其中 8 个扇区从未被访问，对求和无贡献。

只在两个扇区摆动：p = [0.5, 0.5]，H = ln2 ≈ 0.693。

解读：三个数字对应三种行为画像，2.48 是"全空间巡检"，1.28 是"活动范围覆盖三分之一"，0.69 是"在半个空间里来回摆"。本章实验里 explore 组的覆盖熵会向 2 靠拢，exploit 组常常掉到 1 以下，balanced 组位于两者之间。把覆盖熵与 σ̄ 并排看，还能区分"原地抖动"（σ̄ 高但覆盖熵低）与"有方向的巡检"（两者都高）。

4. 行为指标的口径细节

动作标准差 σ̄ 读的是网络输出，而实际动作还要经过 act_scale 与 tanh 两层变换，两者的换算值得写清楚：有效动作噪声约为 act_scale·σ·(1−tanh2μ)。Pendulum 的 act_scale=2，当 μ≈0（摆位于水平附近）时 1−tanh²μ≈1，σ=0.5 对应约 1.0 的动作噪声，占 ±2 力矩区间的四分之一；当 |μ|=1 时 1−tanh²μ≈0.42，同样的 σ 只剩约 0.42 的噪声。也就是说"策略认为自己多随机"与"动作实际多随机"会随状态相差一倍以上，比较不同配置时读数必须来自同一批状态，本章固定 5 个随机回合并用同一套环境点，正是为了这个口径。

覆盖熵也有估计口径问题：五个回合约 1000 个样本分到 12 个扇区，插值熵估计的系统偏差约 (k−1)/(2n)=(12−1)/(2×1000)≈0.006，可以忽略；若把回合数降到 1（约 200 个样本），偏差升到约 0.028，而且"某扇区一次都没被访问"的概率明显上升，读数会系统性偏低。这就是 --probe-episodes 不能取 1 的算术理由，也提示比较覆盖熵时必须固定样本量。

5. 与 PPO 动作噪声的对照

把本章的探索机制与第 022 章 PPO 的动作空间噪声对照，差异集中在三个层面。其一，噪声参数的作用范围：PPO 的噪声尺度是全局的、由人工时间表管理；SAC 的 σ(s) 是状态相关的网络输出，策略可以为需要精调的状态调小 σ、为远离目标的状态保持大 σ。其二，训练与执行的绑定关系：PPO 的噪声在评估时直接关闭，探索是外挂部件；SAC 的随机性写在策略定义里，确定性评估只是取分布的均值。其三，控制原理不同：PPO 靠加噪声扩大动作覆盖、再靠优势筛选，SAC 把熵直接写进最优性条件，策略分布的形态本身参与价值学习。这份差异也解释了行为指标为什么必须用随机策略测量：SAC 的探索强度是一个积分量，等于"状态分布 × 该状态 σ(s)"在访问分布上的平均，单一数字装不下这层信息，确定性口径则会把这一层整体抹掉。

三种配置的探索水平还可以用"熵奖励的相对权重"直接比：explore 固定 α=0.5，balanced 的 α 稳定在 0.2 上下，两者在策略损失里的熵项权重相差约 2.5 倍；若把策略熵按 H≈1.5 估算，这一权重差对应每步约 0.45 个价值单位的目标差异，与 Pendulum 单步奖励量级（0.1～1.5）同阶，足以改变策略在"精确控制"与"保持随机"之间的取舍。这也是 explore 组动作长期抖动、评估回报最差的直接原因。

实现思路与设计

三种配置

配置目标熵温度系数预期行为
exploit−0.1自动调节α 快速塌缩到很小，几乎纯利用
balanced−1.0自动调节SAC 标准配置，探索与利用平衡
explore不适用（温度固定）固定 0.5持续强探索，跳过 α 的优化步骤

数据流

训练循环与第 044 章一致：采样 → 存入均匀回放池 → 每步一次 SAC 更新 → 每 3000 步评估并做行为诊断。诊断部分两套口径并行：评估用确定性策略（mean_action）测最终性能；探测量化用随机采样策略跑 5 个回合，统计动作标准差、平均 |动作|、摆角覆盖熵。三种配置同种子、同步数预算，唯一变量是温度路径。

两套口径为什么要分开，可以用数字说明：explore 组固定 α=0.5，动作标准差常在 0.5 以上，若评估也走随机策略，同一策略两次评估的回报差可以到 100 分以上，三种配置的排序会被噪声淹没；反过来，若行为诊断也走确定性策略，所有组测出的 σ̄ 都是"网络输出"本身，覆盖熵全部退化为单点访问（H=0），探索水平完全测不出来。因此评估问"策略真实水平"，诊断问"策略的随机行为"，两问各用各的口径，日志里也分列呈现。把两列直接写进表头（例如 eval_det 与 probe_stoch）是防止后续读日志的人混口径的最省事办法。

模块划分

组件职责关键点
MODE_CONFIG把配置名映射到目标熵 / 固定温度配置式开关，算法主体不动
SAC.alphaexplore 模式返回常数 0.5固定温度时跳过 log_alpha 的优化步骤
measure_exploration随机策略跑回合，统计 σ̄、|a|、覆盖熵从观测 [cosθ, sinθ] 反推摆角划扇区
日志 / 汇总表打印评估回报、σ̄、覆盖熵、α评估与诊断口径分开，避免混用

参数默认值作用与取值理由
--modesexploit,balanced,explore三种探索强度依次训练，同种子对照

三种配置的预期读数整理成一张对照表，跑完实验后逐行核对：

读数exploit（−0.1）balanced（−1.0）explore（固定 0.5）
α 终值约 0.05，被压得很低约 0.2 附近恒为 0.5
动作标准差 σ̄最低中等最高，可达 0.5 以上
摆角覆盖熵约 1.0 以下约 1.2～1.8接近 2
评估回报（确定性口径）收敛快但上限不稳通常最好，约 −180～−190最差，约 −300 上下
主要风险过早锁定次优策略几乎没有，综合最稳动作长期抖动，学不进细节

核对的原则是"先行为、后成绩"：如果 explore 组的覆盖熵没有明显高于 balanced，说明固定温度没有生效，先查 fixed_alpha 分支；如果 exploit 组的 α 没有降下去，先查目标熵的符号与量级。

与前一章的差异点

  • 第 044 章改数据采样分布；本章数据侧完全不动，只改温度系数与目标熵。
  • SAC.alpha 在 explore 模式下变成固定常数，update() 增加"是否更新 α"的分支。
  • 新增 measure_exploration()：行为层面的探索诊断（σ̄、覆盖熵），这是前面章节没有的指标。
  • 汇总口径从"批次 |TD|"换成"动作 std + 覆盖熵"，把抽象概念落到可观测行为。

关键代码与解读

片段 1：配置表与温度属性的两条路径

MODE_CONFIG = {
    "exploit":  {"target_entropy": -0.1, "fixed_alpha": None},   # 目标熵低 → 几乎只利用
    "balanced": {"target_entropy": -1.0, "fixed_alpha": None},   # SAC 论文标准配置
    "explore":  {"target_entropy": -1.0, "fixed_alpha": 0.5},    # 温度锁死，持续强探索
}

class SAC:
    def __init__(self, obs_dim: int, act_dim: int, action_scale: float,
                 mode: str, args):
        cfg = MODE_CONFIG[mode]              # 配置只在这一处分流，后续代码完全共享
        self.target_entropy = cfg["target_entropy"]
        self.fixed_alpha = cfg["fixed_alpha"]        # 非 None 表示温度固定不学习
        self.log_alpha = torch.tensor(np.log(args.alpha_init), requires_grad=True)
        self.opt_q = torch.optim.Adam(
            list(self.q1.parameters()) + list(self.q2.parameters()), lr=args.lr)
        self.opt_policy = torch.optim.Adam(self.policy.parameters(), lr=args.lr)
        self.opt_alpha = torch.optim.Adam([self.log_alpha], lr=args.lr)

    @property
    def alpha(self) -> torch.Tensor:
        """explore 模式返回固定的 0.5；其余模式返回自动调节值。"""
        if self.fixed_alpha is not None:
            return torch.tensor(self.fixed_alpha)     # 固定温度路径
        return self.log_alpha.exp().clamp(1e-4, 10.0) # exp 保正 + 上下限防爆

解读：（1）把探索配置抽成一张表，是本章"只改一个维度"实验设计的关键，exploit 与 balanced 只差两个字符（−0.1 对 −1.0），explore 走完全不同的固定温度路径。（2）alpha 属性里两条路径合流：调用方永远只写 self.alpha，不需要知道它是学的还是固定的。（3）自动路径用 exp(log_alpha) 保证正值（α 不能为负），clamp(1e-4, 10) 再兜两层底：下界防塌缩到 0 导致熵项失效，上界防爆炸。（4）explore 模式的 log_alpha 参数仍然存在、优化器也仍然创建，只是更新步骤被跳过，代码路径统一，少一类分支 bug。

片段 2：熵项在更新里的两个落点

    def update(self, batch: dict, args) -> dict:
        obs, act = batch["obs"], batch["act"]
        rew, next_obs, done = batch["rew"], batch["next_obs"], batch["done"]

        with torch.no_grad():
            next_act, next_logp = self.policy.sample(next_obs)
            q_next = torch.minimum(self.q1_target(next_obs, next_act),
                                   self.q2_target(next_obs, next_act))
            backup = rew + args.gamma * (1.0 - done) * (q_next - self.alpha * next_logp)
            # 熵项 α·logπ 在这里进入目标值：α 越大，"随机"在价值里越值钱

        q1 = self.q1(obs, act)
        q2 = self.q2(obs, act)
        q_loss = F.mse_loss(q1, backup) + F.mse_loss(q2, backup)
        self.opt_q.zero_grad()
        q_loss.backward()
        self.opt_q.step()

        new_act, logp = self.policy.sample(obs)
        q_pi = torch.minimum(self.q1(obs, new_act), self.q2(obs, new_act))
        policy_loss = (self.alpha * logp - q_pi).mean()   # 熵奖励同样由 α 加权
        self.opt_policy.zero_grad()
        policy_loss.backward()
        self.opt_policy.step()

        # explore 模式固定温度，不更新 log_alpha
        if self.fixed_alpha is None:
            alpha_loss = -(self.log_alpha * (logp + self.target_entropy).detach()).mean()
            self.opt_alpha.zero_grad()
            alpha_loss.backward()
            self.opt_alpha.step()

解读：熵项出现在三个落点，这是理解 SAC 探索机制的全部钥匙。（1）目标值里的 −α·next_logp：软价值 = 奖励 + 折扣后的（Q − α 熵），α 越大，价值函数越"认可随机动作"。（2）策略损失里的 α·logp − q_pi：最小化它既要提高 q_pi，又要把 logp 压得更负（熵更大），两个力由 α 调配比例。（3）α 自身的损失 −(log_alpha·(logp + target_entropy))：括号为正（当前熵高于目标）时梯度把 log_alpha 往下推。（4）explore 模式跳过第 3 个落点，α 恒定，于是"强探索"成为一个永不收手的常驻项，不再随训练调整。

片段 3：把探索量化成数字

@torch.no_grad()
def measure_exploration(agent: SAC, env, episodes: int, n_bins: int = 12):
    """用随机策略跑若干回合，量化探索行为。"""
    stds, act_abs, bins, returns = [], [], [], []
    for _ in range(episodes):
        obs, _ = env.reset()
        done = False
        ep_ret = 0.0
        while not done:
            obs_t = torch.as_tensor(np.asarray(obs, dtype=np.float32)).unsqueeze(0)
            _, log_std = agent.policy.forward(obs_t)
            stds.append(float(log_std.exp().mean().item()))   # 策略自己的随机度
            action = agent.act(obs, deterministic=False)      # 与实际互动同一条策略
            act_abs.append(float(np.abs(action).mean()))
            # Pendulum 观测为 [cos θ, sin θ, θ̇]，由前两维反推摆角
            angle = np.arctan2(float(obs[1]), float(obs[0]))
            bins.append(int((angle + np.pi) / (2 * np.pi) * n_bins) % n_bins)
            next_obs, rew, terminated, truncated, _ = env.step(action)
            ep_ret += rew
            obs = next_obs
            done = terminated or truncated
        returns.append(ep_ret)
    counts = np.bincount(np.asarray(bins), minlength=n_bins).astype(np.float64)
    probs = counts / max(counts.sum(), 1.0)
    coverage_H = float(-np.sum(probs[probs > 0] * np.log(probs[probs > 0])))
    return {"action_std": float(np.mean(stds)), "act_abs": float(np.mean(act_abs)),
            "coverage_H": coverage_H, "mean_ret": float(np.mean(returns))}

解读：（1）action_std 直接读网络的 log_std 输出，回答"策略认为自己该多随机"；注意它和实际动作幅度不是一回事（tanh 压缩会改变有效尺度）。（2）摆角反推用 arctan2(sinθ, cosθ)，取值 [−π, π]，再线性映射到 12 个扇区，这是把连续状态空间"离散化后测覆盖率"的通用做法。（3）覆盖熵只统计 p > 0 的扇区（避免 log 0），上限 ln12 ≈ 2.48。（4）整段用 @torch.no_grad()：诊断只读不写，不产生任何训练副作用。（5）注意这里用的是随机采样策略，行为诊断必须与实际交互策略同口径，确定性策略会低估探索。

python code/ch045.py                                    # 三种配置各 18000 步，CPU 约 4–6 分钟
python code/ch045.py --quick                            # 快速跑通：4000 步/配置，约 1 分钟
python code/ch045.py --modes balanced,explore --max-steps 25000   # 单独对比两种

预期：explore 的动作 std 与覆盖熵最高（σ̄ 可达 0.5 以上、覆盖熵接近 2），但评估回报最差（约 −300 上下）；exploit 的 α 被压到 0.05 量级、覆盖熵掉到 1 以下，收敛快但上限不稳；balanced 通常给出最好的评估回报（约 −180 ~ −190）。以实跑为准，评估只有 5 个回合，单个点抖动 ±50 属正常。

常见坑

  • 把 α 当纯超参数手调，又开着自动调节：两者互相干扰。要么用目标熵控制（推荐），要么固定 α 并停掉优化器；本章用 fixed_alpha 明确区分两条路径。
  • 目标熵符号写反：连续动作空间的标准目标是负值（−dim(A)），写成正数会让 α 无界增长，策略越来越随机、Q 值学不出来。症状：日志里 α 持续增大到 1 以上。
  • 用确定性策略测覆盖熵：确定性策略访问分布窄，覆盖熵低估真实探索水平。行为诊断必须用与环境交互的随机策略，评估才用确定性策略。
  • 评估回报突然变好就以为探索到位：Pendulum 评估只有 5 个回合，±100 的抖动可能只是运气。看趋势要看多个评估点的中位数，单个峰值说明不了问题。
  • log_std 下限设得太宽（−20）导致误判：网络可以把 log_std 压到极负而不报错，σ̄ 读数会"虚假地小"。想比较探索强度时先确认三种配置用的是同一套 clamp 边界。

练习与思考

  1. 把 MODE_CONFIG["explore"] 的固定温度改成 0.05，跑一次。预测它的覆盖熵与 balanced 谁高，再验证。★
    提示
    只改一个数字，看日志 3000/6000 步的覆盖熵。固定 0.05 接近均衡配置后期的 α 水平，预计覆盖熵落在 balanced 与 exploit 之间。
  2. 把 balanced 的目标熵改成 -2.0 再改成 -0.3，做一张"目标熵 − 评估回报 − 覆盖熵"小表。哪一档最好？★★
    提示
    目标熵越低，α 被压得越小、策略越确定。Pendulum 的最优策略本身接近确定（临近目标时频繁微调），过高的目标熵会一直扰动动作。
  3. 给 measure_exploration 增加"最大连续同向动作步数"指标，用它区分"随机抖动"与"持续摆动"两种探索形态。★★
    提示
    统计动作符号连续不变的游程长度再取均值：随机抖动的游程接近 2，策略性的摆动探索游程更长。这个指标能把 explore 的"噪声"与 balanced 的"有方向的探索"分开。
  4. 把 log_std 的下限从 −20 提到 −1.5（改 GaussianPolicy.forward 的 clamp），重跑 balanced。为什么即使 α 变小，σ̄ 也不会掉到 0？★★
    提示
    clamp 下限限制了策略能变得多确定。观察 exploit 配置的 σ̄ 与评估回报变化：硬下限迫使策略一直带噪声，对任务有利还是有弊要跑数据说话。
  5. 用同一套代码跑 --env MountainCarContinuous-v0（步数调到 30000+），比较覆盖熵差别，解释稀疏奖励型任务为什么更需要高探索。★★★
    提示
    MountainCar 的成败取决于"先退后进"的探索，低熵策略几乎必然卡在谷底；覆盖熵可换成位置维度统计。先确认环境在附录白名单内，超参数预算相应放大。

小结

  • SAC 把探索写进目标函数：J(π) = 回报 + α·熵，α 由"当前熵与目标熵的差距"自动调节，探索成为每一时刻最优性条件的一部分。
  • 目标熵决定探索的基准线：−0.1 偏利用、−1.0 均衡；固定 α 是另一条更直接的控制路径，两者不可同时启用。
  • 探索水平要用行为指标衡量，动作标准差 σ̄ 与摆角覆盖熵，它们与评估回报之间通常是倒 U 型关系：探索太少卡局部，太多学不细。
  • 本实验里 explore 覆盖最广但考分最差，exploit 收敛快但有卡局部的风险，balanced 综合最好且最稳。
  • 覆盖熵的三个参照值：均匀盖满 12 个扇区约 2.48，覆盖三分之一约 1.28，只在两个扇区摆动约 0.69；读数落在哪个区间对应哪种行为画像。
  • 外挂噪声与最大熵的区别在时间结构：噪声是分时开关，最大熵把探索写进每一时刻的最优性条件，策略与探索不再互相排斥。
  • 下一章拧动"另一颗稳定器"：目标网络的软更新系数 τ，它决定目标值跟得多快、训练有多稳，并会与本章的探索强度产生交互。
