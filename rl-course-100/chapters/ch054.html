第二篇 · 离策略方法与 SAC

第 054 章：SAC的迁移学习

先在标准重力（g=10）的 Pendulum 上练好一个 SAC，再把全部权重搬到重力加大到 g=16 的"更快摆杆"上微调，与从零开始训练做对照，用初始评估、达标步数和最终成绩三个角度量化"白捡的起点"值多少样本。

  • 主题：迁移学习 / 参数热启动（warm start）
  • 关键公式：transfer: θ(0) = θsrc；scratch: θ(0) ~ 随机初始化
  • 预计学时：55 分钟
  • 前置章节：第 053 章

学习目标

  • 理解迁移学习中"源任务 → 目标任务"的参数复用机制，以及热启动（warm start）与从头训练的本质差别。
  • 掌握用动力学参数（重力 g）构造"同构不同难度"任务对的方法。
  • 实现权重打包/加载（策略、双 Q、目标网络、温度系数），并对比 scratch 与 transfer 两种目标模式的完整训练。
  • 解释负迁移（negative transfer）为什么可能发生，以及如何用初始评估与达标步数一起判断迁移是否划算。
  • 会区分"参数迁移"与"数据迁移"两种复用手法，知道回放池该不该跨任务保留。

背景与动机

"每个任务都从零训练一个智能体"在真实场景里非常昂贵：换了地面摩擦、换了负载、仿真参数微调 20%，难道每次都要几百万步重新采样？迁移学习的答案是：大部分技能在不同参数的任务间是共享的，需要重新适应的只是时间尺度与力度。

本章构造一对"同构不同难度"的任务：同一个 Pendulum，重力从 10 调到 16。摆杆下落更快、需要更频繁的力矩修正，但"把杆子甩起来"的宏观技能完全一致。这正是检验参数迁移的理想场景：结构可复用，尺度要微调。判断迁移是否划算有一个朴素的框架：先问"两个任务的最优解在参数空间里有多远"，再问"重新探索的代价有多大"。距离近、探索贵，迁移的收益最大；距离远（比如把摆杆换成四足机器人）、或者目标预算极短，源参数反而可能把优化带进坏区域，这就是负迁移的两个高发条件。

核心原理

1. 参数迁移的两种形态

把源任务学到的参数 θsrc 作为目标任务的初始点，然后在目标数据上继续训练：

scratch: θ(0) ~ 随机初始化   ·   transfer: θ(0) = θsrc 两者共享同一目标环境、种子、预算与评估协议，唯一变量是初始参数

符号说明：θ 是全部可学习参数（策略、双 Q、目标网络、温度系数），θ(0) 是训练起点。迁移的有效性取决于最优参数的"距离"：如果两个任务的 Q* 与 π* 在参数空间里足够近，目标训练只需局部微调；如果距离很远，源参数可能把优化带进一个坏盆地，这就是负迁移的机理。重力 10 到 16 改变了动力学时间尺度，但力矩方向的模式不变，参数距离通常"中等"。Q 网络与策略共享这种结构，所以整包迁移比只迁移策略更充分。

数值例子：重力变化把任务改了多少

Pendulum 的角加速度为 θ̈ = (3g/2l)·sinθ + (3/(ml²))·u，取 m=l=1、力矩上限 |u|≤2。逐项对比 g=10 与 g=16：

小角度振荡频率：线性化后 ω = √(3g/2)，g=10 时 ω ≈ 3.87 rad/s，g=16 时 ω ≈ 4.90 rad/s。周期比 √(10/16) ≈ 0.79，即新任务的摆动周期缩短约 21%（频率提高约 26%），需要更频繁的力矩修正。

可悬停角度范围：保持静止所需力矩为 |u| = (g/2)·|sinθ|。g=10 时 |sinθ| ≤ 0.4，对应 |θ| ≤ 23.6°；g=16 时 |sinθ| ≤ 0.25，对应 |θ| ≤ 14.5°。可控制的"稳定锥"从约 ±24° 收窄到约 ±15°。

解读：动力学系数变大 60%、摆动周期缩短约 21%、稳定区域收窄约四成，这些变化共同解释了实验现象：源策略的"挥杆节奏"整体偏慢，直接上场初始评估会明显变差；但"先退后进、对称摆动"的动作结构完全通用，微调只需重新校准时间尺度，所以达标步数大约减半。

2. 目标网络与温度系数也要搬

SAC 的参数不止策略：双 Q、双 Q 目标网络、温度系数 α。只迁移策略会导致"策略和评论家不同步"，新策略的动作在旧 Q 那里得不到正确评价，早期梯度会先花在修复 Q 上。本章把六组参数全部打包迁移；同时把 α（log_alpha）也带过去，让探索水平的起点落在源任务终点，从头调整的过程就此免去。注意目标网络必须跟着搬：否则 bootstrap 目标瞬间跳变，价值估计要重新收敛一遍。

用账本理解"不同步"的代价：假设策略参数迁移后，新动力学下的动作分布与源任务相比偏移了半个标准差，而 Q 网络还停留在源任务的价值尺度上，那么早期 TD 目标里的偏差与"从零开始学 Q"量级相当，却额外背上了"策略已经会动"的复杂度；策略损失里的 Q 项方向不准，更新会先把两者重新对齐，这段"对齐期"就体现为迁移后前几百步评估曲线的抖动。整包迁移把六组参数放进同一个坐标起点，对齐期最短。这也是练习 3 里"只迁移策略"值得单独跑一次的原因：它能把这个对齐期的成本直接量出来。

3. 迁移的收益怎么量化

  • 初始评估：迁移瞬间（零目标步数）的成绩。它不一定好，源策略对新动力学是次优的，但它反映"起点质量"；
  • 达标步数：达到同一阈值（−400）所需的目标环境步数，直接对应"省了多少样本"；
  • 最终评估：目标预算耗尽后的成绩，检查迁移有没有把训练带进更差的局部解。

三个指标各有角色：初始评估低是正常现象（源策略没适配新动力学），真正决定"划不划算"的是达标步数，它衡量省下的探索时间。两种模式的预期读数对照如下：

指标scratch（随机初始化）transfer（源权重热启动）
初始评估（零目标步数）约 −1180，随机策略水平约 −900，源策略直接上场，明显低于源任务的 −200
达标步数（−400 阈值）约 6000约 3000，约为前者的一半
最终评估基准持平或略优
任务差距拉大时不变（反正从零开始）初始评估变差、达标优势缩小，逐渐退化为 scratch

读表顺序：先看初始评估确认"参数确实搬过来了"（若 transfer 与 scratch 的初始评估几乎相同，先检查 load_state 是否真的执行），再看达标步数判断收益，最后用最终评估确认没有负迁移。

实现思路与设计

数据流

流程分两段。源任务：在 g=10 的 Pendulum 上训练 20000 步，打包六组参数（state_dict()）并落盘。目标任务：对 scratch 与 transfer 分别执行，先做一次"初始评估"（零目标步数）、再进入统一的 train_agent 循环训练 15000 步，记录达标步数与最终评估。两种模式同种子、同预算、评估环境同 g，唯一差异是训练前是否 load_state(source_ckpt)。

模块划分

组件职责关键点
make_pendulum(seed, g)创建指定重力的摆杆环境通过 env.unwrapped.g = g 修改动力学参数
SAC.state_dict/load_state打包与恢复六组参数包含 log_alpha；copy_ 就地写入保证优化器见到同一张量
train_agent源任务与目标任务共用的训练循环回放池挂在 agent 上（agent.buffer），便于统一控制
run_target_mode训练 scratch 或 transfer 并汇总指标训练前先测"初始评估"
源模型落盘保存 source_pendulum_g10.pt供复现与后续章节使用

关键超参数

参数默认值作用与取值理由
--source-g / --target-g10 / 16任务对的动力学差距；g 大 60%，难度提升明显但不改变任务结构
--source-steps20000源任务训练步数；源策略质量决定迁移上限
--target-steps15000两种目标模式的统一预算
--threshold−400达标阈值，用于达标步数统计
--eval-every3000目标模式评估点更密，便于捕捉早期差异

源任务预算取 20000 步的原因也值得说明：源策略质量决定迁移的上限。如果源任务只练到"勉强能立住"，它的 Q 函数对大范围状态的价值估计还很粗糙，搬到新动力学上后，微调要花大量步数修正这些粗糙估计，迁移收益被吃掉。反之，源任务练得越接近收敛，参数落在"好盆地"的深处，目标微调只需要沿局部梯度走。实践中的折中是：源任务预算略大于"达标所需步数"即可，本章 20000 步对 Pendulum 而言已接近该任务的中等水平，既能提供有效起点，也不至于把总实验时长翻倍。

与前一章的差异点

  • 第 053 章在训练过程中逐步改变任务（课程）；本章训练任务不变，改的是参数初始化来源（迁移）。
  • 新增 SAC.state_dict/load_state 与源模型落盘；前面章节只保存过单个网络的 state_dict。
  • 训练循环抽成 train_agent，源任务与两种目标模式共用同一段代码。
  • 指标新增"迁移后初始评估"，用来分离"起点质量"与"学习能力"。

关键代码与解读

片段 1：任务对与六组参数的打包/恢复

def make_pendulum(seed: int, g: float):
    """创建指定重力的摆杆环境（g 是 Pendulum 的动力学参数）。"""
    env = gym.make("Pendulum-v1")
    env.unwrapped.g = g  # 直接修改底层参数：g=10 为默认，g=16 更难
    env.reset(seed=seed)
    env.action_space.seed(seed)
    return env

    # SAC 类里：
    def state_dict(self) -> dict:
        """打包全部可学习参数，供迁移使用。"""
        return {
            "policy": self.policy.state_dict(),
            "q1": self.q1.state_dict(),
            "q2": self.q2.state_dict(),
            "q1_target": self.q1_target.state_dict(),
            "q2_target": self.q2_target.state_dict(),
            "log_alpha": self.log_alpha.detach().clone(),   # 属参数，走不了 buffer 通道，需单独处理
        }

    def load_state(self, ckpt: dict) -> None:
        self.policy.load_state_dict(ckpt["policy"])
        self.q1.load_state_dict(ckpt["q1"])
        self.q2.load_state_dict(ckpt["q2"])
        self.q1_target.load_state_dict(ckpt["q1_target"])
        self.q2_target.load_state_dict(ckpt["q2_target"])
        with torch.no_grad():
            self.log_alpha.copy_(ckpt["log_alpha"])   # 就地拷贝：优化器引用不变

解读：（1）env.unwrapped.g = g 是构造"同构任务对"的最简方式：重力在 reset 之前设置，训练与评估环境必须用同一个 g，否则"训练和裁判不一致"，成绩虚高。（2）state_dict() 打包六项：策略、双 Q、双目标网络、log_alpha。少搬任何一项都会造成不同步，比如只搬策略不搬 Q，早期梯度会先花在修复价值估计上。（3）log_alpha 是可学习参数，不在 buffer 通道里，走不了 load_state_dict，必须手动 copy_。（4）用 copy_ 就地拷贝：写成 self.log_alpha = ckpt["log_alpha"] 会留下隐患，优化器还在更新旧张量，温度系数从此"冻结"且不报错，这是最隐蔽的坑之一。

片段 2：目标模式的初始评估，先量起点，再开跑

def run_target_mode(mode: str, source_ckpt: dict, args):
    """mode: scratch（随机初始化）/ transfer（从源任务权重初始化）。"""
    set_seed(args.seed)  # 两种模式同种子，控制变量
    env = make_pendulum(args.seed, args.target_g)
    eval_env = make_pendulum(args.seed + 100, args.target_g)
    obs_dim = env.observation_space.shape[0]
    act_dim = env.action_space.shape[0]
    action_scale = float(env.action_space.high[0])
    agent = make_agent_with_buffer(obs_dim, act_dim, action_scale, args)

    if mode == "transfer":
        agent.load_state(source_ckpt)        # 唯一的分叉：换一个初始参数

    initial_eval = evaluate(agent, eval_env, args.eval_episodes)
    print(f"\n===== 目标模式 {mode}：迁移后初始评估 {initial_eval:.1f} =====")
    stats = train_agent(agent, env, eval_env, args, args.target_steps, mode,
                        log_every=args.eval_every, threshold=args.threshold)
    final_eval = evaluate(agent, eval_env, args.eval_episodes)
    best_eval = max([h[1] for h in stats["history"]] + [final_eval])
    return {"mode": mode, "initial_eval": initial_eval, "best_eval": best_eval,
            "final_eval": final_eval, "solved_at": stats["solved_at"],
            "history": stats["history"], "elapsed": stats["elapsed"]}

解读：（1）两种模式的代码路径只差一行 load_state，整洁的对照实验不需要复制两套训练逻辑。（2）初始评估在训练循环之前执行：对 transfer 这是"源策略直接上场"的成绩，对 scratch 是随机策略成绩。差值就是"源的直接价值"：它通常为正但幅度有限（新重力让挥杆节奏不对），别因为初始评估的绝对分低就误判迁移失败。（3）best_eval 从历史 + 最终评估里取最大：既看潜力也看结局。（4）参数迁移不搬数据：回放池从零开始填（make_agent_with_buffer 新建），旧动力学的经验不会污染新任务。这是"参数迁移"与"数据迁移"（第 057 章会用）的分界点。

片段 3：统一训练循环，回放池挂在 agent 上

def train_agent(agent: SAC, env, eval_env, args, steps: int, tag: str,
                log_every: int, threshold: float = None):
    obs, _ = env.reset(seed=args.seed)
    ep_ret = 0.0
    ep_returns = []
    history = []          # (步数, 评估回报)
    solved_at = None
    t_start = time.time()

    for step in range(1, steps + 1):
        if step <= args.start_steps:
            action = env.action_space.sample()
        else:
            action = agent.act(obs, deterministic=False)
        next_obs, rew, terminated, truncated, _ = env.step(action)
        agent.buffer.add(obs, action, rew, next_obs, float(terminated))
        obs = next_obs
        ep_ret += rew
        if terminated or truncated:
            ep_returns.append(ep_ret)
            ep_ret = 0.0
            obs, _ = env.reset()

        if step % args.update_every == 0 and agent.buffer.size >= min(args.start_steps, 1000):
            agent.update(agent.buffer.sample(args.batch_size), args)

        if step % log_every == 0:
            eval_ret = evaluate(agent, eval_env, args.eval_episodes)
            history.append((step, eval_ret))
            recent20 = np.mean(ep_returns[-20:]) if ep_returns else float("nan")
            print(f"[{tag}] 步数 {step:6d} | 近20回合回报 {recent20:8.1f} | 评估 {eval_ret:8.1f}")
            if threshold is not None and solved_at is None and eval_ret >= threshold:
                solved_at = step
                print(f"[{tag}] 首次达到评估回报 {threshold}（步数 {step}）")

    elapsed = time.time() - t_start
    return {"history": history, "solved_at": solved_at, "elapsed": elapsed}

解读：（1）循环读写 agent.buffer：回放池归属智能体，迁移时"人走池留还是人走池也走"的决策被显式化，本章是"搬人不搬池"。（2）预热步数 args.start_steps 对 transfer 仍然执行：前 1000 步用随机动作重新试探新动力学，是廉价且必要的"适应期"。（3）threshold 作为可选参数：源任务训练不需要达标统计（传 None），目标模式传 −400。（4）tag 让同一段代码打印出不同前缀（源任务/scratch/transfer），日志能并行对照，统一循环的最大好处是"两种模式的行为差异必然来自初始参数，代码路径完全一致"。

完整可运行脚本（附录）：code/ch054.py

python code/ch054.py                 # 源 20000 步 + 两种目标模式各 15000 步，CPU 约 4–6 分钟
python code/ch054.py --quick         # 快速跑通：约 1 分钟
python code/ch054.py --target-g 20   # 加大任务差距，观察迁移收益缩小

预期：transfer 的初始评估好于随机策略（约 −900 对 −1180），但远达不到源任务的 −200；达标步数通常只有 scratch 的一半左右（3000 对 6000），最终评估持平或略优。把 --target-g 调到 20 以上，初始评估变差、达标优势缩小，动力学差距越大，迁移越接近从头训练。以实跑为准。

常见坑

  • 只迁移网络、不迁移优化器状态：Adam 的动量从零开始，第一轮更新的有效步长可能偏大。本章接受这一点（最简单），复杂场景可把优化器 state_dict 一并迁移。
  • log_alpha 直接重新赋值，未就地拷贝：优化器更新的是旧张量，温度系数"冻结"且不报错。必须用 copy_。
  • 评估环境忘记改 g：训练用 g=16、评估用默认 g=10，成绩虚高且误导结论。任务对的每个环境都要显式设置。
  • 用初始评估判断迁移成败：源策略在目标动力学上通常立刻变差，初始评估低是正常现象；真正的判据是达标步数与最终评估。
  • 把源任务的回放池一起搬过去：旧动力学下的 (s,a,r,s′) 与新的转移动力学不一致，价值回归会被系统性带偏。参数迁移不搬数据。

练习与思考

  1. 把 --target-g 依次设为 12、16、24，记录三种差距下 transfer 的达标步数。差距多大时迁移收益消失？★
    提示
    保持源任务固定（g=10），只改目标。把三组"初始评估/达标步数"与 scratch 对应值列表对比，找到 transfer 优势消失的阈值。
  2. 把目标预算砍到 --target-steps 5000，迁移的优势变大还是变小？先预测再验证。★★
    提示
    预算越短，"省下的前期探索"占总预算比例越大，迁移的相对收益通常更明显，这也是现实中迁移最有价值的场景：不允许长时间训练。
  3. 实现"只迁移策略、Q 网络随机初始化"的第三种模式，比较它与全量迁移、scratch 的达标步数。★★
    提示
    在 run_target_mode 里加 mode == "policy-only" 分支，只 load_state_dict(ckpt["policy"])。思考：评论家不同步会让早期梯度先花在哪里。
  4. 实现"冻结躯干"变体：迁移后先冻结策略的 body 参数 3000 步，只训练输出层与 Q 网络，再解冻全部。它与全量微调有什么区别？★★★
    提示
    冻结通过 requires_grad 加"只把可学参数传给优化器"实现；解冻后需重建优化器或把参数加回去。观察冻结期评估曲线，特征复用是否让前期更稳。
  5. 把源任务换成 g=16、目标任务 g=10（反向迁移），重复实验。迁移在两个方向上对称吗？★★★
    提示
    只交换 --source-g 与 --target-g。g=16 的策略节奏更快，往慢任务迁移要"放慢动作"；结合结果讨论迁移难度是否与方向有关。

小结

  • 参数迁移把源任务的策略和评论家作为目标任务的起点，收益来自"跳过前期探索"；它并不直接提高最终水平。
  • 本章用重力参数构造同构任务对：g=10 训练、g=16 微调；六组参数（含温度系数）整体打包迁移。
  • transfer 的初始评估通常差于源任务成绩，但达标步数约为 scratch 的一半；任务差距越大，迁移收益越小。
  • 迁移有效的前提是任务间存在可复用的结构；判断依据是"达标步数 + 最终评估"的组合，起点分数只作参考。
  • 重力变化的量化：动力学系数从 15 升到 24（+60%），摆动周期缩短约 21%（频率提高约 26%），可悬停角度从约 ±24° 收窄到约 ±15°，这解释了"节奏要重新校准、结构可以复用"。
  • 负迁移的两个高发条件：任务间最优解距离太远、目标预算过短来不及修复；出现时应退回 scratch 或只迁移部分网络。
  • 下一章把"一对任务"扩展成"一组任务"：让单个策略通过任务标识同时服务多个重力参数的摆杆，研究多任务学习的共享与干扰。
