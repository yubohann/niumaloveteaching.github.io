第二篇 · 离策略方法与 SAC

第 036 章：SAC的连续动作重参数化

同一个策略损失，两种梯度估计方式：让梯度穿过采样值（重参数化），还是让 Q 只当权重、方向全靠 log π 的梯度？在 Pendulum 上把两者摆在一起，用"相邻梯度余弦"给你答案。

  • 主题：策略梯度估计器 / 方差对比
  • 关键公式：pathwise：∇θJ = 𝔼[∇a(α log π − Q)·∇θa]；score：∇θJ = 𝔼[(α log π − Q)·∇θlog π]
  • 预计学时：55 分钟
  • 前置章节：第 035 章

学习目标

  • 理解重参数化技巧（reparameterization trick）的原理：把"采样"改写成"确定性函数 + 外部噪声"。
  • 对比 pathwise 与 score（似然比）两种策略梯度估计器，说清为什么前者方差更小。
  • 实现两种估计器共享同一套 SAC 代码的开关，并新增"相邻策略梯度余弦相似度"诊断量。
  • 在 Pendulum-v1 上读出两条评估曲线与梯度一致性指标的差距。

背景与动机

连续动作的 SAC 策略参数最怕一件事：梯度估计的方差太大。策略梯度定理给出的通用形式是"log π 的梯度 × 一个权重"，它不需要动作可导，但副作用是，同一状态下采样不同动作，梯度方向可以完全相反，只能靠大量样本平均出正确方向。

重参数化换了个思路：如果采样可以写成 a = gθ(ξ)，ξ 是与参数无关的外噪声（比如标准正态），那么梯度就能像普通网络一样"穿过"采样操作，直接知道"参数往哪改，动作就变多少，Q 就涨多少"。同一个样本携带的信息量因此大得多。

直觉上两者都"应该"收敛到同一个最优解，但实际训练里的样本效率差距往往是数倍。本章不靠背诵结论，把两种估计器放在同一段训练预算里跑，并且量化梯度噪声，用一个简单但有效的诊断：相邻两次策略梯度的余弦相似度。噪声越大，方向越随机，余弦越接近 0 甚至为负。

核心原理

1. 两种梯度的数学形式

演员目标（取负号后最小化）是 𝔼[α·log πθ(a|s) − Q(s,a)]。两种估计它的梯度：

pathwise：∇θJ = 𝔼[ ∇a(α log π − Q) · ∇θ aθ(s,ξ) ]
score：∇θJ = 𝔼[ (α log π(a|s) − Q(s,a)) · ∇θ log πθ(a|s) ]，a 视为常数

pathwise 把 Q 对动作的梯度 ∇aQ 当作信息来用：它告诉你"动作往哪个方向调 Q 会变大"，再通过 ∇θa 翻译成参数方向。score 完全不用 ∇aQ，只用标量权重给整个 log π 的梯度缩放，这相当于把向量信息压缩成了一个标量。

把高斯策略展开，pathwise 的写法会更具体。取 a = μθ(s) + σθ(s)·ξ（重参数化形式，ξ∼N(0,1)），由链式法则：

∇θJ = 𝔼ξ[ ∇a(α log π − Q) · ( ∇θμ + ξ · ∇θσ ) ] ∇θa 被拆成"均值方向"与"标准差方向"两部分，ξ 只充当系数

这个式子说明：一次采样提供了两个方向的完整信息，均值往哪调、标准差往哪调，都由同一个 ∇a 同时决定。score 估计器没有这份信息，它只能根据"这个动作得到的好坏"整体缩放 ∇θlog π，好坏方向分不到均值与标准差上。

2. 为什么 pathwise 方差更小

形式上看，score 估计器的随机来源是整个动作采样（每个样本的方向都可能不同）；pathwise 的随机来源只有 ξ 带入的 Q 值波动。SAC 的 Q 网络是局部光滑的，∇aQ 在相邻动作上高度相关，所以即使采样动作不同，梯度方向也大体一致。一句话：pathwise 把"试错"从参数空间搬到了噪声变量空间，让每个样本的梯度更接近"正确方向"。反过来看，当 Q 网络在某段动作区间上很平坦（∇aQ 接近 0）时，pathwise 也会失去方向感，这说明两种估计器各有软肋，选型要结合 Q 的质量。两种软肋都可以量化对照：pathwise 的梯度幅值正比于 ∇aQ，策略接近收敛、Q 在 μ 附近达到极值时它趋近于 0；score 的 ∇log π 里含 (a−μ)/σ2 因子，等于 ξ/σ，策略越接近确定性，这个因子越大。σ=1 时它约为 ξ；σ=0.05 时同样偏离 1 倍标准差的样本给出约 20 倍幅值，方差放大到约 400 倍。训练后期自动温度把 σ 压到 0.05 量级（第 031 章算过 −1 nat 对应 σ≈0.045），score 的梯度噪声比会成百倍恶化，这正是它越到后期越吃力的算术原因。

一个常被忽略的前提

重参数化要求动作分布可写出"确定性变换 + 无参噪声"，且变换对参数可导。高斯（μ+σξ）天然满足；而 tanh 压缩后的分布靠雅可比修正项把密度换算回去，所以采样处少了 log(1−y²) 这一项，梯度就是错的。第二个前提是噪声分布必须与参数无关：ξ 一旦沾上 θ（例如用策略自己的输出去生成噪声），"确定性变换 + 外部噪声"的结构就破坏了，梯度的无偏性也随之失效。第三个前提是 Q 要（近似）对动作可导且光滑：如果 Q 在动作空间里是阶跃式的，∇aQ 处处为零或巨大，pathwise 的优势无从谈起。这也是离散动作不能用重参数化的深层原因：抽样本身不可导，动作空间也没有"局部方向"可言。

3. 用余弦相似度量化梯度噪声

记录每次策略更新时参数梯度的展平向量 gt，计算相邻两次的余弦：

cos(gt−1, gt) = ⟨gt−1, gt⟩ / (‖gt−1‖·‖gt‖) 方向越一致 → 越接近 1；纯噪声 → 期望为 0

它不需要额外前向，只多存一个向量。对 256 宽的两层 MLP 来说开销可忽略。实践上：pathwise 的余弦通常在 0～0.3 甚至更高；score 的余弦常在 0 附近徘徊，这正是"随机试错"的直接证据。

数值例子：两种估计器的方差手算

用一个能算出解析解的最小例子：动作 a = μ + ξ，ξ∼N(0,1)，损失 f(a) = −(a−1)2，要估计的目标是 ∂J/∂μ 在 μ=0 处的值。真值：∂J/∂μ = 𝔼[−2(μ+ξ−1)] = −2(μ−1)，在 μ=0 处等于 2。

pathwise 单样本估计：g = −2(ξ−1)。均值 = 2（正确）；方差 = 4，标准差 = 2。

score 单样本估计：g = f(a)·∇μlog N(a;μ,1) = −(ξ−1)2·ξ（因为 (a−μ)/σ2 = ξ）。均值 = −𝔼[ξ3−2ξ2+ξ] = 2（同样正确）；方差 = 𝔼[ξ2(ξ−1)4] − 4 = 34 − 4 = 30，标准差 ≈ 5.48。

解读：两个估计器都无偏，但 score 的方差是 pathwise 的 30/4 = 7.5 倍，达到同样的梯度精度需要约 7.5 倍的样本。这就是"样本效率差一个档位"的定量版本。数字也可以自己验证：用 10 万个标准正态样本分别算两个估计的经验均值与方差，应当分别落在 2 ± 0.02 与 4、30 附近。

补上中间两步推导，方便手工复核：score 估计量的二阶矩 𝔼[g2] = 𝔼[ξ2(ξ−1)4]，展开后为 𝔼[ξ6] − 4𝔼[ξ5] + 6𝔼[ξ4] − 4𝔼[ξ3] + 𝔼[ξ2]；代入标准正态的矩（0、1、3、15，奇数阶为 0，二阶 1、四阶 3、六阶 15），得到 15 + 18 + 1 = 34，减去均值的平方 4，方差为 30。做精度换算：若希望梯度估计的标准误差降到 0.1，pathwise 需要约 4/0.01 = 400 个样本，score 需要约 30/0.01 = 3000 个样本，7.5 倍的关系在"样本预算"口径下同样成立。

4. 余弦相似度的定量参照线

余弦要从"定性指标"升级成"定量指标"，需要一个能推导、可复算的参照线。把相邻两次梯度写成 gt = s + nt：s 是共同的真方向，nt 是每次独立的零均值噪声；设噪声总方差与信号总方差之比为 ρ，在高维参数空间里可以推出 𝔼[cos(gt−1, gt)] ≈ 1/(1+ρ)。用 1000 维向量模拟三组参数：ρ=1 时余弦约 0.50，ρ=9 时约 0.10，ρ=49 时约 0.02，与公式吻合。

把这条线套回实验读数：pathwise 的余弦 0.1 意味着噪声方差约为信号方差的 9 倍；score 的余弦 0.02 意味着 49 倍。也就是说，score 每一步的梯度里，真实方向只占能量的约 2%，其余是会互相抵消的抖动；要达到 pathwise 同等的方向精度，score 的样本量约需放大 5 倍，这与方差手算得到的 7.5 倍在同一量级，两个独立口径互相印证。余弦还可以当训练的哨兵：如果 pathwise 的余弦长期为负，说明梯度方向与上一轮系统性相反，通常意味着学习率过大或 Q 的局部极值被反复穿越，这是应当考虑降低学习率的信号。

把 batch=256 代进上面两个方差，还能预演练习第 2 题的结果：pathwise 的梯度标准误差约 2/√256≈0.125，score 约 5.48/√256≈0.34；要让 score 也达到 0.125，需要约 (5.48/0.125)2≈1920 个样本，相当于 batch 放大约 7.5 倍。batch 变小则双方误差一起变大，但 score 基线更高，差距在低预算下被进一步拉开。由于回放池允许重复采样，加大梯度 batch 不额外消耗环境交互，这正是"算力换样本效率"在实际项目里的可选手段。

实现思路与设计

模块划分

组件职责关键点
sample(obs, reparameterize)同一采样接口支持 rsample() 与 sample()rsample 的动作可回传梯度；sample 的动作是常量
distribution()单独暴露分布对象score 分支需要在同一个（已 detach 的）x 上重算 log π
update_critic()评论家更新两种估计器共用；目标里的动作始终用 rsample
update_actor()按 estimator 二选一计算策略损失只改损失表达式，其余流程一致
梯度诊断展平策略梯度、算范数与余弦在 step() 之前记录，反映"这次更新用的方向"

关键超参数

参数默认值作用与取值理由
--estimatorspathwise,score本章唯一自变量；同种子依次训练
--max-steps15000两种估计器的步数预算；score 在这个预算内通常学不完
--batch-size256两种估计器共享；样本数相同才能比"样本效率"
--lr3e-4共享学习率；score 若单独调大 lr 会失去对比意义
--eval-every3000记录滚动 200 次更新的梯度统计

数据流

每种估计器：set_seed → 随机探索垫池 → 每步 update_critic（目标动作始终重参数化采样，与本实验无关）+ update_actor（按 estimator 走两条损失表达式之一）→ 在 backward 与 step 之间采集梯度向量、算范数与相邻余弦 → 每 3000 步评估并记录滚动 200 次的梯度统计。诊断的开销与策略参数量成正比：两层 256 宽的 MLP 只有几万个参数，克隆与余弦的成本可以忽略；若策略换成循环网络或更宽的 MLP，可改为每 N 步采样一次梯度，这是后几章处理大网络时的常见折中。

为什么两个估计器要共享 batch 与学习率

把 batch 大小固定为 256、学习率固定为 3e-4，是为了让"样本效率"这个词有明确含义：两种估计器每步消费同样多的样本、以同样的步长更新，回报差距只能来自梯度质量。若给 score 单独调大学习率，它也许能追平回报，但那是"更多有效位移"换来的，噪声问题被掩盖了；若给 score 单独加大 batch，它同样能改善，但那说明的是"需要更多样本"，这本身就是一条有价值的结论。本章选择最严格的对照口径，把差异留在明面上，实验结论才能迁移到"算力有限时该选谁"这类真实问题上。需要补充说明的是，score 估计器本身也有可优化空间，例如减去批内均值基线、使用更小的 σ 参数化，这些改进留作练习，不影响主结论的方向。

与前一章的差异点

  • 第 035 章动的是奖励数值；本章动的是策略损失的梯度路由，奖励与网络结构完全不变。
  • GaussianPolicy 新增 reparameterize 开关与独立的 distribution() 接口。
  • 新增两个诊断量：策略梯度范数与相邻梯度余弦相似度（prev_grad 缓存上次梯度）。
  • 实验组织从"三种奖励尺度"换成"两种梯度估计器"。

关键代码与解读

片段 1：一个开关，两种采样

    def sample(self, obs, deterministic=False, reparameterize=True):
        """reparameterize=True 时梯度可穿过采样；False 时采样值被 detach。"""
        dist = self.distribution(obs)
        if deterministic:
            return torch.tanh(dist.mean) * self.act_scale, None, dist
        x = dist.rsample() if reparameterize else dist.sample()
        y = torch.tanh(x)
        action = y * self.act_scale
        log_prob = dist.log_prob(x) - torch.log(1.0 - y.pow(2) + 1e-6)
        return action, log_prob.sum(dim=-1), dist

解读：两种估计器的分岔从采样这一步就开始了。（1）rsample() 与 sample() 的差别只有一个：前者的结果带计算图（梯度可沿 ξ 穿过），后者是常量。pathwise 拿到可导的 action，score 拿到常量的 action，同一行代码，两种算法。（2）返回值新增了第三个元素 dist：score 分支需要"对已固定的 x 重新计算 log π"，保留分布对象可以避免手写 μ、σ 的重复代码。（3）雅可比修正 −log(1−y²+1e-6) 对两种估计器都不可省，无论梯度怎么走，log π 的数值必须是对的。

片段 2：update_actor 的两个分支，本章的实验开关

        if self.estimator == "pathwise":
            # 重参数化：动作带梯度，Q 的梯度直接回传到 mu / sigma
            action, logp, _ = self.policy.sample(obs, reparameterize=True)
            q_act = torch.min(self.q1(obs, action), self.q2(obs, action))
            policy_loss = (self.current_alpha * logp - q_act).mean()
        else:
            # 得分函数：先用 no_grad 采出动作，Q 与 log π 都用它
            with torch.no_grad():
                dist_det = self.policy.distribution(obs)
                x = dist_det.sample()
                y = torch.tanh(x)
                action = y * self.policy.act_scale
                q_act = torch.min(self.q1(obs, action), self.q2(obs, action))
            # 重建分布并对同一个 x 计算 log π：x 是常量，梯度只走分布参数
            dist = self.policy.distribution(obs)
            logp = (dist.log_prob(x) - torch.log(1.0 - y.pow(2) + 1e-6)).sum(dim=-1)
            adv = (q_act - self.current_alpha * logp.detach()).detach()
            policy_loss = -(adv * logp).mean()

解读：两种估计器的全部差异就藏在这十七行里，逐点对照着看。（1） pathwise 分支：动作来自 reparameterize=True 的采样，q_act 对它可导，backward() 会自动走通 ∂Q/∂a · ∂a/∂θ 这条链，Q 对动作的"方向信息"完整传进 μ、σ。（2） score 分支的第一约束是"同一个动作"：先在 no_grad 下采出 x、算出 q_act，再重建分布对同一个 x 计算 logp。如果 Q 与 log π 用了两次不同的采样，优势估计与方向估计来自不同的点，估计器有偏。（3）权重 adv = (q_act − α·logp.detach()).detach() 整体切断梯度：score 估计器里它不是被优化的对象，只是给 ∇log π 乘的标量系数。（4）损失符号：score 写成 −(adv·logp).mean()，pathwise 写成 (α·logp − q_act).mean()，两者都在最小化同一个目标，只是梯度路径不同。

片段 3：梯度诊断，在 backward 与 step 之间取证

        self.policy_optimizer.zero_grad()
        policy_loss.backward()

        # 诊断：策略梯度的范数与相邻梯度的余弦相似度
        grad_vec = torch.cat([
            p.grad.reshape(-1) for p in self.policy.parameters()
            if p.grad is not None
        ])
        grad_norm = float(grad_vec.norm().item())
        grad_cos = float("nan")
        if self.prev_grad is not None:
            # 维度一致（网络结构没变），可以直接做余弦
            grad_cos = float(F.cosine_similarity(
                grad_vec.unsqueeze(0), self.prev_grad.unsqueeze(0)).item())
        self.prev_grad = grad_vec.detach().clone()

        self.policy_optimizer.step()

解读：十行诊断代码，把"梯度噪声"从一个抽象概念变成日志里的一列数字。（1）取证时机固定在 backward() 之后、step() 之前：此刻 p.grad 里正是"这次更新将要使用的方向"。放在 zero_grad() 之后梯度已清空、放在下一轮则被覆盖。（2）展平拼接的顺序由 parameters() 的迭代顺序决定，同一网络内顺序稳定，因此相邻两次的向量天然对齐，可以直接做余弦。if p.grad is not None 的过滤防止未参与本轮图的参数混入空值。（3）cosine_similarity 自带数值保护，梯度接近零时不会除零；prev_grad 用 detach().clone() 存档，避免引用被下一轮污染。（4）第一次更新没有上一份梯度，返回 NaN，消费端会用 math.isnan 过滤掉它。

片段 4：滚动窗口，让梯度统计可读

        if buf.size >= args.batch_size:
            agent.update_critic(buf.sample(args.batch_size))
            actor_stats = agent.update_actor(buf.sample(args.batch_size))
            grad_norm_window.append(actor_stats["grad_norm"])
            if not math.isnan(actor_stats["grad_cos"]):
                grad_cos_window.append(actor_stats["grad_cos"])
            grad_norm_window = grad_norm_window[-200:]   # 只保留最近 200 次
            grad_cos_window = grad_cos_window[-200:]

解读：窗口机制很小，但决定了实验结论的可靠性。（1）单次更新的余弦在 −1 到 1 之间剧烈跳动，直接看会像噪声；最近 200 次的均值才反映"梯度方向的系统一致性"，这正是两种估计器的本质差异所在。（2）math.isnan 过滤掉序列开始时的那一个 NaN，防止平均值被污染。（3）两种估计器在完全相同的位置做同样的统计：网格结构、初始化、环境种子、batch 大小全一致，唯一差别是损失表达式，这就是"差距可归因"的前提。

完整可运行脚本（附录）：code/ch036.py

python code/ch036.py           # pathwise vs score：CPU 约 5–8 分钟
python code/ch036.py --quick   # 快速跑通：约 1 分钟
python code/ch036.py --estimators score --max-steps 30000   # 给 score 更多预算

以实跑为准：pathwise 评估回报常在 −250 ~ −150，同预算下 score 往往还在 −800 ~ −500 挣扎；score 的相邻梯度余弦接近 0（约 ±0.02），pathwise 明显为正（0.1 上下）。给 score 加倍预算差距会缩小，它本身能学会，只是样本效率差一个档位。

常见坑

  • score 分支里 Q 与 log π 用了两个不同的采样动作：adv 与 logp 必须基于同一个 a，否则估计器有偏。修复：用同一个 x 同时算 Q 和 log π。
  • score 分支忘了解开动作的梯度路径：若直接用重参数化的动作去乘 ∇log π，梯度里混入 pathwise 项，对比就失去意义。修复：采样与 Q 都在 no_grad 下完成。
  • tanh 压缩后漏掉雅可比修正：无论哪种估计器，log π 都要减去 log(1−y²+ε)；漏掉它时策略会系统性地偏爱接近 ±1 的饱和动作。
  • 在 optimizer.step() 之后才读梯度：一旦进入下一轮 zero_grad() 梯度就没了。修复：诊断读取固定在 backward 与 step 之间。
  • 用单次余弦值做结论：单次值抖动大，必须用滚动窗口均值；两种估计器的对比还应在多个种子上复现。

练习与思考

  1. 把 score 分支里的 adv 减去批内均值（adv = adv - adv.mean()）作为基线，重跑对比。基线有没有改善梯度余弦？★
    提示
    减基线不改变梯度的期望，只降低方差。观察梯度余弦与评估回报是否朝 pathwise 的方向靠拢一点。
  2. 把 --batch-size 从 256 降到 64，两种估计器的差距会扩大还是缩小？为什么？★★
    提示
    样本越少，score 的方差劣势越明显。对比两种估计器在新 batch 大小下的评估回报之差。
  3. 给 pathwise 也加一层人工噪声：在 rsample() 得到的 x 上加 0.5 * torch.randn_like(x)（保持梯度路径），观察梯度余弦变化。★★
    提示
    这模拟"动作噪声过大"的极端情况。噪声进入 Q 后梯度方向被打乱，余弦应明显下降。
  4. 实现第三种估计器 pathwise_detach_q：动作仍重参数化，但在 Q 外面套 .detach()（只保留熵项的 pathwise 梯度）。解释它与 score、纯 pathwise 的关系。★★★
    提示
    Q 被 detach 后策略收不到"动作方向"信息，只剩 α·logp 的梯度，策略会一味增大熵。比较三者的评估回报排序。
  5. 用 numpy 抽 10 万个标准正态样本，分别计算 −2(ξ−1) 与 −(ξ−1)2ξ 的经验均值与方差，与框中给出的 4 和 30 对照。★
    提示
    只写五行代码：xi = np.random.randn(100000)，两次 np.var。若方差对不上，检查是否误把 (a−μ)/σ² 写成了 1/σ。

小结

  • 重参数化把采样写成"确定性变换 + 外部噪声"，让 Q 对动作的梯度能直接指导策略参数；score 估计器只用标量权重，方向信息被压缩。
  • Pendulum 上 pathwise 明显快于 score：同样 15000 步，回报差距常在一倍以上。
  • 相邻梯度余弦是量化方差的有效诊断：pathwise 为正，score 在 0 附近徘徊。
  • 两种估计器的实现差异集中在 update_actor() 的损失表达式与"动作是否 detach"一处，其余代码可以完全共享。
  • 重参数化的成立有三个前提：变换可导、噪声与参数无关、Q 对动作光滑可导；三者缺一，pathwise 的方差优势都会打折。
  • 对照实验的口径要克制：共享 batch 与学习率才能把差异归因到梯度质量，单独给劣势方加资源只能掩盖问题。
