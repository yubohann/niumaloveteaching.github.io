第二篇 · 离策略方法与 SAC

第 042 章：SAC的Q网络过估计分析

在 Pendulum-v1 上分别用 min、mean、single 三种双 Q 组合训练 SAC，再用策略回放得到的真实折扣回报 Gt 给 Q 网络对账，把"过估计"从一句口号变成可测量的偏差数字。

  • 主题：SAC 价值估计诊断 / 双 Q 组合
  • 关键公式：Qmin = min(Q1, Q2)；bias = 𝔼[Q(s,a) − Gt]
  • 预计学时：50 分钟
  • 前置章节：第 041 章

学习目标

  • 理解时序差分（Temporal Difference, TD）学习里过估计的根源：最大化操作与函数逼近误差的联合作用。
  • 掌握 min / mean / single 三种双 Q 组合方式的定义，以及各自偏差符号的直觉。
  • 学会用策略回放的真实折扣回报 Gt 对账 Q 网络：bias = Q(s,a) − Gt。
  • 看懂诊断日志里的三个量，Q 偏差、|Q| 均值、评估回报，以及它们之间的关系。
  • 能解释为什么 SAC 默认选 min：保守偏差是主动选择的工程权衡，估计精度排在其后。

背景与动机

Q 学习的目标值里天然带着一个最大化操作：用"下一个状态下最好的动作"来估计未来价值。只要 Q 网络有误差，最大化就会系统性地挑中被噪声抬高的动作，让估计值持续偏高，这就是过估计（overestimation）。在 actor-critic 里它更危险：策略朝着 Q 大的方向更新，等于主动去利用这些虚假高分，误差被策略自我放大。

SAC 的标准对策是裁剪双 Q（clipped double-Q）：训练两个独立的 Q 网络，目标值取两者较小者。但"min 有用"是个需要证据的结论。本章不满足于相信它：我们用当前策略亲自跑回合、算出每步的真实折扣回报 Gt，再和网络的 Q(s,a) 逐点对账，把三种组合方式的偏差量化成可比数字。

核心原理

1. 过估计从哪里来

设真实价值为 Q*(s,a)，网络估计为 Q̂(s,a) = Q*(s,a) + ε(s,a)，其中 ε 是逼近误差与采样噪声之和（均值近似为 0，但两侧都有）。更新目标里带了最大化：

𝔼[maxa Q̂(s,a)] ≥ maxa 𝔼[Q̂(s,a)] = maxa Q*(s,a) Jensen 不等式：max 是凸函数，误差中"偏大"的那一侧被系统性放大

符号说明：Q̂ 是网络输出，Q* 是真实值，ε(s,a) 是每个状态动作对上的误差，𝔼 对误差分布取期望。等号变成不等号的那一步，就是过估计的全部秘密，误差是对称的，但 max 只挑大的一侧。更糟的是它自我强化：策略更新会去追 Q 高的动作，这些动作被采样得更多、被更新得更频繁，虚假高分越滚越大。这就是"乐观误差 → 策略追高 → 目标更高"的正反馈。

数值例子：对称误差下的偏差方向

第一段，看 max 为什么抬高估计。设一个状态下两个动作的真实价值为 Q* = [10, 9]，网络对每个动作的误差独立地取 +2 或 −2（各 50% 概率），枚举四种等概率组合：

(ε动作1, ε动作2)maxa Q̂
(−2, −2)max(8, 7) = 8
(−2, +2)max(8, 11) = 11
(+2, −2)max(12, 7) = 12
(+2, +2)max(12, 11) = 12
期望10.75

真实最大值是 10，期望却到了 10.75：对称误差经过 max 后被系统性抬高 0.75。这就是过估计的静态来源。

第二段，看三种组合在同一动作上的偏差。取某个被评估的动作，Q* = 10，两个独立网络的误差同样是 ±2 等概率：min 的期望 = 10 + 𝔼[min(ε1,ε2)] = 10 − 1 = 9（低估 1）；mean 的期望 = 10 + 0 = 10（无偏）；single 在静态意义上也无偏。

把第一段再一般化，能读出两个规律。设两个动作的真实价值差距为 g、误差独立地取 ±δ：当 g < 2δ 时，"次优动作被抬高而不抬高最优动作"的组合会污染最大值，四种组合的期望为 Qmax + δ/2 − g/4，偏差等于 δ/2 − g/4；当 g ≥ 2δ 时，最优动作在四种组合里都保持领先，偏差降为 0。也就是说过估计随误差幅度线性增大、随真实动作差距增大而缩小：两个动作半斤八两时最容易吹出虚假高分，"一眼最优"的状态不容易被误差骗到。这解释了为什么过估计在动作难以分优劣的任务里最严重，也提示 single 组的 bias 曲线可能随训练推进先大后小：策略越确定，动作间的 Q 差距越大，偏差的静态成分越小，剩下的正是动态自我放大的那部分。

解读：静态例子解释了符号，动态效应还要补一句：single 的无偏只在"误差独立于目标"时成立，实际训练中它的误差会进入下一轮目标，通过"追高"循环自我放大，这就是本章实验要测的那部分偏差；min 则用 −1 量级的保守代价切断这个循环。SAC 的目标是"偏在安全的方向"，估计精度排在其后。

2. 双 Q 的三种组合方式

对策是训练两个独立网络 Q1、Q2（不同初始化、不同样本顺序，误差近似独立），再用组合方式决定偏差的符号：

Qmin = min(Q1, Q2)   ·   Qmean = (Q1 + Q2) / 2   ·   Qsingle = Q1

直觉：把两个网络当成两次带噪声的测量。取最小相当于"宁可相信更悲观的读数"，期望上 𝔼[min(Q1,Q2)] ≤ Q*，偏差为负；取平均能抵消一半左右的独立噪声，但保留乐观风险；single 没有第二把尺子，偏差随训练自由膨胀。SAC 选 min 的理由是它的错误方向安全：偏保守只会让策略少拿一点分，偏乐观会让策略系统性追错动作；估值更准从来不是它的目标。三种方式的对照：

维度min（默认）meansingle
期望偏差方向偏保守（负）接近零，但保留乐观尾部随训练放大，偏乐观
乐观正反馈被切断被削弱但未切断完整保留
|Q| 尺度较小居中较大
典型 bias 观察接近 0 或略负居中明显为正
代价低估导致策略略保守两种风险各留一半高估可能让策略追错动作

3. 用真实回报给 Q 对账

要测偏差，需要一把与网络完全独立的尺子。最直接的是折扣回报：从回合内时刻 t 出发，

Gt = rt + γrt+1 + γ2rt+2 + … + γT−trT
bias = mean(s,a)~π[ Q(s,a) − Gt ]

符号说明：rt 是时刻 t 的环境奖励，γ 是折扣因子（默认 0.99），T 是回合结束时刻；Gt 完全由环境奖励累计而来，不含任何网络输出，因此可以当"标准答案"。（s,a) 样本由当前策略亲自踩出，测到的是策略实际访问分布上的偏差，正是策略提升所依赖的那个分布。bias 为正是过估计，为负是保守。注意：Gt 到 Pendulum 的 200 步上限处截断，漏掉了此后仍为负的奖励，因此对账基准偏高、bias 被系统性压向负侧；这一偏移对三种估计器完全相同，横向对比不受影响。

测量口径还有两个细节值得写进结论的"注意事项"。第一，Pendulum 回合在 200 步被时间截断，Gt 少了"200 步之后还值多少分"这一截，而后期策略每步奖励约 −1，漏掉的负奖励可以按 γ200−t·|r̄|/(1−γ) 估算：回合开头（t=0）约 γ200×100≈13.4，接近末尾（t=180）约 γ20×100≈82。越靠近回合末尾的采样点负偏越大，整体 bias 被压向负侧，"抬向正侧"的效应无从谈起；三种估计器共享同一偏移，横向比较仍然成立，但 bias 的绝对值不能当成精确定标。第二，Gt 是单条轨迹的实现值，本身带随机性：同一 (s,a) 多次执行会得到不同的 G，因此单点的 Q−G 差值不能逐个解读，必须在几百个采样点上取均值；这也是 --bias-episodes 不能取 1 的原因。

4. 目标值里的熵项

SAC 的 bootstrap 目标是 y = r + γ(1−done)(Q· − α log π(a′|s′))，其中 α 是温度系数、log π 是新策略在下一状态采样动作的对数概率。熵项把"策略有多随机"也折算进价值：同等回报下，策略熵越高越"值得"。

一个常被问到的细节：SAC 的 bootstrap 目标对 a′ 求期望，并没有显式取 max，过估计从哪里来？两条通道仍然存在。其一，函数逼近误差在策略访问分布上并不零均值：高频访问的动作被更多次自举更新，误差里混入了累积的自举偏差，这类成分不会像抽样噪声那样互相抵消。其二，策略提升本身接近"软最大化"：策略损失把概率质量推向 Q 高的区域，等价于做了一次近似 argmax 的选择；当误差与动作相关时，被选中的动作恰好也是误差偏正的动作。两条通道的宏观表现与显式 max 的过估计同源，只是强度更弱。这也是本实验只用 single / mean / min 三组对照就能让偏差分层的原因：三种组合对"偏正误差"的处理方式不同，而误差来源是共享的。

5. 偏差的读数方式：相对值与置信区间

比较不同估计器时，先做一次同比换算。bias 的绝对大小会随 |Q| 尺度一起浮动：|Q| 均值 40 时 8 分的偏差是 20%，|Q| 均值 16 时同样的 8 分是 50% 的失真。把 bias/|Q| 作为相对偏差读数，再对照评估回报，才能判断"这点偏差值不值得处理"。诊断表的三列（bias、|Q|、回报）应当一起读：bias 分层明显而回报接近，说明当前任务对这个量级的偏差不敏感，属于可接受的工程状态。

另一件必须做的事是给 bias 配一个误差棒。平均值来自 5 个回合、约 1000 个采样点，但同一回合内的采样点高度相关，有效样本数更接近"回合数"，"采样点数"会高估信息量。若回合同 bias 的标准差约 30，5 个回合均值标准误差约 30/√5≈13.4，两个估计器差 10 分的排序完全落在噪声范围内；把 --bias-episodes 提到 20，标准误差收缩到 30/√20≈6.7，排序才值得相信。这就是脚本要求多种子复核的算术依据。

实现思路与设计

数据流

每个估计器的完整流程：前 1000 步纯随机探索把回放池填出多样性 → 之后每环境步做一次梯度更新（批量 256）→ 每 4000 步评估一次并同时做两件事：用确定性策略测评估回报、用随机采样策略跑 5 个回合作价值对账 → 24000 步结束后输出汇总行。三种估计器使用同一随机种子串行训练，把"估计器"以外的变量尽量摁住。

对账口径有三个设计决定值得说明。其一，对账回合采用随机采样策略：训练时策略以随机动作与环境交互，只有采样分布上的偏差才能解释训练行为；确定性动作只覆盖均值附近的窄带，测出的偏差会系统性偏小。其二，对账回合数与评估回合分开控制，评估回报要的是"策略真实水平"（确定性），对账要的是"策略访问分布上的平均偏差"（随机性），两者混在一起会让任何一个都不准。其三，三种估计器共用同一种子串行训练：初始化、环境重置、回放池采样序列全部对齐，偏差曲线的分层才可能归因到组合方式本身，随机性的影响被大幅压制。

与前一章的差异点

  • 第 041 章研究温度系数 α 的调度；本章让 α 保持自动调节不变，只改双 Q 的组合方式。
  • 新增 combine() 枢纽方法，让三种口径共享同一套训练代码，避免"复制三份代码各改一处"。
  • 新增 measure_q_bias()：用回放得到的 Gt 做价值对账，这是前几章没有的诊断量。
  • 主流程从"训练一次"改为依次训练三种估计器并输出对比表，把结论建立在同一预算的可比数据上。

关键代码与解读

片段 1：三处共用的双 Q 组合器

    def combine(self, q1: torch.Tensor, q2: torch.Tensor) -> torch.Tensor:
        """按照本章的实验设置组合双 Q 输出。"""
        if self.estimator == "single":
            return q1                        # 只用 Q1：没有第二把尺子，乐观误差无人纠偏
        if self.estimator == "mean":
            return 0.5 * (q1 + q2)           # 取平均：抵消部分独立噪声，但保留乐观风险
        return torch.minimum(q1, q2)         # 默认 min：SAC 标准做法，把误差翻到保守一侧

    @torch.no_grad()
    def q_values(self, obs: torch.Tensor, act: torch.Tensor) -> torch.Tensor:
        """给出 (s,a) 的价值估计，用于过估计诊断。"""
        return self.combine(self.q1(obs, act), self.q2(obs, act))

解读：combine() 是整章的枢纽，它同时被三处调用，目标值的 bootstrap、策略损失里的 q_pi、诊断的 q_values。只改目标值不改策略损失，等于"回归的目标"和"提升的方向"用了两套口径，实验结论直接失真，所以这里坚持一个开关走到底。q_values 上的 @torch.no_grad() 保证诊断只是读取，不积累计算图、不产生训练副作用。

片段 2：一次 SAC 更新的五个步骤

    def update(self, batch: dict, args) -> dict:
        """一次 SAC 更新：目标值 → 双 Q 回归 → 策略提升 → 温度调整 → 软更新。"""
        obs, act = batch["obs"], batch["act"]
        rew, next_obs, done = batch["rew"], batch["next_obs"], batch["done"]

        # 1) 目标值 = r + γ·组合Q′ − α·logπ′；no_grad 说明它只是回归标签
        with torch.no_grad():
            next_act, next_logp = self.policy.sample(next_obs)
            q_next = self.combine(self.q1_target(next_obs, next_act),
                                  self.q2_target(next_obs, next_act))
            backup = rew + args.gamma * (1.0 - done) * (q_next - self.alpha.detach() * next_logp)
            # (1 - done) 只在真终止时归零；Pendulum 的 200 步截断仍要 bootstrap

        # 2) 双 Q 回归：两个网络向同一个 backup 靠拢，分开算损失便于诊断
        q1 = self.q1(obs, act)
        q2 = self.q2(obs, act)
        q1_loss = F.mse_loss(q1, backup)
        q2_loss = F.mse_loss(q2, backup)
        q_loss = q1_loss + q2_loss
        self.opt_q.zero_grad()
        q_loss.backward()
        self.opt_q.step()

        # 3) 策略提升：logp 通常为负，最小化 α·logp 等于鼓励高熵、防止过早塌缩
        new_act, logp = self.policy.sample(obs)       # 重参数化让梯度穿过采样
        q_pi = self.combine(self.q1(obs, new_act), self.q2(obs, new_act))
        policy_loss = (self.alpha.detach() * logp - q_pi).mean()
        self.opt_policy.zero_grad()
        policy_loss.backward()
        self.opt_policy.step()

        # 4) 自动温度：把策略熵拉向目标熵（每个动作维度 −1）
        alpha_loss = -(self.log_alpha * (logp + self.target_entropy).detach()).mean()
        self.opt_alpha.zero_grad()
        alpha_loss.backward()
        self.opt_alpha.step()

        # 5) 软更新目标网络：τ=0.005，让 bootstrap 的目标缓慢跟随主网络
        with torch.no_grad():
            soft_update(self.q1, self.q1_target, args.tau)
            soft_update(self.q2, self.q2_target, args.tau)

解读：五个步骤对应五个"为什么"。（1）目标值只当标签用，no_grad 防止梯度顺藤摸瓜污染目标网络；alpha.detach() 同样关键，α 有自己的优化器，若不断梯度，Q 损失会偷偷改 α。（2）q1、q2 分开算损失再相加，方便在日志里分辨哪个网络学得快，也让"min 的保守性"能在两个网络之间体现。（3）策略损失是 α·logp − q_pi 的均值：q_pi 越大学得越积极，熵项则压住"用高随机性冒充高分"的倾向。（5）软更新里的 soft_update 用 tp.data.mul_(...).add_(...) 原地修改，配合目标网络 requires_grad_(False)，确保目标网络是"死"的。

片段 3：用真实回报 Gt 对账

@torch.no_grad()
def measure_q_bias(agent: SAC, env, episodes: int, gamma: float):
    """跑若干回合，比较 Q(s,a) 与真实折扣回报 G_t 的偏差。

    bias = Q - G_t > 0 表示过估计（乐观），< 0 表示偏保守。
    """
    biases, q_abs = [], []
    for _ in range(episodes):
        obs, _ = env.reset()
        obs_list, act_list, rew_list = [], [], []
        terminated = truncated = False
        while not (terminated or truncated):
            action = agent.act(obs, deterministic=False)   # 按策略实际访问分布采样
            next_obs, rew, terminated, truncated, _ = env.step(action)
            obs_list.append(np.asarray(obs, dtype=np.float32))
            act_list.append(np.asarray(action, dtype=np.float32))
            rew_list.append(float(rew))
            obs = next_obs
        # 从后向前递推：G_t = r_t + γ·G_{t+1}，一次循环算完整个回合
        returns = np.zeros(len(rew_list), dtype=np.float32)
        running = 0.0
        for t in reversed(range(len(rew_list))):
            running = rew_list[t] + gamma * running
            returns[t] = running
        obs_t = torch.as_tensor(np.asarray(obs_list))
        act_t = torch.as_tensor(np.asarray(act_list))
        q = agent.q_values(obs_t, act_t)        # 整段轨迹一次前向，减少 Python 开销
        biases.append((q - torch.as_tensor(returns)).mean().item())
        q_abs.append(q.abs().mean().item())
    return float(np.mean(biases)), float(np.mean(q_abs))

解读：对账分三步走。(a) rollout：用随机采样策略（deterministic=False）跑回合，要测的正是策略训练时实际会遇到的那些 (s,a)。(b) 用一次逆序循环把每个时刻的 Gt 算出来，复杂度 O(T)，无需存前半段的和。(c) 整条轨迹的 (s,a) 一次性喂给 q_values 前向，得到对应的 Q 后取 (Q − G).mean()。返回的第二项 |Q| 均值是重要的辅助量：bias 的绝对大小会随 |Q| 尺度水涨船高，比较不同估计器时要同时看这两列。

python code/ch042.py --quick    # 快速跑通：4800 步/估计器，约 1 分钟，只看趋势
python code/ch042.py --estimators min,single --plot   # 只对比两种并保存曲线

预期：随机策略在 Pendulum 上约 −1200 分；训练 2 万多步后评估回报通常在 −350 ~ −180；single 的 bias 明显为正且 |Q| 尺度更大，min 的 bias 在 0 附近甚至略负，mean 居中。回报差距可能不大，但偏差曲线会稳定分层，以实跑为准，换种子有 ±50 左右的波动。

常见坑

  • 目标值用 min、策略损失却用 Q1：两套口径让"提升方向"和"回归目标"打架，偏差诊断失去意义。修复：一切经过 combine()，三处调用自动统一。
  • 目标网络漏了断梯度：软更新用 tp.data 原地改、目标网络 requires_grad_(False)，二者缺一都可能让优化器顺着目标网络反传到主网络，bootstrap 变成自指，Q 值容易发散。
  • 把 200 步截断当终止：Pendulum 每回合 200 步被 truncated。若 done 把截断也置 1，目标值在回合末尾被砍成 r，价值被系统性低估，诊断出的 bias 整体偏正。
  • 诊断时忘记 no_grad：measure_q_bias 每次评估都跑整段轨迹，不关梯度会白白积累计算图，内存见长、速度变慢，还可能污染 log_alpha 的计算图。
  • 用单次诊断下结论：5 个回合的 bias 方差很大。先固定种子和预算复跑两三遍，确认分层稳定，再写结论。

练习与思考

  1. 只跑 --estimators single，观察 bias 随步数的走势（加 --plot 看右图）。它是持续为正，还是会自行回落？★
    提示
    不用改代码，只改命令行参数。重点看 runs/ch042/q_bias.png：单一网络的偏差不会自行消失，因为目标值里没有任何纠偏机制。
  2. 给 combine() 加一种 max 口径（两个 Q 取最大），跑一次并预测 bias 的方向与量级。为什么它应该比 single 更糟？★
    提示
    复制 min 分支改成 torch.maximum 即可，三处调用会自动统一。max 同时放大了两个网络的乐观误差，是"最乐观"的组合。
  3. 把 measure_q_bias 里的动作改成 deterministic=True，偏差如何变化？解释确定性动作分布与随机动作分布下 Q 误差来源的差别。★★
    提示
    确定性策略只踩少量轨迹，Gt 样本更"窄"，但网络对这些点的拟合通常更好。对比两种口径下 bias 的绝对值，别动训练逻辑。
  4. 把 --bias-episodes 从 5 提到 20，用 np.std(biases) 估算诊断量本身的波动，并给出 bias 均值的粗略置信区间。样本太少时，"single 更乐观"的结论会被噪声淹没吗？★★
    提示
    每个回合约 200 个采样点；回合间 Gt 尺度差异大，先把每个回合的 bias 存成列表再看分布，方差的量级会告诉你需要多少回合。
  5. 在 train_estimator 里按滑动窗口记录 TD 误差（q1_loss 开方），对比三种估计器的 TD 误差与 |Q| 均值。两者是同涨同落吗？比较前为什么要先做归一化？★★★
    提示
    把 agent.update(...) 返回值按窗口累积、评估时打印均值。TD 误差随 |Q| 尺度增长是"水涨船高"，用 |Q| 均值归一化后再比较才有意义。

小结

  • 过估计的根源是"max 操作 + 逼近误差"：最大化把被噪声抬高的动作挑出来，并借策略更新自我强化。
  • 裁剪双 Q 把偏差符号翻到保守一侧：min 的期望低于真值，但切断了乐观正反馈；mean 居中、single 放任。
  • 用策略回放的真实折扣回报 Gt 对账是最直接的诊断：bias = Q − Gt，三种口径必须同种子、同预算对比。
  • 对称误差的静态算例：max 抬高估计 0.75、min 低估 1，mean 无偏；动态训练里 single 的误差会进入下一轮目标并自我放大，这是静态算例之外的部分。
  • 对账有两个口径注意点：截断回合让基准略偏低、单点 G 有随机性；bias 只在几百个采样点上取均值才有意义。
