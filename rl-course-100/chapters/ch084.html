第 084 章：多智能体PPO与SAC对比

让 IPPO 与 ISAC 在同一个 3 智能体协同导航任务上同种子、同评估协议地训练，比较样本效率、最终覆盖率与曲线稳定性，看"on-policy 的多轮裁剪更新"与"off-policy 的回放复用"在多智能体场景下各自擅长什么。

  • 主题：多智能体机制 / 算法公平对比与样本效率
  • 关键公式：Ât,i = δt,i + γλÂt+1,i（共享奖励下的 (T,N) 优势递推）
  • 预计学时：55 分钟
  • 前置章节：第 083 章

学习目标

  • 搭建一次公平的多智能体算法对比：同环境、同网络结构、同学习率、同随机种子、同评估协议。
  • 理解 on-policy（PPO 每批数据只用几轮）与 off-policy（SAC 从回放池反复采样）在多智能体中的样本效率差异来源。
  • 掌握共享奖励下 GAE 的 (T, N) 组织方式：奖励序列只有一条，价值矩阵逐智能体递推。
  • 用"首次达到 50% 覆盖率所需环境步数"作为样本效率的量化代理指标；单看最终回报说明力有限。
  • 学会同时报告最终值、最优值与曲线形态，避免用单种子、单点数字下结论。

背景与动机

前面几章你分别练过多智能体 PPO 与多智能体 SAC（两者同属第四篇），但两边的实验环境不同，得到的印象无法直接比较："PPO 更稳、SAC 样本更省"到底是算法性质，还是任务结构造成的？要回答这个问题，唯一的办法是控制变量：同一个环境、同一套超参数预算、同一个评估脚本、同一个随机种子。

本章用协作导航环境做这次对照实验：3 个智能体要把半径 0.6 圆上均匀分布的 3 个地标全部覆盖，奖励是团队共享的。两者都用参数共享（一个网络服务 3 个智能体，因为观测里没有绝对坐标，任务天然平移对称），这样比较的纯粹是更新机制：PPO 用 GAE + 裁剪目标在最新 2048 步数据上做 4 轮更新；SAC 用双 Q + 回放池每步更新一次。谁先爬到 50% 覆盖率，谁就更适合"数据贵"的多智能体场景。

核心原理

1. 样本效率的两种来源

PPO 是 on-policy：每批 2048 步数据只被使用 epochs 轮（本章 4 轮），之后全部丢弃。SAC 是 off-policy：每条转移进回放池后可以被采样任意多次。设一次环境步产出的数据对应多少次梯度更新，即更新/采样比 ρ：

ρPPO = (epochs × 小批量数) / 采样步数 ≈ (4 × 48) / 2048 ≈ 1 : 10.7
ρSAC = 1 : 1（每环境步一次更新，本章设置）

直觉上 SAC 应该更快学会，同一份数据被反复利用。但代价是两次偏差来源：数据分布随策略变化而"陈旧"，以及重要性比率背后的 off-policy 修正。PPO 的裁剪与比率正是量化这类偏差的工具。这条假设是否成立，用实验说话。

2. 共享奖励下的 GAE

本任务所有智能体拿到同一个团队奖励，因此奖励序列只有一条 rt，但每个智能体的价值估计不同。把价值写成 (T, N) 矩阵（T 为时间、N=3 为智能体数）后，逐智能体做同样的后向递推：

δt,i = rt + γVi(ot+1) − Vi(ot)
Ât,i = δt,i + γλ·(1−dt)·Ât+1,i

符号与单智能体版一致：δ 是 TD 残差，γ=0.95 折扣，λ=0.95 控制偏差-方差权衡；rt 对三个智能体相同，V 与 Â 按智能体各自计算。注意 dt 是"真终止"掩码，本环境只有 60 步时间截断，d 恒为 0，价值在回合边界继续 bootstrap。

3. 覆盖率：回报之外的硬指标

团队奖励是"每个地标到最近智能体的距离"的负均值，它是连续势函数，回报高不一定意味着任务完成（三人挤在一个地标旁也能拿不错的回报）。因此评估时额外统计：

coverage = (1/L) · Σj 𝟙[ mini d(i, j) < rcover ]

其中 L=3 是地标数、d(i,j) 是智能体 i 到地标 j 的距离、rcover=0.12 是覆盖半径。首次达到 coverage ≥ 0.5 的环境步数，就是本章衡量样本效率的核心数字，把"学习速度"变成一个可直接比较的整数。

4. 为什么两者都可能卡住

协同导航是"短视陷阱"明显的任务：3 个智能体挤向同一个最近地标，势函数负均值已经不错，但覆盖率只有 1/3。PPO 的熵正则与 SAC 的自动温度都会在早期提供探索，但后者通常更持久（加大的温度让策略在高回报阶段仍保留随机性），这正是第 066 章单智能体探索对比的多人版。

数据流

IPPO：采 2048 步联合轨迹（每步一次前向同时拿到 3 个智能体的动作/logp/价值）→ 用 (T, N) 优势递推 → 展平成 6144 个样本做 4 轮 × 小批量裁剪更新 → 丢弃数据。ISAC：每步把 3 条转移（同一奖励）写入回放池 → 预热 2000 步后每步抽 128 条更新 → 目标网络软更新。两者评估都调用同一个 evaluate，只是传入的 act_fn 不同。

与前一章的差异

第 083 章研究的是信息流向（评论家看不看队友），本章研究的是更新机制（on-policy vs off-policy）。本章把 CTDE、对手建模都关掉：两个算法都只用本地观测和本地动作，保证差异只来自算法本身。环境也换成更干净的协同导航，避免抢道具的动态竞争干扰对比。

公平对比里最容易被忽略的三件事

1) 随机流独立：两个算法各用 np.random.default_rng(args.seed) 重新起流，先跑的算法不会改变后跑算法的随机数序列。

2) 同额数据预算：都按"环境步数"计数（各 3 万步）；"回合数"或"更新次数"都不是公平的公共货币，环境步才是多智能体场景真正的稀缺资源。

3) 同一把评估尺：覆盖率、成功率都由公共 evaluate 计算，确定性策略；如果把 SAC 的评估留下采样噪声、PPO 用 argmax，数字将不可比。

关键代码与解读

片段 1：共享势函数奖励与覆盖率统计

dists = np.linalg.norm(self.landmarks[:, None, :] - self.pos[None, :, :],
                       axis=-1)          # (地标数, 智能体数) 的两两距离矩阵
min_dists = dists.min(axis=1)            # 每个地标到"最近智能体"的距离
reward = float(-min_dists.mean())        # 团队共享回报：三人拿到同一个数

collisions = 0
for i in range(self.n_agents):
    for j in range(i + 1, self.n_agents):
        if np.linalg.norm(self.pos[i] - self.pos[j]) < 0.08:
            collisions += 1
reward -= 0.1 * collisions               # 碰撞惩罚：避免"三车追尾"式合作
# 覆盖率：在覆盖半径内的地标比例，比回报更能反映任务是否真的完成
coverage = float(np.mean(min_dists < self.coverage_radius))
truncated = self.steps >= self.max_steps
return self._obs(), reward, False, truncated, {"coverage": coverage}

解读：环境只用了十几行就定义了整个学习问题。（1）奖励取"每个地标到最近智能体距离"的负均值，是标准的团队势函数：它把"去覆盖没人管的地标"变成提升奖励的最优策略，但存在"三人抱团也能拿分"的局部陷阱，所以必须配覆盖率指标。（2）广播减法 landmarks[:, None, :] - pos[None, :, :] 一次算出 3×3 距离矩阵，比双重循环清晰也更快。（3）碰撞惩罚 0.1 是针对"智能体叠在一起"的物理合理性约束，量级要小于轨道奖励的差异，否则会把策略吓得不敢靠近地标。（4）返回的 terminated=False：本环境没有真终止，所有回合结束都来自 60 步截断，Bellman 在所有边界都 bootstrap。

片段 2：共享奖励下的 (T, N) 优势递推

def compute_gae_shared(rewards, values, dones, last_values, gamma, lam):
    """共享奖励下的 GAE：rewards/dones 为 (T,)，values 为 (T, N)。"""
    T, N = values.shape
    adv = np.zeros((T, N), dtype=np.float32)
    last = np.zeros(N, dtype=np.float32)         # 每个智能体一条优势累加器
    for t in reversed(range(T)):
        next_v = last_values if t == T - 1 else values[t + 1]
        non_term = 1.0 - dones[t]                # 本环境恒为 1（只有截断没有终止）
        delta = rewards[t] + gamma * next_v * non_term - values[t]
        last = delta + gamma * lam * non_term * last
        adv[t] = last
    return adv, adv + values                     # 回报目标 = 优势 + 价值

解读：与单智能体 GAE 逐行对应，只是多了智能体维。（1）rewards[t] 是标量、values[t] 是长度 N 的向量，广播后每个智能体各自得到 TD 残差，这正是"共享奖励、独立价值"的数学写照。（2）last 从长度 N 的零向量开始向后滚动，避免逐时间步维护嵌套列表。（3）dones 只有真终止才为 1；本环境全 0，非终止掩码恒为 1，价值在回合边界连续 bootstrap。（4）返回的 adv + values 是价值回归目标，展平成 T*N 后与动作、logp 一一对齐，形状对齐是这段代码唯一容易错的地方。

片段 3：连续 PPO 的 tanh 逆变换

def log_prob_and_value(self, obs: torch.Tensor, act: torch.Tensor):
    """训练时重算 log 概率（tanh 压缩 + 逆变换）、状态价值与策略熵。"""
    mu, std, v = self.forward(obs)
    dist = Normal(mu, std)
    a = torch.clamp(act, -0.999999, 0.999999)   # 防止 atanh 在 ±1 处发散
    x = torch.atanh(a)                           # 逆变换：把 [-1,1] 动作映回高斯空间
    logp = dist.log_prob(x) - torch.log(1.0 - a.pow(2) + 1e-6)
    return logp.sum(dim=-1), v, dist.entropy().sum(dim=-1)

解读：这是连续控制 PPO 与离散 PPO 最关键的差异。（1）环境里的动作是 tanh(x) 压缩后的结果；训练时重算旧动作的概率，必须先把动作"逆变换"回高斯采样空间 x = atanh(a)，否则 Normal.log_prob 评估的是错误的分量密度。（2）减去 log(1−a²) 是变量替换的雅可比修正，与 SAC 策略里的修正项完全对称。（3）clamp 到 ±0.999999 是保险丝：atanh(±1)=±∞，采样动作恰好落在边界时会让 logp 变成 inf。（4）注意这里返回的熵是压缩前高斯分布的解析熵，它作为探索激励的代理量，不做雅可比修正，PPO 的实现里这是常见且可接受的近似。

片段 4：ISAC 的采样、入库与更新循环

next_obs, rew, terminated, truncated, info = env.step(actions)

for i in range(env.n_agents):
    sac.buffer.append({
        "obs": obs[i], "act": actions[i],
        "rew": np.float32(rew),            # 共享奖励：同一 r 发给所有智能体
        "next_obs": next_obs[i],
        "done": np.float32(terminated),    # 截断仍 bootstrap，只有真终止置 1
    })
total_steps += 1

# 每步一次梯度更新：共享网络看的是全队经验（T*N 条里随机抽 128）
if total_steps > args.warmup and len(sac.buffer) >= args.batch_size:
    sac.update_once()

解读：三行入库对应一个设计决定，其余交给 SAC 更新机制。（1）共享奖励直接复制给 3 个智能体，rew 完全相同，评论家靠观测区分各自该负的责任（这正是"信用分配"最简单的一种自然形态：价值函数自己学归因）。（2）done 只写 terminated：本环境恒为 0，回合边界继续 bootstrap，与 PPO 侧的掩码保持一致。（3）更新条件同时要求"过了预热"和"缓冲够了"，避免用少量初始样本过拟合出病态 Q 值。（4）对比口径：这里每步更新一次是刻意选的高更新率；练习里会让你降频，观察"样本效率 vs 算力效率"的此消彼长。

日志每个评估点打印"步数 / 回报 / 覆盖率 / 成功率"。预期（以实跑为准）：ISAC 通常在更少的环境步数达到中等覆盖率（回放复用），但每次更新更贵、墙钟时间往往是 IPPO 的 1.5～3 倍；IPPO 曲线更平滑，后期高覆盖率区波动更小。3 万步预算下两者都很难把成功率拉到 80% 以上，这是任务分工难度决定的。单种子排名翻转很常见，结论请用多种子中位数。

常见坑

  • 连续 PPO 忘记 tanh 逆变换：环境动作在 [-1,1]，重算 log 概率时若直接拿压缩后的动作喂 Normal.log_prob，评估的是错误空间的密度，重要性比率系统性失真。必须先 atanh 再算，并补 log(1−a²) 修正。
  • 把截断当终止：本环境只有 60 步时间截断，done 掩码必须恒为 0 才能 bootstrap；一旦写成 terminated or truncated，优势估计会在每条轨迹末端被截断，价值学不到"任务延续"的部分。
  • 两大算法共用同一个 rng：train_ippo 与 train_isac 各起一条随机流。若共用一个生成器，先跑的算法会改变后跑算法的随机序列，对比不再公平。
  • 只看回报不看覆盖率：共享势函数"离得近"就有分，3 个智能体挤在一个地标旁回报也不错；不统计覆盖率，会把"抱团局部最优"误判成学得好。
  • 用"更新次数"或"回合数"对齐预算：SAC 每步更新、PPO 每 2048 步更新，用更新次数对齐会让两者的数据量差几十倍。公平的公共货币只有一个，环境步数。

练习与思考

  1. 固定 --seed 1 分别单跑两种算法，先预测哪条覆盖率曲线先穿过 0.5，再把评估日志抄下来画出两条曲线验证。★
    提示
    用 --algo ippo 与 --algo isac 分开跑，日志里每个评估点都有步数和覆盖率两列，直接画折线。注意汇总行里"首次覆盖≥0.5"的步数。
  2. 把 PPO 的 --epochs 从 4 改成 10，先预测样本效率与墙钟时间会怎么变，再实跑对照。★
    提示
    更多 epoch 等于提高 ρ。留意评估曲线是否变得更"陡"但更抖；如果裁剪比例持续很高，说明同一批数据被榨干也学不动了，旧数据的信息已经用完。
  3. 给 ISAC 降频：把"每步更新"改成"每 2 步更新"，根据更新/采样比的变化预测样本效率与用时的走向，再改 total_steps % 2 == 0 验证。★★
    提示
    样本效率（每步学到的量）会降，但墙钟时间几乎减半，这是"样本效率"与"算力效率"的权衡。哪个指标先变化？先想清楚再跑。
  4. 把观测里"最近两个地标"改成"三个地标的相对坐标"（观测升到 14 维），先分析信息变多为什么可能反而不利，再看覆盖率是否明显改善。★★
    提示
    改 _obs 里 order[:2] 为全部地标即可，网络输入维度自动跟随。列一列两种观测下"该去哪个地标"决策难度的差别：多出的信息降低不了歧义，却增大了输入空间。
  5. 实现一个贪心基线：每个智能体朝"最近地标"方向给固定大小动作（如 1.2*rel/||rel||），用同一个 evaluate 量出覆盖率与回报，回答"学习算法比贪心强在哪里、又弱在哪里"。★★★
    提示
    写一个 greedy_policy(obs) 从观测里解出两个地标的相对坐标，取更近的。它无法知道地标是否被占用，正好能暴露局部观测的局限，对比覆盖率曲线在评估仪器下的差异，只看回报会漏掉关键信息。

小结

  • 公平对比的三要素：同环境、同网络规模与学习率、同评估协议；本章还用同种子做了配对实验。
  • 共享奖励下 GAE 按 (T, N) 组织：奖励一条、价值矩阵逐智能体递推，展平成 T*N 后合并更新。
  • 连续控制 PPO 的 atanh 逆变换与 SAC 的 tanh 修正项，是两套算法在"有界动作"上必须处理好的对称细节。
  • 预期结论：SAC 样本效率占优、PPO 单步更便宜、曲线更稳；最终谁赢取决于预算更偏"数据"还是"算力"。
