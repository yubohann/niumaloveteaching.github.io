第 079 章：多智能体SAC：通信

把队友的可见半径压到 0.4，看不见的时候靠"喊话"：每个智能体广播一个 2 维意图消息，队友拼进输入。这次把它接到 off-policy 的共享 SAC 上，消息在回放池里还会经历"时间旅行"。

  • 主题：off-policy 通信 / 带消息的转移存储
  • 关键公式：xt = [ot ⊕ mt−1−i]；(at, mt) = πθ(xt)；Lmsg = ‖mt − Δpt‖2
  • 预计学时：55 分钟
  • 前置章节：第 078 章

学习目标

  • 把第 071 章的通信机制迁移到 off-policy 的共享 SAC 上，理解两种谱系的实现差异。
  • 掌握回放池里"带消息的转移"如何存储：策略输入 x、下一策略输入 x′、消息监督目标三件套。
  • 理解消息延迟一步使用的时序约束，以及预热期与回合边界消息归零的一致性。
  • 在感知半径 0.4 的环境里对照有/无通信，重点比较碰撞与末距。
  • 认识 off-policy 通信的独有现象：回放池里的消息是"历史广播"，存在过期问题。

背景与动机

第 071 章在 PPO 上验证了意图通信：每个智能体广播"我接下来往哪走"，队友把消息拼进输入，消息头用位移预测自监督训练。那一套在 SAC 上依然成立，但有一条新的麻烦：数据进了回放池，消息也跟着一起"冻龄"。池子里某条转移记录的是当时的观测、动作、奖励，以及当时收到的消息。用它来训练当前策略时，消费端看到的是历史消息；但对 Q 目标而言，s′ 处的输入 x′ 记录的也是当时下一时刻实际收到的消息，语义上自洽，这正是 off-policy 数据的标准假设：数据描述的是行为策略下真实发生过的事。

所以本章的实现要点不在算法，而在数据结构：每条转移要存两个输入（当前的 x 与下一时刻的 x′，都含消息）和一个消息监督目标（自己的位移）。把这三件套对齐，剩下的训练流程与第 078 章的共享 SAC 完全一致。实验沿用第 071 章设定：感知半径 0.4，队友看不见就靠消息。

核心原理

1. 消息的时序与延迟

所有智能体同步行动，因此第 t 步能收到的只能是第 t−1 步广播的消息：

xti = [ oti ⊕ mt−1−i ]，  (ati, mti) = πθ(xti) ⊕ 表示拼接；mt−1−i 是其他智能体上一步广播的消息；动作与消息同一前向产生

于是每一步要保存两个输入：当前的 xt（用于重算动作与 logp）和下一步的 xt+1（用于 Q 目标）。xt+1 由"下一观测 + 本步广播的消息"拼成，在环境步之后立即就能算出来，顺序是：拼 xt → 策略输出动作与消息 mt → 环境步进得 ot+1 → 用 mt 拼出 xt+1。四步流水线一步都不能换位。

2. 消息头训练：自监督位移预测

Lmsg = ‖ mti − ( pt+1i − pti ) ‖2 p 是智能体位置；位移目标直接来自环境位置差，无需额外标注；消息语义被固定为"我要往哪走"

与第 071 章相同，真正的端到端可微通信需要沿时间展开（BPTT），这里用自监督固定消息内容、让策略梯度学习"如何使用"，这是教学规模的合理简化。注意位移目标 disp 与 x′ 一样在采样时同步落盘，训练时直接取用。

3. off-policy 通信的"过期消息"

回放池里的 x′ 记录的是行为策略当时广播/接收的消息。如果当前策略的广播习惯已经变化，旧转移里的消息就"过时"了。三种缓解方式：① 控制池子容量（本章默认 5 万步，约 1000 个回合，把容量调小即可主动淘汰旧消息）；② 训练时优先采样较新的数据；③ 定期用当前策略刷新消息（本项目不做，留给练习）。实践中过期消息的影响常常被 off-policy 的固有偏差掩盖，但理解它有助于你设计实验：当你调大池容量时，通信版受到的"过期伤害"通常比无通信版更大。

4. 通信在 off-policy 里为什么依然值得做

on-policy 的通信（第 071 章）数据即采即用，消息永远新鲜；off-policy 的通信虽然引入过期问题，但换来了数据复用与更大的批次，共享 SAC 的样本效率优势叠加消息的信息补充，在感知受限任务上仍然净收益为正。本章要验证的正是这一点：只要信息缺口足够真实（半径 0.4），哪怕消息有一定过期，它带来的协调价值也超过偏差成本。

实现思路与设计

模块划分

组件职责关键点
CooperativeNavEnv带感知半径的导航环境队友超出 0.4 视距时相对位置置零
CommPolicy共享策略 + 消息头输入宽度 = obs + (N−1)·msg_dim（无通信时不变）
build_policy_input拼接观测与队友消息训练/评估/回放池三处共用，保证语义一致
collect采样并生成 x、x′、位移目标消息延迟一步；回合结束消息清零
CommLearner.update共享 SAC 更新 + 消息损失展平批次后一次更新；comm_coef 调权重

关键超参数

参数默认值作用与取值理由
--commbothoff / on 各训练一遍，同预算
--sense-radius0.4制造信息缺口；调大可用于验证收益递减
--msg-dim2与位移维度一致，语义可读
--comm-coef1.0消息 MSE 权重；设 0 会退化为"无监督噪声特征"
--updates-per-round500每采样 1000 步做 500 次小批量更新，充分利用数据

数据流

采样：拼 x → 策略输出 (a, m) → 环境步进 → next_x = build(next_obs, m) → 位移目标 = 位置差。回放池存 (x, act, rew, next_x, disp, done)。更新：展平批次（done 用 np.repeat 对齐）→ 共享 SAC 的批评家/策略/温度更新，策略损失里加 comm_coef × L_msg。评估：消息按确定性前向传递，回合内延迟与训练一致。

与第 078 章、第 071 章的差异点

相对第 078 章：策略输入增加 (N−1)×2 维；每条转移多存 x′ 与位移目标；损失多一项消息 MSE；Q 网络跟着策略输入维度一起变化。相对第 071 章（PPO 版）：数据组织从"回合缓冲"换成"回放池 + 展平批次"，消息经历了"入池—回放"的时间差。其余结构与共享 SAC 相同。

关键代码与解读

片段 1：带消息头的共享策略

class CommPolicy(nn.Module):
    def __init__(self, obs_dim, act_dim, n_agents, hidden=64,
                 use_comm=True, msg_dim=2, msg_scale=0.4):
        super().__init__()
        self.use_comm = use_comm
        self.msg_dim = msg_dim
        self.msg_scale = msg_scale
        in_dim = obs_dim + (n_agents - 1) * msg_dim if use_comm else obs_dim
        self.in_dim = in_dim
        self.body = nn.Sequential(nn.Linear(in_dim, hidden), nn.ReLU(),
                                  nn.Linear(hidden, hidden), nn.ReLU())
        self.mean = nn.Linear(hidden, act_dim)
        self.log_std = nn.Linear(hidden, act_dim)
        if use_comm:
            self.msg_head = nn.Linear(hidden, msg_dim)

    def forward(self, x):
        h = self.body(x)
        mean = self.mean(h)
        log_std = torch.clamp(self.log_std(h), -4.0, 0.5)
        msg = torch.tanh(self.msg_head(h)) * self.msg_scale if self.use_comm else None
        return mean, log_std, msg

解读：与第 071 章的 PPO 版相比，结构几乎一致，但有三处 SAC 化的细节。（1）log_std 是状态相关的网络输出（nn.Linear + clamp），不是独立参数，SAC 策略的标准形态，探索强度随状态变化。（2）in_dim 是公开属性：Q 网络的构造依赖 self.policy.in_dim（观测+消息的宽度），策略与批评家必须"同宽"，否则 Q 读不懂 x。（3）消息头从隐藏层 h 分支、tanh×0.4 压缩，与第 071 章同源；无通信时 msg=None，采样与存储代码走同一套分支判断。（4）注意整个网络是一套（共享 SAC 底座）：三个智能体共同训练这一份参数，消息头也只有一份。

片段 2：拼接输入，一个函数三处共用

def build_policy_input(obs, messages, use_comm, n_agents):
    if not use_comm:
        return obs.astype(np.float32)
    rows = []
    for i in range(n_agents):
        parts = [obs[i]]
        for j in range(n_agents):
            if j != i:
                parts.append(messages[j])   # 只拼别人的消息，与第 071 章约定一致
        rows.append(np.concatenate(parts))
    return np.asarray(rows, dtype=np.float32)

解读：函数的简短背后是"语义一致性"的设计约束。（1）采样时拼 x、采样时拼 x′、评估时拼维护中的消息，三处都调用这一个函数，拼法（顺序、跳过自己、维度）在代码层面被强制统一。（2）返回形状 (N, in_dim)：整批送入共享策略，SAC 的重参数化采样一次处理三个智能体。（3）无通信时直接返回观测矩阵，in_dim=obs_dim，off 与 on 共用全部下游代码，只在这个函数处分叉。（4）消息是"上一步"的：函数本身不关心时序，谁传入什么就拼什么；时序由调用方（collect / evaluate）保证。职责分离让这个约定不容易被破坏。

片段 3：采样四步流水线与带消息转移

def collect(env, learner, steps, obs, messages, device):
    """采集 steps 个环境步；返回堆叠后的缓冲字典与消息状态。"""
    n = env.n_agents
    xs, acts, rews, next_xs, disps, dones = [], [], [], [], [], []
    for _ in range(steps):
        x = build_policy_input(obs, messages, learner.use_comm, n)     # 1) 拼当前输入
        x_t = torch.as_tensor(x, dtype=torch.float32, device=device)
        with torch.no_grad():
            action_t, _, msg_t = learner.policy.sample(x_t)            # 2) 动作 + 新消息
        actions = action_t.cpu().numpy()
        msgs = None if msg_t is None else msg_t.cpu().numpy()
        next_obs, per_rew, team_rew, done, info = env.step(actions)    # 3) 环境步进
        # 下一步的策略输入 = 下一观测 + 本步广播的消息
        next_messages = messages if msgs is None else msgs
        next_x = build_policy_input(next_obs, next_messages, learner.use_comm, n)  # 4) 拼 x'
        xs.append(x)
        acts.append(actions)
        rews.append(per_rew)
        next_xs.append(next_x)
        disps.append(next_obs[:, :2] - obs[:, :2])   # 自身位移（消息监督目标）
        dones.append(float(done))
        obs = next_obs
        messages = np.zeros((n, learner.policy.msg_dim), np.float32) if msgs is None else msgs
        if done:
            obs = env.reset()
            messages = np.zeros((n, learner.policy.msg_dim), np.float32)

解读：这段就是本章的"一切"，四步流水线逐行可辨，练熟它你就能把通信搬到任何 off-policy 算法上。（1）拼 x 用的是"上一步留下的 messages"（首次为零向量）；策略输出动作与消息 mt。（2）环境步进后用 next_messages = msgs 拼 x′，消息在这里完成"延迟一步"的交接：本步广播的 mt 出现在下一步（也是下一状态）的输入里。（3）disps 只取前两维位置差：位移监督目标与 x′ 同时落盘，训练阶段无需再触环境。（4）两条归零路径：msgs is None 时（off 模式）messages 保持零向量；done 时（回合边界）显式清零，绝不能让上一回合的意图漏进新回合。注意 messages = msgs 的赋值发生在 done 清零之前，顺序处理对了才不会把清零漏掉。

片段 4：共享更新里的消息辅助损失

        with torch.no_grad():
            next_act, next_logp, _ = self.policy.sample(next_x)    # Q 目标用 x'
            q1t, q2t = self.q_target(next_x, next_act)
            target = rew.unsqueeze(-1) + self.gamma * (1.0 - done).unsqueeze(-1) * (
                torch.min(q1t, q2t) - self.alpha * next_logp)
        q1, q2 = self.q(x, act)
        q_loss = F.mse_loss(q1, target) + F.mse_loss(q2, target)
        self.q_opt.zero_grad()
        q_loss.backward()
        self.q_opt.step()

        new_act, logp, msg = self.policy.sample(x)
        q1n, q2n = self.q(x, new_act)
        policy_loss = (self.alpha.detach() * logp - torch.min(q1n, q2n)).mean()
        aux_loss = torch.tensor(0.0)
        if self.use_comm:
            aux_loss = F.mse_loss(msg, batch["disp"])              # 消息 vs 真实位移
            policy_loss = policy_loss + args.comm_coef * aux_loss
        self.policy_opt.zero_grad()
        policy_loss.backward()
        self.policy_opt.step()

解读：更新路径与第 078 章的共享 SAC 完全同构，只是"输入换成了 x"、"多了一项消息损失"。（1）批评家目标用 next_x：Q(o′, a′) 变成 Q(x′, a′)，注意 Q 的输入是含消息的策略输入，这也是为什么 Q 网络的输入维度由 policy.in_dim 决定。（2）策略损失里的动作由 sample(x) 重采样（重参数化路径带梯度），消息 msg 与动作同一次前向产生，其 MSE 梯度会回流进共享躯干，消息头的训练与策略优化共享同一个 body。（3）batch["disp"] 已经是展平后的 (B·N, 2)：膨胀批次里每条转移都有自己的位移标签，与 x 行一一对应（在 flatten_batch 里用同样的 reshape 顺序保证）。（4）无通信时 aux_loss=0 仅为日志占位；comm_coef 控制消息学习与策略学习的权重平衡，与第 071 章的用法一致。

以实跑为准的预期：有通信版在半径 0.4 下碰撞更少（约 0.1 vs 0.3）、末距更稳；回报差距不大。消息 MSE 从约 0.05 降到 0.01~0.02 量级说明消息头在学。把半径调到 3.0（全可见），通信优势消失。以实跑为准。

常见坑

  • next_x 用了旧消息：x′ 必须包含"本步广播的消息"（mt），不是上一步的 mt−1。写错后 Q 目标与行为数据脱节，表现为通信版反而不如无通信版。
  • 回合边界忘记清消息：新回合沿用旧回合最后一步的消息，会把无关意图带进来；训练与评估两处都要清零。
  • disp 与 x 的展平顺序不一致：辅助损失的标签必须与修复后的行严格对应；用同一个 reshape 顺序（本脚本在 flatten_batch 统一处理）就不容易错。
  • 池容量过大：消息过期程度随池容量上升；本章默认 5 万步，调大前先想清楚你要测什么。
  • Q 网络输入维度没跟着消息变：Q 吃的是含消息的 x，输入维度必须用 policy.in_dim；硬编码 obs_dim 会在通信模式下直接报维度错（还好这个错会响）。

练习与思考

  1. 把 --sense-radius 设为 0.25、0.4、3.0，预测并验证通信收益（碰撞差、末距差）的单调关系。★
    提示
    3.0 覆盖全局时应退化为无差别。固定种子、跑完两种 comm 配置再比较。
  2. 把 --comm-coef 设为 0、0.5、1 各跑一次，比较消息 MSE 与碰撞。消息内容质量对协调的影响有多大？★
    提示
    coef=0 时消息头只拿到间接梯度，近似随机特征；MSE 不降。对比它和正常配置的碰撞曲线。
  3. 把 --buffer-size 从 5 万调小到 5000（开始淘汰旧消息），比较通信版的性能变化。解释"过期消息"的影响。★★
    提示
    小池子会更快淘汰旧广播，消息更贴近当前策略；池子调大后旧广播占比升高，消费端要同时适应新旧两种消息习惯，容易出现性能回退。无通信版对此不敏感，这正是对照的妙处。
  4. 做"消息刷新"实验：采样一批池中数据后，用当前策略对 x′ 重算消息并替换（近似修正过期），看是否加速收敛。★★★
    提示
    需要一次额外前向并重拼 x′；注意刷新后的消息没有"历史语义"，与 off-policy 自洽性之间有取舍。做过一次你就明白为什么工业界喜欢短池子。
  5. 把消息维度改成 4 或 1，比较带宽与表现。在 off-policy（有回放）设置下，通信带宽的收益曲线与第 071 章 PPO 版一致吗？★★
    提示
    维度变化会同步改变 in_dim、Q 输入与存储量。对照两章结论：机制相同，数据管线的差异会改变量级，但趋势应该一致。

小结

  • 通信机制跨谱系通用：动作与消息同源产生、延迟一步拼接、位移自监督，SAC 版只是换了个数据管线。
  • off-policy 的核心改动是"三件套"：x（当前输入）、x′（下一输入）、disp（位移标签）都要入池并对齐。
  • 采集流水线四步：拼 x → 输出 (a, m) → 环境步进 → 用 m 拼 x′；回合边界清消息。
  • Q 与策略共用同一宽度（in_dim = obs + (N−1)·msg_dim）；无通信时退化为普通共享 SAC。
  • 过期消息是 off-policy 通信的独有代价：用短池子、多采样新数据来限制它。
  • 下一章换对称维度：让共享策略对"角色置换"免疫，用集合编码器把对称性写进结构。
