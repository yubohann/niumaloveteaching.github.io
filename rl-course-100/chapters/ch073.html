第 073 章：多智能体PPO：信用分配

团队奖励是一大锅饭：进球了人人加分，失球了人人扣分。本章用集中式联合 Q 网络把"这口锅"拆开，对比共享基线与反事实基线（COMA），看逐智能体的优势信号如何改变学习。

  • 主题：信用分配 / 反事实基线（COMA）
  • 关键公式：bi(s) = Σa′i πi(a′i|oi)·Qφ(s, a′i, a−i)；Ai = Q(s, a1:N) − bi(s)
  • 预计学时：60 分钟
  • 前置章节：第 072 章

学习目标

  • 理解多智能体信用分配（credit assignment）问题：团队奖励无法直接告诉单个智能体"你做得怎么样"。
  • 掌握反事实基线（counterfactual baseline，COMA 的核心）：只替换自己的动作、队友动作保持不变，衡量"我的这一步比我的平均水平好多少"。
  • 看懂集中式联合 Q 网络 Q(s, a1, …, aN) 的结构，以及用 SARSA 目标训练它的原因。
  • 在同一套网络与数据上对照"共享基线"与"反事实基线"两种优势方案，观察逐智能体信号的差异。
  • 认识计算成本：反事实需要 N×A 次 Q 估值，枚举全部联合动作则需要 AN 次。

背景与动机

三个智能体把球推进了球门，团队奖励 +1，但到底是谁的功劳？是开局那次跑位，还是最后那一脚？如果把同一个优势值广播给所有人，就会出现两种典型病理：搭便车（别人冲，我摸鱼，反正奖励一样）和背黑锅（我做了正确的动作，但队友失误，我被一起惩罚）。在多智能体研究里，这被称为信用分配问题，是多智能体强化学习与单智能体强化学习最本质的差别之一。

本章把动作空间换成离散 5 动作（停/上下左右），这样"枚举一个智能体的所有动作"变得可行；然后用一个联合 Q 网络 Q(s, a1, …, aN) 作为"评审团"，用两种方式从它身上提取优势：共享基线给所有人同一个信号；反事实基线给每个人一个专属信号。这是 COMA（Counterfactual Multi-Agent Policy Gradients）的核心思想，也是后续值分解方法（VDN、QMIX）的思想源头。

核心原理

1. 联合 Q 与 SARSA 目标

集中式评审团把全局状态与所有智能体的联合动作映射到团队价值：

Qφ(s, a1:N) 的训练目标：y = r + γ(1−d)·Qφ̄(s′, a′1:N) φ 是在线 Q 的参数，φ̄ 是目标网络参数；a′ 是行为策略在下一状态真实采取的动作（SARSA），避免对 AN 个联合动作求 max；d 是回合终止标志

这里选 SARSA 目标：枚举联合动作空间呈指数级（3 个智能体、5 个动作就有 125 种），Q-learning 的 max 操作要遍历全部联合动作；改用"实际发生的下一动作"做自举，既便宜又与 on-policy 数据兼容。代价是它只评估行为策略下的价值，对本实验完全够用。

2. 反事实基线：把功劳算到个人头上

关键技巧是"只动一个人"的期望：固定队友的动作 a−i，让智能体 i 在自己策略下试遍所有动作，取 Q 的期望作为它应得的基线：

bi(s) = Σa′i πi(a′i | oi) · Qφ(s, (a′i, a−i))
Ai(s, a) = Qφ(s, a1:N) − bi(s) a−i 表示除 i 以外的队友动作（固定不变）；bi 是"智能体 i 处于自己的平均水平"时的团队价值；Ai>0 说明它这一步比自己的平均选择更好

对比"共享基线" b(s) = 𝔼a′∼随机 Q(s, a′)：它给所有智能体同一个数字，优势只告诉你"这一整步比平均联合动作好多少"，无法回答"是谁让它变好的"。反事实基线则对每个 i 单独求期望，差异只在智能体 i 的动作上，队友的影响被固定住了，这就是"反事实"的含义：在队友不动的前提下，换掉我的动作会怎样。夏普利值、差分奖励等概念都是这一思想的不同形式。

3. 反事实的计算量与实现

对每个状态，构造形状为 (T, N, A, N·A) 的枚举张量，让 Q 一次前向就得到全部 N×A 个反事实值，总前向规模是 T·N·A。若改成枚举全部联合动作，则需要 AN 次前向，A=5、N=3 时是 125 对 15，差距已经可见；智能体再多一点就完全不可行。反事实把指数成本压回线性成本，这是它能在实践中普及的原因。共享基线更便宜（本例用 K=16 组随机联合动作近似，成本 T·K），但信号不含个体信息，便宜和有用之间需要权衡。

4. 诊断量：优势的智能体间标准差

怎么知道信用分配真的"拆开"了？本章统计 adv_std = 同一状态下 N 个智能体优势的标准差。共享基线天然输出 adv_std≈0（所有人同号同值）；反事实基线会产生非零的离散度，某个智能体这一步明显比它的平均选择好，它的 Ai 就高，而摸鱼队友的 A 接近零甚至为负。这个诊断量把"信用是否分化"变成可观察的数字，练习里会让你把它与吞吐/碰撞指标联合分析。

关键代码与解读

片段 1：集中式联合 Q

class JointQ(nn.Module):
    """集中式联合 Q：输入全局状态 + 所有智能体的动作 one-hot。"""

    def __init__(self, state_dim, n_agents, n_actions, hidden=128):
        super().__init__()
        in_dim = state_dim + n_agents * n_actions
        self.in_dim = in_dim
        self.net = nn.Sequential(nn.Linear(in_dim, hidden), nn.ReLU(),
                                 nn.Linear(hidden, hidden), nn.ReLU(),
                                 nn.Linear(hidden, 1))

    def forward(self, state, joint_onehot):
        x = torch.cat([state, joint_onehot.view(-1, self.in_dim - state.shape[-1])], dim=-1)
        return self.net(x).squeeze(-1)

解读：评审团的全部结构就是一个 MLP，输入 = 全局状态 + 联合动作。（1）动作用 one-hot 拼接（3 智能体 × 5 动作 = 15 维）：这个任务的动作少，one-hot 直白，也避免动作索引或嵌入引入"动作 2 与动作 3 更接近"的伪结构。（2）joint_onehot.view(-1, ...) 先展平再拼，保证任意 batch 形状都能用；state.shape[-1] 从输入动态推维度，避免硬编码 19。（3）Q 比策略网络宽（hidden=128 vs 64）：价值回归需要拟合"状态×联合动作"的组合表面，容量不足会直接拖累优势质量，这是值分解/集中批评家方法的通用经验。（4）输出 squeeze(-1) 成 (B,) 与奖励对齐，MSE 回归时形状才不会广播出错。

片段 2：为每个智能体构造反事实动作

def joint_onehot(actions: torch.Tensor, n_agents: int, n_actions: int) -> torch.Tensor:
    """(T, N) 的动作索引 -> (T, N*A) 的 one-hot 拼接。"""
    T = actions.shape[0]
    out = torch.zeros(T, n_agents, n_actions, device=actions.device)
    out.scatter_(2, actions.unsqueeze(-1), 1.0)
    return out.view(T, n_agents * n_actions)


def alternative_joint(actions: torch.Tensor, n_agents: int, n_actions: int) -> torch.Tensor:
    """为每个智能体枚举其全部动作，返回 (T, N, A, N*A)。

    第 i 个智能体的动作块被逐一替换成 A 个 one-hot，其余智能体保持原动作。
    """
    T = actions.shape[0]
    device = actions.device
    base = joint_onehot(actions, n_agents, n_actions)           # (T, N*A)
    alts = base.unsqueeze(1).unsqueeze(2).repeat(1, n_agents, n_actions, 1)  # (T,N,A,N*A)
    eye = torch.eye(n_actions, device=device)                   # (A, A)
    for i in range(n_agents):
        block = alts[:, i, :, i * n_actions:(i + 1) * n_actions]  # (T, A, A)
        block.copy_(eye.unsqueeze(0).expand(T, -1, -1))
    return alts

解读：这是全章最精巧的一段张量体操，值得慢慢拆。（1）joint_onehot 把 (T,N) 索引散列成 (T, N*A) 的 0/1 向量，scatter_ 是标准写法；所有反事实张量都建立在它之上。（2）alts 先复制出"每个智能体、每个候选动作"的完整备份，再对第 i 个智能体的动作块原地覆盖成单位矩阵的一行行，覆盖后，第 (i, a) 行表示"智能体 i 做动作 a、其他人照旧"。copy_ 是原地写，配合广播把 (A,A) 的 eye 铺到 (T,A,A)。（3）一个容易忽略的细节：alts[:, i, :, i*n_actions:(i+1)*n_actions] 的切片是连续内存块吗？不是必需的，PyTorch 会处理视图写回，但要清楚 copy_ 改的是 alts。（4）形状 (T,N,A,N*A) 的存储量按 T·(N·A)² 增长：T=1000、N=3、A=5 时约 22.5 万个浮点数（float32 不到 1 MB），可以接受；N、A 再大一档就按平方膨胀，构造与整批前向都要考虑分批。

片段 3：两种基线的优势计算

        with torch.no_grad():
            q_sa = self.q(state, joint)                            # (T,)
            if self.credit == "coma":
                # 每个智能体的反事实基线：替换它的动作，对其策略分布求期望
                alts = alternative_joint(acts, N, A)               # (T,N,A,N*A)
                q_alts = self.q(state.repeat_interleave(N * A, dim=0),
                                alts.reshape(T * N * A, N * A)).reshape(T, N, A)
                logits = self.actor(obs.reshape(T * N, -1))
                probs = torch.softmax(logits, dim=-1).reshape(T, N, A)
                baseline = (probs * q_alts).sum(dim=-1)             # (T,N)
                adv = q_sa.unsqueeze(1) - baseline                  # (T,N)
            else:
                # 共享基线：随机采 K 组联合动作，用平均 Q 当所有人的基线
                k = args.baseline_samples
                rand_acts = torch.randint(0, A, (T, k, N), device=device)
                rand_joint = torch.zeros(T, k, N * A, device=device)
                idx = (torch.arange(N, device=device)[None, None, :] * A + rand_acts)
                rand_joint.scatter_(2, idx, 1.0)
                q_rand = self.q(state.repeat_interleave(k, dim=0),
                                rand_joint.reshape(T * k, N * A)).reshape(T, k)
                baseline = q_rand.mean(dim=1)                        # (T,)
                adv = (q_sa - baseline).unsqueeze(1).repeat(1, N)    # (T,N)
            adv_std = float(adv.std(dim=1).mean().item())            # 智能体间差异

解读：全章核心对照在此，两个分支输出形状相同的 (T,N) 优势，但含义不同。（1）coma 分支：repeat_interleave 把每个状态复制 N×A 份，喂给反事实张量做一次大前向（T·N·A 条），reshape 回 (T,N,A)；probs 由共享策略对每个智能体的动作分布给出，注意期望按智能体 i 自己的策略分布加权；均匀平均在策略偏离均匀时会给出错误基线。这样"这个动作在它惯常选择里算好算坏"的口径才正确。（2）shared 分支：随机采 K=16 组联合动作（不是逐人独立枚举），得到一个与个体无关的基线；adv 直接复制给 N 个智能体，这就是"大锅饭"的代码形态。（3）q_sa.unsqueeze(1) - baseline：coma 的 baseline 形状 (T,N)，data 项的 broadcast 把同一个 Q(s,a) 减到每人的基线上，得到的正是各自的 Ai。（4）adv_std 用 adv.std(dim=1)（同一状态内 N 个智能体的标准差）再对时间取均值，共享基线这一项恒为 0，coma 这一项为正，是"信用是否分化"的直接读数。

片段 4：SARSA 目标与目标网络软更新

        # ---- 1) 联合 Q 更新（SARSA 目标；最后一条样本缺少后继动作，丢弃）----
        with torch.no_grad():
            next_q = self.q_target(next_state[:-1], next_joint[:-1])
            target = rew[:-1] + args.gamma * (1.0 - done[:-1]) * next_q
        for _ in range(args.q_epochs):
            pred = self.q(state[:-1], joint[:-1])
            q_loss = F.mse_loss(pred, target)
            self.q_opt.zero_grad()
            q_loss.backward()
            self.q_opt.step()

        # 目标网络软更新
        with torch.no_grad():
            for p, p_t in zip(self.q.parameters(), self.q_target.parameters()):
                p_t.data.mul_(1.0 - args.tau_q).add_(args.tau_q * p.data)

解读：为什么这段出现了大量 [:-1]？因为采样窗口的最后一条样本没有"下一步"，它的后继状态与后继联合动作不存在。（1）next_state 与 next_acts 是逐时间对齐的数组：对第 t 条样本，后继动作是第 t+1 步联合动作（由行为策略真实产生，SARSA 语义）。（2）目标里乘 (1.0 - done)：本环境只有 50 步截断、没有真终止，但统一保留掩码，防止未来换环境时遗漏。（3）动作保留为索引、只在需要时 one-hot：joint_onehot(acts) 一次构造，训练循环里复用；joint[:−1] 与 target 对齐。（4）Q 用 4 个 epoch 更新、软更新系数 τ=0.01，比 SAC 的 0.005 略快，因为这里 Q 要追赶的策略学习节奏更快，太慢的目标网络会让优势长期偏差。（5）顺序很重要：先把 Q 更新几轮，再用同一批数据算优势、更新策略，反事实基线依赖 Q 的准确性，先让"评审团"站稳再开会。

常见坑

  • 把 Q(s,a) 当成 Q(s)：集中批评家的老写法 V(s) 无法回答"换个动作会怎样"，反事实基线必须要有 Q。改回 V 会让整个章节失去意义。
  • 反事实期望用均匀分布：baseline 必须按策略概率 probs 加权。用 1/A 均匀平均在策略偏离均匀时给出错误基线，优势符号可能反转。
  • 忘记丢弃最后一条样本：SARSA 目标需要后继联合动作，采样窗口最后一条没有。漏掉 [:-1] 会让形状对不上或语义错位。
  • 目标网络更新太快：τ_q 太大时 Q 目标随在线网络一起漂移，训练不稳；太小又追不上策略。诊断看 q_ev：长期低于 0.3 说明 Q 没学好，先查 Q 的学习率与训练轮数。
  • 拿 shared 的 adv_std 当 bug：共享基线天然 adv_std≈0（所有人同一信号），这不是实现错误，恰是"大锅饭"的定义；对照的意义就在这里。

练习与思考

  1. 把 --credit 分别跑 shared 与 coma，对比日志里的 adv_std 与 q_ev。共享基线的 adv_std 为什么恒为 0？★
    提示
    看代码：adv = (q_sa - baseline).unsqueeze(1).repeat(1, N)，同一状态复制 N 份，标准差自然是 0。
  2. 把 --baseline-samples 从 16 改到 2 与 64，观察 shared 的性能与 q_ev。基线样本数与基线噪声是什么关系？★
    提示
    K 越小，Q 均值估计的方差越大，优势信号越抖；K 大到一定程度后收益递减。代价是 K 倍的前向成本。
  3. 推导：若队友动作固定，用均匀平均替代策略期望，基线会偏大还是偏小？构造一个两动作的例子验证你的结论。★★
    提示
    策略把 0.9 的概率放在好动作上时，均匀平均会把差动作的 Q 也平均进来，基线通常更低/更高取决于 Q 形状，动手算一遍最清楚。
  4. 把 alternative_joint 里的 copy_ 改写成"先克隆再赋值"，确认结果一致。解释为什么需要 unsqueeze(0).expand(T,-1,-1) 配合广播写入，直接循环 T 次的代价在哪里。★★
    提示
    expand 是零拷贝的广播视图，copy_ 会按需展开写入；循环 T 次在 T=1000 时慢 2~3 个数量级。GPU 上差别更明显。
  5. 给 coma 加一个"逐智能体价值头"的对照：每个智能体用独立的 Qi(s, ai)（值分解的雏形），比较它与反事实基线在 adv_std 与回报上的表现。哪种分解更接近"真功劳"？★★★
    提示
    这已经走到 VDN/QMIX 的门口：VDN 把团队 Q 求和分解为个体 Q，训练成本更低但表达受限。可以先实现"个体 Q 加权求和拟合团队 Q"的最小版本。

小结

  • 信用分配是多智能体最本质的问题：团队奖励无法直接告诉单个智能体"你做得怎么样"。
  • 联合 Q 评审团 Q(s, a1:N) 用 SARSA 目标训练，避免枚举 AN 个联合动作。
  • 反事实基线 bi = Σ πi(a′i) Q(s, a′i, a−i)：固定队友、只换自己，得到"我比我的平均好多少"。
  • 计算成本从指数级 AN 压回线性级 N×A，是 COMA 能被实践采用的关键。
  • adv_std 是信用是否分化的体检指标：shared 恒 0，coma 大于 0；回报差距可能不大，但协调细节通常更好。
