第一篇 · 策略梯度与 PPO

第 001 章：PPO在CartPole上的首次实现

从零理解并落地一个完整的 PPO：采样一批经验、用 GAE 估计优势、以裁剪目标做多轮小批量更新，让只活 20 步的小车学会把杆子立稳 500 步。

  • 主题：PPO 基础闭环 / on-policy 训练
  • 关键公式：LCLIP = 𝔼[min(r·Â, clip(r,1−ε,1+ε)·Â)]
  • 预计学时：50 分钟
  • 前置章节：无（本课程从这里开始）

学习目标

  • 理解 on-policy 强化学习的"采样 → 估计优势 → 更新 → 丢弃数据"闭环，以及 PPO 在这条链路中的位置。
  • 掌握策略梯度、重要性采样比率与裁剪目标的数学形式与直觉。
  • 看懂 Actor-Critic 网络、GAE 优势估计与 PPO 裁剪损失的关键实现片段，不仅知道怎么写，还知道为什么这样写。
  • 在 CartPole-v1 上把随机策略训练到 100 回合滑窗平均回报 ≥ 475（满分 500）。
  • 学会读训练日志：KL、裁剪比例、熵、滑窗回报各自意味着什么。

背景与动机

策略梯度方法直接优化策略本身：好的动作提高概率，坏的动作降低概率。想法简单，但工程上一直有个痛点，更新步长难以控制。一次更新走得太远，策略可能直接崩溃成"永远只输出同一个动作"的傻子，而且很难恢复。

TRPO 用二阶优化加"信任域"约束解决这个问题，但需要计算 Fisher 信息矩阵、做共轭梯度，实现复杂、每一步都很贵。PPO（Proximal Policy Optimization，2017）换了个思路：用一次裁剪（clip）就近似实现了信任域，当新旧策略的概率比超出设定范围时，直接掐掉梯度。实现只有几行代码，效果却足够好，因此它成了实际项目里默认的 RL 算法：从机器人控制到 RLHF 微调语言模型，到处都有 PPO 的身影。

为什么从 CartPole 开始？它是验证实现正确性的最小闭环：状态 4 维、动作 2 个、回合上限 500 步、奖励就是存活步数。学习曲线对不对、基线搭得稳不稳，几十个回合的滑窗均值就能给出答案。本章的目标是把 PPO 的每个机制讲透、看到它在代码里长什么样，并不以刷分为目的，后面 29 章都在这个骨架上做单点改动。

核心原理

1. 策略梯度与优势函数

设策略为 πθ，目标函数是期望折扣回报 J(θ)。策略梯度定理告诉我们，梯度可以写成：

∇θJ(θ) ≈ 𝔼t[ ∇θlog πθ(at|st) · Ât ]

其中 Ât 是优势函数：在状态 st 下执行 at，比"按当前策略平均表现"好多少。这里乘的是优势 Ât，它减掉了状态本身的"基准分"，方差比回报 Gt 小得多，梯度估计更稳。优势的估计方式（GAE）是本章和下一章的核心，这里先给出标准形式 GAE(γ, λ)：

δt = rt + γV(st+1) − V(st)
Ât = Σl=0∞ (γλ)l δt+l

δt 是"时序差分残差"，衡量这一步实际发生的事比你预期的价值好多少；λ 在偏差与方差之间插值：λ=0 退化为单步 TD（低方差、有偏差），λ=1 接近蒙特卡洛（高方差、低偏差）。第 002、009 章会专门做这两类实验。

数值例子：手算一次 GAE

设 γ=0.99、λ=0.95，一段 3 步的轨迹在第 3 步真终止（杆子倒下）。奖励 r0=r1=r2=1，价值估计 V(s0)=10、V(s1)=11、V(s2)=12，终止后未来价值为 0。先算每步的 TD 残差：

δ2 = 1 + 0.99×0 − 12 = −11；δ1 = 1 + 0.99×12 − 11 = 1.88；δ0 = 1 + 0.99×11 − 10 = 1.89。

再按 γλ = 0.99×0.95 = 0.9405 从后向前累加：Â2 = δ2 = −11；Â1 = 1.88 + 0.9405×(−11) ≈ −8.47；Â0 = 1.89 + 0.9405×(−8.47) ≈ −6.07。

对应价值回归目标 Rt = Ât + V(st)：R0 ≈ 3.93、R1 ≈ 2.53、R2 = 1。解读：第 2 步的 −11 表示价值网络高估了该状态（预测 12，实际只拿到 1 的回报），这条修正信息向前的传播距离由 λ 控制：λ=0 时 Â0 只有 1.89，看不出后面要崩；λ=0.95 时 Â0 ≈ −6.07，提前给这条轨迹整体降权。这就是 GAE 的核心作用：把未来的预测误差按 (γλ) 的幂次回溯，λ 越大回溯越远、偏差越小、方差越大。

2. 重要性采样比率：让一批数据被多次使用

原始策略梯度是 on-policy 的：数据必须来自当前策略。PPO 想对同一批数据更新多个 epoch，就必须衡量"新旧策略对同一动作的评价差了多少"：

rt(θ) = πθ(at|st) / πθ_old(at|st)

rt > 1 表示新策略更倾向于这个动作，rt < 1 表示更不倾向。没有它，多次更新就等于用过期数据"想当然"地优化，更新方向会错。

3. PPO 的裁剪目标

PPO 的目标函数实现了"谁越界谁没有梯度"：

LCLIP(θ) = 𝔼t[ min( rt Ât, clip(rt, 1−ε, 1+ε) Ât ) ] ε 是裁剪范围，默认 0.2，即比率被限制在 [0.8, 1.2] 内

拆开看更直观（以 Ât > 0 的好动作为例）：

  • rt 在 [0.8, 1.2] 内：不裁剪，正常提升这个动作的概率；
  • rt > 1.2：clip 项封顶在 1.2·Ât，min 选择它，梯度变成 0，"这个动作已经提升够多了，先停"。避免一步更新过猛把策略带偏。

对 Ât < 0 的坏动作镜像成立。所以 PPO 的更新是"有则改进、越界即停"的保守更新，这就是它不需要二阶优化也能稳定的原因。

把 min 对比率求导，可以看清裁剪其实只在"还想继续改进"的那一侧掐掉梯度。对 rt 求导分四种情形（ε=0.2）：

优势符号比率位置min 选中的项对比率的梯度行为
Â > 0r < 1+εr·ÂÂ正常提升该动作的概率
Â > 0r > 1+ε(1+ε)·Â（常数）0停止继续提升
Â < 0r > 1−εr·ÂÂ正常压低该动作的概率
Â < 0r < 1−ε(1−ε)·Â（常数）0停止继续压低

代入数字验证四行：Â=+2、r=1.5 时，未裁剪项 3.0、裁剪项 1.2×2=2.4，min 取 2.4 这个常数，梯度为 0；Â=+2、r=1.1 时两项都是 2.2，min 取 r·Â，梯度为 2。负优势一侧对称：Â=−2、r=0.5 时，未裁剪项 −1.0、裁剪项 0.8×(−2)=−1.6，min 取 −1.6 常数，梯度为 0；Â=−2、r=1.3 时，未裁剪项 −2.6、裁剪项 −2.4，min 取 −2.6，梯度为 −2。

裁剪窗口换算到对数空间更便于和其他诊断量对照：r > 1.2 等价于"新策略对该动作的对数概率比旧策略高出 ln 1.2 ≈ 0.182 以上"，r < 0.8 等价于对数概率位移低于 ln 0.8 ≈ −0.223。也就是说，单个样本的位移要越过约 0.2 个 nats（自然对数单位，1 nat ≈ 1.4427 bit）才有机会被裁剪。注意这是单样本口径：第 003 章的近似 KL 是整批平均，健康区间 0.005～0.02 比这个单样本阈值小一个数量级，两者并不矛盾；批次里通常只有 5%～20% 的样本越界，日志中的裁剪比例就是这件事的读数。

这张表纠正两个常见误读。第一，裁剪是单侧的：负优势样本的比率远大于 1 时（该动作概率已经偏高），梯度照样存在，PPO 不会"手下留情"，惩罚只会在比率被压到 1−ε 以下时才停止。第二，裁剪并不把比率钳制在 [1−ε, 1+ε] 区间内，它只是让越界样本不再贡献有利方向的梯度；日志里出现 r 达到 3、5 的样本是正常的。失效模式是另一种极端：一批数据里绝大多数正优势样本都落在 r > 1+ε，此时策略项的有效梯度接近 0，回报曲线呈现"高原"，KL 却在涨，看到这个签名应当降学习率或缩短 epoch 数；加大训练预算只会让高原延续更久。

4. 总损失：策略 + 价值 + 熵

L(θ) = −LCLIP(θ) + cvf · 𝔼[(Vθ(s) − Rt)2] − cent · H(πθ(·|s))

三项分别对应：让好动作更可能（策略项）；让价值函数预测更准（价值项，为优势估计服务）；保持一定的随机性防止过早收敛（熵项）。典型权重：cvf=0.5、cent=0.01。

5. 与相邻方法的对比

把 PPO 放回方法谱系里，才能看清它的取舍。三种方法的共同点是都沿策略梯度方向更新参数，差别在"一次更新允许走多远"这一约束上：

方法约束方式单次更新成本实现复杂度实践中稳定性
REINFORCE（朴素策略梯度）无显式约束，靠学习率控制步长低，数据用一遍即丢最低差，步长稍大即崩溃
TRPO显式 KL 散度约束 + 信赖域高，需 Fisher 向量积与共轭梯度高好，但调参余地小
PPO裁剪目标近似信任域低，同一批数据可迭代多个 epoch低，约 20 行核心代码好，超参数鲁棒

这张表解释了 PPO 的定位：它用"裁剪"这一一阶近似换掉了 TRPO 的二阶运算，牺牲一点理论保证，换来实现成本的大幅下降和调参友好度。样本利用率上的差距可以用具体数字感受：同一批 2048 步数据，REINFORCE 只更新 1 次就丢弃；PPO 做 10 epochs × 32 个 minibatch，等于从同一批数据里提取 320 次梯度更新。本课程后续所有算法都会以本章的闭环为基础做单点替换，因此把这条数据流走通比追高分更重要。

PPO 的适用边界同样要提前说清：其一，它是 on-policy 方法，每条样本的复用次数被 epochs 卡死在个位数，奖励稀疏、每步交互昂贵的任务（例如真实机器人）样本效率不足，这是第二篇转向 SAC 的动机；其二，裁剪约束的是概率比率，不是参数距离，策略只在"这一批数据的动作"上有约束，分布外状态的脆弱性要靠第 014 章的对抗评估来暴露；其三，优势估计依赖价值网络，当价值函数严重失准时（奖励尺度失衡、长时程信用分配），裁剪再稳也救不了方向错误的梯度，第 007、009 章分别处理这两类问题。

数据流

每个更新周期：采样 2048 步（大约 4～20 个完整回合）→ 计算 GAE 得到每个时刻的优势与回报目标 → 优势标准化 → 打乱后做 10 epochs × 32 个 minibatch 的梯度更新 → 整批数据丢弃（on-policy 的代价：数据不能反复用）。

预算对账：一次完整训练的四个数字

把默认参数整条链算一遍，训练规模就不再是模糊印象：更新次数 = ⌈400000 / 2048⌉ = 196（最后一次不足 2048 步）；每次更新的 minibatch 数 = 2048 / 64 = 32；梯度步总数 = 196 × 10 × 32 = 62720；数据复用系数 = epochs = 10，即每条转移被用于 10 次梯度计算。这四个数字互相咬合：想让曲线更平滑就加大 epochs 或采样批量（复用系数与单批信息量上升），想缩短墙钟时间就减小其中一个（每个环境步的算力开销下降）。

另一个要对账的是 GAE 的回看长度：γλ = 0.9405，有效回看约 1/(1−γλ) ≈ 16.8 步，而单批 2048 步相当于它的 122 倍，优势估计用不到的信息都在批次内，这是批量不能太小的一个定量依据。反过来，若把 steps_per_update 降到 128（小于早期回合长度），批次边界会频繁截断序列，末端优势全靠 V(s) 自举，价值网络一旦不准，更新方向就会系统性偏移。取值参考：采样批量至少覆盖 2 个完整回合，CartPole 早期约 20 步、后期 500 步，所以 1024～4096 都是合理区间。

两个容易忽略的实现细节

1) 终止 vs 截断：杆子倒了是 terminated=True，此时未来价值应视为 0；而 CartPole 达到 500 步上限是 truncated=True，环境只是被时间限制打断，它的价值要用 V(s) 继续估计（bootstrap）。混为一谈会让价值函数系统性低估长回合。

2) 训练预算按步数：CartPole 达标大约需要 10 万～30 万环境步，只用"回合数"做上限很容易训练不足，第 400 个回合时可能才走了 4 万步。

关键代码与解读

片段 1：Actor-Critic 网络与动作采样

class ActorCritic(nn.Module):
    def __init__(self, obs_dim: int, act_dim: int, hidden: int = 64):
        super().__init__()
        self.body = nn.Sequential(                  # 共享躯干：策略与价值共用一个特征提取器
            nn.Linear(obs_dim, hidden), nn.Tanh(),
            nn.Linear(hidden, hidden), nn.Tanh(),
        )
        self.actor = nn.Linear(hidden, act_dim)     # 策略头：输出离散动作的 logits
        self.critic = nn.Linear(hidden, 1)          # 价值头：输出状态价值 V(s)

    @torch.no_grad()
    def act(self, obs):
        """采样动作，同时返回采样时刻的 log 概率与状态价值。"""
        logits, value = self.forward(obs)
        dist = Categorical(logits=logits)           # 离散动作用分类分布
        action = dist.sample()                      # 按概率采样（探索的来源）
        return action.item(), dist.log_prob(action).item(), value.item()

解读：三个设计点值得记住。（1）共享躯干：CartPole 的观测只有 4 维，两个 64 宽的隐层已经足够；共享让策略与价值互相"借力"，也减少参数量。（2）act() 里 log_prob(action) 是采样时刻的对数概率，它会被存进 rollout，充当 PPO 比率的分母。这是整个数据流里最不能出错的一环。（3）@torch.no_grad()：采样本不需要梯度，加上它既省显存又防止计算图泄漏。

片段 2：GAE 的后向递推

def compute_gae(rewards, values, terminateds, last_value, gamma, lam):
    """从后向前递推 GAE。terminateds 只记"真终止"，截断回合不置零。"""
    T = len(rewards)
    advantages = np.zeros(T, dtype=np.float32)
    last_gae = 0.0
    for t in reversed(range(T)):
        next_value = last_value if t == T - 1 else values[t + 1]
        non_terminal = 1.0 - terminateds[t]         # 真终止→未来价值为 0；截断→保留
        delta = rewards[t] + gamma * next_value * non_terminal - values[t]
        last_gae = delta + gamma * lam * non_terminal * last_gae
        advantages[t] = last_gae
    returns = advantages + np.asarray(values, dtype=np.float32)
    return advantages, returns

解读：逆序循环里每一轮做两件事，先算 TD 残差 δ（实际比预期好多少），再把"当前残差 + 衰减后的未来优势"累加成 Ât。non_terminal 掩码是两个分支的开关：真终止时未来项归零（后面没有未来了）；时间截断时不归零，因为环境其实"还能继续"，只是被时间限制打断。returns = advantages + values 是价值网络的回归目标，用 GAE 的优势反推回报，比直接用蒙特卡洛回报方差小得多。

片段 3：PPO 更新的核心循环

for _ in range(args.epochs):                        # 同一批数据反复利用（epochs 轮）
    idx = torch.randperm(N, device=obs.device)      # 每轮重新打乱：避免顺序偏置
    for start in range(0, N, args.batch_size):
        mb = idx[start:start + args.batch_size]
        logits, value = net(obs[mb])
        dist = Categorical(logits=logits)
        logp = dist.log_prob(act[mb])               # 新策略对数概率

        ratio = torch.exp(logp - logp_old[mb])      # 对数差算比率：数值上比相除更稳
        surr1 = ratio * adv[mb]                     # 未裁剪目标
        surr2 = torch.clamp(ratio, 1.0 - args.clip,
                            1.0 + args.clip) * adv[mb]   # 裁剪目标
        policy_loss = -torch.min(surr1, surr2).mean()    # min=悲观下界，越界梯度归零

        value_loss = F.mse_loss(value, ret[mb])     # 价值回归：对齐 GAE 反推的回报
        entropy = dist.entropy().mean()             # 熵：鼓励保持探索
        loss = policy_loss + args.vf_coef * value_loss - args.ent_coef * entropy

        optimizer.zero_grad()
        loss.backward()
        nn.utils.clip_grad_norm_(net.parameters(), 0.5)  # 梯度裁剪，防偶发大步
        optimizer.step()

解读：这段 20 行左右是整个 PPO 的心脏，逐行都值得展开。（1）ratio = exp(logp − logp_old)：用对数差再取指数，避免两个概率直接相除时的数值问题（小概率相除可能溢出/下溢）。（2）min(surr1, surr2)：这是"悲观下界"，当比率跑出 [1−ε, 1+ε]，clip 项变成常数，梯度只剩它，于是越界方向的梯度恰好归零。（3）优势 adv 在进入循环前做过标准化（减均值除标准差），让不同量级的批次都能用同一学习率。（4）总损失的符号：策略项和价值项是"要最小化"的损失；熵奖励是"越大越好"，所以带负号。（5）梯度裁剪 0.5 是保险丝，正常训练几乎不触发；一旦频繁触发，先去检查学习率和 KL。

python code/ch001.py            # 完整训练：CPU 约 2–5 分钟，通常 10 万～30 万步内达标
python code/ch001.py --quick    # 快速跑通：20–40 秒，只验证流程不保证达标

常见坑

  • 用更新后的策略重新算旧 logp：比率的分子分母必须是"同一时刻的两次前向"。logp_old 只能在采样时算一次并存下来；训练里再算的就变成新策略概率，比率恒为 1，PPO 退化成普通策略梯度。
  • 把 truncated 当 terminated：CartPole 的 500 步上限是时间截断。如果这里切断 bootstrap，价值函数永远学不到"回合末端还值点分"，长回合任务会系统性低估价值。
  • 用回合数当训练预算：早期回合只有 20 步，400 个回合才 8000 步，什么都学不出来。预算必须按环境步数算，本章默认 40 万步上限。
  • 评估时还在采样动作：评估用 argmax（贪婪）。如果评估也用随机采样，看到 300 分别慌，那可能只是没撒到好轨迹。
  • 优势标准化泄漏到批次之外：标准化必须每次更新在当批数据内部做；跨批复用统计量会让不同批次的数据口径不一致，梯度方向被系统性扭曲。

练习与思考

  1. 把 --clip 分别改成 0.05 和 0.5 各跑一次，对比 KL 与裁剪比例的变化，解释为什么 ε 越小更新越保守。★
    提示
    只换命令行参数、观察日志即可。关注"裁剪比例"到达稳定值的时间和近20均曲线的陡峭程度：ε 小 → 更多样本被裁剪 → 单次更新更保守。
  2. 把 GAE 的 --lam 分别设为 0 和 1.0，解释单步 TD 与蒙特卡洛两种极端下训练曲线方差的变化。★
    提示
    λ=0：优势只剩单步残差（偏差大、方差小）；λ=1：接近蒙特卡洛（方差大）。多跑几个种子对比，别只看单次曲线。
  3. 注释掉优势标准化（把 adv = (adv - adv.mean()) / (adv.std() + 1e-8) 改成直接使用 adv），训练还稳吗？结合裁剪比例与 KL 的变化解释原因。★★
    提示
    CartPole 早期优势尺度在 ±10 以内，去掉标准化通常还能跑；后期优势变小后梯度尺度失衡。对比 5 万步处两条曲线的波动幅度。
  4. 把默认训练预算改成 --max-steps 40000 跑一次，记录 4 万步时的滑窗均值，对比完整训练的日志。这个实验说明什么？★★
    提示
    答案与"训练预算按环境步数计量"有关，第 400 个回合和 4 万步根本不是一回事。把两条日志按"环境步数"对齐再比较。
  5. 设计实验：实现"KL 早停"，若某个 epoch 后的近似 KL 超过 0.03 就提前结束本轮更新。写出你会改哪几行、观察哪些指标，并预测训练曲线怎么变。★★★
    提示
    在 ppo_update 的 epoch 循环里，每完成一个 epoch 计算一次平均 KL；超阈值即 break。预期：KL 峰值被压平，样本效率略降但稳定性上升，这正是 TRPO 思想以启发式形式的回归。

小结

  • PPO 的完整闭环是：采样一批经验 → GAE 估计优势 → 裁剪目标做多轮小批量更新 → 丢弃数据。
  • 裁剪的直觉是"有则改进、越界即停"：比率跑出 [1−ε, 1+ε] 后梯度归零，用一阶方法近似实现了信任域。
  • 实现上两个关键细节：logp_old 要存快照；terminated 与 truncated 的 bootstrap 处理不同。
  • 训练预算按环境步数衡量，CartPole 达标约需 10 万～30 万步；日志中的 KL、裁剪比例、熵是健康度仪表盘。
  • 下一章把 GAE 单独拆出来做实验：不同 λ、TD 与蒙特卡洛的偏差-方差权衡，以及优势估计如何影响 PPO 的样本效率。
