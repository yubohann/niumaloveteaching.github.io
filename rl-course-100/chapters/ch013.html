第一篇 · 策略梯度与 PPO

第 013 章：PPO的循环神经网络策略

自建一个"线索只在起点可见"的 T 型迷宫：MLP 策略上限 50%，GRU 策略把线索带进隐状态。用整段回合重放 + padding/mask 的标准做法，把循环 PPO 的工程细节一次写对。

  • 主题：部分可观测 / 循环策略
  • 关键公式：ht = GRU(ot, ht−1)；π(at|o1:t) 依赖整段历史
  • 预计学时：65 分钟
  • 前置章节：第 012 章

学习目标

  • 理解部分可观测（POMDP）下"当前观测不充分"的含义，以及为什么 MLP 会在记忆任务上撞到性能上限。
  • 实现 GRUCell 循环 Actor-Critic：采样时逐状态前向、回合边界重置隐状态。
  • 实现带 padding/mask 的定长序列批次，更新时按整段回合重放并只在有效时间步计算损失。
  • 在 CueTMaze 上对比 MLP 与 GRU：MLP ≈ 0.5、GRU 通常 > 0.9，理解差距的来源。
  • 掌握循环 PPO 的三个工程要点：序列边界、mask、以及为什么不逐帧混淆样本。

背景与动机

前面的所有策略都建立在马尔可夫假设上：观测就是决策所需的全部信息。但真实任务经常违反它，股票交易看不到全部持仓历史、导航没有地图、对话机器人只拿到当前一句话。这类任务叫部分可观测马尔可夫决策过程（Partially Observable MDP, POMDP），观测背后还有隐藏状态，而最优动作往往依赖历史。

循环神经网络（Recurrent Neural Network, RNN）是处理这类问题的标准工具：把每一步观测喂进 GRU/LSTM，隐状态逐渐积累历史信息，策略从这个"记忆"里读数。难点不在网络定义，而在训练管线：回合边界必须重置隐状态、批处理必须按序列回放、padding 不能计入损失。本章用 4 步 T 型迷宫把这个闭环完整写出来，任务预算只有 2 万回合，但所有真实 POMDP 问题需要的结构都在。

核心原理

1. POMDP 与"信息集"

POMDP 里环境状态 st 不可见，策略只能看到观测 ot ~ O(o|s)。决策的依据实际上是观测历史的压缩：

π(at | o1:t)　（决策依据是观测历史；π(at | ot) 只是它的特例）

本环境中线索 c 只在第 0 步可见，第 3 步做决定。MLP 在第 3 步看到 [1.0, 0]，与线索无关，最优策略只能在两个方向里固定选一个，成功率 50%。GRU 把 c 写进隐状态，第 3 步的决策可以依赖 o1:4。

更形式化地说，决策的真实依据是信念状态 bt(s) = P(st=s | o1:t, a1:t−1)：对历史的条件分布。最优策略是信念的函数，RNN 的隐状态就是信念的学习式压缩；无记忆策略的信息集只有当前观测，当观测里不含线索时，它对"该往哪边走"的后验始终是 50/50，任何动作选择都无法改进期望得分。

数值算例：0.5 上限的推导与诊断窗口的噪声

第 3 步的观测对两种线索完全相同（都是 [1.0, 0]），确定性策略必须对两种线索选同一个动作：选动作 1 时只在 cue=+1 的回合正确，选动作 0 时只在 cue=−1 的回合正确，两种线索各占 50%，所以成功率上限 = 0.5×1 + 0.5×0 = 0.5。随机策略也无法超过它：以概率 p 选动作 1 时正确率是 0.5p + 0.5(1−p) = 0.5，与 p 无关。这条推导给出清晰判据：在学习正常但天生无记忆的策略上，成功率必然收敛到 0.5，不会更高也不会更低。

再看窗口噪声：500 回合窗口的成功率近似二项比例，标准误为 √(p(1−p)/500)。p=0.5 时是 0.022（2.2 个百分点），p=0.90 时是 0.013。0.5 与 0.9 的差距约 18 个标准误，"GRU 是否真的利用线索"的判断绰绰有余；但 0.89 与 0.90 这样的细差在单个窗口下无法分辨（不足 1 个标准误）。若要以 0.01 的分辨率比较两条曲线，窗口需要约 3600 回合：n = p(1−p)/SE² = 0.09/0.005²。两个数字一起用：大窗口负责排除粗差，重复种子负责收窄细差。

2. 用 RNN 表示记忆

GRU 的更新是：

ht = GRU(ot, ht−1)，　π(at|·) = softmax(Wa ht)，　Vt = wv⊤ht h：隐状态；Wa、wv：策略头与价值头的参数

PPO 的比率要求"同一段历史下两次评估"：采样时隐藏状态从回合起点逐步累积，更新时必须从同一个初始状态出发、按同一顺序重放整段序列。因为采样用零初始状态（每个回合重置），更新时也从头重放即可，这是最容易写错的地方：如果把一批转移打乱成 minibatch、每步独立前向，记忆结构就没了，训练退化成无记忆策略。

数值算例：终局奖励如何回传到序列起点

取一个 4 步回合，奖励序列 [0, 0, 0, 1]（只有第 3 步得分），价值网络在四个时刻都输出 V=0.5，γ=0.99、λ=0.95。从后往前算：δ3 = 1 − 0.5 = 0.5（终止步，不做 bootstrap）；前三个时刻 δ = 0 + 0.99×0.5 − 0.5 = −0.005（价值高估 0.5，每步扣一点）。向后递推得到优势 [0.402, 0.433, 0.465, 0.500]。

逐项读：终局奖励的好消息以 γλ=0.9405 每步衰减，到达第 0 步只剩 0.5×0.94053 ≈ 0.416；再把三处价值高估的 −0.005 项累计扣除约 0.014，得到 0.402。这段计算解释三件事：信用沿序列按 γλ 衰减；价值误差也沿序列累积；第 0 步的优势只能通过完整的隐状态链条拿到。逐帧打乱批次时第 0 步拿不到任何终局信息，记忆层因此永远学不到"线索与决策"的关联。

3. 定长序列批处理：padding + mask

把每个回合当作一条序列，批次形状 (B, L, D)。回合长度不等时垫到最大长度 L，并生成 mask（有效步为 1）。损失只在有效步上求平均：

LCLIP = Σt mt·min(rtÂt, clip(rt)Ât) / Σt mt 本环境所有回合都是 4 步，padding 实际上不触发，但写法保持通用

本实现一次性重放整个回合（4 步），属于"完整 BPTT"。长回合任务要改成截断式 BPTT：把回合切成固定长度的片段，片段起点用采样时保存的隐状态（detach）作为初始状态，否则显存和计算会随回合线性增长。

变长序列还有一处细节：GAE 的 last_value 必须在每个回合自己的终止边界上使用，不能把 batch 里最长回合的 bootstrap 值套到短回合的尾巴上。本章回合固定 4 步且真实终止，这个问题不出现；一旦改成长短混杂的回合，短回合的尾部样本会被接上一个不存在的未来价值，优势与回报都会系统性偏移。正确做法是在采集阶段为每个回合单独计算优势；在垫齐后的张量上统一算会引入跨回合的串台。

边界：回合长度差异造成的 padding 浪费。按最长回合垫齐的代价取决于长度分布。极端例子：一个 batch 里 64 个回合，其中 1 个长 200 步、其余 63 个各 4 步；垫齐后的张量有 64×200 = 12800 个时间步位置，有效位置只有 200 + 63×4 = 452 个，约 96% 的计算打在空位上。对策分三档：按长度分桶再组 batch、把超长回合切片（与截断式 BPTT 共用机制）、或对长度分布稳定的任务直接设回合上限。本章环境每回合固定 4 步，浪费为零；一旦换成长短混杂的真实任务，这个比例要先估再训练。

边界：记忆半径。梯度沿时间连乘，RNN 的有效记忆不是无限的，GRU 通常能覆盖 10～100 步量级的依赖，具体取决于信号强度。本任务只需保留 4 步，处于舒适区；把间隔拉到几百步后，常见做法是截断 BPTT 配合片段起点的状态回传、加大隐状态，或改用带注意力的序列模型。判断是否越界有个便宜的方法：逐步拉长线索与决策之间的间隔，观察达标所需回合数；若增长越来越快甚至不再达标，说明已经接近或越过记忆半径。

4. 循环 PPO 的代价

三个成本要心里有数：更新不能随便打乱时间步（序列回放比逐帧样本慢）；隐状态重置点必须与回合边界严格一致；GRU/Cell 的逐帧循环在 GPU 上不如矩阵乘高效。所以实践中常先试"帧堆叠"（把最近 k 帧观测拼起来喂 MLP）作为无参数记忆方案，它够用就不上 RNN，本章练习 3 会让你亲手比较。

方案记忆载体参数量增量记忆范围适用场景
帧堆叠（k 帧）最近 k 步观测拼接输入维度变 k 倍，网络结构不变固定 k 步，看不见更早线索必然落在最近 k 步内
GRU/LSTM隐状态 htGRUCell 约 3h(d+h)+6h 个参数可学 10～100 步的衰减记忆依赖长度未知或随时间变化

量级感受：hidden=32、观测 2 维的 GRUCell 约 3×32×34 + 192 ≈ 3.5 千参数，hidden=64 时约 1.3 万，相对 MLP 躯干都不算大，真正的开销在逐帧循环的串行计算。选择顺序建议：先用帧堆叠估算"线索需要保留多少步"；窗口固定且小时帧堆叠更省，需要变长记忆或任务结构本身是部分可观测时再上 RNN。

数据流

每个 arm 一条完整训练：重设种子 → collect_episodes 采集 256 个完整回合（GRU 版每回合从零隐状态开始，逐帧采样并记录）→ 每回合独立算 GAE → padding 成 (B, L, ·) + mask → 8 epochs × episode_batch=64：按回合打乱、forward_seq 整段重放、mask 加权求损失 → 大窗口成功率统计 → 跑满 2 万回合 → 贪婪评估。

统一接口：让 MLP 也实现 forward_seq

MLP 版假装"没有隐状态"，但同样提供 forward_seq((B,L,D)) → (B,L,·)：内部把序列摊平成 (B·L, D) 一次前向再 reshape 回来。这样更新的代码与两种网络完全解耦，GRU 换成 MLP 只需要换构造函数，其余一行不用改。这种"接口对齐"是写对比实验时最省事的结构。

评估路径要单独交代：贪婪评估按回合逐步前向并携带隐状态，init_hidden 每回合调用一次。若忘了重置、复用上一回合残留的隐状态，第一个回合之后的读数都会被旧记忆污染。有条低成本的验证：把评估回合数从 20 加到 40，若成功率出现系统性漂移，先查隐状态重置点，再查评估环境是否是新实例。

关键代码与解读

片段 1：把"记忆压力"造进环境里

    def reset(self, seed=None, options=None):
        super().reset(seed=seed)
        self.t = 0
        self.cue = 1.0 if self.np_random.random() < 0.5 else -1.0   # 每回合重抽线索
        return self._obs(), {}

    def _obs(self):
        cue_visible = self.cue if self.t == 0 else 0.0   # 线索只在第 0 步可见
        return np.array([self.t / 3.0, cue_visible], dtype=np.float32)

    def step(self, action):
        if self.t < 3:
            self.t += 1                    # 前 3 步是空操作：只推进时间
            return self._obs(), 0.0, False, False, {"correct": None}
        # 第 3 步：做决定
        correct = bool(int(action) == (1 if self.cue > 0 else 0))
        self.t = 4
        r = 1.0 if correct else 0.0
        return self._obs(), r, True, False, {"correct": correct}

解读：（1）观测是 [t/3, cue] 两维：第一维是时间戳（告诉策略"现在在第几步"），第二维就是记忆压力的来源，只有 t=0 时非零，之后恒为 0。MLP 在第 3 步看不到线索，物理上决定了它的成功率上限是 0.5。（2）奖励只在第 3 步产生（正确 +1、错误 0），前 3 步全是 0：GAE 会把终局奖励的信用通过 γλ 递归回传到序列前端，这正是 RNN 更新"重放整段序列"的原因，切断序列 = 切断信用分配。（3）cue 每回合重抽（各 50%）且写在观测里：如果线索跨回合不变，MLP 也能靠"记住自己的参数偏好"侥幸达到 50%，但那不是解题；重抽保证"必须当回合记住"才是唯一解。（4）回合固定 4 步、终止是真实终止：本任务的 last_value 实际用不到，但代码保留了通用 bootstrap 写法，换变长环境时不需要重写。

片段 2：GRU 的两个接口，单步采样与整段重放

    def init_hidden(self, batch: int, device):
        return torch.zeros(batch, self.hidden_size, device=device)   # 回合起点：零状态

    @torch.no_grad()
    def step(self, obs: torch.Tensor, hidden: torch.Tensor):
        """单步前向（采样用，无梯度）。obs: (1, D)。"""
        h = self.gru(obs, hidden)
        logits = self.actor(h)
        value = self.critic(h).squeeze(-1)
        return logits, value, h

    def forward_seq(self, obs: torch.Tensor):
        """按整段序列重放，返回 (B, L, act_dim) 的 logits 与 (B, L) 的价值。"""
        B, L, D = obs.shape
        h = self.init_hidden(B, obs.device)
        logits_list, values_list = [], []
        for t in range(L):
            h = self.gru(obs[:, t], h)        # 逐帧推进；不 detach，梯度穿过整段
            logits_list.append(self.actor(h))
            values_list.append(self.critic(h).squeeze(-1))
        return torch.stack(logits_list, dim=1), torch.stack(values_list, dim=1)

解读：（1）两个接口是同一段数学的两种"形态"：step 用于"我不知道整段序列"的采样场景（步进式），forward_seq 用于"我拿得到整段序列"的更新场景（批处理）。分开写的目的：采样时套 no_grad 省显存，更新时保留计算图让梯度穿过时间。（2）forward_seq 的循环起点是 init_hidden(B)：注意采样时也是从零状态开始的（每回合重置），两处起点一致，比率才可比。（3）循环体内不能 detach：梯度必须穿过整段历史，GRU 才能学"第 0 步的线索与第 3 步动作的关系"；如果 detach，记忆层得不到训练信号，策略退化成"每帧独立"的 MLP。（4）注意 obs[:, t] 的取值顺序：stack 时 dim=1 把逐帧结果拼回 (B, L, ·)，与观测的 (B, L, D) 对齐，这是形状上最容易错的地方之一。

片段 3：padding 与 mask，把变长回合装进定长张量

    # padding 到最长回合，构建 (B, L, 特征) 张量与 mask
    max_len = max(len(e["obs"]) for e in episodes)
    B = len(episodes)
    obs_t = torch.zeros(B, max_len, env.observation_space.shape[0], device=device)
    act_t = torch.zeros(B, max_len, dtype=torch.long, device=device)
    logp_t = torch.zeros(B, max_len, device=device)
    adv_t = torch.zeros(B, max_len, device=device)
    ret_t = torch.zeros(B, max_len, device=device)
    mask_t = torch.zeros(B, max_len, device=device)      # 有效时间步为 1
    for i, e in enumerate(episodes):
        L = len(e["obs"])
        obs_t[i, :L] = torch.as_tensor(e["obs"], device=device)
        act_t[i, :L] = torch.as_tensor(e["act"], device=device)
        logp_t[i, :L] = torch.as_tensor(e["logp"], device=device)
        adv_t[i, :L] = torch.as_tensor(e["adv"], device=device)
        ret_t[i, :L] = torch.as_tensor(e["ret"], device=device)
        mask_t[i, :L] = 1.0

解读：（1）所有字段统一垫成 (B, L, ·)：观测是三维（带特征维）、其余是两维；mask_t 在写入有效步后才置 1。（2）为什么不用 torch.nn.utils.rnn.pad_sequence 之类的工具：本章想让你看清"垫零 + 掩码"的全部机制；工具函数只是把这段代码封装起来，原理不变。（3）padding 的内容是无意义的全零：它们绝不允许进入损失（片段 4 的 mask 加权就是为了这个），否则网络会被训练成"对零观测输出什么都不做"。（4）本环境每回合恰好 4 步，padding 不触发，这个通用写法是为练习 2 的长走廊与真实变长任务准备的：结构先写对，规模再放大。

            ratio = torch.exp(logp - logp_old[mb])
            surr1 = ratio * adv[mb]
            surr2 = torch.clamp(ratio, 1.0 - args.clip, 1.0 + args.clip) * adv[mb]
            policy_loss = -(torch.min(surr1, surr2) * m).sum() / m.sum().clamp(min=1.0)
            value_loss = (((values - ret[mb]) ** 2) * m).sum() / m.sum().clamp(min=1.0)
            entropy = (dist.entropy() * m).sum() / m.sum().clamp(min=1.0)
            loss = policy_loss + args.vf_coef * value_loss - args.ent_coef * entropy

解读：（1）torch.randperm(B) 打乱的单位是回合索引：时间步顺序完整保留，这是循环策略与 MLP 更新在结构上最大的区别，如果按时间步打乱，forward_seq 拿到的就不是真实序列，记忆结构被破坏。（2）损失三项全部写成 (x * m).sum() / m.sum().clamp(min=1.0)：分子按有效步加权、分母是有效步数，等价于"只在有效步上求平均"；clamp(min=1.0) 防止整个 batch 无有效步时除零。（3）注意策略损失这里用的是 mask 加权的手写平均，没有直接用默认 mean()：这是全书唯一一处不能用默认 .mean() 的 PPO 损失，padding 步在 ratio 与 adv 里都是垫零，不排除就会稀释梯度。（4）优势标准化在进循环前、只在 valid 位置上统计（见 ppo_update 开头）：跨 padding 统计均值/方差会让标准化参数失真。

python code/ch013.py --quick    # 两组各 3000 回合，约 20–40 秒
python code/ch013.py --arms gru --total-episodes 60000   # 加大预算看 GRU 上限

预期结论（以实跑为准）：MLP 的成功率稳稳停在 0.5 附近（它学到"总选一边"，这是它的信息上限）；GRU 通常在 3000～8000 回合内把近 500 回合成功率推过 0.9，熵同步从 0.69 下降，这两个信号都说明它确实在利用线索。若 GRU 跑满 2 万回合仍接近 0.5，优先检查三件事：隐状态是否在回合边界重置、更新时是否被逐帧打乱、forward_seq 的循环是否破了梯度链路。

常见坑

  • 更新时把序列打散成逐帧样本：记忆任务必须按"同一段历史"重放；逐帧更新会让 GRU 退化成只看当前帧的 MLP，成功率掉回 0.5。批处理的单位是回合，不是步。
  • 隐状态跨回合泄漏：回合结束不重置隐状态，会把上回合的线索/噪声带进新回合，训练信号被污染。采样与评估都要在 reset() 时同步重置。
  • padding 参与损失：垫零的假时间步如果计入策略/价值损失，梯度会被拉向"对零观测输出什么都不做"。必须用 mask 加权或只取有效步。
  • 序列重放时切断梯度：为了省显存给隐状态 detach 可以，但要在正确的边界上（截断 BPTT 的片段起点）；整段回合内 detach 会让"记忆"学不到任何东西。
  • 优势标准化把 padding 算进去：垫零步的优势会压低方差、偏移均值。标准化统计必须只在 mask > 0.5 的位置做。

练习与思考

  1. 把 GRUActorCritic 换成 nn.LSTMCell（需要同时维护 cell state），对比到达 90% 的回合数。★
    提示
    LSTMCell 返回 (h, c)，要把 cell state 一起沿回合传递；本任务很短，GRU 与 LSTM 的差距通常不大，但参数量与速度会有差别。
  2. 把走廊加长（第 0 步之后插入更多空步，比如 9 步后再决策），测试 GRU 的记忆长度极限，并观察需要多少回合才能学会。★★
    提示
    修改环境的时间戳分母与阈值即可（如 t/8、第 8 步决策）。间隔越长，信用分配越难，GRU 的达标回合数会显著上升。
  3. 为 MLP 实现"帧堆叠"：把最近 4 步观测拼接成 8 维输入，重跑对比。它能追平 GRU 吗？★★
    提示
    在采集时维护观测队列拼成输入；这样 MLP 也能"看见"第 0 步线索。注意帧堆叠改变了观测维度，两种方法的参数量要一起报告才公平。
  4. 实现截断式 BPTT：把整段回合切成两个长度为 L/2 的片段，第二段起点用采样时保存的隐状态 detach 后继续。★★★
    提示
    在 collect_episodes 里记录每个回合切分点的隐状态并断开梯度；更新时对片段循环（不整段重放）。本任务太短看不出差别，但换成 200 步的 Pendulum 会立刻体现计算与内存差异。
  5. 用二项标准误 √(p(1−p)/n) 设计一次公平比较：在 p≈0.85 附近要把两个 GRU 变体的差距分辨到 0.02，窗口需要多大？单窗口不够时跨种子重复，报告均值与标准误。★★
    提示
    取 SE=0.01（差距 0.02 的一半），n = 0.85×0.15/0.01² ≈ 1275 回合；三个种子均值后标准误再除以 √3。先算清预算再跑，比跑完再争论曲线可靠。

小结

  • POMDP 下策略应基于观测历史；RNN 用隐状态充当历史摘要，T 型迷宫用 1 bit 线索就能区分记忆与无记忆策略。
  • 循环 PPO 的两个接口：采样用单步 step（无梯度）、更新用 forward_seq（整段重放）。
  • 批数据按回合组织、padding 配 mask、损失只算有效步；长回合任务改用截断式 BPTT。
  • 实验结果：MLP 被信息上限锁在 0.5，GRU 在数千回合内超过 0.9，记忆能力的价值被清晰量化。
