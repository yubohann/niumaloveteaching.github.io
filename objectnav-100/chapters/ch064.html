第 064 讲｜ZSON II：跨数据集零样本

第 063 讲拆了 ZSON（Majumdar 等 2022）的语义目标嵌入与训练机制：在 HM3D 的 800 个无标注场景上用 ImageNav 训练 500M 步，评测时把目标换成文本。本讲读这套机制的结果面：同一训练产物在 Gibson、HM3D、MP3D 三个 ObjectNav 数据集上零样本评测，两套本体配置分别训练，共 5,195 条评测 episode、三次运行取平均。对照对象包括 ZER（Al-Halah 等 2022，Zero Experience Required）、CoW 与使用 GPS 与罗盘的有监督 OVRL（Yadav 等 2022）；消融给出两个泛化杠杆（编码器预训练与环境多样性）的量级；微调实验给出上界（MP3D 25M 步、HM3D 100M 步）；最后用复合指令的定性证据讨论开放世界接口的能力与局限。

  • 主题：跨数据集评测 / 零样本协议 / 消融设计 / 结果解读
  • 关键公式：SPL = (1/N) Σi Si · ℓi* / max(ℓi, ℓi*)；跨域增益 = SR跨域 − SR同域基线
  • 预计学时：75 分钟
  • 前置章节：第 063 讲（ZSON I：多模态目标嵌入）

学习目标

  • 会读矩阵：说清三套 ObjectNav 数据集的 episode 数、场景数、类别数、本体配置与成功判据，避免跨配置直接排序。
  • 会算：与 ZER、CoW、OVRL 的绝对与相对差，零样本相对微调上界的保留率，以及两组消融的增量与相对变化。
  • 会判断：跨数据集泛化的两个杠杆（视觉编码器预训练、训练环境多样性）各自影响哪个任务，以及量级差异的原因。
  • 会设计：跨域评测协议，包括检查点选择规则、评测次数与方差报告、可见性口径与本体配置绑定。
  • 会读：微调上界（预算占比 5% 与 20% 的两组实验）、复合指令的定性证据，以及论文自述的失效条件与偏差风险。

背景与动机

第 063 讲证明了机制可行：ImageNav 训练的策略可以接受文本目标。但机制可行不等于结果可信，跨数据集零样本的评测有三个必须回答的问题。第一，训练域只有一个（HM3D 的 800 个场景），测试域有三个（Gibson、HM3D、MP3D），测试场景与训练场景不重叠，性能如何在域间变化？第二，与已有方法的差距有多大，对照是否公平？CoW 使用 RGB-D 且训练步数为零，ZER 在 Gibson 上训练并额外用 14K 标注图训练映射层，OVRL 使用 GPS 与罗盘并且训练了 40k 条人类演示，这些差异都会影响读数。第三，零样本离“用上目标域数据”有多远？微调实验给出上界，也给出预算换算。

本讲的读法分三层。协议层：数据口径、成功判据、检查点规则与方差报告，决定数字能不能比。结果层：三数据集矩阵与三组对照，决定方法处在什么位置。机制层：编码器与环境多样性两组消融，决定性能来自哪里、下一步该往哪里扩。这三层也是读任何跨域零样本论文的通用顺序。

核心原理

1. 评测协议与数据口径

ZSON 的评测使用一个 ImageNav 数据集与三个 ObjectNav 数据集，按各自发布时的挑战协议评测。ImageNav（Gibson）用于确认基础任务能力；三个 ObjectNav 数据集覆盖不同规模与类别体系。所有 ObjectNav 的 episode 均不与训练场景重叠；训练侧只使用 HM3D 的 800 个场景做 ImageNav。

合计 5,195 条 ObjectNav episode，按论文口径对每个数据集评测三次并取平均。成功率的标准差为：Gibson 0.02%、HM3D 0.46%、MP3D 0.11%（Majumdar 等 2022，表 1 注）。三个数字都很小，说明同一检查点上的评测波动有限；但它们不替代多种子训练方差，跨论文比较时不能把 0.46% 当作方法差异的下限。成功判据的基础项是停止位置距目标实例 ≤ 1.0 m；可见性要求随数据集与挑战年份变化，RoboTHOR 与 Pasture 要求可见（Gadre 等 2022），Habitat 2021 口径不要求，跨数据集表格必须把这项单列。检查点规则为：在 ObjectNav 验证集成功率最高的时刻取权重，再进入评测。

先读同配置内的对照。配置 A（Gibson）：ZSON 把 ImageNav 成功率从 ZER 的 29.2% 提到 36.9%（+7.7 个百分点，相对 +26.4%），把 ObjectNav 成功率从 11.3% 提到 31.3%（+20.0 个百分点，相对 +177.0%）。同域基础任务的小幅提升换来下游任务的大幅提升，说明语义目标嵌入对零样本迁移的贡献集中在目标接口处。配置 B（HM3D 与 MP3D）：相对 CoW，ZSON 在 MP3D 上成功率 +4.2 个百分点（相对 +37.8%），SPL 低 1.5（相对 −23.8%），即成功率更高、路径效率略低；相对有监督 OVRL，HM3D 上成功率低 7.3 个百分点（相对 −22.3%），SPL 高 0.3（相对 +2.4%），MP3D 上成功率低 10.0 个百分点、SPL 低 2.2。

跨数据集读法要注意两点。第一，HM3D 与 MP3D 同用配置 B，可比性较强：HM3D 成功率 25.5% 比 MP3D 的 15.3% 高 10.2 个百分点（相对高 66.7%）。论文把差距归给类别体系与场景构成：MP3D 有 21 类、重建伪影更多，HM3D 6 类且与训练场景同源（同为 HM3D 场景库，只是 split 不同）。第二，Gibson 用配置 A，其 31.3% 与配置 B 的结果不可直接比。

成功率增益的量级可以对照挑战赛历史：论文报告相对已有零样本方法的绝对增益为 4.2 到 20.0 个百分点，并指出这一幅度与 Habitat 2020 与 2021 两届挑战赛冠军之间约 5 个百分点的差距相当或更大（Majumdar 等 2022，摘要）。按倍数读，20.0 / 5 = 4.00 倍、4.2 / 5 = 0.84 倍。这个对照说明零样本路线当时的进步速度与有监督竞赛的年度迭代处于同一量级。

3. 与有监督 OVRL 的距离

OVRL（Yadav 等 2022，Offline Visual Representation Learning for Embodied Navigation；其升级版 OVRL-v2 是本系列第 053 与 054 讲的主角）是本组有监督对照：用 40k 条人类演示与模仿学习训练，评测时使用 GPS 与罗盘。它在 HM3D 上的 32.8% / 12.3 与 ZSON 的 25.5% / 12.6 构成一对有意思的读数：成功率差 7.3 个百分点，SPL 几乎持平（ZSON 高 0.3）。路径效率持平说明零样本策略的搜索行为不差，差距集中在“找到并停在目标附近”的最终成功率上。

SPL 与 SR 的联合读法能进一步拆出成功轨迹的路径效率。按定义 SPL = SR × e，其中 e 为成功轨迹上 ℓ* / ℓ 的均值。由表值反推：HM3D 上 ZSON 的 e ≈ 12.6 / 25.5 = 49.4%，OVRL 的 e ≈ 12.3 / 32.8 = 37.5%；MP3D 上 ZSON 的 e ≈ 4.8 / 15.3 = 31.4%，OVRL 的 e ≈ 7.0 / 25.3 = 27.7%。这组反推说明 ZSON 的差距主要在“能否成功”，其成功轨迹的路径更为直接；反推值属估算口径，比较时以原始 SR 与 SPL 为准。

另一个细节是 OVRL 的 HM3D 行与其 MP3D 行是同一个 agent：OVRL 本身也是从 MP3D 跨到 HM3D 评测，因此这组对照是两个跨域系统之间的比较，并不构成“同域训练对跨域零样本”的对照。公平性边界有三条：OVRL 使用 GPS 与罗盘，ZSON 只用单目 RGB；OVRL 使用目标域附近的演示数据；OVRL 的报告含 ImageNav 参考列 27.0 / 54.2，属有监督上限参考。

6. 开放世界复合指令的定性证据

论文给出复合指令实验：同一出生点与朝向下，分别给“bathroom sink”“kitchen sink”“sink and a toilet”“sink and a stove”，每个指令跑 5 条采样轨迹。观察有三点。第一，带房间信息的指令让智能体进入对应房间：找“bathroom sink”时不进厨房，找“kitchen sink”时不进浴室。第二，房间信息可以推断：给“sink and a stove”时智能体偏向厨房，给“sink and a toilet”时偏向浴室，说明策略学到了物体共现的室内先验。第三，轨迹长度为 88 到 225 步，明显长于常规 ObjectNav 的短程目标，智能体常先做一次约 360° 环视再决定方向。这组证据是定性的，5 条轨迹不构成统计结论，它的作用是展示文本接口的可扩展性：属性、房间、共现都可以通过同一嵌入通道表达。

7. 协议边界与失效条件

引用这套结果前要过五道检查。第一，版本与引用链：ZSON 表 1(b) 的 CoW 行（MP3D 6.3 / 11.1）来自 CoW 早期版本，CoW v2 表 3 的对应行为 CLIP-Grad. 的 4.9 / 9.2 与 OWL-ViT 的 3.7 / 7.4，两套数字不可混用。第二，可见性判据：基础项（1.0 m 距离）一致，可见性要求随挑战年份不同，比较时逐表确认。第三，检查点规则：按 ObjectNav 验证成功率选点会抬高报告值，复现时固定同一规则；若要报告“无验证集选点”的严格零样本数字，需要另做实验。第四，方差口径：三次评测的标准差（0.02 / 0.46 / 0.11）反映评测波动，不反映训练种子方差。第五，失效条件：论文自述在非常规位置（如卧室中的炉灶）容易失败，训练场景的统计偏差会被策略继承；嵌入对细粒度属性分辨有限，这一点与第 062 讲属性描述增益不足同源。

关键代码与解读

三段代码覆盖评测循环、消融矩阵与 SPL 计算，输出结构对应上文表格。

片段 1：零样本评测循环与指标聚合

def evaluate_zero_shot(policy, env, episodes, clip_text, runs=3,
                       require_visible=True):
    """用文本目标编码评测；同一检查点跑 runs 次，报告均值与标准差。"""
    results = []
    for _ in range(runs):
        sr_list, spl_list = [], []
        for ep in episodes:
            goal = clip_text(ep.goal_name)          # 文本塔，L2 归一化
            obs, done, info = env.reset(ep), False, None
            state = policy.init_state()
            while not done:
                action, state = policy.act(obs, goal, state)
                obs, done, info = env.step(action)
            success = info.distance_to_goal <= 1.0
            if require_visible:                         # 按数据集协议开关
                success = success and info.goal_visible
            sr_list.append(float(success))
            if success:
                spl_list.append(info.shortest_path / max(info.path_length,
                                                          info.shortest_path))
            else:
                spl_list.append(0.0)                # 失败轨迹 SPL 计 0
        results.append((sum(sr_list) / len(sr_list),
                        sum(spl_list) / len(spl_list)))
    return results

解读：（1）目标编码在评测循环内做接口替换，其余流程与训练一致；可见性项按数据集协议开关，不能写死。（2）失败轨迹 SPL 计 0 是标准口径；若改用 SoftSPL（失败按距离比例计分），数字不可与论文表混排。（3）三次运行共用同一检查点，报告的是评测波动；若要多检查点方差，应在训练侧另做多种子实验。

片段 2：消融矩阵运行器

def run_ablation_matrix(train_sets, encoders, test_sets, clip_text,
                        seeds=(0, 1, 2)):
    """遍历（训练域 x 编码器 x 测试域），固定检查点规则后汇总。"""
    table = {}
    for train_name, train_envs in train_sets.items():
        for enc_name, encoder in encoders.items():
            policy = train_semantic_nav(train_envs, encoder, steps=500_000_000)
            ckpt = select_checkpoint(policy, rule="objectnav_val_sr")
            for test_name, (test_envs, episodes) in test_sets.items():
                row = [evaluate_zero_shot(ckpt, test_envs, episodes, clip_text)
                       for _ in seeds]
                table[(train_name, enc_name, test_name)] = summarize(row)
    return table

解读：（1）检查点规则作为函数参数显式写出，避免不同行使用不同规则；论文的规则用 ObjectNav 验证成功率，消融行之间必须一致。（2）训练域、编码器、测试域三层循环对应论文表 3 的四行与主表的三列，复现时建议固定随机种子集并报告均值与范围。（3）预算固定为 500M 步，训练域与编码器的差异才可归因；若某行预算不同，需要单列说明。

片段 3：SPL 的边界处理

def episode_spl(success, path_length, shortest_path):
    """单 episode SPL；处理退化情形，保证分母非零。"""
    if not success:
        return 0.0
    if shortest_path is None or shortest_path <= 0.0:
        return 0.0                                  # 无有效最短路径
    denom = max(path_length, shortest_path)
    if denom <= 0.0:
        return 0.0                                  # 非法路径长度
    return shortest_path / denom

# 注意：部分平台的 SPL 用 max(l, l*) 作分母，部分用 l；
# 跨论文比较前先确认分母口径与失败计分规则。

解读：（1）SPL 的两处边界是失败计 0 与分母口径；论文使用的是以 max(ℓ, ℓ*) 为分母的标准定义。（2）最短路径来自 oracle 测地距离，缺失时应记为无效，不应以近似值替代，否则会系统性高估 SPL。（3）把该函数与 SR 聚合放在同一处实现，能避免不同实验脚本之间的口径漂移。

常见误区

  • 跨配置直接排序：症状是把 Gibson 的 31.3% 与 HM3D 的 25.5% 当作同一系统的域间差距。根因是配置 A 与配置 B 的相机高度、视场与分辨率不同，且由两个独立 agent 产生。修复：表格按配置分组；跨数据集比较只在同配置内做（HM3D 与 MP3D）。
  • 版本链混用 CoW 数字：症状是引用 MP3D 11.1% 与 9.2% 时互相矛盾。根因是 ZSON 表 1(b) 引用的 CoW 早期口径与 CoW v2 表 3 不同。修复：标注引用链与版本；同一张表只用一条链。
  • 可见性判据与 1.0 m 阈值混谈：症状是复现成功率对不上。根因是成功判据由距离项与可见性项组成，可见性要求随挑战年份变化。修复：评测脚本把两项分开记录，报告时写明数据集与年份。
  • 把检查点规则当作无关细节：症状是训练曲线正常但报告值偏高。根因是用了 ObjectNav 验证成功率选点。修复：固定并写明规则；需要严格口径时改用训练侧验证指标并重跑。
  • 把评测标准差当训练方差：症状是用 0.46% 判断方法差异显著性。根因是三次评测共用同一权重。修复：显著性判断用多种子训练；评测标准差只说明单检查点的评测稳定性。
  • 忽略 OVRL 的输入与训练域差异：症状是得出“零样本已接近有监督”的过强结论。根因是 OVRL 使用 GPS 与罗盘且其 HM3D 行本身是跨域评测。修复：对照表标注传感器、训练域与演示数据量，结论限定在可比范围内。

    提示
    规则按论文固定为 ObjectNav 验证成功率；评测 3 次并报告均值与标准差；可见性按数据集挑战年份分别开关；配置按数据集发布协议绑定。替代方案：训练侧验证指标选点（更严格、数字更低）、更多评测次数（更稳、成本高）、统一配置（可比但破坏历史口径）。

    提示
    基础任务的目标是图像匹配，训练中策略能直接拟合目标特征；下游任务的目标是类别语义，依赖编码器的语义泛化，预训练收益更大。实验：固定策略，替换编码器为不同预训练强度的版本，分别测 ImageNav 与 ObjectNav 成功率，观察增益比是否稳定在 1.8 到 2.1 倍附近。

    提示
    共 2 × 2 × 3 = 12 格，每格固定 500M 步与同一检查点规则；主指标为零样本 SR，辅以 SPL 与失败类型；判定标准包括：跨域增益方向跨种子一致、环境多样性增益在 6.6 个百分点量级可复现、编码器增益在下游大于基础任务。混杂控制包括场景数、类别体系与配置绑定。
  5. 微调实验显示 5% 与 20% 预算分别带来 SR +7.6 与 +24.1。预测把微调预算提到 500M 步的结果，并说明两个风险。★★
    提示
    预计继续向有监督上界收敛但收益递减，可能超过 OVRL；风险一是在目标域上过拟合，跨域回到其他数据集时性能下降；风险二是失去零样本属性，需要目标域标注与 RL 基础设施，部署成本上升。

小结

  • 评测协议：4,200 条 ImageNav（Gibson，配置 A）与 5,195 条 ObjectNav episode（Gibson 1,000、HM3D 2,000、MP3D 2,195）；成功基础项为停止距离 ≤ 1.0 m，可见性要求随数据集与年份变化；三次运行取平均，标准差 0.02 / 0.46 / 0.11。
  • 主结果：配置 A 的 Gibson 上 ObjectNav 31.3% / 12.0，相对 ZER 成功率 +20.0 个百分点（相对 +177.0%）；配置 B 的 HM3D 25.5% / 12.6、MP3D 15.3% / 4.8；相对 CoW 成功率 +4.2、SPL −1.5。
  • 与有监督 OVRL 的对照：HM3D 成功率低 7.3 个百分点，SPL 高 0.3；OVRL 使用 GPS 与罗盘且其 HM3D 行本身为跨域评测，结论需限定在可比范围。
  • 消融：编码器预训练使 ImageNav +4.5 到 +5.8、ObjectNav +9.4 到 +10.4；环境从 72 扩到 800 使 ImageNav −0.9、ObjectNav +6.6（相对 +26.7%）；起作用的是预训练，模型容量本身不是关键变量。
  • 微调上界：MP3D 25M 步（预算 5%）到 22.9% / 9.2；HM3D 100M 步（预算 20%）到 49.6% / 27.0；零样本保留率为 66.8% 与 51.4%。
