第 003 讲｜成功判据：1m 距离 + oracle 可见性

本讲把「到达目标物体」从口头定义变成可执行的判据：STOP 触发后，停止点到任一目标实例表面的欧氏距离小于 1.0m，且该实例在 oracle 可见性意义下可被看到。课程给出四条件分解、表面距离推导、自由偏航下的可见性化简、五个边界样例的实算判定，并落到一份可运行的 Python 判定函数。

  • 主题：ObjectNav 成功判据 / 成功区 / oracle 可见性
  • 关键公式：S = 1(STOP) ∧ ∃i [ d(p, Bi) < 1.0 ∧ Vis(p, Bi) ]
  • 预计学时：60 分钟
  • 前置章节：第 002 讲（任务家族：PointNav / ImageNav / ObjectNav / InstanceImageNav）

学习目标

  • 能用「意图、有效、接近、可见」四个条件完整写出 ObjectNav 成功谓词，并指出每个条件在评测代码中的对应检查。
  • 掌握点到轴对齐包围盒（Axis-Aligned Bounding Box, AABB）表面距离的推导与实现，理解它与物体中心距离在成败判定上的系统性偏差。
  • 会实现 oracle 可见性检查：自由偏航条件下的化简、俯仰可达性判据、遮挡光线投射，以及视场角与深度裁剪参数的接入方式。
  • 能构造并判读五个边界样例：恰好 1.0m、目标被遮挡、双实例各缺一个条件、最近实例被遮挡而次近实例合格、俯仰受限导致翻转。
  • 能解释判据的交互代理动机与防投机作用，并说清 oracle 可见性不检查「智能体是否真的看见过目标」这一语义边界。

背景与动机

第 001 讲把 ObjectNav 形式化为部分可观测马尔可夫决策过程，并约定智能体用 STOP 动作声明完成；第 002 讲把 ObjectNav 放进任务家族，指出它与 PointNav 的差别在目标语义。留下的问题很具体：STOP 之后，评测器凭什么判定这次导航成功？

PointNav 的做法可以照抄的部分很少。2020 挑战页给出的 PointNav 判据是停止点在目标坐标 0.36m 范围内，该数值等于两倍智能体半径（0.18m×2，LoCoBot 配置，Batra 等，2020）。语义目标无法沿用这一口径：类别实例有体积与形状，床与凳子的尺寸相差数倍；把阈值与机器人尺寸绑定，会让「停在大床边缘」被判失败，也会让「贴近小件物体」的门槛失去意义。判据需要一个新的几何对象，即物体本身的包围盒，以及一个新的动机，即交互可达性。

2020 年多机构工作组给出的共识文档（Batra 等，2020，ObjectNav Revisited）把成功判定拆成四个条件：意图（Intentionality，智能体主动触发 STOP）、有效（Validity，停止位置对智能体尺寸可导航）、接近（Proximity，停止点位于物体表面周围的距离壳内）、可见（Visibility，物体能被看到）。文档建议距离壳半径从 r = 1.0m 起步，并允许随社区进展逐年收紧；可见性给出两档口径，严格档要求停止时物体进入画面（宽松实现为至少 1 个像素），宽松档采用 oracle 可见性：假设一个 oracle 能够在不移动位置的前提下，通过原地转向与调节相机俯仰，把物体纳入视野。2020、2021、2023 三届挑战页采用的正是后一档，判据文本历届一致。

本讲解决三件事：第一，把判据写成可以逐条对照实现的布尔表达式，区分页面文本口径与数据集实现口径；第二，给出表面距离与 oracle 可见性的可运行实现，并用五个边界样例验证；第三，解释这套设计为何能抑制「停在地毯上」式的投机成功，以及它仍然留下了哪些漏洞。效率指标（SPL）只在本讲出场一次，用于说明多实例规则；完整的公式、误读与边界留给第 004 讲。

核心原理

1. 成功谓词：四条件与布尔式

设 episode 的目标类别为 c，场景语义标注给出该类别的实例集合 {B1, …, Bn}，每个实例用包围盒表示。智能体在第 T 步触发 STOP，其参考点位置为 p，相机位姿由平移与俯仰决定（偏航可原地调整，见第 4 小节）。成功谓词写为：

S = 1(STOP) ∧ ∃i [ d(p, Bi) < r ∧ Vis(p, Bi) ] r = 1.0m；d 为点到包围盒表面的欧氏距离；Vis 为 oracle 可见性；两个条件必须作用在同一个实例 Bi 上

四个条件与谓词的对应关系如下。意图对应 1(STOP)：只有智能体主动声明完成才进入判定，超时或碰撞终止一律记为失败。有效对应 p 位于可导航区域：真实导航过程中由构造保证，但在回放轨迹、人工标注或数据集合成时需要单独检查。接近对应 d(p, Bi) < r：距离按物体表面度量，理由见第 2 小节。可见对应 Vis(p, Bi)：从停止位置出发，存在一个可达相机位姿使物体进入画面，理由见第 3 小节。

四个条件中，本讲的实现函数省略「有效」项：停止点直接来自仿真器状态，可导航性由构造保证；对日志回放或人工构造的位姿，需要单独调用导航网格查询确认。

三个任务的阈值对照如下表。注意三点差异：阈值数值不同、对物体尺寸的敏感度不同、可见性要求的紧松不同。

任务 / 版本停止判据阈值来源尺寸敏感
PointNav（2020）到目标坐标距离 ≤ 0.36m两倍智能体半径（0.18m×2）否，目标为点
ObjectNav（2020–2023）到任一实例表面 < 1.0m 且 oracle 可见交互可达性代理，可收紧是，按表面度量
RoboTHOR（2020）到目标 < 1.0m 且停止时在相机视场内真机人工核验可行性是

RoboTHOR 一行是严格可见性档的实例：停止时必须真的看着目标。Habitat 挑战页选择 oracle 档，理由是评测目标聚焦导航能力，把取景（framing）从判据中剥离；同时 oracle 可见性被明确定义为「智能体已经足够近、可以交互」的代理量。

2. 接近度：点到 AABB 的表面距离

包围盒取轴对齐形式 B = [bx−, bx+] × [by−, by+] × [bz−, bz+]。点到盒的距离按轴独立计算：某一轴上参考点落在区间内，该轴贡献为零；落在区间外，贡献为该轴到最近端点的差。三个轴的平方和开方即得：

d(p, B) = sqrt( Σk∈{x,y,z} max(0, bk− − pk, pk − bk+)2 ) 落在区间内的轴贡献 0；参考点位于盒内时 d = 0

表面距离与中心距离的差别不是小数。中心距离永远不小于表面距离（盒的中心到表面的最小距离为内切半径，恒大于零），用中心距离实现判据会系统性偏严。以参考点 p = (0, 0.88, 0) 为例，几组实算如下表。

实例包围盒（x,y,z 区间，m）表面距离（m）中心距离（m）按 1.0m 判定
大床 ((0.2,2.4),(0,0.6),(−0.9,0.9))0.3440931.423517表面通过，中心误判失败
凳子 ((0.9,1.3),(0,0.5),(−0.2,0.2))0.9769341.267636表面通过，中心误判失败
高位实例 ((0.7,1.2),(1.0,1.3),(−0.2,0.2))0.7102110.987623两者都通过，边界余量不同

表中第二列的数值由本讲代码实算（Python，双精度）。可以看到，尺寸越大的家具，中心距离相对表面距离的偏大越多：大床案例偏大 1.08m，足以把通过判为失败。

与接近度绑定的还有参考点选择。判据文档建议把智能体位置表示为单一点（例如质心）。参考点高度的选择会让高位或低位实例的判定翻转。以包围盒 ((0.7,1.2),(1.0,1.3),(−0.2,0.2)) 为例：参考点取 y = 0.88m 时距离为 0.710211m，取地面点 y = 0.0m 时距离为 1.220656m，一个通过、一个失败。实现里必须把参考点约定写进配置，并在文档与代码两侧保持一致。

3. oracle 可见性：定义、化简与参数

挑战页的定义是：不要求智能体在停止位姿下正在看着物体，只要求存在一个 oracle，能够在不改变停止位置的前提下，通过原地转向智能体、抬头或低头，把物体纳入视野。该定义把取景从导航评测中解耦，作为「足够近、可以交互」的代理。与之相对的是严格可见性：停止时刻物体至少有一个像素落在画面内（Batra 等，2020 给出的宽松起点）。2020 年 RoboTHOR 赛道采用严格档，Habitat 赛道采用 oracle 档。

在 oracle 模型下，可见性检查可以做两步化简。第一步，消去水平视场约束：偏航可以自由调整，把相机光轴对准物体上任一表面点即可，水平半视场为 79°/2 = 39.5°，物体在 1m 处的半宽覆盖为 tan(39.5°)×1m ≈ 0.824m，足以容纳类别实例。第二步，消去垂直视场约束中的可调部分：相机俯仰可在范围 [−P, P] 内调整，物体表面点的俯仰角为 θ，则存在光轴使该点落在画面内，当且仅当 |θ| ≤ P + VFOV/2。化简后：

Vis(p, B) ⟺ ∃ q ∈ ∂B： |pitch(q)| ≤ P + VFOV/2 且 线段(相机位姿(p), q) 与场景遮挡物不相交 ∂B 为盒表面；P 为俯仰可达上限；oracle 档默认 P = 90°（不再限制）；pitch 以水平面为零起算

相机参数来自 2020 共识文档对 Azure Kinect 的匹配：水平视场 79°，分辨率 480×640（高×宽），深度裁剪区间 [0.5, 6.0] m。由宽高比 480/640 = 0.75 可算垂直视场：

VFOV = 2·arctan( tan(79°/2) × 480/640 ) = 63.4530°，半值 31.7265° 实算值；与俯仰上限组合后，P = 30° 对应的可见边界为 30° + 31.7265° = 61.7265°

深度裁剪下限 0.5m 意味着 1m 判据的内侧存在盲区：停止点离表面过近时，最近表面可能落到深度量程以外。oracle 的遮挡测试不受该限制，基于 RGB-D 的在线实现需要把量程写进可见性判据。

实现上，表面点 q 取「相机到盒的最近表面点」加八个角点共九个样本，任一样本通过遮挡测试即判可见。遮挡测试用线段与 AABB 的 slab 相交法（逐轴计算参数区间求交），无需枚举三角面。可见性检查的是几何可观察性，不检查智能体在停止前是否真的看见过目标：「首见即停」是行为假设，不是判据的一部分。这一点决定了运气停车同样能被判成功，属于判据已知的语义边界。

4. 多实例规则：成功取任意，效率取起点最近

谓词中的存在量词 ∃i 是关键。场景里同一类别可能有多个实例，判据对任意一个成立即成功，与实例离起点的远近无关。效率指标使用另一条规则：SPL 的最短路径参照量 li 取离起点最近实例的测地最短路径长度（Anderson 等，2018；挑战页 2020/2021/2023）。两条规则必须拆开实现，混用会产生系统性错误。

用一个实算例子说明差异。设起点附近的 chair1 的最短路径 l = 2.0m，最近的另一把 chair2 在 15.5m 外。智能体绕过近处实例、跑到远处实例并成功停止，实际路径长度 p = 15.5m：成功指标 S = 1，SPL = 2.0 / max(15.5, 2.0) = 0.129032。若它就近停在 chair1，设 p = 2.4m，则 SPL = 2.0 / 2.4 = 0.833333。两次都算成功，效率相差约 6.5 倍。这就是多实例场景下「成功率高、SPL 低」的典型来源。

另一个容易写错的地方是条件归属。谓词要求接近与可见作用在同一实例上。构造两个实例：inst0 距停止点 0.450999m 但被墙遮挡，inst1 可见但距离 1.063203m；两者各通过一个条件、各失败一个条件，整体判定失败。若实现时把"存在一个接近的实例"与"存在一个可见的实例"分别判断再取与，就会把这个失败案例误判为成功。

5. 版本口径与实现沿革

判据文本在 2020、2021、2023 三届挑战之间保持一致，数据集、类别数与动作空间有变化，整理如下表。

页面文本与数据集实现之间存在一处需要说明的差异。页面写的是「停止点到任一实例的欧氏距离 1.0m 内」，而 2020 年发布的实现检查的是「STOP 位置到有效视点的测地距离 0.1m 内」。两者描述同一对象：数据集合成阶段以 Ragent/2 = 0.09m 的网格在楼层上采样，保留同时满足可导航、在物体有向包围盒 1.0m 内（或盒内）、oracle 可见的位置，记为有效视点；成功区即这些视点的集合。由于视点网格间距 0.09m，0.1m 的测地容差与「停止点落在成功区内」在网格分辨率意义下等价。后续 Habitat-Lab 版本改用 distance_to = VIEW_POINTS 的距离量与 success_distance 参数实现同一逻辑，其中 Success 量使用严格小于比较（nav.py 主分支）。面板级别的定义与代码级别的实现需要分别记清，做跨版本对比实验时以对应版本的配置为准。

成功区的规模可以用一个实算估计。取长 2.2m、宽 1.8m 的床，外扩 1.0m 的环带面积约等于周长乘 1.0m 再加半径 1.0m 的圆角面积：2×(2.2+1.8)×1.0 + π×1.0² = 11.1416 m²。按 0.09m 网格粗算，原始候选点约 11.1416 / 0.09² ≈ 1375 个；再经可导航性与可见性过滤后，才是数据集里的有效视点。该量级说明两件事：预计算视点表可以高保真复现判据；判定边界的精度取决于网格步长，步长减半时候选点数量约增至四倍。

7. 设计动机与失效模式

为什么判据需要可见性这一项？只保留距离条件时，成功区退化为以实例表面为界的球形邻域。在杂物密集的室内场景中，该邻域包含大量视觉上不可观察的位置：墙后、柜内、被大件家具完全挡住的死角。一个不去识别目标的策略，只要在类别常见位置附近（例如客厅地毯一带）停下，就可能落进某个实例的距离壳内并获得成功信号。oracle 可见性要求停止位置与实例之间存在一条无遮挡视线，把「到达」与「可观察」绑定，堵住了「近在咫尺但什么也看不到」这一类投机成功。这就是「停在地毯上」式投机的主要形态：利用几何邻近性获取成功，却从未完成目标发现。

该设计同时划出了两条边界。第一，oracle 可见性只做几何判定，不检查智能体的感知历史：没有「必须看见过才能停」的要求，误打误撞停在合格位置同样算成功。第二，多实例规则下，成功对任意实例成立，因此只要某个实例的成功区恰好被路过，就能拿到成功分，效率分由 SPL 单独约束。这两条边界在评测数据分析里必须纳入解释框架，避免把「运气停车」当成感知能力证据。

实现层面的失效模式有四类，按出现频率排序：只判距离不判可见性（产生隔墙假成功）；用中心距离代替表面距离（大件家具系统性失败）；把两条件跨实例混用（样例 C 类案例误判成功）；可见性样本不足或参考点错误（中心被挡边缘可见的实例误判失败，或高位实例因参考高度不同而翻转）。四类问题都能用第 6 小节的样例表直接回归测试。

实现思路与设计

判定流水线分五步：episode 加载时把每个目标实例的包围盒与标签读出；STOP 事件发生时记录参考点与相机位姿；对每个实例计算表面距离，筛出接近度通过者；对通过者做 oracle 可见性检查；任一实例两条件同时通过则判成功，同时把各实例的距离与可见性明细写入日志，供失败分析使用。效率侧另记两个量：起点到最近实例的测地最短距离 l，以及实际路径长度 p。

关键代码与解读

以下代码为本讲实算所用版本，Python 3 标准库，无第三方依赖。第 1 段给出几何基元。

片段 1：表面距离与线段-AABB 相交

import math

def point_to_aabb(p, box):
    """p: 参考点; box: ((x0,x1),(y0,y1),(z0,z1))。返回点到盒表面的欧氏距离。"""
    sq = 0.0
    for pi, (lo, hi) in zip(p, box):
        d = max(lo - pi, pi - hi, 0.0)   # 该轴落在区间内则贡献 0
        sq += d * d
    return math.sqrt(sq)

def nearest_surface_point(p, box):
    return tuple(min(max(pi, lo), hi) for pi, (lo, hi) in zip(p, box))

def corners(box):
    (x0, x1), (y0, y1), (z0, z1) = box
    return [(x, y, z) for x in (x0, x1) for y in (y0, y1) for z in (z0, z1)]

def segment_hits_aabb(a, b, box, eps=1e-9):
    """slab 法：线段 a-b 与轴对齐盒是否相交。"""
    t0, t1 = 0.0, 1.0
    for ai, bi, (lo, hi) in zip(a, b, box):
        d = bi - ai
        if abs(d) < eps:                 # 与该轴平行：检查起点是否在区间内
            if ai < lo or ai > hi:
                return False
            continue
        ta, tb = (lo - ai) / d, (hi - ai) / d
        if ta > tb:
            ta, tb = tb, ta
        t0, t1 = max(t0, ta), min(t1, tb)
        if t0 > t1:
            return False
    return True

解读：（1）point_to_aabb 的三轴独立计算是盒距离公式的直接实现，参考点在盒内时返回 0。（2）nearest_surface_point 用逐轴夹取求盒上离相机最近的点，它与八个角点共同构成可见性采样集。（3）segment_hits_aabb 是标准 slab 法：每轴求线段参数区间，所有轴区间求交非空即相交；平行轴单独处理，避免除零。eps 取 1e-9，用于吸收浮点噪声。

片段 2：oracle 可见性与成功谓词

def oracle_visible(camera, box, occluders=(), half_vfov_deg=31.7265, pitch_limit_deg=90.0):
    """oracle 可见性：自由偏航下，存在一个俯仰可达且无遮挡的表面采样点。"""
    samples = [nearest_surface_point(camera, box)] + corners(box)
    for q in samples:
        dy = q[1] - camera[1]
        r = math.hypot(q[0] - camera[0], q[2] - camera[2])
        pitch = math.degrees(math.atan2(dy, r)) if r > 1e-9 else math.copysign(90.0, dy)
        if abs(pitch) > pitch_limit_deg + half_vfov_deg:
            continue                     # 光轴可调范围加半视场都覆盖不到
        if not any(segment_hits_aabb(camera, q, ob) for ob in occluders):
            return True                  # 存在无遮挡视线，oracle 可完成取景
    return False

def objectnav_success(stop, camera, boxes, occluders=(), success_distance=1.0,
                      inclusive=False, half_vfov_deg=31.7265, pitch_limit_deg=90.0):
    """成功 = STOP 且存在实例同时满足接近度与 oracle 可见性。"""
    rows = []
    for box in boxes:
        d = point_to_aabb(stop, box)
        close = d <= success_distance if inclusive else d < success_distance
        vis = oracle_visible(camera, box, occluders, half_vfov_deg, pitch_limit_deg)
        rows.append({"distance": d, "proximity": close, "visible": vis,
                     "ok": close and vis})
    return any(r["ok"] for r in rows), rows

解读：（1）俯仰判据用 |pitch| ≤ P + VFOV/2，来自「光轴可调范围加半视场」的化简；P 取 90° 时该行恒不触发，只剩遮挡约束，与 oracle 档语义一致。（2）可见性对每个实例独立计算，与接近度在同一个循环里合并，从结构上排除了跨实例混用的写法。（3）inclusive 开关对应严格小于与含端点两种口径，默认严格小于，与官方实现一致。（4）返回 rows 便于把失败原因（距离不够或不可见）直接写进评测日志。

片段 3：边界样例驱动

P0, CAM = (0, 0.88, 0), (0, 0.88, 0)
WALL = ((0.15, 0.25), (0, 1.5), (-0.6, 0))

CASES = {
    "A exact 1m":   ([((1.0, 2.0), (0, 0.9), (-0.5, 0.5))], []),
    "B occluded":   ([((0.35, 2.0), (0, 0.6), (-0.5, -0.05))], [WALL]),
    "C both gap":   ([((0.35, 2.0), (0, 0.6), (-0.5, -0.05)),
                      ((1.02, 1.5), (0, 0.9), (0.3, 0.5))], [WALL]),
    "D any-inst":   ([((0.32, 0.5), (0, 0.9), (-0.2, -0.05)),
                      ((0.6, 0.8), (0, 0.9), (0.5, 0.7))], [WALL]),
}
for tag, (boxes, occ) in CASES.items():
    ok, rows = objectnav_success(P0, CAM, boxes, occ)
    detail = "; ".join("d=%.6f vis=%s" % (r["distance"], r["visible"]) for r in rows)
    print("%-14s -> success=%s | %s" % (tag, ok, detail))

常见坑

  • 只判距离不判可见性：停止点隔墙距目标 0.450999m，被判成功。根因是把「近」直接当成「到」。修复：四条件完整实现，接近与可见必须作用在同一实例上，并用样例 B/C 做回归。
  • 用物体中心距离代替表面距离：大床案例表面距离 0.344093m、中心距离 1.423517m，合格停止被判失败；误差随家具尺寸增大。根因是距离口径写错。修复：使用点到 AABB 表面距离，禁止在正式判定里使用中心距离。
  • 端点归属未定义：恰好 1.000000m 时，严格小于判失败、含端点判成功，同一批实验换个实现就变结论。根因是比较算子未显式配置，且 0.25m 动作步长与 0.09m 视点网格上端点并不罕见。修复：配置项加开关，比较前做 1e-6 量级的稳定化处理，单测覆盖 1.0 样例。
  • 多实例两条规则混用：把「任意实例成立」用于效率基线，或把「起点最近实例」用于成功判定。实算对照：l = 2.0m 时，就近停下（p = 2.4m）SPL = 0.833333，绕远去停（p = 15.5m）SPL = 0.129032，两者成功都为 1。修复：成功与效率拆成两个函数，分别测试。
  • 可见性采样与参考点错误：只投物体中心一条光线，中心被挡而边缘可见的实例被判不可见；或距离参考点与相机点混用，高位实例从 y = 0.88m 判 0.710211m、从地面点判 1.220656m，结论翻转。修复：最近表面点加八个角点采样，参考点与相机位姿在接口上分开命名并写入配置文档。

小结

  • 成功判据由四条件构成：STOP 意图、位置有效、到任一实例表面距离严格小于 1.0m、oracle 可见；后两个条件必须作用在同一实例上。
  • 接近度使用点到 AABB 的表面距离；中心距离系统性偏严，大床样例相差 1.08m。参考点高度的选择会让高位实例判定翻转（0.710211m 对 1.220656m）。
  • oracle 可见性在自由偏航下化简为「存在无遮挡视线到表面采样点」；俯仰上限与深度裁剪是仅剩的传感器模型参数，VFOV = 63.4530°，半值 31.7265°。
  • 多实例规则：成功取任意实例，效率基线取起点最近实例；l = 2.0m 时近停与远停的 SPL 分别为 0.833333 与 0.129032，成功率相同。
  • 边界口径五个样例覆盖：恰好 1.0m 的算子依赖、遮挡假成功、跨实例混用、任意实例成立、俯仰受限翻转；样板代码与输出可直接作为回归用例。
