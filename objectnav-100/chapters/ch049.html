第三篇 · 端到端与配方

第 049 讲｜PirlNav：BC→RL 两阶段

第 048 讲的人类演示把行为克隆（Behavior Cloning，BC）推到 MP3D val 的 35.4% / 10.2%，但分布偏移与效率上限仍在。PirlNav（论文题名拼作 PIRLNav，Ramrakhya 等 2023，Pretraining with Imitation and RL Finetuning for ObjectNav）把 BC 预训练与强化学习微调拼成两阶段配方：先用人类演示冷启动策略，再用稀疏成功奖励精修，在 HM3D ObjectNav 上取得 65.0% 成功率与 33.0% SPL（test-std 与 test-challenge 双 split）。本讲拆解两阶段微调的技巧、消融与配置表，并读演示来源与规模两组对照实验。

  • 主题：两阶段训练 / 模仿预训练 / RL 微调 / 稀疏奖励
  • 关键公式：JPPO(θ) = 𝔼[min(pt(θ) Ât, clip(pt(θ), 1 − ε, 1 + ε) Ât)]
  • 预计学时：80 分钟
  • 前置章节：第 048 讲（IL 与人类演示：Habitat-Web）

学习目标

  • 会推导：写出 BC 目标与拐点加权，说明模仿训练不评估动作后果的局限；解释 critic 未训练时优势估计有偏，直接联合微调为何破坏预训练策略。
  • 会设计：两阶段微调流程，包括 critic 学习阶段（冻结 actor、8M 步、动作采样）与交互学习阶段（解冻循环层、学习率过渡、300M 步），并说明哪些模块保持冻结。
  • 会算：消融表各行的成功率与 SPL 增量、相对变化，VPT 对照的差值，以及 65.0% 相对 60.0% 的绝对与相对改进。
  • 会判断：演示来源对照（人类演示、前沿探索、最短路径）在控制 BC 训练成功率后的泛化差异，以及规模曲线的收益递减点。
  • 会读：HM3D-Semantics v0.1 与 2022 挑战 split 的口径，val 与 test 差距的来源，以及 592 条失败标注给出的改进优先序。

背景与动机

第 048 讲留下两笔账。行为克隆的优点是样本效率高、行为可继承；缺点是训练时模仿动作、不评估动作的后果，策略一旦离开演示分布就开始累积误差。演示的成本核算也不轻：MP3D 批次 80k 条约 2,894 人时，HM3D 复采 77k 条约 2,378 人时。强化学习可以按需采集在线经验、按回报优化长期后果，但 Maksymets 等（2021）指出常用的 ObjectNav 奖励会惩罚探索，且从零训练在稀疏成功奖励下几乎无法启动。两难之间，PirlNav 的选择是把两者接起来：演示负责冷启动，RL 负责精修。

训练结构上有一个具体障碍。行为克隆只产出策略权重，不产出价值函数；而价值函数正是 actor-critic 方法计算优势的依赖项。用一个随机初始化的 critic 直接与 actor 联合微调，早期优势估计噪声极大，策略梯度会把预训练权重推离演示分布，性能出现明显下滑后才缓慢回升。论文的应对是给 RL 微调本身再分两小阶段：先冻结 actor 只学 critic，再用学习率调度逐步解冻 actor。这套调度把 20k 条演示的 BC 起点从 52.0% 提到 61.9%，最终 77k 条演示的配方在 test-std 与 test-challenge 上同时达到 65.0% / 33.0%，比 2022 年挑战赛的 Stretch 基线绝对高 5.0 个百分点。

本讲聚焦配方本身；演示来源之争的系统对照留给第 050 讲，规模与收益递减的细节留给第 051 讲，失败模式工具箱留给第 052 讲。三讲合起来构成本篇的 IL 路线主线。

核心原理

1. 任务与数据口径

评测落在 HM3D-Semantics v0.1：120 个场景、6 类目标（椅子、床、植物、马桶、电视、沙发），训练与验证分割沿用 Habitat ObjectNav 挑战赛 2022 的划分。动作空间为离散步：前进 0.25 m，左转、右转、抬头、低头各 30°，加停止；成功判据为 500 步内停止位置距目标实例不超过 1 m，且可经转向看到目标。演示数据来自第 048 讲的采集管线：HM3D 上 77k 条人类演示，约 2,378 人时。

训练分两个外层阶段：阶段 A 用行为克隆在人类演示上预训练策略；阶段 B 用 DD-PPO（分布式去中心化近端策略优化）在仿真中微调。阶段 B 内部再分两个小阶段：B1 只学 critic，B2 联合学习。下面先给出 BC 目标与架构，再展开微调机制。

外层阶段数据目标函数产物
A：BC 预训练77k 条人类演示（HM3D v0.1）交叉熵加拐点加权策略权重 πBC，无 critic

2. 行为克隆目标与架构

BC 在演示状态分布上做监督学习：

θ* = arg minθ Σi=1..N Σ(ot, at) ∈ τ(i) −wt · log πθBC(at | ot) wt 为拐点加权系数；动作发生变化的时刻取全局权重，其余为 1

策略架构为 CNN+RNN：RGB 经 ResNet50 编码，先在 Omnidata 数据集上做 DINO 自监督预训练，再随任务微调；GPS+Compass 与目标类别各经全连接层映射为 32 维向量；全部特征拼接后送入 2 层、2048 维的 GRU，输出动作分布。训练端叠加颜色抖动与随机平移防过拟合；分布式 BC 在 64 卡上并行回放演示，Adam 学习率 1e-3 线性衰减（PirlNav 附录 C.1，BC 训练规模为 5 亿步量级）。

演示来源对照在同一 12M 步经验预算下进行：240k 条最短路径（Shortest Path，SP）演示、70k 条前沿探索（Frontier Exploration，FE）演示、77k 条人类演示（Human Demonstrations，HD），BC 结果如下表。SP 演示由带真值地图的规划器生成，策略在训练时没有地图，存在模仿差距（imitation gap）；FE 演示只覆盖任务无关的探索；HD 同时覆盖任务导向的搜索与到达行为。

最短路径 SP240k6.4%5.0%

HD 比 FE 高 19.2 个百分点、比 SP 高 57.7 个百分点。三者统一按经验步数对齐，排除了「演示长短不同」的混淆；HD 的优势来自任务特定的探索行为，与数据量无关。

3. 为什么朴素微调会崩：未训练的 critic

PPO 用优势 Ât = Rt − V(st) 加权策略梯度。行为克隆数据全部由成功者产生，若在演示上直接学 critic，会得到系统性乐观的价值估计，无法刻画失败与探索的代价；因此 critic 必须在 RL 中从零学。若 actor 与 critic 同时从「BC 权重 + 随机 critic」开始，早期 V(st) 噪声大，Ât 的方差随之升高，策略更新方向随机，预训练策略被推离演示分布，表现为成功率急降再缓慢回升。

已有的 VPT 方案用一条 KL 约束把策略拉回冻结的 BC 策略，KL 系数从 0.2 起每次更新乘 0.995 衰减；它限制了漂移速度，却没有解决优势估计本身不可靠的问题。PirlNav 的判断是：先把 critic 学准，再放开 actor，比用一个约束压着走更有效。消融表给出对照：同样用 20k 条演示微调 300M 步，朴素联训把 BC 的 52.0% 提到 53.6%（+1.6 个百分点），仅加 critic 学习阶段提到 56.7%（+4.7），完整调度提到 61.9%（+9.9）；VPT 式 KL 方案为 59.7%，比完整调度低 2.2 个百分点。

4. 两阶段微调配方

阶段 B1（critic 学习）：冻结全部策略参数，用冻结策略采样动作，回放仿真轨迹，只更新 critic，直到价值损失进入平台；论文实测 8M 步足够，并把 critic 最后一层线性层初始化为接近零以稳定训练。注意动作来自采样，不用 argmax，保证 rollout 分布与后续 RL 阶段一致。

阶段 B2（交互学习）：解冻 actor 的循环层，CNN 与非视觉观察嵌入保持冻结；在 8M 至 12M 步之间，critic 学习率从 2.5 × 10−4 线性衰减到 1.5 × 10−5，actor 学习率从 0 线性预热到 1.5 × 10−5，此后两者保持 1.5 × 10−5 训练到 300M 步。actor 与 critic 共享的循环参数取两者中较小的学习率，调度里恒为 actor 的值。

ηcritic(t)：2.5 × 10−4，t < 8M；线性降至 1.5 × 10−5，8M ≤ t < 12M；其后恒定
ηactor(t)：0，t < 8M；线性升至 1.5 × 10−5，8M ≤ t < 12M；其后恒定 过渡窗口 4M 步，占 300M 步总预算的约 1.33%；critic 学习率峰值与终值相差约 16.7 倍

RL 超参与稀疏奖励：DD-PPO 用 16 个 worker、每个从 8 个环境并行收 64 帧，每次收集做 2 轮 PPO、每轮 2 个小批次；折扣因子 0.99，GAE 参数 0.95，优势不做归一化。奖励只有成功项，成功时给正奖励，其余为零。稀疏奖励的价值在于简单且不惩罚探索；它能工作的前提是 BC 预训练已经让策略偶发成功，使奖励信号可被采样到。论文在 BC 缺位时（BC = 0）观察到 RL 从零起不来，这与第 046 讲 RL 冷启动的结论一致。

6. 演示来源与规模：本讲的结论表

要判断「HD 的优势是否只是起点更高」，论文把三种来源的 BC 检查点选到训练集成功率同为约 48.0% 再微调，结果：HD 66.1%、FE 51.3%、SP 43.6%。控制起点后 HD 仍领先 FE 14.8 个百分点、领先 SP 22.5 个百分点，说明人类演示不仅让 BC 起点更好，还让 RL 微调更容易泛化；SP 微调后训练成功率高而验证低，属于过拟合，FE 则是训练与验证都低，属于欠拟合。对抗子集进一步加压：在 SP 擅长的 episode 子集上，HD 的 BC 成功率为 0，微调后到 57.2%，而 SP 从 5.2% 只到 34.8%；在 FE 擅长的子集上，HD 从 0 到 57.2%，FE 从 26.3% 到 43.0%。

规模方面：20k 条演示时 BC→RL 增量为 10.1 个百分点，77k 条时降到 6.3 个百分点，呈收益递减；35k 条微调后为 66.4%，达到 77k 条最好成绩 70.4% 的 94.3%，而演示量只有 45.45%。论文由此给出「用好规模与微调增益的权衡，可以用不到一半演示逼近」的实践建议。FE 演示扩到 70k 条后曲线饱和，提示继续自动生成同类轨迹收益有限。这两组的完整实验设计在第 050 与第 051 讲展开。

7. 失败模式与边界

论文对最好策略的 592 条验证失败做人工标注，主要类型与占比如下。前三项合计 68%，构成改进优先序。

边界条件同样要写清。第一，数据集限定为 HM3D-Semantics v0.1（120 场景、6 类），与 MP3D 的 21 类数字不可混谈；v0.2 扩容后的协议不同，跨版本比较需重新评测。第二，配方依赖仿真器出在线轨迹，BC 权重是稀疏奖励可学习的前提；没有演示预算或无法扩展场景集合时，这套配方的适用性下降。第三，300M 步 RL 与 64 卡 BC 的算力门槛不低，复现时先固定随机种子并复算消融，再比较方法创新。第四，失败标注显示 27% 的失败来自数据标注本身，评测与改进实验应把这部分单列，避免把数据噪声计入算法差距。

实现思路与设计

实现重点是把两阶段与内外层关系映射到训练循环：外层阶段 A 是监督学习循环，外层阶段 B 是在线 RL 循环，B 内部用步数阈值切换 critic 学习与交互学习。全部关键行为由步数驱动，避免用损失阈值触发状态切换造成不可复现阶段。

资源账量级：BC 在 64 卡上以 5 亿步量级训练，RL 微调 300M 步、16 卡 DD-PPO；相对第 017 讲 PointNav 的 2.5B 帧规模，本配方的在线步数少一个数量级，算力重心从环境交互转移到演示数据与监督训练。这也解释了为什么演示质量与数量对最终指标如此关键：公式的另一半（微调）已经相对便宜。

三段代码覆盖调度、critic 学习与策略更新。全部按论文的超参约定书写，输出与消融表的机制解释对应。

片段 1：两阶段学习率调度

def learning_rates(step, freeze_until=8_000_000, warmup_end=12_000_000,
                   critic_start=2.5e-4, critic_end=1.5e-5, actor_end=1.5e-5):
    """返回 (actor_lr, critic_lr)。8M 前 actor 冻结，8M 至 12M 线性过渡。"""
    if step < freeze_until:
        return 0.0, critic_start                 # B1：critic 单飞
    if step < warmup_end:
        frac = (step - freeze_until) / (warmup_end - freeze_until)
        critic_lr = critic_start + (critic_end - critic_start) * frac
        return actor_end * frac, critic_lr        # B2 过渡窗：两端连续
    return actor_end, critic_end                  # B2 稳态

for step in (0, 4_000_000, 8_000_000, 10_000_000, 12_000_000, 300_000_000):
    print(step, learning_rates(step))
# 0           (0.0, 0.00025)
# 8000000     (0.0, 0.00025)      过渡窗左端与 B1 连续
# 10000000    (7.5e-06, 0.0001325)
# 12000000    (1.5e-05, 1.5e-05)  过渡窗右端两率汇合
# 300000000   (1.5e-05, 1.5e-05)

解读：（1）调度只用步数判断，训练中断后按步数恢复即可，不依赖损失值，保证可复现。（2）过渡窗两端连续：8M 处 actor 从 0 启动且 critic 保持峰值，12M 处两率相等，避免学习率跳变带来的更新尖峰。（3）共享的循环参数在实现中用 min(actor_lr, critic_lr)，在 8M 至 12M 窗口内恒取 actor 的预热值，12M 之后两者相同，与论文口径一致。

片段 2：critic 学习阶段（动作采样是关键）

import torch
import torch.nn.functional as F

def collect_frozen_rollouts(policy, envs, steps=64 * 8):
    """用冻结的 BC 策略采样轨迹；刻意用采样而不用 argmax。"""
    policy.eval()
    obs, done = envs.reset(), torch.zeros(len(envs), dtype=torch.bool)
    buffer = []
    for _ in range(steps):
        with torch.no_grad():
            dist = policy.distribution(obs)
            action = dist.sample()               # 采样保证与后续 RL 分布一致
            logp = dist.log_prob(action)
        next_obs, reward, done, info = envs.step(action)
        buffer.append({"obs": obs, "action": action, "logp": logp,
                       "reward": reward, "done": done, "value": policy.value(obs)})
        obs = next_obs
    return buffer

def critic_phase_update(critic, buffer, gamma=0.99, gae_lambda=0.95):
    """B1：actor 冻结，仅回归 GAE 回报；重复直到价值损失平台。"""
    returns, adv = gae(buffer, gamma, gae_lambda)
    values = critic(batch_obs(buffer))
    loss = F.mse_loss(values, returns.detach())

解读：（1）用 argmax 动作会让 rollout 落在演示分布的峰值上，critic 学到的价值与 RL 采样时的真实分布不一致，是常见复现错误。（2）critic 最后一层初始化为接近零，早期价值输出接近 0，优势近似等于回报本身，避免随机大值主导更新。（3）「价值损失进入平台」在实现里落成固定 8M 步，便于与论文对齐；自研项目可以改成滑动窗口的早停，但要在报告中写明规则。

片段 3：PPO 裁剪目标与稀疏奖励

def sparse_reward(success):
    """稀疏成功奖励：仅成功给 1；论文不做密集塑形。"""
    if success:
        return 1.0
    return 0.0

def gae(buffer, gamma=0.99, gae_lambda=0.95):
    """广义优势估计；论文明确不做优势归一化。"""
    adv, last = torch.zeros(len(buffer)), 0.0
    for t in reversed(range(len(buffer))):
        nonterminal = 1.0 - float(buffer[t]["done"])
        next_value = buffer[t + 1]["value"] if t + 1 < len(buffer) else 0.0
        delta = buffer[t]["reward"] + gamma * next_value * nonterminal - buffer[t]["value"]
        last = delta + gamma * gae_lambda * nonterminal * last
        adv[t] = last
    values = torch.tensor([b["value"] for b in buffer])
    return values + adv, adv

def ppo_loss(policy, critic, batch, clip=0.2):
    """B2：actor 与 critic 联合更新；共享循环层用较小学习率。"""
    logp = policy.log_prob(batch["obs"], batch["action"])
    ratio = torch.exp(logp - batch["logp"])
    adv = batch["adv"]
    pg = torch.min(ratio * adv,
                   torch.clamp(ratio, 1.0 - clip, 1.0 + clip) * adv)
    value = critic(batch["obs"])
    return -pg.mean() + 0.5 * F.mse_loss(value, batch["returns"])

# 优化器：actor 组与 critic 组分开；共享的 GRU 参数放入 actor 组，
# 这样在 8M 至 12M 窗口内共享层自动跟随较小的 actor 学习率。

解读：（1）稀疏奖励的关键在回报传播：γ = 0.99 时 100 步外的成功信号衰减到约 0.366，500 步处只剩约 0.007；换 γ 需要重新核算视野与价值传播，论文固定采用 0.99。（2）GAE 循环必须从后向前，且用 nonterminal 截断跨 episode 的自举；缓冲区按 episode 边界切分，避免把失败尾部的价值泄漏到下一回合。（3）裁剪系数 0.2 限制单次更新幅度，与 BC 权重保护配套；优势不归一化，保持回报的自然尺度。

常见误区

  • critic 与 actor 同时从零联合训练：症状是微调初期成功率骤降，靠后续训练缓慢回填。根因是优势估计噪声大，策略更新破坏 BC 权重。修复：先跑 critic 学习阶段（8M 步），再按 8M 至 12M 窗口解冻 actor；消融对照为朴素联训 53.6% 对完整调度 61.9%。
  • critic 阶段用 argmax 动作采样：症状是 critic 训练损失很低，但联合训练后价值误差反弹。根因是 rollout 分布与采样策略不一致。修复：用 dist.sample() 采样动作，保持与 RL 阶段同一探索分布。
  • 全网络解冻或全网络冻结：症状是微调不稳定或学不动。根因是没有区分表征与策略的适应需求。修复：B2 只解冻循环层，CNN 与非视觉嵌入保持冻结；论文报告这一设置在稳定性上更优。
  • 学习率调度窗口与总步数不匹配：症状是过渡被压缩或拖长，微调收益低于预期。根因是照搬 8M / 12M 两个常数而总预算不同。修复：过渡窗按总预算比例缩放（论文中 4M / 300M ≈ 1.33%），共享参数取 actor 与 critic 的较小学习率。
  • 稀疏奖励从零训练：症状是所有轨迹回报为零，价值函数退化为常数。根因是缺少可采样的成功样本。修复：保留 BC 预训练作为冷启动；论文的 BC = 0 对照显示 RL 从零无法启动，这条边界在复现时必须先验证。
  • 跨版本混谈数字：症状是用 HM3D v0.1 的 65.0% 与 v0.2 榜单或 MP3D 的 24.5% 直接比较。根因是数据集、类别数与 split 不同。修复：每张表标注版本、类别数与 split；v0.1 的 120 场景 6 类与 v0.2 的扩容列表各自成表。

小结

  • PirlNav 的两阶段配方：BC 在 77k 条人类演示上预训练（ResNet50 + 2 层 2048 维 GRU），RL 用 DD-PPO 与稀疏成功奖励微调 300M 步；HM3D-Semantics v0.1 上取得 test-std 与 test-challenge 双 65.0% / 33.0%，val 70.4% / 34.1%。
  • 微调本身分两小阶段：B1 冻结 actor 学 critic（8M 步，动作采样，末层接近零）；B2 解冻循环层，8M 至 12M 窗口内 critic 学习率 2.5 × 10−4 降至 1.5 × 10−5、actor 从 0 预热到 1.5 × 10−5，共享参数取较小者。
  • 消融（20k 演示）：朴素联训 +1.6 点，critic 学习 +4.7 点，加 critic 衰减 +7.4 点，加 actor 预热 +6.2 点，完整调度 +9.9 点（SPL +7.3）；VPT 式 KL 对照低 2.2 点。
  • 演示来源：同为约 48% 的 BC 训练成功率下微调后 HD 66.1%、FE 51.3%、SP 43.6%；对抗子集上 HD 从 0% 出发仍反超 SP 与 FE 的起点策略，支持任务特定探索行为的关键作用。
  • 规模规律：20k 演示增益 10.1 点，77k 降到 6.3 点；35k 达到最好成绩的 94.3%，约为一半演示量；FE 演示 70k 后饱和。失败标注中前三项（缺失标注 27%、跨楼层 21%、识别失败 20%）合计 68%。
