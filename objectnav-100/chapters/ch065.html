第四篇 · 开放词汇与大模型

第 065 讲｜LLM frontier 范式深化

第 063 与 064 讲拆了 ZSON（Majumdar 等 2022）的嵌入式目标接口：语言知识通过 500M 步 ImageNav 训练进入策略。本讲转向 2023 年成型的另一条路线，把大语言模型（Large Language Model, LLM）当作前沿排序器：语义地图给出候选前沿与周边物体清单，语言模型用常识判断哪个前沿更可能通向目标类别。主来源为 L3MVN（Yu 等 2023，IROS 2023，视觉目标导航），并逐条核实 2023-01 至 2024-10 的谱系条目（ESC、NavGPT、Co-NavGPT、VLFM、VoroNav、SG-Nav）。本讲给出三条演进轴（排序信号、描述粒度、空间结构）、主表与消融的实算差值、熵过滤与融合带宽的实现细节，以及协议口径的边界。

  • 主题：LLM 前沿排序 / 常识注入 / 谱系时间线 / 协议边界
  • 关键公式：SCU(a) = U(a) − λCUC(a)；H(oi) = − Σj p(tj|oi) log p(tj|oi)；SLLM(fi,tj) = log p(W(fi,tj))
  • 预计学时：75 分钟
  • 前置章节：第 064 讲（ZSON II：跨数据集零样本）

学习目标

  • 会说清 LLM 前沿排序范式的问题结构：语义建图、前沿提取、语言打分、局部规划四段接口，以及各段的输入输出契约。
  • 会算：L3MVN 主表相对 SemExp、随机前沿、自身零样本版本的绝对增益与相对变化，并能联合读成功率（SR）、成功加权路径长度（SPL）与终止距离（DTG）。
  • 会实现熵过滤与查询构造：由共现计数估计条件分布、计算熵、取最低熵 top-15 对象生成查询串。
  • 会对比两种语言打分范式的成本与先验需求：零样本掩码语言模型打分、前馈嵌入加映射头，并说明融合带宽 B 的取值依据。
  • 会按谱系时间线判断 2023–2024 各系统的差异点，并设计横评时的控制变量。

背景与动机

第 064 讲的结论是：嵌入式接口能让零样本 ObjectNav 接近有监督对照（HM3D 成功率 25.5%，相对 OVRL 低 7.3 个百分点），代价是 500M 步规模的训练与目标接口的重学。2023 年初出现互补思路：室内物体共现本身就是强常识（马桶与浴缸同在浴室、电视与沙发同在客厅），语言模型在预训练语料中已经吸收这类常识，可以直接回答“哪个前沿更可能通向马桶”。这条路线的优势有三条：不训练策略也能工作、常识可迁移到新类别、中间产物是可读的文字。代价也很清楚：视觉观测转文字时的信息损失、语言分数的尺度不稳定，以及对候选构造质量的强依赖。L3MVN 是这条路线早期的完整系统：语义地图加前沿候选、语言打分加快速行进法（Fast Marching Method, FMM）局部规划，并在同一框架里给出零样本与前馈两种用法。

本讲回答三个问题。第一，这类方法的收益量级是多少，与语义探索基线 SemExp（Chaplot 等 2020）相比在哪些指标上领先、哪些指标上落后。第二，语言常识以什么接口进入导航，零样本打分与前馈映射头如何分工，超参依据是什么。第三，2023–2024 这条谱系如何演化，后续系统各自改动了哪一层。理解这三点，才能在读 VLFM（第 067 讲）与 SG-Nav（第 069 讲）时准确定位它们的贡献。

核心原理

1. 地图接口与前沿候选

L3MVN 的输入是 RGB-D 图像、里程计与目标类别，动作空间为六动作：前进 0.25 m、左转与右转 30°、抬头与低头 30°、停止；episode 上限 500 步，观测分辨率 480×640，语义分割使用微调后的 RedNet（Jiang 等 2018）。语义地图是一个 K×M×M 的张量，K = Cn + 2，其中两个通道记录障碍与已探索区域，其余 Cn 个通道按类别记录语义，深度点云对齐语义掩码后投影到俯视二维栅格。地图每 episode 清零，智能体置于中心。

前沿从已探索区域与障碍区域导出：先取已探索区域的最大轮廓作为已探索边缘，再对障碍区域做膨胀，二者差集即前沿带；用连通聚类把前沿格聚成链，剔除过小的簇，链中心作为候选前沿点 f ∈ F。候选质量由代价效用分数排序：

SCU(a) = U(a) − λCU C(a) U(a) 为效用项，C(a) 为代价项，λCU 平衡两者，取自 Juliá 等 2012 的路径规划比较；Yamauchi 1997 的前沿法给出探索框架。

每个前沿再取一个搜索窗口，把窗口内的语义物体收集为该前沿的“内容清单” o1, …, ok。清单是语言打分的全部依据，因此窗口半径与分割质量直接决定后续排序的信息量。

2. 两种语言打分范式

L3MVN 给出两种把语言模型接入前沿选择的方式（Yu 等 2023，III-D 节）。零样本范式为每个前沿 fi 与每个目标类别 tj 构造一句查询，形如 “A frontier area containing o1, o2, …, ok, tj.”，用掩码语言模型（论文用 RoBERTa-large）计算句子的对数概率作为分数：

SLLM(fi, tj) = log p(W(fi, tj)) W 为查询串，p 为掩码语言模型给出的句子概率；前沿得分取各前沿在目标 tj 上的最大值。

前馈范式为每个前沿构造一句与目标无关的描述 “This frontier contains o1, …, ok.”，把句子嵌入送入一个三层网络，输出 |LT| 维 logits，取目标类别对应分量作为分数：

SFF(fi, tj) = [ fθ(Emb(W(fi))) ]tj Emb 为微调后的 RoBERTa-large 句子嵌入，fθ 为三层映射头；监督来自 HM3D 房间-物体共现的启发式标签。

两者分工的判据是成本与先验：零样本范式不需要任何标注，但每步需要 |F| × |LT| 次前向；前馈范式需要离线构造共现监督并训练映射头，在线只需 |F| 次嵌入加一次小网络前向，且论文报告在大场景中相关性估计更准（HM3D 成功率 54.2% 对 50.4%）。

3. 熵过滤：只保留有判别力的物体

门、窗之类物体在所有房间都出现，对判断“这个方法通向哪里”几乎没有信息量。论文沿用 Chen 等 2022 的做法，用物体到目标的共现条件分布刻画信息量。设 oi 为观测物体，tj 为目标类别，LO 与 LT 分别为物体与目标类别集合，p(tj|oi) 由公开数据集（HM3D，1,000 个场景）的标注共现统计得到：

H(oi) = − Σtj ∈ LT p(tj|oi) log p(tj|oi) 分布越均匀熵越大，信息量越低；取熵最低的 15 个对象参与查询串构造。

实算示例（自然对数口径，六类目标 chair/couch/plant/bed/toilet/tv）：若马桶的共现分布为 (0.05, 0.05, 0.05, 0.10, 0.70, 0.05)，熵为 1.079；若门的分布接近均匀 (0.20, 0.15, 0.15, 0.20, 0.15, 0.15)，熵为 1.782，接近均匀分布上界 ln 6 ≈ 1.792。马桶的低熵说明它能强指向目标类别，门的熵接近上界说明它几乎不携带指向信息，因此被过滤。注意共现统计来自离线标注数据集，属于预先准备的先验，换数据集需要重算。

4. 融合规则与带宽 B

室内语义稀疏，可能出现“所有前沿附近都没有有信息量的物体”或“前沿清单里混入无关物体”的情况。论文把语言分数归一化到 [0, 1]，并把 SCU 也归一化到同一区间，设定带宽 B = [0.15, 0.3]：

f* = arg maxfi { SLLM(fi) ，当 max SLLM > 0.3； 语言分数与代价效用融合，当 max SLLM ∈ [0.15, 0.3]； SCU(fi)，当 max SLLM < 0.15 } 论文以带宽形式描述三种模式：语言分高时语言主导，中等时与代价效用融合，低时退回纯探索；带宽内分支的具体权重属实现细节，本讲的数值示例取等权平均。

实算示例：方案 (SLLM, SCU) 为 (0.62, 0.10) 时语言主导，输出 0.62；(0.22, 0.90) 落在带宽内，取均值输出 0.56；(0.08, 0.77) 低于下界，退回纯探索，输出 0.77。极端取值的后果值得记住：B = [0, 0] 使上下界重合，融合分支消失，只要归一化语言分稍大于 0 就完全交给语言排序，探索分数不再参与，语言信号弱时失去几何兜底；B = [0, 1] 使全部取值落入融合分支，语言信号再弱也会以等权平均混入排序，等于对语言噪声做平滑。

8. 边界与失效条件

引用与复现前要过五道检查。第一，停止口径：L3MVN 论文的任务定义写明“停止时距目标小于 0.1 m 记为成功”，与 Habitat 挑战常用的 1.0 m 加可见性口径不同，跨表比较成功率前必须对齐。第二，先验来源：熵过滤使用的条件分布来自 HM3D 的 1,000 个场景标注，属于离线监督统计，论文的“零样本”指不训练导航策略，不指零数据。第三，语言分数尺度：log p(W) 随查询串长度与词汇变化，跨模板不可比；论文在同一帧内用同一模板，跨步长变化时需要重新归一化或改用逐 token 平均。第四，场景规模：Gibson 仅 5 个验证场景、HM3D 20 个验证场景，成功率的置信区间较宽，方法间 1 到 2 个百分点的差异不适合下强结论。第五，前沿抖动：建图噪声会使前沿簇分裂或合并，逐帧 argmax 可能在前沿间来回切换；论文未显式跟踪已访问前沿，长 episode 中需要额外的目标锁定或滞后机制。

实现思路与设计

把上述机制工程化，数据流可以拆成六段：RGB-D 观测进入语义建图，地图导出前沿候选，候选窗口收集物体清单，熵过滤裁剪清单，语言模型打分，融合后交给局部规划执行。每段的接口稳定，替换其中一段即可得到谱系里的其他系统，例如把第五段换成视觉语言价值图就是 VLFM 的形态。

与 ZSON 的差异点

ZSON 把语言知识压在策略内部的目标嵌入里，语言的作用点在“策略输入”；L3MVN 把语言知识用作探索方向的排序器，语言的作用点在“候选评估”。前者一次训练换来统一接口，后者零训练换来可读中间产物与可替换组件。第 067 讲的 VLFM 会保留“排序器”的位置，把打分器从文本语言模型换成视觉语言模型，从而绕开物体清单的文本化瓶颈。

import numpy as np

def extract_frontiers(explored, obstacle, min_cells=6):
    """explored/obstacle 为同尺寸布尔栅格；返回前沿链中心候选。"""
    # 障碍膨胀一圈，避免前沿贴墙
    ob = np.zeros_like(obstacle)
    for dy in (-1, 0, 1):
        for dx in (-1, 0, 1):
            ob |= np.roll(np.roll(obstacle, dy, 0), dx, 1)
    # 前沿定义：与未探索区域相邻的已探索格
    unknown = ~explored
    border = np.zeros_like(explored)
    for dy in (-1, 0, 1):
        for dx in (-1, 0, 1):
            border |= explored & np.roll(np.roll(unknown, dy, 0), dx, 1)
    frontier = border & ~ob
    # 简单连通聚类（BFS），链中心作为候选点
    seen = np.zeros_like(frontier, dtype=bool)
    centers = []
    H, W = frontier.shape
    for y in range(H):
        for x in range(W):
            if not frontier[y, x] or seen[y, x]:
                continue
            stack, cells = [(y, x)], []
            seen[y, x] = True
            while stack:
                cy, cx = stack.pop()
                cells.append((cy, cx))
                for dy in (-1, 0, 1):
                    for dx in (-1, 0, 1):
                        ny, nx = cy + dy, cx + dx
                        if 0 <= ny < H and 0 <= nx < W \
                                and frontier[ny, nx] and not seen[ny, nx]:
                            seen[ny, nx] = True
                            stack.append((ny, nx))
            if len(cells) >= min_cells:
                ys = [c[0] for c in cells]
                xs = [c[1] for c in cells]
                centers.append((int(np.mean(ys)), int(np.mean(xs))))
    return centers

解读：（1）前沿的本质是“已探索格与未探索格相邻”的边界，障碍膨胀用于剔除贴墙条带，避免候选点落在不可达位置。（2）示例用 8 邻域滚动实现边界检测，工程实现通常换用形态学运算与并查集，语义一致。（3）min_cells 是候选质量的第一道闸门；取值过小会引入抖动前沿，过大则漏掉小房间入口，复现时建议结合栅格分辨率做实验。

片段 2：熵过滤与查询构造

import math
from collections import Counter

def object_entropy(cooccur_counts):
    """cooccur_counts: {object: Counter({target: count})}，返回各对象熵。"""
    ent = {}
    for obj, cnts in cooccur_counts.items():
        total = sum(cnts.values())
        if total == 0:
            continue
        h = 0.0
        for t, c in cnts.items():
            p = c / total
            h -= p * math.log(p)          # 自然对数口径
        ent[obj] = h
    return ent

def query_for(objs, target, ent, top_k=15):
    """单个前沿的查询串：按熵升序取 top_k，词表外的物体剔除。"""
    known = [o for o in objs if o in ent]
    known.sort(key=lambda o: ent[o])
    kept = known[:top_k]
    return "A frontier area containing " + ", ".join(kept + [target]) + "."

def build_queries(frontier_objects, target, ent, top_k=15):
    """对多个前沿批量构造查询串：过滤后套用固定模板。"""
    out = {}
    for fid, objs in frontier_objects.items():
        known = [o for o in objs if o in ent]
        known.sort(key=lambda o: ent[o])
        out[fid] = query_for(known, target, ent, top_k)
    return out

解读：（1）熵按条件分布 p(t|o) 计算，分布越均匀熵越大，越接近 ln|LT| 上界；示例中马桶 1.079、门 1.782、均匀六类上界 1.792，量级关系与过滤直觉一致。（2）top_k=15 是论文取值；查询串长度随 k 增长，掩码语言模型的打分稳定性会下降，二者需要一起调。（3）真实实现要处理类别词表未覆盖的物体，剔除或回退到上位词，避免查询串里出现未知符号导致分数噪声。片段中 build_queries 仅演示过滤顺序，输入输出类型应与 query_for 统一。

片段 3：前沿打分与带宽融合

import torch

@torch.no_grad()
def score_frontiers_zero_shot(model, tokenizer, frontiers, targets):
    """零样本：逐前沿、逐目标计算 log p(W)。"""
    scores = {}
    for fid, objs in frontiers.items():
        row = []
        for tgt in targets:
            sent = query_for(objs, tgt, ENT)      # 见片段 2
            ids = tokenizer(sent, return_tensors="pt").input_ids
            logp = model(ids, labels=ids).loss * -ids.shape[1]
            row.append(float(logp))               # 句长归一化前的对数概率
        scores[fid] = torch.tensor(row)
    return scores

def score_frontiers_feedforward(head, embed, frontiers):
    """前馈：每前沿一句描述，映射头输出目标维 logits。"""
    scores = {}
    for fid, objs in frontiers.items():
        desc = "This frontier contains " + ", ".join(objs) + "."
        with torch.no_grad():
            scores[fid] = head(embed(desc)).squeeze(0)
    return scores

def fuse_and_pick(s_llm, s_cu, target_idx, band=(0.15, 0.3)):
    """归一化后按带宽融合；返回选中的前沿 id。"""
    def norm(d):
        v = torch.tensor([d[k][target_idx] for k in d])
        return (v - v.min()) / (v.max() - v.min() + 1e-8)
    llm, cu = norm(s_llm), norm(s_cu)
    lo, hi = band
    if float(llm.max()) > hi:
        combined = llm
    elif float(llm.max()) < lo:
        combined = cu
    else:
        combined = 0.5 * (llm + cu)
    ids = list(s_llm.keys())
    return ids[int(combined.argmax())]

解读：（1）零样本分数是句子对数概率，句长不同会带来尺度差异；示例用 loss 反推总量，真实复现建议同时记录逐 token 平均分并做一致性检查。（2）前馈分支把“前沿描述”与“目标选择”解耦，描述可以离线缓存，目标类别切换只需重跑小网络。（3）融合前必须做同一帧内的归一化，否则两个分数不同量纲；带宽 B 的两个边界是超参，论文未给扫描曲线，属于复现时优先做敏感性分析的对象。

常见坑

  • 停止口径混用：症状是复现成功率与论文对不上。根因是 L3MVN 任务定义用 0.1 m 成功距离，而 Habitat 挑战常用 1.0 m 加可见性。修复：评测前固定口径并写入实验表；跨表比较时先对齐再排序。
  • 单看 DTG 下反向结论：症状是看到 HM3D 上 L3MVN 的 DTG 3.934 高于 SemExp 的 2.943，得出其探索更差。根因是均值被失败轨迹的远端终止抬高，而成功率同时更高。修复：SR、SPL、DTG 联合读，并单列失败轨迹的终止距离分布。
  • 把共现先验当作在线统计：症状是换到新数据集后熵过滤失效。根因是 p(t|o) 来自 HM3D 的 1,000 场景标注，属于离线先验。修复：先验来源写进实验记录，跨数据集时重新统计，或改为类别无关的启发式过滤。
  • 语言分数跨句长比较：症状是前沿排序在 episode 后段变得混乱。根因是 log p(W) 随句长下降，不同前沿的查询串物体数不同。修复：同帧内固定模板与截断长度，跨帧做归一化，并记录逐 token 平均分备查。
  • 前沿抖动导致目标切换：症状是智能体在两个前沿之间来回改选，路径变长。根因是建图更新使前沿簇逐帧变化，而选择器只用当前帧 argmax。修复：给候选加最小面积与生命期阈值；对长期目标做滞后或锁定，例如连续 k 帧分数领先才允许切换。
  • 把“零样本”读成“零数据”：症状是向他人介绍时夸大方法边界。根因是该范式不训练导航策略，但使用了预训练模型、离线共现统计与真值语义监督的消融对照。修复：在实验表里逐项列出每类数据的使用情况。

小结

  • 范式结构：语义地图给出前沿候选，物体清单经熵过滤后交给语言模型打分，融合后由 FMM 执行；L3MVN 同时提供零样本打分与前馈映射头两种用法，后者在 HM3D 上把成功率从 50.4% 提到 54.2%。
  • 主表实算：前馈版 Gibson 0.769 / 0.388 / 1.008，相对 SemExp 成功率 +11.7 个百分点、DTG 降低 0.512 m；HM3D 0.542 / 0.255 / 3.934，成功率 +16.3 个百分点、DTG 升高 0.991 m，必须联合读指标。
  • 消融实算：去掉 LLM 降 2.4 个百分点，最近前沿替代降 5.2 个百分点，真值分割提升 12.2 个百分点；感知是主瓶颈，语言模块的价值在探索排序。
  • 熵过滤：条件分布熵把门这类高熵物体剔除，只保留最低熵 15 个对象；共现统计来自离线标注，属于先验数据。
  • 谱系时间线：2023-01 至 2024-10 共 619 天，密集期集中在 2023-10 到 2024-01；演化沿排序信号、描述粒度、空间结构三条轴推进。
