第五篇 · 真机、Sim2Real 与系统集成

第 083 讲｜现实化改造：去 GPS、噪声与禁滑动

2020 年的 Habitat 挑战把重点放在「仿真能否预测真机」上，并对 PointNav 赛道做了四项现实化改造：移除 GPS+Compass、注入致动与传感噪声、关闭碰撞滑动、按 LoCoBot 重设本体与相机。改造的直接证据来自（Kadian 等，2020，Sim2Real Predictivity，arXiv:1912.06321v2）：在 CVPR19 口径下，同一批导航模型在仿真与真机之间的成功率相关系数只有 0.18，大量模型排序发生反转；关闭滑动并把噪声倍率调到更低档后，成功率系数升到 0.844，路径效率系数升到 0.875，排序反转次数从 9 次降到 5 次，约为 13.8%。本讲逐项拆解改造的动机、实现与后果，并明确 ObjectNav 赛道的口径边界：2020 年的 ObjectNav 保留无噪声 GPS+Compass，也不注入传感噪声（Habitat Challenge 2020 官方页面）。

  • 主题：真实感改造 / 在线定位 / 碰撞滑动 / 噪声注入 / 评测协议分档
  • 关键公式：SPL = (1/N)Σ Si · li/max(pi, li)；gstart = R0⊤(gw − p0)；SoftSPL 的软成功项 max(0, 1 − dT/d0)
  • 预计学时：80 分钟
  • 前置章节：第 082 讲（RoboTHOR：配对环境与远程真机）

学习目标

  • 理解：复述 2020 PointNav 的四项现实化改造及其动机，说明移除 GPS+Compass 后目标表示与自定位要求发生了什么变化。
  • 会推导：写出「滑动」与「停止」两种碰撞处理下的单步位移差，并说明该差异如何进入路径长度 p 与最短路径基线 l。
  • 会算：复算 2019 与 2020 榜单的差距、SRCC 的提升幅度、CODA 实验的样本量与真机耗时。
  • 会设计：为「定位、噪声、滑动」三类因素设计控制变量的消融实验，给出观察量、判据与预算。

背景与动机

第 081 讲给出 Sim2Real 落差的定义与历史证据，第 082 讲讨论 RoboTHOR 的配对场景与远程真机平台。两讲共同留下一个问题：仿真里的排名在真机上还成立吗？（Kadian 等，2020，Sim2Real Predictivity，arXiv:1912.06321v2）在受控实验里给出否定答案：以 CVPR19 的仿真设置评测九个模型，仿真成功率几乎都接近 1，真机成功率却差异巨大，相关系数只有 0.18。论文把主要原因指向两类可修复的仿真缺陷：智能体学会利用碰撞后的「贴墙滑动」抄近路，以及致动过程完全确定性。

2020 年挑战沿着这条证据链做了四项改造，本讲的任务是把每一项拆到可复现的粒度：它在观测空间、动力学或评测协议里改了什么，代价是什么，对训练与评测流程提出哪些新要求。第 084 讲会进入噪声模型与 LoCoBot 本体参数的具体数值，第 085 讲则考察在现实化改造之后，一个模块化方案如何迁移到真机。

核心原理

1. 四项改造与证据链

2020 挑战页面对 PointNav 列出四项改动，全部服务于同一个目标：提高仿真对真机表现的可预测性（sim2real predictivity）。四项改动如下。第一，移除 GPS+Compass 传感器：智能体只能依靠自我中心 RGB-D 观测导航，必须在线完成基于 RGB-D 的定位。第二，注入致动与传感噪声：致动噪声模型由 PyRobot 团队对 LoCoBot 机器人做动作基准测试得到，另有 RGB 与深度传感器噪声。第三，关闭碰撞滑动：碰撞后的状态更新只保留合法位移，消除贴墙滑行的捷径。第四，按 LoCoBot 修改本体与相机：包括机器人尺寸、相机分辨率、高度与朝向等。

证据一侧的关键数字是相关系数。论文定义仿真与真机相关系数（Sim-vs-Real Correlation Coefficient, SRCC），即同一批模型在仿真指标与真机指标之间的样本皮尔逊相关系数。CVPR19 设置下滑动开启、噪声关闭，SRCCSucc = 0.18、SRCCSPL = 0.603，按 SPL 排名出现 9 次相对次序反转。对仿真参数做网格搜索后，最优组合为滑动关闭、致动噪声倍率 0.0，SRCCSucc 升到 0.844（提升 0.664），SRCCSPL 升到 0.875（提升 0.272），反转降到 5 次，约为 13.8%。这组数字说明两件事：像素级保真度对预测性的贡献有限，动力学与碰撞响应的影响更大；仿真参数可以被当作优化目标来标定。需要注意，该结论来自论文受控实验环境 CODA（6.5 m × 10 m），不能直接当作全部室内场景的普适定律。

2. 去 GPS+Compass：目标表示与在线定位

点目标导航（PointGoal Navigation, PointNav）的目标位置固定在场景坐标系。设起始位姿为 (p0, R0)，目标为 gw，则「相对起点」的目标向量为：

gstart = R0⊤(gw − p0)

2020 挑战的本地评测配置中，任务传感器只有普通目标传感器（start 坐标系下的固定向量），不再包含 GPS 与 Compass 传感器；官方页面进一步说明，该配置下智能体只能读取自我中心 RGB-D 观测，必须靠在线定位估计自身相对起点的位移与朝向，才能把 gstart 转换成当前可用的导航方向。2019 年口径下，目标在智能体坐标系中的向量随运动持续更新，等效于随时提供理想定位与朝向估计，因此策略无需建模自身运动误差。

在 2020 口径下，若位姿估计 (p̂t, R̂t) 与真值存在误差，目标方向按下式合成：

ωt = R̂t⊤(R0 gstart − (p̂t − p0))

朝向误差直接表现为目标方位角误差（量级为 1 倍朝向误差），位移误差则通过几何投影进入方位与距离。两者的误差随轨迹累积，因此第 081 讲讨论的误差累积在这里有了明确的接口：没有在线定位，回合早期的目标读数尚可，回合后期则完全不可用。论文在真实平台上用激光雷达加 Hector SLAM 把定位误差压到约 7 cm，而轮式里程计加惯性测量单元、经扩展卡尔曼滤波组合后的误差约 40 cm；前者约为 20 cm 成功判定半径的 35%，后者为 200%，这解释了为什么 2020 口径把「RGBD 在线定位」列为独立能力要求。

3. 禁滑动：碰撞响应、抄近路与指标漏洞

2019 口径下，智能体撞到障碍物后沿障碍物表面滑动，与许多游戏引擎、MINOS、DeepMind Lab、AI2 THOR 及 Gibson v1 的默认行为一致。该行为让操作手感平滑，却给学习型策略留下漏洞：策略学会贴着墙滑行，实际轨迹占用合法位置，但相邻状态之间的位移方向可以斜插过障碍物所在的区域，论文将这类轨迹描述为「看起来穿过不可通行区域」，并把由此得到的路径称为优于最优路径。真机上，机器人的碰撞传感器会在接触时强制停机，这类策略直接失效。2020 挑战通过修改 Habitat-Sim（禁用滑动的变更记录见 habitat-sim PR #439）关闭该行为。

从单步位移看差异很直接。设接触面的单位切向为 t，指令位移为 d。滑动开启时，碰撞求解把位移投影到可行切向，智能体保留沿墙的前进分量；滑动关闭后，接触即停，该步位移被取消：

Δxslide = projt(d)，Δxstop = 0

在滑动开启时，智能体沿墙继续前进，无需先转向再接近，单步路径更短。指标层面的漏洞出在 SPL 的分母：pi 由相邻状态位置之间的欧氏距离累加，测地距离不参与该累加。贴近墙角滑动时，相邻状态的连线可以切进障碍的内切区域，使累加量小于按智能体半径约束计算的最短路径 li，理论上可让 SPL 超过 1。CODA 实验用同一批九个模型、三种房间配置、每配置五个起终点、每点三次重复，共 405 次仿真与 405 次真机运行，真机合计约 40.5 小时；关闭滑动后排序相关性大幅提升，说明该漏洞具有实际影响，会改变榜单结论。

榜单层面还有一组直观对比。2019 PointNav 的 RGB-D 赛道冠军 SPL 为 0.948；2020 PointNav 榜首 SPL 为 0.21、成功率 0.28、SoftSPL 0.50、到目标距离 2.29 m。相对下降 77.9%。该差距同时包含四项改造与回合数据重生成的影响，不能归因于单一因素：2020 的本体更宽（半径 0.18 m，成功半径 0.36 m，等于两倍半径），官方明确说明加宽的智能体使 2019 的部分回合不可导航，回合数据随之重新生成。

4. 噪声注入：两条链路

致动噪声的做法是对每个动作采样一个相对位移的多元高斯，均值与协方差来自 PyRobot 团队用动捕设备对 LoCoBot 的基准测试；加入截断后，智能体在指令方向上至少保留一小段位移，避免出现反向运动。传感噪声包含两项：彩色图的加性高斯强度噪声，以及深度图的 Redwood 深度噪声模型。官方说明中有两条工程事实：开启传感噪声会明显降低仿真速度，因此建议先关闭噪声训练、需要时再打开做微调；噪声对长轨迹的影响呈累积形态，同一动作序列的不同采样终态差异很大。第 084 讲会给出这些模型的参数值与采样语义。

5. 指标可读性的变化

现实化之后，二元成功率对噪声非常敏感，柔性成功率（SoftSPL）成为必要的补充。软成功的定义为：

s̃ = max(0, 1 − dT/d0)，SoftSPL = (1/N)Σ s̃i · li/max(pi, li)

其中 d0 为回合初始到目标的距离，dT 为结束时到目标边界的距离。失败回合按接近程度获得部分分数，能反映「差一点成功」的进展。2020 PointNav 榜首的 SoftSPL 0.50 是 SPL 0.21 的 2.38 倍，差距 0.29；第二名 ego-localization 的 SoftSPL 0.60 是其 SPL 0.15 的 4.00 倍。可见在强噪声设置下，只报 SPL 会系统性低估完成接近过程的方法。ObjectNav 2020 榜单还给出一个更尖锐的例子：冠军 Arnold 成功率 0.25、SoftSPL 0.18，亚军 SRCB 成功率 0.19、SoftSPL 0.22，按不同指标排名会互换。

6. 口径边界：ObjectNav 2020 的现实化范围

同年的 ObjectNav 赛道采取不同取舍。官方页面写明：智能体配备 RGB-D 相机与无噪声的 GPS+Compass 传感器，该任务不注入任何传感噪声；成功判据为停止时距任意目标实例不超过 1.0 m，且从停止位姿通过转向或俯仰能够看到目标（oracle 可见性）；数据集为 MP3D 的 90 个场景与手工筛选的 21 个类别，ObjectNav-SPL 的最短路径基线计算到离起点最近的目标实例。该赛道发布的本地评测配置仍沿用 LoCoBot 本体尺寸（半径 0.18 m、身高 0.88 m）、关闭滑动、转向与俯仰角 30°，动作集合包含抬头与低头，RGB 为 640×480、水平视场 79°，深度截断在 0.5 m 至 5 m。「去 GPS、加噪声」属于 PointNav 的改造；ObjectNav 保留了干净定位与干净传感，只共享本体、动作与禁滑动这几项设置。引用任何数字前先确认它属于哪条赛道。

关键代码与解读

三段代码对应三个问题：碰撞响应怎样产生位移差；无 GPS 时目标方向为何依赖在线定位；切角轨迹如何让 SPL 超过 1。

片段 1：滑动与停止的单步位移差

import numpy as np

def step_displacement(intent, normal, allow_sliding):
    """intent: 指令位移向量; normal: 接触面单位法向（指向自由空间）。"""
    into_wall = np.dot(intent, -normal)          # 指向障碍的分量
    if into_wall <= 0:                           # 未接触，直接位移
        return intent
    if allow_sliding:
        return intent - np.dot(intent, normal) * normal  # 2019：保留切向
    return np.zeros_like(intent)                 # 2020：接触即停

normal = np.array([0.0, 1.0])                   # 墙在 y 轴负侧
intent = np.array([0.2, -0.15])                 # 斜向压墙
print(step_displacement(intent, normal, True))
print(step_displacement(intent, normal, False))

解读：（1）滑动分支返回切向投影，语义对应「碰撞后沿障碍滑行」，智能体保住沿墙的前进分量；关闭滑动后返回零位移，语义对应实体机器人的接触即停。（2）真实 sim 中的最终位姿由 habitat-sim 的碰撞求解给出，这里的二维投影只用于说明位移差，不要拿它替代物理后端。（3）把该函数接入回合循环，即可统计「因碰撞损失的位移比例」，它是判断策略是否依赖滑动的直接指标。

片段 2：start 坐标系目标与位姿误差

import numpy as np

def rot(theta):
    c, s = np.cos(theta), np.sin(theta)
    return np.array([[c, -s], [s, c]])

def goal_vector(g_start, pose_hat):
    """g_start: 起点坐标系下的目标向量; pose_hat: (x, y, theta) 估计位姿。"""
    x, y, th = pose_hat
    return rot(th).T @ (g_start - np.array([x, y]))   # 转到当前机体系

g_start = np.array([3.0, 1.0])                        # 起点处看到的目标
for th_err in (0.0, 0.1, 0.3):                        # 朝向误差（弧度）
    w = goal_vector(g_start, (0.0, 0.0, th_err))
    bearing = np.arctan2(w[1], w[0])
    print(f"heading err {th_err:.1f} rad -> bearing {bearing:+.3f} rad")

解读：（1）目标向量固定在起点坐标系，位姿估计是把它转回机体坐标系的唯一途径；朝向误差几乎原样进入目标方位角，1 倍放大。（2）真实系统里 (x, y, θ) 由视觉里程计、SLAM 或激光雷达定位提供，误差随轨迹累积；论文在真机上用 Hector SLAM 把误差压到约 7 cm，而轮式里程计组合滤波约 40 cm，两者相差 5.7 倍。（3）训练时可以按该接口注入定位噪声，把「定位质量」当作独立变量做消融，而不必改动策略网络。

片段 3：切角轨迹与 SPL 分母

import numpy as np

def chord_path(points):
    """相邻状态欧氏距离之和，对应 SPL 的分母 p。"""
    pts = np.asarray(points, dtype=float)
    return float(np.sum(np.linalg.norm(np.diff(pts, axis=0), axis=1)))

# 绕墙角的两条位置序列：左列贴墙滑行（相邻连线切过障碍），右列按半径绕行
slide = [(-0.50, 0.30), (0.00, 0.30), (0.30, 0.00), (0.30, -0.50)]
round_corner = [(-0.50, 0.30), (-0.18, 0.30), (-0.18, -0.18),
                (0.30, -0.18), (0.30, -0.50)]
p_slide, p_round = chord_path(slide), chord_path(round_corner)
l_geodesic = p_round                                  # 半径约束下的绕行长度
print(f"slide p = {p_slide:.3f} m, constrained p = {p_round:.3f} m, "
      f"apparent SPL = {l_geodesic / p_slide:.3f}")

解读：（1）滑动序列中 (0.00, 0.30) 到 (0.30, 0.00) 的连线切入障碍内切区域，欧氏累加 1.424 m 小于按半径约束的绕行长度 1.600 m，比值 1.123 说明表观 SPL 可以大于 1；真实轨迹越贴近墙角、采样越密，该效应越明显。（2）这里用折线近似圆弧，目的是暴露指标对位置序列的敏感性；正式评测中 p 仍由仿真逐步累加，l 由导航网格给出。（3）关闭滑动后，切角序列的位置更新不再合法，策略必须学会提前转向，这既消除了指标漏洞，也把「避障」从隐含能力变成显式要求。

常见误区

  • 把 PointNav 改造套到 ObjectNav：症状是声称 2020 ObjectNav 也去掉了 GPS+Compass 并注入传感噪声。根因是两条赛道的现实化范围不同。修复：以官方页面为准，ObjectNav 2020 保留无噪声的 GPS+Compass，也不注入传感噪声；共享部分是 LoCoBot 本体、30° 动作与禁滑动。
  • 直接续接 2019 与 2020 榜单：症状是解读为「智能体能力下降了 77.9%」。根因是回合数据因本体加宽而重生成，成功半径、动作角、噪声与滑动设置同时变化，属多项并发改动。修复：只做同配置内的横向比较；跨年比较先统一回合集与判据，再做阶梯消融。
  • 认为关闭滑动等于消除碰撞代价：症状是以为禁用滑动后撞墙没有损失。根因是碰撞仍然阻断位移，策略必须转向重新接近，步数预算白白消耗。修复：把碰撞计数与损失位移比例作为训练诊断量，必要时加碰撞惩罚或课程学习。
  • 只报成功率或 SPL：症状是在强噪声口径下低估接近过程。根因是二元成功对噪声敏感，失败回合的全部进展被抹掉。修复：同时报告 SR、SPL、SoftSPL 与 DTG；2020 ObjectNav 榜单中冠军与亚军的 SoftSPL 排序与成功率排序相反，这条教训已经明示。
  • 把噪声模型参数当作真机实测常数：症状是引用 0.5 倍噪声倍率并宣称它代表 LoCoBot 的真实噪声水平。根因是该模型来自特定控制器与场地条件下的基准测试，且论文网格搜索发现噪声倍率 0.0 在其受控环境中预测性最优。修复：把噪声倍率当作可控仿真参数做敏感性分析，不要把它固化为真机常数。

练习与思考

  1. 用片段 1 的函数计算：斜向压墙的指令位移为 (0.2, −0.15)、法向为 (0, 1) 时，滑动与停止两种模式下的前进位移各是多少，损失比例是多少？★
    提示
    滑动模式返回切向投影 (0.2, 0)，前进分量为 0.2 m，法向的 0.15 m 被消去；停止模式返回零位移，前进分量为 0。相对指令前进分量 0.2 m，滑动保留 100%、停止损失 100%；若把法向分量也计入位移模长，滑动模式损失 20%。
  2. 推导：若朝向估计误差为 ε，目标向量长度为 r，位置估计误差为 δp，给出目标方位角误差与距离误差的一阶近似表达式。★★
    提示
    方位角误差约为 ε 加上垂直方向位移误差除以距离 r 的项；距离误差约为位移误差在目标方向上的投影。朝向误差不随距离衰减，位移误差的影响随接近目标而放大。
  3. 设计一组实验，把 2019 到 2020 的 SPL 下降分解到「定位、噪声、滑动、本体」四个因素上。要求写明回合集与种子的控制方式、每个实验臂的配置、观察量与统计口径。★★★
    提示
    用同一批新回合（0.18 m 半径）作为共同基础，构造全因子或阶梯设计：A 理想定位/无噪声/滑动开；B 仅去定位；C 仅加噪声；D 仅禁滑动；E 仅换本体；F 全开。每个臂跑相同种子集合，报告 SR/SPL/SoftSPL 的均值与置信区间，并按「滑动引发的表观 SPL 超 1 轨迹占比」做机理解释。注意本体项必须重建回合，因此不能与旧回合直接配对。
  4. 复算：CODA 实验包含 9 个模型、3 种房间配置、5 个起终点、每个组合 3 次重复，真机每次约 6 分钟。求真机运行总时长与实验总运行次数（含仿真）。★★
    提示
    单侧运行数为 9 × 3 × 5 × 3 = 405，双边共 810。真机时长为 405 × 6 分钟 = 2430 分钟 = 40.5 小时，按每天 8 小时需要约 5 个工作日。
  5. 若把 SPL 的路径长度从「相邻状态欧氏距离累加」改为「相邻状态测地距离累加」，滑动漏洞是否仍然存在？说明理由并给出检验方案。★★
    提示
    漏洞会显著减弱，因为测地累加不会让切角连线穿过障碍；但仍需检验滑动是否让智能体以更少步数完成同等路径，从而在时间预算上获得不公平优势。检验方案：对同一策略分别记录欧氏与测地两种 p，比较两者比值在滑动开/关下的分布差异。

小结

  • 四项现实化改造：去 GPS+Compass、注入致动与传感噪声、关闭碰撞滑动、按 LoCoBot 重设本体；动机是提高仿真对真机表现的预测性，证据是 SRCCSucc 从 0.18 升到 0.844、SRCCSPL 从 0.603 升到 0.875。
  • 去定位改变了目标表示：目标固定于起点坐标系，当前可用方向依赖在线位姿估计；朝向误差原样进入目标方位角，真机上激光雷达 SLAM 约 7 cm、轮式里程计组合滤波约 40 cm，相差 5.7 倍。
  • 禁滑动消除抄近路：2019 口径的贴墙滑行让相邻状态连线切过障碍，表观 SPL 可以超过 1；CODA 中滑动关闭与低噪声倍率的组合把排序反转从 9 次降到 5 次。
  • 指标纪律：强噪声口径下必须同时报告 SR、SPL、SoftSPL 与 DTG；2020 PointNav 榜首 SoftSPL 0.50 是 SPL 0.21 的 2.38 倍，ObjectNav 冠亚军在两类指标下排序相反。
  • 口径边界：ObjectNav 2020 保留无噪声 GPS+Compass、不注入传感噪声，成功判据为 1.0 m 加 oracle 可见性；共享 LoCoBot 本体、30° 动作与禁滑动。
