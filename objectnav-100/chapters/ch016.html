第一篇 · 任务、仿真与评测地基

第 016 讲｜观察与动作空间

前三讲看完数据与平台，本讲收束到智能体的接口：它看到什么、能做什么。RGB-D 的分辨率与视场、GPS+Compass 的有无、致动噪声与碰撞滑动、离散与连续动作，这些假设属于任务难度的一部分，超出实现细节的范畴。同一网络在有定位与无定位下的差距可以超过六倍，复现实验最常失配的位置也在这里。

  • 主题：传感器假设 / 动作空间 / 口径矩阵 / 无定位导航
  • 关键公式：观测 ot = (IRGB, ID, u, g)，动作粒度 360° / θturn 个离散转向
  • 预计学时：60 分钟
  • 前置章节：第 015 讲（ProcTHOR：程序化生成）

学习目标

  • 能写出观察空间的组成 ot = (IRGB, ID, u, g)，逐项说明分辨率、深度量程、定位传感器与目标规范的口径。
  • 能默写 2019 至 2023 年主要口径的传感器与动作矩阵，包括 DD-PPO、2020 PointNav、2020 ObjectNav、2023 ObjectNav 与 RoboTHOR。
  • 能实算视场几何与数据率：79° 视场下每度像素数、1 米处单像素物理尺寸、RGB-D 每帧字节数与带宽。
  • 能用 DD-PPO 的对照证据解释观察假设对难度的主导作用：有无 GPS+Compass 6.32 倍差距、RGB 与 RGB-D 的 3.0% 差距、Blind 与 RGB-D 的 3.17 倍差距。
  • 能实现观察打包、带噪离散动作封装与连续速度适配三层接口，并写出一份可复现的观察动作口径清单。

背景与动机

第 013 至 015 讲依次讨论了三件事：标注体系（HM3DSEM）、平台能力（AI2-THOR / RoboTHOR）与数据规模（ProcTHOR）。三者决定「用什么环境、拿多少数据」，但还不能确定实验是否可比。智能体的输入输出界面另有一组假设：相机分辨率与视场、深度量程、定位传感器是否提供、执行是否有噪声、动作是离散还是连续。两组实验只要在这组假设上不同，即使同任务、同数据集、同指标，数字也无法直接比较。

现实里这类失配非常常见。2019 年 Habitat PointNav 的智能体带 GPS+Compass，训练执行确定；2020 年挑战把定位去掉、注入按 LoCoBot 标定的致动噪声与传感噪声，任务难度陡增。DD-PPO 的对照最能说明问题：同一网络、同一数据，去掉 GPS+Compass 后，SPL 从 0.948 掉到 0.15（Wijmans 等，2019）。另一侧，2023 年 ObjectNav 换成 Hello Robot Stretch 本体并支持连续动作，目标是把仿真口径推向真机可控，第 087 讲会继续这条线。

本讲解决三个问题：观察与动作各自有哪些可选口径；这些口径如何量化地改变难度；工程上如何把口径固定进代码与实验记录。第 017 讲接着用 DD-PPO 的训练规模账，回答「把这套接口训到极限需要多大算力」。

核心原理

1. 观察空间的形式化与代价

导航任务的观测在多数实现里写成四元组：

ot = (IRGBt, IDt, ut, g) ut 为定位读数（可为空）；g 为目标规范；深度图可缺省，缺省后的口径必须单独声明

逐项说明。IRGB 是彩色图，分辨率与水平视场决定角分辨率；ID 是深度图，量程决定多远的信息在理论上可得；ut 是定位读数，相对 episode 起点给出位置与航向；g 是目标，ObjectNav 下为类别词。四个分量里任何一个的口径不同，策略可用的信息集就不同。数据代价可以按未压缩字节估算：

B = H · W · (Crgb · brgb + Cd · bd) · f H、W 为高宽，b 为每像素字节数，f 为帧率，C 为通道开关

以 640 × 480、RGB 三字节每像素、深度 float32 四字节每像素、30 帧每秒为例：单帧 2.05 MiB，单路视频流约 61.5 MiB/s。换成 DD-PPO 的 256 × 256 输入，单帧降到 448 KiB，30 帧每秒约 13.1 MiB/s，像素数为 65,536，是 640 × 480 的 0.213 倍（后者是前者的 4.69 倍）。算力预算有限时，分辨率与帧率是最直接的杠杆，代价是远距目标的角分辨率随之下降。

三条演进线索值得记住。第一，PointNav 的定位从有到无、噪声从无到有，走的是真机化路线；ObjectNav 到 2023 年仍保留无噪声 GPS+Compass，定位问题被有意留在任务之外。第二，动作从 10° 离散走到 30° 离散，再走到连续速度，粒度反过来影响可达路径与评测口径，第 024、083、087 讲会分别展开。第三，2023 年的两处工程约束值得单记：所有 episode 都可以在不跨楼层的前提下完成，且 STOP 在连续控制下是独立动作，取值大于阈值时触发。跨楼层与停止语义直接改变数据生成与评测实现，超出形式细节的范畴。评测预算同样写进协议：2023 年的提交在 1,000 条 episode 上评测、总时限 48 小时，折合每条约 172.8 秒；2020 ObjectNav 为 1,000 至 2,000 条 episode、24 小时，折合每条 43.2 至 86.4 秒。动作粒度与相机假设决定这个预算能否跑满，也决定评测集上限。

3. 离散与连续动作的算术

离散动作空间的两个参数是前向步长与转向角。转向粒度决定一圈的动作数：

nturn = 360° / θturn 10° 对应 36 个动作；30° 对应 12 个；45° 对应 8 个

粒度越细，朝向控制越精确，动作序列越长，训练与评测的步数上限都要相应放宽。10° 粒度下一个 90° 转弯要 9 个动作，45° 粒度只要 2 个；同样的旋转精度差 4.5 倍。前向步长决定路径离散化误差：0.25 m 步长下，靠近目标需要靠停止阈值吸收剩余误差。DD-PPO 用 0.2 m 的成功阈值，面积上相当于 ObjectNav 1 m 成功壳的二十五分之一：π·1.0² 与 π·0.2² 之比正好 25.0。两个任务的接近难度因此完全不同，PointNav 的「接近」远比 ObjectNav 严格。

碰撞语义同样属于动作口径。2019 年 Habitat 允许碰撞后沿障碍物滑动，挑战方发现学到的策略借此穿越非可通行区域，在真机上因碰撞传感而失效，于是在 2020 年修改仿真器关闭滑动。AI2-THOR 与 Gibson v1 等平台默认保留滑动，RoboTHOR 则通过标定噪声模拟真机行为。跨平台迁移策略时，滑动开关必须与训练时一致；把它当作无关紧要的引擎参数是复现失败的常见来源。

连续动作把「一步走多远」交给策略：动作是线速度与角速度指令，仿真按控制周期积分，STOP 单独判定。好处是控制平滑、接近真机；代价是口径复杂度上升：积分周期、速度上限、指令平滑与终止阈值都要写进配置。把连续动作实验与离散动作实验的「步数」直接并排也不成立，两者的时间尺度不同，比较应回到米与弧度。

4. 假设改变难度：DD-PPO 的对照证据

DD-PPO 的消融提供了同一任务上观察假设的受控比较，值得逐条实算：

  • 定位：RGB-D 加 GPS+Compass 的测试 SPL 为 0.948；同一框架在去掉 GPS+Compass、只用 RGB 后，训到 25 亿步才达到 0.15，差距为 6.32 倍；在 1 亿步时无定位版本的 SPL 还是 0。
  • 深度：RGB-D 测试 SPL 0.948 对 RGB 0.920，差距 0.028，相对约 3.0%；两者的成功率却接近（0.980 对 0.977），深度主要影响接近效率。
  • 视觉本身：只带 GPS+Compass 的 Blind 智能体在 20 至 25 米长程 episode 上 SPL 约 0.3，RGB-D 为 0.95，差距 3.17 倍；短程导航两者差距很小。这说明结构先验能解决「转身直走」的短程情形，长程仍依赖视觉。
  • 训练量的边际形态：误差对计算量呈幂律形状，100M 步（占总步数 4.0%）已拿到约 90% 的峰值性能。第 017 讲把这笔算力账展开。

把四项排序，定位的影响最大，其次是有无视觉与视觉的模态，最后是深度的边际作用。这个排序对实验设计的直接含义是：预算有限时优先保证训练环境规模与视觉输入的正确性；若研究目标是真机部署，则要优先处理无定位这一档，不在 RGB 与 RGB-D 之间反复调参。

5. 几何换算：视场、像素与深度

2020 ObjectNav 的相机口径为水平视场 79°、分辨率 640 × 480、深度量程 0.5 至 6 m，对齐 Azure Kinect。三个换算结论常用于判断实现是否合理：

  • 角分辨率：640 / 79 = 8.10 像素每度；单像素张角 0.1234°，在 1 米处对应约 2.15 mm。
  • 覆盖一个方向：79° 视场下，4 个朝向覆盖 316°，不足 360°，全景扫描至少需要 5 个朝向。
  • 物体张角：0.5 米宽的物体在 1 米处张角约 28.07°，占约 227 像素；可见「至少 1 像素」的可见性下限非常宽松，它服务于可复现，精度不是目标。

深度量程 0.5 至 6 m 覆盖了 ObjectNav 的整个交互距离：成功壳在 1 m，任何小于 0.5 m 的物体信息在理论上不可得；相机近端裁剪也意味着贴得太近同样会丢失信息。RoboTHOR 的视角实验给出量程与视场失配的后果：训练用 90° 视场、测试换 42.5°，真机 easy 档成功率掉到 16%，medium 与 hard 归零。视场变化让图像的角分辨率与内容分布同时漂移，策略的输入统计被破坏。

6. 边界与失效

  • 无噪声假设的脆弱性：2020 ObjectNav 明确不注入传感噪声，GPS+Compass 也无噪声。这个理想化让方法比较更干净，但把定位误差、深度缺失与相机标定误差都排除在难度之外；真机部署必须另行评估（第 083、084 讲）。
  • 成功阈值与动作粒度耦合：0.2 m 的 PointNav 阈值配 0.25 m 步长时，接近阶段必须靠停止判定吸收误差；把阈值直接搬到 0.25 m 步长的离散动作上，会制造大量「差一步」的失败样本。
  • 深度缺失的连锁影响：第 014 讲的 RoboTHOR 基线与 ProcTHOR 的模型都验证了无深度可训，但无深度对碰撞规避与近距离接近的影响随场景密度上升，空旷与拥挤环境的结论不可互换。
  • 连续动作的评测口径：速度指令下「步」不再对应固定位移，episode 长度、动作数与路径长度三者解耦；报告时要用米、秒与动作数分别标注，避免与离散动作实验的步数直接相比。
  • 定位传感器的位置假设：GPS+Compass 相对 episode 起点定义，同一场景不同起点得到的坐标不同。跨 episode 复用状态（例如记忆）时，坐标系必须显式转换，否则第二幕的定位读数会把第一幕参考系带入，产生隐性错误。

实现思路与设计

观察与动作层建议设计成三个可独立开关的组件：观察构建器、动作封装器、评测口径记录。三者与策略网络解耦，口径变更只动配置，不动模型代码。

3. 接口与数据结构

观察构建器输出固定字典，策略只读该字典；动作封装器接受统一动作词表，向仿真层翻译；评测记录器逐幕保存口径清单。三层之间不共享隐式状态，换平台时只替换最底层。

设计决策：口径进配置，不进代码

分辨率、视场、量程、步长、转角、噪声开关与滑动开关全部写成配置项，训练脚本启动时打印完整配置并落盘。这样任何两次实验的差异都能从记录中直接读出，对照消融也不会因为一行隐藏的默认值而失真。

设计决策：训练增强与评测口径分离

训练可以随机分辨率、随机噪声、随机帧率做增强，评测必须回到固定口径。把随机化开关放在环境层，不放在数据层，才能保证评测时一键冻结。第 015 讲的材质随机化遵循同一原则。

报告清单

一份导航实验结果至少注明：图像分辨率与视场、深度量程与缺失处理、定位传感器有无与噪声、动作类型与粒度、碰撞滑动开关、致动与传感噪声模型、STOP 语义、步数上限、多帧堆叠方式。缺任何一项，跨论文对比不成立。

4. 与前几讲的差异点

第 001 讲冻结了 2020 口径的六动作与 GPS+Compass；第 014 讲展示了严格可见性与标定噪声；第 015 讲确定了训练数据的规模维度。本讲把三者合成矩阵，并加入 2019（DD-PPO）与 2023（Stretch 连续动作）两端。后续讲次引用任何数字时，都在此处查到对应口径；第 042 讲复现 DD-PPO 的 10° 动作与 0.2 m 成功阈，第 087 讲展开 Stretch 的连续控制。

关键代码与解读

三段代码对应观察、离散动作与连续动作三层接口，字段名做教学简化，思路与主流框架一致。

片段 1：观察打包与相对目标换算

import math
import numpy as np

def build_observation(rgb, depth, pose, start_pose, size=256):
    """打包策略输入：降采样 RGB-D 加相对位姿。"""
    rgb_s = resize(rgb, (size, size))              # 训练分辨率固定，禁止隐式缩放
    d_s = resize(depth, (size, size))
    d_s = np.clip(d_s, 0.0, 1.0)                   # 先按量程裁剪，再归一化
    dx = pose[0] - start_pose[0]                   # GPS：相对起点的位移
    dy = pose[1] - start_pose[1]
    dpsi = wrap_to_pi(pose[2] - start_pose[2])     # Compass：相对航向绕回 [-pi, pi]
    return {"rgb": rgb_s, "depth": d_s,
            "pose_delta": np.array([dx, dy, dpsi])}

def relative_goal(goal_xy, pose):
    """PointGoal 目标以起点为参照，每步换算到本体坐标系。"""
    dx, dy = goal_xy[0] - pose[0], goal_xy[1] - pose[1]
    c, s = math.cos(-pose[2]), math.sin(-pose[2])
    return np.array([c * dx - s * dy, s * dx + c * dy])   # 前向与左向分量

解读：（1）RGB 与深度必须使用相同的降采样与归一化路径，两路不一致会引入隐性错位。（2）深度先裁剪再归一，顺序颠倒会把量程外的远点压回有效区间。（3）相对目标是 DD-PPO 的设计：目标随步更新，策略无需推算全局坐标。（4）把 pose_delta 作为独立字段输出，实验时可一键移除，用于无定位消融。

片段 2：离散动作封装与口径开关

class DiscreteActions:
    """2020 ObjectNav 口径：0.25 m 前向、30 度转向、可选噪声与滑动。"""
    TURN_DEG = 30.0
    STEP_M = 0.25

    def __init__(self, sim, actuation_noise=None, sliding=False):
        self.sim = sim
        self.noise = actuation_noise            # None 表示确定性执行
        self.sliding = sliding                  # 2020 挑战关闭滑动

    def step(self, action):
        if action == "Stop":
            self.sim.stop()                     # 终止由评测器按成功判据裁决
        elif action == "Forward":
            step = self.STEP_M + (self.noise("trans") if self.noise else 0.0)
            self.sim.try_move(step, sliding=self.sliding)
        elif action in ("TurnLeft", "TurnRight"):
            sign = 1.0 if action == "TurnLeft" else -1.0
            deg = self.TURN_DEG + (self.noise("rot") if self.noise else 0.0)
            self.sim.rotate(sign * deg)
        else:
            raise ValueError("未知动作：" + str(action))  # 动作词表封闭，防拼写漂移
        return self.sim.observe()               # 碰撞时位置不变，动作照计步数

解读：（1）动作词表封闭，未登记动作直接报错，避免不同实验间的拼写漂移。（2）噪声与滑动都是显式构造参数，默认值与 2020 口径一致。（3）Stop 只发送终止信号，成功与否交给评测器，保持训练与评测职责分离。（4）碰撞后位置不变但动作计入步数，与挑战口径一致；滑动开关语义写在参数名里，迁移平台时一眼可见。

片段 3：连续速度适配与独立 STOP

import numpy as np

class VelocityAdapter:
    """2023 口径：连续速度指令加独立 STOP 判定。"""
    def __init__(self, env, limits, stop_thresh):
        self.env = env
        self.max_lin, self.max_ang = limits      # 速度上限取自当年 Stretch 配置
        self.stop_thresh = stop_thresh

    def act(self, lin, ang, stop_value):
        if stop_value > self.stop_thresh:         # STOP 是独立动作，与速度解耦
            self.env.stop()
            return True
        lin = float(np.clip(lin, -self.max_lin, self.max_lin))   # 指令先夹取
        ang = float(np.clip(ang, -self.max_ang, self.max_ang))
        self.env.integrate(lin, ang)             # 按控制周期积分位置与朝向
        return False

def episode_length_m(trace):
    """连续动作下的路径长度按位移积分，禁止用步数乘以固定步长。"""
    return float(sum(np.linalg.norm(np.diff(np.asarray(trace), axis=0), axis=1)))

解读：（1）速度上限与停止阈值都必须来自当年配置，代码不写死默认量值。（2）STOP 与速度解耦：即使速度指令为零，也不算停止，终止只由 stop_value 触发，这与 2023 挑战页的描述一致。（3）路径长度按位移积分，连续动作下步数不再对应固定位移。（4）夹取操作保证仿真层收到的指令在物理可达范围内，避免策略靠超限指令取巧。

常见误区

  • 分辨率与视场失配：症状是同一策略换个相机参数就大幅掉分，且失败集中在接近目标阶段。根因是角分辨率与输入分布变化；RoboTHOR 的对照中，训练 90° 视场、测试 42.5° 使真机 easy 档从可用掉到 16%，其余档归零。修复：训练时做视场与分辨率增强，评测固定口径并记录。
  • 有定位与无定位的数字并排：症状是复现表里两个 SPL 相差数倍，怀疑实现有错。根因是观察假设不同：DD-PPO 中 0.948（有 GPS+Compass）对 0.15（无），差距 6.32 倍。修复：把定位有无写进口径清单，任何汇总表都带该列。
  • 成功半径混用：症状是 SR 突然虚高或虚低。根因是 0.2 m（DD-PPO 口径）与 1.0 m（ObjectNav）的阈值互换；面积比达 25.0 倍。修复：阈值随任务与年份传入评测器，禁止模块级常量。
  • 动作子集与转角混用：症状是路径长度与步数对不上论文，动作数统计漂移。根因是 45° 四动作、30° 六动作、10° 四动作三种口径混用，还叠加了有无 Look Up/Down 的差异。修复：动作词表、转角、步长写成三元组配置，单元测试覆盖一圈转向的动作数（8 / 12 / 36）。
  • 碰撞滑动被忽略：症状是训练曲线异常好，真机部署立刻失败。根因是仿真允许沿墙滑动，策略学到穿越非可通行区域的走法；AI2-THOR 等平台默认开启滑动，Habitat 2020 起关闭。修复：显式配置滑动开关，与目标平台对齐，并在报告中记录。

  2. 按 79° 水平视场、640 像素宽度推导：每度像素数、单像素角宽、1 米处单像素物理尺寸、0.5 米宽物体在 1 米处的像素数，以及覆盖 360° 至少需要的朝向数。★★

小结

  • 观察空间写为 ot = (IRGB, ID, u, g)；分辨率、视场、深度量程与定位传感器的取舍直接改变可用信息集与算力预算。
  • 口径矩阵覆盖五个主流配置：DD-PPO（0.25 m / 10°、GPS+Compass、0.2 m 阈值）、2020 PointNav（无定位、带噪声）、2020 ObjectNav（无噪声定位、6 离散动作）、2023 ObjectNav（Stretch、连续动作、独立 STOP）、RoboTHOR（45° 子集、严格可见性）。
  • 观察假设的量级：有无 GPS+Compass 差 6.32 倍，长程 Blind 与 RGB-D 差 3.17 倍，RGB 与 RGB-D 之间只差 3.0%；深度是边际项，定位与视觉是主要项。
  • 几何实算：79° 视场、640 像素对应 8.10 像素每度，1 米处单像素 2.15 mm；0.2 m 与 1.0 m 成功半径的面积比为 25.0。
  • 工程红线：口径进配置、训练增强与评测冻结分离、动作词表封闭、滑动与噪声显式开关、报告带完整观察动作清单。
