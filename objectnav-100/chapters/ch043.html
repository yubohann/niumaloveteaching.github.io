第 043 讲｜导航表征预训练

第 042 讲的大规模训练留下两份资产：策略与视觉编码器。本讲检验它们能否像 ImageNet 那样跨任务复用。以 Wijmans 等（2020）的迁移实验为样本，拆开五种迁移设置，比较导航预训练编码器与 ImageNet 编码器，并给出迁移实验的样本量、评价指标与受控变量设计。

  • 主题：表征迁移 / 具身预训练 / 冻结与微调 / 迁移实验设计
  • 关键公式：n ≈ 16 σ2 / d2（两组均值差的功效近似）
  • 预计学时：70 分钟
  • 前置章节：第 042 讲（DD-PPO 分布式 RL 训练）

学习目标

本讲的目标是把「预训练能迁移」从一句口号变成可核算、可对照、可证伪的实验方案。

  • 理解：说清「具身版 ImageNet」类比的具体含义，以及导航预训练与静态图像预训练在监督信号上的差别。
  • 会算：核算预训练成本核算（100M 步占总步数比例、对应墙钟时间），并用功效公式估算迁移对比所需的验证幕数。
  • 会推导：写出 Flee 与 Exploration 两个迁移任务的回报与奖励式，说明源任务（PointNav）与目标任务的结构关系。
  • 会设计：按五种迁移设置搭建受控实验，明确每种设置的可训练组件、初始化来源与评价指标。
  • 会判断：给定一组迁移结果，区分「编码器表征带来的收益」与「策略初始化带来的收益」，识别冻结策略失效的条件。
  • 能定位边界：理解表征迁移的条件性，分割模型的零样本迁移与循环动力学失稳是反例来源。

背景与动机

第 042 讲用 2.5B 步训练出近满分 PointNav 导航器，花费约 180 GPU 天。如果再遇到一个新导航任务，从零训练一份同等规模的模型显然不划算。监督学习领域给出过标准答案：先在 ImageNet 上预训练视觉骨干，再按任务微调。具身领域能否照搬这一模式，取决于两个问题：导航训练是否真的学到了通用场景理解；这份理解以什么形式存储在网络的哪个部分。

两个问题都可以用实验回答，而且实验设计本身有讲究。冻结预训练编码器再接一个从零策略，测的是表征质量；编码器保持冻结、策略从预训练权重微调，测的是整体适应速度；把预训练智能体当作可微控制器、外挂高层规划器，测的是低层技能的复用性。Wijmans 等（2020）在 Flee 与 Exploration 两个任务上把这套矩阵跑了一遍，结论明确：导航预训练编码器显著优于 ImageNet 预训练编码器，且多数迁移设置优于从零训练。

本讲的主线由此确定：先建立迁移的形式化与两个目标任务的奖励口径，再拆五种设置的对照结构，然后算清楚实验需要多少样本才能下结论，最后用 Ye 等（2021）的反例说明表征迁移的边界。第 044 讲将引入 CLIP，把静态视觉语言预训练接入导航，与本讲的具身预训练形成直接对照。

核心原理

本节按「形式化 → 目标任务 → 五种设置 → 成本与功效 → 边界」展开，数字均标注来源与协议。

1. 迁移学习的形式化

把网络分成两部分：视觉编码器 E（参数 θE）与决策部分 P（参数 θP，含循环层与策略头）。源任务训练得到 θE* 与 θP*。迁移到目标任务时，初始化与可训练范围构成两个独立的自由度：初始化取自源任务或图像预训练；可训练范围分为全量、仅策略、仅编码器、两者皆冻结。源任务目标写成：

θE*, θP* = argmaxθE, θP Eτ~πθ[ Σt γt−1 rtsrc ] 源任务为 PointNav：输入含 RGB 与 GPS+Compass，奖励含测地距离形项，监督信号密集

与 ImageNet 预训练相比，源任务监督信号的差别是结构性的。ImageNet 的标签是静态图像的类别，网络学到物体纹理与外观的判别特征；PointNav 的奖励来自具身交互，编码器必须同时编码可通行区域、场景布局、门洞与走廊等几何线索，才能支撑「朝目标走」的决策。两种预训练信号互补，而导航任务更依赖后者。

2. 两个迁移任务：Flee 与 Exploration

Wijmans 等（2020）选择的目标任务来自 Gordon 等（2019）的对照设定，两者都移除 GPS+Compass，迫使智能体依赖视觉与内部状态。

Flee（远遁）。智能体最大化与起点的测地距离。记 st 为 t 时刻位置，Max(s0) 为从起点可达的最远距离，归一化距离 DT = Geo(sT, s0) / Max(s0)，奖励取相邻两步的归一化距离差放大 5 倍：

rt = 5 ( Dt − Dt−1 ) D 的归一化使不同场景的回报尺度一致；奖励密度与 PointNav 的测地形项同构

Exploration（探索）。智能体最大化访问过的位置数，位置按 1 m 立方计数。记 |Visitedt| 为到 t 时刻的访问数，奖励为新增格数的 0.25 倍：

rt = 0.25 ( |Visitedt| − |Visitedt−1| ) 与第 041 讲体素探索奖励同族；以 1 m 格计数，奖励尺度较小

用一组设例体会奖励尺度。Flee 设在起点最远可达 20 m 的场景，智能体从距起点 8 m 处向外走 0.5 m：D0 = 8/20 = 0.400，D1 = 8.5/20 = 0.425，单步奖励 r = 5 × 0.025 = 0.125。Exploration 设一幕内进入 100 个新格，总回报上限为 0.25 × 100 = 25.0。两个目标任务的共同点是奖励密集、目标不含坐标，智能体必须把「场景还有哪里没去过、目标方向大致在哪」编码进内部状态，这正是 PointNav 预训练应当提供的表征。

前四种设置共享一条注记：PointNav 策略的输入包含目标坐标，目标任务没有目标坐标，论文给策略输入一个任意选定的「哑目标」向量，并报告智能体能很快学会忽略它。这条注记是复现实验的关键细节：哑向量的处理不当会让策略把伪目标当作真实信号，污染迁移结论。第五种设置改变了比较的对象：冻结的低层控制器负责「走到指定坐标」，高层规划器每步输出一个坐标，两者联合训练，梯度穿过冻结控制器回传。它测的是「低层导航技能能否当模块复用」，与「表征能否复用」是两种不同的迁移。

实验结果用一句话概括：几乎所有迁移设置都优于从零训练，说明迁移收益成立；PointNav 预训练编码器显著优于 ImageNet 预训练编码器，说明收益的来源超出通用视觉特征，具身交互学到的场景理解是关键成分；微调策略的设置学习新任务最快，说明策略层也携带可迁移的导航技能；梯度控制器在 Flee 上优于冻结编码器加从零策略的组合，在 Exploration 上与之相当，说明低层控制器具备可组合性。

4. 预训练成本与迁移预算

第 042 讲的账目可以直接换算：2.5B 步对应约 180 GPU 天，而 90% 峰值性能在 100M 步处取得，占总步数的 4.0%，用 64 GPU 约 2.6 小时、用 8 GPU 约 21.1 小时。要做具身预训练，起点资源可以按这一量级准备：8 GPU 一天即可得到接近九成性能的表征，再决定是否扩大规模。

迁移侧的成本由目标任务决定，但实验规模有一个统计下界。比较两组方法在验证集上的平均指标差 d，设单幕指标的总体标准差为 σ，两组均值差检出的样本量与 σ2 / d2 成正比。按常用的 80% 功效近似：

n ≈ 16 σ2 / d2（每组幕数） 近似式在本课第 002 讲以比例标准误形式出现过；此处用于连续指标 SPL 的组间对比

实算四组参数：σ = 0.10、d = 0.05 时每组 64 幕；σ = 0.10、d = 0.02 时每组 400 幕；σ = 0.15、d = 0.05 时每组 144 幕；σ = 0.05、d = 0.02 时每组 100 幕。导航任务的单幕 SPL 波动大（σ 常在 0.1 以上），想检出 0.02 量级的差异需要数百幕；迁移论文常用的 1000 幕验证集能覆盖 0.02 到 0.03 的差异，更小的差异应报告置信区间并谨慎下结论。这是本讲对实验设计最直接的贡献：先算所需样本量，再决定对比方案。

5. 表征质量的测量：探针与消融

冻结编码器的性能差异只能说明「这组特征对新任务有用」，无法说明特征里有什么。线性探针补上这一层：固定编码器，在隐状态上训练线性解码器，预测已知的环境变量（如在场景中的位置、已经过去的时间步、目标是否出现过），以解码精度衡量该变量的可线性读出程度。Ye 等（2021）用这一方法检查 ObjectNav 智能体，发现各个独立信念模块编码了时间与「目标出现过的最大占比」两个量，但融合信念的探针精度低于单个信念，说明注意力融合过程损失了部分可读信息。方法要点有三条：探针必须在线性容量下训练，防止非线性解码器把额外计算当成表征质量；训练与验证场景严格分离；报告多个信念模块的方差，避免只看单点。

消融是第二个工具。Ye 等（2021）移除 SGE 特征使成功率下降约 14 个百分点，说明具身预训练的表征质量对下游任务的影响可能集中在少数接口特征上。判断一份导航表征是否值得冻结复用时，探针精度与下游迁移性能应同时报告，两者指向不同问题：前者回答「编码了什么」，后者回答「这些编码对任务是否有用」。

6. 边界与失效模式

  • 零样本迁移不等于微调迁移。Ye 等（2021）把在真值语义上训练的智能体直接换用预测分割，验证成功率从 58.0% 掉到 30.8%（6 动作设定，300 幕子集）；迁移一份预训练模型前，必须先在其原始评测口径上复现基线数字。
  • 输入接口必须对齐。预训练编码器的输入分辨率、色彩归一化、传感器假设与目标任务不一致时，冻结表征的收益会消失；PointNav 的 GPS+Compass 在目标任务是移除的对象，策略接口处必须做哑输入处理。
  • 噪声输入会破坏循环动力学。分割抖动、域差图片与传感器噪声让循环状态偏离预训练时的流形，迁移性能的下降幅度与噪声类型强相关，测迁移收益时应单独报告噪声条件。
  • 源任务与目标任务的奖励密度差决定迁移效率。PointNav 的奖励密集且与几何距离对齐，Flee 与 Exploration 也密集；若目标是稀疏奖励任务，编码器收益依旧，策略收益会明显下降。
  • 样本量不足的实验会翻转结论。σ 较大时，几十幕的验证集无法区分 0.05 以下的 SPL 差异；论文级对比需要按功效公式配足幕数并报告区间。

实现思路与设计

本节把迁移实验落成接口、参数与判定流程，并给出与上一讲的衔接说明。

1. 迁移接口设计

一个可复用的导航预训练包应暴露三样东西：编码器权重与配套的输入预处理（分辨率、归一化、相机参数）；低层控制器接口（输入目标相对坐标与观测，输出动作）；评测脚本（含原始口径的复现基线）。目标任务的训练代码通过两个适配点接入：观测适配器把目标任务的传感器张量映射到编码器输入；目标适配器为缺省的目标坐标生成哑向量，并暴露掩码供策略学习忽略。五条实现要点：

  • 编码器冻结时将其置于推理模式，禁止归一化层统计更新；可训练时统一改用组归一化，避免批统计随任务漂移。
  • 评论家层始终重初始化，源任务的价值尺度与目标任务不一致。
  • 哑目标向量固定为常数向量，不用随机张量，随机张量会被策略误当作信号；训练日志里记录策略对哑向量的梯度范数作为「忽略程度」的监控量。
  • 迁移训练的学习率按可训练参数量缩放：冻结编码器时策略学习率可高于全量微调档位，全量微调时用较小学习率保护预训练特征。
  • 评测同时记录「达到固定性能阈值所需步数」与「固定步数下的性能」，前者对样本效率更敏感，后者对渐近性能更敏感。

一次性全量微调只能给出最终数字，无法回答「收益来自哪里」。推荐流程：第一段冻结编码器、只训策略，测表征下限；第二段放开编码器小学习率微调，测表征上限；两段之差即微调收益，第一段与从零训练之差即表征收益。两段合计的算力通常仍低于一次盲目的大规模搜索，且结论可直接写进实验报告。

3. 与上一讲的差异点

第 042 讲交付训练系统与近满分策略，本讲把同一批资产拆成可复用的表征与技能，并用受控实验验证其价值。两讲共同构成端到端路线的完整闭环：先有大规模采样能力，再把采样成果沉淀为公共资源。下一讲引入另一类预训练资源：在大规模图像文本对上训练的 CLIP 表征，它不需要具身交互即可获得，而 EmbCLIP 用它搭出极简导航基线，与本讲的具身预训练形成对照实验的另一半。

关键代码与解读

三段代码覆盖迁移智能体组装、迁移评估的样本效率读数与线性探针，接口风格与全课一致。

片段 1：组装迁移智能体

import torch

def build_transfer_agent(pretrained, action_dim, feat_dim=256, freeze_encoder=True):
    """从预训练检查点组装迁移智能体：编码器可冻结，策略与评论家重建。"""
    encoder = pretrained.encoder
    if freeze_encoder:
        for p in encoder.parameters():
            p.requires_grad_(False)      # 冻结后不进入优化器参数组
        encoder.eval()                   # 归一化层统计不再更新
    else:
        switch_to_group_norm(encoder)    # 全量微调时替换批统计型归一化
    policy = torch.nn.LSTM(feat_dim + 2, 512, num_layers=2)   # 输入为特征加哑目标两维
    actor = torch.nn.Linear(512, action_dim)
    critic = torch.nn.Linear(512, 1)     # 评论家始终重初始化：价值尺度跨任务不可迁移
    return {"encoder": encoder, "policy": policy, "actor": actor, "critic": critic}

def dummy_goal(batch_size, dim, fill=1.0):
    """哑目标向量：非随机常量，供缺少目标坐标的任务使用。"""
    return torch.full((batch_size, dim), fill)

def forward_transfer(agent, obs, hidden):
    """前向接口：观测过编码器，哑目标与策略输入拼接，输出动作分布与价值。"""
    features = agent["encoder"](obs)
    goal = dummy_goal(features.shape[0], 2)
    x = torch.cat([features, goal], dim=-1)
    out, hidden = agent["policy"](x.unsqueeze(0), hidden)
    logits = agent["actor"](out.squeeze(0))
    value = agent["critic"](out.squeeze(0))
    return logits, value, hidden

解读：（1）冻结通过 requires_grad 与 eval 双开关实现，只停梯度不停推理会留下归一化统计漂移的隐患。（2）评论家重初始化的理由在价值函数：源任务的回报尺度由测地距离决定，目标任务由访问格数或归一化距离决定，直接沿用会拖慢早期优势估计。（3）哑目标用常量填充，梯度只经策略流入编码器，与哑向量本身无关；上线前用监控量确认它被忽略。（4）该组装函数把「哪些参数可训练」变成显式配置，五种迁移设置共用同一份组装代码，仅参数开关不同。

片段 2：样本效率评估

def steps_to_threshold(curve, threshold):
    """迁移评价之一：达到固定性能阈值所需步数，越小越省样本。"""
    for step, score in curve:
        if score >= threshold:
            return step
    return None                          # 全训练预算内未达标

def final_score(curve):
    """迁移评价之二：训练预算末尾的性能，反映渐近水平。"""
    return curve[-1][1]

def compare_curves(scratch_curve, transferred_curve, thresholds=(0.5, 0.8, 0.9)):
    """两条曲线对照：逐阈值报告样本节省与渐近差。"""
    report = []
    for th in thresholds:
        s0 = steps_to_threshold(scratch_curve, th)
        s1 = steps_to_threshold(transferred_curve, th)
        saving = None if (s0 is None or s1 is None) else (1 - s1 / s0)
        report.append((th, s0, s1, saving))
    report.append(("final", final_score(scratch_curve), final_score(transferred_curve), None))
    return report

解读：（1）阈值设 0.5、0.8、0.9 三档，取任务最终性能的比例，不取绝对值；绝对阈值随任务难度漂移，跨任务不可复用。（2）样本节省按 1 − s1 / s0 计算；设例中若从零训练 100M 步达标、迁移 20M 步达标，节省 80.0%。（3）步数未达标返回 None，对照函数对其跳过，避免用训练预算截断值冒充收敛步数。（4）渐近性能单独报告，因为表征迁移可能加快早期学习却降低最终水平，两条信息缺一不可。

片段 3：线性探针

import torch

def linear_probe(features, targets, ridge=1e-3):
    """线性探针：闭式岭回归解码冻结隐状态中的环境变量。"""
    x = features.double()
    y = targets.double()
    x = torch.cat([x, torch.ones(x.shape[0], 1, dtype=x.dtype)], dim=1)
    eye = torch.eye(x.shape[1], dtype=x.dtype)
    w = torch.linalg.solve(x.T @ x + ridge * eye, x.T @ y)
    return w

def probe_r2(features, targets, w):
    """在验证场景上计算决定系数，衡量变量的可线性读出程度。"""
    x = torch.cat([features.double(), torch.ones(features.shape[0], 1, dtype=torch.float64)], dim=1)
    pred = x @ w
    y = targets.double()
    ss_res = ((y - pred) ** 2).sum()
    ss_tot = ((y - y.mean(dim=0, keepdim=True)) ** 2).sum()
    return 1.0 - ss_res / ss_tot

def probe_report(representations, targets, split_index):
    """按信念模块分组报告：均值与方差都要看，单点精度不足以说明表征质量。"""
    rows = []
    for name, feat in representations.items():
        x_tr, x_va = feat[:split_index], feat[split_index:]
        y_tr, y_va = targets[:split_index], targets[split_index:]
        w = linear_probe(x_tr, y_tr)
        rows.append((name, float(probe_r2(x_va, y_va, w))))
    return rows

解读：（1）闭式岭回归训练成本极低，适合对大量变量做批量探针；线性容量约束保证测到的是可线性读出的信息。（2）训练与验证按场景切分，同一场景的相邻帧高度相关，按帧随机切分会把难度估计得过于乐观。（3）报告按信念模块分组，Ye 等（2021）的观察是各模块探针精度方差大、融合信念低于单模块，只看聚合均值会漏掉这一结构。（4）探针精度与迁移性能是两条独立证据：前者定位「表征里有什么」，后者判断「对任务是否有用」，联合报告才有诊断价值。

常见误区

  • 把 ImageNet 编码器与导航编码器的预处理混为一谈。症状：冻结编码器后性能低于从零训练。根因：图像预训练用的归一化统计、输入尺度与导航像素分布不一致，特征在目标域失配。修复：编码器权重与配套预处理一起加载；冻结前在目标任务的验证幕上核对第一层激活的分布。
  • 哑目标向量随机初始化。症状：迁移早期回报异常波动，策略对不同幕的目标行为不一致。根因：随机哑向量携带噪声信号，策略暂未学会忽略。修复：改用常量向量；监控哑向量分支的梯度范数，接近零后再开始比较迁移结论。
  • 用不同训练预算对比方法。症状：迁移方法在早期领先，长训练后被从零方法追平并反超，结论随评测点翻转。根因：只报固定步数下的单点性能，遗漏曲线交叉。修复：同时报告步数到阈值与渐近性能；固定随机种子并在多个预算点评测。
  • 验证集过小。症状：复现论文的迁移排序失败，换种子后差异消失。根因：单幕 SPL 的 σ 常在 0.1 以上，几十幕验证集检不出 0.05 以下的差异。修复：按 n ≈ 16σ2/d2 配足幕数；报告均值、置信区间与配对检验结果。
  • 把零样本迁移当微调迁移。症状：预训练模型直接换域部署，性能断崖式下降。根因：训练与部署的输入统计不同（如真值分割与预测分割），表征优势被域差淹没（对照第 041 讲的 58.0% 对 30.8%）。修复：迁移前先在原始口径复现基线；换域时至少做一轮小规模微调，并单独报告换域前后数字。

练习与思考

  1. 核算预训练成本：100M 步占 2.5B 步的比例；按每 GPU 164.4 步/秒计算 64 GPU 与 8 GPU 的墙钟时间；说明为什么「先跑 100M 步再决定是否扩大」是理性的预算策略。★
    提示
    100M / 2.5B = 4.0%。64 GPU：100e6 / (64 × 164.4) / 3600 ≈ 2.6 小时；8 GPU ≈ 21.1 小时。90% 峰值在 4% 步数处取得，先花小预算确认表征质量与配方方向，再决定 2.5B 步级投入。
  2. 把五种迁移设置填入表格，逐行给出编码器与策略的初始化来源、可训练状态；并说明为什么评论家层不能沿用源任务的权重。★
    提示
    参照本讲第 3 小节的矩阵：从零、ImageNet 冻结编码器、PointNav 冻结编码器、PointNav 双份微调、冻结控制器加规划器。评论家估计的是目标任务的回报，源任务回报由测地距离尺度定义，目标任务由访问格数或归一化距离定义，价值尺度不可迁移，沿用会拖慢早期优势估计。
  3. 推导 Flee 与 Exploration 的回报式，并用本讲设例数值（最远 20 m、当前 8 m、外移 0.5 m；一幕 100 个新格）核对单步奖励与总回报；再说明两个任务的奖励密度为什么适合作为迁移目标。★★
    提示
    Flee：r = 5 × (0.425 − 0.400) = 0.125；Exploration：总回报 0.25 × 100 = 25.0。两任务奖励密集且不含坐标目标，智能体必须依赖内部表征，能灵敏反映预训练编码器的场景理解质量；稀疏奖励任务会让策略收益被探索难度掩盖。
  4. 某迁移对比中 σ = 0.12，希望检出 d = 0.04 的 SPL 差异。按 n ≈ 16σ2/d2 估算每组幕数；若只跑 100 幕，实际能检出的最小 d 是多少？解释为什么要用配对设计（同一场景内对比）来降低 σ。★★
    提示
    d = 0.04 时 n ≈ 16 × 0.0144 / 0.0016 = 144 幕。只跑 100 幕时可检出 d ≈ sqrt(16σ2/n) = sqrt(16 × 0.0144 / 100) = 0.048。同一场景内的两条策略共享场景难度，幕级差值方差远小于跨场景方差，配对检验等效于缩小 σ。
  5. ★★★ 设计「具身预训练编码器对 ImageNet 预训练编码器」的受控对比实验，要求：给出五组以上对照（含从零与两个编码器来源的交叉）、说明每组哪些参数可训练；给出训练预算、评测阈值与样本量依据；说明如何用探针与消融补充「编码器学到了什么」的证据；最后给出一个可证伪的预测（例如在何种任务上两类编码器差距会缩小）。★★★
    提示
    对照可取：从零、ImageNet 冻结 + 随机策略、具身冻结 + 随机策略、具身冻结 + 预训练策略微调、具身全量微调五组，另加一组具身编码器随机初始化但同等预训练算力，用于排除算力混杂。评测用步数到 0.5/0.8/0.9 阈值加末段性能，样本量按 σ = 0.10、d = 0.02 取 400 幕以上（1000 幕更稳）。探针变量取时间、目标出现与否、房间类型、到目标距离；消融冻结不同层段区分低层纹理与高层布局的贡献。可证伪预测：在纯外观匹配任务（如目标识别式导航）上两者差距缩小甚至持平，因为该任务依赖纹理特征；在需要布局推理的长程探索任务上差距扩大。若实验显示差距与任务结构无关，则具身预训练优势的「场景理解」解释被削弱。

小结

  • 具身预训练的类比对象是 ImageNet 预训练加微调：源任务 PointNav 提供密集的几何奖励，编码器学到的场景布局理解是迁移收益的核心成分。
  • 五种迁移设置分离不同来源的收益：冻结编码器加从零策略测表征质量，冻结编码器加预训练策略微调测技能适应速度，冻结控制器加规划器测低层技能复用；评论家层一律重建。
  • 成本核算：90% 峰值在 100M 步（总步数 4.0%）取得，约 64 GPU 2.6 小时或 8 GPU 21.1 小时；迁移对比的验证幕数按 n ≈ 16σ2/d2 估算，σ = 0.10、d = 0.02 时需每组 400 幕。
  • 评价双指标：步数到阈值刻画样本效率，末段性能刻画渐近水平；两条曲线可能交叉，单点对比会得出随评测点漂移的结论。
  • 迁移有边界：换域前先复现原始口径；噪声与域差会破坏循环动力学（预测分割零样本替换使验证成功率从 58.0% 降至 30.8%）；哑目标与归一化接口必须显式处理。
