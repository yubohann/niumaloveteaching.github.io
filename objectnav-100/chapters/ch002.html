第一篇 · 任务、仿真与评测地基

第 002 讲｜任务家族：PointNav / ImageNav / ObjectNav / InstanceImageNav

本讲把四类导航任务放进同一分析框架：目标形式决定智能体必须推断什么，观察与传感器假设决定瓶颈落在哪里，统一的成功判据与 SR/SPL 决定结果如何比较。学完能独立填写任务家族对照表，并实现四类任务的成功判定与指标聚合。

  • 主题：任务家族 / 目标形式 / 传感器假设 / 评测口径
  • 关键公式：SPL = (1/N) Σi Si · li / max(pi, li)
  • 预计学时：60 分钟
  • 前置章节：第 001 讲（ObjectNav 是什么：形式化与共识）

学习目标

本讲的目标是能读、能算、能判：读懂任务定义，算清指标口径，判断一组结果是否可比。

  • 理解四类任务共享的 POMDP 骨架，能用「目标规范、观察、动作、成功谓词」四元组写出各自的形式化定义。
  • 掌握四类目标形式（相对坐标、类别词、目标图像、特定实例）的表示差异，以及每种目标要求智能体推断什么。
  • 能默写观察与传感器假设矩阵：PointNav 自 2020 年起取消 GPS+Compass，ObjectNav 与 ImageNav 保留无噪声 GPS+Compass。
  • 会计算并分解 SR 与 SPL，理解 SPL ≤ SR 与 SPL = SR × 成功幕平均效率，能解释 max(p, l) 裁剪的作用。
  • 能填写任务家族对照表，并判断一组跨数据集、跨版本的结果是否可比。
  • 能实现四类任务的成功判定器与 SPL 累加器，构造恰好命中阈值、恰好错过阈值的边界样例。

背景与动机

第 001 讲把 ObjectNav 形式化为「在未知环境中找到目标类别的一个实例并停止」，并给出了成功判据与指标的全景。留下一个问题：这套口径从哪里来，为什么与其他导航任务有差别。

答案在任务家族里。同一套强化学习与感知技术被用于多种导航任务，而任务名称背后至少有三层变量：目标以什么形式给出（坐标、类别词、图像、特定实例），观察里有没有定位传感器与噪声，评测用哪条成功谓词与哪个分母。2018 年，Anderson 等发布的评测共识文档指出，导航研究出现了大量「互相不兼容的任务定义与评测协议」，因此组成特别工作组统一问题陈述、评测指标与基准场景。该文档给出推荐口径，此后 Habitat 挑战页把口径落到具体年份、数据集与传感器上。

现实中的混用相当普遍。文献里 PointNav 与 PointGoal Navigation 并存；ImageNav 在不同论文与不同年份的挑战里，有时按类别判定，有时按实例判定；MP3D 时代的 21 类目标与 HM3D 时代的 6 类目标也常被并排引用。不清楚这些差异，就会把不可比的两个数字放在同一张表里。本讲先建立家族坐标系，把差异拆成目标形式、观察与传感器、成功判据、指标四项，再用实算把 SR 与 SPL 的关系讲透，最后收成一张可直接引用的对照表。第 003 讲展开成功判据的几何细节，第 004 讲专攻 SPL 与 ObjectNav-SPL，第 005 讲补上 SoftSPL 与 DTG。

核心原理

本节从共同骨架出发，依次拆解目标形式、观察与传感器、成功判据、指标四层差异，并给出全部数值算例。

1. 共同骨架：POMDP 加一个外部判据

四类任务共享同一副骨架：智能体在部分可观测环境中行动，观测由传感器给出，动作改变自身状态，评测方在幕后用特权信息判定成功。用第 001 讲的符号体系，一幕（episode）由起点位姿 s0、目标规范 g、时间上限 H 三要素确定。策略在时刻 t 依据观测历史与目标选择动作：

at ~ π(· | o0:t, g) o0:t 为到 t 时刻的观测序列；g 对智能体可见；停止动作 STOP 属于动作集合 A

训练目标通常写成折扣回报最大化：

π* = argmaxπ Eτ~π[ Σt=0H γt rt ] τ 为轨迹；rt 常取稀疏形式：成功停止得 1，其余步得 0 或小额负值

训练回报与评测判据属于两套机制。评测方计算的是一幕轨迹上的成功谓词 ρ(τ) ∈ {0, 1}，其输入包含智能体看不到的标注信息（实例位置、几何可视线）。任务家族的差异恰好落在四个位置上：目标规范 g 的形式、观察空间 Ω 的传感器构成、动作接口 A 的离散或连续、成功谓词 ρ 的判定规则。符号约定如下，全课沿用。

2. 四类目标形式

目标形式是家族划分的第一根轴。它决定了智能体必须从观测中推断出什么，也决定了策略输入端的接口形状。

PointNav：相对坐标。目标写成起点坐标系下的二维位移 g = (Δx, Δy)，口语表述为「从起点向北 5 米、向西 3 米」。世界坐标下的目标位置由起点位姿经旋转得到：

pg = p0 + R(ψ0) g,   R(ψ) = [ [cos ψ, −sin ψ], [sin ψ, cos ψ] ] ψ0 为起点朝向；目标在幕开始时确定，之后保持固定；坐标以米为单位

坐标目标的信息量小，困难在于智能体必须自己估计「我现在在哪里、朝哪边」。2020 年挑战的一个关键改动是去掉 GPS+Compass 传感器，使在线定位成为任务的一部分。

ObjectNav：类别词。目标写成一个类别标签 g = c，例如「find a chair」。场景中类别 c 的实例集合记为 I(c)，到达其中任意一个实例即满足目标。类别集合是数据集的属性：MP3D 有 40 个标注类别，2020/2021 挑战剔除视觉边界不清的类别（门、窗）与建筑构件（墙、地板、天花板）后保留 21 类；2022/2023 的 HM3D-Semantics 沿 Chaplot 等（2020）的设定采用 6 类：椅子、沙发、盆栽、床、马桶、电视。类别词目标要求智能体具备语义识别能力与「这类物体通常在哪里」的空间先验。

ImageNav：目标图像。目标写成一张 RGB 图像 I。Krantz 等（2022）在同一篇工作中给出两个粒度：ImageNav 的目标图像表达一个类别，到达该类别任意实例即可；InstanceImageNav 的目标图像表达一个特定实例，必须到达该实例。2023 年挑战页明确其 ImageNav 轨采用 InstanceImageNav 的任务定义，因此读到「ImageNav」一词时，先确认论文或榜单采用哪种粒度。图像目标还有一个结构特点：目标相机的参数与智能体相机解耦，高度、俯仰角、视场角按真实使用场景采样，目标图像的拍摄视角与智能体到达后能获得的视角不必一致。

InstanceImageNav：图像加特定实例。目标写成 (I, i*)，i* 为实例标识。它比类别级多出一道判别题：场景里可能有 m 个同类实例，外观相近、分布在不同房间。类别级判据对其中任何一个都记为成功；实例级判据只认 i*。若策略无法区分同类实例，只能随机选择，实例级成功率的上界为 1/m。代入 m = 2、4、8，上界分别为 0.5000、0.2500、0.1250。这组数字说明实例级任务的核心增量在再识别（re-identification）能力；导航能力本身在类别级任务中已经得到检验。

任务目标形式智能体必须推断成功粒度
PointNav相对坐标 (Δx, Δy)自身定位与朝向、到目标的距离到达坐标点附近
ObjectNav类别词 c语义识别、类别空间先验、探索效率任一实例
ImageNav目标图像 I（2023 轨为实例级）视觉匹配、视角泛化按定义取类别级或实例级

术语口径统一如下：PointNav 即文献中的 PointGoal Navigation，ObjectNav 即 Object Goal Navigation，ImageNav 即 Image Goal Navigation；本课程统一使用短名。更高阶的多模态终身设定（GOAT，同时给出类别、图像、语言三类目标）在第 072 讲展开。

3. 观察与传感器假设

观察空间由传感器组合决定，而传感器假设是任务身份的一部分。忽略它，网络结构与数据管线的对比都会失去意义。

PointNav（2020 与 2021 挑战）。智能体只配备 RGB-D 相机，没有 GPS+Compass。执行动作带有噪声：挑战方用 PyRobot 团队对 LoCoBot 的实测结果建立致动噪声模型，并加入 RGB 与深度传感器噪声；碰撞时禁用滑动，碰到障碍即停。这组改动把「高精度定位」从默认能力改成需要学习或估计的能力。2021 年的任务设定与 2020 年一致，仅调整了 PointNav 相机的俯仰角。

ObjectNav（2020 至 2023 挑战）。智能体配备 RGB-D 相机与无噪声的 GPS+Compass，后者提供相对幕起点的位置与朝向；相机规格向 Azure Kinect 对齐，任务本身不注入传感噪声。由于定位信息由传感器直接给出，困难集中在语义探索：判断目标类别通常出现在哪些房间，规划高效的搜索顺序，并在看到目标时可靠停止。2023 年本体换为 Hello Robot Stretch，引入连续动作空间，并把所有幕限制在无需跨楼层即可到达。

任务（年份）GPS+Compass传感噪声动作与本体
PointNav（2020/2021）无有：致动、RGB、深度离散：前进 0.25 m、转向 30°；LoCoBot 尺度
ObjectNav（2020/2021）有，无噪声无离散；相机规格对齐 Azure Kinect
ObjectNav（2022）有，无噪声无离散；HM3D-Sem v0.1
ObjectNav / ImageNav（2023）有，无噪声无连续动作；Hello Robot Stretch；幕内不跨层

由此得到一个常被忽视的判断：PointNav 衡量的是「定位加导航」的组合能力，ObjectNav 衡量的是「语义探索」的单项能力。把为 PointNav 设计的视觉里程计模块原样搬进 ObjectNav 往往收益有限，因为后者已经从传感器得到精确位姿；反过来，在 ObjectNav 数据上训练的策略缺少定位模块，直接投放到 PointNav 设定会明显退化。传感器配置必须显式写进任务配置对象，训练与评测两端保持一致，第 056 讲会讨论定位退化条件下的鲁棒性。

4. 成功判据与 oracle 可见性

成功谓词是家族的第三根轴，也是口径差异最容易被低估的地方。四类判据可以并列写出：

ρPN = 1[ ‖pT − pg‖2 ≤ 0.36 m ] 0.36 = 2 × 0.18：智能体半径 0.18 m 的两倍，见 2020 挑战页
ρON = 1[ ∃ i ∈ I(c) : ‖pT − vi‖2 ≤ 1.0 m ∧ Visoracle(vi, pT) ] Visoracle：在原位置转动或抬头低头即可看到实例，无需平移

ImageNav 与 InstanceImageNav 沿用 1.0 米加可见性的形式，作用于目标图像对应的实例集合或特定实例。Batra 等（2020）在 ObjectNav 协议说明中解释了两条规定：任意实例都算成功，最近实例决定效率分母；oracle 可见性用于代理「足够接近、可以交互」这一条件，挑战页明确写出，停止位置并不要求智能体当时正在注视目标，只要求存在一条无需平移的可视线。

两个半径的几何含义可以实算。半径 0.36 m 的成功圆面积为 π × 0.36² = 0.4072 m²，半径 1.0 m 为 π × 1.0² = 3.1416 m²，面积比为 (1.0/0.36)² = 7.7160。ObjectNav 的成功区域在面积上约为 PointNav 的 7.7 倍；换成离散动作的尺度，0.36 m 相当于 1.44 个前进动作（步长 0.25 m）。阈值不同，成功区域面积相差近八倍，两类任务的 SR 数字天然不可直接比。

判据还有一条效率侧的口径：ObjectNav-SPL 的参考最短路径算到距起点最近的实例。挑战页给出一个典型案例：起点附近就有 chair1，智能体却跑到远处找到 chair2，SR 记 1，SPL 的分母取到 chair1 的短路径。设最近实例的参考路径 l = 3.0 m、实际走的路径 p = 25.0 m，则该幕贡献 l/max(p, l) = 3.0/25.0 = 0.1200；SR 与 SPL 在这一幕上出现明显背离。第 003 讲将把可见性的几何构造、恰好 1.0 米的边界、遮挡情形的判定展开。

5. SR 与 SPL 的统一定位

评测共识文档（Anderson 等，2018）把导航性能分为两个轴：成功与效率。SR（成功率）只回答「是否到达」，SPL（成功加权路径长度）同时刻画成功与路径效率：

SR = (1 / N) Σi=1N Si Si ∈ {0, 1} 为第 i 幕的成功指示；N 为评测幕数
SPL = (1 / N) Σi=1N Si · li / max(pi, li) li 为到最近合法目标的参考最短路径；pi 为实际路径长度；max 保证单幕效率不超过 1

SPL 有两条可直接使用的性质。第一条是上界：单幕效率 li/max(pi, li) 不超过 1，失败幕贡献为 0，故 SPL ≤ SR ≤ 1。第二条是分解：

SPL = SR × ē,   ē = (1 / |W|) Σi∈W li / max(pi, li) W 为成功幕集合；ē 为成功幕的平均路径效率，失败幕在分解中已由 SR 承担

分解式是最实用的诊断工具：SPL 除以 SR 得到成功幕的平均效率，数值越小说明智能体成功时绕的路越多。用公开榜单实算（数据取自各年挑战页）：2020 ObjectNav 冠军 Arnold 的 SPL 0.10、SR 0.25，得 ē = 40.00%，即成功幕平均走了最优路径的约 2.5 倍；2021 ObjectNav 冠军 Red Rabbit 为 SPL 0.13、SR 0.30，ē = 43.33%；2022 ObjectNav 冠军 ByteBOT 为 SPL 0.35、SR 0.64，ē = 54.69%；2022 亚军 BadSeed 为 SPL 0.33、SR 0.65，ē = 50.77%。作为对照，2021 PointNav 榜首 inspir.ai 的 SPL 0.74、SR 0.96，ē = 77.08%；同年前列的 UCU MLab 为 SPL 0.72、SR 0.95，ē = 75.79%。

表中的规律值得记住：ObjectNav 的成功幕平均要多走一倍上下的路，因为搜索本质上是「先探后达」；PointNav 有坐标指引，成功幕接近最优。max(pi, li) 裁剪的意义在自定义评测器里更明显：若参考路径算错、算到更远的实例，pi 可能小于 li，裁剪把单幕效率压到 1，避免评测器因口径错误给出大于 1 的奖励。SoftSPL 对失败轨迹按比例计分，与 DTG 一起构成失败分析工具，留到第 005 讲。

挑战方以 SPL 作为主排序键，并在页面上声明：当 SPL 差异统计上不显著时，保留使用附加指标决定名次的权利。这句话与下一小节的统计噪声直接相关。

实算结果：SR = 5/6 = 0.8333，SPL = 2.2083/6 = 0.3681，SPL/SR = 0.4417，与逐幕成功效率的平均值一致。三个观察：第 4 幕失败，贡献记 0；第 6 幕虽然成功，但为找 2 米的近目标走了 30 米，单幕效率只有 0.0667，明显拉低 SPL；第 3 幕路径较直，0.8333 是全表最高。

第二个算例评估统计噪声。把 SR 看作二项比例，标准误为 sqrt(p(1−p)/N)。当 N = 1000、p = 0.64 时，标准误 0.0152，95% 置信区间半宽约 2.98 个百分点；当 N = 2000、p = 0.30 时，半宽约 2.01 个百分点。若要检出两个方案之间 2 个百分点的真实差异（p ≈ 0.3、80% 功效的近似样本量 16·p(1−p)/d²），需要约 8400 幕。2022 与 2023 挑战各评测 1000 幕，SR 差异在 3 个百分点以内难以分辨；SPL 的方差高于 SR，名次接近时的小差距需要谨慎解读。

第三个算例比较目标表示的信息尺度（设例，用于说明数量级）。按 224×224×3 的输入规格，目标图像有 150528 字节；坐标对按 ±10 米、1 厘米量化，每轴约 log22000 ≈ 10.97 比特，两轴合计 21.93 比特 ≈ 2.74 字节；6 类类别词为 log26 ≈ 2.585 比特。图像目标的信息量约为坐标对的 5.5 万倍，为类别词的 46.6 万倍。图像目标要求视觉编码器与视角不变的匹配能力，坐标与类别目标需要的是紧凑嵌入与空间先验，这是两条不同的技术路线。

第四个算例回到类别口径。MP3D 从 40 类保留到 21 类，保留率 52.50%，剔除率 47.50%；HM3D-Sem v0.1 用 120 个场景，按 80/20/20 划分，占比 66.67%/16.67%/16.67%；v0.2 扩展到 216 个场景，按 145/36/35 划分，占比 67.13%/16.67%/16.20%，场景规模是 v0.1 的 1.8 倍。类别集合与场景分布同时变化，跨版本比较必须同时标注。

7. 适用边界与失效模式

家族地图的使用边界集中在「可比性」三个字上，下面四条是最常见的越界方式。

  • 跨数据集比较：把 2020 ObjectNav 冠军的 SR 0.25（MP3D，21 类）与 2022 冠军的 SR 0.64（HM3D-Sem v0.1，6 类）并列，得出方法进步 39 个百分点的结论。两个数字分别是各自口径下的最优，数字差距混合了类别集合、场景来源、目标分布与评测协议的变化。
  • 跨版本比较：v0.1 与 v0.2 的场景数从 120 增至 216，2023 年还过滤掉跨楼层幕。同一方法在两个版本上的 SR 变化反映难度与数据分布的变化，需要分版本报告。
  • 跨传感器假设比较：PointNav 无 GPS+Compass 且带噪声，ObjectNav 有精确 GPS+Compass。把 ObjectNav 上训练的策略直接放到 PointNav 评测，得到的数字属于另一套任务。
  • 判据实现差异：自建评测器常把 oracle 可见性换成智能体视角可见，或把参考路径算到类别中心、最远实例。这两类改动会让 SR 与 SPL 同时失真，且与官方榜单不可比。

一条工程判据：报告任何 SR/SPL 数字时，同时给出任务、数据集与版本、类别数、传感器配置、停止阈值、参考路径口径六项信息，缺一项就标注为不可比。

4. 统一接口设计

四类任务可以共用一条策略循环，差异收敛到两个组件：目标适配器（GoalAdapter）与成功判定器（SuccessChecker）。前者把坐标、类别词或图像转成策略输入的目标描述子；后者在评测时用特权信息计算 ρ。指标累加器（MetricAccumulator）负责按幕记录 Si、li、pi 并输出 SR、SPL。四条实现要点：

  • 目标适配器只接触智能体可见的信息；成功判定器只接触场景标注。两者不得共享内部状态，避免训练时「看见答案」。
  • 参考路径 l 的终点由任务决定：PointNav 取目标坐标；ObjectNav 取最近实例；ImageNav 取最近目标视角。同一份评测代码用参数切换，避免复制出多份口径。
  • 动作接口与传感器配置以配置对象传入，环境工厂按任务和年份组装，保证「2021 ObjectNav」与「2023 ObjectNav」是两个可区分的实例。
  • 指标输出同时报告 SR、SPL 与 ē = SPL/SR，前两者回答不同问题，第三者用于诊断绕路程度。

与第 001 讲的差异点：001 建立了 ObjectNav 单任务的形式化与 POMDP 骨架，本讲把坐标系扩展到四类任务，加入传感器与目标形式两条轴，并把指标从定义推进到可分解的计算。下一讲把成功判据展开到几何边界，处理恰好 1.0 米、遮挡与可视线构造。

关键代码与解读

三段代码分别覆盖目标表示与成功判定、指标聚合、边界测试。语言为 Python 加 NumPy，接口按本课统一约定书写。

片段 1：目标表示与成功判定器

import numpy as np

class PointGoal:
    """PointNav 目标：相对起点的二维位移，单位米。"""
    def __init__(self, dx, dy):
        self.dx, self.dy = dx, dy        # 起点坐标系下的目标位移

class ObjectGoal:
    """ObjectNav 目标：类别词，命中任一实例即可。"""
    def __init__(self, category):
        self.category = category         # 例如 "chair"

class InstanceGoal:
    """ImageNav / InstanceImageNav：目标图像加实例编号。"""
    def __init__(self, image, instance_id=None):
        self.image = image               # H x W x 3 的 RGB 目标图像
        self.instance_id = instance_id   # 为 None 时按类别级判定

def rot2(yaw):
    """二维旋转矩阵：把起点坐标系的目标换算到世界坐标。"""
    c, s = np.cos(yaw), np.sin(yaw)
    return np.array([[c, -s], [s, c]])

def pointnav_success(goal, start_xy, start_yaw, stop_xy, radius=0.18):
    """PointNav 判据：停止点到目标的距离不超过 2 倍智能体半径。"""
    goal_xy = start_xy + rot2(start_yaw) @ np.array([goal.dx, goal.dy])
    return np.linalg.norm(stop_xy - goal_xy) <= 2 * radius

def objectnav_success(goal, stop_xy, instances, scene, stop_r=1.0):
    """ObjectNav 判据：1 米内且 oracle 可见，两者缺一不可。"""
    for v in instances:
        if v.category != goal.category:
            continue                      # 先按类别过滤候选实例
        near = np.linalg.norm(stop_xy - v.position) <= stop_r
        if near and scene.oracle_visible(v, stop_xy):
            return True                   # 判定失败时继续找下一个实例
    return False

解读：（1）四类任务的差异被压缩到目标类与判定函数两个位置，策略循环可以完全复用。（2）相对坐标经旋转矩阵换算到世界坐标，旋转方向与仿真器的朝向约定必须一致，写错会把目标镜像到错误一侧。（3）oracle 可见性由场景对象提供，属于评测侧特权接口，策略侧拿不到。（4）距离恰好等于阈值时判成功（≤ 比较），浮点误差可能让边界幕翻转，第 3 段代码专门测试这一点。

片段 2：SR 与 SPL 聚合

def sr_spl(records):
    """records: 每幕 (S_i, l_i, p_i)；l 取到最近合法目标的最短路径。"""
    n = len(records)
    sr = sum(s for s, _, _ in records) / n
    # 失败幕对 SPL 贡献为 0；max 把 p 小于 l 的口径异常截到效率 1
    spl = sum(s * l / max(p, l) for s, l, p in records) / n
    mean_eff = spl / sr if sr else 0.0    # 成功幕平均效率，诊断绕路程度
    return sr, spl, mean_eff

def check(sr, spl):
    """口径自检：SPL 不得超过 SR，违者说明参考路径或权重实现有误。"""
    assert 0.0 <= spl <= sr <= 1.0 + 1e-9, (sr, spl)

解读：（1）聚合只依赖三个标量，评测与分析代码可以共用同一实现。（2）max(p, l) 的裁剪针对参考路径口径错误时的异常值，正常评测中 p ≥ l 恒成立。（3）返回 ē 是把 SPL 与 SR 联系起来的诊断量：两份报告 SR 相同而 ē 差距大，说明路径效率是主要改进点。（4）断言 SPL ≤ SR 是最低成本的一致性测试，能让绝大多数指标实现错误在第一时间暴露。

片段 3：阈值与坐标系的边界测试

def test_threshold_and_frame():
    start_xy, yaw = np.array([0.0, 0.0]), np.pi / 2   # 起点朝北（yaw 为 90 度）
    goal = PointGoal(0.36, 0.0)                       # 目标在起点正前方 0.36 米
    # 旋转后世界坐标为 (0, 0.36)：停在起点，距离恰好等于阈值
    assert pointnav_success(goal, start_xy, yaw, start_xy)
    # 目标推远到 0.37 米：超过 0.36 米阈值，判定失败
    goal_far = PointGoal(0.37, 0.0)
    assert not pointnav_success(goal_far, start_xy, yaw, start_xy)
    # 浮点边界：十进制小数不精确，比较前应留容差或改比平方距离
    assert abs(np.linalg.norm(np.array([0.0, 0.36])) - 0.36) < 1e-12
    # 与 ObjectNav 判据对比：距目标 0.5 米处 PointNav 失败、1 米判据成功
    offset = np.array([0.0, 0.86])                    # 距目标 0.5 米的停止点
    assert not pointnav_success(goal, start_xy, yaw, offset)
    assert np.linalg.norm(offset - np.array([0.0, 0.36])) <= 1.0

解读：（1）第一组断言钉住判据的闭区间性质，恰好 0.36 米记成功，0.37 米记失败。（2）浮点例提醒边界幕的不确定性：智能体停在阈值附近时，评测环境的几何计算与自建实现的微小差异就可能翻转结果，报告数字时应意识到这类幕的存在。（3）最后一组对比说明阈值差异的实际后果：距目标 0.5 米的位置在 ObjectNav 判据下成功，在 PointNav 判据下失败，跨任务比较 SR 前必须先对齐判据。

常见坑

以下五条对应家族边界上最常见的失真与误读。

  • 跨数据集并排数字：把 MP3D 21 类的 SR 与 HM3D-Sem 6 类的 SR 放在同一张表里，得出方法大幅进步的结论。根因是类别集合、场景来源与难度同时变化。修复：同数据集同版本同切分对比；表格每行标注数据集、类别数与场景数。
  • 传感器假设漏标：在 ObjectNav 上做复现实验，配置里没有 GPS+Compass 或带了噪声，结果与榜单差距明显。根因是把传感器组合当作可选项。修复：SensorSpec 写进配置对象与日志，训练与评测共用；引用他人数字前核对传感器配置。
  • oracle 可见性缺失：自建评测只查 1 米距离，不查可视线；或反过来用智能体当前视角代替 oracle 判定。根因是把特权判据当作感知模块实现。修复：评测器单独实现可见性检查，使用场景几何与标注；用官方 minival 对照幕级结果。
  • 类别级与实例级混淆：在 2023 协议下按类别判定 ImageNav，同类多实例场景的成功率虚高；或把实例级要求应用到类别级设定，数字异常偏低。根因是目标规范中没有区分是否携带实例标识。修复：目标对象显式记录 instance_id；对照论文与挑战年份的定义。
  • SPL 分母口径错误：参考路径算到最远实例、类别中心或错误的图像视角。症状是 SPL 与官方榜单差距大，甚至出现 SPL 大于 SR。修复：按任务取最近合法目标；加 SPL ≤ SR 断言；用已公布榜单的 SR 与 SPL 反推 ē 做合理性检查。

  2. 对照 2020 与 2021 挑战页，列出 PointNav 与 ObjectNav 在传感器假设上的三点差异，并各写出一条对算法模块的影响。★
    提示
    差异：PointNav 无 GPS+Compass，ObjectNav 有；PointNav 注入致动与传感噪声，ObjectNav 无；PointNav 禁滑动碰撞，ObjectNav 为纯导航判定。影响：PointNav 需要在线定位或视觉里程计；ObjectNav 的收益主要来自语义探索与停止判定。
  3. 证明单幕效率 l/max(p, l) 不超过 1，据此推出 SPL ≤ SR，并写出 SPL = SR × ē 的分解过程；说明两处等号同时成立的条件。★★
    提示
    由 l ≤ max(p, l) 得单幕效率 ≤ 1；失败幕贡献为 0，把成功幕集合 W 提出即得分解。等号条件：全部幕成功（SR = 1）且每幕路径等于参考最短路径。
  4. 某场景中目标类别的实例数 m 分别为 2、4、8，策略无法区分同类实例时只能随机选择。计算实例级成功率的上界，并设计一个实验检验「外观匹配模块」是否真正提升实例级性能。★★
    提示
    上界为 1/m，依次为 0.5000、0.2500、0.1250。实验思路：固定导航模块与评测场景，构造同类实例外观相似度递增的若干组，对比有无匹配模块的实例级 SR；若匹配模块有效，两组差距应随相似度上升而扩大。
  5. 构造两个各四幕的评测场景，使 SR 与 SPL 给出相反的排序：场景 X 的成功幕多但每幕绕路严重，场景 Y 的成功幕少但路径接近最优。给出每幕的 (l, p, S)，计算两场景的 SR 与 SPL，并讨论榜单为何以 SPL 为主排序键、什么情况下应改报 SR。★★★
    提示
    取 X 为三幕 (8.0, 40.0, 1) 加一幕 (8.0, 40.0, 0)，得 SR 0.75、SPL 0.15；取 Y 为一幕 (8.0, 9.0, 1) 加三幕 (8.0, 9.0, 0)，得 SR 0.25、SPL 0.2222。SPL 同时惩罚失败与绕路，适合「找到且高效」的综合评价；当研究关注可达性、需要把其与效率分开评估时，或失败代价与绕路代价需要分开分析时，应成对报告 SR 与 SPL，并借助 DTG 定位失败原因。

小结

  • 四类任务共享 POMDP 加外部成功谓词的骨架，差异落在目标形式、观察与传感器、动作接口、成功判据四处。
  • 目标形式分四种：相对坐标（PointNav）、类别词（ObjectNav）、目标图像（ImageNav，粒度按论文或年份确认）、图像加实例标识（InstanceImageNav）。
  • 传感器假设属于任务身份：PointNav 自 2020 年起无 GPS+Compass 且带噪声，ObjectNav 与 ImageNav 使用无噪声 GPS+Compass；2023 起本体换为 Stretch 并引入连续动作。
  • SR 与 SPL 构成成功与效率两个轴；SPL ≤ SR，且 SPL = SR × ē，ē 为成功幕平均效率；实测榜单中 ObjectNav 的 ē 在 40% 至 55%，PointNav 约 76% 至 77%。
  • 对照表应固定六项标注：任务、数据集与版本、类别数、传感器配置、停止阈值、参考路径口径；缺失任何一项的数字视为不可比。
  • 下一讲进入成功判据的几何边界：恰好 1.0 米、遮挡与可视线构造，回答「停止位置合格」的精确含义。
