第 093 讲｜VLFM on Spot：办公楼真机

第 067 讲拆机制，第 068 讲读结果与替换表；本讲回到同一篇论文（Yokoyama 等，2023，ObjectNav 零样本语义导航，arXiv:2312.03275），做一次部署复盘，把「仿真里成立」到「办公楼里跑通」之间缺失的工程账补全。论文的真机证据是办公楼单层的定性演示：Boston Dynamics Spot 在无先验地图、无任务训练条件下搜索目标物体；执行接口用本体导航 API 替代训练了 25 亿步的 PointNav 策略；夹爪相机承担价值图与检测输入；单目深度估计模型 ZoeDepth 补足夹爪深度量程；机身深度相机生成占据图与前沿；四个模型同驻一台 16 GB 显存笔记本。本讲实算部署账（训练吞吐、步数预算、频率与显存），逐项审计演示证据能支持与不能支持的结论，并给出一套把演示升级为统计评测的最小实验设计，衔接第 096 讲的真机评测方法学。

  • 主题：真机部署复盘 / 价值图更新 / 执行接口替换 / 证据审计 / 单层限制

学习目标

  • 复述：说清真机系统的完整数据流，从机身深度到占据图与前沿，从夹爪 RGB 到价值图与检测，从目标轮廓到停止判据。
  • 会推导：写出置信度公式与加权更新式，分析光轴、视场边缘与重复观测三种情形的极限行为。
  • 会算：复算部署账，包括 PointNav 训练吞吐（25 亿步、256 个 worker、7 天）、单幕里程上限与模型驻留约束。
  • 会审计：列出定性演示支持的结论与缺口，并设计一套把演示升级为统计评测的最小实验协议。

背景与动机

零样本方法的承诺是「训练一个模块，到处部署」；承诺能否兑现，要看部署环节替换了哪些部件、每个替换带来什么误差、系统在真实办公楼里能跑多久。第 067 讲证明了价值图的机制成立，第 068 讲给出了仿真汇总与真机替换清单；本讲补的是第三层：把演示当作工程对象审计。论文真机部分明确是定性展示，没有给出成功率、路径效率或重复次数，这类证据在方法论上属于「可行性证据」，不能直接外推为性能结论。审计要做的工作是把「已证明什么、还缺什么」写成可执行的补测清单。

从课程结构看，本讲处在第五篇的中段：第 092 讲处理多技能编排，本讲处理单个搜索技能的真机化，第 094 讲换平台并处理多楼层，第 095 讲进入分层语言动作。把 VLFM 的真机部署讲透，也能为第 097 讲的工程栈全景提供组件级的接口依据。

核心原理

1. 三段式数据流

VLFM 的运行分三个阶段。初始化阶段：机器人原地旋转一整周，用深度观测把四周的障碍与已探索区域写入地图，同时为价值图写入初始视角的语义分数。探索阶段：占据地图的已探索区与未探索区边界构成前沿（frontier），每个前沿取中点作为候选航点；价值图对每个前沿打分，分数最高的前沿被选为下一个远距离目标；机器人朝该航点移动，边走边更新两张地图。目标导航阶段：一旦检测器发现目标实例，系统切换到目标航点，导航到物体上离机器人最近的点，进入成功半径后发出停止动作。三个阶段的切换条件只有两个：是否检出目标、地图是否还有前沿。若前沿耗尽而目标仍未检出，机器人直接停止，该 episode 记为失败。

这个结构的关键决定是把所有语义推理都压缩进一张二维栅格。占据图负责几何，价值图负责语义，两张图共享同一坐标系与分辨率；前沿既提供探索边界，也提供打分单元。与第 065 讲的纯文本排序范式相比，价值图避免了「先检测物体、再把物体写成文本、再让语言模型排序」的中间瓶颈，语义分数直接从图像与文本提示的相似度得到。

2. 价值图：语言得分如何落地

价值图与占据图同为俯视二维栅格，包含两个通道：语义价值通道存分数，置信度通道存该格被写入时的可信程度。语义分数的来源是 BLIP-2 图文匹配：对当前 RGB 图像与文本提示计算余弦相似度，提示模板为 “Seems like there is a <target_object> ahead.”，目标词替换为当前类别标签。分数写入地图前要做两步空间筛选（Yokoyama 等 2023，第 4.B 节）：先按相机位姿生成视场锥形掩码，再用深度图把掩码中被障碍遮挡的区域剔除。只有「相机看得见且不被挡」的格子获得新值。这个投影加剔除的步骤决定了分数的空间归属，是价值图与整图分类打分的关键差别。

置信度由像素与相机光轴的夹角决定，光轴处为 1，视场左右边缘为 0：

c = cos²( θ / (θfov/2) · π/2 )

同一格子被重复观测时，价值与置信度都做加权平均。价值取两轮置信度加权的均值，置信度取偏向高置信一方的形式：

vi,jnew = (ci,jcurr vi,jcurr + ci,jprev vi,jprev) / (ci,jcurr + ci,jprev)
ci,jnew = ((ci,jcurr)² + (ci,jprev)²) / (ci,jcurr + ci,jprev)

边界行为需要逐一核对。首次观测某格时 cprev = 0，两式退化为直接赋值，因此代码里不需要单独的「首见」分支，只要分母加一个极小量防止除零。两轮置信度相等且都取 0.5 时，价值等于两轮均值，置信度保持 0.5；一轮为 1、一轮为 0 时，价值完全取高置信轮的值，置信度回到 1，这正是「偏向高置信一方」的含义。语义相似度的值域是 [−1, 1]，更新与写入全程不能裁剪到非负区间，否则负相关区域被抬成 0，前沿排序会被破坏；需要裁剪的只有置信度通道。

3. 目标检测与目标航点

目标检测按类别路由（Yokoyama 等 2023，第 4.C 节）：COCO 类别用 YOLOv7，其余类别用开放词汇检测器 Grounding-DINO；检出后由 Mobile-SAM 从检测框提取轮廓，结合深度图在轮廓上取离机器人最近的点作为目标航点，放弃框中心，是为了让停止位置满足判据里的距离条件；只要停止时距目标实例不超过 1 m 即成功。检测器路由的原因在论文中写得直接：YOLOv7 在 COCO 类别上更准，开放词汇能力由另一条支路提供。这条设计影响部署：真机上也必须同时加载两套检测器，类别名称先与 COCO 清单比对再决定路由。

仿真中的执行使用 PointNav 策略：输入仅深度与相对位姿，输出离散动作（前进 0.25 m、左右转 30°、抬头与低头、停止），在 HM3D 训练集上用 VER 算法训练，4 张 GPU 各 64 个 worker（共 256 个），总步数 25 亿，耗时约 7 天。折算全局吞吐约每秒 4134 步；分摊到每个 worker 为 976.6 万步、约 16.15 步每秒，即每步墙钟约 61.9 ms。策略只吃深度不吃 RGB，因为 PointNav 不要求语义理解，几何信息足够。论文特别说明该策略可以整体替换，真机就没有使用它。

4. 真机部署配置

真机平台是 Boston Dynamics Spot。论文列出四组替换（Yokoyama 等 2023，第 6.C 节）：执行接口由 PointNav 策略换成本体导航 API，本体 API 能把机器人带到指定航点，前提是路径相对无障碍；价值图与检测输入换用夹爪相机，因为夹爪可以在搜索时对准可疑方向；目标深度因夹爪相机的深度量程不足，改用单目深度估计模型 ZoeDepth 生成近似深度；障碍与前沿使用机身深度相机，覆盖机身周围的地面与前方。初始化仍为原地旋转一周。所有模型（BLIP-2、GroundingDINO、MobileSAM、ZoeDepth）加载在一台配备 RTX 4090 MaxQ 移动 GPU（16 GB 显存）的笔记本上实时运行，部署场地是此前未见的办公楼单层，不使用任何先验地图。

只有一处替换改变了方法的数学结构：执行接口。价值图、置信度更新、前沿选择在真机上与仿真完全一致；其余替换都发生在感知接口上，影响的是分数与航点的质量。代价需要写清：本体 API 假设路径相对无障碍，动态障碍由本体栈处理；ZoeDepth 是估计值，目标航点可能带有可见误差；夹爪相机的安装位置决定了目标必须先进入夹爪视野，比仿真相机外参更受限。工程实践上，还需要一项论文未展开而部署必须做的工作：标定夹爪相机与机体的外参、对齐时间戳，并把夹爪视野中的目标点变换到机体坐标系再生成航点；外参误差会直接平移目标航点。

5. 单层限制与仿真结果参考

论文明确写出单层限制的根因：仿真里程计观测不含高度通道 z，导致跨楼层时无法把俯视地图与价值图按楼层重置；因此 VLFM 当前只支持单层 episode。量化影响为：HM3D 验证集 14.6% 的 episode、MP3D 验证集 9.6% 的 episode 需要走楼梯才能遇到目标，这些 episode 全部失败。这条限制把 VLFM 与第 094 讲的多楼层方法划成互补关系：单层方法在覆盖广度上占优，跨层必须另加楼层状态机与地图重置。

仿真结果用于确定真机部署的质量上限（论文表 I，验证集，ObjectNav 判据 1 m 与 500 步）：SPL / SR 在 Gibson 为 52.2 / 84.0，HM3D 为 30.4 / 52.5，MP3D 为 17.5 / 36.4。相对各数据集最强零样本基线：Gibson 对 SemUtil 为 SPL +11.7、SR +14.7；HM3D 对 ESC 为 +8.1、+13.3；MP3D 对 ESC 为 +3.3、+7.7。Gibson 与 MP3D 两行超过有监督方法，HM3D 的成功率低于 PIRLNav 11.6 个百分点，但 SPL 高 3.3。价值图更新消融显示：相对直接覆盖，置信度加权在三个数据集上带来 SR +7.9、+8.0、+4.7 个百分点；相对无权平均，增益收窄到 +1.0、+0.7、+1.4，说明重复观测的融合策略主要价值在「防止高置信读数被低置信读数冲掉」。

一个需要写进核对清单的细节：论文引言给出「相对此前最优 SPL 提升 12%、5%、3%」，而按表 I 与各自最强零样本基线复算的差值是 11.7、3.3、8.1 个百分点。引言口径与表格不一致，引用时应以表 I 为准并注明比较基线。这类核对属于第 004 讲建立的「指标口径纪律」在真机文献上的延伸。

关键代码与解读

三段代码对应部署复盘的三处核心：价值图更新、前沿与检测路由、部署看门狗。第一段按论文公式实现并补边界处理，第二段中前沿聚合算子为教学选择（论文未公布具体算子），第三段为教学化实现。

片段 1：置信度加权价值图更新

import numpy as np

def update_value_map(value, conf, obs_value, obs_conf, mask):
    """双通道价值图更新。
    value/conf：全图；obs_*：本帧观测；mask：可见且未被遮挡的格子。"""
    v_prev = value[mask]
    c_prev = conf[mask]
    v_curr = obs_value[mask]
    c_curr = obs_conf[mask]
    denom = c_curr + c_prev + 1e-9          # 首见时退化为直接赋值
    value[mask] = (c_curr * v_curr + c_prev * v_prev) / denom
    conf[mask] = (c_curr ** 2 + c_prev ** 2) / denom
    return value, conf

def first_seen(value, conf, obs_value, obs_conf, mask, conf_floor=1e-3):
    """可选的首见显式分支，用于日志区分新格与重见格。"""
    new = mask & (conf < conf_floor)
    value[new] = obs_value[new]
    conf[new] = obs_conf[new]
    return value, conf

解读：（1）更新顺序是先价值后置信度，两式都只读旧值；若先写置信度，价值更新的权重基数会被本轮修改，与论文公式不符。（2）obs_value 可能在 [−1, 1] 内取负，函数不对其裁剪；只有置信度天然落在 [0, 1]。（3）首见分支不是数学必需（cprev = 0 时公式等价），但保留一个显式函数便于日志与调试，也能把 conf_floor 以下的噪声格单独处理。

片段 2：前沿选择与检测路由

COCO_CLASSES = {"chair", "sofa", "bed", "toilet", "tv", "plant"}

def route_detector(target):
    """COCO 类别走 YOLOv7，其余类别走开放词汇检测器。"""
    return "yolov7" if target in COCO_CLASSES else "grounding_dino"

def frontier_value(frontier, value_map):
    """前沿打分：区域内价值的最大值。
    论文未公布聚合算子，此处为教学选择，复现时须固定并公开。"""
    cells = frontier["cells"]
    return float(value_map[cells[:, 0], cells[:, 1]].max())

def choose_frontier(frontiers, value_map):
    """选择价值最高的前沿；返回 None 表示地图已探尽。"""
    if not frontiers:
        return None
    scored = [(f, frontier_value(f, value_map)) for f in frontiers]
    return max(scored, key=lambda item: item[1])[0]

解读：（1）路由清单只需覆盖评测类别集，其余全部走开放词汇检测器；部署时把类别清单写成配置文件，避免改代码。（2）聚合取最大值会让「前沿里只要有一格高分」就入选，偏向激进探索；取均值更保守。两种口径在走廊与开放房间的表现不同，复现报告必须写明用了哪种。（3）选择函数对空前沿返回 None，主循环据此触发停止并记失败；把「探尽未找到」与「步数耗尽」分开统计，是后文失败分析的前提。

片段 3：部署看门狗（教学化）

class DeploymentGuard:
    """真机看门狗：频率、进度与资源三类检查。"""

    def __init__(self, min_hz=5.0, stall_steps=40,
                 max_steps=500, vram_limit_gb=15.0):
        self.min_hz = min_hz
        self.stall_steps = stall_steps
        self.max_steps = max_steps
        self.vram_limit_gb = vram_limit_gb
        self.no_progress = 0

    def check(self, obs_hz, vram_gb, step, moved):
        if obs_hz < self.min_hz:
            return "pause: sensor or model too slow"
        if vram_gb > self.vram_limit_gb:
            return "pause: vram near limit"
        if step >= self.max_steps:
            return "stop: step budget exhausted"
        self.no_progress = 0 if moved else self.no_progress + 1
        if self.no_progress >= self.stall_steps:
            return "replan: no progress detected"
        return "ok"

解读：（1）看门狗不参与算法，只做三类硬约束：观测频率反映模型是否跟上，显存上限 15 GB 留出安全余量，无进展计数触发重规划。三者都属于「部署时才会暴露、仿真里不存在」的问题。（2）进度判定用位移与地图增长择一或同时使用；只用位移会误杀原地旋转的初始化阶段，需在初始化阶段禁用该项。（3）返回字符串以区分暂停、停止与重规划三种处置，不用布尔值；真机日志按这三种处置分类，就是第 096 讲评测协议里的干预记录。

常见坑

  • 把定性演示当作成功率证据：症状是引用「Spot 办公楼实验」推断真机成功率与仿真同档。根因是论文真机部分没有统计口径。修复：把真机结论限定为集成可行性；按本讲的升级设计补重复与判据后再报数字。
  • 忽略单层限制：症状是复现时选择多层办公楼，结果大量 episode 卡在楼梯。根因是里程计缺高度通道，跨层时俯视地图无法按楼层重置，论文实测楼梯 episode 失败率 14.6%（HM3D）与 9.6%（MP3D）。修复：单层评测先行；多层需引入高度来源与楼层状态机。
  • 四模型同驻的显存与延迟被低估：症状是联跑时随机崩溃或控制步变慢。根因是 BLIP-2、GroundingDINO、MobileSAM、ZoeDepth 同时常驻，16 GB 是论文实测配置，余量有限。修复：部署前逐模块压测显存与单次前向耗时，明确分时加载策略，把延迟写进验收项。
  • 把估计深度当测距使用：症状是目标航点系统性偏近或偏远。根因是夹爪相机量程不足后改用 ZoeDepth 单目估计，米级误差会平移航点。修复：近距目标用测距传感器或双目复核；日志记录估计值与实际距离的偏差，按偏差范围调整停止判据的余量。
  • 前沿聚合与遮挡剔除口径不固定：症状是同一批场景复现出的排序差异大。根因是论文未公布前沿打分的聚合算子，且价值写入依赖遮挡剔除的正确性。修复：从候选算子（最大、均值、分位数）中选一个并公开，遮挡剔除用深度图逐格验证；初始化旋转不得跳过，否则价值图初始覆盖不完整。

练习与思考

  1. 复算 PointNav 训练账：25 亿步、256 个 worker、7 天，求全局吞吐、每 worker 步数、每 worker 步速与每步墙钟；再算单幕里程上限。★
    提示
    全局吞吐 2.5e9 / 604800 ≈ 4134 步/秒；每 worker 2.5e9 / 256 = 976.6 万步；每 worker 步速约 16.15 步/秒，每步约 61.9 ms。单幕上限 500 × 0.25 = 125 m。注意区分「每 worker 每步墙钟」与「系统整体单步延迟」，两者不可混用。
  2. 推导置信度更新的三种极限：首见（cprev = 0）、等置信重见（两轮均为 0.5）、极端重见（1 与 0 各一轮）；并说明为什么价值更新不能裁剪到非负区间。★★
    提示
    首见退化为直接赋值；等置信重见时价值取两轮均值、置信度保持 0.5；1 与 0 各一轮时价值完全取高置信轮、置信度回到 1。BLIP-2 余弦值域为 [−1, 1]，负值是「不相关」的有效信号；裁剪到非负会把负相关区域抬平，前沿排序因此失真。
  3. 把单幕预算从 500 步改为 250 步，预测「楼梯类」「大范围开放区」「近距目标」三类 episode 的失败顺序与 SPL 变化方向，并设计一个只跑 100 条 episode 的对照。★★
    提示
    预期先失败的是大范围开放区（里程上限 250 × 0.25 = 62.5 m），其次是需要楼梯的 episode（本就不支持），近距目标受影响最小；SPL 在成功样本上可能略升（路径短的样本占比提高）。对照：同场景、同起点、同种子，两档预算各跑同一批 100 条，记录失败原因分布与条件 SPL。
  4. 设计一份把办公楼演示升级为统计评测的最小协议：给出目标集合、起点分布、重复次数、成功判据、效率代理、日志字段与风险控制，并估算所需工时。★★★
    提示
    按本讲设计表的 6 + 2 类目标、3 个起点、每组合 5 次，共 120 条；判据为停止且距目标 1 m 内并人工核验；效率代理用完成时间与行走距离，参考下界由专家演示路径给出；日志含价值图快照、前沿决策、检测框、深度读数、终止原因与干预次数；风险控制含限速、急停、清场与玻璃面标注。工时按单条 10 分钟周转估算，加标定与部署约 2 天，合计约 3 天可完成一轮探索性评测。
  5. 为单层限制设计三条改造路线（高度来源、楼层面重置、楼梯检测），给出每条的代价与验证用例，并说明与第 094 讲 MFNP 层间状态机如何衔接。★★
    提示
    高度来源：接入气压计或本体高度估计，验证用例为跨层往返后的地图一致性；楼层面重置：按高度阈值切换两张地图，验证用例为楼梯口附近的误切率；楼梯检测：语义分割加楼梯通道，验证用例为同一场景内上下行各 3 次。衔接点是把「何时换层」交给 MFNP 的四因子分数，把「如何换层」交给单向楼梯约束与重置机制。

小结

  • 数据流三段：初始化旋转建图、前沿加价值图探索、检出目标后切换目标航点并停止；语义推理全部压缩进二维价值图的两个通道。
  • 价值图更新：置信度 c = cos²(θ/(θfov/2)·π/2)，价值与置信度按旧值加权平均；负值域不可裁剪，首见为公式特例；遮挡剔除决定分数写入哪些格子。
  • 仿真参考：SPL / SR 为 Gibson 52.2 / 84.0、HM3D 30.4 / 52.5、MP3D 17.5 / 36.4（论文表 I，1 m 与 500 步协议）；置信度加权相对直接覆盖带来 SR +7.9、+8.0、+4.7。
  • 真机部署：Spot、办公楼单层、无先验地图；本体 API 替代 PointNav，夹爪相机承担价值与检测输入，ZoeDepth 补深度，机身深度做障碍；四模型同驻 16 GB 笔记本。
  • 证据审计：演示支持集成可行性，不支持成功率；单层限制来自里程计缺高度通道，HM3D 14.6% 与 MP3D 9.6% 的楼梯 episode 失败。
