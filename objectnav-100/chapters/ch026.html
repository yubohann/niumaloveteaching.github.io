第二篇 · 模块化：地图·探索·常识

第 026 讲｜PointGoal 智能体复用

MOPA（Raychaudhuri 等，2024）把 ObjectNav 拆成检测、建图、探索、导航四个模块，导航模块直接复用预训练的 PointNav 策略。本讲给出复用的接口契约、实证收益、显式与隐性成本，以及它与分析式路径规划器的选择判据。

  • 主题：模块化流水线 / 导航模块 / 预训练复用 / 成本核算
  • 关键公式：gt = R(−ψt)(pgoal − pt)
  • 预计学时：60 分钟
  • 上一讲：第 025 讲 辅助任务+探索：端到端也能行

学习目标

  • 能写出「PointNav 策略作为局部导航器」的条件策略形式与相对目标接口，说清它与分析式路径规划器的结构差异。
  • 能复述 MOPA 的四模块数据流与关键参数（检测置信度 0.95、0.2 m 栅格、αexp = 50、uniform 10 m 采样），解释每个参数在流水线中的职责。
  • 能读并复算 MultiON 2.0 与 ObjectNav 2022 验证集上的导航模块对照数字，比较 PointNav 策略与 SPF、BFS、FMM 的成功率、SPL 与评测墙钟。
  • 能列出复用方案的显式成本（训练算力）与隐性成本（接口约束、观察假设、跨数据集迁移风险、失败重采样），并给出选择判据。
  • 能设计控制变量的对照实验，检验「复用 PointNav 优于分析式规划」这一结论在自家平台上的成立条件。

背景与动机

第 022 讲把模块化流水线解剖成四段：检测、建图、探索、导航，并留下一个问题：导航模块到底用什么实现。工程直觉通常给出两个答案，写一个分析式路径规划器（BFS、快速行进法 FMM、最短路径跟随 SPF），或者为 ObjectNav 重新训练一个导航策略。第 025 讲的端到端配方显示，从零训练导航能力动辄需要 25 亿帧量级的交互数据，代价高昂。

MOPA（Modular ObjectNav with PointGoal Agents，Raychaudhuri 等，WACV 2024；arXiv:2304.03696v3）给出第三个答案：把局部导航即「怎么走到 (x, y)」当作一个已经解决的子问题，直接复用公开的预训练 PointNav 策略，冻结参数不再训练。论文在 MultiON 2.0 与 2022 年 ObjectNav 挑战验证集上做了系统对照，发现复用的 PointNav 策略在成功率上超过分析式规划器，同时评测墙钟缩短到四分之一，并且整套 ObjectNav 流水线没有消费任何 ObjectNav 训练数据。

本讲解决三个问题：复用成立的条件是什么（接口契约）；收益与代价如何量化（成功率、SPL、墙钟、隐性依赖）；什么时候该换回规划器或自训策略。第 027、028 讲转向 PONI 的另一条路线：把「去哪找」当作监督学习问题，局部导航交给分析式规划器。两条路线构成第二篇中段的一组对照。

核心原理

1. 复用命题：把 ObjectNav 的局部导航化简为 PointNav 实例

模块化流水线在每一时刻已经决定了一个短期目标点 pgoal（目标物体的质心，或者一个探索采样点）。导航模块的任务是把「从当前位置走到 pgoal」执行完。这一步与 PointNav 的差别只在目标从何而来：PointNav 的坐标点由评测方给定，流水线的坐标点由探索或规划模块产出。局部导航的输入输出完全同构：

gt = R(−ψt)(pgoal − pt)，  at = πnav(ot, gt) pt 为智能体二维位置，ψt 为航向角，R 为二维旋转矩阵；gt 为机体系下的相对位移；ot 为深度观察与定位读数

公式的物理含义是：把世界坐标系里的目标点旋进智能体坐标系，交给一个只关心「目标在自身左前方多少米」的策略。各实现取相对位移 (Δx, Δy) 或相对极坐标 (ρ, φ)，量纲为米与弧度。MOPA 复用的策略接深度图、GPS+Compass 读数与相对目标，输出前向 0.25 m、左转 30°、右转 30°、停止四个离散动作，网络结构为 ResNet-50 深度编码器加 GPS+Compass 多层感知机，再接 LSTM 聚合历史，最后分演员与评论家两个头（Wijmans 等 2020 的 DD-PPO 框架；策略在 Ramakrishnan 等 2021 的 HM3D 场景上训练）。

与分析式规划器的结构差异值得逐条对照。规划器需要三样显式资产：占据图或碰撞图、全局搜索算法、路径跟踪控制器。PointNav 策略把这三样压进网络参数：避障从深度观测里隐式学习，搜索退化为朝向相对目标的反应式决策，「最近可通行点」的兜底也在训练中学到。代价是可解释性下降、行为受训练分布约束；收益是不再维护一张逐步更新的全局占据图，也不再需要手写膨胀与脱困规则。

2. MOPA 的四模块数据流

MOPA 的完整结构如下，四个模块依次衔接：

  • 检测 O：ObjectNav 实验用零样本检测器 Detic，置信度阈值 0.95；MultiON 实验用 Faster R-CNN 微调，圆柱目标另接 k 近邻分类颜色。
  • 建图 M：用深度通道把检测框投影到二维自顶向下栅格，每格 0.2 m，保存该位置最新的预测语义标签；物体一旦被看到就保留到 episode 结束。假设深度与里程计无噪声，与第 023 讲 SemExp 的建图口径一致。
  • 探索 E：目标尚未出现在图上时采样探索点。默认方案为 uniform：在 10 m 间隔的自顶向下网格上均匀采样；若 50 步（αexp = 50）内没有到达，丢弃该点重新采样。备选方案包括 Stubborn（3 m 局部网格）、Frontier 与 Active Neural SLAM 的已训练全局策略。
  • 规划 P：把语义图上同名标签的簇取质心作为目标点。论文报告质心优于从簇内随机取格。
  • 导航 N：把目标点的相对坐标交给冻结的 PointNav 策略，逐步输出动作；探索目标同样走这条通道。

这套结构有两个容易被忽略的设计。第一，探索与导航共用同一个底层策略，区分只发生在规划模块传入的目标点上，接口开销为零。第二，超时重采样是必需项：uniform 与 Stubborn 都可能选到尚未探索、实际不可达的位置，αexp 给每次尝试设了上界，让失败成为可以回退的局部事件。论文在 MultiON 2.0 的对照里，uniform 探索取得最高成功率，这部分结论在第 039 讲展开。

3. 实证 I：导航模块对照（MultiON 2.0）

MultiON 2.0 是论文构建的多物体导航数据集：800、30、70 个 HM3D 场景分别用于训练、验证与测试，训练集 800 万条 episode；每条 episode 含 n 个按序目标与 m = 8 − n 个干扰物，目标物体在场景内随机摆放，刻意不利用常识先验，以便单独研究探索与导航策略；训练集中插入物体之间的最小测地距离 0.6 m，验证与测试集提高到 1.3 m。智能体观察 256 × 256 的 RGB-D 与无噪声 GPS+Compass，离散动作为前向 0.25 m、左转 30°、右转 30°、found，时间上限 2500 步。

论文在 MultiON 2.0 测试集上固定检测（真值标签）与探索（uniform），只替换导航模块，五个随机种子取均值，标准差约 ±2：

6. 数值算例：预算、栅格与失败归因

第一组，时间预算。MultiON 的 episode 上限是 2500 步，ObjectNav 是 500 步；αexp = 50 步占 MultiON 预算的 2.0%，最坏情况下整段 episode 可以重采样 2500 / 50 = 50 次。10 m 网格上的均匀采样，任意位置到最近网格点的最远距离为半对角线 10 / √2 ≈ 7.07 m；全前向动作 50 步可走 50 × 0.25 = 12.5 m，覆盖率 7.07 / 12.5 ≈ 56.6%，余量留给转向与绕障。这说明 αexp 与网格尺寸存在搭配关系：网格调大而 αexp 不变，重采样率上升；网格调小而 αexp 不变，无效探索增多。以 40 m 见方的地图范围为例，10 m 网格给出 5 × 5 = 25 个候选探索点，单次重采样只是在这些点中抽取，实现代价为常数阶。

第二组，栅格与数据规模。0.2 m 栅格下，100 m² 的楼层对应 100 / 0.2² = 2500 个单元；MultiON 2.0 训练集 800 个场景、800 万条 episode，平均每场景 10000 条，比 MultiON 1.0 的场景数扩大 13.1 倍，episode 数扩大 2.62 倍。跨数据集评测需要这种规模才能暴露端到端模型的泛化缺口。

第三组，失败归因。PredSem 在 3ON 圆柱设置上的成功率约 50%，失败 episode 对应另外 50%。按论文给出的分解：全部 episode 中 40% 用尽 2500 步预算、10% 停在目标 1 m 之外；用尽预算的群体里，29% 从未发现目标、11% 发现目标却没能执行停止。两项合计：探索侧缺口 29%，导航侧缺口 21%（11% 加 10%），与 40% 加 10% 的失败总数一致。导航模块只解释约四成失败，探索与检测占大头，这个比例决定了优化的优先顺序。

7. 边界与失效条件

复用策略有成立条件，以下各项任一不满足都会削弱结论：观察假设必须对齐（深度通道、分辨率、GPS+Compass 的有无与噪声、动作集合与步长）；目标接口必须保持相对坐标（若模块内部改用别的坐标框架，策略输入分布立刻漂移）；碰撞模型必须一致（MOPA 的实验协议禁用滑动，与第 001 讲共识一致）；真机上 SPF 的真值导航网格不可得，BFS 与 FMM 的占据图还叠加了定位误差；动态障碍与人群没有进入策略的训练分布。使用前应把上述各项逐条核对，缺项按风险登记项处理，不能默认可行。

接口与数据结构方面，导航模块对外的契约只有三项：输入相对目标 (Δx, Δy)、输入观察（深度；有的策略另接 RGB）、输出离散动作。内部状态由策略自行维护（LSTM 隐状态），流水线不需要读写。语义图接口沿用 0.2 m 栅格与「最新标签优先」的更新规则；探索模块输出一个二维点，规划模块输出一个二维点，两者在导航模块看来完全同形。这种「点进动作出」的窄接口正是复用成立的关键。

设计决策：冻结优先

MOPA 全程冻结导航策略，不在 ObjectNav 或 MultiON 数据上做任何微调。理由是局部导航与目标语义在监督信号上解耦：走到 (x, y) 与「x, y 处有什么」可以分别学习。冻结换来零训练成本与稳定的行为，并把性能瓶颈清晰地暴露在检测与探索模块上。若传感器口径不同，优先做输入对齐（重采样分辨率、统一动作集），对齐无效再考虑微调。

设计决策：失败重采样是流水线的一部分

Uniform 采样会选到未探索区域中的不可达点，PointNav 策略不会「报错」，只会持续尝试。αexp = 50 步的上限把每次尝试成本限定在预算的 2% 以内，超时即弃点重采样。缺少这一步时，启发式探索在复杂场景中的失败会从局部事件升级为整段 episode 的失败。该机制对 uniform 与 Stubborn 尤其重要，学习型探索策略同样受益。

隐性成本清单

复用的账面上训练成本为零，隐性成本包括：策略的观察与动作假设约束流水线设计；GPS+Compass 假设在真机部署时需要替换为里程计并评估噪声；不可解释的局部行为给调试与安全认证带来困难；策略在训练分布外的障碍布局（狭窄通道、可移动物体）上行为不保证。选型时把这份清单与显式成本一起评估。

def relative_goal(agent_xy, yaw, goal_xy):
    """把地图坐标目标转成机体系相对位移，PointNav 策略的标准输入。"""
    dx = goal_xy[0] - agent_xy[0]
    dy = goal_xy[1] - agent_xy[1]
    c, s = math.cos(-yaw), math.sin(-yaw)      # 旋转 -yaw：世界系方向对齐到机体系
    return (c * dx - s * dy, s * dx + c * dy)

def navigate_to(env, policy, goal_xy, max_steps, reach_m=0.5):
    """冻结的 PointNav 策略执行走向目标点；超时返回 False 交给上层。"""
    for _ in range(max_steps):
        rel = relative_goal(env.agent_xy, env.yaw, goal_xy)
        action = policy(env.depth(), env.gps_compass(), rel)   # 四离散动作之一
        env.step(action)
        if env.distance_to(goal_xy) <= reach_m:                # 局部到达，切换目标
            return True
    return False   # alpha_exp 步内未到达：视为不可达点，丢弃重采样

解读：（1）旋转方向必须与坐标定义一致：若把相对位移写成 R(ψ)(pgoal − pt)，策略看到的「左右」会整体翻转，表现为朝反方向走或原地打转。（2）reach_m 取 0.5 m 一类的局部判据，与 ObjectNav 的 1 m 成功判据配合使用：导航模块负责把误差压到成功半径内，是否停靠由上层结合检测与可见性决定。（3）步数上限是接口的一部分：策略本身没有「放弃」动作，超时判定必须由调用方实现，否则不可达点会吞掉整段预算。（4）策略输入不含全局状态，调用方每次都要重新计算 rel，避免依赖策略内部记忆；LSTM 隐状态只承载历史观察。

片段 2：均匀探索与超时重采样

import numpy as np

GRID_M = 10.0       # uniform 采样网格间距，MOPA 验证最优
ALPHA_EXP = 50      # 单次探索尝试的步数上限，超时换点

def sample_uniform_goal(map_extent_m, rng):
    """在自顶向下地图上按 10 m 间隔均匀采样探索点。"""
    xs = np.arange(0.0, map_extent_m + 1e-6, GRID_M)
    return (float(rng.choice(xs)), float(rng.choice(xs)))

def explore_until_found(env, policy, semantic_map, rng):
    """目标未入图时反复探索；发现后返回目标质心交给规划模块。"""
    while not semantic_map.contains_goal():
        goal = sample_uniform_goal(env.map_extent_m, rng)
        reached = navigate_to(env, policy, goal, max_steps=ALPHA_EXP)
        if not reached:
            continue                    # 不可达点：直接丢弃，语义图不受影响
        if semantic_map.contains_goal():
            break                       # 探索途中发现目标，提前结束探索
    return semantic_map.goal_centroid()

解读：（1）采样在固定网格上进行，不使用连续空间，保证覆盖的可复现性；10 m 与 3 m 两个网格分别对应 uniform 与 Stubborn 的最优配置，说明网格尺度与探索策略绑定。（2）重采样不修改语义图、不计入惩罚，只消耗步数预算，实现上是纯局部操作。（3）「发现即停探索」的判据来自语义图：目标类别一旦出现，规划模块接管，导航目标从探索点切换为目标质心。（4）若目标质心不可达（例如检测噪声导致的孤立格），同一套超时机制会在导航阶段兜底，不需要额外分支。

片段 3：失败归因

def attribute_failure(ep):
    """给失败 episode 归因：探索瓶颈与导航瓶颈的修复手段不同。"""
    if ep["timed_out"]:
        # 用尽步数：再分「从未发现目标」与「发现却没能停靠」两种
        return "explore" if not ep["discovered"] else "navigate"
    if not ep["stop_valid"]:
        return "navigate"                # 发出了 STOP 但不在 1 m 成功区
    return "protocol"                    # 满足距离与可见性却判失败：查评测口径

解读：（1）归因的第一刀切在「是否用尽预算」，第二刀切在「是否发现目标」，因为前者指向探索，后者指向停靠策略。（2）MOPA 的实验数据显示导航侧只解释约四成失败，检测与探索占大头；优化前先做这份归因统计，避免把算力投向非瓶颈模块。（3）protocol 分支对应论文报告的真实现象：停止位置在目标 1 m 内且目标可见，仍因有效视点采样稀疏被判失败；这类样本要单独审查评测实现。（4）归因表建议按场景、类别、episode 长度分层统计，分层后的比例才是行动依据。

常见误区

  • 坐标框架混用：症状是策略持续朝错误方向移动、在目标附近来回摆动。根因是输入用了世界系坐标，或者旋转方向取反，策略输入分布与训练时不一致。修复：统一在机体系计算相对位移，用固定样例做单元测试（目标在正前方时 Δx 为正且 Δy 近零）。
  • 观察假设不对齐：症状是仿真里通过率尚可，换成另一套传感器配置后碰撞率猛增。根因是深度分辨率、视场、GPS+Compass 存在性、动作步长与训练配置不一致。修复：逐项对照策略的训练配置，优先重采样与统一动作集；仍不匹配才考虑微调，并为噪声水平做敏感性测试。
  • 缺少超时重采样：症状是整段 episode 停在某个角落反复撞墙，成功率骤降。根因是均匀采样选到未探索区域的不可达点，而调用方没有放弃机制。修复：实现 αexp 步上限与弃点逻辑，并把重采样次数计入日志，异常升高说明网格或场景尺度设置不当。
  • 检测阈值过低：症状是智能体反复走向不存在的目标质心，探索范围收缩。根因是低置信度检测进入语义图，簇质心被拉向噪声位置。修复：提高阈值（MOPA 用 0.95），对簇做尺寸与一致性过滤，并按第 029 讲的方法评估噪声传播。
  • 评测口径误读：症状是自测复现值与论文对不上，轨迹看起来合理却判失败。根因是成功区有效视点的采样密度、停止容差、可见性路线与论文实现不同。修复：冻结评测器版本，用固定 episode 做回归测试；把谓词判定函数与论文描述逐条核对后再比较数字。

小结

  • 复用命题：局部导航的输入输出与 PointNav 同构，把地图目标旋进机体系即可交给冻结策略，避障与搜索被压进网络参数。
  • MOPA 四模块为检测、0.2 m 语义建图、10 m 网格 uniform 探索（αexp = 50）、PointNav 导航；探索与导航共用同一底层策略。
  • 实证：MultiON 2.0 上 PointNav 成功率达 FMM 的 4.50 倍、BFS 的 3.86 倍，评测墙钟为两者的四分之一；SPF 的 SPL 优势来自真值导航网格。
  • ObjectNav 2022 验证集上，检测器把成功率从真值的 64% 压到 Detic 的 30%；复用方案不消费 ObjectNav 训练数据即可超过同检测条件的模块化对照。
  • 跨数据集证据：三个端到端模型换到 HM3D 后成功率落在 0.3% 至 0.5% 区间，复用 PointNav 保持 38%，两者相差约 95 倍，说明局部导航子技能的可迁移性。
  • 失败归因显示导航侧只解释约四成失败，检测与探索占大头；下一讲转入 PONI，看「去哪找」如何改造成监督学习问题。
