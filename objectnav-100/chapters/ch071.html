第四篇 · 开放词汇与大模型

第 071 讲｜ConceptGraphs：开放词汇 3D 图

第 069 至 070 讲的 SG-Nav 在仿真里维护在线 3D 场景图做分层推理，但检测类别与节点描述仍受预设集合约束。本讲读 ConceptGraphs（Gu 等 2023，arXiv:2309.16650）：用类无关分割（Class-Agnostic Segmentation，SAM）、CLIP 特征、LLaVA 描述与 GPT-4 关系推理，从 RGB-D 序列增量构建开放词汇 3D 场景图；物体是带点云与语义特征的节点，空间关系是边。在 Replica 的 7 个场景上，人工评测给出节点描述精度 0.71、边关系精度 0.88；开放词汇分割 mAcc 40.63；文本检索覆盖描述、可供性与否定三类查询；真机实验含 Jackal 轮式平台与 Spot 机械臂。本讲聚焦图结构设计与 LLM 规划消费方式，为第 072 至 073 讲的实例记忆与终身基准打底。

  • 主题：开放词汇 3D 场景图 / 对象级建图 / LLM 任务规划
  • 关键公式：φ(i,j) = φsem(i,j) + φgeo(i,j)；f ← (n·f + fnew) / (n + 1)
  • 预计学时：75 分钟
  • 前置章节：第 070 讲（SG-Nav II：re-perception 纠错）

学习目标

  • 会推导：对象关联分数 φ 的两项构成、取值范围［0, 2］与阈值 δsim = 1.1 的判定含义，能对给定 φsem 与 φgeo 算出是否关联。
  • 会实现：增量式对象建图的核心循环（分割、投影、关联、融合、描述、建边），理解贪心关联与滑动平均融合的代价与收益。
  • 会算：稠密逐点特征与节点级特征的存储量级差，生成树剪枝前后的边数，以及文本检索三项指标的增量。
  • 会判断：人工评测的节点精度、边精度与自动分割指标的口径区别；LLM 检索在描述、可供性、否定三类查询上的强弱分布。
  • 会设计：把场景图序列化成 LLM 可消费的结构（节点 JSON、边关系标签），并处理上下文长度上限与动态更新需求。

背景与动机

第 067 至 068 讲的 VLFM 用语言价值图给前沿打分，第 069 至 070 讲的 SG-Nav 用在线场景图加分层推理纠错，两者都依赖闭集检测与预设的语义类别。一旦任务换成“找那本放在咖啡桌上的白皮书”这类需要实例分辨与开放词汇的查询，闭集表示立刻失效。另一条路线是把视觉语言大模型的特征逐点投射到 3D 地图，形成稠密特征场；这类表示语义丰富，但每个点都存一份特征，内存随场景与时长线性增长，并且点与点之间没有结构，物体移动或消失时无法做局部更新，也不便于任务规划。

ConceptGraphs 的回答是对象级结构化：把场景压缩成物体节点与关系边，语义特征挂在节点上，关系用语言模型推断。这样既能处理训练时未见的类别，又能在下游把图序列化为文本交给大语言模型（Large Language Model，LLM）做查询与规划。对 ObjectNav 而言，这条路线回答了三个问题：开放词汇的场景表示长什么样、如何在线维护、下游导航与操作如何消费它。第 072 与 073 讲的 GOAT 系统与 GOAT-Bench 用的实例级记忆，正是这种对象化思路在真机与基准上的延续。

核心原理

1. 表示：为什么把地图换成图

设机器人收到一系列带位姿的 RGB-D 观测 I = {I1, …, It}。概念图定义为 Mt = ⟨Ot, Et⟩，其中 Ot = {oj}j=1…J 是物体节点集合，Et = {ek} 是关系边集合。每个节点 oj 由两部分描述：3D 点云 pj（几何）与单位化的语义特征向量 fj（视觉语言嵌入，取 CLIP 图像编码器）。边 ek 连接两个节点并携带关系标签，例如“a 在 b 上”“b 在 a 内”。

与逐点特征表示相比，节点级特征的存储量可以缩小到万分之一量级。取单位置编码 512 维、半精度（2 字节）的算例：一百万个点各存一份特征需要 1,024 × 1,024 × 512 × 2 = 1,073,741,824 字节，恰为 1.00 GiB；若同一场景压缩成 100 个节点，则只需 100 × 512 × 2 = 102,400 字节，即 100 KiB，两者相差 10,485.76 倍。这条量级差决定了 3D 语义表示能否扩展到“长时间、多房间”的场景：稠密表示的内存随观测帧数累加，节点表示的内存随物体数增长，而室内场景的物体数量远小于像素与体素数量。

Ddense / Dgraph = (N · d · b) / (J · d · b) = N / J = 1,048,576 / 100 = 10,485.76

结构化的第二个收益是关系。稠密特征场只能回答“这个点像什么”，回答不了“杯子和桌子是什么关系”；而任务的规划层往往需要关系，例如“把水杯放到厨房台面上”。第三是局部更新：节点与边可以增删改，物体被移动时只需重投影受影响的节点；稠密特征场则要做整段重映射。代价是引入分割、关联、描述多个模块，每个模块的错误都会向下游传播，这一点在边界一节展开。

2. 建图管线：六步流水线

对每一帧 It，管线执行以下步骤（Gu 等 2023，第 II 节）：

步骤输入处理默认配置输出
类无关分割RGB 图分割一切模型（Segment Anything Model，SAM）产生候选掩码SAM；无类别标签掩码集合 {mt,i}
特征提取RGB 图与掩码CLIP 图像编码器对掩码区域提特征CLIP；单位化视觉描述子 ft,i
投影与去噪掩码、深度、位姿反投影到点云，DBSCAN 去离群点，变换到地图系DBSCAN点云 pt,i
多视图关联新检测与已有节点几何相似度加语义相似度，贪心取最高分，低于阈值则新建δnn = 2.5 cm，δsim = 1.1匹配结果或无匹配
节点融合匹配到的节点与新检测特征滑动平均，点云并集后体素下采样体素 2.5 cm更新后的节点
描述与建边全部节点与视图LLaVA 生成描述，GPT-4 汇总；IoU 矩阵做生成树剪枝，LLM 标注关系每节点最多 10 个视图图 MT

论文另给一个检测器变体 ConceptGraphs-Detector（CG-D）：用 RAM 标注图像中的类别集合，用 Grounding DINO 出框，替代 SAM 的类无关分割。两条路线共享后续的关联、融合与建边逻辑，区别只在候选物体的产生方式，这一设计让系统可以按算力与场景调整前端。

3. 关联评分：几何相似度与语义相似度相加

新检测 ⟨pt,i, ft,i⟩ 与已有节点 ⟨po_j, fo_j⟩ 的几何相似度定义为近邻比例：新点云中能在旧点云 δnn 距离内找到最近邻的点所占比例。语义相似度把余弦相似度归一化到［0, 1］：

φgeo(i,j) = nnratio(pt,i, po_j; δnn)，δnn = 2.5 cm
φsem(i,j) = ft,iT fo_j / 2 + 1/2 ∈ ［0, 1］
φ(i,j) = φsem(i,j) + φgeo(i,j) ∈ ［0, 2］；当且仅当 maxj φ(i,j) ≥ δsim = 1.1 时接受关联

对每个新检测，只在空间上有部分重叠的已有节点里搜索，取 φ 最大的节点；若最高分低于 1.1，则实例化新节点。贪心策略是论文的工程选择：他们比较过匈牙利算法等最优分配，结论是更慢而提升极小。阈值 1.1 的直观含义是“两项都要及格”：只靠语义（φsem = 1.0）只得到 1.0，低于阈值；只靠几何重叠（φgeo = 1.0）同样不够。下表给出四组算例。

φsemφgeoφ 总和是否关联与阈值之差情形解释
0.850.301.15是+0.05语义相近且几何有重叠，常见于同一物体的新视角
0.900.211.11是+0.01语义很强、重叠较少，边界附近，检查特征质量
0.600.350.95否−0.15邻近的同类不同实例，应新建节点
0.550.501.05否−0.05几何重叠较多但语义不符，检查是否遮挡或错误分割

算例中 φsem = 0.85 对应余弦相似度 0.70（由 0.85 × 2 − 1 反推），φsem = 0.90 对应余弦 0.80。读数时把两项分开记录，否则阈值调参无从下手。

4. 节点融合：滑动平均与点云合并

关联成功后，节点特征按已关联检测数 n 做滑动平均，点云取并集后体素下采样：

fo_j ← (no_j · fo_j + ft,i) / (no_j + 1)；po_j ← downsample(po_j ∪ pt,i)

滑动平均意味着单个新检测对旧特征的权重是 1 / (n + 1)。n = 4 时新检测权重 0.200，n = 9 时降到 0.100：观察越充分的物体，外观特征越稳定，单个噪声视图的影响越小。这一性质对遮挡与运动模糊尤其重要；反过来，若物体外观随时间真实变化（例如台面被清空），旧特征权重过高会拖慢适应，这一项要靠检测与关联环节的更新来处理，特征融合本身不会自适应。

5. 描述与建边：语言模型负责“说不清”的部分

建图完成后，每个节点取贡献有效点最多的最多 10 个视图，用 LLaVA-7B 逐视图生成描述，提示词固定为“描述图像中央的物体”；再把 10 条初始描述交给 GPT-4 汇总成一个连贯的对象标签与一句话描述，GPT-4 还可以把疑似错误检测标为无效。这一步把“同类实例”升级为可区分的语言标签，例如“带白色花纹的花瓶”。

边由两步生成。先对节点两两计算 3D 包围盒交并比（Intersection over Union，IoU），得到稠密相似度矩阵；再对该矩阵做生成树剪枝，只保留 J − 1 条边（J 为节点数），其余边删除。剪枝力度可用算例看清：某场景 54 个有效物体对应 54 × 53 / 2 = 1,431 个节点对，生成树只保留 53 条边，保留率 3.70%，剪掉 96.30%；把节点数放大到 110 的算例中，5,995 个节点对只保留 109 条边，保留率 1.82%。然后对生成树的每条边，把两个节点的描述与 3D 位置交给 LLM，让它输出关系标签及理由，例如“a on b”“b in a”，也可以给出“背包可能收纳在衣柜里”这类开放词汇关系。

6. 规划消费：把图变成 LLM 的输入

下游任务的接口非常直接：把每个节点序列化为 JSON 项，含 id、包围盒尺寸 bbox_extent、包围盒中心 bbox_center、对象标签 object_tag、一句话描述 caption；把整张列表与用户查询一起交给 GPT-4（实验用 gpt-4-0613，上下文 8K token），要求返回结构化字段 inferred_query、relevant_objects、query_achievable、final_relevant_objects 与 explanation。论文同时验证了更长上下文的 Claude-2（32K token）可用。拿到 final_relevant_objects 后，取出节点的 3D 位姿，交给抓取或导航流水线执行。

三类查询的对比最能说明“图 + LLM”的消费特征。下表为 Replica 与 REAL Lab 场景上的 top-1 检索率（R@1，Gu 等 2023，表 III）：

7. 实验读数与失效模式

图质量在 Replica 的 7 个场景（room0 至 room2、office0 至 office3）上由人工评测给出。节点精度定义为“节点描述被三名评测者中至少两人判为正确”的比例，CG 平均 0.71，CG-D 平均 0.61；边精度即空间关系判对的平均比例，CG 为 0.88，CG-D 为 0.91；有效物体数每场景 23 到 60 个，重复检测 0 到 5 个（Gu 等 2023，表 I）。两个变体的对位成绩值得玩味：检测器变体的边更准，但节点描述更差，说明瓶颈主要在描述来源与候选质量的不同组合，不取决于单一模块的绝对优劣。

失效模式有四类：其一，LLaVA 描述错误直接拉低节点精度，节点误差率约 0.29；其二，细小或薄片物体漏检与重复检测，重复数每场景 0 到 5 个，关键物体被漏掉会直接导致规划失败；其三，建图与查询都要调用 LVLM 与专有 LLM，推理成本可观，论文把它列为系统局限；其四，图默认静态，未内建时序推理，物体移动后依赖下游的定位与重映射实验来补救。引用这些数字时，必须同时给出评测方式（人工或自动）、数据集与其版本。

实现思路与设计

把系统拆成可替换的模块后，每个设计点都能给出选择判据。下表汇总论文的选择与替代方案：

决策点论文选择替代方案与代价判据
候选物体来源SAM 类无关分割（CG）RAM 加 Grounding DINO（CG-D）：边精度略升，节点精度下降要跨类别泛化用 CG；要扩到属性框用 CG-D
语义特征CLIP 图像编码器DINO 等自监督特征：语义弱、几何强查询以语言驱动时保留 CLIP
关联分配贪心取最高分匈牙利最优分配：更慢，提升极小在线场景优先吞吐
关联阈值δsim = 1.1（两项和）调高减少错误合并、增加重复节点；调低相反按重复检测与漏检的代价权衡
视图预算每节点最多 10 个视图送描述增加视图提描述鲁棒性，推理成本线性增长描述精度与 LLM 调用成本的折中
规划器GPT-4（8K token）Claude-2（32K）验证可用；本地模型省成本场景图文本长度决定上下文需求

接口层面，节点对下游只暴露五元组：唯一 id、包围盒尺寸、包围盒中心、对象标签、一句话描述。这五元组是感知与规划之间的稳定契约：感知侧可以替换分割与描述模型，规划侧可以替换 LLM，只要契约不变，导航与抓取流水线不用改。与第 069 至 070 讲的 SG-Nav 相比，本讲的差异有三点：类别来源从闭集检测改为类无关掩码加 CLIP，节点语义从类别标签改为多视图语言描述，规划从分层链式推理改为整图序列化后交给通用 LLM。

在线维护的工程边界也要写清楚。稠密特征场更新是“重投影加平均”，图更新的粒度是节点：关联失败会新建重复节点，关联错误会把两个物体合并。两个错误方向不对称：重复节点让 LLM 看到冗余信息，通常不致命；错误合并会让两个物体的点云与特征混合，污染描述并误导规划。因此工程上宁可阈值略高、保留部分重复节点，也不要让不同实例过早合并。论文补充材料也指出，探索阶段用固定阈值匹配容易漏真、后探索阶段改用最高分选择，成功率更高。

关键代码与解读

三段代码对应建图管线的三个关键环节：多视图关联与融合、生成树建边、LLM 消费接口。代码为示意实现，模块接口与论文口径一致。

片段 1：关联评分与节点融合

import numpy as np

def nn_ratio(p_new, p_old, delta=0.025):
    """几何相似度：新点云在旧点云 delta 内有最近邻的点占比。"""
    if len(p_new) == 0 or len(p_old) == 0:
        return 0.0
    d2 = ((p_new[:, None, :] - p_old[None, :, :]) ** 2).sum(-1)
    return float((d2.min(axis=1) <= delta ** 2).mean())

def associate(det_cloud, det_feat, objects, delta_sim=1.1, delta_nn=0.025):
    """为单帧新检测选匹配节点；无匹配返回 None，由调用方新建节点。"""
    best_id, best_phi = None, -1.0
    for obj in objects:
        if not overlaps(obj.points, det_cloud):
            continue                                # 无空间重叠直接跳过
        phi_geo = nn_ratio(det_cloud, obj.points, delta_nn)
        phi_sem = float(det_feat @ obj.feat) / 2.0 + 0.5
        phi = phi_sem + phi_geo                     # 两项之和，范围 [0, 2]
        if phi > best_phi:
            best_id, best_phi = obj.obj_id, phi
    if best_phi < delta_sim:
        return None
    return best_id

def fuse(obj, det_cloud, det_feat, voxel=0.025):
    """融合：特征滑动平均，点云并集后体素下采样。"""
    n = obj.n_views
    obj.feat = (n * obj.feat + det_feat) / (n + 1.0)
    merged = np.concatenate([obj.points, det_cloud], axis=0)
    obj.points = voxel_downsample(merged, size=voxel)
    obj.n_views = n + 1
    return obj

解读：（1）先做重叠预筛再算精确相似度，避免对全场景节点做点云最近邻，这是在线可用的关键；（2）φsem 的“除以 2 加 1/2”把余弦从［−1, 1］映射到［0, 1］，与 φgeo 同量纲后才能直接相加；（3）阈值判断放在全部候选比较之后，贪心且与遍历顺序无关；（4）融合用已关联次数 n 做滑动平均，新检测权重为 1/(n+1)，后续第 072 讲的实例记忆同样遵循“越看越稳”的更新哲学。

片段 2：从节点集合到生成树边集

import itertools

def bbox_iou(a, b):
    """两个轴对齐包围盒的 3D 交并比，作为连边权重。"""
    lo = np.maximum(a.min(axis=0), b.min(axis=0))
    hi = np.minimum(a.max(axis=0), b.max(axis=0))
    inter = float(np.prod(np.clip(hi - lo, 0.0, None)))
    va = float(np.prod(a.max(axis=0) - a.min(axis=0)))
    vb = float(np.prod(b.max(axis=0) - b.min(axis=0)))
    return inter / max(va + vb - inter, 1e-9)

def spanning_tree_edges(objects):
    """Kruskal 最大生成树：密图边数为 J(J-1)/2，剪枝后只剩 J-1 条。"""
    edges = []
    for i, j in itertools.combinations(range(len(objects)), 2):
        w = bbox_iou(objects[i].bbox, objects[j].bbox)
        if w > 0.0:
            edges.append((w, i, j))
    edges.sort(reverse=True)
    parent = list(range(len(objects)))

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    mst = []
    for w, i, j in edges:
        ri, rj = find(i), find(j)
        if ri != rj:
            parent[ri] = rj
            mst.append((i, j, w))
    return mst

def label_edges(objects, mst, call_llm):
    """对生成树每条边询问关系标签，输出开放词汇的边集合。"""
    labeled = []
    for i, j, _ in mst:
        prompt = "物体 A：%s；物体 B：%s。给出二者的空间关系标签与理由。" % (
            objects[i].caption, objects[j].caption)
        labeled.append((i, j, call_llm(prompt)))
    return labeled

解读：（1）IoU 密图是全连接近似，J 增大时边数按平方增长，生成树把它压到 J − 1 条，54 个节点时保留率 3.70%，110 个节点时 1.82%，这是图表示可扩展性的来源；（2）相似度高于 0 才进入候选，实际实现中可加下限过滤明显不相邻的物体对；（3）关系标签交给 LLM 生成，跳过闭集分类器，因此可以产出“可能收纳在”这类训练时未见的关系词，代价是每条边一次推理调用；（4）边集剪枝只保证连通与稀疏，不保证语义上最重要，工程上可对 LLM 输出做人工抽查。

片段 3：场景图序列化与 LLM 查询接口

import json

def serialize_scene(objects):
    """节点序列化为 JSON 列表：五字段契约，控制字符预算。"""
    rows = []
    for obj in objects:
        rows.append({
            "id": obj.obj_id,
            "bbox_extent": [round(float(v), 2) for v in obj.bbox_size],
            "bbox_center": [round(float(v), 2) for v in obj.bbox_center],
            "object_tag": obj.tag,
            "caption": obj.caption,
        })
    return rows

PLANNER_SYS = (
    "输入是一个 3D 场景的 JSON 列表，每项含 id、bbox_extent、bbox_center、"
    "object_tag 与 caption。按用户查询返回 JSON：inferred_query、"
    "relevant_objects、query_achievable、final_relevant_objects、explanation。"
)

def plan(scene_rows, query, call_llm, char_budget=24000):
    """字符预算不足时按空间分块查询，再按候选分数全局重排。"""
    text = json.dumps(scene_rows, ensure_ascii=False)
    if len(text) <= char_budget:
        return call_llm(PLANNER_SYS, text, query)
    chunks = spatial_chunk(scene_rows, limit=char_budget // 2)
    hits = [call_llm(PLANNER_SYS, json.dumps(c, ensure_ascii=False), query)
            for c in chunks]
    return rerank_by_scores(query, hits)

解读：（1）五字段契约把感知输出与规划输入解耦，序列化时保留小数位控制文本长度；（2）论文用 8K token 上下文，本示意用字符预算近似，上线前应按实际模型的分词器换算；（3）大场景必需分块与重排，否则列表被截断，LLM 只在残缺场景上推理；（4）查询返回 final_relevant_objects 的 id 列表，调用方据此取 3D 位姿执行导航或抓取，语言推理与几何执行在此分界。

常见误区

  • 把 δsim = 1.1 当作余弦阈值：症状是阈值怎么调都效果异常，新节点大量产生或物体被错误合并。根因是 φ 为两项之和，取值范围［0, 2］，1.1 与余弦相似度不同量纲。修复：分别记录 φsem 与 φgeo 的分布，按两项各自的物理含义调参。
  • 按点存特征：症状是长场景下内存或显存线性上涨。根因是把 CLIP 特征逐点投射进地图。修复：使用节点级特征与关系边；确需稠密特征时做降维与量化，并把它当作另一条技术路线评测，不要在对象图上混用。
  • 节点描述错误向下游传播：症状是 LLM 规划自信地选错物体。根因是 LLaVA 的视图描述不稳定，汇总后的节点描述精度约 0.71。修复：每节点取多视图描述并做 LLM 汇总，关键任务前用当前观测图像做一次验证，必要时提供候选重排，避免只给单点答案。
  • 把人工评测精度与自动指标混谈：症状是用节点 0.71 与分割 mAcc 40.63 直接比较不同系统。根因是评测协议不同：前者是三名评测者多数表决的语义正确率，后者是点级类别指标。修复：引用时标注评测方式、场景集合与人数；跨论文比较只选同协议数字。
  • 图建好就冻结：症状是物体被移动后机器人反复导航到旧位置。根因是系统默认静态建图，没有时序更新机制。修复：对近期观察节点做重投影更新，物体消失时删除节点，物体移动时以新位置重建节点；论文的粒子滤波定位与重映射实验给出了一个可参考的更新回路。
  • 忽略 LLM 调用的成本与上下文上限：症状是评测单场景耗时远超预期，或大场景文本被截断后规划质量骤降。根因是建图描述与查询都依赖大模型，且 GPT-4 上下文为 8K token。修复：统计每场景的 LLM 调用次数与 token 数，设置分块与缓存策略，把成本列为部署约束的一部分。

小结

  • 表示：概念图 M = ⟨O, E⟩，节点为带点云与 CLIP 特征的物体，边为开放词汇空间关系；相比逐点特征，100 个节点的语义特征（100 KiB）比百万点的逐点特征（1.00 GiB）小 10,485.76 倍。
  • 建图：SAM 类无关分割、CLIP 特征、2.5 cm 体素去噪、φ = φsem + φgeo 匹配（δsim = 1.1）、按已关联次数滑动平均融合。
  • 语言层：每节点最多 10 视图经 LLaVA-7B 描述、GPT-4 汇总；IoU 密图经生成树剪枝到 J − 1 条边（54 节点时保留 3.70%），再由 LLM 标注开放词汇关系。
