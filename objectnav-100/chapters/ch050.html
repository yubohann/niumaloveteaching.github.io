第三篇 · 端到端与配方

第 050 讲｜演示来源之争

第 049 讲的 PirlNav 配方把行为克隆（Behavior Cloning，BC）与强化学习（Reinforcement Learning，RL）拼成两阶段，但人类演示按人时计价：HM3D 上 77k 条约 2,378 人时。自动生成的演示几乎只花算力，能否替换人类演示，是这条路线最关键的成本问题。本讲围绕 Ramrakhya 等（2023，PIRLNav，ObjectNav）的来源对照实验，拆解最短路径、前沿探索与人类演示三类数据：步数预算配平下 BC 成功率为 6.4% / 44.9% / 64.1%；控制 BC 起点后微调成功率为 43.6% / 51.3% / 66.1%；在针对人类演示构造的对抗子集上，人类演示从 0% 出发微调后反超另两类来源。结论指向一个机制判断：人类演示携带了任务特定的搜索行为。

  • 主题：演示来源 / 模仿差距 / 对照实验设计
  • 关键公式：ΔSR = SR(RL) − SR(BC)
  • 预计学时：75 分钟
  • 前置章节：第 049 讲（PirlNav：BC→RL 两阶段）

学习目标

  • 会推导：从状态访问分布与特权信息两个角度写出模仿差距（imitation gap）的成立条件，解释最短路径演示为何训练损失可以下降而任务成功率极低。
  • 会算：由 12M 步经验预算与演示条数反推平均轨迹长度，计算三类来源的成功率（Success Rate，SR）与成功加权路径长度（Success weighted by Path Length，SPL）增量及相对差，还原控制起点实验与对抗子集的数字。
  • 会设计：步数配平、起点配平（训练成功率约 48.0%）与对抗子集三层对照协议，能独立搭出来源对比实验矩阵。
  • 会判断：结合采集成本、可扩展性与行为覆盖，在人类演示、前沿探索与最短路径三类来源之间作出选择，并写明适用边界。
  • 会读：把结论放在 HM3D-Semantics v0.1（120 场景、6 类目标）与 2022 挑战 split 口径下解读，避免跨版本外推。

背景与动机

演示是模仿学习路线的原料，价格由人时决定。Matterport3D（MP3D）批次的 80k 条人类演示耗约 2,894 人时与约 5 万美元（Ramrakhya 等 2022，Habitat-Web）；HM3D 复采 77k 条约 2,378 人时，折算每条约 1.85 分钟。数据集扩容意味着把整条采集管线重跑一遍。自动来源于是有了吸引力：最短路径演示由真值地图生成，前沿探索演示由任务无关的覆盖策略加目标发现后的最短路径构成，两者只消耗算力，可以批量复制到新场景。

第 049 讲已经给出 BC 结果（6.4% / 44.9% / 64.1%），但有三个疑问没有回答。其一，差异是否只是演示条数与轨迹长度的算术后果。其二，RL 微调后的排序是否只是继承了 BC 起点，与来源本身的可微调性无关。其三，是否存在对自动来源有利的 episode 子集，人类演示的优势在那些子集上是否消失。本讲按这三层控制逐一给出实验协议与数字。

结构上，先形式化模仿差距与三种演示的生成口径，再读步数配平、起点配平、对抗子集三张结果表，最后落到实验设计、代码与坑。演示规模与收益递减留给第 051 讲，592 条失败标注的工具箱留给第 052 讲，三讲共同构成 IL 路线主线的收束。

核心原理

1. 三种演示的生成口径

对照实验在 HM3D-Semantics v0.1 上进行（120 个场景、6 类目标，训练与验证划分沿用 Habitat ObjectNav 挑战赛 2022 协议）。三类演示的定义与生成方式如下表，口径差异是后续全部结论的来源。

来源生成方式是否含探索信息集特征
最短路径（Shortest Path，SP）用真值地图计算到最近可导航目标实例的测地最短路，贪心采样动作拟合路径不含含特权信息（privileged information）：真值地图
前沿探索（Frontier Exploration，FE）两段式：任务无关策略最大化覆盖并构建俯视语义地图；语义预测器发现目标后沿地图最短路到达含任务无关探索不含目标导向；依赖在线语义检测
人类演示（Human Demonstrations，HD）众包平台上人类遥操作，第一人称 RGB 观察，走到目标 1 m 以内含任务导向搜索观察与策略部署时一致

SP 演示追求效率，动作序列由地图上的最优路径驱动；FE 演示追求覆盖，先逛完环境再在发现目标后收敛；HD 演示追求找到目标，包含人类在陌生住宅里的搜索直觉，例如先查厨房找杯子、先看卧室找床、进入死胡同后及时折返。三类轨迹的平均长度不同，因此后续所有比较统一按经验步数配平。

2. BC 目标与模仿差距

BC 在演示状态分布上做监督学习，目标为

θ* = arg minθ Σi=1..N Σ(ot, at) ∈ τ(i) −wt · log πθBC(at | ot) wt 为拐点加权系数；动作发生变化的时刻取全局权重，其余为 1

监督损失在演示数据的状态分布 ddemo 上取值，部署回报在策略自身诱导的状态分布 dπ 上取得。两个分布偏离时，小的交叉熵不蕴含高的任务回报；轨迹越长，偏离被放大的机会越多，这就是行为克隆的误差累积问题（Ross 等 2011，DAgger 给出在线聚合的修正思路）。

SP 演示还有第二层问题：特权信息。SP 的动作由真值地图上的最短路决定，而策略输入只有 RGB、GPS+Compass 与目标类别 one-hot 编码，两者信息集不同。在分岔路口，选择哪条走廊依赖地图，策略无法从同类输入归纳出这条规则，只好拟合训练场景里的偶然相关。测试场景换了布局，相关失效，成功率跌到 6.4%。FE 的问题不同：它的探索与目标无关，策略学到了覆盖式巡游，却没学到「在什么房间找什么物体」以及「何时离开当前房间」，因此 BC 成功率停在 44.9%。HD 的轨迹同时包含搜索与到达，两种行为都在监督信号里。

3. 步数配平下的 BC 对照

三类来源的轨迹长度相差数倍，SP 一条平均几十步，FE 与 HD 一条超过百步。若按演示条数比较，训练计算量并不同。论文的做法是配平经验步数：每个来源各收集约 12M 步，对应 240k 条 SP、70k 条 FE 与 77k 条 HD。由每来源的步数总量与条数可以反推隐含平均轨迹长度，进而解释为什么「SP 条数最多」不等于「SP 监督更多」。

来源（约 12M 步经验）条数平均轨迹长度（推算）BC SRBC SPL
最短路径 SP240k50.0 步6.4%5.0%
前沿探索 FE70k171.4 步44.9%21.5%
人类演示 HD77k155.8 步64.1%27.1%

读表要绑定口径：数字来自 HM3D-Semantics v0.1 val，12M 步配平，网络、优化器与增强策略完全一致。成功率差值：HD 比 FE 高 19.2 个百分点，比 SP 高 57.7 个百分点；FE 比 SP 高 38.5 个百分点。换算成相对值，HD 是 FE 的 1.43 倍，是 SP 的 10.02 倍。SPL 的差值分别为 5.6、22.1 与 16.5 个百分点，方向与成功率一致，说明 HD 的优势不靠缩短路径换来。

两类自动来源失败的原因不同：SP 卡在信息集不匹配（模仿差距），FE 卡在行为覆盖缺口（任务无关探索）。这决定了后续改进方向：提高 SP 的条数与改用更好的规划器无法弥补信息差，而延长 FE 只会重复同一种巡游模式。

4. 起点配平：RL 微调是否独立于 BC 起点

BC 起点高的来源，微调后大概率仍然高，这可能是起点继承，也可能来自初始化对 RL 的适应性。为区分两者，论文在三种来源的 BC 检查点中选出训练集成功率同为约 48.0% 的一组再微调。这个水平是 SP 训练成功率的峰值，因此 FE 与 HD 需要取训练早期的检查点。控制变量后，同一个 300M 步微调配方给出下表结果。

来源（BC 训练成功率约 48.0%）BC val SRRL 微调后 val SR读数特征
最短路径 SP较低43.6%训练高、验证低，过拟合
前沿探索 FE略高于 HD51.3%训练与验证都低，欠拟合
人类演示 HD略低于 FE66.1%训练与验证同步抬升

结论直接：控制起点后 HD 仍领先 FE 14.8 个百分点（相对 +28.85%），领先 SP 22.5 个百分点（相对 +51.61%）。人类演示不仅把 BC 起点抬得更高，还让 RL 微调更容易泛化。机制读法有三条。第一，SP 微调后训练成功率很高而验证低，策略把训练场景的地图巧合记住了，泛化失败。第二，FE 训练与验证都低，策略的行为模式本身缺少任务导向成分，微调缺少可放大的正确行为。第三，HD 的搜索与回溯行为在微调中被强化，验证侧同步受益。注意 BC val 一列只作定性描述：论文以「FE 略高于 HD、SP 其后」的次序报告，微调后次序翻转，这正说明微调效果依赖初始化质量，起点排序本身并不能决定结果。

5. 对抗子集：把优势来源压到极限

为排除「HD 恰好落在容易的 episode 上」这种解释，论文构造了两个对抗验证子集。SP-favoring 子集取 SP 的 BC 成功而 HD 的 BC 失败的 episode，以及两者都失败的 episode；FE-favoring 子集同理偏向 FE。按构造，HD 在这两个子集上的 BC 成功率被压到 0%，而对抗来源保留自己的成功 episode。这等于把起跑线让给对手，再看微调后的差距。

子集对抗来源 BC → RLHD BC → RL微调后差距
SP-favoringSP：5.2% → 34.8%HD：0.0% → 57.2%HD 领先 22.4 点
FE-favoringFE：26.3% → 43.0%HD：0.0% → 57.2%HD 领先 14.2 点

从 0% 出发的 HD 初始化，在 300M 步微调内把两个对抗子集的成功率都推到 57.2%，反超保留自身成功 episode 的 SP 与 FE 初始化；反方向的起点做不到这件事。这组数字把「任务导向搜索行为可迁移」的判断压实：RL 能在 HD 学到的搜索策略上继续优化，却难以从 SP 的地图依赖或 FE 的巡游模式里长出目标导向行为。子集的样本量有限，读数适合看方向，不适合当作生产环境的成功率先验。

6. 成本、可扩展性与选择判据

把质量结论与成本放在一张表里，才构成完整的决策依据。HD 的单位成本按 HM3D 采集折算为 1.85 分钟/条，折合 30.88 人时/千条；FE 与 SP 由程序生成，成本按算力与工程时间计。

来源单位成本行为覆盖可扩展性适用场景
HD约 1.85 分钟/条（人时）任务导向搜索加到达新场景需重采，成本线性增长追求部署级搜索质量、预算允许
FE算力与工程时间覆盖式探索，缺任务导向可批量生成，但 70k 后饱和（第 051 讲）低成本冷启动、覆盖型探索基线
SP算力与工程时间只有最优路径，无探索可无限生成，BC 上限极低带真值地图的仿真诊断、上界分析

预算换算：若只采 35k 条 HD，按同一单位成本约需 1,080.9 人时，而完整 77k 条为 2,378 人时。质量判据之外还要算这笔账，第 051 讲会给出规模与收益的曲线。另一个常见误解是「FE 免费所以先用 FE 再视情况补 HD」，论文没有测试混合路线，这个方向目前只有机制上的理由（FE 提供覆盖、HD 提供搜索），没有公开数字支撑，列入本讲练习作为待验证设计。

7. 边界与失效条件

第一，数据集与协议：全部数字绑定 HM3D-Semantics v0.1、120 场景、6 类目标与 2022 挑战 split；v0.2 扩容后的列表与场景不同，MP3D 的 21 类口径不可混谈。第二，结论成立的前提是策略输入不含地图。若系统自带同时定位与建图或在线语义地图，SP 的模仿差距会改变，6.4% 不能直接外推到模块化系统；反过来，模块化方法里的地图也是方法自身构建的，与生成演示时使用的真值地图仍不同源。第三，FE 的管线来自 SemExp 一系方法（Chaplot 等 2020，ObjectNav），换探索策略会改变 FE 的绝对值与饱和点。第四，对抗子集是按其它策略成败筛出的，比例数字受筛选规则影响，只用于方向性判断。第五，1.85 分钟/条是 HM3D 采集经验值，众包平台、质控强度与场景难度都会改变成本。

实现思路与设计

要把来源对照做成可复现实验，关键是三层控制：经验步数配平、BC 起点配平、对抗子集构造。前两层在训练侧，第三层在评测侧。下表给出固定项与操纵项。

对照实验协议

关键代码与解读

三段代码分别对应三层控制：步数配平采样、起点配平检查点选择、对抗子集构造。参数按论文口径固定，输出用于核对正文数字。

片段 1：按经验步数配平演示子集

import random

def step_balanced_sample(demos, step_budget, seed=0):
    """从演示池抽取子集，使累计经验步数不超过预算。"""
    rng = random.Random(seed)
    order = list(range(len(demos)))
    rng.shuffle(order)                    # 固定种子，抽样可复现
    picked, total = [], 0
    for i in order:
        d = demos[i]
        if total + d["steps"] > step_budget:
            continue                      # 跳过会超预算的条目，保持确定性与满额
        picked.append(d)
        total += d["steps"]
    assert total <= step_budget
    return picked, total

# 12M 步预算下：240k 条 SP 平均 50.0 步，70k 条 FE 平均 171.4 步。
# 条数相差 3.4 倍，监督步数相同，比较的才是来源本身。

解读：（1）预算按步数累计，不按条数累计，直接对齐训练时看到的监督信号总量；若按条数取 77k 条 SP，会得到约 3.85M 步，只有 HD 经验步数的约三分之一，结论会朝 SP 不利的方向偏移。（2）遇到超预算的条目选择跳过，不做轨迹截断，避免在 episode 中间切断动作序列，破坏拐点加权的语义。（3）论文未公开逐来源的子集清单，复现时可在报告中给出种子与步数合计，保证第三方能重建同一集合。

片段 2：在训练成功率等高线上选检查点

def pick_checkpoint(records, target=48.0):
    """选训练成功率最接近 target 的检查点；平局时取验证成功率更高者。"""
    def key(r):
        return (abs(r["train_sr"] - target), -r["val_sr"], r["step"])
    ranked = sorted(records, key=key)
    best = ranked[0]
    tied = [r for r in ranked if abs(r["train_sr"] - target)
            == abs(best["train_sr"] - target)]
    if len(tied) > 1 and tied[0]["val_sr"] == tied[1]["val_sr"]:
        print("警告：同分检查点，按更早步数取用并在报告注明")
    return best

# 用法：对 SP、FE、HD 三组训练记录分别以 target=48.0 取检查点，
# 再进入同一 RL 微调流程。SP 的上限约为 48%，取到的是其峰值附近。

解读：（1）匹配变量用训练成功率，报告指标用验证成功率，两者不混用；表中「FE 的 BC val 略高于 HD」正是这种分工下的读数。（2）平局先比 val、再比步数，规则全部写进代码，避免人工挑选检查点引入偏差。（3）切片高度只能由三者中最低的上限决定（此处为 SP 的约 48%），这是控制变量法的固有约束，报告里应写明为何不取更高或更低。

片段 3：构造对抗验证子集

def build_favoring_split(succ_a, succ_b, favor):
    """按论文规则构造 favor 方占优的子集。
    SP-favoring：SP 成功且 HD 失败，或两者都失败；FE-favoring 同理。
    注意：两个条件合并后等价于「HD 失败」，这是设计使然。"""
    split = []
    for eid in sorted(succ_a):
        a, b = bool(succ_a[eid]), bool(succ_b[eid])
        if favor == "A" and a and not b:
            split.append(eid)
        elif favor == "A" and not a and not b:
            split.append(eid)
    return split

# SP-favoring：A=SP、B=HD；FE-favoring：A=FE、B=HD。
# 子集内 HD 的 BC 成功率为 0（按构造），衡量的是微调后的翻转能力。

解读：（1）两条筛选分支合并后等价于取 HD 失败的 episode，代码保留原式是为了与论文表述逐条对应；理解这一等价关系有助于解释为什么 HD 的 BC 读数恒为 0。（2）子集只能用于比较微调后的相对能力，不能把 0% 当作「HD 泛化差」的证据，因为它由构造强加。（3）复现时要同时保存子集 id 列表与构造时的 BC 检查点标识，否则同一策略换检查点后子集不可比。

常见坑

  • 按演示条数配平：症状是把结论写成「SP 用了 3.4 倍的数据仍然最差」。根因是把条数当成经验量，忽略了平均轨迹长度相差数倍。修复：按经验步数配平（12M 步口径），并在表格中报告平均轨迹长度。
  • 不配平 BC 起点直接比较微调结果：症状是把来源排序全部归因于 RL 微调的适配性。根因是微调前的起点并不同。修复：用训练成功率等高线切片（约 48.0%）控制起点，或至少同时报告 BC 与 RL 两条读数。
  • 只盯训练成功率：症状是 SP 在训练侧看起来不错，部署侧差距大。根因是过拟合到训练场景的地图巧合。修复：检查点选择与报告都绑定 val，并单列训练与验证的差值；论文中 SP 微调后训练高、验证仅 43.6%。
  • 忽略演示生成的信息集：症状是期待增加 SP 条数或更换规划器就能追上 FE。根因是特权信息造成的模仿差距，规模无法弥补信息差。修复：核对生成器使用了哪些真值（地图、语义标注、目标实例位置），与策略输入逐项对照；必要时改用在线交互补充，或引入可查询专家的人机在环方案。
  • 跨协议打包结论：症状是用 v0.2、MP3D 或其它类别数的数字佐证来源排序，或把 FE 的饱和外推到 HD。根因是数据集版本与来源机制不同。修复：每张表标注版本、类别数与 split；每个来源单独成表、单独找饱和点。

  1. 从步数配平表计算 HD 对 FE、HD 对 SP 的 SR 与 SPL 增量及相对差；由 12M 步预算反推三条平均轨迹长度，解释为什么 SP 条数最多却监督不足。★

    SR 增量 19.2 与 57.7 点，相对 +42.76% 与 +901.56%；SPL 增量 5.6 与 22.1 点。平均长度 50.0 / 171.4 / 155.8 步，三条来源的监督步数相同，SP 的劣势来自信息集与行为覆盖，不来自步数。
  2. 用状态访问分布写出模仿差距的成立条件，并设计一个能区分「特权信息不足」与「行为覆盖不足」的诊断实验。★★
    提示
    监督分布 d_demo 与策略分布 d_π 的偏离条件；诊断思路：给 SP 策略注入真值地图或目标方向特征再训 BC，若成功率跳升则主因是特权信息；在 FE 演示中保留目标导向片段重采样后再训，若仍无改善则覆盖缺口无法靠重采样补齐。
  3. 设计起点配平协议：说明切片高度怎么选（SP 上限约 48%）、检查点如何排序、种子的作用，以及如何报告结论的稳健性。★★
    提示
    切片取三者中最低训练上限；排序先按与目标的差、再按 val、最后按步数；≥3 个种子，报告均值与区间；若多种子下 HD 相对 FE 的差值方向一致且大于区间宽度，结论可信。
  4. 在 1,500 人时预算内设计一套来源对比实验，目标是复现「HD 最优」的方向判断：给出每个来源的规模与成本、起点控制方式、评测子集与判定标准，并说明哪些结论受预算限制无法回答。★★★
    提示
    HD 可用约 48k 条（约 1,482 人时，按 30.88 人时/千条）逼近比例；FE 与 SP 按算力生成并配平到同一经验步数；三层控制全部保留；判定标准为控制起点后 HD 对 FE、SP 的方向一致。预算限制下无法回答的问题：混合来源、v0.2 场景、真机迁移。
  5. 读对抗子集的结果：解释 HD 的 BC 成功率为 0 而微调后达到 57.2% 的含义；如果换成随机子集，读数会怎样变化；为什么不能把对抗子集的成功率当作生产环境的先验。★
    提示
    57.2% 说明 RL 能在 HD 初始化上长出目标导向行为；随机子集上 HD 的 BC 不为 0，读数会整体上移；对抗子集由其它策略的成败筛出，比例不反映自然分布，仅用于方向比较。

小结

  • 来源对照在 HM3D-Semantics v0.1（120 场景、6 类）与 2022 挑战 split 上进行；三类演示按约 12M 步经验配平：240k 条 SP、70k 条 FE、77k 条 HD，平均轨迹长度 50.0 / 171.4 / 155.8 步。
  • 步数配平下 BC 成功率 6.4% / 44.9% / 64.1%（SPL 5.0% / 21.5% / 27.1%）；HD 比 FE 高 19.2 点，比 SP 高 57.7 点。SP 的失败源于特权信息造成的模仿差距，FE 的失败源于任务无关探索。
  • 起点配平（训练成功率约 48.0%）后微调：HD 66.1%、FE 51.3%、SP 43.6%；SP 过拟合、FE 欠拟合、HD 训练与验证同步抬升，人类演示优势不依赖起点继承。
  • 对抗子集上 HD 从 0% 出发微调后均为 57.2%，反超 SP 的 34.8% 与 FE 的 43.0%；任务导向搜索行为的可迁移性得到方向性证据。
  • 成本口径：HD 约 1.85 分钟/条（30.88 人时/千条），35k 条推算约 1,080.9 人时；FE 与 SP 只计算力，但 FE 在 70k 后饱和、SP 上限极低；混合来源路线尚无公开对照。
