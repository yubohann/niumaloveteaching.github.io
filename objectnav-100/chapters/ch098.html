第五篇 · 真机、Sim2Real 与系统集成

第 098 讲｜结课 I：方法路线图回顾

97 讲之后，ObjectNav 的结果散落在五类协议、四类平台上。本讲把全课收成一条五段路线：Task（任务与口径）→ Module（语义地图与探索）→ E2E（端到端配方）→ VLM（开放词汇与大模型）→ Robot（真机与系统）。每一段给出同协议的关键数字、它解决的问题与留下的缺口：SemExp（Chaplot 等，2020，MP3D 21 类，test-ch SR 25.3 / SPL 0.102）与 Red Rabbit（Ye 等，2021，MP3D 21 类口径 SR 0.30）打开两条主线；PirlNav（Ramrakhya 等，2023，HM3D v0.1 test-std 65.0 / 33.0）与 OVRL-v2（Yadav 等，2023，同协议 64.0 / 29.0）把闭集推向高位；VLFM（Yokoyama 等，2023，HM3D v1 val 52.5 / 30.4）与快慢 ReAct（Lan 等，2026，同协议 68.75 / 33.97）显示零样本路线的后发优势；HomeRobot OVMM 把仿真成绩在最难档从 0.8% 推到 10.8%。本讲的核心工具是协议键：键一致才允许相减，键不同只做方向比较。最后给出按数据预算、算力、泛化与平台四轴的选型表，交给第 099 讲算清复现成本。

  • 主题：路线图 / 方法选型 / 协议键 / 混合路线
  • 关键公式：路线坐标 R = (目标接口, 信念表示, 训练信号, 平台)；协议键 K = (数据集, 版本, 划分, 类别数, 步数预算, 成功判据)
  • 预计学时：90 分钟
  • 前置章节：第 097 讲（工程栈全景）

学习目标

  • 复述：说清五段路线各自的目标接口、信念表示、训练信号与代表方法，能按年份与协议把 12 个以上里程碑放进路线图。
  • 会算：对同协议结果复算成功率与 SPL 的绝对增量及相对百分比，例如 VLFM 到快慢 ReAct 的 SR +16.25 个百分点（相对 +30.95%）。
  • 会判断：写出协议键并辨别任意两组数字能否直接相减；识别把 0.1 m 判据、40 步预算、多机团队指标与挑战 1 m 判据混排的错误。
  • 会选型：按数据预算、算力、开放词汇需求与部署平台四轴，为给定场景选出模块化、端到端、零样本大模型或混合路线，并列出被排除路线的理由。
  • 会设计：为一条混合路线写出阶段划分、每个阶段的验收指标与失败回退，指向第 099 讲的资源清单。

背景与动机

第 001 至 097 讲按主题展开，同一类问题在不同篇章里出现过多次：感知瓶颈在第 029、067、077 讲三次出现，成功与效率的交换在第 018、028、094 讲三次出现，协议不可比性在第 019、051、078、080 讲反复出现。主题式讲授便于深入，代价是读者手里有一堆数字，缺一根把它们串起来的线。本讲补这根线，把全课压成一条五段路线与一张选型表。

路线图的用途不只是复习。真到开新课题或接新场景时，第一个决策是「从哪一段进入」：只有单卡和几天时间，就从免训练的零样本模块化进入；有演示数据但没有万卡时，从行为克隆加轻量微调进入；要做新类别泛化，就把接口从类别词换成文本或掩码；要上真机，就先在第 096 讲式的评测协议里把重复次数与判据定死。四轴选型表回答的正是这个入口问题。本讲与后两讲构成结课三连：本讲给路线，第 099 讲给复现与算力清单，第 100 讲把路线上的缺口转成可开题方向。

核心原理

1. 四个坐标轴与五段路线

任何一篇 ObjectNav 工作都可以放进四个坐标轴。第一轴是目标接口：类别词（MP3D 21 类、HM3D 6 类）、自由文本（HM3D-OVON 的 379 类、15,661 个实例）、目标图像（ImageNav 与 InstanceImageNav）、目标掩码（OVSegDT 一类工作），以及多目标链（GOAT 系列）。第二轴是信念表示：无地图的循环状态、二维语义栅格、三维点云或场景图、跨幕记忆结构。第三轴是训练信号：零样本组合、行为克隆、强化学习、监督与 RL 混合。第四轴是平台：仿真、Stretch、Spot、四足、无人机、机器人与监控协同。

按时间与主导轴切分，全课形成五段路线。Task 段固定口径：1 m 停止加 oracle 可见性、500 步上限、单层可完成、动作与相机的版本差异，这一段决定了后面一切数字能不能相减。Module 段用语义地图加目标导向探索解决「先验往哪搜」；E2E 段用大规模 RL 与演示学习解决「端到端能不能学出来」；VLM 段把目标接口开放、把常识来源换成视觉语言模型；Robot 段把前四段的组件装配到真机，处理定位、时延、恢复与评测样本量。五段之间是叠加关系：2026 年的快慢 ReAct 同时使用语义栅格（Module）、BLIP-2 价值图（VLM）与现成 PointNav 执行器（E2E 的表征），属于典型混合体。

2. Task 段：口径决定台阶

把本段的关键口径集中复述一次，后面所有比较都从这里出发。目标类别：MP3D 21 类（2020 与 2021 届），HM3D 6 类（chair、couch、potted plant、bed、toilet、tv，2022 与 2023 届）。场景规模：MP3D 90 个场景；HM3D-Semantics v0.1 为 120 个场景，切分 80/20/20；v0.2 为 216 个场景，切分 145/36/35，含 142,646 个实例标注。预算与判据：500 步上限，停止点距目标不超过 1 m 且目标 oracle 可见；2022 与 2023 届在 1000 条 episode 上评测，墙钟 48 小时，折合每条约 172.8 秒、每步约 0.3456 秒。

这些口径制造了两个台阶。第一个台阶是数据集换代：2021 届冠军 Red Rabbit 为 SR 0.30 / SPL 0.13（MP3D 21 类），2022 届榜首 ByteBOT 为 SR 0.64 / SPL 0.35（HM3D v0.1 6 类）。把 0.30 到 0.64 读成方法一年进步 2.13 倍会同时忽略数据集、类别、episode 与场景质量四处变化。第二个台阶是判据差异：真机与多家论文使用 0.1 m 停止判据（Co-NavGPT、MFNP）或 0.2 m（CLUE），HM3D-OVON 与挑战口径为 1 m；无人机 AeroBelief 使用 20 m 成功半径与 150 个动作。台阶两侧的数字可以谈方向，不能直接相减。

3. Module 段：语义先验与探索分工

模块化的代表是 SemExp（Chaplot 等，2020，目标导向语义探索）：语义建图、目标导向探索与确定性局部规划三段，训练 10M 帧，挑战 test-ch 以 SR 25.3 / SPL 0.102 / DTG 6.328 m 夺冠。消融给出两条独立增益：去掉语义地图，Gibson 测试集 SR 从 54.4 掉到 48.8；去掉目标导向策略换成覆盖优先，掉到 45.0；换成真值分割升到 73.1。感知与探索是可分别改进的两块短板，这一结论在此后六年反复出现。同期谱系里，PONI（Ramakrishnan 等，2022）用势函数监督把训练成本相对逐场景 RL 降低到最高 1600 分之一；ESC（Zhou 等，2023）加常识谓词，HM3D SR 从 33.1 提到 39.2；L3MVN（Yu 等，2023）用语言模型给前沿排序，HM3D 达 50.4 / 23.1，映射头版本 54.2 / 25.5。

Module 段遗留两个问题。其一，检测质量是误差上限：同一套 MOPA 管线换成零样本检测器 Detic，HM3D 2022 验证集 SR 从 64.0 掉到 30.0，34 个百分点全部来自感知。其二，先验退化为噪声时会伤害性能：RoboTHOR 物体摆放随机，去掉物体级共现后从 38.1 升到 39.3。这两条正好分别在 VLM 段（更强的语义模型）与 E2E 段（学习表示替代手工先验）获得回应。

4. E2E 段：从 6.2% 到 65.0% 的三级跳

端到端的起点由一组反差定义：同一 CNN+RNN 结构在 PointNav 上用 2.5B 步训练到 SPL 0.948，直接搬到 ObjectNav 只剩 6.2% SR（Ye 等，2021，MP3D test-std 口径）。第一级跳来自辅助任务、探索奖励与系留策略：同一批作者把成功率推到 24.5%，相对 6.2% 为 3.95 倍，训练规模约 125M 帧、192 GPU 小时。第二级跳来自演示学习：PirlNav（Ramrakhya 等，2023）先用 77k 条人类演示做行为克隆，再以 DD-PPO 微调 300M 步，在 HM3D-Semantics v0.1 的 test-std 与 test-challenge 同时达到 65.0% SR / 33.0% SPL，比 2022 届 Stretch 基线高 5.0 个百分点。第三级跳是无地图架构：OVRL-v2（Yadav 等，2023）只用 ViT、卷积与 LSTM，在 HM3DSem v0.1 test-standard 取得 64.0% / 29.0%，与 PirlNav 相差 1.0 个百分点，SPL 低 4.0 个百分点。

E2E 段的读法有两条。第一，算力不是主瓶颈，学习信号密度才是：24.5% 的配方用 192 GPU 小时量级把纯 RL 的 6.2% 提升近 4 倍；把 PointNav 配方加 20 倍算力直接搬家，得到的仍是 6.2%。第二，成功与效率可以交换：Red Rabbit 的六动作配置与双策略配置分别以 24.5% / 6.4% 与 21.1% / 8.1% 登顶不同指标；PirlNav 的 critic 学习阶段用 61.9% 对 53.6% 证明了训练顺序的价值。

5. VLM 段：接口开放与常识外置

VLM 段把目标接口从类别词推进到文本、图像与掩码，并把常识从手工先验换成模型。四个同协议读数能看清演进。ZSON（Majumdar 等，2022）用多模态目标嵌入实现跨数据集零样本，HM3D 为 SR 25.5 / SPL 12.6；VLFM（Yokoyama 等，2023）用「深度前沿 + BLIP-2 语言价值图 + 检测目标航点 + PointNav 执行」的组合，在 HM3D v1 val 达到 52.5 / 30.4，其中价值图贡献折算约 +8 个百分点；快慢 ReAct（Lan 等，2026）沿用同一价值图骨架，把「何时深思、读什么记忆」做成事件触发与预算受限的推理循环，在同一 HM3D v1 验证集达到 68.75 / 33.97，相对 VLFM 的 SR 增量为 +16.25 个百分点（相对 +30.95%）。另一条线是开放词汇基准：HM3D-OVON 把词表扩到 379 类，LANav（Zhang 等，2026）用线性注意力状态更新在三个验证划分平均取得 36.4% SR，比 Transformer 基线高 6.3 个百分点；OVSegDT（Zemskova 等，2026）用 1.3 亿参数纯 RGB 加掩码接口，在 val unseen 取得 44.7% / 20.6。

VLM 段的共同瓶颈在感知侧。快慢 ReAct 的失败归因显示，深思带来的 3.60 个百分点改进中，误检占 1.35、无前沿停止占 1.25、漏检占 1.00；OVSegDT 的失败构成里目标识别占 28.2%，是最大单项；第 077 讲的长尾基准显示，图像条件查询在静态定位上平均提高 6.37 个百分点，但在 OVON-syn 的在线闭环中增益从 VLFM 的 +3.34 缩到 OneMap 的 +1.67，落差归因于下游检测质量。语义模型再强，最终仍要经过检测器这一关。

6. Robot 段：真机把问题重新排序

真机段可用四个坐标记住。执行平台上，SemExp 用 LoCoBot 完成 20 次试验 13 次成功（约 65%，Wilson 95% 区间 [43.3%, 81.9%]）；VLFM 部署到 Spot，四个模型在 16 GB 显存笔记本上实时运行，但里程计无高度通道，跨层 episode 直接失败（HM3D 与 MP3D 分别 14.6% 与 9.6%）；MFNP（Zhang 等，2024）在 Go1-Edu 上用云端推理与爬梯 SDK 补上换层；Co-NavGPT（Yu 等，2023）在两台 Go2 上验证多机协作，端到端约 5 FPS。任务上，OVMM 把评测扩到移动操作四阶段：NeurIPS 2023 竞赛最难档（仿真内真实感知）从官方基线 0.8% 到冠军 10.8%，比值为 13.5，绝对增益 10.0 个百分点，赛后回顾把错误检测与恢复列为共同关键。多机上，Co-NavGPT 在 HM3D v0.2 的 1000 条 episode 上取 0.666 SR，比单机 0.579 高 8.7 个百分点（相对 +15.03%），代价是通信与重复探索。

真机段的纪律由第 096 讲的方法学给出：先定判据与样本量，再跑实验。分辨 10 个百分点的成功率差每组约需 197 条 episode，5 个百分点约需 903 条（第 058 讲口径）；真机一次只有几十条，因此真机结论以可行性演示与区间累积呈现。把三场景演示说成成功率、把团队指标当成单机能力，都是本段最常见的口径错误。

8. 三条跨段规律

规律一，能力沿「接口开放」与「表示结构化」两个方向迁移。从类别词到文本，任务不变而泛化对象变多；从无地图到二维图再到三维图与记忆，空间推理变强而构建成本上升。VLM 段后期的工作（快慢 ReAct、CLUE、OVAL）同时在两个方向上叠加。

规律二，协议变更制造台阶，台阶伪装的进步比真实进步更容易传播。SR 0.30 到 0.64、REST 的 HSSD 56.7 与 VLFM 的 HM3D 52.5、AeroBelief 的 21.61 与室内方法，都是台阶两侧的数字。写综述或立项报告时，先列协议键表，再谈剩余差距。

规律三，真机证据要按「演示、统计、榜单」三级折价。单个成功案例支撑可行性，如 MFNP 的跨层演示；重复 20 到 50 次支撑带区间的估计，如 LANav 的 50 次 41 次成功；只有同协议全量评测支撑排序。等级写进结论，读者才能正确使用。

9. 路线图的边界与失效

四条边界写进使用说明。其一，协议键覆盖不了硬件差异：键只约束评测口径，真机的传感器、场地与操作规范仍会让同一方法产生分布差异，跨实验室数字需要重测，不能按系数换算。其二，混合路线的误差耦合：感知、建图、规划与执行串行后，各段误差相乘，路线图中的单模块增益不能简单累加。其三，证据等级不可外推：仿真统计结论不能推出真机排序，真机可行性演示也不能否定仿真中的趋势。其四，路线图有时效：2026 快照中的协议碎片说明评测口径仍在演化，任何汇总表都应带版本与日期，超过一年需要复核。

选型四轴与路线映射如下。四轴同时输入，任何一个轴的极端值都会改变结论：算力极小指向零样本模块化；数据含演示而缺 RL 环境指向 BC 与轻量微调；目标类别开放且评测含未见类指向 VLM 或掩码接口；部署平台有轮足限制或连续动作要求时，执行层优先复用经过验证的 PointNav 或本体接口。

多机或人机共处共享地图加分配器全局语义图 + 前沿分配 + 冲突消解贪心分配在动态环境失效；单机策略无协作接口

混合路线模板

混合路线的组装顺序固定为四步，每步都有验收指标。第一步，感知与检测：选定检测器与开放词表接口，在目标数据集上测召回与误检，验收线用第 029 讲的感知主导结论设定（检测错误占失败的最大单项）。第二步，表示与探索：二维语义图配前沿评分起步，只有跨层或多机需求出现时才升级到三维图或共享地图。第三步，执行：优先复用 PointNav 策略或本体导航接口，把执行误差与策略误差分开记录。第四步，恢复与评测：按第 096 讲协议定重复次数、判据与失败分类，按第 058 讲公式定样本量。四步中任何一步未过验收线，先修该步再进入下一步，避免误差在流水线上叠加。

关键代码与解读

三段代码分别实现协议键守护、同协议增量扫描与选型建议。前两段直接用本讲的登记数据验证，输出与正文表格一致。

片段 1：协议键与受守护的比较

def pkey(dataset, version, split, classes, budget, criterion):
    """协议键：六个字段全一致才允许直接比较。"""
    return (dataset, version, split, classes, budget, criterion)

RESULTS = [
    dict(name="VLFM",    route="VLM",
         key=pkey("HM3D", "v1", "val", 6, 500, "1m+visible"),
         sr=52.5, spl=30.4),
    dict(name="ReAct",   route="VLM",
         key=pkey("HM3D", "v1", "val", 6, 500, "1m+visible"),
         sr=68.75, spl=33.97),
    dict(name="PirlNav", route="E2E",
         key=pkey("HM3D", "v0.1", "test-std", 6, 500, "1m+visible"),
         sr=65.0, spl=33.0),
]

def compare(a, b):
    """键不一致时拒绝相减，返回比较结论，不返回数字。"""
    if a["key"] != b["key"]:
        return {"comparable": False,
                "reason": "协议键不一致：%s 对 %s" % (a["key"], b["key"])}
    return {"comparable": True,
            "d_sr": round(b["sr"] - a["sr"], 2),
            "d_spl": round(b["spl"] - a["spl"], 2),
            "rel_sr_pct": round((b["sr"] - a["sr"]) / a["sr"] * 100.0, 2)}

pair = compare(RESULTS[0], RESULTS[1])
print(pair)   # {'comparable': True, 'd_sr': 16.25, 'd_spl': 3.57, 'rel_sr_pct': 30.95}
ref = compare(RESULTS[1], RESULTS[2])
print(ref["comparable"], ref["reason"][:18])   # False 协议键不一致...

解读：（1）键函数把六个字段放进元组，相等性判断一次完成，避免临时断定「这两个数字差不多可以比」。（2）compare 在键不一致时返回结论对象，不抛异常，登记表生成脚本可以批量跳过不可配对项并打印原因。（3）相对百分比与绝对增量同时返回：小基数下相对值会放大观感，OVMM 的 0.8% 到 10.8% 就是典型，两者并列可互相校正。（4）ReAct 与 PirlNav 虽然 SR 接近，键中划分与版本都不同，脚本会把它们排除在配对之外，这一步正是人工阅读最常漏掉的。

片段 2：同协议增量扫描

def same_protocol_pairs(results):
    """枚举所有键一致的组合，生成可相减的增量清单。"""
    pairs = []
    for i in range(len(results)):
        for j in range(i + 1, len(results)):
            a, b = results[i], results[j]
            if a["key"] == b["key"]:
                pairs.append((a["name"], b["name"],
                              round(b["sr"] - a["sr"], 2),
                              round((b["sr"] - a["sr"]) / a["sr"] * 100.0, 2)))
    return pairs

for row in same_protocol_pairs(RESULTS):
    print("%s -> %s: d_sr=%.2f pts, rel=%.2f%%" % row)
# VLFM -> ReAct: d_sr=16.25 pts, rel=30.95%

解读：（1）扫描逻辑与片段 1 共用键定义，登记表扩到上百行时仍自动分组，避免手工维护配对关系。（2）输出保留两位小数，与课程表格一致；summarize 层面再决定四舍五入与单位。（3）同一协议内出现三个以上结果时，脚本给出所有两两组合，可真对比对「排名翻转」的格子，例如第 018 讲里 SPL 与 SR 排序不一致的两支队伍。

片段 3：四轴选型建议（教学规则）

def recommend(interface, budget_steps, gpu_tier, platform):
    """按接口、步数预算、卡档与平台给出路线建议；规则来自本讲选型表。"""
    if platform != "sim" and budget_steps < 1e7:
        return "零样本模块化 + 现成执行器（真机优先验判据与恢复）"
    if interface in ("text", "image", "mask") and budget_steps < 1e8:
        return "VLM 前沿排序 + 检测验证（T0 免训练档）"
    if budget_steps < 5e8:
        return "BC 预训练 + 轻量 RL 微调（T1/T2 过渡档）"
    if gpu_tier >= 8:
        return "端到端全量配方（T2，先跑 100M 冒烟）"
    return "混合路线：模块化召回 + 端到端执行"

print(recommend("text", 5e5, 1, "sim"))   # VLM 前沿排序 + 检测验证（T0 免训练档）

解读：（1）四个输入对应四轴，函数只做粗分档，精算留给第 099 讲的预算器；接口检查放在算力之前，是因为开放词汇需求改变路线类别，无法用加卡弥补。（2）真机分支优先返回评测与恢复提示，符合第 096 讲的顺序：判据未定不跑数据。（3）全量分支强制附「100M 冒烟」，对应 DD-PPO 的 4% 步数取九成性能的结论，先花小预算确认方向再扩大。

常见误区

  • 跨协议相减：症状是把 REST 在 HSSD 的 56.7、VLFM 在 HM3D 的 52.5、ReAct 在 HM3D v1 的 68.75 排成一句话比较。根因是数据集、预算与判据三处不同。修复：先写协议键；只有六字段全同才相减，其余只做方向与机制比较。
  • 把台阶当进步：症状是引用「SR 从 0.30 到 0.64，一年提高 2.13 倍」。根因是 2021 到 2022 同时换了数据集、类别数、episode 集合与场景质量。修复：跨届对比先列四处口径差异，再做量级描述；配对结论限定同届同 split。
  • 把真机演示当成功率：症状是引用 MFNP 单案例或 VLFM 办公楼演示推断真机 SR。根因是两类证据都是可行性展示，没有重复与区间。修复：按演示、统计、榜单三级标注证据等级；真机结论附重复次数与 Wilson 区间，未达样本量的只写可行性。
  • 把团队指标当单机能力：症状是用 Co-NavGPT 的 0.666 与单机方法比较。根因是多机指标取全队最短路径与最近距离，同起点设定还带来早期覆盖优势。修复：只与多机基线在同口径下比较，同时报告重复探索率与通信量。
  • 用最新路线替代适配判断：症状是不管数据与算力，直接选 2026 年的大模型方案，复现停在环境搭建阶段。根因是忽略零样本路线同样需要检测器、价值图与执行器三要素，以及 40 步与 500 步预算的差别。修复：先过四轴选型表，再用混合路线模板四步验收，任何一步未过线不进入下一步。

小结

  • 五段路线：Task 定口径，Module 用语义先验与探索，E2E 用演示与大规模 RL 推高位，VLM 开放接口与外置常识，Robot 处理定位、时延、恢复与评测。五段是叠加关系，2026 年的强系统多为混合体。
  • 关键坐标：SemExp 挑战 test-ch 25.3 / 0.102；Red Rabbit（MP3D 21 类）SR 0.30；6.2 → 24.5（3.95 倍）→ PirlNav 65.0 / 33.0；OVRL-v2 64.0 / 29.0；ZSON 25.5 → VLFM 52.5 / 30.4 → 快慢 ReAct 68.75 / 33.97（+16.25 点，相对 +30.95%）；OVMM 0.8% → 10.8%（比值 13.5，绝对 +10.0 点）。
  • 协议键 K =（数据集, 版本, 划分, 类别数, 步数预算, 成功判据）；键同才相减，键异只谈方向。多机、0.1 m、40 步、20 m 半径四类特殊口径必须单独标。
  • 四轴选型：数据预算、算力、开放词汇需求、部署平台；混合路线按感知、表示、执行、恢复四步组装，每步设验收线。
  • 三条规律：能力沿接口开放与表示结构化迁移；协议变更制造台阶；真机证据按演示、统计、榜单三级折价。
