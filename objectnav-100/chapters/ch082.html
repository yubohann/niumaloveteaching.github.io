第五篇 · 真机、Sim2Real 与系统集成

第 082 讲｜RoboTHOR：配对环境与远程真机

第 081 讲定义了可预测性实验，落地需要一个同时具备仿真与真机两侧、并且能对全球研究者开放评测的平台。（Deitke 等，2020，RoboTHOR，arXiv:2004.06799）给出参考实现：89 个公寓场景中，75 个用于训练与验证，4 个 test-dev 与 10 个 test-standard 配有实物孪生；实物空间 8.8 m × 3.9 m，模块化重配置约 30 分钟，材料成本约 1 万美元，远程评测通过 HTTP 与调度器组织。语义导航基准使用 14 个目标类别，人类找目标的中位步数为 49.5，最短路径为 22.0。仿真到真机的落差集中在路径效率：最好模型的 easy 档成功率从 55.30 降到 33.33，SPL 从 38.12 降到 3.53；过拟合单个 test-dev 场景的模型成功率保留很多，SPL 只剩 14.94%。本讲读平台设计、配对对齐、评测流程与落差解剖四件事。

  • 主题：配对场景 / 远程真机评测 / 语义导航协议 / 落差解剖 / 可复现成本
  • 关键公式：S = 1[Done ∧ visible ∧ dist ≤ δ]；difficulty = 分位(sp_len)；ΔSPL = SPLsim − SPLreal
  • 预计学时：85 分钟
  • 前置章节：第 081 讲（Sim2Real 问题定义与历史）

学习目标

  • 理解：说清 RoboTHOR 的场景划分、资产库与实物配对结构，以及配对设计控制与不控制的变量。
  • 会算：复算 Sim2Sim 与 Sim2Real 的成功率与 SPL 落差、过拟合模型的保留率，以及真机评测的样本量需求。
  • 会读：按评测流程表解释远程真机的提交、调度、重置与判分链路，识别吞吐瓶颈。
  • 会设计：为自己团队的配对环境写出核验清单，覆盖相机、动作、碰撞、判据与重置五个环节。
  • 会判断：识别 strict 可见性与 oracle 可见性、45° 与 30° 转向角、两层场景划分三处口径边界。

背景与动机

第 014 讲已经从数据集地图的角度介绍过 RoboTHOR，当时关注的是它在 AI2-THOR 家族中的位置与规模。本讲换到系统与评测视角：实物孪生如何建造，远程评测如何避免硬件冲突，配对实验的读数如何解读。这与第 081 讲的可预测性框架直接衔接：HaPy 用 3D 扫描把一间实验室虚拟化，RoboTHOR 则用模块化资产刻意建造两侧环境，规模从 3 个房间配置扩到 89 个公寓，并把真机访问开放给远程用户。

对 ObjectNav 课程而言，RoboTHOR 还有一层任务意义：它是语义导航（Semantic Navigation）的原生基准，目标由类别名词指定，成功要求显式停止、目标可见且距离达标，正是目标物体导航的早期形态。本文的三张读数表（Sim-to-Sim、Sim-to-Real、Overfit Sim-to-Real）构成后续第 083 讲现实化改造与第 084 讲噪声参数的基线。

核心原理

1. 场景、资产与配对结构

场景总数为 89 个公寓，按用途分三层：75 个训练与验证场景（60 训练、15 验证）、4 个 test-dev 场景、10 个 test-standard 场景。三层分别由 15、2、5 种墙体布局构成，平均每种布局对应 5.0、2.0、2.0 个公寓；共享布局的公寓在房间功能与家具布置上没有重叠，避免布局复用带来捷径。test-dev 与 test-standard 的场景同时建有实物孪生，前者用于真机验证，后者作为盲测集不公开。

资产库共 731 件唯一物体，覆盖 11 类家具与 32 类小物体；其中 14 类小物体被指定为目标类别，占小物体类别的 43.75%，并被保证出现在每个场景中。家具与对象大量采用可采购的实物同款，这一选择让仿真与实物在物体实例级别对齐，对齐粒度超过布局层面。墙体使用轻质板材，实物空间仅 8.8 m × 3.9 m（约 34.32 m²），通过模块化拆装实现不同布局，重配置一个场景约 30 分钟，材料与资产成本约 1 万美元，机器人为 LoCoBot 移动平台，配 RealSense RGB-D 相机。场景的模块化与可重构是规模化的关键：同一物理空间轮换承载 14 个配对场景。

配对设计控制语义域差：两侧的布局、家具、物体、光照尽量一致，训练与评测的墙布局和物体实例互不重叠。它不控制的部分必须写明：实物的物理参数（轮子打滑、电机延迟）、传感器噪声、光照的实时变化、以及实物与模型之间的细微几何差。第 081 讲列出的五类落差来源在这里全部存在，配对环境把「外观与语义」这一类压到很低，把「控制与传感」这一类暴露得更清楚。

2. 任务与训练协议

任务为语义导航：智能体从随机位置出发，找到指定类别的一个实例。观测为 RGB、深度或两者组合；动作集含前进、左右转、抬头、低头与停止；基准实验采用 45° 转向。成功判据三项同时满足：智能体发出停止动作、目标在当前帧内可见、与目标距离不超过阈值。第 014 讲指出 RoboTHOR 的可见性是停止帧严格可见，Habitat 挑战使用 oracle 可见性，严格口径的通过集合是 oracle 口径的子集。

任务难度从探索结构直接可见：人类在仿真中找目标的中位步数为 49.5，而最短路径为 22.0 步，相差 27.5 步（2.25 倍），说明大部分步数花在未知环境中的搜索上，接近目标只占少数步数。评测按最短路径长度分档：起点位于场景内最短路径最短的 20% 记为 easy，20% 至 60% 为 medium，其余为 hard。分档使不同起点的难度可比，也让落差分析可以按难度分层进行。

基线训练配置：奖励为成功 +5、每步 −0.01；用 A3C 在 8 张 TITAN X 上训练 100,000 条 episode，32 个线程，Adam 优化器，学习率 0.0001。为模拟真机的不确定性，仿真致动加入噪声：平移位移均值 0.001 m、标准差 0.005 m，转向角均值 0°、标准差 0.5°。这一组参数按实物重复测量标定，属于系统辨识的最小实现。实验报告训练用 50 个训练场景，评测选择 2 个 test-dev 场景，这一点在引用数值时必须注明。

3. 三种评测与主读数

4. 落差解剖：外观、视角与控制

外观层面，论文收集 846 张仿真与真机配对图像，经 ResNet-18 提取特征后用 t-SNE 降维，两个域的点云明显分离，目测相似并不等于特征空间接近。检测层面，用同一检测器在 761 张配对图像上评测 10 个类别的 mAP：真机 0.338、仿真 0.255，仿真侧低 0.083（相对低 24.56%），且置信度分布不同。特征与检测两个证据都指向同一结论：跨域差异足以改变策略动作。

视角层面，相机参数失配的代价被单独测量：训练用 90° 视场、测试改 42.5°，真机 easy 档成功率降到 16%，medium 与 hard 降到 0%，机器人倾向原地旋转。这个实验支持在训练期把相机参数当作增广维度，部署阶段的被动对齐代价过高。控制层面，真机上超过 80% 的轨迹没有碰撞，机器人探索行为安全，但电机噪声、打滑与启停延迟使轨迹变长。论文还测试了图像翻译：用 CycleGAN 把真机图像翻译成仿真风格再交给仿真策略，视觉上纹理被抹平，真机成功率为 0%，像素级翻译没有修复特征空间与物理差异。

5. 远程评测平台

远程评测的目标是让全球研究者无需自建硬件即可在实物上测试模型。链路分四段：模型或代码通过接口提交，调度器分配时间片防止多用户同时占用同一台硬件，真机执行 episode，结果回传。评测用定位系统（Super-NIA-3D 模块）解算机器人的位置与朝向，仅用于判分与可视化，不进入策略输入，这一点与 HaPy 的激光定位纪律一致。episode 结束后机器人自动复位；失败 episode 用预建地图导航到下一个起点。实物空间装有无线摄像头供远程观察。受机器人速度限制，一条 episode 可达 10 分钟，意味着单日可完成的评测条数有限，实验设计必须提前规划样本量。

样本量按 Wilson 方案估算：要把成功率的 95% 区间半宽压到 5 个百分点，按最保守的 p = 0.5 需要约 385 条 episode；按每条 10 分钟计算是 64 小时机器人时间，折合 8 个 8 小时工作日。半宽放宽到 10 个百分点需要 97 条，约 16.2 小时。远程平台的价值不在便宜，而在把这条成本从每个团队各付一次变成共享一次；相应地，提交方必须在本地仿真完成筛选，把真机时间花在确认性实验上。

平台边界同样要记清：论文的实验只用了 4 个 test-dev 场景中的 2 个，真实样本量小；场景为单层公寓，多楼层与室外均不覆盖；机器人只有 LoCoBot 一种；test-standard 为盲测，公开文献无法复核其逐条结果；仿真的致动噪声虽按实物标定，仍无法覆盖全部动力学效应。这些边界在引用「Sim2Real 落差」时都要带上。

6. 任务设计依据与泄漏边界

几个设计选择值得单独说明。目标单元用类别名词，属性与空间描述不进入目标串，这是早期语义导航的共识口径：14 个目标类别保证每个场景都有实例，成功统计才有稳定分母；属性、空间关系与自由文本描述留给开放词汇篇章（第 061 讲起）。奖励取成功 +5 与每步 −0.01，比例让智能体在数十步量级内权衡搜索与接近；若步惩罚增大，策略会倾向提前停止，误停率上升，这一点与第 077 讲检测噪声下的误停分析同源。难度按最短路径分位划档，用途不止于分层报告：过拟合实验说明分档还能揭示失败机制，hard 档成功率掉到 50% 而 easy 档保持 100%，说明记忆在长路径上先失效。

泄漏边界有三条。第一，共享墙体布局的公寓在房间功能与家具摆放上完全不同，布局复用本身不构成捷径；第二，训练与评测的物体实例严格不重叠，复现时若放宽，仿真难度会系统性偏低；第三，test-dev 只公开 4 个场景，论文实验用其中 2 个，正式比较应使用全部 4 个并报告区间，否则场景差异会被误读为方法差异。三条边界对应的核验方法都在上一节的清单里。

关键代码与解读

三段代码对应配对评测的三件工具：难度分档与判分、配对 episode 管理、远程评测适配层。

片段 1：难度分档与成功判据

import numpy as np

def difficulty_of(sp_len, all_lens):
    """按最短路径分位划档：最短 20% 为 easy，20% 至 60% 为 medium。"""
    rank = float(np.mean(np.asarray(all_lens) <= sp_len))
    if rank <= 0.20:
        return "easy"
    if rank <= 0.60:
        return "medium"
    return "hard"

def episode_success(stopped, target_visible, distance, threshold):
    """三项同时成立才成功：显式停止、停止帧可见、距离达标。"""
    return bool(stopped and target_visible and distance <= threshold)

解读：（1）分档在场景内计算，跨场景比较前要先确认分位基数一致，否则同一起点在不同场景会被分到不同档。（2）判据三项缺一不可，可见性使用停止帧的严格口径；实现时最容易出错的是把「进入过可见范围」当成「停止帧可见」，两者对失败的统计差异很大。（3）距离阈值必须写成参数并在报告中注明，跨基准比较时先对齐阈值与可见性定义。

片段 2：配对 episode 管理

def paired_specs(scenes, seeds, waypoints):
    """生成仿真与真机共享的 episode 规格；键相同才可配对。"""
    specs = []
    for scene in scenes:
        for wp in waypoints:
            for seed in seeds:
                key = (scene, wp, seed)
                specs.append({"key": key, "scene": scene,
                              "waypoint": wp, "seed": seed})
    return specs

def record(store, key, platform, metrics, log):
    """按 key 写入两侧结果；缺一侧的条目在分析阶段剔除。"""
    store.setdefault(key, {})[platform] = metrics
    log.append({"key": key, "platform": platform,
                "metrics": metrics})

def paired_pairs(store):
    """只返回两侧齐全的配对；数量必须等于提交总量的两侧交集。"""
    return [(k, v["sim"], v["real"]) for k, v in store.items()
            if "sim" in v and "real" in v]

解读：（1）配对键由场景、路点、种子三元组构成，缺一不可；只按种子配对会在多场景轮流调度时错位。（2）记录函数允许单侧先到，分析前统一过滤，避免真机失败轮次被静默丢弃。（3）配对数量要回查：真机侧若因超时缺档，SRCC 与落差都会偏乐观，分析日志须保留缺失原因。

片段 3：远程评测适配层

import time

def run_remote_episode(client, model_id, spec, poll_s=5.0, timeout_s=900.0):
    """通过平台文档定义的 HTTP 端点提交并轮询；单条可达数分钟。"""
    job = client.post("episode", {"model": model_id,
                                  "scene": spec["scene"],
                                  "seed": spec["seed"]})
    t0 = time.time()
    while time.time() - t0 < timeout_s:
        state = client.get(f"episode/{job['id']}")
        if state["state"] == "finished":
            return state["metrics"]          # 停止、距离、可见性、SPL
        if state["state"] == "error":
            raise RuntimeError(state["reason"])
        time.sleep(poll_s)                   # 轮询间隔与单条时长匹配
    raise TimeoutError(job["id"])

解读：（1）用 client 抽象隔离端点细节，路径以平台文档为准，便于换平台；（2）超时属于真机评测的常态，超时条目要按缺失处理并在报告中单列；（3）轮询间隔取秒级，过密会挤占评测机的网络与调度资源。

常见坑

  • 把配对当逐像素一致：症状是认为实物孪生就等于仿真视觉。根因是实例、光照与传感噪声仍不同，846 张配对图像的特征降维后两域分离。修复：用配对图像做特征距离与检测 mAP 抽查，确认域差量级后再部署。
  • 混用可见性口径：症状是把 RoboTHOR 的严格可见性与 Habitat 的 oracle 可见性放在同一张表里。根因是两者对「同一位置是否算看到目标」的判定不同。修复：报告里注明基准名与判据；跨基准比较只谈机制。
  • 转向角与动作集混排：症状是直接把 RoboTHOR 的 45° 转向结果与 Habitat 30° 的设置比较。根因是动作粒度不同会改变最短路径与 SPL 基线。修复：对齐动作集与角度后再比较，或分表呈现。
  • 小样本真机读数外推：症状是用 2 个 test-dev 场景的结果给方法排名。根因是场景数少、起点分布窄、单条 episode 长达数分钟。修复：报告场景数、episode 数与置信区间；用 385 条的样本量口径规划确认性实验。
  • 忽视吞吐瓶颈：症状是提交几百条 episode 后才意识到排队与超时。根因是单条可达 10 分钟，调度器共享。修复：本地仿真预筛到 10 至 20 个候选，真机只跑配对确认与消融的最小集。

练习与思考

  1. 复算 easy 档的成功率相对下降与 SPL 保持率，并解释为什么 SPL 的落差远大于成功率。★
    提示
    SR 相对下降 (55.30 − 33.33) / 55.30 = 39.73%；SPL 保持 3.53 / 38.12 = 9.26%。成功率只要求最终停对，容错来自探索运气；SPL 同时惩罚步数与绕路，真机控制误差与保守试探会持续累积，所以掉得更狠。
  2. 用 8.8 m × 3.9 m 的空间承载 14 个配对场景，说明需要多少次重配置、累计多少时间；若每次重配置含 10 分钟校验，总成本是多少？★
    提示
    14 个场景各重配置一次约 30 分钟，共 7 小时；加校验 10 分钟每个共 140 分钟，合计约 9.3 小时。若一天只重配一个场景，则 14 天，说明规模化依赖单空间多场景轮换与并行资产准备。
  3. 分析过拟合实验：为什么 easy 与 medium 的成功率能保持高位而 SPL 大幅下降？给出至少两条机制并设计验证实验。★★
    提示
    机制一：场景记忆让智能体知道目标方位，停止决策正确概率高，但真机控制误差让轨迹效率下降；机制二：真机感知延迟使接近过程更保守，步数增加。验证：记录每步与目标的距离曲线与转向次数，对比仿真与真机的接近段长度；若仿真接近段短而真机接近段长，则机制二成立。
  4. 为自建配对平台写一份核验清单的执行方案：指定相机、动作、碰撞、判据、重置五项的测量步骤与通过标准，并说明任一项未通过时的降级路径。★★★
    提示
    相机：标定板测内参与视场，差超 5° 时在训练期加视场增广。动作：各动作重复 50 次得位移与转角分布，均值偏差超 5% 时改用闭环控制。碰撞：贴墙测试确认即停语义，否则关闭仿真滑动。判据：构造可见性临界样例双侧验判，不一致时以严格口径重写。重置：配对日志逐条核对起点与种子，缺项重跑。降级路径统一指向「先测边缘案例，再扩规模」。
  5. 若要在该平台上验证第 080 讲的某个开放词汇方法，写出最小评测方案：模型数量、两侧 episode 数、判据对齐方式与统计口径。★★
    提示
    最小方案：2 至 3 个方法对照（含一个基线）；仿真侧按场景与起点分层抽取 300 条，真机侧按 385 条方案取其子集；判据对齐为停止帧可见加距离阈值；统计报成功率与 SPL 的配对差值与区间，暂不报 SRCC（方法数不足）。若只做可行性验证，可先跑 97 条把半宽控制在 10 个百分点。

小结

  • RoboTHOR 用 89 个公寓（75 训练验证、4 test-dev、10 test-standard）与 15/2/5 三种布局层构建配对语料；14 个配对场景建在 8.8 m × 3.9 m 的模块化空间里，重配置约 30 分钟，材料成本约 1 万美元。
  • 协议：目标类别名词、显式停止、停止帧可见与距离阈值三条件；人类中位 49.5 步对最短路径 22.0 步；训练 100,000 条 episode、8 张 TITAN X、A3C 32 线程；致动噪声按实物标定。
  • 主读数：easy 档 SR 55.30 到 33.33（−39.73%），SPL 38.12 到 3.53（保持 9.26%）；medium SR 28.79 到 16.66，SPL 保持 19.35%；落差集中在路径效率。
  • 过拟合实验：记忆场景后 easy 与 medium 成功率仍在 83% 以上，SPL 保持率仅 14.94% 与 21.68%；hard 成功率降到 50.00，长路径被控制误差侵蚀。
  • 落差解剖：846 张配对图像特征分离；检测 mAP 真机 0.338 对仿真 0.255；视场 90° 到 42.5° 时真机 easy 仅 16%；CycleGAN 翻译后成功率为 0%。
  • 远程评测链路为提交、调度、执行、回传四段，定位仅用于判分；单条可达 10 分钟，385 条约需 64 小时机器人时间。下一讲读 2020 年挑战的现实化改造，把本讲平台变成去特权、带噪声的真机测试场。
