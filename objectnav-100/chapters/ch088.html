第五篇 · 真机、Sim2Real 与系统集成

第 088 讲｜HomeRobot OVMM

开放词汇移动操作（Open-Vocabulary Mobile Manipulation, OVMM）的任务指令形如「把物体从起始容器搬到目标容器」：机器人在未知的单层住宅中任意抓取一个未见过的物体，放到指定的容器上（Yenamandra 等，2023，HomeRobot OVMM，arXiv:2306.11565 v2）。HomeRobot 给出配套的仿真与真机双基准：仿真侧用 HSSD 场景与聚合自四个来源的物体集，真机侧用 Hello Robot Stretch 在受控三居室公寓中评测。论文用四个阶段给分，找物、抓取、找容器、放置，全部完成才算整幕成功，部分成功指标取四阶段平均。基线结果两极化：真机上启发式与强化学习基线总体成功率为 15% 与 20%（各 20 幕），仿真里最优技能组合在真值分割下部分成功指标 48.3%、总体成功率 14.8%，同一组合把分割换成开放词汇检测器 DETIC 后部分指标降到 9.6%、总体成功率降到 0.4%。本讲逐条梳理任务规范、数据口径与判据，并做实算核对。

  • 主题：OVMM 任务定义 / 四阶段判据 / HSSD 数据 / 仿真与真机双基准 / 评测统计
  • 关键公式：S = ∏k=1..4 Sk；Partial = (1/4)·Σk=1..4 SRk
  • 预计学时：85 分钟
  • 前置章节：第 087 讲（Stretch 与连续动作）

学习目标

  • 理解：说清 OVMM 的任务形式、为什么它在 ObjectNav 之外增加操作维度，以及「开放词汇」在物体与容器两侧的分布假设。
  • 会推导：写出四阶段成功率的链式结构，说明部分成功指标为什么是累计通过率的平均，并验证论文表格的恒等关系。
  • 会算：复算真值分割与 DETIC 分割的差额、真机 20 幕的区间估计，以及数据集三档划分的占比与两处「三分之二」规则的交叉核对。
  • 会设计：为仿真与真机两套评测整理对照表，标注判据、预算、视野与感知来源的差异，并给出不可混排的事项清单。
  • 会判断：识别样本量、场景计数、感知替换与部分指标四类误读，避免把小样本真机差异当作算法结论。

背景与动机

本课从第 001 讲的 ObjectNav 出发，主线一直是「找到物体并停下」。第 087 讲的 Stretch 配置把本体与动作接口推近真机，任务本身仍未要求接触物体。HomeRobot 把这层限制打开：目标从「看到」变成「拿起来并放到指定位置」，任务同时包含感知、语言理解、导航、抓取与放置五个子问题，以及把五个子问题整合起来的系统问题。论文给出的定义覆盖任意物体与任意未见环境，这使任务的评测难度远高于单房间、特定物体集与离散动作的既有设定。

为什么需要一个统一基准。论文对既有工作的评价很直接：先前研究大多用离散动作、有限物体集或单房间环境简化移动操作；不同实验室的硬件与场景各异，方法之间难以复现比较（Yenamandra 等，2023）。HomeRobot 的应对是提供标准硬件 Hello Robot Stretch 与标准软件栈，让真机实验跨实验室可复制，同时给出对应的仿真组件用于训练与快速迭代。本讲负责任务与基准规范，第 089 讲拆解软件栈，第 090 讲用竞赛回顾检验这套基准的不足。

核心原理

1. 任务形式化与四阶段结构

任务是形如「Move (object) from the (start_receptacle) to the (goal_receptacle)」的指令。物体是小件可操作物品（杯子、毛绒玩具、盒子等），起始容器与目标容器是家具类大件，提供可放置表面。机器人被放入未知的单层住宅，已知信息只有三个名称：起始容器、目标物体、目标容器；起始容器一定存在且物体确定在其上，这一点降低了「找物」阶段的不确定性。整幕成功的定义是：指定的物体确实从它本幕开始所在的起始容器，被移动到任意一个合法的目标容器上；满足条件的物体实例可能有多个。

过程按四个阶段计分，依次为找物（FindObj）、抓取（Pick）、找容器（FindRec）、放置（Place）。整幕成功是四阶段的合取：

S = SFindObj ∧ SPick ∧ SFindRec ∧ SPlace，即 S = ∏k=1..4 Sk（以 0/1 指示变量表示）

部分成功（partial success）作为并列时的决胜指标，每个阶段完成记 1 分，按阶段数归一：

Partial = (1/4)·Σk=1..4 SRk

把四个阶段率理解为沿链条递减的累计通过率：SRPick 是「找到物体并完成抓取」的比例，SRFindRec 是再加上「找到目标容器」的比例，SRPlace 是四阶段全部完成的比例，也就是总体成功率。相邻两率相除即得该阶段的条件通过率；这个结构意味着链条后段的数值天然偏低，解读时要做条件概率拆解，这一方法沿用了第 033 讲的失败解剖思路。

2. 数据构造：场景、物体与容器

仿真场景来自 Habitat Synthetic Scenes Dataset（HSSD，Khanna 等，2023）：200 余个人工设计的三维住宅场景，含一万八千余个模型。OVMM 实验使用其中 60 个补齐了重排（rearrangement）元数据与仿真结构的场景，按原数据集划分分为训练 38、验证 12、测试 10。物体由四个来源聚合：AI2-THOR、Amazon-Berkeley Objects、Google Scanned Objects 与 HSSD 本身；作者共标注 2,535 个可操作物体、129 个类别，另识别 21 个容器类别。论文表 1 的对照口径为 200 个场景、150 个类别、7,892 个实例，与实验口径存在两处差异，下面逐项对齐。

episode 生成保证三件事：物体可导航到达（机器人能接近容器）、可抓取（机械臂能够到物体）、目标容器可导航到达且可放置。生成流程先取每个场景最大的室内可导航区域，过滤放不下物体的过小容器，按当前划分采样物体，用物理仿真确认放置稳定，最后为每个容器生成候选视点，代表机器人可以观察容器并停靠的导航位置，视点在 1.5 m 以内。场景中物体数量按容器可用面积动态设定，取每平方米 1.5 至 2 个：面积 10 m2 时放置 15 至 20 个物体，具体数量每幕随机。

3. 成功判据：仿真与真机两套定义

判据按阶段逐一定义，仿真与真机在同一个阶段上使用不同阈值与检查方式，两套判据不可互换。

两处差异需要重点关注。第一，距离口径不同：仿真的 0.1 m 是到预生成视点的距离，真机的 1 m 是到物体的距离，数值上相差一个数量级，但语义都是「进入可交互邻域」，比较时不能只看数字。第二，抓取模型不同：仿真不做物理抓取，夹爪到位即吸附，真机使用启发式抓取策略执行真实抓取；论文明确把物理抓取列入仿真局限，未来才计划替换为更严格的抓取条件。真机基准在受控的三居室公寓中进行，物体为八个类别：五个已见（杯子、碗、毛绒玩具、药瓶、玩具动物）与三个未见（魔方、玩具电钻、柠檬）；容器涉及七类：柜子、椅子、沙发、台面、水槽、凳子、桌子；每个基线跑 20 幕。

把最优组合（强化学习导航、强化学习注视、强化学习放置）从真值分割换成 DETIC 分割：找物 66.6 降到 21.7（−44.9 个百分点），抓取 61.1 降到 10.2（−50.9），找容器 50.9 降到 6.2（−44.7），放置与总体 14.8 降到 0.4（−14.4）；部分成功指标从 48.3 降到 9.6，下降 38.7 个百分点，相对降幅 80.1%。感知替换是这套基准里最大的单一损耗源，且损耗沿链条放大：前端的检测错误进入地图，后端的抓取与放置失去可靠目标。另一个值得记录的交叉项：真值分割下强化学习导航的找物率 66.6，比启发式导航的 54.1 高 12.5 个百分点；换到 DETIC 后，强化学习导航的找物率 21.9，比启发式导航的 28.7 低 6.8 个百分点。论文的解释是启发式策略把带噪声的检测写入二维语义地图，多帧累积吸收单帧误检，强化学习策略直接消费分割通道，对噪声更敏感。

用条件率拆解链条能看清损失位置。最优真值组合的四段条件率为：抓取条件于找物 91.7%、找容器条件于抓取 83.3%、放置条件于找容器 29.1%，按 0.666 × 0.917 × 0.833 × 0.291 = 14.8% 相乘，与总体一致。瓶颈集中在放置：进入容器邻域后只有不到三成的尝试成功放下物体。同一行换 DETIC 后，三段条件率变为 47.0%、60.8% 与 6.5%，感知噪声同时压低三段，放置段几乎归零。这两个条件率向量的对照可直接用作失败归因模板。

真机结果（每个基线 20 幕）：启发式 70 / 35 / 30 / 15，强化学习 70 / 45 / 30 / 20。强化学习多完成 1 幕，总体高 5 个百分点，增益来自抓取与放置两个子任务：注视技能改善了对齐，放置技能让物体更贴近容器表面。20 幕的粒度是每幕 5 个百分点，用 Wilson 区间看：4/20 的 95% 区间为 [0.081, 0.416]，3/20 为 [0.052, 0.360]，两区间大幅重叠，1 幕之差在这套样本量下不构成方法结论。真机的找物率两臂同为 70%，说明在这间受控公寓里，导航找物不构成两臂差异来源。把真机 20% 与仿真数字并排时同样要注意口径：仿真最优组合总体 14.8%、部分指标 48.3%，其场景规模、预算与感知来源都与真机评测不同，单个数字的高低不能推出方法优劣。

5. 基准定位与边界

论文表 1 把 OVMM 与导航、重排、操作类基准并排比较，差异集中在四点：支持连续动作、提供真机与仿真迁移路径（sim2real）、提供跨实验室可复用的机器人软件栈、使用开放许可。同表中 Habitat ObjectNav 挑战为 216 个场景、6 个类别、7,599 个实例，不支持操作；VirtualHome 与 ALFRED 支持操作但动作离散、无真机栈；Behavior-1K 支持操作与连续动作，论文标注其无机器人软件栈与仿真到真机路径。这四点构成了 OVMM 的增量，也解释了为什么它要自带硬件与软件栈。

边界如实列出。第一，仿真不做物理抓取，物体在夹爪到位后被吸附，抓取的真实难度只在真机侧出现；论文尝试过更严格的抓取条件（机械臂靠近物体且不与场景碰撞），一个自上而下加侧向回退的基线在从物体视点出发时有 79% 能碰到物体，但全程无碰撞的比例只有 47%。第二，自然语言查询被明确排除在外，指令为结构化的三个名称，句法泛化不在评测范围。第三，仿真里的低层规划依赖导航网格与固定的地图更新，不处理动态障碍。第四，真机基准的场景规模小于仿真公寓，两类结果不做直接排名。这些边界与第 089 讲的软件栈局限互为表里。

口径提醒：场景数、类别数与实例数各有两个版本

实验用 60 个场景、2,535 个物体、129 个类别；表 1 的宣传口径为 200 个场景、7,892 个实例、150 个类别。两套数字都正确，混用会放大或缩小任务规模。写作与开题引用时先注明用的是哪一套。

关键代码与解读

三段代码对应本讲的三个核心机制：状态机与阶段账本、仿真与真机的阶段判定函数、部分指标与区间估计。接口按论文定义做教学化命名。

片段 1：四阶段状态机与账本

STAGES = ("FindObj", "Pick", "FindRec", "Place")

class OVMMAgent:
    """按论文定义依次调用四个技能，账本记录每阶段成败。"""
    def __init__(self, skills, episode):
        self.skills = skills                 # FindObj/Gaze/Pick/FindRec/Place
        self.episode = episode               # 含起始容器、物体、目标容器
        self.ledger = {s: False for s in STAGES}

    def run(self):
        obs = self.skills["FindObj"](self.episode)
        if obs is None:
            return self.ledger              # 找物失败，后续阶段不执行
        self.ledger["FindObj"] = True
        obs = self.skills["Gaze"](obs)       # 注视只影响抓取质量
        if self.skills["Pick"](obs):
            self.ledger["Pick"] = True
        else:
            return self.ledger
        obs = self.skills["FindRec"](self.episode)
        if obs is None:
            return self.ledger
        self.ledger["FindRec"] = True
        self.ledger["Place"] = bool(self.skills["Place"](obs))
        return self.ledger                   # 四阶段全真才是整幕成功

解读：（1）账本让部分成功可计算，同时保留每个阶段的原始判定，便于按条件率拆解；技能顺序与论文的状态机一致，注视（Gaze）不单独计分，服务抓取成功率。（2）任一步失败即返回，后段判定以前段成功为前提，报告时必须写清「条件于前段成功」。（3）整幕成功等于账本全真；步数上限由外层环境控制，账本不承担超时判定，避免双重计数。

片段 2：仿真与真机的阶段判定

def stage_find_obj(sim, agent, episode, mode="sim"):
    """找物判定：仿真看视点距离与像素占比，真机看 1 m 与可见性。"""
    if mode == "sim":
        d = distance(agent.position, nearest_viewpoint(episode, "obj"))
        frac = pixel_fraction(agent.rgb, episode.obj_instance)
        return d <= 0.1 and frac >= 0.001
    d = distance(agent.position, episode.obj_position)
    return d <= 1.0 and object_visible(agent.rgb, episode.obj_name)

def stage_place(sim, agent, episode, mode="sim",
                lin_thr=5e-3, ang_thr=5e-2, hold=50):
    """放置判定：仿真看接触与速度阈值持续步数，真机看稳定落放。"""
    if mode == "sim":
        contact = object_on_receptacle(sim, episode.obj_instance,
                                       episode.goal_receptacle)
        quiet = (object_lin_vel(sim) < lin_thr and
                 object_ang_vel(sim) < ang_thr)
        return contact and quiet and sim.hold_counter(hold) == hold
    return object_settled(agent, episode.obj_name, episode.goal_receptacle)

解读：（1）用 mode 显式区分两套判据，任何把两个分支合并为「距离小且稳」的写法都会产生口径混合的隐形错误。（2）仿真的 0.1 m 与 0.1% 像素是论文附录数值，真机的 1 m 与可见性是另一套数值，参数化之后可以独立演进，但报告必须绑定版本。（3）放置的速度阈值与持续步数只对仿真物理状态有定义，真机用稳定性检查替代，两者输出都是布尔值，供账本统一消费。

片段 3：部分指标、条件率与区间估计

import math

def partial_metric(fo, pk, fr, pl):
    """四阶段率的算术平均，论文表 3 的部分成功指标。"""
    return (fo + pk + fr + pl) / 4.0

def conditional_chain(fo, pk, fr, pl):
    """把四阶段率还原为条件率链，定位损失段。"""
    return {"Pick|FindObj": pk / fo, "FindRec|Pick": fr / pk,
            "Place|FindRec": pl / fr, "Overall": pl}

def wilson_ci(k, n, z=1.959964):
    """小样本比例区间，真机 20 幕场景的报告口径。"""
    p = k / n
    denom = 1.0 + z * z / n
    center = (p + z * z / (2 * n)) / denom
    half = z * math.sqrt(p * (1 - p) / n + z * z / (4 * n * n)) / denom
    return (max(0.0, center - half), min(1.0, center + half))

if __name__ == "__main__":
    print(partial_metric(66.6, 61.1, 50.9, 14.8))   # 48.35
    print(conditional_chain(70, 45, 30, 20))        # 真机 RL 链条
    print(wilson_ci(4, 20))                         # [0.081, 0.416]

解读：（1）部分指标必须与总体成功率同时报告，单独引用会掩盖放置段的低通过率；恒等式复算（四率平均）也可以作为数据录入自检。（2）条件率链把总损失分配到具体阶段，配合感知替换的对照即可区分算法问题与感知问题。（3）Wilson 区间用于 20 幕这类小样本，报告时给出区间、不报单点；两臂区间重叠时不做胜负声明。

常见误区

  • 混用仿真与真机的评测口径：症状是把真机 20% 与仿真数字直接排名。根因是仿真用 0.1 m 视点口径、真机用 1 m 物体口径，预算相差 4 倍以上（1,250 对 300），感知来源也不同。修复：先统一判据再比较；跨环境只讨论机制，不出排序结论。
  • 把部分指标当主指标：症状是引用部分指标 48.3 而忽略总体成功率 14.8，把链条前段的高通过率当成方法能力。根因是部分指标平均了门槛不同的四个阶段，数值偏高。修复：主指标用总体成功率，部分指标只做决胜与诊断。
  • 场景与类别计数混用：症状是声称评测用 200 个场景或 150 个类别。根因是实验口径 60 个场景、129 个可操作物体类别与表 1 宣传口径 200 个场景、150 个类别（含容器）并存。修复：引用时注明口径；涉及评测规模时只用实验口径。
  • 从小样本真机结果下方法结论：症状是「强化学习比启发式高 5 个百分点」被当作定论。根因是 20 幕粒度下每幕 5 个百分点，4/20 与 3/20 的 Wilson 区间大幅重叠。修复：报告区间；扩样本或改用配对设计后再下结论。
  • 把 DETIC 落差记在算法账上：症状是成绩下滑被归因于导航或抓取策略退化。根因是同一技能组合下，感知替换使总体成功率下降 14.4 个百分点、部分指标下降 38.7 个百分点，且前段误差沿链条放大。修复：固定感知来源比较算法，固定算法比较感知；两者分表报告。

练习与思考

  1. 用四阶段率（66.6、61.1、50.9、14.8）复算部分成功指标，并验证它等于四率的算术平均。★
    提示
    (66.6 + 61.1 + 50.9 + 14.8) / 4 = 193.4 / 4 = 48.35，论文写作 48.3，属于四舍五入。
  2. 把同一技能组合（RL-RL-RL）在真值与 DETIC 两种感知下的条件率链都算出来，指出感知替换对哪一段的绝对损失最大。★★
    提示
    真值链为 91.7%、83.3%、29.1%；DETIC 链为 47.0%、60.8%、6.5%。绝对损失最大的是抓取段（61.1 降到 10.2，损失 50.9 个百分点），放置段的条件率降到 6.5%，几乎归零。
  3. 真机 20 幕、每臂基线成功率分别为 15% 与 20%，计算两臂的 Wilson 区间，判断 5 个百分点差异是否可辨，并给出把区间压缩到 ±0.1 所需的大致幕数。★★
    提示
    3/20 区间 [0.052, 0.360]，4/20 区间 [0.081, 0.416]，重叠明显。p 接近 0.5 时半宽 0.1 约需 97 幕；p 约 0.2 时所需幕数更大，且要用配对或分层设计控制场景差异。
  4. 设计一个「感知来源」两因素实验：因素 A 为真值分割与 DETIC 两档，因素 B 为启发式与强化学习导航两档，在固定技能组合下跑 2×2 对照，写出指标表、控制变量与预期交互效应，并解释为什么交互项比主效应更能说明问题。★★★
    提示
    指标：四阶段率、总体率、部分指标、平均步数。控制变量：同场景划分、同随机种子、同目标采样、同注视与放置技能。预期交互：真值下强化学习导航的找物率更高，DETIC 下启发式导航反超（28.7 对 21.9），两者交叉即交互效应；它说明噪声鲁棒性是方法选择的关键维度，单独看主效应会得出相反结论。
  5. 解释「起始容器保证存在且承载目标物体」这一设定对任务难度的作用，并讨论若取消该保证，四阶段率与总体成功率的变化方向。★★
    提示
    该保证把搜索范围从全屋收窄到单个容器附近，降低了找物与建图的负担。取消后找物率下降、无目标容器的状态需要新的失败模式处理，后段条件率随之改变，总体成功率下降；同时评测需要新增「目标不存在」的判定分支。

小结

  • 任务：把物体从起始容器搬到目标容器，未知单层住宅，指令为三个名称；四阶段为找物、抓取、找容器、放置，全部完成才计整幕成功，部分指标取四阶段率平均。
  • 数据：HSSD 实验用 60 个场景（38/12/10），2,535 个可操作物体、129 个类别、21 个容器类别；表 1 宣传口径为 200 个场景、7,892 个实例、150 个类别；两处「三分之二」控制类别与实例的开放程度。
  • 判据：仿真为 0.1 m 视点加 0.1% 像素、放置速度阈值 5×10−3 m/s 与 5×10−2 rad/s 持续 50 步、整幕 1,250 步；真机为 1 m 加可见性、稳定落放、300 步；两套判据不可互换。
  • 结果：真值分割下最优组合总体 14.8%、部分指标 48.3%；同一组合换 DETIC 后总体 0.4%、部分指标 9.6%，分别下降 14.4 与 38.7 个百分点；真机启发式与强化学习基线为 15% 与 20%，20 幕粒度下 1 幕之差不足以下结论。
  • 诊断：条件率链显示放置段是主要瓶颈（真值下 29.1%，DETIC 下 6.5%）；感知替换与导航方法存在交互，DETIC 下启发式找物率反超强化学习 6.8 个百分点。
