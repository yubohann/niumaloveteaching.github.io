第五篇 · 真机、Sim2Real 与系统集成

第 089 讲｜HomeRobot 软件栈

第 088 讲定义了 OVMM 的任务与赛道，本讲拆开它的软件栈。HomeRobot（Yenamandra 等，2023，HomeRobot OVMM，arXiv:2306.11565 v2）的基本主张是：同一套 Agent 接口、同一组技能定义、同一份任务配置，既能在 Habitat 仿真里运行，也能驱动真机 Hello Robot Stretch。代码被拆成三个仓库：home_robot 存放共享组件，home_robot_sim 提供基于 Habitat 的仿真环境，home_robot_hw 提供机器人端的服务进程与工作站端的客户端接口。观测、动作与技能序列在两个世界里对齐，高层策略只调用 FindObj、Gaze、Pick、FindRec、Place 五个技能。本讲沿「分层、接口、状态机、替换清单」四条线展开，并复算两组关键结果：真机 20 次试验中启发式与强化学习基线总体成功率为 15% 与 20%；仿真中把真值分割换成 DETIC 后，最优技能组合的总体成功率从 14.8% 降到 0.4%（同文表 3，HSSD 测试场景）。

  • 主题：统一控制栈 / Agent-Environment 接口 / 技能状态机 / 仿真与真机映射 / 评测口径
  • 关键公式：Partial = (1/4)·Σk=1..4 SRk；仿真预算 1250 步、真机预算 300 步
  • 预计学时：80 分钟
  • 前置章节：第 088 讲（HomeRobot OVMM）

学习目标

  • 理解：说清三仓库分层与 Agent-Environment 解耦，指出统一接口在仿真与真机两侧的边界。
  • 会推导：写出部分成功（partial success）指标的表达式，说明四阶段成功率为何沿链条递减，并解释它与总体成功率及条件通过率的关系。
  • 会算：复算真机与仿真两组结果，量化感知替换（真值分割换成 DETIC）对不同技能组合的差异化影响。
  • 会设计：为跨仿真与真机的控制栈整理接口表与参数表，标明哪些部件保持、哪些部件替换、替换依据是什么。
  • 会判断：识别位姿依赖、圆柱碰撞模型、导航与操作模式切换、网络时序四类失效边界。

背景与动机

第 088 讲回答了「考什么」：任务指令是「把物体从起始容器搬到目标容器」，成功判据按四个阶段给分。它没有回答「用什么考、如何保证两个世界可比」。如果仿真与真机各写一套代码，跨实验室复现的成本会集中落在环境搭建与接口对齐上，结果差异也无法归因到算法本身。HomeRobot 的工程选择是把任务结构放在环境侧，把策略放在智能体侧，两侧通过统一的观测与动作空间通信；仿真侧用 Habitat 与导航网格，真机侧用 ROS 与 Stretch，平台差异被限制在环境实现内部。

本讲在第五篇中的位置如下：088 讲任务与赛道，089 讲软件栈，090 讲用竞赛回顾检验该栈的不足，091 讲另一个平台的基础设施。学完本讲，读者应能判断一个新平台接入这套范式需要改动哪些部件、哪些参数必须先标定、哪些结果不能跨口径比较。核心结论先行：统一接口能保住任务模型与技能结构，无法保住感知与控制，感知替换是仿真到真机损失的主要来源。

核心原理

1. 三层结构与算力分工

Stretch 没有板载 GPU，算力分层是这套栈的前提。机器人端运行低层控制器与定位模块，工作站端运行高层的感知与规划，两者通过一台专用路由器连接（论文使用消费级路由器，建议专网专用）。软件被拆成三个仓库：home_robot 提供共享组件，包括环境接口、控制器、检测与分割模块；home_robot_sim 提供基于 Habitat 的仿真环境；home_robot_hw 提供机器人端服务进程、工作站端客户端接口，以及基于客户端接口构造的环境。功能上再分为两层：Agent 承载策略，Environment 提供观测并执行动作。这层划分与强化学习基准的常见结构一致，也是仿真与真机能够互换的原因。

真机侧的两个运行细节决定栈的可用性。第一是模式切换：Stretch 的机械臂朝行进方向的右侧伸出，无法在看向行进方向的同时操作目标，因此栈定义导航模式（相机朝前，反应式控制，可原地旋转与后退）与操作模式（相机朝臂，基座不再旋转，作为额外的侧向自由度参与操作）。第二是时序纪律：机器人执行完多数导航动作后停下，等待与命令时刻匹配的新观测再继续；机器人的时钟通过 ROS 主时钟（ROS master clock）发布给全网使用，避免工作站与机器人时间不一致造成位姿与深度错配。调试依赖 RVIZ，地图、点云与相机画面都能在工作站侧可视化。

2. 观测、动作与两种控制粒度

策略的观测包含头部深度、语义分割、相对起始位姿（真机由 SLAM 提供）、相机位姿、关节与夹爪状态。RGB 可获取，强化学习基线在训练时未直接使用。动作空间提供两种粒度：离散动作包括固定角度的原地旋转与 0.25 m 的前进；连续动作要求策略输出机体坐标系下的局部短期目标航点，由低层控制器执行。仿真里连续动作按瞬移实现：用导航网格检查路线是否与物体碰撞，若碰撞则把目标吸附到最近的合法位置，不为此模拟完整物理。真机里由速度控制器执行：始终朝向目标位置移动，到达位置后再旋转到目标朝向，速度用梯形轮廓生成，并附加防超调的条件检查。

两种粒度服务不同技能。强化学习基线的导航技能用离散动作，实验观察它对探索更友好且更容易训练；操作技能用连续动作，以获得细粒度控制。真机对运动有物理上限，仿真据此设定单步幅度：基座前进 10 至 25 cm、转角 5 至 30 度，头部与夹爪单步变化 0.02 至 0.1 弧度，臂的伸展与升降单步 2 至 10 cm；训练时直接把基座与臂瞬移到目标位姿。统一接口的收益在于高层策略只输出「去哪里」，运动学与安全性留给低层控制器。

at ∈ {stop, 前进 0.25 m, 左转, 右转} （离散）　或　at = (Δx, Δy, Δθ)（连续航点）

3. 技能状态机与部分成功指标

OVMMAgent 是按顺序调用技能的有限状态机：FindObj（在起始容器上定位物体）、Gaze（接近并调整头部对准目标，提高抓取成功率）、Pick（抓取）、FindRec（定位目标容器）、Place（放置）。真机侧 Pick 由库提供的高层抓取策略完成，仿真侧不模拟夹爪交互。仿真成功判据逐阶段定义：FindObj 要求到达目标物体视点 0.1 m 以内且目标实例像素占比不低于 0.1%；Pick 要求物体可见时闭合夹爪且末端执行器距目标 0.8 m 以内，随后物体吸附到夹爪；FindRec 要求到达目标容器视点 0.1 m 以内且容器像素占比不低于 0.1%；Place 要求释放后物体与容器保持接触 50 步，且线速度低于 5e-3 m/s、角速度低于 5e-2 rad/s，放置过程无碰撞；整幕预算 1250 步。真机判据放宽到 1 m 距离加 RGB 可见性，预算 300 步。

竞赛与论文使用部分成功作为先行指标，定义为四个阶段累计通过率的算术平均：

Partial = (1/4) · Σk=1..4 SRk，SRk = P(前 k 个阶段全部通过)

因为后一阶段以上一阶段成功为前提，SRk 沿 k 递减，总体成功率等于第四阶段率；相邻两率相除可得该阶段的条件通过率。用论文表 3 做数值核验：真值分割下启发式导航配启发式操作的四项为 54.1 / 48.5 / 31.5 / 5.1，均值 (54.1+48.5+31.5+5.1)/4 = 34.8，与报告值一致；强化学习全程组合为 66.6 / 61.1 / 50.9 / 14.8，均值 48.35，报告 48.3；DETIC 感知下该组合为 21.7 / 10.2 / 6.2 / 0.4，均值 9.625，报告 9.6。该指标衡量「推进到哪一步」，不衡量「完成整条链」，两类信息的比值随感知质量下降而放大：真值全程组合为 48.3/14.8 ≈ 3.26 倍，而 DETIC 启发式组合为 12.4/0.4 = 31.0 倍。

4. 仿真到真机的替换清单与证据

保持不动的部分包括任务模型、技能顺序、Agent 接口、地图与规划逻辑，以及一批与平台无关的参数。被替换的部分有四项：感知由真值分割换成 DETIC；位姿由仿真真值换成 Hector SLAM；底层运动由导航网格瞬移换成梯形速度控制器；抓取由瞬移吸附换成体素启发式策略。训练观测另有分辨率差异：强化学习策略在 160×120 图像上训练，而 Stretch 头部相机原生分辨率为 640×480，像素数相差 16 倍，部署时若忽略缩放会引入分布偏移。

真机证据来自受控公寓内的 20 次试验（每条基线）。启发式基线的阶段成功率为 FindObj 70%、Pick 35%、FindRec 30%、总体 15%；强化学习基线为 70%、45%、30%、20%。两队的入口 FindObj 相同，差距出现在抓取与放置：强化学习的 Gaze 技能改善了对准，Place 技能让物体更贴近容器表面，总体多出一个成功回合（20 次中 3 次对 4 次）。仿真证据更直接：HSSD 测试场景上，真值分割下的最优组合为 66.6 / 61.1 / 50.9 / 14.8，切换 DETIC 后降到 21.7 / 10.2 / 6.2 / 0.4，入口 FindObj 单项下降 44.9 个百分点。启发式入口在 DETIC 下降 25.4 个百分点，但整体退化较小（总体 5.1 到 0.4），论文归因于二维语义地图对检测噪声的平均作用：小目标归类不稳时，多帧累计比单帧判决更稳。

边界要写清：真机每组只有 20 次试验，绝对值不宜外推；仿真与真机的差距不是单一因素，感知、定位、控制各贡献一部分，本讲只能依据替换清单做结构性归因，不能做定量分解。

5. 真机栈的失效边界

该栈的定位依赖外部 SLAM，位姿漂移会直接污染语义地图与规划；系统不支持动态障碍；碰撞模型把机器人当成圆柱，而 Stretch 的旋转中心与圆柱中心略有偏移；规划器基于 5 cm 离散化的快速行进法，无法考虑朝向，接近物体与避障之间需要额外调参。语义地图的规格为：格子边长 5 cm（单格面积 25 cm²），通道数 K = C + 4，其中 C 为语义类别数，其余四个通道分别表示障碍、已探索区域、当前位置与历史位置。地图在每幕开始时清零，机器人位于中心并朝向东方。

设计取舍

为何抓取采用启发式策略：论文比较过若干公开抓取模型（Contact-GraspNet、6-DoF GraspNet、GraspNet-1Billion），在调整抓取偏移适配 Stretch 夹爪几何后，仍观察到更多由传感器噪声引起的间歇失败；体素启发式在透明性与复现性上占优，且实测成功率与这些模型相当。为何强化学习导航在仿真里表现更好、在 DETIC 下又输给启发式：强化学习策略直接消费分割输入，对检测噪声敏感；启发式通过语义地图累积观测，对单帧错误有容忍度。这一分歧是第 090 讲「感知与决策整合」主题的直接证据。

关键代码与解读

以下片段按论文流程重写为教学实现，函数名非库内原始接口名。三段分别对应统一协议、语义地图与抓取启发式。

片段 1：仿真与真机共用的环境协议

class UnifiedEnv:
    """仿真环境与真机环境实现同一接口：reset 返回观测，step 执行动作。"""
    def __init__(self, backend):
        # backend 取 "sim" 或 "hw"；两侧只差底层实现，观测字段一致
        self.backend = backend
        self.t = 0

    def reset(self):
        self.t = 0
        obs = self.backend.reset()           # 深度、分割、位姿、关节、夹爪状态
        return obs

    def step(self, action):
        # action 可为离散元组（前进/转向/停止），也可为连续短期航点
        obs = self.backend.apply(action)
        self.t += 1
        # 真机侧先等到与本次命令匹配的新观测，再交给策略
        if self.backend.is_real:
            obs = self.backend.wait_for_fresh_obs(self.t)
        # 预算在环境侧统一管理：仿真 1250，真机 300
        done = self.t >= self.backend.budget
        return obs, done

解读：（1）协议只暴露 reset 与 step，仿真与真机的差异被 backend 吸收，策略代码不需要条件分支。（2）真机分支在返回前等待「新观测」到位，避免策略拿旧图像配新位姿；这是该栈时序纪律在接口层的落点。（3）预算由环境侧统一管理，仿真 1250 步与真机 300 步的差异只体现在配置，不进入策略逻辑。

片段 2：语义地图的增量更新

import numpy as np

def update_semantic_map(map_2d, depth, seg, pose, cell=0.05):
    """把检测分割按深度反投影，累计到二维语义通道（K = C + 4）。"""
    yy, xx = np.nonzero(seg > 0)              # 命中像素
    z = depth[yy, xx]
    keep = z > 0                              # 去掉无效深度
    yy, xx, z = yy[keep], xx[keep], z[keep]
    cls = seg[yy, xx]
    # 简化针孔模型：像素加深度还原到相机系，再按位姿变换到世界系
    x_cam = (xx - 320.0) * z / 554.0
    y_cam = (yy - 240.0) * z / 554.0
    x_w = pose.x + x_cam * np.cos(pose.yaw) - y_cam * np.sin(pose.yaw)
    y_w = pose.y + x_cam * np.sin(pose.yaw) + y_cam * np.cos(pose.yaw)
    col = ((x_w - pose.origin_x) / cell).astype(int)
    row = ((y_w - pose.origin_y) / cell).astype(int)
    # 只写语义通道；5 cm 格子在室内尺度下兼顾分辨率与内存
    np.maximum.at(map_2d, (row, col, cls), 1)
    return map_2d

解读：（1）反投影依赖位姿，真机上该位姿来自 Hector SLAM，漂移会直接写进地图，这是感知外的第二误差源。（2）用「置 1」代替累加计数，配合逐格最大值语义；多次观测同一格不会把分数推向无穷，与第 079 讲多视角取最大的动机同源。（3）5 cm 是论文采用的分辨率，格子再细会增加内存与噪声敏感度，再粗会把小物体并入相邻格。

片段 3：体素启发式顶抓评分

import numpy as np

def top_down_grasp_score(points, voxel=0.005, top_ratio=0.10):
    """论文附录 E.3：顶部点云中，夹缝实、两侧空的位置得分高。"""
    # 取 Z 坐标最高的 10% 点，抓取从物体顶部垂直进入
    z_thr = np.quantile(points[:, 2], 1.0 - top_ratio)
    top = points[points[:, 2] >= z_thr]
    grid = {}
    for p in top:                              # 0.5 cm 体素化
        key = (int(p[0] / voxel), int(p[1] / voxel))
        grid[key] = grid.get(key, 0) + 1
    best = None
    for (ix, iy), cnt in grid.items():
        # 手指落在左右偏移两格的位置，中间格承载物体
        left = grid.get((ix - 2, iy), 0)
        right = grid.get((ix + 2, iy), 0)
        score = cnt - 0.5 * (left + right)     # 中间实、两侧空
        if best is None or score > best[0]:
            best = (score, (ix, iy))
    return best

解读：（1）评分三项对应论文描述：夹缝区域的占据程度越高越好，两侧手指区域的占据程度越低越好；系数 0.5 给两侧留出对称的惩罚强度。（2）先取顶部 10%，把搜索限制在自上而下的可达区域，避免对物体侧面生成不可执行的抓取。（3）体素取 0.5 cm，与 5 cm 地图格子形成两级分辨率：地图负责导航，体素负责接触级几何；调大体会合并细小结构，调小会放大深度噪声。

常见误区

  • 混排真值分割与 DETIC 的数字：症状是引用 14.8% 时未注明感知来源，与 DETIC 口径的 0.4% 混为一谈。根因是同一张结果表内两种感知输入并列。修复：引用时强制标注「真值分割」或「DETIC」，报告卡片同时给出两组。
  • 把部分成功当独立概率：症状是试图用 partial 反推总体成功率，或把四个阶段率相乘。根因是四个阶段率沿链条累计定义，后一阶段包含前一阶段，链式结构下总体率等于最末阶段率，四个率不可相乘。修复：按累计通过率理解，均值只作进度指标；需要条件通过率时用相邻两率相除；需要总体率时直接读 Place 阶段。
  • 忽略导航与操作模式切换：症状是抓取阶段频繁失败，复现日志显示相机没有对准手部。根因是 Stretch 手臂朝右，导航模式下相机朝前，两者不能同时满足。修复：接近目标后显式切到操作模式，基座作为侧向自由度参与对准，落抓前复核目标在相机中心。
  • 低估位姿依赖：症状是长走廊或多房间探索后地图出现重影，规划路径穿墙。根因是 Hector SLAM 漂移与圆柱碰撞模型偏差叠加。修复：控制单幕里程；在长直路段增加重定位检查；把动态障碍纳入规划预算，或至少在评测中单独统计其影响。
  • 网络时序与时钟不同步：症状是真机结果随机波动，复现困难。根因是机器人停止后仍收到旧观测，或工作站与机器人系统时钟不一致。修复：统一使用机器人发布的 ROS 主时钟；在接口层实现「等待与命令时刻匹配的新观测」；用 RVIZ 对照时间戳做现场排查。

练习与思考

  1. 由真值分割下强化学习全程组合的四阶段率（66.6 / 61.1 / 50.9 / 14.8）复算 partial，并说明它为何不等于总体成功率。★
    提示
    均值为 48.35，报告取 48.3。partial 是四阶段累计通过率的算术平均，衡量推进程度；总体成功率等于第四阶段率 14.8%。两者不能互推。
  2. 构造一个反例，说明两组配置可以有相同的 partial 但总体成功率相差很大；用表 3 中启发式基线与 Rulai 的数据做对照（提示：Rulai 在竞赛榜上 partial 16.8、总体 3.2；启发式 partial 17.7、总体 0.8）。★★
    提示
    Rulai 的 partial 低于启发式，总体却高 4 倍，说明两项指标关注不同阶段分布：一组在前期阶段推进广、末期转化差，另一组相反。报告结果时两项并列。
  3. 把抓取体素的边长从 0.5 cm 调到 1 cm，把顶部点比例从 10% 提到 20%，预测抓取候选数量、深度噪声敏感度与抓取成功率的变化方向，并设计 20 次真机对照。★★
    提示
    体素变大，候选格减少、抗噪增强，但细小结构被合并；顶部比例提高会纳入更低处，可能产生不可行抓取。对照：固定物体集与初始位姿，各 20 次，统计抓取成功与碰撞次数。
  4. 为「仿真训练、真机部署」设计一份验证协议：列出必须核验的接口、参数与分布差异，给出每项的检测方法与通过标准。★★★
    提示
    接口项：观测字段与坐标系、动作单位与上限、预算。参数项：地图分辨率、抓取体素、放置接近距离。分布项：图像分辨率与缩放、分割输入来源、位姿误差分布。检测：同一幕回放双端日志、对齐时间戳、统计位姿对地图的残差。通过标准按任务分阶段设置。
  5. 解释为何 DETIC 替换后启发式导航的退化小于强化学习导航（入口阶段分别下降 25.4 与 44.9 个百分点），并给出一个验证实验。★★
    提示
    启发式经二维语义地图累计多帧观测，单帧误检被平均；强化学习直接消费分割通道，噪声直接进入策略输入。实验：固定场景分片，分别用单帧分割与多帧投票合成的地图作为输入，比较入口阶段成功率。

小结

  • HomeRobot 以三仓库（home_robot / home_robot_sim / home_robot_hw）与 Agent-Environment 解耦实现统一栈：任务模型、技能顺序与 Agent 接口在仿真与真机之间保持一致，平台差异被限制在环境实现内部。
  • 观测含深度、分割、位姿与关节状态；动作支持离散（0.25 m 前进）与连续（短期航点）两种粒度；真机通过梯形速度控制器执行，并以 ROS 主时钟与等待新观测维持时序一致。
  • 技能状态机为 FindObj → Gaze → Pick → FindRec → Place；部分成功定义为四阶段累计通过率的均值，本讲对表 3 的八行做了复算，全部与报告值吻合，总体成功率等于第四阶段率。
  • 感知替换是仿真到真机损失的主要来源：真值分割换成 DETIC 后，最优组合总体率从 14.8% 降至 0.4%，入口阶段下降 44.9 个百分点；启发式入口退化较小，归因于二维语义地图的多帧累计。
  • 真机 20 次试验中，启发式与强化学习基线的总体成功率为 15% 与 20%，差距集中在抓取与放置；栈的失效边界包括位姿漂移、圆柱碰撞模型、模式切换与网络时序。
  • 下一讲用竞赛回顾检验这套栈：0.8% 到 10.8% 的改进来自错误恢复与感知决策整合，任务模型保持不变。
