第 068 讲｜VLFM II：Spot 真机零样本

第 067 讲拆解了 VLFM 的机制：深度占据图给前沿，BLIP-2 给语言价值图，检测器给目标航点，PointNav 策略给执行。本讲读同一篇论文（Yokoyama 等 2023，Vision-Language Frontier Maps，arXiv:2312.03275）的结果面与真机面。结果面：零样本 VLFM 在 Gibson、HM3D、MP3D 三个验证集上全部取得零样本最优，SPL / SR 分别为 52.2 / 84.0、30.4 / 52.5、17.5 / 36.4（论文表 I），其中 Gibson 与 MP3D 两行超过有监督方法；价值图更新消融显示，置信度加权相比直接覆盖在三个数据集上分别带来 SR +7.9、+8.0、+4.7 个百分点。真机面：同一套模块部署到 Boston Dynamics Spot，在无先验地图、无任务训练的条件下完成办公楼单层的目标搜索；执行接口换成本体导航 API，夹爪相机承担检测与价值图输入，单目深度估计模型补足量程，四个模型在 16 GB 显存笔记本上实时运行（论文 VI-C 节）。本讲以部署清单的形式回答：仿真证据支持到哪一步、真机系统替换了哪些部件、哪些假设在真机上变弱、复现要先固定哪些口径。

  • 主题：真机部署 / 零样本搜索 / 系统清单 / 证据口径
  • 关键公式：c = cos²(θ / (θfov/2) · π/2)；vnew = (ccurrvcurr + cprevvprev) / (ccurr + cprev)
  • 预计学时：75 分钟
  • 前置章节：第 067 讲（VLFM I：语言价值图）

学习目标

  • 会读协议：说清 Gibson、HM3D、MP3D 三个验证集的 episode 数、场景数、类别数与成功判据，能为表 I 中每个差值标注对照方法与数据集口径。
  • 会算：VLFM 相对 SemUtil、ESC 的 SPL 与 SR 增量及相对变化；相对有监督 SemExp、PONI、PIRLNav 的差额方向；由 SPL / SR 反推路径效率并解读。
  • 会拆部署：列出真机替换的每个部件（BD API 替代 PointNav、夹爪相机与 ZoeDepth 替代仿真深度、机身深度相机做障碍），并说明替换的原因与代价。
  • 会判断：零样本模块化的部署优势来自哪里，目标可见、单层环境、路径较畅通这三条假设在真机上的强弱，以及多层失败的量化代价。
  • 会设计：办公楼单层部署清单与最小可复现实验，包含延迟预算、失败记录表与真机成功判据的重定义方式。

背景与动机

第 067 讲讲清了 VLFM 的机制链条，也留下三个未答问题。第一，这套零样本方法在标准基准上到底处于什么位置，与语言路线（CoW、ESC、SemUtil）和有监督路线（SemExp、PONI、PIRLNav）的差距有多大。第二，一个依赖多个大模型与建图模块的系统，换上真机后哪些部件必须替换，替换是否会破坏方法的核心主张。第三，论文的真机演示只有定性证据，没有成功率的统计表，那么这套演示能支持什么结论、不支持什么结论。本讲按这三个问题组织：先读仿真结果与消融，再拆真机系统，最后给出部署清单与证据边界。

真机证据在这条方法线上格外值得细读。VLFM 的卖点是零样本与模块化：任务层面不做任何训练，组件可以逐个替换。这两点恰好都是部署语言：零样本省去目标域数据采集与训练，模块化让感知、深度、执行各自升级。论文的仿真部分提供了可比的数字，真机部分提供了可运行的证据，两者结合才构成完整的可复现主张。读法上要把“仿真数字”与“部署演示”分开归档，避免用前者给后者背书。

核心原理

1. 一页回顾：价值图与三阶段

VLFM 在深度与里程计上维护两张 2D 俯视图。占据图记录已探索、未探索与障碍，边界的中点构成前沿航点；价值图为双通道，语义通道存 BLIP-2 对当前 RGB 与文本提示的余弦相似度，置信度通道记录每个格子被写入时的可信程度。文本提示形如“Seems like there is a <target_object> ahead.”，其中目标名在评测时由任务给定（Yokoyama 等 2023，IV-B 节）。置信度由像素与相机光轴的夹角决定：

c(θ) = cos²( (θ / (θfov/2)) · (π/2) ) θ 为像素与光轴夹角，θfov 为水平视场角；光轴上 c = 1，视场边缘 c = 0

代入可得几个锚点：θ = 0 时 c = 1；θ 为半视场的一半时 c = cos²(π/4) = 0.5；θ = 0.75 · (θfov/2) 时 c = cos²(3π/8) ≈ 0.1464；到达边缘时为 0（本讲实算）。当新视场与已见区域重叠时，价值按置信度加权融合：

vnew = (ccurr · vcurr + cprev · vprev) / (ccurr + cprev)，   cnew = (ccurr² + cprev²) / (ccurr + cprev) 首次覆盖的像素满足 cprev = 0，两式退化为 vnew = vcurr、cnew = ccurr

算一个数值例子：某格子旧值 vprev = 0.2、旧置信度 cprev = 0.2，新观测 vcurr = 0.8、ccurr = 1.0，则 vnew = (0.8 + 0.04) / 1.2 = 0.7，cnew = (1.0 + 0.04) / 1.2 ≈ 0.8667（本讲实算）。首见条件退化为赋值，保证新区域不会被零置信度的空值稀释。整个 episode 分三阶段：初始化时原地旋转一周建立首版地图；探索阶段每次选取价值最高的前沿；检测到目标后转入目标导航阶段，走向目标轮廓上距当前位置最近的一点，进入成功半径后停止。执行由在 HM3D 训练集上用 VER 训练的 PointNav 策略完成，该策略输入深度与相对目标位置，不使用 RGB（Yokoyama 等 2023，IV-D 节）。

2. 仿真证据：三数据集与增量

评测在 Habitat 仿真器内进行，三个数据集均取验证集：Gibson 使用 SemExp 划分的 1,000 条 episode、5 个场景；HM3D 为 2,000 条、20 个场景、6 个类别；MP3D 为 2,195 条、11 个场景、21 个类别。成功判据为在 500 步内调用 stop 且距目标实例 1 m 以内（Yokoyama 等 2023，III 与 V 节）。主结果如下，数字为百分数，SPL 在前、SR 在后。

先读零样本内部的增量。对 SemUtil，Gibson 上 SPL +11.7（相对 +28.9%），SR +14.7 个百分点（相对 +21.2%）；对 ESC，HM3D 上 SPL +8.1（相对 +36.3%）、SR +13.3（相对 +33.9%），MP3D 上 SPL +3.3（相对 +23.2%）、SR +7.7（相对 +26.8%）（本讲实算，基准值取自论文表 I）。三个数据集的增量方向一致，且 HM3D 的相对增益最大。再读与有监督方法的交叉：对 SemExp，Gibson 上 SPL 与 SR 各高 18.3 个百分点；对 PONI，MP3D 上 SPL +5.4、SR +4.6；只有 PIRLNav 在 HM3D 上的 SR 高于 VLFM 11.6 个百分点，但 SPL 低 3.3。PIRLNav 使用 77k 条人类演示，且能上下楼梯，这两点同时解释了它的优势来源与口径差异。

SPL 与 SR 的联合读法给出一致性检查。按 e = SPL / SR 反推成功轨迹的平均效率：VLFM 在 Gibson、HM3D、MP3D 上分别为 62.1%、57.9%、48.1%；对照组中 SemUtil 为 58.4%、SemExp 为 51.6%、PONI 为 38.1%、PIRLNav 为 42.3%、ESC 为 56.9% 与 49.5%（本讲实算）。VLFM 在 Gibson 与 HM3D 上的效率不低于同表对照，MP3D 上与 ESC 基本持平（48.1% 对 49.5%），说明它的优势既来自找到目标，也来自路径直接。这个反推是估算口径，只用于同表内部的一致性检查，不替代原始 SR 与 SPL。

论文自述两处版本口径需要提前记录。其一，正文 VI-A 节写“相对 SemExp 的 SPL +19.2、SR +19.0”，与表 I 行值相减得到的 18.3 与 18.3 不一致，差约 0.9 个百分点；复现时以表值为准，并把这处差异写进实验记录。其二，引言写三个数据集的 SPL 绝对增量为 12%、5%、3%（顺序为 Gibson、MP3D、HM3D），正文对应值为 11.7、3.3、8.1；两组数字对 MP3D 与 HM3D 的对应关系不同，引用引言时不可与正文混排。这类“正文与表格不一致”是跨论文比较中最常见的误差来源，处理方式是固定一个可追溯的表格来源。

3. 价值图更新消融

当新视场覆盖已见区域时，语义值的融合策略有三种实现：直接覆盖、无权重平均、置信度加权平均。消融覆盖三个数据集（Yokoyama 等 2023，表 II）。

融合方式Gibson SPL / SRHM3D SPL / SRMP3D SPL / SR
直接覆盖48.0 / 76.126.5 / 44.516.6 / 31.7
无权重平均50.9 / 83.030.0 / 51.817.1 / 35.0
置信度加权平均52.2 / 84.030.4 / 52.517.5 / 36.4

增量可分两段。覆盖改平均一段：SR +6.9、+7.3、+3.3，SPL +2.9、+3.5、+0.5（无权重平均减直接覆盖）；平均加置信度一段：SR +1.0、+0.7、+1.4，SPL +1.3、+0.4、+0.4（加权减无权重）。第一段是主要收益，说明“多个视角的信息要融合”这一设计本身贡献最大；第二段虽小但在三个数据集上方向一致，而代价仅是多维护一个通道，属于低风险默认项。工程上直接覆盖等价于只信任最新观测，目标被前景遮挡或检测器波动时会反复改写价值，这是最需要避免的实现。

4. 真机系统：替换件与理由

真机平台为 Boston Dynamics Spot，部署地点为一座此前未见的办公楼单层。全流程不使用先验地图，初始化仍为原地旋转一周。论文明确列出四组替换（Yokoyama 等 2023，VI-C 节）：执行接口由 PointNav 策略换成 BD API 的航点导航；目标检测与价值图输入改用夹爪相机；夹爪相机深度量程有限，改用单目深度估计模型 ZoeDepth 生成深度并近似目标航点；障碍感知与前沿生成使用机身深度相机。检测路由沿用仿真逻辑：COCO 类别用 YOLOv7，其余类别用开放词汇检测器 GroundingDINO，轮廓提取用 MobileSAM（论文 IV-C 与 VI-C 节）。所有模型在配备 RTX 4090 MaxQ 移动 GPU（16 GB 显存）的笔记本上实时运行，包括 BLIP-2、GroundingDINO、MobileSAM 与 ZoeDepth。

这组替换里，只有一处改变了方法的数学结构：执行接口。PointNav 策略被 BD API 取代，意味着真机版没有使用那个训练了 25 亿步的策略；这也是论文自己强调的模块化论据，航点执行可替换为任何能把机器人带到可视航点的方法。其余替换都发生在感知接口上，价值图与前沿选择的逻辑不变。代价需要写清楚：BD API 假设路径相对无障碍，动态障碍的处理依赖本体栈；ZoeDepth 是估计值，目标航点可能带有米级偏差；夹爪相机的安装位置与朝向决定了目标必须先进入该视野，这比仿真的相机外参更受限。

5. 训练账与执行接口

零样本修饰的是 ObjectNav 任务层面，整条流水线仍有训练环节。仿真执行策略是一个 PointNav 智能体，在 HM3D 训练集上用 VER 训练：4 张 GPU、每卡 64 个并行环境（合计 256 个），训练 2.5B 步，耗时约 7 天（Yokoyama 等 2023，IV-D 节）。按论文数字折算，聚合步速约 4,133.6 步/秒，单环境约 16.1 步/秒（本讲实算）。动作空间为前进 0.25 m、左右转与抬头低头各 30°、停止；episode 上限 500 步，按每步 0.25 m 折算，单条轨迹里程上限为 125 m（不含转向消耗）。真机部署不使用该策略，因此这套训练成本属于仿真复现项；但复现者若没有等价的航点执行能力，就需要把这一项算进预算。

6. 证据口径与边界

真机部分在论文中是演示证据：在办公楼内移动到指定类别的物体，配有可查看的录像，未给出成功率表、失败率或重复次数。引用时的正确写法是“论文演示了在单层办公楼中的零样本搜索”，不可写成“真机成功率若干”。这也提示复现计划要为真机补充量化协议：固定出生点集合、目标类别集合、重复次数、成功半径与人工干预记录。

边界条件有五条。第一，单层限制：仿真里程计不提供 z 坐标，前沿图与价值图在换层时无法正确重置，论文报告 HM3D 与 MP3D 分别有 14.6% 与 9.6% 的 episode 因需要上下楼而失败。作为估算，若这些 episode 全部计为失败，则单层子集上的隐含 SR 约为 61.5%（52.5 / 85.4）与 40.3%（36.4 / 90.4）（本讲实算）。第二，目标必须能在默认相机高度被看到：论文自述未来工作才考虑主动看抽屉等封闭空间。第三，MP3D 的视觉保真度低于 HM3D，跨数据集读数差异里混有场景质量因素。第四，检测器路由依赖类别体系，COCO 之外的类别全部走开放词汇检测，检测质量是上限。第五，真机演示的单层环境同时满足“静态、路径较畅通、光照稳定”三条工程假设，这三条恰是部署中最先被挑战的。

最小实验协议

真机量化实验建议按以下协议跑：选同一楼层的 6 个出生点与 6 个目标类别，交叉成 36 组，每组重复 3 次；记录到达成功率、人工干预次数、单次耗时与失败类型（未找到、走错、卡住、超时）；成功判据在实验前冻结，建议沿用 1 m 半径并单独记录“停止时目标是否可见”。对同一楼层再跑一版无价值图的对照（只选最近前沿），用于验证 VLM 价值通道在真机上的净贡献。若楼层有多层，仅取目标与出生点同层的组合，并单独记录楼梯失败占比，与论文的 14.6% 与 9.6% 对齐口径。

关键代码与解读

三段代码对应真机主循环、价值图更新与检测路由，均为按论文描述的参考实现，接口名是本课程定义的薄封装。

片段 1：真机主循环

def run_episode(robot, target_text, max_steps=500, stop_radius=1.0):
    """真机主循环：初始化环视、价值图探索、检测确认后转入目标导航。"""
    send_waypoint = bd_waypoint_api(robot)      # 薄封装，底层调用按 BD SDK 文档
    robot.spin_in_place()                       # 初始化：原地旋转一周建立首版地图
    for step in range(max_steps):
        rgb, depth, pose = robot.get_observations()
        frontier_map.update(depth, pose)             # 占据图与前沿航点
        value_map.update(rgb, pose, target_text)     # BLIP-2 价值与置信度两通道
        det = detect_target(rgb, depth, target_text)
        if det is not None:
            send_waypoint(*det.goal_xy)              # 目标导航阶段
            if robot.distance_to(det.goal_xy) <= stop_radius:
                robot.stop()
                return True
        else:
            frontier = max(frontier_map.frontiers,
                           key=lambda f: value_map.value_at(f.midpoint))
            send_waypoint(*frontier.point)           # 探索阶段：走向价值最高前沿
    robot.stop()
    return False

解读：（1）初始化旋转与三阶段切换是论文的完整流程，检测一旦出现就切到目标导航，检测消失则回到探索；真机中这一切换要加去抖，避免检测闪烁引起来回换向。（2）前沿评分只读价值图中点，是最贴近论文表述的实现；若单点受噪声影响，可换成邻域中值，但要固定口径并记录。（3）stop_radius 在论文仿真口径为 1 m，真机演示未给出统一数值；复现时必须先冻结，避免评价漂移。

片段 2：置信度加权的价值图更新

def update_value_map(value_map, conf_map, rgb, pose, target_text):
    """对当前 FOV 内未被遮挡的格子做置信度加权更新（Yokoyama 等 2023，IV-B 节）。"""
    theta_fov = camera_hfov(rgb)                    # 水平视场角，弧度
    v_curr = blip2_similarity(rgb, f"Seems like there is a {target_text} ahead.")
    for (i, j) in visible_pixels(pose, rgb):        # 深度掩膜剔除被遮挡格子
        theta = angle_to_optical_axis(i, j, pose)   # 像素与光轴夹角
        c_curr = math.cos(theta / (theta_fov / 2.0) * math.pi / 2.0) ** 2
        c_curr = min(1.0, max(0.0, c_curr))         # 数值夹取，防越界
        c_prev = conf_map[i, j]
        if c_prev <= 1e-6:
            value_map[i, j] = v_curr                # 首见像素：c_prev = 0 退化
            conf_map[i, j] = c_curr
        else:
            v_prev = value_map[i, j]
            value_map[i, j] = ((c_curr * v_curr + c_prev * v_prev)
                               / (c_curr + c_prev))
            conf_map[i, j] = ((c_curr ** 2 + c_prev ** 2)
                              / (c_curr + c_prev))
    return v_curr                                   # 供日志记录本帧相似度

解读：（1）两式的顺序重要：先算新价值再更新置信度，否则同一格子的权重基数会被本轮修改。（2）BLIP-2 余弦值域为 [−1, 1]，更新公式对负值同样成立，不要把它夹到非负区间，否则语义排序被破坏；只有置信度需要夹取。（3）首见分支写成“双通道赋值”，与公式在 cprev = 0 时的极限一致，也避免除零。返回值用于日志记录本帧相似度，便于把“价值通道是否工作”与“前沿选择是否合理”分开排查。

片段 3：检测路由与目标航点

def detect_target(rgb, depth, target_text, coco_classes):
    """检测路由：COCO 类走 YOLOv7，其余走 GroundingDINO；MobileSAM 取轮廓。"""
    if target_text in coco_classes:
        boxes = yolov7(rgb, classes=[target_text])       # 域内类更稳定
    else:
        boxes = grounding_dino(rgb, prompt=target_text)  # 开放词汇检测
    if not boxes:
        return None
    box = max(boxes, key=lambda b: b.score)
    mask = mobile_sam(rgb, box)                          # 轮廓用于最近点
    if depth is None or depth_range_limited(depth):
        depth = zoe_depth(rgb)                           # 夹爪深度量程不足时兜底
    point = nearest_point_on_mask(mask, depth)
    return Detection(label=target_text, score=box.score, goal_xy=point)

解读：（1）路由的收益来自域内类检测器的稳定性，代价是两套模型的显存与维护成本；若目标类别固定很少，可只用开放词汇检测简化系统。（2）MobileSAM 的轮廓参与“最近点”选择，使机器人走向目标的可接近一侧，绕开目标自身的遮挡部分；这是仿真与真机共用的逻辑。（3）深度兜底触发条件要显式记录，因为它直接影响航点精度与失败归因；真机日志里建议同时存原始深度与估计深度，便于离线复盘。

常见坑

  • 把仿真数字当作部署证据：症状是汇报时用 84.0% 的成功率描述真机能力。根因是论文真机部分为单层办公楼演示，未报告成功率与重复次数。修复：仿真与真机证据分开陈述；真机补充固定出生点、重复次数与人工干预记录的量化协议。
  • 多层场景直接套用：症状是机器人上楼后前沿图与价值图错乱，episode 必然失败。根因是里程计不提供 z 坐标，换层后 2D 地图无法重置。修复：复现先限定单层；多楼层需要扩展地图重置逻辑，并以论文报告的 14.6%（HM3D）与 9.6%（MP3D）作为失败量级的参照。
  • 夹爪深度量程不足未处理：症状是目标检测正常但航点漂移，接近阶段来回修正。根因是夹爪相机的短量程深度在目标附近饱和或缺失。修复：按论文引入单目深度估计兜底，并对估计深度做行走标定；同时保留原始深度做失败复盘。
  • 忽略多模型共驻的显存与延迟：症状是联跑时随机崩溃或控制频率跟不上步速。根因是 BLIP-2、GroundingDINO、MobileSAM、ZoeDepth 同时常驻，16 GB 显存是论文的实测配置，余量有限。修复：部署前逐模块压测显存与单次前向耗时，明确哪些模块分时加载，并把控制频率写入验收项。
  • 照抄正文数字导致与表值冲突：症状是同一批实验中两个汇报数字互相矛盾。根因是论文正文对 SemExp 报 SR +19.0、SPL +19.2，表 I 行值相减为 18.3 / 18.3；引言在 MP3D 与 HM3D 上的 SPL 增量也与正文对应关系不同。修复：以表 I 为唯一数字来源，正文表述仅作机制说明；引用引言时注明口径未对齐。

    Gibson 对 SemUtil：SPL +11.7（+28.9%）、SR +14.7（+21.2%）；HM3D 对 ESC：+8.1（+36.3%）、+13.3（+33.9%）；MP3D 对 ESC：+3.3（+23.2%）、+7.7（+26.8%）。同表同数据集内差值口径一致；MP3D 的场景质量与类别数最多，跨数据集差值不用于排序。
  2. 为真机部署写一份验收清单：列出场景、计算、接口、判据、安全五类中各自的硬性检查项，并给出每一项的失败示例。★★
    提示
    场景：单层、目标可见；计算：四模型共驻 16 GB 显存且控制频率达标；接口：BD API 能处理常见静态障碍；判据：成功半径冻结为 1 m 并记录可见性；安全：急停演练。失败示例：多层的换层重置缺失、显存溢出导致进程被杀、航点落在障碍上、半径改为事后调整、急停不可达。
  3. 设计一个真机延迟预算表：为建图、价值图、检测、航点下发四类操作各分配频率与单次耗时上限，使系统能稳定跟上行走节拍，并说明超出预算时的降级顺序。★★

    提示
    建议 6 出生点 × 6 类别 × 3 次 = 108 条；判据冻结为 1 m 且记录可见性；对照为“只选最近前沿”的无价值图版本，其余模块相同；失败分类：未找到、走错房间、卡住、超时、误停。净收益判据：价值图版本在成功率上的增量超过重复实验的波动范围，且失败类型中“走错房间”占比下降；若增量只出现在单层子集，需单独报告。

小结

  • 仿真证据：零样本 VLFM 在 Gibson、HM3D、MP3D 上取得 52.2 / 84.0、30.4 / 52.5、17.5 / 36.4（SPL / SR，论文表 I），对 SemUtil 与 ESC 的增量方向一致；Gibson 与 MP3D 上超过有监督方法，仅 HM3D 的 SR 低于 PIRLNav 11.6 个百分点。
  • 协议口径：三个验证集分别为 1,000 / 2,000 / 2,195 条 episode；成功判据为 500 步、1 m；正文与表值存在两处不一致（SemExp 增量 +19.0 对 18.3，引言 SPL 增量与正文对应关系不同），复现以表 I 为准。
  • 消融：置信度加权更新相比直接覆盖带来 SR +7.9 / +8.0 / +4.7 个百分点；其中“覆盖改平均”贡献主要部分，“平均加置信度”在三个数据集上一致小幅增益，属于低风险默认项。
  • 真机系统：Spot + 办公楼单层；BD API 替代 PointNav，夹爪相机承担检测与价值输入，ZoeDepth 补深度量程，机身深度做障碍；BLIP-2、GroundingDINO、MobileSAM、ZoeDepth 在 16 GB 显存上实时运行；真机部分为定性演示，无成功率统计。
  • 边界：单层限制对应 HM3D 14.6% 与 MP3D 9.6% 的楼梯失败，隐含单层 SR 约 61.5% 与 40.3%（估算）；目标可见性、静态环境与路径较畅通是三条尚未在真机被充分挑战的假设。
  • 下一讲进入 SG-Nav：用在线分层 3D 场景图（物体、组、房间）替代纯文本提示，用分层链式推理让 LLM 遍历子图定位目标，再把子图概率按反距离插值到前沿；场景图表示也为后续的重感知纠错机制提供了接口。
