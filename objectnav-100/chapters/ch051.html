第三篇 · 端到端与配方

第 051 讲｜演示规模与收益递减

第 050 讲确定人类演示是质量最高的来源，本讲回答要采集多少条。Ramrakhya 等（2023，PIRLNav，ObjectNav）在 HM3D-Semantics v0.1 上构造从 2k 到 77k 的人类演示子集，每档独立做行为克隆（Behavior Cloning，BC）预训练、独立做强化学习（Reinforcement Learning，RL）微调：20k 处微调带来 +10.1 个百分点，77k 处降到 +6.3 个百分点；35k 子集微调后达到 66.4%，是 77k 最佳成绩 70.4% 的 94.3%，而演示量只有 45.45%。前沿探索演示扩到 70k 后饱和。本讲把这两条曲线变成预算工具：对数拟合、成本换算、停止规则，以及数据噪声构成的约 81.1% 性能上限。

  • 主题：数据规模 / 收益递减 / 预算决策 / 性能上限
  • 关键公式：Δ(n) = SRL(n) − SBC(n) ≈ a − b ln n
  • 预计学时：75 分钟
  • 前置章节：第 050 讲（演示来源之争）

学习目标

  • 会算：绝对增量、相对增量、35k 与 77k 的比例关系（45.45% 与 94.32%）、每千条与每点成本，以及数据噪声构成的性能上限。
  • 会推导：收益递减的四条机制，包括修正空间收缩、覆盖饱和、数据噪声上限与固定 RL 预算，并能指出各机制的证据边界。
  • 会拟合：用两个论文锚点建立对数模型，给出内插预测并说明模型假设与失效条件。
  • 会设计：规模实验协议（固定超参与 RL 预算、每档检查点规则、多种子区间）与数据采集的停止规则。
  • 会判断：在预算约束下选择规模档与来源策略，识别哪些投入属于数据修复，哪些属于继续加量。

背景与动机

第 050 讲的结论把预算引向人类演示，而人类演示按人时计价：HM3D 上 2,378 人时换 77k 条，每条约 111.2 秒。规模决策因此等价于预算决策。从 35k 扩到 77k 需要追加约 42k 条，按同一单价约 1,297.1 人时，换来 4.0 个百分点的验证成功率。这笔账划不划算，取决于曲线的形状与目标水位。

曲线有两条，要一起读。BC 成功率随演示规模上升，微调后的成功率也上升；微调增量（微调后减去 BC 起点）随规模下降。三个陈述并不矛盾：增量是差值，起点抬高后剩余可修正空间变小，差值自然收窄。只看微调增量，会得出「RL 微调不值得做」的错误结论；只看 BC 起点，会用线性外推安排超额预算。正确读法是同时盯住最终成功率与增量两条线，再叠加成本与上限。

上限来自数据侧。第 052 讲将展开的失败标注显示，最强策略在 HM3D val 上的失败里约 36% 与数据标注缺失、导航网格问题有关，算法无法回收这部分；按失败率 29.6% 折算，全部修复也就到约 81.1%。这为收益递减提供了数据侧解释，也提示高段预算应转向数据修复，放缓继续采集。本讲先给协议与锚点，再给拟合与机制，最后落到预算决策；来源差异见第 050 讲，失败构成与干预见第 052 讲。

核心原理

1. 规模实验协议与曲线口径

实验在 HM3D-Semantics v0.1（120 场景、6 类目标，2022 挑战 split）上进行。人类演示子集覆盖 2k 到 77k，正文点名 20k、35k、77k 三个档位；每个子集用同一套超参独立做 BC 预训练（500M 步、64 卡、Adam 学习率 1e-3 线性衰减），再各自从表现最好的检查点出发，用同一套 RL 配方微调 300M 步（DD-PPO、16 卡、稀疏成功奖励、两阶段调度，细节见第 049 讲）。所有读数都是 HM3D val 的成功率（Success Rate，SR）与成功加权路径长度（Success weighted by Path Length，SPL）。

口径项设置作用
自变量演示子集规模 n，从 2k 到 77k画规模曲线
每档起点该档 BC 表现最好的检查点论文口径；注意选择偏差影响
微调预算每档均 300M 步排除 RL 预算差异
报告 splitHM3D-Semantics v0.1 val与 test-std 的 65.0% 口径区分
对照来源前沿探索（Frontier Exploration，FE）子集 10k 至 150k，曲线用 75k 拟合检验自动来源的规模规律

2. 增量定义与论文锚点

把两条曲线差值化，定义规模 n 下的微调增量与相对增益：

Δ(n) = SRL(n) − SBC(n)， 相对增益 = Δ(n) / SBC(n) SBC 为选点后的 BC 成功率，SRL 为同一检查点微调后的成功率；两者同 split、同版本

论文给出的锚点数字如下。20k 档的 BC 起点为 52.0%（消融表口径），微调增量为 +10.1 点；77k 档增量为 +6.3 点；35k 档微调后为 66.4%；77k 档微调后为 70.4%（val 最佳）。以 52.0 + 10.1 = 62.1 与消融表中完整调度的 61.9% 对照，二者相差 0.2 点，属运行波动范围，不构成矛盾。

规模 nSBCSRLΔ(n)来源与口径
20k52.0%约 62.1%（推算）+10.1 点PIRLNav 正文；BC 取自消融表
35k约 57.9%（模型推算）66.4%约 +8.5 点（模型）RL 读数为论文正文；BC 为对数模型反推
77k未单列70.4%+6.3 点PIRLNav 正文与 val 最佳成绩

3. 35k 的位置：不到一半演示与 94.3% 性能

把 35k 与 77k 的比例关系算清楚：35 / 77 = 45.45%，66.4 / 70.4 = 94.32%，两者相差 4.0 个百分点，相对回落 5.68%。论文摘要的表述是「用不到一半的演示达到最佳策略 90% 以上的性能」，精确读法是演示量 45.45%（小于一半），性能 94.32%（大于 90%）。这两个数字是规模决策的核心：曲线的后段已明显变平，最后 42k 条演示的边际产出低于前段。

还可以算每点成本：35k 到 77k 追加 1,297.1 人时换 4.0 点，合 324.3 人时/点，约等于 5.4 个采集日（按每天 60 人时计）。对照前半段，20k 到 35k 之间单条成本相同，但成功率抬升的速率更高。预算有限时，先把钱花到 35k 附近的拐点，再评估是否继续。

4. 对数拟合：把两个锚点变成决策公式

只有两个公开锚点时，可用对数模型描述增量随规模衰减的形状：

Δ(n) ≈ a − b · ln n，其中 b = (Δ1 − Δ2) / ln(n2/n1)，a = Δ1 + b · ln n1 取 (n1, Δ1) = (20k, 10.1)，(n2, Δ2) = (77k, 6.3)，得 b = 2.819、a = 38.016

代入得到内插预测：Δ(35k) ≈ 8.52 点，Δ(50k) ≈ 7.52 点；反解 Δ = 8.0 点对应约 42.1k 条。再由 Δ(35k) ≈ 8.5 反推 BC 起点约 57.9%，高于 20k 的 52.0%，单调性合理，可以作为模型自检。

边界必须写明：模型只用了两个论文锚点，未看过论文原图的完整数据点；它适合内插与量级判断，不适合外推到 100k 以上，也不适合预测换来源、换架构后的曲线。学术写作中引用这类模型时，标注为「本讲拟合，用于教学演示」，与论文报告值分开。

5. 收益递减的机制

机制一，修正空间收缩。BC 起点越高，能通过 RL 修正的失败轨迹越少，Δ(n) 的上界约等于剩余失败率乘以可修正比例。这解释了为什么 77k 的 +6.3 点小于 20k 的 +10.1 点，而最终成功率仍在上升。

机制二，覆盖饱和。演示池扩大时，新增轨迹更多落在已经见过的场景布局、房间结构与类别组合上，边际信息量下降。FE 的曲线把这个机制展示得最直接：任务无关的巡游模式空间有限，数据加倍也无法带来新的行为类型。

机制三，数据噪声上限。最强策略在 val 上的失败率为 29.6%，失败标注显示其中 36% 来自缺失标注与导航网格（第 052 讲详述）。若这些失败全部可修复且与其它类别独立，成功率上界为 70.4% + 29.6% × 36% = 81.06%。继续加演示无法回收这部分，它构成规模收益的天花板。

机制四，固定微调预算。每档都是 300M 步，预算不随 n 增长。演示越多，策略分布越接近部署分布，同等步数下探索需求与修正需求都在变，这一项的净效应方向依赖具体实现，本讲只把它列为需要控制的变量，不给出单向结论。

6. 前沿探索演示的规模曲线与饱和

FE 子集从 10k 构造到 150k，曲线用 75k 档拟合后预测更大规模的取值。结果显示规模扩大并不稳定地提升性能，70k 后曲线饱和；FE 在 70k（12M 步配平口径）的 BC 成功率为 44.9%，明显低于 HD 在 77k 的 64.1%。论文给出的解释是：FE 演示没有任务特定的探索，模式空间小，容易饱和。

读这条曲线时注意外推禁令：FE 的饱和不能移植到 HD，两类数据的行为多样性不同；同样，HD 在 77k 处仍在上升（94.3% 的位置并未触顶），也不能因为 FE 饱和就断言 HD 已接近上限。每条来源的曲线要单独找拐点。

7. 成本换算与预算决策

按 2,378 人时 / 77k 条折算单位成本 30.88 人时/千条，三个档位的人时与相对最优性能如下表。

演示规模人时（按单位成本折算）微调后 val SR相对最优读法

决策表：目标是 val 约 68%，选 35k 档并把资源留给失败修复，按修复上界约 81.1% 计算，补上 1.6 点的空间充足；目标逼近 70% 且预算充足，选 77k 档，同时把数据类失败（第 052 讲）单列处理，防止天花板提前出现；预算低于 20k 且人手有限时，先用 FE 演示冷启动，再用少量 HD 补充任务导向行为，混合配比没有公开对照，需要自行做消融。所有档位的人时按同一单价折算，实际采集会因质控强度与场景难度偏离。

8. 边界与失效条件

第一，split 口径：规模曲线是 val 读数，77k 最佳 val 为 70.4%，对应 test-std 与 test-challenge 均为 65.0%；把 35k 的 val 值直接当 test 值使用会高估。第二，数据集范围：全部数字绑定 HM3D-Semantics v0.1 的 120 场景与 6 类目标。第三，每档挑选最佳检查点会让曲线轻微乐观，若改用统一步数检查点，后段差值可能更大。第四，采集成本随众包平台与质量控制浮动，30.88 人时/千条是 HM3D 经验值。第五，摘要中的 90% 为近似表述，精确核算为 94.32% 与 45.45%，引用时建议给出后两者。第六，混合来源、v0.2 场景与真机迁移不在本实验范围内。

实现思路与设计

实现重点是把「每档独立训练、变量只有一个」落实到流水线：子集构造、训练、检查点选择、评测四段全部由配置驱动，规模 n 是唯一自变量。

规模实验矩阵与检查点规则

成本核算与停止规则

停止规则建议三条并用。其一，目标达成：达到业务所需成功率水位即停止扩容。其二，边际阈值：相邻档位之间每千条演示带来的提升低于 0.05 点，视为进入平坦区。按锚点估计，35k 到 77k 段每千条约 0.095 点，尚未触阈但已接近拐点；继续扩到 100k 以上，模型预测会继续下滑。其三，数据侧优先级：若失败审计显示数据类失败居首且未处理，先修数据，暂停扩容。

每千条边际增益 ≈ [SRL(n2) − SRL(n1)] / (n2 − n1) 示例：35k 至 77k 段，4.0 点 / 42k 条 ≈ 0.095 点/千条；阈值 0.05 点/千条为教学建议，需结合业务方差调整

关键代码与解读

三段代码分别覆盖拟合、成本核算与分层抽样，输出与正文数字逐项对应。

片段 1：两锚点对数拟合与规模反解

from math import log, exp

def fit_delta(n1, d1, n2, d2):
    """用两个锚点拟合 Delta(n) = a - b*ln n，仅用于内插。"""
    b = (d1 - d2) / (log(n2) - log(n1))
    a = d1 + b * log(n1)
    return a, b

a, b = fit_delta(20000, 10.1, 77000, 6.3)
print(round(a, 3), round(b, 3))                       # 38.016 2.819
print([round(a - b * log(n), 2) for n in (35000, 50000)])
# [8.52, 7.52]，对应 35k 与 50k 的增量预测

def min_demos_for(delta_target):
    """反解目标增量所需的演示规模。"""
    return exp((a - delta_target) / b)

print(round(min_demos_for(8.0) / 1000, 1))            # 42.1k
print(round(min_demos_for(7.5) / 1000, 1))            # 50.3k

解读：（1）模型把「增量随规模衰减」编码成一条直线，两个锚点定参，第三点（35k 的 66.4%）用于外部校验，避免自证。（2）反解函数给出「要保住多少增量需要多少条演示」，可直接接进预算讨论；42.1k 与 50.3k 是模型读数，不是论文报告值。（3）打印全部中间量并保留在小数第三位，报告里能追溯；模型声明为教学拟合，与论文原图数据分开引用。

片段 2：成本与边际增益核算

H_PER_DEMO = 2378 / 77000            # HM3D 采集单位成本，约 0.0309 人时/条

def hours(n):
    return n * H_PER_DEMO

print(round(hours(20000), 1), round(hours(35000), 1), round(hours(77000), 1))
# 617.7 1080.9 2378.0

extra = hours(77000) - hours(35000)
print(round(extra, 1), round(extra / (70.4 - 66.4), 1))
# 1297.1 与 324.3：追加 42k 条换 4.0 点，合每点 324.3 人时

print(round(35 / 77 * 100, 2), round(66.4 / 70.4 * 100, 2))
# 45.45 与 94.32：摘要「不到一半演示、九成以上性能」的精确核算

解读：（1）单位成本从论文的时数与条数反算，任何档位的人时都由同一函数导出，不手写猜测。（2）边际增益用最终成功率的差除以条数差，注意它是对曲线的平均斜率，近似导数需要更密的档位。（3）相对最优用 66.4/70.4 这一口径，不用其它变体计算，保证与摘要表述可对照。

片段 3：按场景分层的子集抽样

import random
from collections import defaultdict

def stratified_subset(demos, size, seed=0):
    """按场景分层抽取至多 size 条演示；层内固定种子，覆盖率随 size 单调。"""
    buckets = defaultdict(list)
    for d in demos:
        buckets[d["scene"]].append(d)
    rng = random.Random(seed)
    per_scene = max(1, size // len(buckets))
    out = []
    for scene in sorted(buckets):
        rng.shuffle(buckets[scene])          # 层内洗牌，种子固定
        out.extend(buckets[scene][:per_scene])
    rng.shuffle(out)
    return out[:size]                        # 短抽场景的余量需二次分配再补满

# 用途：为 2k 至 77k 的每个档位生成嵌套子集，
# 小档位是大档位的子集时，曲线才能排除「换了一批场景」的混杂。

解读：（1）按场景分层能防止小档位缺整类场景，代价是实现比随机抽样复杂，且需要处理某场景演示不足配额的情况。（2）返回前整体洗牌，避免场景顺序与训练采样顺序相关；种子固定保证实验可复现。（3）若采用嵌套子集（小档位取自大档位），同一演示在不同档位重复出现，曲线更平滑，但种子要统一；论文未公开子集清单，复现时在报告中写明抽样规则即可。

常见坑

  • 只读一条曲线或只报一个数：症状有两个，只报微调后成功率，把 77k 的优势全记在 RL 配方上；或看到增量从 10.1 点降到 6.3 点就宣布微调无用。根因是 SBC 与 SRL 两条曲线被压成一条，且增量是差值，起点抬高后差值收窄属于算术必然。修复：同图报告起点与终点，并列最终成功率与 Δ(n)，按目标水位判断微调预算的去留；77k 的 70.4% 仍高于 35k 的 66.4%。
  • 每档挑最佳检查点且不设种子：症状是曲线非单调或数值虚高。根因是选择偏差叠加运行波动（消融表标准差约 ±0.47 至 ±1.01 点）。修复：固定选点规则、不少于 3 个种子、报告均值与区间，并补充统一步数的敏感性曲线。
  • 把 FE 的饱和外推：症状是得出「加数据没用」的普遍结论。根因是任务无关探索的模式空间小，饱和点属于 FE 自身。修复：每个来源单独画曲线、单独找拐点；HD 在 77k 处仍在上升，不能与 FE 共用饱和结论。
  • split 与版本混用：症状是用 35k 的 val 66.4% 与 77k 的 test-std 65.0% 直接比较。根因是 val 与 test 口径不同、版本敏感。修复：所有比较绑定同一 split 与版本，分层报告中固定写「HM3D-Semantics v0.1 val」。
  • 忽视数据噪声上限：症状是计划把演示扩到 100k 以上去追 80% 成功率。根因是未处理约 36% 的数据类失败。修复：先做失败审计与数据修复（第 052 讲），再决定是否继续扩容；把 81.1% 作为乐观上界写进方案。

练习与思考

  1. 由 35k 与 77k 的读数计算 45.45%、94.32%、4.0 点差距与 324.3 人时/点；并写出摘要「90% 与一半演示」的精确对应关系。★
    提示
    35/77 = 45.45% 小于一半；66.4/70.4 = 94.32% 大于 90%；差值 4.0 点，追加 42k 条约 1,297.1 人时，合 324.3 人时/点；20k、35k、77k 的人时分别为 617.7、1080.9、2378.0。
  2. 用两锚点 (20k, 10.1) 与 (77k, 6.3) 拟合对数模型，求 a、b，预测 Δ(35k) 与 Δ(50k)，反解 Δ = 8.0 所需的规模；再给出至少三条模型失效边界。★★
    提示
    a = 38.016、b = 2.819；Δ(35k) ≈ 8.52、Δ(50k) ≈ 7.52；Δ = 8.0 对应约 42.1k。失效边界：仅两个锚点的两参数模型、不能外推超出 77k 太远、换来源或架构后参数失效、未反映检查点选择偏差。
  3. 设计一个验证 FE 饱和来源的实验：控制 BC 训练精度、场景数、经验步数与网络容量，判断饱和来自数据模式有限还是模型容量不足；给出主指标、对照与判定标准。★★
    提示
    在 70k 以上继续扩容并固定 BC 精度切片；同时增大容量与训练步数的对照臂；若扩容无提升而增容有提升，饱和主因在数据模式；若两者都平，饱和是联合瓶颈。主指标为 val SR，辅以训练成功率与动作熵。
  4. 给定 1,200 人时预算与 val 68% 的目标，结合第 050 讲的来源结论与本讲曲线，给出采集方案：选来源与规模、预期读数、验收标准、停止规则与主要风险。★★★
    提示
    HD 约 35k 条需 1,080.9 人时，落点 66.4%，与目标差 1.6 点；剩余约 119 人时可做小规模 FE 冷启动或数据修复；若要冲 68% 需补采到约 45k 至 50k（模型内插）并接受成本超出。验收：同 split 复测、≥3 种子、失败构成审计；风险：val 与 test 落差、数据噪声上限、众包质量波动。
  5. 解释 20k 到 77k 之间微调增量从 10.1 点降到 6.3 点、而最终成功率仍在上升的两条主要机制，并说明为什么机制四（固定 RL 预算）不能给出单向结论。★
    提示
    机制一修正空间收缩，机制二覆盖饱和；数值上 Δ 是差值，起点越高差值越小。机制四中探索需求与修正需求随起点变化方向相反，需实验控制，不能先验断言。

小结

  • 规模实验在 HM3D-Semantics v0.1 val 上完成，人类演示子集覆盖 2k 至 77k；每档独立 BC 预训练并从最佳检查点 RL 微调 300M 步，来源与配方固定，规模是唯一自变量。
  • 论文锚点：20k 微调增量 +10.1 点，77k 降到 +6.3 点；35k 微调后 66.4%，为 77k 最佳 70.4% 的 94.32%，演示量占 45.45%，对应摘要的「不到一半演示、九成以上性能」。
  • 两锚点对数模型 Δ(n) ≈ 38.016 − 2.819 ln n 给出内插预测：Δ(35k) ≈ 8.52、Δ(50k) ≈ 7.52；反解 Δ = 8.0 对应约 42.1k 条。模型仅用于内插，不作为论文报告值引用。
  • 成本口径：30.88 人时/千条；20k / 35k / 77k 分别约 617.7 / 1,080.9 / 2,378.0 人时；35k 到 77k 段每点成本 324.3 人时。预算有限时以 35k 为默认拐点档。
  • FE 演示在 10k 至 150k 范围内 70k 后饱和，任务无关探索是机制；该饱和不能外推到 HD。数据类失败（占失败 36%）构成约 81.06% 的乐观上限，继续扩容前应先做数据审计。
