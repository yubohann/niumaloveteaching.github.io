第三篇 · 端到端与配方

第 057 讲｜混合任务训练

第 056 讲证明了只用 RGB 历史的策略对定位噪声更稳，但视觉先验的覆盖范围由训练数据决定。FiLM-Nav（Yokoyama 与 Ha 2025，v2 修订于 2026，Fine-tuned Language Model for Navigation）把预训练视觉语言模型直接微调成前沿选择策略：输入最近 20 帧视觉历史、语言目标与候选前沿图像，输出要探索的前沿编号。它的关键配方是数据混合：ObjectNav、OVON、ImageNav 与辅助空间推理任务一起训练，在 HM3D-v0.2 上取得 77.0% SR 与 41.3% SPL，并在 HM3D-OVON 三档验证集上刷新 SPL。本讲拆解配比核算、消融增量和冲突边界。

  • 主题：多任务配方 / 视觉语言模型微调 / 数据混合 / 消融读法
  • 关键公式：L = Σk (Nk / N) · LCE(k)
  • 预计学时：85 分钟
  • 前置章节：第 056 讲（定位/执行噪声鲁棒性）

学习目标

  • 会算：按样本数核算混合配比与训练步数。四路数据合计 122k 条，三遍训练在全局批量 576 下设每轮约 212 步、总计约 636 步；能据此估算任一配比变化的每轮曝光量。
  • 会实现：确定性混合采样器与多任务序列组装，包括损失掩码（只算答案编号位的交叉熵），并说明为什么按步数计配比会引入隐式加权。
  • 会读：消融表逐项增量。ImageNav 主要提升未见类别成功率，OVON 数据补齐同义类别，辅助空间任务贡献最大的效率增益（v0.2 SPL 加 2.1 个百分点）。
  • 会判断：何时出现负迁移。OVON 行把未见类别 SR 从 41.5 压到 40.8，说明任务分布接近评测分布时收益集中，容量与样本预算有限时另一档会轻微回退。
  • 会设计：分离场景多样性与目标多样性的混合实验；区分「加数据」与「加任务」两种解释。

背景与动机

第 053 至 055 讲的两条主线给了两个结论：规模是端到端方法的关键变量（OVRL-v2 的 scaling 证据），无地图策略有清晰的能力边界。第 056 讲补充了第三个变量：信息通路决定噪声敏感性。剩下的问题是训练数据的构成。标准 ObjectNav 只覆盖 HM3D 的 6 类目标与 145 个带标注训练场景；OVON 扩展到 379 类、181 个场景（HM3D-OVON，Yokoyama 等 2024），把开放类别加入训练是自然选择；但仅靠标注数据无法再扩大场景基数，未标注的场景又该怎么用？

FiLM-Nav 的答案是把任务本身当作数据增强维度。ImageNav 不需要物体类别标注，只要一张目标图像，因此可以把 HM3D 的 800 个训练场景全部用上，而 ObjectNav 与 OVON 只有 145 个场景。再加一个辅助空间推理任务：给智能体一段视觉历史、若干带字母编号的候选图像，以及一个机器人局部坐标 (X, Y)，要求选出拍摄该坐标的图像。这个任务不直接教导航，教的是「第一人称经历」与「空间布局」的对应关系，属于对前沿选择最有帮助的中间能力。

结果层面有两组值得记住的数字。HM3D-v0.2 上 77.0% SR 与 41.3% SPL，相对此前开源词汇方法的最好成绩（Uni-NaVid，73.7% / 37.1%）分别高 3.3 与 4.2 个百分点；消融里从单任务 74.3% 提到全配方 77.0%，且每一路数据加入后几乎没有指标回退，说明这组任务之间基本互补。本讲先把配比账算清，再读消融与榜单。

核心原理

1. 策略形式化与输入序列

任务沿用 HM3D 的 ObjectNav 与 OVON 口径：RGB-D 与相对位姿输入，动作集合为前进 0.25 m、左转 30°、右转 30°、停止，500 步内停在目标 1 m 内判成功。策略把输出对象从动作改为前沿选择：

ft ~ π(ft | Ht, g) Ht 为最近 20 帧的视觉历史，g 为语言目标（ImageNav 时为目标图像）

选出的前沿坐标交给一个预训练 PointNav 策略转成离散动作，检测到目标后用 OWLv2 检测与 MobileSAM 分割做最后一程并触发停止。视觉编码器用冻结的 SigLIP ViT，投影层可训练；语言模型主体是 2.8B 参数的 Cobra，基于 Mamba 状态空间结构。输入序列把四类内容拼在一起：历史视频 token、任务指令 token、可选的目标图像 token、每个候选前沿的「字母编号 token 加图像 token」。训练目标是标准的下一 token 交叉熵，只监督答案编号那一位。

序列段内容生成方式
轨迹历史最近 20 帧第一人称 RGB token高、宽、时间三维平均池化后投影
任务指令「找到椅子」等自由文本分词后输入语言模型
ImageNav 目标目标位置图像 token（仅该任务）高、宽平均池化后投影
前沿选项A 至 N 的编号 token 与对应图像 token代表图取自历史中垂直于前沿边界的机位

前沿代表图的选取规则是这套系统的细节亮点：图像从机器人已经拍过的历史里选，判据是相机朝向与前沿边界的垂直度最大，即对未探索区域视野最好的那个历史机位。训练与推理使用同一规则，避免出现训练时看前沿位置、推理时凭记忆想象前沿外观的分布差。

2. 混合目标与配比核算

四路数据各自有一个下一 token 交叉熵，联合目标按样本数加权：

L = Σk (Nk / N) · LCE(k)，N = Σk Nk 每条样本出一个损失项，序列内部只对答案 token 计权；配比即采样概率

样本量来自论文口径：ObjectNav 约 26k、OVON 约 26k、ImageNav 40k、辅助空间任务 30k，合计 122k。按此配比核算：

数据源样本数占比每轮（3 遍）曝光在配方中的角色
ObjectNav26k21.31%78k标准六类目标，任务地基
OVON26k21.31%78k开放类别，贴近评测分布
ImageNav40k32.79%120k800 个场景的视觉与目标多样性
辅助空间任务30k24.59%90k历史与空间坐标的对应监督

训练配置为：全局批量 576，训练 3 遍，8 张 A40，总时长约 15 小时；AdamW，学习率 2 × 10−5，冻结 SigLIP 视觉编码器，训练投影层与语言模型主体。每轮步数 = 122,000 / 576 ≈ 211.81，向上取整 212 步；三遍合计约 636 步。按占比折算，单批内四路名额的期望约为 122.8、122.8、188.9、141.6 条；以 ObjectNav 为例，单个样本在三遍训练中被抽到 3 次。整个训练只有约 636 次梯度更新，这解释了为什么配方强调参数高效微调，而没有采用从头训练。

3. 混合为什么有效：三条互补机制

目标多样性。ImageNav 的每张目标图像经 SigLIP 编码与投影层映射后都是独特的条件嵌入，而 ObjectNav 只有六个固定类别嵌入。让投影层见过大量不同目标表示，等于训练了「目标条件通路」本身，评测时面对未见类别的文本才有人未见过的组合能力。消融数据支持这一点：ImageNav 加入后，未见类别 SR 从 39.4 提到 41.5（加 2.1 个百分点），是四项增量里对未见档最大的一笔。

场景多样性。ImageNav 把可用训练场景从 145 扩到 800，场景覆盖是防止视觉过拟合的硬约束。这一路数据同时贡献了 v0.2 基准的轻微提升（SR 74.3 到 74.9）与未见档的明显提升，与「多样化场景提升泛化」的常规判断一致。

评测对齐与显式空间监督。OVON 数据直接来自评测同源分布，加入后同义档 SPL 从 21.7 升到 22.4、SR 从 39.3 升到 39.9；辅助空间任务的增量集中在效率维度：v0.2 SPL 从 39.2 升到 41.3，Val Seen SPL 从 23.3 升到 24.5。效率增益来自更准的前沿排序：同样找到目标，选错前沿意味着绕路。

5. 效率与架构口径

选 Mamba 结构的理由是长序列推理代价：论文实测平均推理 0.2 秒对同类 Transformer 的 0.32 秒，吞吐为其 1.6 倍（论文表述为快 60%），推理显存 12.5 GB 对 15.5 GB。按本文统一口径，时延低 37.5%、显存低 19.4%；两个百分比是对不同物理量分别计算的相对降幅，不能平均成一个总体效率数字，引用时必须写明具体口径。Mamba 的常量显存特性允许更高频的前沿重规划，这对动态场景与长 episode 有价值。Cobra 在空间推理类基准上优于部分 7B 级 Transformer 模型，这也是选它做主干的依据之一。

实现思路与设计

训练系统的实现分三块：数据生成、混合采样与序列组装、消融管理。核心设计原则是把「配比」定义成采样概率并固定，使任何消融只改数据源集合，不改优化器与预算。

数据生成与前沿表示

轨迹由贪心前沿探索 oracle 生成：正常朝最近前沿走，目标实例进入 3.5 m 范围后切换到通往目标的那个前沿。每步记录第一人称 RGB-D、当前全部前沿、以及「正确前沿」标签（位于通往最近目标实例最短路径上的前沿）。前沿代表图从历史机位中挑选，判据是相机朝向与该前沿边界垂直度最大。辅助任务在同一批轨迹上生成：取最近 20 帧历史、若干候选图像与局部坐标 (X, Y)，问「环境的哪一部分位于 (X, Y)」，答案是该坐标处拍摄的候选图。

关键代码与解读

三段代码覆盖混合采样、序列组装与损失掩码、消融增量统计。配比常数与论文一致。

片段 1：确定性混合采样器

import numpy as np

MIXTURE = {"objectnav": 26_000, "ovon": 26_000, "imagenav": 40_000, "aux": 30_000}

def mixture_plan(mixture=MIXTURE, batch=576, epochs=3, seed=0):
    """每轮把全部样本按数据源展开后整体打乱，再切片成 batch。
    样本级配比精确成立；打乱种子固定，任何一次重跑得到同一序列。"""
    rng = np.random.default_rng(seed)
    total = sum(mixture.values())
    steps_per_epoch = (total + batch - 1) // batch
    plan = []
    for epoch in range(epochs):
        pool = []
        for name, n in mixture.items():
            pool.extend([name] * n)       # 每轮每个样本恰好出现一次
        rng.shuffle(pool)
        for step in range(steps_per_epoch):
            plan.append((epoch, step, pool[step * batch:(step + 1) * batch]))
    return plan

plan = mixture_plan()
print(len(plan), "steps total")                      # 636
from collections import Counter
print(Counter(plan[0][2]))     # 首批名额；期望约 123 / 123 / 189 / 142
counts = Counter(name for _, _, chunk in plan for name in chunk)
print(counts)                  # 三遍累计 = {objectnav: 78000, ...}

解读：（1）每个样本每轮恰好进入累次一次，样本级配比精确成立；打乱种子固定，任何重跑得到同一序列，消融可以精确归因到数据源变化。（2）122k / 576 得到每轮 212 步，三遍 636 步，与论文训练预算一致；若按步数计配比，长序列任务会获得额外 token 级曝光，口径就变了。（3）单批名额围绕期望值 122.8、122.8、188.9、141.6 波动，跨整轮平均回到占比；验证复现时要检查三遍累计恰为 78k、78k、120k、90k。

片段 2：序列组装与损失掩码

import torch
import torch.nn.functional as F

HISTORY, INSTRUCTION, GOAL_IMG, CHOICE = "hist", "instr", "goal_img", "choice"

def build_sequence(sample, tokenize, encode_image):
    """把一条多任务样本拼成 token 序列；labels 只在答案编号位有值。"""
    tokens, labels = [], []
    for frame in sample["history"][-20:]:
        tokens.append(encode_image(frame, pool="hw_t"))
    tokens.append(tokenize(sample["instruction"]))
    if sample["task"] == "imagenav":
        tokens.append(encode_image(sample["goal_image"], pool="hw"))
    answer_pos = None
    for letter, image in sample["choices"]:
        tokens.append(tokenize(letter))
        if letter == sample["answer"]:
            answer_pos = sum(len(t) for t in tokens) - 1
        tokens.append(encode_image(image, pool="hw"))
    flat = torch.cat(tokens)
    labels = torch.full_like(flat, -100)          # 忽略历史与选项内容
    labels[answer_pos] = flat[answer_pos]          # 只监督答案编号
    return flat, labels

def multi_task_loss(model, batch, tokenize, encode_image):
    losses = []
    for sample in batch:
        tokens, labels = build_sequence(sample, tokenize, encode_image)
        logits = model(tokens.unsqueeze(0))
        losses.append(F.cross_entropy(logits.view(-1, logits.size(-1)),
                                      labels.view(-1), ignore_index=-100))
    return torch.stack(losses).mean()              # 每条样本等权，对应样本级配比

解读：（1）labels 的 −100 掩码保证梯度只来自答案编号，历史帧与候选图像内容不产生监督信号，避免模型学会复述输入。（2）等权平均每条样本的损失，配比由采样名额实现；若对序列长度不一的任务直接按 token 求平均，长序列任务会获得额外权重，配比就变了。（3）答案位置在拼接前计算，注意 sum(len(t) for t in tokens) - 1 的口径与编码器输出长度定义一致，否则监督会错位。

片段 3：消融增量统计

ABLATION = {
    "ON":          {"v02": (74.3, 38.8), "seen": (41.7, 22.0), "syn": (38.8, 21.6), "unseen": (39.4, 22.5)},
    "ON+IN":       {"v02": (74.9, 39.1), "seen": (43.1, 22.8), "syn": (39.3, 21.7), "unseen": (41.5, 23.8)},
    "ON+IN+OV":    {"v02": (74.9, 39.2), "seen": (43.3, 23.3), "syn": (39.9, 22.4), "unseen": (40.8, 23.6)},
    "ON+IN+OV+AX": {"v02": (77.0, 41.3), "seen": (44.9, 24.5), "syn": (40.1, 23.1), "unseen": (40.8, 24.4)},
}
order = list(ABLATION)
for prev, cur in zip(order, order[1:]):
    for split in ("v02", "seen", "syn", "unseen"):
        (p_sr, p_spl), (c_sr, c_spl) = ABLATION[prev][split], ABLATION[cur][split]
        print(f"{prev}->{cur} {split}: dSR={c_sr - p_sr:+.1f} dSPL={c_spl - p_spl:+.1f}")
# 输出与正文增量表逐格一致；ON->全配方: v02 dSR=+2.7, dSPL=+2.5

解读：（1）消融读法固定为「行减上一行」，每行只新增一路数据，把组合效应拆成可归因的增量。（2）统计脚本同时打印四档，避免只挑涨的指标汇报；OVON 行未见档 −0.7 与辅助任务行未见档 SR 0.0 都必须保留在表中。（3）论文报告的是单次运行结果，工程复现时应加多种子重复，并注意基准版本（v0.1 与 v0.2 的类别表与场景列表不同，不可混表）。

常见坑

  • 把步数当配比口径：症状是复现实验里 ImageNav 的隐式权重与论文不符。根因是各任务序列长度不同，固定每步一条样本会让长序列任务曝光更多 token。修复：先声明配比口径（本讲为样本级），在日志里分别统计每路样本数与 token 数，两者都报。
  • 损失在整条序列上计权：症状是训练损失下降很快，评测时前沿选择毫无提升。根因是模型在拟合历史与选项内容的复述，答案位的信号被淹没。修复：标签掩码只保留答案编号位；把答案位的损失单独记录，作为真正的学习信号曲线。
  • 跨基准版本混表：症状是同一张表里出现 v0.1 与 v0.2 的成绩，结论互相矛盾。根因是两个版本的目标类别、场景与 episode 分布不同。修复：每张表标注基准版本与 split；v0.1 的 6 类口径与 v0.2 的数字各自成表。
  • 消融之间冻结策略不一致：症状是增量无法归因，某一行突然大幅波动。根因是有的实验解冻视觉编码器或换了学习率。修复：消融协议先固定编码器状态、优化器、批量与训练遍数，只改数据源集合；把配置写成代码常量并随结果一并记录。
  • 辅助任务的坐标系含糊：症状是辅助损失收敛但前沿选择不涨。根因是 (X, Y) 的参考系在生成端与文档端不一致（机器人局部系与场景全局系混用）。修复：生成时写明坐标系与单位，用一组已知摆放的校验样本回放验证答案唯一性。

  2. 实现片段 1 的采样器并写一个统计测试：任取 100 个 batch，四路累计样本比例的偏差不超过 0.5 个百分点；说明打乱种子为什么必须固定。★★
    提示
    池化打乱保证单轮内每个样本只出现一次，配比精确成立，单批名额的波动随累计 batch 数增加而收敛；累计 100 批约 57,600 条样本，占比偏差可到 0.1 个百分点量级。随机种子不固定会让每次运行的数据顺序不同，消融的增量无法归因到数据源变化。

小结

  • FiLM-Nav（Yokoyama 与 Ha 2025）把 2.8B 的 Mamba 视觉语言模型微调成前沿选择策略：输入 20 帧视觉历史、语言目标与候选前沿图像，输出前沿编号；视觉编码器冻结，训练投影层与语言模型主体，AdamW 学习率 2 × 10−5、批量 576、3 遍、8×A40 约 15 小时。
  • 混合配比按样本数：ObjectNav 26k、OVON 26k、ImageNav 40k、辅助空间任务 30k，合计 122k；占比 21.31%、21.31%、32.79%、24.59%；每轮约 212 步，三遍约 636 步。
  • 消融逐项增量：ImageNav 对未见档贡献最大（SR +2.1、SPL +1.3）；OVON 提升同义档（SR +0.6、SPL +0.7），未见档 SR 回退 0.7；辅助任务贡献最大效率增益（v0.2 SPL +2.1、Seen SPL +1.2）。全配方相对单任务：v0.2 SR +2.7、SPL +2.5。
  • 榜单：HM3D-v0.2 上 77.0% / 41.3%，比 Uni-NaVid 高 3.3 / 4.2 个百分点；HM3D-OVON 三档 SPL 全部第一（24.5 / 23.1 / 24.4），Seen 与 Unseen 档 SR 第一，同义档 SR 落后 3.8 个百分点。
  • 边界：v0.1 上 SR 低于 PIRLNav（61.7% 对 70.4%），2D 图无法跨楼层，13.9% 的 episode 需要楼层切换；真机只验证了图像级前沿选择，整机部署待后续工作。
  • 下一讲把镜头转向仿真与真机的落差：用 HomeRobot OVMM 的两份数据（Yenamandra 等 2023、2024）做阶段分解，并讨论评测样本量对结论可信度的影响。
