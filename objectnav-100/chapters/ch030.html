第二篇 · 模块化：地图·探索·常识

第 030 讲｜ESC：常识谓词

ESC（Zhou 等，2023）把「物体通常出现在哪里」写成一小组带权重的软逻辑规则，挂在经典前沿探索之上：GLIP 负责开放世界接地，语言模型给出房间与物体的常识分数，概率软逻辑（PSL）把两种知识合成对每个前沿的选择倾向。整个过程不做导航训练、不标新环境，在 MP3D、HM3D、RoboTHOR 三个基准上同时超过同设定的零样本基线，MP3D 成功率相对 CoW 提升 287.8%（实算）。

  • 主题：零样本 ObjectNav / 开放世界接地 / 软逻辑谓词
  • 关键公式：P(Y | X) ∝ exp(−Σi wi φi(Y, X))
  • 预计学时：60 分钟
  • 前置章节：第 029 讲

学习目标

  • 能复述 ESC 的三段结构：提示词驱动的开放世界接地、语言模型常识推理、软逻辑前沿选择。
  • 能写出四条软规则与一条和为一硬约束，并用 Łukasiewicz 语义手算规则体的满足度。
  • 能用 one-hot 求解器对候选前沿排序，说明它与凸优化求解的关系以及 8.52 倍的推理耗时差。
  • 能配置 df、do、dr 与规则权重，说明取值依据与调参方向。
  • 能判断常识先验在什么分布下失效，并为「常识有害」的场景设计对照实验。

背景与动机

第 029 讲说明了模块化系统的感知瓶颈，另一条主线是从第 023 讲延续的学习式先验：SemExp 与 PONI 把「物体可能在哪」训练进网络，代价是数据、算力与环境分布绑定。换一批未见物体或未见建筑，先验的表征需要重新校准；PONI 虽把训练成本压低，仍要在带标注的环境上学习势函数。若把常识来源换成大规模预训练的图文模型与语言模型，先验就可以按目标类别现场查询，避开任务特定训练。

ESC（Zhou 等，2023，Exploration with Soft Commonsense Constraints for Zero-shot Object Navigation）正是沿这条路线：用 GLIP 做开放世界接地，识别当前视野里的常见物体与房间；用语言模型回答「目标物体与这个物体、这个房间有多相关」；再用概率软逻辑把相关性、邻近距离与探索距离合成一个分数，选择下一个前沿。它的零样本含义比常见口径更严格：不仅测试环境与目标是新的，而且不使用任何导航数据训练。

本讲解决的问题有两个：常识以什么形式参与决策，才能既有表达力又不被单条错误的常识主导；以及一组手工设计的规则在哪些数据分布上成立、哪些分布上失效。第 031 讲会把这里的规则推理简化成语言模型对前沿描述句的直接打分，第 032 讲回到真机与泛化证据。

核心原理

1. 任务设定与零样本的三档强度

任务仍是第 001 讲的 ObjectNav：智能体在未见环境中寻找类别词指定的物体实例，成功判据为停止时距目标足够近且可见。ESC 关注其中的零样本档位，按「训练数据」把方法分成三档，避免口径混谈：

档位训练内容代表方法跨环境、跨类别的代价
监督学习在标注环境上训练导航策略PONI、ProcTHOR分布外泛化最弱，指标最高
跨任务迁移在 ImageNav 等其他任务上大规模训练ZSON依赖目标嵌入的映射质量
零训练不做任何导航训练CoW、ESC泛化最强，依赖预训练模型质量

ESC 与 CoW 同档，两者的差别在感知与探索的组织方式：CoW 用 CLIP 梯度可视化定位目标，探索取最近前沿；ESC 用 GLIP 理解全场景，探索由常识评分驱动。评测协议为：MP3D 验证集 2195 条 episode、11 个环境、21 个目标类别；HM3D 验证集 2000 条、20 个环境、6 类；RoboTHOR 验证集 1800 条、15 个环境、12 类；三者的最长步数均为 500，智能体为半径 0.18 m、高 0.88 m 的圆柱，动作空间为前向 0.25 m、旋转 30°、抬头低头 30°与 STOP。

2. 开放世界接地与语义地图

接地的目标是把图像转成语言可消费的场景描述。ESC 使用 GLIP（Li 等，2022）这一图文接地模型：给定图像 I 与文本提示 P，输出短语与图像区域的匹配分数与框。物体提示 Po 由常用室内物体集合 {oc} 与可能的目标集合 {og} 的并集拼接而成，房间提示 Pr 由常用房间集合生成：

{ot,i, bot,i} = GLIP(It, Po)    {rt,i, brt,i} = GLIP(It, Pr) o 为物体、r 为房间；b 为对应框；提示词以句点分隔的类别名列表给出，可随测试数据扩展

建图沿用深度反投影：像素结合深度、位姿与相机参数变换到三维体素，靠近地板的体素记为自由空间，再沿高度方向压平成二维导航图。物体投影取框中心落到地图上的单点；房间投影把框内全部像素落入的格都记为对应房间，使房间区域在图上成片。两类投影的粒度差异后面会用到：物体是点状证据，房间是面状证据。

3. 语言模型常识推理

常识查询定义为：对每个候选物体 oi 与房间 ri，语言模型输出「目标 G 与它相关」的实值分数 S(G | oi) 与 S(G | ri)，取值归一在 0 到 1。例如目标为 bed 时，bedroom 的分数高、kitchen 的分数低；nightstand 的分数高、fridge 的分数低。ESC 主要使用 Deberta v3，也验证了 ChatGPT 的可用性，两者在 HM3D 上的差距很小：

模型 / 常识层级SPLSRSoftSPL
Deberta（物体 + 房间）22.339.231.1
ChatGPT（物体 + 房间）22.439.031.1
Deberta（仅物体）21.839.330.6
Deberta（仅房间）22.339.330.2

表中数字说明语言模型的来源不敏感，关键是查询的组织方式；房间级与物体级推理带来接近的收益，两者合并时 SoftSPL 最高（31.1）。这里的分数是查询视角的先验，不含场景证据，场景证据由第 2 节的接地分数提供。

4. 从常识到动作：为什么需要软逻辑

把常识直接写成「目标在厨房就先去厨房」会立刻出问题：房间识别有置信度，常识本身是概率性的，多个前沿可能同时满足多条规则，硬性二值逻辑会把噪声放大成极端决策。ESC 采用概率软逻辑（Probabilistic Soft Logic, PSL，Bach 等，2017）把每条规则写成带权重的软约束。PSL 的基本元素是原子（atom），取值在 [0, 1]；规则是原子的一阶逻辑子句；真值用 Łukasiewicz 连续语义计算：

a ∧ b = max(0, a + b − 1)    ¬a = 1 − a 合取要求两个原子同时接近 1 才得高分；取反把 [0,1] 折返，便于写「不大可能在…」形式的负规则

每条落地规则（ground rule）产生一个铰链损失势：

φ(Y, X) = [ max(0, l(Y, X)) ]p，   P(Y | X) = (1 / Z) exp( − Σi wi φi(Y, X) ) l 为规则的线性违背量；Z 为归一化常数；wi 为规则权重；p 取 1 或 2；X 为观测原子，Y 为待定原子

最大化后验等价于最小化加权违背量之和，目标函数是凸的，可用 ADMM 一类算法求解。ESC 的额外观察是：最终只需要选一个前沿，可用 one-hot 约束把解空间限制成「每个前沿各试一次」，直接计算每种选择的违背量总和，取最小者。这个求解器不需要迭代，实测每次推理 0.25 秒，对应 ADMM 的 2.13 秒，加速 8.52 倍，MP3D 上的 SR 也从 27.0 略升到 27.8。

5. 四条规则、一条硬约束与阈值

ESC 的规则库只有五条，全部围绕「选择哪个前沿」这一个决策变量：

规则形式权重直觉
物体正规则IsCooccur(Goal, Object) ∧ IsNearObj(Frontier, Object) → ChooseFrontierw = 1.0前沿靠近与目标共现的物体，加分
物体负规则¬IsCooccur(Goal, Object) ∧ IsNearObj(Frontier, Object) → ¬ChooseFrontierw = 1.0前沿靠近与目标不相关的物体，减分
房间正规则IsCooccur(Goal, Room) ∧ IsInRoom(Frontier, Room) → ChooseFrontierw = 1.0房间与目标相关，加分
房间负规则¬IsCooccur(Goal, Room) ∧ IsInRoom(Frontier, Room) → ¬ChooseFrontierw = 1.0房间与目标不相关，减分
距离规则ShortDist(Frontier) → ChooseFrontierw = 2.0（双常识时）保留经典最近前沿倾向，防止舍近求远
和为一硬约束ChooseFrontier(+Frontier) = 1硬唯一选择，防止全选退化

原子的取值来源：IsCooccur 取语言模型分数 S(G | ·)；IsNearObj 取对象检测置信度，条件是该物体距前沿 do 以内，否则为 0；IsInRoom 取房间检测置信度，条件是该前沿落入房间范围内；ShortDist 由距离归一化得到。距离阈值与相关半径取 df = 1.6 m（最近前沿基准）、do = 1.6 m、dr = 0.6 m；前两个是探路半径，第三个是房间归属的宽松判定。权重取 1.0 的含义是四类常识证据等权；距离权在同时启用物体与房间推理时提到 2.0，用于抵消常识项数量翻倍后距离项被稀释的倾向。

6. 数值算例：三前沿的软约束排序

构造一个小场景：目标为 bed，三个候选前沿各带一个主导房间与一个邻近物体，ShortDist 定义为 1 − min(1, d / 8)。原子数值与 Łukasiewicz 规则体如下（物体正体 = max(0, S(G|o) + confo − 1)，负体 = max(0, 1 − S(G|o) + confo − 1)，房间同构）：

前沿邻近物体（分数, 置信度）物体正/负体所在房间（分数, 置信度）房间正/负体ShortDist
F1nightstand (0.75, 0.80)0.55 / 0.05bedroom (0.85, 0.90)0.75 / 0.050.750
F2fridge (0.02, 0.90)0.00 / 0.88kitchen (0.05, 0.85)0.00 / 0.800.250
F3door (0.10, 0.95)0.05 / 0.85hallway (0.15, 0.60)0.00 / 0.450.625

one-hot 求解器对每个候选选择计算总违背量。不选某前沿时，它的正体与距离项都被记罚；选中某前沿时，它的负体被记罚。设 SΣ 为所有前沿正体与距离项之和（此处 SΣ = 4.600），则选择前沿 F 的总损失可写成：

Loss(F) = SΣ − ( wo·poso(F) + wr·posr(F) + wd·ShortDist(F) ) + ( wo·nego(F) + wr·negr(F) ) 括号内为「选它的收益」，末项为「选它的代价」；求解器在三个候选间取 Loss 最小者

代入数值：Loss(F1) = 4.600 − (0.55 + 0.75 + 1.500) + (0.05 + 0.05) = 1.900；Loss(F2) = 4.600 − (0 + 0 + 0.500) + (0.88 + 0.80) = 5.780；Loss(F3) = 4.600 − (0.05 + 0 + 1.250) + (0.85 + 0.45) = 4.600。选择 F1（卧室方向，损失 1.900），排序与常识一致。做一次敏感度检查：把 S(bed | bedroom) 从 0.85 降到 0.50，F1 的房间正体降为 0.40、负体升为 0.40，SΣ 变为 4.250，三个损失变为 2.250、5.430、4.250，F1 仍胜出，但领先优势从 2.700 缩到 2.000。这个算例说明软约束的排序由「正体收益减负体代价」决定，单个分数变动不会立刻翻转结论，这正是软逻辑相对硬规则的抗噪来源。

按表内数值实算的相对提升：对 CoW，MP3D 的 SR 从 7.4 到 28.7，相对 +287.8%（原文摘要概括为 288%），SPL 从 3.7 到 14.2，相对 +283.8%（原文为 284%）；RoboTHOR 的 SR 从 26.7 到 38.1，相对 +42.7%，SPL 从 16.9 到 22.2，相对 +31.4%。对需要训练的 ZSON，MP3D 的 SPL 相对 +195.8%，HM3D 的 SPL 相对 +77.0%，跨数据集一致性明显更好。对监督的 PONI，ESC 在 MP3D 的 SR 低 3.1 个点，SPL 高 2.1 个点，说明零训练方法已经逼近监督方法的效率水平。注意 ProcTHOR-ZS 在 RoboTHOR 上 SR 达 55.0，与其预训练环境同源有关；到 HM3D 掉到 13.2，跨环境稳定性不如 ESC。

消融实验把增益拆到常识层级。以 GLIP 接地但不加常识（GoW）为底：MP3D 的 SR 从 25.6 到 28.7（+3.1 个点），HM3D 从 33.1 到 39.2（+6.1 个点），RoboTHOR 从 36.1 到 38.1（+2.0 个点）。去掉房间推理与去掉物体推理的版本互有胜负：在 MP3D 与 HM3D 上双常识最优，在 RoboTHOR 上去掉物体推理反而到 39.3，比完整版高 1.2 个点。原因是 RoboTHOR 的物体摆放随机、不遵循住宅常识，物体级共现先验与场景不符，此时它成为噪声源；这与该基准上房间级推理仍然有效的现象一致。失败分析显示，常识带来的探索收益体现在前沿选择质量上：选择的前沿到最近目标的平均距离从 8.2 m 降到 7.6 m，探索类错误率从 14.3% 降到 10.6%（相对下降 25.9%），规划类从 12.1% 降到 9.5%（相对下降 21.5%），而检测类错误保持在 40.8%，依旧是最大瓶颈。

SoftSPL 提供了另一种读法。HM3D 上 GoW 的 SoftSPL 为 27.0，ESC 为 31.1，相对提升 15%；MP3D 上完整版为 23.8，去掉物体推理的版本为 24.1，说明按「抵达进程」加权时，物体级证据在部分 episode 上拖慢了接近目标的节奏。三个指标并列报告的价值在此显现：SR、SPL 与 SoftSPL 对「差一点到达」的轨迹给出不同分数，单独看任何一个都可能选出不同的配置。

8. 边界与失效模式

第一，常识规则库是手工设计的模板，覆盖的语义关系有限：共现、房间归属、距离三类之外的关系（门后、容器内、楼上）表达不了，目标类别换成抽象词或部件词时查询退化。第二，软逻辑的输入分数来自统计与提示词，分布外环境里语言模型的分数会系统性偏移，需要抽检与校准，尤其在多语言或非欧美住宅布局上。第三，模板权重目前靠枚举与经验设定，本文也只给出两组取值（1.0 与 2.0），大规模规则库需要学习权重。第四，零训练不等于零成本：GLIP 与语言模型的前向、PSL 的实例化都在线运行，单次前沿推理 0.25 秒是相对 ADMM 的优势，绝对算力仍高于纯几何方法。第五，也是最重要的一条：常识只改变探索方向，检测错误的主导地位不受其影响，检测错误占失败的四成，换更强接地模型或补漏检策略是独立且必要的方向。第六，接地侧的提示词同样是边界条件：物体提示由常用集合与目标集合拼接而来，复合词、部件词的拆分粒度会改变框质量；房间提示若缺少某类房间名，该房间的前沿收不到任何房间级证据，软逻辑在该区域退化为物体与距离两类证据。上线前应在目标类别集合上做一次接地召回抽检，记录每类的框命中率，作为规则库是否可信的前置条件。

实现思路与设计

ESC 的工程实现可以拆成一条固定数据流：GLIP 接地 → 语义地图 → 语言模型查询与缓存 → 规则实例化 → one-hot 求解 → 局部导航。各模块的接口与职责如下：

模块输入输出要点
ground（GLIP）RGB 帧、物体与房间提示词类别、框、置信度开放词表，提示词随目标集合在线拼接
map框、深度、位姿导航图、物体点、房间面、前沿集合物体取中心，房间取框内全像素
reason（LLM）目标类别、物体与房间词表S(G | ·) ∈ [0, 1]结果按类别对缓存，重复查询不重算
instantiate地图、常识分数、阈值原子取值与规则表距离过滤在实例化前完成
solve（PSL）原子取值、权重被选前沿one-hot 枚举违背量，硬约束和为一
navigate被选前沿、当前位姿动作序列接经典规划与控制，与前沿方法共用

设计决策：软约束先于硬筛选

常见的工程做法是先按房间分类硬筛掉「不可能」区域，再在剩余区域探索。ESC 的对照说明这种硬筛在识别有噪声时会误伤：房间置信度 0.6 的走廊与 0.9 的卧室在软逻辑里以不同权重参与竞争，硬筛会把走廊直接清零，一旦目标真的在走廊就永久找不到。软约束把判断成本保留到最后一刻，由所有证据联合决定。

设计决策：常识分数缓存与失效

S(G | o) 只与目标类别和词表有关，与 episode 位置无关，可按（目标类别，词）建缓存，跨 episode 复用。失效条件是词表扩展或语言模型更换；工程上给缓存加版本号，模型或提示词一变就整体重算，避免新旧分数混用。

权重不是可忽略的超参

规则等权 1.0 是起点，不是结论。常识项数量变化时若不调整距离权重，前沿选择会退化为「按常识跳最远的房间」，路径效率下降而 SR 可能不变，指标掩盖了代价。调参时同时记录所选前沿到当前位姿的距离分布与 SR、SPL，四项一起看。

关键代码与解读

片段 1 实现第 6 节的数值例：给定原子的观测值，计算每条规则体的 Łukasiewicz 满足度、总违背量与 one-hot 选择。片段 2 给出语言模型查询的缓存组织与提示词构造。

片段 1：规则实例化与 one-hot 求解

import itertools

def land(a, b):
    return max(0.0, a + b - 1.0)          # Łukasiewicz 合取

def rule_bodies(frontier, w_o=1.0, w_r=1.0, w_d=2.0, d_max=8.0):
    """把一条前沿的全部证据换算成规则体取值。"""
    s_o, c_o = frontier["obj_score"], frontier["obj_conf"]
    s_r, c_r = frontier["room_score"], frontier["room_conf"]
    dist = frontier["dist"]
    short = 1.0 - min(1.0, dist / d_max)  # 归一化邻近度，越近越接近 1
    pos_o, neg_o = land(s_o, c_o), land(1 - s_o, c_o)
    pos_r, neg_r = land(s_r, c_r), land(1 - s_r, c_r)
    return dict(pos_o=pos_o, neg_o=neg_o, pos_r=pos_r, neg_r=neg_r, short=short)

def choose_frontier(frontiers):
    bodies = {f["name"]: rule_bodies(f) for f in frontiers}
    total = sum(b["pos_o"] + b["pos_r"] + 2.0 * b["short"] for b in bodies.values())
    best, best_loss = None, None
    for f in frontiers:                    # one-hot 枚举：每个候选各试一次
        b = bodies[f["name"]]
        gain = b["pos_o"] + b["pos_r"] + 2.0 * b["short"]
        cost = b["neg_o"] + b["neg_r"]     # 选中时负规则被触发
        loss = total - gain + cost
        if best_loss is None or loss < best_loss:
            best, best_loss = f["name"], loss
    return best, best_loss

解读：（1）land 是一行核心算子，软逻辑的全部抗噪性质从这里来：两个证据都接近 1 时合取才接近 1，任一证据弱则迅速归零，规避了证据相乘的过度惩罚。（2）rule_bodies 把「目标与物体/房间的相关性」与「场景里检测到它」两个条件合成一个体，正是规则表中前四条的公共结构。（3）choose_frontier 的 total 是常数项，循环里的 loss = total − gain + cost 与第 6 节公式逐项对应；当 frontier 数量增长时该枚举是线性复杂度，但每个候选的规则体是常数个，这是 one-hot 求解器比通用凸优化快的根源。（4）w_d 在函数签名里给出默认 2.0，对应双常识配置；只启用一种常识时改为 1.0，与参数表一致。

片段 2：常识查询缓存与提示词

class CommonsenseCache:
    def __init__(self, scorer, version="deberta-v3-base"):
        self.scorer = scorer              # 输入 (name_a, name_b)，输出 [0, 1]
        self.version = version
        self.table = {}

    def score(self, goal, name):
        key = (goal, name)
        if key not in self.table:         # 只与词对有关，跨 episode 复用
            self.table[key] = self.scorer(goal, name)
        return self.table[key]

def build_scores(cache, goal, objects, rooms):
    obj = {o: cache.score(goal, o) for o in objects}
    room = {r: cache.score(goal, r) for r in rooms}
    return obj, room                      # 键为类别名，值为 S(G | ·)

def bump_version(cache, new_version):
    cache.version = new_version           # 模型或提示词变化时调用
    cache.table.clear()                   # 防止新旧分数混用

解读：（1）缓存键是（目标，候选词）二元组，与 episode 无关，因为常识分数与场景无关；跨 episode 复用使在线成本摊薄到首次查询。（2）score 返回实值直接作为 IsCooccur 原子，调用方不再做二值化，这是软逻辑入口处最容易被写错的地方。（3）bump_version 是防御式设计：模型换代后缓存必须整体失效，否则同一目标会拿到两套量纲的分数。（4）提示词构造被封装在 scorer 内部，词表扩展只需重新注册 scorer 并 bump，不触碰规则实例化代码。

片段 3：前沿邻域检索与原子组装

import math

def nearby_evidence(frontier_xy, objects_on_map, rooms_on_map, d_o=1.6, d_r=0.6):
    """从语义地图收集前沿附近的物体与房间证据。"""
    obj_hits, room_hits = [], []
    for name, conf, (ox, oy) in objects_on_map:
        if math.dist(frontier_xy, (ox, oy)) <= d_o:   # 物体：点状证据，半径 d_o
            obj_hits.append((name, conf))
    for name, conf, cells in rooms_on_map:
        for (rx, ry) in cells:                        # 房间：面状证据，逐格判定
            if math.dist(frontier_xy, (rx, ry)) <= d_r:
                room_hits.append((name, conf))
                break
    return obj_hits, room_hits

解读：（1）物体用单点坐标与半径 do 判定邻近，房间用格集合与半径 dr 判定归属，对应第 2 节两种投影粒度的差异。（2）若同一类别有多个实例命中，调用方取最高置信度，避免同一物体被重复计数进多条规则。（3）阈值在这里以函数参数出现，调参不改变规则逻辑；若要试验不同的 do、dr，只需重跑该函数。（4）该函数输出的列表就是片段 1 中 obj_score 与 obj_conf 的取值来源，两个片段拼起来即为一条前沿的完整实例化路径。

常见误区

  • 用硬阈值替代软约束：症状是房间分类错一次就永久错过目标，成功率的方差大。根因是把 S(G | r) 二值化后直接筛除区域，识别噪声被放大成不可逆决策。修复：保留实值分数参与竞争，只在最后一步做选择；若要硬筛，阈值取在分数分布的极端尾部并记录被筛区域。
  • 权重未标定：症状是启用常识后绕远路变多，SPL 下降而 SR 不降。根因是常识项数量增加后距离项的相当权重被稀释，规则体系整体偏向「按常识远跳」。修复：按第 5 节的配平思路调距离权重，同时监控所选前沿的距离分布，而不只看最终指标。
  • 语言模型分数未归一：症状是换一版模型或提示词后排序整体失真。根因是不同模型的输出量纲不同，直接当原子使用会破坏 [0,1] 语义。修复：在 scorer 出口做温度缩放或分位裁剪，版本升级时清空缓存并重跑基准样例。
  • 房间识别错误未兜底：症状是目标出现在视觉上像别处的房间里，探索反复绕开。根因是房间原子完全依赖 GLIP 的房间识别，缺少与物体证据的联合校验。修复：提高房间负规则的触发门槛，或引入房间与物体的交叉证据；监控房间识别的混淆矩阵。
  • 在语义随机分布上照搬常识：症状是纯随机的合成基准上常识版本反而更差。根因是常识先验假设了住宅式摆放，随机摆放的环境里该假设失效。修复：像 ESC 在 RoboTHOR 上做的那样，按常识层级做消融，确认物体级推理的收益是否为负，再决定启用哪些规则。

练习与思考

  1. 写出 ESC 的四条软规则与和为一硬约束，说明每条规则中两个原子的取值来源，并解释为什么「和为一」约束能防止退化解。★
    提示
    原子来源：IsCooccur 取语言模型分数，IsNearObj / IsInRoom 取检测置信度并按 do / dr 过滤，ShortDist 取距离归一。没有和为一约束时，把所有 ChooseFrontier 全设为 1 可以让所有正规则同时满足，选择结果失去意义。
  2. 用 Łukasiewicz 语义计算：S(G | bedroom) = 0.7、房间置信度 0.8 时，房间正规则体与负规则体各是多少？若再要求该前沿被选中，房间负规则的惩罚是多少？★
    提示
    正体 = max(0, 0.7 + 0.8 − 1) = 0.5；负体 = max(0, 0.3 + 0.8 − 1) = 0.1。选中时负规则被触发，惩罚为该负体乘权重。
  3. 在数值算例中把距离规则权重从 2.0 降到 1.0，重新计算三个前沿的损失与选择结果，并说明权重变化对「舍近求远」倾向的影响。★★
    提示
    距离项降到 1.0 后：SΣ = 0.55 + 0.75 + 0.750 + 0.25 + 0.05 + 0.625 = 2.975；Loss(F1) = 2.975 − 2.050 + 0.10 = 1.025，Loss(F3) = 2.975 − 0.675 + 1.30 = 3.600，Loss(F2) = 2.975 − 0.250 + 1.68 = 4.405；F1 仍胜，领先优势从 2.700 微降到 2.575。降权后距离证据对排序的修正力度变弱，常识分数若估偏，缺少把选择拉回近处的手段。
  4. 解释 one-hot 求解器为什么比通用凸优化快 8.52 倍：从解空间维数、每次评估的代价、迭代次数三个角度分析，并说明它的解与凸优化的解在什么条件下一致。★★

    提示

小结

  • ESC 用三段结构实现零训练 ObjectNav：GLIP 开放世界接地、语言模型常识打分、PSL 软约束前沿选择，全程不做导航训练。
  • 软约束由四条常识规则与一条距离规则组成，Łukasiewicz 合取与铰链损失把证据强弱连续地映射成选择倾向，和为一硬约束保证唯一选择。
  • one-hot 求解器只需枚举 |F| 个候选，0.25 秒/次，比 ADMM 快 8.52 倍且精度相当；数值算例给出三前沿的完整手算过程与敏感度检查。
  • 三基准结果：MP3D 14.2 SPL / 28.7 SR，HM3D 22.3 / 39.2，RoboTHOR 22.2 / 38.1；MP3D 的 SR 相对 CoW 提升 287.8%（实算值），跨数据集一致性优于 ZSON。
  • 常识先验有明确的适用边界：RoboTHOR 随机摆放使物体级推理成为负收益（39.3 对 38.1），检测类错误仍占失败的约四成，是独立瓶颈。
