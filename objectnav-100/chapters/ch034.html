第二篇 · 模块化：地图·探索·常识

第 034 讲｜多楼层推广：MFNP

上一讲指出跨楼层占 PIRLNav 失败的 21%，而挑战赛长期把 episode 限制在单层内。MFNP（Zhang 等，2024）把楼层切换写成四因子决策函数与单向楼梯状态机：何时换层由时间、物体覆盖、探索增量与大模型建议共同打分，换层过程用入口置障约束为单向通行，失败后 200 步重置地图。本讲逐项推导该机制，读 HM3D 与 MP3D 结果表，并给出跨层评测协议的设计方法。

  • 主题：多楼层导航 / 楼梯策略 / 层间状态机 / 足式真机
  • 关键公式：NMFNP = w1 f(t) + w2 · Oexplored/Ototal + w3 (1 − Et) + w4 PLLM
  • 预计学时：70 分钟
  • 前置章节：第 033 讲 失败模式解剖

学习目标

  • 能复述 MFNP 的三个组件与数据流：大模型选点、视觉语言模型复核目标检测、多楼层策略与层间导航。
  • 会算决策分数与时间窗：f(t) = (500 − t) / 500 的取值、[150, 300] 可用窗口、200 步重置期限，以及权重变化对触发结论的影响。
  • 会画并实现跨层状态机：探索、奔梯、梯上、新层探索与重置五个阶段，入口置障保证单向，重置计时防止卡死。
  • 会读结果与消融：HM3D 与 MP3D 上的相对变化、触发子集内的对照、四个信息因子各自的贡献排序。
  • 会设计跨层评测协议：楼层标注缺失时的分层办法、楼梯成本的度量、真机证据的样本边界。

背景与动机

第二篇到这里介绍的方法几乎都默认环境是平的：前沿探索、语义地图、目标导向策略都在单层平面上计算。第 033 讲给出这份默认假设的代价：PIRLNav 的 592 条失败里，21% 是目标位于另一层而智能体没有完成上下楼梯，按修复上界折算相当于 6.22 个百分点的成功率增量。真实住宅大量是多层结构，目标类别的空间分布本身带有垂直结构：卧室家具更常出现在上层，客厅物件更多在底层。MFNP 论文统计 MP3D 数据集中 57.3% 的场景含有跨楼层分布的目标类别，第 001 讲至第 020 讲的评测协议却因 2023 年挑战把 episode 限制为单层，系统性地漏掉了这部分难度。

把搜索从二维推广到多层，难点不在「多走一段楼梯」，而在三个耦合问题。第一，何时换层：早换会导致当前层覆盖不足，晚换会在楼梯上耗尽步数预算。第二，如何换层：楼梯区域在语义地图上是不规则通道，定位与建图在此处噪声最大，往返决策容易形成两层之间的振荡。第三，换层失败后如何恢复：原地卡死的代价是整条 episode 报废。MFNP（Zhang 等，2024）用一套学习自由的流程同时回答三问：决策分数由四个信息因子合成，层间导航用入口置障强制单向，失败恢复用语义地图的重置与策略暂停。

该工作的实现基于 L3MVN 与 TriHelper 的架构：语言侧用 Qwen2，视觉语言侧用 Qwen2-VL-Int4 做目标复核，分割用 Mask2Former，评测落在 HM3D 与 MP3D 的多楼层场景上，真机用宇树 Go1-Edu 四足平台。本讲是第二篇第一次进入垂直空间，第 035 讲的多机协作与第 036 讲的概率信息路径规划都会沿用这里的楼层状态机接口；第五篇第 094 讲会把它放回足式平台的系统语境里复核。

核心原理

1. 地图表示与选点（从 031 至 033 承接）

MFNP 的语义地图是一个三阶张量，通道数为 Cn + 5：前四通道记录障碍、已探索区域、智能体当前位置与历史轨迹，随后 n 个通道对应 n 类物体的语义分布，最后一个通道专门保存楼梯区域，供跨层策略查询。候选探索点从已探索区域的边界与膨胀后的障碍边界之差中提取，保留面积足够大的连通区域，取质心作为候选点集合 P。每个候选点的排序分数沿用代价效用形式：

S(pi) = B(pi) − α D(pi) B 为收益函数，D 为距离代价的代理量，α 调节两者的相对重要度

排序后的大模型选点有两个防退化规则：候选点周边已探索面积占比 Ri = Areaexplored / Areaunexplored 超过 90% 时排除该点，改选下一名；检测到大模型重复选同一候选点时，暂时放开约束让智能体自由探索，以降低未探索面积。目标检测侧引入视觉语言模型复核：分割置信度与视觉语言模型的判定概率按权重合成，

Cconf = β · Pseg + (1 − β) · Pvlm β 为融合权重，取 0 到 1；复核用于压低分割模型的假阳性

两条规则与复核机制都在为跨层决策服务：楼梯通道附近的物体分布稀疏，语义证据本就薄弱，如果不先控制选点震荡与误检，跨层策略收到的输入会先被噪声淹没。

2. 楼层切换决策：四因子分数与时间窗

跨层策略只在检测到楼梯时激活，记楼梯存在性为二值变量 Estair，由语义分割识别楼梯并写入地图通道。激活之后，智能体每个时刻把三类现场信息与大模型的楼层建议合成决策分数：

NMFNP = w1 f(t) + w2 · Oexplored / Ototal + w3 (1 − Et) + w4 PLLM 四个因子加权求和，超过阈值 Nth 时决定经由楼梯探索其他楼层

逐项定义。f(t) 是时间项：

f(t) = (500 − t) / 500 episode 上限 500 步；时间项随进程递减，抑制临近结尾时换层

Oexplored / Ototal 是已探索物体类别数与类别总数的比值，比值越高，当前层出现新目标的概率越低。Et 是固定时间间隔 Δt 内新增探索面积占当前层面积的比例，(1 − Et) 越大表示当前层越接近探完。PLLM 为语言模型基于提示给出的换层建议置信度，提示中包含当前步数、已探索物体与面积增量三组信息。

时间窗是硬约束：前 150 步与最后 200 步禁止上楼梯，可用窗口为 [150, 300]，长度 150 步，占 episode 的 30%；被禁用区间合计 350 步，占 70%。时间项的取值表如下，注意它从起点开始单调下降；前 150 步的禁用由窗口约束直接实现，f(t) 与窗口叠加使用。

3. 层间导航：单向楼梯与失败恢复

决策触发后进入层间导航流程，分为四步。第一步，奔梯：把楼梯区域的质心设为下一个航点，用与普通候选点相同的点对点规划到达。第二步，单向化：智能体进入楼梯区域后，系统对入口区域做膨胀操作并标记为障碍，迫使路径只能从楼梯另一端的出口离开，从机制上排除「走两步又退回来」的振荡。第三步，出口引导：在楼梯对面一端设置出口航点，规划器按该航点完成跨层。第四步，失败恢复：如果 200 步内既没有完成换层，也没有在新楼层更新地图，系统重新初始化语义地图、暂时禁用多楼层策略，让智能体在当前状态恢复探索。200 步占 episode 上限的 40%，为恢复留出足够预算。

单向化与重置是这套机制里最值得借鉴的两处设计。楼梯是多层结构中唯一的高噪声通道：几何呈现陡峭，定位容易漂移，语义分割容易把台阶与家具混淆。若不限制通行方向，策略很容易在两层入口之间来回踱步，地图上两层信息叠加成一张互相污染的平面；若不设重置，一次失败会占用后续全部步数。这两个启发式把「跨层」从连续决策问题转化为一个有超时保护的状态迁移，代价是灵活性的损失：单向化之后，智能体无法在同一楼层与楼梯之间多次往返取舍，重置也可能丢掉已经积累的有效信息。

跨层还需要楼梯几何进入预算账。按常见住宅楼梯的尺寸估算：踏步高 0.18 m、踏面 0.28 m、层高 2.7 m，则每层需要 15 级踏步（2.7 / 0.18 = 15），水平投影 4.2 m（15 × 0.28 = 4.2），斜向里程约 4.99 m（√(2.7² + 4.2²) = 4.993），坡度角约 32.74°（atan(0.18 / 0.28)）。前向步长 0.25 m 时，500 步的前向预算为 125 m，单层楼梯的斜向里程只占 3.99%；楼梯消耗的主要是转向与对齐的步数，以及墙壁附近的局部规划开销。四足平台的自平衡与爬梯技能由底层控制器承担（MFNP 真机使用 Go1 的爬梯接口），策略层只负责把智能体带到楼梯入口与出口。

5. 数值算例（Python 实算）

算例一，决策分数复核。按等权 (0.25, 0.25, 0.25, 0.25) 与偏语言 (0.15, 0.15, 0.15, 0.55) 两组权重代入三个场景：早段 0.4437 / 0.3463，中段 0.6625 / 0.7175，晚段 0.6200 / 0.6120。以 0.5 为教学阈值，早段两个模型都不触发；中段两个模型都触发；晚段两个模型也都仍超过阈值（0.6200 与 0.6120）。触发决策在三个场景中的结论与权重选择一致，说明四因子的方向设计比精确权重更重要；但注意晚段恰在窗口末端，触发后只剩 200 步，与重置期限重合，实现上应直接拒绝这类边界触发。

算例二，结果表差值。HM3D 全量上 MFNP 相对 TriHelper 的三项变化为 +1.8 个百分点、+0.014、−0.305 m；触发子集上同样三项为 +5.5 个百分点、+0.009、−0.328 m。成功率增量在子集上扩大约 3.1 倍（5.5 / 1.8），说明全量平均把跨层收益稀释了。报告多楼层方法的改进时，全量与触发子集应成对出现，只报一个会系统性低估或高估。

算例三，时间预算与重置。可用窗口 [150, 300] 共 150 步（30%），失败重置期限 200 步（40%）。若在 t = 200 触发，剩余 300 步，跨层消耗按楼梯斜向里程 4.99 m 加两侧对齐估算远小于步数预算，主要风险在局部规划与定位；若在 t = 300 触发，重置期限与 episode 剩余长度重合（同为 200 步），恢复空间为零，这种边界情况应在实现里直接拒绝触发。窗口末端应留出保守余量：教学实现把触发上界从 300 收紧到 250（预留 50 步恢复余量），并记录被该规则挡下的触发请求数量，作为参数调整的依据。

6. 适用边界与失效模式

  • 楼梯检测漏报：Estair 为 0 时策略永不激活，智能体把整条 episode 耗在单层；分割模型对楼梯的召回是系统级前置条件。
  • 楼梯误报：把台阶状纹理或家具误判为楼梯会触发无效跨层，浪费可观步数；视觉语言模型复核与多帧投票可以压制但无法消除。
  • 楼层标注缺失：论文无法在 HM3D 上做与 MP3D 相同的跨层统计，因为 HM3D 缺少楼层标注；这限制了协议层面的可比性，跨层评测必须先解决方法层面的分层问题。
  • 基准的垂直盲区：2023 挑战把 episode 限制为单层，单层榜单的分数无法反映跨层能力，引用多楼层方法的改进时必须说明评测集是否含跨层 episode。
  • 记忆重用与单向化的代价：入口置障使智能体无法在同一层与楼梯之间反复取舍，重置会丢弃地图记忆；这两项启发式把灵活性换成了稳定性。
  • 计算依赖：真机实验把感知与语言推理放到云端 RTX 4090 工作站，车载只负责采集与执行；网络中断时的降级策略未在论文中给出。
  • 证据强度：真机为 Go1-Edu 上的展示性实验，论文展示了其中一次成功，定量结论仍需多样本统计（第 096 讲）。

实现思路与设计

本讲的设计产出是一套可实现的跨层子系统：状态机定义接口，参数表固定时间预算，评测协议声明分层口径。三者缺一，跨层结果无法复现。

1. 跨层状态机

设计决策：单向化优先于最短路径

入口置障会让路径变长，换来的是状态可判定：只要进入楼梯，去向只有一个出口，振荡在两个状态之间不可能发生。对 500 步预算的任务，稳定性比单次路径长度更重要。复现时若去掉单向化，应记录两层入口之间的往返次数，用实验证明该设计不是过度约束。

3. 跨层评测协议

协议分三层。第一层，分层标记：每条 episode 标注起点楼层与目标楼层，目标在别层的 episode 单独成组；楼层标注缺失的数据集（如 HM3D 官方版本）应用几何启发式或人工抽查补出可用分层，并在数据卡注明估计方法。第二层，触发子集：借鉴论文做法，把策略实际做出跨层决策的 episode 抽成子集，所有对比方法在同一子集上重评，避免全量平均稀释结论。第三层，反作弊量：地图重置机制会让「换了层」与「地图被清空」在日志上难以区分，评测器应独立记录真实楼层变化（以场景的楼层几何或位姿高度为证据），并报告换层成功率与无效换层次数。

与第 033 讲的差异点：033 用失败的静态分类学决定修什么，本讲把其中占 21% 的跨楼层失败转成可运行的子系统，并补齐其评测口径。评审跨层方法时检查四项：楼梯检测的召回与误报、触发时机与窗口约束、失败恢复是否可观测、评测集是否含跨层 episode 与独立楼层证据。

关键代码与解读

三段代码对应决策、状态机与地图标注三件事。接口按论文描述做教学化处理，权重与阈值作为超参显式传入，避免把未公布的数值写死。

片段 1：四因子决策分数与窗口约束

def n_mfnp(t, o_explored, o_total, area_delta, p_llm, w, t_max=500):
    """四因子分数：时间、物体覆盖、探索增量、语言建议。"""
    f_t = (t_max - t) / t_max                    # 时间项随进程递减
    obj_ratio = o_explored / max(o_total, 1)     # 已探索类别占比
    hold = 1.0 - area_delta                      # 新增面积越小，越接近探完
    return w[0] * f_t + w[1] * obj_ratio + w[2] * hold + w[3] * p_llm

def may_ascend(t, t_max=500, head=150, tail=200):
    """硬窗口：前 150 步与最后 200 步禁止上梯。"""
    return head <= t <= t_max - tail

def decide_floor_switch(obs, w, n_th):
    """决策入口：先查楼梯存在与窗口，再比阈值。"""
    if not obs.stair_detected or not may_ascend(obs.t):
        return False
    score = n_mfnp(obs.t, obs.o_explored, obs.o_total,
                   obs.area_delta, obs.p_llm, w)
    obs.log["n_mfnp"] = score              # 分数落盘，供失败分析复算
    return score > n_th

解读：（1）窗口判断先于分数计算，避免无效算力与日志噪声；（2）分数与分量全部落盘，复现者可以独立扫描权重而不必重跑仿真；（3）默认窗口参数与论文一致，改参数必须同步修改数据卡；（4）obs 封装现场信息，状态机与决策函数解耦，便于单元测试。

片段 2：跨层状态机

from enum import IntEnum

class StairState(IntEnum):
    EXPLORE, GO_STAIR, ON_STAIR, RESET = range(4)

def stair_step(state, obs, w, n_th, reset_limit=200):
    """单步状态迁移；所有计时以 episode 步数为准。"""
    if state == StairState.EXPLORE:
        return StairState.GO_STAIR if decide_floor_switch(obs, w, n_th) else state
    if state == StairState.GO_STAIR:
        if obs.at_stair_entrance:
            return StairState.ON_STAIR
        return StairState.RESET if obs.t - obs.t_enter > reset_limit else state
    if state == StairState.ON_STAIR:
        if obs.floor_changed:                       # 由独立楼层证据判定，不看地图
            return StairState.EXPLORE
        return StairState.RESET if obs.t - obs.t_enter > reset_limit else state
    if state == StairState.RESET:
        return StairState.EXPLORE if obs.map_rebuilt else state
    return state

解读：（1）状态只有四个，转移条件全部可由观测字段核验，避免隐式记忆；（2）换层成功以独立楼层证据（位姿高度或场景几何）判定，避免「地图被重置」被误认为「换层」；（3）计时统一用 episode 步数，与预算和窗口约束同一尺度；（4）重置状态等待地图重建完成，防止在空地图上立刻再次触发跨层。

片段 3：楼梯地图标注与入口置障

OBS_CH, STAIR_CH = 0, -1

def annotate_stair(grid, stair_cells, entry_cells, dilate=3):
    """写入楼梯通道；进入后膨胀入口并置障，形成单向出口。"""
    for cx, cy in stair_cells:
        grid[STAIR_CH, cy, cx] = 1.0               # 楼梯通道供上层策略查询
    for cx, cy in entry_cells:
        for dy in range(-dilate, dilate + 1):
            for dx in range(-dilate, dilate + 1):
                grid[OBS_CH, cy + dy, cx + dx] = 1.0   # 入口置障阻断回撤
    return grid

解读：（1）楼梯通道独立成层，跨层策略只依赖该通道判断 Estair；（2）入口膨胀半径要覆盖机器人半宽加定位抖动量，过小会漏堵、过大会堵死楼梯本身；（3）置障是不可逆操作，触发时刻必须写入日志，事后统计「入口置障后是否完成换层」；（4）真机移植时同一份标注逻辑可直接复用，栅格来源换成激光雷达地图。

常见误区

  • 楼梯漏检导致策略永不激活：症状是整条 episode 停在单层，日志里 Estair 始终为 0。根因是分割模型对楼梯的召回不足或楼梯从未进入视野。修复：多帧投票加专门检测头，在日志中记录楼梯通道的首次写入时刻。
  • 触发过晚：症状是换层后步数不够，重置与超时叠加。根因是只依赖单一因子或阈值过高。修复：以探索增量为主因子监控前沿增长，接近窗口末端时预留恢复余量，t 接近 300 时直接拒绝触发。
  • 入口不置障导致往复：症状是轨迹在两层入口之间振荡，地图上两层信息互相污染。根因是缺少单向化。修复：进入楼梯即膨胀入口并置障，出口单独设航点；用日志统计入口往返次数验证。
  • 换层后地图不重置：症状是新层目标概率被旧层残影拉偏，DTG 高居不下。根因是地图记忆跨层复用。修复：超时即重置并暂停跨层策略，记录重置前后探索效率。
  • 用单层榜解读多层方法：症状是把 MFNP 的成功率改进直接归因于多楼层策略。根因是评测集限制单层或缺少楼层分层。修复：报告触发子集与跨层 episode 占比，用独立楼层证据核验换层。

小结

  • 跨楼层是结构性缺口：PIRLNav 21% 的失败来自它，MP3D 中 57.3% 的场景目标类别跨层分布，而 2023 挑战把 episode 限制为单层。
  • MFNP 三要素：四因子决策分数 NMFNP = w1f(t) + w2·O 比值 + w3(1 − Et) + w4PLLM；[150, 300] 可用窗口；入口置障单向化与 200 步重置。
  • 结果：HM3D 上 58.3 / 0.267 / 3.568，相对 TriHelper 成功率 +1.8 个百分点，SPL +5.53%；触发子集 400 条上相对 TriHelper 成功率 +5.5 个百分点（+16.67%）；相对 VLFM 出现 SR 升、SPL 降的取舍。
  • 消融排序：探索增量因子最重要（去后成功率 −4.3 个百分点，占总损失 42.57%），语言建议在触发决策中权重最小（−1.2 个百分点）。
  • 楼梯几何：层高 2.7 m 的常见住宅约 15 级踏步、斜向里程约 4.99 m、坡度约 32.7°；跨层消耗以转向与对齐步数为主，距 125 m 前向预算的占比仅 3.99%。
