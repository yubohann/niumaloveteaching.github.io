第一篇 · 任务、仿真与评测地基

第 005 讲｜SoftSPL 与 DTG

上一讲把 SPL 定义为「成功才计分、路径越短分越高」：一条停在距目标 1.2 m（判据之外）的失败轨迹与一条原地打转的轨迹同样记零。本讲补上两个失败侧视角。软成功加权路径长度（SoftSPL）把二值成功换成距离进度，让接近目标的失败轨迹拿到部分分数；到目标距离（Distance To Goal, DTG）单独记录停止时刻的剩余距离。三者合起来，就把「找没找到」「差多远」「走得多绕」拆成可分别分析的量。

  • 主题：SoftSPL / DTG / 失败轨迹评分 / 榜单字段解读
  • 关键公式：SoftSPL = (1/N) Σi max(0, 1 − dT,i / d0,i) · d0,i / max(d0,i, pi)
  • 预计学时：60 分钟
  • 前置章节：第 004 讲（SPL 与 ObjectNav-SPL）

学习目标

  • 会算：对任意一条 episode 的 (d0, dT, p) 计算 SoftSPL 分量，并用闭环形式 (d0 − dT) / max(d0, p) 快速手验。
  • 会读源码：说清 habitat-lab v0.3.4 中 soft_spl 与 distance_to_goal 两个量的实现差异，包括软成功项不依赖 STOP、距离可选 POINT 与 VIEW_POINTS 两档。
  • 会解读榜单：从 2021 与 2022 ObjectNav 榜单的 SPL、SOFT_SPL、DISTANCE_TO_GOAL、SUCCESS 四列读出失败轨迹的接近程度，并解释为什么两个统计量的排名可以不一致。
  • 会诊断：把 SPL、SoftSPL、DTG 组合成失败归因流程，区分「没找到」「找到了不肯停」「停错位置还走得很绕」三类失败。
  • 能识别边界：起点距离趋零、轨迹走远后返回、episode 无 STOP 超时结束、可见视点口径混用四类情形的失效方式与防护措施。

背景与动机

第 004 讲的 SPL 与成功率共享一条二值边界：成功指示 Si 一经判定，失败轨迹的全部路径信息从得分中消失。这只对了一半。搜索类任务的失败是有层次的：在目标前 1.2 m 停下、在目标所在的房间外徘徊、随机走到副卧室发呆，三者对研究者的价值完全不同。SPL 把它们折叠成同一个零，观测不到策略是否正在接近目标。

Habitat 挑战的评测体系为此提供了两个失败侧字段。2021 与 2022 两届 ObjectNav 榜单都在 SPL 之外列出 SOFT_SPL 与 DISTANCE_TO_GOAL，四列依次为 SPL、SOFT_SPL、DISTANCE_TO_GOAL、SUCCESS。开源实现 habitat-lab 在导航任务模块中给出对应量化类：SoftSPL 把成功项替换成距离进度，DistanceToGoal 每步汇报当前位置到最近目标视点的测地距离。本讲以 habitat-lab v0.3.4 的实现与两届挑战页的榜单数值为准，实算数字全部由 Python 复算。

本讲解决三个问题：把 SoftSPL 写成可手算的两条等价公式；把 DTG 的口径、取值与榜单用法讲清；用一组十条 episode 的实算表与恒等式把 SoftSPL、SPL、DTG 三者的关系钉死。第 006 讲开始转向仿真器：Habitat-Sim 的架构与性能常识，解释这些指标每一条要在多快的仿真里产生。

核心原理

1. 软化动机：两条失败轨迹的分化

先看两条构造的失败轨迹，两条的起点到最近目标视点的初始测地距离都是 d0 = 10.0 m。轨迹 F1 停在距目标 1.2 m 处，路径 14.0 m；轨迹 F2 停在距目标 8.0 m 处，路径 12.0 m。两条都未通过 1.0 m 成功条件，SPL 同为 0。若只看距离进度 1 − dT/d0，F1 走完了 88%，F2 只走完 20%。把进度乘上路径效率，得到两条轨迹的 SoftSPL：F1 为 0.6286，F2 为 0.1667，相差 0.4619。

2. 定义：挑战实现口径与两条等价形式

设 episode 起始时刻到最近目标视点的测地距离为 d0，结束时刻的剩余距离为 dT，智能体累计平移路径长度为 p。habitat-lab v0.3.4 的 SoftSPL 类按以下顺序计算：每个仿真步更新软成功项与路径累计，末步的 _metric 即该 episode 的分数。

SoftSPLi = max(0, 1 − dT,i / d0,i) · d0,i / max(d0,i, pi) 进度项与效率项的乘积；max(0, ·) 处理 dT 超过 d0 的情形；除以 0 的保护在数据生成侧完成

把 d0 乘进分子可得到闭环形式，它与上式在 dT ≤ d0 时恒等，手算更快：

SoftSPLi = max(0, (d0,i − dT,i)) / max(d0,i, pi) 「净接近距离」除以「初始距离与实走路径的较大者」；本讲 10 条 episode 的两种算法逐条误差不超过 4.2 × 10−17
符号含义来源 / 单位
d0,ireset 时刻的 DistanceToGoal 值，到最近目标视点的测地距离米；由评测侧特权信息给出
dT,iepisode 结束时刻的 DistanceToGoal 值米；超时结束时取最后一步的值
pi累计路径长度，逐帧欧氏位移求和米；原地转向不改变位移
SoftSPLi单条软成功加权路径长度落在 [0, 1]

两个实现细节必须写进实验配置。其一，进度项不检查停止意图：源码中 SoftSPL 只依赖 DistanceToGoal，不依赖 Success，也不读取 is_stop_called。其二，d0 与 dT 取自同一距离量，量程与口径随 distance_to 配置切换，取值有 POINT（到目标参考点）与 VIEW_POINTS（到目标的预计算可停视点，见第 4 小节）两档。SoftSPL 的分子分母必须同档，混档会得到没有物理含义的比值。

从时序看，SoftSPL 的取值在 reset 与每个仿真步之后都会刷新。reset 时智能体仍在起点，dT 等于 d0，进度项为零，因此 episode 开始时分数为零，只有真正接近目标才会上升；随后每步覆盖，结束时保留最后一步的值。这个行为带来一个实用性质：把逐帧的 SoftSPL 与距离曲线并排画出，可以直接观察策略的接近过程，而且峰值时刻与结束时刻可能不一致（经过目标附近后又走远，最终分数低于峰值）。SPL 没有这条时间维度，二值判定不会先升后降。诊断具体轨迹时，两种读数各有用处：逐帧曲线用于定位行为失误，末尾值用于与其他 episode 聚合成榜。

3. 性质：与 SPL 的大小关系不定

先给出四条可直接核验的性质。第一，取值范围：进度项与效率项各自落在 [0, 1]，乘积也在 [0, 1]。第二，SoftSPL 不受 SPL ≤ SR 的约束：失败 episode 的贡献不再为零，聚合值可以超过 SR。本讲的实算表就是例子，SR 为 0.3000 而 SoftSPL 为 0.5989。第三，成功 episode 存在残余损耗：当 episode 判定成功时 dT 通常大于零，此时

SPLi − SoftSPLi = dT,i / max(d0,i, pi) 成功轨迹上 SoftSPL 低于 SPL，差距等于「停在距目标 dT」折算的路径；dT = 0 时两者相等

例：d0 = 10.0、dT = 0.5、p = 10.5 的成功轨迹，SPL = 0.9524，SoftSPL = 0.9048，损耗 0.0476。第四，聚合层面的恒等式把两类差异拆开：

SoftSPL − SPL = ( Σ失败 SoftSPLi − Σ成功 dT,i/max(d0,i, pi) ) / N 失败幕的部分得分与成功幕的残余损耗相减；哪一项占优由数据集与策略共同决定

这条恒等式解释了一个常见困惑：榜单上 SOFT_SPL 常高于 SPL，但这不属于普遍规律。失败的接近程度带来的增益超过成功残余损耗时，SoftSPL 才高于 SPL；一支成功率极高、停点都很贴目标的队伍，SoftSPL 可能略低于 SPL。第 5 小节的实算表会同时给出两种情形的数字。

4. DTG：另一个被忽略的字段

到目标距离（Distance To Goal, DTG）在 habitat-lab v0.3.4 中由 DistanceToGoal 类实现，每步用仿真器的测地距离查询更新当前位置到目标的距离。目标集合的取法由配置项 distance_to 决定：POINT 档取各目标参考点位置，VIEW_POINTS 档取各目标挂载的可停视点（view point）位置集合。源码中 VIEW_POINTS 档在 reset 时把所有 goal.view_points[*].agent_state.position 摊平成一张点表，之后每步对整张点表做测地距离查询，返回其中的最小值。结合 ObjectNav 数据集的加载逻辑（同一类别全部实例的视点都挂在 episode 的目标集合下），这一最小值就是「到最近实例的最近可停视点」的距离，与第 003 讲有效视点的定义、第 004 讲基线 li 的口径对齐。

DTG 与 SR 的关系是解耦的：SR 只回答最终是否通过成功判据，DTG 保留「差多少」的连续信息。2022 HM3D-Sem v0.1 榜单给出一组直观对照：ByteBOT 以 SPL 0.35 排第一，DTG 为 3.19 m；BadSeed 的成功率 0.65 略高于 ByteBOT 的 0.64，DTG 2.46 m 为全榜最低，但 SPL 0.33 排第二。成功率更高、失败停点更近的队伍，可能因成功轨迹绕行更多而输掉 SPL 排名，这正是三个统计量需要成对报告的原因。作为诊断量，DTG 还能让「差一点」和「差很远」的失败分开：同一 SR 的两支队伍，DTG 均值低的说明失败集中在小距离上。

第三，头部名次在两种排序下基本一致。两届榜单按 SPL 与按 SOFT_SPL 排序的前两名组合相同（2022 第三、四名互换），说明头部排序由「找到的能力」主导，软化指标的主要用途是失败分析与论文附录，不用于替换主排序。榜单的两列都只有两位小数，0.01 的间距既可能来自失败接近，也可能来自成功残余距离；引用间距时应先估计舍入区间，再决定是否值得解释。

7. 边界与失效

  • 起点距离趋零。d0 出现在进度项分母与效率项，趋零时比值失稳，等于零时源码路径会出现 0 除 0 或除零。防护：数据生成阶段保证起点不在任何目标的成功区内（第 003 讲的有效视点过滤已隐含该要求），评测代码对 d0 低于 2 倍成功半径的 episode 单列告警。
  • 轨迹走远后返回。dT 大于 d0 时进度项为负，max(0, ·) 把 SoftSPL 截到 0；但效率项里的 p 已经累计了绕行，两条保护同时生效。E7 是构造样例。
  • 无 STOP 超时结束。SoftSPL 与 DTG 照常计分，SPL 因 Success 为假记零。演示与论文引用时必须写明评测是否要求 STOP，避免把两类数字并排比较。
  • 口径混档。d0 用 VIEW_POINTS、dT 用 POINT 会得到跨越两种几何含义的比值；不同 Habitat 版本或不同 distance_to 配置之间的 SoftSPL 不可直接对比。防护：把 distance_to 写进配置审计清单，与 SPL 基线共用同一档。
  • 榜单舍入。SOFT_SPL 与 SPL 只有两位小数时，比值在 SPL 接近 0.005 处失去有效位数；BEyond-VRI-UFPR 一行只能给下界。引用榜单差值前先估计舍入区间。

8. 为什么这样设计：从「是否跨过阈值」到「走了多少路」

SoftSPL 的设计立场可以直接从公式读出：把二值成功 Si ∈ {0, 1} 换成连续的进度 1 − dT/d0，其余结构与 SPL 完全一致。这样改动的结果是每个失败 episode 都变成一条「部分成功的轨迹」，与强化学习里常用的奖励塑形（距离减少给正奖励）口径同源，训练日志与评测报告可以用同一套距离信号对照。代价是它无法区分「沿正确方向接近」与「在目标附近游荡后恰巧停近」：进度项只看终点与起点距离，看不到路径形状。要补上这一层，需要 DTG 时间序列或逐帧距离曲线，本讲不展开。

DTG 的设计立场是保留一个纯结果量：不乘任何效率因子，不做成功判定，直接在评测集上平均剩余距离。它的短板也随之而来：大场景的失败会把均值拉高，跨数据集比较时应按场景难度分层。两届榜单把 SOFT_SPL 与 DTG 与 SPL 并列，正是为了让读者自行选择「成功与效率联合」「失败接近度」「剩余距离」三个视角；任何单一数字都不足以支撑方法优劣的结论。

实现思路与设计

评测模块在 SPL 的两层结构上扩一列：记录层为每条 episode 增加 d0、dT、STOP 三个字段；计算层同时输出 SPLi、SoftSPLi、DTGi；聚合层给出 SR、SPL、SoftSPL、DTG 四个标量与区间。逐条返回值仍然必须保留，否则无法做分解恒等式核对。

计算顺序与接口

一个 episode 内的更新顺序固定为三步：读取当前 DistanceToGoal；用当前位置与上一步位置之差累加 p；计算软成功项并覆盖 _metric。顺序不能调换，否则 dT 与 p 会错开一步。reset 时必须记录 d0 与初始位置，两个量分别供进度项与路径累计使用。评测器对外的接口与第 004 讲保持一致：oracle_l 产基线，episode_returns 产逐条 SPL 与 SoftSPL，aggregate 与 bootstrap_ci 产标量与区间。

基线复用有一条硬规则：d0 与 SPL 的分母必须来自同一张距离场、同一档位。评测若使用预计算视点表，SPL、SoftSPL、DTG 三者共享该表；任何一者换用欧氏直线或目标中心，第 3 小节的恒等式立即失效。稳妥做法是在评测器启动时做一次跨指标一致性检查：对同一批 episode 分别计算两种聚合，断言「SoftSPL − SPL」与恒等式右端在数值容差内相等，任何口径漂移都会在正式跑分之前暴露。

SR、SPL、SoftSPL、DTG 各自回答不同问题，且都已被挑战页或参考实现定义。把它们加权成一个自定义分数会让结果无法与其他论文对齐；正确做法是保留原始列，把排名规则与附加指标使用条件写进实验报告（2021 与 2022 挑战页都声明了 SPL 差异不显著时可参考附加指标）。

SoftSPL 不是成功率的平滑版本

E8 表明无 STOP 的 episode 也能拿到 0.9357。若把 SoftSPL 当作「带置信度的成功率」使用，会把超时结束、路径中途恰好靠近目标等行为混入高分区。诊断流程应固定为：先看 SR 与 stopped 比例，再看 SPL 与条件效率，最后用 SoftSPL 与 DTG 细分失败。

关键代码与解读

三段代码对应三层：量的更新循环、十条 episode 复算与恒等式断言、榜单比值复算。语言为 Python 3，无第三方依赖。

片段 1：soft_spl 量的更新循环（镜像 habitat-lab v0.3.4 逻辑）

class SoftSPL:
    """进度项乘以效率项；每步覆盖 value，末步值即 episode 分数。"""

    def reset(self, d0, position):
        self.d0 = d0                      # reset 时的 DistanceToGoal，即 d_0
        self.path = 0.0                   # 累计平移距离 p
        self.prev = position              # 上一步位置，供增量累计使用

    def step(self, position, d_t):
        dx = position[0] - self.prev[0]
        dy = position[1] - self.prev[1]
        dz = position[2] - self.prev[2]
        self.path += (dx * dx + dy * dy + dz * dz) ** 0.5   # 逐帧欧氏位移
        self.prev = position
        progress = max(0.0, 1.0 - d_t / self.d0)  # 走远时为零，无需额外分支
        efficiency = self.d0 / max(self.d0, self.path)      # 与 SPL 同式
        self.value = progress * efficiency

解读：（1）类中没有任何字段记录 STOP，软成功项只看 dT 与 d0，与官方实现的依赖关系一致。（2）效率项与 SPL 的 max 夹取逐字相同，保证两指标共享同一路径累计；若两者分别维护路径变量，微小的更新顺序差异会让差值恒等式失效。（3）进度项用一次 max 处理 dT 超过 d0 的负值情形；d0 等于零仍会触发除零，防护放在数据生成侧，见设计一节的参数表。（4）更新发生在每个仿真步，末步覆盖值即 episode 分数，没有显式的结束事件。

片段 2：十条 episode 复算与恒等式断言

EPISODES = [
    # (id, d0, dT, path_p, stopped)
    ("E1", 10.0, 0.40, 11.0, True), ("E2", 8.0, 0.80, 8.0, True),
    ("E3", 12.0, 1.20, 13.0, True), ("E4", 15.0, 1.05, 20.0, True),
    ("E5", 9.0, 8.00, 12.0, True), ("E6", 20.0, 12.00, 18.0, True),
    ("E7", 6.0, 6.50, 7.0, True), ("E8", 14.0, 0.90, 14.0, False),
    ("E9", 11.0, 0.30, 15.0, True), ("E10", 7.0, 2.00, 9.0, True),
]

def is_success(d0, dT, stopped, success_distance=1.0):
    return stopped and dT < success_distance        # 严格小于，与第 003 讲一致

def summarize(rows):
    n = len(rows)
    sr = spl = soft = dtg = 0.0
    for _, d0, dT, p, stopped in rows:
        s = float(is_success(d0, dT, stopped))
        eff = d0 / max(d0, p)
        sr += s
        spl += s * eff
        soft += max(0.0, 1.0 - dT / d0) * eff
        dtg += dT
    return {"SR": sr / n, "SPL": spl / n, "SoftSPL": soft / n, "DTG": dtg / n}

result = summarize(EPISODES)
print(result)   # SR 0.3000, SPL 0.2642, SoftSPL 0.5989, DTG 3.3150

fail_credit = sum(max(0.0, 1.0 - dT / d0) * d0 / max(d0, p)
                  for _, d0, dT, p, s in EPISODES if not is_success(d0, dT, s))
succ_loss = sum(dT / max(d0, p)
                for _, d0, dT, p, s in EPISODES if is_success(d0, dT, s))
# 恒等式：SoftSPL - SPL = (失败部分得分 - 成功残余损耗) / N
assert abs((fail_credit - succ_loss) / len(EPISODES)
           - (result["SoftSPL"] - result["SPL"])) < 1e-9

解读：（1）复算脚本与评测器共用同一 is_success 与效率因子，保证表格与代码同源；把第 004 讲的 episode_returns 扩展一个 SoftSPL 累加即可合并。（2）恒等式断言把两个聚合量的差值锁死在失败贡献与成功损耗之差上，任何一处口径漂移都会在运行时暴露。（3）输出与理论一节的表逐行一致，可直接作为回归用例。

片段 3：榜单比值复算与零值保护

LEADERBOARD_2022 = [
    # (team, SR, SPL, SOFT_SPL, DTG)
    ("ByteBOT", 0.64, 0.35, 0.38, 3.19),
    ("BadSeed", 0.65, 0.33, 0.36, 2.46),
    ("Walle", 0.61, 0.30, 0.35, 2.72),
    ("Habitat-Web", 0.59, 0.30, 0.36, 2.89),
    ("ddx", 0.27, 0.13, 0.25, 4.95),
    ("TreasureHunt", 0.21, 0.11, 0.22, 5.78),
]
for team, sr, spl, soft, dtg in LEADERBOARD_2022:
    if spl > 1e-9:
        print(f"{team:<14s} SOFT/SPL={soft / spl:.4f} "
              f"增幅={100 * (soft / spl - 1):+.1f}% DTG={dtg:.2f} SR={sr:.2f}")
    else:
        print(f"{team:<14s} SPL 显示 0.00，比值无有效位数")

解读：（1）榜单数值只有两位小数，比值是近似量；spl > 1e-9 的保护用于显示为 0.00 的行，此时只输出下界，不做比值计算。（2）输出复现 2022 表的比值列：ByteBOT 1.0857（+8.6%）、TreasureHunt 2.0000（+100.0%）。（3）若要加区间，按 episode 自助重采样后重算 SOFT_SPL 与 SPL，再对齐榜单的舍入位数比较。

常见误区

  • 用 SoftSPL 替换 SPL 排序：症状是低成功率的方案在自定义榜单上升。根因是 SoftSPL 给失败部分分数，成功率越低、失败占比越大，软化增益越明显（2022 榜末的 SOFT/SPL 达到 2.00）。修复：主排序保持挑战口径 SPL，SoftSPL 与 DTG 作为附加列报告。
  • 把 SoftSPL 当作平滑成功率：症状是把超时未停的轨迹计入高分区。根因是软成功项不检查 STOP，E8 在无停止动作时仍得 0.9357。修复：报告中同时给出 stopped 比例与 SR；诊断脚本先按 stopped 分层再看 SoftSPL。
  • d0 与 dT 口径混档：症状是 SoftSPL 出现没有对应几何含义的数值，且与 SPL 的差值恒等式被破坏。根因是一端用 POINT、一端用 VIEW_POINTS，或跨版本配置。修复：统一 distance_to，把档位写入配置审计清单；用恒等式断言做运行时检查。
  • 忽视起点距离趋零：症状是出现 NaN 或异常的满分 episode。根因是 d0 趋零时进度项与效率项同时失稳。修复：数据生成侧保证 d0 不低于 2 倍成功半径，评测侧对低于阈值的 episode 单列告警。
  • 用 DTG 均值比较跨数据集方案：症状是同一方法在新数据集上 DTG 恶化，却解释为接近能力退化。根因是场景尺度不同，剩余距离的均值随场景变大自然升高。修复：按场景难度分层报告，或改用相对量 dT/d0 并注明口径。

小结

  • SoftSPL 把 SPL 的二值成功替换为距离进度：SoftSPLi = max(0, 1 − dT/d0) · d0/max(d0, p)，闭环形式 (d0 − dT) / max(d0, p) 等价，habitat-lab v0.3.4 的实现与本讲公式逐项对应。
  • 软成功项不依赖 STOP，也不依赖 Success；超时结束的接近轨迹可以拿到高分。SPL 依赖 STOP 与 1 m 判据，两者语义必须分开报告。
  • 十条 episode 实算：SR 0.3000、SPL 0.2642、SoftSPL 0.5989、DTG 均值 3.3150 m；恒等式失败贡献 3.5029 减去成功损耗 0.1564 等于差值 0.3347，逐项闭合。
  • 榜单读法：2021 前三队 SOFT/SPL 为 1.6923、3.0000、2.7500；2022 从榜首 1.0857 升到榜尾 2.0000。比值随 SPL 降低总体上升，它度量失败接近程度，不度量能力。
  • DTG 是纯结果量，与 SR 解耦：2022 BadSeed 的 SR 0.65 与 DTG 2.46 m 均为该榜最佳，SPL 0.33 仍低于 ByteBOT 的 0.35。四个量必须成对解读。
