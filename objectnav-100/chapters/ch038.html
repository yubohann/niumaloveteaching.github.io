第二篇 · 模块化：地图·探索·常识

第 038 讲｜2D 语义图 vs 3D 场景图

上一讲从 SoftSPL 与 DTG 视角重审模块化方案的评测。本讲转入模块化系统的记忆层：2D 语义图把语义压在 0.2 m 栅格上，3D 场景图把物体写成节点、关系写成边。本讲推导两种表示的更新与关联公式，用 Python 实算构建成本（内存、体素规模、离线模型调用量），读 MOPA（Raychaudhuri 等，2023）与 ConceptGraphs（Gu 等，2023）的证据，最后给出表示选择的决策树与混合接口。

  • 主题：场景表示 / 2D 语义图 / 3D 场景图 / 表示选择
  • 关键公式：φ(i, j) = φsem + φgeo；fo ← (n fo + fnew) / (n + 1)
  • 预计学时：70 分钟
  • 前置章节：第 037 讲 模块化评测（SoftSPL 视角）

学习目标

  • 能写出两种表示的数学形式：栅格张量的更新规则与对象图的节点、边、关联、融合定义，并说明各自的适用条件。
  • 会算构建与维护成本：给定场景面积与通道数算 2D 图内存，给定节点数与点云规模算 3D 图内存，并估算离线视觉语言模型的调用量。
  • 会读两类评测证据：MOPA 的 ObjectNav 验证集成绩与失败分析，ConceptGraphs 的节点/边标注精度、开放词汇检索 R@k 与分割指标。
  • 能按目标词汇、查询类型、算力与时延四个约束选择表示，写出决策表，并设计 3D 语义加 2D 几何的混合接口。
  • 能识别两种表示的主要失效模式，覆盖关系查询错位、标签溅射、垂直叠加、节点缺失与重复、描述错误、成本失控与跨协议比较。

背景与动机

第二篇的方法共享同一个问题：智能体把沿途看到的东西记在哪里。第 023 至 037 讲介绍的方法大多采用 2D 语义图做记忆：SemExp 用 5 cm 栅格加 15 个语义通道，MOPA 用 0.2 m 栅格存「每格最新标签」，L3MVN 在语义图上提取前沿并打分，MFNP 在二维张量里加一条楼梯通道。记忆载体决定了模块间接口：探索模块读地图取目标，规划模块读地图解路径，感知模块往地图写标签。

第四篇的开放词汇方法正在换用另一种记忆：3D 场景图。ConceptGraphs 把每个物体建成带点云与语义特征的节点，把「在…上、在…里」这类关系建成边，用语言模型做任务规划。两种表示面对同一场景，保留的信息与付出的代价完全不同：2D 图几何紧凑、查询快，但丢失高度与支撑关系；3D 图表达丰富、支持语言查询，但构建需要位姿、实例分割、大量视觉语言模型调用。

表示选择先于算法选择：同一探索策略接不同记忆，性能与失效模式都会改变。本讲回答四件事：两种表示如何构建，各自成本多少，证据读出什么，什么条件下选哪一个。数字纪律先交代：MOPA 的数字取自 arXiv:2304.03696v3（2024 年 1 月修订），ConceptGraphs 的数字取自 arXiv:2309.16650v1（2023 年 9 月），两篇协议不同，本讲只做同表内比较，不做跨表排名。

核心原理

1. 2D 语义图：形式、更新与查询

2D 语义图把三维场景投影到水平面，用栅格单元承载语义。设单元边长 s，场景映射为 H × W 的网格，记 Lt ∈ ℤH×W 为第 t 帧结束时的标签图，Lt[i, j] 取类别编号或 0（无语义）。MOPA 的口径是 s = 0.2 m，每个单元存最近一次预测的语义标签，且「见过的物体保持可见」，即空观察不清除已有标签（Raychaudhuri 等，2023）。工程实现常在标签图旁并列维护障碍、已探索、智能体当前位置与历史轨迹四条辅助通道，SemExp 式的实现还会把每条语义通道存成概率或距离场。

更新由检测结果驱动。对第 t 帧的第 n 个检测，记其类别 l、置信度 c 与像素框，先做置信度门控，再按深度反投影：

cn ≥ θ 时：Lt[i, j] ← l，其中 (i, j) = floor((x − x0) / s, (y − y0) / s) (x, y) 为检测框内像素按深度 d(u, v) 反投影到世界系的坐标；θ = 0.95 为 MOPA 实现的置信度门限

深度不可用或超量程的像素被丢弃，因此地图只更新到相机实际看到的表面。查询接口有三类：目标类别的单元集合 Sc = {(i, j) : Lt[i, j] = c}；前沿集合，取已探索区域的边界单元；可通行区域，取标签为空且深度确认无碰撞的单元。规划模块在可通行通道上解测地路径。MOPA 的规划模块把每个标签簇的质心作为目标点，论文报告该做法优于从簇中随机取格（Raychaudhuri 等，2023）。

适用条件需要写清：2D 语义图假定场景可以用一个高度层描述；类别集合由检测器决定；物体标签一旦写入不会擦除，适合静态场景；多楼层需要额外机制（第 034 讲的楼梯通道）或按高度分图。

2. 3D 场景图：形式、关联与融合

3D 场景图把场景写成对象与关系。ConceptGraphs 的定义为 Mt = ⟨Ot, Et⟩，其中 Ot = {oj} 为节点集合，每个节点 oj = (po, fo) 包含三维点云 po 与单位语义特征 fo；Et = {ek} 为边集合，每条边记录一对对象与关系标签（Gu 等，2023）。构建流程逐帧进行：用类别无关的分割模型在 RGB 图上取掩码，对每个掩码提取视觉特征，按深度投影到三维，去噪后得到候选对象；再与地图中已有对象做关联与融合；回合结束后批量生成节点描述与边关系。

关联分数是可推导的核心。几何项取邻域点占比，语义项取余弦相似度映射：

φgeo(i, j) = nnratio(pi, po,j)，  φsem(i, j) = fiT fo,j / 2 + 1/2，  φ(i, j) = φsem(i, j) + φgeo(i, j) f 为单位向量，内积落在 [−1, 1]，除以 2 加 1/2 映射到 [0, 1]；nnratio 为点云 pi 中在 po,j 内有 2.5 cm 内最近邻点的比例

两项都在 [0, 1]，总和 φ ∈ [0, 2]，因此关联阈值 δsim = 1.1 允许「几何证据弱、语义证据强」或相反情形通过。匹配采用贪心策略：每个新检测与所有几何有交叠的已有对象比较，取 φ 最大者；若最大 φ 低于 δsim，实例化新节点。融合分两路：特征按观测次数加权平均，点云取并集后降采样：

fo ← (no fo + fnew) / (no + 1)，  po ← downsample(po ∪ pnew) no 为已关联观测次数；加权平均让特征随观测增多而稳定，代价是物体移动后更新滞后

节点描述与边关系由大模型离线生成。对每个节点挑选贡献点数最多的 10 个视角，送给视觉语言模型生成初始描述，再由语言模型汇总为最终描述或判为无效检测；边关系先按三维包围盒交并比对构图，取最小生成树剪枝，再对每条树边让语言模型输出「a on b」「b in a」等关系标签（Gu 等，2023）。任务规划时把节点序列化为含编号、包围盒、标签与描述的文本，交给语言模型选出与查询最相关的对象。

3. 表达能力对照

两种表示的区别在保留信息的侧重点不同。逐维度对照如下。

维度2D 语义图3D 场景图
空间粒度水平 0.2 m（MOPA）；高度压平点云与节点保留高度（体素 2.5 cm）
词汇范围检测器类目表，闭集或固定开放集自由文本描述，开放词汇
对象身份连通簇，无跨帧稳定标识节点编号，跨帧关联与融合
关系能力无显式关系；支撑与包含压进同一平面边保存 on / in 等空间关系
查询接口类别单元、前沿、可通行区域语言查询，支持可供性与否定

对照的结论可以压缩成两句：几何与规划选 2D 图，语义与关系选 3D 图。ConceptGraphs 自身在真机导航时也维持一张由三维点云降投影得到的 2D 代价地图，交给 Jackal 的导航栈（Gu 等，2023），这是混合架构的直接证据：语义层与几何层分工承担职责。

4. 构建成本实算

先算 2D 图内存。HM3D 多数场景可用面积小于 100 m²（MOPA 自述）。取 s = 0.2 m，单元数 = 100 / 0.2² = 2,500。若只存一个 uint16 标签，占 5 KB；若按六类目标加障碍、已探索、位置、轨迹四通道的 float32 张量计，10 × 2,500 × 4 B = 97.66 KiB。场景扩到 400 m²（约四个大户型），单元数为 10,000，张量 390.62 KiB。数量级很小，说明 2D 图的瓶颈不在存储，而在每帧的检测与投影计算。

再算 3D 图。稠密逐点表示给每个点存一个 512 维 CLIP 特征：100 万个点 × 512 × 4 B = 2.048 GB。对象级表示按 Replica 单场景平均 45 个有效节点、每节点保留 5,000 个降采样点估算：点云 45 × 5,000 × 3 × 4 B = 2.70 MB，特征 45 × 512 × 4 B = 92.16 KB，合计 2.792 MB。两者相差 733.5 倍，这正是 ConceptGraphs 自述「逐点特征在大场景不可扩展」的算术依据。体素粒度同样可以量化：2.5 cm 体素每平方米 1,600 个，0.2 m 单元每平方米 25 个，前者是后者的 64 倍。

离线模型的调用量是本讲最容易被低估的部分。仍按单场景 45 个节点算：节点描述需要 45 × 10 = 450 次视觉语言模型调用，再加 45 次语言模型汇总；边关系按最小生成树计，边数为 45 − 1 = 44，即 44 次语言模型调用。合计 539 次深度模型调用，其中语言模型调用 89 次。对比 MOPA 的在线流程：每帧一次检测加一次投影，没有离线批量阶段。两笔账对应两种工程形态：2D 图适合逐帧在线的单机系统，3D 图适合可以在回合外调用大模型、且对语义深度有要求的系统。

成本结论

2D 图的成本以 KB 计，瓶颈在检测吞吐；3D 图的存储以 MB 计，瓶颈在离线标注调用量与位姿来源。选择表示时先问三个问题：位姿是否可靠、能否承担每场景数百次大模型调用、查询是否需要关系与开放词汇。三问中有两个否定，2D 图是合理起点。

5. 评测证据怎么读

MOPA 在 2022 年 ObjectNav 挑战验证集（HM3D 语义场景、6 类目标、2,000 条 episode）上给出同一套 2D 图配不同检测来源的对照：真值语义把成绩推到 SR 64.0 / SPL 32.0，换成零样本检测器 Detic 后降到 30.0 / 14.0（Raychaudhuri 等，2023）。两行的探索、建图、导航模块完全相同，34 个百分点的成功率差全部来自检测质量。这条对照回答了一个常见疑问：2D 图的表达能力上限在哪里。在固定类别集合内，图的表达能力足够支撑导航，成绩先被感知瓶颈压住；第 029 讲已用噪声公式解释误差如何经投影进入地图。

MOPA 的失败分析还暴露表示与评测协议的耦合：官方成功判据要求在距物体包围盒 1 m 处采样的一组视点附近停下，采样稀疏时，智能体停在 1 m 内且目标在视野中仍可能被判失败。作者据此建议改进评测协议（Raychaudhuri 等，2023）。阅读 2D 图方法的成绩时，必须同时检查成功判据的操作化方式。

ConceptGraphs 的证据来自另一类任务：Replica 七个场景的图构建精度、开放词汇检索与语义分割。节点标签精度七场景均值为 0.71，即约 29% 的节点描述有误；边关系精度均值为 0.89（论文表格标 0.88）；单场景平均有 3 个重复节点。检索方面，语言模型规划在 Replica 的描述性查询上 R@1 为 0.61，与 CLIP 的 0.59 接近；可供性查询 0.57 对 0.43；否定查询 0.80 对 0.26，是差距最大的类别（Gu 等，2023）。图的价值集中在 CLIP 单向量检索失效的复杂查询上：可供性与否定。分割指标上，ConceptGraphs 的 mAcc 40.63、F-mIoU 35.95，对 ConceptFusion 的 24.16 / 31.31 分别提升 68.17% 与 14.82%；对分割更强的 ConceptFusion+SAM，mAcc 高 9.10 个百分点，F-mIoU 低 2.75 个百分点，互有胜负。读法要注意：对象级表示提升的是语义指标，不保证几何指标全面领先。

6. 数值算例（Python 实算）

算例一，标签溅射与质心平滑。MOPA 指出语义图存在标签溅射，并把簇质心选作目标点。用统计口径量化：若单帧投影误差近似零均值、标准差 σ = 0.2 m，一簇有 n 次观测时，质心误差约为 σ / √n。n = 10 时 0.0632 m，n = 50 时 0.0283 m，n = 200 时 0.0141 m。质心把随机取格的典型误差从 0.2 m 压到 0.028 m 量级，且观测越多越稳。实现时应把每簇的观测计数一并记录，计数少的簇不宜作为长期目标。

算例二，重复节点占比。单场景平均 45 个有效节点与 3 个重复节点，重复占比 = 3 / 48 = 6.25%。重复节点会让语言查询命中同一个物体两次，规划器可能选择坐标略有偏差的那个实例；对需要精确接近的导航任务，偏差直接体现为最后一公里的失败（第 033 讲的失败类别之一）。

算例三，词汇与查询的匹配。Replica 检索中，从 CLIP 换成语言模型后，否定查询 R@1 由 0.26 升到 0.80，比值 3.08 倍。同时节点标注错误率为 29.4%（1 − 0.7057），意味着复杂查询的上界被标注质量压住：即使语言模型推理完全正确，描述错误的节点仍无法被正确检索。提升检索的两个方向同样重要：换更强的语言模型，以及提升节点描述质量。

7. 失效模式与选择决策

把两种表示的失效模式逐一列出，再给出选择规则。

失效模式所属表示症状根因
关系查询错位2D 图「桌上的杯子」返回桌上或桌下同类物体高度与支撑关系被压平
标签溅射2D 图目标点落在物体边缘，路径反复绕行多帧投影散成多格簇
垂直叠加2D 图不同楼层证据互相污染投影到同一平面
细长物体缺失3D 图数据线、衣架类目标查不到分割掩码小，关联被并或漏
重复节点3D 图同一物体出现两个节点，规划摇摆关联阈值与视角变化
节点描述错误3D 图语言查询选错对象视觉语言模型误标（实测约 29%）
成本失控3D 图单场景数百次大模型调用，延迟与费用高离线批量流程放入在线循环

选择规则按四问展开。问词汇：目标集合固定且检测器覆盖，2D 图足够；目标为长尾或开放词汇，需要 3D 图或 2D 图加文本特征检索。问查询：查询只涉及位置与区域，2D 图；涉及关系、容器、可供性、否定，3D 图。问算力与时延：单机在线、每步更新，2D 图；可离线批处理、能调用大模型，3D 图。问几何：需要测地规划与安全避障，必须有 2D 或三维几何地图；3D 图单独使用不提供可通行区域。前两问指向 3D 图、后两问指向 2D 图时选混合：3D 图做语义与查询，2D 地图做规划。第四篇第 071 讲会从开放词汇角度重访 ConceptGraphs，验证这条分工线。

实现思路与设计

本讲的设计产出是三个可落地的部件：统一的数据结构、混合接口、参数口径表。

设计决策：对齐键是混合架构的关键

3D 图知道「这是杯子」，2D 图知道「从哪里能走过去」。两者若不共享标识，规划器拿到图查询结果后无法定位到栅格。做法是在对象融合时把节点编号写回它覆盖的标签簇，维护双向映射；对象移动或节点合并时同步刷新。没有这层映射，混合系统只能退化成两个独立模块各答一半问题。

3. 混合架构与数据流

推荐的混合流水线分四步。第一步，感知同时喂两个下游：类别级检测写标签图，类别无关分割与特征写对象集。第二步，对象融合后刷新对齐键，标签簇继承节点编号。第三步，查询分流：位置类查询直接查标签图；关系与开放词汇查询走对象集与语言模型。第四步，规划统一落到几何图上：无论长期目标来自哪条路径，最终都转换为栅格单元上的测地点，交给局部规划器或 PointNav 策略。与第 037 讲的差异点：037 检查评测口径，本讲检查记忆接口；两者共同决定模块化系统能否被复现。

关键代码与解读

三段代码分别对应 2D 更新与质心、3D 关联与融合、混合查询分流。接口按两篇论文的描述做教学化处理，参数默认值显式传入。

片段 1：2D 标签图更新与簇质心

import numpy as np

def project_update(label, votes, det, depth, pose, s=0.2, theta=0.95):
    """把检测投影进标签图；置信度过门限才写，已见标签保留。"""
    if det["score"] < theta:                          # 0.95 为 MOPA 实现门限
        return label, votes
    cells = backproject_footprint(det["box"], depth, pose)   # 像素到世界坐标
    for x, y in cells:                                # 逐格写入类别编号
        gx, gy = int(x / s), int(y / s)
        label[gy, gx] = det["category"]               # 空观察不清除已有标签
        votes[gy, gx] += 1                            # 每帧一次投票，供质心可信度过滤
    return label, votes

def goal_from_label(label, votes, category, min_votes=10):
    """取最大连通簇的质心；观测不足的簇不参与长期目标。"""
    mask = (label == category) & (votes >= min_votes)
    clusters = connected_components(mask)
    if not clusters:
        return None
    best = max(clusters, key=len)                     # 观测充分的连通簇
    ys, xs = np.nonzero(best)
    return xs.mean() * 0.2, ys.mean() * 0.2           # 质心抵消标签溅射

解读：（1）门限判断放在投影之前，避免低置信检测白算反投影；（2）空观察不擦除标签，对应「见过保持可见」口径，适合静态场景；（3）质心取代随机取格，把单帧投影噪声按 1/√n 压低；（4）min_votes 过滤一次性观测，防止偶发误检成为长期目标。

片段 2：对象关联与特征融合

def associate(pts, feat, objects, delta_nn=0.025, delta_sim=1.1):
    """φ = φ_sem + φ_geo 的贪心匹配；低于阈值时新建节点。"""
    best, best_phi = None, 0.0
    for obj in objects:
        if not overlap(pts, obj["pts"]):
            continue                                  # 只在几何交叠候选中比较
        phi_geo = nn_ratio(pts, obj["pts"], delta_nn) # 邻域点占比，[0, 1]
        phi_sem = float(feat @ obj["feat"]) / 2.0 + 0.5   # 余弦映射到 [0, 1]
        if phi_sem + phi_geo > best_phi:
            best, best_phi = obj, phi_sem + phi_geo
    if best is None or best_phi < delta_sim:
        return new_object(pts, feat)                  # 证据不足，实例化新节点
    n = best["n"]
    best["feat"] = (n * best["feat"] + feat) / (n + 1)   # 按观测次数加权
    best["n"] = n + 1
    best["pts"] = downsample(best["pts"] + pts)
    return best

解读：（1）跳过几何不相交的对象，把比较次数从全部节点压到邻域候选；（2）两项等权求和，δsim = 1.1 表示允许单一证据为主；（3）加权平均取代直接覆盖，特征随观测稳定；（4）节点编号 best 保持不变，这是对齐键能被下游引用的前提。

片段 3：混合查询分流

def resolve_and_plan(sg, grid, query, start):
    """关系查询交给场景图，路径规划落到二维几何图。"""
    node = llm_pick(sg, query)                        # 语言模型返回最相关节点
    if node is None:
        return None                                   # 图上无相关物体，转探索模块
    key = node["id"]
    cluster = cluster_of_key(grid, key)               # 用对齐键找回标签簇
    gx, gy = grid_centroid(cluster)
    free = nearest_free_cell(grid, gx, gy)            # 吸附到可通行单元
    return plan_geodesic(grid, start, free)           # 栅格测地路径

解读：（1）查询分流避免让 2D 图回答它无法回答的问题；（2）对齐键把语义结果翻译成几何目标，是混合系统的枢纽；（3）最近可通行单元防止目标点落在障碍或未探索区；（4）规划接口统一，局部策略可以换成 PointNav 或 FMM，不影响上游语义层。

常见坑

  • 在二维栅格上查询三维关系：症状是「桌上的杯子」「柜子里的瓶子」返回空结果或错误实例。根因是支撑与包含关系在俯视图里被压成同格或邻格。修复：关系查询走场景图节点与边，二维图只承担几何规划，两类查询在接口层分流。
  • 把标签溅射当对象位置：症状是长期目标点漂到物体边缘或墙外，路径反复绕行。根因是多帧投影形成多格簇，取格时把投影噪声当成位置。修复：取最大连通簇质心并对簇设观测计数下限；σ = 0.2 m、n = 50 时质心误差约 0.028 m。
  • 垂直方向不分离：症状是上层证据污染下层地图，跨层目标概率被拉偏。根因是三维证据投影到同一平面。修复：加入楼梯通道并分层（第 034 讲机制），或按位姿高度维护分图。
  • 把离线大模型流程放进逐帧循环：症状是单步时延上升、评测超时、调用费用失控。根因是 3D 图的描述与建边本属回合外批处理，被误当作在线更新。修复：在线只做分割、关联、融合，描述与关系放到回合外；查询结果做缓存。
  • 跨表示直接比成绩，或只看几何指标验收：症状是用检索 R@1 与 ObjectNav SR 并排得出表示优劣，或场景图上线后语言查询频繁失败而指标正常。根因是评测协议不同、节点标注误差未纳入验收。修复：对齐口径卡后再比较；对节点与边做抽样人工核验，把描述错误率与重复率写进验收报告。

  1. 计算 2D 语义图内存：100 m² 与 400 m² 场景、0.2 m 单元、六类语义加四条辅助通道的 float32 张量各占多少；再与单 uint16 标签图对比，说明为什么存储不是 2D 图的瓶颈。★

    100 m² 对应 2,500 单元，10 通道 float32 为 97.66 KiB；400 m² 为 390.62 KiB；uint16 标签图 100 m² 仅 5 KB。瓶颈在每帧检测与投影的计算量。
  2. 读 ConceptGraphs 检索表：Replica 上描述性、可供性、否定三类查询的 CLIP 与语言模型 R@1 各是多少；计算否定类别的比值提升，并结合节点精度 0.71 讨论语言模型检索的上界。★
    提示

  3. 推导关联分数的取值范围与 δsim = 1.1 的含义；设计一个最小实验，观察几何项权重变化对重复节点数与漏关联数的影响，写出自变量、指标与预期趋势。★★

    控制变量含分割模型、深度与位姿来源、目标词表、导航策略与预算；指标加节点/边精度与成本；避免归因错位的办法是加一行「同检测源」的消融：两种表示共用同一分割与特征提取，只换组织方式。

小结

  • 2D 语义图以 0.2 m 栅格存最新标签，更新常数代价，支持前沿与测地规划；MOPA 用簇质心抑制标签溅射，簇质心误差按 σ/√n 下降。
  • 3D 场景图以节点存点云与特征、以边存关系；关联分数 φ = φsem + φgeo ∈ [0, 2]，阈值 1.1 贪心匹配，特征按观测次数加权融合。
  • 成本实算：100 m² 的 2D 图约 97.66 KiB；对象级 3D 图约 2.79 MB，比逐点特征省 733.5 倍；单场景约 539 次离线模型调用，其中语言模型 89 次。
  • 证据读法：MOPA 中检测来源造成 34 个百分点的 SR 差；ConceptGraphs 节点精度约 0.71、边精度约 0.89，图的价值集中在可供性与否定查询。
  • 选择规则：几何与规划用 2D 图，关系与开放词汇用 3D 图，语义层与几何层用对齐键连接；真机系统普遍采用混合架构。
