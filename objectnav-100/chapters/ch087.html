第五篇 · 真机、Sim2Real 与系统集成

第 087 讲｜Stretch 与连续动作

2023 年 Habitat 挑战把导航智能体从 LoCoBot 尺度换成 Hello Robot Stretch 配置，并把动作空间从离散改为连续（Habitat 挑战 2023 挑战页）。本讲把这次换代的接口细节全部落表：仿真智能体为半径 0.17 m、高 1.41 m 的圆柱，相机位于 1.31 m，RGB 与深度分辨率 480×640、水平视场 42 度，深度有效区间 0.5 至 5.0 m，导航网格单元高 0.05 m、最大攀爬 0.1 m，墙边滑动被关闭；动作空间为速度控制，含归一化的线速度、角速度、相机俯仰速度与独立停止通道（habitat-challenge 仓库，navigation-challenge-2023 分支配置；arXiv:2306.11565 v2 附录给出真机侧本体事实）。本讲回答三个问题：连续动作的归一化语义是什么、这套配置为什么服务 Sim2Real、量程未公布时如何做敏感性分析。

  • 主题：Stretch 本体 / 连续动作空间 / 速度控制 / 传感器几何 / Sim2Real 接口
  • 关键公式：v = vmin + (u+1)(vmax−vmin)/2，u ∈ [−1,1]；w(d) = 2d·tan(hfov/2)
  • 预计学时：80 分钟
  • 前置章节：第 086 讲（L3MVN 真机）

学习目标

  • 理解：复述 2023 挑战本体的全部接口参数与连续动作的四通道语义，说明独立停止通道与离散动作中 STOP 的差别。
  • 会推导：写出归一化动作到物理量的仿射映射，并解释固定量程为什么等价于固定动作尺度，从而简化 Sim2Real 标定。
  • 会算：由相机高度、水平视场与深度区间计算地面覆盖宽度、垂直视场与像素角分辨率，并与 2022 本体参数对照。
  • 会设计：为速度控制的本体整理标定清单，包括速度上限、控制频率、停止阈值、安全半径与墙边余量，并给出验收判据。
  • 会判断：识别把归一化值当物理速度、忽略墙钟时限、混用控制器接口、忽略半径与滑动设置四类错误。

背景与动机

086 讲的真机平台是 Jackal，仿真侧仍然按学术惯例使用离散动作与无噪声位姿对齐。2023 年挑战改变了这套假设：任务数据集升级到 HM3D-Semantics v0.2（216 个场景，145/36/35 划分，6 类目标），本体换成 Hello Robot Stretch，动作空间改为连续速度控制，并保证所有 episode 都可在不跨楼层的前提下完成（Habitat 挑战 2023 挑战页）。这几项改动服务同一个目的，把仿真里的控制接口推到真机可直接复用的形态。

为什么动作空间要写进课程主线、不留在工程附录里。连续动作改变三件事：策略输出的含义从「下一格」变成「速度指令」，评估从「步数预算」部分转为「挂钟预算」，低层控制与安全约束从策略中剥离到控制器。三件事都会改变复现方法，也都会改变方法对比的公平性。第 019 讲曾指出 2023 届榜单与往年不可直接比较，本讲给出不可比较的具体来源。下一讲转入 HomeRobot OVMM，把这套本体放进抓取与放置的完整任务。

2. 连续动作空间的形式化

2023 挑战的动作空间配置名为 velocitycontrol，策略可提交四个通道：线速度、角速度、相机俯仰速度与停止。前三个通道接受 [−1, 1] 的归一化值，按 VelocityControlActionConfig 中定义的量程缩放；停止通道接受 [−1, 1]，取值大于 0 即终止 episode（habitat-challenge 仓库 README，navigation-challenge-2023）。归一化到物理量的映射是仿射变换，通用形式为：

v = vmin + (u + 1)(vmax − vmin) / 2，u ∈ [−1, 1]

若量程关于零对称（角速度与俯仰速度通常如此），映射退化为 v = u·vmax。这个形式的关键性质是尺度不变性：策略只需学习「以多快的比例朝哪个方向运动」，物理速度上限由环境配置提供，换到速度不同的真机时，只要低层控制器接受同一种归一化指令，策略权重无需改动。挑战仓库同时提供两种抽象控制器，供不直接输出速度的策略使用：航点控制器接受平面相对航点与转动量、最大执行时长与俯仰增量，代策略计算速度指令；离散航点控制器把旧版离散动作（前进 0.25 m、左转 30 度、右转 30 度、抬低头 30 度）翻译成速度指令，方便复用旧策略。

3. 相机几何与感知量表

水平视场 42 度决定了地面覆盖宽度。对深度 d，地面上的水平覆盖宽度为：

w(d) = 2d·tan(hfov/2) = 2d·tan(21°)

实算四档距离：1 m 处 0.768 m，1.5 m 处 1.152 m，3 m 处 2.303 m，5 m 处 3.839 m。传感器纵向像素 640、横向 480，在像素为正方形的前提下，垂直视场为 2·arctan(tan21°×640/480) = 54.208 度；水平方向每像素对应 42/480 = 0.0875 度，即 1.527×10−3 弧度。

这组数字有两个直接用途。第一，判断目标可见性：常见家居目标（椅子、马桶、沙发）的横向尺寸在 0.4 至 1 m 量级，3 m 距离下覆盖宽度 2.303 m，视野内可同时容纳多个候选；5 m 距离下单像素 7.64 mm，远距离小目标的像素占比下降，与第 077 讲的检测瓶颈呼应。第二，规划安全余量：机身直径 0.34 m，1.5 m 处视野宽度为其 3.39 倍，相机能在单帧内同时看到机身宽度与两侧余量，窄通道中的贴边程度可以被观测覆盖，但碰撞判定仍以半径 0.17 m 的圆柱为准，观测余量不能替代碰撞几何。

4. 时间预算：墙钟计时口径

连续动作把评估的时间口径改写。挑战配置显式设置单幕 max_episode_seconds 为 500，锁定版本的 Environment 实现（habitat-lab 的 Env 类）把该上限与挂钟时间累积值比较，每步检查一次；步数上限继承基础配置，两者同时生效时先到者结束。挑战评测在 48 小时内完成 1000 幕，折合平均每幕 172.8 秒，低于 500 秒的单幕上限。推论是：单幕上限不容易触顶，聚合预算会成为大多数策略的实际上限；感知或语言模块越慢，单位时间可完成的幕数越少，评测完成度直接受影响。

5. Sim2Real 的意义与边界

连续动作对 Sim2Real 的价值可以归纳为四条。第一，动作语义与机体解耦：策略输出比例指令，速度上限由平台侧参数决定，换本体不必重训策略。第二，低层控制与安全从学习问题中剥离：避障、速度平滑、急停由控制器与安全层负责，高层专注语义与探索，这与模块化地图方案的分工一致。第三，停止被拆成独立通道：离散动作中 STOP 是六选一，连续空间中它是独立信号，停止行为可以在不干扰动作分布的前提下单独校准。第四，滑动被关闭：贴墙时不再沿墙滑行，碰撞成为真实的失败，导航网格的几何误差不再被滑动掩盖，这对真机碰撞代价的建模更诚实。

边界同样要写清。仿真仍然把速度指令按固定时长积分并做导航网格吸附，未建模轮子打滑、地面摩擦与惯性；圆柱碰撞体不包含机械臂与传感器的外形，臂在真机上是侧向伸出，仿真碰撞判定按圆柱近似；关闭滑动也意味着仿真的窄缝通过性可能低于真机，真机控制器在小误差下可以擦边微调，两侧效应方向相反，净效应需要通过真机重复实验确认。连续控制还让强化学习更难：挑战仓库的 DD-PPO 基线把动作分布类型设为 gaussian，环境数 4、更新次数 270,000，这一训练成本远高于离散四动作时代的对应配置（navigation-challenge-2023 分支配置）。

关键代码与解读

三段代码对应归一化映射、航点控制与停止通道，全部按挑战仓库文档的动作语义做教学化实现，量程以参数注入，不写死数值。

片段 1：归一化动作到物理量的仿射映射

import numpy as np

def denormalize(u, v_min, v_max, deadzone=0.02):
    """归一化指令映射为物理量；死区抑制零点附近的抖动。"""
    u = float(np.clip(u, -1.0, 1.0))        # 契约上限：超出即裁剪
    if abs(u) < deadzone:
        return 0.0                          # 零点死区，避免电机持续微动
    return v_min + (u + 1.0) * (v_max - v_min) / 2.0

def split_action(action, limits):
    """limits = {'lin': (l0,l1), 'ang': (a0,a1), 'pitch': (p0,p1)}。"""
    lin = denormalize(action["linear_velocity"], *limits["lin"])
    ang = denormalize(action["angular_velocity"], *limits["ang"])
    pit = denormalize(action["camera_pitch_velocity"], *limits["pitch"])
    stop = action["velocity_stop"] > 0.0    # 独立通道，正数结束 episode
    return (lin, ang, pit), stop

解读：（1）裁剪与死区都放在映射之前，保证输出物理量始终落在契约区间；死区大小与电机静摩擦有关，真机标定时用最小启动速度确定。（2）量程通过 limits 注入，与配置常量同源，避免代码默认值与运行配置漂移。（3）停止通道单独解码，任何把停止并入角速度向量的实现都会破坏语义；停止的判定是「大于 0」，其余通道的数值不影响终止。

片段 2：航点控制器的最小实现

def waypoint_to_velocity(pose, waypoint, max_lin=0.25, max_ang=1.0,
                        k_lin=1.0, k_ang=2.0, eps=0.05):
    """先转向目标，再前进；到点后对齐朝向。"""
    dx = waypoint[0] - pose[0]
    dy = waypoint[1] - pose[1]
    dist = (dx * dx + dy * dy) ** 0.5
    heading_err = wrap_to_pi(np.arctan2(dy, dx) - pose[2])
    if abs(heading_err) > 0.2:              # 朝向偏差大时原地转
        lin, ang = 0.0, np.clip(k_ang * heading_err, -max_ang, max_ang)
    elif dist > eps:
        lin = np.clip(k_lin * dist, 0.0, max_lin)
        ang = np.clip(k_ang * heading_err, -max_ang, max_ang)
    else:                                    # 位置到点，对齐目标朝向
        yaw_err = wrap_to_pi(waypoint[2] - pose[2])
        lin = 0.0
        ang = 0.0 if abs(yaw_err) < 0.05 else np.clip(
            k_ang * yaw_err, -max_ang, max_ang)
    return lin / max_lin, ang / max_ang      # 返回归一化指令交给环境

解读：（1）控制器分三段，先转向前进方向、再平移到点、最后对齐朝向，与真机 HomeRobot 速度控制器的行为描述同构，也与挑战文档对航点控制器的说明一致。（2）返回值除以各自上限得到归一化指令，控制器与策略输出走同一接口，训练与部署可以对换。（3）参数 k 与 eps 需要按平台标定；eps 过小会在目标点附近震荡，过大则触发下一段时仍有位置误差。

片段 3：停止通道与几何安全门

def stop_gate(depth, stop_cmd, target_visible, radius=0.17,
              min_clearance=0.25, valid_range=(0.5, 5.0)):
    """停止申请与安全门；depth 为米制，取水平中线邻带估计前方净空。"""
    lo, hi = valid_range
    mid = depth.shape[0] // 2
    band = depth[max(0, mid - 20): mid + 20]     # 机身高度附近的射线
    front = band[:, depth.shape[1] // 4: 3 * depth.shape[1] // 4]
    front = front[np.isfinite(front)]
    front = front[(front >= lo) & (front <= hi)]
    free = float(front.min()) if front.size else hi
    if stop_cmd > 0.0 and target_visible and free > radius + min_clearance:
        return True                          # 三重条件同时满足
    return False

解读：（1）停止通道给出终止意愿，安全门检查实际几何：目标可见、前方净空大于半径加余量，两者同时成立才执行停止，避免在贴墙或目标被遮挡时终止。（2）余量 0.25 m 是工程建议起点，可按制动距离标定；半径 0.17 m 来自配置，与碰撞体一致。（3）深度先裁剪到有效区间再取最小值，0.5 m 内的无效读数不会制造虚假的「贴墙」判断。

常见坑

  • 把 [−1,1] 当物理速度：症状是策略输出 1.0 被视为 1 m/s，与真机实测不符。根因是量程在 VelocityControlActionConfig 中定义且挑战文档未公布数值。修复：从锁定配置读取常量并以配置文件注入；真机测速回归验证线性映射。
  • 把停止当作第四个连续维度：症状是策略微调停止通道数值试图「减速停止」。根因是终止语义为取值大于 0，其余数值不参与运动。修复：停止单独分支处理，速度平滑由控制器负责。
  • 按步数做时间预算：症状是复现时按 500 步规划，实际运行被墙钟截断或聚合预算不足。根因是配置显式设置 500 秒墙钟上限，评测聚合为 48 小时 1000 幕。修复：以单步耗时统计反推可运行幕数，把推理延迟纳入预算。
  • 混用控制器接口：症状是训练用离散航点控制器、提交时改用速度控制，动作分布完全错位。根因是三种控制器虽然共享终止通道，但输入语义不同。修复：训练与评测锁定同一接口版本，配置写入实验记录。
  • 忽略半径与滑动设置：症状是规划路径贴墙、仿真中通过而真机刮碰，或相反地放弃可通行窄缝。根因是圆柱半径 0.17 m、侧伸机械臂外形与 allow_sliding=False 共同改变可通行性。修复：规划时按外扩半径留余量；真机重复关键窄通道并在报告中列出差异。

练习与思考

  1. 用 v = vmin + (u+1)(vmax−vmin)/2 计算 u = 0、0.5、1.0 在对称量程 [−0.5, 0.5] 与不对称量程 [0, 1.0] 下的取值，并说明两种量程对「倒退」语义的差异。★
    提示
    对称量程下 u=0.5 为 0.25、u=1.0 为 0.5；不对称量程 [0,1] 下 u=0 映射到 0.5，负指令映射到 [0, 0.5)，物理上无法倒退。量程区间决定动作语义的可达集合。
  2. 由水平视场 42 度与 480×640 分辨率，复算垂直视场与水平像素角分辨率，并计算 2 m 处单像素对应的地面尺寸。★★
    提示
    垂直视场 2·arctan(tan21°×640/480) = 54.208 度；水平每像素 42/480 = 0.0875 度；2 m 处约 2×1.527×10−3 = 3.05 mm。
  3. 假设线速度量程上界在锁定配置中为 R，推导平均速度分别为 0.6R 与 0.8R 时，500 秒可覆盖的最大位移表达式，并给出 R = 0.3 m/s 的数值。★★
    提示
    位移为平均速度乘 500 秒：0.6R×500 = 300R，0.8R×500 = 400R；R = 0.3 时分别 90 m 与 120 m。用于判断任务场景边长与预算是否匹配。
  4. 设计一个「离散航点控制器对速度控制」的接口消融实验：同一策略网络、同一场景集，评测成功率、SPL、碰撞率与平均单步耗时，说明如何控制变量并解释预期差异来源。★★★
    提示
    控制变量：同一随机种子、同一观测管线、同一停止逻辑；两臂只改动作接口，策略网络输出层按接口调整。预期连续臂路径更平滑、SPL 更高，但训练方差更大、单步耗时更长；碰撞率差异来自滑动设置与控制器限幅。预先写清比较口径，碰撞率按每幕均值登记，不用总次数。
  5. 用墙钟预算解释：为什么单步耗时 0.5 秒的策略能通过 500 秒的单幕检查，却只给 48 小时聚合预算留下约四成余量；给出聚合预算允许的最大单步耗时估算（设每幕平均 200 步）。★★
    提示
    聚合预算 172,800 秒，1000 幕共约 20 万步，单步耗时上限约 0.86 秒；单步 0.5 秒时总耗时约 10 万秒，余量约 42%；超过 0.86 秒则无法完成。单幕 500 秒上限只约束单幕，聚合预算约束整体效率。
