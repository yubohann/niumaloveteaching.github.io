第一篇 · 任务、仿真与评测地基

第 004 讲｜SPL 与 ObjectNav-SPL

上一讲把成功判定落到「1 m 距离 + oracle 可见性」，成功率只回答是否找到目标。本讲补上效率维度：推导 SPL 的定义与三条性质，拆解 oracle 最短路径的构造口径，说明 ObjectNav-SPL 与 PointNav-SPL 的唯一差异，并用两组对照轨迹实算「高 SR 低 SPL」与「低 SR 高 SPL」的排名反转。

  • 主题：SPL / ObjectNav-SPL / oracle 最短路径 / 与 SR 联合解读
  • 关键公式：SPL = (1/N) · Σ Si · li / max(pi, li)
  • 预计学时：60 分钟
  • 前置章节：第 003 讲（成功判据）

学习目标

  • 会算：给定一组 episode 的 (Si, li, pi)，逐条算出 SPL 分量，得到 SR 与 SPL 两个聚合值，并解释分解式 SPL = SR × 条件效率。
  • 会判断：说清 SPL ≤ SR 的成立条件与 max 夹取的作用，区分「高 SR 低 SPL」与「低 SR 高 SPL」两类结果的含义。
  • 会构造：按「半径 1 m 内可停点、测地最短路径、最近实例」三步构造 ObjectNav 的 oracle 基线，并说明它与 PointNav-SPL 的唯一差异。
  • 会实现：写出向量化的 SR/SPL 评估代码，保留逐 episode 返回值以支持自助重采样置信区间，并用不变量断言防住口径错误。
  • 能识别五类常见误读：欧氏距离近似基线、聚合口径混用、单指标排序、路径长度口径不一、退化 episode。

背景与动机

第 003 讲确定了成功判据：停止位置到目标类别任一实例表面的欧氏距离不超过 1 m，且该实例能从停止位姿经旋转与俯仰被 oracle 看见。成功率（Success Rate，SR）把每条 episode 压缩成 0 或 1，回答「是否找到目标」，忽略「走了多远」。这一口径会奖励漫游：在 ObjectNav 中，只要最终停在某个实例附近就计成功，绕遍整层楼再停下的策略与直奔目标的策略拿到同样的 SR。

为把效率纳入评测，Anderson 等在 2018 年的评测共识报告（On Evaluation of Embodied Navigation Agents）中确立了成功率加权的路径长度指标 SPL（Success weighted by Path Length）。Habitat 挑战赛 2020 与 2021 沿用该指标，2021 挑战页给出定义式与 ObjectNav 适配版本；本讲的公式与成功判据均以该页及其引用的 2020 共识文档为准。

ObjectNav-SPL 与 PointNav-SPL 的公式形式完全相同，唯一的差异落在基线路径的终点选择：PointNav 的目标是坐标点，最短路径直达该点；ObjectNav 的目标是类别，最短路径按「离起点最近的实例」计算。挑战页给出的例子值得记住：agent 出生点离 chair1 很近，却停在远处的 chair2，成功率 100%，SPL 却相当低，因为实际路径远长于 oracle 指向 chair1 的路径。

2021 ObjectNav 榜单同时报告 SPL、SOFT_SPL、DISTANCE_TO_GOAL 与 SUCCESS 四个字段，并以 SPL 排序。由此产生两个必须讲清的问题：SPL 与 SR 怎样联合解读；基线口径（最短路径如何构造、以哪个实例为准）如何影响数值。本讲解决这两个问题；SOFT_SPL 与 DTG 的定义与工程用法留给第 005 讲。

数字纪律先交代：本讲所有表格数字由固定环境的 Python 程序实算得到，2D 栅格对照实验的代码在关键代码一节给出，使用相同的栅格与距离定义即可复现每一行。

核心原理

1. 定义与符号

设评测集含 N 条 episode。对第 i 条，记成功指示 Si、oracle 最短路径长度 li、agent 实际路径长度 pi，SPL 定义为：

SPL = (1/N) · Σi=1..N Si · li / max(pi, li) Anderson 等 2018 给出指标；Habitat 挑战赛 2021 官方页给出该式与 ObjectNav 适配说明
符号含义单位 / 取值来源
Nepisode 数正整数评测集
Si成功指示0 或 1第 003 讲判据
li起点到最近目标实例可停集的测地最短路径长度米评测端构造
pi起点到 STOP 位姿的实际路径长度米仿真器累计
ri单条效率比li / max(pi, li)由 l、p 导出
SPLi单条得分Si · ri，落在 [0, 1]由 S、r 导出
SR成功率(1/N) · Σ Si同上

SPL 是「逐条比值再平均」的均值，不是总长度之比。它把每条 episode 视为独立样本，成功记 0、失败记 0 分，两个维度在同一张表里收束。基线的口径细节在 4 节展开。

2. 三条性质（逐步推导）

性质一：SPL ≤ SR，等号当且仅当所有成功 episode 的效率比为 1。对协议内产生的数据，agent 若成功，其停止位姿落在某个实例的可停集内，而 li 是所有实例、所有可停点里离起点最短的那一条，故 pi ≥ li。此时 ri = li / max(pi, li) = li / pi ≤ 1，进而 SPLi = Si · ri ≤ Si。对 i 求和再除以 N，得 SPL ≤ SR。max 夹取的作用是防御口径错配：当某个实现让 li 大于 pi（例如基线与执行使用了不同尺度）时，把比值压回 1，避免出现「效率超过最优」的荒谬分数。

性质二：SPL 可分解为成功率与条件效率的乘积。设成功的 episode 有 Ns 条，把求和按成功与失败拆开：

SPL = (1/N) · Σsucc ri = (Ns/N) · (1/Ns) · Σsucc ri = SR · r̄succ r̄succ 称为条件效率：只在成功 episode 上平均的效率比；SR = 0 时 SPL 记为 0

该分解是联合解读的钥匙：SPL 的每一分变化都能归因到「找到的比例」或「找到时路径的笔直程度」之一。它也解释了为什么只报 SPL 不够：两个 SR 差异悬殊的智能体可以给出接近的 SPL，0.5000 的 SPL 配上 0.50 的 SR 意味着 0.94 的条件效率，配上 1.00 的 SR 只意味着 0.50 的条件效率。

性质三：失败 episode 的效率比不进入得分。由 SPLi = Si · ri，无论失败时走了 9 m 还是 90 m，单条得分都是 0。因此「SPL 提升」可能来自停止策略变得更保守：只在十拿九稳的 episode 上停止，条件效率上升，SR 同时下降。评测必须成对报告 SR 与 SPL，才能区分「找得更多」与「只在容易处收手」。

4. oracle 最短路径的构造口径

li 取评测端在可导航空间上解出的测地距离，直线距离会低估绕行。按挑战页定义与成功判据，构造流程分四步：

  1. 枚举实例：找出当前 episode 场景中属于目标类别的全部实例 g1, …, gM（ObjectNav 允许停在任一实例，因此 M 可大于 1）。
  2. 圈定可停集：对每个实例，取到实例表面欧氏距离不超过 1.0 m 的可导航位姿，并检查 oracle 可见性，得到可停点集合 Qk。半径取 1.0 m 的理由是成功判据与之共用；可见性用射线检验或采样朝向近似，保证「停在 q 的确能算成功」。
  3. 解测地距离：以起点为源，在导航网格或可导航图上解单源最短路径，查询到各实例所有可停点的距离，对每个实例取最小，再对实例取最小：li = mink minq∈Qk dgeo(si, q)。单源求解一次覆盖所有可停点，比逐点查询更省算力。
  4. 记录与校验：保存数值与取到最小值的实例编号（argmin）。若 agent 停在另一个实例上，argmin 是排查低 SPL 的第一条线索；若某实例无可停点或不可达，应从实例集合中剔除并记录。

口径上有三处容易失配，需要在实验配置里显式写明：l 与 p 必须使用同一距离尺度（都按米、都走导航网格）；可停集半径与成功半径同为 1.0 m；多楼层场景的楼梯与断连通区域要有确定处理（不可达实例剔除并标注）。工程上常用导航网格上的 A* 或 Dijkstra 实现该基线，评测框架一般提供对应测度接口，接口命名与参数随版本演进。

实现成本可以估：导航网格由场景几何预计算，节点为可通行多边形上的采样点，一次单源 Dijkstra 的复杂度为 O(E log V)；随后对每个实例的每个可停点做一次距离读取，读取次数等于总可停点数。以每场景 6 个实例、每实例 10 个可停点计，单条 episode 的基线查询不到百次，评测整体开销远小于策略前向。若环境只提供实例中心到起点的直线距离接口，应在导航网格上补齐测地查询，并把该口径列入评测配置审查项。工程实现上，可停点集合只依赖场景与实例，可以预计算并缓存；起点随每条 episode 变化，测地距离场按 episode 求解一次，供该条全部实例查询复用，跨 episode 不保留。

5. 捷径失真：最近实例口径的后果

ObjectNav-SPL 的基线只指向最近实例，这一口径把「选择了哪个实例」编码进了分母。考虑一条一维走廊：起点在 x = 0，chair1 在 x = 4.0 m，chair2 在 x = 14.0 m，成功半径 1.0 m。最近可停点在 chair1 左侧 1 m 处，l = 3.0 m；chair2 对应 l2 = 13.0 m。某 agent 路过 chair1 而未停，继续走到 x = 13.2 m（距 chair2 0.8 m），途中绕开杂物多走 0.4 m，p = 13.6 m。它成功了，单条 SPL = 3.0/13.6 = 0.2206。

基线口径l (m)p (m)比值
最近实例可停集（ObjectNav-SPL 定义）3.013.60.2206
所停实例可停集（换成 chair2 计基线）13.013.60.9559
停在最近实例（对照路线）3.03.01.0000

同一段轨迹，换口径后比值相差 4.333 倍。要点有两层：第一，低 SPL 可能来自实例选择，轨迹本身可以相当高效，解读时要结合停止实例编号与 DTG；第二，反过来看，若 agent 直奔 chair1 停稳，p 与 l 都接近 3.0 m，单条得分接近 1，说明该口径奖励「就近解决」。这正是挑战页那一句「成功 100%、SPL 却相当低」的算术来源。

还有一类同源失真来自 episode 生成。若起点与最近实例的测地距离没有下限，l 会趋近 0，比值失去稳定行为：l = 0、p = 0 时 0/0 未定义，l = 0、p 大于 0 时直接得 0。此时 SPL 的高低更多反映生成协议的宽松程度，策略能力的信号被稀释。稳妥做法是在生成阶段要求起点到所有实例的测地距离不低于一个下限（例如 2 × 成功半径），并把该阈值写进数据卡片。

6. 与 SR 的联合解读

把 SPL 与 SR 放在同一平面上，比单看任何一个数字信息量更大。由于绝对 SPL 受 SR 上界约束，表格用条件效率判断「相对高」：

条件效率相对高条件效率相对低
SR 高成功率与效率兼顾，搜索与执行都成熟找得到但绕路，典型症状是探索过度或停止判定迟滞
SR 低有把握才停，覆盖范围不足，需要提升探索与召回成功率与效率都需改进，先修感知与目标定位

除了单系统解读，SPL 还常用于系统比较，这时要比的是同一评测集上的配对结果。两个系统若在不同难度混合的 episode 集合上评测，均值差会携带难度构成差异：甲系统在容易的 episode 上效率高，乙系统在困难的 episode 上成功多，合并后的排序可能由集合组成决定。固定评测集、逐条配对求差，并对配对差值给出自助区间，是消除这类混淆的标准做法，榜单统一在同一 test 集上评测正基于此。

用 Habitat 挑战赛 2021 的 ObjectNav 榜单检验这套读法。SPL/SR 一列由榜单公布的两位小数反推，存在舍入误差，作为近似解读：

7. 不确定度：SPL 差异何时可信

SR 是伯努利均值，标准误 SESR = sqrt(SR · (1 − SR)/N)。取 N = 1000、SR = 0.30，得 SESR = 0.01449，95% 置信区间半宽约 0.0284（2.84 个百分点）。SPL 是 Si · ri 的均值，其单条方差为 Var = E[(Si ri)²] − SPL² = SR · E[r² | 成功] − SPL²。把 r 近似看作常数 r̄，则 E[(S r)²] = SR · r̄²，SPL² = SR² · r̄²，于是 Var ≈ SR · r̄² · (1 − SR)。对 Red Rabbit 的分解值 SR = 0.30、r̄ = 0.4333，得 Var ≈ 0.0394，SESPL ≈ sqrt(0.0394/1000) = 0.00628，95% 半宽约 0.0123。实际数据里 r 有分布，方差更大，正式报告用按 episode 自助重采样（Bootstrap）估计区间。

若要在 80% 检验效能、双侧 5% 显著性下分辨 ΔSPL = 0.02 的差距，所需 episode 数约为 N ≈ (z0.975 + z0.80)² · σ² / Δ² = 7.849 × 0.0394 / 0.0004 ≈ 774。这解释了挑战页为什么保留「SPL 差异不显著时参考附加指标」的规则：千条量级的评测集对 0.02 以下的 SPL 差距分辨力有限，排序结论要附区间。

8. 边界与失效

  • l 趋近 0：起点若已在某个实例的可停集内，正确口径给出 l = 0。p = 0 时 0/0 未定义，工程上有两种约定：生成期剔除该类 episode，或约定比值取 1 并在日志单列；p 大于 0 时比值 0，即「本可立即成功却先行游走」得 0 分。示例：l = 0、p = 5 的比值为 0.0000。
  • p = 0 而 l 大于 0：若基线口径正确，这两个事实矛盾（起点可停则 l 应为 0）。它通常说明基线的可停集被收窄，例如只把实例中心当作基线终点而未使用半径 1 m；此时比值被 max 夹到 1.0000，属于口径伪影，需要在实现里报警。
  • 度量混用：用欧氏距离近似 l 会系统性低估绕行。设某场景真实测地长度 l = 13.4 m、欧氏直线 10.0 m，agent 路径 p = 13.6 m：正确比值 0.9853，近似口径只剩 0.7353，绝对差 0.2500。基线实现必须与 p 同尺度。
  • 路径长度口径：p 应定义为累计平移距离；原地转向不改变位置，不计入；平台滑动与回退按位移累计。不同实现混用「步数」与「米」会带来比例漂移。
  • 不可达与多楼层：实例全部可停点不可达时 l 为无穷，该 episode 无定义，应在生成期剔除并记录；跨楼层场景的楼梯代价要与执行一致，否则 l 与 p 的差会被楼梯放大。
  • 端点贴边：停止距离恰好 1.0 m 的判定归第 003 讲的边界样例处理，SPL 侧只需保证同一阈值贯穿成功判定与可停集构造。

实现思路与设计

评估模块按三层组织：记录层保存每条 episode 的原始量，计算层产出逐条返回值，聚合层给出标量与区间。逐条返回值必须保留，任何区间估计与分组分析都以它为输入。

数据结构与接口

@dataclass
class EpisodeResult:
    episode_id: str
    success: bool
    shortest_m: float        # l_i：oracle 基线，米
    path_m: float            # p_i：实际路径，米
    stop_distance_m: float   # DTG：停止点到最近实例的距离，米
    stop_instance_id: int    # 停靠实例编号，用于诊断实例选择

接口约定四个函数：oracle_l(scene, start, category) 产基线；episode_returns(results) 产逐条 (SRi, SPLi)；aggregate(...) 产 SR、SPL、条件效率、绕路税；bootstrap_ci(...) 产区间。校验规则：l 与 p 非负有限；停止距离不超过 1 m 而 success 为假、或超过 1 m 而 success 为真，都应触发日志告警，前者查可见性检验，后者查成功判定。

诊断路径建议固定成三步：先看基线的 argmin 实例与 stop_instance_id 是否一致，不一致的低分多半来自实例选择；再看 stop_distance_m 的分布，失败集中在 1 m 附近说明停止判定迟滞；最后看 p 与 l 的散点，长尾点对应卡死或绕圈。三个字段在一次评测中即可导出，无需重跑仿真。

自助区间的实现要点：以 episode 为最小重采样单位，每次抽取 N 条并重算 SR、SPL，重复 1000 次后取 2.5% 与 97.5% 分位数；不要在长度层面单独重采样 l 或 p，否则会破坏两者的配对关系。配对比较时，对逐条差值序列做同样的重采样。

关键代码与解读

三段代码对应三层：指标核心、基线构造、对照实验复算。环境与数据在上一节给出，片段 3 的输出与两张表逐行对应。

片段 1：指标核心与不变量断言

import numpy as np

def episode_returns(success, shortest_m, path_m, eps=1e-9):
    """返回逐 episode 的 SR 分量与 SPL 分量。"""
    s = np.asarray(success, dtype=float)
    l = np.asarray(shortest_m, dtype=float)
    p = np.asarray(path_m, dtype=float)
    assert np.all(l >= 0) and np.all(p >= 0)             # 长度非负
    denom = np.maximum(p, l)                              # max 夹取，防口径错配
    ratio = np.where(denom > eps, l / np.maximum(denom, eps), 0.0)
    spl_i = s * ratio                                     # 失败 episode 得 0
    assert np.all(spl_i <= s + 1e-9)                     # 不变量：SPL_i 不超过 S_i
    return s, spl_i

def evaluate(success, shortest_m, path_m):
    sr_i, spl_i = episode_returns(success, shortest_m, path_m)
    sr, spl = float(sr_i.mean()), float(spl_i.mean())
    eff = spl / sr if sr > 0 else float("nan")            # 条件效率
    return {"SR": round(sr, 4), "SPL": round(spl, 4),
            "cond_eff": round(eff, 4), "gap": round(sr - spl, 4)}

解读：（1）逐条返回，不直接对长度求均值，是后续自助重采样与分组诊断的前提。（2）分母加 eps 并把退化情形记为 0，让 l = 0 与 p = 0 同时出现时有确定行为；若项目选择「过滤退化 episode」，在生成层实现并保持报告口径一致。（3）不变量断言把 SPL ≤ SR 变成运行时检查，任何基线口径错误都会在这里暴露，可以避免把问题带进报告。

片段 2：栅格基线与最近实例口径

import heapq, math

NEIGHBORS = [(dx, dy) for dx in (-1, 0, 1) for dy in (-1, 0, 1) if dx or dy]

def dijkstra(start, blocked):
    """八连通栅格单源最短路，返回以格为单位的距离表。"""
    dist = {start: 0.0}
    pq = [(0.0, start)]
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist.get(u, math.inf):
            continue                                      # 过期条目跳过
        for dx, dy in NEIGHBORS:
            v = (u[0] + dx, u[1] + dy)
            if v in blocked:
                continue
            if dx and dy and ((u[0] + dx, u[1]) in blocked or (u[0], u[1] + dy) in blocked):
                continue                                  # 禁止对角穿墙
            nd = d + (math.sqrt(2.0) if dx and dy else 1.0)
            if nd < dist.get(v, math.inf):
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return dist

def oracle_l(dist, instances, radius_cells, cell):
    """l*：对每个实例圈定半径内可停格，所有实例取最小。"""
    best = math.inf
    for gx, gy in instances:
        for q, d in dist.items():
            if math.hypot(q[0] - gx, q[1] - gy) <= radius_cells:
                best = min(best, d * cell)
    return best

解读：（1）禁止对角穿墙保证路径物理可达，否则 r 会被高估。（2）单源 Dijkstra 一次给出到所有可停格的测地距离，最近实例口径在最后一步取 min。（3）半径按格数换算，1.0 m 成功半径对应 2 格；真实实现把可停集与可见性检验交给场景层，这里用开放格近似。

常见坑

  • 用欧氏直线近似 oracle 基线：症状是 SPL 系统性偏低，且低得没有规律。根因是 l 忽略了墙体与障碍的绕行。修复：改用与执行同尺度的测地距离；实算对照为真实 0.9853 对近似 0.7353，偏差 0.2500。
  • 聚合口径混用：症状是复现论文数字总是差一点。根因是把总长度比当作 SPL。修复：逐 episode 算比值再平均；反例数字为 0.2550（正确）对 0.3367（总长度比）。
  • 用 SPL 单指标排序：症状是「SPL 高的系统被判定更优」。根因是忽视 SPL ≤ SR 与条件效率的含义。修复：报告 (SR, SPL) 成对加区间；对照实验里族 B 以 0.4717 的 SPL 超过族 A 的 0.2842，而 SR 只有其一半。
  • 路径长度口径不一：症状是同一策略在不同框架里 SPL 漂移。根因是一边按步数累计、一边按米换算，或把原地转向计入路径。修复：统一为累计平移距离并在配置里写明单位与动作步长对应关系。
  • 退化 episode 未处理：症状是出现 NaN 或异常满分的单条记录。根因是 l 与 p 同时趋零（0/0）或基线可停集被收窄到实例中心（p = 0、l 大于 0 被判 1.0000）。修复：生成期设最小测地距离、评测期对 l 低于阈值的 episode 单列，并保持与成功半径的口径一致。

小结

  • SPL = (1/N) · Σ Si · li / max(pi, li)，由 Anderson 等 2018 确立，Habitat 挑战赛 2020 与 2021 沿用；基线口径为测地最短路径。
  • ObjectNav-SPL 与 PointNav-SPL 的唯一差异：基线指向离起点最近的实例的可停集，成功率仍允许停在任一实例，由此产生「成功却低分」的捷径现象。
  • 三条性质：SPL ≤ SR 恒成立；SPL = SR × 条件效率；失败 episode 的效率比不进入得分。
  • 实算对照：全成功的观光族 SR 1.0000、SPL 0.2842；半成功的谨慎族 SR 0.5000、SPL 0.4717。SPL 排名与 SR 排名方向相反，成对报告是硬要求。
  • 工程红线：l 与 p 同尺度、逐 episode 再聚合、保留逐条返回值、退化 episode 单列、区间与标量同报。
