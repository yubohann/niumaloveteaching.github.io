第二篇 · 模块化：地图·探索·常识

第 022 讲｜模块化流水线解剖

上一讲把前沿探索从 1997 年讲到现在。本讲把它放回完整系统：Raychaudhuri 等（2023，MOPA）用「检测、建图、探索、PointGoal 导航」四个模块组装 ObjectNav 智能体，并系统对比每一槽位的实现选项。关键结论有三条：预训练 PointNav 智能体在成功率上超过解析路径规划器；简单均匀采样在 MultiON 2.0 上超过前沿与学习式探索；模块接口处的误差会逐段放大。本讲用论文数据复算模块对比、失败分解与评测预算，给出一张可直接实现的接口表。

  • 主题：模块化流水线 / 四段式接口 / 误差传播 / MOPA
  • 关键公式：Psucc ≈ p检测 · p建图 · p探索 · p导航（误差链示意）；αexp = 50 步重采样阈值
  • 预计学时：80 分钟
  • 前置章节：第 021 讲（FBE）

学习目标

  • 会画：默画「检测 → 建图 → 探索 → PointGoal 规划」四段式数据流，标出每段输入、输出与失败模式。
  • 会算：复算 MultiON 2.0 的规模账、四类导航模块与四类探索模块的对比差、失败分解占比与评测预算。
  • 会判：给定一组模块对比数据，判断改进来自感知、探索还是执行，并识别「无训练」声明中的训练来源。
  • 会设计：为一套四段式流水线写出接口表、参数表与逐段监测指标，并给出误差链的合成与实验验证方案。
  • 会诊断：识别标签散裂、坐标框架错位、超时重采样缺失、完美深度与里程计假设四类常见失效。

背景与动机

第 021 讲完成了探索模块的溯源，但真实系统不只有探索。ObjectNav 智能体至少要回答四个问题：视野里有什么（检测），它们在哪里（建图），还没找到目标时去哪里（探索），看到目标后怎么走过去（导航）。2018 年以来的头部方案按这四段拆开实现，每一段都可以替换成学习模块、解析模块或规则模块。拆开带来的收益是复用与可解释，代价是误差在接口处传播：检测漏掉的目标不会出现在地图上，地图错位的目标会把导航引向错误房间。

Raychaudhuri 等（2023，v3 于 2024 年修订）的 MOPA（Modular ObjectNav with PointGoal Agents）把这套结构做了系统的消融。论文把任务拆成四个模块：用 RGB 检测物体的检测模块、把检测投影成俯视语义地图的建图模块、在未找到目标时推进探索的探索模块、把智能体移动到已发现目标的导航模块。两个关键结论分别修正与补充了当时的直觉：其一，直接复用预训练的 PointGoal 智能体作为导航模块，在成功率与进度上超过最短路径跟随与栅格搜索等解析规划器，且耗时更低；其二，在 MultiON 2.0 的测试集上，简单均匀采样成功率 81%，超过前沿的 72%、规则的 72% 与学习式 Active Neural SLAM 的 76%。此外，论文把场景从 MultiON 1.0 的 61 个扩到 800 个、episode 从 3.05M 扩到 8.00M，并在未见环境上与三个端到端基线对比，展示模块化方法跨环境迁移更稳。

本讲回答四个问题：四段各自的机制与接口；模块对比数据怎么读；误差如何逐段传播；一套可复现的流水线应该带哪些监测量。MOPA 是第 023 讲 SemExp 的对照片：SemExp 用语义先验指导探索，MOPA 在目标随机放置的设定下展示了不带类别先验的探索同样有效，探索模块可以用更朴素的策略；两讲合起来给出第二篇最重要的一组设计判据。

核心原理

1. 四段式数据流

用 MOPA 的模块划分作为解剖对象。四段的职责、输入与输出如下，全部对应论文第 4 节。

段输入输出MOPA 实例失败模式
检测当前 RGB 帧类别标签加检测框MultiON 用 Faster R-CNN，ObjectNav 用零样本 Detic漏检、误检、置信度阈值不当

数据流有一个容易忽略的细节：MOPA 把「规划」拆成两层。上层规划器（论文记作 P）只负责选择当前要去的目标点，是任务目标还是探索目标；下层导航模块（论文记作 N）负责把目标点转成动作序列。目标点统一为智能体系下的相对坐标，因此探索模块与任务目标可以走同一条接口进入导航模块。这个统一是流水线可替换性的关键：换探索策略不需要动导航，换导航策略不需要动探索。

2. 四段的机制细节

检测段。MultiON 用 Faster R-CNN 在 oracle 智能体采集的帧上离线训练；柱体目标微调出「有无柱体」检测并用 kNN 分类颜色，自然物体直接微调多类检测。ObjectNav 实验改用零样本检测器 Detic，置信度阈值统一取 0.95。检测段的输出不进入地图之前不做跨帧跟踪，跨帧一致性由建图段的「最新标签覆盖」机制间接保证。

建图段。语义地图是俯视二维栅格，格边长 0.2 m；每个格子存该位置最新一次被投影的语义标签。投影用深度通道与位姿完成，论文明确假设深度与里程计完美（与同期地图方法一致）。物体一旦被观测到就保留到 episode 结束，即使之后离开视野也不清除。地图同时服务探索段（采样候选目标）与规划段（选择目标簇质心），是四段中唯一被两个下游模块共享的数据结构。

探索段。探索目标从地图上采样。论文对比四类策略：均匀俯视采样（在地图上均匀取点）、Stubborn（在本体局部网格里选角落方向直行）、前沿（走向已探索区域的边界）、Active Neural SLAM（加载官方预训练全局策略，按自由空间地图预测远距离探索目标）。所有策略都配一个失效保护：若智能体在 αexp = 50 步内没有到达探索目标，重新采样目标。论文报告均匀采样效果最好，并给出参数依据：均匀策略的最佳网格尺度为 10 m，Stubborn 为 3 m。

规划与执行段。上层用质心选目标：对地图上同一标签的像素簇取质心，论文发现质心比簇内随机取格更稳。下层导航对比四类：预训练 PointNav 策略（ResNet50 深度编码器 + GPS+Compass 的 MLP + LSTM + actor/critic，来自 Wijmans 等 2020 的 DD-PPO 训练）、最短路径跟随（SPF，可访问真值导航网格）、BFS 与快速行进法（FMM，在预测占据图上规划，障碍膨胀后配「解卡」回退动作序列）。

5. 实算三：误差链与失败分解

四段串联的系统成功率可以近似写成各段条件成功率的乘积。用一个示意模型说明敏感性：取 p检测 = 0.90、p建图 = 0.95、p探索 = 0.90、p导航 = 0.90，则合成成功率约 0.6925。若只把其中一段提高 0.05，合成增益等于 0.05 乘以其余三段之积；检测段对应的增益约为 0.0385。若四段同时提高到 0.95，合成成功率约 0.8145。示意模型的用途是排序改进优先级：乘积结构中，改进应投给「其余段之积最大」的槽位，不能只看哪一段数字最低。

Psucc ≈ p检测 · p建图 · p探索 · p导航，∂P/∂pk = ∏j≠k pj 示意模型，假设各段条件独立；真实系统的失败类型有重叠，仅用于比较改进的边际收益

论文对 PredSem 在 3ON 柱体任务上的失败做了手工分解（成功率 50%）。失败 episode 中：最多的一类是耗尽 2500 步上限，占全部 episode 的 40%；其中 29% 是从未发现目标（探索段的责任），11% 是发现了目标但没有成功在 1 m 内发出 found（导航段的责任）；剩下 10% 是停在距目标较远处（导航与停止判定）。按 50% 的失败总数换算，三类各占 58%、22%、20%。分解的价值在于方向：多数失败落在探索覆盖，执行精度只占少数；这与模块对比里导航模块高成功率的结论互补。论文同时报告 nn-ON 的跨目标数泛化：Progress 在 1ON / 3ON / 5ON 上分别为 95% / 87% / 76%，5ON 比 1ON 低 19 个百分点，目标越多，地图记忆与回访能力越吃紧。

跨环境迁移是模块化路线的另一项证据。用 MP3D 场景训练的 PointNav 智能体，直接接到 HM3D 场景的 MultiON 2.0 上，PredSem 的成绩为 Success 38 / Progress 54 / SPL 17 / PPL 25（MP3D 上为 38 / 53 / 15 / 21）。同一组模块换环境后数字稳定，说明「感知加地图加规则探索加学习导航」的组合把环境先验的需求降到了较低水平；三个端到端基线在同一测试集上的成功率只有 0.3% 至 0.5%（进度 6% 至 10%）。

7. 边界与失效

  • 完美深度与里程计假设。建图段用深度与位姿投影，论文与同期方法一致地假设两者无噪声。真机部署时这两项都由感知估计，误差会直接进入地图；第 029 讲专门分析语义地图的噪声传播。
  • 评估协议的视点近似。论文报告一部分「停在目标 1 m 内且目标在视野中」的 episode 被判失败，原因是 2022 协议用「距目标包围盒 1 m 的采样视点」近似可停区域，视点稀疏时有效停靠被漏判。这是评测协议的边界，不是策略错误，报告时应单列这类 episode。
  • MultiON 与 ObjectNav 口径不同。前者的 2500 步、found 序列、干扰物设计只用于模块研究；把 MultiON 的模块结论直接搬到 ObjectNav 时，步数上限、动作集合与成功判据都要重新对齐。
  • 均匀采样依赖场景尺度。论文的解释明确绑定「场景多数小于 100 m²」这一条件；在大户型或多层场景，均匀采样的换向优势会削弱，前沿与语义探索的相对排序可能改变。
  • 模块对比的固定项不同。表 3 与表 4 都以 OracleSem 为基础，真实部署的 PredSem 会同时携带检测误差；用 OracleSem 的模块排序去预测 PredSem 的瓶颈会低估感知段的权重。

把 MOPA 结构落地需要三张表：接口表、参数表、预算表。设计目标是最小化模块间的耦合面，并让每一段都有独立的监测量。

接口设计的三条约束。第一，所有位置统一为「当前位姿坐标系下的相对坐标」，建图段负责坐标变换，下游不感知全局坐标。第二，语义栅格带已探索掩码，探索段无需自己推断哪些区域已覆盖。第三，探索目标带类型标记，规划段据此决定是否允许在接近时切换为任务目标。

设计决策：目标点接口优先于模块内部实现

流水线可替换性的成本几乎全部落在接口上。MOPA 把探索目标与任务目标统一成相对坐标，使四类探索策略与四类导航模块可以自由组合。自研系统若把位姿坐标系、位姿来源或动作定义漏进模块内部，替换一个模块就会牵动其余三段，消融实验失去意义。

模块对比必须逐段审计

表 3 与表 4 的固定项不同：导航对比用 OracleSem，探索对比也用 OracleSem。若把两张表的结论直接相乘，会忽略检测误差。落地审计流程：先用真值语义确认探索与导航的相对排序，再打开预测检测器观察排序是否翻转，最后在部署配置上报告端到端数字。三层之间的差异正是误差传播的量。

4. 与 SemExp 的分界

第 023 讲将展开的 SemExp（Chaplot 等 2020）与本讲的 MOPA 代表两种模块化立场。SemExp 把「目标类别常出现在哪类房间」的语义先验训练进探索模块，用先验排序探索目标；MOPA 把语义地图与探索解耦，探索策略不需要类别先验。论文指出语义先验在目标随机放置的 MultiON 中收益受限；在 ObjectNav 验证集上，PredSem 的成功率超过使用 SemExp 的 ModLearn 变体。设计判据可以记成一句话：目标分布符合室内常识时，语义先验值得引入；目标随机放置或需要跨类别泛化时，通用探索加地图记忆更稳。

关键代码与解读

三段代码对应四段式中的关键接口：语义地图投影、带重采样的流水线循环、目标簇质心选择。语言为 Python 3 加 NumPy，栅格约定与第 021 讲一致。

片段 1：语义地图投影更新

import numpy as np

def project_update(sem_map, known, detections, depth, pose, cam, cell=0.2):
    """把检测投影到俯视栅格：只覆盖已知自由格的标签，最新观测优先。"""
    h, w = sem_map.shape
    for (label, (x1, y1, x2, y2), conf) in detections:
        if conf < 0.95:
            continue                              # 与论文一致的阈值
        cx, cy = (x1 + x2) // 2, (y1 + y2) // 2   # 框中心像素
        d = float(depth[cy, cx])                  # 中心像素深度
        if not np.isfinite(d) or d <= 0.0:
            continue                              # 无效深度直接丢弃
        # 相机坐标 -> 世界坐标 -> 栅格坐标（实现中由位姿与相机参数完成）
        wx, wy = cam.unproject(cx, cy, d, pose)
        gx, gy = int(wx / cell), int(wy / cell)
        if 0 <= gx < w and 0 <= gy < h and known[gy, gx]:
            sem_map[gy, gx] = label                # 最新标签覆盖旧值
    return sem_map, known

解读：（1）置信度过滤放在投影之前，高阈值意味着「宁可漏、不可错」，与检测段参数表一致。（2）中心像素深度是对检测框的粗略近似，真实实现用框内多点到地面的反投影取中值，代码保留最简形式以突出接口。（3）标签写入只在已探索掩码为真处生效，防止把墙后的投影写到未知区域；这条保护对应第 9 节「投影错位」失效。（4）「最新观测优先」不提供跨帧衰减，物体一旦写入即持久，与 MOPA 的设定一致；动态物体较多的真实场景需要另行设计清除策略。

片段 2：带重采样的流水线循环

def run_episode(env, modules, alpha_exp=50, max_steps=2500):
    """四段流水线主循环；alpha_exp 为探索目标的重采样步数阈值。"""
    obs = env.reset()
    sem_map, known = modules["map"].init()
    goal, goal_type, goal_age = modules["explore"].sample(known)
    for t in range(max_steps):
        dets = modules["detect"](obs.rgb)
        sem_map, known = modules["map"].update(sem_map, known, dets, obs)
        task_goal = modules["plan"].query(sem_map, env.goal_label)
        if task_goal is not None:
            goal, goal_type = task_goal, "task"      # 看到目标立刻切换
            goal_age = 0
        elif goal_age >= alpha_exp:
            goal, goal_type = modules["explore"].sample(known)
            goal_age = 0                             # 超时重采样，防不可达
        action = modules["nav"].act(obs, goal)
        obs, done = env.step(action)
        goal_age += 1
        if done:
            break                                    # 停止动作或超时结束
    return env.result()

解读：（1）任务目标一经发现立即占用目标槽位，探索目标让位，这条优先级避免「看到目标还继续探索」的承诺失败（第 021 讲 Ye 等 2021 的行为分析）。（2）重采样只重置探索目标与计时，不重置地图与已访问状态，保证覆盖记忆跨目标保留。（3）主循环不接触任何模块内部状态，四段可独立替换；nav.act 接受统一的目标点接口。（4）goal_age 的滑动窗口与 max_steps 相互独立：重采样控制单目标空转，max_steps 控制整条 episode。

片段 3：目标簇质心选择

def cluster_goal(sem_map, label, min_cells=3):
    """在同一标签的连通簇中选质心；散裂噪声由 min_cells 过滤。"""
    h, w = sem_map.shape
    visited = np.zeros_like(sem_map, dtype=bool)
    best = None
    for y in range(h):
        for x in range(w):
            if sem_map[y, x] != label or visited[y, x]:
                continue
            stack, cells = [(x, y)], []
            visited[y, x] = True
            while stack:
                ux, uy = stack.pop()
                cells.append((ux, uy))
                for dx, dy in ((1, 0), (-1, 0), (0, 1), (0, -1)):
                    nx, ny = ux + dx, uy + dy
                    if 0 <= nx < w and 0 <= ny < h and not visited[ny, nx] \
                            and sem_map[ny, nx] == label:
                        visited[ny, nx] = True
                        stack.append((nx, ny))
            if len(cells) < min_cells:
                continue
            cx = sum(c[0] for c in cells) / len(cells)
            cy = sum(c[1] for c in cells) / len(cells)
            if best is None:
                best = (cx, cy)
    return best

解读：（1）先做连通域再取质心，规避标签散裂：同一物体的检测碎片若彼此相连仍是同一簇，孤立的一两格被 min_cells 过滤。（2）函数返回栅格坐标，由外层换算成相机坐标系下的相对坐标，接口与片段 2 的 goal 约定一致。（3）多簇场景只返回一个代表点（扫描顺序下的第一个达标簇）；工程上可加优先级规则（距离近、置信度高、面积大），但必须保持选择函数的确定性，便于复现实验。

常见坑

  • 标签散裂导致目标点漂移：症状是同一物体的目标点每帧跳动，导航来回修正。根因是把单格检测直接当作目标，未做连通域聚合。修复：按标签做连通域，取簇质心；对小于 min_cells 的簇过滤；必要时对簇做时间平滑。
  • 坐标系错位：症状是地图上目标出现在墙后或镜像位置。根因是相机坐标到世界坐标的变换方向写反，或相对坐标与全局坐标混用。修复：接口只暴露相对坐标；在合成样例上用已知点做单测，验证「同一物理点的两次观测落入同一格」。
  • 重采样缺失：症状是机器人在一个不可达的探索目标上耗尽预算。根因是选择函数没有 αexp 超时保护，或保护只重置目标、不重置计时。修复：目标与计时器同生命周期，超时同时重置；把重采样次数记入监测。
  • 完美深度假设带入真机：症状是仿真结果与真机差距集中在建图段。根因是深度与里程计在真机上由估计给出，误差回投到地图。修复：真机实验单独评估投影误差，或引入不确定性建模；第 029 讲给出噪声传播的分析框架。
  • 把无训练读成零先验：症状是复现时连 PointNav 与检测器都从零训练，成本远超预期。根因是忽视 MOPA 的训练来源。修复：按「PointNav 预训练 + 离线检测器 + 可选微调」三层列出依赖，报告每层的训练数据与算力。

    提示
    监测量示例：检测段用每类召回与误检率；建图段用有效投影率与地图覆盖率；探索段用重采样次数与首目标发现步数；导航段用卡死步数与停止距离误差。反推规则一：发现步数正常但成功率骤降，责任在建图或导航（目标进了地图但走不到）。规则二：地图覆盖率低且重采样次数高，责任在探索。对照实验：固定探索与导航，把真值语义换成 Detic 预测，预期成功率与 SPL 同时下降，失败集中在目标类别检测召回低的 episode 子集；若观察到建图段覆盖率同步下降，则误差从检测传播到了地图，需要区分「漏检」与「投影失败」两类原因。

小结

  • 模块化 ObjectNav 的四段式：检测、建图、探索、PointGoal 规划与执行；统一接口是相对坐标下的目标点，规划层只负责在任务目标与探索目标之间切换。
  • MOPA（Raychaudhuri 等 2023）在 MultiON 2.0 上系统对比模块：预训练 PointNav 成功率 81，超过 SPF 的 76、BFS 的 21 与 FMM 的 18，且整轮评测 12 小时对 48 小时；Uniform 探索成功率 81，超过 ANS 的 76 与 Frontier、Stubborn 的 72。
  • MultiON 2.0 规模：训练 / 验证 / 测试场景 800 / 30 / 70，训练 episode 8.00M，每 episode 8 − n 个干扰物，时间上限 2500 步，αexp = 50 步。
  • 误差链 Psucc ≈ p检测·p建图·p探索·p导航；示意参数 (0.90, 0.95, 0.90, 0.90) 下合成 0.6925。PredSem 在 3ON 的失败分解：未发现 58%、发现未停 22%、停远 20%，探索覆盖是最大缺口。
  • ObjectNav 验证集：OracleSem 64 / 32 与 ModLearn 62 / 32 同档；PredSem 30 / 14 在零训练条件下与 OVRL 33 / 12 接近；无训练声明含 PointNav 预训练、离线检测器与可选检测微调三层来源。
