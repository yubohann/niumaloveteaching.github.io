第五篇 · 真机、Sim2Real 与系统集成

第 090 讲｜OVMM 回顾：0.8%→10.8%

第 089 讲拆完了软件栈，本讲用一场竞赛检验它。NeurIPS 2023 HomeRobot OVMM 竞赛（Yenamandra 等，2024，OVMM 竞赛回顾，arXiv:2407.06939v1）设仿真资格赛与真机决赛两个阶段：仿真赛道 61 支队伍累计提交 368 次，最终挑战榜 21 支队伍留下 79 次提交；使用 DETIC 感知的启发式基线总体成功率为 0.8%，冠军 UniTeam 达到 10.8%，比值 13.5 倍（报告表述为 13 倍），领先第二名 7.6 个百分点。回顾给出两条共性经验：其一，错误检测与恢复决定长程任务能否收敛；其二，感知与决策的整合方式决定噪声如何被消化。真机阶段只有前三名与两条基线各评估 3 次，冠军取得三分之一回合成功，强化学习基线取得三分之二，样本量小到只能定性解读。本讲沿竞赛结构、结果复算、冠军方案、两条共性、真机证据与评测工程六条线回顾，并把教训落成可执行清单。

  • 主题：竞赛回顾 / 指标口径 / 错误检测与恢复 / 感知与决策整合 / 容器化评测
  • 关键公式：Partial = (1/4)·Σk=1..4 SRk；仿真每幕 1250 步、真机 300 步、评测 250 幕
  • 预计学时：80 分钟
  • 前置章节：第 089 讲（HomeRobot 软件栈）

学习目标

  • 理解：说清竞赛的双阶段结构、五个数据分片与三要素指标（总体成功、部分成功、动作步数）各自回答什么问题。
  • 会算：复算 0.8% 到 10.8% 的比值与领先差距，验证部分成功与总体成功的关系，并解释小基数对倍数表述的影响。
  • 会分析：从冠军与前三名方案中提炼错误恢复的可复用结构，把验证信号、触发条件与回退动作写成状态机设计。
  • 会判断：识别真机 3 次评估与仿真 250 幕之间的可比性边界，不把两种口径的数字放在同一张表里排序。
  • 会设计：为开放词汇长程任务设计一套带重试与回退的评测协议，并说明容器化评测与分布式评测的取舍。

背景与动机

第 089 讲展示的是一套「原样就能跑两个世界」的栈，它的基线在仿真里只有 0.8%（DETIC 感知口径）。竞赛的意义在于给出一个受控的比较场：同样的提交接口、同样的场景分片、同样的动作预算，让不同团队把失败原因暴露出来。0.8% 到 10.8% 的改进不是某一个模型换新带来的，回顾明确指出两条共性经验，错误检测与恢复、感知与决策整合，两者都属于系统层设计。本讲先复算数字，再按团队方案拆解这两条经验的实现方式，最后讨论真机与评测基础设施的局限。

与前两讲的边界：088 讲任务与赛道设计，089 讲统一栈的部件与参数，本讲站在「使用者」角度评估栈在真实竞赛压力下的表现。与 091 讲的衔接：竞赛暴露的问题（错误恢复、感知整合、评测工程）正是后续平台基础设施要承接的需求。

核心原理

1. 竞赛结构：两个阶段与五个分片

竞赛分仿真与真机两个阶段，仿真阶段同时充当真机决赛资格赛。仿真平台为 Habitat，场景取自 HSSD 的 60 个场景；公开分片为 train、val、minival，其中 train 与 val 共 38 与 10 个场景，供本地训练与调试；托管在 EvalAI 的分片为 test-standard 与 test-challenge，前者用于公开榜单与论文报告，后者用于决定真机决赛名额且结果保密。每个评测任务在 250 幕上进行，单次运行限时 48 小时，官方评测机型为 AWS EC2 p2.xlarge（Tesla K80 显卡、12 GB 显存、4 核 CPU、61 GB 内存）。

提交物被封装为三个 Docker 镜像：任务镜像预装全部依赖并提供 gRPC 接口；环境镜像在任务镜像上替换私有数据路径并启动环境服务；参赛镜像在任务镜像上加入各自实现，只需实现智能体接口的 act 与 reset 两个方法。评测时环境容器与参赛容器通过 gRPC 交换观测与动作，结果回传榜单。真机决赛沿用同一批参赛镜像，在受控公寓中执行，每支队伍评估 3 次，单次评估允许最多 3 次碰撞，超出即中止并按已完成阶段给部分成功。

3. 共性一：错误检测与恢复

回顾的定性结论是：远距离感知不可靠，长程任务必须持续判断当前子目标是否达成，并在失败时选择重试或回退。基线栈的技能状态机按顺序执行、不重试，一旦某阶段失败，后续动作建立在错误前提上。冠军 UniTeam 的方案是四状态机加验证门：抓取阶段检查物体是否真的被夹起，成功才进入下一阶段，失败则回到探索阶段换位置重试；放置阶段检查物体是否稳定落在容器上。KuzHum 在凝视阶段加入最多 10 次重试，10 次失败后退回导航到物体技能。Rulai 则在导航层加入自行脱困策略，避免卡死在原地消耗预算。三支队伍的共同点是：把「成功信号」当成状态转移的条件，把「失败」映射成明确的回退目标，避免继续无效消耗动作预算。

验证信号的选择需要与平台能力匹配。抓取有夹爪状态传感器与视觉复核可用；放置只能依赖物体与容器的接触与稳定判定；导航到达依赖位姿与视点定义。信号缺失时，队伍采用多帧观测与位置复核代替。论文把「何时重试、如何重试」列为未来研究方向，并建议探索用视觉语言模型自动构造带恢复的行为树，替代人工枚举回退分支。

4. 共性二：感知与决策的整合

所有队伍都把时间花在围绕开放词汇检测模型做工程化改造，回顾给出的第一条核心结论是：现有感知模型是必需的，但单独使用不够好。几个可复用的整合手段如下。按类别分开阈值：UniTeam 发现统一置信度阈值无法兼顾，最终对物体用较低阈值、对目标容器用较高阈值，减少容器误分类。几何过滤：利用深度设定容器高度阈值，剔除把地板误判为桌面的检测。按置信度保留候选：UniTeam 只在鸟瞰图中保存最可能的目标容器，再选择可达且匹配概率最高的一个，避免把物体放到误检的容器上。多模型互补：KuzHum 用微调 YOLOv8 提供框、MobileSAM 提供掩码，再与 Detic 的开词分割合并，任务相关类别覆盖在上层，并用跟踪提升分割稳定性；Rulai 把仿真图像与真实室内数据混合微调检测器，并在 8 个模型中按精度与响应时间选型。全景更新：UniTeam 在赛后尝试定期生成全景图（旋转 360 度拍照、等距柱状变换后拼接，拍摄时把相机转 180 度使其光轴靠近旋转轴以减少拼接伪影），用 OWL-ViT v2 加 MobileSAM 检测分割，按覆盖区域触发更新，缓解相机朝向错过的目标与边缘分类问题。

一个反直觉的细节：置信度不能当作正确性保证。UniTeam 明确报告，目标容器即使预测错误也可能有很高的置信度；感知精度随类别变化，上限由模型决定。工程含义是决策层必须保留多个候选并具备事后纠错能力，不能把最高分当作事实。这一条与第 089 讲的启示互补：地图式累积能压低随机噪声，但压不住系统性误分类。

5. 学习与运动规划的角色

冠军方案几乎没有使用学习：检测用 Detic，其余为运动规划与手工启发式。前三名中另两支做了不同程度的微调（Rulai 的检测微调、KuzHum 的强化学习检查点微调）。回顾的观察是：在本竞赛的时间预算下，把强化学习调通所需的工程投入不低于传统栈，奖励函数调参带来大量问题。KuzHum 的经验尤为具体：放置技能的奖励从稀疏改为鼓励「保持物体在视野内并靠近容器」后一度改善，但进一步延长训练后出现局部最优，智能体在回合一开始就把物体丢下，平均奖励反而更高；团队只能放弃大部分训练结果，采用温和改进的权重。这些证据支持一个实践判断：模块化栈加恢复逻辑是当前开放词汇长程任务的稳健起点，学习模块的价值集中在感知与局部技能，全局行为仍由显式状态机承载。

解读必须克制。每次成功或失败对应三分之一回合，33.3% 与 66.6% 的差异只有一个回合；强化学习基线的 66.6% 与其仿真 DETIC 口径的 0.0% 冲突，原因可能包括真机公寓远小于仿真场景（真机预算 300 步）、任务分布差异与极小样本，不能据此得出「强化学习更适配真机」的结论。可用的结论有两条：仿真名次对真机表现有预测性，冠军是唯一在真机上完成完整回合的队伍；没有任何一支参赛队拥有 Stretch 真机，仿真承担了全部开发工作，说明该仿真栈的开发价值得到验证。回顾也承认，真机评测只有单一公寓、单一机器人，是扩展性瓶颈，建议未来采用分布式评测。另需对齐一处口径差异：同一批基线在原论文的 20 次真机试验中为 15% 与 20%（第 089 讲引用），在竞赛的 3 次评估中为 33.3% 与 66.6%，两套数字来自不同的场景、回合数与执行流程，不能跨协议对照。

7. 评测工程

容器化评测被回顾列为最成功的决定：镜像让同一份策略在仿真与真机、在不同实验室之间运行而不出现依赖问题，还支持主办方把参赛镜像直接拉到真机上运行。配套经验有两条：评测入口应提供任务镜像作为统一基础，只暴露 act 与 reset 这类最小接口；评测资源（每次 48 小时、250 幕）与提交配额（不同分片分别限制）共同控制过拟合。改进建议集中在沟通与评测分布：用实时社区渠道替代邮件列表，用分布式部署扩大真机评测的场景多样性。

错误恢复状态机的接口

设计一套跨任务的恢复结构，需要回答四个问题：每个技能的成功信号是什么、由什么传感器提供、失败时回退到哪个状态、重试上限如何与总预算匹配。以 OVMM 为例，抓取的成功信号来自夹爪传感器与视觉复核，失败回退到找物阶段；凝视的成功信号是目标居中且距离进入臂展，失败先原地重试再回退；放置的成功信号是物体与容器接触并稳定，失败回退到找容器阶段；导航的失败信号是规划不可达或碰撞计数增加，回退到前沿探索。所有重试都占用同一预算，因此上限必须与 1250 步的总量联合标定：凝视 10 次、抓取数次、末端放置小步推进，三者叠加不能耗尽预算。

与第 089 讲的差异：089 讲的是栈的部件与参数，本讲给出该栈在竞赛中必须追加的决策逻辑与评测工程。与第 091 讲的衔接：竞赛回顾留下的三个需求（错误恢复、感知整合、跨实验室评测）将在 Spot 基础设施中看到另一种工程形态。

关键代码与解读

三段代码分别对应回顾的两条共性经验与评测工程：带验证门的状态机、跨帧跟踪、容器化评测循环。均为按论文流程重写的教学实现。

片段 1：带验证门与回退的技能状态机

class OVMMStateMachine:
    """阶段 0 找物、1 凝视、2 抓取、3 找容器、4 放置、5 结束。"""
    def __init__(self):
        self.stage = 0
        self.gaze_fails = 0

    def on_gaze_done(self, object_centered):
        if object_centered:
            self.stage = 2                    # 对准后交给抓取
            self.gaze_fails = 0
        else:
            self.gaze_fails += 1
            # 连续失败达到上限就回退探索，避免在误检目标上耗尽预算
            self.stage = 0 if self.gaze_fails >= 10 else 1
        return self.stage

    def on_grasp_signal(self, holding):
        if holding:
            self.stage = 3                    # 抓取成功才进入找容器
        else:
            self.stage = 0                    # 抓取失败回到找物，换位置重试
        return self.stage

    def on_place_done(self, stable_on_receptacle):
        if stable_on_receptacle:
            self.stage = 5
        else:
            self.stage = 3                    # 放置失败重新定位容器
        return self.stage

解读：（1）每个阶段转移都由外部信号驱动（居中、夹持、稳定接触），状态机本身不猜测结果，这是冠军方案与基线的关键差别。（2）凝视重试上限取 10 次，来自 KuzHum 的公开配置；上限与总预算共同标定，过大等于在错误目标上消耗步数。（3）失败回退到「上一个可靠状态」，抓取回退找物、放置回退找容器，保证错误不会被后续技能继承。

片段 2：跨帧检测关联与迟滞确认

def iou(a, b):
    # 轴对齐框交并比：用于把相邻两帧的同一实例关联起来
    x1, y1 = max(a[0], b[0]), max(a[1], b[1])
    x2, y2 = min(a[2], b[2]), min(a[3], b[3])
    inter = max(0.0, x2 - x1) * max(0.0, y2 - y1)
    area = lambda r: max(0.0, r[2] - r[0]) * max(0.0, r[3] - r[1])
    return inter / (area(a) + area(b) - inter + 1e-9)

def track_detections(tracks, dets, iou_thr=0.3, hit_thr=2, score_thr=0.8):
    """连续命中达到阈值，或单帧得分很高，才允许进入决策。"""
    for det in dets:
        best, best_iou = None, 0.0
        for trk in tracks:
            v = iou(det["box"], trk["box"])
            if v > best_iou:
                best, best_iou = trk, v
        if best is not None and best_iou >= iou_thr:
            best["hits"] += 1                 # 关联成功，累计命中次数
            best["box"] = det["box"]
            best["score"] = max(best["score"], det["score"])
        else:
            tracks.append({"box": det["box"], "score": det["score"], "hits": 1})
    # 命中不足的短命轨迹被剔除；高置信度的单帧检测暂时保留
    return [t for t in tracks
            if t["hits"] >= hit_thr or t["score"] > score_thr]

解读：（1）单帧检测直接进入决策是随机误检的主要来源；跨帧关联把「稳定可见」当作进入条件，呼应 KuzHum 用跟踪替代逐帧判决的做法。（2）逐检测匹配是简化实现，多个检测可关联同一轨迹；工程上应加入匹配代价全局求解与轨迹失效管理。（3）双阈值结构（连续命中或高单帧分）保留两种证据：时序稳定性与置信度，两者逻辑或的关系避免高置信真目标被延迟。

片段 3：容器化评测的最小接口与评测循环

class ParticipantAgent:
    """参赛镜像内的最小接口：reset 接收任务，act 返回动作。"""
    def reset(self, episode_info):
        self.goal = episode_info["instruction"]     # 物体与两个容器名
        self.map = None

    def act(self, obs):
        self.update_map(obs)                        # 深度与分割入图
        return self.policy(self.map, self.goal)     # 离散动作或连续航点

def run_episode(agent, server, budget=1250):
    """主办方评测循环：环境在私有镜像，双方经 gRPC 交换观测与动作。"""
    obs = server.reset()
    agent.reset(server.episode_info)
    for t in range(budget):
        action = agent.act(obs)
        obs, done = server.step(action)
        if done:
            break
    return server.metrics()                         # 四阶段率与总体率

解读：（1）接口只保留 reset 与 act，语言、地图、模型全部封装在参赛侧，主办方只保证任务语义与预算一致；这是同一镜像能在仿真与真机复用的前提。（2）预算 1250 步写在评测侧，参赛方不能通过内部截至步数规避失败统计。（3）metrics 返回四阶段累计通过率，与部分成功指标同源；评测侧持有终判权，避免参赛方自定义成功判据。

常见误区

  • 把 13 倍当作绝对性能提升：症状是引用「提升 13 倍」但不提基数。根因是 0.8% 的小基数把比值放大，绝对增量只有 10.0 个百分点。修复：倍数与两个绝对值同时给出，并注明 DETIC 感知口径。
  • 混用两个仿真分片：症状是拿 test-challenge 的 10.8% 与 test-standard 的 6.0% 对比得出「分片导致性能翻倍」。根因是分片场景不同、用途不同，且名次也会变化（Rulai 在挑战榜第 2、在标准榜第 4）。修复：报告时标注分片名与用途，跨分片只做敏感性讨论，不做性能结论。
  • 用真机 3 次评估做方法排序：症状是引用强化学习基线 66.6% 并推断学习优于运动规划。根因是每个成功率对应三分之一回合，且真机公寓规模与步数预算都不同于仿真。修复：真机结果只作定性证据；需要排序时扩充场景与回合数，或改用统计口径（第 096 讲展开）。
  • 把置信度当作正确性：症状是决策层只保留最高分检测，随后在错误容器上放置。根因是开放词汇模型在容器类别上存在高置信度误分类，且各类别精度不均。修复：保留多个候选并按可达性与匹配度重排；对已知易混类别单独标定阈值；加入几何与场景一致性检查。
  • 没有重试上限的错误恢复：症状是加入重试后步数暴涨、总体成功率反而下降。根因是重试次数没有与总预算联合标定，反复在误检目标上消耗动作。修复：为每个技能设置重试上限与回退目标，用总预算做约束求解；监控每阶段平均步数作为回归指标。

  1. 复算：10.8% 与 0.8% 的比值、与第二名的差距，以及冠军部分成功与总体成功的比值；说明三个数字各自适合回答什么问题。★

    比值 13.5（报告写 13 倍），差距 7.6 个百分点，partial/overall 为 3.04。比值回答相对改进幅度，差距回答领先度，partial/overall 回答「推进与完成」的落差。
  2. 用表 1 论证部分成功是先行指标：找出至少两组「部分成功率与总体成功率的排序不一致」的例子，并解释成因。★★
    提示
    启发式基线 partial 17.7 高于 Rulai 的 16.8，总体却为 0.8 对 3.2（相差 4 倍）；启发式 partial 17.7 也高于 GXU-LIPE-Li 的 13.9，总体为 0.8 对 1.6（相差 2 倍）。差别在于末期阶段（找容器与放置）的转化率，前期推进广不等于末端可靠。
  3. 为「抓取失败」设计完整恢复流程：列出验证信号、触发条件、回退目标与重试上限，并给出把上限从 3 次改到 10 次时对总步数与成功率的预测。★★
    提示
    信号：夹爪状态加视觉复核；回退：找物阶段并更换接近位置；上限与 1250 步预算联合估算。上限提高会减少「误检一次就放弃」的损失，但增加每幕步数；预测方向取决于误检比例与预算余量。
  4. 设计一个只用公开分片（train/val/minival）的复现实验：固定基线与预算，消融「错误恢复」与「多帧确认」两个因素，给出实验矩阵、评估指标与通过标准。★★★
    提示
    2×2 矩阵：恢复开/关 × 多帧开/关，各跑 minival 全量并固定随机种子；指标用总体成功、部分成功与平均步数三要素；通过标准预先注册（如恢复模块在 DETIC 输入下使总体成功相对提升不低于 X，且步数增幅不超过 Y%）。同时报告感知来源，禁止真值分割混入。
  5. 分析高置信度误分类为何对容器检测比对物体检测影响更大，并设计两种缓解方案（提示：从放置动作的不可逆性、候选数量与复核成本三个角度）。★★
    提示
    放置一旦执行就难以撤销，容器误判直接导致失败；容器候选通常不止一个，可并行保留并按可达性重排；复核成本低于重试成本时，放置前增加一次近距离确认。方案：候选重排加放置前复核，或对易混容器类别单独训练或标定。

小结

  • 竞赛结构：仿真资格赛加真机决赛，五个数据分片，250 幕与 48 小时评测预算，三个 Docker 镜像经 gRPC 交换观测与动作；仿真阶段从 7 月 12 日到 10 月 20 日共 100 天，61 支队伍提交 368 次，最终挑战榜 21 支队伍 79 次。
  • 结果复算：基线 0.8% 到冠军 10.8%，比值 13.5（报告写 13 倍），绝对增量 10.0 个百分点，领先第二名 7.6 个百分点；部分成功与总体成功之比从基线的 22.1 收窄到冠军的 3.04。
  • 共性一为错误检测与恢复：冠军用四状态机加验证门，抓取与放置都以传感器信号确认后才转移；KuzHum 凝视重试上限 10 次；Rulai 加入自行脱困。重试上限必须与总预算联合标定。
  • 共性二为感知与决策整合：按类别分开阈值、深度几何过滤、按置信度保留容器候选、多模型互补、全景定期更新；置信度不能作为正确性保证，决策层必须保留候选与复核能力。
  • 真机阶段只有每队 3 次评估，UniTeam 33.3%、两条基线 33.3% 与 66.6%，不能据此做方法排序；可确认的结论是仿真名次具有预测性、所有队伍都在仿真中完成开发。
