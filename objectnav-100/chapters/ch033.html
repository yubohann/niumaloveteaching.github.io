第二篇 · 模块化：地图·探索·常识

第 033 讲｜失败模式解剖

平均成功率回答不了「智能体在哪里失败」。本讲用 PIRLNav 对 592 条失败 episode 的人工标注建立八类失败分类学，给出分组统计与修复上界的计算方法，再用 IPPON 的零样本消融与真机失败补上另一侧证据。学完能为任意一份评测日志设计分类器、排出修复优先序，并识别哪些失败账目属于数据集、哪些属于算法。

  • 主题：失败分类学 / 人工标注 / 归因统计 / 修复优先级
  • 关键公式：SR′ = SR0 + (1 − SR0) · Σc wc（修复上界）
  • 预计学时：65 分钟
  • 前置章节：第 032 讲 L3MVN II：真机与零样本泛化

学习目标

  • 能复述八类失败模式的定义与占比，并按数据、感知、执行、跨层、记忆五个层面分组。
  • 会算修复上界：给定基准成功率与各类失败占比，推导逐类修复与累计修复后的成功率上限，并说明独立假设的局限。
  • 会实现失败日志分类器：绕圈、误停与漏检、最后一公里卡滞、跨楼层失败四类规则，并说明判定优先级。
  • 会读 IPPON 消融：贝叶斯滤波缺失导致误停增多、语义引导缺失损失效率、局部采样规划缺失损失成功率，各自对应哪类失败。
  • 能设计失败驱动的改进路线：从分类学选择优先项，给出预期收益、验证实验与风险。

背景与动机

第 032 讲把 L3MVN 的感知瓶颈量化：真值语义分割把成功率从 0.542 抬到 0.664。这个结论回答了一个模块的贡献，却留下一组更大的问题：不同方法的失败是否同质，失败里有多少是算法能修的，修复的先后顺序应该怎么排。成功率与 SPL 是聚合标量，同一条 70% 的成功率可以由完全不同的失败构成支撑，改进方向也随之不同。失败解剖的任务就是把聚合指标拆回结构信息。

目前公开文献里规模最大的一次拆解来自 PIRLNav（Ramrakhya 等，2023，CVPR；榜单名 BadSeed）。该工作在 HM3D-Sem v0.1 的 2000 条验证 episode 上把策略做到 70.4% 成功率，随即对全部 592 条失败 episode 做人工标注，归成八类，并逐类给出修复建议。作为对照，人类在 MP3D 验证集上的成功率为 88.9%（21 类目标、500 步，Habitat-Web 2022 收集的 8 万条演示），当时最好的学习方法是 35.4%，两者相差 53.5 个百分点；这条落差说明导航能力仍有可观空间，也说明「差在哪」值得单独研究。

第二条证据来自 IPPON（Qu 等，2024），它用零样本方法在 Habitat ObjectNav 挑战赛 2023 上拿到 SPL 0.34 与 SoftSPL 0.46，并在消融与真机实验中暴露另一类失败：误停与小目标漏检。两套证据合起来覆盖了训练型与零样本两条路线。本讲的产出直接服务第 034 讲的多楼层推广与第 036 讲的 IPPON 深化：跨楼层失败占 PIRLNav 失败的五分之一，是下一个必须正面处理的结构性缺口。

核心原理

1. 失败分类学的单位与层级

分类的基本单位是 episode，每一条失败 episode 归入一个主导原因，允许标注者记录次要原因但不进入占比统计。设评测集含 N 条 episode，基准成功率为 SR0，失败总数 F = (1 − SR0) · N。第 c 类失败的占比记为 wc = nc / F，满足 Σc wc = 1。

归因层级分五层，从外到内依次为：数据层（标注缺失、导航网格缺陷）、跨层结构层（目标在别的楼层）、感知层（漏检、语义混淆）、执行层（最后一公里、碰撞）、记忆层（绕圈、探索覆盖不足）。层级决定修复的责任方：数据层由数据工程处理，跨层与记忆层由策略与系统设计处理，感知层的上限由模型决定。把层级写进表格，可以避免把数据问题误记为算法问题。

2. PIRLNav 的八类失败

PIRLNav 的实验设置：HM3D-Semantics v0.1，6 类目标（chair、couch、potted plant、bed、toilet、tv），2000 条验证 episode，成功判据为停止时距目标 1 m 内且原地转头可见，上限 500 步（与挑战赛口径一致）。策略为人类演示行为的克隆预训练加强化学习微调，验证集成功率 70.4%，对应的失败率为 29.6%，592 条失败全部经过人工标注。标注结果如下表，计数列按 592 条折算，显示到两位小数以说明百分比的舍入来源。

3. 修复上界：把百分比换算成成功率空间

失败占比描述构成，修复决策需要的是成功率增量。假设第 c 类失败被完全修复，即该类失败全部转换为成功，成功率的增量为：

ΔSRc = (1 − SR0) · wc 失败率 1 − SR0 乘以该类占比；该式为单类独立修复的增量

若同时完美修复若干类，且各类之间互不重叠，累计上界为：

SR′ = SR0 + (1 − SR0) · Σc ∈ C wc C 为被修复类别的集合；Σ wc ≤ 1 时 SR′ ≤ 1；假设各类失败互斥

代入 SR0 = 0.704、失败率 0.296，按下表的顺序累计修复，得到一串上界。增量一列是单类的独立收益，累计一列是逐类叠加后的上界。

只修复方法侧六类（排除数据层的 36%），上界为 SR0 + 0.296 × 0.64 = 89.34%。三处读法要写清楚。第一，上界不是预测值：修复一类失败的同时可能改变其他类别的分布，例如跨楼层策略上线后，部分「探索失败」会转化为新的失败样本。第二，单类增量与当前 SR0 绑定，换一个基准策略后同一占比换算出的增量不同。第三，累计顺序只影响中间行，不影响总和；把数据层放在最前是为了提醒读者先做数据审计。上界方法的价值在排序，它把「先修哪一类」从直觉变成算术。

4. IPPON 的零样本侧证据：消融与真机失败

PIRLNav 代表训练型路线的失败结构，IPPON 代表零样本路线。IPPON 在 Habitat ObjectNav 挑战赛 2023 标准阶段（1000 条 episode、连续动作）上以零样本方法得到 SPL 0.34、SoftSPL 0.46、成功率 0.54，SPL 相对同场已训练的最好成绩 0.28 高出 21.43%，SoftSPL 相对 0.37 高出 24.32%；同场榜首 SkillTron 的成功率为 0.59。挑战成功率从 2020 年的 14% 升到 2023 年的 59%，感知与检测能力的进步把失败结构整体推向更难的部分。IPPON 的消融给出各类失败的反向证据：去掉某个模块后哪类失败增多，就说明该模块在压制哪类失败。

读法：贝叶斯滤波对应误停这一类失败，投票式建图会把单帧假阳性直接写成高概率体素，导致机器人在错误物体前停止；滤波用多帧后验修正分割的闪烁与不一致。论文报告缺少滤波时「频繁错误终止」，成功率损失 9.0 个百分点，是全部消融项中最大的一项。语义引导对应效率型失败，去掉后 SPL 降到 0.31，典型症状是机器人明知目标类别却仍进入浴室检查镜子与洗手池。局部采样规划对应最后一公里，窄通道与 L 形走廊的直线连接失效时，成功率损失 7.0 个百分点，与 PIRLNav 的执行层失败同类。移动中的俯仰控制对应观测覆盖，提醒感知机会由动作策略创造。

真机实验给出另一组失败样本：ANYmal 足式机器人加机械臂，机载 Jetson Orin 与 i7 计算单元，测试 10 个物体、每个 3 次共 30 次，26 次成功，成功率 0.8667。4 次失败中 3 次来自小目标（学生卡过小，分割网络在近距离才能识别），占 75%；1 次是在目标为螺丝刀时误停在黄色按钮前，占 25%，原因是按钮与预定义常见物体清单都对不上，分割网络把最接近的类别判成了目标。两类失败与仿真侧的消融证据相互印证：小目标漏检属于感知层的召回边界，按钮误停属于预定义物体清单的覆盖边界，而消融中去掉贝叶斯滤波同样会放大误停。

5. 数值算例（Python 实算）

算例一，计数回填。592 条失败按百分比折算得到 159.84、124.32、118.40、71.04、53.28、29.60、23.68、11.84，合计 592.00，与总数严格一致；四舍五入到整数为 160 / 124 / 118 / 71 / 53 / 30 / 24 / 12，合计 592。百分比表可以精确回填计数，说明标注是完备划分，没有多重归类的重复计数；若你的评测日志出现合计超过 100% 的分类，先检查是否把同一 episode 记入了多个主类。

算例二，修复上界链。取 SR0 = 0.704，逐类修复的增量依次为 7.99、6.22、5.92、3.55、2.66、1.48、1.18、0.59 个百分点。前两项合计已经把上界推到 84.61%，前三项推到 90.53%。标注缺失与跨楼层两类合计占失败的 48%，任何整体改进计划忽略这两项都会触到收益上限。方法侧单独修复的上界为 89.34%，意味着即使把全部策略与感知问题清零，数据层不修时的成功率也不会超过这个数。

算例三，两套体系的失败构成对照。PIRLNav 的感知类失败（识别加语义混淆）占 25%，其中识别失败定义为「看见了却没过去」，与检测召回相关但不完全相同；IPPON 真机失败里小目标漏检占 75% 的失败样本，但样本只有 4 条，置信区间很宽。用二项比例的粗略区间看，0.8667 的 30 次试验标准误约 0.062，95% 半宽约 0.122，真机成功率的不确定范围覆盖 0.745 到 0.989。真机失败统计的样本瓶颈必须显式报告，不能把 3 次小目标失败当作普适占比（第 096 讲展开真机评测方法学）。

6. 适用边界与失效模式

  • 人工标注的主观性：八类之间的边界需要预定义判据，「看见却没过去」与「没看见」的区分依赖轨迹与视野回放；不同标注者对同一 episode 的归类可能不同，报告应附标注协议与仲裁规则。
  • 标注只覆盖单一策略：592 条来自一个成功的训练型策略，失败分布与策略的能力边界绑定；换一个策略或换一个数据集，比例会变，上界方法的算术不变。
  • 上界的独立性假设：跨楼层修复可能顺带修复部分探索失败，识别修复可能改变最后一公里的分布，累计上界应视为乐观界。
  • 数据集版本漂移：HM3D-Sem v0.1 的标注缺失问题在后续版本与数据审计流程中可能已被修正，引用 27% 这一比例时必须标注版本与年份。
  • 零样本侧样本量：IPPON 真机 30 次试验只能支撑失败类型的定性归因，不支持比例外推。
  • 指标口径：PIRLNav 与 IPPON 都遵循各自协议的停止判据与可见性检查，跨论文比较失败占比前先核对判据（第 032 讲已给出 0.1 m 与 1 m 的差异提醒）。

实现思路与设计

失败解剖的工程产出是一套日志、一套分类规则与一张优先级矩阵。日志必须在评测时就采集，事后无法补录；分类规则要可执行、可复算；优先级矩阵把统计结论转成下一个迭代的工作项。

2. 分类规则与优先级

规则按责任层级从上到下匹配，先判数据层与结构层，再判感知与执行，最后落入记忆层兜底。顺序的理由是：数据层证据是确定的，跨楼层证据可由楼层字段直接核验，感知与执行的区分依赖停止状态，绕圈需要轨迹分析，成本最高。

优先级条件归类
1annotation_present 为假且轨迹经过目标实例标注缺失（数据层）
2navmesh_blocked 为真且路径被网格截断导航网格失败（数据层）
3floor_target 为真且 floor_changes 为 0跨楼层导航（结构层）
4已停止，距离不超过 1 m，可见性核验失败识别失败（感知层）
5已停止，距离超过 1 m，且停在同类相似物体前语义混淆（感知层）
6目标附近碰撞次数超过阈值最后一公里（执行层）
7回访率超过阈值绕圈（记忆层）
8其余探索失败（记忆层兜底）
设计决策：分类与修复排序解耦

分类回答「失败是什么」，排序回答「先修什么」。两者用不同表格承载：分类表按层级组织，保证归因责任清晰；排序表按「增量乘以修复成本」组织，允许数据层的低成本修复排在最前。PIRLNav 的统计把数据层推上第一位，与直觉中「失败来自模型」相反，这正是需要两张表的原因。

关键代码与解读

三段代码对应本讲的三件工具：修复上界计算、绕圈检测、失败分类器。输入为评测日志与轨迹，输出为可与论文表对照的统计表。

片段 1：修复上界与累计上界

def repair_bounds(sr0, shares):
    """shares: 有序的 (类别, 失败占比) 列表。返回单类与累计上界。"""
    fail = 1.0 - sr0
    rows, acc = [], 0.0
    for name, w in shares:
        single = sr0 + fail * w            # 单类独立修复的上界
        acc += w
        cumulative = sr0 + fail * acc      # 前缀累计修复的上界
        rows.append((name, round(single, 4), round(cumulative, 4)))
    return rows

SHARES = [("missing_annotation", 0.27), ("inter_floor", 0.21), ("recognition", 0.20),
          ("last_mile", 0.12), ("navmesh", 0.09), ("semantic_confusion", 0.05),
          ("looping", 0.04), ("exploration", 0.02)]
for name, s, c in repair_bounds(0.704, SHARES):
    print(f"{name:20s} single={s:.4f} cumulative={c:.4f}")

解读：（1）上界公式只有两个输入，基准成功率与失败占比，任何评测日志都能套用；（2）累计一列要求占比有序，表头写明顺序，中间值才有意义；（3）输出与论文占比表一一对应，592 条折算值与百分比保证可回填；（4）真实修复存在交互，使用该表时必须在正文或脚注声明「乐观上界」。

片段 2：绕圈检测

def loop_score(trajectory_xy, cell=0.5, window=200, min_visits=3):
    """回访率：窗口内重复进入的格子占访问步数的比例。"""
    if len(trajectory_xy) == 0:
        return 0.0
    tail = trajectory_xy[-window:]                     # 只统计尾段，聚焦失败前行为
    counts = {}
    for x, y in tail:
        c = (int(x // cell), int(y // cell))           # 离散到栅格，吸收定位抖动
        counts[c] = counts.get(c, 0) + 1
    repeated = sum(v for v in counts.values() if v >= min_visits)
    return repeated / len(tail)

解读：（1）窗口取 200 步与 episode 上限 500 匹配，经验上绕圈发生在后半段，窗口过大稀释信号；（2）格子边长 0.5 m 约为两个前向步长，过小会把正常往返误判为绕圈，过大则漏检小范围打转；（3）min_visits 过滤短暂停留，计数方式可在报告里注明；（4）回访率对阈值敏感，第 4 题要求做扫描实验，不能只报一个数。

片段 3：失败分类器

def classify_failure(rec, loop_threshold=0.35, collision_threshold=5):
    """按层级从上到下匹配；rec 为单条 episode 的日志字典。"""
    if not rec["annotation_present"] and rec["passed_goal_instance"]:
        return "missing_annotation"        # 数据层：确定证据优先
    if rec["navmesh_blocked"]:
        return "navmesh"
    if rec["floor_target"] and rec["floor_changes"] == 0:
        return "inter_floor"               # 结构层：楼层字段直接核验
    if rec["stopped"] and rec["stop_distance_m"] <= 1.0 and not rec["stop_visible"]:
        return "recognition"               # 到了却没停对的区域
    if rec["stopped"] and rec["stop_distance_m"] > 1.0:
        return "semantic_confusion" if rec["near_similar_instance"] else "last_mile"
    if rec["collision_count"] >= collision_threshold:
        return "last_mile"                 # 未停止但近目标处反复碰撞
    if loop_score(rec["trajectory_xy"]) >= loop_threshold:
        return "looping"
    return "exploration"

解读：（1）规则顺序就是责任层级顺序，数据层证据先于行为分析，避免把标注问题误记为感知问题；（2）「到达却不可见」与「停在相似物体前却超距」是两类不同失败，前者查可见性与停止取向，后者查语义判别；（3）碰撞规则放在停止规则之后，因为贴近目标时的碰撞与远距离碰撞的含义不同，最近碰撞时刻更精确的版本可替代计数版本；（4）函数返回字符串，直接进入分组统计，报告保留原始标量供人工复核。

常见误区

  • 只看平均成功率不做构成分析：症状是两个方案 SR 接近却给出相同的改进计划。根因是聚合指标丢掉了失败结构。修复：评测流水线固定输出分类统计，把失败构成写进实验报告模板。
  • 把数据问题记到算法账上：症状是团队反复优化策略却触到收益上限。根因是标注缺失与网格缺陷合计 36% 的失败不具备策略可修复性。修复：训练前运行数据审计，生成期过滤无效 episode，报告中区分数据层与算法层失败。
  • 误停与漏检混为一谈：症状是调整停止阈值后两类错误此消彼长，指标不升。根因是误停（假阳性）与漏检（假阴性）方向相反。修复：分开统计；误停查分割假阳与贝叶斯融合，漏检查召回与小目标距离。
  • 失败日志字段缺失：症状是事后无法分类，只能人工看视频。根因是评测时未采集停止距离、可见性、碰撞与轨迹。修复：把日志 schema 纳入评测器接口，跑分即落盘，禁止只存标量指标。
  • 忽略跨楼层分层：症状是单层测试通过而真实住宅失败率上升。根因是评测集缺少跨层 episode 或未按楼层拆分。修复：按是否跨层分层报告，缺失楼层标注的数据集应在数据卡中声明（第 034 讲处理策略侧）。

小结

  • PIRLNav 在 HM3D-Sem v0.1 的 2000 条验证 episode 上标注 592 条失败（29.6%），八类占比为标注缺失 27%、跨楼层 21%、识别 20%、最后一公里 12%、导航网格 9%、语义混淆 5%、绕圈 4%、探索 2%。
  • 按层级分组：数据 36%、跨层 21%、感知 25%、执行 12%、记忆 6%；方法侧内部跨楼层 32.81% 与识别 31.25% 并列第一梯队。
  • 修复上界 SR′ = SR0 + (1 − SR0) Σ wc：逐类修复可把 70.4% 推到 78.39%、84.61%、90.53%，只修方法侧的上界为 89.34%；该式是乐观界，只用于排序，不做预测。
  • IPPON 提供零样本侧证据：去贝叶斯滤波成功率 −9.0 个百分点（误停），去语义引导 SPL 相对 −8.82%（效率），去局部采样规划成功率 −7.0 个百分点（最后一公里）；真机 30 次试验成功 26 次，失败为小目标漏检 3 次与误停 1 次。
  • 工程三要素：评测时落盘的失败日志、可复算的分类规则、按增量与成本排序的修复矩阵；分类责任与修复顺序分表管理。
