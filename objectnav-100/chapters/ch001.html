第一篇 · 任务、仿真与评测地基

第 001 讲｜ObjectNav 是什么：形式化与共识

本讲把 ObjectNav 从一句话描述写成可执行的 POMDP 与评测判据：目标以类别词给定，智能体在未见环境中搜索任一实例，成功由 STOP、可通行位置、1 米距离壳与可见性共同判定。口径来自 Batra 等（2020）的共识文档，它是全书后续所有数字得以互相比较的前提。

  • 主题：任务定义 / POMDP 形式化 / 评测共识
  • 关键公式：SPLi = Si · li / max(pi, li)
  • 预计学时：60 分钟
  • 前置章节：无（本课程从这里开始）

学习目标

  • 能复述 ObjectNav 的任务三要素：目标按类别词给定、环境为未见场景、成功按停止时的状态判定。
  • 能写出 ObjectNav 的 POMDP 实例 ⟨S, A, T, R, Ω, O, γ⟩，并逐项说明其物理含义与适用边界。
  • 能对任意一条停止记录逐条核验共识文档的四条成功条件，并计算该 episode 的 SPL。
  • 能用对比表说清 ObjectNav 与 PointNav、VLN 在目标、观察、评测三方面的差异，并解释差异的设计动机。
  • 能识别口径不一致造成的实验不可比问题，并在实验配置中固化评测版本与参数。

背景与动机

具身导航的任务谱系在 2018 年被系统地梳理过一次。Anderson 等（2018）的评测共识按目标的描述方式把导航任务分成三类：PointGoal 的目标是空间中的坐标点，ObjectGoal 的目标是语义上可区分的对象，AreaGoal 的目标是语义上可区分的区域。该文档还留下一套被广泛采用的建议：用 SPL（Success weighted by Path Length，按路径长度加权的成功率）衡量效率，用 STOP 动作让智能体显式宣布 episode 结束。

此后语义目标导航的研究迅速增多，同名的 ObjectNav 出现了多种互相不一致的实现。分歧集中在三处。其一，成功如何定义：到物体中心还是到物体表面，要不要在停止时可见。其二，本体如何规定：本体半径取多大，一次转身取多少度。其三，环境用什么：游戏引擎合成的房间还是真实空间的三维扫描。这些看似低层的细节会直接改变实验结论，同一算法在不同解释下可以得出方向相反的对比。Batra 等（2020）为此组织多机构工作组，写成 ObjectNav 共识文档，对评测判据、本体参数、环境特征给出建议，并在 2020 年 CVPR 具身 AI 工作坊的 Habitat 与 RoboTHOR 挑战中实例化。本课程以这份文档为任务地基。

本讲解决三个问题：把一句话的任务描述写成精确的 POMDP；把「找到并停止」写成可复现的四条件判据；划清与 PointNav、VLN 的边界。术语从本讲冻结：SR、SPL、成功区、有效视点、oracle 可见性。后面九十九讲的方法、数字与榜单解读都引用这里建立的口径；第 002 讲展开任务家族谱系，第 003 讲深入成功判据的边界样例，第 004 讲专门处理 SPL。

核心原理

1. 一句话定义与三个约束

ObjectNav 的定义可以压缩成一句话：智能体被初始化在一个未探索环境的随机位置与朝向，要求找到以类别词指定的一个物体实例，并导航到它。例如「找一把椅子」（Batra 等，2020）。展开成可执行的表述，有三个必须写明的约束：

  • 目标按类别指定：指令是「chair」这样的类别词，任意一个该类实例都算数。指定具体实例（「this chair」）属于另一类任务，第 002 讲讨论。
  • 环境为未见场景：训练与测试的场景不重叠，评测衡量的是在新建筑中的搜索能力。
  • 成功按停止时刻的状态判定：智能体自主决定何时停止，判据只看停止位置与位姿，与它途中是否经过目标、看得是否仔细无关。

共识文档的立场值得单独说明：寻找物体是与物体交互的第一步。打开容器、抓取物体、回答问题都以此为前置能力，因此评测应测量「导航到物体」的能力，并把检测质量与框选质量排除在外。这一刀切开了导航与感知的评测职责，也让 ObjectNav 成为可与其他导航任务横向比较的基准。

2. POMDP 形式化

ObjectNav 在形式上是一个部分可观测马尔可夫决策过程（Partially Observable Markov Decision Process, POMDP）。采用 POMDP 建模的理由有三条：目标实例的位置在初始时刻未知；目标类别需要语义识别与记忆，单帧观察无法提供；真实化设置下定位存在噪声。形式化如下：

⟨S, A, T, R, Ω, O, γ⟩ 六元组加折扣因子；g ∈ C 为目标类别，作为输入给定，不进入状态

逐项定义，符号与物理含义一并给出：

  • 状态 s ∈ S：s = (p, ψ, κ; M; 𝒪)。p = (x, y, z) 为本体位置，ψ 为航向角，κ 为相机俯仰角；M 为场景几何（墙面、地板、家具网格）；𝒪 = {(ok, ck, Bk)k=1..K} 为实例集合，每个实例含实例标识、类别标签与三维包围盒。智能体不可直接读取 𝒪 与实例位置，这正是部分可观测的来源。
  • 动作 a ∈ A：六个离散动作，前向 0.25 m、左转 30°、右转 30°、抬头 30°、低头 30°、STOP（Batra 等，2020 的 2020 挑战实例）。动作是状态相关的：碰撞时位置不变，2020 起禁止沿障碍物滑动。
  • 转移 T(s′ | s, a)：在给定场景与动作下确定性执行，s′ = f(s, a)；碰撞触发时 s′ = s。随机性留给真实部署与噪声模型，共识的仿真口径本身无致动噪声。
  • 观察 o ∈ Ω：o = (IRGB, ID, u)。IRGB 与 ID 为同步的彩色与深度图，2020 挑战取 640 × 480、水平视场 79°、深度裁剪 0.5 至 6 m；u = (Δx, Δy, Δz, Δψ) 为 GPS+Compass 给出的、相对 episode 起点的位置与航向。起点位姿由此定义了该 episode 的坐标系。
  • 观察模型 O(o | s)：理想化模型，除三维重建本身存在的瑕疵外不注入传感器噪声。深度量程与视场是硬约束，量程外与视场外的信息在理论上不可得。
  • 奖励 R：评测口径下 rt = 1 当且仅当 episode 以成功终止，其余时刻为 0。训练时常加入逐步惩罚或奖励塑形，那属于算法设计，不改变 SR 与 SPL 的定义。共识文档有意不规定奖励，把「任务是什么」与「怎么训」分开。
  • 折扣因子 γ：只在强化学习训练中使用，评测指标不含 γ。

智能体是一个条件策略，条件是观察历史与目标类别：

π(at | o≤t, g) o≤t 为到 t 时刻的观察历史；g 为类别词；策略需要记忆，因为目标大多不在当前视野

在信念层面，智能体维护对状态的后验。设 bt(s) = P(st = s | o≤t, a<t, g)，标准信念更新为：

bt+1(s′) ∝ O(ot+1 | s′) · Σs∈S T(s′ | s, at) · bt(s) 预测步（对 T 求和）与校正步（乘 O）交替；∝ 表示归一化常数使信念和为 1

目标类别固定，因此信念真正需要维护的是「类别 ck = g 的实例可能位于何处」。第二篇的语义地图方法把这个信念显式画在栅格或图上，第三篇的端到端方法把信念隐式压进循环网络状态。两条路线解决同一个推断问题，本讲只建立问题本身。策略的优化目标为：

π* = argmaxπ Eπ[ Σt=0T γt rt ] T 为 episode 终止时刻；评测时 γ = 1，目标退化为成功概率与路径效率的联合表现

3. 成功判据：四条同时成立的条件

共识文档给出的成功判据是四条条件的合取，逐条如下（Batra 等，2020）：

  • 意图（Intentionality）：智能体发出 STOP 动作，表示它认为已经到达目标。没有 STOP 的轨迹一律记失败，无论它当时距目标多近。
  • 有效性（Validity）：停止位置对智能体尺寸与环境约束而言可通行。仿真中真实导航轨迹自动满足；对网格上随机采样的点、或真机上报坐标经定位误差投影后的点，这一条需要单独核验。
  • 邻近（Proximity）：智能体位置（取质心之类的参考点）到物体表面的欧氏距离落在给定距离壳内。壳的尺寸随机器人尺寸与伸展范围调整，共识建议以 r = 1 m 为起点，并预计随研究进展收紧。物体表面可用轴对齐或定向三维包围盒近似，以提高计算效率。
  • 可见性（Visibility）：物体落在智能体视野内。若实施严格可见性，共识建议从宽松口径起步，物体至少占 1 个像素。另一条路线是 oracle 可见性：假设存在一个 oracle，可在不改变智能体位置的前提下（原地转头、调整相机俯仰）把物体最优地框入视野；此时目标是到达「能看见」物体的位置，停止姿态是否正对物体不影响判定。oracle 可见性是「已经足够接近、可以交接给交互模块」的代理，适合把研究焦点放在找路上。

2020 年 Habitat 挑战把上述判据操作化为可计算的集合。物体定向包围盒 1 m 范围内的地面点中，可通行且 oracle 可见的点组成有效视点集合，全体有效视点构成成功区；有效视点以本体半径之半 Ragent/2 = 0.09 m 的网格采样。episode 判成功当且仅当 STOP 时智能体位置距最近有效视点的测地距离不超过 0.1 m。RoboTHOR 2020 挑战则采用「目标在 1 m 内且位于相机视野中」的严格口径，真机阶段用外部定位模块测量距离并人工核对可见性（Deitke 等，2020）。两套挑战共用同一份高层判据，具体操作化随平台不同，这正是共识文档要求实验者写明实现细节的原因。

4. SPL 与 ObjectNav-SPL

评测同时报告成功与效率两个维度。成功率 SR = (1/N) Σ Si，效率由 SPL 给出：

SPLi = Si · li / max(pi, li)，  SPL = (1/N) Σi SPLi Si ∈ {0,1} 为成功指示；li 为起点到最近实例的最短路径长度；pi 为实际路径长度；max 防止 li > pi 时超过 1

ObjectNav-SPL 与 PointNav-SPL 的唯一区别在 li 的取法：最短路径算到离起点最近的实例。这个细节会显著改变数字。设智能体在 chair1 旁出生，到 chair1 的最短路径 l = 5 m；它一路走到远处的 chair2 才停止，实际路径 p = 24 m。episode 判成功（找到了椅子），SPL = 5 / 24 = 0.208。若实现错误地把分母改为所找到实例的路径 l = 20 m，SPL 会虚高到 20 / 24 = 0.833，相差 4 倍。榜单复现时这一处错误足以让数字与官方不可比。

共识文档同时列出了 SPL 的四个已知局限，前三个直接影响实验设计：

  • 失败不等价：走到距目标 (r + ε) 处停止，与从头到尾不动，同样记 SPL = 0，指标不反映部分进展。
  • 高方差：Si 是二值量，若停点因致动噪声在阈值两侧摆动，Var(SPL) ≈ p(1 − p) · [ (1/N) Σ SPLi ]²。取 p = 0.5、E[SPL] = 0.4，方差为 0.04，标准差 0.2，等于均值的一半。
  • 不惩罚原地转向：pi 只累计移动距离，智能体可以每步原地转 360° 做全景扫描，动作开销增加而 SPL 不变。
  • 不能跨数据集比较：最优路径越短，留给智能体的容错越小，不同数据集的 SPL 数值不可直接并排。

这些局限后来催生了 SoftSPL 等补充指标（第 005 讲），但共识文档的立场明确：新指标应与 SPL 并列报告，成功率的定义保持不变。

5. 与 PointNav、VLN 的边界

ObjectNav 的很多设计只有放进任务家族对照中才看得清。三类任务的观察、目标与评测差异整理如下：

三处差异值得展开。第一，目标的信息量决定探索难度。PointNav 拿到坐标后，剩下的主要是定位与避障；ObjectNav 只拿到一个类别符号，必须先推断「椅子通常出现在哪里」，探索策略成为性能瓶颈。第二，参考路径的来源决定指标含义。ObjectNav 与 PointNav 用 oracle 最短路径做分母，衡量的是相对最优效率；VLN 用人类示范做参照，衡量的是对指令的忠实程度，因此 VLN 报告导航误差 NE 与 oracle 成功率 OSR。第三，观察假设决定哪些方法可用。R2R 的智能体在预先建好的导航图上移动（平均每图约 117 个视点），不使用定位传感器；ObjectNav 的智能体连续移动并使用 GPS+Compass，后续研究常把定位去掉以逼近真机。方法移植时必须先核对观察与动作假设，这是第 016 讲的主题。

R2R 的细节由 Anderson 等（2018）给出：21,567 条众包指令，成功判据为停止点与终点的导航误差小于 3 m，动作空间为左、右、上、下、前、停止六种，前向动作跳到视野中心最近的候选视点。指令跟随的方法与数据在 VLN 课程中展开，本课程只在边界处引用。

6. 数值算例：成功区几何与动作口径

先算成功区的面积。设物体足迹为 0.6 m × 0.6 m 的矩形，到表面距离不超过 r 的点集是「矩形外扩圆角」区域，面积为 A + P·r + πr²，其中 A 为底面积、P 为周长。代入 A = 0.36 m²、P = 2.4 m：

  • r = 1.0 m：0.36 + 2.4 + 3.1416 = 5.90 m²，占 4 m × 4 m 房间的 36.9%；
  • r = 0.5 m：0.36 + 1.2 + 0.7854 = 2.35 m²，占同一房间的 14.7%。

半径减半使成功区缩小到原来的 1/2.52。这解释了共识文档把 1 m 定义为「起点、日后收紧」的原因：它直接控制任务的判定宽容度，收紧后同样的轨迹会有相当比例从成功翻转为失败。以 0.09 m 网格采样成功区，单个物体最多可产生约 5.90 / 0.09² ≈ 729 个候选点，再经可通行与 oracle 可见性过滤，剩下的才是有效视点。

再算传感器与动作的几何。水平视场 79° 对应 640 像素，即 8.10 像素/度；1 像素约 0.1234°。在 1 m 距离上，宽 2.15 mm 的物体即可占满 1 个像素，0.5 m 宽的物体张角 28.07°、约 227 像素。可见「至少 1 像素」的初始口径非常宽松，它的作用是先保证判定可复现，再留给后续研究收紧。动作侧，30° 转向转满一圈需 12 个动作；若沿用 2019 年及更早的 10° 口径则需 36 个，扫描成本差 3 倍。水平视场 79° 时，全向覆盖至少需要 5 个朝向（4 × 79° = 316° 不足 360°）。前向步长 0.25 m 与 750 步的最短动作路径上限相乘，对应全前向 187.5 m，而 MP3D 场景内最短路径的测地距离量级为米到数十米，上限对正常 episode 不构成约束，只用于剔除异常长程样本。

本体参数的变化同样可以量化。2019 年 Habitat 把智能体建模为半径 0.10 m、高 1.5 m 的理想圆柱，体积 0.0471 m³；2020 挑战为对齐 LoCoBot，改为半径 0.18 m、高 0.88 m，体积 0.0896 m³，为前者的 1.90 倍。footprint 直径从 0.20 m 增到 0.36 m，窄通道的通过性明显变差，智能体必须更早绕行。此外，成功半径 1 m 减去本体半径 0.18 m，得到边缘净距 0.82 m；深度裁剪下限 0.5 m 低于停止距离，物体在判定时刻处于深度有效量程内。

统计结果：SR = 6 / 10 = 0.60；SPL = (0.7368 + 0.5 + 0.45 + 0.5333 + 1.0 + 0.8) / 10 = 0.402。只看成功 episode，平均 SPL 为 4.0201 / 6 = 0.670，成功与高效之间存在明显落差。第 3 条 d = 1.20 展示邻近条件的失败；第 4 条失败于有效性，这一条在仿真轨迹中通常自动满足，对真机上报坐标或网格采样点才有区分度；第 6 条距离只有 0.40 m 却因遮挡不可见而失败，说明邻近与可见性必须分开核验；第 7 条走到了 0.75 m 却不发 STOP，按判据记零，这正是意图条件的意义。第 5 条 d = 1.00 恰好压线通过。把它的 d 改为 1.01，SR 降为 0.50，SPL 降为 0.357，一条 episode 的 1 cm 差异足以移动两个统计量，可见判定边界与方差控制必须写进评测协议。

8. 为什么这样设计：共识的取舍逻辑

把共识文档的设计动机逐条摊开，可以看清每条规则排除的是什么：

  • 类别级目标：考察跨实例的通用识别与搜索能力；实例级目标留给 ImageNav 与 InstanceImageNav。
  • 未见环境：防止记忆场景布局，训练与测试场景分离是硬要求。
  • oracle 可见性：把「找路」与「框选物体」解耦，使导航模块可以独立评测；严格可见性路线并用 1 像素下限，先保证可复现。
  • 1 m 距离壳可收紧：判定宽容度与机器人尺寸、伸展范围挂钩，留出版本演进的接口。
  • 离散动作加差分驱动：移除低层控制（关节力矩、轮速）的难度，同时不允许「传送到厨房」这类使决策退化的动作。
  • 传感器理想化：先聚焦视觉感知与决策，避免多传感器融合一起进入评测；定位传感器可以给，真机化研究再逐项去除。
  • 禁止滑动：Kadian 等（2019）发现允许沿墙滑动会让学到的策略借非可通行区域「穿墙」，在真实机器人上因碰撞传感而失效；关闭滑动恢复了 sim2real 的意义。
  • 真实扫描环境：物体与空间的布局接近现实，使仿真结果对真机迁移有参考价值。

边界也要说清。1 m 半径对大型家具（床、沙发）与小件物体（杯子）的含义不同，前者容易触发、后者需要更精确的接近；1 像素可见性几乎不构成约束；SPL 不能跨数据集比较；2020、2021、2022 各年的挑战页在类别数、场景集与动作空间上持续演进（第 013、019 讲）。本讲冻结的是 2020 共识的任务骨架，后续讲次只在此骨架上叠加版本差异。

把共识落到工程，需要三件东西：一份自包含的 episode 记录、一个与记录解耦的评测器、一套写入配置的口径清单。episode 记录的最小字段如下。

设计决策：成功区预计算进 episode

若在评测时即时计算成功区，评测器需要重新采样网格、做可见性射线测试，不同实现会得到不同的有效视点集合，榜单数字随之漂移。把有效视点连同 episode 一起冻结，评测退化为最近邻查询，任何人重放同一条轨迹得到同一判定。代价是数据集生成成本高，但对基准的可复现性是必要投入。

设计决策：参考路径按动作序列存储

SPL 的分母必须与动作空间和几何一致。只存欧氏距离会低估绕行成本，在大房间与多房间场景中偏差最大；存动作序列还能顺带支持第 004 讲的 SPL 边界检查与第 005 讲的 SoftSPL 计算。750 步上限正是对动作序列长度的约束。

口径清单必须随实验报告

一份 ObjectNav 实验结果至少需要注明：共识版本与年份、场景集与划分、目标类别数、本体参数、动作空间、传感器配置、成功半径、可见性路线、停止容差、最短路径口径（最近实例）。缺少任何一项，与公开榜单的对比都不成立。

关键代码与解读

以下片段实现本讲的两个核心约定：四条件成功判定与 ObjectNav-SPL。接口风格参照 Habitat 评测体系的公开设计，字段名做了教学简化。

片段 1：成功判定与 SPL

def is_success(rec):
    """Batra 等（2020）四条件：意图、有效、邻近、可见。"""
    if not rec["stopped"]:                 # 意图：没有 STOP 一律失败
        return False
    if not rec["stop_navigable"]:          # 有效：停点必须可通行
        return False
    if rec["distance_m"] > 1.0:            # 邻近：到物体表面/包围盒的距离壳
        return False
    if not rec["oracle_visible"]:          # 可见：oracle 可把物体框入视野
        return False
    return True

def objectnav_spl(rec):
    """SPL_i = S_i * l / max(p, l)；l 取到最近实例的最短路径。"""
    s = int(is_success(rec))
    l, p = rec["l_shortest_m"], rec["p_taken_m"]
    return s * l / max(p, l)

解读：（1）四条条件是全称合取，检查顺序任意；这里按判定成本从低到高短路，可通行与可见性来自预计算字段，查询代价低。（2）邻近条件的边界是闭区间：distance_m = 1.00 通过，1.01 失败，改动阈值会连带改变 SR 与 SPL。（3）l_shortest_m 由数据集提供，指向离起点最近的实例，与智能体实际选择的实例无关；自行用「找到的实例」重算会系统性抬高 SPL。（4）max(p, l) 防止 l > p 时结果超过 1，例如轨迹经过异常路径或距离字段口径不一致的情形。（5）函数返回单条 episode 的 SPL，批次均值才是报告的 SPL。

片段 2：episode 过滤

def keep_episode(num_viewpoints, gd_m, ed_m, shortest_action_len):
    """数据集侧过滤：无有效视点、过易、超长的 episode 不入库。"""
    if num_viewpoints == 0:
        return False                       # 该实例没有可停靠的成功位置
    if gd_m / max(ed_m, 1e-6) < 1.05:
        return False                       # 测地路径接近直线，任务过易
    if shortest_action_len > 750:
        return False                       # 最短动作路径超长，资源与统计都吃亏
    return True

解读：（1）有效视点为空说明该实例无法在 1 m 壳内找到可通行且可见的停靠点，该实例整体剔除，避免做出无法成功的 episode。（2）测地与欧氏之比接近 1 意味着直线可达、绕行极少，这类 episode 不区分探索能力，用 1.05 的下限过滤。（3）750 步按动作计数，转向也占步数，因而比「距离/步长」的直觉更严格。（4）三个阈值都是数据集级口径，改动后生成的 episode 集合变化，任何跨版本数字对比都需要重新验证。

常见误区

  • 距离算到包围盒中心：症状是 SR 与官方榜单出现系统性偏差，大件家具附近偏差最大。根因是邻近条件定义在「到物体表面」的距离上，中心距离要再加物体的半尺寸。修复：统一在包围盒表面（或定向包围盒）上取最近点，并把该口径写进评测文档。
  • 可见性口径混用：症状是本地复现的数字比论文高或低一截，轨迹本身却看不出问题。根因是论文用 oracle 可见性、复现代码用停止姿态的严格可见性，两者对停止朝向的要求不同。修复：先读论文与代码的判定函数，再决定用哪条路线；两条路线都跑一遍，把差值当作口径敏感性报告。
  • 保留滑动或更换碰撞模型：症状是训练曲线优于公开结果，真机部署迅速失败。根因是沿墙滑动允许策略穿越非可通行区域，等效路径变短而 SPL 虚高。修复：按共识关闭滑动，并在配置中显式固定碰撞参数，实验报告注明。
  • 最短路径取错实例：症状是 SPL 比官方复现值高一大截，SR 却一致。根因是 li 应取到离起点最近实例的路径，实现里改用了被找到实例的路径；文中示例的差距可达 4 倍。修复：检查数据集 info 字段的来源，用固定 episode 做单元测试，断言 SPL 不高于用最近实例计算的数值。
  • 跨任务套用阈值：症状是把 R2R 的 3 m 或 PointNav 的点距离阈值搬到 ObjectNav，SR 严重虚高。根因是三个任务的成功判据服务于不同的目标类型，判据混用改变了任务本身的难度。修复：评测器只接受 ObjectNav 四条件，阈值作为配置项显式传入并记录版本。

小结

  • ObjectNav 的三要素：类别词目标、未见环境、按停止时刻判成功；评测只测导航到物体，与检测质量解耦。
  • POMDP 实例 ⟨S, A, T, R, Ω, O, γ⟩ 中，目标类别作为输入给定；六动作、RGB-D 加定位、理想化观察与稀疏成功奖励构成 2020 口径。
  • 成功判据为四条件合取：STOP、可通行、到表面距离 ≤ 1 m、可见性（oracle 或至少 1 像素）；Habitat 2020 操作化为停止点距最近有效视点 ≤ 0.1 m。
  • SPL 的分母取到最近实例的最短路径；失败不等价、高方差、不罚转向、不可跨数据集四个局限在实验设计中必须正面处理。
  • 与 PointNav 的差别在目标信息量，与 VLN 的差别在目标模态与参考路径来源；三者的成功判据不可混用。
