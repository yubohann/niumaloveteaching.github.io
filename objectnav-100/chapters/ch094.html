第五篇 · 真机、Sim2Real 与系统集成

第 094 讲｜足式平台：Co-NavGPT / MFNP

第 034 讲与第 035 讲分别讲了 MFNP 与 Co-NavGPT 的方法面，并注明第 094 讲会复核平台层；本讲兑现这个承诺。Co-NavGPT（Yu 等，2023，多机视觉语义导航，arXiv:2310.07937）在 HM3D v0.2 的 1000 条 episode 上把成功率做到 0.666，并已迁移到两台 Unitree Go2：RealSense D455 与 Livox Mid-360 建点云，FAST-LIO2 定位，GICP 做初始对齐，工作站 RTX 4090 承担检测与视觉语言模型推理，端到端约 5 FPS。MFNP（Zhang 等，2024，多楼层零样本目标导航，arXiv:2409.10906）在仿真把 HM3D 成功率推到 58.3，真机用 Unitree Go1-Edu：双目鱼眼与 IMU 采集，数据上传云端由 RTX 4090 工作站推理，爬梯由本体 SDK 承担，仅改动输入图像尺寸。本讲把两套系统放进同一张足式适配清单：定位、外参、时间同步、动作接口、计算分层、安全与恢复逐项对照，实算重规划周期、窗口预算与成功率增量，并划清定性演示与统计证据的边界。

  • 主题：足式真机 / 多机协作 / 多楼层 / 平台适配 / 计算分层
  • 关键公式：NMFNP = w1 f(t) + w2 Oexplored/Ototal + w3 (1 − Et) + w4 PLLM；f(t) = (500 − t) / 500
  • 预计学时：85 分钟
  • 前置章节：第 093 讲（VLFM on Spot：办公楼真机）

学习目标

  • 复述：说清两个系统在足式平台上的硬件与软件栈，从传感器、定位、建图到控制与计算放置。
  • 会算：复算 Co-NavGPT 相对四个基线的成功率、SPL、DTG 增量与百分比，复算 MFNP 的窗口预算与触发子集增量。
  • 会设计：写出一张足式适配清单，覆盖定位、外参、时间同步、动作接口、楼梯、计算分层、安全与日志。
  • 会判断：区分仿真统计证据与真机定性演示，识别 0.1 m 判据与挑战 1 m 判据、团队指标乐观偏差两类口径问题。
  • 会迁移：把第 034、035 讲的方法层结论与第 093 讲的单层限制放进同一张平台对照表，说明各自缺失的接口。

背景与动机

方法在仿真里成立，与系统在四足平台上成立，中间隔着一组平台问题。足式机器人的优势是能走楼梯、跨门槛、适应地毯与室外小台阶，恰好覆盖第 093 讲暴露的单层限制与第 033 讲统计的跨层失败；代价同样明确：定位依赖雷达惯性里程计，仿真真值位姿在真机上不存在；执行依赖本体 SDK 的速度接口，离散动作只存在于仿真侧；算力受载荷与散热限制，长距离行走还有打滑与漂移。把方法放到足式平台，必须逐项回答「谁来提供位姿、谁来执行动作、算力放在哪、失败后怎么恢复」。

本讲选择的两篇论文恰好覆盖两种平台架构。Co-NavGPT 把多机协作搬到两台 Unitree Go2，感知与定位在机上、重算力在工作站，验证了多机语义导航的实时性；MFNP 把多楼层策略搬到 Unitree Go1-Edu，数据上传云端计算，爬梯交给本体 SDK，验证了跨层流程的可行性。两者真机部分都没有给出成功率统计，因此本讲的主要工作是：把方法层的数字与平台层的证据分开归档，并给出复现所需的适配清单。课程位置上看，本讲与第 092 讲的技能编排、第 093 讲的单机搜索共同构成第五篇「真机三要素」：编排、搜索、平台。

核心原理

1. 两套系统的方法面回顾

Co-NavGPT 的任务设定为多机视觉目标导航：n 台机器人从同一位置、不同朝向出发，搜索同一类别目标；动作空间为六项离散动作（前进 0.25 m、左右转 30°、抬头、低头、停止），每台机器人最多 500 步，停止时距目标 0.1 m 以内记为成功；任一台机器人成功则整条 episode 成功（Yu 等 2023，第 3.A 节）。地图分两层：各机的 RGB-D 观测经开放词汇检测与类别无关分割后投影为局部点云，再按位姿合并成全局三维点云，并用 DBSCAN 去噪；全局点云投影出二维栅格，含障碍与已探索两个通道，前沿由已探索区边界膨胀、减去障碍边界后提取。全局规划器用视觉语言模型（论文配置为 GPT-4o）完成前沿分配：每一步为每个候选前沿生成一张带编号的俯视图，机器人位置用圆圈与编号标出，提示词包含任务、背景、要求与 JSON 输出格式；模型输出每台机器人分配到的前沿编号。重规划周期为每 25 个局部步一次，无可用前沿时在已探索区域随机采样回退点。局部执行用快速行进法（FMM）规划路径，再沿路径取短程目标生成离散动作。

MFNP 的任务设定沿用零样本目标导航：500 步预算、停止时距离小于 0.1 m（Zhang 等 2024，第 3.A 节）。语义地图为三维张量，通道数为 Cn + 5：前四个通道是障碍、已探索区域、当前位置与历史轨迹，随后 Cn 个通道为各类别物体的语义分布，最后一个通道专存楼梯区域。候选探索点从已探索边界与膨胀障碍边界之差中提取，打分沿用代价效用式 S(pi) = B(pi) − α D(pi)；语言模型对候选点排序，若某候选点周围已探索面积与未探索面积之比超过 90% 则剔除，改选次优项，并检测重复选择同一候选点的退化情况。目标检测由语义分割与视觉语言模型双重确认，融合式为 Cconf = β Pseg + (1 − β) Pvlm，用于抑制把壁画误认成电视一类的分割错误。

2. Co-NavGPT 的足式真机栈

真机验证使用两台 Unitree Go2 四足机器人，每台配备 RealSense D455 RGB-D 相机与 Livox Mid-360 激光雷达（Yu 等 2023，第 4.B 节）。定位由雷达、IMU 与 FAST-LIO2 承担；相机与雷达做外参标定，把深度数据对齐到全局系；探索开始前用广义迭代最近点（GICP）计算两机之间的初始位姿对齐，以 0 号机的初始坐标系为全局参考。感知侧沿用仿真配置：YOLOv8 检测、Mobile-SAM 分割、DBSCAN 聚类去密点与滤除离群点，VLM 规划器照常工作。计算放置分两层：YOLOv8、Mobile-SAM 与 VLM 运行在一台配 RTX 4090 的工作站上；传感器处理、雷达定位与底层控制运行在机器人本体。整个系统端到端约 5 FPS，论文评价该速率对室内多机导航足够。真机任务包含三个目标：椅子、水槽与人，三组场景各自展示了两机分配互补前沿并协同完成搜索的过程。

平台层的关键点在「谁提供地图的骨架」。仿真里位姿是真值，点云合并与前沿提取都不会因漂移出错；真机上点云质量由 FAST-LIO2 的定位精度决定，两机地图能拼在一起的前提是 GICP 初始对齐正确。论文特别强调框架与硬件无关：系统只需要 RGB-D 观测与位姿估计作为输入，输出离散动作，因此换平台时替换的是定位与执行两端，地图、提示与规划协议保持不变。

4. MFNP 的足式真机栈

真机实验使用 Unitree Go1-Edu（Zhang 等 2024，第 5.G 节）。感知由机器人的双目鱼眼相机与 IMU 承担：鱼眼相机提供 RGB 与深度，IMU 提供姿态；位姿由本体接口给出。计算方式与 Co-NavGPT 不同：数据上传到云端，由一台 RTX 4090 工作站推理并回传动作，机器人端通过 Go1 SDK 执行；跨楼层所需的爬梯动作直接调用本体的爬梯 SDK。论文强调复现口径：推理时使用与仿真相同的模型配置与参数，唯一改动是输入图像尺寸。真机结果是「在完全未见的环境中成功完成多楼层导航并找到目标物体」，以单个成功案例的形式展示。

平台层的关键点在「谁承担换层动作」。MFNP 的策略层只负责决策「何时换层」与「朝哪个方向走」，楼梯的物理攀爬交给底层 SDK；这带来两个工程后果：其一，策略无需学习爬梯，跨层可行性取决于本体 SDK 的能力边界（台阶高度、材质、负载）；其二，地图在爬梯过程中仍按二维平面更新，楼梯区的观测噪声大，需要入口置障与重置机制兜底。

5. MFNP 决策、窗口与预算实算

多楼层决策在楼梯区域被检出（Estair = 1）且时间步位于可用窗口内时触发。可用窗口为第 150 步到第 300 步：前 150 步禁止上楼，保证当前层先积累覆盖证据；最后 200 步禁止上楼，给已开始的跨层过程留出回退时间。窗口长度 150 步，占 500 步预算的 30%；禁上楼的 200 步占 40%。决策分数为四因子加权和：

NMFNP = w1 f(t) + w2 · Oexplored / Ototal + w3 (1 − Et) + w4 PLLM，f(t) = (500 − t) / 500

四个因子分别是时间有效性、已见物体类别占比、探索增量不足程度与语言模型建议概率。时间因子的端点值为 f(150) = 0.70、f(300) = 0.40，随时间线性下降，含义是换层越晚越不划算。触发后进入层间导航：先把楼梯区域质心设为航点；进入楼梯区后对入口做膨胀并标记为障碍，强制单向通行；在楼梯另一端设置出口航点；若 200 步内未完成换层或未在新楼层更新地图，则重新初始化语义地图并暂时禁用多楼层策略。200 步重置占 500 步的 40%，与最后 200 步禁上楼共同保证「换层失败不吞掉整条 episode」。

7. 足式平台的六个共性问题

把两套系统放在一起，平台差异可以归入六个共性问题。定位：FAST-LIO2 加雷达提供较稳的位姿，IMU 加本体接口更轻但漂移更大；地图质量的上限都由定位决定。动作接口：Co-NavGPT 输出离散动作并由本体执行，MFNP 直接调用 SDK；两者都依赖底层控制器处理地形，策略层只给速度或航点。楼梯：一个把多楼层列为失败类别，另一个用爬梯 SDK 加单向约束实现换层；策略与本体能力的边界必须写清。计算分层：工作站模式（机器人端只做传感器处理与定位）与云端模式（数据上传、动作回传）各有延迟与断网风险。安全：足式本体的急停、限速与人员避让属于部署前置条件。恢复：重置地图、禁用策略、回退已探索区三类机制是长时程任务的兜底。

关键代码与解读

三段代码分别对应多机重规划周期、楼层决策窗口与足式预检。第一段按论文的 25 步周期与随机回退实现，第二段按四因子分数与窗口约束实现（权重为教学默认值，论文未给出具体数值），第三段为教学化实现。

片段 1：多机重规划周期与回退

class GlobalPlanner:
    """每 25 个局部步调用一次 VLM 做前沿分配（教学化骨架）。"""

    def __init__(self, period=25, max_calls=20):
        self.period = period
        self.max_calls = max_calls        # 500 / 25 = 20，与预算一致
        self.step_count = 0
        self.calls = 0
        self.assignment = {}

    def maybe_replan(self, step, frontiers, robots, explored_cells):
        if step % self.period != 0:
            return self.assignment
        if self.calls >= self.max_calls:
            return self.assignment
        if not frontiers:
            return self._fallback(robots, explored_cells)
        self.calls += 1
        self.assignment = vlm_assign(frontiers, robots)   # 外部 VLM 接口
        return self.assignment

    def _fallback(self, robots, explored_cells):
        """无可用前沿时，在已探索区域随机采样回退点。"""
        goals = {}
        for robot in robots:
            goals[robot] = random_choice(explored_cells)
        return goals

解读：（1）周期与预算联动：500 步除以 25 等于 20，调用次数上限直接写成 20，避免实现漂移导致额外调用。（2）前沿为空先走回退分支，回退点只从已探索区域采样，保证可达；把回退逻辑放进规划器内，避免散落在主循环里，也让日志能统计回退频率。（3）VLM 调用函数独立成外部接口，方便替换模型或加缓存；真机部署时这一层就是延迟与失败重试的边界。

片段 2：楼层决策窗口与重置看门狗

def stair_allowed(t, t_min=150, t_max=300, has_stair=True):
    """爬梯窗口：前 150 步与最后 200 步禁止上楼。"""
    return has_stair and (t_min <= t <= t_max)

def mfnp_score(t, obj_ratio, delta_explore, llm_prob,
               w=(0.25, 0.25, 0.25, 0.25)):
    """四因子决策分数；权重为教学默认值，原文未给出数值。"""
    f_t = (500.0 - t) / 500.0
    return (w[0] * f_t + w[1] * obj_ratio +
            w[2] * (1.0 - delta_explore) + w[3] * llm_prob)

class StairWatchdog:
    """层间导航看门狗：200 步未完成换层则重置。"""

    def __init__(self, reset_steps=200):
        self.reset_steps = reset_steps
        self.elapsed = 0

    def tick(self, floor_changed, map_updated):
        self.elapsed += 1
        if floor_changed and map_updated:
            self.elapsed = 0
            return "done"
        if self.elapsed >= self.reset_steps:
            self.elapsed = 0
            return "reset"        # 重初始化语义地图并暂时禁用多楼层策略
        return "waiting"

解读：（1）窗口端点来自论文：150 与 300 两个边界同时排除「过早换层」与「过晚换层」，函数把两端约束写成一个条件，减少配置错位。（2）四因子中时间因子随时间下降，探索增量因子用 (1 − Et) 表示「新探索面积比例越低越该走」，两项方向一致时触发更可信；权重未公开，等权只是复现起点。（3）看门狗区分「换层完成」与「超时重置」，重置包含地图重初始化与策略暂停两个动作；状态字符串直接进日志，与第 034 讲的四步层间流程一一对应。

片段 3：足式部署预检（教学化）

CHECKS = (
    ("localization", "pose source and rate logged"),
    ("extrinsics", "camera-lidar calibration verified"),
    ("time_sync", "sensor timestamps aligned"),
    ("team_align", "GICP initial alignment between robots"),
    ("map_bounds", "floor area within configured map range"),
    ("action_map", "discrete actions map to sdk commands"),
    ("stairs", "stair sdk tested both directions"),
    ("compute", "workstation or cloud link measured"),
    ("fallback", "planner works when vlm is unavailable"),
    ("estop", "emergency stop reachable during run"),
)

def preflight(env):
    """逐项检查，任何一项未通过都不允许开始实验。"""
    report = []
    for key, desc in CHECKS:
        ok = env.probe(key)
        report.append({"check": key, "desc": desc, "ok": ok})
        if not ok:
            print("[FAIL] %s: %s" % (key, desc))
    return all(item["ok"] for item in report)

解读：（1）清单把平台问题变成布尔检查，任意一项失败就阻断实验，避免把平台故障记成算法失败。（2）probe 函数由部署方实现，例如 localization 检查返回位姿频率与漂移统计，extrinsics 检查返回重投影误差；接口固定后不同机器人共用同一张预检表。（3）报告写回实验日志，失败分类时可以按检查项统计「实验作废」与「算法失败」，这正是第 096 讲评测方法学的输入。

常见误区

  • 把团队指标当作单机能力：症状是用 Co-NavGPT 的 0.666 与单机方法比较并宣称算法更强。根因是多机指标取全队最短路径与最近距离，同起点异朝向的设定还会带来早期覆盖优势。修复：只与多机基线在同一指标口径下比较；报告重复探索率与通信量等协作代价。
  • 把演示案例当成功率：症状是引用「Go2 三场景演示」或「Go1 完成多楼层」推断真机成功率。根因是两篇论文的真机部分均为定性展示，无重复与统计。修复：真机结论限定为可行性；按第 093 讲的升级协议补重复次数、判据与失败分类。
  • 忽略计算分层与回传延迟：症状是仿真参数照搬后控制频率掉到不可用。根因是工作站与云端模式引入网络延迟与抖动，端到端约 5 FPS 是在理想链路下的读数。修复：先做链路压测与断网注入；规划器必须有 VLM 不可用时的回退策略，回退动作要能在断网时独立运行。
  • 定位漂移污染跨层地图：症状是换层后新旧楼层地图叠在一起，入口置障也压不住振荡。根因是入口置障解决的是路径层面折返，位姿误差会让点云本身错位。修复：跨层前后做重定位或回环校验；地图按楼层分区存储；漂移超阈值的 episode 作废并计入平台失败。
  • 判据与动作口径混用：症状是把自己测的真机结果直接对照挑战榜。根因是两篇论文的仿真判据均为 0.1 m，挑战口径为 1 m 加可见性条件；动作空间的离散步长（0.25 m、30°）与本体 SDK 速度控制也不一致。修复：报告标注判据来源与动作接口；跨口径比较只允许趋势层面，数值排序必须同口径重跑。

    提示

小结

  • Co-NavGPT 足式栈：两台 Unitree Go2、D455 与 Mid-360、FAST-LIO2 定位、GICP 机间对齐；检测、分割与 VLM 在工作站，端到端约 5 FPS；每 25 步重规划一次，每幕至多 20 次 VLM 调用。
  • Co-NavGPT 仿真账：HM3D v0.2 1000 条 episode、6 类目标，SR 0.666 对贪心 0.611（+9.00%），DTG 1.684 m（相对贪心 −24.79%）；消融显示语义俯视图贡献成功率，多机相对单机 SR +0.087；失败约 14% 探索、20% 检测。
  • MFNP 足式栈：Go1-Edu、双目鱼眼与 IMU、云端 RTX 4090 推理、本体 SDK 执行、爬梯 SDK 承担换层；仅改输入图像尺寸；真机为单案例定性证据。
  • MFNP 决策账：窗口第 150 至 300 步（30%），200 步重置（40%），f(150) = 0.70、f(300) = 0.40；HM3D SR 58.3 对 TriHelper 56.5，触发子集 38.5 对 33.0，跨层收益集中在需要换层的 episode；相对 VLFM 为 SR +5.8、SPL −0.037 的取舍型结果。
  • 平台纪律：定位与外参是第一约束，计算分层的延迟与断网要有回退，判据与动作口径必须标注，真机演示与仿真统计分开归档。
