第四篇 · 开放词汇与大模型

第 063 讲｜ZSON I：多模态目标嵌入

第 062 讲的 CoW 不训练任何策略，靠开放词汇定位与前沿探索完成零样本导航，代价是无法学习室内布局先验，属性文本利用也不充分。本讲拆解另一条路线：Majumdar 等（2022，ZSON: Zero-Shot Object-Goal Navigation using Multimodal Goal Embeddings，NeurIPS 2022）用 CLIP 把图像目标与文本目标投影到同一个语义嵌入空间，在 HM3D 的 800 个无标注场景上用图像目标导航（ImageNav）训练语义目标导航（SemanticNav）策略，500M 步后把文本目标直接送进同一策略，全程不使用 ObjectNav 奖励、演示或标注。本讲讲清嵌入对齐、网络结构、奖励函数、数据生成与训练账；跨数据集评测留给第 064 讲。

  • 主题：多模态嵌入 / 零样本迁移 / ImageNav 预训练 / 强化学习
  • 关键公式：svg = CLIPv(vg)，sog = CLIPt(og)；rt = rsuccess + rangle-success − Δdtg − Δatg + rslack
  • 预计学时：80 分钟
  • 前置章节：第 062 讲（CoW / Pasture：CLIP 基线）

学习目标

  • 会推导：写出 CLIP 的对比对齐目标（InfoNCE）与余弦相似度形式，说明图像目标与文本目标可以互换的数学条件与经验条件。
  • 会实现：语义目标嵌入的预计算管线（1024 维、L2 归一化、四朝向增广），以及策略网络的前向结构（视觉编码器、目标嵌入、动作嵌入、两层 LSTM）。
  • 会算：9k × 800 = 7.2M episode 与 36M 增广口径的差异，单 agent 852 GPU 时与 8 卡墙钟，γ = 0.99 的折扣视野与 slack 累计。
  • 会判断：ImageNav 训练为何能迁移到 ObjectNav，奖励各分项的作用，无提示工程的取舍，以及嵌入预计算相对端到端训练的收益。
  • 会读：成功判据（1.0 m 与 25°）与后续评测协议的衔接，训练检查点选择规则对复现的影响。

背景与动机

第 062 讲留下两个问题。第一，启发式 CoW 无法学习室内布局先验，而这类先验对导航有用，例如炉灶通常出现在厨房。第二，属性与空间描述没有带来稳定增益，说明把语言理解全部压给定位模块并不够。要解决这两点，需要让导航策略本身可训练；但 ObjectNav 的训练数据昂贵：3D 语义标注需要人工，人类演示以千小时计，奖励稀疏且难以采样。ZSON 的思路是把问题拆成两半：目标的表示交给 CLIP，导航的学习交给 ImageNav。

拆分的依据是图像目标导航的一个性质：episode 由起始位置与目标视点定义，目标图像可以从场景里程序化采样，不需要任何物体或房间标注，因此训练数据的规模只受场景数量限制。若把目标图像先经 CLIP 编码成语义目标嵌入，再训练策略，那么图像目标与文本目标就共享同一个目标空间。评测时把目标从图像换成文本，策略接口不变，零样本迁移由此成立。

这条路线与 CoW 形成互补对照：CoW 用开放词汇模型做感知、用规则做决策、训练步数为零；ZSON 用开放词汇模型做目标编码、用强化学习做决策、训练 500M 步。第 063 讲讲清机制与训练账，第 064 讲读跨数据集结果与协议。

核心原理

1. CLIP 与对比对齐

CLIP（Radford 等 2021）用双编码器把图像与文本映射到同一嵌入空间，在 400M 图文对上训练。训练目标是 InfoNCE 式的对比损失：一个批次内，配对样本的相似度被拉高，非配对样本被压低。设批次大小为 B，图像嵌入 vi、文本嵌入 ti 均已 L2 归一化，相似度取余弦，温度参数 τ 可学习：

L = −(1/2B) Σi=1..B [ log exp(sim(vi, ti) / τ) / Σj exp(sim(vi, tj) / τ) + log exp(sim(ti, vi) / τ) / Σj exp(sim(ti, vj) / τ) ] sim 为余弦相似度；两项分别以图像与文本为锚，构成对称目标

对齐质量的一个直观数值：若某张“洗手池”图像的嵌入与“bathroom sink”“kitchen sink”“sofa”三个文本的余弦相似度分别为 0.31、0.28、0.12，CLIP 推理时的 logit 缩放接近 100，则前两者的相对倍数约为 e3 ≈ 20.09，与第三个的倍数约为 e19 ≈ 1.78 × 108。这说明在嵌入空间里，语义相近的文本距离可以很近，但排序仍然分明；0.03 的余弦差经过缩放后足以形成显著区分度。ZSON 依赖的正是这一性质：目标嵌入不要求文本与图像逐像素对应，只要求语义近邻关系稳定。

2. 语义目标嵌入的构造

ZSON 把导航目标统一定义为语义目标嵌入 sg。图像目标 vg 经 CLIP 视觉编码器得到 svg = CLIPv(vg)；文本目标 og 经 CLIP 文本编码器得到 sog = CLIPt(og)。论文使用 ResNet-50 版本的 CLIP，嵌入维度为 1024。图像目标在训练时由环境提供，文本目标在评测时由任务给出，两者共用同一策略网络。

实现上有一个刻意简化的选择：不做提示工程，直接把物体名（如“sofa”）作为文本输入，不套“A photo of a …”模板。理由是可复现性与接口清晰：目标文本来自任务，策略端不应假设模板；嵌入空间的近邻结构由 CLIP 预训练保证。语义目标还带来两个副作用：其一，嵌入丢弃了目标图像的底层纹理信息，保留语义概念，这使策略更难但迁移更稳；其二，目标嵌入可以离线预计算，训练时直接读取，论文报告训练时间因此缩短约 3.5 倍（时间降为 28.6%）。

3. SemanticNav 的形式化与网络结构

把两类导航任务统一为语义目标导航（SemanticNav）：在时刻 t，智能体收到自我中心 RGB 观测 ot、语义目标嵌入 sg 与上一动作 at−1，输出动作分布 π(at | ot, sg, at−1)。动作集合为四元离散：前进 0.25 m、左转 30°、右转 30°、停止。策略网络结构简单：RGB 经 ResNet-50 编码，该编码器先在 Omnidata Starter Dataset（OSD）上用 DINO 自监督预训练，再随任务微调，预训练配方沿用 OVRL（Yadav 等 2022，Offline Visual Representation Learning for Embodied Navigation；其升级版 OVRL-v2 见第 053 与 054 讲）；视觉特征与目标嵌入、动作嵌入拼接后送入两层 LSTM，输出动作分布。若按 ResNet-50 常见输出 2048 维、动作嵌入取 32 维估算，拼接向量约 3,104 维（估算口径，论文未给出动作嵌入维度）。

这个结构里没有目标类别的输入端口，也没有物体检测分支：目标只以 1024 维向量的形式进入 LSTM。策略学到的行为因此指向“朝某个语义方向的视觉证据移动”，并未显式“识别某个类别后走向它”。评测时把目标向量从图像编码换成文本编码，行为层面的接口完全一致。

4. ImageNav 奖励与折扣账

训练使用 Al-Halah 等（2022）为 ImageNav 设计的奖励，共五项：

rt = rsuccess + rangle-success − Δdtg − Δatg + rslack rsuccess = 5：停止时距目标位置 ≤ 1.0 m；rangle-success = 5：停止时距目标 ≤ 1.0 m 且朝向在目标朝向 25° 内；Δdtg 为到目标测地距离的变化量；Δatg 为到目标朝向角的变化量，距离超过 1.0 m 时置 0；rslack = −0.01 鼓励高效路径

各分项的作用不同。两个成功项都要求停止动作正确：只到达位置拿 5 分，到达且朝向正确再拿 5 分，后者与下游 ObjectNav 的“看到目标再停”对齐。Δdtg 提供密集的靠近信号：前进使距离减小，该项为正。Δatg 只在 1.0 m 内生效，防止策略在远处为对准朝向而牺牲探索。rslack 是每步常数惩罚，抑制原地打转。

折扣账决定成功信号的传播视野。取 γ = 0.99，100 步外的成功奖励权重为 0.99100 ≈ 0.366，200 步外为 0.99200 ≈ 0.134，500 步外只剩 0.99500 ≈ 0.0066。ImageNav 的难度档上限为 10 m，按 0.25 m 步长，直线推进约 40 步，加上转向与绕行，数百步内可以覆盖；γ = 0.99 与这个尺度匹配。slack 的累计量级也值得核算：500 步的 −0.01 未折扣累计为 −5.00，恰好等于一个成功奖励，折扣累计为 −0.9934；也就是说，常数惩罚在折扣口径下约为 1 分，不足以压过成功项，但足以在两条相近路径之间偏向更短的一条。

5. 训练数据生成与规模口径

SemanticNav 数据集在 HM3D 的 800 个训练场景上生成。每个场景采样 9,000 条 ImageNav episode，三档难度均分：简单 1.5–3 m、中等 3–5 m、困难 5–10 m，每档 3,000 条；合计 9,000 × 800 = 7.2M 条。目标图像经 CLIP 视觉编码器离线处理为 1024 维向量。预处理阶段再做朝向增广：在四个均匀间隔的朝向采样目标图像。论文正文写“产生 36M 条训练 episode”。这里存在一个需要标明的口径差：按 7.2M × 4 计算为 28.8M，与 36M 相差 7.2M；若把四个朝向理解为在原始目标图之外追加，总数为 5 × 7.2M = 36M，与论文一致。引用时建议保留论文原文的 36M，并注明乘法口径的差异。

存储账可以校验这个规模：36M 条 1024 维 float32 目标向量约 147.5 GB，float16 约 73.7 GB；未增广的 7.2M 条分别约 29.5 GB 与 14.7 GB。这解释了预计算成为必要设计：把 CLIP 前向从训练循环里移出，既省算力，也让目标嵌入的存储与加载成为独立的工程问题。

6. 训练配置与算力账

训练算法为分布式去中心化近端策略优化（DD-PPO），在 8 张 NVIDIA A40 上运行，每个 GPU 并行 32 个环境（共 256 个），rollout 长度 64。两套本体配置各训练一个 agent，每个 agent 500M 步，合计约 1,704 GPU 时；单 agent 约 852 GPU 时，8 卡墙钟约 106.5 小时（4.44 天），8 卡聚合步速约 1,304 步/秒，单卡约 163 步/秒。下表为论文附录给出的完整超参（Majumdar 等 2022，表 7）。

7. 零样本成立的条件与边界

零样本成立依赖两个条件。第一是表示条件：图像目标与文本目标在 CLIP 空间中语义对齐，训练时策略见到的目标向量分布与评测时文本向量分布处于同一邻域。第二是行为条件：ImageNav 训练出的探索与停止行为对目标的具体形态不敏感，只依赖语义方向。论文的定性观察支持第二点：智能体在长轨迹中常先做一次约 360° 旋转，疑似在环视环境后再决定方向。

边界同样明确。其一，策略的先验来自 HM3D 场景的统计规律，目标出现在非常规位置时（如卧室里的炉灶）容易失效。其二，嵌入空间对细粒度属性（颜色、材质）的分辨能力有限，这也是第 062 讲属性描述增益不足的同源问题。其三，评测协议依赖检查点规则与三次平均，跨论文比较要先对齐这两项。其四，36M 与 7.2M 两个数据口径不可混用；算力账应按 500M 步与 1,704 GPU 时报告。

实现思路与设计

实现重点是三条流水线：数据生成与嵌入预计算、策略训练、评测时的目标替换。前两条在本讲展开，第三条的评测矩阵与协议在第 064 讲。

数据流

训练侧：场景 → 程序化采样 episode（三档难度）→ 目标图像 → CLIP 视觉编码器 → 1024 维嵌入存盘 → 训练循环按 episode 索引读取嵌入，与观测、动作一起送入策略。评测侧：任务文本 → CLIP 文本编码器 → 1024 维嵌入 → 同一策略。两条路径只在目标编码处不同，其余环节共用，这是“接口替换”式零样本迁移的标准形态。

训练循环与预算

训练循环按 DD-PPO 组织：256 个环境并行采样 rollout，每个 rollout 64 步；每轮 2 个 PPO epoch、每个 epoch 2 个小批次；优势用 GAE（λ = 0.95）估计，不做优势归一化。总预算 500M 步，两套配置合计约 1,704 GPU 时。数据增强在观测端做颜色抖动与随机平移，目标端不变。检查点按 ObjectNav 验证成功率选择，评测采样动作并做三次平均。

关键代码与解读

三段代码覆盖嵌入预计算、策略前向与奖励实现，均按论文口径书写。

片段 1：目标嵌入预计算（离线）

import torch

def encode_goal_images(clip_visual, images, batch=256):
    """把目标图像编码为 1024 维语义目标向量；训练时直接读取。"""
    vectors = []
    with torch.no_grad():
        for i in range(0, len(images), batch):
            chunk = images[i:i + batch]              # 已缩放为 224 x 224
            feat = clip_visual(chunk)                # CLIP ResNet-50 视觉塔
            feat = torch.nn.functional.normalize(feat, dim=-1)  # L2 归一化
            vectors.append(feat.cpu())
    return torch.cat(vectors, dim=0)

# 朝向增广：每个 episode 在四个均匀朝向各采一张目标图
HEADINGS = (0.0, 1.5708, 3.1416, 4.7124)             # 弧度，间隔 90 度
# 7.2M 基础 episode x 4 朝向 = 28.8M；论文正文按 36M 口径报告

解读：（1）L2 归一化必须与 CLIP 训练时一致；若省略，后续若用点积检索或与文本嵌入做相似度，尺度会破坏可比性。（2）预计算把 CLIP 前向从训练循环移出，训练只读向量；收益是训练时间降为 28.6%，代价是目标图像集合固定。（3）朝向增广的动机是让策略见过从不同方向看目标的图像，减少对单一视角的依赖；增广口径的差异要在实验记录里写明。

片段 2：策略网络前向

import torch.nn as nn

class SemanticNavPolicy(nn.Module):
    """ResNet-50 视觉编码器 + 目标嵌入 + 上一动作嵌入，送入两层 LSTM。"""
    def __init__(self, goal_dim=1024, action_dim=32, hidden=512):
        super().__init__()
        self.visual = resnet50()                         # 权重按 OVRL 配方加载
        self.visual_fc = nn.Linear(2048, hidden)
        self.goal_fc = nn.Linear(goal_dim, hidden)
        self.action_embed = nn.Embedding(4, action_dim)
        self.lstm = nn.LSTM(hidden + goal_dim + action_dim, hidden,
                            num_layers=2)
        self.actor = nn.Linear(hidden, 4)                # 四动作分布
        self.critic = nn.Linear(hidden, 1)

    def forward(self, obs, goal, prev_action, state):
        vis = torch.relu(self.visual_fc(self.visual(obs)))     # [B, hidden]
        act = self.action_embed(prev_action)                   # [B, 32]
        x = torch.cat([vis, goal, act], dim=-1)                # 拼接目标
        out, state = self.lstm(x.unsqueeze(0), state)          # 单步循环
        h = out.squeeze(0)
        return self.actor(h), self.critic(h), state

解读：（1）目标嵌入以拼接方式进入 LSTM，未采用单独的条件网络；这与实现简单性相关，也让目标信息每步都可见，避免被循环状态遗忘。（2）动作嵌入给策略提供动作历史，部分缓解部分可观测；评测时采样动作，与训练分布一致。（3）actor 与 critic 共享 LSTM，价值函数与策略在同一表征上学习；若拆开，需要额外的特征对齐设计，论文未采用。

片段 3：ImageNav 奖励实现

def imagenav_reward(stop_called, dist_to_goal, angle_to_goal,
                    prev_dist, prev_angle, slack=-0.01):
    """Al-Halah 等 2022 的 ImageNav 奖励；角度项仅在 1 m 内生效。"""
    reward = slack
    if stop_called and dist_to_goal <= 1.0:
        reward += 5.0                                   # 到达奖励
        if angle_to_goal <= 25.0 * 3.14159 / 180.0:
            reward += 5.0                               # 到达且朝向正确
    reward -= (dist_to_goal - prev_dist)                # 靠近为正
    if dist_to_goal <= 1.0:
        reward -= (angle_to_goal - prev_angle)          # 仅在 1 m 内生效
    return reward

# gamma = 0.99 时：0.99**100 = 0.366，0.99**200 = 0.134，0.99**500 = 0.0066

解读：（1）角度项的距离门控是奖励设计的关键：不设门控时，远处为对准朝向的原地转向会获得正奖励，策略容易停在原地。（2）slack 每步 −0.01，500 步折扣累计约 −0.9934，量级约等于一个成功奖励的 1/5（按折扣口径），既抑制绕路又不压过成功信号。（3）成功项要求停止动作被调用，若智能体走到目标旁却不停止，拿不到 10 分；这与评测的停止判据一致。

常见坑

  • 嵌入未归一化或编码器混用：症状是文本目标与图像目标的相似度排序紊乱，零样本成功率异常低。根因是训练用 CLIP 视觉塔、评测用文本塔时未保持同一归一化与同一模型版本。修复：两个编码器都做 L2 归一化，固定同一 CLIP 检查点，并先用一组检索样例验证图像与文本近邻一致。
  • 目标模态在训练与评测间颠倒：症状是训练正常、评测崩坏。根因是把文本目标用于训练、图像目标用于评测，分布与论文相反。修复：训练用图像目标、评测用文本目标；做一次交换模态的对照实验来确认机制。
  • 混用 7.2M 与 36M 数据口径：症状是复现规模对不上。根因是论文正文的 36M 与 7.2M × 4 的乘法口径不一致（28.8M）。修复：报告时写清基础 episode 数与朝向增广方式，两个数字都标注来源。
  • 奖励角度项未做距离门控：症状是策略学会原地旋转对准朝向而不前进。根因是 Δatg 在远处持续给正奖励。修复：距离超过 1.0 m 时把角度项置 0；若自定义奖励，需重新核算转向与前进的收益比。
  • 忽略检查点选择规则：症状是与论文数字差距明显但训练曲线正常。根因是用了 ImageNav 验证指标选检查点，论文用 ObjectNav 验证成功率。修复：复现时固定论文规则；自研项目写明所选规则并保持一致。
  • 把预计算嵌入当作无损加速：症状是更换数据增强或目标图像后策略退化。根因是嵌入离线固定，增强只作用于观测端。修复：把目标端增强纳入预计算流程，或在训练循环里对嵌入加噪声模拟变化。

练习与思考

  1. 给定某目标图像与三个候选文本的余弦相似度 0.31、0.28、0.12，写出温度 τ 下的 softmax 概率，并说明 logit 缩放为 100 时前两者的相对倍数。★
    提示
    概率按 exp(sim/τ) 归一化；缩放 100 等价于 τ = 0.01，前两者比值 exp(3) ≈ 20.09，与第三者的比值约 exp(19) ≈ 1.78 × 108。结论是排序分明但相近语义仍可区分。
  2. 为 36M 条 1024 维目标向量设计存储与加载方案，比较 float32 与 float16 的容量，并说明分片与内存映射的取舍。★★
    提示
    float32 约 147.5 GB，float16 约 73.7 GB；按场景或分片存盘，训练按 episode 索引读取；内存映射减少常驻内存，代价是随机访问延迟；若采样器按场景分组，顺序读取可提升吞吐。
  3. 复算 γ = 0.99 下 100、200、500 步的折扣权重与 slack 的折扣累计，说明为什么 −0.01 的量级合适，并给出一个让路径更短的替代奖励设计。★★
    提示
    折扣权重 0.366、0.134、0.0066；500 步 slack 折扣累计约 −0.9934，与单个成功项 5 分相比量级偏小但不为零。替代设计可用步数惩罚线性项或路径长度正则，需重新扫参确认不压过成功信号。
  4. 论证“图像目标训练可迁移到文本目标评测”的成立条件，并设计一个证伪实验：若迁移仅靠视觉模式匹配，结果应如何变化？★★★
    提示
    条件包括嵌入空间语义对齐与行为对目标形态不敏感。证伪实验：评测时随机替换目标文本为不相关文本（如把“sofa”换成“toilet”），若成功率不下降，说明策略忽略目标语义；再做目标嵌入置零或置随机向量的对照，观察行为是否退化为无目标探索。
  5. 若把困难档上限从 10 m 提高到 15 m，预测 ImageNav 成功率与零样本 ObjectNav 成功率的相对变化，并说明依据。★★
    提示
    困难档占比不变（每档 3,000 条）时，平均 episode 更长、成功信号折扣更弱，ImageNav 成功率预计下降；ObjectNav 探索更久，对策略的远程目标保持能力要求更高，零样本成功率可能同步下降。依据是 γ = 0.99 的折扣视野与 500 步上限。

小结

  • ZSON 把目标表示与导航学习解耦：CLIP 双编码器提供 1024 维语义目标嵌入，图像目标与文本目标共用同一空间，评测时做接口替换即可零样本迁移。
  • 策略结构为 ResNet-50（DINO/OSD 预训练）+ 目标嵌入 + 动作嵌入 → 两层 LSTM → 四动作分布；无检测分支、无类别输入端口、不做提示工程。
  • 训练任务为 ImageNav，奖励含到达 5 分、到达且朝向 25° 内 5 分、距离变化、角度变化（1 m 内生效）与每步 −0.01 的 slack；γ = 0.99 时 100/200/500 步折扣为 0.366/0.134/0.0066。
  • 数据规模为 9k × 800 = 7.2M 条 episode，四朝向增广后论文报告 36M（乘法口径为 28.8M，需注明差异）；嵌入离线预计算使训练时间降为 28.6%。
  • 训练账为 DD-PPO、256 个并行环境、每个 agent 500M 步、两套配置合计约 1,704 GPU 时（单 agent 约 852 GPU 时，8 卡墙钟约 106.5 小时）；检查点按 ObjectNav 验证成功率选择。
