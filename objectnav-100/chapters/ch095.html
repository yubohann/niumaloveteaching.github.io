第五篇 · 真机、Sim2Real 与系统集成

第 095 讲｜NaVILA：语言中期动作

第 094 讲把策略层与底层运动的分工交给本体 SDK 与爬梯技能，本讲拆解一种把分工写进模型接口的方案。NaVILA（Cheng 等 2025，腿足机器人视觉语言动作导航，arXiv:2412.04453v2）采用两级框架：视觉语言动作模型（Vision-Language-Action, VLA）输出带空间数值的中期动作字符串，例如 forward 75 cm、turn right 30 degrees，由视觉运动策略（visual locomotion policy）执行成关节位置。该设计让同一 VLA 在 Unitree Go2、Unitree H1、Booster T1 上换用不同运动策略即可部署；VLA 在单张 RTX 4090 上约 1 FPS，运动策略实时运行，构成双频结构。R2R-CE 验证集成功率 54.0、SPL 49.0，超过不依赖路点预测器的单目基线 NaVid（37.0）17.0 个百分点；RxR-CE 验证集为 49.3。真机用 25 条指令各重复 3 次，总体成功率 88%。本讲实算动作时长、双频覆盖、量化代价与训练算力，并划清 VLN 指令跟随口径与 ObjectNav 口径的边界。

  • 主题：分层执行 / 语言中期动作 / 双频调度 / 腿足运动策略 / 跨本体迁移
  • 关键公式：at = πVLA(I1:t, L)；qd = πL(ot, at)；texec = Δd / 0.5 或 Δθ / (π/6)
  • 预计学时：85 分钟
  • 前置章节：第 094 讲（足式平台：Co-NavGPT / MFNP）

学习目标

  • 复述：说清 NaVILA 两级框架的输入输出、两条时间尺度与跨本体迁移的接口条件。
  • 会算：由中程动作的距离与角度换算执行时长，检查命令队列覆盖；复算量化前后的延迟、显存与指标差。
  • 会设计：为中期动作语言写出语法、解析器与命令队列，配超时与安全回退。
  • 会判断：区分 R2R-CE 指令跟随口径与 ObjectNav 的成功判据；识别 88% 真机数字的聚合口径与样本边界。
  • 会迁移：把双频结构映射到第 094 讲的航点接口与第 097 讲的工程栈分层。

背景与动机

第 094 讲留下的问题是「策略层输出什么」。Co-NavGPT 输出离散动作，MFNP 输出航点并调用本体技能；两者都把「往哪走」与「怎么走」分开，分开的切口由工程约定给出。第 074 至 076 讲走过另一条路线：VLM 直接充当策略，输出离散动作或文本决策。NaVILA 提出第三种表示：动作以自然语言书写并携带公制数值，上承语言模型的推理习惯，下接专门训练的运动策略。论文把这一选择写成设计问题：动作是否需要停留在量化后的底层命令空间。

这一表示带来三个可验证的后果。其一，VLA 与执行器解耦，换机器人时替换运动策略，VLA 与提示协议保持不变，论文在 Go2、H1、T1 三种本体上验证。其二，训练数据不再局限于遥操作动作序列，人类游览视频经过位姿估计与指令生成后可直接用于连续环境导航训练，论文给出约 5% 的指标增益。其三，两个模块以不同频率运行，VLA 承担低频推理，运动策略承担高频避障。对 ObjectNav 读者，本讲的价值在于接口设计：中期动作把「目标相对方位与距离」用语言表达，正是第 093 讲价值图与第 094 讲航点之间的第三种契约形式。

核心原理

1. 两级框架与问题形式

设机器人在时刻 t 收到观测 It（单目 RGB）与自然语言指令 L，维护历史观测 I1:t−1 作为记忆。VLA 输出中期动作 at，形式为语言字符串；运动策略接收本体观测 ot 与该字符串，输出 12 个腿部关节的目标位置 qd ∈ ℝ12，由关节伺服转成力矩：

at = πVLA(It, I1:t−1, L)，qd = πL(ot, at)

VLA 由 VILA 系列的图文模型微调而来，训练从第二阶段权重出发，用导航数据混合集做一轮指令微调，视觉编码器、投影器与语言模型全部解冻；学习率 1×10−4，余弦衰减，预热比 0.03（Cheng 等 2025，附录 C2）。推理时用正则解析器从输出文本提取动作类型与参数，论文报告全部实验中的动作都被成功匹配（第 II-A 节）。两级结构的关键量是频率差：4090 上单次 VLA 推理约 1 FPS，而运动策略在仿真训练中达到每秒 6 万帧的采样吞吐（论文第 II-B 节），部署时以实时频率跟踪速度指令，障碍规避发生在高频侧。

论文把这一设计归纳为三条收益（第 I 节）。执行与推理解耦之后，同一 VLA 可以配不同运动策略，跨本体部署只替换低频侧的搭档；动作以语言表达，训练可吸收人体行为数据与问答数据，不必把监督信号压进特定机器人的底层命令分布；两条时间尺度各司其职，低频侧负责理解与规划，高频侧负责避障与稳定。这条路线与第 074 至 076 讲的「VLM 即策略」形成互补：那条路线强化单模型的多任务能力，这条路线把可靠性拆给两个专用模块。选择判据可以写成两个问题：目标机器人是否已有可用的运动控制器，训练数据是否有大量无动作标签的视频。

模型侧沿用 VILA 的三段预训练流程：先对齐冻结语言模型与视觉骨干之间的连接器，再用图文交错语料预训练连接器与语言模型，最后用指令数据端到端微调全部模块。NaVILA 从第二段权重接手，只做导航指令微调，因此模型保留了通用视觉问答能力，这也是第四组通用数据仍然进入混合集的原因。视频输入的组织方式沿用多图推理约定，所有帧信息放在文本之前。

2. 中期动作的语法与执行

论文给出的动作词表为 {move forward, turn left, turn right, stop}，每个词带数值参数。仿真数据的构造方式是沿最短路径跟随器采样离散动作，再把连续同类动作合并，最多合并三步：两个前进 25 cm 合并为一个前进 50 cm。由此得到的前进距离取值为 25、50、75 cm；转角按同一合并规则推导，论文示例给出 30°，取值为 30°、60°、90°。执行侧的映射为固定速度：前进 0.5 m/s，转向 ±π/6 rad/s（即每秒 30°），停止为 0；持续时间由数值除以速度得到。逐项换算：

中期动作执行时长中期动作执行时长
前进 25 cm0.50 s左转 30°1.00 s
前进 50 cm1.00 s左转 60°2.00 s
前进 75 cm1.50 s左转 90°3.00 s

把时长与 VLA 周期放在一起看，最长动作 3.0 s 覆盖三个决策周期，最短动作 0.5 s 只覆盖半个周期。这一错位决定了执行层必须有命令队列与截止时间，否则新命令会截断未完成的转向。停止动作在训练数据中占比偏低，论文做了标签再平衡（第 II-A 节）。用语言承载动作的代价是每次决策都要经过文本生成，收益是动作空间与机器人本体解耦，并且动作值可以连续取值。

3. 观测组织与提示构造

NaVILA 采用图像模型处理视频流。提示把帧分成两类：最近一帧作为当前观测，之前的历史帧按均匀间隔采样作为记忆，且首帧永远入选，用于保留起点信息。两类帧在文本中以不同标签区分，历史段写作 video of historical observations，当前段写作 current observation，避免引入额外特殊符号，使输入输出都停留在语言域。论文实验了 8 到 64 帧的记忆规模；消融显示 R2R-CE 上 8 帧已覆盖多数指令的时域跨度，继续增加收益有限（附录 A3）。

4. 训练数据混配

监督微调数据分四组。第一组是真实视频导航数据：从 2 千段 YouTube 第一视角游览视频出发，经熵采样得到 2 万条轨迹，用 MASt3R 估计相机位姿得到逐步动作，再用视觉语言模型生成描述、语言模型改写为指令。第二组是仿真导航数据：R2R-CE 与 RxR-CE 的最短路径跟随序列。第三组是辅助数据：指令增强与轨迹摘要任务，以及基于真实扫描的 ScanQA 空间问答。第四组是通用视觉问答，用于保持模型的世界知识。消融显示，加入人类视频后 OS、SR、SPL 约提升 5%（附录 A2）；跨数据集设置下，仅用 R2R 样本训练的模型在 RxR-CE 上零样本成功率 34.3，超过 NaVid 的 23.8（表 II）。

5. 运动策略与高度图

运动策略用 PPO 单阶段训练，动作空间为 12 个关节的目标位置。执行器观测不含线速度，用本体感觉历史隐式推断；评论家观测含特权地形高度扫描。机器人用 LiDAR 建立 2.5D 高度图：每个体素格取范围内最低点，再对最近 5 帧点云做最大值滤波，平滑后交给策略。仿真训练参数为 32 线、水平分辨率 4°、体素 0.06 m、x 范围 [−0.8, 0.2] m、y 范围 [−0.8, 0.8] m、z 范围 [0.05, 0.5] m（附录表 XII）。按 0.06 m 体素估算，平面网格约 17 × 27 格，合计约 459 格；每帧 32 × 90 = 2880 个点，15 Hz 下每秒约 4.32 万个点，5 帧滤波窗口为 0.333 s。高度图表达式为：

H(x, y) = maxk = 0 … 4 minp ∈ V(x, y, k) z(p)

式中 V(x, y, k) 为第 k 帧落在格 (x, y) 的点集合。只保留最低点可以滤掉草丛与噪声高点，最大值滤波抑制单帧空洞。LiDAR 在这里的职责是安全通道：深度与 RGB 对玻璃与强光失效，高度图仍能检出玻璃面与地形落差（论文第 II-B 节与附录图 12）。单阶段训练与教师学生蒸馏式两阶段相比，省去蒸馏环节；论文报告训练吞吐超过 60K FPS（RTX 4090），碰撞率指标明显更低。

6. 结果与实算

先对齐指标口径。NE 为停止点到目标的测地距离（米，越低越好）；OS 为「曾经到达过目标附近」的比例，允许后续走偏；SR 为在预算内停止在目标处的比例；SPL 为成功加权路径长度，用最短路径长度除以实际路径长度再乘成功指示；nDTW 为归一化动态时间规整，衡量执行轨迹与参考轨迹的贴合度，反映指令跟随质量（Cheng 等 2025，第 III-A 节）。这些口径中 SR 与 SPL 和第 003 至 005 讲的 ObjectNav 指标同名，判据来源不同；NE、OS、nDTW 为 VLN 惯用指标，引用时按论文协议标注。

7. 算力、量化与失效边界

训练算力按附录 C4 复算：前两阶段继承 VILA，16 个 A100 节点、每节点 8 卡，连接器初始化 4 小时、视觉语言预训练 30 小时，合计 128 × 34 = 4352 GPU·h；指令微调 4 个节点 18 小时，32 × 18 = 576 GPU·h；总计 4928 GPU·h，折合一台八卡节点 25.7 天。部署侧，VLA 单张 4090 约 1 FPS；论文用 AWQ 权重量化到 W4A16，在 1737 个上下文 token 与 10 个生成 token 的测试条件下，总延迟 594.58 → 367.80 ms（−38.1%，约 2.7 FPS），显存 18.5 → 8.6 GB（−53.5%），代价是 R2R 验证子集 SR 49.7 → 48.2（−1.5 个百分点）、SPL 45.5 → 43.6（表 XIII）。失效方面，论文明确指出真实失败来自偏差发生后缺少纠错：机器人沿初始提示前进，偏离后无法返回正确卧室（附录 E）。

import math

MOVE_RE = re.compile(r"move forward (\d+) cm")
TURN_RE = re.compile(r"turn (left|right) (\d+) degrees")
V_FWD = 0.5            # 论文命令速度：0.5 m/s
W_TURN = math.pi / 6.0  # 论文命令速度：30 deg/s

def to_command(text):
    """把 VLA 文本转成 (线速度, 角速度, 时长)；单位统一在边界处换算。"""
    m = MOVE_RE.search(text)
    if m:
        distance = int(m.group(1)) / 100.0          # cm 转 m，杜绝量纲混用
        return V_FWD, 0.0, distance / V_FWD         # 75 cm -> 1.5 s
    m = TURN_RE.search(text)
    if m:
        angle = math.radians(int(m.group(2)))       # 度转弧度
        sign = 1.0 if m.group(1) == "left" else -1.0
        return 0.0, sign * W_TURN, abs(angle) / W_TURN
    if text.strip() == "stop":
        return 0.0, 0.0, 0.0
    raise ValueError("unparsed mid-level action: %r" % text)

解读：（1）解析器只接受论文动作词表的四种模式，未匹配直接抛错，部署日志可以按异常统计 VLA 输出漂移，与论文「全部动作匹配成功」的报告形成对照。（2）单位换算集中在解析边界完成，下游队列只处理米与弧度，避免 cm 与 m 混用造成的 100 倍错误。（3）时长由数值与固定速度相除得到，与论文命令速度一致；若替换机器人改动速度，换算函数是唯一改动点。

片段 2：历史帧采样与提示构造

def build_prompt(frame_ids, instruction, n_history=8):
    """当前帧与历史帧分开描述；首帧必选；总帧数受 n_history 控制。"""
    current = frame_ids[-1]
    history = frame_ids[:-1]
    if len(history) > n_history:
        step = len(history) / float(n_history)
        sampled = [history[int(i * step)] for i in range(n_history)]
        sampled[0] = history[0]          # 起点记忆不因均匀采样丢失
    else:
        sampled = list(history)
    mem = " ".join("frame%d" % i for i in sampled)
    return ("video of historical observations: %s "
            "current observation: frame%d "
            "instruction: %s "
            "answer with one mid-level action" % (mem, current, instruction))

解读：（1）最近帧单独标注，承担即时决策；历史帧承担进度记忆，两类角色在文本上可区分，与论文的提示设计对应。（2）首帧强制保留，避免均匀采样在长 episode 中丢掉起点信息，这一条直接影响「返回起点附近」类指令的表现。（3）n_history 默认 8，与消融结论一致；上调到 64 只在长指令场景尝试，同时要付出上下文长度与延迟代价（量化测试使用 1737 个上下文 token）。

片段 3：双频调度与安全回退（教学化）

class DualRateScheduler:
    """VLA 低频决策，运动策略高频执行；命令带截止时间，缺命令时回退停止。"""

    def __init__(self, vla_period=1.0):
        self.vla_period = vla_period
        self.queue = []                 # (line_vel, ang_vel, deadline)
        self.last_decision = -1e9

    def maybe_decide(self, t, run_vla):
        if t - self.last_decision < self.vla_period:
            return
        self.last_decision = t
        text = run_vla()                # 超时或解析失败返回 None
        if text is None:
            self.queue.append((0.0, 0.0, t + 0.5))   # 半秒安全停止
            return
        v, w, dur = to_command(text)
        self.queue.append((v, w, t + dur))           # 截止时间来自动作时长

    def actuate(self, t):
        while self.queue and self.queue[0][2] <= t:
            self.queue.pop(0)                        # 到期命令出队
        if not self.queue:
            return 0.0, 0.0                          # 无命令保持静止
        v, w, _ = self.queue[0]
        return v, w

解读：（1）决策周期 1 s 与 VLA 约 1 FPS 对应；执行长度 1.5 s 的前进命令会跨两个决策时刻，队列保证旧命令到期前不被截断。（2）VLA 超时或解析失败时插入 0.5 s 停止命令，把「模型无输出」与「模型要求停止」分开记录，真机日志据此统计降级频率。（3）actuate 返回队列头部速度，队列为空时返回零速度；这条规则覆盖论文未写的空窗期，测试用例应包含「丢一帧后剩余 0.5 s 无命令」的场景。

常见误区

  • 单位与量纲混用：症状是机器人前进距离差 100 倍或转向角度偏差过大。根因是解析器把文本数值直接送进控制器，cm、m、度、弧度在不同模块各自解释。修复：在解析边界完成换算，队列与控制器只收 SI 单位；为四种动作各写一条单元测试并断言时长。
  • 命令时长与决策频率错配：症状是转向执行到一半被新命令覆盖，机器人画弧。根因是 90° 转向需要 3.0 s，而 VLA 周期约 1 s，最新命令直接抢占执行器。修复：命令队列按截止时间出队；在「丢帧」注入下验证队列不为空；把队列深度写入日志。
  • 把 VLN 数字当 ObjectNav 口径：症状是拿 R2R-CE 的 54.0 与 ObjectNav 榜单并列。根因是 R2R 的成功判据为按指令到达并停止，ObjectNav 使用 1 m 加可见性判据，VLN-CE-Isaac 还只取 1077 条可通行子集。修复：报告标注任务、判据与子集来源；跨任务只做机制层面的类比。
  • 帧数与算力失配：症状是照搬 64 帧后推理超时，或量化后精度下滑未察觉。根因是上下文长度随帧数上升，量化在延迟与显存上的收益伴随 SR −1.5 个百分点。修复：从 8 帧起步，按延迟预算定帧数；量化前后在同一子集上复测并记录差值。
  • 真机证据外推过度：症状是引用 88% 推断任意住宅可迁移。根因是 25 条指令各 3 次的便利样本，单格约 12 次试验，复杂指令三格均值 0.7667 与摘要 75% 的口径差异也未说明。修复：按第 096 讲协议补家庭数与重复次数；报告单格样本量、失败分类与纠错失败案例。

小结

  • NaVILA 用两级框架把动作表示成带公制数值的语言串：VLA 在 4090 上约 1 FPS，运动策略实时执行，同一 VLA 换运动策略即可迁移到 Go2、H1、T1。
  • 动作换算：前进 25/50/75 cm 对应 0.5/1.0/1.5 s，转向 30°/60°/90° 对应 1.0/2.0/3.0 s；最长动作跨三个决策周期，命令队列与截止时间不可省。
  • 仿真账：R2R-CE SR 54.0 / SPL 49.0，相对 NaVid 为 +17.0 点（+45.9%）；RxR-CE SR 49.3；跨数据集 SR 34.3 对 23.8。与使用路点预测器的方法相比，NaVILA 属于可比但未全面领先。
  • 系统账：VLN-CE-Isaac 取 1077/1839 条可通行轨迹，Go2 视觉策略比盲策略 +14.0 点，H1 为 +20.9 点；低层碰撞率 0.81 对 ROA 3.09（−73.8%）；训练合计约 4928 GPU·h，AWQ 后延迟 367.80 ms、显存 8.6 GB、SR 损失 1.5 点。
  • 真机账：75 次试验，总体 88%，复杂指令三格均值 0.7667，主要失效是偏差后缺少纠错；引用时区分总体、子集与单格口径。
