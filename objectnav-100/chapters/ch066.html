第四篇 · 开放词汇与大模型

第 066 讲｜NavGPT（跨课引用）

NavGPT（Zhou 等 2023，R2R 指令跟随）是纯大语言模型（Large Language Model, LLM）的零样本视觉语言导航（Vision-and-Language Navigation, VLN）智能体：每步把视觉观察翻译成文字，连同指令与历史送进 GPT 模型，输出推理链与下一个视点。VLN-100 第 82 讲「NavGPT：纯 LLM 零样本推理」已从模型内部拆解其视觉描述管线、提示管理与推理链，本讲不重复内部结构，从 ObjectNav 视角做接口对照：目标输入、动作空间、观察表示、历史记忆、停止判据五类接口中，哪些设计能迁移到目标物体导航，哪些受任务形态限制。本讲用 R2R 验证集未见过划分（783 条轨迹、11 个场景）的主表与两套消融（216 个样本）实算数字，量化语言化观察的信息损失与调用成本，并给出移植设计表。

  • 主题：显式推理 / LLM 导航智能体 / 任务接口对照 / 文本化信息损失
  • 关键公式：⟨Rt+1, At+1⟩ = LLM( M(P), M(W), M(F(Ot)), M(H<t+1) )
  • 预计学时：70 分钟
  • 前置章节：第 065 讲（LLM frontier 范式深化）

学习目标

  • 会对照两任务接口：R2R VLN 与 ObjectNav 在目标输入、动作空间、观察表示、历史记忆、停止与成功判据五处的差异。
  • 会算：NavGPT 相对监督方法（DuET、HAMT）的指标保留率与差距，理解零训练对照（DuET-LXMERT）的含义。
  • 会解读消融：观察粒度（12、24、36 视图）、检测框信息、深度信息三组变量对成功率与路径指标的贡献。
  • 会判断信息瓶颈：字幕生成与历史摘要两次文本化的损失如何随轨迹变长累积，以及对 ObjectNav 迁移的含义。
  • 会设计：把显式推理移植到 ObjectNav 时的调用频率、记忆接口、停止接口与成本上界。

背景与动机

第 065 讲的 L3MVN 把语言模型当作前沿排序器，语言接口的内容是候选前沿的物体清单；NavGPT 更激进，把整个导航循环交给 LLM：每一步的观察被翻译成文字，历史被总结成文字，决策以推理链加动作的形式输出。它证明了显式推理可承担顶层规划，包括子目标分解、地标识别、进度跟踪与异常时的计划调整，同时给出一个诚实的负结果：零样本成绩仍明显低于监督模型。读它的价值有两层。第一层是能力边界：语言化接口在什么条件下有效、在什么条件下成为瓶颈。第二层是工程取舍：ObjectNav 应该把哪些信息留在向量与地图里，把哪些信息放进语言通道，需要一套按任务形态制定的接口对照表，本讲给出这张表。

需要先明确边界：NavGPT 做的是 VLN 任务，指令指定了一条路线，智能体沿预定义导航图逐视点前进；ObjectNav 只有类别标签，智能体在连续度量空间里自主探索，动作是 0.25 m 与 30° 的连续控制量化。任务不同，方法不能照搬，但接口可以逐项对照。VLN 侧的内部机制请回看 VLN-100 第 82 讲，本讲只取对 ObjectNav 有迁移价值的部分。

核心原理

1. 两个任务的形式化对照

VLN 的策略形式化为 π(at | W, Ot, OtC, St; Θ)：给定自然语言指令 W、当前视点观察 Ot 与可通行视点集合 OtC，在状态历史 St 条件下选择下一个视点。动作是在导航图上选一个编号视点，移动本身由仿真器完成；R2R 的成功判据是终止位置距目标在 3 m 以内，且不要求目标可见。ObjectNav 的策略输入是类别标签 c 与 RGB-D 观测，动作是六动作集（前进 0.25 m、转向 30°、俯仰 30°、停止），成功判据是停止位置距目标实例 ≤ 1 m 且满足数据集的可见性要求（Habitat 2023 挑战口径）。两套判据不是同一把尺子：3 m 与 1 m 的半径比为 3 倍，按圆形面积近似则判别区域比为 9 倍，且 ObjectNav 多一条可见性条件，跨任务比较成功率没有意义。

接口R2R VLN（NavGPT 场景）ObjectNav

2. NavGPT 的循环与推理格式

NavGPT 每一步的决策可写成统一的接口方程（Zhou 等 2023，式 1）：

⟨Rt+1, At+1⟩ = LLM( M(P), M(W), M(F(Ot)), M(H<t+1) ) P 为导航系统原则提示，W 为指令，F 把视觉观察翻译成文字，H 为历史三元组，M 为提示管理器，R 为推理文本，A 为动作。

视觉侧：每个视点取 8 个朝向乘 3 个俯仰共 24 张视角图，朝向视场 45°、间距 45° 无重叠；俯仰间距 30°、视场 45°，相邻层重叠 15°。每张图由 BLIP-2（Li 等 2023）生成描述，再取 Faster-RCNN 的检测框与仿真器深度，只保留 3 m 内的物体，最后把同朝向三层描述摘要为一句。历史侧：观察、推理、动作三元组进入缓冲，缓冲过长时用 GPT-3.5 摘要。决策侧：借鉴 ReAct（Yao 等 2022）把动作空间扩为动作加推理，先输出思考再输出动作。这一格式对 ObjectNav 的价值在推理链的位置，不在具体视点机制。

4. 消融：描述粒度与辅助信息的贡献

两组消融用 GPT-3.5 在 216 个样本（72 个场景各取 1 条轨迹、每条 3 条指令）上进行，口径与主表不同，只能作组内比较。第一组比较观察粒度：

实算差值：45° / 24 视图相对 60° / 12 视图成功率 +6.48 个百分点、SPL +6.48；相对 30° / 36 视图成功率 +2.78 个百分点、SPL +3.88。两种糟糕配置的失败机理不同：视场 60° 时画面里物体小、描述泛化；视场 30° 时单图内容太少，字幕模型难以识别；45° 在两者之间取得平衡。这说明描述粒度是需要实验选择的接口参数，不是无关的实现细节。第二组比较辅助信息：基线成功率 11.11%，加入检测框物体信息后 15.97%（+4.86 个百分点，SPL +4.79），再加入相对距离后 16.67%（+0.70 个百分点，SPL +1.29）；深度信息的贡献集中在“知道离目标多近”，修正到达目标附近后立即停止的行为。

5. 文本化瓶颈与对 ObjectNav 的含义

NavGPT 的失败根因在论文中被明确成两个信息损失点。第一是字幕损失：若指令中的目标物体没有出现在任何视角描述里，智能体只能先探索；描述粒度越粗，损失越大。第二是摘要损失：历史随步数增长时用摘要压缩，摘要丢弃细节，轨迹越长，进度跟踪越弱，异常处理越依赖近期摘要。把这条结论映射到 ObjectNav：视觉到文字的转换是可选环节，地图的占据与语义通道、检测器的类别分数、视觉语言相似度都可以直接进入决策，无需先变成文字；语言模型的优势在于注入常识与做顶层选择。第 065 讲把语言用作前沿打分器，正是把文本化限制在候选清单这一小段；第 067 讲的 VLFM 会进一步取消清单，用视觉语言模型直接给空间打分。NavGPT 留给 ObjectNav 的可迁移件因此收敛为：推理链的结构、子目标分解的提示格式、异常时的重规划思路，以及“调用要贵、频率要低”的经济性约束。

实现思路与设计

把显式推理移植到 ObjectNav，核心设计决策是“语言调用的粒度”。逐动作调用 LLM 不可行：ObjectNav 单条 episode 上限 500 步，每步一次调用意味着最坏 500 次请求，延迟与费用都失控。可行方案是把语言调用绑定到事件：新前沿出现、长期目标切换、检测到疑似目标需要验证、收到重复访问信号时触发。事件间隔远大于控制步长，调用次数从每步一次降到每 episode 十几次。

调用频率与成本估算

方案触发条件每 episode 调用量级判据
逐动作调用每个控制步最坏 500 次延迟与费用不可接受，仅作上界参考
事件触发（推荐）前沿集合变化、目标切换、验证请求约 10 到 25 次（按切换间隔 20 到 50 步估算）调用量下降约 96%，语言优势保留在顶层
离线批处理先建图、后统一规划1 到 3 次失去在线适应性，需可重置的探索策略配合

上表的 20 到 50 步是设计假设，需要按前沿更新频率实测标定；调用量 96% 的降幅由 20 / 500 与 1 − 20 / 500 两个算式给出。提示协议侧建议固定五段结构：系统原则（任务定义与输出格式）、当前目标、地图摘要（房间、已访问区域、候选前沿）、历史推理与动作、输出约定（先推理后动作）。模型版本必须固定并在实验记录中写明，原因见坑 2。

记忆与停止接口

记忆不用文本摘要，用地图加两张掩码：已访问掩码记录相机与足迹覆盖，前沿生命周期记录每个候选的产生、选中、失效时间。停止接口复用检测器：当目标类别检测分数超过阈值且估计距离进入 1 m 时触发停止；检测不到时到达无前沿状态后按数据集协议终止。推理链只写日志与触发重规划，不承担记忆职责。

与相邻讲次的关系

第 065 讲的语言入口是前沿物体清单，本讲的语言入口是完整文本循环，第 067 讲将取消文本入口，用视觉语言模型的价值图做空间打分。三讲连起来是一条信息通道的收窄与置换：从“全部文本化”到“局部文本化”，再到“免文本化”。

关键代码与解读

四段代码覆盖观察文本化、历史摘要、动作解析与 ObjectNav 适配；均为机制示意，不依赖任何未公开接口。

片段 1：多视角观察文本化

def textualize_observation(rgb_views, detector, captioner, depth_fn,
                           max_depth=3.0):
    """把 8 朝向 x 3 俯仰的视图转成一句面向决策的描述。"""
    per_heading = []
    for heading in range(8):                    # 朝向以当前机头为起点顺时针
        layers = []
        for elev in (-1, 0, 1):                 # 俯仰：下、中、上
            img = rgb_views[(heading, elev)]
            cap = captioner(img)                # 生成形状、颜色、场景描述
            boxes = detector(img)               # 类别与检测框
            near = []
            for cls, box in boxes:
                d = depth_fn(box)               # 取框中心像素深度
                if d is not None and d <= max_depth:
                    near.append((cls, d))
            layers.append((cap, near))
        # 同一朝向三层合并，保留最近物体的距离信息
        scene = merge_layers(layers)
        per_heading.append(f"direction {heading * 45} degrees: {scene}")
    return "; ".join(per_heading)

解读：（1）8 朝向乘 3 俯仰的结构让每张图保持足够内容量，同时不遗漏地面与小物体；朝向间距等于视场，无重叠，俯仰层间重叠 15° 用于衔接。（2）深度阈值 3 m 来自论文设置，作用是把远处检测噪声挡在提示之外；阈值过小会漏掉房间对面的关键物体。（3）描述按“以当前朝向为起点顺时针”排列，与后续提示模板的方位表述绑定，改动顺序会破坏方向词与观测的对应。

片段 2：历史缓冲与摘要组装

class HistoryBuffer:
    """保存 (观察, 推理, 动作) 三元组；超长时压缩早期项。"""

    def __init__(self, llm_summarize, max_items=6):
        self.items = []
        self.summarize = llm_summarize
        self.max_items = max_items

    def append(self, obs_text, reasoning, action):
        self.items.append((obs_text, reasoning, action))
        if len(self.items) > self.max_items:
            old = self.items[:-self.max_items]
            merged = self.summarize(old)        # 生成一段历史摘要
            self.items = [("summary", merged, "-")] + self.items[-self.max_items:]

    def render(self):
        lines = []
        for obs, reason, act in self.items:
            tag = "[past summary]" if obs == "summary" else "[observed]"
            lines.append(f"{tag} {obs}\n[reasoning] {reason}\n[action] {act}")
        return "\n".join(lines)

解读：（1）保留最近 6 条原始三元组，更早的压缩为摘要，控制提示长度；max_items 是接口参数，调大更保真但更快触顶上下文窗口。（2）摘要由另一个模型完成，本身引入二次信息损失，且摘要质量随被压缩内容复杂度下降；复现时应分别记录原始与摘要两路的历史。（3）渲染格式中保留推理文本，让后续决策继承此前的子目标与计划，这一项是可迁移到 ObjectNav 的关键设计。

片段 3：动作解析与非法输出回退

def parse_action(llm_output, valid_ids, last_action=None):
    """从模型输出解析视点编号；非法或缺失时回退到安全动作。"""
    import re
    match = re.search(r"action\s*[:：]\s*(\d+)", llm_output)
    if match is None:
        return last_action if last_action in valid_ids else min(valid_ids)
    idx = int(match.group(1))
    if idx not in valid_ids:
        # 模型可能编造不存在的编号，回退到离目标朝向最近的合法视点
        return last_action if last_action in valid_ids else min(valid_ids)
    return idx

def make_decision(prompt, llm_generate, valid_ids, last_action=None):
    """一次决策：生成推理与动作，解析失败时按回退策略处理。"""
    text = llm_generate(prompt, stop=["Observation:"])
    thought = text.split("Action")[0].strip()
    action = parse_action(text, valid_ids, last_action)
    return thought, action

解读：（1）解析器对格式噪声与编号编造都做了防护；编号编造是文本接口最典型的不确定性，必须在系统原则提示里明确禁止并保留回退路径。（2）回退到上一次合法动作或最小合法编号只是保底，工程上更好的是回退到几何可达的最近候选；该决策点的选择规则应写入实验记录。（3）推理文本与动作分开解析，推理只进历史与日志，动作才执行，避免推理中的假设被误当作指令。

片段 4：ObjectNav 适配层（前沿选择）

def adapt_to_objectnav(frontiers, goal, llm_generate):
    """把显式推理输出映射为前沿选择，与第 065 讲的融合规则衔接。"""
    lines = [f"F{i}: objects near frontier: {', '.join(objs)}"
             for i, (objs, _s_cu) in enumerate(frontiers)]
    prompt = (
        "You are a search planner. Goal: {g}.\n"
        "Candidate frontiers:\n{lines}\n"
        "First reason about which room each frontier likely leads to, "
        "then output 'choice: <index>'."
    ).format(g=goal, lines="\n".join(lines))
    text = llm_generate(prompt)
    import re
    m = re.search(r"choice\s*[:：]\s*(\d+)", text)
    if m is None or not (0 <= int(m.group(1)) < len(frontiers)):
        # 语言输出不可用：退回代价效用分数最高的前沿
        return max(range(len(frontiers)), key=lambda i: frontiers[i][1])
    choice = int(m.group(1))
    return choice

解读：（1）适配层把“候选前沿清单”文本化，明显窄于 NavGPT 的全观察文本化，信息损失可控；这正是第 065 讲 L3MVN 的接口形态。（2）语言输出非法时回退到纯几何排序，与第 065 讲的带宽融合配合使用，保证系统始终可运行。（3）提示要求先推理后选择，推理文本可作调试日志；若把推理文本回灌给控制回路，需要新的事件触发规则，避免每步调用。

常见坑

  • 跨任务比较成功率：症状是宣称“NavGPT 的 34% 相当于 ObjectNav 的某个水平”。根因是 R2R 成功口径为 3 m 误差，ObjectNav 为 1 m 加可见性，判别区域相差一个量级。修复：只做接口对照，不做成绩换算；需要换算时明确写出两套判据并附推导。
  • 模型版本混用：症状是引用 34% 成功率的同时引用 16.67% 的消融结论。根因是主表用 GPT-4，消融用 GPT-3.5，且消融只覆盖 216 个样本。修复：引用时标注模型与样本口径；把消融结论限定为组内相对关系。
  • 把描述粒度当实现细节：症状是复现时随手选视场与视图数，结果成功率显著低于报告值。根因是字幕质量对粒度敏感，60° 与 30° 两种配置分别损失 6.48 与 2.78 个百分点。修复：粒度作为显式超参做网格实验，记录字幕样例并人工抽检。
  • 摘要压缩吞掉进度信息：症状是长指令后段反复走错，重规划频繁。根因是历史摘要二次损失随轨迹增长累积。修复：保留最近若干条原始三元组；把关键进度写成结构化字段（已完成的子目标列表），与自由文本摘要并行。
  • 逐动作调用 LLM：症状是仿真步速被接口延迟拖垮，费用失控。根因是把 R2R 的每步决策直接搬到 500 步预算的 ObjectNav。修复：语言调用绑定到事件（前沿变化、目标切换、验证请求）；对调用次数设硬上界并监控。
  • 用推理文本回灌评测：症状是生成轨迹图或反向指令时指标虚高。根因是推理链包含未来信息或目标信息，泄漏进生成结果。修复：评测生成任务时隔离推理链，只使用动作与观察流；数据划分与提示模板一并写入实验记录。

练习与思考

  1. 用主表计算 NavGPT 相对 DuET 的成功率、SPL、OSR 保留率，并解释导航误差是 HAMT 的 2.82 倍、轨迹长度却只有 DuET 的 82.14% 这一组合说明了什么。★
    提示
    保留率分别为 47.22%、48.33%、51.85%。轨迹更短而误差更大，说明失败集中在“走到附近但没停在目标”与“方向错误提前终止”，长距离绕行不是主因；NE 高而 TL 低也提示停止决策与进度判断是主要短板。
  2. 解释零训练 DuET-LXMERT（SR 1%、SPL 0）与零样本 NavGPT（SR 34%、SPL 29）的差距来源，并说明该对照为何能支持“推理与常识在起作用”。★★
    提示
    DuET-LXMERT 只有未训练的跨模态编码器与图结构，没有任何语义推理能力；NavGPT 用预训练 LLM 的常识做子目标分解与地标匹配。两者都没有在 R2R 上训练，差异只能来自模型内知识与推理，这就是对照的设计意图。
  3. 预测把 24 视图换成 12 视图（视场 60°）后成功率与 SPL 的变化幅度，并解释深度信息加入后只有 +0.70 个百分点成功率增益、却有 +1.29 SPL 增益的原因。★★
    提示
    参考消融，成功率从 16.67% 降到 10.19%（−6.48），SPL 从 13.00 降到 6.52。深度信息主要修正“目标在视野内就提前停”的行为，让成功轨迹停在更近的位置，路径效率提升明显，但对本来就可能失败的 episode 帮助有限，因此成功率增益小。
  4. 设计 ObjectNav 版显式推理适配层：写出五类接口的具体方案（目标、动作、观察、记忆、停止），给出调用频率的触发条件、每 episode 调用上界与一个失败回退规则。★★★
    提示
    目标：类别标签加房间先验；动作：候选前沿枚举；观察：地图摘要（已探索比例、候选清单、检测结果）；记忆：已访问掩码与前沿生命周期，不压缩文本；停止：检测分数加 1 m 距离双条件。触发：前沿集合变化或目标切换时调用，调用上界设 25 次；回退：语言输出非法或超时时退回几何分数最高的前沿，并记录事件。
  5. 从成本角度比较三种调用方案（逐动作、事件触发、离线批处理），给出每 500 步 episode 的调用量与适用条件，并说明为什么 ObjectNav 更适合事件触发。★★
    提示
    逐动作约 500 次，事件触发约 10 到 25 次（降幅约 96%），离线批处理 1 到 3 次。ObjectNav 是探索任务，前沿更新频率远低于控制步频，且语言只参与顶层选择，事件触发既保住常识注入又控制成本；离线批处理失去在线适应性，适合已知地图场景。

小结

  • 接口对照是跨任务阅读的核心：目标输入、动作空间、观察表示、历史记忆、停止判据五处差异决定了哪些模块可迁移；R2R 的 3 m 成功率与 ObjectNav 的 1 m 加可见性判据不可互算。
  • 主结果实算：NavGPT 零样本 SR 34%、SPL 29、OSR 42%，相对 DuET 的保留率为 47.22%、48.33%、51.85%；NE 6.46 m 是 HAMT 的 2.82 倍，TL 11.45 却只有 DuET 的 82.14%。
  • 消融实算：45° / 24 视图相对 60° / 12 视图成功率 +6.48 个百分点；检测框信息 +4.86 个百分点；深度信息 +0.70 个百分点但 SPL +1.29，主要修正提前停止。
  • 瓶颈在两次文本化：字幕损失与摘要损失随轨迹增长累积；对 ObjectNav 的启示是让地图与检测分数留在结构化通道，语言只做顶层推理与选择。
  • 工程结论：语言调用绑定到事件，不绑定到控制步，调用量从最坏 500 次降到 10 到 25 次；停止与记忆接口分别由检测器和地图承担。
