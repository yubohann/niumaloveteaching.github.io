第三篇 · 端到端与配方

第 053 讲｜OVRL-v2 I：ViT+压缩层

第 049 至 052 讲的主线配方以 ResNet50 表征加 GRU 策略为核心。OVRL-v2（Yadav 等 2023，论文题名 OVRL-V2: A Simple State-of-art Baseline for ImageNav and ObjectNav）提出另一条路线：只用任务无关组件（ViT、卷积、LSTM）构成单一架构，在 ImageNav 上取得 82.0% 成功率与 58.7% SPL，在 ObjectNav 上与同期最好方法接近（64.0% 对 65.0%，HM3DSem v0.1 test-standard）。本讲拆解架构与参数账：vanilla ViT 为何输给 ResNet，压缩层如何用一次卷积修复空间结构，掩码自编码预训练的数据从哪来，以及各方案的参数代价。

  • 主题：通用架构 / ViT / 压缩层 / 自监督预训练
  • 关键公式：Z = Flatten(ReLU(GroupNorm(Conv3×3(Reshape(P))))) ∈ ℝB×N·L，N = round(2048 / L)
  • 预计学时：80 分钟
  • 前置章节：第 052 讲（失败模式工具箱）

学习目标

  • 会推导：patch 序列重排为二维网格再压缩的完整张量路径，说明 [CLS] 汇总与全局平均池化丢失空间结构的机制，写出输出维度公式并给出适用条件。
  • 会算：给定 patch 数 L 与目标维度 2048，算出每 patch 通道数与实际输出维度，核算压缩层参数量及其在 agent 总参数量中的占比。
  • 会实现：PatchReshape 与压缩层的 PyTorch 代码，正确处理批次维、方形网格假设与边界情形。
  • 会判断：从零训练时 ViT 与 ResNet 的取舍、预训练开关对架构规模的否决作用、域内预训练数据与通用视觉语言模型的差别。
  • 会读：ImageNav 与 ObjectNav 观察口径（分辨率、视场、动作集、GPS+Compass）对编码器设计的影响，并标出每条数字的协议来源。

背景与动机

截至第 052 讲，本课程端到端主线的主力配置是 ResNet50 表征加循环策略：第 043 讲讲表征预训练，第 044 讲讲 CLIP 骨干，第 046 讲讲辅助任务与探索，第 049 讲讲行为克隆加强化学习微调。这套配方的性能已经很强（PirlNav 在 HM3D-Semantics v0.1 上 65.0% / 33.0%），但有两个悬而未决的问题。第一，卷积网络的配方成熟，容量扩展带来的收益有限，全宽 ResNet50 相对半宽只把 ImageNav 成功率从 59.9% 提到 60.0%（Yadav 等 2023，附录表 E）。第二，视觉社区的经验表明，自监督预训练的 ViT 可以随规模稳定获益，而在具身导航里这条规律尚未被观察到。

OVRL-v2 的出发点是把问题推到极限：若完全放弃目标检测、语义分割、建图与规划模块，只用任务无关的神经网络组件，能否在两个语义导航任务上同时达到最好水平。作者报告的直接障碍是，朴素地把 ResNet 换成 ViT 会显著退化：从零训练的 ViT-Small 在 ImageNav 上只有 36.1% 成功率，而半宽 ResNet50 有 59.9%，尽管前者的 agent 参数量是后者的约 2.37 倍。诊断结论是空间结构被破坏：分类任务惯用的 [CLS] 汇总与全局平均池化都把 patch 的二维排布压掉了，而导航恰恰需要知道线索在画面中的位置。

本讲聚焦架构与参数账，包括压缩层的张量路径、维度与参数实算、掩码自编码预训练的数据口径，以及奖励与训练配方的架构相关部分。双任务结果与 scaling 证据留到第 054 讲，适用边界与失效模式留到第 055 讲。三讲共用同一主来源（arXiv:2303.07798，v1，2023-03-14）。

核心原理

本节先固定两个任务的观察口径，再讨论 ViT 表示的结构问题与压缩层的数学形式，最后给出从零训练与预训练的对照证据。所有指标均来自 Yadav 等（2023）的 ImageNav Gibson 验证集与 ObjectNav HM3DSem v0.1 协议，逐条标注。

2. ViT 的 patch 表示与空间结构问题

ViT（Vision Transformer）把图像切成不重叠的 16×16 patch，每个 patch 经线性投影成一个 token，再拼接一个 [CLS] token 送入 Transformer。128×128 输入得到 (128/16)² = 64 个 patch token，加 [CLS] 共 65 个 token。标准 ViT-Small 的 patch 嵌入维度 D = 384，ViT-Base 的 D = 768。分类任务通常用两种方式把 token 序列汇总成图像表示：取 [CLS] 的输出，或对所有 patch token 做全局平均池化（Global Average Pooling，GAP）。

这两种汇合都丢掉了 patch 的二维排布信息。设 patch 特征矩阵为 P ∈ ℝL×D，[CLS] 读出的是整幅图的全局摘要，GAP 计算 (1/L)·Σi Pi，两者都把「哪一块 patch 长什么样」折叠掉了。对分类而言这种折叠是可接受的，类别信息在全局统计里依然保留；对导航而言，智能体需要判断目标线索在画面中的方位，并据此决定朝哪转、在哪停，位置信息直接进入控制回路。从零训练时，容量更大的 ViT 败给较小的 ResNet，说明瓶颈在表示结构，与参数容量无关。

3. 压缩层：保留空间结构的张量路径

压缩层（compression layer）的做法是把 patch 序列还原成网格，用卷积在通道方向压缩，再展平。完整路径如下，设批次大小为 B，patch 数为 L，patch 维度为 D，且输入为方形图像，因此 H = W = √L：

P ∈ ℝB×L×D → Reshape → ℝB×H×W×D → Permute → ℝB×D×H×W → Conv3×3 → ℝB×N×H×W → Flatten → ℝB×N·L N = round(2048 / L)；卷积核 3×3、边界填充 1、无偏置，随后接单组 GroupNorm 与 ReLU

输出维度 N·L 被设计为接近 2,048。取 L = 64 时 N = 32，输出恰为 2,048；L = 196 时 N = 10，输出 1,960；L = 256 时 N = 8，输出 2,048。这样做的好处是下游 LSTM 的输入规模保持稳定，换用不同分辨率或不同 patch 数量的编码器时不需要重设策略网络的大部分接口。代价是当 L 不是 2,048 的近似因子时输出维度会略偏离目标，最大偏差在常用配置下约为 4.3%（L = 196 的情形）。

压缩层的参数量很小。3×3 卷积的参数量为 D·N·9：ViT-Small 的 D = 384、N = 32 时是 110,592，约 0.11M；ViT-Base 的 D = 768、N = 32 时是 221,184，约 0.22M。相对 agent 总参数 50.9M 与 179.2M，占比分别为约 0.217% 与 0.123%。它的作用在结构：用极小的参数代价换回二维邻接关系，让后续卷积能同时看到相邻 patch。

5. 掩码自编码预训练与数据口径

MAE（Masked Autoencoder，掩码自编码器，He 等 2022）的流程是：把图像切成 patch，随机遮住 75% 的 patch，编码器只处理剩余 25%，小型解码器根据编码结果重建整幅图，预训练结束后丢弃解码器、保留编码器。高掩码率可行，依赖自然图像 patch 之间的冗余。OVRL-v2 对 ViT-Small 与 ViT-Base 都从零开始做 800 轮 MAE 预训练，编码器随后用于 ImageNav 与 ObjectNav 两个任务。

预训练数据名为 HGSP（HM3D-Gibson Shortest Path）：从 800 个 HM3D 训练场景与 72 个 Gibson 训练场景采集，共 872 个场景；让 oracle 智能体沿最短路径从随机起点走到随机终点，采集 1.45M 张 512×512、90° 视场的 RGB 图像。选 1.45M 这个规模有依据：上一代 OVRL（Yadav 等 2022）发现，用 Omnidata Starter Dataset（OSD，共 14.5M 张）的 10% 预训练即可达到与全量相同的下游性能，1.45M 恰为 14.5M 的 10%。与下游 128×128 的观察相比，预训练图像为 512×512，单幅面积是 16 倍；这提供了高分辨率的细节监督，而下游推理仍保持低分辨率以控制算力。

对照实验回答了「域内数据还是通用表示」的问题。CLIP 权重冻结时 ImageNav 为 51.7% / 37.4%，可微调时 65.5% / 47.7%；MAE 域内预训练为 82.0% / 58.7%，比可微调 CLIP 高 16.5 点 SR（相对 +25.19%）。Data2Vec 预训练得到 81.0% / 59.3%，与 MAE 接近，SR 低 1.0 点、SPL 高 0.6 点。把预训练数据从 HGSP 换成 OSD，结果为 81.1% / 57.5%，与 HGSP 的 82.0% / 58.7% 接近。合起来看，关键因素是与下游域匹配的图像分布，数据来源的具体选择影响较小。

6. 奖励修正与训练配方的架构相关部分

ImageNav 用 DD-PPO 训练，奖励由三部分组成：稀疏成功项、到达目标的测地距离增量、每步松弛罚项。ZER（Al-Halah 等 2022）在此之上加了朝向角奖励，但该项可在目标半径内外反复进出以累积，训练回报上升而验证 SPL 与 SR 下降（奖励被钻空子，原文称 reward hacking）。OVRL-v2 的修正是把朝向角项改写成势函数差分：定义 θ̂t = θt（当 dt < rg），否则 θ̂t = π。于是该项在半径外恒为 0，进入半径时为正、退出时付回同等负值，形成零和路径。

θ̂t = θt，若 dt < rg；θ̂t = π，若 dt ≥ rg
rt = cs·[dt < rg ∧ at = STOP] + ca·[θt < θg ∧ at = STOP] + (θ̂t−1 − θ̂t) + (dt−1 − dt) − γ cs = 5.0，ca = 5.0，rg = 1.0 m，θg = 25°，γ = 0.01（每步）

零和性质可以用一组角度算例验证：180° → 60° → 10° → 180° 对应奖励增量 +120 + 50 − 170 = 0。角度单位在实现中按弧度计算，此处用度数列出便于核对方向。注意每步罚项 γ = 0.01 与成功项 cs = 5.0 的量级关系：500 步无塑形轨迹的累计罚项为 5.0，恰好抵消一次成功奖励。这解释了奖励塑形的不可或缺：仅有稀疏成功与每步罚项时，长路径的成功样本回报接近零，优势估计难以区分好坏轨迹。

与架构直接相关的其余配方还有三点，细节在第 054 讲展开。其一是删除输入图像的预下采样（AvgPool）操作，ImageNav 成功率从 27.7% 升到 60.6%（+32.9 点），SPL 从 18.8% 升到 27.9%。其二是编码器使用独立的小学习率：ImageNav 主体学习率 2.5×10−4、编码器 1.5×10−6，相差约 166.7 倍；用错学习率（主体同值的 2.5×10−4 直接作用于编码器）时成功率为 51.0%，低于完全冻结编码器的 61.8%。其三是训练与测试阶段都施加颜色抖动与随机平移增强：ImageNav 用亮度/对比度/饱和度/色相 0.3 与 4 像素平移，ObjectNav 用 0.4 与 16 像素平移。

实现思路与设计

实现重点是把「观察编码、目标编码、姿态编码、时序策略」四段拼成单一网络，并让观察编码器在两种输入分辨率下都能接到固定规模的策略输入。观察编码器与压缩层是任务无关组件，目标编码与姿态编码按任务开关。

import torch.nn as nn

class PatchReshape(nn.Module):
    """把 (B, L, D) 的 patch 序列还原为 (B, D, H, W) 网格。"""
    def forward(self, x):
        B, L, D = x.shape                 # 批大小、patch 数、patch 维度
        H = W = int(L ** 0.5)             # 论文输入均为方形，网格为方阵
        if H * W != L:
            raise ValueError("patch 数必须为完全平方数")
        x = x.reshape(B, H, W, D)         # 还原二维邻接关系
        return x.permute(0, 3, 1, 2)      # 通道维前置，供卷积使用

def create_compression_layer(patch_dim, num_patches, approx_output_size=2048):
    """每个 patch 压成 N 个通道，展平后输出 N * num_patches 维。"""
    num_channels = int(round(approx_output_size / num_patches))
    layer = nn.Sequential(
        PatchReshape(),
        nn.Conv2d(patch_dim, num_channels, kernel_size=3, padding=1,
                  bias=False),            # 3x3 邻域融合，参数 D*N*9
        nn.GroupNorm(num_groups=1, num_channels=num_channels),
        nn.ReLU(inplace=True),
        nn.Flatten(),                     # 保留逐 patch 的独立特征
    )
    return layer, num_channels * num_patches

解读：（1）重排把序列顺序还原为二维邻接，reshape 之后同一行的 patch 在内存中相邻，permute 只改视图不复制数据，代价是一次廉价的重排。（2）卷积用 padding=1、kernel=3，输出网格与输入同尺寸，空间分辨率不降，压缩只发生在通道方向；这与池化式降采样不同，patch 级的位置精度被完整保留。（3）无偏置卷积加单组 GroupNorm，归一化在通道维整组进行，避免小批次下 BatchNorm 统计不稳。（4）输出维度恰好为 N·L，调用方据此设置全连接维度；若 L 变化，只需保证上游能整除或近似整除 2,048。

片段 2：维度与参数核算

def compression_dims(num_patches, patch_dim, approx_output_size=2048):
    """返回 (每 patch 通道数, 输出维度, 相对 2048 的比, 卷积参数量)。"""
    channels = int(round(approx_output_size / num_patches))
    output = channels * num_patches
    conv_params = patch_dim * channels * 3 * 3     # 无偏置
    return channels, output, output / approx_output_size, conv_params

for L in (64, 100, 196, 256):                      # 128x128、160x160 等输入
    n, out, ratio, p = compression_dims(L, patch_dim=384)   # ViT-Small
    print(f"L={L:3d}  channels={n:2d}  out={out:4d}  "
          f"ratio={ratio:.3f}  conv={p / 1e3:.1f}K")
# L= 64  channels=32  out=2048  ratio=1.000  conv=110.6K
# L=100  channels=20  out=2000  ratio=0.977  conv= 69.1K
# L=196  channels=10  out=1960  ratio=0.957  conv= 34.6K
# L=256  channels= 8  out=2048  ratio=1.000  conv= 27.6K
print("ViT-Base L=64:", compression_dims(64, patch_dim=768)[3] / 1e3, "K")
# ViT-Base L=64: 221.2 K   (卷积参数随 patch 维度线性增长)

解读：（1）输出维度围绕 2,048 上下浮动，L = 196 时最低到 1,960，偏差 4.3%；如果下游接口写死 2,048，这个偏差会在加载权重时暴露，核算脚本应作为单元测试的一部分。（2）卷积参数量只随 patch 维度与通道数增长，与输入分辨率无关；从 ViT-Small 换到 ViT-Base，参数从 110.6K 翻倍到 221.2K，仍不到 agent 总参数的 0.25%。（3）核算脚本独立于训练代码，用于在改分辨率或换编码器时快速确认新配置的输出维度，避免把形状错误拖到训练中途才暴露。

常见坑

  • [CLS] token 直接当观察特征：症状是 ViT 明明容量更大，训练损失降得动，验证成功率却掉到 36.1%（ImageNav，从零）。根因是 [CLS] 汇总丢掉了 patch 的二维排布，控制回路拿不到线索方位。修复：接入压缩层保留网格结构；同一实验里压缩层把成功率抬到 67.4%。
  • 看到预训练后 GAP 的 SPL 接近就断言两种汇总等价：症状是用 GAP 省事，SR 却比压缩层低 5.1 点（76.9% 对 82.0%）。根因是平均池化对停止位置的判别信息不足。修复：以 SR 为主排序量选择汇总方式，SPL 作为辅助；若部署更看重路径效率，再按业务代价权衡。
  • 压缩层输出维度按 floor 取整或不取整：症状是全连接层维度与期望不符，或 L 变化后训练中断。根因是 N = round(2048/L) 的取整规则与调用方约定不一致。修复：统一使用 round，把 compression_dims 作为单元测试；L = 196 时输出 1,960，接口需接受该值。
  • 用通用视觉语言预训练替代域内预训练：症状是冻结 CLIP 权重时 ImageNav 只有 51.7%，微调后也只到 65.5%，低于 MAE 的 82.0%。根因是域外数据与导航观察分布不匹配，冻结权重更无法适应。修复：优先采集与下游同域、同视场的图像做自监督预训练；若必须用通用模型，至少对其权重微调并在报告中标注口径。
  • 忽略两端观察口径直接迁移超参：症状是把 ImageNav 的编码器学习率、增强强度搬到 ObjectNav 后训练不稳或过拟合。根因是分辨率、视场、动作集与演示监督都不同（640×480 对 128×128，行为克隆对在线 RL）。修复：按下表口径逐项核对，编码器学习率在 ImageNav 取 1.5×10−6、ObjectNav 取 1.0×10−4，增强参数分别取 0.3/4 与 0.4/16。

  2. 解释为什么空间结构对「成功率」的影响大于对「SPL」的影响。用表 7b 的 [CLS]、GAP、压缩层三行数据支撑论点，并设计一个能区分「位置信息」与「参数量差异」的解释性实验。★★
    提示
    成功率要求停在正确位置，位置判别依赖网格结构；SPL 主要由路径策略决定，汇总方式影响较小。对照实验可固定参数量：给 [CLS] 分支加同规模的无关全连接层，或把压缩层的 3×3 卷积换成 1×1 卷积（去掉邻域），比较网格结构有无的差异。
  3. 实现片段 1 的压缩层，补写输入形状检查：当 L = 49、L = 196 时各说明网格边长，并验证输出维度与 compression_dims 的返回值一致；再指出方形假设在非方形输入下应如何扩展。★★

小结

  • OVRL-v2 用任务无关组件组成单一架构：ViT 观察编码器、压缩层、目标编码、GPS+Compass 姿态编码与 LSTM 策略；ImageNav 与 ObjectNav 共用预训练编码器，仅目标编码与训练监督不同。
  • 从零训练时，[CLS] 与全局平均池化分别只有 36.1% 与 35.0% 成功率（ImageNav，128×128），压缩层为 67.4%；容量更大的 ViT 败给半宽 ResNet50 的 59.9%，瓶颈在空间结构。
  • 压缩层把 patch 序列还原为 H×W 网格，经 3×3 卷积把每 patch 通道数压到 N = round(2048/L)，展平输出约 2,048 维；L = 64 时卷积参数约 0.11M（ViT-S），占 agent 总参数约 0.217%。
  • MAE 以 75% 掩码率在 HGSP（872 个场景、1.45M 张 512×512 图像，沿用 OVRL 的 10% OSD 结论）上预训练 800 轮；域内预训练是关键词，CLIP 冻结 51.7%、微调 65.5%，均低于 MAE 的 82.0%。
  • 奖励侧用势函数差分修正朝向角塑形，进入与退出目标半径的奖励互相抵消；常数取 cs = 5.0、ca = 5.0、rg = 1.0 m、θg = 25°、每步罚 0.01。
  • 下一讲给出双任务完整结果与 scaling 证据：预训练把 ViT-Small 的 ImageNav 成功率从 67.4% 提到 80.5%，并让 ViT-Base 相对 ViT-Small 转为正向收益（82.0% 对 80.5%）。
