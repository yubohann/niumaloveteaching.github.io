第五篇 · 真机、Sim2Real 与系统集成

第 099 讲｜结课 II：复现与算力清单

第 098 讲给出了路线图，本讲回答「这条路要花多少资源」。复现按四档组织：T0 免训练零样本模块化（单卡 16 至 24 GB，数天），T1 行为克隆与轻量微调（1 至 8 卡，10M 至 500M 帧量级），T2 全量强化学习（8 至 64 卡，300M 至 2.5B 步），R 档真机（一台机器人加一台工作站）。核心公式只有两条：墙钟 W = N / (SPS总 × η)，成本 C = 卡数 × 墙钟 × 单价。用第 059 讲 Habitat 2.0 的实测吞吐（单进程 Interact 510 SPS、八卡 7699 SPS）核算：2.5B 步纯交互口径为 90.2 小时、721.6 GPU-时，端到端 DD-PPO 口径为 176 GPU-天、约 3802 美元，两者相差 5.85 倍，口径必须标注。隐藏成本同样入账：77k 条演示采集约 2377.8 人时（约 297.2 人日），零样本评测若按 VLFM 的 1.67 帧/秒跑 2000 条 episode 约需 99.8 小时。本讲给出四档路线、版本锁定清单、样本量表与 12 周计划模板。

  • 主题：复现路线 / 算力核算 / 版本锁定 / 数据与评测准备
  • 关键公式：W = N / (SPS总 · η)；C = P · W · c；n ≈ (zα/2 + zβ)2 [p1(1−p1) + p2(1−p2)] / Δ2
  • 预计学时：90 分钟
  • 前置章节：第 098 讲（结课 I：方法路线图复盘）

学习目标

  • 会算：由步数预算、总吞吐与仿真占比求墙钟，由卡数与单价求成本；复算 2.5B 步的纯交互口径（721.6 GPU-时）与端到端口径（4224 GPU-时）。
  • 会分档：为给定硬件、数据与目标选择 T0 / T1 / T2 / R 四档复现路线，并写出该档的验收指标与证据等级。
  • 会准备：列出 Habitat-Lab 与 Habitat-Sim 的版本锁定项、四个数据集的版本口径、episode 与种子的固定方式。
  • 会判断：识别纯仿真 SPS 与训练有效吞吐的量级差、演示采集与推理的隐藏成本、评测样本量不足三类失效。
  • 会设计：写出一份 12 周复现计划，含阶段门、成本上界、降级路线与失败分类。

背景与动机

第 098 讲把方法排成路线，落地时最先撞到的往往是资源与版本问题：仿真环境装不起来、训练预算估错一个数量级、演示数据没人采、评测集太小导致结论翻转。本课程此前的工程数字散落在各处，本讲把它们收成一份可直接执行的清单：第 009 讲的版本冻结与安装顺序，第 017 讲的 GPU-天与单价，第 042 讲的 100M 冒烟与同步扩展，第 049 讲的演示规模与两阶段配置，第 059 讲的 SPS 测量与墙钟换算，第 058 讲的样本量与 Wilson 区间。

复现的目标也需要分层。数字复现指同协议同划分下与原文相差在评测噪声内；趋势复现指消融与基线排序方向一致；机制复现指替换组件后行为变化与原文解释吻合。多数课题组没有资源做数字复现，却常常拿趋势复现的投入去承诺数字复现的结论。本讲先给四档路线与验收线，再给成本与数据清单，最后交给第 100 讲，把清单上仍空着的格子转成开题方向。

核心原理

1. 两个公式与三类计数

训练墙钟由步数预算、总吞吐与训练有效利用率决定：

W ≈ N / (SPS总 · η)，η ≈ t仿真 / (t仿真 + t推理 + t优化摊销) N 为环境步预算；SPS总 为聚合仿真吞吐；η 为仿真段占比（第 059 讲口径）

成本由卡数、墙钟与单价相乘：C = P · W · c。第 017 讲给出的折算单价为单卡时 0.9 美元（8 卡机每小时 7.2 美元）。三类计数必须分清：环境步（2.5B 指环境步）、智能体步与 episode 数；一条 500 步上限的 episode 只对应 500 个环境步，把 2.5B 步读成 2.5B 次导航会把 episode 数高估约 500 倍。

3. 数据与仿真准备：版本敏感项

4. 评测预算与样本量

挑战口径给出一个可直接复用的预算：1000 条 episode、48 小时墙钟，折合每条约 172.8 秒、每步（500 步上限）约 0.3456 秒，即仿真加策略合计吞吐不低于 2.89 步/秒。自建评测按同一公式缩放：总墙钟 = episode 数 × 平均步数 / 实测吞吐。样本量按第 058 讲的两组比例差公式计算，下表列出常用档，全部假设双侧 α = 0.05 与 80% 功效。

要分辨的成功率差基线档每组所需 episode适用场景
10 个百分点10% 对 20%197低基线大改进；初筛够用
5 个百分点55% 对 60%1,531中高基线的方法消融
5 个百分点60% 对 65%1,468高位方法的配方比较

真机侧样本更少，只能用区间累积。参考两则：SemExp 真机 20 次 13 次成功的 Wilson 95% 区间为 [43.3%, 81.9%]；LANav 真机 50 次 41 次成功的区间为 [69.2%, 90.2%]。区间宽度随重复次数收缩，报告真机结果时点估计、次数与区间三项同时给出；区间重叠时不写排序结论。若目标是分辨 10 个百分点的真机差别，每组需要约 197 次，按每次会话可跑 10 至 20 次计，意味着至少 10 至 20 个会话，排期时要预留。

5. 隐藏成本：推理、存储与人工

三类成本最容易漏。推理成本：零样本管线不是免费的，OVAL 实测 VLFM 约 1.67 帧/秒、OVAL 约 1.14、GOAT 约 1.85。按 VLFM 的 1.67 帧/秒与平均 300 步/幕估算，2000 条 episode 需 2000 × 300 / 1.67 ≈ 359,281 秒，约 99.8 小时；对照快慢 ReAct 式的事件触发设计，平均每幕仅 5.00 次深思调用、205 个环境步，2000 条 episode 的仿真在八卡上约 53 秒，1 万次调用按每次 0.5 秒合计约 1.39 小时，总计约 1.4 小时。同样规模的评测，设计差异带来约 70 倍的墙钟差。存储成本：把观测逐帧物化并不经济。77k 条演示按平均 155.8 步、每帧 256×256 RGB-D 约 448 KiB 估算，原始容量约 5.50 TB（5.01 TiB）；640×480 口径下 2000 条 500 步 episode 约 2.15 TB（1.96 TiB）。只存 episode、动作与最短路径，观测在评测与训练时现场渲染，既省容量也省读取延迟。训练检查点按参数量算：OVRL-v2 的 179.2M 参数在 fp32 下约 716.8 MB，连同梯度与优化器状态约 2.87 GB（2.67 GiB），需要按检查点频率预留磁盘。人工成本：演示采集 297.2 人日是排在卡租之前的约束，先定数据预算再定训练预算。

6. 边界与失效

四条边界写进计划书。其一，吞吐随配置漂移：第 059 讲的 510 与 7699 SPS 来自 ReplicaCAD 与 Fetch、128×128 双相机；换成 HM3D 全屋扫描、640×480 或多相机，必须重测。其二，纯仿真上限不等于训练可达：端到端账目与纯交互口径相差 5.85 倍，规划用端到端口径，任何「极限吞吐」表述标注口径。其三，冻结项目的版本风险：Habitat-Lab v0.3.4 之后无官方适配，新硬件与新的数值库大版本都可能破坏环境，锁文件、离线包缓存与容器是标准缓解手段（版本与维护状态沿用第 009 讲的归档记录，本讲写作时未能重新联网复核上游页面）。其四，零样本模型的接口风险：VLM 服务的延迟、限流与停服不可控，实验报告要记录模型名、调用参数与失败率，并准备本地小模型降级路径。

关键代码与解读

三段代码分别实现成本核算、档位选择与准备清单校验，均用本讲的公开数字验证。

片段 1：墙钟与成本核算

def repro_budget(steps, sps, gpus, eta=1.0, price=0.9):
    """由步数、聚合吞吐、卡数与仿真占比估算墙钟与成本。"""
    hours = steps / (sps * eta) / 3600.0
    gpu_hours = hours * gpus
    return {"wall_hours": round(hours, 2),
            "wall_days": round(hours / 24.0, 2),
            "gpu_hours": round(gpu_hours, 1),
            "cost_usd": round(gpu_hours * price, 1)}

# 八卡 Interact 纯交互口径（第 059 讲）
print(repro_budget(2.5e9, 7699, 8))          # 90.2 h / 3.76 d / 721.6 GPU-h / 649.4 USD
# 单卡 510 SPS，同一步数
print(repro_budget(2.5e9, 510, 1))            # 1361.66 h / 56.74 d / 1361.7 GPU-h / 1225.5 USD
# 端到端口径：2.5B 步在 64 卡上 2.75 天（DD-PPO，V100）
sps_agg = 2.5e9 / (2.75 * 86400)              # 聚合吞吐约 10522 步/秒（单卡约 164.4）
print(repro_budget(2.5e9, sps_agg, 64))        # 66.0 h / 2.75 d / 4224 GPU-h / 3801.6 USD

解读：（1）函数把「墙钟」与「资源量」分列，加卡缩短墙钟但不减少 GPU-时，排期与预算各看一列。（2）同一步数在三组参数下从 90.2 小时到 1361.66 小时，差 15.1 倍；换端到端口径后 GPU-时从 721.6 升到 4224，差 5.85 倍。两个比值都写进工作单，向他人解释估算依据时直接引用。（3）第三个调用用反推聚合吞吐（2.5B 除以 64 卡 2.75 天的秒数，约 10522 步/秒；折合单卡约 164.4 步/秒）复现 DD-PPO 账目，验证公式与第 017 讲一致。

片段 2：档位选择

def pick_tier(gpus, gpu_mem_gb, steps, has_demos, real_robot):
    """按硬件与数据条件选择 T0/T1/T2/R；返回该档承诺的证据等级。"""
    if real_robot:
        return ("R", "可行性演示与带区间的估计；不承诺榜单排序")
    if steps == 0:
        return ("T0", "趋势复现与失败分析；调用预算可复算")
    if steps <= 5e8:
        if has_demos or gpus <= 8:
            return ("T1", "趋势复现加小规模数字复现")
        return ("T2", "数字复现（同协议同划分）")
    if gpus >= 8 and gpu_mem_gb >= 24:
        return ("T2", "数字复现（同协议同划分）")
    return ("T1", "先降级到 100M 冒烟；只能承诺趋势复现")

print(pick_tier(1, 24, 0, False, False))     # ('T0', ...)
print(pick_tier(8, 24, 3e8, True, False))    # ('T1', ...)
print(pick_tier(4, 24, 2.5e9, False, False)) # T1 降级，先跑冒烟

解读：（1）真机优先返回 R 档，因为真机实验的门槛是评测设计，训练资源再多也不能把几十次试验变成统计显著的排序。（2）步数为零即免训练，落到 T0；有演示且步数不超过 500M 时 T1 的性价比最高，对应 PirlNav 的两阶段结构中较便宜的一半。（3）最后一个调用返回 T1 降级，明确写出「只能承诺趋势复现」，防止小集群团队在开题报告里承诺全量数字。

片段 3：准备清单校验

REQUIRED = {
    "habitat_lab": "v0.3.4",
    "habitat_sim": "conda-build-pinned",
    "python": "3.9-or-3.12",
    "dataset": "HM3D-v0.1-or-v0.2",
    "episodes": "file-id-pinned",
    "detector": "weights-pinned",
    "vlm": "model-and-endpoint-logged",
    "seeds": "train-env-eval-fixed",
}

def prep_check(fields):
    """逐项核对准备清单，缺失项直接阻断开训。"""
    missing = [k for k in REQUIRED if not fields.get(k)]
    wrong = [k for k, v in REQUIRED.items()
             if fields.get(k) and k in ("habitat_lab", "dataset")
             and not str(fields[k]).startswith(v.split("-or-")[0].split("-v")[0])]
    ok = not missing and not wrong
    print("ready" if ok else "blocked", "missing:", missing, "wrong:", wrong)
    return ok

prep_check({"habitat_lab": "v0.3.4", "dataset": "HM3D-v0.2"})

解读：（1）清单字段与设计节表格一一对应，任何缺失项阻断开训，避免训到一半才发现数据版本不对。（2）版本字段用前缀匹配校验，v0.3.4 的补丁后缀可通过，跨次版本被拦下。（3）episode、检测器与 VLM 三项要求「标识可写」，即便选择在线服务也必须记录模型名与参数；真机与线下复核时，这行日志决定结果能否被解释。

常见坑

  • 把纯仿真吞吐当训练吞吐：症状是给 2.5B 步预算写「八卡三四天完成」，与端到端实验对不上。根因是 7699 SPS 是交互仿真上限，不含策略前向与优化。修复：预算按端到端口径，或对纯仿真值乘 5 至 6 倍系数并标注口径；正式训练前实测三段耗时。
  • 漏算演示与人工成本：症状是训练卡租批下来了，演示数据迟迟采不完。根因是 77k 条演示约 297.2 人日，通常长于训练墙钟。修复：先按 30.88 人时/千条估算数据预算；采集与训练并行排期；预留质量控制与返工比例。
  • 版本随环境漂移：症状是两周后重跑曲线对不上，或新机器上仿真器导入失败。根因是 Habitat-Lab 在 v0.3.4 后停更，Python 文档口径与 CI 口径分叉，NumPy 大版本会破坏编译扩展。修复：锁 tag、锁 conda 构建号、锁 NumPy 上限；用容器与离线缓存复现环境。
  • 评测样本不足：症状是 200 条 episode 上 3 个百分点的差距，换随机种子后翻转。根因是样本量未按目标分辨率反推。修复：按公式定样本量（3 个百分点约需 4,126 条）；预算不够时降低要分辨的差值或改用配对比较；报告附区间。
  • 物化观测与显存规划缺失：症状是磁盘一周写满，或训练在第一次更新时显存溢出。根因是按帧存储与按参数量估算检查点两类账没算。修复：观测现场渲染，只存 episode 与动作；检查点按参数量的 4 倍（含优化器状态）预留；批量与分辨率先用小配置压测。

练习与思考

  1. 用 W = N/(SPS·η) 复算 2.5B 步在八卡 Interact 口径下的墙钟与 GPU-时，再复算 64 卡端到端口径的 GPU-时，解释两者 5.85 倍差距的来源与标注方式。★
    提示
    八卡 7699 SPS、η = 1：90.2 小时，721.6 GPU-时；端到端 64 卡 2.75 天：4224 GPU-时。差距来自策略前向、梯度更新、通信以及观测负载不同。预算按端到端写，或注明纯交互系数。
  2. 把 PirlNav 的 RL 微调量级 300M 步按八卡 7699 SPS、η = 2/3 重算墙钟、GPU-时与成本，并说明为什么这一档仍是 T2 中较轻的负担。★
    提示
    16.24 小时、129.9 GPU-时、约 116.9 美元。相对 2.5B 端到端口径的 4224 GPU-时低一个多数量级，且 300M 步在公开配方里已能取得较高指标，适合作为 T2 的首次全流程演练。
  3. 两组方法成功率预计为 60% 与 65%。按第 058 讲公式计算所需样本量，并与低基线档 10% 对 20% 的 197 条对照，说明高位方法比较为什么更贵。★★
    提示
    60% 对 65% 每组约 1,468 条；10% 对 20% 约 197 条。差值同为 5 到 10 个百分点，但方差项 p(1−p) 在 0.5 附近最大，且高位方法的绝对差更小；预算不足时改用配对比较或扩大差值目标。
  4. 某零样本管线实测 1.7 帧/秒，要在 2,000 条 episode、平均 300 步的协议上评测。估算墙钟与租卡成本，给出三个降低到 24 小时以内的工程手段，并说明各自的代价。★★
    提示
    2000 × 300 / 1.7 ≈ 352,941 秒 ≈ 98.0 小时，约 88 美元。手段一：事件触发调用替代逐步调用，把每幕推理次数降到 5 次量级；手段二：批处理与缓存重复视图；手段三：抽样子集先做趋势判断并声明统计功效。代价分别是非关键帧信息损失、缓存命中率依赖场景重复度、结论粒度下降。

    提示
    档位：主路线 T1（行为克隆或轻量微调），评测按 T0 零样本作对照；不建议在 4 卡上承诺 T2 全量。阶段门按 12 周模板五段设置。成本上界按本地实测 SPS 重算，推理与人工单列。降级一：显存不足时缩骨干或梯度累积；降级二：真机重复不足时改为分层部分评测加 Wilson 区间。评测：判据统一并标注（1 m 加可见或 0.1 m）；样本量按 5 个百分点约 1,468 条或分批累积；失败分类沿用探索、检测、换层、平台四类。最可能先失败：版本环境与演示采集，两项都在训练之前。

小结

  • 两条公式：W = N/(SPS总·η) 与 C = P·W·c；单价取 0.9 美元/GPU-时。2.5B 步纯交互口径 90.2 小时、721.6 GPU-时，端到端口径 176 GPU-天、4224 GPU-时，比值 5.85，预算按端到端或注明系数。
  • 四档路线：T0 免训练单卡零样本，T1 单卡至八卡监督与微调，T2 八卡至 64 卡全量 RL，R 档真机。每档只承诺与资源匹配的证据等级，跨档不承诺。
  • 版本与环境：Habitat-Lab 钉 v0.3.4（2026-05-07 后停更）；Python 3.9 与 3.12 二选一并锁依赖；数据集口径为 MP3D 90 场景 21 类、HM3D v0.1 120 场景、v0.2 216 场景 142,646 实例、HM3D-OVON 379 类 15,661 实例；episode、权重与种子全部固定并写日志。
  • 评测与样本量：挑战预算 1000 条 48 小时折合每步 0.3456 秒；分辨 5 个百分点约需 1,468 至 1,531 条，3 个百分点约 4,126 条；真机 41/50 的 Wilson 区间为 [69.2%, 90.2%]，区间重叠不排序。
  • 隐藏成本：77k 条演示约 297.2 人日；零样本评测按 1.67 帧/秒约 99.8 小时；物化观测约 5.50 TB；检查点每份约 2.87 GB。先算清这些再批训练预算。
