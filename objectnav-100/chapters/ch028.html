第二篇 · 模块化：地图·探索·常识

第 028 讲｜PONI II：成本优势与局限

PONI 的训练成本相对 SemExp 低 7 倍、相对 THDA 低最高 1600 倍。本讲把成本口径算清，读透验证集与测试标准榜单，用消融与分割敏感性实验界定这条监督路线的适用边界，并与第 026 讲的复用式方案做横比。

  • 主题：训练成本核算 / 效能前沿 / 消融 / 失效边界
  • 关键公式：GPU 小时 = GPU 数 × 训练墙钟
  • 预计学时：60 分钟
  • 上一讲：第 027 讲 PONI I：势函数

学习目标

  • 能复算 PONI 的 7 倍与 1600 倍两个训练成本比值，说清它们各自的比较对象与口径，并解释两个比值不能互相换算的原因。
  • 能用监督通过量与交互帧数做量级校验，解释「免交互学习」省下的算力量级从何而来。
  • 能读验证集与测试标准两张结果表，区分成功率与 SPL 两种取向，解释 PONI 在测试标准上「四项指标拿下三项」的具体含义。
  • 能用消融表分解性能来源（物体势、边缘限制、面积势、真值分割），并量化分割误差对成功率的敏感性。
  • 能给出 PONI 的适用条件清单与失效场景（闭集类别、多楼层、噪声、动态环境、评测协议），并设计考虑训练与推理两段成本的预算方案。

背景与动机

第 027 讲把 PONI 的机制拆开：面积与物体两类势函数、离线监督、前沿上的损失。机制讲清楚之后，选型问题随之而来。研究预算有限时，把算力投给交互式强化学习、投给感知模块、还是投给数据标注，三种选择的结果差异很大；部署预算有限时，推理频率与网络调用次数决定系统的实时性。第 026 讲的 MOPA 提供了另一个参照：训练成本接近零，代价是复用了一个别人花大算力训练的导航策略，且探索仍靠启发式。

PONI（Ramakrishnan 等，CVPR 2022；arXiv:2201.10029v2）的论文标题直接写出了主张：免交互学习（interaction-free learning）。主张成立与否，要看三件事：成本省在哪里、省下成本后性能付出多少、哪些条件下方法失效。本讲按这三件事逐一核算。核算的素材全部来自论文公开数字：训练成本以 GPU 小时计，性能以 Gibson 与 Matterport3D 两个验证集以及 Habitat ObjectNav 榜单的测试标准结果为准。

核心原理

1. 成本口径：GPU 小时与效能前沿

论文用有效 GPU 小时衡量训练成本，定义为 GPU 数量与训练墙钟小时数的乘积。这个口径把并行规模与训练时长压成一个标量，便于在同一张图上比较异构方法：端到端强化学习用多机多卡跑数天，监督学习用单卡跑数小时，两者都能换算到同一坐标轴。以 GPU 小时为横轴、SPL 为纵轴，得到的曲线称为效能前沿（performance versus cost frontier）；PONI 的定位是在低得多的成本处达到当时的最高 SPL。

论文给出两个关键比值：在 Gibson 验证集口径下，PONI 的训练成本是 SemExp 的 1/7；在 MP3D 验证集口径下，是 THDA 的 1/1600。复算两者之比：1600 / 7 = 228.6，说明两个比值描述的是两条不同的基准线，不能互相换算。SemExp 是模块化强化学习方法（Chaplot 等，NeurIPS 2020），交互训练规模相对温和；THDA 是端到端强化学习方法（Maksymets 等，ICCV 2021），训练规模在 25 亿帧量级。选取的对手不同，比值自然不同。报告成本时必须同时写出三样东西：参照方法、数据集口径、成本包含的训练对象。

成本包含什么，同样需要界定。PONI 的成本账包含势函数网络的训练与离线语义图数据集的生成；图像分割模型的成本另计：MP3D 上使用 THDA 训练好的 RedNet 分割模型，Gibson 上微调 COCO 预训练的 Mask R-CNN。也就是说，「比最好的端到端方法便宜 1600 倍」这一句的准确含义是探索决策模块的训练账便宜 1600 倍，整套系统的感知成本、地图生成成本与推理成本都要单列。

2. 量级校验：监督通过量与交互帧数

用监督学习自身的量级做一次独立校验。第 027 讲给出：每个数据集 40 万条训练样例，训练 3 个 epoch，监督通过量 = 40 万 × 3 = 120 万次。交互式方法的标准量级取自 DD-PPO（Wijmans 等，ICLR 2020）：单个 PointNav 策略的训练消耗 25 亿帧观察。两者比值为 2.5 × 109 / 1.2 × 106 ≈ 2083 倍。

2083 与论文的 1600 处在同一数量级，说明 1600 倍量级的成本优势来自结构层面，工程优化只能解释其中小部分：同一条监督样例可以反复使用，而交互帧用过即弃。把 40 万条样例训练三个 epoch，等价于三次遍历同一份数据；强化学习每产生一帧都要推进一次仿真，数据生成与参数更新在同一个循环里。免交互把这两个循环拆开：数据生成离线完成，训练退化为标准监督问题，这才有百倍到千倍的成本差。

这条账的另一面是存储与生成成本：第 027 讲估算 40 万条样例在 5 cm 栅格下约合 1.5 TB，离线生成也需要一次三维标注投影与逐图最短路径计算。省下的是交互算力，付出的是一份可复用的静态数据集。当目标类别体系变化时，这份数据需要重新生成与重训，这笔再生产成本在下一节的边界清单里。

「四项指标拿下三项」指 PONI 在 SPL、SoftSPL、DTS 上第一，成功率列第三。解读要点有三。第一，成功率与 SPL 取向不同：SPL 同时惩罚失败与绕路，PONI 的成功质量高（SPL 8.82 对 THDA 8.75，高出 0.8%），Red-Rabbit 的到达率更高（23.67%），但成功路径的效率低（SPL 6.22）。第二，SoftSPL 的方向一致：PONI 17.08 对 THDA 16.96，高 0.7%，说明失败轨迹也更接近目标。第三，DTS 8.68 m 最低，说明未成功 episode 最终停靠点离目标更近。三个效率类指标一致指向「走得稳、落点近」，成功率指标指向「到达次数不及训练量更大的方法」。选择哪种方法，取决于应用把到达率还是效率放在第一位。

再补一个聚合效率换算：把 SPL 除以成功率，得到的恰好是成功 episode 上 l / max(p, l) 的均值：PONI 为 8.82 / 20.01 = 0.441，THDA 为 0.415，SemExp 为 0.396，Red-Rabbit 为 0.263。PONI 的成功轨迹效率最高，与「到达次数少、单次质量高」的画像一致。使用该换算时注意榜单数字经过四舍五入，比值只用于横向直觉。

5. 分割敏感性：免交互学习的结构代价

论文在局限部分给出最重要的量化：把真值分割换成预测分割，Gibson 成功率相对下降 14.9%，MP3D 相对下降 45.4%；SPL 相对下降 20.4% 与 56.0%。绝对值上，Gibson 从 86.5 跌到 73.6（12.9 个百分点），MP3D 从 58.2 跌到 31.8（26.4 个百分点）。

更能说明问题的是效率比值。用 SPL / 成功率衡量「成功 episode 的平均路径效率」：Gibson 预测分割 41.0 / 73.6 = 0.557，真值分割 51.5 / 86.5 = 0.595，相对下降 6.5%；MP3D 预测分割 12.1 / 31.8 = 0.381，真值分割 27.5 / 58.2 = 0.473，相对下降 19.1%。找路效率的下滑小于成功率的下滑，意味着分割误差主要破坏「发现目标后的确认与停靠」，对「朝目标接近」的搜索过程影响较小。根因是 PONI 的停靠完全依赖语义图：图里出现相符的类别标签才触发走向目标，分割漏检让目标永不上图，误检则把智能体引向错误位置。免交互学习没有内置的主动验证机制（例如走近后重新观察、靠近后复核），也没有在线纠错回路，这些能力在交互式方法里可以由策略从奖励中自行学到。论文把这条局限列为方法的主要缺点，并指出缓解方向：使用更强的分割模型、换更高质量的场景重建、在真机上验证重建瑕疵的影响。

6. 推理成本与采样频率

省下的训练成本会部分转移到推理。PONI 的最优采样频率为 T = 1，即每一步都调用一次势函数网络；第 023 讲的 SemExp 等模块化方法与回归式基线使用 T = 25。以 500 步的 ObjectNav episode 估算：T = 1 约调用 500 次，T = 25 约调用 20 次，网络前向次数相差 25 倍。势函数网络是小型的二维卷积网络，单次前向的算力远低于三维渲染或大骨干网络，所以论文仍在端到端部署上可行；但核算部署预算时，要把「每步一次小网络」与「每 25 步一次」分列，并考虑实时性约束下的降频实验。降频的代价是目标切换变迟钝：无法在抵达一条边缘后立刻响应新出现的物体势信号。

论文还验证过目标采样的一种扩展：加入随距离衰减的行动代价势 Ud，理论上可以让智能体在同分边缘间选近的。网格搜索后的结果略低于原始形式（MP3D 验证集成功率 31.8% 降到 30.3%），原因在于 PONI 行为上倾向把一条边缘探索充分再换方向，均摊未来代价的收益有限。这条负结果本身有教学价值：能带来的先验并不都值得写成显式项，先测再定。

7. 边界清单：什么时候不适用

把适用范围写成可检核的清单，共六条：

  • 闭集类别体系：MP3D 21 类、Gibson 6 类，物体势解码器的每个输出通道绑定一个类别。新增类别需要扩充标注数据、重建监督标签并重训对应通道，没有零样本能力。开放词汇设定属于第四篇的内容。
  • 单层平面假设：完整图按楼层逐层投影，部分图与前沿定义都建立在单层平面内。跨楼层需要楼层识别、跨层连通与楼梯策略，第 034 讲的 MFNP 处理这一问题。
  • 对三维语义标注的依赖：监督标签来自场景语义标注，标注质量与覆盖类别决定监督上限；没有标注的场景无法直接复现这条路线。
  • 无噪声传感器假设：实验设置沿用挑战口径，深度与里程计无噪声。真机上里程计漂移会同时污染语义图与势函数输入，需要按第 029 讲评估噪声传播，必要时引入定位修正。
  • 静态环境假设：训练数据与评测环境中的物体静态摆放；移动物体、重排、遮挡变化都不在分布内。
  • 评测协议敏感：成功判定依赖 1 m 成功区与预采样的有效视点。MOPA（第 026 讲）报告过停靠位置在目标 1 m 内、目标可见却被判失败的现象；复现实验要把评测器版本与视点采样密度一并冻结。

设计决策：把预算花在感知，少花在交互

PONI 的成本结构说明：在语义地图信息充足的环境里，先修分割与建图，再谈策略训练，单位算力的收益更高。消融与敏感性两张表给出同一结论：真值分割带来 12.9 与 26.4 个百分点的成功率空间，远大于探索模块内部的一切改进。工程上先用第 029 讲的方法定位噪声源，再决定投算力方向。

成本比值的报告规范

引用「低 1600 倍」时必须同时给出：参照方法（THDA）、数据集与分局（MP3D 验证集）、成本范围（势函数网络训练，不含分割与推理）。换参照或换分局，比值随之改变；Gibson 口径下的 7 倍对应的是 SemExp。把三要素写进实验记录，避免不同论文的比值被直接拼在一张表里。

关键代码与解读

三个片段分别核算成本、推理调用量与分割敏感性，用于把本节表格变成可复算的脚本。

片段 1：训练成本的换算

def gpu_hours(n_gpus, wall_clock_hours):
    """有效训练账：GPU 数乘以墙钟小时数，论文的成本口径。"""
    return n_gpus * wall_clock_hours

def cost_ratio(cost_reference, cost_method):
    """成本倍率；调用处必须记录参照方法、数据集与成本范围。"""
    return cost_reference / cost_method

my_poni = gpu_hours(1, 6.0)              # 示例：按自家配置替换（单卡 6 小时）
gibson_ref = 7.0 * my_poni               # Gibson 口径的 SemExp 等效账
mp3d_ref = 1600.0 * my_poni              # MP3D 口径的 THDA 等效账
print(cost_ratio(gibson_ref, my_poni))   # 7.0
print(cost_ratio(mp3d_ref, my_poni))     # 1600.0

解读：（1）函数只做换算，参照关系由调用方显式给出，强制记录口径。（2）两个参照账基于不同对手与数据集，脚本里用两行分开写，杜绝把比值混算成一个数。（3）自测账（单卡 6 小时）必须来自真实日志的 GPU 数乘墙钟，不能用理论算力推算，显卡型号与并行效率都影响结果。（4）正式对比时把分割模型训练与数据生成工时单列，汇总进总账。

片段 2：推理调用量与采样频率

def pf_calls(episode_steps, interval):
    """势函数网络的调用次数：T=1 每步一次，T=25 每 25 步一次。"""
    return episode_steps // interval

steps = 500
for interval in (1, 25):
    calls = pf_calls(steps, interval)
    print("T=%d: %d 次，约占总步数 %.0f%%" % (interval, calls, 100.0 * calls / steps))
print("调用次数比:", pf_calls(steps, 25), ":", pf_calls(steps, 1))

解读：（1）500 步 episode 下，T = 1 为 500 次、T = 25 为 20 次，相差 25 倍；这是训练成本之外必须核算的部署开销。（2）论文选择 T = 1 是为响应每一帧新增的语义信息；回归式基线选 T = 25 是为稳定输出，说明采样频率与目标信号的统计特性绑定。（3）部署到算力受限平台时，先测 T = 5、10、25 的成功率与墙钟曲线，再决定降频档位，不要直接套用论文取值。（4）同一脚本可扩展到统计分割模型与检测器的调用次数，形成完整的推理预算表。

片段 3：分割敏感性的简化评估

def success_upper_bound(detection_recall, stop_accuracy):
    """教学过程用的简化上界：类未检出则无法停靠，检出后停靠仍有误差。"""
    return detection_recall * stop_accuracy

onset = [0.9, 0.7, 0.5]                  # 示意检出率，演示敏感性形状
for r in onset:
    print(r, round(success_upper_bound(r, 0.95), 3))
# 输出 0.855 / 0.665 / 0.475：检出率下降直接把成功上界往下拉

解读：（1）模型抓住 PONI 停靠机制的核心：没有图上标签就没有成功，成功率上界与检出率成正比。（2）参数 0.9、0.7、0.5 为示意值，用于演示曲线形状；换成实测的按类别检出率才有定量意义。（3）MP3D 上真值到预测分割的相对下降 45.4%，与此模型的敏感性方向一致：多类别、细物体的分割召回偏低时，成功率随之下坠。（4）缓解手段有两条：提高分割质量，或者给停靠机制加主动验证（走近后复核），后者会让系统重新引入交互。

常见坑

  • 把 1600 倍当成通用结论：症状是在报告或选型时把两个比值混用，得出错误的总账。根因是忽视了参照方法、数据集与成本范围三要素。修复：按本讲的成本表格式记录每笔账；两个比值分列，注明 SemExp 对 Gibson、THDA 对 MP3D。
  • 用真值分割数字估计部署表现：症状是技术方案承诺的成功率远高于现场实测。根因是把 86.5% 与 58.2% 这两个含特权信息的数字当成了可达目标。修复：以预测分割的数字为工作基线，真值数字只用于定位天花板与估计改进空间。
  • 把 MP3D 验证集 31.8% 当成方法上限：症状是过早否定监督路线或停止改进感知。根因是忽略分割敏感性实验的结论：瓶颈落在感知，决策模块只占小头，真值分割下同一决策模块可到 58.2%。修复：先修分割与建图，再评估决策模块。
  • 忽略推理频率的代价：症状是复现时训练顺利但评测墙钟超预期，实时性不达标。根因是 T = 1 的每步网络调用没有进入预算，或降频后没有重新调参。修复：把调用次数计入部署预算；降频实验与成功率、墙钟联合报告。
  • 跨数据集或多楼层直接沿用流程：症状是换数据集后性能骤降、面积项行为异常，或跨层目标始终找不到、楼梯口前沿信号失效。根因是类别数（21 对 6）、输出通道、面积归一化口径与场景尺度不同，且逐层二维图之间没有连通表示。修复：迁移时重生成监督数据、重训通道映射并按尺度校准归一化常数；跨层场景按第 027 讲练习补楼层识别与跨层图，或直接采用第 034 讲的方案。

  2. 用 120 万次监督通过与 25 亿帧交互的标准量级做量级校验，说明 2083 与 1600 同量级为什么支持「成本优势来自结构」的判断；再估算如果只训练 1 个 epoch，成本还能降多少、可能付出什么性能代价。★
    提示

小结

  • 成本口径为 GPU 小时（GPU 数乘训练墙钟）：PONI 的训练成本为 SemExp 的 1/7（Gibson 口径）、THDA 的 1/1600（MP3D 口径）；两比值参照不同，不可互相换算。
  • 量级校验：120 万次监督通过对 25 亿帧交互约 2083 倍，与 1600 同量级，证明成本优势来自免交互的循环结构，代价是离线数据的存储与再生成。
  • 测试标准上 PONI 在 SPL、SoftSPL、DTS 三项第一，成功率 20.01% 列第三；效率与到达率取向不同，选型时按应用目标取舍。
  • 消融显示相对仅物体项，完整模型提升 14.8 个百分点；真值分割把成功率推到 86.5% 与 58.2%，指明感知是主要改进空间。
  • 分割敏感性是结构性局限：真值到预测分割使成功率相对下降 14.9%（Gibson）与 45.4%（MP3D）；停靠完全依赖语义图，缺少主动验证机制。
  • 推理侧 T = 1 带来约 25 倍网络调用；下一讲沿语义图的误差传播链条继续展开，回答检测噪声如何在流水线中放大。
