第四篇 · 开放词汇与大模型

第 075 讲｜NaVid 对接

第 074 讲的 VLMnav 用零样本提示把 VLM 直接变成策略，暴露了两个缺口：朴素拼接历史无增益，跨域与真机迁移缺少训练支撑。本讲拆 NaVid（Zhang 等 2024，RSS 2024，arXiv:2402.15852）：一个以单目 RGB 视频流为唯一观测的视频 VLM 导航智能体，不依赖地图、里程计与深度。它把每帧编码为 1 个指令查询 token 与若干指令无关 token（历史帧 4 个、当前帧 64 个），用特殊 token 分隔历史、观测与导航指令，让 Vicuna-7B 以语言形式输出带参数量（前进距离、旋转角度）的动作；训练混合 51 万条连续环境导航样本与 76.3 万条网页数据，单轮微调后在 R2R-CE 验证集取得 37.4% SR 与 35.9 SPL，跨数据集迁移到 RxR 取得 23.8% SR，真机 200 条指令成功约 66%。本讲的重点不在复述 VLN 结果，而在设计一套「VLN 视频 VLM 对接到 ObjectNav」的适配层：类别到指令的转换、连续参数到离散动作的映射、停止口径对齐、视频缓冲与评测口径迁移。

  • 主题：视频 VLM / 端到端导航 / 适配层设计 / 跨域与真机迁移
  • 关键公式：视觉 token 预算 5(T−1) + 65（T 为帧数）；动作 = 类型 + 参数；SR 与 SPL 的 VLN-CE 口径
  • 预计学时：75 分钟
  • 前置章节：第 074 讲（VLMnav：VLM 即策略）

学习目标

  • 会拆架构：说清 EVA-CLIP 视觉编码、Q-Former 查询生成、Vicuna-7B 推理与两类视觉 token 的分工，会手算视频 token 预算。
  • 会读配方：51 万条导航样本的三个来源（专家轨迹、非专家轨迹、指令推理）各自的作用，以及网页数据与导航数据的配比逻辑。
  • 会解读结果：R2R-CE 表内 SR 与 SPL 的取舍（相对 WS-MGMap 的 SR 低 1.5、SPL 高 1.6）、RxR 跨数据集增益、四种历史表示对照与视觉 token 数量的收益曲线。
  • 会设计适配层：把 VLN 式视频 VLM 对接到 ObjectNav 的类别目标、离散动作、1 m 停止判据与长程评测口径，列出每一处接口的转换规则。
  • 会判断边界：停止阈值差异、动作参数到离散步的映射误差、视频缓冲的显存与延迟、真机部署的延迟预算。

背景与动机

第 074 讲的 VLMnav 证明了「VLM 即策略」可行，但它的历史实验给出了否定结论：把最近 15 步观测拼进提示词，SR 反而比无历史低 6.4 个百分点。这说明通用 VLM 的提示接口无法承担「记住走过的路」这一职能，而导航恰恰需要历史：同一扇门走过与否，决定下一步该继续探索还是折返。与此同时，VLMnav 的真机可行性也被滑行消融打上问号。要补这两个缺口，方向有二：给 VLM 换上能利用历史的输入结构，以及用导航数据训练它。

NaVid 属于第二条路线的代表工作：把历史观测组织成视频流，用每帧少量视觉 token 压缩存储，并用连续环境的人类演示数据微调一个视频 VLM。它面向的是视觉语言导航（Vision-and-Language Navigation, VLN），任务是「按指令走」，与本课的「找目标物」并不相同。本讲的价值因此分两层。第一层是机制层：视频 token 的历史编码方式，是第 076 讲之后所有记忆设计的基础工具。第二层是对接层：如何把一台为指令跟随训练的视频 VLM，改造成 ObjectNav 智能体，需要补哪些接口、改哪些口径、防哪些坑。这一层是第 074 与 076 讲之间缺失的工程桥。

核心原理

1. 任务形式化与动作接口

NaVid 在连续环境视觉语言导航（Vision-and-Language Navigation in Continuous Environments, VLN-CE）口径下定义问题。t 时刻给定自然语言指令 ℐ（l 个词）与视频观测 𝒪t = {x0, …, xt}，智能体输出下一步低层动作 at+1 ∈ 𝒜，执行后收到新帧 xt+1。决策过程是一个 POMDP，观测空间为单目 RGB 视频，动作空间包含「类型 + 定量参数」两层：类型取自 {FORWARD, TURN-LEFT, TURN-RIGHT, STOP}，FORWARD 附带前进距离，TURN-LEFT 与 TURN-RIGHT 附带旋转角度。输出用正则表达式解析，论文报告在 R2R 验证集上有效动作解析率达到 100%。

与本课 ObjectNav 的动作口径对照：Habitat 离散动作每步固定前进 0.25 m 或旋转 30°，NaVid 输出的是带参数的动作，部署时需要一个映射层把「前进 1.2 m」展开为若干离散步，或把动作参数直接交给连续控制器。这个映射层是后文适配设计的第一块砖。评测指标沿用 VLN 标准：成功率（Success Rate, SR）、oracle 成功率（OS）、成功加权路径长度（SPL）、轨迹长度（TL）、导航误差（NE）。VLN-CE 的停止成功判据是距目标 3 m 内调用 STOP，真机实验用 1.5 m。注意这两个数值与 ObjectNav 的 1 m 判据都不同，跨口径比较会系统性高估。

2. 观测编码：两类 token 与特殊分隔符

NaVid 的骨架沿用 LLaMA-VID 视频 VLM：EVA-CLIP 视觉编码器、Q-Former 查询生成器、Vicuna-7B 语言模型、BERT 文本编码器，以及两个跨模态投影器。每帧图像经视觉编码得到 Nx = 256 个 patch 特征 Xt ∈ ℝ256×C，随后分成两类 token。第一类是指令查询 token：Q-Former 以指令文本为条件生成查询 Qt，再对图像特征做交叉注意力并池化，得到 1 个与当前指令最相关的视觉 token：

EQt = PQ( Pool( Softmax(Qt XtT) Xt ) ) ∈ ℝ1×C

第二类是指令无关 token：对图像特征做网格池化再投影，得到 Nv 个 token：EVt = PV(GridPool(Xt))。论文的关键设计是历史帧与当前帧使用不同的 token 数：当前帧 64 个，历史帧每帧 4 个。理由是当前帧承担动作参数的几何推理，需要保留更多空间信息；历史帧主要提供「走到过哪里」的上下文，粗粒度即可。作为对照，LLaMA-VID 每帧只用 2 个 token，适合高层问答，却不足以支撑动作参数的推理，这也是 NaVid 改用网格池化的原因。

三类信息用特殊 token 分隔：<HIS> 与 </HIS> 包裹历史帧 token，<OBS> 与 </OBS> 包裹当前帧 token，<NAV> 标记指令开始。输入格式为 <HIS>{历史帧}</HIS><OBS>{当前帧}</OBS><NAV>{指令}，输出为动作文本。按每帧 1 个查询 token、历史帧 4 个无关 token、当前帧 64 个无关 token 计算，T 帧的视觉 token 总数为 5(T−1) + 65。取 T = 50、100、300，预算分别为 310、560、1560 个 token。导航数据里绝大多数轨迹小于 300 帧，因此 1560 是该配方在训练时的实际上界；这个线性增长是后续记忆设计要对付的对象（第 076 讲给出两种有界替代方案）。

3. 训练配方：混合数据与单轮微调

训练数据分三块导航来源与一块网页来源。专家轨迹 32 万条步级样本，采集自 R2R-CE 的 61 个 MP3D 场景，含单目视频、指令与动作。非专家轨迹 18 万条：先用专家数据训练一个初始智能体，再把它放到环境中运行、收集它自己产生的轨迹。这一步模仿 DAgger 思路，让训练分布覆盖智能体的真实错误状态，缩小训练与推理的分布差。指令推理样本 1 万条：给一段视频轨迹，要求模型反推对应指令，作为环境理解与指令跟随的辅助任务。三块合计 51 万条。网页数据 76.3 万条视频问答样本用于共训，防止微调破坏预训练通用知识；导航与网页数据的配比约为 0.668 : 1。

训练配置：24 张 A100 约 28 小时，合计 672 GPU 小时，只训练 1 个 epoch，只优化 LLaMA 与文本编码器的可训练参数，EVA-CLIP、Q-Former、BERT 均加载预训练权重。按导航样本折算约 4.74 秒每样本，按全部样本折算约 1.90 秒每样本。视频问答数据按 1 FPS 抽帧去冗余，导航数据保留全部帧。推理侧，真机每步动作耗时约 1.2 至 1.5 秒，论文建议用量化等加速手段压缩。

读法与第 074 讲的表不同：NaVid 的 SR 比 WS-MGMap 低 1.5 个百分点，SPL 高 1.6，NE 低 0.81 m，OS 高 1.5 个百分点。论文的表述是「在 SPL、NE、OS 上达到最优，SR 相当」，这组取舍的机制是：NaVid 的轨迹更短、更少绕路（SPL 与 NE 受益），但少数难例上停不准或停不下来（SR 略低）。相对同观测口径的 RGB 基线，SR 从 5.0 提到 37.4（+32.4 个百分点，相对 648%），SPL 从 4.43 提到 35.9（相对 710%），说明能力来自训练数据与视频结构，不来自观测模态的堆叠。

跨数据集实验把 R2R 训练好的模型零样本搬到 RxR 验证未见集（Zhang 等 2024，表 2）：NaVid 23.8% SR / 21.2 SPL / NE 8.41，相对当时零样本最优的 A²Nav（16.8% / 6.3）SR 高 41.7%、SPL 高 236.5%。RxR 指令更细、轨迹更长、语言与视觉分布差更大，这组数字是「指令模板与动作接口可迁移」的直接证据，也是后文把类别目标包装成指令的依据。

四组辅助对照给出机制解释。第一，历史表示（表 4）：纯文本历史 0.0% SR，地图加文本 9.13%，自我视角加文本 23.5%，视频 37.4%。自我视角到视频的跨度为 +13.9 个百分点（相对 +59.1%），证明历史必须以视觉形式进入模型，转写成文字会丢失大部分信息。第二，与通用大模型对照（表 3，100 条 episode 子集）：GPT-4V 5.0% / 3.11，LLaVA-Nav 10.0% / 9.43，LLaMA-VID-Nav 29.0% / 27.5，NaVid 38.0% / 35.4；LLaMA-VID 微调后有效动作输出率从 0% 提到 91.3%，说明导航数据的作用首先是「把模型教会说可执行的动作」。第三，视觉 token 数量（表 8）：每帧 1 到 4 个 token，SR 提高 56.4%，时间增加 40.2%；4 到 16 个 token，SR 只再提高 1.60%，时间增加 122%。4 个是收益与成本的平衡点。第四，长程稳定性：指令所需步数 30 至 90 步（约 5 至 20 m）时性能保持稳定；训练集中 74.3% 的 episode 在 35 至 75 步，5.91% 超过 90 步。

5. 真机迁移：四场景 200 条指令

真机平台为 Turtlebot4 加 Kinect DK 相机，场景为会议室、办公室、实验室、休息室四类，每场景设计 25 条简单地标指令与 25 条复合指令，合计 200 条（Zhang 等 2024，表 6）。成功判据为 1.5 m。结果：NaVid 简单指令平均 85.0%，复合指令平均 47.0%，总体 66.0%；WS-MGMap 分别为 51.0%、22.0%、36.5%；Seq2Seq 约 0.5%，CMA 约 1.5%。总体差 29.5 个百分点，简单差 34，复合差 25。读法有三点：其一，复合指令的成功率折半，说明多步语言推理仍是瓶颈；其二，纯 RGB 输入在真机上没有出现深度或里程计误差导致的大幅退化，这是该路线最重要的迁移证据；其三，1.2 至 1.5 秒每步的延迟在慢速服务机器人上可用，在动态环境里需要压缩。

6. 对接 ObjectNav 的适配层

把 NaVid 用于 ObjectNav，需要改造五处接口。第一，目标接口：ObjectNav 给定类别词（chair、bed、plant、toilet、sofa、TV），VLN 给定完整指令。做法是用指令模板把类别包装成自然语言目标，例如「Find the chair in the room.」。跨数据集实验已证明模型对未见指令分布有迁移能力，模板差异在可接受范围内，但模板措辞仍需按验证集标定。

第二，动作接口：NaVid 输出带参数的动作，ObjectNav 环境通常提供离散动作。需要把前进距离除以步长并向上取整为若干前进步，把旋转角度除以每步转角展开为若干旋转步；展开会引入量化误差，最大半步步长。若环境支持连续控制，则把参数直接交给控制器，此时要另设速度与安全约束。

第三，停止接口：VLN-CE 的 3 m 判据不能直接用于 ObjectNav 的 1 m 判据。做法是保留 NaVid 的 STOP 输出作为「候选停止」，再叠加一层几何或检测门控：只有目标检测框存在、深度距离小于阈值时才接受停止。第 074 讲的提前停止问题与这里同源，双确认策略可复用。

第四，记忆接口：视频缓冲按帧存储，token 预算随帧数线性增长。ObjectNav 的 episode 可达数百步，直接照搬会把上下文撑满。可选的裁剪规则包括：按最近 T 帧滑窗、对历史帧降采样、或在检测到目标后只保留目标附近帧。第 076 讲的有界记忆设计可作为替代方案。

第五，评测接口：VLN 指标里的 OS 与 TL 在 ObjectNav 报告中通常不出现，SPL 的最短路径口径也不同（VLN 用专家轨迹，ObjectNav 用测地距离）。对接后报告结果时，必须同时声明数据集、成功阈值与最短路径来源，否则数字不可比。

关键代码与解读

四段代码覆盖视频缓冲与 token 组装、动作解析与执行映射、ObjectNav 适配包装器、数据收集循环。代码为教学重写。

片段 1：视频缓冲与特殊 token 组装

class VideoBuffer:
    def __init__(self, max_frames=300, hist_tokens=4, curr_tokens=64):
        self.frames, self.max_frames = [], max_frames
        self.hist_tokens, self.curr_tokens = hist_tokens, curr_tokens

    def push(self, frame):
        self.frames.append(frame)
        if len(self.frames) > self.max_frames:      # 滑窗：丢最旧帧
            self.frames.pop(0)

    def encode(self, encoder, instruction):
        """历史帧 4 个无关 token，当前帧 64 个，另有每帧 1 个查询 token。"""
        hist = self.frames[:-1]
        hist_tok = [encoder.grid_pool(f, self.hist_tokens) for f in hist]
        curr_tok = encoder.grid_pool(self.frames[-1], self.curr_tokens)
        query_tok = encoder.query(self.frames[-1], instruction)
        seq = ([encoder.special("<HIS>")] + sum(hist_tok, [])
               + [encoder.special("</HIS>"), encoder.special("<OBS>")]
               + curr_tok + [encoder.special("</OBS>"),
                             encoder.special("<NAV>")])
        return seq + query_tok

解读：（1）token 预算随帧数线性增长（5(T−1) + 65），max_frames 是显存与延迟的第一道闸门。（2）历史帧与当前帧的 token 数分开配置，是论文消融支持的关键设计。（3）特殊 token 让模型区分「历史、当前、指令」三段，去掉后性能明显下降（论文架构消融）。（4）查询 token 以指令为条件，实现「看指令相关的视觉内容」。

片段 2：动作解析与离散执行映射

import re

ACTION_RE = re.compile(
    r"(FORWARD|TURN-LEFT|TURN-RIGHT|STOP)"
    r"(?:\s*[\(\[]?\s*([0-9]+(?:\.[0-9]+)?)\s*(m|deg|°)?\s*[\)\]]?)?")

def parse_action(text):
    """解析语言动作；解析失败返回 None，由调用方降级。"""
    m = ACTION_RE.search(text.upper())
    if not m:
        return None
    kind, value, unit = m.group(1), m.group(2), m.group(3)
    return kind, float(value) if value else None

def to_habitat_steps(action, step_len=0.25, step_deg=30.0):
    """把带参数动作展开为离散动作序列。"""
    kind, value = action
    if kind == "STOP":
        return ["STOP"]
    if kind == "FORWARD":
        n = max(1, round((value or step_len) / step_len))
        return ["MOVE_FORWARD"] * n
    n = max(1, round((value or step_deg) / step_deg))
    name = "TURN_LEFT" if kind == "TURN-LEFT" else "TURN_RIGHT"
    return [name] * n

解读：（1）正则解析是部署的硬前提，论文报告 val-unseen 上 100% 有效，但真实文本仍要准备 None 分支。（2）展开取整的量化误差最大半步，长距离前进会累积；对精度敏感时可改用连续控制。（3）STOP 单独成一步，交给上层门控决定是否真正终止。（4）把解析与执行分开，便于在 ObjectNav 适配层替换映射规则。

片段 3：ObjectNav 适配包装器

class ObjectNavAdapter:
    TEMPLATE = "Find the {category} in the room."

    def __init__(self, policy, detector, stop_distance=1.0):
        self.policy, self.detector = policy, detector
        self.stop_distance = stop_distance

    def act(self, category, obs, video_buffer, depth=None):
        instruction = self.TEMPLATE.format(category=category)
        action = self.policy.predict(video_buffer, instruction)
        if action is None:                              # 解析失败降级
            return "TURN_LEFT"
        kind, value = action
        if kind == "STOP":
            det = self.detector(obs, category)          # 停止门控
            dist = det.distance if det else float("inf")
            if det is not None and dist <= self.stop_distance:
                return "STOP"
            return "MOVE_FORWARD"                       # 拒绝停止，继续接近
        return to_habitat_steps(action)

解读：（1）类别到指令的模板是适配层最便宜也最敏感的一环，模板措辞要按验证集标定。（2）停止门控把 VLN 的 3 m 判据收紧到 ObjectNav 的 1 m，并叠加目标检测，避免模型在语义相似物体前误停。（3）门控拒绝停止后强制前进一步，保证不会原地反复询问。（4）解析失败降级为旋转，比随机动作更安全，也让 episode 有机会恢复。

片段 4：专家与非专家轨迹收集

def collect_oracle(env, episodes, policy=None):
    """收集专家轨迹：视频帧、指令、动作三元组。"""
    samples = []
    for ep in episodes:
        obs = env.reset(ep)
        video, actions = [], []
        for step in ep.oracle_actions:                  # 最短路径动作序列
            video.append(obs.rgb)
            actions.append(step)
            obs = env.step(step)
        samples.append({"video": video, "instruction": ep.instruction,
                        "actions": actions})
    return samples

def collect_non_oracle(env, episodes, policy):
    """用已训练策略跑环境，收集它自己的轨迹（DAgger 思路）。"""
    samples = []
    for ep in episodes:
        obs, video, actions = env.reset(ep), [], []
        done = False
        while not done:
            act = policy.predict(video, ep.instruction)
            video.append(obs.rgb)
            actions.append(act)
            obs, done, _ = env.step(act)
        samples.append({"video": video, "instruction": ep.instruction,
                        "actions": actions})
    return samples

解读：（1）专家轨迹给「正确做法」，非专家轨迹给「错误恢复」，两者共同覆盖推理时的状态分布。（2）非专家收集需要先有一个可用策略，因此训练分两阶段：先专家数据训初始模型，再收集、合并、重训。（3）数据格式统一为视频、指令、动作三元组，指令推理辅助任务只需交换输入输出字段。（4）采集成本是大头，复现时应先估算场景数与步级样本量的关系。

常见误区

  • 停止阈值直接照搬：症状是仿真成功率虚高、复现偏低。根因是 VLN-CE 用 3 m、真机用 1.5 m、ObjectNav 用 1 m。修复：停止做成「模型输出 + 几何门控」两级，评测时把阈值写进结果表。
  • token 预算失控：症状是长 episode 显存溢出或延迟飙升。根因是视觉 token 随帧数线性增长（300 帧约 1560 个）。修复：滑窗或降采样历史帧；按 4 个 token 每历史帧配置，避免盲目加到 16（时间 +122%，SR 仅 +1.60%）。
  • 只用专家轨迹训练：症状是仿真尚可、闭环运行迅速偏离。根因是训练分布没有覆盖智能体自己的错误状态。修复：按 DAgger 思路收集非专家轨迹，与专家样本混合训练。
  • 去掉共训数据：症状是模型输出大量不可执行文本，动作合法率骤降。根因是微调破坏了预训练通用能力，LLaMA-VID 的有效动作率从 0% 到 91.3% 正是共训加导航数据的组合结果。修复：保留网页视频问答共训，并在训练日志里单独监控动作合法率。
  • 动作参数直接截断：症状是转向不足或前进不够，轨迹系统性偏短。根因是把带参数动作展开为离散步时向下取整或限制步数。修复：用四舍五入并检查最大展开步数；对长距离动作优先走连续控制通道。

练习与思考

  1. 按每帧 1 个查询 token、历史帧 4 个、当前帧 64 个的配置，计算 T = 20、80、200 帧时的视觉 token 总数，并说明该预算在 8k 上下文模型中的占比风险。★
    提示
    公式为 5(T−1) + 65：T=20 得 160，T=80 得 460，T=200 得 1060。占比分别为约 2.0%、5.6%、12.9%（按 8k 计）。风险随 episode 变长线性上升，且与指令、输出 token 竞争预算。
  2. 解释为什么「自我视角加文本」只有 23.5% SR，而视频达到 37.4%，并设计一个实验区分「帧数增加」与「视觉编码」两个因素。★★
    提示
    文本历史丢失空间布局与地标细节，视频保留连续视角变化。实验：固定帧数，对照「视频 token」与「同帧转文字描述」两种编码；再固定编码，对照不同帧数。若视频优势在固定帧数下仍存在，则编码形式是主因。
  3. 为 ObjectNav 设计完整的适配层测试方案：类别模板、动作映射、停止门控三个模块各自的单元测试与端到端测试，给出指标与通过标准。★★
    提示
    模板：同义改写下的成功率方差；动作映射：给定参数时的展开步数与误差上界（≤ 半步长）；停止门控：误停率、拒停率与最终 SR。端到端：在 HM3D 验证集固定 episode 集合上对照原始 VLN 口径与 ObjectNav 口径两套报告。
  4. 设计「视频 token 预算 × 性能」的完整实验：帧数取 50、100、200、300，历史 token 数取 1、4、8、16，给出预算公式、评测指标与预期曲线，并说明如何在显存约束下选择配置。★★★
    提示
    预算 = 5(T−1) + 65 但历史 token 数变化时改为 (h+1)(T−1) + 65。指标：SR、SPL、每步延迟、峰值显存。预期：SR 随 token 数先快后慢，延迟近似线性；论文的 1 到 4 与 4 到 16 两段斜率可作为先验。选择规则：在显存与延迟硬约束下取边际收益转折点，默认每历史帧 4。
  5. 真机实验里复合指令成功率（47%）不到简单指令（85%）的一半。给出两个可检验的原因假设，并为每个假设设计最小对照实验。★★
    提示
    假设一：多步语言推理错误累积，实验为把复合指令拆成顺序子指令逐条执行，比较 SR；假设二：复合任务轨迹更长、视频 token 预算与视觉漂移放大，实验为固定任务复杂度、只改变轨迹长度，观察 SR 随长度衰减。两个假设可叠加，需交叉设计。

小结

  • 机制：单目 RGB 视频是唯一观测；每帧 1 个指令查询 token 加若干指令无关 token（历史 4、当前 64）；特殊 token 分隔三段信息；动作以语言输出类型与参数。
  • 配方：32 万专家 + 18 万非专家 + 1 万指令推理 = 51 万导航样本，配 76.3 万网页样本共训；24 张 A100 约 28 小时、672 GPU 小时、单轮微调。
  • 结果：R2R-CE 37.4% SR / 35.9 SPL，相对 WS-MGMap 的 SR 低 1.5、SPL 高 1.6、NE 低 0.81；RxR 零样本 23.8% SR，相对 A²Nav 高 41.7%；真机总体 66.0%，简单 85.0%、复合 47.0%。
  • 机制证据：历史表示从文本 0.0 到视频 37.4；视觉 token 1 到 4 的边际收益最大，4 到 16 只再涨 1.60% 而时间涨 122%。
  • 对接：五处接口（目标、动作、停止、记忆、评测）各有转换规则与风险，停止门控与 token 预算是 ObjectNav 场景下最需要加固的两处。
