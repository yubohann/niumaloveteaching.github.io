第二篇 · 模块化：地图·探索·常识

第 037 讲｜模块化评测（SoftSPL 视角）

第 036 讲的结果形状值得单独研究：SPL 与 SoftSPL 双双第一，成功率却排第二；第 034 讲的 MFNP 成功率超过 VLFM，SPL 却落后。当四个指标给出不同排序时，模块化方案的真实优劣如何判断？本讲以 2023 挑战标准赛道六支队伍、2022 与 2021 两届榜单以及第二篇的模块化结果表为样本，实算指标缺口、排序差异与 1000 条 episode 的统计分辨率，给出模块化评测清单与五类常见误读的修复办法。

  • 主题：评测协议 / 指标组合 / 统计分辨率 / 反作弊
  • 关键公式：SoftSPL−SPL 缺口；二项标准误 SE = √(p(1−p)/N)
  • 预计学时：70 分钟
  • 前置章节：第 036 讲 IPPON：概率图 + 信息路径规划

学习目标

  • 会算 2023 挑战六支队伍的四项读数、SoftSPL−SPL 缺口、SoftSPL/SPL 比值、SoftSPL−SR 差值与条件效率 SPL/SR。
  • 会解释三种排序冲突的成因：高成功率队伍的 SoftSPL 可低于 SR，低成功率队伍可远高于 SPL；跨楼层搜索会形成成功率换效率的取舍。
  • 会算二项标准误与 95% 半宽，区分独立样本比较与同 episode 配对比较，说出 McNemar 口径的位置与样本量估算。
  • 能设计模块化评测报告：数据集版本、判据、四指标、失败分层、近失率、零样本标签与成本字段。
  • 能识别并修复五类误读：SoftSPL 当成功率、忽略配对、跨数据集并排、DTG 单独排名、多重比较不校正。

背景与动机

第 005 讲建立了 SoftSPL 与 DTG 的机制：SPL 只在成功时计分，SoftSPL 把失败轨迹的接近程度折算成分数，DTG 记录停点的剩余距离。此后第二篇的方法章节不断给出新的结果表，却留下一个共同的评价难题：不同方法在不同指标上的排序不一致。第 036 讲在 2023 挑战标准赛道上拿到 SPL 0.34 与 SoftSPL 0.46，均为全场最高，成功率 0.54 却低于 SkillTron 的 0.59；第 034 讲的 MFNP 在 HM3D 上成功率 58.3 高于 VLFM 的 52.5，SPL 0.267 却低于 0.304。方法评审、选型与论文复现都需要一套固定的读法，把「谁更强」拆成「在哪个维度更强、代价是什么」。

本讲把评测从单条公式上升到协议层。评测协议要回答的问题包括：四个指标各自证明什么；排序差异在什么时候有意义；1000 条 episode 的分辨率能支撑多大的结论；榜单的数字是训练方案还是零样本方案；提交阶段的成绩是否可复现。这些问题在挑战赛历史上反复出现：2021 与 2022 两届榜单在头部排序上大体一致，在中后段出现位置交换；2023 年动作空间改为连续、数据集改为 HM3D-Semantics v0.2、episode 限制为单层，每一项都改变了数字的可比边界。

本讲在第二篇的位置是评测收束：第 038 讲比较 2D 语义图与 3D 场景图，第 039 讲讨论 uniform 探索的反直觉结论，第 040 讲做第二篇回顾，三讲都以本讲的指标口径和统计判据为基础。来源口径：2023 挑战页与 IPPON 论文表（arXiv:2410.19697v1）；2021 与 2022 榜单数值经第 005 讲收录，本讲复算。

核心原理

1. 四条指标的分工与 2023 榜单

四个量的分工先明确。SR 回答「是否跨过成功判据」，只做二值判定；SPL 回答「成功时路径多高效」，失败一律记零；SoftSPL 回答「离成功多近」，每条失败轨迹按进度比例得分，且不检查停止信号；DTG 回答「结束时差多少米」，不做任何成功判定。挑战页的主排序是 SPL，SoftSPL 与 DTG 在榜单与论文表中作为并列报告的诊断量；2023 判据为停止信号加 1 m 欧氏距离加 oracle 可见性，评测 1000 条 episode。

三列排序逐一看。SPL：IPPON 0.34 第一，SkillFusion 与 SkillTron 并列 0.28，ICanFly 0.26，其后直接落到 0.10 与 0.05。SoftSPL：IPPON 0.46 第一，ICanFly 0.37 升到第二，SkillTron 0.36、SkillFusion 0.34 依次后移。SR：SkillTron 0.59 第一，IPPON 0.54、SkillFusion 0.53 紧随。三种排序中，IPPON 的名字都在前三，但没有任何一个指标让六支队伍的顺序完全一致。

缺口列给出诊断信息。SoftSPL−SPL 从 0.06 到 0.22，比值从 1.21 到 5.40，规律与第 005 讲一致：SPL 越低，软化带来的相对增益越大，说明这些方案的失败大量发生在接近目标处。SoftSPL−SR 一列发生符号翻转：SR 0.18 及以下的两支队伍为正（失败比成功更常见，但失败离目标不远），SR 0.43 及以上的四支队伍为负。负值不表示指标出错：高成功率队伍的失败已经很少，SoftSPL 的均值由成功轨迹主导，而每条成功轨迹的停止点距目标仍有残余距离、路径也未必最短，两项损耗相乘后 SoftSPL 自然低于 SR。用第 005 讲的恒等式读：成功率越高，「成功残余损耗」项越能盖过「失败部分得分」项。

条件效率 SPL/SR 是第四个视角：它把成功率除掉，近似衡量「成功一条要付出多少路径代价」。在成功率 0.4 以上的队伍中，IPPON 的 0.6296 最高、SkillTron 的 0.4746 最低。SkillTron 的成功最多、单条效率最低，IPPON 的成功略少、单条效率最高，两种优势类型无法合并成一个名次；这正是挑战页拒绝用单指标排名、并声明 SPL 差异不显著时参考附加指标的原因。

2. 排序冲突的三种形态

把榜单抽象成三种可检验的冲突形态，评审时按形态对照，比背诵具体名次更有用。

形态一，成功率领先、效率落后。代表是 SkillTron：SR 第一（0.59），SPL 与 SoftSPL 都不是第一，条件效率在成功率 0.4 以上的队伍中最低。这种形状常见于「搜索覆盖优先」的方案：宁可多走也要确保找到，失败少而成功轨迹长。

形态二，效率领先、成功率落后。代表是 IPPON：SPL 与 SoftSPL 第一，SR 0.54 第二。这种形状常见于「概率引导加终止优先」的方案：路径直、停点准，未找到的 episode 数量略多。第 034 讲的 MFNP 是镜像案例：成功率超过 VLFM（58.3 对 52.5，相对 +11.05%），SPL 反低 0.037（相对 −12.17%），条件效率 0.4580 低于 VLFM 的 0.5790。跨楼层策略用更长的搜索路径换更高的找到概率，SR 与 SPL 的排名必然分叉。

形态三，失败接近度高但成功率低。代表是 Host team 与 Auxiliary RL：SoftSPL 与 SPL 的比值达到 5.40 与 3.10，SoftSPL 高出 SR 0.15 与 0.13，说明大量轨迹停在目标附近却未满足判据。2022 榜的榜尾两行重现同一形态：ddx 的 Soft/SPL 为 1.9231，TreasureHunt 为 2.0000，而榜首两行只有 1.0857 与 1.0909。2021 MP3D 榜更极端：Red Rabbit 1.6923、Habitat on Web 3.0000、Alstar 2.7500。

三种形态合起来给出一条评审规则：先按主指标 SPL 定位档次，再用 SoftSPL 分辨「差一点」与「差很远」，用 DTG 看失败纵深，最后用条件效率判断成功轨迹的代价结构。任何只引用其中一列的结论都应要求补充其余三列。

3. 统计分辨率：1000 条 episode 能分辨多大差距

榜单让成绩看起来精确到 0.01，但每个数字都有采样误差。成功率是二项比例，标准误为：

SE(SR) = √( p (1 − p) / N ) p 为成功率，N 为 episode 数；N = 1000 时可用它估计 95% 半宽约为 1.96 SE

代入数字：p = 0.54 时 SE = √(0.54 × 0.46 / 1000) = 0.01576，95% 半宽 0.03089；p = 0.59 时 SE = 0.01555，半宽 0.03048。单队的区间已经接近 ±0.03，两队差值的区间更宽。按独立样本近似，SkillTron 0.59 与 IPPON 0.54 的差值 0.05，差值标准误 √(0.01555² + 0.01576²) = 0.02214，95% 半宽 0.04340，差值 0.05 仅略高于半宽；SkillTron 0.59 与 SkillFusion 0.53 的差值 0.06 与半宽 0.04343 的关系类似。

独立样本的算法对挑战榜偏保守，因为所有队伍评测同一批 1000 条 episode，成功与失败是配对的。配对比较只看两队结论不一致的 episode：一队成功、另一队失败的数量构成 McNemar 检验的两个计数，方差通常小于独立口径。实现配对比较需要逐 episode 的返回值，这也是第 005 讲要求保留逐条字段的原因。若只有聚合榜单，只能按独立口径给出保守估计，并在报告中写明这一点。

样本量的角度同样重要。要在 5% 显著性水平、80% 检验力下分辨 0.05 的成功率差，独立口径每组约需 1543 条 episode；分辨 0.03 约需 4287 条；分辨 0.02 约需 9645 条。1000 条 episode 的标准赛道足以分辨 0.05 以上的大幅差距，不足以稳定分辨 0.02 到 0.03 的细微改进；论文正文声称小幅提升时必须给出区间或配对检验。

还有一层多重比较问题。六支队伍两两比较共 15 组，若每组都用 5% 显著性水平而不做校正，期望误报约 0.75 组；把六个方法乘四个指标，比较次数进一步放大。稳妥做法是预注册主指标与主比较，把其余结果标注为探索性分析，或使用 Bonferroni、Holm 之类的校正。

4. 榜单协议与反作弊

2023 挑战的提交分三档：minival 用于本地与远程一致性检查，每天上限 100 次；test-standard 用于论文报告，每天上限 10 次；test-challenge 决定名次，每队总共 5 次，成绩在研讨会公布前不公开。评测环境为 AWS p2.xlarge（Tesla K80，12 GB 显存），1000 条 episode，总时限 48 小时。论文应当报告 test-standard 成绩；把 test-challenge 的名次与 test-standard 的数字混在一张表里会破坏可比性，提交预算的差异也会影响成绩的可复现程度。

反作弊要盯住 SoftSPL 的口径特性。SoftSPL 不依赖停止信号，逐帧更新且在末步取值，因此一个从不发出停止信号、却在某一时刻恰好靠近目标的策略也能拿到高分；第 005 讲的 E8 样例（无 STOP，SoftSPL 0.9357）就是构造证明。评测侧应同时报告 stopped 比例与 SoftSPL，并把未停止却高分的情形单列。另一处是距离口径：d0 与 dT 必须取自同一档 distance_to（POINT 或 VIEW_POINTS），混档会让比值失去几何含义。episode 起点若落在目标的成功区内，d0 趋零会使进度项失稳，数据生成侧应保证 d0 至少为成功半径的两倍。

2023 协议还有三项边界需要写进报告：episode 全部可在单层内完成，多楼层方法的优势无法在标准赛道上体现；判据为 1 m 加 oracle 可见性，论文自定义的 0.1 m 判据不能与榜单并排；数据集为 HM3D-Semantics v0.2（216 个场景，划分 145 / 36 / 35），与 MP3D 的 21 类口径不可混谈。

5. 数值算例（Python 实算）

算例一，缺口与比值复核。以 IPPON 为例：SoftSPL−SPL = 0.46 − 0.34 = 0.12；SoftSPL/SPL = 0.46 / 0.34 = 1.3529；SoftSPL−SR = 0.46 − 0.54 = −0.08；条件效率 = 0.34 / 0.54 = 0.6296。同一套算式对另外五队逐行复算，结果与上表一致。Host team 的四项为 +0.22、5.4000、+0.15、0.4167。

算例二，跨案例对照。MFNP 相对 VLFM 的成功率高 5.8 个百分点（相对 +11.05%），SPL 低 0.037（相对 −12.17%），条件效率 0.4580 对 0.5790。把 2023 挑战的 IPPON 与第 034 讲的 MFNP 放在同一评审框架里：两者都优秀，类型不同，IPPON 属于效率领先型，MFNP 属于覆盖领先型；用同一条「SR 优先或 SPL 优先」的规则二选一会丢掉信息。

算例三，统计分辨率。SE(0.54) = 0.01576，SE(0.59) = 0.01555，差值独立口径 SE = 0.02214，95% 半宽 0.04340；分辨 0.05、0.03、0.02 成功率差所需的每组 episode 数约为 1543、4287、9645；15 组两两比较在 5% 水平下的期望误报 0.75 组。三组数字共同说明：榜单排序在头部的小间距上不稳健，模块化方法的选型结论应绑定具体指标与区间，不绑定名次。

6. 适用边界与失效模式

  • SoftSPL 与停止意图解耦：未停止的高分轨迹必须单列；演示或论文引用时写明评测是否要求 STOP。
  • 距离口径敏感：POINT 与 VIEW_POINTS 两档不可混用；跨 Habitat 版本的 SoftSPL 不可直接对比。
  • 榜单舍入：两位小数下 0.01 的差距失去有效位数，比值在 SPL 接近零时只能给下界。
  • 数据集不可比：MP3D 21 类、HM3D-Sem v0.1 与 v0.2、HM3D-OVON 的类别与难度不同，SR 与 SPL 的数值不可并排。
  • 单层限制：2023 标准赛道 episode 不跨楼层，跨层能力需要单独协议（第 034 讲）。
  • 成绩阶段混淆：test-standard 与 test-challenge 的提交预算与公开程度不同，混用会误读稳定性。

实现思路与设计

本讲的设计产出是一份可复用的模块化评测报告模板：字段一次写全，任何方法放进同一张表就能横向比较；配套一张指标选择表与一套失败分层协议，避免每次评审都临时商量口径。

3. 失败分层协议

分层用四个桶：近失（未成功但 DTG 不超过 2 m，可由 SoftSPL 与 DTG 联合判定）、远程失败（DTG 超过 2 m 或未接近过目标）、未停止（轨迹接近目标但无 STOP，SPL 记零而 SoftSPL 高分）、卡滞或绕圈（步数耗尽且轨迹长度异常，可由轨迹曲率与重复访问统计识别）。四桶之外把目标缺失与不可检测的 episode 单列，因为它们的失败与策略无关。每桶报告占比与典型样例，修复优先级按桶的贡献排序，第 033 讲的分类学与这里的统计口径配套使用。

设计决策：主排序不合成单一名次

四个指标回答不同问题，加权合成会引入任意权重并切断与挑战页的可比性。正确做法是固定主指标（SR 与 SPL）用于对外比较，附加指标用于内部分析；若必须给出综合判断，报告条件效率与近失率两个可解释的派生量。

口径提醒：SoftSPL 不是成功率的平滑版本

不要求 STOP、逐帧取值、对 d0 敏感，三条性质都能制造出高分却不成功的记录。评审流程应固定为：先看 SR 与停止比例，再看 SPL 与条件效率，最后用 SoftSPL 与 DTG 细分失败。

与前一讲的衔接：第 036 讲的消融表本身就是本讲框架的用例，去掉引导模块后 SPL 下降 0.03，但 SR 与 SoftSPL 也同步下降，说明该模块影响多层指标，不属于「效率换成功率」的取舍型改动。评审一个模块时，先判断它属于「取舍型」还是「同时改进型」，再决定是否需要协议层面的额外证据。

片段 1：单条 episode 的四指标计算

import numpy as np

def episode_metrics(d0, dt, path, stopped, success_dist=1.0):
    """返回 (success, spl, softspl, dtg)；d0、dt 为测地距离，path 为平移路径。"""
    success = int(bool(stopped) and dt < success_dist)     # STOP 与距离共同决定
    spl = success * d0 / max(d0, path)                      # 失败记零
    progress = max(0.0, 1.0 - dt / d0)                      # 走远后截断为零
    softspl = progress * d0 / max(d0, path)                 # 不依赖 STOP
    return success, spl, softspl, float(dt)

def evaluate(records):
    """records 为逐条字典列表；返回四指标均值与停止比例。"""
    out = [episode_metrics(**r) for r in records]
    arr = np.asarray(out, dtype=float)
    return {"SR": arr[:, 0].mean(), "SPL": arr[:, 1].mean(),
            "SoftSPL": arr[:, 2].mean(), "DTG": arr[:, 3].mean(),
            "stopped_ratio": float(np.mean([r["stopped"] for r in records]))}

解读：（1）成功判据集中在 episode_metrics 一处，切换 0.1 m 与挑战口径只改 success_dist 与 stopped 的语义，评测代码不散落判断；（2）SoftSPL 与 STOP 解耦，返回的 stopped_ratio 单独成列，用于审计高分未停记录；（3）d0 的保护在数据生成侧完成，函数内不额外截断，避免隐藏上游口径错误；（4）DTG 直接返回数值，不做聚合平均之外的加工。

片段 2：同 episode 配对 bootstrap 区间

def paired_bootstrap(a, b, n_boot=2000, seed=0):
    """a、b 为同一批 episode 的逐条指标；返回差值均值与 95% 区间。"""
    diff = np.asarray(a, dtype=float) - np.asarray(b, dtype=float)
    n = len(diff)
    rng = np.random.default_rng(seed)
    idx = rng.integers(0, n, size=(n_boot, n))              # 按 episode 重采样
    boots = diff[idx].mean(axis=1)                          # 每次都保配对结构
    return float(diff.mean()), float(np.percentile(boots, 2.5)), \
        float(np.percentile(boots, 97.5))

def mcnemar_counts(success_a, success_b):
    """成功指示的对子；返回两方结论不一致的计数 (A败B胜, A胜B败)。"""
    a = np.asarray(success_a, dtype=bool)
    b = np.asarray(success_b, dtype=bool)
    return int(np.sum(~a & b)), int(np.sum(a & ~b))

解读：（1）配对 bootstrap 对索引重采样，两方法在同一重采样样本内比较，方差小于独立口径；（2）采样单位必须是 episode，禁止对多条指标分别重采样；（3）fixed seed 保证报告可复现，区间随样本量收敛，不随重采样次数收缩；（4）McNemar 两个计数只依赖成功指示，用于成功率差的显著性判断，SPL 类连续指标的配对检验交给 bootstrap。

片段 3：失败分层与近失率

def failure_buckets(records, near=2.0, success_dist=1.0):
    """按近失、远程、未停、卡滞四桶统计失败 episode。"""
    buckets = {"near_miss": 0, "remote": 0, "no_stop": 0, "stuck": 0,
               "total_fail": 0}
    for r in records:
        if r["stopped"] and r["dt"] < success_dist:
            continue                                        # 成功不进入失败桶
        buckets["total_fail"] += 1
        if r["dt"] <= near:
            if r["stopped"]:
                buckets["near_miss"] += 1
            else:
                buckets["no_stop"] += 1
        elif r.get("stuck_flag", False):
            buckets["stuck"] += 1
        else:
            buckets["remote"] += 1
    total = sum(buckets[k] for k in ("near_miss", "remote", "no_stop", "stuck"))
    buckets["near_miss_rate"] = buckets["near_miss"] / max(total, 1)
    return buckets

解读：（1）分桶顺序先看距离再看卡滞标记，保证近失与未停的优先归类；（2）near 阈值默认 2 m 是诊断用教学值，报告时应声明并做一档敏感性（例如 1.5 m 与 3 m）；（3）stuck_flag 由轨迹统计外部提供（例如重复访问率与净位移），本函数只消费不计算；（4）目标缺失的 episode 应在数据侧先剔除或单列，混入四桶会把与策略无关的失败计入方法改进空间。

常见误区

  • 把 SoftSPL 当成功率：症状是引用一个从未停止却拿到 0.9 以上 SoftSPL 的演示作为「接近成功」的证据。根因是忽略 SoftSPL 不依赖 STOP。修复：同时报告 stopped 比例与 SR，把未停高分单列。
  • 忽略配对结构：症状是同一批 episode 上两队的 0.05 差距被说成显著，或不显著。根因是按独立样本算区间。修复：保留逐条返回值，用配对 bootstrap 与 McNemar 计数，并写明评测是否使用同一批 episode。
  • 跨数据集跨判据并排：症状是把 MP3D 21 类成绩与 HM3D 6 类成绩放进同一张表，或把 0.1 m 判据的成功率与挑战榜对比。根因是只抄数字不看协议。修复：每张表标注数据集版本、类别数、判据与动作空间。
  • DTG 单独排名：症状是「DTG 最小」被当成最优方案。根因是 DTG 不区分成功与失败，全员失败且停点集中的方案也能得到低均值。修复：DTG 与 SR、SPL 成组报告，并排查其分布是否被少数接近轨迹拉低。
  • 多重比较不做校正：症状是从 15 组两两比较中挑出一组「显著」结果写进摘要。根因是未预注册主比较。修复：预注册主指标与主对比，其余结果标注探索性，或用 Holm 校正。

小结

  • 四条指标分工固定：SR 判定、SPL 主排序、SoftSPL 度量失败接近度、DTG 记录失败纵深；挑战页只把 SPL 当作主排序，其余并列报告。
  • 2023 标准赛道：IPPON SPL 0.34 与 SoftSPL 0.46 第一，SR 0.54 第二；SkillTron SR 0.59 第一而单条效率在成功率 0.4 以上的队伍中最低。三种排序冲突的形态分别是覆盖优先、效率优先、失败接近度高。
  • 模块化案例：MFNP 相对 VLFM 成功率高 5.8 个百分点、SPL 低 0.037（−12.17%），属于成功率换效率的取舍型改动；评审必须成组报告。
  • 统计分辨率：N = 1000 时成功率标准误约 0.016，差值 95% 半宽约 0.043；分辨 0.05、0.03、0.02 的差距分别约需 1543、4287、9645 条每组；15 组两两比较的期望误报约 0.75 组。
  • 反作弊与协议：SoftSPL 不要求 STOP、距离口径必须同档、d0 设下限；论文报告 test-standard；单层限制与数据集版本写进每张表。
