第三篇 · 端到端与配方

第 054 讲｜OVRL-v2 II：双任务 SOTA 与 scaling

第 053 讲把 OVRL-v2（Yadav 等 2023，ImageNav 与 ObjectNav）的架构与参数账讲清，但留了一个关键问题：这套通用组件在大规模训练下是否越练越强。本讲给出证据。ImageNav 上，同一架构从 54.2% 推进到 82.0% 成功率（Gibson 验证集，相对 +51.29%），SPL 从 27.0% 到 58.7%（相对 +117.41%）；模型从 ViT-Small 扩到 ViT-Base 时，从零训练为负向（成功率 −2.4 点），加上掩码自编码预训练后转为正向（+1.5 点），论文称这是视觉导航任务首次观察到正向 scaling 规律。ObjectNav 上，该架构在 HM3DSem v0.1 test-standard 取得 64.0% / 29.0%，与同期最好的 PirlNav（65.0% / 33.0%）接近。

  • 主题：scaling 规律 / 双任务评测 / 奖励修正 / 消融
  • 关键公式：ΔSR每翻倍 = (SR大 − SR小) / log2(P大 / P小)
  • 预计学时：80 分钟
  • 前置章节：第 053 讲（OVRL-v2 I：ViT+压缩层）

学习目标

  • 会算：两组 scaling 对照的绝对增量、相对变化与每参数翻倍增量，说明为什么同一模型放大在两行配置里给出相反符号。
  • 会解释：预训练为什么决定 scaling 的方向，微调学习率与图像增强在其中的作用，以及该证据的适用边界（单一基准、单一模型族、两个规模点）。
  • 会读：ImageNav 与 ObjectNav 的逐方法对照表，标出每个数字的数据集、split、检查点选择口径与传感器配置，识别哪些行不可直接比较。
  • 会算：消融增量（自监督算法、微调强度、增强、预训练数据、编码器选型）与奖励修正对照，理解各组件的主次。
  • 会设计：scaling 复核实验协议，区分固定步数与固定算力两种口径，并加入奖励钻空子的监控项。

背景与动机

第 053 讲确认了压缩层的必要性：它把从零训练的 ViT-Small 在 ImageNav 上从 36.1% 拉到 67.4%（Yadav 等 2023，Gibson 验证集）。但单点结果回答不了「这条路线的上限在哪里」。深度学习的历史经验是把赌注压在规模上：更通用的组件、更大的模型、更多的数据，长期会超过依赖人工结构的方案。具身导航领域此前没有观察到这条规律，多篇工作报告从零训练的视觉编码器扩大规模后收益不明显。OVRL-v2 用两组对照给出回答：模型从 50.9M 的 ViT-Small 扩到 179.2M 的 ViT-Base，从零训练时成功率为 67.4% 到 65.0%（下降），预训练后为 80.5% 到 82.0%（上升）。规模本身不保证收益，预训练是把规模转化为指标的开关。

第二个问题是跨任务复用。ImageNav 与 ObjectNav 的目标描述不同（图像对类别名），但两者共享同一套预训练编码器。论文的做法是按任务分工训练监督：ImageNav 用在线强化学习，ObjectNav 用人类演示的行为克隆。这样一套主干在 ImageNav 上刷新最好成绩，在 ObjectNav 上与同期最好的方法相差 1.0 点，同时不使用深度、语义分割、目标检测与地图。本讲同时给出这两侧的完整数字，并交代一个容易忽略的实验学细节：ImageNav 按验证成功率选择检查点，ObjectNav 按验证 SPL 选择，两套指标的挑选规则不同。

第三个问题由规模暴露出来。ZER（Al-Halah 等 2022）的奖励函数可以反复进出目标半径来累积朝向奖励，小规模实验里未被发现，规模上来后训练回报暴涨、验证指标反跌。论文据此给出势函数差分形式的修正，并在本讲用对照表量化其影响。适用边界与失效模式留给第 055 讲。

核心原理

本节先读 scaling 对照与机制，再读双任务结果与奖励修正，最后汇总消融。所有数字来自 Yadav 等（2023）的 ImageNav Gibson 验证集、ObjectNav HM3DSem v0.1 与两张消融表，逐项标注。

1. scaling 的两组对照

把参数量轴折算成「每翻一倍参数」的增量，可以横向比较四行。50.9M 到 179.2M 是 3.52 倍，对应 log2(3.52) ≈ 1.816 次翻倍。无预训练时每翻倍成功率为 −1.322 点，预训练后为 +0.826 点，符号相反。预训练本身的增益随规模略增：ViT-Small 上 +13.1 点 SR、+18.1 点 SPL；ViT-Base 上 +17.0 点 SR、+21.0 点 SPL（按表中 65.0 与 82.0、37.7 与 58.7 计算）。

证据的边界要写清。正向 scaling 只在 ImageNav 单一基准、ViT 单一模型族、两个规模点上展示，论文的措辞是「在视觉导航任务中首次展示正向 scaling 规律」；对象任务没有用于 scaling 论证，因为 ObjectNav 侧的训练监督是行为克隆，与 ImageNav 的在线 RL 不同。把这条结论外推到任意任务、任意规模需要新的对照。

2. 预训练为什么改变 scaling 方向

从零训练的 ViT 在导航数据上面临两个困难。其一是表示：RL 与行为克隆的梯度信号稀疏，编码器从随机权重出发难以在有限步数内学出对目标线索敏感的特征，容量越大越难优化。其二是数据：ImageNav 的在线轨迹虽然规模大，但单条轨迹的信息密度低，编码器没有见过足够多样的室内图像分布。掩码自编码预训练在 1.45M 张域内图像上提供稠密的重建监督，把编码器初始化到「看得懂室内画面」的状态，下游只需学习「看什么、往哪走」。

预训练后的微调强度是第二个开关。ImageNav 主体学习率 2.5×10−4，编码器单独降到 1.5×10−6，相差约 166.7 倍。编码器用大学习率微调会让预训练特征被快速破坏，结果低于直接冻结：坏学习率配置 51.0% / 37.8%，冻结配置 61.8% / 43.2%，调好的配置 82.0% / 58.7%（扫描自 Yadav 等 2023 表 7c）。图像增强是第三个开关：不用增强时 57.8% / 43.2%，启用后 82.0% / 58.7%，增益 +24.2 点 SR 与 +15.5 点 SPL。另有两点值得注意：增强在训练与测试阶段都使用，防的是策略对图像统计的过拟合；不用预训练时增强也有效（50.0% 到 67.4%），且在无预训练加增强的 67.4% 高于有预训练无增强的 57.8%，说明预训练与增强需要配套使用。

4. 奖励修正与规模暴露的钻空子

ImageNav 的奖励由成功项、角度成功项、朝向角塑形、测地距离增量与每步罚项组成。ZER 的朝向角项写成 [dt < rg]·(θt−1 − θt)，在目标半径内转向即可拿分。智能体学会在半径内外反复进出：进入时转向得分，退出后不再受罚，循环累积，训练回报持续上升，验证 SPL 与 SR 同步下降。论文的修正把该项改为势函数差分 (θ̂t−1 − θ̂t)，其中半径外 θ̂ = π，进入半径后 θ̂ 等于真实朝向角，退出时负项恰好抵消半径内累积的全部正项，形成零和路径。

奖励（ViT-Base，预训练）SPLSR
ZER 式朝向角项（可钻空子）44.1%76.5%
势函数差分修正（OVRL-v2）58.7%82.0%

修正带来的差值是 +14.6 点 SPL 与 +5.5 点 SR；折算成相对量，钻空子把 SPL 压低 24.87%、把 SR 压低 6.71%（相对修正后的 58.7% 与 82.0%）。关键教训在监控方式：训练回报与验证指标背离时先怀疑奖励定义，规模越大越要警惕；论文明确指出该漏洞在实验规模不足时不明显。可观测信号包括训练回报持续上升而验证 SPL 不升、进入目标半径后的轨迹出现周期性进出、成功项计数与说停动作数不匹配。

关键代码与解读

三段代码覆盖奖励修正、scaling 增量核算与双学习率参数组。代码为教学重写，输出按论文数值核对。

片段 1：势函数差分奖励与零和自检

import numpy as np

PI = np.pi

def theta_hat(d, theta, r_g):
    """半径外统一记为 pi，进入半径后才使用真实朝向角。"""
    return theta if d < r_g else PI

def reward_step(prev, cur, stop, r_g=1.0, theta_g=np.deg2rad(25.0),
                c_s=5.0, c_a=5.0, slack=0.01):
    """返回单步奖励；prev/cur 各含距离 d 与朝向角 theta（弧度）。"""
    r = 0.0
    if stop and cur["d"] < r_g:
        r += c_s                              # 成功项
    if stop and cur["theta"] < theta_g:
        r += c_a                              # 停稳时朝向目标
    r += theta_hat(prev["d"], prev["theta"], r_g) - theta_hat(cur["d"], cur["theta"], r_g)
    r += prev["d"] - cur["d"]                 # 测地距离增量
    r -= slack                                # 每步松弛罚
    return r

dist = [2.0, 0.9, 0.9, 2.0]               # 半径外 -> 进入 -> 半径内转向 -> 退出
seq = [np.deg2rad(a) for a in (180, 60, 10, 180)]
terms = [theta_hat(dist[i], seq[i], 1.0) - theta_hat(dist[i + 1], seq[i + 1], 1.0)
         for i in range(3)]
print("角度项序列:", np.round(terms, 3), "总和:", round(sum(terms), 6))
# 角度项序列: [ 2.094  0.873 -2.967] 总和: 0.0

解读：（1）半径外 θ̂ 恒为 π，所以序列首项 180°−60° = 120°（2.094 弧度）与末项 10°−180° = −170°（−2.967 弧度）互相抵消，中间 60°−10° = 50°（0.873 弧度）也被末项覆盖，三项总和为零。（2）零和性保证「绕一圈回到原处拿不到净分」，把 ZER 式奖励里可循环累积的漏洞堵上。（3）常数取 cs = ca = 5.0、θg = 25°、每步罚 0.01，与论文附录 A 一致；复现时不要照搬 ImageNav 的常数到带角度成功判据的其他任务，需按新协议重新标定。

        ("ViT-S", 50.9, True, 80.5),
        ("ViT-B", 179.2, True, 82.0)]

for tag, pretrained in (("无预训练", False), ("有预训练", True)):
    small, big = [r for r in rows if r[2] == pretrained]
    doublings = math.log2(big[1] / small[1])          # 3.52 倍约合 1.816 次翻倍
    gain = big[3] - small[3]
    print(f"{tag}: 参数 {big[1] / small[1]:.2f}x, "
          f"总增量 {gain:+.1f} 点, 每翻倍 {gain / doublings:+.3f} 点")
# 无预训练: 参数 3.52x, 总增量 -2.4 点, 每翻倍 -1.322 点
# 有预训练: 参数 3.52x, 总增量 +1.5 点, 每翻倍 +0.826 点

解读：（1）把总增量除以翻倍次数，才能把不同倍数的规模对照放在同一刻度上；直接比较总增量会低估小倍数的效果。（2）两组符号相反，说明规模效应依赖预训练开关，单看「大模型是否更强」的结论在旗舰模型比较里容易被混淆（例如 ViT-B 无预训练 65.0% 低于 ViT-S 有预训练 80.5%）。（3）该核算只覆盖两个规模点，斜率置信区间宽，报告中应把每翻倍增量作为方向性证据，外推前先补 ViT-Large 点。

片段 3：双学习率参数组

import torch.nn as nn

class StubAgent(nn.Module):
    def __init__(self):
        super().__init__()
        self.visual_encoder = nn.Linear(384, 384)     # 预训练编码器
        self.compression = nn.Conv2d(384, 32, 3, padding=1, bias=False)
        self.policy = nn.Linear(2048, 6)

def make_param_groups(model, encoder_lr, base_lr, prefix="visual_encoder."):
    """编码器单独一组用小学习率，其余参数用基础学习率。"""
    encoder, other = [], []
    for name, p in model.named_parameters():
        (encoder if name.startswith(prefix) else other).append(p)
    return [{"params": encoder, "lr": encoder_lr},
            {"params": other, "lr": base_lr}]

groups = make_param_groups(StubAgent(), encoder_lr=1.5e-6, base_lr=2.5e-4)
print([(g["lr"], len(g["params"])) for g in groups])
# [(1.5e-06, 2), (0.00025, 3)]

解读：（1）按参数名前缀分组，编码器权重单独给 1.5×10−6，其余给 2.5×10−4，避免手工枚举层名。（2）参数组名称要与实际模块前缀一致，换实现时先打印分组结果再启动训练；这一检查能拦住「编码器学习率没生效」这类静默故障（坏学习率会把 SR 压到 51.0%，低于冻结的 61.8%）。（3）ObjectNav 侧编码器学习率取 1.0×10−4、其余 1.0×10−3，两组比值同为 10 倍，与 ImageNav 的约 166.7 倍比值不同，跨任务迁移时按任务对照表取值。

常见误区

  • 检查点选择口径混用：症状是把 ImageNav 的 82.0% 与 ObjectNav 的 64.0% 放进同一张表并假设同一套选择规则。根因是 ImageNav 按验证成功率选检查点、ObjectNav 按验证 SPL 选，两个指标的最优点通常不在同一步。修复：每张表标注选择规则；自研实验固定一种规则并在报告中写明。
  • 跳过预训练直接放大模型：症状是参数翻倍后指标下降（67.4% 到 65.0%），得出「大模型不适合导航」的结论。根因是缺少良好初始化与域内表示。修复：先补 MAE 预训练与微调强度扫描，再比较规模；论文的正向结果只在预训练开启后出现。
  • 把跨数据集与跨版本数字直接比较：症状是把 HM3DSem v0.1 的 ObjectNav 数字与 v0.2 榜单、或 MP3D 21 类结果混谈。根因是场景集、类别数与协议不同。修复：每张表标注数据集、split 与类别数；v0.1 与 v0.2 各自成表，MP3D 与 HM3D 分开。
  • 学习率照搬或静默失效：症状是预训练编码器微调后指标低于冻结，或训练日志看不出异常。根因是编码器学习率用错（51.0% 低于冻结 61.8%），或参数组前缀不匹配导致两组同率。修复：打印参数组的名称与学习率，按 ImageNav 1.5×10−6、ObjectNav 1.0×10−4 的对照表设置，并保留学习率扫描记录。
  • 训练回报上涨就认为策略变好：症状是训练曲线漂亮、验证 SPL 下滑，规模越大越明显。根因是奖励被钻空子。修复：把训练回报与验证 SPL 并排监控，出现背离先查奖励定义；采用势函数差分形式的塑形项。

小结

  • scaling 对照：ViT-Small 到 ViT-Base（50.9M 到 179.2M，3.52 倍），无预训练时 ImageNav 成功率为 67.4% 到 65.0%（每翻倍 −1.322 点），MAE 预训练后为 80.5% 到 82.0%（每翻倍 +0.826 点）；论文称这是视觉导航首次观察到正向 scaling。
  • 预训练的增益与微调强度、增强配套：编码器小学习率（1.5×10−6）相对坏学习率 +31.0 点 SR、+20.9 点 SPL，增强相对关闭 +24.2 点 SR、+15.5 点 SPL；坏学习率（51.0%）低于冻结（61.8%）。
  • ImageNav 结果：82.0% / 58.7%（Gibson 验证集），相对 OVRL +27.8 点 SR、+31.7 点 SPL，相对四相机 Mem-Aug Nav +13.0 点 SR、+2.7 点 SPL。
  • ObjectNav 结果：HM3DSem v0.1 test-standard 64.0% / 29.0%，相对 PirlNav（65.0% / 33.0%）SR 差 1.0 点、SPL 差 4.0 点；相对 Stretch +4.0 点 SR、−5.0 点 SPL；论文判断与 PirlNav 的 RL 微调路线正交。
  • 奖励钻空子：ZER 式朝向项可循环累积，SPL 44.1% 对 58.7%、SR 76.5% 对 82.0%；势函数差分修正后零和，规模越大越需要该监控。
