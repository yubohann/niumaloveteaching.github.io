第三篇 · 协同控制与任务协同

第 051 章：协同探索未知环境

把 050 章的协同机制放进真实世界：通信时断时续、地图各执一词、目标可能在路上"消失"。用机会通信、log-odds 证据融合、目标复检与周期会合，把探索系统做成断连也不失灵的样子。

  • 主题：任务协同 / 受限通信探索
  • 关键机制：机会通信队列、log-odds 融合、目标锁定与复检、会合调度
  • 预计学时：65 分钟
  • 前置章节：第 050 章

学习目标

  • 理解"未知环境"包含双重未知：空间未知与通信未知，后者决定协同架构的形态。
  • 掌握机会通信（store-carry-forward）队列的设计：优先级、TTL、复连批量发送与预算控制。
  • 会用 log-odds 表示与证据相加实现可交换、可结合的地图融合，理解限幅的必要性。
  • 能设计目标锁定、到达前复检与弃置条件，避免"抱着过期目标跑空"与"目标震荡"。
  • 会规划会合（rendezvous）调度：会合频率与探索效率的定量权衡，以及通信窗口预算。

背景与动机

050 章在"网络良好、地图共享顺畅"的假设下建立了协同探索闭环。真实未知环境的两个特征会同时推翻这个假设：(1) 通信随位置随机中断，墙、楼梯间、地下层把 WiFi 切成一个个孤岛，机器人走进盲区就"失联"几分钟；(2) 地图彼此不一致，同一条走廊，两台机器人的局部地图可能一个说通、一个说墙（传感器角度与建图漂移导致），累加的差异如果不按证据融合处理，会在合并时互相抹除。

这一章不引入新任务，专注把 050 章机制的每一环都做"抗断连与抗不一致"加固：消息发不出去怎么办（机会队列）、地图打架怎么办（log-odds 融合与冲突复检）、目标失联期间过期了怎么办（复检与弃置）、整队长期失联怎么重新同步（周期会合）。这套打法同样适用于巡检、搜救等一切"基础设施不可靠"的现场任务。

核心原理

1. 双重未知：空间未知与通信未知

探索未知空间时，机器人的每一步都在产生新知识（"这里能走"）；但通信未知意味着"新知识传不出去"，队友在盲区外永远看到旧地图。两个未知耦合在一起：越往深处探，通信越差、知识越局部；退出来通信恢复了，却又浪费了探索时间。协同系统的设计目标因此从"最优化分配"变成"断连可活、复连可续"，每个机器人在任何时刻都能独立完成"继续探索"与"按计划返回/会合"两件事。

2. 机会通信：把消息存起来等网络

机会通信（opportunistic networking）的模型很朴素：发不出去的消息不丢弃，按优先级入本地队列；链路恢复或相遇时批量发送。队列的三条纪律：

  • 优先级：地图增量（0）> 目标与认领状态（1）> 遥测与统计（2）。地图是探索的"共同真理"，最值得抢带宽；遥测基本可以等。
  • TTL（生存期）：地图块 300 s、目标状态 60 s、遥测 10 s。过期消息比没有消息更危险，它会把队友的地图"打回过去"。
  • 发送预算：复连后按时间片发送（例如每 200 ms 发 20 条），避免突发洪峰把刚恢复的窄链路再次压垮；抢带宽的优先级由队列排序决定，先来先发只用于同优先级内部的平局。

会合（rendezvous）是机会通信的"主动版"：既然被动等相遇太随机，就约定每 T 分钟在区域中央或入口会合一次，交换地图与任务状态。会合频率的权衡可以直接算：设会合耗时 tr（含往返与交换）、会合周期 Tc，则探索效率损失约为 tr / Tc。Tc = 120 s、tr = 25 s 时损失约 20%；Tc = 300 s 时损失 8%，但两次会合间的地图分歧窗口长达 5 分钟，取舍点取决于区域大小与失联风险，通常先取 120–300 s 再用实验收敛。

3. log-odds：让地图融合对"乱序到达"免疫

用"已知覆盖未知"的规则做合并（050 章）在断连场景会出错：两台机器人对同一格产生的结论可能相反，谁先到就覆盖谁，结果依赖网络时序。更稳的表示是 log-odds（对数几率）地图：每格保存 l = log(pocc / (1 − pocc))，一次测量带来的证据是常数（占用 +0.85、空闲 −0.41 之类），融合就是相加：

lnew(x) = lold(x) + lz(x)，  lz = log(pz / (1 − pz)) 加法可交换、可结合 → 与消息到达顺序无关；判读时 l > 0 视为占用、l < 0 视为空闲、|l| 接近 0 为未知

加法还要求限幅（如 ±3，对应概率 0.95）：同一堵墙被观测一千次，未限幅的 l 会膨胀到无穷，一个新出现的门（合法通道）要用天文数字的证据才能翻案。限幅让地图保留"可被新证据修正"的能力，这对动态环境至关重要。冲突格（一方证据偏占用、一方偏空闲）在 log-odds 上会自然抵消回到接近 0 的"不确定"，系统据此可以安排"复检访问"，用一次实地观测替目前的猜测。

4. 过时目标的处置：复检与锁定

断连期间，机器人奔向的目标可能已被队友探索（信息丢失）或已被证明进不去。两个机制配合：

  • 到达前复检：距离目标 3 m 时用本地最新地图再查一次，目标处已是已知区域（不是未知边界），或栅格显示不可通行，立即弃置重选。复检成本几乎为零，却能省下整段白跑的路。
  • 锁定与弃置：目标一旦选定就锁定，正常情况下 5 s 内不因小幅效用波动改选（防震荡）；连锁条件：不可达、超过 90 s 未到达、或候选效用超过当前 1.5 倍才允许换目标。锁定让轨迹连贯，弃置条件保证它不会变成"执念"。

5. 探索完成判定：三条件合议

断连场景下"无 frontier"的可信度进一步下降。稳健的完成判定要三条件同时成立：(a) 全队地图合并后无 frontier 或最大效用低于阈值；(b) 最近一次会合中所有在线机器人一致报告"无待探索目标"，且过去 60 s 地图无新增格；(c) 离线机器人列表为空（有失联成员时，其可能带着未同步的边界）。条件 (c) 尤其重要：分区里的一台机器人可能正站在一个未同步的洞口前，不等它回来就宣布完成，等于主动留下盲区。

6. 数值算例：log-odds 证据与队列预算

证据数值：pocc = 0.7 对应 l = ln(0.7/0.3) = +0.847，pfree = 0.4 对应 l = ln(0.4/0.6) = −0.405。两个数字并不对称：占用证据的绝对值约为空闲证据的两倍，编码了"看到墙比看到空地更可信"的工程直觉。限幅 ±3 对应概率约 0.9526，即地图对任何单格的自信心上限约 95%，永远保留被新证据修正的空间。

事件序列l 的累计判读
一次占用观测+0.847占用
再加三次空闲观测+0.847 − 3×0.405 = −0.368翻转为空闲
三次占用后一次空闲3×0.847 − 0.405 = 2.136仍为占用

读表结论：一堵被观测到一次的"墙"需要三次独立空闲观测才能翻案，反过来"空地"更不容易被误判成墙。拆隔断的场景里，机器人连续三次看到通道就会更新地图，响应速度与现场节奏匹配；对怀疑为墙的格子，系统宁可多等几次观测，避免把通道误判掉造成规划器穿墙。

队列预算：地图块 1 Hz、每块约 5 kB，TTL 300 s，断连 5 分钟最多积压 300 条、约 1.5 MB，机载内存毫无压力。复连后按"20 条/200 ms"即 100 条/秒发送，纯地图数据 3 秒清空；若链路质量只允许 10 条/秒，清空需要 30 秒，期间地图块仍在 TTL 内，不会出现"刚发出就过期"的尴尬。反过来，若把 TTL 拉长到 1800 s，积压上限涨到 9 MB，还引入"旧地图把队友打回过去"的风险，不划算。

会合周期 Tc效率损失 tr/Tc地图分歧窗口适用场景

表里每一档都对应一个"最长多久看不到队友地图"的承诺。选择方法：先按区域大小写出可接受的分歧窗口（例如"任何方向 5 分钟内可能被队友改变的区域不超过 200 m²"），再反推 Tc，最后用实测的效率损失微调；直接抄 120 s 是起点，不是结论。

边界与失效：log-odds 融合假设各次观测独立，实际相邻帧之间的观测强相关（同一角度、同一光照），把 30 Hz 的连续 10 帧当 10 次独立证据会把置信度刷爆。工程修正按"时间窗去重"处理：同一格在 2 s 内的重复观测折算为一次证据，或把证据权重按帧间隔缩小；另外，动态障碍（移动的桌椅、行人）会给占用方向持续加证据，需要在 l 上叠加遗忘项（每 60 s 向零衰减 0.05），让地图保留适应变化的能力。把证据去重与遗忘项写进地图更新的同一入口，所有来源就会一视同仁。这套修正的验收线是：同一场景重放两遍，占用格数的差异应小于 2%；差异更大说明事件相关性处理不到位，需要继续调整去重窗口。这条回归检查建议列入地图模块每次升级的清单，代价是一次录包回放。

实现思路与设计

  1. 通信状态机：每台机器人维护链路质量估计（最近 5 s 内成功收发率），LINK_GOOD / LINK_POOR / DISCONNECTED 三态；状态切换影响发送策略（直接发 / 降频 / 入队）。
  2. 机会队列：内存队列（可选落盘防重启丢失）；出队规则 = 优先级 + TTL + 单批预算；队列深度做成指标，持续增长说明链路长期不可用。
  3. 地图融合：本地地图以 log-odds 存储（float16，0.05 m 分辨率，100 m × 100 m 约 8 MB 内存，可接受）；收到增量块后做证据相加 + 限幅；冲突格写入"复检候选"列表。
  4. 复检与锁定：目标 3 m 复检；TargetLock 管理锁定/弃置；复检失败或弃置触发重选（复用 050 章效用）。
  5. 会合调度：预设 3 个会合点（起点、区域中心、远端入口）；周期 120 s，实际触发条件 = "距上次会合 120 s 或链路中断超过 60 s"；会合期间交换队列，预算内先地图后目标。
  6. 验收：3 台机器人、300 m² 两层区域、人为制造 3 个通信盲区：完成度（visited 面积/可探索面积）大于 95%；地图跨机 IoU 大于 0.8；会合开销占比小于 25%；无机器人因断连"卡死"（距离上次位置变化小于 0.2 m 超过 2 min 视为卡死，应为零次）。

关键代码与解读

片段 1：机会通信队列

import heapq

class OpportunisticQueue:
    """断连缓存、复连批量发送：优先级 + TTL + 单批预算。"""
    def __init__(self):
        self.q = []                    # (优先级, 入队序号, born, life, msg)
        self.seq = 0

    def enqueue(self, msg, prio, life, now):
        # 优先级数字小者先发：0=地图 1=目标任务 2=遥测
        self.seq += 1
        heapq.heappush(self.q, (prio, self.seq, now, life, msg))

    def flush(self, link, now, budget=20):
        """复连后按预算发送；过期消息直接丢弃，不再占用窗口。"""
        sent = 0
        while self.q and sent < budget:
            prio, seq, born, life, msg = heapq.heappop(self.q)
            if now - born > life:
                continue               # 过期：旧地图块比没有更危险
            link.send(msg)
            sent += 1
        return sent, len(self.q)           # 返回剩余深度供健康监测

解读：队列本身是十行代码，价值全在三条纪律的取舍上。用堆按优先级出队，保证窄窗口里的带宽先给地图增量，遥测排在最后；TTL 判断放在出队时执行，因为"消息还值不值得发"只在发送时刻才能判定；flush 返回队列深度，让监控系统能看见"积压趋势"，深度持续大于 500 意味着这台机器人已经在盲区待太久，运维可以静待它按调度自动返回会合点。link.send 抽象成接口，实际接 DDS 话题或自定义传输层，队列逻辑与中间件解耦。

片段 2：log-odds 地图融合

import numpy as np

def merge_log_odds(logodds, block, p_occ=0.7, p_free=0.4):
    """证据相加式融合：与到达顺序无关；限幅防止过度自信。"""
    d = block["data"]                       # -1=未知 0=空闲 100=占用
    l_occ = np.log(p_occ / (1 - p_occ))     # 约 +0.85：占用证据
    l_free = np.log(p_free / (1 - p_free))  # 约 -0.41：空闲证据
    delta = np.zeros_like(d, dtype=float)
    delta[d == 100] = l_occ
    delta[d == 0] = l_free                  # 未知格不贡献证据
    win = logodds[block["y0"]:block["y0"] + d.shape[0],
                  block["x0"]:block["x0"] + d.shape[1]]
    win += delta
    np.clip(win, -3.0, 3.0, out=win)        # 限幅：保留被新证据修正的能力
    conflicts = int(np.count_nonzero(np.abs(win) < 0.2))
    return conflicts                        # 接近 0 的格 = 需要复检的争议区

解读：与 050 章的覆盖式合并相比，这段代码最重要的性质是顺序无关：两台机器人的证据先来后到、分几批到达，融合结果都一样，在断连场景里这直接消灭了"谁的网络快谁说了算"的随机性。p_occ = 0.7 / p_free = 0.4 对应单次观测的置信度，来自里程计与传感器模型的标定；数值不必精确，证据的相对强度（占用 +0.85 vs 空闲 −0.41）才是关键，它编码了"看到墙比看到空地更可信"的工程直觉（自由空间可能被后续角度遮挡修正，墙很少凭空出现）。最后返回冲突格数：接近 0 的格说明两台机器人对同一区域意见相反，输出给复检调度，让机器人顺路去"亲眼看看"。

片段 3：目标锁定、复检与弃置

class TargetLock:
    """目标锁定与弃置：防震荡，也防"抱着过期目标不放"。"""
    def __init__(self, abandon_after=90.0, swap_gain=1.5):
        self.abandon_after, self.swap_gain = abandon_after, swap_gain
        self.target, self.since = None, 0.0

    def update(self, candidate, cand_u, cur_u, dt, reachable=True):
        self.since += dt
        if self.target is None:
            if candidate is not None:
                self.target, self.since = candidate, 0.0      # 首次锁定
        else:
            if not reachable or self.since > self.abandon_after:
                self.target, self.since = candidate, 0.0      # 不可达/超时
            elif candidate is not None and cand_u > cur_u * self.swap_gain:
                self.target, self.since = candidate, 0.0      # 显著更优才换
        return self.target

    def revalidate(self, goal, logodds, unknown_thresh=-0.1):
        """到达前复检：目标不再是未知边界，说明队友已探明。"""
        gx, gy = int(goal[0] / 0.05), int(goal[1] / 0.05)
        if logodds[gy, gx] > unknown_thresh:     # 已判为已知：弃置
            self.target, self.since = None, 0.0
            return False
        return True                                # 仍是未知边界：继续

解读：update 把"锁定"与"弃置"两个矛盾需求放在一起：平时不轻易换（swap_gain = 1.5 意味着候选效用不超过当前 150% 就不动），但三条硬弃置条件（不可达、超时 90 s、显著更优）保证目标不会变成执念。注意"不可达"来自执行层的反馈（046–049 规划失败上报），这是跨模块接口：探索决策要消费规划的结果，不能假设规划一定成功。revalidate 在到达前查一次 log-odds 地图：大于阈值说明该格已有明确证据（不再未知），目标作废，一个成本趋近于零的检查，避免了断连场景里最典型的浪费："跑了 40 秒到达目标，发现队友两分钟前已经探过"。

常见坑

  • 带着过期 frontier 跑空：断连期间队友已探明目标区，自己还在全速前进。修复：到达前 3 m 复检 + 目标 TTL；复检失败率做成指标，偏高说明队伍重叠严重。
  • 合并规则把墙抹掉：断连后重连，一方用旧覆盖式规则合并，冲突格被空闲证据抹除，规划器开始穿墙。修复：改造为 log-odds 证据相加；已上线的系统至少要做"冲突保占用 + 冲突计数告警"。
  • 复连洪峰打垮链路：两台机器人相遇瞬间互发数千条积压消息，窄链路拥塞、又断。修复：单批预算 + 优先级排序 + 指数退避重试；把"复连后 5 s 的丢包率"作为专项测试用例。
  • 会合过于频繁：为了保守把会合周期设成 30 s，机器人 30% 的时间在往返会合点。修复：按公式 tr/Tc 估效率损失，从 120 s 起步；用"地图分歧度（跨机会合后差异格数）"判断是否需要更频繁。
  • TTL 用墙上时钟导致误判：两台机器人的时钟差 30 s，一条 300 s TTL 的地图块在慢钟那边永远"新鲜"、在快钟那边瞬间过期。修复：TTL 用发送方单调时钟 + 接收方本地差值估计，或先做时间同步（第 009 章）再依赖墙钟。

练习与思考

  1. 计算会合预算：会合点平均往返总里程 12 m（速度 0.5 m/s），交换耗时 10 s。会合周期 120 s 与 300 s 时的探索效率损失各是多少？两个数值的差值对应什么代价？★
    提示
    tr = 12/0.5 + 10 = 34 s；损失 = 34/120 ≈ 28%，34/300 ≈ 11%。差值换来的代价是"地图分歧窗口"从 2 分钟拉长到 5 分钟，区域越大、失联越频繁，越不能贪这点效率。
  2. 把 log-odds 限幅从 ±3.0 改为 ±1.0 与 ±6.0，预测：新出现的通道（拆除的隔断）被多快接受？地图稳定性（噪声翻面概率）如何变化？给出量化实验设计。★★
    提示
    ±1.0：两三次逆向证据即可翻案，噪声敏感；±6.0：稳定但顽固。实验：人为移动一堵墙，统计"地图状态翻转所需观测次数"。
  3. 设计一个"断连 5 分钟"的完整测试用例：机器人 A 进入盲区，B 在外继续探索。列出 A 的队列内容演化（条数、优先级分布、TTL 清理）、B 的等待行为、复连后 30 s 内的消息交换序列与地图收敛检查。★★★
    提示
    按 1 Hz 地图增量、5 s 目标刷新估算队列增长；复连后先地图后目标的顺序可在消息日志中验证；收敛检查用合并后 IoU 曲线。
  4. 把目标弃置的 abandon_after 从 90 s 改为 30 s 与 240 s，分析对探索覆盖完整性的影响；构造一个"30 s 弃置造成盲区"的场景并给出修复。★★
    提示
    30 s 太短：远处的合法目标被弃置，那个方向成盲区；240 s 太长：坏目标拖累队伍。修复可用"弃置前记录该目标，完成后再回访"的补探队列。
  5. 综合本课内容，为你的探索系统写"分区自主 + 周期会合"运行手册：通信状态判定阈值、会合点与周期、断连时的独立决策边界、恢复流程与验收指标。★★★
    提示
    独立决策边界指"断连期间允许自主做什么"：继续探索当前分区、按队列攒数据、到点回会合点；不允许改全队性决策（如宣布完成）。

小结

  • 未知环境有双重未知：空间与通信；协同架构必须做到"断连可活、复连可续"。
  • 机会通信队列三纪律：优先级（地图 > 目标 > 遥测）、TTL、单批预算；会合调度按 tr/Tc 估算效率损失。
  • log-odds 地图让融合顺序无关；限幅保留地图被新证据修正的能力；冲突格输出给复检。
  • 目标锁定防震荡、三条弃置条件防执念、到达前 3 m 复检防白跑，三个机制一个都不能少。
  • 探索完成判定三条件合议，含"离线成员为零"。下一章换任务：多机器人协同搜索，目标是在概率地图上尽快找到可疑目标，建图退居为手段。
