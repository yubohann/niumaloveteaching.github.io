第四篇 · 系统集成与工程化

第 082 章：多机器人协同学习入门

当规则写不完时，让机器人自己"学"出协同：搞懂集中训练-分散执行（CTDE）范式、参数共享，以及学习系统绕不开的通信预算。

  • 主题：协同学习入门（多智能体强化学习基础）
  • 关键机制：CTDE、参数共享、量化消息、通信预算
  • 预计学时：55 分钟
  • 前置章节：第 081 章

学习目标

  • 理解多机器人学习问题的本质：全局状态不可见、奖励共享、以及"每个机器人都在学"带来的非平稳性。
  • 掌握集中训练-分散执行（Centralized Training with Decentralized Execution, CTDE）的适用条件与账本：训练期的全局信息如何"买断"执行期的通信需求。
  • 会用"消息字节 × 邻居数 × 台数 × 决策频率"估算学习策略的通信预算，并知道量化、事件驱动等手段能把预算压到什么量级。
  • 能搭出最小训练回路与 ROS2 部署节点的分工结构：仿真里训练、话题上部署、参数共享复用样本。
  • 形成判断标准：什么样的任务值得上学习，什么样的任务应当继续用手写规则或安全过滤器兜底。

背景与动机

前 81 章你建立的全是"规则系统"：编队按几何关系、分派按代价矩阵、避障按势场或采样式规划。规则系统可解释、可验证，但有一类问题它写不动，机器人之间的交互太密集、太多样，人工规则会爆炸成上千个 if-else，而且彼此打架。比如 20 台机器人在窄走廊里同时相向通行、围捕一个会逃跑的目标、在拥堵的任务点之间动态分工：这类场景里"该怎么动"取决于别人怎么动，而别人怎么动又取决于你怎么动。

多智能体学习（Multi-Agent Learning）正是为这类交互密集场景准备的：不依赖人工规则，改为定义每个机器人看到什么（观测）、能做什么（动作）、做完得到什么反馈（奖励），用大量仿真试错让策略自己长出来。放在系统架构里，它是协同层的第二种实现方式：规则系统之上叠一层学习策略，或整层替换。

但要清醒：学习不是白吃的午餐。它带来三类新成本，样本成本（要跑成千上万次仿真）、通信成本（策略之间可能要交换"意图消息"）、可靠性成本（学出来的行为是概率性的）。本章把这些成本逐项量化，让你能判断"值不值得学"。

核心原理

1. 从单机强化学习到多机器人：Dec-POMDP

单机强化学习假设环境是一个马尔可夫决策过程（Markov Decision Process, MDP）：智能体看到状态 s，选动作 a，环境按转移概率 P 给出下一个状态和奖励。多机器人场景把这个模型"打碎"了：没有任何一台机器人能看到全局状态，激光只能看 12 米、相机有视场角、队友的状态要么看不到要么有延迟。工程上通用的建模是分布式部分可观测马尔可夫决策过程（Decentralized Partially Observable MDP, Dec-POMDP）：

全局状态 s → 局部观测 oi = Oi(s)；联合动作 a = (a1, …, aN)；共享奖励 R(s, a) 每个机器人只能依赖自己的观测历史做决策；奖励通常共享，导致"功劳归属"（credit assignment）难题

比"看不到全局"更麻烦的是非平稳性：站在机器人 1 的角度，"环境"里包含了机器人 2 到 N，而它们也在更新自己的策略，于是环境的转移规律一直在漂移。独立学习（每台机器人各自跑自己的单机算法）在简单场景能凑效，交互一密集就震荡：我适应了你，你又在适应我，来回摆。

2. CTDE：训练用上帝视角，执行只用局部信息

CTDE 是当前工程上最主流的解法，它的核心交易非常清晰：训练阶段拿全局信息，执行阶段不拿。训练在仿真里进行，全局状态本来就唾手可得（仿真器直读），此时训练一个"评委"网络，集中评论家（centralized critic），它看全局状态 s 和所有人的动作，评估"刚才这套联合动作值多少分"。但每个机器人的"选手"网络（actor）自始至终只吃自己的局部观测。

为什么这样能成立？因为评论家只在更新梯度时被使用，部署时整个网络被丢弃。类比：教练在场边看着全场指挥训练（评价与纠错），上场后每个球员只看自己视野内的信息做动作（执行）。执行期不需要任何"上帝视角通信"，这是 CTDE 相对"集中执行"的最大工程优势：它不让通信预算变贵。

设计决策：为什么执行期坚持"分散"？

集中执行（所有决策发给一台中心机）会引入单点故障与集中延迟：中心机挂掉全队瘫痪，且每步决策要等所有机器人上报。分散执行把决策下放到每台机器人本地，中心机或教练只在训练期存在。工程上如果非要集中执行，必须显式地把集中控制器做冗余，那又回到了分布式共识的老问题（第 091 章会从控制视角再讲一遍这个权衡）。

3. 参数共享：同构机器人只养一套策略

如果 20 台同构机器人各学一套策略，样本效率极差：每台机器人的经验只喂自己。参数共享（parameter sharing）让所有机器人共用同一套权重，同一个策略在 20 台机器人上执行，20 台机器人产生的经验也全部回喂同一个策略，样本效率近似提升 N 倍。两个纪律：观测里不要编码 robot_id（否则策略会把行为绑定到编号，破坏泛化）；异构机器人按角色分组共享（比如抓取臂和底盘各一组）。

4. 通信预算：学习系统最容易超支的账

协同学习里消息传的是压缩后的"意图"（位置、朝向、速度、目标点方向，或一个低维嵌入向量），原始数据留在本地。量级感受一下：25 个 float32 数 = 100 字节；若传 64 维嵌入（float32）就是 256 字节。负载估算公式与第 013 章同源，但参数换成了学习的输入：

学习通信负载 = 消息字节 × 每机邻居数 × 机器人台数 × 决策频率 20 台、环状邻居（每机 2 对）、100 字节、10 Hz → 40 KB/s；全连接（每机 19 对）→ 380 KB/s

结论直接：环状/邻居式拓扑比全连接省 9.5 倍，且随台数线性增长（全连接的平方增长在大规模下不可承受），大规模车队的通信策略必须建立在稀疏交互图（第 087 章）上。若消息从 100 字节膨胀到 2 KB（比如不小心把原始扫描塞进去），环状拓扑也要 800 KB/s，控制指令的时延立刻恶化。三条压缩纪律：固定长度（序列化与 MTU 可预测）、低维（量化训练效果衰减往往远小于带宽收益）、事件驱动（只在信息变化超过阈值时发，第 090 章展开"学出来的通信门控"）。

5. 判断标准：什么时候不该用学习

该用：交互密集且规则难以穷举、有高保真仿真器、容忍概率性行为、指标以全局效率为主（硬安全另有兜底）。不该用：硬安全约束（碰撞避免应继续用规划与安全过滤器兜底，学习只做"高层意图"）、真机样本昂贵、需要可解释与认证、问题结构清晰且规则已够用。成熟系统是混合体：学出来的策略输出意图/优先级，确定性下层负责把它变成安全动作。

实现思路与设计

把多机器人学习落地成 ROS2 可部署的东西，要算清"训练回路"和"部署回路"两个独立系统之间的接口。

训练回路与部署回路的分工

环节训练回路（离线）部署回路（机上）
环境并行仿真（数十个副本加速采样）真实机器人 / 高保真仿真
观测来源仿真器直读，含特权信息话题订阅：自身状态 + 邻居消息
决策actor 网络（可批量前向）actor 网络（单次推理，目标 < 5 ms）
评价集中 critic（全局状态）不存在，已丢弃
产物策略权重文件 + 训练配置加载权重的 ROS2 推理节点

接口设计三原则：（1）观测用固定长度向量，12 维自身状态 + 8 维消息 + 4 维任务目标，避免策略对可变输入过敏；（2）动作定义为"-1 到 1 的归一化量"，节点内再乘最大速度，让同一策略适配不同底盘；（3）决策频率与部署频率一致，训练时 10 Hz 决策、部署时也用 10 Hz；若部署频率更高，用上层 10 Hz 出意图、下层 100 Hz 控制器插值跟随。

  • 通信消息内容：位置（厘米级 int16）、朝向（int8 覆盖 360°，约 1.4° 分辨率）、速度档位、目标点方向。共约 10–16 字节，留余量按 32 字节消息 + 头部估算。
  • 邻居选择：策略输入限定为最近 K 台（K=2–3），输入维度固定，通信负载线性；"发给所有能收到的人"会让维度与负载随规模膨胀。
  • 训练评估：不只看平均回报，看最差 5% episode（尾部风险）；同策略在固定种子的 20 个场景上复测，防止"背种子"。

关键代码与解读

片段 1：通信预算计算器，写策略之前先算账

def learning_comm_budget(n_robots=20, neighbors=2, msg_bytes=100, rate_hz=10):
    """估算学习策略通信负载：字节/秒。邻居数决定增长率是线性还是平方。"""
    ring = msg_bytes * neighbors * n_robots * rate_hz          # 环状：每机固定 2 邻居
    full = msg_bytes * (n_robots - 1) * n_robots * rate_hz     # 全连接：每机 19 邻居
    # 对比三种优化手段的效果：量化 / 事件驱动 / 稀疏拓扑
    quantized = ring / 4            # int8 量化：float32 的 1/4
    event_driven = quantized * 0.3  # 事件驱动：实测约只有 30% 步需要发消息
    print(f"环状 {ring/1e3:6.1f} KB/s | 全连接 {full/1e3:7.1f} KB/s")
    print(f"量化 {quantized/1e3:6.1f} KB/s | 再加事件驱动 {event_driven/1e3:5.1f} KB/s")
    return ring, full

learning_comm_budget()   # 环状 40 KB/s，全连接 380 KB/s，两级优化后约 3 KB/s

解读：这段脚本的作用是在设计策略之前把"要不要实时发消息"变成算术题。环状与全连接差 9.5 倍，说明拓扑选择是第一优先级；量化与事件驱动再各砍一刀，20 台车队的消息负载可以压到个位数 KB/s，对比第 023 章图像压缩的 MB/s 量级，学习系统如果只传低维意图，通信根本不是瓶颈。真正的坑是有人把视觉特征整块共享出去，那时负载会瞬间回到图像级。

片段 2：参数共享策略，邻居消息的平均聚合

import numpy as np

class SharedPolicy:
    """同构机器人共享一套权重：各自产生的经验都回喂同一个网络。"""
    def __init__(self, obs_dim=12, msg_dim=8, act_dim=2, hidden=64, seed=0):
        rng = np.random.default_rng(seed)
        # 输入 = 自身观测 + 邻居消息；结构固定，邻居多寡不改变网络形状
        self.w1 = rng.normal(0, 0.1, (obs_dim + msg_dim, hidden))
        self.w2 = rng.normal(0, 0.1, (hidden, act_dim))

    def act(self, obs, neighbor_msgs):
        # 对邻居消息取平均：天然支持 0 到 K 个邻居，且对邻居顺序不敏感
        msg = np.mean(neighbor_msgs, axis=0) if len(neighbor_msgs) else np.zeros(8)
        h = np.tanh(np.concatenate([obs, msg]) @ self.w1)
        return np.tanh(h @ self.w2)   # 输出归一化到 [-1, 1]，由底层再乘速度上限

policy = SharedPolicy()
# 同一 policy 对象被 20 台机器人共用：这就是参数共享的字面含义
cmd = policy.act(np.zeros(12), [np.random.randn(8), np.random.randn(8)])

解读：三个设计点都值得展开。（1）平均聚合让网络与邻居数量解耦，输入维度恒定，训练时 K=2、部署时 K=3 也不会崩；更讲究的做法是按距离加权或注意力聚合，但那是第 090 章的进阶话题。（2）tanh 输出把动作限幅到 [-1,1]，上层再乘底盘最大速度，使策略与具体硬件解耦（换底盘只改一个系数）。（3）观测里没有 robot_id，保持"任何机器人代入都成立"的对称性，这是参数共享泛化的前提。

片段 3：集中评论家的训练骨架，全局信息只用来算梯度

import numpy as np

def discount_returns(rewards, gamma=0.97):
    """把逐步奖励折算成回报：R_t = r_t + γ·R_{t+1}，越早的决策分摊的功劳越小。"""
    out = np.zeros(len(rewards), dtype=float)
    acc = 0.0
    for t in reversed(range(len(rewards))):   # 从尾到头累加，单趟完成
        acc = rewards[t] + gamma * acc
        out[t] = acc
    return out

# 训练循环骨架：critic 看全局，actor 只看局部（微分实现交给深度学习框架）
for episode in range(2000):
    joint_obs = sim.reset()                        # 仿真特权：可直接读全局状态
    traj = []
    for step in range(500):
        acts = [policy.act(o, sim.neighbor_msgs(i))     # actor 的合法输入
                for i, o in enumerate(joint_obs)]
        reward, done, joint_obs, _ = sim.step(acts)
        traj.append((joint_obs, acts, reward))          # 记录联合转移
        if done:
            break
    returns = discount_returns([t[2] for t in traj])    # 共享奖励 → 共享回报
    critic_fit(traj, returns)      # 用全局信息拟合评分函数；部署时整段丢弃

解读：这段骨架把 CTDE 的账本写成了代码。sim.neighbor_msgs(i) 是执行期接口的真实形状（部署时对应话题订阅），而 joint_obs 与 critic_fit 只存在于训练循环。注意 critic_fit 接收的是整条轨迹的回报：共享奖励意味着无法区分"谁的功劳"，评论家的价值估计就是为每个人提供相对稳定的评价坐标，这个"功劳归属"问题在第 090 章会有专题拆解。done 提前截断则保证真有终止条件，避免无限循环里回报发散。

常见坑

  • 仿真里学、真机上崩（sim-to-real 落差）：训练用理想里程计与零延迟通信，真机有 20–50 ms 延迟和 5% 打滑。修复：在仿真里注入噪声与延迟（域随机化），并在部署节点里对观测加低通滤波、动作加限速。
  • 奖励设计贪心导致"躺平"或"互蹭"：奖励里碰撞惩罚权重过大，策略学会原地不动（负分最少）；权重过小，机器人贴着队友擦过去。修复：惩罚用"距碰撞的时间预算"取代瞬时距离，并把任务进度项与安全项的量级调到 10:1 左右再微调。
  • 忽略非平稳性直接独立训练：每台机器人各训各的，收敛曲线来回震荡。修复：至少加参数共享 + 集中评论家；再不行引入"对手策略快照"（用队友的旧版本策略训练，降低相互追逐）。
  • 通信消息维度悄悄膨胀：从实验代码复制了 64 维嵌入，没算预算就上系统，20 台全连接时约 1 MB/s 起步。修复：把本章的预算函数放进代码评审清单，消息定义后用 ros2 topic bw 实测对账。
  • 只看平均回报不看尾部：平均分很高，但 5% 的回合里机器人撞墙。修复：评估报表必须包含最差 5% 分位、碰撞次数、任务超时率三个尾部指标。

    平均聚合会随邻居增多把消息幅值"稀释"，方差随 K 减小，这既是鲁棒性也是缺点（单个关键邻居的信息被淹没）。由此引出第 090 章的注意力/加权威重聚合。
  5. 写一页决策备忘：给你的研究项目判定"该不该用学习"，填表格：任务结构（清晰/模糊）、仿真成熟度、样本成本、安全等级、可解释要求，每项打分后给出结论与兜底方案。★★★
    提示
    参考本章判断标准：三项以上不利（安全等级高、样本贵、要认证）就不该整体上学习，可退化为"学习只做任务优先级排序、其余规则化"。备忘要写清楚如果学习部分失效，系统降级到哪个故障模式。

小结

  • 多机器人学习的建模底座是 Dec-POMDP：局部观测、共享奖励、非平稳环境；独立学习在交互密集场景不可靠。
  • CTDE 是一笔清晰的交易：训练期用全局信息训练集中评论家，执行期丢弃它，策略只依赖局部观测与稀疏消息，不把通信预算做贵。
  • 参数共享让同构机器人共用一套权重，样本效率近似 ×N；观测里不要编码 robot_id。
  • 学习通信预算 = 字节 × 邻居数 × 台数 × 频率；稀疏拓扑 + 量化 + 事件驱动可以把 20 台车队压到个位数 KB/s。
  • 判断标准：交互密集、有仿真、容忍概率行为才用学习；硬安全约束交给确定性兜底。
