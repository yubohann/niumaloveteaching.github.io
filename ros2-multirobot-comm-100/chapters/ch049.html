第三篇 · 协同控制与任务协同

第 049 章：路径跟随与冲突消解

把规划好的路径走出精度与节奏：纯跟踪算法的几何原理与前视距离取舍，再处理执行层特有的问题，计划无冲突、跑起来却擦肩，用预测轨迹交换与让行状态机把最后一厘米管住。

  • 主题：协同控制 / 执行层
  • 关键机制：纯跟踪（pure pursuit）、速度自适应前视、意图轨迹交换、让行状态机
  • 预计学时：60 分钟
  • 前置章节：第 048 章

学习目标

  • 掌握纯跟踪算法的几何推导：前视点、偏角 α、曲率 κ = 2sin α / Ld，以及到差速车角速度的转换。
  • 理解前视距离 Ld 的取舍与"随速度自适应"的理由，能用实验确定系数。
  • 能解释"规划层无冲突 ≠ 执行层无冲突"，并用预测轨迹交换实现在线冲突检测。
  • 会设计 FOLLOW / YIELD / RESUME 让行状态机，包括让行点选择、恢复缓冲与超时升级。
  • 能识别并打破循环等待死锁，为执行层定义 fail-safe（不确定即停）原则。

背景与动机

046–048 章规划出了时空无冲突的路径，但计划永远赶不上执行：轮子打滑、定位跳变、控制器滞后让实际轨迹与计划差出 10–30 cm；两台机器人"计划上"前后错开 0.16 s 通过路口，实机因为减速度不足同时压进路口。更隐蔽的是，多个控制回路的时延叠加会吃掉规划预留的安全裕度。规划层把冲突概率降到很低，执行层必须把剩下的概率管住。

本章做两件事：先把"路径 → 轮速"这一环做准（跟踪精度是所有协同的前提）；再加一层 10 Hz 的在线冲突检测与消解，用交换预测轨迹代替猜测邻居意图。它是第三篇"控制与规划"的收尾章，后面 050 章起进入任务级协同，底盘层的所有保证都建立在本章之上。

核心原理

1. 纯跟踪的几何：把"切圆弧"变成公式

路径跟随的目标是让机器人沿参考路径移动。纯跟踪（pure pursuit）的洞察是：不需要跟踪整条路径，只盯住"前方 Ld 处的一个点"，让车沿一段圆弧切过去。设前视点相对车头方向的偏角为 α，由圆几何可得所需曲率：

κ = 2·sin α / Ld，  ω = v·κ κ 越大弯越急；v 一定时角速度与曲率成正比；差速车直接用 ω 驱动转向

推导直觉：前视点落在半径 R 的圆弧上时，弦长 Ld 与圆心角 2α 的几何关系给出 sin α = Ld/(2R)，即 1/R = 2sin α / Ld。Ld 是这套算法唯一的"性格参数"：Ld 大 → 路线平滑但抄近道（切弯、内切障碍）；Ld 小 → 贴线精确但在噪声下左右摆动。实践标准是让它随速度变化：Ld = L0 + k·v（L0 ≈ 0.3–0.5 m，k ≈ 0.5–1.0 s），静止时也能稳定收敛，高速时保持平滑。

2. 横向误差从哪来：三层误差叠加

跟随误差来自三层叠加，任何一层都不可忽略：控制器误差（纯跟踪是小增益反馈，弯道内侧有稳态偏差，可用前馈曲率补偿）；定位误差（里程计漂移 1–3% 里程，AMCL 开关后局部跳变）；执行误差（轮子打滑、减速比标定偏差）。三层各占 5–15 cm，叠加后典型 15–30 cm，这就是执行层安全裕度不能碰规划层预留的原因。工程上把"横向误差"做成监控指标：正常小于 0.1 m，持续超过 0.2 m 就停下重定位，不能"顶着误差跑"。

3. 在线冲突检测：用交换预测替代猜测

执行层的冲突判定以预测轨迹为对象：每台机器人按自己当前 (v, ω) 外推未来 2 s 的轨迹（10 个采样点、间隔 0.2 s），以 5–10 Hz 广播，同时接收邻居的预测。对每一对轨迹逐采样点计算距离，得到"最小距离 + 首次低于安全阈值的时刻"。判据有两条：

风险条件：mink dk < dsafe = ri + rj + 0.3 m，且 TTC < 2 s "距离近"与"时间紧"同时成立才算冲突；只近不急（如并行队形）不触发避让

为什么执行层用预测轨迹，044 章的速度障碍差在哪？因为执行层的核心矛盾变了：速度障碍解决"这一拍选什么速度"，这里要解决"接下来的路线是否安全、谁先过"。预测轨迹恰好是 048 章预约行在执行层的轻量版本（仅 2 s、更频繁、更小），也是与意图层对接的数据形态。

4. 冲突消解的优先级阶梯

检测到风险后按代价从低到高选择动作：(1) 速度微调，先到者快一点、后到者慢一点，机器人匀速流不中断（代价：几秒的时间差）；(2) 时间窗让行，一方在冲突点前 1 m 的"让行点"减速停等，等对方离开冲突区（代价：数秒停滞）；(3) 空间绕行，重新规划一条侧偏路径（代价：更长里程与 048 章的重规划）；(4) 强制优先级，低优先级无条件让。规则要把"对称"全部消灭：同优先级时按约定方向（一律靠右）与 id 打破平局；让行点位置、恢复条件都写进协议，不能留"看情况"。

5. 死锁与 fail-safe

执行层死锁的典型形态往往是循环等待（表面像"停住"，实际每台都在等别人）：A 让 B、B 让 C、C 又让 A，全队原地不动。检测手段是维护等待图（谁在等谁）并查环；打破手段按代价排序：等待最久者优先（优先级翻转）、随机微扰动、退回上一个安全点重新规划。最后一层保险是 fail-safe：任何模块异常（感知丢失、通信中断、定位跳变）时默认减速停车，把"系统不知道怎么办"统一处置为安全状态，执行层没有比"停下"更便宜的安全动作。

6. 数值算例：曲率、拐角切割与冲突判定

曲率账：前视偏角 α = 20°、Ld = 0.7 m 时，κ = 2sin20°/0.7 = 0.977 1/m，对应转弯半径 1.02 m；v = 0.5 m/s 下角速度 ω = v·κ = 0.489 rad/s。把 Ld 增到 1.2 m，同样偏角下 κ 降到 0.570、ω 降到 0.285 rad/s，转向"变懒"但更平滑。控制器输出对 Ld 的敏感度是线性的，这就是"前视距离是纯跟踪唯一性格参数"的定量含义：它同时缩放所有场景下的转向力度。

拐角切割账：把 L 形直角路径交给纯跟踪跑一遍（v = 0.5 m/s，起点在直段），轨迹离拐角点的最近距离就是"切角量"：Ld = 0.15 m 时约 0.06 m，Ld = 0.30 m 时约 0.12 m，Ld = 0.50 m 时约 0.20 m。三组数字的比例关系几乎恒定：切角量约为 0.4 × Ld。排布货架通道时把"半通道宽减去 0.4·Ld"当作可用净宽，就能提前算出机器人会不会蹭到货架，比现场试跑一圈便宜得多。

冲突判定账：A 从原点沿 +x 以 0.5 m/s 出发，B 从 (1.5, −0.5) 沿 +y 以 0.5 m/s 出发。各自按片段 2 外推 2 s 的十条预测轨迹逐点比较：距离在 t ≈ 1.47 s 处首次低于 0.8 m（第 8 个采样点的读数 0.762 m 已越线），窗口内最小距离 0.707 m 出现在窗口末端 t = 2.0 s。对 A 而言，判定流程是"t ≈ 1.5 s 发现风险，检查优先级，进入 YIELD 或速度微调"；阈值 dsafe = 0.8 m 比物理接触距离（半径和 0.5 m）提前 0.3 m 报警，这 0.3 m 恰好覆盖执行误差与定位误差的合计预算。

边界与失效：预测模型假设邻居保持当前 (v, ω)。若邻居以 0.5 m/s² 制动，2 s 内位置可差出 ½ × 0.5 × 2² = 1 m，远超 dsafe 的余量；邻居突然加速同理。所以预测窗口内前 1 s 可信、后 1 s 只看趋势：工程上把窗口内的点按时间加权（越远权重越低），或用 1.5 s 的短窗口配合 10 Hz 刷新来补偿。只把"预测轨迹"当精确真相、不做时变处理，是执行层冲突检测里最隐蔽的一类失效。

让行点回退 1 m 的依据再核算一遍：按匀减速 a = 0.25 m/s²，从 0.5 m/s 停稳需要 0.5²/(2 × 0.25) = 0.5 m，加决策与通信用掉的约 0.5 s（0.25 m），合计 0.75 m，回退点取 1.0 m 还留 25% 余量；若系统减速能力更弱（a = 0.1 m/s²），停稳距离升到 1.25 m，回退点必须同步加大到 1.6 m 以上，否则 YIELD 触发时已经停不进让行点。

7. 与速度障碍的对照：两层各管什么

维度速度障碍（044 章）预测轨迹（本章）
时间视野瞬时速度 + τ 截断固定 2 s、10 个采样点
输出安全速度集合（可直接执行）风险时刻与地点（供谈判）
对机动邻居保守（外推相对速度）中等（假设保持 v、ω）

两层不是二选一：044 章保证"任何一拍的速度都安全"，本章回答"接下来两秒的路线是否可持续、该谁让"。只留速度障碍时，机器人会频繁急停但始终不撞；只留预测层时，对突然摇控介入的第三方机器人反应太慢。两层的分工与数据接口是同一个邻居表：速度障碍取瞬时场，预测层取轨迹序列，融合顺序是"先让行决策调整偏好速度，再交给速度安全层过滤"，任何顺序颠倒都会破坏安全闭环。

速度微调与停等的取舍也能算清楚：按 v′ = d/(d/v + Δt)，走完共享段的耗时恰好增加 Δt，"降速错开 2 s"与"原地等 2 s"在时间账上打平，差别在形态：降速保持流动、不打断后车；停等干脆、易于观测，代价是两次加减速的过渡损失与追尾风险。经验边界是错开需求在 2 s 内用降速，超过 2 s 改用"停等 + 重新规划"，因为长时间龟速会拖烂整条链路的速度曲线，而停等期间正好重算后续路径。这条边界与第 048 章的 0.15 m/s 速度下限是同一条原则：宁可短暂停，不要长期爬。

等待图的检测与打破用数量级确认一遍：等待边是"本拍正在让谁"，以 10 Hz 周期维护；三机环、每台等待超过 10 s 触发优先级翻转，最坏情况下第一台翻转后 1 个周期内就出现可行解，全环解开在 1–2 个检测周期（0.1–0.2 s）内完成。把"等待图上环的数量"做成仪表盘指标，正常应为 0，一旦出现立即启动超时倒计时，这比事后复盘"为什么两队不动"直接得多。指标按 1 Hz 采样留存，长期观测还能发现"某个路口反复出现环"的结构性原因，据此调整通道设计或优先级表；出现环时同时记录涉事机器人编号与等待时长，复盘效率会高很多。

实现思路与设计

  1. 跟踪器：50 Hz 控制环读取规划路径（来自 046–048 任一路线），做纯跟踪 + 曲率前馈；速度上限 1.0 m/s，过弯按 κ 自动降至 0.5 m/s。
  2. 意图广播：10 Hz 发布 /fleet/traffic_intent（robot_id、pose、twist、predicted[10]、priority、stamp），约 200 字节，Best-effort；接收侧外推补偿时延（复用 044 章的邻居表逻辑）。
  3. 冲突管理：10 Hz 检测；风险存在时进入 YIELD 或速度调整；同一风险持续 3 s 未消解则升级到重规划请求。
  4. 让行点：取冲突点沿自己路径回退 1.0 m 的位置；若路径上没有回退空间（路口正中），取进入路口前的最后一个可停位置，绝不在路口里停。
  5. 状态机：FOLLOW → YIELD → RESUME；YIELD 超过 10 s 触发优先级翻转；恢复需"对方已离开冲突区 0.5 m 以上 + 2 s 无新风险"双条件。
  6. 验收：4 台机器人、单双向混合路口场景 100 次交会：碰撞 0；最小间距大于 0.3 m；每次交会平均延迟小于 4 s；死锁事件 0；跟踪横向误差 P95 小于 0.15 m。

关键代码与解读

片段 1：纯跟踪，从路径点到角速度

import math

def pure_pursuit(car, path, v_cmd, k_look=0.6, l_min=0.4):
    """差速车路径跟随：取前视点求曲率，输出 (v, omega)。"""
    L_d = max(l_min, k_look * v_cmd)          # 速度自适应前视：快了看远
    target = path[-1]                          # 兜底：路径终点
    for p in path:
        if (p[0] - car[0]) ** 2 + (p[1] - car[1]) ** 2 >= L_d ** 2:
            target = p                         # 第一个超出前视距离的点
            break
    dx, dy = target[0] - car[0], target[1] - car[1]
    alpha = math.atan2(dy, dx) - car[2]        # 前视点在车体系下的偏角
    alpha = math.atan2(math.sin(alpha), math.cos(alpha))   # 归一化到 (-pi, pi]
    curvature = 2.0 * math.sin(alpha) / L_d    # 纯跟踪核心公式
    return v_cmd, v_cmd * curvature            # 角速度 = 线速度 x 曲率

解读：函数只有十几行，但每行都有明确的工程含义。前视距离随速度线性变化：1 m/s 时 Ld = 1.0 m，既保证弯道有足够前瞻，也避免把远处噪声点当成航向依据。前视点取"第一个超出 Ld 的路径点"，避免"最近点"在采样密度不均匀时抖动。角度归一化不能省，路径折返时 α 会跨过 ±180°，不归一化会让车头猛转。最后返回 v_cmd * curvature，由几何定曲率、由上层定速度，职责分明，这正好对接 044/047 章的输出接口。

片段 2：预测轨迹与在线风险判定

import math

def predict_traj(pos, yaw, v, w, n=10, dt=0.2):
    """按等速模型外推未来 2 s 的轨迹：10 点、0.2 s 间隔。"""
    pts, x, y, th = [], pos[0], pos[1], yaw
    for _ in range(n):
        x += v * math.cos(th) * dt             # 车体系速度投影到世界系
        y += v * math.sin(th) * dt
        th += w * dt                           # 航向随角速度积分
        pts.append((x, y))
    return pts

def conflict_risk(my_traj, its_traj, d_safe=0.8):
    """逐采样点比较两条预测轨迹，返回首次风险 (距离, 序号)。"""
    for k, (mx, my) in enumerate(my_traj):
        ix, iy = its_traj[k]
        d = math.hypot(mx - ix, my - iy)
        if d < d_safe:
            return d, k                        # 只报最早的入侵事件
    return None

解读：等速外推模型很"粗"，但用在 2 s 窗口恰好合适，窗口内加速度对位置的影响是二阶梯量（0.5 m/s² 的加速度 2 s 只产生 1 m 的位置偏差，且预测量会被下一拍刷新），更复杂的模型在这里收益有限、鲁棒性反而下降。`conflict_risk` 只返回"最早的入侵"，因为消解动作是针对第一个冲突点设计的；一次报出全部冲突点反而会让决策逻辑变复杂。`d_safe = 0.8` 与设计表的"半径和 + 0.3 m"对应（0.25 + 0.25 + 0.3），意味着两台机器人中心距小于 0.8 m 即触发，比物理接触（0.5 m）提前 0.3 m，这正是给执行误差留的预算。

片段 3：让行状态机与超时升级

def step_yield(state, obs, dt):
    """执行层让行状态机：FOLLOW / YIELD / RESUME，含超时升级。"""
    if state == "FOLLOW":
        # 只在自己是低优先级或同级更远者时让行（规则在协议里约定）
        if obs["risk"] is not None and obs["must_yield"]:
            return "YIELD", 0.0
    elif state == "YIELD":
        if obs["peer_cleared"]:
            return "RESUME", 0.0               # 对方离开冲突区
        if obs["wait_time"] > 10.0:
            obs["bump_priority"]()             # 等待超时：优先级翻转
            return "FOLLOW", 0.0
    elif state == "RESUME":
        # 恢复缓冲：确认前方 0.5 m 内无新风险才真正回到 FOLLOW
        if obs["clear_ahead"] >= 0.5:
            return "FOLLOW", 0.0
        if obs["risk"] is not None:
            return "YIELD", 0.0                # 新风险立即回退到让行
    return state, obs["time_in_state"] + dt

解读：状态机的骨架刻意做小，把复杂性放进 obs 的计算里。YIELD 期间的速度规划是"到让行点前减速为零"：立即停车会让后车追尾，减速过程本身就是给后车的信号。10 s 超时后调用 bump_priority 强制翻转优先级，是打破循环等待的最后手段：优先级一旦翻转，原来的僵局在下一个检测周期即被打破。RESUME 的双重条件（净空 + 无新风险）解决了一个经典 bug：对方刚离开、己方刚起步，一台第三方机器人进入冲突区，旧代码会"盲目恢复"。最后注意 time_in_state 由调用方维护并在切换时清零（与 045 章同一模式），超时与遥测都依赖它。

常见坑

  • 前视距离固定且偏小：机器人贴着路径左右摆（"画龙"），在直线上也抖。症状是角速度指令高频正负翻转。修复：Ld = L0 + k·v；同时检查路径点采样密度是否低于前视距离。
  • 让行点算在路口中央：机器人停在路口中，把整条通道堵死，双方互相等待。修复：让行点取"冲突点回退 1 m"，并限定在路径的可停区内；初始化时就给每个路口标注可停位置。
  • 双方都触发让行（对称死锁）：两台机器人互相判定"我让"，双双停下。修复：让行条件必须是互斥的（优先级不同，或同级时引入确定性平局规则），并用等待图查环做兜底。
  • 速度微调没有下限：为错开时间窗把速度降到 0.05 m/s，机器人龟速爬行十分钟。修复：设置 0.15 m/s 的速度下限，低于下限改用停等（与 048 章同一阈值，保持全课程一致）。
  • 执行误差吃掉规划裕度：规划给的间隙 0.25 m，跟踪误差 0.3 m，实际擦肩。修复：规划的安全裕度必须大于"跟踪误差 P95 + 定位误差"之和；跟踪误差做成在线指标，超标即降速并重定位。

练习与思考

  1. 机器人以 v = 0.5 m/s 跟随路径，前视偏角 α = 20°，Ld = 0.7 m。计算曲率 κ 与角速度 ω；若 Ld 改为 1.2 m，角速度如何变化？解释这一差异对弯道跟踪精度的含义。★
    提示
    κ = 2sin20°/0.7 ≈ 0.98 1/m，ω ≈ 0.49 rad/s。Ld 增大后同样偏角下角速度变小，拐弯变"懒"，适合高速平滑，不适合贴线。
  2. 把你的 L0 从 0.4 改到 0.2 与 0.8，预测：直线跟踪误差、弯道切内程度、角速度波动幅度分别如何变化？给出实验记录表的设计。★★
    提示
    0.2：贴线好但抖动大；0.8：平稳但切弯明显（内侧超差）。记录表列：L0、直线误差 RMS、弯道最大内切、ω 标准差。
  3. 构造一个三机循环等待场景（A→B→C→A 互相让行），写出等待图的表示方法和检测环的算法，并仿真验证"等待最久者优先"能在几个周期内解开死锁。★★★
    提示
    等待图：顶点为机器人，边 A→B 表示 A 在等 B；环检测用 DFS 或 Tarjan。超时翻转后预计 1–2 个检测周期（10 Hz）内解开。
  4. 比较执行层冲突检测用"预测轨迹"与用"当前位置 + 速度障碍"（044 章）的差异：检测提前量、误报率、对非匀速邻居的鲁棒性各如何？用两机匀速与一机减速两种场景分析。★★
    提示
    预测轨迹对"减速邻居"更准（位置直接排队比较）；速度障碍对机动突变更灵敏但保守。别把两者对立，执行层用预测轨迹，瞬时安全用 044 章兜底。
  5. 为 fail-safe 设计完整的触发清单与动作矩阵：列出至少六种异常（定位跳变、意图消息断流、路径过期、状态机超时、低电压、感知丢失），分别给出立即动作、恢复条件与告警等级。★★★
    提示
    动作只有三档：减速保持、停车等待、靠边停。恢复条件要可观测（例如"意图恢复 3 帧且无风险"）；告警分级对应运维响应速度。

小结

  • 纯跟踪的唯一参数是前视距离：κ = 2sin α/Ld、ω = v·κ；Ld 随速度自适应是标配。
  • 跟随误差 = 控制器 + 定位 + 执行三层叠加（典型 15–30 cm），必须在规划裕度里预扣。
  • 执行层用预测轨迹（2 s、10 点、10 Hz 广播）做在线冲突检测：又近又急才算风险，只近不急不触发。
  • 消解阶梯：速度微调 → 时间窗让行 → 空间绕行 → 强制优先级；让行点永远选在路口外，恢复要双条件。
  • 循环等待用等待图检测、超时翻转打破；fail-safe 原则是"不确定即停"。下一章从控制转入任务：多机器人协同探索，领航机器人群去测绘未知区域。
