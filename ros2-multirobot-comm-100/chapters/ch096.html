第 096 章：多机器人协同调度机制与优化建模

把"谁在什么时候做什么"写成数学：时间索引 MILP 的三个约束、NP 难的代价、LPT 的 4/3 保证与下界，以及滚动时域调度怎么在动态任务流里保持不抖。

  • 主题：协同调度机制（优化建模）
  • 关键机制：时间索引 MILP、NP 难与规模边界、LPT 启发式与下界、滚动时域与冻结窗口
  • 预计学时：65 分钟
  • 前置章节：第 095 章

学习目标

  • 会把调度问题写成时间索引 MILP：决策变量、三条核心约束（每任务一次、每机时容量、完工时间）、目标函数。
  • 理解 NP 难的含义与"可精确求解规模边界"：什么规模该用求解器、什么规模必须换启发式。
  • 掌握 LPT 启发式与下界计算：为什么"最长任务先做"有 4/3 近似保证，以及 gap 指标怎么报告。
  • 会做局部搜索改进（交换/插入），理解它"保底不劣化"的接受准则。
  • 能设计滚动时域调度：规划窗口、冻结窗口、重规划频率、改动率（churn）控制，动态任务流下的稳定调度。

背景与动机

第 066–071 章做过任务分配与调度：贪心、拍卖、优先级排队。这是一种"工程直觉"的调度；本章给自己的调度能力补上"优化建模"的另一半：把问题写成求解器能读的形式，用精确解与下界给启发式打分。为什么必须要有这一半？两个理由。其一，科研与论文里"我们的调度比基线好 15%"需要一个参照系，精确解或理论下界就是那个参照系，否则 15% 可能只是"对手太弱"。其二，启发式什么时候会离谱地差是有规律的：不懂模型的人调参靠试，懂模型的人知道"任务时长分布越偏、机器数越少，LPT 的保证越紧"这类结论。

本章走完建模三角：精确模型（MILP）管小规模正确性，启发式（LPT + 局部搜索）管大规模可用性，滚动时域管理动态性。三者配合的标准姿势是：小规模实验用 MILP 给最优解，验证启发式的实际 gap；大规模上线跑启发式，每轮调度报告"距下界多少"。这套方法论可以让一份调度系统的实验章从"我们试了三种方法"升级为"我们证明了我们是 x% 以内最优"。

核心原理

1. 调度问题三件套：任务、机器、时间

先统一记号：任务集合 J（每个任务 j 有处理时长 pj，在不同机器人上可能不同，记 pij），机器人集合 I（共 m 台），时间离散成时隙 t = 0, 1, …, T−1（比如 1 分钟一格）。调度的输出是"每个任务何时由哪台机器人开始执行"。这个抽象覆盖了取送任务、巡检点、充电窗口等大多数场景。

目标函数的选择会改变系统行为，是最容易被忽视的设计决策：最小化完工时间（makespan）让最后完成的任务尽快结束（总吞吐优先）；最小化总完成时间（sum of completion times）偏向短任务先做（平均体验优先）；最小化超期（tardiness）给每个任务一个截止期，晚一秒罚一秒（外部承诺优先）。第 084 章讲过 makespan 与 SOC 对轨迹规划的行为差异，这里是同一枚硬币的调度面，选目标 = 选价值观，必须与业务承诺对齐并写进文档。

2. 时间索引 MILP：三条约束装下整个调度

最通用的建模方式是时间索引（time-indexed）：决策变量 xijt ∈ {0, 1} 表示"任务 j 由机器人 i 在时隙 t 开始"。每个变量就是一个开关，约束逐条写：

目标：min C；约束：① Σi,t xijt = 1（每个任务恰好做一次） ② Σj Σs ∈ [t−pij+1, t] xijs ≤ 1（每台机器人任一时刻至多一个任务） ③ t + pij ≤ C + M·(1 − xijt)（完工时间定义，M 为足够大的常数） C 是 makespan 变量；③ 是"big-M"技巧：x = 1 时它强制 t + p ≤ C，x = 0 时被 M 完全松开，不起作用

写出来不到十行，它却精确覆盖了调度的全部核心困难：①保证不漏不重；②是资源容量（防同一台机器人被同时派两活）；③把"完成时间的最大值"线性化。可扩展性也直白：加截止期就加一行（t + p ≤ dj + M(1−x)），加先后关系（任务 B 必须在 A 后）再写对齐时刻的约束对；这就是"建模"的威力，新业务规则 = 新约束行，无需重写算法。

规模感：任务 20 个、机器人 4 台、时域 60 格 → 变量 20×4×60 = 4800 个二进制变量，现代求解器（CBC、SCIP、Gurobi、OR-Tools 系）几秒内可解；任务 100 个、8 台、时域 240 格 → 19 万变量，分钟级到小时级甚至解不动。这就是后面要讲的"规模边界"。

3. NP 难与求解边界：为什么必须准备启发式

多机器人调度的一般情形是 NP 难的（它是车间调度/并行机调度的推广，最坏情况计算量随规模指数爆炸），这意味着"总能快速找到最优调度"的算法不存在（在公认的计算复杂性假设下）。工程结论有三条：

  • 小规模用精确解：任务 ≤ 15–30 个时用 MILP 求最优（或限时求"当前最好 + 界"）；精确解主要用于基准与验证，不必上线全量跑。
  • 大规模用"启发式 + 下界"：启发式给可行解，下界给"最优不可能低于这个值"的证据，两者相除得到 gap，报告"距下界 8%"比"平均快 12%"专业一个量级。
  • 复杂度不吓人但要防最坏：实际数据极少触发最坏情况，但重规划超时必须有兜底（沿用上一版调度并顺延），调度器绝不能把系统"卡住等解"。

4. LPT 启发式：一个漂亮的保证

同构机器人、最小化 makespan 的经典启发式叫最长处理时间优先（Longest Processing Time first, LPT）：把任务按时长从大到小排序，逐一把每个任务分给"当前累计负载最小"的机器人。它的理论保证很漂亮：LPT 的 makespan ≤ (4/3 − 1/(3m)) × 最优值。直觉两句话：（1）大任务先来，避免"最后剩一块巨石"把所有负载顶穿（巨石放进某个空槽时其他槽都接近满，所以顶多超过最优一个巨石引发的裕量）；（2）下界取"最长单任务"与"总负载 ÷ 机器数"的较大者，任何调度的 makespan 都不可能小于这两者，与 LPT 结果一比即得实际 gap。异构图（机器人速度不同）时 LPT 的保证减弱，但"下界 + 局部搜索"的组合依然好用。

5. 滚动时域调度：动态世界里的稳定性

真实任务不是一次给全的：新订单随时来、某台机器人可能临时退出。标准做法是滚动时域（receding horizon）：每隔一个周期（如 30 s）取"待派任务窗口"重新优化一次，只执行计划的前一段（冻结窗口），再滚动。两个参数决定行为：

  • 规划窗口长度 W：短窗口反应快但容易短视（只看近日，忽略远处）；长窗口更好但有计算量与"信息未到"的风险。经验起点：W ≈ 平均任务时长的 5–10 倍。
  • 冻结窗口 F：距现在 F 时间内的计划不许改（执行中与马上要执行的），防止"每次重规划都把在途任务改派"引起震荡。F ≈ 一次任务的最大执行时长。

配套指标是改动率（churn）：两次重规划之间被改派的任务占比。churn 高说明调度"神经质"，机器人不停地被改目标，既费能量又不可预测。控制手段：冻结窗口、改派代价（把"改派"写进目标函数加罚）、以及重规划频率下调。滚动调度是一个典型的"最优性 vs 稳定性"权衡：每 30 s 全力优化一次的 churn 通常远高于每 60 s 温和优化一次，而 makespan 差距往往不到 3%。

关键代码与解读

片段 1：时间索引 MILP，用建模语言把调度写"清楚"

from pulp import (LpProblem, LpVariable, LpMinimize, lpSum, LpBinary, LpContinuous)

def build_schedule_milp(m, tasks, p, horizon):
    """时间索引 MILP：m 台机器人、tasks 任务、p[j] 时长、horizon 时隙数。"""
    prob = LpProblem("fleet_schedule", LpMinimize)
    T = range(horizon)
    # x[i, j, t] = 1 表示机器人 i 在时隙 t 开始执行任务 j
    x = {(i, j, t): LpVariable(f"x_{i}_{j}_{t}", cat=LpBinary)
         for i in range(m) for j in tasks for t in T}
    C = LpVariable("makespan", lowBound=0, cat=LpContinuous)   # 目标变量
    for j in tasks:                       # 约束 1：每个任务恰好被做一次
        prob += lpSum(x[i, j, t] for i in range(m) for t in T) == 1
    for i in range(m):                    # 约束 2：任一时刻至多一个任务（容量）
        for t in T:
            prob += lpSum(x[i, j, s] for j in tasks for s in T
                          if s <= t < s + p[j]) <= 1
    M = horizon + max(p.values())         # big-M：足够大即可，过大伤数值
    for i in range(m):                    # 约束 3：makespan 不小于任何任务完工
        for j in tasks:
            for t in T:
                prob += t + p[j] <= C + M * (1 - x[i, j, t])
    prob += C                             # 目标：最小化完工时间
    return prob, x, C

解读：这段代码与公式一节一一对应，读代码等于复习建模。（1）变量用字典装：时间索引模型变量多，字典是"按需生成 + 便于查询"的常规容器；（2）约束 2 的区间和写法（s <= t < s + p[j]）是时间索引建模的招牌技巧：任务占用的是一个"滑动窗口"，用起始变量在窗口内的求和表达"此刻忙不忙"；（3）big-M 取值：恰好足够大（horizon + 最大任务时长）即可，M 取 10⁶ 这种"随便大"会恶化求解器的数值稳定性与松弛质量。另一个实战技巧是顺手加入"对称为破除"约束（比如机器人同构时约束 x 的字典序）能把求解时间砍掉一半以上，属于求解器使用的进阶手艺。

片段 2：LPT + 理论下界，启发式也要自带"成绩单"

def lpt_schedule(p, m):
    """最长任务优先：排序后逐个放到当前负载最小的机器人上。
    同构机、最小化 makespan 时保证 ≤ (4/3 − 1/(3m)) × 最优。"""
    loads = [0.0] * m
    assign = {}
    for j in sorted(p, key=lambda j: -p[j]):      # 大石头先放，避免结尾顶穿
        i = min(range(m), key=lambda i: loads[i])  # 当前最闲的机（确定性平局）
        assign[j] = i
        loads[i] += p[j]
    makespan = max(loads)
    # 下界：任何调度都不可能低于 max(最长单任务, 总时长/m)；gap 有据可依
    low_bound = max(max(p.values()), sum(p.values()) / m)
    gap = (makespan - low_bound) / low_bound
    return assign, makespan, low_bound, gap

# 例：p = {a: 8, b: 7, c: 6, d: 5, e: 4}，m = 2
# LPT 逐一放最闲机（平局取小编号）：a→机0(8)，b→机1(7)，c→机1(13)，d→机0(13)，
# e 时两台同为 13，取机0 → (17, 13)；makespan 17，下界 max(8, 30/2) = 15，gap ≈ 13%

解读：LPT 十行，但注释里那句"4/3 − 1/(3m)"是它进入教科书的原因，所有实例都有保证，不只是平均表现。小例子的演算（注释里展开了每一步）值得亲手复核一遍：排序思路不是玄学，每一步"最闲机"的选择都是可以手算跟踪的。gap 的计算是最重要的工程习惯：启发式的输出天然带证伪的风险（"它到底好不好？"），下界是免费的参照物（两条下界的推导各自只要半行），报告里给出 "makespan 17，下界 15，gap 13%" 的信息量远大于"耗时 17"。注意这里的参照是"下界"：下界不保证可达，所以它是保守参照（真实 gap ≤ 报告中值）；要精确的最优参照就回到片段 1 的 MILP。

片段 3：局部搜索与滚动冻结，把静态解变成动态调度

import numpy as np

def local_search(p, assign, m, iters=300, rng=None):
    """交换/插入局部搜索：只接受严格改善的移动（保底不劣化）。"""
    loads = [0.0] * m
    for j, i in assign.items():
        loads[i] += p[j]
    for _ in range(iters):
        j = rng.choice(list(p))                    # 随机挑任务试挪
        i, i2 = assign[j], rng.randrange(m)
        if i2 == i:
            continue
        others = [v for k, v in enumerate(loads) if k not in (i, i2)]
        span = max(loads[i] - p[j], loads[i2] + p[j], *others)
        if span < max(loads):                      # 只看"总完工时间"是否改善
            assign[j] = i2
            loads[i] -= p[j]
            loads[i2] += p[j]
    return assign, max(loads)

def rolling_update(tasks_new, frozen, assign, m, rng):
    """滚动时域：冻结在途任务，只对窗口内任务重排。"""
    window = [j for j in tasks_new if j not in frozen]   # 冻结：不许改派
    sub = {j: assign[j] for j in frozen if j in assign}   # 保留冻结分配
    fresh = lpt_schedule({j: tasks_new[j] for j in window}, m)[0]
    sub.update(fresh)
    return local_search(tasks_new, sub, m, rng=rng)

解读：局部搜索的接受准则"只接受严格改善"（span < max(loads)）让它成为"保底改进器"：输出永远不差于输入，是给 LPT 解"镶边"的安全工具，与模拟退火（可接受暂时变差以跳出局部极小）形成鲜明对比：调度系统上线初期建议只用保底版，等有实验数据再决定要不要引入退火与重启。rolling_update 展示了阻尼式滚动：frozen 集合（执行中与即将执行的任务）直接保留原分配，其余重新 LPT + 局部搜索，冻结集合的大小就是 churn 的安全阀。注意子问题里时长字典的重建（sub 与 tasks_new 的不同视图）容易写错，一个务实的约定是：任务对象不可变、分配可变；所有视图只是引用集合，从数据结构层面消灭这类 bug。

常见坑

  • 忘记容量约束导致"双份预定"：调度表里同一台机器人同一时段被派两个任务，执行端来回跳。修复：约束 2 是硬红线，写单元测试，随机生成 1000 个调度表，验证任意机器人的任务区间不重叠。
  • 时长估计凭感觉：p 值不准会让最优调度变成事故（"纸面完成 10 分钟，实际 25 分钟"）。修复：用实绩统计（P50/P90）驱动估计，并周期性校准；对"高估风险"的任务用 P90。
  • 目标函数单选 makespan 造成负载不均：一台忙死、一台闲死，公平性差。修复：目标里加负载方差小权重；验收时同时看 makespan 与负载极差（最大负载 − 最小负载）。
  • 重规划把在途任务改派：机器人走到一半接到"你去另一个任务"的指令，churn 高且能耗差。修复：冻结窗口 + 改派惩罚项；churn 指标超过 20% 就告警。
  • 启发式报告不报 gap、随机不设种子：结论不可复现、效果无法评价。修复：种子进配置；每轮调度日志记录"makespan、下界、gap、churn"四个数，这四元组是调度系统的体检报告。

练习与思考

  1. 算一算：3 台机器人，任务时长 p = {6, 3, 3, 2, 2, 2}（分钟）。手算 LPT 的分配与 makespan，再算下界 max(最长任务, 总和/3)，给出 gap；尝试通过交换找一版更好解，说明 LPT 是否在你这组数据上最优。★
    提示
    总和 18，下界 max(6, 6) = 6。LPT：6→机0，3→机1，3→机2，2→机1，2→机2，2→机1（平局取小编号）→ 负载 (6, 7, 5)，makespan 7，gap ≈ 17%。把机1 的 3 与机2 的 2 对换：(6, 6, 6) 达到下界，说明这组数据上 LPT 不是最优，一次简单交换就能补上。
  2. 改配置并预测结果：把目标函数从 makespan 换成"总完成时间之和"（Σ completion times）。预测调度形状会怎么变（短任务还是长任务优先），以及公平性指标（负载极差）如何变化。★
    提示
    总完成时间目标下短任务优先（SPT 类规则最优），每台机器人内部按短任务排序；负载分布可能更不均匀（一台专做碎活）。预测要写"目标函数换 ⇔ 行为策略换"的对应关系。
  3. 设计：给调度模型加两条新约束并写出公式：(a) 任务 j 有最晚开始时刻 uj；(b) 任务 B 必须在任务 A 完成后才能开始（先后依赖）。说明你加在时间索引模型的哪一行、怎么用 x 表达。★★
    提示
    (a) 对 t > u_j 的所有 x[i,j,t] 直接约束为 0（或写 Σ_{t≤u_j} x = 1）。(b) 引入辅助对齐：对任意 i_t, i_s，t_B + p_B ≤ t_A + M(2 − x_A − x_B) 型的成对约束（或按时间窗求和形式 t_A 的区间和 = 1 在 t_B 之前）。关键：big-M 要把"两条都执行"与"只执行为 0 的松弛"区分开。
  4. 推导：对同构机调度，证明下界 LB = max(maxj pj, Σpj/m) 对任何可行调度的 makespan 都成立（两句论证），并说明为什么 LPT 的 4/3 保证里"最后一块巨石"是关键情形。★★
    提示
    任何调度里最长任务自己就占用 ≥ max p；总负载必须被 m 台分担，至少一台 ≥ Σp/m，两句话各自独立成立。4/3 情形：LPT 最大的超支发生在"最后放入的大任务把某台机顶起来而其他机都接近满"，分析该情形可得上界。
  5. 实验：任务流模拟器（任务随机到达，平均每 20 s 一个，共 60 个，4 台机器人）对比三种策略：(a) 全量重规划每 30 s（无冻结）；(b) 滚动时域（窗口 10 任务、冻结 120 s）；(c) 贪心即时分配。统计 makespan、churn、平均任务等待时间，写 5 行结论并给出上线建议。★★★
    提示
    预期：全量重规划 makespan 最好但 churn 最高（机器人被频繁改派）；滚动冻结版 makespan 差 2–5% 但 churn 下降数倍；贪心简单但 makespan 差 10–20%。建议通常落在 (b)：用 <5% 的最优性换稳定的执行行为，并用数据支撑这句话。

小结

  • 调度建模三件套：任务、机器、时间；目标函数（makespan / 总完成 / 超期）是价值观选择，必须与业务承诺对齐。
  • 时间索引 MILP 三条约束：每任务一次（①）、每机时容量（②）、big-M 线性化完工时间（③）；新规则 = 新约束行。
  • NP 难 ⇒ 规模边界：≤ 20–30 任务用精确解（基准），大规模用启发式 + 下界，报告 gap，不用"快了百分之几"这类无参照的说法。
  • LPT：最长优先 + 放最闲机，4/3 − 1/(3m) 保证；下界 = max(最长任务, 总负载/m) 免费提供成绩单。
  • 局部搜索只接受严格改善（保底不劣化）；随机种子进配置保证可复现。
  • 动态世界用滚动时域：规划窗口 W、冻结窗口 F、churn 监控，最优性与稳定性的交换要用实验数字来谈。
