第三篇 · 协同控制与任务协同

第 045 章：多机器人协同编队避障

编队遇到墙、柱子和窄门：先算几何能不能挤过去，再在"刚性绕行、形变收缩、临时纵队"三种策略里切换，用带阻尼的势场把队形保持与环境避障融合到一个速度指令里。

  • 主题：协同控制 / 编队级避障
  • 关键机制：队形宽度判定、模式状态机、势场融合与阻尼、纵队依次通过
  • 预计学时：60 分钟
  • 前置章节：第 044 章

学习目标

  • 区分"机器人互避"与"编队避障"两类问题：第 044 章处理前者，本章处理环境障碍与队形保持的耦合。
  • 掌握队形几何可通行性判定：由模板与缩放计算队形宽度 B，与门宽、安全边距做比较。
  • 会用"CRUISE / SQUEEZE / COLUMN / REFORM"四态机组织通过策略，并说清每个迁移条件与超时兜底。
  • 能设计"编队保持 + 障碍斥力 + 阻尼"的势场合成，理解权值过大过小各自造成的问题。
  • 会为编队避障定义双指标验收：队形误差与最小安全距离同时达标。

背景与动机

044 章的安全层保证机器人之间不撞，但编队任务还要面对第三种物体，环境本身。走廊、门框、立柱不会"各让一半"，它们对队形的态度是寸步不让。更麻烦的是尺度错配：一台机器人 0.5 m 宽，一扇门 1.0 m 宽，单机轻松通过；但三台并排的楔形队形宽 2 m，硬顶只会撞门框；如果每台机器人只顾自己躲墙，队形会当场散架，恢复又要几秒。

所以编队避障必须是"两件事同时管"：队形整体对障碍物做战略决策（绕行、收缩还是解体），每台机器人对局部障碍做战术反应（不能撞墙）。本章的四态模式机与势场融合，是把这两个尺度统一到同一控制回路的标准做法，也是巡逻、搜索、搬运任务穿行建筑环境的必备技能。

核心原理

1. 三个层次的通过策略

按对队形的"破坏程度"从低到高：(1) 刚性绕行，把编队当作虚拟刚体，整个队形平移到障碍侧方绕过去。队形完好，但只适合"障碍可以绕过"的场景（例如一根柱子），通道整体变窄时它无能为力。(2) 形变收缩，保持模板形状与相对顺序，按比例缩小间距。收缩的下限由机器人尺寸与容错决定：两台机器人中心距小于 0.6 m 时，定位误差就可能让安全层持续介入，所以最小缩放因子通常定在 0.6–0.8。(3) 临时解体，切换成纵队依次通过，过门后重组。破坏性最大、但能通过最窄的通道，且纵队天然与门的形状匹配。

可通行条件：B(s) = s · B0 ≤ Wgate − 2·m B0 为模板在机体系下的横向宽度，W 为门宽，m 为单侧安全边距（0.25 m 量级）

2. 模式状态机：谁在什么时候说"换"

策略选择必须集中、及时、可回退。由协调者（可以是编队领航者）运行一个四态机：CRUISE（常态）→ 检测到前方门框，且原队形宽度超过可用宽度时进入 SQUEEZE（收缩）或 COLUMN（纵队）；通过后进入 REFORM（重组）直到队形误差回到阈值内，再回 CRUISE。两个工程细节决定成败：

  • 超时兜底：SQUEEZE 状态停留超过 10 s 仍未通过，说明"收缩也不够"或"卡住了"，直接降级为 COLUMN，宁可临时解体，不可无限等待。
  • 恢复条件：REFORM 的退出条件是"队形误差小于 0.15 m 连续 2 s"，不是"队尾过了门"。过早恢复会让队形在门框里展开，二次剐蹭。

模式切换消息走可靠 + 持久化 QoS：模式只有四种、切换频率为一分钟几次，带宽零头都算不上，但漏一条消息代价很大（一队按纵队走、一队按楔形走，现场立刻混乱），所以用 Reliable + Transient-local 让重启节点也能同步到当前模式。

3. 势场融合：三种"力"的分工

无论处于哪个模式，每台机器人最终执行的是一层速度场：

vcmd = kf·(pd − p) + Σo ko·(1/do − 1/D)·d̂o − kv·v 编队保持项 + 障碍斥力项（影响半径 D 内有效）+ 阻尼项；障碍项只在 d < D 时非零

三个设置要点。其一，斥力采用 (1/d − 1/D) 形式：它在 d = D 处平滑归零，不会出现"刚进入影响圈就被猛推一下"的跳变；1/d² 形式在边界处仍有非零斥力，进入影响圈的瞬间会产生跳变。其二，阻尼项必须有：势场天生是保守系统，没有耗散就会在目标点附近来回振荡；阻尼系数 0.5–0.8（对应 1/s 量纲）在 20 Hz 控制环下能把振荡压到可接受范围。其三，编队保持力要限幅（如每轴 ±2 m/s 当量）：跟在队尾 5 m 外的机器人不能因为"误差大"就爆冲，追击速度必须由上层统一限幅。

4. 纵队通过的时间账

纵队策略的时间成本可以直接算：设每台间距 ds（1.0–1.5 m）、巡航速度 v（0.4 m/s 的保守值）、门框纵深 Lg，全队通过时间为：

Tcolumn ≈ Lg/v + (N−1)·ds/v 4 台、间距 1.0 m、门深 0.5 m、0.4 m/s：约 1.3 + 7.5 = 8.8 s

这个公式解释了为什么"能不纵队就不纵队"：纵队的时间几乎全耗在"排队"上。走廊连续出现三扇门时，应尽可能在通过第一扇后顺路保持纵队通过后续门，省掉每扇门各一次的重组，状态机里用"前方 10 m 内是否还有门"作为 REFORM 的附加条件。

5. 局部避障不能被代替

协调者算的是"队形级几何"，但门框的具体位置受定位误差影响，且队形里每台机器人两侧的空间各不相同。因此每台机器人必须保留本地激光避障（10 Hz 量级）作为最后防线：势场的障碍项直接来自本机激光检测的近障碍点，与队形保持项按权值叠加。编队级决策负责"走哪种形状"，本机避障负责"这一步别撞上"，层级与 044 章的速度安全滤波器完全一致。

6. 数值算例：门宽档位与纵队时间

用片段 1 的 choose_mode 对四个门宽逐档算一遍。楔形模板 scale = 1 时横向宽度 B = 2.0 m，单侧边距 0.25 m，收缩需求 s_need = (W − 0.5)/2.0：

门宽 Ws_need决策收缩后相邻间距

2.0 m0.75SQUEEZE（缩到 0.75）1.425 m
1.6 m0.55COLUMN（低于最小缩放 0.7）队列间距 1.2 m

读表注意两点。其一，2.0 m 门是 SQUEEZE 的典型档：收缩到 0.75 后相邻间距 1.425 m，远高于 0.6 m 的控制下限，队形形状不变，看上去仍是楔形；其二，1.6 m 门恰好落在"收缩不够用"的档位，s_need = 0.55 低于最小缩放因子 0.7，硬缩会突破间距下限，所以直接纵队。把最小缩放改成 0.6 后 1.6 m 门仍然是 COLUMN（0.55 < 0.6），说明这个档位的安全边界较宽，参数微调不会引起模式翻转。

纵队通过的时间账：T = Lg/v + (N−1)·ds/v = 0.6/0.4 + 3×1.2/0.4 = 1.5 + 9.0 = 10.5 s，其中排队占了 9 s、约 86%。对照"整形"的成本：四台机器人从纵队重塑回楔形，按第 043 章算例的量级需要 4–8 s 的节拍加稳定时间；门后 10 m 内还有第二扇门时，保持纵队几乎免费，能省下整整一次重塑。这就是状态机里"前方 10 m 内有门就不恢复队形"条件的定量依据。

感知误差的安全线：门宽估计误差与定位误差合计约 0.3 m。若 s_need 恰好贴近 0.7（1.9 m 门对应 0.70），实际收缩后两侧可能只剩不到 5 cm 余量，任何横向抖动都会剐蹭。工程做法是把 0.70–0.85 定义为"低置信修剪区"：落在这一档优先选 COLUMN，用一次排队换掉剐蹭风险；s_need 高于 0.85 才放心 SQUEEZE。

7. 三档策略对照与势场权值的量级

三档策略的取舍放一张表里，选型时按判据对号入座：

策略适用几何时间代价队形代价
刚性绕行障碍可绕过、通道净宽足够绕行距离 ÷ 巡航速度（数秒量级）无
形变收缩门宽不低于 2·m + 0.7·B0接近零间距缩小，抗扰余量下降
临时纵队任意窄门（含 1.2 m 及以下）本例 10.5 s解体与重组各一次

势场里"队形散架"的机理也能定量化。按片段 2 的参数（kf = 1.2、ko = 0.6、D = 0.8、障碍半径 0.2）：距离墙体 0.3 m 时斥力为 0.6 × (1/0.3 − 1/1.0) = 1.4 m/s 当量；同一时刻若队形误差只有 0.5 m，编队保持项为 1.2 × 0.5 = 0.6 m/s 当量。斥力是保持项的 2.3 倍，机器人会先远离墙、后归位，队形被"压扁"。修复方向有两个：把 ko/kf 限制在一倍以内，或让斥力在 SQUEEZE/COLUMN 模式才放大；调参时用"过门段槽位误差的 P95"作指标，比肉眼观察通道更可靠。

失效模式补一条：如果把 D 调大到 1.5 m 以上，空旷环境下两个正常通过的门也会被当作"障碍区"，阻碍项持续进入速度场，队形在门口反复微调、速度掉到 0.1 m/s 以下。判据是"无障碍段的速度不应低于巡航值的 90%"，把这条写进验收脚本，D 的调大就不会越过安全区。

模式广播的可靠性账也值得一算：一条模式消息含字符串与版本号约 100 字节，按"切换时立即发 + 1 Hz 重播"算，事件期间总流量不到 1 kB/s，用 Reliable + Transient-local 的代价几乎为零。真正要防范的是"消息到了但语义晚了"：Transient-local 会在新加入者上线时补发最后一条，若那条消息是 10 分钟前的旧模式，新机器人会按过期队形行动。修复办法是消息带时间戳与序号，接收方发现"模式消息年龄超过 60 s 或序号落后于已知值"时先请求全量状态再用；这两个字段缺失时不要进入生产。

纵队通过时最容易出错的不是几何、是次序。若每台按"找最近的队友尾随"的隐式规则排队，两台机器人可能同时认为自己紧跟领航者，队列里出现并排。把 column_slot 显式随模式消息下发，每台只认自己的前车编号，是纵队实现里唯一可靠的排序方式；这条与第 043 章"顺序由公告确定"是同一原则在不同场景的复现。

实现思路与设计

  1. 障碍与门框感知：领航者从前视激光/深度传感器提取"正前方 3 m 内的通道可用宽度"。实现上取前方 2 m 处的占用栅格列并测量空闲区间宽度，对应门宽估计 gate_width；两侧墙形成连续窄段时才视为门。
  2. 几何决策：用模板与缩放计算队形宽度 B(s)，按可通行条件输出 CRUISE / SQUEEZE / COLUMN。BELOW 0.7 的最小缩放直接纵队。
  3. 模式广播：/fleet/formation_mode（字符串或枚举 + 版本号），Reliable + Transient-local，切换时立即发布并 1 Hz 重播。
  4. 执行：每台机器人本地运行"编队保持 + 障碍斥力 + 阻尼"速度场，20 Hz；SQUEEZE 时目标位置由收缩后的模板给出；COLUMN 时目标位置由上一台机器人后方 ds 的固定距离给出（复用 042 章的跟随控制）。
  5. 恢复判定：协调者收齐各机队形误差（1 Hz 上报）后判定 REFORM 完成。
  6. 验收：走廊场景（宽 1.5 m、两扇 1.2 m 门）10 次运行全部通过；过程中队形横向误差峰值小于 0.5 m；门框处最小间距大于 0.15 m；无卡死（速度低于 0.05 m/s 的累计时长小于总时长 5%）。

关键代码与解读

片段 1：队形宽度与通过模式决策

import numpy as np

def formation_width(template, scale):
    """机体系下队形的横向宽度 B：决定能不能过窄门。"""
    ys = np.asarray(template)[:, 1] * scale
    return float(ys.max() - ys.min())

def choose_mode(gate_width, template, scale, min_scale=0.7, margin=0.25):
    """根据门宽与队形宽度选择通过策略；gate_width 为 0 表示未见门。"""
    if gate_width <= 0.0:
        return "CRUISE", scale              # 没有障碍：保持原队形巡航
    B = formation_width(template, scale)
    # 收缩后每侧至少留 margin，防止贴边剐蹭与检测误差
    s_need = (gate_width - 2.0 * margin) / max(B, 1e-6)
    if s_need >= 1.0:
        return "CRUISE", scale              # 原宽度足够：整体直过
    if s_need >= min_scale:
        return "SQUEEZE", scale * s_need    # 收缩队形通过（保持模板）
    return "COLUMN", scale                  # 收缩也过不去：临时纵队

解读：决策函数的输入只有"门宽、模板、当前缩放"，输出是模式与目标缩放，把"过不过得去"这样一个现场判断，压缩成一个三行不等式，好处是可测试、可复现。min_scale = 0.7 不是随手定的：楔形模板 scale = 1 时相邻机器人间距约 1.9 m，缩到 0.7 剩 1.3 m，仍大于 0.6 m 的控制下限；若场景要求更小间距，应当改模板，继续压缩放无法突破下限。返回的 scale * s_need 直接把收缩比例传到执行层，保证"决策"与"执行"用同一个几何模型，不会出现两边算法不一致的错位。

片段 2：编队保持 + 障碍斥力 + 阻尼的合成速度场

import numpy as np

def desired_velocity(pos, vel, target, obstacles,
                     k_f=1.2, k_o=0.6, k_v=0.6, v_max=0.8, D=0.8):
    """三层速度场：编队保持 + 障碍斥力 + 速度阻尼，输出限幅后的速度。"""
    e = target - pos
    f_form = k_f * np.clip(e, -2.0, 2.0)          # 限幅：远距不爆冲
    f_obs = np.zeros(2)
    for op, oradius in obstacles:                  # 本机激光提取的障碍点
        d_vec = pos - op
        d = float(np.linalg.norm(d_vec))
        if 1e-3 < d < D + oradius:
            # (1/d - 1/D) 在影响边界平滑归零，避免势场跳变
            infl = D + oradius
            f_obs += k_o * (1.0 / d - 1.0 / infl) * (d_vec / d)
    f_damp = -k_v * vel                            # 阻尼：压住势场振荡
    v = f_form + f_obs + f_damp
    n = float(np.linalg.norm(v))
    return v * min(1.0, v_max / max(n, 1e-6))      # 限速到 v_max

解读：这是"单层速度场"写法，三项增益量纲都是 1/s，输出在物理上就是"期望速度"，直接对应 Twist 的线速度，省掉一层动力学换算。三个细节决定行为：限幅让队尾远距误差不转化为爆冲；斥力平滑使进入影响圈的过程没有冲击；阻尼对速度下手（误差进的是编队项），压的是振荡的"势头"。调参有个可操作的顺序：先只开编队项确认能收敛，再加障碍项把 D 调大直到能及时躲开，最后加阻尼把目标点附近的振荡压掉，一次性全开很难分清是哪一项出问题。

片段 3：模式状态机与超时兜底

def step_mode(state, obs, dt):
    """四态机推进：CRUISE / SQUEEZE / COLUMN / REFORM。obs 为感知汇总。"""
    t = obs["time_in_state"] + dt
    if state == "CRUISE":
        if obs["gate_ahead"] and not obs["fits_original"]:
            state = "SQUEEZE" if obs["fits_scaled"] else "COLUMN"
    elif state == "SQUEEZE":
        if not obs["gate_ahead"]:
            state = "REFORM"                      # 已通过：准备恢复队形
        elif t > 10.0:                            # 收缩 10 s 未过：降级纵队
            state = "COLUMN"
    elif state == "COLUMN":
        # 队尾离门 1.0 m 以上且前方短距无门，才允许恢复
        if obs["tail_clear_gate"] >= 1.0 and not obs["gate_within_10m"]:
            state = "REFORM"
    elif state == "REFORM":
        if obs["formation_error"] < 0.15:          # 重组到位：回到巡航
            state = "CRUISE"
    return state, (0.0 if state != obs["prev_state"] else t)

解读：状态机本体只有四个迁移判断，工程价值在条件的设计上。tail_clear_gate 用"队尾离门距离"判定，避免了 042 章里说过的"领航者过门就算过完"的跟错参照问题；gate_within_10m 实现"门后还有门就保持纵队"的优化，省掉一次 9 s 量级的重组；SQUEEZE 的 10 s 超时给出了最坏情况下的收敛保证。返回的计时器在同一状态内累加、切换时清零，供超时与遥测使用，这类"状态 + 时间"的组合在协同决策里到处出现，值得做成公用小工具。

常见坑

  • 斥力权值过大导致队形散架：机器人为了离墙远一点而偏向通道中线另一侧，队形被"压扁"甚至交叉。症状是过门后队形误差长时间大于 0.5 m。修复：限制斥力项幅度（比值不超过编队保持项的 60%），或只在 SQUEEZE/COLUMN 模式放大斥力。
  • 收缩判定不考虑检测误差：门宽估计比实际大 0.3 m，SQUEEZE 时贴边剐蹭。修复：边距 m 不小于"门宽估计误差 + 定位误差"之和；把单侧边距做成配置项，现场可调。
  • 恢复过早：队尾还在门框内，协调者就发 REFORM，队形在门里展开撞框。修复：恢复条件用"队尾净空 + 连续 2 s 队形误差达标"，两个条件都满足才切换。
  • 纵队切换时跟错前车：网络中两台机器人同时声称是"第 2 号"，纵队顺序错乱。修复：纵队顺序由协调者显式分配（column_slot 随模式消息下发），每台只跟自己的前车，不靠"最近的机器人"这类隐式规则。
  • 只做队形决策不做本机避障：协调者按估计的几何决策，遇到凹凸不平的墙面（检测误差大）时整队剐蹭。修复：本机激光避障永远保留，权值可以更低，但不能关，"战略 + 战术"两层缺一不可。

练习与思考

  1. 楔形模板（scale = 1）横向宽度 2.0 m。门宽分别为 2.6 m、2.0 m、1.6 m、1.2 m 时，按 choose_mode 的规则各应选择什么模式？若最小缩放因子改为 0.6，结论有变化吗？★
    提示
    s_need = (W − 0.5)/2.0：2.6→1.05（CRUISE）、2.0→0.75（SQUEEZE）、1.6→0.55（COLUMN）、1.2→0.35（COLUMN）。改 0.6 后 1.6 m 门仍为 COLUMN，因为 0.55 小于 0.6。
  2. 4 台机器人以纵队过门：间距 1.2 m、速度 0.4 m/s、门深 0.6 m。计算全队通过时间；若门后 8 m 还有第二扇门，比较"先重组再过门"与"保持纵队过两门"的时间差。★
    提示
    T = 0.6/0.4 + 3×1.2/0.4 = 1.5 + 9 = 10.5 s；重组需变队形再展开（+6 s 量级），保持纵队直接省下一次重组。
  3. 把你系统里 k_o 从 0.6 依次改为 0.3、1.2、2.0，预测三种情况下过门行为，并给出一个能验证"队形散架"的量化指标。★★
    提示
    0.3 太弱可能剐蹭；0.6 正常；1.2 起队列被压向门洞中线；2.0 时队形散架。指标用"过门段内模板槽位误差的 P95 值"。
  4. 设计一个连续通道场景（三扇门、两道弯），写出状态机需要的附加感知量（每扇门的宽度与距离、弯道曲率）与模式迁移条件，并估算总通过时间。★★★
    提示
    附加量：门列表（距离+宽度）、当前通道方位。迁移条件用"下一扇门在 10 m 内则保持纵队"。时间按各段走廊长度/速度加纵队排队时间求和。
  5. 为编队避障写验收方案：定义队形误差、最小间距、通过时间、停滞时间占比四类指标，给出仿真与真机各自的通过标准与测量方法。★★★
    提示
    队形误差取槽位偏差的 RMS 与峰值；最小间距由录包逐帧计算；停滞占比用速度阈值 0.05 m/s 统计；每类场景至少 10 次重复取分布。

小结

  • 编队避障的三档策略：刚性绕行不伤队形但只适合可绕过障碍；形变收缩受最小缩放限制；临时纵队能过最窄通道，代价是排队时间。
  • 可通行判定就是"收缩后宽度 ≤ 门宽减安全边距"；决策集中做、执行分布式，模式消息用 Reliable + Transient-local。
  • 速度场三项分工明确：编队保持（带限幅）、障碍斥力（平滑归零）、速度阻尼（压振荡）；调参顺序先编队、再斥力、最后阻尼。
  • 恢复条件看"队尾净空 + 队形误差达标"，并且要跳过连续门的重组；SQUEEZE 超时降级 COLUMN 是最坏情况的兜底。
  • 下一章从"局部避让"上升到"全局路径"：集中式路径规划，一个大脑为全队求解无冲突路径，以及它昂贵的通信与计算账单。
