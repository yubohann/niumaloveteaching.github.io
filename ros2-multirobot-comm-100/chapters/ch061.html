第三篇 · 协同控制与任务协同

第 061 章：多机器人协同覆盖

把一片区域公平地"分家"：条带、网格与 Voronoi 三种分区方法，加权负载均衡与 Lloyd 迭代，进度共享与失联接管，让每块地都被盖到，谁也不吃亏。

  • 主题：任务协同 / 区域覆盖
  • 关键机制：加权 Voronoi 分区、Lloyd 负载均衡、进度共享、失联重划
  • 预计学时：60 分钟
  • 前置章节：第 060 章

学习目标

  • 理解覆盖任务的四类评价指标：完成时间、总路程、重叠率、工作量方差，以及它们之间的取舍。
  • 掌握三种分区方法（条带、细粒度任务田、Voronoi/加权 Voronoi）的适用场景与工程实现。
  • 会用 Lloyd 迭代（向分区质心移动）改善分区形态，理解它为什么能提升负载均衡与紧凑性。
  • 能设计进度共享协议与失联接管规则（含滞回），让"完成"的判定基于全体一致的数据。
  • 能定量估计覆盖任务的通信需求，并规划边界余量与重叠率的验收标准。

背景与动机

覆盖是三篇任务型协同的收官主题：清扫、喷药、巡检、除草、扫雪，任务的定义是"区域内每一点都被处理至少一次"。它与探索的区别在于：探索的目标是获得地图（知识），覆盖的目标是施加动作（效果）；探索可以接受"看漏一点"（之后补），覆盖往往不行（漏喷一块地要返工）。它与搜索的区别在于：搜索用概率地图追一个目标，覆盖要求全空间的均匀性。

多机器人覆盖的核心问题是分区与均衡：分得不好，一边过载一边闲置；边界没对齐，交接处漏一条缝；队友失联后其分区无人接管，整片区域留下空洞。本章先解决"怎么分、谁分到多少、失联怎么办"；下一章（062）接着解决"每个分区内部怎么走出最短最密的路径"。两章合起来才是完整的覆盖系统。

核心原理

1. 覆盖的指标：没有"最好"，只有"权衡"

覆盖方案的好坏至少要看四个量：完成时间（makespan），全队最后一台完成的时间，决定任务工期；总路程，全队累计行驶距离，决定能耗与磨损；重叠率，多台机器人重复处理的面积占比，直接浪费；工作量方差，各机器人实际工时的离散程度，决定公平性与"有人在等"的程度。最小化 makespan 往往意味着让强的机器人多干活（方差大），而最小方差又可能拖长工期；重叠率与边界漏覆盖是一对矛盾（重叠是防漏的保险）。工程上先锁定"哪些指标是红线"（例如重叠率 ≤ 15%、漏覆盖 0），再在红线内优化其余。

2. 三种分区方法

方法做法优点代价
条带分区把区域切成 N 条平行长条，宽度按能力加权简单、路径天然规整、边界清晰形状必须近似矩形；异形区域难处理
细粒度任务田把区域切成小格，机器人逐个"认领"待覆盖格适应任意形状、天然动态平衡认领通信量大、路径碎、频繁转场
Voronoi 分区每格归最近的机器人（可加权）连续、随位置自动调整、无空洞形状可能奇异（长条/飞地）；需机器人移动才平衡

工业清扫与农业喷洒多用条带（地形规整、效率优先）；园区巡检多用 Voronoi（点位分散、需要动态）；不规则废墟多用任务田（形状任意、允许抢占）。本章聚焦 Voronoi 系，因为它最"分布式"：每台只需知道队友位置就能算出自己的分区，与 044 章邻居表、050 章认领是同一套信息基础设施。

3. 加权 Voronoi 与负载均衡

标准 Voronoi 让"离谁近就归谁"，但机器人能力不同：速度 0.5 m/s 的清扫车与 1.0 m/s 的车应按 1:2 分面积。加权 Voronoi 把距离除以权重再比较：

Vi = { p : d(p, ri)/wi ≤ d(p, rj)/wj，∀j } w 可取速度、作业宽度、续航等能力的乘积量；wi 越大分区越大，分区必须与能力成正比；按数量均分是常见错觉

分区形状还会影响效率：细长的分区让机器人频繁转场（条带间往返），紧凑的分区路径最省。改善形状的手段是Lloyd 迭代：算出每个分区的质心，让机器人向自己分区的质心移动，重新分区，重复。数学上这逐步降低分区的"紧凑度代价"（分区点到质心的距离平方和），实践效果是分区越来越方正、边界越来越平滑。代价是机器人要实际移动（几米到几十米），因此 Lloyd 适合"轮次制"覆盖：每轮开始前迭代几次，再开始干活。

4. 进度共享与完成判定

每台机器人对"自己分区覆盖了多少"有本地计数（已处理的格数/格总数），1 Hz 上报（分区 id + 进度百分比 + 位置）。完成判定三条合议：(a) 每个分区进度 ≥ 98%（留 2% 给传感器边缘与定位误差的合理损耗，阈值本身要由漏覆盖抽样验证）；(b) 全队进度报告的时间戳都在最近 10 s 内（防止拿旧数据宣布完成）；(c) 无失联成员或失联成员的分区已被接管且接管进度 ≥ 98%。满足三条后由任一机器人广播"任务完成"，其他机器人复核自己的数据后确认，单一来源的"宣布"不足以终结任务。

5. 失联接管与滞回

队友失联后，它的分区要有人接手，但"失联"与"暂时抖动"必须区分：丢包 1–2 s 是常态，直接重划会让分区频繁变动、机器人来回跑冤枉路。滞回规则：10 s 无进度上报才启动接管；接管时优先按"就近原则"把失联者的分区格划给几何最近的在线机器人（比重新全局 Voronoi 更平滑、不需要所有人移动）；原机器人回来后，先从"当前分区状态"开始（不抢回已经转给别人的区域，避免二次重划），只接收"新的"待覆盖区。接管过程广播一次分区版本号，与 043 章队形版本、048 章 epoch 是同一纪律。

6. 通信量：覆盖任务里最"省"的一类协同

覆盖的协同数据只有"谁在哪、分了哪块、进度多少"：位置 1–2 Hz（几十字节）、分区事件驱动（每条几 kB）、进度 1 Hz（约 20 字节/台）。三台机器人总量不到 1 kB/s；即使 20 台也不到 10 kB/s。方向相反地，真正的瓶颈在路径与执行，所以本章把通信协议做厚、把带宽做薄，把复杂度留给 062 章的分区内部路径规划。另一个实操经验：分区消息用 Transient-local 让中途加入的机器人立刻拿到当前分区，避免"新机器人不知道自己在哪块地里干活"。

7. 数值算例：加权分区的面积与工时闭环

用本章的三台清扫机器人核算一遍加权分区的完整链条。权重 w = 速度 × 作业宽度：前两台 0.5×0.6 = 0.30 m²/s，第三台 0.8×0.6 = 0.48 m²/s，权重比精确为 5:5:8。按此比例切分 600 m² 的园区，三块面积分别是 166.7、166.7、266.7 m²。单机的理论净作业时长 = 面积 / w：慢机 166.7/0.30 ≈ 555.6 s，快机 266.7/0.48 ≈ 555.6 s，三台几乎同时收工，均衡度接近 1.0。若忽略能力按面积均分（每台 200 m²），慢机需要 200/0.30 ≈ 666.7 s（11.1 min），快机只需 200/0.48 ≈ 416.7 s（6.9 min），makespan 被慢机抬高约 20%，快机还空转 4 分钟。这就是"权重必须反映能力乘积"的量化依据：均分面积看似公平，实际上让全队为最慢成员陪跑。

权重还会被机器人位置掩盖。举一个一维算例：区域 [0, 10]，两台机器人位于 x = 1 与 x = 9，权重 1:2。加权 Voronoi 的分界解方程 (b − 1)/1 = (9 − b)/2，得 b ≈ 3.667，两块面积 3.667 与 6.333，比值约 1.73，低于权重要求的 2.0。原因在区域的有限边界：位置靠边的重权机器人的"势力范围"被墙截断，达不到理想比例。Lloyd 迭代正好修补这一点：机器人向各自分区质心移动后再重划，分界点按 3.667 → 3.5 → 3.417 → 3.375 的序列收敛到 3.333，两块面积比精确回到 2:1。这解释了为什么"加权 + 迭代"要成对出现：权重管比例，迭代管边界效应。

8. 重叠率的定量来源与预算

重叠不是靠感觉留的，它可以从边界长度直接算出来。三台机器人并排分区，内部边界共两条，每条长 20 m；0.1 m 的保险带由两侧各覆盖一次，重叠面积 ≈ 2 × 20 × 0.1 = 4 m²，占 600 m² 的 0.67%。即使分区数量更多、边界更曲折，按"保险带宽 × 内部边界总长"估算，常见布局下的重叠都在 1%–3% 量级，远低于 15% 的验收线。另一种重叠来自路径层的搭接（063 参数的作业幅宽重叠），那部分在 062 章按条带计算，与本节的边界带分开记账，两份预算相加才是总重叠率。

保险带买到的容错也可以用误差语言写出来。设每台机器人的定位误差近似零均值高斯、标准差 5 cm，边界处各自的覆盖线在误差下左右浮动，两侧同时"各差一点"时期望漏缝宽度约为 2 × σ × 0.8 ≈ 8 cm（0.8 为半正态分布 E|x|/σ 的系数）。0.1 m 的保险带刚好把 8 cm 的期望漏缝覆盖掉，而 0.05 m 的带宽就要靠运气。反过来，如果实测定位误差只到 2 cm，期望漏缝 3.2 cm，保险带可以缩到 5 cm，把重叠预算省下来换作业时间。重叠率、保险带宽、定位精度三者构成一个可验证的闭环，每次标定完定位系统都应重算一遍这个预算。

实现思路与设计

  1. 任务设定：三台清扫机器人（速度 0.5/0.5/0.8 m/s，作业宽度 0.6 m）覆盖一个 600 m² 的园区（矩形 30 m × 20 m），完成时间目标 90 分钟以内。
  2. 初始化分区：起点出发前用加权 Voronoi（w = 速度 × 作业宽度）算初始分区；随后 Lloyd 迭代 5 次（允许机器人移动到位，单次总移动小于 15 m）。
  3. 边界处理：分区边界内缩 0.1 m、相邻分区在边界带共享一条 0.1 m 的"保险带"（两端都覆盖），由重叠率验收约束其上限。
  4. 进度与上报：每台本地维护"已处理格集合"（0.5 m 网格），1 Hz 上报 /fleet/coverage_progress（分区版本、进度、位置）。
  5. 失联接管：10 s 滞回触发就近接管；广播 /fleet/coverage_partition（格子归属 + 版本，Transient-local）。
  6. 验收：完成时间小于 90 min；漏覆盖率 0（以 0.1 m 抽样检查）；重叠率小于 15%；三台工时方差（标准差/均值）小于 15%。

关键代码与解读

片段 1：加权 Voronoi 分区与面积统计

import numpy as np

def weighted_voronoi(area_mask, robots_xy, weights, res=0.5):
    """网格化加权 Voronoi：每格归给 d/w 最小的机器人。"""
    ys, xs = np.nonzero(area_mask)                        # 区域内的格子
    pts = np.stack([xs * res, ys * res], axis=1)          # 物理坐标
    owner = np.full(area_mask.shape, -1, dtype=int)
    best = np.full(len(pts), np.inf)
    for i, (rx, ry) in enumerate(robots_xy):
        d = np.hypot(pts[:, 0] - rx, pts[:, 1] - ry) / max(weights[i], 1e-6)
        upd = d < best                                     # 加权距离最小者拥有
        best[upd] = d[upd]
        owner[ys[upd], xs[upd]] = i
    return owner

def area_stats(owner, res=0.5):
    """各分区面积：负载均衡的第一观测指标。"""
    return {i: int((owner == i).sum()) * res * res
            for i in range(int(owner.max()) + 1)}

解读：实现采用"以机器人为外层"的结构：对每台机器人一次性算出全区域距离（numpy 向量化），再逐格比较，3 台机器人、2400 个格子的规模毫秒级完成。weights 的物理含义要在调用处写清楚（本项目 = 速度 × 作业宽度），因为权重定义错会直接导致分区比例错：如果只按速度分，作业宽度不同的机器人会得到错误面积。area_stats 的返回是最常用的负载均衡观测：标准 Voronoi 下若两台同能力机器人面积差超过 20%，通常意味着它们的初始位置扎堆（都靠在一侧），这正是启动前 Lloyd 迭代要解决的问题。

片段 2：Lloyd 迭代改善分区形态

def lloyd_step(robot_xy, weights, area_mask, res=0.5, iters=5):
    """Lloyd 迭代：机器人向自己分区质心移动，分区逐渐紧凑均衡。"""
    pos = [np.array(p, dtype=float) for p in robot_xy]
    ys, xs = np.nonzero(area_mask)
    owner = None
    for _ in range(iters):
        owner = weighted_voronoi(area_mask, pos, weights, res)
        new_pos = []
        for i in range(len(pos)):
            sel = owner[ys, xs] == i
            if not sel.any():
                new_pos.append(pos[i])                   # 空分区：原地不动
                continue
            # 分区质心：格坐标平均（物理坐标）
            new_pos.append(np.array([xs[sel].mean(), ys[sel].mean()]) * res)
        shift = sum(np.linalg.norm(n - p) for n, p in zip(new_pos, pos))
        pos = new_pos
        if shift / len(pos) < 0.05:                      # 平均移动不足 5 cm
            break                                        # 已收敛
    return pos, owner

解读：Lloyd 迭代的每一步都很朴素，算质心、移过去、重新分区，但它收敛后的分区在"紧凑度"意义上是最优的（这是构造性几何里的经典结果）。工程上有三处细节：空分区保护（某台机器人被完全挤出时保持原位，否则质心计算会除零）；收敛判据按平均移动距离（5 cm 门槛在 0.5 m 网格下合理；太大浪费迭代，太小意义不大）；迭代次数上限 5 次（前 2–3 次贡献最大，之后收益递减，而每次迭代都意味着机器人要重新跑位）。注意这段代码在"任务开始前"执行：迭代过程中机器人实际移动到 pos 的新位置，到位后才开始覆盖，把几何会话与物理移动分开记账，避免"边迭代边干活"的两头不讨好。

片段 3：失联接管（就近划分 + 滞回）

def reassign_orphans(partitions, centroids, last_seen, now, timeout=10.0):
    """失联 ≥ timeout 才接管；失联者的格按几何最近在线机器人划分。"""
    active = [r for r in partitions
              if now - last_seen.get(r, -1e9) < timeout]
    missing = [r for r in partitions if r not in active]
    if not missing:
        return partitions, False                     # 全员在线：分区不动
    for m in missing:
        for cell in partitions.pop(m):               # 取出失联者的每一格
            nearest = min(active, key=lambda r:
                          (cell[0] - centroids[r][0]) ** 2 +
                          (cell[1] - centroids[r][1]) ** 2)
            partitions[nearest].append(cell)         # 就近划给在线机器人
    return partitions, True

解读：接管逻辑坚持两个原则。(1) 只有"确实失联"才重划：timeout = 10 s 的滞回把网络抖动与真故障分开；如果没有这层过滤，一次 3 s 的丢包就会触发分区震荡，机器人跑向新分区、原队友回来又跑回去。(2) 就近划分、不改全局：全局 Voronoi 重算会让所有分区边界同时移动（所有机器人要重新跑位），而"把失联者的格子按最近在线者分配"只影响失联区域周边，扰动最小，与 042 章"队形变换用局部调整优于全队重算"是同一条思路。返回的布尔值表示是否发生重划，调用方据此发布新版本、重置相关统计；失联者回来后按其本地记录继续（只覆盖仍属于它的格子），避免争吵。

常见坑

  • 分区形状奇异（飞地/长条）：机器人在两块分离的小区之间来回跑，转场时间超过作业时间。修复：Lloyd 迭代压紧形状 + 分区后检查每块的"周长/面积比"阈值，超标时合并小块。
  • 分区不按能力加权：快慢机器人拿到同样面积，慢的先累垮、快的早完工。修复：w 取能力乘积；完成后用"工时方差"指标复核，只看面积是否相等会看走眼。
  • 边界漏覆盖：定位误差让两台机器人都"差一点没扫到"边界线。修复：边界保险带（0.1 m 重叠）+ 抽样验收（0.1 m 网格抽查漏点）；重叠预算从完成时间里扣除。
  • 进度口径不一致：各机器人对"已覆盖"的定义不同（格心过车 vs 格内任意点），汇总后总进度虚高。修复：统一规定"格被处理"的判据（作业中心进入格内且停留时间达标）并写进协议文档。
  • 失联接管无滞回或抢回逻辑缺失：频繁重划或者旧机器人回来后"夺回"分区引发二次震荡。修复：10 s 滞回 + "不抢回已转出的格"的确认规则；接管与归还都广播版本号。

练习与思考

  1. 30 m × 20 m 区域、两台机器人（作业宽度 0.5 m 与 0.6 m、速度相同）。按能力加权计算各自应分到的条带宽度与面积；若忽略作业宽度按面积均分，重叠或漏覆盖会出现在哪里？★
    提示
    权重比 0.5:0.6，面积约 273:327 m²。按数量均分时宽作业机器人要来回补窄作业者的欠账，边界处必然出现重叠或漏缝。
  2. 用三台机器人做一次 Lloyd 仿真：初始位置都挤在区域一角，观察 1/3/5/10 次迭代后分区面积方差与形状变化；解释为什么迭代 5 次之后收益变小。★★
    提示
    前两次迭代修正大失衡，之后边界微调；用分区面积方差与质心间距两个曲线展示收敛。10 次以后移动距离已小于网格精度，继续迭代无意义。
  3. 设计"漏覆盖 0 + 重叠 ≤ 15%"的边界策略：计算保险带宽度与重叠率的定量关系（作业宽度 0.6 m、定位误差 ±5 cm），给出可验证的实验方案。★★
    提示
    重叠 ≈ 保险带宽 × 边界线长度 / 总面积；0.1 m 保险带在网格边界上造成的重叠约 5–10%。实验：随机起点跑 10 次，统计漏点与重叠率分布。
  4. 把失联滞回从 10 s 改为 3 s 与 60 s，预测：分区震荡次数、失联期间的漏覆盖风险、恢复后的重划成本如何变化；给出选滞回值的量化方法。★★★
    提示
    3 s：抖动重划频繁；60 s：漏覆盖窗口长。选值依据 = 链路丢包时长分布 P99 的 2–3 倍，并统计"重划次数/任务时长"。
  5. 比较 Voronoi 与细粒度任务田两种方案在"30% 区域为不规则障碍"场景下的表现：给出你选择方案的判据、待测指标与预期结论（提示：重点比较转场次数与通信量）。★★★
    提示
    Voronoi 在异形区域会产生飞地与长条，转场多但通信省；任务田适应形状但认领消息多、路径碎。判据 = 转场时间占比 + 认领带宽；结论通常按"障碍密度"分档选择。

小结

  • 覆盖看四指标：完成时间、总路程、重叠率、工作量方差；先定红线（漏覆盖 0、重叠 ≤ 15%），再优化其余。
  • 分区三方法：条带最规整、任务田最灵活、Voronoi 最分布式；加权 Voronoi 的权重必须反映能力（速度 × 作业宽度）。
  • Lloyd 迭代让分区紧凑均衡，适合"轮次制"覆盖；迭代 3–5 次后收益递减。
  • 进度 1 Hz 上报、完成三条件合议；失联 10 s 滞回触发就近接管，回来后不抢回已转出的分区。
  • 覆盖的通信开销极小（< 1 kB/s/台），复杂度都在路径执行层，下一章协同覆盖路径规划走进分区内部：怎么用最短路径把每一块都"犁"一遍。
