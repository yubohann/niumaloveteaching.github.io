第三篇 · 协同控制与任务协同

第 052 章：多机器人协同搜索

地图已知、目标未知：用概率地图表达"目标在哪"，用检测模型处理"没看见"的信息，让多台机器人互斥地搜索期望发现概率最高的区域。

  • 主题：任务协同 / 概率搜索
  • 关键机制：贝叶斯信念更新、检测模型、期望发现概率、稀疏增量共享
  • 预计学时：60 分钟
  • 前置章节：第 051 章

学习目标

  • 区分"探索"与"搜索"两类任务：前者减少地图不确定性，后者减少目标位置的不确定性。
  • 掌握贝叶斯信念更新的推导：扫过未发现如何改变后验，以及"没看见"为什么也是有价值的信息。
  • 会设计检测模型（距离/角度相关的发现概率），并解释它如何决定搜索路径的选择。
  • 能实现多机器人互斥的期望发现概率评估，避免重复搜索同一片已排除区域。
  • 会设计稀疏增量更新协议和终止判据，并识别动态目标场景下静态假设的失效。

背景与动机

050/051 章让队伍把地图建出来了，但地图只是舞台：真正的任务常常是"在已知场地里找到一个东西"，寻找失联的设备、泄漏源、走失的人员、遗落的包裹。这类问题叫搜索，它的数学核心是信念（belief）：目标位置的先验分布逐次叠加"看了却没看到"的证据，覆盖只是收集证据的手段。目标不在固定位置也没关系，只要它慢到可以用静态近似处理；真正会动的目标交给 054 章的跟踪。

多机器人搜索的协同价值和探索一样直白：同一片信念地图，N 台机器人并行排除区域，排除速度近似 N 倍。但重复搜索的浪费也更刺眼，两台机器人先后搜同一走廊，等于把 N 倍的并行优势白白扣掉一半。本章对"谁搜哪里"采用效用层面的互斥，兼顾效率与灵活；硬性分区留作更严格需求下的备选（061 章）。

核心原理

1. 信念地图与贝叶斯更新

把搜索区域栅格化（0.5 m 分辨率起步），每格保存"目标位于该格的概率" b(x)，初始先验来自任务信息（例如"最后出现在走廊东侧"，对应东侧概率更高；没有信息则均匀分布）。机器人带着传感器扫过一片区域却什么都没发现时，按贝叶斯法则更新：

b'(x) = b(x)·Pmiss(x) / Σu b(u)·Pmiss(u) Pmiss = 1 − Pd（漏检概率，随距离增大）；分母归一化让概率质量流向未搜索区域

公式的一个关键含义："没看见"是强证据。如果某格在视野内且漏检率只有 0.2，那么一次未发现就把它的概率乘以 0.2，几次扫过之后，哪怕先验很高也会被压到接近零。这正是搜索收敛的机制：靠反复排除让概率逐步归零，收敛过程不依赖某一次"找到"。反过来，从未被目光扫过的格子概率不动，随着其他格被排除，它的归一化概率不断上升。搜索的完整图景因此是：已搜索区的概率持续流向未搜索区，直到整个地图的剩余质量低到可以宣布"这里没有"。

2. 检测模型：视野与距离的物理限制

Pd 是传感器"看得到"的概率，建模三件事：视野（FOV 角度与距离上限之外 Pd = 0）、距离衰减（远一点分辨率与对比度下降，常用指数或分段模型）、遮挡（视线被墙挡住时 Pd = 0，需用射线投射判定）。工程上常用一条足够好的近似：

Pd(d) = e−d/λ（d ≤ dmax） λ ≈ 2 m、dmax ≈ 3–5 m 时，1 m 处发现概率约 0.6，3 m 处约 0.22，目标"看得到"的半径比"看得清"大得多，但不可靠

检测模型直接决定搜索路径的形态：Pd 衰减快，机器人会倾向于"多绕弯、近距离深耕"；衰减慢，则"长直线扫过"更划算。这也是为什么搜索参数必须与传感器一起标定，用一次"目标放已知位置、多距离实测发现率"的实验就能拟合 λ，比抄一个默认值可靠得多。

3. 期望发现概率与路径选择

给定信念地图与检测模型，一条候选路径的价值是沿途采样点的期望发现概率之和：

V(path) = Σk b(xk)·Pd(xk, zk) xk 为路径采样点、zk 为该点的传感器覆盖范围；此处取和累加，来自"希望最早发现"的期望收益逼近

全空间最优是带覆盖收益的旅行商问题（NP 难），工程上用"贪心 + 滚动"：从当前位置出发，枚举若干候选方向（例如 12 个方位 × 3 m 前瞻），各积分一小段的价值，走价值最高的方向，每 5 s 重评估。信念更新会让"刚走过的地方"价值骤降，行为上自然表现为向前推进、避免原地打转。

4. 互斥协同：把"重复"从路径层消灭

多机器人搜索的最优分工不一定是几何分区。更轻的做法是在效用层面互斥：每台机器人在计算 V(path) 时，把已被队友（且距离更近）认领覆盖的格子的概率乘以一个很小的残余权重（0.1），相当于"我去搜也不是完全没用，但价值很低"。收益是全球性的：不用维护复杂的分区边界，队友离线后其认领自然衰减，整个数值场保持连续，这与 050 章认领协议是同一套底层机制，只是作用对象从 frontier 变成了信念格。若场景要求严格的"不重复"（例如搜索资源有限、重复当前任务的成本必须为零），再叠加 061 章的 Voronoi 硬分区。

5. 更新共享与终止判据

信念更新本身要共享：如果 A 扫过走廊却不同步"未发现"，B 会认为走廊的概率没变、重复去搜。共享的形态是稀疏增量：只发布状态变化超过阈值的格子（坐标 + 新概率），1 Hz。由于未发现更新会压低整片区域的概率，一次扫过通常产生几十到几百个格子的更新，压成消息后不到 2 kB，比地图增量还便宜。

终止判据应写成双条件，不能采用"某格概率为 1"这种错误目标：(a) 全图最大单格概率低于阈值（例如 0.02），目标大概率不在此区域；(b) 已搜索面积占比超过 98%，物理上已经搜遍。两条同时成立才能宣布"未发现"。只满足 (a) 可能是假阴性（目标藏在遮挡区），只满足 (b) 可能是漏检残留（概率还没收敛）。

6. 数值算例：一次未发现更新的完整计算

用一个只有两格的玩具地图走一遍贝叶斯更新，再看真实模型下的衰减速度。设先验 b = (0.5, 0.5)，机器人扫过第 1 格、该格漏检概率 Pmiss = 0.2：更新后未归一化的概率为 (0.5 × 0.2, 0.5) = (0.1, 0.5)，归一化后为 (0.167, 0.833)。概率质量从"已扫格"流向"未扫格"，两格之和始终保持 1，这是"搜索收敛靠排除"的最简演示。

把检测模型代进实际参数（λ = 2 m、Pd = e−d/λ）：1 m 处发现概率 0.607、2 m 处 0.368、3 m 处 0.223、5 m 处 0.082。作为对照，代码片段里的漏检概率 p_miss = 0.4 + 0.6·(1 − e−d/λ)：距离 0 处 0.40、2 m 处 0.779、3 m 处 0.866。两组数字一起读："扫过"不等于"看清"，3 m 外一次扫过的排除力只有 13%，1 m 内是 60%，这解释了为什么检测模型标定错误会让搜索策略从"深耕"变成"滑过"。

重复扫过的衰减：某格先验 0.3、单次漏检 0.5 时，两次未发现降到 0.3 × 0.5² = 0.075，三次降到 0.0375；要把概率压到 0.002（约为初始值的 1/150），需要 7.2 次、取整 8 次扫过。这个数字的工程含义是"排除深度与扫过次数成对数关系"：想更快排除，就要提高单次 Pd（靠近、正对、慢速通过）；单纯增加扫描次数收效慢。

路径价值的量纲再核对一遍：V = Σ b·Pd 中 b 与 Pd 都是概率，乘积无量纲；12 个候选方向各取 4 个采样点，一次比较的浮点运算量在几十次，5 s 重评估的算力占比可以忽略。真正的开销在信念地图的可见性计算（射线投射），所以实现里把它缓存到"每 2 帧重算一次"。

终止判据的数量级也要有物理直觉：max b 低于 0.02 意味着"最可疑的格子也只有 2% 概率"；对 400 m²、按 0.25 m² 一格共 1600 格的区域，剩余总概率质量约 0.02 × 1600 = 32 格当量，若这些质量集中在遮挡区，就对应"还有一块没看清的地方"。所以第二条件（搜索面积 98%）与遮挡区的复检必须一起读，单看 2% 会漏掉"概率分散在多个死角"的假收敛。

认领残余权重 0.1 的效果也能看到数字：两台机器人同时评估同一片区域时，后到者的路径价值被压到原来的 10%。若一次扫过该区域的期望发现价值是 0.05，队友认领后对后到者只剩 0.005，低于其余候选（典型 0.01–0.07）的竞争线，转向就是自动发生的；若机械地把残余设为 0，边界两侧的价值会因归一化出现不连续跳变，两台机器人在认领边界上左右横跳。0.1 这个值不需要精确，重要的是"足够小以让位、足够大以连续"。把残余权重与终止阈值一起纳入参数扫描：同一场景跑 20 次，记录发现时间与方向反转次数，选两者都优的档位。扫描成本很低，单机仿真跑一轮 400 m² 场景只需分钟级，建议在实机验收之前完成，扫描记录一并留档备查。

实现思路与设计

  1. 信念地图：0.5 m 分辨率（100 m × 100 m 时 200 × 200 格，float32 约 160 kB，广播全图也不贵，但按稀疏增量发）；初始先验支持"均匀分布"与"热点先验"两种配置。
  2. 观测管线：机器人把当前视野内的格子（射线投射得到的可见格）作"未发现"处理；可见区域计算可缓存（每 2 帧重算一次即可）。
  3. 覆盖收益计算：路径价值用局部窗口积分（前缀和加速）；候选方向 12 个 × 前瞻 3 m，按 5 s 周期重评估。
  4. 互斥与共享：覆盖声明（机器人 + 覆盖中心 + 半径 + 时间戳）走 /fleet/search_claims（2 Hz）；信念增量走 /fleet/belief_delta（1 Hz，稀疏格式）。
  5. 发现处理：检测置信度超过阈值即暂停搜索并进入"确认"流程（就近复看 + 上报）；误报率要求高时进入 053 章的双确认机制。
  6. 验收：3 台机器人、室内 400 m²、单目标随机位置 100 次试验：平均发现时间相对单机基线缩短 55% 以上；重复覆盖面积占比小于 25%；假阴性率（搜完未发现而目标确实在场）小于 5%。

关键代码与解读

片段 1：贝叶斯信念更新

import numpy as np

def bayes_update(belief, robot_xy, res=0.5, fov=3.0, lam=2.0, p_miss0=0.4):
    """扫过视场未发现目标：按漏检概率压低对应的信念格并归一化。"""
    ys, xs = np.indices(belief.shape)
    cx, cy = robot_xy[0] / res, robot_xy[1] / res
    dist = np.hypot(xs - cx, ys - cy) * res          # 距机器人的物理距离
    p_miss = p_miss0 + (1.0 - p_miss0) * (1.0 - np.exp(-dist / lam))
    p_miss = np.clip(p_miss, p_miss0, 0.99)          # 近处最乐观也不会全信
    in_view = dist <= fov                            # 简化视场（工程加射线遮挡）
    belief[in_view] *= p_miss[in_view]               # 未发现：乘漏检概率
    total = belief.sum()
    if total > 0:
        belief /= total                              # 归一化：质量流向未搜区
    return belief

解读：三处设计意图值得圈出。(1) 漏检概率随距离上升且被夹紧在 p_miss0 = 0.4 之上，即使目标就在脚边，"没看到"也不能视为全信，否则一次传感器故障就能把地面概率清成零，再也无法回头。(2) 归一化是全局的：只压低搜索区而不重新分配，会让"未搜索区"的相对概率自动升高，这正是概率质量流动的机制。(3) 工程实现里 in_view 必须用射线投射做遮挡判断，否则机器人会把墙后的区域也当作"看过"，几轮之后地图上出现大片虚假的"已排除"，这是搜索结果"看起来收敛了但目标就在墙后"的经典事故。

片段 2：互斥的期望发现概率

def path_value(path, belief, claims, my_id, res=0.5, p_det=0.6):
    """路径的期望发现概率：沿途信念 x 检测概率；被队友认领处衰减。"""
    value = 0.0
    for (px, py) in path:
        gx, gy = int(px / res), int(py / res)
        if not (0 <= gx < belief.shape[1] and 0 <= gy < belief.shape[0]):
            continue                                  # 越界采样点直接跳过
        b = float(belief[gy, gx])
        owner = claims.get((gx, gy))                  # 该格由谁认领覆盖
        if owner is not None and owner != my_id:
            b *= 0.1                                  # 队友更近：残余价值 10%
        value += b * p_det
    return value

def choose_direction(robot_xy, heading, belief, claims, my_id, n=12, step=3.0):
    """枚举候选方向，各积分一小段路径价值，返回最优朝向。（示意）"""
    best_angle, best_val = heading, -1.0
    for i in range(n):
        ang = heading + (i - n / 2) * (2.0 * np.pi / n) / (n / 4)
        path = [(robot_xy[0] + step * k / 3 * np.cos(ang),
                 robot_xy[1] + step * k / 3 * np.sin(ang)) for k in range(4)]
        v = path_value(path, belief, claims, my_id)
        if v > best_val:
            best_angle, best_val = ang, v
    return best_angle

解读：path_value 是"贪心搜索"的打分函数，两点设计：认领残余取 0.1 的小值，让数值场保持连续（严格置零时，两台机器人在认领边界两侧会来回跳变）；越界采样直接跳过，路径规划器给出的前瞻点可能落到地图外一两个格，这属于常态。choose_direction 的候选方向取"当前朝向附近约 ±60°"的前方扇区：搜索场景里前进方向的连贯性本身就是价值（减少转向损耗），收窄候选范围让行为更稳。工程版本会用前缀和把 path_value 的逐格循环向量化，当前写法直观，适合先把逻辑跑对。

片段 3：信念的稀疏增量共享

def encode_delta(belief, last_sent, thresh=1e-4):
    """把相对上次发送的变化编码为稀疏更新：(x, y, 新概率) 列表。"""
    diff = np.abs(belief - last_sent)
    ys, xs = np.where(diff > thresh)
    return [(int(x), int(y), float(belief[y, x]))
            for x, y in zip(xs, ys)]

def apply_delta(belief, delta):
    """应用队友的增量：直接写入并整体归一化，保持全局一致。"""
    for x, y, p in delta:
        belief[y, x] = max(p, 1e-9)                   # 概率非负
    total = belief.sum()
    if total > 0:
        belief /= total
    return belief

解读：为什么按"变化量"发送？按 200 × 200 的 float32 地图算，全图约 160 kB，1 Hz 广播给 N−1 台邻居，10 台时就是 1.4 MB/s 量级，而实际情况中一次扫过只改变视野内的几十到几百格，稀疏增量不到 2 kB。阈值 1e-4 的作用是过滤归一化带来的全局微变：归一化会让每一格都变一点点，如果没有阈值，每帧产生的"变化格"等于全图，很多实现在这里栽过跟头。应用端直接覆盖：发送方的概率（在它本地）已经包含了自己收到的所有证据；叠加需要额外的版本信息来判断"哪些证据已计入"，覆盖式协议更简单、也够用。

常见坑

  • 归一化数值下溢：连续几百次更新后概率小到浮点精度以下，除以总和出现 0/0 或全零。修复：对数域（log-probability）更新，或定期重新归一化 + 概率下限钳制。
  • 不共享"未发现"事件：B 不知道 A 搜过的区域已被排除，重复搜索。修复：信念增量以 1 Hz 共享；哪怕只共享"覆盖圆"（中心 + 半径）也比什么都不发强。
  • 遮挡判断缺失：墙后区域被误判为"已搜索"，概率被压到零。修复：射线投射判定可见性；把遮挡区从更新中排除，这是本类系统里杀伤力最大的一个 bug。
  • 终止条件只看归一化后的概率：归一化后总和恒为 1，永远不满足"收敛"。修复：看绝对量，全图最大单格概率、搜索覆盖面积占比、剩余未搜索概率质量，三者组合。
  • 目标其实在动：静态假设下连续漏检把"目标去过的地方"概率压没，而目标已经走到别处。修复：发现"多次复搜仍无果 + 搜索时间超过阈值"时切换假设（增大过程噪声、重设先验），或交 054 章的跟踪模块处理。

练习与思考

  1. 某格先验概率 b = 0.3，检测模型在该距离下 Pd = 0.5。连续两次扫过均未发现，该格后验是多少（忽略其他格更新与归一化）？三次呢？说明这一衰减速度对搜索效率的意义。★
    提示
    0.3 × 0.5 × 0.5 = 0.075；三次 0.0375。指数衰减意味着 3–4 次未发现即可基本排除，这正是"搜索收敛"的量化形态。
  2. 把检测模型的 λ 从 2 m 改为 1 m 与 5 m，预测搜索路径的形状变化与平均发现时间；给出一个用仿真标定 λ 的实验方案（目标位置已知、多次测量发现率）。★★
    提示
    λ 小：近距离耕织式搜索，路径弯曲；λ 大：长直线扫掠。标定实验固定目标于 0.5/1/2/3/5 m 距离各测 50 次，拟合 Pd(d)。
  3. 设计一个"团队失误"场景：两台机器人因认领消息丢失而重复搜索同一大片区域，量化重复造成的发现时间损失；提出两种修复（更高频认领、覆盖圆冗余共享）并比较代价。★★
    提示
    重复 = 一台机器人的搜索效能被浪费，发现时间约退化到单机水平。修复一：认领 2 Hz 变 5 Hz（带宽 ×2.5）；修复二：覆盖圆比格列表小，冗余发包（带宽 ×2）。
  4. 把终止阈值从"max b < 0.02"改为 0.2 与 0.002，预测假阴性率与搜索时间的变化；设计一个能测出"覆盖 98% 但仍有 2% 遮挡盲区"的对照实验。★★★
    提示
    0.2：提前收工、假阴性高；0.002：过度搜索、时间超支。对照组在地图里专门放置 1–2 个遮挡死角，检查终止时目标的实际后验。
  5. 为动态目标写"搜索转跟踪"的切换方案：触发条件（连续 N 次复搜无果、收到目击报告）、切换动作（先验重建、请求 054 章跟踪模块接管）、以及无法跟踪时回退搜索的路径。★★★
    提示
    目击报告把先验重构为"最后目击点附近的高斯"；切换时发布全队公告避免一半在搜一半在追；回退条件用"跟踪丢失超过 60 s"。

小结

  • 搜索的数学对象是信念地图：贝叶斯更新让"未发现"成为强证据，概率质量持续流向未搜索区。
  • 检测模型 Pd(d) 决定搜索形态，必须实测标定；遮挡判断缺失是最危险的一类 bug。
  • 路径价值 V = Σ b·Pd，用"贪心 + 5 s 重评估"滚动求解；认领残余权重实现效用级互斥。
  • 信念增量稀疏共享（1 Hz、几 kB），阈值过滤归一化噪声；不发增量就会重复搜索。
  • 终止是双条件：最大单格概率 + 覆盖占比；下一章把搜索与救援执行拼在一起，协同搜索与救援，目标价值还会随时间衰减。
