第三篇 · 协同控制与任务协同

第 042 章：领航-跟随者编队

用一个"领航者"带三台"跟随者"：把编队几何写成机体系偏移，用前馈加反馈的控制律让每台机器人收敛到自己的位置，并弄清误差为什么会在队尾被放大。

  • 主题：协同控制 / 编队架构
  • 关键机制：位姿广播、领航者机体系偏移、前馈 + 比例反馈、失联降级
  • 预计学时：55 分钟
  • 前置章节：第 041 章

学习目标

  • 理解领航-跟随（leader-follower）编队的通信结构，说清它与虚拟结构、行为法各自的代价与适用场景。
  • 掌握两种编队几何描述，机体系直角偏移与距离-方位（l-φ），并能互相换算。
  • 会推导"前馈 + 比例反馈"控制律，解释纯反馈跟踪恒速领航者为什么必然留下稳态误差。
  • 能独立配置跟随者节点的话题、QoS、增益与失联保护参数，并说清每个参数的取值依据。
  • 能诊断链式拓扑"队尾摆动"问题，给出改拓扑、加阻尼或加前馈补偿的修复方案。

背景与动机

第 041 章建立了编队控制的一般图景：让多台机器人维持某个相对位形。落到工程上，第一个必须回答的问题是"队形信息怎么流动"。领航-跟随是最省通信、最容易实现的一档：只有领航者对外广播位姿与速度，每台跟随者独立解算自己的期望位置，不需要任意两台机器人两两通信，也不需要全局坐标系下的统一解算器。

代价同样明确：队形精度依赖领航者，队形误差沿跟随链逐级放大，领航者一旦失联全队失去参照。把这套架构写对、调稳，是后面编队变换（043）、编队避障（045）、协同搬运（056–058）的共同地基，那些任务里，"保持相对位形"永远是底层必备能力。

核心原理

1. 通信结构：一张有向图

领航-跟随编队在通信上就是一张有向图：每个跟随者有一条指向"它参照谁"的边。常见三种拓扑：星形（所有跟随者直接参照领航者，边的数量 N−1）、链式（每台参照自己的前车，形成一条蛇），以及两者的混合。星形对单条链路的丢包不敏感，丢的是某一台自己的参照，不影响别人；链式省了跟随者与领航者的长距离链路，但误差会一级一级传下去，队尾最不稳定。

2. 编队几何：为什么偏移定义在领航者机体系

跟随者的期望位置由领航者位姿与一个固定偏移共同决定。偏移定义在领航者机体坐标系（x 朝前、y 朝左），世界系下的量由它旋转导出：

pi,d = pL + R(ψL) · [dx,i, dy,i]T R(ψ) 为绕 z 轴的旋转矩阵；d 在机体系固定，队形随领航者航向整体转动

这样定义的好处有三点：领航者转向时队形自动跟着转，不需要重算偏移；偏移量是"物理尺寸"，可以直接对照机器人的外形（间距 1.5 m 就是真 1.5 m）；系统对全局坐标的漂移不敏感。直角偏移与前文提到的 l-φ 描述可以互换：li = √(dx² + dy²)，φi = atan2(dy, dx)。直角偏移适合布置固定队形，l-φ 适合把控制律直接作用在"测得的距离与方位"上。

3. 前馈 + 反馈：跟踪移动目标的必修项

设跟随者当前位置为 pi，位置误差 ei = pi,d − pi。如果只用比例控制令速度指令 vi = Kp ei，当领航者以恒速 vL 前进时，稳态下跟随者必然与领航者同速，由 vi = vL = Kp ei 可得稳态误差：

ess = vL / Kp vL = 0.5 m/s、Kp = 1.0 s⁻¹ 时，距离误差高达 0.5 m，队形已经散了一半

结论：纯比例反馈对恒速目标是"一阶滞后系统"，误差与速度成正比、与增益成反比。要么把 Kp 调到很大（带来抖动与执行器负担），要么把领航者速度作为前馈直接加进指令：

vi = vL + Kp · ei 前馈项让稳态误差趋近于 0，比例项只负责修正初始偏差与扰动

这是控制工程里"模型已知量直接前馈、未知量靠反馈"的通用思路：领航者速度它自己知道，广播过来直接用，比让跟随者用微分去"猜"更准、更平滑。

4. 误差传递：链式拓扑的队尾放大

链式拓扑下，第 i 台跟踪的是第 i−1 台的"实际输出"，而这输出本身带着上一级的跟踪误差。把每级的误差传递看成低通环节，一旦某级在某个频率上放大系数大于 1，扰动就会沿链放大，表现为领航者一个速度阶跃，队尾机器人先滞后、再超调、来回摆动。这就是串稳定性（string stability）问题。缓解手段按优先级排列：把拓扑改成星形（从结构上消除传递链）；增大阻尼项抑制高频放大；缩短链长；给每台补上领航者速度前馈（第一级不再产生滞后，后级就不会被逐级放大）。

5. 时效性：时间戳比内容更重要

跟随者拿到的是"过去的领航者"。无线网络端到端时延 20–50 ms，30 Hz 广播下还会丢帧。控制环使用前必须做两件事：检查消息年龄（本地时钟减去消息时间戳），必要时按领航者速度做短时外推（外推窗口控制在 100 ms 内，否则噪声被放大）；消息年龄超阈值就进入降级状态。这要求全队时钟先对齐（第 009 章），否则"年龄"算出来是错的。

6. 数值算例：稳态误差、时延偏差与链式累加

先看纯比例反馈的稳态误差表（ess = vL/Kp）：

领航者速度 vL增益 Kp稳态距离误差现象
0.5 m/s1.0 s⁻¹0.50 m队形缩水三分之一，肉眼可见
0.6 m/s1.5 s⁻¹0.40 m大于验收线 0.15 m 的两倍
0.6 m/s2.0 s⁻¹0.30 m增益翻倍只把误差减半，收效递减
0.8 m/s2.0 s⁻¹0.40 m速度越高误差越大，与增益无关

读表结论：把增益从 1.0 加倍到 2.0 只能把误差从 0.6 m 压到 0.3 m，永远消不掉；前馈才是正解。加前馈后，恒速段的稳态误差归零，剩下来自时延的偏差：设领航者以 a = 0.5 m/s² 加速、前馈消息延迟 δ = 40 ms，误差动态近似为 ė = vL(t − δ) − vL(t) − Kp·e ≈ −a·δ − Kp·e，稳态偏差：

eδ = a·δ / Kp = 0.5 × 0.04 / 2.0 = 0.01 m 只在加速段出现，恒速段归零；这就是"前馈 + 保守增益"的误差预算算法

1 cm 的加速段偏差与 0.15 m 的验收线之间还有大量余量，说明前馈方案的瓶颈已经转移到定位精度（第 029 章），控制律本身不再是限制。再把单级数字放进链式拓扑做累加：每级跟随者在速度阶跃下残留约 0.3 m 的跟随滞后（0.6 m/s ÷ 2.0 s⁻¹），三台跟随者串成链后，队尾相对领航者的累积滞后约 (N−1) × 0.3 = 0.9 m，队形长度被拉长近一米；换成星形拓扑后每台都直接参照领航者，误差不再累加。这条算式解释了为什么同一套增益参数在链式下"看着能跑、精度崩坏"，选型阶段先用它估一遍再动手调参。

边界与失效：Kp 超过约 4 s⁻¹ 时，20 Hz 采样周期（50 ms）与广播链路的相位滞后一起把闭环推向等幅振荡，表现为机器人围绕目标点小幅高频抖动；Kp 低于 0.5 s⁻¹ 时，跟随者像"松弛的橡皮筋"，起步滞后好几秒、减速段又冲过头。两个方向都要用速度阶跃实验标定，落点取"出现明显振荡的增益的 60–70%"，这与第 041 章先保守后上调的结论一致。

还有一个容易在集成阶段才暴露的细节：倒车限制。跟随者位于领航者正后方时，前馈加反馈的距离修正可能给出负速度指令，若底盘允许倒车且限幅失效，机器人在队形里会反复前进后退。设置倒车速度上限（示例 0.2 m/s，见参数文件中的 v_back）并加一条"零指令附近无自激"的验收测试，可以提前拦住这个问题。

7. 数值算例：转弯时谁先跟不上

把三台跟随者的偏移放进定圆转弯的几何里，可以直接算出各自的"路程倍率"。领航者以半径 R 做定圆运动时，机体系偏移为 (dx, dy) 的刚性点走过的路径半径是 √((R − dy)² + dx²)：左后成员靠近圆心、路径更短，右后成员在圆外、路径更长。取 R = 3 m、vL = 0.8 m/s，对本章的三台跟随者逐一计算：

跟随者位置偏移 (dx, dy)路径半径路程倍率需求速度
正后方(−1.5, 0)3.354 m1.1180.894 m/s
左后（转弯内侧）(−2.6, 1.3)3.106 m1.0350.828 m/s
右后（转弯外侧）(−2.6, −1.3)5.025 m1.6751.340 m/s

表里 1.34 m/s 的需求速度已经超过速度上限 0.8 m/s，说明 3 m 半径左转时右侧跟随者物理上无法保持队形，它会持续落后、把队形拖成弧形。正确的处置有两条：放大转弯半径，R 从 3 m 增到 8 m 时路程倍率降到 1.207，需求速度 0.966 m/s 仍偏高；按最外侧成员限速，转弯段把领航者速度压到 vmax × R / ρmax = 0.8 × 3 / 5.025 ≈ 0.48 m/s，转向结束后再恢复。工程实现上，把这条限速做成"根据队形宽度与转弯半径自动计算"的规则写进规划层，比在调参阶段逐个跟随者改增益可靠得多。

实现思路与设计

按六步落地一个 4 台机器人（1 领航 + 3 跟随）的编队系统：

  1. 定拓扑：我们的场景选星形（全部直跟领航者），通道窄、链长短，精度优先；若覆盖距离远、无线电支撑不了全网直连，再退化为链式并加强阻尼。
  2. 定接口：领航者发布 /robot1/pose（PoseStamped，30 Hz）与 /robot1/cmd_vel（Twist，即它的速度指令，作为前馈）；每台机器人发布自己的 odom_pose（50 Hz）。位姿类消息用 Best-effort：多机器人系统里"最新比完整更重要"，丢一帧下一帧马上补上。
  3. 定编队几何：偏移表放参数文件。三台跟随者分别位于领航者正后 1.5 m、左后 2.6 m 偏左 1.3 m、右后 2.6 m 偏右 1.3 m，队形呈"箭头"状，前后间距大于机器人对角线尺寸（约 0.6 m）的两倍，留足控制余量。
  4. 控制器：位置误差做比例项，领航者速度做前馈，航向对齐领航者；线速度上限 0.8 m/s，角速度上限 1.5 rad/s，控制环 20 Hz（跟车位姿广播 30 Hz 匹配，避免欠采样）。
  5. 失联降级：消息年龄 0.5 s 内全速；0.5–1.5 s 线性降速；超过 1.5 s 停车等待。绝不"用最后位置继续低速跟随"，那等于盲跟。
  6. 验收：直线段稳态位置误差小于 0.15 m；半径 3 m 圆轨迹下队形误差小于 0.25 m；人为断链 2 s 内全队停稳，恢复后 5 s 内重新收敛。

关键代码与解读

片段 1：跟随者控制环

import math
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import Pose2D, Twist

class Follower(Node):
    """跟随者：领航者平面位姿 + 自身位姿 -> 本机速度指令。"""
    def __init__(self):
        super().__init__("follower", namespace="robot2")
        self.declare_parameter("offset_x", -1.5)  # 领航者机体系：x 前、y 左，单位 m
        self.declare_parameter("offset_y", 0.0)
        self.kp = 2.0                             # 位置环增益 1/s
        self.leader, self.me, self.v_lead = None, None, 0.0
        # 编队内部用 Pose2D（x, y, theta）：平面任务无需四元数换算
        self.create_subscription(Pose2D, "/robot1/pose2d", self.on_leader, 10)
        self.create_subscription(Twist, "/robot1/cmd_vel", self.on_vel, 10)
        self.create_subscription(Pose2D, "odom_pose2d", self.on_me, 10)
        self.pub = self.create_publisher(Twist, "cmd_vel", 10)
        self.create_timer(0.05, self.control_loop)  # 20 Hz 控制环

    def on_leader(self, m): self.leader = m
    def on_me(self, m): self.me = m
    def on_vel(self, m): self.v_lead = m.linear.x

    def control_loop(self):
        if self.leader is None or self.me is None:
            return                                # 缺信息时不发指令，保持静止
        psi = self.leader.theta                   # Pose2D 直接给出偏航角
        ox = self.get_parameter("offset_x").value
        oy = self.get_parameter("offset_y").value
        xd = self.leader.x + math.cos(psi) * ox - math.sin(psi) * oy
        yd = self.leader.y + math.sin(psi) * ox + math.cos(psi) * oy
        ex, ey = xd - self.me.x, yd - self.me.y   # 世界系位置误差
        cmd = Twist()
        # 前馈（领航者速度）+ 反馈：没有前馈项，稳态误差正比于 v_lead
        cmd.linear.x = max(-0.2, min(0.8,
                        self.v_lead + self.kp * math.hypot(ex, ey)))
        # 航向误差先 wrap 再进比例项，否则 ±180° 附近会反向打转
        raw = math.atan2(ey, ex) - self.me.theta
        cmd.angular.z = max(-1.5, min(1.5, self.kp * math.atan2(
            math.sin(raw), math.cos(raw))))
        self.pub.publish(cmd)

解读：控制环里最有信息量的是三行。第一，期望位置用领航者航向做旋转：cos/sin 展开的就是 R(ψ)·d，队形随航向整体转动。第二，线速度 = 前馈 + 比例反馈，前馈来自领航者自己的速度指令，这是对"它要去多快"最准确的回答，比任何观测估计都干净。第三，航向误差必须先做角度归一化：把差值折到 (−π, π]，否则机器人位于领航者正后方、角度差跨越 ±180° 边界时会朝反方向打转。另外注意"缺信息不发指令"的早退：编队系统里沉默比乱动安全。编队内部消息用 Pose2D 是因为平面任务不需要四元数，但机器人底层接口若用 PoseStamped，就在桥接节点里做一次换算即可。代码用的是 rclpy 的通用稳定接口（create_subscription、create_publisher、create_timer），Humble/Iron/Jazzy 间的细微差异以对应发行版官方文档为准。

片段 2：前馈滤波与失联分级降速

class SafetyGate:
    """统一把关前馈速度与消息新鲜度：滤波降噪 + 分级降速。"""
    def __init__(self, t_slow=0.5, t_stop=1.5):
        self.t_slow, self.t_stop = t_slow, t_stop
        self.v_filt, self.alpha = 0.0, 0.3    # 一阶低通，20 Hz 下等效约 150 ms

    def smooth(self, v_meas):
        # 领航者速度若来自差分会很吵；滤波避免噪声直接进入执行器
        self.v_filt += self.alpha * (v_meas - self.v_filt)
        return self.v_filt

    def scale(self, age_s):
        if age_s <= self.t_slow:
            return 1.0                        # 新鲜：全速跟随
        if age_s >= self.t_stop:
            return 0.0                        # 过旧：停车，宁可失去队形
        # 中间区：线性降速，避免突变急停造成队尾追尾
        return (self.t_stop - age_s) / (self.t_stop - self.t_slow)

# 控制环中的用法（片段 1 的 control_loop 内）
# age = (now - self.leader.header.stamp) 按同一时间源换算为秒
# v = gate.smooth(self.v_lead); cmd.linear.x *= gate.scale(age)

解读：这段代码回答两个工程问题。其一，为什么前馈也要滤波：若领航者速度来自位姿差分，单帧噪声会直接变成速度毛刺，被前馈放大到全队；一阶低通（系数 0.3 对应约 150 ms 时间常数）用很小的相位代价换来平滑。其二，为什么降速要分两级：0.5 s 门限对应"广播抖动、再等一两帧"，1.5 s 对应"确定失联"。中间线性过渡是为了避免急停引发追尾，编队里减速比停车更难，减速太快队尾还在按旧速度冲上来。工程实践里 20 Hz 控制环、30 Hz 广播的正常年龄约 30–60 ms，把 0.5 s 留给抖动余量是合理量级。

片段 3：编队偏移与增益配置

# formation.yaml：队形与增益全部配置化，改队形不动代码
fleet:
  leader: robot1
  pose_hz: 30                 # 位姿广播频率：与 20 Hz 控制环留出过采样比
  offsets:                    # 单位 m，领航者机体系（x 前、y 左）
    robot2: {x: -1.5, y:  0.0}   # 正后方
    robot3: {x: -2.6, y:  1.3}   # 左后
    robot4: {x: -2.6, y: -1.3}   # 右后
  gains: {kp: 2.0, kd: 0.6}      # 位置环：先调 kp 到 80% 处，再加 kd 压超调
  limits: {v_max: 0.8, w_max: 1.5, v_back: 0.2}
  safety: {t_slow: 0.5, t_stop: 1.5}

解读：把偏移表放进 YAML（源码零硬编码），带来两个能力：换队形（正后 → 斜后）只需要改配置文件；同一份节点程序通过参数注入复用给所有跟随者，符合多机器人"实例化复用"的第一原则。增益注释里写的是调参顺序经验：先把 Kp 加大到接近等幅振荡再回退 20–30%，然后加阻尼压超调，这比背一个"经验数字"更可迁移。

常见坑

  • 角度差没有 wrap：机器人接近航向对齐时突然原地打转或朝反方向绕圈。症状是角速度指令跳变到上限。修复：所有做减法的角度一律过 atan2(sin, cos) 归一化，包括"期望航向 − 当前航向"。
  • 只反馈不前馈：直线跟随看起来"还行"，一加速就落后且误差随速度线性增大。用 ess = vL/Kp 验算：0.6 m/s 配 Kp = 1.5 就是 0.4 m 的稳态缩距。修复：把领航者速度前馈进指令，反馈只修扰动。
  • 链式拓扑误差放大：领航者做速度阶跃，队尾先滞后、再超调摆动，像蛇尾甩动。这是结构性缺陷，调增益只能缓解。修复优先级：星形化 → 加长链前馈补偿 → 增加阻尼。验证方法：对比星形与链式在同一阶跃输入下的队尾误差峰值。
  • 用未标定的里程计速度做前馈：跟随者自己的 odom 速度偏大 10%，外部看不出问题，内部表现为"永远贴着队形内部、与领航者抢位"。修复：前馈只用领航者广播量；本机 odom 只用于位置反馈，并做轮径标定（直线 5 m 往返，误差控制在 2% 以内）。
  • 时钟不一致导致年龄误判：两台机器人的时钟差 0.3 s，安全门限计算全部失真，一台"永远新鲜"、一台"永远过期"。修复：先做时间同步（第 009 章），再依赖时间戳；同步不可用时退化为"接收间隔计时"这种保守近似。

练习与思考

  1. 领航者以 0.6 m/s 直线前进，跟随者只有比例控制且 Kp = 1.5 s⁻¹。计算稳态距离误差；若再加 40 ms 通信时延，误差会变大还是变小？为什么？★
    提示
    ess = 0.6 / 1.5 = 0.4 m。时延使控制"动作迟到"，稳态误差进一步增大（控制器看到的是旧误差）；前馈项不受时延影响的部分让整体误差重新回到小量级。
  2. 把队形偏移从"正后方 1.5 m"改成"左后方（−1.5, 0.8）"。不运行仿真，预测：跟随者相对领航者的轨迹形状如何变化？改为星形拓扑后，第 4 台的队尾摆幅预计如何变化？★
    提示
    斜置偏移在转向时会形成内切/外扩轨迹；星形拓扑下每台的参照都是领航者，没有级联，队尾摆幅按单环特性收敛，不再逐级放大。
  3. 推导：把跟随者简化为 v̇ 与位置误差的一阶模型，写出从领航者速度到位置误差的传递函数；证明加入前馈后稳态误差为 0，并解释时延会给前馈带来什么影响。★★
    提示
    误差动力学 ê = vL − Kpe（稳态 ê = 0 时 e = vL/Kp）；前馈使 ê = −Kpe，稳态 e → 0。时延让前馈滞后一个 δ，产生约 v̇L·δ 的瞬时偏差。
  4. 试验设计：在 Gazebo 里让 4 台机器人跑半径 3 m 的圆轨迹（0.5 m/s），分别测量星形与链式拓扑下的队形误差曲线与队尾超调峰值；把 Kp 从 1.0 调到 4.0，找出振荡开始的增益并解释与采样频率的关系。★★★
    提示
    固定其他参数只动 Kp；当增益对应的闭环带宽接近 20 Hz 控制环的奈奎斯特频率一半时明显起振。记录"增益—超调"表格，这比记住单个数字有用。
  5. 为你的编队设计一套"失联—恢复"流程：定义两个门限、计时器行为、恢复后的重新对齐策略（原地等领航者回来还是前去追赶），并写出对应的状态机或伪代码。★★★
    提示
    状态：FOLLOW → DEGRADED（线性降速）→ HOLD（停车）→ REACQUIRE（限速朝领航者最后位置靠近）→ FOLLOW。注意 REACQUIRE 期间的速度上限要比正常低一半。

小结

  • 领航-跟随的通信结构是一张有向图：星形稳健、链式省链路但误差沿链放大；选择标准是精度优先用星形，覆盖优先再看链式。
  • 编队几何定义在领航者机体系，队形随航向整体旋转；直角偏移 (dx, dy) 与 l-φ 描述可互换。
  • 纯比例反馈对恒速领航者必有稳态误差 vL/Kp；前馈领航者速度是消除它的正解，反馈只负责修扰动。
  • 30 Hz 位姿广播 + 20 Hz 控制环 + 前馈滤波 + 0.5 s/1.5 s 分级失联保护，是一套经过量级验证的起步参数。
  • 下一章把"固定偏移"升级为"队形模板"：编队变换，如何从纵队切成楔形、从楔形切成圆环，还要保证过程中不打架。
