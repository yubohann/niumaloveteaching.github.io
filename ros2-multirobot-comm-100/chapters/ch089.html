第 089 章：多机器人协同决策机制

从"谁来拍板"到"怎么达成一致"：合同网拍卖、迭代共识与确定性打破平局，三种决策机制覆盖离散选择、连续变量与多轮协商，全部不用中心节点。

  • 主题：协同决策机制（分布式决策规则）
  • 关键机制：合同网协议、VCG 直觉、迭代共识、最大共识选举、承诺窗口
  • 预计学时：55 分钟
  • 前置章节：第 088 章

学习目标

  • 按决策变量形态（离散选择 / 连续变量 / 多轮协商）选择决策机制：拍卖、共识、协商各自的适用边界。
  • 掌握合同网协议四步流程（发布 → 投标 → 授标 → 确认），会设计投标内容、决策窗口与超时回退。
  • 理解"第二价格（Vickrey）让诚实出价成为占优策略"的直觉，以及工程上为什么仍要防虚报。
  • 会实现迭代共识与最大共识：权重与步长的收敛条件、有限轮数的近似误差、离散选举的轮数下界（图直径）。
  • 能为决策机制设计"承诺窗口 + 滞回 + 确定性平局打破"，让分布式决策稳定可复现。

背景与动机

第 086 章把机制拆成四要素，其中"决策规则"是最核心的一环：机器人每天要做成千上万个决定，这个任务谁接、充电桩谁先占、搜索区域怎么分、路口谁先过。集中式决策简单（一个节点算完全场最优），但单点、瓶颈、跨网延迟一个不少；完全各自为政又是另一极端（各抢各的，拥堵与冲突）。分布式决策机制要同时做到：无中心、能收敛、结果够好、过程可解释。

本章覆盖三类经过时间考验的机制：拍卖解决"离散资源给谁"（任务、充电桩、通行权）；迭代共识解决"大家一起确定一个连续量"（分工比例、集结中心、队形尺度）；协商/多轮交互解决"一次谈不拢的复杂分配"。它们都能叠在第 087 章的通信协议上：发布用事件通道、出价用请求-应答服务、共识用状态通道反复迭代。

与第 095 章的分工：本章讲"机制怎么运转与实现"，095 讲"机制背后的博弈论（纳什均衡、势博弈、无政府状态代价）"。049 章的路口冲突消解是从控制视角讲具体场景，本章把它抽象成决策机制的设计问题。

核心原理

1. 决策变量三形态，对应三套机制

形态典型问题机制通信轮数
离散选择任务/充电桩/区域分给谁拍卖（合同网）2–3 轮（发布、投标、授标）
连续变量集结中心、搜索权重、队形尺度迭代共识多轮迭代（每轮邻居交换）
复杂组合任务包、联盟形成多轮协商/组合拍卖3+ 轮，可能需要结构化让步

选择标准一句话：能用一次广播加一次应答解决的，别开会；需要全体折中的，必须迭代；牵涉组合结构的，接受多轮。决策机制的轮数直接换算成时间：每轮 20–50 ms（局域网广播 + 应答），3 轮拍卖约 100 ms，远快于任何机器人做一次全局规划，这就是拍卖类机制流行的硬理由。

2. 合同网与拍卖：让出价可比较

合同网协议（Contract Net Protocol）是分布式任务分配的经典骨架，四步：

  1. 发布（Announcement）：任务持有者广播任务描述，必须有 task_id、位置、截止期、验收标准，缺一个都会引发责任争议。
  2. 投标（Bid）：愿意接的机器人报价，报价 = 自己完成该任务的预计代价（预计完成时间或路程 + 电量惩罚）。关键是所有报价必须同一量纲：有人报时间有人报路程，择优就是掷骰子。
  3. 授标（Award）：发布者在决策窗口（如 200 ms）内收集报价，选最小者并广播授标。窗口为什么不能无限等：协同决策有时限（任务在等、机器人在动），迟到 1 秒的完美出价不如 200 ms 内的正常出价。
  4. 确认（Confirm）：中标者回执确认，发布者收到回执才算成交；超时未确认则顺延给次低价，防止中标者恰好掉线。

报价的博弈论细节：第一价格拍卖（付自己报的价）中，理性参与者会低报/高报花招；第二价格拍卖（Vickrey：赢家支付第二高报价）中，"诚实报价"是占优策略，因为你付多少由别人定，报高说好话也占不到便宜，报低只会在该赢时输掉。多机器人工程里第二价格用得不多（"支付"是抽象代价，不是真金），但用它的直觉来设计"报价 = 真实预计代价"的规范，并用多轮重复博弈（每次任务都合作）来抑制虚报：虚报赢单却做不好，下次没人投标给你。这就是重复博弈中的声誉机制。

3. 迭代共识：平均值会收敛到哪里、要多久

连续变量的分布式决策用迭代共识：每台机器人持有自己的值，反复与邻居做加权平均修正：

xi(k+1) = xi(k) + ε · Σj∈N(i) [xj(k) − xi(k)] 收敛条件：0 < ε < 1 / Δmax（Δmax 为最大邻居数）；收敛目标是全体初值的平均（连通无向图）

三步理解它。（1）为什么收敛到平均：每轮迭代保持总和不变（进出对称），且不断消除差值；总和不变 + 差值趋零 ⇒ 全体趋于平均。这是"信息守恒"给出的直觉论证。（2）为什么有限轮是近似：消除差值的速度由图的谱隙（连通快慢的数学刻画）决定，环状拓扑收敛慢（信息绕圈），随机图快；20 台环状图要 30+ 轮才能到 1% 误差，全连通 5 轮就够。（3）工程必做截断：跑无限轮不现实，固定轮数（如 10 轮）+ 允许残差（最终值差千分之几），或用"当最大变化小于阈值就停"的本地终止判据，但要接受不同机器人可能在不同轮停止。

离散选择的共识叫最大共识（max-consensus）：每轮 xi ← max(xi, max 邻居值)，传播的是"目前见过的最优先级"。它的收敛轮数等于图的直径：链状图两端距离 d 条边，就要 d 轮才能互相听见。用它做"优先级选举"（最高优先级者当选队长）：收敛后所有人知道同一个赢家，无需中心。连续与离散两个版本的对比记忆点：连续共识传的是平均值（信息在加权中混合），离散共识传的是极值（信息原样传播），后者轮数由图直径决定，前者由谱隙决定。

4. 稳定化三件套：承诺窗口、滞回、确定性平局

分布式决策的敌人是"决策抖动"：同一资源被反复拍卖、胜负在毫秒间翻转。三个稳定化手段：（1）承诺窗口，中标后的固定时间（如 30 s）内不得重新拍卖该资源（任务不做完不放手，充电桩占满 1 分钟才允许抢）；（2）滞回，重新拍卖的触发阈值严于初次分配（第 083 章的阈值分离思想在决策层的再现）；（3）确定性平局打破，两个报价完全相同时，比 robot_id（小者胜）。为什么必须是确定性的：随机打破让同一输入产生不同结果，实验不可复现、分布式节点也可能各自"随机"到不同赢家；robot_id 谁都知道、谁算都一样，这是无中心系统里"共识"的最便宜形态。

关键代码与解读

片段 1：合同网拍卖者，广播、收标、授标、顺延

import time

class Auctioneer:
    """合同网拍卖者：一次任务分配的全流程状态机。"""
    def __init__(self, window=0.2, confirm_wait=0.1):
        self.window = window               # 投标窗口：200 ms 量级
        self.confirm_wait = confirm_wait   # 中标确认等待：100 ms
        self.bids = {}                     # robot_id -> (cost, recv_time)

    def announce(self, task):
        self.task = task                   # task 含 id/位置/截止期/验收标准
        self.bids.clear()                  # 清空上一轮：同一拍卖者串行处理任务
        self.t0 = time.monotonic()
        return {"type": "ANNOUNCE", "task": task.to_dict()}

    def on_bid(self, robot_id, cost, now):
        if time.monotonic() - self.t0 <= self.window:
            self.bids[robot_id] = (cost, now)   # 迟到的标直接忽略：窗口是硬边界

    def award(self, now):
        if not self.bids:
            return {"type": "NO_BID"}      # 无人投标：交回任务池换个时间再发布
        if now - self.t0 < self.window:
            return None                    # 窗口未关：还不能裁决
        # 平局打破：先比代价，再比 robot_id（确定性：所有人算出同一赢家）
        winner = min(self.bids, key=lambda r: (self.bids[r][0], r))
        self.awaiting = (winner, now)
        return {"type": "AWARD", "task": self.task.id, "winner": winner}

    def confirm(self, robot_id, now):
        winner, t_award = self.awaiting
        if robot_id == winner:
            return "DONE"                  # 成交
        if now - t_award > self.confirm_wait:
            self.bids.pop(winner, None)    # 中标者失联：剔掉它，重走裁决
            return self.award(now)
        return None

解读：这段代码把拍卖的关键工程点全放在了正确的位置。（1）窗口是硬边界：迟到标忽略，因为协同决策有截止时间，且"永远再等一个更好报价"的系统不收敛。（2）平局打破写成 key 元组：先比 cost 再比 id，任何节点重算结果一致，无中心系统里"确定性"就是最廉价的共识。（3）顺延逻辑反向使用：确认超时不按"失败重来"处理，改为剔除中标者后立即用已有报价集重新裁决，不重新广播，省一轮通信；代价是次优者用略旧的报价接单，可接受且可解释。（4）NO_BID 是正常出口：无人投标不是异常，是市场信号（大家都很忙或都不顺路），交回任务池延迟重发。

片段 2：出价估计，把"真实代价"翻译成数字

def estimate_cost(robot, task):
    """报价 = 真实预计代价。三项按量纲统一成"秒"再相加。"""
    travel = dist(robot.pose, task.pickup) / robot.v_max      # 空驶时间
    service = task.service_time_est                           # 作业时间估计
    # 电量惩罚：完成后电量若低于 20%，加一个等效时间惩罚
    soc = robot.battery - robot.rate_per_s * (travel + service)
    soc_penalty = max(0.0, (20.0 - soc)) * 2.0                # 每秒等效 2 s
    return travel + service + soc_penalty

def bid_truthfully(robot, task):
    # 诚实报价的前提：重复博弈里的声誉。虚报赢单却拖延，下次无人邀你
    return estimate_cost(robot, task)

解读：报价函数是把异构资源放进一把尺子的过程，路程、时间、电量都折算成"秒"。电量惩罚系数（每秒 2 s）是设计出来的，不是物理常数：它的作用是让"顺路但会把自己饿死"的机器人自动让出低价（两秒换一秒），避免赢单后中途去找充电桩。出价函数是决策机制里的"价值观代码"：改这个函数，等于改变车队"什么行为值得做"，所以它必须集中评审、写进文档，而不能散落在各机器人里各写各的。诚实的落地保障：每次任务完成后把"预估 vs 实际"记录打分，长期虚报者的信誉分直接进报价系数，声誉机制让诚实成为个体的长远最优。

片段 3：最大共识选举，离散优先级的一致化

def max_consensus_round(my_value, neighbor_values):
    """最大共识：一轮迭代 = 取自己与所有邻居的最大值。
    每个值 = (优先级, robot_id)：优先级比大小，id 只用于当次打破平局。"""
    best = my_value
    for v in neighbor_values:
        if v > best:
            best = v
    return best

def elect_leader(robot_id, priority, gossip_rounds):
    """链状拓扑、直径 d 的图上，d 轮后所有节点看到同一最大值。
    用 (priority, robot_id) 做全序键：任何节点重算结果一致。"""
    my = (priority, robot_id)
    for _ in range(gossip_rounds):        # 固定轮数：工程必做的截断
        my = max_consensus_round(my, received_this_round())
    return my[1]                           # 全体收敛到同一赢家（图连通时）

解读：最大共识与平均值共识的骨架一模一样，只是"平均"换成"取最大"，但两者性质差异很大：平均值共识需要多轮才逼近（近似结果），最大共识在信息传播到全体后的第一时刻就精确达成（一旦最大值传遍，每个人持有的就是它）。轮数等于图的直径：20 台链状车队直径 19，就要 19 轮（每轮 20 ms 约 0.4 s）；这也解释了为什么通信拓扑越"扁"（星状、随机图），选举越快。注意 received_this_round() 的语义：每一轮用同一批消息（同步轮），混合使用不同轮次的消息会破坏收敛性论证，工程上给每轮消息打"轮号"，收到旧轮号直接丢弃。

常见坑

  • 投标窗口过短：窗口 50 ms，正常服务往返 10–20 ms 加上调度抖动，一半机器人"来不及投标"，分配质量骤降。修复：窗口 ≥ 往返 P99 的 5–10 倍（200 ms 是局域网稳妥起点），并用丢标率指标监控。
  • 报价量纲不统一：有的报路程有的报时间，优化方向变成抽奖。修复：全队共用同一个 cost 函数模板（片段 2），评审后下发，禁止各机自编。
  • 共识迭代无限期待：等着"完全收敛"，系统卡在毫秒级差值上循环。修复：固定轮数 + 残差阈值 + 超时用当前值表决；不同节点停止轮数不同没关系，产生的偏差（比如集结中心差 2 cm）小于下游容差即可。
  • 平局随机打破：两个节点"随机"到不同赢家，分配撕裂。修复：全序键（代价, robot_id）确定性比较；任何分布式决策的平局规则都要能做到"人人重算同一答案"。
  • 决策抖动：充电桩刚退出拍卖又被秒抢回来，机器人来回折返。修复：承诺窗口（占用后有最低持有时间）+ 重拍卖冷却 + 滞回阈值，三件套一起上。
  • 只测正常流不测丢包流：共识在 5% 丢包下平均值被扭曲（某些子树的消息到不了全场）。修复：把丢包场景作为决策机制的必测项，量化"决策结果偏差 vs 丢包率"曲线。

  3. 设计：5 台机器人、3 个充电桩，"低电量优先、但必须预留返程电量"作为约束。给出一个多轮分配流程：第一轮拍卖规则、冲突处理、承诺窗口、以及"电量极低"时的强制插队规则（说明为什么插队需要特殊通道）。★★

    常规轮：低电量者报价更低（惩罚函数自然实现）。插队需求来自"再等一轮就回不去"，此时需要发布方直接拒接普通投标（预留规则），或给低电量者一次性 veto 权；veto 是打破公平的机制，必须写明触发条件与冷却，防止滥用。
  4. 推导：在一条 5 节点链状图（0—1—2—3—4）上，初始值 x = (0, 0, 0, 0, 10)（节点 4 持有最大值）。证明最大共识需要恰好 4 轮传遍全场；再说明如果拓扑改为全连接，几轮就够。★★
    提示
    每一轮最大值只能前进一条边：0→1→2→3→4 共 4 跳，即图的直径。全连接时 1 轮（每人直接听所有人）。结论：选举轮数 = 图直径，拓扑连通性直接换成决策延迟。
  5. 实验：同一批 20 个任务、4 台机器人，对比三种分配机制：(a) 集中式贪心（最优解参照）；(b) 合同网拍卖（片段 1）；(c) 随机分配。指标：总完成时间、消息数、对 5% 丢包的退化。写一页三轴对比（参考第 086 章模板），给出你的结论与适用建议。★★★
    提示
    典型结果：拍卖比集中式差 5–15%，消息数低一到两个数量级，丢包下仍可用（窗口内重发一次即恢复）；随机分配差 40%+ 但在全通信中断时是唯一还能跑的兜底。结论要落到"机制选择 = 三轴权衡在具体约束下的投影"。

小结

  • 决策变量三形态对应三机制：离散选择用拍卖（2–3 轮、约百毫秒）、连续变量用迭代共识（多轮、近似收敛）、组合问题用多轮协商。
  • 合同网四步：发布 → 投标 → 授标 → 确认；窗口是硬边界、顺延用已有报价、无人投标是正常出口。
  • 报价必须同一量纲且反映真实代价；Vickrey 直觉解释"为何诚实是占优策略"，工程上用重复博弈声誉来落地。
  • 迭代共识收敛条件 0 < ε < 1/Δmax，收敛到平均；轮数由谱隙决定，工程必做固定轮截断。最大共识传极值、轮数 = 图直径，用于选举与离散优先级。
  • 稳定化三件套：承诺窗口、重拍卖冷却与滞回、确定性平局打破（代价, robot_id），保证结果可复现、系统不抖。
