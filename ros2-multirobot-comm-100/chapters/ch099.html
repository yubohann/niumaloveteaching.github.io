第五篇 · 科研进阶与协同机制

第 099 章：多机器人科研论文复现方法

把一篇论文从 PDF 变成能跑、能测、能对账的系统：三层对齐法（问题/方法/结果）、环境锁定、单元级 sanity check 与差异分诊，复现是一套流程，成败与运气无关。

  • 主题：科研方法（论文复现流程）
  • 关键机制：三层对齐、假设清单对照、环境锁定、sanity check、差异分诊三类归因
  • 预计学时：60 分钟
  • 前置章节：第 098 章

学习目标

  • 理解复现的三个层次（同码重跑 / 独立复现核心主张 / 变体复现）与各自的工作量与证据标准。
  • 掌握三层对齐法：问题对齐（任务/假设/指标口径）、方法对齐（公式↔代码↔参数逐项）、结果对齐（数值表与曲线趋势）。
  • 会做单元级 sanity check：把论文的公式或小算例单独实现，先在"必然正确的小问题"上验证再上全量实验。
  • 掌握差异分诊：把"对不上"归入实现 bug、暗含假设、环境/口径差异三类，并会设计区分它们的判别实验。
  • 能写一份合格的复现报告：主张清单、逐项结论（复现/部分/未复现）、差异日志与根因、以及给原作者的澄清问题。

背景与动机

第 098 章教你把"自己的实验"做扎实；本章教你把"别人的论文"读成能跑的系统。为什么这是多机器人方向的高价值技能？三个理由。其一，复现是理解的最高形式：论文里一句"our scheduler achieves 12% improvement"背后是几十个未写出的决定（初始化、超参、指标口径、仿真器版本），只有把它们逐个补齐，你才真正懂这篇论文在说什么。其二，复现是研究的起跑线：你要在 CBS 之上做改进，就得先让 CBS 基准在你的环境里跑出论文量级的结果，否则"改进"无从比较。其三，复现本身就是产出：复现报告、开源的复现代码、给作者提出的澄清问题，都是学术社区认可的工作。

现实是：跨实验室复现一篇多机器人论文，直接重跑论文全量实验的失败率极高，失败并不说明能力不足，"复现"这个动作的默认难度本就被严重低估。本章把它拆成一套有检查点的流程：先对齐问题与假设、再对齐方法与参数、先小后大地对齐结果；对不上时不慌，用分诊表定位原因。流程化之后，复现从"玄学"变成"项目管理"。

核心原理

1. 复现的三个层次：先明确你要做到哪一层

层次含义证据标准典型工作量
同码重跑作者开源代码 + 数据，在你的机器上跑出同量级结果主要数字落在原论文 ± 波动范围内数天（含环境折腾）
核心主张复现不看代码（或仅参考），按论文文字独立实现，复现 2–3 个核心主张核心结论的趋势与量级一致，关键表格对得上2–4 周
变体复现在新环境/新参数域验证结论的边界与稳健性给出"成立/失效"的条件区间1–2 个月（研究级）

选层的判据是你的目的：工程选型（"这个算法值不值得用"）做到第一、二层即可；写论文做对比基准，至少第二层；声称"发现原作者结论有边界"则要第三层。提前声明层次，能省下大量"复现到什么程度才算完成"的内耗。

2. 三层对齐法之一：问题对齐（任务、假设、指标口径）

复现失败的一大半根源在"问题不在同一层"。问题对齐要求把论文的这三样东西逐条抄出来做成对照表：（1）任务定义，优化什么（makespan 还是总代价？失败实例算不算分母？）；（2）假设清单，单位速度？全局通信？同步轮次？理想定位？每个假设都问一遍"我的实现里它成立吗"；（3）指标口径，成功率怎么算、超时怎么处理、时间怎么计时（含初始化吗）。举例：MAPF 论文的"成功率 95%"通常指"在时间上限内找到解"，而你若把误报无解的实例算作成功，指标就悄悄变宽了，对账时必然对不上。

问题对齐产出物 = 任务定义卡 + 假设清单（每条标"我的实现：满足/不满足/未知"）+ 指标口径表 "未知"的假设是最危险的一类，它可能在结果对不上时才浮出水面；要求自己把它降级为"满足"或"不满足"

3. 三层对齐法之二：方法对齐（公式 ↔ 代码 ↔ 参数）

方法对齐的做法是把论文的核心公式抄进代码注释或文档，逐式对应到实现，并给每个超参标注来源：

  • 公式对应：论文式 (3) 的每一项在代码哪一行？尤其是损失/代价函数的每个系数，它们常藏在附录。
  • 参数清单：学习率、迭代上限、安全距离、量化步长逐项列表，未给值的参数要标"论文未给"（这是复现差异的常见来源；但"论文未给"不能成为随意估值的借口，估值也要记录并标注）。
  • 初始化与随机性：网络初始化方式、种子、数据顺序，深度学习类论文的复现差异常来自这里。
  • 边界条件：分母为零、目标无法到达、通信断开时的论文行为，论文往往不写，你要显式决定并记录。

产出物是一张"公式-代码-参数"三角对照表：论文一边、你的实现一边，中间列差异与理由。这张表在写复现报告与联络作者时都是核心资产。

4. 三层对齐法之三：结果对齐（数值、趋势、现象）

结果对齐按证据强度分三级：数值级（论文表格的每个数字，落在你重复实验的置信区间 ±10% 内）、趋势级（随规模/密度变化的曲线形状一致：都在 N ≈ 30 开始掉；你掉它不掉即为趋势不符）、现象级（论文描述的定性行为出现：比如 CBS 在窄门场景耗时爆增）。复现报告里逐项标注对齐等级："表 2 数值级复现，图 3 仅趋势级（差异原因见 5.2 节）"。趋势对不上比数值对不上更严重，数值差 10% 常是环境与参数，趋势差意味着机制理解有偏差。

5. 差异分诊：三类归因与判别实验

结果对不上时，切忌漫无目的地改参数。把差异归入三类，各配一个判别实验：

归因症状判别实验
实现 bug小规模就错；指标在边界条件下离谱（如成功率为 0）单元级 sanity check：论文的小算例、退化场景（1 台机器人）单独验证
暗含假设未满足小规模对得上、大规模趋势先崩；换场景差异剧增把假设逐条"补上"再跑：加同步轮次、加全局通信、改为单位速度，看差异是否消失
环境/口径差异趋势一致但所有数值整体平移（如统一慢 15%）口径核对 + 对照实验：同一份指标代码跑双方系统；或按公式修正计时起点

分诊的纪律：每次只改一个变量，记录前后数字。三类有时会叠加（bug 加口径差异），先修 bug（否则一切对比都是噪声）、再核口径、最后调假设，按"越基础越先排"的顺序，这是复现时间管理的关键。

实现思路与设计

把复现做成一条十步流水线，每步带检查点（gate）：

步骤内容检查点
1 选文与选层确定复现层次（重跑/核心主张/变体）一句话写下目标与预算
2 主张提取从摘要/结论摘出 2–3 条可证伪主张每条主张配"需要什么证据算复现"
3 问题对齐任务定义卡 + 假设清单 + 口径表"未知"假设数量清零
4 环境锁定依赖版本、随机种子、配置快照全部固定环境记录脚本一键输出
5 找代码/写代码优先后作者代码（若选同码重跑）；否则独立实现核心模块核心公式三角对照表完成
6 单元 sanity check小算例、退化场景逐个通过论文给的任何小数字都对得上
7 小规模全流程最小配置端到端（2 台、小地图）跑通定性行为与论文描述一致
8 全量实验按论文规模跑，多重种子原始数据与种子落盘
9 差异分诊不符项按三类归因，逐项做判别实验每项差异有"根因 + 证据"
10 复现报告主张清单逐项结论 + 差异日志 + 澄清问题他人可据报告复跑

时间预算建议：第 3、6 步各占 20% 时间，第 8 步占 30%，其余分摊，新手常把 80% 时间花在第 8 步（急着跑大实验），结果对不上又回头补第 3、6 步，总时长翻倍。流程的哲学是"便宜的先做"：写在纸上的清单比跑 100 组实验便宜，单元检查比全量复跑便宜。

设计决策：结果对不上时，能不能"微调自己的数字去对齐论文"？

绝对不行，这是复现的诚信红线。正确的做法分两种情形：若差异已被分诊为口径/环境差异（例如论文计时不含初始化而你的含），修正的是口径，并在报告中写明"按统一口径后对齐"；若差异来自无法消除的假设分歧，如实报告"部分复现 + 差异量级 + 根因"。复现报告的价值恰恰在于"诚实记录差异"，把未复现修成"复现"的报告，等于亲手毁掉自己下一阶段研究的基准。

关键代码与解读

片段 1：环境与实验元数据记录，复现的"身份证"

import json, platform, subprocess, hashlib, time

def record_environment(cfg_path, run_id):
    """一键记录环境与配置唯一标识：版本、配置摘要、时间、机器信息。"""
    meta = {
        "run_id": run_id,
        "time": time.strftime("%Y-%m-%d %H:%M:%S"),
        "python": platform.python_version(),
        "platform": platform.platform(),
        # 依赖版本：用 pip freeze 的快照（命令以对应环境为准，如 python -m pip）
        "pip_freeze": subprocess.run(["python", "-m", "pip", "freeze"],
                                     capture_output=True, text=True).stdout.splitlines(),
    }
    # 配置摘要：任何影响结果的配置文件都参与 SHA-256 计算，改动可被自动发现
    with open(cfg_path, "rb") as f:
        meta["config_sha256"] = hashlib.sha256(f.read()).hexdigest()
    with open(f"runs/{run_id}/env.json", "w", encoding="utf-8") as f:
        json.dump(meta, f, ensure_ascii=False, indent=2)
    return meta["config_sha256"]

解读：这份元数据的三个字段各有分工。（1）依赖版本快照：多机器人研究横跨 rclpy/numpy/求解器/仿真器，"在我机器上能跑"的本质是这些版本锁定的组合；pip freeze 是标准证据。（2）配置摘要：实验越多，"这组结果用的哪版配置"越容易失控；摘要让任何配置改动都能与结果曲线对上（页面上画线时把摘要标在角落，评审一眼就能看出不同曲线的配置差异）。（3）run_id 目录规范：每次运行一个目录，装环境、种子、日志、原始数据，复现报告里的每条结论都能定位到目录，不用翻聊天记录找数字。

片段 2：公式级 sanity check，先在"必然正确的小问题"上验证

import numpy as np

def sanity_check_lpt_bound():
    """论文小算例照抄：验证 LPT 启发式的 4/3 上界与小例数值。
    这类检查文案来自论文正文表格/示例，能对上一个，核心公式大体没实现错。"""
    p = {0: 4.0, 1: 3.0, 2: 3.0, 3: 2.0, 4: 2.0}   # 论文示例任务时长
    m = 2
    loads = [0.0] * m
    for j in sorted(p, key=lambda j: -p[j]):        # LPT 主循环（与论文一致）
        i = int(np.argmin(loads))
        loads[i] += p[j]
    makespan = max(loads)
    lower = max(max(p.values()), sum(p.values()) / m)
    # 论文保证：makespan ≤ (4/3 − 1/(3m)) × OPT；抽查是否违反理论
    ratio_bound = (4.0 / 3.0 - 1.0 / (3.0 * m)) * lower
    assert makespan <= ratio_bound + 1e-9, "违反上界：实现或公式抄错了"
    print(f"makespan={makespan} LB={lower} bound={ratio_bound:.2f}")
    return makespan

# 若论文给了具体示例数值（本例 makespan=8），在此直接断言相等：
# assert sanity_check_lpt_bound() == 论文示例值

解读：sanity check 的黄金法则是"拿论文里作者自己算过的东西当锚点"：示例表格、附录小算例、图示中的单个点，它们不依赖实验环境，是最干净的对照。这段里两个细节值得学：（1）断言"理论性质"，不只对数字，就算论文没给示例值，LPT 的 4/3 上界也是可断言的强性质，实现错了必然被抓住；（2）检查点写成可执行的 assert，写在测试文件里随代码长跑，不依赖"上次手工对过所以相信它"。任何后续重构（适配新版本、加功能）只要破坏了这些性质，测试立即报警，复现的成果就被固化成了回归测试，这也是复现代码值得开源的原因之一。

片段 3：差异分诊实验，用尺度扫描区分 bug 与假设差异

import numpy as np

def triage_scale_sweep(run_mine, run_paper_curve, sizes=(5, 10, 20, 40)):
    """尺度扫描：若差异随规模放大 ⇒ 指向假设差异；恒定平移 ⇒ 口径差异。"""
    report = []
    for n in sizes:
        mine = run_mine(n)                        # 我的实现：指标（如成功率）
        ref = run_paper_curve[n]                  # 论文曲线上的读数（估算）
        ratio = mine / ref if ref else float("nan")
        report.append((n, mine, ref, ratio))
        print(f"N={n:3d} mine={mine:.2f} paper={ref:.2f} ratio={ratio:.2f}")
    # 读表两问：① 小规模就偏 ⇒ 查实现 bug；② 比值随 N 恶化 ⇒ 查假设/规模效应
    return report

# 例：paper = {5: 0.98, 10: 0.95, 20: 0.90, 40: 0.75}
# mine 若为 0.60/0.58/0.55/0.50（恒定偏低）⇒ 疑似口径/参数差异
# mine 若为 0.97/0.93/0.80/0.40（随 N 加速恶化）⇒ 疑似通信假设或调度差异

解读：这个 20 行的"诊断仪"体现了分诊思维的本质：不看单个数字的差距，看差距随自变量的"形状"。恒定比值偏差（到处都差 5%）几乎总是指向测量口径或固定参数；随规模放大的偏差指向"假设在大规模下才起作用"（通信、同步、资源竞争）；小规模就崩则是实现 bug。把每次改动后的扫描结果并排保存（同一张表三列：原版 / 改假设后 / 修口径后），当某列突然"贴住"论文曲线，根因就当场锁定。这就是"每次只改一个变量"原则的可视化实现。

常见坑

  • 跳过问题对齐直接开跑：跑了两周发现指标口径根本不同（你的失败案例算分母，论文不算），全部数据作废。修复：步骤 3 的检查点（"未知"假设清零）必须过了才动代码。
  • 拿自己的框架差异当 bug 修：用自研仿真器复现，发现"总是慢 20%"，花了三周改算法，最后发现是两套仿真器的物理步长不同。修复：先做"同一指标代码跑两个环境"的对照，环境差异要在结果对齐前通过分诊实验排除。
  • 不看附录与小字：关键超参（安全半径、迭代上限）写在附录脚注里。修复：方法对齐清单逐项标注来源（正文/附录/代码/作者澄清），"未给"也要显式记录。
  • 结果对不上就换指标：成功率对不上就改报"平均路径长度"。修复：主张与指标在步骤 2 预绑定；替换指标必须走"报告差异 + 说明原因"的正道。
  • 不联系作者：有个假设读不懂，硬猜三周。修复：步骤 9/10 的澄清问题是复现流程的合法产出，写清"我们复现到哪、卡在哪、问题是什么"的邮件，作者通常乐意回复；这封邮件比匿名抱怨有用得多。

练习与思考

  1. 算一算：论文表 2 报告成功率 0.83；你的 20 次重叠实验均值 0.71、95% CI [0.66, 0.76]。区间不重叠，差异显著。按三层分诊流程，写出你的前三步动作与各自的验证方式（不要直接猜 bug）。★
    提示
    第一步核对口径（成功率的分母/超时处理）→ 第二步核对参数清单（时间上限、安全距离）→ 第三步尺度扫描看差异形状（恒定 or 放大）。每一步产出一个可判定的结论，再决定下一步。
  2. 改配置并预测结果：把实验种子从一组换到另一组，预测成功率均值的波动幅度（相对 CI 宽度）。说明"换种子结论翻转"意味着什么，以及论文报告里应如何预防这类不可靠结论。★
    提示
    种子变化下均值应在 CI 宽度量级内波动；若翻转（差异符号都变了），说明效应量小于噪声，结论不成立，需要增加重复或缩小随机源。预防：多种子 + CI 报告，杜绝单种子演示。
  3. 设计：为第 097 章地图上的 CBS 论文（或你手头的任一篇 MAPF 论文）写完整三层对齐清单：任务定义卡、假设清单（至少 5 条）、指标口径表、公式-代码-参数对照表大纲。★★
    提示
    MAPF 假设清单要素：单位速度、同步时间片、等待动作允许、全局通信、静态地图、目标不重叠等；每条标注你的实现满足/不满足/未知。口令：假设清单越具体，分诊越快。
  4. 推导/诊断：你的算法在 N=20 之后成功率比论文掉得快（论文到 40 才开始掉）。列出至少 3 个假设差异候选（如通信延迟、冲突解决顺序、时间上限），并为每个候选设计一个"只改这一项"的判别实验与预期观察。★★
    提示
    候选与实验示例：①时间上限，把上限按论文附录调大一档，看掉点位置是否右移；②冲突解决顺序，换用论文的低层优先规则，看曲线形状；③通信模型，给交换的轨迹加延迟并量化。每个实验的预期写成"若候选成立，则 X 变化方向是 Y"。
  5. 综合：选一篇你有兴趣的多机器人论文，完成复现流水线的第 1–3 步（选层、主张提取、问题对齐），输出一页"复现方案"：主张清单、假设清单、口径表、里程碑与时间预算。★★★
    提示
    自检：每条主张配上"证据形态"（对哪张表/哪条曲线达成什么）；时间预算按"3、6 步各 20%，第 8 步 30%"的基准分；最后一个字段写"什么情况下我会停手并写部分复现报告"，预期管理是复现项目活下来的关键。

小结

  • 复现分三层：同码重跑、核心主张复现、变体复现，先声明层次与预算，再动手。
  • 三层对齐：问题对齐（任务/假设/口径，未知假设清零）、方法对齐（公式↔代码↔参数三角表）、结果对齐（数值/趋势/现象三级证据）。
  • 小算例、退化场景、理论性质断言构成单元级 sanity check；论文自带的示例数字是最干净的锚点。
  • 差异分诊三类：实现 bug（小规模就崩）、暗含假设（差异随规模放大）、环境口径（恒定平移）；每次只改一个变量。
  • 环境锁定 + 配置摘要 + run_id 目录，让任何结论都能定位到一次运行；换种子与 CI 是结论稳健性的试纸。
  • 诚信红线：绝不"微调数字对齐论文"；差异如实报告，澄清问题写进复现报告发给作者。
