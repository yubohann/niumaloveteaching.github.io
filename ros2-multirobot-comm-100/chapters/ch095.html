第五篇 · 科研进阶与协同机制

第 095 章：多机器人协同任务机制与博弈视角

当每台机器人只在乎自己的任务收益，团队会滑向何方：纳什均衡、拥堵博弈、势函数保证的收敛，以及"利己均衡比社会最优差多少"的无政府状态代价。

  • 主题：协同任务机制（博弈论视角）
  • 关键机制：纳什均衡、拥堵博弈与势函数、最佳响应动态、无政府状态代价 PoA、沙普利分配
  • 预计学时：60 分钟
  • 前置章节：第 094 章

学习目标

  • 会用博弈语言重述多机器人任务分配：玩家、策略集、收益函数、(纯策略) 纳什均衡的定义与识别方法。
  • 理解拥堵博弈的势函数构造：为什么"选任务"这类利己行为能保证有限步收敛而不循环。
  • 掌握无政府状态代价（Price of Anarchy, PoA）的计算：最差均衡的社会代价 ÷ 社会最优代价，并会手算小例子。
  • 理解"均衡 ≠ 最优"的根源是外部性，以及拥堵定价/惩罚项如何把 PoA 拉回接近 1。
  • 掌握沙普利值（Shapley value）的直觉与计算：把"每个人都重要"的合作收益按平均边际贡献分配。

背景与动机

第 066–071 章的任务分配与调度，都是站在"车队管理者"的位置算全局指标（完工时间、总路程）；第 089 章的拍卖则是"市场"式分配。本章把视角再拧一格：假装每台机器人是一个自利的玩家，它们只优化自己的收益，这时候系统会停在哪里？停的地方好不好？这是对真实系统的一种更诚实的建模，不只是一场思维游戏：当机器人属于不同厂商、不同小队、甚至不同公司时，"统一指挥"并不存在，你必须理解并设计"让利己行为自然产生好集体结果"的规则。

博弈视角还回答一个工程上极其实用的问题：为什么自利选择能收敛（不来回抢）？答案叫势博弈：这类博弈存在一个被所有个体改进共同推动的全局函数，个体每改一步，全局函数就上一个台阶，台阶有限，所以必停。理解了这条机制，你就能判断"我的自利分配规则会不会震荡"，不再靠调参运气。

与前面章节的连线：本章的均衡分析给第 089 章拍卖一个理论背书（为什么市场机制稳定）；沙普利值与第 090 章的反事实优势是同一思想的两种形态（边际贡献）；本章的 PoA 指标会进入第 098 章的评价体系。

核心原理

1. 把任务选择写成博弈：玩家、策略与纳什均衡

一场多机器人任务的博弈由三件东西定义：玩家（N 台机器人）、策略集（每台可选的任务点/区域/路线）、收益函数（ui(我的选择, 大家的选择)，注意收益依赖别人，这是博弈与单机优化的本质区别）。纳什均衡（Nash equilibrium）的定义一句话：没有任何一个玩家能通过"单方面改变自己的策略"来提高自己的收益。

纯策略纳什均衡：ui(si*, s−i*) ≥ ui(si, s−i*)，∀i, ∀si 读法：给定别人的选法不变，我在均衡里的选择已经是我的最优，人人都"懒得改"，系统就停住了

判别方法（小规模手算三步）：对每个玩家的每个备选策略，在"假设其他人保持当前选择"的前提下比较收益；所有玩家都无改进动机的组合即均衡。注意两个概念陷阱要提前拆掉：（1）均衡可能不唯一（多个"谁都懒得改"的组合）；（2）均衡未必是最优，这正是下一小节的主题。

2. 拥堵与外部性：均衡比最优差多少

任务选择的标准剧情是拥堵：去同一个任务点的机器人越多，每人分到的好处越少（排队、遮挡、互相等让）。而每台机器人做选择时只算自己的账，不会为"我给队友添的堵"内疚，这个被忽略的账就是外部性。用一个两充电桩的小例子把差距算出来：

充电桩单独使用两台同时使用
S1：单工位快充1 分钟串行排队：各 2 分钟
S2：双工位慢充2 分钟各 2 分钟（并行不排队）

社会最优：一台去 S1（1 分钟）、一台去 S2（2 分钟），总耗时 3 分钟。均衡分析："全去 S1"也是纳什均衡，从中任一台改去 S2 仍是 2 分钟（不变得更差，也即无"严格"改进动机），谁都懒得改。这个均衡的总耗时是 4 分钟。于是：

无政府状态代价 PoA = 最差纳什均衡的社会代价 ÷ 社会最优代价 = 4 / 3 ≈ 1.33 PoA ≥ 1，越接近 1 说明"利己行为的集合结果"越接近理想；PoA 是对机制设计的直接考核指标

把 PoA 降下来的标准手法是拥堵定价：在每台机器人自己的收益里加一项"我加入后对现有成员的损害"（比如每增加一台在 S1，全体各付 0.5 分钟等效惩罚）。加价之后，"全去 S1"的诱惑被削弱（我去了别人变慢、我也要分担这份变慢），均衡被推向分散。第 066 章的报价函数里那道"电量惩罚"、第 089 章里让"顺路者"让贤的机制，本质上都是给外部性定价，博弈视角让这类设计的目的一目了然：不改行为，改账本。

3. 势函数：自利行为为什么会停下

自利动态最坏的情况是循环：A 抢任务 1、B 被挤到任务 2、A 又想换任务 2、B 换回任务 1，无限对调。势博弈（potential game）排除了这类灾难：如果存在一个全局函数 Φ（势函数），使得任何玩家单方面改变策略时，Φ 的变化方向与他自己收益的变化方向一致，那么每次"有意义的改动"（收益提高）都会让 Φ 严格上升。Φ 的取值组合有限（离散任务数有限），上升不能无限进行，所以必停，而且停下的地方就是纳什均衡。这就是"有限改进性质"（finite improvement property）：

拥堵博弈的势函数：Φ(分配) = Σ任务 t Σk=1n_t [ vt − c(k) ] vt 为任务价值，nt 为选择它的机器人数，c(k) 为第 k 个加入者带来的边际拥堵代价，个体收益 = vt − c(nt) 恰好是 Φ 中"最后一项"的增量

验证式的读法：个体从任务 A 换到任务 B，对自己收益的影响 = （B 的边际收益）−（A 的边际损失）；而 Φ 的变化恰好等于这两项之和，Φ 的差分 = 个体收益的差分，一一对应。这个精确对齐让"自私"变成了"给 Φ 做爬山"，于是收敛不再需要任何中央协调。工程推论：设计分布式任务分配时，先问"我的个体收益函数能不能从一个全局势函数差分出来"，能，则收敛有保证；不能，则策略大概率会循环震荡（需要用第 089 章的承诺窗口等外挂手段兜住）。

4. 合作收益怎么分：沙普利值

有些任务必须合作完成（两台一起搬、三台围捕），合作产生的收益比各自单干之和多，多出来的部分谁该拿大头？沙普利值（Shapley value）给出一个公理化答案：按"平均边际贡献"分配。把"可能的加入顺序"全排列，对每种顺序记录"我加入联盟那一刻，联盟收益增加了多少"，再对所有顺序取平均：

φi = (1/N!) · Σ所有排列 π [ V(联盟中 i 之前的成员 ∪ i) − V(之前的成员) ] V 是联盟价值函数；φi 是 i 的"平均边际贡献"；三人时共 6 种顺序，手算可行

它和第 090 章的反事实优势是同一血脉：反事实问"没有我，团队差多少"（一种顺序下的边际），沙普利对所有顺序取平均（更公平、更稳定）。工程用途：多机器人协同搬运/围捕后的"收益分配"（奖金、能耗配额、信用分）、以及论文里论证"我们的分配公平且稳定"（沙普利值满足有效性、对称性、零贡献者零分配等公理，是唯一同时满足这些公理的分配方式，这句话本身就是答辩利器）。

实现思路与设计

把博弈机制落成系统时，三个角色及各自动作：

角色内容工程载体
个体收益函数ui = 任务价值 − 路程代价 − 拥堵惩罚（− 电量惩罚）每台机器人本地计算，参数全队统一并版本化（第 081 章）
拥堵信息各任务的当前人数 nt、预计完成时间状态通道广播（1 Hz 足够），或者带 TTL 的"占位声明"
改选动态最佳响应/更好响应迭代 + 承诺窗口事件驱动，0.5–1 s 一轮；与第 089 章的平局打破、冷却规则共用

设计参数与检查表

  • 拥堵代价函数 c(k)：起点取"线性定价"c(k) = q·(k−1)（加入第 k 个的边际惩罚），q 取任务平均时长的 20–50%。q 太小 PoA 高、q 太大任务没人去。
  • 收敛检查：跑 100 轮随机初始分配，统计到达均衡的平均改选步数（预期 5–15 步）与是否出现循环（用 Φ 单调性验证，出现即说明收益函数与势函数差分不符，通常是拥堵信息滞后造成的）。
  • PoA 体检：离线穷举全部均衡（小规模）或 Monte Carlo 采样均衡（大规模），计算 PoA；进入实验章（第 098 章）作为机制评价指标之一。
  • 承诺与冷却：即使势收敛有保证，也要承诺窗口防"信息滞后期的无效改选"，收敛性解决"会不会停"，承诺窗口解决"停之前别抖"。
设计决策：为什么不让机器人直接优化全局目标？

当系统里所有机器人归你管、通信也够好时，集中式优化确实更直接（第 091 章的三档机制）。博弈视角真正的主场是三类场景：（1）跨组织协作，不同厂商/课题组各管一摊，你没权替别人改目标函数；（2）局部信息，全局优化需要全局状态，而 n_t、别人的路程只有分布式才拿得到；（3）鲁棒性研究，集中式失效时（中心掉了、被对抗性虚报攻击时），利己均衡机制是天然的无中心兜底。先想清楚你的场景属于哪类，再决定要不要引入博弈机制，为攻关而博弈是过度设计。

关键代码与解读

片段 1：拥堵博弈的更好响应动态，势函数逐帧上升

import numpy as np

def payoff(choice, counts, values, q=1.0):
    """个体收益 = 任务价值 − 拥堵边际惩罚。counts[t] 为当前选择任务 t 的人数。"""
    return values[choice] - q * (counts[choice] - 1)   # 第 k 个加入者罚 q(k−1)

def potential(counts, values, q=1.0):
    """势函数 Φ = Σ_t Σ_{k=1..n_t} [v_t − q(k−1)]：与个体收益差分完全对齐。"""
    phi = 0.0
    for t, n in enumerate(counts):
        for k in range(1, n + 1):
            phi += values[t] - q * (k - 1)
    return phi

def better_response_once(choices, values, q=1.0):
    """扫描一轮：任一机器人改选更优任务并执行（分布式版本各自比选、比选即改）。"""
    counts = np.bincount(choices, minlength=len(values))
    for i, t in enumerate(choices):
        cur = payoff(t, counts, values, q)
        for t2 in range(len(values)):
            if t2 == t:
                continue
            # 试算改选后的收益：我走后原处人数减一、新处人数加一
            gain = (values[t2] - q * counts[t2]) - (values[t] - q * (counts[t] - 1))
            if gain > 1e-9:                          # 严格改进才动：防平局抖动
                choices[i] = t2
                counts = np.bincount(choices, minlength=len(values))
                return i, "switched"
    return None, "stable"        # 无人再度改选：到达纯纳什均衡

解读：三个设计点在代码里可摸得到。（1）payoff 的"k−1"和 potential 的"k−1"逐项对应，把两个函数写在一起看，就明白差分对齐说的是什么：个体每赚一分，Φ 就涨一分。（2）严格改进阈值 1e-9：相等收益不改动，避免两个等价任务之间的无限对调（等价于确定性平局打破的数值版）。（3）每次只允许一台机器人实际改选（返回后重新计算 counts），"异步更好响应"，这是分布式现实的忠实模型，也是"势上升有界 ⇒ 必停"结论的适用条件（若所有人同时看旧信息改选，同步更新可能过冲，需要额外的调度约定）。

片段 2：PoA 计算，穷举小规模的全部均衡

from itertools import product

def social_cost(choices, values, q=1.0):
    """社会账本 = 全体收益之和（越大越好）；这里直接返回总收益。"""
    counts = np.bincount(choices, minlength=len(values))
    total = 0.0
    for t, n in enumerate(counts):
        for k in range(1, n + 1):
            total += values[t] - q * (k - 1)     # 与势函数同构：社会账本
    return total

def nash_equilibria(n_robots, values, q=1.0):
    """穷举全部策略组合，筛出纯纳什均衡（小规模专用：N×T 组合量级）。"""
    eqs = []
    for choices in product(range(len(values)), repeat=n_robots):
        counts = np.bincount(choices, minlength=len(values))
        is_eq = True
        for i, t in enumerate(choices):
            cur = values[t] - q * (counts[t] - 1)
            for t2 in range(len(values)):
                if t2 != t and values[t2] - q * counts[t2] > cur + 1e-9:
                    is_eq = False                # 找到严格改进：不是均衡
                    break
            if not is_eq:
                break
        if is_eq:
            eqs.append(choices)
    best = max(social_cost(c, values, q) for c in product(range(len(values)), repeat=n_robots))
    worst_eq = min(social_cost(c, values, q) for c in eqs) if eqs else None
    poa = (best / worst_eq) if worst_eq not in (None, 0) else float("inf")
    return eqs, poa     # poa = 全局最优账本 ÷ 最差均衡账本（收益型效率比；代价型场景取倒数）

解读：PoA 的计算是"机制设计者的体检报告"，这段代码在离线跑（几十毫秒），把"我的收益函数到底会把人带多歪"变成数字。（1）均衡筛选用严格改进阈值：与片段 1 一致，弱均衡的平局比较不误判；（2）worst_eq 取最差：PoA 的定义是对抗性指标，机制的最坏表现，不是平均表现（平均表现会掩盖最坏的均衡戏剧性地差这件事）；（3）大规模场景改用 Monte Carlo 采样纳什均衡或用势函数下降的近似口径，穷举只用于验证与教学，这正是"小规模成套理论 + 大规模数值口径"的常见研究分工。

片段 3：沙普利值，枚举顺序，平均边际贡献

from itertools import permutations

def shapley_values(players, coalition_value):
    """沙普利值：对全部加入顺序计算平均边际贡献。
    coalition_value：集合 → 该联盟的价值（由任务/实验定义）。"""
    n = len(players)
    phi = {p: 0.0 for p in players}
    for order in permutations(players):          # 3 人 = 6 种顺序，手算可行
        members = set()
        for p in order:
            before = coalition_value(members)               # 我加入前的联盟价值
            members.add(p)
            after = coalition_value(members)                # 我加入后的联盟价值
            phi[p] += after - before                        # 我的边际贡献
    for p in phi:
        phi[p] /= len(list(permutations(players)))          # 对所有顺序取平均
    return phi

# 例：V({})=0；V(单台)=1；V(两台)=3；V(三台)=6 →
# 对称博弈：每人 φ = 6/3 = 2.0（加入位置边际为 1/2/3，平均 (1+2+3)/3 = 2）

解读：沙普利值的计算量是 N!（N=6 就是 720 次枚举，N=10 到 360 万，工程上通常对任务小联盟算精确值，大联盟用采样近似或把"边际贡献"的评估留痕复用（第 090 章的反事实优势就有现成的逐次边际记录）。注释里的三台例子值得亲手验算一遍：联盟价值按规模取 1/2/3 递增（这是边际增量），沙普利值却是每人 2.0。原因：边际贡献按"加入位置"依次为 1、2、3，而每个玩家在 6 种顺序里恰好各经历一次这三个位置，平均后人人相等；这既是对称性公理（对称玩家同分配）的直接体现，也是效率公理的验证（2+2+2 = 6 = 大联盟价值），是理解公理化分配的最好入口。

常见坑

  • 收益函数不含拥堵项，机器人蜂拥：所有人看"任务价值 ÷ 路程"，选出的分配把每个任务都挤爆。修复：拥堵边际惩罚 q·(k−1) 进收益（片段 1），并从实验中回调 q，它其实是"外部性的价格"。
  • 弱均衡的平局抖动：两个任务收益恰相等，机器人按分秒级随机值来回改选。修复：严格改进阈值 + 确定性平局打破（robot_id 比较），与第 089 章同款药方。
  • 同步改选引起过冲循环：所有机器人同时看到旧人数、同时改选，counts 一帧内翻倍错乱。修复：异步更好响应（一次一台实际改选）或加随机的改选延迟；把"Φ 必须单调上升"写进运行期断言（调试模式开启）。
  • 把均衡当最优验收：看见系统"停住了"就以为分配合理，实际是停在差的均衡（PoA 大的位置）。修复：验收里同时报均衡账本与最优账本（离线算），PoA 超标就改收益函数/加定价。
  • 理性假设不成立：真实机器人会因通信延迟看不到最新人数、"理性"基于过期信息。修复：把博弈分析定位为"收敛性与最坏情况保证"，工程层永远叠加上承诺窗口与冷却；文档里把信息滞后作为假设写明。

练习与思考

  1. 算一算：用本章的充电桩例子（S1 单人 1 分钟/双人各 2 分钟；S2 恒 2 分钟），枚举两种分配方式，验证：社会最优总耗时 3 分钟；"全去 S1"是（弱）纳什均衡且总耗时 4 分钟；PoA = 4/3。★
    提示
    重点体会"弱"字：全去 S1 时某台改去 S2 是 2 分钟 vs 现状 2 分钟，不严格变差也不严格变好，所以它留得住。把 S2 改成 1.9 分钟，这个均衡就不存在了，均衡对参数是脆的，这正是要算 PoA（最坏均衡）而不只看"有没有均衡"的原因。
  2. 改配置并预测结果：给上面的例子加拥堵定价：每多一人使用同一桩，全体各多付 0.5 分钟（随人数递增）。预测新的均衡集合与 PoA 变化方向，并说明定价过大（如 3 分钟）会带来什么新问题。★
    提示
    0.5 定价下"全去 S1"的收益被拉低，"分散"成为唯一均衡，PoA → 1。定价过大时没人愿意去任何一个桩（收益都为负），机器人开始"待机等充电"，外部性定价的经典副作用：罚款过重导致市场冻结。
  3. 设计：5 台机器人 3 个任务点（价值 10 / 8 / 5，线性拥堵 q = 1）。手算或写 20 行枚举，找出一个纯纳什均衡与全局最优分配，计算 PoA；再提出一版改良的收益函数让 PoA ≤ 1.1。★★
    提示
    先跑片段 2 的枚举确认基线；改良思路：把 q 从 1 升到约 2–3 再测 PoA 与"全员有任务可去"的约束是否同时满足。结论要落在"定价 = 外部性价格"的结构化解释上，不能停留在"参数试出来的"。
  4. 推导：证明片段 1 的收益函数与势函数 Φ 满足"差分对齐"，对任意单台机器人从任务 t 改选 t′ 的动作，证明 Δui = ΔΦ，并据此论证改进路径有限（Φ 有上界）且终点必为纳什均衡。★★
    提示
    Δu_i = [v_t′ − q·n_t′] − [v_t − q·(n_t−1)]；ΔΦ 计算加入 t′ 的增量 v_t′ − q·n_t′ 与离开 t 的损失 v_t − q·(n_t−1) 之差，逐项相同，故 Δu_i = ΔΦ。Φ 是 n_t 的有界函数（人数有限），严格上升不能无限进行，故有限步停；停在无严格改进处即均衡。
  5. 实验：6 台机器人 4 个任务点，实现两个版本（A：无拥堵定价；B：线性定价 q = 1.5），各跑 200 次随机初始分配：(a) 统计到达均衡的步数与 Φ 曲线（应单调）；(b) 用片段 2 的小规模版算 PoA；(c) 用片段 3 计算一次"两台协作搬运"的沙普利分配并检查公平性直觉。★★★
    提示
    A 版：步数少但 PoA 明显 > 1（蜂拥）；B 版：PoA 下降、个别场景步数略增。报告里并联"PoA vs 定价系数"曲线，给出你的定价建议与失效区间（没人接单的临界点附近）。

小结

  • 博弈三要素：玩家、策略、收益；纳什均衡 = 人人都没有单方面改进动机的组合，可能不唯一、可能不优。
  • 拥堵外部性使利己均衡偏离社会最优；PoA（最差均衡 ÷ 最优）量化偏离程度，充电桩例子给出 4/3。
  • 拥堵博弈是势博弈：Φ 的差分与个体收益差分逐项对齐；严格改进 ⇒ Φ 严格上升 ⇒ 有限步收敛，不会循环。
  • 工程三药方：收益函数带拥堵边际惩罚（给外部性定价）、严格改进阈值 + 确定性平局打破（防抖动）、异步改选（防同步过冲）。
  • 合作收益分配用沙普利值 = 全排列的平均边际贡献；N! 成本限制了规模，局限与近似要写清楚。
  • 博弈视角的主场：跨组织、局部信息、抗单点，不是所有任务都该博弈化。
