第 041 章：编队控制基础

从"知道彼此在哪"走向"保持队形一起动"：用图和拉普拉斯矩阵描述队形，用一致性协议让每台机器人只看邻居就能收敛到目标形状。

  • 主题：协同控制 / 编队与图论
  • 关键机制：编队约束图、拉普拉斯矩阵、一致性协议、通信拓扑与收敛速度
  • 预计学时：65 分钟
  • 前置章节：第 040 章（阶段项目：协同建图与状态共享）

学习目标

  • 掌握编队的数学描述：节点、期望偏移、编队误差，以及"队形保持"作为误差最小化问题的含义。
  • 理解四类编队方法（领航-跟随、虚拟结构、基于行为、一致性）的取舍与适用场景。
  • 掌握一致性协议 ẋ = −Lx 的推导直觉、拉普拉斯矩阵的构造与代数连通度对收敛的作用。
  • 会实现离散一致性更新（一个机器人 = 一个节点），并把队形偏移接入协议。
  • 理解通信拓扑、丢包与时延如何影响编队稳定性，能设定控制频率与增益的起点。

背景与动机

第二篇解决了"共享认知"：每台机器人知道队友在哪、世界长什么样。第三篇开始解决"协同动作"：让它们以队形运动，这是多机器人系统最直观也最考验系统的能力。编队控制是整个第三篇的地基：领航-跟随（第 042 章）、队形变换（第 043 章）、避障（第 044/045 章）都建立在同一个问题上："如何让 N 个个体共同维持一个几何形状？"

这个问题在控制理论上有一个非常漂亮的答案：把编队写成图，把控制写成一致性协议，每台机器人只需要与它"邻居"交换位置，本地计算一个速度指令，整个系统就会收敛到期望队形。没有中心、没有全局规划，通信量与 N 成正比（全连接的对照方案才会达到 N²）。这个"局部规则产生全局秩序"的图景，正是分布式多机器人系统的灵魂。本章先把图与协议的骨架立起来，为后续章节的工程化加料（跟随者、变换、避障）。

核心原理

1. 编队的数学描述：图 + 偏移向量

队形可以完全由"谁与谁需要保持什么相对位置"来定义：

  • 编队图 G = (V, E)：顶点 V 是机器人，边 E 表示"这两台之间有明确的相对约束"（也是通信链路）；
  • 期望偏移 cij：机器人 j 相对 i 应该处于的位置（世界系下的向量；队形旋转时随参考航向一起转动）；
  • 编队误差：E = Σ(i,j)∈E ‖(xj − xi) − cij‖²。保持队形 = 让这个误差趋于零。

举例：三角形队形（边长 3 m）可以用三条边或两条边 + 一条定向约束定义；物理含义都很直接，每条边就像一根"隐形连杆"。注意图的连通性是硬前提：图不连通时，两个"图分量的形状"各自可以保持，但分量之间没有约束，队形整体可能相对漂移，甚至一分为二。

2. 四类编队方法：先选哲学再选算法

3. 一致性协议：从"拉齐"到"成形"

先看最简单的问题：让 N 台机器人的位置"拉齐"到同一个值（没有队形偏移）。每个机器人只和邻居通信，用这种局部规则更新自己：

ui = Σj∈N(i) ( xj − xi )，即 ẋ = −L x N(i) 是 i 的邻居集合；L = D − A 是拉普拉斯矩阵（D 度矩阵、A 邻接矩阵）

直觉：每台机器人朝"邻居们的平均位置"移动—平均位置的矢量 = 邻居位置之和经度归一化。拉普拉斯矩阵 L 把这张规则网络写成了线性系统：它的每一行和为 0（说明"全体平移"是零特征值对应的模式，一致性协议不改变整体质心）；第二小特征值 λ₂（代数连通度）决定收敛速度，λ₂ 越大，拓扑越"紧密"，队形收敛越快。链式拓扑（1-2-3-4）的 λ₂ 最小、收敛最慢；全连接的 λ₂ = N、收敛最快。这条定量关系解释了为什么"通信拓扑就是控制性能"：连不上，就快不了。

4. 带上队形偏移：让"拉齐"变成"成形"

要形成队形，把目标从"邻居的位置"改成"邻居位置加上期望偏移"：

ui = Σj∈N(i) ( (xj + cji) − xi ) cji 表示"i 应该在 j 的哪个方位"；偏移随编队参考航向旋转时，c 也要跟着旋转

收敛后 xi − xj = cij，即所有相对位置达标，队形形成且整体质心保持不动。如果需要队形整体朝某个方向前进，就再叠加一个"全局运动参考"（如领航者的速度）：每台机器人的总控制 = 队形维持项 + 运动参考项。这本"两步曲"是后面所有编队章节的主旋律。

5. 通信现实：拓扑、丢包与时延进入稳定性条件

理论里的"邻居"在工程里是"能收到消息的邻居"：

  • 丢包改变等效拓扑：连续丢包相当于边临时消失，λ₂ 下降、收敛变慢；极端情况（关键边长期断开）让图不连通，编队分裂。设计时要为"最坏丢包下的连通性"留余量（冗余边、多跳转发）。
  • 时延引入相位滞后：每个控制周期用到的邻居位置平均滞后半个周期以上（采样 + 传输 + 处理）。时延过大会让"拉向平均值"的动作过冲、震荡。工程结论：控制频率应显著高于编队动态的带宽（编队运动通常 < 1 Hz 带宽，控制 10–20 Hz 足够），增益先保守再上调。
  • 漂移的邻居位置：位姿估计本身有误差（第 029 章），队形精度上限由定位精度和相对位姿精度共同决定，1 cm 级融合定位对应分米级编队保持精度。
设计决策：为什么从"位置一致性"起步，"距离约束"的障碍在哪？

距离约束（每对邻居保持固定距离，忽略朝向）更符合"机械连杆"直觉，但存在翻转二义性（1 米距离可以是左边也可以是右边），需要额外的朝向约束消歧。位置一致性把方向也编码进偏移 c，天然无二义、数学线性、分析完备。工程上先做位置一致性，需要更灵活的"可伸缩队形"再考虑距离约束。

6. 数值算例：拓扑、λ₂ 与收敛步数

用片段 1 的函数量四种 4 节点拓扑的代数连通度，并把 λ₂ 换算成"误差衰减到 1% 所需步数"。离散更新 x ← x − k·dt·L·x 下，k = 0.8、dt = 0.05 s 时每步的衰减因子为 (1 − k·dt·λ₂)，四种拓扑的实测谱与步数如下：

拓扑边数λ₂单步衰减因子收敛到 1% 的步数对应时长
链式 0-1-2-330.5860.97661949.7 s
星形（1 号为中心）31.0000.96001135.6 s
环形 0-1-2-3-042.0000.9200552.8 s
全连接64.0000.8400261.3 s

表的读法有三层。其一，加一条冗余边收益很高：环形只比链式多一条边，收敛快 3.5 倍；星形同样只用 3 条边，却把链式的最慢短板抬高近一倍，因为链式的瓶颈在"信息要走满全程"。其二，时间常数 τ = 1/(k·λ₂) 是通用抓手：链式 τ = 1/(0.8 × 0.586) ≈ 2.1 s，环形 ≈ 0.63 s；把 τ 乘以 4.6（等于 ln 100）就得到"误差降到 1%"的时长，这个 4.6 倍率与拓扑无关，可以直接记作常数。其三，验收要按最慢拓扑写：链式 9.7 s 的收敛时间直接决定编队启动的等待窗口，任务时间预算按它算，不能只按平均情况凭感觉估。

边界情形：λ₂ 的收敛结论以"图连通"为前提；边失效让图裂成两个分量后，拉普拉斯矩阵出现两个零特征值，协议只能让每个分量各自拉齐，分量之间相对漂移失去约束（表现为队形从中间一分为二）。工程判据是把"最坏丢包组合下图的 λ₂ 仍不低于设计值的一半"写进部署检查项，不满足就补冗余边。另外，加权边（对信噪比高的邻居给大权重）会改变 λ₂ 的分布：它能加速强链路方向的收敛，但让收敛速度随信号质量起伏；调试期先用等权重，稳定后再考虑引入权值，并重新跑一遍上表。

增益上界的数量级也可以先算后调：理想离散更新要求 k·dt·λmax < 2，上表四个拓扑的 λmax 都在 3.4–4.0 量级，dt = 0.05 s 时理论增益上限 k < 2/(0.05 × 4) = 10。理论上限这么高、实践中却只取 0.5–1.0，原因在模型之外：控制环内嵌了邻居位姿的一拍滞后、采样抖动与执行器延迟，这些环节把有效相位裕度削掉大半。先取保守值，再用阶跃实验逐步上调，是唯一可靠的标定顺序。

为什么表里用离散步数：真实系统每 50 ms 用一次测量更新一次速度，本质是离散迭代，"连续收敛时间"只有在控制周期远小于 τ 时才近似成立。本课参数下 τ 最小 0.63 s，是周期的 12 倍以上，两种口径差距在 10% 以内；若你为了省算力把控制周期拉长到 200 ms，τ 最小的环形拓扑也只剩约 3 个周期，离散效应开始显现，收敛会明显慢于连续模型预测，这时要么恢复控制频率，要么改用 λ₂ 更大的拓扑。

实现思路与设计

  1. 定义队形与图：画出目标形状与"谁连谁"，标定期望偏移 c；检查连通性并留冗余边。
  2. 分配通信：每个机器人订阅邻居的位姿话题（第 021 章的共享机制），10–20 Hz；本地做一致性更新。
  3. 设计控制环：位姿误差 → 速度指令（先 P 控制起步，必要时加阻尼）；输出接入底层速度环（cmd_vel，第 020 章）。
  4. 加防护：邻居失联处理（保持上一目标或原地等待）、速度饱和（限幅）、安全距离（留给第 044/045 章）。
  5. 验收：编队误差曲线（稳态误差、收敛时间）、丢包场景下的行为、队形整体平移/旋转测试。

关键代码与解读

片段 1：拉普拉斯矩阵，把通信图写进线性代数

import numpy as np

def laplacian(n, edges, weights=None):
    """由边表构造拉普拉斯矩阵 L = D - A。
    edges: [(i, j), ...] 无向边（i、j 为 0 基编号）；weights: 每条边权重。"""
    A = np.zeros((n, n))
    for k, (i, j) in enumerate(edges):
        w = 1.0 if weights is None else weights[k]
        A[i, j] = A[j, i] = w            # 对称：边的权重对两端一致
    D = np.diag(A.sum(axis=1))           # 度矩阵：每行求和（加权度）
    L = D - A
    # 自检：行和必须为 0（"全体一起平移"是协议的不变模式，质心不动）
    assert np.allclose(L.sum(axis=1), 0.0), "拉普拉斯构造错误"
    # 代数连通度：第二小特征值，决定收敛快慢（链式最小、全连接最大）
    eig = np.sort(np.linalg.eigvalsh(L))
    return L, eig[1] if n > 1 else 0.0

edges = [(0, 1), (1, 2), (2, 0)]         # 三角形全连接：抗单边失效
L, lambda2 = laplacian(3, edges)
print(f"lambda2 = {lambda2:.3f}")        # 3 节点全连接：lambda2 = 3

解读：这段代码把"拓扑即性能"落到了数字上。（1）对称化（A[i,j] = A[j,i]）对应"无向通信"假设：编队协议默认邻居关系是对等的；单向链路（只能收不能发）会让矩阵不再对称，性质与稳定性分析都要重来，设计时优先保证对称。（2）行和为零的断言是免费的单元测试：它同时检查了度矩阵与邻接的构造逻辑；这个性质也是"质心守恒"的代数表达（一致性协议不改变整体平均位置）。（3）λ₂ 的工程读法：它是"图有多像全连接"的度量，也是收敛速率的下界（收敛时间尺度 ≈ 1/λ₂）。三角形全连接的 λ₂ = 3；换成三个节点排成链（0-1-2），λ₂ = 1，收敛慢三倍。部署前用这个小函数量一下你的队形图，比事后调试震荡便宜得多。

片段 2：一致性编队节点，只和邻居说话的机器人

class FormationNode(Node):
    """一致性编队环：订阅邻居位姿，计算队形维持速度，发布 cmd_vel。"""
    def __init__(self, rid, neighbors, offsets, gain=0.8, rate=20.0):
        super().__init__(f"formation_{rid}")
        self.rid = rid
        self.neighbors = neighbors           # [(nid, c)，c 为期望偏移]
        self.gain = gain
        self.poses = dict()                  # nid -> (x, y, theta)
        self.my_pose = (0.0, 0.0, 0.0)
        for nid, _ in self.neighbors:
            self.create_subscription(
                PoseStamped, f"/robot{nid}/pose",
                lambda m, n=nid: self.on_neighbor(n, m), 10)
        self.cmd = self.create_publisher(Twist, "cmd_vel", 10)
        self.create_timer(1.0 / rate, self.control)   # 20 Hz 编队控制环

    def on_neighbor(self, nid, msg):
        self.poses[nid] = (msg.pose.position.x, msg.pose.position.y,
                           quat_to_yaw(msg.pose.orientation))

    def control(self):
        ux = uy = 0.0
        alive = 0
        for nid, c in self.neighbors:
            if nid not in self.poses:
                continue                     # 邻居暂缺：该条边本周期不参与
            xj, yj, _ = self.poses[nid]
            # 期望本机位置 = 邻居位置 + 偏移（偏移随队形参考航向旋转）
            cx, cy = rotate_by_yaw(c, self.formation_heading())
            ux += (xj + cx) - self.my_pose[0]
            uy += (yj + cy) - self.my_pose[1]
            alive += 1
        if alive == 0:
            self.cmd.publish(Twist())        # 无邻居信息：停车等待（安全默认）
            return
        ux *= self.gain / alive              # 平均化：邻居多时不因增益失控
        uy *= self.gain / alive
        cmd = Twist()
        cmd.linear.x = clamp(ux, -1.0, 1.0)  # 限幅：底盘能力与安全边界
        cmd.linear.y = clamp(uy, -1.0, 1.0)
        self.cmd.publish(cmd)

解读：这个"只和邻居说话"的节点是分布式编队的最小完整实现。（1）控制律 Σ(期望位置 − 当前位置) / 邻居数 是一致性协议的归一化版本：除以邻居数让增益与拓扑规模解耦，否则邻居多的机器人"步子大"，编队一启动就过冲。（2）邻居暂缺（丢包或未启动）时该边跳过、其余边照常：这是分布式协议对抗丢包的天然弹性；但所有邻居都缺时立即停车，"没有信息"与"信息说不动"是两回事，前者的安全默认是静止。（3）偏移随队形参考航向旋转（formation_heading）：队形整体转弯时，"我在你左侧"这些相对方位要跟着转，否则队形一转向就塌成一条线，这是队形跟随与坐标系的第一次交手（第 024 章的世界系输出在这里被消费）。（4）限幅与 20 Hz 控制频率：编队动态远慢于控制频率，这给时延与计算抖动留了大余量。注意真实系统里速度指令还要经过安全层（急停、避障，第 044 章），本节点直接发 cmd_vel 只是为了聚焦一致性逻辑。

片段 3：收敛性验证小仿真，先离线跑，再上真机

import numpy as np

def simulate(n=4, edges=None, offsets=None, steps=600, dt=0.05, k=0.8):
    """离散一致性编队仿真：验证拓扑与增益下的收敛行为。"""
    edges = edges or [(0, 1), (1, 2), (2, 3), (3, 0)]     # 环形拓扑
    x = np.random.uniform(-2, 2, size=(n, 2))             # 随机初始位置
    hist = []
    for t in range(steps):
        u = np.zeros_like(x)
        for i, j in edges:
            c = offsets.get((i, j), np.zeros(2))          # 队形偏移
            u[i] += (x[j] + c) - x[i]
            u[j] += (x[i] - c) - x[j]                     # 反向边偏移取负
        x += k * dt * u / 2.0                             # 每边两端各担一半
        err = 0.0
        for i, j in edges:
            c = offsets.get((i, j), np.zeros(2))
            err += np.linalg.norm((x[i] - x[j]) - c) ** 2
        hist.append(err)
    # 收敛判据：误差在最后 100 步内下降小于 1%，且终值足够小
    tail = hist[-100:]
    converged = (hist[-1] < 1e-3) and (abs(tail[0] - tail[-1]) < 1e-3)
    return np.array(x), np.array(hist), converged

offsets = {(0, 1): np.array([2.0, 0.0])}                  # 0 在 1 的右侧 2 m
pos, err_hist, ok = simulate(offsets=offsets)
print(f"converged={ok}, final_err={err_hist[-1]:.6f}")
print("前 5 步误差:", np.round(err_hist[:5], 3))

解读：这个小仿真把"上真机前先验证"的工程习惯具体化。（1）初始位置随机生成：一致性协议的正确性必须对任意初始条件成立（它本来就是分布式收敛算法），随机化能抓出"特定对称配置下才收敛"的假阳性。（2）每边两端各承担一半修正（u[i] 与 u[j] 分别更新）：这与第 028 章位姿图松弛的对称拉拽是同一模式，分布式协作的通用握手：每个局部决策各让一步。（3）收敛判据同时检查"终值小"与"最后 100 步变化小"：只看终值会误判"缓慢漂移还未停止"，只看变化率会误判"早早就停滞在错误的位置"。（4）把它作为真机前的第一道闸：改拓扑、改增益、改偏移，先跑一轮短仿真看误差曲线；震荡或发散的问题在这一步拦下，比在真机上追车安全得多，也便宜得多。

常见坑

  • 拓扑不连通：图裂成两部分，各自保持"局部形状"、整体漂移甚至走散。修复：设计冗余边并监控关键边心跳；λ₂ 过小时主动降速。
  • 增益相对控制周期过大：离散化后过冲震荡（k·dt 与 λ₂ 的乘积超过稳定区间）。修复：先保守增益，仿真扫描 k 的稳定上界，再按真机微调。
  • 坐标系没统一：偏移用本体系、位置用世界系，队形随航向"旋转塌陷"。修复：一致性计算全程世界系；队形参考航向显式广播。
  • 把一致性环当避障用：协议不感知障碍，两台机器人对撞点照样收敛。修复：安全层独立（第 044/045 章），编队环的输出经过安全仲裁才到底盘。
  • 邻居位姿不新鲜就用：拿 500 ms 前的邻居位置做控制，等效于大时延输入。修复：位姿带时间戳，超期则跳过该邻居（片段 2 的暂缺处理）。

小结

  • 编队 = 图 + 期望偏移；保持队形 = 最小化"实际相对位置与期望偏移"的平方误差。
  • 四类方法各有哲学：领航-跟随简单、虚拟结构刚性、行为法灵活、一致性可扩展；工程上混合使用。
  • 一致性协议 ẋ = −Lx：局部平均规则让全局拉齐；λ₂（代数连通度）决定收敛速度，通信拓扑即控制性能。
  • 带上偏移即成队形；叠加全局运动参考即可整体行进；丢包与时延通过"跳过-停车"两段式与保守增益吸收。
