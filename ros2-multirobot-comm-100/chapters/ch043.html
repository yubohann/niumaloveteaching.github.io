第三篇 · 协同控制与任务协同

第 043 章：多机器人编队变换

从纵队切成楔形、从楔形收成圆环：用"队形模板 + 仿射变换"描述目标形状，用最优分配避免对撞，用统一完成时间保证全队同步到位。

  • 主题：协同控制 / 队形管理
  • 关键机制：形状模板、匈牙利分配、同步时间参数化、版本化队形指令
  • 预计学时：55 分钟
  • 前置章节：第 042 章

学习目标

  • 理解"队形 = 模板 + 仿射变换"的建模方式，会用平移、缩放、旋转三个参数描述任意队形目标。
  • 掌握编队变换的三个子问题：槽位分配、轨迹生成、碰撞规避，并说清每个子问题的输入输出。
  • 会使用匈牙利算法求解槽位分配，能比较它与贪心分配的差异，理解"为什么贪心会引起对撞"。
  • 掌握同步时间参数化的原理：先定全队统一完成时间，再让每台机器人按同一时间轴生成轨迹。
  • 能设计队形指令的消息结构与版本机制，避免变换过程中不同机器人执行不同代次的队形。

背景与动机

第 042 章让机器人保持固定相对偏移。真实任务里队形要变：走廊里必须排队成纵队，开阔地展开成楔形，围住目标时收成圆环。如果只是"每台机器人各自朝新偏移点直着走"，会遇到三个工程问题：谁去哪个位置（分配错了会对撞）、什么时候到达（各自尽快会队员散乱、先到者挡路）、路上怎么不撞（直线交叉是常态）。

编队变换是把"队形管理"从固定偏移提升为动态队形库的最小系统。它也是后续协同编队避障（045）、围捕（055）与覆盖（061）的公共组件，那些任务里"切换到某形状并同步到位"会被反复调用。

核心原理

1. 队形模板与仿射变换

把队形定义成一组"单位尺度"的模板点 F = {f1, …, fN}，每个点的实际世界坐标用三个参数生成：

pi = c + s · R(α) · fi c 队形中心、s 缩放因子、α 方位角；先缩放、再旋转、最后平移，顺序不可交换

三种典型模板各有物理含义：纵队的 f 是一条线上等距点，间距 1.6 m；楔形的相对夹角固定 60°，缩放时整体变大变小但形状不变；圆环的 f 是单位圆上的等分点，缩放因子直接就是半径。模板化让"换队形"变成三参数（c, s, α）的连续变化，N 台机器人共用同一组参数各自计算目标点，存储、带宽与一致性三个问题一次解决。

2. 槽位分配：为什么必须全局最优

变换时每台机器人要从当前位置去往某个槽位。把机器人 i 到槽位 j 的距离记为代价 Cij，分配问题就是找一个一一映射使总代价最小，这是标准的线性分配问题，匈牙利算法（Hungarian algorithm）在 O(N³) 内给出全局最优解。为什么不能贪心（每次让"最近的一对"先配对）？因为贪心的局部选择会让两对机器人交叉换位：

贪心：rA→槽 1、rB→槽 2，两条直线交叉 → 中途相遇 匈牙利：rA→槽 2、rB→槽 1，代价略高但轨迹不交叉

注意：最小总距离并不严格等于"无交叉"。在一条线上交换两两位置，怎么做都会交叉；对平面队形，匈牙利把交叉对压到了最少，剩余交叉再用第三部分的时间错峰处理。N ≤ 20 时 N³ 的运算量对现代计算单元可忽略，没有理由用次优解。

3. 同步时间参数化：一起出发、一起到位

最省事的方案是每台机器人以最大速度奔向目标，"先到先等"。问题是先到者会占住槽位，后到者穿过正在展开的队形时冲突概率大增，且全队到位时间不可控。更好的方案是统一完成时间 T = maxi(Ti)：先按各自动力学算单机最快时间 Ti，取最大者作为全队节拍，其余机器人放慢，轨迹用五次多项式 s(τ) = 10τ³ − 15τ⁴ + 6τ⁵（τ = t/T ∈ [0,1]）归一化，两端速度与加速度都为零，避免启动与停止的冲击。距离短的机器人速度自然更慢，全队同时到位、同时进入"队形保持"状态。

五次多项式的另一个优点是与第 042 章的控制律天然衔接：变换结束的瞬间速度为零，随后队形保持控制器从前馈状态平滑接管，不会出现速度阶跃。

4. 变换中的碰撞：三种处理次序

按代价从低到高：时间错峰，给剩余交叉的机器人分配不同的出发时刻（等待几秒即可），代价是总时长拉长；空间绕行，在直线路径上加一个固定侧偏的中间点，让两条路径分离；优先级通行，约定同时到达冲突点时低优先级等待。实战里的默认组合是"匈牙利去交叉 + 同步轨迹 + 局部避让兜底（第 044 章）"，不要指望规划层消灭所有冲突。

5. 队形指令的一致性：版本号与生效时间

变换指令是全队广播，但网络延迟不均：可能出现两台机器人已经切换、另两台还在旧队形的瞬间。消息里必须带队形版本号（单调递增）与生效方式：版本号防止旧消息乱序覆盖新指令；"收到即生效"配合统一时钟可以近似同步，时钟不可靠时用"版本号 + 全队确认计数"作为进入阶段的依据。指令话题用 Transient-local 持久性，让中途重启的机器人一上线就拿到当前队形。

6. 数值算例：从纵队到圆环的时间账

场景：4 台机器人排成纵队（间距 1.6 m，队形中心 (−2.4, 0)），变换成半径 1.5 m 的圆环，中心不动。圆环四槽位取 135°、45°、−45°、−135° 四个方位，若按编号顺序（0 号在队首）直接对位，各机的直线位移是：

机器人起始位目标槽位直线位移
0 号（队首）(0, 0)(−3.461, 1.061)3.62 m
1 号(−1.6, 0)(−1.339, 1.061)1.09 m
2 号(−3.2, 0)(−1.339, −1.061)2.14 m
3 号（队尾）(−4.8, 0)(−3.461, −1.061)1.71 m

五次多项式轨迹有两个硬约束：峰值速度 1.875·d/T、峰值加速度 5.7735·d/T²（d 为位移、T 为完成时间）。代入 vmax = 0.8 m/s、amax = 0.5 m/s²：0 号需要 T = max(8.48, 6.46) = 8.48 s，2 号 5.02 s，3 号 4.44 s，1 号 3.55 s。取全队节拍 tcommon = 8.48 s 后，1 号的实际峰值速度只有 0.24 m/s，"慢吞吞地走完 1 米"。这个例子说明统一节拍的时间由最慢者决定，也让"槽位分配"的价值浮出水面。

把编号对位换成全局最优分配（匈牙利求解），一种最优配对是 0→右上、1→右下、2→左上、3→左下，四个位移降为 1.708 / 1.093 / 1.093 / 1.708 m，最长者 1.708 m，节拍 T = max(4.00, 4.44) = 4.44 s。同一场景、同一轨迹模板，只把对位方式从"按编号"改成"按最小位移"，全队完成时间从 8.5 s 缩到 4.4 s，这就是第 2 节"分配是变换第一子问题"的定量版本。

分配之外还有一道几乎免费的安全检查：把配对后的直线路径两两做线段相交测试。按编号对位时，0 号与 1 号的路径在 (−1.49, 0.46) 处相交，最近距离 0.000 m，两台机器人会在中途迎面相遇；换成上面的最优配对后，六对路径全部不相交，最小间距 0.994 m（出现在 2 号与 3 号之间），直接满足 0.5 m 的安全余量。相交测试是 O(N²) 的纯几何计算，在变换开始前不到 1 ms 就能完成，它把"变换途中互相卡住"从运行时故障降级为出发前的纸面检查。

边界与失效：上面的约束像一对剪刀，改参数时要同时看。若把 scale 或槽位半径改大，位移变大而 T 未变，加速度峰值可能先触顶（正比于 d/T²），表现为起步瞬间轮子打滑、里程漂移；若 T 取得过于保守（例如 12 s），全队像慢动作，通道占用时间白白拉长。把 T 设到约束允许的最小值，再按实测放宽 10–20% 即可。另一个失效模式是分配翻转：定位噪声让最小位移配对在两个近似对称的解之间反复跳，20 次重复变换里若配对发生变化超过 2 次，就应给代价矩阵加 5% 的对称扰动或引入迟滞。

7. 五次多项式的系数从哪里来

s(τ) = 10τ³ − 15τ⁴ + 6τ⁵ 由六个边界条件唯一确定，能够完整推导：s(0) = 0、s(1) = 1、s′(0) = s′(1) = 0、s″(0) = s″(1) = 0，六个条件锁定六个系数。对 τ 求一阶与二阶导可以算出两个峰值系数：s′ 在 τ = 0.5 处达到峰值 1.875，s″ 在 τ = (3 − √3)/6 ≈ 0.211 处达到峰值 5.7735。这两个数字就是前面算例里 1.875·d/T 与 5.7735·d/T² 的出处，量纲自洽：s′ 无量纲，乘以 d/T 得速度；s″ 无量纲，乘以 d/T² 得加速度。若把轨迹改成三次多项式（只有四个边界条件），两端加速度不为零，启停会带上冲击；五次是"位置、速度、加速度"全平滑的最低阶插值，这就是它在队形变换里成为默认选择的原因。

三个子问题的成本可以一起估：分配（匈牙利）N = 20 时约 20³ = 8000 次基本运算，微秒级；轨迹生成（每条 50 点、五次多项式）几十微秒；相交检测 O(N²) 对 N = 20 是 190 对线段，同样是微秒级。整条变换流水线的中央开销在毫秒量级，真正的时延来自消息与执行（ACK 汇总、轨迹跟踪）。"会不会算不过来"不是变换系统的瓶颈，"有没有人没收到、没跟上"才是，工程预算和监控都应该花在后者上。

失败回退写成状态机上的一条明确路径：任意成员在 TRANSFORMING 超过 tcommon + 5 s 仍未到位，管理器把该台标记为 LAGGING，其余成员进入 SETTLING；LAGGING 恢复后单独接收"继续到原目标"的指令，不用全队重来。放弃变换（回退）只在新障碍出现在目标区这类几何前提被破坏时触发，且规定"先到新队形再统一回退"，避免半途折返制造二次冲突，这条规则值得作为默认策略固化进配置。全套开关（超时、滞回、回退条件）都放进队形管理器的参数文件，改行为不动代码，这是第 042 章"配置化"原则在队形管理上的延伸。

实现思路与设计

落地成一个"变换管理器 + 每机执行器"的两层结构：

  1. 变换管理器（可由某台机器人兼任）维护队形模板库与当前状态，接收任务层的变换请求，计算分配与同步轨迹，广播带版本号的队形指令。
  2. 队形指令：自定义消息 FormationCmd，字段含 version、shape、center、scale、alpha、t_common、stamp。意象是"广播意图，各机自行推导目标点"：每台机器人用同一个模板与参数自行算目标，指令体积与队数无关。
  3. 执行器：收到指令后按本地序号校验版本，用五次多项式生成 5 s 轨迹（0.1 s 采样 50 点），50 Hz 跟踪；到位误差小于 0.15 m 后上报 ACK。
  4. 阶段机：IDLE → TRANSFORMING（执行轨迹）→ SETTLING（队形保持控制器接管）→ DONE。管理器收齐全队 ACK 或超时 8 s 视为完成。
  5. QoS：队形指令 Reliable + Transient-local（新加入者补发）；位姿反馈 Best-effort（高频、可丢）。
  6. 验收：楔形→圆环变换全队到位误差小于 0.2 m；变换过程中最小机器人间距大于 0.5 m；同场景重复 20 次无碰撞、无死锁。

关键代码与解读

片段 1：模板库与仿射变换

import math
import numpy as np

# 模板点是"单位尺度"坐标：实际队形 = 缩放 -> 旋转 -> 平移
TEMPLATES = {
    "column": np.array([[0.0, 0.0], [-1.6, 0.0], [-3.2, 0.0], [-4.8, 0.0]]),
    "wedge":  np.array([[0.0, 0.0], [-1.6, 1.0], [-1.6, -1.0], [-3.2, 0.0]]),
    "circle": np.array([[math.cos(math.pi * k / 2), math.sin(math.pi * k / 2)]
                        for k in range(4)]),
}

def to_world(template, center, scale, alpha):
    """模板 -> 世界目标点：先缩放、再旋转、最后平移。"""
    c, s = math.cos(alpha), math.sin(alpha)
    rot = np.array([[c, -s], [s, c]])       # 2x2 旋转矩阵
    pts = np.asarray(template) * scale      # 圆环模板：scale 即半径
    pts = pts @ rot.T                       # 旋转必须右乘转置，避免转反方向
    return pts + np.asarray(center, dtype=float)

解读：三个模板共用一个变换函数，说明"队形库"是可以无限扩充的数据，扩充时不需要动代码。注意注释里强调的运算顺序：先缩放再旋转与先旋转再缩放对形状本身其实等价（都是线性），但与平移组合时顺序绝不能错，先平移后旋转会让队形绕着 center 转圈，得不到整体转动的效果。圆环模板四等分点用 math.pi/2 步进生成，扩展到 N 台只需把 4 换成 N，这正是"参数化描述"的价值。

片段 2：槽位分配，贪心与匈牙利

import numpy as np
from scipy.optimize import linear_sum_assignment   # 可选依赖，或自行实现匈牙利

def cost_matrix(robot_xy, slot_xy):
    """行=机器人、列=槽位，元素=两点直线距离。"""
    diff = robot_xy[:, None, :] - slot_xy[None, :, :]
    return np.linalg.norm(diff, axis=2)

def assign_greedy(C):
    """贪心：每次配对当前最近的机器人-槽位。可能产生交叉换位。"""
    C = C.copy()
    pairs = {}
    for _ in range(C.shape[0]):
        i, j = np.unravel_index(np.argmin(C), C.shape)
        pairs[int(i)] = int(j)
        C[i, :] = np.inf                  # 该机器人已分配
        C[:, j] = np.inf                  # 该槽位已占用
    return pairs

def assign_optimal(C):
    """匈牙利：O(N^3) 全局最小总距离，把交叉换位压到最少。"""
    rows, cols = linear_sum_assignment(C)
    return {int(r): int(c) for r, c in zip(rows, cols)}

解读：两个函数故意放在一起，方便你写一段仿真直接对比。贪心版的问题不在"总距离更长"，而在局部最优解会挑出交叉配对，两条直线轨迹交叉，机器人中途迎头相遇，把本属于控制层的小问题放大成安全事件。匈牙利版注释里也说明了它的局限："压到最少"不等于消灭。若场景就是两两换位（工作在一条直线上），任何分配都交叉，此时必须在时间轴上加等待窗口，这就是片段 3 的同步轨迹要配合做的事。linear_sum_assignment 是 scipy 的稳定接口，若不想引入依赖，用 20 行以内的经典匈牙利实现即可，行为一致。

片段 3：全队统一的五次多项式轨迹

def sync_trajectory(p_now, p_goal, t_common, n=50):
    """生成 [0, t_common] 上归一化的同步轨迹：两端速度、加速度为零。"""
    p_now, p_goal = np.asarray(p_now), np.asarray(p_goal)
    d = float(np.linalg.norm(p_goal - p_now))
    u = (p_goal - p_now) / d if d > 1e-6 else np.zeros(2)  # 直线方向
    ts, xs, vs = [], [], []
    for k in range(n + 1):
        tau = k / n
        # 位置比例 s(tau)：5 次多项式，s(0)=0, s(1)=1，导数为零
        s = 10 * tau**3 - 15 * tau**4 + 6 * tau**5
        ds = 30 * tau**2 - 60 * tau**3 + 30 * tau**4     # ds/dtau
        ts.append(tau * t_common)
        xs.append(p_now + u * d * s)
        vs.append(u * d * ds / t_common)                 # 链式法则还原量纲
    return np.array(ts), np.array(xs), np.array(vs)

# 管理器侧：先算各自最快时间，再取全队最大者作为统一节拍
# T_i = trapezoid_time(d_i, v_max=0.8, a_max=0.5)
# t_common = max(T_i for i in robots)   # 距离短的自然自动放慢

解读：这段代码的核心是"时间归一化 + 统一节拍"。位置比例 s(tau) 只与归一化时间有关，物理量纲由 u * d 和 t_common 还原：ds/dtau / t_common 就是速度。这样同一份代码服务所有机器人，改变 t_common 只影响快慢、不影响轨迹形状。末段注释说明了节拍的决定方式：让最慢的机器人决定 t_common，其余按比例放慢，这正是"同步到位"的实现，与控制层的"到位后交棒"无缝衔接。

常见坑

  • 贪心分配引起对撞：变换开始后某两台机器人迎面走近、互相顶住。症状是局部避让频繁触发、变换超时。修复：改用匈牙利分配；剩余交叉用出发时刻错峰。
  • 各自"尽快到位"：先到的机器人已按新队形站定，后到的要穿过队列，冲突增多且全队到位时间不可控。修复：统一完成时间 + 五次多项式，所有机器人同一时刻收敛。
  • 线性插值导致速度跳变：变换开始和结束的瞬间速度从 0 跳到上限，轮式底盘打滑、里程计漂移。修复：用两端速度为零的多项式轨迹；若沿用线性插值，至少给速度加斜坡限幅。
  • 左右手系搞反：队形整体镜像，机器人在转弯时朝与预期相反的一侧展开。诊断：让领航者左转 90°，检查原"左后"位置是否确实出现在左侧。修复：模板点统一采用"x 前、y 左"约定，并在单元测试里断言一次镜像用例。
  • 版本号缺失导致指令乱序覆盖：WiFi 抖动下旧队形消息后到达，两台机器人退回旧队形。修复：消息带单调递增版本号，执行器只接受更高版本；配合 Transient-local 让新上线机器人拿到当前版本。

练习与思考

  1. 4 台机器人从纵队（间距 1.6 m）变换成圆环（半径 1.5 m）、队形中心原地不动。用五次多项式轨迹估算全队完成时间：设 vmax = 0.8 m/s、amax = 0.5 m/s²，最长位移的机器人是谁？★
    提示
    先画纵队与圆环槽位的相对位置，最长位移约 2.5–3.5 m 量级；t≈位移/平均速度，梯形曲线平均速度约 0.6·vmax，再加两端加速段，估 5–7 s。
  2. 把圆环缩放因子从 1.5 改成 0.9，不改变模板。预测：分配结果会变吗？碰撞风险升高还是降低？给出两条校验标准。★
    提示
    分配取决于"当前位置到槽位"的代价矩阵，缩放改变所有槽位位置，分配可能翻转；半径 0.9 m 时四台机器人圆周间距约 1.27 m，仍大于 0.5 m 安全余量，但收缩过程路径更拥挤，需检查交叉数。
  3. 手算一个 3×3 分配例子：机器人位置 A(0,0) B(1,0) C(0,1)，槽位 1(1,0) 2(0,1) 3(2,2)。分别用贪心与匈牙利求匹配，并画出直线轨迹判断谁交叉。★★
    提示
    代价矩阵对角线放置。贪心首先配对距离 0 的两对，剩下 C→3 距离 √8 约 2.83；匈牙利可给出总代价最小的另一组。把两组的线段画在纸上，交叉一目了然。
  4. 设计一个"无交叉 + 同步 + 可回退"的变换调度：当剩余交叉无法被分配消除时，用出发时刻错峰或侧偏中间点处理；要求写出判定条件与时间预算，并说明回退策略（变换失败回到原队形还是继续）。★★★
    提示
    先按匈牙利分配算交叉数；对每条交叉对，比较"错峰等待 2–4 s"与"侧偏 0.6 m 绕行"的时间代价，取小者；回退策略建议"中途不打折、到新队形后再统一回退"，避免半途折返制造二次冲突。
  5. 给队形指令设计完整的消息与状态机：字段、QoS、版本规则、ACK 汇总与超时处理；画出 IDLE/TRANSFORMING/SETTLING/DONE 四态的迁移图，标出每条迁移的触发事件。★★★
    提示
    ACK 汇总注意容错：一台丢失 ACK 不应卡死全队，超时后把该台标为 LAGGING、其余进入 SETTLING；LAGGING 恢复后单独补发指令，全队无需重来。

小结

  • 队形 = 模板点 + 仿射三参数（中心 c、缩放 s、方位 α）；换队形只需改参数，指令体积与队数无关。
  • 槽位分配用匈牙利算法求全局最优，其价值首先是压掉交叉轨迹、避免对撞，而不只是省几米路程。
  • 同步时间参数化：全队统一完成时间 T = max(Ti)，五次多项式轨迹两端速度加速度为零，杜绝切换冲击。
  • 队形指令必须带版本号与持久性 QoS；ACK 汇总要有超时容错，一台掉线不能卡死全队。
  • 变换过程中仍会有残余冲突，最终要靠下一章的多机器人避障协同兜底，规划消解大头、反应式避让处理尾数。
