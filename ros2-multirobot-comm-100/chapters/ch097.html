第五篇 · 科研进阶与协同机制

第 097 章：多机器人协同路径机制与规划算法

MAPF 算法谱系的完整地图：从联合空间 A* 的地面真值、CBS 的两层最优，到 SIPP 的安全区间与 LNS/PIBT 的大规模近似，以及"完备、最优、快"三者为何不可兼得。

  • 主题：协同路径规划算法（MAPF 谱系与性质）
  • 关键机制：时空 A*、SIPP 安全区间、CBS 约束树、有界次优 ECBS、LNS/PIBT 规模化
  • 预计学时：65 分钟
  • 前置章节：第 096 章

学习目标

  • 掌握 MAPF（多智能体路径寻找）问题的标准定义与三类算法承诺：完备最优、有界次优、无保证快解。
  • 理解时空 A* 与 SIPP 的区别与联系：状态 (x, y, t) 的搜索如何被"安全区间"压缩。
  • 掌握 CBS 两层结构（冲突驱动的约束树 + 单机时空规划）的最优性论证骨架与瓶颈失效模式。
  • 知道把离散 MAPF 搬到连续世界的三个工程转换：栅格化、速率/运动学约束、后平滑与轨迹跟踪。
  • 能设计 MAPF 基准实验：网格类型 × 密度 × 规模的成功率与代价曲线，用"性能包络"替代"最好成绩"汇报。

背景与动机

第 084 章从系统工程角度处理了协同运动规划：冲突检测、优先级、预约表、重规划触发。那一章问的是"怎么把系统跑起来"；本章回到算法本体的科研问题：MAPF 这个问题的解空间有多大、有哪些解法谱系、各自的承诺（保证）是什么、在什么规模上会失效？这是协同规划领域的核心学术地图，也是你写论文时"相关工作"与"方法对比"两节的直接素材。

为什么不能只用一个"最好"的算法？因为三者不可兼得：完备性（有解就找得到）、最优性（找的是最好的）、效率（快），这是规划领域的不可能三角。联合空间 A* 完备且最优但状态数随机器人数指数爆炸；CBS 在小规模保持最优却在瓶颈场景的分支树爆炸；优先级规划快如闪电但可能死锁（不完备）；LNS 与 PIBT 能吞下几百台但只给"还行"的解。工程与科研的功夫都在这张谱系上选点：先明确"你能接受什么保证"，再选算法。

与相邻章节：第 084 章是"用算法"（工程侧），本章是"懂算法"（科研侧）；第 098 章会把本章的基准实验纳入统一的实验设计方法。

核心原理

1. 问题与评价量：MAPF 的标准提法

标准 MAPF 问题：网格地图 + N 个智能体，每个有起点与终点；每步（时间片）智能体执行一个动作（上下左右移动或等待）；要求任意时刻任意两个智能体不同格、且不存在"交换格子的对穿"（边冲突）。解 = 一组无冲突的时空轨迹；常用目标：总代价（sum-of-costs，所有轨迹步数之和）或完工时间（makespan）。第 084 章讲过的冲突类型（顶点/边）在算法语境里有精确名字：它们正是所有 MAPF 算法要消灭的两类事件。

三个承诺的不可兼得：完备（有解 ⇒ 找到）· 最优（找到的是代价最小）· 快（多项式级扩展） MAPF 的 NP 难本质：一般情形下不存在同时拥有三项的算法；谱系上每个算法放弃什么，必须显式知道

2. 联合空间 A*：唯一的"地面真值发生器"

最朴素的解法把全队看成一个联合体：状态 = 所有智能体的位置向量加时间。它的状态数是单机的 指数次幂，10×10 网格上 4 台机器人就有 (100×T)⁴ 量级，只适合 2–6 台的验证。但它在科研里不可替代：小规模上它是"标准答案发生器"，你在论文里报告"我们的近似算法距离最优平均差 7%"，那个"最优"就是联合空间求解器在小实例上算出来的。养成习惯：任何近似 MAPF 算法的起步验证，都先拿它对照。

3. 时空 A* 与 SIPP：把"动态"展平，再用区间压缩

单机在"别人轨迹已知"的环境里规划，就是时空 A*：状态加上时间维 (x, y, t)，别人的轨迹变成"带时间的墙"（某格在某时刻被占）。两个细节决定成败：（1）等待动作（原地不动）必须存在，瓶颈场景的解法常常是"让对方先过，我等一拍"，没有等待动作的解空间是残缺的；（2）时间上限要截断，无解时算法必须能报告"超时无解"，不允许无限搜索。

SIPP（Safe Interval Path Planning）是时空 A* 的著名优化：观察发现，一个格子的占用时刻往往连成少数几段，某格只在 t ∈ [3, 5] 被占，那么"空闲"其实是两段长区间 [0, 2] 与 [6, ∞)。SIPP 把搜索状态从 (x, y, t) 换成 (x, y, 安全区间)，同一格子在多个空闲段内只被展开"一段一次"，而时空 A* 对每个时刻都展开一遍。在长走廊、稀疏冲突的环境里，SIPP 的扩展节点数能比时空 A* 少一个数量级；这正是"算法改进"在文献里的典型形态：问题不动，换的是状态表示。

4. CBS：两层结构如何保住最优性

CBS（Conflict-Based Search，基于冲突的搜索）是 MAPF 最优解法的里程碑，结构两句话说清：底层为每个智能体在其"约束集合"下做单机时空 A*（约束 = "某时刻不许在某格"）；顶层维护一棵"约束树"，从无约束的各自最优解出发，检测第一条冲突，然后分裂出两个子节点，分别给冲突的两个智能体加上"避开对方"的约束并重新规划它。反复直到某节点的解无冲突。为什么它保持最优（骨架论证）：（1）底层单机规划在约束下最优；（2）顶层是对"约束组合"的穷举式展开，任何可行解都对应某条约束路径，且先展开的节点按代价有序，因此第一个无冲突的叶节点就是全局最优。它在"开阔 + 中等密度"网格上能处理数十台；但在地图存在瓶颈（窄门、单车道）时，冲突集中在同一批格子上，约束树呈爆炸式分裂，这时必须换有界次优版本（ECBS：允许代价乘以系数 w，用"焦点搜索"优先展开接近下界的节点）或放弃最优性（优先级/LNS）。

算法承诺适用规模（开放网格量级）失效模式
联合空间 A*完备 + 最优2–6 台（验证用）状态指数爆炸
CBS完备 + 最优（标准假设）数十台（开阔）瓶颈处约束树爆炸
ECBS（w = 1.2–1.5）完备 + w 有界次优数十台（含瓶颈）w 大时解质量差
优先级 + 预约无（可能死锁）数百台低优先级被堵死
LNS / PIBT 类无（经验有效）数百至上千解质量与成功率随密度降

5. 从离散 MAPF 到连续世界：三个转换

论文算法都在网格上，车队在物理世界跑，转换要过三关：（1）栅格化，格子边长 0.25 m 级（≥ 车身宽度的 1.2 倍并含安全余量）、时间片 0.2 s 级（≈ 格子边长 ÷ 速度量级）；太粗会切掉可行解，太细会炸规模。（2）速率与运动学，标准 MAPF 假设单位速度，多速度机器人要上"时间索引带速率"的变体；轮式底盘的转向约束让"任意折线"不可跟随，通常做法是 MAPF 出离散路径 → 转成航向连续的平滑轨迹（贝塞尔/样条）→ 交给跟踪控制器（第 083 章），平滑过程可能重新引入碰撞（切内角），必须过一遍第 084 章的冲突复检。（3）确认与兜底：离散解到连续执行的误差（定位、跟踪偏差）用"物理安全层"兜底（第 093 章 CBF/紧急刹车），算法层的保证不直接等价于物理安全。

实现思路与设计

算法选型决策表（先问承诺，再问规模）：

基准实验设计（性能包络）

MAPF 的基准实验有三条黄金纪律：（1）网格类型与密度，空地图、随机障碍（10%/20%/30%）、仓储货架图、瓶颈图（窄门）；密度决定冲突频率，是首要自变量。（2）规模扫描，每类网格扫 N = 10/20/30/50（每档 ≥ 50 个随机实例，固定种子）。（3）三指标，成功率（有解找到的比率）、解质量（SOC 相对 CBS/最优的比值）、运行时间（P50/P99）。汇报方式是"性能包络"：画成功率-规模曲线，标注每条曲线在哪里跌破 95%，避免只报"我们最大能跑 100 台"的峰值成绩。

参数起点：CBS 类算法加节点上限（如 10⁵ 次扩展）后转降级策略；ECBS 的 w 从 1.2 起步（质量损失约 5–10%、速度升 2–10 倍），按需上调到 1.5；优先级规划的顺序启发式用"起点到终点的距离降序"（远的先规划，避免被近的堵住）；预约表沿用第 084 章的粒度并加 TTL。

关键代码与解读

片段 1：时空 A*，等待动作与时空占用查询

import heapq

def spacetime_astar(start, goal, blocked, t_max=60):
    """状态 (x, y, t)；blocked(x, y, t) 查询"他人轨迹占用的时空格"。
    动作集含等待 (0, 0)：瓶颈场景常常要靠"等一拍"解冲突。"""
    h = lambda x, y: abs(x - goal[0]) + abs(y - goal[1])   # 一致启发式：不过估
    g = {(start[0], start[1], 0): 0}
    parent, heap = {}, [(h(*start), start[0], start[1], 0)]
    while heap:
        _, x, y, t = heapq.heappop(heap)
        if (x, y) == goal:
            path, node = [], (x, y, t)
            while node in parent:                 # 回溯：路径含"等待"节点
                path.append(node[:2])
                node = parent[node]
            return [start] + path[::-1]
        if t >= t_max:
            continue                              # 时间上限：超时即放弃该分支
        for dx, dy in ((1, 0), (-1, 0), (0, 1), (0, -1), (0, 0)):
            nxt = (x + dx, y + dy, t + 1)
            if blocked(*nxt):
                continue                          # 动态障碍展平为"时空墙"
            ng = g[(x, y, t)] + 1
            if ng < g.get(nxt, 1 << 30):
                g[nxt] = ng
                parent[nxt] = (x, y, t)
                heapq.heappush(heap, (ng + h(nxt[0], nxt[1]), *nxt))
    return None        # 时限内无解：把"无解"当作正常返回值交给上层

解读：这段代码是本章所有算法的"低层引擎"，四个细节都值得盯。（1）动作集里的 (0,0)：等待是一等公民，不是补丁，删掉它，很多实例会从"可解"变成"无解"。（2）blocked 采用函数接口，替代常量集合：它把"别人轨迹"封装成查询接口，这条接口设计让同一个 A* 同时服务于优先级规划（他人的完整轨迹）与 CBS（约束集合 + 他人的解）两种上层，避免重复实现。（3）h 用曼哈顿距离且不涉时间：对含等待动作的时空图，曼哈顿距离仍是一致下界（时间只增不减，位置每步最多近一格），启发式"守住不过估"是 A* 最优性的前提。（4）无解返回 None，不用抛异常：MAPF 里"无解/超时"是高频正常事件，上层要拿这个信号做降级（换算法、延迟出发、把某台机器人临时停靠），异常流会污染正常控制逻辑。注意相比教科书版本，这里省去了 closed 集合，工程版建议加上（g.get 判断在稠密重复访问时偏慢），本片段保留最简结构便于阅读。

片段 2：SIPP 安全区间，把冗长的时间展开折叠成区间

def safe_intervals(cell_occupancy, t_max):
    """把某格"被占用的时刻集合"压成"安全（空闲）区间列表"。
    时空 A* 逐时刻展开；SIPP 对每个 (格, 安全区间) 只展开一次。"""
    intervals, start = [], None
    for t in range(t_max + 1):
        if t not in cell_occupancy:               # 空闲
            if start is None:
                start = t                         # 一段空闲的开始
        elif start is not None:                   # 由空转占：封口
            intervals.append((start, t - 1))
            start = None
    if start is not None:
        intervals.append((start, t_max))          # 收尾：末尾的开放区间
    return intervals

def earliest_in_interval(intervals, t_arrive):
    """到达时刻映射到安全区间内的"可行最早时刻"：早到就在该格等到区间起点。"""
    best = None
    for lo, hi in intervals:
        if t_arrive <= hi:                        # 能在这个区间内等到/走入
            cand = max(lo, t_arrive)
            best = cand if best is None else min(best, cand)
    return best

解读：SIPP 优化的本质是"状态表示的改进"，把逐时刻的占用折叠成区间，搜索空间从 O(格数 × 时域) 变成 O(格数 × 区间数)。earliest_in_interval 的两个语义要分清：早到可以等到区间起点（等待是免费的），但从区间末段"晚到"就只能放弃这个格子的这段空闲，这正是把等待内化进区间查询的写法。工程上这两段函数配合一个"区间二分"（intervals 有序）即可支撑整个 SIPP；它相对片段 1 的收益在长走廊（占用稀疏）里最大，在"每格频繁被占"的拥堵地图里区间碎成小段，优势缩小，这就是为什么论文里的性能表必须带地图类型。

片段 3：CBS 顶层，约束树的分裂与最优性的边界

def cbs(agents, low_level, max_expansions=100000):
    """CBS 顶层示意：约束树 + 冲突驱动分裂。
    agents: 智能体集合；low_level(agent, constraints) 返回约束下的最优单机路径。"""
    root = {"constraints": {a: [] for a in agents}, "paths": {}, "cost": 0}
    for a in agents:                              # 根节点：无约束各自最优
        root["paths"][a] = low_level(a, [])
        root["cost"] += len(root["paths"][a])
    tree = [root]                                 # 真实实现用优先队列按 cost 出队
    for _ in range(max_expansions):
        node = tree.pop(0)                        # 取当前最优节点（示意为 FIFO）
        conflict = find_first_conflict(node["paths"])   # 顶点或边冲突
        if conflict is None:
            return node["paths"], node["cost"]    # 无冲突：第一个即最优（论证见正文）
        a1, a2, loc, tt = conflict
        for agent in (a1, a2):                    # 分裂：两个子节点各禁其一
            child = {"constraints": {k: list(v) for k, v in node["constraints"].items()},
                     "paths": dict(node["paths"]), "cost": node["cost"]}
            child["constraints"][agent].append((loc, tt))    # 新约束：该时刻避开该处
            p = low_level(agent, child["constraints"][agent])
            if p is None:
                continue                          # 该分支不可行：直接剪掉
            child["cost"] += len(p) - len(node["paths"][agent])
            child["paths"][agent] = p
            tree.append(child)
    return None, None     # 超扩展上限：降级到 ECBS/优先级规划（绝不死等）

解读：CBS 的全部魔法浓缩在这 30 行里。三个设计点：（1）只重规划被约束的那一个智能体，child["paths"] 复用其他智能体的路径，这把"联合规划"的指数负担限制在"约束树的分支数"上，是 CBS 相对联合 A* 的关键优势来源。（2）两个子节点分别约束冲突双方，保证约束树的完备：任何可行解至少满足其中一边的约束（"要么 A 不在那里，要么 B 不在那里"），这条分裂逻辑就是最优性论证的第二块拼图。（3）扩展上限 + 返回 None，约束树爆炸（瓶颈地图）是 CBS 的已知死穴，生产代码必须设上限并预先写好降级链（ECBS → 优先级 + 预约 → 人工调度），片段里返回 None 就是这条链的入口。出队顺序在真实实现中按 cost 优先（保证第一个无冲突解最优）；此处用 FIFO 是为了让分裂逻辑显式可见，注释里已注明。

常见坑

  • 删掉等待动作以"省时间"：解空间残缺，密集场景成功率暴跌，表现为"明明有解却报无解"。修复：等待永远是动作集成员；若嫌效率低，用 SIPP 的区间表示内化等待，避免删动作。
  • 时间上限太短直接宣布无解：T 上限只比"最短路径长度"大一点，遇到绕行需求就误报无解。修复：上限取"单机最短路径 × 3 + N"量级起步，并单独统计"上限截断"与"真无解"两类失败（它们的处置完全不同）。
  • 在瓶颈地图上硬跑 CBS：窄门场景冲突全挤在一格，约束树爆炸，运行时间不可控。修复：提前识别瓶颈（图论割点/人流量统计），瓶颈区改用"单车道管制"（交替通行，回到第 084 章的预约），只在开阔区用 CBS 系算法，算法要按地图分区使用，避免全图统一处理。
  • 离散解直接下发给底盘：网格折线含 90° 硬转角，轮式底盘跟踪不上，实际轨迹切内角撞上障碍。修复：离散路径 → 连续平滑 → 冲突复检（对平滑后轨迹再跑一遍检测）→ 跟踪控制；平滑后余量不够就回退重规划。
  • 基准只报"我们最大 100 台"：峰值单例不可复现也无代表性。修复：成功率-规模曲线 + 密度分层 + 固定种子 + P50/P99 运行时间；把失败案例按类型归因（冲突爆炸 / 超时 / 真无解）。

练习与思考

  1. 算一算：10×10 网格、时域 T = 40、4 台机器人。联合空间状态数量级是多少（含等待动作，按 (100×40)⁴ 估）？同样的地图用 CBS 的完全展开树又是什么量级（提示：只在地图格 × 时间上展开，顶层树受冲突数约束）？用这两组数字解释"为什么 CBS 能用"。★
    提示
    联合：(4000)⁴ ≈ 2.6×10¹⁴，不可穷举。CBS 底层单机时空搜索每台约 10⁴–10⁵ 节点，顶层树每层只重规划一台，把"乘积的指数"降级为"加法 × 树规模"，这就是两层结构的价值。
  2. 改配置并预测结果：把 ECBS 的 w 从 1.2 提到 1.6。预测成功率、解质量（相对最优的 SOC 比值）、运行时间 P99 三个指标各自的走向，并说明什么场景下高 w 合理。★
    提示
    w 越大解越差但搜得越快：SOC 比值上界 ≤ w（有界次优的字面含义），时间下降，成功率上升（更多实例能在预算内求解）。高 w 合理场景：实时性优先、解质量有物理兜底、或实例接近无解边界时"能解出就行"。
  3. 设计：一个仓储地图（两排货架、中间单车道、两端各一个出入口），给出一条"分区混合"方案：瓶颈区用什么机制、开阔区用什么算法、两者交接处怎么保证无冲突，并说明死锁的检测与解除。★★
    提示
    单车道 = 天然瓶颈：用"方向交替 + 预约"（一次只允许一个方向的车队进入），开阔区用优先级/ECBS；交接处把"车道口"当临界区（第 069 章的互斥资源）；死锁检测用环检测（第 084 章），解除用最低优先级退让。
  4. 推导：按正文骨架补全 CBS 最优性论证的两块拼图：(a) 底层在约束下返回最优路径，因此约束树每个节点的 cost 是其约束集合下全队代价的下界；(b) 任何可行解都对应树中某条路径（分裂是"要么……要么……"的完备划分）。由 (a)(b) 说明"第一个无冲突节点即最优"。★★
    提示
    (a) 每台在自身约束下最优 ⇒ 合成代价是该约束组合下的最小可能；(b) 解的每条约束若被违反，必然落入某个子节点的约束里，逐层下降到叶子，两个方向合起来：树中每个解都能被找到，且出队顺序保证先出更优下界。命题成立的关键前提：底层最优性 + 分裂完备性，缺一不可。
  5. 实验：在三种地图（空、随机障碍 20%、瓶颈窄门）上各生成 50 个实例（N = 10、20、30），对比优先级规划、ECBS（w = 1.3）、CBS 的成功率与 SOC 比值、P99 运行时间，绘制成功率-规模曲线并标注各算法的失效点。写半页结论：给"你的仓库项目"的选型建议。★★★
    提示
    预期：空图上 CBS 都能撑到 30；随机障碍图上 CBS 在 30 台开始吃力、ECBS 稳定；瓶颈图上优先级成功率最先掉、CBS 时间爆炸。结论模板："开阔区 CBS/ECBS 二选一（按 p99 预算），瓶颈区退回预约管制，整体用分区混合"，用量化数据背书。

小结

  • MAPF 的三承诺不可兼得：完备、最优、快；谱系里每个算法先问"放弃了什么、放弃值多少"。
  • 联合空间 A* 是指数爆炸但不可替代的"地面真值发生器"；小规模验证任何近似算法都以它为准。
  • 时空 A* 把动态展平为带时间的墙；等待动作必须存在、时间上限必须截断；SIPP 用安全区间折叠时间维，是状态表示的典型改进。
  • CBS 两层：底层单机最优 + 顶层约束树"要么 A 让、要么 B 让"的完备分裂 ⇒ 第一个无冲突解最优；瓶颈地图是它的死穴，必须预置降级链。
  • 连续世界三转换：栅格化、速率/运动学适配、平滑后冲突复检 + 物理安全兜底。
  • 基准用性能包络（成功率-规模-密度曲线 + P50/P99）说话，峰值成绩不构成结论。
