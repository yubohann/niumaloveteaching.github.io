第五篇 · 科研进阶与协同机制

第 098 章：多机器人系统实验设计与评价指标

从"跑了一次，看起来不错"到"20 次重复、因子可控、置信区间有界、指标预先注册"：实验设计四要素、因子矩阵、分位数指标与自助法置信区间，一次把科研可信度补齐。

  • 主题：研究方法（实验设计与指标口径）
  • 关键机制：变量分类、全因子设计、随机化与重复、分位数与置信区间、预注册清单
  • 预计学时：60 分钟
  • 前置章节：第 097 章

学习目标

  • 掌握变量四分类（自变量/因变量/控制变量/混淆变量），能从自己的系统中找出至少两个隐藏混淆变量。
  • 理解全因子设计（2k）相对"一次只动一个因素"（OFAT）的优势：用更少的运行发现交互效应。
  • 会给重复次数找依据：用置信区间半宽公式估算"报告 ±5% 需要多少重复"，拒绝"跑三次取平均"。
  • 掌握指标口径：成功率、makespan、通信量、恢复时间、公平性（Jain 指数）的定义、量纲与尾部报告（P95/P99）。
  • 能写一份合格的实验计划：预注册指标清单、因子矩阵、种子策略、统计方法与可复现清单。

背景与动机

到这里你已经攒了十余个机制：编队、避障、拍卖、调度、学习、MAPF……接下来所有"我做的比基线好"的论断，都必须过同一道关：实验设计。没有它，再花哨的机制也只是"跑了一次，看起来不错"，现场演示能过，审稿人一追问"几次重复？方差多大？换了种子还成立吗？"就露馅。多机器人系统尤其容易骗人：机器人起始位姿、网络抖动、任务顺序、仿真器版本都会悄悄改变结果，而这些因素通常没人记下来。

本章把实验设计拆成四个可操作的部件：变量（改什么、测什么、锁什么、防什么）、因子设计（怎么组合实验格）、重复与统计（结论的不确定度有多大）、指标口径（每个数字怎么定义、量纲是什么）。它们是第 086 章"验证计划"那一格的展开，也直接决定第 099 章论文复现与第 100 章作品答辩的可信度，答辩评委几乎必问的三个问题（怎么测的、跑了几次、置信度多少）都在这章里有标准答案。

核心原理

1. 变量四分类：把"可能影响结果的量"全部登记在案

类别定义你的系统里的例子处置
自变量（因素）你主动调节的机器人台数 N、通信延迟档、故障注入率按水平枚举进实验格
因变量（指标）你测量报告的完成率、makespan、通信量、恢复时间预注册定义与口径
控制变量固定不变的地图、机器人速度上限、仿真器版本、任务集写进配置，随结果存档
混淆变量没控制住、且与因素相关的"延迟升高"和"台数增多"同时发生分解或随机化隔离

混淆（confounding）是最隐蔽的敌人，看一个真实形态的例子：你对比"2 台"和"6 台"两种规模，发现 6 台时通信延迟也更高（链路更挤），于是"规模变大导致性能下降"这个结论里，混着"延迟变大导致性能下降"的贡献，两者分不开。拆解方法：把"台数"与"延迟"都作为自变量放进因子设计（2 台/6 台 × 低延迟/高延迟 四格），每格里都能独立观察两种效应，这是下一小节的直接动机。

2. 全因子设计：2^k 格实验与交互效应

一次只动一个因素（One-Factor-At-a-Time, OFAT）看起来省实验，但它有个致命盲区：看不见交互。所谓交互：因素 A 的效果依赖于因素 B 的取值。多机器人系统里交互遍地都是，"延迟从 20 ms 涨到 80 ms"在 2 台时几乎无感，在 6 台时却让协调机制崩溃：延迟的伤害与台数有关。OFAT 的做法（固定 2 台调延迟、固定延迟调台数）恰好错过这两个因素的"合力格子"。

全因子设计把所有因素的水平组合全部跑一遍：3 个两水平因素就是 2³ = 8 格；每格重复 r 次。为什么不直接上"每因素 5 个水平"的穷举：格数随因素数指数增长（5³ = 125 格），实践里的标准组合是筛选用两水平（低/高）+ 验证用少量三水平。两水平全因子能告诉你：(a) 每个因素的主效应大小；(b) 任意两因素的交互方向与量级，后者的价值常高于前者：如果你的机制在"高延迟 + 大台数"角落里崩溃，那正是论文里最该报告的一条曲线。

全因子运行数 = Π(各因素水平数) × 重复数 r；2³ × r=10 → 80 次运行 与 OFAT 相比：运行数只约翻倍，换来全部两两交互的可测量，对"机制实验"这是必需的，算不上奢侈

3. 重复与统计：每次重复都是一个不可替代的样本

多机器人实验的运行结果天然带随机性（起始位姿、网络抖动、任务到达序列），所以"跑一次"的结论没有意义；但"跑 100 次就万事大吉"也不对，重复次数应该由你想报告的精确度倒推。若指标近似正态、标准差为 σ，n 次重复的均值标准误是 σ/√n，95% 置信区间半宽约 1.96·σ/√n。反过来解 n：

n ≈ (1.96 · σ / 目标半宽)² 例：makespan 的变异系数（σ/均值）约 15%，想把误差报告到 ±5% → n ≈ (1.96×0.15/0.05)² ≈ 35 次/格

两个配套习惯。（1）种子策略：每次重复用固定、可复现的种子序列（种子 = 格子号 × 1000 + 重复号），全部落盘，实验不可复现的第一大原因就是"种子没存"。（2）尾部优先：延迟、恢复时间这类指标分布是重尾巴（偶发的 2 秒卡顿比平均值重要得多），必须报告 P95/P99；只报均值 + 标准差会把"平均好看、尾部危险"的系统伪装成明星。统计检验上：对比两组的差异用 t 检验（近似正态时）或 Mann-Whitney U（分布未知/重尾时），报告 效应量 + 置信区间（"均值差 12%，95% CI [8%, 16%]"）而不只是 p 值，p 值只说"有没有差异"，效应量说"差异值不值得关心"。

4. 指标口径：每类指标的定义、量纲与常见陷阱

指标定义量纲/口径陷阱
任务完成率完成的任务数 ÷ 下达任务数%，分母含超时未完成把"取消的任务"从分母里偷偷拿掉
完工时间从第一任务下达到最后一任务完成秒（同任务集下可比）不同任务集直接比 makespan
通信负载Σ 字节 ÷ 运行时长 ÷ 机器人台数B/s/台（归一化才可与规模无关地比）只报总量，台数一变就失真
恢复时间故障注入时刻 → 系统恢复运行时刻秒（P50/P95 分开报）人手动算卡点、无自动打点数据
公平性Jain 指数 J = (Σxi)² / (n·Σxi²)1/n 至 1；1 为绝对均匀只看平均值掩盖"一台累死"

Jain 指数值得记牢：xi 可取各机器人的完成任务数或里程数，J = 1 表示人人一样，J = 1/n 表示一人全包。算例：台数 4、任务数分别 30/30/20/20 → J = (100)² / (4 × (900 + 900 + 400 + 400)) = 10000/10400 ≈ 0.96，公平性良好；如果分布是 79/7/7/7，J = (100)²/(4×(6241+49+49+49)) = 10000/25552 ≈ 0.39，均值同为 25/台，公平性天壤之别。"均值 + 公平性 + 尾部分位数"三件套一起报，"我们平均不错"这类含糊结论就没有生存空间了。

实现思路与设计

以第 085 章的任务系统为实例，给一份完整的实验计划模板（可直接迁移到你的项目）：

要素方案
自变量（因素）台数 N ∈ {2, 4, 6}；通信延迟 ∈ {20 ms, 80 ms}；故障注入 ∈ {无, 每运行 1 次}
运行格数3 × 2 × 2 = 12 格；每格重复 20 次 → 240 次运行（仿真，每次数分钟）
预注册指标完成率、makespan、通信负载（B/s/台）、P95 恢复时间、Jain 公平指数
控制变量地图、任务集（固定随机种子的 20 任务）、速度上限、仿真器与依赖版本
种子策略seed = 格子号 × 1000 + 重复号；记录于 CSV；分析脚本按种子复算
统计方法每格报告均值 ± 95% CI（自助法）；两组比较用 Mann-Whitney U + 效应量；公平性报告分布图
可复现清单代码版本（git commit）、配置快照、原始数据 CSV、分析脚本三者随报告打包

三个设计决定给理由：把故障注入作为因素（有/无）纳入同一设计，避免"单独另跑一组"；它与其他因素的交互（故障在 6 台时伤害是否更大）正是最值得报告的结论，放在同一设计里才测得出来。（2）延迟两个水平取 20/80 ms：20 ms 是局域网的良性水平，80 ms 是"WiFi 拥塞"的典型水平，两极分化让主效应明显（若真实曲线是非线性的，再补 50 ms 的中档验证）。（3）每格 20 次：按第 3 小节的置信区间公式反推，指标 CV 约 15%、目标 ±6.5% 半宽时 n ≈ 20，且 20 次在 12 格规模下总运行量可控。

设计决策：为什么不"跑最好的格子多跑几次"？

因为把重复次数与"结果好看"挂钩就是选择性汇报的开始。预注册的格数与每格重复数必须在看到数据之前确定并写进实验计划，这样即使某个格子结果难看，它也在报告里有一席之地。同理，指标清单也要预注册：跑完后"发现"的新指标只能放在探索性分析一节（明确标注），不能冒充验证性结论。这两条纪律是科研诚信的工程版，也是评委分辨"真实验"与"演示"的最快试纸。

关键代码与解读

片段 1：全因子运行器，格子、种子、长表记录

from itertools import product

def run_factorial(factors, reps=20, base_seed=0, simulate_once=None):
    """全因子运行器：所有水平组合 × 重复，输出长表（每行一次运行）。
    factors 例：{"n_robots": [2, 4, 6], "delay_ms": [20, 80], "fault": [0, 1]}"""
    keys = list(factors)
    rows = []
    for cell_id, combo in enumerate(product(*(factors[k] for k in keys))):
        cfg = dict(zip(keys, combo))
        for r in range(reps):
            # 种子 = 格子号 × 1000 + 重复号：可复现、可定位、每格独立
            seed = base_seed + 1000 * cell_id + r
            metrics = simulate_once(cfg, seed)     # 返回指标字典
            rows.append({**cfg, "cell": cell_id, "rep": r, "seed": seed, **metrics})
    return rows        # 长表格式：直接喂给 pandas 做分组统计与画图

解读：运行器的三个设计点决定了实验能否"活着跑完并活到分析阶段"。（1）长表格式（每行 = 一次运行，列 = 因素 + 指标）：这是数据科学里的"整洁数据"惯例，分组统计、画箱线图、找异常点都是一行代码；宽表（每格一列）在格数变化时会折磨分析脚本。（2）种子公式可定位：任何一个异常结果都能用行里的 seed 精确重放，不用翻日志找"那次是哪个种子"。（3）base_seed 整批可平移：想复跑整套实验换一批种子（检验结论稳健性）只改一个参数，"换种子还成立吗"这个问题应该是一行代码，不再需要手工重录。

片段 2：指标收集器，分位数是延迟类指标的底线

import numpy as np

class MetricsCollector:
    """运行期指标收集：事件打点，事后按指标名汇总。"""
    def __init__(self):
        self.events = []                      # (指标名, 时间戳, 数值)

    def record(self, name, t, value):
        self.events.append((name, t, float(value)))

    def summary(self):
        rows = {}
        for name, _t, v in self.events:
            rows.setdefault(name, []).append(v)
        out = {}
        for name, vals in rows.items():
            a = np.asarray(vals)
            # 均值给"总体印象"，P50/P95/P99 给"最坏体验"：两边都必须有
            out[name] = {"n": len(a), "mean": round(float(a.mean()), 3),
                         "p50": round(float(np.percentile(a, 50)), 3),
                         "p95": round(float(np.percentile(a, 95)), 3),
                         "p99": round(float(np.percentile(a, 99)), 3)}
        return out

解读：收集器的关键设计是"打点与汇总分离"：运行期只做 O(1) 的追加（不能因为统计拖慢实时环路），汇总在运行结束后做。为什么不只存均值：均值对重尾分布有欺骗性，恢复时间均值 3.2 s 听起来不错，若 P99 是 28 s，说明百分之一的故障让系统瘫了半分钟。n 字段（样本量）必须随分位数一起报：P99 需要至少 100 个样本才有意义，n = 20 时报 P99 等于报最大值，这类"小样本报高分位"是审稿常见驳回理由。预注册指标清单时就要写明每个指标报哪个统计量（均值/中位数/分位数）与最小样本量。

片段 3：自助法置信区间，不做正态假设的"误差棒"

import numpy as np

def bootstrap_ci(samples, statistic=np.mean, alpha=0.05, B=5000, seed=0):
    """自助法 95% CI：对样本反复重抽样得到统计量分布。
    不假设正态，均值、中位数、P95 这些统计量都能配它。"""
    rng = np.random.default_rng(seed)
    data = np.asarray(samples, dtype=float)
    n = len(data)
    boots = [statistic(rng.choice(data, size=n, replace=True))
             for _ in range(B)]
    lo = np.percentile(boots, 100 * alpha / 2)          # 2.5% 分位
    hi = np.percentile(boots, 100 * (1 - alpha / 2))    # 97.5% 分位
    return round(float(lo), 3), round(float(hi), 3)

# 用法：每格的 20 个 makespan → 均值与 CI，图上画成"均值 ± 误差棒"
# 两组对比：区间不重叠 ⇒ 有肉眼可见的差异；再做 Mann-Whitney 作正式检验

解读：自助法的实操价值在于"什么统计量都能配"：多机器人指标常常重尾（前面说过），此时均值 CI 的教科书公式（1.96σ/√n）本身就不准；自助法不做分布假设，直接对"统计量的抽样分布"做经验估计，甚至可以对 P95 这种"非均值统计量"求置信区间（这在论文里是很讲究的一手）。解读两个细节：（1）B = 5000 与 n = 20 的组合：自助法修的是统计量的抽样分布，不会凭空制造新信息，n 小的时候 CI 会诚实地变宽（这正是我们要的诚实）。（2）"区间不重叠 = 有显著差异"是直觉判据，严格的显著性报告仍应附检验 p 值与效应量；把 CI 与检验并列，是实验章节的完整形态。

常见坑

  • 单次运行出结论：看到一次实验结果就写"提升显著"。修复：所有格必须有多重复（依据 CI 半宽公式反推 n），报告均值 ± CI，不报单个数字。
  • 混淆变量混入结论：规模效应里混着延迟效应（示例见原理一节）。修复：把疑似混淆量升格为自变量放进因子设计；不能升格的（如"仿真器版本"）就锁死并记录。
  • 只报均值，隐藏重尾：平均恢复时间漂亮，P99 灾难。修复：延迟类、恢复类指标一律 P50/P95/P99 并列；样本量不足 100 时不报 P99（报最大值并注明）。
  • 种子不落盘：写论文时无法复现某条曲线，导师要求"再跑一遍那个异常案例"时手忙脚乱。修复：种子随每次运行写入 CSV 第一列；分析脚本按需重放。
  • 跑完再挑指标：预注册了 A、B、C，跑完发现只有 D 好看就只报 D。修复：预注册清单 + 探索性结果单列置顶声明；这是审稿底线问题，不是文风问题。
  • 多重比较不加校正：12 个格两两比较 66 对，按 p<0.05 总会有假阳性。修复：减少比较次数（先主效应后交互）、或对 p 值做 Bonferroni 类校正、或以 CI 为主叙述。

练习与思考

  1. 算一算：某指标变异系数 12%，你希望报告的均值误差在 ±4% 以内，需要每组重复多少次？如果只想报 ±8% 呢？（用 n ≈ (1.96·CV/目标)²。）★
    提示
    ±4%：n ≈ (1.96×0.12/0.04)² ≈ 35；±8%：n ≈ 9。结论：精度要求翻倍，样本量约翻四倍，重复次数遵循"精度定价"，满足目标半宽即可，加量不再带来收益。
  2. 改设计并预测结果：3 个两水平因素，对比 OFAT（每次只动一个：基线 + 3 次单因素变动 = 4 次运行）与全因子（2³ = 8 次）各能回答哪些问题；假设存在"延迟 × 台数"交互，预测两种设计会得出怎样不同的结论。★
    提示
    OFAT 4 次只能估主效应（且基线依赖）；全因子 8 次同时估 3 个主效应 + 3 个两两交互。若有交互，OFAT 会得到"平均意义上延迟有害"，全因子会得到"延迟只在 6 台时有害"，后者才是可据以设计的结论。
  3. 设计：为你正在做的研究项目写完整实验计划（模板照抄设计一节）：因素与水平、格数 × 重复、预注册指标及口径、种子策略、统计方法、可复现清单。限制在一页内。★★
    提示
    自检清单：每个指标有没有"定义句 + 量纲 + 统计量"？重复次数有没有依据？有没有至少一个"对抗性因素"（故障/干扰/对手）进因子？一页写不下的部分（如具体脚本）用附件引用。
  4. 推导：证明 Jain 公平指数 J = (Σxi)²/(n·Σxi²) 满足 1/n ≤ J ≤ 1，并分别给出取到上下界的分配形态；用 79/7/7/7 与 30/30/20/20 两组数字验算（n = 4）。★★
    提示
    上界：由 Cauchy-Schwarz，(Σx)² ≤ n·Σx²，等号当且仅当所有 x 相等 → J = 1。下界：仅一台为正时 J = x²/(n·x²) = 1/n。验算：0.96（均衡）vs 0.39（独占），均值相同，公平性天壤之别。
  5. 综合：用片段 1 的框架跑（或模拟）你的 12 格实验，输出：(a) 每格 20 次的均值与 95% 自助法 CI；(b) 至少一张"因素交互"图（例如"延迟效应随台数变化"）；(c) 一段 150 字的实验结论草稿，要求每个数字带口径（样本量、统计量类型）。★★★
    提示
    结论草稿模板："在 20 次重复下，6 台 + 80 ms 延迟格的完成率为 82%（95% CI [77%, 87%]），显著低于 2 台低延迟格的 96%（CI [94%, 98%]）；交互分析显示延迟惩罚随规模放大…"。每个数都能追溯到 CSV 的某 20 行。

小结

  • 变量四分类：自变量、因变量、控制变量、混淆变量；把疑似混淆量升格为因素放进设计，比事后解释便宜得多。
  • 全因子 2k 设计的核心价值是测交互（延迟 × 规模这类"合力"），OFAT 结构性看不见它。
  • 重复次数由精度反推：n ≈ (1.96·CV/目标半宽)²；种子公式化落盘（格子 × 1000 + 重复号）。
  • 指标口径三件套：定义 + 量纲 + 统计量；延迟/恢复类必须报 P95/P99 并注明样本量；公平性用 Jain 指数（1/n 到 1）。
  • 统计报告：自助法 CI 打头，检验与效应量跟上；预注册指标清单，探索性发现单独声明。
  • 可复现 = 代码版本 + 配置 + 种子 + 原始数据 + 分析脚本，五件套随报告打包。
