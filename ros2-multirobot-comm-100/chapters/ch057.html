第三篇 · 协同控制与任务协同

第 057 章：协同搬运重物

没有抓手、只有推力：用准静态力平衡与摩擦锥分析"推得动吗、会不会打滑、会不会翻"，用带约束的力分配把期望推力摊到每个接触点，再用导纳控制让机器人成为可控的力源。

  • 主题：任务协同 / 推式协同搬运
  • 关键机制：摩擦锥、准静态力平衡、带约束力分配、导纳控制、打滑检测
  • 预计学时：65 分钟
  • 前置章节：第 056 章

学习目标

  • 理解推式搬运与抓持式搬运的本质差异：接触面可滑移、力方向由几何决定、无"夹持内力"可用。
  • 掌握摩擦锥约束 |Ft| ≤ μFn 与准静态力平衡（合力过质心、力矩平衡防翻转）。
  • 会实现带约束的推力分配：A·t = b 的最小范数解 + 边界钳制的迭代校正。
  • 能设计导纳控制律（力误差 → 速度增量），理解增益与通信延迟的关系并会选初始参数。
  • 会做打滑检测（里程位移 vs 物体位移）与对策（降力、换接触点、加法向贴合）。

背景与动机

056 章的框架假设"接触是刚性的、可以夹持"，但很多重物压根没法抓：大箱子、料架、汽车壳体，机器人只能推。推式搬运的物理图景完全不同：接触面允许切向滑移（靠摩擦力传递推力）、施力方向被接触几何锁死（只能沿面的法向推）、没有"夹持内力"这种调节手段（力大了打滑、力小了推不动）。多台机器人一起推时，力必须同时满足"合力方向正确"和"每台都在摩擦锥内"两个约束，协调难度反而更高。

本章把 056 章的"对象坐标系 + 分解思想"移植到纯力域：期望对象运动先被翻译成"所需合力与力矩"，再分配到接触点，每台机器人用导纳控制把力误差变成速度修正。058 章的"长物体"会在此基础上加入姿态约束，059 章回到有抓持的形态，先掌握这章的摩擦与准静态分析，是后面一切力域协同的基础。

核心原理

1. 摩擦锥：推力传递的硬上限

接触面上能传递的切向力受摩擦定律限制：|Ft| ≤ μ·Fn，所有可行接触力构成一个以法向为轴的圆锥（二维截面里是楔形），就叫摩擦锥。推重物时这条约束有直接的工程后果：机器人对物体的法向压力来自它自身的重量与驱动（轮式机器人受地面摩擦限制），最大可用推力 ≈ μ·（可施加的压力）。如果需要的推力超过这个上限，无论怎么协调都推不动，系统设计的第一道算术题是"需要的合力 vs 单机推力上限 × 台数"。

单机推力上限 ≈ μ地面·Wrobot（轮式）或 μ·F压；系统可行条件：|Fdes| ≤ Σ上限（留 30% 裕度） 示例：20 kg 箱子、地面摩擦系数 0.6，μ地面·W = 0.6 × 8 kg 当量 ≈ 47 N/台；三台合计 140 N 远大于所需 ~20 N，瓶颈通常在几何（推点布置与方向），推力总量反而宽裕

2. 准静态力平衡：合力过质心、力矩不能翻转

搬运速度做到 0.1–0.3 m/s 时惯性力可忽略（ma ≈ 20×0.2 = 4 N，与推力同量级但可控），系统可用准静态近似：ΣF = 0、ΣM = 0。这给出两条设计律：

  • 合力方向必须穿过质心的稳定域：推力合力偏离质心太远，物体绕质心旋转（"推歪了"）；合力矩应主动配平到接近零。
  • 翻转裕度：箱体绕底边翻转的力矩由推力与高度决定（Mtip ≈ F·h），稳定力矩由重力与底宽决定（Mstab ≈ mg·w/2）。高个子箱体（h 大、w 小）必须限制推力和推力作用点高度，这条约束常常比推力总量更先触顶。

3. 带约束的力分配

给定期望合力 (Fx, Fy) 与期望力矩 Mz，把任务摊给 k 个接触点，每台沿固定推方向贡献标量推力 ti ≥ 0：

A·t = b，A 的第 i 列 = [dix, diy, rixdiy − riydix]T，b = [Fx, Fy, Mz] t 为各点推力大小；约束 0 ≤ ti ≤ tmax（非负 = 只能推不能拉）

无约束时最小范数解 t = A+b 已经给出"最省力"分配；加上非负与上限约束后没有闭式解，但有个非常实用的迭代：把越界的 t 钳到边界，把未满足的合力残差重新分配给剩下的接触点，重复直到收敛（通常 3–5 次）。这个"钳制 + 残差重分配"的处理与 046 章 CBS 的剪枝、本章的摩擦锥同源：先把硬约束做实，再在可行集内优化。

4. 导纳控制：机器人是力源，不是位置源

推力控制不能直接命令位置（接触力会随定位误差剧烈波动），正确姿势是导纳控制：机器人表现为一个"受控的力执行器"，力误差产生速度修正：

vcmd = vff + ka·(Fmeas − Fdes) 推力超了→加速让开；推力不足→减速顶紧；ka 量纲 m/(s·N)，示例 0.02

增益选择有硬性上限：导纳环本质是"力反馈 + 通信/传感延迟"的闭环，延迟 δ 越大，允许的增益越低（经验上 ka·m等效/δ 控制在一定范围内，否则力振荡）。三台机器人的力数据经 20 Hz 融合，端到端延迟 50–150 ms，ka 从 0.02 起步用实验标定。没有力传感器时可以用电机电流 × 力矩常数近似推力，代价是标定误差（5–10%）与温漂，做打滑检测时需要把这一误差计入阈值。

5. 打滑检测：里程与物体位移的差值

推重物最隐蔽的故障是"机器人走着、物体没动"（打滑）或"物体滑得比机器人快"（失控）。检测方法是同时测两个位移：机器人里程计位移 dr，与物体位移在推力方向上的投影 db（物体位置来自视觉标记或队友共识）。定义打滑比：

slip = max(0, (dr − db) / dr) 0 = 同步推进；接近 1 = 纯打滑；示例阈值 0.15 触发告警、0.3 触发降力策略

打滑的常见原因是法向压力不足、接触面有异物、或期望推力超过了摩擦锥。对策按成本排序：先降低该接触点的目标力（重新分配），再调整推点高度与方向（改善力矩），必要时停顿重新标定接触几何。注意打滑比必须用同一时间窗的两个位移，时间不同步时用物体位移插值到机器人采样时刻，这与 044 章的邻居外推是同一类时延处理。

6. 通信结构：频率低、语义强

力域协同的通信与位置域不同：期望力/观测力 20 Hz（每台几十字节）、物体状态 20 Hz、方向和几何参数事件驱动。带宽需求很小，但消息语义要求高：每条力消息必须带推点 id、方向、标定版本与时间戳，力是"有方向的历史"，不知道方向与参考系的数据无法融合。重物场景通常还要求"同一时刻只有一台在改写目标"：对象轨迹由 leader 唯一发布（与 056 章一致），其余人只做力反馈，避免"人人都是 leader"的混乱。

6. 数值算例：推力、翻转与导纳的预算

推力预算：20 kg 箱体在等效摩擦系数 0.1 的路面上匀速推动约需 20 × 0.1 × 9.8 = 19.6 N；若还要求 0.2 m/s² 的加速能力，再加 20 × 0.2 = 4 N，合计约 24 N。三台机器人平均 8 N/台，而单台推力上限约 μ × W = 0.6 × 8 × 9.8 = 47 N，裕度接近 6 倍。结论是推力总量远不是瓶颈，瓶颈在接触几何（推点布置、每条推力的方向）与力矩配平；先把预算算出来，团队就能把调试精力放对地方。

翻转预算：箱体 0.8 m × 0.6 m × 0.5 m、重 20 kg，稳定力矩 Mstab = mg × w/2 = 196 × 0.4 = 78.4 N·m（w = 0.8 m）；推力作用于 0.3 m 高度、合力 40 N 时翻转力矩 Mtip = 40 × 0.3 = 12 N·m，安全系数 6.5，很稳。换成高窄型箱体（高 0.5 m、底宽 0.3 m、同样重）：Mstab = 196 × 0.15 = 29.4 N·m，推力置于 0.45 m 高度时 Mtip = 40 × 0.45 = 18 N·m，安全系数降到 1.6，接近"轻碰就翻"的区间。这正是常见坑里"高箱体把 tmax 折半"的数学出处：宽高比一变，约束从推力换成翻转。

导纳预算：ka = 0.02 m/(s·N) 下，5 N 的力误差产生 0.10 m/s 的修正速度，7.5 N 就触及 0.15 m/s 的修正限幅。设计含义：正常工况下力跟踪误差应保持在 5 N 以内，否则修正器长期饱和、对抗扰动的余量耗尽。验收线"三台推力跟踪误差小于 3 N"就是这么来的：3 N 的稳态误差留出约 1.5 倍突发余量到限幅点。

功率与打滑阈值：50 N 推力以 0.3 m/s 推进对应 15 W 机械功率，按驱动效率 50% 估约 30 W 电功率，8 m 行程（约 27 s）耗能不足 1 kJ，电机热负荷不是问题，这进一步说明"慢而稳"在能耗上几乎没有代价。打滑阈值 0.15 的噪声裕度：里程计 2% 误差加视觉 3 cm 量化，在 0.5 m 的统计窗口里合计约 8%，阈值 0.15 相当于约 2 倍裕度，低于它就不用惊动调度层。

边界与失效：准静态假设只到 0.3 m/s 左右。把推进速度提到 0.8 m/s，按 0.5 s 加速过程估惯性力 ma ≈ 20 × 1.6 = 32 N，与可用推力（约 50 N）同量级，力分配必须加入惯性项、摩擦锥要按加速度方向重算，否则会出现"起步打滑、到位冲过"；再往上就该换用动力学分配，本章的准静态模型不再适用。

摩擦锥还能给布置提供校验角：每条推力方向与接触面法向的夹角必须小于 arctan(μ) ≈ 31°（μ = 0.6），超出就是打滑先兆；三台推点的方向按这个角预算布置并留 5–10° 余量。推点高度的影响同样直接：从 0.2 m 抬到 0.45 m，翻转力矩按比例增加 2.25 倍，"低推比高推稳"由此有了量化依据。打滑比的实测门槛也演练一遍：0.5 m 统计窗口内里程位移 0.5 m、物体位移 0.46 m 时 slip = 0.08，低于 0.15；物体位移 0.35 m 时 slip = 0.30，正好触发降力档。这套窗口与阈值把"多大程度的打滑才值得干预"固定成了可复现的数字，现场不再靠目测判断。

还有一个实测细节：用电机电流近似推力时，标定误差 5–10% 与温漂叠加，建议每 30 分钟用一次静止段做零漂检查，漂移超限就降级为保守限力模式（限力后验收线是"力跟踪误差不超过最后标定值的 10%"），并记录事件；对零流程约 2 分钟，慢速任务可以这样保守运行，高速重载任务应停机维保，不带病运行。零漂与限力事件按周统计，漂移趋势随时间上升说明电机或电流传感器需要保养，这是把"力控质量"纳入常规运维的最省事方式。打滑分级把对策固定成一张动作表，值班人员查表即可：

实现思路与设计

  1. 任务设定：三台机器人合推一个 20 kg 箱体（0.8 m × 0.6 m × 0.5 m）沿直线移动 8 m；地面摩擦系数 0.6；推点分别在箱体后侧的左中右（对象系 (−0.4, ±0.25) 与 (−0.4, 0)）。
  2. 期望量生成：leader 按"物体速度 PID"生成所需合力 Fdes（推进 20 N + 摩擦补偿）与 Mdes ≈ 0（让合力过质心）；加速度段限 0.2 m/s²。
  3. 力分配：每 50 ms 用钳制迭代分配三台推力；tmax = 30 N。
  4. 每台机器人：20 Hz 导纳环（ka = 0.02，低通 0.2）；输出 (v, ω) 交 044 章安全层与底层执行。
  5. 监测：物体位移用箱顶标记 + 队友共识；打滑比 0.15/0.3 两级告警；翻转裕度在线估算（推点高度 × 推力 vs 重力稳定矩）。
  6. 验收：8 m 推动到位误差小于 0.2 m；总耗时小于 60 s（0.3 m/s 标称）；打滑比全程小于 0.15；姿态偏转小于 8°；三台推力跟踪误差小于 3 N。

关键代码与解读

片段 1：带约束的推力分配

import numpy as np

def allocate_pushes(f_des, m_des, contacts, dirs, t_max=30.0, iters=30):
    """静态推力分配：A t = b，t 为各点推力大小（沿固定推方向）。"""
    k = len(contacts)
    A = np.zeros((3, k))
    for i, ((rx, ry), (dx, dy)) in enumerate(zip(contacts, dirs)):
        A[0, i] = dx
        A[1, i] = dy
        A[2, i] = rx * dy - ry * dx          # 力矩 z 分量：r x f
    b = np.array([f_des[0], f_des[1], m_des])
    A_pinv = A.T @ np.linalg.inv(A @ A.T + 1e-9 * np.eye(3))
    t = A_pinv @ b                           # 无约束最小范数解
    for _ in range(iters):                   # 钳制越界分量，残差再分配
        fix = (t < 0.0) | (t > t_max)
        if not fix.any():
            break
        free = ~fix
        t[fix] = np.clip(t[fix], 0.0, t_max)
        b_res = b - A[:, fix] @ t[fix]
        if not free.any():
            break
        t[free] = np.linalg.lstsq(A[:, free], b_res, rcond=None)[0]
    return np.clip(t, 0.0, t_max)

解读：这个迭代是"受约束最小二乘"的工程近似，逻辑与人的直觉一致：先按最省力方案分（伪逆），谁分到负数（不可能"吸"着推）就把它钉在 0，然后把它的那份缺口重新摊给其他人；有人超过了 30 N 上限就钉在上限，缺口再摊。收敛性在 k ≤ 10 的规模下极好（每轮至少固定一个分量）。三个细节：+1e-9*I 是防 A 行相关时的求逆爆掉；lstsq 处理"自由接触点不够表达 b"的场景（自动给出最小二乘逼近，不报错）；最终 clip 是兜底，迭代未收敛时也不输出越界力。提手旁的"推不能拉"约束（t ≥ 0）在这里不是数学洁癖：它正是摩擦锥在工作点上的投影。

片段 2：导纳控制轴

class AdmittanceAxis:
    """单轴导纳：力误差 -> 速度增量；低通抑制延迟引起的振荡。"""
    def __init__(self, k_a=0.02, alpha=0.2, v_extra_limit=0.15):
        self.k_a, self.alpha = k_a, alpha
        self.v_extra_limit = v_extra_limit   # 修正速度上限
        self.v_extra = 0.0

    def step(self, f_meas, f_des, dt):
        err = f_meas - f_des                 # 推力超出目标：加速让开
        v_target = self.k_a * err
        self.v_extra += self.alpha * (v_target - self.v_extra)  # 一阶低通
        self.v_extra = max(-self.v_extra_limit,
                           min(self.v_extra_limit, self.v_extra))
        return self.v_extra

解读：三行核心代码对应三个稳定性设计。(1) 误差取 (实测 − 目标)：谁超过目标谁加速，这实现了"力的负反馈"：某台机器人推得太狠，加快脚步把多余力"释放"掉，队友的推力自然被重新分担。(2) 一阶低通（α = 0.2 对应约 4 个采样周期的平滑）：力信号含电机电流噪声与延迟，不滤波时误差每帧跳动会让速度指令抖动，反过来又扰动接触力，形成力-速耦合振荡。(3) 修正速度限幅 0.15 m/s：防止异常力读数（例如撞到障碍）把机器人瞬间加速，也把 ka 的实际有效作用域限制在人能预判的范围内。调试顺序建议：先并网用 ka = 0.01 跑通，再逐步加到出现轻微振荡后回退 30%，与 042 章调增益的方法论一致。

片段 3：打滑比计算

import numpy as np

def slip_ratio(odom_delta, box_delta, push_dir, min_move=1e-3):
    """打滑比：机器人里程位移与物体位移（沿推方向投影）的差。"""
    d_r = float(np.linalg.norm(odom_delta))
    if d_r < min_move:
        return 0.0                           # 机器人几乎没动：无从判断
    d = np.asarray(push_dir, dtype=float)
    d = d / max(np.linalg.norm(d), 1e-6)
    d_b = float(np.dot(box_delta, d))        # 物体沿推方向的位移
    return max(0.0, (d_r - d_b) / d_r)       # 钳制负值（物体滑太快另判）

def slip_policy(slip, f_meas, f_des):
    """打滑分级对策：告警、降力、停机。"""
    if slip < 0.15:
        return "ok", 1.0
    if slip < 0.30:
        return "warn", 0.8                   # 降 20% 目标力再试
    if f_meas < 0.5 * f_des:
        return "stop", 0.0                   # 力远未达到却狂滑：接触失效
    return "reduce", 0.6                     # 继续降力并检查接触几何

解读：slip_ratio 用"沿推方向投影"，不取全模长：物体在横向的微小漂移不算推不动，只有沿推方向"里程消耗不掉物体位移"才是打滑的定义。slip_policy 的分级把两种物理情形区分开：力已达标但滑（摩擦力不足、接触面问题）→ 降力避让，因为更大的推力只会加剧滑动（越过摩擦锥）；力远未达标却滑（接触点悬空、标定错位）→ 直接停机，这时继续推是"空转"，还可能撞上物体侧缘。这套策略与 057 设计表的两级阈值对应，整数系数（0.8/0.6）保留给现场整定。

常见坑

  • 推力方向不通过质心：物体边走边转，轨迹越走越歪。修复：分配方程里把 Mdes 显式控制为 0；推点布置对称（左中右三点比两点好配平）。
  • 分配器要求"负推力"：几何布置不合理时伪逆解出负值，未加非负约束直接下发，机器人执行不了（或执行成反向）导致失稳。修复：带约束分配（本片段）+ 检查可行残差；布置阶段就应验证"零空间方向上都可正向发力"。
  • 导纳增益过大振荡：力读数与速度指令形成 2–4 Hz 的往复摆动。修复：增益从 0.01 起步标定；通信延迟增大时同步降增益；低通系数一并复核。
  • 打滑不检测：机器人"努力行进"、物体原地不动，任务超时才发现。修复：里程 vs 物体位移的在线对比；视觉标记或队友共识提供物体位移，阈值 0.15/0.3 分级。
  • 翻转裕度被忽视：高箱体在加力瞬间绕底边翻倒。修复：在线估算 Mtip/Mstab 比例，限制推力与推点高度；箱体高度超过底宽 1.5 倍时把 tmax 折半。

练习与思考

  1. 设箱体等效滑动摩擦阻力约 20 N（20 kg × 等效系数 0.1 × 9.8）。要获得 30 N 的净推力，三台合计需多少推力、平均每台多少？若某台机器人重 8 kg、轮地摩擦系数 0.6，它的推力上限是多少？★
    提示
    所需合力 = 20 + 30 = 50 N，三台平均约 17 N。单机上限 ≈ 0.6 × 8 × 9.8 ≈ 47 N，裕度充足，瓶颈通常在接触几何与配平，推力总量反而宽裕。
  2. 把 Mdes 从 0 改为 2 N·m（故意让物体缓慢转向），用分配代码预测三个推点的分工变化；说明哪台载荷增加、何时会触到 tmax。★★
    提示
    力矩由左右两侧的推力差产生，转向方向决定哪一侧加点；当差值超过该侧剩余裕度时触限，残差由中点分担。
  3. 设计一个"高箱体防翻转"验证实验：箱体高度/底宽比 1.8，推力逐步从 0 加到 40 N，记录倾角；写出裕度计算公式并与实测对比。★★
    提示
    Mstab = mg·w/2、Mtip = F·h（h 为推点高度）；比例接近 1 时开始可见倾斜。实测用 IMU 或视觉测倾角曲线。
  4. 把导纳低通系数从 0.2 改为 0.05 与 0.6，预测力跟踪带宽、振荡倾向、打滑响应的变化；给出三条观察曲线（力误差、速度指令、打滑比）的实验设计。★★
    提示
    0.05：太钝，打滑响应慢；0.6：锐利但振荡。实验：阶跃目标力，观察力误差超调与速度指令的抖动幅度。
  5. 为三机推重物写完整通信与降级方案：消息定义、频率、leader 规则、断连各阶段动作（0.3 s / 1.5 s）、恢复共识流程与验收指标。★★★
    提示
    断连时力目标冻结在最后值、各机保持推力方向不变（不松不猛加）；恢复后先对齐物体位姿共识再重启动态分配。

小结

  • 推式搬运的物理上限是摩擦锥：|Ft| ≤ μFn；第一步算术是"所需合力 vs 各机推力上限之和"。
  • 准静态近似下合力必须过质心、力矩配平；高箱体先受翻转约束，推力总量反而靠后。
  • 力分配用"伪逆 + 钳制 + 残差重分配"处理非负与上限；先把硬约束做实，再谈最优。
  • 导纳控制让机器人成为可控力源：v = vff + ka(F−Fdes)，低通与增益上限受延迟制约。
  • 打滑检测 = 里程 vs 物体位移；分级对策区分"摩擦不足"与"接触失效"。下一章换物理形态：协同搬运长物体，姿态约束、内力抑制与过弯策略。
