第五篇 · 科研进阶与协同机制

第 088 章：多机器人协同感知机制

让多台机器人的"眼睛"合成一只更大的眼睛：目标级融合、协方差交叉、马氏距离关联、时延补偿，以及为什么"把两个估计简单平均"是一种系统性错误。

  • 主题：协同感知机制（多源融合）
  • 关键机制：目标级融合、协方差交叉（CI）、数据关联与门限、时延补偿、一致性
  • 预计学时：55 分钟
  • 前置章节：第 087 章

学习目标

  • 理解感知融合的三个层级（原始级、特征级、目标级）的带宽与精度取舍，知道工程主流为什么选目标级。
  • 掌握目标级融合的核心机制：状态 + 协方差、马氏距离门限、匈牙利全局关联、航迹生命周期。
  • 理解协方差交叉（Covariance Intersection, CI）为什么在"误差来源相关"时仍然一致，而朴素逆方差加权会过度自信。
  • 会做时延补偿：把不同时刻的观测外推到统一时刻再融合，并知道外推会放大不确定性。
  • 会选评价指标：OSPA/GOSPA 集合距离、ID 切换率、首检时延；单看"帧准确率"远远不够。

背景与动机

单台机器人的视野是局部的：激光 10 米、相机一个锥体，墙后面、车后面、远处拐角全是盲区。多机器人系统的第一份红利就来自感知互补，同一目标被 2–3 台机器人从不同角度观测，遮挡被天然消解，定位精度按观测数提升。这也是"协同"二字最直观的兑现方式。

但"把大家的感知结果合起来"这句话里藏着一打陷阱：两台的观测时间不一样（差 80 ms，目标已移动 0.4 m）；两套坐标系的标定差 5 cm；两个估计的误差来源高度相关（都用了同一颗 GPS），朴素平均会让系统"以为自己很准"；目标在同一时刻被两台机器人报成两个 ID，计数直接翻倍。这些错误不会让程序崩溃，它们让融合结果看起来更平滑、更自信、也更错，这是协同感知在论文里最难发现、在实机上最危险的一类缺陷。

本章与第二篇的 031/032 章是同一主题的两个视角：031/032 讲"怎么做（工程管线）"，本章作为机制专题讲"为什么这么做（统计与机制原理）"，包括一致性理论与评价指标。

核心原理

1. 融合三层级：精度换带宽的阶梯

按"融合发生在管线哪个位置"分三级，带宽与信息损耗的阶梯非常陡：

层级交换内容单帧带宽量级（20 台）优点劣势
原始级点云/图像原帧几十 MB/s（须先压缩）信息最大，可做联合检测带宽爆炸、对齐要求苛刻
特征级检测框 + 特征嵌入几百 KB/s折中，保留较多信息特征异构难对齐、实现复杂
目标级航迹列表（状态+协方差）1–10 KB/s低带宽、模块解耦、可扩展丢失原始信息，关联错误难回溯

工程主流选择目标级融合（track-to-track fusion）：每台机器人本地跑自己的跟踪器，把"目标列表"发出去，融合器（或每台机器人互相融合）产出全局目标表。一个 20 台车队的航迹消息只有：目标数（平均 5 个）× 每目标 40 字节、5 Hz，约 1 KB/s/机。对比原始级需要的图像压缩流（第 023 章算过是 MB/s 级），相差三个数量级。

2. 朴素融合的谬误：相关误差与双重计数

拿到两个估计 (μ₁, P₁) 与 (μ₂, P₂)，教科书式的"独立传感器融合"是逆方差加权：P−1 = P₁−1 + P₂−1。这在两个估计误差独立时是对的，融合后不确定性一定下降。但在多机器人场景，独立性经常不成立：两台机器人用同一张共享地图做定位、同一颗 GPS 校时、同一段历史轨迹推算，误差高度相关。此时朴素融合把"同一份信息"用了两遍（双重计数），融合协方差被系统性低估，滤波器逐渐"精神错乱"：明明偏差 1 米，报告的不确定性却只有 10 cm，后续的关联门限、安全距离判断全部失准。

朴素融合：P−1 = P₁−1 + P₂−1（两者同源时 → 协方差塌缩，过度自信） 协方差交叉：P−1 = ω·P₁−1 + (1−ω)·P₂−1，0 ≤ ω ≤ 1 CI 的性质：tr(P) ≥ min(tr(P₁), tr(P₂))，绝不比最好的单源更自信，对任意相关性都"安全"

CI 的几何直觉：两个椭圆（不确定度区域）相交，CI 取"包住交集且保守"的椭圆，它承认"我无法确定两个误差相关性多少"，于是用权重 ω 在保守与激进之间滑动：ω 越大越信 1 号。可以证明 CI 的协方差对所有可能的真实相关性都是一致的（不会过度自信），代价是当独立性确实成立时它偏保守、精度略亏。多机器人工程里"宁可保守不可过度自信"是条铁律，保守只是精度损失，过度自信会导致系统级错误。

3. 数据关联：融合之前先"认人"

融合的前提是两个估计说的是同一个目标。关联三步走得稳：（1）门限，马氏距离 d² = eᵀS−1e（e 为残差，S 为残差协方差）服从卡方分布，取 99% 分位（2 维约 9.2、4 维约 13.3）作为门限，超出者排除，先剔"绝不可能"。（2）代价矩阵 + 全局分配，所有"航迹 × 检测"的配对代价排成矩阵，用匈牙利算法找全局最优一对一分配；为什么不用"各挑最近"的贪心：贪心会出现"A 抢了 B 的目标、B 抢了 A 的目标"的交叉错误，全局分配在 O(n³) 内给最优配对，几十个目标毫无压力。（3）生命周期，新出现的目标先进"候选"状态，连续 3 帧被关联才升级为"确认"（防虚警），连续 5 帧未更新则删除（防鬼影）。确认延迟与虚警率就是这一条的调节旋钮。

4. 时延补偿：先对表，再融合

机器人 A 的目标观测到达融合器时已经是 80 ms 前的历史；机器人 B 的只过了 20 ms。直接融合等于把"过去的 A"和"现在的 B"平均，产生系统性空间偏差（目标速度 5 m/s 时，60 ms 就是 30 cm）。标准做法：每台机器人给航迹打上观测时间戳，融合器先把所有航迹外推到统一时刻 t*（通常是当前时刻或消息最晚时刻），再关联与融合。匀速模型外推 x ← x + v·Δt；同时协方差必须膨胀 P ← F P Fᵀ + Q(Δt)，外推让位置更"新鲜"，但代价是更不确定，这个膨胀必须如实带上，否则又回到了过度自信。

5. 评价指标：集合到集合的距离

"准确率"无法评价多目标跟踪：数量对不上、ID 换来换去都不体现在单帧准确率里。学界用 OSPA（Optimal SubPattern Assignment）/GOSPA 距离：它同时惩罚位置误差（匹配上的目标距离）与数量误差（漏检、虚警的基数罚分），是一次性量化"这张目标表错得多远"的标量。配套指标还有 ID 切换率（同一真实目标被系统换了多少次 ID：反映关联稳定性）与首检时延（目标进入视野到被确认的时间）。答辩时这三个指标一摆，比"平均精度 95%"诚实得多。

实现思路与设计

目标级协同感知的参考架构：每台机器人 = 本地感知 + 本地跟踪器；融合节点（可分布可集中）订阅所有航迹流，输出全局目标表。

航迹消息设计（每目标约 40 字节）

字段编码为什么需要
track_id（本机局部）uint16关联稳定性：配合"来源机器人 id"构成全局唯一键
位置 + 速度各 int16（厘米、厘米/秒）外推需要速度；量化误差进协方差（见下）
协方差（对角线 4 值）各 uint16 对数刻度融合的权重全靠它；不传协方差只能等权平均，退化为朴素融合
观测时间戳uint32 毫秒时延补偿的前提（跨机统一时钟）
置信度 / 状态uint8候选/确认/预测三态，供融合器取舍

设计要点：（1）只传对角线协方差，完整协方差 4×4 有矩阵浪费与一致性风险（旋转后非对角项不可忽略时应整体传并做坐标变换，工程折中见"常见坑"）；（2）量化误差要计入协方差，厘米量化相当于附加方差（1 cm 量化 → 方差约 0.08 cm²量级），小协方差必须"托底"到量化噪声以上，否则融合会把数字游戏的精度当真；（3）消息频率 5–10 Hz + 事件触发新航迹，航迹是状态语义（latest-wins），丢一帧下帧补。

融合器的处理管线（每周期）

  1. 收集本周期所有航迹（各来源、各时间戳），按来源维护"最新航迹表"。
  2. 时延补偿：全部外推到 t*（本周期融合时刻）；协方差同步膨胀。
  3. 分组关联：来自不同机器人的航迹两两做门限 + 匈牙利关联，形成"同一目标簇"。
  4. 簇内融合：每簇用 CI 逐对或序贯融合（ω 按迹比），得到全局航迹；单源簇直接透传。
  5. 全局航迹生命周期管理：确认、删除、以及对外发布（第 087 章的状态通道）。
设计决策：融合放在中心节点还是每台机器人？

中心融合：一份权威全局目标表，逻辑简单；中心掉线全队失明，且有一跳额外延迟。分布融合：每台机器人跑同一套融合器，输入同一批航迹消息（广播），输出各自一份全局表，无单点，带宽无额外增加（航迹本来就是广播的），代价是每台都要算（5 个目标 × 几台来源的 CI，占用可忽略）。推荐分布（对称）方案：它把"融合"从一个服务变成一个纯函数，任何一台机器人拿到消息流即可重建全局表，训练与调试都更容易。

关键代码与解读

片段 1：协方差交叉融合，保守但安全

import numpy as np

def fuse_ci(mu1, P1, mu2, P2):
    """协方差交叉（CI）：对任意相关的两个估计都给出一致的结果。
    输入 4 维状态 (x, y, vx, vy) 与 4×4 协方差。"""
    I1, I2 = np.linalg.inv(P1), np.linalg.inv(P2)
    # 权重用迹的比例：越自信（迹越大）的来源权重越高（ω 的最优值需数值优化，
    # 迹比是工程常用近似，性质仍然一致）
    w = np.trace(I1) / (np.trace(I1) + np.trace(I2))
    P_inv = w * I1 + (1.0 - w) * I2
    P = np.linalg.inv(P_inv)
    mu = P @ (w * (I1 @ mu1) + (1.0 - w) * (I2 @ mu2))
    # 一致性自检：融合结果不允许比更自信的单源更"确定"
    assert np.trace(P) >= min(np.trace(P1), np.trace(P2)) - 1e-9
    return mu, P

解读：这段代码的第一价值是把"融合"写成有不变量的函数：assert 是一条可在测试中常年开启的安全带，任何修改一旦破坏"不比单源更自信"的性质立刻暴露。权重取迹比这一工程近似，替代更精细的数值优化，是"足够好 + 可读"的工程取舍：ω 的精确值对最终迹的影响是二阶的，而数值优化会让嵌入在 10 Hz 循环里的这段代码成本失控。注意逆矩阵计算：4×4 矩阵求逆单次微秒级，20 个目标 × 每周期几次融合，占比可忽略，若目标数上百，再考虑按对角线近似或序贯 CI。

片段 2：数据关联，马氏门限 + 匈牙利全局分配

import numpy as np
from scipy.optimize import linear_sum_assignment

def associate(tracks, detections, gate2=9.21):
    """航迹-观测关联：门限先剔错，再全局最优一对一。
    gate2=9.21 是 2 维卡方 99% 分位；4 维用 13.28。"""
    C = np.full((len(tracks), len(detections)), 1e6)   # 大代价 = 禁止配对
    for i, tr in enumerate(tracks):
        for j, de in enumerate(detections):
            e = de.z - tr.hx()                 # 观测残差：必须已变换到同一坐标系
            S = tr.H @ tr.P @ tr.H.T + de.R    # 残差协方差：航迹不确定 + 观测噪声
            d2 = float(e @ np.linalg.solve(S, e))        # 马氏距离平方
            if d2 < gate2:
                C[i, j] = d2                   # 门限内的真实代价
    rows, cols = linear_sum_assignment(C)      # O(n³) 全局最优分配
    return [(i, j) for i, j in zip(rows, cols) if C[i, j] < 1e6]

解读：三个关键选择。（1）马氏距离的归一化作用：欧氏距离没有考虑"位置估计本身有多准"，远处目标估计本来就粗，用欧氏会错杀；马氏把不确定性归一化，得到的是"相对自己置信度的远近"，这正是卡方门限成立的前提。（2）禁止配对的代价要足够大（1e6）且最后过滤：匈牙利算法要求方阵式完全分配，不设大代价它会把不搭界的航迹硬配给新检测；设了以后通过阈值过滤，未配对者自然进入"航迹起始"或"丢失计数"。（3）求解用 np.linalg.solve 替代显式求逆：数值稳定，代价还低，这类细节是"这段代码写进产品"与"只写进论文伪代码"的区别。

片段 3：时延补偿，外推加协方差膨胀

import numpy as np

def predict_to(mu, P, t_obs, t_now, q_acc=0.1):
    """把航迹外推到当前时刻。匀速模型：
    mu' = F·mu；P' = F·P·Fᵀ + Q。q_acc 是加速度噪声谱密度。"""
    dt = t_now - t_obs
    if dt <= 0:
        return mu, P                       # 无延迟：不折腾，防止数值倒推
    F = np.eye(4)
    F[0, 2] = F[1, 3] = dt                 # x += vx·dt；y += vy·dt
    # 过程噪声：假设加速度未知但有限，dt 越长位置越不可信
    q_pos = q_acc * dt**3 / 3.0
    q_vel = q_acc * dt
    Q = np.diag([q_pos, q_pos, q_vel, q_vel])
    return F @ mu, F @ P @ F.T + Q

解读：这段 15 行的函数是"诚实"的典范，它们同时返回外推后的状态和"膨胀后的不确定性"。很多实现只更新状态不更新协方差，等于宣称"我把目标的位置推到了 80 ms 后，且精度还和刚观测时一样"，融合器收到这种航迹会严重高估它，错误权重就产生了。过程噪声量级配合加速度假设：q_acc = 0.1 m²/s³ 对应"加速度大约 0.3 m/s² 量级"的机动；轮式机器人在平地上足够，若目标是行人/无人机应上调。dt ≤ 0 分支防的是时钟抖动导致的负外推，负时间外推不是"补偿"，是制造误差。

常见坑

  • 朴素融合造成双重计数：两台机器人用同一地图定位，误差强相关，逆方差融合后协方差塌缩。症状：系统自信满满地偏离真值。修复：默认用 CI，只有在能够论证独立同分布时才用逆方差；对共享了上游信息源的估计永远不用。
  • 融合前不做时延对齐：快慢来源直接平均，融合航迹被"拖向过去"，跟随运动目标时持续滞后。修复：全管线带时间戳，融合前统一外推；外推协方差如实膨胀。
  • 协方差不做坐标旋转：航迹从机体系转世界系时只转了均值，协方差仍是机体系的对角阵，朝向 90° 的机器人，其横向不确定度被当成纵向用。修复：P' = R·P·Rᵀ 与 R 同源变换，写单元测试验证"旋转 90° 后不确定性椭圆跟着转"。
  • 门限过松或过紧：过松把不同目标配成一对（换 ID），过紧大量漏配（目标数翻倍）。修复：用卡方分位数做起点（2 维 9.2），用 ID 切换率与漏配率的实测数据回调，避免凭感觉取值。
  • 只看准确率不看集合指标：单帧检测准确率 97% 掩盖了"目标表数量经常错 1–2、ID 每小时换 200 次"。修复：报告必须含 GOSPA（含基数罚分）、ID 切换率、首检时延三项。

练习与思考

  1. 算一算：A 机给出位置估计 σA = 0.10 m，B 机 σB = 0.20 m（一维、零均值）。分别计算(1)朴素逆方差融合的 σ；(2)取 ω 按方差比的 CI 融合的 σ。解释两者差值说明什么。★
    提示
    (1) σ = (1/0.01 + 1/0.04)^(−1/2) ≈ 0.089 m，比 A 单独还准，这是"取用两次信息"的结果；(2) CI 的一维形式 σ ≥ min(σ_A, σ_B)，取 σ→0.10 m 一侧。差值告诉你：当两个估计高度相关时，朴素融合的"变准"是虚的。
  2. 改配置并预测结果：把航迹消息里的协方差字段去掉（只发位置与速度，接收端假设固定协方差），预测关联门限行为与融合权重分配的变化，特别是"远处精度差的目标与近处高精度目标"的处理差异。★
    提示
    固定协方差使门限失去"距离自适应"能力：远处目标被频繁漏配（真实不确定度大得多），融合权重也无法区分好坏来源，退化成等权平均。结论：协方差不是可省字段，是关联与融合的度量衡。
  3. 设计：为"仓库 5 台 AMR 共享行人检测"写航迹消息的完整字段表（字段、类型、字节、来源、更新频率），并给出你选择"只传对角协方差"还是"传完整协方差"的论证。★★
    提示
    参考设计小节表格；论证要包含：什么情况下非对角项不可忽略（强旋转、目标机动耦合），此时"对角近似 + CI 保守化"是否能兜底（能，代价是膨胀），以及你的场景是否容忍该代价。
  4. 推导：设两个航迹的估计误差完全同源（相关系数 ρ = 1，即两次估计其实测的是同一条误差轨迹）。证明朴素逆方差融合的方差恰好是单源方差的 1/2 倍（过度自信），并用 CI 的下界性质说明正确的融合方差至少应为多少。★★
    提示
    ρ=1 时 e₂ = e₁，融合误差方差 Var = 0.25(Var₁+Var₂+2ρ√Var₁Var₂) = 单源的均值平方形式；证明要点是"融合不产生新信息"。CI 的 tr(P) ≥ min 单源 tr 意味着正确做法退回"用较好的那个"，这就是保守的物理含义。
  5. 实验：两台机器人各带 100 ms 级别延迟观测同一匀速目标，对比三个版本：(a) 不补偿直接融合；(b) 补偿 + 协方差膨胀；(c) 补偿但协方差不膨胀。绘制位置 RMSE 与"报告的 σ vs 实际误差"曲线，用一页结论说明"诚实的不确定性"为什么比"看起来准"重要。★★★
    提示
    预期：(a) 系统性滞后偏差；(b) RMSE 略升但报告的 σ 与实际误差相符；(c) RMSE 与 (b) 相近但报告的 σ 远小于实际误差，下游门限与安全判断会因此误判。结论落在"Σ 可信度"这条指标上；单比 RMSE 会漏掉过度自信。

小结

  • 融合三层级：原始级信息全但带宽爆炸，目标级 1–10 KB/s 成为工程主流；航迹消息 = 状态 + 协方差 + 时间戳 + 置信度。
  • 朴素逆方差融合假设独立，对同源误差会双重计数、协方差塌缩；CI 用权重 ω 在保守与激进之间滑动，对任意相关性都给出一致结果。
  • 关联三步：卡方门限剔错 → 匈牙利全局分配 → 生命周期管理（候选/确认/删除）；马氏距离是门限成立的前提。
  • 时延补偿 = 外推 + 协方差膨胀；不膨胀的补偿等于制造过度自信。
  • 评价用集合指标：GOSPA（位置 + 数量）、ID 切换率、首检时延；报告的 σ 与实际误差的一致性是可信度的核心。
  • 下一章把融合后的"看得清"升级为"做决定"：协同决策机制，拍卖、共识与协商的决策规则设计。
