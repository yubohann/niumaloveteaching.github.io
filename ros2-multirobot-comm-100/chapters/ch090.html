第五篇 · 科研进阶与协同机制

第 090 章：多机器人协同学习机制

第 082 章学会了"怎么训"，本章拆开三个学习机制内核：门控通信（何时开口）、注意力聚合（听谁的）、反事实功劳分配（谁的贡献），让学出来的协同既省带宽又可解释。

  • 主题：协同学习机制（通信学习与功劳分配）
  • 关键机制：通信门控、注意力消息聚合、反事实基线、对弈课程
  • 预计学时：60 分钟
  • 前置章节：第 089 章

学习目标

  • 掌握"学习通信"的三种形态：固定广播、门控触发、端到端学出的消息，以及门控为什么能把通信量压到 30% 左右而不掉性能。
  • 理解注意力聚合（query-key-value）在邻居消息上的作用：为什么"按相关性加权"比"取平均"更能利用关键邻居。
  • 掌握反事实基线（counterfactual baseline）与差分奖励：解决共享奖励下的功劳归属，抑制"搭便车"行为。
  • 理解非平稳性的对弈解法：对手快照、课程式扩规模（2 台 → 8 台）、联赛训练的基本思想。
  • 会为学习系统设计评价方案：协同成功率、通信-性能帕累托曲线、零样本扩展（N+2 台）测试。

背景与动机

第 082 章给了你 CTDE 骨架与通信预算，但骨架里有个神秘的洞："消息"到底是什么、什么时候发、谁的话该听？第 082 章的 SharedPolicy 用了最朴素的答案，每步都发、邻居消息取平均、训练靠集中评论家。这个答案能跑通玩具任务，但放到真实系统会暴露三个机制级问题：

  • 话太多：每步都发消息，带宽账单直接乘以决策频率；但很多步骤其实"无话可说"（道路畅通、无取舍），浪费的通信没有换来性能。
  • 听错人：20 台机器人里真正影响你决策的往往只有 2–3 台（正前方的、同任务的），平均聚合把关键信息淹没在无关消息里。
  • 搭便车：共享奖励下，一个机器人躲在队友后面"蹭团分"也能拿高回报，它学不会对集体真正有用的行为，因为奖励信号没有区分"有它"和"没它"。

本章逐个机制拆解这三个问题：门控（何时说）、注意力（听谁的）、反事实（谁重要），它们是 2020 年代以来多智能体学习从"能收敛"走向"可部署"的核心增量。每个机制都会回到同一条底线：学出来的东西必须过工程验收，带宽、可解释性、失效模式，一个都不能少。

核心原理

1. 通信门控：把"何时说"变成一个可学习的二元决策

门控通信的机制设计非常简洁：策略网络每步先算一个门信号 g ∈ {0, 1}（通常用 sigmoid 输出 + 阈值 0.5），g = 1 才编码并发送消息，g = 0 则静默。训练的驱动力来自任务奖励 + 通信惩罚：

目标 = 任务回报 − λ · Σt gt ·（每消息字节数 / 参考字节数） λ 控制"省话"的力度：λ 太小时门恒开（无收益），λ 太大时门恒关（协同崩），常用做法是拉格朗日乘子自适应：把通信量约束在预算内，λ 自动调整

实验现象与直觉一致：训练收敛后的门开率稳定在 20–40%，门开启的时刻集中在"即将相遇、让行、任务切换"等真正需要协调的时刻；直线巡航阶段全程静默。这带来两个工程红利：带宽从"周期恒定"变成"事件平均"，且门信号本身是可观测的旁观指标，把每台机器人的门开率画出来，协调热点一目了然，这是不可解释的端到端策略里少有的一扇"解释窗口"。

2. 注意力聚合：听相关性最高的话

平均聚合有一个隐含假设：所有邻居同等重要。真相是：影响你下一步决策的邻居排它性极强。注意力机制（attention）把每个邻居的消息变成三件东西：查询 q（我在找什么）、键 k（你声称你是什么）、值 v（你真正要传达的内容）。用我的 q 与每个邻居的 k 做点积、softmax 归一化成权重，再对 v 加权求和：

αj = softmax( qi · kj / √d )，消息 mi = Σj αj · vj √d 缩放防点积过大导致 softmax 饱和；邻居顺序无关（天然置换等变），比按固定顺序拼接输入更抗拓扑变化

它相对平均的三个改进：（1）信息选择，α 高的邻居主导输入，正前方拦路者的消息自然压过远处队友的闲聊；（2）规模不变，2 个邻居和 8 个邻居的网络结构不变，只是求和项数不同（置换等变性），这直接支撑零样本扩展：训练时 4 台、部署时 6 台仍可用；（3）权重可解释，α 是可视化对象，"机器人 A 的决策 70% 受 B 影响"可以直接画出来，比黑箱输出多了审计入口。

3. 反事实基线：没有我，情况会怎样？

共享奖励 R 只说"大家总共得了几分"，不说"这一分跟我多大关系"。反事实功劳分配（counterfactual credit assignment）问一个很自然的问题：如果把我的动作换成"默认动作"（比如停住/不干预），其余不变，团队回报会差多少？差值就是我的边际贡献：

Ai = Q(s, a) − Q(s, (a−i, ci)) ci 是智能体 i 的默认动作；Ai 即"反事实优势"，只归功于 i 的那部分

为什么它比"直接减一个团队平均"好：答案藏在基线的数学性质里。策略梯度的基线 b 只要与当前动作无关，不改变梯度的期望，只降低方差，所以用任何基线都是"安全"的，问题只在于哪个方差更小。团队平均基线对"人人都重要"的场景有效；反事实基线精确剔除了"其他人也会做的好事"，只留 i 的边际增量，因此在混住场景（有的机器人关键、有的摸鱼）里方差更小、学习更快。代价是要对每个 i 做一次额外的 Q 评估（计算量 ×N），工程上用"对代表性 ci"（停住/直行）近似，换来显著的行为分化，训练后你会看到关键岗位的机器人主动"顶上去"，全队不再挤在一起蹭分。

4. 非平稳性的对弈解法

第 082 章说过非平稳性是独立学习的头号敌人。工程上最有效的缓解是把"环境在变"变成"环境故意在变"，让变化变得可控：对手快照，训练时每个队友的动作来自其几轮之前的旧策略快照（慢变化，近似固定环境）；课程扩规模，从 2 台开始学让行，稳定后加第 3 台、第 5 台，每阶段冻结上一阶段成果；联赛（league），保留"主策略 + 多个专攻某种打法的利用者（exploiter）"，主策略被利用者打败就针对性加练，防止策略退化到"只会打熟悉的对手"。这三条的共同逻辑：与其祈祷非平稳不存在，不如主动控制它变化的速度与多样性。

5. 评价：从"团队分数"到机制级验收

学习机制的验收不能只有一条团队回报曲线：

  • 通信-性能帕累托曲线：横轴通信量（字节/步/机），纵轴任务成功率；门控机制应该给出"省 70% 通信、掉 2% 性能"这样的点，与全时广播的基线对比成曲线。
  • 零样本扩展：在 4 台训练的系统上直接跑 6 台（不改任何参数），成功率退化在一个事先约定的阈值内（如从 92% 掉到不低于 80%）。
  • 行为分化检查：统计每台机器人"关键动作"（如先通过窄道、吸引注意）的发生率，如果 10 台机器人行为完全一样且没有分工，说明功劳分配失效，全在搭便车。
  • 门开率与 α 权重的解释性审计：找几个典型场景人工检查"该说话时说了吗、该听的人听了吗"，这是把学习机制写进论文实验章的关键素材。

实现思路与设计

把三个机制装进策略网络的结构里：每台机器人的策略节点 = 门控 + 编码器 + 注意力聚合 + 动作头，训练侧 = 集中评论家 + 对弈课程。

模块输入 → 输出规模参考对应机制
门控 g观测 → 1 bit2 层 × 32 单元 MLP何时说（省带宽）
编码器 m观测 → 8 维消息2 层 × 48 单元说什么（低维意图）
注意力邻居键值 → 加权消息每邻居投影 3×16 维听谁的
动作头自身观测 + 聚合消息 → 2 维2 层 × 64 单元决策输出
集中评论家联合状态+动作 → 每机价值3 层 × 128 单元功劳分配（训练期）

工程接口约定：消息 8 维 float16 量化（16 字节）或 int8（8 字节）；门关时不发任何字节；注意力只对"通信半径内、最近 K=5 台"计算 α。训练配置：课程 2→3→5→8 台；每阶段 2000 episode；对手快照每 200 episode 更新一次；通信预算 λ 从 0 起步（先学协作）再逐步升到预算约束值（再省话），先学会说话，再学会少说，直接罚通信量会让门从一开始就关闭，协作能力根本没机会长出来。

设计决策：门控开关的梯度怎么过？

阈值化 g = (sigmoid(u) > 0.5) 本身不可导，工程上两种做法：(a) 用直通估计（straight-through）：前向用 0/1，反向把梯度原样透传给 sigmoid；(b) 用"软门"g = sigmoid(u) 全程可导，前向时按阈值 0.5 决定实际发不发，软门值还用作消息的缩放系数。两者都能收敛，(b) 更平滑但门开率最终会略高(软门难以真正归零)。选 (b) 起步，若带宽仍超预算再切 (a)。这个细节之所以要写进设计文档：它直接决定"通信预算"能不能被兑现。

关键代码与解读

片段 1：门控 + 编码器，先决定说不说，再说多少

import numpy as np

class CommGate:
    """通信门控：sigmoid 软门决定是否发送；门值缩放消息（可导）。"""
    def __init__(self, obs_dim=12, msg_dim=8, hidden=32, seed=0):
        rng = np.random.default_rng(seed)
        self.w_gate = rng.normal(0, 0.1, (obs_dim, hidden))
        self.b_gate = rng.normal(0, 0.1, (hidden, 1))
        self.w_msg = rng.normal(0, 0.1, (obs_dim, msg_dim))
        self.threshold = 0.5               # 前向判定用：门值低于它就不发字节

    def forward(self, obs):
        h = np.tanh(obs @ self.w_gate)
        gate = 1.0 / (1.0 + np.exp(-(h @ self.b_gate).item()))  # 软门 σ∈(0,1)
        msg = np.tanh(obs @ self.w_msg) * gate   # 门值缩放：训练信号直达编码器
        return gate, msg

    def should_send(self, gate):
        # 前向时硬化：省下的是真实带宽；反向梯度由 soft gate 承担
        return gate > self.threshold

# 校准观察：训练收敛后平均门开率 20–40%，若 >80% 说明 λ 太小或没升到位

解读：这个结构把"省带宽"与"可训练"平衡在两个量上：前向用硬判定（真实省字节），反向用软门（梯度流动）。msg = tanh(...) * gate 一行是设计的核心：门值与消息相乘，当门趋近 0 时，任务梯度会同时调节"发送决策"和"消息内容"两个路径，网络自动学会"要发就发有用的，没用就别发"。门开率 20–40% 是收敛良好的信号；恒在 80% 以上说明通信惩罚 λ 没有升到有效区间，需要检查自适应 λ 的实现（预算未绑定）。

片段 2：注意力聚合，按相关性给邻居消息加权

import numpy as np

def attention_aggregate(obs_neighbors, msg_neighbors, w_q, w_k, w_v):
    """注意力聚合：q 来自我的观测，k/v 来自邻居（消息）。
    obs_neighbors: (K, obs_dim)；msg_neighbors: (K, msg_dim)。"""
    q = obs_neighbors[0] @ w_q           # 本机视角的查询向量
    # 每个邻居给出键（我声称的关注点）与值（真正要传的内容）
    K_mat = np.tanh(msg_neighbors @ w_k)   # (K, d)
    V_mat = np.tanh(msg_neighbors @ w_v)   # (K, m)
    scores = K_mat @ q / np.sqrt(K_mat.shape[1])   # 缩放点积：防 softmax 饱和
    a = np.exp(scores - scores.max())      # 减最大值：数值稳定的 softmax
    a = a / a.sum()
    return a @ V_mat, a                    # 返回加权消息与权重（权重可供审计）

解读：三处工程细节。（1）q 只用本机观测算：注意力是"我的需求"匹配"你的信息"，不是双向对称；这样每个机器人只计算自己的权重，无需额外通信。（2）减最大值再归一化：softmax 的标准数值技巧，邻居分数差异大时不易溢出，嵌入控制循环的代码必须假定输入可能"离谱"。（3）返回权重 a 不只是为了好看：它是整条学习管线里唯一可直接解释的中间量，实验章节可以画"谁在什么时候主导了谁的决策"，也是调试利器（若 a 长期均匀分布，说明学到的注意力退化为平均，需检查键值投影是否学到东西）。

片段 3：反事实优势，每个智能体算一次"没有我"的回报

import numpy as np

def counterfactual_advantages(critic, s, joint_actions, default_actions):
    """反事实优势：A_i = Q(全体) − Q(把 i 换成默认动作)。
    训练期才能用：critic 需要看到联合状态与联合动作。"""
    q_all = critic.value(s, joint_actions)      # 一次前向：全员真实动作
    adv = np.zeros(len(joint_actions))
    for i in range(len(joint_actions)):
        cf = list(joint_actions)
        cf[i] = default_actions[i]              # 只把 i 换成"停住/直行"
        # 边际贡献：我的动作让团队多拿（或少拿）了多少
        adv[i] = q_all - critic.value(s, cf)
    # 逐智能体归一化：不同岗位的边际贡献量级差异大，防梯度被大值主导
    scale = np.abs(adv).mean() + 1e-6
    return adv / scale

解读：这段代码是"责任到人"的培训版，教练（critic）逐一模拟"把某个球员换下场"后的比分差，差值就是这个球员的场上价值。两个工程要点：（1）默认动作的选择是机制的一部分：选"停住"偏向惩罚冒险，选"直行"偏向评估进攻性；论文里必须写明你选了什么、为什么。（2）归一化按批内均值：抓取机器人一次出手的边际贡献可能是导航机器人的几十倍，不归一化时策略梯度会被大数主导，小贡献岗位学不动，归一化让"每个人的信号都在同一个量级说话"。计算成本 N+1 次 critic 前向：N=8 时每步 9 次小网络前向，训练可接受（部署时 critic 不存在，无影响）。

常见坑

  • 门坍缩：训练开始就重罚通信，门恒关，机器人学成"独行侠"，之后再打开也学不会协作。修复：λ 从 0 起步、课程式升高；监控门开率曲线，低于 5% 立即回退 λ。
  • 消息同质化：学出的消息与自家观测线性相关（"只报自己位置"），注意力权重学不出区分度。修复：加消息多样性正则，或给编码器加噪声冻结（类似 VAE 式压缩）逼迫信息瓶颈；检查 α 分布是否退化均匀。
  • 搭便车与懒惰智能体：共享奖励下部分机器人净贡献为负（挡路、蹭分）。修复：反事实/差分奖励训练；评估里加入"逐智能体边际贡献"统计，把持续为负的个体策略单独微调。
  • 非平稳发散：所有机器人同时学、同时变，回报曲线剧烈震荡。修复：对手快照 + 课程扩规模 + 集中评论家三件套；震荡期先冻结一半机器人的策略再训练另一半。
  • 仿真里的通信是真通信：训练时消息零延迟零丢包，部署时消息要过 WiFi，门控策略在真实链路上抖动。修复：训练时给消息注入延迟（5–30 ms）与丢包（1–5%），用第 082 章的量化纪律（int8、固定长度）直接对齐真实预算。

  3. 设计：两台机器人在 3 米宽走廊对向行驶，只允许发 4 维消息（float32，每步至多发一条）。用"门控 + 编码"框架设计你会让消息携带什么（位置、速度差、意图编码、让行请求……选 4 个），并解释每个维度的信息量理由与可解释性。★★

    候选：纵向间距（决定是否进入让行区）、相对速度（判断相遇时刻）、意图位（我让/你让）、目标点方向。论证角度：4 维是全带宽的千分之一，必须传"决策变量"本身；4 维的预算装不下原始观测。
  4. 推导：证明策略梯度里的基线不改变梯度期望，即对任意与动作 a 无关的 b(s)，有 E[∇logπ(a|s)·(R−b(s))] = E[∇logπ(a|s)·R]。再解释反事实基线为什么属于"合法的 b"（它是一个特定形式的状态-动作替换价值，训练时用它当优势估计）。★★
    提示
    核心恒等式：E_a[∇logπ·b(s)] = b(s)·∇Σπ = b(s)·∇1 = 0。反事实基线 b_i = Q(s, (a_-i, c_i)) 是 s 与其他人动作的函数，不显式依赖 i 当前选的动作，对 i 的梯度通道而言就是一个合法基线，因此不引入偏差、只降方差。
  5. 实验：4 台机器人窄道让行任务，训练三组：(a) 无通信；(b) 全时广播 + 平均聚合；(c) 门控 + 注意力。绘制通信-性能帕累托点和至少一条门开率/注意力权重的解释性曲线；再做 6 台零样本测试，填三轴对比表（第 086 章模板）。★★★
    提示
    预期：(a) 成功率最低但有兜底价值；(b) 高通信高成功率；(c) 介于两者且帕累托支配 (b) 更省、(a) 更强。零样本：注意力结构的退化最小（置换等变），平均聚合次之，无通信最难适应。报告里把 α 在关键相遇时刻的分布画出来做解释性证据。

小结

  • 学习通信三种形态：固定广播（简单费带宽）、门控触发（事件平均，开率 20–40%）、端到端学出的消息（低维意图，需解释性审计）。
  • 门控 = 软门训练 + 硬判定发送 + 字节级通信惩罚（λ 课程式升高：先学说话再学少说），门坍缩是最常见的训练事故。
  • 注意力聚合按相关性加权：规模不变、顺序无关（置换等变）、权重可解释；α 均匀化是退化的信号。
  • 反事实优势 Ai = Q(s,a) − Q(s,(a−i,ci)) 是合法基线：不偏梯度、只降方差，把功劳分到边际贡献上，抑制搭便车。
  • 非平稳用对弈化解：对手快照、课程扩规模（2→8 台）、联赛；仿真的通信必须带延迟与丢包才能迁移。
  • 评价三件套：通信-性能帕累托曲线、零样本扩展（N+2 台）、逐机行为分化检查。
  • 下一章换轴：从"学决策"回到"控制的数学"：协同控制机制：从集中到分布，最优性的差距与通信代价的精算。
