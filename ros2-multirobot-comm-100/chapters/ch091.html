第五篇 · 科研进阶与协同机制

第 091 章：多机器人协同控制机制：从集中到分布

控制机制的三档信息结构：集中式最优先贵、分散式便宜但盲、分布式介于两者，用"代价差 vs 通信轮数"的精算决定你在哪一档上停手。

  • 主题：协同控制机制（最优性-通信权衡精算）
  • 关键机制：集中式联合优化、分散式局部反馈、DMPC 迭代共识、收敛预算
  • 预计学时：60 分钟
  • 前置章节：第 090 章

学习目标

  • 用统一框架描述三档控制机制：集中式联合优化、分散式局部反馈、分布式迭代（DMPC），明确各自的假设与代价。
  • 掌握"最优性差距 vs 通信轮数"的量化方法：为什么边际收益递减、甜点通常落在每控制步 2–4 轮。
  • 理解分布式 MPC 的工程要素：热启动、Jacobi/Gauss-Seidel 更新、收敛判据、不收敛时的安全兜底。
  • 会用"耦合强度矩阵"为具体任务选择机制档位：强耦合任务不得不集中，弱耦合任务不值得通信。
  • 能算清控制周期的收敛预算：周期 100 ms、单轮 20 ms → 最多几轮迭代，以及超预算时怎么裁剪。

背景与动机

第 083 章你搭了策略层的工程骨架（仲裁、平滑、限幅），但那里的"贡献源"从哪来是给定的。本章回到更根本的问题：这些控制量到底应该由谁、基于什么信息、经过几轮交互算出来？这是协同控制的信息结构问题，也是科研论文里最常见的一根比较轴：同一个任务，集中式求解器、分散式控制器、分布式迭代控制器各跑一遍，比代价、比通信、比鲁棒性，然后论证"我们的机制在哪个位置更好"。

一个反直觉的结论要先摆出来：分布式控制并不天然省通信。它省的是"对中心的依赖"，但每步多轮迭代的消息量可能超过"集中式上传状态"的量，省不省，算过才知道。本章的核心工作就是把这三档机制放在同一张坐标系里：横轴是通信代价（字节/步/机），纵轴是最优性差距（相对集中式上限的百分比），每档机制在这张图上占一个点，你的任务是给具体任务找出哪个点最值。

与第 094 章的分工：本章关注信息结构与代价精算；094 章深入编队场景的稳定性证明（李雅普诺夫/图拉普拉斯）。两章合起来构成"分布式控制"的完整工具箱。

核心原理

1. 三档信息结构：同一控制问题的三个答案

设控制目标是使全队代价 J(x, u) 最小（x 联合状态，u 联合控制），约束包括动力学与安全。三档机制的答案：

档位机制需要的信息每步通信性质
集中式一个求解器算全部 ui全局状态全员上传 + 下发解最优（J = J*），单点，扩展差
分散式每台用本地反馈算 ui仅自身状态零（控制环内）便宜，把队友当"扰动"，忽略外部性
分布式本地求解 + 邻居迭代自身 + K 跳邻居每步数轮邻居交换介于两者，性能取决于轮数

分散式的"盲"有一个精确的说法：它不内部化外部性。当我的动作对队友的代价有影响（我堵住路口、我抢占空间），局部反馈看不到这笔账，于是算出的动作序列在个体意义上合理、在集体意义上亏。用一个小例子建立数量直觉：两台机器人位置 x₁、x₂，代价是"各自到位"加"保持间距"：

J = (x₁ − 0)² + (x₂ − 0.2)² + ρ·(x₁ − x₂ + 1)² ρ 是耦合强度。集中式解 (x₁, x₂) = (−0.27, 0.47)，J* ≈ 0.21；分散式各管各的（无异距项）取 (0, 0.2)，J ≈ 0.64，差 3 倍

差 3 倍不是数学巧合，接近"间距违反量² × ρ"的量级：没人协调时每个机器人只挪自己那一小步，而真正的代价藏在"它们之间"。耦合越强（ρ 越大），这个差距越夸张，这正是强耦合任务（协同搬运、协同抓取）必须上集中式或高轮数分布式的根本原因。

2. 分布式的杠杆：每步迭代几轮，收益怎么算

分布式机制的核心旋钮是"每控制步跑几轮邻居迭代"。轮数越多，各机器人的局部解越接近全局最优；但每轮都要花通信与时间。典型实验形态（编队过门任务、代价归一化到集中式）：

每步轮数相对代价（集中=1.00）额外通信（相对单轮）说明
0（分散式）1.800无人协调，拥堵代价大
11.351×一轮就能吃掉大半差距
31.123×甜点区：差距进入 10% 量级
61.036×收益已很薄
121.00512×基本逼近上限，通信亏

规律一望便知：收益递减、成本线性。这个形状的直接推论是最优轮数在"边际收益 = 边际成本"处，多数编队/避障任务落在 2–4 轮（相对代价 1.10–1.15，换来几倍通信节省与低延迟）。另一条要记住的反直觉结论：分布式每轮交换的消息可能比集中式全量上传还贵，轮数是乘法因子。所以"分布式更省通信"只在满足"轮数少 × 消息小 × 邻居少"时成立，这三个因子必须逐个精算，不能想当然。

3. 分布式 MPC 怎么真的跑起来

工程实现叫分布式模型预测控制（Distributed MPC, DMPC），分解成五个动作：

  1. 预测：每台机器人基于自身动力学预测未来 H 步轨迹（H 取 10–20，对应 1–2 秒）。
  2. 共享：把预测轨迹（不是原始观测）发给邻居，轨迹是低维结构信息（H 步 × 3 维 = 60 个浮点，量化后 120–250 字节）。
  3. 迭代：每台把邻居轨迹当前值当作"会动的环境"解本地优化（目标里含间距离、避让等耦合项），更新自己的轨迹，再交换，重复 r 轮。
  4. 热启动：下一控制步的初始猜测用本步的解（轨迹平移一步），热启动通常能省 1–2 轮迭代，是"收敛预算"的最大来源。
  5. 兜底：达到轮数上限仍未收敛（残差超阈值）时，不输出"半成品共识"，改为退到本地安全控制器（保守减速/停），分布式优化可以近似，安全兜底不能近似。

迭代更新方式：Jacobi（每轮用同一批旧值，天然并行）与 Gauss-Seidel（用邻居最新值，收敛快但需顺序/异步约定）。并行实现首选 Jacobi；收敛速度不足时再用"最新值可用则用"的异步版本，但必须处理消息的轮次标签（第 089 章谈过的轮号纪律）。

4. 收敛预算：控制周期是硬约束

控制周期 T 内要完成：通信往返 τ（5–20 ms）+ 本地求解（1–5 ms，热启动后更小）× 轮数。取 T = 100 ms（10 Hz 控制）、τ = 20 ms、求解 2 ms：

轮数上界 ≈ (T − 通信结算裕量) / (τ + 求解) ≈ (100 − 20) / 22 ≈ 3.6 → 取 3 轮 收敛预算是第四篇"实时性预算"（第 015 章）在控制机制上的应用：先划预算，再选算法

若任务要求每步 6 轮才能达标，只有三个合法出口：降控制频率（10 Hz → 5 Hz，用延迟换轮数）、增通信并发（轮次流水线：第 k 轮消息在算第 k−1 轮结果时已在路上，等效压缩 τ）、或换机制档位（回落分散式 + 更强安全过滤，接受性能差距）。偷偷超标（超时后用上一轮控制量）是事故的温床，控制量过期与丢失完全是两回事。

实现思路与设计

选档位的判据是耦合强度，不是系统规模。耦合强度可以量化：把"一台机器人的动作对其他机器人代价函数的影响系数"排成矩阵，看非对角项量级。

耦合强度典型任务推荐档位依据
强（非对角 ≈ 对角）协同搬运、协同抓取集中式或高轮数 DMPC约束互相纠缠，局部信息不足
中（非对角 30–80%）编队、协同避障DMPC 2–4 轮 + 兜底甜点区，代价差 10–15% 可接受
弱（非对角 < 10%）车队导航、覆盖分散式 + 安全过滤通信买来的收益低于成本

ROS2 实现要点：（1）轨迹消息走第 087 章的状态通道（Best-effort、10 Hz、增量位图编码），轮次用消息头里的 round 字段标记；（2）控制环与通信环解耦，通信在独立回调里收轨迹并按"最新轮次"覆盖，控制环只读快照：控制循环绝不 await 通信；（3）兜底控制器独立话题，安全控制器订阅同一批传感器，一旦 DMPC 超时/发散，直接输出减速指令（优先级覆盖，第 083 章的仲裁出口复用）。

通信负载精算（20 台、10 Hz、3 邻居、每轮 100 字节）

机制计算结果
集中式上传 500 B×20×10 + 下发 200 B×20×10≈ 140 KB/s
分布式 3 轮100 B×3 邻×20 台×10 Hz×3 轮≈ 180 KB/s
分布式 3 轮（量化 30 B）30 B×3×20×10×3≈ 54 KB/s
分散式0（控制环内无通信）0，但代价差 80%

这张表是全章最重要的一张：未量化的 3 轮分布式比集中式还费通信；量化后降到 1/3 才有优势。论文里报"分布式省通信"必须给出这三行对照，否则审稿人随手一算就会质疑。分散式的 0 也要并排放，"零通信"本身是一种机制，它的位置（代价差 80%）为整张权衡图提供了锚点。

关键代码与解读

片段 1：分布式 MPC 的单步，热启动 + 有限轮迭代 + 收敛判据

import numpy as np

def dmpc_step(robots, rounds_max=3, tol=1e-3):
    """一个控制步：本地解 + 邻域轨迹交换，最多迭代 rounds_max 轮。"""
    # 热启动：用上一步的解平移作为初始猜测，通常能省 1-2 轮迭代
    plans = {rid: r.shift_plan(r.last_plan) for rid, r in robots.items()}
    for k in range(rounds_max):
        new = {rid: r.solve_local_mpc(neighbor_plans=plans)   # 本地求解
               for rid, r in robots.items()}
        gap = max(plan_gap(new[rid], plans[rid]) for rid in robots)
        plans = new                     # Jacobi 更新：本轮统一用上一轮快照
        if gap < tol:
            break                       # 提前收敛：省下的时间还给控制周期
    ok = gap < 10 * tol                 # 兜底判据：没收敛就不假装收敛
    return {rid: (p, ok) for rid, p in plans.items()}

def plan_gap(a, b):
    """两个轨迹计划的最大逐点差：收敛判据用最大范数，卡的是最坏点。"""
    return float(np.max(np.abs(np.asarray(a) - np.asarray(b))))

解读：四个工程决定。热启动（第一行）把"每步从零迭代"变成"每步精修"，这是满足收敛预算的最大功臣；Jacobi 更新用上一轮快照，代码上表现为 new 与 plans 分离，任何依赖本轮队友最新值的写法都会让并行实现失去确定性（学习与复现都变难）；收敛判据用无穷范数（最大逐点差），不用均值：卡最坏点，均值小可能掩盖某一台机器人的轨迹还在剧烈摆动；最后的 ok 标志把"近似结果"与"可用性"分开交给上层：调用方必须检查它，不收敛时切兜底控制器；把半成品轨迹发给执行器属于明确禁止行为。

片段 2：集中式参照，为什么它需要"全局账本"

from scipy.optimize import minimize
import numpy as np

def central_reference(rho=1.0):
    """集中式参照解：两台机器人耦合代价的全局最优。
    J = x1² + (x2 − 0.2)² + ρ·(x1 − x2 + 1)²：间距项对双方同时生效。"""
    def J(x):
        return x[0]**2 + (x[1] - 0.2)**2 + rho * (x[0] - x[1] + 1.0)**2
    res = minimize(J, np.zeros(2), method="BFGS")   # 二次问题：任何求解器皆可
    # 参照上限 J* 作为纵轴零点：所有分布式机制的"代价差"都对着它算
    return res.x, float(J(res.x))

def decentralized_cost(x1=0.0, x2=0.2):
    """分散式解：各台按自己的目标 x1→0、x2→0.2 行动，间距项无人负责。"""
    return x1**2 + (x2 - 0.2)**2 + 1.0 * (x1 - x2 + 1.0)**2   # 实测同一代价

解读：集中式参照是整章实验的纵轴原点，没有它，"分布式差了 12%"是一句没有意义的话（跟什么比？）。这段代码刻意用最简单的二次问题：加法式耦合项（间距违规的平方惩罚）就是"外部性"的数学化身，它同时出现在双方的目标里，但只有集中式求解器会把它当真。分散式的实现里没有任何代码写错，错的是信息结构：没人有权限把这个耦合项最小化。运行两个函数你会得到 0.21 vs 0.64 的比值，练习 4 会让你手推这两个数。

常见坑

  • 不收敛却照发控制量：达到轮数上限残差仍大，直接截断当结果用，机器人在队列里"抖着走"。修复：残差判据 + ok 标志 + 兜底控制器（减速/停），把"近似"与"失败"分开处理。
  • 异步更新破坏一致性：有的机器人用邻居旧值、有的用新值且不打轮号，收敛性论证失效，实测随机发散。修复：消息带 round 字段，收旧轮直接丢；先保证 Jacobi 确定性，再考虑异步优化。
  • 通信延迟没进预算：设计时按零延迟算轮数，实机 τ = 30 ms，3 轮变 2 轮，"怎么调都差一口气"。修复：用 P99 往返延迟做预算（不是均值），并给收敛预算留 20% 余量。
  • 集中式单点无热备：中心求解器重启的 2 秒里全体机器人冻结在原地（或乱走）。修复：中心进程热备 + 控制端本地安全控制器常驻；中心的"最优"与本地兜底的"安全"是两层，不能互相等待。
  • 忽略消息量化的精度损失：轨迹量化到厘米后，耦合项里 1–2 cm 的抖动被平方放大成代价差，性能曲线莫名恶化 5%。修复：量化步长与耦合项的敏感度一起评估；对间距项做死区（小于 2 cm 的偏差不计），让量化噪声不进入目标。

练习与思考

  1. 算一算：20 台机器人、10 Hz 控制、每轮消息 30 字节（量化后）、每机 4 邻居。分别计算 1/3/6 轮分布式的通信负载；与集中式（上传 400 B/机、下发 150 B/机、10 Hz）对比。给出"分布式在几轮以内优于集中式"的结论。★
    提示
    分布式每轮 = 30×4×20×10 = 24 KB/s，3 轮 = 72 KB/s，6 轮 = 144 KB/s；集中式 = (400+150)×20×10 = 110 KB/s。结论：量化后 4 轮以内优于集中式，因子是"轮数 × 邻居数 × 消息大小"，三个都要算。
  2. 改配置并预测结果：把每步迭代从 6 轮降到 2 轮（其他不变）。预测代价差、通信量、单步延迟三项的变化方向；再从收敛预算公式估计这能否把控制周期从 100 ms 压到 50 ms。★
    提示
    先给方向：代价差上升（约 1.03 → 1.2 量级）、通信降 2/3、延迟降约 4×20 = 80 ms。50 ms 周期需要 2 轮 ≈ 2×22 = 44 ms + 裕量，临界，必须用 P99 延迟重新核算再定。
  3. 设计：3 台机器人协同搬一张长桌（强耦合），给出你的机制设计：档位选择、每步迭代轮数、消息内容（传轨迹还是传力？）、通信中断时的降级方案（谁先停、怎么停）。★★
    提示
    强耦合 → 集中式同步求解或高轮数 DMPC（6+ 轮）；消息传轨迹 + 意图；中断降级按"最保守者优先"：任一台失去同步就全体缓停（桌子悬停），恢复后重新同步再走。论证里要写明为什么不允许"单台自己继续"。
  4. 推导：对公式 J = x₁² + (x₂ − 0.2)² + ρ·(x₁ − x₂ + 1)²（ρ = 1），用一阶条件分别求集中式最优与"分散式忽略耦合项"的解，验证 J* ≈ 0.21、J_dec ≈ 0.64；再证明差距随 ρ 增大单调上升（提示：把间距违规量 δ = x₁ − x₂ + 1 表示为 ρ 的函数）。★★
    提示
    集中式：∂J/∂x = 0 联立得 x1 = −0.267、x2 = 0.467，δ* = 0.27；分散式 δ_dec = 0.8。J 的间距项 ρδ² 从 0.071 涨到 0.64，差距主要是 δ² 项。随 ρ：δ* 按 1/(1+ρ) 量级收缩而 δ_dec 恒定 0.8，差距 ∝ ρ 单调升。
  5. 实验：在编队过门任务上扫描轮数 0–12，绘制"相对代价 vs 每步字节数"曲线（片段 3 的产物），标出你推荐的甜点轮数与理由；再做一次 10% 丢包重跑，说明丢包把甜点推向哪一侧、为什么。★★★
    提示
    丢包使每轮有效信息变"稀"，需要更多轮达到同样残差 → 甜点右移；但丢包也使轮间方差变大，兜底触发率上升。报告里给出两条曲线的并列图与一句话结论："甜点不是常数，是网络质量的函数"。

小结

  • 控制机制三档：集中式最优但单点；分散式零通信但忽略外部性（例子中代价差 3 倍）；分布式用迭代在两者之间取点。
  • 分布式杠杆 = 每步迭代轮数：收益边际递减、通信线性增长；甜点通常 2–4 轮，选择依据是"边际收益 = 边际成本"或收敛预算。
  • DMPC 五动作：预测、共享轨迹、迭代、热启动、兜底；收敛判据卡最坏点，不收敛时安全控制器接管。
  • 收敛预算 = (周期 − 通信裕量) / (往返 + 求解)；10 Hz、τ = 20 ms 下约 3 轮；超标要显式降频或换档，不许偷偷用过期控制量。
  • 精算三因子：轮数 × 邻居数 × 消息大小，量化后分布式才真正便宜（表里 180 KB/s → 54 KB/s 的对照）。
  • 选档由耦合强度决定：强耦合集中/高轮数，中耦合 2–4 轮 DMPC，弱耦合分散式 + 安全过滤。
