第一篇 · 任务、数据、仿真与评测地基

第 006 讲｜指标 I：NE、TL、SR

本讲把轨迹换算成可比数字：先给出导航误差（NE）、轨迹长度（TL）与成功率（SR）的严格定义，再讲清距离口径、停止要求与阈值来源，最后用一条自设算例覆盖截断、未停、折返与提前停止四类边界，并核对 R2R 原文表 1 的相对量。

  • 主题：NE / TL / SR / 平均口径 / 边界语义
  • 关键公式：NE = dG(vT, v*)；SR = (1/N)·Σ 1[NE < 3]；TL = (1/N)·Σ Σt dG(vt, vt+1)
  • 预计学时：60 分钟
  • 前置讲：第 005 讲

学习目标

  • 会算：对一批 episode 记录计算 NE、TL、SR，并写出三个指标的平均口径。
  • 会区分：图距离（geodesic）与欧氏距离；按最终位置评分与按 oracle 停止评分。
  • 会实现：与官方评测脚本一致的指标累加器，含全对最短路缓存、成功计数与断言。
  • 会判断：截断、未输出停止、原地打转、提前停止四类边界轨迹对三个数字的影响。
  • 会核对：用 Python 复算 R2R 原文表 1 的行间相对量，解释 seen 与 unseen 的落差方向。

背景与动机

第 005 讲把动作空间与解码讲完了：模型能走、能停、能搜索候选。接下来必须回答「走得怎么样」。评测指标就是这门课的数字语言：同一句指令、同一个起点，两条轨迹谁更好，要靠指标给出可复核的判断。R2R 原文把任务的成功定义得相当克制：导航误差小于 3 米即成功，轨迹与朝向不进入判定（Anderson 等，2018，4.4 节）。这份克制是刻意设计，理解它才能读懂后续所有论文的数字。

三个基础指标分工明确。导航误差（Navigation Error, NE）度量终点离目标多远；轨迹长度（Trajectory Length, TL）度量智能体实际走了多少路；成功率（Success Rate, SR）把每个 episode 的成败变成 0/1 再求平均。三者合起来能回答「有没有到、绕了多少、成不成」三个问题，但每个指标单独看都会漏掉信息：NE 低而 TL 高的轨迹可能绕远，SR 高而 TL 极短的模型可能提前停在目标附近。

评测方法学上还有两条来自共识文献的纪律。Anderson 等 2018 的评测报告（arXiv:1807.06757，导航评测工作组共识）建议：智能体必须输出专门的结束动作（DONE），评分在该动作发生的时刻进行；接近程度用环境中的最短路距离度量（该报告称 geodesic distance），欧氏距离会给出误导结论。这份报告同时建议 SI 单位与场景划分的公开化，本课程全部沿用米与弧度。

本讲只处理 NE、TL、SR 与它们的边界语义；SPL、OSR 与统计口径留给第 007 讲。两者合读，才能组出一张完整的评测表。R2R-CE 与 RxR-CE 的验证集包含已知标注讹误（后续 045、048 讲展开），其数字与离散 R2R 不可直接混排，这条纪律从本讲开始执行。

核心原理

1. 三个指标的定义

设第 i 个 episode 的起点为 v0，目标为 v*，智能体输出停止动作时所在位置为 vT（T 为停止时刻），轨迹经过的视点序列为 v0, v1, …, vT。导航图为带权无向图 G，dG(a, b) 为两点间最短路距离，单位米。三个指标定义为：

NEi = dG(vT, v*) 忽略朝向与仰俯，只比较位置；评测脚本在停止时刻取最终位置计算
Successi = 1 [ NEi < 3 m ]，SR = (1/N) Σi=1..N Successi 判定为严格小于；N 为参与平均的 episode 数（R2R 以指令为条目）；3 m 为 R2R 协议阈值
TLi = Σt=0..T−1 dG(vt, vt+1)，TL = (1/N) Σi TLi 相邻两项为同一视点时贡献 0；官方脚本要求相邻视点在图中相邻，否则报错退出

还有一个不参与平均、但每次计算都要用到的参考量：最短路径长度 ℓi = dG(v0, v*)。它出现在第 007 讲的 SPL 中，此处先记住它的两个用途：判断 TL 是否合理，以及为效率指标提供分母。

2. 距离口径与停止要求

共识报告的两条建议直接决定实现。第一条关于停止：报告建议智能体配备结束动作，评分在结束动作产生时进行；若未产生该动作，episode 自动判为失败（Recommendation 1）。R2R 的动作空间包含停止动作，本课程以「停止时刻的位置」为准。第二条关于距离：报告建议使用环境中的最短路径距离度量接近程度，理由是欧氏距离不考虑墙体与可通行结构（Recommendation 2）。

构造一个最小反例验证第二条。两点在欧氏度量下相距 1.00 m，但中间隔着不可通行的隔断，必须绕行三个边：2.70 m + 1.00 m + 2.70 m = 6.40 m。用 Python 实算，图距离与欧氏距离之比为 6.40。若评测用欧氏距离，智能体隔墙站在目标旁边会被记为成功；用图距离则记为失败。NE 的「米」必须标明是图距离，本课程与 R2R 官方脚本统一。

官方评测脚本（仓库 tasks/R2R/eval.py）的实现口径与本讲一致：误差边界 error_margin = 3.0；成功计数为标准距离小于边界的条目数；轨迹长度沿提交的视点序列累加，相邻视点必须在图中相邻，否则抛出异常；脚本还断言 SPL 不超过成功率。这些实现细节说明一件事：指标超出公式本身，还包含数据合法性检查与边界约定，报告数字时必须连同脚本版本与配置一起写。

按最终位置评分与按 oracle 停止评分是两种口径。R2R 原文除 SR 外还报告 oracle 成功率（OSR）：允许智能体在轨迹上离目标最近的位置停止（Anderson 等，2018，4.4 节）。官方脚本用 _get_nearest 取轨迹经过视点中离目标最近者，并单独记录其误差。两个口径的差别是「识别目标」与「决定停下」的差别，细节与统计留到第 007 讲，本讲先建立正确的 SR 口径。

3. 阈值来源与平均口径

3 m 阈值有两个参照。其一，全景视点平均间距 2.25 m（第 002、004 讲），3 m 约合 1.33 个间距，为「停在目标附近一个视点内」留出余量。其二，R2R 路径采样时起点的最小误差为 5 m（第 004 讲），3 m 明显低于该值，避免「原地不动也能成功」的退化。原文的描述是「约一个视点的误差余量，且明显低于 5 m 的最小起始误差」（Anderson 等，2018，4.4 节）。

阈值是协议的一部分。共识报告的标准化场景（PointGoal）建议用两倍体宽作为阈值，默认体宽 0.2 m，即 τ = 0.4 m（arXiv:1807.06757，第 6 节）。3 m 与 0.4 m 相差 7.5 倍，两个协议的成功率没有可比性。连续环境的 VLN-CE 另有一套距离与超时定义（第 017、048 讲）。跨协议只做定性比较，定量数字各自成套报告。

平均口径按指令，不按路径。R2R 每条路径配 3 条指令，评测条目是指令：val-unseen 为 783 条路径、2,349 条指令；test 为 1,391 条路径、4,173 条指令；val-seen 为 340 条路径、1,020 条指令（第 004 讲实算）。官方脚本按指令累加并断言数量完整，缺一条即报错。把分母写成路径会立刻把 N 缩小三倍，SR 的数值也会改变；统计显著性还受「同路径三条指令相关」影响，第 007 讲给出修正方法。

4. 完整算例：L 形走廊

构造一个 6 视点、5 条边的 L 形走廊：v0 与 v1 在水平段，v2 为拐角，v3、v4 在竖直段，v5 为支路端点；每段长 2.5 m。起点 v0，目标 v4，最短路为 v0-v1-v2-v3-v4，ℓ = 10.0 m。各点到目标的图距离为：v0 10.0、v1 7.5、v2 5.0、v3 2.5、v4 0.0、v5 2.5（单位米，Python 实算）。六条轨迹与其指标如下。

episode轨迹（停止于末项）TL (m)NE (m)最近点误差 (m)成功备注
Av0 v1 v2 v3 v410.000.000.00是直达目标
Bv0 v1 v2 v37.502.502.50是TL 小于最短路，提前停止
Cv0 v1 v25.005.005.00否距离不足

汇总实算：A 至 D 四条，SR = 0.7500，平均 NE = 2.5000 m，平均 TL = 8.7500 m，OSR = 0.7500；加入 E 后 SR = 0.8000，平均 NE = 2.5000 m，平均 TL = 8.5000 m，OSR = 0.8000；加入 F 后 SR = 0.6667，平均 NE = 3.7500 m，平均 TL = 10.4167 m，OSR = 0.8333。读表要点如下。

  • B 的 TL 小于最短路（7.50 < 10.00）：这是提前停止的信号。TL 更短不代表更高效，只说明它没走完。SPL 的 max 分母正是为这类情形准备的（第 007 讲）。
  • D 成功但绕行：NE 与 B 相同（2.50），TL 比 B 多 5.00 m；只看 NE 无法区分两者，SR 都是 1。
  • E 的截断：官方脚本按轨迹最后位置计算，因此 E 与 B 的指标完全相同；共识报告建议无结束动作即失败，两种处理必须在报告中显式声明。截断标记是本讲推荐的必备字段。
  • F 的 OSR 与 SR 分离：轨迹经过 v4（最近点误差 0.00），OSR 记为成功，SR 记为失败。SR 反映「是否在正确位置停下」，OSR 反映「是否到过目标附近」。

6. 适用边界与失效模式

  • 截断轨迹：官方基线的 rollout 上限为 20 步（仓库 agent.py 与 train.py），超过即截断。官方评测脚本按最后位置计分，共识报告建议无结束动作判失败；两种口径对 SR 的影响可正可负，必须记录截断率并声明处理方式。
  • 原地打转与来回振荡：TL 被转向与折返抬高，NE 与 SR 可能完全不变。TL 上涨不能解释为探索，需结合动作分布与停步位置判断。
  • 朝向不进判定：成功只看位置，一个背对目标的停止动作同样成功。若任务关心朝向（例如拍照），需在协议外增加指标，不能在 SR 上附加未声明条件。
  • test 目标隐藏：R2R test 只发布起点与指令，评测由官方服务器完成；本地只能用 val-seen 与 val-unseen。用 val 数字冒充 test 属于误报。
  • 跨协议混排：离散 R2R 的 3 m 阈值、标准场景的 0.4 m 阈值与 R2R-CE 的连续环境阈值互不兼容；R2R-CE 与 RxR-CE 的验证集含已知标注讹误，数字需与其协议一并引用，不能与离散 R2R 拼接成一张表。

实现思路与设计

指标实现的目标是「可复核」：同一条轨迹在任何时候、任何机器上算出的数字一致，边界情形有显式标记，协议依赖项写在输出里。设计分三层：数据记录、计算核、报告模板。

数据记录与计算核

评测器在加载阶段做三件事：按 scan 建图并缓存全对最短路；按 (scan, path_id, 序号) 建立指令索引；校验提交覆盖全部指令。计算核逐条处理：检查轨迹首项等于起点、相邻视点存在边、按序累加 TL、取末项计算 NE、取轨迹中离目标最近的视点计算 oracle 误差。所有累加器带有下列不变式：成功数不超过 episode 总数；SPL 不超过 SR（第 007 讲实现后启用）；截断条目数单独计数。下表给出字段口径。

报告模板

一张合格的指标报告至少包含：数据集与版本（R2R 离散、Matterport3D Simulator v0.1 图文件）、split、指令数、步数上限、成功阈值、距离口径、解码方式、截断处理、是否含 oracle 停止。建议的表格列顺序为：方法、split、NE、TL、SR、OSR、SPL、截断率。NE 与 TL 带单位，SR 与 OSR 带百分号，SPL 保留三位小数。与第 005 讲的衔接在于：解码方式（贪婪或束搜索）改变轨迹，从而改变全部指标；与第 007 讲的衔接在于：SPL、OSR 的深入分析与显著性检验在那里展开。

关键代码与解读

三段代码分别实现图距离与轨迹指标、边界测试、官方风格的汇总。输出数值均由 Python 实算，与第 4 小节表格一致。

片段 1：图距离与单 episode 指标

import heapq

def dijkstra(graph, src):
    """带权无向图的单源最短路，返回距离字典。"""
    dist = {src: 0.0}
    pq = [(0.0, src)]
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist.get(u, float("inf")):
            continue
        for v, w in graph[u]:
            nd = d + w
            if nd < dist.get(v, float("inf")):
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return dist

def episode_metrics(traj, dist, goal, margin=3.0):
    """按停止位置计算 NE/TL/SR 三要素，并给出最近点误差。"""
    tl = sum(dist[a][b] for a, b in zip(traj, traj[1:]))
    ne = dist[traj[-1]][goal]
    oracle = min(dist[v][goal] for v in traj)
    return {"tl": tl, "ne": ne, "oracle": oracle, "success": ne < margin}

# L 形走廊：每段 2.5 m，目标 v4
nodes = {"v0": (0, 0), "v1": (2.5, 0), "v2": (5, 0),
         "v3": (5, 2.5), "v4": (5, 5), "v5": (2.5, 5)}
edges = [("v0", "v1"), ("v1", "v2"), ("v2", "v3"), ("v3", "v4"), ("v4", "v5")]
graph = {n: [] for n in nodes}
for a, b in edges:
    w = ((nodes[a][0] - nodes[b][0]) ** 2 + (nodes[a][1] - nodes[b][1]) ** 2) ** 0.5
    graph[a].append((b, w))
    graph[b].append((a, w))
dist = {n: dijkstra(graph, n) for n in nodes}
print(dist["v0"]["v4"])                      # 10.0
print(episode_metrics(["v0", "v1", "v2", "v3", "v4"], dist, "v4"))
# {'tl': 10.0, 'ne': 0.0, 'oracle': 0.0, 'success': True}

解读：（1）TL 沿轨迹相邻项累加，同一视点重复出现时距离为 0，符合官方脚本口径。（2）NE 只取末项，oracle 误差取轨迹最小值，两者分开记录，为 OSR 与 SPL 提供原料。（3）图距离全部来自最短路缓存，避免每次查询重复搜索；真实评测中按 scan 建一次缓存即可覆盖该场景全部指令。

def success(ne, margin=3.0):
    """严格小于：2.9 成功，3.0 与 3.1 失败。"""

assert success(2.9) and not success(3.0) and not success(3.1)
assert success(0.0)

def record(traj, dist, goal, truncated=False):
    m = episode_metrics(traj, dist, goal)
    m["shortest"] = dist[traj[0]][goal]   # 参考路径长度，供 SPL 使用
    m["truncated"] = truncated
    return m

# E：未输出停止，20 步截断；官方脚本按最后位置计分
e = record(["v0", "v1", "v2", "v3"], dist, "v4", truncated=True)
assert e["ne"] == 2.5 and e["success"] and e["truncated"]

# F：到过目标但终点回起点；SR 失败，oracle 成功
f = record(["v0", "v1", "v2", "v3", "v4", "v3", "v2", "v1", "v0"], dist, "v4")
assert f["oracle"] == 0.0 and not f["success"] and f["ne"] == 10.0
assert f["oracle"] <= f["ne"]  # 最近点误差不会大于终点误差

解读：（1）严格小于的边界用断言固定：3.0 m 判失败，避免浮点比较写成小于等于造成口径漂移。（2）截断通过显式参数传入，指标函数本身不猜测结束方式；这样同一批轨迹可以按两套口径重算，对照输出。（3）oracle 误差不超过终点误差是恒成立的不等式，可作为实现正确性的断言；若违反，说明最近点搜索或缓存有错。

片段 3：官方风格的汇总

def summarize(records):
    """对齐官方评测脚本的汇总口径：按指令平均，SPL 上限为 SR。"""
    n = len(records)
    num_success = sum(1 for r in records if r["success"])
    oracle_success = sum(1 for r in records if r["oracle"] < 3.0)
    spls = []
    for r in records:
        if r["success"]:
            l = r["shortest"]
            spls.append(l / max(r["tl"], l))
        else:
            spls.append(0.0)
    summary = {
        "length": sum(r["tl"] for r in records) / n,
        "nav_error": sum(r["ne"] for r in records) / n,
        "success_rate": num_success / n,
        "oracle_success_rate": oracle_success / n,
        "spl": sum(spls) / n,
    }
    assert summary["spl"] <= summary["success_rate"] + 1e-9
    return summary

# 用第 4 小节 A 至 D 四条记录验证：SR=0.75, NE=2.5, TL=8.75, SPL=0.7000

解读：（1）汇总字段名与官方脚本一致（length、nav_error、success_rate、oracle success_rate、spl），便于与公开数字对照。（2）SPL 的 max 分母与失败记 0 的口径在这里先行实现，第 007 讲给出完整推导。（3）断言 SPL 不超过 SR 是官方脚本同款检查；加了 1e-9 容差规避浮点误差。A 至 D 四条的汇总 SPL = (1.0 + 1.0 + 0 + 0.8) / 4 = 0.7000，与第 007 讲的推导一致。

常见误区

  • 用欧氏距离算 NE：隔墙的终点被判成功，指标虚高。根因：欧氏距离忽略可通行结构，1.00 m 的直线在实例中对应 6.40 m 的绕行。修复：一律用导航图全对最短路；把距离函数写进评测器唯一入口，训练侧禁止调用。
  • 把数据自带的 distance 当 TL 或 NE：指标与榜单不可比。根因：distance 是采集时写下的路径长度（参考量 ℓ），描述数据本身，与智能体实际轨迹无关。修复：TL 沿提交轨迹逐段累加；NE 与 ℓ 都用 connectivity 图重算。
  • 截断 episode 不标记：SR 被截断样本抬高或压低，且原因无法追溯。根因：官方脚本按最后位置计分，不区分是否输出过停止。修复：记录 truncated 字段，报告截断率，并给出「按失败处理」与「按最后位置处理」的对照数字。
  • 平均分母混用：同一模型换一份代码后 SR 变化。根因：按路径平均与按指令平均相差 3 倍条目，且同路径指令相关。修复：固定按指令平均并断言条目数等于 split 发布的指令数；路径级统计另做。
  • 阈值与协议混排：把标准场景的 0.4 m 数字或连续环境数字与 R2R 的 3 m 数字放进同一张表。根因：不同论文的阈值、动作空间与最大步数不同。修复：每张表只放同一协议的数字；跨协议比较先统一协议，或降级为定性讨论。

小结

  • NE 为停止位置到目标的图距离，朝向与仰俯不参与；SR 为 NE 严格小于 3 m 的比例；TL 为轨迹相邻视点距离之和的平均。
  • 距离口径用环境最短路（共识报告 Recommendation 2），停止时刻用 DONE/停止动作（Recommendation 1）；官方脚本 error_margin = 3.0，并断言 SPL 不超过 SR。
  • 3 m 阈值约合 1.33 个视点间距且低于 5 m 的最小起始误差；标准场景协议的阈值是 0.4 m（两倍体宽），跨协议不可比。
  • L 形走廊算例覆盖四类边界：B 提前停止（TL 小于最短路）、D 折返、E 截断、F 到过目标但终点失败（OSR 与 SR 分离）；A 至 D 汇总为 SR 0.7500、NE 2.5000 m、TL 8.7500 m。
  • R2R 原文表 1 的相对量：seen 到 unseen，SR 相对下降 43.52%，NE 上升 29.95%；人类 NE 为模型的 20.51%，模型 TL 比最短路短 18.1%，指向提前停止。
