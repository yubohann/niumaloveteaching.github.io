第三篇 · 连续环境、跨域与真实平台

第 044 讲｜执行效率与真实平台实测

本讲把路点模型从导航指标推进到执行代价：用真机 LoCoBot 标定的旋转与平移时间模型计算估计执行时间（EET），对比路点预测网络与固定步长网络在每条轨迹上的耗时、决策数与平均速度，给出延迟预算表与 SCT 口径，并写清仿真到真机的剩余差距。

  • 主题：执行效率 / 真机运动模型 / EET / SCT
  • 关键公式：yrot = 0.000358φ² + 0.108φ + 2.23；ytrans = 4.2x + 0.362
  • 预计学时：60 分钟
  • 前置讲：第 043 讲（Waypoint 模型：路点预测与动作谱）

学习目标

  • 会算：按 LoCoBot 运动模型计算任意转向角与任意前进段的执行时间，并对一条示例轨迹给出 EET 预算。
  • 会判断：区分 EET、墙钟时延与 SPL 的口径差异，解释导航指标与执行效率为何可能给出相反排序。
  • 会实现：按决策序列累计 EET，计算 TL/EET 平均速度与成功按完成时间加权（SCT）两个效率指标。
  • 会诊断：真机迁移相对仿真的四类附加代价（定位误差、碰撞、加减速、感知与推理延迟）与各自的可测性。
  • 会取舍：路点预测网络（WPN）与固定步长网络（HPN）在成功率与执行效率之间的选择判据。

背景与动机

第 043 讲把 VLN-CE 的动作空间从逐帧低层控制推进到学习式路点预测：网络一次决策输出一个相对路点，低层导航器沿直线走向该点，候选生成与动作谱执行构成两级结构。该讲遗留一个没有量化的问题：同样的成功率与路径效率，换成真机执行要花多少时间。仿真里的前进 0.25 米与转向 15 度都是瞬时完成的数学操作；真机上每条命令都有通信、启停与加减速开销，代价随动作频率放大。

本讲以 Krantz 等 2021 的 Waypoint Models 工作（ICCV 2021，arXiv:2110.02207）为主线。作者在一台实体 LoCoBot 上反复测量旋转与平移的耗时曲线，拟合出运动模型，再用它为仿真中的智能体轨迹估计执行时间（Estimated Execution Time, EET），并提出按完成时间加权的成功率（Success weighted by Completion Time, SCT）。结论有一处反直觉：标准导航指标更高的模型，执行时间可以接近两倍。

这项工作还承接了一条更早的迁移线索：Anderson 等 2021 的 Sim2Real-VLN 指出，把离散仿真训练的智能体搬到真机时，生成合适的候选路点是主要瓶颈，其软件外挂只依据局部视觉与激光估计候选点，表现明显低于直接给定导航图。VLN-CE 把动作空间连续化之后，路点预测可以在仿真里训练、在仿真里评测，真机标定则负责回答“执行要多久”。

本讲的产出是一张延迟预算表：把一条 episode 的总代价拆成感知、策略推理与低层执行三层，说明论文的 EET 只覆盖第三层，其余部分要么留给部署章节，要么用可复现的测量方法补齐。读完本讲应能对任意一段轨迹写出耗时公式，并对“仿真成绩好是否等于现场快”给出结构化回答。

核心原理

本讲按“代价为何成为一等指标、真机运动模型、EET 与 SCT、论文结果、边界条件”展开；所有公式代入与汇总数字均由 Python 实算，论文数字标注协议与来源。

1. 动作频率为什么值钱：两类固定开销

VLN-CE 的低层动作空间是参数化的离散命令：前进 0.25 米、左转 15 度、右转 15 度、停止（Krantz 等 2020，R2R-CE 协议）。在仿真里这些命令零成本；在真机上每条命令都触发一次速度规划与执行，产生与位移无关的固定开销。把它写成时间模型，平移 T 米、分 n 步执行的耗时为：

Tmove(T, n) = n · (a · (T / n) + b) = a · T + b · n a 为每米线性耗时，b 为每条平移命令的固定开销；固定开销随步数线性累加，与距离无关

代入手工标定的系数（论文附录 7.2 的 MoveBase 拟合：a = 4.2 秒/米，b = 0.362 秒）做实算：平移 2.4 米，一步完成需 4.2 × 2.4 + 0.362 = 10.442 秒；分成 10 步、每步 0.24 米，需 4.2 × 2.4 + 0.362 × 10 = 13.700 秒，多出 31.2%。结论一：平移总耗时等于“距离项加步数项”，缩短步长不减少距离项，只放大固定开销。

旋转的固定开销更重。论文的旋转拟合含二次项、一次项与常数项：

yrot(φ) = 0.000358 φ² + 0.108 φ + 2.23 φ 为转角，单位度；输出单位秒；常数项 2.23 为一条旋转命令的固定开销，二次项刻画加减速段

实算：15 度转弯 3.930 秒，其中固定项占 2.23 / 3.930 = 56.7%；45 度 7.815 秒，固定项占 28.5%；90 度 14.850 秒，固定项占 15.0%。若把一整圈 360 度拆成 24 次 15 度，总耗时 24 × 3.930 = 94.33 秒；拆成 12 次 30 度为 69.51 秒；拆成 8 次 45 度为 62.52 秒；一次完成 87.51 秒。离散搜索在 5 次 72 度（59.31 秒）附近取到最小，连续最优约在 79 度一步。结论二：旋转代价对命令次数极敏感，协议规定的 15 度粒度在真机上比 45 度粒度贵约 1.5 倍（94.33 / 62.52 = 1.51）。

两条结论合起来解释了本讲的主线：动作空间越抽象（一次决策走更远、转更少次），执行越快；动作空间越细，导航指标可能越接近最短路径，但现场耗时越高。两类指标衡量的是不同东西，必须分开报告。

2. 真机运动模型的标定方法

运动模型的三个可选底控制器为 MoveBase、ILQR 与 Proportional；论文对每个控制器重复测量并拟合，MoveBase 整体最快，全部估时用它。标定流程可直接复现：旋转项在 φ = 30°、60°、…、180° 上各采集 5 次“下达命令到机器人停止”的耗时，拟合二次函数；平移项在 x = 0.25、0.5、…、2.75 米上同样各采集 5 次，拟合一次函数。采用二次加一次的形式，原因是短距离与长距离的启停占比不同，二次项承担了加减速的非线性。

3. EET：把轨迹折算成执行时间

给定一条轨迹，先按低层导航器的执行方式分解成动作序列，再逐项代入运动模型：

EET = Σi yrot(φi) + Σj ytrans(xj) φi 为第 i 条旋转命令的角度，xj 为第 j 条平移命令的距离；只统计运动执行，不含感知采集与策略网络推理

论文评测两类轨迹：WPN 的“转向到路点方向，再直线走完预测距离”两步执行（连续导航器 CN），以及 HPN 的“在选定方向上一步 0.25 米”（复刻 VLN-CE 动作空间，用离散导航器 DN 近似到达路点）。给一个可以手验的示例：一次 30 度转向加 1.6 米直行需 5.792 + 7.082 = 12.874 秒；同样走 1.6 米、改用 6 次“15 度转向加 0.25 米”需 6 × (3.930 + 1.412) = 32.055 秒，为前者的 2.49 倍。这个对比只用于说明机制：实测的 HPN 每条轨迹平均 33.41 个动作、移动约 0.23 米/动作，转向命令的占比决定了总耗时。

EET 有两个必须记住的口径限制。第一，它只计运动，不含感知与推理；把它当墙钟时间会低估现场延迟。第二，它假设完美执行：转向精确、直线到达、无碰撞、无定位漂移；论文在 VLN-CE 的评测协议里同样假设完美执行，以便与仿真基线可比。

4. SCT：按完成时间加权的成功率

SPL 用路径长度加权成功率，对“绕远路”敏感；它对“走对了但走走停停”不敏感。SCT 把分母换成时间：

SCT = T / max(C, T) C 为智能体的估计完成时间；T 为在相同动力学约束下到达目标所需的最短时间；未成功时记 0；当 C 小于 T 时比值封顶为 1

论文把 T 的求解适配到该智能体的动力学：以 LoCoBot 运动模型定义两点间代价，用改进的 RRT*-Unicycle 在多楼层空间搜索最小时间路径，采样范围延到图节点外 4.0 米以匹配最自由的动作空间。实算两个代表行（论文表 1，R2R-CE val-unseen）：WPN 最好行 EET 153 秒、SCT 23；HPN 最好行 EET 297 秒、SCT 11。SCT 比为 23 / 11 = 2.09。结论三：同一批 episode 上，两类模型的排序在 SR/SPL 与 EET/SCT 之间翻转，效率优势必须用时间口径表达。

6. 标准榜单上的位置与执行层的取舍

为与已有工作公平比较，论文另用离散导航器（DN）执行 WPN 与 HPN，动作空间回到 R2R-CE 的 0.25 米 / 15 度，提交 VLN-CE 测试榜（论文表 3）。HPN+DN 的 test-unseen 为 SR 32 / SPL 30，比当时最好模型（CMA+PM+DA+Aug，SR 28 / SPL 25）高 4 SR（相对 14%）与 5 SPL（相对 20%）；WPN+DN 为 SR 29 / SPL 25。WPN 在标准指标上让出 3 SR / 5 SPL，换来执行时间的大幅下降。选择判据可以写成一句话：比榜单用 HPN 类细粒度输出，谈部署预算用 WPN 类抽象输出，两侧都报时间口径。

7. 边界与失效模式

  • 单平台标定：系数来自一台 LoCoBot 与 MoveBase 控制器，换底盘、换控制器、换地面材质都要重新测量。论文明确说明其他机器人可用同样流程另算模型。
  • 开环假设：EET 假定命令精确执行。真机的定位漂移会让实际转角与里程偏离计划，误差随轨迹累积；这一步不在 EET 之内。
  • 碰撞与动态障碍：仿真协议假设完美执行，EET 没有碰撞项。真机上一次卡住或重新规划的开销可能超过整条轨迹的估计值；碰撞处理的定量分析在 045 讲给出（固定步长的碰撞步占比 15% 对路点方案的 7%），工程侧方案见 051 与 058 讲。
  • 感知与推理未计入：全景 12 帧采集、路点网络前向、地图与规划（046 讲）都不在 EET 中。比较两种策略的现场时间时必须把这三层补齐，或明确声明只比较运动层。
  • 指标权衡不是单向的：WPN 的 SR/SPL 确实低于 HPN。效率收益以导航精度为代价，是否接受取决于任务：长走廊巡检偏好 WPN，靠近目标需要精细停靠时 HPN 的短步优势更稳。

产出 2：轨迹到 EET 的折算流程

流程分四步。第一步，记录轨迹的两类基元：每次决策的转向角 φ 与随后直行距离 x；对离散导航器，先把路径折线量化成 15 度转向与 0.25 米前进的命令序列。第二步，逐条命令代入运动模型得到用时。第三步，汇总得到 EET，并用轨迹长度除以 EET 得到平均速度。第四步，计算 SCT：用同一运动模型跑改进 RRT* 得到最短时间 T，再套公式。评测协议上与论文对齐：val-unseen、单次运行、确定性解码、停止阈值 3 米。

设计决策：时间模型与路径指标解耦

EET 由轨迹几何与运动模型相乘得到，与智能体的网络结构无关；同一段轨迹换机器人只需换系数。这种解耦让“策略效率”与“平台性能”两条改进线可以分别评估：策略侧缩短路径、减少转向；平台侧提高转向速度、降低命令开销。报告时两者分开归因。

关键代码与解读

三段代码分别实现运动模型、轨迹到 EET 的折算、以及 SCT 与平均速度的汇总。所有输出由 Python 实算，与本讲正文数字一致。

片段 1：LoCoBot 运动模型与单段预算

import math

def turn_time(deg):
    """MoveBase 旋转拟合：二次项刻画加减速，常数项为命令固定开销。"""
    return 0.000358 * deg * deg + 0.108 * deg + 2.23

def move_time(meter):
    """平移拟合：4.2 s/m 线性项 + 0.362 s 每条命令的固定开销。"""
    return 4.2 * meter + 0.362

# 两类执行方式的单决策对比：一次大跨步 对 六次小步
big = turn_time(30) + move_time(1.6)          # 12.874 秒
small = 6 * (turn_time(15) + move_time(0.25)) # 32.055 秒
print(round(big, 3), round(small, 3), round(small / big, 2))

# 整圈 360 度不同步长的总耗时
for n, phi in [(1, 360), (8, 45), (12, 30), (24, 15)]:
    print(n, phi, round(n * turn_time(phi), 2))

解读：（1）两个函数直接来自论文附录的拟合式，系数写成字面量便于替换成自测平台的结果。（2）单段对比把“转向次数”和“步长”两个变量的作用分离：每次执行都支付命令固定开销，一次大跨步省下 5 次转向与 5 次平移的命令项。（3）整圈循环验证非单调性：15 度粒度的总耗时 94.33 秒高于 45 度粒度的 62.52 秒，协议的细粒度在时间上更贵；若要实现速率优先的控制器，应允许更大的单次转角。

片段 2：轨迹到 EET 的折算

def parse_trajectory(commands):
    """把命令序列折算为 (旋转命令数, 旋转总角, 平移命令数, 平移总距离)。"""
    n_rot = n_move = 0
    sum_deg = sum_m = 0.0
    for kind, value in commands:
        if kind == "rotate":
            n_rot += 1
            sum_deg += abs(value)
        elif kind == "move":
            n_move += 1
            sum_m += value
        else:
            raise ValueError("未知命令类型: %s" % kind)
    return n_rot, sum_deg, n_move, sum_m

def eet(commands):
    """逐条命令计费；旋转按角、平移按距离，各自加固定开销。"""
    total = 0.0
    for kind, value in commands:
        total += turn_time(value) if kind == "rotate" else move_time(value)
    return total

# 15 度转向 x4 加三次 0.5 米直行，再接 30 度转向与 1.6 米
cmds = [("rotate", 15)] * 4 + [("move", 0.5)] * 3 + [("rotate", 30), ("move", 1.6)]
print(round(eet(cmds), 2))            # 35.98 秒
print(parse_trajectory(cmds))         # (5, 90.0, 4, 3.1)

解读：（1）parse 与 eet 分离：前者做统计（用于报告决策数与转向次数），后者做计费（用于累计时间），同一份命令流可派生两类报告。（2）逐条计费保留了“命令粒度”信息，若改成“总角乘平均系数”会系统性低估多命令轨迹，因为固定开销按次数累计。（3）遇到未知命令直接抛出异常，防止静默漏算：EET 对遗漏命令的敏感度等于该命令的完整耗时。

片段 3：EET、平均速度与 SCT 汇总

def episode_report(tl, eet_sec, success, oracle_time):
    """单条 episode 的效率报告：平均速度、SCT；未成功 SCT 记 0。"""
    speed_cm_s = tl * 100.0 / eet_sec
    sct = 0.0
    if success:
        sct = min(1.0, oracle_time / max(eet_sec, oracle_time))
    return speed_cm_s, sct

rows = [   # (编号, 轨迹长度 m, EET s, 成功, 最小时间 s)
    ("A", 10.62, 153.0, True, 118.0),
    ("B", 7.71, 297.0, True, 64.0),
    ("C", 9.10, 201.0, False, 95.0),
]
speeds = [episode_report(tl, e, s, o)[0] for _, tl, e, s, o in rows]
scts = [episode_report(tl, e, s, o)[1] for _, tl, e, s, o in rows]
print(round(sum(speeds) / 3, 2), round(sum(scts) / 3, 3))   # 4.69 0.329

解读：（1）SCT 分母取 max(C, T) 并对成功 episode 封顶 1.0，防止“抄近路快于理论最短时间”的数值越界；失败 episode 记 0，与 SPL 的失败口径一致。（2）算例 B 的 EET 297 秒接近 A 的两倍，SCT 从 0.771 降到 0.216，平均后两项指标都被拖低，说明 SCT 与耗时同向敏感。（3）速度与 SCT 都不含感知与推理，打印时保留位数的目的是在实验日志里可追溯；正文报告的 6.94 与 2.60 厘米/秒即由该函数在论文两个代表行上得出。

常见坑

  • 把 EET 当墙钟时延上报：真机实测比估计慢数倍，追查发现感知与推理未计。根因：EET 只求和运动命令。修复：按延迟预算表三层分解，缺测的层用参数化表达式标注，不用估计值冒充实测值。
  • 只看 SPL 选部署模型：选到 SPL 更高的细粒度模型，现场耗时近乎翻倍。算例：HPN 的 SPL 36 高于 WPN 的 30，EET 却是 297 秒对 153 秒。修复：效率类决策同时报告 EET、SCT 与决策数，并给出任务时间预算。
  • 跨平台直接套用运动模型：换机器人后估计值系统性偏移。根因：4.2 / 0.362 / 二次项系数都是单平台标定。修复：按同流程重测 5 次取平均，注明控制器与地面条件，不同平台不混表。
  • 用仿真“完美执行”推断现场安全：仿真无碰撞、无定位漂移，EET 也不含避障代价。根因：协议为了可比性刻意假设完美执行。修复：把碰撞、定位、动态障碍列为独立部署风险，量化实验放到 051 讲，其中碰撞步占比可从 045 讲的 15% 对 7% 起步。
  • 停止行为与阈值耦合被忽略：同一模型换停止规则后 TL 与 EET 同时漂移。根因：成功阈值 3 米之内的停止时机影响轨迹长度与命令数。修复：固定并报告停止规则（学习停止或最近点停止），两者成对报告，避免把停止策略的差异算进轨迹效率。

练习与思考

  1. 用本讲运动模型计算：45 度转向加 1.6 米直行的单决策耗时，与 4 次“15 度转向加 0.25 米”加 1 次 0.6 米直行的耗时，并解释差额来源。 ★
    提示
    前者 7.815 + 7.082 = 14.897 秒；后者 4 × (3.930 + 1.412) + (4.2 × 0.6 + 0.362) = 21.368 + 2.882 = 24.25 秒。差额主要来自 4 次旋转命令的固定开销（4 × 2.23 = 8.92 秒）。
  2. 三条 episode 数据为（TL，EET，成功，最小时间）：E1 (9.0, 140, 是, 100)、E2 (6.0, 260, 是, 60)、E3 (8.0, 180, 否, 90)，单位米与秒。计算平均速度与平均 SCT，说明哪个 episode 对 SCT 拖累最大。 ★
    提示
    速度 6.43、2.31、4.44 厘米/秒，均值 4.39；SCT 0.714、0.231、0，均值 0.315。E3 的 0 拖累最大，其次 E2 的低比值；两处都体现“时间口径惩罚慢执行”。
  3. 设计一个控制实验，使两个模型的 SR 相同但不含时间指标时无法区分效率，并写出需要记录的最小字段集。 ★★
    提示
    固定同一 split、同一停止规则、同一检查点选择标准；选取 SR 相同的两个模型，比较 EET 分布。字段：episode 编号、轨迹长度、命令流（类型、参数、顺序）、成功标志、最小时间。缺命令流就无法反算 EET。
  4. 把距离预测上限从 4.0 米降到 2.0 米，其余不变。结合平均预测距离 1.6 米、标准差 0.8 米与三段时间分布（2.3 / 1.6 / 0.76 米），预测决策数、EET 与 SR 的变化方向。 ★★
    提示
    上限 2 米截断尾部（约 31% 的分布超过 1.6 加 0.5 个标准差，前段 2.3 米的决策全部受限），决策数上升、EET 上升；SR 方向不确定：小步更接近最短路径但命令更多，需实验回答。该题的正确产出是带方向的预测加验证方案。
  5. 推导题，分三问：(a) 证明 n 步走完 D 米的平移耗时为 4.2D + 0.362n，并说明 n 减半时耗时如何变化；(b) 对转角 A 拆成 n 次 A/n 的旋转总耗时写式，说明为何整圈 360 度的最优粒度落在 70 度至 90 度之间（连续最优约 79 度）；(c) 基于 (a)(b) 给出一个降低 EET 的轨迹重排策略，并指出它可能带来的导航风险，以及用小规模实验验证“重排后 SR 不降”的判据。 ★★★
    提示
    (a) n 次求和即 n(4.2D/n + 0.362) = 4.2D + 0.362n；n 减半省 0.181n 秒。(b) 总耗时 = 0.000358A²/n + 0.108A + 2.23n，对 n 求导取零得 n ≈ sqrt(0.000358A²/2.23)，A = 360 时约 n = 4.6，故粗粒度近优，协议 15 度 (n = 24) 更贵。(c) 策略：合并连续转向、对齐路径折线后合并共线线段；风险：单段过长遇障重规划、转角过粗偏离参考路径；判据：同 checkpoint、同 val-unseen、SR 与 SPL 下降不超过预注册阈值（例如 1 个点）且 EET 显著下降。

小结

  • 执行时间由运动模型与轨迹几何共同决定：平移耗时 4.2D + 0.362n，旋转耗时含 2.23 秒命令固定项，动作频率越细代价越高；整圈 360 度用 15 度粒度比 45 度粒度贵 1.51 倍。
  • EET 把轨迹折算为纯运动时间，只覆盖执行层；墙钟时间还要加感知与推理，论文未测的部分必须显式标注。
  • R2R-CE val-unseen 上，WPN 代表行 EET 153 秒 / SCT 23 / SR 36 / SPL 30，HPN 代表行 297 秒 / 11 / 38 / 36：标准指标与效率指标的排序相反，各行比值 1.94，引言口径约 2.2 倍。
  • SCT = T / max(C, T) 用完成时间加权成功，失败记 0；与 SPL 成对报告才能同时约束路径长度与执行时间。
  • 边界：单平台标定、完美执行假设、碰撞与定位漂移未计；换平台需按同一流程重测运动模型。
