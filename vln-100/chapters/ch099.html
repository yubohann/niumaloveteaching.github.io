第五篇 · 基础模型与 2026 前沿

第 099 讲｜物理部署鸿沟再审视

第 060 讲的差距地图 v1 建立在室内静态证据上：四层（感知、地图、决策、执行）加一份协议与数据账，核心分解是 9.1 = 3.9 + 5.2 个百分点。本讲用第 041 至 098 讲的增量证据把地图升级到 v2：加入跨体态观察空间（相机高度 1.8 / 1.2 / 0.5 米）、环境动态与可通行性语义、以及一份新的接口与成本账。关键新证据：VLN-PE 报告物理设定下成功率相对下降 34%，Go2 真机微调后 SR 从 7.14% 升到 28.57%；DaViNCi 的动态元素让已见场景 SR 再降 5.0 个百分点；TEA 在 A2A 把 SR 从 0.47 提到 0.54；系统级智能体每集消耗 220.8 万输入 token、每次成功折合 424.7 万。交付物是部署检查表 v2（六组、含放行判据）与差距账 v2 模板。

  • 主题：部署差距 / 跨体态 / 动态与语义 / 接口成本账 / 检查表 v2
  • 关键公式：P部署 ≈ P仿真 × Π(1 − δ层)；C成功 = N调用(T入+T出) / SR；可比四元组（基准、半径、动作、split）
  • 预计学时：75 分钟
  • 前置讲：第 098 讲（2026 快照 VI：空中与室外新基准）

学习目标

  • 会写：把第 041 至 098 讲的部署证据按四层加两账归位，说明 v1 与 v2 的差异来源。
  • 会算：按每集调用数、token 与成功率折算「每次成功成本」；复算 OS−SR 停止缺口与体态、动态、光照三类差距量级。
  • 会实现：成本折算器、协议可比性闸门与风险评分卡三段示意代码。
  • 会判断：四个成功半径（2、3、10、20 米）之间哪些数字可引用、哪些必须重算；相对降幅与绝对百分点各自的分母。
  • 会设计：为给定机器人、环境与预算填写部署检查表 v2，并为未通过项设计最小诊断实验。

背景与动机

第 060 讲把第三篇的证据收成差距地图 v1 时，可用证据以室内静态评测为主：Anderson 等 2020 的 Coda 差距分解、ETPNav 的试错消融、R2R-CE 的协议口径。v1 的两个隐含前提在 2026 年的证据面前需要修订。第一，智能体的身体在 v1 里被简化为一个高度固定、运动理想的相机平台；第 051 讲的 VLN-PE 证明相机高度、控制器一致性与摔倒卡死会造成可观差距。第二，v1 把环境视为静态可通行空间；第 098 讲的 DaViNCi 与 TEA 说明动态障碍与体态相关的可通行性会直接改写成功率。

同时，第五篇引入了一类 v1 没有覆盖的部署对象：靠 API 调用的系统级智能体。它们的失败方式与成本结构不同。第 093 讲的协议跨度实验显示，同一模型家族在 R2R-CE 上可报出 81.3 与 52.0 两个数字，全部由协议决定；第 094 讲进一步把不确定性、按需计算与求助延迟变成可报告的量；第 098 讲的 AirAnchor 把「每集 45.8 次调用、6.8 万 token」写进结果表。这类系统的部署判断不能只看成功率，还要看每次成功的 token 与延迟，成本与性能必须成对评审。

本讲的任务是把这三类增量（体态与物理、动态与语义、接口与成本）并进差距地图，形成检查表 v2 与差距账 v2 模板。它同时是第 100 讲的输入：结课讲的复现清单按算力分档，而分档的边界正是本讲量化的成本与方法依赖。

核心原理

本节按「证据复盘、地图 v2、三类增量量化、检查表 v2、差距账模板、边界」六步展开；所有换算由 Python 实算，引用数字标注来源、协议与 split。

性能与成本分开记账的理由是二者的失效机制不同。性能缺口来自分布偏移与物理约束，靠离线评测与域随机化缓解；成本缺口来自接口设计，靠调用粒度、缓存与记忆压缩缓解，两者不共享对策。v2 的部署判断因此写成两个条件的合取：

可部署 ⇔ ( P部署 ≈ P仿真 × Π(1 − δi) ≥ Pmin ) ∧ ( C成功 = N调用(T入+T出) / SR ≤ Cmax ) δi 为各层相对损耗，乘性口径给出保守下界；C 以 token 或费用为单位，SR 用同一协议下的成功率，两项必须来自同一次评测

3. 三类增量量化

体态与物理。VLN-PE 用同一评测代码换机器人：人形约 1.8 米、平台默认 1.2 米、四足约 0.5 米，最高与最低相差 3.6 倍。把 CMA 的相机高度从默认 1.2 米对齐到 1.8 米后，验证未见集 SR 从 10.31 升到 13.58，相对提升 31.72%，显示观测几何是可以单独校准的增益项。体态微调的效果更直接：四足零样本 SR 4.73、体态数据微调后 17.00，跨体态共训后 23.83；人形共训后 26.87。控制器一致性是另一条独立账：采集与评测都用控制器时验证未见集 SR 18.78%，两者不一致时降到 13.51% 与 15.90%，瞬移设定 21.31% 但坠落与卡住都为零。物理设定的真实代价由「一致控制器 18.78%」与「瞬移 21.31%」的差给出：2.53 个百分点，同时失败方式从零失败变成有坠落与卡住；只看成功率会低估这一项。真机侧，Unitree Go2 加 RealSense D455 在 14 条室内 episode 上，未微调 7.14% SR / 14.29% OSR，按 VLN-PE 微调后 28.57% / 57.14%，两项均为 4.00 倍；论文同时指出停止动作仍是主要失误来源。样本量只有 14 条，这一数字用于说明方向，不能当作稳定估计。

动态与语义。DaViNCi 把动态元素设成三档：零动态、10 车 10 人、30 车 30 人。已见图 town10 的成功率为 23.1 / 21.7 / 18.1（动态对照表口径），从零到默认档降 5.0 个百分点、相对降 21.65%；APC 从 57.8% 降到 48.0%（相对降 16.96%），平均导航误差升 14.65%。论文的失败分析把机制落在动态物体造成的局部视野遮挡。可通行性一侧，TEA 在 A2A 的整体 SR 增益是 +7 个百分点，但分面差异极大：铺装 +13 点、草地 +7 点、泥地 +3 点、稀疏植被 0 点；场景上村庄 +33 点、温室 +14 点，山地 0 点且 NE 微升 0.01 米。语义质量与地面类型耦合，报警模块的收益上游受分割质量限制；「可通行」在这类场景里是体态与作物状态的函数，标注与评测都要带体态条件。

接口与成本。把三组系统放在同一账上：AirAnchor 每集 45.8 次调用、每次 1,418 输入加 68 输出 token，共 68,058.8 token，SR 9.6%，折合每次成功约 70.9 万 token；SPF 每集 21,725.1 token、SR 5.7%，折合约 38.1 万；FineCog-Nav 每集 390,697.4 token、SR 6.9%，折合约 566.2 万。按每次成功折算，FineCog-Nav 的成本是 AirAnchor 的 7.99 倍。系统级智能体的账更重：第 093 讲第二篇在 50 条 episode 上累计输入 1.1041 亿 token、生成延迟 22.55 小时，折合每集 2,208,200 token 与 1,623.6 秒（27.06 分钟），26 条成功折合每次成功 4,246,538 输入 token。两个量级并排说明接口设计的杠杆：技能级调用与动作级调用的每集 token 可以相差近两个数量级，部署预算必须落在「每次成功」口径上，不能停在「每集」口径，失败重试的消耗单列。

停止判定单列一账，因为它是跨越感知、决策与执行的复合问题。沿用各来源的 OSR 与 SR 计算缺口：NaVid 零样本 4.90 点，CMA-Full 3.78 点；平台内微调后缺口反而扩大，CMA+ 12.55 点、Seq2Seq+ 12.34 点、RDP 12.08 点；空中场景 AirAnchor 在验证未见集为 12.80 点。OS−SR 越大，说明「曾到达成功邻域但停在邻域外」的比例越高，停止行为是训练目标与评测口径共同塑造的独立风险项，不能并入常规导航误差。

5. 差距账 v2 模板

记录格式在 v1 六元组 (层, 来源, 协议, 指标变化, 分母, 备注) 基础上增加成本行与体态条件：

(账目: 性能或成本, 层或组, 来源, 协议四元组, 体态与环境条件, 指标变化, 分母, 备注) 性能示例：性能, 感知, VLN-PE 光照对照, R2R val-unseen 3 米, 人形 H1, NaVid SR −12.47 点, 分母 22.42；成本示例：成本, 接口, 第 098 讲, AerialVLN-S 20 米, 无人机, 每集 68,059 token, 分母 45.8 次调用

汇总时先算性能账的加性与乘法两种口径，再算成本账的每次成功值，最后填「两条件合取」的结论。性能账的四层相对损耗仍以 v1 的 3.9 / 5.2 / 18.64% / 30.64% 等为基准项，v2 新增体态、动态与可通行性条目时给出量级与出处，不把不同协议的数字直接连乘。

6. 边界与失效模式

  • 34% 不是通用常数：它来自 VLN-PE 的特定机器人、控制器与场景，换平台必须重新测；引用时写清协议，不能把它乘到任意系统的仿真分数上。
  • 真机样本量与统计功效有限：Go2 的 14 条 episode、3DGS 单场景都在小样本范围，方向性结论可靠，点估计不稳健。
  • 成本账随服务端变化：token 价格、缓存折扣与模型版本都会漂移；本讲数字冻结在检索日 2026-10-01 的论文口径，复现时需重录。
  • 动态与语义证据以仿真为主：DaViNCi 的动态体是程序化代理，TEA 的评测在 A2A 仿真基准；真实交通与农田的动态统计特性未被覆盖。
  • 检查表是工程约定：放行判据的阈值不是论文结论，需按失效代价重新标定；本课程写到方案与复现指南级，不承诺替读者完成真机实验。

接口成本同一任务记录调用数、token、延迟与成功集模型版本、提示、预算C成功 与延迟分位数；判据为不超预算

报告模板字段

  1. 系统档案：机器人型号与相机高度、控制器、观测接口、动作空间、记忆策略。
  2. 协议四元组：基准名、成功半径、动作空间、split 与版本；跨基准统计另附清理前后双报。
  3. 性能账：四层各至少两条量化项加新增三轴各一条；加性与乘法两种汇总；主导项按占比排序。
  4. 成本账：每集调用数、输入输出 token、每次成功 token、延迟分位数、缓存与重试口径。
  5. 结论行：两条件合取的判断，附未通过项的诊断实验编号。
设计决策：为什么把接口成本单列成账，而不放进执行层

执行层的代价是物理的：命令固定开销、碰撞、死锁，按时间或动量计量，对策落在控制器与运动规划。接口成本是非物理的：调用粒度、上下文长度、缓存命中，按 token 与延迟计量，对策落在系统架构。两者唯一的共同点是都表现为延迟。把成本放进执行层会导致两类误判：用运动模型的改进去解释 token 的下降，或用调用次数的削减去宣称执行效率提升。第 044 讲的 EET 与第 098 讲的每集 token 属于两个账本，报告时分行列出，延迟指标则在结论行合并呈现。

关键代码与解读

三段代码分别给出每次成功成本折算、协议可比性闸门与风险评分卡。数字取本讲算例，示意实现。

片段 1：每次成功成本折算

def cost_per_success(runs, retry_factor=1.0):
    """按成功集折算 token 与延迟；失败重试消耗单独放大。"""
    tok = sum(r["calls"] * (r["tok_in"] + r["tok_out"]) for r in runs)
    lat = sum(r["seconds"] for r in runs)
    ok = sum(1 for r in runs if r["sr"])           # 成功条数
    if ok == 0:
        return {"tokens_per_episode": tok / len(runs),
                "tokens_per_success": float("inf"),
                "seconds_per_success": float("inf")}
    return {"tokens_per_episode": tok / len(runs),
            "tokens_per_success": tok * retry_factor / ok,
            "seconds_per_success": lat * retry_factor / ok}

# AirAnchor 口径：45.8 次调用、(1418+68) token、每 1000 条成功 96 条
aa = [{"calls": 45.8, "tok_in": 1418, "tok_out": 68,
       "seconds": 0.0, "sr": i < 96} for i in range(1000)]
print(round(cost_per_success(aa)["tokens_per_success"]))   # 708946

解读：（1）分母取成功条数，不取总条数，得到的是每次成功摊到的全部消耗，包含失败 episode 的开销；这是 API 系统做预算时的正确口径。（2）retry_factor 预留给重试与超时重发，默认 1.0 表示只统计首次执行；真实评测中失败重试常显著放大成本，必须显式记录。（3）函数同时返回每集与每次成功两个口径：每集值用于横向比较方法开销，每次成功值用于预算闸门。两值在 SR 较低时差距可达数倍，例如 FineCog-Nav 每集 39.1 万、每次成功 566.2 万。

片段 2：协议可比性闸门

RADIUS = {"r2r": 3.0, "r2r_ce": 3.0, "aerialvln_s": 20.0,
          "davinci_ce": 10.0, "a2a": 2.0}       # 基准到成功半径（米）

def comparable(a, b):
    """可比四元组：基准、半径、动作空间、split 与版本全同才可排名。"""
    keys = ("benchmark", "radius_m", "action_space", "split", "version")
    diff = [k for k in keys if a.get(k) != b.get(k)]
    if not diff:
        return {"verdict": "同协议可比", "diff": []}
    if diff == ["version"]:
        return {"verdict": "近似可比", "diff": diff}      # 版本差需重放固定轨迹
    return {"verdict": "不可比", "diff": diff}

row_a = {"benchmark": "r2r_ce", "radius_m": RADIUS["r2r_ce"],
         "action_space": "low_level", "split": "val_unseen", "version": "2020"}
row_b = dict(row_a, benchmark="aerialvln_s", radius_m=RADIUS["aerialvln_s"])
print(comparable(row_a, row_b))    # 不可比：基准与半径不同，禁止排名

解读：（1）半径从基准表读取，防止手工填错；20 米与 2 米的比值是 10，量纲差异必须在闸门层拦截。（2）只差版本时给「近似可比」并强制重放固定轨迹集，与第 079 讲的报告规范一致。（3）返回值携带差异列表，可直接写入报告的可比性一栏；函数对键缺失同样返回差异，缺项运行不允许进入聚合。

片段 3：风险评分卡与放行判断

GATES = [   # (名称, 权重, 判据函数)
    ("perception_camera_gap", 1.0, lambda v: v <= 4.0),
    ("memory_shuffle_gap", 1.0, lambda v: v <= 2.0),
    ("stop_gap_os_minus_sr", 1.0, lambda v: v <= 9.8),   # 基线 4.90 的两倍
    ("exec_sdtw_loss", 1.0, lambda v: v <= 2.0),
    ("cost_per_success", 1.5, lambda v: v <= 1.0e6),
]

def gate_report(measured):
    """返回未通过项与加权风险分；成本项超限直接拦截。"""
    bad, score, hard_block = [], 0.0, False
    for name, weight, ok in GATES:
        v = measured.get(name)
        if v is None:
            bad.append((name, None, "missing"))    # 缺测按未通过处理
            score += weight
        elif not ok(v):
            bad.append((name, v, "over"))
            score += weight
            hard_block = hard_block or weight == 1.5
    if not bad:
        verdict = "放行"
    elif hard_block:
        verdict = "拦截"
    else:
        verdict = "整改"
    return {"bad": bad, "score": score, "verdict": verdict}

m = {"perception_camera_gap": 3.9, "memory_shuffle_gap": 0.2,
     "stop_gap_os_minus_sr": 8.8, "exec_sdtw_loss": 1.4,
     "cost_per_success": 7.09e5}
print(gate_report(m))   # 全部通过：放行

解读：（1）判据阈值来自本讲各证据的保守缩放，写入表中，不散落在代码里，便于按场景替换并保留版本。（2）成本项权重 1.5 并在结论中单独拦截：性能达标但成本超预算的系统不允许进入下一阶段，这一规则对应 v2 的两条件合取。（3）缺失项按未通过处理，避免「没测就等于通过」的静默放行；返回的风险分可用于多方案排序，但排序前先做片段 2 的可比性检查。

常见坑

  • 沿用 v1 清单部署 2026 系统：只查四层与协议账，漏掉体态、动态、成本三项。根因是 v1 的证据以室内静态为主。修复：改用 v2 六组检查表；对每个未覆盖项至少跑一次诊断矩阵中的最小实验。
  • 把 34% 当通用降幅：用它乘任意仿真成功率预测部署表现。根因是忽略该数字的机器人、控制器与场景条件。修复：只在 VLN-PE 协议内引用；跨平台时重新实测，或按四层差距账自建分解。
  • 跨半径比较成功率：把 2 米半径的 54% 与 20 米半径的 9.2 并列排名。根因是成功判定的量纲不同，最大差 10 倍。修复：用片段 2 的闸门拦截；跨半径比较只允许 NE、APC 等尺度无关量，或统一重算。
  • 性能与成本分头评审：算法团队报 SR，工程团队报费用，结论互不约束。根因是缺少每次成功口径。修复：把 C成功 写进同一次评测记录；预算超限时即使 SR 达标也拦截。
  • 记忆复用越界：部署时让智能体使用先前 episode 累积的场景记忆，却按单集协议报告成绩。根因是评测协议允许同场景在线记忆（AirAnchor 的做法），部署复用范围更宽。修复：在协议四元组里写明记忆复用规则；做顺序打乱实验给出波动区间；跨场景复用单独声明并评测。

  1. 成本折算：AirAnchor 每集 45.8 次调用、1,418 输入加 68 输出 token、SR 9.6%；系统级智能体每集 2,208,200 输入 token、26 / 50 成功率。分别计算两者的每集与每次成功 token，并说明为什么预算讨论必须用后者。 ★

    AirAnchor 每集 68,058.8，每次成功约 70.9 万；系统级每集 220.8 万，每次成功 424.7 万。每集口径在 SR 低时严重低估真实开销，失败 episode 的消耗同样要摊到成功上。
  2. 停止缺口：用 NaVid（OSR 27.32 / SR 22.42）、CMA+（31.33 / 18.78）、RDP（34.06 / 21.98）、AirAnchor 未见表（22.0 / 9.2）计算 OS−SR，并按缺口从大到小排序；解释为什么 OSR 高、SR 低这一组合指向停止行为，不能归因于路径选择。 ★
    提示
    缺口为 12.80（AirAnchor）、12.55（CMA+）、12.08（RDP）、4.90（NaVid）。OSR 统计轨迹上任意一点是否进入成功邻域，SR 只看终点；缺口大说明「到过附近却没停对」，路径与停止的贡献可以在日志里用最近点距离与停止步号分离。

    提示
