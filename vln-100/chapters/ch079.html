第四篇 · 规模、记忆与泛化方法论

第 079 讲｜评测公平性

本讲把前面各讲反复提到的协议问题收成一套方法：同一个基准上，解码方式、模型集成、预先探索、地图与路线先验任意一项变化，数字就会移动好几个甚至十几个点。以 Zhou、Liu、Mu 2021 的路线先验工作（arXiv:2110.05728v1）为镜像，先展示 62 到 73 的平台期与 73 / 78 的先验结果各自成立的条件，再给出协议元组、可比性三级判定与十二项公平报告清单。学完能独立审计一组论文数字是否可比。

  • 主题：评测公平性 / 协议匹配 / 推理预算 / 先验 / 报告规范
  • 关键数字：单跑平台 62%、beam 加集成 73%、探索 40 节点单模型 73%、加 Speaker 78%、已知地图 74 / 79
  • 预计学时：60 分钟
  • 前置讲：第 078 讲（少样本与 unseen 泛化）

学习目标

  • 会算：不同协议之差的绝对量与相对量（单跑对 beam 集成、探索预算、集成规模），以及先验改变候选空间时的规模对比。
  • 会解释：路线先验为什么把路径选择问题改写为终点分类问题，这一改写对候选数量、决策步数与评测口径各自意味着什么。
  • 会实现：协议元组提取与可比性判定、预算固定的评测运行器、带必填字段的公平报告生成器三段示意代码。
  • 会判断：两组数字属于同协议可比、近似可比还是不可比，并给出降级处理方式。
  • 会设计：一份十二项公平报告清单，覆盖 split、步数上限、探索预算、先验假设、模型选择与算力口径。

背景与动机

这门课在不同章节里反复埋下同一类伏笔。第 018 讲指出训练步数与步数上限是公平比较的前提；第 031 讲提醒编码器与跟随者输出的分数口径不同，跨 split 排名会失真；第 040 讲说明 beam search 与模型集成会系统性抬高 SR；第 048 讲列出连续环境的五个口径分歧；第 059 与 061 讲要求所有报告数字带 split 与协议。这些线索指向同一个问题：在 VLN 里，数字是协议的产物，脱离协议谈高低没有意义。

本讲用一个极端案例把问题推到台前。Zhou、Liu、Mu 2021（arXiv:2110.05728v1）指出，R2R 的路径全部是最短路，若再把地图视为已知，起点终点一旦确定，中间走法随即确定，路径选择问题退化为「在所有节点中选一个终点」的普通分类问题。论文摘要记录了两组参照：过去两年 VLN 单跑成功率停在约 62%、beam search 加模型集成停在约 73%；而在他们的设定下，探索约 40 个节点后单模型即达 73%，集成一个 Speaker 模型后到 78%，超过使用三个模型集成并借助大量预训练的 VLN-BERT。同一基准、同一指标，数字跳变的原因几乎全是协议。

本讲不评价该方法的优劣，任务是把这个案例翻译成可操作的审计流程：先提取协议元组，再判定可比级别，最后写进公平报告。第 078 讲的少样本协议与第 077 讲的迁移口径都依赖这套流程收尾。

核心原理

本节按「自由度、先验案例、证据、判据、清单、边界」六步展开。案例数字均来自 arXiv:2110.05728v1，协议为 R2R val-unseen 或 test-unseen 成功率。

1. 数字的六类自由度

把影响 VLN 报告数字的协议变量归成六类，每类给一个已在本课出现过的实例：

自由度实例对数字的影响
监督规模61 个房屋全量对 1 个房屋微调（第 078 讲）未见 SR 相差 15 个点以上
推理预算单跑对 beam search 加模型集成（第 040 讲）R2R val-unseen 约 62 到 73
环境访问无探索对预先探索、已知地图本讲案例中单模型 71 与 72、加 Speaker 集成到 74 与 76（test-unseen）
任务先验最短路先验、可通行图先验把路径搜索变成终点分类
评测口径split 版本、步数上限、停止判定、评测数据勘误天花板与可分性变化（第 048 讲）
模型选择用验证集选模型又报同一验证集（第 009、029 讲）系统性乐观偏差

六类自由度里，前三类影响最大也最常被省略；后三类影响隐蔽，只在复现时暴露。

2. 先验案例：从路径搜索到终点分类

设环境为边权图 G = {V, E}，V 为可观测位置，E 为相邻边。若承认最短路先验且地图已知，起点 ns 与终点 ni 之间的最短路 P(ns, ni) 唯一（多最短路的情形极少），路径打分问题即可写成对所有候选终点的分类：

argmaxni F(P(ns, ni), I)，∀ ni ∈ V I 为指令；F 为路径-指令兼容性打分；候选数从路径的指数增长变为节点数的线性增长

候选规模的实算：R2R 平均节点度 4.1，金路径 4 至 6 步，逐步扩展的候选数约为 4.14 = 282.6 到 4.16 = 4,750.1；分类式只需对平均 117 个节点打分，对应约 2.42 到 40.6 倍的压缩。第二个效应在决策步数：R4R 上逐步智能体的平均决策序列约 12 步，按局部最短路分解后只有约 3.3 段，压缩 3.64 倍。

先验成立与否可以量化。论文用贪心算法把训练路线分解为局部最短路，统计「分解段数 / 原步数」：R4R 为 0.21、RxR 为 0.25，随机路线为 0.79。R4R 与 RxR 的比值比随机路线低 3 到 4 倍，说明真实路线的确由少数局部最短路拼接而成，R2R 则整体就是一条最短路。第 012 讲给出同向证据：RxR 中 44.5% 的路径不沿最短路，平均比最短路长 27.4%。先验属于任务结构的一部分，不宜当作数据集缺陷；不同基准的先验强度不同，处理方法也应不同。

3. 证据与协议：同一方法的三组数字

把案例结果按协议切开看（val-unseen，单模型与集成，探索预算 40 节点）：

配置val-unseen SRtest-unseen SR协议要点
探索 40 节点，单模型0.730.71先探索子图，再在子图上分类
探索 40 节点，加 Speaker 集成0.780.74集成规模 2
已知地图，单模型0.740.72地图信息完整，仅作上界
已知地图，加 Speaker 集成0.790.76集成规模 2

判断这些数字是否可比，先看论文自己披露的口径。第一，主表（排除探索轨迹的路径查找能力比较）与榜单表（计入探索轨迹）给出的 SR 相同，但 TL 完全不同：test-unseen 上探索 40 节点的模型 TL 为 625.1 米，已知地图为 533.6 米，差 91.5 米（17.15%）；完整地图用深度优先遍历的 TL 甚至小于 40 节点子图，因为子图方案在已探索区域内有大量往返。第二，作者明确声明该方法带有额外探索阶段，无法与单跑模型直接比较，比较对象限定为 beam search 加重排家族。第三，与 SSM 的对照（单跑 SR 0.60、NE 4.58；叠加上本方法后 0.61、4.22）同样被标注本质不公平，因为引入了额外探索。这三点披露本身就是公平性的范例：先声明协议，再解释数字。

协议差还可以用同一模型家族内部的数据做一次粗分解。R2R val-unseen 上（Airbert，Guhur 等 2021，表 6）：VLN-BERT 单模型 59.26，加 Speaker 与 Follower 后集成到 73.61（+14.35）；Airbert 单模型 68.67，同样加 Speaker 与 Follower 后到 75.01（+6.34）；单独组合的 Speaker 加 Follower 为 67.90。同一组推理组件在不同底模上的增益从 6.34 到 14.35 个百分点不等，孤立报告集成数字无法归因；62 到 73 的平台差里含有相当比例的集成与解码贡献，引用时必须把单模型、单跑与集成值成组给出。分解只能在同家族对照内估计，跨家族照搬顺序不可靠。

4. 可比性判据：三级分类

给出一个可执行判定流程。把一次评测的协议写成元组 π =（split 与数据版本，步数上限与截断规则，停止判定，解码方式，运行次数，集成构成，探索或预先访问预算，地图与先验假设，训练与预训练语料，模型选择依据，指标定义与主次，算力预算）。对两组数字的元组逐项比较，得到三级结论：

级别条件处理方式
同协议可比十二项全同或差异与结论无关允许排名与差值陈述，给显著性
近似可比仅探索预算或集成规模等可量化项不同并排报告并标注差异项与差值分解，不做排名
不可比训练规模、先验假设或评测口径不同分表陈述，只做定性讨论，禁止「超过」「落后」字样

用本讲案例做三个判定练习。其一，62% 单跑与 73% beam 集成，属于近似可比，差值 11 个点（相对 17.74%）主要来自推理预算，只能记为「协议差」；其二，73% 单模型与 78% 加 Speaker，属于同协议下的集成差，+5 个点可记为集成贡献；其三，73% 的探索式结果与 59.26% 的单跑 VLN-BERT，属于不可比，前者花了几十个节点的探索预算，把它写作「超过」需要同时给出预算对照。

6. 边界与失效模式

  • 不公平不等于没有价值：探索式方法、带先验的方法本身就是方法贡献，问题只在把不同预算的数字放进同一排名。分表后它们仍有信息量。
  • 先验的粒度要分级：已知完整地图与仅探索子图是两档预算；子图规模 10 节点时邻域分数聚合会伤害性能，20 节点以上才转为增益，默认 40 节点是精度与代价的折中。把「用了先验」当作单一变量会掩盖这些分层。
  • SR 高不代表各项都好：案例方法在部分对照组上 SR 更高但 NE 更差（分类错误会带来大偏差），说明指标间可能背离，报告时应给出主指标之外的次级指标。
  • 集成与 SPL 存在语义陷阱：多候选重排协议下，若 SPL 按全部候选轨迹长度计算，数值会异常低且在各方法间趋同（第 078 讲的 Airbert 榜单脚注是同款现象），引用时必须写明 SPL 的分子分母。
  • 连续环境另有数据勘误：R2R-CE val-unseen 确认 8 条错误 episode、RxR-CE 10 条，天花板分别被压低约 0.44 与 0.27 个百分点；比较前未注明清理规则的结果不可直接对齐。

实现思路与设计

把方法落成流程需要三样东西：协议登记表、匹配运行器、报告生成器。目标是把「讨论数字」前置为「核对协议」，让不公平的比较在流程里直接暴露。

审计流程

  1. 提取：对每组数字抽取十二项协议字段，缺项标注「未声明」。
  2. 比较：逐项判定，得到同协议 / 近似 / 不可比三级结论。
  3. 分解：对近似可比的差异，估算各差异项的贡献（如集成贡献 +5 点、探索预算贡献另计）。
  4. 落表：可比数字入主表并给显著性；近似数字入附表并标注差异；不可比数字只做定性描述。
  5. 复核：由第二人按清单重抽一次协议字段，核对结论一致性。
设计决策：协议先于数字，预算先于排名

任何汇总表的行都必须携带协议元组；任何「更高 / 超过」的结论都必须通过可比性判定且有预算对照。近似可比时先并排展示再分解差值，不可比时直接分表。把公平性做成流程约束，避免依赖写作自觉，是这套方法唯一能被团队规模复制的部分。

匹配运行器与报告模板

组件职责要点
预算封装器固定探索节点数与候选数把探索与决策拆成两个计时、两个 TL 口径
协议断言运行前校验必填字段缺字段直接拒绝出数
报告生成器按级别渲染表格不可比行不出现在排名列

与相邻讲的分工：第 048 讲处理连续环境内部的口径分歧，第 078 讲处理少样本统计，本讲给出跨论文、跨协议的统一判定与清单；第 080 讲复盘第四篇时，全篇数字都会按本讲的三级判定复核。

关键代码与解读

三段代码分别给出协议元组与可比性判定、预算固定的评测运行器、公平报告生成器。示意实现，可直接接入既有评测脚本。

片段 1：协议元组与三级可比性判定

from dataclasses import dataclass, field

@dataclass
class Protocol:
    split: str                      # "r2r/val_unseen"
    data_version: str               # 数据集版本或勘误规则
    max_steps: int
    stop_rule: str                  # "call_stop_and_dist3m"
    decode: str                     # "greedy" / "beam8"
    num_runs: int
    ensemble: tuple = ()            # 例：("speaker", "follower")
    explore_nodes: int = 0          # 预先探索节点数，0 表示不探索
    known_map: bool = False
    train_corpus: str = ""
    model_selection_split: str = ""
    compute: str = ""

TIGHT = ("split", "data_version", "max_steps", "stop_rule")
BUDGET = ("decode", "num_runs", "ensemble", "explore_nodes", "known_map")

def comparability(a, b):
    """返回 same / approx / diff；硬字段与语料相同才允许推理预算差异。"""
    hard_diff = [f for f in TIGHT if getattr(a, f) != getattr(b, f)]
    if hard_diff or a.train_corpus != b.train_corpus:
        return ("diff", hard_diff or ["train_corpus"])
    budget_diff = [f for f in BUDGET if getattr(a, f) != getattr(b, f)]
    return ("same", []) if not budget_diff else ("approx", budget_diff)
# 例：单跑贪心与 beam8 加集成 → approx（同为推理预算类差异）

解读：（1）把十二项字段固化成数据类，未声明的字段无法进入记录；split、数据版本、步数上限与停止判定属于「硬」字段，一旦不同直接判不可比。（2）推理预算类差异（解码、运行次数、集成、探索预算、地图假设）允许作为近似差异，但仅当硬字段与训练语料相同；训练语料或监督规模不同直接降级为不可比。（3）判定结果携带差异字段列表，供报告附注直接引用，减少人工转述误差。

片段 2：预算固定的评测运行器

def evaluate_matched(agent, envs, protocol):
    """固定探索节点数与候选数；分别记录含与不含探索的 TL。"""
    assert protocol.explore_nodes >= 0
    results = {"sr": [], "ne": [], "tl_nav_only": [], "tl_with_explore": []}
    for env in envs:
        explored = set()
        if protocol.explore_nodes:                 # 预先探索阶段
            explored = explore_subgraph(env, agent,
                                        budget=protocol.explore_nodes)
        traj = run_navigation(env, agent,
                              candidates_from=explored or None)
        results["sr"].append(success(traj, env, protocol.stop_rule))
        results["ne"].append(final_distance(traj, env))
        results["tl_nav_only"].append(path_len(traj))
        results["tl_with_explore"].append(
            path_len(traj) + path_len(exploration_trace(env)))
    return summarize(results)

解读：（1）探索与导航分离执行，探索预算显式入参，杜绝「顺手探索」这类不可审计的预算。（2）TL 记两版：只算导航段的与含探索轨迹的；案例中两者相差 91.5 米（17.15%），混用会让路径效率类指标失真。（3）停止规则与成功判定来自协议对象，评测器不做隐式默认值。

片段 3：公平报告生成器

LEVEL_ORDER = {"same": 0, "approx": 1, "diff": 2}

def fair_report(entries, baseline):
    """entries 为 (name, protocol, metrics)；按可比级别分组渲染。"""
    groups = {"same": [], "approx": [], "diff": []}
    for name, proto, metrics in entries:
        level, diff_fields = comparability(baseline[1], proto)
        groups[level].append({"name": name, "metrics": metrics,
                              "diff_fields": diff_fields,
                              "protocol": proto})
    for level, rows in groups.items():
        for row in rows:
            if level == "same":
                row["note"] = "可排名"
            elif level == "approx":
                row["note"] = "并排展示，标注差异：" + ",".join(row["diff_fields"])
            else:
                row["note"] = "分表，禁止排名用语"
    return groups
# 输出时 same 组给显著性；approx 组差值分解；diff 组只列数字与协议

解读：（1）报告结构由可比性判定直接决定，级别决定呈现方式，写作阶段没有「凭感觉比较」的空间。（2）近似组自动携带差异字段，读者能看到差值来自哪里（如集成规模或探索预算）。（3）不可比组保留原始数字与协议，把「不可比」变成待办的实验任务。

常见坑

  • 预算与先验未进协议就直接排名：把 62% 单跑与 73% beam 集成写成方法差距，或把「知道最短路」与「逐边决策」写成同一任务。根因是推理预算与地图假设未进入协议元组。修复：前者判定为近似可比，差值 11 个点（相对 17.74%）标注为推理预算贡献；后者在协议第 8 项单独登记，先验把候选空间从 282.6 至 4,750.1 压缩到约 117，差值需先扣除先验贡献。
  • TL 口径混用：与探索式方法比较时只用导航段 TL，或把探索轨迹算进别人的数字。根因是 TL 未区分两段。修复：TL 记两版并写明；案例中两版相差 91.5 米（17.15%），完整地图的遍历 TL 甚至小于 40 节点子图方案。
  • SPL 在多候选重排下被误读：榜单把全部候选轨迹长度计入分母，SPL 数值异常低且各方法趋同。根因是 SPL 定义未随协议更新。修复：写明分子分母口径；需要路径效率时改用单跑轨迹或另立指标。
  • 验证集选择偏差：用 val-unseen 早停与选模型，又在同一 split 上报告并宣称泛化。根因是选择与报告共用数据。修复：协议第 10 项记录选择 split；无法隔离时降级结论强度并报告选择敏感性（第 009、029 讲的口径）。
  • 连续环境忽略勘误：R2R-CE 与 RxR-CE 的 val 集含确认错误 episode（8 条与 10 条），未清理时天花板被压低约 0.44 与 0.27 个百分点。根因是沿用旧版本数据。修复：按统一规则剔除并同报清理前后结果（第 048 讲，arXiv:2403.10700）。

练习与思考

  1. 协议差核算：(a) 单跑平台 62% 与 beam 加集成 73% 的绝对差与相对差；(b) 探索 40 节点单模型 73% 加 Speaker 后 78%，集成的贡献是多少；(c) 探索式 73% 与单跑 59.26% 为什么不可比，写出两条理由。 ★
    提示
    (a) +11 个百分点，相对 11/62 = 17.74%。(b) +5 个百分点，属同协议下的集成贡献。(c) 探索预算不同（几十个节点对零）且方法族不同（beam 重排对单跑）；按三级判定为不可比，只能分表。
  2. 候选空间与决策步数核算：平均节点度 4.1、金路径 4 至 6 步、全图平均 117 个节点、R4R 逐步决策约 12 步。计算 (a) 两种步数下的逐步候选数；(b) 对 117 的压缩倍数；(c) 子路径分解后决策步数 3.3 的压缩倍数，并说明这两个压缩是否属于同一种收益。 ★
    提示
    (a) 4.14 = 282.6，4.16 = 4,750.1。(b) 约 2.42 与 40.6 倍。(c) 12/3.3 = 3.64 倍。两类收益不同：前者来自先验把搜索变分类，后者来自决策粒度从单边变为多步子路径，评估时要分开计入。
  3. 三级判定练习：给定四组数字（同一方法家族）。(A) 单跑贪心 58.0；(B) 单跑贪心 59.5，训练语料更大；(C) beam8 集成 72.0；(D) 探索 40 节点 73.0。为每对组合给出可比级别与处理方式，并说明哪一对的差值可以写「方法更好」。 ★★
    提示
    A 与 B 训练规模不同，判不可比，分表；A / B 与 C 属近似可比（解码与集成不同），并排并标注；与 D 属近似可比或不可比取决于训练语料与地图假设，需要补齐协议字段；只有 A 与同协议重复实验之间的差、或同预算下的对照才允许写「更好」。
  4. 复核一条真实主张：某文声称「在 R2R val-unseen 上以 78% 超过此前 73% 的最佳」。要求 (a) 列出核对这条主张所需的十二项协议字段；(b) 指出最可能的三项差异；(c) 给出一个预算匹配的重跑方案。 ★★
    提示
    (a) 按清单逐项提取，缺项标注未声明。(b) 最可能是集成构成（是否含 Speaker）、探索预算（节点数与 TL 口径）、预训练语料规模。(c) 固定 split 与停止判定，用同一候选数与探索预算跑两套方法各 3 个种子，报均值与标准差。
  5. 公平报告设计：为一个新提交（探索 20 节点、beam 宽度 8、集成 3 模型、使用全量预训练）写完整报告方案。要求 (a) 十二项字段取值；(b) 与单跑基线和 40 节点方案各自的判定级别；(c) 若被要求给出「单跑可比」数字，设计一套消融把探索、beam、集成、预训练四项贡献拆开；(d) 说明哪些贡献可以合并陈述。 ★★★
    提示
    (a) 按清单逐项填，勘误规则写进第 1 项。(b) 对单跑基线判不可比（预算与解码都不同）；对 40 节点方案近似可比（探索节点数与集成规模不同）。(c) 消融阶梯：单跑无探索无预训练 → 加预训练 → 加 beam → 加集成 → 加探索；每级只动一项，固定其余。(d) 同协议内的 beam 与集成贡献可合并为「推理预算」陈述，但不能与探索或预训练贡献混为一项。

小结

  • VLN 数字受六类自由度支配：监督规模、推理预算、环境访问、任务先验、评测口径、模型选择；前三类影响最大，后三类最隐蔽。
  • 先验案例把路径搜索改写为终点分类：候选数从 282.6 至 4,750.1 压缩到约 117（2.42 到 40.6 倍），R4R 决策步数从 12 降到 3.3（3.64 倍）；R4R 与 RxR 的局部最短路分解比为 0.21 与 0.25，随机路线 0.79。
  • 同一方法的数字随协议三层跳变：单跑平台 62%、beam 加集成 73%、探索 40 节点单模型 73%、加 Speaker 78%、已知地图 74 / 79；舍弃探索轨迹口径后 SR 不变而 TL 相差 91.5 米（17.15%）。
  • 可比性三级判定：同协议可比允许排名；近似可比并排并分解差值（解码、集成、探索预算类差异）；不可比只做定性陈述。
  • 十二项公平报告清单覆盖 split 与勘误、步数上限、停止判定、解码、运行次数、集成、探索预算与 TL 口径、地图与先验、语料、模型选择、指标定义与算力，缺项即降级结论。
  • 下一讲是第四篇复盘：把数据规模、记忆载体、偏差诊断、表征迁移、少样本与评测公平性串成「数据-表征-泛化」闭环，并给出通往基础模型时代的接口（第 080 讲）。
