第四篇 · 规模、记忆与泛化方法论

第 061 讲｜ScaleVLN I：1200+ 场景与 4.9M 轨迹

本讲拆解 ScaleVLN（Wang 等 2023，ICCV 2023，arXiv:2307.15644v2）的规模账：800 个 HM3D 场景加 491 个 Gibson 场景，合计 1,291 个（论文称 1200+），可导航面积 15 万平方米以上，约为此前训练场景的 7.5 倍；生成 2,890,267 加 2,051,443 共 4,941,710 条指令轨迹对；单次运行在 R2R test-unseen 上把成功率推到 80%（前最佳 73%，本文基线 69%），seen-unseen 缺口压到 0.92 个百分点，并在 R2R-CE 上报告 +5 个百分点 SR。本讲核对每一个倍数、指出来源内部的口径冲突，并给出规模化的算力档位与决策表。

  • 主题：数据规模化 / 环境多样性 / 指令生成 / 规模-收益分析
  • 关键公式：N总 = NHM + NGib = 2,890,267 + 2,051,443 = 4,941,710；倍数 = N总 / N基准
  • 预计学时：60 分钟
  • 前置讲：第 060 讲（第三篇回顾：仿真到现场的差距地图）

学习目标

  • 会写：复述 ScaleVLN 的三张规模量（场景数、可导航面积、指令轨迹对数）、采样规则与头部结果，并标注来源与协议。
  • 会算：核对 4,941,710 的组成与相对基准的倍数；把「相对前最佳」与「相对本文基线」两类增益分开计算。
  • 会实现：写出规模-收益表的汇总脚本与两阶段数据配比采样器，输出训练集的信息量与采样权重。
  • 会判断：在「扩场景、扩样本、提图像质量、提指令质量」四条路线之间按预算排序。
  • 会诊断：识别倍数口径冲突、指令低质量、域漂移三类问题，并给出复现检查步骤。

背景与动机

第三篇的回顾把决策层最强的杠杆指向数据：seen 与 unseen 的成功率缺口长期在 8 个百分点左右，而环境增广的尝试（环境丢弃、回译、图像编辑）大多在 61 个 Matterport3D 训练场景内做文章，视觉多样性有上限。ScaleVLN 换了一条路线：不动模型结构，先用仿真器在额外环境里批量生成「轨迹加指令」，再把生成数据按两阶段（预训练、微调）组织进现有智能体。论文的自我定位是「简单、全自动、可复现」，与依赖非公开模型的前作（如使用非公开语言模型 Marky 与视觉编码器 MURAL 的 MARVAL）形成对照。

账面数字先摆出来（Wang 等 2023 摘要与第 3 节）：环境来自 HM3D 的 800 个训练场景与 Gibson 的 491 个训练及验证场景，合计 1,291 个，可导航面积超过 15 万平方米，约为此前训练场景（Matterport3D，2 万平方米、61 个扫描）的 7.5 倍；轨迹按 PREVALENT 的规则采样，再配 EnvDrop 说话者生成指令，最终得到 4,941,710 条指令轨迹对。头部结果：R2R test-unseen 单次运行成功率 80%（人类 86%，前最佳方法 73%），seen-unseen 缺口压到不足 1 个百分点（表 6 的 80.02 对 79.10）。这组数字把「数据规模」从背景变量变成了主要变量，第 061 与 062 讲分别处理它的总账与管线细节。

本讲的产出是一张数据集卡片、一张规模-收益证据表与一张扩展决策表。它服务三个下游：第 062 讲拆解生成管线，第 064 讲讨论数据工程与许可，第 065 讲讨论增广的边界与风险。

核心原理

本讲按「三张规模量、环境与图、轨迹与指令、头部结果、规模-收益证据、训练配方、边界」展开；倍数与增益由 Python 实算，来源内部不一致处逐条标注。

1. 三张规模量：场景、面积与指令轨迹对

ScaleVLN 的规模由三层组成，每层都有明确的来源。第一层是环境：HM3D 训练场景 800 个，Gibson 训练与验证场景 491 个，合计 1,291 个。第二层是可导航面积：超过 15 万平方米，Matterport3D 训练场景为约 2 万平方米与 61 个扫描，比值 7.5。第三层是监督量：HM3D 生成 2,890,267 条路径，Gibson 生成 2,051,443 条，合计 4,941,710 条指令轨迹对。

2. 环境与导航图：密度、连通与图像质量

额外场景能否转成有效监督，取决于导航图与图像质量两件事。图的构建分四步（论文第 3.2 节）：用 Habitat 的可导航位置采样函数密集采样视点，限制任意两视点测地距离大于 0.4 米；用层次聚类把相邻视点合并，阈值 1.0 米，使节点靠近开放空间中心；在 5.0 米以内随机连接视点，每个视点的边数上限为 5；最后用已有的图精修方法得到完全连通、完全可通行的图。得到的图平均边长 1.41 米，平均节点度 4.55。

论文用一组对照证明「图质量本身就是变量」：同样是 800 个 HM3D 场景、不做图像修复，使用 AutoVLN 的稀疏图（节点密度 0.36 个每平方米，29.35% 的边穿过障碍物）生成数据后，val-unseen 为 72.75 SR / 62.56 SPL，低于完全不使用增广数据的 72.92 / 62.82；使用本文的密集可通行图（密度 1.16，穿障边比例 0.00%）后升到 76.01 / 66.94，相对无增广提升 3.09 SR 与 4.12 SPL。结论二：增广数据并不天然有效；图的可通行性与覆盖度决定了采样数据是否落在下游导航流形上。

图像质量方面，HM3D 与 Gibson 的网格渲染图常有破损、扭曲或缺失区域。论文用 Co-Mod GAN 做图到图修复，训练对来自 Matterport3D 的渲染图与相机图。修复前后的对照（val-unseen）：HM3D 从 76.01 / 66.94 升到 76.59 / 67.74；在 HM3D 修复图基础上加入 Gibson 修复图后升到 78.08 / 68.31，而加入 Gibson 未修复图只有 76.33 / 66.97。结论三：Gibson 的额外场景只有在图像修复之后才贡献收益，加 1.75 SR；未修复时相对不含 Gibson 的配置几乎无增益（+0.32）。

3. 轨迹与指令：4.94M 条是怎么来的

轨迹采样沿用 PREVALENT 的规则：在任意两个视点之间取全部最短路径，且两点间恰有 3 至 5 个中间节点。该规则生成 HM3D 2,890,267 条与 Gibson 2,051,443 条路径。每条路径配一条由 EnvDrop 说话者生成的英语指令；说话者只使用 R2R 的人工指令路径对训练，属轻量 LSTM 模型。论文对照了更强的 GPT-2：EnvDrop 生成指令的 BLEU-4 为 27.66，高于 GPT-2 的 24.36；用两者数据训练同一个智能体，val-unseen 分别为 76.59 SR / 67.74 SPL 与 75.82 / 66.08，EnvDrop 数据高 0.77 SR 与 1.66 SPL。结论四：指令质量的关键指标是结构与路径的对应关系，模型规模不是决定因素；低 BLEU 的合成指令仍能带来收益，但与人类指令的差距会在错误注入与歧义评测中暴露（第 056 讲）。两步生成（采样、生成）的完整质检与过滤规则留给第 062 讲。

6. 训练配方与算力档位

论文的训练配方分两阶段，模型按任务选择：R2R、CVDN、REVERIE 用 DUET，R2R-CE 用 HAMT（配合候选路点预测器）。预训练 20,000 次迭代、批 256、学习率 5×10−5，在两张 A100 上约 72 GPU 小时；微调 200,000 次迭代、批 16，单卡约 48 GPU 小时。折算监督量：预训练约 5,120,000 个样本，相当于 4.94M 条数据约 1.04 轮（实算 1.036）；微调约 3,200,000 次环境交互。视觉主干为 CLIP ViT-B/16，最佳配置额外使用 ViT-H/14 与图像增广。

7. 边界与失效模式

  • 倍数口径冲突：352 倍按 R2R 训练集 14,025 条成立；4.62 倍按论文自述的 PREVALENT 178,270 条不成立（实算 27.72）。引用时给出分母或改用绝对条数。
  • 指令质量上限：EnvDrop 说话者 BLEU-4 为 27.66，论文自述生成指令「质量较低」；数据装配了大量低质量监督仍有效，但不能保证细粒度接地能力，方向错误与歧义场景需要单独评测。
  • 域漂移：Gibson 生成数据适合预训练，不适合微调；论文推测其与 Matterport 场景的差距过大，在微调阶段引入噪声。跨数据集使用增广数据前先做小规模微调对照。
  • 离散监督的错配：ScaleVLN 生成的是离散指令轨迹对，迁移到连续环境需要外接候选路点预测器，增益从离散的 +11 SR 缩到连续的 +2 至 +5 SR。
  • 评测协议敏感：R2R 的 80% 为单次运行口径（无集束搜索、无集成、无预探索）；与其他榜单数字比较时须核对解码与集成配置（第 079 讲展开）。
  • 静态与室内限定：全部环境为室内静态扫描，动态物体、光照变化与室外场景不在覆盖范围；城市与空中数据的规模化需要另一套管线（第 053 讲与第 098 讲）。

理由有三条：同样本量下场景多样性的边际收益大于样本量的边际收益（表 2）；微调配比是零成本改动，收益（+2.51 SR）接近图像修复的成本收益；指令质量的两个候选之间只差 0.77 SR，优先级最低。判据是「每单位预算的 SR 增量」，且每次只变一个因素，保留对照。

与相邻讲的分工：第 062 讲拆生成管线（采样、模板、过滤、训练配方细节），第 063 讲处理 HM3D 与 HM3DSEM 的环境卡片，第 064 讲补充数据获取与许可，第 065 讲讨论增广边界。本讲只对规模与收益的关系负责。

入库前的四项监控指标

每批生成数据入库前做一次健康检查，四项指标均为一次扫描可得：唯一场景覆盖率（本批出现过的场景数除以目标场景数）；指令重复率（去重后指令数除以生成总数，用于发现说话者退化为模板）；修复图占比（经 Co-Mod GAN 处理的图像比例，按场景统计，用于核对图像质量假设）；训练与评测的场景交集（应为空，防止泄漏）。阈值由本地数据分布标定并记录版本；任何一项越界时暂停扩容，先修管线（第 062 讲的质检清单会给出更细的过滤规则）。

片段 2：规模-收益汇总与边际分析

ROWS = [   # (场景数, 样本量标签, val-unseen SR, SPL)
    (800, "2.89M", 76.59, 67.74), (800, "1.4M", 76.01, 66.56),
    (800, "700k", 76.25, 66.00), (400, "700k", 75.22, 65.32),
    (200, "700k", 74.84, 64.59), (0, "0", 72.92, 62.82),
]
BASE_SR, BASE_SPL = 72.92, 62.82

def gain(sr, spl):
    """相对无增广基准的绝对增益，单位百分点。"""
    return round(sr - BASE_SR, 2), round(spl - BASE_SPL, 2)

for scenes, samples, sr, spl in ROWS:
    print(scenes, samples, "SR gain", gain(sr, spl)[0], "SPL gain", gain(sr, spl)[1])
# 同场景（800）内样本 700k 到 2.89M：76.59 - 76.25 = 0.34，样本边际递减
# 同样本（700k）内场景 200 到 800：76.25 - 74.84 = 1.41，场景边际更强

解读：（1）边际比较必须在另一维固定时进行：同场景比样本、同样本比场景。（2）样本维从 700k 到 2.89M 的总增益 0.34 SR 小于场景维 200 到 800 的 1.41 SR，与结论六一致。（3）表里 800/1.4M 行（76.01）低于 800/700k 行（76.25），属于训练波动的量级，报告时不宜把 0.24 的差解读为负缩放。

片段 3：两阶段配比采样器

import random

def sample_source(stage, rng):
    """按论文结论设置权重：预训练三源均衡，微调只用 R2R 与 HM-E。"""
    if stage == "pretrain":
        sources = [("r2r", 0.4), ("prevalent", 0.3), ("hm_e", 0.3)]
    elif stage == "finetune":
        sources = [("r2r", 0.6), ("hm_e", 0.4)]   # 不放 PREV 与 Gib-E
    else:
        raise ValueError(stage)
    names = [s[0] for s in sources]
    weights = [s[1] for s in sources]
    return rng.choices(names, weights=weights, k=1)[0]

rng = random.Random(2023)
counts = {"r2r": 0, "prevalent": 0, "hm_e": 0}
for _ in range(10000):
    counts[sample_source("pretrain", rng)] += 1
print(counts)   # 约 4000 / 3000 / 3000，比例由权重控制

解读：（1）权重实现论文表 6 的两条结论：微调保留 HM-E、不加入 PREVALENT 与 Gibson。（2）采样器只决定抽到哪个来源，样本过滤与质检规则由第 062 讲补充；两处必须共用同一数据卡片版本。（3）固定随机种子便于对照实验；报告中记录权重、来源版本与每轮实际样本数。

常见误区

  • 倍数不写分母：引用「352 倍」或「4.62 倍」而不写基数是 R2R 训练集还是 PREVALENT。根因是倍数看起来比绝对条数直观。修复：报告格式固定为「4,941,710 条，为 R2R 训练集 14,025 条的 352 倍」；发现 4.62 与基数冲突时以绝对值为准。
  • 把生成成本当零：只核算 72 与 48 GPU 小时，忽略 1,291 个场景的建图、渲染、修复与 4.94M 条指令生成。根因是训练与生成在时间上分离。修复：预算表分「生成」与「训练」两栏，生成按场景数与每条指令的推理成本估算。
  • 在微调阶段加入全部来源：把 Gibson 数据与 PREVALENT 一并放进微调，结果下降。根因是照搬预训练配比。修复：微调只用与下游分布近的来源；表 6 的对照显示加入 PREV 会损失 2.00 SR。
  • 只看均量不看多样性：把预算全部投到单场景样本数，忽略场景扩展。根因是样本数更容易统计。修复：同时报告场景数与样本数两个维度的边际增益；同预算下优先场景。
  • 跳过图像修复：直接使用 Gibson 的原始渲染图并期待线性增益。根因是只检查数量不检查质量。修复：先用小规模对照测修复前后差（论文为 +1.75 SR），低质量来源占比高时先修图。
  • 拿离散增益外推连续环境：把 R2R 的 +11 SR 直接写成 R2R-CE 的预期。根因是忽略监督与动作空间的错配。修复：连续环境单独报告，并以同表对照（HAMT+InternVideo 53 / 48 对 HAMT+ScaleVLN 55 / 51）为参照。

小结

  • 三张规模量：1,291 个场景（800 HM3D 加 491 Gibson，论文称 1200+）、15 万平方米以上可导航面积（MP3D 训练场景的 7.5 倍）、4,941,710 条指令轨迹对（2,890,267 加 2,051,443）。
  • 倍数账：相对 R2R 训练集 14,025 条为 352.35 倍，相对 R2R 全量 21,567 条为 229.13 倍，相对论文自述的 PREVALENT 178,270 条为 27.72 倍；论文写的 4.62 倍与自述基数冲突，引用时以绝对条数与分母为准。
  • 头部结果：R2R test-unseen 80 SR（人类 86，前最佳 BEVBert 73，基线 DUET 69），相对两个参照系的增益分别为 7 与 11 个百分点；seen-unseen 缺口 0.92；R2R-CE 为 55 SR / 51 SPL（val-unseen）与 55 / 50（test-unseen），相对同表视频预训练基线 +2 SR 与 +3 SPL。
  • 规模-收益五组证据：场景多样性优于样本数量（700k 同量下 200 到 800 场景 +1.41 SR）；Gibson 图像修复 +1.75 SR；EnvDrop 指令对 GPT-2 +0.77 SR；微调保留 HM-E +2.51 SR，加入 PREVALENT −2.00；MLM+SAP 相对无预训练 +13.97 SR，加 MRM 为 −0.77。
  • 算力档位：预训练 256 × 20,000、双 A100、约 72 GPU 小时；微调 16 × 200,000、单卡、约 48 GPU 小时；生成成本未报告，需在预算中单列。
