第一篇 · 任务、数据、仿真与评测地基

第 005 讲｜离散导航图上的动作空间

本讲把第 003 讲的状态相关候选接口与第 004 讲的路径数据接成可训练的动作空间：先分清仿真器接口、6 动作基线与 36 视角全景三层口径，给出候选视角的分解与 picking 规则、行为克隆目标的构造方法，最后用小型概率表演示贪婪解码与束搜索解码的差别。

  • 主题：离散动作空间 / 候选视角分解 / picking / 束搜索
  • 关键公式：Wt+1；viewIndex = 12·(b+1) + (round(ψ/30°) mod 12)；maxa Σt log π(at)
  • 预计学时：60 分钟
  • 前置讲：第 003 讲、第 004 讲

学习目标

  • 会算：36 = 12 × 3 的视角分解、30° = π/6 ≈ 0.523599 rad、候选方向到最近标准视角的量化误差上界（单轴 15°、合成 21.21°）。
  • 会实现：把候选列表中的 rel_heading 与 rel_elevation 映射为 viewIndex，并按视场生成 picking 结果。
  • 会构造：行为克隆（behavior cloning）的逐步监督标签，覆盖转向、仰俯中和、移动与停止四类分支。
  • 会判断：在仿真器接口、6 动作基线、36 视角全景动作三种口径之间做出选择，说明各自的观测代价与解码方式。
  • 会复现：在小型动作概率表上完成贪婪与束搜索解码，说明束宽度对联合概率与计算量的影响。

背景与动机

第 003 讲给出了仿真器的交互接口：动作写成 makeAction(index, Δψ, Δθ)，候选集合 Wt+1 随位姿与视场变化，index 只在本步观察内有效。第 004 讲给出了数据：R2R 的 episode 是视点序列，每条路径配 3 条指令，评测按最终位置判成功。两讲之间还缺一环：路径序列如何变成模型可学习的动作序列，模型输出又如何变回仿真器动作。这一环就是动作空间的口径，本讲把它讲透。

原文给出了两种口径。R2R 基线模型把仿真器的状态相关动作空间简化成 6 个动作：左转、右转、上看、下看、前进、停止（Anderson 等，2018，5.1 节）；前进定义为移动到视场中心最近的可达视点，四个转向动作固定为 30°。随后，Speaker-Follower（Fried 等，2018，NeurIPS）改用全景动作空间：先环视 36 个视角获得完整感知，再在少量可通行方向中做选择，停止动作编码为零向量。两种口径的观测、动作语义与训练标签都不同，混用会直接污染监督信号。

工程层面的问题同样具体。官方仓库的简单动作接口（makeSimpleActions）只有 5 个动作：前进加四个 30° 转向；代码注释明确警告，该接口很可能裁掉图中一部分可通行边。也就是说，用简单接口跑通的环境与用完整接口跑通的环境，可达性不同。再如，把候选方向落到 36 个预缓存视角时，方向与最近视角之间存在量化误差，单轴最大 15°，两轴合成最大 21.21°，picking 规则写错会系统性损失空间精度。

本讲解决四个问题：第一，给出三层动作空间的对照与选择判据；第二，讲清候选视角分解、viewIndex 约定与 picking；第三，给出行为克隆目标的构造方法；第四，讲清贪婪解码与束搜索解码在导航任务中的写法。下一讲起进入评测指标，动作空间的一切实现在那里接受数字检验。

核心原理

1. 三层动作空间：仿真器、6 动作基线、36 视角全景

三层从下到上依次抽象：仿真器只管位姿演化，基线模型把动作压缩成离散词表，全景动作空间把感知与动作都换成高层表示。

仿真器层。动作是三元组 at = (k, Δψ, Δθ)：k 选择 Wt+1[k]（下标 0 为原地停留），Δψ 与 Δθ 是相机朝向与仰俯的相对增量，单位弧度。动作确定性，且受限于视场：受限导航开启时，只有当前视场内（允许上下瞥视）的邻居进入候选集合（第 003 讲）。

6 动作基线。R2R 原文的序列到序列模型把动作定义为「左、右、上、下、前进、停止」。前进的语义是移动到视场中心最近的可达视点，四个转向动作各改变 30°。这条口径的代价在原文与仓库注释里都说得很直白：模型无法在不同前进方向之间做细粒度选择，只能走「中间的那一个」；回报是动作词表小、训练稳定。

36 视角全景。Speaker-Follower 把当前位姿周围的全景离散为 36 个视角（12 个朝向 × 3 个仰俯档，间隔 30°），每个视角编码为外观特征与四维朝向特征的拼接：

vi = [ fappear(i) ; sin ψi ; cos ψi ; sin θi ; cos θi ] ψi 与 θi 为视角 i 的朝向与仰俯；候选方向 j 的编码 uj 用同样方式构造，停止动作固定为 u0 = 0

动作改为在候选方向集合（含停止）上作分类，不再逐词输出转向：

yj = (W3 ht)T (W4 uj)，pj = exp(yj) / Σj′ exp(yj′) ht 为解码器记忆状态；注意力先在 36 个视角上加权得到一个全景感知向量，再与候选方向做双线性打分

三层口径的差异可以放进一张表，选择判据在实现思路与设计一节给出。

2. 候选视角分解与量化误差

36 个标准视角由上中下三个仰俯带与 12 个朝向列组成。编号约定沿用官方接口（第 003 讲）：0 至 11 为俯视带（约 −30°），12 至 23 为平视带（0°），24 至 35 为仰视带（约 +30°）。把候选方向 (rel_heading, rel_elevation) 映射到最近视角的公式为：

b = clamp( round(θ / 30°) , −1, +1 )，c = round(ψ / 30°) mod 12，viewIndex = 12·(b + 1) + c ψ、θ 分别为相对朝向与相对仰俯（角度制参与取整，弧度制参与存储）；b 为仰俯带下标，c 为朝向列下标

量化误差有两个来源：朝向列误差不超过 15°，仰俯带误差不超过 15°（超过 45° 的仰俯会被夹到 ±30° 带，误差可能更大，属于边界情形）。合成的角距离误差上界为两轴误差的欧氏合成：sqrt(15² + 15²) = 21.21°（0.3702 rad）。用 Python 对第 003 讲轨迹中的真实候选值实算，结果如下表。

3. picking：候选方向与视角缓存之间的桥

全景模型在每个位姿上需要把「可通行候选」与「36 个视角」对应起来，这一步称为 picking。实现上有两条路线，代价与精度不同。

  • 视角挑选。对每个候选方向，按上一小节的公式选出最近的 viewIndex，取该视角的缓存特征，并把四维朝向编码拼接在其后。优点是直接复用 (36, 2048) 的特征库，存储与读取都简单；缺点是精度受 15° 量化限制，两个候选可能落到同一视角。
  • 方向编码。按候选的实际方向，从局部图像块提取外观特征，再拼接四维朝向编码 [sin ψ; cos ψ; sin θ; cos θ]。优点是方向连续、精度高；缺点是需要额外的特征提取或裁剪逻辑，缓存不可直接复用。

两条路线对动作执行没有影响：无论选择哪条，最终都换算回仿真器参数 makeAction([k], [rel_heading], [rel_elevation])，在一步内完成跳转与相机对准。候选的排序键沿用仿真器的口径，即角距离 sqrt(rel_heading² + rel_elevation²)，下标 0 恒为原地停留选项。

维度视角挑选方向编码

4. 行为克隆目标：从最短路径到逐步标签

有了动作空间，监督信号来自数据中的最短路径 P = v0 : v*。设策略在每个状态输出动作分布，则行为克隆最小化教师动作的负对数似然：

L(θ) = − (1/B) Σi=1..B Σt=0..Ti log πθ( a*i,t | oi,≤t, ℓi ) B 为批大小；a*i,t 为教师动作，由当前状态到下一个路径视点 pt+1 的几何关系决定；到达目标后输出停止标签，停止之后的步以忽略符掩码

教师动作的构造需要处理一个事实：路径上的下一个视点未必在当前视场内。官方基线（仓库 env.py 的 _shortest_path_action）用一套确定规则生成标签，可以概括为三态：

几何条件教师标签说明
下一视点在候选列表中移动（该候选下标）候选必须同时满足可通行与视场条件
rel_heading > π/6右转π/6 = 30°，对应一个转向动作；小于 −π/6 则左转
rel_elevation > π/6 且仰俯带小于 2上看上方还有仰视带时才允许；小于 −π/6 且带大于 0 则下看
下一视点不在候选且无法直接转先中和仰俯，再转向先回到平视带，再按目标位置算出的朝向差选择左右
当前视点等于目标视点停止训练序列在此后置忽略掩码

这张表决定了实现的三个要点。其一，移动标签的下标是候选列表下标，随位姿逐步重排，不能把路径上的节点编号直接当动作。其二，在 6 动作口径下，前进固定为「视场中心最近的可达视点」，因此移动标签必须配合转向标签使用；把「沿最短路径的下一节点」直接标成前进，会在目标偏离视场中心时造假标签。其三，停止标签出现在到达目标的时刻，序列长度因 episode 而异，需要忽略掩码对齐批内损失。

5. 解码：贪婪与束搜索

训练给出逐步动作分布，测试时的解码规则决定把这些分布转成哪条轨迹。最简单的是贪婪解码：每步取概率最大的动作。原文的测试期采用贪婪（argmax）单次解码，因为评测是单发的（Anderson 等，2018，5.2 节）。贪婪的弱点在于逐步最优未必联合最优。

束搜索（beam search）在每步保留得分最高的 K 条部分轨迹，目标函数为联合对数概率：

score(a0..T) = Σt=0..T log π(at | o≤t, ℓ)，保留 top-K，最终取最高分 K = 1 退化为贪婪；原始对数概率对长轨迹不利，常配长度归一化 score / Tα（α 为长度惩罚指数，常用 0.6 至 1.0）

导航任务的束搜索有一个特殊问题：两条不同的动作序列可能到达同一环境状态，按动作数对齐会让它们重复竞争。Speaker-Follower 的做法是按状态因子化：状态取「位置、离散朝向、是否已停止」三元组，搜索中只保留到达每个状态的最优路径，允许更高分的路径重新展开该状态，取 K = 40 条候选路径用于重打分。原文报告，标准束搜索按动作数让部分路径竞争的表现更差，状态因子化搜索在单独使用跟随器打分时已优于贪婪。用一个小型概率表实算两种解码的差距：

完整路线联合概率对数概率
a1 → b10.6 × 0.30 = 0.1800−1.7148
a1 → b20.6 × 0.25 = 0.1500−1.8971
a2 → c10.4 × 0.90 = 0.3600−1.0217
a2 → c20.4 × 0.05 = 0.0200−3.9120

第一步概率 a1 为 0.6、a2 为 0.4，贪婪先选 a1，随后在 a1 的分支里选 b1，联合概率 0.1800；束宽 2 保留 a1 与 a2，最终选中 a2 → c1，联合概率 0.3600，为贪婪的 2.00 倍。这个算例说明束搜索的价值来自「第一步次优、后续更优」的分支。束宽度存在边际递减：按几何衰减假设计算 top-K 的概率质量，K = 1 覆盖 0.3000，K = 2 为 0.5100，K = 3 为 0.6570，K = 5 为 0.8319，K = 10 为 0.9718，边际收益迅速下降，而计算量近似按 K 线性增长。停止动作的处理也需要显式规则：停止后的轨迹进入「已完成」集合，与未完成的候选分开排序。

6. 适用边界与失效模式

  • 简单接口裁剪图边：官方简单接口只有 5 个动作，注释明确提示可能裁掉部分可通行边（仓库 env.py）。用它复现实验时，可达性与完整接口不同，指标会偏低。
  • viewIndex 与模式绑定：离散视角模式才有 0 至 35 的编号；连续模式不更新该字段。训练用离散特征、推理切连续模式，会让 picking 与缓存全部失配。
  • 仰俯夹取：超过 ±45° 的候选被夹到 ±30° 带，误差可超过 15°；若任务涉及楼梯上下，必须单独核对这一批候选。
  • 步数上限：官方基线的 rollout 长度为 20 步（仓库 agent.py 的 episode_len 默认值，train.py 取 max_episode_len = 20），截断轨迹的指标语义见下一讲。
  • 缓存规模：单个视点的 36 视角 float32 特征为 36 × 2048 × 4 B = 294,912 B = 288 KiB；12 个平视视角为 96 KiB；全库约 2.89 GiB（10,530 个参与导航视点口径）。特征精度与视角集合都是接口的一部分。

数据流

一次决策的完整链路为：getState 返回渲染帧与候选列表；策略对每个候选生成编码（picking 或方向编码）；语言编码与历史记忆共同打分；动作在候选与停止之间归一化；选中候选后换算为 makeAction([k], [rel_heading], [rel_elevation])；环境更新位姿并重排候选。训练时同一条链路只把动作换成教师标签并累加交叉熵。与第 003 讲的差异在于：003 讲的是接口语义与字段单位，本讲的是训练与解码层；与第 004 讲的差异在于：004 讲的是数据如何采集与校验，本讲的是数据如何变成监督信号。

关键代码与解读

三段代码分别处理视角映射、行为克隆标签与束搜索解码；输出数值均由 Python 实算，与本讲正文一致。

片段 1：候选方向映射到 viewIndex

import math

def nearest_col(heading):
    """朝向列：30 度分度，返回列号与带符号误差（度）。"""
    deg = math.degrees(heading) % 360.0
    col = int(round(deg / 30.0)) % 12
    err = (deg - col * 30.0 + 180.0) % 360.0 - 180.0
    return col, err

def nearest_band(elevation):
    """仰俯带：-1 俯视、0 平视、1 仰视，超过 45 度时夹取。"""
    band = max(-1, min(1, int(round(math.degrees(elevation) / 30.0))))
    return band, math.degrees(elevation) - band * 30.0

def view_index(rel_heading, rel_elevation):
    """组合编号：12*(band+1) + col，与官方 0 至 35 约定一致。"""
    col, _ = nearest_col(rel_heading)
    band, _ = nearest_band(rel_elevation)
    return (band + 1) * 12 + col

for h, e in [(0.17239, -0.00051), (0.49482, 0.02685), (-0.94198, 0.05)]:
    print(view_index(h, e))
# 输出：12 13 22

解读：（1）取整前先把角度归一到 [0, 360)，避免负角度的列号错误；误差用带符号的最小角差计算，便于统计。（2）仰俯夹取上限为 ±1 带，对应 ±30°；真实评测中超过 45° 的候选极少，夹取逻辑仍要保留。（3）函数只做编号映射，不做合法性判断；调用方需确认候选确实在当前视场内，否则把视场外邻居选成目标会触发仿真器过滤。

片段 2：教师动作（行为克隆标签）构造

import math

TURN = math.pi / 6.0  # 30 度，一个转向动作的阈值

def teacher_action(state, next_viewpoint, goal_viewpoint):
    """按官方基线口径生成三态标签：转向、移动、停止。

    state 需包含 viewpoint、band（0/1/2）、navigable 列表；
    navigable[k] 含 viewpoint、rel_heading、rel_elevation。
    """
    if state["viewpoint"] == goal_viewpoint:
        return ("stop", None)
    for k, loc in enumerate(state["navigable"]):
        if loc["viewpoint"] != next_viewpoint:
            continue
        if loc["rel_heading"] > TURN:
            return ("right", None)          # 目标在右侧 30 度之外
        if loc["rel_heading"] < -TURN:
            return ("left", None)
        if loc["rel_elevation"] > TURN and state["band"] < 2:
            return ("up", None)             # 上方仍有仰视带
        if loc["rel_elevation"] < -TURN and state["band"] > 0:
            return ("down", None)
        return ("move", k)                  # 直接移动到候选 k
    # 下一视点不在候选：先中和仰俯，再由调用方按位置计算转向
    if state["band"] == 0:
        return ("up", None)
    if state["band"] == 2:
        return ("down", None)
    return ("turn_toward", None)

state = {"viewpoint": "v0", "band": 1,
         "navigable": [{"viewpoint": "v0"},
                       {"viewpoint": "v1", "rel_heading": 0.10, "rel_elevation": 0.02}]}
print(teacher_action(state, "v1", "v2"))   # ('move', 1)
print(teacher_action(state, "v2", "v2"))   # ('stop', None)

解读：（1）标签是状态相关的：同一个下一视点，在不同朝向下可能得到右转、上看或移动三种不同标签，这要求数据加载时逐帧重算，不能离线写死。（2）仰俯带条件（band 小于 2、band 大于 0）防止在仰视极限处继续上看；官方实现还包含「先中和仰俯再转向」的两级逻辑，示例保留了这一分支的接口。（3）停止标签在到达目标视点时生成，之后的时间步应在损失中掩码；批内序列长度不同，掩码与对齐在 021 讲展开。

片段 3：贪婪与束搜索解码

import math

STEP1 = {"a1": math.log(0.6), "a2": math.log(0.4)}
STEP2 = {"a1": {"b1": math.log(0.30), "b2": math.log(0.25)},
         "a2": {"c1": math.log(0.90), "c2": math.log(0.05)}}

def beam(step1, step2, K):
    """两层动作树的束搜索；K=1 等价于逐步贪婪。"""
    hyps = [(0.0, [])]
    for level in (step1, step2):
        cand = []
        for score, seq in hyps:
            options = level.items() if not seq else level[seq[-1]].items()
            for a, lp in options:
                cand.append((score + lp, seq + [a]))
        hyps = sorted(cand, key=lambda x: x[0], reverse=True)[:K]
    return hyps[0]

print(beam(STEP1, STEP2, 1))   # (-1.7148, ['a1', 'b1'])
print(beam(STEP1, STEP2, 2))   # (-1.0217, ['a2', 'c1'])

解读：（1）分数用对数概率累加，避免长序列的浮点下溢；示例两层的分数分别对应正文表中的 −1.7148 与 −1.0217。（2）K = 1 时第一层只保留 a1，第二层只能展开 a1 的分支，复现贪婪路线；K = 2 保留两个分支，最终选中联合概率更高的 a2 → c1。（3）真实实现要把「已停止」状态单独维护，并在每条候选路径上记录环境状态以满足状态因子化去重；长度归一化在这里未加入，加入后需要重新核对排序。

常见误区

  • 三类下标混用：动作跳到错误视点或直接抛越界异常。根因：节点编号、候选列表下标、viewIndex 是三个独立编号体系，各自作用域不同。修复：在数据结构里显式命名（node_id / candidate_index / view_index），动作执行前断言 candidate_index 落在候选长度内。
  • 把路径下一节点直接当作前进标签：模型学到大量不可执行的目标，训练损失下降而评测轨迹乱走。根因：6 动作口径的前进只走视场中心最近的可达视点，目标偏出视场时该标签非法。修复：按教师三态生成标签，目标不可见时先转向或中和仰俯。
  • 用简单接口跑评测：同一模型指标比论文低，且部分场景到达不了目标。根因：5 动作简单接口按注释会裁掉部分可通行边，可达图变小。修复：改用完整 makeAction 接口，或逐场景统计被裁边比例并在报告中注明。
  • 束搜索的长度偏置：束宽增大指标不升反降。根因：原始对数概率惩罚长轨迹，且不同序列到达同一状态时重复计分。修复：按状态因子化去重，加入长度归一化并单独验证停止分支；束宽按候选重打分数量设置（参考 K = 40）。
  • 视角口径漂移：训练与推理的 picking 结果不一致，行为表现随机化。根因：视角缓存依赖离散模式、视场与分辨率，任一配置变更都会改变映射。修复：把 vfov、受限导航开关、离散模式与特征版本写入配置清单，训练与评测逐项核对。

小结

  • 离散动作空间分三层：仿真器接口 (k, Δψ, Δθ) 状态相关；R2R 基线 6 动作（四个 30° 转向、前进到视场中心最近可达视点、停止）；36 视角全景在候选方向（含停止）上分类。
  • 视角分解为 12 朝向列 × 3 仰俯带 = 36；viewIndex = 12·(b+1) + c；单轴量化误差不超过 15°，合成上界 21.21°（0.3702 rad）。
  • picking 有视角挑选与方向编码两条路线；前者复用 288 KiB/视点的特征缓存，后者精度连续。两条路线都必须写进实验记录，换路线会改变数字。
  • 行为克隆标签由最短路径与当前几何关系共同决定，含转向、仰俯中和、移动、停止四类分支；移动标签的下标是候选列表下标，须逐步重算。
  • 解码口径影响数字：原基线测试期用贪婪；束搜索通过保留 K 条候选扩大联合概率覆盖，导航中按状态因子化去重，参考 K = 40。本讲算例中束宽 2 把路线概率从 0.1800 提升到 0.3600。
  • 下一讲进入评测：NE、TL、SR 三个指标的定义、平均口径与边界语义，本讲的动作轨迹将在那里被换算成可比数字。
