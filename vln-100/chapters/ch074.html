第四篇 · 规模、记忆与泛化方法论

第 074 讲｜预训练数据边界与泄漏

第 073 讲排开了模仿学习、强化学习与 DAgger 三条训练路线；本讲处理比训练策略更靠前的检查点：预训练语料与评测集之间的边界。以 PREVALENT（Hao 等 2020，CVPR 2020，arXiv:2002.10638）的 658.2 万条图文动作三元组为完整样本，定义环境级、样本级、语言级、特征级、选择级、口径级六类泄漏，推导泄漏对成功率的稀释公式，给出抽样检出概率与泄漏自查清单 v1，供论文、模型卡与实验记录共用。

  • 主题：预训练语料 / 数据边界 / 泄漏诊断 / 评测口径
  • 关键数字：6,582K 三元组（104K 与 6,482K 分段，合报差 0.061%）、1,020K 合成指令、每条合成指令平均 6.355 步、SPL 47→51（相对 8.511%）、8% 泄漏使 SR 虚高 2.24 个点
  • 预计学时：60 分钟
  • 前置讲：第 073 讲（训练策略：IL / RL / DAgger）

学习目标

  • 会界定：预训练语料 C、下游训练集 Tr 与评测集 Ev 三类集合的允许与禁止交集，按环境级与样本级两个粒度写出边界声明。
  • 会算：PREVALENT 语料的规模链条（104K、1,020K、6,482K、6,582K、平均 6.355 步）与泄漏稀释公式，估计泄漏对 SR 的虚高幅度。
  • 会查：完成语料与评测的交叉检查四件套：环境标识、视角与轨迹重叠、指令近重复、编码器来源，并写成可执行断言。
  • 会判断：六类泄漏各自的传播渠道、检出手段与后果上界，区分必须排除、需要声明与无法审计三种处置。
  • 会写：一份泄漏自查清单与边界声明模板，把语料来源、交集矩阵、检查阈值与选择协议固定成可复核的证据链。

背景与动机

第 073 讲讨论的是「拿到数据之后怎么训练」，第 064 讲讨论的是「数据本身怎么审计」。两讲之间还缺一环：用于预训练的大规模语料，其覆盖范围与评测集之间的空间关系。VLN 的评测口径建立在环境隔离上：val unseen 与 test unseen 的场景不得出现在训练数据里。预训练把数据规模放大几十倍后，这条隔离线是否仍然成立，需要逐项核对。

PREVALENT（Hao 等 2020）是第一条 VLN 预训练与微调范式：在 Matterport3D 场景图上收集图文动作三元组，用自监督目标预训练编码器，再迁移到 R2R、CVDN 与 HANNA 三个任务。它的语料构造把边界问题一次性摆上台面：语料全部来自训练场景，通过 Speaker 模型把指令数量扩大约 72.7 倍，预训练改善的是「在训练环境内学习表征、向外泛化」的能力。这个设计的边界在哪里、收益如何归因、后续工作怎样在基础模型时代引入新的泄漏渠道，构成本讲主线。

本讲先定义三类集合与六类泄漏，再以 PREVALENT 为样本复盘语料构造与边界声明，随后给出稀释公式与抽样检出概率，最后落成自查清单 v1。第 075 讲在此边界内做偏差诊断，第 076 讲给出因果去偏的处方；边界不清时，两者的结论都无从附着。数据边界是偏差与去偏讨论的前置条件。

核心原理

本讲按「三类集合、PREVALENT 复盘、六类泄漏、交叉检查、稀释公式、检出概率、报告规范、收益边界」八步展开；论文数字全部标注来源与协议（arXiv:2002.10638v2，CVPR 2020；arXiv:2407.07035v2，2024 综述）。

1. 三类集合：语料、训练、评测

把一次完整的实验拆成三类数据集合：预训练语料（pre-training corpus）记为 C，下游训练集（training split）记为 Tr，评测集（evaluation split）记为 Ev。VLN 中每个样本都带环境标识（scene ID）与视角标识（viewpoint ID），因此集合关系可以在两个粒度上检查：环境级（scene level）与样本级（sample level）。

判定规则分三档。C 与 Ev 在环境级必须不相交，一旦相交，unseen 的语义被破坏，任何 unseen 数字都失去解释力；C 与 Tr 相交是允许的，但必须声明并量化覆盖度，这种用法叫域内预训练（in-domain pre-training），其结论是「在训练环境内预训练后向未见环境泛化」，与「在完全无交集的语料上预训练」是两个不同的命题；Tr 与 Ev 相交属于划分错误，与泄漏无关，是流程缺陷，必须在数据入口拦截。样本级还要再看一层：即使环境隔离，评测指令的近重复文本、评测视角出现在合成轨迹中，仍会污染指标。

集合关系是否允许对结论的影响处置
C ∩ Ev = ∅必须满足unseen 口径成立的前提落入断言，违者拒绝
C ∩ Tr ≠ ∅允许改变命题强度，需声明复用度报告复用比例与用途
Tr ∩ Ev ≠ ∅禁止测试集信息进入训练划分脚本拦截
样本级近重复（跨 C/Ev）禁止指标按重复比例虚高近重复检索并剔除

2. PREVALENT 语料与边界复盘

PREVALENT 的预训练语料由两部分组成。第一部分是 R2R 训练集，共 104K 条图文动作三元组，来自 14,025 条训练指令（论文口径：三元组按轨迹逐步计数，约 7.415 条三元组对应一条指令）。第二部分用 Speaker 模型（Fried 等 2018 提出、后在 EnvDrop 中扩展的指令生成器）在训练环境的最短路径上合成 1,020K 条新指令，对应 6,482K 条三元组，即每条合成指令平均 6.355 步。两部分论文合报 6,582K 条三元组，为 R2R 训练三元组的 63.288 倍，指令条数为训练指令的 72.727 倍。

这里有一个值得写进复现笔记的数字口径问题：分段值 104K 与 6,482K 相加为 6,586K，与论文合报的 6,582K 相差 4K，相对差 0.061%。这种量级的差异通常来自分段取整，处理原则是引用时以合报值为准，同时注明分段相加的差值；复现方若要逐条核对，必须以官方发布的文件清单为准，不能用手算总数反推。把「合报值、分段值、差值」三件一起写出，是数据口径的最小纪律。

边界方面，两部分语料都取自训练环境，val unseen 的 11 个场景不在其中，因此 C ∩ Ev 为空；C ∩ Tr 在环境级为满覆盖，复用度按环境计为 100%。这一关系决定了 PREVALENT 的结论措辞：它能证明「域内自监督预训练改善未见环境泛化」，不能证明「无交集语料预训练同样有效」。训练侧配置为 8 块 V100、单卡批大小 96（全局 768）、AdamW、学习率 1e-5、20 轮；按每三元组一次前向粗算，遍历语料约 8,570 步一轮，20 轮约 17.1 万步。预训练目标是图像参与注意力的掩码语言建模（MLM，15% 掩码比例）与动作预测（AP，action prediction），总损失为两项之和；掩码图像建模的尝试未带来更好结果，被作者排除。

收益证据分三层。R2R 上，单指令设置 val unseen 为 SR 58 / SPL 53，多指令设置为 SR 60 / SPL 57；单指令设置的 test unseen 从 EnvDrop 的 SPL 47 提升到 51，绝对 +4，相对 +8.511%。迁移到 CVDN（对话历史导航），val unseen 的目标进度（Goal Progress）在 Oracle / Navigator / Mixed 三种监督路径下为 2.58 / 2.99 / 3.15，均高于同结构 Seq2Seq 基线。迁移到 HANNA（交互式求助导航），test unseen 的 SR 为 52.91（对照系统 Anna 为 47.45），SPL 为 28.72（对照 25.50）；seen 与 unseen 的 SPL 差从 Anna 的 38.42 收窄到 30.66，收窄 7.76 个点，相对 20.198%。

3. 六类泄漏：渠道、检出与后果

泄漏（leakage）指任何使评测信息通过非正常路径进入模型训练、模型选择或报告环节的情形。按传播渠道分为六类，前两类是经典的数据泄漏，后四类在预训练与基础模型时代出现频率更高。

类型渠道检出手段后果量级
环境级评测场景进入语料或训练scene ID 集合运算unseen 结论失效，最大
样本级评测指令或轨迹的近重复进入语料5 元组 Jaccard、轨迹视角交集与重合比例同阶
语言级语料与评测指令共享模板与短语BLEU/ROUGE 最大相似度分布语言先验虚高，需分层
特征级视觉或语言编码器在覆盖评测的数据上预训练编码器来源审计、探针实验不可解析，须降级声明
选择级反复用 val unseen 调参与选模型实验记录、选择次数统计乐观偏差随次数累积
口径级评测时使用真值语义、错标未剔除评测脚本审查、拆分核对指标绝对水平失真

六类之中，环境级与选择级的判定是二值的：前者一旦命中，unseen 数字不能作为论文主结论；后者一旦发生，val unseen 事实上退化成了验证集，只能作为开发集使用，最终结论必须等待 test unseen 的单次评测。样本级与语言级可以量化，按比例处理。特征级在基础模型时代最棘手：CLIP、GPT 系列一类模型在网页规模数据上训练，审计者无法取得其完整数据清单，只能通过探针实验估计污染程度，并在报告中把结论降级为「在编码器可能见过相关数据的条件下」。Zhang 等 2024 的 VLN 基础模型综述（arXiv:2407.07035v2）在更广范围指出同类问题：基础模型来自互联网数据，缺少具身经验，且训练数据规模使其携带的偏差难以逐项追溯；报告时只能如实说明验证边界。

4. 语料与评测的交叉检查四件套

检查的输入是四份清单：语料的场景标识与视角标识、语料的指令文本、评测集的场景标识与视角标识、评测集的指令文本，外加一份编码器来源说明。四件套按顺序执行，前一环不通过就不进入下一环。

第一件，环境标识集合运算。分别计算 C∩Ev、C∩Tr 与 Tr∩Ev 三组交集。前者非空则拒绝，中者非空则登记复用度，后者非空则修划分脚本。PREVALENT 的对应值是 C∩Ev 为空、C∩Tr 覆盖全部 61 个训练场景。

第二件，视角与轨迹重叠。把每条轨迹表示为视角序列，检查评测轨迹的视角是否出现在语料轨迹中；若出现，再用图距离（测地距离）判断重合长度。合成语料沿最短路径生成时，评测路径与合成路径在房间入口等枢纽视角上重合属于常见现象，需要设定允许阈值并报告命中比例，例如视角交集占比低于 0.5 且不构成连续片段可放行，连续 3 个以上视角重合则按样本级泄漏剔除。

第三件，指令近重复。对指令做规范化（统一小写、去标点、压缩空白），切成 5 元组集合，用倒排索引找候选，再算 Jaccard 相似度。示例：两条指令为「go up the stairs and turn left」与「go up the stairs then turn left」，词集合的交集为 6，并集为 8，Jaccard 为 0.75，接近复述。阈值取 0.8 时，短指令的命中基本可判为改写或复述；长指令因集合变大，阈值应下调到 0.6 至 0.7 并配合最长公共子串检查。语言级泄漏还要报一个分布量：每条评测指令与整个语料的最大相似度，按相似度分箱统计，展示评测集是否整体偏向语料高频模板。

第四件，编码器来源与探针。逐项记录视觉编码器（如 ResNet-152、CLIP-B/16）、语言编码器（如 RoBERTa、BERT）与多模态大模型的训练数据画像，标注其中是否可能覆盖 Matterport3D 图像、R2R 指令文本或评测环境的网页内容。无法取得清单时，设计探针：让模型补全评测指令的挖空词，或判别指令与轨迹是否匹配，若显著高于随机，说明存在记忆性携带，需要把结论降级。四件套的共同产物是一张交集矩阵；单句「数据无重叠」的声明不构成检查记录。

5. 泄漏对结论的影响：稀释公式

设评测集共 N 条，其中泄漏样本占比例 p，泄漏样本上的表观成功率为 SRleak，其余干净样本上的成功率为 SRclean。混合评测得到的表观成功率满足线性稀释关系：

SRmeasured = p · SRleak + (1 − p) · SRclean ΔSR = p · (SRleak − SRclean)；p 为泄漏样本比例，SR 为成功率（0 到 1）或百分数，两处口径须一致

取值代入。评测集取 R2R val unseen 的样本量 N = 2,349。假设泄漏子集的成功率被先验抬到 92.0%，干净子集为 64.0%：泄漏比例 8%（188 条）时，表观 SR 为 0.08 × 92.0 + 0.92 × 64.0 = 66.24%，虚高 2.24 个点，相对 3.500%；泄漏比例 2%（47 条）时，表观 SR 为 64.56%，虚高 0.56 个点，相对 0.875%。同一条泄漏样本的边际影响由 28 个点的成功率差决定，比例决定总量。

稀释公式有三个适用条件必须写明。第一，泄漏样本在评测集内是均匀抽取的；若泄漏集中在某类指令或某类场景（例如短指令、短路径更容易既出现在语料又出现在评测），应按分层重新加权，否则低估影响。第二，SRleak 与 SRclean 的取值需要独立估计，常用做法是先在泄漏子集与干净子集上分别评测再合并，合并口径与报告口径必须一致。第三，公式只描述评测混合，不描述训练侧影响：语料中的评测相似样本还会影响模型参数，这部分偏差无法用一次评测拆开，只能通过重训对照实验估计。

6. 抽样检出概率：查多少条才够

审计通常用抽样检查估计泄漏比例，样本量太小会漏检。在无放回抽样下，评测集 N 条、实际泄漏 K 条、抽检 n 条，一条都没抽中泄漏样本的概率为组合数之比：

P(未命中) = C(N − K, n) / C(N, n) C 为组合数；P(至少命中一条) = 1 − P(未命中)

仍取 N = 2,349。当泄漏 K = 47 条（2%）时，抽 100 条的命中概率为 87.32%，抽 150 条为 95.64%，抽 200 条为 98.54%。当泄漏 K = 188 条（8%）时，抽 100 条的命中概率已超过 99.9%，抽 200 条在六位小数下等于 1。结论：对 2% 量级的泄漏，约 150 条的分层抽检才能达到 95% 的命中概率；对 8% 量级，100 条足够。抽检应分层执行，在短指令、长指令、高频模板、罕见模板四层内各抽固定数量，用各层命中率反推总体，避免把命中概率与泄漏比例混为一谈。（组合数用对数伽马函数计算，避免大数溢出，见关键代码片段 3。）

7. 报告规范：边界声明的五个字段

边界声明写成五个字段，缺一不可，随论文与模型卡发布。字段一，语料来源：数据名称、版本、获取批次、许可证；字段二，交集矩阵：C∩Tr 与 C∩Ev 在环境级与样本级的取值，含复用度比例；字段三，检查记录：交叉检查四件套的脚本版本、阈值、命中数量；字段四，编码器来源：视觉与语言编码器的训练数据画像，无法审计的写「未知」并附探针结果；字段五，选择协议：调参使用的划分、val unseen 的查询次数、test unseen 的评测次数。前四个字段决定结论的适用范围，第五个字段决定结论的乐观程度。

8. 收益与边界的对照

把 PREVALENT 的收益放进边界里读：语料环境复用度 100%、评测零交集，因此 SPL 47→51、SR 58 与 SPL 53、CVDN 迁移与 HANNA 收窄 7.76 个点的结论都限定在域内预训练这一档。后续工作若改用网页图文语料，C∩Tr 可能降到接近零，但 C∩Ev 的审计能力同时下降，语言级与特征级泄漏的风险上升，结论强度需要重新划分。把结论按证据强度分三态记录：三集合隔离且编码器可审计为「干净态」，可与论文主结论并列；C∩Tr 非空但 C∩Ev 为空为「声明复用态」，主结论必须带「域内预训练」限定词；C∩Ev 非空或编码器覆盖未知且探针阳性为「降级态」，只能作为探索性实验报告。收益数字不变，结论的资格随边界变化，边界声明是数字的解释契约。

关键代码与解读

三段代码分别给出环境级集合检查、指令近重复检查、泄漏稀释与检出概率计算。数字与正文一致，可直接作为审计脚本的骨架；生产环境应把组合数计算与倒排索引替换为分块实现。

片段 1：环境级边界检查

def audit_environment_split(pretrain_scenes, train_scenes, eval_scenes):
    """环境级边界检查：返回三对交集、结论标签与语料复用度。"""
    C, Tr, Ev = set(pretrain_scenes), set(train_scenes), set(eval_scenes)
    assert C and Tr and Ev, "三份场景清单都不能为空"
    overlap = {
        "C_Ev": sorted(C & Ev),      # 预训练与评测相交：一票否决
        "C_Tr": sorted(C & Tr),      # 预训练与训练相交：允许，必须声明
        "Tr_Ev": sorted(Tr & Ev),     # 划分自身错误：一票否决
    }
    if overlap["C_Ev"] or overlap["Tr_Ev"]:
        verdict = "reject"            # 触碰评测，结论降级为探索性实验
    elif overlap["C_Tr"]:
        verdict = "declare"           # 声明复用度后，可报告 unseen 结论
    else:
        verdict = "clean"             # 三集合隔离，unseen 口径成立
    reuse = len(C & Tr) / max(len(C), 1)   # 语料环境复用度
    return overlap, verdict, round(reuse, 4)

# PREVALENT 口径：C 与 Tr 都取自 61 个训练场景，复用度 1.0
# C∩Ev 为空，返回 verdict = "declare"，主结论须加「域内预训练」限定词

解读：（1）把三种交集一次算清，前两者决定结论资格，第三者是流程缺陷；（2）复用度用「语料中与训练集共享的场景数除以语料场景总数」，预训练与训练完全同源时取 1.0，便于声明时给出单一数字；（3）函数返回标签，让自动化流程可以按标签决定实验能否进入正式评测链路。

片段 2：指令近重复检查

import re

def normalize(text):
    """指令规范化：统一小写、非字母数字替换为空格、压缩空白。"""
    text = re.sub(r"[^a-z0-9 ]", " ", text.lower())
    return text.split()

def ngram_set(tokens, n=5):
    """切出 n 元组集合，短指令回退到全部词。"""
    if len(tokens) < n:
        return {tuple(tokens)}
    return {tuple(tokens[i:i + n]) for i in range(len(tokens) - n + 1)}

def check_near_duplicate(pretrain_instr, eval_instr, threshold=0.8):
    """报告评测指令中与语料高度重合的条目与总体命中率。"""
    corpus = [ngram_set(normalize(x)) for x in pretrain_instr]
    hits = []
    for idx, raw in enumerate(eval_instr):
        grams = ngram_set(normalize(raw))
        best = 0.0
        for other in corpus:
            inter = len(grams & other)
            if inter == 0:
                continue
            jac = inter / len(grams | other)   # Jaccard 相似度
            if jac > best:
                best = jac
        if best >= threshold:
            hits.append((idx, round(best, 3)))  # 命中：先剔除再评测
    rate = len(hits) / max(len(eval_instr), 1)
    return hits, round(rate, 4)

# 示例：两条指令词集合交集 6、并集 8，Jaccard = 0.75，接近复述
# 生产实现改倒排索引：只为同时命中的候选计算并集

解读：（1）规范化先把大小写、标点与空白差异消掉，否则同一句话的不同写法不会被检出；（2）5 元组集合对词序变化不敏感，适合抓模板复述；对长指令应改用最长公共子串补充顺序检查；（3）阈值 0.8 面向短指令，长指令下调到 0.6 至 0.7；命中条目按样本级泄漏处理，报告时给出命中清单与比例；概括性结论不满足证据要求。

片段 3：稀释计算与抽样检出概率

import math

def diluted_sr(leak_rate, sr_leak, sr_clean):
    """泄漏样本按比例稀释后的表观成功率，返回表观值与虚高幅度。"""
    measured = leak_rate * sr_leak + (1.0 - leak_rate) * sr_clean
    return round(measured, 3), round(measured - sr_clean, 3)

def detect_prob(n_eval, n_leak, n_sample):
    """无放回抽样至少命中一条泄漏样本的概率。"""
    def log_comb(n, k):
        return (math.lgamma(n + 1) - math.lgamma(k + 1)
                - math.lgamma(n - k + 1))      # 对数组合数，防溢出
    if n_leak >= n_eval:
        return 1.0
    log_p0 = log_comb(n_eval - n_leak, n_sample) - log_comb(n_eval, n_sample)
    return round(1.0 - math.exp(log_p0), 6)

# 取 R2R val unseen 样本量 N = 2349，泄漏 47 条（2%）：
# diluted_sr(47 / 2349, 92.0, 64.0) -> (64.56, 0.56)
# detect_prob(2349, 47, 150) -> 0.9564，抽 150 条有 95.64% 概率命中

解读：（1）稀释函数把「泄漏比例」与「成功率差」分离，便于对未知场景做区间估计；（2）组合数用对数伽马函数计算，避免泰勒展开前的整数溢出，2349 与 47 的量级已超出直接阶乘的稳妥范围；（3）检出概率只依赖 N、K、n 三个量，与泄漏样本具体内容无关，适合在审计计划阶段先算样本量，再决定分层方案。

常见坑

  • 用「同一数据集」代替场景标识：认为预训练用 R2R 训练集、评测用 R2R val unseen，于是判定无重叠。根因是忽略场景级统计：R2R 的 val seen 与训练集共享场景，若预训练语料在采样时混入 val seen，评测口径即复杂化。修复：所有审计以 scene ID 集合运算为准，数据集名字不作为边界证据。
  • 把语言级泄漏当无害：合成指令与人工指令共享模板短语，评测时语言先验抬高停止决策的成功率。根因是只查了环境与轨迹，未查文本近重复。修复：跑 5 元组 Jaccard 与 BLEU/ROUGE 最大相似度分布，按相似度分箱报告；阈值设置写入脚本，命中条目剔除或降权。
  • 忽略编码器的第三种泄漏：自建语料干净，但换成网页预训练的视觉编码器后，评测场景图像可能已在编码器训练集中。根因是把「数据边界」只理解为自有数据集。修复：编码器来源逐项登记，无法取得清单时做补全与匹配探针，阳性则降级声明。
  • 反复用 val unseen 调参：每次改进都在 val unseen 上选择，最后报告的数字带选择偏差。根因是混淆开发集与评测集。修复：明确规定 val unseen 的查询次数与用途，最终结论以 test unseen 单次评测为准；论文中报告查询次数与调参过程。
  • 口径混用：分段值与合报值互相推导：PREVALENT 的分段和 6,586K 与合报 6,582K 差 4K，若用手算值覆盖合报值，复现数字与论文不符。根因是未记录取整口径。修复：引用时合报值与分段值并列，差值注明；复现以官方文件清单为唯一事实源。

小结

  • 三类集合 C、Tr、Ev 的边界规则：C∩Ev 必须为空，C∩Tr 允许但须量化复用度，Tr∩Ev 属于流程错误；环境级与样本级两个粒度都要检查。
  • PREVALENT 语料为 104K 训练三元组加 1,020K 合成指令对应的 6,482K 三元组，合报 6,582K（分段和差 4K，相对 0.061%）；合成指令平均 6.355 步；语料全部取自训练场景，val unseen 场景零交集。
  • 六类泄漏为环境级、样本级、语言级、特征级、选择级与口径级；前两类用集合运算与近重复检索判定，后四类在基础模型时代出现频率上升，需要来源审计、探针与使用纪律。
  • 稀释公式 SRmeasured = p·SRleak + (1−p)·SRclean：8% 泄漏在成功率差 28 个点下使表观 SR 虚高 2.24 个点（相对 3.500%），2% 泄漏虚高 0.56 个点。
  • 抽样检出：2% 泄漏时抽 150 条才有 95.64% 的命中概率，8% 泄漏时 100 条已超过 99.9%；审计计划先用检出公式定样本量，再分层执行。
  • 结论按边界分三态：干净态、声明复用态、降级态；边界声明五字段（语料来源、交集矩阵、检查记录、编码器来源、选择协议）随文发布。
