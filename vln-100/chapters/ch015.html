第一篇 · 任务、数据、仿真与评测地基

第 015 讲｜CVDN / NDH：对话历史导航

本讲讲「问路」：CVDN 把两名人类放进 Matterport3D 仿真环境，一人导航、一人拿着最短路特权信息作答，收集 2,050 段人前人（human-human）对话；NDH 任务从这些对话切出 7,415 个实例，要求智能体只凭目标物与截至当前的对话历史推断动作。学完能定义并计算 Goal Progress，能设计对话历史的编码接口，能判断三种监督来源对策略的影响。

  • 主题：对话导航 / 特权信息 / 对话历史编码 / Goal Progress
  • 关键公式：GP = dG(b, Gj) − dG(e, Gj)
  • 预计学时：60 分钟
  • 前置讲：第 014 讲（SOON / FAO：场景描述与任意起点）

学习目标

  • 会写：复述 CVDN 的双角色协议（Navigator 与 Oracle）、提示的两个性质（有歧义、信息不足），以及起点选取规则。
  • 会算：核对 2,050 段对话到 7,415 个 NDH 实例的拆分（4,742 / 382 / 907 / 1,384），并用 2.25 m 的跳距口径换算路径长度。
  • 会推：写出 Goal Progress 的定义，构造算例说明负值与零值的含义，并解释它与 SR、NE 的分工。
  • 会实现：把对话历史序列化为带说话人标记的 token 流，并按问答交换切分 NDH 实例。
  • 会判：在 Navigator、Oracle、混合（Mixed）三种监督之间做取舍，说明各自的偏差来源与适用条件。

背景与动机

第 014 讲的 SOON 仍然假设信息在开局一次给全：一段场景描述覆盖整段 episode。真实机器人会在走错时提问，人会在回应中给出新的导向，下一段动作必须结合问答历史来理解。把这条交互通道做成可训练的任务，需要三样东西：一套能反复出现的求助场景、一份带特权信息的回应数据、一个把对话历史与动作预测连起来的任务定义。Thomason 等 2019 在 CoRL 2019 给出的 CVDN（Cooperative Vision-and-Dialog Navigation，协作式视觉对话导航）同时提供了这三样东西。

CVDN 的每个 episode 由两名人类协作：Navigator 只看第一人称观察，可以移动、提问或直接猜测目标房间；Oracle 与 Navigator 看到同一帧画面，但额外拥有一个最短路规划器给出的未来 5 跳动画，用自然语言回应提问。提示句由构造保证两个性质：有歧义（目标物在房内出现 2 至 4 次，目标房间待定）与信息不足（不描述路线）。起点选在离所有候选目标区域最远的位置，把探索压力写进任务设计（Thomason 等, 2019，3 节）。

在这份数据上，论文定义 NDH（Navigation from Dialog History，从对话历史导航）任务：给定目标物与截至当前的一段问答历史，智能体在未知环境中朝目标区域推断动作。每个对话按问答交换切成多个实例，得到 7,415 个训练与评测单元。初始的多模态序列到序列基线显示两条结论：把对话历史看得更远能提升进度，混合人类与规划器的监督能同时利用两种信号的优点（Thomason 等, 2019，摘要与 5 节）。

本讲要解决三件事：第一，把 CVDN 的采集协议与统计口径讲清；第二，把 NDH 的实例切分、监督来源与 Goal Progress 推导清楚；第三，给出对话历史编码接口的最小实现。014 讲的图记忆与动作接口在本讲继续沿用，评测指标 NE、SR、SPL 的通用定义见 006、007 讲。

核心原理

1. 采集协议：角色、提示与激励

每段对话由一个提示四元组实例化：场景 S、目标物 to、起点 p0、目标区域 Gj。目标物从 Matterport3D 物体标注中筛选：先取初始 929 类，剔除怪异名称与非特定类别（如墙），合并近义名称，再要求每类物体至少在 5 个不同场景出现、在每个场景出现 2 至 4 次，最终得到 81 类（Thomason 等, 2019，3 节脚注）。目标区域 Gj 是房内包含该物体实例的房间节点集合，同一场景可能有多个候选区域，这正是「有歧义」的来源。

起点由一条最大化规则给出，对场景内每个候选视点 p 计算它与所有候选目标区域的聚合距离，取最大者：

p0 = argmaxp ∈ S ( Σj minpi ∈ Gj dh(p, pi)2 )1/2 dh 为导航图上的跳数距离；对每个目标区域先取区域内最近节点，再把各区域的距离平方求和后开方，聚合值最大者作起点

该式的读法：先算候选位置到每个可能目标区域的最近跳距，平方求和再开方，得到对「所有可能目标」的整体远离程度；取最大者意味着起点几乎必然位于远处，Navigator 必须依靠探索与提问逼近。数据集覆盖 83 个场景，其余场景缺少符合条件的物体实例。

交互规则直接塑造了数据的形状：Navigator 回合内可以移动、提问或猜测目标房间；猜测错误会禁用后续移动，强制提问一次；Oracle 回合可以看到未来 5 跳的规划动画并用语言回应。5 跳的选择有依据：R2R 的平均路径为 6 跳，5 跳略短于这个长度，人类标注者能给出合理描述（Thomason 等, 2019，3 节）。采集合规还包括质量门槛：段均同伴协作评分低于 4 的直接失去后续任务资格，最终段均评分为 4.52 / 5。

3. NDH 任务定义与实例切分

一段 CVDN 对话写成交替序列 ⟨N0, Q1, A1, N1, …, Qk, Ak, Nk⟩，其中 N 为 Navigator 的动作段、Q 为提问、A 为 Oracle 的回答；每次提问或回答结束一个回合，因此 Q 与 A 都是单条 token 字符串（Thomason 等, 2019，4 节）。对每个交换下标 i（0 ≤ i ≤ k）切出一个 NDH 实例：输入为目标物 to 与问答历史 (Q1:i, A1:i)，输出为从 Ni−1 终点（i = 0 时为起点 p0）出发、朝目标区域前进的动作序列。i = 0 表示「还没有任何问答，先按提示走一段」。

切分产生 7,415 个实例，按对话粒度保持与 R2R 相同房型折（fold）的一致性：同一对话的全部实例进入同一折，未见房验证与测试沿用 R2R 的场景划分。四个折的规模闭合如下表，求和与总数一致：

折实例数占比（实算）用途
训练4,74263.95%训练
验证（见房）3825.15%模型选择
验证（未见房）90712.23%泛化诊断
测试（未见房）1,38418.66%最终结果；训练集并入验证集后重训

对话历史是任务输入的一部分，它随 i 增长，信息逐步揭示。这一点与 R2R 的固定指令形成结构差异：R2R 的条件 ℓ 跨时间不变，NDH 的条件是序列 (Q1:i, A1:i)，状态设计必须容纳「不确定的目标在对话中被逐步收窄」这一过程。

4. 监督来源：Navigator、Oracle 与混合

每个 NDH 实例自带两种监督路径：Ni 是人类 Navigator 在问答交换之后实际走的路，Oi 是 Oracle 当时看到的规划动画，即向目标区域的最短路，长度上限 5 跳。统计上，Ni 的平均长度为 6.63 跳（范围 1 至 40），Oi 的平均长度为 4.35 跳（范围 0 至 5），前者的长度优势对应人类探索中的绕行与回溯（Thomason 等, 2019，4 节）。

两种监督各有偏差：只学 Ni 会吸收人类的低效绕行；只学 Oi 会把策略限制在 5 跳以内的短视行为，且规划器路径与提问语境未必对应。论文给出混合监督：以「Oracle 的终点是否落在人类路径上」为二值置信度，落在其中就用 Ni，否则退回 Oi。该规则可以读作对演示数据的一次置信度过滤，与「先学再精炼」的演示学习思路一致（Thomason 等, 2019，5 节）。

设计决策：混合监督把两种信号拼成一条监督路径

Ni 提供长程探索与任务直觉，Oi 提供短程准确性与语言相关性。二值置信度规则简单，却直接改变训练分布：人类走过头或绕远时按规划器纠正，人类沿合理路线前进时保留其探索行为。原文报告，混合监督在三个评测折上都优于单独使用任一来源，差异经过多重比较校正（Thomason 等, 2019，表 3 与附录 7.3）。

5. 评测口径：Goal Progress

NDH 的目标是在未知环境中朝目标区域持续前进，最终是否到达留给到位型指标，因此主指标为 Goal Progress（GP，目标进度）：从起点到终点，到目标区域的拓扑距离减少了多少米。设 P̂ 为智能体推断的路径，b 为起点节点，e 为终点节点，Gj 为目标区域节点集合：

GP = dG(b, Gj) − dG(e, Gj)，dG(q, Gj) = minp ∈ Gj dm(p, q) dm 为图上的拓扑距离（只沿可通行边绕行，不穿越墙体）；区域距离取区域内节点的最小距离；GP 可为负，表示整体朝远离目标的方向移动

GP 与 SR、NE 的分工很清晰：SR 与 NE 回答「最终是否到达」，GP 回答「这一段有没有更靠近」。在 NDH 的实例粒度上，很多片段本来就到不了目标，只用到位型指标会几乎全零，进度型指标才能提供训练与比较信号。构造一个教学算例，逐条核对计算口径：

实例起点距离 dG(b) (m)终点距离 dG(e) (m)GP (m)

Python 实算：平均 GP = (2.25 + 2.25 − 2.25 + 4.50 + 2.25) / 5 = 1.80 m；正向进展占比 4/5 = 0.80。I3 的负值提醒我们 GP 与成功率的口径不同：朝错方向走完整段会记为负进度，训练时应对负值样本做单独统计，避免把「退步」与「原地」混为一谈。原文测试集（未见房）上，全历史输入加混合监督的平均 GP 为 2.35 m，随机策略 0.83 m，监督上限（最短路智能体）为 9.76 m（Thomason 等, 2019，表 3）。

6. 基线模型：对话历史如何进入解码器

初始基线沿用 R2R 的序列到序列骨架并替换条件输入：对话历史经词嵌入送入 LSTM 编码器，编码结果初始化解码器的隐状态；解码器每一步接收当前视角的 ResNet-152 倒数第二层特征与上一步动作，输出离散动作。输入流用四个特殊标记组织：NAV 与 ORA 标注说话人，TAR 前置目标物词元，EOS 结束序列。词表以出现次数 5 为阈值，低频词替换为 UNK；训练折词表 1,042 个 token，训练加验证折 1,181 个，增幅 13.34%。训练配置为学生强制（student-forcing）2 万次迭代、批大小 100，验证性能每 100 次迭代检查一次（Thomason 等, 2019，5 节与附录 7.4）。

输入消融给出「看多远」的答案：只给目标物、只给最后一条回答、只给最后一组问答，均不如完整历史；在未见房测试上，完整历史显著优于只给目标物。监督消融给出「学什么」的答案：混合监督在三个折上都显著优于单独监督。把所有模型与随机策略、最短路智能体放在一起看，序列到序列基线在未见房测试上取得 2.35 m 的平均进度，仍与最短路上限 9.76 m 有明显距离，论文据此判断该任务留有余量（Thomason 等, 2019，5 节）。

8. 适用边界与失效模式

  • Oracle 是特权智能体：它的回答基于最短路规划器，真实人类向导未必知道最短路；模型学到的「提问就能得到接近最优的提示」这一先验，迁移到真人时会高估信息质量。
  • 提示可解性依赖筛选：81 类物体经过多重筛选，稀有物与不在清单中的目标无法构成 episode，任务分布比开放世界窄。
  • 起点最大化规则改变状态分布：起点几乎总在远处，模型很少见到「已在目标附近」的问答样本，早停与确认行为缺少监督。
  • 实例与对话的依赖关系：同一对话切出的实例共享历史，划分必须按对话整体进行；按实例随机划分会造成同源泄漏，数字系统性偏高。
  • 进度指标不封口：GP 衡量片段进展，不要求到达；只报 GP 会掩盖「原地打转但单步凑巧变近」的策略，评测应补充到位型指标或逐条核对方向一致性。

实现思路与设计

本讲的工程落点有三件：一份 NDH 实例字段规范、一套对话历史序列化接口、一张训练配置与监督取舍表。

目标物[TAR] + 词元把目标从普通名词中分离，防止与话语中的同类词混淆
Navigator 话语[NAV] + 词元标注提问者角色，区分问题与回答的语气差异
Oracle 话语[ORA] + 词元标注回答者角色，回答通常承载动作指令
序列结束[EOS]定长补齐时的真实长度标记，避免把补齐位当作内容
低频词[UNK]（出现少于 5 次）控制词表规模；测试时的新词同样映射到 UNK

接口选择的判据是「角色与顺序都要保留」：拼接成纯文本会丢掉说话人身份，交换顺序会改变「回答依赖问题」的指代关系。若未来要接入语言模型编码器，同一序列化可以映射为带角色前缀的提示串，语义等价、实现不同。

关键代码与解读

三段代码覆盖序列化、实例切分与进度指标；算例数字与正文一致。

片段 1：对话历史的序列化

class Special:
    TAR, NAV, ORA, EOS, UNK = "[TAR]", "[NAV]", "[ORA]", "[EOS]", "[UNK]"

def serialize(target, history, vocab, max_len=200):
    """把目标物与问答历史编成单条 token 流。
    history: [(speaker, text)], speaker 取 'nav' 或 'ora'。"""
    tokens = [Special.TAR]
    tokens += [w if vocab.get(w, 0) >= 5 else Special.UNK
               for w in target.lower().split()]
    for speaker, text in history:
        tokens.append(Special.NAV if speaker == "nav" else Special.ORA)
        # 角色标记必须逐条插入: 拼接纯文本会丢失说话人身份
        tokens += [w if vocab.get(w, 0) >= 5 else Special.UNK
                   for w in text.lower().split()]
    tokens.append(Special.EOS)
    if len(tokens) > max_len:
        # 超长时丢弃最早的历史窗口, 保留目标标记与最近内容
        head = tokens[:2]
        tokens = head + tokens[-(max_len - len(head)):]
    return tokens

def lengths_stats(batch):
    return sum(len(t) for t in batch) / len(batch)

解读：（1）角色标记逐条插入，NAV 与 ORA 交替出现的顺序本身就是信号，不能压平成一段文本。（2）低频词映射在序列化时完成，词表统计口径与训练一致；推理时遇到新词同样映射到 UNK，保证接口稳定。（3）超长截断从最早的历史开始丢弃，保留目标标记与最近的问答交换，原因是最近一次交换与当前动作最相关；截断策略应与消融实验中的「历史长度」变量分开控制。

片段 2：NDH 实例切分

def split_ndh(dialog):
    """把一段对话切成 NDH 实例。
    dialog: {'scan', 'target', 'start', 'exchanges', 'nav_steps', 'oracle_steps'}
    exchanges: [(question, answer)] 按时间序。"""
    instances = []
    history = []                       # 逐步累积的问答历史
    start = dialog["start"]
    for i, (q, a) in enumerate(dialog["exchanges"]):
        # i 号实例使用交换之前的输入历史与上一段导航的终点
        instances.append({
            "dialog_id": dialog["id"],
            "exchange_id": i,
            "history": list(history),  # 拷贝, 防止后续交换污染本实例
            "start_node": start,
            "sup_nav": dialog["nav_steps"][i],
            "sup_oracle": dialog["oracle_steps"][i],
        })
        history += [("nav", q), ("ora", a)]
        start = dialog["nav_steps"][i][-1]   # 下一实例的起点
    instances.append({                 # 最后一个实例: 走完剩余路段
        "dialog_id": dialog["id"],
        "exchange_id": len(dialog["exchanges"]),
        "history": list(history),
        "start_node": start,
        "sup_nav": dialog["nav_steps"][-1],
        "sup_oracle": dialog["oracle_steps"][-1],
    })
    return instances

解读：（1）实例与交换一一对应，外加末尾一个「全部历史」实例，切分数量与原文口径一致（一段对话 k 组问答产生 k+1 个实例）。（2）history 用拷贝保存，若直接引用可变列表，后续循环追加的交换会污染先前实例的输入，这是实现中最典型的静默错误。（3）起点由上一段人类路径的终点给出，对应论文「从 Ni−1 的终点出发」；监督路径与实例同折，划分必须以 dialog_id 为单位整体进行。

片段 3：Goal Progress 与算例

def goal_progress(start_d, end_d):
    """GP = 起点到区域的距离 - 终点到区域的距离, 单位米。
    正值为接近, 负值为远离, 零为原地或等距移动。"""
    return start_d - end_d

rows = [                    # (起点区域距离, 终点区域距离), 自设教学数字
    (20.25, 18.00),
    (15.75, 13.50),
    (9.00, 11.25),          # 远离: GP 为负, 训练时应单独统计
    (24.75, 20.25),
    (13.50, 11.25),
]
gps = [goal_progress(a, b) for a, b in rows]
avg = sum(gps) / len(gps)
pos = sum(1 for g in gps if g > 0) / len(gps)
print([f"{g:+.2f}" for g in gps])
print(f"avg GP = {avg:.2f} m, positive ratio = {pos:.2f}")
# 输出: ['+2.25', '+2.25', '-2.25', '+4.50', '+2.25']
#       avg GP = 1.80 m, positive ratio = 0.80

解读：（1）区域距离必须先对目标区域节点取最小，再作差；若直接用区域中心坐标，绕墙的拓扑结构会被抹平。（2）负值样本单独可统计，用它区分「走错方向」与「原地未动」；只报平均值会把两种失败混在一起。（3）该函数只依赖距离输入，评测脚本与训练诊断脚本可以共用同一实现，避免两处口径漂移。

常见坑

  • 把对话历史当普通指令拼接：模型在「仅确认词」类回答上表现异常。根因：丢失说话人角色与问答配对关系，[NAV] / [ORA] 标记缺失。修复：按片段 1 的接口逐条插入角色标记，并保留问题与回答的先后顺序。
  • GP 的符号方向写反：训练损失与验证指标趋势相反。根因：把「终点距离减起点距离」当进度，方向翻转。修复：固定为「起点距离减终点距离」，用本讲算例做单元测试，断言负值样本对应远离目标。
  • 按实例随机划分数据：未见房数字虚高。根因：同一对话的多个实例共享历史与场景，按实例划分造成同源泄漏。修复：以 dialog_id 为单位整体划折，并断言训练与测试的 dialog_id 交集为空。
  • 把 Navigator 监督当理想标签：模型学会绕行与回溯，短程准确率下降。根因：人类路径平均 6.63 跳，长于规划器路径且含试探。修复：使用混合监督或置信度过滤，并在报告中说明人类演示的非最优性。
  • 把 Oracle 动画当成可得的观测：部署时接口缺失，策略失效。根因：训练期把 5 跳规划动画混入输入通道。修复：动画只允许出现在监督标签与评测上限，不得进入模型输入；导出的测试样本用断言剔除监督字段。

练习与思考

  1. 已知 2,050 段对话切成 7,415 个 NDH 实例，四个折为 4,742 / 382 / 907 / 1,384。验证求和是否闭合，计算平均每段对话的实例数，并解释为什么一段有 3 组问答的对话会产生 4 个实例。 ★
    提示
    4,742 + 382 + 907 + 1,384 = 7,415，闭合。7,415 / 2,050 = 3.617。k 组问答切出 k+1 个实例：第 i 个实例在交换 i 之前决策，另加走完全部历史后的末尾实例。
  2. 五条 NDH 片段数据为 (起点区域距离, 终点区域距离)：G1 (18.0, 15.75)、G2 (12.0, 12.0)、G3 (9.0, 13.5)、G4 (24.0, 18.0)、G5 (15.0, 12.0)，单位米。计算平均 GP 与正向占比，并说明 G3 在训练集中占 20% 时对「只报平均 GP」的解读会造成什么影响。 ★
    提示
    GP 为 +2.25、0、−4.5、+6、+3，平均 1.35 m，正向占比 3/5 = 0.6。平均值掩盖了 20% 的明显远离样本；只报均值会高估策略的一致性，应同时报告负值比例与分布。
  3. 复现「历史长度」消融：分别用仅目标物、最后一组问答、全部历史三种输入训练同一基线。预测三者在未见房测试上的 GP 次序，并结合自我中心指代占 92.5% 这一现象解释原因。 ★★
    提示
    预期次序为全历史 > 最后一组问答 > 仅目标物。自我中心指代需要位姿与语境，只有当前帧不足以消解；更早的问答可能包含区域约束与方向约定，完整历史提供消歧上下文。
  4. 给一个混合监督的改进实验：把「Oracle 终点是否在人类路径上」的二值规则改为连续置信度（例如以人类路径与最短路的重合长度比例作为权重）。写出训练目标的修改点、预期影响与一个可证伪的判据。 ★★
    提示
    把交叉熵前乘置信度 w ∈ [0,1] 再归一化；预期短程准确率上升、长程探索略降。判据示例：若加权训练在未见房的 GP 不低于二值版本且 SPL 类短程指标更高，则改进成立；否则说明加权引入的方差抵消了收益。
  5. 设计一套「对话历史编码接口」的对照实验，比较三种实现：A 拼接纯文本、B 带 NAV/ORA 标记的序列、C 在 B 的基础上再插入交换序号标记。要求：(a) 写出每组的状态接口差异；(b) 给出每组适合检验的假设；(c) 设计一个能区分 B 与 C 的最小数据子集；(d) 分析 C 可能引入的副作用。 ★★★
    提示
    (a) 差异在角色与轮次标记的有无。(b) A 对 B 检验说话人身份的价值；B 对 C 检验长程轮次结构的价值。(c) 取「回答仅为确认词」且更早交换含方向约定的样本，只有保留轮次的编码才能正确指代。(d) 显式轮次标记会拉长序列、加剧长距离依赖，对短对话可能无增益并增加过拟合风险。

小结

  • CVDN 用双角色协议收集 2,050 段人前人对话，覆盖 83 / 90 个场景与 81 类目标物；提示同时具有歧义与信息不足两个性质，起点按聚合距离最大化规则选取。
  • NDH 从对话切出 7,415 个实例（4,742 / 382 / 907 / 1,384），输入目标物加问答历史，输出朝目标区域的动作；历史随交换下标增长，条件从固定文本变为序列。
  • 监督有两条来源：人类路径平均 6.63 跳，规划器路径平均 4.35 跳；混合监督按「Oracle 终点是否在人类路径上」拼接两者，在三个折上均优于单独来源。
  • Goal Progress = 起点区域距离减终点区域距离，可为负；算例平均 1.80 m、正向占比 0.80；测试集上全历史加混合监督为 2.35 m，随机 0.83 m，监督上限 9.76 m。
  • 语言现象以自我中心指代为主（92.5%），需要导航历史的样本占 14%；接口必须保留说话人角色与问答顺序，划分必须以对话为单位防止泄漏。
