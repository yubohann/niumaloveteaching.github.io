第五篇 · 基础模型与 2026 前沿

第 100 讲｜结课：路线图、复现清单与开题建议

全课收束。三份交付物：第一，五篇 100 讲的知识图谱，把任务地基、离散方法、连续与真实平台、规模与泛化、基础模型与 2026 前沿串成一条闭环；第二，按算力分档的复现清单，无卡档做评测与协议复现、单卡档跑通两条方法线的最小版本、多卡档处理数据规模化与跨体态评测，预算锚点采用公开数字（预训练 72 GPU 小时、微调 48 GPU 小时、每集 6.8 万 token 的轻接口与 220.8 万 token 的重接口两档）；第三，10 个开题方向，每个方向给出缺口证据、最小可验证实验与资源档位，并附增量论文的更新指引。

  • 主题：课程地图 / 复现路线 / 开题建议 / 增量更新
  • 关键数字：5 篇乘 20 讲；复现两线（离散预训练、连续拓扑规划）；72 加 48 GPU 小时；68,059 与 2,208,200 token 每集两档接口
  • 预计学时：90 分钟
  • 前置讲：第 099 讲（物理部署鸿沟再审视）

学习目标

  • 会写：用五篇结构复述全课知识图谱，说明每条方法主线的入口讲、代表方法与部署关系。
  • 会算：按算力档位核算复现预算，包括训练样本量、GPU 小时、API token 与每次成功成本。
  • 会实现：复现路线选择器、评测协议登记与指标聚合、最小零样本循环三段示意代码。
  • 会判断：给定个人约束（显卡、时间、目标）选择复现路线，并写出验收判据与失败判据。
  • 会设计：从 10 个开题方向中选择一个，展开为含缺口证据、最小实验、对照设计与资源估算的研究计划。

背景与动机

课程从第 001 讲的 POMDP 定义与五类任务形态开始，先把数据、仿真平台与指标口径立起来；第二篇在离散导航图上走完从 Seq2Seq 到预训练与记忆地图的完整谱系；第三篇把三条隐含假设逐条放松，进入连续环境、真实平台与室外空中域；第四篇处理规模、记忆与泛化方法论；第五篇接入基础模型，并以 2026 快照收尾。走过全程之后，问题已经从「还有哪些方法没读」转为「先复现什么、用什么算力、从哪里切入研究」。

本讲面向三种读者给出三条读法。研究者线重读第 4、5 篇，从记忆范式、偏差诊断与 2026 快照中选题；工程线重读第 1、3、5 篇，把评测协议、执行效率与部署清单落成验收流程；开题线速览第 1 篇后精读第 4、5 篇，直接使用本讲的 10 个方向。三条读法共享同一份复现纪律：先评测、后训练、再扩展，任何一步的成果都必须挂回协议四元组（基准、成功半径、动作空间、split 与版本）。

最后交代边界：本课写到「方案加复现指南」级，不承诺替读者完成真机实验；2026 快照章的数字会随时间过时，本讲末尾给出自行检索增量的指引。第 099 讲的检查表 v2 与本讲的复现清单配套使用：前者判断一个系统能否部署，后者判断一项能力能否在给定资源内复现。

2. 三条主线与三对张力

评测与协议线从 NE / SR / SPL 出发，经过连续环境的停止判定与步数上限、R2R-CE 与 RxR-CE 的 val 集错事实、系统级运行的协议登记，最后落到检查表 v2 的可比四元组。这条线是全课的公共语言，任何实验结论都必须挂在它上面。方法线从离散图上的序列建模出发，经过预训练与记忆地图，进入连续环境的规划与执行，再进入数据规模、基础模型与多任务统一；每一代方法解决的问题都能在前一代的失效模式里找到出处。部署与成本线从执行效率与真机迁移出发，经过物理体态评测，最后加上接口成本账；它的作用是给前两条线加上现实约束。

3. 复现清单：按算力分三档

复现目标是课程开始时的承诺：独立跑通评测并正确解读指标；复现两条方法线（离散预训练类与连续拓扑规划类）的最小版本。三档任务按依赖顺序排列，上一档的产物是下一档的输入。

档位目标任务数据与产物预算锚点（来源）
无卡（CPU 与 API）把测量装置建起来实现 NE / SR / SPL / OSR / CLS 并跑通 R2R val-unseen；复算 val 集标注错误（R2R-CE 8 条、RxR-CE 10 条）；搭最小零样本循环；协议登记与聚合指标报告、错误清单、协议登记表、提示词版本记录轻接口每集 68,059 token，重接口每集 2,208,200 token（第 098、093 讲）

预算做一次实算核对：单卡档若按第 061 讲的微调配方（48 GPU 小时）执行，折算约 2.0 个 24 小时周期；预训练配方 72 GPU 小时在双卡上约 36 小时墙钟。数据生成成本另计，1,291 个场景的建图、渲染、图像修复与 494 万条指令生成不在上述小时数内，按场景数线性估算。API 档的账要按「每次成功」看：轻接口每集 6.8 万 token，1,000 集约 6,810 万 token；重接口每集 220.8 万，100 集约 2.21 亿 token，成本随协议差异可达两个数量级。

设计决策：为什么复现顺序是评测、单卡方法、规模与体态

三条理由。第一，评测装置的复用率最高：指标、协议与数据审计的代码被后续所有实验复用，且无需训练卡。第二，两条方法线的最小版本（离散预训练类与连续拓扑规划类）在单卡可完成，它们建立对失效模式的直觉，例如曝光偏差、停止判定与执行误差，缺了这一步直接上大模型会把协议错误误读为方法缺陷。第三，规模与体态任务的成本最高且依赖前两档的数据接口与评测代码，放在最后可以避免在错误的口径上放大实验。判据是「单位算力换取的认知增量」：评测档最高，规模档最低但不可替代。

5. 增量更新指引

2026 快照章（093 至 098）有生命周期。自行检索增量时按四步执行：第一步定范围，关注 arXiv 的 cs.RO、cs.CV 与 cs.CL 分类，关键词组合为 VLN、vision-and-language navigation、R2R-CE、RxR-CE、continuous environment、aerial VLN、traversability、zero-shot navigation、agentic navigation；第二步核协议，对每条新结果记录四元组与运行次数，只有四元组一致的数字才允许进入对比表；第三步核版本，优先采纳有 v2 以上修订或已被会议接收的版本，记录检索日与版本号；第四步回归本课，判断新工作落在哪一层的缺口上（第 099 讲的地图 v2 六组），把新数字填入差距账模板。

6. 边界与失效模式

  • 本课不替读者完成真机实验：真机内容写到方案与复现指南级，验收与安全责任在部署方。
  • 算力锚点是公开数字的迁移：72 与 48 GPU 小时来自 A100 级设备与特定配方，换硬件与实现需重新测；本课不给超规模配方。
  • 快照有时效：2026 数字冻结在检索日 2026-10-01，服务端模型与论文版本都会漂移，复现前重录。
  • 十个方向是起点：每个方向的最小实验只验证机制是否存在，能否形成结论取决于对照设计与样本量。
  • 课程覆盖的缺口：多机器人协同、社交合规、可穿戴与人机交互评测在课内只到接口级；硬件与能耗评测未展开。

实现思路与设计

把结课内容落成个人执行计划，需要三份材料：路线图模板、复现验收表与评测纪律清单。

个人路线图模板（六个月版本）

  1. 第 0 至 1 月，测量装置：完成指标实现与 R2R val-unseen 评测，复现标注审计，产出协议登记表。验收判据：指标复算与论文口径误差在 0.5 个百分点以内；未通过时先修评测代码再进入下一阶段。
  2. 第 1 至 3 月，两条方法线：离散线训练到超过论文复现基线；连续线完成迁移数据上的训练与 DAgger，报告 SR、SPL、NE 与 OS−SR。验收判据：两条线的消融至少各完成三组；失败判据：两条线都低于基线的 80% 时排查数据接口与评测口径，不继续加模型。
  3. 第 3 至 6 月，选题与扩展：从 10 个方向选一个，按最小实验完成首轮对照，产出可复现实验报告。验收判据：对照效应大于两倍运行标准差；未达到时扩大样本量或更换方向。

  • 可比四元组（基准、成功半径、动作空间、split 与版本）随每条数字记录；跨半径比较改用 NE 或重算。
  • val-seen 与 val-unseen 并列报告；模型选择只用 val，test 结果以服务器或冻结次运行报告。
  • 停止规则固定并写入配置；OS 与 SR 成对报告。
  • 随机种子、运行次数与标准差成组记录；单次运行的结果不得用于排名。
  • 标注清理前后双报；跨版本重放固定轨迹集。
设计决策：开题为什么从「最小可验证实验」写起

十个方向覆盖的机制跨度很大，直接写完整研究计划容易停在概念层。最小可验证实验的作用是把方向压缩成一个能在两周到一个月内闭合的实验：固定什么、变什么、看什么指标、判据是什么。例如方向 5（记忆生命周期）的最小实验只需要一个场景集合、三种记忆策略与三次顺序打乱，产出顺序敏感性与 SR 差值两个数；这两个数一旦得到，是否扩大实验规模就有依据。判据是「实验能否回答一个二值问题」，不能则继续拆。

关键代码与解读

三段代码分别给出复现路线选择器、协议登记与指标聚合、最小零样本循环。示意实现，接口按公开设计重写。

片段 1：复现路线选择器

ANCHORS = {   # 公开预算锚点，来源注明讲次
    "finetune_gpu_h": 48,          # 第 061 讲：单卡微调
    "pretrain_gpu_h": 72,          # 第 061 讲：双卡预训练
    "light_tokens_per_ep": 68059,  # 第 098 讲：技能级接口
    "heavy_tokens_per_ep": 2208200 # 第 093 讲：系统级接口
}

def choose_track(vram_gb, n_gpus, api_token_budget, weeks):
    """按约束返回建议路线与首要产物，约束不足时给出替代项。"""
    tracks = []
    if api_token_budget >= 100 * ANCHORS["light_tokens_per_ep"]:
        tracks.append(("api_zero_shot", "协议登记表与零样本报告，无需本地训练卡"))
    if n_gpus >= 1 and vram_gb >= 16:
        tracks.append(("single_gpu_lines", "两条方法线最小版本与消融表"))
    if n_gpus >= 2 and vram_gb >= 40:
        tracks.append(("multi_gpu_scale", "规模预训练或跨体态评测"))
    hours = weeks * 7 * 24
    budget = n_gpus * hours
    plan = {"weeks": weeks, "gpu_hours_available": budget, "tracks": tracks}
    if budget < ANCHORS["finetune_gpu_h"]:
        plan["note"] = "GPU 小时不足单卡微调锚点，先执行无卡档或减少轮数"
    return plan

print(choose_track(24, 1, 5e7, 6))

解读：（1）锚点以常量集中存放并标注讲次，预算变化时只改一处；选择器不做性能预测，只做可行性筛选，避免把工程估计写成结论。（2）API 档的判断用「轻接口乘 100 集」作下限，重接口方案自动被筛出，防止用轻接口预算启动重接口实验。（3）返回结构中包含可用的 GPU 小时数与提示，便于把「算力不足」与「方向不成立」区分开；提示文案对应设计决策里的失败判据。

片段 2：协议登记与指标聚合

import math

def register(benchmark, radius_m, action_space, split, version, runs):
    """登记一次评测；runs 为逐条 episode 的结果记录。"""
    return {"benchmark": benchmark, "radius_m": radius_m,
            "action_space": action_space, "split": split,
            "version": version, "runs": runs}

def aggregate(rec, success_radius_m=None):
    """聚合 SR / OSR / NE / SPL；未提供半径时以登记值重算成功。"""
    r = rec["radius_m"] if success_radius_m is None else success_radius_m
    n = len(rec["runs"])
    sr = sum(1 for x in rec["runs"] if x["ne"] < r) / n
    osr = sum(1 for x in rec["runs"] if x["min_dist"] < r) / n
    ne = sum(x["ne"] for x in rec["runs"]) / n
    spl = 0.0
    for x in rec["runs"]:
        if x["ne"] < r:
            spl += x["ref_len"] / max(x["ref_len"], x["traj_len"])
    spl /= n
    return {"SR": round(100 * sr, 2), "OSR": round(100 * osr, 2),
            "NE": round(ne, 3), "SPL": round(100 * spl, 2),
            "OS-SR_gap": round(100 * (osr - sr), 2), "n": n}

rec = register("r2r_ce", 3.0, "low_level", "val_unseen", "2020",
               [{"ne": 2.1, "min_dist": 1.8, "ref_len": 9.0, "traj_len": 10.0},
                {"ne": 4.5, "min_dist": 2.9, "ref_len": 8.0, "traj_len": 8.0}])
print(aggregate(rec))   # SR 50.0, OSR 100.0, NE 3.3, SPL 45.0, OS-SR 50.0

解读：（1）登记与聚合分离：协议字段随结果入库，聚合函数只读登记值，杜绝「同一条轨迹在两套半径下各报一次」的口径漂移。（2）OS−SR 缺口在聚合层直接产出，与第 099 讲的停止监控对接；SPL 只对成功 episode 累计路径效率，失败记 0，与标准口径一致。（3）重算半径只需传入参数，可用于「换半径后结论是否翻转」的敏感性分析，输出保留整数条数与两位小数，满足可追溯性。

片段 3：最小零样本循环（无卡档入口）

def zero_shot_episode(env, model, prompt_builder, max_steps=500):
    """最小零样本循环：观察、提示、解析、执行、记账。"""
    obs, info = env.reset()
    history, tokens = [], 0
    for step in range(max_steps):
        prompt = prompt_builder(obs, history)          # 历史与当前观测入提示
        reply, used = model.chat(prompt)               # 一次调用，返回文本与用量
        tokens += used["input"] + used["output"]
        action = parse_action(reply)                   # 白名单解析，拒绝非法输出
        history.append((action, used))
        obs, done, info = env.step(action)             # 0.25 米 / 15 度 / STOP
        if done:
            break
    return {"ne": info["distance_to_goal"],
            "min_dist": info["closest_goal_dist"],
            "steps": step + 1, "tokens": tokens,
            "traj_len": info["trajectory_length"]}

# 预算核对：100 条 episode 乘每集 68,059 token 约 6.8M token
print(100 * 68059)

解读：（1）解析动作走白名单，非法输出不执行并计入失败，避免把接口错误混入模型能力统计；第 093 讲的行为分解（接受 STOP 与预算终点）可以在这段循环上加两个计数器得到。（2）token 在循环内累计并随 episode 返回，是成本账的最小实现；与片段 1 的锚点相乘即可得到批量实验预算。（3）返回最近距离与终点距离两个量，OS 与 SR 可在离线聚合中同时得到，不需要重跑；这一结构让无卡档也能产出与论文对齐的完整指标。

常见坑

  • 从训练大模型开始：跳过评测装置直接复现预训练，结果异常时无法区分数据、实现与口径问题。根因是低估测量装置的复用价值。修复：按复现清单从无卡档开始，指标误差小于 0.5 个百分点后再训练。
  • 单次运行下结论：不做重复与方差，把 1 至 2 个百分点的差异当作改进。根因是忽略系统级评测 1.5 至 3.5 点的运行标准差（第 093 讲）。修复：同一配置至少三次运行，效应小于两倍标准差时写「差异不显著」。
  • 协议四元组缺项：只记录模型名与成功率，缺半径、动作空间或 split。根因是把评测当模型属性。修复：使用片段 2 的登记结构，缺项运行拒绝进入聚合。
  • 成本不计入复现计划：用轻接口预算启动重接口实验，或在数据生成阶段耗尽算力。根因是只核算训练小时。修复：按第 061 讲的「生成与训练」两栏预算，API 实验按每次成功折算并设上限。
  • 把快照数字当长期结论：直接引用 2026 数字而不记录检索日与版本。根因是忽略模型服务端漂移与论文修订。修复：引用时带版本号与检索日；复现前重跑三次方差，必要时替换为更新版本。

练习与思考

  1. 预算核算：某团队用轻接口（每集 68,059 token）做 3 次重复、每次 100 集的零样本评测；另一团队用重接口（每集 2,208,200 token）做 1 次 50 集评测。分别计算总 token，并说明为什么两组结果的「信息量」不能只按 token 比较。 ★
    提示
    轻接口 3×100×68,059 = 20,417,700 token；重接口 50×2,208,200 = 110,410,000 token。重接口消耗约 5.4 倍，但只有单次运行且样本 50 条；重复次数与样本量决定统计功效，不随 token 线性增加。
  2. 协议审计：判断下列三句话各自属于「同协议可比」「近似可比」还是「不可比」：(a) 同一基准同一 split 下两个模型的 SR 差 3 点，各三次运行；(b) 同基准同 split 但一个是 v0.2 数据一个是 v0.1 数据；(c) 20 米半径的 9.2 与 3 米半径的 38.6。 ★
    提示
    (a) 同协议可比，但 3 点是否显著要看合并标准差；(b) 近似可比，需重放固定轨迹集；(c) 不可比，半径相差 6.67 倍且任务族不同。
