第五篇 · 基础模型与 2026 前沿

第 093 讲｜2026 快照 I：通用模型零样本系统评测

本讲是 2026 快照第一篇：通用大模型开始直接充当导航系统，评测单位从「方法」变成「系统」，数字随之被交互载体、episode 子集、动作预算与运行口径重新塑形。三篇来源已在 arXiv 逐一核实（检索日 2026-10-01）：Dai、Sun、Wu、Zhu 2026（arXiv:2609.29861v2）用 Codex harness 最小接口在 R2R-CE-100 达到 75.7 与 81.3 SR（medium 与 ultra，三次运行均值）；Dai、Wu、Zhu 2026（arXiv:2609.20116v2）用直接 API 四角色工作流在 Open-Nav 同池前 50 条上得到 52.0 SR / 48.9 SPL，且只有 36.0% 的局面以「被接受 STOP」成功；Zhou 等 2026（arXiv:2607.26148v3）在 rand100 上让编程代理 harness 直接控制动作，opus-5 为 70.7±3.5 SR，fable-5 最高 78 SR，混合路点接口 76.7±0.6 SR。同一模型家族的数字跨度 29.3 个百分点，全部来自协议。学完能填写系统评测维度表并审计任意一条系统级主张。

  • 主题：零样本系统评测 / harness / episode 子集 / 动作预算 / 运行重复性 / 零样本语义
  • 关键数字：81.3 与 52.0 与 70.7±3.5；+15.3 / +9.2 个百分点；36.0% + 16.0%；协议跨度 29.3
  • 预计学时：70 分钟
  • 前置讲：第 092 讲（AO-Planner：affordance 低层规划）

学习目标

  • 会解释：同一模型家族在 R2R-CE 上出现 81.3、78、70.7、52.0 四个量级不同的数字，分别由哪些协议项造成。
  • 会算：从 SR 与对照数字反推「最强已报零样本」与「最强训练法」的读数，核对 18 / 8 的 STOP 与预算终点分解，并计算运行内标准差。
  • 会实现：协议登记与聚合、最小接口动作预算、重复运行稳定性分类三段示意代码。
  • 会判断：一条系统级主张是否可引用，属于同协议可比、近似可比或不可比，并给出降级写法。
  • 会设计：覆盖 13 项的系统评测维度表与一次固定模型、episode 池、harness、预算的重跑方案。

背景与动机

第 082 到第 092 讲讨论的对象是方法：NavGPT 的提示循环、MapGPT 的语言地图、NaVid 的视频策略、AO-Planner 的两阶段规划。方法级评测的公共语言相对成熟：R2R-CE 与 RxR-CE 有规定的 split、动作空间与 3 米成功半径，第 079 讲还给出十二项公平报告清单。2026 年出现的新对象超出了这套语言：通用大模型带着自己的会话框架（harness）直接进入环境，模型决定何时观察、移动与停止，外围代码只负责执行与记账。此时一次运行的结果由四层共同决定：模型权重、harness 交互方式、工具与观测接口、episode 与预算配置。只报告模型名与一个 SR，信息量已经不够。

三篇来源恰好构成一组对照实验。两篇同一模型家族的报告（arXiv:2609.29861v2 与 arXiv:2609.20116v2）在同一个 100 条 episode 池上工作，却给出 81.3 与 52.0 两个 SR；第三篇（arXiv:2607.26148v3）系统性交换模型、harness 与接口，证明在最小接口固定时，仅更换模型就能把 SR 从 5 拉到 72。数字的巨大差异并不神秘，它来自可枚举的协议项，本讲的任务就是把这些项枚举清楚。

本讲的产出是一张系统评测维度表与一套审计流程：任何一条「某模型在 R2R-CE 上达到 X%」的主张，先按表填协议，再做可比性判定，最后决定是引用、降级还是重跑。第 094 讲会在同一框架下补充「不确定性」这一长期缺位的维度。

核心原理

本节按「三种系统组织、数字核对、不可比证明、行为证据、成本与延迟、零样本语义、边界」七步展开；所有引用数字标注 arXiv 版本、episode 池与预算。

1. 三种系统组织与接口

第一篇（Dai、Sun、Wu、Zhu 2026，R2R-CE-100 零样本评测）把 GPT-6-Astra 放进 Codex harness 的持续会话：模型通过模型上下文协议（Model Context Protocol, MCP）调用两个工具，observe() 返回一帧 512×512 单目 RGB 且不消耗动作步，step(actions) 执行有序动作串（0.25 米前进、15° 左右转、30° 俯仰、STOP）并返回执行计数与剩余预算；每集 500 个原子动作与 2,400 秒时限，环境地图、参考轨迹、目标坐标、全局位姿与深度都不通过接口暴露。第二篇（Dai、Wu、Zhu 2026）放弃现成 harness，用直接 API 搭外部工作流：GPT-6-Astra 扮演四个提示角色（任务规划、进度评估、动作提议、到达评估），外围代码负责挑选上下文、保留历史与判断、施加动作约束与 STOP 校验；初始给出 12 个朝向的环视，之后观测为正面 RGB-D，每集预算 100 步，推理强度 medium，单次运行。第三篇（Zhou 等 2026，R2R-CE rand100 最小接口代理研究）把同一极简接口接进三个编程代理 harness（mini-swe-agent、Claude Agent SDK、Codex CLI），每集 500 步预算，无位姿、无深度、无地图、无路点、无碰撞反馈，模型只靠单目 RGB 与交互历史决定观察、移动、恢复与停止；该文把这种组织命名为代理式具身控制（agentic embodied control）。

2. 数字逐一核对

先核对第一篇的内部一致性。其 ultra 设置报告 81.3±2.5 SR，来自三次运行的 79、81、84 个成功。实算：均值 81.33，样本标准差 2.52，与报告的 81.3±2.5 吻合；三次合计 244 条成功轨迹，与文中「244 successful trajectories」一致。medium 设置 75.7±1.5 SR / 65.6±2.1 SPL；ultra 设置 81.3±2.5 SR / 71.5±1.7 SPL，OSR 83.7±1.5、NE 2.9±0.2 米。论文用「未取整数值」计算 medium 到 ultra 的差为 5.7 与 5.9 个百分点，本讲按展示值复算为 5.6 与 5.9，差异来自取整，引用时以论文口径为准。摘要的 +15.3 与 +9.2 个百分点按 81.3 减对照读数得到：最强已报零样本为 66.0，最强训练法为 72.1（后者为全量 val-unseen 的 Qwen-RobotNav-8B，两者分属不同 cohort，论文自述比较严格性有限，只用于帮助定位竞争力）。失败谱的核查同样重要：六次评测（medium 三次加 ultra 三次）里，62 个任务全部成功、8 个全部失败、30 个胜负混合，三者合计 100。

第二篇（50 条子集）的 52.0 SR 分解为 26 条成功轨迹：其中 18 条以「工作流接受的 STOP」结束（36.0%），另有 8 条在预算耗尽时终点已落在 3 米内（16.0%）。其余分解：被接受 STOP 但有 3 条未达距离标准（EP7、EP371、EP377，NE 分别 3.04、3.37、4.07 米），预算耗尽且失败 21 条。OSR 62.0 与 SR 52.0 相差 10 个百分点，对应 31 条轨迹至少一次进入成功邻域、26 条最终停在邻域内。工作量侧：4,040 个执行步、每集平均 80.8 步与 8.97 米位移、2,182 次旋转占动作计数 54.0%、9,208 次模型生成（每执行步约 2.28 次）、累计输入 1.1041 亿 token、累计生成延迟 22.55 小时。

第三篇的数字结构最接近因子实验：模型轴从 5 到 72 SR（同接口、同预算，仅换模型），harness 轴差距 2 到 7 个 SR 点，推理强度轴的增益为 fable-5 +9.7、opus-5 +3.3 个点。默认档下 opus-5 复跑三次为 70.7±3.5（标准差 3.5），fable-5 为 68.3±1.5；fable-5 最高档 78 SR / 65.27 SPL；把训练好的路点模块与原子动作并排暴露为可选工具后，fable-5 默认档达到 76.7±0.6 SR，每集中位步数从 87 降到 48、中位耗时从 210 秒降到 112 秒，相对最高档 484 秒的耗时比值为 0.231。同一 rand100 赛道上，人类测跑者为 94 SR / 80.80 SPL，最强模型配置与其相差 16 个 SR 点与 15.53 个 SPL 点。核对这些数字时，均值、样本标准差、运行次数与对照 split 必须成组引用；单独摘出 81.3 或 78 会丢掉至少一半信息。

3. 不可比证明：为什么 81.3 与 52.0 不能相减

先列出两篇之间可枚举的协议差：交互载体（Codex harness 持续会话对四角色外部工作流）、动作预算（500 对 100）、推理强度（ultra 对 medium）、episode 数（100 对同一池前 50 条）、观测（单目 RGB 对初始环视加正面 RGB-D）、运行次数（3 次均值对单次）。其中任何一项都足以改变 SR 的含义：100 步预算下，16 个百分点的成功来自预算耗尽时的距离判定，若把预算放宽到 500 步，这批局面中的一部分可能转为常规成功，也可能因新增动作引入新失败；ultra 与 medium 在同一 harness 内的差已达 5.6 个点；观测与上下文管理方式改变的是模型可见证据本身。因此 81.3 与 52.0 的差 29.3 个百分点只能记为「协议跨度」，不能归给模型能力。作为参照，同一协议内的三次运行标准差为 1.5 到 3.5 个点，协议跨度约为运行噪声的 8 到 20 倍，这个倍数关系才是「协议主导」的量化表述。

第三篇与两篇 GPT-6-Astra 报告之间同样不可直接排名：rand100 与 Open-Nav 100 条是否同一集合，第三篇没有声明逐条对应关系（两篇 GPT-6-Astra 报告的池来源一致）；harness 型号与版本（mini-swe-agent v2.4.5、Claude Agent SDK v0.2.110、Codex CLI v0.142.0 至 0.145.0）也参与结果。可做的只有两件事：把每行按维度表填满后并排展示；或者在固定模型、池、预算与运行的条件下重跑对照。本讲第三节后给出后者的方案骨架。

4. 行为证据与失败结构

系统级数字之外，三篇都提供了失败结构。第一篇用「六次评测的每任务成功计数」把失败分成三类：8 个任务在 medium 与 ultra 下反复失败（例如 EP1133，最终 NE 在 5.6 到 12.3 米之间波动，从未进入 3 米），30 个任务结果混合，说明单次轨迹不足以判断能力。第二篇沿「理解与执行分离」审计：终点判定的类别识别证据覆盖 50 条中的 33 条，关系落点 23 条，实例对应 18 条；时间判断的证据覆盖率分别为 84.9%（事件时点）、82.0%（顺序约束）、46.2%（事件连续性）；66 个「问题处理」审计过程中 36 个带来局部缓解、75 个「验证」过程中 48 个以证据消解了不确定判断。典型失败模式是「判断正确但动作没跟上」：识别出未完成的穿越，旋转却持续进行；或到达邻域后没有触发被接受的 STOP。第三篇对最强配置三次复跑中一次运行的 30 个失败做分类：错误参照或分支 12 个、停止决策 7 个、失控搜索 8 个、几何与仿真陷阱 3 个，中位最终距离在错误参照类达到 17.3 米。长程压力测试给出上限：同一模型、harness 与预算下，原子接口的 SR 从 R2R-CE 的 70 掉到 RxR-CE 的 26，路点接口为 69 与 39。

把这三套失败结构并排看，共同的薄弱环节集中在「执行闭环」：进度跟踪、无效动作识别、到达验证与停止决策；这些环节恰好是第 094 讲不确定性工具的用武之地。

5. 成本、上下文与延迟

系统评测必须带资源账。第二篇报告累计输入 1.1041 亿 token 与 324 万输出 token，累计生成延迟 22.55 小时（这组数字的边界是：缓存折扣与账单未记录，进度交接与到达评审两类调用合计占输入 token 的 80.2%）。第三篇报告最小循环每次调用都重发完整观测历史，R2R-CE 原子接口配置的末轮上下文中位数为 2.2 万 token，RxR-CE 为 4.9 万；跨配置峰值达到 16.9 万；4,700 个记录 episode 的中位墙钟时间为 206 秒，18.6% 的运行超过十分钟。这些量级说明：无状态重发的循环在长程下不可持续，上下文管理与记忆压缩将成为下一阶段的必备组件（第 096 讲展开）。成本一侧还要记接口差异：观察调用是否消耗动作预算、旋转是否计入步数、终止 STOP 是否占一步，都会改变「预算」的实际含义。

6. 零样本语义与边界

第一篇在结论部分主动声明：此处的零样本指「未针对导航微调」，不表示模型训练期从未见过导航数据；训练数据不可得，无法核查。第二篇同样声明其子集并未对所有工作流开发过程保持完全留出。这提醒我们，「零样本」在系统评测里至少有三种强弱不同的含义：未做导航微调（最弱）、未用导航数据构建提示与工作流（中等）、评测池对全部开发过程不可见（最强）。引用时必须写明是哪一种，本课程后续把第一类一律写作「未微调零样本」。

其他边界：三篇的评测都集中在室内 R2R-CE（外加摘要级提到的 RxR-CE 长程压力），室外、空中与社交场景外推有限；开放模型权重不公开时，复现只能达到「同接口复测」级别；harness 与模型版本按月更新，本讲数字只对检索日的 arXiv 版本负责，增量检索方法见第 100 讲更新指引。

实现思路与设计

把审计做成流程需要三件东西：一张 13 项维度表、一个可比性三级判定器、一份重跑方案模板。目标与第 079 讲一致：让「可信引用」成为流程输出，减少写作阶段的即兴比较。

可比性判定与报告规范

级别条件写法
同协议可比模型不同，其余 12 项全同或差异与结论无关允许排名与差值，附运行方差
近似可比仅推理强度、辅助模块或运行次数不同并排展示，标注差异项，不做排名

用三篇来源做三个判定。其一，81.3 与 52.0：池来源相同但子集规模、预算、强度、观测、载体五项不同，判不可比，只能分表。其二，opus-5 70.7 与 fable-5 68.3：同 harness、同池、同预算、同接口，差异只在模型，模型不同且各自运行方差 3.5 与 1.5，判同协议可比但差值落在噪声边缘，结论应写「差异不显著」。其三，fable-5 默认 68.3 与最高档 78：同协议下仅推理强度不同，判近似可比，差值 9.7 个点大于自身标准差 1.5，可记为强度的贡献。

重跑方案骨架

  1. 固定：模型快照与推理强度、episode 池（全部 100 条）、观测接口、动作预算、成功判定与运行次数（不少于 3 次）。
  2. 交换：仅交互载体一个因子（harness 对直接 API 工作流），其余不变。
  3. 报告：SR / SPL / NE / OSR 与「被接受 STOP 成功率」「预算终点成功率」两个派生量，均给均值 ± 样本标准差。
  4. 审计：对每次运行的失败做四类分类（参照、停止、搜索、几何），核对分布是否随载体变化。
  5. 记账：token、调用数、会话时长按第 13 项记录，缓存口径单列。

与相邻讲的分工：第 079 讲面向方法级论文的协议元组，本讲面向系统级运行；第 094 讲补充不确定性维度（覆盖率、按需计算、求助）；第 096 讲处理记忆与闭环纠错；第 099 讲把系统数字翻译成部署清单。

关键代码与解读

三段代码分别给出协议登记与聚合、最小接口的动作预算管理、重复运行的稳定性分类。示意实现，接口按三篇论文的公开描述重写，可直接接入评测脚本。

片段 1：协议登记与跨运行聚合

from dataclasses import dataclass, field
import statistics as st

@dataclass
class SystemRun:
    model: str                  # 模型快照名
    effort: str                 # 推理强度档位
    harness: str                # 交互载体名称与版本
    obs: str                    # mono_rgb / front_rgbd
    subset: str                 # on100 / on100_first50 / rand100
    version: str                # 数据版本，例如 R2R_VLNCE_v1-3
    budget: int                 # 动作预算
    stop_rule: str              # 停止与成功判定口径
    outcomes: list = field(default_factory=list)   # 每集成功标记

    def sr(self):
        return 100.0 * sum(self.outcomes) / len(self.outcomes)

def aggregate(runs):
    """同一配置的多次运行：报均值与样本标准差，低方差才允许比较。"""
    vals = [r.sr() for r in runs]
    if len(vals) == 1:
        return {"sr_mean": round(vals[0], 1), "sr_sd": None,
                "n_runs": 1, "note": "single run"}
    return {"sr_mean": round(st.mean(vals), 1),
            "sr_sd": round(st.stdev(vals), 1),
            "n_runs": len(vals)}

解读：（1）每条运行记录携带完整的 13 项字段，缺项的运行直接拒绝进入聚合，避免「只记模型名再比较」的流程性失误。（2）单次运行返回 note 标记，下游报告器据此禁止输出排名结论。（3）均值与样本标准差成对返回，刻意不提供「只看 SR」的接口。

片段 2：最小接口的预算与执行回执

class MinimalInterface:
    """最小接口：只暴露 observe 与 step；预算与回执由接口维护。"""
    def __init__(self, env, budget=500, fwd=0.25, turn=15.0):
        self.env = env
        self.budget = budget          # 动作预算，按论文设定传入
        self.fwd, self.turn = fwd, turn
        self.used = 0                 # 已消耗动作计数
        self.stopped = False          # 是否已发出 STOP

    def observe(self):
        return self.env.render_rgb()  # 观察不消耗动作预算

    def step(self, actions):
        executed = 0
        for a in actions:
            if self.used >= self.budget or self.stopped:
                break                 # 预算或终止状态先于动作检查
            if a == "FORWARD":
                self.env.move_forward(self.fwd)
            elif a in ("LEFT", "RIGHT"):
                self.env.rotate(self.turn if a == "LEFT" else -self.turn)
            elif a == "STOP":
                self.stopped = True   # STOP 占用一个动作位
            self.used += 1
            executed += 1
        return {"executed": executed, "remaining": self.budget - self.used,
                "done": self.stopped or self.used >= self.budget}

解读：（1）observe 与 step 分离，观察不计预算，这直接决定「500 步」实验的实际交互成本；对照系统若把观察计入步数，两个 500 步不可同日而语。（2）STOP 占用一个动作位并置位终止标记，返回结构里同时给出剩余预算与完成状态，方便把「被接受 STOP」与「预算耗尽」分开统计。（3）批量动作串在执行前统一检查预算，避免中途超支；回执不含图像与碰撞信号，迫使模型再次 observe 取得新观测，这一约束是「最小接口」的核心。

片段 3：重复运行的稳定性分类

def classify_tasks(run_outcomes, n_evals):
    """run_outcomes: 任务号到各次评测成功标记列表；按全成/全败/混合分类。"""
    stable_success, stable_fail, mixed = [], [], []
    for task_id, marks in run_outcomes.items():
        n_ok = sum(marks)
        if n_ok == n_evals:
            stable_success.append(task_id)      # 所有评测都成功
        elif n_ok == 0:
            stable_fail.append(task_id)         # 所有评测都失败
        else:
            mixed.append((task_id, n_ok))       # 混合结果，单次对比不可靠
    total = len(run_outcomes)
    return {"stable_success": len(stable_success),
            "stable_fail": len(stable_fail), "mixed": len(mixed),
            "fail_ratio": round(100.0 * len(stable_fail) / total, 1)}
# 29861 六次评测（medium 三次 + ultra 三次）：62 全成、8 全败、30 混合

解读：（1）把评测维度从「每次运行的 SR」提升到「每任务跨运行的稳定类别」，8 个全败任务才是系统能力的真实缺口，30 个混合任务提示运行间波动不可忽略。（2）输出直接是计数与比例，便于与「62 / 8 / 30」这类原文结构对齐核对。（3）同一函数可复用到任意重复评测表，只要传入每任务的成功标记列表。

常见坑

  • 拿 81.3 与训练法 72.1 直接排名：得出「通用模型已超越全部训练导航器」的结论。根因是 split 与观测不同：81.3 来自 100 条子集、单目，72.1 来自全量 1,839 条、全景。修复：按维度表分表，引用论文自己的说明（帮助定位竞争力，不构成同条件证据）。
  • 把「零样本」理解为训练期未见过导航数据：对模型能力做出无法核查的推断。根因是术语滑移。修复：用三档写法标注（未微调 / 未用导航数据构建工作流 / 开发全程留出），闭源模型只能主张第一档。
  • 忽略动作预算差异：把 500 步系统与 100 步系统的 SR 并列。根因是「步」的语义在不同 harness 下不同（观察是否计步、STOP 是否计步、批量动作串如何计步）。修复：维度表第 7 项记录预算与计数规则，必要时按步数归一化曲线报告。
  • 把单次运行的小数点当精确值：52.0 SR 来自单次执行与固定种子配置，重复试验与消融都未做。根因是把执行当测量。修复：标注「单次执行」；需要结论时至少三次复跑并给样本标准差，差值小于噪声时写「差异不显著」。
  • 忽略 episode 池重叠与数据版本：将 Open-Nav 100 条、其前 50 条与 rand100 当作同一集合。根因是池来源描述缺失。修复：记录池来源、条数、场景数与数据版本（含航向勘误），对「未验证同一集合」的池（如 S-100）单独标注。

练习与思考

  1. 数字反推：81.3 比最强已报零样本高 15.3 个百分点、比最强训练法高 9.2 个百分点，反推两个对照读数；第二篇 50 条子集里 52.0 SR 对应多少条成功，其中被接受 STOP 与预算终点各多少条？ ★
    提示
    对照读数为 66.0 与 72.1；52.0% × 50 = 26 条，其中 18 条被接受 STOP（36.0%）、8 条预算终点（16.0%）。另可验证 79+81+84 的均值 81.33、样本标准差 2.52，与 81.3±2.5 一致。
  2. 协议跨度与噪声：81.3 与 52.0 相差 29.3 个百分点；同协议三次运行的标准差为 1.5 至 3.5。求协议跨度相对运行噪声的倍数区间；若要把两篇放到同一张表，需要统一的最小因子集合有哪些？ ★
    提示
    29.3 / 3.5 ≈ 8.4，29.3 / 1.5 ≈ 19.5。最小统一集合至少含 episode 池与条数、动作预算与时限、观测模态、推理强度、运行次数；交互载体是否统一取决于研究问题。
  3. 改配置预测：把第二篇的 100 步预算放宽到 500 步，预测 SR 的变化方向与依据；再预测「被接受 STOP 成功率」会上升还是下降，说明两条预测各自的推理链与不确定处。 ★★
    提示
    SR 方向不确定偏正面：预算终点成功中的 8 条有转正空间，但更长轨迹引入新的迷路与停止失误。被接受 STOP 比例可能下降：步数增加不改变模型判定质量，分布会向预算终点一侧移动。结论应写成带条件的预测并设计三臂实验（100 / 300 / 500 步各三次运行）。
  4. 效率核算：混合接口相比原子接口默认档，每集中位步数 87 降到 48、耗时 210 秒降到 112 秒；最高档原子接口耗时为 484 秒。计算两个比值，说明为什么「一半步数」与「四分之一时间」采用不同比较基准。 ★★
    提示
    48/87 ≈ 0.55；112/484 ≈ 0.231。步数比值相对默认档，时间比值相对最高档：混合接口的卖点是「接近最高档成绩、远低于最高档成本」，因此时间基准取 484 秒；若统一相对默认档，时间比为 112/210 ≈ 0.53。
  5. 设计题：设计一次「harness 效应」的三因子评测。要求 (a) 固定项与交换项的清单；(b) 三种 harness 与两档推理强度的组合数与每种运行次数；(c) 主指标与派生指标；(d) 如何用运行方差决定哪些差值可以写「显著」；(e) 列出两条会被审稿人追问的遗漏。 ★★★
    提示
    (a) 固定模型快照、池（全部 100 条）、观测、预算、成功判定；交换 harness 与推理强度。(b) 3 × 2 = 6 个单元，每单元至少 3 次，共 18 次运行。(c) 主指标 SR / SPL；派生量为被接受 STOP 成功率、预算终点成功率、每集 token 与耗时。(d) 差值超过两倍合并标准差才写显著，否则写方向性观察。(e) 遗漏候选：服务端版本漂移未冻结、池顺序与上下文长度未控制。

小结

  • 2026 年通用模型开始直接充当导航系统，评测对象从方法变成系统；数字由模型、harness、工具接口、episode 池、预算与运行口径六层共同决定。
  • 三篇来源（arXiv:2609.29861v2、2609.20116v2、2607.26148v3，检索日 2026-10-01）给出 81.3、52.0、70.7±3.5、78 等读数；同一模型家族的协议跨度 29.3 个百分点，约为同协议运行噪声（1.5 至 3.5 点）的 8 到 20 倍。
  • 内部一致性核对：79 / 81 / 84 对应 81.33±2.52；50 条子集的 26 条成功分解为 18 条被接受 STOP 与 8 条预算终点；六次评测的 62 / 8 / 30 稳定分类刻画真实缺口。
  • 失败结构集中在执行闭环：错误参照、停止决策、失控搜索、几何陷阱；长程把 SR 从 R2R-CE 的 70 拉到 RxR-CE 的 26 至 39，上下文与墙钟时间成为第二重约束。
  • 「零样本」按三档强弱的写法标注；闭源模型只能主张「未微调」一档。下一讲在同一框架下补充不确定性：保形预测的 episode 级覆盖、熵触发的按需计算与基于预测集的求助延迟（第 094 讲）。
