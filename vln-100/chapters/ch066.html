第四篇 · 规模、记忆与泛化方法论

第 066 讲｜记忆范式总览（承 039）

第 039 讲在第二篇做了第一遍四范式横评，口径是单条 episode、t = 15。本讲把它搬进第四篇的规模语境重算一遍：t = 30、批大小 64 下，HAMT 历史每样本 93 KiB、DUET 100 节点 300 KiB、BEVBert 度量图 1.29 MiB、GridMM 记忆库 51.68 MiB，批内存从 5.81 MiB 跨到 3.23 GiB；2 GiB 预算下 GridMM 必须降到半精度才能过线。本讲给出记忆预算方程、推导流程与三档预算下的选型判据。

  • 主题：记忆预算 / 四类载体 / 内存-延迟-精度 / 训练规模
  • 关键数字：t = 30 每样本 3 KiB 至 51.68 MiB；批 64 为 5.81 MiB 至 3.23 GiB；BEVBert 键值缓存 0.65 GiB
  • 预计学时：60 分钟
  • 前置讲：第 065 讲（数据增广的边界与风险）

学习目标

  • 会写：记忆预算方程 M总 ≈ B·(M载体 + M键值 + M激活) + M观察，并逐项说明来源与增长方式。
  • 会算：给定步数 t、批大小 B 与数值精度，实算四类载体的单样本内存、批内存、键值缓存与注意力延迟代理量。
  • 会判断：在显存与延迟预算约束下选择载体与压缩方案（半精度、限窗、截断、缓存），并写出精度代价的验证计划。
  • 会诊断：用 token 数代替延迟、单样本与批内存混淆、键值缓存重复计数、跨协议精度排名四类系统性错误。
  • 会设计：为一个长 episode、大场景任务写出记忆预算表与消融计划，含精度项与协议标注。

背景与动机

第 039 讲给出的三笔账回答了「四类载体差在哪里」，当时的口径是单条 episode、t = 15：从 RecBERT 的 3 KiB 到 GridMM 的 25.84 MiB，跨四个数量级。进入第四篇后，这个视角不够用了。第 061 至 063 讲把训练环境推到 1,291 个真实场景与 1000 个 HM3D 建筑，HM3D 单场景可导航面积均值 112.5 平方米，探索范围与 episode 长度都在增长；第 064 与 065 讲又要求把数据与增广的成本写成可审计的账。记忆从模型结构问题变成训练配置问题：同样的载体选择，在 t = 30、批 64 的训练里会触到不同的资源上限。

本讲要补的三件事。第一，把三笔账的计量口径从「一条 episode 的一次前向」扩展到「一个训练步的整批」（batch），并显式写出键值缓存与观察缓存两项常被漏算的开销。第二，把延迟从单一代理量拆成注意力、地图维护、执行三段，说明为什么 token 数不能代表延迟。第三，把选型从决策树升级为预算门槛表：先过内存与延迟门槛，再在通过者中比较精度，并给每个精度数字标注协议。

本讲的产出是记忆预算推导流程与一张可填写的预算表，服务后续四讲：第 067 讲深入局部度量地图与预训练，第 068 讲讨论全局拓扑与跨尺度推理，第 069 讲处理网格记忆与指令相关性，第 070 讲设计地图预训练目标。第 039 讲是横评，本讲是预算；两者配合使用，先预算后选型。

核心原理

本讲按「预算方程、单样本重算、批账、延迟账、精度账、推导流程、压缩折中、失效模式」八步展开；载体与第 039 讲一致，数字由 Python 实算，单位统一为 float32 下的字节数，半精度单独标注。

1. 预算方程与三层结构

把训练一步的资源占用写成四个来源：载体状态、键值缓存、激活与观察缓存。载体状态是 episode 内持续存在的记忆本体；键值缓存是注意力在前向时物化的中间量，每一步重建；激活是网络其他层的中间张量；观察缓存是并行环境的帧缓冲。预算方程取近似形式：

M训练 ≈ B · (M载体 + M键值 + M激活) + M观察 B 为批大小；M载体 按载体形态取常数、线性（随 t）、按节点数或固定尺寸；M键值 按 token 数与层数计；M观察 与载体选择无关
载体增长方式训练时要不要每步重建易漏算项
P1 递归状态（RecBERT）常数否历史压缩层激活
P1 显式历史（HAMT）线性随 t追加，无需全量重建全景编码器的视图 token
P2 拓扑图（DUET）随观测节点数增量加点节点特征与距离矩阵
P3 度量加拓扑（BEVBert）固定尺寸加节点每步重投影局部窗口窗口内网格特征与投影缓冲
P4 网格（GridMM）线性随 t每步按相对坐标重建地图记忆库本体与相关性缓存

方程的第一用途是排错：训练显存峰值与「载体 × 批」对不上时，先查键值与激活是否漏算，再查精度设置。载体账只是预算的入口，键值、激活与观察缓存同样是预算的一部分。

2. 单样本账重算（t = 30）

沿用第 039 讲的换算口径（维度 768、float32、每步 588 个网格特征对应 12 视角乘 7 乘 7 特征），把时间跨度从 t = 15 推到 t = 30，单条 episode 的载体占用如下。

载体t = 30 单样本换算备注
P1 递归状态（RecBERT）3.0 KiB768 × 4 B常数，信息随时间衰减
P1 显式历史（HAMT）93.0 KiB31 × 768 × 4 Bt 加 1 个摘要 token，线性
P2 拓扑图（DUET）300.0 KiB100 节点 × 768 × 4 B节点数随探索增长，有上界
P3 度量加拓扑（BEVBert）1.29 MiB21 × 21 × 768 × 4 B固定尺寸，与 t 解耦
P4 网格（GridMM）51.68 MiB30 × 588 × 768 × 4 B记忆库保存全部历史特征

读数有两点。第一，从 15 步到 30 步，线性载体的占用翻倍（HAMT 48 → 93 KiB，GridMM 25.84 → 51.68 MiB），常数与固定尺寸载体不变。第二，网格载体的主导项是记忆库本体；地图张量只有 14 × 14 个单元，记忆库存放的却是每个历史视角的网格特征。压缩网格载体的第一步是限制记忆库窗口或降低特征精度，第二步才是改地图分辨率。

3. 批账：B = 64 时谁能过 2 GiB 门槛

训练批内存等于单样本占用乘批大小。观察缓存另计：按第 018 讲的口径，64 个并行环境各存 5 帧、每帧 RGB 192 KiB 加深度 256 KiB，合计 140 MiB，这部分与记忆载体无关，属于任何方案都要付的底价。

载体B = 64（float32）半精度占 2 GiB 预算备注
HAMT 历史5.81 MiB2.91 MiB0.3%可通过加大历史长度换精度
DUET 100 节点18.75 MiB9.38 MiB0.9%节点上限与图规模挂钩
BEVBert 度量图82.69 MiB41.34 MiB4.0%不含键值缓存

实算：把 2 GiB 均摊到 64 个样本，每样本上限 32 MiB。GridMM 的 float32 单样本 51.68 MiB，超出 1.61 倍；换成半精度 25.84 MiB，降到预算的 81%。其余三类载体占比都低于 5%，预算压力主要来自键值缓存与激活，需要单独计量。预算门槛的写法应是「载体加缓存加观察」的总和，任何只算载体一栏的配置表都无法解释实测显存。

4. 延迟账：token 数不决定延迟

注意力计算的延迟代理量按查询长度 s、键值长度 t、维度 d 估算：单层约 4sh2 + 4th2 + 4sth，其中 h 为隐藏维度。实算（d = 768，s = 37）：键值 196 个地图 token 时每层 0.572 GFLOPs；键值 441 个度量单元时 1.178；键值 100 个拓扑节点时 0.335；键值 31 个历史摘要时 0.164；31 个 token 的自注意力每层 0.149。

读取对象键值长度每层代理量键值缓存（4 层）
HAMT 历史摘要310.164 GFLOPs744 KiB
DUET 拓扑节点1000.335 GFLOPs2.34 MiB
GridMM 地图1960.572 GFLOPs4.59 MiB
BEVBert 度量图4411.178 GFLOPs10.34 MiB

三个结论。第一，键值长度与代理量近似线性，GridMM 的 196 个 map token 每层成本约为 BEVBert 441 单元的 0.486 倍；token 少并不自动等于快，查询侧投影项（4sh2）在短键值下占主导，31 个 token 的交叉成本 0.164 GFLOPs 与自注意力 0.149 GFLOPs 同量级。第二，键值缓存随长度与层数线性增长，BEVBert 在批 64、4 层下的键值缓存实算 0.65 GiB，属于必须进预算表的一项。第三，整机延迟还取决于地图维护与执行两段：GridMM 每步重建地图并用缓存压缩相关性计算（t = 30 时压缩比 15.50），DUET 的全局动作需要图最短路规划，HAMT 论文在单张 P100、R2R val unseen 全集上的实测为 RecBERT 69 秒、HAMT 104 秒（1.51 倍），可作为「显式历史相对递归状态」的执行侧参照。延迟必须按注意力、地图维护、执行三段分别测量，用任何单一代理量下结论都会失真。

6. 记忆预算推导流程

把预算写进配置表需要六步，顺序固定：列载体、算单样本、乘批、加缓存与观察、算延迟代理、标注精度协议。示例如下（t = 30，B = 64，float32，环境观察缓存 140 MiB）。

步骤操作本例结果
1 列载体按候选方案列出载体形态与增长方式四条候选行
2 单样本token 数 × 维度 × 字节，或特征数 × 步数 × 维度 × 字节3 KiB 至 51.68 MiB
3 乘批乘 B，得到载体批内存5.81 MiB 至 3.23 GiB
4 加缓存加键值缓存、激活与观察缓存；注意键值按层计BEVBert 键值 0.65 GiB
5 延迟代理按 s 与 t 算注意力，另测地图维护与执行0.164 至 1.178 GFLOPs 每层
6 精度协议标注 split、步数上限、解码方式与预训练配方写入配置表脚注

把方程落到一个具体配置上：以 BEVBert 为例，t = 30、B = 64、float32，载体批内存 82.69 MiB，地图两路编码器的键值缓存 661.76 MiB，观察缓存 140 MiB，三者合计 884.45 MiB（约 0.86 GiB）；余量留给激活与优化器状态，这是 2 GiB 单进程预算成立与否的关键项。同配置下换成 GridMM float32，仅载体一项就是 3.23 GiB，在任何 2 GiB 门槛下都无法启动。同一预算档位的两个候选，差别经常不在载体单价，而在缓存项能不能随批线性扩展。

7. 压缩与折中选项

四类载体各有对应的压缩杠杆，选择时按「先免费、后有损」排序。

  • 半精度：所有载体通用，内存减半。GridMM 从超预算 1.61 倍变为占预算 81%，是四类中唯一被半精度解救的载体。代价是数值漂移，必须用同一评测协议验证后放行。
  • 窗口限制：BEVBert 把 21 × 21 降到 11 × 11，单样本从 1.29 MiB 降到 0.354 MiB，短期 transformer 计算量（论文口径）从 15.2 GFLOPs 降到 4.5 GFLOPs；论文消融显示 11 × 11 配 1.0 米单元与 21 × 21 配 0.5 米单元接近，覆盖半径比分辨率更关键（第 067 讲展开）。
  • 历史截断：HAMT 限制历史长度上限，代价是早期信息丢失；截断点用长程任务（R4R 类）验证。
  • 节点剪枝与合并：DUET 对已访问节点掩码、按距离阈值合并重复节点，降低节点数与最短路规划开销。
  • 缓存机制：GridMM 用相关性缓存把 t = 30 时的计算量压到 1/15.50，属于实现层杠杆，不影响精度账。

8. 适用边界与失效模式

  • 预算方程是近似：激活项依赖具体算子与框架，必须用实测显存反标定，不能把估算值当验收线。
  • 线性增长载体在长 episode 下失控：t = 60 且 B = 64 时 GridMM 记忆库达 6.46 GiB 量级，必须提前设窗口或降精度。
  • 固定尺寸载体把成本转移到计算：BEVBert 内存与 t 解耦，但每步重投影与注意力成本随地图边长增长。
  • 精度与内存的取舍没有全局最优：同一载体在不同任务上的精度代价不同，必须逐任务验证。
  • 动态环境未覆盖：四类载体都假设环境不变，时效机制超出本讲的预算模型范围（第 096 讲回到该话题）。

关键代码与解读

三段代码：预算计算器、注意力与键值缓存核算、训练侧计量钩子。数字与正文一致。

片段 1：四类载体的预算计算器

KIB, MIB, GIB = 1024, 1024 ** 2, 1024 ** 3

def carrier_bytes(kind, t=30, nodes=100, d=768, dtype=4):
    """按载体形态返回单样本字节数；dtype 为每元素字节数。"""
    if kind == "recbert":
        return d * dtype                        # 常数状态
    if kind == "hamt":
        return (t + 1) * d * dtype              # 每步一个全景摘要
    if kind == "duet":
        return nodes * d * dtype                # 节点特征集合
    if kind == "bevbert":
        return 21 * 21 * d * dtype              # 固定尺寸度量图
    if kind == "gridmm":
        return t * 588 * d * dtype              # 每步 588 个网格特征
    raise ValueError(kind)

def budget(kind, batch=64, t=30, dtype=4):
    per = carrier_bytes(kind, t=t, dtype=dtype)
    total = per * batch
    return per, total, total / (2 * GIB)        # 相对 2 GiB 门槛

for k in ("recbert", "hamt", "duet", "bevbert", "gridmm"):
    per, total, ratio = budget(k, dtype=4)
    print(k, round(per / MIB, 2), "MiB", "share %.3f" % ratio)
# gridmm float32：per 51.68 MiB、ratio 1.61；dtype=2 时 ratio 0.81

解读：（1）所有载体走同一函数，口径统一，避免跨表比较时单位漂移；（2）返回值同时给单样本与批内存，训练日志与配置表可用同一数字源；（3）比例项直接对照预算门槛，超线 1.61 倍这类结论在启动训练前就能得到。

片段 2：注意力代理量与键值缓存

def cross_flops(s, t, h=768):
    """单层交叉注意力代理量：查询与键值投影加打分。"""
    return 4 * s * h * h + 4 * t * h * h + 4 * s * t * h

def kv_bytes(t, layers, h=768, dtype=4):
    """键与值各一份，按层数累加。"""
    return 2 * t * h * dtype * layers

for name, t in (("hamt", 31), ("duet", 100), ("gridmm", 196), ("bevbert", 441)):
    print(name, "%.3f GFLOPs" % (cross_flops(37, t) / 1e9),
          "kv %.2f MiB" % (kv_bytes(t, 4) / MIB))
# bevbert 批 64、4 层的键值缓存 0.65 GiB，必须计入训练预算
print("gridmm/bevbert key ratio %.3f" % (cross_flops(37, 196) / cross_flops(37, 441)))

解读：（1）代理量把「读什么」变成可比数字，短键值下查询投影项占比上升，token 数与延迟的对应关系被拆开；（2）键值缓存按层累加，且每步重建，属于瞬时开销，预算表要把峰值当约束；（3）比值 0.486 说明 GridMM 地图 token 数不到 BEVBert 单元数的一半，但每步地图重建仍需单独测量。

片段 3：训练侧计量与预算断言

class BudgetMonitor:
    """训练循环内的显存与延迟计量：按三段分别记录并断言预算。"""
    def __init__(self, cap_bytes):
        self.cap = cap_bytes
        self.log = []

    def step(self, carrier, kv, t_carrier_ms, t_map_ms, t_exec_ms):
        used = carrier + kv
        assert used <= self.cap, (used, self.cap)   # 超预算立即中断
        self.log.append({
            "used": used,
            "carrier": carrier,
            "kv": kv,
            "latency_ms": round(t_carrier_ms + t_map_ms + t_exec_ms, 2),
            "split": (round(t_carrier_ms, 2), round(t_map_ms, 2), round(t_exec_ms, 2)),
        })
        return self.log[-1]

# 每 N 步对最近窗口取均值与 95 分位，写进训练配置表；
# 载体账、键值账与执行三段分开记，避免用总延迟归因单个模块

解读：（1）断言把预算从文档约定变成运行约束，超线时给出实际占用与上限两个数，便于定位；（2）延迟按载体、地图维护、执行三段记录，任何一段异常都能单独暴露；（3）日志字段与预算表的列一一对应，实验复现时可直接比对配置表。

常见误区

  • 用 token 数代替延迟：GridMM 地图只有 196 个 token，就推断它整体更快。根因是忽略每步地图重建、相关性聚合与执行侧动作。修复：延迟按三段测量，缓存开关作为消融变量。
  • 单样本内存直接乘批却漏掉键值与激活：配置表写 83 MiB，实测显存高出一个量级后用「框架开销」搪塞。根因是预算方程不完整。修复：把键值、激活与观察缓存写进同一张表，用实测反标定激活项。
  • 把半精度当免费午餐：内存减半后指标漂移，复现实验无法对齐。根因是精度变化未进协议。修复：精度写入配置表脚注，同协议重跑验证集；对数值敏感的载体先做数值稳定性检查。
  • episode 边界不重置载体：跨 episode 残留上一段记忆，训练指标虚高而评测时行为异常。根因是载体对象在环境中复用未清空。修复：环境 reset 时显式清空载体、键值与缓存，并在单元测试里断言重置后的内存回到初值。
  • 跨协议排名与收益归属混淆：把 BEVBert 的 R2R-CE 59 / 50 与 GridMM 的 49 / 41 直接相减。根因是两行管线不同，且预训练收益被算进载体。修复：同管线内比较；预训练与结构收益分列记账。

练习与思考

  1. 按 t = 30、float32 实算四类载体的单样本内存与批 64 内存，指出哪一类在 2 GiB 门槛下需要降精度，并给出降精度后的占比。 ★
    提示
    单样本 3 KiB / 93 KiB / 300 KiB / 1.29 MiB / 51.68 MiB；批 64 为 5.81 MiB / 18.75 MiB / 82.69 MiB / 3.23 GiB。GridMM float32 超 2 GiB 门槛 1.61 倍，半精度后 25.84 MiB 每样本，占预算 81%。其余载体占比均低于 5%。
  2. 推导与求解：GridMM 记忆库在批 64、float32、每步 588 个网格特征的口径下，若要求单样本载体不超过 32 MiB，历史长度 t 的上限是多少？步长 30 改为 60 时批内存变成多少？ ★★
    提示
    每步占用 588 × 768 × 4 = 1,806,336 B ≈ 1.72 MiB；32 MiB / 1.72 MiB = 18.58，取 t ≤ 18。t = 60 时单样本 103.36 MiB，批 64 约 6.46 GiB。
  3. 改超参并预测：把 BEVBert 的地图从 21 × 21、0.5 米改为 11 × 11、1.0 米。预测 (a) 每样本内存与注意力代理量的方向与倍数；(b) SR 与 SPL 的大致走势；(c) 一个可证伪的观测指标。 ★★
    提示
    (a) 单元数 441 → 121，内存与代理量约降到 0.27 倍（论文 FLOPs 15.2 → 4.5 G）。(b) 覆盖半径从 5.25 米保持 5.5 米量级，SR 接近 21 × 21 档（论文 74.58 对 74.88），SPL 略低；预测差距在 1 个点内。(c) 观测指标：近距离小物体指代类指令的成功率，若显著下降说明分辨率损失开始生效。
  4. 延迟分解设计：给定同一批硬件与同一策略，设计一个实验把总延迟拆成注意力、地图维护、执行三段，并要求给出缓存开关与精度两个维度的消融表。 ★★
    提示
    在环境 step、策略前向、地图重建三处加计时器，各取中位数与 95 分位；消融维度：缓存开 / 关、float32 / 半精度；判据是任意一段占比超过 50% 时优先优化该段，且精度变化必须同步验证指标。
  5. 完整预算设计：为目标任务「多层别墅、RGB-D 可用但深度噪声大、单进程显存预算 2 GiB、要求全局回退与细粒度指代」写出记忆预算表与消融计划。要求 (a) 给出载体组合与每层分工；(b) 计算 t = 30、B = 64 的总内存并与预算对照；(c) 设计三档消融分离载体收益与预训练收益；(d) 写出两个预期失效模式与降级路径。 ★★★
    提示
    (a) 全局用拓扑保回退，楼内局部用度量图保短程推理，多楼层用楼层标识切分并维护楼间连接。(b) 拓扑 18.75 MiB 加度量图 82.69 MiB 加键值约 12 MiB，合计低于 120 MiB，2 GiB 预算余量充足；GridMM 若加入需半精度加窗口。(c) 三档：单拓扑、拓扑加度量、拓扑加度量加楼层切分；训练配方与动作头固定。(d) 失效一：深度噪声使度量图投影漂移，降级路径为按第 067 讲的误差预算限制可靠半径；失效二：多楼层连接点错配，降级路径为楼层标识与楼梯节点显式建模。

小结

  • 预算方程 M训练 ≈ B·(M载体 + M键值 + M激活) + M观察：载体账只是入口，键值、激活与观察缓存必须同表计量。
  • t = 30、float32 的单样本载体从 3 KiB 到 51.68 MiB；批 64 从 5.81 MiB 到 3.23 GiB；2 GiB 门槛下 GridMM 必须用半精度（0.81 占比）才能过线。
  • 延迟用三段口径：注意力代理量（0.164 至 1.178 GFLOPs 每层）、地图维护（缓存压缩比 15.50）、执行侧（HAMT 相对 RecBERT 1.51 倍推理时间）。token 数不决定延迟。
  • 精度账必须带协议：REVERIE 上 DUET 到 BEVBert 为 +4.80 / +2.64，R2R-CE 同管线内 DUET 到 GridMM 为 +2 / +2；预训练收益单列。
  • 压缩顺序：半精度、窗口限制、历史截断、节点剪枝、缓存；每项都要用同协议验证，不能只报内存收益。
