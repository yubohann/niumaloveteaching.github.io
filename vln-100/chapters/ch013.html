第一篇 · 任务、数据、仿真与评测地基

第 013 讲｜REVERIE：远程物体指代

本讲把导航目标从「一个位置」换成「一个远程物体」：指令是高层日常命令，目标是训练时未见过的指代对象，成功判定要求在 3 m 内给出正确边界框。内容覆盖任务形式化、数据规模与切分、交互式 Navigator-Pointer 基线、评测口径，以及与本系列 ObjectNav-100 的接口对照。

  • 主题：远程指代 / 高层指令 / 物体级标注 / 导航加指代基线
  • 关键公式：SRREVERIE = 1[d ≤ 3 m 且指代正确]；IoU ≥ 0.5 判定
  • 预计学时：70 分钟
  • 前置讲：第 012 讲（RxR：多语言与稠密对齐）

学习目标

  • 会写：把 REVERIE 写成 POMDP 扩展形式，说明动作空间新增的指代输出、观测中新增的物体候选、以及 3 m 与 IoU 双条件成功判定的位置。
  • 会算：核对 21,702 条指令、10,567 个全景、4,140 个目标物体的规模与四个切分的汇总，独立推导 val-seen 的指令数与物体数。
  • 会解释：远程指代相对传统指代表达（Referring Expression）新增的三个难点，以及高层指令与逐步指令对状态设计的不同要求。
  • 会设计：一个最小「导航加指代」基线（Navigator、Pointer、Interaction 三模块），写清数据流、损失组合与参数依据。
  • 会判断：REVERIE 与本系列 ObjectNav-100 的类别目标接口如何对应，哪些数字可以对照、哪些必须重新评测。

背景与动机

第 001 讲把 VLN 的三类指令变体划开：逐步指令、高层描述、对话。前 12 讲的重心落在逐步指令一系（R2R、RxR、R4R），智能体的输出是一个停止位置，语言描述了走法。现实里的家庭机器人任务更接近另一类：「去书房把窗边的靠垫拿过来」任务里，路线描述并不存在，物体才是目标；智能体既要自己找到路，又要在到达后指出具体是哪一个物体。REVERIE（Remote Embodied Visual referring Expression in Real Indoor Environments）由 Qi、Wu、Anderson 等 2019 年提出、CVPR 2020 正式发表（arXiv:1904.10151），把这一类任务做成基准。

它与既有任务的关系可以用三句话定位。相对逐步指令导航，REVERIE 的指令是高层日常命令，目标由物体决定，路径留给智能体推理；相对单图指代表达，目标物体在初始视野中不可见，必须主动探索后指认，候选来自多个视点与视角，数量高出一个数量级；相对问答式具身任务（EQA），输出改为目标物体的边界框，比位置或文字答案更接近可执行的机器人指令。

本讲的产出是一个更完整的任务视角：状态里要同时容纳「我在哪」与「目标是什么」，动作里要同时容纳「怎么走」与「认出它」。第 014 讲 SOON / FAO 会把「目标位置不确定」这一维度继续推进；连续环境与真机部署（第三篇）会复用本讲的物体级接口。与本系列 ObjectNav-100 的对照放在实现设计一节，便于两门课交叉阅读。

核心原理

1. 任务定义与 POMDP 扩展

每个 episode 开始时，智能体位于某建筑内的一个全景位点，收到一条高层自然语言指令 X = ⟨w1, w2, …, wL⟩，它指向建筑内另一个位置的某个目标物体；目标物体在起始视野中不可见。智能体可在导航图上移动到可达全景位点，也可以选择停止。与第 001 讲五元组 M = ⟨S, A, T, R, O⟩ 相比，REVERIE 在三个位置做了扩展：

元件逐步指令 VLN（第 001 讲）REVERIE 的扩展
S：状态建筑布局、物体与位姿增加「目标物体是哪一个实例」这一隐变量，目标实例由指令指代确定
A：动作转弯、前进、停止增加检测输出动作 detect：输出目标边界框或从候选框中选择；其余动作在导航图上进行
O：观测当前位姿 RGB 帧与可达视点增加候选视角的物体集：类别标签、边界框、区域特征；指代目标本身不在观测中
R：奖励到达目标位置并停止双条件：停止点距目标物体不超过 3 m，且指代判定正确（IoU ≥ 0.5 或选中正确候选框）
ℓ：条件整段固定、按整句条件化同一形式；但语义上是指代消解，条件化对象从「路径描述」变为「物体身份」

任务规定智能体在单个 episode 中只允许输出一次指代结果。这一约束把任务从「多猜测提高命中率」拉回到「一次性判断」，实现时通常的做法是：智能体在认为已经接近目标时输出边界框，episode 随即结束。成功判定的两种口径都要写清：当评测器提供候选框集合时，判「是否选中正确候选」；当不提供候选框时，判预测框与真值框的 IoU 是否达到 0.5。目标物体可在多个视点、多个视角被观察到，因此只在「停止点距目标不超过 3 m」的前提下判定，不会因观察角度不同而改变难度的定义。

SuccessREVERIE = 1[ dstop(vT, o*) ≤ 3 m ] · 1[ 指代正确 ] o* 为目标物体，dstop 为停止点到物体的距离；指代正确指选中正确候选框，或无候选集时 IoU(预测框, 真值框) ≥ 0.5

由定义可直接推出一个结构性事实：REVERIE 成功必然蕴含导航成功，因为两者都要求停止点在 3 m 以内。因此成功率满足 SRREVERIE ≤ SRnav。论文基线在 test 上的数字正好符合：11.28 ≤ 19.88。这个不等式是第 5 节失败归因的基础。

2. 与相邻任务的关系

论文表 2 用六个维度对比了相关任务，下表按本课程口径重排。

任务指令形态目标输出操作要求

三处关键差异值得单独记住。第一，目标粒度不同：ObjectNav 给类别（「椅子」），REVERIE 给具体实例（「书房窗边那把靠垫」），指代消解成为任务的主难点之一。第二，输出不同：只要求停止位姿时，智能体可以「走到附近即算对」；要求边界框时，必须真正定位到物体。第三，候选来源不同：静态指代在同一张图里比较候选，REVERIE 的候选散布在建筑所有可能视点与视角上，且外观随观察角度变化，论文据此指出候选数量高出一个数量级。

4. 基线模型：交互式 Navigator-Pointer

论文先把既有最优导航模型与指代模型直接组装成流水线，结果都很弱：FAST-Short 加 MAttNet 在 test 上指代成功率只有 7.07%。直接组装的问题是误差复合：导航未到达 3 m 以内则整体必败，指代未命中则整体也败，两类错误在乘积中叠加。随后论文提出交互式 Navigator-Pointer 模型，让两个模块互相提供信号。

Navigator 模块采用 FAST 的短版本：指令经 LSTM 编码为 X ∈ RL×512；视觉侧由交互模块更新后的候选特征 V′ ∈ RK×4736；文本注意力 αt 与视觉注意力 βt 分别由上一时刻隐状态计算：

αt = softmax(PE(X) · (Wx ht−1))，βt = softmax(g(V′) · (Wv ht−1)) PE 为位置编码，g 为一层多层感知机，Wx 与 Wv 可学习；αt 在词上加权，βt 在候选视角上加权

新上下文由 LSTM 在拼接的接地文本、接地视觉与上一动作上更新；每个候选视角的 logit 由隐状态与指令特征的联合表示同视角特征做内积得到。解码采用候选队列与结束队列：所有可达视点（含当前视点）进入候选队列，累计 logit 最大的视点被弹出并执行，走过的视点进入结束队列；当当前视点被选中、候选队列为空或达到步数上限时 episode 结束，累计 logit 最大的视点作为停止位置。

Pointer 模块用 MAttNet，把指代表达分解为主体外观、位置关系、物体关系三个模块，分别与候选物体计算匹配分数，再按可学习的权重求和。位置模块使用与同类物体的相对偏移和面积比，关系模块考虑周围物体，这两个设计正对 REVERIE 指令里「窗边那把」「架子上的」这类空间修饰。

Interaction 模块是论文的关键增量：对每个候选视角，Pointer 先选出匹配度最高的 3 个物体，用双向 LSTM 编码其类别标签，用 ResNet FC7 层输出做物体区域特征，然后把「原始视角特征、标签编码、区域特征」拼接，送回 Navigator 作为更新后的视角特征。指针因此充当候选视角上的硬注意力，把与目标最相关的物体信息注入导航决策。

损失由两部分组成：导航损失是动作交叉熵与进度均方误差的加权和，权重 λ1 = 0.5；指代损失是排序损失，正样本对与两种负样本对的间隔项权重 λ2 = λ3 = 1.0；总损失为 L = Lnav + λ4 Lexp，默认 λ4 = 1.0。训练分两段：先在目标视点的可见视图上训练 Pointer，再把 Pointer 的输出作为辅助信息训练 Navigator。

读法与逐步指令任务不同，需要注意三点。第一，随机基线约 1%，说明指代空间巨大，1% 附近的差异不构成方法优劣。第二，交互增益集中在 test：相对最强的直接组装基线，val-seen 只升 0.56 点（31.97 对 31.41），val-unseen 升 1.60 点，test 升 4.21 点（相对 +59.5%）。训练场景上直接组装已经够用，交互模块的价值在未见环境才显现。第三，与人类的距离非常大：test 上 11.28 对 77.84，约为人类水平的 14.5%，绝对差 66.56 点。

导航侧指标给出失败的结构：Ours 在 test 上导航成功率 19.88%、oracle 成功率 30.63%、SPL 11.61%、平均路径 39.05 m；人类为 81.51%、86.83%、53.66%、21.18 m。智能体的 SPL 仅为人类的 21.6%，路径长度是人类 1.84 倍，说明大量探索消耗在寻找目标所在房间的过程里。论文还给出一个对照：FAST-Short 的导航 SPL 从 R2R 的 43% 掉到 REVERIE 的 6.17%，相对下降约 85.7%。同一个导航模型换到「目标由远程物体决定」的任务上，性能损失远大于换建筑。

语言消融进一步排除捷径：只给指令不给视觉的 FAST-Lan-Only 在 test 上只有 4.34%（val-seen 5.97%、val-unseen 5.00%），远低于多模态基线，说明任务无法靠语言先验解出，视觉探索与物体指认缺一不可。

6. 适用边界与失效模式

  • 指代口径双轨制：候选集选择与 IoU ≥ 0.5 是两条不同的判定路径，候选集给定时任务更简单；报告必须写明用的是哪一条，跨论文比较前先核对。
  • 成功蕴含导航成功：SRREVERIE ≤ SRnav 是定义带来的上界；把端到端成功率直接当作指代模块的水平会系统性低估，先除以导航成功率得到条件正确率（test 实算 56.74%），再判断失败主要出在找路还是认物。
  • 3 m 是判定余量，不保证可见：物体标注只保留视点 3 m 内的实例，但停止点与目标距离小于 3 m 时目标仍可能被遮挡或在视野外，因此「停止正确但指代失败」是真实存在的失败类型。
  • 单次输出约束容易被放松：若实现允许反复输出或对多个候选框投票，成功率会虚高；官方评测按一次输出计分，复现实验应保持同一约束。
  • 标注者差异：指令由 1,000 名以上标注者创作，指代风格与用词存在方差；跨语言、跨标注池的迁移（承第 012 讲）在本数据集上尚无对应标注，结论外推要谨慎。

实现思路与设计

本讲设计一个最小可运行基线，目标是说清三件事：观测里放什么、三个模块怎么连、成功怎么算。与上一讲的差异在于，数据接口从「路径监督」转为「物体监督」，训练目标从「走到终点」转为「走到并指出」。

设计决策：两段训练加交互回路

论文采用两段式训练：先在目标视点的可见视图上训练 Pointer，再把冻结的 Pointer 输出接入 Navigator，端到端联合训练不在原文设置中。交互模块只传类别标签与区域特征两类信息，不传具体匹配分数，避免 Navigator 直接继承 Pointer 的置信度偏差。

迁移的三条判据：第一，REVERIE 的 3 m 与 ObjectNav 的 1 m 门限不同，成功率不可直接对比；第二，把 REVERIE 指令替换成类别名并去掉 bbox 头，可构造 ObjectNav 风格的评测，但会丢失指代消解这一维度；第三，两门课共用 Matterport3D 与 Habitat 系平台接口，动作与观测层可直接共享代码。

关键代码与解读

三段代码分别覆盖环境交互、评测口径与交互模块。片段 1 与片段 2 为可离线运行的最小实现，片段 3 是可训练模块的骨架。

片段 1：POMDP 扩展与单次指代约束

from dataclasses import dataclass, field

@dataclass
class Observation:
    views: list = field(default_factory=list)        # 36 个视图特征
    navigable: list = field(default_factory=list)    # 可达视点，含当前视点
    objects: list = field(default_factory=list)      # 每个视角的候选物体
    instruction: str = ""                            # 高层指令

class ReverieEnv:
    """REVERIE 环境的最小接口；只示意状态机，不含渲染与图数据。"""
    def __init__(self, episode, max_steps=20):
        self.episode = episode
        self.max_steps = max_steps
        self.t = 0
        self.detected = False                        # 单次输出约束
    def step(self, action):
        if action["type"] == "detect":
            if self.detected:
                raise RuntimeError("每个 episode 只允许一次指代输出")
            self.detected = True
            reward = self._score_bbox(action["bbox"])  # 3 m 与指代正确同时满足
            return reward, True, None
        self.t += 1                                  # 导航动作：切换到可达视点
        return 0.0, self.t >= self.max_steps, self._observe()
    def _observe(self):
        return Observation(instruction=self.episode["instruction"])
    def _score_bbox(self, bbox):
        raise NotImplementedError                    # 判定归评测器，见片段 2

解读：（1）Observation 的四个字段对应 POMDP 扩展表：views 与 navigable 沿用 VLN，objects 与 instruction 承载指代条件。（2）detected 标志把「一次输出」写成状态机的硬约束，从接口层杜绝多次猜测。（3）导航中间步不产生任务奖励，奖励只在 detect 分支结算；训练信号主要来自监督与塑形项，检测后的评分由评测器实现。

片段 2：REVERIE 成功判定与指标口径

def iou(a, b):
    """两个边界框的交并比；坐标为 (x, y, w, h)。"""
    ax2, ay2 = a[0] + a[2], a[1] + a[3]
    bx2, by2 = b[0] + b[2], b[1] + b[3]
    iw = max(0.0, min(ax2, bx2) - max(a[0], b[0]))
    ih = max(0.0, min(ay2, by2) - max(a[1], b[1]))
    inter = iw * ih
    union = a[2] * a[3] + b[2] * b[3] - inter
    return inter / union if union > 0 else 0.0

def success_by_candidates(choice, gt_index, stop_dist, radius=3.0):
    """候选集口径：选中的候选编号与真值编号一致。"""
    return stop_dist <= radius and choice == gt_index

def success_by_iou(pred_bbox, gt_bbox, stop_dist, iou_thr=0.5, radius=3.0):
    """无候选集口径：预测框与真值框的 IoU 达到阈值。"""
    return stop_dist <= radius and iou(pred_bbox, gt_bbox) >= iou_thr

def nav_success(stop_dist, radius=3.0):
    """导航成功：只看到达距离，不含指代判定。"""
    return stop_dist <= radius

# 条件正确率的实算：test 上 11.28 / 19.88 给出导航成功口径下的指代条件正确率
print(round(11.28 / 19.88 * 100, 2))                 # 56.74

解读：（1）两条成功口径拆成两个独立函数，调用方必须显式选择其一，杜绝口径漂移。（2）两个函数都先判距离门限，体现 SRREVERIE ≤ SRnav 的结构；指代模块的正确率必须条件在导航成功上解读。（3）最后一行由论文 test 数字实算：导航成功样本中约 56.74% 指代正确，其余约 43% 属于「走到了但没认对」。这个条件量比直接看 11.28% 更能定位失败来源。

片段 3：交互模块骨架

import torch
import torch.nn as nn

class InteractionModule(nn.Module):
    """把 Pointer 的 top-k 物体信息拼进每个候选视角的特征。"""
    def __init__(self, base_dim, num_labels, label_dim=512, obj_dim=2048, top_k=3):
        super().__init__()
        self.top_k = top_k
        self.label_encoder = nn.Embedding(num_labels + 1, label_dim)  # 0 为占位标签
        self.label_lstm = nn.LSTM(label_dim, label_dim, batch_first=True, bidirectional=True)
        self.obj_proj = nn.Linear(obj_dim, obj_dim)                   # 区域特征投影
        self.out_dim = base_dim + 2 * label_dim + obj_dim             # 拼接后的维度

    def forward(self, base_feat, topk_labels, topk_feats):
        # base_feat: (K, base_dim)；topk_labels: (K, top_k)；topk_feats: (K, top_k, obj_dim)
        labels = self.label_encoder(topk_labels)                      # (K, k, label_dim)
        label_seq, _ = self.label_lstm(labels)                        # (K, k, 2*label_dim)
        label_vec = label_seq.mean(dim=1)                             # (K, 2*label_dim)
        obj_vec = self.obj_proj(topk_feats.mean(dim=1))               # (K, obj_dim)
        return torch.cat([base_feat, label_vec, obj_vec], dim=-1)     # (K, out_dim)

mod = InteractionModule(base_dim=1024, num_labels=489, top_k=3)
base = torch.randn(8, 1024)                     # 8 个候选视角
labels = torch.zeros(8, 3, dtype=torch.long)    # top-3 类别标签占位
objs = torch.randn(8, 3, 2048)                  # top-3 区域特征
print(mod(base, labels, objs).shape)            # torch.Size([8, 4096])

解读：（1）交互模块只做特征拼接，不改变 Navigator 的注意力结构；更新后的维度为 base_dim 加 2 × label_dim 加 obj_dim。论文报告其配置下该维度为 4736，各分量取值随实现配置而定，示例用 1024 + 2 × 512 + 2048 = 4096 演示形状规则。（2）标签用双向 LSTM 编码以保留 top-3 的顺序信息；位置与关系信息已由 Pointer 的匹配分数体现，这里不再重复编码。（3）推理时 top-k 取自 Pointer 输出，训练时若改用真值物体注入会形成老师强制，需要在验证阶段切回模型自选，否则复现曲线虚高。

常见坑

  • 两种指代口径混用：症状是同一模型在两次报告里差出十多个点；根因是候选集选择与 IoU ≥ 0.5 的判定难度不同。修复：评测脚本显式传入口径参数，报告标注「候选集」或「IoU@0.5」，跨论文比较前先核对。
  • 把指代失败全部记在 Pointer 头上：症状是 Pointer 离线指标很高、端到端成功率很低，就断言指代模块无效；根因是误差复合，导航未到达时 Pointer 没有机会命中。修复：按 2 × 2 交叉表统计导航成功与指代成功，先看条件正确率（实测算例为 56.74%），再看各单元格的改进空间。
  • 把 3 m 当作可见性保证：症状是停止点已在目标 3 m 内却指代失败，被误判为「标注错误」；根因是遮挡与视野外。修复：评估时记录目标在该时刻是否可见，把失败拆成「不可见」与「可见但认错」两类。
  • 放松单次输出约束：症状是复现成功率高于论文；根因是实现允许对多个候选框投票或多步输出。修复：把首次输出后的所有动作置为无效，并在评测脚本中拒绝第二次 detect。
  • 跨任务直接搬数字：症状是拿 REVERIE 成功率与 ObjectNav 或 R2R 的成绩做排名；根因是目标、动作与成功口径都不同。修复：只比较同一任务、同一 split、同一判定口径的数字，跨任务比较改为结构性对照表。

练习与思考

  1. 写出 REVERIE 的 POMDP 扩展：在 M = ⟨S, A, T, R, O⟩ 的每一项上写明与逐步指令 VLN 的差异，并解释单次指代输出为什么应写成动作空间的硬约束。★
    提示
    S 增加目标实例隐变量；A 增加 detect；O 增加候选物体集合；R 增加 3 m 与指代双条件；条件 ℓ 的语义从路径描述变为物体身份。单次约束保证任务度量的是判断质量，防止用多次猜测抬高命中率。
  2. 核对数据切分：由 train 10,466、val-unseen 3,573、test 6,292、验证合计 4,944 推导 val-seen 的指令数；由 4,140 与 2,353、525、834 推导 val-seen 的物体数；再验证四段之和与总数一致。★
    提示
    val-seen 指令 = 4,944 − 3,573 = 1,371；物体 = 4,140 − 2,353 − 525 − 834 = 428，也等于 953 − 525。指令四段之和 21,702，物体四段之和 4,140。
  3. 设计一个最小「导航加指代」基线：画出 Pointer、Interaction、Navigator 三模块的数据流，说明两段训练的顺序、每段使用的监督信号，以及为什么 Pointer 需要在目标视点的视图上单独训练。★★
    提示
    第一段：指令与候选物体在目标视点视图上训练 Pointer 的排序损失。第二段：冻结 Pointer，对每个候选视角取 top-3，经交互模块拼接后训练 Navigator 与进度头。单独训练的原因是候选框监督只在目标附近完备，早期导航轨迹上缺少正样本。
  4. 假设某次 test 评测有 100 条 episode，导航成功 20 条，其中指代正确 12 条，另有 3 条在导航失败的情况下指代判对。请计算导航成功率、REVERIE 成功率与「导航成功条件下的指代正确率」，并说明第三个量与另两个量的关系。★★
    提示
    导航成功率 20%，REVERIE 成功率 12%（3 条不满足距离门限，不计入），条件正确率 12 / 20 = 60%。由定义 SRREVERIE = SRnav × P(指代正确 | 导航成功)，三个量必须互相自洽；论文 test 数字的对应值为 19.88%、11.28% 与 56.74%。
  5. 设计把 ObjectNav 评测迁移到 REVERIE 接口的方案：目标从类别名换成指代指令、输出从停止位姿换成边界框、成功阈值从 1 m 换成 3 m 并附加指代判定。要求逐项写出需要补充的标注、必须重新评测的数字，以及哪一类结论可以沿用。★★★
    提示
    需要补充：实例级指代指令（若沿用类别名则退化为 ObjectNav）、每个视点的实例边界框与可见性、目标实例编号。必须重测：成功率、SPL、指代准确率与误差分解，两门课的数字不可换算。可沿用：仿真平台接口、探索策略、感知模块的消融结论，因为观测与动作层未变。

小结

  • REVERIE 把导航目标改成远程指代物体：高层指令、目标初始不可见、单次输出边界框；成功要求停止点距目标 ≤ 3 m 且指代正确（IoU ≥ 0.5 或选中候选框）。
  • POMDP 扩展落在三处：状态增加目标实例隐变量，动作增加 detect，观测增加候选物体；由定义可得 SRREVERIE ≤ SRnav，实算条件正确率 11.28 / 19.88 = 56.74%。
  • 数据规模：21,702 条指令、10,567 个全景、4,140 个目标物体、489 个类别；切分为 train 10,466、val-seen 1,371（实算）、val-unseen 3,573、test 6,292，四段之和严格吻合。
  • 基线为交互式 Navigator-Pointer：FAST-short 导航、MAttNet 指代、top-3 物体经双向 LSTM 编码后拼入视角特征；test 成功率 11.28%，比直接组装基线高 4.21 点，约为人类 77.84% 的 14.5%。
  • 失败结构由导航主导：test 导航成功率仅 19.88%，SPL 11.61%，路径长为人类 1.84 倍；FAST-Short 的 SPL 从 R2R 的 43% 掉到 6.17%，说明「找物体」比「按描述走」更难。
