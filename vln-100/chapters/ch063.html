第四篇 · 规模、记忆与泛化方法论

第 063 讲｜HM3D / HM3DSEM：环境规模化

本讲把 062 管线依赖的环境资产本身讲透：HM3D 用 1000 个建筑级重建把可导航面积推到 112.5k 平方米（10,600 个房间、约 1,920 层），比 MP3D 大 3.72 倍，缺陷视图占比低于 5% 的场景有 560 个；HM3DSEM 为其中 216 个场景标注 142,646 个物体实例与 3,100 个区域，耗时 14,200 人时。两篇论文的划分、评测资产、跨数据集迁移证据与许可边界全部标注版本。

  • 主题：环境资产 / 数据集卡片 / 语义标注 / ObjectNav 评测 / 版本与许可
  • 关键数字：1000 场景、112.5k 平方米可导航、142,646 个实例、3,100 个区域、14,200 人时
  • 预计学时：70 分钟
  • 前置讲：第 062 讲（ScaleVLN II：合成管线拆解）

学习目标

  • 会算：核对 HM3D 的总量指标与单场景均值（112.5 平方米、10.6 个房间、1.92 层），完成与 MP3D、Gibson 的规模对比表，理解缺陷视图口径的两级阈值（单视图 55%、场景 5%）。
  • 会解释：视觉保真、重建完整性两个质量指标的口径（缺陷视图比例、FID 与 KID），以及 HM3D 在 PointNav 上被称为帕累托最优的含义。
  • 会判断：HM3D、HM3DSEM 与 MP3D 三个资产分别在什么时候使用，划分与版本口径怎样影响评测可比性。
  • 会实现：场景筛选、语义标注统计核对与 ObjectNav 回合生成约束检查三段示意代码。
  • 会设计：为一项导航课题写出数据集卡片与子集筛选方案，覆盖版本、许可、缺陷率与场景清单四项证据。

背景与动机

第 002 讲把 Matterport3D 的 90 个场景与 1.08 万个全景作为课程的数据底座，第 009 到 011 讲讨论了 seen 与 unseen 的泛化协议与环境偏差。到第四篇，90 个场景成为明确瓶颈：第 061 与 062 讲的合成管线一次用到 1291 个真实场景，其中 800 个来自 HM3D。合成数据的上限由环境资产决定，理解资产本身才能理解数据工厂的边界。

HM3D（Habitat-Matterport 3D，Ramakrishnan 等 2021，NeurIPS 2021 Datasets and Benchmarks Track，arXiv:2109.08238v1）把规模推到 1000 个建筑级重建，并给出采集、筛选、质量对照与导航实验的完整证据链。HM3DSEM（Yadav 等 2022，arXiv:2210.05633v3）在其上增加语义层：216 个场景、3,100 个区域、142,646 个物体实例，标注成本 14,200 人时。两篇论文合起来回答同一个问题：真实环境资产怎样从几十个场景走到上千个场景，并且质量可控。

本讲解决三件事。第一，资产卡片怎么读：规模、保真、完整性、划分四组指标的口径。第二，资产怎样支撑评测：PointNav 的跨数据集实验与 ObjectNav 的回合数据集配置。第三，资产的边界：许可、隐私、版本与标注噪声。第 064 讲再把采购、清洗、许可与版本写成可审计的工程流程。

核心原理

本讲按「采集、规模、质量、划分、迁移、语义层、标注成本、下游评测、边界」九步展开；数字来源为 arXiv:2109.08238v1 与 arXiv:2210.05633v3，估算值单独标注口径。

1. 采集与筛选：从候选池到 1000 个场景

全部场景用 Matterport Pro2 三脚架深度相机扫描，RGB-D 对齐、表面网格化与纹理由 Matterport 的重建管线完成。场景来自 38 个国家、181 个地区；仅美国境内就覆盖 43 个州。候选场景的筛选分两轮：先由 15 名志愿标注者按 1 到 5 分评估质量，检查项目包括破洞与裂缝、家具密度、关闭的门数量与交互潜力，同时参考可导航性指标识别楼层断裂；再由 3 名专家汇总，优先保留高分场景并按楼层数分布维持多样性。整理与发布合计约 800 人时。最终场景的楼层面积从 49 平方米到 2,172 平方米，倍差 44.3；建筑层数 1 到 8 层；房间数从 1 到 93 个。结论一：大规模资产的质量靠「先评分、再按多样性配额选择」的流程保证，人均审核成本必须计入数据预算。

2. 规模指标与对比

HM3D 的总量指标：1000 个场景、10,600 个房间、约 1,920 层、112.5k 平方米可导航面积、365.42k 平方米楼层面积。实算单场景均值：可导航面积 112.5 平方米，楼层面积 365.4 平方米，房间 10.6 个，层数 1.92，每层约 5.52 个房间。与 MP3D 相比：场景数 11.11 倍，可导航面积 3.72 倍，楼层面积 3.59 倍；与 Gibson 相比：可导航面积 1.37 倍，楼层面积 1.68 倍；与 Gibson 的高质量子集（4 分以上，17.74k 平方米）相比，楼层面积为其 20.6 倍。论文摘要给出的口径是：可比数据集（MP3D 与 Gibson）的 1.4 到 3.7 倍可导航面积，楼层面积约为 Gibson 的 1.7 倍。

3. 视觉保真与重建完整性

两个质量指标各有明确口径。重建完整性用「缺陷视图比例」衡量：把场景的可导航区域切成 1 米 × 1 米网格，每格在 0°、90°、180°、270° 四个朝向下渲染 256 × 256 的 RGB-D 图像（90° 视场角），深度为 0 或 RGB 全黑的像素记为无效；单视图无效像素超过 55% 即记为缺陷视图，场景内缺陷视图占比构成该场景的缺陷率。结果上，缺陷视图占比低于 5% 的场景，HM3D 有 560 个，Gibson 为 175 个，比值为 3.2；ScanNet 几乎全部场景存在严重缺陷，Replica 部分场景因缺少天花板，缺陷率接近 80%。

视觉保真用 FID 与 KID 衡量：把各数据集的渲染图分别与真实全景提取的图像组比较。HM3D 的 FID / KID 为 20.5 / 12.8，MP3D 为 24.4 / 17.3，Gibson 为 39.3 / 25.5，ScanNet 为 126.7 / 97.4；真实图像之间的域差（Gibson 真实与 MP3D 真实对照）给出 6.16 到 6.23 的下界。实算降幅：相对 MP3D，FID 降 15.98%、KID 降 26.01%；相对 Gibson，FID 降 47.84%、KID 降 49.80%。论文摘要的总结是：渲染图像的视觉保真高 20% 到 85%，网格因表面缺失产生的伪影少 34% 到 91%。结论二：质量指标要成对报告，重建精度高的数据集也可能因缺面（例如缺少天花板）出现大面积无效渲染，FID 因此偏高。

4. 划分与评测资产

HM3D 的 1000 个场景按 800 / 100 / 100 划分训练、验证与测试，测试场景不公开。PointNav 回合数据集按每个训练场景 1 万条、每个验证与测试场景 25 条生成，规模为 800 万训练、2500 验证、2500 测试；回合生成脚本沿用 Habitat 的公开流程。规模消融实验另取训练集的 10%（80 个场景）与 50%（400 个场景）训练同一架构：导航性能与训练场景的可导航总面积近似线性相关，论文报告皮尔逊相关系数 0.88。结论三：环境规模的收益可以先按可导航面积预估，再按面积预算分配场景数。

这套划分与回合资产是后续所有数字的可比性基础。引用 HM3D 指标时必须同时写明：场景版本（课程口径下 HM3D 资产分 v0.1 与 v0.2 版本）、划分口径（800 / 100 / 100）、回合集版本与传感器配置。第 062 讲使用 800 个训练场景构造成导航图，正是在这份划分之上。

5. 迁移证据：PointNav 的帕累托性质

HM3D 的论文用 PointGoal 导航（PointNav）验证资产价值：同一架构（ResNet-50 加 LSTM，DD-PPO 训练 15 亿帧）分别在 HM3D、MP3D、Gibson 上训练，再到三个测试集上交叉评测。摘要中的「帕累托最优」指：HM3D 训练的智能体在三个测试集上都不低于用对应数据集训练的智能体。

6. 语义层 HM3DSEM：规模与格式

HM3DSEM 从 HM3D 的 950 个带家具扫描中随机抽取 216 个场景（占 22.74%）做密集语义标注，训练 / 验证 / 测试划分为 145 / 36 / 35。总量：142,646 个物体实例、3,100 个区域。实算均值：每场景 660.4 个实例与 14.35 个区域，每区域 46.0 个实例（论文表 1 印约 60，与 142,646 个实例、3,100 个区域两总量相除不符，本课以实算为准）；全库共 1,625 个类别标签，平均每场景 106 个类别；标签最终映射到 MP3D 的 40 个规范类别（平均每个规范类别约 40.6 个原始标签）。建筑元素与未知标签共 34,368 个实例（占 24.09%），剩余约 108,278 个为家具、电器与杂物类实例。

7. 标注流程与质检成本

标注由 20 多名标注者完成，总投入 14,200 人时。实算：单实例约 5.97 分钟，单场景约 65.7 小时，单区域约 4.58 小时。其中 640 小时用于迭代与纠错，占 4.51%。自动化检查覆盖三类规则：文本中的颜色必须来自纹理、每个颜色在场景内只出现一次、文本格式符合「索引、颜色、类名、区域号」。人工检查以虚拟漫游方式进行，核查漏标、边界混乱、过度聚合（多个实例共用一个颜色）、语义错标（例如把洗碗机标成洗衣机）与同义标签的归并。

论文明确了残留问题：标注者在命名上有自由度，最终数据保留了较多同义标签；部分错误在交付后仍可能存在。工程上的对策是两条：引用时以 40 个规范类别为对齐口径，并在自己的数据卡片里记录原始标签到规范类别的映射版本；使用时抽检目标类别的实例质量，避免把标签噪声计入方法收益。

8. 下游评测：ObjectNav 协议与结果

HM3DSEM 的下游任务是目标导航（Object Goal Navigation，ObjectNav）：智能体带 RGB-D、指南针与 GPS，动作空间为前进（0.25 米）、左转、右转（30°）、抬头、低头与停止；底座半径 0.18 米，相机高度 0.88 米。目标类别为椅子、床、植物、马桶、电视或显示器、沙发六类；在距离目标类任一实例 1.0 米以内执行停止，且目标从停止位置无遮挡可见，记为成功。回合生成约束三条：起点可导航、目标可达、起点到最近目标距离在 1 到 30 米之间；规模为约 720 万训练回合、1072 验证、1000 测试（实算每训练场景约 49,655 条、每验证场景 29.8 条、每测试场景 28.6 条）。

三种训练范式的跨数据集结果支持同一结论：在 HM3DSEM 上训练的策略平均表现最好。强化学习（RL）的跨集平均成功率为 29.95，Gibson 训练为 24.13，MP3D 为 18.70；在同一 HM3DSEM 验证集上，HM3DSEM 训练的智能体成功率为 39.36，是 MP3D 训练智能体（18.97）的 2.07 倍。模仿学习（IL）平均为 28.86 对 24.30 与 18.26；模块化方法（ML）平均为 47.70 对 46.2 与 42.67。规模实验显示：RL 从最小子集（25 场景）到最大子集（145 场景）成功率为 17.79 到 39.36，比值 2.21；IL 从 25 到 80 个场景为 34.98 到 54.20，比值 1.55。

社区采用度的证据来自挑战赛：2020 年 ObjectNav 收到 563 份提交（27 支队伍），2021 年为 400 份（45 支队伍），2022 年换用 HM3DSEM 后增至 1022 份（54 支队伍），2022 对 2021 的提交比为 2.56。2022 年测试榜前五名的成功率与 SPL 为：ByteBOT 64.0 / 35.0、BadSeed 65.0 / 33.0、elf 61.0 / 30.0、Populus 60.0 / 30.0、Stretch 56.0 / 29.0；DDPPO 基线为 25.0 / 12.0，冠军方案的 SPL 是基线的 2.92 倍。

9. 边界与失效模式

  • 许可为非商业研究：HM3D 与 HM3DSEM 通过 Matterport 学术许可发布，限定学术、非商业用途；论文本身采用 CC BY-NC-ND 4.0。商业部署前必须单独取得授权，训练出的模型也属于派生数据，受同一许可链约束。
  • 隐私与场景性质：扫描对象包含私人住宅与商业空间；二次发布与可视化时必须复核面部、屏幕、门牌等敏感内容，尤其在论文插图与演示视频中，并保留权利人撤回的处理流程。
  • 版本口径：HM3D 资产与 HM3DSEM 语义层分别有版本号，场景清单、修复内容与回合集都会随版本变化；引用数字必须同时写明资产版本与论文版本，跨版本比较前先对齐场景清单。
  • 标注噪声与同义标签：1,625 个原始标签映射到 40 个规范类别，映射过程可能吞掉细粒度差异；目标类别内的实例质量参差，评测前应抽检目标类。
  • 域差仍然存在：FID 下界 6.16 到 6.23 说明跨数据集渲染本身就有可测的域差；HM3D 的保真改进缩小差距，不能消除差距。第 049 与 051 讲的真机差距问题在资产层面依旧成立。
  • 测试集不公开：评测必须通过官方服务器或固定验证集；本地改动划分后得到的数字不可与榜单直接比较。

关键代码与解读

三段代码分别给出场景筛选、语义标注统计核对与 ObjectNav 回合约束检查。接口以论文与官方发布页的描述为参照，具体字段名随版本演进。

片段 1：场景筛选与质量核对

import json

def select_scenes(meta, defect_max=0.05, min_rooms=3):
    """按缺陷率与房间数筛选高质量场景，输出冻结清单。"""
    kept, defects = [], []
    for scene in meta["scenes"]:              # 每个场景含缺陷率与房间数
        rate = scene["defect_view_ratio"]
        if rate <= defect_max and scene["rooms"] >= min_rooms:
            kept.append(scene["id"])
        defects.append(rate)
    kept.sort()                               # 排序保证清单可复现
    stats = {
        "n_total": len(meta["scenes"]),
        "n_kept": len(kept),
        "kept_ratio": round(len(kept) / len(meta["scenes"]), 4),
        "defect_mean": round(sum(defects) / len(defects), 4),
    }
    return kept, stats

# 复现断言：场景内缺陷视图占比低于 5% 的场景约 560 个
# 论文对照：Gibson 同口径约 175 个，比值约 3.2

解读：（1）筛选函数把「缺陷视图占比低于阈值」与「房间数满足任务需求」写成显式条件，输出带统计的冻结清单，便于第三方复现。（2）缺陷口径与论文一致：单视图无效像素超过 55% 记为缺陷视图，场景内缺陷视图占比低于 5% 才算高质量场景；两级阈值要一并记录。（3）断言参考值为 HM3D 约 560 个、Gibson 约 175 个；若复算结果偏离过大，先检查渲染配置与视场角是否一致，再怀疑数据版本。

def audit_semantics(scene_files):
    """核对每个场景的实例数、类别数与区域数，并做格式断言。"""
    rows = []
    for path in scene_files:
        entries = parse_semantic_meta(path)   # 行格式：索引 颜色 类名 区域号
        colors = [e.color for e in entries]
        assert len(colors) == len(set(colors))         # 场景内颜色唯一
        assert all(e.color in texture_colors(path) for e in entries)
        raw = {e.name for e in entries}
        rows.append({
            "scene": path.stem,
            "instances": len(entries),
            "raw_categories": len(raw),
            "regions": len({e.region for e in entries}),
        })
    n = len(rows)
    print("scenes", n,
          "inst/scene", round(sum(r["instances"] for r in rows) / n, 1),
          "regions/scene", round(sum(r["regions"] for r in rows) / n, 2))

    # 换算：660.4 实例/场景、14.35 区域/场景、46.0 实例/区域

解读：（1）三条断言与论文的自动化质检对应：颜色必须来自纹理、场景内颜色唯一、文本格式合法；把断言写进读取器可以拦截损坏样本。（2）统计口径取「实例、原始类别、区域」三个量，与论文的 660.4 / 14.35 / 46.0 三个均值对照；原始类别数与 40 个规范类别的映射分开记录，便于追踪同义标签问题。（3）跨场景汇总前要统一区域编号语义，不同版本的编号规则可能不同。

片段 3：ObjectNav 回合约束检查

def check_episode(ep, navmesh, targets, lo=1.0, hi=30.0):
    """检查单条 ObjectNav 回合的三条生成约束是否成立。"""
    start = ep["start_position"]
    assert navmesh.is_navigable(start), "起点必须可导航"
    goal_pts = nearest_target_points(navmesh, targets, ep["goal_category"])
    assert goal_pts, "目标类别在当前场景必须存在实例"
    geodesic = min(navmesh.geodesic_distance(start, g) for g in goal_pts)
    assert navmesh.reachable(start, goal_pts[0]), "目标必须从起点可达"
    assert lo <= geodesic <= hi, "起止测地距离必须落在区间内"
    return {"scene": ep["scene_id"], "geodesic": round(geodesic, 3),
            "goal_category": ep["goal_category"]}

# 生成规模参考：约 720 万训练 / 1072 验证 / 1000 测试
# 实算每训练场景约 49,655 条；测试集每场景约 28.6 条

解读：（1）三条约束与论文一致：起点可导航、目标可达、测地距离在 1 到 30 米之间；距离用测地线计算，避免把跨墙的欧氏近点误判为易回合。（2）目标类别必须是场景内真实存在的实例集合，空集合的回合直接丢弃；六类目标的分布要单独统计，防止类别失衡。（3）生成规模按每训练场景约 4.97 万条估算总量，与论文的约 720 万条口径对照；变更采样约束后必须重新统计，不能沿用旧密度。

常见坑

  • 混用资产版本与语义版本：场景能加载，评测数字却与论文对不上。根因是 HM3D 与 HM3DSEM 的清单、修复内容与回合集随版本变化。修复：数据卡片同时记录资产版本、语义版本、清单校验值与获取日期；跨版本比较前先对齐场景清单。
  • 把 800 / 100 / 100 与 145 / 36 / 35 混用：训练在 800 个无标注场景上，评测却引用 216 场景的语义划分，出现跨划分泄漏。根因是两个划分属于不同论文与不同资产子集。修复：训练与评测使用同一份冻结清单；报告中写明划分来源（HM3D 论文口径或 HM3DSEM 口径）。
  • 忽略许可范围：用非商业许可的资产训练模型后直接商用，或把场景图像放进公开演示。根因是只看论文的开放许可，未查数据资产的 Matterport 学术许可。修复：先记录许可链（资产、训练模型、派生数据），发布前逐项复核；对外演示只使用获批的场景。
  • 只看场景数不看缺陷率：选了大子集，训练收益却低于预期。根因是可导航面积与缺陷率决定有效信息量，场景数只反映名义规模。修复：筛选时同时报告缺陷率分布与可导航面积；用 560 个低缺陷场景作为高质量子集的起点。
  • 直接使用原始标签当类别体系：同一类目标在不同场景下被拆成多个标签或合并错误，指标波动。根因是 1,625 个原始标签到 40 个规范类别的映射未经核对。修复：固定映射版本，抽检目标类的实例；类别体系变更后重跑基线。
  • 把验证集数字当测试集引用：测试场景不公开，本地只能评测验证集。根因是榜单与本地协议不同。修复：报告时标清 split、回合数、成功判定与距离阈值；跨论文比较以官方榜单或统一复现协议为准。

小结

  • HM3D 提供 1000 个建筑级重建：10,600 个房间、约 1,920 层、112.5k 平方米可导航面积、365.42k 平方米楼层面积；单场景平均 112.5 平方米与 10.6 个房间；规模为 MP3D 的 3.72 倍可导航面积与 11.11 倍场景数。
  • 质量证据：缺陷视图占比低于 5% 的场景有 560 个（Gibson 为 175 个，比值 3.2）；渲染图像的 FID / KID 为 20.5 / 12.8，相对 MP3D 降低 15.98% / 26.01%，相对 Gibson 降低 47.84% / 49.80%。
  • 划分与评测资产：800 / 100 / 100 场景划分；PointNav 回合 800 万训练、2500 验证、2500 测试；10% 与 50% 消融显示性能与可导航面积近似线性（相关系数 0.88）。
  • 迁移证据：HM3D 训练的 PointNav 智能体在三个测试集上都不低于对应数据集训练的智能体；深度输入在 Gibson 测试达到 1.00 / 0.93，RGB 输入在 MP3D 测试为 0.85 / 0.71。
  • HM3DSEM 为 216 个场景标注 142,646 个实例与 3,100 个区域（每场景 660.4 个实例、每区域 46.0 个），纹理级格式给出像素精确边界；成本 14,200 人时，其中 640 小时用于纠错（4.51%）。
  • ObjectNav 跨数据集训练与挑战数据证实资产价值：RL 平均成功率 29.95，IL 为 28.86，ML 为 47.70；2022 年挑战提交量从 400 增至 1022，冠军方案 SPL 为基线的 2.92 倍；使用时必须对齐版本与非商业许可。
