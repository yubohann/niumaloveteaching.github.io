第一篇 · 任务、数据、仿真与评测地基

第 007 讲｜指标 II：SPL、OSR 与统计口径

本讲承接三个基础指标，把效率与停止误差纳入评价：先推导 SPL 并证明它等于成功率乘以成功集平均效率，再讲 OSR 的诊断价值与可被搜索放大的风险，最后给出标准误、聚类设计效应与配对检验的完整统计口径，让两个模型的数字之差能经得起追问。

  • 主题：SPL 推导 / OSR / 解码与集成影响 / 统计显著性
  • 关键公式：SPL = (1/N)·Σ Si·ℓi/max(pi, ℓi)；OSR = (1/N)·Σ 1[mint dG(vt, v*) < 3]；SE = sqrt(p(1−p)/N)
  • 预计学时：60 分钟
  • 前置讲：第 006 讲

学习目标

  • 会推导：由 SPL 定义推出分解式 SPL = SR × e（e 为成功集平均效率），并证明 0 ≤ SPL ≤ SR ≤ OSR ≤ 1。
  • 会算：对一批 episode 记录计算 SPL、OSR，并识别 max 分母、失败记 0 与抄近路封顶三类边界。
  • 会判断：贪婪、束搜索、候选重打分与集成分别把数字往哪个方向改变，报告时必须补齐哪些协议标注。
  • 会统计：用标准误、聚类设计效应与配对检验区分真实提升与噪声，写出可复核的比较结论。
  • 会设计：一张包含 SR、SPL、OSR、NE、TL 的报告口径表，以及一个以路径为聚类单位的重采样诊断方案。

背景与动机

第 006 讲建立了 NE、TL、SR 的严格口径。三个指标留下两个空白。第一，SR 只看是否到达，不区分高效到达与绕远到达：第 006 讲算例中的 D（折返成功）与 B（提前停止成功）在 SR 上没有差别，代价却不同。第二，SR 依赖停止决策，一个到过目标却继续行走的模型会被全部记失败，而它的识别能力可能并不差。SPL 与 OSR 分别针对这两个空白。

SPL 来自导航评测工作组的共识报告（Anderson 等，2018，arXiv:1807.06757）：报告在比较多种候选指标后，建议把「按路径长度加权的成功率」作为首要指标，写作 Success weighted by (normalized inverse) Path Length，简称 SPL（Recommendation 3）。报告同时指出这是一项严格的指标，在复杂未见环境中 SPL 达到 0.5 已是良好水平，并建议配合一组辅助指标共同报告。

OSR 来自 R2R 原文的 oracle 停止规则：允许智能体在轨迹上离目标最近的位置停止再判成功，用于把「识别目标」与「决定停下」两个难点分开（Anderson 等，2018，4.4 节）。随后的大量工作沿用该列数字，Speaker-Follower（Fried 等，2018，NeurIPS）把它定义为「在路径上离目标最近点判成功，允许越过后不受罚」。OSR 是诊断工具，直接当主指标会掩盖停止能力的缺陷。

最后是统计口径。评测集是有限样本：val-unseen 2,349 条指令、test 4,173 条指令，同一条路径的 3 条指令彼此相关，不同模型的预测又在同一批 episode 上配对出现。一个百分点量级的差异可能来自抽样波动，也可能来自解码与集成策略。本讲把这些因素拆开，给出「先配对、再聚类、后报告」的比较流程，并固定 R2R-CE 与 RxR-CE 验证集含已知标注讹误的提示，提醒跨协议数字不可拼表。

核心原理

1. SPL：从定义到分解

沿用第 006 讲的符号：第 i 个 episode 的成功指示 Si ∈ {0, 1}，最短路径长度 ℓi = dG(v0, v*)，实际路径长度 pi = Σt dG(vt, vt+1)，其中 pi 为停止时刻为止的轨迹长度。SPL 定义为：

SPL = (1/N) · Σi=1..N Si · ℓi / max(pi, ℓi) 成功 episode 按 ℓ/p 的效率因子加权；失败 episode 记 0；max 保证 pi 小于 ℓi 时因子被封顶为 1

把求和按成功与否拆开，可以推出一个更好用的分解式。设成功集为 C，成功数为 NS = Σi Si，则：

SPL = (NS / N) · (1/NS) · Σi∈C ℓi / max(pi, ℓi) = SR · e SR = NS/N；e 为成功集的平均效率，0 < e ≤ 1。推导中只用到求和重新分组，未引入近似

这个分解式有四个直接推论。第一，SPL 同时奖励成功与效率：任一因子提高，SPL 提高。第二，SPL ≤ SR 恒成立，因为 e ≤ 1（max 分母保证每项因子不超过 1）；失败集对 SR 与 SPL 都是 0，不破坏不等式。官方评测脚本正是用这条不等式做断言。第三，当且仅当所有成功 episode 都满足 pi ≤ ℓi 时 e = 1，此时 SPL = SR；第 006 讲 L 形走廊的 B 就是这种情形（TL 7.5 < ℓ 10，因子被封顶为 1）。第四，失败直接记 0，绕行的成功只损失效率因子，两类代价都进入同一个数字，SPL 的严格性由此而来。

共识报告给出三个教学算例，本讲用 Python 复算：50% 的 episode 成功且全部走最优路径，SPL = 0.50；全部成功但路程是最优的两倍，SPL = 0.50；50% 成功且成功集路程为最优两倍，SPL = 0.25。三个例子说明 SR 与效率可以互相替代地压低 SPL，只报其中一个会丢失信息。报告还建议以人类表现标定：在复杂未见环境中 0.5 属于良好水平（arXiv:1807.06757，第 4 节）。

用第 001 讲沿用至今的四条 episode 数据做一次完整分解（ℓ、p、NE 单位为米）：A (11.5, 12.0, 0.2)、B (8.0, 10.0, 2.1)、C (12.0, 9.0, 3.4)、D (10.0, 25.0, 1.2)。实算得到 SR = 0.7500，各条期望内的 SPL 因子为 0.9583、0.8000、0（C 失败）、0.4000，SPL = 0.539583，成功集平均效率 e = SPL / SR = 0.719444。D 的 NE 只有 1.2 m（成功），但 SPL 因子 0.4000；若 D 与最短路等长（因子 1.0000），SPL 会升到 (0.9583 + 0.8000 + 1.0000) / 4 = 0.6896，绕行使 SPL 损失 0.1500。这正是效率指标要暴露的对象。

2. OSR：把停止误差从识别误差中剥出来

oracle 成功率（Oracle Success Rate, OSR）把判定位置从「停止点」换成「轨迹上离目标最近的点」：

OSR = (1/N) · Σi=1..N 1[ mint dG(vt, v*) < 3 m ] t 遍历轨迹经过的视点；官方脚本先取最近视点再算距离，与逐点取最小等价；阈值口径与 SR 一致

三个性质需要记住。第一，OSR ≥ SR 恒成立：停止点是轨迹上的一个点，其距离不可能小于轨迹最小值；第 006 讲 F（到过目标却回到起点）给出 SR = 0 而 OSR = 1 的实例。第二，两者的差值衡量停止决策的代价；差值大说明模型到过目标附近但没在该处停下，差值小说明失败主要来自走错位置。第三，OSR 使用的最近点信息来自评测侧目标真值，它属于诊断工具，不能替代主指标，也不允许模型在推理时使用。

把公开数字代进来看差值：R2R 原文 student-forcing 在 val-seen 的 SR/OSR 为 38.6 / 52.9（差 14.3 个百分点），val-unseen 为 21.8 / 28.4（差 6.6），test 为 20.4 / 26.6（差 6.2）；人类在 test 为 86.4 / 90.2（差 3.8）。Speaker-Follower 的完整模型在 val-seen 为 70.1 / 78.3（差 8.2），val-unseen 为 54.6 / 65.2（差 10.6），test 为 53.5 / 63.9（差 10.4）。两组数字方向一致：停止是独立难点，且不会随识别能力自动消失。

OSR 也可以被搜索放大，需要警惕。Speaker-Follower 提交挑战赛的变体为了维持物理可行性并对齐提交规则，把 test OSR 从 63.9 抬到 96.0，同时轨迹长度从 11.63 m 涨到 1257.38 m：challenge 轨迹长度是标准推理的 108.1 倍、人类轨迹的 105.7 倍。这个极端例子说明：只报 OSR 的改进而隐去 TL 与 SPL，会把「穷举式搜索」包装成「识别能力提升」。报告 OSR 时必须同时报告 TL、SPL 与搜索协议。

3. 解码与集成对数字的影响

第 005 讲建立了动作空间与解码口径，本讲把它接到指标上。同一份动作分布，换解码规则就会换出一批不同的轨迹：贪婪解码（R2R 原文测试期口径）与小概率分支的保留策略对 SR、TL、SPL 的影响方向不同。用第 005 讲的概率表复算：贪婪路线联合概率 0.1800，束宽 2 找到 0.3600 的路线，数值翻倍；但束宽扩大到 10，按几何衰减假设的 top-K 质量从 0.3000 升到 0.9718，收益递减，计算量近似线性增长。束搜索的候选覆盖不同长度的轨迹，原始对数概率之和系统性偏向短轨迹，加入长度归一化会改变偏好方向；无论采用哪种，报告中必须写明 K、长度归一化指数与停止处理。

候选重打分是另一种解码变体。Speaker-Follower 用状态因子化搜索生成 K = 40 条候选路径，再分别用跟随器打分与加入说话者重打分：val-unseen 的成功率从只重排的 30.5% 提到 39.3%（+8.8 个百分点）。这个提升来自候选生成加模型组合，不能归因于底座模型参数变化。对比实验要把「底座模型」「候选生成」「重打分器」三者拆开，否则提升无法归因。

集成（ensemble）的效果取决于成员误差的相关性。做一个最小模型：两个模型在每条 episode 上的成功率都是 p = 0.20，共同成功的比例为 p·q（q 为在 A 成功条件下 B 也成功的概率）。若集成在候选层面「至少一个成员成功即有机会成功」，则集成成功率上界为 2p − pq = 0.40 − 0.20q。实算：q = 1.00（两个模型完全相同）时上界 0.20，提升 0；q = 0.75 时为 0.25（+5.0 个百分点）；q = 0.50 时为 0.30（+10.0）；q = 0.20（接近独立）时为 0.36（+16.0）；q = 0.00（完全互补）时为 0.40（+20.0）。结论是：集成的收益来自成员之间的分歧；报告集成结果时必须报告成员数量、挑选规则与是否在同一验证集上选择成员。没有这些标注，+16 个百分点可能只是把错误相关性调低了。

还有一层数据协议的影响容易被忽略。官方仓库的 test 提交流程在训练时合并 train、val_seen、val_unseen 三个 split（仓库 train.py 的 test_submission），而验证集数字来自只用 train 训练的快照。同一篇论文的 val 列与 test 列，训练数据量不同；引用数字对比时必须先确认「训练数据口径」一致。

4. 统计口径：从点估计到可比较结论

SR 是伯努利变量的均值，标准误为 SE = sqrt(p(1−p)/N)。实算：val-seen（N = 1,020，p = 0.386）SE = 1.52 个百分点；val-unseen（N = 2,349，p = 0.218）SE = 0.85；test（N = 4,173，p = 0.204）SE = 0.62。95% 区间的半宽约为 1.96 倍标准误：val-unseen 为 1.67 个百分点。据此，两个独立模型在 val-unseen 上相差 1.7 个百分点以内时，用两倍标准误的粗判据无法下结论。

聚类会让标准误被低估。R2R 每 3 条指令共享同一条路径，同一路径上的成功与失败高度相关。若把每条指令当独立样本，就忽略了组内相关。设计效应（design effect）的近似为 DE = 1 + (m − 1)·ICC，其中 m = 3 为每簇指令数，ICC 为组内相关系数。实算：ICC = 0.1 时 DE = 1.2，等效样本量 1,958，SE 从 0.85 升到 0.93 个百分点；ICC = 0.3 时 DE = 1.6，等效 1,468，SE = 1.08（放大 1.265 倍）；ICC = 0.5 时 DE = 2.0，等效 1,174，SE = 1.20（放大 1.414 倍）。路径级重采样（按路径整簇抽取再做 bootstrap）能自动包含簇相关，是更稳妥的做法，推荐重采样次数不少于 10,000。

配对比较比独立比较更有力。两个模型跑同一批 episode，可以把结果拆成四格：都对、都错、A 对 B 错、A 错 B 对；后两格称为不一致对。McNemar 检验只用不一致对：χ² = (|b − c| − 1)² / (b + c)（b、c 为两类不一致对的计数，1 为连续性校正）。用 val-unseen 的数据构造算例：N = 2,349，模型 A SR = 21.8%，模型 B SR = 23.5%，差 1.7 个百分点，对应 b − c ≈ 39.9。若不配对，两独立比例之差的标准误为 1.22 个百分点，z = 1.39，落在常规显著阈值以内；若配对且不一致对总数 100（b = 70、c = 30），χ² = 15.21，p = 9.6 × 10⁻⁵，结论显著；若不一致对总数 200（b = 120、c = 80），χ² = 7.61，p = 5.8 × 10⁻³，仍然显著；若不一致对总数只有 60（b = 50、c = 10），χ² = 25.35，p = 4.8 × 10⁻⁷。可见同一 1.7 个百分点的差距，能否下结论取决于不一致对的数量，也就是两个模型的错误是否落在同一批样本上。

最后是多随机种子与多重比较。单次训练的数字包含种子波动，建议至少 3 个种子并报告均值与标准误；调参只在 val 上进行，test 只评估一次；在同一批验证集上比较多个方法时，把训练集划分、解码协议与评测脚本全部固定，否则显著性检验的名义覆盖率失效。共识报告给出的辅助指标清单可以直接作为报告的检查表：归一化逆距离下的成功率曲线、归一化的终点距离、阈值扫描下的 SPL、归一化逆路径长度分布、碰撞等违规次数、执行时间与能量（arXiv:1807.06757，第 4 节）。

实现思路与设计

评测代码在第 006 讲计算核之上增加三块：SPL 与 OSR 的累加、统计诊断、报告生成。设计目标是让每个数字都能追溯到 episode 记录与协议字段。

比较流程

报告两个模型的比较结论时按顺序执行：先固定评测脚本、协议与解码参数；再在同一批 episode 上收集配对结果并计算不一致对；然后按路径聚类做 bootstrap 或设计效应修正；最后报告差值、置信区间与检验结果，并附上集成成员、搜索候选数与训练数据口径。若差值落在噪声范围，报告「未观察到显著差异」并给出最小可检测差值，避免把点估计当作结论。与第 008 讲的衔接在于：SR 与 SPL 都不度量路径是否尊重指令的中间约束，R4R 与 CLS 正是对路径保真的补充。

关键代码与解读

三段代码分别实现 SPL 与 OSR 汇总、配对与聚类修正统计、路径级 bootstrap。输出数值均由 Python 实算，与正文一致。

片段 1：SPL 与 OSR 汇总

def summarize(records, margin=3.0):
    """records 字段：ne、oracle、tl、shortest；返回 SR/SPL/OSR 与断言。"""
    n = len(records)
    sr = sum(1 for r in records if r["ne"] < margin) / n
    osr = sum(1 for r in records if r["oracle"] < margin) / n
    spl = 0.0
    for r in records:
        if r["ne"] < margin:
            l, p = r["shortest"], r["tl"]
            spl += l / max(p, l)          # 抄近路时封顶为 1
    spl /= n
    assert spl <= sr + 1e-9               # SPL = SR * e, e <= 1
    assert sr <= osr + 1e-9               # 停止点是轨迹上的点
    return {"sr": sr, "spl": spl, "osr": osr}

# 算例：C 的 oracle 误差 3.1 m 越过阈值，OSR = 0.75，与 SR 相同

eps = [
    {"ne": 0.2, "oracle": 0.0, "tl": 12.0, "shortest": 11.5},   # A
    {"ne": 2.1, "oracle": 2.0, "tl": 10.0, "shortest": 8.0},    # B
    {"ne": 3.4, "oracle": 3.1, "tl": 9.0, "shortest": 12.0},    # C 失败
    {"ne": 1.2, "oracle": 0.1, "tl": 25.0, "shortest": 10.0},   # D 绕行
]
print(summarize(eps))
# {'sr': 0.75, 'spl': 0.539583..., 'osr': 0.75}

解读：（1）SPL 只在成功条目上累加，失败自动记 0，与官方脚本一致；max 封顶处理 p < ℓ 的情形。（2）两条断言把第 1 小节的两个不等式直接写进代码，任何违反都说明记录或计算有错。（3）算例中 OSR = 0.75 与 SR 相同：C 的最近点误差 3.1 m 越过阈值，不构成 oracle 成功，说明阈值同样作用于 OSR；若把 C 的 oracle 改成 2.9，SR 不变而 OSR 升到 1.0，读者可自行复算。

片段 2：标准误、设计效应与配对检验

import math

def se_bernoulli(p, n):
    return math.sqrt(p * (1 - p) / n)

def design_effect(m, icc):
    return 1 + (m - 1) * icc

def mcnemar(b, c):
    """不一致对计数；带连续性校正，返回卡方与 p 值。"""
    chi2 = (abs(b - c) - 1) ** 2 / (b + c)
    p = math.erfc(math.sqrt(chi2 / 2.0))   # 1 自由度卡方的生存函数
    return chi2, p

print("SE val_unseen:", round(se_bernoulli(0.218, 2349), 4))
print("SE x sqrt(DE):", round(se_bernoulli(0.218, 2349) * math.sqrt(design_effect(3, 0.3)), 4))
print("McNemar b=70 c=30:", ["%.2e" % v for v in mcnemar(70, 30)])
# SE val_unseen: 0.0085
# SE x sqrt(DE): 0.0108
# McNemar b=70 c=30: ['1.52e+01', '9.62e-05']

解读：（1）伯努利标准误只适用于条目独立的情形；乘以 sqrt(DE) 得到聚类修正后的近似值，ICC = 0.3、每簇 3 条指令时标准误从 0.85 升到 1.08 个百分点。（2）McNemar 只使用不一致对，示例 χ² = 15.21、p ≈ 9.6 × 10⁻⁵，说明即使总样本很大，结论仍取决于不一致对规模。（3）p 值用 erfc 实现 1 自由度卡方生存函数，避免引入额外依赖；生产代码建议直接调用统计库并记录版本。

片段 3：路径级 bootstrap 置信区间

import random

def bootstrap_ci(clusters, metric, draws=10000, alpha=0.05, seed=1):
    """clusters 为路径列表，每条路径含 3 条指令记录；整簇重采样。"""
    rng = random.Random(seed)
    n = len(clusters)
    vals = []
    for _ in range(draws):
        sample = [clusters[rng.randrange(n)] for _ in range(n)]
        flat = [r for cl in sample for r in cl]
        vals.append(metric(flat))
    vals.sort()
    lo = vals[int(alpha / 2 * draws)]
    hi = vals[int((1 - alpha / 2) * draws) - 1]
    return lo, hi

def sr_of(recs):
    return sum(1 for r in recs if r["ne"] < 3.0) / len(recs)

解读：（1）重采样单位是路径；同路径三条指令始终一起进出样本，从而反映聚类相关。（2）区间取百分位法，实现简单、可复核；样本极不平衡时可改用 BCa 等改进方法。（3）固定随机种子保证区间可复现；报告时写明重采样次数、单位与种子，三项缺一不可。

常见误区

  • SPL 分母漏掉 max：抄近路的 episode 因子大于 1，SPL 超过 SR，被官方断言拦下或悄悄污染结论。根因：直接用 ℓ/p 计算，未处理 p < ℓ 的成功样本。修复：分母写 max(p, ℓ)，并保留 SPL ≤ SR 断言；单独统计 p < ℓ 的比例，判断封顶是否频繁触发。
  • 把 OSR 当主指标报：表里只有 OSR，看起来比 SR 高得多，停止缺陷被隐藏。根因：OSR 使用了评测侧目标真值与最近点判定。修复：OSR 只作诊断列，与 SR、TL、SPL 同表；搜索变体必须附候选数与长度上限。
  • 跨数据集比较 SPL：把 R2R 的 SPL 与另一基准的 SPL 并排下结论。根因：ℓ 分布、阈值、动作空间与场景规模不同，SPL 没有跨集绝对标尺。修复：只在同一批 episode 上比较智能体；跨集比较使用相对人类的归一化或退回定性讨论。
  • 忽略聚类做显著性：标准误被低估三分之一以上，小差异被误判显著。根因：每路径 3 条指令相关，条目独立假设不成立。修复：路径级 bootstrap 或设计效应修正；报告 ICC 假设或直接展示整簇重采样区间。
  • 解码与训练数据口径不说明：两个数字看似可比，实际一个用贪婪、一个用束搜索，或者一个在 test 提交时合并了验证集。根因：解码规则与训练数据范围改变轨迹与指标。修复：每张表标注解码方式（贪婪 / 束宽 / 候选重打分）、长度归一化与训练 split 组合，缺省视为不可比。

练习与思考

  1. 四条 episode 的 (ℓ, p, 成功) 为：E1 (10, 12, 是)、E2 (8, 8, 是)、E3 (12, 15, 否)、E4 (9, 6, 是)。计算 SPL 与成功集平均效率 e，并说明哪一条对 SPL 的拖累最大。 ★
    提示
    SPL 因子依次为 10/12 = 0.8333、1.0000、0、9/max(6,9) = 1.0000；SPL = 0.7083，SR = 0.75，e = 0.9444。E1 的绕行把 SPL 从 0.75 拉到 0.71 以下；E4 因封顶不产生惩罚，可据此讨论 max 的副作用。
  2. 证明 SPL ≤ SR，并给出等号成立的条件。再用一个 p < ℓ 的成功 episode 说明为什么不能把因子写成 p/ℓ。 ★
    提示
    分解式 SPL = SR · e，每项因子 ℓ/max(p, ℓ) ≤ 1，故 e ≤ 1；等号当且仅当所有成功 episode 满足 p ≤ ℓ（含相等）。若把因子写成 p/ℓ，p < ℓ 的成功样本（停在容差内、实际路程更短）会被额外折扣，封顶设计失效；p > ℓ 的绕行样本因子大于 1，还可能把 SPL 抬到 SR 之上。两个方向的错误都与效率的含义相反。
  3. 某模型在 val-unseen（N = 2,349）上 SR = 21.8%，另一个模型 SR = 23.5%。若两者独立，差值的标准误是多少？若两个模型的不一致对为 b = 70、c = 30，用 McNemar 检验的结果是什么？说明两种判断为何不同。 ★★
    提示
    独立比较：SE = sqrt(0.218×0.782/2349 + 0.235×0.765/2349) ≈ 1.22 个百分点，z ≈ 1.39，不显著。配对：χ² = (40 − 1)² / 100 = 15.21，p ≈ 9.6 × 10⁻⁵，显著。差异来自配对利用了「错误是否落在同一批 episode」的信息，配对检验的方差远小于独立比较。
  4. 某模型在 val-unseen 上 SR = 21.8%（N = 2,349），按路径聚类、ICC = 0.3、每簇 3 条指令，计算设计效应、等效样本量与修正后的标准误；再计算 95% 区间的近似半宽，并说明它与未修正值差多少。 ★★

    DE = 1 + 2 × 0.3 = 1.6；等效样本量 2,349 / 1.6 ≈ 1,468；修正 SE = sqrt(0.218×0.782/1468) ≈ 1.08 个百分点，未修正为 0.85；95% 半宽从 1.67 扩大到约 2.12 个百分点（1.96 × 1.08）。
  5. 设计一个「解码变体对照 + 集成 + 显著性」的组合实验，回答「提升 1.5 个百分点是否可信」。要求：（a）列出至少三个对照臂与各自固定的参数；（b）给出配对与聚类的统计流程；（c）说明怎样防止集成成员在验证集上挑选造成乐观偏差；（d）给出两个可能推翻结论的失效模式。 ★★★
    提示
    （a）臂：贪婪基线、束宽 K 与长度归一化固定、候选重打分；全部用同一底座权重与同一评测脚本。（b）先做路径级配对表，取不一致对做 McNemar，再用整簇 bootstrap 给差值区间；报告最小可检测差值。（c）成员按训练种子预注册，不在验证集上挑选成员组合；若必须选择，用独立划分估计选择后的效果。（d）失效模式：解码变体改变轨迹长度分布导致 SPL 与 SR 方向相反；验证集反复调参使名义 p 值失效，需固定协议或做嵌套验证。

小结

  • SPL = (1/N)·Σ Si·ℓi/max(pi, ℓi)，可分解为 SR × e；失败记 0，p < ℓ 时封顶为 1，恒有 SPL ≤ SR。
  • 教学分解：四 episode 算例 SR = 0.7500、SPL = 0.539583、e = 0.719444；D 的 NE 很低但绕行 2.5 倍，SPL 因子仅 0.4000。
  • OSR 取轨迹最近点，恒有 SR ≤ OSR；公开数字的差值为 3.8 至 14.3 个百分点，停止是独立难点。challenge 变体 OSR 96.0 对应 TL 1257.38 m（标准推理的 108.1 倍），说明 OSR 可被搜索放大。
  • 解码与集成改变数字：状态因子化搜索加说话者重打分把 val-unseen 从 30.5% 提到 39.3%；集成收益取决于成员误差相关性（p = 0.2 时上界从 0.20 到 0.40）。
  • 统计口径：val-unseen 的 SR 标准误 0.85 个百分点，ICC = 0.3 的聚类修正后为 1.08；配对 McNemar 在 100 个不一致对上可把 1.7 个百分点的差异判为显著，独立比较则不能。
