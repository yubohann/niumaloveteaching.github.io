第一篇 · 任务、数据、仿真与评测地基

第 019 讲｜AerialVLN / CityNav：空中与城市

本讲把语言导航从地面推到空中：AerialVLN 用 AirSim 与虚幻引擎搭建 25 个城市级场景，定义四自由度动作与 20 米着陆口径；CityNav 把任务放到真实城市点云上，给出 32,637 条人类示范轨迹与地理语义图辅助输入。本讲给出室内、空中、城市三档任务的统一对比与全部规模算例。

  • 主题：空中 VLN / 无人机动作空间 / 真实城市数据 / 地理语义图
  • 关键数字：AerialVLN 8,446 条路径、25,338 条指令、平均 661.8 米；CityNav 32,637 条轨迹、4.65 平方公里
  • 预计学时：60 分钟
  • 前置讲：第 018 讲（Habitat：平台架构与任务接口）

学习目标

  • 复述 AerialVLN 的任务定义、四自由度动作空间与 20 米着陆成功判定，并说明它与地面任务的差异。
  • 会算：两套数据集的规模、路径与动作统计，核算指令长度、动作数、路径长度的倍数关系与标注成本。
  • 会判断：区分合成城市（AerialVLN）与真实城市（CityNav）的数据来源、任务含义与泛化口径。
  • 会设计：地理语义图（Geographic Semantic Map, GSM）的通道构成与接入位置，写出噪声鲁棒性与人类示范对照实验。
  • 会诊断：长路径、停止失败与垂直维度误用造成的评测偏差，能给分层诊断表。

背景与动机

前几讲的任务都发生在地面：013 的 REVERIE 在室内指代目标，014 的场景描述与 015 的对话导航在地面全景图上，016 的 Touchdown 走到街道级。空中场景的应用动机是配送、巡检、搜救与航拍导览，任务难度在三个维度上同时上升：动作从平面扩展到三维（高度与横移），空间关系推理从人眼高度转为俯视与斜视，路径尺度从十米级跃升到数百米级。

AerialVLN（Liu 等 2023，ICCV 2023，arXiv:2308.06735v1）是这一方向的城市级合成基准：用虚幻引擎 4 与 AirSim 搭建 25 个城市场景，由持证飞手采集 8,446 条飞行路径，平均路径长度 661.8 米，是 R2R 的 66.2 倍。CityNav（Lee 等 2024，ICCV 2025 接收，arXiv:2406.14240v3）走真实数据路线：基于 SensatUrban 的真实城市三维扫描，在剑桥与伯明翰两个城市上采集 32,637 条人类示范轨迹，覆盖 4.65 平方公里，并引入地理语义图作为辅助输入。两者一合成一真实，正好构成空中任务的口径对照。

还有一个来自基准结果的动机：AerialVLN 上最优基线的未见环境成功率只有 1.0% 至 1.6%，人类达到 80.8%；CityNav 上引入地理语义图后模型成功率为 6.72%，人类为 87.86%。空中任务与人类能力的差距远大于同期的地面任务，而地面任务的经验不能直接迁移：动作空间、成功阈值、视场与路径尺度都发生了变化。

本讲解决三件事：把两套任务的接口与评测口径讲清；把规模、动作与指令的统计做成可复核的算例；用一张室内、空中、城市三档对比表收束第一篇的任务地图，为 020 讲复盘与第三篇（052、053 讲）的深入展开铺垫。

核心原理

1. AerialVLN：任务定义与四自由度动作

AerialVLN 的 episode 从初始位姿 P = [x, y, z, pitch, roll, yaw] 开始，智能体收到自然语言指令与第一人称 RGBD 观察，输出动作直到选择停止。动作空间包含 8 个低层动作：前进（forward）与左移、右移各平移 5 个单位（模拟环境中 1 单位等于 1 米），上升与下降各 2 个单位，左转与右转各 15 度，以及停止。深度传感器量程 100 米。环境支持动态元素：车辆行驶、树叶摆动、晨昏光照与多种天气，语义分割也作为可观察项提供。

A = {forward(+5 m), left(+5 m), right(+5 m), ascend(+2 m), descend(−2 m), turn±15°, stop} 四自由度：水平前后、水平横移、垂直升降、偏航；起飞后不控制滚转与俯仰，与多旋翼的常见遥控档位对应

成功判定与地面不同：停止点进入以目标为球心、半径 20 米的球域记成功。论文给出的依据是 20 米接近多数国家直升机停机坪的尺度；对照环境平均半径 3867.8 米，成功球半径只占 20 / 3867.8 ≈ 0.52%。评价指标为成功率（SR）、oracle 成功率（OSR）、导航误差（NE）与按归一化动态时间规整加权的成功率（SDTW）。

与 VLN-CE 的动作接口对比：两者都是低层动作，但 AerialVLN 多出横移与升降两个平移方向，转向从 15 度起步、单步位移从 0.25 米放大到 2 至 5 米。动作尺度变大使长路径成为可能，也把停止判定推上主要矛盾：停止点与目标相距数十米仍属常见误差，而 20 米球域直接决定成败。

2. AerialVLN 数据集：规模、切分与语言现象

场景由虚幻引擎 4 与 AirSim 渲染，共 25 个城市级环境，覆盖市中心、工厂、公园与村落，包含 870 余种物体。路径由持有 AOPA 证书的飞手遥控采集，指令由众包工人根据飞行视频撰写，每条路径配 3 条；采集端还做了子路径与子指令的对齐，用于细粒度跨模态匹配训练。

语言学统计给出任务的语言难度画像：在随机抽样的 25 条指令中，参考表达出现率 100%、平均每条 9.7 次；顺序表达出现率 68%、平均 3.7 次；异我中心空间关系出现率 56%、平均 4.6 次；时间条件出现率 76%、平均 5.6 次。作为对照，R2R 的异我中心关系出现率 20%、平均 0.2 次。空中指令的难点集中在多物指代与序列化的空间描述上，单句理解不足以支撑决策，需要把「先到桥、再左转、飞过带招牌的五层楼」这类链条展开为动作计划。

3. AerialVLN 的基线与失败模式

论文评测了随机、按训练分布采样、LingUNet、Seq2Seq、跨模态注意力（CMA）五个基线与一个人工组。地面任务的经典基线在这里全面受挫：完整数据集上，Seq2Seq 与 CMA 在未见 split 的成功率为 1.0% 至 1.6%，人类在 test 为 80.8%（NE 73.5 米）。CMA 的 NE 为 358.6 米，是人类误差的 4.88 倍；成功率相差 50.5 倍。

论文的失败分析给出两条结论。第一，路径长度主导成功率：把测试集按路径长度分为两组，长路径组（平均 813.2 米）成功率 1.8%，短路径组（平均 326.9 米）为 7.4%，短路径组的成功率约为长路径组的 4.11 倍；模型能在轨迹早期跟随指令，一旦偏离就难以回正。第二，停止判定是独立难点：OSR 显著高于 SR，说明智能体多次经过目标附近却未能停下。这两条与第 017 讲连续环境的观察一致，只是尺度被放大。

论文还给出两条工程手段。数据聚合（Dataset Aggregation, DA）用模型自身动作采样缓解训练与测试的分布错位，在小场景变体 AerialVLN-S 上把 CMA 的未见成功率从约 3.2% 提到 4.5%；前瞻引导（Look-ahead Guidance, LAG）在训练时不按当前位置到目标的最短路生成监督动作，改为先回到真值路径、沿真值路径前瞻 10 步，再用到该点的最短路生成当前监督，在 AerialVLN-S 上取得 4.5%（test）与 5.1%（val-unseen）的成功率。模态消融显示视觉与语言缺一不可：去掉视觉后未见 SR 从 4.5% 降到 1.3%，去掉指令降到 2.1%；RGB 与深度同时保留最好，去掉 RGB 的损失大于去掉深度。

4. CityNav：真实城市与地理语义图

CityNav 把任务放到真实城市的三维点云上。场景来自 SensatUrban 的城市级扫描，覆盖剑桥与伯明翰共 4.65 平方公里。运行环境 CityFlight 基于开源 WebGL 点云渲染器 Potree 构建，在浏览器中运行，支持众包标注；仿真与 OpenStreetMap 同步，智能体可获得自身的 GNSS 坐标（地理语义图的视野与已探索区域由它推导），但目标坐标不在观察之列。

p = (x, y, z, θ, ψ) ∈ ℝ5，A = {move-forward(5 m), turn-left(30°), turn-right(30°), ascend(2 m), descend(2 m), stop} 五维位姿不含滚转；目标由 CityRefer 提供的自然语言描述指定，至少含一个地标并描述空间关系；起始点位于目标 500 米半径内，高度 100 至 150 米，飞行上限 200 米

任务成功判定同样取 20 米球域：停止点进入以目标坐标为中心、半径 20 米的球。指标为 NE、SR、OSR 与 SPL。做一个量级演算：起始距离通常约 200 米，随机停止命中 20 米球的体积比约为 (20/200)3 = 0.1%，截面比约为 1%；基准模型 6.72% 的成功率远高于盲猜，但距离人类 87.86% 仍有 13.1 倍的差距。

数据采集的规模与成本值得单独核算。171 名通过资格测试的标注者在浏览器里完成 32,637 条示范轨迹，每条轨迹配一段描述；总标注工时 711 小时，按每小时 12.83 美元计，实算成本 711 × 12.83 = 9,122.13 美元（论文记为 9,123 美元，四舍五入）。把工时摊到轨迹：711 × 3600 / 32,637 ≈ 78.4 秒一条；人均完成 32,637 / 171 ≈ 190.9 条。质量流程分三段：资格测试筛掉低效标注者；首轮采集中 18.4% 未达成功标准的轨迹被剔除；重采后仍有 7.2% 的目标没有合格轨迹，从数据集中删除。目标类型以建筑（48.3%）与车辆（40.7%）为主，另含地面（7.4%）与停车场（3.6%）。

轨迹统计：平均动作数 240 步，论文报告轨迹总长度 17.8 × 106 米，除以 32,637 条得平均 545.4 米，对应每动作平均位移 545.4 / 240 ≈ 2.27 米（混合了 5 米前移、2 米升降与 30 度转向）。切分为：train 22,002 条与 val-seen 2,498 条共享 24 个场景，val-unseen 2,826 条（4 个场景），test-unseen 5,311 条（6 个场景），四行相加 32,637 条，与总量一致。

5. 地理语义图：把地图变成辅助模态

CityNav 的核心方法是地理语义图（GSM）：一张与二维地图对齐的多通道二值掩码，五类通道分别是当前视场、已探索区域、地标（来自 OpenStreetMap 的道路与地物段）、潜在目标与周边物体（由 Grounding DINO 检测）。地标与物体名称由语言模型（论文使用 GPT-3.5）从描述中抽取。GSM 经一个小型五层卷积网络编码为特征向量，追加到 RGB 与深度特征之后送入策略的 GRU 输入端。

三条读数。第一，地理语义图对所有基线都带来大幅增益：AerialVLN 模型的 SR 从 1.79% 升到 6.72%（3.75 倍），NE 从 187.7 米降到 85.1 米（下降 54.7%）。第二，消融显示地标信息最关键：去掉地标后 SR 降到 0.60%、NE 升到 190.7 米；去掉潜在目标与周边物体分别降到 3.97% 与 5.17%。第三，训练数据的来源影响鲁棒性：用人类示范训练的模型优于用最短路训练的模型，且差距在扰动下扩大。测试时对智能体位置加入 ±100 米高斯噪声，最短路训练与人类示范训练的 NE 差距从 10.0 米（95.1 对 85.1）扩大到 28.1 米（123.1 对 95.0）；论文的解释是人类示范带有更多轨迹多样性，策略学会了更稳的停止与纠偏行为。

7. 适用边界与失效模式

  • 合成与真实的边界：AerialVLN 的观测为游戏引擎渲染，天气与光照可配置但物理真实度有限；CityNav 来自真实扫描，但覆盖范围限于两座城市，向全球城市外推缺少证据（论文自述局限）。
  • 成功阈值属协议：20 米球域对长路径宽松、对短路径严格；报告 SR 必须同时给出 NE 分布与 OSR，避免把「路过目标」的表现与「停在目标」混为一谈。
  • 垂直维度不可省略：NE 为三维距离，若实现里只用水平距离，升降误差被系统性低估；成功判定与失败分析都要按三维计算。
  • 地理信息的边界：CityNav 不给目标坐标，但提供自身 GNSS 与地图数据；把目标坐标、真值轨迹或标注地标框喂给策略都超出任务定义，会高估感知能力。
  • 算力与数据规模：空中数据集轨迹长、观察序列长；完整复现需要多卡训练，课程建议按小场景变体（AerialVLN-S）或单城市子集起步（052、053 讲给出档位）。

关键代码与解读

片段 1：四自由度动作的位姿更新与路径效率核算

import math

STEPS = {"forward": 5.0, "left": 5.0, "right": 5.0, "up": 2.0, "down": 2.0}
TURN = math.radians(15)

def step_pose(pose, action):
    """四自由度位姿更新：水平位移按 yaw 合成，升降直接改高度。
    pose = (x, y, z, yaw)，动作集合取 AerialVLN 与 CityNav 的公共项演示。"""
    x, y, z, yaw = pose
    if action == "turn_left":
        return (x, y, z, yaw + TURN)
    if action == "turn_right":
        return (x, y, z, yaw - TURN)
    if action == "up":
        return (x, y, z + STEPS["up"], yaw)
    if action == "down":
        return (x, y, z - STEPS["down"], yaw)
    if action in ("forward", "left", "right"):
        offset = {"forward": 0.0, "left": math.pi / 2, "right": -math.pi / 2}[action]
        d = STEPS[action]
        return (x + d * math.cos(yaw + offset),
                y + d * math.sin(yaw + offset), z, yaw)
    raise ValueError(action)

pose = step_pose((0.0, 0.0, 120.0, 0.0), "forward")   # (5.0, 0.0, 120.0, 0)
pose = step_pose(pose, "turn_left")                    # yaw = 0.261799 rad
pose = step_pose(pose, "up")                           # z = 122.0
print(tuple(round(v, 3) for v in pose))                # (5.0, 0.0, 122.0, 0.262)
print(round(545.4 / 240, 2))                           # 2.27 米/动作（CityNav 实算）

解读：（1）水平位移统一由 yaw 与相对方位角合成，横移等价于附加 ±90 度偏移的平移；把动作语义写在一个函数里，方便对照不同数据集的位移尺度。（2）升降不与 yaw 耦合，体现四自由度设计；真实旋翼还有滚转与俯仰，任务把这两维锁死以降低控制难度。（3）最后一行把论文总长度为 17.8 × 106 米、平均 240 步的 CityNav 轨迹折算为每动作 2.27 米，用于检查动作尺度估算与真值统计是否自洽。

片段 2：地理语义图的五通道构造

import numpy as np

CATEGORIES = ["current_fov", "explored", "landmarks",
              "potential_goals", "surroundings"]

def stroke_segment(mask, p0, p1, width=1):
    """把一条线段以给定宽度画进二值掩码，模拟地标线要素的栅格化。"""
    n = int(np.hypot(p1[0] - p0[0], p1[1] - p0[1])) + 1
    for t in np.linspace(0.0, 1.0, n):
        x = int(round(p0[0] + t * (p1[0] - p0[0])))
        y = int(round(p0[1] + t * (p1[1] - p0[1])))
        mask[max(0, y - width):y + width + 1, max(0, x - width):x + width + 1] = 1.0

def build_gsm(h, w, pose_xy, radius_cells, landmarks, goal_box, object_boxes):
    """五通道地理语义图（骨架实现）。
    视野与已探索区域由自定位坐标推导；地标来自地图；后两类来自检测器。"""
    gsm = np.zeros((len(CATEGORIES), h, w), dtype=np.float32)
    yy, xx = np.mgrid[0:h, 0:w]
    dist = np.hypot(xx - pose_xy[0], yy - pose_xy[1])
    gsm[0] = (dist <= radius_cells).astype(np.float32)   # 当前视场（圆近似）
    gsm[1] = gsm[0]                                     # 已探索区域（演示用同一掩码）
    for p0, p1 in landmarks:
        stroke_segment(gsm[2], p0, p1)
    x0, y0, x1, y1 = goal_box
    gsm[3, y0:y1, x0:x1] = 1.0
    for x0, y0, x1, y1 in object_boxes:
        gsm[4, y0:y1, x0:x1] = 1.0
    return gsm

gsm = build_gsm(256, 256, (128, 128), 60, [((40, 40), (200, 60))],
                (150, 150, 170, 170), [])
print(gsm.shape, int(gsm[2].sum()), int(gsm[3].sum()))
# 输出 (5, 256, 256) 529 400：五通道、地标线段栅格化与检测框写入

解读：（1）五通道掩码是任务定义的一部分：视野与已探索区域需要自定位坐标，地标来自地图数据，潜在目标与周边物体来自开放词表检测；三者来源不同，接口上分开注入便于消融。（2）掩码与二维地图同分辨率对齐，编码器是小卷积网络；论文把编码结果追加到 RGB 与深度特征之后送入循环单元，实现上只需一次拼接。（3）打印出的 529 与 400 分别是线段像素数与检测框像素数，用于检查栅格化正确性；真实实现还需按地图分辨率换算米制尺度。

片段 3：20 米球成功判定与位置噪声评估

import numpy as np

def success_at(stop_xyz, goal_xyz, radius=20.0):
    """空中任务成功判定：停止点进入以目标为球心、半径 20 米的球域。"""
    d = np.linalg.norm(np.asarray(stop_xyz, dtype=np.float64) - np.asarray(goal_xyz))
    return float(d <= radius)

def noisy_positions(xyz, sigma_m, n, seed=0):
    """位置噪声评估：对同一停止点做 n 次高斯扰动，返回样本矩阵。"""
    rng = np.random.default_rng(seed)
    base = np.asarray(xyz, dtype=np.float64)
    return base + rng.normal(0.0, sigma_m, size=(n, 3))

goal = np.array([205.0, 104.0, 132.0])
stop = np.array([200.0, 100.0, 130.0])
print(success_at(stop, goal))                          # 1.0，距离约 6.7 米
samples = noisy_positions(stop, 100.0, 8, seed=7)      # ±100 米量级扰动
print([success_at(p, goal) for p in samples])
# 示例种子下 8 次采样全部脱靶（样本到目标 39.5 至 300.7 米）；sigma 减小时命中率上升。

解读：（1）成功判定严格按三维球域计算，水平距离会低估升降误差，禁止替换。（2）噪声函数固定随机种子，保证鲁棒性实验可复现；对照实验中分别用最短路训练与人类示范训练的模型，观察命中率差距随扰动强度的放大。（3）该评估只扰动评测时的位置输入，不改变任务定义；论文报告噪声下两种训练数据的 NE 差距从 10.0 米扩大到 28.1 米，可用同一函数复现趋势。

常见坑

  • 把 20 米阈值与室内 3 米混用：直接跨数据集比较 SR，得出「空中任务更简单」的结论。两者的阈值相对环境尺度的比例不同。修复：报告阈值、环境尺度与成功球半径的相对比例，跨任务只看 NE 分布形态。
  • NE 只用水平距离：垂直方向误差被忽略，升降动作的正确性无法评估。修复：按三维距离计算 NE 与成功判定，失败分析中单列高度误差。
  • 把目标坐标或真值轨迹喂给策略：CityNav 明确排除目标坐标已知的情形；给策略真值会系统性高估能力。修复：允许的输入只有自身 GNSS、地图数据与观察；目标信息只经自然语言描述进入。
  • 把 OSR 当 SR 报告：OSR 只要求轨迹经过目标附近，训练中该指标显著更高，容易造成「已经接近解决」的错觉。修复：成对报告 SR 与 OSR，并把停止失败单独做失败分析（AerialVLN 的主要失败类型之一）。
  • 合成环境结论直接外推到真实城市：AerialVLN 的渲染、动态与物体分布来自游戏引擎，CityNav 的真实扫描在纹理、遮挡与地理结构上都不同。修复：跨域结论必须用真实数据实验支撑；训练在合成、评测在真实的组合要单独报告。

练习与思考

  1. 完成两组换算：(a) AerialVLN 平均 204 动作、661.8 米，求每动作平均位移；(b) CityNav 总长 17.8 × 106 米、32,637 条、240 动作，求平均轨迹长度与每动作位移。解释两者单位位移为何都低于 5 米的前移步长。 ★
    提示
    (a) 661.8 / 204 ≈ 3.24 米；(b) 17.8M / 32,637 ≈ 545.4 米，545.4 / 240 ≈ 2.27 米。转向、升降不产生水平位移，人类还包含绕行与悬停观察，平均值被拉低。
  2. 若把 CityNav 的成功半径从 20 米改为 10 米，预测 SR、OSR 与 NE 三个指标的变化方向，说明哪些指标不受影响；再从 20 米的依据出发评论这次改动的工程含义。 ★
    提示
    SR 与 OSR 都会下降，NE 的统计不受影响（它是距离字段）。成功球体积缩小为 1/8，接近目标但停止精度不足的轨迹被判失败，SR 降幅会大于 OSR；10 米小于直升机坪尺度，任务会偏离原始设定。
  3. 对 AerialVLN 的切分做一次口径审计：(a) 四个 split 的指令数与路径数是否能与总量闭合；(b) 场景数 17、8、8 与总量 25 的关系说明了什么；(c) 引用该数据集场景规模时应当怎么写。 ★★
    提示
    (a) 25,338 与 8,446 均能闭合，且每路径恰 3 条指令。(b) 17 + 8 + 8 = 33 大于 25，说明 split 之间存在场景复用。(c) 引用时写「25 个场景，train 与 val-seen 共享 17 个，val-unseen 与 test 各 8 个」，不自行推导唯一场景映射。
  4. GSM 消融显示去掉地标后 SR 从 6.72% 降到 0.60%。请给出两条解释，并设计一个地标密度分层实验（短描述/长描述 × 少地标/多地标）预测哪一格的 GSM 增益最大。 ★★
    提示
    解释：地标是空间关系的锚点，也是与指令词对齐的视觉实体；没有地标，地图与语言失去共同参照。预期长描述、多地标一格的增益最大，因为可对齐的锚点多、序列推理信号强；少地标短描述格的增益最小且需要控制描述词数变量。
  5. 设计一个「跨城市泛化」实验：在剑桥数据上训练、在伯明翰数据上评测，要求 (a) 写出训练与评测的完整输入清单（含 GSM 通道）；(b) 给出三组对照（无 GSM、合成场景预训练、人类示范对最短路）；(c) 预测两组主要失效并给出量化指标；(d) 说明为什么该实验比同城 val-unseen 更有说服力，同时指出它的局限。 ★★★
    提示
    (a) 输入含 RGB、自身 GNSS、OSM 地标与检测框，目标仅以描述给出。(b) 对照固定策略与训练轮数，只替换 GSM 开关、预训练数据来源与监督轨迹来源。(c) 失效一：地名词表与建筑风格差异导致地标对齐失败，用地标检索命中率与 NE 分层量化；失效二：高度与视场统计漂移，用升降动作占比与高度误差量化。(d) 跨城市排除了同城场景复用的记忆效应，更接近真实部署；局限是两城数据由同一扫描与采集流程产生，分布差异有限，不能代表全球城市。

小结

  • AerialVLN 是城市级合成基准：25 场景、8,446 条飞手路径、25,338 条指令（每路径 3 条）、平均 83 词、661.8 米、204 动作；8 动作覆盖四自由度，成功判定为 20 米球域。
  • 基线在未见 split 成功率 1.0% 至 1.6%，人类 test 为 80.8%；失败主因是长路径偏离与停止判定，OSR 显著高于 SR；DA 与前瞻引导在小场景变体上把 CMA 提到 4.5%。
  • CityNav 是真实城市数据集：两城市 4.65 平方公里、32,637 条人类示范、171 人、711 小时、实算成本 9,122.13 美元；平均轨迹 545.4 米、240 动作；六动作覆盖四自由度，20 米球成功口径。
  • 地理语义图（GSM）五通道接入策略，把 AerialVLN 模型的 test-unseen SR 从 1.79% 提到 6.72%、NE 下降 54.7%；消融显示地标通道最关键。
  • 三档对比的判据：成功阈值随尺度伸缩（室内 3 米、空中 20 米），自由度决定执行难度，语言复杂度随场景倍增；跨档比较必须报告阈值比例与 NE 分布。
