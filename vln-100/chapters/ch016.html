第一篇 · 任务、数据、仿真与评测地基

第 016 讲｜Touchdown：街道级空间推理

本讲把导航搬到纽约街景：Touchdown 用 29,641 个全景与 61,319 条边构成真实城市图，9,326 条指令平均 108 词，先按指令走到目标街景，再消解一段空间描述找到隐藏的玩具熊。学完能解释街景图动作语义与 R2R 固定转角的差异，会算 TC、SPD、SED，能实现语言条件卷积的语言切核接口，并理解室内到室外任务在语言与评测上的边界变化。

  • 主题：街景导航 / 空间描述消解 / 图动作语义 / 评测口径
  • 关键公式：SED = (1/N) Σ Si (1 − lev(ei, êi) / max(|ei|, |êi|))
  • 预计学时：60 分钟
  • 前置讲：第 015 讲（CVDN / NDH：对话历史导航）

学习目标

  • 会写：复述 Touchdown 的两级任务（导航加空间描述消解）与状态、动作定义，说明「按边朝向转动」与固定转角的差别。
  • 会算：核对导航与 SDR 两组 split 的闭合关系，计算 SED 的教学算例，并与 SPL 的结构差异作对比。
  • 会推：解释 TC、SPD、SED 三个指标的分工，说明为什么 SED 只统计成功样本、为什么编辑距离在全景序列上计算。
  • 会实现：把描述文本编码后切成 m 段卷积核，与图像特征图逐层融合的语言条件图像重建接口。
  • 会判：列出室内任务假设在街道环境失效的位置，并给出采集协议与评测口径的应对方式。

背景与动机

第 015 讲把交互引入室内导航，环境仍是封闭房间与整洁住宅。真实服务机器人面对的另一半世界在室外：开放街道、动态交通、广告牌与橱窗、更大的图与更长的路线。Chen 等 2019 在 CVPR 2019 提出 Touchdown，把语言导航搬到谷歌街景（Google Street View）覆盖的纽约市街区，并把「到达目标街景后还要读懂一段空间描述」设为第二阶段任务，取名 SDR（Spatial Description Resolution，空间描述消解）。数据规模为 9,326 条完整任务示例（Chen 等, 2019，CVPR 2019）。

该工作的采集设计值得单独讲：他们把标注框成「藏宝与寻宝」游戏，写作的人沿规定路线行走并藏起玩具熊 Touchdown，同时写下路线描述与藏匿地点的空间描述；另一名工人只看指令去寻宝，找到即验证成功。写作者与寻宝者的利益绑定在同一个奖金上，指令质量就有了可度量的目标。验证通过的示例才进入数据集，89.1% 的写作任务通过验证，其中 80.1% 一次通过（Chen 等, 2019，4 与 5 节）。

任务结构因此比前几讲都复杂：一条指令同时包含导航段与目标描述段，两段的切分与实际长度在数据里有标注，导航需要自我中心（egocentric）空间推理，目标描述需要异中心（allocentric）空间推理。语言统计显示，Touchdown 平均每条指令提到 10.7 个可观察实体，是 R2R 的 2.9 倍；异中心空间关系在 25 条抽样里出现于全部指令，而 R2R 只有 20%（Chen 等, 2019，表 3）。

本讲要解决三件事：第一，讲清街景环境的状态与动作语义，这是复现时最容易照搬 R2R 而出错的地方；第二，把导航与 SDR 的评测口径推导清楚，包括 SED 与 SPL 的结构差异；第三，把完整任务的级联关系与边界条件算明白。此后第三篇的城市航拍（019、053 讲）与 2026 快照中的室外基准（098 讲）都会复用本讲的口径。

核心原理

1. 环境与动作语义

环境由 29,641 个街景全景与 61,319 条无向边构成，平均每个全景连接 4.14 条边（实算：2 × 61,319 / 29,641 = 4.137）。每个全景是 360° RGB 图像，边把相邻全景连接起来，每条边在一个确定的朝向上与全景相连。状态定义为二元组 s = (I, α)：I 为当前全景，α 为智能体朝向，且只允许存在「该朝向上有边可走」的状态（Chen 等, 2019，3.1 节）。

动作集合为 FORWARD、LEFT、RIGHT、STOP 四个。转移是确定性的，语义与 R2R 的固定转角不同：FORWARD 沿当前朝向的边移动，到达新全景后朝向更新为新全景中与 α 最接近的边的朝向；LEFT 与 RIGHT 把朝向切换到当前全景中位于左（右）侧最近的边的朝向。换言之，转动动作的幅度由图的局部结构决定，可能是数十度的锐角，也可能接近直角，不存在「每次转 30°」的约定（Chen 等, 2019，3.1 节）。

T((Ii, α), FORWARD) = (Ij, α′)，α′ = argminαe |αe − α| αe 为全景 Ij 中各条出边的朝向；LEFT / RIGHT 在当前全景的出边朝向中取相邻的一侧，动作粒度随图结构变化

与 R2R 的对照可以压缩成三点。第一条，R2R 的转向是固定的 30°，观测侧把全景离散成 12 个候选视角；Touchdown 的转向直接落在图的出边上，没有固定步长，也没有 12 视角这一中间层。第二条，R2R 的前进在「视场中心最近的可达视点」上选择，Touchdown 只在当前朝向有边时才能前进。第三条，两个环境的状态都不含全局坐标，Touchdown 的朝向状态被限制在边朝向上，离散程度更高。复现时若照搬 R2R 的动作层，指令里的「转左、继续、直到看见学校再停」会因转角与边的对应关系错位而系统性失败。

2. 两级任务与采集协议

导航任务要求智能体按指令从起点走到目标街景；SDR 任务要求在给定全景中输出描述所指位置的像素坐标 (x, y)。Touchdown 玩具熊在输入中不可见，SDR 的监督来自标注者藏匿时记录的位置及向邻接全景的传播。完整任务把两者串起来：先导航，到达后在当前全景执行 SDR（Chen 等, 2019，3 节）。

采集分四个众包任务：写作要求工人按俯视地图上的规定路线行走并写下指令，出发点朝向正北，工人要先自行转向路线方向，由此产生大量「朝车流方向转、伞在你的右边」式的自我中心描述；写作时禁止引用图像中的文字，包括街名、店名与门牌号。传播把目标位置标注到相邻全景，使「停在邻接位置也算找到」成立。验证让另一名工人只看指令寻宝，允许五次点击，命中半径为 90 像素，两人都失败则丢弃该示例。切分把指令标注为导航段前缀与 SDR 段后缀，两段允许重叠，平均重叠 11.4 个 token（Chen 等, 2019，4 节）。

质量与激励数据：写作任务完成 11,019 次，验证任务 12,664 次；按示例计的验证通过率 89.1%，其中首次通过 80.1%、二次通过 9.0%；64% 的验证只需一次尝试，只有 1.4% 需要五次。写作基础报酬 0.60 美元，传播 0.15、验证 0.25、切分 0.12 美元；通过验证后写作者与寻宝者分别获得 0.25 与 0.10 美元奖金，双方利益绑定，指令写坏会同时拿不到奖金。参与写作、传播、验证、切分的工人分别为 224、218、291、46 人（Chen 等, 2019，4 节与表 1）。

3. 数据规模与切分

导航任务共 9,326 条示例，按 6,526 / 1,391 / 1,409 切分训练、开发与测试；SDR 任务有 9,326 条唯一描述，展开为 25,575 条示例，按 17,880 / 3,836 / 3,859 切分，平均每条描述有 2.74 个可执行实例（同描述在不同邻接全景上）。两组数据求和均闭合（9,326 与 25,575）。

读表有三条结论。第一条，异中心空间关系从 20% 升到 100%，说明 SDR 与室内指代任务在推理类型上不同，它要求「理解物体之间的关系，再在图像中定位」，语言与视觉的耦合方式不同（目标描述段负责异中心推理，导航段负责自我中心推理）。第二条，时间条件与状态核实各覆盖 84% 的指令，模型必须学会「在移动过程中持续核对观察是否匹配描述」，这类能力在 R2R 中几乎没有训练信号。第三条，唯一实体提及数量大，意味着指令携带大量可观察锚点，答案通常藏在锚点之间的相对关系里，单一地标往往不足以定位。

5. 导航评测：TC、SPD 与 SED

导航任务有三个指标。任务完成率 TC（Task Completion）按「到达精确目标全景或它的一个邻接全景」判定，宽松半径的实现来自 SDR 的位置传播，保证停在语义等价位置也算完成。最短路径距离 SPD（Shortest Path Distance）为最终全景到目标全景的图距离平均值，忽略转向动作与朝向。成功率加权编辑距离 SED（Success weighted by Edit Distance）把执行序列与参考序列对齐后按编辑距离打折：

SED = (1/N) Σi=1..N Si · ( 1 − lev(ei, êi) / max(|ei|, |êi|) ) Si 为 TC 指示；e 为参考执行、ê 为预测执行；lev 为 Levenshtein 编辑距离；距离与长度都在全景序列上计算，忽略朝向变化

SED 与 SPL 的结构差异值得逐条对照。SPL 按「路径长度」加权，比较的是走了多长；SED 按「序列编辑距离」加权，比较的是走了哪些全景、顺序是否一致。两个智能体可以到达同一目标且路径等长，SPL 完全相同，而 SED 会因为中途停了不该停的点、或顺序不同而分开。SED 只对成功样本计分，失败样本记 0，与 SPL 的失败记 0 口径一致。构造五条教学算例核对（参考序列长度 4，S 为 TC 指示）：

算例参考长度 |e|预测长度 |ê|编辑距离 levTC 指示 SSEDi
A44011.000

Python 实算：平均 SED = (1.000 + 0.750 + 0.800 + 0.750 + 0.000) / 5 = 0.660。两个细节：算例 D 停在邻接全景，TC 判定通过，编辑距离按「删除一个节点」计 1；算例 C 多走一步，分母取预测长度 5，折扣比 B 更轻。这体现了 SED 的设计取向：奖励与参考序列高度重合的轨迹，对多走一步与少走一步用归一化编辑距离区分（Chen 等, 2019，3.1 节）。

测试集基线结果给出任务的难度刻度：Stop 0.0 / 27.0 / 0.000，Frequent（总走 FORWARD）0.0 / 53.1 / 0.000，Random 0.2 / 26.9 / 0.001，GA 5.5 / 21.3 / 0.054，RConcat 10.7 / 19.5 / 0.104（依次为 TC、SPD、SED；Chen 等, 2019，表 5）。RConcat 相对随机策略把 SPD 改善 27.5%（(26.9 − 19.5) / 26.9），但 TC 只有 10.7%，说明「大致朝目标靠近」与「按指令精确到达」之间存在明显落差。单模态消融进一步显示：去掉视觉后模型无法有效学习，去掉语言后仍有有限性能，两个基线从文本获得的增益都相对有限（Chen 等, 2019，附录 F.2）。

6. 空间描述消解与 LingUNet

SDR 把语言定位写成「语言条件图像重建」：输入全景 I 与描述 x̄s，输出全景上每个像素的得分，取分布的众数作为预测位置。模型以 UNet 的图像到图像编解码为骨架，把语言逐层注入重建阶段，称为 LingUNet。文本侧用双向 LSTM 编码描述，取前向与后向隐状态拼接后平均，得到句子向量 x；图像侧用预训练 ResNet18 得到特征图 F0；在 m 个层级上，把 x 切成 m 段，每段经线性投影变成 1×1 卷积核 Kk，与对应层的特征图做卷积得到语言条件特征 Gk；解码器逐层上采样并与 Gk 拼接，最后对每个像素输出标量并做 SoftMax（Chen 等, 2019，6.1 节）。

Fk = CNNk(Fk−1)，Gk = Conv(Kk, Fk)，Hk = Deconvk([Hk+1; Gk]) k = 1..m，m 为语言切段数与层数；H 为解码侧逐层恢复的特征图，最后经单层感知机与 SoftMax 得到像素分布

训练标签为高斯平滑后的位置分布，损失采用预测分布与高斯标签的 KL 散度，监督信号在目标点附近呈梯度衰减，可缓解「正样本只有一个像素」带来的稀疏问题。SDR 的评测有三个指标：准确率（预测点落在标注点半径 40 / 80 / 120 像素内）、一致性（同一描述的全部示例都预测正确才算对，衡量跨视角稳定性）与平均距离误差。测试集上 LingUNet 的准确率 / 一致性为 26.11 / 8.80（40 px）、34.59 / 14.57（80 px）、37.81 / 16.11（120 px），平均距离误差 708 像素；同口径的 Text2Conv 为 24.82 / 8.21、30.40 / 11.73、34.13 / 13.32，距离误差 747。80 px 阈值下 LingUNet 高 4.19 个百分点、一致性高 2.84 个百分点（Chen 等, 2019，表 4）。

像素级定性分析给出一个可迁移的观察：锚点唯一时（如「消防栓顶部」）模型定位准确；同一画面出现多个相似结构（如四扇门）时，概率分布会分散到相似位置之间，这正是距离误差偏大的主要来源（Chen 等, 2019，6.3 节）。

7. 完整任务与人类对照

把导航与 SDR 的最佳模型串成管线，完整任务在 80 px 阈值下的成功率为 4.5%；论文用「至少完成 30 次任务的合格工人」估计人类对照，在有效示例上的准确率为 92%，两者相差 87.5 个百分点（Chen 等, 2019，8 节）。用比值分析级联结构：若导航 TC 取 RConcat 的 10.7%、SDR 取无条件的 34.59%，独立乘积为 3.70%；论文管线报出 4.5%；若以 RConcat 的 10.7% 作为管线导航完成率的近似，反推条件 SDR 准确率为 4.5% / 10.7% = 42.1%，比无条件值高 7.5 个百分点。这个差值的方向符合任务结构：能正确到达目标全景的 episode，其画面里往往存在描述锚点，SDR 的条件难度低于全量平均；完整任务的瓶颈首先在导航，其次才在定位。

级联审计提示

报告完整任务数字时，应同时给出导航 TC、SDR 条件准确率与两者乘积的区间。乘积是下界的粗估（假设独立），条件准确率是上界的粗估（只看成功样本）；两者的差值反映任务耦合强度，直接比较两家系统的完整任务分数前先核对这两个分解量。

8. 适用边界与失效模式

  • 街景数据的时间漂移：环境图与指令固定发布，全景图按发布帧使用；直接用谷歌接口抓取实时图像会因街道变化导致指令失效。论文把图、数据与代码以 CC-BY 4.0 发布，图像保留需遵循谷歌政策（Chen 等, 2019，9 节）。
  • 禁写文字的规则约束语言分布：路牌、店名、门牌号一律不可用，指令依赖物体与空间关系；模型在真实场景中可利用文字信息，但在该基准上不应依赖文字捷径。
  • SDR 的多义性：相似结构重复出现时分布分散，708 像素的平均距离误差说明精确定位仍是开放问题；一致性指标只有 8.8 至 16.1，跨视角稳定性弱。
  • 图动作的离散化：前进只能落在既有边上，真实街道的任意点移动无法表达；评测用邻接全景放宽 TC，属于协议内的补偿。
  • 室内外语言迁移：室内任务的「房间、家具、走廊」词汇与室外任务的「车流、红绿灯、围栏」几乎没有重叠，词表与先验不可直接迁移；跨域评测需要分别报告词表覆盖与 OOV 比例。

关键代码与解读

三段代码分别覆盖街景状态转移、导航指标与语言条件核的构造；算例数字与正文一致。

片段 1：按边朝向定义的状态转移

import math

def wrap(a):
    """把角度归一化到 (-pi, pi]。"""
    return (a + math.pi) % (2 * math.pi) - math.pi

def edge_headings(pano):
    """返回该全景所有出边的朝向列表。"""
    return [e.heading for e in pano.edges]

def step(pano, heading, action, graph):
    """Touchdown 语义: 转动幅度由图结构决定, 没有固定转角。"""
    if action == "stop":
        return pano, heading
    if action == "forward":
        nxt = graph.follow(pano, heading)      # 当前朝向必须存在出边
        # 新朝向取下一全景中最接近原朝向的出边
        h = min(edge_headings(nxt), key=lambda a: abs(wrap(a - heading)))
        return nxt, h
    hs = edge_headings(pano)
    if action == "left":
        # 左侧最近边: 朝向差在 (0, pi) 区间内取最小
        cand = [a for a in hs if 0 < wrap(a - heading) < math.pi]
        return pano, min(cand, key=lambda a: wrap(a - heading))
    if action == "right":
        cand = [a for a in hs if -math.pi < wrap(a - heading) < 0]
        return pano, max(cand, key=lambda a: wrap(a - heading))
    raise ValueError(action)

解读：（1）左转与右转按「相对当前朝向的角差区间」筛选候选边，再在区间内取最近者，语义与论文定义一致；用固定 30° 的代码替换这一段会改变评测口径。（2）角度差全部经过 wrap 归一化，跨 ±π 边界的边会被正确处理。（3）前进后的新朝向取最近出边，这是「过路口后车头方向」的形式化；实现时应对无候选的情况显式报错，不要静默保持原朝向。

片段 2：TC、SPD、SED 汇总

def levenshtein(a, b):
    """标准编辑距离: 插入、删除、替换代价均为 1。"""
    prev = list(range(len(b) + 1))
    for i, ca in enumerate(a, 1):
        cur = [i]
        for j, cb in enumerate(b, 1):
            cur.append(min(prev[j] + 1, cur[j - 1] + 1,
                           prev[j - 1] + (ca != cb)))
        prev = cur
    return prev[-1]

def sed_row(ref_panos, pred_panos, success, goal, neighbors):
    # TC 判定: 精确命中或停在邻接全景
    tc = success or (pred_panos and pred_panos[-1] in neighbors)
    if not tc:
        return 0.0, tc
    lev = levenshtein(ref_panos, pred_panos)   # 在全景序列上算, 忽略朝向
    m = max(len(ref_panos), len(pred_panos))
    return 1.0 - lev / m, tc

rows = [                    # (参考, 预测, 是否精确命中)
    (list("ABCD"), list("ABCD"), True),    # lev=0, SED 1.000
    (list("ABCD"), list("ABXD"), True),    # lev=1, SED 0.750
    (list("ABCD"), list("ABCDX"), True),   # lev=1, |e|=5, SED 0.800
    (list("ABCD"), list("ABC"), True),     # 停在邻接点, lev=1, SED 0.750
    (list("ABCD"), list("AXYD"), False),   # 失败, SED 0.000
]
vals = [sed_row(r, p, s, "D", {"C"})[0] for r, p, s in rows]
print(["%.3f" % v for v in vals], "avg=%.3f" % (sum(vals) / len(vals)))
# 输出: ['1.000', '0.750', '0.800', '0.750', '0.000'] avg=0.660

解读：（1）编辑距离在「全景序列」上计算，朝向变化与多余的转向不进入序列；若直接把动作序列喂进编辑距离，转向动作会让距离虚高，指标与论文不可比。（2）TC 判定把「停在邻接全景」也算命中，与 SDR 的位置传播对齐；邻接集合由数据字段给出，不由模型推断。（3）失败样本先返回 0，不再计算编辑距离，保证 SED 与 TC 的方向一致：完成率高的方案不会被序列错位反噬。

片段 3：LingUNet 的语言切核

import torch
import torch.nn as nn

class LingUNet(nn.Module):
    def __init__(self, text_dim=512, levels=2):
        super().__init__()
        self.levels = levels
        # 文本向量切成 levels 段, 每段投影为一个 1x1 卷积核
        self.to_kernel = nn.ModuleList(
            [nn.Conv2d(text_dim // levels, 1, kernel_size=1) for _ in range(levels)])
        self.deconv = nn.ModuleList(
            [nn.ConvTranspose2d(1, 1, kernel_size=2, stride=2) for _ in range(levels)])

    def forward(self, feat_maps, text_vec):
        """feat_maps: 编码侧逐层特征, 由粗到细; text_vec: [B, D]。"""
        chunks = torch.chunk(text_vec, self.levels, dim=-1)   # 按通道切段
        out = None
        for k in range(self.levels - 1, -1, -1):
            f = feat_maps[k]                                  # [B, Ck, H, W]
            kernel = self.to_kernel[k](chunks[k][:, :, None, None])
            cond = torch.sigmoid(kernel) * f                  # 语言条件调制
            out = cond if out is None else torch.cat([out, cond], dim=1)
            out = self.deconv[k](out)
        return out                                            # 逐像素得分, 外部做 SoftMax

解读：（1）文本向量按通道切成 m 段，每段生成一个 1×1 卷积核，与对应层的特征图相乘，实现「语言的每一部分控制一层重建」，与论文的 Kk 与 Gk 对应。（2）用逐通道乘性调制代替论文中的单通道卷积示意，保持「语言条件逐层注入」的机制；复现实验若严格对齐论文，应保留 1×1 卷积的输出通道数再拼接。（3）输出为逐像素标量，SoftMax 放在损失函数侧与高斯标签计算 KL 散度；分层数与文本切段数必须相等，否则 chunks 与 feat_maps 无法一一对应。

常见坑

  • 照搬 R2R 的固定转角：模型在「过路口后继续」类指令上系统性走错。根因：Touchdown 的转向目标是相邻出边朝向，幅度随图结构变化。修复：按片段 1 重写动作层，先用一条人工轨迹做逐步回放核验。
  • SED 在动作序列上计算：同一模型换实现后指标骤降。根因：编辑距离被转向动作与朝向变化污染。修复：先把执行压成全景序列，再算编辑距离；朝向信息只用于状态推进，不进入指标。
  • TC 只认精确命中：数字低于论文。根因：忽略了位置传播到邻接全景的标注。修复：用 neighbor_targets 字段判定邻接命中，同时保持 SDR 的精确评测口径不变。
  • SDR 用单点标签训练：损失难以下降、预测总偏离目标数像素。根因：正样本只有一个像素，梯度稀疏。修复：标签做高斯平滑，用 KL 散度训练，并核对平滑带宽与 40 / 80 / 120 px 评测半径的匹配关系。
  • 数字与数据源不固定：引用 27,575 而不核对闭合的 25,575，或用实时街景替换发布帧。根因：未做求和核对与数据版本固定。修复：以 split 求和为准确认 SDR 规模，全景一律使用发布帧，跨校结果说明数据版本（arXiv:1811.12354v7，CVPR 2019）。

小结

  • Touchdown 在纽约街景上构建 29,641 个全景与 61,319 条边的图（平均度 4.14），状态为全景加朝向，转向目标是相邻出边朝向，不存在固定转角。
  • 两级任务为导航与空间描述消解；9,326 条指令平均 108.0 词、路径平均 35.2 个全景；SDR 25,575 条示例（引言 27,575 与 split 求和不符，按可闭合口径采用 25,575）。
  • 语言现象以异中心空间关系（100%）与自我中心空间关系（100%）并重；时间条件 84%、状态核实 84%，对「移动中核对观察」提出明确要求。
  • 导航指标为 TC、SPD 与 SED；SED 在成功样本上按全景序列的归一化编辑距离加权，五条算例平均 0.660；测试集最佳基线 RConcat 为 TC 10.7、SPD 19.5、SED 0.104。
  • SDR 用语言条件图像重建解决：双向 LSTM 编码、文本切段生成 1×1 卷积核、逐层注入解码器、高斯标签加 KL 散度；测试集 80 px 准确率 / 一致性为 34.59 / 14.57。
  • 完整任务成功率 4.5% 对人类的 92%；级联分析显示瓶颈在导航（TC 10.7%），条件 SDR 为 42.1%。下一讲进入连续环境，讨论离散图三假设放松后的动作、观察与评测变化。
