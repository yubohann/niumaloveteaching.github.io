第四篇 · 规模、记忆与泛化方法论

第 064 讲｜数据工程再谈（承 033）

第 033 讲把 BnB 数据集造了出来，本讲把整个流程按工程审计的口径重走一遍：15 万个房源如何抽样（美国房源的四分之一），留存率 46.300% 与描述覆盖率 51.332% 怎么算出来，划分为什么必须以房源为最小单位，论文的 CC BY 4.0 许可为什么盖不住图片权利，以及一条清洗规则改动会怎样影响复现。最后给出数据工程检查清单 v2，并把人工标注、合成管线、环境资产、平台采集四类数据源放进同一张对照表。

  • 主题：数据工程 / 抽样框 / 清洗审计 / 许可链 / 数据卡片
  • 关键数字：15 万房源、138.9 万保留图、留存率 46.300%、描述覆盖率 51.332%、划分粒度按房源
  • 预计学时：60 分钟
  • 前置讲：第 063 讲（HM3D / HM3DSEM：环境规模化）

学习目标

  • 会算：核对留存率、描述覆盖率、每房源图像数与正负样本预算，把 033 的规模数字变成可断言的验收指标。
  • 会解释：抽样框偏差、清洗误杀与漏放、划分粒度三类问题怎样污染训练与评测，以及各自的检查方法。
  • 会实现：清洗审计、房源级划分与重复检查、数据卡片校验三段示意代码。
  • 会判断：人工标注、合成数据、环境资产、平台采集四类来源的许可链条与成本结构，识别再分发风险。
  • 会设计：为一个新数据源写出数据卡片与审计计划，覆盖抽样框、许可、版本冻结与更新策略。

背景与动机

第 033 讲围绕 BnB 数据集讲过域内数据的价值与构造：从在线短租平台采集图文对，用五种策略生成路径-指令对，用乱序损失强化时序对齐，最后在少样本设置下把一环境微调的 val unseen SR 从 22.43% 提到 50.00%。那一讲的重心在方法机制。本讲换一个视角，把同一批数据当作工程对象：数据从哪里来、依据什么规则被删掉、集合怎么切、权利归谁、版本怎么冻结。

进入第四篇后，这个视角变得关键。第 061 与 062 讲的合成管线使用了 1291 个真实场景，训练预算约 72 GPU 小时（预训练）与 48 GPU 小时（微调）；第 063 讲的 HM3DSEM 标注投入 14,200 人时，并受 Matterport 非商业许可约束。规模越大，数据侧的任何一个口径错误越难在事后修补：场景清单漂移会让指标失去可比性，许可越界会让成果无法发布，划分泄漏会让少样本结论虚高。数据工程在第一篇是背景知识，到第四篇是成果能否成立的前提。

本讲以 BnB（Guhur 等 2021，ICCV 2021，arXiv:2108.09105v1）为完整样本，回顾采集、清洗、划分、许可、版本、成本六个环节，再把结论扩展成跨数据源的检查清单 v2。第 065 讲接续讨论数据增广的边界与风险，本讲先把「合法、可复现、可审计」这条底线立住。

核心原理

本讲按「规模回顾、抽样框、清洗审计、划分纪律、许可链条、版本溯源、成本结构、收益与边界」八步展开；BnB 数字全部标注来源（arXiv:2108.09105v1，ICCV 2021），与第 033 讲口径一致。

1. 规模回顾：从 15 万个房源到 138.9 万张保留图

先核对第 033 讲的规模链条。平台侧背景口径为 560 万个房源、覆盖 10 万多个城市；BnB 只采集美国房源（约占平台总量 10%），下载约 15 万个房源（约为美国房源总量的四分之一），得到超过 300 万张图片与约 100 万条描述。清洗后保留 71.3 万条图文对与 67.6 万张无描述图，合计 138.9 万张。实算：图片留存率 1,389,000 / 3,000,000 = 46.300%，描述覆盖率 713,000 / 1,389,000 = 51.332%；每房源平均保留 9.26 张（原始约 20.00 张；房源基数取论文正文的近 15 万下载量，论文表 1 另列 14 万个环境，按 140,000 计为 9.92 张，引用时写明基数）；图文对与无描述图的比例为 1.055。划分取 95% 训练、5% 验证，对应 142,500 与 7,500 个房源。

这些数字在工程上要成组出现，缺一个就无法判断规模的真实含义：只报保留图数量，读者不知道原始规模与过滤强度；只报留存率，读者不知道清洗规则；只报房源数，读者不知道每房源的图像密度。结论一：数据规模必须按「下载量、过滤后量、训练用量」三段报告，并附每段的规则版本。

2. 抽样框：偏差在采集那一刻就已写入

BnB 的采集流程为五步：从维基百科获取地点列表；在平台按地点检索房源；下载房源与元数据；用 Places365 预训练的 ResNet 分类器剔除室外图片；清理邮箱、网址与重复描述。限定美国房源的理由是两条：保证高质量英文描述，尽量贴近 Matterport 室内风格。这两条理由本身就承认了抽样框（sampling frame）与下游分布之间的取舍：语言上偏向英语，视觉上偏向与扫描资产相近的装修风格。

抽样框带来三类可预期的偏差。第一，地理偏差：地点列表与检索排序偏向热门城市与高活跃房源，冷门地区与低活跃房东覆盖不足。第二，内容偏差：为出租展示而拍摄的图像偏爱广角、明亮、样板间式构图，杂乱与弱光场景少。第三，描述偏差：房源描述是营销文本，物体词密集而动作词稀缺，第 033 讲把它总结为动作性差距。三类偏差不能在清洗阶段消除，只能在采集设计阶段记录并抽样核对。

核对方法是分层抽检：按城市层级（热门与冷门）、房源规模（单间与整租）与描述语言分层，从每层抽固定数量样本，人工判断装修风格与房间类型的分布，并与目标域（例如 Matterport 的住宅场景）做对照。抽检结果写进数据卡片的「已知偏差」字段，作为后期配比与清洗权重的依据。结论二：抽样框的偏差要显式记录，不能靠扩大采集量掩盖。

3. 清洗审计：两条曲线与三类损失

清洗的目的是把不适合下游的样本删掉，代价是同时删掉一部分可用样本。BnB 的清洗把图片从 300 万降到 138.9 万，删除动因包括室外过滤、无效描述与重复项。工程审计需要把损失分成三类分别计量：第一类是过滤器按判据删除的样本（室外图片），可复算、可审计；第二类是从未下载的样本（平台检索未覆盖的房源），不可审计，只能用抽样框偏差描述；第三类是被误删的可用样本（把室内图判成室外、把有效描述判成非法），需要通过人工抽检估计误杀率。

每类损失对应一个验收指标：留存率与描述覆盖率反映过滤强度；重复率反映数据去重质量；误杀率反映判据的保守程度。第 033 讲给出的 46.300% 留存率与 51.332% 覆盖率是这套指标的两个锚点，复现时应写成断言，任何偏离都要解释原因。清洗规则还需要版本化：正则表达式表、分类器权重与阈值、去重相似度阈值都是规则的一部分；结论三：清洗规则与数据同版本管理，规则不记录版本的清洗结果不可审计。

r保留 = N保留 / N原始 = 1,389,000 / 3,000,000 = 46.300% r 为图片留存率；N 为图片数。对应描述覆盖率 c = 713,000 / 1,389,000 = 51.332%；每房源保留图 1,389,000 / 150,000 = 9.26 张（论文表 1 的 140K 环境口径则为 9.92 张，口径注见第 1 小节）

4. 划分纪律：最小单位决定泄漏边界

BnB 按房源划分训练与验证，同一房源的全部图片只出现在一侧。这条纪律针对的是近似重复：同一房源的多张客厅图往往视角接近、内容相似，如果按图片随机划分，验证集里会出现与训练集近乎相同的图像，指标随之虚高。第 033 讲在边界里点出过这个问题，本讲把它上升为通用规则：划分粒度取「最小独立采集单位」。对 BnB 是房源；对 R2R 一类人工标注数据是场景；对视频采集是同一段视频或同一家庭；对平台采集还可能出现同一房东多房源共用素材的情况，此时应再上收一层按房东划分。

划分完成后需要三道检查。第一，房源 ID 集合不相交；第二，跨集合的图像相似度检索结果低于阈值（近似重复检测）；第三，验证集与训练集的元数据分布（城市、房间类型、描述长度）对得上，避免划分引入新的分布偏移。实算提示：若按图片划分，一个房源平均 9.26 张图意味着一条房源的两个近景落入不同集合的概率不可忽略；按房源划分后该概率降为零。

5. 许可链条：论文许可、内容权利、平台条款是三件事

BnB 论文采用 CC BY 4.0 许可，这只覆盖论文文本与图表；图片与描述来自房东与平台，其权利链条独立于论文许可。平台服务条款通常限制批量抓取与再分发；图片可能包含可识别的个人物品、人像、屏幕与门牌，涉及隐私。发布派生数据集前至少要核对四项：平台条款允许的使用范围、图片权利人的授权状态、数据集再分发的形式（原图、链接或特征）、以及人物与敏感内容的处理记录。结论四：论文许可不构成对训练数据内容的授权，许可核对必须沿权利链逐层进行。

6. 版本与溯源：数据卡片是交付物

数据工程的可复现性由数据卡片承载。BnB 的关键字段包括：来源（平台与地区范围）、采集时间窗、原始与保留规模、清洗规则版本、划分粒度与比例、生成策略（K 与 N 的采样分布、连接词表）、训练轮数、许可与已知偏差。缺少任一字段，第三方都无法判断一份派生数据与原始数据的关系。

溯源还需要校验值：对场景清单、房源清单与图像文件名清单分别计算内容校验值，写入卡片；缓存的资产按校验值核对，防止静默变化。评测集额外做两件事：冻结（发布后不再变动）与隔离（生成脚本不读取评测集内容，防止特征统计泄漏）。更新策略也要写明：数据源改动时是追加、替换还是重建，旧版本保留多久，指标是否重跑。

7. 成本结构：三条路线，三种账

把三类数据来源的成本放进同一张账：平台采集的成本主要在采集工程与清洗人力；合成数据（第 062 讲）的成本主要在 GPU 与采样工程，预训练约 72 GPU 小时、微调约 48 GPU 小时，外加一次性的图修复模型训练；环境资产（第 063 讲）的成本主要在采集与标注，HM3DSEM 为 14,200 人时。用 BnB 的训练预算做一次实算：95% 的 15 万房源为 142,500 个，每轮每房源一个正样本，15 轮共 2,137,500 个正样本；每个正样本配 9 个负样本，正负比较次数约 1,924 万（2,137,500 × 9 = 19,237,500）；批大小 64 时每轮约 2,227 步，全程约 33,398 步。

质检人力同样要预算。假设人工抽检速度为每秒一张图，对 138.9 万张全检需要约 386 小时；按 1% 的分层抽样则约 3.9 小时，且能给出各层的误杀率估计。结论五：抽检比例按误差目标与分层设计，不按剩余预算随意加码。对多模态数据，抽检单元应取「图文对」，避免只查图片漏检文本侧错误。

8. 收益证据与边界

工程纪律本身不产生指标，但错误的工程会让指标失真。BnB 的收益证据分三层：只用 BnB 图像描述对预训练、不做任何域内改造，R2R val unseen 为 60.54%，高于 VLN-BERT 的 59.26%；加入域内改造策略后，单项最好的是插入无描述图（66.05%），三策略合用 66.52%；再加 Speaker 数据与乱序损失到 68.67%。少样本设置最有冲击力：单个环境微调从 22.43% 到 50.00%（2.23 倍），6 个环境从 35.99% 到 57.97%，61 个环境从 57.15% 到 65.60%。

边界与失效模式：

  • 路径-指令对不是真实轨迹：同一房源的图像之间没有可通行性保证，只能用于表示学习与对比目标，不能作为导航监督或强化学习奖励来源。
  • 生成指令的忠实性无保证：改写与生成都可能写入路径中不存在的物体，需要以小比例抽检估计噪声率，并在数据卡片中记录。
  • 风格偏移仍在：广角摆拍与扫描全景在光照、畸变与分辨率上都有差异，跨域部署时预训练收益不代表无域差。
  • 近似重复会虚高验证指标：按图片划分或未做相似度检索时，验证集与训练集共享视觉内容，少样本结论会被夸大。
  • 许可与隐私是一票否决项：再分发原图、公开含人像与屏幕的样本、把非商业资产用于商业演示，都会让成果无法发布，规模再大也无法补救。

数据源的引入顺序应按风险排序：许可链不清的来源直接排除，因为它是发布阶段的一票否决项；分布与下游差距大的来源放在预训练并控制配比；规模扩张放在最后，且必须先通过质量门槛（第 062 讲的图像修复消融给出了 61% 环境增量被低质数据抵消的实例）。判据是「这笔数据能否进入正式评测链路」：能，则按清单 v2 逐项留证；不能，则降级为探索性实验并写明原因。

与相邻讲的分工：第 033 讲解释 BnB 的机制与收益；本讲把同一批数据按工程审计口径重走一遍，并把结论扩展成通用清单；第 065 讲讨论增广的收益递减与分布漂移，需要用到本讲的划分与许可纪律作为实验前提。

关键代码与解读

三段代码分别给出清洗审计、房源级划分与重复检查、数据卡片校验。数字与第 033 讲及本讲正文一致，可直接作为验收断言的实现骨架。

片段 1：清洗审计与留存断言

RULES_VERSION = "bnb-clean-v1"          # 清洗规则版本必须与数据一起冻结

def clean_audit(raw_images, raw_captions,
                kept_pairs, kept_captionless, rules=RULES_VERSION):
    """核对留存率与覆盖率，输出可写入数据卡片的审计块。"""
    kept = kept_pairs + kept_captionless
    retention = kept / raw_images        # 图片留存率
    coverage = kept_pairs / kept         # 描述覆盖率
    assert 0.40 < retention < 0.55, retention      # 论文口径 46.300%
    assert 0.45 < coverage < 0.60, coverage       # 论文口径 51.332%
    return {
        "rules_version": rules,
        "raw_images": raw_images,
        "kept_images": kept,
        "retention": round(retention, 5),          # 0.463
        "coverage": round(coverage, 5),            # 0.51332
        "pairs": kept_pairs,
        "captionless": kept_captionless,
    }

# 调用示例：clean_audit(3_000_000, 1_000_000, 713_000, 676_000)
# 输出 retention 0.463，coverage 0.51332，与正文一致

解读：（1）把规则版本写进审计块，任何一次口径变化都能追溯到对应的数据版本；（2）断言区间取论文值附近的窄带，偏离时直接报错，迫使复现者解释原因；（3）输出字段直接对应数据卡片的「清洗后规模」行，卡片与脚本保持同一数据源，避免手抄数字。

片段 2：房源级划分与重复检查

import random

def split_by_listing(listings, val_ratio=0.05, seed=0):
    """按房源为最小单位划分，杜绝同房源近景跨集合。"""
    ids = sorted(listings.keys())        # 排序后固定随机序列，保证可复现
    random.Random(seed).shuffle(ids)
    n_val = int(len(ids) * val_ratio)    # 150000 * 0.05 = 7500
    val_ids = set(ids[:n_val])
    train = {i: listings[i] for i in ids if i not in val_ids}
    val = {i: listings[i] for i in ids if i in val_ids}
    assert not (set(train) & set(val))   # 集合不相交断言
    return train, val

def cross_split_duplicates(train, val, similarity_index, threshold=0.95):
    """跨集合近似重复检查：低于阈值才算通过。"""
    hits = []
    for vid in val:
        for img in val[vid]:
            matches = similarity_index.query(img, top_k=1)
            if matches and matches[0].listing_id in train:
                if matches[0].score >= threshold:
                    hits.append((vid, matches[0].listing_id, matches[0].score))
    return hits                          # 返回空列表才允许进入训练

解读：（1）划分键取房源 ID，按图像划分会把同房源近景拆散；排序加固定随机种子让划分可复现，5% 验证对应 7,500 个房源。（2）相似度检索用图像特征索引实现，跨集合高相似匹配即为泄漏信号；命中列表非空时必须先处理再训练。（3）同一房东多房源共用素材时，把最小单位上收为房东 ID，划分函数改一个键即可复用。

片段 3：数据卡片校验

REQUIRED = ["source", "raw_scale", "kept_scale", "split_unit",
            "split_ratio", "license", "rules_version",
            "gen_strategy", "known_bias", "checksums"]

def validate_card(card):
    """校验数据卡片字段完整性与规模自洽性。"""
    missing = [k for k in REQUIRED if k not in card or card[k] in ("", None)]
    assert not missing, f"missing fields: {missing}"
    assert card["split_unit"] in ("listing", "house", "host", "video")
    assert 0.0 < card["split_ratio"]["val"] < 1.0
    kept = card["kept_scale"]["pairs"] + card["kept_scale"]["captionless"]
    ratio = kept / card["raw_scale"]["images"]
    assert abs(ratio - card["audit"]["retention"]) < 1e-4  # 卡片与审计同源
    return True

# 发布门槛：字段齐全、划分粒度声明、规模与审计一致、校验值可核对
# 任一断言失败，数据只能停留在实验态，不能进入正式评测链路

解读：（1）必填字段覆盖来源、规模、划分、许可与生成策略，缺一即拒绝；（2）划分粒度只允许预先声明的四种，避免用「随机划分」这类无法审计的表述蒙混；（3）规模自洽断言把卡片与审计脚本绑定，防止导出阶段手改数字造成前后不一致。

常见误区

  • 按图片划分训练与验证：训练收敛正常，验证与少样本指标偏高。根因是同一房源的多张近景跨集合，验证集包含训练集见过的视觉内容。修复：按最小独立采集单位划分；划分后跑跨集合相似度检索，命中阈值的样本重新归并到同一侧。
  • 描述重复未清除：数据规模虚高，同一句描述在多个样本里反复出现。根因是只看图片唯一性，未对文本去重（模板描述、复制粘贴的营销文案）。修复：文本侧做规范化后去重，报告重复率；把重复率列入数据卡片的清洗块。
  • 把论文许可当内容许可：论文标 CC BY 4.0，于是把图片一起再分发。根因是混淆了「论文文本许可」与「图像内容权利」。修复：许可链分层核对，内容侧确认平台条款与权利人授权；不确定时只发布标识符与特征，不镜像原图。
  • 清洗规则不版本化：半年后复现出的数据规模与论文对不上，无法定位差异。根因是正则、阈值与模型权重未被记录。修复：规则集独立成文件并标版本号，审计脚本输出规则版本；数据卡片引用同一版本号。
  • 抽检比例随意设定：要么全检耗时巨大，要么比例过低漏掉系统性错误。根因是缺少按分层与误差目标的设计。修复：按城市、房型、语言分层抽样，先估各层错误率再定总量；以 1% 抽样为例，138.9 万张对应约 1.39 万张与约 3.9 小时，可覆盖主要分层。
  • 评测集未冻结或生成脚本读取评测集：一次调参后指标波动无法归因。根因是评测集没有版本锁定，或采样器直接从评测分布中估计参数。修复：冻结评测集并记录校验值；生成脚本与评测数据隔离，参数统计只允许来自训练侧。

练习与思考

  1. 完成 BnB 规模核对：15 万个房源、约 300 万原始图、71.3 万图文对与 67.6 万无描述图。计算：(a) 图片留存率与描述覆盖率；(b) 每房源平均保留图数；(c) 图文对与无描述图的比例，并说明这个比例对「插入无描述图」策略的意义。 ★
    提示
    (a) 保留 (713,000 + 676,000) / 3,000,000 = 46.300%；覆盖率 713,000 / 1,389,000 = 51.332%。(b) 1,389,000 / 150,000 = 9.26 张。(c) 713,000 / 676,000 ≈ 1.055，两类素材接近对半，为路径中约三成位置插入无描述图提供了充足原料。
  2. 把路径长度分布从 K 取自 4 至 7 改为 3 至 8，N 仍取自 2 至 K。预测三件事的方向：正样本平均长度、无描述图占比、每个样本的平均描述段数；写出预测依据与一个可证伪的观测指标。 ★
    提示
    K 的期望在两个区间都是 5.5，平均长度与平均描述段数 E[N] = (5.5 + 2) / 2 = 3.75 不变，但方差上升，长样本与短样本都增多。无描述图占比的期望从 0.3101 略降到约 0.2970，因为新增的 K = 3 样本占比低（K 固定时占比为 1/2 − 1/K，K 越小占比越低）。可证伪指标：统计生成样本的边数分布、无描述位置占比与描述段数分位数，与原始区间对比。
  3. 推导与审计设计：已知一条房源平均保留 9.26 张图，且同一房源内近景相似度较高。要求 (a) 推导按图片随机划分时，一条房源的两张图落入不同集合的概率表达式（设验证比例为 r）；(b) 给定 r = 5%，估算该概率；(c) 说明为什么按房源划分后该风险为零。 ★★
    提示
    (a) 两张图分属两侧的概率为 2r(1 − r)。(b) 2 × 0.05 × 0.95 = 0.095，即约 9.5% 的房源会跨集合。(c) 房源作为整体进入一侧，同房源图对的跨集合概率为 0。
  4. 许可链分析：给定三种使用场景，分别列出需要核对的许可环节并判断可行性。(a) 复现论文并在论文中对比指标；(b) 用 BnB 域内预训练权重发布开源模型；(c) 把含平台图片的数据集镜像到公开网盘供下载。 ★★
    提示
    (a) 遵守数据集与平台条款即可，标注来源与版本。(b) 核对模型派生条款与平台条款，通常需要脱敏并声明数据来源，不能附带原图。(c) 镜像原图通常超出平台条款允许范围，应改为发布标识符、特征或采集脚本，并保留权利人撤回的处理流程。
  5. 审计计划设计：为一个新的数据源（例如某平台的室内导览视频）写出完整数据工程方案，要求 (a) 抽样框与分层抽检设计；(b) 清洗规则清单与误杀率估计方法；(c) 划分单位选择与泄漏检查；(d) 许可链与隐私处理记录；(e) 数据卡片字段与校验值设计；(f) 三个预期风险与降级方案。 ★★★
    提示
    (a) 按城市、房型、拍摄设备分层，先估每层有效率再定样本量。(b) 规则含镜头边界检测、室内外判别、重复视频检索；误杀率用分层人工抽检估计。(c) 划分单位取「同一房源或同一视频」，跨集合做感知相似度检索。(d) 识别内容权利人、平台条款、人像与屏幕处理三件事并留痕。(e) 卡片覆盖来源、规模、划分、许可、规则版本、生成策略、已知偏差与校验值。(f) 示例风险：平台接口变化（改用历史快照并标注时间窗）、许可撤回（准备仅保留特征的下架版本）、重复内容泛滥（先聚类再抽样）。

小结

  • BnB 的规模链条为：约 15 万个美国房源、超过 300 万张原始图与约 100 万条描述，清洗后保留 71.3 万图文对与 67.6 万无描述图；留存率 46.300%、描述覆盖率 51.332%、每房源保留 9.26 张；划分按房源 95% / 5%。
  • 抽样框决定偏差结构：地理集中、营销式构图与动作词稀缺三类偏差在采集阶段写入，只能通过分层抽检记录并缓解。
  • 清洗审计把损失分为可审计删除、不可审计未采集与误杀三类，对应留存率、覆盖率、重复率与误杀率四类指标；清洗规则必须与数据同版本管理。
  • 划分粒度取最小独立采集单位；按房源划分时 9.26 张图的近景相似风险降为零，划分后仍要做跨集合相似度检索。
  • 许可链分三层：论文许可覆盖文本，内容权利归创作者与平台，资产许可（如 Matterport 非商业条款）约束派生模型；再分发前逐层核对。
  • 成本核算：BnB 15 轮训练约 214 万个正样本与约 1,924 万次正负比较、约 33,398 步；抽检按分层与误差目标设计，按每秒一张图估算，全检约 386 小时，1% 分层抽样约 3.9 小时。
