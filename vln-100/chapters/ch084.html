第 084 讲｜MapGPT：语言化地图与自适应规划

本讲解剖 MapGPT（Chen、Lin、Xu、Chai、Liang、Wong 2024，ACL 2024，arXiv:2401.07314v3）：把在线构建的拓扑地图序列化成提示词，交给单一导航专家，并让模型输出可迭代更新的多步规划。R2R val-unseen（783 条，单跑）上 GPT-4V 版本 43.7 SR、5.63 NE；REVERIE 抽样 500 条上 31.6 SR；回溯修正率 39.2%，为 NavGPT 的 4.11 倍。学完能独立设计一套地图到提示词的地图序列化格式。

  • 主题：零样本提示 / 语言化地图 / 自适应规划 / 成本控制
  • 关键数字：每步 672 输入与 115 输出 token（对照 NavGPT 的 2,465 与 317）；val-unseen SR 43.7 对 34；回溯修正 39.2% 对 9.54%
  • 预计学时：70 分钟
  • 前置章节：第 083 讲（NavGPT-2：冻结 LLM + 策略网络）

学习目标

  • 会算：单专家与多专家的每步 token 成本比、SR / OSR / NE / SPL 增量、回溯与修正率的联合概率。
  • 会解释：纯局部动作空间为何导致无目的探索、精确坐标为何对 LLM 不可读、拓扑关系文本化为何能补全局视野。
  • 会实现：在线拓扑图更新、地图序列化、自适应规划提示组装与解析三段示意代码。
  • 会判断：72 场景子集、val-unseen 783 条、REVERIE 抽样 500 条三套协议的适用范围，以及单预测与 5 预测对照的口径差异。
  • 会设计：一份包含轨迹、连通关系、节点注释与补充信息的地图序列化格式，并给出上下文预算控制方案。

背景与动机

第 082 讲的 NavGPT 把每一步的全景观测翻译成文本再交给 GPT-4，决策只发生在当前节点的相邻候选上。失去全局视野的后果在图 1 的分析中被点名：智能体一旦发现走错，只能围绕当前视野继续试探，缺少回到合适节点重新探索的结构。第 083 讲的 NavGPT-2 用训练好的策略网络解决了这个问题，代价是需要两阶段训练与推理数据。

MapGPT 选择零样本路线解决同一个问题：把环境拓扑在线构造成图，再序列化成自然语言提示，让语言模型的输入从邻域视角扩展为一份包含已探索轨迹、连通关系与候选注释的地图。论文给出两条支撑观察：其一，精确 GPS 坐标对 GPT 不可读，把坐标塞进提示后表现下降；其二，把拓扑关系改写为「Place A is connected with Places B, C」这类句子后，全局探索与回溯能力同时出现。

另一个工程动机是成本。NavGPT 的三专家体系每步平均消耗 2,465 个输入 token 与 317 个输出 token（论文 3.1 节，R2R 口径）；MapGPT 用单专家系统压到 672 与 115。地图提示附带成本：提示长度随步数增长，需要专门设计序列化格式与截断规则。本讲在 083 的「训练策略」之后给出零样本一侧的技术全貌，第 085 讲的 DiscussNav 会在同一成本坐标轴上再增加多专家讨论的分支。

核心原理

本节按「决策式、地图构建、序列化、坐标对照、自适应规划、结果、边界」七步展开。数字来自 MapGPT 论文（Chen 等 2024，arXiv:2401.07314v3）表 1 至表 4；R2R 指标遵循离散协议（成功为终点距离小于 3 米），各表均注明场景数与轨迹数。

1. 单专家决策式

每步输入由任务描述 D、指令 I、历史 Ht、观测 Ot、动作空间 At、地图 Mt 与上一轮规划 Pt−1 组成，提示管理器（Prompt Manager, PM）把它们拼成一次调用，语言模型同时输出思考、规划与动作：

Tt, Pt, at = LLM( PM(D, I, Ht, Ot, At, Mt, Pt−1) ) Ot 只保留可导航点的观测；At 含 N 个候选加 1 个 stop；输出思考 T、规划 P、动作 a

与 LangNav 等微调路线相比，这里没有任何训练：地图、规划、动作全部由提示结构定义；与 NavGPT 相比，去掉了历史摘要与指令分解两个额外专家，历史只记录动作序列（「step 0: …, step t−1: …」）。

2. 在线拓扑地图

地图是动态更新的图 Gt = {Vt, Et}，跟随 DUET 的图记忆思想：每个观测到的节点按观测顺序编号（该编号同时充当节点 ID），每步仿真器返回的相邻可导航节点与新边用于把 Gt−1 更新为 Gt。节点分三类：

类别含义在提示中的角色
已探索节点 enj轨迹经过的节点，含起点 en0 与当前节点 ent构成轨迹行，供理解行进路线
可达节点 anti当前节点相邻、本步可导航的节点构成动作空间与连通行
未探索不可达节点 unj曾被观测但当前不可达的节点补充信息，供回溯时参考

三类节点的划分直接决定提示结构。已探索节点保证模型知道「从哪里来」，可达节点限定「能去哪里」，不可达节点保留「以后可能回去哪里」。回溯能力来自第三类节点的保留，只维护「当前可通行」列表的做法不支持回头。

3. 地图序列化

论文给出三类序列化片段。第一类是轨迹行，把节点 ID 按观测顺序排开：

Trajectory: Place en0 … ent 只记节点 ID，不重复观测内容；避免历史信息与地图冗余

第二类是连通关系行。连通性只在已探索节点处可观测，因此每行以已探索节点开头，列出其相邻的可达节点 ID：

Map: Place en0 is connected with Places an00, …；…；Place ent is connected with Places ant0, … 回溯到旧节点时连通关系无需重建，图一旦写入即可反复读取

第三类是动作注释：动作空间每一项从「方向加观测」升级为「标签、方向、节点 ID、观测」四元组，模板为「{label} {direction} Place {anti}: {ot,i}」。节点 ID 让模型的规划文本与地图条目可以互相引用。补充信息区保存未探索不可达节点的原始图像（单阶段 GPT-4V 系统）或场景描述（两阶段文本系统）。

4. 坐标图对拓扑图：一次负结果

DUET 把节点精确坐标编码进图学习，MapGPT 尝试把同样的坐标喂给 GPT，结果在 72 场景子集上出现负增益：GPT-4V 带坐标地图的 SR 为 41.2，低于不带地图基线的 42.6；SPL 从 34.7 降到 32.8。换用拓扑关系文本后，SR 升到 44.9、SPL 升到 36.5。论文的解释是坐标数值难以激活语言模型的空间推理。这项消融给出一个可迁移的结论：给语言模型的空间信息应当保持关系形态，保持拓扑即可，无需回到几何数值。

5. 自适应规划

NavGPT 与 DiscussNav 记录每一步的思考过程，再另设专家做摘要，冗余度高。MapGPT 改为维护一段可迭代更新的多步规划 Pt：模型结合思考、地图与前次规划生成新规划，当前规划作为下一步输入，初始规划 P0 记为空状态。相比单步动作选择，规划文本可以同时覆盖多个候选节点与子目标，发现走错时可以显式声明「若此处未见目标，则回到 Place 2 重新探索」。论文把它概括为从「每步记录想法」转向「写工作预案并按需更新」。

7. 边界与失效模式

  • SPL 模态分化：GPT-4 两阶段版本在 val-unseen 的 SPL 为 25.8，低于同协议 NavGPT 的 29.0；在 72 场景子集上，41.2 SR 对应的 SPL 25.4 也低于同为子集口径的 DiscussNav 33.3。论文归因于视觉到文本的信息损失，模型在描述不足时倾向继续探索、路径变长。GPT-4V 单阶段 38.1 才恢复路径效率，引用 SPL 必须注明模态、阶段数与协议。
  • 提示长度随步数线性增长：地图行、轨迹行、补充信息都以每步 O(1) 条增加的速率累积，长程任务需要截断或压缩；论文未给出上下文溢出的处理细节，复现时需自建预算规则。
  • 72 场景对照的训练背景不齐：NavGPT 版本用 GPT-3.5，DiscussNav 用 GPT-4 且为单预测口径（其原论文在 783 条 val-unseen 上 5 预测为 43 SR，协议与预测数均不同），MapGPT 用 GPT-4 与 GPT-4V。表内差值是「模型加方法」的混合差，不能全部归因于地图。
  • 零样本与训练模型的差距仍在：同数据协议内，MapGPT GPT-4V 的 43.7 SR 与训练类方法（HAMT 66、DUET 72、ScaleVLN 81，val-unseen）相差 22 至 37 个点；论文自己把「与预训练微调模型的显著差距」列入局限性。
  • REVERIE 只评导航：实验忽略物体定位子任务，31.6 SR 只表示停靠在正确位置附近的比例，与含定位评测的 REVERIE 数字不可对齐；抽样 500 条也要求同种子复现。

实现思路与设计

本讲的工程核心是地图序列化格式。一份可用的实现需要回答四个问题：节点如何命名、连通关系写多少行、每个动作带哪些字段、上下文超预算时先删谁。下面给出与论文结构一致的设计方案。

序列化格式

区块格式更新频率预算策略
TrajectoryPlace en0 … ent每步追加一个 ID只存 ID，长度线性且系数最小
MapPlace enj is connected with Places …新节点或新边出现时追加每行只列 ID；旧行不重建
Action{label} {direction} Place an: {observation}每步重建观测描述截断到固定长度
Supplementary未探索不可达节点的图像或描述每步重建只在需要回溯时保留少量条目
Planning多步规划文本 Pt每步迭代限行数，保留子目标与回溯条件

节点名直接用观测顺序整数，保证提示内可引用、可追溯。动作标签（A、B、C…）与方向短语一起出现，输出侧只要求一个标签（如「Action: B」），解析成本低。历史区只写被选动作，不重复写思考，防止与规划区重复。

上下文预算

设第 t 步地图行数为 Lt，轨迹行长度 t，动作区长度 N+1。合理预算优先级是：动作注释优先保留，其次当前规划，再次连通关系，最后是补充信息与早期轨迹。一个可执行的截断规则是「补充信息只保留最近 K 个不可达节点、轨迹只保留最近 K 步加起点」，K 取 3 至 5，兼顾回溯与预算。该规则属于工程建议，论文未给出具体截断参数；复现时应在验证集上扫 K 并记录溢出步数。

与相邻讲的差异

相对 082（NavGPT）：去掉历史摘要与指令分解专家，新增地图与规划区，token 成本降到 27.26% 的输入与 36.28% 的输出。相对 083（NavGPT-2）：不训练、不依赖策略网络，代价是空间决策仍由语言模型完成，且每次推理调用付费。相对 085（DiscussNav）：单专家与多专家的分工取舍将在下一讲展开。

关键代码与解读

三段代码分别给出在线拓扑图更新、地图序列化、自适应规划提示的组装与解析。示意实现，接口风格贴近 Python 字典式图记忆。

片段 1：在线拓扑图更新

class TopoMemory:
    """按观测顺序编号的拓扑图；ID 从 0 递增，同时充当提示里的 Place 编号。"""
    def __init__(self):
        self.nodes = {}          # id -> {"obs": ..., "visited": bool}
        self.edges = set()       # 无向边 (i, j)，i < j
        self.order = []          # 观测顺序，用于 Trajectory 行
        self.current = None

    def observe(self, view, neighbors):
        """每步调用：登记当前节点、相邻新节点与新边。"""
        if self.current is None:                     # 起点首次登记
            nid = self._register(view, visited=True)
            self.current = nid
        for nbr_view in neighbors:                   # 相邻可导航节点
            nid = self._register(nbr_view, visited=False)
            a, b = sorted((self.current, nid))
            self.edges.add((a, b))                   # 去重，无向存储
        return [n for n in self.reachable()]         # 本步可达节点 ID

    def _register(self, view, visited):
        for nid, node in self.nodes.items():
            if node["view_key"] == view.key:         # 视图唯一标识去重
                return nid
        nid = len(self.nodes)
        self.nodes[nid] = {"view_key": view.key, "obs": view,
                           "visited": visited}
        if visited:
            self.order.append(nid)
        return nid

    def reachable(self):
        """当前节点的一跳邻居：从无向边中取出另一端，去重后返回。"""
        nbrs = [j for (i, j) in self.edges if i == self.current]
        nbrs += [i for (i, j) in self.edges if j == self.current]
        return sorted(set(nbrs))

解读：（1）节点 ID 取观测顺序整数，与提示中的 Place 编号一一对应，规划文本回引不会歧义。（2）视图唯一标识用于去重，同一节点被多次观测只登记一次；这是控制地图规模的关键。（3）无向边用排序元组存储，避免同一条边写两次。

片段 2：地图序列化

def serialize(memory, reachable, max_supplementary=5):
    """把图记忆转成 Trajectory、Map、Action、Supplementary 四个区块。"""
    lines = []
    traj = " ".join("Place %d" % i for i in memory.order)
    lines.append("Trajectory: " + traj)               # 只放节点 ID

    for nid in memory.order:                          # 已探索节点逐行写连通关系
        nbrs = sorted(j if i == nid else i
                      for (i, j) in memory.edges if nid in (i, j))
        if nbrs:
            lines.append("Place %d is connected with Places %s"
                         % (nid, ", ".join(str(n) for n in nbrs)))

    unexplored = [n for n in memory.nodes
                  if not memory.nodes[n]["visited"] and n not in reachable]
    supp = unexplored[-max_supplementary:]            # 只保留最近若干条，控预算
    if supp:
        lines.append("Supplementary Info: Places %s"
                     % ", ".join(str(n) for n in supp))
    lines.append("""Choose one action. Reply exactly:
Thought: <one sentence>
Plan: <subgoals and when to backtrack>
Action: <label>""")                                # 输出协议固定，便于解析
    return "\n".join(lines)

解读：（1）Trajectory 与 Map 都只写节点 ID，观测内容集中在动作区，防止同一信息在提示里出现两次。（2）连通行只从已探索节点出发，因为可达性只在走过的地方可见；回溯到旧节点时这些行无需重建。（3）Supplementary 限制条数（示例 5 条），这是上下文预算的第一道闸门；论文用图像或描述填充该区，工程实现可替换为短摘要。

片段 3：自适应规划与动作解析

ACTION_RE = re.compile(r"^Action:\s*([A-Z])\s*$", re.M)

def step(agent, memory, instr, history, reachable, plan_prev, labels):
    """组装一次调用；输出思考、规划与动作标签，规划进入下一轮。"""
    actions = []
    for label, nid in zip(labels, reachable):         # 标签一一对应可达节点
        direction = agent.direction_to(memory.nodes[nid]["obs"])
        actions.append("%s %s Place %d: %s"
                       % (label, direction, nid, memory.nodes[nid]["obs"].caption))
    prompt = build_task_prompt() + "\n" + serialize(memory, reachable)
    prompt += "\nAction Space:\n" + "\n".join(actions)
    prompt += "\nHistory: " + " ".join(history) if history else ""
    prompt += "\nPrevious Plan: " + (plan_prev or "none")
    reply = agent.chat(prompt)                        # 单次调用，无历史摘要
    match = ACTION_RE.search(reply)
    if not match or match.group(1) not in labels:     # 解析失败或标签越界
        raise ValueError("invalid action reply")      # 上层重试或回退到启发式
    plan_prev = extract_plan(reply)                   # 多步规划迭代更新
    thought = extract_thought(reply)
    return match.group(1), thought, plan_prev

def extract_plan(reply):
    """取 Plan 行到 Action 行之间的文本；缺失时返回空串。"""
    m = re.search(r"Plan:\s*(.+?)(?=\nAction:|$)", reply, re.S)
    return m.group(1).strip() if m else ""

解读：（1）动作区把标签、方向、节点 ID、观测绑在一起，输出协议只要求一行「Action: 标签」，解析正则显式校验标签合法，越界即抛错，避免把幻觉出来的动作喂给环境。（2）Previous Plan 字段让规划跨步迭代；论文的 P0 为空状态，此处用 none 表示。（3）解析失败的处理属于工程补强：可重试一次，或者回退到「选与指令地标匹配度最高的候选」启发式，并在日志中记录发生率。

常见坑

  • 把精确坐标塞进提示：认为定位越准越好。症状是全局探索退化，SR 从基线 42.6 降到 41.2，SPL 从 34.7 降到 32.8（GPT-4V，72 场景子集）。根因是数值坐标难以激活语言模型的空间推理。修复：只保留拓扑关系，坐标留在环境侧供控制使用。
  • 历史区重复写地图信息：把每步观测文本全量累积进历史。症状是提示长度迅速膨胀、成本失控且噪声挤压关键信息。根因是历史与地图职责重叠。修复：历史只记被选动作一行，观测集中在动作区，地图区只放 ID；补充信息设条数上限。
  • 动作空间缺 stop 或标签与节点错配：只列 N 个候选。症状是智能体无法停止或停错位置，OSR 与 SR 差距拉大。根因是动作空间不完整。修复：定义 at,0 为「A. stop」，共 N+1 项，并在解析时校验标签指向的节点与本步可达列表一致。
  • 对照协议混排：把 72 场景 216 条、val-unseen 783 条、REVERIE 500 条的子集数字放进同一张排名表；或者拿 DiscussNav 在 783 条协议上的 5 预测成绩（43 SR）与它在 72 场景上的单预测成绩（37.5）交叉比较。修复：按协议分组出表；对照多预测方法时统一到单预测口径，并把预测数与轨迹数写进表注。
  • SPL 跨模态直读：把 GPT-4 两阶段 25.8 的 SPL 解释为「路径效率差的方法缺陷」，忽略信息损失与探索路径变长这一机制，并与 GPT-4V 的 34.8 混谈。修复：SPL 与 NE、OSR、SR 成组报告，注明单阶段或两阶段、文本或视觉观测量。
  • 把零样本数字与训练模型直接排名：43.7 SR 被拿来与 ScaleVLN 的 81、DUET 的 72 直接比较。修复：单独列出零样本区间，另注训练数据规模与是否使用额外环境，跨区间只做定性讨论。

小结

  • MapGPT 用单专家提示系统实现零样本导航：任务描述、基本输入、语言化地图与前次规划拼成一次调用，输出思考、规划与动作。
  • 地图为按观测顺序编号的在线拓扑图，分已探索、可达、未探索不可达三类节点；序列化只写节点 ID 与连通关系，观测集中在动作区，保证提示可读且可回溯。
  • 坐标对语言模型不可读：GPT-4V 坐标档 SR 41.2 低于无地图基线 42.6；拓扑文本档 44.9，加自适应规划到 47.7。
  • R2R val-unseen（783 条，单跑）GPT-4V 43.7 SR / 5.63 NE，对 NavGPT 分别高 9.7 个点与低 0.83 米；REVERIE 抽样 500 条上 31.6 SR；回溯修正联合比例 39.2%，为 NavGPT 的 4.11 倍。
  • 成本压到每步 672 输入与 115 输出 token，为 NavGPT 三专家体系输入侧的 27.26%；代价是提示长度随步数增长，需要自建预算与截断规则。
