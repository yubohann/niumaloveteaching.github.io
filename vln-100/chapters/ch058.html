第三篇 · 连续环境、跨域与真实平台

第 058 讲｜真实机器人系统集成方案

本讲以 Anderson 等 2020（CoRL 2020，arXiv:2011.03807v1）与 Krantz 等 2021（ICCV 2021，arXiv:2110.02207v1）为两条主线，把 VLN 策略接进真实机器人导航栈：感知输入、位姿与同步、路点接口、低层控制、安全兜底与评测闭环。Coda 实验给出有图 46.8%、无图 22.5% 两档集成基线；Waypoint Models 证明接口松耦合可行，换成离散导航器只掉 1 至 3 个成功率点，而两种接口的动作数与运动代价差异达到 3.97 倍与 1.94 倍。

  • 主题：系统集成 / 导航栈 / 接口契约 / 安全兜底 / 真机评测
  • 关键公式：决策间隔 = EET / 决策数（如 153 s / 8.41 = 18.19 s）；EET 只覆盖运动层
  • 预计学时：60 分钟
  • 前置讲：第 057 讲（视角与高度变化鲁棒性）

学习目标

  • 会写：画出策略接入导航栈的四层框图（传感与位姿、策略服务、执行、安全监督），并说明每层的输入输出与失效模式。
  • 会算：由路点模型数据核算决策间隔、执行时间与动作数差异；判断某段运动耗时是否落在 EET 的口径之内。
  • 会实现：观测装配与策略服务循环、两段式导航器、独立于策略的看门狗与限幅三个最小部件。
  • 会判断：给定平台与任务，选择有图或无图部署模式、连续或离散导航器，并给出理由与代价。
  • 会诊断：坐标与时间错配、把 EET 当墙钟预算、停止判定缺确认、安全兜底从属策略四类问题的成因与修复。

背景与动机

第 049 至 057 讲分别处理了子目标模型、感知接口、部署评测、视角鲁棒性等单点问题，本讲把它们装进同一台机器人。系统集成回答的是接口问题：策略看到什么、以什么频率思考、输出交给谁执行、出错时谁来兜底。第 044 讲已把运动代价拆到 LoCoBot 的时间模型，本讲沿数据流向上补齐感知、推理、网络与安全四段，并给出可复制的契约与检查表。

两条参考线各有侧重。Anderson 等 2020 给出首个完整的真机系统评测：TurtleBot2 平台加全景相机与二维激光，ROS 1 工具链做建图、定位与规划，子目标模型把离散策略的动作翻译成路点；在预先建图的 Coda 办公室中成功率 46.8%，无图冷启动 22.5%，且无图设置下首次出现碰撞。Krantz 等 2021 从接口表达力入手：策略只输出相对路点或停止动作，低层导航器负责执行；换成离散导航器后成功率只掉 1 至 3 个点，说明接口可以松耦合，而运动代价与动作数的差距说明接口选择直接影响部署效率。

本讲先建立分层视图与接口契约，再讲执行与安全，最后给出真机评测闭环与边界。读完应能为自己的策略写出一份「谁在什么频率上收到什么、失败时发生什么」的集成方案。

核心原理

本讲按「分层分解、两条参考线、输入链路、决策与执行解耦、控制接口、安全兜底、评测闭环、边界」展开；论文数字标注来源与协议，换算先算后写。

1. 四层分解：每一层都有独立的失效模式

把导航任务从传感器到轮子切成四层，是集成的第一原则：层与层之间用显式契约连接，层内的失效不直接穿透到层外。

  • 传感与位姿层：全景相机与激光、深度相机的采集、时间同步与位姿估计（SLAM 或外部定位）。典型失效是丢帧、时间戳错位与定位漂移。
  • 策略服务层：把观测装配成策略输入，运行推理，输出路点或停止动作。典型失效是输入不齐、推理超时与输出越界。
  • 执行层：把路点目标交给全局与局部规划、控制器，或两段式导航器直接执行。典型失效是目标不可达、规划失败与卡死。
  • 安全监督层：看门狗、速度限幅、安全距离、急停与人工接管。安全层独立于策略，直接作用于速度指令或动力回路；典型失效是安全信号被策略覆盖。

Anderson 等 2020 的系统可以按这四层逐项对照，第 4 至 7 小节展开。

2. 参考系统 A：Anderson 等 2020 的分工

硬件为 TurtleBot2 平台：Kobuki 移动底座、Asus Xtion Pro Live RGBD 相机、车载微型计算机；为获取 360° 视觉加装 Ricoh Theta V 全景相机，安装高度 1.35 米；二维激光扫描仪 Hokuyo 覆盖 270°、量程 30 米，安装高度 0.24 米。软件运行 ROS Kinetic，用 gmapping 构建 0.05 米分辨率的占用栅格地图，amcl 做粒子滤波定位，move_base 做全局与局部规划。策略侧沿用 R2R 训练的 EnvDrop 智能体，通过子目标模型（第 049 讲）获得候选路点。

两处系统级设计值得记住。第一，评测定位与机器人定位分离：机器人靠自己的 SLAM 导航，评测另跑一套带地图的定位栈记录位姿，后者的误差约 0.3 米，比 3 米成功阈值小一个数量级；这样评估工具的先验知识不会替机器人完成任务。第二，两组先验条件分开报告：有图设定预先提供占用图与导航图，成功率 46.8%；无图设定每次从零开始 SLAM，成功率 22.5%。相对仿真的 55.9%，有图差距 9.1 个百分点（相对降幅 16.28%），无图相对有图再降 24.3 个百分点（相对降幅 51.92%）。

环境方面，Coda 空间有 5 处 80 至 90 厘米的窄点，机器人加车载计算机宽约 40 厘米，单侧余量 0.20 至 0.25 米；有图设置下无碰撞、无导航失败，无图设置下记录到子目标误检（螺旋楼梯假阳性）与漏检（窄通道假阴性），并首次出现碰撞。行人偶发干扰也被记录，静态假设在真实环境中只能近似成立。

3. 参考系统 B：Krantz 等 2021 的松耦合接口

Waypoint Models 把策略与执行之间的接口定义得更清晰：策略输出相对极坐标路点 (r, θ) 或停止动作，r 的连续范围为 0.25 至 4 米，θ 的修正范围为 ±15°（可离散为 5° 档），低层导航器负责把机器人送到路点。论文用两段式导航器做实验：先转向路点方位，再直行到路点距离；整个导航器不处理语言，职责单一。

接口表达力与执行代价的权衡由一组数字给出（第 044 讲的模型复算）：每轨迹动作数，路点模型 8.41 次，固定步长模型 33.41 次，比值 3.97；估计执行时间（EET）分别为 153 秒与 297 秒，相差 144 秒，比值 1.94；平均速度折算 6.94 与 2.60 厘米每秒，比值 2.67；按完成时间加权的成功率 SCT 为 23 与 11，比值 2.09。换成离散导航器（15° 转向、0.25 米步长）执行同一批路点，成功率只下降 1 至 3 个百分点，说明接口的松耦合在性能上可以接受，代价集中在运动效率，任务成功率的损失有限。

路点预测的统计特征也进入接口设计：平均路点距离 1.6 米、标准差 0.8 米；轨迹前 25% 平均 2.3 米、中间 50% 平均 1.6 米、后 25% 平均 0.76 米，呈先粗后细的节奏。这解释了为什么决策率可以很低：每个路点要执行数秒到十余秒，策略不需要按控制频率思考。

4. 输入链路：全景、位姿与同步

策略输入可以概括为「观测加位姿」。观测侧有两条常见路线。第一条是全景相机直出一张 360° 图像，再按 12 个朝向重采样（Anderson 等 2020 的 Theta V）；第二条是多个相机或激光融合出 12 路对齐 RGB-D 视图（Sun 等 2025 的 TurtleBot2 加 Ouster OS0 激光方案，每个朝向间隔 30°）。离散侧的路点模型以 12 帧、每帧 90° 视场、256 × 256 分辨率的口径训练（Krantz 等 2021），重采样时必须对齐这个口径，否则策略看到的分布与训练不一致。

位姿侧要求两个约定：坐标系链一致（map、odom、base_link、相机系的外参固定并在配置中版本化）与时间戳一致（图像、激光与位姿按采集时刻对齐，允许的陈旧上限显式配置）。Anderson 等 2020 用二维激光加 amcl 提供平面位姿，足够支撑单层室内；第 057 讲的真机系统在 ROS 2 上用远程服务器推理，机器人把图像流经网络送往服务器，动作与目标再传回执行，这条链路在集成时要把网络往返纳入预算，并准备断线降级策略。

5. 决策与执行解耦：两个频率互不拖累

策略频率远低于控制频率，这个数量级差是接口设计的出发点。按第 044 讲口径复算决策间隔：路点模型 153 秒内做 8.41 次决策，平均 18.19 秒一次；固定步长模型 297 秒内做 33.41 次决策，平均 8.89 秒一次。而底盘控制环在 5 至 10 赫兹（周期 100 至 200 毫秒）量级，两者相差约两个数量级。结论：策略应当按事件触发（到达路点或视角显著变化时重新推理），控制环按固定周期运行；把两者绑成同一频率会浪费算力，也会把推理抖动引入控制回路。

决策间隔 = EET / 决策数 路点模型 153 / 8.41 = 18.19 秒；固定步长模型 297 / 33.41 = 8.89 秒（Krantz 等 2021 的 LoCoBot 运动模型，单位秒）

执行一侧的接口有两种实现：把路点作为目标交给导航栈（全局规划加局部控制器），或由两段式导航器直接执行。导航栈的优点是复用避障与恢复行为，代价是目标容差、规划周期与坐标系约定需要逐项核对；两段式导航器的优点是行为可预测、延迟低，代价是避障要靠上游候选筛选与安全层兜底。选择判据是「环境复杂度」：走廊与开放房间可用两段式；窄通道、动态障碍与多楼层用导航栈。

6. 执行层与控制：容差、恢复与卡死

路点执行需要三类参数：位置容差与朝向容差（到位判定）、执行超时（放弃当前路点并请求重规划）、恢复行为（原地旋转、后退、重新规划）。Anderson 等 2020 的移动作业依赖 move_base 自带恢复行为，Coda 的窄点余量只有 0.20 至 0.25 米，恢复行为若过于激进会擦碰；无图设置下的卡住与提前终止是该系统中失败的主要形态之一。

Krantz 等 2021 的两段式导航器把「转向到位再直行」写成两个循环，未达容差或超时都返回失败，由策略侧决定下一步。这个设计在集成时的含义是：执行器只报告成功或失败，不自行解释语言；策略拿回控制权后可以换一个候选路点。失败上报比静默重试更利于诊断，也避免执行层与策略层各自维护一套超时。

7. 安全兜底：独立、就地下沉、可审计

安全层的第一原则是独立于策略：策略可能输出错误路点、持续输出或完全静默，安全层都要把机器人带回安全状态。可落地的部件有四类。

  • 看门狗：监视策略心跳与目标流。目标流停止超过阈值（示例 0.5 秒，按控制环 10 赫兹折算 5 个周期）即输出零速度并等待；阈值与频率成正比配置。
  • 速度限幅：在速度指令进入底盘前做最后一道裁剪（示例上限线速度 0.4 米每秒、角速度 0.8 弧度每秒），裁剪只降不升，保证任何上游错误都不会放大为危险速度。示例值为设计起点，需按底盘能力标定。
  • 安全距离：用激光或深度前向读数设置停车距离。Coda 的窄点余量为单侧 0.20 至 0.25 米，安全距离若取 0.25 米量级会在最窄处触发停车，需要按机器人宽度与通过策略联合标定；论文环境中机器人宽约 40 厘米。
  • 急停与接管：硬件急停回路不经过软件；软件侧提供接管开关与降级模式（断网保持原地、定位漂移超限停车请求重定位）。

安全信号的优先级要写入接口契约：急停高于看门狗，看门狗高于限幅，限幅高于策略目标；任何一层触发都不等待上层确认。

8. 集成后的评测闭环

评测沿用第 048 讲协议，但增加两项系统级要求。第一，配对设计：同一批指令在仿真与真机、有图与无图条件下各跑一遍，环境尽量平行（Anderson 等 2020 的做法），差距才能分解为视觉、视角与先验三项。第二，位姿跟踪独立：评测用带图定位栈记录位姿，与机器人自身导航定位分离，且报告评测栈的误差量级（约 0.3 米）。指标沿用 SR、SPL、NE，并记录终止原因（到达、超时、卡死、碰撞、人工接管）与恢复行为触发次数；无图设置的轨迹变短不能计入效率提升，要先排除卡住与提前终止。

9. 边界与失效模式

  • 静态单层假设：Coda 为 325 平方米单层办公空间，家具每次复位，实验在白天进行；动态人流、多层建筑与光照剧变需要重新验证。
  • 定位精度依赖：amcl 加二维激光在 Coda 可用；换成精度更差的里程计方案，3 米成功判定本身会变得模糊，停位误差进入视角差距。
  • 网络与算力：远程推理（第 057 讲模式）依赖网络；断线、抖动与服务器排队都要有降级路径，端侧部署则受显存与功耗约束。
  • 接口版本漂移：ROS Kinetic 与 move_base 已结束主流维护，ROS 2 对应组件为 Nav2；迁移时坐标、容差与恢复行为语义需要逐项重验。
  • 先验条件混用：46.8% 依赖预先采集的占用图与导航图，22.5% 为无图冷启动；两者对应不同的部署成本与适用场景，不能当作同一系统的两个随机种子。
  • 评测栈误差：约 0.3 米的位姿记录误差显著小于 3 米阈值，但它不参与成功阈值的余量计算时，仍可能影响 OSR 一类依赖最近点的指标。

实现思路与设计

集成方案由四张表支撑：系统框图（分层数据流）、接口契约、硬件与软件对照、延迟预算；最后给一条部署模式的选择判据。

系统集成框图（分层数据流）

层数据流
传感与位姿层全景相机（12 路 / 30°）＋ 激光或 RGB-D ＋ 轮式里程计 → 同步帧与 TF 位姿 → 策略服务
策略服务层观测装配 → VLN 策略（输出路点 (r, θ) 或 STOP）→ 路点目标（地图系）＋ 策略心跳 → 执行层与安全层
执行层路点目标 → 导航栈（全局规划加局部控制）或两段式导航器 → 速度指令 → 底盘

设计决策：路点接口作为策略与栈的边界，安全层作为速度接口的最后一道

把路点定为接口，策略不关心底盘与规划器，导航栈也不理解语言；换导航器只掉 1 至 3 个成功率点，证明边界稳定。安全层挂在速度接口上并独立于策略进程，判据是「任何上游失效都不能产生危险速度」：看门狗处理静默，限幅处理越界，安全距离处理环境，急停处理一切。四者不需要理解策略输出的是路点还是离散动作。

关键代码与解读

片段 1：观测装配与策略服务

import rclpy
from rclpy.node import Node
from sensor_msgs.msg import Image
from geometry_msgs.msg import PoseStamped, Twist

class PolicyBridge(Node):
    """装配 12 路全景与位姿，事件触发调用策略，发布路点目标或停止。"""
    def __init__(self):
        super().__init__("vln_policy_bridge")
        self.views = [None] * 12
        for i in range(12):
            topic = "/camera/view_%d" % i
            self.create_subscription(Image, topic, self.make_cb(i), 10)
        self.create_subscription(PoseStamped, "/slam/pose", self.on_pose, 10)
        self.goal_pub = self.create_publisher(PoseStamped, "/nav/goal", 10)
        self.stop_pub = self.create_publisher(Twist, "/safety/stop", 10)
        self.pose = None
        self.create_timer(0.2, self.check_ready)      # 仅做就绪检查，低频

    def make_cb(self, i):
        def cb(msg):
            self.views[i] = msg                        # 记录最近一帧
        return cb

    def on_pose(self, msg):
        self.pose = msg

    def check_ready(self):
        if self.pose is None or any(v is None for v in self.views):
            return                                     # 数据不齐不推理
        obs = self.assemble(self.views, self.pose)     # 12 路帧加位姿
        action = self.policy(obs)                      # 路点或停止
        if action.is_stop:
            self.stop_pub.publish(Twist())             # 停止转为零速度
        else:
            self.goal_pub.publish(self.to_goal(action))  # 极坐标路点转地图系目标

解读：（1）感知回调只做缓存，策略调用集中在就绪检查里，避免每来一帧就推理一次；事件触发的真正条件（到达路点或视角变化）由执行层反馈，示例用低频检查简化。（2）数据不齐时不发布任何目标，安全层的心跳看门狗会独立判断是否停车，两层职责不重叠。（3）停止动作单独走安全话题，语义是「立即停」，与路点目标的「前往某处」分开，便于安全层做优先级处理。

片段 2：两段式路点执行

import time

def execute_waypoint(cmd, r, theta_deg, tol_deg=5.0, tol_m=0.15, timeout_s=30.0):
    """先原地转向路点方位，再直行到路点距离；失败返回 False。"""
    deadline = time.monotonic() + timeout_s
    while abs(cmd.yaw_error_deg(theta_deg)) > tol_deg:
        cmd.turn(max(-30.0, min(30.0, cmd.yaw_error_deg(theta_deg))))
        if time.monotonic() > deadline:
            cmd.stop()
            return False                              # 转向超时，交还策略
    while abs(cmd.traveled_m() - r) > tol_m:
        cmd.forward(max(-0.3, min(0.3, r - cmd.traveled_m())))
        if time.monotonic() > deadline:
            cmd.stop()
            return False                              # 直行超时，交还策略
    cmd.stop()
    return True                                       # 成功到位

解读：（1）两个循环对应「先转向、再直行」，与 Krantz 等 2021 的两段式导航器一致；执行器不解释语言，只跟踪一个路点。（2）容差与超时都写成参数：容差决定停位精度（对应第 049 讲停位误差造成的视角差距），超时决定卡死时的接管时机。（3）失败时直接返回，由策略侧换候选路点或请求重规划，不进入无限重试；这一约定让「谁负责重试」没有歧义。

片段 3：独立安全监督

import time

class SafetyMonitor:
    """独立于策略的看门狗、限幅与安全距离；任何越界都输出零速度。"""
    def __init__(self, timeout_s=0.5, v_max=0.4, w_max=0.8, min_obstacle_m=0.25):
        self.last_goal_t = time.monotonic()
        self.timeout_s = timeout_s            # 心跳超时：0.5 秒约 5 个控制周期
        self.v_max = v_max                    # 线速度上限，按底盘标定
        self.w_max = w_max                    # 角速度上限
        self.min_obstacle_m = min_obstacle_m  # 停车距离，按宽度与窄点标定

    def notify_goal(self):
        self.last_goal_t = time.monotonic()   # 每次收到目标刷新心跳

    def guard(self, cmd_v, cmd_w, obstacle_m, estop):
        if estop:
            return 0.0, 0.0, "estop"          # 最高优先级
        if time.monotonic() - self.last_goal_t > self.timeout_s:
            return 0.0, 0.0, "goal_timeout"   # 策略静默，停机等待
        if obstacle_m < self.min_obstacle_m:
            return 0.0, 0.0, "obstacle"       # 安全距离先于规划器生效
        v = max(-self.v_max, min(self.v_max, cmd_v))   # 限幅：只降不升
        w = max(-self.w_max, min(self.w_max, cmd_w))
        return v, w, "ok"

解读：（1）三个条件按优先级短路返回，急停最先、看门狗其次、安全距离第三，与设计小节写定的优先级一致。（2）限幅在最后生效，处理策略与规划器的越界输出；裁剪后的值仍需经过底盘驱动层的物理限制校验，两层不互相替代。（3）看门狗计时用「最近一次收到目标的时间」，策略侧只需每次发布目标时刷新；0.5 秒阈值与控制周期成正比，控制环频率变化时要同步调整。

常见坑

  • 时间戳与坐标框架错配：图像、激光与位姿各用自己的时钟，或 TF 链里外参写反，表现为路点目标系统性偏向一侧。根因是同步与标定没有版本化。修复：统一时钟源并在回放数据上做静态场景验证；外参文件带版本号，改动后重跑一条固定轨迹核对落点。
  • 把 EET 当墙钟预算：用运动层的 EET（代表行 153 秒）直接承诺现场耗时，漏掉感知、推理、网络与排队。根因是忽略第 044 讲只覆盖运动层的口径。修复：分层列预算并实测每段；把决策间隔（18.19 秒量级）与运动耗时分开记录，避免把「决策少」误读为「整段快」。
  • 停止判定缺少确认：策略输出停止后没有二次校验，机器人在错误位置停机，成功判定随之失败。根因是只信策略输出的一个信号。修复：停止动作进入安全流程做确认（允许微调、要求静止时速度为零、记录最近一次位移）；第 049 讲的 oracle 成功率与成功率差值可用于估计这类失败的量级。
  • 安全兜底从属策略：看门狗由策略进程兼职，或限幅放在策略内部，策略卡死时整条链停摆。根因是安全组件与业务逻辑同进程同频率。修复：安全组件独立进程或独立 MCU，输入只依赖心跳与传感器；把优先级写进接口文档并做故障注入测试。
  • 有图与无图口径混用：引用 46.8% 时不写「预先提供占用图与导航图」，或把无图的 22.5% 与有图直接平均。根因是先验条件没有作为数字标签。修复：所有数字带部署模式标签；报告两档结果与部署成本，需要单档结论时注明适用场景。

小结

  • 集成分四层：传感与位姿、策略服务、执行、安全监督；每层有独立失效模式与契约，评测层另设并与机器人定位分离。
  • Anderson 等 2020 的系统给出两档基线：有图 46.8%、无图 22.5%，相对仿真 55.9% 的差距为 9.1 与 33.4 个百分点；Coda 窄点余量单侧 0.20 至 0.25 米，有图无碰撞，无图首次出现碰撞。
  • Krantz 等 2021 证明路点接口可松耦合：换离散导航器只掉 1 至 3 个成功率点；接口表达力带来 3.97 倍动作数与 1.94 倍 EET 的差异，决策间隔 18.19 秒远大于控制周期。
  • 安全层独立于策略并置于速度接口之前：看门狗、限幅、安全距离、急停按优先级短路；任何上游失效都不能产生危险速度。
  • 评测闭环要求配对设计、位姿跟踪独立与终止原因记录；EET 只覆盖运动层，感知、推理、网络与规划要另列预算并实测。
