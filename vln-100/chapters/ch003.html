第一篇 · 任务、数据、仿真与评测地基

第 003 讲｜Matterport3D Simulator：导航图与接口

本讲把 002 讲的静态全景数据变成可交互环境：导航图（节点为全景位姿、边为可通行连接、权重为距离）、观察与动作接口（视角旋转、仰俯调整、前向跳转）以及渲染与状态分离的调用协议。读完应能独立读取官方图文件、解释每个字段的单位与约定，并用一条真实轨迹核对观察与动作的时序关系。

  • 主题：导航图 / 观察接口 / 动作接口 / 渲染与状态分离
  • 关键接口：newEpisode / getState / makeAction
  • 数据规模：90 场景 / 10,800 全景节点 / 平均度 4.16
  • 预计学时：60 分钟
  • 前置讲次：第 002 讲（Matterport3D 全景数据底座）

学习目标

  • 能描述导航图的三元结构（节点、边、边权）与成图规则，并解释 5m 上限、全景点间距 2.25m 之间的约束关系。
  • 能写出观察接口的结构字段（scanId、step、rgb、depth、location、heading、elevation、viewIndex、navigableLocations）及其类型、单位与坐标系约定。
  • 能解释动作接口 makeAction 的三个参数（候选下标、朝向增量、仰俯增量）的语义，并判断给定位姿下哪些邻居进入候选列表。
  • 能区分仿真器层与任务层（客户端）的职责：渲染、位姿、候选列表由仿真器持有；指令、奖励、停止动作与指标由任务层实现。
  • 能独立读取官方连通性文件，复算节点数、度数与边长的统计量，并用一条 episode 轨迹核对观察与动作字段的对应关系。

背景与动机

第 002 讲把 Matterport3D 作为数据集介绍：90 个建筑尺度场景、10,800 张全景、每张全景由 18 张带 6 自由度位姿的 RGB-D 图拼接而成、相邻全景平均间距 2.25m。数据集本身是静态的，智能体无法在其中迈出一步。要让「按自然语言指令走到目标」这类任务可训练、可评测，需要一个能返回观察、接受动作、并保证动作合法（不能穿墙、不能瞬移）的可执行环境。Matterport3D Simulator 正是这个环境，它与 R2R 数据集同文发布（Anderson 等，2018，arXiv:1711.07280；CVPR 2018）。

为什么环境要以「图」的形式组织？因为全景只出现在离散的拍摄点上，拍摄点之间的空间没有连续观测；直接把任意两点连起来会在墙、楼板与镜面处产生非法位移。官方做法是：先在场景网格上做射线检测，判断两个全景点之间是否存在障碍；再删除过长的边，保持每一步都是局部移动；最后人工复核窗户、镜面等网格中缺失的障碍。结果是每个场景一张带权无向图，智能体在节点之间跳转，在节点上自由旋转相机。

本讲解决三个具体问题：其一，看懂导航图的存储格式与统计口径；其二，看懂观察与动作接口的字段、单位与调用顺序；其三，弄清「哪些事由仿真器做、哪些事由任务层做」的职责边界。前者决定数据检查怎么做，中者决定代码怎么写，后者决定指标与实验的可比性。

与后续讲次的衔接：第 004 讲解剖 R2R 数据集如何在图上采样路径并配指令；第 005 讲把动作接口抽象成 12 视角候选与 picking、beam search 等解码口径；第 017 讲讨论离散图环境与连续环境（VLN-CE）的鸿沟。本讲是这条链路的机器层底座。

核心原理

1. 导航图：结构、成图规则与版本口径

仿真器对每个场景维护一张带权无向图 G = <V, E>：节点 v ∈ V 对应一个全景位姿（3D 位置、相机朝向、仰俯），边 ⟨vi, vj⟩ ∈ E 表示两点之间可以机器人通行，边权为两点的直线距离。节点的位姿由数据集的 6 自由度相机位姿给出，相机高度约为站立人眼高度（官方示例中 z 约为 1.5m 至 1.7m）。

论文（Anderson 等，2018）描述的成图流程分三步：在 Matterport3D 场景网格上对全景点两两做射线检测（ray-tracing），检测中间是否存在障碍；删除长度超过 5m 的边以保持运动局部性；人工检查并修正窗户、镜面等网格未刻画的障碍。给定当前节点 vt，仿真器在每一步返回的候选集合为

Wt+1 = { vt } ∪ { vi ∈ V | ⟨vt, vi⟩ ∈ E 且 vi ∈ Pt } Pt 为第 t 步相机视锥左右边界围出的空间区域；vt 表示原地停留选项，始终存在

这条式子的含义：只有当前视场内（允许上下瞥视）的相邻节点才是可行动作。动作是确定性的，同样的位姿与同样的动作参数得到同样的结果，这为复现与调试提供了基础。

需要提前说明一个版本口径问题：论文描述的是 2018 年发布时的图；本讲对当前官方仓库（含 90 份连通性文件，2019 年后维护状态）做了逐图复算，发现 5m 上限只是近似执行。43,909 条有向可通行连接中，99.2% 不超过 5m，另有 352 条（0.80%）超过 5m，最长 16.798m。引用「5m 上限」时应当同时标注版本，评测结果也必须与所用图文件绑定，详见第 8 小节的失效模式。

3. 位姿与坐标系

智能体位姿是三元组 st = ⟨v, ψ, θ⟩：v 为节点编号（内部用整数下标 ix，外部用全景唯一标识 viewpointId 表示），ψ 为相机朝向（heading），θ 为相机仰俯（elevation）。官方接口的约定如下，务必记牢，后续所有动作设计都依赖它：

  • 朝向：以 y 轴为基准、z 轴向上，右转为正，单位为弧度。取值归一化到 [0, 2π)。
  • 仰俯：以 x-y 平面为地平线，向上为正，单位为弧度。默认限幅为 ±0.94 rad（约 ±53.86°），防止相机朝向极点造成投影畸变。
  • 动作结果确定性：相同的位姿与相同的动作参数组合产生相同的下一状态。

观察接口对每个候选邻居返回三个相对量：相对朝向 rel_heading、相对仰俯 rel_elevation 与相对距离 rel_distance。设当前位姿为 (ψ, θ)，当前节点到候选节点的位移为 (Δx, Δy, Δz)，仿真器按下面的式子计算（与官方 C++ 实现一致）：

c = ( cos(π/2 − ψ), sin(π/2 − ψ) )
rel_heading = atan2( Δx·cy − Δy·cx, Δx·cx + Δy·cy )
rel_elevation = atan2( Δz, sqrt(Δx² + Δy²) ) − θ
rel_distance = sqrt(Δx² + Δy² + Δz²) c 为相机水平朝向的单位向量；rel_heading 正值表示目标在当前朝向的右侧；rel_elevation 需减去当前仰俯

把动作参数取成 Δψ = rel_heading、Δθ = rel_elevation，就能在一步跳到邻居的同时把相机对准它，这正是「前向」动作在连续接口下的写法。若在离散视角模式下操作，转向被量化为 ±30°（分度值 π/6 ≈ 0.523599 rad）或 0，此时 rel_heading 只用于选择方向，不再逐弧度对齐。

4. 观察接口：SimState 与相对量

仿真器每次 getState 返回一个批量为 B 的列表，每个元素是一个 SimState。字段与语义如下：

  • scanId：所在场景标识，字符串。
  • step：自本次 newEpisode 以来经过的帧数；每次 makeAction 加一，纯旋转也计一步。
  • rgb：当前视角的透视投影图，8 位三通道，通道顺序为 BGR（OpenCV 约定），默认尺寸 320×240，基线配置为 640×480。
  • depth：可选的 16 位单通道深度图，默认关闭。数值为像素沿相机 z 轴的垂直距离（相机近处曲面产生的欧氏距离已被着色器换算），每个单位 0.25mm，除以 4000 得米；0 表示无读数（镜面、透明面等）。满量程 65,535 × 0.25mm = 16.384m。
  • location：当前节点对象，含 viewpointId、图内下标 ix 与三维坐标 (x, y, z)，相对量字段均置零。
  • heading、elevation：当前相机朝向与仰俯，单位弧度。
  • viewIndex：仅离散视角模式有效的观察编号，取值 0 至 35：0 至 11 为俯视带（约 −30°），12 至 23 为平视带（0°），24 至 35 为仰视带（约 +30°）。三个带各含 12 个 30° 分隔的朝向，共 12 × 3 = 36 个标准视角。
  • navigableLocations：候选节点列表。下标 0 恒为当前节点（原地停留选项），其余元素按角距离 sqrt(rel_heading² + rel_elevation²) 从小到大排序；因此下标 1 是画面中心附近最接近「正前方」的候选。

候选列表的排序键同时包含水平与垂直偏差，这是对「画面中心」的合理代理：仰俯偏差大的候选即便水平方向正对，也不适合作为前向目标。

5. 动作接口：状态相关的候选选择

动作通过 makeAction(index, heading, elevation) 一次性提交三个参数。index 是进入 navigableLocations 的下标，取值必须落在列表长度内，越界会抛出异常；index = 0 表示不移动、只调整相机。heading 与 elevation 是相对增量：连续模式下为任意弧度，离散模式下按符号取 ±30° 或 0。动作在一步内同时完成跳转与相机调整，随后仿真器更新位姿、重算候选集合、再渲染下一帧。

这个接口有两个容易忽视的性质。其一，动作空间是状态相关的：候选集合随位姿、视场配置与受限导航开关变化，同一个邻居在不同朝向下可能进列表也可能被过滤。其二，index 是「本次观察内的局部下标」，不是节点编号；下一步观察到的是重新排序后的新列表，沿用旧下标会把动作作用到另一个候选上。

官方 Python 接口的完整调用顺序为：构造 Simulator，配置分辨率、视场、深度、批量、缓存等参数，调用 initialize，用 newEpisode 指定场景、起点、朝向与仰俯（或用 newRandomEpisode 随机起点），随后循环执行「getState 观察、决策、makeAction 执行」。示例中把相机左转 30° 的调用为 makeAction([0], [-0.523599], [0])，可作为符号约定的自检用例。

6. 受限导航与视场公式

在默认配置下，受限导航（restricted navigation）开启，候选只能取视场内的邻居。实现层面，仿真器对每个邻居计算其方向与相机水平朝向的夹角余弦，要求不小于半水平视场的余弦阈值。半水平视场由垂直视场与宽高比推出，实现中采用的是小角度近似：

半水平视场 ≈ vfov × (width / height) / 2 近似式；精确式为 atan(tan(vfov/2) × width/height)，两者在大视场下差异明显

代入两组常用配置做数值核对。默认 vfov = 0.8 rad、宽高比 4:3 时，近似半视场为 30.56°，对应水平视场 61.12°；精确值为 58.82°，偏差 2.29°。论文基线 vfov = 60°、640×480 时，近似水平视场 80.00°，精确值 75.18°，偏差 4.82°。视场越大偏差越大，这条实现细节会影响候选集合的边界判定。

对全部 10,567 个 included 节点、12 个离散朝向（共 126,804 个状态）统计默认配置下的候选数量，结果如下表。表中候选数含原地停留选项，因此可见邻居数需再减一。

均值 1.70 意味着在默认视场下，任意朝向上平均只有 0.70 个邻居可见，中位状态恰好只有 1 个可见邻居。这与无受限时的平均度数 4.16 形成鲜明对比：大量可通行连接需要通过旋转相机才会出现在候选集合中。由此得到两条设计启示：策略必须把「旋转以发现出口」当作核心子能力；评测配置必须显式记录视场与受限导航开关，否则候选集合量纲不一致，指标不可比。

7. 渲染、缓存与吞吐

渲染侧的实现要点：每个全景点预存一张立方体贴图（六个面拼在一张图里），运行时用透视投影把相机视锥方向的贴图内容投射到目标分辨率；渲染后端有三种，带窗口的 OpenGL、离屏的 EGL 与纯 CPU 的 OSMesa，训练场景推荐 EGL。相机近平面 0.1m、远平面 100m，天空盒立方体缩放为 10m 边长。仓库 README 报告在 Titan X 上以 640×480 做 RGB-D 离屏渲染约 1000 帧/秒，单帧约 1ms；若按历史做法一次铺满 36 个标准视角，约需 36ms。对 10Hz 量级的决策频率而言余量约两个数量级，瓶颈通常不在渲染。

内存侧有两笔账。预加载（preloading）把全部场景贴图放进内存，README 给出的量级为 RGB 约 50GB、含深度约 80GB，按 10,800 张全景折算每张约 4.7MB 至 7.6MB；预加载只影响启动时间，不影响每个动作的延迟。显存侧用 LRU 缓存保存最近使用的全景贴图，缓存 200 张时约占 1.2GB 显存，折合每张约 6MB，官方建议缓存容量明显大于批量大小以避免抖动。仓库还保留了一条历史工作流：把朝向与仰俯按 30° 离散为 36 个视角并预计算 ResNet-152 特征（2,048 维），特征文件约 380K 行、2.9GB。按 10,800 × 36 = 388,800 复算，文件行数比全量乘积低约 2.3%，与被排除的重复全景点及版本差异方向一致。

8. 适用边界与失效模式

这个环境有明确的适用边界，越界使用会带来方法层面的误判：

  • 离散拓扑限制：智能体只能在拍摄点之间跳转，学到的连续控制能力有限，这也是 VLN-CE 等连续环境工作出现的原因（第 017 讲）。
  • 采集偏差：论文自述场景以整洁、陈设讲究的住宅、办公室与酒店等室内空间为主，人和动物极少，拍摄点倾向于视野开阔处；智能体学到的先验可能偏离真实机器人所处环境。
  • 静态假设：场景无动态物体、无物理交互，渲染结果随版本固定，策略无法应对移动障碍与光照变化。
  • 配置敏感：候选集合依赖视场、分辨率、受限导航开关与图版本；任何一项变化都会改变动作空间，跨配置比较指标无效。
  • 图版本漂移：论文的 5m 上限在当前官方图中只是近似成立（0.80% 超限，最长 16.798m），旧论文数字与当前文件混用时会出现无法复现的差异。
  • 深度口径：深度默认关闭；开启时需先做深度天空盒预处理，且原始深度存在缺失值（镜面、透明、远处表面），官方用滤波填补大部分空洞，零值代表无读数。

把这些边界写进实验记录，是保证结论可追溯的最低要求。

实现思路与设计

1. 调用协议：渲染与状态的职责分离

官方实现是 C++ 引擎加 Python 绑定（进程内调用，无网络 RPC）：仿真器持有导航图、位姿状态、贴图缓存与渲染管线，对外只暴露 newEpisode、getState、makeAction、close 等少量入口；任务层（如 R2R 的 env 封装）负责指令、episode 采样、奖励、停止动作与指标。这种划分让渲染与状态管理对任务代码透明，也解释了为什么环境本身不包含「停止」动作：停止、奖励与成功判定都由任务层扩展。仓库另附一套 WebGL 前端，用于轨迹可视化与机械 Turk 标注，说明渲染层可以与策略客户端解耦部署。

层持有状态提供不负责
仿真器（C++/OpenGL + Python 绑定）导航图、位姿、贴图缓存、渲染管线观察（rgb/depth/候选列表）、动作执行、批量与缓存配置指令、奖励、停止、指标
任务客户端（R2R env 等）指令、episode、轨迹、指标累加器动作空间扩展（含停止）、奖励函数、评测口径渲染与位姿演化
WebGL 前端可视化状态轨迹回放、标注采集策略训练与评测

这样的分层直接决定了写代码时的顺序：先跑通「观察循环」，再加载指令与奖励；仿真器侧的配置必须先行固定，初始化后再修改配置不会生效。

2. 一条 episode 的观察→动作轨迹

5. 工程组织与运行开销

训练侧的常规组织是批量加缓存：批量取到显存允许的规模，缓存取批量的两倍左右；预加载只在数据盘与内存充足时开启。以渲染 1ms/帧的 README 口径估算，批量 100 时一次同步渲染约 0.1 秒，若策略前向耗时相近，则环境与模型各占约一半时间，属于可接受配比；当批量继续增大时，先触顶的通常是贴图缓存与显存；渲染吞吐通常仍有富余。调试阶段建议关闭预加载、把批量设为 1，用官方 Python 演示脚本验证渲染与动作链路，再切到批量训练。

关键代码与解读

以下片段为数据结构与流程示意（原创示例，非工程源码拷贝），用于说明图文件读取、观察字段计算与最小交互循环的写法。

片段 1：读取连通性文件并构建出边邻接表

import json

def load_graph(path):
    """读取官方连通性 JSON：节点表与出边邻接表。"""
    nodes = json.load(open(path, encoding="utf-8"))
    ids = [n["image_id"] for n in nodes]
    included = [n["included"] for n in nodes]
    # pose 为行主序 4x4，平移分量位于索引 3、7、11；z 为高度
    pos = [(n["pose"][3], n["pose"][7], n["pose"][11]) for n in nodes]
    # unobstructed 是长度 N 的布尔行；仿真器额外要求目标节点 included
    adj = {i: [j for j, ok in enumerate(n["unobstructed"])
               if ok and j != i and included[j]]
           for i, n in enumerate(nodes)}
    return ids, included, pos, adj

ids, included, pos, adj = load_graph("17DRP5sb8fy_connectivity.json")
edges = {(min(i, j), max(i, j)) for i, ns in adj.items() for j in ns
         if included[i] and included[j]}
print(len(ids), sum(included), len(edges))
# 输出：48 44 83（48 个节点、44 个可导航节点、83 条可导航无向边）

解读：（1）读取路径与字段名严格对应官方文件，unobstructed 只给出边，不给出距离，距离需由 pose 平移分量计算。（2）仿真器构图时跳过 included=false 的目标，示例保持一致。（3）该场景 44 个可导航节点与 83 条无向边对应平均无向度约 3.77，与全局统计 4.06 同量级，可用作读取逻辑的正确性自检。这段代码可直接用于数据检查与场景筛选。

片段 2：复算观察中的相对量与视场过滤

import math

def rel_parts(cur_xy, cur_z, tgt_xy, tgt_z, heading, elevation):
    """复算仿真器 populateNavigable 的相对量，单位弧度 / 米。"""
    dx, dy = tgt_xy[0] - cur_xy[0], tgt_xy[1] - cur_xy[1]
    dz = tgt_z - cur_z
    cam = (math.cos(math.pi / 2 - heading), math.sin(math.pi / 2 - heading))
    rel_h = math.atan2(dx * cam[1] - dy * cam[0], dx * cam[0] + dy * cam[1])
    rel_e = math.atan2(dz, math.hypot(dx, dy)) - elevation
    return rel_h, rel_e, math.sqrt(dx * dx + dy * dy + dz * dz)

def in_view(rel_h, vfov, aspect):
    """受限导航的视场判定，与官方实现的近似式保持一致。"""
    half_hfov = vfov * aspect / 2.0
    return math.cos(rel_h) >= math.cos(half_hfov)

rh, re, dist = rel_parts((1.44112, -0.394211), 1.52512, (1.59346, 0.480708), 1.52467,
                         heading=0.0, elevation=0.0)
print(round(rh, 5), round(re, 5), round(dist, 4), in_view(rh, 0.8, 4 / 3))
# 输出：0.17239 -0.00051 0.8881 True

解读：（1）四个式子与官方 C++ 实现逐项对应，可用于离线核对仿真器返回的观察值。（2）rel_heading 的符号由叉积项决定，正值表示目标在当前朝向右侧；把动作增量取为该值即可对准目标。（3）视场判定只使用水平夹角，仰俯不参与过滤；阈值用近似式，视场越大与精确值的偏差越大。

片段 3：最小交互循环（伪代码）

sim = MatterSim.Simulator()
sim.setCameraResolution(640, 480)
sim.setCameraVFOV(math.radians(60))
sim.initialize()
sim.newEpisode(["17DRP5sb8fy"], ["ee59d6b5..."], [0.0], [0.0])

for t in range(max_steps):
    s = sim.getState()[0]                    # 观察：rgb、位姿、候选列表
    k, dpsi, dtheta = policy(s, instruction) # 策略输出候选下标与转向增量
    if k == STOP:                            # STOP 由任务层定义与结算
        break
    sim.makeAction([k], [dpsi], [dtheta])    # 跳转与转相机在同一步完成

解读：（1）循环体固定为「观察、决策、执行」三段，任何方法（Seq2Seq、Transformer、LLM 智能体）都套用同一骨架。（2）策略输入含指令，指令的注入与奖励结算都在任务层完成，仿真器对此无感知。（3）动作参数只在当步候选列表内解释，策略需在每一步重新读取候选，禁止缓存跨步的下标。

常见误区

  • 转向方向反了：策略输出的 Δψ 与目标脱节，轨迹系统性偏离。根因：朝向以 y 轴为基准、z 轴向上、右转为正；许多图形库默认左转为正。修复：用官方示例 makeAction([0], [-0.523599], [0]) 即左转 30° 做符号自检，再在策略侧统一乘号。
  • 沿用了上一步的候选下标：动作跳到了非预期节点，且越界时直接抛异常。根因：navigableLocations 每一步都按新位姿重新计算与排序，index 是局部下标。修复：把候选列表视为「本步快照」，决策与执行使用同一份快照，禁止跨步缓存。
  • 把停止与奖励算进仿真器：找不到 stop 动作或奖励无法挂钩。根因：仿真器只做位姿演化与渲染，不定义目标、奖励与停止。修复：在任务层扩展动作空间（R2R 的 6 动作含 stop），奖励与成功判定在客户端实现。
  • 候选集口径漂移：训练与评测的候选数量对不上，指标不可比。根因：候选集合依赖视场、分辨率、受限导航开关，甚至依赖图版本的单向标记。修复：把 vfov、受限导航、图文件版本写入配置文件并在日志中打印；跨配置实验先做候选集分布对照。
  • 深度图用错单位或把 0 当有效值：以米为单位误用原始读数，或把无读数的 0 当成「距离为零」。根因：深度为 16 位、0.25mm/单位，需除 4000 换算成米，0 代表缺失。修复：读取后立即换算并构造有效掩码，缺失值不入损失。

小结

  • 导航图把 10,800 张全景组织成带权无向图：节点为全景位姿，边为可通行连接，边权为直线距离；官方图实算平均度 4.06、平均边长 2.258m。
  • 观察接口以 SimState 为中心：rgb/depth 为像素观察，heading/elevation 为相机状态，navigableLocations 为状态相关的候选列表（下标 0 为原地，其余按角距离排序）。
  • 动作接口 makeAction(index, Δψ, Δθ) 在一步内完成跳转与相机调整；候选下标只在本步观察内有效，停止与奖励属于任务层。
  • 默认受限导航把候选限制在视场内，平均只有 0.70 个邻居可见；视场、分辨率与图版本共同决定候选口径，必须在实验记录中固定。
