第一篇 · 任务、数据、仿真与评测地基

第 020 讲｜第一篇回顾：任务-数据-评测公共语言

本讲收束第一篇：把 001 至 019 讲的任务、数据、指标与平台压进同一张「任务 × 数据 × 指标 × 平台」大表，逐项标注协议版本；给出十条高发误用清单；用 Python 完成指令总量、切分闭合、协议换算与显存档四组实算；最后交付术语与口径表汇总版与一套阶段自测。

  • 主题：第一篇回顾 / 公共语言 / 口径对账 / 阶段自测
  • 关键数字：六套指令数据集合计 189,927 条指令；R2R 落差 16.8 点（相对 43.52%）；协议换算差异 4.2 m 对 0.5 m
  • 预计学时：60 分钟
  • 前置讲：第 019 讲（AerialVLN / CityNav：空中与城市）

学习目标

  • 会整理：把任意一项 VLN 工作写进「任务 × 数据 × 指标 × 平台」四格，并为每格标注协议版本三要素（数据集版本、split、步数上限）。
  • 会算：复算六套指令型数据集的指令总量与占比、每路径指令数、切分闭合，以及指令长度的跨数据集倍数。
  • 会判断：给定两组数字，指出它们能否直接比较，并定位失配维度（阈值、距离定义、动作接口、停止规则、语言覆盖）。
  • 会诊断：用本讲的误用清单定位实验日志与论文表格中的口径错误。
  • 会设计：按阶段自测检验第一篇的掌握度，并为第二篇的复现实验建立统一的协议记录卡。

背景与动机

第一篇用 19 讲铺完了四层地基：任务定义（001、013 至 016）、数据与仿真（002 至 005、012）、评测指标（006 至 011）、平台与跨域（017 至 019）。读者此时手里有大量数字，却不共享同一套比较规则：R2R 的 20.4%（学生强制基线）、RxR 的 25.9%、VLN-CE 的 32%、AerialVLN 的 1.6%，任何一个脱离协议的裸数字都会误导判断。

公共语言缺位才是问题的症结。Gu 等 2022 的 VLN 综述（ACL 2022，arXiv:2203.12667v3）在开篇就把问题分为任务、评测方法与挑战三块，指出同一名称下的协议差异是系统性问题；Zhang 等 2024 的综述（arXiv:2407.07035v2）进一步以具身规划与推理的框架自顶向下组织基础模型时代的方法与挑战。两篇综述给的是研究地图；本讲补的是地图的坐标单位：每个数字在什么协议下测出、能回答什么问题、不能回答什么问题。

无统一口径的代价可以用一个数字说明：第一篇建立的三条基线事实中，R2R 的 seen 与 unseen 成功率落差达到 16.8 个百分点（相对降幅 43.52%，实算）。若把 val-seen 的数字当泛化证据，会把「环境记忆」误读为「方法进步」；若把 val-unseen 的 21.8% 与后文完全不同协议的数字拼表，会得出错误的难度排序。

本讲解决三件事：把四层公共语言压成一张可查的大表；把高发误用做成清单与判定规则；用实算对账验证数据侧的规模与闭合。读完本讲，你应能在十分钟内判断一篇 VLN 论文的数字可信度与可比范围，并知道第二篇（021 起）的每条方法线对应哪一格协议。

核心原理

1. 公共语言的四层结构

3. 指标层：四类分工与定义式

指标按度量对象分四类，混用会掩盖失败模式。终点类看「到没到」，效率类看「绕没绕」，保真类看「走法对不对」，过程类看「进度与目标语义」。

NE = dG(vT, v*)，Success = 1[ NE < 3 m ] dG 为导航图最短路径距离，忽略朝向与俯仰；连续环境改用欧氏距离并单独声明阈值
SPL = (1 / N) · Σi=1..N Si · li / max(pi, li) Si 为成功指示；li 为最短路径长度；pi 为实际路径长度；失败记 0，max 防止抄近路时超过 1
类别指标度量对象适用协议报告要求
终点类NE、SR、OSR停止点与目标的距离；是否停在阈值内；轨迹是否曾接近目标全部协议三个数字成组报告，OSR 与 SR 差值单列
效率类SPL成功轨迹相对最短路径的长度比R2R、RxR、R2R-CE、城市与空中与 SR 成对；注明最短路径的定义来源
保真类CLS、NDTW、SDTW轨迹对参考路径的覆盖与对齐R4R、RxR注明参考路径构造与对齐来源（词级时间戳）
过程类GP、TC / SPD / SED、框命中相对目标区域的距离增量；触发器与空间描述；指代框匹配CVDN、Touchdown、REVERIE与主指标并报，注明单位与阈值

四类指标存在可证明的结构关系：同一条轨迹上 OSR 不小于 SR（在更宽停止规则下成功集合更大）；REVERIE 的复合成功率不超过其导航成功率（013 讲实算条件正确率 11.28 / 19.88 = 56.74%）；SPL 同时对失败与绕行计罚，只看 SR 无法区分这两类损失。引用单指标结论时，先检查结构关系是否被打破，打破即说明口径或实现有误。

5. 实算对账：总量、闭合、倍数与换算

把第一篇的规模数字做一次统一对账，验证它们在同一套算术下自洽。六套以指令为主的数据集（R2R、RxR、REVERIE、SOON / FAO、Touchdown、CVDN / NDH）合计 189,927 条指令；其中 RxR 占 66.38%，REVERIE 占 11.43%，R2R 占 11.36%，Touchdown 占 4.91%，CVDN / NDH 占 3.90%，SOON / FAO 占 2.03%（Python 实算，见代码片段 1）。RxR 一套的指令量约为其余五套之和的 1.97 倍（实算 1.9742），这解释了它为何成为多语言与对齐研究的首选底座。

切分闭合是数据可信度的第一道检验：R2R 的场景数 61 + 11 + 18 = 90 与总量吻合；RxR 四条切分路径 11,089 + 1,232 + 1,517 + 2,684 = 16,522，指令 28,010 + 13,992 + 42,068 + 41,999 = 126,069；REVERIE 四段 10,466 + 1,371 + 3,573 + 6,292 = 21,702；NDH 四段 4,742 + 382 + 907 + 1,384 = 7,415。全部闭合，说明这些规模数字可以直接进入实验预算。

指令长度给出语言难度排序：以 R2R 的 29 词为基准，RxR 78 词为 2.69 倍，AerialVLN 83 词为 2.86 倍，Touchdown 108 词为 3.72 倍。单句对齐方法的能力上限会随指令长度系统性下降，这解释了 022 的增广、031 的预训练与 034 之后的长程历史工作的动机。

落差与人类距离同样用实算固定口径：R2R 的学生强制基线 val-seen 38.6%、val-unseen 21.8%，绝对落差 16.8 点、相对降幅 43.52%；Speaker-Follower 完整系统为 70.1% 与 54.6%，绝对落差 15.5 点、相对降幅 22.11%。两个系统的绝对落差接近、相对降幅相差近一倍，报告落差时必须写清采用绝对还是相对口径。人类与模型的差距：R2R test 人类 86.4% 为学生强制基线 20.4% 的 4.235 倍；Speaker-Follower test 53.5% 达到人类的 61.9%；Touchdown 人类 92% 为最佳基线 4.5% 的 20.44 倍。

成功阈值的相对尺度决定了任务宽严印象：R2R 的 3 m 约占平均路径 10 m 的 30%，AerialVLN 的 20 m 占 661.8 m 的 3.02%，CityNav 的 20 m 占约 545.4 m 的 3.67%。室内阈值相对宽松、空中与城市阈值相对严格，直接比较成功率没有意义。

最后是协议换算的最小算例：自设最后一条边权 4.2 m，智能体停在边上距目标 0.5 m 处。离散协议只认节点，NE 记 4.2 m，判定失败；连续协议按欧氏距离记 0.5 m，判定成功。同一条轨迹、同一终点，两个协议给出相反结论，比值 0.5 / 4.2 = 0.119。这就是跨协议拼表无效的直接证据。

显存档沿用 001 与 004 讲的口径：12 视角 × 2048 维 float32 特征每帧 96 KiB；全库 379,080 行、约 2.89 GiB；若换原始像素，每帧 12 × 640 × 480 × 3 字节约 10.55 MiB，为特征表示的 112.5 倍。第一篇的所有方法讨论都建立在这一组预算上。

7. 适用边界

  • 大表是快照：以本篇写作时点为准，HM3D 与 2023 年后的新基准会在 063、093 至 098 讲补充；引用前先核对是否有更新的协议版本。
  • 四层齐备是必要不充分条件：两份工作四层全同，数字仍可能因预训练、增广、解码搜索与快照选择而不可比；与第 007、079 讲的统计口径配合使用。
  • 指标的结构关系只对同协议成立：OSR 不小于 SR 在离散与连续协议内均成立，跨协议不保证。
  • 语言覆盖决定训练信号：RxR 的 7.63 条每路径含三语冗余，三语并未覆盖每条路径；把 126,069 当训练样本上限会高估。
  • 平台维护状态会漂移：habitat-lab v0.3.4 后官方停更，复现旧数字需要绑定发布号与容器环境（018）。

实现思路与设计

本讲交付三件工程对象：统一协议卡、术语与口径表汇总版、阶段自测与复核流程。三者的共同目标是让「比较」成为一次可机检的操作。

产出 1：统一协议卡

协议卡把四层公共语言压成一行键值对，作为任何实验记录、表格与图注的前置字段。缺字段的记录不得进入对比表。

片段 2：同一轨迹的协议换算

EDGE = 4.2          # 离散图上最后一条边的权，单位米
REMAIN = 0.5        # 连续环境中智能体停在边上，距目标 0.5 米

ne_graph = EDGE                     # 离散协议只认节点，整条边计入 NE
ne_cont = REMAIN                    # 连续协议按欧氏距离计
ok_graph = ne_graph < 3.0
ok_cont = ne_cont < 3.0

print("离散 NE =", ne_graph, "成功 =", ok_graph)
print("连续 NE =", ne_cont, "成功 =", ok_cont)
print("同一终点状态，两协议判定相反：", ok_graph != ok_cont)
print("NE 比值 =", round(ne_cont / ne_graph, 3))
# 输出：离散 NE = 4.2 成功 = False；连续 NE = 0.5 成功 = True；比值 0.119

解读：（1）换算函数保持极简，重点在展示 distance 字段差异如何单独翻转成功判定；真实评测中还要加上网格投影、碰撞与步数上限，误差只会更大。（2）输出比值 0.119 表示同一条轨迹在连续口径下的 NE 只有离散记法的约一成，任何把两种 NE 放进同一坐标轴的图表都不可读。（3）该片段可作为数据管线的一部分：给定离散轨迹与网格碰撞体，重放并同时输出两种口径的 NE 与成功标记，用于跨协议误差分解。

片段 3：协议卡校验与可比性判定

REQUIRED = ["dataset", "version", "split", "max_steps",
            "observation", "action", "distance", "stopping", "metric"]
KEY_FIELDS = ["dataset", "version", "split", "max_steps", "observation",
              "distance", "stopping", "action", "metric"]

def check_card(card):
    """缺字段直接报错，禁止带病记录进入对比表。"""
    missing = [k for k in REQUIRED if k not in card]
    if missing:
        raise ValueError("协议卡缺字段: " + ",".join(missing))
    return True

def comparable(card_a, card_b):
    """关键字段全同才允许数字比较；返回差异字典供图注引用。"""
    check_card(card_a), check_card(card_b)
    diff = {k: (card_a[k], card_b[k])
            for k in KEY_FIELDS if card_a[k] != card_b[k]}
    return (len(diff) == 0), diff

card_a = {"dataset": "R2R", "version": "CVPR2018", "split": "val_unseen",
          "max_steps": "unspecified", "observation": "RGB640x480_vfov60",
          "action": "discrete_6", "distance": "graph_m",
          "stopping": "agent_stop", "metric": "SR"}
card_b = dict(card_a, version="R2R-CE", distance="euclid_m",
              action="continuous_0.25m_15deg", observation="RGBD256_hfov90",
              max_steps=500)
print(comparable(card_a, card_b))
# (False, {'version': ('CVPR2018', 'R2R-CE'), 'max_steps': ('unspecified', 500),
#          'observation': ('RGB640x480_vfov60', 'RGBD256_hfov90'),
#          'action': ('discrete_6', 'continuous_0.25m_15deg'),
#          'distance': ('graph_m', 'euclid_m')})

解读：（1）校验分成两级：字段完整性检查与关键字段相等性检查。前者防止漏记版本与步数，后者产出差异明细，直接进入表格脚注。（2）示例输出显示 R2R 与 R2R-CE 在五个关键字段上不同，结论必然是不可比；这比「读者自行注意」可靠。（3）该校验器可扩展：把 metric 的失败记分规则、平均口径也做成字段，即可覆盖第 007 讲的统计口径检查。

常见误区

  • 把不同协议的成功率并排排序：症状是对比表给出「某方法在 A 数据集更强」的结论，读者复现后无法重现排序。根因是动作接口、距离定义与停止规则至少有一项不同。修复：运行协议卡校验，关键字段不同则改列脚注；跨协议比较只保留趋势与失败模式分析。
  • 相对落差与绝对点差混用：把 R2R 的 16.8 点落差写成「16.8%」，或把 43.52% 的相对降幅当百分点。修复：统一写「绝对点差 + 相对降幅」两栏；本讲算例中两个系统的绝对落差接近（16.8 对 15.5）而相对降幅相差近一倍（43.52% 对 22.11%），只报一栏必然误导。
  • 把 val-seen 数字当泛化证据：val-seen 与训练共享建筑，分数包含环境记忆。修复：报告模板固定两列并自动计算落差；方法主张泛化时只引用 val-unseen 与 test。
  • 忽略每路径指令数与语言覆盖：用 126,069 与 21,567 的比值论证「RxR 数据量为 R2R 的 5.85 倍」，却把三语冗余与覆盖不全都算成独立样本。修复：同时报告路径数、每路径条数与语言构成（RxR 四语文档量占比实算为 22.22% / 11.10% / 33.37% / 33.31%），训练预算按去重后的路径数估算。
  • 把派生值与报告值当同一口径：用均值反推总量后与报告总量不等，判定数据集有错。修复：以总量为准，派生值标注算法与容差；第 002 讲的 219,398.49 与 219,399 的 0.51 m² 残差就是这类舍入现象。

小结

  • 公共语言分四层：任务（指令粒度、目标、交互）、数据（环境、规模、切分、语言）、指标（终点、效率、保真、过程）、平台（观测、动作、版本）；协议卡把四层压成一行可机检字段。
  • 数据对账：六套指令数据集合计 189,927 条，RxR 占 66.38%；R2R 每路径 3.0 条、RxR 7.63 条；四套切分全部闭合；指令长度以 R2R 29 词为基准，RxR 2.69 倍、AerialVLN 2.86 倍、Touchdown 3.72 倍。
  • 可比性由平台与指标决定：R2R 落差 16.8 点（相对 43.52%），Speaker-Follower 落差 15.5 点（相对 22.11%）；成功阈值相对尺度为 30% / 3.02% / 3.67%；同轨迹两协议换算 NE 比值 0.119。
  • 误用清单十条，前五条直接产出错误结论：跨协议拼表、val-seen 当泛化、只看 SR、OSR 当 SR、落差口径混用；后五条覆盖步数上限、规模口径、距离字段、目标泄漏与派生值。
  • 显存档保持一致：12 视角 × 2048 维每帧 96 KiB，全库约 2.89 GiB，原始像素为特征表示的 112.5 倍。
