第一篇 · 任务、数据、仿真与评测地基

第 009 讲｜val-seen / val-unseen：泛化协议

本讲把评测从单次分数推进到协议层：两个验证集各自测什么、场景与指令在哪个层级切分、test 目标为何隐藏、榜单提交要求哪些声明；并用二项标准误与聚类抽样的账目说明 seen-unseen 落差里哪些部分能归因于泛化、哪些只是选择与噪声。

  • 主题：数据集划分 / 泛化协议 / 模型选择 / 统计口径 / 榜单提交
  • 关键数字：61 / 11 / 18 场景；14,025 / 1,020 / 2,349 / 4,173 指令；SR 38.6 → 21.8
  • 预计学时：60 分钟
  • 前置讲：第 008 讲（R4R 与 CLS：路径保真）

学习目标

  • 会算：推导各 split 的场景密度与指令密度，说明 val-seen 与 val-unseen 的切分发生在不同层级（场景池内 / 场景池间）。
  • 会判断：面对「unseen 掉点」的结论，区分环境难度分量、模型过拟合分量与选择偏差分量，并给出各自的证据。
  • 会设计：split × 指标 × 版本的实验记录表，以及不污染 val-unseen 的模型选择协议。
  • 会评估：用二项标准误与场景级聚类抽样估算方法间差距的噪声底，判断小数点差异是否值得主张。
  • 会执行：写清榜单提交所需的口径声明，识别「在 test 上调参」「训练数据组成不明」两类不可比情形。

背景与动机

第 004 讲解剖过 R2R 的四个 split 与 GUID 结构，第 008 讲把保真指标补齐。还剩一个决定结论可靠性的问题没展开：这套划分究竟在测什么，以及报告数字时哪些口径必须声明。R2R 论文报告的学生强制基线在 val-seen 上成功率 38.6%，val-unseen 上 21.8%（Anderson 等，2018，CVPR，表 1）。同一个模型、同一套超参、同一份训练数据，只是评测场景是否见过，数字相差约 1.8 倍。把这个落差直接解释成「模型不会泛化」是常见做法，却经不起推敲：随机基线在两个 split 上几乎不变（15.9% 与 16.3%），落差本身携带的结构信息远比一句「泛化差」丰富。

更棘手的是选择偏差。多数论文的模型快照按验证集挑选，而验证集又有 seen 与 unseen 两套；挑选规则不同，报告的可比性就不同。最终 test 的评测在官方服务器完成，目标位置不公开，训练数据组成也与本地调参阶段不同（R2R 论文的 test 提交使用全部训练与验证数据）。在不清楚这些口径的情况下跨论文对比数字，几乎必然误判。

本讲解决三件事：第一，把划分结构写成可检查的表，明确每个 split 的角色；第二，给出「落差分解」的量化方法，并把噪声底算出来；第三，整理实验记录与提交口径，保证自己的数字与他人的数字可比。

核心原理

1. 划分的三层结构：场景、指令、目标可见性

R2R 沿用 Matterport3D 的场景划分，90 个建筑被拆成三个互不重叠的场景组：61 个场景组成训练池，11 个场景作 val-unseen，18 个场景作 test（Anderson 等，2018，4.4 节）。训练池内部的指令再按 14,025 / 1,020 切成 train 与 val-seen。三层结构可以分开记忆：场景级切分决定「环境是否见过」，指令级切分决定「任务是否新」，目标可见性决定「能否本地评分」。

split场景数指令数路径数场景来源目标可见本地评分协议角色
train61（池内）14,0254,675训练池是是训练与调参
val-seen61（池内）1,020340训练池，指令级新切分是是环境记忆上界、快照选择
val-unseen112,349783独立场景组是是本地泛化主指标
test184,1731,391独立场景组否否，服务器评分榜单对比

密度实算（Python，路径数 = 指令数 ÷ 3）：train 每场景约 229.9 条指令、76.6 条路径；val-unseen 约 213.5 与 71.2；test 约 231.8 与 77.3。三个数字同量级，说明两个未见 split 与训练场景的体量相当，跨 split 比较不会因场景规模失衡而系统性失真。val-seen 的密度单列时只有 16.7 条指令每场景，因为它与 train 共享同一批场景，只是指令级的新切分；把训练池合起来算，每场景 246.6 条指令。看这张表时最常被忽略的一列是「目标可见」：val-seen 与 val-unseen 的目标都公开，本地可评分；test 的目标隐藏，唯一合法路径是提交轨迹由服务器评分（Anderson 等，2018，4.4 与 5.2 节）。

2. 两个验证集的分工：从数字看它们分别约束什么

论文表 1 给出同一模型的四组数字，student-forcing 口径下：val-seen SR 38.6%、NE 6.01 m、OSR 52.9%；val-unseen SR 21.8%、NE 7.81 m、OSR 28.4%。teacher-forcing 口径下：val-seen 27.1%、val-unseen 19.6%。随机基线：val-seen 15.9%、val-unseen 16.3%。test 上 student-forcing 为 20.4%，随机 13.2%，人类 86.4%（NE 1.61 m，覆盖 test 三分之一的 1,390 条指令）。

两组对照给出本讲的核心判断：seen-unseen 落差的主要来源是「模型可利用的、随场景变化的证据」在 unseen 场景失效；两个场景集合的绝对难度差贡献很小。随机基线的数字近似持平（16.3% 相对 15.9%，相差 0.4 个百分点），teacher-forcing 的落差（27.1% → 19.6%）明显小于 student-forcing（38.6% → 21.8%），说明落差幅度与模型对训练场景的利用深度相关。R2R 论文自身的解释是「学到的视觉接地可能相当依赖训练场景」，并给出训练曲线佐证：unseen 性能较早进入平台期，而 seen 性能随训练继续上升（Anderson 等，2018，图 7）。这条曲线是识别过拟合分量的关键证据，比单点数字更有说服力。

3. 训练与选择口径：数字背后的三件声明

任何 val-unseen 数字都由三件声明共同定义，缺一件就失去可比性。

  • 训练数据组成。R2R 论文在实现细节中说明：test 提交的模型在全部训练与验证数据上重训（Anderson 等，2018，5.2 节）。因此榜单数字与「只用 train 训练」的本地数字不是同一口径，后者训练数据少约 3,369 条指令（1,020 + 2,349）。跨论文比较时必须先对齐这一项。
  • 快照选择规则。常见做法有两类：按 val-seen 选、按 val-unseen 选。两种都合法，但若按 val-unseen 选快照，再把同一 val-unseen 的分数当作无偏报告值，就引入了选择偏差：从 K 个快照里挑最大值，期望上会抬高报告值。独立噪声假设下的抬升幅度约为 SE × E[max ZK]：val-unseen 在 21.8% 附近的标准误约 1.0%，K = 10 时抬升约 1.5 个百分点，K = 20 时约 1.9 个百分点（正态极值蒙特卡洛）；快照间高度相关时该效应减弱，但不能忽略。更稳妥的协议是在 val-seen 或固定训练预算上做选择，把 val-unseen 保留为一次性报告。
  • 解码与停止规则。贪心解码、beam search、集成、oracle 停止会分别抬升不同指标。第 007 讲已讨论 beam 对数字的影响；本讲补充协议视角：同一篇论文内部要固定解码口径，跨论文引用时要写明对方使用的规则。
选择协议：把 val-unseen 当报告集，把选择权交给别的信号

推荐流程：用 train 训练，用 val-seen 做早停与超参选择，用固定训练预算或训练损失曲线确定快照，最后在 val-unseen 上报告一次。若必须用 val-unseen 选择（例如没有合适的 dev 信号），则在论文里明确声明「在 val-unseen 上选择后报告同集合分数」，并附多快照的分数分布，让读者看到选择宽度。

4. 落差的归因分解：三分量账目

把「unseen 比 seen 差」拆成可检验的三部分，是设计泛化实验的基本功。第一分量是任务难度分量：两个场景集合的固有难度差。随机基线适合做它的上界探针，本例中约为 0。第二分量是模型过拟合分量：模型对训练场景特有的视觉证据与路径结构记忆过深，迁移时失效。证据形态是 seen 与 unseen 曲线的分离、teacher/student 落差差异、以及第 010 讲将展示的视觉消融实验。第三分量是选择与噪声分量：快照选择的乐观偏差、验证集规模有限带来的标准误、以及早期的过拟合判读。后文第 5 小节给出它的量级。

负面清单同样重要，下面四种误读在文献与评审意见中反复出现：把 val-seen 高分当作泛化证据；把落差整体归因于「语言理解不足」（OSR 落差与 NE 趋势说明问题更多在视觉接地与场景记忆）；把 test 数字当作 val-unseen 的同分布外推（11 个场景与 18 个场景是两个独立集合，test 略难，20.4% 对 21.8%）；以及拿训练数据组成不同的两个数字并排比较（见上一小节第一件声明）。此外需要留一个边界说明：val-unseen 本身也是被大量论文用于模型选择的「开发集」，它的历史榜单数字整体带有一点选择效应；把它当完全干净的泛化测量会高估其可靠性。

5. 噪声底：多少差距值得主张

验证集规模有限，SR 是二项比例，其标准误约为 SE = √(p(1−p)/n)，在 p = 0.5 附近最大，SEmax = 0.5 / √n。按本讲各 split 的指令数实算：

评估集指令数 nSEmax95% 区间半宽两方法差的噪声界（近似）
val-seen1,0201.57%±3.07%±4.34%
val-unseen2,3491.03%±2.02%±2.86%
test4,1730.77%±1.52%±2.15%

读法：在 val-unseen 上，单个数字的 95% 区间约 ±2%，两个方法各测一次再做差的噪声界约 ±2.9%。这意味着小于 3 个百分点的差距在 95% 置信水平上通常站不住，除非有配对设计或多随机种子支撑。两个收紧手段：其一，配对比较。两个模型在同一批 episode 上评测时，逐条对比成功与否，用配对差异的标准误替代独立两样本近似，通常可缩小噪声界近一半。其二，场景级聚类抽样。同一场景内的指令与同一路径的 3 条指令高度相关，独立同分布假设被打破；按场景（或路径）整簇重采样的 bootstrap 给出更接近真实的区间。实现上把「按场景分组、整组重采样」写进评估脚本即可，见关键代码片段 2。

还有一层容易被忽视的口径：平均 NE、平均 CLS 等连续指标的标准误不能用比例公式，应对 episode 做 bootstrap；报告规范建议「均值 ± 标准误」或「均值 [CI]」，并注明重采样单元。对个位数差异的主张，至少给 3 个随机种子；种子间的波动常常大于验证集噪声本身。

6. 榜单提交口径

test 协议的目标隐藏设计决定了两件事：本地复算 test 指标不可行；迭代式调参被规则性阻断。R2R 论文写明：test 的目标位置不公开，官方提供评测服务器，智能体轨迹上传后由服务器评分（Anderson 等，2018，4.4 节）。「提高 test 分数」的唯一合法循环是：读服务器返回的汇总指标，但不接触目标，因此无法像 val 那样逐样本调参。

提交与报告时应包含的口径声明清单：数据集与版本（R2R 原始协议 / R2R-CE 等派生协议分开标注）；训练数据组成（是否含 val-seen / val-unseen）；快照选择规则；解码方式（贪心 / beam / 集成）；停止规则（是否使用 oracle 停止或进度监控）；图像特征来源与分辨率；步数上限。榜单页面与提交入口随平台迁移而变化，历史入口与格式不保证长期稳定，提交前应以当前挑战页面为准逐项核对；本讲给出的口径清单与平台无关，可直接作为方法章节的检查项。

版本敏感项单独提示：本讲全部数字出自 R2R 原始离散协议；派生协议另有口径风险，后续评测工作发现 R2R-CE / RxR-CE 的 val 集含标注错事实（arXiv:2403.10700），其影响范围与处置在第 048、056 讲展开。引用任何评测数字之前，先确认协议族、split 与步数上限三要素，再确认是否触及已知的数据讹误。

关键代码与解读

三段代码对应协议层的三件日常工作：划分完整性校验、场景级聚类 bootstrap、提交文件审计。

片段 1：划分完整性校验

import json

EXPECT = {"train": (61, 14025), "val_seen": (61, 1020),
          "val_unseen": (11, 2349), "test": (18, 4173)}

def audit_split(root):
    """核对场景集合与指令数：场景隔离是泛化声明的前提。"""
    scenes, counts = {}, {}
    for split, (n_scene, n_instr) in EXPECT.items():
        data = json.load(open(f"{root}/R2R_{split}.json", encoding="utf-8"))
        scenes[split] = {ep["scan"] for ep in data}
        counts[split] = sum(len(ep["instructions"]) for ep in data)
        assert len(scenes[split]) == n_scene, (split, len(scenes[split]))
        assert counts[split] == n_instr, (split, counts[split])
    # val_unseen 与 test 必须与训练池完全隔离
    pool = scenes["train"] | scenes["val_seen"]
    assert not (pool & scenes["val_unseen"]), "val_unseen 场景泄漏"
    assert not (pool & scenes["test"]), "test 场景泄漏"
    assert not (scenes["val_unseen"] & scenes["test"]), "两个未见集必须互斥"
    # val_seen 与 train 共享场景组，但路径不得重合
    assert scenes["train"] == scenes["val_seen"]
    return scenes, counts

解读：（1）EXPECT 常量把论文口径写死成断言，任何版本漂移（例如换成 HM3D 数据）都会在加载阶段暴露，避免后续实验在错误划分上白跑。（2）场景隔离检查分三层：训练池对两个未见集、两个未见集彼此、以及 val-seen 与 train 的场景组相同。第三层容易被误删，它正是「val-seen 不属于泛化测量」的结构依据。（3）路径级去重（scan + path_id 三元组，见第 004 讲）应作为独立断言补充，本片段只覆盖场景与数量两层。

片段 2：场景级聚类 bootstrap 置信区间

import numpy as np

def cluster_bootstrap(success_by_scene, n_boot=2000, seed=0):
    """按场景整簇重采样，估计 SR 的 95% 置信区间。

    success_by_scene: {scan: 成功布尔值列表}，一条指令一个记录。
    同一场景内的指令相关，独立重采样会低估区间宽度。
    """
    rng = np.random.default_rng(seed)
    scans = list(success_by_scene)
    means = []
    for _ in range(n_boot):
        pick = rng.choice(len(scans), size=len(scans), replace=True)
        vals = []
        for i in pick:
            vals.extend(success_by_scene[scans[i]])
        means.append(float(np.mean(vals)))
    lo, hi = np.percentile(means, [2.5, 97.5])
    return lo, hi

def binomial_se(p, n):
    """独立同分布假设下的比例标准误，用于对照聚类区间的宽度。"""
    return (p * (1 - p) / n) ** 0.5

解读：（1）重采样单元是场景，整簇进整簇出，保留了场景内的指令相关结构；用指令级重采样会把区间画窄，导致显著性主张过度。（2）同一个 rng 顺序采样，使两次运行的区间可复现；seed 暴露为参数便于报告。（3）binomial_se 保留为对照量，两者并列展示能直观展示聚类修正的幅度：场景数越少、簇内相关越强，聚类区间相对比例公式越宽。（4）若要做两模型配对比较，对同一场景簇同时取两个模型的成功记录，在簇内算配对差，再走同一套 bootstrap，即可得到配对差异的区间。

片段 3：提交文件审计

def audit_submission(preds, eval_instr_ids, valid_actions, max_steps):
    """提交前检查：instr_id 覆盖完整、路径合法、步数不超限。

    preds: 列表，每项形如 {"instr_id": str, "path": [动作, 动作]}。
    max_steps: 按当前 benchmark 协议传入的步数上限。
    """
    got = {p["instr_id"] for p in preds}
    assert got == set(eval_instr_ids), "提交条目与评测集不一致"
    assert len(preds) == len(got), "存在重复 instr_id"
    stats = {"max_len": 0, "bad_action": 0, "over_limit": 0}
    for p in preds:
        acts = p["path"]
        stats["max_len"] = max(stats["max_len"], len(acts))
        if any(a not in valid_actions for a in acts):
            stats["bad_action"] += 1
        if len(acts) > max_steps:
            stats["over_limit"] += 1
    return stats

解读：（1）第一条断言要求两个集合完全相等，仅做包含检查不够：漏提交与多提交都会让服务器把缺失条目按 0 分处理或直接拒收。（2）重复 instr_id 会被后写覆盖，造成静默丢分，单独断言。（3）动作合法性依赖协议版本，valid_actions 由调用方按当前 benchmark 传入；离散协议的动作集合见第 005 讲。（4）max_steps 与 benchmark 版本绑定，由调用方传入；正式提交前以挑战页面公布的步数上限为准。

常见误区

  • 把 val-seen 数字当泛化证据。症状：方法在 val-seen 上大幅领先，正文却写「泛化能力更强」。根因：val-seen 与训练共享 61 个场景，高分包含环境记忆的贡献。修复：主结论只引用 val-unseen；val-seen 用于诊断与选择，并标注场景重叠。
  • 在 val-unseen 上反复调参后按原始分数报告。症状：报告值比同配置的多快照均值高出一个可观的量。根因：从 K 个快照中取最大值引入乐观偏差（独立噪声下约为 1.5 到 2 个百分点量级）。修复：选择交给 val-seen 或固定预算；若无法避免，附快照分数分布并声明选择协议。
  • 训练数据组成不同的数字并排比较。症状：自己的 val-unseen 比论文低，后来发现论文使用了全部验证数据重训。根因：榜单口径与本地口径的数据量相差 3,369 条指令。修复：在实验记录表与论文表格中固定声明「训练包含哪些 split」；对齐后再比较。
  • 用指令级独立假设宣称显著性。症状：两个方法差 1.5 个百分点就被判为显著。根因：同一路径的 3 条指令与同场景指令相关，有效样本量小于 2,349。修复：场景级聚类 bootstrap；主张差距前先给区间与种子数。
  • 把 test 数字当作 val-unseen 的直接外推。症状：用 val-unseen 的调参结论预测 test 分数，误差被归因于「服务器不公平」。根因：两个集合场景数不同（11 与 18）、难度不同、且 test 目标不可见。修复：test 只做一次性提交；报告时把二者分开陈述，不做同分布外推。

    路径数 4,675 / 340 / 783 / 1,391；密度 229.9 / 16.7 / 213.5 / 231.8。val-seen 与 train 共享 61 个场景，是在同一场景池内按指令切出的子集，因此单列密度低；合池后每场景 246.6 条。
  2. 用 student-forcing 的 SR 38.6 / 21.8 与随机基线的 15.9 / 16.3，计算两者的相对落差并写一段解读：落差中哪些部分不能由「场景难度不同」解释？★
    提示
    模型落差 (38.6−21.8)/38.6 ≈ 43.5%，随机基线为 −2.5%（unseen 略高）。随机基线无法利用语言与视觉，说明两个场景集合的固有难度接近；落差的绝大部分与模型可利用的场景相关证据失效有关。
  3. 某方法在 val-unseen（2,349 条指令）报告 SR 34.0%，另一方法 36.0%。用 p ≈ 0.35 的二项标准误估算两方法差的噪声界，判断 2 个百分点差距是否值得主张；再说明配对设计与场景级 bootstrap 会如何改变结论。★★
    提示
    单方法 SE ≈ 0.98%，独立两样本差的 95% 界约 ±2.7%；2 个百分点落在界内，不能单独主张。配对比较用同一批 episode 的逐条差异，方差通常明显更小；聚类 bootstrap 用场景作重采样单元，区间比指令级独立假设更宽，两者从不同方向修正朴素估计。
  4. 设计一套「不污染 val-unseen」的模型选择协议：说明选择集、选择准则、快照候选数、最终报告方式，并给出至少两个能够发现「选择偏差残留」的检查信号。★★★
    提示
    选择集可用 val-seen 或从训练池再切一个 dev 子集（保持场景共享、指令隔离）；快照候选可以多留，但选择准则只读 dev 分数；最终在 val-unseen 只评一次。检查信号：val-seen 选择曲线与 val-unseen 的分数散布是否同步；多随机种子下最优快照的波动幅度是否与验证集噪声同阶。
  5. 写一份提交前审计清单（不少于 8 项），覆盖数据、模型、解码、文件四个层面；每项给出通过判据与不通过时的处置，并说明为什么 test 上的任何本地指标计算都应当从清单中删除。★★★
    提示
    数据层：split 数量、场景隔离、目标字段不出现；模型层：训练数据组成声明、快照规则、参数量记录；解码层：动作合法性、步数上限、停止语义；文件层：instr_id 集合相等、无重复、格式与当前页面一致。test 目标隐藏，本地无法定义成功判定，任何本地计算都只会产生无意义数字并诱导按该数字调参。

小结

  • 三层划分：场景级（61 池 / 11 val-unseen / 18 test，互不重叠）、指令级（池内 14,025 / 1,020）、目标可见性（val 本地评分、test 服务器评分）。密度 229.9 / 16.7 / 213.5 / 231.8（val-seen 与 train 共享场景，16.7 属池内切分）；train、val-unseen 与 test 的场景体量同量级。
  • val-seen 衡量「见过的建筑里执行新指令」，含环境记忆贡献；val-unseen 是本地泛化主指标。student-forcing 的 SR 38.6 → 21.8（相对 −43.5%），OSR 52.9 → 28.4（−46.3%），NE 6.01 → 7.81 m（+30.0%）；随机基线近似持平（15.9 / 16.3）。
  • 数字由三件声明定义：训练数据组成（榜单用 train + val-seen + val-unseen 重训）、快照选择规则（val-unseen 选择会带来约 1.5–2 个百分点的乐观偏差量级）、解码与停止规则。
  • 噪声底：val-unseen 单数字 95% 区间约 ±2%，两方法差约 ±2.9%；场景级聚类 bootstrap 与配对比较是两项标准修正；个位数差距需要多种子与区间支撑。
  • test 目标隐藏、轨迹上传、服务器评分；提交与报告需声明协议版本、训练组成、选择规则、解码与步数上限；平台入口会迁移，提交前以当前挑战页面核对。
  • 下一讲用本讲的协议做第一次偏差诊断：视觉消融后 unseen 性能不降甚至更好（Hu 等，2019），并讨论对象表征与混合专家如何把视觉信息重新变成增益（第 010 讲）。
