第三篇 · 策略与世界模型深化

第 060 章：世界模型的任务泛化

从单任务世界模型到任务族世界模型：本章讲清任务嵌入的推断与条件化、元学习中"学会快速适应"的初始化机制，以及内插与外推分离的留出任务评估。

  • 主题：世界模型 / 元学习（Meta-Learning）
  • 关键公式：L = −Eq(z|c)[log p(s′ | s, a, z)] + β·KL(q(z | c) ‖ p(z))
  • 预计学时：60 分钟
  • 前置章节：第 059 章 VLA策略的指令跟随精度

学习目标

本章作为第三篇的收束，处理世界模型的跨任务能力与快速适应机制。

  • 理解任务条件世界模型 p(s′ | s, a, ztask) 的结构，掌握任务嵌入的三类来源：语言描述、目标状态与上下文推断。
  • 掌握变分任务编码器：从少量 episode 的上下文推断任务分布，并用 KL 项约束先验。
  • 理解元学习的初始化机制（MAML 与 Reptile 的核心思想），能描述内层适应与外层元更新的角色分工。
  • 能构建内插与外推分离的留出任务套件，定义适应速度与零样本精度两项指标。
  • 能诊断任务嵌入塌缩与任务标签泄漏两类失效，并给出修复路径。

背景与动机

训练分布内的世界模型在少数任务上预测精确，任务族一旦扩展（新负载、新摩擦条件、新目标类型），动力学参数整体偏移，单任务模型需要重新收集数据。任务泛化的目标是把"任务"从权重里抽出来变成输入条件：同一套参数建模任务族的共享动力学，个体差异由任务嵌入承载，新任务先以零样本或少量适应步数接入。

与第 047 章的策略零样本评估相比，本章处理的问题对象是世界模型，泛化维度从语言组合扩展到动力学参数；与第 055 章的目标条件相比，那里的条件变量是单个目标状态，本章的任务嵌入描述整段任务的动力学语境。两类条件的层级不同：目标决定"去哪"，任务嵌入决定"世界如何运转"，世界模型同时接收两者。本章按条件结构、元学习、评估与诊断展开，并为第四篇的系统机制做衔接。

核心原理

依次讨论任务嵌入、上下文推断、元学习与评估设计。

1. 任务条件结构与嵌入来源

条件化世界模型把任务信息注入动力学网络，常用方式是特征调制（FiLM）与条件拼接。任务嵌入的三类来源各有适用场景：

来源获取方式优点局限
语言描述任务文本经语言编码器接口自然，与策略条件共享动力学相关的隐参数难以用文本完整表达
目标状态目标观测的潜编码与第 055 章的接口统一只覆盖目标层面，不携带动力学信息
上下文推断从少量 episode 推断隐变量直接编码动力学参数，适应能力最强需要上下文数据，推断结果需要正则

三者可以联合：语言与目标提供先验，上下文推断对先验做残差修正，推理期先用先验、有交互数据后逐步切换到修正值。

2. 变分任务编码器

上下文 c 为若干条短 episode（观测、动作、后继观测）。任务编码器输出后验分布 q(z | c)，训练目标为：

L = −Eq(z|c)[ log p(s′ | s, a, z) ] + β · KL( q(z | c) ‖ p(z) ) p(z) 为标准正态先验；β 平衡重构与正则，过大会使嵌入塌缩回先验

上下文用置换不变的聚合（均值或注意力池化）汇总为定长向量。训练时上下文从同任务 episode 池随机采样，数量在 1 至 8 条之间随机，让编码器适应不同长度；推理时新任务仅需少量交互片段即可推断嵌入。嵌入维度取 32 至 64 即可承载常见的动力学差异，维度过高时后验难以被数据充分约束，KL 项提前主导。

3. 元学习：快速适应的初始化

上下文推断解决"看到数据后识别任务"，元学习解决"少量梯度步内适应到新任务"。MAML 的目标是寻找对所有任务适应都快的初始化：内层用支持集做一步或几步梯度更新，外层在查询集上评估更新后的参数并回传梯度。Reptile 用更简单的近似：内层多步适应得到 θ′，外层把参数朝 θ′ 的方向移动：

θ ← θ + η · (θ′k − θ)，θ′k 为第 k 个任务上适应后的参数 Reptile 不需要二阶梯度，计算量约为 MAML 的一半，收敛点略有差异

元学习适合的策略是"共享动力学为主、个体参数为辅"：把大部分参数共享并用上下文推断承载任务差异，仅对解码器等少数模块做梯度适应。全参数适应在机器人数百步量级的交互预算内难以收敛，混合结构更稳妥。

4. 评估：内插与外推分离

留出任务套件按两个轴划分：内插任务在训练因子的组合空间内部（两种已见摩擦系数的中间值），外推任务在组合空间之外（超出训练范围的负载）。两类任务的难度与失败含义不同：内插不达标说明表示或条件化不足，外推不达标可能来自动力学机制的根本差异，需要单独归因。指标包含零样本预测精度与适应速度（达到目标精度所需的交互步数或梯度步数），后者是元学习机制的核心验收项。

数值算例：摩擦系数训练覆盖 0.3 至 1.0 时，外推段按量程的 20% 预留：0.2 × (1.0 − 0.3) = 0.14，即外推任务取 1.14 以上；0.3 与 1.0 两个端点单独留出做边界检查，内插任务取区间内部值，与外推组分开统计。

套件构建的三条纪律：任务现象学标签与输入特征分离（禁止把任务编号或动力学参数作为模型输入）；评估任务与训练任务不共享 episode 文件；适应实验固定上下文长度与随机种子。

实现思路与设计

设计覆盖嵌入结构、元训练循环与评估套件三部分，第四篇的异步更新机制在此已可前置预留接口。

训练流程

  1. 任务族数据按任务分组，组内划分为上下文池与查询集。
  2. 每个训练步采样整任务：上下文推断 z，查询集上计算预测损失与 KL。
  3. 每若干步执行一轮元更新：选定任务做 k 步内层适应，Reptile 式回写共享参数。
  4. 评估套件按内插与外推分组，报告零样本精度与适应曲线。

超参数表

参数默认值作用取值依据

与第 047 章的差异点

第 047 章评估策略在语言组合上的零样本能力，基准划分的单位是任务文本；本章评估世界模型在动力学参数上的泛化与适应，划分单位是任务过程，指标从成功率扩展为预测精度与适应速度。语言条件在本章降级为任务嵌入的一个来源，动力学信息由上下文推断补充，这是两个层次的泛化在接口上的交汇。

关键代码与解读

以下片段以公开实现的通用设计为参照，接口命名随版本演进。

片段覆盖变分任务编码、内插外推划分与快速适应更新。数值与上表一致。

片段 1：上下文编码与任务条件化

import torch
import torch.nn as nn

class TaskEncoder(nn.Module):
    """从上下文 episode 推断任务后验，输出均值与对数标准差。"""
    def __init__(self, feat_dim=128, task_dim=48):
        super().__init__()
        self.gru = nn.GRU(feat_dim, 128, batch_first=True)   # 上下文 episode 内按时间读
        self.head = nn.Linear(128, 2 * task_dim)             # 输出后验参数

    def forward(self, context_feats):
        # context_feats: (B, C, T, D)，C 为 episode 条数；置换不变的聚合用均值
        B, C = context_feats.shape[:2]
        flat = context_feats.reshape(B * C, *context_feats.shape[2:])
        _, h = self.gru(flat)                                # 每条 episode 的摘要
        pooled = h.squeeze(0).reshape(B, C, -1).mean(dim=1)  # 对 episode 取均值：顺序无关
        mu, log_std = self.head(pooled).chunk(2, dim=-1)
        return mu, log_std

# 条件注入：任务嵌入经 FiLM 调制动力学网络的特征
# gamma, beta = film(task_embed); h = h * (1 + gamma) + beta

解读：（1）episode 内用循环网络按时间读取，episode 之间用均值池化保证置换不变；上下文条数从 1 到 8 变化时同一套参数可用。（2）输出均值与对数标准差支持重参数化采样，训练时采样、推理时按需采样或取均值；取均值用于稳定的零样本预测，采样用于刻画任务不确定性。（3）条件注入用 FiLM 的形式，与第 055 章目标条件的注入机制同构，两路条件可以在不同深度分别注入，互不干扰。

片段 2：内插与外推任务的划分

def split_task_suite(tasks, factor_name="friction", inner_ratio=0.6):
    """按动力学因子范围划分内插与外推任务。
    设计意图：内插测表示与条件化，外推测机制迁移，两类失败归因不同。"""
    values = sorted(t[factor_name] for t in tasks)
    lo, hi = values[0], values[-1]
    inner = [t for t in tasks if lo < t[factor_name] < hi]   # 内插：范围内部
    edge = [t for t in tasks if t[factor_name] in (lo, hi)]  # 端点任务留出验证边界
    # 外推：因子取值超出训练上限 20% 量程以上，先留出缓冲再测机制迁移
    margin = 0.2 * (hi - lo)
    outer = [t for t in tasks if t[factor_name] > hi + margin]
    assert not set(map(id, inner)) & set(map(id, outer)), "内外插任务不得重叠"
    return inner, edge, outer

解读：（1）内插任务落在训练因子范围的内部，评估表示空间的覆盖质量；外推任务超出范围，评估机制层面的迁移能力，两组的失败含义不同必须分开统计。（2）端点任务单独留出，防止模型对范围边界过拟合，边界样本同时用于检查条件化的连续性与外推起点。（3）断言检查两组任务不重叠；实际数据中因子取值连续时，改用区间划分，避免离散标签带来的边界争议。

片段 3：Reptile 式快速适应

def reptile_update(model, tasks, inner_steps=5, inner_lr=1e-3, meta_lr=1e-4):
    """元更新：各任务内层适应后，把共享参数朝各自适应解的方向拉近。
    设计意图：免二阶梯度，成本约为 MAML 的一半，适合交互预算紧张的场景。"""
    start_params = [p.detach().clone() for p in model.adapt_parameters()]
    deltas = []
    for task in tasks:
        adapted = model.clone()                       # 任务副本，内层只改副本
        inner_opt = torch.optim.SGD(adapted.adapt_parameters(), lr=inner_lr)
        for _ in range(inner_steps):
            loss = adapted.task_loss(task.support_batch)   # 支持集上的预测损失
            inner_opt.zero_grad()
            loss.backward()
            inner_opt.step()
        # 记录与初始化的差：该方向包含"如何适应"的信息
        deltas.append([p.detach() - s for p, s in
                       zip(adapted.adapt_parameters(), start_params)])
    # 外层元更新：沿"适应解减初始化"的平均方向拉动共享参数
    with torch.no_grad():
        for i, (p, s) in enumerate(zip(model.adapt_parameters(), start_params)):
            mean_delta = sum(d[i] for d in deltas) / len(deltas)
            p.copy_(s + meta_lr * mean_delta)
    return model

解读：（1）内层在任务副本上执行支持集适应，副本机制保证各任务互不干扰；副本克隆只覆盖适配参数，共享主干引用同一份权重。（2）外层沿"适应解减初始化"的平均方向移动参数，这正是 Reptile 的更新形式；不需要对内层过程求导，内存与算力都低于 MAML。（3）写回按参数逐个执行 p ← p + meta_lr · mean_delta，内层步数与部署预算一致，元学习得到的初始化直接对接现场适应流程。

常见坑

  • 任务嵌入塌缩：KL 权重过大或重构信号过弱，嵌入退化为常数。修复：下调 β，检查嵌入的方差与任务间可分离度。
  • 任务标签泄漏：任务编号或动力学参数混入模型输入，指标虚高。修复：输入特征审计，评估时用现象学划分，禁止任何任务标识进入网络。
  • 外推任务共享训练动力学：外推套件实际仍是内插分布，泛化结论不成立。修复：外推任务的因子取值严格超出训练范围，构建后复核分布重叠。
  • 上下文过短或固定长度：模型只适应单一上下文规模，部署时推断失准。修复：训练时上下文长度随机化 1 至 8 条。
  • 元学习内层步数超出预算：适应曲线好看但现场无法执行。修复：内层步数与部署交互预算对齐，把"快速"作为硬约束进入实验设计。

练习与思考

  1. 推导：写出变分任务编码器目标中 KL 项的展开形式，说明 β 增大时嵌入为何趋向先验常数。★★
    提示
    KL(q||p) 对高斯族展开后，均值偏离先验与方差偏离单位值都被惩罚；β 足够大时最优解是后验等于先验，嵌入不再携带任务信息。
  2. 把内层适应步数从 5 改到 1，预测三件事的变化：现场适应后的预测精度、元训练收敛速度、元更新的梯度噪声，并说明验证方式。★★
    提示
    单步适应精度下降但速度最快，元训练更快收敛、噪声更大。验证：绘制适应步数与精度的曲线，选择满足部署预算的拐点。
  3. 设计评估协议：为"负载质量变化"任务族构造内插、边界与外推三组任务，说明因子范围、样本量与指标口径。★★★
    提示
    训练覆盖 0.5 至 2.0 千克的中间段，边界样本取 0.5 与 2.0，外推取 2.5 至 4.0。指标：零样本预测误差与 5 步适应后的误差，分组报告。
  4. 讨论：为什么元学习更适合"共享动力学加少量个体参数"的混合结构？结合交互预算与二阶梯度成本说明。★★
    提示
    全参数适应的样本与算力需求超出机器人交互预算；混合结构把任务差异压缩到小参数子集，内层适应快且稳定，元梯度的方差也更低。

小结

  • 任务条件世界模型把任务差异抽入嵌入，语言、目标与上下文推断三类来源可按先验加修正的层级组合。
  • 变分任务编码器从少量 episode 推断后验，KL 权重控制嵌入的信息量，过大会塌缩回先验。
  • 元学习寻找快速适应的初始化，Reptile 用"适应解减初始化"的平均方向更新，免二阶梯度。
  • 留出任务套件分离内插与外推，指标包含零样本精度与适应速度，适应步数与部署预算对齐。
  • 任务嵌入塌缩与标签泄漏是两类高频失效，分别用 KL 调节与输入审计修复。
