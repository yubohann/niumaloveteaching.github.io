第 089 章：VLA策略的长期规划

长程任务的三个困难（误差累积、信用分配、稀疏反馈）如何用子目标分解、滚动视野与价值终端代价化解：规划器、价值头与重规划触发的分工设计。

  • 主题：VLA 策略（Vision-Language-Action, VLA）/ 长期规划（long-horizon planning）
  • 关键公式：滚动视野目标与 n 步时序差分价值学习
  • 预计学时：55 分钟
  • 前置章节：第 088 章

学习目标

  • 理解长程任务的三个结构性困难：想象误差累积、动作与结果的信用分配、稀疏反馈下的学习信号缺失。
  • 掌握滚动视野规划的目标形式，理解价值终端代价为什么能缓解短视而模型误差限制了视野长度。
  • 掌握价值头的 n 步时序差分训练，理解价值估计偏差沿状态分布外扩大的机制。
  • 会设计子目标粒度、束搜索宽度与重规划触发条件的组合，并按计算预算核算规划开销。
  • 能诊断不可达子目标、价值外推偏差与规划执行错位三类长期规划故障。

背景与动机

任务长度一旦超过单次动作块的覆盖范围，规划就从"预测一步"变成"组织一串决策"，困难随之出现。世界模型的多步想象误差随步长指数放大（第 084 章给出递归界），直接用长视野 rollout 评分不可行；成功信号通常只出现在任务末端，中间动作的贡献难以分配；而模拟环境与真实场景中，稀疏反馈让梯度信号长期为零。

第 014 章与第 075 章分别在动作空间与隐空间做过短程规划，接受视野较短的限制。本章把规划器组织为两层：高层用子目标排序解决"先做什么"，低层用动作块策略执行解决"怎么做"；配合价值终端代价把视野外的回报压缩成一个标量估计。这一结构同时与第 095 章的故障检测、第 096 章的层次结构衔接。

核心原理

长期规划的可行结构是：子目标空间降维、滚动视野限长、价值函数补尾、事件触发重规划。

1. 滚动视野与价值终端代价

单次规划在潜空间展开 H 步，目标为累计预测回报加终端价值：

a*1:H = arg maxa1:H Σk=0H−1 γk r̂( zk, ak ) + γH V̂( zH ) r̂ 为世界模型预测的奖励；V̂ 为价值头，估计 zH 之后的期望回报

两项分工明确：短视野内的细节由模型预测承担，视野外的远景由价值头概括。价值项把无限期决策压缩为有限期搜索，是长期规划成立的前提。视野长度 H 的取值受两侧约束：太短则规划短视，把价值头没有学会区分的状态当成等价；太长则模型预测误差主导，评分数值不可信。经验取值 H = 3–5（以子目标为步进单位），并用"价值排序与实际成功率的秩相关"验证视野是否够长。

2. 价值头的时序差分学习

价值头在世界模型潜状态上估计期望折扣回报，用 n 步时序差分（temporal difference, TD）目标训练：

Vtarget = Σk=0n−1 γk rk + γn V̂( zn )，LV = ( V̂(z0) − sg[Vtarget] )2 sg 为停止梯度；n 取 3–5，与规划视野匹配

目标侧的停止梯度防止自举发散。价值估计的偏差随状态偏离训练分布而增大：规划器会主动搜索价值高的区域，而这些区域恰是价值头训练样本稀疏的地方，形成外推偏差。缓解手段有三：想象 rollout 生成的数据回灌训练价值头（Dyna 式循环，第 091 章展开）；集成多个价值头取悲观下界；把价值头的训练状态覆盖扩展到规划器实际访问的分布。

3. 子目标粒度与重规划触发

子目标是规划与执行的接口，粒度选择是核心权衡：过细（"把夹爪移动到坐标 (x, y, z)"）退化为动作序列预测，失去抽象优势，且数量爆炸；过粗（"完成任务"）低层策略无法执行，也无法提供进度信号。合适的粒度是"低层策略在 8–16 个动作块内可执行、且末端状态可验证"，例如"抓住杯子"、"移动到托盘上方"、"放下并释放"。子目标可由语言模板生成器提议，或从演示数据中按状态变化分段学习。

重规划在两类事件后触发：计划走完（正常推进）与进度停滞（异常）。进度用价值增量或进度头输出衡量，窗口内增量低于阈值即判定停滞，提前重规划。触发条件要平滑，避免单帧噪声引发频繁重规划；工程上用长度为 8–12 步的滑动窗口均值对照阈值。

4. 束搜索与计算预算

子目标序列的搜索用束搜索（beam search）：每层保留打分最高的 B 条候选，展开下一层。开销约为 B × 候选数 × 深度 × 单步推理成本，B = 4、候选 8、深度 4 时单次规划约 128 次世界模型前向。以 5 ms/次估计，单次规划约 0.6 s 量级，因此高层规划不能进入控制环，按事件触发、异步执行。规划结果只取第一个子目标交给低层执行，执行期间后台继续规划，实现"边执行边规划"。

实现思路与设计

系统分三层节拍运行：低层动作块策略 10–20 Hz，高层规划器事件触发（约 1 Hz），价值头与规划器同步更新。

  1. 高层提议：子目标生成器按任务模板产出候选集合（8 个左右），带可达性过滤（低层策略近期成功率低于阈值的子目标先剔除）。
  2. 世界模型评分：对候选做深度 4 的束搜索，奖励取进度增量，终端加价值项，输出最优序列。
  3. 低层执行：执行序列首个子目标，动作块策略按第 086 章的调度运行；子目标完成判定由末端状态验证器给出。
  4. 重规划触发：正常推进到序列耗尽，或进度窗口均值低于阈值，或故障检测器（第 095 章）报警。
  5. 与第 014、075 章的差异：规划单位从单步动作升级为子目标，新增价值终端与重规划触发；搜索与执行异步化。

设计决策：为什么规划器与低层执行要异步？

束搜索计算量高出控制环允许的延迟一到两个数量级，同步执行会让控制频率崩塌。异步结构把规划放在后台：低层按既有子目标持续推进，规划完成或触发重规划时切换子目标。切换点的选择要保持动作连续性，新子目标与当前执行状态的距离过远时先执行过渡动作，避免急停急转。

关键代码与解读

以下片段为 PyTorch 风格示意，接口命名以各开源实现的公开设计为参照，随版本演进可能变化。

片段 1：滚动视野束搜索规划器

def beam_plan(world_model, value_head, z0, candidates, depth=4, beam=4, gamma=0.99):
    """在潜空间展开子目标序列：进度奖励累积 + 终端价值补齐。"""
    beams = [(0.0, z0, [])]                       # (累计打分, 当前潜状态, 子目标序列)
    for d in range(depth):
        expand = []
        for score, z, seq in beams:
            for g in candidates:
                z_next = world_model.step_subgoal(z, g)          # 子目标级转移
                r = world_model.progress(z, z_next)              # 进度增量作为即时奖励
                expand.append((score + (gamma ** d) * r, z_next, seq + [g]))
        # 按累计打分截断到束宽：宽度换多样性，深度换远见
        beams = sorted(expand, key=lambda t: -t[0])[:beam]
    # 终端项：视野之外的回报由价值头概括，这是长期规划成立的关键
    best = max(beams, key=lambda t: t[0] + (gamma ** depth) * value_head(t[1]).item())
    return best[2][0], best[0]                    # 只返回首个可执行子目标

解读：搜索在子目标空间进行，每层展开 |候选| × 束宽个分支，深度 4、束宽 4、候选 8 时总模拟约 128 次。key=lambda t: -t[0] 用取负实现降序排序，避免定制比较函数。终端价值只对保留的束打分，计算量可控。函数只返回首个子目标：执行期间状态会变化，后续子目标需要按新状态重新评估；提前返回整条计划会造成"计划执行错位"。

片段 2：价值头的 n 步时序差分损失

def td_value_loss(value_head, latents, rewards, gamma=0.99, n=4):
    """n 步 TD：目标侧停止梯度，防止自举发散。"""
    # latents: (B, T+1, d) 潜状态序列；rewards: (B, T) 逐步奖励
    z0 = latents[:, 0]
    boot = latents[:, n]                          # 自举点
    ret = 0.0
    for k in range(n):
        ret = ret + (gamma ** k) * rewards[:, k]
    target = ret + (gamma ** n) * value_head(boot).detach()   # 停止梯度
    return F.mse_loss(value_head(z0), target)

def should_replan(progress_history, window=10, thresh=1e-3):
    """进度停滞检测：滑动窗口均值低于阈值时触发重规划。"""
    if len(progress_history) < window:
        return False
    recent = progress_history[-window:]
    return sum(recent) / window < thresh

解读：TD 目标的奖励部分精确累加，第 n 步之后用价值自举；detach 截断目标侧梯度，损失只更新当前状态的价值估计。n 取 4 与规划视野对齐，训练与规划对远期回报的截断位置一致，避免两种口径的估计互相矛盾。停滞检测放在策略循环中调用，进度历史包含价值增量或进度头输出；阈值量级按归一化进度的 1e-3 设置，具体数值要以正常推进时的进度均值标定，一般取正常值的 10%–20%。

片段 3：重规划调度与过渡动作

def maybe_replan(state, planner, executor, fault_flag, progress_hist):
    """重规划决策：正常耗尽、停滞、故障三种触发共用入口。"""
    need = executor.finished() or should_replan(progress_hist) or fault_flag
    if not need:
        return None
    seq = planner(state)                          # 异步规划结果（可为缓存的最新计划）
    # 过渡检查：新子目标与当前状态差距过大时先插入回正动作，防止损伤
    gap = planner.distance(seq[0], state)
    if gap > planner.gap_limit:
        return planner.transition_action(state)
    return seq[0]

解读：三类触发收敛到同一入口，日志中区分触发原因便于统计各类事件的频率。过渡动作解决的是规划器视角与执行器视角的错位：规划在潜状态空间评估可达性，执行器关心关节空间的可执行性，两者不一致时直接切换子目标会产生大幅动作跳变。gap_limit 可按末端位姿差与关节速度上限推导，超过时插入一个过渡动作块作为缓冲，代价是轻微的效率损失，收益是执行安全与动作连续性。

常见坑

  • 子目标不可达：规划器提议的子目标超出低层策略能力，执行反复失败。症状是同一子目标被执行多轮仍未完成。修复：可达性过滤（近期成功率低于阈值先剔除）、失败后提高该子目标的执行代价。
  • 价值外推偏差：规划器偏好价值头未充分训练的区域，实际回报远低于估计。症状是规划打分与真实成功率的秩相关偏低。修复：想象数据回灌价值头、集成悲观下界、限制候选集合到训练覆盖的分布内。
  • 视野选择失当：视野过短导致短视，过长导致模型误差主导评分。症状分别是"局部最优卡死"与"规划打分与执行结果无关"。修复：按价值排序与真实回报的相关性调参，扫描 H = 2–6。
  • 计划执行错位：执行旧计划时环境已变化，子目标序列过期。症状是执行动作与当前场景明显不符。修复：执行前核对计划时间戳与状态一致性，超时或状态偏移超阈重规划。
  • 重规划抖振：停滞阈值过敏感，系统频繁中断正在完成的子目标。症状是子目标切换频率过高、任务进度不进。修复：滑动窗口平滑、增加最小执行时长约束。

练习与思考

  1. 说明价值终端项 γHV̂(zH) 在 H 增大时对规划结果的影响，给出 H→∞ 时的退化形式与不可行原因。★
    提示
    H 增大时价值项权重下降、模型误差上升；H→∞ 退化为纯模型 rollout，误差指数放大导致评分失效。
  2. 把束宽从 4 改为 1（贪心），预测规划质量与计算量的变化，并给出适用场景。★
    提示
    计算量降至四分之一，质量在候选区分度高的任务上损失小；适合子目标模板冗余度低的场景。
  3. 设计子目标粒度的对照实验：分别用动作级、子目标级、任务级三种粒度训练规划器，给出评估指标与预期结论。★★
    提示
    指标含单步规划计算量、子目标完成率、整任务成功率；动作级计算爆炸，任务级无进度信号。
  4. 推导 n 步 TD 目标的偏差与方差随 n 的变化方向，说明为什么 n 与规划视野对齐是合理选择。★★
    提示
    n 增大偏差（自举依赖）下降、方差（回报噪声）上升；对齐后训练与使用对远期信息的截断一致。
  5. 设计一套长期规划的失败恢复协议：定义失败类别（子目标超时、进度倒退、验证失败），给出每类的检测信号与恢复动作。★★★
    提示
    超时用执行时长阈值，倒退用进度增量符号，验证失败用末端状态检查；恢复动作从"重试、换候选、回退到上一子目标"分级。

小结

  • 长期规划用子目标空间降维，滚动视野限长，价值终端代价补齐视野外回报。
  • 价值头按 n 步 TD 训练，目标侧停止梯度；外推偏差用想象数据回灌与悲观集成缓解。
  • 子目标粒度以"低层 8–16 个动作块可执行、末端可验证"为准，重规划按耗尽、停滞、故障三类事件触发。
  • 束搜索的开销按束宽、候选数与深度核算，规划器与执行器异步运行，只执行首个可行子目标。
