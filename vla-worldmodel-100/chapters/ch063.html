第 063 章：世界模型的图结构表示

本章讲世界模型的图结构表示（Graph-Structured Representation）：把场景分解为对象节点与关系边，用图神经网络的消息传递做动力学预测，靠置换等值性与权重共享获得对物体数量的泛化。

  • 主题：世界模型 / 结构化场景表征
  • 关键公式：e′ij = φe(hi, hj, eij)，h′i = φh(hi, Σj e′ij)
  • 预计学时：50 分钟
  • 前置章节：第 062 章：VLA策略的贝叶斯推断

学习目标

  • 理解对象为中心的图表示（Object-Centric Graph Representation）为什么适合世界模型：把整体隐状态拆成节点与关系，交互结构显式化。
  • 掌握图神经网络（Graph Neural Network, GNN）消息传递（Message Passing）的更新式，理解边网络与节点网络的职责划分。
  • 理解置换等值性（Permutation Equivariance）的含义与来源，能推导它在对象数量泛化中的作用。
  • 能实现场景图构建、关系推理层与多步想象，掌握边特征与动作条件的接入方式。
  • 会诊断过平滑（Over-Smoothing）、图构建误差传播与对象数失配等问题，能设计对象数量泛化实验。

背景与动机

本节说明图表示针对的结构性缺陷：整体隐向量把交互结构藏在特征里。卷积或 Transformer 式编码器输出整体表征，物体之间的接触与遮挡关系需要网络隐式学习。当物体数量、组合关系超出训练分布时，这种隐式表示的外推能力有限。图结构表示把场景显式拆成对象节点与关系边，让动力学在节点与边两个层级上参数共享地计算。世界模型的预测、奖励估计与想象 rollout 都可以在图空间完成。

核心原理

1. 从像素到图：节点与边的构造

场景图的构造分两步。第一步做对象分解（Object-Centric Decomposition）：主流做法用槽注意力（Slot Attention）把视觉特征分配到固定数量的槽位，每个槽位对应一个对象；每个槽输出节点特征 hi ∈ Rd 与几何位置 pi。第二步建边：以位置为准连 k 个最近邻，得到稀疏图，边特征 eij 由相对位置与距离组成：

eij = [pj − pi, ‖pj − pi‖] 相对位置保留方向信息，距离标量给出交互强度先验；二者拼接供边网络使用

全局图的边数随对象数平方增长，而多数对象对之间没有实际交互。近邻图把复杂度压回线性，代价是长程交互需靠多层消息传递间接补齐。

2. 消息传递与置换等值性

图网络（Graph Network）的一步更新由边网络与节点网络组成：

e′ij = φe(hi, hj, eij)，h′i = φh(hi, Σj∈N(i) e′ij) φe、φh 为所有节点共享的多层感知机；N(i) 为节点 i 的邻居集合

置换等值性指：对节点做任意排列 P，输出按同一排列变换，即 f(PH) = P f(H)。该性质来自两处设计：节点与边共享参数；求和聚合与邻居顺序无关。直觉上，模型学到的是一条“交互规则”，与对象编号无关。置换等值让模型把规则迁移到未见过的对象数量上。

3. 数值算例：置换等值性的手算验证

取三个节点的一维特征 h = [1, 2, 4]，全连接图（每节点聚合除自身外的全部邻居），消息函数简化为直接传递源节点特征，聚合取求和。原始排列下各节点的聚合量为：节点 1 得 2 + 4 = 6，节点 2 得 1 + 4 = 5，节点 3 得 1 + 2 = 3，即聚合向量 [6, 5, 3]。现在对节点做排列 P，把排列后的特征序列变为 [4, 1, 2]（原节点 3、1、2 依次排开），重新计算：新序列第一个位置对应原节点 3，其邻居为原节点 1、2，聚合 1 + 2 = 3；第二个位置对应原节点 1，聚合 4 + 2 = 6；第三个位置对应原节点 2，聚合 4 + 1 = 5。排列后聚合向量为 [3, 6, 5]，恰好等于把原输出 [6, 5, 3] 按同一排列重排的结果，等值关系 f(PH) = P f(H) 在数值上成立。

把该验证推广到局部聚合结构：边网络逐边计算、每边的输入只依赖两个端点与边特征，节点聚合与邻居进入顺序无关。三处排列等变性复合后，整个更新层等值。工程含义是：训练时见过的“两个物体靠近会怎样相互作用”直接适用于推理时对象编号完全不同的场景，模型的输出只依赖对象之间的关系，不依赖编号的分配。

4. 聚合算子与替代方案的对照

聚合算子的选择影响数值行为与可训练性，常见四类方案的特性对照如下：

聚合算子置换不变性邻居数缩放行为典型问题适用条件
求和 Σj ej满足消息尺度恒定，总交互量随邻居数增加稠密区域数值偏大稀疏图加归一化层的默认组合
均值 (1/|N|) Σj ej满足尺度不随邻居数变化稀疏与稠密区域消息强度不可比，弱交互被稀释邻居数固定或近似固定的图
最大 maxj ej满足只保留最强信号丢弃交互总量信息，梯度只流向最大项强调显著接触或碰撞的场景
注意力加权 Σj αij ej满足权重归一化，尺度受控注意力塌缩到少数邻居，需要正则需要显式选择交互对象的任务

选用顺序建议：以求和加归一化层为基础配置；邻接结构在训练与推理间保持恒定且邻居数少时可用均值；接触检测类任务可把最大聚合作为补充通路；只有当任务需要显式表达“关注哪个对象”时再引入注意力聚合，并监控注意力熵。聚合算子的替换会改变消息的数值尺度，切换后需要重新校准学习率与归一化层位置。

5. 把动作条件接进图动力学

动力学需要动作条件。动作是全局量（末端位姿增量、夹爪开合），接入方式有三种：广播到每个节点、并入边特征、或先用动作嵌入调制节点特征。选择广播方式时，节点更新变为 h′i = φh(hi + aemb, Σj e′ij)，动作对全部对象施加同一扰动，对象之间的差异由交互项补偿。三种方式表达力接近：广播最简单，调制方式对细粒度操作更友好。

6. 预测目标与误差结构

图世界模型的训练目标是预测下一时刻的节点状态：Lnode = Σi ‖hit+1 − ĥit+1‖2，可附加关系一致性项，约束邻居相对向量的预测误差。多步想象时误差沿两个通道传播：节点特征内的误差逐层累积，图结构本身的误差（把不该连的边连上）在重构图时被反复注入。关系一致性项让边预测在早期训练中先对齐，减少结构误差向节点状态的回流。评估需分别报告单步节点误差与多步关系误差。

实现思路与设计

本节给出实现管线：共享视觉编码器输出特征图，槽注意力分解为 N 个对象槽，位置头解码几何位置；建图模块按位置连 k 近邻；两层图动力学层堆叠做隐空间转移；预测头输出下一时刻节点状态与任务奖励。损失由节点预测误差、关系一致性误差与奖励回归误差组成；与 VLA 的接口不变，动作块经编码器转为动作嵌入。与第 062 章的差异：本章改造世界模型的状态表征结构，二者可叠加使用。

设计决策：为什么求和不求平均

聚合算子的选择影响数值行为。均值聚合会随邻居数量变化缩放消息强度，稀疏与稠密区域的消息尺度不一致；求和聚合保持消息尺度恒定，邻居增多即总交互量增加。求和配合后续的节点网络（含归一化层），是关系推理中最常用的组合。

其余参数的取值依据与替代选项

  • 槽数 N 的上界由任务对象数上分位数决定。桌面操作场景的对象数通常在 5 到 9 之间波动，取 12 覆盖上分位数并留两个冗余槽；冗余槽的特征会在训练中收敛到接近零向量，代价是轻微的注意力分散。
  • 邻居数 k 与图的直径。k 层的消息传递可覆盖 k 跳交互半径；4 邻居配 2 层可覆盖多数桌面接触场景；若场景中存在需要跨越整张桌子的动作依赖，把 k 提到 6 而保持层数为 2 优于把层数加到 4。
  • 边特征可选的增强项。基础版用相对位置与距离；加入相对朝向（四元数差）可改善铰接物体的预测；加入接触指示位（由几何引擎或触觉传感器提供）在抓取阶段收益明显，推理时缺失则退化进特征并被网络自适应忽略。
  • 位置头的监督信号。位置头可直接回归真值位置，也可经可微渲染监督；直接回归收敛快，可微渲染与视觉目标一致但训练不稳定，建议以直接回归起步、后期加入渲染项微调。
  • 节点特征维度的对齐。取 128 与世界模型其余隐层对齐，便于读取下游预测头；若下游需要更高容量，优先加宽边网络与节点网络的隐藏层，节点特征维度保持恒定。

关键代码与解读

以下片段以关系网络与图动力学网络的公开设计为参照，接口随版本演进。三个片段分别覆盖建图、消息传递层与想象 rollout 接口。

片段 1：从对象位置构建 k 近邻图

import torch

def build_scene_graph(node_feat, node_pos, k=4):
    """把节点特征与位置组织成稀疏图：每个节点连 k 个最近邻。"""
    # 两两相对位置（邻居减中心，与边公式 e_ij = p_j − p_i 一致）：B x N x N x 2
    rel = node_pos.unsqueeze(1) - node_pos.unsqueeze(2)
    dist = rel.norm(dim=-1)                          # B x N x N
    eye = torch.eye(dist.shape[-1], dtype=torch.bool, device=dist.device)
    dist = dist.masked_fill(eye, float("inf"))       # 去掉自环，避免只聚合自身
    knn = dist.topk(k, dim=-1, largest=False).indices  # B x N x k
    # 收集每个邻居对的相对位置与距离，拼成边特征
    idx = knn.unsqueeze(-1).expand(-1, -1, -1, rel.shape[-1])
    edge_feat = torch.cat([rel.gather(2, idx), dist.gather(2, knn).unsqueeze(-1)], dim=-1)
    return knn, edge_feat

解读：（1）自环先置为无穷远再取 topk，保证邻居都是其他对象；若需要保留自身信息，由节点网络中的残差连接承担。（2）边特征采用相对位置，配合节点共享权重，天然获得对整体平移与旋转的敏感性控制。（3）knn 索引在后续消息传递中重复使用，建图与推理解耦，便于缓存与可视化。

片段 2：一步关系推理层

import torch.nn as nn

class GraphDynamicsLayer(nn.Module):
    """一步关系推理：先算边消息，再对入边求和更新节点。"""
    def __init__(self, node_dim=128, edge_dim=3, hidden=128):
        super().__init__()
        # 边网络与节点网络对所有对象共享权重，这是置换等值性的来源之一
        self.edge_mlp = nn.Sequential(
            nn.Linear(2 * node_dim + edge_dim, hidden), nn.SiLU(),
            nn.Linear(hidden, hidden))
        self.node_mlp = nn.Sequential(
            nn.Linear(node_dim + hidden, hidden), nn.SiLU(),
            nn.Linear(hidden, node_dim))

    def forward(self, h, knn, edge_feat, action_emb):
        # 全局动作嵌入对每个节点广播：同一扰动下，对象差异靠交互项补偿
        h_a = h + action_emb.unsqueeze(1)            # B x N x D
        src = h_a.unsqueeze(2).expand(-1, -1, knn.shape[-1], -1)
        idx = knn.unsqueeze(-1).expand(-1, -1, -1, h.shape[-1])
        dst = torch.gather(h_a, 1, idx)              # 邻居视角的接收端特征
        msg = self.edge_mlp(torch.cat([src, dst, edge_feat], dim=-1))
        # 求和聚合：置换不变，且消息尺度不随邻居数量缩放
        agg = msg.sum(dim=2)
        return h + self.node_mlp(torch.cat([h, agg], dim=-1))

解读：（1）迭代式更新 h ← h + Δh 的残差形式让每一层只学增量，多层堆叠时稳定。（2）动作嵌入在进入边计算前加到节点上，等价于“动作改变对象状态，再由交互传播影响”的分解。（3）gather 取代循环：批量维、节点维、邻居维全向量化，GPU 利用率高。

片段 3：隐空间想象 rollout

@torch.no_grad()
def imagine_nodes(model, h, node_pos, action_chunk, k=4):
    """在隐空间想象多步轨迹：每步重建图结构并预测下一时刻节点状态。"""
    traj = []
    for a in action_chunk:                       # 动作块长度 8，与预测步长一致
        action_emb = model.act_encoder(a.unsqueeze(0))
        knn, edge_feat = build_scene_graph(h, node_pos, k=k)
        h = model.dynamics(h, knn, edge_feat, action_emb)
        node_pos = model.pos_head(h)             # 位置头把隐状态解码为几何位置
        traj.append(h)
    return torch.stack(traj)                     # B x T x N x D

def graph_pred_loss(pred_nodes, pred_pos, target_nodes, target_pos,
                    knn, rel_weight=0.1):
    """节点预测误差 + 邻居相对向量一致性，抑制结构误差回流。"""
    node_loss = ((pred_nodes - target_nodes) ** 2).mean()
    # 关系项：按邻居索引收集相对位置向量，约束图的几何结构
    idx = knn.unsqueeze(-1).expand(-1, -1, -1, pred_pos.shape[-1])
    pred_rel = pred_pos.gather(1, idx) - pred_pos.unsqueeze(2)
    tgt_rel = target_pos.gather(1, idx) - target_pos.unsqueeze(2)
    rel_loss = ((pred_rel - tgt_rel) ** 2).mean()
    return node_loss + rel_weight * rel_loss

解读：（1）每一步都重构图结构：位置头输出的新位置进入下一轮建图，图随想象演化。（2）动作块逐元素消费，与世界模型的预测步长一一对应。（3）关系项按邻居索引 gather 相对向量差，约束图的几何结构；rel_weight 置 0 时训练退化为逐节点回归，结构误差随想象步数累积放大。

常见坑

  • 过平滑：消息传递层过深，节点特征趋同，不同对象的隐状态几乎无法区分。症状为预测图上所有对象位置趋近质心。修复：层数控制在两层到三层，层间加残差与归一化，监控节点特征的两两距离。
  • 图构建误差随想象步数传播：位置头的小误差使近邻集合在某一步发生跳变，交互结构瞬间改变。修复：对位置输出做平滑、建图时加入边稳定性约束，评估时单独报告图结构的切换频率。
  • 对象槽数失配：场景对象多于槽数时，多个对象被压进同一槽，节点特征失去区分度。修复：按场景对象数的上分位数设置槽数，预留两个冗余槽。
  • 动作广播方式与任务不符：细粒度操作中末梢动作只影响单个对象，广播给全部节点引入无关扰动。修复：改用调制式接入或按空间近邻加权广播。
  • 聚合算子选择随意：均值聚合在稀疏与稠密区域产生不一致的消息尺度。修复：统一用求和聚合，配合节点侧归一化稳定尺度。

练习与思考

  1. 推导题：证明片段 2 的更新在节点排列 P 下满足 f(PH) = P f(H)（提示：逐项考察边计算、求和聚合与共享权重对排列的反应）。★★
    提示
    边随排列重排，边网络用相同参数逐边作用；求和与顺序无关，节点网络逐节点共享权重。三处均等值，复合后整体等值。
  2. 把片段 1 的邻居数 k 从 4 改为 12（接近全连接），预测显存占用、训练速度与长程交互建模能力的变化。★
    提示
    边数随 k 线性增长，显存与耗时同步上升；近全连接丢掉了稀疏先验，小数据下更易过拟合，长程能力未必提升。
  3. 实验设计：训练对象数为 4 的场景，在 6、8 个对象的测试场景上评估单步预测误差，验证置换等值性带来的数量泛化，并报告误差随对象数增长的斜率。★★
    提示
    参数共享使规则与对象数解耦，但对象增多后交互变密，误差仍会上升；对照整体隐向量模型可观察更大的误差跳变。
  4. 诊断题：训练后期节点预测误差持续下降，但多步 imagination 的奖励预估明显偏离真实。给出两条排查路径，区分节点特征误差与图结构误差的主次。★★
    提示
    路径一：固定真值图结构做想象，若误差显著回落则结构误差为主因；路径二：统计想象中近邻集合与真值图的交集比例，观察其随步数的衰减。
  5. 设计题：为双臂协作场景设计边特征与动作接入方案：双臂动作应建模为节点特征、边特征还是全局广播？说明理由并写出消息传递的修改点。★★★
    提示
    双臂动作具有对象归属，建议按末端位置分配动作到对应节点（调制式接入），手臂间协调性由臂末端节点之间的边承担，全局广播只保留基座移动。

小结

  • 图结构表示把场景拆成节点与关系边，交互结构显式化，动力学由共享的边网络与节点网络承担。
  • 消息传递更新 e′ij = φe(hi, hj, eij)，h′i = φh(hi, Σj e′ij)，求和聚合保证置换不变。
  • 置换等值性 f(PH) = P f(H) 来自参数共享与对称聚合，是对象数量泛化的来源。
