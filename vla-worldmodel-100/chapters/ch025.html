第二篇 · 联合训练进阶与策略能力

第 025 章：联合训练中的元学习

同一套策略换到新环境后如何用少量轨迹快速适应；本章讲清任务分布的建模、MAML 内外循环的推导与一阶近似，以及把元学习目标压缩到动力学头与策略头的成本控制方案。

  • 主题：元学习（meta-learning） / 快速适应（fast adaptation）
  • 关键公式：θ′i = θ − α∇θL支持(θ)；θ ← θ − β∇θ Σi L查询(θ′i)
  • 预计学时：55 分钟
  • 前置章节：第 024 章

学习目标

  • 理解任务分布（task distribution）假设在元学习中的地位，能说明分布设计与部署场景的对应关系。
  • 掌握 MAML（Model-Agnostic Meta-Learning）的内外两层优化结构，会推导内循环一步适应的梯度形式。
  • 掌握一阶近似（FOMAML）与 Reptile 的近似方式，理解它们省去的计算量与精度代价。
  • 会设计低成本元学习方案：元参数限定在动力学头与策略头，冻结共享骨干，控制内外循环的次数比例。
  • 能诊断元学习的三类失效：任务泄漏、批归一化统计污染、内循环过拟合支持集。

背景与动机

联合训练出的策略与世界模型绑定在训练环境上：同一台机器换到新桌面、新光照、新物体布局后，动力学与观测分布发生变化，直接部署会失效。在线微调每次都从当前参数出发做多步梯度更新，样本效率有限。元学习（meta-learning）把优化目标抬高一层：训练目标从"在某环境上表现好的参数"改为"到新环境后少量梯度步就能适应的参数"。

第 024 章的对抗训练处理的是扰动邻域内的鲁棒性，扰动不改变任务本身；元学习处理的是任务级的分布变化，例如摩擦系数、负载质量、相机外参的系统性改变。两者共同扩大模型的有效工作范围。

在联合训练框架里，元学习的自然落点是：共享骨干保持不变，元参数限定在世界模型动力学头与策略动作头上，用少量真实轨迹做内循环适应。这既保留了大规模预训练的成果，又把元学习的计算与显存开销压到可接受范围。

核心原理

1. 任务分布：元学习的假设与边界

元学习假设训练与测试任务来自同一个分布 p(T)，每个任务 Ti 对应一套环境参数（摩擦、质量、相机位姿、目标物体集合等）与一个数据分布。元训练目标是：

minθ ET~p(T) [ LT( AdaptT(θ) ) ] AdaptT 表示在新任务的数据上执行的适应过程，通常为若干步梯度更新

分布假设决定适用边界：p(T) 覆盖的偏移类型与幅度，就是元学习器能够快速适应的范围。若部署环境的偏移类型未出现在任务分布中（例如从桌面任务迁移到移动底盘任务），元学习退化为普通预训练。任务分布的设计是元学习里优先级最高的决策，其影响大于任何内循环超参数。

任务采样器的实现方式：从环境参数空间采样一个向量 ξi，用生成器或仿真器构造对应环境，再采集该环境下的短轨迹。视觉任务还需采样纹理、光照与相机位姿；动力学任务采样质量、摩擦与执行延迟。采样范围的设定原则是覆盖部署侧观测到的偏移清单：摩擦系数按标称值上下各留三成余量、负载质量按加减三成、相机外参按标定误差的两倍上限，范围过窄则部署时超界、过宽则任务内差异过大导致适应步数不足。

2. MAML：内外两层优化

把每个任务的数据切分为支持集（support set）与查询集（query set）。内循环在支持集上做少量梯度步，得到任务专属参数；外循环在查询集上评估适应后的参数，并把梯度传回初始参数：

θ′i = θ − α ∇θ Li支持(θ) ，（内循环）
θ ← θ − β ∇θ Σi Li查询(θ′i) ，（外循环） α 为内循环学习率，β 为外循环学习率；梯度 ∇θ 穿过适应过程，需要二阶信息

关键点在最后一个梯度的求法：θ′i 由 θ 经过梯度更新得到，对 θ 求导需要穿过这次更新，包含损失函数对参数的二阶导数项。展开一步适应的外梯度：

∇θ L(θ′i) = ( I − α ∇2θ L支持(θ) ) · ∇θ′ L查询(θ′i) 括号内的 Hessian 项即二阶信息；FOMAML 直接令该括号近似为单位矩阵

一阶近似（First-Order MAML, FOMAML）丢弃二阶项，用 θ′i 处的梯度直接更新 θ，误差通常在可接受范围，计算与显存开销显著下降。Reptile 走得更远：用 θ′i − θ 的方向作为更新信号，完全不做元梯度，实现为多次内循环后向初值回归。

二阶修正的量级用一个可解算例看清：单参数二次损失 L(θ) = 0.5·a·(θ − c)2，取 a = 1、任务最优 c = 1、内循环学习率 α = 0.1，从 θ = 0 出发一步适应得 θ′ = 0.1，适应后损失从 0.500 降到 0.405。外梯度的完整形式为 (1 − α·a)·L′(θ′) = 0.9 × (−0.9) = −0.81；FOMAML 丢掉 (1 − α·a) 因子后得到 −0.90。本例中两种梯度的方向一致、幅度相差 11%，差异由 α 与曲率 a 的乘积控制：α·a 越接近 1，二阶修正越重要，当内步长与曲率匹配到 1 附近时 FOMAML 的误差急剧放大。这给出内循环学习率的隐含约束：α 保持在曲率倒数的十分之一量级以内，一阶近似的代价才是“可接受范围”。

Reptile 的更新信号 θ′ − θ 与一阶元梯度同向：把内循环各步位移累加展开，两者都近似指向使支持集损失下降最快的方向；差别在 Reptile 不做二阶修正，也不区分支持与查询角色（泛化压力由任务批次的轮换承担）。它的工程优势明显：内循环用普通自动求导、关闭 create_graph，最后做一次参数差计算，不需要元梯度的计算图，是三档方案里最容易先落地的起点。

3. 低成本落地：元参数范围的压缩与稳定化

对大型联合模型做全参数 MAML 不现实（二阶梯度需要保存计算图，显存随内步数线性增长）。压缩方案有三条：

  • 元参数限定：只把动力学头与动作头纳入内外循环，共享骨干冻结。适应能力集中在任务相关的输出层，实验显示这覆盖了大部分环境参数偏移。
  • 一阶化：内循环用普通自动求导，外循环用 FOMAML，计算图不保留跨步二阶路径。
  • 内步数控制：内循环 3 至 5 步即可，步数增加带来显存增长快于收益。

稳定化的两个细节：其一，批归一化（BatchNorm）的滑动统计在内循环中会随支持集漂移，外循环评估时统计量不一致，应改用层归一化（LayerNorm）或冻结统计；其二，支持集与查询集必须来自不同的轨迹片段，否则外循环目标被支持集损失的下降直接满足，元学习退化为过拟合。

压缩方案的开销可以算出来：两层 256 宽的头部约 13 万参数，相对 2 亿参数的主干是万分之七；内循环计算图只需保存头部参数的中间量，显存开销只与 13 万量级成正比，与全模型规模无关，跨 5 步内循环的总图长也远小于全参数方案。若把骨干也纳入内循环，显存随 2 亿参数与内步数增长，多数单卡配置直接溢出。头部的选择也有讲究：动力学头负责环境参数偏移，动作头负责执行层适配，两者都在输出端，梯度路径短、二阶项影响集中，适合承担适应职责；把中间层纳入元参数收益有限，因为环境偏移主要通过输出映射体现。

4. 与多任务学习的分工

第 021 章的多任务学习让共享参数同时拟合多个任务，优化的是多任务平均性能；本节的元学习优化的是适应过程的效率。二者可以叠加：共享骨干用多任务损失训练，动力学头与策略头用元目标训练。判断是否需要元学习的信号是部署侧指标：若干步微调后的性能提升幅度。若提升微弱，说明元目标没有学到可适应结构；若提升剧烈，说明元学习的收益真实存在。适应增益的量化定义：增益 = (适应前损失 − 适应后损失) / 适应前损失，例：查询集损失从 0.40 降到 0.25 对应增益 37.5%；分层报告按偏移类型给出，某一类偏移增益接近零时回到任务分布设计，检查该类任务的采样密度。

部署期适应还有安全约束：适应数据必须来自受控的短交互（小幅度动作、限定工作域），适应过程在任务间隙离线执行、完成后冻结参数，绝不允许在线策略边执行边更新。这一约束与 015 章的安全层同源：学习过程与执行过程的分离是机器人系统的结构性要求，元学习只是把“学习量”从数百步压缩到数步，并不改变该分离原则。

实现思路与设计

元训练循环由三层嵌套构成：任务采样、内循环支持集适应、外循环查询集更新。与第 024 章的差异：024 在扰动邻域内增强表示稳定性，本章在任务分布上训练适应机制。

  1. 任务批次：每个元步采样 4 至 8 个任务，每个任务采集 2 至 4 条短轨迹，按 1 : 1 切分支持集与查询集。
  2. 内循环：在支持集上对动力学头与动作头做 5 步梯度更新，内循环学习率 1×10−3（头部参数尺度较小，需要更大的相对步长）。
  3. 外循环：在查询集上计算适应后的损失，FOMAML 方式回传，外学习率 3×10−4 与主训练一致。
  4. 与主训练的交替：元步与普通联合训练步按 1 : 4 交替，保证主任务性能持续提升，元能力不脱离基础水平。

设计决策：内循环学习率为何显著大于外循环？

内循环面对的是单个任务的少量数据，需要快速形成对该环境的偏置；头部参数初始化尺度较小，同样的相对变化需要更大的绝对步长。外循环更新的是共享的初始参数，步长过大会破坏跨任务的通用结构，因此保持与主训练同量级。两者比例在 2 至 10 倍范围内都属常见。

关键代码与解读

以下片段参照公开的 MAML 实现风格编写，为便于展示内循环细节，这里用函数式前向显式管理参数字典；工程版本可改用 torch.func 系列的函数式接口，语义一致。

片段 1：一步内循环的函数式参数更新

import torch

def functional_head_forward(x, weights):
    """用参数字典做前向：内循环需要临时替换参数，函数式写法最清晰。"""
    h = torch.relu(x @ weights["w1"].t() + weights["b1"])
    return h @ weights["w2"].t() + weights["b2"]

def inner_adapt(head, support_x, support_y, inner_lr=1e-3, steps=5):
    """内循环：在支持集上做 steps 步梯度更新，返回适应后的参数。"""
    weights = {k: v for k, v in head.state_dict().items() if k in ("w1", "b1", "w2", "b2")}
    for _ in range(steps):
        pred = functional_head_forward(support_x, weights)
        loss = torch.nn.functional.mse_loss(pred, support_y)
        # create_graph=True：外循环需要穿过这些更新求元梯度
        grads = torch.autograd.grad(loss, list(weights.values()), create_graph=True)
        weights = {k: w - inner_lr * g
                   for (k, w), g in zip(weights.items(), grads)}
    return weights

解读：（1）参数字典的键过滤只保留头部权重，骨干参数不进入内循环，显存开销只与头部参数量成正比，与全模型规模无关；（2）create_graph=True 是元学习的关键开关，它保留更新过程的计算图，使外循环能对初始参数求导；关闭它即退化为 FOMAML 的近似；（3）内循环不调用优化器，手动构造参数更新，避免优化器内部状态（动量等）干扰元梯度的可微性；（4）步数固定为 5，超过这个量级后大部分精度的边际收益来自查询集拟合，适应能力不再提升。

片段 2：外循环元更新

def meta_train_step(head, meta_batch, meta_optimizer,
                    inner_lr=1e-3, outer_lr=3e-4):
    """外循环：对任务批次汇总查询集损失，更新初始参数。"""
    meta_loss = 0.0
    for task in meta_batch:
        spt_x, spt_y = task["support"]
        qry_x, qry_y = task["query"]
        # 每个任务从同一初始参数出发，得到各自的适应参数
        adapted = inner_adapt(head, spt_x, spt_y, inner_lr, steps=5)
        pred_q = functional_head_forward(qry_x, adapted)
        meta_loss = meta_loss + torch.nn.functional.mse_loss(pred_q, qry_y)
    meta_loss = meta_loss / len(meta_batch)
    meta_optimizer.zero_grad()
    # 元梯度穿过内循环更新，经由 create_graph 建立的计算图回传
    meta_loss.backward()
    torch.nn.utils.clip_grad_norm_(head.parameters(), max_norm=1.0)
    meta_optimizer.step()
    return float(meta_loss.detach())

解读：（1）每个任务独立做内循环，任务间的计算图互相独立，元梯度是各任务梯度的求和平均；（2）查询集损失不参与内循环，保证外循环评估的"未见过数据"性质；（3）若显存受限，把 create_graph 改为 False 并在内循环后手动 detach 参数更新，即得到 FOMAML，显存下降约一个内步数的倍数；（4）梯度裁剪同样是必需项：元梯度的方差比普通梯度更大，尤其是任务数较少时。

片段 3：元测试阶段的少步适应

def meta_test_adapt(head, traj_x, traj_y, steps=5, inner_lr=1e-3):
    """部署阶段：用真实轨迹做几小步适应，随后冻结参数执行策略。"""
    weights = {k: v.detach().clone()
               for k, v in head.state_dict().items()
               if k in ("w1", "b1", "w2", "b2")}
    for _ in range(steps):
        pred = functional_head_forward(traj_x, weights)
        loss = torch.nn.functional.mse_loss(pred, traj_y)
        # 部署期不求元梯度，普通梯度即可，显存需求极低
        grads = torch.autograd.grad(loss, list(weights.values()))
        weights = {k: w - inner_lr * g
                   for (k, w), g in zip(weights.items(), grads)}
    head.load_state_dict(weights, strict=False)
    return head

解读：（1）部署阶段只做前向与一阶更新，不需要 create_graph，显存与计算开销与普通微调一致；（2）适应用的轨迹来自当前环境的短交互，长度与内循环训练时的支持集规模匹配，避免分布不一致；（3）strict=False 允许参数字典只覆盖头部，骨干保持不变；（4）适应完成后冻结参数，让策略在线执行时不因持续更新而漂移。

常见坑

  • 任务泄漏：支持集与查询集取自同一条轨迹的相邻片段，外循环几乎不需要泛化。症状是元训练损失极低但部署适应效果差。修复：支持集与查询集来自不同轨迹、不同初始状态，必要时来自不同环境种子。
  • 批归一化统计污染：内循环的若干步更新改变了 BatchNorm 的滑动统计，外循环评估时统计量与适应参数不匹配。修复：把归一化层换成 LayerNorm，或在元训练期间冻结统计量。
  • 内循环过拟合支持集：内步数过大或内学习率过高时，适应参数只拟合支持集的噪声。修复：内步数控制在 5 以内，支持集至少包含 2 条轨迹，观察查询集损失与支持集损失的分叉。
  • 任务分布与部署不匹配：元训练采样的是摩擦系数，部署变化却是负载质量，适应无收益。修复：按部署侧的偏移清单设计任务分布，并在元测试集上分层报告各类偏移的适应增益。
  • 二阶开销失控：全参数 MAML 在大型模型上显存溢出。修复：元参数限定头部、改用 FOMAML、减少内步数，三者按顺序尝试。

练习与思考

  1. 把内循环步数从 5 增到 20。预测元训练显存占用、单步时间与部署适应增益的变化，指出哪个内步数区间最不值得继续增加。★
    提示
    显存随步数近似线性增长（计算图变长），适应增益在 5 至 8 步后趋于平台；超过平台区后每增加一步只带来微小增益，成本却线性上升。
  2. 推导：设支持集损失为 LS、查询集损失为 LQ，一步内循环参数为 θ′ = θ − α∇LS(θ)。写出 ∇θLQ(θ′) 的链式展开，指出单位矩阵近似在哪一步出现。★★★
    提示
    ∇θLQ(θ′) = (I − α∇2LS(θ))∇LQ(θ′)；FOMAML 令括号为单位矩阵，即忽略 Hessian 项，只保留 θ′ 处的查询梯度。
  3. 设计任务分布的消融实验：三组分布（仅视觉偏移 / 仅动力学偏移 / 二者混合）训练同一元学习器，预测各组在对应测试集上的适应增益，并说明结果如何指导分布设计。★★
    提示
    预期各自在匹配的测试集上增益最大，混合分布下单类增益有所稀释但总覆盖更广；若某类偏移上增益接近零，说明该类偏移所需的任务向量未被充分差异化采样。
  4. 验证批归一化的影响：同一元训练流程分别使用 BatchNorm 与 LayerNorm，在查询集损失曲线上预测两者的差异，并给出一个能快速复现差异的检查方法。★★
    提示
    BatchNorm 版本的查询集损失抖动更大且外循环收敛更慢；检查方法：比较内循环前后归一化层的滑动均值变化幅度，BatchNorm 会有显著漂移。
  5. 把元学习与第 021 章的多任务损失结合：给出联合目标的写法（多任务损失在外、元目标在内），并说明两者的梯度如何隔离，避免相互抵消。★★★
    提示
    总目标可写为 L = LMTL + η·Lmeta，元梯度只对元参数生效，多任务损失作用于全部参数；隔离手段是参数分组加 stop-gradient 或分步更新，交替执行两种更新比同时回传更稳定。

小结

  • 元学习优化的是适应效率：初始参数在少量梯度步后应达到新任务上的良好性能。
  • 任务分布覆盖的偏移类型决定元学习的有效范围，分布设计优先于内循环调参。
  • MAML 的外梯度包含 Hessian 修正项，FOMAML 忽略该修正项换取显存与计算的大幅下降。
  • 工程落地把元参数限定在动力学头与动作头，内步数控制在 5 以内，与主训练按比例交替。
  • 任务泄漏、批归一化统计漂移与支持集过拟合是三类高频失效，分别用数据切分、归一化替换与步数控制处理。
