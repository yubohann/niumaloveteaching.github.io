第 016 章：VLA策略的端到端训练

本章把策略训练落到工程配置：端到端的边界定义、显存预算与混合精度、参数分组与学习率调度、梯度累积的正确次序，以及可复现检查点的完整状态。

  • 主题：VLA 策略 / 端到端训练
  • 关键公式：Beffective = Bmicro × Naccum × Ndevice
  • 预计学时：65 分钟
  • 前置章节：第 015 章

学习目标

  • 理解端到端训练的边界：梯度从动作损失直达到视觉前端，与分阶段训练的本质区别。
  • 掌握显存预算的估算方法，以及混合精度、梯度检查点、梯度累积三种压缩手段的作用位置。
  • 掌握参数分组与学习率调度：主干与头部差异化学习率、预热与余弦衰减、权重衰减的豁免项。
  • 能正确实现“累积后裁剪”的训练步与可复现的检查点保存。
  • 能诊断损失尖峰、续训曲线断裂、显存不足三类工程问题。

背景与动机

到此为止，策略、损失、数据、梯度、融合、语言各模块都已就绪，本章回答最后一个第一性问题：整条链路怎么以端到端方式训练，工程上哪些配置决定成败。端到端指梯度从动作损失不经阻断直达视觉与语言前端，表征按控制任务的需要塑造，与“冻结编码器、只训头部”的分阶段做法形成对照。

端到端的代价集中在工程侧：激活显存随深度与 token 数增长，长窗口联合训练进一步放大；低精度计算的数值稳定性需要损失缩放；大批量依赖累积与多卡。这些配置项的取值与次序都有明确的规则，偏离规则的常见后果是“训练能跑但收敛更慢或不可复现”。

边界：007 章排班“谁训”，本章配置“怎么训”；009 章解释梯度机制，本章落实执行次序；017 章的潜空间会重新标定显存预算。

核心原理

1. 端到端的边界与收益

端到端训练的判据是梯度可达性：动作损失的梯度能流经主干到达视觉与语言前端。收益有两层：表征对齐控制目标（视觉前端学到的特征直接服务于动作决策），免去人工设计中间监督；代价有三项：显存需求最高、对数据量敏感、早期不稳定。常规做法是混合边界：编码器加载预训练权重后解冻参与端到端，仅对小数据量的新增模态保留分阶段预热。两种训练形态的对照见下表。

训练形态梯度边界显存数据需求适用
分阶段（冻结编码器）止于头部低小新增模态、数据稀缺
端到端（解冻主干）直达前端高大主训练阶段
混合边界部分路径可达中中预训练权重加载后的常规起步

判据可以执行化：取一个小批次，计算动作损失对视觉前端首层输入的梯度范数。范数为正且与头部梯度同阶时端到端路径成立；范数为零说明路径存在 detach 或 requires_grad 被关闭。该检查纳入冒烟测试，模型结构调整后重跑，避免冻结开关误配造成“名义端到端、实际分阶段”的假象，这类假象的典型症状是训练正常但视觉前端长期停留在预训练特征上。

2. 显存预算与三种压缩

训练显存由四部分组成：参数、参数梯度、优化器状态、激活。前三项与参数量成正比，激活与“批量 × token 数 × 层数”成正比，是可变项。

Mact ≈ c · Bmicro · Ltoken · D层数 （c 为每 token 每层字节系数） 224×224 分块 16 得 196 token/帧；联合训练窗口含多帧时 Ltoken 相应倍增

三种压缩手段作用于不同环节：混合精度把激活与计算压到 16 位，显存约减半；梯度检查点只存层边界激活，反向时重算中间激活，以约三成计算换大幅显存；梯度累积用小批量多次前向累积梯度，等效大批量而不增加激活峰值。

把预算代入具体配置过一遍：微批 16、token 长 392、主干 32 层，每 token 每层保留约 20 个 d=512 的 fp32 张量，即 40 KB 的系数 c，则激活 Mact ≈ 40 KB × 16 × 392 × 32 ≈ 8.2 GB。参数侧按 2 亿参数计：权重 800 MB、梯度 800 MB、AdamW 一阶与二阶矩 1.6 GB，合计约 3.2 GB。混合精度把激活压到约 4.1 GB；再启用每 8 层一个段边界的梯度检查点，激活降到约 1.0 GB。两者叠加后训练峰值从约 11.4 GB 降到约 4.2 GB 量级，这就是“先精度、再检查点”的启用顺序在数字上的依据。

Beffective = Bmicro × Naccum × Ndevice 等效批量决定学习率与训练动态；显存由 Bmicro 决定，两者解耦

三者可叠加使用，但每项都有约束：混合精度需要损失缩放防下溢；检查点对含随机性的层（丢弃）需保证重算一致；累积与批量归一化的统计口径需要对齐，否则小批量统计噪声被带入全局。

梯度累积与批统计的交互值得单独展开：批归一化类模块在微批上计算的统计与等效批量不同，统计噪声会经累积写进滑动平均。Transformer 主干使用层归一化，天然规避该问题；若结构中含批归一化或任何跨样本统计模块，处理规则是累积期间冻结滑动统计，仅在最后一步按等效批量统一更新。验收方式是核对滑动统计的更新次数等于参数更新步数，与微批次数脱钩。吞吐与显存的对偶关系同样一句话可总结：累积步数增加不改变梯度期望，只拉长单步耗时；微批增大提高吞吐但抬高峰值。选型顺序固定为显存优先（微批压到最小可用），再按吞吐需求调累积与卡数。

3. 参数分组与学习率调度

端到端不等于全参数同一学习率。标准分组：主干（预训练权重）用基准学习率，动作头与新增投影层用 2–3 倍学习率加速收敛；权重衰减豁免归一化层与偏置参数，这些参数衰减会破坏其统计职责。调度采用预热加余弦衰减：预热期线性升到峰值，随后余弦降到峰值的 10%，全程训练步数按数据规模标定。

余弦段的学习率代入数字：峰值 1e-4、终点 1e-5 时，进度 25%、50%、75% 处的学习率分别为 8.7e-5、5.5e-5、2.3e-5。曲线的形状是前段缓、后段陡：从 25% 到 50% 只降三分之一，而 50% 到 75% 降近六成，末段的小步长承担细调职责。预热段与余弦段的衔接点在峰值处，两段的斜率不连续属于预期行为；若在衔接点观察到损失尖峰，先查预热是否足够长（2000 步是数据规模中等时的起点），再查该处批次是否恰逢课程调度切换（018 章），两者叠加才会产生可见扰动。

权重衰减的取值依据：AdamW 的解耦衰减取 0.05 是视觉语言模型微调的常用档。偏大（0.1 以上）在数据量小时抑制对新任务的适应，表现为训练损失下降缓慢；偏小（0.01 以下）正则不足，训练与验证的指标差距拉大。豁免组与衰减组分开后，两组学习率可以一致，衰减只在衰减组生效，配置审阅时逐组核对参数数量与前缀。

4. 稳定性机制

三类机制配合使用：梯度裁剪限制单步更新的最坏情况（累积后执行，009 章结论）；损失尖峰检测在异常步回滚优化器状态并跳过高风险批次；权重指数滑动平均（EMA）维护评估用的平滑副本，评估用 EMA 权重、训练用在线权重是精度与稳定的常规配对。所有机制都需要记录触发次数，尖峰频率上升往往预告数据或学习率配置的问题。

EMA 参数与 007 章同口径：ρ=0.999 对应等效权重年龄约千步，评估副本的改进滞后于在线权重约一个评估周期以内，适合作为发布权重的来源。触发计数的监控线可以写成比例：尖峰回滚在最近千步内超过 1% 的步数，或混合精度溢出超过 0.5% 的步数，任一越线即暂停自动继续并转入排查，因为这两类事件的高频出现通常对应学习率、缩放初值或数据批次构成的具体缺陷。

尖峰回滚的粒度是工程细节：完整回滚需要逐步快照优化器状态，成本高；通行做法是维护“最近一次更新前”的单步状态副本，回滚发生时丢弃该步并跳过触发尖峰的批次。回滚日志要带批次来源标记，同一来源反复触发指向数据缺陷，分散触发才指向学习率或缩放配置，两类问题的修复动作完全不同。

5. 检查点与可复现

完整检查点包含五类状态：模型参数（在线与 EMA）、优化器状态、学习率调度器状态、数据管线进度（采样器与随机种子）、混合精度缩放器状态。缺少任何一类都会让续训曲线在断点处出现可见断裂，且断裂难以事后归因。可复现还要求随机源的统一管理：Python、NumPy、框架三层种子绑定同一个训练步，数据增强与丢弃的随机流分离。

检查点的体积也要预算：按 2 亿参数模型计，在线权重 800 MB、EMA 副本 800 MB、优化器一阶与二阶矩 1.6 GB，合计约 3.2 GB，调度器与缩放器状态可忽略。按每 5000 步保存一次、保留最近 5 份的策略，存储配额约 16 GB；若存储紧张，压缩方向是“只对发布候选点保存 EMA 与优化器全量，中间点只存在线权重与步数”，代价是中间点不能用于严格续训，适合作为评估快照使用，不能作为恢复点。

严格复现还有一层算子级因素：部分注意力内核与并行归约在默认设置下非确定，同一批次两次前向的末位数值会有差异。要求比特级复现时启用确定性内核开关，代价是吞吐下降；多数实验只需统计级复现，即固定种子下两条曲线在噪声带内重合，此时保留默认内核并在实验记录中注明内核与驱动版本。复现验收的判据也据此分档：比特级用于排查回归缺陷，统计级用于常规实验对照。

实现思路与设计

训练循环骨架按“累积窗口内前向反向、窗口结束裁剪更新”组织；精度策略为 bf16 前向加 fp32 参数副本；显存策略按优先级启用：先累积对齐等效批量，再检查点主干，最后降微批。评估周期与检查点周期对齐。

设计决策：先定等效批量，再定压缩组合

等效批量决定学习率与优化动态，先固定它并作为不变量；微批、累积、卡数都只是“如何凑出该批量”的手段，可随显存与机器配置自由变化。这样超参数搜索的结果与硬件配置解耦，换机器不必重扫学习率。若显存仍不足，才考虑降低等效批量并同步下调学习率。

衔接与差异：005 章的损失与 009 章的梯度规则在本章组装成可执行的循环；007 章在需要时把本章循环按阶段启用；017 章换用潜空间后，激活占用的主导项从像素解码转为潜序列，本章预算公式需要相应替换系数。

关键代码与解读

片段以大规模 Transformer 训练与 VLA 端到端实现的公开设计为参照，接口随版本演进。第 1 段给出参数分组。

片段 1：参数分组与优化器配置

import torch

def build_param_groups(model, trunk_lr=1e-4, head_lr=3e-4, wd=0.05):
    """参数分组：主干与头部差异化学习率，归一化与偏置豁免权重衰减。"""
    trunk, head, no_decay = [], [], []
    for name, p in model.named_parameters():
        if not p.requires_grad:
            continue                                  # 冻结参数不进优化器
        # 归一化层与偏置不施加权衰：衰减会破坏其统计与偏置职责
        if p.ndim == 1 or name.endswith(".bias"):
            no_decay.append(p)
        elif "action_head" in name or "proj" in name or "modulation" in name:
            head.append(p)                            # 动作头与新增投影走头部学习率
        else:
            trunk.append(p)                           # 预训练主干走基准学习率
    return [
        {"params": trunk, "lr": trunk_lr, "weight_decay": wd},
        {"params": head, "lr": head_lr, "weight_decay": wd},
        {"params": no_decay, "lr": trunk_lr, "weight_decay": 0.0},
    ]

def build_optimizer(model):
    # AdamW：解耦权重衰减，与 Transformer 训练的标准选择一致
    return torch.optim.AdamW(build_param_groups(model), betas=(0.9, 0.95))

解读：（1）分组依据是参数职责，不看模块名字习惯：一维参数（归一化缩放、偏置）自动进入豁免组，避免逐个列出。（2）头部识别用名称匹配；更稳妥的做法是注册时显式打标签。（3）betas 取 (0.9, 0.95)，不用默认的 (0.9, 0.999)：长序列训练中二阶矩的慢速滑动会让更新迟滞，这是大模型训练的常见调整。

片段 2：混合精度与累积训练步

def train_step(model, optimizer, scaler, batch_iter, n_accum=8, clip=1.0):
    """一个更新步：累积内前向反向，累积完成后统一裁剪与更新。"""
    optimizer.zero_grad(set_to_none=True)
    total_parts = {}
    for micro in range(n_accum):
        batch = next(batch_iter)
        # bf16 前向 + fp32 损失：低精度显存优势与数值稳定的组合
        with torch.autocast(device_type="cuda", dtype=torch.bfloat16):
            loss, parts = joint_loss_from_batch(model, batch)
        # 按累积步数缩放：多次反向的梯度之和等价于一次大批量的平均
        scaler.scale(loss / n_accum).backward()
        for k, v in parts.items():
            total_parts[k] = total_parts.get(k, 0.0) + v / n_accum
    # 反缩放后再裁剪：先让梯度回到真实尺度，裁剪阈值才有意义
    scaler.unscale_(optimizer)
    torch.nn.utils.clip_grad_norm_(model.parameters(), clip)
    # scaler.step 内部处理溢出跳过：溢出批次不更新参数并自动调低缩放系数
    scaler.step(optimizer)
    scaler.update()
    return total_parts

解读：（1）loss/n_accum 的缩放与“在等效批量上取均值”的语义一致，保证累积步数改变时损失尺度不漂移。（2）unscale 必须在裁剪之前：缩放后的梯度范数被整体放大，直接裁剪等效于阈值缩小若干倍，属于隐性配置错误。（3）scaler.step 的溢出跳过是混合精度的安全网，溢出计数应纳入监控，频繁溢出说明学习率或缩放初值需要调整。

片段 3：完整检查点与续训

def save_checkpoint(path, step, model, ema_model, optimizer, scheduler,
                    scaler, sampler_state, seed_state):
    """完整状态保存：五类状态缺一都会让续训曲线在断点处断裂。"""
    torch.save({
        "step": step,
        "model": model.state_dict(),
        "ema": ema_model.state_dict(),          # 评估副本与在线权重分开保存
        "optimizer": optimizer.state_dict(),    # 含动量与二阶矩：缺失则更新动态重置
        "scheduler": scheduler.state_dict(),    # 学习率进度：缺失则预热重放
        "scaler": scaler.state_dict(),          # 损失缩放系数与溢出计数
        "sampler": sampler_state,               # 数据采样进度与来源配额游标
        "seed": seed_state,                     # 三层随机源状态绑定训练步
    }, path)

def load_checkpoint(path, model, ema_model, optimizer, scheduler, scaler):
    """加载顺序与保存一致；返回步数与采样状态供训练循环恢复。"""
    ckpt = torch.load(path, map_location="cpu")
    model.load_state_dict(ckpt["model"])
    ema_model.load_state_dict(ckpt["ema"])
    optimizer.load_state_dict(ckpt["optimizer"])
    scheduler.load_state_dict(ckpt["scheduler"])
    scaler.load_state_dict(ckpt["scaler"])
    return ckpt["step"], ckpt["sampler"], ckpt["seed"]

解读：（1）EMA 副本单独保存：只存在线权重会导致评估结果在续训后跳变，无法区分“训练改善”与“评估切换”。（2）采样器状态包含来源配额游标，保证续训后的批次构成与不中断训练一致。（3）种子状态记录三层随机源在断点步的完整状态，是严格可复现的最后一环；对复现要求不严格的场景可省略，但评估一致性仍需 EMA 与优化器状态。

常见坑

  • 裁剪在反缩放之前：梯度被缩放系数整体放大后裁剪，等效阈值除以缩放系数，更新被隐性削弱。修复：unscale 与 clip 的次序写入训练步的固定模板。
  • 参数组学习率串组：名称匹配的头部规则过宽，把主干层误分进头部，学习率暗中提高。修复：分组后打印各组的参数数量与前缀清单核对。
  • 显存估算漏掉世界模型路径：只按策略头估算，联合路径激活叠加后溢出。修复：按完整计算图估算，预估后预留两成余量。
  • 归一化层被权重衰减：豁免规则遗漏，长时间训练后归一化统计被拉偏。修复：一维参数自动豁免，规则固化为构建函数。
  • 续训只存模型权重：优化器与调度器状态缺失，曲线在断点明显断裂。修复：五类状态全量保存，续训后对比断点前后损失曲线做验收。

练习与思考

  1. 单卡、微批 16、累积 8、等效批量目标 128，验证配置是否成立；若换双卡，给出两种等效批量不变的调整方案。★
    提示
    16×8×1=128 成立。双卡可改微批 8×累积 8，或保持微批 16 把累积降到 4。
  2. 把余弦终点从 10% 改为 1%，预测末期训练动态与最终指标的变化。★
    提示
    末期步长更小，细调更充分但训练总时长内损失下降变慢；通常在固定步数预算下收尾略优，超出预算则表现更差。
  3. 推导：说明梯度检查点以计算换显存的量级关系，并解释为什么它对含丢弃层的重算需要一致性保证。★★
    提示
    激活显存从 O(层数) 级降到 O(检查点间隔) 级，计算约增加一次前向；丢弃掩码若重算时不同，反向梯度与真实前向不符。
  4. 设计续训验收流程：从同一个检查点分别直接训练与中断续训，比较两条损失曲线的重合度，给出允许偏差与检查步骤。★★
    提示
    固定种子，续训后逐 100 步对比损失；重合偏差应在噪声范围内，超出则按“模型、优化器、调度器、缩放器、数据”顺序排查。
  5. 构造实验：在相同等效批量下比较“微批 64×累积 2”与“微批 16×累积 8”的收敛曲线与显存峰值，解释差异来源。★★★
    提示
    两者梯度期望一致，但批内统计不同：大批量微批的收敛略快、显存峰值高；小批量累积吞吐略低。结论按“显存预算与吞吐”选择。

小结

  • 端到端的判据是动作损失梯度可达视觉与语言前端，预训练权重解冻参与是常规混合边界。
  • 显存三压缩：混合精度、检查点、累积；等效批量与微批解耦，先定批量再定组合。
  • 参数分组差异化学习率，归一化与偏置豁免衰减；预热加余弦是稳定调度。
  • 累积后反缩放再裁剪，混合精度的溢出计数纳入监控。
  • 检查点五类状态缺一不可，EMA 副本与优化器状态是续训一致性的底线。
