第 061 章：联合训练中的异步更新

本章讲分布式联合训练中的异步更新（Asynchronous Update）机制：梯度为什么会陈旧、陈旧梯度带来多大偏差、怎样用版本号、陈旧度感知学习率与重要性采样把偏差控制在可收敛范围。

  • 主题：训练机制 / 分布式异步优化
  • 关键公式：θt+1 = θt − ηt · g(θt−τ)
  • 预计学时：55 分钟
  • 前置章节：第 060 章：世界模型的任务泛化

学习目标

  • 理解异步更新（Asynchronous Update）在 VLA（Vision-Language-Action）与世界模型（World Model）联合训练中的定位：用并发换吞吐，用偏差换取消同步屏障。
  • 掌握陈旧梯度（Stale Gradient）的数学形式，理解偏差与 Hessian 矩阵、参数位移的关系，能解释有界延迟（Bounded Delay）下的收敛条件。
  • 掌握陈旧度阈值同步（Stale Synchronous Parallel, SSP）与截断重要性采样（Truncated Importance Sampling）两类修正手段的适用位置。
  • 能实现带版本号的梯度提交、陈旧度感知学习率与双缓冲（Double Buffering）参数快照，避免参数撕裂（Torn Read）。
  • 会诊断异步训练中的发散与吞吐长尾问题，能设计同步（BSP）、异步（ASP）、SSP 三者对照实验。

背景与动机

本节说明异步更新针对的训练瓶颈：联合训练中两类网络的算力需求并不一致。世界模型的重建损失可在密集帧数据上大批量快速计算；VLA 策略的动作损失依赖轨迹级 rollout，单步代价高、方差大。若每个训练步都等待最慢的工作进程，加速器利用率受长尾支配。异步更新去掉同步屏障：工作进程读取当前参数、本地计算梯度、立即提交。代价是梯度可能基于旧版本参数，方向不再是当前点的下降方向。本章回答三个问题：偏差能否被界定、修正项写在哪里、工程上怎样避免读写不一致。

核心原理

1. 异步随机梯度下降的形式与陈旧度

异步随机梯度下降（Asynchronous Stochastic Gradient Descent, ASGD）的更新式与同步版本只差一个下标。设参数服务器（Parameter Server）维护全局参数 θ，第 t 步合并的梯度来自在版本 t−τt 读取参数的工作进程，则

θt+1 = θt − ηt · g(θt−τt) τt ≥ 0 为陈旧度（Staleness），单位是更新步数；τt = 0 退化为同步更新

关键结论：异步更新的偏差等于旧点梯度与当前点梯度之差。对平滑损失做二阶泰勒展开可得 g(θt−τ) ≈ ∇L(θt) − HtΔ，其中 Ht 为 Hessian 矩阵（二阶偏导矩阵），Δ 为参数位移。曲率越大、位移越大，偏差越显著：在动作头输出层这类高曲率方向，旧梯度持续把参数推离下降方向，表现为损失尖刺。

2. 数值算例：偏差与陈旧度、位移的定量关系

取一维二次损失 L(θ) = (c/2)θ2，曲率 c = 10，工作点在 θt = 1.0，当前梯度 ∇L(θt) = cθt = 10。学习率 η = 1×10−3 时每步参数位移约 η·10 = 0.01，陈旧度 τ 对应的累计位移近似 Δ ≈ τ × 0.01。代入二阶展开 g(θt−τ) ≈ ∇L(θt) − cΔ，得到偏差随 τ 的变化：τ = 2 时 Δ = 0.02、偏差 0.2，占比 2%；τ = 10 时 Δ = 0.1、偏差 1.0，占比 10%；τ = 100 时 Δ = 1.0、偏差 10.0，与真实梯度等大且方向相反。把偏差代回原式可得一条紧凑的结论：

g(θt−τ) ≈ (1 − c τ η) · ∇L(θt) 当 cτη < 1 时旧梯度只是被缩放；当 cτη > 1 时方向发生翻转，参数被推向上升方向

该式子把发散条件归结为一个乘积：曲率 c、陈旧度 τ、学习率 η 三者共同决定稳定性。曲率 10 与学习率 1×10−3 下，临界陈旧度约为 100 步；把学习率提高到 1×10−2，临界值降到 10 步；若陈旧度上限设为 4，则学习率必须低于 2.5×10−2。数值算例给出了两条实践规则：偏差占比超过约 10% 后旧梯度的方向不再可信，应收缩步长或丢弃该梯度；提高学习率与放宽陈旧度预算不可同时进行。这正是有界延迟加步长收缩组合的定量来源。

3. 两处修正：学习率缩放与重要性采样

修正手段按损失项的性质分成两类，这是本节最重要的区分。第一类作用在学习率上：步长随 τ 收缩，常用幂律衰减

ηt = η0 / (1 + κ · τt1.5) κ 为衰减系数；幂指数 1.5 使 τ = 1 时几乎不惩罚、τ 较大时快速收缩

第二类作用在数据分布上：回放缓冲区（Replay Buffer）中的样本由旧策略 πold 产生，涉及策略概率的项（策略梯度、优势加权回归等）需乘以截断重要性比 ρ = min(ρ̄, πθ(a|s)/πold(a|s))，上截断 ρ̄ 把差异过大样本的权重压回可控范围。行为克隆（Behavior Cloning, BC）类项的回归目标不依赖 θ，重加权意义有限，通常只修正策略梯度项。把修正写在正确的损失项上比加大修正力度更重要。在 actor-learner 架构中，V-trace 对时序差分残差（Temporal-Difference Residual）做逐级截断，属于价值估计侧的标准修正。

4. 读到一半的参数：内存一致性

异步系统的第二个问题在内存层。若工作进程在参数服务器写入张量的过程中读取，可能得到一半新值一半旧值的参数，称为参数撕裂（Torn Read）。撕裂参数既不属于任何历史版本，也没有对应的修正理论。工程解是版本化快照：写端在后台缓冲区累积更新，读端只看到完整提交的前台快照，提交以整字典级别的指针交换完成。读写协议的正确性优先于学习率调参。

5. 有界延迟下的收敛直觉

设损失为 L-平滑（梯度 Lipschitz 常数为 L），全部梯度满足最大陈旧度 τmax，一个保守的步长上界是 η ≤ 1 / (L(1 + τmax))。直觉解释：每步的有效下降窗口被延迟占去一部分，步长按最坏延迟打折才能满足充分下降条件（Sufficient Decrease Condition）。该界过于保守，仅作安全上限使用：先按上界的十分之一量级设基准学习率，再依赖 SSP 控制最坏 τ。无界延迟、无步长收缩、无一致性协议三者同时缺失时，异步训练才会发散。

6. 三种同步模式的对照

同步屏障（Bulk Synchronous Parallel, BSP）、纯异步（Asynchronous Parallel, ASP）与有界陈旧同步（Stale Synchronous Parallel, SSP）构成训练机制的三点选择。BSP 每步等待全部进程，无陈旧偏差但被最慢进程拖累；ASP 完全不等待，吞吐最高但陈旧度无上界；SSP 设定延迟预算 τmax，只让超预算的快速进程等待，把偏差控制在可修正范围内。三者的工程特性对照如下：

维度BSP 同步ASP 纯异步SSP 有界陈旧
同步屏障每步全体等待无仅超预算进程等待
最坏陈旧度恒为 0无上界，随集群抖动放大不超过 τmax
吞吐受最慢进程支配接近硬件上限介于两者之间，τmax = 4 时接近 ASP
偏差控制不需要修正需要步长收缩与重要性比小 τ 可用轻微收缩，大 τ 丢弃
复现性高，位级可复现低，结果依赖执行序中等，受预算约束
适用场景小规模、调试阶段进程速度均匀且同质异质负载的联合训练

联合训练的负载异质性来自两处：工作进程的 rollout 长度随任务阶段波动；两类网络的提交频率不同。SSP 用延迟预算把长尾抖动挡在预算之外，是三类模式中与联合训练最匹配的机制。选择顺序建议为：先用 BSP 建立正确性基线，再切 SSP 观察吞吐收益，ASP 仅在前者收益到顶且进程同质时尝试。

实现思路与设计

本节给出可落地的异步架构：8 个工作进程（Worker）并行采样与反向，2 个学习者（Learner）消费回放数据训练世界模型，参数服务器统一维护两套参数并按模块分桶提交。数据流为：Worker 拉取快照，本地 rollout 与联合损失反向，按模块提交梯度（附版本号与样本数），服务器判定陈旧度并合并，更新版本号。与第 060 章的差异点：模型结构与损失公式不变，改动全部集中在训练机制层。

设计决策：世界模型与 VLA 为什么分开提交梯度

两套参数的最优更新频率不同：世界模型在帧级数据上高频更新，VLA 动作损失依赖轨迹 rollout，天然低频。捆成一次提交会让快的一侧被拖到同一陈旧度。按模块分桶提交后，每个模块维护独立的逻辑时钟，跨模块耦合项（VLA 损失含世界模型前向，世界模型目标含动作条件）的陈旧度由两侧时钟的较大值决定。

SSP 调度的实现要点

  • 提交队列与条件变量。服务器为每个工作进程维护待合并队列，合并线程按到达顺序处理；当最快进程的出生版本与最慢进程已合并版本之差达到 τmax 时，暂停合并该进程的提交并向其发送等待信号。
  • 以逻辑时钟计时。版本号由服务器在合并后递增，进程之间的进度比较全部基于版本号；用墙钟近似会把通信抖动误判为计算落后。
  • 超预算梯度丢弃策略。版本差超过 τmax 的提交直接丢弃，进程收到重拉快照的指令；保留超龄梯度只会让偏差继续累积，丢弃后重新计算的成本低于失控偏差的代价。
  • 桶级合并。梯度按模块与层分组装入缓冲桶，同一桶内的提交按样本数加权平均后再统一应用；桶粒度兼顾通信次数与内存占用，典型取每 10 到 40 个张量一桶。
  • 长尾监控。记录每个进程提交延迟的 P50、P95、P99 分位数，P99 与 P50 的比值超过 3 时说明负载严重不均，需要调整分片策略；调大 τmax 只会把不均推迟暴露。

关键代码与解读

以下片段以参数服务器式训练框架的公开设计为参照，接口随版本演进。三个片段分别覆盖提交协议、陈旧度修正与读写一致性。

片段 1：带版本戳的工作进程迭代

import torch

class AsyncWorker:
    def __init__(self, server, model, worker_id, base_lr=2e-4):
        self.server = server      # 参数服务器句柄：pull / push 两个原语
        self.model = model        # 本地副本，承载某一时刻的参数快照
        self.wid = worker_id      # 工作进程编号：用于给随机种子加偏移
        self.base_lr = base_lr

    def iteration(self, batch):
        # pull 返回（参数字典, 版本号）。版本号是陈旧度计算的唯一依据，
        # 用墙钟时间近似会把通信抖动误算成策略落后
        params, version = self.server.pull()
        self.model.load_state_dict(params)
        # 联合损失：世界模型重建项 + VLA 动作项，本地一次反向
        loss = self.model.joint_loss(batch)
        loss.backward()
        grads = {k: p.grad.detach().clone()
                 for k, p in self.model.named_parameters() if p.grad is not None}
        # 提交时附带版本号与样本数：服务器据此判定陈旧度并做加权合并
        self.server.push(grads, version=version, n_samples=len(batch))
        return float(loss.detach())

解读：（1）版本号在 pull 时捕获、push 时原样带回，构成梯度的出生证明；服务器逻辑时钟只在合并后递增，版本差即陈旧度。（2）梯度先克隆再提交，否则本地模型被下一次 pull 覆盖时张量已被改写。（3）样本数随梯度上传，合并时按样本数加权，避免不同批规模的梯度尺度不可比。

片段 2：陈旧度感知步长与截断重要性比

def stale_lr_scale(version, server_clock, base_lr=2e-4,
                   kappa=0.5, max_stale=4):
    """按陈旧度收缩步长；超过预算的梯度直接丢弃。"""
    tau = max(0, server_clock - version)      # 已合并更新数减去出生版本
    if tau > max_stale:
        return 0.0                            # 交给 SSP 逻辑：等下一轮快照
    # 幂律比线性更贴合经验曲线：小陈旧度几乎无损，大陈旧度快速保守
    return base_lr / (1.0 + kappa * tau ** 1.5)

def truncated_is_ratio(logp_cur, logp_old, clip=2.0):
    """截断重要性比：只用于损失里依赖策略概率的项。"""
    ratio = torch.exp(logp_cur - logp_old)    # ρ = π_θ(a|s) / π_old(a|s)
    # 采用上截断：压低极大权重控制方差，保留小于 1 的收缩信息
    return torch.clamp(ratio, max=clip).detach()

解读：（1）步长缩放把偏差控制从损失侧搬到优化器侧，通用但无法区分损失项。（2）重要性比 detach 后使用，避免引入对旧策略概率的额外梯度路径。（3）只做上截断：比值小于 1 时保留以便自然降权。

片段 3：双缓冲快照消除参数撕裂

import threading

class DoubleBufferedParams:
    """写端在后台缓冲累积更新，读端永远只看到完整提交过的快照。"""
    def __init__(self, params):
        self._front = dict(params)                     # 读端稳定视图
        self._back = {k: v.clone() for k, v in params.items()}
        self._lock = threading.Lock()                  # 只保护交换动作

    def apply(self, grads, lr, version):
        # 学习者在本模块的时钟与全局时钟一致时，才在后台缓冲执行合并
        for k, g in grads.items():
            self._back[k] -= lr * g

    def commit(self):
        # 交换整字典引用，避免逐张量拷贝：交换瞬间完成，读端零等待
        with self._lock:
            self._front, self._back = self._back, self._front

    def snapshot(self):
        # 工作进程拉取引用即可；后续对 _back 的写入不影响已发出的快照
        return {k: v for k, v in self._front.items()}

解读：（1）双缓冲把一致性与并发度解耦：读操作无锁，临界区只有一次指针交换。（2）snapshot 返回浅拷贝，写端只在后台缓冲上原地更新，读端视图始终自洽。（3）该模式同样适用于回放缓冲区与目标网络（Target Network）。

常见坑

  • 陈旧度过大导致发散：症状为损失尖刺、参数范数持续增长。修复：设定 SSP 上限，超过预算的梯度丢弃并要求该进程重新拉取快照。
  • 无锁读写导致参数撕裂：验证损失随机突变且无法复现，单进程复跑正常。修复：双缓冲快照，禁止在发布中的张量上原地写入。
  • 旧策略数据不做分布修正：策略梯度项等价于对已不正确的分布求梯度，策略熵异常下降。修复：随样本存版本号，按 ρ 截断重加权，并为缓冲区设版本窗口。
  • 各进程数据顺序高度相关：使用同一全局种子与同一分片，梯度方差被系统性低估。修复：每进程种子加固定偏移，分片轮转错开。
  • 只看平均吞吐忽略长尾：个别进程提交延迟长，实际陈旧度远超设定上限。修复：监控提交延迟的高分位数，纳入预算核算。
