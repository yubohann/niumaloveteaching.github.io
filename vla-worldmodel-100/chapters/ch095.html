第 095 章：VLA策略的故障检测

世界模型预测残差、累积统计与保形阈值标定：把"执行出问题了"变成可量化、可校准的报警信号，再接上分级恢复流程。

  • 主题：VLA 策略（Vision-Language-Action, VLA）/ 故障检测（fault detection）
  • 关键公式：CUSUM 累积统计与保形阈值分位数
  • 预计学时：50 分钟
  • 前置章节：第 094 章

学习目标

  • 区分三类需要检测的状态：执行失败、分布偏移与传感器退化，理解各自可用的检测信号。
  • 掌握世界模型预测残差的归一化方法，理解为什么按预测不确定度归一后残差才可比。
  • 掌握 CUSUM 累积统计的更新逻辑，会设置漂移容差与报警阈值并解释误报与漏报的权衡。
  • 掌握保形预测（conformal prediction）的阈值标定，理解其有限样本覆盖保证的成立条件。
  • 会设计分级恢复状态机，在重观测、重规划、回退与停机之间按证据强度递进。

背景与动机

策略在开放环境中必然遇到训练分布之外的情况，系统的可靠性取决于"发现问题"的速度与"处理问题"的秩序。抓取滑落、物体被移走、光照突变、触觉漂移，这些事件不会主动报告，只能从监控信号的统计特征中推断。检测太迟钝，失败继续累积；太敏感，频繁中断正常执行。工程上需要一套可校准、可复现的检测链路：明确信号、平滑统计、分位数标定、分级响应。

第 031 章的不确定性估计为检测提供了原料，本章把原料加工为决策：残差如何归一化、累积统计如何设置、阈值如何用验证数据标定、报警后系统如何分级恢复。第 089 章的进度停滞检测与第 084 章的迁移攻击评测在本章统一为监控体系的一部分。

核心原理

故障检测链路由三级构成：原始残差分数、时间累积统计、阈值判定与恢复动作。

1. 残差分数与归一化

世界模型在每步给出预测，真实观测与预测的偏差即残差：

st = ‖ xt+1 − x̂t+1 ‖ / ( σ̂t+1 + ε ) x̂ 为世界模型预测；σ̂ 为预测的不确定度估计（集成标准差或异方差头输出）

按不确定度归一化的目的：不同场景下世界模型的固有残差水平不同（遮挡场景残差天然偏高），归一化后残差尺度可比，同一个阈值可以跨场景使用。没有归一化时，阈值只能在单一场景内标定，换场景立即失效。σ̂ 过小会放大噪声，实践常加下限保护（例如取 σ̂ 的 10% 分位作为下界）。

2. 累积统计与报警判定

单帧残差噪声大，直接对原始分数设阈值会产生大量误报。累积和（Cumulative Sum, CUSUM）统计对持续偏移敏感、对孤立噪声稳健：

St = max( 0, St−1 + ( st − k ) )，St 大于 h 时报警并清零 k 为漂移容差（通常取基线残差均值的 1.5–2 倍）；h 为报警阈值，单位为残差标准差

更新规则有两个关键性质：分数低于容差时统计量向零回退，孤立尖峰不会累积；分数持续超容差时统计量线性增长，缓变故障也能触发。检测延迟约等于 h/(s − k) 步，例如 s 稳定在 2k、h 取容差的 5 倍时约需 5 步累积。误报率随 h 增大指数下降，漏报率随之上升，两者由验证数据上的标定曲线确定。

3. 保形阈值标定

阈值选择有两种依据：统计假设（残差服从已知分布）或保形预测（无需分布假设，用验证数据分位数给出覆盖保证）。保形方法取标定集上的残差分位数：

q = Quantile⌈(n+1)(1−α)⌉/n( {s1, …, sn} ) n 为标定样本数，α 为目标误报率；次序统计量的使用给出有限样本保证

在未发生故障、样本可交换的条件下，新样本分数超过 q 的概率不超过 α。可交换性是关键假设：机器人任务中时间相关性、工况漂移都会破坏它，长期运行的覆盖会偏离目标。工程对策是滑动窗口在线校准：用最近 N 步的分数重算分位数，跟踪工况变化，同时对校准结果设平滑（EMA），避免阈值抖动。

4. 多监控器与分级恢复

单一监控器存在盲区：世界模型残差对"策略故意执行错误动作"不敏感（预测正确但目标错），进度停滞对慢性失败不敏感。工程用三路监控投票：残差监控（世界模型失配）、进度监控（价值增量或进度头停滞）、动作分歧监控（策略集成预测不一致）。两路以上报警才升级恢复级别，降低误报的系统代价。

恢复动作按证据强度递进：一级重观测（重新采集，排除瞬时噪声）；二级重规划（丢弃当前计划，用第 089 章的规划器重新生成）；三级回退（退回到最近一次人工确认或系统验证过的状态）；四级停机（持续失败，等待人工介入）。恢复动作本身也要监控：回退过程触发新报警说明问题级别更高，直接跳到停机。

实现思路与设计

数据流为：世界模型每步预测 → 残差归一化 → CUSUM 累积 → 多监控投票 → 状态机响应。阈值全部来自验证集或在线滑动校准。

  1. 残差监控：世界模型集成 5 个成员，σ̂ 取标准差；k = 1.5 倍基线均值，h = 5。
  2. 进度监控：进度头输出增量的滑动窗口均值，窗口 10 步，低于训练集 5% 分位报警。
  3. 动作分歧：策略集成动作标准差超过验证集 99% 分位报警。
  4. 投票规则：单路报警进入观察，两路报警触发一级恢复，三路触发二级以上。
  5. 与第 031、089 章的差异：不确定性估计与停滞检测在此整合为带标定的监控系统，新增恢复状态机与在线校准。

设计决策：为什么恢复级别需要"重观测"这一级？

相当比例的报警由瞬时噪声触发（反光、遮挡一帧、通信抖动）。重观测的代价几乎为零，却能过滤这类假故障，让后续级别只处理真实问题。直接跳到重规划会浪费计算并中断正常执行；直接停机则过度保守。分级设计把系统代价与证据强度对齐，这是检测系统在实际运行中可用性的关键。

关键代码与解读

以下片段为 PyTorch 风格示意，接口命名以各开源实现的公开设计为参照，随版本演进可能变化。

片段 1：残差监控与 CUSUM 累积

class ResidualMonitor:
    """残差监控：归一化预测误差经 CUSUM 累积，越界报警并清零。"""
    def __init__(self, k=1.5, h=5.0, sigma_floor=0.1):
        self.k, self.h = k, h                 # 容差与阈值，单位为归一化残差
        self.sigma_floor = sigma_floor
        self.s = 0.0                          # 累积统计量的当前值

    def score(self, obs_next, pred_next, pred_std):
        # 按预测标准差归一化：不同场景的残差变得可比
        std = pred_std.mean().clamp(min=self.sigma_floor)
        return ((obs_next - pred_next).abs().mean() / std).item()

    def update(self, score):
        # 向零回退的正部累积：孤立尖峰不触发，持续偏移必触发
        self.s = max(0.0, self.s + (score - self.k))
        alarm = self.s > self.h
        if alarm:
            self.s = 0.0                      # 报警后重置，等待下一次累积
        return alarm

解读：clamp 给 σ 设下界，防止某些步骤预测异常自信时归一化残差爆炸。max(0, S + s − k) 的取正部操作实现单侧 CUSUM，只关心残差偏大的方向；若需要检测"残差过小"的异常（传感器卡死输出恒定值）可对称再开一路。报警后清零是标准做法，避免同一故障持续报警刷屏；日志记录报警时刻与累计步数用于统计检测延迟。k 与 h 的数值以归一化残差为单位，标定前先用验证集画出残差分布。

片段 2：保形阈值标定与在线校准

def conformal_threshold(scores_val, alpha=0.01):
    """保形标定：取验证分数的修正分位数，给出误报率上界。"""
    n = len(scores_val)
    # 有限样本修正：使用 ceil((n+1)*(1-alpha))/n 分位，保证覆盖
    level = math.ceil((n + 1) * (1.0 - alpha)) / n
    q = torch.quantile(torch.as_tensor(scores_val, dtype=torch.float32),
                       min(level, 1.0))
    return q.item()

class OnlineCalibrator:
    """在线校准：滑动窗口重估分位数，跟踪工况漂移并做 EMA 平滑。"""
    def __init__(self, window=500, alpha=0.01, beta=0.95):
        self.buf, self.window = [], window
        self.alpha, self.beta = alpha, beta
        self.q = None
    def update(self, score):
        self.buf.append(score)
        if len(self.buf) > self.window:
            self.buf.pop(0)                   # 维持固定窗口长度
        if len(self.buf) < self.window // 5:
            return self.q
        q_new = conformal_threshold(self.buf, self.alpha)
        # EMA 平滑：防止单批异常把阈值整体推高
        self.q = q_new if self.q is None else self.beta * self.q + (1 - self.beta) * q_new
        return self.q

解读：math.ceil((n+1)(1−α))/n 是保形预测的标准修正，样本量小的时候比直接取经验分位更保守。在线校准的窗口长度是权衡：窗口太长跟不上工况变化，太短阈值被噪声主导；EMA 的 beta 再做一层时间平滑。注意校准数据必须来自"判定为正常"的时段，若把故障期数据混入，阈值会被失败样本抬高，检测能力被自己削弱；工程上用"近期未报警"作为纳入条件。

片段 3：分级恢复状态机

class RecoveryController:
    """故障恢复：按证据强度在重观测、重规划、回退、停机间递进。"""
    def __init__(self, max_fallback=2):
        self.level = 0
        self.max_fallback = max_fallback
        self.fallback_count = 0

    def step(self, alarm_votes, plan_valid=True):
        if alarm_votes < 2:
            self.level = 0                    # 证据不足：回到正常，继续观察
            return "continue"
        self.level = min(self.level + 1, 3)
        if self.level == 1:
            return "reobserve"                # 一级：重采集，过滤瞬时噪声
        if self.level == 2 and plan_valid:
            return "replan"                   # 二级：丢弃计划重新规划
        if self.level == 3 and self.fallback_count < self.max_fallback:
            self.fallback_count += 1
            return "fallback"                 # 三级：回退到已验证状态
        return "halt"                         # 四级：停机等待人工介入

解读：alarm_votes 为多路监控的报警数，两路以下不改变级别，体现"证据强度决定响应"的原则。级别只升不降的窗口内逻辑配合外部的"无报警清零"，形成带滞回的状态机，避免级别抖动。max_fallback 限制回退次数，防止在不可恢复的故障中无限循环；超过后直接停机。plan_valid 参数处理"规划器自身失效"的情况，此时跳过重规划直接回退。状态机的每次迁移都写入运行日志（时间、级别、触发监控），作为事后复盘的依据。

常见坑

  • 在训练分布上标定阈值：验证数据与部署分布不同，实际误报率远高于目标。症状是上线后报警频繁。修复：用留出工况的数据标定、在线校准、定期用真实运行数据回灌检查覆盖。
  • 只看单帧残差：无累积统计，瞬时噪声造成大量误报。症状是报警与任务进度无关地频繁出现。修复：CUSUM 或滑动窗口均值，阈值改按统计量标定，原始分数受单帧噪声影响，不适合直接设阈。
  • 归一化缺失或不稳定：残差未除以不确定度，或 σ 过小，跨场景阈值不可比。症状是某些场景报警不断、另一些场景漏报。修复：标准化残差加 σ 下界保护，检查归一化后不同场景的残差分布是否重叠。
  • 检测过晚：阈值过高或容差过大，故障发生数步后才报警。症状是恢复动作启动时状态已不可逆。修复：用检测延迟（报警步数减故障步数）作为标定指标，与误报率联合优化。
  • 监控盲区重合：三路监控共享同一信号源，故障同时欺骗全部监控。症状是特定故障类型完全无报警。修复：覆盖不同信号源（感知、进度、动作），用故障注入测试表逐类验证。

练习与思考

  1. 分析 CUSUM 更新式的行为：分别给出分数恒为 k、恒为 2k、单步尖峰三种情况下统计量的演化和检测结论。★
    提示
    恒为 k 时统计量停在零；恒为 2k 时每步净增 k，约 h/k 步触发；单步尖峰随后回退。
  2. 把误报率目标 α 从 0.01 放宽到 0.05，预测阈值、检测延迟与恢复次数三个量的变化。★
    提示
    阈值降低，检测更快但误报与恢复动作增加；用任务中断代价与故障损失之和评估取舍。
  3. 推导保形分位数的有限样本覆盖保证，说明可交换性假设在时间序列上何时被破坏。★★
    提示
    次序统计量分析给出 P(新分数超过 q) ≤ α；工况漂移与时间自相关破坏可交换性，覆盖偏离目标。
  4. 设计故障注入测试表：列出五类故障、注入方式、期望检测信号与允许延迟。★★
    提示
    覆盖感知（遮挡）、执行（滑落）、本体（负载突增）、传感（触觉卡死）、环境（目标移走）；每类验证至少一路监控能响应。
  5. 设计检测系统的完整评估协议：指标含误报率、漏报率、检测延迟、恢复成功率，说明标定集、验证集与测试集的划分方式。★★★
    提示
    按工况划分数据，避免相近工况同时进入标定集与测试集；用 ROC 与延迟曲线联合选择工作点，恢复成功率用注入故障后的任务完成率衡量。

小结

  • 故障检测链路为：归一化残差分数、CUSUM 累积统计、阈值判定与分级恢复。
  • 残差按预测不确定度归一化才能跨场景比较；CUSUM 对持续偏移敏感、对孤立噪声稳健。
  • 保形标定给出误报率上界，可交换性被破坏时用滑动窗口在线校准跟踪工况。
  • 多监控投票降低系统误报，恢复按重观测、重规划、回退、停机四级递进。
