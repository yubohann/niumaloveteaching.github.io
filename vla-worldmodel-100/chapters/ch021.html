第二篇 · 联合训练进阶与策略能力

第 021 章：联合训练中的多任务学习

共享骨干同时承担动作预测、未来帧预测与奖励预测时，各任务的梯度会在共享参数上叠加，方向可能相互抵消；本章讲清冲突判据、自动加权与梯度投影两类协调手段，以及任务采样比例的设计依据。

  • 主题：多任务学习（Multi-Task Learning, MTL） / 梯度协调
  • 关键公式：L = Σ wi Li；cos(gi, gj) 为负判为冲突；PCGrad 投影
  • 预计学时：45 分钟
  • 前置章节：第 020 章

学习目标

  • 理解多任务学习（Multi-Task Learning, MTL）在 VLA 与世界模型联合训练中的角色：共享表征（shared representation）负责迁移，任务头（task head）负责分工。
  • 掌握梯度冲突（gradient conflict）的判据与几何含义，能计算两个任务梯度的余弦相似度并解释其正负。
  • 掌握两类协调手段：不确定性加权（uncertainty weighting）自动调节损失尺度，梯度投影（PCGrad）消除冲突方向。
  • 会为动作预测、帧预测、奖励预测、语言对齐四个任务设计损失权重表、任务采样比例与共享结构。
  • 能通过逐层梯度统计诊断负迁移（negative transfer），区分容量瓶颈与优化冲突两种失败模式。

背景与动机

联合训练（joint training）的天然形态就是多任务：同一个骨干网络同时服务动作预测（action prediction）、未来帧预测（future frame prediction）、奖励预测（reward prediction）与语言对齐（language alignment）等多个目标。多任务学习的期望是正迁移（positive transfer）：数据丰富的任务帮助数据稀缺的任务学到可复用的表征，例如视觉编码器在帧预测中学会的几何结构可以提升动作预测的精度。

问题出在共享参数上。四个任务的梯度叠加在同一个 θsh 上，语言对齐关心语义不变性，帧预测关心像素级细节，动作预测关心几何精度，奖励预测关心任务进度；当两个梯度方向相反时，更新互相抵消，出现负迁移：任务数量和共享宽度增加之后，所有指标反而下降。

第 020 章处理了部分可观测下的记忆机制，本章处理多目标在共享参数上的协调问题。奖励预测（022）、模仿初始化（023）与元学习（025）都建立在本章的任务协调机制之上。

核心原理

1. 形式化：共享参数与任务头

把网络参数划分为共享部分 θsh 与任务专用部分 {φi}，每个任务 i 的损失 Li(θsh, φi) 都依赖共享参数。总目标为加权和：

L = Σi wi Li（θsh, φi） ，共享参数的梯度为 g = Σi wi gi wi 为任务权重，gi = ∇θsh Li 为第 i 个任务在共享参数上的梯度

关键观察：多任务训练的质量由梯度向量的方向与尺度共同决定。尺度失衡让某个任务主导更新，方向冲突让更新相互抵消。两类问题需要两类手段：加权解决尺度，投影解决方向。

2. 梯度冲突的判据与几何

两个任务梯度 gi 与 gj 的夹角余弦为：

cos(gi, gj) = gi·gj / (‖gi‖·‖gj‖) 余弦为负说明两个任务的更新在共享参数上存在相互抵消的分量

几何直觉：把两个任务的梯度看作向量，夹角小于 90 度时它们的和比单个分量更有推进力；夹角大于 90 度时，和向量的一部分做功被另一部分抵消，更新效率下降。负余弦的比例（冲突样本占比）是判断是否需要梯度手术的统计量，逐层统计比只看总梯度更精细：视觉编码器低层的冲突往往比高层更严重，因为低层承载的任务公共性最强。

3. 自动加权：把噪声参数化

人工设定 wi 需要反复试错。不确定性加权把每个任务的观测噪声尺度 σi 作为可学习参数，按高斯似然的负对数展开：

L = Σi [ (1 / 2σi2) · Li + log σi ] σi 越大，该任务的权重 1/2σi2 越小；log σi 项阻止 σi 无界增大导致退化解

推导来源：假设任务 i 的回归目标服从均值 fθ(x)、方差 σi2 的高斯分布，其负对数似然即 (y − f)2 / 2σi2 + log σi；把残差平方用任务的原始损失 Li 代替，就得到上式。工程上用 si = log σi2 作参数，保证 σi 恒正且无约束优化。这只是任务相关不确定性的一种参数化，用于自动调节权重，并不等同于完整的贝叶斯推断。

自动调节的平衡点可以解出来：对 si 求偏导并令其为零，−0.5·e−si·Li + 0.5 = 0，得 e−si·Li = 1，即 σi2 = Li。代入算例：任务 A 的残差量级 LA = 4，任务 B 为 LB = 0.25，平衡时 sA = ln4 ≈ 1.386、sB = ln0.25 ≈ −1.386，有效权重 0.5·e−sA = 0.125 与 0.5·e−sB = 2.0，比值 16 比 1，与残差量级比 16 比 1 互为倒数，因为平衡点处 wi = 0.5 / Li。含义是：残差大的任务获得更小的损失权重，训练的注意力自动向已经接近收敛的任务倾斜，防止难任务长期主导更新方向。控制这一机制的前提是各任务的损失尺度可比，否则 σ 学到的只是尺度差异，无法反映难度差异。

4. 梯度投影：PCGrad

梯度手术（Projecting Conflicting Gradients, PCGrad）在检测到冲突时修改梯度方向，把 gi 中与 gj 相反的分量去掉：

gi′ = gi − ( gi·gj / ‖gj‖2 ) · gj ，仅当 gi·gj 为负时执行 几何含义：把 gi 投影到与 gj 垂直的超平面上，保留不冲突的分量

做法是把任务两两配对，逐对判断内积符号，为负则对当前任务的梯度做一次投影。投影后的梯度求和更新共享参数。注意两点：其一，投影只在共享参数上做，任务头各自的参数不受影响；其二，投影不改变任务目标的定义，只改变更新方向，因此可以与任何加权方案叠加使用。

数值算例：一次投影的完整计算

把两个任务的梯度放在二维平面上：gA = (3.0, 0)，gB = 0.5 × (cos120°, sin120°) = (−0.25, 0.433)，即范数 3.0 与 0.5、夹角 120 度。内积 gA·gB = 3.0 × 0.5 × (−0.5) = −0.75 为负，触发投影。投影系数 = −0.75 / 0.25 = −3，gA′ = gA − (−3) × gB = gA + 3 gB = (2.25, 1.299)。核对范数与方向：‖gA′‖ = √6.75 ≈ 2.598，相对 gA 旋转约 30 度，正好等于“去掉在 gB 方向上的全部投影分量”的几何结果。合并之后，gA′ + gB = (2.0, 1.732)，范数 2.646；未投影的原始和为 (2.75, 0.433)，范数 2.784。投影后的总梯度范数略小，但方向同时靠近两个任务的下降方向，避免了“一个任务的推进被另一个任务拉回”。两个极端值先记下：夹角 90 度时投影不触发；夹角 180 度时 gA′ 与 gB′ 同时归零，共享参数在该步完全不更新（任务头仍按各自梯度更新），这是纯方向冲突的极限情形。

5. 采样比例与有效更新量

每个优化步抽到哪些任务由采样比例决定，有效更新量近似为：

有效更新量 ≈ 采样频率 fi × 梯度范数 ‖gi‖ 两个任务梯度范数相差 10 倍时，即使采样频率相同，小范数任务的有效更新也仅占约十分之一

这解释了为何"按数据量等比采样"经常效果不佳：数据量反映的是覆盖度，梯度范数反映的是当前学习难度，两者并无固定比例关系。压缩任务梯度范数（GradNorm 思想）与调整采样比例是同一个问题的两种解法：前者把尺度拉平，后者把频率拉平。实现上优先监控各任务的梯度范数与损失量级，再决定动权重还是动采样。

数值读数：任务 A 与任务 B 的梯度范数分别为 10 与 1、采样频率各 0.5，则有效更新量之比为 10 比 1。两条纠偏路径：把 B 的采样频率提高到约 10 倍（频率拉平）会让 B 的样本使用效率骤降，通常先试权重路线；把 A 的损失权重调到 B 的十分之一或在共享层上对 A 的梯度做尺度归一（尺度拉平）保留两条路径的数据配比。若范数差异来自任务本身的量纲（例如奖励头输出方差极小），尺度拉平是正确解；若来自学习阶段（某任务已接近收敛），让权重随训练进展衰减更合理。监控粒度建议按模块分组：骨干浅层、骨干深层、融合块各自的范数曲线分开画，混合统计会把层间的此消彼长抹平。

适用边界与失效模式

四类情形需要区分对待。其一，本质冲突：两个任务的偏好在真实目标上互斥（例如帧预测要保留纹理而语言对齐要忽略纹理），投影只能掩盖冲突，症状是各任务损失都停在中等水平、冲突比例长期高企而不下降，正确动作是调整共享范围或放弃部分迁移，加大投影力度无法解决本质冲突。其二，极端夹角：梯度夹角接近 180 度时投影后两侧同时归零，共享参数长期得不到更新，表现为骨干表征停滞而任务头独自缓慢改善。其三，尺度失衡放大冲突：某任务梯度范数高出十倍时，即使它与其他任务方向接近正交，总梯度也几乎等于它单独的方向，投影触发次数与真实冲突程度脱钩。其四，损失可比性被破坏：不确定性加权要求各任务损失在量纲上可比较，回归误差与交叉熵直接混合会把 σ 的学习推向拟合量纲差，实施前应把损失归一到可比的量级区间，再启用自动加权。

实现思路与设计

把联合训练改造成多任务训练，按下面六步设计；本章与第 020 章的差异在于：020 的共享结构只服务单一序列建模目标，本章引入多个任务头与梯度协调机制。

  1. 任务清单：动作预测（连续或分箱）、下一帧预测（low-level 或潜空间）、奖励预测、语言对齐（对比损失）。每个任务保持一个独立头，输入取自共享表征。
  2. 共享范围：视觉语言骨干共享到最后一层 Transformer；帧预测解码头、策略解码头、奖励头、对比投影头四者分离。低层共享、高层分离是默认选择。
  3. 损失权重与协调机制：先按原始损失尺度把权重对齐到同一量级，再启用不确定性加权；当逐层统计的冲突比例超过 20% 时启用 PCGrad。
  4. 采样比例：按任务难度与数据量设定，动作 2 : 帧 2 : 奖励 1 : 语言 1 作为起点，按梯度范数统计修正。
  5. 梯度监控：每 200 步统计一次逐任务、逐层的梯度范数与两两余弦相似度，导出冲突比例曲线。
  6. 消融基线：单任务训练四个独立模型作为上界参照，多任务训练与之对比，确认净收益。

参数取值再展开三点。损失权重起点 1.0 / 1.0 / 0.5 / 0.2：动作与帧预测的原始损失量级接近，权重保持同量级；奖励损失是标量回归、尺度较小，给 0.5 补偿；语言对比损失经温度缩放后量级偏高，给 0.2 压低。若不做量级对齐直接按 1 比 1 设权重，语言任务的有效更新量可能高出十倍。冲突比例阈值 20%：任务目标同向时逐层冲突比例通常在 10% 以内，而结构性冲突（帧预测与语言对齐对纹理信息的偏好相反）多在 30% 以上，20% 作为启用投影的分界可减少无效开启；阈值过高会漏掉真实冲突，过低会让投影开销常态存在。共享层数取骨干全部层加一层融合块：融合块用交叉注意力汇总视觉与语言特征，是所有任务共享的最后一站，若把它也按任务分离，跨任务的梯度信号将无法在共享层之前汇聚，迁移收益显著缩水。

设计决策：为什么任务头必须分离？

共享骨干学到的是任务公共因子，例如物体位置与几何结构；头部分离让每个任务保留自己的输出分布假设：动作头输出连续向量，奖励头输出标量，语言对比头输出归一化嵌入。若三类输出强行共用一个头，输出分布的尺度差异会把冲突推向网络的每一层，负迁移显著加剧。

关键代码与解读

以下片段为机制示意，与公开的多任务协调实现（不确定性加权、PCGrad）设计一致；PyTorch 接口在各版本间保持稳定，细节随版本演进，此处以 2.x 风格书写。

片段 1：不确定性加权损失

import torch
import torch.nn as nn

class UncertaintyWeightedLoss(nn.Module):
    """把每个任务的噪声参数化，让优化器自己学习损失权重。"""
    def __init__(self, task_names):
        super().__init__()
        self.task_names = task_names
        # 以 log σ² 为参数：无约束优化，且 1/σ² 恒正
        # 初值 0 对应 σ=1，早期权重近似 1/2，保持各任务中性
        self.log_var = nn.ParameterDict(
            {name: nn.Parameter(torch.zeros(())) for name in task_names})

    def forward(self, losses):
        # losses 为每个任务的原始标量损失
        total = losses[self.task_names[0]] * 0.0
        for name in self.task_names:
            # 0.5 * exp(-s) * L + 0.5 * s，正是 σ 参数化下的负对数似然
            total = total + 0.5 * torch.exp(-self.log_var[name]) * losses[name] \
                    + 0.5 * self.log_var[name]
        return total

解读：（1）选择 log σ2 作参数，规避了正数约束，优化器无需投影到正半轴；（2）每个任务初始权重 0.5，训练早期与手工等权接近，随着各任务残差量级变化，权重自动分化；（3）log σ 项让 σ 无法通过无限增大来逃避任务，因为增大 σ 会让正则项线性增长，形成平衡点。替代方案是手工调权重或 GradNorm 归一化，前者费人力，后者需要控制多个头部的梯度范数，实现复杂度更高。

片段 2：PCGrad 梯度投影

def pcgrad_projection(shared_params, task_losses):
    """对共享参数做 PCGrad：冲突方向的投影消除，返回投影后的梯度。"""
    grads = []
    for loss in task_losses:
        # retain_graph=True：后续还要对每个任务分别取梯度
        # create_graph=False：投影只在一阶梯度上做，不求二阶
        g = torch.autograd.grad(loss, shared_params,
                                retain_graph=True, create_graph=False)
        grads.append(g)

    proj = [list(g) for g in grads]          # 复制一份，避免原地覆盖
    for i in range(len(grads)):
        for j in range(len(grads)):
            if i == j:
                continue
            # 内积为负表示两个任务的更新方向冲突
            dot = sum((pi * pj).sum() for pi, pj in zip(proj[i], grads[j]))
            if dot < 0:
                norm_sq = sum((gj ** 2).sum() for gj in grads[j]) + 1e-8
                # 减去在 g_j 方向上的投影分量，得到垂直部分
                proj[i] = [pi - (dot / norm_sq) * pj
                           for pi, pj in zip(proj[i], grads[j])]
    # 投影后的梯度取平均，交回优化器，缩放系数被学习率吸收
    merged = [torch.stack([p[k] for p in proj]).mean(0)
              for k in range(len(shared_params))]
    return merged

解读：（1）逐参数张量计算内积总和，得到整个梯度向量的内积，逐层统计时把参数分组即可；（2）投影顺序会影响结果，标准做法在每步打乱任务顺序，本片段按固定顺序演示，训练时应加入随机排列；（3）均值与求和的差别仅在于常数因子，被学习率吸收，取均值便于跨任务数比较梯度尺度；（4）开销约为标准反传的 2 倍，因此实际训练按间隔启用，冲突比例低的阶段无需投影。

片段 3：任务采样与联合训练步

def joint_train_step(model, batch, weights, rng, optimizer):
    """一次联合训练步：按比例抽任务，汇集损失，统一回传。"""
    task_pool = ["action", "frame", "reward", "language"]
    sampled = rng.choice(task_pool, size=3, replace=False,
                         p=[0.333, 0.333, 0.167, 0.167])
    losses = {}
    for name in sampled:
        # 同一批轨迹数据可同时服务多个任务，只是取用字段不同
        losses[name] = model.compute_loss(name, batch)
    total = sum(weights[name] * loss for name, loss in losses.items())
    optimizer.zero_grad()
    total.backward()
    # 多任务叠加后梯度范数容易超界，裁剪是必需项
    torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
    optimizer.step()
    return {k: float(v.detach()) for k, v in losses.items()}

解读：（1）每步只抽部分任务计算损失，控制显存与计算量；未被抽中的任务头该步不更新，等价于低频采样；（2）用同一批轨迹的不同字段构造任务损失，保证任务间的数据分布一致，利于共享表征学习；（3）返回逐任务损失用于监控，若某任务损失长期不降而梯度范数正常，说明该任务的头部容量或标签质量存在问题。

常见坑

  • 权重靠直觉设定后不再复核：症状是某任务指标冻结、其余任务正常。修复：每 200 步统计逐任务梯度范数，把权重调整到各任务的有效更新量可比的范围。
  • 把任务采样频率当作数据配比来设：采样频率决定有效学习步数，数据配比决定覆盖度，两者错误绑定会让稀缺任务更快过拟合。修复：按梯度统计独立设定采样比例，数据加载层按任务分别构造批次。
  • 共享主干过窄导致所有任务同时欠拟合：症状是多任务模型低于全部单任务基线，且训练误差也高。修复：扩大共享宽度或减少共享层数，让高层任务专属化。
  • 只对总梯度做冲突检测：不同层的冲突方向可能相反，总梯度上相互抵消后看似无冲突。修复：按模块分组统计余弦相似度，定位冲突集中的层段再决定投影范围。
  • 评估只报算术平均指标：一个任务崩溃时平均值掩盖问题。修复：逐任务报告并给出最差任务指标，同时给出每个任务相对单任务基线的差值。

练习与思考

  1. 两个任务的共享参数梯度分别为 gA（范数 3.0）与 gB（范数 0.5），夹角 120 度。计算投影后 gA′ 的范数，并说明投影对总梯度方向的影响。★
    提示
    先算 cos120° = −0.5，投影系数 = (gA·gB) / ‖gB‖² = (3.0 × 0.5 × (−0.5)) / 0.25 = −3，投影后 gA′ = gA + 3 gB；其范数 = √(9 + 2.25 − 4.5) = √6.75 ≈ 2.598，方向相对 gA 朝 gB 一侧旋转了约 30 度，抵消分量被去除。
  2. 把不确定性加权的初值从 s = 0 改为 s = 2（即 σ2 ≈ 7.4）。预测训练前 1000 步内各任务权重的走势，并说明与 s = 0 起始的差别。★★
    提示
    s = 2 时初始权重为 0.5 e−2 ≈ 0.068，所有任务同时被缩小，等效全局学习率下降；随后残差大的任务推动 s 下降、权重回升。与 s = 0 相比只是起点不同，平衡点的相对权重分布近似，但前期收敛更慢。
  3. 设计 2×2 消融实验：共享骨干宽度（窄 / 宽）× PCGrad（开 / 关），预测四种组合下各任务指标的模式，并指出哪种结果支持"冲突主导"、哪种支持"容量主导"。★★
    提示
    若加宽骨干后所有任务明显提升，容量主导；若加宽提升有限而开 PCGrad 提升显著且冲突比例高，冲突主导；两者同开效果最好说明两种效应都存在，需要同时处理。
  4. 推导：从高斯似然 N(y; fθ(x), σi2) 出发，写出负对数似然，并说明它如何转化为 (1/2σi2) Li + log σi 的形式。★★★
    提示
    −log N = (y − f)² / (2σ²) + log σ + 常数；把 (y − f)² 记为任务损失 Li（如均方误差），忽略与参数无关的常数项即得。对 σ 求极值可得 σ² = Li，说明平衡点处权重与残差成反比。
  5. 设计分层共享方案：四个任务中，帧预测与奖励预测在视觉编码器低层冲突严重，语言对齐与动作预测在高层冲突严重。给出共享与分离的层段划分，并说明这种划分的依据为何优于按任务类型划分。★★★
    提示
    低层让帧预测走独立分支（或投影后再汇总），高层让动作与语言分支分离；依据是冲突统计量，任务语义只作参考，因为同一对任务在不同层段的冲突模式可能相反。划分后用逐层余弦统计验证。

小结

  • 联合训练天然是多任务问题，质量由共享参数上梯度向量的方向与尺度共同决定。
  • 冲突判据是逐层余弦相似度；负分量占比超过约 20% 时考虑梯度投影。
  • 不确定性加权把噪声尺度参数化，自动调节损失权重；log σ 正则项防止退化解。
  • PCGrad 在共享参数上消除冲突分量，可与任意加权方案叠加，代价约为两倍反传开销。
  • 有效更新量由采样频率与梯度范数共同决定，两者需要分别监控并独立调节。
