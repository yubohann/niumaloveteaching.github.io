第 086 章：VLA策略的连续控制

连续动作头的概率建模、动作块的重叠执行与平滑约束：从 tanh 压缩高斯的对数概率修正，到时序集成的指数加权与抖动惩罚。

  • 主题：VLA 策略（Vision-Language-Action, VLA）/ 连续控制（continuous control）
  • 关键公式：tanh 压缩高斯对数概率与时序集成加权
  • 预计学时：50 分钟
  • 前置章节：第 085 章

学习目标

  • 理解连续动作分布的两类建模方式：压缩高斯（squashed Gaussian）与扩散/流匹配（diffusion / flow matching）动作头的差别与适用边界。
  • 掌握 tanh 压缩的对数概率修正推导，理解漏掉雅可比项会造成多大的梯度偏置。
  • 掌握动作块（action chunk）的重叠执行与时序集成（temporal ensembling），解释指数加权窗口如何消除块边界跳变。
  • 会设计抖动惩罚与安全层的组合，理解后置滤波与训练期正则的取舍。
  • 能补偿推理延迟，设计带时间戳对齐的闭环执行流程。

背景与动机

连续控制的工程难点集中在三处：动作的概率语义、动作块的时间拼接、执行时延的闭环补偿。离散动作分类头无法表达精细的连续量（关节角、末端位姿增量），直接用均方误差回归又失去探索能力与多模态表达能力；预测单步动作在大模型推理频率（5–20 Hz）下跟不上控制环（50–1000 Hz），需要一次预测多步并用时间维度拼接；大模型推理延迟与通信延迟叠加后，动作到达执行器时状态已经变化，必须显式补偿。

第 053 章从生成结构角度讨论过时序动作生成，本章从控制视角展开：概率密度修正、重叠动作块的加权融合、抖动正则与延迟对齐。这些机制共同决定策略在真实控制环中的表现，是系统集成阶段的必备环节。

核心原理

连续控制头设计围绕三个问题展开：如何表示动作分布、如何跨时间拼接动作、如何让执行平滑且不滞后。

1. tanh 压缩高斯与对数概率修正

最常用的连续动作头输出高斯分布 N(μ, σ²)，采样无界样本 u，再经 tanh 压缩到 (-1, 1) 的合法动作范围。压缩改变了概率密度，对数概率必须按变量替换公式修正：

a = tanh(u)，log π(a) = log μ(u) − Σi log( 1 − tanh2(ui) ) 求和遍历动作维度；第二项即雅可比行列式的对数，μ 表示高斯密度

修正项的直觉：tanh 在两端把宽的 u 区间压成窄的 a 区间，动作落在边界附近时密度被放大，对数概率相应上调。省略该项会让策略优化目标系统性偏移，倾向于把动作推向边界（因为边界处未修正的概率被低估，策略为达到目标概率会过度放大 u 的均值）。数值上 tanh 饱和时 log(1 − a²) 趋向负无穷，实现中加 1e-6 平滑常数。

扩散与流匹配动作头从噪声迭代生成动作块，天然表达多模态分布且无需修正项；代价是推理需要 10–50 次迭代，通过蒸馏或一致性模型可压缩到 1–4 次。选择标准：动作分布单峰、延迟敏感选压缩高斯；多模态演示数据（同一观测存在多种合法动作）选扩散/流匹配。

2. 动作块与时序集成

动作头一次预测 H = 8–16 步动作块，控制器每 k = 4–8 步重新推理。相邻两次推理的块在时间上大幅重叠，直接按块切换会在边界处跳变。时序集成对覆盖当前时刻的所有预测做加权平均：

at = Σi wi at(i) / Σi wi，wi = exp( −κ ( t − t0i ) ) t0i 为第 i 个块的起始时刻；κ 控制权重衰减速度（τ = 1/κ 为时间常数）

权重随预测年龄指数衰减，新预测权重高，旧预测提供连续性与平滑。κ 的取值构成权衡：κ 过大退化为最近块独占，边界跳变回归；κ 过小则旧预测拖尾，响应变钝。常用时间常数 τ ≈ 1–2 个执行周期。集成窗口天然消除单次推理的随机波动，相当于对动作序列做了因果平滑，且不引入相位滞后（旧块已经推进到当前时刻，不含未来信息）。

3. 抖动正则与执行安全层

高频抖动的来源有两类：演示数据本身的噪声、策略在不稳定状态下的反复修正。训练期加入二阶差分惩罚（jerk penalty）直接约束动作序列的平滑性：

Ljerk = (1/T) Σt ‖ at+2 − 2at+1 + at ‖2 二阶差分近似加速度变化率，抑制方向的频繁翻转

训练期正则优于执行期低通滤波：滤波在时域引入相位延迟，对闭环稳定不利；训练期惩罚让策略自身生成平滑动作，延迟不变。安全层保留两项执行期保护：动作幅值裁剪（硬边界）与速度上限（相邻时刻差分裁剪），两者都在物理约束已知时启用。动作值的归一化按本体统计量完成（例如关节速度用运行均值方差标准化），归一化统计随本体存储，避免跨本体尺度混用。

4. 延迟补偿与时间戳对齐

从观测采集到动作到达执行器存在总延迟 δ（推理与通信之和，典型 50–200 ms）。若直接执行"当前推理的第一个动作"，相当于用过期状态驱动系统。标准补偿流程：为动作块内的每一步打绝对时间戳；执行侧按当前时钟查找应执行的索引，动作块覆盖时刻 t 时选择最接近 t 的索引动作；δ 超过执行周期时提前触发下一次推理（预测性调度）。时间戳对齐把延迟从控制品质问题转化为索引查表问题，这是闭环系统可复现的关键工程手段。

实现思路与设计

数据流为：观测编码 → 动作头输出动作块 → 时间戳标注 → 缓冲集成 → 安全层 → 执行器。训练侧叠加抖动正则，执行侧维护动作缓冲。

  1. 动作头：默认压缩高斯，均值与 log 标准差各一条投影；多模态数据切换扩散头，蒸馏到 4 步采样。
  2. 块参数：H = 8，执行周期 k = 4，即保持 4 步重叠；推理频率与控制频率比约为 1:4（控制环 50 Hz，推理 12.5 Hz）。
  3. 缓冲集成：时间常数 τ = 1.5 个执行周期，κ = 1/τ；缓冲只保留仍覆盖当前时刻的块。
  4. 损失组合：模仿损失 + 0.02 抖动惩罚 + 安全层约束（执行侧，不进损失）。
  5. 与第 053 章的差异：结构上从生成模型细节转向控制闭环，新增延迟对齐与集成缓冲；动作头结构沿用。

设计决策：为什么时序集成不会引入控制延迟？

旧动作块在集成时使用的是其"当前时刻"的索引值，与新块在世界时间上对齐，只提供平滑先验，不含过期状态信息；其贡献随年龄指数衰减。集成等价于对动作序列做因果加权平均，因此不增加相位滞后。

关键代码与解读

以下片段为 PyTorch 风格示意，接口命名以各开源实现的公开设计为参照，随版本演进可能变化。

片段 1：压缩高斯的采样与对数概率修正

def squashed_gaussian_logprob(mu, log_std, u):
    """tanh 压缩高斯：返回动作 a 与 log π(a)，含雅可比修正项。"""
    x = u - mu
    logp = -0.5 * (x ** 2 / log_std.exp().square() + 2.0 * log_std) - 0.9189385
    # 0.9189385 = 0.5*log(2π)，即标准高斯归一化常数
    a = torch.tanh(u)
    # 变量替换修正：log|da/du| = log(1 - tanh(u)^2)；边界加平滑常数防 -inf
    logp = logp - torch.log(1.0 - a.square() + 1e-6)
    return a, logp.sum(dim=-1)     # 动作维求和得到轨迹样本级对数概率

解读：对数概率拆成高斯核项、归一化常数与雅可比修正三部分，逐项对应公式。修正项在 a 接近 ±1 时数值敏感，1e-6 平滑常数保证梯度有限；动作维求和与独立维度假设对应，若动作维度间存在约束（例如末端姿态四元数）需在损失层单独处理。该函数供策略梯度或最大熵正则使用；纯模仿学习只取 a，可以跳过对数概率计算节省算力。

片段 2：动作块缓冲与时序集成

class ChunkBuffer:
    """重叠动作块的时间对齐与指数加权集成。"""
    def __init__(self, tau=1.5):
        self.chunks = []            # 元素为 (起始步 t0, 动作张量 (H, D))
        self.kappa = 1.0 / tau      # 权重衰减率

    def push(self, t0, chunk):
        self.chunks.append((t0, chunk))

    def act(self, t):
        num, den = None, 0.0
        for t0, chunk in self.chunks:
            if t0 <= t < t0 + chunk.shape[0]:
                w = math.exp(-self.kappa * (t - t0))   # 年龄越大的预测权重越低
                a = chunk[t - t0]
                num = a * w if num is None else num + a * w
                den += w
        # 清理已完全过期的块，缓冲长度与推理频率无关，保持常数级
        self.chunks = [c for c in self.chunks if c[0] + c[1].shape[0] > t]
        return num / max(den, 1e-8)

解读：t0 <= t < t0 + H 的索引条件确保只融合覆盖当前时刻的块；权重 exp(-κ·年龄) 与公式一一对应。清理逻辑放在查询后执行，保证内存占用与块长度、推理频率成正比而与运行时长无关，长时间运行不会累积。若两个块覆盖同一时刻，融合动作落在两者之间，方向突变被抑制。该组件运行在执行环内，计算量 O(活跃块数 × 动作维)，可以忽略。

片段 3：抖动正则与总损失组合

def jerk_penalty(actions, dt=1.0):
    """动作块二阶差分平方均值：相当于加速度变化率的离散近似。"""
    # actions: (B, H, D)；除以 dt^2 使惩罚与时间尺度无关
    d2 = (actions[:, 2:] - 2 * actions[:, 1:-1] + actions[:, :-2]) / (dt * dt)
    return d2.square().mean()

# 训练循环中的损失组合示意
loss_act = F.mse_loss(pred_actions, demo_actions)      # 主模仿损失
loss = loss_act + 0.02 * jerk_penalty(pred_actions)     # 抖动正则权重见超参表
# 安全层在执行侧生效，不进入训练损失：训练与执行的职责分离
safe = actions.clamp(-1.0, 1.0)

解读：二阶差分除以 dt² 后量纲为加速度变化率，切换控制频率（dt 变化）时权重无需重调。抖动惩罚只作用于预测动作块，演示动作中保留的抖动不会被放大学习。安全层刻意不进入损失：把物理约束放进损失会让策略在训练分布内学习开销更大的表示，而执行侧裁剪的实现代价为零，且约束边界变化时无需重训模型。若任务对边界动作敏感，可在损失中补充软约束项作为第二阶段微调。

常见坑

  • 遗漏雅可比修正：对数概率少了 log(1 − tanh²) 项，策略梯度有偏，动作长期贴边。症状是动作饱和比例异常升高、成功率低于预期。修复：按公式补齐修正项，并用数值积分校验概率密度归一性。
  • 块边界跳变：相邻块直接切换，末端执行器出现周期性顿挫。症状是跟踪曲线上每隔 k 步出现尖峰。修复：启用时序集成，或降低执行频率提高重叠率。
  • 滤波过度滞后：用大时间常数的低通滤波替代集成，动作平滑但响应迟钝。症状是轨迹跟踪的相位滞后随 κ 减小而增大。修复：控制平滑强度在训练期完成，执行侧只保留安全裁剪。
  • 动作未归一化：不同本体的关节尺度混合训练，损失被大量纲通道主导。症状是某个关节误差远大于其他关节。修复：按本体统计量归一化动作与状态。
  • 延迟未补偿：按推理完成时刻执行块首动作，等效于使用过期观测。症状是高速运动下轨迹超前振荡。修复：为块内每步打时间戳，执行侧按当前时钟查索引；延迟超过阈值时提前推理。

练习与思考

  1. 由变量替换公式推导 tanh 压缩后的对数概率表达式，说明修正项在动作靠近边界时的行为。★
    提示
    log π(a) = log μ(u) − log|da/du|，|da/du| = 1 − tanh²(u)；边界处该因子趋于零，log 修正趋于正无穷，因此需要平滑常数。
  2. 把执行周期从 4 步改为 8 步（块长仍为 8），预测延迟容忍度、动作平滑度与计算量的变化。★
    提示
    重叠消失、边界平滑下降，延迟容忍度降低，推理计算量减半；适合推理极慢的场景但控制品质下降。
  3. 设计延迟测量实验：分别在推理 5 Hz、10 Hz、20 Hz 下测量指令到执行的端到端延迟，给出补偿参数的标定流程。★★
    提示
    用阶跃指令与编码器响应的时间差测量；补偿参数取多次测量的分位数，超过阈值触发提前推理。
  4. 把抖动惩罚权重从 0.02 调到 0.2，预测动作平滑度与任务成功率的变化，并说明验证方法。★★
    提示
    抖动显著下降但快速动作幅度被压制，成功率可能下降；用频谱能量与完成时间两个指标验证。
  5. 设计一个闭环稳定性测试：比较无集成、固定权重平均与指数加权集成三种执行方式在推拉扰动下的恢复时间，给出评估协议。★★★
    提示
    统一扰动幅度与施加时刻，测量位置误差回到阈值内的时间；指数加权预期恢复最快且无超调尖峰。

小结

  • tanh 压缩高斯的对数概率必须包含雅可比修正，漏项会使策略梯度有偏、动作贴边。
  • 动作块重叠执行按时序集成加权融合，指数权重随预测年龄衰减，不引入相位滞后。
  • 平滑约束优先放在训练期（抖动惩罚），执行期只保留安全裁剪，避免滤波延迟。
  • 延迟补偿用绝对时间戳与索引查表实现，延迟超阈值触发提前推理。
