第 012 章：VLA策略中的语言指令编码器

本章深入语言一侧：编码器选型、冻结基座加低秩适配（LoRA）的微调策略、表示提取与融合接口，以及指令改写增强与截断规则对语义保真的影响。

  • 主题：VLA 策略 / 语言编码
  • 关键公式：lemb = Pool(Eθ+Δθ(tokenize(指令)))
  • 预计学时：60 分钟
  • 前置章节：第 011 章

学习目标

  • 理解语言指令在 VLA 中的三类职能：任务识别、对象指代、约束条件。
  • 掌握语言编码器三类选型（对比学习文本编码器、序列到序列编码器、大语言模型主干）的差异与成本。
  • 掌握冻结基座加低秩适配的微调策略与秩、学习率、注入位置的配置方法。
  • 掌握表示提取方式（均值池化、末位 token、注意力池化）对语义保真的影响。
  • 能设计指令改写增强与截断规则，并通过保留集评估语言泛化。

背景与动机

010 章的融合模块把语言当作键值来源，但语言本身如何编码成 token 并未展开。语言编码器的质量直接决定策略能否区分细粒度指令：“把红色方块放到左侧”与“把蓝色方块放到左侧”只差一个词，视觉相同、动作不同，编码器必须保留这类区分度，同时还要对无关改写（“请把”与“把”）保持稳定。

机器人示教数据规模远小于自然语言语料，默认策略是在预训练模型上做轻量适配，不从头训练编码器；同时用改写增强模拟用户指令的多样性，用保留改写集监控泛化。本章把选型、适配、增强三件事拆解成可配置的实现。

与相邻章节的边界：010 章负责融合方向与成本，本章负责语言表示的生成；038 章深入语义理解的增强方法，092 章展开跨语言支持；本章只覆盖与联合训练直接相关的编码机制。

核心原理

1. 语言的三类职能与表示要求

指令承载三类信息：任务类型（抓取、放置、推拉）、对象指代（颜色、形状、空间关系）、约束条件（顺序、速度、避让）。三类信息对表示的要求不同：任务类型需要整体语义，对象指代需要细粒度区分度，约束条件往往含顺序结构，要求编码器保留词序信息。这一分析直接决定后文的池化与截断设计。

2. 编码器选型

三类候选各有侧重：对比学习文本编码器（与视觉编码器对齐训练）天然利于指代任务，语言与视觉共享嵌入空间；序列到序列编码器（T5 类）语义组合能力强，适合含顺序约束的指令；大语言模型主干把指令 token 与动作 token 放进同一序列，语言与动作共享参数，适合大规模端到端路线。三者对照如下表，选型由数据规模与部署预算决定。

编码器优势成本适用
对比学习文本编码器视觉对齐、指代强低对象指代为主的任务
序列到序列编码器组合语义、顺序约束中复杂指令、多步约束
大语言模型主干语言动作统一、可扩展高大规模端到端训练

三类的规模与开销量级不同：对比学习文本编码器参数量在数千万、隐层 512 左右；序列到序列编码器参数量以亿计、隐层 768；大语言模型主干在十亿级参数以上，即使只取前若干层，单条指令的编码开销也逐级上升一个数量级。选型可写成量化门槛：轨迹数据五万条以内取对比学习编码器加适配，五万到五十万之间取序列到序列编码器，五十万条以上且延迟预算允许时才评估大语言模型主干路线。数据规模与编码器容量的匹配比绝对性能更重要，小数据配大主干时适配层以外全是浪费。

3. 冻结基座与低秩适配

机器人数据量不足以微调整个编码器，标准做法是冻结基座参数，注入低秩适配矩阵：

W′ = W + (α/r)·B·A ，A∈Rr×d，B∈Rd×r r 为秩（取 8–16）；A 用高斯初始化、B 初始化为零，训练起点等价于原始模型

低秩适配保留基座的通用语义，只学习任务相关的偏移，可训练参数量约为原模型的百分之一量级。B 零初始化的作用是保证未训练状态下适配无副作用，这是低秩适配稳定性的结构来源。注入位置优先选注意力的查询与值投影：查询侧控制“读取什么信息”，值侧控制“输出什么内容”，两处对下游任务的杠杆最大。

参数量逐项算清：基座隐层 768、秩 r=8 时，单个矩阵新增 8×768 + 768×8 = 12288 个参数，查询与值两个投影合计 24576 个；12 层编码器全部注入共约 29.5 万，相对基座约 8490 万的 0.35%；只注入最后 4 层则降到约 9.8 万，占比 0.12%。秩从 8 减到 4 参数量同比减半，翻到 16 则翻倍，α/r 保持 2 时缩放强度不变，差异只体现在可训练容量与过拟合风险。经验判据：示教数据在一万条以内时秩取 4 到 8、只注入后半部分层；数据到十万条量级再考虑全层注入与更高秩。

α 与 r 的联动再给一组数字：α 固定 16 时，r=8 的有效缩放为 2，r=16 降为 1，r=4 升为 4。同一学习率下秩翻倍会让有效更新幅度减半，秩减半会让幅度翻倍；扫描秩时若不同步调整 α，观察到的差异混入了更新强度变化，实验结论无法归因到容量。规范做法是固定 α = 2r 使缩放恒为 2，或固定“学习率乘以缩放”的乘积；报告实验时把 α、r 与该乘积一并列出。

4. 表示提取与融合接口

token 序列到单一嵌入的池化方式影响语义保真：均值池化平稳但对词序不敏感；末位 token 保留序列位置的归纳偏置，适合自回归编码器；注意力池化用可学习查询加权，表达最灵活但需要更多数据。VLA 场景常取“均值池化加一层小投影”作为默认：投影层把语言嵌入对齐到融合模块的 dmodel，该投影是唯一新增的接口参数，与 010 章的模态嵌入职责区分开。若融合采用交叉注意力（010 章），语言侧可以不做池化、直接提供 token 序列，池化仅用于需要单一摘要的路径。

三种池化的对照见下表。均值池化的语义锚定最稳，但“把杯子推到桌子左侧，再拿到右侧”这类顺序约束会被平均掉；末位 token 在自回归基座上天然携带序列归纳偏置，换到非自回归基座后该偏置消失，摘要依赖末位对齐质量；注意力池化在数据不足时学习到的查询容易塌缩到少数高频词位置，表现为表示方差缩小。

池化方式词序敏感性数据需求典型失效
均值池化低低顺序约束类指令区分度不足
末位 token高（依赖自回归归纳偏置）中非自回归基座上锚定不稳
注意力池化高高欠拟合时查询塌缩、表示方差缩小

掩码遗漏的污染比例可以量化：48 上限下一条 30 个有效 token 的指令，未加掩码的均值池化会把 18 个补齐位的隐藏状态混入摘要，混合比例 18/48 = 37.5%。补齐位在注意力中彼此可见，其隐藏状态带有非零内容，短指令因此系统性偏向“补齐位语义”，长度越短污染越重。修复成本是一行掩码乘法，单元测试用全一掩码与真实掩码两路前向对比即可锁定。

投影层的参数量常被低估：768 到 512 的线性映射是 768×512 ≈ 39.3 万参数，与全层低秩适配的 29.5 万同量级。投影层是随机初始化的新模块，训练不足时它先成为瓶颈：新词表、新语言或新指令分布上线后若指标普遍偏低，先检查该层的更新幅度与梯度范数，再怀疑基座语义，该排查顺序对跨语言支持同样适用（092 章）。

5. 指令增强与截断规则

两种数据侧机制决定语言泛化。指令改写：模板替换、同义替换、语序调整三类，训练集按 30% 概率应用，保留集固定原始与少量未见改写。截断规则：token 预算有限时按“动作动词与对象名词优先”的顺序保留，截断永远从修饰语开始丢，不能丢弃动词或对象。评估时分离两类指标：原始指令准确率与改写指令准确率，两者差距扩大说明模型在记忆模板。

改写的统计形态：按 30% 概率应用且三类随机选一，训练集中约 30% 的样本为改写形式，三类各占约 10%；若只做主谓倒装一类，模型很快适应单一模式，保留集上换类型即失效。改写必须附语义等价校验：动名词与颜色、形状词表在改写前后不一致的样本直接回退原文；校验器实现是词表比对，成本可忽略，但它把“改写引入错误监督”这条风险路径整体关掉。

长度分布外推是隐藏的失效面。训练指令集中在 10 到 20 个 token，短指令表现好；部署时用户可能给出 60 token 的复合指令，截断规则开始丢弃动词之外的成分，失败集中在长指令档。缓解取两条：训练期按长度分档采样，并合成约 10% 的长指令样本进入数据；推理期对超预算指令按连接词做结构化拆分，把单一长条件转成顺序执行的子指令序列，长度问题由此转为时序协调问题。评估报告必须把长指令档单列，总体均值会掩盖这一档的退化。

词表外词是另一个边界：品牌名与新造词被字节级回退切成碎片，碎片嵌入的区分度低，两条只差该词的指令在表示空间里接近重合。缓解按代价排序：先做推理侧的同义替换映射，把领域低频词换成语义等价的常见表述；再收集高频领域词加入词表，扩容词嵌入并只训练新增行，其余行保持冻结；解冻整个嵌入层放在最后。监控手段是构造最小对样本集（两条指令只差一个词），报告表示空间余弦的分离度，分离度收敛到常态水平即修复生效。

实现思路与设计

语言前端流水线：分词与截断、预训练编码器前向、低秩适配注入、池化与投影、输出供 010 章融合模块消费。增强与保留集逻辑位于数据侧（002 章管线内），编码器侧只负责确定性的前向。

关键参数起点

参数默认值作用取值依据
token 上限48序列预算与 002 章截断约定一致

设计决策：语言嵌入不参与世界模型预测损失

指令是策略侧条件，世界模型的观测预测不依赖语言（011 章的条件只有观测与动作）。训练时语言嵌入只经策略路径回传梯度，避免预测任务向语言编码器施加与语义无关的约束。009 章的路径隔离在此按模态复用：语言侧梯度路径独立，诊断为单独的统计项。

衔接与差异：010 章的融合假设语言 token 已就绪，本章完成该前置；004 章的动作头通过融合表征间接消费语言；038 章将在此结构上加语义理解增强，本章保证接口与基线质量。

关键代码与解读

片段以参数高效微调（Parameter-Efficient Fine-Tuning）与 VLA 语言端的公开设计为参照，接口随版本演进。第 1 段给出低秩适配层。

片段 1：低秩适配层

import torch
import torch.nn as nn
import math

class LoRALinear(nn.Module):
    """冻结基座线性层加低秩旁路：只训练 A、B 两个小矩阵。"""
    def __init__(self, base_linear, rank=8, alpha=16):
        super().__init__()
        self.base = base_linear
        self.base.weight.requires_grad_(False)      # 基座冻结，保留通用语义
        if self.base.bias is not None:
            self.base.bias.requires_grad_(False)
        d_out, d_in = base_linear.weight.shape
        self.A = nn.Parameter(torch.randn(rank, d_in) * (1.0 / math.sqrt(d_in)))
        self.B = nn.Parameter(torch.zeros(d_out, rank))   # 零初始化：起点无副作用
        self.scale = alpha / rank                   # 缩放并入常数，推理零额外分支

    def forward(self, x):
        # 旁路增量与基座输出相加：训练学偏移，推理可合并权重零开销
        return self.base(x) + (x @ self.A.t() @ self.B.t()) * self.scale

解读：（1）A 按输入维度标准差初始化，B 取零，数学上保证初始输出与基座完全一致，适合在预训练模型上无损接入。（2）缩放系数 alpha/rank 编码为常数，避免两个超参数联动调整；rank 增大时缩放自动补偿。（3）推理阶段可以把 BA 合并进基座权重，部署路径无额外延迟，这也是低秩适配适合端侧的原因。

片段 2：池化与投影输出

class InstructionEncoder(nn.Module):
    """指令编码前端：冻结基座提取 token，池化加投影对齐到融合维度。"""
    def __init__(self, backbone, d_model=512, pool="mean"):
        super().__init__()
        self.backbone = backbone
        for p in self.backbone.parameters():
            p.requires_grad_(False)                 # 双保险：调用方忘记冻结也安全
        self.pool = pool
        self.proj = nn.Linear(backbone.config.hidden_size, d_model)

    def forward(self, input_ids, attention_mask):
        out = self.backbone(input_ids, attention_mask=attention_mask)
        h = out.last_hidden_state                     # (B, T, d_backbone)
        if self.pool == "mean":
            # 掩码加权均值：补齐位置不参与池化，避免末端语义被稀释
            mask = attention_mask.unsqueeze(-1).float()
            emb = (h * mask).sum(dim=1) / mask.sum(dim=1).clamp(min=1.0)
        else:
            emb = h[:, -1]                            # 末位池化：依赖位置归纳偏置
        return self.proj(emb)                         # 投影到融合模块的 d_model

解读：（1）掩码加权均值是无 padding 批次的正确池化；遗漏掩码会让补齐 token 的隐藏状态混入摘要，短指令的表示被系统性污染。（2）池化方式作为可配置项，便于对照实验；两种模式的参数量一致，只有提取规则不同。（3）投影层是语言侧唯一新增接口参数，判断新词表或新语言适配问题时先检查这一层是否训练充分。

片段 3：按语义优先级的截断

def truncate_instruction(tokens, tokenizer, priority_words, max_len=48):
    """截断时保护动作动词与对象名词：语义关键 token 永不先丢。"""
    if len(tokens) <= max_len:
        return tokens
    # 找出关键 token 的位置：动词与对象词优先保留，修饰语最先被裁剪
    keep = [i for i, t in enumerate(tokens)
            if tokenizer.decode([t]).strip() in priority_words]
    if len(keep) >= max_len:
        # 关键 token 本身就超预算：按原始顺序取前 max_len 个，语义无法两全
        return tokens[:max_len]
    # 其余名额按原顺序从两端补足，保持词序结构完整
    budget = max_len - len(keep)
    others = [i for i in range(len(tokens)) if i not in set(keep)]
    selected = sorted(keep + others[:budget])
    return [tokens[i] for i in selected]

解读：（1）截断策略在词表层面显式保护语义关键 token，比单纯截尾对指令保真度更好，代价是需要维护优先级词表。（2）关键 token 超预算的兜底分支保证函数在任何输入下返回定长结果，训练管线无需处理变长分支。（3）保留原词序（sorted），维持编码器训练时见到的自然语序；按保留类别重排会打乱词序。

常见坑

  • 分词器与基座不匹配：自行替换分词器导致 token id 错位，词嵌入整体失效。修复：分词器与基座作为整体资产发布，加载时校验两者版本的唯一标识一致。
  • 截断丢动词：截尾规则把句末关键信息丢弃，长指令任务失败率显著高于短指令。修复：使用语义优先级截断，并统计长短指令的指标差值做监控。
  • 池化遗漏掩码：补齐位置进入均值，短指令表示被稀释。修复：所有池化路径强制携带掩码，用全一掩码与真实掩码的对照做单元测试。
  • 改写集泄漏：训练期改写与保留集改写同源，语言泛化被高估。修复：改写模板分池隔离，保留集改写不进入训练样本。
  • 适配学习率过高：低秩旁路用主干预设的大学习率，基座语义被快速冲掉。修复：适配层单独参数组，学习率取主干的一半到同等量级。

    提示
    可训练容量减半，训练略快但读取侧不再受任务调整，指代类任务的增益预期下降。
  3. 推导：说明 B 初始化为零时 LoRALinear 输出等于基座输出的原因，并解释若 A 也取零会带来什么问题。★★
    提示
    BA 为零矩阵时旁路恒为零；A 与 B 同时为零会让梯度对两者皆为零，参数永远无法离开起点，形成死初始化。
  4. 设计语言泛化评估：原始指令、已知改写、未见改写三档指标与判定标准，说明如何区分“记忆模板”与“理解语义”。★★
    提示
    三档指标若呈阶梯下降且未见档仍高于阈值，说明语义迁移；若未见档骤降则倾向模板记忆。阈值由基线模型统计确定。
  5. 构造实验：将截断规则从截尾改为语义优先级，在长指令子集上比较任务成功率与关键 token 保留率，解释差异来源。★★★
    提示
    优先级截断的保留率显著更高，长指令成功率提升；若提升有限，检查下游是否对词序或修饰语同样敏感。

小结

  • 语言承载任务类型、对象指代、约束条件三类信息，表示设计需兼顾整体语义与细粒度区分度。
  • 编码器选型在视觉对齐、组合语义、统一主干三者间取舍，由数据规模与部署预算决定。
  • 冻结基座加低秩适配是数据受限下的默认策略，B 零初始化保证无损接入。
  • 池化必须携带掩码，投影层是语言与融合模块之间的唯一接口参数。
  • 截断保护动词与对象，改写增强分池隔离，语言泛化用三档指标分层评估。
