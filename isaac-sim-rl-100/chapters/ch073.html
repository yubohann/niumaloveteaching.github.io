第 073 章：实现逆强化学习

不写奖励函数，从专家演示里"读出"它：本章讲清逆 RL 的歧义性、最大熵 IRL 与 GAIL 的对抗等价，并在 Isaac Sim 里用插销装配演示跑通 GAIL 训练。

  • 主题：从演示中学习 / 占据度量匹配
  • 相关组件：Isaac Sim / Isaac Lab / PPO / GAIL 实现
  • 预计学时：65 分钟
  • 前置章节：第 072 章

学习目标

  • 说清逆强化学习（IRL）的问题设定，以及"奖励不可辨识"的根源（歧义性与势函数等价类）。
  • 理解最大熵 IRL 的目标函数与梯度 = "专家特征期望 − 策略特征期望"的推导直觉。
  • 理解 GAIL 的对抗形式：判别器与策略的 min-max 博弈等价于占据度量匹配。
  • 会在 Isaac Sim 里收集专家演示、实现判别器网络、把对抗奖励接入 PPO 训练。
  • 会用"判别器准确率 0.6–0.8 健康区间"与任务指标双轨监控训练。
  • 能修复判别器速塌、奖励饱和、价值函数被非平稳奖励拖垮等典型故障。

背景与动机

第 072 章教你"怎么把奖励写得安全"，但更根本的问题是：你写得出奖励吗？让机器人"把插销插得又顺又不伤件"，顺、不伤，这两个词背后是一整套难以写清的力/速度/位姿联合条件。相比之下，人能示范：拖动示教或遥操作录 100 条成功轨迹，比写 100 个奖励项容易得多。逆强化学习（Inverse RL, IRL）就是从这个需求出发的：从演示中反推出一个奖励函数，再用它训练策略。

IRL 有一条绕不开的理论门槛：奖励不可辨识，无数个奖励函数都能让同一组演示显得"最优"（比如全零奖励）。本章先把这个歧义性讲透（它是理解所有 IRL 算法为什么长成那样的钥匙），再给出两类主流解法：最大熵 IRL（恢复一个分布匹配的奖励）与 GAIL（不显式恢复奖励，直接用判别器当奖励的对抗博弈）。最后在插销装配任务上完整落地 GAIL。

核心原理

1. 奖励不可辨识：IRL 的阿喀琉斯之踵

给定专家演示轨迹 τE，IRL 要找 R 使得专家（在 R 下）近似最优。问题：解不唯一。两个经典事实：

  • 常值平移：R 与 R + c（c 为任意常数）引出相同的最优策略，奖励的绝对基线不影响排序。
  • 势函数等价：R 与 R + (γΦ(s′)−Φ(s)) 的所有势函数塑形版本共享同一最优策略集（第 072 章定理的镜像）。IRL 的歧义空间恰好是"势函数塑形那部分"：这就是"不可辨识"的精确含义。

所以 IRL 必须有额外准则从等价类里挑一个解：最大熵准则（在满足"专家最优"的奖励里选让演示分布熵最大的那个）、对抗判别（让奖励能最好地区分专家与当前策略）、或人工先验（偏好稀疏奖励、偏好某类特征）。没有免费的午餐：你总要以某种形式注入偏好，这是理解 IRL 的第一原则。

2. 最大熵 IRL：让专家轨迹"大概率"

把轨迹的似然建成基于回报的指数分布：P(τ) ∝ exp(R(τ))（R(τ)=Σγtr(st, at)）。最大化演示的似然等价于最大化：

L(R) = Eτ~演示[ R(τ) ] − log Σ全部轨迹 exp( R(τ) )　（配分函数 Z 的对数）

第二项（log Z）是对"所有可能轨迹"的归一化，数值上算不动，但它对参数的梯度有一个漂亮的形式：

∇θ L = E演示[ ∂R/∂θ ] − Eπ(R)[ ∂R/∂θ ] 让"专家常走的状态/动作"的奖励升、让"当前策略常走的地方"的奖励降，直到两者特征期望对齐

这就是占据度量匹配（occupancy matching）：不减损专家看到的状态分布，同时压低策略自己的。若 R 是特征线性函数 r = θTf(s,a)，梯度就化为"专家特征均值 − 策略特征均值"，非常直观，IRL 学习的是"演示里哪些特征被看重"。

3. GAIL：把"匹配"直接做成对抗游戏

最大熵 IRL 的每一步梯度都需要推断新策略（强循环依赖）。GAIL（Generative Adversarial Imitation Learning）把它合并成一个 min-max 博弈：

minπ maxD　E演示[ log D(s, a) ] + Eπ[ log( 1 − D(s, a) ) ] D 是判别器：给"像专家"的数据打高分；π 想生成让 D 分不出"假"的行为

实践中的训练循环是：判别器把"专家=1、当前策略=0"当二分类问题学；策略收到奖励 r = −log(1 − D(s, a))（有实现用 log D，等价偏置一个常数），用任意 RL 算法优化。理论上在最优判别器处，该奖励的梯度与最大熵 IRL 的占据度量匹配严格一致，GAIL 是"不需要解出奖励的 IRL"。它的优势是无需知道转移核、也不显式迭代奖励参数；代价是奖励是随策略移动的（非平稳），训练动态比固定奖励复杂。

4. 健康训练的读数：判别器准确率

GAIL 的成败几乎能从一个数字读出来：判别器对"专家 vs 策略"的分类准确率。理想区间 0.6–0.8：明显高于 0.5（说明还有差距可学、有梯度给策略），又没到 1.0（判别器没赢麻）。准确率长期 0.95+ 说明判别器过强，策略收到的奖励趋于饱和（−log(1−D)→大常数或 0），梯度消失，模仿停滞；长期 ≈0.5 则说明判别器太弱，奖励信号无语义（策略已与专家难分，或判别器欠拟合）。对应的稳定手段：判别器学习率比策略低一个量级、加大 batch、加梯度惩罚或权重衰减、标签平滑。

实现思路与设计

以"插销插入孔位"（peg-in-hole）任务为例，落地 GAIL 的完整流程：

  1. 采集专家演示：用脚本控制器或遥操作录 100–200 条成功轨迹，每条 3–5 s（60 Hz 下 180–300 步）。保存 (s, a, s′) 三元组，观测与训练环境逐字节同构（同样的归一化、同样的关节顺序），演示与训练的观测口径不一致是 GAIL 第一号杀手。
  2. 判别器设计：输入拼接状态与动作（state-action 版，能抓住"动作细节"；state-only 版更省事但对动作风格不敏感），2 层 256 的 MLP + Tanh，输出 logit；用二元交叉熵损失训练，正样本来自演示回放池、负样本来自当前策略的新数据。
  3. 奖励构造：rGAIL = −log(1 − D(s, a))，逐项归一化（滑动均值方差）后叠加一个小的任务塑形（可选的粗糙成功奖励，加速早期）；给 rGAIL 设上限防冷启动前期取值爆炸。
  4. 训练循环：PPO 更新策略；每 4 个 PPO 迭代更新一次判别器（保持奖励相对平稳）；判别器学习率 1e-4，策略 3e-4；batch 512（专家采样 256 + 策略采样 256）。
  5. 监控与验收：每 10 个迭代记录判别器准确率、rGAIL 均值、价值损失、任务成功率（以环境的真实成功判定为准）；验收看成功率与"轨迹相似度"（用动态时间规整 DTW 比对成功轨迹与演示的位姿序列）。
设计思维：为什么 GAIL 奖励之外还要留一点任务奖励？

纯 GAIL 在早期信息极稀疏：判别器还没学出有意义的分界，策略几乎收不到可用的方向性信号，容易在接触丰富的任务里直接卡死。加一个"粗粒度成功判定"（例如插销底部进入孔口 2 cm 给 +1）相当于给博弈一个初始锚点，让策略先能碰到"值得模仿的邻域"，再靠 GAIL 精修风格。这是工程实践常见的"混合奖励"，理论纯度下降，但收敛稳定性显著提升，理论告诉你等价性，工程负责把等价性变成可收敛性。

关键代码与解读

片段 1：专家回放池与策略数据的采样接口

import numpy as np
import torch

class DemoReplay:
    """专家演示池：按轨迹存储，采样时随机切片；接口与训练回放对齐。"""
    def __init__(self, obs_dim, act_dim, capacity_trajs=200, device="cuda"):
        self.obs = np.zeros((capacity_trajs, 400, obs_dim), dtype=np.float32)
        self.act = np.zeros((capacity_trajs, 400, act_dim), dtype=np.float32)
        self.length = np.zeros(capacity_trajs, dtype=np.int32)
        self.count, self.device = 0, device

    def add_episode(self, obs_seq, act_seq):
        # 长度不足 400 的轨迹尾部用长度标记屏蔽，采样时不越界读垃圾数据
        n = len(obs_seq)
        self.obs[self.count, :n] = obs_seq
        self.act[self.count, :n] = act_seq
        self.length[self.count] = n
        self.count += 1

    def sample(self, batch):
        idx = np.random.randint(0, self.count, size=batch)
        steps = (np.random.rand(batch) * self.length[idx]).astype(np.int32)
        obs = torch.as_tensor(self.obs[idx, steps], device=self.device)
        act = torch.as_tensor(self.act[idx, steps], device=self.device)
        return obs, act                        # 返回 (s, a) 对，供判别器正样本用


def policy_sample(policy_data, batch):
    """从 PPO 刚采集的 rollout 缓冲里随机取 (s, a)：负样本必须来自"当前策略"。"""
    idx = np.random.randint(0, len(policy_data["obs"]), size=batch)
    return policy_data["obs"][idx], policy_data["act"][idx]

解读：演示池的两个工程点决定训练质量。按轨迹存储、随机切片采样：如果按"帧"独立洗牌采样，判别器看到的正样本会丢失时间关联（尤其对接触类任务，单帧状态大量重复），且掩盖了"同一条演示内部多样性"的真实结构；按轨迹采样更接近"专家那类行为"的分布。长度掩码（length）防止短视频尾部的零填充被当成"专家静止状态"，零填充会让判别器把"不动"学成专家特征，策略随即学会赖着不动，这个事故在初学者实现里非常常见。policy_sample 强调负样本来自当前策略：若误用旧策略数据，判别器学的是"新旧差异"，"模仿差距"就丢了，奖励方向会跑偏。大 batch（256+256）是对抗训练的标准配置：小 batch 下判别器对样本噪声过拟合，准确率剧烈波动。

片段 2：判别器与 GAIL 奖励

import torch
import torch.nn as nn

class GAILDiscriminator(nn.Module):
    """二分类判别器：专家样本 → 高 logit；策略样本 → 低 logit。"""
    def __init__(self, obs_dim, act_dim, hidden=256):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(obs_dim + act_dim, hidden), nn.Tanh(),
            nn.Linear(hidden, hidden), nn.Tanh(),
            nn.Linear(hidden, 1))
        # 输出保留 logit：BCEWithLogits 数值更稳，概率与奖励由公式换算

    def gail_reward(self, obs, act, reward_scale=1.0, cap=10.0):
        logit = self.net(torch.cat([obs, act], dim=-1)).squeeze(-1)
        # r = −log(1 − D)：D→0 时 r 大、D→1 时 r→0；用 softplus 抗饱和实现
        r = torch.nn.functional.softplus(logit) * reward_scale
        return torch.clamp(r, max=cap)          # 上限：防冷启动阶段奖励数值爆炸


def update_discriminator(disc, opt, expert_obs, expert_act, policy_obs, policy_act):
    """一次判别器更新：正负样本混合做 BCE；平滑标签缓解过强。"""
    pos = disc.net(torch.cat([expert_obs, expert_act], -1)).squeeze(-1)
    neg = disc.net(torch.cat([policy_obs, policy_act], -1)).squeeze(-1)
    loss_pos = torch.nn.functional.binary_cross_entropy_with_logits(
        pos, torch.full_like(pos, 0.9))        # 标签平滑 0.9：防止判别器把专家"背下来"
    loss_neg = torch.nn.functional.binary_cross_entropy_with_logits(
        neg, torch.zeros_like(neg))
    loss = loss_pos + loss_neg
    opt.zero_grad(); loss.backward(); opt.step()
    with torch.no_grad():                      # 监控用：判别器对两类样本的准确率
        acc = 0.5 * ((pos > 0).float().mean() + (neg <= 0).float().mean())
    return float(loss), float(acc)

解读：softplus(logit) 是 −log(1−D) 的数值稳定实现，当 D→1（logit 很大）时，直接算 1−D 会遇到精度损失和梯度饱和，softplus 在全程给出平滑梯度（softplus(z)=log(1+ez) 对任意大 z 都不会溢出）。标签平滑 0.9 是对"判别器过强"最便宜的抑制：让正样本目标不是硬 1，判别器无法把 logit 推到无穷，D 准确率更久地停留在 0.7 附近，策略端持续有梯度。上下限 cap=10 与第 071 章 RND 的上限同理。监控量选择"准确率"：对抗训练的损失同时受两方影响，绝对值无意义，准确率才反映"分得开不开"。注意 pos > 0、neg <= 0 只是分类正确的近似（logit 过零即阈值 0.5），这个近似在监控口径下够用，且零成本。

片段 3：训练循环，策略与判别器的时间尺度分离

import numpy as np

class GAILRewardNorm:
    """GAIL 奖励的滑动标准化：非平稳奖励的入门处理，防止价值函数被拖着走。"""
    def __init__(self, alpha=0.99, clip=5.0):
        self.mean, self.var, self.alpha, self.clip = 0.0, 1.0, alpha, clip

    def __call__(self, r):
        r = float(np.asarray(r).mean())
        self.mean = self.alpha * self.mean + (1 - self.alpha) * r
        self.var = self.alpha * self.var + (1 - self.alpha) * (r - self.mean) ** 2
        z = (r - self.mean) / (np.sqrt(self.var) + 1e-8)
        return float(np.clip(z, -self.clip, self.clip))


def train_step(env, policy, disc, opt_d, demo, gail_norm, step):
    obs = env.obs
    act, logp = policy.act(obs)
    env.step(act)                                  # 环境推进，收集 s'
    r_env = env.reward                             # 可选的任务塑形小奖励
    r_gail = gail_norm(disc.gail_reward(obs, act)) # 奖励在线生成 + 归一化
    policy.reward = r_env + r_gail
    policy.store(obs, act, logp, policy.reward)
    policy.update()                                # PPO 更新（每次） 
    if step % 4 == 0:                              # 判别器每 4 步更新一次
        e_obs, e_act = demo.sample(256)
        p_obs, p_act = policy_sample(policy.data, 256)
        loss, acc = update_discriminator(disc, opt_d, e_obs, e_act, p_obs, p_act)
        return {"disc_loss": loss, "disc_acc": acc}
    return {}

解读：循环里最关键的两个字是分离。step % 4 让判别器更新慢于策略，如果两者同频，策略刚适应奖励、判别器立刻重画分界，PPO 的价值网络追着一个移动靶更新，表现为价值损失长期不降。GAILRewardNorm 用运行均值方差把奖励拉回单位尺度，这是非平稳奖励与价值函数和平共处的最低要求；clip=5 防止个别极大值（判别器瞬间失准）主导整个 batch。监控循环里应当每 10 步记录三组数字：判别器准确率（0.6–0.8 之外就该调参）、GAIL 奖励均值（持续上升说明模仿变好）、真实任务成功率，最后这个是唯一能验收的指标：GAIL 奖励上升只说明"更像演示"，是否真的完成插销插入要另算。若成功率与 GAIL 奖励背离（奖励涨、成功率平），优先怀疑演示本身包含大量低质量轨迹或任务成功率判定与任务目标不一致。

常见坑

  • 演示与训练的观测口径不一致：归一化统计、关节顺序、坐标系不同，判别器把"数据来源差异"当成专家特征。症状是 GAIL 奖励一学就"完美"但任务成功率不动。修复：演示采集与训练共用同一个观测构造模块；加一条一致性测试（同一物理状态，两端观测差小于 1e-6）。
  • 判别器过强/速塌：准确率几分钟就冲到 0.99，奖励饱和、策略停滞。症状是奖励曲线早早贴平。修复：判别器学习率降一个量级、标签平滑、加权重衰减或梯度惩罚；观察准确率曲线是否回归 0.6–0.8 区间。
  • 非平稳奖励拖垮价值函数：奖励分布随判别器漂移，价值网络追不上，优势估计全噪声。症状是价值损失反复冲高、策略回报和 GAIL 奖励同步抖动。修复：奖励滑动标准化 + 降低判别器更新频率 + 价值网络学习率略降；严重时先冻结判别器几个 PPO 周期再解冻。
  • 示范质量决定上限：演示里混入 30% 低质量轨迹（磕碰、试探），GAIL 会把"磕碰"也学进风格。症状是策略成功率上不去、接触力偏大。修复：先对演示做筛选（按成功判定与平滑度过滤），宁少勿滥，100 条干净的好于 300 条混杂的。
  • 用 GAIL 奖励当验收指标：训练报告里只有"模仿奖励上升"没有任务指标。症状是上线即露馅。修复：验收永远用任务级指标（成功率、力峰值、时间）；GAIL 奖励只做训练诊断。

  2. 把 GAIL 奖励换成 log D（另一种常用形式，与 −log(1−D) 只差常数偏置），观察训练稳定性与策略行为差异，解释"只差常数偏置"的直觉为什么在实践中仍有差别。★★
    提示
    早期 D 接近随机时两种形式给出的梯度尺度与饱和点不同；记录前 10% 训练期奖励均值与梯度范数。
  3. 实现 state-only GAIL（判别器只看观测），与 state-action 版对比：在插销任务上哪个更能复制"轻柔插入"的动作风格？★★★
    提示
    state-only 匹配状态占据但不匹配动作细节，可能学出"到达同样状态但用力很猛"的策略，测接触力峰值。
  4. 给演示数据人为混入 20% 的"抖动轨迹"，观察策略动作平滑度的退化，并设计一个演示筛选规则修复它。★★
    提示
    按逐帧动作差的均方排序轨迹，剔除上四分位；再训练看动作平滑度（动作差均值）是否恢复。
  5. 设计实验比较"纯 GAIL"与"GAIL + 稀疏成功奖励"在早期收敛（前 20% 训练步）上的差异，量化锚点奖励的加速倍数。★★
    提示
    记录达到 50% 成功率的步数；预计纯 GAIL 方差大且起步慢，锚点版显著更稳，但注意最终上限是否被锚点"带偏"。

小结

  • IRL 从演示反推奖励；奖励不可辨识的根源是"势函数等价类 + 常值平移"，任何算法都必须注入额外偏好。
  • 最大熵 IRL 的梯度 = 专家特征期望 − 策略特征期望：让专家常去的地方涨价、策略常去的地方降价，直到分布对齐。
  • GAIL 用判别器把这个匹配做成对抗博弈：D 分"专家 vs 策略"，策略奖励 −log(1−D)；无需显式奖励模型。
  • 训练健康度看判别器准确率（0.6–0.8）；过强就降 lr/加平滑/加正则，过弱就加大容量与 batch。
  • 工程四件套：演示口径一致、按轨迹采样、奖励滑动标准化、任务指标与模仿奖励双轨监控。
