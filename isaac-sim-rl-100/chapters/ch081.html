第四篇 · 控制与优化

同样的任务，用一半的电：本章讲清机械功率与 CoT 的账怎么算、能量如何"泵入和回收"，再落到奖励设计与无源能量整形，把省电变成可以测量、可以优化的目标。

  • 主题：能耗度量 / 能量整形与省电奖励
  • 相关组件：Isaac Sim / Isaac Lab / PPO / 无源控制
  • 预计学时：60 分钟
  • 前置章节：第 080 章

学习目标

  • 会计算与解读三个能耗指标：机械功率 τ·q̇、电气功率估计 I²R、运输成本 CoT = E/(m·g·d)。
  • 理解能量在机器人系统里的四个去向（势能、动能、摩擦、电热），以及哪些理论上可回收。
  • 掌握无源性与能量整形：用 H = 动能 + 势能 与"泵能项 × 能量误差"实现摆的起摆，理解阻尼注入。
  • 会设计能量感知的 RL 奖励：只罚"正向机械功率"、锚定任务回报、防"静止最省"类作弊。
  • 会画"速度-能耗"曲线（CoT vs 速度），解释为什么行走机器人在某个速度段最省电。

背景与动机

前面八十章的目标几乎都是"完成任务"：更快、更准、更稳。但真机还有一条硬约束：电量。四足机器人的续航常是 1–2 小时，工业机械臂的能耗直接进电费与散热预算，外骨骼与假肢的省电更是决定"能不能穿戴一整天"的核心指标。把能耗当二等公民，训练出的策略往往有惊人的浪费：关节之间"打架"（一个输出正扭矩、另一个同时对抗）、步态里多余的加速-刹车循环、以及把重力做功白白烧在刹车电阻上。

能量优化不是"把速度降到零"，那样当然省电但任务失败。它的核心是两条路线：控制层面用无源性与能量整形，让系统利用自然动力学（像荡秋千一样"顺势而荡"）；学习层面把可测量的能耗量写进奖励，让 RL 在保持任务成功率的前提下搜索省电行为。本章先讲清能量的会计学（怎么量），再讲两种优化通道（怎么改），最后给出验证协议，毕竟"省电"这种承诺，必须能被电表验证。

核心原理

1. 能量的会计学：三个层次的度量

最基础的是机械功率：每个关节的机器人力矩乘角速度，Pm = τ·q̇。符号有物理含义：P>0 表示电机在做正功（电池放电），P<0 表示关节在"被反拖"（理论上可回馈，但大多数驱动器只是把它烧掉）。对整机求和时间积分，就得到一次任务的机械功 Em。

更接近电表的是电气侧估计：电机电流与铜损。仿真里常用扭矩近似电流：Pe ≈ Σ(τ²/kt²)·R，或粗略写作 τ² 的惩罚。它抓住了机械功率漏掉的一项：静力保持，关节不动时 τ·q̇=0，但电机堵转电流照样发热，这部分只有电流项能看见。

CoT = E / (m·g·d)　（无量纲运输成本：走单位距离、单位质量所需的能量） 人步行 CoT≈0.2；轮式机器人 <0.1；足式机器人常见 0.5–3，优化空间巨大

CoT 是可比较的"血压计"：不管机器人多点大、走多快，换算出无量纲数字才能横向比较、才能设优化目标（例如"CoT 降到 0.8 以下"）。注意它适合评估移动距离类任务；机械臂类任务更适合用"每次任务操作的能量"（焦耳/次）与"保持姿态的功率"（瓦）分开报告。

2. 能量去哪了：四个去向与可回收性

去向形式可回收性
重力势能mgh 抬高质心/负载可回收（放低时正功变负功，若有回馈电路）；否则制动烧掉
动能½mv² 加减速同上；频繁加减速是最大浪费源
摩擦/阻尼关节与地面摩擦热不可回收（只减不省：减少不必要的运动即可减少）
电热 I²R电机铜损，正比扭矩平方不可回收；扭矩尖峰是主要贡献者

由此推出省电的两个方向：不做不必要的加减速与做功（步态周期里减少急停急起），以及让高扭矩时刻远离高速度时刻，因为 P=τq̇，大扭矩乘大速度是"双高"浪费点，而 I²R 只关心扭矩大小。观察一个未优化四足步态的能量曲线常会看到：着地瞬间的冲击与高频微调占据了大部分电热损耗，这正是"能量整形"和"奖励塑形"要打击的目标。

3. 无源性与能量整形：荡秋千的数学

以倒立摆起摆为例（人类荡秋千的抽象）：系统总能量 H = ½I·q̇² + mgl(1 − cos q)（以竖直向下为 q=0、以该处为零势能点；竖直向上处 H = 2mgl，这正是起摆到顶所需的能量 Hd）。无源性的直觉是：系统的"能量账本"H 只通过控制输入与耗散改变；只要控制律保证 H 有界、耗散非负，系统对"外部假设"的依赖就被断掉了，这是比"调参稳定"更强的稳定性概念。能量整形控制律：

u = k · (Hd − H) · q̇　（能量误差 × 速度：把控制输入设计成"泵"） H < Hd 时 sign(u)=sign(q̇)：顺着运动方向加力，能量增加；H > Hd 时反向，能量回落

为什么乘 q̇？因为"往系统里注入能量"的唯一有效方式是沿速度方向施加力（功率 = 力×速度）。这正是荡秋千的节奏：每次都在身体摆动的同向时刻用力蹬，这就是"泵"。当 H 接近目标 Hd（起摆到竖直所需能量）时自动停止泵能，再叠加阻尼项把摆稳定在顶上。这个例子虽小，但思想贯穿整个省电设计：利用系统自身的动力学完成大部分工作，控制只负责补差与耗散。

4. RL 能量奖励：罚什么、不罚什么

惩罚项形式效果与副作用
总扭矩平方−w·Στ²降电热损耗；但惩罚"必要的支撑扭矩"（站立也要发力）
正向机械功率−w·Σmax(0, τ·q̇)只罚做正功的一侧，允许并被吸引到"回收侧"运动，推荐
绝对功率−w·Σ|τ·q̇|连回收侧一起罚，等于鼓励"少动不代表省电"；不推荐
CoT / 距离−w·E/(d+ε)直接优化核心指标；但会在低速时爆炸（分母），需加 ε 与限幅

三条纪律：一，任务回报必须锚定，能量项只做"同分情况下的偏向"，权重按"任务成功的奖励 ≈ 全程能量惩罚累积的 5–10 倍"标定，否则策略学会"原地不动最省电"；二，用正向功率，回收侧（负功率）是好朋友，别一起罚；三，量纲归一化，机械功率的瞬时峰值可能上千瓦，先除以"名义功率"再进奖励，防止个别尖峰主导（用截断或 tanh 压缩）。

5. 速度-能耗曲线：没有"越慢越省"的单调律

步行、奔跑类任务里 CoT 对速度呈 U 形：太慢时"每步的固定代价"（抬腿、保持平衡的微调功率）均摊到距离上偏大；太快时空气阻力与冲击损耗增长过快。中间存在一个"最省速度"（人步行约 1.3 m/s 附近）。所以能量优化的正确目标是给定的速度设定点下最小化 CoT；"慢下来"这种笼统目标会把速度与效率混为一谈。训练时固定速度指令，评估时扫速度画曲线，曲线的谷底就是这台机器的最经济工作点。这条曲线本身也是很好的工程交付物：告诉部署团队"这台机器按 1.0 m/s 跑最划算"。

实现思路与设计

场景：四足机器人以指令速度行进（0.5/1.0/1.5 m/s 三档），基线策略 vs 能量感知策略。实现五步：

  1. 计量模块：每步读 12 个关节的 τ 与 q̇，计算逐关节机械功率与正向功率之和、扭矩平方和；按时间积分成一次任务的 Em、Ee；距离按躯干实际位移算，最后输出 CoT。计量先于优化，没有可靠的电表，任何省电宣称都是故事。
  2. 奖励设计：r = rtask（速度跟踪 + 姿态 + 存活）− 0.001·Σmax(0, τ·q̇)/Pnominal − 0.0002·Σ(τ/τmax)²。两个惩罚分别对"正功"与"电热"，权重按前 5000 步的能量项累积 ≈ 任务项 1/10 标定。
  3. 训练配置：从基线策略热启动（继续训练 20k 迭代）；其余超参与基线一致；监控能量项占比曲线（应稳定在 5–10%，漂到 20% 以上说明任务正在被牺牲）。
  4. 速度扫描：三个速度档各训一个策略（或一个策略带速度指令输入），评测时每档跑 20 次 20 米，记录 CoT 与成功率，画出 U 形曲线，标注谷底速度。
  5. 行为对照：录两段同速度步态对比，统计"双高浪费"（|τ·q̇| 同时大的时刻占比）与扭矩尖峰数量（第 99 分位扭矩），量化能量整形到底改了什么。
设计思维：为什么从基线策略热启动？

省电优化是"在会走路的基础上跳得更省"，而学会走路本身需要大量探索（第 044 章）。从头联合训练时，早期策略连站都站不稳，能量惩罚只会压缩它的探索空间，经常两件事都做不好。热启动让任务能力已经存在，能量梯度只需微调步态参数（步频、步幅、躯干起伏），收敛快 3–5 倍且成功率不掉。多目标优化的一条经验：先让主目标稳，再引入副目标微调，与第 072 章成功奖励的"锚定"原则同源。

关键代码与解读

片段 1：能量计量，机械功率、电热估计与 CoT

import numpy as np

class EnergyMeter:
    """逐环境能量账本：机械功率按符号分开记、电热按扭矩平方估、CoT 按位移算。"""
    def __init__(self, n_envs, kt=0.05, resistance=0.5, dt=1.0 / 60.0):
        self.n, self.kt, self.R, self.dt = n_envs, kt, resistance, dt
        self.m_work_pos = np.zeros(n_envs)     # 累计正功（电机做正功，电池放电）
        self.m_work_neg = np.zeros(n_envs)     # 累计负功（被反拖，理论可回收）
        self.e_heat = np.zeros(n_envs)         # 累计铜损估计
        self.last_pos = None                   # 上一次躯体位置，用于算位移

    def update(self, torque, qvel, base_pos):
        # 逐关节机械功率 P = τ·q̇（[N, D]），符号分开累计：回收侧不能被"抹掉"
        p = torque * qvel
        self.m_work_pos += np.maximum(p, 0.0).sum(axis=1) * self.dt
        self.m_work_neg += np.minimum(p, 0.0).sum(axis=1) * self.dt   # 负值累计（电能回馈潜力）
        # 铜损 I²R 估计：I ≈ τ/kt，按扭矩平方近似；站立保持时机械功率为零但这项不为零
        current = torque / self.kt
        self.e_heat += (current ** 2 * self.R).sum(axis=1) * self.dt
        if self.last_pos is None:
            self.last_pos = base_pos.copy()
        distance = np.linalg.norm(base_pos - self.last_pos, axis=1)   # 本步躯体位移
        self.last_pos = base_pos.copy()
        return distance

    def cot(self, distance_total, mass=12.0, g=9.81):
        e_total = self.m_work_pos + self.m_work_neg + self.e_heat   # 净消耗 = 正功 − 回收 + 铜损（负功本身为负值）
        return e_total / (mass * g * np.maximum(distance_total, 1e-3))

解读：这个模块的设计最值得注意的是把正功与负功分开累计：合并成一个净值会掩盖两件关键事实，"回收了多少"（负功绝对值大小）与"浪费了多少"（正功大但没被利用）。前者是硬件能力（有没有回馈电路），后者是步态质量（有没有做多余的正功）。铜损项 τ²/kt²·R 看似粗糙，但它抓住了机械功率漏掉的静力保持发热；如果仿真平台能提供电机电流或有效功率接口，优先用真实值，这里的估计只作为无电流数据时的替代。cot() 里"净消耗 = 正功 − 回收 + 铜损"的口径要在全项目里统一：不同口径算出的 CoT 可能差 2 倍以上，跨团队对比时先对口径。位移累计用"逐帧位移之和"；起终点直线距离会低估绕行路程，绕圈行走和直线行走的能耗应可比。

片段 2：能量感知奖励合成（锚定 + 限幅 + 记账）

import numpy as np

class EnergyAwareReward:
    """任务基线奖励 + 两项能量惩罚；限幅与锚定是防作弊的核心。"""
    def __init__(self, w_mech=0.001, w_heat=0.0002, p_nominal=200.0, tau_max=87.0):
        self.w_mech, self.w_heat = w_mech, w_heat
        self.p_nominal, self.tau_max = p_nominal, tau_max

    def __call__(self, r_task, torque, qvel):
        # 正向机械功率：只罚"做正功"的一侧；回收侧（负功率）豁免，相当于隐含鼓励
        p_pos = np.maximum(torque * qvel, 0.0).sum(axis=1)
        mech_term = self.w_mech * p_pos / self.p_nominal
        # 铜损代理：扭矩平方；用 tau_max 归一后天然落在 0–1 量级，无需再调
        heat_term = self.w_heat * ((torque / self.tau_max) ** 2).sum(axis=1)
        # 限幅：单步惩罚不超过任务奖励的 30%，防异常尖峰把学习带偏（截断不改变常态梯度）
        penalty = np.minimum(mech_term + heat_term, 0.3 * np.abs(r_task) + 1e-6)
        total = r_task - penalty
        # 台账：分项返回，训练日志里分别画；"任务被牺牲"应能立刻看出是哪项过大
        return total, {"task": float(np.mean(r_task)), "mech": float(np.mean(mech_term)),
                       "heat": float(np.mean(heat_term))}

解读：三项工程设计的动机各不相同。只罚正向功率给了策略一个明确的偏好：负功率（回收侧）不受罚，策略自然倾向于"利用被拖拽的相位"，远离两根关节互相顶牛的动作。限幅到任务奖励的 30% 是对"能量项突然变大"的防御：策略在早期偶尔做出高功率动作（例如落地冲击）时，不设限的单步惩罚可能比任务回报大 10 倍，直接把该经验变成"禁忌"；限幅保证能量项永远只当"修饰"，不会抢占"主导"。分项台账让诊断闭环：如果训练后期成功率下滑，看台账就知道是 mech 项在涨（步态变得保守）还是 heat 项在涨（扭矩尖峰增多），进而选择调权重还是查步态。参数标定的实操：先把两个权重设为零跑几千迭代记录各项的自然量级，再按"稳态惩罚 ≈ 任务回报的 5–10%"反推 w，不要凭空拍系数。

片段 3：能量整形，摆的起摆（泵能 + 阻尼注入）

import numpy as np

class EnergyShapingController:
    """无源能量整形：u = k·(Hd − H)·q̇ − b·q̇。
    第一部分是"泵"（按能量误差与速度注入或抽出能量），第二部分是阻尼。"""
    def __init__(self, m=1.0, l=0.5, g=9.81, k=3.0, b=0.5, hd=None):
        self.m, self.l, self.g = m, l, g
        self.I = m * l ** 2                      # 单摆绕轴惯量
        self.k, self.b = k, b                    # 泵能增益与阻尼
        self.Hd = 2 * m * g * l if hd is None else hd  # 目标能量：摆到竖直向上所需

    def energy(self, q, qd):
        # H = 动能 + 势能；取竖直向下为 q=0 时 H(0,0)=0，向上能量为正
        return 0.5 * self.I * qd ** 2 + self.m * self.g * self.l * (1.0 - np.cos(q))

    def step(self, q, qd, dt=0.001):
        H = self.energy(q, qd)
        delta = self.Hd - H                      # 能量误差：还差多少能量才够起摆
        u = self.k * delta * qd                  # 泵能项：方向与速度同号则注入、反号则抽出
        u -= self.b * qd                         # 阻尼注入：H 到位后把多余动能耗散掉
        # 物理近似积分（真实系统用解析模型/仿真步进）
        qdd = (u - self.m * self.g * self.l * np.sin(q)) / self.I
        qd += qdd * dt
        q += qd * dt
        return q, qd, {"H": H, "u": u}

解读：三行控制律装下了无源控制的核心思想。u = k·(Hd−H)·q̇ 是"泵"：当能量不足且摆动方向为正（q̇>0）时给正力矩，顺势加速；方向为负时同理，功率 u·q̇ = k·(Hd−H)·q̇² ≥ 0，即能量误差为正时控制器永远只在注入能量，绝不"跟身体对着干"；当 H 超过 Hd 后系数变负，控制器自动转为抽取（刹车）。阻尼项 −b·q̇ 保证能量到位后动能不失控（注入停止、多余能量被耗散），它对应"无源性"里耗散性的数学条件，也是让系统停在目标态、不至于永远荡下去的关键。练习里可以让摆稳定在 q=π 附近后观察仿真里能量曲线 H(t)：你应该看到它像楼梯一样爬到 Hd 附近然后被阻尼磨平。这段代码演示的是"控制层的省电"：没有用大扭矩硬把摆拽起来（那会消耗数十倍能量），改为按自然频率一点点泵能，省电的极致就是少做功、多利用动力学。

常见坑

  • 用 |τ·q̇| 当惩罚：把回收侧（负功率）也一起罚，策略丧失"被拖带"利用自然动力学的空间，步态变得僵硬耗电。症状是步态看起来"用力缩小但更频繁"。修复：只罚正向功率；如果硬件没有回馈电路，回收侧无法省电是硬件事实，但也不该额外惩罚。
  • 能量权重过大导致"静止不动"：策略发现"不动"的能耗最低并锁死在低速/静止行为。症状是成功率下滑但 CoT 数字好看。修复：任务回报锚定（能量项 ≤10%）；把 CoT 的分母加 ε 并限幅；验收先看成功率再看 CoT。
  • 只测机械功率、忽略静态发热：站立保持的堵转电流没被计量，优化出的策略"站着省电、走着废电"或者反过来。症状是仿真 CoT 与真机电池电流对不上。修复：加入 I²R 估计；有条件时直接记录电池侧功率做回归验证。
  • 跨速度比较 CoT 不看基准：拿 0.5 m/s 的 CoT 和 1.5 m/s 的 CoT 直接比大小。症状是得出"慢速策略更优"的假结论。修复：先画速度-CoT 曲线再比；优化目标永远是"同一速度设定点下更低"。
  • 仿真摩擦与真机差异污染结论：仿真里摩擦小，回收侧贡献被高估，迁移到真机发现省电效果打折。症状是仿真省 20%、真机只省 5%。修复：用第 067 章的辨识校准摩擦；比较优化版与基线版在同一模型下训练、真机两端同测，避免跨系统对比。

练习与思考

  1. 给摆的起摆控制器记录 H(t) 曲线，标出"泵能阶段、切换点、阻尼沉降"三段，并解释 k 与 b 各自控制哪一段。★
    提示
    k 决定能量爬升速度与超调风险；b 决定接近 Hd 后的收敛快慢。b=0 时摆会永远接近但大幅振荡。
  2. 把能量奖励权重从 0.001 调到 0.01 与 0.0001，画出三组训练的"CoT-成功率"散点，说明锚定原则的边界在哪。★★
    提示
    0.01 可能开始牺牲成功率换 CoT（作弊苗头）；0.0001 效果几乎不可见。找"成功率不掉的最大 CoT 改善"。
  3. 对比"只罚扭矩平方"与"只罚正向功率"两种策略的步态视频与 CoT，解释两者激励出的行为差异。★★
    提示
    扭矩平方版倾向减少主动发力（可能步频变慢、姿态摇晃），正功率版倾向减少净做功（可能步幅变大、利用势能摆动）。
  4. 设计速度扫描实验：0.4/0.7/1.0/1.3/1.6 m/s 五档，画 CoT 曲线找谷底，与文献中人步行的 1.3 m/s 对比讨论。★★★
    提示
    每档 20 次 × 20 米；CoT 谷底附近速度的策略通常步频稳定、着地冲击小；谷外策略要么步幅过大要么步频过快。
  5. 把回收侧从计量里去掉（净消耗 = 正功 + 铜损），重估 CoT 并讨论"有/无回馈电路"两种硬件下优化目标的差异。★★
    提示
    无回馈时硬件把负功率烧成热，能量账本更差；仿真奖励此时也应反映"硬件事实"（惩罚包含制动损耗），否则优化方向不落地。

小结

  • 三个度量：机械功率 τ·q̇（正负分开记）、I²R 电热估计、CoT = E/(m·g·d)；计量口径必须全项目统一。
  • 能量四个去向：势能/动能（可回收）、摩擦（减无可减只减不用）、电热（扭矩尖峰最伤）；"双高"（大扭矩 × 大速度）是重点打击对象。
  • 无源与能量整形：u = k(Hd−H)q̇ 是"泵"，沿速度方向注入能量；阻尼项负责耗散；利用自然动力学比硬拽省几十倍。
  • 能量奖励三纪律：任务锚定（能量项 ≤10%）、只罚正向功率、量纲归一化加限幅；防"静止最省"类作弊靠成功率验收。
  • 速度-CoT 曲线是 U 形：优化目标是"同速度下更低"，交付物里应明确最经济工作点。
