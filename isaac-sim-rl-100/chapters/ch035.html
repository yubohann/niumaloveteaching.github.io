第 035 章：实现运动规划与强化学习结合

让"全局最优的路线"与"局部灵活的反应"接力：RRT 类规划器管绕障，RL 管接触与扰动，四套混合架构一次讲清。

  • 主题：任务实现 / 规划与学习的混合架构
  • 相关组件：Isaac Sim、OMPL 系规划接口（概念）、Stable-Baselines3
  • 预计学时：55 分钟
  • 前置章节：第 034 章

学习目标

  • 说清规划与学习的互补性：规划强在全局可行与几何约束，弱在接触与不确定性；RL 恰好相反。
  • 理解 RRT 类采样规划器的工作原理：构型空间搜索、概率完备、路径后处理，以及它在仿真工作流里的接入方式。
  • 掌握四种混合架构：规划器当教师、路点 + RL 跟踪、残差 RL、规划器的势场奖励。
  • 会实现"路点观测"与"手递手切换"：自由空间段跟规划、接触段交给 RL 的判定与切换逻辑。
  • 能评估混合架构的收益：成功率、轨迹长度、规划调用频率与失败归因。

背景与动机

到这一章，你手里已经有了两个"会走路的部件"：第 034 章的 IK（局部、能到点、不会绕障）和从 017 章一路练来的 RL（能学、能适应、但不知道全局几何）。把它们放进同一个任务，短板立刻显形：纯 IK 的机械臂会径直穿过障碍物；纯 RL 的机械臂在长距离绕障任务里样本效率极低（几十万步才能背下障碍的几何）。

经典机器人学给出的答案是路径规划（motion planning）：在构型空间里搜一条无碰路径，这是纯几何搜索，不学也能做对。但它有三条硬伤：对接触无能为力（接触即碰撞，规划器只会绕开）、对不确定性迟钝（执行偏差不会自动纠正）、对约束堆叠（推、拧、插）没有模型。本章的主线：规划管"从 A 到 B 怎么绕"，RL 管"最后几厘米怎么磨"。理解这条分工线，你就能设计出比任何单一方法都强一个量级的系统。

核心原理

1. RRT 类规划器：在构型空间里"撒点连线"

规划=搜索。搜索空间是构型空间（C-space）：机械臂的每个位形是一个 n 维点。RRT（Rapidly-exploring Random Tree）的循环只有三步：随机撒一个构型点 → 找树上离它最近的节点 → 朝它长出一步（并做碰撞检查）。树就这样向空间的未探索区域生长。它不保证最优，但保证"只要解存在，点够多就找得到"（概率完备，probabilistically complete）。RRT\* 在长出一步后做"换父节点"的剪枝，让解逐步逼近最优；实践中更常用的是"快速 RRT + 路径平滑后处理"：

原始路径 q0 → q1 → … → qk（带锯齿） → 捷径平滑（shortcut） → 时间参数化（速度/加速度约束） 平滑把锯齿路径换成短直线段；时间参数化给每段配速度曲线，否则直接跟点会速度突变

仿真工作流里的接入方式：用宿主提供的规划组件（Isaac 生态里围绕 OMPL 的规划接口、或 cuRobo 类的 GPU 规划库），输入"起始构型、目标构型、碰撞对象集合"，输出构型路径与时间参数化。注意规划一次通常要几十到几百毫秒，绝不能每控制步调用，应当作为"事件"：回合开始、目标更新、路径被阻挡时调用。

2. 规划的边界在哪里

  • 接触不可规划：规划的定义域是"无碰"，而抓取、推动、插拔的本质是受控接触。让规划器"贴着物体推"在一开始就是矛盾的。
  • 模型不确定性：规划基于几何状态，执行时物体可能被动过、标定有偏差；重规划能处理"大偏差"，小偏差（毫米级）交给反馈控制/RL。
  • 任务规格缺失：规划器不知道"什么时候该停下抓取"，任务层的语义得由你的逻辑或 RL 提供。

反过来，RL 的短板是规划的长处：探索长距离路径 = 用采样拟合几何，效率极低；而 RL 的长处恰是规划的死角：接触、扰动、容差。混合架构的设计原则：让每种方法只做它擅长的、且把接口做窄，接口越窄（如一个路点序列、一个残差动作），系统越可测。

3. 四种混合架构的谱系

架构规划器角色RL 角色适用
A. 规划当教师生成无碰轨迹BC 预训练 + RL 微调需要专家数据又不想遥操作
B. 路点 + RL 跟踪回合开始生成路点序列在线跟踪路点、处理扰动长距离移动 + 局部灵巧
C. 残差 RL每个控制步给"参考动作"输出修正量叠加在规划动作上需要保持规划性能下限
D. 势场奖励提供路径作为"进度尺"在奖励里加"沿路径前进"项教 RL 绕障、加速收敛

四者可以叠加：B + C 是工业界常见的"规划跟到接触区、RL 接管精调"。选择判据：规划能覆盖的比例越高，架构越靠 B/C；任务越接触密集、规划越不可用，越靠 A/D 让 RL 独立成长。

4. 手递手切换：何时从规划切到 RL

混合系统里最微妙的机制是"交接"。两种触发方式：

  • 空间触发：末端进入"接触区"（距目标 < 10 cm）或路径耗尽时切换。可预测、可测试，但阈值附近的切换抖动要处理（滞回：进入用 10 cm、退出用 15 cm）。
  • 事件触发：接触检测（第 030 章）第一次确认接触时切换。更语义化，但需要接触检测稳定可靠。

切换时的状态衔接是失败高发区：RL 接手时策略看到的状态（相对目标位姿、接触力）必须与训练时的初始状态分布接近，否则"接手即崩"。对策：训练 RL 时就用"规划器的结束状态 + 随机扰动"做初始状态分布（domain randomization on start states），让交接口成为训练分布内的常见点。这是第 021 章域随机化思想在系统集成层的复用。

5. 残差行动的数学形式

最紧凑的混合形式是残差 RL：

at = atplan + k · atRL， aRL ∈ (−1, 1)n， k 为残差增益（如 0.1） 规划给基准动作，RL 只学"修正量"；k 控制修正幅度上限，系统的行为下限由规划保证

残差结构有两个漂亮性质：(1) 性能下限，RL 全零时系统退化为纯规划，不会比规划更差（除非学坏，所以奖励设计要保证"修正不亏"）；(2) 小输出空间，策略只需学 ±k 范围内的修正，探索空间小、样本效率高。代价是如果规划的基准动作系统性错误（模型偏差大），残差量不足以扳回来，此时要么修规划，要么退回架构 A/D。实践判据：先用纯规划跑评估，成功率 > 60% 时残差 RL 是高效选择；低于 40% 时应先让 RL 独立或换教师。

6. 数值算例：时间参数化与规划开销预算

规划器输出的构型路径只负责几何，要变成可执行的轨迹还需要时间参数化。以两个路点之间的一段直线段为例：段长 L = 0.30 m，按关节限速折算的末端速度上限 vmax = 0.25 m/s，加速度上限 amax = 1.0 m/s²。梯形速度剖面的计算过程：加速段距离 da = vmax²/(2amax) = 0.03125 m，加速时间 vmax/amax = 0.25 s；两端加减速共占 0.0625 m，剩余 0.2375 m 匀速段耗时 0.95 s，总时间 1.45 s。若把 vmax 提到 0.5 m/s 而加速度不变，加速段距离涨到 0.125 m（按速度平方增长），但总时间反而缩短到 1.10 s。这组数字说明"规划得快"与"跟得住"的折中点在加速度侧：速度上限翻倍时，加速段浪费按平方增长，距离足够长时总时间仍下降，距离很短时（L 接近 2da）速度上限完全失效、总时间由加速度决定。时间参数化的输出（每段的时刻表）还有第二个用途：路点跟踪器用它估计"按当前速度能否在预算内到达"，据此提前加速；等到落后再补，时间预算已经失守。

规划开销另算一笔账：单次规划耗时 150 ms，控制周期 16.7 ms（60 Hz）。把规划塞进控制循环，单步耗时变成 167 ms，控制频率跌到约 6 Hz，训练吞吐与动作平滑同时受损；把规划作为回合级事件、每 500 个控制步重规划一次，平均每步只分摊 0.3 ms，占比约 2%。同样的计算量，摆放位置不同，摊到每个控制步的开销相差 500 倍（150 ms 对 0.3 ms），"规划按回合级事件调用"这句话有了定量版本。若场景需要更高频的重规划（动态障碍靠近），正确的方向是换用更快的规划实现或增量式规划（复用上次树的样本）；缩短重规划间隔硬扛只会让每个控制步都背上规划开销。

实现思路与设计

本章按"架构 B + C 组合"落地：回合开始规划一条路点序列，自由空间由轨迹跟踪器跟随，进入接触区后 RL 接管精调，并用残差形式保持规划的行为下限。五个实现模块：

  1. 规划模块：封装"起始构型 → 目标构型"的规划调用；只在 reset/目标更新时触发；规划失败（找不到路）时退回直线接近并记录事件。
  2. 路点跟踪：把构型路径抽稀成 M 个路点（如 8–16 个）；跟踪器（IK + 限速）负责逐点跟随；到达阈值 3 cm 切下一个点。
  3. 观测表达：给 RL 的观测含"当前路点相对位姿、路点序号/总进度、接触标志、末端—目标相对位姿"；路点序列作为观测的一部分让策略知道"后面还有没有"。
  4. 切换逻辑：进入接触区（末端—目标距离 < 10 cm）且接触标志为真 → 切 RL；用 15 cm 退出阈值形成滞回。
  5. RL 形态：残差动作 a = atrack + 0.1·aRL；奖励沿用任务奖励 + 残差幅度小惩罚。
设计点推荐值理由
路点数 M8–16太少转弯失真；太多观测维度虚高
路点到达阈值3 cm太严会卡在路点前反复；太松会切太早积累误差
切换距离进入 10 cm / 退出 15 cm滞回防抖动；阈值对齐接触区的物理尺度
残差增益 k0.1（关节增量的 10%）修正能力与"不破坏规划"的平衡
重规划条件偏差 > 15 cm 或阻挡事件重规划是事件不是周期任务；门槛保证不频繁打断
规划超时200 ms超时=规划失败，走退化路径并打点
设计思维：把"谁负责哪段"写进观测

切换架构最常见的事故是"RL 不知道自己在跟路点还是已到接触区"，策略在两种模式间行为矛盾。对策是把模式标志（跟路点/精调）作为一维观测显式给出：策略可以学着"模式=跟路点时尽量小修正、模式=精调时全力"。这与第 032 章"等级进观测"是同一条设计原则：凡是影响最优行为的隐藏变量，都在观测里给它一票。反过来，如果两个模式的行为差异不大，就说明架构可以简化，观测标志也提供了一个"是否需要切换"的检测手段。

关键代码与解读

片段 1：规划调用与路点抽取

def plan_waypoints(planner, start_conf, goal_conf, max_waypoints=12):
    """回合级事件：规划构型路径并抽稀成路点。绝不放进控制循环内"""
    path = planner.plan(start_conf, goal_conf)      # 返回 N 个构型点或 None（失败）
    if path is None:
        return None                                  # 调用方走退化路径：直线接近 + 打点记录
    # 抽稀：等间隔取点。路点是"里程碑"；逐帧跟踪交给控制器
    idx = torch.linspace(0, len(path) - 1, steps=max_waypoints).long()
    wps = [path[i] for i in idx]                    # 首尾必含：第一个是起点、最后是目标构型
    return wps

class WaypointTracker:
    """路点跟踪器：当前路点到达 3 cm 就切下一个；耗尽则进入交接准备"""
    def __init__(self, waypoints, tol=0.03):
        self.wps, self.tol = waypoints, tol
        self.idx = 1                                # 从第二个路点开始（第一个是当前位形）

    def current_target_conf(self, cur_conf):
        while self.idx < len(self.wps) - 1 and \
              torch.linalg.norm(cur_conf - self.wps[self.idx]) < self.tol:
            self.idx += 1                            # 到达阈值后才推进：防"路点竞速"
        return self.wps[self.idx]

    def progress(self):
        return self.idx / (len(self.wps) - 1)        # 0→1：给观测的进度标量

解读：路点层有三个防坑细节。(1) 抽稀到 12 个点：RRT 输出可能几百个密点，全塞进观测既无必要又稀释学习信号；等间隔抽 12 个点保留"里程碑"语义，轨迹细节由控制器采样时补足。(2) 到达阈值推进（while 循环）：如果某帧跨过了两个路点（高速移动），循环一次性跳过，否则策略会"回头"去够已经被甩在身后的路点，产生折返。(3) 进度标量：idx/(M−1) 是给 RL 观测的"完成度"，与第 032 章的成功率、第 031 章的 goal 一样，是让策略"知道自己在哪"的关键状态量。跟踪器状态（idx）必须随回合重置，又一个"跨步状态入重置清单"的实例。

片段 2：手递手切换与观测组装

class HybridController:
    """混合控制：跟路点 → 接触区切换 → RL 精调；带滞回防抖动"""
    def __init__(self, tracker, ik, enter_dist=0.10, exit_dist=0.15):
        self.tracker, self.ik = tracker, ik
        self.enter_dist, self.exit_dist = enter_dist, exit_dist   # 滞回双阈值
        self.mode = "track"                        # 初始模式：自由空间跟踪

    def build_obs(self, cur_conf, cur_pose, target, contact):
        wp = self.tracker.current_target_conf(cur_conf)          # 当前路点（构型空间）
        rel_wp = wp - cur_conf                     # 相对路点差：策略需要"往哪偏"
        rel_goal = target - cur_pose               # 末端—目标相对位姿：精调阶段的核心信号
        mode_flag = torch.tensor([1.0 if self.mode == "rl" else 0.0])
        # 模式显式进观测：影响最优行为的隐藏变量必须给策略一票（本箱"设计思维"）
        return torch.cat([rel_wp, rel_goal, [self.tracker.progress()],
                          contact.float(), mode_flag])           # 拼接成策略输入的字典项

    def switch(self, end_effector, target, contact):
        d = (end_effector - target).norm(dim=-1)   # 末端到目标的距离
        if self.mode == "track":
            self.mode = "rl" if (d < self.enter_dist) and contact else self.mode
            # 双条件：进入接触区 且 检测到接触；只用距离会在未真正接触时误判
        else:
            self.mode = "track" if d > self.exit_dist else self.mode
            # 退出只在"离开足够远"时发生：滞回死区内的模式保持稳定
        return self.mode

解读：切换器是混合架构里最需要"防抖"的部件，三处设计都值得学。(1) 双条件进入：只看距离 10 cm 就交给 RL，会在"还没真正碰到"时提前切换，RL 的接触策略在空中的表现没训练过；加上接触标志后，"贴着目标的手"才是 RL 的上班时间。(2) 滞回退出：模式切换有成本（RL 接手要重新稳定），进入阈值 10 cm 与退出阈值 15 cm 之间是"保持现状"的死区，和第 032 章课程的滞回是同一种控制抖动的手法。(3) 模式标志进观测：设计思维里讲的"隐藏变量给一票"在这里落地；mode_flag 让策略能学出"跟随时克制、精调时积极"的分段行为。另外注意 rel_wp 与 rel_goal 都给的是"相对量"：绝对构型/绝对位姿的数值范围太大且随任务场景漂移，相对量在归一化前后都稳定，这与第 029 章"力要转工具系"的动机一致：把观测组织成"策略直觉可读"的形式，是加速学习的一半。

片段 3：残差 RL 的动作组装

def hybrid_step(env, controller, policy, cur_conf, cur_pose, target, contact):
    """一个控制步的完整混合动作：跟踪器给基准，RL 给修正"""
    controller.switch(cur_pose, target, contact)      # 先定模式：观测构建依赖它
    obs = controller.build_obs(cur_conf, cur_pose, target, contact)

    # 基准动作：跟踪模式用 IK 追路点；RL 模式用 IK 追目标（"参考但不锁死"）
    if controller.mode == "track":
        base_target = controller.tracker.current_target_conf(cur_conf)
    else:
        base_target = target                          # 精调阶段：不再跟路点，直追目标
    a_base = controller.ik.solve(cur_conf, base_target)  # 关节增量基准（第 034 章）

    a_rl, _ = policy.act(normalize(obs), deterministic=False)   # 策略输出 (-1,1)^n
    k = 0.1                                           # 残差增益：修正幅度上限 10%
    a = a_base + k * a_rl * env.joint_delta_scale     # 组合动作：规划主导、RL 微调
    # k 太小（0.01）RL 学不动；k 太大（0.5）等于纯 RL；0.05–0.15 是常用带

    env.apply_joint_delta(a)                          # 积分 + 限位（第 025/026 章同款安全层）
    rew, done = env.step_reward(contact)              # 任务奖励 + 残差幅度小惩罚
    return obs, a_rl, rew, done

解读：残差结构把"规划的性能下限"与"RL 的上限能力"焊在一起。读三个关键词：a_base 是基准，它保证即使策略输出全零、甚至学坏了，系统行为仍接近规划（退化保障）；k=0.1 是残差频带，策略的探索空间被限制在基准动作 ±10% 的邻域内，第 026 章动作缩放讨论过的"探索半径"在这里由结构（k 的频带）设定，噪声只负责频带内的抖动；deterministic 在训练时用采样、评估时用确定性，与第 026 章纪律相通。一个容易被忽略的细节：RL 模式的基准动作选择。代码里精调阶段把 IK 的目标从"路点"换成"最终目标"，让基准自身也在收敛；如果没有这个切换，IK 停在最后一个路点不动，RL 的残差要独自完成最后 10 cm，超出 k 频带的修正能力，表现为"永远差一点"。残差幅度惩罚的权重建议 0.01 量级：它的作用是防止策略用满 ±k 乱动；修正本身仍被允许。

常见坑

  • 每控制步调用规划器：规划耗时几十到几百毫秒，把 60 Hz 控制循环拖成 5 Hz。症状：训练吞吐暴跌、动作抖动。修复：规划只在 reset/目标更新/阻挡事件时调用，路点序列缓存起来。
  • 路点当逐帧轨迹：直接把路点位置当每帧的关节目标，路点之间的"跳跃"造成速度突变。症状：机械臂抽搐式前进。修复：路点给跟踪器（IK/限速插值），控制器负责连续性。
  • 切换无滞回：模式在阈值边界反复横跳，两种控制策略高频交替。症状：日志中模式切换频率异常高、接触力振荡。修复：进入/退出双阈值 + 最短保持时间。
  • RL 训练分布与交接口不匹配：RL 只在"目标正前方"训练，实际接手时状态来自规划末尾（可能带偏差），分布外即崩。症状：混合系统成功率低于纯规划。修复：训练时用"规划终点 + 扰动"作为初始状态分布。
  • 规划器与仿真场景不同步：规划用的碰撞场景里没有随机化后的新障碍/大质量物体，规划出的路径在仿真里穿模。症状：碰撞事件、轨迹异常。修复：规划前把当前场景的障碍集合同步给规划器。

练习与思考

  1. 计算题：规划一次耗时 150 ms（单次），控制周期 16.7 ms。若"每步重规划"会怎样？若"每 100 步重规划一次"，规划开销占训练时间的多少？★
    提示
    每步重规划：单步时间变成 167 ms，控制频率跌到 6 Hz。每 100 步一次：平均每步多 1.5 ms，开销约 10%，这才是可接受的量级。
  2. 实验设计：对比"纯 IK 教师""RRT 教师""RRT+平滑教师"三种示教，用第 033 章的 BC 训练后比较成功率，解释差异来自轨迹的哪些性质。★★
    提示
    纯 IK 在绕障场景会撞（教师失败轨迹被过滤后数据变少）；RRT 原始路径锯齿大，BC 学到的动作抖动；平滑后轨迹动作连续，BC 最容易学。
  3. 实现题：给切换器加"最短保持时间"（模式切换后至少保持 20 个控制步不再切换），验证它对接触力振荡的抑制效果。★★
    提示
    监控指标：模式切换次数 / 回合、接触力方差。最短保持时间消除边界抖动，但太长会拖慢"该交不交"的响应。
  4. 消融实验：残差增益 k ∈ {0.02, 0.1, 0.3}，对比"最终成功率"与"早期学习速度"。解释为什么存在最优 k，以及它与"规划基准质量"的关系。★★★
    提示
    规划越好，最优 k 越小（几乎不需要修正）；规划越差，需要更大 k，但 k 太大失去"下限保障"。把纯规划成功率与最优 k 画在一张图上，趋势应该一目了然。
  5. 思考题：为什么说"规划 + RL"的分工本质是"几何先验"与"经验先验"的分工？请从状态空间覆盖的角度，解释混合系统为什么比纯 RL 样本效率高。 ★★★
    提示
    规划用几何知识直接跳过"学习绕障"所需的大量样本；RL 只在其剩余的不确定性（接触/扰动/容差）上采样，训练分布被大幅收窄。

小结

  • 规划强在全局几何与可行性，弱在接触与不确定性；RL 反之。混合的原则：让各自的"最强项"对接窄接口（路点/残差）。
  • RRT 类算法在构型空间采样搜索，概率完备；工程链路是"规划 → 捷径平滑 → 时间参数化 → 跟踪"。
  • 四种架构 A 教师 / B 路点跟踪 / C 残差 / D 势场奖励；B+C 组合（跟到接触区、RL 精调）是通用主力。
  • 手递手切换三件套：接触/距离双条件进入、滞回退出、模式标志进观测；RL 训练初始分布要覆盖交接口。
