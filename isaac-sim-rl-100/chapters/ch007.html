第一篇 · 仿真环境与训练框架

第 007 章：读取传感器数据

让策略"感知"自己和世界：读关节状态包、挂载 IMU、接上接触传感器，并学会用归一化、滤波与坐标系约定把原始读数整理成可靠的观测。

  • 主题：观测设计 / 本体传感器数据读取
  • 相关组件：Isaac Sim（关节状态、IMU、Contact Sensor）
  • 预计学时：50 分钟
  • 前置章节：第 006 章

学习目标

  • 理解 Isaac Sim 传感器的读取模型：传感器是挂在场景树上的 prim，数据按物理步更新，"读"到的永远是最近一次步进后的值。
  • 会读取并组织关节状态包（位置、速度、力矩），理解关节角的有界性与连续关节的特殊处理。
  • 会创建并读取 IMU（朝向、角速度、线加速度），说清加速度计测的是"比力"，并区分它与运动加速度。
  • 会使用接触传感器获取接触力/接触状态，并用指数滑动平均（EMA）抑制求解器带来的高频抖动。
  • 掌握观测打包的三条规范：单位统一、幅度归一化、坐标系统一；理解仿真特权信息与可部署信息的区别。

背景与动机

策略是根据观测做决策的函数：观测里没有的信息，策略永远学不会；观测里带有噪声或语义错误的信息，策略会学到错的映射。前面六章把"行动"的链路搭好了（加载、驱动、三种控制），本章开始搭"感知"的链路，先从最基础的本体传感（proprioception）开始：关节编码器、IMU、接触传感器。视觉、深度与激光这三类"外部感知"放到 008–010 章。

为什么先本体传感？因为多数任务的观测主干就是它：机械臂看关节角+速度就能完成到达与抓取，四足看躯干姿态+腿关节状态就能学会行走。相机与雷达只是往这条主干上续接更多模态。

核心原理

1. 传感器的读取模型：挂在树上，按步更新

Isaac Sim 里的传感器是有位置的场景对象（prim）：IMU 挂在机器人躯干或掌心，接触传感器挂在手指，深度相机挂在腕部。它们有两个共同的时序性质：数据随物理步更新（你 step 一次，传感器就有了一份新的"最近读数"），以及读取的是缓存值（拿到的是上一步刚算完的数据；"此刻"的瞬时值取不到）。这解释了两个常见困惑：为什么刚 reset 时读数是空的/默认的（还没步进过），为什么同一个数据连续读两次完全相同（缓存没变）。

传感器的"挂点"用相对 prim 路径描述。挂点决定测量坐标系：IMU 装在手心测的就是手心角速度；装错父级，策略看到的世界整体偏移。

2. 关节状态包：三个物理量，三种命运

关节状态包含三件事：位置 q、速度 q̇、力矩 τ。它们都是物理引擎的"真值"，真机上分别来自编码器、编码器差分与电流估计，差异主要在噪声与延迟。使用时注意三件事：

  • 角度是有界的，速度不是：有界关节（如机械臂）q ∈ [−2.9, 2.9] rad；连续关节（轮子）q 会无限累积，直接放进观测会让数值无界，应改用 sin/cos 编码或对 2π 取模。
  • 速度量级差异大：腕部关节速度可以到几 rad/s，大臂通常不到 1 rad/s。归一化要逐关节做（除以各自上限），否则策略的网络输入被某个维度主导。
  • 力矩是特权信息：仿真直接可读，真机只能从电流估计。放进观测可行，迁移时会"打折"。

3. IMU：加速度计测的是"比力"

IMU（Inertial Measurement Unit，惯性测量单元）包含加速度计与陀螺仪。加速度计测量的是比力（proper acceleration）：

ameas = aworld − g  （在传感器本地坐标系中表达） 静止时 a_world = 0，读出 |a_meas| = g ≈ 9.81 m/s²，方向指向"上"

这就是第一次读 IMU 最困惑的一点：静止时读出 9.81。反推姿态的原理也在于此：自由落体时读出接近 0，静止时方向就是重力反方向。陀螺仪测角速度、短时精确但会漂移，两者融合得到姿态四元数。仿真 IMU 是理想模型，迁移前按手册加噪声（021 章处理）。

4. 接触传感器：为什么必须滤波

接触传感器报告"哪个刚体与什么发生了接触、法向力多大"。数据天生"毛刺"：接触力本质是刚度×穿透深度，接触瞬间剧烈跳变（从 0 跳到几十牛）。原始值直接进观测或奖励会让策略学到抖动行为，工程解是低通滤波：

yt = α·xt + (1 − α)·yt−1，  α = dt / (τf + dt) τ_f 是滤波时间常数，如 50 ms；dt = 1/60 s 时 α ≈ 0.25

滤波带来的代价是滞后 τf。抓取任务里 50 ms 的滞后通常可接受（机械臂本体的响应时间也在几十毫秒量级），但高频力控任务要把 τf 压到 10 ms 以内。

5. EMA 的量化对照：时间常数、噪声衰减与信号延迟

EMA 的两个关键指标都可以解析计算。等效时间常数 τf = dt·(1 − α) / α；对白噪声输入，输出标准差与输入标准差之比约为 √(α / (2 − α))。取 dt = 1/60 s，逐档代入：

α时间常数 τf噪声标准差降至噪声衰减幅度适用场景
0.050.317 s16%84%静态监控、慢变力统计
0.250.050 s38%62%抓取判定与奖励（本课程默认）
0.800.004 s82%18%轻度平滑，接近原始信号

读表的顺序是先看中间列再看右列：α 每减半，时间常数约翻倍、噪声再压一档，两者是同一笔交换的两种标价。选择判据是"信号本身的变化时间尺度"：接触建立与脱离的物理过程约 20–50 ms，所以 τf 取 20–50 ms 恰好覆盖，对应 α 落在 0.2–0.4；把 τf 拉过 100 ms，接触与脱离的判定会晚半拍，抓取任务里表现为"已经捏住却还在加力"或"已经滑脱却以为仍接触"。反过来，α 取 0.8 时滤波几乎不抑制求解器毛刺，奖励项的方差仍然很大。默认档 0.25 就是在这条判据下选出的中间值。

6. 观测数据量的两级估算：本体传感与图像的对比

把观测的存储与带宽当成一道乘法题。本体观测 27 维、float32 时每样本 108 B；60 Hz 下单环境每秒约 6.3 KB；4096 个并行环境合计约 26 MB/s（108 × 60 × 4096 ≈ 2.6 × 107 B/s）。106 条经验合计约 108 MB，对回放缓冲只是零头。

换成图像再算一遍：一帧 84×84×3 的 float32 图像约 84.7 KB，三帧堆叠约 254 KB，是本体观测的约 2352 倍；106 条经验需要约 254 GB，单机内存无法承载。同样是"每条经验存一份观测"，两者的量级差出三个数量级，这解释了为什么本体传感为主的训练可以随手加大回放缓冲，而视觉训练必须在采样策略、精度（可用 float16 或 uint8 存图像）与并行规模上同时做减法。估算习惯保持不变：先数维度、再乘精度、最后乘条数与环境数。

7. 观测尺度的核对：分母怎么定、贴边怎么查

归一化分母只有三种合法来源：物理量程（关节限位）、规格上限（关节速度 2.2 rad/s、力矩 87 N·m）、任务典型幅度（接触力 20 N、工作半径 0.8 m）。用运行时统计量（滑动均值与方差）做分母会破坏可迁移性，因为它随策略变化漂移。分母定完后用两个统计量核对：分位数与贴边率。采集 105 个样本，逐维度看 1% 与 99% 分位：落在 ±1 以内说明尺度合适；99 分位长期超过 1.2 说明分母偏小、该维度容易饱和；99 分位低于 0.3 说明分母偏大，该维度对网络的贡献被压成噪声。贴边率统计 |x| 大于 0.99 的样本占比，任一维度超过 1% 就要复核它的物理来源。

连续关节的角度编码单独记账。把无界角 θ 换成 (sinθ, cosθ) 后，每个关节占用两个维度：四轮底盘多出 4 维，Franka 的单腕部关节多 1 维，27 维观测升到 31 维也只是每样本 124 B，存储代价可忽略。收益是角度差的可比性：0 与 2π 处的观测不再跳变，代价是丢失"转了几整圈"的信息，多数任务并不需要它。核对判据同样简单：编码后每个分量的取值天然落在 [−1, 1]，若统计到超界，说明实现里漏掉了取模或用了打字错位的公式。

8. 读取时序的延迟账

传感器的数据按物理步更新，读取的永远是"最近一次步进后"的缓存值，因此两条时序规则决定了观测里信息的新鲜度：决策步内先 step 再读，读到的是该步积分完成后的状态，用于观测、奖励与终止判定时与物理时刻对齐；相机等低频传感器的滞后由采样周期决定，30 Hz 配 60 Hz 物理时最大滞后 33.3 ms。

把滞后换算成位移：末端以 1 m/s 运动时，一个物理步（16.7 ms）对应约 1.7 cm，相机一整拍（33.3 ms）对应约 3.3 cm。对位置控制任务，这个量级的滞后通常被内环伺服吸收；对策略直接输出力矩的任务，滞后会让策略基于"稍旧"的状态施力，表现为过冲或振荡，缓解方式是把上一步动作或速度历史放进观测，让策略显式知道自己的动作还没生效（005 章的观测设计用的正是这一招）。核对方法：让关节以已知常速运动（例如速度模式给恒定 1 rad/s），记录读取值与解析值 θ(t) = θ0 + v·t 的偏差，偏差除以步长就是滞后步数；超过设计预期时逐环节排查读取位置与传感器频率设置。

9. 多模态观测的频率与成本核对表

三路本体传感器的工作频率与读取成本放在一起对照，打包决策就有依据：

传感器更新频率延迟量级观测处理
关节状态每物理步（60 Hz）不超过 1 步（16.7 ms）逐维归一化，无滤波
IMU每物理步（60 Hz）不超过 1 步角速度可轻滤波，四元数直接用
接触力每物理步（60 Hz）滤波引入 20–50 msEMA 后再用于观测与奖励

频率一致时打包顺序没有额外时序风险；三路合计的单步读取成本通常在 0.1 ms 以内，真正需要注意的是每步的数组分配：若读取函数每次返回新数组，60 Hz 乘以 4096 个环境就是每秒约 24.6 万次分配，垃圾回收的停顿会以"偶发的墙钟尖峰"形式干扰吞吐。工程写法是预分配缓冲、就地填充，或在读取层缓存最近一次结果。两个参数口径顺手记下：IMU 静置时比力模长的健康带是 9.81 ± 0.05 m/s²，超差先查挂点朝向，再怀疑物理；接触传感器的 min_threshold 推荐取 0.05–0.2 N，取太小会把求解器的数值接触收进来让标志位抖动，取到 1 N 以上又会漏掉轻触，抓取"刚刚碰到"的判定要的正是 0.1 N 量级的灵敏度。若再叠加帧堆叠或速度历史，维数按倍数放大：本体观测堆 3 帧后是 81 维、324 B/样本，106 条经验约 324 MB，仍在单机可承受范围，但要写进实验配置让复用者心里有数。

实现思路与设计

组织观测的完整流程：

  1. 列清单（任务需要哪些量：关节 q/q̇？躯干姿态？手指接触？先写下来再编码）。
  2. 挂载传感器（IMU 挂躯干/手掌，接触挂手指；相对路径挂接，reset 后统一初始化）。
  3. 读原始数据（每个决策步先 step、再读，保证读到的与当前物理状态一致）。
  4. 归一化（关节角除以限位、速度除以上限、接触力除以"典型最大力"，全部映射到约 [-1,1]）。
  5. 滤波（接触力、角速度等高频量过 EMA；关节角不加滤波，延迟不划算）。
  6. 打包（按固定顺序拼接成一维数组；顺序一旦定下就不要再改，网络的输入维度含义必须稳定）。
传感器数据归一化分母（示例）典型用途
关节状态q (9), q̇ (9), τ (9)限位 / 2.2 rad·s−1 / 87 N·m所有任务的主观测
IMU四元数 (4), 角速度 (3), 比力 (3)1 / 10 rad·s−1 / 20 m·s−2平衡、行走、姿态敏感任务
接触接触力 (3)，接触标志 (1)20 N / 1抓取判定、接触奖励（030 章）
设计思维：归一化的必要性从何而来？

输入没有统一尺度时，梯度会被量纲大的维度主导：30 N 的力与 0.5 rad 的角度同层，前者影响是后者的 60 倍。准则：除以"该维度物理上的典型幅度"（角度除限位、速度除上限、力除任务预期最大力），不要用运行时统计量归一，那会破坏可迁移性。

关键代码与解读

片段 1：关节状态包与观测打包（接口名随版本有差异，以官方文档为准）

import numpy as np

Q_LIMIT = np.array([2.897, 1.762, 2.897, 3.071, 2.897, 3.752, 2.897, 0.04, 0.04])
QD_LIMIT = np.full(9, 2.2)          # Franka 关节速度上限约 2.2 rad/s（示例值）
TAU_LIMIT = np.array([87.] * 7 + [60., 60.])

def get_proprioception(robot):
    """读关节状态包并归一化：输出 27 维观测（9 角 + 9 速 + 9 力矩）。"""
    q = robot.get_joint_positions()                 # 单位：rad（旋转）/ m（平动）
    qd = robot.get_joint_velocities()               # 单位：rad/s
    tau = robot.get_measured_joint_efforts()        # 关节力矩实测值：仿真特权信息
    obs = np.concatenate([
        np.clip(q / Q_LIMIT, -1.0, 1.0),            # 角度按限位归一，天然落在 [-1,1]
        np.clip(qd / QD_LIMIT, -2.0, 2.0) / 2.0,    # 速度可短暂超限：裁剪后再压到 [-1,1]
        np.clip(tau / TAU_LIMIT, -1.0, 1.0),        # 力矩按上限归一
    ])
    return obs.astype(np.float32)                   # float32：训练管线的标准精度，省一半内存

解读：注意三种量的归一化写法差异，这反映了它们的物理性质。角度除以限位是最自然的：限位就是该关节"物理上的满量程"。速度用 clip(qd / QD_LIMIT, -2.0, 2.0) / 2.0 两步走：先允许到 2 倍上限（速度偶尔超限是正常的，直接 clip 到 1.0 会饱和），再整体除以 2 压回单位区间，等价于"以 2 倍上限为满量程"。最后 astype(np.float32) 省一半内存（神经网络精度只需要 float32）。若某维度长期贴 ±1，说明该量常超预期范围，该检查物理或归一化分母了。

片段 2：挂载并读取 IMU

from isaacsim.core.api.sensors import IMU  # 传感器类路径随版本有差异

imu = world.scene.add(IMU(
    prim_path="/World/Robots/Franka/panda_hand/Imu_Sensor",  # 挂点：手掌下，测手掌运动
    name="hand_imu",
    frequency=60,          # 采样频率（Hz）：与物理步对齐，避免重复采样或漏采
    translation=np.array([0.0, 0.0, 0.05]),  # 相对父节点偏移 5 cm：挪出掌心网格
))
world.reset()  # 传感器在 reset 时完成初始化；此前的读取不可信

def get_imu_obs(imu):
    """读 IMU：朝向四元数、角速度、比力。"""
    quat = imu.get_current_frame()["orientation"]        # 朝向（w, x, y, z，仿真世界系）
    ang_vel = imu.get_current_frame()["ang_vel"]         # 角速度（本地坐标系）
    lin_acc = imu.get_current_frame()["lin_acc"]         # 比力：静止时模长约 9.81 m/s²
    return np.concatenate([quat, ang_vel / 10.0, lin_acc / 20.0]).astype(np.float32)

解读：frequency=60 与物理步一致是有意为之：传感器的硬件模型有独立的采样率，设得比物理步高没有新信息（引擎状态只在步进时变化），设得低则会漏掉数据。挂点路径 .../panda_hand/Imu_Sensor 演示了"相对挂接"的思路，把传感器放在手掌 prim 下面，它测量的就是手掌坐标系中的量，机器人整体移动到哪，IMU 都跟着。读出的三个量各有注意点：四元数按仿真世界系表达（若策略只需要"躯干相对于世界"的倾斜，可以只取部分分量减少输入维度）；角速度与比力在本地坐标系，角度/单位与 2、3 节的讨论一致。比力静止时模长为 9.81 是留给你的"健康检查"：机器人静止时若 lin_acc 的模长明显不是 9.81，说明挂点或坐标约定出了问题。

片段 3：接触传感器与 EMA 滤波

from isaacsim.core.api.sensors import ContactSensor  # 接触传感器类，路径随版本有差异

finger_contact = world.scene.add(ContactSensor(
    prim_path="/World/Robots/Franka/panda_hand/panda_leftfinger_contact",
    name="left_finger_contact",
    min_threshold=0.1,     # 只有法向力超过 0.1 N 才报告，滤掉求解器的数值级接触
))

class EMA:
    """指数滑动平均：y = alpha*x + (1-alpha)*y，抑制接触力毛刺。"""
    def __init__(self, alpha, size):
        self.alpha = alpha            # alpha = dt/(tau_f+dt)；tau_f=50ms、dt=1/60 时约 0.25
        self.y = np.zeros(size)

    def update(self, x):
        self.y = self.alpha * np.asarray(x) + (1.0 - self.alpha) * self.y
        return self.y.copy()

force_filter = EMA(alpha=0.25, size=3)   # 三维接触力各自独立滤波

def get_contact_force():
    frame = finger_contact.get_current_frame()          # 含 in_contact 与接触力等信息
    raw = np.array(frame.get("force", [0.0, 0.0, 0.0])) # 无接触时为零向量
    return force_filter.update(raw)                     # 滤波后输出给观测/奖励

解读：min_threshold=0.1 是接触传感器最实用的参数：物理求解器在"刚要接触/刚分离"时会产生 0.01 N 量级的数值接触，不屏蔽它们，in_contact 标志会在真实接触边缘疯狂跳变。滤波类 EMA 的 update 返回副本 self.y.copy()；直接返回 self.y 的话，内部数组会被下一次 update 原地改写，调用方拿到的"历史值"会神秘变化，这是 NumPy 编程的经典坑。滤波后的力用于观测与奖励（030 章展开）；但"力超过 50 N 立即松开"这类保护逻辑要用原始值，否则反应太慢。

常见坑

  • reset 前后读传感器：传感器视图未初始化时读数为空或默认值。修复：统一在 world.reset() 之后开始读取，并把"首次读取"作为环境初始化的检查点。
  • 挂点选错父级：IMU 挂在机器人根基上却以为在测手，或接触传感器挂在整体层级、未落到手指。修复：挂到正确连杆的相对 prim 路径下，并在可视化里确认位置。
  • 原始接触力直接进奖励：奖励充满高频噪声，策略学到抖动行为、return 方差巨大。修复：EMA 滤波（τf ≈ 50 ms）后再用；安全逻辑例外，用原始值。
  • 连续关节角度直入观测：轮子转久了 q 无限增大，观测数值爆炸。修复：用 sin/cos 或取模处理，或者干脆用速度代替位置。
  • 忘记归一化或归一化分母不合理：症状是训练 loss 抖动、某些维度主导梯度。修复：逐维度确定物理量级再相除，检查每维输入的实际取值范围（打印 min/max）。

练习与思考

  1. 把手掌静止在初始姿态下读 IMU 的比力，验证模长约 9.81 m/s²；再让机械臂做一次快速摆臂，观察比力变化，解释"加速度计读到的不只是重力"。★
    提示
    比力 = 运动加速度 − 重力。摆臂中运动加速度的贡献会叠加到 9.81 上，快速运动的段落读数会明显偏离。
  2. 给接触力滤波器扫描 α ∈ {0.05, 0.25, 0.8}，记录同一次抓取中的力曲线，比较"平滑程度"与"响应滞后"。★★
    提示
    α=0.05 对应 τ_f ≈ 0.32 s（几乎不动），α=0.8 接近原始信号；推荐落在 0.2–0.4 区间。
  3. 用 sin/cos 重写轮子关节角的观测表示，验证"转 10 圈"与"转 100 圈"的观测相同，并解释这对策略含义的影响。★★
    提示
    θ → (sinθ, cosθ) 把无界角度映射到单位圆，代价是丢失"转了几整圈"的信息，大多数任务并不需要它。
  4. 设计一个"传感器健康检查"函数：机器人静止时验证 IMU 模长、关节速度近零、接触力为零。写出检验条件与容差，并说明每一项失配可能的原因。★★★
    提示
    容差要考虑数值噪声：速度 |q̇| < 1e-3 rad/s；IMU 模长在 ±0.05 内；接触阈值以下不报告。
  5. 实验设计：把观测里的关节速度维度整体去掉（只留位置与力矩），预测 Cartpole 平衡任务成功率的变化方向并设计对照实验。★★
    提示
    cartpole 是欠驱动系统，速度是判断"杆子正在倒向哪边"的关键信号；去掉后策略变成部分可观测，成功率应明显下降（对照 052 章）。

小结

  • 传感器是挂在场景树上的对象：挂点决定测量坐标系，数据按物理步更新，reset 后才可用。
  • 关节状态包（q / q̇ / τ）是观测主干：注意角度有界、速度量级差异与连续关节的无界问题，逐维度归一化。
  • IMU 的加速度计测"比力"（静止时读 9.81），四元数给姿态；仿真模型理想，迁移前需按手册加噪声与偏置。
  • 接触力天生毛刺，用 EMA（τf ≈ 50 ms）滤波后再进观测与奖励；保护逻辑用原始值。
