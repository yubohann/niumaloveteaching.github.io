第一篇 · 仿真环境与训练框架

第 014 章：编写第一个强化学习环境类

把前十三章的能力封装成标准的 Gymnasium 接口：观测空间、动作空间、reset、step、终止与截断，让任何主流 RL 库都能直接驱动你的 Isaac Sim 场景。

  • 主题：强化学习 / 环境接口与时间尺度
  • 相关组件：Isaac Sim、Gymnasium（接口规范）、Stable-Baselines3（消费者）
  • 预计学时：55 分钟
  • 前置章节：第 013 章

学习目标

  • 理解 Gymnasium 环境接口的契约：reset() 与 step() 的返回值、终止（terminated）与截断（truncated）的区别。
  • 掌握决策周期（decimation）概念：物理步与 RL 步的换算，以及动作重复对样本效率的影响。
  • 会设计环境类的分层结构：仿真层（世界/机器人/传感器）与任务层（观测/奖励/终止）分离。
  • 会正确定义 observation_space 与 action_space，理解 dtype 与形状约定为什么必须严格。
  • 会用随机动作的冒烟测试与 check_env 验证环境符合规范。

背景与动机

前十三章聚焦"仿真怎么跑"；从本章起焦点切换到"学习怎么接入"。要用的 RL 生态（Stable-Baselines3、RL-Games 等）都按同一套接口约定工作：环境提供 reset() 与 step(action)，算法提供策略与更新规则。只要你的 Isaac Sim 场景包上这层接口，就能被 PPO、SAC 等算法直接训练，这也是 017–018 章的前提。

这层封装还解决了另一个工程问题：仿真与任务解耦。同一台 Franka 世界可以挂不同的任务（到达、推挤、抓取），环境类让"换个任务"变成换一个 reward/termination 的实现，不必重写整个脚本。本章的骨架将是 015、016 章 Cartpole 与 Franka 两个具体环境的模板。

核心原理

1. Gymnasium 契约：五个返回值决定一切

标准接口就两个方法，但每个返回值的语义都必须精确：

obs, info = env.reset()
obs, reward, terminated, truncated, info = env.step(action) obs 是观测（数组），reward 是标量（float），terminated/truncated 是布尔，info 是字典

细节决定的成败。观测必须是 observation_space 中声明的 dtype 与形状（通常是 float32 的 Box）：dtype 不匹配时，主流实现要么报错要么悄悄转换，性能与正确性都受影响。terminated 与 truncated 不能合并：前者表示任务终态（倒了、成功）、后者表示时限截断（超时）；学习算法对两者做不同引导（011 章已讨论）。info 是可选的诊断通道：成功率标志、奖励分量、初始状态采样值都放这里，训练脚本的日志系统直接消费它。

为什么值得遵守一个"别人的规范"？因为它把接口成本降为零：stable_baselines3.check_env(env) 能自动帮你检查几十项约定；Monitor、VecEnv 等包装器可以叠上去记录回合统计、并行化；你在社区里见到的任何技巧都能直接搬过来。

2. 时间尺度：物理步与 RL 步的换算

Isaac Sim 物理以 60 Hz 步进，但策略不应该也在 60 Hz 做决策，典型的机器人控制频率是 10–30 Hz，且每个决策重复执行若干物理步：

TRL = decimation × physics_dt decimation = 4、physics_dt = 1/60 s 时，一个 RL 步 = 66.7 ms（15 Hz 决策）

为什么需要动作重复（action repeat）？三个理由。样本效率：同样的墙钟时间内，决策次数越少、每条经验覆盖的仿真时间越长，"每秒经验"的信息密度更高（近距重复帧几乎不含新信息）。控制平滑：位置驱动的机械臂在 60 Hz 接收不同目标会产生抖动，15 Hz 的稳定目标让运动更从容。真机对齐：很多真机伺服环与通信链路本身就是 10–30 Hz，训练用同量级更利于迁移。代价是反应延迟：decimation 越大，策略对突发变化的响应越晚，接触丰富的任务不宜超过 8。

3. 分层设计：仿真层与任务层

环境类内部建议划成两半：仿真层负责 World、机器人、传感器、物理步进；任务层负责观测组装、奖励计算、终止判定。理由有三：任务可替换（同一仿真跑多任务实验）；可测试（任务函数不依赖真实仿真就能做数值测试）；可读（训练出问题先判断"是仿真坏了还是奖励写错了"）。这个分层在 Isaac Lab 里对应 ManagerBasedEnv 的 manager 思想，先用手写类把思想吃透，将来读大规模框架会顺畅很多。

5. decimation 的量化：决策频率、延迟与样本账

把动作重复步数 K 的三笔账算清楚。以 5 秒回合、60 Hz 物理：

决策次数 = T / (K · dt) = 5 / (K / 60) K = 1 → 300 次；K = 4 → 75 次；K = 8 → 约 38 次
K决策频率单步延迟 K·dt适用任务（按时间尺度）
160 Hz17 ms快速接触、Cartpole（特征时间约 0.2 s）
230 Hz33 ms平衡、常规跟踪
415 Hz67 ms机械臂到达与抓取（本课程默认）
8–106–7.5 Hz133–167 ms导航、移动底盘

选择方法：取 K 使"单步延迟不超过任务特征时间的 1/3"。Cartpole 特征时间约 0.21 s，对应 K ≤ 4（本课程取 2）；到达任务的特征时间约 0.5–1 s，K = 4 合适。K 越大，同墙钟预算下的经验条数越少、每条覆盖的仿真时间越长，采样预算按"决策步"计价时要记入这笔换算。若任务的变化速度快（接近人类操作速度量级），直接把 K 压到 1–2，把"快"写进任务的最基本约束里，再考虑其它优化。

6. reset 与 step 的观测一致性契约

接口文档只写了"reset 返回初始观测"，没写它必须与 step 的观测同分布。这条隐性契约是训练稳定的前提：如果 reset 读观测的时机在稳定期之前、而 step 在稳定期之后，初始观测会带两套不同的统计，策略要额外拟合这个差异。验证方法：各采集 200 个观测样本（reset 返回 200 个、step 走几步后取 200 个），逐维比较均值与标准差：

相对偏差 = |μreset − μstep| / (σstep + ε)，逐维应小于约 0.1 超出说明两条路径的读取时机或预处理不一致，先修环境再训练

实现上只需一个函数：观测的读取与预处理集中在 _build_observation() 一处，reset 与 step 都调用它，契约由结构保证，可不靠检查。

8. 环境类的验收清单

环境类写完后的验收按六项打分，每项都有可观察的证据：

六项里最容易漏掉的是"时间口径"：把 K 与 physics_dt 相乘核对一次回合时长，能同时发现"决策周期写错"与"超时计数单位错"两类问题。验收顺序先自检、后 check_env，问题定位范围更清晰。把六项写成断言随环境代码进版本管理，015 与 016 章的 Cartpole、Franka 环境都用同一套断言做回归；环境是训练系统的地基，验收成本远低于在百万步训练后排查一次静默错误。落地前再做一次对齐检查：在仿真里数 100 个物理步，确认决策计数增加 100 / K 次；数字对不上说明 decimation 的实现位置有偏差。

9. 时间账与失效边界：K 的三笔换算表

把 K 的三笔账（决策周期、回合时长、墙钟产出）并排成表，选值依据一目了然。设 physics_dt = 1/60 s，回合上限 200 个 RL 步，单环境 RTF = 60（对应约 3600 环境步/秒）估算 30 分钟墙钟内可采集的 RL 步数：

K单步决策周期决策频率200 步回合时长30 分钟可采 RL 步数
116.7 ms60 Hz3.3 s约 648 万
233.3 ms30 Hz6.7 s约 324 万
466.7 ms15 Hz13.3 s约 162 万
8133.3 ms7.5 Hz26.7 s约 81 万

读表得到三层信息。第一，K 每翻一倍，可采的 RL 条数减半，但每条覆盖的仿真时间翻倍，物理时间的总量不变；换言之，选 K 的自由度来自"任务需要多快看到反馈"，与"训练想多快跑完"是两笔独立的账。第二，回合时长随 K 线性放大：200 步的到达任务在 K = 4 下是 13.3 秒仿真时间，把超时上限当作"策略允许慢到几秒"的量化口径时，K 必须与它一起核对，否则会得到"训练里 13 秒完成、部署时 3 秒完成"的误导性认知。第三，墙钟产出与 K 成反比，做实验预算时用"决策步数 ÷ K ÷ 物理步率"换算，不要拿物理步数直接报价。

失效边界由"任务特征时间"划定：单步决策延迟 K·dt 不应超过任务特征时间的三分之一。Cartpole 的特征时间约 0.21 s，对应 K ≤ 4（本课程取 K = 2，30 Hz）；接触丰富任务的特征时间常在 0.05 s 量级，只能取 K = 1；导航类任务的特征时间在 1 s 以上，K 取 8 甚至 10 仍有余量。把延迟换算成物理后果更直观：末端以 1 m/s 运动时，K = 4 的一步延迟（66.7 ms）对应约 6.7 cm 的"盲走"距离，接近抓取容差的量级；这就是接触任务不能沿用"机械臂默认 K = 4"的原因。

观测空间声明与数值预处理的核对也补两笔。若实际送入的观测已经归一化到约 [−1, 1]，那么 observation_space 就按有界范围声明，让 check_env 的越界检查真正生效；只有像末端绝对坐标这类理论上无界的量才声明为宽范围。断言模板可以写成逐维清单：关节位置 7 维 |x| ≤ 1、速度 7 维按 2 倍典型值裁剪后 |x| ≤ 1、位置类 6 维（末端 3 + 目标 3）|x| ≤ 1.2。清单同时是"观测尺度是否合理"的体检：任何一维长期贴边或长期接近 0，都对应归一化分母取错，回到分母来源处（量程、规格上限、任务幅度）复核。观测的统计检查一次只需几百步，却能拦住大多数"训练慢得莫名其妙"的隐性缩放问题。

渲染开关的成本也给出参考数字：同一场景、同一物理设置下，单环境 render=False 的步进耗时约 1 ms（RTF 约 16.7），render=True 时升到约 3 ms（RTF 约 5.6），差距接近三倍；带相机与多光源时差距更大。这就是本章接口把 render 做成构造参数的原因，也提醒评估可视化要用独立实例：训练实例始终保持 render=False，评估实例按需开渲染，两者互不影响。world.step(render=...) 的每一次调用都显式传参，是防止"某处漏关渲染把吞吐拖垮"的静态习惯。

实现思路与设计

编写环境类的步骤：

  1. 搭仿真层（World + 机器人 + 传感器 + 010 章的对象；构造函数完成搭建与 reset 前准备）。
  2. 定空间（动作维度、观测清单与范围；先写进 __init__ 的常量，方便和 015/016 的任务类共享）。
  3. 实现 reset()（011/012 章的重置逻辑 + 返回初始观测与 info）。
  4. 实现 step()（动作缩放 → 下发 → decimation 次物理步 → 组装观测/奖励/终止/截断/info）。
  5. 冒烟测试（随机动作跑 500 步，检查：无 NaN、观测在空间内、奖励量级合理、回合能正常结束）。
  6. 规范检查（check_env；修复它报告的所有警告，再进训练）。
设计思维：为什么 step() 里只做"物理与数据"，不做"学习"？

常见的越界设计：在 step() 里做观测归一化的"自适应统计"、奖励缩放或探索噪声。这些属于学习算法或在训练循环里处理的事。环境类的职责边界是：给定动作，推进世界，返回观测/奖励/终止，它应当是一个尽量"没有记忆"的确定映射（随机性只来自显式的采样）。边界清晰后，同一个环境可以被任何算法使用，行为可预期。

关键代码与解读

片段 1：环境类骨架与空间定义

import numpy as np
from gymnasium import spaces, Env  # 若环境使用旧版 gym，把这里换成 gym 的 spaces（接口相同）

class FrankaReachEnv(Env):
    """示例环境：Franka 到达任务。仿真层与任务层都在此类内，但函数分工清晰。"""
    def __init__(self, decimation=4, render=False):
        self.decimation = decimation      # 决策周期 = decimation × physics_dt
        self.render = render              # 训练 False、评估 True
        self.dt = 1.0 / 60.0

        # 仿真层：World、机器人、传感器在 _build_sim() 中创建（前十三章的全部工作）
        self._build_sim()

        # 动作空间：7 个手臂关节的目标位置偏移，归一化到 [-1, 1]
        self.action_space = spaces.Box(low=-1.0, high=1.0, shape=(7,), dtype=np.float32)
        # 观测空间：关节位置(7) + 关节速度(7) + 末端位置(3) + 目标位置(3)，共 20 维
        self.observation_space = spaces.Box(low=-np.inf, high=np.inf, shape=(20,), dtype=np.float32)

    def _build_sim(self):
        # 这里放置 002-013 章的全部场景搭建：World、机器人、目标物、传感器
        self.world = None   # 示意：实际代码创建并返回 World 与 robot 引用
        self.robot = None

解读：骨架里的两个设计点。第一，decimation 与 render 作为构造参数暴露，它们是典型的实验超参，随时会被对照实验改动；参数化让"同一份环境跑不同设置"成为可能。第二，observation_space 声明为"无限范围"（-inf/inf 到 inf）在这里是诚实的选择：末端位置与目标位置是绝对坐标（单位米，理论上是无界的），硬写 [−1,1] 会撒谎。相对的，实际送的观测仍然应该做过归一化处理（关节量除以限位），因为"空间的声明"与"数值预处理"是两件独立的事：前者是契约，后者是工程优化。类型统一为 float32，与神经网络的计算精度对齐。

片段 2：reset() ， 复用前两章的重置逻辑

    def reset(self, seed=None, options=None):
        """标准签名：返回 (obs, info)。seed 用于可复现的初始状态采样。"""
        super().reset(seed=seed)  # 若继承 gymnasium.Env，基类会管理 np_random 生成器
        if seed is not None:
            self._sampler.rng = np.random.default_rng(seed)  # 把种子灌进 012 章的采样器

        # 1) 清空软件状态（011 章的清单：滤波器、帧栈、动作历史、计数）
        self._clear_caches()
        # 2) 写入采样初始状态（012 章的采样器：关节、目标物位姿）
        s = self._sampler.sample(self._default_joints, self._workspace_box)
        self.robot.set_joint_positions(self._clip_to_limits(s["joints"]))
        self.robot.set_joint_velocities(np.zeros(self.robot.num_dofs))
        self._set_target(s["object_pose"])
        # 3) 稳定期：只步进不决策（011 章约定），保证初始状态一致
        for _ in range(15):
            self.world.step(render=False)
        # 4) 产出初始观测与 info：观测读取路径与 step() 内完全一致
        obs = self._build_observation()
        info = {"target_pose": np.asarray(s["object_pose"][:2], dtype=np.float32)}
        return obs, info

解读：reset 的每一步都在前章有出处，这里是第一次把它们组装到接口里。注意三个接口细节。第一，签名是 reset(self, seed=None, options=None)：Gymnasium 最新规范推荐环境自己管理随机数（继承 gymnasium.Env 会拿到 self.np_random），这里为直观起见把种子直接灌给采样器，两种做法等价，选一种并保持一致即可。第二，稳定期放在 reset 内部：外部调用者（训练循环、评估脚本、check_env）不可能知道"这个环境需要 15 步稳定"，把它藏进 reset 是唯一正确的封装位置。第三，info 里带上了目标位姿：调试时能直接从日志里还原"这一局的目标在哪"，比训练崩了之后翻采样代码高效得多。

片段 3：step() ， 一个决策步的完整生命周期

    def step(self, action):
        """给定动作：缩放 → 下发 → decimation 次物理步 → 组装五元组。"""
        action = np.asarray(action, dtype=np.float32).clip(-1.0, 1.0)  # 防御性裁剪（004 章）

        # 动作保持：整个决策周期内目标不变：这正是"动作重复"的含义
        q_target = self._action_to_target(action)
        self.controller.apply_action(ArticulationAction(joint_positions=list(q_target)))

        for _ in range(self.decimation):   # 重复物理步：一次决策，多次物理推进
            self.world.step(render=self.render)

        obs = self._build_observation()    # 决策点采样观测（与 reset 用同一函数）
        reward = self._compute_reward()    # 任务层：奖励计算（019 章深入）
        terminated = self._is_terminated() # 任务终态：成功或灾难性失败
        self._step_count += 1
        truncated = self._step_count >= self._max_steps  # 超时：人为截断（任务终态另行判定）
        info = {"is_success": self._check_success(), "reward_terms": self._reward_terms()}
        return obs, float(reward), bool(terminated), bool(truncated), info

解读：step 是整门课最需要背下来的一段结构。四个关键决策。第一，先缩放再下发、且只在周期开始时下发一次：动作重复意味着"这 4 个物理步里机器人一直朝同一个目标运动"；对位置驱动，"周期开始下发一次"与"每步重发"物理上几乎等价，但对力矩驱动差别巨大（每步重发会引入高频抖动），统一成"周期开始下发"的语义更稳健。第二，观测在周期末尾采样：策略看到的永远是"执行完整个动作之后"的状态，这与 MDP 的 (s, a, s′) 语义一致；在周期中间采样会造成"看到的与奖励对应的时间点错位"。第三，terminated 与 truncated 分开计算：超时用步数计数（self._step_count 在 reset 里已清零），任务终态由任务层判定，两者独立，互不替代。第四，返回类型显式转换（float()、bool()）：NumPy 标量在部分学习库中会引发类型警告或隐式开销，显式转换是零成本的规范。

常见坑

  • 观测 dtype/形状与空间声明不符：SB3 可能报错或静默警告（观测被当对象处理），训练奇慢。修复：step/reset 返回前统一 astype(np.float32)，用 check_env 验证。
  • 动作不裁剪：策略探索时输出越界，驱动器追不上或触发奇怪行为。修复：环境内第一行就 clip（004 章），不要依赖算法端保证。
  • 忘记 decimation 或设置不当：60 Hz 直接决策导致样本效率过低、动作抖动；过大（如 30）导致反应迟钝、接触任务失败。修复：从 4 起步，按任务频率特性扫描 1–8。
  • terminated/truncated 合并：所有结束都当终态，价值引导错误、超时前的动作被错误学习。修复：分开计算并返回五元组；训练框架会正确处理。
  • step 里缺少 render 开关：训练时开着渲染，吞吐掉一半以上。修复：构造参数控制并在所有 world.step 调用处传入。

练习与思考

  1. 用 decimation=4 与 60 Hz 物理步，计算一个 RL 步与 500 步回合的仿真时长（秒）。★
    提示
    一个 RL 步 = 4/60 ≈ 66.7 ms；500 步 ≈ 33.3 秒。
  2. 写一个冒烟测试脚本：随机动作跑 500 步，断言观测 dtype 为 float32、无 NaN、每步奖励在合理量级，并打印回合结束原因分布。★★
    提示
    用 np.random.uniform(-1, 1, env.action_space.shape) 产生动作；回合结束原因从 terminated/truncated 与 info['is_success'] 组合判断。
  3. 把环境包一层 gymnasium.wrappers.TimeLimit（取代手写 truncated），对比两种实现的语义差异。★★
    提示
    TimeLimit 在包装层计数并产生 truncated；环境内部的超时把"计数器"职责混进了任务逻辑，两种都可以，但要选定一种避免双计数。
  4. 分层实验：把 _compute_reward 抽成一个纯函数（输入状态、输出奖励），为它写 3 个数值测试（成功状态给正奖励、失败状态给负、中间状态量级正确）。★★★
    提示
    纯函数不依赖仿真对象，输入用手工构造的数组；这是"任务层可测试"的直接收益。
  5. 实验设计：decimation 分别取 1 与 8，预测同一任务在"样本效率（到达目标所需 RL 步数）"与"控制平滑度"两个指标上的差异，并设计对照实验。★★
    提示
    decimation=1 的动作空间实际更细但噪声大；=8 单步覆盖时间长、更平滑，但精细操作受阻。比较同墙钟时间下的成功率曲线。

小结

  • Gymnasium 契约：reset() 返回 (obs, info)，step() 返回五元组；terminated 与 truncated 语义必须分开。
  • 时间尺度：RL 步 = decimation × 物理步；动作在整个决策周期内保持不变，观测在周期末尾采样。
  • 环境内部按"仿真层/任务层"分层：任务函数尽量纯化，便于替换与测试。
  • 空间与 dtype 声明是契约：action 用 [−1,1] Box，观测按归一化范围声明，全部 float32。
