第 079 章：实现事件触发控制

不一定每毫秒都要算：本章把"定时更新"换成"按需更新"，状态偏离超过阈值才重新计算控制量，用触发频率换算力与通信，同时用 Lyapunov 条件守住稳定性。

  • 主题：按需计算 / 事件触发与自触发
  • 相关组件：Isaac Sim / Isaac Lab / 策略推理调度
  • 预计学时：55 分钟
  • 前置章节：第 078 章

学习目标

  • 说清周期控制与事件触发控制（ETC）的区别：何时算、误差从哪来、稳定性怎么守。
  • 掌握触发条件的标准形式 ‖e‖ ≤ σ‖x‖ + ε 及它背后的 Lyapunov 分析思路。
  • 理解 Zeno 现象与最小驻留时间（dwell time）的必要性。
  • 会在 Isaac Sim 中实现"开关式策略推理"：状态监测廉价、推理与通信昂贵，只在需要时触发。
  • 会用触发率、平均事件间隔、跟踪误差三条指标评估 ETC 相对周期控制的收益与代价。
  • 能设计带最大周期的兜底触发，防止长期不更新导致的失控。

背景与动机

从第 077 章的 MPC 到前面所有策略网络，控制循环都默认一个假设：每个控制周期都必须重新计算。60 Hz 下这意味着每秒 60 次推理/求解。但对大多数机器人来说，绝大部分时间系统根本不需要新指令：机械臂稳态保持时控制器输出几乎不变；多机器人协同里多数机器人多数时刻"没什么新事"；工控机上的算力又要被视觉、规划、状态估计瓜分。

事件触发控制（Event-Triggered Control, ETC）把"定时计算"改成"按需计算"：只有当系统状态偏离上次更新点足够远时，才重新计算并更新控制量；其余时间用零阶保持（ZOH）沿用旧值。它天然匹配本课程的两类场景：一是把昂贵的策略推理/MPC 求解按需执行（算力账），二是多机系统中把通信按需触发（带宽账，第 049/093 章会用到）。代价是引入了"触发间误差"这个新的误差源，需要设计触发阈值保证它不破坏稳定性，这正是本章的理论核心。

核心原理

1. 设定：把"采样误差"变成设计变量

周期控制里，控制量 u 在 [tk, tk+1) 内保持不变（ZOH），触发时刻是固定的 tk = k·Δt。ETC 里触发时刻 tk 由条件动态决定。定义"自上次更新以来状态漂了多远"的误差：

e(t) = x(tk) − x(t)　（x(tk) 是上次触发时的状态快照） e 表示"控制所依据的旧状态"与"当前真实状态"的偏差，与跟踪误差不同

控制律 u(t) = K·x(tk)，在两次触发之间 u 不变。那么稳定性分析必须在"存在采样误差 e"的前提下做，直觉上，只要 e 相对当前状态足够小，控制量虽旧但方向仍对。

2. 触发条件与 Lyapunov 分析

闭环系统 ẋ = A x + B K (x + e)（因为 x(tk) = x(t) + e(t)）。取 Lyapunov 函数 V = xTPx，V̇ 中除了稳定项外会多出由 e 引入的干扰项：

V̇ ≤ −xTQx + 2‖xTPBK‖·‖e‖ 只要第二项小于第一项，V̇ 仍为负，这给出了触发条件该长什么样的线索

引入标准阈值条件：

触发当且仅当　‖e(t)‖ ≥ σ‖x(t)‖ + ε σ ∈ (0,1) 是相对阈值：状态越大容忍的绝对漂移越大；ε>0 是绝对项，防止 x→0 时阈值过苛

可以证明（在 K 使无采样闭环稳定、σ 足够小的前提下）V̇ ≤ −c·V，闭环稳定且收敛速度与 σ 相关：σ=0 退化为"连续更新"、σ→1 允许很大漂移但可能失稳；工程上 σ 从 0.1–0.3 起试。这就是 ETC 设计的全部秘密：稳定性靠"漂移有界"保证，不依赖"更新得够勤"。

3. Zeno 与最小驻留时间

理论上需要担心一件事：触发条件可能在有限时间内被无限次满足（Zeno 现象），例如状态在阈值边界来回磋、或系统噪声让 e 频繁越线，触发频率趋于无穷。物理系统里仿真步长本身是离散的，Zeno 表现为"每个仿真步都触发"，ETC 退化成周期控制还多花判断开销。两种处理：最小驻留时间，两次触发至少间隔 τmin（常取 1–3 个仿真步），强制频率上限；滞回，用两个阈值（触发后必须漂回 σin 以内才"重新武装"），防止边界抖动。噪声大的状态信号应先生成低通滤波后的版本再进触发器，否则触发被噪声主导。

4. 事件触发 vs 自触发 vs 动作重复

机制触发方式适用
事件触发（ETC）持续监测状态，越限才更新监测便宜（传感器已在读）、更新昂贵（推理/通信）
自触发（STC）更新时预测"下次更新时刻"，无需持续监测监测本身昂贵（如需要额外通信/计算）
动作重复（action repeat）固定重复 n 个仿真步再更新实现最简单，但固定 n 无法适应"快变时刻"

动作重复是 ETC 的离散简化版：省了 n 倍推理，但快变段（接触、急转）会和慢变段受同样的粗粒度更新。ETC 的价值恰恰在于自适应粒度：平稳段 20 步一更新，突变段一步一更新。它与 RL 的结合点很自然：策略推理（或 MPC 求解）是"昂贵动作"，触发器决定何时调用，训练时甚至可以把这个触发逻辑做进环境，让策略学会在"更新与不更新"之间权衡（练习 5 的方向）。

5. 代价与收益的账

ETC 的收益用触发率衡量：周期控制触发率 100%；平稳任务里 ETC 常能压到 20–50%，即算力开销省一半以上。代价有三：触发间误差（跟踪性能的轻微下降，通常 RMSE 增加 5–20%）、额外延迟（ZOH 让控制量平均陈旧半个事件周期，要给第 065 章的延迟预算加上这一笔）、实现复杂度（阈值调参、Zeno 防护、监测开销）。验收规则：先定性能损失上限（如 RMSE 允许 +10%），再在这个约束下最小化触发率，两列数字一起报，单看任何一列都会误导。

实现思路与设计

场景：Franka 追踪一条"慢变 + 突变"的复合轨迹，策略用第 076 章蒸馏出的小网络，推理是昂贵动作。方案：

  1. 监测对象选择：触发器监测"控制相关状态"，关节位置与速度（12 维）加权范数比值；权重按每维的名义变化范围归一，避免大范围维度支配判断。
  2. 触发条件：‖qk − q(t)‖W ≥ σ‖q(t)‖W + ε，σ=0.2、ε=0.02 rad（对应"明显偏离"的尺度）；滞回内阈 σin=0.1。
  3. 防护：τmin=2 步（33 ms）防抖；最大周期 30 步（0.5 s）兜底强刷；状态信号先过 5 ms 低通防噪声触发。
  4. 更新动作：触发时才调用策略推理；未触发则零阶保持旧动作。
  5. 对照组：纯周期控制（每步推理）跑同一轨迹；对比触发率、平均事件间隔、跟踪 RMSE、动作陈旧度（平均动作年龄）四项。
设计思维：为什么最大周期兜底不能省？

相对阈值 ‖e‖>σ‖x‖+ε 有个危险特性：当系统接近稳态且 x 很小时，阈值被 ε 主导；若系统恰好在"慢漂移"状态（例如缓慢外力推着走），误差可能长时间爬不过阈值，期间控制器完全开环。最大周期是防御"开环时间过长"的硬保险，它不参与稳定性证明，但参与工程安全。多层防御（阈值 + 驻留 + 最大周期）是 ETC 从论文到机器的标准配置。

关键代码与解读

片段 1：事件触发器，阈值、滞回与驻留时间

import numpy as np

class EventTrigger:
    """触发判定：相对阈值 + 滞回 + 最小驻留 + 最大周期四件套。"""
    def __init__(self, sigma=0.2, sigma_in=0.1, eps=0.02,
                 tau_min_steps=2, max_steps=30, w=None):
        self.sigma, self.sigma_in, self.eps = sigma, sigma_in, eps
        self.tau_min, self.max_steps = tau_min_steps, max_steps
        self.w = w                    # 各维权重：按名义变化范围归一（大范围维度不主宰判断）
        self.x_snap = None            # 上次触发时的状态快照
        self.armed = True             # 滞回：触发后要回落到内阈才重新武装
        self.steps_since = 10 ** 9    # 距上次触发的步数（初始保证第一步触发）

    def _norm(self, v):
        return float(np.sqrt(np.sum((v * self.w) ** 2)))

    def should_trigger(self, x):
        self.steps_since += 1
        if self.x_snap is None:
            self.x_snap, self.armed, self.steps_since = x.copy(), False, 0
            return True                                   # 第一步建立快照并更新
        if self.steps_since >= self.max_steps:
            self._reset(x); return True                   # 兜底：开环太久强刷
        e = self.x_snap - x                               # 触发间误差（旧快照 vs 当前）
        if self.steps_since < self.tau_min:
            return False                                  # 驻留时间内不再触发（防 Zeno）
        if not self.armed:
            if self._norm(e) < self.sigma_in * self._norm(x) + 0.5 * self.eps:
                self.armed = True                         # 已回落到内阈，重新武装
            return False
        if self._norm(e) >= self.sigma * self._norm(x) + self.eps:
            self._reset(x); return True                   # 越外阈：真正的触发
        return False

    def _reset(self, x):
        self.x_snap, self.armed, self.steps_since = x.copy(), False, 0

解读：should_trigger 的判定顺序本身是设计：先处理首次与兜底（安全优先），再检查驻留（Zeno 防护），最后才看误差阈值。权重 w 的作用容易被忽略但很关键：12 维状态里关节位置（±3 rad）与速度（±20 rad/s）量纲差近 10 倍，不归一化的话"速度微动"就能淹掉"位置大偏"，触发逻辑名存实亡，按每维名义标准差归一，让每一维的"一个典型变化"等价。滞回（armed 机制）是开放问题：真实系统的 x 会在阈值边界小幅震荡，若不武装-回落的双向门，会连续触发（每分钟上千次）污染快照。内阈取外阈的一半是经验配比。steps_since 的初始化用大数保证第一步必触发，任何控制器都需要一个合法的初始动作。

片段 2：事件驱动的推理调度与零阶保持

import numpy as np

class EventDrivenController:
    """只在触发时推理：算力大户（策略网络/MPC）按需调用，其余时间 ZOH。"""
    def __init__(self, trigger, policy_fn, act_dim=7):
        self.trigger, self.policy_fn = trigger, policy_fn
        self.last_action = np.zeros(act_dim)    # 初始动作：零位保持，也是首步的兜底
        self.trigger_count, self.step_count = 0, 0
        self.last_trigger_step = 0

    def step(self, obs, step):
        self.step_count += 1
        if self.trigger.should_trigger(obs["state"]):
            self.last_action = self.policy_fn(obs)     # 昂贵路径：推理/求解
            self.trigger_count += 1
            self.last_trigger_step = step
        return self.last_action                 # 未触发：零阶保持（含首步前的零位）

    def metrics(self):
        events = self.trigger_count
        return {
            # 触发率：相对"每步都推理"的百分比；省下的算力直接用这个数字陈述
            "trigger_rate": events / max(self.step_count, 1),
            # 动作陈旧度：非触发步的平均"年龄"，直接进第 065 章的延迟预算
            "mean_action_age_steps": (self.step_count - self.last_trigger_step) / max(self.step_count, 1),
        }

解读：step 的分支结构就是 ETC 的工程形态：昂贵路径藏在 if 里，其余步只做一次触发判定（几微秒）与动作复用。有两个细节值得强调：动作复用必须是显式的零阶保持，有些实现"未触发时沿用最新观测自己重算一遍轻量部分"，结果省了推理却引入了不一致，触发语义被破坏；指标里的"动作年龄"是 ETC 特有的健康指标：它测量控制量平均有多旧，直接叠加到系统延迟预算（第 065 章）。触发率 30% 但动作年龄 300 ms 的系统，性能损失主要来自动作陈旧这一侧，计算节省只是账面收益，两指标必须一起看。真实系统里 policy_fn 可能是"策略网络推理 + 安全滤波"，两者一起受触发控制；但急停、看门狗这类安全逻辑绝不进事件触发，它们始终逐步运行。

片段 3：周期 vs 事件触发的对照评估

import numpy as np

def compare_controllers(env, periodic_ctrl, event_ctrl, n_episodes=30, seed_set=None):
    """对照组实验：同一轨迹集上跑两类控制器，四项指标并排输出。"""
    rng = np.random.default_rng(0)
    results = {"periodic": [], "event": []}
    for ep in range(n_episodes):
        for name, ctrl in [("periodic", periodic_ctrl), ("event", event_ctrl)]:
            obs = env.reset(seed=int(rng.integers(1e9)))   # 每一对用同一初始条件
            done, errs, triggers = False, [], 0
            while not done:
                a = ctrl.step(obs, env.step_idx)
                obs, _, done, info = env.step(a)
                errs.append(info["tracking_error"])        # 与参考轨迹的即时误差
                triggers += int(info["triggered"])
            results[name].append({
                "rmse": float(np.sqrt(np.mean(np.square(errs)))),
                "trigger_rate": triggers / max(len(errs), 1)})
    summary = {}
    for name in results:
        r = results[name]
        summary[name] = {"rmse": np.mean([x["rmse"] for x in r]),
                         "trigger_rate": np.mean([x["trigger_rate"] for x in r])}
    # 验收判据：性能损失 ≤10% 且触发率显著低于 1.0 才算有收益
    loss = (summary["event"]["rmse"] - summary["periodic"]["rmse"]) / summary["periodic"]["rmse"]
    summary["verdict"] = {"rmse_delta": float(loss),
                          "benefit": bool(loss < 0.10 and summary["event"]["trigger_rate"] < 0.8)}
    return summary

解读：对照实验有两个容易作弊的点，这里都堵上了。同一初始条件配对比较：每对（周期 / 事件）用同一个 seed 重置，比较的是"同一场景下两种更新逻辑"，把场景差异从比较中剔除；不配对时事件触发常因任务难度抽样波动被误判。验收判据写成显式布尔：性能损失 10% 以内且触发率低于 80% 才算"有收益"，这个阈值共同表达了 ETC 的交易本质。指标之外建议再录一段"动作阶梯图"（动作随时间的阶梯状保持）直观展示触发时刻分布：好的触发模式应当是"平稳段台阶宽、突变段台阶密"，这比任何数字都能说明问题。最后注意评测所有配置应在同一延迟模型下（ZOH 的延迟影响已经体现在仿真时序里）。

常见坑

  • 阈值没有绝对项 ε：纯相对阈值 σ‖x‖ 在 x→0（稳定停下）时阈值趋零，任何噪声都触发，Zeno 退化成每日触发。症状是站立时触发率反而 100%。修复：加绝对下限 ε，并按噪声幅度标定（ε 取 2–3 倍噪声标准差）。
  • 误把 ETC 当"降频省电"：把控制周期整体拉长（如 60 Hz→10 Hz），这是降采样，与事件触发不同，快变段无法自适应。症状是接触任务明显变差。修复：保留步级监测，只压缩昂贵路径的调用；用动作年龄指标验证。
  • 触发器吃原始噪声信号：状态估计的抖动让 e 频繁越线。症状是触发时刻在时间轴上均匀密布（健康的模式是"平稳疏、突变密"）。修复：信号低通预处理 + 滞回；评分时区分"真突变触发"与"噪声触发"。
  • 忘记把动作陈旧度计入延迟预算：ETC 引入的平均陈旧（例如 40 ms）叠加原有延迟，让系统越过第 065 章的稳定裕度边界。症状是"单独测每部分都合格，组合起来振荡"。修复：动作年龄直接加进端到端延迟核算。
  • 安全逻辑也放进触发路径：碰撞检测、看门狗、急停被"省一省"。这是不可接受的工程错误。修复：安全回路恒定运行，事件触发只调控"性能相关的计算"；在架构图上画出两条独立的环路。

练习与思考

  1. 把 σ 从 0.1 扫到 0.5，画出"触发率-跟踪误差"曲线，找出你任务上的可用工作点并解释形状。★
    提示
    σ 增大触发率下降、误差先缓增后陡增；拐点前是"免费"的节省，拐点后是"用性能换算力"。
  2. 去掉最大周期兜底（设为无穷），构造一个"缓慢漂移"场景（如恒定小外力），观察失控过程并记录多久后系统明显偏离。★★
    提示
    慢漂移下相对误差长期小于阈值，控制器开环；用外力 2 N 缓慢推 5 秒再看位置偏差。
  3. 对比"动作重复 n=4 固定"与"事件触发（平均频率相同）"在复合轨迹上的性能，说明自适应粒度在哪里产生了价值。★★
    提示
    突变段的误差差异最明显；把两段（慢变/突变）的 RMSE 分开统计，结论更干净。
  4. 实现自触发（STC）版本：在每次触发时用名义模型预测"状态漂到阈值需要的步数"，作为下次强制更新时刻，与 ETC 对比监测开销与性能。★★★
    提示
    STC 省的是"持续监测"；在仿真里监测本来免费，收益要从"多机器人通信次数"角度评估。
  5. 把触发逻辑与控制策略联合训练：给策略一个"本次跳过推理"的动作选项，奖励里加入计算节省（或触发惩罚），看策略学会什么时候"不更新"。★★★
    提示
    奖励设计：节省项要小（如 −0.001/跳过），否则策略学会"永远不更新"；观察学到的触发分布是否与轨迹突变对齐。

小结

  • ETC 把"定时更新"换成"按需更新"：监测便宜、更新昂贵时收益最大；触发间误差 e = x(tk) − x(t) 成为新的设计变量。
  • 触发条件 ‖e‖ ≥ σ‖x‖ + ε 由 Lyapunov 分析给出：漂移有界则 V̇ 仍负，稳定性由漂移阈值保证，不取决于更新频率。
  • Zeno 防护三件套：最小驻留时间、滞回、噪声滤波；最大周期是独立于稳定性证明的安全兜底。
  • 工程实现：状态归一化加权、动作显式 ZOH、动作年龄计入延迟预算、安全逻辑不进触发路径。
  • 验收：先定性能损失上限，再最小化触发率；平稳段疏、突变段密的触发模式才是健康的。
