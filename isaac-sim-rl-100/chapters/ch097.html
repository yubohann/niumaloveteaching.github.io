第 097 章：实现水下机器人控制

从空气进入水中：附加质量、平方阻尼与洋流让动力学彻底变样。本章讲清水下平台的物理特性，以及 RL 如何在"滑行感强、扰动大、能量贵"的水下世界里找到控制节奏。

  • 主题：系统集成 / 水下平台与抗扰控制
  • 相关组件：Isaac Sim / Isaac Lab / Stable-Baselines3
  • 预计学时：60 分钟
  • 前置章节：第 096 章

学习目标

  • 理解水下动力学的三项特有修正：附加质量、非线性阻尼与浮力-重力平衡。
  • 会说清 AUV（欠驱动、鱼雷型）与 ROV（多推进器、全驱动）的控制差异与 RL 适用性。
  • 会把洋流扰动建模为"相对速度修正"，并设计抗流的观测与课程。
  • 会设计以能量效率为显式目标的奖励，理解水下任务"省电即续航"的工程含义。
  • 能诊断附加质量忽略、浮力失衡、线性阻尼误用、速度观测歧义等问题。

背景与动机

上一章的无人机在空气中飞行，本章的机器人来到 800 倍密度的介质里。水的密度带来三个立刻显形的后果：惯性被放大（附加质量）、阻力不可忽略且随速度平方增长、浮力与重力几乎同量级需要精心配平。这让水下机器人成为"最不像教科书刚体"的机器人：你不推它，它还会滑很远（滑行特性）；洋流轻轻一吹，它的对地方向的速度就偏了。

同时，水下是通信与视觉最不友好的环境，声学链路延迟秒级、图像浑浊，这逼着机器人高度自主。RL 在这里的价值有两个独特面：一是学"脉冲式省电推进"这类经典控制器不擅长优化的行为；二是把洋流从"纯扰动"升级为可以"顺势而为"的资源。本章为你补上水下这一课。

核心原理

1. 附加质量：水跟着你一起被加速

推动水下物体时，物体周围的流体也被带动加速，等效于给物体"增加"了一部分惯性。对常见 AUV 外形，附加质量可达自身质量的 0.2–1.0 倍（各轴不同，横向常比纵向大）：

(Mrb + Ma)·ν̇ = −C(ν)ν − D(ν)ν − g(η) + τ M_rb 是刚体质量矩阵，M_a 是附加质量矩阵；忽略 M_a 会按轴高估加速度能力 20%–100%

后果很实际：如果训练时忽略附加质量，策略学会的"加速、减速"节奏会整体偏快，真机上一个"急刹车"指令根本刹不住，滑行几十厘米。附加质量是水下仿真的第一优先项。

2. 非线性阻尼：v 与 v² 的双重世界

水下阻力由黏性摩擦（低速近似线性）与压差阻力（高速近似平方）组成，工程上写成两者之和：

D(ν)ν = Dl·ν + Dq·|ν|·ν D_l 线性系数、D_q 二次系数；0.5 m/s 以下线性项主导，1 m/s 以上平方项主导

这解释了水下机器人的"节奏感"：低速微调时像在蜂蜜里（阻尼大、响应慢）；高速巡航时阻力急剧上升（巡航功率 = 阻力 × 速度，与 v³ 成正比）。于是"经济航速"成为真实问题：巡航速度提升 20%，所需功率上升约 73%，这是奖励里能量项存在的物理基础。

3. 浮力平衡与恢复力矩

水下机器人的竖直方向受力来自重力与浮力的差：

Fnet,z = ρ·V·g − m·g（ρ=1000 kg/m³） ROV 通常配到"微正浮力"（+5–20 N 净浮力）便于失效时自动上浮；差 1 L 排水量就是 9.8 N

重浮心分离（重心在下、浮心在上）还会提供天然的恢复力矩，让机器人"自扶正"。这两者必须建模：净浮力失衡 10 N 时，策略要额外输出 10 N 的垂向推力"扛着"，等效损失一个推进器。检查方法：在零推力仿真下看机器人是否缓慢下沉/上浮，这就是最直接的配平验证。

4. 洋流：把扰动变成相对速度

均匀洋流 vc 的物理效应是：阻尼项应该用相对水的速度 νrel = ν − vc 计算，而运动学积分用的仍是相对地面的速度。这个区别是很多实现出错的根源：

M·ν̇ = τ − D(νrel)·νrel，  νrel = ν − vc DVL 测的是对地速度 ν（部分型号可测相对水速度）；阻尼力取决于相对速度

直觉：顺流时 |ν−vc| 小、阻力小、省电；逆流时阻力大。策略如果学会"顺流走弧线、逆流走直线"，就能显著省电，这是 RL 相对经典控制的独特收益点。

5. AUV 与 ROV：两类平台的 RL 定位

维度AUV（鱼雷型）ROV（作业型）
驱动1 主推 + 舵面：欠驱动（4 输入 6 自由度）6–8 推进器：全驱动
速度/航程1–2 m/s 巡航、航程数十公里0.2–0.5 m/s、脐带缆供电
控制难点欠驱动转弯（像船一样），不能横向平移多推进器推力分配与耦合
RL 用法学到比 PID 更省能的巡航/下潜节奏抗流悬停、精细定位（本章主线）

实现思路与设计

  1. 任务：ROV 从起点移动到目标点并悬停（水平 8 m、深度变化 ±2 m），姿态横滚/俯仰保持在 ±15° 内；环境中存在 0–0.3 m/s 的侧向洋流。
  2. 观测：位置误差（3，其中 z 用深度计）、旋转误差向量（3）、对地线速度（3）、角速度（3）、洋流线索（3，实际加速度与指令加速度之差，见片段 2）、上一动作（6）= 21 维。速度来源注明：DVL 对地速度，洋流速度信号不直接给（真实系统测不到，需要策略自己推断）。
  3. 动作：6 维推力（前后、左右、上下、横滚、俯仰、偏航）限幅 ±40 N / ±5 N·m，对应 6 推进器配置，经推力分配矩阵。
  4. 奖励：−‖ep‖ − 0.3·倾斜² − 0.02·Σ|τi|（能量项，与推进器推力绝对值成正比）− 0.02·‖Δτ‖²（平滑）− 0.01（时间） + 1.0（悬停保持 1 s）。
  5. 课程：静水悬停 → 静水点到点 → 洋流 0.1 → 0.2 → 0.3 m/s（方向随机）；每档用成功率 >70% 升级。
  6. 域随机化：附加质量系数 ±30%、阻尼系数 ±30%、净浮力 ±5 N、推进器效率 ±10%、传感器延迟（DVL 50 ms、深度计 20 ms）。
  7. 评估：位置误差、姿态 RMS、能耗（累计 Σ|τ|·dt 换算瓦时）、抗流偏移量、以及能量与时间两指标的帕累托前沿（与第 081 章呼应）。
设计思维：为什么能量项在"水下"比"陆上"重要一个量级？

陆地机器人多插电，能耗主要是电费；水下机器人靠电池，能耗等于任务半径与下潜时长。而且功率 ∝ v³ 的强非线性意味着"稍微开快点"的代价非常昂贵。把能耗写成奖励的显式项（用 Σ|τ| 的一阶范数）是有意选择：一阶范数近似"推力绝对值之和∝功率"，同时在 τ=0 处梯度不为零，鼓励"常用零推力滑行"的稀疏推进模式，这正是水下最优策略的形态。

关键代码与解读

片段 1：水下六自由度动力学步进

import torch

def underwater_step(eta_pos, quat, nu, tau, current, dt,
                    mass=15.0, added=(6.0, 8.0, 8.0), 
                    d_lin=8.0, d_quad=20.0, buoyancy_residual=8.0):
    """简化水下 6-DoF 步进：附加质量 + 线性/平方阻尼 + 净浮力。
    nu = (u, v, w, p, q, r) 体坐标系线速度/角速度；current: (3,) 洋流（对地）。"""
    # 1) 相对水的速度：阻尼力取决于相对速度（洋流进入动力学就在这里）
    nu_rel = nu.clone()
    nu_rel[:, :3] = nu[:, :3] - current          # 只修正线速度部分（简化）
    # 2) 阻尼力：线性 + 平方两项之和（系数按轴向不同可扩展为对角阵）
    drag = d_lin * nu_rel + d_quad * nu_rel * nu_rel.abs()
    # 3) 净浮力：正值为上浮（微正浮力设计），作用在体坐标竖直方向
    g_effect = torch.zeros_like(nu)
    g_effect[:, 2] = buoyancy_residual            # 换算成加速度还要除质量
    # 4) 有效质量 = 刚体质量 + 附加质量（各轴不同）
    m_eff = torch.tensor([mass + added[0], mass + added[1], mass + added[2]])
    acc_lin = (tau[:, :3] - drag[:, :3]) / m_eff - g_effect[:, :3] / mass
    # 5) 转动：按简化对角惯量处理（教学版；完整版需含附加惯量与科氏项）
    moment_of_inertia = torch.tensor([0.6, 0.8, 0.8])    # kg·m²
    acc_ang = (tau[:, 3:] - drag[:, 3:] * 0.1) / moment_of_inertia
    nu = nu + torch.cat([acc_lin, acc_ang], dim=-1) * dt
    return nu

解读：（1）nu_rel 的三行是本章最核心的实现：洋流通过修正阻尼计算的参考系来建模，不作为单独的"外力"加入，顺流时相对速度小、阻力小，物理自然涌现"顺流省力"；（2）附加质量 added=(6, 8, 8) 对 15 kg 的 AUV 意味着横向等效质量 +53%：忽略它策略会学出"要多少加速度给多少推力"的错误映射；（3）净浮力 8 N 的建模：正浮力让"断电自动上浮"成为安全特性，但策略必须持续用垂向推力抵消它，这是水下任务能量被"白白消耗"的主要来源，配平得好能省 20% 的电；（4）转动部分简化为对角惯量 + 阻尼系数 0.1 倍（水的转动阻尼远小于平动），生产环境应使用完整的 6×6 矩阵与科氏项，这里保留结构便于理解。

片段 2：抗流观测与"洋流不可见"的处理

class UnderwaterObs:
    """观测的关键约束：洋流速度真实系统测不到，只能从"速度误差的历史"里推断。"""

    def __init__(self, num_envs, vel_buf_len=3):
        self.vel_buf = None                # 保存最近 3 步的对地速度
        self.buf_len = vel_buf_len

    def build(self, pos_err, quat, nu, omega, prev_action, accel_cmd):
        import torch
        # 用"给过的加速度指令"与"实际速度变化"的差异作为洋流线索：
        # 指令往前推却没加速 → 可能有逆向流。这是真实系统的做法（无需测流仪）。
        if self.vel_buf is None:
            self.vel_buf = nu[:, :3].unsqueeze(1).repeat(1, self.buf_len, 1)
        self.vel_buf = torch.cat([self.vel_buf[:, 1:], nu[:, :3].unsqueeze(1)], dim=1)
        # 实际加速度（后两帧差分）vs 指令加速度：差值即"未解释的加速度"
        accel_actual = (self.vel_buf[:, -1] - self.vel_buf[:, -2]) / (1.0 / 60.0)
        current_hint = (accel_actual - accel_cmd).clamp(-1.0, 1.0)   # 粗略线索，限幅
        return torch.cat([pos_err / 5.0,                 # 位置误差归一化
                          orientation_error_vector(quat, self.quat_des),
                          nu[:, :3] / 1.0, omega / 1.0,  # 对地速度、角速度
                          current_hint, prev_action], dim=-1)

解读：这段回应了一个真实的工程难题：洋流在多数水下机器人上不可直接测量。做法是把"实际加速度 − 指令加速度"的残差作为线索放进观测，如果一直给推力却没有相应加速，大概率是顶流。clamp(±1.0) 防残差被其他误差（模型不准）污染成极端值。观测里同时保留对地速度与残差：前者告诉策略"我在动多快"，后者告诉它"水在推我多少"。这一对信号也解释了为什么水下 RL 任务常需要历史观测（与第 088 章视觉延迟、第 089 章速度估计同属一类"推断不可观测量"的技术）。

片段 3：洋流课程与能耗统计

import torch, math

class CurrentCurriculum:
    """洋流课程：大小与方向逐步放开；顺/逆流都出现过才允许升级。"""
    def __init__(self):
        self.stage = 0
        self.magnitudes = [0.0, 0.1, 0.2, 0.3]     # m/s 四档
        self.win = []

    def sample(self, num_envs, device="cpu"):
        mag = self.magnitudes[self.stage]
        # 方向随机但保证每个批次里顺流/逆流/侧流都有（避免方向过拟合）
        ang = torch.rand(num_envs) * 2 * math.pi
        v = torch.stack([mag * torch.cos(ang), mag * torch.sin(ang),
                         torch.zeros(num_envs)], dim=-1)
        return v.to(device)                         # 水平流场，垂向流暂不考虑

    def update(self, success_rate):
        self.win.append(success_rate)
        if len(self.win) >= 20 and sum(self.win[-20:]) / 20 > 0.7:
            self.stage = min(self.stage + 1, len(self.magnitudes) - 1)
            self.win.clear()

def energy_stats(tau_hist, dt=1.0 / 60.0):
    # 简化的"推进能耗"度量：Σ|τ|·dt（与功率近似成正比，见理论第 2 节）
    tau = torch.stack(tau_hist)                     # (T, ...)
    return (tau.abs().sum(dim=-1) * dt).mean()      # 每回合平均能耗代理

解读：（1）洋流课程的关键在 sample 的注释：方向必须覆盖顺流、逆流、侧流，只训侧流的策略在顺流下会"滑过头"（对地速度突然变大），在逆流下会"够不着"（相对速度小、机动变慢）；三类场景的物理完全不同，缺一类就是盲区；（2）energy_stats 用一阶范数（Σ|τ|）：正如设计节所述，它更接近"推进功率"且鼓励零推力的滑行段；把它作为主评估指标之一（与时间、精度并列），你就能量化"顺流省电"的真实收益，通常课程到最后一档时，同样的任务能耗比静水策略低 10%–20%。

常见坑

  • 忽略附加质量：策略学出 1.5–2 倍于真机的加速度能力，真机"刹不住、拐不过"。修复：Ma 建模 + ±30% 随机化；验证方法：一个已知推力下的速度响应时间是否与理论一致。
  • 阻尼只有线性项：低速悬停表现尚可，一进入巡航阻力被严重低估。修复：线性 + 平方双项，参数按船形标定或域随机化。
  • 浮力-重力失衡：净浮力没配平（仿真里差 5–10 N），策略被迫"扛着"一个方向的力，能量与姿态都受拖累。修复：在环境中显式建模 residual buoyancy 并在零推力下验证飘移方向与速度。
  • 速度观测的参考系歧义：把"DVL 对地速度"直接当阻尼计算里的速度用，顺流时阻尼被高估、逆流时被低估。修复：明确区分 ν（对地）与 νrel（对水），阻尼只用后者。
  • 没有垂向流/温度分层：真实海水有密度跃层（温跃层），跨层时浮力变化可达数牛。修复：进阶任务里加入"过跃层"课程，让策略学会动态配平。
  • 能量项用平方：Στ² 惩罚让"长时间小推力"看起来比"短脉冲大推力"便宜，与水下的真实最优行为相反。修复：能源模型用一阶范数（片段 3），或直接建电机功耗曲线。

练习与思考

  1. 计算：15 kg 的 ROV 排水 15.5 L，净浮力是多少牛？方向如何？需要多少推力才能悬停中立？★
    提示
    浮力 = 15.5 L × 1000 kg/m³ × 9.8 ≈ 151.9 N；重力 147 N；净上浮约 4.9 N，需 4.9 N 向下推力配平，这是"白白消耗"的部分。
  2. 把附加质量系数设为 0（关闭）训练，再用真实的 0.5 倍评估，观察过冲距离（刹车距离）的变化。★★
    提示
    刹车距离与等效质量成正比；在 0.5 m/s 下差异可达 10–20 cm 量级，正是作业型 ROV 定位精度的临界值。
  3. 把奖励的能量系数从 0.02 调到 0.2，观察完成时间与能耗代理（Σ|τ|·dt）的联合变化，画出帕累托曲线。★★
    提示
    能量项上调后策略会用"滑行 + 脉冲"模式替代连续推进；记录（能耗，时间）点集，通常存在明显的拐点。
  4. 实验：只训练侧流（方向固定 90°），评估时换成顺流/逆流，分别记录轨迹偏差，解释两类失败的物理差异。★★★
    提示
    顺流失败是"滑过目标"（速度合成后对地速度变大、制动不及时）；逆流失败是"移动迟缓"（相对速度不足）。两类都可以用 course 的 sample 修复。
  5. 设计实验：比较"有 current_hint 观测"与"无 current_hint"两种策略在洋流突变（0 → 0.3 m/s 阶跃）后的恢复时间。★★★
    提示
    无 hints 的策略要靠位置误差慢慢积累才知道有流，恢复慢；有 hints 的策略在速度残差出现的几步内就能反应。用位置误差回到 0.2 m 内的耗时对比。

小结

  • 水下动力学三项特有修正：附加质量（+20%–100% 等效惯性）、线性 + 平方阻尼（功率 ∝ v³）、浮力-重力配平与恢复力矩。
  • 洋流在动力学上的正确姿态是"修正阻尼的参考系"（νrel = ν − vc），不是简单的外力叠加。
  • 洋流通常不可测：用"指令加速度 vs 实际加速度"的残差作观测线索；速度要注意对地/对水的参考系区分。
  • 能量奖励用一阶范数 Σ|τ|，鼓励"滑行 + 脉冲"；课程必须覆盖顺流/逆流/侧流三类，温跃层等进阶效应后续再补。
  • 下一章进入软体机器人：它连"刚体"这个前提都不成立，状态空间近似无限维，控制与 RL 的思路都要重写，见第 098 章。
