第三篇 · 高级强化学习专题

第 071 章：实现探索策略

当回报稀疏、状态空间巨大时，"学会做对的事"的前提是先"遇到对的事"：本章从动作噪声、熵正则讲到 RND 内在奖励，搭一条从随机游走到定向好奇心的探索阶梯。

  • 主题：探索机制 / 噪声、熵与内在奖励
  • 相关组件：Isaac Sim / PPO / SAC（熵温度）/ 自定义奖励回路
  • 预计学时：55 分钟
  • 前置章节：第 070 章

学习目标

  • 说清探索-利用困境在机器人任务里的具体形态：稀疏奖励、巨大状态空间、危险局部最优。
  • 掌握三类探索工具的原理与适用边界：动作噪声、策略熵正则、内在奖励（RND/ICM）。
  • 会实现带衰减调度的探索噪声，并解释白噪声与相关噪声（OU）的行为差异。
  • 会实现 RND 新颖性奖励：目标网络、预测网络、误差归一化与上限保护。
  • 会把熵系数与温度调节（SAC 自适应 α）用于连续控制，理解它和动作噪声的关系。
  • 会评估探索质量：覆盖率、首次成功时间、内在/外在奖励占比；最终回报只是其中一项。

背景与动机

强化学习理论告诉我们策略会收敛到更好的行为，但前提是"足够多次地访问过各种状态"。机器人的状态空间大到离谱：12 个关节 × 位置速度 = 24 维连续空间；步态探索更狠，四足机器人要发现"腿别打结、身体别翻倒"的协调模式，早期随机动作 90% 以上以摔倒告终，而奖励如果是稀疏的（"走到目标点给 1 分"），学习信号几乎为零。

探索策略就是解决"如何高效地撞见有用的经验"。它有三条从弱到强的阶梯：动作噪声（最简单，让策略的采样分布变宽）、熵正则（让策略主动维持随机性，理论上是最大熵 RL 的最优解）、内在奖励（给"新奇"本身发奖金，把探索变成有方向的行为）。本章依次实现三层，并给出"该用哪层"的判断树：如果奖励密集、局部最优浅，噪声加熵就够；如果奖励稀疏、状态巨大，必须上内在奖励。

核心原理

1. 探索的本质：在"信息"与"回报"之间配置访问量

策略 π(a|s) 定义了行为的分布。经典强化学习只在利用当前认为好的动作；探索则是刻意把概率质量分给"还没试够"的动作。数学上把目标改为带熵的形式（最大熵 RL）：

J(π) = E[ Σt γt ( rt + α · H(π(·|st)) ) ]，H 为策略熵 α 是温度：α 越大越愿意"乱动"，α=0 退化为纯利用

这个目标的解（正则化策略迭代）可以证明：最优策略在"动作价值"和"熵"之间做加权 softmax，高价值动作概率大，但不是零概率覆盖所有动作。这避免了确定性策略把探索通道彻底关死。SAC 家族的自动温度调节让 α 随训练自动下降（行为够了就少乱动），比手工退火省事。

2. 动作噪声：白噪声 vs 相关噪声

最简单的做法是在动作上加噪声。两种常见分布的行为差异很大：

类型公式行为特征适用
白噪声（高斯）a′ = a + σ·ε，ε~N(0,I)每步独立抖动，均值零；高频分量多多数任务的默认；速度型执行器可滤掉部分抖动
相关噪声（OU）dx = θ(μ−x)dt + σdW，a′ = a + x平滑漂移，一段时间持续朝一个方向探索动量大的系统（行走、平衡）
参数噪声θnet′ = θnet + δ整个策略扰动，在策略族层面探索，粒度高于单步低维策略、需要系统性探索

为什么行走任务常偏爱 OU 噪声？白噪声逐步独立意味着加速度每一步都在抖，在接触动力学里容易激发出"抖腿"，策略学到的成了抗噪技巧，行走本身进展缓慢；OU 噪声有自相关时间（θ 决定），一段时间内持续朝一个方向试探，符合"迈左腿还是右腿"这类离散的、持续一段时长的决策结构。工程上先试白噪声，训练不稳再换 OU，别一开始就上复杂方案。

3. 内在奖励：把"新奇"变成奖励函数

稀疏奖励下最有效的方向是加一路"好奇心"奖励。RND（Random Network Distillation）的做法朴素得可爱：

ri(s) = ‖ f̂(s) − f(s) ‖² f 是随机初始化且冻结的目标网络，f̂ 是可训练预测网络；访问越多，预测越准，奖励越小

它的直觉：随机网络的输出是状态的特征标识；预测网络只被训练在去过的状态上变准，遇到没见过的新状态时误差大，误差就是新颖度。与计数法（访问次数倒数）相比，RND 在连续高维状态下有可微、可泛化的优势：按"特征空间里离熟悉区域多远"打分，不依赖精确计数。

三条必须遵守的纪律：一，奖励归一化，误差随训练整体缩小，要用滑动标准差把它标准化到与外在奖励同量级；二，设上界，防止偶发的巨大误差（如状态维异常值）压过任务奖励；三，注意随机性问题，如果环境本身随机（观测含噪声），预测网络永远会有残留误差，TV 类的"死胡同问题"（看无噪声电视）是 RND 的已知失败模式，Isaac Sim 的自定义环境最好先把观测噪声关掉或让 RND 只吃本体状态。

4. 三层的选择与组合

诊断信号推荐动作
训练回报上升但中途卡平，经验回放里状态分布单一加动作噪声 σ=0.1–0.3（归一化动作域），并保持熵系数 ≥ 0.005
回报长期为零、几乎不成功熵温度上调 / SAC；检查奖励是否真稀疏
稀疏奖励 + 巨大空间 + 目标可辨（如找导航通路）RND 内在奖励（权重初值 0.1–0.3，随成功次数衰减）
探索导致频繁危险（结合第 069 章）探索预算加约束：噪声在"安全动作集"内采样，或降低危险区域的探索温度

组合原则：探索强度要"随信息量递减"。训练早期缺信息，噪声/熵/好奇大一些；中后期要用"利用"锁定收益。所有探索机制都要有退出路径（衰减到零或接近零），否则最终策略永远带着随机抖动，真机上这是灾难。

实现思路与设计

以"四足机器人穿越稀疏奖励地形（每 5 米一个奖励点）"为例，三层探索的落地顺序：

  1. 基线：PPO，动作噪声 σ=0.2（归一化域）固定不变，观察训练曲线，大概率卡在"原地小步"的局部最优。
  2. 加熵正则：熵系数 0.01（占位尺度，后续扫描 0.003/0.01/0.03），观察策略动作方差与覆盖的地形类型数量。
  3. 加 RND：只对本体观测（48 维）计算新颖度，输出奖励 ri，用滑动标准差归一化后乘权重 0.2 加进总奖励；当外在奖励的移动平均值超过阈值（例如 20 个回合平均成功 12 次）时，把权重按每回合 0.995 的因子衰减。
  4. 调度与评测：σ 从 0.2 线性降到 0.05（前 40% 训练步），部署评测时 σ=0；评测指标除回报外，加"地形覆盖率"（训练中到达过的地形类型数 / 总类型数）与"首次成功回合数"。
  5. 安全旁路：地形边缘的探索配合速度限制（第 069 章的 CBF 滤波复用），避免探索演出"翻下台阶"式灾难。
设计思维：为什么探索噪声要加在"动作"上？

观测噪声在训练里是"鲁棒化工具"（第 066 章），它让策略适应传感器误差，但不会增加状态访问多样性，你还是在同一片轨迹上打转。探索必须作用在决定行为分布的量上：动作（最简单）、策略参数（更系统）、或内在奖励（最聪明）。把两者混为一谈会把"该探索的问题"误诊成"传感器噪声不够"。

关键代码与解读

片段 1：探索噪声包装器（白噪声 / OU 切换 + 调度 + 评估关闭）

import numpy as np

class ExplorationNoise:
    """动作噪声注入：支持 white / ou 两种模式；训练中按调度衰减，评测时归零。"""
    def __init__(self, act_dim, mode="white", sigma=0.2, theta=0.15,
                 sigma_min=0.05, decay_steps=200_000):
        self.n, self.mode = act_dim, mode
        self.sigma0, self.sigma_min = sigma, sigma_min
        self.theta = theta                       # OU 回归速率：1/theta 是相关时间尺度
        self.decay_steps = decay_steps
        self.step_count = 0
        self.x = np.zeros(act_dim)               # OU 的状态变量

    def sigma(self):
        # 线性衰减：早期大噪声覆盖状态空间，后期收敛到小噪声精细利用
        frac = min(1.0, self.step_count / self.decay_steps)
        return self.sigma0 + frac * (self.sigma_min - self.sigma0)

    def sample(self, deterministic=False):
        if deterministic:
            return np.zeros(self.n)              # 评测/部署：噪声必须严格为零
        self.step_count += 1
        if self.mode == "white":
            return self.sigma() * np.random.randn(self.n)
        # OU 过程离散更新：上一状态向 0 回归 + 新扰动，产生时间相关噪声
        self.x += -self.theta * self.x + self.sigma() * np.sqrt(2 * self.theta) * np.random.randn(self.n)
        return self.x.copy()

解读：deterministic 分支是这个类最重要的 3 行，探索噪声泄漏到评测是常见事故：评测指标忽高忽低，部署动作带抖动，却常常忘了问题出在"训练器"这一侧。OU 的离散更新里 sqrt(2θ) 的缩放让稳态方差等于 sigma²（连续 OU 的标准形式），这样切换模式时"噪声强度"可比；θ=0.15 对应相关时间约 6.7 步（60 Hz 下 111 ms），大约是一次迈步周期的量级，这是 OU 在行走任务好用的物理原因。衰减下限取 σmin=0.05：留一点残余噪声能让策略不把某个动作的 Q 值当成"唯一真理"，也给在线微调留探索口。注意所有噪声都在归一化动作域（±1）里加，之后再统一反归一化，避免不同关节因量程不同而实际噪声权重不同。

片段 2：RND 内在奖励模块

import torch
import torch.nn as nn

class RND(nn.Module):
    """随机网络蒸馏：预测误差作为新颖性奖励；目标网络冻结、预测网络可训练。"""
    def __init__(self, obs_dim=48, feat_dim=128, device="cuda"):
        super().__init__()
        self.target = nn.Sequential(nn.Linear(obs_dim, 256), nn.ReLU(),
                                    nn.Linear(256, feat_dim)).to(device)
        self.predictor = nn.Sequential(nn.Linear(obs_dim, 256), nn.ReLU(),
                                       nn.Linear(256, feat_dim)).to(device)
        for p in self.target.parameters():       # 关键：目标网络永不更新
            p.requires_grad_(False)
        # 优化器只接收 predictor 的参数：写错这一行，新颖度信号会直接塌缩
        self.optimizer = torch.optim.Adam(self.predictor.parameters(), lr=1e-4)
        self.norm = RunningRMS()                 # 误差的滑动 RMS，用于归一化

    def intrinsic_reward(self, obs, cap=5.0):
        with torch.no_grad():
            t = self.target(obs)
        p = self.predictor(obs)
        err = ((p - t) ** 2).mean(dim=-1)        # 逐样本新颖度
        self.optimizer.zero_grad()               # 外部挂的优化器只更新 predictor
        err.mean().backward()                    # 训练预测网络"看多几次就变准"
        self.optimizer.step()
        r_raw = err.detach()
        self.norm.update(r_raw)                  # 先用本批数据更新统计，再归一化
        r = r_raw / (self.norm.rms() + 1e-8)     # 归一化到与外在奖励可比
        return torch.clamp(r, max=cap)           # 上限：防异常大误差压过任务奖励


class RunningRMS:
    def __init__(self, alpha=0.99):
        self.value, self.alpha = None, alpha

    def rms(self):
        return 1.0 if self.value is None else max(self.value ** 0.5, 1e-6)

    def update(self, x):
        x = float(x.detach().mean())
        if self.value is None:
            self.value = x * x
        else:
            self.value = self.alpha * self.value + (1 - self.alpha) * x * x
        return self

解读：三处设计决定成败。目标网络冻结：如果两边一起训，误差可以靠"两边一起变简单"来消掉，新颖度信号就死了；冻结目标后，误差下降只能来自"见过"。err.mean().backward() 写在了奖励计算函数里（每个仿真批更新一次），这是 RND 的训练循环约定：预测网络的更新频率与数据摄入同步。归一化必须用滑动 RMS：训练中误差会整体下降一个数量级，固定缩放会导致"训练后期内在奖励几乎为零、无法完成二次探索"。上限 cap=5 的作用是防"观测异常值引发惊人大误差"污染 batch 内的奖励尺度。注意 torch.no_grad() 只包了 target，predictor 的梯度必须保留，而外部优化器在学习率上一般取策略主网络的 1/3（辅助任务别喧宾夺主）。这套模块与第 073 章 GAIL 的判别器结构同源：一个学"像不像专家"、一个学"熟不熟悉"，都是把"不确定性"变成标量奖励。

片段 3：内在奖励的合成、衰减与账务

import numpy as np

class IntrinsicMixer:
    """把外在奖励与内在奖励合成，并把探索预算随成功自动退火。"""
    def __init__(self, w0=0.2, decay=0.995, w_min=0.01, success_window=100):
        self.w, self.decay, self.w_min = w0, decay, w_min
        self.success_hist = []                   # 最近的成功/失败记录
        self.success_window = success_window

    def step(self, ext_reward, intr_reward, success):
        self.success_hist.append(int(success))
        if len(self.success_hist) > self.success_window:
            self.success_hist.pop(0)
        rate = np.mean(self.success_hist)         # 近期任务成功率
        if rate > 0.6:                            # 任务已能被顺稳完成：开始收探索
            self.w = max(self.w_min, self.w * self.decay)
        total = ext_reward + self.w * intr_reward
        return total, self.w, rate


# 训练侧账务（每 N 个迭代记录）：
# 日志里必须分别记录：ext 总和 / intr 总和 / w / 成功率
# 若 intr 占比长期 >50% 而 ext 不涨，说明"好奇心"在带队漫游，需要降 w 或检查奖励密度

解读：探索预算要"挣得越多、花得越少"，rate > 0.6 的门槛意味着任务已见雏形，此时继续用大权重养好奇心会把策略拉去"刷探索分"（典型 reward hacking 形态：在没去过的角落反复转圈）。衰减系数 0.995 是每步乘一次吗？不，是由调用方每"回合结束或每 N 步"调用一次 step 的量级；请按你的调用频率标定，否则衰减太慢。最重要的工程习惯在注释里：分开记录 extrinsic 与 intrinsic 两路奖励、权重 w 与成功率四组曲线。只有这四组数据才能让你回答"训练没学会，是好奇心没带路，还是好奇心带错路"。

常见坑

  • 评测忘记关闭噪声：回报曲线在评测点反复抖动，部署时动作带高频抖动。症状是"训练指标好、demo 视频很抖"。修复：噪声由独立的 deterministic 开关控制；评测流程统一强制关闭。
  • 探索噪声直接加在物理量纲动作上：不同关节量程差异（±2.9 rad vs ±87 N·m）导致噪声权重失衡。症状是某些关节疯动、其他关节不动。修复：统一在归一化动作域（±1）加噪再反归一化。
  • 内在奖励不归一化：RND 误差早期巨大，把外在奖励压成"零头"，策略一心追求新奇。症状是 intr 占比 >80%、任务成功率不涨。修复：滑动 RMS 归一化 + 上限 + 随成功的衰减权重三件套。
  • 目标网络被意外训练：忘记冻结或优化器包含了全部参数，新颖度信号很快塌缩到零。症状是探索阶段戛然而止、回报曲线卡平。修复：requires_grad_(False) + 优化器显式只接收 predictor 参数 + 定期断言目标网络权重未变。
  • 熵系数照抄论文：不同任务的回报尺度差十倍，同系数效果完全不同。症状是"论文能学、我这里不学"。修复：把熵系数当超参扫描（0.003/0.01/0.03），或改用 SAC 的自动温度调节让任务自己定。

练习与思考

  1. 固定其余配置，对比 σ=0.05 / 0.2 / 0.5 三条训练曲线，给出你任务上"探索强度-收敛速度"的经验区间。★
    提示
    σ 太小时早熟（卡在局部最优）；太大时走不稳、样本效率低。看三条曲线的分叉点出现的时间。
  2. 把白噪声换成 OU 噪声（θ 取 0.05 / 0.15 / 0.5），在行走任务上对比稳定步态的出现时间，解释 θ 与步态周期的关系。★★
    提示
    θ 越小相关时间越长（更"执着"的探索方向）；θ=0.15 在 60 Hz 下对应约 0.1 s 相关尺度。
  3. 只给 RND 只看本体状态 vs 只看外感受等效特征，设计实验比较两种输入下探索的"方向性"，并给出你的解释。★★
    提示
    本体状态与任务进展强相关，新颖度更快地把策略推向"没走过的平衡姿态"；耦合过多会引入随机噪声污染。
  4. 把 RND 权重的衰减门槛（成功率 0.6）改成 0.3 与 0.9，观察最终回报与训练后期行为，说明探索退火时机过晚的代价。★★
    提示
    门槛太晚（0.9）意味着策略已在"刷探索分"很久，退火要花更长时间恢复任务性能。
  5. 设计一个"探索安全"方案：让噪声幅度随与障碍的距离增大/减小（不要越危险越乱探索），用你第 069 章的安全集定义来支撑设计。★★★
    提示
    把 CBF 的 h(x) 映射成噪声尺度 σ(h)=σmax·min(1, h/h0)：安全距离内大胆试，逼近边界就收敛行为。

小结

  • 探索的目标是让"有用的状态"被足够多次访问；三层阶梯：动作噪声 → 熵正则/温度 → 内在奖励。
  • 白噪声简单通用，OU 噪声"持续朝一个方向试"，适合动量大的行走/平衡任务；噪声统一在归一化动作域添加。
  • RND 用"冻结随机网络的预测误差"度量新颖度：目标网络必须冻结、误差必须归一化、输出必须有上限。
  • 探索强度必须随信息量/成功率退火，并保留各路的独立账务（ext/intr/权重/成功率），否则无法诊断。
  • 评测与部署一律关闭探索噪声；探索要和安全边界联动（噪声随危险度收缩）。
  • 下一章讨论"该往哪里探索"的另一种答案：不再让探索漫无目的，改为设计回报地形引导策略，奖励塑形，含保持最优策略不变的势函数方法。
