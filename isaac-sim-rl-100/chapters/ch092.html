第 092 章：实现移动机械臂操作

给机械臂长上轮子：工作空间从一张桌子扩展为一整间厂房。难点是底盘与臂的耦合，谁先动、谁后动、怎样不被对方的运动干扰。

  • 主题：系统集成 / 底盘-臂协调与全身控制
  • 相关组件：Isaac Sim / Isaac Lab / Stable-Baselines3
  • 预计学时：55 分钟
  • 前置章节：第 091 章

学习目标

  • 理解移动机械臂的冗余结构与底盘-臂耦合：完整/非完整约束、稳定裕度与时间尺度分离。
  • 掌握全身控制（WBC）的任务优先级思路，会说清它与 RL 的分工方式。
  • 会把"底盘速度 + 臂动作"的组合动作空间接进 RL，并处理目标坐标系问题。
  • 会设计课程：从"底盘固定"到"底盘必要"，从"目标在近处"到"跨越房间"。
  • 能诊断底盘漂移、策略乱开底盘、忽略运动耦合等常见问题。

背景与动机

固定基座机械臂的工作空间由臂长决定：一套 1 m 臂长的机械臂，能触及的就是面前那一亩三分地。移动机械臂（mobile manipulator）把 3 自由度的底盘和 6–7 自由度的臂组合起来，工作空间扩展成整层楼，仓储拣选、酒店服务、建筑巡检都靠它。

但组合不是加法。底盘是"慢而重"的子系统，臂是"快而轻"的子系统；底盘一动，臂的基座就在动，末端误差被连坐；臂伸得远，整车重心就偏移，转向稍快就有倾覆或侧滑风险。上一章解决"两臂之间的内部协调"，本章解决"一个系统内部、不同时间尺度的两个子系统"的协调，这是系统集成篇从"同构协作"迈向"异构协作"的第一步。

核心原理

1. 冗余与运动学：底盘让自由度"富余"起来

差速轮底盘的位姿 (x, y, θ) 有 3 个自由度，但只受 2 个速度控制（前进 v、转向 ω），满足非完整约束：

ẋ·sinθ − ẏ·cosθ = 0 轮子只能沿车身方向滚动、不能横移：底盘"能到任意位置，但不能任意方向同时动"

底盘 3 + 臂 7 = 10 个自由度对 6 维末端任务：冗余 4 维。冗余本可以用于优化（避障、姿态舒适），但也意味着"无穷多解"，固定基座时你会用零空间投影（第 084 章），移动平台上这些解里混进了"底盘怎么摆"的大尺度选择：是底盘凑近、只用手够？还是停在门口、伸长臂够？这正是策略要学的高层权衡。

2. 时间尺度分离：底盘是"慢变量"

底盘速度上限约 0.5–1.5 m/s、加速度约 0.5–1 m/s²；臂末端速度可达 1–2 m/s、加速度 5–10 m/s²。臂的加减速能力高一个数量级，意味着：底盘的运动在臂看来是"缓慢的基座漂移"，臂的运动对底盘则近似"瞬时"。这个分离带来两个工程后果：

  1. 底盘与臂可以用不同的控制频率（如底盘 20 Hz、臂 60–100 Hz），仿真里也常这样配置；
  2. 底盘到位后，臂的"精调"可以在底盘近似静止的假设下进行，把"移动"与"操作"在时间上分开（move-then-act）是最稳妥的基线策略，但代价是慢。

更高效的方案是边动边操作（mobile manipulation），让臂在底盘减速的间隙提前伸展（anticipation，与第 089 章同源）。它能压缩总节拍，但要求协调精度，评估指标应包括"操作起始与底盘停稳的时间间隔"，越小越好。

3. 稳定与安全：伸臂就是"移动重心"

底盘-臂系统的重心随臂的伸展移动。以轮式底盘为例，倾覆条件近似为：重心投影点必须留在支撑多边形内，并保留安全裕度：

dmargin = 重心到支撑多边形最近边的水平距离 > 0.05–0.1 m（静态裕度） 臂全伸展、满载时重心前移可达 0.2 m 量级，超过轮距的一半就很危险

除了静态倾覆，急加速/急转向的惯性力同样危险。策略层面的对策是把"底盘速度 + 臂伸展量"联合限幅：臂伸得越远，允许的底盘速度越小；写进奖励后策略会自发学会"伸臂时减速"。

4. 全身控制（WBC）：经典派的答案

经典移动机械臂常采用分层二次规划（Quadratic Programming, QP）求解"全身"指令，任务按优先级排开：

优先级任务原因
高末端位姿跟踪任务本体，"做什么"
中稳定裕度 / 不碰撞安全，"不能翻、不能撞"
低关节裕度、姿态舒适、能耗冗余自由度上的优化

数学上每层任务在高优先级任务的零空间里求解（与第 084 章的零空间投影同构）。WBC 的优点是行为可预测、安全约束可硬保证；缺点是任务权重与切换开销要人工调。RL 与 WBC 的分工方案：RL 输出底盘速度与末端参考位姿（"做什么、往哪走"），WBC/底层控制器负责在安全约束内执行，这也是本章推荐的落地架构。

实现思路与设计

  1. 任务：目标点定义在工作台处（世界系坐标随机），机器人需移动底盘进入工作范围并把末端放到桌上的目标位姿；允许"臂够不到时移动底盘"。
  2. 动作空间：底盘 (v, ω) 2 维（限幅 v∈[−0.5,0.5] m/s、ω∈[−0.8,0.8] rad/s）+ 臂末端速度指令 6 维（经底层 IK）。合计 8 维可学；不要一上来连臂的力矩也端到端学。
  3. 观测：底盘位姿与速度、臂关节位置/速度、末端到目标的相对位姿误差（统一在世界系表达）、"目标是否在当前可达域"的布尔量。最后一项让策略具备"要不要挪车"的决策信号。
  4. 奖励：末端误差为主 + 底盘运动惩罚（−0.05·‖v‖ −0.02·‖ω‖ 每步）+ 稳定裕度越界惩罚 + 时间税；成功（误差 <1 cm 且末端速度 <0.05 m/s）+1。
  5. 课程：阶段 1 目标全部在可达域内（底盘几乎不用动）→ 阶段 2 目标 30% 在域外（要求移动）→ 阶段 3 跨房间随机。阶段切换用成功率滑动窗口。
  6. 稳定约束：计算重心投影与支撑多边形距离，把 dmargin 进观测、越界进惩罚；臂伸展量 × 底盘速度的联合限幅写进动作后处理。
  7. 评估：成功率、总完成时间、"底盘不必要移动量"（浪费的里程）、dmargin 的最小值分布、以及操作开始与底盘停稳的时间差。
设计思维：把"要不要动底盘"从学习问题变成结构判断

"目标是否可达"是一个几何判断，用解析的臂展球检查（目标到肩部距离 ≤ 0.85·臂展）就能以 99% 的准确率给出。把它作为观测里的一个布尔量，比让策略从 10 维状态里自己发现这个边界容易得多。这与第 089 章给拦截点、第 087 章写死选择矩阵是同一原则：廉价而准确的先验，一律结构化地喂进去；学习留给真正模糊的部分。

关键代码与解读

片段 1：非完整底盘的位姿积分与坐标变换

import torch

def differential_drive_step(pose, cmd, dt=1.0 / 20.0):
    """差速底盘位姿积分：pose=(x,y,theta)，cmd=(v,w)。20 Hz 控制周期。
    用中点法降低大转向下的离散误差（前向 Euler 会"切弯道"）。"""
    x, y, th = pose[:, 0], pose[:, 1], pose[:, 2]
    v, w = cmd[:, 0], cmd[:, 1]
    # 中点法：先用半步长的朝向角；大转向时 Euler 积分会"切弯道"
    th_mid = th + 0.5 * w * dt
    x = x + v * torch.cos(th_mid) * dt
    y = y + v * torch.sin(th_mid) * dt
    th = th + w * dt
    # 角度归一化到 (-pi, pi]：不做的话 theta 会一直累积导致后续 cos/sin 精度下降
    th = torch.atan2(torch.sin(th), torch.cos(th))
    return torch.stack([x, y, th], dim=-1)

def world_to_base(pose_base, p_world):
    """世界坐标 → 底盘坐标：把目标误差转到"车头视角"。
    策略用底盘系理解"目标在左前方"，比世界系绝对值更易学。"""
    x, y, th = pose_base[:, 0], pose_base[:, 1], pose_base[:, 2]
    dx = p_world[:, 0] - x
    dy = p_world[:, 1] - y
    c, s = torch.cos(th), torch.sin(th)
    # 旋转 (-th)：世界→底盘的坐标变换
    px = c * dx + s * dy
    py = -s * dx + c * dy
    return torch.stack([px, py], dim=-1)

解读：（1）differential_drive_step 用中点法替代前向 Euler：以 0.8 rad/s 转向、0.5 m/s 速度计，Euler 每步横偏差约 0.5 mm，10 步累计到约 5 mm，底盘运动误差会直接变成臂的定位误差，积分精度在这里是工程问题；（2）角度归一化是长回合训练的刚需：θ 累积到 100 rad 后 float32 的 cos/sin 精度降到 1e-5 rad，表现为"机器人走十分钟后开始画龙"；（3）world_to_base 把误差转到车头视角，局部相对坐标比世界系绝对坐标泛化好（与第 088 章特征归一化同源）。

片段 2：稳定裕度与联合限幅

def stability_check(com_xy, support_polygon, ee_extension, cmd,
                    margin_min=0.06, k_coupling=0.8):
    """重心-支撑多边形裕度检查 + 臂伸展与底盘加速度的联合限幅。
    支撑多边形给 4 个轮子的凸包 (B,4,2)；com_xy: (B,2) 整车重心水平投影。"""
    import torch
    B = com_xy.shape[0]
    d_margin = torch.full((B,), 1e6)
    for i in range(support_polygon.shape[1]):      # 逐边计算点到边距离
        a = support_polygon[:, i, :]
        b = support_polygon[:, (i + 1) % support_polygon.shape[1], :]
        ab = b - a
        ap = com_xy - a
        # 点到线段距离（多边形边）：d = |ab × ap| / |ab|
        cross = ab[:, 0] * ap[:, 1] - ab[:, 1] * ap[:, 0]
        d = cross.abs() / ab.norm(dim=-1).clamp(min=1e-6)
        inside = (cross * inside_sign(support_polygon)) >= 0   # 简化：假定顶点有序
        d_signed = torch.where(inside, d, -d)      # 多边形外为负
        d_margin = torch.minimum(d_margin, d_signed)
    # 联合限幅：臂伸展越长（ee_extension 0→1），允许的底盘线速度越小
    v_scale = 1.0 - k_coupling * ee_extension.clamp(0.0, 1.0)   # 伸满时只剩 20%
    cmd = cmd.clone()
    cmd[:, 0] = cmd[:, 0] * v_scale
    return cmd, d_margin

解读：（1）裕度的定义是"重心到支撑多边形边界的有符号距离"，负值表示已在多边形外（即将倾覆）；这个量直接可以作为奖励惩罚项与观测通道；（2）k_coupling=0.8 的含义：臂完全伸展（extension=1）时底盘速度被压到 20%，这是"物理直觉写成代码"的例子。为什么是 0.8 不是 0.95？因为还要留余量给制动距离：0.5 m/s 停下需要约 0.25 m，与整车轴距同量级；（3）简化部分（inside_sign、顶点有序假定）在实际工程里换成标准的凸多边形包含测试即可，这里保留结构是为了让读者看清"每一步在算什么"。

片段 3：课程与"是否移动底盘"的观测设计

class MobileManipCurriculum:
    """三阶段课程：底盘几乎不用动 → 需要移动 → 跨房间。"""
    def __init__(self):
        self.stage = 0
        self.reach_radius = 0.85      # 臂展球半径系数：85% 臂展内视为可达
        self.arm_reach = 0.855        # 名义臂展 0.855 m（如 7-DoF 协作臂）
        self.success_win = []

    def sample_target(self, base_xy, workspace_corners, num_envs):
        import torch
        if self.stage == 0:
            # 目标全部落在可达域内：末端随机在肩部 0.6 m 内
            ang = torch.rand(num_envs) * 6.2832
            r = 0.2 + 0.35 * torch.rand(num_envs)
            return torch.stack([base_xy[:, 0] + r * torch.cos(ang),
                                base_xy[:, 1] + r * torch.sin(ang)], dim=-1)
        # 阶段 1/2：从工作空间角点内均匀采样（可能超出可达域）
        lo, hi = workspace_corners[0], workspace_corners[1]
        return lo + torch.rand(num_envs, 2) * (hi - lo)

    def reachability_flag(self, base_xy, target_xy, shoulder_offset=0.3):
        # 目标到"肩部"（底盘中心前移 0.3 m 的近似）的水平距离判断
        import torch
        d = torch.linalg.norm(target_xy - base_xy, dim=-1)
        return d < self.reach_radius * self.arm_reach + shoulder_offset

    def update(self, success_rate):
        self.success_win.append(success_rate)
        if len(self.success_win) >= 20 and sum(self.success_win[-20:]) / 20 > 0.7:
            if self.stage < 2:
                self.stage += 1
            self.success_win.clear()

解读：reachability_flag 的输出（布尔量）拼进观测，让策略明确知道"目标现在可达/不可达"，这是"要不要动底盘"的决策依据。可达半径用 reach_radius=0.85（不是 1.0）留 15% 裕度：臂在极限伸展时（奇异附近）几乎无法控制姿态、末端精度也差（第 084 章的教训），所以"物理可达"不等于"工程可达"。shoulder_offset=0.3 m 是底盘中心到肩部的典型前移距离。课程阶段 0 刻意把目标限制在 0.6 m 内，使"移动底盘"暂时变成无用行为，策略先学会"停稳+伸手"，再进入需要移动的阶段；这与第 091 章"先学独立任务"的课程哲学一致。

常见坑

  • 底盘漂移：速度积分（或仿真中轮子滑移）让真实位姿慢慢偏离估计，末端误差周期性变大。修复：里程计噪声与轮子摩擦随机化，观测用带噪声位姿，臂留纠偏能力。
  • 目标坐标系混乱：同一目标一会儿按世界系算误差、一会儿按底盘系下发，误差跳变几十厘米。修复：全链路统一坐标系，转换只在一处发生。
  • 底盘"乱开"：策略发现"漂移底盘"能快速减小末端误差（底盘一动整条臂跟着动），到处乱转。修复：底盘运动小惩罚 + 必要性课程。
  • 忽略时间尺度：底盘与臂都用 60 Hz。修复：底盘 20 Hz、臂 60 Hz 的双频率结构；观测显式给底盘速度。
  • 稳定裕度没进奖励：仿真里轮式底盘不易翻，策略学会"伸满臂 + 急转"，真机危险。修复：裕度惩罚 + 联合限幅，并把 dmargin 最小值作为部署门槛。

练习与思考

  1. 计算：底盘 0.5 m/s、控制周期 20 Hz 时每步移动多少米？这与末端 5 mm 精度要求相比说明什么？★
    提示
    每步 25 mm，是末端精度要求的 5 倍，所以"边动边操作"必须依赖臂的实时纠偏，不能指望底盘精确到位。
  2. 用片段 3 的 reachability_flag 构造 100 个随机目标，统计需要移动底盘的比例，并与训练日志里的"实际移动回合比例"对比。★★
    提示
    几何判断给出的是"物理必要性"下限；策略实际移动更多（有的目标在可达域边缘，移动底盘更省力）是合理的，差异本身就是分析材料。
  3. 把底盘运动惩罚权重提高 5 倍，预测并验证总完成时间与"无必要移动量"的变化。★★
    提示
    权重大 → 底盘更"懒"，能不动就不动，但边界目标会伸到奇异附近导致精度下降、时间变长。用两个指标权衡。
  4. 设计实验：对比"底盘 20 Hz + 臂 60 Hz"与"两者同频率 60 Hz"的训练曲线，解释差异。★★★
    提示
    频率分离更接近真实系统，也让"底盘慢变量"近似成立；同频率训练的策略部署时反而难以迁移到真机。
  5. 复现"边动边操作"：测量操作动作开始时刻与底盘停稳时刻的间隔，比较课程早期（分开做）与后期（学习协调后）的差异。★★★
    提示
    后期策略通常会在底盘减速阶段提前伸臂（利用时间重叠），但切入太早会因基座运动导致末端误差超标，存在最优重叠比例。

小结

  • 移动机械臂 = 非完整底盘 + 机械臂，10 个自由度对 6 维末端任务是冗余系统；"底盘凑近还是伸臂够"是策略要学的高层权衡。
  • 时间尺度分离（底盘慢、臂快）允许双频率控制；底盘积分要用中点法且角度要归一化，否则长回合里会出现厘米级漂移。
  • 稳定裕度 dmargin（重心到支撑多边形边界的距离）与"臂伸展 × 底盘速度"联合限幅是安全骨架；两者都可进奖励与观测。
  • 架构推荐：RL 输出底盘速度 + 末端参考，WBC/底层控制保证安全约束；"目标是否可达"用几何判断作为观测铺进去。
