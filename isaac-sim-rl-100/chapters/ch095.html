第 095 章：实现机器人足球

对抗给多机器人协作加了最强的一味料：对手也在学习和进化。本章把稀疏进球奖励拆成分层技能，用自我对弈让策略在循环克制中保持进步。

  • 主题：系统集成 / 对抗多智能体与分层策略
  • 相关组件：Isaac Sim / Isaac Lab / Stable-Baselines3
  • 预计学时：65 分钟
  • 前置章节：第 094 章

学习目标

  • 理解对抗多智能体任务的三重挑战：稀疏长时程奖励、非平稳对手、部分可观测与信用分配。
  • 掌握分层策略（技能 + 战术）的分解方式，会说清它为什么能缓解稀疏奖励。
  • 掌握自我对弈（self-play）与对手历史池的机制，理解策略循环（rock-paper-scissors）问题。
  • 会设计足球任务的观测、奖励与课程（1v0 → 1v1 → 2v2），并避开可被钻空子的奖励塑形。
  • 能诊断奖励 hack、非平稳训练发散、评估过高等问题。

背景与动机

机器人世界杯（RoboCup）有一条著名的愿景：到 2050 年，一支机器人足球队要能战胜人类世界杯冠军。即使只做简化版 2v2，它也把前面所有章节的能力拧成一股绳：移动与控球（第 043 章）、多智能体协作（第 093/094 章）、对抗与策略，以及最难的，奖励稀疏、对手会变。

与编队不同，足球里"协作"与"竞争"同时存在：你既要与队友配合，又要与对手争夺；且对手与你一样是在学习、在适应的智能体，不能当作环境的固定部分。这个"敌我同江"的设定让训练动态变成博弈问题，这也是本章要引入自我对弈与分层策略的原因。

核心原理

1. 三个叠加的困难

困难具体表现本章对策
稀疏长时程奖励进球才得分，一个回合数百步只有 1 个信号分层策略 + 阶段性塑形 + 课程
非平稳对手对手策略在变，MDP 的转移模型随时间漂移自我对弈 + 历史对手池
部分可观测每台机器人只见局部；队友/对手意图不可见局部观测 + 循环记忆 + 角色信号

三者叠加的后果是：直接用单智能体算法（第 018 章那套）训足球，往往在"全队乱转偶尔蒙进一球"附近长期徘徊。逐个对症下药，才有可能学到有组织的打法。

2. 分层：把稀疏拆成密集

分层强化学习（第 055 章）在这里有了具体形态。把"进球"分解成技能链：

"接近球" → "控住球" → "带球朝门" → "进入射门区" → "射门" 每一级的成功条件都是下一级的输入；单级技能可以单独训练，奖励密集得多

高层策略（战术层）负责选择技能与环境：什么时候追球、什么时候回防、把球传向哪。低层技能（运动层）负责"以多快的速度、从什么角度接近球"这类连续控制。低层技能训练时的奖励是"完成本级目标"，可以跨任务复用，这正是分层相对端到端的最主要红利。

3. 自我对弈：与"过去的自己"比赛

如果对手是固定规则或固定版本，策略很快学会针对它，但会变得脆弱（过拟合到特定对手）。自我对弈的基本循环是：

每一轮训练后把当前策略存入对手池；训练时从池中采样一个历史版本当对手 对手池 = 策略的"记忆"，防止单一对手被过拟合

但自我对弈有著名的病态：策略循环（strategy cycling），新策略克制上一代，上一代的上一代又克制新的（类似猜拳）。对策：对手池足够大、采样偏重近期但不排除老版本；用 Elo 评分跟踪绝对水平，不只看"赢了最新对手"；定期用固定基准策略做绝对标尺。

4. 塑形奖励的陷阱与护栏

为了缓解稀疏，几乎一定会加塑形：接近球、把球推向对方球门方向等。塑形一旦可被"刷"，策略就会钻空子。经典的两条护栏：

护栏一：塑形项只奖励"状态的改善"，不奖励"状态本身"（差分式塑形，与第 072 章一致） 护栏二：塑形项的总量要显著小于进球奖励（建议 ≤ 0.2 × 单个进球）

例："球向对方门方向的速度分量"就是易被刷的量，机器人可在自家半场反复推球制造正投影。改成"球到对方球门距离的减少量"（差分）后，必须真的逼近才有奖励。"接近球"的奖励也要排除"对手控球时你也去接近"的情形。

5. 对称性与样本效率

足球场是中心对称的：把两队的进攻方向对调，任务结构完全一样。训练时可以利用这一对称性做数据增强：把同一局面的坐标做 180° 旋转 + 队伍交换，得到一条等价训练样本，等效把样本量翻倍。同理，队友之间的策略可以共享参数（同构智能体，第 093 章的参数共享），再把"我是几号位"编码进观测（角色信号）。

实现思路与设计

  1. 任务：2v2 简化足球。球场 6 m × 4 m，球为圆形刚体，机器人用底盘推动球（无踢球动作），把球推进对方球门；回合 60 秒或进 3 球。
  2. 观测（每台）：局部半径 3 m 内的球/队友/对手的相对位置与相对速度（聚合为定长特征，见第 094 章）；自己球门与对方球门的角度距离；自己在队伍中的角色编码（0=守、1=攻）。
  3. 动作：底盘速度 (v, ω) 2 维，v≤0.8 m/s（比编队快，足球要求机动性）。
  4. 奖励：进球 ±1（团队）；差分塑形：球到对方球门距离的减少量 ×0.05；失分预警：对手控球时球到自己球门距离减少量 ×(−0.05)；控制惩罚：机器人-球距离的持续过大不罚、但"球被对手控制"要被感知（观测信号）。
  5. 技能层：先用单机器人训练三个技能，"追球并面向球门"、"推球直线前进（带球）"、"射门（近距离推球进角度窗口）"。技能以固定策略或参数化控制器形式提供，战术层（RL）选择调用。
  6. 自我对弈：从规则型基准开始，每 500 万步把当前策略存入对手池（上限 20 个），采样时近期版本概率 ×2；每轮用固定规则对手与历史池各评一次胜率，记 Elo。
  7. 课程：1v0 空场带球射门 → 1v1 防守者半速 → 1v1 全力 → 2v2。
设计思维：为什么"全场乱转"是分层前的常态？

没有技能分解时，一条"追球，转身，推球，进球"的完整链路要等一整回合才可能有 +1 信号，而中间的每一步都缺少独立反馈，信用分配被稀释到几乎为零。分层把"哪一步错了"变成了可判定的短链问题：带球技能不需要理解战术，射门技能不需要理解防守，这正是"模块化降低学习复杂度"的物理直觉，与第 089 章把拦截点铺进观测是同一类先验注入。

关键代码与解读

片段 1：差分塑形与奖励护栏

import torch

class SoccerReward:
    """2v2 足球奖励：稀疏进球 + 差分塑形（防钻空子）。"""

    def __init__(self, shape_gain=0.05, goal_bonus=1.0, concede_penalty=1.0):
        self.shape_gain = shape_gain      # 塑形系数：≤ 0.2 倍进球奖励
        self.goal_bonus = goal_bonus
        self.concede_penalty = concede_penalty

    def compute(self, ball_pos_now, ball_pos_prev, own_goal, opp_goal,
                scored_team, conceded_team, own_ball_control):
        # 差分塑形：球到对方门"距离的减少量"；注意用差分，不用绝对距离
        d_now = torch.linalg.norm(opp_goal - ball_pos_now, dim=-1)
        d_prev = torch.linalg.norm(opp_goal - ball_pos_prev, dim=-1)
        progress = (d_prev - d_now).clamp(min=-0.05, max=0.05)   # 限幅防瞬移条纹
        r_shape = self.shape_gain * progress
        # 只有"我方实质控球"时才给推进奖励，否则双方谁碰球都加分会鼓励群追
        r_shape = torch.where(own_ball_control, r_shape,
                              torch.zeros_like(r_shape))
        # 稀疏主奖励：进球 +1 / 丢球 -1（团队级，广播给所有本队个体）
        r_goal = self.goal_bonus * scored_team.float() \
                 - self.concede_penalty * conceded_team.float()
        return r_shape + r_goal

解读：三处护栏，缺一不可。（1）clamp(±0.05)：限幅不仅防数值异常，更防"一帧内球瞬移"（重置边界、物理穿透）被当成史诗级推进；（2）own_ball_control 门控：没有它，只要球朝对方推进，哪怕是对方自己运球，双方都加奖励，形成互相刷分的病态；（3）用差分量替代绝对值：绝对距离奖励会让球"停在原地离门近"成为最优解，差分保证了每份奖励都对应"真的更接近进球"的行为变化。shape_gain=0.05 与进球 1.0 的比例（5%）是经验值：足以引导探索，小到策略无法靠刷塑形放弃进球。

片段 2：分层接口，战术选择与技能执行

class StrikerPolicy:
    """战术层示例：输出技能索引与技能参数；技能层用简单控制器执行。
    训练战术层时，技能层冻结（或作为环境的一部分）。"""

    SKILLS = ["intercept_ball", "dribble_to_goal", "shoot", "return_defend"]

    def __init__(self, skill_controllers):
        # skill_controllers: dict[skill_name -> 可调用控制器]
        # 例如 shoot 技能是"对准门角 + 全速推球"的参数化控制器（解析或小网络）
        self.skills = skill_controllers

    def act(self, high_obs):
        # 高层动作 = (技能索引 k, 技能参数 p)：离散 + 连续混合动作空间
        logits, p = self.high_net(high_obs)          # 高层网络输出
        k = torch.distributions.Categorical(logits=logits).sample()   # 选技能
        # 逐个环境调用对应技能控制器：教学版用循环，生产版按索引向量化
        cmds = []
        for b in range(high_obs.shape[0]):
            skill = self.SKILLS[int(k[b])]
            cmds.append(self.skills[skill](high_obs[b], p[b]))
        return torch.stack(cmds), k, p

    def high_reward(self, ball_to_goal_dist, possession, scored, conceded):
        # 高层奖励 = 稀疏进球 + 每步微小的控球推进（差分已在外部算好）
        return scored.float() - conceded.float()

解读：（1）混合动作空间（离散技能索引 + 连续参数）在足球战术层非常自然，"做什么"离散、"做多用力"连续；（2）技能层冻结后，战术层的搜索空间从"每秒 30 维连续控制"变成"每秒 4 个选项"，学习难度数量级下降，这正是第 055 章分层思想的具体收益；（3）act 里的 Python 循环是教学版，生产实现按技能索引做 batched 选择。

片段 3：自我对弈的对手池与 Elo 跟踪

import random

class SelfPlayPool:
    """对手池：保存历史策略快照，按"近期加权"采样。"""
    def __init__(self, max_size=20, recent_bias=2.0):
        self.pool = []                    # 每个元素 = 策略快照（state_dict 或路径）
        self.max_size = max_size
        self.recent_bias = recent_bias    # 近期版本的采样权重倍数
        self.elo = {}                     # 版本号 -> Elo 评分

    def add(self, policy_state, version):
        if len(self.pool) >= self.max_size:
            self.pool.pop(0)              # 淘汰最老版本（也别忘了它的 Elo 归档）
        self.pool.append((version, policy_state))
        self.elo[version] = self.elo.get(version, 1200)   # 新版本从 1200 开始

    def sample(self, rng):
        n = len(self.pool)
        # 权重：版本越新越容易被选中（线性加权），但不排除老对手
        weights = [(i + 1) ** 1.0 * (self.recent_bias if i >= n - 3 else 1.0)
                   for i in range(n)]
        total = sum(weights)
        r = rng.random() * total
        acc = 0.0
        for (ver, state), w in zip(self.pool, weights):
            acc += w
            if r <= acc:
                return ver, state
        return self.pool[-1]

    def update_elo(self, ver_a, ver_b, score_a, k=16):
        # score_a ∈ {1, 0.5, 0}：标准 Elo 更新；Elo 是"绝对水平"的代理指标
        ea = 1.0 / (1 + 10 ** ((self.elo.get(ver_b, 1200) - self.elo[ver_a]) / 400))
        self.elo[ver_a] += k * (score_a - ea)
        self.elo.setdefault(ver_b, 1200)
        self.elo[ver_b] += k * ((1 - score_a) - (1 - ea))

解读：（1）sample 的权重设计：基础权重随版本线性增长（新版本更常被练），但最近 3 个版本再乘 recent_bias=2，这模仿了"棋类训练里既练最新着法、也偶尔翻旧谱"的经验；（2）Elo 更新的作用是监测绝对水平：如果 Elo 停滞而训练曲线（对最新对手的胜率）在涨，说明陷入了循环克制，这是自我对弈最常见的"假进步"；（3）版本号键控 Elo 需要与策略快照一起归档，否则赛季长了会乱。

常见坑

  • 塑形被刷：不加 own_ball_control 门控时，双方对着"球朝门推进"互相刷分。症状是比赛场面热闹但进球数停滞。修复：门控 + 差分 + 限幅（片段 1）。
  • 对手固定不变：训练对手是规则基准，策略学会专杀它的"套路"，遇到新对手立刻失效。修复：自我对弈池 + 用池中老版本做周期性评估。
  • 评估用训练对手：对最新对手胜率 90%，对规则基准却只有 55%，自我对弈的"相对进步"不等于绝对变强。修复：固定基准 + Elo 双轨评估。
  • 训练时给全局观测：部署时只有局部（半径 3 m），能力断崖。修复：训练就用局部观测 + 聚合特征；给循环网络记忆（第 061 章）。
  • 队伍视角不对称：忘了做 180° 旋转的数据增强/视角统一，政策学到"主场优势"而无法泛化到另一边。修复：统一把"我方进攻方向"旋转到 +x 方向的规范视图，再做所有计算。
  • 搭便车与"守门员发呆"：纯团队奖励下，某个角色学会"什么都不做"（预期收益≈0）而进攻手承担全部风险。修复：角色化的局部奖励（守门员的"封堵角度"等），或按贡献重加权。

练习与思考

  1. 给片段 1 的差分塑形再做一次"对抗性审计"：写出至少一种可以刷分但不利于赢球的行为，并给出对应的护栏修改。★★
    提示
    例：把球推离对方球门再拉近（制造距离差）；护栏 = 只累计单调改善或对"倒退"也对称扣分。审计思路来自第 072 章的奖励塑形。
  2. 设计 1v0 → 1v1 → 2v2 的课程切换判据：用哪三个指标决定升级？★★
    提示
    建议：射门成功率、平均控球时长、对抗下丢失球的次数；三个都达标才升级（避免单一指标虚高）。
  3. 实验：对手池大小取 1（只用最新版本）与 20，比较 Elo 曲线与对规则基准的胜率。★★★
    提示
    池=1 时策略循环明显（Elo 抖动、对基准胜率周期性回落）；池=20 时更稳。用训练全程的 Elo 方差量化。
  4. 把角色编码从观测中移除再训练 2v2，观察"守门员是否还待在后场"。★★
    提示
    没有角色信号时，同构策略容易"双双压上"或者"双双跟球"；用每台机器人平均 y 坐标分布（前场/后场占比）来量化。
  5. 实现 180° 旋转数据增强：对每个采样的回合状态，生成镜像样本并验证策略的等价性（动作应为对应的镜像动作）。★★★
    提示
    对 (v, ω) 动作，180° 旋转下 v 方向反向、ω 保持不变；检查网络对镜像输入输出的对称误差来验证实现正确。

小结

  • 足球 = 多机器人协作 + 竞争 + 部分可观测：稀疏奖励、非平稳对手、信用分配三重困难叠加。
  • 分层是稀疏奖励的正解：技能（追球/带球/射门）单独可训、可复用；战术层在离散技能空间里学习，搜索维度骤降。
  • 自我对弈用历史池对抗策略循环；Elo + 固定基准做绝对水平评估，警惕"相对进步、绝对退化"。
  • 塑形护栏三条：差分、门控（控球判定）、限幅；塑形总量 ≤0.2 倍进球奖励；旋转对称性可做数据增强。
  • 下一章换平台：从轮式地面机器人跳到空中，四旋翼是欠驱动系统，控制结构与之前所有章节都不同，见第 096 章。
