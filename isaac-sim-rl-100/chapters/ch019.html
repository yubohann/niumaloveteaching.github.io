第一篇 · 仿真环境与训练框架

第 019 章：实现自定义奖励函数

奖励函数是任务的完整规范：把"我们想要机器人做什么"翻译成数学。学会拆解奖励分量、对齐量纲、监控每项贡献，并识破"策略钻空子"的经典模式。

  • 主题：强化学习 / 奖励设计与调试
  • 相关组件：Isaac Sim 环境、SB3 训练日志（TensorBoard）
  • 预计学时：55 分钟
  • 前置章节：第 018 章

学习目标

  • 理解"奖励即任务规范"：不在奖励里的目标，对智能体而言不存在；每一项目标都必须显式编码。
  • 掌握奖励分量的分解方法：距离、进度、动作代价、姿态对齐、成功奖励各自的公式与适用场景。
  • 会给各项对齐量纲与量级，并按"时间归一"的原则设计跨决策频率可比的奖励。
  • 会实现分项奖励日志，用贡献比例定位"哪一项在主导行为"。
  • 能识别常见的 reward hacking（奖励钻空子）模式，并设计反制实验。

背景与动机

前面章节的奖励都很朴素：Cartpole 每步 +1，Reach 每步 −d 加成功奖励。真实任务远不止一个目标：既要到达目标、又要动作平滑、还要省电、还要不撞桌子。这些诉求无法塞进一个 −d，必须组织成多分量奖励。

更根本的是：智能体是"极端字面主义"的优化器，它忠实地优化你写下的每一个字；你心里想要但没写下的目标，它不会去猜。奖励写偏了，它会找到你没预料的实现路径（reward hacking）。本章教你把"想要的"翻译成"写下的"。

核心原理

1. 奖励的分量结构

多目标任务的奖励通常写成若干分量（term）的加权和：

rt = Σi wi · fi(st, at, st+1) w_i 是权重，f_i 是每个分量的物理表达；权重调节"各目标的相对优先级"

机械臂任务里的经典分量（以到达/推挤类为例）：

分量公式（示意）典型权重作用与风险
距离项−‖pee − pgoal‖1.0稠密引导；量级需与成功奖励匹配
进度项−(dt − dt−1)，即"靠近为正"0.5–2.0直接奖励"朝目标移动"；与距离项部分冗余，选其一或调低权重
动作幅度−‖a‖²1e-3 量级省力、平滑；过大导致"不敢动"
动作变化−‖at − at−1‖²1e-3 量级抑制抖动；同样防止"僵住"要小
姿态对齐−(1 − |⟨qee, qdes⟩|²)0.5抓取类必要；注意四元数符号约定
成功奖励+5（一次性，随后终止）5–10稀疏锚点；过大诱发"赌一把"行为

两条原则：第一，别重复惩罚同一件事，距离项与进度项高权重并用时，"原地晃动"会被进度项中性对待，实际偏好难以推理；第二，每个"禁止行为"都要显式给负项；"别撞桌子"若不写进负项，撞桌在距离项里甚至会被计成"更近"。

2. 量纲与时间归一

三个工程细节。第一，各分量先无量纲化：距离（米，典型 0.5）、动作范数平方（典型 7）、对齐度（0–1）直接乘权重时，1e-3 与 5 的差别来自量纲换算，与偏好无关。把分量压到 O(1) 内，权重才真正表达优先级。第二，按时间归一：同样的物理行为，decimation=2 与 4 时"每步奖励"相差两倍，跨决策频率的实验不可比。把奖励定义为"每秒"量（每步乘 decimation·dt），或者在做对照实验时固定 decimation 并记录口径。第三，成功奖励与稠密项的比例要匹配视野：gamma=0.98 下 50 步前的 +5 折现后仅剩约 1.8；成功奖励必须显著高于"磨蹭接近但从不成功"的累计收益，否则策略宁可不成功。

3. Reward Hacking：智能体钻空子的三种经典剧本

  • 僵住策略：动作惩罚过大（比如权重 0.05），"站着不动"比"移动接近"更划算。症状：成功率长期 0、动作范数单调下降。修复：动作惩罚权重压回 1e-3，并对策略做"动作幅度下界"统计。
  • 原地振荡：进度项权重相对距离项过高时，策略学会"来回穿越目标点附近"反复领取正向进度（贴现下有利可图）。修复：降低进度权重、提高 gamma 让"最终到达"更受重视，或改用势函数塑形（020 章证明振荡无法套利）。
  • 危险冲刺：成功奖励与失败惩罚比例失衡，策略学会"全速冲一把"，成功率方差极大、平均表现差。修复：调整奖惩比例（如失败 −3 / 成功 +5），评估时同时报告最差回合。

把第二条剧本的账算一遍会有反直觉的发现。设进度项权重为 wprog、策略每步换向、单步距离变化幅度为 δ，则无限折扣下振荡策略从进度项提取的总收益为 wprog·δγ/(1+γ)，γ 趋近 1 时上限趋近 wprog·δ/2。取极端抖动 δ=0.2 m、wprog=2，提取量只有约 0.20，远小于成功奖励折现后的 1.82；普通抖动 δ=0.02 m 时只剩约 0.02。可见振荡在账面并不胜过"到达"，它真正胜过的是"僵住"（僵住的进度收益恒为 0）。振荡成为最优可行选择的场景是：成功信号几乎兑现不了（成功率长期接近 0），策略退而求其次，保住一个恒正的小收益。因此看到目标附近抖动时，先查成功奖励的折现有效值与实际成功率，再谈调整进度权重。

反制共性：把奖励分项日志化，用数据说话。每项贡献占比一算便知谁在主导行为；再配合"想要的 vs 得到的"差异分析，就能在训练早期定位剧本。

4. 分项日志与消融实验

实践：compute_reward() 返回 (total, terms_dict)，累计进 info 与 TensorBoard，训练异常时能回答"哪一项爆了"。配套消融（ablation）：对每个分量做权重对照训练，只比任务指标，不同奖励函数下的回报永不可比。

5. 权重灵敏度的量化：为什么 1e-3 与 1e-2 是两个世界

动作惩罚从 1e-3 调到 1e-2 看起来只差十倍，行为却可能完全翻转。用单步收支算清楚。均匀随机动作在 7 维上的范数平方期望：

E[‖a‖²] = 7 × E[a²] = 7 × (1/3) ≈ 2.3（a 在 [−1, 1] 上均匀） 动作惩罚的典型值 = w_act × 2.3；w_act = 1e-3 时约 0.0023，1e-2 时约 0.023

再看移动的收益：以有效接近速度 0.3 m/s 计，单步（1/30 s）缩短距离约 0.01 m，距离项的改善也是 0.01。两个数一对比，翻转条件立刻出现：

移动占优 ⇔ 0.01 > wact × 2.3 ⇔ wact 小于约 0.004 w_act = 1e-3 时移动明显占优；0.01 时已越界，行为趋近静止；0.05 时原地不动成为占优策略

这就是"辅助项压到 1e-3 量级"的算术依据：它是"单步收益"与"单步代价"的比较结果。同样的方法可以用于任何辅助项：先估计它的典型值与主目标的单步收益，再确定安全上限。翻转线还会随任务基线速度移动：接近速度降到 0.1 m/s 时单步收益只有 0.0033，翻转线同步降到约 0.0014，慢任务里"更小的辅助权重也可能压住主目标"。顺带对齐一个记号：第 1 节表里的"典型 7"是动作饱和（每维 ±1）时的上界，均匀随机动作的期望是 2.33，相邻两步独立动作差值的期望平方是 4.67；做安全上限估计用 7，做平均收支估算用 2.33，两种取值差三倍，混用会让安全上限算得偏松或偏紧三倍。

7. 完整算例：三种策略的折扣回报核算

把前面的原则串成一个可复算的例子。配置：Franka 七自由度到达任务，控制频率 30 Hz（decimation=2，物理步 1/60 s），wdist=1.0、wact=1e-3、成功奖励 +5、γ=0.98，起始距离 d0=0.5 m，回合上限 200 步；折扣回报 G = Σt γt rt，动作项按每步 ‖a‖²≈0.5 估计（动作向量范数约 0.7）。三种策略的账面如下。

策略距离项成功奖励动作项回报合计结局
A 僵住（d 恒为 0.5）−24.560≈0−24.56失败
B 匀速（0.01 m/步，50 步到达）−9.42+1.82−0.02−7.62成功
C 爬行（0.005 m/步，100 步到达）−14.37+0.66−0.02−13.73成功

三个数字各有来历。僵住策略的距离项是等比级数：−0.5×(1−γ200)/(1−γ)=−0.5×49.12=−24.56。有效策略运行 50 步、距离线性递减到 0，逐项求和得 −9.42，比"距离恒为 0.5 走 50 步"的估计（−15.90）高 6.48，接近行为本身在距离项里就有回报；成功奖励在第 50 步领取，折现后仍有 5×γ50=1.82；动作项因为权重只有 1e-3，全程仅 −0.02。爬行策略要付"每多走一步就被折扣与距离项双重削弱"的代价：晚 50 步到达使成功奖励缩到 0.66，距离项累计也更差。

读表得到两条可迁移的结论。第一，稠密项与稀疏项的分工在数字上很清楚：B 比 A 高出 16.94，其中 15.14 来自"更早把距离拉近"，1.82 来自成功奖励；也就是说在 γ=0.98 下学习早期主要由距离项驱动，成功奖励是收尾阶段的边际信号。第二，效率的回报是可以计算的：B 比 C 高出 6.11，其中距离项差 4.95、成功折现差 1.16；如果希望策略"尽快完成"，这 6.11 就是速度激励的上限量级，把它与评估指标（完成时间中位数）对照，能判断当前 γ 与成功奖励是否给足了速度激励。表里所有数字都能用同样的逐项求和方式复算，改动 γ 或起点距离就能得到新表。

8. 边界与失效模式

多分量奖励在四类边界上会变质，逐一给出判据与修复。

  • 成功半径小于单步位移：0.01 m/步时，半径 0.02 m 的判定窗口只有 2 步宽；半径压到 0.005 m 后，策略可能整步跨过成功区而不被判定，成功率对控制相位极度敏感。判据：成功半径不小于 2 倍单步位移；达不到就把成功判定放到更快的物理子步上执行。
  • 非有限值：距离趋零时方向向量未定义、四元数未归一化时除法趋零，都会让分量变成 NaN；NaN 一旦进入回放缓冲区，价值网络整个失效。修复：在 compute 里用 np.isfinite 掩码把坏项置 0 并计数，计数持续不为零说明上游数据有待修的问题。
  • 截断与终止混淆：时间上限触发的截断不是失败，框架若不给截断回合做价值引导（bootstrap），价值函数会把"回合结尾"一律学成负信号。修复：训练循环区分 done 与 truncated，参照所用框架对时间限制的处理约定逐项核对。
  • 奖励尺度漂移的连锁反应：权重改动十倍后，回报的均值与方差整体变化，价值网络、学习率、优势估计的最优匹配全部改变。修复：每次奖励变更记录回报均值与标准差，必要时对回报做固定缩放，让量级稳定在 O(1)。

还有一个概率性的边界：进度项在接近速度为零时没有信号（前后两步距离相同，进度为零），若任务的最后阶段必须"零速微调"，进度项帮不上忙，只剩距离项提供梯度。设计时让两类信号共存，互为兜底。

9. 修订策略的对照表

剧本检测指标首选修复代价

修复任何一项都要回到消融协议：单变量、多种子、固定评估种子、只比任务指标。修订前后的对比数字写进实验记录，下一次遇到类似症状时从这张表起步。

最后给一条实践顺序：先让主目标单独跑通（成功率超过 50%），再逐项加入辅助分量，每加一项都记录贡献占比与任务指标的变化；一次性把所有分量全开会显著抬高定位成本。奖励函数是逐步长出来的，需要多轮实验打磨。实践中最常见的疏漏是把权重改了好几轮却只记得最后一轮的数值；把每一轮的权重、贡献占比与任务指标成套保存，既方便回溯，也让"哪个版本更好"的讨论有据可查。这套记录方式在 020 章的退火调试里同样适用：w(t) 的时间表要能从记录里重建。

实现思路与设计

为你的任务设计奖励函数的步骤：

  1. 列目标清单（必须到达、动作平滑、省力、不碰撞、姿态正确，逐条写成句子）。
  2. 每条翻译成分量函数（优先用物理量；禁止项显式给负项）。
  3. 无量纲化（把每个分量的典型值压到 O(1)，注释里写典型值）。
  4. 定权重初值（主目标 1.0，辅助 1e-3–0.5，成功奖励按 2 节的比例算）。
  5. 分项日志（terms 字典进 info；回合统计存档）。
  6. 消融与调参（每次只动一个权重，固定评估种子，用任务指标比较）。
设计思维：为什么奖励函数要写成"纯函数 + 字典返回"？

纯函数让你可以离线构造输入、做单元测试；字典返回让每项贡献天然可观测、可记录、可消融。反过来，把奖励写成一大坨混合运算、只返回一个总数，等于主动放弃"诊断能力"，训练出问题时你只能猜。015 章写奖励时留下的 alive 参数、016 章的独立判定函数，都是这条思路的延续。

关键代码与解读

片段 1：多分量奖励函数的实现

import numpy as np

class ReachReward:
    """到达任务的奖励：距离 + 动作代价 + 动作变化 + 成功奖励，分项可查。"""
    def __init__(self):
        self.w_dist = 1.0        # 主目标：距离权重（米制量，典型 0.5）
        self.w_act = 1e-3        # 动作幅度：抑制大力挥动，量级必须小（见 3 节剧本一）
        self.w_dact = 1e-3       # 动作变化：抑制抖动；同样小
        self.bonus = 5.0         # 成功奖励：按 2 节折现比例选值
        self.prev_action = np.zeros(7)

    def compute(self, p_ee, p_goal, action, success):
        d = float(np.linalg.norm(p_ee - p_goal))        # 距离（米）
        act_pen = float(np.sum(np.square(action)))       # 动作幅度平方：典型 0-7
        dact_pen = float(np.sum(np.square(action - self.prev_action)))  # 变化平方
        self.prev_action = np.asarray(action).copy()     # 记录供下一步使用；copy 防别名
        terms = {
            "distance": self.w_dist * (-d),               # 典型 -0.5 到 0
            "action": self.w_act * (-act_pen),            # 典型 -0.007
            "action_delta": self.w_dact * (-dact_pen),    # 典型 -0.007
            "success": self.bonus if success else 0.0,    # 一次性大项
        }
        return float(sum(terms.values())), terms          # 总数 + 分项：诊断的原材料

解读：这段代码把 1、2 节的原则逐项落地。注意每个分量都带"典型量级"注释，这不是装饰：action 项的量级必须比距离项小两三个数量级才能表达"省力是次要目标"；若写成 w_act=0.1，动作惩罚典型值 −0.7 与距离项 −0.5 相当，"不动"立刻成为占优策略。成功奖励 5.0 的取值依据在 2 节算过：折现后仍显著高于稠密项累计。self.prev_action.copy() 与 007 章 EMA 的坑同源，不拷贝的话，外部若原地修改 action 数组会污染内部记录。最后返回 (total, terms) 这个二元组是整个设计的关键：调用方拿总数做学习，拿字典做日志与调试。

片段 2：分项日志接入训练循环

import numpy as np
from collections import defaultdict

class TermLogger:
    """奖励分项的回合统计器：累计 → 回合结束归档 → 清零。"""
    def __init__(self):
        self.episode_acc = defaultdict(float)   # 本回合各项累计
        self.history = []                       # 历史回合计录

    def add(self, terms):
        for k, v in terms.items():
            self.episode_acc[k] += float(v)     # 逐项累加：保留每项的贡献

    def end_episode(self, extra):
        record = dict(self.episode_acc)         # 冻结本回合数据
        record.update(extra)                    # 追加任务指标（成功率、最小距离等）
        self.history.append(record)
        self.episode_acc.clear()                # 原地清空而不换对象：保持引用稳定

    def contribution_ratio(self):
        """最近 N 个回合里各项贡献的占比：谁在主导行为，一眼可见。"""
        if not self.history:
            return {}
        n = min(len(self.history), 50)
        keys = [k for k in self.history[-1] if k not in ("is_success", "steps")]
        totals = {k: sum(h.get(k, 0.0) for h in self.history[-n:]) for k in keys}
        grand = sum(abs(v) for v in totals.values()) + 1e-9
        return {k: round(v / grand, 3) for k, v in totals.items()}

解读：TermLogger 解决"事后归因"问题：训练曲线告诉你回报是多少，分项贡献告诉你回报由什么构成。contribution_ratio 用绝对值之和做分母（因为各项有正有负）：如果输出 {"distance": 0.9, "action": 0.02, "success": 0.08}，说明行为由距离项主导、动作代价可以忽略，符合设计意图；若 action 占比蹿升到 0.4，就是剧本一的预警。episode_acc.clear() 原地清空内容，保持对象引用，让别处持有的引用仍然指向"当前累计器"（重新赋值会替换对象；与 011 章 EnvState.clear() 同一习惯）。这套日志在 021 章做域随机化对照时会直接复用，那时的实验维度更多，归因能力更值钱。

片段 3：权重消融的实验协议（骨架）

import itertools
import numpy as np

def run_ablation(make_env, train_fn, evaluate_fn, base_weights, variations, seeds=(0, 1)):
    """对每个权重变体训练并评估：固定其余条件，只动一个权重。"""
    results = []
    for term, values in variations.items():          # 例如 {"w_act": [0.0, 1e-3, 0.05]}
        for v in values:
            scores = []
            for seed in seeds:                       # 多种子：单次结果不作数（018 章纪律）
                weights = dict(base_weights)
                weights[term] = v                    # 只改一个权重
                env = make_env(weights, seed=seed)
                model = train_fn(env, seed=seed)     # 相同的训练预算与算法配置
                scores.append(evaluate_fn(model, seed=9000))  # 固定评估种子集
            results.append({
                "term": term, "value": v,
                "success_mean": float(np.mean(scores)),
                "success_std": float(np.std(scores)),
            })
            print(f"{term}={v:<8} 成功率 {np.mean(scores):.0%} ± {np.std(scores):.0%}")
    return results
# 比较口径：任务指标（成功率、最小距离）；绝不比较训练回报，它依赖奖励定义本身

解读：这个骨架把"奖励调参"从玄学变成可复现的流程。三个纪律写在代码结构里：只动一个变量（内层循环每次只改一个权重）；多种子重复（每个变体至少 2–3 个种子，报告均值±标准差）；固定评估种子集（seed=9000 起，与训练种子无关）。最后的注释是全章最重要的警告：不同奖励定义下训练回报的数值不可比，把 w_act 从 1e-3 改到 0.05，回报可能"上升"而任务成功率崩掉，因为回报的计算方式变了。评估只认任务指标。

常见坑

  • 辅助项权重过大：动作/能耗惩罚压过主目标，策略选择"僵住"或"躺平"。修复：辅助项典型量级 O(1e-3)，用贡献比例日志监控。
  • 用训练回报比较不同奖励设计：回报依赖奖励定义，比较毫无意义。修复：统一用任务指标（成功率、完成时间、最小距离）做所有对照。
  • 禁止行为没有负项：撞击、越界在距离项里甚至可能"更近"，策略学会钻空子。修复：对每个禁止行为写显式惩罚项，并构造针对性测试场景验证。
  • 成功奖励和折扣不匹配：奖励给得太小（折现后近乎为零）时策略无视成功条件。修复：按 2 节计算折现后的有效值，保证它显著高于稠密项的最大累计差。
  • 忽略时间归一：decimation 变化后奖励口径改变，旧实验不可比。修复：奖励按"每秒"定义或固定 decimation 并写入实验记录。
  • 回合边界不重置动作记忆：动作变化项用的 prev_action 若跨回合保留，每回合首步会按上一回合末的动作算出伪惩罚尖峰。修复：在 reset() 里把 prev_action 清零（或置为首步动作），并在日志里单独统计首步贡献。
  • 方向类分量在重合点除零：奖励或观测里若出现 (pee − pgoal)/‖pee − pgoal‖ 这类单位方向，目标重合时产生 NaN。修复：分母加 1e-6 下限，或在距离小于阈值时用 np.where 把方向项置零。

小结

  • 奖励是任务的完整规范：写下的才是要优化的；多目标 = 多分量加权和，禁止行为要显式负项。
  • 先无量纲化再谈权重；辅助项保持在 1e-3 量级；成功奖励按折扣视野核算有效值；奖励口径按时间归一并写入实验记录。
  • 返回"总数 + 分项字典"、记录贡献比例：分项日志是定位异常与反制 reward hacking 的第一工具。
  • 调参协议：单变量、多种子、固定评估种子、只比任务指标，绝不比较训练回报数值。
