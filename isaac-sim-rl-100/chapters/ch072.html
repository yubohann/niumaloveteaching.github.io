第 072 章：实现奖励塑形

把稀疏的"成功给一分"改造成有梯度的回报地形：本章讲透势函数塑形（PBRS）为什么能保持最优策略不变，以及多目标奖励的配平、写账与防作弊。

  • 主题：奖励设计 / 塑形理论与多目标配平
  • 相关组件：Isaac Sim / Isaac Lab / PPO / 自定义奖励项
  • 预计学时：55 分钟
  • 前置章节：第 071 章

学习目标

  • 说清稀疏奖励为什么难学，以及"加中间奖励"什么时候安全、什么时候改变最优解。
  • 掌握势函数奖励塑形（PBRS）的公式 F = γΦ(s′) − Φ(s) 与策略不变性定理的直觉证明。
  • 会用"到目标的距离取负"构造最常用的塑形势函数，并正确处理终止状态与时间限制。
  • 会给多目标奖励（进度、成功、能耗、平滑）配平量纲，并逐项记录账目。
  • 能识别并修复典型的奖励塑造失败：绕圈刷分、悬停不碰、冲刺摔落、终止重复计分。
  • 会设计 A/B 实验验证塑形只加速学习、不改变最优行为。

背景与动机

最诚实的奖励是"任务成功给 1 分，其余 0 分"。数学上它没有偏置，策略学到什么就是任务要求的。但学习效率灾难性地低：抓取任务里，随机策略摸索到合格抓取的概率可能是百万分之一，梯度信号在成功之前完全为零；第 071 章的探索手段能帮忙，但对付复杂操作任务往往不够。

奖励塑形（reward shaping）的思路是给策略"沿途的路标"：靠近目标给一点奖励、远离扣一点。风险也随之而来，随意的路标会改变任务的真实目标：如果你给"手靠近杯子"发奖励，策略可能学会的是"悬停在杯子旁边"，"抓起来"则学不到。本章先讲清"什么样的塑形是安全的"（势函数塑形定理），再讲工程上怎么把进度、成功、能耗、平滑等多个目标配成一张梯度良好又不作弊的回报地形。它是第 019/020 章的深化：那两章给了直觉，这一章给理论与账务纪律。

核心原理

1. 塑形的安全性问题：什么能被加、什么会被改

原始奖励 r(s, a)，塑形后 r′ = r + F(s, a, s′)。我们关心两个性质：策略不变性（学到的最优策略仍是原任务的最优策略）与收敛加速（值函数更容易估准、梯度更早出现）。任意 F 都会改变最优解的风险，但有一类 F 被证明不改变，势函数塑形。

2. PBRS：势函数塑形与策略不变性定理

取任意标量函数 Φ: S → R（"势能"，例如到目标距离的负值），塑形奖励：

F(s, s′) = γ · Φ(s′) − Φ(s) Ng, Harada & Russell (1999) 证明：F 为该形式时，对任意 MDP 与任意 γ∈[0,1)，最优策略集不变

不变量为什么成立？看一段轨迹的累积塑形奖励：

Σt=0..T−1 γt F(st, st+1) = γTΦ(sT) − Φ(s0) 逐项相消（望远镜求和）：γΦ(s₁)−Φ(s₀) + γ²Φ(s₂)−γΦ(s₁) + … 只剩首尾

关键在 γ 系数与折扣系数的精确对齐：每一项 γt(γΦ(st+1) − Φ(st)) 展开后中间项完全抵消。于是总塑形回报只差一个与策略选择无关的常数 −Φ(s₀) 加上末端项 γTΦ(sT)。如果 sT 是终止状态且 Φ(终止)=0（或所有回合末端的 Φ 相同），那部分也成了常数，任何两条策略的回报差完全由原奖励决定，最优策略自然不变。这就是"安全的塑形"的全部秘密：奖励只发"势能的变化量"，而"势能的高低"本身不发钱。

反过来，直接发 Φ(s) 或距离奖励（"离目标近就加分"）是危险的：策略可以找到"低势能打转"的循环路线无限刷分。一个小实验最能说明问题：若塑形项是 +1·(距离减少)，策略学会"来回逼近-后退"抖动刷分；换成 γΦ(s′)−Φ(s)，同样抖动一圈的净和为 0，刷分通道被数学封死。

3. 终止状态与时间限制：两个常见的"漏气点"

定理的两个前提在工程里最容易破：其一，终止状态的势能。如果 Φ(sT) ≠ 0 且不同回合的终止方式（成功/超时/跌落）对应不同的 sT，那 γTΦ(sT) 不再是常数，最优策略可能被改变。处理：塑形项在终止转移上直接置 0，或者把所有终止状态接进 Φ 时小心定义（成功终点 Φ=0，跌落终点 Φ=0，只有"过程状态"有非零势能）。其二，时间限制（time limit）的截断。Isaac Sim 里回合一到上限就截断，这不是真正的终止；如果用 γΦ(s′) 记账而值函数对截断状态 bootstrap，塑形和 bootstrap 的折现口径要一致，否则塑形会悄悄改变"拖到超时"与"尽快成功"之间偏好。工程习惯：截断转移按非终止处理（照常 bootstrap），塑形项照常计算，与第 011 章的重置逻辑保持一致。

4. 距离势函数：最值钱的 10 行代码

操作任务的默认选择：Φ(s) = −d(s)，d 为末端到目标的欧氏距离。代入得 F = γ(−d′) − (−d) = d − γd′，即"距离缩短量"（带 γ 折扣修正）。它给策略的梯度特征是：远离目标时立刻有方向性信号（每步都有 d − γd′ 的差额）；等到成功才收到第一笔奖励的方案给不了这种信号。两个工程细节：d 用米还是厘米？用哪个坐标（末端、掌心、还是指尖中点）？答案是把 Φ 的单位缩放当作权重旋钮（Φ = −w·d，w 控制塑形与成功的相对权重），并用"哪一步接触先发生"的任务分析来选参考点。多阶段任务（先接近、再抓、再放）可以为每阶段各设一个势函数切换，切换点选在两阶段都合理的状态（例如接触发生时刻），并保证切换处势值连续，避免"跨阶段瞬间"出现虚假的大额塑形。

5. 多目标配平：让每项"各说各话但不吵架"

奖励项典型形式量级出发点
任务成功+10（一次性，终止时发）锚定：与全部辅助项全程累积同量级
进度（PBRS）γ(−wd·d′) − (−wd·d)，wd≈1–5每步 0.01–0.1 量级，全程累积接近成功奖励
动作平滑/能耗−wa·‖a−aprev‖² 或 −wτ·‖τ‖²每步 1e-3–1e-2，别让"省电"压倒任务
惩罚项（碰撞/越界）−wp·指示或连续量一次性 0.5–2；与安全章（069）的代价分开记

配平方法：先把每项的"单步典型值"打印出来，让所有项落在同一数量级（0.01–0.1/步），成功奖励单独锚定在全部辅助项累积的 50–100%。校准看的是行为，不能只看回报数值：训练中期录一段视频，检查"策略在做什么"。若它频繁执行某个你没想到的动作模式，那多半是某个奖励项被钻了空子（奖励作弊，reward hacking）。

实现思路与设计

以 Franka 抓取-放置为例，从稀疏基线到塑形版的完整路径：

  1. 基线：稀疏奖励 r = +10（放置成功，终止），其余 0。记录它学不动的时间（大概率 20 万步无进展），这是对照组。
  2. 加 PBRS 进度：Φ(s) = −(1.0·dgrip→obj + 1.5·dobj→goal)（抓取前物-目标距离权重小，抓起后权重生效，两段势函数在"抓稳"事件处切换，事前保证切换处连续：抓握时 obj 还在手上，两项都较小）。
  3. 加平滑与能耗：−0.002·‖a−aprev‖²，不设速度惩罚（避免策略用"慢"作弊，慢速留给时间惩罚/课程处理）。
  4. 验证策略不变性：PBRS 版与稀疏版的最优行为应当一致。跑两个实验：成功率曲线对比（塑形版应早 3–5 倍收敛）与"最终成功路径的定性对比"（都应当直接、不绕圈）。
  5. 逐项账务：信息字典里分别返回 progress/success/smoothness 三项，训练日志分列绘制；出现异常行为时先看哪一项在异常地涨。
设计思维：为什么要"两段势函数在切换点连续"？

势函数切换瞬间若势值跳变，F = γΦ′−Φ 会出现一次性的巨额正/负奖励，等效于给策略发了一笔意外奖励，它可能学会在切换点附近反复横跳刷这笔钱。事前检查方法：列一个 10×10 的状态网格，手动计算切换边界两侧的 Φ 差值；把跳变压到"单步典型塑形值的 2–3 倍"以内。更稳的做法是让两段势函数在切换区域用平滑权重（如按抓取置信度插值）融合。

关键代码与解读

片段 1：PBRS 进度奖励（含终止与截断处理）

import numpy as np

class ProgressPotential:
    """势函数塑形：F = γ·Φ(s′) − Φ(s)；终止时置零，截断时照常结算。"""
    def __init__(self, gamma=0.99, w_grip=1.0, w_place=1.5, grip_eps=0.02):
        self.gamma, self.w_grip, self.w_place = gamma, w_grip, w_place
        self.grip_eps = grip_eps          # 判定"已抓稳"的距离阈值（米）
        self.prev_phi = None

    def potential(self, grip_pos, obj_pos, goal_pos):
        d_grip = float(np.linalg.norm(obj_pos - grip_pos))       # 夹爪-物体距离
        d_goal = float(np.linalg.norm(goal_pos - obj_pos))       # 物体-目标距离
        w_place = self.w_place if d_grip < self.grip_eps else 0.1  # 未抓住时目标距离权重低
        # 两段目标距离权重在 d_grip 跨越阈值处连续变化（0.1→1.5 经平滑区间），避免切换处的意外奖励
        blend = 1.0 / (1.0 + np.exp((d_grip - self.grip_eps) / 0.005))  # Sigmoid 平滑权重
        w_place = 0.1 + (self.w_place - 0.1) * blend
        return -(self.w_grip * d_grip + w_place * d_goal)

    def shaped_reward(self, state, next_state, terminated, truncated):
        phi = self.potential(*state)
        phi_next = self.potential(*next_state)
        # 真终止（成功/跌落）：末端势值不参与结算，防止不同终止方式改写最优策略
        if terminated:
            return 0.0
        f = self.gamma * phi_next - phi
        self.prev_phi = phi_next
        return float(f)                  # 截断照常结算：与值函数的 bootstrap 口径一致

解读：这段代码把第 3、4 节的理论全部落进了细节。Sigmoid 平滑权重（以抓握距离阈值为中心的 5 mm 过渡带）让"抓取前/后"两段势函数平滑融合，解决了切换连续性问题，工程上比手工对齐两段值可靠得多。终止置零：成功或跌落时直接返回 0，确保 γTΦ(sT) 项不出现；若不置零，从同一个 sT 走向"成功终止"与"跌落终止"的势能末值不同，会让策略偏好某一类终止，等价于偷偷改了目标。截断照常结算：时间上限截断不是真终止，值函数会从截断状态继续 bootstrap，塑形项也必须照常折现，两者口径不一致会系统性偏移"拖延 vs 快速完成"的偏好。最后注意返回值用 float：这一步在 4096 并行环境 × 60 Hz 的热路径上执行，避免产生 numpy 标量对象（小的类型开销会被放大成可观的吞吐差异）。

片段 2：多目标奖励合成与逐项账务

import torch

class RewardComposer:
    """多目标奖励：配平靠权重、诊断靠分项台账；不改变各项物理定义。"""
    def __init__(self, w_success=10.0, w_progress=1.0, w_smooth=0.002):
        self.w_success, self.w_progress, self.w_smooth = w_success, w_progress, w_smooth

    def __call__(self, progress_f, success_flag, act, prev_act):
        smooth = torch.sum((act - prev_act) ** 2, dim=-1)     # 动作变化平方和
        r_success = self.w_success * success_flag             # 一次性成功奖励（稀疏锚点）
        r_progress = self.w_progress * progress_f             # PBRS 项（稠密路标）
        r_smooth = -self.w_smooth * smooth                    # 平滑惩罚（辅助正则）
        total = r_success + r_progress + r_smooth
        # 分项台账：训练日志按项分组统计，出问题时第一时间定位"是谁在涨"
        terms = {"success": r_success.mean(), "progress": r_progress.mean(),
                 "smooth": r_smooth.mean()}
        return total, terms

解读：合成公式朴素，纪律体现在两处。一，辅助项只"配平"不"改符号"：progress 与 smooth 的权重是数量级旋钮（1.0 与 0.002 相差 500 倍，但乘上各自的单步量级后贡献接近），你不能靠调 w_smooth 把任务目标改成"省电"，若要严肃优化能耗，应走第 081 章的专用奖励设计与验收。二，逐项台账进日志：只记总回报时，出现"回报上升但行为退化"根本无从下手；有了三项曲线，典型病都能秒判，success 平、progress 涨而成功率不升 → 在刷进度（抖动刷分或悬停）；smooth 贡献异常大 → 策略停滞不动。建议台账还记录每项的回合累积值和占比（progress 占比长期 >80% 说明 w_success 相对太小）。这个 composer 返回 (total, terms) 的接口与第 081 章能量优化、第 069 章代价通道保持一致，方便上层训练框架统一消费。

片段 3：A/B 验证，塑形只加速、不改最优

import numpy as np

def ab_check(sparse_returns, shaped_returns, window=50):
    """对两组训练的评测回报做比对：看收敛速度与最终水平两个维度。"""
    def moving_avg(x, w):
        return np.convolve(x, np.ones(w) / w, mode="valid")
    ma_s, ma_f = moving_avg(sparse_returns, window), moving_avg(shaped_returns, window)
    # 收敛速度：达到"最终水平的 80%"所用步数（两个训练预算需一致才能比）
    threshold = 0.8 * min(ma_s[-1], ma_f[-1]) if min(ma_s[-1], ma_f[-1]) > 0 else 0.0
    steps_to = lambda ma: int(np.argmax(ma >= threshold)) if (ma >= threshold).any() else -1
    return {
        "final_sparse": float(ma_s[-1]), "final_shaped": float(ma_f[-1]),
        "speedup": steps_to(ma_s) / max(steps_to(ma_f), 1),   # >1 表示塑形版更快
        "same_optimum": abs(ma_s[-1] - ma_f[-1]) / max(abs(ma_s[-1]), 1e-9) < 0.1,
    }

解读：验证脚本回答两个问题，"是否更快"（speedup）与"是否到同一个地方"（same_optimum，末段回报差距小于 10%）。两个实验的训练预算与随机种子集合必须一致，否则比出来的是噪声；建议每组 3 个种子取中位数。注意"最终回报相同"只是必要证据，不是充分证据：两类最优策略若回报相近但行为不同（例如塑形版绕路完成），回报比对看不出来。所以完整验证还要加一条行为检查：固定初始状态下录 20 条成功轨迹，比较平均路径长度与动作幅度，PBRS 正确的实现下，两者应当无系统性差异。这套 A/B 流程也适用于你后续修改任何辅助项时的回归验证。

常见坑

  • 直接用距离发奖励（非势函数形式）：r += w·(1/d) 或 r += w·(距离小于阈值的加分)。症状是策略学会在阈值边缘来回横跳刷分、或贴近目标但不接触。修复：改为 γΦ′−Φ；对"贴近不碰"再加接触事件奖励或把成功条件做成逻辑链（抓稳+到位）。
  • 终止未处理：塑形项在终止转移照常计算 γΦ(sT)−Φ(s)，不同终止方式的末值差被策略利用。症状是策略"偏好"某种失败方式（例如爱跌落，因为跌落末状态势能更高）。修复：终止转移置零（片段 1 的做法），或对各类终止统一 Φ 值。
  • 距离用错参考点：用基座到目标的距离做势函数，策略学出"扭腰"这类动作，"伸臂"则学不到。症状是末端不动、身体乱晃。修复：势函数用的距离必须与"成功判定"用同一对物理点（末端-物体、物体-目标）。
  • 权重全凭"感觉调大"：把 progress 权重调到 success 的 10 倍以"学得快"，结果策略只接近不完成任务。症状是成功率平台远低于预期且 progress 台账占比极高。修复：按第 5 节的配平法，success 应至少与全程 progress 累积同量级。
  • 忘记区分"训练奖励"与"评估指标"：评估也用塑形后的总奖励，无法发现奖励作弊。症状是评估分数很高、真实成功率低。修复：评估永远用任务本身的指标（成功率、完成时间、接触力），奖励只用于训练。

练习与思考

  1. 实现一个"抖动刷分"陷阱：故意用非势函数形式的距离奖励（趋近加分），观察策略行为，再用 PBRS 重训对比。★
    提示
    趋近加分下，来回抖动每步都能得分；PBRS 下往返一圈净和为 0。录视频看差异最直观。
  2. 把成功奖励从 +10 改成 +50 与 +3，固定其余项重训，预测并验证策略"冒险程度"的变化。★★
    提示
    成功奖励越大，策略越愿意承担中途失败风险（更激进）；太小则成功动机被平滑惩罚抵消、变得拖延。
  3. 设计"终止势能"实验：分别用（a）终止置零、（b）终止按状态计算 Φ，训练两组策略，检查是否出现"偏好跌落"的行为差异。★★★
    提示
    让跌落终点的 Φ 明显高于成功终点（例如给跌落终止单独设一个偏高的 Φ 末值），观察失败方式分布是否偏向跌落。
  4. 给 3 段式任务（接近-抓取-放置）设计 3 个势函数的平滑融合权重，写出切换区域的连续性检查脚本。★★
    提示
    在切换边界上采样 100 个状态，计算 |Φ_前 − Φ_后| 的 95 分位，应远小于单步塑形典型值。
  5. 跑一次完整 A/B 验证：稀疏基线 vs PBRS，报告收敛速度比、最终回报差、行为路径对比三项结论。★★
    提示
    4 个种子起步；收敛步数用"达到最终 80%"定义并写清楚，否则不同人算出的 speedup 不可比。

小结

  • 塑形的目标是给策略"沿途路标"，但任意加项都可能改变最优策略，安全性有严格条件。
  • PBRS 定理：F = γΦ(s′) − Φ(s) 的望远镜求和只剩首尾项，最优策略集不变；前提是终止势值与折现口径处理正确。
  • 距离势函数 Φ = −w·d 是最常用的塑形：提供每步的方向性梯度；切换点要平滑、参考点要与成功判定一致。
  • 多目标配平：各项单步贡献拉到同一数量级，成功奖励锚定全程辅助项累积；校准靠行为录屏，不靠回报数值。
  • 纪律：终止置零、截断照常、逐项台账、评估只用任务指标、A/B 验证"更快且同最优"。
