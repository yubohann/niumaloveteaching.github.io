第 030 章：实现接触检测与奖励

把"碰到没碰到"变成可学习信号：接触事件的检测、去抖、一次性奖励与力窗口设计，动机是让奖励帮你精确表达"想要什么样的接触"。

  • 主题：奖励设计 / 接触事件
  • 相关组件：Isaac Sim（接触报告 / 力）、Stable-Baselines3
  • 预计学时：45 分钟
  • 前置章节：第 029 章

学习目标

  • 掌握接触检测的三层实现：物理接触报告、净接触力阈值、几何距离代理，各自的精度与成本。
  • 会做接触事件的"瞬间判定"与去抖：用前一时刻状态维护事件边沿，避免逐帧奖励抖振。
  • 理解接触奖励的四类形态（触碰一次性奖励、力窗口塑形、超力惩罚、脱离惩罚）及其权重设计。
  • 能识别并修复"接触奖励刷分"（reward hacking）：策略贴着物体反复触碰骗奖励的行为。
  • 会把接触事件同时用于奖励与终止判断，形成接触丰富任务的奖励骨架。

背景与动机

上一章你学会了把力信号"读出来"，本章要把它"用起来"。接触事件是操作任务里最基础的成功判据构件：抓到了没（夹爪与物体接触）、到达了没（工具与目标接触）、撞坏了没（接触力超限）。很多任务用"接触 + 条件"就能写出稀疏但正确的奖励，比调一堆塑形项可靠得多。

接触奖励同时也是最容易出问题的地方：奖励写成一个逐帧电费表，策略就会用"贴着刷新"的方式薅羊毛；不做去抖，一秒里接触状态翻转几十次，奖励噪声比信号还大；把全机器人的接触力都算进来，地面接触也变成"触碰奖励"。本章逐个解决这些问题，你从第 036 章开始看到的每一个任务，奖励函数里都有本章方法的影子。

核心原理

1. 接触检测的三条实现路线

路线原理优点成本/局限
物理接触报告PhysX 对指定刚体报告接触对与接触点，按力/穿透阈值过滤精确、可直接拿到接触点与法向开关式启用，报告量大时有开销；需给每个环境正确设置过滤
净接触力阈值读取刚体净接触力，模长超过阈值即判定接触接口最简单；与第 029 章复用只能给"合力"，区分不出接触点；地面支撑力会混入
几何距离代理用末端与目标表面距离，低于阈值视为"准接触"零物理成本、对穿模鲁棒阈值依赖几何先验；快速掠过时可能漏判

工程默认用"净接触力 + 阈值"，需要接触点信息（如判断是哪个手指先碰到）时再上物理接触报告。阈值取值要有物理依据：夹爪与物体的稳定接触力通常 2–10 N，取 1.0 N 做"是否接触"的判据，既排除数值噪声（仿真接触求解残差约 0.01–0.1 N），又不会漏掉轻触。

2. 事件边沿：把"状态"变成"事件"

接触是一个持续状态，而奖励通常想要一个事件，"刚刚碰到"的那一刻。用状态的上升沿表示事件：

eventt = contactt ∧ ¬contactt−1 需要为每个环境保存上一帧的接触布尔量；重置时必须把该状态清零，否则会把"上一回合的接触"误判成本回合的上升沿

为什么事件化很重要？因为逐帧状态奖励会引导"保持接触刷奖励"的行为，而上升沿事件奖励不可重复刷取（一次回合通常只有一个上升沿）。这是奖励设计里"事件 vs 状态"的通用原则：想让行为发生一次，奖励边沿；想让状态保持，惩罚偏差。进阶做法是加去抖（debounce）：要求接触连续维持 k 帧（如 3 帧 = 50 ms）才确认"真的碰上了"，否则该接触视为传感器噪声，这会把策略从"点一下就缩回"的投机路径赶回物理上可信的接触。

3. 接触奖励的四种形态与权重

围绕同一次接触，通常叠加四个分量，各司其职：

  • 触碰事件奖励：首次接触 +1.0（一回合一次）。给出强稀疏信号，直接回答"任务的关键一步做了没"。
  • 力窗口塑形：r = −wf·|F − Ftarget|/Ftarget，让接触力保持在目标窗口（如 5 N）附近。wf 取 0.1 量级，塑形是"锦上添花"，不能盖过事件信号。
  • 超力惩罚：F > Fsafe（如 30 N）时收到 −1.0 且可以触发终止。它表达的是"安全约束"，用未滤波的原始力判定（第 029 章的原则）。
  • 脱离惩罚：本该保持接触的阶段里接触丢失，给 −0.5。它把"抓着不放"和"碰一下就跑"区分开。

权重设计的纪律：事件与安全是"主角"（±1 量级），塑形是"配角"（0.1 量级）。常见错误是把力窗口塑形的权重也给 1.0，结果策略为了维持"完美的 5 N"而完全无视任务推进，塑形项的目标是加速学习，不是定义任务。

4. 奖励刷分与它的三种疫苗

只要奖励里存在"可重复获取"的项，策略就会找到重复路径。接触奖励的经典作弊模式是"贴着目标反复碰"：接触→断开→再接触，每个上升沿都领钱。三种防御：

  1. 事件一次性：上升沿奖励加"每回合只发一次"的掩码（配合 3 帧去抖，把每回合的假事件数量压到接近 0）。
  2. 脱离惩罚配对：想刷新接触就要先付"脱离"的成本，把刷分路径变成负收益。
  3. 以任务进度为主奖励：接触奖励的权重不能大到让策略忘记目标（如抓取任务的最终奖励是"举起来"）；当塑形项收益超过任务项时，策略必然刷分。

5. 接触状态与终止：一对好搭档

终止条件常和接触信号联动：物体掉落（脱离 + 高度低于阈值）、超力接触（安全性）、意外碰撞（如机械臂碰到非目标物体）。判断终止用的是"原始力"和"未做去抖的瞬时状态"：去抖会让终止晚 50 ms 生效，对安全性判断来说太晚；而奖励通道可以承受这一点延迟。奖励可以平滑，安全不能平滑，这个区分要在代码注释里写清楚。

6. 完整算例：阈值与去抖的信噪比核算

阈值 1.0 N 与去抖 3 帧的组合可以用概率算清楚。设接触求解残差近似高斯、σ=0.1 N（区间 0.01–0.1 N 的上端），则"无接触时单帧噪声越过 1 N"发生在 10 个标准差之外，概率低于 1e-20，单帧误报可以忽略；这就是阈值取 1 N 的依据：0.2 N 只高出残差上端 2 个标准差（σ=0.1 N），会有百分之几的逐帧误报，1 N 同时避开了数值残差（0.01–0.1 N）与真实轻触（2 N 起）之间的空档。

去抖对付的是"接触维持期间的间歇性塌陷"，高斯噪声在阈值这一层就已经被隔离：物体若与手指反复微分离（刚性接触的解脱-再接触周期），某帧力跌回阈值以下的概率设为 q。连续 3 帧都塌陷才误判"未接触"，误判概率降到 q³：q=0.2 时约 0.8%，q=0.1 时约 0.1%。反向地，单帧毛刺（概率 1%）要连续三帧出现才会误报一次接触，概率降到 1e-6。两个方向的数字说明：3 帧去抖用 50 ms 的确认延迟换来两个数量级以上的净噪声压制，是划算的。

延迟的代价也要量化：确认延迟 3 帧 = 50 ms，若接触时刻的接近速度为 0.1 m/s，事件确认时末端已多走了约 5 mm。对插孔这类需要"轻触即退"的任务，这 5 mm 会转化成超力风险，处理办法是把"预接触减速"写进任务塑形（接近目标区域时限制速度）；把去抖帧数调回 1 只会把毛刺问题放回来。

7. 奖励收支核算：刷分路径为什么是负收益

把"正确行为"与"刷分行为"在一段 500 步（约 8.3 s）的回合里做账。假设刷分策略每秒触碰再脱离 10 次，整回合约 83 次：

科目正确行为（碰一次并保持推进）刷分行为（全回合约 83 次触碰-脱离）
触碰事件奖励+1.0（一次）+1.0（一次性掩码只发首份）
脱离惩罚（−0.5/次，保持阶段内）0约 −41（82 次脱离结算）
力窗口塑形（−0.1 量级）−0.05 至 −0.2（保持期小额）接近 0（大部分时间不在接触）
任务推进奖励+5 量级（0.01/步 × 500 步）0（不推进）

账目把防线说透了：一次性掩码把刷分者最强的那一路收入砍到与正确行为同额，脱离惩罚把它变成约 −40 的净亏，任务推进项再拉开正向差距。反过来若拆掉任意一环：掩码去掉则 83 次触碰给 +83（远超成功奖励），脱离惩罚去掉则刷分净收益为正。防刷分不靠"策略自觉"，靠每一项的收支都算过账，这张表就是模板：把你的奖励项逐条列成收入/支出，找找有没有净收益为正的捷径。

8. 边界与失效模式

  • 轻快敲击被去抖吞掉：接触持续时间短于 3 帧（50 ms）的敲击根本到不了 confirmed 状态，事件奖励永远不发。判据：任务是否存在"轻点一下就算成功"的合法接触；若是，给这类接触单独开一条"原始上升沿 + 一次性掩码"的通路，去抖只管状态型用途。
  • 阈值与负载重量的错位：0.5 kg 物体的重力载荷约 4.9 N，若阈值设成 1 N 而判据又要求"净接触力超过阈值"，抓着物体静止时接触力包含自重，看起来一切正常；但一旦把阈值提高到 5 N（想过滤支撑力），静止持握的信号就会被误判为"未接触"。修复：夹持类任务的判据区分"抓取保持力"与"外部接触力"，或用指定刚体对过滤掉自重。
  • 力窗口目标没有算入自重：持握阶段传感器读到的 5 N 可能本就是物体的重量，窗口目标若再设 5 N，策略会把"额外夹紧"当成训练目标。修复：标定空载与带载两种状态的基线，窗口围绕"接触力 − 载荷基线"设。
  • 去抖计数与模仿跨帧状态漏重置：count 或 touch_awarded 漏进重置清单时，新回合要么"出生即接触"，要么"触碰奖励永远不再发"。修复：维护一张跨帧状态清单，重置时逐项清零，并用"每回合事件计数"日志核对。

实现思路与设计

接触奖励的工程实现分五步：确定检测对象 → 取信号并阈值化 → 去抖 + 事件掩码 → 组装四个奖励分量 → 与终止逻辑对接。关键状态（上一帧接触、事件已发放掩码）都要进入重置清单。

  1. 检测对象：只对"末端执行器（夹爪指掌）与目标物体"这一对做接触判定，不对全场刚体开报告，这是性能与语义的双重要求。
  2. 阈值与去抖：接触力模长 > 1.0 N 记 contact=1；连续 3 帧为 1 才算确认接触。
  3. 事件掩码：first_touch = confirmed ∧ ¬prev_confirmed；发放后置 touch_awarded=True，回合内不再发。
  4. 奖励组装：touch + force-window + over-force penalty + lose-contact penalty；四项权重刻意差一个数量级。
  5. 终止对接：超力（原始力）立即终止并给负奖励；目标物体落地失败终止；回合接近上限的阶段性判定。
参数推荐值理由
接触阈值1.0 N高于求解残差（0.01–0.1 N）、低于典型轻触（2 N）
去抖帧数3 帧（50 ms）滤掉单帧数值毛刺，又不拖慢真实接触的确认
触碰事件奖励+1.0（一次性）强稀疏信号、不可刷
力窗口5 N，w=0.1塑形配角；窗口来自任务物理需求
超力阈值30 N，罚 −1.0 并终止安全约束；用原始力判定
脱离惩罚−0.5（仅"应保持"阶段）与事件奖励配对，堵刷分路径
设计思维：接触奖励是"中间站"，不是"终点"

接触本身极少是任务目标，它只是通往目标的必经之路。奖励结构应该是"接触事件 → 保持接触/推进 → 最终成功"的梯子：触碰给 1.0，让策略知道方向；持续接触下的推进（如插入深度、抬升高度）给 0.5 量级的连续信号；最终成功再给 3–10 的大额奖励。梯子上每一级都要有合理高度差，否则策略学会了第一级就不想往上爬，这在第 037 章抓取与第 041 章插拔的奖励设计里会被反复引用。

关键代码与解读

片段 1：接触读取与去抖状态机

import torch

class ContactTracker:
    """接触状态跟踪：阈值 → 去抖 → 事件边沿，三个状态量都随回合重置"""
    def __init__(self, num_envs, threshold=1.0, debounce_frames=3, device="cuda"):
        self.threshold = threshold                        # 1 N：高于残差、低于轻触
        self.debounce = debounce_frames                   # 连续 3 帧才算确认：抗单帧毛刺
        self.device = device
        self.count = torch.zeros(num_envs, dtype=torch.long, device=device)   # 连续接触计数
        self.confirmed = torch.zeros(num_envs, dtype=torch.bool, device=device)  # 去抖后状态
        self.raw = torch.zeros(num_envs, dtype=torch.bool, device=device)     # 未去抖：给终止用

    def reset(self, env_ids):
        self.count[env_ids] = 0                           # 不重置 = 上回合的接触渗进新回合
        self.confirmed[env_ids] = False
        self.raw[env_ids] = False

    def update(self, force_norm):
        """force_norm: (N,) 末端净接触力模长（原始值，未滤波）"""
        self.raw = force_norm > self.threshold            # 瞬时判定：安全逻辑用它
        self.count = torch.where(self.raw, self.count + 1,
                                 torch.zeros_like(self.count))   # 连续帧计数，断开即清零
        prev_confirmed = self.confirmed.clone()
        self.confirmed = self.count >= self.debounce      # 去抖后的"确认接触"
        event = self.confirmed & (~prev_confirmed)        # 上升沿：本帧刚刚"确认碰上"
        return event

解读：这个状态机里有三个布尔量，每个都对应一个明确用途，合在一起才是"正确的接触抽象"。raw 是最快的信号（零延迟），终止与安全判断用它；count/confirmed 是去抖后的稳定状态，观测与状态奖励用它；event 是上升沿，一次性奖励用它。三者分开存储的代价是几十字节，收益是"同一物理事件在不同用途下各取所需"，避免"用去抖信号判终止导致晚 50 ms 反应"或"用瞬时信号发奖励导致一次接触发五份奖金"的两难。torch.where 那一行是去抖的精髓：接触时计数加一、断开时直接清零，"中断即重新计"保证了只有"连续"接触才能累积到 3 帧。重置清单：三个状态全部清零；漏掉任何一个，新回合开头都会出现"幽灵事件"。

片段 2：四分量接触奖励的组装

class ContactReward:
    """接触奖励：事件 + 力窗口 + 超力惩罚 + 脱离惩罚；权重刻意差一个数量级"""
    def __init__(self, num_envs, f_target=5.0, f_safe=30.0, device="cuda"):
        self.f_target = f_target            # 期望接触力 5 N：来自任务物理分析
        self.f_safe = f_safe                # 30 N 安全上限：超过即罚并终止
        self.touch_awarded = torch.zeros(num_envs, dtype=torch.bool, device=device)
        self.keep_phase = torch.zeros(num_envs, dtype=torch.bool, device=device)  # 应保持接触阶段

    def reset(self, env_ids):
        self.touch_awarded[env_ids] = False
        self.keep_phase[env_ids] = False

    def compute(self, tracker, force_mag, raw_force_mag):
        rew = torch.zeros_like(force_mag)

        first_touch = tracker.confirmed & (~self.touch_awarded)
        rew = rew + first_touch.float() * 1.0          # 事件奖励 +1：同回合只发一次，天然不可刷
        self.touch_awarded |= tracker.confirmed        # 发放后打标记：之后不再重复

        in_contact = tracker.confirmed
        window_err = (force_mag - self.f_target).abs() / self.f_target
        rew = rew - 0.1 * window_err * in_contact.float()   # 力窗口塑形：配角，权重 0.1

        over = raw_force_mag > self.f_safe             # 超力判定用原始力：滤波会洗白冲击
        rew = rew - over.float() * 1.0                 # 安全惩罚：与事件奖励同级

        lost = self.keep_phase & (~in_contact)
        rew = rew - lost.float() * 0.5                 # 应保持却脱离：堵"碰一下就跑"的作弊路径
        return rew, over                               # over 同时交给终止逻辑使用

解读：这段代码是"奖励权重纪律"的活教材。四个分量的系数 1.0 / 0.1 / 1.0 / 0.5 不是随手写的：事件与安全是任务级信号（+1/−1），力窗口是学习加速器（−0.1），脱离惩罚是对冲工具（−0.5），任何一个塑形项的累计收益都不该超过一次任务事件。假想刷分场景：策略每秒断开再接触 10 次，若无 touch_awarded 机制可薅 10 分/秒；现在第一份之外为零，且每次断开吃 −0.5，刷分路径变成负收益。另一个细节是 over 被同时返回给终止逻辑：同一个判据服务两个用途（奖励 + 终止）时，要确保它们读的是同一个物理量（这里都是原始力），如果终止用去抖、奖励用原始，会出现"被罚了但没终止"的不一致日志。

片段 3：接进环境循环与终止对接

def step_contact_task(self, actions):
    for _ in range(self.decimation):
        self._world.step(render=False)               # 物理推进：接触在这里发生

    raw = self._end_effector_net_force()             # (N, 3)：世界系净接触力（第 029 章）
    raw_mag = raw.norm(dim=-1)                       # (N,)
    force_mag = self.force_obs.f_filt.norm(dim=-1)   # 观测用的滤波值：奖励窗口参考它

    event = self.tracker.update(raw_mag)             # 去抖状态机：取原始模长做判定
    rew_contact, over = self.contact_reward.compute(self.tracker, force_mag, raw_mag)

    # 终止：安全（超力）用原始力；任务失败用几何判据；超时用计数器
    terminated = over | self._object_dropped()       # 真失败：引导时按 0 截断价值
    truncated = self.progress_buf >= self.max_steps  # 超时截断：引导时与失败区分
    rew_task = self._task_progress_reward()          # 任务主奖励：接触奖励之外的主体
    rew = rew_contact + rew_task + self._regularizers()  # 总奖励 = 接触 + 任务 + 正则

    self._autoreset(terminated | truncated)          # 只重置结束的环境
    return self._build_obs(), rew, terminated, truncated

解读：把本章所有构件在这十行里对上了号。注意力的分配：raw_mag 走判定与终止、force_mag（滤波）走塑形，两个变量名刻意不同，读代码的人一眼能看出"哪个信号服务哪个用途"。奖励的层次：rew_contact 只是骨架，真正驱动任务的是 rew_task（如插入深度、抬升高度），本章反复强调的"接触是中间站"在这里落地。终止与截断的分工：terminated（超力/掉落）在引导时按 0 截断，truncated（超时）保留价值估计；这和第 022 章讲的规范完全一致。最后一行 _autoreset 顺手把三个状态机（tracker、reward 掩码、第 029 章的滤波状态）交给环境的重置清单统一清零，凡是跨步状态，都属于重置清单，一个都不能漏。

常见坑

  • 接触奖励刷分：触碰奖励逐帧发放且无脱离罚，策略学会每秒碰十次。症状：成功率低但回合回报异常高。修复：事件一次性 + 脱离惩罚 + 任务奖励权重占主导。
  • 全场刚体都算接触：机器人脚垫、基座与地面的支撑力混进"接触判据"，所有环境开局即"接触"。症状：事件奖励永不触发（上升沿早就发生过了）。修复：只对指定刚体对做判定；接触力查询指定 body 索引。
  • 状态不随重置清零：上一回合的接触计数残留，新回合第一帧就"确认接触"或计数已经累计到去抖阈值。症状：奖励日志出现时空错位的奖励峰值。修复：把接触相关状态全部放进 reset 清单。
  • 去抖帧数过大：想滤噪声把去抖设成 10 帧（167 ms），快速接触（如敲击）根本来不及确认。症状：策略动作有效但奖励不变。修复：去抖 ≤ 3 帧；毛刺主要靠更合理的阈值和滤波在前面处理。
  • 用滤波力做安全判定：撞击被低通"洗白"，超力事件漏判。症状：评估日志中力的峰值远超安全阈值却不终止。修复：安全路径一律读原始力。
  • 短敲击被去抖吞掉：接触短于 3 帧（50 ms）的合法轻点永远到不了确认状态。症状：任务做对了但事件奖励从不发放。修复：为轻点单独开"原始上升沿 + 一次性掩码"通路，去抖只管状态型用途。
  • 阈值与自重错位：把阈值抬高到能过滤支撑力的量级（5 N）后，静止持握 0.5 kg 物体的信号（约 4.9 N）反而被误判为未接触。修复：按刚体对过滤，或用"接触力减载荷基线"的净信号做判定。

练习与思考

  1. 实现"去抖帧数"消融：debounce 设为 1 / 3 / 10，训练同一个触碰任务，从"事件奖励发放次数"的日志解释三者的差异。★
    提示
    debounce=1 时事件数与"接触翻转次数"挂钩，一次物理接触被算成多次；debounce=10 时真实事件反被漏掉。对照日志的每次接触平均时长（典型 100–300 ms）。
  2. 设计一个"刷分策略"的探测工具：在训练日志里同时跟踪"触碰事件次数/回合"与"任务成功率"。什么样的曲线组合标志策略正在刷分？★★
    提示
    健康的信号是事件次数接近 1、成功率上升；刷分信号是事件次数远大于 1 且成功率平坦（甚至下降）。
  3. 把力窗口的目标从 5 N 改成 15 N，预测并验证策略接触力的分布变化。用直方图量化"实际接触力"与目标的偏差。★★
    提示
    窗口塑形权重只有 0.1，预期分布向 15 N 移动但不精确贴合；差多少反映塑形权重的强度，这也是检验权重是否合理的指标。
  4. 工程题：给第 029 章的力观测管线接入本章的驱动状态机，跑通"观测用滤波值、奖励用原始值、终止用原始瞬时值"三路信号，并写一段不超过 5 行的验证脚本证明三路确实不同。★★★
    提示
    在撞击瞬间打印三个量：滤波值会明显低估峰值、raw 会尖峰、confirmed 会晚几帧翻转。把三者的曲线画在一起，差异一目了然。
  5. 思考题：为什么"事件奖励 + 保持惩罚"的组合比"逐帧状态奖励"更不容易被利用？从 MDP 的回报定义出发给出一段证明式论证。★★★
    提示
    逐帧奖励的回报随"持续帧数"线性增长，策略可以直接优化"贴住时长"这个与任务无关的量；事件奖励的回报与时长无关，只表达"发生过"。保持惩罚则给"贴住"这个中间状态定价为负。
  6. 用 7 节的账目模板做一次压力测试：假设你的任务是"把插头插到底"（成功 +10），有人把力窗口权重从 0.1 改成 1.0、窗口误差典型 0.5，保持阶段 200 步。算出正确行为的窗口净支出与成功奖励的对比，判断这个权重是否越界。★★★
    提示
    窗口支出 = 1.0 × 0.5 × 200 = 100，远超成功奖励 +10；即便误差只有 0.1，支出也有 20。结论是塑形权重要用"累计支出不得超过任务奖励"反推，先算账再定值。

小结

  • 接触检测三条路：接触报告（精细）、净接触力阈值（默认）、几何距离（零成本代理）；阈值取 1 N 量级。
  • 三个状态量分工：raw（终止/安全，零延迟）、confirmed（观测/状态奖励，去抖 3 帧）、event（一次性奖励，上升沿）。
  • 四分量奖励权重纪律：事件 ±1、安全 ±1、力窗口 0.1、脱离 0.5；塑形累计收益不得超过任务事件。
  • 防刷分三件套：事件一次性、脱离惩罚配对、任务主奖励占权重主导。
  • 本章是本篇的收官：观测三模态（027–029）与接触奖励（030）构成完整拼图。下一章进入第二篇，目标条件强化学习，让奖励从"固定目标"升级为"任意目标"。
