第一篇 · 仿真环境与训练框架

第 001 章：创建基础仿真环境

从零搭起一个 Isaac Sim 物理场景：启动应用、创建 World、放入地面与第一个刚体，并想明白"仿真时间"到底是怎么流动的。

  • 主题：仿真环境 / World 与物理步进
  • 相关组件：Isaac Sim（Kit / USD / PhysX）
  • 预计学时：40 分钟
  • 前置章节：无（本课程从这里开始）

学习目标

  • 理解 Isaac Sim 的三层结构：Kit 应用框架、USD 场景描述、PhysX 物理引擎，知道每层各管什么。
  • 掌握"先启动 SimulationApp、再导入其余模块"这条铁律背后的原因。
  • 会用 World 组织场景：地面、光源、刚体、world.step() 循环。
  • 说清 physics_dt、rendering_dt、子步数（substeps）与实时倍率（RTF）的关系，并会为机器人任务选一组合理的时间参数。
  • 完成第一个可运行的仿真小场景：一个立方体在重力下落到地面并静止。

背景与动机

训练机器人策略动辄需要几百万个交互回合，在真机上做这件事既不安全也买不起。仿真让我们能以 10–100 倍实时速度、零损耗地采集数据，还能顺便得到完美的真值标签（位姿、接触力、深度图）。Isaac Sim 是 NVIDIA 面向机器人学习的仿真平台：GPU 并行物理、可微渲染级的传感器仿真、以及对 USD 场景格式的原生支持，让"成千上万个环境同时训练"成为可能。

但所有上层能力，加载机器人、配置驱动、写 RL 环境，都建立在一个最小闭环上：一个能被推进时间的物理世界。本章的目标就是把这个世界搭出来，并且把其中每个概念都讲透，因为后面 99 章都会以它为地基。

学习路径上，本章处在整条链路的根部：先有可步进的世界（本章），再有机器人与关节接口（002–003），然后才有观测、动作、奖励与训练循环（004 之后）。越是根部的问题，排查成本越高，所以本章把时间参数、启动顺序、验收判据全部显式化，让后续每一章都继承一组经过校验的默认配置。

核心原理

1. Isaac Sim 的三层结构

理解这三层，后面遇到任何"这个功能写在哪"的问题都能自己定位：

层角色你打交道的对象
Kit 应用框架Omniverse 的应用容器：加载扩展、管理 UI、事件循环SimulationApp、扩展（extension）
USD 场景描述层次化的场景图：物体、变换、材质都是 USD 图元（prim）Stage、prim 路径如 /World/Cube
PhysX 物理引擎对场景中的刚体/关节做数值积分，产出下一时刻的状态World、RigidPrim、关节 API

关键认知：USD 是"声明"，PhysX 是"执行"。你在 USD 里声明"这里有个 1 kg 的立方体"，PhysX 在每次 step() 时根据它计算下落。仿真卡住不动时，第一反应应该是："我是不是只声明了，没让 PhysX 真正步进？"

2. 仿真时间：physics_dt 与子步

物理引擎用固定步长做积分，这个步长就是 physics_dt。两次 world.step() 之间，物理世界前进 physics_dt 秒。同一帧内还可以拆成若干"子步"（substeps）：

Δtframe = physics_dt 例如 physics_dt=1/60 s 时，每次 step() 仿真时间前进 16.7 ms；substeps 只细分帧内部的积分，不改变帧长

为什么步长不能太大？看一个数字：在重力 g=9.8 m/s² 下，1/60 秒内物体下落的距离是 ½·g·(1/60)² ≈ 1.36 mm，这已经接近小型抓取任务的指尖尺度。若把步长放成 1/10 秒，单帧位移就是 49 mm，接触检测会严重失真，刚体会"陷进"地面或剧烈弹跳。

那为什么不干脆用 1/1000 秒？因为每一步都有计算开销，步长减半、成本翻倍。工程上的常用做法是：控制频率取 50–100 Hz（physics_dt = 1/60 或 1/100），需要更高保真时用 substeps 提高子步精度，而不改控制周期。

3. 实时倍率 RTF：你离"比实时快 100 倍"有多远

RTF = （仿真时间） / （真实流逝时间）

RTF > 1 表示仿真跑得比真实快。RTF 受显卡、场景复杂度、平行环境数影响。训练时我们关心的是它：RTF 越高，单位墙钟时间采集的数据越多。这也是 Isaac Sim 的看家能力，把 GPU 用在刀刃上。

4. 步长的量化选择：接触穿透与积分误差

结论先说：步长上限由场景中最快的运动尺度决定，下限由算力预算决定。做两个量化分析。第一，接触穿透。立方体从 1.0 m 落到 0.05 m 的静止高度，落差 0.95 m，接触瞬间速度 v = √(2gh) ≈ √(2 × 9.8 × 0.95) ≈ 4.3 m/s，一步之内的位移为 d = v · Δt：

d = v · Δt Δt = 1/60 s 时 d ≈ 72 mm；Δt = 1/10 s 时 d ≈ 432 mm。立方体边长 100 mm，1/10 步长下单步位移已超过物体尺寸，接触检测容易漏检，表现为穿透或弹飞

把不同步长的取舍并列成表，量级关系一目了然：

physics_dt单步位移（v = 4.3 m/s）相对 RTF（同样墙钟成本/步）适用场景
1/10 s432 mm约 6×粗粒度演示，不适合任何接触任务
1/60 s72 mm基准 1×常规操作、行走、导航
1/120 s36 mm约 0.5×高精度接触、装配对准
1/240 s18 mm约 0.25×插拔、灵巧手等强接触任务

第二，积分误差。把关节闭环近似为弹簧振子：固有角频率 ω = √(k / I)，k 为刚度、I 为等效惯量。显式积分要求 ω·Δt < 2 才不发散，工程上要求 ω·Δt < 0.5 才把误差压到可接受范围。代入 Franka 关节量级参数 k = 400 N·m/rad、I = 0.1 kg·m²，得 ω ≈ 63 rad/s，要求 Δt < 0.5 / 63 ≈ 7.9 ms。默认 1/60 s ≈ 16.7 ms 已超过这条线，这说明物理引擎对关节约束实际采用隐式解法（允许更大步长），也说明凡是要把刚度调高的任务，都应配合 substeps 把等效步长降下来。等效步长的定义：

Δteff = physics_dt / substeps substeps = 4、physics_dt = 1/60 s 时 Δt_eff = 1/240 s ≈ 4.2 ms；对外的控制周期仍是 16.7 ms 不变

5. RTF 的吞吐换算：从倍率到每秒环境步

设 N 个平行环境一次全局 world.step() 的墙钟耗时为 Twall，每秒可执行的步数与 RTF 为：

fstep = 1 / Twall，RTF = fstep · physics_dt = physics_dt / Twall "环境步/秒" = N · f_step；训练预算按这个量折算，回合数不参与折算

数值算例：2048 个平行环境、physics_dt = 1/60 s、关闭渲染后 Twall = 2 ms。则 f_step = 500 步/秒，RTF ≈ 8.3，环境步吞吐 ≈ 2048 × 500 ≈ 1.0 × 10⁶ 步/秒。若把 T_wall 压到 0.5 ms（减少碰撞对数量、关闭渲染），吞吐提升到 ≈ 4.1 × 10⁶ 步/秒。反过来做预算：采集 2 × 10⁶ 个环境步，在 10⁶ 步/秒的吞吐下折算为 2 秒墙钟。同一条公式解释了为什么优化物理步进开销比优化算法本身更早见到收益。

6. rendering_dt 与物理时间的解耦

rendering_dt 决定画面刷新周期，与物理积分相互独立，常见配置有两档：

rendering_dt = physics_dt（逐帧渲染），或 rendering_dt = n · physics_dt（每 n 个物理步渲染一次） 渲染开销大时（多相机、高分辨率、大面积材质），拉大 rendering_dt 不影响物理精度，只降低画面帧率

需要区分两个频率：物理世界状态的更新频率由 physics_dt 决定，视觉反馈频率由 rendering_dt 决定。训练时 render=False 相当于把渲染负担整体移除；带视觉观测的训练必须渲染，此时优先降低分辨率与相机数量，再考虑拉长 rendering_dt。把两个周期分开配置，是"物理精度"与"画面流畅"各自独立调优的起点。

7. 最小闭环的验收标准

把"场景能跑"拆成可检验的四条，每条都配一个可量化的判据：

  • 重力生效：立方体 z 坐标从 1.0 m 单调下降到 ≈0.05 m，说明 PhysX 真正在积分状态，USD 里的声明值由引擎同步更新。
  • 接触正确：静止后 z 值波动小于 1 mm，说明接触求解收敛，没有持续抖动。
  • 时间正确：600 步对应仿真 10 s，用"步数 ÷ 频率"核对打印序列的最后一行为 t = 9.0 s，循环结束时累计 600 步、10 s。
  • 可重复：同一脚本连续运行两次，落点与静止轨迹一致（无随机初始化时），说明 reset 语义闭合。

这四条覆盖物理、接触、时间、状态四个维度，后面每一章写出的环境都可以用同样的四问法自检。

8. 步进预算的完整数值算例

把上面的量级关系落成一套能照着算的账。设场景里有 1024 个平行环境，关闭渲染后一次全局 world.step() 的墙钟耗时 Twall = 3 ms，其中固定开销（传感器整理、状态拷贝、调度）约 0.5 ms，物理求解约 2.5 ms。按四步算完整个预算：

第一步，频率与实时倍率。fstep = 1 / 0.003 ≈ 333 步/秒；RTF = fstep × physics_dt ≈ 333 / 60 ≈ 5.6。批量步进不改变单个环境的时间推进速度，所以这个 RTF 对批内每个环境同样成立。

第二步，吞吐。环境步/秒 = N × fstep ≈ 1024 × 333 ≈ 3.4 × 105。要采集 107 个环境步（百万步级训练的一道常见门槛），需要约 107 / (3.4 × 105) ≈ 29 秒墙钟。

第三步，子步的代价。把 substeps 从 1 提到 4，物理部分按子步近似线性增长：2.5 ms 变为 10 ms，固定开销不变，Twall 升至 10.5 ms。此时 fstep ≈ 95 步/秒，RTF 跌到约 1.6，吞吐约 9.8 × 104 环境步/秒，只剩原来的约 29%。子步买到的是积分精度，付出的是近乎等比例的吞吐。

配置TwallfstepRTF吞吐（环境步/秒）
substeps = 13.0 ms约 333约 5.6约 3.4 × 105
substeps = 410.5 ms约 95约 1.6约 9.8 × 104

第四步，把吞吐换算成训练账。若目标是用 3.4 × 105 环境步/秒的吞吐训练 5 × 107 个环境步，墙钟约 147 秒（约 2.5 分钟）；同一目标在 substeps = 4 下需要约 513 秒。两个数字并列，"这一步精度值不值"才有可比较的答案。

极端参数下的两例失效供对照：physics_dt 取到 1/10 s 时，接触任务几乎必然失效（穿透与弹飞的来源见前文），这种步长只适合做纯运动学演示；反过来把 physics_dt 压到 1/1000 s 而环境数不变时，物理部分的开销按 1000 / 60 ≈ 17 倍放大，RTF 会掉到远低于 1，训练在墙钟意义上失去可行性。可行区由"接触精度要求"与"算力预算"共同夹出，这就是本章要你带走的选择逻辑。

再补一条并行规模的边界：当 N 增大到显存或数据通道装不下时，吞吐不再随 N 线性增长，Twall 中固定开销的占比上升。判据是实测 Twall 随 N 的变化曲线：仍近似水平则加环境数最划算，开始明显上翘时应先降低每步的数据搬运量，再考虑扩容。

把吞吐再换算成一次实验的规模：30 分钟墙钟（1800 秒）在 3.4 × 105 环境步/秒的吞吐下对应约 6.1 × 108 个环境步；若把资源缩减到 256 个环境（吞吐约 8.5 × 104 步/秒），同样墙钟只能采到约 1.5 × 108 个环境步。环境数是吞吐的乘数，这两个数字是"要不要再加一批环境"的直接依据。

最后核对渲染与物理的解耦：把 rendering_dt 设成 4 × physics_dt 时，渲染以 15 Hz 推进，画面更新变慢但物理积分仍以 60 Hz 进行，物理精度不受影响，渲染开销降到约四分之一。需要视觉观测的训练里，相机数据跟着 rendering_dt 更新，相当于相机帧率被限制在 15 Hz（与 008 章的频率选择呼应）；纯本体感知的训练则把 render 直接关闭，渲染开销归零。三种配置（逐帧渲染、降频渲染、关闭渲染）覆盖从调试到训练的全部场景，切换时只需改一个参数。

实现思路与设计

搭一个最小仿真世界的完整顺序（每一步的"为什么"都在括号里）：

  1. 启动 SimulationApp（它拉起 Kit，加载物理与渲染扩展；必须先于所有 omni.* 导入，否则扩展还没注册，import 直接报错）。
  2. 创建 World（物理世界的句柄：它统一管理场景对象、时间步与 reset）。
  3. 加地面（没有碰撞平面，立方体会永远下落，这是新手最经典的"东西不见了"问题）。
  4. 加光源（纯物理仿真其实不需要光，但一面黑屏无法确认场景是否正常）。
  5. 加一个刚体立方体（第一个被测对象，验证重力、接触与静止判定）。
  6. world.reset()（把所有对象推到初始状态并对齐物理引擎；忘了它，第一帧的状态可能不对）。
  7. 循环 world.step()（推进物理时间；不 step，世界永远停在第一帧）。

时间参数怎么选：本课程统一用 physics_dt = 1/60 s。理由是机器人控制板卡与训练框架的常见控制周期就是 50–100 Hz；60 Hz 既有足够精度，又能与显示刷新率整除对齐，避免渲染抖动。后续章节涉及高速接触（如插拔）时会用 substeps=4 提高内部积分精度，但对外接口保持 60 Hz 不变。

设计思维：World 在裸 Stage 之上补了什么？

裸 USD Stage 只描述场景，不知道"时间"和"重置"是什么。World 在 Stage 之上补齐了 RL 所需的三件事：批量对象管理、reset 语义、以及可预测的步进接口。当后面做成千上万个平行环境时，你会发现正是这套接口让所有环境可以一次 step 全部推进，这是 Isaac Sim 用于 RL 的核心优势。

把本章涉及的时间与控制参数集中成一张表，后续章节都从这里取默认值：

参数本课程默认值选择理由何时调整
physics_dt1/60 s（≈16.7 ms）与常见控制板卡 50–100 Hz 对齐；与 60 Hz 显示周期整除高速接触任务降到 1/120 或 1/240
substeps1（接触任务用 4）提高内部积分精度，同时保持对外控制周期不变刚度高、接触频繁时加大
rendering_dt1/60 s与 physics_dt 一致，避免视觉状态的时序跳变渲染开销大时设为 physics_dt 的 2–4 倍
render 开关训练 False / 调试 True关闭渲染通常可提升 RTF 20–50%需要视觉观测、人工检查画面时打开

这张表的使用方式是"先取默认值，再按任务改一格"：普通抓取保持 60 Hz 单子步即可；插拔类任务只动 substeps；训练吞吐不足时检查的是环境数与渲染开关，物理精度相关的参数一次只改一个，便于定位效果来源。

再补一个状态内存的数量级估算，用于后续扩容判断：一台 Franka 的动态状态主要是关节位置与速度两个向量，每个自由度按单精度 4 字节算，9 个自由度约 72 字节；加上基座位姿（7 个单精度数约 28 字节），单实例物理状态不足 128 字节。4096 个实例合计约 0.5 MB，相对几何与纹理的显存占用可以忽略。结论：限制并行规模的因素是每秒物理步的计算吞吐与渲染开销，状态存储的份额可以忽略。

关键代码与解读

片段 1：启动应用与创建 World

from isaacsim import SimulationApp  # 拉起 Kit 应用容器（老版本路径为 omni.isaac.kit）

app = SimulationApp({"headless": False})  # headless=True 时不渲染 UI，训练时省显存

from isaacsim.core.api import World  # 注意：必须在 SimulationApp 之后再导入！
world = World(physics_dt=1.0 / 60.0, rendering_dt=1.0 / 60.0)
# physics_dt 是物理积分步长；rendering_dt 是画面刷新周期。
# 两者常保持一致；若渲染很贵，可只调大 rendering_dt，物理精度不受影响。

解读：这三行里最容易忽略的是导入顺序。Kit 的扩展系统是懒加载的，SimulationApp 启动后才会注册 isaacsim.core.api 这些模块的 Python 绑定。先 import 后启动，会得到 "module not found" 或更隐蔽的 API 不完整错误。把启动语句写在文件最顶部、所有业务导入之前，是 Isaac Sim 项目的第一个工程规范。

片段 2：放好地面、光源与第一个刚体

from isaacsim.core.api.objects import DynamicCuboid  # 动态刚体立方体

world.scene.add_default_ground_plane()  # 加地面：自带碰撞与摩擦属性，省去手调

cube = world.scene.add(
    DynamicCuboid(
        prim_path="/World/Cube",   # USD 场景中的唯一路径，后续查询/控制都用它
        name="cube",               # 逻辑名，world.get_object("cube") 用
        position=(0.0, 0.0, 1.0),  # 起始高度 1 m，要让它"掉下来"才能验证物理
        scale=(0.1, 0.1, 0.1),     # 边长 10 cm 的小方块
        mass=0.2,                  # 质量必须显式给：PhysX 按它算惯性与重力响应
    )
)

world.reset()  # 把对象推到初始状态并初始化物理视图；不做这一步第一帧状态不可信

解读：prim_path 与 name 的区别值得记住，前者是场景图里的地址（唯一、层级化），后者是 Python 侧的快捷句柄。mass 显式给了 0.2 kg；质量直接影响接触响应：质量过小，立方体会被求解器的数值误差弹飞。这类"参数背后的物理量级"意识会在后面每一章反复出现。

片段 3：主循环，让时间流动起来

for i in range(600):                # 600 步 × 1/60 s = 仿真 10 秒，足够掉落并静止
    world.step(render=True)         # 推进一帧：物理积分 + 渲染；训练时可 render=False

    if i % 60 == 0:                 # 每仿真 1 秒打印一次状态
        pos, _ = cube.get_world_pose()   # 返回 (位置, 朝向四元数)
        print(f"t={i/60:.1f}s  z={pos[2]:.3f} m")

# 预期输出：z 从 1.0 快速下降，~0.6 s 后稳定在 0.05 m 附近
# （立方体半边长 0.05 m，静止时中心离地 0.05 m）

app.close()   # 显式关闭 Kit，释放 GPU 资源；脚本结束前必须调用

解读：注意 600 步 × 1/60 秒 的换算习惯，后面设计训练预算时，"环境步数"与"仿真秒"之间永远用这个系数互换。另外 world.step(render=True) 的 render 开关在训练时非常关键：关掉渲染后 RTF 通常能再提高 20–50%。最后，app.close() 少了它，进程会挂在后台占着 GPU，这是排查"显存莫名其妙被占满"的第一个检查点。

常见坑

  • 先 import 后启动：任何 isaacsim.* / omni.* 的业务导入都必须放在 SimulationApp(...) 之后，否则模块绑定不存在。症状是启动即报 ImportError 或 AttributeError。
  • 只声明不步进：场景里放好了物体却没有 world.step()，画面永远静止。USD 是声明，PhysX 是执行，记住这条就不会迷路。
  • 把 physics_dt 当成渲染帧率随便调：调大它会直接损害接触精度（1/10 秒步长下物体一步移动近 5 cm），表现为穿透、抖动、莫名弹飞。要提速请增加平行环境数；放大步长会直接换来接触精度的损失。
  • 忘记 world.reset()：第一帧的位姿/速度可能带着上一次运行或默认随机值；RL 环境里忘记 reset 更严重，回合切换时状态不归位，训练数据全被污染。
  • 单位混用：Isaac Sim 内部一律国际单位制（米、千克、秒、弧度）。从 CAD 导入的模型常是毫米，忘了缩放会出现"机器人在 1 mm 尺度上抽搐"的经典事故。

练习与思考

  1. 把 physics_dt 从 1/60 改成 1/10，观察立方体落地。记录首次接触时它"最深的穿透深度"变化，并解释为什么接触精度与步长强相关。★
    提示
    在每步打印 pos[2]，找最小值与最终静止值的差；对比两组参数下的差值数量级。
  2. 给 World 设置 substeps=4（保持 1/60 对外步长），猜测并验证 RTF 与接触质量的变化。★★
    提示
    子步提高的是内部积分精度：接触会更"实"，但每帧物理计算量变为 4 倍。用仿真 10 秒的墙钟时间做对比。
  3. 删除 add_default_ground_plane() 再运行。描述现象，并从"碰撞几何"的角度解释为什么。★
    提示
    没有碰撞平面，重力把人往下拉却没有任何东西"接住"它，这正是奖励函数里"掉落惩罚"的现实来源。
  4. 把立方体质量改为 0.001 kg 与 10 kg 各跑一次，记录静止时的 z 值差异，并解释为什么轻物体更容易受数值误差影响。★★
    提示
    关注接触求解器中的"穿透修正力"与质量的关系：修正力上限通常按绝对数值设定，轻物体更容易被同样的修正力弹起。
  5. 设计一组时间参数，使仿真既能跑 100 个平行环境、又保证插拔任务的接触精度（提示：控制周期 60 Hz + substeps 提高内部精度 + render 关闭）。写下你的参数表并说明每个选择的理由。★★★
    提示
    对外的 physics_dt 决定数据的"时间分辨率"，substeps 决定"数值精度"，parallel environments 决定吞吐，三者各自负责一个维度的折中。

小结

  • Isaac Sim 分三层：Kit（应用容器）→ USD（场景声明）→ PhysX（物理执行）；"声明与执行"的区分是理解一切行为的第一把钥匙。
  • 启动顺序是硬规范：SimulationApp 在最前，其余导入在后。
  • physics_dt = 1/60 s 是本课程的默认控制周期；精度不够时用 substeps 提高内部积分精度，放大步长会损害接触质量。
  • RTF 衡量仿真速度，训练吞吐取决于它；render=False 是第一个提速开关。
