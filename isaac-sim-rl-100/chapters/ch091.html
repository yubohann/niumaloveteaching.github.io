第 091 章：实现双臂协作

两条手臂抬一块板，难点不在"每条臂怎么走"，而在"它们如何保持彼此"：闭链约束、相对位姿与内部力。本章把双机器人协调写成可训练的目标。

  • 主题：系统集成 / 双臂协调与闭链约束
  • 相关组件：Isaac Sim / Isaac Lab / Stable-Baselines3
  • 预计学时：55 分钟
  • 前置章节：第 090 章

学习目标

  • 理解双臂协作与"两个独立单臂"的本质差别：共享工作空间、运动学闭链与内部力。
  • 掌握相对位姿误差与相对雅可比的概念，会用它们设计观测与奖励。
  • 会说清主从、对称与集中式三种协调架构的取舍，以及"单智能体看全部状态"的适用条件。
  • 会设计带相对约束的双臂搬运任务：观测、奖励、课程与评估指标。
  • 能诊断内部力过大、双臂僵持、动作不同步等常见问题。

背景与动机

从本章起进入第五篇"机器人系统集成"：研究重心从"单台机械臂如何把一个动作做好"转向"多个执行机构、多个子系统如何合成一个整体"。双臂协作是第一块试金石，学术界有"两臂 = 一个 14 自由度冗余机器人"的说法，但工程上它远不止维度翻倍：闭链约束会让两条臂通过刚性物体"串"成一个系统，一臂的误差会直接变成另一臂的外力。

这在第 087 章的"刚性接触"里已经见过一次：位置误差 × 高刚度 = 巨大的耦合力。双臂持物是把这一效应放大到极致的情形。学会本章，你就掌握了"多个身体、一个目标"的第一种融合方式；第 093 章的协同搬运与它同源，只是把"刚体连接"换成了"各自独立抓取"。

核心原理

1. 闭链约束：两条臂被物体"焊"在一起

设两臂末端位姿为 T1(q1)、T2(q2)，共同抓持一个刚性物体。若两处抓取点在物体上的相对位姿固定为 Trel（抓取时确定），则任意时刻满足：

T1−1 · T2 = Trel = 常数 6 个标量等式把两条 6-DoF 臂的 12 个自由度约束掉 6 个，剩下的自由度才是"物体能怎么动"

对时间微分得到速度级约束（设两抓取点重合于物体上同一点时为最简）：

v1 = v2，  ω1 = ω2（同一刚体上同一点的速度/角速度必须一致） 若两抓取点有杆长 d：v1 = v2 + ω × d，这就是"相对雅可比"要管住的量

关键推论：双臂的关节速度必须在任务空间"对得上"，任何不一致都会让物体承受内应力。

2. 内部力：闭链的代价

想象两条高刚度臂分别用位置控制把同一个刚性物体"按"向两个略不一致的目标点：位置误差 Δx 被两臂的等效刚度 k1、k2 串起来放大成内部力。串联刚度 keq = k1k2/(k1+k2)：

finternal ≈ k1Δx / 2（对称情形） k=5000 N/m、误差 5 mm ⇒ 12.5 N 的内部力；20 mm ⇒ 50 N，足以让薄板弯曲/夹爪打滑

处理办法有三类：（1）降低刚度：至少一臂用阻抗/力控（第 048、087 章），给误差留柔顺空间；（2）主动协调：让一臂"主"、另一臂"从"，从臂只跟踪相对位姿（误差闭环吃掉不一致）；（3）让 RL 负责一致性：把相对位姿误差写进观测与奖励，让策略学会"同时动"。本章主要走第 2+3 条路线。

3. 相对位姿与相对雅可比

"相对位姿误差" erel 描述两末端偏离期望相对关系多少：位置部分 ep = p2 − p1 − ddes，姿态部分用第 086 章的旋转误差向量。它的"速度版"是相对雅可比：

ėrel = Jrel(q)·q̇，  Jrel = [−J1o(q1),  J2o(q2)] 定义在对物体的观察坐标系 o 下；相对雅可比把 14 个关节速度映射成 6 维相对误差变化

经典协调控制用它做零空间上的相对位姿闭环；对我们而言，erel（6 维）直接进观测、相对雅可比只用于理解"哪些关节组合不会破坏约束"。一个有用的数字：7+7 自由度的双臂系统，维持 6 维相对约束后还剩 8 个可用自由度，这是冗余，可以分配给避障、姿态舒适度等次级目标（第 084 章零空间思路）。

4. 架构选型：单智能体还是多智能体

架构观测/动作优点缺点
集中式（单策略）14 关节 + 物体状态 → 14 维动作协调自然、实现简单维度高、泛化到不同搭档难
主从式主臂策略 + 从臂跟踪相对位姿结构清晰、从臂用经典控制从臂的灵活性受限
多智能体（第 059 章）每臂独立观测/策略可模块化、可迁移需要处理信用分配与通信

本题材从"集中式"起步性价比最高：仿真环境里状态获取无成本，先验证任务可学，再谈架构先进性。

实现思路与设计

  1. 任务：双臂共持一根 0.6 m 的杆（两端各一抓取点），把杆从初始位姿搬运到目标位姿（位置 ±1 cm、姿态 ±3°），全程保持两抓取点相对位姿恒定。
  2. 观测：两臂关节位置/速度（14 维）+ 杆的位姿误差（旋转误差向量 3 维 + 位置 3 维）+ 相对位姿误差 erel（6 维）+ 上一动作。上一步动作依旧必要（接触/耦合系统的速度感）。
  3. 动作：14 维关节位置目标（PD 底层，刚度 200–500 N·m/rad 偏低，留柔顺），或 14 维速度指令。不推荐两臂都是高刚度位置目标。
  4. 奖励：主项 −‖eobj‖（物体跟踪）− 0.5·‖erel‖（相对约束）− 平滑项 − 自碰撞惩罚；成功 +1。相对项权重不能过大，否则策略学到"两手僵持不动"（不动时 e_rel 恒为零）。
  5. 防僵持技巧：相对项只在物体运动的前提下降权（用物体速度门控），或采用"分阶段"：先学搬运、再把相对项加进来微调。
  6. 课程：阶段 1 两臂抓取点相距的期望设为"几乎重叠的位置跟踪"（退化为两个独立任务）；阶段 2 拉开到真实杆长。
  7. 评估：物体位姿误差、erel 的 P95（内部力代理）、两臂关节力矩峰值、自碰撞次数、任务时长。
设计思维：相对约束是"防打架"的通用模式

把"两个部件必须保持某种关系"直接写成误差项，是集成篇反复出现的模式：双臂（本章）、多机器人搬运（第 093 章的负载分配）、编队（第 094 章的相对队形）、外骨骼的人机耦合（第 099 章）都在用。观察对象不同（物体、邻居、人），但"关系误差进观测、进奖励"的手法一致，学会本章，后面四章都能直接迁移。

关键代码与解读

片段 1：相对位姿误差（位置 + 旋转）

import torch

def relative_pose_error(p1, q1, p2, q2, p_rel_des, q_rel_des):
    """两末端之间的相对位姿误差：先把臂2的位姿变换到臂1坐标系，
    再与期望相对位姿比较。p: (B,3) 位置；q: (B,4) 四元数。"""
    # 1) 位置误差：转到"臂1姿态"下比较，避免世界系旋转带来的伪误差
    R1 = quat_to_matrix(q1)                       # (B,3,3) 臂1朝向
    dp_world = p2 - p1                            # 世界系位置差
    dp_1 = (R1.transpose(-1, -2) @ dp_world.unsqueeze(-1)).squeeze(-1)
    e_pos = dp_1 - p_rel_des                      # 期望相对位置（如 (0.6,0,0)）
    # 2) 旋转误差：相对旋转 q1^{-1} ⊗ q2，再与期望相对四元数求误差
    q_rel = quat_mul(quat_inverse(q1), q2)        # 当前相对朝向
    e_rot = orientation_error_vector(q_rel, q_rel_des)   # 3 维旋转向量
    return torch.cat([e_pos, e_rot], dim=-1)      # (B,6) 相对位姿误差

# 单测习惯：p2=p1、q2=q1、p_rel_des=0、q_rel_des=单位四元数时，
# 返回应精确为 0 向量；相对误差算错是双臂调不通的第一大原因

解读：三处设计。（1）位置误差先转到臂 1 坐标系再比较：如果两臂在世界系下"绝对位置"一致但姿态错了 30°，世界系的差值是误导性的；相对误差必须在相对参考系里看，这与第 087 章 C-frame 的思想同源；（2）旋转误差沿用第 086 章的工具函数，说明前面打的地基在集成篇直接复用；（3）最后一行"单测习惯"是实战经验：相对位姿误差符号写反、四元数顺序写反，都会让奖励曲线显示"任务不可学"，而真相是算错了。写双臂代码前，先跑这个零误差对拍。

片段 2：双臂环境的奖励，防僵持的相对约束

class DualArmCarryEnv:
    """双臂搬运：物体跟踪为主，相对约束用"物体运动门控"防僵持。"""

    def __init__(self, num_envs, w_rel=0.5, rel_gate=0.05, w_coll=0.1):
        self.w_rel = w_rel             # 相对约束权重：过大→僵住，过小→撕扯
        self.rel_gate = rel_gate       # 门控阈值：物体速度 > 0.05 m/s 才计相对项
        self.w_coll = w_coll           # 自碰撞惩罚权重

    def compute_reward(self, e_obj, e_rel, obj_vel, self_collide, time_scale=0.01):
        r_obj = -torch.linalg.norm(e_obj, dim=-1)            # 物体跟踪（主任务）
        # 防僵持：物体不动时，"保持相对位姿"毫无意义，还会把"僵持"变成奖励
        moving = obj_vel.norm(dim=-1) > self.rel_gate
        r_rel = torch.where(moving, -self.w_rel * e_rel.norm(dim=-1),
                            torch.zeros_like(obj_vel.norm(dim=-1)))
        r_coll = -self.w_coll * self_collide.float()         # 自碰撞一次性惩罚
        return r_obj + r_rel + r_coll - time_scale

    def check_success(self, e_obj, e_rel, hold_steps):
        # 成功 = 物体到位 + 相对约束满足 + 保持 N 步（防"瞬间甩到位"）
        return (e_obj.norm(dim=-1) < 0.012) & (e_rel.norm(dim=-1) < 0.02) & (hold_steps > 15)

解读：（1）rel_gate 是本段的核心发明，第 087 章我们用类似的"末段激活"保证速度匹配项不被钻空子，这里同理：相对约束项是"保持项"，天然有"不动最安全"的退化解，用物体速度做门控后，只有真正在运动时才考核相对一致性；（2）自碰撞用一次性惩罚（类似第 087 章的冲击）：碰撞属于瞬时事件，一次性 −0.1 配合每步时间税即可形成清晰梯度；（3）成功判据里的 hold_steps > 15（0.25 秒）确认"稳住"，没有它，策略会学会用极限速度"甩"到目标点让误差瞬间扫过阈值。

片段 3：低刚度驱动与相对雅可比监控

def configure_dual_arm(articulation, stiffness=300.0, damping=30.0):
    """给双臂设置"柔顺位置驱动"：刚度比单臂任务低，为闭链误差留余地。
    参考量级：单臂点到点 800-2000 N·m/rad；双臂耦合 200-500 更稳。"""
    # 不同版本配置驱动的接口名有差异（如 get_articulation_controller /
    # set_gains 系列），以官方 API 为准；这里给出概念性写法
    kps = [stiffness] * articulation.num_dof
    kds = [damping] * articulation.num_dof
    # 手腕小关节的力矩小，增益按关节惯量比例再缩放更合理
    for i, name in enumerate(articulation.dof_names):
        if "wrist" in name.lower():
            kps[i] *= 0.5                     # 腕部减半：避免小关节"较劲"
            kds[i] *= 0.5
    return kps, kds

def relative_jacobian_check(J1, J2):
    """相对雅可比秩检查：若 rank 不足，说明该位形下无法独立控制相对位姿。
    J1/J2 均在观察系 o 下（B,6,7）。"""
    import torch
    J_rel = torch.cat([-J1, J2], dim=-1)      # (B,6,14) 相对雅可比
    s = torch.linalg.svdvals(J_rel)           # 14 维关节对 6 维相对任务
    rank_ok = (s[:, 5] > 1e-3)                # 第 6 个奇异值不为零 ⇒ 满秩
    return rank_ok, s[:, -1]

解读：（1）刚度建议不是拍脑袋：闭链柔性 = 两侧刚度串联，单臂刚度降一半，内部力同样降一半，而跟踪精度在低速搬运任务里够用，用跟踪精度换内部力，是双臂设计中必须做的第一笔交易；（2）腕部增益减半是"按关节能力分配刚度"的示例：大关节扛负载，小关节当"缓冲垫"；（3）相对雅可比检查回答"这个位形下两臂能否合作"：第 5 个奇异值太小时，某个相对位姿方向无法独立控制，这不是策略的锅，是运动学结构问题，只能靠换位形解决。

常见坑

  • 双臂都用高刚度位置控制：内部力随位置误差线性放大（k=5000 时 5 mm 就 12.5 N）。症状是杆/板"抖动、吱吱响"或仿真里数值能量暴增。修复：一侧或两侧降刚度/改用阻抗，或明确主从。
  • 相对约束权重过大：策略学到"僵持不动"（e_rel 恒零是局部最优）。症状是物体跟踪误差居高不下、动作幅度极小。修复：物体运动门控 + 主任务权重占优。
  • 相对位姿误差公式写错：坐标系顺序、四元数乘法顺序、符号任一处错就得到"不可能任务"。修复：零误差对拍单测（片段 1 的最后一行）。
  • 忽略自碰撞：共享工作空间里两臂互相穿模，仿真跑通、真机撞臂。修复：碰撞惩罚 + 探测距离进观测（用最小距离或接近度）。
  • 成功判据没有"保持时间"：高速甩到位的瞬间扫过阈值被记为成功。修复：hold_steps 确认（≥0.25 s），并统计"到位后反弹"比例。
  • 把物体位姿直接当观测，但没有相对量：策略只看到"物体离目标多远"，不知道"两臂是否对齐"，协调全靠猜。修复：e_rel 必须进观测，它是协调的充分统计量。

练习与思考

  1. 推导：两臂在相同物体上抓取点相距 d=0.6 m 时，纯旋转（角速度 ω）对两个抓取点速度的约束关系，写出 v1−v2 的表达式。★★
    提示
    刚体上两点的速度差等于 ω × (r1 − r2)；相对位姿正确时这个差恰好由杆长与旋转决定；若它取任意值，说明相对位姿算错了。
  2. 把相对约束权重 w_rel 从 0.1、0.5、2.0 各训一次，记录物体跟踪误差与"物体速度门控时长占比"。★★★
    提示
    w_rel=2.0 时预期看到"僵持"，物体速度长期低于门控阈值的比例显著上升，任务时间变长。
  3. 把两臂刚度从 300 提到 3000 N·m/rad，观察内部力代理指标（e_rel 的 P95 与关节力矩峰值）的变化。★★
    提示
    刚度大时同样的 e_rel 会产生更大内部力；用"关节力矩 × 相对雅可比"估算内部力，观察趋势。
  4. 设计：让一臂只在水平方向动作、另一臂负责全部竖直方向（分工），对比集中式策略的样本效率。★★★
    提示
    分工方案把 14 维搜索空间砍掉一半耦合，通常收敛更快但上限略低，用"达 80% 成功率步数"与"最终成功率"两栏对比。
  5. 实验：把 hold_steps 从 15 改成 0，统计"到位后反弹超过 2 cm"的回合比例，解释这一失败模式。★
    提示
    没有保持要求时，策略会用极大速度扫过目标点；反弹比例是衡量"是否稳稳停住"的量化指标。

小结

  • 双臂协作的核心是闭链约束：T1−1T2 = Trel 常数；违背约束的误差会被刚度放大成内部力（k=5000 时 5 mm → 12.5 N）。
  • 协调手段：降刚度/阻抗化、主从分工、把相对位姿误差 erel 写进观测与奖励，三招可叠加。
  • 奖励设计要点：物体跟踪为主、相对项运动门控防僵持、自碰撞与冲击用一次性惩罚、成功判据要求保持 ≥0.25 s。
  • 架构从集中式起步验证可学性；相对雅可比秩检查回答"两臂能否在该位形合作"。
  • 下一章让机械臂"长上轮子"：底盘与臂的耦合带来新的约束（稳定裕度、任务优先级）与机遇（更大的工作空间），移动机械臂操作，见第 092 章。
