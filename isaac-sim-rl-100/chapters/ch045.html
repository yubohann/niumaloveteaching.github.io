第 045 章：实现双足机器人行走

双足没有对角腿可以配对，支撑多边形退化成一条窄线：本章用线性倒立摆与捕获点解释"为什么必须迈步才能不摔"，并给出落足点奖励、双支撑约束与直立惩罚这套双足专用奖励设计。

  • 主题：任务实现 / 双足行走与平衡
  • 相关组件：Isaac Sim / Isaac Lab / rsl_rl 风格 PPO
  • 预计学时：60 分钟
  • 前置章节：第 044 章

学习目标

  • 能说清双足稳定性比四足差在哪：支撑多边形维度、质心高度、踝关节扭矩限制与单支撑期占比。
  • 理解线性倒立摆模型（LIPM）与捕获点（capture point）的推导直觉，会用它解释"落足点决定加减速"。
  • 会把捕获点/Raibert 落足律写进观测或奖励，并说明它在训练中充当什么角色。
  • 掌握双足奖励与四足奖励的四组关键差异：直立惩罚、落足点奖励、双支撑奖励、横向漂移惩罚。
  • 会设计"站立 → 原地踏步 → 慢走 → 常速"的速度课程，并理解为什么双足课程必须比四足更细。
  • 能诊断双足训练的典型失败：原地小碎步、向前扑倒、左右摇摆累积、落地砸脚。

背景与动机

双足行走是人形机器人（humanoid）能力的入场券：只有会走，才谈得上进入人类环境、上楼梯、跨门槛。但它也是足式控制里最难的一档，四足走 trot 时始终有一对对角腿撑地，而双足单支撑期只靠一只脚，支撑多边形小到接近一个点，质心还悬在 0.9 m 高的地方。更糟的是，踝关节扭矩有限，脚掌方向能提供的恢复力矩有硬上限：一旦质心偏出脚掌太远，靠脚踝已经救不回来，唯一的恢复手段是迈步。

这句"必须迈步"背后是双足训练的全部难点：策略不仅要学会抬腿摆腿，还要学会"把脚踩到哪里"，落足点本质上是一个控制变量，它同时管平衡与速度。本章先把这套物理直觉讲透（LIPM 与捕获点），再落成可训练的环境：观测、奖励、课程与终止条件。它与第 044 章共用"相位 + 周期性奖励"的骨架，你要重点体会的正是奖励设计上那几处差异。

核心原理

1. 双足 vs 四足：稳定性的三重劣势

维度四足 trot双足 walk
支撑多边形对角线（两点，跨躯干前后）单脚掌（近似一个点）；双支撑期也只是一条窄带
质心高度0.3–0.5 m，翻倒所需能量高0.8–1.0 m，重力势能差大，倒下更快
单支撑占比约 50%，且对角腿互相"对拉"约 70–80%，单脚独立支撑，无对拉伙伴
恢复手段再迈一步，代价低只能靠踝扭矩 + 落足点，踝扭矩有硬上限

结论：四足是"两个稳定三角轮流工作"，双足是"持续可控的摔倒"。这决定了两件事，双足的观测里必须包含躯干姿态的精细信息（倾斜从 5° 长到 15° 往往只用 0.3 s），奖励里必须有比四足更重的直立惩罚。

2. 线性倒立摆：把身体近似成一根晃动的杆

假设双腿质量远小于躯干，身体可以近似成一根"质心在顶端、脚在底端"的倒立摆。当支撑脚固定不动时，质心水平动力学近似为线性方程：

ẍ = ω02·(x − p),   ω0 = √(g / h) x 为质心水平位置，p 为支撑点（脚）位置，h 为质心高度

取 h = 0.9 m，则 ω0 ≈ 3.3 rad/s，对应时间常数 1/ω0 ≈ 0.3 s。这个方程的含义是"偏离支撑点越远，被推得越快地倒"，标准的不稳定平衡。要让它停下来，脚必须提前移动到质心将要跑到的地方。

3. 捕获点：该把脚踩到哪

对上面的方程做一次积分，可以得到一个漂亮的不变量。定义捕获点（capture point）：

ξ = x + ẋ / ω0 位置 + 速度除以自然频率；h=0.9 m、走 1.2 m/s 时 ξ 在质心前方约 0.36 m

它的物理含义：如果把脚恰好踩在 ξ，质心速度会在"自然刹车"的过程中衰减到零，且正好停在脚的正上方。验证数字：v = 1.2 m/s 时 ẋ/ω0 = 0.36 m，这就是为什么人走得越快，脚越要往前伸。工程上的落足律（Raibert 型）在捕获点基础上加两个修正：

pfoot = x + vdes·Tstep/2 + k·(v − vdes) 第一项决定"跟着指令走多快"，第二项 k·(v − vdes) 是稳定项：快了就多踩前一点减速

第二项是精髓：落足点同时是速度控制器。把实际速度与期望速度之差乘一个增益 k（典型 0.1–0.3 s），得到"额外往前/往后挪多少"，这就是双足行走中"用脚控制速度"的数学表达。训练里它有两个用法：直接算出来进观测（把"理想落点"当先验喂给策略），或算出来进奖励（要求实际落点靠近它）。

4. 步态相位与双支撑

双足的相位框架和四足相同：每条腿一个相位 φi ∈ [0, 1)，左右腿差 0.5。差别在 duty（支撑期占比）：双足 walk 的 duty 取 0.6–0.7，于是两个相位图存在重叠区间，重叠部分即双支撑期（占总周期 20–40%）。双支撑期是双足稳定的"窗口"：这段时间内支撑多边形从点扩展成一条带，质心可以在上面短暂"喘息"并完成重心转移。duty = 0.5 会得到没有双支撑的走法（更像竞走/小跑），训练上更难、更接近持续单脚平衡，不建议作为第一版目标。

5. 数值算例：捕获点数量级、发散速度与双支撑窗口

把数字代入前面的公式。h = 0.9 m 时 ω₀ = √(9.81/0.9) ≈ 3.30 rad/s，时间常数 1/ω₀ ≈ 0.30 s；行走速度 1.2 m/s 时捕获点 ξ 位于质心前方 1.2/3.30 ≈ 0.36 m。这个 0.36 m 与常见人形机器人的髋部可达步长（0.3–0.5 m）同阶，说明"以 1.2 m/s 行走"本身就处在"脚要伸到接近最大步长"的位置，速度上限很大程度上由捕获点几何决定（电机能力在此之上还有富余）；这也解释了双足课程必须一档一档加：速度每上一档，落足点前送量按 v/ω₀ 线性增长，0.9 m/s 时是 0.27 m，1.2 m/s 时是 0.36 m，每一步都在消耗步长余量。

发散速度的核算同样直接。LIPM 的偏差按 eω₀t 增长：1 cm 的初始质心偏移，0.3 s 后变成 2.7 cm，0.6 s 后 7.2 cm，0.9 s 后接近 0.19 m。这组数字是"摔倒判定要早"的数学根据：从 5° 倾斜到 20° 只需约 0.4–0.5 s，若终止阈值放宽到 1.0 rad，策略会把大量样本花在"已不可恢复"的状态区间里，信用分配被污染。训练时还可以把发散速度当诊断量：统计"终止前 0.3 s 内质心偏移的增长率"，增长率接近 ω₀ 说明是真摔，远低于 ω₀ 说明终止条件可能过严，误杀了一些还能救回的回合。

双支撑窗口最后算：duty = 0.65 时两腿支撑区间各占周期的 65%，重叠部分为 2×0.65 − 1 = 30%；duty = 0.6 时重叠降到 20%。步态周期 0.6 s 时，30% 意味着双支撑持续 0.18 s，约 11 个 60 Hz 策略步。这段时间正是重心从一只脚倒向另一只脚、落足点验证走完的窗口，缩短它会让步态明显变"赶"，也与设计里"双支撑时长给 +0.3 奖励"的动机吻合：该奖励不是装饰，它直接购买这 0.18 s 的重心转移时间。

奖励项之间的量级也核一遍（以 0.9 m/s 档为例）：速度跟踪误差 0.15 m/s 时指数核得 0.37；落足点误差 5 cm 时罚 0.1；直立角 0.1 rad（约 6°）时姿态平方罚 1.5×0.01 ≈ 0.015。三项量级分布在"零点几、零点一、零点零几"三档，其中直立罚在接近终止阈值的 0.6 rad 时才显著：0.6²×1.5 = 0.54，接近速度跟踪满分的量级，这正符合"直立在危险区间才发力"的意图。如果直立权重被随意调到 −5，直立角 0.1 rad 的常规波动就要罚 0.05/步，策略会把行为压缩成"僵直少动"，速度跟踪随之掉档，这是"把双足当四足训"后出现僵直步态的一个具体成因。

实现思路与设计

双足环境的搭建流程，以及每一处与 044 章不同的设计理由：

  1. 资产与初始状态：人形机器人（本节用双腿 ≈ 12 自由度、躯干浮动基座）；开回合时从站立、双支撑开始，速度指令从零起步。四足常常能从任意姿态起步，双足不行，悬空起步等于给策略送一个必摔的回合。
  2. 控制链：仿真 240 Hz、策略 60 Hz（decimation=4），比四足更高：双足的接触事件更密集（脚掌拍地），控制延迟的容忍度更低。踝关节 PD 增益要留余量，别让踝先饱和。
  3. 观测（约 55–60 维）：躯干姿态（重力投影 3 维）、躯干角速度、质心线速度、速度指令、左右脚位姿与接触、关节位置/速度、上一步动作、相位时钟（8 维）+ 期望触地（2 维）、名义落足点（2 维，由片段 1 的落足律算出）。把落足先验直接进观测，是双足收敛速度的关键差异点。
  4. 奖励（相对四足的四组强化）：直立惩罚 ×2–5、落足点误差惩罚、双支撑奖励、横向漂移惩罚；速度跟踪仍用指数核，但 σ 取 0.15（比四足的 0.5 小），因为双足速度波动本来就更小。
  5. 课程：vx 上限按 0 → 0.05 → 0.2 → 0.5 → 0.9 m/s 五档推进，每档要求近 50 回合的速度跟踪误差小于 0.15 m/s。0.05 m/s 这一档看起来无用（只是"原地踏步"），但它是双足学会重心转移的必经台阶。
  6. 终止：躯干俯仰/横滚超过 0.6 rad（约 34°，比四足的 0.8 更严）、质心高度跌到 0.6 m 以下、或脚掌接触力超过体重 3 倍。摔倒判定要"早"，让策略在进入不可恢复状态前就结束回合。
  7. 随机化：初始站立姿态 ±3°、地面坡度 0–2%、脚底摩擦 0.5–1.0、躯干质量 ±15%、观测与动作延迟 0–15 ms。双足对延迟极敏感，这一步不能省。
奖励项四足典型值双足典型值为什么不同
直立（姿态平方罚）−0.3−1.5双足倾倒是失败，小角度也危险
落足点误差通常不需要−2.0落足点是双足唯一的速度/平衡控制变量
双支撑时长无需（trot 无此相）+0.3鼓励利用双支撑窗口做重心转移
横向速度较宽松−1.0·|vy|双足左右摇晃会累积成侧向翻倒
速度跟踪 σ0.50.15双足速度波动小，容差必须更细
设计思维：为什么把"名义落足点"放进观测，只放进奖励有什么问题？

放奖励里，策略要靠 trial-and-error 从"落点错了被扣分"反推落点该在哪，学习曲线长；放观测里，相当于把 LIPM 的解析结论当先验直接交给网络，它只需要学"怎么把脚放到给定点"这种低层技能。这就是足式训练里最常见的"控制先验进观测、学习负责执行"范式：能被经典理论算出来的量，就不该让神经网络从零学。奖励里保留落足项，则是为了在策略偏离先验时提供纠偏梯度，两者不矛盾。

关键代码与解读

片段 1：捕获点与 Raibert 落足律

import numpy as np

G = 9.81

def raibert_footstep(com_pos, com_vel, v_des, com_height, step_time, k=0.2):
    # 1) 捕获点：xi = x + v / omega0。把脚踩在 xi 上，速度会自然衰减到 0
    omega0 = np.sqrt(G / com_height)                 # h=0.9 m 时约 3.3 rad/s
    xi = com_pos[:2] + com_vel[:2] / omega0

    # 2) Raibert 落足律 = 匀速前送项 + 速度误差稳定项
    #    v_des * T/2：以期望速度走半步时会到的位置
    #    k * (v - v_des)：实际比期望快就再往前踩一点；落点越靠前，减速效果越强
    nominal = com_pos[:2] + v_des[:2] * step_time * 0.5 \
              + k * (com_vel[:2] - v_des[:2])

    # 3) 机械约束：落点必须在腿的可达范围内（步长上限 0.45 m，髋关节几何决定）
    delta = nominal - com_pos[:2]
    if np.linalg.norm(delta) > 0.45:
        nominal = com_pos[:2] + delta / np.linalg.norm(delta) * 0.45
    return nominal, xi

解读：这段代码把 LIPM 的理论结论翻译成了两个坐标。第一，xi（捕获点）是"紧急刹车点"，当策略发现速度过快时，理论上只要把脚伸到 ξ 就能停；它同时是很好的观测特征，能让策略"看见"自己的不稳程度。第二，nominal 是"正常行走点"，它在捕获点的基础上偏向期望速度方向：走得越快，脚越靠前。第三，最后的三行裁剪不可少：Raibert 律给出的点在理论上正确，但可能超出髋关节的可达步长（典型 0.4–0.5 m），一旦超了，策略就被要求执行一个物理上做不到的动作，训练里表现为"落足点奖励永远拿不满"。先裁剪再进观测/奖励，保证先验永远可行。注意 step_time 的取值：一个步态周期 0.6 s、双腿各占一半时，单腿的半步时间约 0.3 s，若把它误当成整个周期，前送项会大一倍，落足点系统性前偏。

片段 2：双足专用奖励项

def biped_reward(state, nominal_l, nominal_r, cmd, dt):
    # 1) 直立：俯仰/横滚平方罚权重 1.5，比四足高 5 倍；角速度单独再罚一次
    r_upright = -1.5 * (state["rpy"][0] ** 2 + state["rpy"][1] ** 2) \
                - 0.5 * np.linalg.norm(state["ang_vel"][:2])

    # 2) 落足点误差：摆动脚应该落在名义点上；只考核摆动结束前 0.1 s，避免全程拉扯
    if state["swing_landing_soon"]:
        err_l = np.linalg.norm(state["foot_pos"][0][:2] - nominal_l)
        err_r = np.linalg.norm(state["foot_pos"][1][:2] - nominal_r)
        r_step = -2.0 * (err_l + err_r)
    else:
        r_step = 0.0

    # 3) 双支撑奖励：两脚同时触地的采样给正分，鼓励利用双支撑窗口转移重心
    r_double = 0.3 * float(state["contacts"][0] and state["contacts"][1])

    # 4) 横向漂移：双足天生左右晃，v_y 必须压住；同时罚踝关节的横向力矩峰值
    r_drift = -1.0 * abs(state["com_vel"][1])

    # 5) 落地冲击：摆动脚触地瞬间的竖直速度小于 0.3 m/s 才不罚（软着陆）
    r_land = -0.5 * max(0.0, state["foot_vel_z"] - 0.3) if state["just_landed"] else 0.0
    return r_upright + r_step + r_double + r_drift + r_land

解读：五项各管一个失败模式。直立项把"姿态角平方 + 角速度"都拴住：只罚角度会让策略学"快速晃过去"的动平衡钻空子，加上角速度罚才逼它真正稳住。落足项只在 swing_landing_soon（触地前约 0.1 s）打开，是一个重要技巧：摆动早期脚还在空中高速移动，落点误差天然很大，全程考核会给大量"不可避免的罚分"淹没信号；只在临落地前考核，梯度才指向"最后阶段往名义点收脚"。双支撑奖励量级不大（0.3）但要开，它是唯一直接鼓励"停下来换重心"的信号，关掉后策略倾向于快速倒脚、跳过双支撑相，走出很"赶"的步态。横向漂移罚 1.0·|vy| 看似很凶，但双足横向速度正常波动在 0.05 m/s 以内，折算每步只有 0.05 分，属于"平时不痛、漂了很痛"的正确量级。落地冲击项用 max(0, v_z − 0.3) 的软阈值：低于 0.3 m/s 完全不罚，超过才线性累加，避免策略为了"轻落"而不敢落脚、拖长摆动期。

片段 3：速度课程与晋级判据

class SpeedCurriculum:
    # 双足课程表：直接学 0.9 m/s 几乎必摔，0.05 m/s 这档专门学"重心转移"
    STAGE_MAX = [0.0, 0.05, 0.2, 0.5, 0.9]          # v_x 上限，单位 m/s

    def __init__(self, promote_err=0.15, window=50):
        self.stage = 0                              # 当前档位
        self.history = []                           # 每回合的速度跟踪误差
        self.promote_err = promote_err              # 晋级门槛
        self.window = window                        # 统计窗口（回合数）

    def sample_cmd(self):
        vx_max = self.STAGE_MAX[self.stage]
        # 档位内均匀采样；最大档的 50%-100% 区间单独加权，训练高速步幅
        if vx_max == 0.0:
            return np.array([0.0, 0.0, 0.0])
        vx = np.random.uniform(0.5 * vx_max, vx_max)
        return np.array([vx, 0.0, 0.0])

    def update(self, episode_err):
        self.history.append(episode_err)
        if len(self.history) >= self.window:
            recent = float(np.mean(self.history[-self.window:]))
            # 连续窗口内误差都达标才晋级：单回合侥幸不发车
            if recent < self.promote_err and self.stage + 1 < len(self.STAGE_MAX):
                self.stage += 1
                self.history.clear()

解读：课程机制的三个细节决定成败。第一，档位划分的密度：四足的课程可以从 0.3 直接跳到 0.8，双足不行，0.05 → 0.2 → 0.5 → 0.9 这条链看起来保守，但每一档的步幅差异都对应"落足点前送量"的显著变化（参见片段 1 公式里的 vdes·T/2 项），跨档太大策略会直接摔到学不动。第二，晋级判据用窗口平均：双足训练偶发性的"侥幸回合"很常见（顺着惯性晃着走完），单回合达标就晋级会把课程推进到策略并不掌握的速度上。第三，晋级时 history.clear()：让新档位重新累计窗口，避免旧档的低误差样本"带分"进来。最后注意 0.0 档的处理：直接返回零指令，让策略在这一档专门学"站着别倒、重心左右转移"，这是双足的站立课，通常几千个回合就能过关，但它把后面所有档位的成功率提高了不止一倍。

常见坑

  • 原地小碎步（vx 上不去）：策略发现高频小步最安全，速度指令被"磨"在 0.2 m/s 以下。症状是步频明显高于设定、步幅很小。修复：检查速度跟踪 σ 是否过大（0.15 合适）、给步频设上限，并确认落足前送项在奖励中确实生效，小碎步的本质是"不敢把脚往前踩"。
  • 向前扑倒：策略学会"前倾 + 快速倒脚"的冲刺式走法，慢速段反而不会走。修复：课程回到 0.05 m/s 档重练双支撑定步，加大直立项权重，并在终止条件里加上"质心偏离支撑点超过 0.25 m"这一条。
  • 左右摇晃累积：横向速度没罚或太小，策略利用侧向摆动换重心，短期走得"省力"，几十步后横滚角累积翻倒。修复：横向漂移罚提到 −1.0 量级，观测里加入横滚角与横滚角速度，终止阈值收紧到 0.6 rad。
  • 落地砸脚：没有冲击约束时，策略用"猛踏地"获取恢复力矩，仿真里关节扭矩尖峰明显，真机上一周就得换减速器。修复：落地竖直速度软阈值罚（片段 2 的第 5 项），并检查接触力分布的重尾。
  • 把双足当四足训：直接复用四足的超参（直立权重 0.3、σ=0.5、终止姿态 0.8 rad），结果是训练不收敛或收敛到"僵尸走"，身体僵直、靠高频抖动挪动。修复：按本章表格把四组参数全部重调，尤其是直立权重与终止阈值。

练习与思考

  1. 把晋升函数（片段 1）的 k 从 0.2 调到 0.05 与 0.5，观察策略速度跟踪的收敛速度与稳定性，解释 k 的作用。★★
    提示
    k 太小，落足点对速度误差不敏感，策略反应慢、超调大；k 太大，落足点随速度噪声剧烈跳动，轨迹发抖。k 是"用脚刹车"的增益。
  2. 去掉双支撑奖励（其余不变），记录步态周期中双支撑相占比与能耗代理（扭矩平方积分）的变化。★
    提示
    观察触地时序：双支撑占比小于 10% 时步态会明显"赶"，能耗通常反而更高，因为单腿支撑期需要更多踝扭矩来维持。
  3. 做一个对照实验：观测里有/无名义落足点（其余不变），对比达到 0.5 m/s 档位所需的训练步数。★★
    提示
    无落足先验时策略要从零学"脚往哪踩"，收敛步数通常增加 2–4 倍。注意两组要用同一课程与随机种子组。
  4. 设计实验找出你的机器人的"最大稳定步长"：写出扫描方法、判定指标与预期曲线形状。★★★
    提示
    固定步频、逐步增大落足前送量，记录能维持 N 步不摔的上限；通常上限随步频降低而增大，曲线在某个步频附近有一个"最快又稳"的峰值。
  5. 把终止阈值从俯仰 0.6 rad 放宽到 1.0 rad，预测并验证训练结果，为什么"摔倒判定要早"？★
    提示
    放宽后策略会在"已不可恢复"的姿态里继续获得大量样本与部分奖励，信用分配被污染，最终学会"拖着残姿多撑几步"的坏习惯。

小结

  • 双足的稳定性劣势是三重的：支撑区退化成点/窄带、质心高、踝扭矩有限，恢复只能靠迈步，落足点因此成为核心控制变量。
  • LIPM 给出 ω0=√(g/h)≈3.3 rad/s 与捕获点 ξ = x + ẋ/ω0；Raibert 落足律 = 匀速前送 + k·速度误差，是"用脚控制速度"的解析先验。
  • 能解析算出来的量（名义落足点）应进观测当先验，奖励里保留落足误差项做纠偏，"先验 + 学习"的组合最省样本。
  • 双足奖励相对四足的四处加强：直立项 ×5、落足点误差项、双支撑奖励、横向漂移罚；σ 从 0.5 收到 0.15。
  • 课程要比四足更细（0 到 0.9 m/s 共五档），晋级用窗口平均；摔倒终止必须早，避免污染信用分配。
