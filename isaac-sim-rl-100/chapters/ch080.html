第四篇 · 控制与优化

第 080 章：实现容错控制

电机卡死、关节掉力、传感器漂移：故障一定会发生，问题只在"何时"。本章讲检测（残差）、隔离（定位到部件）、容纳（重新分配控制）三段式，并在 Isaac Sim 中注入故障训练出带健康掩码的策略。

  • 主题：故障检测与容纳 / 控制重分配
  • 相关组件：Isaac Sim / Isaac Lab / PPO / 加权伪逆分配
  • 预计学时：65 分钟
  • 前置章节：第 079 章

学习目标

  • 会用控制效能模型描述故障：ueff = diag(ρ)·u + d，区分卡死、掉力、偏差、漂移四类。
  • 掌握残差法故障检测：模型预测与实测的差、阈值与 CUSUM 累积检测的取舍。
  • 理解控制分配与加权伪逆：冗余执行器系统里如何把任务"让给"健康部件。
  • 会在 Isaac Sim 中实现故障注入包装器（时机、类型、强度、持久性可控）。
  • 会训练带"健康掩码"的容错策略：故障指示进观测、课程从轻到重、与故障无关的失败模式被隔离。
  • 会建立容错验收矩阵：故障类型 × 严重度 ×（成功率、检测延迟、误报率、降级模式可用性）。

背景与动机

第 070 章的鲁棒 RL 让策略"在参数变动下不塌"，但故障是另一类事件：它的本质是系统结构变了，远超"参数偏了一点"的范畴：一个电机彻底卡死、一路传感器开始撒谎、某根线缆接触不良。对这类事件，单纯鲁棒化只能买到有限的宽容度；真正需要的是容错管线：检测故障、定位部件、重新分配控制，把"还能做的任务"在"剩下的健康部件"上完成。飞机、卫星、核电站的控制系统几十年来都是这么设计的，机器人只是把同一套方法论搬到更小的尺度上。

本课程的主线（RL）与容错结合的方式很直接：把故障注入进训练环境，让策略在训练中就见过"某关节掉了"的世界，并给它一个"健康掩码"观测告诉它哪些部件还可用；推理时掩码来自检测模块。这样策略在故障后会切换到"三足模式"这类降级方案，不再硬撑着执行原计划。本章的验收标准也因此特殊：允许性能下降，但要求下降可控、可预测、可挽救。

核心原理

1. 故障模型：效能矩阵与加性干扰

把标称控制输入 u 与"实际作用"的关系写成：

ueff = diag(ρ)·u + d，ρi ∈ [0, 1] ρi=1 健康；ρi=0 完全失效（卡死或断线）；中间值=部分掉力；d 表示卡死位、偏置等加性项

四类常见故障对应关系：卡死（lock）：ρ=0 且 d=常数（关节锁在某位置，等效于持续干扰力矩）；掉力（loss of effectiveness）：ρ 降到 0.3–0.8，控制仍有效但变弱；偏差（bias）：传感器故障，输出加常数；漂移（drift）：输出缓慢变化。执行器故障改变的是 B 矩阵的列（效能），传感器故障改变的是观测方程 y = h(x) + b(t)，两者在残差里都会现形，但定位方法不同。

2. 检测：残差从哪里来、阈值怎么定

残差 = "应该发生"与"实际发生"的差。执行器故障用动力学模型预测的残差：

r(t) = ẋmeas − f(x, u)　（观测到的加速度 − 模型在同样输入下的预测） 传感器故障则用解析冗余：多源观测互检（如 IMU 与编码器估计的速度差）

阈值判据 r(t) 与噪声协方差挂钩：单点阈值 r > 3σr 触发简单但误报/漏报难两全；CUSUM（累积和）对"持续的小偏差"更敏感：

Sk = max( 0, Sk−1 + (|rk| − ν) )；Sk > h 时报警 ν 是噪声容限（漂移量），h 是报警阈值：小故障靠时间累积浮出水面

检测的核心矛盾是延迟与误报的取舍：阈值低则 10 ms 内报出小故障、但噪声大时每分钟误报；阈值高则噪声免疫、但 20% 掉力这种"温和故障"可能要几秒才被发现，期间控制器一直在用错误模型。CUSUM 的门限设计要参考"故障可容忍时间"：先问"这类故障最多能容忍多久不被发现"（例如掉力 20% 容忍 2 s，卡死容忍 0.1 s），再反推参数。

3. 容纳：控制分配与降级策略

检测到 ρ 后，两种容纳路径。路径 A：控制重分配（解析法），对于冗余执行器（例如全向底盘、多旋翼、带冗余执行器的机械臂），任务可以写成"需要某个合力/力矩 w"，由执行器分配解出 u：

u* = argminu ‖u‖²W　s.t.　A·u = w；解 u* = W−1AT(A W−1AT)−1w W 是对角权重矩阵：故障后把对应维权重调到极大（等效于禁用），任务自动分给健康执行器

路径 B：策略降级，对于欠驱动情况（4 足坏 1 腿只剩 3 足），"重新分配"无法完全恢复任务能力，需要改变行为模式（步态改变、承担范围变小）。这属于策略层面的容纳，正是 RL 的用武之地：把健康掩码给策略，训练它几种故障模式下的降级行为。

4. 容错 RL：掩码、课程与观测

训练容错策略的三个关键设计：故障掩码进观测，m ∈ {0,1}n 或软化的 ρ̂ 估计，告诉策略"哪个部件不可信"，否则策略只能从异常状态里猜（学习慢且容易过拟合特定故障）；故障注入课程，从"无故障"开始，先教好任务，再逐步加"单部件轻度故障"、再到"单部件完全故障"、最后"故障时机随机"；一上来就 50% 故障率会让任务基线都学不出来；故障事件标记，在观测里加入"故障发生后的相对时间"（或把故障检测的置信度给进去），让策略区分"刚坏、还在挣扎"与"坏了一段时间、已经适应"两种阶段。

5. 验收矩阵：四类指标

指标定义典型目标
检测延迟故障发生到报警的时间卡死 <100 ms；20% 掉力 <2 s
误报率无故障时每分钟误报次数<0.1 次/分钟
故障后成功率带故障继续任务的成功比按故障类型分列（卡死腿仍能 3 足行走等）
降级行为可用性最坏故障下能否安全停靠/保持100%，这是底线，不是目标

注意最后一行的性质："能安全停靠"是容错的第一性目标，任务性能恢复是第二性。任何设计都要先能安全降级，再谈降级后继续干活。

实现思路与设计

场景：四足机器人行走，注入三类故障：单腿"掉力 50%"、单腿"完全卡死"、IMU 偏置 0.2 rad/s。流程五步：

  1. 注入器：环境包装器管理"故障剧本"，故障类型、生效时刻（回合内 20–80% 处随机）、持续到回合结束；注入方式：缩放该关节力矩（掉力）／把目标位置写死为当前值（卡死）／在观测速度上叠加偏置（传感器）。
  2. 检测器：对每条腿用关节位置/速度与模型预测做残差，CUSUM 检测；检测输出两件东西，布尔告警与连续的健康估计 ρ̂∈[0,1]（用残差幅度映射，做滑动平均），后者更平滑、更适合进观测。
  3. 掩码观测：obs 中加入 4 维 ρ̂（每条腿一个）与 1 维"距最近故障的时间/检测置信度"，共 5 维；故障前这些维恒为 1 / 0。
  4. 训练课程：阶段 1 无故障（照常学步态，10k 迭代）→ 阶段 2 单腿掉力 30–70% 随机（10k）→ 阶段 3 单腿卡死概率 0.3（10k）→ 阶段 4 全谱故障 + 随机时机（10k）。每阶段验收后再进下一阶段。
  5. 评测：按验收矩阵跑 4 类故障 × 3 档严重度 × 20 回合；对照组为无故障训练的普通策略与第 070 章鲁棒策略；记录故障后 3 s 内的姿态恢复时间。
设计思维：为什么用"软化的 ρ̂"？

布尔掩码有两个问题：检测抖动（1→0→1 跳变）会让策略观测突变、行为跳变；检测延迟期间策略拿不到任何提示。连续 ρ̂ 携带"故障有多确凿"的信息，策略可以在"疑似故障"时提前准备（略微改变步态），在"确诊"后完全切换；训练时对 ρ̂ 加噪声（模拟检测误差）还能让策略对检测器的不完美脱敏，可观测的信息当礼物，不可靠的布尔当炸弹。

关键代码与解读

片段 1：故障注入包装器（可控剧本）

import numpy as np

class FaultInjector:
    """故障剧本管理器：类型、时机、强度、持续全部可控，支持并行环境张量化。"""
    def __init__(self, n_envs, n_joints=12, rng=None):
        self.n, self.m = n_envs, n_joints
        self.rng = rng or np.random.default_rng(0)
        self.kind = np.array(["none"] * n_envs, dtype=object)   # 每环境当前故障类型
        self.rho = np.ones((n_envs, n_joints), dtype=np.float32)  # 效能系数矩阵
        self.bias = np.zeros((n_envs, n_joints), dtype=np.float32) # 传感器偏置
        self.onset_step = np.zeros(n_envs, dtype=np.int64)         # 故障发生的仿真步
        self.fault_joint = np.zeros(n_envs, dtype=np.int64)

    def reset(self, t_episode_len, fault_prob=0.3):
        """每个回合开始时采样：是否故障、何时、哪里、多严重。"""
        will_fault = self.rng.random(self.n) < fault_prob
        self.onset_step = (self.rng.random(self.n) * 0.6 * t_episode_len).astype(np.int64)
        self.kind = np.array(["none"] * self.n, dtype=object)
        self.rho[:] = 1.0; self.bias[:] = 0.0
        self.fault_joint = self.rng.integers(0, self.m, self.n)
        for i in np.where(will_fault)[0]:
            # 三类故障轮换采样：掉力 / 卡死 / 传感器偏置
            self.kind[i] = ["loss", "lock", "bias"][self.rng.integers(0, 3)]
            if self.kind[i] == "loss":
                self.rho[i, self.fault_joint[i]] = self.rng.uniform(0.3, 0.8)

    def apply(self, step, action, sensor_vel):
        """每步调用：返回被故障修改后的动作与观测。"""
        active = (~np.isin(self.kind, ["none"])) & (step >= self.onset_step)
        for i in np.where(active)[0]:
            j = self.fault_joint[i]
            if self.kind[i] == "loss":
                action[i, j] *= self.rho[i, j]        # 掉力：执行器力矩按比例衰减
            elif self.kind[i] == "lock":
                action[i, j] = 0.0                     # 卡死：该关节不再接受指令
            elif self.kind[i] == "bias":
                if self.bias[i].sum() == 0.0:
                    self.bias[i, j] = 0.2              # 传感器偏置一次到位（可改漂移）
        # 传感器故障作用在观测上，不在执行器上；两条路径分开处理
        return action, sensor_vel + self.bias[:, :sensor_vel.shape[1]]

    def truth_rho(self):
        """训练时可用的"真值健康度"（模拟理想检测器）；部署时换成本章检测器的 ρ̂。"""
        return self.rho.copy()

解读：剧本管理有三个必须显式化的量：时机（onset_step 在回合 0–60% 处采样，保证故障后至少还有 40% 回合长度来观察恢复行为）、位置（随机关节，避免策略只学会应付"第 3 关节坏"）、类型轮换（三类故障的注入路径不同：动作缩放、动作归零、观测叠加，一定分开写，混在一起会调试不清）。truth_rho 暴露真值是有意的：训练早期用理想检测器（真值掩码）让策略先学会"拿着准确故障信息该怎么动"；后期把掩码换成检测器输出并加噪声，让策略适应检测误差，这是"先心理学、后生理学"的两阶段设计。并行环境下的 Python 循环（np.where 内的 for）在故障稀疏时开销可接受；若故障率设得很高，应把三类故障的注入全部改成张量运算。

片段 2：CUSUM 故障检测器

import numpy as np

class CUSUMDetector:
    """残差累积检测：对持续小故障敏感，同时用阈值ν抑制噪声。"""
    def __init__(self, n_envs, n_joints, nu=0.5, h=4.0, rho_lr=0.05):
        self.n, self.m = n_envs, n_joints
        self.S = np.zeros((n_envs, n_joints))       # 累积和
        self.nu, self.h = nu, h                     # 噪声容限与报警阈值
        self.rho_hat = np.ones((n_envs, n_joints))  # 连续健康估计（进观测用）
        self.rho_lr = rho_lr                        # 健康估计的更新速率

    def update(self, residual, dt):
        """residual：|观测加速度 − 模型预测加速度|，逐环境逐关节（已归一化）。"""
        # CUSUM 递推：小残差被 ν 吃掉，持续超过 ν 的部分才累积
        self.S = np.maximum(0.0, self.S + (residual - self.nu) * dt)
        alarm = self.S > self.h                     # 布尔报警（供安全逻辑使用）
        # 连续健康度：报警越深，ρ̂ 越低；无报警时缓慢回归 1（带遗忘）
        target = 1.0 / (1.0 + self.S)
        self.rho_hat += self.rho_lr * (target - self.rho_hat)
        return alarm, self.rho_hat.copy()

解读：residual 的来源应与动力学模型对齐：四足上用"关节实际加速度 − 由指令力矩与简化模型预测的加速度"的差（归一化后），传感器故障则走另一路解析冗余。参数标定有物理锚点：nu 应取"无故障残差的 95 分位"（用一段健康数据统计），保证噪声基本不积累；h 决定"多少积累算确凿"，h=4 意味着持续 8 倍于噪声容限的残差约 1.1 s 后报警（按 dt 归一：4 ÷ (8×0.5−0.5)）。连续健康度 ρ̂ = 1/(1+S) 是一个方便的有界映射：无故障 S≈0 时 ρ̂≈1，S 升到 4（报警线）时 ρ̂≈0.2，正好是"严重不可信"的直观刻度；加一阶滤波（rho_lr）是为了让观测平滑。检测器只做检测不做隔离，隔离由"哪个关节的 S 最大"自然给出（block 3 会用上）。这段代码在 4096 环境下每步只需几次张量运算，开销可忽略。

片段 3：控制重分配（加权伪逆）与掩码策略入口

import numpy as np

def weighted_pseudoinverse_alloc(A, w_desired, health, eps=1e-6):
    """控制分配：把期望力矩 w_desired 分给执行器；health 低者权重被降。
    A: [k, m] 执行器对任务的贡献矩阵；u* = W⁻¹Aᵀ(AW⁻¹Aᵀ+εI)⁻¹ w。"""
    W_inv = np.diag(health + eps)          # 健康度直接当权重：故障执行器自动被边缘化
    AWA = A @ W_inv @ A.T + eps * np.eye(A.shape[0])
    u = W_inv @ A.T @ np.linalg.solve(AWA, w_desired)
    return u

class FaultAwarePolicyWrapper:
    """策略入口：观测拼接健康估计；故障严重时退回安全模式。"""
    def __init__(self, policy, safe_mode, rho_threshold=0.35):
        self.policy, self.safe_mode = policy, safe_mode
        self.thr = rho_threshold

    def act(self, obs, rho_hat, desired_wrench, alloc_matrix):
        obs_aug = np.concatenate([obs, rho_hat])          # 故障信息进入策略观测
        if np.min(rho_hat) < self.thr:
            # 健康度过低：任务性能已不可保，切换"安全保持"（蹲伏/停靠）
            return self.safe_mode()
        u_task = self.policy.act(obs_aug)
        return weighted_pseudoinverse_alloc(alloc_matrix, desired_wrench, rho_hat) \
               if alloc_matrix is not None else u_task

解读：加权伪逆的三行是控制分配的标准解：W_inv 用健康度做权重，故障执行器（health→0）在最小范数解里自动被"躲开"，任务由剩余执行器承担；eps 保证矩阵可逆（全部健康时也数值稳定）。它适用于执行器冗余的系统；四足这类欠驱动平台走 FaultAwarePolicyWrapper 的策略降级路线，注意 rho_threshold 的语义是"任务性能不可保的边界"，越过它时切安全模式（蹲伏、慢停），这不是失败，这是设计好的降级态。策略观测里拼接 rho_hat 是训练与部署的共同接口：训练时喂检测器输出（含噪声），部署时喂真检测器输出，两者口径一致。这个 wrapper 演示的是"检测→反应"的最小闭环完整链路：注入器制造故障、检测器估计健康、分配器/策略消化健康信息。

常见坑

  • 训练环境无故障，部署盼奇迹：普通策略遇到卡死关节会把全部控制量堆到坏关节上（教学里所谓"对抗式努力"），加速磨损甚至损伤其他部件。症状是故障后行为夸张、失败迅速。修复：故障注入进训练 + 健康掩码进观测，这是根本手段。
  • 检测阈值照搬论文：ν 与 h 与噪声水平强相关，实验室静音环境的值到真机上必出问题。症状是误报泛滥或漏报。修复：用健康数据统计残差分位（ν=95 分位起步）；上线前记录"每分钟误报次数"并接受再调。
  • 故障指示不做延迟训练：训练时用理想检测器（零延迟），部署时检测器有 200 ms 延迟，策略在"信息迟到"的窗口里行为错乱。修复：训练加随机检测延迟（0–300 ms）与 ρ̂ 噪声；这属第 066 章随机化思想在"检测器维度"的移植。
  • 把安全模式和任务策略混在一个动作输出：故障后安全模式与策略输出插值，结果"既没停下也没走好"。症状是故障后抖动爬行。修复：硬切换 + 平滑过渡窗口（如 0.2 s 的斜率限制），并明确各自的验收指标。
  • 只在故障类型上训练、不在故障时机上训练：只训练"回合开始就坏"的策略，遇到"行走中途突然坏"仍然崩。症状是中途故障的恢复率远低于开局故障。修复：故障时机也要随机化（0–60% 回合处），验收时分开统计两种时机。

练习与思考

  1. 固定故障为"单腿掉力 50%"，对比无故障训练策略与容错训练策略的故障后成功率与恢复时间。★
    提示
    重点看故障后前 2 s 的行为差异：普通策略可能直接翻倒，容错策略有一个"步态重组"的过渡段。
  2. 把 CUSUM 的 ν 从 95 分位调到 50 分位，观察误报率与检测延迟的此消彼长，选出你系统上的折中点。★★
    提示
    ν 太小→噪声积累→频繁误报；太大→检测迟钝。画"ν vs（延迟, 误报率）"双轴图。
  3. 把健康掩码从观测里去掉（策略得不到故障提示），保持其余设置不变，比较两种训练的成功率与行为方式。★★
    提示
    无掩码时策略需要从状态里"猜"故障，学习慢、且对未见故障泛化差；对比故障后 3 s 的关节力矩分布。
  4. 设计并实现"故障时机随机化"实验：开局故障 vs 中途故障，比较策略在不同时机的恢复能力，解释为什么两者都需要出现在训练集里。★★★
    提示
    中途故障时策略带着"全腿运动记忆"进入残障相位，需要能快速改写周期性步态；分开统计才看得清短板。
  5. 给系统加一条"双故障"压力测试（两腿同时掉力 30%），报告成功率与降级策略切换率，说明容错设计的边界在哪。★★
    提示
    预期双故障下任务性能大幅下降甚至不可行；重点验收"安全保持/停靠"的完成率，继续行走只作参考。

小结

  • 故障是"结构变化"：ueff = diag(ρ)u + d 模型统一了卡死、掉力、偏差、漂移四类。
  • 三段式管线：检测（残差 / CUSUM，延迟与误报取舍）、隔离（哪一路的残差最大）、容纳（加权伪逆重分配 或 策略降级）。
  • 容错 RL 三件套：故障注入训练（类型、位置、时机、强度随机）、连续健康估计 ρ̂ 进观测、课程从无故障到全谱。
  • 验收用矩阵：检测延迟、误报率、故障后成功率、降级可用性；"能安全停靠"是底线目标，任务恢复是上限目标。
  • 工程细节：检测阈值用健康数据标定、训练包含检测延迟、安全模式与任务策略硬切换。
