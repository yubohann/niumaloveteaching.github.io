第三篇 · 环境与任务实践

第 054 章：多智能体机器人协作

机器人协作把作业流程写进多智能体决策：阶段状态机定义进度，同步点定义交接条件，等待图定义死锁；本章说明如何用柔顺控制接口与协调奖励让一组异构机器人完成装配作业。

  • 主题：作业流程协同 / 同步与交接
  • 关键公式：sync_err = ‖ pi − pides ‖ + ‖ pj − pjdes ‖ ， 交接就绪条件 sync_err ≤ ε
  • 预计学时：65 分钟
  • 前置章节：第 053 章 多智能体自动驾驶协同

学习目标

读完本章，应当能够把装配类作业拆成阶段与同步点，并为协调行为设计可诊断的奖励。

  • 掌握作业流程的状态机建模：阶段、前置条件、同步点与交接，理解阶段推进条件与动作空间的关系。
  • 掌握同步误差与交接就绪条件的定义，理解交接为什么需要位置与力同时满足约束。
  • 理解共享资源的互斥与死锁：等待图、环检测与消解策略（优先级、超时回退）。
  • 掌握柔顺控制接口：阻抗或导纳控制在交接与插入阶段的作用，以及学习策略与柔顺层的分工。
  • 会为异构机器人设计能力向量与角色分配，并识别能力未入观测导致的错配行为。

背景与动机

机器人协作的难点不在单个动作的控制精度，而在作业流程的时序协调与资源共享。

装配作业由阶段序列组成：取件、定位、交接、插入、锁紧。每个阶段有进入条件与完成条件，阶段之间还可能存在并发：一台机器人准备工具的同时另一台机器人搬运工件。多机器人协作的效率取决于流程组织：等待浪费、交接失败与资源冲突都会直接降低产出。与搬运任务不同，工件交接意味着控制权转移，两侧机器人的位置与力必须同时进入就绪窗口，任一侧偏差过大都会造成冲击或掉落。与编队任务不同，机器人之间的关系由作业流程定义，协调的对象是阶段与资源；几何队形与相对位姿退居次要位置。

强化学习的接入方式通常分两层：高层选择阶段动作或角色，低层由柔顺控制器执行接触任务。分层结构的收益是信用分配清晰：高层决策对应流程进度，低层控制对应物理执行。本章同时讨论端到端方案与分层方案的取舍，重点在同步点与死锁这两个流程层的技术问题，它们在第 088 章的联盟形成与第 090 章的投票机制中会以更抽象的形式再次出现。

核心原理

本章原理分四层：阶段状态机、同步与交接、共享资源的死锁、以及柔顺控制接口。

1. 阶段状态机与进度表示

作业被离散化为阶段，阶段推进由前置条件与完成条件共同决定。

advance(φ → φ′) 成立 ⟺ pre(φ′) ⊆ Done 且 complete(φ) = true φ 为当前阶段；pre(φ′) 为进入下一阶段所需的前置阶段集合；Done 为已完成阶段集合；complete(φ) 为该阶段的完成判据（例如插入深度达到阈值）

阶段状态机把长目标任务分解为短程子目标，每个阶段的完成条件由几何或物理量定义，避免了密集奖励的全部工程量。状态机的实现要点是幂等与显式：完成条件在每步被检查，满足即推进，推进动作不依赖上一步的选择；每个阶段给出独立的可观测标记，策略据此判断进度。若把完成条件设计得过严（例如要求误差小于噪声量级），阶段会在边界反复震荡；过松则阶段提前完成、后续动作基于错误的初始状态执行。工程上把阈值设为估计噪声的标准差数倍，并在完成条件中加入持续时间要求（稳定若干步才算完成）。

2. 同步点与交接

同步点要求多个机器人在同一时刻同时满足各自的就绪条件。

sync_err = ‖ pi − pides ‖ + ‖ pj − pjdes ‖ ≤ εp 且 ‖ fi − fides ‖ + ‖ fj − fjdes ‖ ≤ εf p 为末端位置；f 为接触力；下标 i、j 为交接双方；εp、εf 为位置与力的就绪阈值

交接就绪是位置与力的联合条件：位置对齐保证工件不会错位，力就绪保证抓持已经建立或已经释放。两个条件缺一不可，只检查位置的实现在释放瞬间会出现掉件。从策略视角看，交接是一个隐式的同步博弈：双方都需要到达就绪点并保持，先到者需要等待，等待会引入空闲惩罚。若双方都学习“等对方先就绪”，阶段推动的时机被推迟；若双方都抢时间，就绪窗口错开导致失败。协调的常见解法是主从约定：一方负责对齐并给出“可以交接”的信号，另一方响应；信号进入观测后博弈退化为序贯执行。

等待的代价需要在奖励中显式表达，否则策略会倾向无限等待；同时等待惩罚不能过大，否则策略在未就绪时强行交接。回调结构（先到达者保持并小幅调整，未就绪者加速接近）通常是自动涌现的最优行为，诊断时可观察交接前的力与位置误差曲线是否收敛到阈值内。

等待成本与就绪窗口的数量级可以联算：等待惩罚 0.05 每步、阶段完成奖励 1.0 时，等待 20 步的累计成本等于一次阶段完成，超过 20 步的徘徊在回报上已不如放弃本轮交接重新接近；就绪窗口方面，双方以约 0.05 米每秒的残余速度收敛时，位置阈值 0.02 米对应的保持窗口约 0.4 秒，折算到 10 赫兹的决策频率只有约 4 个决策步。窗口宽度决定保持动作的可学习性：窗口小于一个决策步时，就绪判定几乎无法被稳定命中，需要降低接近速度或放宽阈值。两个数字联立即可判断当前参数下交接是可学习的任务，还是一道靠运气的时序题。

3. 共享资源与死锁

工具、工位与通道属于共享资源，互斥使用约束下的等待环即死锁。

wait-for 图：顶点为机器人，有向边 i → j 表示 i 等待 j 释放资源；死锁 ⟺ 图中存在有向环 典型环为两台机器人各持有一件对方需要的资源并同时等待；单机持有的不可抢占资源的等待环无法自行解开

死锁处理有预防与消解两条路线。预防给资源申请设定全序：所有机器人按同一顺序申请资源，环在结构上不可能形成；代价是灵活性下降，且作业流程必须服从预定义顺序。消解允许死锁出现后检测并打破：检测等待图的环，按优先级撤销低优先级机器人的占用并让其回退重试；代价是实现复杂且撤销行为会浪费已完成的动作。学习方法通过奖励设计抑制死锁：等待时间超过阈值时施加递增惩罚，策略会自行学会回退或改变申请顺序。评估指标中应统计“等待环出现次数”与“回退次数”，两者同时下降说明协调改善。

4. 柔顺控制接口与接触操作

插入与交接阶段的接触操作对位置误差敏感，宜采用柔顺控制；刚性位置控制在接触瞬间容易卡死或损坏工件。

阻抗控制：M ( ẍ − ẍd ) + D ( ẋ − ẋd ) + K ( x − xd ) = − fext M、D、K 为虚拟质量、阻尼与刚度矩阵；xd 为期望轨迹；fext 为接触外力；调整 K 使系统在接触时表现为柔性

阻抗控制让末端执行器在受到外力时产生可控的位移（表现为弹簧阻尼），插入装配时工件能顺从孔位偏差自行微调，避免卡死或损坏。参数选择决定行为：刚度 K 低时柔顺但定位慢，K 高时刚性但容易抵抗偏差。学习策略的接口有两种形式：输出末端的期望轨迹或力，由柔顺层跟踪；或输出刚度参数，由策略调制柔顺程度。后者把“用多大力去接触”变成学习问题，在装配这类对力度敏感的任务中更自然，动作维度也很低（每个方向一个刚度参数）。

实现思路与设计

实现采用两层架构：高层策略选择阶段动作与角色，低层柔顺控制器执行接触与运动，环境为纯 NumPy 的简化接触模型。

1. 数据流

高层策略以 10 Hz 决策，输出为阶段推进请求、目标工位选择或刚度参数；低层控制器以 200 Hz 执行位置与力控制。环境维护阶段状态机、工件状态、资源占用表与等待图。每个高层周期结束时计算奖励并检查完成条件，交接与插入阶段的接触力按软接触模型结算。

3. 网络结构与训练要点

高层策略的观测包含自身阶段、队友阶段、工件位姿、资源占用、等待时长与能力向量；输出为离散的阶段动作加连续的刚度参数（混合动作空间，实践中可拆成两个头）。训练使用集中式评论家读取完整流程状态，执行时各机器人只读本机与局部感知。阶段奖励为事件型，训练使用稀疏奖励加过程势能（阶段距离），与第 045 章的塑形技术同源。异构机器人按能力向量条件化，避免共享参数被单侧能力主导。

4. 与第 046 章、第 042 章的差异点

第 046 章处理载荷的合力分配，协作的媒介是刚体载荷，人数与抓取点固定；本章处理作业流程，协作的媒介是阶段与资源，任务结构本身是动态的。第 042 章的约束是相对位姿等式，可以是静态队形；本章的进度约束是事件驱动的状态机，最优行为随阶段变化。前者的奖励以几何误差为主，后者的奖励以事件完成与等待成本为主，训练信号更稀疏，因此状态机就绪条件的设计质量直接决定可学性。

关键代码与解读

三段代码分别实现阶段状态机、交接就绪检查与死锁检测，以及带等待成本的事件奖励。

片段 1：阶段状态机

import numpy as np

class StageMachine:
    """作业阶段机：维护完成集合与各阶段的前置条件。"""
    def __init__(self, stages):
        # stages: 每个元素为 dict(name, pre, check)，check 返回完成判据布尔值
        self.stages = stages
        self.done = set()
        self.stable_count = {}                # 连续满足完成条件的步数

    def advance(self, obs):
        """检查并推进阶段；返回本步新完成的阶段列表。"""
        finished = []
        for st in self.stages:
            name = st["name"]
            if name in self.done:
                continue
            if not set(st["pre"]).issubset(self.done):
                continue                      # 前置阶段未完成，暂不检查
            ok = st["check"](obs)
            # 去抖：连续满足若干步才算完成，避免边界震荡导致反复推进
            n = self.stable_count.get(name, 0) + (1 if ok else 0)
            self.stable_count[name] = n if ok else 0
            if n >= st.get("hold", 2):
                self.done.add(name)
                finished.append(name)
        return finished

解读：阶段检查只在前置条件满足后进行，避免无效计算与错误推进。去抖计数器把“瞬时满足”与“稳定满足”区分开，这是接触任务中状态机稳定性的关键；hold 参数按感知噪声与任务节奏设定，取 2 至 5 步。返回新完成列表供奖励函数使用，事件型奖励与状态机解耦，便于替换奖励结构。状态机不保存机器人的具体位置，它只消费观测，保持与具体场景的解耦。

片段 2：交接就绪与等待图

def handover_ready(pos_i, des_i, f_i, f_des_i, pos_j, des_j, f_j, f_des_j,
                  eps_p=0.02, eps_f=2.0):
    """交接就绪：双方位置与力同时进入阈值窗口。"""
    e_p = np.linalg.norm(pos_i - des_i) + np.linalg.norm(pos_j - des_j)
    e_f = abs(f_i - f_des_i) + abs(f_j - f_des_j)
    return bool(e_p <= eps_p and e_f <= eps_f), e_p, e_f

def detect_deadlock(holding, waiting, priority):
    """等待图环检测：DFS 找环，返回可回退的低优先级机器人。"""
    graph = {i: [j for j in waiting.get(i, []) if j in holding]
             for i in waiting}
    visited, stack = set(), []

    def dfs(node):
        stack.append(node)
        for nxt in graph.get(node, []):
            if nxt in stack:                  # 回到栈中节点即发现环
                cycle = stack[stack.index(nxt):]
                return min(cycle, key=lambda k: priority[k])  # 牺牲低优先级者
            if nxt not in visited:
                visited.add(nxt)
                r = dfs(nxt)
                if r is not None:
                    return r
        stack.pop()
        return None

    for node in graph:
        if node not in visited:
            r = dfs(node)
            if r is not None:
                return r
    return None

解读：就绪检查把位置误差与力误差分开计算并分别对照阈值，返回两个分量用于诊断哪一侧未就绪。等待图只保留“等待对方持有的资源”这类边，其他等待（例如等待工件到达）不构成死锁条件，剪枝减少了误报。环检测用深度优先搜索并在栈上判定回环，返回环中优先级最低的机器人作为回退者，回退策略因此有确定的仲裁依据。递归实现只适合小规模，机器人数量增加时应改为显式栈的迭代版本。

片段 3：事件奖励与等待成本

def collaboration_reward(finished, sync_ok, wait_steps, stage_potential,
                       w_stage=1.0, w_sync=1.0, w_wait=0.05, w_prog=0.2):
    """奖励：阶段完成 + 同步质量 + 等待成本 + 过程势能。"""
    r = w_stage * len(finished)                 # 事件型：按完成阶段数计分
    if finished and not sync_ok:
        r -= w_sync                             # 交接阶段完成但同步质量不合格时扣分
    r -= w_wait * wait_steps                    # 空闲成本：抑制无限等待
    # 过程势能：与最近阶段的完成距离成反比，提供稠密进展信号
    r += w_prog * (stage_potential - 0.0)
    info = {"stages_done": len(finished), "sync_ok": sync_ok,
            "wait": wait_steps}
    return r, info

解读：阶段完成奖励按事件计数，与状态机的推进语义一致；按时间累积会与事件语义脱节。同步失败惩罚只在完成阶段时检查，避免对过程中间的瞬时偏差过度反应。等待成本按步线性累加，权重较小，作用是打破“无限等待”的平衡，正常排队不受惩罚。过程势能项由外部按“到最近阶段目标的距离”计算，属于势能塑形，保持最优策略不变；具体势能函数随任务定义，接口保持通用。三项权重的关系是：事件奖励主导方向，等待成本调节节奏，过程势能提供早期信号。

常见坑

  • 完成条件无去抖：接触噪声使完成判据在阈值附近抖动，阶段在推进一步后立即被判定未完成。症状是阶段状态反复回跳、奖励曲线呈周期性尖刺。修复：连续满足若干步才推进，抖动窗口按噪声水平设定。
  • 共享资源申请无序：两台机器人按各自的最优顺序申请工具，形成等待环。症状是双方长时间静止且等待时间超过任务节拍。修复：资源全序申请或引入优先级仲裁与超时回退。
  • 交接只检查位置：力未就绪就释放，工件掉落或滑移。症状是交接阶段失败率高于插入阶段。修复：位置与力双条件判定，就绪保持一小段时间后执行转移。
  • 等待惩罚过大：策略为避免等待而提前交接或抢资源，失败率上升。症状是等待时长下降而同步失败次数上升。修复：按事件奖励的二十分之一量级设定等待成本，两项指标联合观察。
  • 能力向量未入观测：异构机器人共享参数但不了解彼此能力，出现重复认领或超过能力的任务选择。修复：能力向量拼入观测并按角色分组共享参数。

练习与思考

  1. 设计题：给出一个包含取件、交接、插入、锁紧四阶段的作业图，写出各阶段的前置条件与完成判据，并说明哪些阶段构成同步点。★
    提示
    交接与插入通常构成同步点，前者需要双方就绪，后者需要工件与孔位对齐。完成判据优先选择可测的几何与力量，例如插入深度与接触力阈值组合。
  2. 推导题：分析全序申请规则为什么能消除死锁，并说明代价（灵活性与顺序约束）体现在哪些指标上。★★
    提示
    全序下等待图不可能成环，因为等待边的方向与资源序一致，形成严格偏序。代价是申请顺序与自然作业顺序可能冲突，导致等待增多与节拍延长，可用等待总时长衡量。
  3. 改参数并预测：把就绪阈值 εp 从 0.02 米放宽到 0.1 米，预测交接成功率、交接耗时与掉件风险三项指标的变化方向。★★
    提示
    阈值放宽后交接更快、成功率初期上升，但位置偏差增大使掉件与冲击风险上升。风险在评估中可用交接后的工件位置漂移来量化。
  4. 设计题：为交接设计协调信号机制，说明信号的内容、频率与失效处理，并分析它如何把同步博弈转为序贯执行。★★★
    提示
    信号可包含“已就绪”与“可以接收”两种状态，占用一个布尔通道。失效处理包括超时重发与回退到无信号协议。信号使双方无需同时猜测对方状态，博弈退化为交替行动。
  5. 实验设计：对比“事件奖励单用”与“事件加过程势能”两种设置，设计指标区分学习速度与最终质量，说明势能项的作用边界。★★★
    提示
    指标包括达到给定阶段完成率的样本步数与最终节拍时间。势能项加速早期学习但可能引入偏差（势能设计不当会改变偏好），需要与无势能基线对照最终质量。

小结

  • 作业协作以阶段状态机组织：前置条件与完成判据分离，完成判据需要去抖，事件型奖励与状态机解耦。
  • 交接就绪是位置与力的联合条件，同步博弈可通过主从信号转为序贯执行；等待成本在奖励中需要显式表达。
  • 共享资源的等待环是死锁的判据，预防用资源全序，消解用优先级回退；等待与回退次数是协调质量的直接指标。
  • 接触阶段用阻抗控制保证柔顺，策略可以输出刚度参数调节接触行为，形成低维且物理可解释的动作空间。
