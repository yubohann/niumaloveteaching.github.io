第一篇 · CTDE 基础与核心算法

第 025 章：探索策略在CTDE中的设计

本章讲多智能体探索（Exploration）的设计：独立探索在同步协作任务中的抵消效应、共享随机数的联合探索、计数式内在奖励与熵正则、温度调度，以及探索行为与评估行为的分离。

  • 主题：行为策略设计 / 探索与利用
  • 关键公式：独立联合覆盖 1 − (1 − ε)N；计数奖励 η / √n(s)
  • 预计学时：50 分钟
  • 前置章节：第 024 章 目标网络在CTDE中的使用

学习目标

  • 理解探索与利用权衡在多智能体环境中的形态变化：联合动作空间巨大使随机命中协作序列的概率指数下降。
  • 掌握独立探索与相关探索的区别，能推导独立 ε-greedy 下联合动作覆盖概率的表达式。
  • 掌握共享随机数联合探索、计数式内在奖励、参数空间噪声三类协调探索手段的适用条件。
  • 理解温度系数与熵正则系数的调节逻辑，能根据回报曲线与熵曲线判断探索过强或过弱。
  • 能实现探索配置对象，将采集期探索与评估期确定性行为严格分离。

背景与动机

探索机制决定训练数据从哪里来，是强化学习中最先影响样本分布的组件。多智能体环境把探索的难度推高一个量级：N 个智能体的联合动作空间规模是单体动作空间的 N 次幂，协作序列（例如同时向两侧包抄）只占其中极小比例，纯随机探索命中这些组合的概率随 N 指数下降。

更棘手的是探索的结构问题。每个智能体独立加噪声时，同一时刻不同智能体在探索彼此不相关的动作，联合状态变化无法归因到任何单个智能体的选择，训练数据里充满了"一个智能体探索、队友正常行动"的混合行为，协作模式的统计信号被稀释。第 024 章稳定的是目标值，本章处理的是行为策略：让探索在智能体之间产生相关性，使联合新颖状态的出现概率从乘积结构恢复到接近单体的水平，同时保持离策略学习的接口不变。

核心原理

1. 从单体探索到联合探索

单智能体的标准手段在两个层面发挥作用：动作层面用 ε-greedy 以概率 ε 替换贪婪动作为随机动作，或以玻尔兹曼（Boltzmann）分布按价值比例采样；参数层面在策略参数或输出均值上注入噪声，使相邻策略之间保持平滑的可达性。多智能体环境的核心变化在于：探索对象从单个动作升级为联合动作，而联合动作的数量随智能体数量指数增长。

设每个智能体以概率 ε 独立执行随机动作，在给定状态下，至少有一个智能体处于探索状态的概率为：

P(联合动作中出现探索) = 1 − (1 − ε)N N 个智能体的探索事件相互独立；N = 6、ε = 0.1 时该概率约为 0.47

这一概率看似在上升，真正的问题在于探索事件的组成结构：多数时刻只有部分智能体在探索，联合动作分布以"少量智能体随机"的混合状态为主，需要全体协调才能触发的协同行为始终得不到连续覆盖。依赖单个智能体探索去发现协作序列，等价于在大规模联合动作空间中沿坐标轴逐个搜索，命中率不足。

2. 相关探索：共享随机数与联合调度

相关探索（Coordinated Exploration）让各智能体的探索决策共享随机因素，使"全体探索"与"全体利用"成为高频事件。最简单的实现是共享随机数：一次采样决定所有智能体同时探索或同时贪婪。

联合 ε-greedy：以概率 ε 全体采样随机联合动作，以概率 1 − ε 全体执行贪婪动作 探索与利用在时间上成块出现，协作序列在探索块内有更高的同时出现概率

共享随机数把探索行为的时间相关性显式化：探索块内各智能体继续按自身策略采样，智能体之间的动作组合不再被独立噪声打散。代价是探索的总时长集中化，若 ε 偏大，集体随机行动的块会显著降低有效数据占比。离散动作空间中还可以进一步用联合温度控制随机程度，连续动作空间中则用参数噪声或目标策略平滑（第 029 章展开）。

3. 计数式内在奖励与新密度量

另一条路线把探索目标从"动作选择"转移到"状态访问"：对访问次数少的状态给予内在奖励，引导策略主动前往未探索区域。计数式奖励的常用形式：

rint(s) = η / √( n(s) ) n(s) 为状态 s 的累计访问次数，η 控制内在奖励量级；访问次数越多，奖励衰减越平缓

多智能体环境下计数对象的选择有讲究：按联合状态计数时，状态数量随智能体维度指数增长，计数表几乎命中不到重复项，奖励退化为常数；按各智能体局部观测分别计数、取和或取最大值作为团队内在奖励，可以在"个体探索"与"联合新颖性"之间取得折中。计数奖励与势能式塑形可以组合使用：计数项鼓励探索广度，势能项引导探索方向，两者的量级需要分别标定，避免内在奖励压过任务奖励。局部观测量连续时，先用离散化或映射表把观测映射到固定数量的桶，桶数按内存预算设置，典型为 104 到 106 量级。

4. 熵正则与温度调度

策略梯度类算法把探索内化到目标函数中，在回报项上加入策略熵的正则：

J(θ) = E[ 回报 ] + λent · H(πθ(·|o)) H 为策略动作分布的熵，λent 为熵系数；熵越大动作分布越均匀

熵系数与温度扮演同一角色：控制动作分布的"平坦程度"。调度逻辑分两阶段：训练早期保持较大的熵以维持覆盖面，中后期逐步降低让策略收敛到确定的协调模式。判断探索是否合适可以读两条曲线：回报曲线长期平坦且熵快速下降意味着探索不足，策略过早确定；回报正常上升但熵高位徘徊意味着探索过强，策略持续被随机性稀释。玻尔兹曼温度的作用位置在动作选择端，不进入损失函数，适合与离策略算法配合；熵正则进入损失函数，适合与策略梯度类算法配合。

还有一条工程纪律贯穿所有方法：采集期使用探索策略，评估期使用确定性策略（贪婪或分布均值），两条通路的动作来源必须在代码层面严格区分，否则评估曲线混入探索噪声，无法反映策略的真实水平。

6. 映射冲突的定量与方向

离散化粒度与桶数的组合决定碰撞率。取每维 16 档、观测 4 维，格子数为 164 = 65536；桶数 2×105 时装载因子约 0.33，随机映射下约 28% 的格子与别的格子共享桶（1 − e−0.33 近似，数值经程序核对）。观测升到 6 维时格子数涨到 166 ≈ 1.68×107，桶均承载约 84 个格子。冲突的方向必须记清：桶计数高于任一单格的真实访问次数，1/√n 奖励被系统性低估，探索激励偏弱；补偿手段是提高桶数、收缩离散化粒度，或按预估冲突率上调 η。冲突同时抹平相邻观测之间的新颖度差异，稀有观测的探索价值受影响最大。

实现思路与设计

探索模块作为行为策略层独立于算法主体：算法只暴露动作价值的查询接口，探索模块决定最终执行的动作。配置对象包含探索类型、参数初值与调度方式，训练循环在采集与评估两条通路分别调用。

关键代码与解读

片段 1：共享随机数的联合探索

import numpy as np

class JointEpsilonGreedy:
    """共享随机数的联合探索：一次采样决定全体探索或全体利用。"""
    def __init__(self, eps_start=1.0, eps_end=0.05, anneal_steps=1_000_000):
        self.eps_start, self.eps_end = eps_start, eps_end
        self.anneal_steps = anneal_steps
        self.rng = np.random.RandomState()

    def epsilon(self, step):
        # 线性退火：按环境步推进，课程切换点应调用 reset 重新调度
        frac = min(1.0, step / self.anneal_steps)
        return self.eps_start + frac * (self.eps_end - self.eps_start)

    def act(self, greedy_actions, n_actions, step, evaluate=False):
        # 评估通路直接返回贪婪动作：探索噪声不得进入评测
        if evaluate:
            return greedy_actions
        # 关键设计：全体共享同一次伯努利采样，形成成块的探索与利用
        explore = self.rng.rand() < self.epsilon(step)
        if explore:
            return [self.rng.randint(n) for n in n_actions]
        return greedy_actions

解读：act 方法里的一次伯努利采样是整个类的核心：它把 N 个独立伯努利事件替换为单个伯努利事件，联合行为因此具有时间块结构。评估分支提前返回，保证评估曲线只反映确定性策略。rng 使用独立随机源并与环境种子解耦，便于复现实验时单独控制探索噪声序列。若要调节"探索块"长度，可以在 explore 为真时维持若干连续步的探索状态，减少逐 step 判断造成的块长波动。

片段 2：玻尔兹曼采样与温度调度

def boltzmann_action(q_values, avail, temperature=1.0, rng=None):
    """按 exp(Q/temperature) 采样合法动作，温度越高分布越平坦。"""
    q = np.asarray(q_values, dtype=np.float64).copy()
    q[avail == 0] = -np.inf              # 非法动作概率严格置零
    q = q - q[avail == 1].max()          # 减最大值防溢出：不影响相对概率
    weights = np.exp(q / max(temperature, 1e-3))
    probs = weights / weights.sum()
    return int((rng or np.random).choice(len(probs), p=probs))

class TemperatureScheduler:
    """温度指数衰减：与价值尺度挂钩的温度调度。"""
    def __init__(self, tau0, tau_min=0.05, decay=0.9999):
        self.tau0, self.tau_min, self.decay = tau0, tau_min, decay

    def value(self, step):
        # 指数衰减比线性衰减更符合价值估计改善的速度曲线
        return max(self.tau_min, self.tau0 * (self.decay ** step))

解读：q - max 的平移操作是数值稳定性的标准手段，指数运算在 Q 值跨度较大时极易溢出。温度下限 tau_min 保证训练末期仍有非零随机性，避免策略完全固化后无法适应队友更新。温度与 Q 值量级耦合是常见配置错误：回报缩放（第 026 章）改变 Q 值尺度后，同一温度对应的探索强度完全变化，两处配置需要联动标定。

片段 3：局部观测计数与内在奖励

class HashCounter:
    """把连续观测离散化后计数，返回计数式内在奖励。"""
    def __init__(self, obs_dim, bins=16, n_buckets=200_000, eta=0.05, seed=0):
        self.bins = bins                     # 每维离散档数：bins^obs_dim 增长极快
        self.n_buckets = n_buckets           # 桶数上限，控制内存占用
        self.eta = eta
        self.salt = np.random.RandomState(seed).randint(1, 1_000_000, size=obs_dim)
        self.counts = np.zeros(n_buckets, dtype=np.int64)

    def _key(self, obs):
        # 离散化后按随机盐做线性映射：相近观测落入同桶的概率被压低
        discrete = np.clip((obs + 1.0) * 0.5 * self.bins, 0, self.bins - 1).astype(np.int64)
        return int((discrete * self.salt).sum()) % self.n_buckets

    def bonus(self, obs):
        # 访问越多奖励越小：1/sqrt 的衰减比 1/n 更温和，防止热点迅速失去探索价值
        k = self._key(obs)
        self.counts[k] += 1
        return self.eta / np.sqrt(self.counts[k])

解读：映射表计数把"精确计数"松弛为"桶计数"，用可控的冲突率换取固定内存。离散化档数与观测维度的乘积决定原始格子数量，n_buckets 独立限制内存；当桶数远小于格子数时冲突率上升，桶计数高于任一单格的真实访问次数，内在奖励被系统性低估，偏差方向固定，需要相应提高桶数或按冲突率上调 η。奖励取 1/√n 的形式来自计数式探索的带宽估计，实践中同时兼顾了数值稳定。多智能体使用时对每个智能体的局部观测分别计数、把各自奖励求和加入团队奖励，或者只对变化最快的观测子空间计数，两种选择按任务的信息来源结构决定。

常见坑

  • 评估通路残留探索噪声。评估时仍走 ε-greedy 采样，评测回报被随机性抹低，且曲线出现与采样周期同频的波动。症状是评估曲线比训练曲线更平滑的低水平平台。修复：evaluate 分支只返回确定性动作，并在评测代码路径上做断言检查。
  • 课程切换后未重置探索调度。ε 按全局步数衰减，进入高难阶段时已接近终值，新难度上的探索量严重不足。修复：课程升阶时调用探索模块的重置接口，或按阶段内步数调度衰减。
  • 探索方案与规模脱节。独立探索时联合行为长期处于部分探索的混合状态，协作序列样本稀缺；共享随机数配合过大 ε 时全体随机块占据大量回合，有效数据骤减。修复：采用共享随机数或成块探索，同时控制 ε 上限与探索块长度，监控随机动作占比曲线。
  • 内在奖励量级失控。计数奖励权重过大时，智能体持续追逐访问次数而忽略任务回报。症状是状态覆盖曲线上升、任务回报曲线平坦。修复：内在奖励不超过任务单步奖励的十分之一量级，并对总奖励做归一化监控。
  • 温度与价值尺度脱耦。回报缩放或课程奖励重塑改变 Q 值量级后，温度未联动调整，探索强度发生漂移。修复：把温度配置与奖励缩放系数绑定，或在价值侧固定归一化口径。

    共享随机数下"全体探索"由一次采样决定，N 个智能体的触发概率为 ε；独立方案下为 εN。条件在探索事件之后，两种方案中指定同步动作的组合概率均为 (1/|A|)N，差异完全来自探索事件的概率，因此比较操作数时只需看 εN 与 ε 的量级差。
  2. 改参数预测：把 ε 终值从 0.05 调到 0.3，保持其他配置不变，预测训练末期回报均值与种子间方差的变化方向，并说明对非平稳队友的适应速度如何变化。★
    提示
    末期残留高探索使策略保持适应性，方差可能略降，但平均回报低于低探索配置；适应速度更快，代价是收敛精度下降。
  3. 设计：为一个 4 智能体、观测高维连续的任务设计计数奖励方案，选择计数对象（联合状态、局部观测或其子空间）、离散化粒度与桶数，并给出内存占用与碰撞率的估算过程。★★
    提示
    高维观测下精确格子不可行；对低维运动子空间离散化、对感知类维度按符号压缩，桶数按 105 量级估算碰撞率。
  4. 实验设计：在同步协作任务上比较独立探索、共享随机数探索、计数奖励三种设置，指标使用首个协作成功回合出现的环境步数与训练末期成功率。★★★
    提示
    三种设置使用相同种子集合与相同总步数；预期共享随机数在"首次成功"的步数指标上优势最大，计数奖励在覆盖率上优势最大。

小结

  • 多智能体探索的核心困难是联合动作空间的指数规模，独立随机探索命中协作序列的概率随智能体数量指数衰减。
  • 共享随机数联合探索把全体探索变为单个事件，恢复协作模式的样本密度；共享度与探索块长度是调节旋钮。
  • 计数式内在奖励把探索目标转向状态覆盖，多智能体下选择局部计数聚合；1/√n 衰减形式与固定桶映射是工程标配。
  • 熵正则与玻尔兹曼温度分别作用于损失端与动作端，调度逻辑一致：早期保持覆盖，后期逐步确定化。
