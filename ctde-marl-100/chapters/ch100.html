第五篇 · 研究复现与系统集成

第 100 章：综合研究项目设计与技术报告写作

全课收官：把算法原理、实验方法与工程规范整合为一条完整研究流程，从问题定义与预算核算到技术报告七节结构与可复现清单，并给出全课程的知识地图回顾。

  • 主题：研究项目设计 / 技术写作规范
  • 关键公式：预算核算 组数 × 种子数 × 单次环境步、报告统计 mean ± 95% CI 与 IQM
  • 预计学时：65 分钟
  • 前置章节：第 099 章

学习目标

  • 能把研究想法写成规范的问题定义与五要素实验设计，并给出可检验的研究假设。
  • 掌握技术报告七节结构（摘要、引言、相关工作、方法、实验、讨论、附录）与各节写作规范。
  • 掌握可复现清单五项：配置唯一标识、种子列表、环境与框架版本、评估协议、原始曲线数据。
  • 理解报告中的统计规范与四类常见失范：选择性报告、无区间结论、隐藏负结果与坐标轴不统一。
  • 能核算一个完整项目的计算预算，并规划从预实验到报告的项目检查节点。

背景与动机

前面九十九章分别交付了三类能力：算法原理（值分解、策略梯度、通信与机制设计）、实验方法（复现三层对齐、统计检验、消融设计）与工程规范（环境集成、评测协议、框架选型）。研究项目的困难恰在整合：方向选得对、代码跑得通、曲线画得出，报告却讲不清"解决了什么问题、证据为什么支持结论"。项目设计与写作属于研究本身的方法论组成部分：问题定义决定实验设计，报告结构决定结论能否被审阅者复核。

本章先给项目设计的模板与预算核算方法，再逐节讲技术报告的写作规范，最后用一张知识地图把全课程串起来。作为收尾章，本章的定位是"集成与复核"：任何一节的具体技术都回指前面章节，读者应能把前九十九章当作可查询的方法库，而本章是调用这个库的项目模板。

核心原理

1. 项目设计：从问题到假设

规范的项目设计从问题定义开始：用第 001 章的形式化语言写出任务（状态、观测、动作、奖励、转移与视野），指出任务的困难来源（部分可观测、非平稳、异构、规模），再收敛为一个可检验的假设。假设必须含比较对象与方向，例如"在观测受限的捕食任务上，引入通信代价对偶控制的 MAPPO 在相同环境步预算内到达 80% 胜率所需步数少于无代价版本"。句子中每个成分都对应一个后文设计决定：任务对应基准选择（第 097 章），比较对应基线与消融（第 092 至 096 章），预算对应资源核算。

2. 基线与消融计划

基线选择遵循"一弱一强"原则：弱基线是领域内最简单的合理方法（独立 Q 学习或 IPPO），强基线是当前公认最优（MAPPO 或最新复现对象）。弱基线证明问题的非平凡性，强基线决定贡献的可信度。消融计划按第 096 章的因子设计组织，必做项与方法主张一一对应；任何"我们的方法在 X 上更好"的句子，都应当在消融表里找到对应组件的删除行或替换行。

3. 计算预算核算

预算以环境的决策步为单位核算，覆盖四个来源：主实验（算法 × 地图 × 种子 × 单次预算）、消融（因子组合 × 种子 × 单次预算）、敏感性与调参（预留 20% 到 30%）、复算与修正（预留 10%）。

总环境步 ≈ ( N算法 × N地图 + N消融组 ) × N种子 × T单次 × 1.3 示例：4 算法 × 3 地图 + 16 组消融，10 种子，单次 100 万步，总计约 3.6 亿环境步；先按此核算再决定矩阵规模

核算的意义在于暴露不可行：如果总量超出可支配资源，应当缩减地图数或消融组数，在预实验阶段完成决策。先定协议与预算再开跑，是防止项目中途返工的最直接手段。

4. 技术报告七节结构

节内容写作规范
摘要问题、方法、结果各一句结果句给出量级与区间，不用"显著提升"这类无数字表述
引言动机、挑战、贡献列表贡献逐条编号，每条可指向后文图表
相关工作定位差异按方法族组织，讲清与最相近工作的区别
方法形式化定义与设计决策每个设计决策附理由与替代方案
实验协议、主结果、消融协议先写、结果后写；表格含区间与检验标注
讨论局限、失效模式、未来方向负面结果如实报告，说明适用边界
附录配置表、敏感性与额外曲线附录承载细节，正文只保留主张与关键证据

图表是报告的主要证据载体：主结论用一张主表与一张主图，其余进附录。每张图独立可读（坐标轴、单位、平滑声明、种子数齐全），图注不复制正文，正文不复述图注，两者互补。

5. 可复现清单与统计规范

可复现清单五项与第 092 至 097 章的规范一致：配置唯一标识（完整超参数字典的摘要）、种子列表、环境与框架版本、评估协议（贪心、回合数、种子基址、计胜规则）、原始曲线数据。报告统计统一用 mean ± 95% 置信区间或 IQM 加分层自助区间，显著性检验标注方法与校正，效应量与被比较的量纲一起给出。四类失范必须避免：只报最好种子、只报容易难度档、隐藏失败的消融行、横轴用墙钟时间且不声明平滑。

6. 全课程知识地图

回看全课：第一篇（001 至 025）建立 CTDE 的形式框架与核心算法，值分解、反事实、策略梯度与通信基础在此成型；第二篇（026 至 040）处理训练工程，归一化、梯度、批处理与种子方差的稳定性手段在此交付；第三篇（041 至 060）把算法放进具体任务验证迁移性；第四篇（061 至 080）扩展到机制与研究专题，安全、迁移、分层与模型预测在此接入；第五篇（081 至 100）完成研究闭环，公平与解释、实验统计、复现方法、评测平台、框架与规模化逐一补全。项目设计时，五篇分别回答"用什么算法、怎么稳住训练、在什么任务上验证、叠加哪些机制、如何证明结论"，缺一环则证据链不完整。

实现思路与设计

项目生命周期分六步，每步有明确交付物：

  1. 问题定义：任务形式化、困难来源与可检验假设（一页文档）。
  2. 预实验：单算法小地图校准与噪声估计，确定种子数与效应量（五种子曲线）。
  3. 协议与预算：第 095 章协议模板加本章预算公式，冻结矩阵规模。
  4. 执行：按种子成组调度（第 095 章配对结构），记录逐运行清单（第 082 章格式）。
  5. 分析与消融：主结果与消融并行分析，区间与检验按规范输出。
  6. 报告：七节结构成文，可复现清单随稿发布，附图原始数据。

与第 099 章的差异点：099 章解决"规模能不能上得去"，本章解决"项目能不能收得住"；前者是技术扩展，后者是流程集成，两者共享实验预算与评估协议这两个接口。

项目检查节点

节点检查内容通过标准
节点一（问题定义完成）假设与基线清单假设含方向与比较对象，基线一弱一强齐备
节点二单算法校准曲线进入参考文献同量级，协议冻结
节点三主实验过半记录字段完整，无配置漂移
节点四消融完成必做消融项与方法主张一一对应
节点五报告一审每句结论可指向具体图表与检验
设计决策：为什么预算核算必须在矩阵展开之前完成？

矩阵展开后的任何缩减都会制造不可比的子集：跑了三分之二发现超支，砍掉的地图与算法留下空档，事后补跑引入时间与版本差异。把预算公式前置，在纸面上完成"矩阵规模与资源的匹配"，是唯一不产生事后偏差的调整时机。预实验的另一重价值即在于用真实吞吐量校准预算公式。

关键代码与解读

片段 1：报告表格生成器

import numpy as np

def report_table(results, baseline):
    """生成报告表格行：IQM、95% 区间与相对基线的配对显著性标记。"""
    rows = []
    base = np.array(results[baseline], dtype=np.float64)
    for name, per_seed in results.items():
        vals = np.sort(np.asarray(per_seed, dtype=np.float64))
        k = len(vals)
        iqm = float(vals[k // 4: k - k // 4].mean())          # 两端各裁 k//4 后取均值
        lo, hi = np.quantile(vals, [0.025, 0.975])
        diff = np.asarray(per_seed, dtype=np.float64) - base  # 同种子配对差
        n_pos = int((diff > 0).sum())
        # 符号检验近似：几乎全部同向才标记显著，正式版换成自助区间
        sig = "*" if n_pos >= k - 1 or n_pos <= 1 else ""
        rows.append((name, f"{iqm:.3f}", f"[{lo:.3f}, {hi:.3f}]", sig))
    return rows

# results 记录每个算法的逐种子最终性能；基线自身 diff 全零，不标记
results = {"mappo": [0.72, 0.68, 0.75, 0.70, 0.66, 0.73, 0.71, 0.69, 0.74, 0.70],
           "ippo":  [0.60, 0.55, 0.62, 0.58, 0.52, 0.61, 0.59, 0.56, 0.63, 0.57]}
print(report_table(results, baseline="mappo"))

解读：（1）表格三列分别承载点估计、区间与显著性：这是第 095 章报告规范的最小集合，任何一列缺失都会降低证据强度。（2）符号检验近似用"差值几乎全同向"作判据，实现简单、无需分布假设；正式报告中应替换为自助区间或 Wilcoxon 检验，并把方法名写进表格脚注。（3）IQM 用排序后两端各裁四分之一（向下取整）的均值，与第 082 章的聚合口径一致；区间用种子分位数，k = 10 时分位数估计粗糙，故四舍五入到三位小数即可，不必假装更高精度。（4）基线自身也参与循环（diff 全零、不标记），表格行序与 results 插入序一致，保证跨版本输出稳定可 diff。

片段 2：可复现清单生成与校验

import hashlib
import json

def make_manifest(cfg, seeds, versions):
    """可复现清单：配置唯一标识、种子与版本，一行 JSON 冻结一次实验。"""
    payload = json.dumps(cfg, sort_keys=True).encode("utf-8")
    manifest = {
        "config_hash": hashlib.sha256(payload).hexdigest()[:16],  # 配置唯一标识
        "seeds": list(seeds),                                    # 训练种子
        "versions": versions,                                    # 环境与框架版本
    }
    return manifest

def verify_manifest(manifest, cfg):
    """复算前校验配置未被修改：标识一致才允许复用历史结论。"""
    payload = json.dumps(cfg, sort_keys=True).encode("utf-8")
    current = hashlib.sha256(payload).hexdigest()[:16]
    return current == manifest["config_hash"]

cfg = {"algo": "mappo", "lr": 5e-4, "clip": 0.2, "n_agents": 8, "horizon": 200}
m = make_manifest(cfg, seeds=range(10), versions={"env": "1.3.2", "framework": "0.9"})
print(m["config_hash"], verify_manifest(m, dict(cfg)))

解读：（1）唯一标识由完整配置字典生成：任何一处超参数改动都会改变标识，从机制上阻止"悄悄换参数后沿用旧结论"。（2）种子列表显式记录：复算时需要完全相同的一组种子才能精确重现曲线，种子范围的隐含约定不算文档。（3）verify_manifest 是分析脚本的入口检查：标识不匹配时脚本应拒绝复用表面数字，强制重跑。（4）清单与原始曲线数据、评估脚本共同构成可复现包；包的最小标准是第三方无需联系作者即可复算报告中的全部数字。

常见坑

  • 假设写成愿景：如"提升多智能体协作能力"，无比较对象无方向。修复：改写成含基准、指标、方向与条件的句子。
  • 预算未核算就展开矩阵：中途缩减留下不可比子集。修复：先按预算公式纸面核算，预实验校准吞吐量。
  • 报告只呈阳性结果：失败的消融行与负结果被删除。修复：负结果进讨论节，说明失效边界，这是可信度的一部分。
  • 图与统计口径不一：图用平滑均值、检验用原始点，结论互相打架。修复：图表与检验共享同一分析函数（第 082 章）。
  • 可复现清单缺失版本字段：第三方复算时环境漂移，数字对不上。修复：环境与框架版本加唯一标识写进清单，随稿件发布。

练习与思考

  1. 为一个自选课题写一页问题定义：任务形式化、困难来源与一条可检验假设，标注假设中每个成分对应的实验设计决定。★
    提示
    假设句分解为"任务、比较对象、指标、方向、条件"五段；每段指向基准选择、基线清单、指标定义与协议冻结四个动作。
  2. 用预算公式核算：5 算法 × 2 地图 + 12 组消融，8 种子，单次 80 万步，求出总环境步并判断是否可在缩减一半算力时完成。★★
    提示
    总量 ≈ (10 + 12) × 8 × 80 万 × 1.3 ≈ 1.83 亿步；缩减一半时优先砍地图或算法档，保留消融组与种子数，因为统计结论的可靠性优先级更高。
  3. 为一段仿真结果写两种摘要句：一种含区间与量级，一种用无数字表述，比较两者作为审稿证据的差异。★★
    提示
    "到达阈值步数减少 32% 且差值区间不跨零"对比"显著提升了样本效率"。前者可复核，后者不可证伪，写作训练从拒绝无数字表述开始。
  4. 设计一次投稿前的内部复核：列出五类检查（图表可读性、统计口径、消融完整性、可复现清单、负结果呈现），各写一条通过标准。★★★
    提示
    通过标准要可操作：图表检查用"随机抽一张图能否独立读懂"；消融用"逐条主张找到对应组件行"；清单用"第三方按包复算三个数字"。
  5. 以本课程某一章的方法为主题，设计一个"复现加改进"小项目：给出复现验收标准、改进假设、消融计划与预算核算四项内容。★★★
    提示
    从第 092 至 094 章任选一条脉络，改进点写成一个开关式组件；验收用两级标准（趋势与量级），预算按本章公式核算，消融至少包含该组件与一个交互检查。

小结

  • 项目设计从形式化问题与可检验假设出发，基线一弱一强，消融项与方法主张一一对应，预算在矩阵展开前核算。
  • 技术报告七节结构：摘要三段式、引言给编号贡献、方法写决策理由、实验先协议后结果、讨论含局限与负结果、附录承载细节。
  • 可复现清单五项与统计规范三项（点估计、区间、检验）是报告的证据底线。
  • 四类失范须避免：只报最好种子、只报容易档、隐藏负结果、坐标轴与平滑不声明。
  • 全课程回顾：第一篇建算法、第二篇稳训练、第三篇验任务、第四篇扩机制、第五篇成研究闭环；项目设计时五环相扣，缺一环则证据链不完整。
  • 课程到此结束。建议的继续路径：选择第五篇中的一条复现脉络做完整闭环，再用第 099 章的方法把规模推到百级，最后按本章流程成文。谢谢学习，祝研究顺利。
