第二篇 · 训练工程与稳定性

第 034 章：混合合作竞争环境

本章讲混合动机（Mixed-Motive）任务的建模与训练：团队奖励、个体奖励与竞争项的组合结构，双头价值设计与联盟内优势分解，对手的两种处理路线，以及合作激励成立的权重条件。

  • 主题：奖励结构设计 / 联盟内信用
  • 关键公式：ri = wt·rteam + ws·rself,i + wo·ropp,i
  • 预计学时：55 分钟
  • 前置章节：第 033 章 对抗环境下的CTDE

学习目标

  • 理解混合动机任务的激励结构：团队共享、个体专属与竞争三类分量如何组合，以及它们对均衡的影响。
  • 掌握合作激励成立的条件分析：个体收益何时与团队收益对齐，何时出现搭便车与背叛倾向。
  • 掌握双头价值设计：团队价值头与个体价值头的分工、优势合成方式与尺度匹配。
  • 理解对手在混合环境中的两种处理路线（环境化与显式建模）及其与第 032、033 章手段的接续关系。
  • 能实现奖励混合器与双头评论家，并诊断个体激励主导、尺度失衡两类典型故障。

背景与动机

第 033 章处理纯粹对抗：一方所得即另一方所失，目标是极小极大。多数真实任务介于两端之间：一个联盟内部共享目标（合作），联盟之间争夺有限资源（竞争），同一智能体同时收到团队奖励、个体奖励与对抗相关的收益信号。这类结构称为混合动机（Mixed-Motive）任务，联盟内合作与联盟间竞争的激励在同一损失函数中共存。

混合结构把两个既有问题叠加：联盟内部的信用分配（第 020 章）与联盟之间的非平稳对抗（第 032、033 章）。朴素做法把三路奖励打成标量和再送入单头价值网络，表面简单，实际问题被掩盖：团队分量与个体分量的价值尺度不同，网络被大量级分量主导；对抗分量进入团队价值头会污染团队决策。本章的核心主张是奖励分层与价值分层：不同来源的信号有不同的归属对象与不同的回答方式，分层处理让每个信号被正确归因。

核心原理

1. 混合激励的数学结构

智能体 i 的即时奖励写成三类分量之和：

ri = wt · rteam + ws · rself,i + wo · ropp,i rteam 对联盟内全体共享，rself,i 为个体专属回报，ropp,i 记录与竞争对手的得失差

权重决定均衡的存在性与性质。以两人的公共品实验结构为例：投入公共品给全体带来放大后的共享收益，个体保留则独占收益。设共享放大系数为 β，个体投入成本为 c，当 β/N 大于 c 时社会最优是全体投入，但个体最优是坐享他人投入（搭便车）。学习动力学收敛到哪个结构由权重比例决定：团队权重相对个体权重大到一定程度后，个体偏离合作的即时收益被团队分量抵消，合作行为在学习动态中稳定。这个"大到一定程度"的临界值依赖博弈的具体收益表，工程上通过小规模数值实验标定，无通用闭式解。

反向问题同样存在：纯团队奖励（ws = 0）在共享网络下把信用分配完全交给结构（值分解或反事实基线），个体差异被平均化，能力强的智能体缺少继续提升的梯度。混合权重的实践区间通常是团队分量占主体、个体分量作为辅项，具体比例与任务对个体贡献可辨识度的需求相关。

工程上确定权重比例的标准流程是一次小规模扫描：固定其余配置，在 3 到 5 档团队权重上各跑较短预算，比较联合成功率与个体回报方差的组合；选择联合成功率达标且个体方差未显著扩大的最低团队权重，再在该点附近细扫个体与竞争权重。扫描结论随任务的收益结构变化更新，不在没有收益表依据的情况下跨任务照搬。

2. 双头价值设计

价值侧采用双头结构，把两种回答分开：团队头回答"这个联合状态有多好"，个体头回答"我的行为相对他人有多大增量"。优势合成写成：

Ai = Ateam(s, a) + λ · Aself,i(oi, ai) Ateam 由集中式评论家给出（可含反事实基线），Aself,i 由个体评论家给出

分层的意义在训练信号上：团队头接收团队分量与对抗分量的团队投影，个体头只接收个体专属分量。损失函数按头加权，团队头损失权重取 1，个体头取较小系数（0.1 到 0.3 量级），防止个体优势在合成时淹没团队信号。两个头的价值尺度必须对齐后再合成：团队头输出对全体智能体共享，量级与个体头相同（同一奖励量纲）；若某头使用独立的归一化统计，合成前需要换算到公共尺度，否则 λ 的物理含义随训练漂移。

λ 与个体头损失权重的标定可以走一条可测量的路径：分别统计两个头在共享主干处的梯度范数，取其比值作为工作点，让个体头的梯度范数落进团队头的十分之一到三分之一区间。这比直接猜 λ 更稳定，因为梯度范数同时反映奖励量级与样本分布两个因素，训练中比值持续漂移说明两头的信号强度在失衡，需要重标定，继续训练无法自行修复。逐窗口的梯度范数记录并入训练日志，与第 035 章的诊断指标共用字段。

3. 对手的两种处理路线

混合环境中的竞争对手有两种接入方式：

  • 环境化。把对手当作环境动态的一部分，用第 032 章的漂移监控与第 033 章的对手池管理对付其非平稳性，队友侧维持纯合作的信用分配结构。适合对手策略相对稳定、交互模式简单的任务。
  • 显式建模。为对手建立预测头（第 032 章）并把其输出作为团队评论家的条件输入；对手的竞争分量只在个体头结算，团队头关心联盟整体对竞争对手的相对优势。适合对手适应性强、需要利用其行为模式的任务。

两条路线的切换判据是可预测性：对手行为预测误差显著低于随机基线时，显式建模的收益才成立；否则预测头提供的条件只是噪声，增加容量负担。对抗分量进入哪一头是一个易错的设计点：把 ropp 混进团队头会让团队价值把竞争对手的得失当作自己联盟内部的好坏，污染联盟内的信用分配。

可预测性判据可以定量化：用对手行为预测头在留存数据上的分类准确率与随机猜测（1/|A|）比较，准确率高出随机基线十个点以上时，显式建模的条件输入才开始稳定降低团队价值的拟合误差；差距不足时，优先扩大对手池的多样性再回看判据。该统计与第 032 章辅助头的交叉熵诊断共用同一份预测质量度量，避免两章各自维护一套口径。

4. 联盟内均衡与评估

联盟内部仍有均衡选择问题：多智能体任务常存在多个质量相近但协调方式不同的解（例如左绕与右绕），混合动机下个体奖励差异会打破对称，让学习动力学收敛到某个特定协调结构。这一性质既是稳定性来源（打破对称加速收敛），也是公平性隐患（个体可能收敛到承担更多成本的角色）。评估需要同时报告三个层次：团队回报（做得如何）、个体回报分布（谁承担了成本）、对手收益（竞争结果）。只报告团队总回报会掩盖内部分配问题，第 081 章会展开公平性指标。

5. 数值算例：公共品结构的合作条件与权重阈值

两人公共品实验给出可手算的合作条件。每人的选择为投入（成本 c = 1）或保留；总投入乘以放大系数 β = 1.2 后在两人间均分。双方投入时总产出 2.4，各得 1.2，扣除成本后各净得 0.2；单方投入时总产出 1.2，各得 0.6，投入者净得 −0.4、保留者净得 0.6；无人投入时双方为 0。社会最优是全体投入（总福利 0.4，高于单方投入的 0.2），个体最优却是对方投入时自己保留：这一张力就是混合动机的典型结构，团队权重的任务是把偏离方向的即时收益压回非正。

设团队分量取联盟平均收益、个体分量取自身净收益。偏离（从双方投入到单方保留）使自身净收益增加 0.4，联盟平均从 0.2 降到 0.1、减少 0.1。混合奖励的偏离增量约为 ws × 0.4 − wt × 0.1，令其非正解得 wt / ws ≥ 4：本例参数下团队权重要达到个体权重的四倍，折算到归一化权重即 wt ≥ 0.8。把 β 降到 1.1 再做同样计算，偏离收益与团队损失按比例收窄，阈值随之变化：外部性越强（β 越大），维持合作所需的团队权重越高。这个可核算的例子把"临界值依赖收益表"的定性结论落到了数字上。

单步阈值的解释有边界：重复互动中偏离会触发后续惩罚或声誉损失，多步收益提供额外的稳定项，实际阈值一般低于单步计算值；反过来，若团队分量在训练中随集体表现被放大或压缩，名义权重不变而实际压差已经改变，阈值核算随之失效。报告此类实验时把奖励表、权重与阈值计算一并列出，读者才能判断合作行为的稳定来源是权重结构还是侥幸的初始条件。

实现思路与设计

系统在数据管线中加入奖励混合器，在网络侧加入双头评论家，两处改动都以配置项驱动，保持与协作基线的结构兼容（权重配置为纯团队时退化为标准 CTDE）。

参数默认值作用取值依据
团队权重 wt0.6 至 0.8共享目标强度合作失稳时上调，个体停滞时下调
个体权重 ws0.1 至 0.3个体贡献信号与任务对个体可辨识度的需求相关
竞争权重 wo0.1 至 0.2相对得失过大会诱发拿团队利益换个体战绩
合成系数 λ0.2 至 0.5个体优势占比个体头损失权重与 λ 联动标定
个体头损失权重0.1 至 0.3训练信号配比团队收敛优先，个体信号作调制
评估报告项团队 / 个体分布 / 对手三层评估缺任一层的实验结论不可迁移

与第 033 章的衔接点：竞争分量的对手池管理与可被利用度评测全部沿用；混合环境在其上增加团队内部的信用分层，评测加入个体回报的分布指标。

权重配置的冻结与调整纪律需要写进实验协议：奖励权重定义的是优化目标本身，训练中途改动权重等价于更换任务，价值函数与策略同时失去一致性。若必须调整，采用的流程是停止训练、载入最新检查点、在新权重下短程微调，并在图表中把微调段单独标注；把权重改动混入主曲线会造成不可归因的性能跳变。该纪律与第 022 章的课程阶段化配置思路一致：目标结构的变更始终显式化、阶段化。

关键代码与解读

片段 1：奖励混合器

import numpy as np

class MixedReward:
    """三类分量的加权组合：团队、个体、对抗；权重独立于环境配置。"""
    def __init__(self, w_team=0.7, w_self=0.2, w_opp=0.1):
        assert abs(w_team + w_self + w_opp - 1.0) < 1e-6, "权重需归一化以便跨任务比较"
        self.w = (w_team, w_self, w_opp)

    def compose(self, team_r, self_r, opp_r):
        """输入：标量团队奖励、个体奖励向量、对抗得失向量。"""
        wt, ws, wo = self.w
        # 团队分量广播到每个智能体：共享奖励不因个体差异改变
        r = wt * team_r + ws * np.asarray(self_r) + wo * np.asarray(opp_r)
        return r.astype(np.float32)

    def split_for_heads(self, team_r, self_r, opp_r):
        # 团队头只接收团队分量与对抗的团队投影，个体头只接收个体分量
        team_part = self.w[0] * team_r + self.w[2] * float(np.mean(opp_r))
        self_part = self.w[1] * np.asarray(self_r)
        return team_part, self_part

解读：split_for_heads 是这段代码的设计核心：同一条即时奖励在写入回放池前按头拆分，团队头得到与联盟相关的部分，个体头得到专属部分。对抗分量的团队投影取均值是简化约定（联盟整体相对对手的得失），更细的做法按角色或贡献加权。权重归一化断言保证不同任务配置的奖励尺度可比，避免"换任务后等效权重悄然漂移"这一类隐性 bug。混合器位于环境出口与回放池入口之间，与第 021 章的塑形模块串联时注意次序：先塑形后混合，塑形项跟随团队分量。

片段 2：双头评论家

import torch
import torch.nn as nn

class DualHeadCritic(nn.Module):
    """团队头 + 个体头：分别回答“联合有多好”与“我贡献多少”。"""
    def __init__(self, state_dim, obs_dim, n_agents, hidden=128):
        super().__init__()
        self.team = nn.Sequential(nn.Linear(state_dim + n_agents * obs_dim, hidden), nn.ReLU())
        self.team_head = nn.Linear(hidden, 1)                  # 团队价值：全体共享
        self.self_head = nn.Sequential(nn.Linear(obs_dim, hidden), nn.ReLU(),
                                       nn.Linear(hidden, 1))   # 个体价值：逐智能体输出

    def forward(self, state, obs_joint, obs_self):
        t = self.team_head(self.team(torch.cat([state, obs_joint], dim=-1)))
        # 个体头逐智能体前向：参数共享，输出形状 (batch, n_agents, 1)
        s = self.self_head(obs_self)
        return t, s

解读：团队头拼接全局状态与联合观测，个体头只吃自身观测，两条计算路径在结构上分离，保证梯度归因清晰。个体头共享参数而逐智能体输出：身份差异依赖输入区分，与第 030 章的共享策略保持同一哲学。两个头的输出量级由各自的损失调节，尺度对齐在损失侧完成（团队目标未归一化的原始回报，个体头目标为个体分量回报，量纲相同）；若引入 PopArt（第 026 章），两个头各配一套统计，合成优势前按统计换算。

片段 3：优势合成与联盟内信用

def composed_advantage(team_adv, self_adv, lam=0.3):
    """团队优势与个体优势的加权合成，供策略梯度类算法使用。"""
    # 团队优势：由集中式评论家对联合行为给出，可含反事实基线（第 020 章）
    # 个体优势：由个体头给出，量级较小，λ 控制其影响
    combined = team_adv + lam * self_adv
    # 标准化只作用于合成后的整体，避免两个分量各自的尺度差异被放大
    mean = combined.mean()
    std = combined.std().clamp(min=1e-6)
    return (combined - mean) / std

def credit_report(self_adv, agent_ids):
    """按智能体聚合个体优势：诊断谁长期承担负增量。"""
    stats = {}
    for i in sorted(set(agent_ids)):
        vals = self_adv[agent_ids == i]
        # 均值负且持续多轮意味着该个体的行为长期拖累团队，需要检查其职责配置
        stats[i] = (float(vals.mean()), float(vals.std()))
    return stats

解读：合成后统一标准化的选择避免了"分量各自标准化再相加"的经典错误：分别标准化会把小量级分量的方差人为放大，λ 的实际作用被稀释。credit_report 把个体优势当作诊断信号：某智能体的均值长期为负未必是它在犯错，也可能是任务分配把最难的子任务给了它，报告需要结合职责配置解读。该统计进入第 035 章的训练曲线诊断体系，与团队回报曲线联读判断联盟内信用分配是否健康。

常见坑

  • 个体权重过大。个体分量主导损失后，各智能体为个体奖励互相竞争，联盟协作退化。症状是团队回报平台化而个体回报方差增大。修复：上调团队权重，观察联合成功率曲线响应。
  • 竞争分量混入团队头。团队价值把对手得失当作联盟内部好坏学习，联盟内信用被污染。症状是团队优势与个体优势的相关系数异常偏高。修复：按片段 1 的方式在写入前拆分，团队头只取团队投影。
  • 优势合成的尺度处理错误。双头尺度失衡使合成优势被团队项独占；分量各自标准化再相加会把小量级个体分量人为放大。修复：两头使用同一奖励量纲，先合成再整体标准化。
  • 评估只看团队总回报。联盟内分配失衡（个别智能体长期负增量）被平均掩盖。修复：报告个体回报分布与逐智能体优势统计。
  • 对手处理路线混合不清。同一实验既把对手当环境又建立对手条件输入，两套机制口径冲突。修复：明确单一路线并在配置中互斥声明。

    提示
    投入的个体净收益为 wt·βN / N − c 量级，搭便车为 wt·β(N−1)/N；令两者之差非负解出权重条件，注意这是单步简化，长期收益还有重复博弈效应。
  2. 改参数预测：把竞争权重 wo 从 0.1 提高到 0.5（团队与个体权重等比缩放），预测团队回报曲线与个体收益分布方差两个指标的变化方向。★
    提示
    竞争分量占比上升后团队协作被相对得失驱动，团队回报可能先升后降（利用对手获得的收益难持续），个体分布方差显著增大。
  3. 设计：为一个两队对抗、每队 3 人的任务设计奖励分层方案：三类分量的来源与权重、双头损失的配比、评估三项指标，并说明竞争分量在团队头中的投影方式。★★
    提示
    竞争分量按队伍得分差生成，团队头取本队投影；评估报告两队得分差、每队个体贡献分布与对手池最差胜率。
  4. 实验设计：比较纯团队奖励、混合奖励单头、混合奖励双头三种设置的团队回报与个体优势分布，说明如何判定双头结构的增益来自信用分层，并排除参数量增加的混淆。★★★
    提示
    增加单头等参数量对照组；双头增益应表现为个体优势分布的区分度提升，而不只是团队回报略升。

小结

  • 混合动机任务把团队、个体、竞争三类奖励分量叠加，权重比例决定合作是否成为稳定学习结果。
  • 奖励分层与价值分层是核心设计：团队头回答联合状态质量，个体头回答个体增量，合成优势前统一尺度。
  • 对手处理二选一：环境化依赖漂移监控与对手池，显式建模要求对手行为可预测；竞争分量只进个体头。
  • 联盟内存在多均衡选择与分配公平问题，评估需同时报告团队回报、个体分布与对手收益。
  • 下一页进入稳定性分析第一题：训练曲线如何读写，价值损失、熵、时序差分误差等指标怎样联合诊断训练故障。
