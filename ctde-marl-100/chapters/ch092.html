第五篇 · 研究复现与系统集成

第 092 章：论文复现方法：值分解系列

复现是研究训练的基本功：本章以 VDN、QMIX、QTRAN、QPLEX、WQMIX 组成值分解脉络，给出"接口对齐、超参数对齐、随机性控制"三层复现框架、实验矩阵设计与常见偏差来源清单。

  • 主题：论文复现方法论 / 值分解算法族
  • 关键公式：IGM 条件 argmaxa Qtot = (argmaxa1 Q1, …, argmaxaN QN)、QMIX 单调性 ∂Qtot/∂Qi ≥ 0
  • 预计学时：65 分钟
  • 前置章节：第 091 章

学习目标

  • 理解值分解系列的方法脉络与个体全局最大（Individual-Global-Max, IGM）条件的演进逻辑。
  • 掌握三层对齐复现框架：接口对齐、超参数对齐、随机性控制，能逐层列出检查项。
  • 能设计复现实验矩阵：算法、地图、种子的组合方式与抽样规模。
  • 掌握记录字段清单，保证每次运行的结果可追溯、可比较。
  • 能识别测试协议、死亡掩码、奖励尺度、难度配置四类常见偏差来源并给出修正方案。

背景与动机

值分解是 CTDE 体系中最成熟的方法族：从第 006 章的 VDN 到第 008 章的 QTRAN，教材层面已经交代了机制。研究层面的困难出现在复现：同一算法在不同实现下的胜率可以相差二十个百分点以上，而两者代码看起来都"忠于论文"。复现偏差的主要来源几乎都与论文正文无关，而与接口约定、超参数细节和随机性处理有关，这三类信息常常不在论文表格里。

本章把复现当作一项系统工程：先用三层对齐消除实现层面的自由度，再用实验矩阵组织对比，最后用记录字段清单保证结果可审计。选择值分解系列作为复现专题的开篇，原因是它结构清晰、公开实现多、社区约定成熟，是练习复现方法论的理想载体。随后第 093 章处理策略梯度系列，第 094 章处理通信与协作系列，三章的框架共用，偏差清单各自不同。

核心原理

1. 方法脉络：从加性分解到加权投影

值分解的共同目标是把联合动作价值 Qtot(s, a) 表示为个体价值 Qi(oi, ai) 的函数，同时保证个体贪心选择与联合贪心选择一致，即 IGM 条件：

argmaxa Qtot(s, a) = ( argmaxa1 Q1(o1, a1), …, argmaxaN QN(oN, aN) ) 满足 IGM 时，执行期各智能体独立贪心即为联合最优，无需集中式搜索
方法混合结构归纳偏置与代价
VDNQtot = Σ Qi（加性）最简单；无法表达智能体间非加性交互
QMIX超网络按状态生成单调混合权重，∂Qtot/∂Qi ≥ 0覆盖加性之外的部分单调交互；不自适应地放宽单调性
QTRAN松弛 IGM 为"最优联合动作处价值排序正确"表达力更强；松弛项优化困难、训练不稳
QPLEX对偶化：把 Q 分解为价值项与优势项，各自施加单调与限制表达力接近无约束；实现复杂度高
WQMIX加权投影：对高价值样本提高拟合权重缓解单调性对最优动作的欠拟合；权重方案需调

复现该系列时的对照顺序建议为 VDN 到 QMIX 到一种表达力扩展（QTRAN 或 QPLEX），每一步只改变混合结构，其余组件完全固定，这样变量归因清晰。

2. 三层对齐框架

第一层是接口对齐：环境版本与地图编号、回合步数上限、全局状态的字段组成、动作空间的合法集合、测试协议（贪心或采样、评估回合数）。这些约定决定"任务是什么"，任何一处不同都会移动性能基准。

第二层是超参数对齐：回合级回放缓冲 5000 条、批量 32 回合、优化器与学习率（RMSProp 5e-4 或 Adam 5e-4 量级）、目标网络更新周期 200 个更新步、探索率自 1.0 线性衰减到 0.05 的步数、隐藏维度 64。这些是值分解系列的社区惯例值，先按惯例固定，再做敏感性分析。

第三层是随机性控制：环境种子、网络初始化种子、探索噪声种子、评估种子分别设定并记录；评估用贪心策略、评估回合数固定（32 或更多）、报告统计量用第 082 章的 IQM 管道。三层的顺序不可颠倒：接口不齐时调超参数，等于在错误的基准上过拟合。

3. 偏差来源清单

  • 测试协议偏差：训练开着探索噪声、测试用贪心，若测试时忘记切换，胜率被低估；评估回合数 8 与 32 的标准误相差一倍以上（p = 0.5 时分别约 0.177 与 0.088）。
  • 死亡掩码偏差：死亡智能体的动作在反传中被置零还是被排除，两种处理的混合网络梯度路径不同，中期胜率差异可达数个百分点。
  • 奖励与终止语义偏差：胜负判定是"全歼"还是"任务完成"，截断是否算负，直接改变学习目标。
  • 难度配置偏差：同一地图的敌方数量、初始兵力、视野半径的非标准修改会让曲线整体平移。
  • 训练预算偏差：各算法的总环境步数不一致时，"收敛快慢"的结论不可比；预算应固定并居中报告。
  • 序列截断偏差：RNN 序列按情节切分还是固定长度截断，影响 BPTT 的有效视野与 Q 值估计滞后。

4. 实验矩阵与记录字段

实验矩阵按算法 × 地图 × 种子组织：算法维度放待比较的方法（三到五种），地图维度选难度递增的两到三张，种子维度不少于五个。记录字段的最小清单：配置唯一标识（完整超参数字典的摘要）、算法与依赖版本、环境版本与地图、种子、评估点（环境步与胜率）、置信区间、训练损失曲线摘要。字段清单的意义在于让任何一条结论都能回放到具体运行，这是复现的审计基础。

5. 复现验收标准

验收分两级：级别一，趋势一致，算法间的相对排序与论文一致；级别二，量级一致，同地图同预算下胜率与原报告差距不超过十个百分点或在置信区间内。级别一未达成时优先排查接口层；级别二未达成而级别一达成时，排查超参数与随机性层。两级验收都达成后，复现结果才可作为后续消融实验的基线。

实现思路与设计

复现流程分五步：

  1. 基座选择：以 PyMARL 或 EPyMARL 风格的开源实现为参照基座，锁定版本。
  2. 接口核对：逐项核对地图、步数上限、状态字段、测试协议，写成检查表。
  3. 单算法校准：先用一张小地图校准学习率与探索调度，使单算法曲线进入论文量级。
  4. 矩阵展开：算法 × 地图 × 种子展开，训练预算固定，评估点对齐。
  5. 结果审计：按记录字段清单导出，用第 082 章管道聚合，与论文曲线对照验收。

与第 091 章的差异点：091 章设计执行期的市场机制，本章处理研究流程本身的工程规范；机制序列的结论要经本章方法验证后才能进入论文对比。

设计决策：为什么先用小地图做单算法校准？

全矩阵展开的计算量是算法数乘地图数乘种子数，在校准前展开意味着把未验证的配置复制到每个单元。先用一张小地图跑单算法，观察曲线形状（上升速度、平台水平、方差带宽度），与论文同图对比，能在成本最低处发现接口与超参数问题。校准通过后再展开矩阵，失败的单元数量会显著下降。

关键代码与解读

片段 1：QMIX 混合网络（超网络生成权重）

import torch
import torch.nn as nn

class QMixer(nn.Module):
    """QMIX 混合网络：超网络按全局状态生成权重，绝对化保证单调性。"""
    def __init__(self, n_agents=5, state_dim=32, embed_dim=32, hyper_dim=64):
        super().__init__()
        self.n_agents, self.embed_dim = n_agents, embed_dim
        # 超网络：状态到权重，两层结构是惯例，隐藏维 64
        self.hyper_w1 = nn.Sequential(nn.Linear(state_dim, hyper_dim), nn.ReLU(),
                                      nn.Linear(hyper_dim, n_agents * embed_dim))
        self.hyper_w2 = nn.Sequential(nn.Linear(state_dim, hyper_dim), nn.ReLU(),
                                      nn.Linear(hyper_dim, embed_dim))
        self.hyper_b1 = nn.Sequential(nn.Linear(state_dim, embed_dim))
        self.hyper_b2 = nn.Sequential(nn.Linear(state_dim, embed_dim), nn.ReLU(),
                                      nn.Linear(embed_dim, 1))

    def forward(self, q_agents, state):
        b = q_agents.size(0)
        q_agents = q_agents.view(b, 1, -1)                 # (B, 1, N)
        # abs 激活是单调性的实现核心：权重非负则输出对每个 Q_i 单增
        w1 = torch.abs(self.hyper_w1(state)).view(b, self.n_agents, -1)
        b1 = self.hyper_b1(state).view(b, 1, -1)
        h = torch.relu(torch.bmm(q_agents, w1) + b1)       # 第一层混合
        w2 = torch.abs(self.hyper_w2(state)).view(b, -1, 1)
        b2 = self.hyper_b2(state).view(b, 1, 1)
        return (torch.bmm(h, w2) + b2).view(b)             # 第二层汇聚为标量

解读：（1）两个超网络的输出都用 torch.abs 保证非负权重，偏置不受限制：单调性只约束权重符号，偏置取任意值不破坏 ∂Qtot/∂Qi ≥ 0。（2）权重形状按批量矩阵乘组织：第一层 (B, N, E)、第二层 (B, E, 1)，与 (B, ·, N) 的输入相称，避免最常见的维度顺序错误。（3）hyper_b1 与 hyper_b2 的隐藏层结构不同：惯例做法是 b2 多一层非线性以增强状态条件化能力。（4）复现对照点：把 abs 替换为 softplus 或 ReLU 是等价实现，但梯度行为不同，替换后要重新校准学习率；把状态输入替换为常数（即无状态条件的混合权重）就退化为 VDN 的推广形式，可用于消融。

片段 2：评估协议与运行清单

import json
import numpy as np

def evaluate_greedy(env, policy, episodes=32, base_seed=10000):
    """贪心评估：固定独立种子集，返回胜率与平均回报。"""
    wins, returns = [], []
    for k in range(episodes):
        obs, _ = env.reset(seed=base_seed + k)     # 评估种子与训练种子分离
        done, ret, term = False, 0.0, {}
        while not done:
            actions = {i: int(policy.argmax(obs[i])) for i in range(len(obs))}
            obs, rew, term, trunc, _ = env.step(actions)
            ret += sum(rew.values())
            done = all(term.values()) or all(trunc.values())
        wins.append(float(all(term.values())))     # 截断不计为胜
        returns.append(ret)
    return float(np.mean(wins)), float(np.mean(returns))

def run_manifest(cfg, seed):
    """运行清单：配置、种子与实现版本，复现审计的入口。"""
    return json.dumps({"cfg": cfg, "seed": seed,
                       "algo_commit": "value-decomp-v1"}, sort_keys=True)

解读：（1）评估种子从固定的基准值派生（base_seed + k），与训练种子完全分离：评估集固定让不同算法的对比共享同一组测试条件，这是配对比较的前提。（2）胜率只统计终止达成（term）的情节，时间上限触发的截断不计为胜；不同论文对截断的处理不同，复现时必须与原协议逐字核对，这是偏差清单里的第一项。（3）run_manifest 把完整配置与种子序列化为一行 JSON，与第 082 章记录管道对接；配置里包含算法提交号，方便定位实现层面差异。（4）policy.argmax 假设策略网络已切换评估模式（关闭 dropout、固定动作选择），调用方负责切换并在清单里注明。

常见坑

  • 只复现算法不复现协议：代码与论文结构一致，但评估回合数、贪心与否、截断处理不同，曲线不可比。修复：协议逐项对齐并写入检查表。
  • 各算法训练预算不一致：结论"某算法收敛更快"可能只是预算分配不同。修复：固定总环境步数，居中报告，附预算一致声明。
  • 种子数不足就下排序结论：三到五个种子的置信区间常重叠。修复：主结论用十个种子验证，排序结论附配对检验。
  • 死亡掩码处理混用：同一份代码里训练用置零、评估用排除，性能测量与优化目标错位。修复：掩码逻辑单点实现，训练评估共用。
  • 把调参结果当复现结果：为提高胜率触碰了惯例超参数，却仍声明"复现"。修复：维护两套配置（惯例配置与调优配置），报告中明确区分。

练习与思考

  1. 列出 VDN 与 QMIX 的组件差异清单，指出复现对照时应保持相同的最小组件集合。★
    提示
    差异只在混合结构（求和与超网络单调混合）；智能体网络、RNN、回放、目标网络、探索调度都应固定。逐项列出与论文正文无关的实现细节作为对照清单。
  2. 把评估回合数从 32 降到 8，预测胜率置信区间宽度与"算法 A 优于 B"结论稳定性的变化。★★
    提示
    区间宽度按 1/√n 放大到两倍；原显著性边缘的结论将不再稳定。验证：同一份记录按两种回合数重算区间并观察结论翻转。
  3. 设计一份实验矩阵：3 个算法 × 3 张难度递增地图 × 5 个种子，估算总环境步数与评估点数量，并说明中间结果检查点。★★
    提示
    总步数 = 3×3×5×单次预算；评估点按 25000 步间隔对齐。检查点设在单算法小地图验收通过时，避免带错误配置展开全矩阵。
  4. 设计消融实验：在 QMIX 基础上依次替换（混合权重取常数）、（状态输入置零）、（掩码逻辑改为置零），分别预测三项变化对胜率的影响方向与量级。★★★
    提示
    常数权重退化为 VDN 类加性混合，预期降幅最大；状态置零削弱条件化能力，降幅中等；掩码差异通常在数个百分点量级。三组都用相同种子集与评估协议。
  5. 写一份复现报告模板：包含验收标准两级、偏差清单六项、记录字段清单与免责声明（哪些配置偏离了论文惯例）。★★★
    提示
    模板目标是一页之内可核对：验收的量化阈值、每项偏差的检查方法、配置与论文的逐项对照。免责声明中列出所有改动及其理由，作为复现可信度的自证材料。

小结

  • 值分解系列由 IGM 条件串联：VDN 加性、QMIX 单调混合、QTRAN 松弛、QPLEX 对偶、WQMIX 加权投影，表达力与训练难度同步上升。
  • 复现三层对齐：接口、超参数、随机性；顺序不可颠倒，接口不齐时调参等于在错误基准上拟合。
  • 偏差来源六大项：测试协议、死亡掩码、奖励终止语义、难度配置、训练预算、序列截断。
  • 实验矩阵按算法、地图、种子组织；记录字段清单保证结论可回放到具体运行。
  • 验收分两级：趋势一致与量级一致；两级都达成后复现结果才能作为消融基线。
