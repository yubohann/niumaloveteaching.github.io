第三篇 · 环境与任务实践

第 047 章：多智能体游戏对战

游戏对战把多智能体协同放进高维离散动作与强对抗的框架中；本章围绕单位级决策、动作掩码与死亡掩码，说明集火战术如何在信用分配机制下自发形成。

  • 主题：离散战术决策 / 单位级信用分配
  • 关键公式：rteam = α · ΔHPenemy − β · ΔHPally + γt · 1[胜利]
  • 预计学时：65 分钟
  • 前置章节：第 046 章 多智能体协同搬运

学习目标

读完本章，应当能够把一场战术冲突写成带动作掩码的离散多智能体博弈，并解释单位级信用分配的机制。

  • 理解对战环境的建模要素：单位属性、视野与开火范围、冷却与伤害结算、增援与胜负判定。
  • 掌握动作掩码（action mask）的作用与实现方式，理解未屏蔽无效动作如何破坏策略学习。
  • 掌握团队战斗奖励的构造：血量交换项、稀疏胜负项与时间项的组合逻辑。
  • 理解单位级信用分配的难点：死亡单位、可变参数量与集中式评论家的状态设计。
  • 会分析集火（focus fire）与分散火力两种战术的收益条件，并能设计实验验证策略是否学到集火。

背景与动机

对战任务的价值在于它把部分可观测、高维离散动作与角色异质性压缩在同一环境里。

游戏对战是多智能体协同的经典检验场景，星际争霸多智能体挑战（StarCraft Multi-Agent Challenge, SMAC）是其中被引用最多的基准：每方控制一组兵种各异的单位，在局部视野下移动与攻击，胜负由单位存活状况判定。该基准的价值在于它同时包含三类难度：动作空间的组合爆炸（每个单位的动作随可见目标数增长）、部分可观测（雾战机制使观测半径有限）、以及战术层面的协同（集火、拉扯、地形利用）。

在 CTDE 训练框架中，对战任务常被用来展示集中式训练的价值：执行期每个单位只能看到局部视野，若仅依赖局部信息，单位无法协调攻击目标；训练期评论家读取全局战场状态，可以把“这次攻击对整体战局的价值”回传给单次决策。与上一章搬运任务的差异也在此：搬运的耦合通过物理约束传递，对战的耦合通过伤害与位置传递，前者连续且可微，后者由离散事件构成，信用分配只能依靠价值估计，解析梯度不可用。

核心原理

对战任务的原理由三部分组成：带掩码的离散决策、伤害交换的战术逻辑、以及单位级别的信用分配。

1. 单位、动作与掩码

每个单位每步从动作集合中选择一项：向某个方向移动、攻击某个可见敌单位、或保持不动。

Ai = { stop } ∪ { move: 4 个方向 } ∪ { attack: j ∈ Ei } ， |Ai| = 5 + |Ei| Ei 为单位 i 当前可见且可攻击的敌单位集合；动作空间的维度随视野内容变化，需要固定维度加掩码表示

动作集合的大小随战场状态变化，而神经网络的输出层维度固定，因此实现上取最大可能的动作数（例如 5 + 最大敌单位数），把当前无效的动作用掩码置为不可选。掩码在策略端的使用方式是对无效动作的对数几率加一个极大的负数，使其概率为零。若省略掩码，策略会把概率质量浪费在无效动作上，这些动作执行后等价于“不动”，策略可能学会依赖这种“隐形等待”而跳过决策，训练效率显著下降。

动作掩码参与损失计算时有两个细节。其一，熵正则化只对有效动作统计，否则无效动作的均匀分布会虚增熵值。其二，目标动作的对数几率在计算重要性比率时只取有效项，无效项不参与。这两点实现错误的表现分别是熵曲线虚高与策略早熟收敛。

2. 伤害交换与战术逻辑

战斗的宏观结果由血量交换决定，集火是压缩敌方有效火力最快的战术。

集火收益：一轮齐射把总伤害 D 集中于单目标时，敌方火力下降 ⌊ D / hpe ⌋ 个单位；均摊到 m 个目标时下降 m · ⌊ D / ( m · hpe ) ⌋ 个单位 D = wd · d 为一轮齐射的总伤害；hpe 为单个敌单位的血量；⌊·⌋ 表示向下取整，D 小于 hpe 时分散火力的击杀数为零

该式说明集火的优势来源：伤害在单个目标上累积到超过其血量时，敌方的火力立即下降一个单位；伤害分散在多个目标上时，只要没有任何目标被击倒，敌方火力保持不变。因此集火策略在目标被击杀前始终更优，直到目标的“溢出伤害”变得可观时，切换目标才更划算。策略需要学到的正是击杀阈值感知：观察敌单位剩余血量与己方总伤害，选择能被本轮齐射击杀的目标。

位置与射程构成第二层战术。攻击范围限制让单位必须靠近才能开火，靠近又增加被集火的风险，二者构成攻防取舍。地形掩码（部分格子提供掩体）进一步改变伤害系数，策略需要把地形作为观测的一部分。实现上把这些机制写成显式的伤害系数表与距离衰减函数，保证战术逻辑可被诊断：当胜率低而伤害交换比高时，说明策略位置决策有问题；交换比与胜率同时低时，问题更可能在目标选择。

3. 单位级信用分配

战斗奖励是团队级的，但决策是单位级的，二者之间的桥接由价值函数完成。

Qtot(τ, a) = fθ( Q1(τ1, a1), …, QN(τN, aN) ) τi 为单位 i 的局部观测历史；ai 为其动作；Qi 为个体价值；fθ 为混合网络，把个体价值合成为团队价值

值分解方法把团队价值拆成个体价值再混合，个体价值因此获得梯度信号，缓解团队奖励下的信用分配难题。对战场景对分解结构提出两个额外要求。第一，个体价值的输入必须包含足够的战术上下文，例如本单位剩余血量与弹药冷却，否则同一观测在不同战场态势下对应的价值差异无法表达。第二，死亡单位要从计算中移除，把其价值置零的做法会带来问题：置零在数学上仍然影响混合函数的梯度路径，移除则保持参数量随存活单位数的正确语义。工程实现通常用掩码在混合前把死亡单位的特征置零，并同步修正混合网络的权重归一化。

反事实基线（counterfactual baseline, COMA）给出另一种信用分配路径：对每个单位，固定其他单位动作，计算其各动作的期望价值，用实际动作价值与期望值之差作为优势。该量直接度量“该单位的动作相对平均水平的增益”，与集火这类协同行为兼容性高，代价是每步需要 N 次额外前向计算。

4. 集中式评论家的状态设计

训练期的全局状态包含所有单位的位置、血量、冷却与阵营信息，是策略无法在部署时获得的特权信息。

状态向量的构造遵循两条规则：单位槽位固定（例如固定最大 20 个单位，按阵营分组排序），缺失单位用掩码标记；单位属性包含可变与不变两类，不变属性（兵种类型、最大血量）常常只需编码一次。集中式评论家的输入维度因此为 O(Nmax · F)，Nmax 为最大单位数、F 为属性数。规模扩大时评论家的参数量增长线性，而策略网络保持常量规模，这是 CTDE 结构在战术场景下的直接收益。

5. 对抗多样性与课程难度

固定对手配置会让策略过拟合到特定兵种组合，评估需要覆盖多种配置。

对手建模的常用手段是逐级加难的对手池：从随机策略开始，逐步替换为经过训练的检查点，最后与当前策略自博弈。兵种组合也需要课程化：先练同兵种同数量的对称战斗，再加入数量劣势（以少打多）与兵种克制（远程对近战）。评估阶段固定一组对手检查点与随机策略，报告胜率、剩余血量比与伤害交换比三项指标，任何单项指标领先但其余落后的策略都不能判定为改进。

实现思路与设计

实现采用脚本内联的轻量战斗环境，机制参照 SMAC 的单位与战斗规则，规模控制在单机可训练的范围。

1. 环境循环与数据流

每步流程为：构造每个单位的观测与动作掩码；策略输出动作；环境按同时决策执行（攻击同时结算）；更新冷却、血量与死亡；计算战斗奖励；更新视野（雾战）；判定胜负。全局状态在策略执行后另行构造，供评论家使用。

3. 网络结构与训练要点

策略网络输入为单位自身的观测向量（血量比、冷却、可见盟友与敌单位的属性表），盟友与敌单位分别用共享编码器处理后拼接。输出层维度覆盖全部动作类型，攻击目标的候选位置按固定顺序排列，掩码屏蔽不可攻击的槽位。更新算法从值分解方法（VDN、QMIX）与策略梯度方法（MAPPO、COMA）中择一，前者的混合网络需处理死亡单位的掩码，后者用反事实基线简化信用分配。训练批次按单位展开，单位数的不一致由掩码归一化处理。

4. 与前几章的差异点

第 046 章的动作是连续力，奖励可微，信用分配通过物理耦合隐式完成；本章动作是离散选择，奖励由事件触发，信用分配必须依靠价值估计。第 045 章的安全约束用几何过滤保证，本章的合法性约束用动作掩码保证，两者的实现位置都在策略输出端，作用对象从连续速度换成离散选项。对战任务的另一处差异是对手策略的多样性：前几章的对手单一（追捕章节有一个逃逸者），本章对手是成建制的单位编队，需要联合考虑多个对手的动作，含对手建模的评论家（例如把对手动作作为附加输入）在训练后期能带来稳定收益。

关键代码与解读

三段代码分别实现动作掩码、战斗结算与奖励、以及带死亡掩码的集中式状态构造。

片段 1：动作掩码构造

import numpy as np

def build_action_mask(unit, allies, enemies, max_enemies=8,
                      move_dirs=5, attack_range=0.6):
    """构造定长动作掩码：前 move_dirs 项为移动，其余为攻击槽位。"""
    n_act = move_dirs + max_enemies
    mask = np.zeros(n_act, dtype=np.float32)
    mask[:move_dirs] = 1.0                       # 移动动作恒定可用
    for k, e in enumerate(enemies[:max_enemies]):
        d = np.linalg.norm(e["pos"] - unit["pos"])
        # 只有存活、可见且在射程内的敌单位可以成为攻击目标
        if e["alive"] and e["visible"] and d <= attack_range:
            mask[move_dirs + k] = 1.0
    # 冷却未结束时全部攻击动作禁用，保留移动以维持走位能力
    if unit["cooldown"] > 0:
        mask[move_dirs:] = 0.0
    return mask

def masked_logits(logits, mask, neg=-1e9):
    """把无效动作的对数几率压到极小值，使其概率为零。"""
    return logits + (1.0 - mask) * neg

解读：掩码与动作槽位的对应关系必须与策略输出层严格一致，移动槽位固定占用前五个位置，攻击槽位按敌单位索引排队。射程判定与可见性判定分开：不可见但射程内的单位不能攻击，这保证雾战机制的语义正确。冷却期禁用攻击而保留移动，避免单位在等待期被迫执行“无效攻击”。掩码加负值的写法使用 -1e9；负无穷会让 softmax 在数值计算中产生 NaN。熵正则化时须对掩码后分布重新归一化再统计，否则熵会被无效动作的零概率干扰。

片段 2：战斗结算与奖励

def resolve_combat(actions, units, damage=20.0):
    """同时结算攻击：先统计伤害再统一扣血，避免先后顺序带来方向性偏差。"""
    pending = {}
    for uid, act in actions.items():
        u = units[uid]
        if act["type"] != "attack" or u["cooldown"] > 0:
            continue
        tid = act["target"]
        pending[tid] = pending.get(tid, 0.0) + damage
        u["cooldown"] = 3                        # 攻击后进入冷却，节流射击
    dead = []
    for tid, dmg in pending.items():
        units[tid]["hp"] -= dmg                  # 同时伤害：无先手优势
        if units[tid]["hp"] <= 0:
            units[tid]["alive"] = False
            dead.append(tid)
    return dead

def combat_reward(prev_hp, curr_hp, prev_enemy_hp, curr_enemy_hp,
                  ally_units, enemy_units, alpha=1.0, beta=1.0, win_bonus=10.0):
    # 血量交换项：己方损失给负号，敌方损失给正号
    r = alpha * (prev_enemy_hp - curr_enemy_hp) - beta * (prev_hp - curr_hp)
    ally_alive = any(u["alive"] for u in ally_units)
    enemy_alive = any(u["alive"] for u in enemy_units)
    done = not (ally_alive and enemy_alive)      # 任一方全灭即结束
    if done:
        r += win_bonus if ally_alive and not enemy_alive else 0.0
    return r, done

解读：结算分两阶段是并发系统的标准写法，若边遍历边扣血，先被处理的攻击会获得次序优势，战术平衡被实现细节破坏。血量取队伍总量，奖励对“打谁”保持中立，主要区分“打得准”与“打得散”，让策略在集火方向上保持自由度。胜负奖励只在己方存活且敌方全灭时给出，对称实现下败方获得的终局信号为负的血量差，无需额外负奖励，保持零和结构。冷却在攻击结算时设置，保证同时攻击的单位冷却同步。

片段 3：带死亡掩码的集中式状态

def global_state(ally_units, enemy_units, max_units=10, feat=8):
    """构造定长全局状态：单位槽位固定，死亡单位置零并置掩码。"""
    s = np.zeros((max_units, feat), dtype=np.float32)
    alive_mask = np.zeros(max_units, dtype=np.float32)
    for slot, u in enumerate((ally_units + enemy_units)[:max_units]):
        if not u["alive"]:
            continue                             # 死亡单位保留槽位但不写入特征
        s[slot, :6] = [*u["pos"], u["hp"] / u["hp_max"], u["cooldown"] / 3.0,
                       float(u["team"])]
        alive_mask[slot] = 1.0
    # 掩码单列存放，便于混合网络在死亡单位处跳过梯度路径
    return np.concatenate([s.ravel(), alive_mask])

解读：槽位固定加掩码的处理让评论家输入维度恒定，网络不必处理变长序列；死亡单位槽位保留并把特征置零，维持槽位与单位身份的对应关系，价值网络可以学习“该槽位已阵亡”的语义。掩码与特征分开存放，混合网络读取掩码后在求和或加权时跳过无效槽位，避免零点参与归一化导致比例失真。血量与冷却归一化到零至一区间，与位置量级对齐，减少价值网络的尺度敏感问题。评论文家的输入因此同时包含战术信息与结构信息，训练时对战场规模变化的适应性更强。

常见坑

  • 掩码位置与动作槽位错位：掩码的索引与策略输出层的语义不一致，有效动作被禁用或无效动作被允许。症状是策略频繁输出“原地不动”且熵异常。修复：把动作编码写成单一映射表，掩码、环境执行与损失计算共用同一表。
  • 目标列表顺序不稳定：每步按字典序枚举可见敌单位，导致同一目标在不同步进入不同槽位，策略无法积累经验。症状是集火行为难以形成。修复：目标按固定单位编号排序，槽位与编号绑定。
  • 死亡单位仍参与价值计算：混合网络对死亡单位的个体价值照常输入，价值估计出现系统偏差。症状是胜率曲线在双方减员阶段明显异常。修复：死亡掩码在混合前归零，并同步修正权重归一化。
  • 奖励只看胜负：稀疏信号下训练极慢，策略在长期拉锯中无法区分优劣。症状是回合数长、胜率长期为零。修复：加入血量交换的稠密项，权重按单次击杀收益的十分之一量级设定。
  • 评估只用胜率：以数量优势换取惨胜的策略与优势稳健策略难以区分。修复：同时报告伤害交换比与剩余血量比，三个指标联合判断，并固定多组对手配置。

练习与思考

  1. 计算题：单次伤害 20、目标血量 100、己方 5 个单位同轮齐射，必须多少个单位集火同一目标才能在本轮造成击杀？剩余伤害如何处理更划算？★
    提示
    需要 5 个单位全部命中同一目标（100/20 = 5）。若只有 4 个可用，则需考虑冷却轮转，使次轮齐射刚好完成击杀，避免溢出伤害浪费。
  2. 推导题：证明在两队各单位血量相同、伤害相同时，先完成一次击杀的一方获得不可逆优势，并给出该优势的量化表达式。★★
    提示
    击杀后对方火力下降一个单位，此后每轮齐射的伤害差为固定值，优势随时间线性放大。可把优势写为“每轮多出的伤害乘以剩余回合数”。
  3. 改参数并预测：把冷却从 3 步改为 1 步（射击更快），预测集火收益与位置战术的相对重要性变化，说明哪种行为会先被策略掌握。★★
    提示
    射击频率提高后击杀窗口频繁出现，集火收益放大，位置调整的边际价值下降。策略通常先学会集火，因为其收益即时可见，走位需要更长的信用链。
  4. 设计题：为雾战设计观测构造方式，说明“看见但不能打”与“能打但看不见”两类状态如何编码，并给出验证观测正确性的单元测试思路。★★★
    提示
    观测中分别保存可见性与可攻击性标志，两者独立于距离属性。单元测试构造三种几何关系（视野内射程外、射程内视野外、两者兼有）逐一核对标志位。
  5. 实验设计：设计实验验证策略是否学到集火，给出统计口径与干扰因素控制方式，说明什么结果支持“集火由信用分配驱动”的结论。★★★
    提示
    统计每轮齐射命中同一目标的比例与击杀延迟。控制变量包括对手配置与随机种子。若换用反事实基线后集火比例上升，而改变奖励结构影响不大，则说明信用分配机制是主要驱动因素。

小结

  • 对战任务的建模要素是单位属性、视野与射程、冷却与伤害结算，动作空间用固定维度加掩码表示。
  • 动作掩码保证无效动作概率为零，实现时与动作编码表严格对应；死亡单位的槽位保留并单独存放掩码。
  • 集火战术的收益来自击杀阈值效应：在击杀未达成前，分散伤害不降低敌方火力，策略需要学习击杀窗口的识别。
  • 信用分配由值分解混合网络或反事实基线承担，评论家使用全局状态并在训练期补偿执行期的局部视野。
