第 090 章：投票机制

多方协同决策不一定需要谈判：本章把联合动作选择建模为社会选择问题，比较相对多数、Borda 计分、批准投票与 Condorcet 胜者四类规则，用 Arrow 不可能定理界定规则的边界，并给出基于 Q 值偏好的投票协调器实现。

  • 主题：社会选择理论（Social Choice Theory）/ 联合动作协调
  • 关键公式：Borda 计分 Σ(m − rank)、Condorcet 胜者的两两多数条件、Arrow 三条件冲突
  • 预计学时：55 分钟
  • 前置章节：第 089 章

学习目标

  • 理解社会选择框架：候选人、偏好剖面、投票规则与获胜者的形式定义。
  • 掌握相对多数、Borda 计分、批准投票、Condorcet 胜者四种规则的计分方式与差异。
  • 理解 Condorcet 悖论与 Arrow 不可能定理的表述，能说明它对机制设计的约束。
  • 学会在 MARL 中用 Q 值构造偏好序，并实现加权投票的联合动作选择。
  • 能设计平局打破规则与候选集预筛方案，分析策略性投票的风险。

背景与动机

第 089 章的协商机制适合两三方之间的利益分配，智能体数量继续增加时，逐轮议价的通信与轮数开销按参与方数量增长。当决策问题退化为"从有限个联合方案里挑一个"时，投票（Voting）提供了更轻量的替代：每个智能体报告自己对方案的偏好序，协调者用固定规则聚合出获胜方案。投票把复杂的联合决策压缩成一次偏好收集加一次计分，通信量可控、结果可复现，适合执行频率高、单步决策价值有限的场景。

本章的视角是"联合动作选择即社会选择"：候选是联合动作或动作组合，智能体的偏好来自自身 Q 值或价值估计。这一视角带来两个直接收益：可用社会选择理论的成熟结论分析规则性质；把 Q 值的学习与动作的聚合解耦，各智能体的价值网络可以独立训练。代价是规则本身引入新的操纵空间：智能体可能虚报偏好获益，Arrow 与 Gibbard-Satterthwaite 的结果表明这类风险无法完全消除，只能针对场景选择较稳健的规则。

核心原理

1. 社会选择的基本框架

设候选人集合 A（|A| = m），选民集合 N（|N| = n）。每个选民 i 有一个严格偏好序 ≻i，全体偏好序构成偏好剖面。投票规则是从偏好剖面到获胜者的映射 f: {≻i} → A。四种常用规则：

规则计分方式特点
相对多数（Plurality）统计各候选获得的第一名票数简单快速；忽视非头名偏好，容易选出"最多人不反感"之外的分裂结果
Borda 计分第 k 名得 m − k 分，总分最高者胜利用完整偏好序；对名次操纵敏感度居中
批准投票（Approval）选民批准若干候选，得票最多者胜只收集二元信息，通信量最小；阈值选择影响结果
Condorcet 方法两两多数比较，全胜者当选理论性质优雅；胜者可能不存在

规则选择依赖信息结构：智能体能给出完整排名时 Borda 与 Condorcet 可用；只能给出"可接受/不可接受"判断时用批准投票；通信预算极小时用相对多数。MARL 中 Q 值天然给出完整排名，因此 Borda 与 Condorcet 是默认候选。

2. Condorcet 悖论与不可能定理

Condorcet 悖论指多数关系可能出现循环：三选民三候选的偏好 a ≻ b ≻ c、b ≻ c ≻ a、c ≻ a ≻ b 中，两两比较得到 a 胜过 b、b 胜过 c、c 胜过 a，无候选全胜，Condorcet 胜者不存在。悖论出现的条件是偏好分布足够"旋转对称"，在智能体偏好相关性高的协作任务中较少见，在对抗与异构偏好场景中显著。

Arrow 不可能定理把这一问题升格为结构性结论：在至少两个选民、至少三个候选的设定下，同时满足以下三条的投票规则不存在：

  • 帕累托原则：全体认为 a 优于 b，则整体排序中 a 优于 b；
  • 无关备选独立性（IIA）：a 与 b 的相对排序只依赖选民对 a、b 的偏好，不受其他候选进出影响；
  • 非独裁：不存在单个选民的决定性排序完全决定整体排序。

Gibbard-Satterthwaite 定理进一步指出：三候选以上、非独裁的投票规则必然可被策略性投票操纵。两条定理的共同含义是：操纵风险无法完全消除，机制选择的目标是在规则、信息与场景之间取平衡。

3. 基于 Q 值的偏好与投票协调器

把投票接入 MARL 的具体映射：候选集是联合动作的候选集合（可先按每个智能体的局部 Q 值预筛 top-k 再组合）；智能体 i 对候选 c 的效用是 Qi(oi, ci)，偏好序按效用降序排列；协调者收集排序后按规则计分。加权版本允许按信任度或价值敏感度给选票加权重：

score(c) = Σi ∈ N wi · ( m − ranki(c) )，获胜候选 c∗ = argmaxc score(c) ranki(c) 是候选 c 在智能体 i 偏好序中的名次（0 起）；wi 为选票权重，缺省全为 1

通信量核算：每个智能体发送完整排名需要 O(m log m) 比特（等价于排列的编码长度），批准投票只需 m 比特，相对多数只需 log m 比特。候选集预筛把 m 从联合动作空间大小压到每个智能体 top-k 的并集规模，是控制通信与计算的关键一步。

4. 平局打破与操纵风险

平局打破规则必须是确定性的并写入协议：常用的字典序（按候选编号）打破简单但不公平；按价值敏感度打破（平局候选交给价值最高的智能体决定）更符合任务结构。跳变的打破规则会成为操纵点：智能体学会制造平局再依赖打破规则获益。把打破规则固定并公开，是把操纵空间压缩到"偏好虚报"这一维度的必要前提。虚报风险本身无法根除，但排序型规则（Borda、Condorcet）比计分型规则对小幅虚报更稳健，因为虚报需要同时承诺一套完整排序的一致性。

5. 与协商、市场的分工

三种机制在信息与目标上互补：投票聚合离散偏好、目标是一次性选择；协商允许连续报价、目标是分配比例；市场用价格同时完成选择与分配（下一章展开）。选择标准按决策频率与代价：高频低价值决策用投票，低频高价值分配用协商，资源可分割且价值可比较时用市场。

实现思路与设计

投票协调器作为独立模块嵌入执行期：

  1. 候选生成：每个智能体按局部 Q 值给出 top-k 动作，笛卡尔组合后去重，得到候选联合动作集合。
  2. 偏好交换：各智能体对每个候选计算效用（自身 Q 值），生成排名并经信道发送。
  3. 聚合：协调者按选定规则计分，平局按固定规则处理，输出获胜候选。
  4. 执行与学习：各智能体执行自身分量；训练中使用集中式 critic 估计联合价值，投票规则本身的参数（权重、阈值）可通过外层搜索调优。

与第 089 章的差异点：协商是同步的逐轮交互、面向连续分配；投票是一次性的偏好聚合、面向离散选择。投票的通信轮数恒为一轮，延迟上界确定，适合高频控制环。

设计决策：为什么先做本地预筛，再对缩小后的候选集投票？

联合动作空间大小是 |Ai|N，对每个智能体只保留局部 top-k 动作后，候选集大小降至 kN 量级，通信与计算都从指数级压力降为可控量级。预筛的理论代价是可能排除全局最优候选，但在价值函数可靠时，被排除的候选在任一智能体视角都劣于保留候选，损失有限。k 的选择是效率与最优性之间的直接旋钮。

关键代码与解读

片段 1：相对多数与 Borda 计分

def plurality(rankings):
    """相对多数：统计各候选获得的第一名票数。"""
    tally = {}
    for order in rankings:                    # order 是候选列表，按偏好降序
        top = order[0]
        tally[top] = tally.get(top, 0) + 1
    return tally

def borda(rankings, candidates):
    """Borda 计分：第 k 名获得 m - k 分，总分最高者胜。"""
    scores = {c: 0 for c in candidates}
    m = len(candidates)
    for order in rankings:
        for rank, c in enumerate(order):
            scores[c] += m - rank             # 名次越靠前得分越高
    return scores

# 经典例：4 人选 a>b>c、3 人选 b>c>a、2 人选 c>b>a
R = [["a", "b", "c"]] * 4 + [["b", "c", "a"]] * 3 + [["c", "b", "a"]] * 2
C = ["a", "b", "c"]
print(plurality(R))          # {'a': 4, 'b': 3, 'c': 2}：a 赢得相对多数
print(borda(R, C))           # {'a': 17, 'b': 21, 'c': 16}：b 赢得 Borda

解读：（1）同一个偏好剖面下两种规则给出不同获胜者，差异来自规则本身：相对多数只看头名，Borda 利用完整排名，b 在大量选民中是第二名因而 Borda 得分最高。（2）本例子中 b 同时是 Condorcet 胜者（对 a 得 5 票、对 c 得 7 票），说明 Borda 在该剖面上与 Condorcet 方向一致；构造两者背离的例子需要更细的偏好设计。（3）两个函数都返回完整计分表，获胜者选择与平局处理交给调用方，便于调试分析；返回值是字典，与第 082 章的记录管道相容。

片段 2：基于 Q 值的加权投票协调器

def vote_joint_action(q_tables, candidates, weights=None, rule="borda"):
    """按各智能体的 Q 值排序构造偏好，投票选出联合候选动作。"""
    rankings = []
    for q in q_tables:                        # q: 候选到估计价值的映射
        rankings.append(sorted(candidates, key=lambda c: -q[c]))
    weights = weights or [1.0] * len(rankings)
    tally = {c: 0.0 for c in candidates}
    m = len(candidates)
    for w, order in zip(weights, rankings):
        if rule == "plurality":
            tally[order[0]] += w              # 仅头名计加权票
        else:
            for rank, c in enumerate(order):
                tally[c] += w * (m - rank)    # Borda 名次分乘选票权重
    # 平局用候选自身作第二排序键：固定且确定，避免随机跳变
    best = max(candidates, key=lambda c: (tally[c], c))
    return best, tally

# 三智能体各给出候选排名，等权 Borda 选出协调动作
qs = [{"go_a": 2.0, "go_b": 1.0, "wait": 0.5},
      {"go_a": 0.2, "go_b": 1.5, "wait": 1.0},
      {"go_a": 1.8, "go_b": 1.2, "wait": 0.3}]
print(vote_joint_action(qs, ["go_a", "go_b", "wait"]))

解读：（1）偏好由 Q 值排序生成，避免直接用不同智能体的原始 Q 值相加：各智能体的价值尺度不同，直接相加会被尺度大的智能体主导；排序后只保留相对信息，这正是社会选择框架的用意。（2）权重参数支持异构智能体：价值估计更可靠的智能体（例如观测更完整）可以赋更高权重，权重本身属于协议的公开参数。（3）平局用 (tally[c], c) 元组比较，第二键固定，行为确定可复现；示例中三智能体对 go_a 与 go_b 的偏好交错，Borda 计分选出唯一获胜者。（4）返回计分表供评估使用：分布过于平坦（计分接近）说明偏好冲突严重，可作为触发协商机制的信号。

常见坑

  • 平局规则未定义或随机化：行为不可复现，评估方差被凭空放大，还可能被策略利用。修复：固定确定性的打破规则并写入协议文档。
  • 直接比较跨智能体的原始 Q 值：价值尺度不同导致聚合被单方主导。修复：先转成排名或按各自尺度归一化再聚合。
  • 候选集未预筛：联合动作空间指数增长，投票的通信与计算开销失控。修复：本地 top-k 预筛后再组合，k 用消融确定。
  • 忽视策略性投票：智能体学会虚报偏好提升自身份额，整体回报受损。修复：选择排序型规则、固定打破规则，并在评估中比较诚实报告与最优虚报的效用差。
  • 把 Arrow 定理理解为"投票无用"：定理限定的是同时满足全部性质的完美规则不存在。修复：按场景列出必须满足的性质清单，选择在该清单上代价最小的规则。

练习与思考

  1. 对正文的经典偏好剖面计算 Condorcet 两两比较结果，验证 b 是 Condorcet 胜者；再构造一个三候选循环偏好剖面。★
    提示
    循环例：a≻b≻c、b≻c≻a、c≻a≻b 各一票，两两比较分别得到 a 胜 b、b 胜 c、c 胜 a。三候选三选民的规模即可构造悖论。
  2. 把投票规则的权重从等权改为 [1.0, 1.0, 0.5]，预测协调动作的选择变化，并说明权重偏差超过多少会系统性改变结果。★★
    提示
    第三个智能体权重减半后，前两名的竞争格局改变；权重偏差的影响取决于该智能体偏好与多数方向的一致程度。验证：扫描权重比例画出获胜候选的变化边界。
  3. 推导：m 个候选的完整偏好排名最少需要多少比特编码？与只发送头名相比，Borda 方案的通信量倍数是多少（m = 5 时）？★★
    提示
    排列的日志下界约 log2(m!)；m = 5 时约 6.9 比特，相对 log25 ≈ 2.3 比特的头名编码是约 3 倍，换取完整排名信息。
  4. 设计实验：在四智能体协作任务中比较（集中式 argmax 联合 Q）、（相对多数投票）、（Borda 投票）三种协调方式，报告回报、每步通信比特数与偏好分歧率。★★★
    提示
    偏好分歧率 = 各智能体头名不一致的步数占比。集中式 argmax 无通信但需要访问全体 Q 值（执行期违规），验证投票方案能否在分布式约束下逼近其表现。
  5. 设计策略性投票实验：让一个智能体用两种偏好报告策略（诚实、最优虚报模拟退火搜索），测量其单方效用增益与团队回报损失，验证 Gibbard-Satterthwaite 定理在本任务中的表现。★★★
    提示
    最优虚报在固定其余偏好下枚举排列搜索；团队损失用相同种子对照。若单方增益为正且团队损失显著，说明当前规则需要换用排序型替代。

小结

  • 投票把联合动作选择建模为社会选择：候选人、偏好剖面与聚合规则三要素。
  • 相对多数、Borda、批准投票、Condorcet 方法在信息利用与通信量上各有取舍，Q 值场景默认 Borda 与 Condorcet。
  • Condorcet 悖论显示多数关系可能循环；Arrow 与 Gibbard-Satterthwaite 定理表明完美且不可操纵的规则不存在。
  • MARL 投票协调器由候选预筛、偏好交换、规则计分三部分组成，平局规则必须固定且公开。
  • 评估除回报外要报告通信比特数、偏好分歧率与操纵敏感度。
  • 下一章进入机制序列第四类：市场机制，讨论拍卖、均衡价格与出清算法如何同时完成资源选择与分配。
