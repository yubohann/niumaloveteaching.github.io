第一篇 · CTDE 基础与核心算法

第 005 章：全局状态与局部观测分离

框架已经确立，接下来是信息设计的接地工作：全局状态从哪里来、局部观测怎么编码、如何检测"状态不足"与"信息泄漏"两类相反故障。学完本章，你能为任意协作任务写出状态与观测的构造函数，并用可执行的检验确认它们各守其位。

  • 主题：状态表示 / 信息充分性与泄漏检测
  • 关键公式：πi(ai | τi) 与 Q(s, a) 的输入分离；状态充分性条件
  • 预计学时：45 分钟
  • 前置章节：第 004 章

学习目标

  • 理解全局状态与局部观测在信息角色上的分工，以及二者各自对应的函数依赖约束。
  • 掌握全局状态的三种来源：仿真真状态、联合观测拼接、特征工程构造，及其充分性条件。
  • 理解感知别名（perceptual aliasing）导致的观测不足问题，掌握历史记忆的引入时机。
  • 会实现固定的观测归一化、带掩码的观测编码，以及批量化的信息泄漏检测（patch test）。
  • 能区分"状态不足"与"状态泄漏"两类故障的症状，并给出各自的诊断与修复路径。

背景与动机

第 003 章的框架规定执行策略依赖 τi、集中式评论家依赖 (s, a)。公式里 s 是现成的符号，落到具体任务时却需要回答一连串工程问题：环境能否提供真状态；若只能提供各智能体的观测，拼接起来能否充当状态；观测编码要不要归一化、用谁统计量；历史记忆何时必须引入。这些问题回答错误产生的故障方向相反：状态不足让评论家学到偏差的价值面，信息泄漏让离线评估虚高但在部署中失效。

第 001 章的 Dec-POMDP 已指出理论根源：状态 s 对执行期不可见，仅训练期可见；局部观测 oi 是状态的不完整投影，投影会丢失区分性。本章把这两个事实落成设计流程与检验工具。信息设计是 CTDE 各算法共享的底座，第 015、016 章的注意力与图通信都已假设状态表示被正确构造，第 018 章将在此基础上系统处理记忆。

核心原理

本节给出信息分离的严格表述、状态构造的充分性条件、感知别名的机理，以及两类故障的检验原理。

1. 信息角色与函数依赖

训练与执行两条通路对信息的依赖可以写成一组函数约束：

执行：ai ∼ πi(· | τi,t)，τi,t = (oi,1, ai,1, …, oi,t)；
训练：Q(s, a) 与 A(s, a)，s ∈ S 为状态，a 为联合动作 依赖关系是函数级的：πi 的输入集合中不允许出现 s、oj≠i、aj≠i；Q 可以依赖任意训练期可观测量

一个关键事实：训练期可见的状态是仿真器的实现细节，执行期的可用信息由部署环境决定；设计时以执行侧为基准构造观测接口，训练侧允许更宽。若某特征（例如每个智能体到目标点的全局坐标）在部署时无法送达每个智能体，它就只能进入训练侧，进入执行侧即构成泄漏。

2. 全局状态的构造与充分性

状态的三种来源按可信度排序：

  • 仿真真状态。环境内部维护的全部变量，例如所有智能体位置与任务时钟。它是标准选择，前提是训练环境模拟器确实拥有这些变量。
  • 联合观测拼接。当环境只暴露观测时，用 oall = (o1, …, oN) 作为状态代理。其充分性依赖观测函数的区分能力：
若观测函数 O 满足：∃ s ≠ s′ 时 O(s) = O(s′)，则拼接观测无法区分 s 与 s′；
当且仅当 O 为单射（不同状态产生不同联合观测）时，oall 与 s 信息等价 随机观测下改用分布 p(o | s)：当分布族 {p(· | s)} 两两可分时信息等价，实践中退而接受"近似充分"
  • 特征工程构造。对既有变量做线性组合、相对距离、可见性掩码等变换，目标是让状态尽量接近"马尔可夫充分统计量"。特征越少但越切题，评论家学习越快；特征冗余会加大输入维度与估计方差。

三种来源的取舍列成对照表：

状态来源信息量充分性条件实现成本典型风险
仿真真状态最全自身即定义，无需附加条件最低，直接取用训练仿真与部署任务的变量集不一致时状态失去意义
联合观测拼接取决于观测函数观测函数在可达状态上单射低，拼接即得对称场景下别名使残差偏高
特征工程构造可控，可能冗余或缺失需实验验证，用 TD 残差判据高，设计、验证、维护均要投入特征选择失当引入偏差或泄漏

用协作位移任务核对单射条件。基线观测为 oi = (pi / 5, (5 − pi) / 5)，两个分量都只是自身位置的线性函数，存在冗余，但对 pi ∈ {0, 1, …, 5} 逐一取值为 (0, 1)、(0.2, 0.8)、(0.4, 0.6)、(0.6, 0.4)、(0.8, 0.2)、(1, 0)，两两不同，拼接后可完全恢复 (p1, p2)，单射成立。把目标从线端移到中点（目标在位置 3）并把观测改为只含绝对距离 |3 − pi| / 5 后，位置 2 与位置 4 都给出 0.2，位置 1 与位置 5 都给出 0.4，单射被破坏，拼接观测无法区分对称位置，充分性检验的残差随之上升。该例子给出一条观测设计准则：距离类特征对单点目标通常可逆，一旦场景具有左右对称结构，必须补充方向特征，带符号距离或位置本身都是可行的补法。

充分性的实践判据：在专家策略数据上训练以 s 为输入的价值函数，若时序差分残差能降到即时奖励的噪声量级，认为状态近似充分；否则说明存在被忽略的隐藏变量。状态不足在价值函数层面可以定量刻划：设动力学依赖 s 与不可见变量 h，评论家能学到的极限是对 h 边缘化后的价值，残差下界由隐藏变量与随机转移的联合条件方差决定：

Q̄(s, a) = Σh p(h | s) 𝔼 [ R(s, a, h) + γ V̄(s′) ]，残差下界 = 𝔼s, a Var( R(s, a, h) + γ V̄(s′) | s, a ) 设计表中阈值 0.01 在奖励与转移都确定的仿真任务上对应约 0.1 的均方根价值偏差（√0.01）；任务存在隐藏变量时残差无法降到该水平，检验失败应先排查隐藏变量，加大网络容量只会拟合噪声

把该检验加入数据处理脚本，可在算法实验开始前拦截大部分状态设计缺陷。

3. 感知别名与历史的必要性

局部观测丢失的不仅是状态数值，还包括区分性。考虑两条平行走廊，智能体位于任一走廊时观测相同（走廊内部特征一致），目标仅在其中一条走廊的尽头。观测 o 对应两个状态，最优动作在其中一个是向左、另一个是向右，任何确定性策略 π(a | o) 在这两个状态上必须给出相同动作，至少在一个状态上是错的。这个现象称为感知别名（perceptual aliasing）。

消解别名只有两条路径：补充观测特征（把走廊标识加入观测，需要环境设计配合），或引入历史记忆。历史编码把 τi,t 压缩为隐藏状态：

hi,t = fθ(hi,t−1, oi,t)， πi(ai | hi,t) = πi(ai | τi,t) fθ 为循环网络（如 GRU）；历史进入后策略输入从 o 升格为 τ，别名可通过"到过哪个路口"的轨迹上下文消除

别名的代价可以量化到极限。两状态共享一个观测、最优动作相反、两个状态出现概率相等时，任何以该观测为输入的策略（确定或随机）在两个状态上输出相同的动作分布，最优选择是把概率集中在一个动作上，成功率上限为 0.5。若在进入走廊前有一次可区分的观察，并且智能体把它记入历史，历史编码使策略在两个状态下能够输出不同动作，成功率上限升到 1.0。0.5 到 1.0 的全部差距都来自记忆，这是第 001 章"历史才能消解歧义"的具体数值形态，也是第 018 章正式处理记忆机制的动机。

引入记忆的代价：数据必须按序列组织，训练改为片段采样（第 018 章展开）；隐藏状态在多环境并行采样时需要逐环境维护。基线实现先不带记忆，把"加记忆"作为对别名敏感任务的对照变量。

4. 两类故障与检验原理

状态不足（欠信息）的症状是评论家 TD 误差居高不下、价值面随训练方差的抖动放大，策略改进受限。信息泄漏（过信息）的症状是训练期指标优秀、离线评估（仅本地观测）明显回退，两套输入的差距就是泄漏的可测量信号。两类的检验都基于同一个操作：对信息做置换，观察输出变化。执行侧检验（patch test）：固定智能体 i 的观测历史，替换其他智能体观测、全局状态、以及任何候选泄漏量为随机值，策略输出分布应逐点不变。训练侧检验（充分性检验）：固定 s 以外的信息，观察以 s 为输入的价值函数能否复现 TD 残差下限。两个检验方向相反，合起来把信息设计夹在中间：充分但不泄漏，就是状态表示设计的操作目标。

实现思路与设计

本节把信息设计落成一份可执行清单：状态构造函数、观测编码器、归一化策略、以及两个检验脚本。

设计项取值（基线）作用与依据
状态来源仿真真状态（_state 接口）信息最全，作为基线与后续"伪状态"实验的对照组
观测编码固定边界线性归一化到 [0, 1]任务坐标范围先验已知，固定边界在训练与评估间完全一致
历史长度0（当前实现基于单帧观测）基线任务无别名；记忆作为第 018 章的对照变量引入
掩码处理无（N 固定且全部存活）死亡智能体与变长队伍的掩码在第 012 章引入
充分性检验TD 残差 ≤ 0.01（奖励量级为 1）阈值按奖励尺度设定；超过则检查状态构造
泄漏检验patch test 批量版本，每次训练前运行把泄漏检测固化为固定流程，无需依赖人工抽查

与第 004 章的衔接：网络结构、优化器、超参数不变，新增的全部工作在数据入口与检验环节。本章的产物是一组数据整形函数与断言，它们将随课程一直复用：后续每一章的评论家都消费同一个 StateBuilder，演员都消费同一个 ObsEncoder。

设计决策：基线选择固定边界归一化

运行统计归一化（running mean/std）随训练更新统计量，若同一缩放被用于执行特征，训练后期与评估期的输入分布不再一致，属于隐蔽的泄漏源；若只用于训练期，又需要一条独立的执行期缩放通路，实现复杂度上升。任务坐标范围已知时，固定边界的实现最短、语义最清晰，且天然满足"训练与执行同分布"。坐标范围未知或跨任务迁移的场景在第二篇第 026 章处理。

关键代码与解读

片段 1：状态与观测的统一构造

import numpy as np

class StateBuilder:
    """集中侧: 提供评论家输入; 允许消费全部训练期可观测量。"""
    def __init__(self, mode="true_state"):
        self.mode = mode                     # true_state | concat_obs 两档对照

    def build(self, obs, env_state):
        if self.mode == "true_state":
            # 仿真真状态: 训练环境直接暴露, 语义最明确
            return np.asarray(env_state, dtype=np.float32)
        # 伪状态: 联合观测拼接, 充分性依赖观测函数的区分能力
        obs_all = np.asarray(obs, dtype=np.float32)  # (N, obs_dim)
        return obs_all.reshape(-1)                   # 展平为定长向量

class ObsEncoder:
    """执行侧: 只接受单个智能体的观测, 归一化边界固定。"""
    def __init__(self, obs_dim, lo=-1.0, hi=1.0):
        self.lo, self.hi = lo, hi            # 任务坐标先验范围, 评估期完全复用

    def encode(self, obs_i):
        # 线性映射到 [0,1]: 无运行统计, 训练与执行同分布
        return (np.asarray(obs_i, dtype=np.float32) - self.lo) / (self.hi - self.lo)

解读：两个类把"训练侧允许什么、执行侧允许什么"编码进类型系统。（1）StateBuilder 持有 mode 开关，让"真状态"与"拼接观测"两档可以一键切换，这是第 005 章实验协议的核心变量。（2）ObsEncoder 的归一化边界是构造参数，训练与评估共用同一实例语义；若把统计更新逻辑藏进 encode，就会引入随时间变化的缩放，评估期无法复现。（3）两个类都没有对方的引用，状态与观测在类型层面互不可见，比注释约定更可靠。

片段 2：充分性检验

def sufficiency_check(env, sb, n_rollouts=200, threshold=0.01):
    """评估状态代理的充分性: 以 s 为输入的值函数 TD 残差应接近噪声下限。"""
    import torch
    from torch import nn
    n_in = env.n * env.obs_dim if sb.mode == "concat_obs" else env.state_dim
    critic = nn.Sequential(nn.Linear(n_in, 64), nn.ReLU(), nn.Linear(64, 1))
    opt = torch.optim.Adam(critic.parameters(), lr=1e-3)
    residuals = []
    for _ in range(n_rollouts):
        obs, s = env.reset()
        done = False
        while not done:
            a = [np.random.randint(env.n_actions) for _ in range(env.n)]
            s_t = torch.tensor(sb.build(obs, s), dtype=torch.float32)  # 当前状态
            nobs, ns, r, done = env.step(a)          # 推进环境一步
            ns_t = torch.tensor(sb.build(nobs, ns), dtype=torch.float32)
            # 单步 TD 目标: 随机策略下估计状态的贝尔曼残差
            y = r + 0.95 * (1.0 - float(done)) * critic(ns_t).detach()
            loss = (critic(s_t) - y) ** 2
            opt.zero_grad(); loss.backward(); opt.step()
            residuals.append(float(loss))
            s, obs = ns, nobs
    mean_res = float(np.mean(residuals[-50:]))   # 取收敛段尾部均值
    return mean_res, mean_res <= threshold        # False 时检查状态是否遗漏变量

解读：检验思路是"假装状态已经充分，看残差能否压到噪声水平"。（1）使用随机策略采集，不依赖任何尚未训练的策略，这让检验可以在算法实验之前独立执行。（2）threshold 按奖励尺度标定：奖励量级为 1 时取 0.01，若奖励量级为百位则等比放大。（3）返回布尔值便于挂进实验前置流程；检验失败时的第一修复动作为审查状态构造函数，第二动作为检查环境是否隐藏了影响奖励的变量。

片段 3：批量泄漏检测（patch test）

import torch

def patch_test(actor, obs_batch, noise=1.0, n_patches=8, atol=1e-6):
    """执行侧泄漏检测: 固定本地观测, 扰动一切非本地量, 策略输出必须不变。"""
    obs_i = torch.as_tensor(obs_batch, dtype=torch.float32)
    with torch.no_grad():
        base = actor(obs_i).probs                     # 基准分布 (B, n_actions)
        for _ in range(n_patches):
            # 对同一批本地观测重复前向, 期间变化任何外部状态都不应影响输出;
            # 实现时把全局状态/队友观测作为可选输入传入全局缓存, 此处以重复前向
            # 覆盖"随机状态注入"类泄漏, 外部张量篡改类由集成脚本单独注入后重放
            probs = actor(obs_i).probs
            if not torch.allclose(base, probs, atol=atol):
                return False, "actor 输出随非本地量变化, 存在泄漏"
    return True, "pass"

解读：patch test 的可执行版本遵循"扰动非本地量、观察本地输出"的模板。（1）这里以重复前向覆盖随机性注入类泄漏，因为随机噪声源（如未固定的 Dropout、随机采样层）大多表现为输出不可复现；对张量篡改类泄漏，集成脚本需要在两次前向之间替换全局缓存后重放。（2）断言用 allclose 逐点比较，直接比较动作会掩盖分布层面的依赖。（3）返回文字诊断信息让失败可定位。把该函数放进训练启动流程，泄漏从"事后调试"变为"前置拦截"。

常见坑

  • 运行统计归一化直接暴露给执行侧。症状：评估分布与训练分布缓慢偏离，长训练后回退明显。原因：执行特征的缩放随训练更新而变化。修复：执行侧使用固定边界或冻结的统计量；统计更新只允许出现在训练侧通路（第 026 章给出隔离实现）。
  • 把回报到当前步（reward-to-go）加入状态。症状：训练期评论家损失极低，策略评估全面失真。原因：回报是马尔可夫决策过程里未来的函数，进入状态破坏贝尔曼结构的自洽性。修复：状态只保留当前时刻可观测量；回报归于目标值一侧。
  • 观测别名误诊为探索不足。症状：提高探索率、延长训练均无效，策略在特定观测上反复摇摆。原因：同一观测对应不同最优动作，确定性策略容量上无法适配。修复：确认别名后引入历史记忆或扩展观测特征，参考第 018 章的记忆改造流程。
  • 混淆观测与状态的统计量。症状：评论家输入维度与状态维度不符，或行为评估时形状错误。原因：构造函数把拼接观测当成真状态反复套用。修复：在类接口层面固定 state_dim 与 obs_dim 两个常量，所有构造路径复用同一常量。
  • 泄漏检验只测动作不测分布。症状：检测通过但评估仍回退。原因：泄漏在低温度策略下不改变 argmax，只改变概率质量。修复：比较完整概率分布（或 logits），容差设到 1e-6，动作层面的比较仅作为冗余检查。

练习与思考

  1. 构造一个两状态、两观测的感知别名例子：写出状态集合、观测函数与两个状态下的最优动作，说明任何确定性策略至少在一个状态上犯错。★
    提示
    两条走廊例子即可：s1（左走廊）最优动作向左，s2（右走廊）最优动作向右，O(s1) = O(s2)。确定性策略在两个状态输出同一动作，必错其一；引入"上一动作"等历史特征可区分。
  2. 把 StateBuilder 的 mode 从 true_state 改为 concat_obs，在协作位移任务上预测充分性检验的残差变化，并解释任务中观测函数是否单射。★
    提示
    协作位移任务的观测由自身位置与到目标的有符号距离组成，联合拼接可恢复全部位置，单射成立，残差与真状态档接近。把目标移到线段中点并把观测改为只含绝对距离后，对称位置产生相同观测，拼接不再单射，残差上升，可用于对照。
  3. 推导：在确定性观测函数下，证明"联合观测拼接构成状态充分统计量"当且仅当观测函数在可达状态上为单射；并说明随机观测下该条件的放宽形式。★★
    提示
    充分性要求由 oall 唯一确定 s，单射直接给出；反之若存在碰撞则两个状态同一观测，任何函数都无法区分。随机观测下换成"观测分布族两两可分"，即不存在两个状态产生相同的观测分布。
  4. 设计实验：对同一训练好的演员，分别在 (a) 单帧观测、(b) 四帧观测堆叠、(c) GRU 历史编码 三种输入下评估别名任务的成功率。预测排序并说明数据组织方式的差异。★★
    提示
    预期 (b)、(c) 显著高于 (a)，且 (c) 在长程依赖任务上领先。数据组织：帧叠扩维、无需序列采样；(c) 需按回合切片并处理隐藏状态，训练成本更高。
  5. 设计题：为 patch test 写一份集成方案，要求覆盖三类泄漏源：随机性注入、全局缓存篡改、归一化统计共享。给出每类的注入方法、检测点与判据。★★★
    提示
    随机性注入：重复前向比较分布；缓存篡改：前向间替换全局张量重放；统计共享：跨批改变统计基准并断言执行特征不变。判据统一取"固定本地输入时输出逐点一致"，与第 003 章布局一致。

小结

  • 信息分离是函数级约束：πi 只依赖 τi；Q 与 A 可依赖任何训练期可观测量，包括状态与联合动作。
  • 状态来源三档：真状态、联合观测拼接（充分性依赖观测单射性）、特征工程构造；充分性可用 TD 残差作实践判据。
  • 感知别名要求引入历史记忆或扩展观测特征；基线实现先不带记忆，把记忆作为独立对照变量。
  • 两类相反故障：状态不足表现为残差高与改进受限，信息泄漏表现为评估回退；patch test 与充分性检验合围。
