第三篇 · 环境与任务实践

第 050 章：多智能体交通信号控制

交通信号控制把每个路口看作一个决策单元；本章推导排队动力学与相位压力的定义，解释压力均衡为何同时改善本路口与邻居，并给出干道协调的观测与奖励设计。

  • 主题：基础设施协同 / 相位调度
  • 关键公式：pressurep = Σ ( 上游排队 − 下游排队 ) · 流量系数
  • 预计学时：60 分钟
  • 前置章节：第 049 章 多智能体任务分配

学习目标

读完本章，应当能够把路口信号配时写成排队动力学上的序贯决策，并用压力指标解释协同信号的行为。

  • 理解信号控制的动作空间构造：相位（phase）、绿灯时长与周期（cycle）三者的关系，以及损失时间的来源。
  • 掌握排队长度动力学递推与饱和流率（saturation flow rate）的作用，能估算某相位在给定绿灯时长下的可放行车辆数。
  • 掌握相位压力（pressure）的定义与最大压力控制器（max-pressure controller）的直观原理，理解其与干道绿波协调的联系。
  • 能为路网设计局部观测与邻域观测，说明参数共享策略在多路口场景下的适用条件。
  • 会设计延误、排队与切换频率的组合奖励，识别“只顾本路口”导致的网络级次优。

背景与动机

信号控制是多智能体协同在公共基础设施上的典型应用，协同的收益可以量化且立即可见。

每个信号路口可以独立控制，但车辆在路口之间流动，上游路口的决策会改变下游的到达分布。若所有路口都用固定配时，一条干道上出现连续红灯的概率不可忽略，车流被反复截断；若干道采用统一周期与相位差，车流可以在绿灯窗口内连续通过多个路口，形成绿波带（green wave）。传统方案包括周期配时、感应控制与自适应控制，效率上限受限于配时表无法覆盖流量的全部变化。

多智能体强化学习把每个路口建模为一个智能体，观测本路口车道排队与邻接路口状态，动作选择下一相位或绿灯时长，奖励刻画延误或排队。与前面章节的物理系统相比，本任务的动力学是离散事件队列：车辆到达、排队、被服务放行，模型没有连续力与碰撞问题，耦合来自队列跨路口转移。正因如此，压力这一局部信号同时携带邻居信息，策略比较容易从局部观测中学会接近全局最优的协同行为，本章的技术重点因此放在观测构造与压力的解释上。

核心原理

信号控制的原理由排队动力学、相位压力与协同协调三部分构成。

1. 信号时序与动作空间

一个路口的信号由若干相位组成，相位是允许通行的车道组合，任意时刻只有一个相位放行。

C = g1 + g2 + … + gK + L ， L = K · ( y + ar ) C 为信号周期；gk 为第 k 个相位的绿灯时长；L 为全部相位切换损失的合计；y 为黄灯时长；ar 为全红清空时长；K 为相位数

动作空间的常见三种设计依次增强灵活性。其一，固定周期下选择相位顺序，即按预定序列切换，学习只在必要时跳相。其二，选择下一相位并指定绿灯时长（离散档位，例如 5 至 30 秒四档），灵活性最高，动作维度为相位数乘档位数。其三，纯选择下一相位的切换时刻（决策在每个时间点进行，选择继续放行或切换），等价于给每个相位学习一个持续的时长分布，实现简单且在多数任务上表现接近第二种。三种设计共享同一组约束：最短绿灯时长（避免车辆刚启动即被截断）、黄灯与全红（清空路口的物质需求），动作执行器需要把网络输出映射到满足约束的时序上。

2. 排队动力学与饱和流率

车道排队长度按到达与服务逐时步更新，服务速率受饱和流率限制。

qℓ(t + 1) = max( 0, qℓ(t) + Aℓ(t) − s · Δt · 1[ ℓ ∈ phase(t) ] ) qℓ 为车道 ℓ 的排队车辆数；Aℓ(t) 为该步到达车辆数；s 为饱和流率（辆/秒），取值常在 0.4 至 0.5 之间；Δt 为决策步长；指示函数表示该车道是否处于放行相位

该递推式把路口动态描述为受服务能力约束的队列系统。三个量决定信号效率：到达率（需求侧，不可控）、饱和流率（车道物理容量，常被保守估计）、绿灯占比（控制侧）。放行能力为 s 乘绿灯时长：一个 15 秒的绿灯最多放行约 6 至 7 辆车。因此信号决策的收益来自把绿灯分配给需求更大的相位，代价是切换损失与低需求相位的等待增长，这一权衡在每一步重复出现，构成序贯决策问题。

排队长度本身是有上界的（路口物理空间有限），溢出后车辆阻塞上游路口，产生二次拥堵。实现中把溢出建模为“排队封顶并把超量返还上游”，否则奖励会低估拥堵的传播。

3. 相位压力与最大压力控制

压力把上下游排队之差作为局部协同信号，直接对应车辆在路网中的转移方向。

pressureφ = Σ(ℓ, m) ∈ φ [ qℓ − qm ] · sℓm φ 为候选相位；ℓ 为相位内放行的上游车道；m 为对应的下游车道；sℓm 为该转向的饱和流率；压力等于各转向排队差的加权和

相位压力的直观解释：当上游排队多、下游空闲时，压力为正且较大，放行该相位可以把车辆推向空闲的下游；当下游已经堵塞时，压力下降甚至为负，放行只会加剧下游拥挤。最大压力控制选择压力最大的相位放行，它的性质是可证明的：在一定条件下使路网总排队的漂移最小，属于吞吐最优的控制族。多智能体强化学习的策略在训练中通常会自发学出近似压力均衡的行为，因此压力可以直接作为观测特征与基线的动作选择规则。

压力作为奖励信号也在引入协同时有优势：单个路口的压力项包含邻居排队，最大化自身压力的过程自然向下游空闲方向疏导车流，等价于弱耦合的分布式协调。与干道绿波的关系在于相位差：上游放行产生的车队经过行驶时间到达下游路口，若下游绿灯窗口与之对齐，车辆无需停车通过，连续对齐即形成绿波。策略通过观测邻居相位与排队信息可以隐式学出相位差，无需显式优化绿波带宽。

4. 奖励设计：排队、延误与切换代价

交通控制的目标是减少延误，排队长度是延误的代理量，切换频率影响乘客舒适与损失时间。

rt = − wq Σℓ qℓ(t) − wd Σ 等待车辆 − ws Σ 切换次数 − wo Σ 溢出车道数 等待车辆统计本步未通过的排队车辆；切换次数统计相位的改变；溢出车道数统计排队达到物理上限的车道

等待车辆项与排队长度的差别在于惩罚的时间结构：排队长度惩罚当前存量，等待项累积每辆车的等待时长，后者与平均延误直接对应但方差更大。切换惩罚的权重需要谨慎：过大会使策略长期不切换相位，低需求方向无限等待；过小会出现每秒切换一次的震荡行为。溢出项是对网络级目标的补充，它让策略在局部排队尚未爆满时就对上游拥堵做出反应。

奖励的归一化对交通任务尤其重要：不同路口的车道数与流量差异使原始排队长度的量级不同，若不按车道容量归一化，参数共享策略会被高流量路口主导，低流量路口的策略退化。

5. 观测设计与路网规模

观测需要覆盖本路口的车道状态与邻接路口的粗粒度状态。

oi = [ qℓ / capℓ , phase onehot , tgreen / gmax , { 邻居：qin / cap , qout / cap , phase } ] capℓ 为车道容量；tgreen 为当前相位已持续时长；邻居项只保留与本路口直接相连的车道，控制观测维度

车道观测一维化后按固定顺序排列，顺序与动作空间的相位定义严格对应，任何错位都会让策略学到错误的车道关联。邻居观测的粒度需要权衡：给全量邻居车道会带来维度增长与通信负担，给汇总量（入向总排队、出向总排队、当前相位编号）已足以表达协调所需信息。路网规模从单个交叉口扩展到 4×4 网格时，参数共享使参数量保持不变，策略泛化依赖观测中不含路口绝对身份；若路网异质（车道数、限速不同），需要把结构特征拼入观测或按类型分组共享。

实现思路与设计

实现采用事件式排队仿真：以决策步长推进车辆到达与放行，奖励按步结算，环境同时输出压力与延误等诊断量。

1. 环境循环

每个决策步（典型为 5 秒）内：按需求模型生成车辆到达并按转向分配；执行各路口当前绿相位对应的放行；更新排队、等待时间与溢出；构造观测与奖励；处理相位切换（黄灯与全红在实现中折算为损失时间）。车辆离开路口后按转向比例进入下游车道的到达队列，跨路口的耦合由此产生。

3. 网络结构与训练要点

参数共享的多层感知机或循环网络均可胜任，输入维度在数十量级，无需深层结构。训练使用集中式评论家读取全路网排队状态；执行期仅用本地与邻居观测。动作选择采用“选择下一相位并指定绿灯档位”的形式，训练时对相位选择施加掩码（禁止选择当前相位作为“下一相位”除非指定延长）。评估指标包括平均排队长度、平均延误、平均停车次数与吞吐量，四者需同时报告：排队下降但吞吐下降说明策略以牺牲通行换取了局部指标。

4. 与第 049 章的差异点

任务分配中智能体可选任务、任务完成后消失；信号控制中智能体管理持续的流，状态由队列存量刻画，不存在“任务被认领”的概念。任务分配的协调通过投标价格，信号控制的协调通过排队差的压力信号。两者共同点是耦合都经由环境介质传递（任务时间占用、车辆流动），且局部观测加参数共享是通用的起点架构。

关键代码与解读

三段代码依次实现排队动力学、压力计算与动作选择、以及受约束的奖励与观测拼装。

片段 1：排队动力学推进

import numpy as np

def step_lanes(lanes, arrivals, phase_lanes, dt=5.0, s=0.45, cap=20):
    """推进一个路口全部车道的排队：q' = max(0, q + A - 放行量)。"""
    q = np.zeros(len(lanes))
    overflow = 0
    for k, lane in enumerate(lanes):
        served = s * dt if k in phase_lanes else 0.0   # 仅当前相位放行的车道有服务
        raw = lane + arrivals[k] - served
        # 物理容量封顶：超出部分视为溢出，阻塞上游（诊断量）
        if raw > cap:
            overflow += 1
            raw = cap
        q[k] = max(0.0, raw)                          # 排队不下溢为负数
    return q, overflow

解读：服务量用饱和流率乘决策步长计算，与绿相位绑定的成员判断放在循环内完成，避免对车道做两次遍历。容量封顶返回溢出标志，把上游阻塞的信息保留下来。排队截断在零处（max 操作）与容量处（封顶）对称处理，保证状态始终有界，价值网络输入不会出现异常大值。该函数不处理相位切换，切换逻辑放在环境主循环中，职责单一便于单元测试。

片段 2：相位压力与动作选择

def phase_pressure(phase_map, q, sat=0.45):
    """计算每个候选相位的压力：上游排队减下游排队，按饱和流率加权。"""
    scores = np.zeros(len(phase_map))
    for p, moves in enumerate(phase_map):
        # moves 的元素为 (上游车道, 下游车道) 转向对
        for up, down in moves:
            scores[p] += (q[up] - q[down]) * sat
    return scores

def max_pressure_action(phase_map, q, min_green_left=0):
    """最大压力基线：禁止在最短绿灯结束前切换。"""
    if min_green_left > 0:
        return None                    # 保持当前相位，不参与决策
    scores = phase_pressure(phase_map, q)
    return int(np.argmax(scores))      # 选择压力最大相位

def logits_with_mask(logits, phase_map, current, min_green_left=0):
    """策略输出的掩码处理：最短绿灯内只允许当前相位。"""
    if min_green_left > 0:
        mask = np.full_like(logits, -1e9)
        mask[current] = 0.0            # 仅当前相位可选，梯度只作用于延长决策
        return logits + mask
    return logits

解读：压力计算遍历转向对并累加，转向表由相位定义一次性构造，运行时只做查表与加法。基线控制器返回 None 表示无需决策，环境据此保持相位，该约定把“最短绿灯”这一硬约束从策略中剥离。策略端掩码与基线使用同一份约束逻辑，训练与基线在时序约束上完全一致，两者的性能差异因此归因于决策质量，约束处理差异已被对齐排除。掩码实现复用第 047 章的负值写法，保持代码风格统一。

片段 3：奖励与观测拼装

def traffic_reward(q_before, q_after, waiting, switches,
                   caps, w_q=1.0, w_s=2.0, w_w=0.1):
    """奖励：归一化排队 + 等待时长 + 切换惩罚。"""
    # 按车道容量归一化：消除路口规模差异，参数共享策略不被大路口主导
    q_norm = float(np.sum(q_after / caps))
    wait_norm = float(waiting.sum() / caps.sum())
    r = -w_q * q_norm - w_w * wait_norm - w_s * switches
    return r, {"queue_norm": q_norm, "wait": wait_norm, "switch": switches}

def build_obs(q, caps, phase_onehot, t_green, g_max, neighbor_feat):
    """观测：归一化车道排队、相位独热、绿时长比例、邻居汇总特征。"""
    # 车道顺序必须与相位定义、动作语义严格一致，避免车道与相位错位
    base = np.concatenate([q / caps, phase_onehot, [t_green / g_max]])
    return np.concatenate([base, np.asarray(neighbor_feat, dtype=np.float32)])

def neighbor_summary(q, caps, in_lanes, out_lanes, phase_id, n_phase):
    """邻居路口汇总：入向排队比、出向排队比与相位独热，控制维度。"""
    onehot = np.zeros(n_phase)
    onehot[phase_id] = 1.0
    return np.concatenate([q[in_lanes] / caps[in_lanes],
                           q[out_lanes] / caps[out_lanes], onehot])

解读：归一化把不同规模路口的奖励拉到同一尺度，是参数共享生效的前提。等待项权重取排队项的十分之一，避免两个相关量重复主导奖励；切换次数以标量加入，权重取单步排队量级的两倍。观测拼装函数显式注释了车道顺序的约束，这是交通任务最常见的错误来源。邻居汇总只保留与本路口相连的车道与相位编号，维度可控且信息量足够支撑协调，不需要全量邻居状态。

常见坑

  • 奖励完全局部化：只惩罚本路口排队，策略把车流尽快推给下游，独立看每个路口指标良好而全网延误上升。症状是上游排队下降、下游持续拥堵。修复：奖励加入邻域排队项，或观测中加入邻居排队并以压力作为特征。
  • 缺少切换惩罚：策略高频切换相位以即时清空单条车道，损失时间与启停损失被忽略。症状是切换次数异常高且乘客体验指标恶化。修复：加入切换次数惩罚并设最短绿灯约束。
  • 车道顺序与相位定义不一致：观测向量与动作语义错位，策略学习到错误的关联。症状是训练初期指标不降且换种子后表现剧变。修复：用单一数据结构同时生成观测、相位映射与奖励口径，避免多头维护。
  • 训练需求分布与评估不匹配：只在均匀低流量下训练，评估遇到高峰与转向不均衡时失效。修复：训练分布覆盖多种到达率与转向比例，评估按需求强度分层报告。
  • 溢出未建模：排队无上限，拥堵在网络中凭空消失，训练出的策略对真实拥堵缺乏反应。修复：排队容量封顶并把溢出量返还上游车道，奖励中记录溢出车道数。

练习与思考

  1. 计算题：饱和流率 0.45 辆/秒，绿灯 20 秒，问该相位一次放行最多多少辆车？若需求为 0.3 辆/秒且相位每 60 秒放行一次，比较到达与服务能力。★
    提示
    一次放行约 9 辆。60 秒内到达 18 辆而单次服务 9 辆，若每周期只放行一次会持续积压，需要增加绿灯时长或放行频率。
  2. 推导题：对单路口两相位情形，写出总延误对绿灯比例的近似表达式，说明为何存在最优绿信比，“给需求大的相位越多越好”为何不正确。★★
    提示
    每个相位的延误随其绿灯比例下降但其撤销收益递减，两相位延误之和在二者到达率之比处分界，超出会因另一相位等待剧增而总延误回升。切换损失固定时最优绿信比还与周期长度耦合。
  3. 改参数并预测：把决策步长从 5 秒改为 15 秒，预测平均延误、相位切换次数与训练收敛所需步数的变化方向。★★
    提示
    步长变粗后切换次数下降、时序精度下降、延误上升；训练所需环境步数减少（决策变少）但效果上限降低。该取舍常用于加速早期实验。
  4. 设计题：为三路口干道设计邻居观测与相位差学习方案，说明如何用观测表达“上游车队的预计到达时间”。★★★
    提示
    邻居观测中包含上游相位与已持续时长，策略可结合路段长度与速度推断车队到达窗口。也可以显式构造“预计到达车辆数”特征作为观测，减少网络需要自行推断的量。
  5. 实验设计：比较“局部奖励”“局部加邻居奖励”“压力型奖励”三种奖励设置对全网延误的影响，设计控制变量与评价流程。★★★
    提示
    固定需求分布、种子集合与评估时长，报告全网延误、各路口队列方差与吞吐。局部奖励通常本路口最优而全局次优，压力型奖励在拥堵传播场景中收益明显。

小结

  • 信号控制的动作是相位选择与绿灯时长，时序受最短绿灯、黄灯与全红的约束，损失时间不可忽略。
  • 排队动力学由到达与饱和流率服务共同决定，放行能力等于饱和流率乘绿灯时长，排队需要设容量上限以表达溢出。
  • 相位压力是上下游排队差的加权和，最大压力控制具有吞吐最优性质，压力同时可作为策略的观测特征与协同信号。
  • 奖励需组合归一化排队、等待时长、切换惩罚与溢出项；参数共享要求观测与奖励按容量归一化。
