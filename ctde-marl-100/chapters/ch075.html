第 075 章：多任务学习与CTDE结合

用一套共享表征同时学习多个协作任务：本章先讲清多任务学习的加权目标与梯度冲突问题，再讲投影式梯度修正与不确定性加权两种平衡手段，最后给出与集中式训练分布式执行（Centralized Training with Decentralized Execution, CTDE）结合的架构与实验设计。

  • 主题：共享表征 / 梯度冲突与任务平衡
  • 关键公式：minθ ΣtwtLt(θs, θt)，gt·gu < 0 时投影修正
  • 预计学时：60 分钟
  • 前置章节：第 074 章

学习目标

  • 掌握多任务学习的参数共享范式，区分硬共享与软共享的结构差异与适用条件。
  • 理解梯度冲突的判定（梯度内积为负）与后果，能描述投影式梯度修正（Projecting Conflicting Gradients, PCGrad）的操作步骤。
  • 掌握不确定性加权与梯度范数平衡两类自适应权重方法，说明它们与手工权重的区别。
  • 能实现共享编码器加任务头的策略结构，说明任务标识在训练期与执行期的使用边界。
  • 能设计实验：单任务单独训练作为上界、无平衡共享组、两种平衡方法的对照与梯度冲突率统计。

背景与动机

实际系统的协作需求常成组出现：同一车队既要覆盖巡检区域，又要保证避障与能耗约束；不同子任务共享感知与运动技能，仅在目标与终止条件上不同。为每个任务训练独立网络会使参数量与样本需求随任务数线性增长。多任务学习让共享层承载跨任务通用的表征，任务头承载任务特有的决策，用一份交互数据同时改善多个任务。

共享带来新的干扰：任务的梯度方向不一致时，共享参数的更新相互抵消，联合训练可能劣于分别训练，称为负迁移。相比第 073 章的跨任务参数迁移，本章的多个任务在同一个模型内同时训练；相比第 074 章的快速适应，本章关注的是并列任务的容量分配与梯度协调。

核心原理

本节先讲多任务学习的目标与共享结构，再讲梯度冲突、两类平衡方法与 CTDE 落点。

1. 参数共享与目标函数

硬共享让全部任务共用底层网络，仅在输出层分开；软共享为每个任务保留独立网络，用参数距离或表示对齐做约束。硬共享参数效率高，任务差异大时易受冲突困扰。目标函数为加权求和：

minθs, θ1,…,θT Σt=1T wtLt(θs, θt) θs 为共享参数，θt 为任务头；wt 决定任务的容量分配

奖励尺度的差异使损失量级天然失衡：任务 A 的时序差分残差可能是任务 B 的十倍。固定权重的选择依赖对损失量级的手工标定，这是自适应权重方法出现的直接动机。

2. 梯度冲突与投影修正

把第 t 个任务对共享参数的梯度记为 gt。两个任务内积为负表示方向冲突：沿 g1 更新会增大 L2。-PCGrad 的做法是逐对检查梯度，出现冲突时把一方投影到另一方法向的正交补：gt ← gt − (gt·gu/‖gu‖2)gu。修正后再求和更新共享参数，任务头的梯度不受影响。

gtproj = gt − min(0, gt·gu/‖gu‖2)·gu，最终 g = Σtgtproj 内积为正时投影为零向量贡献，保持原梯度；负时消除投影分量

3. 自适应任务权重

不确定性加权把每个任务的损失乘上可学习的精度参数：L = Σt(1/2σt2)Lt + logσt，σt 越大代表该任务噪声越大、权重越低，模型自动把容量让给确定性高的任务。梯度范数平衡（GradNorm）则调整权重使各任务梯度范数趋于一致。两类方法与 PCGrad 可以叠加：前者调权重，后者调方向。

4. CTDE 落点

共享编码器处理观测，任务头输出各自策略；评论家采用多头结构共享底层，各头对应任务的价值尺度；混合网络按任务分组重建或共享。任务标识在训练期与执行期作为输入特征，执行期的目标任务由部署配置决定，策略输出不依赖运行时任务切换。若任务在执行期动态切换，需要额外的任务推断模块从观测历史识别当前任务。

5. 数值算例：冲突投影与不确定性权重

取任务梯度 g1=(1, 0)、g2=(−1, 1)，内积为 −1，判定冲突。按逐对投影修正：g1proj=g1−((g1·g2)/‖g2‖2)g2=(1, 0)−(−1/2)(−1, 1)=(0.5, 0.5)；g2proj=g2−((g2·g1)/‖g1‖2)g1=(0, 1)。

对照两组更新。未修正的合并梯度为 (0, 1)，与 g1 的点积为 0，任务 1 在一阶意义上没有进展；修正后的合并梯度为 (0.5, 1.5)，与 g1、g2 的点积分别为 0.5 与 1.0，两个任务同向改善。投影的语义是把冲突分量从更新方向中剔除，任务权重本身不受压制。

不确定性权重算例。两个任务损失 L1=4、L2=1。对 logσ 求驻点得 σt2=Lt，权重 1/(2σ2) 分别为 1/8 与 1/2，损失较大的任务权重反而小，容量让给更可学的信号；logσ 正则项防止所有权重被整体压小。若把 L2 换成 100，权重变为 1/8 与 1/200，模型几乎放弃任务 2，此时应考虑为它增加专属容量，继续调权重无法挽回。

解读：两个算例对应调方向与调权重两类机制。先记录各任务梯度内积为负的比例，冲突率低于约 10% 时投影是冗余操作；权重方法解决的是损失量级差异。两类机制作用维度不同，可以叠加，但不要以相同频率同时更新，否则补偿叠加会引发震荡。

补充一个实施细节：投影的逐对检查在任务数 T 上的运算量为 O(T2) 次向量操作，T 增大后应缓存冲突对并只重算本步更新过的梯度，避免全量两两比较；梯度维度很大时，点积与投影的代价会超过网络前向的代价，任务数超过 6 到 8 个后尤其明显。

实现思路与设计

结构为共享编码器、任务头与多头评论家；训练按任务交替采样批次，共享层梯度做投影修正后合并。

实验设计

  1. 对比基线：每个任务单独训练（性能上界参照）、硬共享无平衡、软共享。
  2. 消融设置：PCGrad 开/关、不确定性加权与固定权重对照、共享层宽度两档、任务数从 2 增到 4。
  3. 评价指标：各任务相对单任务基线的回报比、训练各阶段梯度冲突率、目标任务的样本效率（达到门槛的总交互步）。
  4. 统计方式：任务族内所有任务都要报告，均值掩盖个别任务的退化。
设计决策：为什么先统计冲突率再决定是否开投影

投影修正不是免费的：它改变了共享层的有效更新方向，任务梯度方向高度一致时投影是冗余操作，还引入额外计算与实现复杂度。先记录每步各任务梯度内积为负的比例，冲突率低于约 10% 时无平衡训练已足够；高于 30% 时投影或权重调整开始显示价值。冲突率随训练演化，后期通常下降，可设置随步数衰减的投影开关。

与第 074 章的差异：元学习按任务顺序适应，本章任务并列共享；关注点从适应速度转为容量分配的公平性与梯度方向的相容性。

对比分析：四类平衡手段的作用点

手段作用对象可学习参数失效模式适用条件
固定权重损失量级无后期由易任务主导任务量级接近
梯度范数平衡（GradNorm）梯度范数每任务一个权重与投影叠加时震荡收敛速率差异明显
不确定性加权损失权重每任务一个对数方差难任务权重趋零噪声水平任务间不同
PCGrad 投影梯度方向无顺序偏差、冗余计算冲突率高于约三成

组合使用的原则是一次只调一个维度：先按冲突率决定是否开投影，再按收敛速率差异决定是否开自适应权重。两类同时开启时，投影改变梯度方向会使权重估计的历史统计失准，需要把权重更新与投影放在不同频率上，或先冻结一类再启用另一类。

任务采样比的换算示例：单回合 200 步的困难任务与单回合 50 步的简单任务按 1:1 的回合数采样时，环境步数比为 4:1，困难任务实际获得更多样本；若希望步数比为 1:1，简单任务的回合数配比应提高到 4 倍。按回合采样与按步数采样在长时程差异大的任务族中会给出不同结论，配置表里必须写明采样单位。

配置表中记录采样单位后，跨任务的比较曲线都按环境步重新采样对齐，避免用回合数横轴造成斜率失真；任务头的容量分配同理需要写入配置，难度接近的任务复用同一头宽度，差异大的任务单独加宽。

关键代码与解读

片段 1：梯度冲突投影

import torch

def pcgrad_project(grads):
    """对任务梯度列表做两两投影修正，返回合并梯度与冲突计数。"""
    projected = [g.clone() for g in grads]
    conflicts = 0
    for i, gi in enumerate(projected):
        for j, gj in enumerate(grads):
            if i == j:
                continue
            dot = torch.dot(gi.flatten(), gj.flatten())
            if dot < 0:                     # 冲突：减去在对方方向上的投影
                gi -= (dot / gj.norm() ** 2) * gj
                conflicts += 1
    merged = torch.stack(projected, dim=0).sum(dim=0)
    return merged, conflicts

解读：投影在每对梯度间顺序执行，顺序会影响结果但影响量级可控，随机打乱任务顺序可消除系统性偏差。第二个返回值统计冲突对数，用于监控与开关决策。合并用求和保持与原损失权重一致，权重调整交由不确定性加权处理，两类机制不重复作用在同一环节。

片段 2：不确定性加权

import torch
import torch.nn as nn

class UncertaintyWeighting(nn.Module):
    """学习各任务的精度参数，自动平衡损失量级。"""
    def __init__(self, n_tasks):
        super().__init__()
        # 用对数方差参数化：保证权重恒为正且更新尺度平稳
        self.log_var = nn.Parameter(torch.zeros(n_tasks))

    def forward(self, losses):
        total = 0.0
        for t, l in enumerate(losses):
            precision = torch.exp(-self.log_var[t])
            total = total + 0.5 * precision * l + 0.5 * self.log_var[t]
        return total

解读：目标函数中 log(sigma) 项防止模型把所有任务权重都压小，两项的组合等价于以噪声方差为条件的最大似然。log 参数化避免了方差必须为正的投影操作。学习到的权重需要监控：某任务权重持续趋零说明该任务在当前共享容量下无法改善，应考虑增加专属容量或从共享集合中移除。

片段 3：共享编码器与任务头

import torch
import torch.nn as nn

class MultiTaskPolicy(nn.Module):
    """共享编码器加每任务策略头；任务标识训练期用于选择头。"""
    def __init__(self, obs_dim, act_dim, n_tasks, emb=128):
        super().__init__()
        self.encoder = nn.Sequential(nn.Linear(obs_dim, emb), nn.ReLU())
        self.heads = nn.ModuleList(
            [nn.Linear(emb, act_dim) for _ in range(n_tasks)])

    def forward(self, obs, task_id):
        z = self.encoder(obs)               # 共享表征：跨任务通用技能
        logits_all = torch.stack([h(z) for h in self.heads], dim=1)
        # 按样本的任务编号收集对应头：[批, T, 动作] -> [批, 动作]
        idx = task_id.view(-1, 1, 1).expand(-1, 1, logits_all.size(-1))
        return logits_all.gather(1, idx).squeeze(1)

解读：gather 的写法让一次前向同时更新全任务头，避免逐任务循环前向带来的重复编码计算。共享编码器承担跨任务表示学习，任务头各自收敛不会被其他任务的样本直接更新。执行期部署时 task_id 固定，若任务动态切换需从观测推断，或改为任务嵌入连续向量作为输入。

常见坑

  • 任务权重长期不变：固定权重在训练后期使易任务主导共享层，难任务停滞。修复：启用自适应权重或按收敛速率周期调整。
  • 共享层过窄：任务数增加但容量不增，任务头无法从被挤占的表征中恢复性能。修复：按任务数扩展共享宽度，或对难任务增加专属层。
  • 投影与权重双调整打架：同时对梯度做投影并大幅调权重，补偿叠加导致震荡。修复：先只启用一类机制，验证无冲突后再考虑组合。
  • 任务样本比失衡：困难任务的单回合步数更长，按回合采样导致其样本量被低估。修复：按环境步数配比采样；按回合数配比会低估长回合任务的样本量。
  • 执行期依赖任务标识：任务切换场景下策略等待外部标注，切换延迟期间行为错乱。修复：用观测推断任务或训练任务无关的通用策略作为兜底。

练习与思考

  1. 两任务梯度 g1=(1,0)、g2=(−1,0.1)，判断是否冲突并计算 PCGrad 修正后的合并梯度。★
    提示
    点积为 −1 冲突；g2 投影去掉后约剩 (0,0.1)，合并梯度约 (1,0.1)。
  2. 把任务采样比从 1:1 改为 1:4，预测两任务回报曲线与共享层梯度的变化。★★
    提示
    权重高的任务收敛更快、占据表征；另一任务回报下降或停滞，冲突率上升，需与不确定性加权对照。
  3. 推导：说明不确定性加权的目标在固定损失取值下关于 logσ 的最优解为 σ2=L，并解释该解的直观含义。★★★
    提示
    对 logσ 求驻点得 2σ2 关系式；含义是损失越大的任务权重越小，把容量让给更可学的信号。
  4. 设计实验：3 任务硬共享、T=2 与 T=4 两组，统计训练全程梯度冲突率与各任务回报比，给出开启投影的判定阈值建议。★★★
    提示
    预期 T=4 组冲突率显著更高；以投影带来回报提升的最小冲突率为阈值，通常在 20% 到 30% 之间。
  5. 取 g1=(1, 0)、g2=(−1, 1)，按投影公式计算修正后的两条梯度与合并梯度，并验证合并梯度与两任务原梯度的点积均为正。★★
    提示
    g1proj=(0.5, 0.5)、g2proj=(0, 1)，合并梯度 (0.5, 1.5)；与两原梯度的点积分别为 0.5 与 1.0，均为正，说明两任务在一阶意义上同时改善。

小结

  • 多任务学习用共享层承载通用表征、任务头承载专属决策，目标为加权损失和，权重决定容量分配。
  • 梯度冲突表现为任务梯度内积为负，PCGrad 以投影方式消除冲突分量，投影顺序需随机化消除偏差。
  • 不确定性加权与梯度范数平衡自动调权重，与投影调方向互补；不确定性的最优解把容量让给可学信号。
  • CTDE 中评论家采用多头共享结构，任务标识限于训练期；执行期任务固定或由观测推断。
  • 数值算例量化了两类机制：投影把冲突分量从更新方向剔除，不确定性加权按损失量级自动分配容量，两类机制作用维度正交。
