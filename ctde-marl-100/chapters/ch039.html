第二篇 · 训练工程与稳定性

第 039 章：异步更新与同步更新对比

本章讲更新时序的两类方案：同步批次更新与异步流水更新。讨论策略版本偏离度、截断重要性修正（V-trace）、半同步等待因子、更新与数据比，以及多智能体非平稳性与滞后叠加的后果。

  • 主题：更新语义 / 滞后与修正
  • 关键公式：ρt = min(ρ̄, π(at|st) / μ(at|st))
  • 预计学时：55 分钟
  • 前置章节：第 038 章 分布式训练与并行采样

学习目标

  • 理解同步与异步更新在数据构成与优化过程上的语义差异，能写出两者的训练循环流程。
  • 掌握异步更新中策略版本偏离度的来源与度量，理解截断重要性修正的动机与形式。
  • 掌握半同步更新的等待因子设计，理解其在吞吐与一致性之间的连续调节作用。
  • 理解多智能体场景下滞后与队友漂移双重叠加的效应，能评估对同策略与离策略算法的影响差异。
  • 能按更新与数据比对齐不同架构的对照实验，避免架构对比中的配置漂移。

背景与动机

第 038 章建立了并行采样架构，留下的问题是更新如何消费这些数据。同步更新在固定的数据批次上执行优化，数据与参数版本严格对应；异步更新让学习器持续消费到达的数据，数据可能由若干个更新步之前的策略产生。两者的差异无法简单归结为吞吐与正确性的取舍：异步释放了等待时间，代价是优化目标偏离当前策略的真实梯度方向，偏离程度需要修正或管理。

多智能体训练对这个问题的敏感度更高。队友策略持续更新（第 032 章）已经让数据分布随时间漂移，版本滞后在时间轴上再叠加一层偏离：一批数据不仅由旧版本的自身策略产生，也记录着旧版本队友的行为。学习器用当前参数去拟合旧行为下的联合回报，误差随滞后时间与队友漂移速度共同增长。本章把偏离度、修正手段与选择判据整理成可操作的设计框架。

核心原理

1. 同步与异步的语义差异

两种循环的结构对比：

同步：采集固定步数 B → 等待全部完成 → 用同一批数据执行若干次更新 → 广播权重 → 重复 数据与参数版本严格对应，批内版本一致
异步：演员持续采集并推送 → 学习器持续取用并更新 → 权重周期性广播 数据版本散布在一个区间内，学习器不等待任何特定数据

同步循环的等待发生在"最慢演员"处：吞吐受短板制约，且随着演员数量增加，长尾延迟让等待比例上升。异步循环消除等待，但引入了策略版本偏离。管理偏离的量化起点是滞后度：

滞后度 τ = 当前学习器版本号 − 数据产生时的策略版本号 沿队列统计 τ 的分布（均值与 95 分位）；τ = 0 表示数据与当前策略版本一致

τ 的分布比均值更重要：平均滞后很小的队列里可能存在少量长期滞留的批次，它们对损失的贡献权重固定，反复扭曲梯度方向。工程上以 τ 的 95 分位作为新鲜度指标。

滞后分布的尾部为什么是重点：全队列平均滞后 2 个版本、95 分位为 8 个版本时，长期滞留的少数批次以接近固定的权重反复参与更新，梯度方向的系统性偏移由这部分样本决定。监控面板把 τ 的均值与 95 分位并列展示，均值正常而分位异常时优先排查演员的延迟分布与背压配置。

2. 截断重要性修正

同策略算法在异步数据上需要修正旧行为策略与新目标策略的分布差。V-trace 形式给出两条规则：截断的单步比率与累积乘积：

ρt = min(ρ̄, π(at | st) / μ(at | st))；ct = min(c̄, π(at | st) / μ(at | st)) π 为学习器当前策略，μ 为产生数据的行为策略；ρ̄、c̄ 为截断上界（常取 1.0 与略大值）

直观解释：比率大于 1 表示当前策略比行为策略更倾向该动作，截断把放大效应限制在上界内；比率小于 1 的收缩不截断，保留对低估的修正。累积乘积 c 控制多步回报中偏差的传播半径。截断参数与同策略裁剪（第 027 章）可以并列理解：裁剪限制单步更新幅度，截断限制旧数据的影响力，两者都用部分理论正确性换取方差控制；区别在作用对象，裁剪作用于损失对当前批数据的方向，截断作用于数据分布对目标的权重。两者并用时，诊断常用判据是裁剪触发率与滞后分位是否同步变化，同步抬升说明两个机制都在响应同一批陈旧数据。截断引入偏差换取方差控制，这是与第 023 章重要性采样修正相同的权衡结构，区别在于对象从"采样优先级"变为"时序步"。离策略自举算法（Q 学习类）对分布差不要求显式修正，但目标值的自举仍会受旧行为影响，通常用目标网络与较小更新率吸收（第 024 章）。

3. 半同步与等待因子

两端之间存在连续调节：半同步更新等待 N 个演员中的 K 个，用已到达的数据执行更新，不等待其余演员。等待因子 λ = K / N 取值从同步（λ = 1）到异步（λ 趋向 0）连续变化，滞后分布随 λ 减小单调放宽。

方案等待行为滞后分布适用条件
完全同步等待全部演员恒为零同策略算法、小规模、延迟稳定
半同步等待 K 个先到者窄分布，尾部受控需要吞吐但容忍轻度偏离
完全异步不等待宽分布，需上限管理离策略算法、异构硬件、长尾延迟严重

多智能体场景还有一条偏向同步的论据：参数共享结构下全体智能体共享策略，同步更新保证"队友版本"与"自身版本"严格一致；异步更新中一次广播前的所有数据记录的是旧队友，学习器离线拟合自身的同时也被迫拟合队友的历史行为，双重偏离使有效修正更复杂。因此多智能体同策略算法的默认选择是同步或小滞后半同步；异步主要留给离策略算法与对吞吐极敏感的系统。

半同步的工程实现需要注意读取语义：先到者判定基于带超时的通道读取，超时后回退到已就绪集合，避免阻塞等待指定演员；否则一个挂起的演员会把整个调度器卡死。等待因子的取值按硬件延迟分布标定，同构集群取 0.6 到 0.8，异构集群按最慢档的延迟决定，必要时改为批次就绪即更新的加权半同步。

4. 更新与数据比

架构对比实验中最容易被忽视的控制变量是更新与数据比（Update-to-Data Ratio, 也叫回放比）：单位环境步的数据被优化器消费的次数。定义与计算：

更新与数据比 = 优化步数 × 批大小 / 环境步数 正文报告为无量纲比值；同步方案中由配置直接决定，异步方案中随吞吐与优化频率漂移

比较同步与异步配置时必须对齐该比值：异步系统的优化吞吐更高，若不相应减少优化频率，同一批数据会被消费更多次，收益上的差距可能来自"训练更充分"，与"数据更新鲜"的贡献无法区分。第 040 章讨论样本效率时会再次用到这个量，两者口径约定保持一致。

5. 数值算例：等待因子、截断权重与比值对齐

用指数分布刻画演员延迟可以核算等待成本：设 8 个演员的单批延迟服从均值 1 的指数分布，完全同步要等最慢者，其均值等于调和级数 H8 ≈ 2.72；等待因子 0.75 时只等前 6 个到达，第 6 个次序统计量的均值约 1.22；因子 0.5 时等前 4 个，约 0.63；完全异步取第 1 个到达，约 0.125。等待因子从 1 降到 0.75，等待时间减少约五成，跳过的只是两个最慢的采集者；继续降低因子的收益递减，同时滞后分布变宽，吞吐与一致性的交换曲线由此得到刻度。指数分布是延迟的理想模型，真实系统长尾更重，各档等待成本的差距还会更大。

V-trace 的截断效果用两个比率核对：当前策略对某动作的比率 ρ = 1.5 而截断上界 ρ̄ = 1.0 时，权重被压到 1.0，0.5 的放大部分被放弃；比率 ρ = 0.6 时整个值保留，收缩方向不截断。截断只切右侧尾部，偏差来自被放弃的那部分放大，方差收益来自避免个别大比率样本主导梯度。累积系数的传播范围用短序列示意：单步截断系数 c = (0.8, 1.0, 0.5) 时，前向累积得 cs = (c2c3, c3, 1) = (0.5, 0.5, 1.0)，第 1 步之外的偏差在向后传播时被 0.5 的总折扣限制。

更新与数据比的对齐用一次换算说明：某同步配置的环境吞吐为每秒 12800 步、批大小为 256，按比值 1.0 得到每秒 50 次优化；异步架构测得吞吐为 1.2 倍，不限速时每秒约 60 次优化，等效比值 1.2。把优化频率压回每秒 50 次之后再比较两种架构的回报曲线，结论才能归因到数据新鲜度与更新语义。实验档案记录限速后的实际比值，与目标值偏离超过一成时触发复核。

实现思路与设计

更新调度器统一管理三种模式的实现：同步模式直接以批次为单位循环；异步模式以队列门槛与滞后上限管理消费节奏；半同步模式在两者之间按等待因子参数化，三种模式共享采集与学习两侧的代码路径。

参数默认值作用取值依据
更新模式同步调度语义同策略多智能体任务的默认；离策略可选异步
等待因子 λ0.75半同步等待比例吞吐优先下调，稳定性优先上调
滞后上限 τmax4 个版本数据新鲜度门槛与广播频率联动：广播越稀，上限越小
截断上界 ρ̄1.0V-trace 单步比率上限文献惯例；偏离重时下调减小方差
累积截断 c̄1.0 到 1.2多步传播半径任务回合越长取值越保守
更新与数据比1.0实验对照控制量架构对比时必须对齐并写入实验档案

与第 038 章的衔接点：本章的滞后管理直接消费第 038 章的版本标记字段；有界队列的容量参数与滞后上限 τmax 联动设置，容量过大时先压缩队列再调 τmax。

模式切换的成本应当接近零：调度器在初始化时选择等待策略，训练中途不切换；需要对比时用配置区分运行实例，让每个实例的模式在全过程中保持固定。中途切换引入的策略行为变化会污染对照曲线，这一纪律与第 036 章的单变量对照原则一致。同一次实验中的广播频率也应固定，滞后统计在两种频率之间没有可比性。

等待因子与广播频率的标定顺序是先固定一个再调另一个：滞后分位长期贴住上限时先调等待因子，回报曲线抖动而滞后正常时再调广播频率；两个参数同时调整会让诊断失去参照，也无法把行为变化归因到具体机制；复测保持同一档位组合，结论才有累积性。

关键代码与解读

片段 1：同步与半同步的最小调度器

class SyncScheduler:
    """三种更新模式的统一入口：wait 参数决定等待策略。"""
    def __init__(self, mode="sync", wait_factor=0.75):
        self.mode = mode
        self.wait_factor = wait_factor            # 半同步模式生效

    def collect_batch(self, actors):
        """从演员集合取一批数据，返回 (batch, 版本区间)。"""
        if self.mode == "sync":
            batches = [a.get_batch() for a in actors]      # 等待全部到位
        elif self.mode == "semisync":
            # 只等待先到达的 K 个演员：K 取 ceil(wait_factor * N)
            k = max(1, int(len(actors) * self.wait_factor + 0.5))
            batches = self._first_k(actors, k)
        else:
            batches = [actors[0].get_batch()]              # 异步：不等待
        versions = [b["policy_version"] for b in batches]
        return batches, (min(versions), max(versions))

    def _first_k(self, actors, k):
        """等待前 k 个到达的数据；生产者各自的队列只会在就绪时返回。"""
        return [a.get_batch() for a in actors[:k]]

解读：三种模式共用一条数据出口，唯一的差异是等待范围，这让模式切换停留在配置层，代码路径无需分叉。返回的版本区间进入监控：区间宽度是滞后度的直接观测，半同步下若区间长期超过 τmax，说明等待因子偏低需要上调。_first_k 的写法是示意性的（真实实现用带超时的通道读取先到者），接口语义保持"取回就绪数据、未就绪则等待"一致。同步模式下版本区间理论上退化为单点，可加断言验证。

片段 2：V-trace 截断权重

import torch

def v_trace_weights(logp_behavior, logp_target, rho_bar=1.0, c_bar=1.0):
    """按轨迹计算截断比率与累积系数，供多步回报修正使用。"""
    ratio = torch.exp(logp_target - logp_behavior)     # 单步重要性比率
    rho = torch.minimum(ratio, torch.tensor(rho_bar))  # 上截断：放大受限
    c = torch.minimum(ratio, torch.tensor(c_bar))      # 累积截断：传播受限
    # 累积乘积 cs[:, t] = c_{t+1} * ... * c_{T-1}：
    # 给出第 t 步之外偏差向后传播时的总折扣，范围越大越保守
    T = ratio.shape[1]
    cs = torch.ones_like(c)
    for t in range(T - 2, -1, -1):
        cs[:, t] = cs[:, t + 1] * c[:, t + 1]
    return rho, cs

def v_trace_value_loss(values, rewards, gamma, rho, cs):
    """截断修正的多步价值目标：偏差与方差的受控折中。"""
    T = rewards.shape[1]
    targets = torch.zeros_like(rewards)
    acc = values[:, -1]                                # 末步价值作为自举起点
    for t in reversed(range(T)):
        # 反向累积：v_t = r_t + gamma * (c_t * (rho 修正的 td) + 余项)
        delta = rho[:, t] * (rewards[:, t] + gamma * values[:, t + 1] - values[:, t])
        targets[:, t] = values[:, t] + delta + gamma * cs[:, t] * (acc - values[:, t + 1])
        acc = targets[:, t]
    return targets

解读：两个截断参数分工明确：rho_bar 限制单步比率的上传放大，c_bar 限制偏差沿时间传播的范围；比率小于 1 的收缩方向不截断，保留对低估的修正。反向累积循环按回合维度组织，与第 023 章的回合式缓冲结构对齐；逐步累乘的显式写法便于调试，生产实现可用对数域累加替代以避免下溢。该损失与第 024 章的目标网络正交：前者修正新旧分布差，后者平滑自举目标，异步同策略系统通常两者并用。

片段 3：更新与数据比的对照控制

def align_update_ratio(arch, target_ratio=1.0):
    """按目标更新与数据比反推优化频率：跨架构对照的控制手段。"""
    # 环境步吞吐量由架构决定（第 038 章测量）
    steps_per_sec = arch.measured_steps_per_sec
    batch_size = arch.batch_size
    # 优化步频率 = 目标比值 * 环境步率 / 批大小
    updates_per_sec = target_ratio * steps_per_sec / batch_size
    arch.set_optimizer_rate(updates_per_sec)
    # 返回实际比值预估，供实验档案记录：仅记录目标值不足以反映真实情况
    return updates_per_sec * batch_size / steps_per_sec

解读：该函数把"架构吞吐差异"翻译成"优化频率差异"，让两种架构在同一更新与数据比下比较。函数回传的是实际值：异步系统中的限速设置总有误差，实验档案记录实际比值，报告时以实际值为准。与之配套的监控项是优化队列的积压长度，积压持续增长说明优化跟不上采集，比值被系统强制压低，此时要么提高更新频率要么降低采集速率，不能放任两种资源竞争。

常见坑

  • 异步数据上直接用同策略目标。策略比率失真的同时梯度方向被旧分布主导。症状是策略熵异常、回报振荡。修复：引入截断重要性修正，或退回半同步。
  • 滞后无上限。个别批次长期滞留队列，反复以固定权重参与更新。修复：τmax 门槛与队列容量联动，超限数据丢弃并记录比例。
  • 半同步等待因子设为 1。等价于完全同步，失去吞吐收益且在长尾延迟下等待放大。修复：按硬件延迟分布选 0.6 到 0.8 的等待因子。
  • 架构对比未对齐更新与数据比。异步系统的收益被"多消费数据"混淆。修复：按片段 3 对齐并记录实际比值。
  • 版本一致性边界。独立策略架构下各智能体副本刷新时点不同，联合数据来自多个版本组合；评测进程读取的策略状态不确定。修复：刷新做成单次原子广播；评测固定读取指定版本快照。

    提示
    截断切掉右侧尾部：ρ̄ 增大时偏差减小、方差回升；极端大比率（方差大）场景宁可保留偏保守的截断。
  2. 改参数预测：把等待因子从 0.75 降到 0.25，预测滞后度 95 分位、吞吐率与训练回报曲线三个量的变化方向。★
    提示
    滞后分位显著上升，吞吐提高；同策略算法下回报曲线更抖或走低，离策略算法下差异小。
  3. 设计：为一个 8 演员、参数共享的多智能体任务选择更新模式并给出参数（等待因子、广播频率、滞后上限），说明为什么不采用完全异步。★★
    提示
    共享参数下同步或高等待因子半同步即可满足吞吐；完全异步让数据同时记录旧自身与旧队友行为，双重偏离的修正成本高于收益。
  4. 实验设计：在相同更新与数据比与相同种子集合下比较同步、半同步、异步三种模式的回报曲线与吞吐，给出三种模式下"是否值得异步"的定量结论模板。★★★
    提示
    报告每组：吞吐（步/秒）、达到固定回报的环境步数、达到同回报的墙钟时间；异步的墙钟优势与回报劣势同时呈现。

小结

  • 同步与异步的本质差异在数据与参数版本的对应关系；异步的代价是滞后度分布，需以 95 分位指标管理。
  • 截断重要性修正用上传受限、收缩不截断的规则控制分布差，与目标网络在稳定化上正交配合。
  • 半同步以等待因子在吞吐与一致性之间连续调节；多智能体同策略任务默认同步或高等待因子半同步。
  • 更新与数据比是架构对比的必控变量；实验档案记录实际比值与优化队列积压。
