第一篇 · CTDE 基础与核心算法

第 017 章：通信信道受限下的CTDE

给通信加预算：消息发送由门控决定，发送行为附带代价，目标函数在回报与通信量之间权衡。本章实现发送门控、直通估计与代价惩罚，画出"回报对通信量"的权衡曲线，并给出噪声信道的鲁棒化方案。

  • 主题：受限信道 / 学习式通信
  • 关键公式：J = 𝔼[ Σt γt ( rt − β · Ct ) ]， Ct = Σi gi,t · c
  • 预计学时：55 分钟
  • 前置章节：第 016 章

学习目标

  • 理解受限信道的成本建模：发送次数与消息尺寸构成可计量的通信代价，预算通过拉格朗日乘子进入目标。
  • 掌握发送门控的两种可导化方案：直通估计器与 Gumbel 松弛采样，以及各自训练与推理的一致性要求。
  • 会实现门控通信模块与代价损失，并联调 β 得到回报与通信量的权衡曲线。
  • 掌握噪声信道的基础鲁棒化手段：训练期消息丢弃与信道扰动正则。
  • 能设计"预算硬约束"与"软惩罚"两套方案的对照实验，并解释与第 016 章边门控的叠加关系。

背景与动机

第 016 章的图通信让消息沿边自由流动，没有为"说多少话"设置成本。真实系统里带宽与能耗都是硬约束：无人机链路的可用时隙有限、水下通信的比特代价高昂、多机器人系统的无线电共享同一个信道。把通信量当作免费资源，训练出的策略会在部署时因信道拥塞或能耗超限而失效。

受限信道的 CTDE 把通信量写进优化目标：每发送一条消息支付代价，策略在"多说话换取协调精度"与"少说话节省预算"之间自动权衡。实现的核心难点是发送决策的离散性：门控变量取 0 或 1，采样不可导，梯度无法穿过。直通估计器与 Gumbel 松弛把离散决策转化为可训练对象；β 系数把预算这个工程约束翻译成目标函数里的一个旋钮，扫描 β 即得到整条权衡曲线。本章的模块建立在第 016 章的消息布局之上，门控作用于消息张量，与边门控形成"能发给谁"与"要不要发"两层稀疏结构。

核心原理

本节给出成本模型与拉格朗日视角、发送门控的可导化、消息与信道的设计空间，以及鲁棒化与评估方法。

1. 成本模型与拉格朗日视角

设智能体 i 在时刻 t 的发送门控为 gi,t ∈ {0, 1}，单条消息代价为 c：

Ct = Σi gi,t · c， J(π) = 𝔼[ Σt γt ( R(st, at) − β · Ct ) ] β > 0 为通信代价系数。求解"回报最大且平均通信量不超过 Cmax"的约束问题, 其拉格朗日形式正是上式: β 是最优乘子。扫描 β 等价于扫描预算 Cmax

成本的具体计量有两种口径：按发送次数（每条消息记一次）与按比特（消息维度乘精度）。协作任务中两种口径的权衡曲线形状相似，工程实验取发送次数口径更易统计。β 的量级要与回报尺度对齐：回报量级为 1 的任务，β 从 0.01 到 0.1 扫描即可覆盖"几乎不限"到"高度吝啬"的区间；跨任务对比时先归一化回报尺度再比较 β。

2. 发送门控与可导化

门控网络输出发送概率，采样得到离散决策。两种可导化方案：

直通估计器（Straight-Through, ST）： 前向 g = 1[ u < p ]， 反向 ∂g/∂p ≈ 1（当作恒等映射）
Gumbel 松弛： g = softmax( ( log p + G ) / τ )， G 为 Gumbel 噪声， 温度 τ 退火趋近离散 u 为均匀噪声, p 为发送概率。ST 实现最短、推理直接取硬门；Gumbel 有可微理论但多一个温度调度。本节基线取 ST, Gumbel 作为对照档

门控梯度的直觉：发送概率高的样本若碰巧没发（g = 0），直通估计把"少发一条"的代价按概率方向回传，推动模型在"确定要发"时提高概率、在"犹豫"时降低概率。门控崩溃是主要风险：概率全体趋零时消息通道关闭，协调退化为无通信基线；概率全体趋一时代价项失效。缓解手段是概率初始偏置（初期鼓励发送）与代价项预热（先学习通信内容，再逐渐加码预算）。两种方案的选择判据列成对照表，供实现前定档：

维度直通估计器（ST，基线）Gumbel 松弛（对照）
前向行为硬门 0/1，消息稀疏性与代价统计真实软门，温度 τ 控制逼近离散的程度
反向梯度恒等近似，偏差集中在概率 0.5 附近对 logits 完全可微，梯度形式完整
推理一致性取阈值即硬门，与训练口径天然一致需将温度退火到低温再取硬门，否则口径漂移
新增超参无温度调度（如 1.0 退火到 0.1）
训练表现实现最短，方差略大更平滑，温度偏高时门值弥散
选档判据快速实验与训练推理同构优先需要可微信号，或 ST 训练持续不稳时启用

3. 消息与信道的设计空间

  • 消息内容。消息向量由门控前的编码器生成，维度取 4 至 16；维度是"单条消息的字节数"，与发送频率共同决定带宽占用。
  • 离散化。把连续消息经 Gumbel 松弛量化为符号（如 8 符号表），逼近真实数字协议的比特流；代价按符号数计量。
  • 信道扰动。训练期以概率 pdrop 丢弃消息、给消息叠加高斯噪声，策略在测试时必须容忍同类扰动，这是对抗信道不确定性的最小正则。
  • 与图结构的叠加。第 016 章的边门控决定"能否发给"，本章发送门控决定"是否发送"；两者相乘得到有效消息，实验时分别测量各自的稀疏贡献。

4. 评估：权衡曲线与通信统计

受限通信方法的标准评估采用一条曲线：横轴为评估期平均每步发送消息数（用硬门统计），纵轴为平均回报；同一方法扫描 β 得到一条曲线，曲线整体越靠上越好。评估必须使用与训练一致的硬门推理（ST 的推理天然为硬门；Gumbel 需要退火到低温）。训练期软门统计与评估期硬门统计的差异若超过百分之几，说明概率分布接近 0.5 的样本过多，离散化不稳定，应降低温度或调整初始偏置。丢包正则的强度通过单独扫描 pdrop 验证：理想的鲁棒化在无丢包评估中损失极小，在有丢包的测试信道中回撤明显更小。

ST 与 Gumbel 的偏差特性可由一个统计量监控：直通估计把采样噪声当作零，偏差最大的区域在 p 靠近 0.5 处（伯努利方差 p(1−p) 的最大值为 0.25），在 p 接近 0 与 1 时偏差消失。记录门控概率落在 [0.4, 0.6] 区间的样本占比：占比长期高于百分之十说明大量决策停在犹豫区，此时或换 Gumbel 松弛并退火降温，或对犹豫样本做重加权。该统计量也能解释门控崩溃的早期征兆：概率从两侧向 0.5 聚拢时占比先升，随后整体滑向零。

5. 数值算例：单步发送决策的经济学

最小可算的模型：某决策点上，发送消息使协作成功概率从 0.6 升到 0.9，成功回报为 1，单条消息的代价系数为 β。发送的净优势 = 0.9 − 0.6 − β = 0.3 − β，决策阈值在 β = 0.3。据此扫描：β ∈ {0.05, 0.1} 时发送占优，β = 0.3 处于临界，β = 0.5 时不发送占优。这个两行算式锚定权衡曲线的两端：β 远小于 0.3 时通信量由任务需求决定，扫描 β 不改变发送率；β 越过阈值后发送率断崖式下降。真实任务的收益结构随状态变化，曲线表现为平滑下降，台阶形状被状态差异抹平，但"阈值附近最敏感"的形态一致，β 的扫描范围应围绕敏感区加密取样。

6. 数值算例：丢包率下的有效通信量

设硬门发送率为 ρ，训练期丢包概率 pdrop = 0.1。评估期平均每步有效消息数约为 ρ × 0.9；以 ρ = 0.5 为例，期望有效消息数由 0.5 降到 0.45。可靠性随窗口长度提升：某智能体连续 5 步都不发送的概率为 0.55 = 3.1%，即 5 步窗口内"至少发送一条"的概率接近 96.9%；两条独立发送的消息中至少一条送达的概率为 1 − 0.12 = 99%，数值经程序核对。两个读数：其一，稀疏通信不等于不可靠通信，接收侧若有跨步记忆（第 016 章的 GRU 状态），间断消息的价值显著高于单步视角的判断；其二，丢包正则的强度应参照失败代价设计，平均无害的丢包若集中在关键同步时刻，策略仍会学到脆弱行为，评估必须包含按关键状态分组的丢包统计。

7. 数值算例：硬预算的对偶上升及其稳定条件

把"平均发送数不超过 Cmax"做在线调节：β ← [β + η ( 平均发送数 − Cmax )]+。用线性响应模型核对收敛：设发送数对 β 的灵敏度为 −50（发送数 = 3 − 50(β − 0.02)），Cmax = 2，η = 0.01，从 β = 0.02 起步的迭代轨迹为 0.0200 → 0.0300 → 0.0350 → 0.0375 → 0.0388 → 0.0394 → 0.0397 → 0.0398，发送数同步收敛到 2.0，数值经程序核对。收敛条件是 η × 灵敏度 < 2，本例灵敏度为 50，故 η 需小于 0.04；η = 0.01 时误差每步减半，约 7 步进入 1% 邻域；η 过大时 β 与发送数来回震荡，日志上表现为发送率与 β 反相波动。工程建议：用最初十余次调节估计灵敏度，再把 η 设在稳定性上限的五分之一以内。实际系统的灵敏度可由最近若干次调节的历史数据直接回归估计，线性响应模型只是把检验条件讲清楚的简化，不影响 η 的取值流程。

实现思路与设计

本节给出受限通信模块的组件与配置。模块挂在第 016 章消息模块的输出端，门控张量与消息布局预留逐边掩码字段。

设计项取值（基线）作用与依据
消息维度8小消息降低单条成本；信息容量与协调精度在消融中权衡

与第 016 章的差异点：消息张量增加门控乘子与代价统计两个字段；训练损失增加 β·C 项；评估器增加通信量统计。门控与边掩码相乘的顺序为"先边掩码、后发送门控"，这样被屏蔽的边不会计入发送代价，代价与物理信道占用的语义一致。

设计决策：代价项预热与门控偏置的分工

门控偏置解决"从零学会发送"的冷启动探索问题：概率初始偏高，通信通道先打开，消息编码器有梯度可学。代价预热解决"过早关闭"的优化问题：β 从零渐增，让策略先形成有通信的价值结构，再逐步施加预算压力。两者都指向同一目标（保留可学习的通信通道），手段分别作用在表示层与目标层。常见失败是只做其一：只偏置不加预热，代价项在早期就把通道关闭；只预热不加偏置，门控在早期因随机梯度漂到低概率区，同样关闭。

关键代码与解读

片段 1：带门控与代价的消息模块

import torch
import torch.nn as nn

class GatedComm(nn.Module):
    """受限通信: 消息经发送门控加权, 同时返回可微代价与硬门统计。"""
    def __init__(self, hidden=64, msg_dim=8, gate_bias=1.0):
        super().__init__()
        self.encoder = nn.Sequential(nn.Linear(hidden, 64), nn.ReLU(),
                                     nn.Linear(64, msg_dim))
        self.gate = nn.Linear(hidden, 1)               # 输出 logits
        nn.init.constant_(self.gate.bias, gate_bias)   # 初始偏置: 鼓励发送

    def forward(self, h, beta=0.02):
        msg = self.encoder(h)                          # (N, msg_dim) 待发内容
        p = torch.sigmoid(self.gate(h))                # (N, 1) 发送概率
        u = torch.rand_like(p)
        hard = (u < p).float()                          # 前向: 硬门 0/1
        # 直通估计: 反向把硬门的梯度当作恒等传回概率
        g = hard + p - p.detach()
        cost = g.sum() * beta                          # 可微代价: 发送数乘系数
        return msg * g, cost, hard.mean().item()       # 消息/代价/发送率

解读：直通估计写成 g = hard + p - p.detach() 是本章梯度机制的全部。（1）前向数值等于 hard（0 或 1），保证消息的真实稀疏性与代价统计的准确性；反向时 p - p.detach() 的梯度为 1，梯度经概率平滑地回传，避免 NULL 梯度。（2）代价项 g.sum() * beta 使用软硬混合的门值：前向按硬门计费（与真实通信量一致），反向带梯度（能把"发太多了"的梯度推回概率）。（3）返回硬门均值供日志观测：它与评估期统计口径一致，是发现"门控崩溃"的第一指标。（4）门控只作用于消息内容，不影响本地状态更新；被关闭的智能体仍能接收他人消息，通信的单向性由消息布局决定。

片段 2：代价项进入训练目标

def gated_comm_loss(task_loss, cost, beta_now, reward_scale=1.0):
    """把通信代价并入训练目标: 在任务损失上减去(加)代价项。"""
    # 收敛纪律: 代价先归一化到与回报同尺度, 再乘当前 beta
    total = task_loss + (cost / max(reward_scale, 1e-8)) * beta_now
    return total

def beta_schedule(step, warmup_steps=20000, beta_target=0.02):
    """代价系数预热: 从 0 线性升到目标值, 期间通信通道先建立。"""
    frac = min(1.0, step / warmup_steps)
    return beta_target * frac

解读：两行代码承载拉格朗日视角的工程化。（1）reward_scale 归一化使成本与回报可比：回报量级为 100 的任务直接使用 β = 0.02 相当于几乎免费，量级错配是"代价项看似存在却不起作用"的最常见原因。（2）代价接入位置在任务损失的加号侧，方向由"最大化回报减代价"取负后变成"最小化损失加代价"；符号写反会把通信越推越多，日志上表现为发送率单调上升。（3）预热函数把 β 变成时间的线性函数，前 2×104 步给通信编码器留出建立语义的时间；min(1.0, ...) 保证预热结束后恒定在目标值。

片段 3：权衡曲线评估器

def tradeoff_curve(run_eval, betas=(0.005, 0.01, 0.02, 0.05, 0.1)):
    """扫描代价系数: 每个 beta 训练一条曲线, 汇报 (通信量, 回报) 点列。"""
    pts = []
    for b in betas:
        policy, stats = run_eval(b)                    # 训练与评估的完整回路
        # 评估期用硬门推理: 统计平均每步发送数与平均回报
        pts.append({"beta": b,
                    "msgs_per_step": stats.msgs_per_step,   # 硬门口径
                    "return": stats.mean_return})
    # 输出按通信量升序排列的曲线, 供绘图与预算选择
    return sorted(pts, key=lambda d: d["msgs_per_step"])

解读：评估器把"受限通信"从单一算法变成一族可选择的运行点。（1）每个 β 对应一次完整训练，报告点是硬门口径的通信与回报；论文与实验记录中必须同时给出两点，只报回报无法体现约束的意义。（2）排序后的点列构成曲线，部署时按可用预算在曲线上选点，这与"拟合一条曲线后选预算"的工程流程一致。（3）五档 β 的间距按近似几何分布选取（×2 左右），覆盖从接近无限制到强限制；若曲线两端仍未包住预算区间，再向外扩档。

常见坑

  • 代价项量级失配。症状：β 扫描出的曲线几乎是水平线，通信量不随 β 变化。原因：回报尺度远大于代价项。修复：先做奖励尺度归一化，再观察发送率对 β 的敏感区间；日志同时打印代价项与任务损失的量级。
  • 门控冷启动关闭通道。症状：训练早期发送率跌破 0.05，此后不再恢复。原因：偏置与预热缺失其一的组合。修复：同时保留初始偏置与 β 预热；用发送率曲线的前 104 步形态判断是否已崩。
  • 训练软门、评估硬门口径混用。症状：报告的通信量与部署实测不符。原因：训练期用软门统计（概率和），评估期硬门计数，两者差距未校验。修复：统一报告硬门口径，并在日志中同时记录两者差值作为离散化稳定性的指标。
  • 丢包正则强度未校准。症状：无丢包评估回撤明显，或测试信道下毫无鲁棒收益。原因：pdrop 与测试信道失配。修复：以实际信道的丢包率量级为基准，取 0.5 至 1.5 倍区间做一维扫描，报告两种评估条件。
  • 边门控与发送门控混淆归因。症状：稀疏化收益算不清是哪一个模块的贡献。原因：两处门控同时改动。修复：消融矩阵固定一个开一个关，四组对照分别统计有效边数与发送数。

练习与思考

  1. 单个智能体、单条消息的情形：回报收益为 1，代价系数 β。写出"发送"与"不发送"的目标值差，求使发送占优的 β 上界。★
    提示
    差值为 1 − β，β < 1 时发送占优。接收侧的协调收益由任务结构给出，该式只用于校准"量级感"：回报以 1 为尺度时，β 在 0.01 至 0.1 之间才能形成有意义的权衡区间。
  2. 把代价预热从 2×104 步缩短到 2×103 步，预测发送率曲线的早期形态与最终回报。★
    提示
    预算压力提前到位，通信编码器尚未学到有用消息就被抑制，发送率低谷更深，最终回报预计低于长预热版本；缩短预热可作为"通信是否真的有价值"的压力测试。
  3. 推导：约束问题 max 𝔼[R] s.t. 𝔼[C] ≤ Cmax 的拉格朗日形式为 max 𝔼[R − βC]，说明 β 与 Cmax 的对应关系及其单调性。★★
    提示
    拉格朗日对偶给出 β 作为乘子；在标准化条件下 β 随 Cmax 减小而增大，最优值函数对 Cmax 的导数为 −β。扫描 β 与扫描预算等价。
  4. 设计对照：ST 直通与 Gumbel 松弛（τ 从 1.0 退火至 0.1）在同一管线上的发送率、回报与训练稳定性。给出判定"离散化是否稳定"的具体指标与阈值。★★
    提示
    指标：训练软门均值与评估硬门均值的绝对差、概率分布的方差、门值在 0.5 附近的样本占比。阈值示例：前后差值超过 5% 判不稳定。预期 ST 训练更快但方差略大，Gumbel 更平滑但需要调温度。
  5. 设计题：实现"硬预算"方案：把平均发送数控制在阈值以内（例如用对偶上升自适应调节 β），给出更新规则、超参与与软惩罚方案的对照实验设计，说明两种方案在曲线形态上的预期差异。★★★
    提示
    对偶上升：β ← [β + η ( 平均发送数 − Cmax )]+，η 为调节步长；软惩罚给定 β 不调节。预期硬预算方案在阈值附近形成折点，软方案给出平滑曲线；两者在曲线中段应重合。

小结

  • 受限信道把通信量写进目标：代价系数 β 是预算约束的拉格朗日乘子，扫描 β 得到回报与通信量的权衡曲线。
  • 发送门控的两种可导化：直通估计器前向硬、反向恒等；Gumbel 松弛可微但需要温度退火。两者都要求训练与评估口径一致。
  • 冷启动由门控偏置与代价预热共同保护，归因实验显示两者缺一不可。
  • 鲁棒化用丢包与信道扰动正则实现；评估统一使用硬门口径并同时报告两种信道条件。
