第一篇 · CTDE 基础与核心算法

第 013 章：HATRPO信任区域策略优化

把信任域从工程近似升级为严格约束：多智能体优势分解引理把联合优势写成按顺序排列的个体优势之和，于是逐智能体施加信赖域约束、按顺序更新，即可获得联合策略的单调改进保证。HATRPO（Heterogeneous-Agent Trust Region Policy Optimisation）给出理论基础与闭式解，HAPPO 给出 PPO 风格的实用版本。

  • 主题：信任区域 / 单调改进保证
  • 关键公式：Aπ(s, a) = Σi=1N Aπi( s, a1:i−1, ai )
  • 预计学时：55 分钟
  • 前置章节：第 012 章

学习目标

  • 理解 MAPPO 裁剪机制的局限：它近似信任域，但不提供多智能体联合更新的单调改进保证。
  • 掌握多智能体优势函数的定义与分解引理的证明（望文变量求和消去）。
  • 掌握顺序更新加逐智能体信赖域约束的改进论证，以及 HATRPO 闭式解与 HAPPO 比率链的对应关系。
  • 会实现 HAPPO 风格的顺序更新：前缀比率链、逐智能体裁剪、随机置换。
  • 能设计实验测量"每轮迭代联合价值是否单调上升"，并理解优势估计近似带来的偏差。

背景与动机

第 012 章的 MAPPO 把全部智能体的比率一起裁剪，简洁有效，但两个理论问题始终悬着：裁剪是对信赖域的可微近似，不构成严格约束；多智能体同时更新时，各智能体的改进方向相互干扰，联合策略的改进没有保证。单智能体信赖域方法（如 TRPO 的每步单调改进）的理论强度，在多智能体设定下能否恢复？

HATRPO（Heterogeneous-Agent Trust Region Policy Optimisation）的回答由三个部件组成：多智能体优势分解引理把联合优势精确拆成按智能体顺序排列的个体优势之和；顺序更新让每个智能体的策略改进"继承"前面智能体的改进结果；逐智能体信赖域约束把每个子问题压回单智能体理论框架，从而整条更新链保持单调改进。HAPPO（Heterogeneous-Agent PPO）用比例裁剪替代信赖域求解，把理论收敛率换成工程可落地性。两条实现共享同一分解结构，本章以 HAPPO 代码为主、HATRPO 闭式解为辅。

核心原理

本节给出多智能体优势的定义、分解引理的证明、顺序信赖域更新的改进论证与两种求解方式。

1. 多智能体优势函数与分解引理

固定智能体更新顺序 1, 2, …, N。定义第 i 个智能体的多智能体优势函数：

Aπi( s, a1:i−1, ai ) = 𝔼ai+1:N∼πi+1:N [ Qπ(s, a1:i−1, ai, ai+1:N) ] − 𝔼ai:N∼πi:N [ Qπ(s, a1:i−1, ai:N) ] 第一项把自身动作 ai 作为条件保留, 第二项对 ai 也取期望; 两者之差即"加入第 i 个动作条件"的边际贡献

分解引理：Aπ(s, a) = Σi=1N Aπi(s, a1:i−1, ai)。证明用望远镜求和：记 Bk = 𝔼ak+1:N[ Qπ(s, a1:k, ak+1:N) ]，约定 B0 = Vπ(s) = 𝔼a1:N∼π[Qπ]，BN = Qπ(s, a)。则 Aπi = Bi − Bi−1，求和后望远镜消去中间项：Σ Aπi = BN − B0 = Qπ(s, a) − Vπ(s) = Aπ(s, a)。直观：智能体 i 的优势度量"它有别于前缀前状态的平均水平"的边际贡献，逐智能体边际贡献之和即联合优势。每一步的期望变量在相邻两项间精确抵消，引理是恒等式，不含任何近似。

2. 顺序信赖域更新与单调改进

更新过程按顺序进行：智能体 1 先更新，智能体 2 在前缀策略已更新的条件下更新，依此类推。每个子问题是一个带信赖域约束的期望优势最大化：

πk+1i = argmaxπi 𝔼s∼ρ, a1:i−1∼πk+11:i−1 [ 𝔼ai∼πi Aπki(s, a1:i−1, ai) ]， s.t. 𝔼s KL( πki(·|s) ‖ πi(·|s) ) ≤ δ 下标中旧策略与更新顺序的耦合是全部要义：自身优势以更新到一半的联合策略为参照, KL 约束只作用于自己的策略。每个子问题对应单智能体信赖域方法, 存在单调改进保证

改进论证的结构：分解引理说明联合优势是各智能体优势之和；子问题把第 i 项提高到不低于零，其余各项在各自更新时不增不减；归纳可推出联合价值 Vπk 随 k 单调不减（在精确求解与足够小步长的前提下）。顺序是论证的骨架：若改为同时更新，"其余各项保持不变"的前提失效，单调性链条断裂，这正是第 012 章并行裁剪的缺口。

3. 两种求解方式

（1）HATRPO 闭式解。子问题在 KL 约束下用镜像下降求解，对 softmax 与高斯策略有近似闭式：

θk+1i = θki + √( 2δ / ( g⊤ F−1 g ) ) · F−1 g g 为该子问题的策略梯度, F 为费舍尔信息矩阵; 步长由 δ 与二阶量共同决定。实现需共轭梯度与线搜索, 计算成本高于 PPO 一个量级

（2）HAPPO 比率链。用 PPO 裁剪替换信赖域求解，前缀比率作为累积权重：

Li(θ) = 𝔼[ M1:i−1 · min( ri Â, clip( ri, 1−ε, 1+ε ) Â ) ]， M1:i−1 = Πj<i rj rj 为第 j 个智能体新旧策略比率。M 刻画"前缀智能体已更新"对样本分布的影响, 是顺序结构在重要性采样上的显式痕迹; 实现中 M 的梯度被截断（detach），梯度只经 ri 回流

HAPPO 每轮迭代按随机置换顺序对全部智能体各做一轮裁剪更新，置换保证没有任何智能体固定占据前缀位置，长期而言信用分配公平。理论保证在 HAPPO 中退化为直觉指导：顺序与权重结构保留了分解引理的形状，严格单调性以裁剪近似取代。

4. 优势估计的近似

精确计算 Aπi 需要对后缀动作求期望，代价随智能体数增长。广泛采用的近似是用集中式评论家给出的联合优势 A(s, a)（GAE 计算）作为每个 Aπi 的替身，比率链 M1:i−1 负责吸收顺序结构的效应。该近似引入偏差但保留了分解结构的主要收益；精确版本在主代码之外的对照实验中实现，用于量化近似的代价。

5. 数值算例：分解引理的逐项核对

取两智能体各两动作的联合 Q 表 Q = [[6, 2], [3, 1]]（行对应智能体 1 的动作，列对应智能体 2 的动作），后缀期望用均匀分布计算：B0 = (6 + 2 + 3 + 1) / 4 = 3，B1 为固定第一动作后的行均值 (4, 2)，B2 即 Q 条目本身。全部数值经程序核对：

联合动作 (a1, a2)QAπ1 = B1 − B0Aπ2 = Q − B1两项之和Q − V（联合优势）
(0, 0)64 − 3 = 1.006 − 4 = 2.003.003.00
(0, 1)21.002 − 4 = −2.00−1.00−1.00
(1, 0)32 − 3 = −1.003 − 2 = 1.000.000.00
(1, 1)1−1.001 − 2 = −1.00−2.00−2.00

逐行解读：Aπ1 只依赖 a1，动作 0 的边际优势 1.00 来自"行均值 4 高于全表均值 3"；Aπ2 条件于 (a1, a2)，在同一行内衡量列选择，例如 (0, 0) 处的 2.00 表示"第一动作固定为 0 时，第二动作选 0 比行内平均多出 2.00"。两项之和逐行等于 Q − V，望远镜恒等式在这个 4 行小表上完全兑现。该表同时给出顺序更新的解释：先更新智能体 1 会优先沿行方向改进（让动作 0 的概率上升），更新智能体 2 时再在新的行分布下沿列方向改进（(0, 0) 相对行均值仍正，强化继续）。

6. 闭式解的步长归一化（数值核对）

HATRPO 闭式解中步长的作用是让 KL 恰好抵达 δ。用一维标量情形核对：设梯度 g = 1、费舍尔信息 F = 4、约束 δ = 0.02，则步长 = √(2δ / (g F−1 g)) · F−1 g = √(0.04 / 0.25) × 0.25 = 0.4 × 0.25 = 0.1；参数移动 0.1 后按二次型 KL ≈ ½ F (Δθ)² = ½ × 4 × 0.01 = 0.02，恰好等于 δ，数值经程序核对。工程含义：步长公式把"移动多少"与"曲率多大"绑定，曲率 F 越大（策略分布越尖锐）步长越小；维度上升后 F 由共轭梯度近似求解，还需线搜索修正二次近似的残差，这正是闭式版比裁剪版昂贵的根源。

7. 三者对照与适用边界

维度MAPPO（第 012 章）HAPPO（本章）HATRPO（本章）

理论保证近似信任域，无联合改进保证结构保留，严格性由裁剪近似精确求解前提下每步单调改进
每次迭代成本最低低，前缀链为标量运算高一个量级，费舍尔矩阵与线搜索为主
适用场景大规模任务、快速实验异构智能体、需要顺序结构收益小中规模、验证理论性质

选择顺序：先用 MAPPO 建立基线；出现"并行更新互相拖累"的症状（回报振荡、按智能体消融差异大）时切换到 HAPPO；只有需要严格单调性实验或小规模理论验证时才使用 HATRPO。三者的数据层与价值函数完全共用，迁移成本集中在一个更新循环内。

适用边界需要写清楚：单调改进论证的前提是每个子问题被精确求解且优势估计的偏差受控，实际实现中裁剪与联合优势替身都引入偏差，保证退化为"结构性引导"；批次内策略相关性高时，优势估计误差沿顺序链被前缀比率放大，表现为后几轮回报下滑，与第 012 章"轮数过多"的症状同源，处理方式一致：降低轮数，或缩短同一批数据的复用窗口。监控建议：每轮迭代在固定评估状态批上估计并记录 V 曲线，连续多轮下降时优先检查优势替身的偏差与轮数设置，再核对置换日志中是否存在连续相同的顺序。把分解引理验证与置换检验一并挂进训练前流水线后，顺序结构相关的主要故障基本可以在启动前拦截。

实现思路与设计

本节给出 HAPPO 的实现结构与配置：集中式价值函数产出的联合优势、按置换顺序的逐智能体更新、前缀比率链。

设计项取值（基线）作用与依据
演员结构各智能体独立 MLP 64×64（异构兼容）HATRPO 家族面向异构智能体；同构时可叠加共享，作为对照变量
价值函数集中式 V(s)，MLP 128×128与第 012 章同构，优势经 GAE 计算

KL 参照（HATRPO 档）δ = 0.02，伴随线搜索仅闭式版使用；提供与 HAPPO 的对照

与第 012 章的差异点集中在更新循环内部：并行裁剪换为顺序裁剪，新增置换采样与前缀比率链；网络与数据层完全不动。对照实验由此天然成立：同一份缓冲、同一组超参，唯一的差异是"更新顺序结构"。

设计决策：前缀比率在对数域累加并截断梯度

前缀比率是 (N−1) 个比率的连乘，智能体数增加或在多轮更新后，数值会指数级偏离 1 并触发溢出。对数域累加（sum of log ratios）在数值上稳健，指数还原时自然给出乘性权重。梯度截断的依据来自分解结构：M1:i−1 描述"前缀智能体的更新对数据分布的影响"，在更新第 i 个智能体时它是既成事实，应作为权重常数处理。若允许梯度穿透 M，不同智能体的更新会通过比率链互相纠缠，顺序结构的理论形状被破坏。

关键代码与解读

片段 1：分解引理的数值验证

import numpy as np

def prefix_exp(q_tab, k, a_prefix, nA, N):
    """B_k = E[Q(s, a_{1:k}, a_{k+1:N})]: 对后缀动作均匀求期望。"""
    total, cnt = 0.0, 0
    for a_rest in np.ndindex(*(nA,) * (N - k)):
        total += q_tab[a_prefix + a_rest]      # 联合动作索引直接查表
        cnt += 1
    return total / cnt

def verify_decomposition(q_tab, n_agents, nA, atol=1e-6):
    """验证 A(s,a) = sum_i (B_i - B_{i-1}), 望远镜求和恒等。"""
    N = n_agents
    b0 = prefix_exp(q_tab, 0, tuple(), nA, N)  # V(s): 全动作均匀期望
    for a in np.ndindex(*(nA,) * N):           # 遍历全部联合动作
        lhs = 0.0
        for i in range(N):
            # 第 i 项 = 固定前缀到 i 的期望 减去 固定前缀到 i-1 的期望
            lhs += prefix_exp(q_tab, i, a[:i], nA, N) \
                 - prefix_exp(q_tab, i - 1, a[:i - 1], nA, N)
        # 求和后只剩 B_N - B_0 = Q(s,a) - V(s), 即联合优势
        assert abs(lhs - (q_tab[a] - b0)) < atol, f"分解失败于 {a}"
    return True

解读：验证脚本的存在意义是让引理的"望远镜消去"变成可执行的断言。（1）prefix_exp 对应定义中的 Bk：对第 k 个之后的动作求均匀期望（用均匀分布代替策略期望不损失一般性，引理对任意固定后缀分布都成立）。（2）循环里的 lhs 逐项累加 Bi − Bi−1，中间项两两抵消；断言比较的是"累加结果等于联合优势"，只要实现中前缀索引切法不一致（例如 a1:i−1 与 a1:i 错位），断言立即失败。（3）该测试与第 006 章的 IGM 验证、第 008 章的 QTRAN 验证属于同一工程传统：算法级恒等式配穷举级测试。

片段 2：HAPPO 顺序更新

import torch

def happo_update(actors, batch, perm, eps=0.2):
    """按置换顺序逐个更新: 前缀比率链作为常数权重。"""
    obs, idx, acts, old_logp, adv = batch.split()
    log_m = torch.zeros(obs.shape[0], dtype=torch.float32)   # 前缀对数比率
    for i in perm:                                           # 顺序遍历置换
        dist = actors[i](obs[:, i])                          # 每个智能体自己的演员
        logp = dist.log_prob(acts[:, i])                     # 当前策略
        r = torch.exp(logp - old_logp[:, i])                 # 自身比率
        surr = torch.min(r * adv, r.clamp(1.0 - eps, 1.0 + eps) * adv)
        loss = -(torch.exp(log_m).detach() * surr).mean()    # 前缀权重常数化
        actors[i].optimizer.zero_grad()
        loss.backward()
        actors[i].optimizer.step()                           # 只更新当前智能体
        # 前缀链吸收本次更新: 后续智能体看到的分布已包含第 i 个
        log_m = log_m + (logp - old_logp[:, i]).detach()

解读：这段循环是理论结构中"顺序"二字的完整实现。（1）log_m 在对数域累加前缀比率，更新第 i 个智能体时经 exp 还原为权重并 detach，梯度路径严格限制在当前智能体；这对应设计决策中"既成事实作为常数"的约定。（2）循环结束后把本次比率写回前缀链，后续智能体在计算权重时"知道"前面的策略已经前移，重要性采样的参考点随顺序推进，这正是分解引理中前缀条件（a1:i−1 已更新）的数值形态。（3）每个智能体有自己的优化器与参数，更新互不触碰；顺序由 perm 决定，每轮迭代重新采样置换。

片段 3：置换采样与更新轮循环

def train_epochs_happo(actors, critic, buffer_batch, epochs=3, seed=0):
    """多轮顺序更新: 每轮一个随机置换, 保证前缀位置公平轮换。"""
    g = torch.Generator().manual_seed(seed)
    n = len(actors)
    logs = []
    for ep in range(epochs):
        # 每次迭代采样一个新置换: 无智能体固定占据前缀, 信用分布长期无偏
        perm = torch.randperm(n, generator=g).tolist()
        stats = happo_update(actors, buffer_batch, perm)
        logs.append({"epoch": ep, "perm": perm, "stats": stats})
    return logs

解读：置换采样是公平性的实现机制。（1）若顺序固定为 1 至 N，排在前面的智能体在每轮迭代都"先行改进"，其优势权重以旧分布为参照，长期获得更准确的学习信号；排尾的智能体承担前缀漂移带来的样本失配。随机置换把这种位置收益在期望意义下均摊。（2）日志同时记录置换与统计量，复盘时可以把"某轮回报掉点"与"不利置换"关联起来检验。（3）轮数取 3 与第 012 章保持一致，使 HAPPO 与 MAPPO 的对照控制在同一数据复用强度上。

常见坑

  • 固定更新顺序。症状：某些智能体长期学习更快，回报结构偏科。原因：位置收益未被均摊。修复：每轮迭代采样随机置换，并记录置换序列供复盘。
  • 前缀比率未 detach 或精度不足。症状：梯度通过比率链互相污染，训练出现联动震荡；或连乘在多轮后下溢为 0 与溢出交替。原因：乘性链在普通数值域失控。修复：对数域累加、更新前 exp 还原、对权重做截断上限以兜底极端值。
  • 顺序循环内未更新参考点。症状：与"并行裁剪加权重"的差异消失，顺序结构的收益无法复现。原因：log_m 在循环外一次性算好，未随更新推进。修复：把"写回前缀链"放在每个智能体更新之后，并用单元测试断言第二次迭代的权重与第一次不同。
  • 优势近似未经声明就使用。症状：论文对比时"分解引理的严格版本"与代码行为不符。原因：实现用联合优势代替 Aπi 而未标出。修复：在实验记录中显式声明近似档位，并保留精确版对照（后缀期望采样估计）。
  • 把 HATRPO 闭式解直接搬运到大规模网络。症状：每次更新耗时失控。原因：费舍尔矩阵与共轭梯度开销随参数量上升。修复：超过约 105 参数的网络改用 HAPPO 裁剪档，闭式解留作小规模验证工具。

练习与思考

  1. 两智能体各两动作，联合 Q 表取任意 2×2 数值。手写 B0、B1、B2 的表达式，验证对每个联合动作 a 有 (B1−B0) + (B2−B1) = Q(a) − V。★
    提示
    B0 为全表均值，B1 为固定第一个动作后的行均值，B2 为单个条目。相加后中间量消去，恒等式与数值取值无关。
  2. 把置换固定为自然顺序，重复 5 个随机种子训练，记录各智能体单独评估回报的均值。与随机置换版本比较，预测差异方向并解释其信用分配根源。★
    提示
    固定顺序下前缀智能体的学习信号更"新鲜"，预计其单独回报略高；随机置换下差距收紧。差异幅度与任务耦合强度正相关，耦合越强位置效应越大。
  3. 写出分解引理的完整证明：定义 Bk，说明 Aπi = Bi − Bi−1 的成立步骤，并给出望远镜求和。★★
    提示
    关键在于相邻两项的期望变量域恰好互补：第一项对 ai+1:N 求期望，第二项把 ai 也纳入期望，两者的差恰为"加入第 i 个动作条件"的边际量。求和后仅剩首尾。
  4. 设计实验测量单调性：每轮迭代结束在固定评估状态上估计 Vπk（多次滚动平均），绘制随迭代的曲线，比较 MAPPO 与 HAPPO。说明预期差异与各自的噪声来源。★★
    提示
    预测：HAPPO 曲线更接近台阶式上升（顺序改进的结构痕迹），MAPPO 抖动更大；评估噪声来自滚动采样，可用固定种子与更多滚动次数压低。
  5. 设计题：给出精确估计 Aπi 的一种方案（对后缀动作做采样期望），分析其每次更新的额外前向次数与偏差方差特性，并给出用其做"近似偏差量化"实验的协议。★★★
    提示
    对每个样本对后缀动作采 M 组样本，构造 B 的两个估计再作差；前向次数随 N·M 增长。协议：小规模任务上精确版与近似版同种子对照，比较优势相关性、更新方向余弦相似度与最终回报。

小结

  • 多智能体优势分解引理 A = Σ Aπi 是望远镜求和恒等式；顺序更新的前缀结构由此获得严格的改进链条。
  • 逐智能体信赖域子问题保留单智能体理论保证；HATRPO 闭式解与 HAPPO 比率链是同一结构的两种求解方式。
  • HAPPO 实现要点：前缀对数比率、权重 detach、参考点随顺序写回、每轮随机置换保证公平。
  • 优势估计的实用近似（联合优势替身）保留分解结构的主要收益，偏差需要显式声明与对照量化。
