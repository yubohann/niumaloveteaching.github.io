第二篇 · 训练工程与稳定性

第 030 章：异构智能体协作

本章讲异构智能体（Heterogeneous Agents）的组织与训练：异构性的四个维度、参数共享的四种配置、角色条件化与智能体身份嵌入、异构观测编码与角色分组价值分解，以及角色映射的复现约束。

  • 主题：网络组织 / 角色与共享策略
  • 关键公式：πi(a | oi, zi)，zi = Embed(rolei)
  • 预计学时：55 分钟
  • 前置章节：第 029 章 多智能体连续动作空间处理

学习目标

  • 理解异构性的四个维度（观测、动作、动力学、奖励与角色），能对给定任务判断异构来源。
  • 掌握参数共享的四种配置：完全共享、共享主干加身份嵌入、角色分组共享、完全独立，及其参数量与适用条件。
  • 掌握角色条件化与智能体身份嵌入的实现方式，理解嵌入维度选择与过拟合风险的权衡。
  • 掌握异构观测编码器的组织：按模态分组编码、统一隐空间投影、与价值分解网络的对接。
  • 能诊断身份顺序错配、填充污染两类典型故障，并给出角色映射的复现约束。

背景与动机

真实的多智能体系统很少由同型号智能体组成：侦察单元观测半径大而动作简单，攻击单元动作空间大而感知范围小；一个任务中同时存在快速小载体与慢速大载体时，两者的动力学、动作维度与最佳行为差异显著。这类系统在观测空间、动作空间、动力学或职责上存在结构性差异，统称异构智能体系统（Heterogeneous Multi-Agent System, HMAS）。

第 004 章的参数共享对同构智能体高效，对异构智能体则面临两难：完全共享会让不同职责的智能体被迫共用一套策略，梯度相互干扰（第 027 章的冲突诊断直接适用）；完全独立则每个智能体单独学习，样本效率随智能体数量下降。本章给出介于两端之间的组织手段，核心思路是把"共享什么、区分什么"显式设计为网络结构决策。与第 029 章的接口层分工：动作与观测的维度差异在接口层处理，网络结构层面的共享与区分在本章处理，第 031 章进一步讨论智能体数量增长时的组织与计算缩放。

核心原理

1. 异构性的四个维度

判断一个任务的异构来源，按四个维度逐一检查：

维度表现对训练系统的影响
观测异构维度不同、模态不同（图像、向量、雷达）编码器需按模态分组，观测归一化分组统计
动作异构离散与连续混合、维度不同动作头分组，联合动作拼接顺序固定
动力学异构速度、质量、转向能力不同同一观测输入对应不同最优行为，策略容量要求高
职责异构角色分工（侦察、攻击、支援）可显式建模为角色条件，也可由训练涌现

四个维度并不总是同时出现：动力学异构最难处理，因为它不改变接口维度，只改变"输入到行为"的映射，需要结构或条件化手段来区分。职责异构是显式标签，可以低成本注入；先把显式异构处理干净，再观察动力学异构是否仍需进一步区分。

2. 参数共享的四种配置

从共享到独立连续排列：

  • 完全共享。全部智能体使用同一套参数，参数量与智能体数量无关。适用条件：智能体同构且观测同构（第 004 章的默认配置）。
  • 共享主干加身份嵌入。网络主体共享，输入端拼接智能体身份或角色的嵌入向量 zi，策略形式 πi(a | oi, zi)。参数量只增加嵌入表，表达力介于共享与独立之间。
  • 角色分组共享。按角色把智能体分组，组内共享参数、组间独立，参数量为角色数乘单组规模。适用条件：角色语义明确且组内动力学接近。
  • 完全独立。每个智能体一套参数，参数量线性增长，仅在智能体数量少且差异极大时使用。

选择流程可以形式化为三个问题：接口维度是否相同；动力学是否同构；角色标签是否可信。接口不同先分组；接口相同而动力学不同时先用身份嵌入试探，若诊断显示共享层梯度冲突持续（余弦相似度长期为负），升级为角色分组。身份嵌入有一个被低估的风险：网络在表达力足够时会忽略嵌入、退化为共享策略，此时嵌入形同虚设；诊断方法是打乱嵌入后观察行为变化，无变化即说明嵌入未被使用。

3. 角色条件化与身份嵌入的实现

zi = Embed(rolei) ∈ Rdz，πi(a | oi, zi) = Softmax/Wμ( fθ( [enc(oi), zi] ) ) enc 为观测编码器，[·, ·] 表示拼接；嵌入维度 dz 常取 8 到 32

实现要点有三：其一，嵌入既可以固定（角色独热）也可以可学习，可学习嵌入让"角色相似度"由数据决定，代价是训练数据不足时过拟合到个别智能体；其二，嵌入需要在智能体维度上对齐拼接，批量计算时通过索引表一次取出全部嵌入，避免循环；其三，角色到索引的映射是模型产物的一部分，必须随检查点保存并在加载时校验顺序，映射错位会让两个角色交换策略且难以从损失曲线上察觉。

4. 异构价值分解

值分解框架对异构智能体的扩展沿两个位置进行：个体端的编码器与价值头按组实例化，混合端接收角色的条件信息后合成团队价值：

Qtot = fmix( Q1(o1; θg(1)), …, QN(oN; θg(N)) ; 角色统计向量 ) g(i) 为智能体 i 的角色分组索引；混合器额外接收角色构成信息以区分不同编队

观测维度不同时，各分组的编码器先把输入映射到统一隐空间维度，再进入个体价值头；混合器输入端因此总是同维向量，单调性约束的逐元素单调结构不受影响。角色统计向量（各角色智能体数量）让混合器感知编队构成，同一套混合参数可以服务多种编队组合；省略该信息时混合器对不同编队的价值尺度失去区分能力，跨编队泛化显著变差。个体奖励不同的任务（半合作结构）在混合器处只聚合团队相关分量，个体专属分量留在个体头，避免污染团队价值，第 034 章展开该主题。

5. 数值算例：四种共享配置的参数量

取单角色子网络参数量 P = 20 万、角色数 R = 3、智能体数 N = 12、嵌入维度 dz = 16（数值经程序核对）：

配置参数量表达式数值相对完全共享
完全共享P200,0001.0 倍
共享主干加角色嵌入P + R·dz200,0481.00024 倍
角色分组共享R·P600,0003.0 倍
完全独立N·P2,400,00012.0 倍

读数：角色嵌入的额外参数只有 48 个（约为完全共享的万分之 2.4），表达力代价是"角色差异只能经一个低维向量进入网络"；分组共享按角色数线性增长，与智能体数量解耦；完全独立随 N 线性增长，N = 12 时已是共享主干方案的十二倍。选择次序清晰：先试嵌入（参数代价近零），嵌入验证失效再分组（三倍量级），独立方案留作小规模对照。

6. 数值算例：嵌入是否被使用的可检验判据

用动作分布差异度量角色分化强度。设两个角色在同一观测下的策略为 softmax(0, 1) 与 softmax(1, 0)，即 (0.269, 0.731) 与 (0.731, 0.269)，两者的 KL 散度为 0.4621 奈特（数值经程序核对）。诊断流程因此可以量化：在固定评估状态集上打乱角色嵌入，逐状态计算打乱前后动作分布的 KL 散度并取均值。嵌入被有效使用时均值应在 0.1 奈特量级以上（角色分化越强数值越大）；均值低于 0.01 奈特说明网络几乎忽略嵌入，嵌入形同虚设，应转而使用角色分组或增大角色相关训练信号。该检验同时适用于角色嵌入与身份嵌入，是上线前的常规验收项之一。

7. 角色映射的复现契约

角色映射是模型产物的一部分：检查点保存"智能体索引到角色标签到分组索引"的三级映射，加载时逐项断言。典型事故形态是训练时把攻击映射为组 0、支援映射为组 1，加载时按字典序重排，两个角色的策略被交换；损失曲线完全正常（两组参数都在有效工作），行为却与训练期不符，只能靠回放记录发现。防错措施有三：映射表与网络结构定义在同一文件声明；部署入口用固定角色样本做冒烟测试（各角色执行若干步并断言动作统计落在训练期分布特征内）；角色标签的语义在任务生命周期内不允许改变。同一条契约适用于第 031 章的位置编码与规模扩展配置。

嵌入的诊断还有第二条通道：统计嵌入层参数梯度范数与主干梯度范数的比值，比值长期低于千分之一说明角色信号几乎不进入主干计算，与打乱检验互为佐证。两项诊断合并进同一次监控周期执行，额外开销可忽略；两者都通过后角色嵌入版本才值得投入长训练，否则直接跳到角色分组方案，节省反复调参的成本。梯度比值的参考区间来自量级推算：嵌入表参数量远小于主干时，健康状态的梯度比值通常也在千分之一到百分之一之间，绝对值不是判据，长期趋零才是报警信号。

实现思路与设计

网络工厂按角色配置生成模块：每个分组一个编码器与价值头，共享部分（主干、混合器）只实例化一次。角色配置表定义分组划分、每组观测维度与动作维度，训练与加载两侧共用。

参数默认值作用取值依据
共享配置角色分组共享决定参数组织同构任务退化为完全共享；异构任务按角色划分
嵌入维度 dz8 至 32身份信息容量角色数少时取下限；嵌入被忽略时增大训练信号或加大维度
嵌入可学习性可学习数据驱动的角色相似度每角色样本量充足时启用；否则用独热固定
隐空间维度64 至 128统一异构观测各分组编码器输出投影到同一维度，供混合器消费
角色统计向量启用编队构成感知任务含多种编队组合时必需
角色映射校验加载时断言防止映射错位角色数、顺序与检查点记录逐项比对

与第 029 章的衔接点：动作头在本章按角色分组，连续与离散接口的类型标记在分组内保持一致；若同一角色内动作维度仍不同，说明分组划分过粗，需要先修正分组再进入训练。

关键代码与解读

片段 1：角色条件化的策略网络

import torch
import torch.nn as nn

class RoleConditionedPolicy(nn.Module):
    """共享主干 + 角色嵌入：一套主体参数服务多个角色。"""
    def __init__(self, obs_dim, act_dim, n_roles, embed_dim=16):
        super().__init__()
        self.embed = nn.Embedding(n_roles, embed_dim)   # 角色到向量的查表
        self.trunk = nn.Sequential(nn.Linear(obs_dim + embed_dim, 128), nn.ReLU(),
                                   nn.Linear(128, 128), nn.ReLU())
        self.head = nn.Linear(128, act_dim)
        nn.init.normal_(self.embed.weight, std=0.02)    # 小标准差初始化：训练早期嵌入近似等价

    def forward(self, obs, role_ids):
        z = self.embed(role_ids)                        # 批量一次取出全部角色嵌入
        x = torch.cat([obs, z], dim=-1)                 # 拼接位置固定：观测在前、角色在后
        return self.head(self.trunk(x))

解读：嵌入初始化为接近零的噪声是刻意选择：训练早期所有角色获得近似相同的策略，避免随机初始化强行把角色行为分开后难以重新融合。拼接顺序（观测在前、角色在后）是跨模块契约的一部分，混合器与对手建模模块读取同一约定。需要区分身份嵌入与角色嵌入：角色数是小常数、嵌入表极小；若改用逐智能体身份，嵌入表随智能体数量增长，规模化任务（第 031 章）需要换用角色级或位置级编码。

片段 2：角色分组参数共享的管理器

class GroupedModules(nn.Module):
    """按角色分组实例化子网络；组内共享参数，组间独立。"""
    def __init__(self, role_sizes, obs_dims, act_dims, hidden=128):
        super().__init__()
        # 逐组构建：每个角色一份编码器与输出头，参数量与角色数成正比
        self.encoders = nn.ModuleDict()
        self.heads = nn.ModuleDict()
        for role, n in role_sizes.items():
            self.encoders[role] = nn.Sequential(nn.Linear(obs_dims[role], hidden), nn.ReLU())
            self.heads[role] = nn.Linear(hidden, act_dims[role])

    def forward(self, obs, role_ids, role_of):
        # 按角色分桶前向：同一批内不同角色的观测维度不同，先分组再各自处理
        outputs = {}
        for role in self.encoders:
            idx = [i for i in role_ids if role_of[i] == role]
            if idx:
                h = self.encoders[role](obs[idx])
                outputs[role] = self.heads[role](h)
        return outputs

解读：该结构把"共享粒度"实现为可配置的字典，新增角色只增加一个条目，混合、共享、独立三种极端配置都是它的特例（全部角色同一键即完全共享，每智能体一键即完全独立）。按角色分桶的前向避免了对异构维度的填充，代价是引入了批内分支，在小批次下 GPU 利用率下降；工程上通常保证每个角色在批次中的样本量达到数十的量级。对连续动作角色，输出头替换为第 029 章的均值与标准差双头，管理器结构不变。

片段 3：异构观测编码与统一隐空间

class HeteroEncoder(nn.Module):
    """不同模态观测各自编码后投影到统一隐空间，供混合器消费。"""
    def __init__(self, modal_dims, latent=96):
        super().__init__()
        self.encoders = nn.ModuleDict({
            "vec": nn.Sequential(nn.Linear(modal_dims["vec"], 64), nn.ReLU()),
            "grid": nn.Sequential(nn.Conv2d(1, 16, 3, stride=2), nn.ReLU(), nn.Flatten(),
                                  nn.Linear(16 * ((modal_dims["grid"][0] - 2) // 2) *
                                                ((modal_dims["grid"][1] - 2) // 2), 64), nn.ReLU()),
        })
        # 统一投影：把各模态编码压到同一隐空间，混合器输入端维度恒定
        self.project = nn.ModuleDict({k: nn.Linear(64, latent) for k in modal_dims})

    def forward(self, batch):
        feats = []
        for modal in self.encoders:
            if modal in batch:                          # 智能体只携带自己的模态数据
                x = batch[modal]
                if modal == "grid":
                    x = x.unsqueeze(1)                  # 单通道图像增加通道维
                feats.append(self.project[modal](self.encoders[modal](x)))
        return torch.stack(feats, dim=1)                # (batch, n_agents, latent)

解读：统一隐空间是多模态异构的枢纽设计：各编码器容量的差异被投影层吸收，混合器与后续价值头只面对固定维度。按模态键组织前向让缺模态的智能体自然跳过对应分支，无需零填充（零填充会被网络学习为有效信号，即"填充污染"）。投影后的堆叠顺序按智能体索引排列，与动作拼接顺序共用同一约定表。编码器容量的分配原则是：信息密度高的模态（如网格）给卷积结构，低维结构量（位置、速度）给全连接，两者输出的隐维度对齐到同一 latent。

常见坑

  • 身份信息管理不当。角色映射顺序错乱使两个角色的策略被交换；嵌入维度远大于角色信息量时过拟合到个别智能体，更换配置即失效。修复：映射表进入检查点并逐项断言；dz 从 8 到 16 起步，用跨编队泛化验证。
  • 身份嵌入被网络忽略。表达力不足或角色差异未被数据区分时，嵌入梯度趋零，网络退化为共享策略。修复：打乱嵌入观察行为变化；无变化时改为角色分组共享。
  • 异构观测用零填充对齐。填充位被网络当作有效观测学习，智能体学到"零即缺席"的伪特征，跨场景泛化变差。修复：按模态分支处理，缺模态直接跳过。
  • 分组过粗。把动力学相差较大的智能体并入同一组，组内梯度冲突持续。修复：用第 027 章的余弦相似度诊断，冲突持续则细分分组。
  • 混合器缺少编队感知。不同角色配比的任务共用混合器而无角色统计输入，团队价值尺度失准。修复：混合器输入拼接角色统计向量。

练习与思考

  1. 推导：设角色数为 R、每角色子网络参数量为 P、嵌入表参数量为 R·dz，写出完全共享、角色分组共享、完全独立三种配置的参数量表达式，并给出智能体数量 N 增大时三者的渐近比较。★
    提示
    完全共享为 P；分组为 R·P 与 N 无关；完全独立为 N·P 随 N 线性增长。嵌入方案为 P + R·dz，当 P 远大于 R·dz 时几乎不增加参数量。
  2. 改参数预测：把角色嵌入维度从 16 提高到 256，预测训练集内回报与跨编队评估回报的差距变化，并解释偏差与方差的来源。★
    提示
    大嵌入提升训练集表达力，可能轻微改善内部回报；参数量增加带来过拟合，跨编队评估差距扩大，方差上升。
  3. 设计：为一个含侦察、攻击、支援三种角色的 6 智能体任务设计参数共享方案，给出分组划分、每组的输入输出维度、嵌入配置与诊断指标，并说明为何不允许把支援与攻击合为一组。★★
    提示
    两角色的动作空间与动力学差异同时存在，合并必然触发持续梯度冲突；侦察与支援若观测模态相近可尝试合并并验证冲突指标。
  4. 实验设计：比较共享嵌入与角色分组两种方案在训练回报、参数量、跨编队泛化三方面的表现，说明如何固定随机种子与编队采样以构成受控对比。★★★
    提示
    两方案共享同一训练-评估编队分布；报告参数量差异作为解释变量；跨编队泛化用训练未见过的角色配比评测。

小结

  • 异构性分观测、动作、动力学、职责四个维度；显式维度用接口层处理，动力学异构需要结构条件化或分组。
  • 参数共享四配置：完全共享、共享主干加嵌入、角色分组、完全独立；选择依据为接口同构性、动力学同构性与角色标签可信度。
  • 角色嵌入需小初始化、固定拼接约定、随检查点保存映射；嵌入是否被使用应通过打乱验证。
  • 异构价值分解按角色实例化个体端，编码器投影到统一隐空间，混合器接收角色统计向量感知编队构成。
