第五篇 · 研究复现与系统集成

第 097 章：多智能体基准与评测平台

评测生态决定研究的可比性：本章梳理 MPE、SMAC、PettingZoo、MAgent、Google Research Football、Hanabi 等基准家族的特征与适配场景，给出协议固定要素、可比性威胁清单与统一评测脚本的搭法。

  • 主题：基准（Benchmark）与评测协议
  • 关键公式：胜率置信区间 p̂ ± 1.96√(p̂(1−p̂)/n)、基准选择矩阵（规模 × 观测结构 × 奖励类型）
  • 预计学时：55 分钟
  • 前置章节：第 096 章

学习目标

  • 了解主流基准家族的特征差异：观测结构、动作空间、规模量级与奖励类型。
  • 掌握评测协议固定要素：评估回合数、难度等级、评估种子集与贪心开关。
  • 理解可比性威胁清单：版本漂移、默认参数差异、协议差异与统计口径差异。
  • 学会按研究问题选择基准，特别是通信与协作研究对观测缺口的要求。
  • 能搭建注册表加统一评估函数的评测脚本，产出跨基准的可比报告。

背景与动机

多智能体研究没有单智能体领域那样统一的基准共识：有人用粒子环境，有人用实时策略游戏，有人用网格聚合任务，不同基准上的结论经常无法互推。评测平台的价值因此有两层：提供标准任务降低对比成本，以及通过协议与日志制度保证数字的可比性。前者是任务供给，后者是可信性基础设施。

可比性威胁在实践中比想象中严重：同一基准的两个版本可能因引擎补丁改变物理行为；同一版本的不同论文可能修改了默认奖励尺度；同一算法在两个实现里的"环境步"定义可能不同（决策步与仿真步）。本章按"家族特征、协议要素、威胁清单、选择原则、脚本实现"五段组织，与第 095、096 章的统计方法配套：平台提供任务与协议，统计方法提供比较规则。

核心原理

1. 基准家族特征

基准观测结构动作空间规模量级适配研究
MPE（多智能体粒子环境）连续位置与速度，局部视野连续或离散2 到 10合作、竞争、混合动机的基础验证
SMAC（星际争霸多智能体挑战）部分可观测，单位异构离散，动作空间大2 到 27 单位值分解、信用分配、微操协同
PettingZooTick 同步的多智能体接口标准视子环境而定2 到数十接口统一化、经典博弈复现
MAgent 系列网格局部观测离散移动与攻击数十到数百大规模群体行为、可扩展性
Google Research Football长时程，连续控制加离散动作混合每队 11（含控制子集）长时程协作、层次结构
Hanabi不完全信息，卡牌对局离散2 到 5通信协议、心智理论

选择基准的第一步是问题匹配，流行度只是次要参考：通信研究需要观测缺口（局部视野必须小到信息共享成为必需），信用分配研究需要异构单位与稀疏奖励，可扩展性研究需要规模可调的智能体数量。第二个维度是评测成本：跑满十个种子的成本决定矩阵规模，粒子环境适合快速迭代，长时程环境适合最终验证。

2. 评测协议固定要素

跨论文可比的最小协议集合包含五项：

  • 评估回合数：32 回合起步，胜率的标准误约 1.96√(p̂(1−p̂)/n)，p̂ = 0.5 时约 ±0.17（95% 区间宽度）；
  • 难度等级：按基准自身的难度轴选取（地图复杂度、对手强度、初始兵力），报告时注明具体等级名；
  • 评估种子集：固定且公开的种子列表，训练种子与评估种子分离；
  • 策略模式：贪心或采样，二选一并全程统一；
  • 计胜规则：按基准定义的胜负与截断处理，说明截断是否计胜。

协议要素一旦公开，其他实验室才能复算。缺少任意一项数字都只能作为内部参考，不能进入跨论文比较。

3. 可比性威胁清单

  • 版本漂移：基准引擎补丁改变单位行为或奖励数值，同一地图名称下任务已变。修复：在配置与报告中记录引擎版本与内容唯一标识。
  • 默认参数差异：视野半径、最大回合长度、奖励缩放被局部修改而未声明。修复：非默认参数全部进入配置表并加偏差列。
  • 环境步定义差异：决策步与仿真步的换算系数不同，横轴 100 万步对应的决策次数可以相差数倍。修复：统一以智能体决策次数计步。
  • 轨迹采样与更新解耦：并行副本数不同导致相同环境步下的更新次数不同。修复：报告并行度与更新次数，或按更新次数对齐预算。
  • 选择偏差：只在成功的难度等级上报告。修复：按协议固定难度集合，全部报告。

4. 平台治理与可复现包

公开评测平台的常态设施包括：提交格式规范（模型接口与超时限制）、公共日志（曲线与配置全公开）、排行榜规则（提交频率与撤回政策）。对个体研究者，等价的轻量设施是"可复现包"：环境版本与唯一标识、种子列表、配置文件、评估脚本与原始曲线数据。可复现包的最小标准是第三方只凭包内文件即可复算报告中的每一个数字，而不需要联系作者索要细节。

5. 统一评测脚本的设计

跨基准评测脚本用注册表模式组织：每个基准注册"构造工厂加评测协议"两项，评估函数面对统一接口遍历基准与种子。注册表把"环境如何构造"与"如何评估"绑定在同一处，避免协议在多次实验中被局部修改；评估函数只依赖（reset, step, 协议）三元组，基准特征差异全部被协议字段吸收，新增基准的边际代码量接近为零。

6. 数值算例：胜率区间与配对分辨力

胜率 p=0.6、评估回合 32 时，95% 区间半宽为 1.96×√(0.6×0.4/32)≈0.170，报告形式为 0.60±0.17；回合数升到 128 时半宽降到约 0.085，是原值的一半。区间宽度按回合数的平方根收缩，评估成本按回合数线性增长，从 32 提到 128 需要四倍评估量，分辨率却只提高一倍，这是为提高精度而堆回合数前必须了解的比例关系。

配对比较的收益。同一评估种子集上比较两个算法时，逐回合差值可以消去情景难度。若 32 个情景上的差值标准差为 0.05，差值均值的标准误约 0.05/√32≈0.009，可分辨 2% 量级的差异；非配对设计要达到同等分辨力需要数倍的情景数量。配对结构是评测脚本固定种子集后自然获得的能力，这也是种子集必须公开的原因之一。

解读：评估规模的决定顺序是先定需要分辨的最小差异，再由差值标准差反推回合数与种子数。区间半宽与配对标准误相差一个量级，说明配对与否比单纯增加回合数更能提升分辨力，脚本设计应优先保证配对结构，再考虑扩大规模。

实现思路与设计

评测脚本分四层：

  1. 注册层：基准名称映射到构造工厂与协议字典，协议含回合数、种子基址、贪心开关。
  2. 执行层：统一评估函数按基准与种子循环，产出逐种子胜率。
  3. 聚合层：按第 082 章与第 095 章的方法计算 IQM、区间与配对对比。
  4. 报告层：跨基准表格加雷达式汇总，附协议与版本声明。

与第 096 章的差异点：096 章归因单一方法内部的组件，本章处理外部基准的横向评测；两者共用记录格式，消融实验同样跑在本章的注册表之上。

设计决策：为什么把评测协议绑定在环境注册表里？

协议与环境的错配是评测事故的常见形态：环境换了但评估回合数沿用旧值，或新基准沿用了旧种子基址导致种子重叠。把协议与工厂绑定，构造环境时协议同时就位，宏观层面消除了这类错配的可能。代价是灵活性下降（同一环境不能用两套协议），收益是可审计性上升，评测系统里这个交换通常值得。

关键代码与解读

片段 1：环境注册表

ENV_REGISTRY = {}                          # 名称到（工厂, 协议）的注册表

def register(name, factory, protocol):
    """注册基准：工厂函数与评测协议一起绑定，防止二者错配。"""
    ENV_REGISTRY[name] = {"factory": factory, "protocol": dict(protocol)}

def make_env(name, seed):
    """按名称构造环境并取出协议；随机性全部由 seed 注入。"""
    entry = ENV_REGISTRY[name]
    env = entry["factory"]()
    proto = dict(entry["protocol"])        # 复制协议：评估期间不污染注册表
    proto["base_seed"] = proto.get("base_seed", 10000) + seed   # 逐种子平移
    return env, proto

# 注册两个基准：协议字段统一，差异全部显式记录
register("grid_team", lambda: GridTeamEnv(n_agents=4),
         {"episodes": 32, "greedy": True, "base_seed": 10000})
register("particle_predator", lambda: ParticlePredator(n_agents=4),
         {"episodes": 32, "greedy": True, "base_seed": 10000})

解读：（1）register 对协议字典做浅复制，防止调用方后续修改影响全局注册条目；配置对象的不可变性是评测脚本最常见的防御点。（2）make_env 里种子按"基准基址加实验种子"平移：同一实验种子在不同基准上使用不同的评估情景，同时保持可追溯。（3）工厂用 lambda 延迟构造，注册阶段不创建环境实例，避免资源占用；真实项目中工厂可接受参数以覆盖智能体数量。（4）协议字段在所有基准上保持同构（回合数、贪心、基址），异构信息（难度名、地图名）以额外字段附加，聚合脚本只读同构字段，保证跨基准汇总不炸形状。

片段 2：统一评估与胜率区间

import numpy as np

def evaluate_on_suite(policy_factory, names, seeds=(0, 1, 2)):
    """跨基准评估：返回 {基准: {种子: (胜率, 半宽)}} 的嵌套报告。"""
    report = {}
    for name in names:
        per_seed = {}
        for s in seeds:
            env, proto = make_env(name, s)
            wins = []
            for k in range(proto["episodes"]):
                obs, _ = env.reset(seed=proto["base_seed"] + k)
                done, term = False, {}
                while not done:
                    actions = policy_factory(s)(obs)     # 策略可与种子绑定
                    obs, r, term, trunc, _ = env.step(actions)
                    done = all(term.values()) or all(trunc.values())
                wins.append(float(all(term.values())))
            p = float(np.mean(wins))
            half = 1.96 * np.sqrt(p * (1 - p) / len(wins) + 1e-12)
            per_seed[s] = (p, float(half))               # 胜率与 95% 半宽
        report[name] = per_seed
    return report

解读：（1）返回值把"胜率"与"95% 半宽"成对存储：单点胜率没有可比性，区间是报告的最小单位；半宽用正态近似公式，n = 32 时对 p 在 0.3 到 0.7 区间足够准。（2）评估种子来自协议基址加回合序号，同一基准的 32 个回合共享一批固定情景，跨种子也保持情景不重复。（3）policy_factory(s) 允许策略与种子绑定（例如加载第 s 个种子的检查点），评估脚本不关心策略来源，接口保持最小。（4）外层按种子循环、内层按回合循环：报告天然支持第 095 章的配对分析，种子是配对单位，回合是评估点。

常见坑

  • 只报容易难度档：算法在困难档崩溃的事实被隐藏。修复：协议固定难度集合，全部等级报告，选择性报告视为不规范。
  • 训练种子与评估种子重叠：评估情景在训练中已见过，胜率虚高。修复：两段种子区间分离并写进协议。
  • 环境步口径不一致：决策步与仿真步混用，横向比较失真。修复：统一以决策次数计步，配置文件声明换算关系。
  • 依赖基准默认参数的隐性假设：默认视野或奖励被版本更新改变。修复：固定并记录环境版本与唯一标识，关键参数显式传入。
  • 报告数字无法复算：曲线数据与配置不带版本信息。修复：可复现包最小标准，包内可独立复算全部数字。

练习与思考

  1. 为通信协议研究选择两个基准并说明理由，指出各自的观测缺口设计要点。★
    提示
    Hanabi（信息不完全，通信是核心机制）与缩小视野的 MPE 捕食任务（几何上的观测缺口）。要点：确保无通信基线显著下降，见第 094 章的必要性判据。
  2. 把评估回合数从 32 提高到 128，计算胜率区间的变化倍数与评测成本变化倍数。★★
    提示
    区间宽度按 1/√n 缩小到一半，成本增加四倍；评估成本相对训练成本通常可忽略，困难任务除外。种子数与回合数的分工见第 095 章。
  3. 构造一个"版本漂移"检查清单：列出可复现包中需要固定版本的五个对象与各自的记录方式。★★
    提示
    基准引擎、深度学习框架、驱动版本、评估脚本、超参数配置。记录方式：版本号加内容唯一标识，标识覆盖配置文件全文。
  4. 设计实验：同一算法在三个基准上评测，报告跨基准表格与各基准的配对区间；讨论两个基准结论矛盾时如何解释与呈现。★★★
    提示
    矛盾结论先检查协议与难度档是否一致，再检查任务对算法优势的敏感度（例如值分解优势在异构单位任务上更明显）。报告中并列呈现，不做跨基准平均掩盖矛盾。
  5. 实现注册表的扩展：为每个基准附加"最大环境步数"与"推荐学习率"两个元字段，设计聚合脚本如何在不破坏同构协议字段的前提下读取元字段。★★★
    提示
    把元字段放在协议的 "meta" 子字典下，聚合脚本对 meta 做可选读取（缺省为空），同构字段与元字段在结构上分离。

小结

  • 基准家族的四个特征维度：观测结构、动作空间、规模量级与适配研究；选择以问题匹配优先。
  • 评测协议五个固定要素：评估回合数、难度等级、种子集、策略模式与计胜规则；缺一项即不可比。
  • 可比性威胁五项：版本漂移、默认参数差异、环境步口径、并行度差异与选择性报告。
  • 可复现包的最小标准是第三方凭包内文件复算全部报告数字。
  • 注册表模式把工厂与协议绑定，统一评估函数按基准与种子循环，产出可直接进入配对分析的报告。
  • 评估规模由目标分辨力反推：区间半宽随回合数平方根收缩，配对结构把可分辨差异降一个量级，预算分配优先给种子维度。
