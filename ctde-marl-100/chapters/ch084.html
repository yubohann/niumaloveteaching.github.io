第 084 章：真机集成：从仿真到实体系统

仿真中收敛的策略搬上实体系统常常立刻失效：本章分析差距的四类来源，给出域随机化与延迟建模的训练侧方案，并讨论安全层、看门狗与部署架构如何把风险限制在可接受范围。

  • 主题：仿真到现实迁移（Sim-to-Real）/ 部署安全
  • 关键公式：域随机化期望 J = Eθ∼p(θ)[J(θ)]、加速度限幅投影 v′ = v + clip(vcmd − v, ±Δv)
  • 预计学时：55 分钟
  • 前置章节：第 083 章

学习目标

  • 理解仿真到现实（Simulation-to-Reality, Sim-to-Real）差距的四类来源及其在观测、动作、动力学上的表现形式。
  • 掌握域随机化（Domain Randomization）与系统辨识（System Identification）两种迁移路线的适用条件与组合方式。
  • 学会实现观测延迟缓冲与动作延迟注入，让策略对真实系统的时延具有鲁棒性。
  • 理解安全层（Safety Layer）的动作投影与看门狗（Watchdog）降级逻辑。
  • 能设计部署架构：模型导出、推理与控制频率分离、分布式执行，并说明在线微调的边界。

背景与动机

仿真环境中的智能体可以瞬移、无噪声、零延迟，实体系统则受执行器惯性、传感器噪声、通信时延的约束。训练分布与部署分布不一致时，策略在仿真里越"精确"，在实体上越脆弱：它学到的细微动作依赖仿真特有的确定性反馈。Sim-to-Real 的核心问题可以一句话概括：让策略在训练时见到参数与噪声的分布，避免只对一组固定参数求最优解。

多智能体场景的迁移难度高于单智能体：传感器时延与通信时延叠加，邻居观测的一致性更难保证；执行机构的差异在协同任务中被放大，例如编队中一台机器人的响应滞后会破坏整个队形。本章的处理顺序遵循风险由低到高：先在训练侧做随机化与延迟建模，再在部署侧加安全层与降级策略。

核心原理

1. 差距的四类来源

来源典型表现训练侧对策部署侧对策
动力学参数误差质量、摩擦、时滞与仿真不符参数域随机化系统辨识收窄分布
观测噪声与偏差传感器白噪声、标定漂移注入高斯与均匀噪声状态估计器与滤波
观测与动作延迟图像管线延迟、执行器响应滞后延迟缓冲建模控制周期与推理预算匹配
通信延迟与丢包邻居状态过期随机丢包与延迟注入新鲜度检查与降级

四类差距的排查顺序是先测量再建模：真机上逐项测量噪声方差、响应延迟与通信时延，用测量值确定训练侧的注入参数。没有测量支撑的随机化范围只能靠试错，且无法解释失败模式。

2. 域随机化与系统辨识

域随机化把动力学参数 θ 视为随机变量，优化目标从单个环境的回报改为分布上的期望：

maxπ Jrand(π) = Eθ ∼ p(θ) Eτ ∼ P(·|π, θ) [ R(τ) ] p(θ) 覆盖真机参数的支持集；θ 每个情节重采样一次，策略被迫学习跨参数稳健的行为

随机化范围的确定是核心难点：范围过窄覆盖不到真机参数，范围过宽会迫使策略过度保守，任务性能显著下降。系统辨识走另一条路线：通过激励轨迹与参数回归估计真机参数 θ∗，把 p(θ) 收窄到 θ∗ 附近。两条路线互补：先用系统辨识确定参数中心，再用适度随机化覆盖辨识残差。

3. 延迟建模

观测延迟 d 步用队列实现：环境产生观测后进入长度为 d + 1 的先进先出队列，策略读取队首，读取值与当前时刻相差 d 步。动作延迟在环境施加侧建模：接收到的动作进入队列，da 步后才作用到动力学。两类延迟必须同时注入：只加观测延迟会让策略学会依赖"即时动作反馈"，真机上动作同样滞后时仍然失效。延迟量级按照控制周期的整数倍设置，典型为 1 到 3 个周期。

4. 安全层与降级策略

安全层（Shield）位于策略输出与执行器之间，把动作投影到安全集合：先限加速度，再限速度模长，必要时用控制屏障函数（Control Barrier Function, CBF）约束与障碍的距离。安全层的投影是逐动作的局部修正，保证任何策略输出都不会直接造成越界指令：

v′ = v + clip(vcmd − v, −Δvmax, +Δvmax)，随后按 ‖v′‖ ≤ vmax 等比缩放 双重投影保证指令连续且不超速；clip 保护执行器，缩放保持方向不变

看门狗（Watchdog）监控观测新鲜度：超过阈值未见新观测即触发降级。降级策略按任务分级：悬停、减速、原地停止。降级逻辑本身不依赖学习策略，用固定的安全控制器实现，保证神经网络故障时系统仍可控。

5. 部署架构与在线微调的边界

部署采用"训练端与推理端分离"：策略导出为 TorchScript 或 ONNX 格式，推理端只依赖运行库；控制循环按固定频率执行，推理预算与控制周期匹配，超时即按上一时刻动作延用并记录。分布式执行要求每台机器人独立运行本地策略，仅通过通信信道交换消息。在线微调（Fine-tuning）能补偿残余差距，但必须限制学习率（比训练期低一个量级）并保留安全层与降级逻辑；未经风险评审的持续在线更新会破坏已验证的策略行为。

实现思路与设计

迁移流程分五步：

  1. 测量：在真机上测量噪声方差、响应延迟、通信时延与丢包率，记录为参数表。
  2. 训练侧注入：包装器中加入参数随机化、观测噪声、观测与动作延迟、丢包模拟。
  3. 鲁棒性评估：在仿真中用参数扫描评估策略在分布边缘与分布外的表现，选择随机化范围。
  4. 安全层实现：实现投影函数与看门狗，用单元测试覆盖限幅边界与超时路径。
  5. 部署验收：分阶段放开：低速单机、低速编队、正常速度编队，逐级记录异常。

与第 083 章的差异点：083 章定义干净仿真接口，本章在同一包装器栈的最外层加入"现实差距层"，其参数来自真机测量，任意设定缺乏依据。

设计决策：为什么随机化参数要每情节重采样？

若整个训练共用一组固定随机参数，策略会针对该组参数过拟合，随机化退化为"换了一个仿真"。每情节重采样让同一策略在不同参数下都获得奖励梯度，学到的行为对参数变化不敏感。重采样粒度是随机化有效性的关键变量，情节级重采样是常见起点。

关键代码与解读

片段 1：差距注入包装器

import numpy as np

class SimRealGapWrapper:
    """在仿真训练中注入三类差距：参数随机化、观测噪声、观测与动作延迟。"""
    def __init__(self, env, rng, mass_range=(0.8, 1.2), noise_std=0.02,
                 obs_delay=2, act_delay=1):
        self.env, self.rng = env, rng
        self.mass_range, self.noise_std = mass_range, noise_std
        self.obs_delay, self.act_delay = obs_delay, act_delay
        self.obs_queue = None
        self.act_queue = None

    def reset(self, seed=None):
        obs, info = self.env.reset(seed)
        # 每个情节重新采样动力学参数：策略要覆盖整个参数分布
        self.mass = float(self.rng.uniform(*self.mass_range))
        self.obs_queue = [obs] * (self.obs_delay + 1)
        self.act_queue = [None] * self.act_delay
        return obs, info

    def step(self, action):
        self.act_queue.append(action)
        applied = self.act_queue.pop(0)          # 动作延迟 d 步后生效
        if applied is None:
            applied = action                     # 情节开头的空档用当前动作补齐
        obs, rew, term, trunc, info = self.env.step(applied)
        # 观测噪声在真机上不可避免：以测量值同量级的高斯噪声模拟
        noisy = {i: (o + self.rng.normal(0, self.noise_std, o.shape)).astype(np.float32)
                 for i, o in obs.items()}
        self.obs_queue.append(noisy)
        if len(self.obs_queue) > self.obs_delay + 1:
            self.obs_queue.pop(0)
        delayed = self.obs_queue[0]              # 策略看到的是 d 步之前的观测
        info["mass"] = self.mass
        return delayed, rew, term, trunc, info

解读：（1）随机数生成器从外部注入，训练与评估可以用不同种子复现同一随机化序列，便于对照实验。（2）观测队列预填充 d + 1 份初始观测，避免情节开头出现空值分支，逻辑更简单。（3）动作延迟队列用 None 占位并在开头用当前动作补齐，保证稳态时延迟恒为 d 步；用随机丢动作替代会改变语义，属于另一类随机化。噪声量纲与归一化后的观测一致，0.02 对应约 2% 的最大观测幅值。

片段 2：安全层与部署循环

import numpy as np

def project_to_safety(action, v_cur, v_max=1.0, dv_max=0.2):
    """部署安全层：先限加速度、再限速度模长，返回可下发指令。"""
    # 大机动会触发实体系统保护或打滑，加速度限幅优先执行
    v_cmd = v_cur + np.clip(action - v_cur, -dv_max, dv_max)
    speed = np.linalg.norm(v_cmd)
    if speed > v_max:                            # 超速时等比缩放，保持方向不变
        v_cmd = v_cmd * (v_max / speed)
    return v_cmd

def deploy_loop(policy, robot, stop_timeout=0.5):
    """单机推理循环：固定频率、看门狗降级、动作全程经过安全层。"""
    v_cur = np.zeros(2)
    last_obs_t = robot.now()
    while not robot.stopped():
        obs = robot.read_obs()
        if robot.now() - last_obs_t > stop_timeout:
            robot.estop()                        # 观测超时：降级为急停
            break
        raw = policy(obs)                        # 策略输出不直接下发执行器
        v_cmd = project_to_safety(raw, v_cur)
        robot.send(v_cmd)                        # 只下发投影后的安全指令
        v_cur = robot.read_velocity()
        last_obs_t = robot.now()

解读：（1）order 先加速度后速度：若先缩放再限加速度，缩放后的加速度可能重新越界；两级投影的顺序由约束的物理优先级决定。（2）看门狗检查放在读取观测之后、推理之前，超时路径直接调用急停，不经过策略，保证网络故障或卡顿时系统仍可控。（3）v_cur 从真机读取：指令与实测量之间可能存在差值（打滑、阻力），以实测值为基准才能保证限幅语义正确；从历史指令推断会掩盖这一差值。

常见坑

  • 训练不注入噪声，部署指望鲁棒：策略对仿真观测过拟合，真机出现高频抖动。修复：按真机测量注入噪声，噪声量级取测量值的一到二倍。
  • 随机化范围过宽：策略学到极度保守的行为，任务完成率在仿真与真机上同时下降。修复：系统辨识收窄分布，或在课程中逐步扩宽并观察性能拐点。
  • 只建模观测延迟忽略动作延迟：仿真里策略可以利用即时动作反馈，真机上动作滞后导致振荡。修复：两类延迟同时注入并扫描延迟量级。
  • 归一化统计量沿用仿真侧：真机观测分布与仿真不同，归一化后的输入偏移。修复：部署端重新统计滚动均值方差，或固定训练期统计量并对偏移做监测。
  • 在线微调学习率过高：更新几步后策略越过安全边界，安全层频繁介入导致行为退化。修复：学习率比训练期低一个量级，微调期间保持安全层与降级逻辑启用。

练习与思考

  1. 解释动作延迟队列用 None 占位、不直接丢弃情节开头动作的原因，并验证稳态延迟确实为 d 步。★
    提示
    丢弃会让情节开头出现"无动作"状态，环境无法推进；占位补齐保证每步都有动作生效。验证：固定动作序列长度为 10，延迟 2 步，比较环境收到的动作序列与输入序列的平移关系。
  2. 把观测噪声标准差从 0.02 提高到 0.1，预测仿真内评估曲线与安全层介入频率的变化。★★
    提示
    噪声过大会压低回报上限并让动作抖动增加，安全层介入频率上升。验证：统计单位时间内限幅触发次数，并对比 0.02、0.05、0.1 三档。
  3. 设计实验：同一策略在（无随机化）、（仅参数随机化）、（参数 + 延迟随机化）三种训练设置下，比较其在参数分布边缘的评估回报。★★
    提示
    评估时固定一组分布边缘参数（例如质量 1.2 倍），观察只有参数随机化的策略是否仍被延迟问题拖垮；这能分离两类差距的作用。
  4. 推导：若控制周期为 10 ms、制动减速度为 2 m/s²，要从速度 1 m/s 安全停下至少需要多少制动距离？据此给出 Δvmax 的取值建议。★★★
    提示
    制动距离 v²/(2a) = 1/(4) = 0.25 m。若障碍最小安全距离 0.3 m 已由屏障函数覆盖，Δvmax 需保证单个周期内速度变化不超过制动能力可以消化的范围，建议不超过 0.2 m/s 每周期。
  5. 设计一套部署验收清单：列出分阶段放开的条件、每阶段需要记录的指标（位置误差、安全层触发率、通信延迟）与回退判据。★★★
    提示
    阶段划分按速度与编队规模递增；回退判据写成可测量的阈值（例如安全层触发率超过 5% 立即回退到上一阶段）。所有指标与第 082 章 JSONL 字段对齐。

小结

  • Sim-to-Real 差距分四类：动力学参数、观测噪声、观测与动作延迟、通信时延；先测量再建模。
  • 域随机化优化分布上的期望回报，参数每情节重采样；系统辨识收窄分布中心，两者互补。
  • 观测延迟与动作延迟必须同时注入，延迟量级按控制周期整数倍设置。
  • 安全层按物理优先级做动作投影，看门狗在观测过期时执行不依赖策略的降级动作。
  • 部署采用训练推理分离与分布式执行；在线微调需限制学习率并保留全部安全机制。
  • 下一章回到算法层面：通信学习与通信代价，讨论可微消息信道、离散消息的梯度估计与带宽预算约束。
