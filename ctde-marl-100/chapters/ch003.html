第一篇 · CTDE 基础与核心算法

第 003 章：集中式训练分布式执行基础框架

本课程的中枢框架：训练期允许一个集中式评论家（centralized critic）读取全局状态与联合动作，执行期每个智能体仅凭本地历史决策。学完本章，你能画出训练与执行两条独立的数据通路，写出分散演员加集中式评论家的策略梯度，并用接口检查防止全局信息泄漏进执行路径。

  • 主题：框架设计 / 训练与执行的信息不对称
  • 关键公式：∇θi J = 𝔼[ ∇θi log πi(ai | τi) · Q(s, a) ]
  • 预计学时：50 分钟
  • 前置章节：第 002 章

学习目标

  • 理解 CTDE 的三要素：训练期集中信息、执行期分散策略、两者的接口约束，以及三者在代码中的落点。
  • 掌握集中式评论家的两种形式（联合动作价值 Q(s, a) 与状态价值 V(s)）与多智能体策略梯度公式的推导思路。
  • 能列出给定算法的"训练期允许信息"与"执行期允许信息"两份清单，并设计泄漏检查。
  • 会实现分散演员加集中式评论家的训练骨架，包括时差目标、优势估计与联合更新顺序。
  • 能说明 CTDE 对非平稳性与信用分配分别提供了什么、没有提供什么，为第 005 至 009 章的深入机制建立坐标。

背景与动机

第 002 章的独立 Q 学习暴露了两难：训练期只用本地信息，成本最低，但目标值随队友策略漂移，紧耦合任务里会落入相对过度泛化的次优稳定点。另一个极端是直接学习联合策略 π(a | s)，训练目标平稳且信息充分，执行时却要求每个智能体知道全局状态与其他人的动作，部署条件常常不满足。

集中式训练分布式执行（Centralized Training with Decentralized Execution, CTDE）是这两个极端之间的制度化折中：训练期使用一个可访问全局信息的集中式组件来估计价值，执行期每个智能体只依赖自己的观测历史。它的立足点是信息获取能力在训练与部署两个阶段本就不对称：训练发生在仿真或集中算力环境，全局状态、所有智能体的动作与观测都可记录；部署发生在分散的实体上，跨实体信息依赖通信，带宽与可靠性没有保证。

COMA、MADDPG、MAPPO 属于集中式评论家家族，VDN、QMIX、QTRAN 属于联合价值分解家族，两类方法共享同一框架。本章给出的是骨架，第 004 至 014 章分别替换其中的部件并测量替换带来的收益。

核心原理

本节依次形式化信息结构、解释集中式评论家的三重作用、推导多智能体策略梯度，并给出训练与执行接口的纪律清单。

1. 信息结构：把"谁在什么阶段能看到什么"写成约束

设智能体 i 的本地历史为 τi,t = (oi,1, ai,1, …, oi,t)，训练期的集中信息为 It = (st, a1,t, …, aN,t)。CTDE 要求执行期策略满足：

πi(ai | τi,t)， 即 πi 的函数依赖中不出现 It 的任何分量 该约束必须可检验：固定 τi,t，扰动其他智能体的观测或全局状态，策略输出的分布应逐点不变。第 005 章给出批量检验方法

训练期评论家的允许输入则宽松得多，两种常用形式是：

Qπ(s, a) = 𝔼π [ Σk=0∞ γk R(st+k, at+k) | st = s, at = a ]， 或 Vπ(s) = 𝔼a∼π [ Qπ(s, a) ] Q(s, a) 显式建模联合动作的影响，便于信用分配；V(s) 参数量小、方差略高，MAPPO 类实现常取后者。注意对 It 的依赖只允许出现在评论家中

两种形式的分工列成对照表，选择依据是任务对信用分配的需求与评论家的规模约束：

评论家形式输入输入维度（协作位移任务）方差与估计难度信用分配能力典型算法
Q(s, a)全局状态 + 联合动作N + 3N = 4N：N = 2 时 8 维，N = 10 时 40 维条件信息最全，梯度估计方差较低可直接执行"固定队友动作、替换个体动作"的反事实运算与值分解COMA、MADDPG、VDN 系列
V(s)全局状态或联合观测拼接N：N = 2 时 2 维，N = 10 时 10 维不含动作条件，回报方差更大，常配广义优势估计补偿不显式建模个体贡献，需要额外的分配机制MAPPO 及优势估计类方法

输入维度的差别随智能体数量线性放大：离散动作数为 3 时，联合动作段占 Q 输入的 3/4，且该比例不随 N 改变，绝对开销按 4N 增长；V 形式只按 N 增长，代价是丢掉了动作条件信息。

2. 集中式评论家的三重作用

（1）方差降低。智能体 i 的策略梯度估计需要"当前决策对未来回报的影响"，本地历史 τi 对全局状态的信息有缺口，缺口表现为估计噪声。评论家条件于 s 与 a 后，同一决策的回报分布条件更紧，梯度估计方差下降。这一效应在部分可观测程度高时最明显。

（2）缓解非平稳性的机制转换。IQL 中队友策略漂移通过"有效转移 Pi"进入目标值，智能体无从区分漂移与噪声。集中式评论家把队友策略的效应显式建模为 Q(s, a) 的输入维度：队友动作 a−i 成为输入的一部分，评论家可以学习"在给定队友动作下我的价值"这一相对稳定的函数。联合策略仍在变化，评论家需要持续追踪，但追踪的对象从一个含噪的边缘分布变为一个条件价值函数，追踪难度显著下降。

（3）信用分配的载体。联合动作进入评论家后，反事实比较（第 009 章）与值分解（第 006 至 008 章）都成为可计算的运算：固定其他智能体的动作，改变智能体 i 的动作，价值差即该动作的反事实贡献。三重视角合成一句话：集中信息的作用发生在训练期，执行期不因此获得任何特权。

三重作用有明确的边界，训练期信息无法自动解决两类问题：其一是联合策略空间的规模问题，评论家只是价值估计器，不改变"最优联合策略需要协调"这一事实；其二是探索层面的协调失灵，若行为策略从未联合尝试过某个高收益组合，评论家对其价值的估计没有数据支撑，策略改进仍会指向被数据覆盖的保守区域。这两条边界分别由第 006 至 009 章的结构设计与第 025 章的探索专题承接。

3. 多智能体策略梯度的推导要点

联合策略梯度定理给出对全部参数的梯度，把对智能体 i 参数 θi 的梯度单独写出：

∇θi J = 𝔼s∼ρπ, a∼π [ ∇θi log πi(ai | τi) · Qπ(s, a) ] 推导要点：J 对 θi 求导时只有 πi 的分量产生 log 导数项；Qπ(s, a) 作为权重保留完整联合信息。Qπ 只出现在训练目的梯度里，执行期不被调用

推导不跳步地展开为三步。第一步：目标按时间分拆。J(θ) = Σt γt Σs P(st = s) Σa π(a | s) R(s, a)，其中 P(st = s) 是策略诱导的状态访问概率。第二步：对 θi 求导。状态访问概率本身依赖策略，直接求导繁琐，改用似然比恒等式 ∇θ π(a | s) = π(a | s) ∇θ log π(a | s)，并把从时刻 t 起的回报期望记作 Qπ(s, a)，得到 ∇θi J = Σt γt Σs P(st = s) Σa π(a | s) ∇θi log πi(ai | τi) Qπ(s, a)。此处用到联合策略的可分解性 π(a | s) = Πj πj(aj | τj)：对数分解为求和，对 θi 求导后只有第 i 项存活，其余项导数为零。第三步：归一化为期望。把 Σt γt P(st = s) 归一化为折扣状态访问分布 ρπ(s)，即得期望形式。

该式回答了框架的合法性问题：执行期约束作用于策略函数 πi 的输入，训练期信息可以不违背该约束地进入梯度权重与优势估计。实践中把 Q 换成优势 A(s, a) = Q(s, a) − V(s) 或时序差分优势 ρ = r + γV(s′) − V(s)，并配以自举截断，得到各类演员批评家算法的具体形态。

集中信息在梯度中承担什么角色，可以用一个小数值例看清。设某状态 s 处评论家给出的四个联合动作价值为 Q(s, (A, A)) = 8.0、Q(s, (A, B)) = 2.0、Q(s, (B, A)) = 3.0、Q(s, (B, B)) = 1.0，智能体 1 当前策略为均匀分布。对每个固定的队友动作 a2，反事实基线取 Σa′1 π1(a′1) Q(s, (a′1, a2))：

a2 = A：基线 0.5 × 8.0 + 0.5 × 3.0 = 5.5，优势 A(A, A) = +2.5、A(B, A) = −2.5
a2 = B：基线 0.5 × 2.0 + 0.5 × 1.0 = 1.5，优势 A(A, B) = +0.5、A(B, B) = −0.5 每个固定的队友动作下，按自身策略取期望的优势恰为零：0.5 × 2.5 + 0.5 × (−2.5) = 0。这一性质在第 009 章 COMA 中起核心作用

比较原始 Q 值与优势，即可看清"信用分配载体"的含义：Q 值 8.0、2.0、3.0、1.0 全部为正，直接按原始值加权无法区分同一队友动作下两个候选动作的优劣；扣除趋同的基线后，动作间的差别被分离。再把 π1 换成 (0.9, 0.1)，基线变为 0.9 × 8.0 + 0.1 × 3.0 = 7.5 与 0.9 × 2.0 + 0.1 × 1.0 = 1.9，优势相应变为 +0.5 与 −4.5、+0.1 与 −0.9。同一个联合动作的优势随本智能体策略变化，信用分配是相对本策略的度量，实现反事实类算法时基线必须与采样时刻的策略版本对应。

4. 接口纪律：训练通路与执行通路

把系统画成两条数据通路是检查泄漏的实用方法。执行通路：观测 oi → 历史编码 → 策略 πi → 动作 ai，只允许出现本地量；训练通路：联合转移 (s, a, r, s′) → 评论家 → 优势信号 → 策略参数更新，允许出现任何集中量。两条通路的交汇点只有一处：策略参数更新。任何把评论家输出、全局状态或他人观测送入执行通路的连接都是违规，包括归一化统计量。后者的隐蔽性最高：训练集统计若在采集时即时更新并直接归一化执行特征，等于把全队分布信息写进了执行路径，第 026 章会给出隔离方案。

实现思路与设计

本节给出框架的最小实现：分散演员输出动作分布，集中式评论家输入全局状态与联合动作，训练循环交替更新两者。

设计项取值（基线）作用与依据
演员网络MLP 64×64，输出离散动作 logits与第 002 章保持同构，便于逐部件对照；连续动作版本见第 010 章
评论家网络输入 dim(s) + N × n_actions（联合 one-hot），隐藏层 128联合动作显式进入输入，是信用分配类算法的通用接口
演员学习率5e-4策略梯度对步长敏感，取保守值
评论家学习率1e-3评论家需要更快跟上价值面变化；观察过高时降至 5e-4
折扣因子 γ0.95全篇统一
批大小128 步联合转移critic 输入维度随 N 增长，批量不宜过小
更新比例每次采集后 1 轮 actor + 1 轮 critic 交替首版实现保持 1:1；比例调节是第二篇稳定性专题的内容

与第 002 章的差异集中在三处：回放数据新增联合动作的 one-hot 编码字段；新增评论家网络及其时序差分损失；演员的损失从回归改为策略梯度。数据接口与探索策略保持原样，确保第 002 章与本章的对比只反映评论家结构这一项变量。

设计决策：评论家输入采用 one-hot 联合动作拼接的理由

离散小动作空间下 one-hot 拼接实现最直接，且天然支持"固定其他智能体动作、替换某一个体动作"的反事实运算，这一运算将在第 009、020 章反复使用。动作嵌入（embedding）在动作数很大时可省参数，但会让反事实替换变得不直观。本课程在动作数小于 20 的场景统一使用 one-hot，保证跨章代码接口稳定。

关键代码与解读

片段 1：分散演员与集中式评论家

import torch
import torch.nn as nn
import torch.nn.functional as F

class Actor(nn.Module):
    """分散演员: 函数依赖只有本地观测历史, 执行期可独立部署。"""
    def __init__(self, obs_dim, n_actions, hidden=64):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(obs_dim, hidden), nn.ReLU(),
            nn.Linear(hidden, hidden), nn.ReLU(),
            nn.Linear(hidden, n_actions),      # 输出 logits, 由分布对象自行归一化
        )

    def forward(self, obs):
        return torch.distributions.Categorical(logits=self.net(obs))

class CentralCritic(nn.Module):
    """集中式评论家: 训练期专用, 输入全局状态与联合动作的 one-hot 拼接。"""
    def __init__(self, state_dim, n_agents, n_actions, hidden=128):
        super().__init__()
        # 输入维度 = |s| + N * |A_i|, 队友动作显式成为输入分量
        self.net = nn.Sequential(
            nn.Linear(state_dim + n_agents * n_actions, hidden), nn.ReLU(),
            nn.Linear(hidden, hidden), nn.ReLU(),
            nn.Linear(hidden, 1),              # 单一标量: 联合动作价值
        )

    def forward(self, state, joint_action_onehot):
        x = torch.cat([state, joint_action_onehot], dim=-1)
        return self.net(x).squeeze(-1)

解读：两个网络的类注释直接写明信息权限，这是接口纪律的第一道防线。（1）Actor 的输入参数只有 obs_dim，编译期就不可能接收全局状态；若后续需要循环记忆，扩宽的是历史编码器而不改变这条纪律。（2）CentralCritic 用 torch.cat 拼接状态与联合动作，形状约定为 batch 主序：状态 (B, state_dim)，联合动作 (B, N·n_actions)。拼接顺序固定为先状态后动作，后面替换评论家结构（第 009、015 章）时保持该约定，训练循环代码不用改动。

片段 2：联合转移采集与评论家更新

def collect_step(actors, obs, eps_actors=None):
    """执行通路: 每个演员只吃自己的观测, 返回联合动作。"""
    acts, logps = [], []
    for i, actor in enumerate(actors):
        dist = actor(obs[i])                    # obs[i] 为智能体 i 的本地观测
        a = dist.sample()                       # 采样动作: 训练期需要 log 概率
        acts.append(a)
        logps.append(dist.log_prob(a))
    return torch.stack(acts), torch.stack(logps)

def critic_loss(critic, batch, gamma=0.95):
    """训练通路: 只有这里允许触碰全局状态与联合动作。"""
    s, a_oh, r, ns, na_oh, done = batch        # one-hot 编码在数据层预先完成
    with torch.no_grad():
        # 自举目标用下一状态与"下一联合动作已执行者"的近似: 单评论家版本
        q_next = critic.target(ns, na_oh)
        y = r + gamma * (1.0 - done) * q_next  # 终止截断: done=1 时目标只剩即时奖励
    q_pred = critic(s, a_oh)
    return F.mse_loss(q_pred, y)

解读：collect_step 是执行通路的全部内容：循环体内仅出现 obs[i] 与 actors[i]，没有全局状态、没有其他智能体的动作，这保证采集出的轨迹与真机部署时的信息条件一致。critic_loss 中 na_oh 的构造值得注意：这里的自举目标直接以回放中的"下一联合动作"作为近似，适用于同策略或近同策略设定；第 010 章的确定性演员版本会显式区分"行为联合动作"与"策略联合动作"，替换这一行即可。把待替换点集中在几行内，是框架章代码设计的核心考量。

片段 3：策略梯度更新与泄漏检查

def actor_loss(actor_i, logp_i, advantages):
    """策略梯度: 集中式评论家只贡献优势权重, 不出现在执行函数依赖里。"""
    # advantages 由训练通路计算并随批次传入, 梯度不反传进评论家
    return -(logp_i * advantages.detach()).mean()

def leak_check(actor, obs_i, n_repeats=3):
    """执行期泄漏检查: 固定本地观测重复前向, 输出分布必须逐点一致。"""
    with torch.no_grad():
        probs = [actor(obs_i).probs for _ in range(n_repeats)]
    # 若输出随重复变化, 说明存在隐藏状态或全局依赖注入
    for p in probs[1:]:
        assert torch.allclose(probs[0], p, atol=1e-6)
    return True

解读：actor_loss 中 advantages.detach() 是必须的：优势是对回报的估计，可视为常数权重，若让梯度穿过它就会把"策略改进"与"价值拟合"两个目标耦合，训练不稳定。leak_check 给出可执行的检验模板：固定本地观测重复前向，任何输出差异都指向隐藏状态或全局依赖。更严格的做法是扰动全局状态与队友观测后重放，第 005 章将其升级为批量检验。框架章的最后一段代码负责把纪律固化为可运行的测试，纪律若只停留在注释中，在大规模重构时必然失守。

常见坑

  • 评论家输出流入执行路径。症状：训练回报曲线漂亮，离线评估（仅本地观测）暴跌。原因：actor 的输入拼接了 critic 的中间特征，采集与评估的信息条件不一致。修复：以 leak_check 为模板建立回归测试，actor 的 forward 参数表里出现任何全局张量即判失败。
  • 演员与评论家学习率失衡。症状：优势估计长期为正或为负（策略被系统性高估/低估），策略快速坍缩到单动作。原因：评论家学得太慢导致权重失真，或评论家学得太快过拟合当前批次。修复：先冻结演员训练评论家到优势均值接近零，再解冻演员，并把评论家学习率降到演员的 2 至 3 倍以内。
  • 联合动作 one-hot 列序错位。症状：评论家损失下降但策略不改进。原因：编码时按不同智能体的动作空间循环拼接，索引零起点混用，队友动作被贴到错误列。修复：固定"第 i 段对应智能体 i 的 one-hot"，并在编码函数内断言段数等于 N。
  • 时差目标忘记截断。症状：回合结束值附近价值虚高，回合越长偏差越大。原因：终止转移仍参与自举。修复：数据层显式存 done 并在目标中做 (1 − done) 乘法，附一条断言"终止步目标等于即时奖励"的单元测试。
  • 集中式评论家只吃局部观测。症状：与 IQL 表现几乎重合，改进消失。原因：评论家输入误接局部观测，未使用全局状态，退化回独立设置。修复：打印评论家输入维度，核对是否等于 |s| + N·|Ai|，并在日志中记录其对全局状态分量的梯度范数。

练习与思考

  1. 为本章骨架填写两张信息清单：训练通路允许的量与执行通路允许的量，并指出 advantages、logp_i、s、na_oh 各属于哪一侧。★
    提示
    执行通路只有 obs_i 与 actor 参数；advantages、s、na_oh 均在训练通路；logp_i 产生于执行通路却被训练通路消费，属于交汇点，传输中不得附加全局依赖。
  2. 把评论家学习率从 1e-3 改为 1e-5，预测训练前 5×103 步内优势均值、策略熵与回报曲线的变化，并解释每一步。★
    提示
    评论家几乎不学习，优势权重近似随机初始值，优势均值偏离零、策略熵快速下降（被噪声梯度推走）、回报在低水平震荡。该实验用于校准"评论家需要多快"的量级感。
  3. 从联合策略梯度定理出发，推导智能体 i 的梯度式中 Qπ(s, a) 必须在期望内对 a 求平均（联合动作分布）的理由，并说明若误用 Q(s, ai, a−i = 固定默认值) 会引入什么偏差。★★
    提示
    梯度是 𝔼a∼π[∇log πi·Q]，a 含队友分量，用固定默认动作替换改变了被估计的期望，等价于把队友行为当作常量，梯度方向偏向"对默认队友最优"。这正是差值奖励要处理的问题（第 020 章）。
  4. 设计实验：评论家分别输入 (a) 全局状态 s；(b) 全部智能体观测的拼接 concat(o1, …, oN)；(c) 仅 oi。控制其余设置相同，预测三者的学习曲线排序并说明各自暴露的假设。★★
    提示
    (a) 信息最全，通常最好；(b) 在观测可恢复状态的马尔可夫任务中等价于 (a)，否则略差，是"伪全局状态"实验；(c) 退化为独立评论家，是第 002 章水平。该实验直接通向第 005 章的状态设计。
  5. 设计题：为 leak_check 写一个更强的检测方案，要求覆盖三类泄漏源：直接输入拼接、归一化统计量共享、网络内的全局池化层。给出每类的扰动方式与通过判据。★★★
    提示
    直接输入：替换全局张量后比较输出；统计量：跨批次改变统计基准，观察执行特征是否变化；池化层：改变其他智能体的输入，检查本智能体输出的雅可比是否为零。判据统一为"固定本地量时输出逐点不变"。

小结

  • CTDE 制度化信息不对称：执行期策略只依赖 τi，训练期评论家可依赖全局状态与联合动作，约束落在函数依赖上且可检验。
  • 集中式评论家提供方差降低、非平稳性缓解与信用分配载体三重作用，全部作用于训练期梯度信号。
  • 多智能体策略梯度 ∇θi J = 𝔼[∇log πi(ai|τi)·Qπ(s, a)] 是全部演员批评家算法的出发点。
  • 实现上维持两条数据通路，交汇点唯一，用 leak_check 类测试把纪律固化为回归测试。
  • 下一章解决框架落地后的第一个工程问题：参数共享与不共享的对比，同构智能体注定要面对参数量的取舍。
