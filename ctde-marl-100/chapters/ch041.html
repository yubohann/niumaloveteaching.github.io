第三篇 · 环境与任务实践

第 041 章：多智能体粒子环境

粒子环境（Multi-Agent Particle Environment, MPE）用几百行 NumPy 把协作、对抗、通信三类任务装进同一套接口；本章讲清观测、动作、奖励、终止四要素的设计方式，以及这些设计如何决定 CTDE 算法的训练上限。

  • 主题：任务环境建模 / 观测与奖励设计
  • 关键公式：oi = [vi, pi / W, {pj − pi, ‖pj − pi‖}j∈N(i), mi, onehot(i)]
  • 预计学时：55 分钟
  • 前置章节：第 040 章 经验共享与样本效率

学习目标

读完本章，应当能够把任意一个协作任务拆解成观测、动作、奖励、终止四类可实现的接口定义。

  • 理解粒子环境（Multi-Agent Particle Environment, MPE）的定位与适用边界：以最小计算代价暴露多智能体协作的核心矛盾，用于快速验证 CTDE 算法的正确性。
  • 掌握部分可观测随机博弈（Partially Observable Stochastic Game, POSG）对粒子任务的建模方式，能逐项写出状态、联合动作、观测函数、奖励与折扣的含义。
  • 理解局部观测的三项设计：相对坐标、邻域截断与身份锚定，以及它们对策略泛化与置换不变性的影响。
  • 掌握距离势奖励与碰撞惩罚的组合方式，能说明团队共享奖励的信用分配难点为何在该环境下仍然存在。
  • 能独立实现一个纯 NumPy 的协作导航环境，并正确处理终止（terminal）与时间截断（truncation）的语义差别。

背景与动机

环境定义问题，算法只负责在问题里寻找解，因此第三篇从环境建模起步。

粒子环境最早随多智能体深度确定性策略梯度（Multi-Agent Deep Deterministic Policy Gradient, MADDPG）工作一同发布，把智能体抽象为二维平面上的圆点，用简单的速度积分代替刚体动力学。它省略了碰撞体、关节、传感器噪声等物理细节，换来两个直接收益：单步仿真落在微秒量级，单机在数小时内可以完成数十万回合的训练；任务语义简单到可以手推近似最优行为，算法缺陷与代码缺陷更容易分离。

在 CTDE 体系里，粒子环境是任务侧的第一站。它规模足够小，能把观测设计、奖励设计、终止语义这三件影响训练结果的要素完整暴露；语义又足够典型，协作导航、追捕、通信三类任务分别对应后续的空间协同、对抗博弈与机制设计主题。星际争霸多智能体挑战（StarCraft Multi-Agent Challenge, SMAC）、PettingZoo 接口规范、多智能体 MuJoCo 任务，都可以视为在粒子环境之上逐步补充物理真实性与观测复杂度。算法主线在第二篇已经完成，本章开始进入任务侧：先认清环境如何定义问题，再讨论算法如何在其中收敛。

核心原理

粒子环境的全部设计可以归约为一个部分可观测随机博弈，加上一套把连续动力学、稠密奖励与回合边界写清楚的实现约定。

1. 形式化：从马尔可夫决策过程到部分可观测随机博弈

单智能体任务用马尔可夫决策过程（Markov Decision Process, MDP）刻画，多智能体任务则需要把转移与奖励同时依赖所有智能体动作这一事实写进模型。

ℳ = ⟨N, S, {Ai}, P, {Ri}, {Oi}, γ⟩ N 为智能体数量；S 为全局状态空间；Ai 为第 i 个智能体的动作空间；P(s′ | s, a1, …, aN) 为联合动作驱动的转移；Ri 为个体奖励；Oi 为观测函数；γ 为折扣因子

与单智能体模型的差别有三处。其一，转移概率依赖联合动作，单个智能体的动作不再决定环境走向。其二，智能体只能拿到观测 oi = Oi(s)，无法直接读取 s，这使任务成为部分可观测的，历史信息因此进入策略输入。其三，奖励可以是个体化的，也可以是团队共享的，两者的信用分配难度差别很大。

CTDE 的接口分工正好与该模型对应：集中式训练使用全局状态 s 与联合动作，分布式执行只使用观测 oi。粒子环境在实现上同时提供这两条数据通路，这是它被广泛用作基准的直接原因。

2. 观测设计：相对坐标、邻域截断与身份锚定

观测向量决定策略能看到什么，也决定训练出来的策略能否在规模变化时继续使用。粒子环境采用三项处理：全部位置以相对坐标表示，邻居按视野半径截断，智能体自身身份以独热编码锚定。

oi = [ vi, pi / W, { pj − pi }j∈N(i), { ‖pj − pi‖ }j∈N(i), mi, onehot(i) ] vi 为自身速度；W 为世界边长，自身位置以归一化坐标保留（见设计决策）；N(i) 为视野半径内的邻居集合；mi 为邻居掩码；onehot(i) 为身份锚定，用于解除同构智能体的对称性

相对坐标带来平移不变性：把整个场景平移到另一处，观测数值不变，策略因此不依赖绝对位置。邻域截断控制观测维度，也把注意力限制在真正可能发生交互的邻居上：远处智能体对当前决策的影响通过环境动力学延迟体现，无需进入观测。身份锚定解决同构智能体的对称问题：若所有智能体观测相同且策略共享参数，协作任务中的角色分工（例如谁去哪个目标）无法稳定形成，逐个智能体的独热编码提供了区分手段。

邻居数量随场景变化，直接把邻居列表铺开会导致观测长度变化。实现上固定 K 个槽位，邻居不足时补零并用掩码标记有效位。该做法保留了张量形状的稳定性，代价是引入了槽位顺序，因此排序规则必须确定，通常按距离升序。

3. 动作与动力学：半隐式积分与速度阻尼

连续控制版本的粒子环境把动作解释为力或加速度，位置与速度按半隐式欧拉格式推进。

vt+1 = κ · vt + Δt · at ， pt+1 = pt + Δt · vt+1 κ 为速度保持系数（阻尼），取 0.9 时旧速度逐步衰减；Δt 为步长，取 0.1；at 为被裁剪到 [−1, 1] 的加速度

先更新速度再更新位置称为半隐式，它在相同步长下的数值稳定性优于显式格式。阻尼项 κ 保证动作归零后智能体最终静止，否则一旦获得速度就会永久漂移，覆盖类任务无法收敛到静止覆盖状态。速度范数还要裁剪到上限，防止个别样本的极端输出把位置推进墙外，破坏观测分布。

离散版本的粒子环境把动作空间定义为若干方向加静止，观测格式不变。两种版本对应不同的算法族：连续版本配确定性策略梯度类算法，离散版本配值分解类算法。切换动作空间只改变策略头与损失形式，观测与奖励设计保持通用。

4. 奖励设计：距离势、覆盖稀疏项与碰撞惩罚

协作导航目标的奖励由三部分组成：到最近目标点的距离势、成功覆盖的稀疏奖励、智能体之间的碰撞惩罚。

rshare = − wd Σi minj ‖pi − gj‖ + ws ncovered − wc ncollision gj 为第 j 个目标点；ncovered 为被任意智能体覆盖的目标数；ncollision 为发生重叠的智能体无序对数

距离势项为每个智能体选择最近目标，这种逐行取最小的写法放松了目标任务：不要求预先指定配对，只要存在一种分配使总距离小即可。对应的全局最优量是全组匹配的最小总距离，属于指派问题（assignment problem），可以用匈牙利算法（Hungarian algorithm）在多项式时间内求解。训练时无需精确解匹配，用逐行取最小即可提供稠密的学习信号。

覆盖项只在智能体进入目标半径时给出奖励，属于稀疏信号；距离势属于稠密信号。两者组合的用意是让早期训练有梯度可依赖，后期收敛到精确覆盖。碰撞惩罚按无序对统计，如果按每个智能体各自计数会重复计算，团队奖励被放大约一倍，惩罚强度随之失控。全部三项求和后作为共享奖励发给每个智能体，团队收益与个体收益完全一致，信用分配问题从模型层面被保留下来，这正是该环境能检验 CTDE 算法价值的地方。

5. 终止与截断：两种回合结束的语义差别

回合结束有两种原因：任务完成与步数上限到达。

任务完成称为终止，其后没有未来回报，价值目标是当前回报。步数上限到达称为截断，环境只是被强制中断，其后仍可能有回报，价值目标需要加上自举项。两者在实现上都必须返回结束标志，训练端用不同的自举规则处理。若把截断当作终止，价值函数在学习后期会被系统性低估；若把终止当作截断，终止状态的价值会被高估。

实现约定

步进函数同时返回 done 与 truncation 两个标志，或者返回内含 truncated 字段的信息字典，标准接口（Gymnasium 风格）采用后者。价值自举只看 done 字段，不看 truncated 字段，这个区分在后续所有任务章节中通用。

6. 三类经典任务与观测奖励的差异

任务观测重点奖励结构主要难点
协作导航（cooperative navigation）目标点相对位置与邻居相对位置距离势加覆盖奖励加碰撞惩罚，全共享配对歧义与碰撞规避的权衡
追捕逃逸（predator-prey）追捕者与逃逸者相对位置区域覆盖奖励加碰撞罚，个体项与共享项混合对抗方非平稳，合围要形成几何包围
定向通信（speaker-listener）任务目标仅发言者可见，听者只看自身依任务完成分配，稀疏且延迟通信通道与动作通道联合学习

三类任务的观测构造方式共用同一套工具，差异集中在信息不对称程度上：协作导航完全对称，追捕引入角色不对称，定向通信引入私有信息。信息不对称越强，历史编码与显式通信的价值越高，这条线索贯穿本篇后续章节。

实现思路与设计

实现粒子环境的最小完整集合是：一份环境类、一份观测构造、一份奖励计算、一份步进与边界处理，加上可复现的初始化。

1. 环境与学习器的接口契约

环境对外暴露四个入口：reset 返回初始观测列表与全局状态，step 接收动作列表并返回观测、奖励、结束标志与信息字典，state 返回拼接后的全局状态，seed 控制随机源。全局状态的字段与观测字段对齐，集中式评论家（critic）直接读取该向量，分布式执行的策略只读取各自的观测。该契约与 PyMARL、EPyMARL 的采样器假设一致：采样器只需要按智能体维度索引观测与奖励，不关心任务语义。

3. 与第 040 章的差异点

第 040 章处理的是训练侧的样本效率工程，关注经验如何跨智能体共享；本章把视角切换到任务侧，关注问题本身如何被定义。两者的连接点在于数据接口：环境提供的观测、奖励、结束标志正是采样器写入经验缓冲区的字段，任何字段语义出错都会以训练曲线的形式表现出来，这让环境实现成为排查训练异常的第一现场。

设计决策：为什么观测中保留自身绝对位置

相对坐标解决邻居关系的平移不变性，但自身绝对位置仍以一个归一化坐标的形式保留。原因在于边界条件与目标点分布依赖绝对位置，完全去掉会让策略无法判断自身是否接近墙体。保留归一化绝对坐标、其余全部相对化的折中方案，在实践中兼顾了泛化与信息完整性。

关键代码与解读

三段代码分别覆盖观测构造、奖励计算与步进终止，形成环境最小闭环。全部实现采用纯 NumPy，接口命名参照 MPE 与 PettingZoo 的通用习惯。

片段 1：世界状态与相对观测构造

import numpy as np

class ParticleWorld:
    """最简粒子世界：协作导航任务，纯 NumPy 实现。"""
    def __init__(self, n_agents=5, world_size=2.0, vision=1.0, slots=3):
        self.n = n_agents
        self.m = world_size                 # 世界边长，同时作为坐标归一化分母
        self.vision = vision                # 视野半径：只把可能交互的邻居写进观测
        self.slots = slots                  # 邻域槽位上限，把变长邻域压成定长张量
        self.steps = 0
        self.max_steps = 25                 # 与设计表一致：回合上限
        rng = np.random.default_rng(0)      # 固定种子，实验之间只允许算法变量不同
        # 坐标落在 [-m/2, m/2]；速度为 0，避免开局随机漂移干扰行为归因
        self.pos = rng.uniform(-self.m / 2, self.m / 2, (self.n, 2))
        self.vel = np.zeros((self.n, 2))
        # 目标点数量等于智能体数量，便于用最小和距离衡量覆盖质量
        self.goals = rng.uniform(-self.m / 2, self.m / 2, (self.n, 2))

    def _obs(self, i):
        # 相对坐标是关键设计：整体平移场景时观测不变，策略因此平移不变
        rel = self.pos - self.pos[i]
        dist = np.linalg.norm(rel, axis=1)
        order = np.argsort(dist)[1:self.slots + 1]   # 跳过自身，取最近的若干邻居
        pad = np.zeros((self.slots, 3))              # 邻居不足时补零并置掩码为 0
        mask = np.zeros(self.slots)
        for k, j in enumerate(order):
            if dist[j] <= self.vision:               # 视野之外的邻居不进观测
                pad[k] = [rel[j, 0], rel[j, 1], dist[j]]
                mask[k] = 1.0
        own = np.concatenate([self.vel[i], self.pos[i] / self.m])
        return np.concatenate([own, pad.ravel(), mask])  # 定长向量，直接拼进批次

解读：结构上做了三个取舍。其一，随机源独立于全局随机数，实验复现时其他模块消耗随机数不会改变环境轨迹。其二，邻居按距离升序进入槽位，顺序确定，策略不会因为邻居排列变化而看到不同输入。其三，掩码与数值分开存放，网络端可以把掩码作为加性偏置（例如在注意力计算中把无效槽位置为负无穷），避免补零被误当成真实的零向量邻居。

片段 2：团队奖励的计算

def team_reward(env, w_dist=1.0, w_cover=1.0, w_collide=1.0,
                cover_radius=0.05, collide_radius=0.08):
    """协作导航奖励：距离势 + 覆盖稀疏项 + 碰撞惩罚，全队共享。"""
    # 逐行取最小的距离和：不预设配对，任何可行分配都能获得低代价
    d = np.linalg.norm(env.pos[:, None, :] - env.goals[None, :, :], axis=-1)  # (n, n) 距离矩阵
    r_dist = -w_dist * d.min(axis=1).sum()
    # 碰撞按无序对统计一次，若对每个智能体都记一遍会把惩罚放大一倍
    n_coll = 0
    for i in range(env.n):
        for j in range(i + 1, env.n):
            if np.linalg.norm(env.pos[i] - env.pos[j]) < collide_radius:
                n_coll += 1
    # 覆盖按“目标视角”统计：对列取最小，表示该目标被任意智能体接管
    covered = int((d.min(axis=0) < cover_radius).sum())
    reward = r_dist + w_cover * covered - w_collide * n_coll
    info = {"dist_sum": float(-r_dist), "collisions": n_coll, "covered": covered}
    return reward, info

解读：奖励函数返回信息字典用于诊断，这在环境调试阶段比奖励值本身更重要：距离和持续下降而覆盖数为零，说明策略学会了靠近但尚未收敛到目标半径；碰撞数长期不降，说明惩罚权重偏小或智能体数量相对世界尺寸过大。距离矩阵用广播一次算完，形状为 (n, n)，对行取最小得到每个智能体的最近目标距离，对列取最小得到每个目标是否被接管，同一份中间结果支撑两个统计口径。

片段 3：半隐式步进与终止截断

    def step(self, actions, dt=0.1, kappa=0.9, v_max=1.0):
        """推进物理并返回四元组信息；done 与 truncated 语义必须分开。"""
        a = np.clip(np.asarray(actions)[:, :2], -1.0, 1.0)  # 只取前两维作为加速度
        # 先更新速度再更新位置：半隐式欧拉，在相同步长下比显式格式稳定
        self.vel = kappa * self.vel + dt * a
        speed = np.linalg.norm(self.vel, axis=1, keepdims=True)
        # 速度裁剪：防止极端输出把位置推出世界，污染后续观测分布
        self.vel = np.where(speed > v_max, self.vel / (speed + 1e-8) * v_max, self.vel)
        self.pos = self.pos + dt * self.vel
        # 边界用夹取处理：实现简单，且把“靠近边界”的信息保留在归一化坐标里
        self.pos = np.clip(self.pos, -self.m / 2, self.m / 2)
        self.steps += 1
        reward, info = team_reward(self)
        done = info["covered"] == self.n          # 任务完成：真终止，无需自举
        truncated = self.steps >= self.max_steps  # 步数上限：截断，训练端需要自举
        obs = [self._obs(i) for i in range(self.n)]
        return obs, [reward] * self.n, done, truncated, info

解读：步进函数返回五元组，把终止与截断分开，采样器据此决定价值自举：终止样本的目标值直接用即时回报，截断样本要加上折扣后的下一状态价值估计。奖励按智能体数量复制成列表，团队共享奖励的接口与个体奖励完全一致，切换奖励模式无需改动采样代码。数值细节也有依据：`speed + 1e-8` 防止零速度样本产生除零，`np.clip` 的位置放在速度更新之后，保证裁剪后的速度参与下一步位置计算，物理上自洽。

常见坑

  • 观测里塞入全局状态：训练阶段看起来收敛很快，执行阶段拿不到全局状态导致策略失效。症状是所有曲线在训练环境内异常完美。修复：观测构造只使用局部信息，全局状态仅注入集中式评论家。
  • 邻居槽位顺序不稳定：同一场景两步之间邻居排列变化，策略需要额外容量学习顺序无关性，表现为方差增大。修复：固定按距离升序排序，或对槽位使用置换不变聚合（如对槽位求和或注意力）。
  • 碰撞惩罚重复计数：对每个智能体分别统计碰撞次数，团队奖励中的惩罚被放大成接近两倍。症状是智能体过早学会彼此远离并放弃覆盖。修复：只对无序对统计一次，或在信息字典中核对碰撞数与几何重叠数是否一致。
  • 把截断当成终止：回合上限到达也写入 done，价值目标缺少自举项，学习后期价值被系统性低估。症状是策略在临近回合上限时行为退化。修复：接口分开返回 done 与 truncated，价值计算只对 done 屏蔽自举。
  • 归一化统计跨回合累积：用全部历史数据的均值方差归一化观测，早期统计偏差大，等价于给策略输入了未来信息。症状是训练曲线前段剧震后段突然平稳。修复：统计量按回合重置，或使用有界的固定尺度（如世界边长）归一化。

练习与思考

  1. 复杂度估算：N = 6 时，每步碰撞检测需要比较多少对智能体？若把视野截断用于碰撞检测，需要哪些额外假设？★
    提示
    无序对数量为 N(N−1)/2 = 15。视野截断假设是“超出视野的智能体永不碰撞”，这只在世界几何与半径关系受限时成立，一般仍需全局检测。
  2. 改参数并预测：把碰撞惩罚权重从 1.0 提高到 3.0，其他不变。预测训练前期行为会如何变化，覆盖数曲线与碰撞数曲线各自的走向。★★
    提示
    惩罚增强后智能体倾向分散，碰撞数更快下降，但覆盖需要互斥配对，分散过度会推迟覆盖数上升的时点。若权重加到极端，会出现策略停在远离所有目标的位置“摸鱼”的退化平衡。
  3. 设计题：为 10 个智能体设计固定 K = 3 槽位的邻域观测，写出每个智能体的观测张量形状与掩码处理方式，并说明 K 小于真实邻居数时信息损失会怎样影响合围类任务。★★
    提示
    观测长度固定为 4 + 3×3 + 3 + 10 = 26（自身速度与归一化位置 4 维、3 个邻居的三元组 9 维、掩码 3 维、独热 10 维）。K 过小时最近邻被保留、远处协作者被丢弃，合围任务中相隔较远的对侧智能体互相不可见，封口行为难以形成。
  4. 实验设计：比较“共享奖励”与“共享奖励加个体距离项”两种设置在相同超参数下的收敛步数，说明差异来源是否为信用分配。★★★
    提示
    个体项相当于把团队信号分解到每个智能体，通常收敛更快，但要控制个体项与共享项的相对权重。差异来源可以用逐智能体回报的方差佐证：方差大说明团队信号的信用分配负担重。
  5. 推导题：证明在只有一个智能体、一个目标的退化情形下，距离势奖励的最优策略是沿目标方向的恒定加速，并给出到达所需步数的表达式。★★★
    提示
    距离随步数递减，加速度方向始终指向目标，速度受阻尼与上限约束。到达步数由初速度、阻尼系数与步长共同决定，可先按无阻尼情形推导再引入修正项。

小结

  • 粒子环境用部分可观测随机博弈建模，转移依赖联合动作、执行期只可见局部观测，同时提供全局状态供集中式评论家使用。
  • 局部观测的三项设计：相对坐标保证平移不变，邻域截断控制维度，独热身份解除对称；固定槽位加掩码解决变长邻居问题。
  • 动力学采用带阻尼的半隐式积分，速度裁剪与边界处理共同保证数值稳定；奖励由距离势、覆盖稀疏项与碰撞惩罚组合，碰撞按无序对统计。
  • 终止与截断必须分开返回，价值自举只由终止标志屏蔽，这一约定在后续全部任务中复用。
