第五篇 · 研究复现与系统集成

第 096 章：消融实验设计

消融回答"到底哪个组件在起作用"：本章把消融从逐项删除升级为因子设计，讲清移除、替换、冻结三种操作，单因子与全因子的取舍，主效应与交互效应的估计，以及多重比较下的报告规范。

  • 主题：消融方法论（Ablation Study）/ 因子设计
  • 关键公式：主效应 = E[指标 | 因子开] − E[指标 | 因子关]、交互效应 = (A1B1 − A0B1) − (A1B0 − A0B0)
  • 预计学时：60 分钟
  • 前置章节：第 095 章

学习目标

  • 理解消融与参数扫描的区别，掌握移除、替换、冻结三种消融操作。
  • 掌握 2k 因子设计的运行组织与主效应、交互效应的估计方法。
  • 学会用配对种子与置信区间评估组件的边际贡献，避免单点数字比较。
  • 理解单因子轮换设计的局限，能识别交互效应导致的误判。
  • 能设计一份完整的消融实验：因子选择、运行矩阵、分析口径与报告格式。

背景与动机

论文的方法部分通常列出五到十个组件，实验部分的消融却常常只删减其中两三项。读者真正想知道的问题很朴素：每个组件对最终性能贡献多少，组件之间是否互相依赖。逐项删除的直觉做法（单因子轮换，One-Factor-At-A-Time, OFAT）在组件互相加强或互相抵消时会给出错误结论：单独删除组件 A 影响甚微，但 A 与 B 同时存在时才产生增益，OFAT 会把这份增益记到 B 头上而看不见 A 的价值。

第 095 章解决了主实验的统计比较，本章处理同一方法内部的机制归因。两者的统计工具相同（配对差值、区间、校正），组织方式不同：主实验的自变量是算法，消融的自变量是组件。术语上要区分两种实验目的：消融回答"组件贡献多少"（因果归因），参数扫描回答"参数取多少最好"（调优）。扫描的结果告诉你在最优点附近组件的价值，消融要固定其他参数回答组件本身的平均值。

核心原理

1. 三种消融操作

操作做法适用场景
移除（Remove）删掉组件及其参数，重新训练组件可独立删除（例如通信模块、注意力头）
替换（Replace）用更简单的变体替代（注意力换均值池化）组件不可删除但可以简化，保持接口不变
冻结（Freeze）保留结构但关闭其功能性效果（权重冻结、目标置零）需要保持计算图或参数量一致的对照

三种操作回答的是稍微不同的问题：移除度量组件连同其参数的贡献；替换度量"这种实现相对简单实现的增益"；冻结度量组件功能的贡献而保持容量不变。报告时必须注明采用哪种操作，同一组件的三种操作结果可以相差数个百分点。任何消融都不可在原模型上直接推断，必须从头训练：组件的效果体现在训练动力学上，事后冻结权重与训练时就缺少它完全不同。

2. 单因子与全因子设计

设待讨论的组件数为 k，2k 全因子设计枚举每个组件开与关的全部组合：k = 3 时 8 组，k = 4 时 16 组。因子 i 的主效应定义为它在所有组合中"开"的平均指标减去"关"的平均指标：

MEi = E[ M | 因子 i 开 ] − E[ M | 因子 i 关 ]，交互效应（两因子） = (A1B1 − A0B1) − (A1B0 − A0B0) 主效应是"平均贡献"；交互效应是"一个因子的效果随另一个因子状态变化的程度"，为零说明两组件独立

交互效应的量纲与指标一致：正交互说明两组件互相加强（同时开时的增益超过各自增益之和），负交互说明冗余或冲突。OFAT 只测量"从完整模型出发单独删除"的一个组合点，等价于在全因子表中只取一行；当交互显著时，这一行的读数无法推广到其他组合。组件数 k 超过 4 时全因子成本（2k × 种子数）过高，常用两步策略：先用 OFAT 从 k 个组件中筛出三个候选，再对候选做全因子验证。

3. 边际贡献与配对估计

与主实验相同的统计学要求适用于消融：每个组合用相同种子集训练，同一组合内逐种子配对取差，置信区间不跨零才宣称贡献。组件的边际贡献定义为 Δi = M(完整) − M(去掉 i)，与主效应的区别在于它固定其余组件于完整状态。

Δi = M( 全部组件 ) − M( 去掉组件 i )，报告 Δi 与逐种子配对差值的 95% 区间 Δ 依赖"其余组件全开"的背景；主效应 MEi 是对全部背景的平均，两者一起报告才完整

四个组件的消融涉及四次"删除对比"或一张 16 组的因子表，前者更省算力，后者能给出交互。推荐组合：预算充足时做全因子；预算受限时用 OFAT 出边际贡献，附一段两组件的交互检查（2×2 子设计）作为敏感性。

4. 多重比较与选择偏差

k 个组件意味着 k 个显著性判断，不做校正时族错误率随 k 上升（k = 6 时名义 5% 的族错误率约 26%）。校正方法与第 095 章相同：Holm 或 Bonferroni。此外还有一层更隐蔽的偏差：组件选择本身来自观察，先用大量实验找出"看起来有用"的组件，再用同一批数据评估其显著性，会双重使用数据。规范的顺序是先设计因子集合（来自方法描述与先验推理），再运行、分析、报告，一次到位。

5. MARL 常见消融清单

多智能体论文的消融项通常从以下组件中选择，选择原则是与论文主张直接相关：混合结构（单调约束、加性、无状态条件化）、参数共享（共享与个体网络）、critic 输入（全局状态与局部观测）、序列模型（RNN 与 MLP）、通信（开关、代价系数、聚合方式）、掩码处理（死亡置零与排除）、探索调度与课程。主张"单调性带来增益"的论文必须做混合结构消融；主张"通信有效"的论文必须包含通信消融，清单与主张一一对应，缺少对应项的消融视为不完整。

实现思路与设计

消融流程分五步：

  1. 因子确定：从方法主张出发列出二值因子，标出必做项（与主张对应）与可选项。
  2. 设计选择：k ≤ 4 做全因子；k 更大先 OFAT 筛选再对候选做全因子。
  3. 运行组织：全部组合共享同一训练预算与种子集，按种子成组调度。
  4. 分析：计算主效应、边际贡献与两两交互，配对差值给出区间，Holm 校正显著性。
  5. 报告：效应表加因子表，完整模型与删除行高亮，交互显著的组合单独说明。

与第 095 章的差异点：095 章比较不同算法（外部对比），本章归因同一算法的内部组件（内部对比）；两章共享配对与区间工具，但消融需要额外处理交互效应与因子选择。

消融参数起点

参数默认值作用取值依据
因子数上限（全因子）4（16 组）成本控制16 组 × 10 种子为可用预算上限
种子数10区间宽度与主实验一致，保证区间可比
训练预算与主实验相同公平性删组件后收敛更快不代表更好，预算不能缩短
评估协议与主实验相同可比性贪心、32 回合、固定种子集
显著性校正Holm族错误率对比数大于 3 时启用
设计决策：为什么删掉组件后仍要跑满训练预算？

缺少组件的模型常在前 20% 预算内看起来不差：此时主导因素是基础学习动态，组件作用的差异尚未展开。提前比较会把"收敛速度暂时接近"误读为"组件无用"。跑满预算后再比较末期窗口与整条曲线，是消融的默认口径。样本效率的差异另用到达阈值步数指标呈现，与最终性能分开报告。

关键代码与解读

片段 1：2k 因子设计的运行生成

from itertools import product

def factorial_runs(factors):
    """生成 2^k 因子设计的运行列表：0 表示组件关闭，1 表示开启。"""
    runs = []
    for combo in product([0, 1], repeat=len(factors)):
        cfg = {name: bool(bit) for name, bit in zip(factors, combo)}
        runs.append(cfg)
    return runs

# 三因子示例：单调混合、全局状态、参数共享
runs = factorial_runs(["monotonic", "global_state", "share_params"])
for r in runs:
    print(r)
# 共 8 组；全关组合是天然的无组件基线，全开组合是完整模型

解读：（1）因子用显式名称字典表达，配置对象直接可序列化进运行清单（第 092 章），避免位串与语义脱节。（2）product 的字典序生成保证全关组合与全开组合都在列表中：全关是基线，全开是完整模型，两者之间是各单项与组合。（3）k = 3 只需 8 组训练；若预算只能支持部分组合，优先保留"单组件删除"的四行与首尾两行，这五行足以估计边际贡献与一个粗粒度交互指示。（4）扩展名列表即可扩展设计，运行组织代码不变，这是用生成函数代替手写配置的原因。

片段 2：主效应与交互效应估计

import numpy as np

def main_effect(scores, factor_idx):
    """主效应：该因子开启与关闭组合的平均指标差（配对已在此前完成）。"""
    on = [v for key, v in scores.items() if (key >> factor_idx) & 1]
    off = [v for key, v in scores.items() if not ((key >> factor_idx) & 1)]
    return float(np.mean(on) - np.mean(off))

def interaction_2x2(scores):
    """两因子交互：差之差 (11-01) - (10-00)，使用 0b 编码的四格字典。"""
    return float((scores[0b11] - scores[0b01]) - (scores[0b10] - scores[0b00]))

# 例：因子位 0 为单调混合，位 1 为全局状态；数值为平均胜率
scores = {0b00: 0.55, 0b01: 0.60, 0b10: 0.58, 0b11: 0.72}
print(main_effect(scores, 0), main_effect(scores, 1))
print(interaction_2x2(scores))
# 交互约 +0.09：两组件同时开启的增益超过各自单独收益之和

解读：（1）scores 的键是二进制位串编码（低位对应先列出的因子），字典的键顺序与 factorial_runs 的因子顺序严格一致，两个函数通过同一约定衔接。（2）main_effect 用位运算筛组合，K 很大时也是常数级开销；真实项目中每个键存储的是"种子序列"（含多个种子值），配对差分与区间在上一层完成。（3）示例值的交互为正：以 00 格为基准，单独开单调混合增益 0.05、单独开全局状态增益 0.03，同时开增益 0.17，超出线性叠加（0.05 + 0.03 = 0.08）的部分 0.09 正是差之差公式的读数。（4）报告交互时给出四格原始值加差之差，读者可自行核验算术。

常见坑

  • 只做单组件删除却声称完整消融：交互效应被漏掉，组件的价值可能被低估或归错。修复：至少对两个可疑组件做 2×2 交互检查。
  • 消融训练预算缩短：删组件后曲线早期接近，误判为无贡献。修复：跑满相同预算，比较末期窗口与整条曲线。
  • 不同组合的种子集不一致：方差差异混入效应估计。修复：全部组合共享同一批种子，按种子成组调度。
  • 用参数扫描替代消融：扫描最优点的读数带着调优偏差，不能当作组件贡献。修复：消融固定其余参数于主配置，扫描另作附录。
  • 忽略容量一致性：删除通信模块同时删掉大量参数，增益差异无法归因于机制。修复：用替换或冻结操作保持参数量近似，或报告参数量差异。

练习与思考

  1. 为三因子设计写出全部 8 组配置，并指出其中哪些行单独即可估计边际贡献，哪些行专门用于交互估计。★
    提示
    单组件删除行（111 的邻居）估计边际贡献；000 与 111 提供整体范围；两两交互用 2×2 子格（00, 01, 10, 11 投影到两个因子）估计，三阶交互需要全 8 行。
  2. 在正文示例 scores 中把 0b11 从 0.72 改为 0.58，重算两主效应与交互，解释交互转负的含义。★★
    提示
    两主效应降到 0.025 与 0.005，交互为 −0.05：同时开启的增益低于各自单独增益之和，两组件存在冗余或资源竞争，例如共享编码器容量被同时占用。
  3. 设计实验：为"通信代价系数有效"的主张选择三个必做消融项并说明理由，写出因子表与预期效应方向。★★
    提示
    必做项：通信开关（β = 0 与正常）、聚合方式（广播均值与注意力）、消息维度（16 与 8）。预期：通信开关效应最大，聚合与维度效应较小但方向一致。
  4. 设计两步走消融：6 个候选组件先用 OFAT 筛到 3 个，再全因子验证；计算总训练组数并与直接全因子对比。★★★
    提示
    两步：7 组（完整 + 6 删除）加三候选全因子的 8 组，去重后共 11 组（新增 4 组：三个单因子组合与全关）；直接全因子 2⁶ = 64 组。代价是 OFAT 筛选可能漏掉只在组合中显效的组件，报告中作为已知局限说明。
  5. 写一份消融报告模板：因子表、主效应与交互表、配对区间、校正说明、容量一致性声明五项齐全。★★★
    提示
    模板强调可复算：因子表给每个组合的配置唯一标识，效应表给配对差与区间，校正列列出 p 值校正前后值，容量列给参数量差异。

小结

  • 消融三种操作：移除、替换、冻结，报告时必须注明操作方式；消融必须从头训练，不能在原模型上事后推断。
  • 2k 全因子设计给出主效应与交互效应；OFAT 只测一个组合点，交互显著时结论无法推广。
  • 边际贡献 Δi 与主效应 MEi 互补；估计用配对种子与置信区间，显著性用 Holm 校正。
  • 消融项与方法主张一一对应，缺少对应项的消融视为不完整。
  • 容量一致性是归因前提：删组件同时删参数时，先换用替换或冻结操作。
