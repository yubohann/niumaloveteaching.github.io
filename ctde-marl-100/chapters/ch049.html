第三篇 · 环境与任务实践

第 049 章：多智能体任务分配

任务分配处理带时间窗与依赖关系的任务集合；本章推导投标价格与序列可行性条件，说明契约网协议如何在动态到达下维持分配质量，以及学习型投标函数与调度启发式的结合方式。

  • 主题：序列决策 / 组合分配机制
  • 关键公式：bidi(τ) = ci( Qi ∪ {τ} ) − ci( Qi )
  • 预计学时：60 分钟
  • 前置章节：第 048 章 多智能体资源分配

学习目标

读完本章，应当能够把“谁去做哪件事、按什么顺序做”写成带可行性约束的分配问题，并把学习组件放在正确的位置。

  • 理解任务与资源的区别：任务具有位置、处理时长、时间窗与依赖关系，完成后从系统中消失。
  • 掌握任务序列的可行性条件与到达时间递推，能判断一条任务队列是否在时间窗内可完成。
  • 掌握边际成本投标的构造与契约网协议（Contract Net Protocol, CNP）的招标、投标、授予流程。
  • 理解分配目标的差别：最小化总完成时间与最大化总任务价值在动态到达下不等价。
  • 能设计任务依赖图的检查逻辑与完成奖励，识别“挑软柿子”与分配抖动两类退化行为。

背景与动机

任务分配关心的是任务的时序可行性，约束来自时间与依赖，与容量价格无关。

仓储拣选、巡检点位、应急响应都属于任务分配问题：一组待执行的任务分布在不同位置，每个任务有处理时长与截止时间，部分任务之间还存在顺序依赖（先取货再送货）。多机器人系统的目标通常是完成尽可能多的任务，或让全部任务尽早完成。经典方法把它写成多旅行商问题（multiple traveling salesman problem, mTSP）或其带时间窗的变体，配合启发式求解；分布式版本用契约网协议让机器人通过招标与投标自行认领任务，避免中心节点的通信与算力瓶颈。

与上一章资源分配的差异决定了本章的技术重点。资源分配的对象是可复用的资源，使用者的核心信息是偏好；任务分配的对象是一次性的任务，核心信息是时空可行性：任务能否被某台机器人在其时间窗内完成，取决于该机器人已有的任务序列与行驶时间。因此分配决策相互耦合，一个机器人的认领会改变其他机器人后续任务的可行性。强化学习在此的价值有两点：学习价值函数以估计“完成某任务对整体目标的价值”，以及学习执行策略处理路径与干扰；分配机制本身仍可用拍卖或 CNP 承载，形成“学习加机制”的组合结构。

核心原理

本章原理沿四层展开：任务模型与可行性、投标与分配机制、依赖与分解、以及奖励与信用归属。

1. 任务模型与序列可行性

任务 τ 由位置、处理时长、时间窗与价值构成，机器人 i 已完成的任务队列为 Qi。

Tarrive(τk+1 | Qi) = max( Tfinish(τk), ek+1 ) + d( pk, pk+1 ) / vi ek+1 为任务可用开始时间（早于该时刻到达需要等待）；d 为距离；vi 为机器人速度；要求 Tfinish(τk+1) ≤ lk+1（截止时间）

递推式包含两个机制：等待与截止。若到达时刻早于任务的允许开始时间，机器人需要等待，空闲时间因此可能被后续任务利用；若完成任务时刻超过截止时间，该序列不可行。可行队列的构造是一个带约束的排序问题，插入新任务时需要逐位置尝试并检查其后全部任务的截止条件是否保持满足。单次插入位置的检查复杂度为 O(L)（L 为队列长度），逐位置试插的合计为 O(L2)；分布式拍卖中每台机器人对每个候选任务执行一次，总代价为 O(N · M · L2)。

2. 边际成本投标与契约网协议

投标价格定义为“把新任务插入自身队列所增加的最小代价”，这一构造让自利投标导向全局效率。

bidi(τ) = mink [ ci( Qi ⊕k {τ} ) − ci( Qi ) ] ， ci(Q) = Στ∈Q ( Tfinish(τ) − t0 ) ⊕k 表示把任务插入队列第 k 位；ci 常取完成时刻之和，也可换成行程距离或能耗

投标值越低表示该机器人完成任务的附加代价越小，招标方选择最低投标者。该规则在“代价函数可加、任务一次分配”的条件下近似最优：把任务交给边际代价最小的机器人使总代价的一阶增量最小，与贪心分配一致。边际代价用完成时刻之和定义时，隐含了对早完成的偏好，与最小化平均完成时间的目标吻合；若目标是完成尽量多的任务，代价应改为“任务价值减超时损失”，投标随之包含价值判断。

契约网协议把流程组织为四步：招标方广播任务描述，机器人计算投标并回报，招标方选择中标者并授予任务，中标者更新队列。动态任务到达时协议周期性重复。CNP 的两个工程细节影响质量：投标期限必须覆盖通信与计算延迟，期限太短会让慢速机器人错失机会；分配结果需要迟滞机制，新任务到达时不轻易改动已确认的任务，否则任务在机器人之间反复转移，实际执行资源被浪费在重新规划上。

3. 依赖关系与任务分解

复合任务由子任务组成，子任务之间形成有向无环图（directed acyclic graph, DAG）。

ready(τ) = 1[ ∀ τ′ ∈ pred(τ), τ′ ∈ Done ] ， 非法动作惩罚：执行未就绪任务额外计入违规 pred(τ) 为 τ 的先决任务集合；只有当全部先决任务完成后，τ 才进入可分配状态

依赖图把可分配任务的集合动态化：初始只有入度为零的任务可投标，任何任务完成后其后继任务的入度减一，减到零时加入待分配列表。策略的观测中需要给出可执行任务集合，否则会浪费概率质量在不可执行任务上，等效于第 047 章动作掩码的连续版本。任务分解的另一层含义是能力约束：部分任务要求特定设备或载荷，分配时只向具备能力的机器人招标，能力集合进入投标过滤条件。

4. 学习组件的位置

机制负责可行性，学习负责估值与执行，二者分工明确。

学习型投标是本章最自然的设计：用网络估计任务对整体目标的边际贡献 fθ(τ, Qi, 全队状态)，替代解析代价函数的投标。该做法在代价难以解析（例如拥堵与不确定行驶时间）时优势明显。另一条路线是用学习替代整个分配层：策略直接输出任务选择，训练信号来自完成价值与时间代价。端到端方案表达能力强，但在任务数量动态变化时泛化困难，通常需要把任务集合编码为集合型输入（对每个任务生成嵌入向量，再在嵌入上做选择打分），固定长度的向量难以适应任务数的变化。

执行层的策略负责把机器人从当前位置移动到任务点并处理过程扰动。分配层与执行层可以分层训练：先固定执行策略训练分配估值，再联合微调，避免两层同时更新造成信号混叠。第 076 章的分层强化学习会把这一结构形式化。

5. 奖励与信用归属

任务完成是稀疏事件，奖励需要同时表达价值、代价与超时。

rt = Στ 完成于 t vτ · 1[ Tfinish(τ) ≤ lτ ] − wc · 行驶距离t − wl · 超时任务数 vτ 为任务价值；行驶距离项抑制无效机动；超时项对错过截止的任务扣分，注意与完成价值的加权关系

信用归属相对清晰：任务由单个机器人完成，其价值可记到该机器人的账上，团队价值则是总和。这与资源分配的拥挤外部性不同，任务之间主要经由“时间占用”相互影响。动作空间的信用因此按机器人分组，值分解较容易奏效。若某任务是协作完成的（例如需要两台机器人共同搬运），信用归属回到合作博弈的分配问题，第 088 章的联盟形成会讨论补救方式。

实现思路与设计

实现采用 CNP 承载分配、学习型投标提供价格、贪心加局部交换做改进入的三层结构。

1. 环境循环

每个分配周期：环境公布待分配任务（含新到达任务）；各机器人计算投标（执行策略估值的边际代价或学习型投标）；环境选择各任务的最优投标者并授予；机器人更新队列；执行层按队列顺序执行，环境推进时间并结算奖励；完成后释放后继任务。周期长度由分配延迟与任务到达率共同决定。

3. 网络结构与训练要点

投标网络与执行网络分离。投标网络的输入为任务特征（位置、时长、时间窗、价值）、机器人当前队列的汇总特征与全队状态，输出为该任务的边际代价估计，用回归损失拟合事后计算的真实边际代价。执行网络的输入为局部观测与当前任务相对位置，输出移动动作。训练流程为：先以启发式投标与随机执行收集数据，训练投标网络；再固定投标网络训练执行策略；最后两端联合微调。该流程避免了稀疏奖励直接作用于投标网络。

4. 与第 048 章的差异点

资源分配是对可复用资源的静态匹配，无时间维度；任务分配是一次性任务的时序安排，可行性随队列变化。资源分配的价格由负载决定，任务分配的投标由队列插入代价决定。资源分配中公平是显式目标（收益分布），任务分配中公平表现为任务负载的均衡与完成价值的分布，评估指标相应换成任务完成率、平均完成时间与迟到率的组合。两章的机制工具箱（拍卖、边际定价）共享，应用对象与约束结构不同。

关键代码与解读

三段代码分别实现序列可行性检查、投标计算与局部交换改进、以及依赖与奖励结算。

片段 1：队列插入的可行性检查

import numpy as np

def queue_feasible(agent_pos, speed, queue, insert, task_map, t_now):
    """检查把 insert 插入 queue 后是否全部任务仍满足截止时间。"""
    pos, t = agent_pos, t_now
    seq = queue + [insert]
    for k, tid in enumerate(seq):
        tau = task_map[tid]
        # 行驶时间按欧氏距离除以速度估计，忽略绕行是保守性来源
        travel = np.linalg.norm(tau["pos"] - pos) / speed
        arrive = t + travel
        start = max(arrive, tau["earliest"])       # 早到需等待到允许开始时间
        finish = start + tau["duration"]
        if finish > tau["deadline"] + 1e-9:
            return False, k                        # 记录第一个失败位置，便于诊断
        pos, t = tau["pos"], finish
    return True, len(seq)

def insertion_cost(agent_pos, speed, queue, insert, task_map, t_now):
    """边际代价 = 完成时刻之和的最小增量；无可行插入位置时返回 None。"""
    base = _finish_sum(agent_pos, speed, queue, task_map, t_now)
    best_inc = None
    for k in range(len(queue) + 1):
        cand = queue[:k] + [insert] + queue[k:]
        # 复用同一套递推检查候选序列：前段作为 queue，末位作为 insert 传入
        ok, _ = queue_feasible(agent_pos, speed, cand[:-1], cand[-1],
                               task_map, t_now)
        if not ok:
            continue
        inc = _finish_sum(agent_pos, speed, cand, task_map, t_now) - base
        if best_inc is None or inc < best_inc - 1e-9:
            best_inc = inc
    return best_inc

解读：可行性检查逐位置推进时间，第一个失败位置被记录下来，作为重规划与诊断的依据。行驶时间用直线距离估计，忽略绕行与拥堵，属于乐观估计，需要在评估中用更精细的仿真修正。早到等待的处理（max 操作）保证了时间递推的正确性，遗漏它会把空闲时间错算为无效。插入代价函数遍历全部插入位置并返回完成时刻之和的最小增量，无可行位置时返回 None；可行插入位置的集合另行记录，用于序列构造与 2-opt 改进。

片段 2：投标选择与局部交换改进

def select_winner(bids):
    """CNP 授予规则：选择最小投标者，平局时按编号确定性裁决。"""
    best_a, best_b, best_v = -1, None, np.inf
    for a, b in bids.items():
        if b is None:
            continue                               # 无可行插入位置的投标视为弃标
        if b < best_v - 1e-9:
            best_a, best_b, best_v = a, b, b
    return best_a, best_b

def two_opt(queue, task_map, agent_pos, speed, t_now, iters=20):
    """队列内 2-opt 交换：代价不降则保持，抑制顺序劣化。"""
    cost = _finish_sum(agent_pos, speed, queue, task_map, t_now)
    for _ in range(iters):
        improved = False
        for i in range(len(queue) - 1):
            for j in range(i + 1, len(queue)):
                cand = queue[:i] + queue[i:j + 1][::-1] + queue[j + 1:]
                c = _finish_sum(agent_pos, speed, cand, task_map, t_now)
                if c < cost - 1e-9:                # 严格改善才接受，避免循环
                    queue, cost, improved = cand, c, True
        if not improved:
            break                                  # 已无改进则提前退出
    return queue

解读：投标裁决平局时按编号确定，保证分布式结果可复现。2-opt 在单机器人队列内部做反转交换，计算量随队列长度平方增长，对 20 任务规模完全可接受。严格改善条件（减去微小容差）避免代价相等时的无限往复。局部交换与投标是互补的：投标决定任务归属，2-opt 决定队列顺序，前者处理全局分配，后者处理单机调度，两层各自有明确的改进上界，便于分层调试。

片段 3：依赖就绪与完成奖励

class TaskDAG:
    """依赖图：维护入度与就绪集合，任务完成后释放后继。"""
    def __init__(self, tasks):
        self.tasks = tasks                         # 每个任务含 pred 列表与价值
        self.pending = {tid: len(t["pred"]) for tid, t in tasks.items()}
        self.done = set()

    def ready(self):
        # 入度为零且未完成的任务即为可投标集合
        return [tid for tid, d in self.pending.items()
                if d == 0 and tid not in self.done]

    def complete(self, tid, t_finish):
        tau = self.tasks[tid]
        self.done.add(tid)
        for nxt, nt in self.tasks.items():
            if tid in nt["pred"]:
                self.pending[nxt] -= 1             # 每完成一个先决，入度减一
        # 奖励口径：按时完成给全值，超时按线性折扣给部分价值
        if t_finish <= tau["deadline"]:
            return tau["value"]
        lateness = t_finish - tau["deadline"]
        return tau["value"] * max(0.0, 1.0 - lateness / (2 * tau["duration"]))

解读：入度表在初始化时一次性计算，之后仅做减一操作，复杂度与依赖边数成正比。奖励对超时任务给线性折扣，梯度信号在截止时间附近保持连续；直接归零会在截止点造成信号断裂，策略失去“接近按时”与“严重超时”的区分；折扣斜率以任务时长为尺度，保证不同规模任务的惩罚比例一致。就绪集合在每步重新计算，避免缓存导致的状态不一致。该结构把依赖可行性集中在一个类里，投标与执行模块只消费就绪列表，职责边界清晰。

常见坑

  • 时间估计过于乐观：行驶时间用直线距离估计且不加余量，队列在仿真中陆续超时。症状是规划可行但执行迟到率居高不下。修复：在投标时间估计中加入保守系数，或用学习型投标拟合真实行驶时间。
  • 选择指标与目标不一致：目标是完成尽可能多的任务，代价却用完成时刻之和，策略倾向先做近处廉价任务而错过高价值任务。修复：明确目标的优先级，把任务价值并入代价函数或改用完成价值型奖励。
  • 分配抖动：新任务到达时反复重分配，机器人在任务点之间来回移动。症状是行驶距离上升而完成率不升。修复：引入迟滞阈值，只有边际代价改善超过阈值才允许改派。
  • 未就绪任务参与投标：忽略依赖检查，机器人提前认领后继任务并在原地等待，占用队列位置。修复：投标集合限制为就绪任务，依赖释放逻辑与分配周期严格同步。
  • 执行层与分配层信用混叠：两层同时训练时，投标网络的回归目标随执行策略变化，训练信号不稳定。修复：分层训练加联合微调，或对投标目标做滑动平均处理。

    位置 0 先做新任务会把 (1, 0) 任务推迟到 9.06 完成（超过 3.5）；位置 1 会令 (1, 1) 任务在 10.65 完成（超过 6.5）；只有追加到队尾时三个任务依次在 3、6、9.41 完成，全部满足约束。截止约束会让顺路直觉失效，必须比较完整时刻表。
  2. 推导题：证明在代价可加且任务互不影响的条件下，边际代价投标的最优授予等价于贪心地最小化总代价增量，并说明任务之间存在时间耦合时结论为何失效。★★
    提示
    可加情形下每个任务的分配独立，逐任务选最小边际增量即得全局最优。时间耦合使后来的插入改变先前任务的完成时刻，各任务代价不再独立，贪心失去最优性保证。
  3. 改参数并预测：把迟滞阈值从 20% 降低到 0（允许任何改善都改派），预测行驶距离、完成率与重分配次数三条指标的变化方向。★★
    提示
    重分配次数上升，行驶距离上升，完成率可能反降。改善幅度小于执行扰动幅度的改派是纯损耗，阈值的作用是把这类改派过滤掉。
  4. 设计题：为带能力约束的任务集合设计投标过滤规则与观测编码，说明能力不匹配的任务如何被排除以及如何避免策略在无任务可选时陷入无效动作。★★★
    提示
    在投标前按能力集合过滤任务，并在观测中给出“有资格任务”的掩码；无任务时允许保持动作分支。掩码与第 047 章的动作掩码同源，都是把不可行选项从概率质量中移除。
  5. 实验设计：对比“规则投标加启发式撮合”“学习型投标加规则撮合”两组，设计指标区分投标质量与执行质量的贡献。★★★
    提示
    构造对照：同一投标下换不同执行策略，观察指标变化幅度估计执行贡献；同一执行下换投标，观察分配相关指标（等待时间、负载方差）的变化估计投标贡献。分项指标比总完成率更能定位来源。

小结

  • 任务分配的对象是一次性任务，核心约束是时间窗与依赖；序列可行性通过逐位置时间递推检查，早到等待不可遗漏。
  • 边际成本投标是 CNP 的价格核心，代价可加且任务相互独立时逐任务最低投标即得全局最优；时间耦合与价值差异需要把目标写进代价或奖励。
  • 依赖图通过入度表管理就绪集合，超时任务用连续折扣奖励保留梯度信号；分配抖动用迟滞阈值抑制。
  • 学习组件置于两处：投标网络的边际代价估计与执行策略的路径机动；分层训练避免两类信号混叠。
