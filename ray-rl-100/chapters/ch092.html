第 092 章：端到端实践：Atari风格任务训练流水线

一句话：本章把图像观测、离散动作的游戏风格任务组装成完整流水线：预处理的包装器顺序、卷积网络配置、采样与评估协议、以及围绕它的超参搜索。

  • 主题：端到端实践 / 图像离散控制
  • 关键机制：观测预处理链、卷积特征提取、评估协议、搜索接入
  • 预计学时：65 分钟
  • 前置章节：第 091 章

学习目标

  • 掌握图像观测预处理链的标准顺序：跳帧、灰度化、缩放、帧堆叠，并解释每一步的动机与颠倒顺序的后果。
  • 会为 84×84×4 输入配置卷积特征提取网络，并估算参数量与推理成本。
  • 能组装 PPO 的完整配置：采样批、片段长度、并行环境与复用轮数的整除一致性。
  • 掌握该任务形态的评估协议：独立评估环境、评估回合数、评估频率与回报口径。
  • 会把关键超参接入 Tune 搜索，并定义抗噪声的排序指标。

背景与动机

图像输入加离散动作是强化学习最经典的任务形态：观测是高维像素，动作是有限按键，环境步廉价而观测处理昂贵。这类任务把前面章节的全部配置项同时拉到台面上：批结构、并行度、显存、复用、容错与评估协议，任何一项配置错误都会表现为"训练不收敛"，难以从回报曲线定位根因。本章按数据从像素到动作的实际路径组织配置，把每一步的选择依据写清楚，使流水线成为可检查、可搜索、可复现的整体。

与前面的连续控制、多智能体实践相比，本章流水线的特殊性集中在两处：其一，预处理链在采样与评估两条路径上都要一致地复现，且它对吞吐的影响很大；其二，评估噪声显著（游戏回报方差大），需要固定的评估协议才能比较配置优劣。这两点构成了本章的设计重心。

核心原理

Atari 风格流水线的核心是把"像素到决策"的每一级变换固定成确定性的、两路一致的管道，再围绕它做参数配置。本节依次讨论预处理、网络、采样配置、评估协议与搜索接入。

1. 预处理链的顺序与动机

标准预处理链的次序为：跳帧（Frame Skip）→ 灰度化（Grayscale）→ 缩放（Resize）→ 帧堆叠（Frame Stack）。每一步的依据：

步骤作用颠倒或遗漏的后果
跳帧每 k 帧决策一次，动作在帧间重复决策频率与动作语义错位，学习量成倍增加
灰度化通道从 3 降到 1，带宽与内存降为三分之一在堆叠后灰度化会破坏时间结构
缩放分辨率归一到 84×84 量级先堆叠再缩放使插值跨帧混合，产生鬼影
帧堆叠近 4 帧拼接，提供速度与方向信息缺失堆叠使部分可观测性无法缓解

顺序不变量只有一条：逐帧的几何与颜色变换在堆叠之前完成，堆叠之后不再做任何跨帧混合的变换。训练与评估必须使用同一份包装器代码构造环境，评估端另起一套等价实现是历史 bug 的高发地带。

2. 卷积特征提取与成本

84×84×4 输入的标准卷积栈为三段：32 通道 8×8 步长 4、64 通道 4×4 步长 2、64 通道 3×3 步长 1，输出展平后接 256 维全连接。参数量约 1.7 百万量级，前向计算量集中在第一层。参数量小意味着显存的主要占用在激活与工作区（第 084 章），模型宽度不需要为显存收缩，需要克制的是采样端推理成本。采样端每个环境步都要一次前向：卷积前向在 CPU 上与在 GPU 上的单样本时延差异明显，采样规模大时把采样端推理放到 GPU（分数资源共享）或批量前向可以降低每步成本；是否值得取决于实测的采样侧耗时结构（第 085 章的分解）。

3. 采样与更新配置的整除一致性

沿用第 083 章的约束：批大小 = 采样进程数 × 每进程环境数 × 片段长度。一组典型配置：批 4096 步、8 个进程、每进程 2 个环境、片段长度 256；更新轮数 4 至 6、小批 256（4096 除 256 得 16 个小批），整除关系需要逐项验证。图像任务的成本结构使并行度偏保守：每个进程持有独立的帧堆叠缓存（约 28 KiB × 环境数），进程过多时内存与调度开销上升，收益递减点通常早于低维任务。

4. 评估协议

评估回答"策略当前水平如何"，协议包含五个要素：独立环境（与训练环境隔离的实例，避免评估污染训练状态）；回合数（每个评估点至少 3 至 5 回合，取平均或中位数）；策略模式（评估使用同一动作规则，确定性或固定温度的随机，全程一致）；频率（按训练步数计量，训练与评估的样本量对应关系稳定；墙钟时间因机器负载波动不可比）；记录字段（每回合回报、回合长度、评估时的步数与版本号）。游戏任务的回报方差大，单回合评估的排序噪声可以覆盖配置差异，这是评估协议必须写死的直接原因。

5. 搜索接入与排序指标

该任务形态的敏感超参通常是：学习率、熵系数、裁剪参数、更新轮数。搜索空间按第 081 与 082 章的原则组织：学习率用对数分布（10-4 至 10-3），熵系数对数分布（10-3 至 10-1），裁剪参数取 {0.05, 0.1, 0.2} 的离散集合，更新轮数取 {2, 4, 6, 10}。排序指标用评估点的平滑曲线面积（若干评估点的均值），配合 ASHA 提前终止；搜索预算按试验 20 至 40 次规划，每试验的样本预算取基线收敛步数的 60% 至 80%，使弱配置尽早暴露。

单次策略前向的乘加运算约 930 万次，其中卷积三段合计约 770 万次、两路全连接合计约 160 万次，第一层卷积占卷积计算量约四成。参数量占比最大的是两路全连接，计算量占比最大的是第一层卷积：前者决定显存常驻，后者决定采样端单步推理成本，两个瓶颈位置不同。采样规模大时用批量前向摊薄固定开销，收益由实测的采样侧耗时结构判定。

8. 跳帧与样本预算的关系

跳帧 k 表示每个决策在环境中重复 k 个仿真帧：k 取 4 时，同样仿真帧数对应的决策样本缩小到四分之一，学习所需样本量下降，单决策的时间分辨率变粗。跳帧与栈深共同决定观测覆盖的时间跨度：k = 4、栈深 4 时观测覆盖约 16 个仿真帧的历史。跳帧参数在环境构造处只出现一次并由工厂统一分发，任何离线评估脚本都不得自行实现跳帧逻辑。训练与评估的帧堆叠缓存各自独立，评估实例在两次评估之间保持空闲但不释放，内存预算按常驻计算。批量前向下用整批观测做一次前向，推理吞吐高于逐个智能体逐步调用，采样规模越大收益越明显。灰度与缩放的具体参数写入配置快照，复现实验时按快照还原预处理链。评估实例的场景种子集固定后，跨配置的评估序列一致；新增配置按同一套种子评估，历史对比不需要重跑旧配置。

实现思路与设计

流水线组装分六步，产物是一份"配置 + 包装器 + 评估 + 搜索"四件套。

  1. 环境工厂：把预处理链封装为单一函数，训练与评估共用。
  2. 网络配置：卷积栈与全连接头，冻结随机初始化种子。
  3. 采样配置：批、进程、环境数、片段长度按整除约束联合确定。
  4. 算法参数：PPO 的学习率、折扣、GAE、熵系数、裁剪与更新轮数。
  5. 评估与检查点：评估协议五要素与检查点间隔（沿用第 090 章模型）。
  6. 搜索接入：开放 2 至 3 个敏感超参，指标与调度器按第 5 点组织。

关键代码与解读

以下片段基于 Ray 2.x 时期的通用写法，接口随版本演进，以对应版本的官方文档为准。

片段 1：预处理链的环境工厂

import gymnasium as gym

def make_env(env_id, frame_skip=4, size=84, stack=4, seed=0):
    """环境工厂：训练与评估共用同一构造路径。
    顺序不变量：几何与颜色变换全部在帧堆叠之前完成。"""
    env = gym.make(env_id, frameskip=frame_skip)
    # 灰度化与缩放先行：先降维再堆叠，堆叠后不再做跨帧混合变换
    env = gym.wrappers.GrayscaleObservation(env)
    env = gym.wrappers.ResizeObservation(env, (size, size))
    # 帧堆叠提供速度与方向信息，缓解像素观测的部分可观测性
    env = gym.wrappers.FrameStackObservation(env, stack)
    # 种子在包装之后设置：保证重置序列与评估端可复现
    env.reset(seed=seed)
    env.action_space.seed(seed)
    return env

# 评估用独立的工厂调用（独立环境实例），不用训练环境做评估
train_env = make_env("ALE/Pong-v5", seed=101)
eval_env = make_env("ALE/Pong-v5", seed=909)

解读：工厂函数把整条链固定成单一入口。（1）包装顺序在函数内部固化，调用方无法在不修改代码的情况下颠倒步骤，顺序不变量由结构保证。（2）种子在包装完成后设置，包装可能改变观察空间但不改变重置语义，此顺序保证同一场景序列可复现。（3）训练与评估用不同种子构造独立实例：共用实例会让评估步进污染训练状态，也让评估结果依赖训练进度，失去可比性。

片段 2：图像任务的 PPO 配置与整除校验

from ray.rllib.algorithms.ppo import PPOConfig

def atari_config(batch=4096, n_runners=8, n_envs=2, epochs=4):
    """组装图像输入任务的 PPO 配置：整除链在入口处一次校验。"""
    total = n_runners * n_envs
    assert batch % total == 0, "批大小须被进程数与环境数整除"
    assert batch % 256 == 0, "批大小须被小批整除"   # 4096 / 256 = 16
    fragment = batch // total                    # 片段长度由整除链反推
    return (
        PPOConfig()
        .environment("ALE/Pong-v5", env_config={"frameskip": 4})
        .env_runners(
            num_env_runners=n_runners,           # 图像任务并行收益递减较早
            num_envs_per_worker=n_envs,
            rollout_fragment_length=fragment,
        )
        .training(
            train_batch_size=batch,
            sgd_minibatch_size=256,              # 每批 16 次小批更新，梯度噪声可控
            num_sgd_iter=epochs,                 # 复用轮数：4 是图像任务的常用值
            lr=2.5e-4,                           # 对数空间中低位，配合裁剪稳定更新
            gamma=0.99,
            lambda_=0.95,                        # GAE 参数：长回合任务的标准起点
            entropy_coeff=0.01,                  # 离散动作保持少量探索
            clip_param=0.1,                      # 裁剪宽度：0.1 是通用起点
        )
        .env_runners(record_env_steps=True)      # 评估与排序统一按环境步口径
    )

解读：这份配置把前几章的结论按图像任务语境落地。（1）整除断言前置，片段长度由除法推导，避免运行期静默截断。（2）更新轮数 4 对应"每样本复用 4 次"，图像任务的裁剪比例对复用敏感，基线不取高档位。（3）按环境步记录进度：图像任务墙钟波动大（预处理与推理竞争），步数口径是实验之间唯一稳定的公共标尺。

片段 3：评估协议与搜索指标

def evaluate(algo, eval_env, episodes=5):
    """评估协议：独立环境、固定回合数、统一动作规则。
    返回每回合回报与长度的均值，供 Tune 排序使用。"""
    returns, lengths = [], []
    for i in range(episodes):
        obs, _ = eval_env.reset(seed=9000 + i)    # 固定评估场景集，跨配置可比
        done, total_r, steps = False, 0.0, 0
        while not done:
            action = algo.compute_single_action(obs, explore=False)
            obs, reward, terminated, truncated, _ = eval_env.step(action)
            done = terminated or truncated
            total_r += float(reward)
            steps += 1
        returns.append(total_r)
        lengths.append(steps)
    mean_r = sum(returns) / len(returns)
    # 回报与长度一起上报：偶然的短回合高分不应被当成能力提升
    return {"eval_return": mean_r, "eval_length": sum(lengths) / len(lengths)}

def smooth_score(history, window=5):
    """排序指标：最近若干评估点的均值，抵抗单点噪声。
    评估点不足窗口时用全部历史，保持冷启动阶段的可用性。"""
    recent = history[-window:]
    return sum(recent) / len(recent)

解读：评估代码把协议五要素具体化。（1）固定评估场景种子集：所有候选配置在相同初始状态上评估，配置间差异不混入场景抽样的随机性。（2）动作规则固定为不探索，排序口径一致；如需随机策略评估，应整套流程切换并在记录中标注。（3）平滑窗口作为排序指标：单点回报的方差可以覆盖真实差异，滑动均值把比较基准稳定到趋势上，这一点在噪声大的游戏任务中尤其重要。

常见坑

  • 包装器顺序颠倒：先堆叠再缩放使插值跨帧混合，观测出现重影，回报上限被压低。修复：工厂函数固化顺序，并用单步观测可视化抽查。
  • 训练与评估的预处理不一致：评估端手工实现简化版处理，离线指标与训练行为不符。修复：评估复用同一工厂；导出清单与工厂同源（与第 091 章衔接）。
  • 单回合评估下结论：游戏回报方差大，单回合差异多数来自场景抽样。修复：固定场景集，至少 3 至 5 回合，排序用滑动均值。
  • 跳帧参数与动作重复语义错配：动作在框内的重复次数与决策间隔不一致，策略学到错误的控制频率。修复：跳帧参数只出现一处（环境构造处），训练与评估一致。
  • 帧堆叠观测的内存低估：缓冲与对象存储按单帧估算，实际按堆叠倍数增长。修复：按第 084 章公式重新估算，存储用 1 字节每像素。

练习与思考

  1. 计算题：批 6000、8 进程、3 环境、更新轮数 4、小批 250。检查整除链；若小批改为 256，调整哪个参数能恢复一致性？★
    提示
    总数 24，6000/24=250 片段恰好；小批 256 不整除 6000，可改小批为 240 或批为 6144 并重算片段。
  2. 预测题：把更新轮数从 4 提到 12、其余不变。预测裁剪比例、评估回报与训练耗时结构的变化。★
    提示
    裁剪比例上升、学习时间占比上升；回报可能短期提升随后出现平台或回落；样本效率指标不一定改善。
  3. 设计题：为该任务设计一次 24 试验的搜索：两个超参维度、空间范围与理由、每试验预算、调度器参数、排序指标与复核方案。★★
    提示
    学习率与熵系数两维对数空间；预算取基线收敛步数的 70%；ASHA 保留前 25%；排序用评估滑动均值；前三名多种子复核。
  4. 分析题：解释为什么"先灰度化后缩放"通常比"先缩放后灰度化"更省计算，而两者的数值结果几乎一致；什么情况下这个顺序会造成可见差异？★★★
    提示
    灰度化按全分辨率计算但通道合并线性；顺序对线性变换可交换；若缩放采用带邻域混合的插值且颜色空间非线性（如含 gamma），差异才会可见。
  5. 计算题：按卷积栈 [32·8·4]、[64·4·2]、[64·3·1] 与 256 维全连接（策略与价值各一路）估算总参数量，指出占比最大的模块，并说明它对应的资源瓶颈类型。★★
    提示
    卷积合计约 7.8 万，两路全连接合计约 160.6 万，总参数约 169 万；占比最大的是全连接层，对应显存常驻瓶颈，卷积层对应推理计算瓶颈。

小结

  • 预处理链顺序不变量：跳帧、灰度、缩放先于堆叠；训练与评估共用同一工厂。
  • 卷积栈参数量适中，显存瓶颈在激活与工作区；采样端推理成本决定是否启用批量前向。
  • 采样配置按整除链一次校验：批 = 进程 × 环境 × 片段，复用轮数取中低档位配裁剪约束。
  • 评估协议五要素固定后，比较才有效；排序用滑动均值抵抗场景抽样噪声。
