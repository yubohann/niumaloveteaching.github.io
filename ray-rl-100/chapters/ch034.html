第二篇 · RLlib 核心接口与训练

第 034 章：RLlib处理文本输入

文本观测把指令、告警或描述以词序列形式送入策略网络。本章讲清词表与分词约定、嵌入与序列编码结构、填充与掩码机制，以及指令条件策略的观测组织方式。

  • 主题：RLlib 训练 / 观测模态
  • 关键机制：词表与分词、嵌入层、序列编码、填充掩码、指令条件策略
  • 预计学时：55 分钟
  • 前置章节：第 033 章

学习目标

  • 理解文本观测的编码链路：分词、词表映射、定长填充与掩码的完整流程。
  • 掌握嵌入层与序列编码器的结构选择，理解嵌入参数量与词表规模的关系。
  • 会组织指令条件策略的观测：指令序列与状态向量的组合方式。
  • 理解掩码在池化与注意力中的作用，会诊断填充污染类问题。
  • 能把自定义文本编码模型接入 RLlib 配置并核对观测空间契约。

背景与动机

语言指令让同一套策略覆盖多种任务：任务描述以文本给出，策略根据指令内容调整行为。告警文本、日志摘要与用户指令都属于此类观测。文本是离散符号序列，直接送回整数编号给网络没有意义，需要先经过嵌入与序列编码转换成语义向量。

文本链路的工程要点与技术要点同样重要：词表必须在数据编码、训练与评估三处完全一致；变长文本必须统一到定长并用掩码区分真实内容与填充位；嵌入层的参数量随词表规模线性增长。链路中任何一处编码表漂移或掩码遗漏，都会让训练数值正常而语义错位。上一章处理连续图像，本章处理离散符号序列。

核心原理

文本观测的处理分三步：把文本变成定长的整数序列、把整数序列变成向量序列、把向量序列压缩成固定长度的特征。

1. 分词、词表与定长序列

分词（Tokenization）把文本切分为词元（Token），词表（Vocabulary）建立词元到整数编号的映射，未知词元映射到专用标记。观测空间是整数区间上的定长箱式空间，形状等于最大序列长度。词表与映射规则是三处共享的合同：数据编码端、训练端与评估端使用同一份词表；任何一处漂移都会使同一句话映射到不同编号。变长文本用填充位补齐，由掩码区分真实内容。

嵌入参数量 = 词表规模 × 嵌入维度 词表 5 万、维度 64 时约 320 万参数；维度翻倍参数量翻倍，小词表任务可以直接训练嵌入，大词表场景常共享嵌入或冻结部分层

2. 嵌入与序列编码器

嵌入层把编号查表为稠密向量，序列变成（序列长度, 嵌入维度）的矩阵。编码器再压缩为固定长度特征，常用结构三类：循环网络（Recurrent Neural Network, RNN）逐词元推进，天然处理顺序；卷积结构提取局部模式；注意力结构（Transformer）建模全局依赖，表达能力强、代价更高。选择依据是任务对顺序与长程依赖的敏感度：短指令用掩码池化或浅层循环网络即可，长文本关系推理才需要更重的结构。

3. 掩码与填充污染

填充位若不屏蔽会把无意义向量混入特征：池化分母包含填充位，注意力让真实词元关注填充位。掩码把填充位置权重置零并修正分母，使编码结果与真实长度无关。掩码遗漏是最隐蔽的错误：损失与回报曲线正常，策略对相同语义的不同填充长度表现不稳定。掩码可由固定填充标记在模型内重建，也可随观测流转。

4. 指令条件策略的观测组织

指令条件策略的观测通常是组合结构：指令序列与本体状态分开编码，再在特征层拼接。观测空间用字典空间（Dict Space）声明两个分支，自定义模型分别处理后拼接，编码器各司其职，文本侧参数不干扰状态侧尺度。组合泛化用训练未见的指令与状态配对检验：表现骤降说明模型在记忆配对，尚未学到组合能力，需要增加指令多样性或调整结构。

5. 掩码池化的数值示例

取嵌入维度 2 的示意向量：真实词元向量为 [1, 0.5]、[0, 1]、[0.5, 0.5]、[1, 1]，填充向量恒为 [0.2, 0.2]，最大长度 16。真实长度 4 的样本中，真实段和为 [2.5, 3.0]，填充段和为 12 × [0.2, 0.2] = [2.4, 2.4]；不加掩码按 16 做分母得到 [0.306, 0.338]，加掩码按 4 做分母得到 [0.625, 0.75]。换一条同语义、真实长度 2 的样本，真实段和为 [1, 1.5]：不加掩码的结果降到 [0.238, 0.269]，同一语义的特征尺度随填充数量下降约两成；加掩码后得到 [0.5, 0.75]，恰好等于真实词元的均值，与填充数量无关。

带掩码池化 = Σt mt · et / max(Σt mt, 1) m 为非填充位掩码，e 为嵌入向量；分母修正让特征只由真实词元决定，省略修正时特征被填充向量按比例稀释，同语义样本的表示产生系统性偏差

6. 嵌入参数量与编码器结构的对比

嵌入层参数量 = 词表规模 × 嵌入维度，常见组合如下：

序列编码器三类结构的主要差异：

结构参数与计算特征顺序建模长依赖实现复杂度适用
循环网络（RNN）参数 O(d²)，沿序列串行计算天然保持顺序远距离信息衰减中短序列、顺序敏感任务
一维卷积（CNN）参数 O(k·d²)，计算可并行依赖窗口与位置处理由感受野决定，堆叠加深低局部模式与短语识别
注意力（Transformer）参数含查询键值投影，计算随序列长度平方增长位置编码显式表达全局直接访问高长文本与关系推理

选择依据：指令在十几个词元量级时，带掩码池化或浅层循环网络即可覆盖需求；出现跨句关系或序列到序列决策时再升级到注意力结构，并同步引入掩码注意力与正则化手段。

7. 填充长度与截断率的核算

最大序列长度按指令长度分布的高分位取值。数值示例：长度分布的 90 分位为 12 词元，取最大长度 16；文本填充到 16 后平均填充比例约三成，查表与掩码计算量按 16 计。若把上限调到 32 以覆盖长尾，平均填充比例升到约六成，计算量翻倍而有效信息不变。截断率需要监控：被裁剪样本比例高于百分之一时，考虑提高上限或对超长指令做摘要预处理。填充上限的选择是长尾覆盖与平均计算量之间的直接兑换，兑换比例由长度分布的分位数给出。

8. 注意力参数账与序列字节账

把三种编码器的代价落到具体数字。嵌入维度 64、4 个注意力头的结构，单层含查询、键、值三组投影 3 × 64 × 64 = 12288 个参数，加输出投影 4096 个，单层 16384 个，两层约 3.3 万；对照之下，嵌入表（词表 2000、维度 32）为 6.4 万参数，拼接投影（32 + 2 → 256）约 0.9 万。小词表任务的结构升级账很轻：两层注意力的参数约为嵌入表的一半（3.3 万对 6.4 万），代价集中在计算量上。

注意力单层参数量 = 3 · d²（查询、键、值投影）+ d²（输出投影）= 4d² d = 64 时单层 16384 个，两层约 3.3 万；词表 2000、维度 32 的嵌入表为 6.4 万，升级注意力的参数增量低于嵌入表本身的规模

计算量随序列长度平方增长：长度 16 时的注意力位置对为 256 个，长度 128 时升到 16384 个，相差 64 倍；按每个位置对每头 64 次乘加估算，单头单层从约 1.6 万次升到约 105 万次，再按头数与层数相乘。这是"短指令先用池化、长文本再上注意力"的量化依据：池化对长度线性，注意力对长度平方。

序列存储同样要提前算。指令分支按 16 个词元存储：int64 时 128 字节，int32 时 64 字节；2 维 float32 的状态分支为 8 字节，单样本下指令分支是状态分支的十六倍。训练批次 4000 时，int64 指令合计约 500 KB，int32 降到约 250 KB；观测在采样、回放与评估间多次复制，位宽减半省下的是对半的搬运。词表编号空间远小于 21 亿时 int32 足够且无溢出风险；选 int64 的理由通常是与其他组件对齐，这一点要在建模前确认，不能在混用后才排查。填充比例与位宽两笔账合起来，决定文本分支在样本体积中的占比；短指令任务的文本观测体积规划不能凭"指令短"想当然。

实现思路与设计

实施顺序：固定词表与分词规则、实现环境侧编码、实现自定义模型、接入配置、验证掩码与越界行为。

设计决策：为什么从小词表定长指令任务起步？

小词表让嵌入参数量可控，定长指令让掩码与形状契约简单，任务闭环短、可快速验证全链路。先证明"词表一致、掩码正确、组合泛化可测"三件事，再放大到更长的文本与更大的词表。文本任务的复杂度大多来自链路工程，起点越大，问题归因越困难。

未知词元比例应作为常驻监控项：比例超过百分之一说明词表覆盖不足，需要扩充词表并重训嵌入层；监控值按批次统计并写入训练结果，骤升通常意味着数据管道混入了新来源。分词粒度的选择：空白分词对形态变化少的短指令足够；含缩写、标点与派生词的场景改用子词切分（Subword Tokenization），用小词表覆盖开放词汇并保持泛化。超长指令的截断方向由任务语义决定，动作描述位于句尾时保留尾部，反之保留头部；截断规则写入数据说明并在审计报告中给出影响面统计。

注意力结构的计算量随序列长度平方增长：长度 16 时的注意力位置对为 256 个，长度 128 时升到 16384 个，是前者的 64 倍；升级结构前先用长度分布估算计算预算。组合泛化的数据构造按笛卡尔积预算：每条指令至少配若干状态簇，每个状态簇覆盖若干指令，交叉表写入实验记录便于评估集切分。规模示例：20 条指令与 5 个状态簇共 100 种组合，训练集用其中 80 种，评估集取剩余 20 种从未在训练中共同出现的配对，泛化缺口即为两集回报之差。嵌入层的初始化与冻结策略按数据规模决定：小数据先冻结下半层、只训练顶部，数据充足后再整体解冻微调。池化与投影之间可插入层归一化，稳定不同序列长度下的特征尺度。词表文件随模型检查点一并发布，训练端、评估端与推理端读取同一版本，映射一致性由发布物保证。同一指令在一批数据中重复出现时，编码结果可按原文缓存复用，避免重复分词；缓存容量按指令集合规模设定即可。

与上一章差异：第 033 章的观测是连续像素张量；本章的观测是离散编号序列，新增词表合同与掩码机制。下一章进入算法实现篇，讨论 DQN。

关键代码与解读

片段 1：环境侧的文本编码

import numpy as np
from gymnasium.spaces import Box, Dict

# 词表是三处共享的合同：此处构建，数据端、训练端与评估端共用
VOCAB = {"move": 1, "to": 2, "the": 3, "left": 4, "right": 5, "goal": 6}
MAX_LEN = 16                      # 定长填充长度，按指令长度高分位取值
PAD_ID = 0                        # 填充位编号；0 保留给填充与未知词


def encode_instruction(text):
    """把指令文本编码为定长整数序列；超出截断，不足填充。"""
    ids = [VOCAB.get(word, PAD_ID) for word in text.split()]
    ids = ids[:MAX_LEN]
    return np.asarray(ids + [PAD_ID] * (MAX_LEN - len(ids)), dtype=np.int64)


class TextGoalEnv:
    """指令条件任务：指令描述目标方向，状态为二维位置与速度。"""

    def __init__(self, env_config=None):
        self.observation_space = Dict({
            # 指令分支：整数编号序列，上界为词表最大编号
            "instruction": Box(low=0, high=max(VOCAB.values()),
                               shape=(MAX_LEN,), dtype=np.int64),
            # 状态分支：连续量，与指令分支分开编码
            "state": Box(low=-np.inf, high=np.inf, shape=(2,),
                         dtype=np.float32),
        })
        # 动作空间与任务维度一致，此处略去具体定义

    def reset(self, *, seed=None, options=None):
        self.rng = np.random.default_rng(seed)
        # 指令在训练集内随机抽取，评估集可切换为未见组合
        self.text = self.rng.choice(["move to the left", "move to the right"])
        obs = {
            "instruction": encode_instruction(self.text),
            "state": np.asarray([0.0, 0.0], dtype=np.float32),
        }
        return obs, {}

解读：环境侧编码承担两件事：词表映射与定长化。词表、填充位与最大长度都是跨环节合同，首页注释即强调这一点；编码结果用 int64 数组，与观测空间声明的 dtype 严格一致。字典空间把指令与状态分成两个分支，为自定义模型的分支编码提供结构依据。评估集切换未见组合的开关放在环境参数中，与第 026 章的评估协议衔接。

片段 2：嵌入与掩码池化模型

import numpy as np


class TextEncoder:
    """嵌入加带掩码的均值池化：短指令任务的轻量编码器。"""

    def __init__(self, vocab_size=2000, embed_dim=32, state_dim=2):
        # 嵌入表参数：词表规模乘嵌入维度；小词表可直接训练
        self.embedding = np.random.normal(
            0.0, 0.02, size=(vocab_size, embed_dim)).astype(np.float32)
        self.proj = np.random.normal(
            0.0, 0.02, size=(embed_dim + state_dim, 256)).astype(np.float32)

    def forward(self, instruction_ids, state):
        # 查表得到（批量, 序列, 维度）的向量序列
        tokens = self.embedding[instruction_ids]
        # 掩码：非填充位为 1，填充位为 0；分母只统计真实词元
        mask = (instruction_ids != 0).astype(np.float32)
        denom = np.clip(mask.sum(axis=1, keepdims=True), 1.0, None)
        pooled = (tokens * mask[..., None]).sum(axis=1) / denom
        # 文本特征与状态特征在特征维度拼接，再送公共投影层
        fused = np.concatenate([pooled, state], axis=1)
        return np.tanh(fused @ self.proj)

解读：模型演示掩码池化的三个关键动作：查表得到向量序列；用非零判定构造掩码；求和时乘掩码并用真实长度做分母。掩码的分母修正是容易被省略的一步：只乘掩码不修正分母时，池化结果的尺度随填充数量漂移，等效于语义特征被随机缩放。文本特征与状态在拼接后共享投影层，特征维度 256 是容量与参数量之间的折中。真实实现应把嵌入与投影接入框架的自动微分，此处以 NumPy 呈现机制。

片段 3：自定义模型接入配置

from ray.rllib.algorithms.ppo import PPOConfig

config = (
    PPOConfig()
    .environment(env=TextGoalEnv)
    .training(
        train_batch_size=4000,
        model={
            # 自定义模型类接收超参与模型配置：词表与维度经此对齐
            "custom_model": "text_encoder_model",
            "custom_model_config": {
                "vocab_size": 2000,          # 与观测空间上界一致
                "embed_dim": 32,             # 嵌入宽度
                "state_dim": 2,              # 状态分支维度
            },
            "fcnet_hiddens": [256],          # 编码器输出后的全连接头
        },
    )
    .env_runners(num_env_runners=4)
)
algo = config.build_algo()

解读：接入点有两处校验：配置中的词表规模与观测空间上界一致，状态维度与环境输出长度一致。两者的不一致在冒烟阶段以查表越界或拼接错误暴露；更难查的是词表内容一致而映射规则不同，需用同一样例文本在三处做编码比对。注册方式随版本演进，以官方文档为准。

常见坑

  • 词表映射漂移：数据端与训练端词表版本不同。症状是语义错位而数值正常。修复：词表随数据与检查点共同存档，三处读取同一份文件。
  • 填充位未加掩码：池化混入填充向量。症状是同一语义的不同长度表现不一致。修复：掩码加权并修正分母，或改用在模型内重建掩码的固定标记方案。
  • 变长序列直接入批：不同长度导致批次形状不一。症状是形状错误或隐式截断。修复：统一填充到定长，长度上限写入观测空间声明。
  • 编号越界：文本中出现词表外词汇且未映射到未知标记。症状是嵌入查表报错。修复：编码端兜底到未知标记，并对越界计数做监控。
  • 嵌入维度过大：小词表配大维度导致参数量与过拟合风险上升。症状是训练损失低而评估泛化差。修复：嵌入维度与状态特征尺寸匹配，先小后大做消融。

练习与思考

  1. 词表 5000、嵌入维度 64，计算嵌入层参数量并说明与全连接头参数的占比关系。★
    提示
    约 32 万参数；若全连接头为 64→256→动作维度，参数量约两万量级，嵌入层占主导，词表规模直接决定模型容量。
  2. 把最大序列长度从 16 改到 32，预测掩码计算量与嵌入特征质量的变化方向。★
    提示
    掩码与查表计算量约翻倍；长指令不再被截断，但填充比例上升，掩码正确性变得更关键。
  3. 推导：说明带掩码均值池化与不带掩码时特征期望的差异，解释分母修正的必要性。★★
    提示
    不带掩码时分母为最大长度，特征期望被填充向量的期望按长度比例稀释；修正分母后特征期望只由真实词元决定，与长度无关。
  4. 设计组合泛化评估：训练指令集合与状态分布交叉，构造评估集并说明判定指标。★★
    提示
    评估集取训练未见的指令与状态配对；指标用评估回报与指令跟随成功率，与训练组合的表现差值即泛化缺口。
  5. 设计升级路径：把掩码均值池化替换为注意力编码器，说明参数量、计算量与需要的正则化手段的变化。★★★
    提示
    注意力增加查询、键、值投影参数，计算量随序列长度平方增长；需要掩码注意力防填充污染，并加权重衰减或丢弃法控制过拟合。

小结

  • 文本观测经分词、词表映射、定长填充与掩码进入网络；词表是三处共享的合同。
  • 嵌入参数量等于词表规模乘嵌入维度，词表规模直接决定模型容量与过拟合风险。
  • 序列编码器按任务选择：短指令用掩码池化或浅层循环网络，长依赖再上注意力结构。
  • 掩码遗漏造成填充污染，症状隐蔽；池化需同时修正权重与分母。
  • 指令条件策略用字典空间组织观测，文本与状态分支分开编码后拼接。
