第二篇 · RLlib 核心接口与训练

第 030 章：RLlib与Ray Tune集成

Ray Tune 是训练之上的实验调度层。本章讲清试验（Trial）的执行模型、RLlib 算法作为可训练对象的接入方式、参数注入的层级结构、资源声明与并发度的关系，以及结果读取与检查点恢复的要点。

  • 主题：RLlib 训练 / 实验调度
  • 关键机制：试验执行模型、参数注入层级、资源声明、结果上报、检查点
  • 预计学时：55 分钟
  • 前置章节：第 029 章

学习目标

  • 理解 Tune 的试验执行模型：试验、调度器与运行配置三者的职责划分。
  • 掌握 RLlib 算法作为可训练对象的接入方式与参数注入的层级结构。
  • 会声明每个试验的资源并推算并发试验数，避免资源超配导致排队。
  • 会设置停止条件、读取结果表并从检查点恢复训练。
  • 能设计第一轮实验规模：先少量试验建立基线，再放大搜索范围。

背景与动机

单次训练只能回答这套配置表现如何，无法回答哪套配置更好。超参搜索把训练封装为可重复的试验，由调度层批量运行、收集结果。RLlib 与 Ray Tune 的集成让算法配置直接成为搜索空间载体：学习率、批次、并行度作为参数注入，Tune 负责排队与结果汇总。

集成难点集中在两处：参数注入的层级必须与算法配置结构对应，写错层级时参数被静默忽略；资源声明必须与容量匹配，超配的试验停留在排队状态。先做对这两处，再谈搜索策略与调度算法。上一章完成多卡扩展，本章把训练整体接入调度层。

核心原理

Tune 把"跑很多次训练"组织为试验生命周期管理问题，核心对象是试验、训练函数与调度器。

1. 试验执行模型

一个试验是一次完整训练运行，承载一组具体参数；调度器决定试验何时启动与停止；运行配置（RunConfig）描述停止条件、检查点策略与并发控制。RLlib 算法以可训练对象（Trainable）注册，Tune 按名称加配置实例化，训练循环对外表现为迭代步进与结果上报。每个试验独立持有自己的算法实例、工作进程与检查点目录，试验之间默认不共享状态。

2. 参数注入的层级结构

搜索空间通过 param_space 注入，结构与算法配置层级一一对应：顶层键对应算法级配置，嵌套键对应分组配置（采样、训练、资源）。注入发生在试验启动前，Tune 为每个试验采样一组值再构造算法。层级写错是最高频的错误：参数落在未识别键上会被部分版本安静忽略，症状是不同试验曲线完全一致。

3. 资源声明与并发度

每个试验声明资源包（CPU 核组与 GPU 配额），基本约束是同时在运行的试验资源之和不超过容量。并发试验数由容量除以单试验资源得到；试验内部并行度调高会直接减少并发数，两者共享同一批核心。总吞吐近似为并发数乘单试验吞吐。

并发试验数 ≈ floor(可用资源 / 单试验资源包) 8 试验并行、每个占用 2 核加 0.5 张卡时，总需求为 16 核与 4 张卡；任一维度不足都会使部分试验排队

4. 检查点与恢复

检查点（Checkpoint）保存算法状态：策略权重、优化器状态与训练计数器。检查点策略决定保存频率与保留数量，恢复时按检查点重建算法继续迭代。恢复要求配置结构与原始实验一致，结构变化会使旧检查点无法映射。结果表记录指标序列与检查点位置，模型选择基于评估指标。

5. 搜索成本与并发墙钟的估算

给定总试验数 K、最大并发 C、单试验迭代数 T，搜索墙钟按波次估算：

W ≈ ceil(K / C) × T，C = min( ⌊CPU总量 / CPU试验⌋, ⌊GPU总量 / GPU试验⌋ ) K = 24、C = 6、T = 50 时 W ≈ 4 × 50 = 200 个迭代单位；并发数取两个资源维度的较小值，先触顶的维度决定排队

数值示例：32 核与 4 卡的容量下，单试验声明 5 核与 0.5 卡，CPU 维度容纳 6 个试验，GPU 维度容纳 8 个，并发取 6。20 个试验排成 4 波，末波只有 2 个试验，其余资源空转；试验数接近并发数的整数倍时排程最紧凑。把 K 调整为并发数的整数倍，或用 num_samples 补齐末波，是低成本提升资源利用率的做法。

6. 试验内部并行度与并发数的权衡

容量固定时，单试验核数 c 与并发数 C = ⌊32/c⌋ 互为反比。数值对照：c = 5 时 C = 6，单个试验推进最快；c = 3 时 C = 10，单试验变慢但并行试验数多；c = 2 时 C = 16，单试验进入效率偏低的核数区间。在核心线性区间内，两种组合的总试验吞吐接近，差异在于周转速度与资源碎片；当 c 小到并行收益很弱的区间，总吞吐反而下降。选择依据：需要尽快得到单个结果时用大 c 小 C；需要广泛筛参数时用小 c 大 C，并保持所有试验使用相同的 c 与 T，结果才可比。

7. 资源声明策略的对比

声明策略声明值示例试验实际占用后果适用情形
保守5 核 + 0.5 卡4 个采样进程加学习线程并发略低，调度行为稳定默认建议，首轮实验
精确按实测峰值声明与声明一致并发最高，资源利用率最好已有监控数据、进入正式搜索
偏低3 核 + 0.25 卡实际需要 5 核试验间争抢核心，指标抖动不推荐，仅用于短期验证

核算方法：把试验内部声明的采样进程核数与学习线程核数相加，再加上容器与系统开销，得到单试验资源包；声明值与实际占用偏离越大，调度器的排队与争抢行为越难预测。

8. 停止条件的组合与风险

迭代上限与评估阈值可以同时写入 stop 字典，先满足者生效。示例：{"training_iteration": 200, "evaluation/episode_return_mean": 180}。阈值口径决定风险：训练回报带探索噪声，数值偏高，用训练字段做停止条件会让试验过早停止；评估字段的更新频率低于训练轮次（例如每 5 轮评估一次），阈值检测会滞后若干轮，迭代上限在这里起兜底作用。双条件并用是标准写法：指标负责效率，迭代上限负责预算可控。

9. 波次排程与检查点写入的量化

试验按波次推进，每波占满并发后开始下一波，末波不满时资源空转。取并发数 6（32 核容量、单试验 5 核的推算值），三档试验数的排程效率如下：24 个试验恰好排 4 波，利用率百分之百；20 个试验同样要 4 波，末波只有 2 个在跑，利用率约 83%，相对理想时长多耗约两成；8 个试验排 2 波，利用率约 67%，多耗约五成。把试验数定成并发数的整数倍，或用重复采样补齐末波，是不花额外成本的调度优化。

试验数并发数波数资源利用率
2464100%
2064约 83%（多耗约 20%）
862约 67%（多耗约 50%）
利用率 = 试验数 /（波数 × 并发数），波数 = 向上取整（试验数 / 并发数） 末波不满的损失只发生在最后一波；试验数远大于并发数时该损失占比被摊薄，整数倍排程仍然最紧凑

另一笔固定账是检查点的写入量。5000 万参数模型的完整状态（参数、优化器矩与计数器）按参数体积的三到四倍估算，约 600 至 800 MB；20 个试验各保留 5 份中期检查点即约 60 GB 写入，按持续 200 MB/s 的写盘速度折算约 300 秒的额外输入输出时间。短试验只保留末次检查点、长试验限制保留份数，两项纪律把写入量压回与恢复需求匹配的水平。写入与训练共用存储时，检查点时刻的输入输出抢占会叠加到迭代时间上，保存频率的取值要把这条隐性成本计入。

搜索空间也有一笔格子账：4 个参数各取 5 档时全网格为 625 组，预算只有 25 个试验时，网格只能覆盖其中二维的 5 × 5 子格，其余参数被迫固定；同等预算下随机采样能在全部维度上撒点，代价是每维覆盖稀疏。首轮筛选用随机采样铺开维度，锁定少数关键参数后再用网格细化，两阶段组合兼顾广度与可比性。

实现思路与设计

第一轮集成的设计顺序：单试验验证、资源核算、小规模搜索、结果读取、扩展边界。

配置项示例值作用取值依据
num_samples8采样的参数组合数首轮验证用少量组合，确认链路后再放大
试验资源包2 核 + 0.5 卡单试验占用的资源与试验内部并行度合计核算，总量不超过容量
stop迭代数或评估回报试验终止条件指标用评估口径，避免训练噪声误停
检查点频率每 10 轮状态保存间隔长试验取小值，短试验只留末次
设计决策：为什么第一轮只跑少量试验？

失败模式大多与训练质量无关：参数层级写错、资源超配、停止条件不触发、目录冲突。少量试验把链路验证与搜索质量分开：先用个位数试验确认启动、上报与落检查点，再放大数量。链路未验证前扩大试验数，只会把同一处错误重复很多遍。

搜索空间大小的组合计算：学习率取 3 档、训练批次取 2 档、采样进程数取 2 档，网格组合为 3 × 2 × 2 = 12 组，num_samples 取 2 时总试验 24 个，按并发 6 排成 4 波调度。层级写错时，24 个试验只跑出同一种实际配置，结果表的参数列完全相同，识别成本很高；首轮打印生效配置可以在试验数量放大之前拦截这类问题。

检查点频率的权衡：保存动作的写入量等于模型与优化器状态的大小，频率越高累计写入越多。以 5000 万参数的模型为例，一次完整状态按数百 MB 至 1 GB 量级估算，保留十份即占用数 GB 磁盘空间。短试验只保留末次检查点，长试验按 10 至 20 轮间隔保留并限制份数，写入量与恢复粒度之间取平衡。恢复前核对四项：检查点目录完整、参数结构一致、依赖版本一致、迭代计数从检查点续接；核对完成后先做一次短运行，确认恢复后的评估指标与保存前衔接。

结果表分析的起步视图取三列：参数列确定配置，评估指标列衡量质量，迭代数列衡量速度。先看参数与指标的趋势关系，再决定放大搜索的方向；趋势不明显的维度保持固定，把预算集中到有区分度的参数上；训练与评估两套口径并存时，排序一律使用评估列。停止条件每次调整后，先在单试验上验证触发时机，再投入批量搜索。

停止条件的阈值需要按评估间隔折算：每 5 轮评估一次时，指标从达标到触发终止最多滞后 5 轮，迭代上限按这一滞后量留出余量。试验内部并行度一旦改变，历史试验与新试验的结果可比性下降；对照实验应保持内部结构一致，只变动待研究的参数。多个实验并行运行时，检查点与结果文件的写入目标目录必须隔离，同名文件互相覆盖会让恢复流程读到混杂状态；目录命名带上时间戳与参数摘要，事后检索无需打开文件即可定位到目标实验。

与上一章差异：第 029 章在单次训练内部扩展算力；本章把训练放进调度框架，引入试验间资源竞争与结果汇总。搜索空间设计与调度策略属于第四篇主题，本章只建立集成骨架。下一章接入训练曲线可视化。

关键代码与解读

片段 1：PPO 试验的最小集成

from ray import tune
from ray.tune import RunConfig

# 单试验验证用最小结构：算法名、参数注入、停止条件三件套
tuner = tune.Tuner(
    "PPO",                                    # RLlib 算法名字符串即 Trainable
    param_space={
        "env": LineGoalEnv,                   # 环境类经配置序列化分发
        "env_config": {"horizon": 120},
        "lr": 3e-4,                           # 顶层键对应算法训练配置
        "train_batch_size": 8000,
        "num_env_runners": 2,                 # 试验内部并行度：直接影响资源包
        "num_envs_per_env_runner": 2,
    },
    run_config=RunConfig(
        stop={"training_iteration": 30},      # 首轮用迭代数停止，便于预估预算
        checkpoint_config={"checkpoint_frequency": 10},
    ),
)
results = tuner.fit()
best = results.get_best_result(metric="episode_return_mean", mode="max")
print(best.metrics["episode_return_mean"])

解读：最小集成验证三个环节：参数注入（顶层字典展开为算法配置）、结果上报（每轮结果进入试验指标）、停止与检查点。首轮用迭代数停止便于估算单试验成本；正式搜索再切换评估指标停止条件。get_best_result 按评估口径取最优试验，返回值可直接用于后续分析。

片段 2：小规模搜索空间与资源声明

from ray import tune

# 首轮搜索只放两个参数：学习率与批次，其余保持常量
param_space = {
    "env": LineGoalEnv,
    "lr": tune.grid_search([1e-4, 3e-4, 6e-4]),      # 三个候选：共三组试验
    "train_batch_size": 8000,
    "num_env_runners": 4,
    "num_envs_per_env_runner": 2,
    # 资源声明与试验内部并行度合计核算：
    # 每试验 4 个采样进程加学习线程，资源包按 5 核声明较稳妥
}
tuner = tune.Tuner(
    "PPO",
    param_space=param_space,
    tune_config=tune.TuneConfig(
        num_samples=1,                        # 与 grid_search 组合：每组各跑一次
    ),
    run_config=RunConfig(
        stop={"evaluation/episode_return_mean": 180},
        checkpoint_config={"checkpoint_frequency": 10},
    ),
)
results = tuner.fit()

解读：网格搜索的候选组合数等于各参数候选数乘积，与 num_samples 相乘得到总试验数；首轮用单维网格便于核对成本。资源声明依据试验内部进程与学习线程的实际占用：偏小造成争抢，偏大降低并发数。停止条件使用评估字段路径，写法随版本演进，以对应版本文档为准。

片段 3：结果表读取与检查点恢复

import pandas as pd

# 结果表每行一个试验：参数、指标、检查点与状态
df = results.get_dataframe()
cols = ["trial_id", "lr", "episode_return_mean",
        "evaluation/episode_return_mean", "training_iteration"]
print(df[cols].sort_values("evaluation/episode_return_mean",
                           ascending=False).head())

# 恢复：从最优试验的检查点继续，参数结构必须与原始实验一致
best = results.get_best_result(metric="evaluation/episode_return_mean",
                               mode="max")
restored = tune.Tuner.restore(
    best.path,                                # 试验目录或实验目录
    trainable="PPO",
    resume_errored=True,                      # 出错试验一并恢复
)
results_2 = restored.fit()

解读：结果表把搜索过程变成可分析数据：参数列用于归因，指标列用于排序，检查点路径用于恢复。排序使用评估指标，与评估章节的约定一致；若结果表中评估字段缺失，先检查评估配置是否随试验生效。恢复入口接受实验目录或单个试验目录，参数结构一致的约定必须在实验管理层面维护：配置一旦调整，旧检查点的可恢复性随之改变。

常见坑

  • 参数注入层级写错：键名与配置结构不匹配，试验静默使用默认值。症状是不同试验曲线完全一致。修复：对照配置结构逐键核对，首轮打印实际生效配置。
  • 资源声明超过集群容量：任何时刻都无法凑齐单试验资源。症状是试验长期处于排队状态。修复：按容量与单试验需求重新核算，或缩小试验内部并行度。
  • 停止条件永不触发：指标名错误或阈值不可达。症状是试验耗尽时间预算，指标并未达标。修复：首轮打印指标键名，用单试验确认停止逻辑。
  • 检查点目录冲突：多次实验写入同一目录，恢复读取到混杂状态。症状是恢复后行为异常。修复：实验目录按时间或标识隔离，恢复时显式指定目录。
  • 搜索空间一次开得过大：数十组试验同时启动，失败模式被复制放大。症状是大量试验同时报错或排队。修复：先少量试验验证链路，再按预算分批扩展。

练习与思考

  1. 集群有 32 核与 4 张卡，单试验声明 5 核与 0.5 卡，计算最大并发试验数并说明哪一维先成为约束。★
    提示
    核心维度可容纳 6 个试验（32/5），GPU 维度可容纳 8 个；核心先成为约束，并发数取 6。
  2. 停止条件从迭代数切换为评估回报后，预测试验平均时长的变化与风险，说明双条件并用的写法。★
    提示
    达标早停的试验变短，平均时长受表现差异影响波动加大；双条件写法是 stop 中同时给出上限迭代数与指标阈值，取先满足者。
  3. 推导：总搜索墙钟时间与并发试验数、单试验时长、试验总数三个量的关系，说明为什么单试验内部并行度存在最优区间。★★
    提示
    时间约为试验总数除以并发数再乘单试验时长；内部并行度提高单试验吞吐但占用更多资源，降低并发数，两者乘积存在极值点。
  4. 设计首轮验证清单：从参数注入、结果上报、检查点、恢复到资源核算，列出每项的验证方式与通过标准。★★
    提示
    每项都可用单试验最小运行验证：打印生效配置、检查指标键、确认检查点文件生成、执行一次恢复运行、核对并发数达到预期。
  5. 设计实验：固定总预算，比较"少量长试验"与"大量短试验"两种策略对最终评估指标的取舍，说明适用条件。★★★
    提示
    长试验减少早停噪声、适合接近收敛的对比；短试验覆盖更多组合、适合早期筛选。用同一预算跑两种策略，比较最优试验的评估回报与方差。

小结

  • Tune 把训练封装为试验，调度器控制排队与终止，每个试验独立持有算法实例与检查点目录。
  • 参数注入的层级与算法配置一一对应，层级写错会静默失效，首轮必须打印实际生效配置。
  • 并发试验数由总资源除以单试验资源包得出，内部并行度与并发数共享同一批核心。
  • 停止条件用评估口径并设置迭代上限，检查点用于恢复，恢复要求参数结构一致。
  • 集成的第一步是少量试验验证链路，再按预算放大搜索范围与试验数量。
