第 042 章：RLlib实现AlphaZero风格算法

搜索与学习互相成就：蒙特卡洛树搜索（Monte Carlo Tree Search, MCTS）如何用策略价值网络的先验替代均匀探索、访问计数如何蒸馏回网络参数、自博弈（Self-play）回路为什么需要缓冲区与竞技场两道闸门。

  • 主题：RLlib 训练（搜索增强型算法）
  • 关键机制：PUCT 选择、访问计数蒸馏、自博弈数据回路
  • 预计学时：60 分钟
  • 前置章节：第 041 章

学习目标

  • 理解 AlphaZero 风格算法的三段结构：网络引导的搜索、访问计数蒸馏、自博弈数据回路。
  • 掌握 PUCT 选择公式中先验项与探索项各自的数学作用，以及根节点狄利克雷（Dirichlet）噪声的动机。
  • 掌握温度参数（Temperature）对策略目标分布的影响，能设计退火计划。
  • 会在 RLlib 中通过多智能体映射与自定义回环组织自博弈训练，理解为什么该算法没有现成内置实现。
  • 能规划模拟次数、缓冲区容量、竞技场评估阈值三类参数，并说明其与训练成本的量化关系。

背景与动机

标准策略梯度方法直接学习"状态到动作分布"的映射，在搜索树分支极多的对弈任务里，每一步都被迫在没有前瞻的情况下选择动作，样本效率低下。AlphaZero 风格的算法把搜索嵌入学习回路：搜索借助网络先验减少无效展开，网络又借助搜索产生的更优动作分布得到改进，两者互相增强。

RLlib 内置算法集中于无搜索的策略优化，AlphaZero 风格需要自行组装。本章讲透其数学结构，并给出在 RLlib 框架内落地的最小骨架，重点是"为什么这样组织"，完整系统的复现不在本章范围。

核心原理

本节按数据流顺序拆解算法：一次模拟如何选择、目标如何构造、回路如何闭合。

1. 网络的两个输出与搜索的两个用途

策略价值网络的输入是状态，输出两部分：动作先验 P(s,·) 与状态价值 v(s)。搜索过程对两部分的使用方向相反：先验 P 用于"选择向何处展开"（把模拟预算花在更可能的好着法上），价值 v 用于"判断叶节点好坏"（替代到终局的完整模拟）。搜索结束后，根节点各子动作的访问计数 N(s,a) 就是一份比网络原始先验更可靠的策略，这正是蒸馏信号的来源。

2. PUCT 选择：先验与探索的加权和

模拟从根节点下行时，每个节点按 PUCT 分数选择子动作：

U(s, a) = Q(s, a) + cpuct · P(s, a) · √( Σb N(s, b) ) / ( 1 + N(s, a) ) Q(s,a) 为该动作的平均回传价值；先验项随父节点访问总量增长而增大，随自身访问次数衰减，实现"探索一次即降权"

公式里藏着两条设计意图。（1）当某动作从未被访问（N=0），先验项取最大值、Q 项为零，网络认为有希望的分支优先获得尝试机会。（2）随父节点总访问量上升，未充分尝试的动作的探索权重递增，搜索不会过早锁死在单一分支上。系数 cpuct 控制探索强度，对弈任务常用 1.5 至 2.5。

根节点处还会向先验注入狄利克雷噪声：P′(s,·) = (1−ε)·P(s,·) + ε·Dir(α)。训练期的自博弈需要足够的落子多样性，否则搜索反复选择同一条主变，数据分布塌缩到单一路径；评估期关闭噪声，取确定性强着。

3. 目标构造：计数蒸馏与结果回传

一局结束后，每个时间步 t 生成一条训练样本：搜索结束的根节点访问计数构成策略目标 πt(a) ∝ N(st, a)1/τ，价值目标是该局结果 z ∈ {+1, −1}（或引入折扣回传的多步目标）。网络损失为三项之和：

L = − Σa πt(a) · log pθ(a | st) + ( z − vθ(st) )² + c · ‖θ‖² 第一项为交叉熵策略蒸馏，第二项为价值回归，第三项仅做示意；温度 τ 控制 π 的尖锐程度

温度的行为需要精确理解：τ=1 时目标正比于访问计数，保留搜索的探索分布；τ→0 时目标退化为访问量最大的单点分布，用于强着法。训练早期用高温（如 1.0）保证样本多样，随训练推进或对局步数增长线性降温到接近零，这是标准做法。

4. 自博弈回路：三个部件与两道闸门

自博弈指当前网络同时执黑白两方对局，把对局数据写入回放缓冲（Replay Buffer），再用缓冲区数据训练网络，形成闭环。回路中必须设置两道闸门：

  • 数据闸门（缓冲区窗口）：只保留最近若干局数据。网络迭代若干次后，早期数据对应的策略分布已过时，继续训练会把网络拉向旧分布；窗口大小需要与每轮迭代的数据产出量匹配。
  • 版本闸门（竞技场评估）：新网络与基准网络对弈若干局，胜率超过阈值（如 0.55）才将其设为新的数据生成网络，防止一次糟糕更新污染后续所有数据。评估必须关闭根节点噪声与温度退火，保证结果可复现。

从 RLlib 的视角看，自博弈就是上一章"学习者对固定对手"的演进：数据生成网络固定在样本收集路径上，训练更新其副本，竞技场通过后交换角色。映射函数在此承担对手生成器的职责，两方映射到同一策略集合的不同成员。

5. 数值算例：竞技场判定与搜索成本

竞技场的判定本质是一次二项检验。200 局、胜率阈值 55%（即至少 110 胜）时，观测胜率的标准差约 3.5%。真实胜率 50% 的网络偶然过线的概率约 8.9%；真实胜率 53% 的网络过线概率约 31.0%；真实胜率 57.5% 的网络过线概率约 78.5%。这组数字揭示版本闸门的两类错误：阈值 0.55 对 53% 水平的网络放行概率不低，而 57.5% 的网络仍有约两成概率被拦下。降低误判的标准手段是加局数：局数升到 800 时标准差减半、判别力提高，代价是评估耗时同步上升。

搜索成本同样要算：每步 200 次模拟、对局 60 步时，单局需要 1.2 万次网络前向；单次前向 2 毫秒时单局约 24 秒，评估期用 800 次模拟时升到约 96 秒。自博弈的数据产出速率由此被搜索预算锁定，训练批次的供给节奏与模拟次数直接挂钩；把训练期模拟次数压到评估期的一半以内，是控制采样占比的常用手段。批量并行搜索时还要注意虚拟损失（virtual loss）：同一批并发线程需要临时下调已选中路径的分数，否则多个线程反复撞进同一条主变，模拟预算被重复消耗。

6. 边界与失效模式

终局语义的边界有三种要区分：一方获胜（±1）、和棋（0）、达到步数上限判和（0）。胜负符号只对取胜方取正；和棋样本的价值目标取零，若错误地按"最后行动者取正"处理，网络会把和棋学成胜负，评估胜率随之扭曲。

循环局面的边界在规则层：对弈状态可能重复出现（双方来回走子），搜索若不做局面去重（置换表）会被无意义分支吞掉模拟预算；规则层若有重复判和条款，环境的终止逻辑必须实现它，否则自博弈数据里会出现大量重复状态的样本。

推理吞吐的边界在搜索与网络的耦合方式：搜索是串行的树推进，网络是批量的张量运算，两者节奏不匹配时设备利用率被单线程拖低。缓解手段是把一次模拟内的多次前向合并成批（树并行），或用统一的推理服务进程承接前向请求，代价是同步与延迟管理复杂度上升。

7. 数值算例：温度缩放与噪声强度

狄利克雷噪声的典型强度也可估计：7 个动作、α = 0.3 时，噪声分布的最大分量平均约 0.55，约 81% 的采样会把某个动作的噪声分量推到 0.4 以上；经 ε = 0.25 混合后，一个原本均匀的先验（约 0.143）会被典型抬升到约 0.24 的级别。噪声过小则主变单一、数据塌缩；过大则先验被淹没、搜索退化为随机试探，α 与 ε 的取值就是在这两端之间找落点。

8. 探索结构的对照

搜索变体选择依据数据多样性样本效率失效形态
均匀蒙特卡洛树搜索访问次数高低，预算摊薄在弱分支收敛慢
先验引导（PUCT）Q 值与先验加权中高先验偏差被放大、主变单一

对照的读法：三种变体的差别只在探索项的信息来源与扰动方式，训练目标与蒸馏机制不变；结构升级的顺序是从均匀起步，加入先验，再加入噪声与退火，每一步都用竞技场胜率验证收益，负收益的组件回退，升级过程本身留在完整的对照记录里。

实现思路与设计

在 RLlib 中实现该算法的最小路径分四步。

  1. 把搜索封装进策略决策路径：每一步动作由 MCTS 给出，搜索使用网络推理。落地方式是把搜索作为策略类的方法（自定义策略的 compute_actions 内调用搜索），网络参数由 RLlib 管理，训练时复用同一策略对象做批量前向。
  2. 用多智能体接口组织对局双方：两个玩家各为一个 agent，映射到"数据生成"与"基准"两份策略；数据生成策略的更新通过参数同步完成，基准策略保持冻结。
  3. 在样本后处理中构造监督目标：搜索产生的计数目标写入样本批次，作为策略蒸馏项与价值回归项的标签，替换标准策略梯度的优势估计。
  4. 组装训练回环：采集若干局 → 训练若干个 mini-batch → 竞技场评估 → 达标后同步参数并清空旧数据。

关键代码与解读

片段 1：PUCT 选择与一次模拟的主循环

import math

def puct_select(node, c_puct=2.0):
    """在节点内选择一个子动作：Q 均值 + 先验加权的探索项。"""
    best, best_score = None, -float("inf")
    for action, child in node.children.items():
        # Q 在首次访问时定义为 0，先验项占主导，保证未见过的分支被尝试
        q = child.value_sum / child.n if child.n > 0 else 0.0
        # 先验项：父访问总量开方后乘以先验，除以自身访问数实现探索衰减
        u = c_puct * node.prior[action] * math.sqrt(node.n) / (1 + child.n)
        score = q + u
        if score > best_score:
            best, best_score = action, score
    return best

def simulate(root, model, depth=60):
    """一次模拟：下行选择、叶节点估值、回传。"""
    node, path = root, []
    while node.children:                       # 已展开的内部节点继续下行
        action = puct_select(node)
        path.append((node, action))
        node = node.children[action]
    value = node.terminal_value if node.terminal else model.predict_value(node.state)
    for parent, action in reversed(path):      # 自底向上回传，符号随换手翻转
        parent.children[action].n += 1
        parent.children[action].value_sum += value
        value = -value                          # 视角交替：对手的好即自己的坏
    root.n += 1

解读：这段代码包含 PUCT 实现中最容易出错的三个细节。（1）Q 的未访问默认值取 0：若取负无穷，先验项永远被压制，搜索退化为广度遍历；取 0 与"价值在零附近的对称对局"直觉一致。（2）探索项分母用 1 + n：未访问时退化为常数，避免除零并使首次选择完全由先验决定；改用 n 作分母会在首访时除零。（3）回传时价值取负号：节点价值以"轮到谁行动"的视角存储，沿路径逐层翻转符号，这正是双人零和博弈的标准约定，漏掉翻转会让网络学到相反的胜负观。

片段 2：从访问计数构造训练目标

import numpy as np

def make_training_targets(root, outcome, temperature=1.0):
    """把一局中某一步的搜索结果转成监督标签。
    root 为该步搜索树根，outcome 为局终结果（当前玩家视角 +1 / -1）。"""
    counts = np.array([root.children[a].n for a in range(root.n_actions)], dtype=np.float64)
    if temperature < 1e-3:
        pi = np.zeros_like(counts)              # 退火到极限：单点分布
        pi[int(np.argmax(counts))] = 1.0
    else:
        weights = counts ** (1.0 / temperature) # 高温保留搜索的探索分布
        pi = weights / weights.sum()
    # 价值目标用局终结果；若用多步回传目标，需按折扣逐步替换 outcome
    return {"policy_target": pi.astype(np.float32), "value_target": float(outcome)}

def self_play_game(env, net, temperature_steps=15, n_sim=400):
    """网络对自身下一整局，逐步保存（状态，搜索目标）。"""
    trajectory, state = [], env.reset()
    while True:
        root = build_tree(env, state, net)      # 根节点注入狄利克雷噪声
        for _ in range(n_sim):
            simulate(root, net)
        tau = 1.0 if len(trajectory) < temperature_steps else 0.1
        target = make_training_targets(root, 0.0, tau)
        action = np.random.choice(len(target["policy_target"]), p=target["policy_target"])
        trajectory.append((state, target))
        state, _, done, info = env.step(action)
        if done:
            z = info["winner_sign"]             # 统一视角的胜负符号
            for idx in range(len(trajectory)):
                # 偶数步属于同一方；胜负符号按步数奇偶翻转成"该步玩家视角"
                trajectory[idx][1]["value_target"] = z * (1 if idx % 2 == 0 else -1)
            break
    return trajectory

解读：逐块说明设计意图。（1）温度分支处理两种模式：退火后取最大访问动作，训练早期按 counts^(1/τ) 采样，让对局覆盖不同分支。（2）动作从目标分布中采样以保留训练期数据多样性；评估期应改为确定性取最大。（3）胜负符号按步数奇偶翻转，把统一的局终结果改写成每一步行动者的视角，与片段 1 的回传符号约定保持一致。（4）轨迹先收集完后统一写标签，因为局终结果只在结束时可知。

片段 3：RLlib 中的自博弈回环骨架

from ray.rllib.algorithms.ppo import PPOConfig

# 自博弈的两个角色：generator 产出对局数据，baseline 冻结用于评估
def self_play_mapping(agent_id, episode, worker=None, **kwargs):
    return "generator" if agent_id == "player_0" else "baseline"

config = (
    PPOConfig()
    .environment("ConnectFourLike")
    .framework("torch")
    .multi_agent(
        policies={"generator", "baseline"},
        policy_mapping_fn=self_play_mapping,
        policies_to_train=["generator"],     # 基准冻结：角色由训练名单区分
    )
)

def train_loop(algo, arena_games=200, win_threshold=0.55, sync_every=5):
    for it in range(50):
        for _ in range(20):                      # 每轮产出 20 局自博弈数据
            gen_one_episode(algo, anneal_temperature=it > 10)
        algo.train()                             # 用缓冲区数据更新 generator
        if it % sync_every == 0:
            win_rate = arena(algo, games=arena_games, noise=False)
            # 胜率过线才同步：防止一次坏更新污染后续全部自博弈数据
            if win_rate > win_threshold:
                algo.get_policy("baseline").set_weights(
                    algo.get_policy("generator").get_weights())
    return algo

解读：这段骨架演示 RLlib 组织自博弈的三个关键动作。（1）用两份策略区分"产数据"与"评估"角色，policies_to_train 只含生成方，基准方参数被冻结。（2）温度退火由训练轮次驱动，前 10 轮高温保多样性，之后转为确定性策略。（3）竞技场结果决定参数同步时机，这是版本闸门的实现。接口随版本演进，策略权重存取与算法 API 以对应版本的官方文档为准。

常见坑

  • 价值符号体系不统一：搜索回传用"当前行动者视角"，训练标签用"绝对视角"，网络学出相反胜负观，表现为训练损失不降且对弈胜率长期在 50% 附近。修复：全程统一为"行动者视角"，写一个函数集中处理符号翻转。
  • 搜索成本失控：每步模拟 800 次加网络前向，单局数据产出耗时远超训练耗时，采样成为瓶颈。修复：训练期降低模拟次数（如 200），评估期再用高次数；网络推理批量并行。
  • 温度未退火：对局后期仍按访问分布采样，强着法被稀释放大，棋力停滞。修复：按步数或训练轮次双条件退火，末期取确定性动作。
  • 缓冲区不设窗口：全部历史数据永久保留，网络被旧策略分布持续牵制。修复：按最近 10–50 轮的数据量设定容量上限，或按胜率闸门通过时清空。
  • 评估时残留探索噪声：竞技场未关闭根噪声与采样，胜率波动大，误判频发。修复：评估路径使用独立的确定性搜索入口。

练习与思考

  1. 把片段 1 的模拟次数从 200 提高到 800，预测三件事：单步延迟、对局棋力、单位样本成本。给出验证方案。★
    提示
    延迟约线性增长；棋力先升后缓，边际收益递减；单位样本成本随模拟次数线性上升。用固定网络、固定局面做离线对照最干净。
  2. 推导：当某父节点只有一个子动作未访问、其余均被访问过，证明 PUCT 中该子动作的 U 项随父节点总访问量单调递增。★★
    提示
    U = c·P·√N_parent/(1+0)，分母恒为 1，直接对 N_parent 求导即可证明导数恒正，这条性质保证未探索分支不会被永久忽略。
  3. 设计竞技场协议：给出局数、先后手分配方式、胜率阈值、平局处理规则，并估算把"真实胜率 53% 的网络误判为过线"的概率量级。★★★
    提示
    双方各执先手一半局数以抵消先手优势；平局计半胜；用二项分布的标准差 σ=√(0.25/G) 估算，G=200 时 σ≈3.5%，阈值 55% 距离约 0.5σ 至 1σ，误判并不罕见，故应增大局数或提高阈值。
  4. 解释为什么自博弈中"数据生成网络"与"被训练网络"必须解耦成两份策略参数，若直接用同一份参数在线更新会发生什么。★★
    提示
    训练中的分布偏移会立即反映到数据生成上，回路失去稳定性；解耦后旧策略为数据提供了短时程的平稳参照，缓冲区与闸门才有意义。
  5. 把片段 3 的同步周期从 5 轮改为 1 轮与 20 轮，分别预测数据新鲜度、训练稳定性与吞吐的变化，设计对照实验。★★★
    提示
    同步越频繁数据越新但闸门失去了过滤作用，坏更新立刻进入回路；过疏则数据陈旧。对照实验固定总采样量，比较不同周期下的胜率曲线。

小结

  • AlphaZero 风格算法的三段结构：网络引导搜索、访问计数蒸馏、自博弈数据回路。
  • PUCT 用 Q 均值负责利用、先验加权项负责探索，根节点狄利克雷噪声保证自博弈的落子多样性。
  • 策略目标来自访问计数的温度缩放，价值目标来自局终结果并统一到行动者视角，两者共同构成监督损失。
  • 回路稳定依赖两道闸门：缓冲区窗口控制数据新鲜度，竞技场阈值过滤坏更新。
  • RLlib 没有内置该算法，落地路径是自定义策略封装搜索、多智能体映射组织双方、样本后处理构造标签。
  • 下一章回到通用训练议题：自定义探索策略，把本章的噪声与温度思想推广到连续动作与无搜索任务。
