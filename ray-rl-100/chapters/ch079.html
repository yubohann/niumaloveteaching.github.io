第 079 章：超参搜索实战：网络层数与宽度

网络结构决定函数的表达上限，也决定每步计算的代价。本章讲清参数量估算、宽度与深度的分工、容量不足与容量过剩的曲线特征，以及“先宽度后深度”的分层搜索安排与预算依赖的判读警惕。

  • 主题：超参搜索实战 / 网络结构参数族
  • 关键机制：参数量估算、容量与样本复杂度、结构化候选、后段爬升判读
  • 预计学时：55 分钟
  • 前置章节：第 078 章

学习目标

  • 会估算多层感知机的参数量，并把它与显存、每步计算代价的联动关系说清楚。
  • 理解宽度与深度的分工：宽度决定单层分辨率，深度决定组合层次，两者对优化的难度不同。
  • 会用“后段是否仍爬升”判读容量是否饱和，区分容量不足与容量过剩的曲线特征。
  • 会设计结构化候选与分层搜索（先宽度、后深度），避免结构维度的全因子爆炸。
  • 会在结构变更后同步检查学习率与批量的适配，并记录吞吐与显存代价。

背景与动机

网络结构是唯一“先于训练发生”的参数族：它不改变训练怎么走，改变的是函数能表示什么。容量不足时，策略与价值函数都难以拟合目标的复杂度，训练曲线早早进入低平台；容量过剩时，模型需要更多样本来填充参数，强化学习的非平稳目标与自生成数据让“大网络”经常得不偿失。

结构维度的搜索还多一层现实约束：宽度、深度、激活函数三个维度做全因子网格会让试验数成倍膨胀，而三者的效应并不等价。宽度效应通常最大且评估代价低，深度次之，激活函数的效应最小（下一章处理）。本章按“先宽度、后深度”的顺序把结构搜索拆成两段，用结构化候选代替笛卡尔积。

核心原理

1. 参数量估算与代价联动

全连接结构的参数量按逐层权重与偏置求和：第 l 层从 nl−1 维到 nl 维贡献 nl−1·nl + nl 个参数。同宽堆叠时，参数量近似与宽度平方、深度线性成正比：宽度翻倍使参数量约增四倍，每加深一层约增一份“宽度平方”的量级。

Params = Σl ( nl−1 · nl + nl ) 观测 8 维、动作 4 维、隐藏层 [256, 256] 时约 6.9 万参数；[512, 512] 约 27 万，是前者的近四倍

参数量与两类代价线性联动：显存（参数、梯度与优化器状态各占一份，Adam 家族大约三倍参数量）与每步计算量（正向与反向的乘加次数近似与参数量同阶）。计算量上升会推高学习段在迭代时间里的占比，第 066 章的时间分解判读在结构搜索期间要同步进行，避免把“学习变慢”误判为“采样出问题”。

2. 宽度与深度的分工

宽度决定单层能刻画的模式数量，深度决定模式的组合层次。对多数向量观测的强化学习任务，两到三层的结构足以表达策略与价值函数所需的映射，宽度的边际收益更稳定；继续加深的收益在没有归一化与残差结构的条件下迅速衰减，且深层网络的优化难度上升，训练更容易卡在坏的初值区域。结构的默认起点因此是两层宽度适中的配置，把搜索预算先给宽度，再评估是否值得加深。

3. 结构化候选

结构搜索不采用笛卡尔积，改用结构化候选：每个候选是一套完整的隐藏层配置（含层数与宽度），候选之间沿一条设计轴变化，例如“小/中/大宽度的双层”“宽而浅”“窄而深”。候选表附带参数量估算列，试验预算与代价在提交前就能被核对；名义参数把候选名称进搜索空间，训练函数负责把名称映射回落层配置。这样的空间只有一维，配合复验就足以回答“这个任务的容量需求在哪一档”。

4. 容量判读：后段爬升

容量是否饱和，最直接的判据是曲线后段是否仍在爬升：取最后 30% 预算做最小二乘拟合，斜率为正且显著说明容量尚未饱和，继续训练或增大容量仍可能获益；斜率接近零且有平台特征说明训练在该容量下的表达极限附近。两类异常的形态区分：容量不足的曲线“早期上升快、平台低且平”；容量过剩的曲线“早期上升慢、曲线抖动大、平台高度未必更高”。

判读必须叠加预算条件：短预算下小容量因“学得快”领先，长预算下大容量可能反超，这与第 077 章的预算依赖同源。结构比较的结论若在两个预算快照间排名翻转，标注为预算依赖，用延长预算的复验决定采纳哪一档。

5. 结构变更后的参数适配

结构改变会移动训练动态的最优点：参数量变化改变损失曲率与梯度尺度，上一章校准的学习率在新结构上可能不再合适；批量与结构的交互相对温和，但数据复用轮数在大容量上更容易过拟合小批量数据。规范做法是结构搜索阶段锁定学习率的档位集合（例如三个候选），把结构视为“学习率的函数”，最优结构连同其适配学习率一起进入复验；只报结构不报配套学习率的结论是不完整的。

实现思路与设计

结构搜索按“算预算、列候选、分两段、配动态、记代价”五步执行。与上一章的差异在于，第 078 章控制训练过程，本章控制模型能力上限。

  1. 算预算：按参数量公式估算各候选的显存与计算量，剔除超出预算的候选（估算脚本先于搜索执行）。
  2. 列候选：构建结构化候选表，覆盖“宽而浅、两层适中、窄而深”三类形态。
  3. 分两段：第一段固定深度搜宽度并在少量学习率档位上交叉；第二段固定最优宽度搜深度。
  4. 配动态：结构候选与其适配学习率成对进入复验，避免“结构最优但步长失配”。
  5. 记代价：全程记录学习段耗时占比与显存占用，作为结构选择的附加判据。
候选隐藏层配置参数量（观测 8 / 动作 4）形态
s64x2[64, 64]约 0.5 万小容量基线

s256x2[256, 256]约 6.9 万两层宽

s128x3[128, 128, 128]约 3.5 万窄而深
设计决策：为什么宽度先于深度？

三点依据：其一，宽度与容量的关系更直接，同样参数预算下宽两层通常比窄三层更易优化；其二，宽度搜索的每个候选训练负担可控，评估循环短，而加深带来的优化不稳定会放大评估噪声，让比较失去分辨率；其三，深度对强化学习的收益有任务依赖，把它放在第二阶段，可以用第一阶段的信息决定“是否值得加深”，避免无条件展开深度网格。

关键代码与解读

片段 1：参数量估算与结构化候选

def mlp_params(hiddens, obs_dim=8, act_dim=4):
    """估算 MLP 参数量：逐层权重与偏置求和。"""
    dims = [obs_dim] + list(hiddens) + [act_dim]
    total = 0
    for a, b in zip(dims, dims[1:]):
        total += a * b + b        # 权重矩阵 + 偏置向量
    return total

# 结构化候选：每项是一条设计轴上的完整结构，不是笛卡尔积因子
CANDIDATES = {
    "s64x2":    [64, 64],          # 小容量基线
    "s128x2":   [128, 128],        # 两层适中
    "s256x2":   [256, 256],        # 两层宽
    "s512x1":   [512],             # 宽而浅
    "s128x3":   [128, 128, 128],   # 窄而深
}

for name, h in CANDIDATES.items():
    print(f"{name:8s} 参数量约 {mlp_params(h):,}")

# 搜索空间只有一维名义参数：训练函数把名称映射回落层配置
from ray import tune
space = {"arch": tune.choice(list(CANDIDATES))}

解读：估算与候选表把“结构搜索”变成可预算的一维问题。（1）参数量函数显式包含输入与输出层，遗漏它们会让估算偏低，尤其在小网络上误差显著。（2）候选表覆盖三类形态，不做宽度值的机械枚举，每个候选回答一个结构问题：小容量是否够用、加宽到哪里饱和、加深是否优于加宽。（3）进搜索空间的是候选名称，映射逻辑放在训练函数里，结构定义只有一处维护；复验与归档引用名称即可还原完整配置。

片段 2：训练函数中的结构映射与代价记录

def train_fn(config):
    hiddens = CANDIDATES[config["arch"]]
    algo = build_algo(
        config,
        # RLlib 的模型配置字段：隐藏层列表与激活函数名（以版本文档为准）
        model_hiddens=hiddens,
        learner_lr=config["lr"],
    )
    for it in range(config["max_iters"]):
        stats = step_and_eval(algo)
        tune.report(
            episode_return_mean=stats["ret"],
            epoch=it,
            # 代价随结构变化的两个观测位：学习耗时占比与显存峰值
            learn_time_frac=stats["learn_time_frac"],
            gpu_mem_gb=stats["gpu_mem_gb"],
            n_params=mlp_params(hiddens),
        )
    # 归档时把结构名称与参数量一起写入口径卡
    return {"arch": config["arch"], "params": mlp_params(hiddens)}

解读：训练函数承担两个职责。（1）把名义候选翻译为真实的模型配置，保证“空间里的一维”对应“训练里的一整套结构”；复验阶段只需换名称即可复现结构。（2）把参数量与两类代价指标随结果上报：学习耗时占比用于确认结构变小时学习段占比下降的幅度，显存峰值用于核对预算是按估算值预留的；这两个字段进入结果表后，结构选择的代价可以在分析阶段与回报并列。（3）结构名与参数量写入返回的元数据，归档报告的口径卡可以直接引用，避免事后口算。

片段 3：后段爬升与容量判读

import numpy as np
import pandas as pd

def capacity_read(df, metric="episode_return_mean", frac=0.3):
    """容量判读：后段斜率（是否仍爬升）与尾段水平（是否领先）。"""
    rows = []
    for tid, g in df.sort_values("epoch").groupby("trial_id"):
        y = g[metric].to_numpy(dtype=float)
        n = max(3, int(len(y) * frac))
        slope = float(np.polyfit(np.arange(n), y[-n:], 1)[0])
        rows.append({"trial": tid, "arch": g["arch"].iloc[0],
                     "tail_slope": slope,
                     "tail_mean": float(y[-10:].mean())})
    out = pd.DataFrame(rows)
    summary = out.groupby("arch").agg(
        slope=("tail_slope", "mean"), mean=("tail_mean", "mean"),
        n=("trial", "size"))
    # 斜率正且尾段高：容量与预算匹配；斜率正但尾段低：容量或预算不足
    print(summary.round(2))
    return out, summary

detail, summary = capacity_read(arch_df)

解读：判读表把结构比较从“比尾部高度”升级为“比高度加趋势”。（1）后段斜率用最后 30% 预算拟合，正值显著说明训练尚未饱和；把斜率与尾段水平并列，四象限的处置各不相同（高斜率低水平指向“增加预算或容量”，零斜率低水平指向“结构确实不足”）。（2）按结构名称聚合均值并附样本数，样本稀疏的候选结论降级为线索；这与第 071 章的纪律一致。（3）若两个快照（如 2/3 与全程预算）的排名发生翻转，按第 077 章的预算依赖流程处理：标注、延长预算复验，不做淘汰。模型结构的配置字段名随版本演进，以对应版本的官方文档为准。

常见坑

  • 结构维度做全因子网格：宽度 × 深度 × 激活三轴展开，试验数成倍膨胀，预算被结构耗尽。修复：结构化候选加分层搜索，激活函数冻结到下一章单独处理。
  • 只比最终值不看趋势：仍在爬升的中容量被“暂时领先”的小容量淘汰，长预算下反超。修复：后段斜率与尾段水平双口径判读，预算依赖的排名进入复验。
  • 参数量估算遗漏输入输出层：小网络上的估算误差可达可观比例，显存与预算预留失准。修复：估算函数显式包含全部层，并在首轮试验中核对实测显存。
  • 结构变更后沿用旧学习率：曲率与梯度尺度变化让旧档位失配，结构比较的结论实际测的是“结构加失配”。修复：结构候选与少量学习率档位交叉，最优结构带着适配学习率进入复验。
  • 忽略深网络的优化难度：窄而深候选在无归一化条件下训练不稳定，被误判为“深度无效”。修复：把稳定性纳入判读（曲线方差），必要时先修稳定手段再评深度。

练习与思考

  1. 算一算：观测 12 维、动作 3 维、隐藏层 [128, 128] 与 [256, 128] 的参数量各是多少？后者相对前者增加的比例是多少？★
    提示
    [128,128]：12×128+128 + 128×128+128 + 128×3+3 = 1664+16512+387=18563；[256,128]：12×256+256 + 256×128+128 + 128×3+3 = 3328+32896+387=36611，增加约 97%，接近一倍。
  2. 预测题：把两层宽度从 128 提到 512（参数量约四倍），在短预算与长预算下，后段斜率、尾段水平与学习耗时占比各会如何变化？★★
    提示
    短预算：尾段水平未必更高（学得慢），后段斜率大（未饱和），学习耗时占比上升；长预算：尾段可能反超；若预算继续延长仍爬升，才说明容量是有效约束。
  3. 设计题：为向量观测的控制任务设计一次两段结构搜索：第一段候选表、第二段深度评估的候选、每段试验数与判据，并说明激活函数与优化器为何冻结。★★★
    提示
    第一段五个结构候选 × 3 个学习率档位 = 15 个试验；第二段在最优宽度的基础上加一层或减一层共 6 个试验；激活与优化器在本章冻结以隔离结构效应，给下一章独立预算。
  4. 推导题：对同宽 L 层网络，证明参数量随宽度约为 O(w2)、随深度为 O(L)，并解释“宽度翻倍约四倍代价”的推导条件。★★★
    提示
    每层参数量为 wl−1·wl + wl，同宽时主项为 w2，L 层相加为 L·w2；条件包括输入输出维固定的主项占优与同宽假设，输入维接近宽度时需按完整公式修正。
  5. 实践题：对一次已完成的结构搜索用片段 3 生成判读表，找出“斜率正且尾段低”的候选，给出“加预算”与“加容量”两种动作各自的验证方式。★★
    提示
    加预算：延长最高容量候选的预算，观察斜率是否转零且尾段上移；加容量：同预算下引入更大候选，观察是否早期更慢但后段反超。两种动作分别回答“预算不够”与“容量不够”。

小结

  • 参数量按逐层求和估算；同宽时随宽度平方、随深度线性增长，与显存和每步计算同阶联动。
  • 宽度决定单层分辨率、深度决定组合层次；向量观测任务从两层适中宽度起步，深度放第二阶段。
  • 结构化候选把结构搜索压成一维名义参数；候选表附参数量列，提交前完成预算核对。
  • 容量判读用双口径：后段斜率判断是否饱和，尾段水平判断相对位置；排名翻转按预算依赖处理。
  • 结构变更必须配套学习率适配与代价记录，结论以“结构加适配参数”成对交付。
