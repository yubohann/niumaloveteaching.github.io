第三篇 · RLlib 算法实现

第 041 章：RLlib实现MARL算法

从单策略到多策略：策略映射（Policy Mapping）如何把智能体分派到策略、参数共享（Parameter Sharing）与独立策略（Independent Policies）各自适用于什么任务、非平稳性（Non-stationarity）为什么会破坏单智能体算法的收敛假设。

  • 主题：RLlib 训练（多智能体算法）
  • 关键机制：策略映射、参数共享、集中式训练分布式执行（CTDE）
  • 预计学时：55 分钟
  • 前置章节：第 040 章

学习目标

  • 理解多智能体任务相对单智能体的三处本质差异：联合动作空间、非平稳转移、信用分配（Credit Assignment）。
  • 掌握策略映射函数（Policy Mapping Function）的语义与一致性约束，知道它为什么必须可复现。
  • 掌握参数共享（Parameter Sharing）与独立策略（Independent Policies）的取舍，能按角色对称性规划共享范围。
  • 会配置 RLlib 多智能体接口，并逐策略读取训练指标诊断更新是否发生。
  • 能设计共享与独立的对照实验，用量化指标评估样本效率差异。

背景与动机

多智能体强化学习（Multi-Agent Reinforcement Learning, MARL）要处理的环境里，转移概率依赖全部智能体的联合动作（Joint Action），任何一个智能体的策略更新都会改变其余智能体面对的转移分布。把单智能体算法复制若干份、各自训练，会持续违反"环境平稳"这一收敛前提，训练曲线表现为互相追逐的震荡。

RLlib 的解法是把多智能体组织成"策略集合 + 映射函数 + 训练名单"三件套：采样阶段按映射把每个智能体的经验分派给对应策略，训练阶段按名单更新参数。本章讲透这套组织方式的原理与配置，它是后续自博弈、种群训练等复杂范式的基础设施。

核心原理

本节回答一个问题：多智能体训练的组织结构，究竟在解决什么数学与系统层面的困难。

1. 从 MDP 到多智能体：三处本质变化

多智能体环境在数学上对应随机博弈（Stochastic Game）：状态 s、联合动作 a = (a1, …, aN)、转移 P(s′ | s, a)、各智能体回报 Ri。相对单智能体马尔可夫决策过程（Markov Decision Process, MDP），有三处变化直接冲击算法设计：

  • 非平稳性：智能体 i 的转移分布是 P(s′ | s, ai, π−i)，依赖其余智能体的当前策略 π−i。他人每更新一次，i 面对的"环境"就变一次，基于固定环境假设的价值估计会被持续推翻。
  • 信用分配：团队回报由全体动作共同产生，把回报归因到单个智能体的某个动作是病态问题。共享回报训练的是"团队行为"，个体奖励设计则决定行为如何分工。
  • 样本归属：每个时刻产生 N 份经验（观测、动作、回报各一组），采样批次按策略拆分，单策略分到的数据量取决于映射结果。

非平稳性的强度可以用更新频率差来感受：对手策略每 K 轮更新一次、学习者每轮都更新时，学习者面对的是一个缓慢漂移的环境，价值目标的有效稳定窗口约等于对手的更新周期。把对手更新频率降下来（冻结或低频陪练）能显著恢复平稳性，这条工程手段与自博弈章节的对手池设计直接衔接。

2. 策略映射：多智能体训练的分派中枢

RLlib 用策略映射函数把智能体 ID 映射到策略 ID：policy_mapping_fn(agent_id, episode, worker, **kwargs)。它在两类位置被调用：采样 worker 上决定用哪份参数计算动作，训练阶段决定经验写入哪份批次。两个调用点相距很远，映射函数必须满足确定性约束：同一 episode 内同一 agent_id 必须得到同一结果，且不能依赖本地随机数或墙上时间，否则经验会被写入与产生它的参数不对应的批次，优势函数与梯度全部错位。

允许依赖 episode 参数是刻意设计：它支持"每局重新分边"的对练范式，只要随机性来自 episode 层级的种子，所有 worker 就能得到一致结论。

3. 参数共享与独立策略：样本效率与表征能力的权衡

组织方式机制优势代价
参数共享全部 agent 映射到同一 policy_id，经验汇入同一批次样本效率约提升 N 倍；共享参数带来隐式课程要求空间一致；难以表达角色差异；容量竞争
独立策略每个 agent 一份参数，各自更新表征能力最强，角色差异充分表达每份策略的数据量缩小约 N 倍，学习更慢
按组共享按角色或队伍分组，组内共享、组间独立折中方案，实践中用得最多需要预先定义角色划分

共享策略的近似结论可以量化：设采样批次共 B 条经验，共享策略一次梯度更新用到全部 B 条；独立策略下平均每份策略只见到 B/N 条。在空间一致的同质角色任务里，共享带来的样本效率收益通常远大于表征损失。

用片段 1 的奖励结构再算一笔：每步成本 0.02、成功奖励 2.0、回合上限 50 步。平均 40 步成功时单局每智能体回报为 2.0 − 0.02 × 40 = 1.2；始终不成功则以 −0.02 × 50 = −1.0 收尾。团队奖励在智能体之间共享，行为差异都落进同一个数字里，信用分配的质量直接决定协作是否出现：奖励设计过粗时，搭便车的行为获得同样的回报，训练出的分工因此不稳定。

4. 集中式训练与分布式执行

集中式训练分布式执行（Centralized Training with Decentralized Execution, CTDE）是缓解非平稳性与信用分配的主流范式：训练阶段 Critic 允许读取全局状态或全体观测，价值估计因此更稳定；执行阶段 Actor 只依赖本地观测，部署时无需通信。RLlib 中没有强制的 CTDE 开关，一种常见做法是通过共享 Critic 网络（vf_share_layers 之外的参数共享）或自定义模型在 forward 里拼接全局信号来实现。

策略梯度的更新目标仍是 PPO 截断形式，只是在多智能体批次上按策略归属分别估计优势：

5. 指标口径：多智能体报表与单智能体不同

多智能体任务里 episode_reward_mean 的默认口径是"每个 episode 内全部智能体回报之和"，量纲约为单智能体的 N 倍。跨任务比较奖励水平时必须换算成每智能体平均值。训练健康度则依赖逐策略指标：共享策略在 info.learner 下只有一个条目，独立策略有 N 个条目，某条目的 policy_loss 恒为零通常意味着该策略未列入训练名单。

6. 数值算例：策略数、批次分裂与收敛代价

把"批次按策略拆分"算成一张表。总批次 8192 时：单份共享策略一次更新使用全部 8192 条；N = 2 的独立策略各得约 4096 条，梯度噪声按平方根上升约 1.41 倍；N = 4 时各得 2048 条，噪声约 2.00 倍；N = 8 时各得 1024 条，噪声约 2.83 倍。若要在独立策略下维持与共享相同的单策略有效批次，总采样量需要按 N 放大。这就是"样本效率约 N 倍"说法的定量来源，也是异质角色拆分策略后训练变慢的原因。

7. 边界与失效模式

变长智能体集合是环境层的边界：智能体中途退出后观测字典的键减少，共享策略的批次里样本数随之波动；若某个策略在某轮批次中一条数据都没有，多数实现会以空批次跳过更新，该策略停在原地。极端情形需要监控每策略的样本计数下限，必要时用固定长度的填充或调整终止逻辑。

映射函数的边界在恢复与评估：从检查点恢复时映射函数逻辑必须一并复现，否则智能体被分派到不同的策略，行为与训练时不一致；评估流程必须复用训练映射，报表才可比。自博弈类任务会把映射函数的作用升级为"对手生成器"，此时映射的输出空间随训练阶段演化，版本管理要覆盖映射逻辑本身。

CTDE 的执行边界出现在部署：集中式 Critic 只在训练期存在，部署时只有本地观测可用的 Actor；训练期的全局信号若被 Actor 误用（例如自定义模型把全局特征拼进策略输入），部署环境里该信息缺失会让行为退化。设计时把 Actor 的输入集与部署时可得的信息逐一核对，是 CTDE 落地的固定动作。

冻结对手还有停滞边界：对手长期不更新时，学习者可能收敛到只克制这套固定策略的解法，一旦对手恢复更新，性能迅速回退。缓解手段是安排陪练对手的轮换或按周期解冻，把对手池的多样性当成超参来管理。

实现思路与设计

把一个多智能体任务接入 RLlib PPO，按以下五步推进。

  1. 空间对齐：先检查各智能体的观测、动作空间能否统一。能统一的先统一（补齐维度、对齐取值范围），统一是参数共享的前提；无法统一的角色走独立策略。
  2. 共享范围决策：对称角色（同型机器人、同型单位）全局共享；异质角色按组共享；对抗双方完全独立以保留博弈策略的差异。
  3. 编写映射函数：只依赖 agent_id 与 episode 元数据，保持确定性；评估配置必须复用同一映射。
  4. 声明策略集合与训练名单：policies 列出全部策略及空间，policies_to_train 列出参与更新的策略（冻结对手时留空）。
  5. 规划采样与验证：采样批次按策略拆分，独立策略数量多时相应放大 train_batch_size；开训后逐策略检查损失与 KL。

关键配置参数

参数典型值作用取值依据

批次放大有一条直接算式：希望每份策略每轮至少见到 4096 条数据时，N 份独立策略要求全局批次至少 4096 × N。N = 4 时为 16384，N = 8 时为 32768；若全局批次保持 8192 不动，每份策略只有 1024 至 2048 条，梯度噪声相对共享配置放大 2 至 2.83 倍。共享与独立的对照实验要把这条算式写进方案，否则两组的单策略数据量并不对等，结论无法归因。

与上一章的差异：IMPALA 处理的是单策略下的一条采样流，本章把采样流按策略分流，批次、并行度、指标三处口径都随策略数量发生变化。

关键代码与解读

片段 1：最小多智能体环境（MultiAgentEnv）

import gymnasium as gym
from gymnasium.spaces import Box, Discrete
from ray.rllib.env.multi_agent_env import MultiAgentEnv

class CoopGrid(MultiAgentEnv):
    """两智能体协作网格：观测与动作空间完全一致，是参数共享的前提。"""
    def __init__(self, config=None):
        super().__init__()
        # 观测 4 维：自身坐标与相对目标坐标，统一缩放到 [-1, 1]
        self.observation_space = Box(-1.0, 1.0, (4,), dtype="float32")
        self.action_space = Discrete(5)          # 上/下/左/右/停留
        self.max_steps = 50
        self.agents = ["agent_0", "agent_1"]     # 本局参与的智能体集合
        self._agent_ids = set(self.agents)       # 基类据此校验动作字典的键

    def _obs(self, agent):
        x, y = self.pos[agent]
        return [x / 4.0, y / 4.0, (3 - x) / 4.0, (3 - y) / 4.0]

    def reset(self, *, seed=None, options=None):
        self.pos = {"agent_0": [0, 0], "agent_1": [1, 0]}
        self.t = 0
        return {a: self._obs(a) for a in self.agents}, {}

    def step(self, action_dict):
        # 动作字典只包含仍存活的 agent，RLlib 按映射函数选择策略计算动作
        moves = {0: (0, 1), 1: (0, -1), 2: (1, 0), 3: (-1, 0), 4: (0, 0)}
        for a, act in action_dict.items():
            dx, dy = moves[act]
            self.pos[a] = [self.pos[a][0] + dx, self.pos[a][1] + dy]
        self.t += 1
        done = all(self.pos[a] == [3, 3] for a in self.agents)
        reward = 2.0 if done else -0.02            # 团队共享回报
        terminated = {a: done for a in self.agents}
        # "__all__" 是全局终止约定，漏写会让采样器认为 episode 永不结束
        terminated["__all__"] = done
        truncated = {"__all__": self.t >= self.max_steps}
        obs = {a: self._obs(a) for a in self.agents if not done}
        rew = {a: reward for a in self.agents}
        return obs, rew, terminated, truncated, {}

解读：多智能体环境接口的核心约定有三处。（1）观测与回报都以字典返回，键是 agent_id，采样器据此把每条经验路由到映射函数指定的策略。（2）终止字典除每个 agent 的布尔值外必须包含 "__all__" 键，它是环境声明"本局结束"的唯一官方通道；遗漏会让 rollout 无限进行，worker 被永久占用。（3）已终止的 agent 从观测字典中移除，这要求策略在训练时能处理"变长智能体集合"，RLlib 通过各策略独立批次绕开该问题。

片段 2：两种映射函数与 PPO 多智能体配置

from ray.rllib.algorithms.ppo import PPOConfig

def shared_mapping(agent_id, episode, worker=None, **kwargs):
    # 全部 agent 映射到同一 policy_id：经验汇入同一批次，参数共享
    return "shared_policy"

def independent_mapping(agent_id, episode, worker=None, **kwargs):
    # 每个 agent 独占一份参数；对抗训练中可用于固定对手与学习者
    return "learner" if agent_id == "agent_0" else "opponent"

config = (
    PPOConfig()
    .environment(CoopGrid)
    .framework("torch")
    .env_runners(num_env_runners=8, num_envs_per_env_runner=4)
    .training(
        train_batch_size=8192,      # 按策略拆分，共享策略独占全部数据
        lr=3e-4,
        gamma=0.99,
        lambda_=0.95,
        entropy_coeff=0.01,         # 协同早期保留探索，避免策略过早趋同
    )
    .multi_agent(
        policies={"shared_policy"},          # 只声明一个策略即参数共享
        policy_mapping_fn=shared_mapping,
        policies_to_train=["shared_policy"],
    )
)
# 注：multi_agent 的参数形态随版本演进，新版以 AlgorithmConfig.multi_agent
# 与 RLModuleSpec 声明策略空间，以对应 Ray 版本的官方文档为准。

解读：映射函数与配置之间存在强耦合，逐点说明设计意图。（1）映射只引用配置中声明过的 policy_id，拼写错误会在训练启动时报"未知策略"，属于最早暴露的配置错误。（2）independent_mapping 与 policies_to_train 配合即可实现"学习者对固定对手"：对手策略在名单之外，只采样不更新，这正是 042 章自博弈的起点。（3）两台以上机器共享策略时，本片段配置可原样扩展，因为映射逻辑与智能体数量无关。

result = algo.train()

# 队级口径：多智能体报表里的 episode_reward_mean 是各 agent 回报之和，
# 与单智能体任务的奖励量纲不同，比较前先除以智能体数量
team_return = result["env_runners"]["episode_reward_mean"]
per_agent = team_return / 2.0

learner = result["info"]["learner"]
for pid, stats in sorted(learner.items()):
    s = stats["learner_stats"]
    # 策略未列入训练名单时 policy_loss 恒为 0，这是最隐蔽的配置错误
    print(pid, "policy_loss=", round(s["policy_loss"], 4),
          "kl=", round(s["mean_kl_loss"], 4))
# 指标键路径随版本演进（旧版在 info.learner 下），以官方文档为准

解读：这段代码演示多智能体训练的两个检查动作。（1）奖励口径换算：把队级回报除以智能体数量后再与单智能体基线比较，避免"奖励看起来涨了 2 倍"的误判。（2）逐策略损失巡检：每个策略都应出现非零且波动的 policy_loss，恒零条目直接指向 policies_to_train 或映射函数的问题。

常见坑

  • 空间不一致却配置共享策略：两个智能体观测维度不同（如 4 维与 6 维）仍映射到同一策略，采样阶段报形状不匹配，或更隐蔽地静默截断。修复：先做空间对齐（补齐、投影到统一维度），无法对齐就按角色拆分策略。
  • 映射函数带随机性：函数体内调用 random.choice 或读取本地时间，不同 worker 对同一 agent 给出不同策略，经验与参数错配。修复：随机分组放进 episode 元数据（由种子驱动，全局一致），映射只做查表。
  • 漏配训练名单：新增对手策略后未加入 policies_to_train，该策略永远停在初始化参数，采样数据全部作废。症状：该策略的 policy_loss 恒为 0。
  • 用错奖励口径：把队级回报当作单智能体回报调参，学习率、熵系数按错误的奖励量级设定，导致策略更新幅度失当。修复：统一换算到每智能体平均值再比较。
  • 终止条件缺 "__all__"：episode 永不结束，采样吞吐随运行时间衰减，最终触发环境步数上限报错。修复：每个 step 返回的 terminated 字典显式写入 "__all__" 键。

练习与思考

  1. 把片段 1 的环境扩展到 4 个智能体（两两协作、目标相同）。保持参数共享配置不变，说明为什么这段代码只需改 agents 列表与初始坐标。★
    提示
    映射函数与智能体数量无关，共享策略的批次由采样器自动汇聚。注意奖励口径随 N 放大，报表换算系数要同步改成 4。
  2. 把全局共享策略改为"每智能体独立策略"，预测三件事：样本效率、收敛所需的采样步数、报表中的策略条目数量。设计一个对照实验验证预测。★★
    提示
    独立策略下每份策略约分到 1/N 的经验，达到同等性能需要更多采样；条目数量变为 N。对照实验固定种子与总采样步数，只改映射函数。
  3. 推导：设总采样批次 B 条经验、N 个空间一致的对称智能体，证明参数共享下单次更新使用的有效样本量约为独立策略的 N 倍（忽略策略间数据分布差异）。★★
    提示
    从采样器按映射分派经验出发：共享时全部 B 条进入同一批次；独立时按映射均匀分派，每份策略期望得到 B/N 条。
  4. 设计一个三类角色的任务（2 个侦察、2 个采集、1 个指挥），给出策略划分方案（几份策略、映射逻辑、训练名单），并说明共享范围选择的依据。★★★
    提示
    侦察与采集若观测动作空间一致可合并为一份共享策略；指挥角色观测含全局信息，单独一份。映射按 agent_id 前缀查表，全部列入训练名单。
  5. 解释为什么策略映射函数必须可复现，并给出一个反例场景：mapping 使用 worker 本地随机数时，训练会出现什么具体错误现象。★★
    提示
    经验写入的批次与产生动作的参数不对应时，重要性比值失去意义，优势估计错位，表现为策略损失剧烈震荡且评估性能与训练性能大幅背离。

小结

  • 多智能体相对单智能体的三处变化：联合动作引发的非平稳转移、信用分配、经验按策略分流。
  • 策略映射函数是多智能体训练的分派中枢，确定性是硬约束，episode 级元数据是其唯一的随机性出口。
  • 参数共享把 N 条轨迹汇成一份批次，样本效率约提升 N 倍，前提是空间一致；独立策略保留角色差异，代价是每份数据量缩小。
  • CTDE 让 Critic 在训练期读取全局信息、Actor 在执行期只依赖局部观测，是缓解非平稳性的主流范式。
  • 多智能体报表的奖励是队级求和，逐策略损失巡检是发现配置错误的第一手段。
