第 090 章：训练任务的容错与恢复策略

一句话：本章讲训练任务从故障中恢复的完整机制：检查点内容与间隔的成本模型、恢复语义、重启风暴的隔离方法、以及降级运行的设计。

  • 主题：训练工程 / 容错（Fault Tolerance）与恢复（Recovery）
  • 关键机制：检查点清单、间隔成本模型、恢复语义、断路器、降级运行
  • 预计学时：60 分钟
  • 前置章节：第 089 章

学习目标

  • 能列举训练的故障形态：进程崩溃、节点失联、抢占、数据损坏与确定性崩溃，并说明各自的检测方式。
  • 掌握完整检查点的内容清单，理解遗漏任一部分对恢复语义的破坏。
  • 会用成本模型确定检查点间隔，权衡写入开销与故障重算量。
  • 理解恢复的"丢弃晚于检查点样本"语义，以及它与第 088 章一致性契约的关系。
  • 会设计重启风暴的隔离机制（断路器）与降级运行方案。

背景与动机

前九章的系统设计都把"组件持续可用"作为隐含前提，真实环境里这个前提随时被打破：长时训练跨越数小时到数周，硬件故障、配额抢占与软件异常在这类时间尺度上几乎必然出现。容错设计的目标在于把故障的代价限制在"重算窗口"内：从最近一个有效检查点恢复，损失的只是检查点之后的进展。

强化学习训练的容错比监督学习多一层复杂性：训练状态不仅是模型权重，还包含优化器状态、探索参数、学习率调度、随机数流与回放缓冲；恢复时若只还原权重，探索率与调度从头计数会让训练轨迹偏移，表现为"恢复后回报突然下滑再缓慢爬升"的典型异常。本章把这些状态作为一个整体处理，先定义"完整的检查点"，再讨论间隔经济学与故障后的行为设计。

核心原理

容错的核心是两个数字：检查点写一次的成本，与故障后需要重算的窗口长度。本节从故障分类开始，依次给出检查点清单、间隔模型、恢复语义与风暴防护。

1. 故障形态与检测

故障形态检测方式恢复手段
进程崩溃心跳超时、进程退出码重启进程并从检查点恢复
节点失联心跳丢失、资源视图变化资源替换，重新申请放置组
抢占中断信号通知、调度器事件收到信号后立即存检查点再退出
数据损坏校验和比对、反序列化异常回退到上一个通过校验的检查点
确定性崩溃同一步必然复现的异常隔离样本或参数后重试，见断路器设计

检测延迟直接影响恢复质量：心跳周期决定多久发现失联，检查点写入方式决定抢占时能保存多少。为抢占信号注册处理器（Handler）是低成本高收益的措施，收到信号后完成一次检查点写入再退出，能把抢占的代价从"整个检查点间隔"压缩到"一次写入时长"。

2. 完整检查点的内容清单

一个足以支撑精确恢复的检查点包含六类内容，缺一不可的判据是"恢复后第一步的更新是否与未中断时一致"：

  • 网络参数与优化器状态：后者常被遗漏，动量缺失使恢复初期的更新方向突变。
  • 全局步数与计数器：包括策略版本号、已采样步数、已更新次数，它们决定调度位置。
  • 调度状态：学习率、探索率、KL 系数、回放比例等随进度变化的量，恢复时按步数还原。
  • 随机数状态：策略采样与环境重置的随机流各存各的，否则恢复后行为分布改变。
  • 回放缓冲摘要：全量缓冲存储代价高时，至少记录其规模、写入位置与抽样状态，并明确恢复后缓冲从空开始重填充的策略。
  • 版本标识：代码、依赖与配置的标识，用于校验恢复环境与中断环境一致（第 098 章展开）。

3. 检查点间隔的成本模型

检查点的两类成本随间隔向相反方向变化：写得太频繁，吞吐被写入时间侵蚀；写得太稀疏，故障时重算窗口大。用一次写入的代价 c（折算为推进等量训练的时间）、故障到达率 λ、重算速率与写入速率之比 R 建模，总代价为：

Cost(Δ) = c / Δ + λ · Δ / 2 · R，最优间隔 Δ* = √( 2c / (λR) ) Δ 为检查点间隔（按训练步或时长），λ 为故障到达率，c 为单次写入折算时间

代入数值感受量级：单次写入折算 30 秒、平均 24 小时出现一次故障、重算与写入同速，则最优间隔约 38 分钟。模型的用途是数量级决策：写入成本上升一个数量级，间隔约扩大三倍；故障率上升一个数量级，间隔缩小约三倍。实际取值再按外部约束修正：抢占窗口、维护时段与人工检查需求都可能要求更密的检查点。

4. 恢复语义：丢弃与对齐

恢复点之后采集的样本如何处置，属于语义决策，必须在设计文档中明确。两种选择：丢弃，把晚于检查点的样本全部舍弃，从检查点状态重新采集，恢复后的训练轨迹与未中断时严格一致（前提是随机流也精确还原）；保留，把新样本并入缓冲继续使用，节省采集时间，但样本产生于"未恢复的中间状态"，与恢复后的策略存在版本差，需要按第 086 章的有界滞后过滤处置。同策略训练默认选择丢弃：重算窗口本来就小，语义简单优先；离策略训练可以保留并依赖缓冲的年龄机制自然淘汰。无论哪种选择，恢复日志必须记录丢弃量，便于监控系统量化故障损失。

分布训练下还有一处容易失守：参数与缓冲分布在不同进程，恢复顺序应为"先装载学习器状态，再清空或裁剪队列与缓冲，最后广播参数并重启采样"，任何其他顺序都会让采样端用旧参数产出与新检查点不匹配的样本。

5. 重启风暴与断路器

确定性崩溃是容错系统最危险的故障：同一步骤必然触发同一异常，自动重启形成"崩溃、恢复、再崩溃"的循环，每次循环消耗一次检查点读取与一段重算，且永远不会成功。断路器（Circuit Breaker）是最小防护：统计单位时间内的重启次数，超过阈值即停止自动重启，保留现场并升级人工处置。常见成因与隔离手段：某条样本触发数值异常（跳过该批并记录样本标识）、随机种子组合触发环境缺陷（更换种子后重试）、配置组合非法（启动前静态校验可拦截大部分）。断路器参数用"窗口内最大重启次数"表达，例如一小时内不超过 3 次。

6. 降级运行与资源替换

部分资源失效时，继续以缩小的规模运行通常优于整体退出：样本吞吐按损失比例下降，训练与检查点机制保持运转，等待替换资源加入后重启扩容。实现要点是把资源申请写成幂等的协调循环：检测缺口、申请替换、就绪后并入、更新并行度并同步批次结构（第 083 章的整除约束在并行度变化后需要重新满足）。降级期间的进度记录必须与新并行度一起写入实验日志，否则吞吐曲线会出现无法解释的拐点。任务编排器一侧的对应配置是最大失败次数（Max Failures），它决定自动重启的预算；预算耗尽前的告警应早于耗尽时刻发出，留出人工介入窗口。

实现思路与设计

容错设计的落地按六步执行，产出物是检查点规范与恢复演练记录。

  1. 盘点状态：按清单逐项确认训练的持久化状态，标记暂不持久化的量及其恢复策略。
  2. 确定间隔：用成本模型算出理论间隔，再按抢占与运维约束修正。
  3. 实现原子写入：复用第 088 章的清单提交协议，写入路径与装载路径分离。
  4. 定义恢复语义：明确丢弃或保留策略、恢复顺序与日志字段。
  5. 配置断路器：设定重启窗口与阈值，接通告警通道。
  6. 演练验证：在训练中主动注入故障（终止进程、模拟抢占信号），验证恢复行为与日志完整性。

关键代码与解读

以下片段基于 Ray 2.x 时期的通用写法，接口随版本演进，以对应版本的官方文档为准。

片段 1：检查点间隔求解器

import math

def checkpoint_interval(save_seconds, failures_per_hour, rework_ratio=1.0,
                        min_minutes=10, max_minutes=120):
    """按成本模型求最优检查点间隔：平衡写入开销与故障重算。
    返回建议间隔（分钟），并按运维上下界裁剪。"""
    if failures_per_hour <= 0:
        return max_minutes                       # 故障率可忽略时按上界取稀疏检查点
    lam = failures_per_hour / 3600.0             # 换算为每秒故障率
    # 最优间隔：写入成本越大越稀疏，故障越频繁越密集
    best = math.sqrt(2.0 * save_seconds / (lam * rework_ratio))
    minutes = min(max(best / 60.0, min_minutes), max_minutes)
    print(f"写入 {save_seconds:.0f}s、故障 {failures_per_hour}/h："
          f"建议间隔 {minutes:.0f} 分钟")
    return minutes

# 单次写入折算 30 秒、24 小时一次故障：理论间隔约 38 分钟
checkpoint_interval(save_seconds=30, failures_per_hour=1.0 / 24.0)
# 故障率提升十倍（抢占频繁）时，间隔应缩小到约三分之一
checkpoint_interval(save_seconds=30, failures_per_hour=10.0 / 24.0)

解读：求解器把间隔选择从经验值变成可复核的计算。（1）零故障率分支返回上界，避免除零，同时保留"即使无故障也要周期性落盘"的运维习惯。（2）上下界裁剪吸收模型之外的信息：下界来自抢占窗口与人工检查需求，上界来自可接受的最大重算量。（3）两行示例的对照说明了敏感度：故障率上升一个数量级，间隔按平方根关系缩小约三倍，缩放幅度低于故障增幅，这正是成本模型中重算项与写入项相加的结果。

片段 2：完整的保存与恢复流程

def save_training_state(trainer, path):
    """完整检查点：权重、优化器、计数器、调度与随机流一并落盘。
    缺失任何一项都会让恢复后的第一步更新偏离未中断轨迹。"""
    state = {
        "weights": trainer.get_weights(),            # 网络参数
        "optimizer": trainer.get_optimizer_state(),  # 动量等优化器状态
        "counters": trainer.get_counters(),          # 步数、版本号、更新次数
        "schedulers": trainer.get_schedule_state(),  # 学习率、探索率、KL 系数
        "rng": trainer.get_rng_state(),              # 策略与环境的随机流
    }
    write_checkpoint_atomic(path, state)             # 复用第 088 章的清单提交协议

def restore_training_state(trainer, path, queue, drop_stale=True):
    """恢复顺序：先装载学习器，再处置队列，最后广播参数。
    其他顺序会让采样端以旧参数产出与新检查点不匹配的样本。"""
    state = read_checkpoint(path)                    # 清单缺失或校验失败即抛出
    trainer.set_weights(state["weights"])
    trainer.set_optimizer_state(state["optimizer"])
    trainer.set_counters(state["counters"])          # 调度位置随计数器还原
    trainer.set_rng_state(state["rng"])
    if drop_stale:
        # 同策略默认丢弃：重算窗口小，语义简单优先
        dropped = queue.purge()
        print(f"恢复完成，丢弃检查点之后的 {dropped} 批样本")

解读：这段流程把恢复语义写成代码路径。（1）五个状态分量在同一检查点内原子提交，读取时校验失败即整体拒绝，杜绝"一半新一半旧"的混合状态。（2）恢复顺序由注释固定：学习器就绪、队列处置、参数广播，三步之间没有可交换的余地。（3）丢弃分支返回丢弃量并打印，监控系统按此字段累计故障损失；离策略配置改传 drop_stale=False，队列由年龄机制自然淘汰。

片段 3：重启断路器

import time

class RestartBreaker:
    """重启断路器：窗口内重启次数超限即停止自动恢复并升级告警。
    针对确定性崩溃：自动重启只会重复失败的轨迹。"""
    def __init__(self, window_seconds=1800, max_restarts=3):
        self.window = window_seconds
        self.max_restarts = max_restarts
        self.events = []

    def allow_restart(self):
        now = time.monotonic()
        # 仅保留窗口内的事件：超出窗口的历史重启不再计入
        self.events = [t for t in self.events if now - t < self.window]
        if len(self.events) >= self.max_restarts:
            print(f"窗口内已重启 {len(self.events)} 次，停止自动恢复，请人工检查")
            return False
        self.events.append(now)
        return True

# 与调度器的最大失败次数配套设置：断路器负责"何时停"，
# max_failures 负责"总共允许几次"，两个参数应保持同一数量级

解读：断路器实现了一个简单的速率限制。（1）用单调时钟滑动窗口，重启事件过期即失效，允许长时间的偶发故障逐次恢复。（2）触发后的动作是停止自动恢复并告警；确定性崩溃的根因处理（跳过样本、更换种子、修正配置）必须由外层逻辑完成，断路器只负责终止循环。（3）与任务编排器的 max_failures 分工：前者按时间窗口节流，后者给出总预算，两者数量级一致可以避免"预算未耗尽但已陷入循环"的盲区。

常见坑

  • 只保存网络权重：优化器与调度状态缺失，恢复后学习率与探索率跳变，回报曲线异常。修复：按六类清单完整保存，并用"恢复后第一步与未中断轨迹一致"做验收标准。
  • 恢复时不处置回放与队列：新旧样本混用且无版本过滤，等效于无界滞后训练。修复：按恢复语义显式清空或过滤，丢弃量记入日志。
  • 检查点直接写正式路径：写入中途失败留下损坏文件，装载方读到部分数据。修复：临时路径加清单提交，校验失败视为无检查点。
  • 无断路器自动重启：确定性崩溃循环消耗大量重算与读取带宽。修复：断路器加告警，根因隔离由外层处理。
  • 抢占信号未接处理器：抢占发生后从更早的检查点恢复，重算量放大数倍。修复：注册信号处理器，收到后立即写一次检查点再退出。

练习与思考

  1. 计算题：单次检查点写入折算 60 秒，平均 12 小时一次故障，重算比 1。求最优间隔。若写入成本降到 15 秒，间隔如何变化？★
    提示
    λ = 1/43200，Δ* = √(2×60×43200) ≈ 2277 秒 ≈ 38 分钟；写入降四倍后间隔减半，约 19 分钟。
  2. 预测题：恢复时保留晚于检查点的样本且不做过滤。预测回报曲线的形态与监控指标的变化。★
    提示
    恢复后回报先降后升、抖动加大；滞后分布与裁剪比例异常升高，说明混入了版本差过大的样本。
  3. 设计题：为"可能被抢占、平均 6 小时一次、单次写入 45 秒"的任务设计容错方案：检查点间隔、抢占处理、断路器阈值与演练计划。★★
    提示
    按模型约 23 分钟；抢占处理器必开；断路器窗口 30 分钟、阈值 3 次；演练注入终止信号验证恢复。
  4. 分析题：讨论"丢弃晚于检查点样本"与"保留并过滤"两种语义在同策略与离策略场景下的取舍，并说明为什么同策略默认丢弃可以简化正确性证明。★★★
    提示
    丢弃使恢复轨迹与未中断轨迹在随机流精确还原时逐位一致；保留引入版本混合，正确性依赖过滤与修正机制，证明链更长。

小结

  • 容错把故障代价限制在重算窗口内；检测延迟决定恢复质量，抢占信号处理器是低成本高收益措施。
  • 完整检查点含权重、优化器、计数器、调度状态、随机流与版本标识；验收标准是恢复后第一步更新与未中断一致。
  • 间隔按成本模型选择：写入越贵越稀疏，故障越频繁越密集，敏感度遵循平方根关系。
  • 恢复语义分丢弃与保留两类；同策略默认丢弃并记录丢弃量。
  • 断路器防重启风暴，降级运行维持进度。下一章把训练好的策略推向服务：导出、批处理与状态管理。
