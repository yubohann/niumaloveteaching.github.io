第四篇 · Ray Tune 超参搜索

第 069 章：调优报告生成与实验导出

把一次搜索变成可交付的归档：结果表、最优配置、检查点与一份口径完备的报告。本章讲清导出对象的分类与格式选择、报告的结构化模板、归档清单与校验策略，以及保证日后可复跑的元数据清单。

  • 主题：Ray Tune 调优 / 结果导出与报告
  • 关键机制：格式选择、口径卡、归档清单、校验和比对、复跑信息
  • 预计学时：50 分钟
  • 前置章节：第 068 章

学习目标

  • 掌握三类导出对象（清单表、迭代记录、工件）各自的格式选择依据：类型保真、嵌套结构与读取效率。
  • 会从结果接口提取最优试验、最优配置与检查点路径，并处理路径随版本变化的兼容问题。
  • 会按结构化模板生成实验报告：口径卡、结果摘要、证据链、复跑信息四部分。
  • 会建立归档清单与校验和比对流程，保证归档在传输与长期保存中可验证。
  • 会设计复跑信息清单，使他人能在另一环境中重建同等口径的搜索。

背景与动机

搜索结果若停留在运行目录里，价值会随环境变动而流失：节点释放、存储回收、依赖升级都可能让数据不可读。导出与报告解决的正是“结果的可搬运性”：把一次搜索压缩成自描述的归档，任何人拿到它都能回答三个问题：当时搜了什么、结果是什么、怎么复跑。

上一章把数据加工成视图，本章把视图沉淀为文件。两者之间隔着“口径”这道关：图上的每个数字都有前提（聚合方式、过滤条件、版本），报告必须把前提与数字装订在一起。缺少口径的数字在跨实验对比时无法仲裁，只能重跑，这正是导出环节要预防的浪费。

核心原理

1. 三类导出对象与格式选择

导出对象分为三类：清单表（每试验一行：配置、状态、最后检查点）、迭代记录（每试验每迭代一行：指标序列）、工件（检查点文件与训练日志）。格式选择遵循三条规则：数值密集的表格用列式格式（Parquet），读取快、类型保真、压缩率高；需要人眼直读的副本用 CSV；配置字典这类嵌套结构用 JSON，保留层级语义。同一种数据可以存多份格式，代价是冗余，收益是不同的读取场景各自最优；冗余带来的不一致风险用“主格式唯一”约束来控制：以 Parquet 为主格式，其余为派生副本。

导出 = 主格式（Parquet，类型保真） + 派生副本（CSV 人读、JSON 嵌套） + 工件（检查点、日志） 主格式唯一保证一致性；派生副本随时可由主格式重建，重建脚本应与归档一同保存

2. 报告的结构化模板

报告按四段式组织：口径卡描述搜索问题（空间与范围、试验数、调度器与阈值、并发与资源声明、预算定义）；结果摘要给出最优与 top-K，附分位带表或图；证据链把每条结论挂到具体记录（试验标识、预算点、统计口径）；复跑信息列出重建实验所需的全部输入。四段式的作用是让报告可审计：读者能从结论逐级下钻到原始记录，任何一步缺失都能立刻定位。

3. 配置序列化的两个陷阱

配置字典里可能包含非 JSON 类型：搜索空间的分布对象、路径、枚举。把“空间定义”与“采样后的取值”分开存储可以同时避开两个陷阱：空间定义用规范化文本表达（分布名 + 参数的稳定写法），采样后的配置是纯数值与字符串，直接序列化。另一个陷阱是键冲突：嵌套配置展开成平铺列时，不同层级可能产生同名列；展开规则必须写明（例如用斜杠连接层级），并把规则随数据一起保存，否则重建时无法还原层级。

4. 归档清单与校验

归档是一个目录，不是一堆散落文件。清单文件（Manifest）记录每个文件的相对路径、大小与内容校验和，随归档一起保存。清单的价值有三个：传输完整性校验、长期保存后的损坏检测、增量同步时只搬运变化部分。校验和取前 16 位十六进制足以在实践中避免碰撞，又保持清单可读。校验流程应在导出完成后立即执行一次“写入、重读、比对”，把损坏挡在归档进入长期保存之前。

5. 复跑信息清单

让另一个人或另一台机器重建同等口径的搜索，需要五类信息：环境特征（框架版本、环境标识与版本）、搜索定义（空间、试验数、预算）、执行参数（调度器、并发、资源声明）、随机性设置（种子及其作用范围）、入口（复跑命令与代码标识）。五类信息缺一不可：缺少种子时结果只能近似，缺少版本时接口行为可能已经变化，缺少入口时重建成本急剧上升。

实现思路与设计

导出流程按“提取、落盘、成文、校验”四步执行。与上一章的差异在于，第 068 章在内存里聚合，本章把一切固化到文件并接受校验。

  1. 提取：从实验接口读取结果表与试验清单，只在实验停止或快照后进行，避免与运行写入争抢。
  2. 落盘：写主格式与派生副本，检查点与日志复制到工件目录；全部写入独立的归档区，不写回实验目录。
  3. 成文：按四段式模板生成报告，摘要数字从主格式数据重新计算，不从终端日志摘抄。
  4. 校验：生成清单，重读抽查，输出校验结论；校验失败的归档不进入长期保存。
数据主格式派生副本关键约束
迭代记录表ParquetCSV列类型保真，压缩后体积可控
试验清单与配置JSONCSV（展开列）展开规则随数据保存
检查点原样目录无只保留 top-K 试验的检查点
报告Markdown无数字全部来自主格式重算
设计决策：为什么只保留 top-K 的检查点？

一次 60 试验的搜索会生成同量级的检查点目录，每个目录包含模型与优化器状态，合计体积常超出记录表两个数量级。归档的目标是“可复跑与可续训”，续训只需要少数优胜者的检查点。按末端指标保留 top-K（K 取 3 至 5）既控制体积，又保住最有价值的工件；被舍弃的检查点属于过程数据，其信息已由记录表承载。

关键代码与解读

片段 1：结果与最优配置导出

import json
from pathlib import Path
from ray.tune import ExperimentAnalysis

analysis = ExperimentAnalysis("/shared/tune_results/ppo_sweep_v2")
df = analysis.results_df

out = Path("/shared/archive/ppo_sweep_v2")
out.mkdir(parents=True, exist_ok=True)

# 主格式：Parquet 保留数值类型与列压缩，供后续统计与绘图
df.to_parquet(out / "results.parquet", index=False)
# 派生副本：CSV 便于快速检视，可用脚本从 Parquet 随时重建
df.to_csv(out / "results.csv", index=False)

# 末端记录与 top-K：排序后再取每试验最后一条，避免挑到中途峰值
final = (df.sort_values("epoch").groupby("trial_id").last()
           .sort_values("episode_return_mean", ascending=False))
final.head(10).reset_index().to_csv(out / "topk.csv", index=False)

best = analysis.get_best_trial(metric="episode_return_mean",
                               mode="max", scope="last")
payload = {
    "best_trial_id": best.trial_id,
    "best_config": analysis.get_best_config(
        metric="episode_return_mean", mode="max", scope="last"),
    "checkpoint": analysis.get_last_checkpoint(best).local_path,
}
(out / "best.json").write_text(
    json.dumps(payload, indent=2, ensure_ascii=False), encoding="utf-8")

解读：导出函数的每个选择都能对应到格式规则。（1）Parquet 与 CSV 双写不是冗余：前者服务程序读取与统计，后者服务人工检视；主格式唯一意味着 CSV 只作副本。（2）top-K 基于末端记录计算，与第 068 章的聚合口径一致，避免把中途的波动峰值选为“最优”。（3）scope="last" 明确最优判定取试验的最后一条记录，历史最大值是另一种口径；不同 scope 会给出不同的“最优”，口径必须显式声明。（4）检查点路径的获取接口与返回对象形态随版本演进（不同版本返回不同包装类型，字段名亦有差异），以对应版本的官方文档为准。

片段 2：四段式报告生成

def write_report(out_dir, analysis, bands, topk):
    """生成 Markdown 摘要：口径卡、结果摘要、证据、复跑信息。"""
    out = Path(out_dir)
    df = analysis.results_df
    lines = [
        "# 超参搜索报告：ppo_sweep_v2",
        "",
        "## 一、实验口径",
        f"- 试验数：{df['trial_id'].nunique()}；预算：{int(df['epoch'].max())} 迭代",
        "- 空间：lr 对数均匀 1e-5~1e-2；批量 {2048,4096,8192}",
        "- 调度器：ASHA(reduction_factor=3)；并发：6；声明：cpu=7, gpu=1",
        "",
        "## 二、结果摘要（末端口径，从主格式重算）",
        f"- 最优试验：{topk.iloc[0]['trial_id']}，"
        f"末端回报 {topk.iloc[0]['episode_return_mean']:.1f}",
    ]
    # 分位带末尾几行作为趋势证据：数字来自 Parquet，不摘抄终端输出
    # （to_markdown 依赖表格格式化库，缺失时改用 to_string 输出等价内容）
    lines.append(bands.tail(5).to_markdown(index=False))
    lines += [
        "",
        "## 三、证据链",
        "- 边界信号：top-5 的学习率分布集中在 3e-4 附近，未贴边",
        "- 曲线文件：figures/bands.png（由 results.parquet 重绘）",
        "",
        "## 四、复跑信息",
        "- 版本：ray 2.x / rllib 2.x（以实际记录为准）",
        "- 种子：搜索层 1234；评估层固定集合 [0,1,2]",
        "- 入口：python sweep.py --space ppo_v2 --samples 40",
    ]
    (out / "report.md").write_text("\n".join(lines), encoding="utf-8")
    return out / "report.md"

解读：报告函数的重点是“数字来源可追溯”。（1）口径卡把空间、调度、资源、预算四个维度写全，任何读者都能判断该报告与另一份报告是否可比。（2）摘要数字从 bands 与 topk 重算，它们本身由主格式数据生成；转手摘抄终端输出是口径事故的高发点。（3）证据链把文字结论挂到具体试验与图文件，读者可以做下钻核对。（4）复跑信息包含种子与入口两类，分别对应“结果近似”与“重建成本”两个维度。报告生成脚本随归档保存，日后格式升级时重跑同一脚本可再生成。

片段 3：归档清单与校验

import hashlib
import json
from pathlib import Path

def write_manifest(out_dir):
    """清单：记录相对路径、大小与截断校验和，供校验与增量同步。"""
    root = Path(out_dir)
    entries = []
    for p in sorted(root.rglob("*")):
        if p.is_file() and p.name != "manifest.json":
            digest = hashlib.sha256(p.read_bytes()).hexdigest()[:16]
            entries.append({"file": p.relative_to(root).as_posix(),
                            "size": p.stat().st_size, "sha256_16": digest})
    manifest = {"generator": "sweep-export v1", "files": entries}
    (root / "manifest.json").write_text(
        json.dumps(manifest, indent=2, ensure_ascii=False), encoding="utf-8")
    return manifest

def verify_archive(out_dir, sample=3):
    """校验：重读清单并抽查若干文件校验和，确认归档可运输。"""
    root = Path(out_dir)
    manifest = json.loads((root / "manifest.json").read_text(encoding="utf-8"))
    files = manifest["files"][:sample]   # 抽查前 sample 个，全量校验可另跑
    for e in files:
        digest = hashlib.sha256((root / e["file"]).read_bytes()).hexdigest()[:16]
        if digest != e["sha256_16"]:
            raise RuntimeError(f"归档损坏：{e['file']}")
    print(f"校验通过：抽查 {len(files)}/{len(manifest['files'])} 个文件")
    return True

解读：清单机制的三处设计细节。（1）路径使用 POSIX 风格相对路径，跨系统搬运后仍可解析；校验和取 16 位十六进制，碰撞概率在实践中可忽略，清单保持人读友好。（2）清单自身不纳入校验序列，避免自我引用。（3）校验默认抽查前若干文件，导出后立即执行；长期保存场景可以全量校验，代价与文件数成正比。（4）增量同步的实现依据是清单比对：路径与校验和都相同的文件跳过，只搬运新增与变化的文件，这与第 064 章的远端同步互补，一个管运行期，一个管归档期。

常见坑

  • 只导出迭代记录表：缺少试验清单与配置结构，无法回答“这个试验用的是哪套配置”，归档沦为半成品。修复：试验清单、配置 JSON 与记录表三类对象齐全后再打包。
  • 归档写回实验目录内部：归档文件被下一轮同步重复上传，实验目录体积自我膨胀。修复：归档区与实验目录分开，工件采用复制落盘，避免移动破坏实验目录。
  • 版本与口径未记录：报告数字在跨版本对比时无法仲裁。修复：版本特征与口径卡作为报告固定段落，缺失视为未完成。
  • 直接序列化搜索空间对象：分布对象不是 JSON 原生类型，序列化报错或写出不可读的结构。修复：空间定义与采样取值分开存储，前者用规范化文本，后者为纯数据类型。
  • CSV 类型漂移：布尔与空值在 CSV 往返后变成字符串与 NaN，后续过滤条件静默失效。修复：以 Parquet 为主格式做分析，CSV 仅作检视副本。

练习与思考

  1. 为三类数据（记录表、配置字典、检查点）各选一个导出格式，并说明选择依据与一个失败场景。★
    提示
    记录表用 Parquet（类型与压缩），失败场景是缺失读取依赖；配置用 JSON（嵌套），失败场景是非原生类型；检查点原样目录，失败场景是绝对路径在迁移后失效。
  2. 预测题：把记录表从 CSV 换成 Parquet 后，归档体积与“只读 3 列做统计”的读取时间各自如何变化？★★
    提示
    体积通常下降数倍（列压缩与去重编码）；列裁剪读取让部分列统计显著加快。反向代价是与纯文本工具链的兼容性下降，需保留 CSV 副本。
  3. 设计题：为你的任务写一份报告模板：五段结构与每段的证据来源，要求任何一位读者都能从任意结论下钻到原始记录。★★★
    提示
    口径卡、摘要、证据链、复跑信息之外可加“下一步建议”段；证据来源要写到行级口径（试验标识、预算点、聚合方式），下钻路径保持单向：报告到主格式到检查点。
  4. 实现题：写一个配置展开函数：把嵌套配置展平为列，层级用斜杠连接；给出键冲突的处理策略与展开规则随数据保存的方式。★★
    提示
    递归遍历字典，遇到字典继续下钻，遇到标量写列；冲突策略可选“抛错”或“加后缀并记录”，推荐前者，因为静默覆盖会让列语义不可信。展开规则以说明文件形式写入归档。
  5. 实践题：列出一份“复跑信息清单”，要求另一环境的研究者据此重建同等口径的搜索，逐条说明缺失该信息时会产生什么后果。★★
    提示
    参考五类信息：环境特征、搜索定义、执行参数、随机性设置、入口。逐条模拟缺失后果，例如缺种子导致结果分布不可复现，缺版本导致接口语义漂移。

小结

  • 导出对象分三类；主格式 Parquet 保证类型保真，CSV 与 JSON 作派生副本，主格式唯一保证一致性。
  • 报告按口径卡、结果摘要、证据链、复跑信息四段组织，每条结论可下钻到原始记录。
  • 空间定义与采样取值分开序列化，展开规则随数据保存，避免类型与层级两类陷阱。
  • 归档清单提供完整性校验与增量同步依据；校验在导出后立即执行。
  • 复跑信息包含环境特征、搜索定义、执行参数、随机性设置与入口五类，缺一不可。
