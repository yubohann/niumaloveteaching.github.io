第三篇 · RLlib 算法实现

第 048 章：RLlib策略模型选择：MLP、CNN与RNN

网络结构跟随观测形态：多层感知机（Multilayer Perceptron, MLP）处理低维向量、卷积网络（Convolutional Neural Network, CNN）利用空间局部性、循环网络（Recurrent Neural Network, RNN）承载时间记忆，以及主干与输出头共享（Shared Trunk）与否对训练的影响。

  • 主题：RLlib 训练（策略网络结构）
  • 关键机制：感受野、参数预算、多模态拼接
  • 预计学时：50 分钟
  • 前置章节：第 047 章

学习目标

  • 掌握观测形态到网络结构的映射规则：向量用 MLP、图像用 CNN、序列用 RNN，以及混合形态的拼接方案。
  • 理解卷积网络的感受野（Receptive Field）与下采样结构，能手工核算输出尺寸与参数数量。
  • 掌握主干共享与分离两种结构对策略价值双头的梯度影响，能按任务选择。
  • 会配置 RLlib 的内置模型字典（fcnet、conv、lstm 三类键）并校验形状。
  • 能设计消融实验验证结构选择的必要性，例如打乱空间结构后性能变化。

背景与动机

算法决定优化目标，网络结构决定这套目标能否被高效表达。RLlib 为常见观测形态提供了默认网络，默认值在小规模任务上工作良好，一旦观测结构特殊（多通道图像、向量与图像并存、空间动作图）就会失配：结构不匹配时，网络要么浪费大量参数，要么根本学不到观测中的关键模式。

结构选择还有成本维度：全连接层参数量随输入维度线性增长，图像输入动辄上万个维度，直接展平会让参数量失控；卷积结构用局部连接与权重共享把参数量压到可训练范围。本章把三类结构与配置参数对应起来，并给出参数量与感受野的核算方法。

核心原理

本节按"结构先验、尺寸核算、双头组织、混合形态"四步展开。

1. 结构先验：三种观测形态各自的内置假设

结构内置先验适配观测失配后果
MLP维度间无序、全连接低维状态向量图像输入时参数量爆炸、丢失平移不变性
CNN局部性、平移等变、权重共享图像、网格、空间张量向量输入时无收益，白白增加计算
RNN时序递归、隐状态记忆序列、部分可观测马尔可夫任务中增加状态管理成本

选择规则可以压缩成一句话：观测里存在什么结构，网络里就内置什么先验。观测是图像且目标会平移出现时，卷积的平移等变先验直接降低样本需求；观测是无序特征向量时，任何空间先验都没有意义。

三类结构的参数走向同样要先算一遍：全连接层参数量随输入维度线性增长，卷积层参数量只与核大小、通道数有关而与输入分辨率无关，循环层参数量与序列长度无关、与隐状态宽度的平方相关。这组关系决定了核算顺序：输入维度大时先检查卷积或池化能把维度压到哪里，时序依赖强时先算循环部分的参数量级，再决定用帧堆叠还是循环网络承载历史。把这三笔账在选型前算完，网络规模的讨论就不会停留在"大一点更保险"的层次，每个参数都有对应的职责与成本。

2. 卷积的尺寸与感受野核算

卷积层的输出尺寸由卷积核、步幅与填充共同决定：

Wout = ⌊ ( Win + 2·P − K) / S ⌋ + 1 W 为空间边长，K 卷积核，S 步幅，P 填充；逐层递推即得最终空间尺寸，供后续全连接层对接

感受野是输出单元能"看到"的输入区域边长，逐层递推公式为 RFl+1 = RFl + (K−1)·∏S前缀。感受野必须覆盖任务的关键目标尺度：目标占据 10×10 像素而感受野只有 5，网络只能看到局部纹理，无法判断目标的身份与运动。参数量的核算同样直接：单个卷积层参数量为 K²·Cin·Cout 加偏置，全连接层为输入维乘输出维，两者相加即可估计模型的规模预算。

3. 双头结构：主干共享与分离

策略网络同时输出动作分布与价值估计，两个头可以共享特征提取主干（Shared Trunk），也可以各自独立。共享主干的参数量更小、特征复用效率更高，但两个损失的梯度在同一组参数上叠加，存在相互干扰的可能；分离主干则各自优化，参数量接近翻倍。实践中带图像输入的任务常用共享卷积主干加两套全连接头，低维任务多数直接用默认的 vf_share_layers=False 结构。当价值损失与策略损失的量级差异大（例如 044 章奖励归一化失配）时，共享主干的不稳定性会被放大，此时优先检查归一化，再考虑结构调整。

4. 混合形态与拼接设计

观测同时包含图像与向量（如相机帧加关节角度）时，标准做法是分支编码后拼接：图像分支用卷积压缩到低维特征，向量分支过若干全连接层，两者拼接后进入共享头。拼接的维度配比决定梯度在不同模态上的分配：某分支输出维度过大时，该模态的梯度主导训练。常用起点是让两个分支的输出维度处于同一量级，再用消融实验调整配比。

5. 数值算例：参数量与感受野的逐步核算

以 84×84 单通道帧的经典配置 conv_filters=[[32,[8,8],4],[64,[4,4],2],[64,[3,3],1]] 为例逐步核算。第一层输出边长 (84−8)÷4+1=20，参数量 8×8×1×32+32=2080；第二层 20 经核 4、步幅 2 得 9，参数量 4×4×32×64+64=32832；第三层 9 经核 3、步幅 1 得 7，参数量 3×3×64×64+64=36928。卷积输出 7×7×64=3136 维，经 256 维全连接层需要 3136×256+256=803072 个参数，四部分合计 874912 个参数。

感受野按 RFl+1 = RFl + (K−1)·∏S前缀 递推：初始 1；第一层加 (8−1)×1 得 8，累计步幅 4；第二层加 (4−1)×4 得 20，累计步幅 8；第三层加 (3−1)×8 得 36。输出单元覆盖 36 像素，约为帧宽的 42.9%，对 20×20 量级的目标有富余。若把配置缩成 [[16,[3,3],2],[32,[3,3],2]]，感受野只有 1+2+4=7 像素，目标尺度 20 时顶层特征看不到完整目标，学到的只能是局部纹理，这就是感受野失效模式的定量依据。

与直接展平的对照：84×84 展平为 7056 维，接两层 256 全连接的参数量为 7056×256+256+256×256+256=1872384，约为卷积配置 874912 的 2.14 倍，同时丢失平移等变先验。两组数字并排后，"图像输入用卷积"从经验判断变为参数预算与结构先验两条可核算的理由。

6. 多模态拼接的梯度配比与边界

多模态观测里，各分支输出维度之比近似决定融合层输入上各模态的梯度份额。图像分支卷积输出 3136 维、状态分支 64 维时不加压缩直接拼接，图像占融合输入约 98.0%，状态分支的梯度在总梯度里几乎可以忽略；把图像分支先投影到 128 维再与 64 维状态拼接，图像份额降到约 66.7%，两个模态都能获得有效训练。配比争议不要靠感觉，先算份额再决定投影层的位置与宽度。

三条边界同样要记牢：其一，卷积配置对输入分辨率敏感，84×84 上的配置套到 42×42 输入时输出边长从 7 降到 2，全连接层的输入维度必须重算，形状核对以目标分辨率为准；其二，循环网络的序列训练要求批次能被序列长度整除，不匹配时错误常出现在构建期，先把整除关系写进配置校验；其三，帧堆叠与循环记忆提供不同形式的历史，前者是固定窗口，后者是可调长度的记忆，任务依赖更早信息时优先加长窗口或增大隐状态，两者的成本与效果要用消融实验分别确认。

7. 双头共享的参数量对照

以 24 维观测、两层 256 隐层、5 个离散动作为例：分离结构的参数量约为 2×(24×256+256×256)+256×5+256=144896；共享主干约为 24×256+256×256+256×5+256=73216。共享节省约 49.5%，节省量恰好等于少建的一份主干（71680 个参数）。共享的成本是两个损失在同一组主干参数上叠加，是否采纳的判定与 051 章的稳定性面板联动：共享后解释方差与裁剪占比同时恶化，就回到分离结构，问题不解决再谈结构调整。

8. 消融验证的判定口径

结构先验是否真被利用，用破坏结构的消融实验判定：把图像观测的像素做固定置换（保留数值分布、破坏空间局部性）后重训，若性能在统计噪声之外显著下降，说明卷积的空间先验确实被依赖。判定口径：设正常训练与置换训练的评估回报差为 d、种子间标准差为 σ，各跑 3 粒种子时差值的标准误约为 σ·√(2/3)≈0.82σ；d 小于 0.82σ 时结论不确定，需要增加重复或改用更彻底的置换（如逐行重排）。若置换几乎不影响性能，说明任务依赖的是颜色统计一类的全局特征，卷积先验没有发挥作用，应检查观测预处理与任务定义。

实现思路与设计

网络结构的确定按五步执行。

  1. 检查观测结构：打印观测空间的形状与取值范围，判断属于向量、图像还是序列，是否存在多模态。
  2. 选择主干：按映射规则选 MLP、CNN 或 RNN；图像输入必须先做归一化与必要的降采样。
  3. 核算规模：用两条公式估算参数量与感受野，把参数量控制在任务样本量支撑的范围内。
  4. 决定双头组织：默认共享主干；损失量级差异大或结构异质时改用分离头。
  5. 消融验证：打乱观测中认定的结构（如空间置换）后重跑，性能显著下降则说明结构先验确实被利用。

结构定稿前的三项核算清单

核算清单一：尺寸链。从输入分辨率逐层推到最终空间尺寸，与 post_fcnet_hiddens 的输入对接；42×42 输入走同一套三层卷积配置时输出为 1×1×64，全连接入口从 3136 维缩到 64 维，参数量随之大幅减小，但高层特征的容量可能不足，分辨率变化必须重算这条链。清单二：感受野与任务目标尺度之比，覆盖率低于 1 时必须扩大核或加深下采样。清单三：多模态分支的输出维度比，超出一比三的分支先做投影压缩。三项都建议在模型入口用一次空张量前向实测核对，让形状与规模问题在构建期暴露。

清单核对完成后留一组对照：结构与观测不匹配时，训练曲线通常长期停在随机水平附近，且解释方差持续为负；排查顺序是先核对归一化与通道顺序，再怀疑结构容量。顺序颠倒会在一堆无关的参数上反复试验，而真正的故障点始终没有被检查。

关键代码与解读

片段 1：MLP 配置与参数量核算

def mlp_params(obs_dim, hiddens, n_actions, share=False):
    """核算策略价值双头的参数量（不计偏置的简化估计）。"""
    dims = [obs_dim] + list(hiddens)
    trunk = sum(dims[i] * dims[i + 1] for i in range(len(dims) - 1))
    if share:
        # 共享主干：两个头都接在最后一层隐层之上
        head = hiddens[-1] * n_actions + hiddens[-1] * 1
        return trunk + head
    # 分离结构：策略头与价值头各自拥有一份主干
    per_head = sum(dims[i] * dims[i + 1] for i in range(len(dims) - 1))
    return per_head * 2 + hiddens[-1] * n_actions + hiddens[-1] * 1

config_model = {
    "fcnet_hiddens": [256, 256],       # 观测几十维：两层 256 足够起步
    "fcnet_activation": "tanh",        # tanh 输出有界，与优势函数的尺度更协调
    "vf_share_layers": False,          # 默认分离：先隔离两个损失再谈共享
}
print("参数量估计：", mlp_params(24, [256, 256], 5), "个（共享主干更省，但有干扰风险）")

解读：这段代码把"网络多大"变成可核算的数字。（1）简化公式忽略偏置与激活层，量级判断足够；若内存吃紧，真实参数量再加 5% 左右。（2）任务观测 24 维时两层 256 的参数量在十万量级，与通常 105 至 106 步的样本预算匹配。（3）vf_share_layers 默认取假：先建立基线，再通过消融实验决定是否共享，避免一开始就引入梯度干扰这一变量。

片段 2：CNN 配置与尺寸核算

def conv_out(size, k, s, p=0):
    """逐层递推卷积输出边长，供拼接全连接层时核对。"""
    return (size + 2 * p - k) // s + 1

def receptive_field(layers):
    """layers: [[out_ch, [k, k], stride], ...]，返回累计感受野。"""
    rf, stride_prod = 1, 1
    for _, (k, _), s in layers:
        rf += (k - 1) * stride_prod     # 当前层贡献叠加在已有跨度上
        stride_prod *= s                # 后续层的贡献按累计步幅放大
    return rf

conv_layers = [[32, [8, 8], 4], [64, [4, 4], 2], [64, [3, 3], 1]]
size = 84
for _, (k, _), s in conv_layers:
    size = conv_out(size, k, s)
print("卷积输出边长：", size, " 感受野：", receptive_field(conv_layers))

model_cfg = {
    "conv_filters": conv_layers,       # 84x84 灰度帧的经典配置
    "conv_activation": "relu",
    "post_fcnet_hiddens": [256],       # 卷积特征压到 256 维再进双头
    "vf_share_layers": True,           # 图像任务：卷积主干共享，节省显存
}
# 84 输入经三层卷积后输出 7x7x64 = 3136 维，接 256 维全连接后进双头
# 感受野核算结果为 36 像素：约覆盖帧宽的 43%，目标尺度更大时需调整核或层数

解读：逐块说明。（1）两条递推函数是卷积配置的"计算尺"，改任何一层核大小或步幅后先跑一遍再填配置，避免形状不匹配在构建时报错。（2）感受野核算显示该配置约 36 像素：覆盖帧宽的 43% 左右，对视野中央的目标足够，目标更大或更靠边时通过增大首层核、增加下采样层来扩大。（3）图像任务共享卷积主干是常见起点：卷积参数占比高，共享收益明显；若训练震荡再切换分离结构对比。

片段 3：图像与向量混合模型

class MultiModalModel(TorchModelV2, nn.Module):
    """观测为 {"image": (C,H,W), "state": (d,)}：分支编码后拼接。
    两个分支输出维度保持同一量级，避免单模态梯度主导。"""
    def __init__(self, obs_space, action_space, num_outputs, model_config, name):
        TorchModelV2.__init__(self, obs_space, action_space, num_outputs,
                              model_config, name)
        nn.Module.__init__(self)
        c, h, w = obs_space["image"].shape
        self.conv = nn.Sequential(
            nn.Conv2d(c, 32, 5, stride=2), nn.ReLU(),
            nn.Conv2d(32, 64, 3, stride=2), nn.ReLU(),
            nn.Flatten(),
        )
        with torch.no_grad():
            conv_dim = self.conv(torch.zeros(1, c, h, w)).shape[1]
        self.state_fc = nn.Sequential(nn.Linear(obs_space["state"].shape[0], 64),
                                      nn.ReLU())
        self.fuse = nn.Sequential(nn.Linear(conv_dim + 64, 128), nn.Tanh())
        self.pi = nn.Linear(128, num_outputs)
        self.vf = nn.Linear(128, 1)
        self._value = None

    def forward(self, input_dict, state, seq_lens):
        obs = input_dict["obs"]
        img = obs["image"].permute(0, 3, 1, 2).float() / 255.0   # 通道前置 + 归一化
        x = torch.cat([self.conv(img), self.state_fc(obs["state"].float())], dim=-1)
        x = self.fuse(x)
        self._value = self.vf(x).squeeze(-1)
        return self.pi(x), state

    def value_function(self):
        return self._value

解读：三个设计点。（1）用一次空张量前向自动推算卷积输出维度，改卷积结构时无需手工改全连接层，这是多模态模型最常见的形状错误来源。（2）图像张量需要从观测字典中的 HWC 布局转为 CHW 并归一化到 [0,1]，未归一化的像素值会让第一层权重的梯度尺度失控。（3）拼接后的融合层把两模态压到 128 维，量级对等；若某分支实际信息量差异大，通过调整 64 与 conv_dim 的配比再平衡。

常见坑

  • 图像未归一化：像素值 0 至 255 直接进入网络，首层梯度量级过大，训练发散或学习率被迫调到极小。修复：进入网络前除以 255，必要时再按通道减均值。
  • 通道顺序错误：观测为 HWC 而卷积按 CHW 解释，形状报错或张量被错误重排后训练出诡异行为。修复：在模型入口显式转换并写注释，片段 3 的 permute 即该转换。
  • 卷积输出与全连接层维度不匹配：改一层核大小后忘记同步更新 post_fcnet_hiddens 的输入维度。修复：用片段 2 的递推函数先核算再改配置，或让框架自动推断。
  • 感受野小于目标尺度：顶层特征看不到完整目标，学习退化为局部纹理匹配，样本需求异常高。修复：核算感受野，用更大核或更多下采样层扩大覆盖。
  • 参数量与样本预算失衡：几十万参数的网络配 104 量级样本，过拟合表现为训练评估差距大。修复：缩小隐层、加正则，或先增大采样预算。

练习与思考

  1. 用两条递推公式核算：输入 64×64，卷积序列 [[16,[5,5],2], [32,[3,3],2]]，输出空间边长与累计感受野各是多少？★
    提示
    64 经第一层到 30，第二层到 14；感受野第一层贡献 4，累计步幅 2，第二层再贡献 4，合计 9 像素，约为输入边长的 14%；若目标尺度在 20 像素量级，需要增大首层核或再加深一层下采样。
  2. 把片段 1 的 vf_share_layers 从假改为真，预测参数量、训练稳定性与收敛速度的变化，给出验证方案。★★
    提示
    参数量约减半；共享后两个损失在同一主干上叠加，稳定性取决于两者量级是否匹配。固定种子对比两条价值损失曲线。
  3. 设计消融实验验证"空间结构先验被利用"：对图像观测做像素置换（破坏空间局部性）后重训，给出预期与解释。★★
    提示
    像素置换后卷积先验不再匹配数据，性能应显著下降；若变化不大，说明任务依赖的其实是颜色统计等全局特征。
  4. 设计一个三模态观测（前后两帧图像 + 速度向量）的网络结构：给出分支划分、拼接维度与参数量估算，并说明为什么速度分支不应与图像帧一起丢进卷积。★★★
    提示
    两帧可堆叠成通道或各自卷积后拼接；速度语义与像素无关，卷积核在其上无物理意义，应走全连接分支。
  5. 解释 post_fcnet_hiddens 的作用：为什么需要卷积主干之后再接全连接层，直接对卷积输出做线性动作投影会损失什么。★★
    提示
    卷积输出的是局部特征图，全连接层负责跨位置的非线性组合；缺少这一层时动作只能由局部特征线性叠加，表达能力受限。

小结

  • 网络结构跟随观测形态：向量用 MLP、图像用 CNN、序列用 RNN，观测里有什么结构，网络就内置什么先验。
  • 卷积配置可核算：输出尺寸与感受野有递推公式，改层前先算再改，形状错误在构建前拦截。
  • 策略价值双头默认分离，图像任务因卷积参数占比高常改为共享主干，切换后用消融确认收益。
  • 多模态观测用分支编码加拼接，分支输出维度保持同量级，卷积输出维度用空张量前向自动推算。
  • 高频错误集中在归一化、通道顺序、维度同步与参数预算四处，配好核算工具即可规避。
