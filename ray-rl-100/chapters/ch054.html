第三篇 · RLlib 算法实现

第 054 章：阶段实践：自定义算法接入与训练

把分散的机制装进一个算法：接入的三档深度如何选择、配置类与算法类的职责边界、训练回环（Training Step）的骨架设计，以及冒烟测试与检查点恢复两道验收关卡。

  • 主题：RLlib 训练（自定义算法工程）
  • 关键机制：配置继承、训练回环、验收测试
  • 预计学时：60 分钟
  • 前置章节：第 053 章

学习目标

  • 掌握算法接入的三档深度：组件组合、损失扩展、完整自定义，并能按机制差异度选择。
  • 理解 RLlib 两代接口范式的结构差异：训练器加策略的旧范式与配置加模块加学习器的新范式。
  • 会设计训练回环的骨架：采样、构造损失、参数更新、指标上报四个环节的职责与顺序。
  • 能编写冒烟测试与检查点恢复测试，把数值校验、接口一致性与状态完整性纳入验收。
  • 能按检查清单逐项核对前十九章的关键机制，形成可复用的接入流程。

背景与动机

前十九章分别处理了算法组织、探索、奖励、记忆、模型、吞吐、蒸馏、稳定性、回放与目标网络等机制。真实项目里这些机制需要装进同一个算法对象，与框架的采样、训练、断点恢复、报表四条流水线无缝衔接。接入方式选得对，后续的 Tune 搜索、分布式扩展与部署导出都能复用框架能力；接入方式偏，则处处需要绕过框架，维护成本指数上升。

本章给出接入深度的判断标准、训练回环的骨架与验收测试模板，作为第三篇的综合收束，也为第四篇把该算法交给 Tune 搜索做好准备。

核心原理

本节回答三个问题：接到多深、接口长什么样、回环怎么组织。

1. 接入深度的三档选择

档位做法适用条件维护成本
组件组合只改配置：模型、探索、回放、目标网络参数机制差异可由现有开关表达最低
损失扩展在现有算法的损失中增加项（正则、蒸馏、辅助任务）采样与更新结构不变，仅目标函数变化中等
完整自定义新配置类加新算法类，实现训练回环更新结构、数据流或组件关系本质不同最高

判断标准是"机制差异度"；改动量不能作为判据：只调整参数值属于第一档；目标函数增加可加项属于第二档；需要改变采样与更新之间的时序关系（如异步、双缓冲、搜索增强）才进入第三档。能用低一档实现的方案，框架的检查点、报表与分布式能力都可直接继承，这是选择时最重要的隐性收益。

2. 两代接口范式

RLlib 的接口处于演进期，两种范式并存。旧范式以训练器为中心：训练器持有策略对象，策略内含模型与优化器，扩展点包括自定义策略的损失方法与训练器的训练方法。新范式做了职责拆分：配置类声明超参与组件规格，算法类负责编排采样与训练，强化学习模块（Reinforcement Learning Module, RLModule）只做前向，学习器（Learner）负责损失与优化。

拆分的收益是组件可独立测试与替换：模块的前向可以在没有环境的情况下用固定张量验证，学习器的损失可以在固定批次上做数值检查。接入自定义算法时，先确认当前版本默认启用哪套栈，再决定扩展点位置；两套栈可以通过配置开关切换，行为差异需要以对应版本文档为准。

3. 训练回环的骨架

无论哪种范式，算法的训练回环都包含四个环节：

  1. 采样：从并行采样器获取一批经验，或在回放缓冲中抽样；批量组织方式见 046 章的计数口径与 045 章的序列结构。
  2. 损失构造：把批次转换为损失项的组合；蒸馏、正则、优劣归一化在此接入（050、044 章）。
  3. 参数更新：按更新节奏执行梯度步与目标网络同步（052、053 章）。
  4. 指标上报：返回报表字典，供诊断面板与后续 Tune 调度器消费（051 章）。

回环的每个环节都应是可独立测试的函数：采样器可以用合成数据替代，损失可以在固定张量上核对数值，更新可以检查参数确实变化。把"能训练"拆成"每个环节可验证"，是自定义算法最省调试时间的结构决策。

4. 验收测试的两道关卡

冒烟测试在最小规模上验证接口打通：单环境、极小批次、两轮迭代，检查报表字段齐全、损失有限、参数发生更新。恢复测试验证状态完整性：训练若干轮保存检查点，恢复后继续训练，比较恢复前后的报表连续性（回报与损失不出现跳变），并确认自定义状态（如 044 章统计量、053 章目标网络）随检查点往返无损。

两道关卡之外，还应固定一个"不变量清单"在持续验证中运行：采样计数单调递增、损失为有限值、动作形状与空间一致、检查点往返后参数一致。这些不变量不依赖具体任务，可以在每个提交上自动化执行。

6. 验收测试的定量口径

冒烟测试的规模按最小可运行单元设定：单采样进程、单环境副本、批次 256、两轮迭代，合计约 512 个环境步；断言项为参数位移与损失有界。

Δθ = ‖θafter − θbefore‖，冒烟断言 Δθ > 0 参数移动证明更新链路连通；恢复测试的对应断言是恢复后参数与保存点参数之差不超过浮点容差，两条断言都在最小规模上执行，成本可忽略

恢复测试在保存前后各跑一轮：保存前损失量级记为基准，恢复后首轮损失与基准的比值落在 0.1 至 10 之间视为连续，越界说明状态缺失或加载顺序错误。自定义状态逐一断言：同步计数精确相等，归一化统计量按容差比较。

参数位移的核算示例：学习率 3×10−4、首批梯度范数约 10 时，一步更新的一阶位移估计为 3×10−3；两轮冒烟后断言参数位移大于 10−3 是稳妥门槛。位移低于该量级时的排查路径：先确认学习率为非零、梯度没有在裁剪或归一化环节被清零，再检查优化器是否正确挂载了参数。恢复连续性的示例：保存前末轮价值损失 3.9，恢复后首轮 4.1，比值 1.05 落在连续区间内；比值跌破 0.1 常伴随状态未加载（动量归零或记录错位导致损失突降），超过 10 则常见于数据管道在恢复后被重新洗牌。

恢复演练的成本核算：同步间隔 1000 个梯度步、单步 8 毫秒时，故障发生在第 1500 步而最近检查点在 1000 步处，重算量不超过 500 步、约 4 秒，相对一轮小规模验证只是零头。这正是把同步间隔当作"可接受重算量"旋钮的原因：间隔翻倍时最坏重算翻倍，而检查点的存储与写入成本减半，两个方向的代价用同一个参数交换。

7. 机制归属与状态清单

机制归属表按四个位置填写：超参与默认值归配置类，时序与编排归算法类，前向结构归模块，损失与优化归学习器。自定义状态清单从两个来源收集：算法侧计数器（同步计数、更新数据比累计）与策略侧统计量（奖励归一化均值方差）；每项标注存取位置与恢复断言方式。清单之外的状态不应跨越检查点边界；发现遗漏时优先检查训练回环内出现过的可变变量。

状态清单的完整性可以用一次故障注入验证：手动在训练循环中引入一次中断，从恢复点继续后比较自定义状态的关键值，缺失项会立刻暴露在断言中。把该演练脚本化并纳入持续验证，每次修改训练回环后自动运行，状态清单就能与代码保持同步，人工维护的遗漏被自动化兜住。

实现思路与设计

完整自定义的接入按六步执行。

  1. 定义配置类：继承算法配置，声明自定义超参与默认值，覆盖组件规格（模块、学习器）。
  2. 实现训练回环：编排采样、损失、更新、上报四段，每段独立成函数。
  3. 接入前十九章的机制：按检查清单逐项确认探索、奖励、回放、目标网络等机制的归属位置。
  4. 冒烟测试：最小规模两轮，恒等校验报表与数值。
  5. 恢复测试：检查点往返，核对连续性与自定义状态。
  6. 基线对照：与最近的内置算法在同任务同预算下对照，量化自定义带来的收益与代价。

接入完成后先冻结配置结构，用固定种子连跑两遍确认结果可复现；两遍之间的指标差异超过噪声水平时，优先排查状态存取与随机源，调整超参放在排查之后。复现性问题不解决，后续任何性能比较都缺少可靠基线。恢复测试的矩阵可扩展：除末次检查点外，对中间检查点抽样恢复一次，覆盖不同步数对应的状态；抽样比例取检查点总数的两成左右，兼顾覆盖率与运行成本。

复现性检查的数值口径：固定种子连跑两遍，终轮指标的差异应落在末段 10 轮均值的一个标准差以内；越界时优先排查状态存取与随机源（例如未固定的数据加载顺序、环境侧计数器的初值），调整超参放在排查之后。复现性问题的排查产出要留档：哪一处随机源、如何修复、修复后两遍差异收敛到什么量级，这三项记录在下一次接入时可以直接复用。

片段 1：自定义配置类

from ray.rllib.algorithms.algorithm_config import AlgorithmConfig
from ray.rllib.algorithms.algorithm import Algorithm

class CustomACConfig(AlgorithmConfig):
    """把自定义超参与默认值集中在配置类：算法类只读取，不硬编码。"""
    def __init__(self, algo_class=None):
        super().__init__(algo_class=algo_class or CustomAC)
        # 第一层：从内置配置继承训练与环境的全部成熟默认值
        self.lr = 3e-4
        self.gamma = 0.99
        self.train_batch_size = 8192
        # 第二层：本算法特有超参的默认值
        self.kl_coeff = 0.1          # 策略与目标分布的约束强度
        self.aux_coeff = 0.05        # 辅助损失权重（如 050 章的蒸馏项）

    def training(self, *, lr=None, kl_coeff=None, aux_coeff=None, **kwargs):
        # 链式接口保持与内置配置相同的使用手感：赋值后返回 self
        super().training(**kwargs)
        if lr is not None:
            self.lr = lr
        if kl_coeff is not None:
            self.kl_coeff = kl_coeff
        if aux_coeff is not None:
            self.aux_coeff = aux_coeff
        return self

    def validate(self):
        super().validate()           # 先执行父类校验，再叠加自定义约束
        assert self.train_batch_size % 256 == 0, "批次需为 256 的倍数"
        assert self.kl_coeff >= 0, "KL 约束强度不能为负"

解读：配置类的三个设计意图。（1）默认值集中在 __init__，实验脚本只写覆盖项，两年后回看仍能还原默认行为。（2）链式方法保持与内置配置一致的调用风格，切换成本低。（3）自定义 validate 在父类校验之后追加领域约束，把"批次整除""系数非负"这类规则前移到最后一道配置关口，错误在构建时就暴露。

片段 2：算法类与训练回环骨架

class CustomAC(Algorithm):
    """训练回环：采样、损失、更新、上报四段各自独立。"""
    @classmethod
    def get_default_config(cls):
        return CustomACConfig()

    def setup(self, config):
        super().setup(config)
        # 采样器与学习器由框架按配置构建；此处只保留本算法独有的状态
        self._sync_clock = 0         # 目标网络同步计数，随检查点保存

    def training_step(self):
        # 1) 采样：一批经验；序列或智能体相关的组织已由采样器完成
        batch = self.env_runner_group.sample(self.config.train_batch_size)
        # 2) 损失：任务项加辅助项，各项权重来自配置类
        losses = self.compute_losses(batch, kl_coeff=self.config.kl_coeff,
                                     aux_coeff=self.config.aux_coeff)
        # 3) 更新：梯度步与节奏组件（目标网络同步见 053 章）
        self.apply_gradients(losses["total"])
        self._sync_clock += 1
        if self._sync_clock % 1000 == 0:
            self.sync_target_network()
        # 4) 上报：指标字典进入报表，供诊断与调度器消费
        return {"policy_loss": losses["policy"], "value_loss": losses["value"],
                "kl": losses["kl"], "aux": losses["aux"],
                "sync_clock": self._sync_clock}

    def compute_losses(self, batch, *, kl_coeff, aux_coeff):
        # 独立函数：可在无环境的固定批次上做数值单测
        out = self.learner.forward(batch)
        policy_loss = -(out["logp"] * batch["advantages"]).mean()
        value_loss = ((out["vf"] - batch["returns"]) ** 2).mean()
        kl = self.learner.kl_to_reference(batch)      # 策略约束项（043/051 章）
        aux = self.learner.auxiliary_loss(batch)      # 辅助/蒸馏项（050 章）
        total = policy_loss + 0.5 * value_loss + kl_coeff * kl + aux_coeff * aux
        return {"policy": policy_loss, "value": value_loss, "kl": kl,
                "aux": aux, "total": total}

# 接口形态随版本演进：新版将前向拆到 RLModule、损失拆到 Learner，
# 训练回环的四个环节不变，以对应版本的官方文档为准

解读：逐块说明。（1）training_step 的结构与理论部分的四环节一一对应，注释标明每一步对接的历史章节，评审时按图索骥。（2）同步计数 _sync_clock 是算法自有状态，必须随检查点保存，否则恢复后节奏错位。（3）损失计算独立成函数并抛出未实现，是刻意的留白位置：数值单测直接调用它，不需要启动训练。返回字典的字段名与内置报表对齐，诊断面板无需特判。

片段 3：冒烟测试与恢复测试

import tempfile, os, math

def smoke_test(algo, iters=2):
    """冒烟：报表字段齐全、损失有限、参数确实变化。"""
    before = [p.detach().clone() for p in algo.get_policy().model.parameters()]
    last = None
    for _ in range(iters):
        last = algo.train()
    after = [p.detach().clone() for p in algo.get_policy().model.parameters()]
    moved = any(not (a == b).all() for a, b in zip(before, after))
    assert moved, "两轮后参数未变化：检查更新链路"
    for key in ("policy_loss", "value_loss"):
        assert math.isfinite(last["info"]["learner"]["default_policy"]["learner_stats"][key])
    return last

def restore_test(algo, iters=3):
    """恢复：检查点往返后损失连续、自定义状态无损。"""
    with tempfile.TemporaryDirectory() as d:
        for _ in range(iters):
            algo.train()
        ckpt = algo.save(os.path.join(d, "ckpt"))
        loss_before = algo.train()["info"]["learner"]["default_policy"]["learner_stats"]["value_loss"]
        restored = algo.from_checkpoint(ckpt.path)
        loss_after = restored.train()["info"]["learner"]["default_policy"]["learner_stats"]["value_loss"]
        # 连续性口径：恢复前后损失量级接近，不出现数量级跳变
        ratio = max(loss_after, 1e-9) / max(loss_before, 1e-9)
        assert 0.1 < ratio < 10.0, f"恢复后损失跳变: {ratio:.2f}"
        assert restored._sync_clock == algo._sync_clock, "自有状态未随检查点恢复"
    return True

解读：两段测试分别对应两道验收关卡。（1）冒烟测试用"参数是否移动"与"损失是否有限"两个断言覆盖最常见故障：更新链路断开与数值发散。（2）恢复测试的连续性口径用比值区间；绝对相等会误报，损失本身随训练变化是正常的，异常的是数量级跳变。（3）自有状态（同步计数）单独断言，示范"自定义状态必须随检查点往返"的检查方法；字段路径与保存接口随版本演进，以对应版本文档为准。

常见坑

  • 接入深度过度：能用配置开关表达的改动整包重写成自定义算法，放弃了框架的恢复与分布式能力。修复：按机制差异度三档评估，能低档不高档。
  • 接口范式混用：在旧范式的训练器里调用新范式的学习器接口，或反之，行为异常且文档难对应。修复：开工前确认版本默认栈，统一扩展点位置。
  • 自定义状态未入检查点：同步计数、统计量等自有状态不保存，恢复后节奏与尺度错位。修复：纳入状态存取并在恢复测试中显式断言。
  • 报表字段自造口径：返回非标准字段名，诊断面板与 Tune 调度器无法消费。修复：与内置报表字段对齐，额外指标用命名空间前缀补充。
  • 跳过基线对照：自定义算法与内置算法差异巨大却未量化，收益无法归因。修复：同任务同预算跑基线，报表并列归档。

练习与思考

  1. 对下列三项需求判定接入档位并说明理由：给 PPO 增加熵系数调度；给 DQN 增加辅助重构损失；实现"每隔若干环境步暂停采样做一轮评估"的新回环。★
    提示
    调度可用回调或配置（第一档）；辅助损失是目标函数可加项（第二档）；回环时序变化需要掌握采样控制权（第三档）。
  2. 为片段 2 的 compute_losses 写一份数值单测设计：给出固定批次构造、期望检查项与容差口径。★★
    提示
    用手工构造的小批次算出各项损失的解析值，与实现比对；容差按浮点量级取相对误差 1e-5 量级；同时检查辅助项权重为零时损失退化为任务项。
  3. 设计恢复测试矩阵：保存点分别选在同步事件前、事件后、更新数据比变更后，说明每格检查什么状态。★★★
    提示
    同步事件前后核对目标网络参数与计数一致性；UTD 变更后核对换算后的同步节奏，防止环境步口径漂移。
  4. 解释为什么"每个环节可独立测试"能显著缩短自定义算法的调试周期，给一个没有独立测试时故障定位困难的例子。★★
    提示
    端到端训练失败时，采样、损失、更新、上报四段都可能出错且症状相似；分层测试把故障范围缩小到一段。
  5. 给自定义算法写一份"机制归属表"：把 041 至 053 章的机制分配到配置类、算法类、模块或学习器四个位置，并说明分配依据。★★★
    提示
    超参与默认值归配置；时序与编排归算法；前向结构归模块；损失与优化归学习器。分配依据是"职责单一"与"可独立测试"。

小结

  • 接入深度三档：组件组合、损失扩展、完整自定义，按机制差异度选择，低档继承的框架能力最多。
  • 两代接口范式的扩展点不同，先确认版本默认栈，再决定配置类、算法类、模块与学习器的职责分配。
  • 训练回环四环节：采样、损失构造、参数更新、指标上报；每环节独立成函数是调试效率的结构保障。
  • 机制归属有据可依：探索与奖励在策略侧，回放与目标网络在学习侧，计数口径贯穿配置与报表。
  • 验收两道关卡：冒烟测试校验接口与数值，恢复测试校验状态完整性与连续性。
