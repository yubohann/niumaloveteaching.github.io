第二篇 · RLlib 核心接口与训练

第 033 章：RLlib处理图像输入

图像观测把视觉信息直接送入策略网络，代价是样本体积与计算量同时上升。本章讲清帧堆叠的时序语义、卷积特征提取器的结构参数、归一化与格式约定，以及图像样本对采样链路的影响。

  • 主题：RLlib 训练 / 观测模态
  • 关键机制：帧堆叠、卷积过滤器配置、感受野、归一化、样本体积预算
  • 预计学时：55 分钟
  • 前置章节：第 032 章

学习目标

  • 理解图像观测的时序语义：为什么单帧状态不完整，帧堆叠如何近似状态。
  • 掌握卷积特征提取器的配置结构：层数、通道、卷积核与步长的作用。
  • 会计算特征图尺寸与感受野，用它们解释网络容量与代价的取舍。
  • 掌握归一化与数据格式约定，保证观测空间声明与真实编码一致。
  • 会估算图像样本对内存、对象存储与采样吞吐的影响并做预算规划。

背景与动机

视觉观测在游戏与机器人任务中普遍存在：画面比低维状态量携带更多信息，也让环境接口更通用。代价同样明确：单帧图像按百万像素计，堆叠后的观测体积进一步放大，采样链路与存储带宽承压；网络在图像上提取特征所需的计算量显著高于全连接结构。

图像输入还有一层时序问题：单帧画面往往是部分观测，仅凭一帧无法判断运动方向与速度。帧堆叠（Frame Stacking）把连续若干帧沿通道方向拼接，让网络从帧间差异中恢复动态信息。图像链路的三个核心决策是：栈深取多少、卷积结构如何配、样本体积是否在预算内。上一章完成了实验跟踪，本章转入输入模态的具体处理。

核心原理

图像观测的处理围绕时序补全、特征提取与体积预算三条线索展开。

1. 帧堆叠与部分可观测性

把连续 k 帧沿通道拼接后，观测张量形状为（高, 宽, k 乘通道数）或按框架约定组织。栈的作用是近似完整状态：单帧给出位置，帧间差异给出速度信息，k 通常取 2 到 4。栈深与信息量不成正比：过大时最早帧价值下降、体积线性增长；过小时动态信息不足，策略短视。回合边界的清空或重复填充两种语义应在包装中明确并保持一致。

特征图边长 = floor((输入边长 − 卷积核) / 步长) + 1 逐层代入可估算输出尺寸；连续堆叠小核卷积的感受野按核尺寸线性叠加，下采样主要由步长承担

2. 卷积特征提取器的结构

RLlib 的卷积配置是一组过滤器描述：每项给出输出通道数、卷积核大小与步长，按顺序堆叠。典型结构从较大步长开始快速降采样，随后堆叠同尺寸卷积提取纹理与结构特征，最后拉平接入全连接头。结构参数的决定因素是空间分辨率与感受野：步长过大细节早期丢失，感受野过大局部响应变钝；通道数决定特征容量与显存占用。通用起点是三到四层卷积配 32 到 64 通道。

3. 数值范围与格式约定

原始像素通常为 8 位整数，取值 0 到 255；网络输入端应归一化到 0 到 1 区间，并把观测空间声明为 float32。未归一化输入使激活尺度放大，学习率需重新校准，梯度裁剪频繁触发。另一处要求是布局一致：空间声明必须与包装器实际输出一致，形状错位在分布式训练中表现为远端异常，定位成本高。框架在部分版本提供归一化包装器，启用后确认训练与评估两条路径都生效。

4. 样本体积与链路预算

图像观测放大三项成本：回放或批次对象的字节数、对象存储流量、跨进程与设备搬运时间。以 84×84 灰度四帧为例，单个观测约 28 KB；并行环境 32 个、每环境每秒 60 步时，观测流量约每秒 5400 万个字节量级，链路压力开始显现。预算手段按优先级排列：降低分辨率与灰度化（信息量损失可控时）、控制栈深、减少并行环境副本数、把图像处理留在采集端。先把单样本体积定下来，再放大并行规模，是图像任务与低维任务在工程顺序上的最大差别。

5. 结构参数的数值演算

对 84×84 灰度输入与过滤器列表 [[32, 8, 4], [64, 4, 2], [64, 3, 1]] 逐层推算尺寸与感受野：

6. 栈深档位的对比

84×84 灰度观测按 uint8 存储，单帧 7056 字节，不同栈深下的体积与流量对比如下（32 个并行环境、每环境每秒 60 步）：

栈深单观测体积观测流量动态信息适用情形
17.1 KB约 13.5 MB/s无（仅位置）完全可观测的静态任务
214.1 KB约 27.1 MB/s一阶差分（速度）动态需求温和的任务
428.2 KB约 54.2 MB/s位置、速度与趋势通用起点，动态任务
856.4 KB约 108.4 MB/s收益递减长时依赖明显的特殊任务

选择依据：默认从 4 起步；消融实验分别验证栈深降到 2 是否损失表现、升到 8 是否带来净收益。栈深翻倍让体积与流量同步翻倍，而动态信息的边际收益递减，超过 4 之后需要明确的实验证据支持。

7. 分辨率与步长的耦合

同一套卷积参数在不同输入分辨率下的输出差异显著。把输入从 84×84 换成 64×64，同样三层卷积后的特征图从 7×7 变为 4×4，拉平维度从 3136 降到 1024，全连接头参数缩到约三分之一，单观测体积降到原来的约 58%（28 KB 中的 16 KB 量级）。分辨率、步长与全连接规模三者耦合，修改任一输入尺寸后都要用尺寸公式重算特征图与拉平维度，再核对显存预算。缩小分辨率不一定省整体计算：若要保持感受野比例，需要同步调整核与步长，卷积层的参数与计算量会随之变化。

8. 卷积与全连接的两笔账：参数与乘加

把卷积栈展开逐层算两笔账。以 84×84 灰度四帧输入（首层输入通道 4）与过滤器列表 [[32, 8, 4], [64, 4, 2], [64, 3, 1]] 为例：

  • 卷积 1：8 × 8 × 4 × 32 + 32 = 8224 个参数；每输出位置乘加 8192 次，20 × 20 个位置、32 个通道合计 8192 × 400 ≈ 327.7 万次。
  • 卷积 2：4 × 4 × 32 × 64 + 64 = 32832 个参数；9 × 9 个位置、64 个通道合计约 265.4 万次。
  • 卷积 3：3 × 3 × 64 × 64 + 64 = 36928 个参数；合计约 180.6 万次。

卷积栈合计约 8.8 万参数、约 774 万次乘加；接一个 3136 → 256 的全连接头则有约 80.3 万参数、约 80.3 万次乘加。对照给出本讲最值得记住的定量结论：卷积栈的参数不到全连接头的九分之一，乘加量却是它的近十倍，摊到每个参数约八十八次乘加；全连接的乘加量与参数量一比一。

结构参数量每样本乘加量特征
卷积栈（四帧输入）约 8.8 万约 774 万参数少、计算密度高，乘加约为参数的 88 倍
全连接头（3136 → 256）约 80.3 万约 80.3 万参数多，每参数一次乘加

两笔账分开解释三类工程现象。其一，分辨率与通道数的调整首先改写乘加量，训练迭代时间对卷积结构敏感，对全连接宽度相对迟钝。其二，批量 4096 时卷积栈的整批前向约 317 亿次乘加，一次前后向更新在千亿次量级，这是图像任务依赖加速器、且学习阶段时间占比高的直接原因。其三，全连接头是参数与显存的大头，缩小它省显存，缩小卷积栈省时间，两种压缩各有靶点。栈深从 1 加到 4 只影响首层输入通道：首层参数从 2080 升到 8224，卷积总乘加量从约 528 万升到约 774 万，涨幅约五成，这是帧堆叠换动态信息的算力标价。

实现思路与设计

实施顺序：确定分辨率与栈深、实现包装器、配置卷积结构、核对空间声明、测量吞吐与内存。

设计决策：为什么 84×84 灰度四帧成为常见起点？

这一组合在三个约束之间取得了平衡：空间信息足以支撑多数视觉决策，灰度去掉的信息通常与任务无关，四帧覆盖短时动态；单观测体积约 28 KB，在并行采样与批次搬运的预算内。它属于经过验证的默认配置，不宣称理论最优。起点选默认，随后用消融实验回答两个问题：灰度是否损失任务信息、栈深能否减到 2 而不损性能。

内存预算的数值示例：训练批次 4096 个观测按 28 KB 计约 112 MB 的批次对象，内部小批 256 时为 7 MB；32 个并行环境的栈缓存合计不足 1 MB。批次对象的打包与搬运是主要开销来源，回放式算法的池内存另按容量单列。观测量化与帧跳步是两种常见的体积控制手段：帧跳步把每个决策推进多个仿真步，跳步 4 时单步决策覆盖 4 帧时间，样本效率与反应精度之间取折中；感受野所覆盖的时间跨度需与动作影响的持续时间对齐，动作长期起作用的任务需要更大的感受野或循环结构补充。量化这两笔：60 帧每秒的环境、跳步 4 时决策频率降到每秒 15 次，观测流量同步降到四分之一；栈深 4 加跳步 4 的时序窗口约 12 个仿真帧（0.2 秒），窗口短于动作实际影响的持续时间时，网络难以建立动作与结果的对应关系，此时应减小跳步或增大栈深。

消融实验的记录模板固定五项：分辨率、颜色通道、栈深、评估回报与每秒样本数，每组一行，便于横向比较。放大或缩小分辨率时同步复核卷积结构与感受野比例，空间尺寸、步长与全连接规模三者互相牵制，单独改动任一项都应重算特征图。视觉任务的观测增强需要谨慎：亮度与对比度扰动通常安全，随机裁剪会改变空间对应关系，仅在位置不敏感的任务中考虑。

预处理链的测试与审计：对固定输入帧序列调用包装器，断言输出形状、数值范围与帧序方向三项；帧序方向（旧帧在前或新帧在前）一经确定不再改动，训练、评估与导出推理共用同一构造函数。通道布局在导出推理时保持一致，避免训练侧通道末尾、推理侧通道优先的隐性错位。批量前向的收益与采样规模相关：并行环境数越大，单次前向覆盖的样本越多，固定开销摊薄越明显；并行规模小时逐步前向与批量前向差异有限。跳帧参数在环境构造处只出现一次，任何离线脚本不得复制该逻辑。包装器的超参（分辨率、栈深、灰度开关）属于实验配置的一部分，修改后训练与评估同步生效，配置快照中一并记录。

关键代码与解读

片段 1：帧堆叠与归一化包装器

import numpy as np
from gymnasium.spaces import Box


class FrameStackGray:
    """把彩色帧转为灰度并堆叠 k 帧；输出 float32，取值 0 到 1。"""

    def __init__(self, env, k=4):
        self.env = env
        self.k = k
        self.frames = []                      # 最近 k 帧，最新帧放在列表尾部
        obs_space = env.observation_space
        self.observation_space = Box(
            low=0.0, high=1.0,
            shape=(84, 84, k),                # 形状声明与实际输出布局严格一致
            dtype=np.float32)

    def _process(self, obs):
        # 灰度化：按感知亮度加权，再缩放到 84×84 并归一化到 0 到 1
        gray = np.dot(obs[..., :3], [0.299, 0.587, 0.114])
        small = gray[::max(1, gray.shape[0] // 84),
                     ::max(1, gray.shape[1] // 84)]
        return (small / 255.0).astype(np.float32)

    def reset(self, **kwargs):
        obs, info = self.env.reset(**kwargs)
        frame = self._process(obs)
        # 回合开始时用首帧填满栈：语义明确、实现简单
        self.frames = [frame] * self.k
        return np.stack(self.frames, axis=-1), info

    def step(self, action):
        obs, reward, terminated, truncated, info = self.env.step(action)
        self.frames.append(self._process(obs))  # 新帧入栈
        self.frames = self.frames[-self.k:]     # 只保留最近 k 帧
        return np.stack(self.frames, axis=-1), reward, terminated, truncated, info

解读：包装器承担三件事：灰度化、缩放与归一化、帧堆叠。形状声明 (84, 84, k) 必须与 np.stack 的输出一致，通道维放在最后与多数框架的默认布局兼容；回合开始时用首帧重复填充，语义是静止起始；与逐帧真实填充两种做法都可行，关键是评估与训练一致。缩放用抽样示意，生产实现应使用面积插值，避免纹理失真。

解读：过滤器列表的每一项包含通道、核与步长三个数字，顺序即数据流方向。首层大步长把 84×84 快速降到约 20×20 量级，控制后续层的计算量；第二个卷积核继续降采样；第三层保持尺度提取结构。配置键名随版本演进（新 API 栈中模型配置的层级有调整），以对应版本文档为准。通道数顺次放大是通行模式：空间分辨率下降时，用更多通道承载语义信息。

片段 3：特征图尺寸与感受野估算

def feature_map_size(size, kernel, stride, layers):
    """逐层计算特征图边长，返回各层尺寸与最终尺寸。"""
    sizes = []
    for _ in range(layers):
        size = (size - kernel) // stride + 1
        sizes.append(size)
    return sizes


# 84 输入配 8/4、4/2、3/1 三个卷积：观察空间如何逐层收缩
sizes = feature_map_size(84, 8, 4, 1) + feature_map_size(
    feature_map_size(84, 8, 4, 1)[-1], 4, 2, 1)
final = feature_map_size(sizes[-1], 3, 1, 1)[-1]
# 拟合全连接层的输入维度：最终特征图边长平方乘通道数
print(sizes, final, final * final * 64)

解读：尺寸估算回答两个问题：全连接层输入维度、计算量集中在哪层。边长按公式递推，最终边长乘通道数得到拉平维度，决定全连接层参数与显存。最终边长退化到 1 附近说明降采样过狠，空间信息丢失；估算与批大小联立可得到激活占用上界。

常见坑

  • 忘记归一化：像素保持 0 到 255。症状是损失尖峰、梯度裁剪频繁。修复：包装器内缩放并声明空间上界为 1。
  • 堆叠顺序与评估不一致：训练按帧序堆叠，评估按反向。症状是评估回报远低于训练。修复：堆叠逻辑封装在唯一包装器内，训练与评估共用。
  • 首层步长过大：空间细节早期丢失。症状是策略对细节敏感的任务表现差。修复：减小首层步长或提高输入分辨率，用尺寸估算验证输出。
  • 空间声明与实际布局不一致：声明为通道优先，输出为通道末尾。症状是远端形状异常，报错无调用现场。修复：断言输出形状与声明一致，包装器单元测试。
  • 副本数照搬低维任务配置：观测体积放大后内存与链路吃紧。症状是内存溢出或吞吐骤降。修复：按样本体积重新规划副本数与批次。

练习与思考

  1. 84×84 灰度四帧的观测体积约多少字节？并行环境 32 个、每环境每秒 60 步时的观测流量量级是多少？★
    提示
    单观测约 84×84×4=28224 字节；流量约为 28224×32×60，约每秒 5400 万字节量级。
  2. 把栈深从 4 减到 2，预测样本体积、采样吞吐与动态任务表现的变化方向。★
    提示
    体积与搬运开销约减半、吞吐上升；速度信息减少，需要短时动态判断的任务表现可能下降。
  3. 推导：给定卷积层序列，写出特征图尺寸与感受野的递推式，并说明为什么感受野过大会削弱局部响应。★★
    提示
    尺寸按 floor((n−k)/s)+1 递推；感受野按 k+(k−1)×累积步长累加。感受野覆盖过大时，单个输出单元混合远端像素，局部动作对应的特征被平均化。
  4. 设计消融实验：分辨率 84 与 64、灰度与彩色两组对照，说明评估指标与样本体积的权衡记录方式。★★
    提示
    固定其余配置，比较评估回报与每秒样本数；体积收益记录为倍数关系，性能损失以回报差值的置信区间表达。
  5. 设计图像任务的内存预算：从单观测字节数推演批次对象、回放缓冲与并行副本三项占用，给出副本数上限的计算过程。★★★
    提示
    批次占用等于训练批次乘单观测字节；缓冲按容量乘单观测估算；副本占用等于总环境数乘栈缓存大小。三项相加与内存预算对照，反推副本数上限。

小结

  • 单帧图像是部分观测，帧堆叠补全短时动态信息，栈深取 2 到 4 是通行区间。
  • 卷积过滤器按通道、核、步长三元组配置，首层大步长降采样，后续层堆叠提特征。
  • 特征图尺寸按 floor((n−k)/s)+1 逐层递推，拉平维度决定全连接层规模。
  • 像素归一化到 0 到 1、dtype 用 float32、空间声明与实际布局一致，三处约定缺一不可。
  • 图像样本放大链路成本，先定单样本体积再放大并行规模。
