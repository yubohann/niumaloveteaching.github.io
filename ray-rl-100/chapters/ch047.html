第三篇 · RLlib 算法实现

第 047 章：RLlib算法选择方法：从任务特性出发

先读任务再选工具：动作空间形态、采样成本、样本预算与并行规模如何构成决策变量，同策略（On-policy）与异策略（Off-policy）两大类算法的经济性差异，以及如何用一次小预算试点（Pilot Run）验证选择。

  • 主题：RLlib 训练（算法选型方法）
  • 关键机制：任务特性画像、样本与计算成本交换、试点验证
  • 预计学时：50 分钟
  • 前置章节：第 046 章

学习目标

  • 掌握任务特性画像的六个维度：动作空间、采样成本、样本预算、可观测性、奖励结构、并行规模。
  • 理解同策略与异策略算法在样本效率与计算效率上的结构性差异，能解释各自的适用区间。
  • 会使用一张决策表把任务特性映射到候选算法与初始配置起点。
  • 能设计小预算试点实验，用收敛步数与单位时间吞吐两类指标验证算法选择。
  • 能识别三类常见的选型错误：指标口径错配、动作空间错判、忽略部署约束。

背景与动机

RLlib 提供十余种算法实现，官方文档列出了各自的能力边界，但把边界翻译成"这个任务该选哪个"仍需要一套方法。选型错误的代价很高：在采样昂贵的环境里选错策略类，意味着要付出数倍的真实环境交互；在并行仿真充足的任务里选错，意味着放弃吞吐优势、训练周期被无谓拉长。

本章把算法选择拆解为任务画像、成本模型、试点验证三步，把直觉判断变成可复核的流程。后续章节的模型选择、吞吐调优、稳定性诊断都在这个选择结果之上展开。

核心原理

本节先建立任务画像的六个维度，再给出两套成本模型与一张决策表。

2. 成本模型：样本效率与计算效率的交换

同策略算法（PPO、A3C、IMPALA）只用最新数据，每个样本贡献一次梯度后即丢弃；异策略算法（DQN、SAC）把数据存入回放缓冲反复利用，单个样本贡献多次梯度。设单样本的梯度复用次数为 k，则两类算法的样本效率相差约 k 倍：

达到同等性能的采样量：Non-policy ≈ k · Noff-policy，k 为经验复用次数 k 由回放缓冲区与更新数据比（Update-To-Data Ratio, UTD）决定；k 越大，对价值估计误差的放大也越强

计算侧的账本同样关键：异策略算法每采样一步要伴随多次梯度更新，CPU 与 GPU 时间消耗更高；当环境并行度充足、单步采样代价低时，同策略算法把计算预算花在"多采样"上，墙钟时间反而更短。选型的本质是回答：瓶颈在采样侧还是在计算侧。采样侧的瓶颈用异策略算法缓解，计算侧的瓶颈用同策略算法缓解。

瓶颈侧的快速判断口径：同一配置下分别测量每轮迭代的采样时间与学习时间，取两者比值。比值大于约 1.2 视为采样侧主导，小于约 0.8 视为学习侧主导，中间区间说明两侧已接近匹配。该口径与 049 章的吞吐调优共用同一组计时字段，选型阶段用于估算 k*，调优阶段用于验证扩展收益；两处口径保持一致，可以避免一次训练维护两套账本，测量结果归档后选型结论与后续调优还能共用同一份基线数据。

4. 试点验证：把选择变成可复核的实验

候选算法各跑一次小预算试点，预算取 105 至 106 环境步量级，比较两类指标：达到目标回报的采样步数（样本维度）与单位时间的采样步数及更新次数（吞吐维度）。两个维度会给出四条可能的结论，其中"样本效率与吞吐都占优"并不常见，多数任务需要在两者间按总成本做加权决策。试点结论要记录随机种子与评估协议，为正式训练提供基线。

5. 数值算例：样本效率与并行度的盈亏平衡

把成本模型写成可代入的算式：总墙钟时间 T ≈ N · ( c / W + l )。其中 N 为达到目标性能所需的环境步数，c 为单环境步的采样成本（秒），W 为并行环境数，l 为摊到每个环境步的更新计算成本（秒）。令 k = N同策略 / N异策略 为样本效率倍数，异策略算法在墙钟上占优的条件是 k 超过盈亏平衡值：

k* = ( c / W异 + l异 ) / ( c / W同 + l同 ) k 超过 k* 时异策略墙钟更短；k* 的下界是并行度之比 W同/W异，采样越昂贵，k* 越接近该下界

代入一组给定参数逐步计算。PPO：N = 2×106 步，64 个并行环境，每 32768 个环境步配套 32 次梯度更新，单次更新 8 毫秒，于是 l同 = 32×8÷32768 ≈ 7.8 微秒；单步采样 2 毫秒时 c/W同 ≈ 31 微秒，T同 ≈ 2×106×(31+7.8) 微秒 ≈ 78 秒。SAC：N = 2.5×105 步，4 个并行环境，每环境步一次批量 256 的梯度更新、耗时 0.25 毫秒，则 c/W异 = 0.5 毫秒，T异 ≈ 2.5×105×0.75 毫秒 ≈ 188 秒。本例 k = 8，PPO 反而快约 2.4 倍，原因是 64 比 4 的并行度差距抵消了样本效率优势。若环境只能开 8 路并行，同样参数下 T同 ≈ 516 秒，SAC 反超约 2.7 倍。

单步采样成本 ck*（同策略 8 路对异策略 4 路）读数
0.1 毫秒（廉价仿真）13.5同策略吞吐优势大，典型 k=8 不够
1 毫秒3.8接近临界，两者都值得进试点
10 毫秒2.2异策略默认占优
50 毫秒（真实设备）2.0k* 趋近并行度之比的下界

读数方式：k* 随 c 下降而上升，说明采样越便宜，越要求异策略拿出压倒性的样本效率；采样越昂贵，盈亏平衡越接近并行度之比这个下界。试点前先用该式做一次纸面核算，把明显不划算的候选排除，试点只比较接近临界的一对，试验预算的分配由此有了依据。试点的统计口径同样要量化：设种子间回报标准差为 σ、重复次数为 r，均值标准误约为 σ/√r；头名差距小于一个标准误时不具备区分力，应增加重复次数或改看更稳健的配置，常规做法是每组跑 2 至 3 个种子，用最差种子的回报做保守排序。

6. 判据的边界与失效模式

盈亏平衡式在四条假设成立时可靠，逐条给出边界：（1）采样吞吐与并行度线性相关。W 超过物理核数后进程争抢 CPU，环境共享内存带宽时 c/W 不再下降，模型会低估同策略方案的时间；此情形按实测吞吐回填 c。（2）样本效率倍数 k 不是常数。回放数据陈旧、更新数据比过高时单样本贡献下降，k 从名义值 8 缩到 2 至 3 并不少见，判据要把 k 按保守值代入。（3）更新成本 l 与批次无关的假设不成立。批量增大时每步梯度成本上升，l 必须随配置重算。（4）任务平稳性。非平稳任务里早期数据对后期无用，回放复用受限，异策略优势进一步收窄。操作口径是先用单变量试点测量 c、W 与 l 的实测关系，再代入选型；任何一项偏离假设都回到测量步骤，避免用名义参数算出错误结论。

实现思路与设计

选型流程分五步执行。

  1. 画任务画像：填写六个维度，标注每个维度的证据来源（仿真计时、动作空间声明、奖励统计）。
  2. 定位瓶颈：估算单步采样代价与单次梯度更新代价之比，判断瓶颈侧。
  3. 生成候选集：按决策表取首选与备选各一至两个，控制候选总数不超过三个。
  4. 试点实验：固定种子、评估协议与网络规模，各跑小预算对照。
  5. 拍板与留档：按总成本加权选择，记录结论及适用条件，写入实验档案。

关键代码与解读

片段 1：把决策表写成函数

def recommend_algorithm(spec):
    """按任务画像返回候选算法与首选理由。
    spec 键：action、sample_cost、budget、pomdp、multi_agent、search。"""
    candidates = []
    if spec.get("search"):
        candidates.append(("alphazero_like", "搜索型任务：需要前瞻信号"))
    if spec.get("multi_agent"):
        base = "sac_multiagent" if spec["sample_cost"] == "high" else "ppo_multiagent"
        candidates.append((base, "多智能体：按采样成本选内核"))
        return candidates
    if spec["action"] == "discrete":
        # 离散动作：采样昂贵走价值型异策略，采样便宜走同策略吞吐
        if spec["sample_cost"] == "high" or spec["budget"] <= 5e5:
            candidates.append(("dqn", "离散 + 低预算：回放复用样本"))
        else:
            candidates.append(("ppo", "离散 + 高预算：并行吞吐优先"))
    else:
        if spec["sample_cost"] == "high" or spec["budget"] <= 1e6:
            candidates.append(("sac", "连续控制 + 低预算：熵正则 + 回放复用"))
        else:
            candidates.append(("ppo", "连续控制 + 高预算：同策略批量稳定"))
    if spec.get("pomdp"):
        candidates.append(("叠加循环网络", "部分可观测：按 045 章方法启用 LSTM"))
    return candidates

解读：逐块说明设计意图。（1）函数把决策表固化为代码，评审时可逐条件核对该任务的证据，选型结论从此可复核。（2）预算阈值（5e5、1e6 步）是经验起点：低于该量级时异策略的复用优势更值钱，高于该量级时同策略的并行吞吐更值钱，阈值随任务上下浮动。（3）部分可观测作为叠加项返回，体现"算法与记忆结构正交"的原则。

片段 2：同一环境的两套最小配置对照

from ray.rllib.algorithms.ppo import PPOConfig
from ray.rllib.algorithms.sac import SACConfig
import gymnasium as gym

ENV = "HalfCheetahSim"                 # 连续控制仿真，单步约 2 毫秒

# 候选 A：SAC，回放复用样本，更新频率高于采样
sac_cfg = (
    SACConfig().environment(ENV).framework("torch")
    .env_runners(num_env_runners=4, num_envs_per_env_runner=1)
    .training(
        train_batch_size=4096,       # 异策略：批次取自回放，不与采样一一对应
        tau=0.005,
        lr=3e-4,
        replay_buffer_config={"capacity": 1000000},
    )
)

# 候选 B：PPO，采样与更新比例固定，worker 可扩展到 16 以上
ppo_cfg = (
    PPOConfig().environment(ENV).framework("torch")
    .env_runners(num_env_runners=16, num_envs_per_env_runner=4)
    .training(
        train_batch_size=32768,      # 同策略：批次即最新采样，必须足量
        lr=3e-4,
        gamma=0.99,
        lambda_=0.95,
    )
)
# 试点时两套配置固定同一随机种子与评估协议，只比较这两份配置

解读：这段对照把两类算法的结构差异落到配置上。（1）SAC 的 worker 少而批次小，因为样本会被反复使用，不需要高采样吞吐。（2）PPO 的批次必须覆盖全部 worker 的最新产出，worker 数与批次同步放大，采样吞吐是其主要优势来源。（3）试点要求固定种子与评估协议，否则两条曲线的差异无法归因到算法本身。

片段 3：试点结果对比口径

def summarize_pilot(runs, target_return):
    """runs: {name: [(env_steps, return, wall_clock_s), ...]}。
    输出两个维度的到达指标，供加权决策。"""
    table = []
    for name, series in runs.items():
        steps_to_target = next((s for s, r, _ in series if r >= target_return), None)
        total_steps = series[-1][0]
        total_time = series[-1][2]
        throughput = total_steps / max(total_time, 1e-9)      # 步/秒
        table.append((name, steps_to_target, total_steps, round(throughput, 1)))
    for row in table:
        print(f"{row[0]:8s} 达标步数={row[1]} 总步数={row[2]} 吞吐={row[3]} 步/秒")
    return table

# 决策规则示例：以"达标步数 × 单位步成本 + 墙钟时间 × 单位时间成本"排序；
# 仅看曲线高度会误导：不同算法的曲线横轴口径并不相同

解读：逐块说明。（1）达标步数衡量样本维度，吞吐衡量计算维度，两者分开输出避免单一指标误导。（2）墙钟时间的单位成本与单步采样成本在不同任务里权重悬殊，加权系数应由任务画像填入，函数保持中立。（3）注释里的决策规则强调曲线对比的陷阱：横轴口径不一致时直接比高度会得到错误结论。

加权决策的数值示例：候选 A 达标步数 3×105、吞吐 2000 步每秒，候选 B 达标步数 8×105、吞吐 8000 步每秒。按墙钟折算 A 需 150 秒、B 需 100 秒，B 占优；若真实环境按 0.001 元每步计费，A 花费 300 元、B 花费 800 元，结论在费用口径下反转。同一个试点数据在两套权重下给出相反结论，正说明加权系数必须在试点前从任务画像确定，事后挑口径等于挑答案。

常见坑

  • 用采样步数单维对比：忽略每步成本与吞吐差异，得出"异策略总是更省钱"的错误结论。修复：并行输出达标步数与吞吐两列，按任务成本加权。
  • 动作空间误判：把"离散选择的连续参数"当成纯连续任务，或将多离散头结构塞进单一离散空间，策略头与损失全部错配。修复：逐维检查动作语义，混合结构用复合动作空间支持。
  • 试点预算过小：预算低于算法发挥差异的尺度，两条曲线都在随机水平附近，结论无效。修复：试点预算按候选算法中最保守的收敛尺度取值，至少 105 环境步量级。
  • 忽略部署约束：离线环境里选了推理成本高的方案，上线时才发现延迟超标。修复：画像阶段记录部署约束，试点时同步测量推理延迟。
  • 频繁更换算法：每个算法都没有完成一次完整调参周期，归档数据互相不可比。修复：候选集控制在三个以内，每个候选至少完成一轮学习率与批次规模的粗调。

练习与思考

  1. 给出三个任务画像（离散 + 高成本采样；连续 + 廉价仿真；离散 + 稀疏奖励 + 部分可观测），分别用决策表给出候选算法并写出理由。★
    提示
    分别对应 DQN 家族、PPO、PPO 叠加循环网络与探索机制；理由要落到六个维度中的具体条目。
  2. 推导：设异策略算法的经验复用次数 k=8，同策略算法每样本使用 1 次，忽略两者单次梯度成本差异，证明达到同等性能的采样量之比约为 k，并说明这个近似在什么条件下失效。★★
    提示
    样本量正比于所需梯度信息量除以单样本贡献；当回放数据陈旧、价值估计偏差增大时，单样本贡献下降，k 倍关系退化。
  3. 设计试点实验：三个候选算法、两组随机种子、统一评估协议，给出实验矩阵、总预算与结论判定规则。★★
    提示
    3×2 矩阵共 6 次运行；预算按单次 2e5 步计；判定规则按达标步数与吞吐的加权得分排序，并记录二、三名差距是否在种子波动范围内。
  4. 某任务单步仿真 5 毫秒、可用 16 个并行 worker，SAC 单步更新开销 1 毫秒，PPO 每步采样仅需 0.2 毫秒计算。粗估两者吞吐上限并给出选择建议。★★★
    提示
    PPO 吞吐上界约 16/(5+0.2) 毫秒每步的倒数；SAC 受限于更新链路且采样并行度低。计算瓶颈侧决定建议，注意估计只用于量级判断。
  5. 解释为什么"团队调试经验"是合法且重要的选型因素，并给出把经验因素纳入决策而不失客观性的做法。★★
    提示
    调试效率影响问题定位速度；做法是把它写成工程约束条目（如日志完备性、社区资料规模）并纳入试点评估的备注，定量指标仍是主判据。

小结

  • 算法选择从六维任务画像开始：动作空间、采样成本、样本预算、可观测性、奖励结构、部署约束。
  • 同策略与异策略的差异本质是样本效率与计算效率的交换，选型先定位瓶颈在采样侧还是计算侧。
  • 决策表把任务形状映射到候选算法，工程约束（框架支持、恢复链路、调试经验）参与修正。
  • 试点实验固定种子与评估协议，输出达标步数与吞吐双指标，按任务成本加权决策。
  • 三类高频错误：单维对比、动作空间误判、试点预算过小。
  • 下一章处理选择的下一层：同一算法内部策略网络的结构选择，MLP、CNN 与 RNN 各自对应什么观测形态。
