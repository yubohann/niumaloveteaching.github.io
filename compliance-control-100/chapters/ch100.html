第五篇 · 鲁棒控制与工程实践

第 100 章：阻抗控制中的性能评估

全课程的收官一章：把"调得不错"变成"测得清楚"。力跟踪精度、动态响应、稳定性代理、鲁棒性包线、安全指标、工程开销，六组指标 + 一套可重复的测试清单，构成柔顺控制从演示走向产品的那道验收门。

  • 主题：性能评估 / 指标体系与验收测试
  • 关键公式：误差 RMS、2% 调节时间、高频能量比、∫F·v dt（交互能量）
  • 预计学时：70 分钟
  • 前置章节：第 099 章

学习目标

  • 理解性能评估的三重价值：验收（能不能上线）、诊断（哪里不对）、迭代（往哪改）。
  • 掌握六组指标：力跟踪精度、动态响应（上升/超调/调节时间/纹波）、稳定性代理（高频能量比、交互能量）、鲁棒性包线（跨环境刚度）、安全指标（检测延迟、停止距离）、工程开销（实时性、噪声底）。
  • 会从日志计算指标：稳态误差、RMS、超调、调节时间、纹波、高频能量比与交互能量，并输出通过/不通过报表。
  • 会设计可重复的测试清单：阶跃、斜坡、正弦扫频、变刚度、碰撞模拟；明确每项的判据、采样时长与记录字段。
  • 能完成全课程的收束：把 100 章的知识组织成"建模—参数—稳定性—感知—安全—工程"的知识树，并知道下一步怎么深入。

背景与动机

柔顺控制的现场故事里，"看起来不错"和"验收通过"之间经常隔着一段争议：力跟踪差 0.5 N 算不算问题？接触瞬间的力尖峰到 45 N 会伤工件吗？换了更硬的工作台会不会振荡？这些问题的共同难点是，没有指标就没有共识。本章的第一个目标是把"手感"翻译成数字：跟踪精度、响应时间、超调、纹波、振荡能量、跨环境包线、检测延迟、停止距离。指标一旦固定，验收就有了裁判，调参就有了方向（哪个指标在恶化），复盘就有了证据（这次事故是谁超限）。

第二个目标是建立可重复的测试方法。柔顺控制的表现强烈依赖工况：同一套参数在软垫上温柔、在钢台上暴躁。所以测试清单必须覆盖"任务包线"：环境刚度、接近速度、负载、期望力曲线，每一项都按统一脚本执行、统一字段记录，才能在参数或代码改动后做"前后对比"。这也是本章反复强调的工程习惯：测过的参数才叫调过，没测过的调参只是换了个说法。

最后，作为第 100 章，它还要承担收官任务：把五篇、一百章的方法、公式与踩坑串成一张知识地图。学完本章，你应当能为任何一台柔顺机器人设计一份验收方案，也能凭指标曲线反推问题出在控制器的哪一层。

核心原理

1. 力跟踪精度：最核心，也最容易被"平均"掩盖

力控任务的成败首先看力。三个基本量：

ess = F̄稳态 − Fdes（稳态误差）；RMSE = √(Σ(Fi−Fdes)²/n)（全段均方根） F̄稳态：末段均值；RMSE 对瞬态尖峰敏感，两者必须一起看

为什么必须一起看？稳态误差回答"稳不准"，RMSE 回答"全程波动多大"：一个稳态误差为零、但接触瞬间冲高 20 N 的系统，平均下来误差可能很小，但工件已经在那一瞬间受伤了。所以第三个数是峰值：接触瞬态的 max|F|（第 001 章讲过它的来源：动量与未建模动态）。工程常用写法：稳态误差 ≤ 0.5 N、RMSE ≤ 1 N、瞬态峰值 ≤ 1.5×Fdes，具体数值随工艺，但"三个一起定"的原则通用。

纹波（稳态段的 F 标准差）是第四个量：它反映噪声通道与抖振（第 047、084、085 章）。纹波大通常意味着滤波不足、增益过高或切换项太激进；纹波小但误差大则往往是标定/补偿问题（第 091–093 章）。诊断口诀：先看误差的"均值 vs 波动"，均值偏 → 查标定补偿与稳态公式；波动大 → 查噪声、增益与切换。

2. 动态响应：阶跃是试金石

对阶跃目标（力的或位置的）记录四条曲线指标：上升时间 tr（10%→90%）、超调、调节时间 ts（进入并保持在 ±2% 或 ±5% 带内）、以及"到达前是否有反向"（有些阻抗参数会先"让过头"再回来）。调节时间是其中最有工程意义的一个：它同时包含响应速度与振荡衰减，直接对应节拍时间。

ts：最后一次离开 ±2% 容带之后再未越界的时间；超调 = (Fpeak − Fdes)/Fdes 对接触任务建议用 ±2% 的严带；对自由运动位置跟踪用 ±5%

与前面的理论挂钩：二阶系统里 Overshoot 与阻尼比、ts 与自然频率一一对应（第 037 章的阻尼比调节），如果你测出的超调远大于 ζ 理论预测，几乎一定是"未建模动态"在参与（内环延迟、滤波、碰撞非线性），指标异常的价值不在数字本身，而在它指向的理论缺口。

3. 稳定性代理：把"看起来稳"变成可测的量

严格稳定裕度（增益/相位裕度）需要辨识闭环模型，工程验收常没这个条件。两个实用的代理指标：

高频能量比 = Σ|F(f > 40 Hz)|² / Σ|F(f > 0.5 Hz)|²；交互能量 E(t) = ∫F·v dt 前者抓"抖振/振荡"，后者是"无源性观察"：E 持续正增长说明系统在从环境吸能，需要警惕

高频能量比对"嗡嗡振"极其敏感（第 083 章的振动监督器用的就是它的实时版本）：稳定的接触（比如打磨）里 40 Hz 以上的能量占比通常在 1% 以下；一旦切换项过猛或增益过界，这个数会成倍上升。交互能量则用来观察能量流向：柔顺系统应该是"耗散型"的，四个象限里工作量主要落在 F·v < 0（机器人对外做功、环境吸收）一侧，E(t) 有界；如果 E(t) 随时间持续增大，说明控制器或模型误差在向系统注能，稳定性余量在消耗（第 058、059 章的无源性设计的实践检验）。

4. 鲁棒性包线、安全指标与工程开销

剩下的三组是"上线必测"：

组别指标典型判据（量级示例）
鲁棒性包线Kenv ∈ [103, 105] N/m 的稳态误差与振荡指标的最坏值；参数漂移 ±20% 的表现最坏稳态误差 ≤ 1 N；最坏高频能量比 ≤ 3%
安全指标碰撞检测延迟（第 097 章）、停止距离（第 098 章）、停止峰值力、回退成功率（第 099 章）、虚警次数25 N 碰撞 < 5 ms；停止峰值力 ≤ 1.5×Fmax；虚警 0 次/30 分钟
工程开销控制周期抖动、超时次数、CPU 占用、传感器噪声底抖动 < 20% 周期；超时 0 次/小时；噪声底作为一切阈值的基准

为什么要单独列"工程开销"？因为柔顺控制是"慢而精细"的控制，很多人误以为它对实时性不敏感，恰恰相反：阻抗/导纳方程里的积分与微分对周期抖动非常敏感，10% 的抖动等效于在控制回路里加入随机延迟（第 015、016 章的稳定性分析对延迟最敏感）。周期抖动本身必须进指标；而传感器噪声底是一切门限、死区、阈值的来源（第 091/096/097 章反复用到），它必须在"完整信号链"上测量。这三组指标与前三组一起，构成六组验收体系。

工程直觉：指标体系是一张"合同"，它规定了机器人在这台工作台上、对这个工件、以这套流程工作时，哪些行为可接受、哪些不可接受。合同里没有的项目，现场就会各自解释；合同里写死的项目，调参与返工才有依据可循。

实现思路与设计

  1. 定指标：与工艺（工件许用力、节拍）和安全（人体限值）一起定六组指标和判据；每一项写清"测量工况"（环境刚度、速度、负载、目标曲线）。
  2. 建测试台：可换刚度的标定台（如 103/104/105 N/m 三档衬垫或弹簧组）；力标定装置（第 091 章）；记录系统（力、位置、速度、事件标志，1 kHz，统一时间戳）。
  3. 测试脚本：按统一顺序执行，阶跃（0→15 N）、斜坡（0→15 N/2 s）、正弦（0.2/0.5/1/2 Hz）、变刚度重复、接近速度扫描（10/50/200 mm/s）、碰撞模拟（5/10/25 N 标定撞击）、安全动作（停止/回退）。
  4. 指标计算：离线脚本从日志算全部指标（本章片段 1–2），输出"实测—判据—裕量"报表（片段 3）。
  5. 基线管理：每次参数/代码变更后重跑并对比基线；指标恶化超 10% 需要解释并通过评审（把"感觉变差了"变成"ts 从 0.35 s 升到 0.48 s"）。
  6. 上线门禁：六组指标全部通过 + 安全动作演练记录 + 现场工况抽样，缺一不可。
设计决策：为什么建议用"最坏工况"跑验收，不选"典型工况"？

典型工况下的漂亮曲线可以靠"环境恰好合适"获得；而现场的变化才是风险：今天在钢台上、明天在橡胶垫上、操作员还换来换去。最坏工况验收（最软/最硬、最快、最重）等价于给系统一份保守包线：包线内通过，实际使用就基本不会有意外。代价是测试时间长、可能被迫接受保守参数；收益是"上线后不出幺蛾子"。柔顺控制的一次事故（压坏工件/伤到人）的成本，通常远大于把包线测完的花费。

关键代码与解读

片段 1：阶跃响应指标计算

import numpy as np

def step_metrics(t, f, f_ref, tol=0.02):
    """从一段阶跃响应日志计算：稳态误差/超调/上升时间/调节时间/纹波。"""
    t, f = np.asarray(t), np.asarray(f)
    n = len(f)
    f_ss = float(np.mean(f[-n // 10:]))          # 末段均值：比标称目标更鲁棒
    err_ss = f_ss - f_ref
    overshoot = (float(f.max()) - f_ref) / abs(f_ref)
    # 上升时间：首次跨过 10% 与 90% 目标的时刻差（仅正阶跃示例）
    t_rise = float("nan")
    if np.any(f >= 0.9 * f_ref):
        t10 = t[int(np.argmax(f >= 0.1 * f_ref))]
        t90 = t[int(np.argmax(f >= 0.9 * f_ref))]
        t_rise = t90 - t10
    # 调节时间：±tol 容带内"最后离开"的时刻；残留振荡会把它推大
    outside = np.where(np.abs(f - f_ref) > tol * abs(f_ref))[0]
    t_settle = float(t[outside[-1]]) if outside.size else 0.0
    ripple = float(np.std(f[-n // 10:]))
    return {"err_ss": err_ss, "overshoot": overshoot, "t_rise": t_rise,
            "t_settle": t_settle, "ripple": ripple}

解读：五个指标各管一段信息：err_ss 看末段（标定与稳态公式），overshoot 看全段峰值（阻尼与瞬态），t_rise 看前沿（带宽），t_settle 看衰减过程（振荡与非线性），ripple 看稳态波动（噪声与抖振）。两个实现选择：（1）稳态值用"末段均值"，不用设计目标，保证万一有稳态偏差也能被抓到（否则用目标值算，稳态误差永远为零）；（2）tol 容带默认 2%，接触力用严带、自由运动可换 5%。

片段 2：稳定性代理指标（高频能量比与交互能量）

def stability_indices(t, f, v, fs=1000.0, f_cut=40.0):
    """两个稳定性代理：高频能量比（抖振/振荡）与交互能量（无源性观察）。"""
    f = np.asarray(f); v = np.asarray(v)
    # 1) 高频能量比：把力信号的频谱分成"工作段"与"抖动段"
    F = np.fft.rfft(f - f.mean())
    freqs = np.fft.rfftfreq(len(f), 1.0 / fs)
    hf = float(np.sum(np.abs(F[freqs > f_cut]) ** 2))
    tot = float(np.sum(np.abs(F[freqs > 0.5]) ** 2)) + 1e-12
    chatter = hf / tot
    # 2) 交互能量：∫F*v dt 的累积与峰值，观察系统是否在"吸能"
    dt = t[1] - t[0]
    energy = np.cumsum(f * v) * dt
    return {"chatter": chatter,
            "energy_end": float(energy[-1]),
            "energy_peak": float(energy.max())}

解读：chatter 的判读经验：稳定打磨通常 < 1%；2–3% 说明有可见的振荡需要处理；> 5% 基本可以听到"嗡嗡声"，要回到第 083 章的振动监督与参数检查。energy 曲线的用法：柔顺系统的交互能量曲线应当是"爬升—走平"的：爬升段对应接触建立时的动能被环境吸收，走平说明稳态下没有额外的能量注入；若持续线性增长，检查力方向与速度方向是否长期同号（主动压入）、模型误差是否在持续泵能。注意这是"观察指标"，不能替代严格"证明"：它能抓住大部分工程问题，但严格的无源性验证仍需第 058/059 章的理论工具。

片段 3：验收报表（实测—判据—通过/不通过）

def accept_report(metrics, spec):
    """把实测指标与验收规格逐项对照，输出报表，返回总体是否通过。"""
    ok_all = True
    for key, (limit, mode) in spec.items():
        val = metrics[key]
        ok = (abs(val) <= limit) if mode == "max" else (val >= limit)
        ok_all = ok_all and ok
        margin = limit - abs(val) if mode == "max" else val - limit
        print(f"{key:12s} 实测={val:8.3f}  判据 {mode} {limit:7.3f}  "
              f"裕量={margin:7.3f}  {'通过' if ok else '不通过'}")
    print("总体:", "通过" if ok_all else "不通过（见上表红项）")
    return ok_all

spec = {"err_ss": (0.5, "max"), "ripple": (0.3, "max"),
        "overshoot": (0.20, "max"), "t_settle": (0.50, "max"),
        "chatter": (0.03, "max")}
demo = {"err_ss": 0.21, "ripple": 0.12, "overshoot": 0.14,
        "t_settle": 0.42, "chatter": 0.008}
accept_report(demo, spec)

解读：报表的三个字段设计，实测、判据、裕量，让评审能一眼看出"哪项在边缘、哪项很宽松"。mode="max" 用绝对值比较（超调、误差这类双向指标），mode="min" 留给"回退成功率 ≥ 99%"这类下限指标。注意裕量的意义：所有指标都"刚好压线通过"的系统是最危险的，它离失效只有一点扰动之遥；工程上常见的底线是"关键项裕量 ≥ 30%"。把这份报表与测试脚本、日志一起归档，就得到了这份系统全生命周期的"健康档案"，也是后续第 082/093 章各种在线自适应机制能够被信任的前提，因为你知道它们"在没有它们的时候"表现如何。

常见坑

  • 只测典型工况：软垫上完美通过，钢台上一片振荡。修复：环境刚度、速度、负载三维包线的角点必测；本章设计决策的"最坏工况"原则。
  • 用目标值当稳态值：稳态误差永远算出 0。修复：稳态值取末段均值（片段 1），并把两者之差作为"标定/补偿"的诊断量。
  • 忽略周期抖动：离线回放日志时用理想周期积分，掩盖了实时系统的抖动。修复：记录真实时间戳，把"抖动"本身作为工程开销指标；抖动大时所有动态指标都不可信。
  • 指标没有基线：每次改完参数只看"当前像不像好"，无法判断是否退化。修复：建立基线 + 变更对比（恶化 10% 触发评审），把调参变成可追溯的工程记录。
  • 验收只测成功路径：碰撞、停止、回退这些"低概率事件"从不在验收里演练，真出事时第一次运行就是它们。修复：安全动作必须按标定事件（5/10/25 N 撞击）定期演练并记录指标（检测延迟、停止距离、回退成功率）。

练习与思考

  1. 用片段 1 的指标定义，说明"稳态误差小、RMSE 大"与"稳态误差大、RMSE 小"分别指向哪一类问题，各给出两个可能的根因与对应的检查章节。★
    提示
    前者多半是瞬态问题（接触冲击、滤波延迟，第 001/047 章）；后者多半是标定/补偿/稳态公式问题（第 091–093 章、第 083 章的自适应残差分析）。
  2. 给一段人造的力日志（稳态 15 N，含 0.02 N 高频噪声与 12 Hz 上 0.5 N 的振荡），用片段 2 计算高频能量比与交互能量，判断系统状态；再把振荡幅度翻倍，观察指标的比例变化。★★
    提示
    12 Hz 的能量落在 40 Hz 截止之下，chatter 指标不会抓它，这提醒你"高频能量比"只抓高频抖振，中频振荡要用时域的波纹/包络或专门的带能量指标补充。翻倍振荡后能量按平方增长（4 倍）。
  3. 为你的仿真系统写一份完整测试脚本（可用第 083/088 章的仿真作为被检对象）：包含阶跃、正弦、变刚度三组，共 9 次实验；输出章末形式的验收报表，并说明哪一项最先"压线"。★★
    提示
    典型结果：变刚度到最硬（105 N/m）时 ripple 或 chatter 最先压线；此时应按第 083 章降低 K_d 或按第 088 章加入约束，不能接受压线通过。
  4. 设计"全课程知识树"：把五篇（共 100 章）组织成六个主题（建模与坐标、参数与任务、稳定性与无源性、感知与估计、智能与先进控制、工程与安全），为每个主题写出 3 条最重要的公式或结论，并标出你的薄弱环节。★★★
    提示
    示例锚点：Mẍ+Dẋ+Kx=F（第一篇）、F=K·偏置与 D=2√(KM)（第一篇）、无源性/能量整形（第三篇）、观测器残差（第三/五篇）、滑模 sat 边界层与最终界（第五篇）、检测阈值与停止距离（第五篇）。用"能否独立推导"作为掌握标准。

小结

  • 性能评估的三重价值：验收有裁判、诊断有方向、迭代有基线；六组指标，力跟踪、动态响应、稳定性代理、鲁棒性包线、安全指标、工程开销。
  • 核心计算：稳态误差与 RMSE 必须同看（均值查标定、波动查噪声/增益），阶跃给出 tr/超调/ts/纹波，频谱给出高频能量比与交互能量。
  • 测试清单按"最坏工况 + 可重复脚本"组织：阶跃/斜坡/正弦扫频/变刚度/接近速度扫描/碰撞与安全动作演练；变更必对比基线。
  • 安全与实时性是验收硬门槛：检测延迟、停止距离、回退成功率、周期抖动与噪声底都要有实测记录；关键指标裕量建议 ≥ 30%。

全课程回顾：从一架弹簧到一台会"拿捏"的机器人

回望整门课，我们把一句话反复讲了 100 遍：柔顺控制的全部内容，就是把"力"和"位置"之间那条被环境决定的隐含关系，变成机器人身上一条被设计出来的显式关系。第一篇（第 001–020 章）从单自由度出发，把这条关系写成 Mdẍ + Ddẋ + Kdx = −F，用 F = Kd·偏置和 Dd = 2√(KdMd) 两个公式解决了"稳态力怎么来、参数怎么起手"，并补上重力/摩擦补偿、动力学模型与稳定性分析这些地基，没有它们，开篇的公式只是黑板上的漂亮式子。第二篇解决参数调节与交互任务：恒力跟踪、拖动示教、装配/插拔、抛光打磨等典型工艺，以及力/位/速/矩限制。第三篇学会"看见力"并进入智能调参：滤波、观测器、辨识是所有柔顺的前提，模糊、神经网络、强化学习、能量整形与无源性则是参数面对时变环境时的武器。第四篇把触角伸向复杂任务（曲面跟踪、六维力控、冗余与任务优先级），并在约束、避障与学习里收束（限制、动态避障、ILC 学习辅助、自适应增益）。第五篇是"不确定性的武器库"与车间现场：鲁棒项（sat 边界层与最终界 ρ/(kv+ρ/ε)）、滑模、反步、动态面、MPC、H∞ 与无传感器估计，加上传感器校准、重力补偿、负载适应、多机与主从协同、接触/碰撞检测、安全停止与紧急回退，最后用本章的指标体系把一切落在可验收的坐标上。

如果只能带走三句话，请带走这三句：第一，先想清楚"力-位关系"，你想让机器人对外表现成什么弹簧，方程里的每个参数都要能说出它的物理含义与量级；第二，稳定性不是调出来的，是算出来的，从无源性、能量、李雅普诺夫到最坏情况范数，方法与工具各有代价，但都要有论证；第三，工程的一半在校准与检测，零点、重力、负载、噪声、阈值、状态机，这些"不性感"的工作决定了实验室演示与产线设备之间的全部距离。愿你带着这套知识树继续往前走：去读文献、去做实验、去踩新的坑，然后，把柔顺控制教给下一台机器人。
