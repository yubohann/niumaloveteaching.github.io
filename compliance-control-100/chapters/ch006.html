第一篇 · 基础、建模与稳定性

第 006 章：基于力控制的阻抗控制实现

当机器人直接吃"关节力矩"时，柔顺不再靠位置命令变戏法：你输出弹簧-阻尼力矩，剩下的交给物理。本章讲清 τ = JTF 的映射、惯性无法凭空改变的现实，以及重力与饱和这两个逃不掉的账。

  • 主题：阻抗控制 / 力矩（力）接口实现
  • 关键公式：τ = JT(Kde + Ddė)，Mxẍ + Dd(ẋ−ẋd) + Kd(x−xd) = Fext，Mx = J−TMJ−1
  • 预计学时：55 分钟
  • 前置章节：第 005 章

学习目标

  • 理解力矩接口实现阻抗的物理机理：为什么"给一个弹簧-阻尼力矩"就能得到期望的柔顺行为。
  • 会用虚功原理推导 τ = JTF，并说清它与第 005 章"位置命令"路线在计算上的根本差异。
  • 掌握 Level-0/Level-1/Level-2 三种实现等级：无模型弹簧-阻尼、加重力前馈、加惯量整形与外力项，各自需要什么条件。
  • 理解"表观惯量 = 机器人自身惯量 Mx(q)"这一限制的来源，以及为什么它随构型变化。
  • 会写带力矩饱和与重力补偿的力接口控制律，并解释重力、摩擦、饱和各自对阻抗的污染方式。

背景与动机

协作机器人与直驱机器人普遍开放"力矩模式"：控制柜接受关节力矩指令，不再多管一层位置环。这条通道让柔顺控制进入另一个世界，控制方式从"骗"机器人走路转为直接告诉它每块肌肉使多大劲。位置型方案（第 005 章）里"内环带宽决定手感真假"的焦虑消失了，但两条更硬的规则浮出水面：第一，机器人自身的惯性无法靠软件变没，除非你有模型；第二，重力、摩擦和力矩上限都直接印在最终手感上。

本章先给出力接口的最简实现骨架 τ = JT(Kde + Ddė)，证明它确实实现阻抗；再沿着"精度—代价"阶梯往上爬，看每一级要付出什么信息、买到什么性能。第 013 章会把阶梯顶端（基于动力学模型）完整展开。

核心原理

1. 从物理出发：力接口为什么"天生"柔顺

机器人关节级动力学（教学简化版，忽略科氏项）：M(q)q̈ + g(q) = τ + JTFext，其中 M(q) 为关节空间惯量矩阵（kg·m²），g(q) 为重力力矩（N·m），τ 为控制器输出的关节力矩（N·m），JTFext 是环境广义力投影到关节上的力矩。现在让控制器输出纯粹的"弹簧-阻尼力矩"：

τ = JT(Kde + Ddė)， e = xd − x， ė = ẋd − ẋ e：任务空间位置偏差（m）；ė：速度偏差（m/s）；Kd(N/m)、Dd(N·s/m) 为期望刚度与阻尼

把控制律代入动力学，并假定机器人运动较慢（q̈ ≈ J−1(ẍ − J̇q̇)，J̇q̇ 较小可并入误差项；重力由前馈补偿到 g−ĝ≈0），投影到任务空间后得到：

Mx(q)·ẍ + Dd(ẋ−ẋd) + Kd(x−xd) = Fext， Mx(q) = J−TM(q)J−1 Mx：机器人末端的等效惯性矩阵（kg），随构型 q 变化；这就是"物理实现"的阻抗方程

工程直觉：外力和弹簧-阻尼力矩在同一个运动方程里"抢方向盘"，外部一推，误差 e 出现，控制器回一个反向力矩，力度正比于 e；而机器人自己的质量充当了方程左端的惯性项。注意一个和第 005 章完全不同的细节：外力 Fext 不需要测量，它通过物理动力学自然进入方程；位置接口下必须测力（因为力要被换算成位置命令），力矩接口下柔顺是"物理自洽"的。这是两类实现最深刻的区别，也是协机器人"推力即走、松手即停"手感的来源。

2. 虚功原理：力域映射取 JT 的原因

任务空间的力怎么变成关节力矩？用虚功原理：外力在任务空间做的虚功 FTδx 必须等于关节力矩做的虚功 τTδq，而运动学给出 δx = J·δq：

τTδq = FTδx = FTJ·δq ⟹ τ = JTF 对任意虚位移 δq 成立；JT 即"力域"的映射，J 是"速度域"的映射

这个映射带来一个宝贵的工程性质：JT 不需要求逆，在奇异位形附近仍然有界。位置接口路线每拍要做 IK 或 J−1，奇异点附近数值爆炸需要阻尼化处理；力矩接口的 Level-0 实现完全绕开逆运算，只要机器人还在工作空间内就能出力。当然代价也真实存在：JT 的"投影"会使某些方向上的力无法独立产生（对应 J 的零空间方向），末端刚度矩阵的几何形状随之畸变，这属于高级话题，先记住"转置安全、逆不安全"。

3. 三条实现等级的完整地图

力接口实现阻抗有三个层次，按所需信息递增排列：

等级控制律需要的信息实现的阻抗
Level-0τ = JT(Kde + Ddė)运动学 J、状态 x/ẋMx(q)ẍ + Dd(ẋ−ẋd) + Kd(x−xd) = Fext，惯量=真实惯量
Level-1再加关节重力前馈 ĝ(q)+ 重力模型或辨识同上，静态不再下垂，"零力"手感成立
Level-2计算力矩 + 外力项 −JTF̂ext+ 完整动力学 M、C、g 与测力惯量可整形为 Md，全频段理想阻抗（第 013 章）

Level-2 里那个减号最容易让初学者困惑，值得单独说清：机器人动力学里本来就含 +JTFext 一项；如果你的目标是"外力按 1/Md 的规则驱动末端"，就要先把环境项从回路里扣掉，再由外环按 Md−1Fext 重新注入。少扣或多扣都会让阻抗"变味"，只扣不注入，机器人对外会变硬（那是力伺服，不是柔顺）。

4. 表观惯量：改不动的那一半

Level-0 的方程左端惯性是 Mx(q)，不是你能指定的 Md。这是物理使然，与实现是否粗糙无关：输出力不能直接决定质量，质量由牛顿第二定律和物体本身决定。Mx 有两个现实后果：

  • 构型依赖：手臂伸直时末端等效惯量可达弯曲构型的数倍（Mx 随 J 变化）。同样的 Kd，手推起来的"沉重感"会随姿态漂移。碰撞同样的速度，伸直构型的冲击动能更大。
  • 耦合：Mx 非对角项意味着 x 方向受力会带着 y 方向加速，末端像被"斜着推"。对低速接触任务影响小，对快速协作任务需要模型补偿。

如果任务要求"无论怎么摆姿态，末端手感一样"，就必须进 Level-2 做惯量整形；如果任务只是稳速接触（打磨、装配），Level-0/1 的稳态行为足够，因为稳态与质量无关（第 003 章已经证明）。

5. 重力、摩擦与饱和：三笔逃不掉的账

力接口把"本体的一切"直接暴露给手感：

  • 重力：不补偿时，弹簧的平衡点被 g(q) 平移。2 kg 工具挂 0.8 m 偏心处，静态重力矩约 2×9.81×0.8 ≈ 15.7 N·m，占典型关节力矩上限（50–150 N·m）的 10–30%；表现为松手后末端缓慢"塌"向低位，松手停位根本做不到。
  • 摩擦：关节摩擦在低速下形成死区：小于摩擦值的力矩指令推不动关节，表现为"小力微调时末端不动，一过阈值突然窜动"。精密微动任务必须做摩擦补偿（第 012 章）。
  • 力矩饱和：每个关节都有 τmax。一旦饱和，实际输出的阻抗和你写在代码里的不是一回事：某个方向先到极限后，误差继续增大而力矩不涨，表现为"越推越软"甚至反向塌陷。所有力矩指令必须经过逐关节饱和，并在饱和时记录、降级。

实现思路与设计

力接口阻抗的工程落地流程：

  1. 确定目标阻抗：Kd 按任务取 200–2000 N/m（接触类），Dd 用 2ζ√(KdMref) 给初值，Mref 用当前构型下 Mx 的近似对角值，Level-0 下 ζ 要按真实惯量算，否则你以为的临界阻尼可能只是 0.3。
  2. 写反馈项：e 与 ė 用 FK 状态与滤波速度；e 的速度项建议用"参考速度与实测速度之差"，但参考速度规划要平滑，否则 ė 里的尖峰直接变力矩尖峰。
  3. 加前馈：ĝ(q) 用解析模型或离线辨识表；有工具负载时把工具重力/惯性也并入前馈。没有前馈表时，至少把"零位附近"的重力矩拟合出来。
  4. 安全环节：wrench 等比限幅 → JT 映射 → 关节力矩饱和 → 关节速度超限时注入阻尼。顺序不能反：先限幅再映射，保证方向不变；映射后再饱和，防止某关节爆表。
  5. 验收测试：静态推压测试，用测力计缓慢推末端，记录力-位移曲线，斜率应等于 Kd（Level-0 的斜率为 Kd，因为稳态与惯量无关）；松手后回中时间应接近 4/(ζωn)。
设计决策：为什么重力前馈要提前到 Level-0，留到 Level-2 再补行不行？

因为重力污染的是静态行为，而静态恰好是接触任务的核心工况：装配对孔、打磨压紧都发生在准静态。省掉 ĝ 的代价是平衡点偏移与"零力示教"手感缺失，而且频繁触发力矩饱和。重力前馈只需一个中等复杂度的模型（或 6–10 个参数的辨识表），量产机器人出厂通常都带这个能力。反过来说，如果机器人不开放重力模型但开放"零力模式"，可以直接利用它已有的补偿，把注意力放在外层 Kd、Dd 上。

最后一个前置判断：目标任务是否需要惯量整形？判据有两条：任务的动态接触频带（如 5 Hz 碰撞检测）是否高到惯性项不可忽略；同一程序是否要在多种构型下保持统一手感。两者有一个成立，就该规划 Level-2 路线，并在参数整定前先把模型辨识好，这是第 013 章的内容。

关键代码与解读

片段 1：按等级装配的力矩控制律

import numpy as np

def impedance_torque(J, e, de, k_d=500.0, d_d=None,
                      m_ref=1.0, g_hat=None, f_meas=None):
    """力接口阻抗：按接口能力逐级装配控制律，返回关节力矩。

    参数：
      J      : 3×n 或 2×n 雅可比（此处通用写法，行数=任务维数）
      e, de  : 任务空间位置/速度偏差（m, m/s）
      g_hat  : 关节重力前馈（N·m），None 表示不做（Level-0）
      f_meas : 实测外力的广义力向量（N），None 表示纯柔顺（不抵消）
    """
    d_d = d_d if d_d is not None else 2.0*np.sqrt(k_d*m_ref)
    f_cmd = k_d * e + d_d * de           # Level-0：弹簧-阻尼广义力
    tau = J.T @ f_cmd                    # 力域映射：不需要求逆，安全
    if g_hat is not None:
        tau = tau + g_hat                # Level-1：扣掉本体重力，静态不塌
    if f_meas is not None:
        # Level-2 的部件：把外力从回路中抵消（配合模型重新注入）。
        # 单独使用=对外变硬（力伺服语义），不是柔顺，勿混用
        tau = tau - J.T @ f_meas
    return tau

解读：这个函数把三个等级压缩成一个"信息开关"，方便对照理解，但真机上建议按等级拆成独立类，防止误传参数。m_ref 的用途是给 ζ 定标：它应当填当前构型下 Mx 对角项的估计值（比如伸直构型的 1–3 kg）；随便取 1 kg 正是 Level-0 最容易被忽略的"隐性参数错配"。f_meas 分支上方的注释值得反复读：很多人拿"减去实测力"当万能柔顺配方，结果发现机器人变硬，其实这是力伺服语义，柔顺的正确用法是让它作为第 013 章计算力矩控制器的一个组件。

片段 2：2 连杆臂上的力接口柔顺，没有力传感器也能"让位"

L1, L2 = 0.35, 0.30

def fk(q):
    return np.array([L1*np.cos(q[0]) + L2*np.cos(q[0]+q[1]),
                     L1*np.sin(q[0]) + L2*np.sin(q[0]+q[1])])

def jac(q):
    return np.array([[-L1*np.sin(q[0]) - L2*np.sin(q[0]+q[1]), -L2*np.sin(q[0]+q[1])],
                     [ L1*np.cos(q[0]) + L2*np.cos(q[0]+q[1]),  L2*np.cos(q[0]+q[1])]])

q, qd = np.array([0.40, 0.50]), np.zeros(2)
I_j = np.array([0.08, 0.05])         # 关节惯量（kg·m²，教学简化对角型）
k_d, d_d = 500.0, 45.0               # 目标刚度与阻尼（稳态与 d_d 无关）
x_d = fk(q) + np.array([0.02, 0.0])  # 期望点：向 x 正方向偏 2 cm
xe, k_env, dt = 0.52, 1e5, 1e-3

for i in range(2000):
    x, J = fk(q), jac(q)
    e = x_d - x                      # 任务空间偏差（位置接口的"误差"）
    de = -J @ qd                     # 速度偏差：参考静止，故取实测负值
    f_ext = -k_env*(x[0]-xe) if x[0] > xe else 0.0   # 环境：单向弹簧
    # 核心一行：弹簧-阻尼力矩 + 环境力矩（环境力经 Jᵀ 进关节）
    tau = J.T @ (k_d*e + d_d*de) + J.T @ np.array([f_ext, 0.0])
    qdd = tau / I_j
    qd += qdd * dt
    q += qd * dt
    if i % 400 == 0:
        print(f"t={i*dt:3.1f}s x=({x[0]:.3f},{x[1]:.3f}) "
              f"F={f_ext:6.2f}N e_x={(x_d-x)[0]*1e3:6.1f}mm")

解读：注意这段代码里没有力传感器、没有力变量进入控制律，f_ext 只出现在仿真用的机器人动力学里（作为物理事实），控制器对它一无所知，柔顺却依然发生。这就是第 1 节推导的代码化。运行后你会看到：末端被墙挡住后，e 并不归零，会稳定在 F/k_d ≈ 一个几毫米的区间，稳态偏差就是"柔顺的迹象"，与第 003 章的稳态公式一致。把 k_d 从 500 抓到 2000 重跑：误差缩小、接触力更"较真"，曲线更抖；把 d_d 减半：松手回弹出现振荡。为什么参考只在 x 方向偏 2 cm：让接触力自然浮现在几牛的量级（x_d=0.52 附近时 F≈2–5 N），不至于把教学例子的量级搞大。真机移植时，把 tau = ... 前加 ĝ(q)、后加逐关节饱和，就得到可用的 Level-1 回路。

片段 3：wrench 限幅与力矩饱和，安全顺序不能反

def limit_wrench(f, f_max):
    """广义力等比缩放：保方向、留总幅值，避免单轴独占限幅。"""
    n = np.linalg.norm(f)
    return f if n <= f_max else f * (f_max / n)

def wrench_to_torque(J, f, tau_lim):
    """Jᵀ 映射 + 逐关节饱和；返回力矩与饱和标志供上层降级。"""
    tau = J.T @ f
    tau_sat = np.clip(tau, -tau_lim, tau_lim)
    saturated = bool(np.any(np.abs(tau) > tau_lim + 1e-9))
    if saturated:
        # 饱和发生时实际阻抗与设定不符：宁可记录并让上层"软化"，
        # 也不要在饱和状态下继续累积积分/误差（真机上常见失控来源）
        print(f"[warn] 力矩饱和: 指令 {np.round(tau,2)} → {np.round(tau_sat,2)}")
    return tau_sat, saturated

# 使用演示：12 N 预算、每关节 20 N·m 上限
f_max, tau_lim = 12.0, 20.0
J_demo = np.array([[0.3, -0.2], [0.4, 0.5]])
for f_raw in (np.array([8.0, 6.0]), np.array([30.0, 10.0])):
    f_lim = limit_wrench(f_raw, f_max)          # 先限幅：||f|| ≤ 12N
    tau, sat = wrench_to_torque(J_demo, f_lim, tau_lim)
    print(f"f={f_raw} → f_lim={np.round(f_lim,2)} → tau={np.round(tau,2)}")

解读：工程上这两个函数是"保命件"。先限幅再映射的理由：如果在映射之后逐关节截断，各关节截断比例不同，合成出来的力方向会歪掉，末端感觉像"被未知的手法拽走"；等比缩放力向量等于"所有关节一起按同比例缩水"，方向不变。反过来，映射之后再对关节力矩饱和也是必须的，因为 JT 会把多轴力叠加到单关节：某个关节可能独自爆表。saturated 标志的设计意图是给上层留降级接口：检测到饱和时应触发轨迹放缓、刚度软化或任务暂停；放任误差在饱和状态下继续累积，会让机器人在脱离接触瞬间"弹射"。演示里的第二组输入（30 N 的大力）展示完整链路：等比缩放把方向保住、幅值砍到 12 N，映射后仍可能触碰关节上限，则再次被逐关节截断并报警。

常见坑

  • 忘记重力前馈：Level-0 直接上机，末端静态下垂、松手不回位，大家误以为是 Kd 不够大。修复：先补 ĝ(q)，再做推压标定；判断特征，"偏置不随刚度成比例缩小"。
  • 把 −JTF̂ 单独当柔顺用：机器人对外表现变硬甚至顶着人走，因为它把环境力从回路里抵消了。修复：明确"柔顺（不接外力项）"与"力伺服（接外力项且配套模型）"两种语义，不混用。
  • 用 J−1 换 JT 求速度前馈再顺手求力：力矩方向写反（该转置的地方求逆），奇异点附近数值爆炸。修复：记死"速度用 J（或 J−1），力用 JT"。
  • ζ 按错误的惯量标定：Level-0 的表观惯量是 Mx(q)，取 1 kg 常量去算 Dd，某些构型下实际阻尼比低到 0.3，松手晃得像弹簧门。修复：按当前构型估算 Mx 调整 Dd，或上 Level-2。
  • 不计摩擦死区：微弱力指令被关节摩擦"吃掉"，微调时末端不动、稍加力就窜。修复：摩擦前馈（第 012 章）或增大 Dd 抑制低速爬行，前者治本，后者治标。

练习与思考

  1. 用虚功原理推导 τ = JTF，并说明若把 J 误写成 JT 会出现什么物理后果。★
    提示
    δx = Jδq，令 FTδx = τTδq 对任意 δq 成立；误用 JT 相当于维度/单位错配（N/m 与 N·m 混乱），轻则方向错误、重则量级荒谬，接触时正反馈。
  2. 把片段 2 中 k_d 改成 2000、100，分别预测并仿真接触稳态力与"让位"幅度，核对 e = F/k_d 的稳态关系是否仍成立。★★
    提示
    稳态与惯量无关（第 003 章），位置偏差 e_x 应满足 k_d·e_x ≈ |F|；k_d=2000 时偏差缩小、接触更"硬"，观察曲线是否更易振荡（ζ 没跟着同步）。
  3. 把片段 2 的 d_d 从 45 改到 15 再改到 2√(500×m_ref)（按伸直构型 m_ref≈2.5 kg 计算），对比松手后的回弹行为，用 ζ 公式解释差异。★★
    提示
    d_d=15 时 ζ≈15/(2√(500×2.5))≈0.3，明显振荡；按 m_ref 修正后 ζ≈1，回弹干净。这正是"隐性参数错配"的可见后果。
  4. 推导 Level-0 闭环：把 τ = JT(Kde + Ddė) 代入 M(q)q̈ + g(q) = τ + JTFext，整理出任务空间方程，并逐项说明做了哪些近似（忽略 C(q,q̇)、设 ĝ→g、J 变化慢）。★★★
    提示
    两边左乘 J−T 并令 ẍ ≈ Jq̈；环境项 +JTFext 左乘后正是 Fext；重力项相消。最终 Mxẍ + Dd(ẋ−ẋd) + Kd(x−xd) = Fext。
  5. 设计一条升级路线：现有系统只有关节力矩接口与零力模式（内部已做重力补偿），要求"推压手感在所有构型一致、松手 0.3 s 回中、2 Hz 以内的接触力可编程"。请说明哪些目标 Level-1 就能达到、哪个必须 Level-2，并列出 Level-2 所需要的额外信息清单。★★★
    提示
    零力模式已提供 ĝ；"手感一致"受 Mx(q) 构型依赖限制，需要惯量整形 → Level-2；"2 Hz 力可编程"若要求全频段精确，也指向 Level-2。额外信息：M(q)、C(q,q̇) 模型或辨识、J̇、可靠的 Fext 测量或估计。

小结

  • 力矩接口实现阻抗的机理：在机器人动力学里注入弹簧-阻尼力矩，外力通过物理方程自然参与，Level-0 无需力传感器。
  • 力域映射 τ = JTF 来自虚功原理，天然避开了 J−1 的奇异问题；位置接口用 J/Ik、力接口用 JT，两者不可混用。
  • 三等级路线：Level-0 纯弹簧-阻尼（惯量=机器人自身 Mx(q)）；Level-1 加重力前馈；Level-2 加惯量整形与外力项，需完整模型（第 013 章）。
  • 重力和摩擦直接污染手感，力矩饱和会改变实际阻抗；wrench 限幅在映射前、关节饱和在映射后，顺序不能反。
  • 下一章把两条路线摆在一起：同一组虚拟参数下，位置接口与力接口实现的导纳/阻抗在什么意义上等价、什么时候会分道扬镳，推导加数值双重验证。
