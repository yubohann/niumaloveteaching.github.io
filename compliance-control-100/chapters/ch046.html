第二篇 · 参数调节与交互任务

第 046 章：基于导纳控制的遥操作

上一章用波变量把信号"变形"来保住稳定性；本章换一种哲学：力与位置信号保持原样传输，只在两端各放一个"能量账本"，一旦发现链路开始凭空造能量，立刻用阻尼把它烧掉，这就是时域无源监视与控制（TDPA）路线。

  • 主题：双边遥操作 / 无源监视器与阻尼注入
  • 关键公式：Er(k) = Er(k−1) + Δt·Fapp·v，Fapp = −kfFr；α = Er/(Δt·Fapp²)
  • 预计学时：55 分钟
  • 前置章节：第 045 章（基于阻抗控制的遥操作）

学习目标

  • 理解"位置-力（P-F）"遥操作架构：主手位置命令从手、从手接触力回传主手，为什么力反射增益 kf 与稳定性直接对立。
  • 掌握时域无源监视器（PO）的账本公式：对"反射力对主手的做功"记账，理解账本为正为什么意味着链路在给主手泵能量。
  • 会推导无源控制器（PC）的耗散修正公式 α = Er/(Δt·Fapp²)，并说明它"只烧多余能量、不影响其余频段"的性质。
  • 能对比两条遥操作路线的适用场景：波变量（强保证、改造信号）与能量监控（原语义、依赖信号质量）。
  • 会处理从侧两个工程细节：力偏置更新与位置漂移抑制。

背景与动机

第 045 章的波变量方案有一个前提：链路上传输的信号从"力"和"速度"换成它们的线性组合。这让整个系统的稳定性有严格保证，但也带来副作用，特征阻抗 b 会像一层"隔膜"一样夹在操作者和环境之间，手感永远不会百分之百透明；而且已有的通信协议、滤波、记录工具都要适配新的信号语义。

本章给出第二条实用路线：信号保持原样（主手位置发下去、从手力发回来），但两端各维护一个"能量账本"，实时计算流经接口的净功率与累计能量。延迟链路在某些瞬间会表现为"负阻尼"，把能量灌回主手；无源监视器一旦发现账本透支，就精确地注入等量的阻尼把它烧掉。这种方法叫时域无源监视与控制（time domain passivity approach, TDPA），它的思想非常工程化："随时审计、有亏就补"，并不追求证明"永远无事"。与第 045 章对比：波变量是"改路线保平安"，能量监控是"走原路装护栏"。

核心原理

1. P-F 架构：谁传谁

基于导纳的遥操作典型结构是"位置-力"式：

  • 主手侧：导纳控制。人施加 Fh，从手回传接触力 Fr（经时延），主手按 Mmẍm + Dmẋm = Fh − kfFr 解算速度，输出位置 xm；
  • 链路下行：xm 延迟 τ 后到达从手；
  • 从手侧：位置内环跟踪 xm，与环境接触后测量接触力 Fs；
  • 链路上行：Fs 延迟 τ 后回到主手，成为 Fr。

力反射增益 kf ∈ (0, 1] 是透明性旋钮：kf = 1 时操作者"隔空摸到"环境刚度，kf = 0.3 时环境显得软糊糊但稳。经典结论（Niemeyer & Slotine等）是：无时延下 kf = 1 完美透明；有时延下，kf 必须显著降小否则振荡。本章的 PO/PC 正是要把 kf "救"回来：保持 kf 接近 1，只在账本告急的瞬间加阻尼。

2. 能量账本：PO 的递推公式

把"反射力作用在主手上的那个端口"看成一端口网络：输入是反射力沿 +v 方向的分量 Fapp = −kfFr（反射力顶回主手时 Fapp 为负），输出是主手速度 v。无源通道应有的性质是：它可以向主手"放电"（推送主手），但放出的不能超过之前主手顶着力做功时"充"进去的。定义反射力对主手的做功功率与累计账本：

Pr(k) = Fapp · v(k) = −kf·Fr · v(k)，Er(k) = Er(k−1) + Δt · Pr(k) Pr > 0：反射力与速度同向，通道在给主手"泵"能量；Pr < 0：主手顶着力做功，相当于给通道"充电"（正常耗散）

为什么账本会被破坏？因为 Fr 是 τ 秒之前的测量值。典型场景：主手撞墙后正在回弹（v 反向），而延迟的接触力还在"顶"着主手，此刻推力与回弹速度同向，通道把能量泵进主手，而那份能量本该更早被环境拿走。时序错位让"充电"与"放电"不再配对，这就是延迟诱发振荡的微观机制。注意账本允许为负（主手向通道做功是合法的），监视器真正盯的是"正余额"，这与第 059 章导纳端口的判据方向相反，符号约定不同，推导时先画一张"哪两个量相乘、正方向如何定义"的关系表，是 TDPA 实现最有效的防错手段。

3. PC：把"正在泵入"的能量即时烧掉

监视器发现 Er > 0 时，不允许"记账了事"，而要在本周期输出上做修正。取修正速度 Δv = −α·Fapp（沿反射力方向加一个黏性阻尼 α），它带来的能量变化为 Δt·Fapp·Δv = −Δt·α·Fapp²，令其恰好抵消账本余额：

α = Er / (Δt · Fapp²)，v修正 = v − α Fapp，修正后 Er ← 0 α 的量纲是 (m/s)/N，即导纳；负号的含义：阻尼永远逆着"被泵的方向"，这才是本架构下的耗散方向

这个方案的优美之处在于"精确"：注入的耗散刚好等于泵入量，不多烧一丝，因此 Er ≤ 0 的时段完全透明。它是保守版 TDPA：不做"电量预算"式的借贷（那是第 058 章能量槽的更精细方案），只要通道对主手净注能就即时烧掉；代价是主手用不上通道里"存"的能量，收益是实现简单、符号逻辑几乎不会误判，工业实现里很受欢迎。

4. 两条路线的分工

维度波变量（第 045 章）能量监控 TDPA（本章）
信号语义改为波变量 u、w保持 F、V（位置/力）原语义
稳定性依据任意时延下链路严格无源在线审计 + 按需耗散，依赖监视正确
透明性受 b 匹配限制kf 可接近 1，透支时才打折
失效模式b 失配 → 手感偏离力偏置/符号错误 → 账本审计失效
实现复杂度链路改造 + 缓冲两端加监视环路，链路不动

一句话选择：链路质量差、时延大且变化剧烈（如公网）优先波变量；已有成熟力/位置通信、想保住透明性（如本地局域网手术机器人）优先能量监控。

实现思路与设计

本节把两端的实现要点按顺序列清楚（控制周期 1 ms）：

  1. 主手导纳步：以 Fh − kfFr 为输入，解出速度与位置；对速度做状态限幅（≤ 0.5 m/s）。
  2. 账本更新：Er += Δt·Fapp·v，Fapp = −kfFr；单独记录本周期导纳耗散 −Dmv²·Δt 供对账。
  3. PC 修正：若 Er > 0 且 |Fapp| > 0.5 N（防除零与噪声放大），按 α 逆着 Fapp 修正速度，修正过的速度作为本周期输出并回写状态，账本归零。
  4. 从手跟踪：位置内环跟踪延迟后的 xm；在自由段用小刚度、接触段切换到位控+力限幅（也可直接用导纳）；接触力经偏置补偿后上行。
  5. 偏置更新：从手无接触时（|Fs| 小于阈值且运动缓慢）慢速更新力零点，防止偏置让"没碰到也报力"、把主手越推越远。
设计决策：为什么 PC 的门限设 |Fapp| > 0.5 N？

α = Er/(ΔtFapp²) 在 Fapp → 0 时趋于无穷。而反射力恰好经过零点（人手力与反射力相互抵消、接触力自然归零的瞬间）是接触任务的常态，此时若让公式裸奔，修正速度会被噪声放大成乱抖。设 0.5 N 门限保证：要么反射力有真实幅值，要么宁可不修正，此时账本只留下小余额，下次反射力回升时一并处理。

关键代码与解读

片段 1：主手导纳 + 能量账本 + PC 修正

import numpy as np

class AdmittanceReflectionPort:
    """主手端口：导纳模型 + 时域无源监视(PO)与控制(PC)。"""
    def __init__(self, m_m=1.5, d_m=30.0, dt=1e-3, kf=1.0, pc_on=True):
        self.m_m, self.d_m, self.dt = m_m, d_m, dt
        self.kf = kf              # 力反射增益：1.0 最透明，也最挑时延
        self.pc_on = pc_on
        self.v = 0.0              # 导纳积分状态
        self.e_r = 0.0            # 账本(J)：反射力对主手的累计做功
        self.v_max = 0.5          # 主手速度硬限幅(m/s)

    def step(self, f_h, f_r):
        # --- 导纳动力学：M dv + D v = f_h + f_app，f_app = -kf * f_r ---
        f_app = -self.kf * f_r            # 反射力作用在主手 +v 方向的分量
        a = (f_h + f_app - self.d_m * self.v) / self.m_m
        v_new = self.v + a * self.dt
        v_new = float(np.clip(v_new, -self.v_max, self.v_max))
        # --- PO：对“反射力对主手的做功”记账；正值=通道在泵能量 ---
        self.e_r += self.dt * f_app * v_new
        # --- PC：账本为正时沿反射力反向加阻尼，把泵入量即时烧掉 ---
        if self.pc_on and self.e_r > 0.0 and abs(f_app) > 0.5:
            alpha = self.e_r / (self.dt * f_app * f_app)
            v_new -= alpha * f_app        # 阻尼永远逆着“被泵的方向”
            v_new = float(np.clip(v_new, -self.v_max, self.v_max))
            self.e_r = 0.0                # 烧掉后归零，其余时段零干预
        self.v = v_new
        return self.v

解读：三行逻辑各有讲究。（1）修正量 v_new -= alpha * f_app 的方向"逆着 Fapp"：账本为正说明反射力此刻正把主手往某个方向泵，加一个反向阻尼刚好把泵入的能量吸收，这就是本架构下真正的耗散方向。符号写反是 TDPA 实现里最常见的错误：写反后修正变成"帮着泵"，账本越修越正、系统看起来"打了补丁"却仍然振荡。（2）修正后立即把账本清零，不留下余额：能量已经烧掉，账本必须同步销账，否则下一周期又会重复扣款，把系统越修越"死"。（3）速度限幅放在 PC 之前、并在修正后再限一次：先限幅再记账保证账本里积分的速度就是真实输出速度；修正后的二次限幅保证 PC 不会把速度推出执行器能力之外。把 pc_on 关掉对比运行，你能看到主手从收敛变成打满限幅的极限环，这是本章最值得亲手做的实验。

片段 2：从手跟踪 + 力偏置维护

class SlaveSide:
    """从手：位置跟踪 + 接触力测量与偏置维护（力反馈信号源）。"""
    def __init__(self, k_env=2e4, x_wall=0.03, dt=1e-3, track_rate=0.15):
        self.k_env, self.x_wall, self.dt = k_env, x_wall, dt
        self.track_rate = track_rate     # 位置内环跟随速度(一阶近似)
        self.x = 0.0
        self.f_bias = 0.0                # 力零点偏置
        self.still_t = 0.0

    def step(self, x_m_delayed, v_cmd):
        # 位置内环：一阶跟随延迟后的主手位置；真机上是伺服环
        self.x += (x_m_delayed - self.x) * self.track_rate
        # 环境接触力：只算单向接触（墙不会拉住工具）
        f_raw = self.k_env * (self.x - self.x_wall) if self.x > self.x_wall else 0.0
        # 偏置维护：无接触且运动缓慢时慢速归零，防止“空气里也报力”
        if f_raw < 1.0 and abs(v_cmd) < 0.01:
            self.still_t += self.dt
            if self.still_t > 0.5:
                self.f_bias += (f_raw - self.f_bias) * self.dt / 5.0
        else:
            self.still_t = 0.0
        return f_raw - self.f_bias

解读：从手这段代码承担"环境代理"的角色，三个细节都对应真实工程问题。（1）位置内环用一阶跟随近似（每周期走 15% 的剩余误差），它引入的相位滞后本身就是主从回路的一部分，真机上伺服环越快，可用的 kf 越大。（2）偏置维护的门控条件是"无接触且几乎不动"：运动中的惯性力不能进偏置，否则高速运动后偏置被污染。（3）偏置虽然简单，却是能量审计的隐形杀手：若偏置让自由段报出 2 N 的"假接触力"，主手会被这股力持续推开且无法到达目标，用户报告的现象是"不动它，主手自己被吸着走"。所以每次换工具后都应先跑一段空载标定。

片段 3：有/无 PC 的对比仿真

from collections import deque

def teleop_sim(pc_on, tau=0.03, t_end=3.0, dt=1e-3, kf=1.0):
    """主手导纳 + 30ms 下行(位置) + 30ms 上行(力)：观察末段振荡。"""
    port = AdmittanceReflectionPort(kf=kf, pc_on=pc_on, dt=dt)
    slave = SlaveSide(k_env=5e3, dt=dt)   # 中等刚度环境，失稳但不至于飞车
    nd = int(tau / dt)                    # 单程 30 ms 缓冲
    x_buf = deque([0.0] * nd, maxlen=nd)  # 下行：主手位置
    f_buf = deque([0.0] * nd, maxlen=nd)  # 上行：从手力
    x_m, v_hist = 0.0, []
    for k in range(int(t_end / dt)):
        f_r = f_buf[0]                    # 延迟后的反射力
        v_m = port.step(5.0, f_r)         # 操作者恒定推 5 N
        x_m += v_m * dt
        f_meas = slave.step(x_buf[0], v_m)
        x_buf.append(x_m)                 # 入队等待延迟读取
        f_buf.append(f_meas)
        v_hist.append(v_m)
    tail = v_hist[int(2.5 / dt):]         # 末段 0.5 s
    return np.ptp(tail), port.e_r + 0.0

for flag in (True, False):
    amp, e = teleop_sim(flag)
    print(f"pc_on={flag}  末段速度峰峰值={amp*1000:7.2f} mm/s")
amp_on, e_on = teleop_sim(True)
print(f"仿真结束时账本余额: {e_on:+.4f} J")

解读：脚本让主手在恒定 5 N 推力下撞向 5×103 N/m 的墙，观察 60 ms 往返时延的效应。关掉 PC 时，延迟的反射力与主手速度错相成"泵"，主手在 ±0.5 m/s 的限幅之间来回撞，末段峰峰值约 670 mm/s；打开 PC 后，每次"泵入"都被即时烧掉，主手稳定收敛、全程最大速度降到约 0.17 m/s。注意打印的账本余额是"烧完后的残值"：PC 工作正常时它始终贴着零，你想检查的恰恰是触发日志，若账本长期为正不归零，说明 PC 没在被触发（符号或门限有错）；若主手在接触前就"发涩"，则是门限太低、噪声在触发 PC。把 tau 拉到 0.1 s 再跑，PC 版依然有界（代价是手感变"黏"、透明性打折），这正是 TDPA"用透明性换稳定性"的可控折衷。

常见坑

  • 账本与修正方向写反：Fapp 少一个负号、或把"逆着泵的方向加阻尼"写成"顺着"，会出现两种相反的故障，PC 从不触发（振荡原样出现）或 PC 变成"加油器"（振荡迅速发散）。修复：先做"无时延自检"（良性系统里 PC 应几乎不触发），再对触发瞬间打印 fapp 与 v 的符号，确认"力与速度同向时账本增加"。
  • PC 门限过低：0.1 N 就触发修正，噪声方向上的修正量巨大（α ∝ 1/F²），主手在接触前就开始"发涩"。修复：门限 0.5 N 起步，配合力信号前置滤波。
  • 修正后又把速度打回原值：实现时写成 self.v = v_new 之前又叠加了未修正的加速度积分，代理器层面"烧了能量"、状态层面又还回去。修复：修正值必须写回状态并使用到下一周期。
  • 只对主手做审计：严格的无源性要求审计整个两端口；只做单端是工程折衷，需要配合从侧自己的力限幅与位置限幅，否则从侧撞击的瞬时能量可能绕过审计。
  • 用未滤波力做审计：力噪声在每个周期都贡献微小功率，长期单向偏置（如偏置漂移）会让账本缓慢"漏水"，误触发 PC。修复：审计用与反射同一路已滤波信号，并对账本加速度死区（|P| 小于 0.05 W 不记账）。

练习与思考

  1. 推导 PC 修正公式：设账本 Er > 0（通道在向主手泵能量），取修正速度 Δv = −αFapp，求使修正后能量变化恰好抵消账本的 α。说明 α 的量纲与修正方向的物理含义。★
    提示
    本周期能量变化 ≈ Δt·Fapp·Δv + Er = 0，得 α = Er/(Δt·Fapp²)；量纲为 (m/s)/N，即导纳。方向为"逆着被泵的方向"，阻尼才能做负功。
  2. 用片段 3 把 kf 设成 0.3 与 1.0 各跑一遍（PC 开启），比较末段速度峰峰值。解释 kf 为什么既是透明性旋钮又是稳定性旋钮。★★
    提示
    kf 直接乘在延迟的反射力上，回路增益随 kf 线性放大；TDPA 把 kf=1 的振荡压住，因此可以两者兼得，但代价是 PC 触发更频繁、手感略"黏"。
  3. 把账本定义改成"扣除导纳自身耗散"的版本：E′ = Eobs + ∫Dmv²dt，重跑仿真并解释为什么 E′ 比 Eobs 更严格（也更容易触发 PC）。★★
    提示
    导纳自身的阻尼耗散是"合法收入"，不记入会延迟发现透支；记入后审计更灵敏，但在强阻尼参数下 PC 会更频繁触发，这是在"少误报"和"早报警"之间的工程取舍。
  4. 推导能量视角下"延迟造能量"的微观机制：取主手做简谐运动 v(t) = v0cos(ωt)，反射力有延迟 Fr(t) = Kex(t−τ)。计算一个周期内 ∫Frv dt，证明它非零且符号取决于 ωτ，并求出"注能最严重"的 ωτ。★★★
    提示
    用 cos(ωt)cos(ω(t−τ)) 积化和差，得周期平均功率 ∝ sin(ωτ)/2；ωτ = π/2 时注能最大（注意这是"乘积"条件：τ = 100 ms 时对应约 2.5 Hz；第 045 章"5 Hz/100 ms"是另一类危险组合，对应 ωτ = π 的相位边界，不是注能峰值），ωτ = 0 或 π 时均值为 0。
  5. 比较两条路线的失效模式：假设链路出现 10% 丢包，波变量方案与 TDPA 方案各会怎样退化？给出各自的兜底措施。★★
    提示
    波变量：丢包等价于少送一段入射波，能量只会变少，仍无源，表现为时断时续的"空格感"；TDPA：丢包造成力/位置信号阶跃，可能瞬时透支，需要 PC 处理 + 序号检测重发上一包。

小结

  • 导纳式遥操作采用 P-F 架构：主手导纳把力差变成位置命令，从手跟踪位置并回传接触力；kf 调节透明性。
  • 时延的破坏作用是"能量审计错账"：延迟的反射力会在错误的时间对主手做功，向系统注入能量。
  • PO 跟踪反射力对主手的累计做功 Er；Er > 0（通道在泵能量）时按 α = Er/(Δt·Fapp²) 逆着反射力加阻尼、精确烧掉泵入能量，其余时段零干预。
  • 与波变量路线对比：TDPA 不改造信号语义、透明性上限更高，但审计正确性依赖力信号质量与符号约定。
  • 工程防护：PC 门限、速度状态限幅、"修正写回状态"、从手偏置维护，缺一不可。
