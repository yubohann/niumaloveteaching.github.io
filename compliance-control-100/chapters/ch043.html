第二篇 · 参数调节与交互任务

第 043 章：阻抗控制在人机协作中的应用

当交互对象从工件换成活人，评价控制器好坏的标准就从"磨得匀不匀"变成"安不安全、顺不顺手"。本章讲清楚一个核心问题：机器人的阻抗参数取多大才不会和人的手臂"顶起来"，以及协作任务里怎么按阶段调度刚度。

  • 主题：物理人机协作（pHRI）/ 耦合稳定性
  • 关键公式：Mrẍ + Drẋ + Kr(x−xd) = Fh，配合人手阻抗 Mhẍ + Dhẋ + Kh(x−xh) = −Fh
  • 预计学时：55 分钟
  • 前置章节：第 042 章（阻抗控制在打磨中的应用）

学习目标

  • 区分人机协作中的两类物理接触：安全型接触（意外碰撞）与意图型接触（协同搬抬、手把手示教），并说明为什么本章只谈后者。
  • 会把人的手臂建模成阻抗源，写出"人-机器人"耦合闭环方程，并解释为什么机器人刚度越高越容易激起振荡。
  • 掌握时延预算规则：把力传感滤波、内环跟随全部折算成总时延 τ，用 ωn·τ ≤ 0.3 rad 做稳定性初筛。
  • 会设计两档（或多档）变阻抗协作策略：自由段软、任务段硬，变化率受限、阻尼同步重算。
  • 能写协作安全速度缩放的代码，并说明"距离减速"和"力减速"两个通道各自的物理依据。

背景与动机

协作机器人（cobot）与工人共享工作空间时存在两类物理接触。第一类是意外碰撞：人无意中撞到机器人，控制器要在几毫秒内做出反应，这是第 096、097 章的主题。第二类是意图型接触：人主动抓住机器人一起搬零件、扶着手臂做示教，这种接触不但不该被"急停"，还要被控制器温柔地接住并顺着人的意图走，本章讲的正是这一类。

意图型协作的难点在于：交互回路由两台"阻抗"串联而成，人的手臂是一个活的组织，刚度、阻尼随肌肉紧张程度变化；机器人是另一个可控阻抗。两个阻抗串在一起，若机器人在交互频段表现得又硬又轻，就会和人的手"顶"起来，出现 20–30 Hz 的高频抖动甚至力失控。所以本章要建立一套"看人下菜"的参数设计逻辑，"把刚度调大调小"只是其中一步。

核心原理

1. 把人手臂建模成阻抗源

人的手臂在低速交互时可以用一个二阶阻抗很好地近似（神经肌肉产生的力由"肌肉弹簧+黏性+惯性"决定）：

Mhẍ + Dhẋ + Kh(x − xh) = −Fh Mh：手-臂等效质量（约 0.5–2 kg）；Kh：肌肉刚度（放松约 200 N/m，用力可达 1000 N/m）；xh：人的"意图位置"

其中 Kh 是最有意思的参数：人手在放松时像软弹簧（约 200–500 N/m），一旦人"紧张地把住"机器人，刚度能到 1000 N/m 以上、阻尼 Dh 也在 20–60 N·s/m 之间变动。这意味着评判机器人稳定性的"环境"本身是活的、会变的，不可能像对固定工件那样一次性算准，只能用保守裕度去覆盖最坏情况。

2. 耦合闭环与"刚度比"直觉

设人的手和机器人末端刚性耦合在同一位置 x，把两个阻抗方程联立：

(Mr + Mh)ẍ + (Dr + Dh)ẋ + (Kr + Kh)x = Krxd + Khxh 理想无时延下：两个刚度和阻尼直接相加，永远稳定；危险全部来自"未建模动态"，时延与滤波滞后

理想情况当然稳定，但现实中机器人这一侧有三处滞后：力传感器滤波（几毫秒）、通信/内环位置跟随（几毫秒到几十毫秒）、控制周期离散化。把全部滞后折算成总时延 τ 后，闭环特征方程变为 e−sτ 因子，在交越频率 ωg 附近增加 −ωgτ 的相位滞后。经验判据：

ωn · τ ≤ 0.3 rad，其中 ωn = √((Kr+Kh)/(Mr+Mh)) 总时延 τ 包括采样、滤波、内环跟随；超过 0.3 rad 时相位裕度通常不足

代入典型数字：Mr = 2 kg、Mh = 1 kg、Kh = 300 N/m，τ = 16 ms。若 Kr = 600 N/m，ωn ≈ 18 rad/s，ωnτ ≈ 0.29 rad，恰好压在边界内；若 Kr = 12000 N/m，ωn ≈ 64 rad/s，ωnτ ≈ 1.0 rad，远超 0.3，接触后必然持续高频抖动。工程直觉：协作场景里"刚度上限"由时延预算决定，与"力够不够大"无关。

3. 按任务阶段调度刚度：自由段软、任务段硬

单一刚度很难同时讨好"安全接近"与"任务精度"。合理策略是按阶段调度：

  • 接近/空载段：Kr 取小（约 300 N/m），机器人"软而顺"，任何误碰都不会产生大力量；
  • 协作任务段（已确认意图型接触）：Kr 升到 800–1200 N/m，提供任务所需的位置精度与力分辨率；
  • 脱离段：先降刚度再退出，避免"抽搐式"脱手。

但变刚度有个物理代价：刚度突然升高时，存在虚拟弹簧里的能量 ½K x² 会突变。设 x = 10 mm，K 从 300 跳到 1200 N/m，储能从 0.015 J 跳到 0.06 J，多出的 0.045 J 若没有阻尼吸收，会转成机器人动能，0.045 J 对 2 kg 的等效质量相当于 0.21 m/s 的速度突变。所以变刚度必须限速率、并且同步增大阻尼（第 053、058 章会把这条"无源性"要求推导完整）。

4. 安全速度缩放：两个通道

协作速度整定（speed and separation monitoring 的简化版）要求速度上限随两个量减小：与人距离（越近越慢，留出制动距离）和交互力（力越大越说明接触在强化，越要减速确认）。形式上取两个限幅的较小者：

vmax = min{ κd(d − dstop), v0(1 − |Fh|/Ffull) } d：与人的最短距离；dstop：安全停距（如 0.15 m）；Ffull：触发最低速度的力（如 40 N）

第一个通道来自运动学（制动距离），第二个通道来自交互动力学（力大→意图不明确或危险）。两个通道都做"只减速不加速"的单侧限幅，绝不能因为"力很小"而把速度放大，安全通道只允许做减法。

实现思路与设计

协作单元的软件结构分四层，从外到内：

  1. 状态判定层：用交互力大小、变化率、机器人与人的距离，判定"接近/任务/脱离"阶段，输出目标刚度档位。判定加 200 ms 滞回，避免在阈值附近来回跳。
  2. 变阻抗调度层：由当前档位平滑过渡到目标刚度，速率限幅（如 2000 N/(m·s)，即 900 N/m 的跨度至少走 0.45 s），每一步同步重算阻尼 Dr = 2√(KrMr)。
  3. 阻抗控制层：与第 001 章相同的离散积分结构，输入为力传感器读数（经滤波）。
  4. 安全层：速度缩放 + 绝对力上限（超过 60 N 直接柔顺停，第 098 章展开）。
设计决策：为什么协作场景的阻尼比取 ζ ≥ 1？

机器人单独运行时 ζ = 0.7 的手感已经够用，但和人耦合后还要加上人的阻尼与刚度，用"人的最松/最紧"两种极端各验一遍。取 ζ = 1（临界阻尼）让机器人一侧始终"偏黏"，多出来的阻尼会掩盖时延带来的相位损失，这是协作场景的保守做法；代价是自由运动时略"沉"。

关键代码与解读

片段 1：人-机器人耦合闭环仿真（含总时延）

import numpy as np
from collections import deque

def coupling_test(k_r, m_r=2.0, tau_ms=16.0, t_end=3.0, dt=1e-3):
    """人(阻抗源)+机器人(阻抗控制)刚性耦合闭环。
    tau_ms 把力传感滤波、内环跟随与阻抗力生成的滞后折算成总时延；返回末段振幅(mm)。"""
    d_r = 2.0 * np.sqrt(k_r * m_r)          # 机器人偏黏：zeta=1 抗时延
    k_h, d_h, x_h = 300.0, 30.0, 0.02       # 人：K_h=300 N/m，意图位置 +2 cm
    nd = max(1, int(tau_ms * 1e-3 / dt))    # 时延拍数
    x = x_cmd = v_cmd = 0.0
    x_buf = deque([0.0] * nd, maxlen=nd)    # 机器人“看到”的自身位置(延迟)
    v_buf = deque([0.0] * nd, maxlen=nd)    # 自身速度同样延迟：弹簧阻尼都慢半拍
    xs = []
    for _ in range(int(t_end / dt)):
        # 机器人阻抗：M ẍ + D ẋ + K x = F_h（取交互力使机器人前进为正的约定）；
        # 自身的弹簧-阻尼力用延迟状态计算，高刚度+时延失稳正是从这里长出来的
        a_cmd = (k_h * (x_h - x) - d_h * (x - 0.0)
                 - d_r * v_buf[0] - k_r * x_buf[0]) / m_r
        v_cmd += a_cmd * dt
        x_cmd += v_cmd * dt
        x += (x_cmd - x) / 0.008 * dt       # 内环位置环 8 ms 一阶滞后
        x_buf.append(x)                     # 延迟状态入缓冲，等待被读出
        v_buf.append(v_cmd)
        xs.append(x)
    return np.ptp(xs[-500:]) * 1000         # 最后 0.5 s 峰峰值(mm)

for k_r in (300.0, 600.0, 3000.0, 12000.0):
    print(f"K_r={k_r:7.0f} N/m  末段振幅 {coupling_test(k_r):8.3f} mm")

解读：这段代码想让你亲手看到三个现象。（1）刚度越高越难稳定：Kr 从 300 扫到 12000，300–3000 档几个往返就收敛（末段振幅接近零），约 4000–4500 附近出现稳定临界，越过后末段振幅指数放大；可以自己精扫出这个阈值，并用 ωnτ ≤ 0.3 的保守判据核对量级（仿真阈值对应 ωnτ ≈ 0.6）。（2）时延是罪魁：把 tau_ms 减半再跑，阈值会明显上移（16 ms 档约 4300 N/m，压到 8 ms 后升到 1.5 万 N/m 以上），这解释了为什么协作机器人要做低延迟力接口。（3）阻尼在兜底：把 d_r 改成 0.3 倍临界阻尼再跑，小刚度档就出现 0.4 mm 量级的残余振荡、中等刚度直接失稳，这正是"协作机器人又硬又轻"的经典故障。

片段 2：带速率限制的变阻抗调度

class SafeStiffness:
    """两档协作刚度：自由段 300 N/m，任务段 1000 N/m。
    刚度变化率限幅 + 阻尼同步重算，保证切换过程不注入能量。"""
    def __init__(self, m_r=2.0, rate_max=2000.0, dt=1e-3):
        self.m_r, self.rate_max, self.dt = m_r, rate_max, dt
        self.k = 300.0
        self.d = 2.0 * np.sqrt(self.k * self.m_r)   # 初始临界阻尼
        self.timer = 0.0                            # 任务段驻留计时(滞回用)

    def update(self, task_flag, f_int):
        # 判定任务段需要“接触持续时间”：单帧力大不算，连续 0.2 s 才算
        self.timer = self.timer + self.dt if task_flag else 0.0
        k_target = 1000.0 if self.timer > 0.2 else 300.0
        # 速率限幅：K 突变会让虚拟弹簧的储能 ½Kx² 跳变、变成动能
        dk = float(np.clip(k_target - self.k,
                           -self.rate_max * self.dt, self.rate_max * self.dt))
        self.k += dk
        self.d = 2.0 * np.sqrt(self.k * self.m_r)   # 阻尼同步，zeta 恒为 1
        return self.k, self.d

解读：为什么用"连续 0.2 s"确认？瞬时阈值会怎样？人手在自由段也可能瞬间碰到 5 N 的力（如整理姿态时的轻擦），如果立刻升刚度，机器人会突然变硬、把人吓一跳。驻留计时相当于一个意图确认窗口。为什么阻尼每次重算？临界阻尼公式 D = 2√(KM) 是 K 的函数，K 变了不同步更新 D，ζ 就漂到 0.3 以下，切换瞬间出现振荡，这是变阻抗实现里最容易漏的一步。最后注意 rate_max：900 N/m 的跨度以 2000 N/(m·s) 变化需要 0.45 s，这个"慢半秒"就是换来的安全性。

片段 3：协作速度双通道缩放

def safe_velocity(v_nom, d_human, f_int, v_max=0.25):
    """协作速度缩放：距离通道 + 力通道，只允许减速、不允许加速。"""
    d_stop, d_range = 0.15, 0.35        # 安全停距 15 cm，减速作用半径 50 cm
    f_full = 40.0                       # 交互力达到 40 N 时降到最低速
    # 通道 1：制动距离约束 v^2/(2a) 的线性化：距离越近速度上限越低
    v_by_dist = v_max * np.clip((d_human - d_stop) / d_range, 0.0, 1.0)
    # 通道 2：力越大说明接触越强/意图越不明，同样限速(保底 10%)
    v_by_force = v_max * np.clip(1.0 - abs(f_int) / f_full, 0.1, 1.0)
    # 取两通道最小者，再对名义速度只做“向下的裁剪”
    return float(np.clip(v_nom, 0.0, min(v_by_dist, v_by_force)))

解读：两个通道的物理依据不同，距离通道来自"制动距离必须小于剩余间距"，力通道来自"接触强度是意图与危险的综合指示"。代码里的 np.clip(v_nom, 0.0, ...) 保证安全层只做减法：即使 d_human 异常大、力异常小，也绝不把 100 mm/s 的名义速度放大到 250 mm/s。真机上还有一个实践细节：d_human 通常来自视觉/深度相机，刷新率只有 10–30 Hz，必须做"最坏情况外推"（假设人持续靠近）后再送进这里，否则两帧之间的盲区会让减速滞后。

常见坑

  • 又硬又轻的"抖动症"：Kr 调得很高追求精度，Dr 只按 ζ = 0.5 配，人一握手就出现 20–30 Hz 嗡嗡抖动。修复：按 ζ ≥ 1 配阻尼，再用 ωnτ ≤ 0.3 复核刚度上限。
  • 把人的慢速接触当碰撞急停：碰撞检测阈值调得太敏感，工人正常扶着机器人就被断电，协作体验极差。修复：分离"意图检测"与"碰撞检测"两套通道（力变化率+持续时间判意图，第 096 章展开）。
  • 时延预算只算了控制周期：忘了力传感器滤波（2 阶 40 Hz ≈ 5 ms 群延迟）和内环跟随（8–20 ms），实际 τ 是估算值的两三倍，按 5 ms 校核的刚度全部偏硬。修复：用"关掉滤波看抖动是否收敛"的现场实验反推实际 τ。
  • 变刚度不做速率限制：切换瞬间储能跳变、机器人"抖一下"，本质是能量注入。修复：限 dK/dt，阻尼同步升高；连续两次切换间隔不小于 0.2 s。
  • 安全速度层允许加速：代码写成 v = v_max·(1−|F|/Ffull) 并直接输出，力很小时反而超过名义速度。修复：安全层永远只做单侧裁剪。

练习与思考

  1. 推导耦合闭环方程：把人的阻抗方程代入机器人阻抗方程（刚性耦合、同一位置 x），写出等效质量、阻尼、刚度，并解释为什么"理想无时延下永远稳定"。★
    提示
    两式相加消去 Fh：(Mr+Mh)ẍ+(Dr+Dh)ẋ+(Kr+Kh)x = Krxd+Khxh。系数全正 → 特征根实部全负。
  2. 用片段 1 扫描 Kr ∈ [300, 15000]，找到"末端振幅超过 0.5 mm"的临界值，与公式 ωnτ ≤ 0.3 rad 的预测对比。再把 tau_ms 从 16 改到 32，看临界值怎么变。★★
    提示
    把每档 Kr 代入 ωn=√((Kr+300)/3) 算出预测临界值，与仿真对照。τ 翻倍后临界刚度大约降到 1/4（因为 ωn ∝ √Kr）。
  3. Dr 只取临界阻尼的 30%，重跑 Kr = 3000 的耦合仿真，记录振幅变化；再用能量视角解释"欠阻尼为什么放大了时延的影响"。★★
    提示
    欠阻尼时每个振动周期耗散的能量少；时延每周期注入的扰动能量不变，耗散不够就逐周期累积放大。
  4. 设计一个三档协作策略：接近（200 N/m）、协作搬运（800 N/m）、精调（1500 N/m），给出每档的阻尼、切换条件（力/速度/时间）、速率限制，并逐档用 ωnτ ≤ 0.3 检验（τ 自定，说明理由）。★★★
    提示
    先算每档 ωn = √((Kr+Kh)/(Mr+Mh))，再看 τ 允许多大；1500 N/m 档若通不过，就要么减 τ（提高力环采样率）、要么把该档的 Mr 调大（ωn 降下来）。
  5. 安全速度函数的距离通道目前是线性的。改成"vmax = √(2a(d−dstop))"（匀减速制动距离的精确式），比较两种曲线在 d = 0.2–0.5 m 的差异，并说明为什么工程上常用线性化版本。★★
    提示
    精确式在近距更保守、远距更宽松；线性版计算简单、参数直观，且可以用最坏情况加速度 a 统一覆盖，安全性不依赖距离估计的精度。

小结

  • 意图型协作中，人手臂是一个可变的二阶阻抗（Kh 200–1000 N/m、Dh 20–60 N·s/m），机器人必须在"人能给出的最坏参数"下保持稳定。
  • 理想耦合（两阻抗相加）永远稳定；真正的不稳定源是时延与滤波滞后。经验判据：ωnτ ≤ 0.3 rad 决定协作刚度上限。
  • 协作场景取 ζ ≥ 1，用"偏黏"的阻尼吸收相位损失；刚度、阻尼必须成对设计。
  • 变阻抗按阶段调度，且速率受限、阻尼同步重算，瞬变刚度会注入能量。
  • 速度安全双通道（距离、力）都只做减速裁剪，这是协作安全设计的底线逻辑。
  • 下一章换一条实现路线：当机器人只有位置接口、力来自力传感器时，同样的协作需求将由导纳控制来承担，手感参数的含义会变成"虚拟质量与阻尼"。
