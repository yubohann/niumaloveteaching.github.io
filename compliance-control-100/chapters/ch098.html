第五篇 · 鲁棒控制与工程实践

第 098 章：阻抗控制中的安全停止

碰撞检测说出了"有意外"，接下来的问题是"怎么停下来"。断电急停会让机器人失控滑行，瞬时位置锁定会硬砸在工件上，柔性机器人的正确停法是一段受控的减速曲线：限加加速度、保阻抗、限力，然后以"带电的柔顺保持"站在安全区里，等待人工确认。

  • 主题：安全停止（protective stop）/ 停止轨迹与状态机
  • 关键公式：d停 = v·t反应 + v²/(2amax) + d裕量，amax ≤ Fmax/m
  • 预计学时：60 分钟
  • 前置章节：第 097 章

学习目标

  • 理解"安全停止"与"断电急停"的本质区别：前者保留驱动与柔顺控制，减速过程可控；后者放弃控制，让惯量自由滑行。
  • 会推导并核算停止距离预算 d = v·t反应 + v²/(2amax) + 裕量，并用力约束 amax ≤ Fmax/m 选择减速度。
  • 理解减速曲线为什么要限加加速度（jerk），阶跃减速会带来什么代价，以及"停止期间必须保持阻抗"的原因。
  • 会设计安全停止状态机：NORMAL → DECEL → HOLD → REARM，含故障锁存与人工确认，理解每个转移的触发条件。
  • 能说清安全停止与下一章紧急回退的分工：本章"原地停下并保持柔顺"，回退负责"物理上离开障碍物"。

背景与动机

第 097 章的碰撞检测在几毫秒内给出了事件，但事件之后的几百毫秒谁来负责？这是安全体系里最容易被忽视的一段：最危险的时刻往往不在碰撞发生的那 3 ms，而在随后"怎么处理"的 200 ms。工程上有三种选择，各自的作用与误区：

  • 断电急停：切断动力。对高速运动的大惯量轴，机器人会带着全部动能滑行，停在哪里、压到什么完全听天由命；对有力控任务的机器人，断电瞬间所有补偿失效（重力补偿也没了），工具可能"砸"下来。只应作为最后防线。
  • 瞬时位置锁定：把当前位置冻结为硬目标。听起来最果断，但它把"减速"这一步从"受控"变成"硬刹"，位置环会瞬间给出巨大的速度/力矩指令，在最脆弱的接触状态下制造力尖峰，甚至激发机械共振。
  • 受控减速 + 柔顺保持（本章方法）：让机器人沿一段限加加速度的减速曲线把速度降到零，其间阻抗照常工作（让"停不下来的部分"由柔顺吸收），停稳后用"带电的柔顺保持"守住位置，等待处理。这就是"安全停止"：它不追求停得最狠，而追求停得最不伤人、不伤件。

本章把安全停止做成一个能被审计的状态机：谁触发、按什么曲线减速、停在哪、为什么还带电、什么时候允许恢复，每个问题都有一个明确的答案，"检测到碰撞就断电"这种看似安全实则危险的默认行为被彻底排除。

核心原理

1. 停止距离：三段预算一条公式

从"碰撞发生"到"完全停下"，机器人的行程由三段组成：

d停 = v·t反应 + v²/(2amax) + d裕量 t反应：从事件发生到减速开始（观测器检测 + 通信 + 计算，本章按 3–10 ms）；d裕量：安全余量（5–20 mm，按标定误差与工艺抖动给）

第一段是"反应期"，检测（第 097 章的 t = (1/Ko)ln(Δ/(Δ−th))）+ 数据链路 + 决策；这段期间机器人按原速前进。第二段是"减速期"，以减速度 amax 把动能吃掉。第三段是给不确定性留的净空。工程直觉：停止距离实质是一份设计预算，并不只是"刹车性能"，工作空间的规划必须为每个方向预留 d停；预留不够时，正确的做法是降低速度（速度是平方项，降一半速度，减速段距离降为 1/4），不能指望"检测得更快"。

减速度 amax 不是随便取的，它受两个约束：（1）力约束，减速需要力 F = m·a，如果机器人在接触中，这份力会变成接触力增量，所以 amax ≤ Fmax/m（Fmax 是与工件的许用力或安全接触力限值的较小者）。例如 2 kg 等效惯量、允许 15 N 的接触力增量，则 amax ≤ 7.5 m/s²。（2）机械约束，减速引起的关节力矩不应触发过载，也尽量落在"不影响寿命"的区间（一般取额定力矩的 50–70%）。两个约束中更小的那个决定了减速能力，再代入距离公式。

2. 为什么必须限 jerk：阶跃减速的两个代价

让减速度从 0 阶跃到 amax，数学上停止距离最短；工程上却会付出两个代价：（1）加速度的阶跃意味着力的阶跃，机械系统的响应对阶跃的"振铃"（弹性、间隙、未建模动态）会在工件接触处被放大，停稳之后力曲线还在振荡；（2）减速指令与阻抗相互作用时，阶跃参考会激发控制器的瞬态响应（相当于给系统一个冲击输入）。限加加速度（jerk-limited，S 形减速）把 a 的变化率限制在 jmax（典型 20–100 m/s³），这只增加十几到几十毫米的停止距离，却把力尖峰压掉大半。

a(t)：0 → amax 以斜率 jmax 过渡，减速段延长的距离 ≈ v·amax/(2jmax) 例：v = 0.5 m/s、amax = 4 m/s²、jmax = 50 m/s³ ⟹ 额外约 19 mm（换成 jmax = 10 则约 74 mm）

这个近似只在"从零到满减速的时间 amax/jmax 相对整个减速过程不可忽略"时才有意义，所以工程上更稳妥的做法是把 jerk 段直接算进预算：在仿真里生成限幅曲线、量出真实停止距离（本章代码片段 2 就是这样做的），不能只背近似公式。jmax 的选择就是"用几毫米距离换多少力尖峰"的加权，典型区间 20–100 m/s³。

3. 停止期间保持阻抗：让"动能残留"有地方去

受控减速开始时，机器人往往已经和工件接触（这正是触发停止的常见场景）。此时有两种错误的直觉：把阻抗调硬（"这样停得更准"）或把阻抗调软到底（"这样最安全"）。正确做法是保持原阻抗参数，只把参考轨迹的速度部分收敛到零。理由：

  • 阻抗调硬 → 位置误差被放大成大力，工件的许用应力可能被突破，这正是"安全停止"要避免的；
  • 阻抗调软到底 → 机器人在自重、残余动量下"陷进"工件，停止距离不可控，还可能引发漂移；
  • 保持阻抗 → 残余动量由虚拟阻尼吸收，接触力沿设计好的柔顺曲线衰减，停稳后的力由 Kd 与残余偏移决定（第 001 章的稳态公式）。

停止完成后的"柔顺保持"同样重要：位置冻结成一个新的参考 xhold（取停稳时刻的位置），阻抗继续带电运行。这样即使操作员推动机器人或工件微动，力也不会积累成静载；同时保持带电也意味着重力补偿、限力、监控全在岗位上，这正是协作机器人规范里"安全等级监控停止"想要的行为。工程直觉：安全停止的目标状态是"像一根有阻尼的弹簧一样待命"，与"僵住"完全不同。

4. 状态机与再使能：安全的一半是"怎么恢复"

状态集：NORMAL（正常）、DECEL（受控减速）、HOLD（柔顺保持）、FAULT（锁存故障，等待人工）、REARM（准备恢复）。转移的要点：

  • NORMAL → DECEL：任一保护事件（第 096/097 章、限位、看门狗、通讯超时）触发；记录"触发原因 + 时刻 + 方向"。
  • DECEL → HOLD：速度降到阈值（|v| < 5 mm/s）并持续 100 ms（防"过零抖动"）。
  • DECEL → FAULT：减速期间发生第二事件、或检测到力超限、或减速超时未停（说明参数不对）。重度碰撞应在检测时就直接进入 FAULT 并交给第 099 章的紧急回退。
  • HOLD → REARM：必须在确认安全后（见下），不允许"等一秒自动恢复"这种看似流畅实则危险的设计。
  • REARM → NORMAL：机器人缓慢回到任务轨迹（低速重入），期间任何事件都立即退回 DECEL。

恢复条件的设计原则：不同触发原因配不同的恢复门槛。限位触发可以自动回退一步后自动恢复；轻度过力可以人工确认后恢复；碰撞事件必须人工到现场确认，因为"碰撞为什么发生"这个信息只有人能判断（工件移位？操作员进入？程序错？）。再使能前建议自动执行一次自检：力零点复核（第 091 章）、观测器残差归零检查、路径上是否仍有障碍（用低速探测）。

实现思路与设计

  1. 定义停止参数：按 Fmax/m 与机械约束取 amax（示例 2–4 m/s²）；jmax = 20–100 m/s³；vstop = 5 mm/s；HOLD 判定驻留 100 ms。
  2. 计算预算：对每段任务轨迹算 d停（含反应时间 3–10 ms），检查工作空间各向裕量；不满足就降速（平方收益）。
  3. 减速参考生成：从触发时刻的位置/速度出发，生成 jerk 限幅的速度参考；位置参考按积分得到；不改动阻抗参数，只把参考收敛到零速度。
  4. 保持层：进入 HOLD 时把当前实测位置写成 xhold，阻抗方程继续运行（力、重力补偿、限力全开）。
  5. 故障锁存与确认：FAULT 需要显式复位；复位动作包括原因显示、现场检查清单、自动自检。
  6. 重入：REARM 阶段用 20–50 mm/s 的低速回到轨迹；任何事件立即重新 DECEL；重入期间的阻抗柔顺降低一级（Kd × 0.5）以进一步降低碰撞后果。
设计决策：为什么"保持带电"比"断电"更安全？

断电直觉上最安全，但柔顺机器人断电会同时失去三样东西：重力补偿（关节在工具重力下缓慢下坠）、限力能力（电机不再"顶"住外力，人可以推着跑）、监控与检测（没有编码器/电流环，无从知道发生了什么）。协作机器人（其安全概念建立在"力与速度受限"之上）断电后反而变成"无力但有大惯量的自由物"。所以正确的层级是：安全停止（保留控制、受控减速、柔顺保持）是第一道；断电急停只留给"停止逻辑本身失效"的极端情形，这也是为什么真正的安全系统里，急停回路的可靠性与停止逻辑的可靠性是分开认证的。

关键代码与解读

片段 1：安全停止状态机

import numpy as np

class SafeStopFSM:
    """安全停止状态机：NORMAL/DECEL/HOLD/FAULT/REARM 与故障锁存。"""
    def __init__(self, dt=1e-3, v_stop=0.005, hold_dwell=0.1):
        self.dt, self.v_stop, self.hold_dwell = dt, v_stop, hold_dwell
        self.state = "NORMAL"
        self.timer = 0.0
        self.reason = ""
        self.x_hold = None

    def trigger(self, reason, severe=False):
        """保护事件入口：severe 事件直接锁存故障（交给第 099 章回退）。"""
        if self.state == "NORMAL":
            self.state, self.timer, self.reason = "DECEL", 0.0, reason
        if severe and self.state in ("DECEL", "HOLD"):
            self.state = "FAULT"           # 二次事件/重度：升级并锁存
        return self.state

    def update(self, v, x):
        self.timer += self.dt
        if self.state == "DECEL" and abs(v) < self.v_stop:
            self.state, self.timer = "HOLD", 0.0
            self.x_hold = x                 # 停稳点 = 柔顺保持的参考
        elif self.state == "HOLD" and self.x_hold is None:
            self.x_hold = x
        elif self.state == "REARM":
            pass                            # 重入由轨迹层处理，事件随时打断
        return self.state, self.x_hold

    def rearm(self, operator_ok, selfcheck_ok):
        # 恢复需要"人为确认 + 自检通过"两条腿，缺一不可
        if self.state in ("HOLD", "FAULT") and operator_ok and selfcheck_ok:
            self.state, self.timer, self.reason = "REARM", 0.0, ""
            return True
        return False

解读：状态机刻意做得"单调乏味"，这正是安全逻辑的美德。（1）trigger 里 severe 事件直接升到 FAULT，保证重度碰撞直接走回退流程（下一章），不会"停在原地继续等"；（2）进入 HOLD 的条件是"速度低于阈值"，不以"时间到了"为准，前者才是"停稳"的物理判据；（3）x_hold 用实测位置，不用参考位置，柔顺停止的落点是机器人与环境共同作用的结果，参考位置可能还在工件内部；（4）rearm 的双条件把"安全恢复"变成流程，防止软件自动恢复带来的连锁事故。

片段 2：受控减速仿真（jerk 限幅 + 保持阻抗）

def run_stop(a_max=4.0, j_max=50.0, k_d=300.0, v0=0.5, x_wall=0.065,
             m=2.0, n=800, dt=1e-3):
    """机器人以 v0 冲向 x_wall；t=0 触发安全停止，观察停止距离与接触力。"""
    d_d = 2.0 * np.sqrt(k_d * m)          # 保持原阻抗（软），不改参数
    x, v = 0.0, v0
    a_cmd, v_ref, x_ref = 0.0, v0, 0.0
    f_peak = 0.0
    for i in range(n):
        # 减速参考：a 以 j_max 斜率趋近 -a_max，速度到零后钳在零
        a_target = -a_max if v_ref > 0.0 else 0.0
        a_cmd += np.clip(a_target - a_cmd, -j_max * dt, j_max * dt)
        v_ref = max(v_ref + a_cmd * dt, 0.0)   # 到零即保持，避免参考速度反向漂移
        x_ref += v_ref * dt
        f_env = 1e4 * (x - x_wall) if x > x_wall else 0.0   # 墙：单向接触弹簧
        # 阻抗跟踪减速参考：只动参考，不动参数，这是"柔顺停止"的核心
        u = -k_d * (x - x_ref) - d_d * (v - v_ref)
        v += (u - f_env) / m * dt
        x += v * dt
        f_peak = max(f_peak, f_env)
    f_hold = 1e4 * (x - x_wall) if x > x_wall else 0.0
    return x * 1000.0, f_peak, f_hold

for a in (4.0, 2.0):
    x_fin, fpk, fhold = run_stop(a_max=a, k_d=300.0)
    print(f"a_max={a:.1f} m/s^2  停止位置={x_fin:6.1f} mm  峰值接触力={fpk:5.1f} N  保持力={fhold:4.1f} N")
x_fin, fpk, fhold = run_stop(a_max=2.0, k_d=3000.0)
print(f"a_max=2.0 + 硬阻抗(k=3000)  停止位置={x_fin:6.1f} mm  峰值接触力={fpk:5.1f} N  保持力={fhold:4.1f} N")

解读：三组数字各说清一个问题。amax = 4 时参考停点约 50 mm（减速段 31.25 mm 加 jerk 段约 19 mm），柔顺跟踪的超调（要靠位置领先才能产生减速力）让它一度走到约 63 mm，随后被阻尼拉回约 50 mm 的停稳点，全程在 65 mm 处的墙前，峰值接触力为 0；amax = 2 时纯减速段停点 v²/(2a) = 62.5 mm，含 jerk 段后参考停点约 72 mm，越过墙，机器人以约 0.3 m/s 与墙"会合"，峰值力 38 N，随后被阻抗吸能，停稳后以约 2 N 轻顶墙面。把阻抗临时调硬到 3000 N/m 后，同样场景的峰值略降到 27 N（跟踪更紧、接近更慢），但停稳后的保持力从约 2 N 放大到约 16 N，这就是"别硬停"的代价：硬阻抗让停稳后持续顶住工件的力放大 8 倍，而碰撞瞬间的峰值主要由接近速度决定。实现里值得注意：f_env 的写法把"墙"建模成单向弹簧（不接触则为零），这是所有接触仿真的标准细节；减速参考的速度到零后必须钳住（max(v_ref + a_cmd * dt, 0.0)），否则 a_cmd 仍停在 -amax，参考速度会越过零点反向漂移、机器人"停不下来"；x_ref 的积分从当前位置出发，保证停止轨迹与触发时刻无缝衔接（不引入位置跳变）。

片段 3：停止距离预算表

def stop_budget(v_list=(0.1, 0.25, 0.5), a_list=(2.0, 4.0, 7.5),
                t_react=0.005, margin=0.010):
    """列出不同速度/减速度下的停止距离（mm），并给出约束提示。"""
    for v in v_list:
        for a in a_list:
            d = v * t_react + v * v / (2 * a) + margin
            note = ""
            if a * 2.0 > 15.0:               # m=2kg 时 a 超过 7.5 就超 15 N 力预算
                note = " (超力预算)"
            print(f"v={v:4.2f} m/s  a={a:4.1f} m/s^2  d_stop={d*1000:6.1f} mm{note}")

stop_budget()

解读：表格把三个变量（速度、减速度、反应时间）与两个约束（力预算、空间预算）放在一起，便于规划阶段直接取数。注意示例里写死的注释条件 a*2.0 > 15.0 ，它提醒你"力约束来自 m 与 Fmax"，实际工程中应作为参数传入，不能硬编码。使用顺序建议：先从工件允许力与机械约束筛出可行的 amax 列，再对每个任务速度算 d停，最后与工作空间余量对照；若超预算，优先降速（平方收益），其次提高减速度（受力的天花板），最后才考虑缩短反应时间（改动检测与总线，工程量最大）。

常见坑

  • 停止时把阻抗调硬：以为"紧一点停得准"，实际把位置误差放大成大力，工件变形、甚至触发过力保护。修复：减速期间保持原参数，只收敛参考速度；硬度是任务参数，不是安全参数。
  • 忘记反应时间：预算只算了 v²/2a，漏掉检测 + 总线 + 计算（数毫秒）。修复：在预算表里保留 t反应 列，并从实测（第 097 章的检测延迟）取值。
  • 减速超时不停：摩擦力/负载让减速比预期慢，机器人"蹭着不停"。修复：DECEL 增加超时监控（如 1.5 倍理论减速时间），超时转入 FAULT；同时检查负载补偿是否失效。
  • 自动恢复：为了节拍，HOLD 后 1 s 自动回到任务，碰撞原因未查明就继续冲上去。修复：按触发原因分级恢复；碰撞类必须人工确认 + 自检。
  • 把停止当成回退用：碰撞后原地保持，机器人仍"顶"在障碍物上（比如手被夹在机器人和夹具之间）。修复：这种场景的需求是"离开"，"停住"解决不了问题，必须走第 099 章的紧急回退；判断依据是"障碍物是否仍与机器人接触"。

练习与思考

  1. 推导停止距离三段公式：分别写出反应段（匀速）、减速段（等减速）与裕量的表达式，并说明为什么速度减半能把减速段距离降到 1/4。★
    提示
    反应段 d₁ = v·tr（线性），减速段 d₂ = v²/(2a)（平方）；v→v/2 时 d₁ 减半、d₂ 降到 1/4，减速段是主导项。
  2. 用片段 2 的代码，把 j_max 从 50 降到 5、再从 50 升到 500，记录停止位置与峰值接触力的变化，解释 jerk 限制在"距离—力尖峰"之间的取舍。★★
    提示
    j 很大时接近阶跃减速，距离最短（本工况下停在墙前，峰值接触力为零），但加速度阶跃带来的振铃风险最大；j 很小时减速"软启动"，停止距离明显增加（本工况下参考停点从约 50 mm 拉长到约 150 mm，机器人撞上墙，峰值力达几十牛）。典型折中在 20–100 m/s³，按机械共振频率的 1/10 量级选取。
  3. 设计实验：让机器人在接触状态下（先以 3 N 预压力停住）触发安全停止，比较"保持阻抗"与"硬度翻倍"两种设置的峰值接触力与停稳时间；再解释为什么停稳后的力应当回到 Kd×残余偏移。★★
    提示
    接触中停止时，参考速度的收敛让机器人"退一步"再停；硬度翻倍会把停止瞬间的位置差变成大力（近似线性放大）。停稳后的静态力由当前偏移与 Kd 决定，回到第 001 章的稳态公式。
  4. 为一个"焊枪在 2 kg 工具下、允许接触力 20 N、工作空间余量 40 mm、最高速度 0.8 m/s"的单元做安全停止设计：给出 amax 的选择、t反应 预算、d停 核算；如果超预算，给出三种方案并比较对节拍的影响。★★★
    提示
    a ≤ 20/2 = 10 m/s²，但机械约束可能更低（取 5–7）；v=0.8 时减速段 45–64 mm 已超 40 mm 余量。方案：限速到 0.5（减速段 18–25 mm）、分段降低接近速度、或把停止改成"减速 + 回退"减少占用空间。

小结

  • 安全停止 = 受控减速 + 柔顺保持：保留驱动与控制，让柔顺吸收残余能量；断电急停只作为停止逻辑失效时的最后防线。
  • 停止距离预算 d = v·t反应 + v²/(2amax) + 裕量；amax 由力约束 Fmax/m 与机械约束共同决定。
  • 减速参考必须限 jerk（20–100 m/s³），停止期间阻抗参数保持不变；停稳后以实测位置作为柔顺保持参考。
  • 状态机 NORMAL→DECEL→HOLD→(REARM)→NORMAL，重度事件直接 FAULT；恢复需要"人工确认 + 自检"，禁止无脑自动恢复。
  • 停止解决"停"，不解决"离开"：障碍物仍与机器人接触时，下一步是，紧急回退：沿安全方向撤出并重新武装系统。
