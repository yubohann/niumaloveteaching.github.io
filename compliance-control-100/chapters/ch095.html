第五篇 · 鲁棒控制与工程实践

第 095 章：导纳控制中的主从协同

上一章两台机器人"对等谈判"，这一章改成"角色分工"：主端负责意图与轨迹，从端用导纳控制"揣着弹簧跟随"，主端再借力反馈感知从端的受力。两条解析公式给出全部设计依据，协调力 ≈ Dd·v主，失配力 ≈ Kd·Δ。

  • 主题：主从协同（master-slave coordination）/ 从端导纳
  • 关键公式：Mdẍc + Ddẋc + Kd(xc−xr) = F；f ≈ Dd·v，f静 ≈ Kd·Δ
  • 预计学时：65 分钟
  • 前置章节：第 094 章

学习目标

  • 理解主从协同与对等协同（第 094 章）的架构差异：信号流是"单向参考 + 可选力回传"，代价与收益各在哪里。
  • 会写出从端导纳方程 Mdẍc + Ddẋc + Kd(xc−xr) = F，并解释每个增益在协同语境下的物理角色。
  • 会推导两条协调力解析式：匀速段 f ≈ Dd·v（与时速度成正比），静态失配 f静 ≈ Kd·Δ（与参考偏置成正比）。
  • 会设计"主端力反馈柔顺"：xr ← xr − β·F，并用回路增益 β·Kd < 0.3 约束 β。
  • 能说清什么时候主从架构"够用"（低速、轻载、精度中等），什么时候必须升级回对等 + 内力管理（连续夹持力、重载、高精度）。

背景与动机

第 094 章的对等架构很强大，但对系统的要求也高：两台机器人要交换位置与力、要统一时钟、要共同维护抓持矩阵的分解，通信与软件成本都不低。现实里大量协作任务其实不需要这么重：一台机器人"带路"（主端，掌握任务意图与轨迹），另一台"跟随并为整体提供柔顺"（从端，导纳控制）。焊接配合、大件搬运的"一头抓、一头托"、主臂装配副臂支撑，都是这种分工。

从端为什么天然适合导纳控制？因为从端的任务本质是"感知受力 → 调整位姿"，正是导纳方程的工作方式：用虚拟的 Md、Dd、Kd 把"跟随刚度"做成可调旋钮。主端不需要知道从端的位置精度，从端也不需要知道主端要去哪，它只需要处理"当前被拉向哪里、受了多大力"。整条链只有两个信号：从主到从的参考（+握距偏移）和从从到主的力（可选）。

本章的核心工作就是把"让它跟得舒服"翻译成两条可以计算的公式：协调力 ≈ Dd·v、静态失配力 ≈ Kd·Δ。有了它们，导纳增益的选择就不再靠感觉，可以直接从"允许多大的协调力 / 允许多大的参考偏差"反推，这正是工程上把主从协同调稳、调准的最短路径。

核心原理

1. 架构：单向参考 + 可选力回传

主从协同的信号流非常简洁：主端按自己的任务轨迹运动，把位姿参考 xr(t) 与握距偏移 Δ 送给从端；从端以导纳方程计算"修正位置"，由自己的位置内环执行：

Mdẍc + Ddẋc + Kd(xc − xr,从) = Fmeas，xr,从 = xr + 握距 + Δ xc：从端导纳生成的命令位置；Fmeas：从端接触力（方向约定：使从端"让位"为正）

这里每个参数在协同语境下都有清晰的角色：Md 决定从端对力的"惯性反应"（主要影响高频质感）；Dd 决定"随速度让位"的程度；Kd 决定"偏离参考多远才产生多少稳态力"。与单机导纳（第 002 章）相比只是 xr 来自另一台机器人，但参数的含义可以直接换算成协同指标，这就是下一节的推导。

可选的第二条信号是从端 → 主端的力回传。主端把力按增益 β 变成自己的参考修正（"主端柔顺"）：

xr,主 ← xr − β·Fmeas 主端"感觉到"从端受的力后主动让步，协同从单向变成轻度双向，仍然不需要完整的力分解

2. 两条解析公式：把协同力变成预算表

先看最典型的场景：主端以恒定速度 v 平移，从端导纳跟随，两侧通过刚性工件耦合（等效接触刚度 Kc ≫ Kd）。在运动坐标系里，从端导纳达到准稳态，把几何关系代入后可以解出协调力。推导分三步：（1）几何：从端位置滞后 L（跟随落后于参考的距离）通过握手刚度产生力 F = Kc·L；（2）导纳准稳态（ẍc ≈ 0，匀速段）：Dd·v + Kd·δ = F，其中 δ 是命令位置相对参考的偏差；（3）命令偏差与几何滞后一致（δ = −L，从端落在后面），联立消去 L：

f = Dd·v / (1 + Kd/Kc) ≈ Dd·v （Kd ≪ Kc） 匀速段的协调力只由"从端阻尼 × 主端速度"决定，与质量、刚度都无关，这就是协同力预算的主公式

再推导静态失配：主从参考之间有一个固定偏差 Δ（标定误差、工件公差、抓持点偏差），速度为零时由导纳方程与握手几何联立：

f静 ≈ Kd·Δ / (1 + Kd/Kc) ≈ Kd·Δ 静止时协调力由"从端虚拟刚度 × 参考失配"决定

工程直觉：从端的 Dd 是"运动的税"、Kd 是"偏差的税"。这两条公式把一个模糊的问题（"从端调多软？"）变成两个不等式：给定期望的最大协调力 fmax、最大主端速度 vmax 与最大失配 Δmax，直接解出 Dd ≤ fmax/vmax 与 Kd ≤ fmax/Δmax。例如 vmax = 0.06 m/s、fmax = 6 N ⇒ Dd ≤ 100 N·s/m；Δmax = 3 mm、同一 fmax ⇒ Kd ≤ 2000 N/m。

3. 稳定性与带宽：从端的"内部账"

从端导纳本身是一个级联系统：导纳方程（虚拟动力学）→ 位置内环 → 工件耦合 → 力反馈回导纳。稳定性的经验约束与单机导纳完全一致：导纳虚拟带宽（√(Kd/Md)/2π 与 Dd 共同决定）必须远低于位置内环带宽；而协同又叠加了一条更长的回路：从端力 → 主端让步（力回传）→ 从端参考变化 → 力变化，这条回路的增益近似为 β·Kd（参考每移动 1 m 产生 Kd 量级的力变化），因此约束是：

β·Kd < 0.3 （力回传柔顺的稳定预算） 再加上通信延迟 τ：写成 β·Kd·e−sτ，τ 越大 β 越要保守

带宽预算的结论是：主从协同的"协调带宽"由最慢的一环决定，通信（0.5–2 ms 的实时总线）、从端导纳带宽（5–20 Hz）、位置内环（20–50 Hz）里，最慢的一环决定协同能做的动作速度。这也是为什么主从协同几乎总是出现在"低速、重协作"的场景：速度越慢，两条公式给出的力预算越宽松。

4. 与对等架构、与遥操作的边界

与第 094 章对比：对等架构显式管理内力，能保证"夹多紧"这件事故意地可控；主从架构把夹持力交给工件与抓持的被动柔顺，只保证"不会互顶到失控"。因此主从适合"搬运与支撑"（力的下限不关键、上限要防超），对等适合"压装与贴合"（需要持续控制夹持力）。与第 045/046 章的遥操作也要分清：遥操作的主从之间隔着物理距离，主端提供的是"操作者手感"（透明性/力觉反馈）；本章的主从共享同一工件与同一工位，追求的是"位置协调 + 力不超标"。两者都用导纳，但设计目标函数完全不同。

实现思路与设计

  1. 角色与安全分级：主端承担轨迹与任务逻辑、具备全速权限；从端只做导纳跟随，限速、限位、限力（严格于主端）。
  2. 坐标与偏移：统一双方的世界坐标系（工件标定）；握距与 Δ 一次性标定，接任务时复核（工件公差大时把 Δ 计入力预算）。
  3. 从端参数初值：先按力预算反推 Dd ≤ fmax/vmax、Kd ≤ fmax/Δmax；Md 取 0.5–2 kg，保证导纳带宽低于内环的 1/5。
  4. 力回传（可选）：β 初始取 0.1/Kd（回路增益 0.1），逐步加大到 0.3/Kd；有通信延迟时优先减 β，把减 Kd 留作最后手段（保住静态刚度）。
  5. 滤波与死区：从端力信号 20–50 ms 低通（第 047 章）；死区取 3σ（第 091 章），防止噪声经导纳积分成漂移。
  6. 验收实验：主端跑一段 0.06 m/s 的匀速段，测量协调力峰值/均值、从端滞后、静止段失配力；对照两条公式的反推值逐项核对。
设计决策：从端"软"到什么程度才合适？

从端太硬（Dd、Kd 大），协同力高、工件与夹具受罪，且两台机器人的同步误差变成硬碰硬；从端太软，滞后大、动作发飘，导纳受噪声驱使容易漂移（第 091 章的爬行问题）。正确做法是把"软硬"交给任务给出的两条预算不等式：先确定 fmax（工件许用侧向力/夹具防滑力的较小者），再按最大工作速度与标定误差算出 Dd、Kd 的上限，最后把参数顶到上限附近使用，这样"能硬就硬"（精度好），"该软才软"（安全）。

关键代码与解读

片段 1：从端导纳 + 主端力回传

import numpy as np

class SlaveAdmittance:
    """从端导纳：由接触力生成命令位置修正，参考来自主端。"""
    def __init__(self, m_d=1.0, d_d=100.0, k_d=800.0, dt=1e-3,
                 deadband=0.3, x_max=0.03):
        self.m_d, self.d_d, self.k_d, self.dt = m_d, d_d, k_d, dt
        self.deadband, self.x_max = deadband, x_max
        self.x_c, self.v_c = 0.0, 0.0      # 导纳状态（命令位置与速度）

    def step(self, f_meas, x_ref):
        f = 0.0 if abs(f_meas) < self.deadband else f_meas   # 死区：噪声不积分
        # 导纳方程：力把命令位置"推离"参考；D 管速度、K 管稳态偏移
        a_c = (f - self.d_d * self.v_c - self.k_d * (self.x_c - x_ref)) / self.m_d
        self.v_c += a_c * self.dt
        self.x_c += self.v_c * self.dt
        # 修正量限幅：保护从端不被"意外的力"带出去太远
        self.x_c = float(np.clip(self.x_c, x_ref - self.x_max, x_ref + self.x_max))
        return self.x_c

class MasterYield:
    """主端力回传柔顺：感受到协调力就按 beta 让步（回路增益 beta*K_d）。"""
    def __init__(self, beta=2e-4, f_deadband=0.3):
        self.beta, self.f_deadband = beta, f_deadband

    def adjust(self, x_ref, f_meas):
        f = 0.0 if abs(f_meas) < self.f_deadband else f_meas
        return x_ref - self.beta * f

解读：从端类里两个保护都值得强调：deadband 让噪声不能通过"力→位置"通道累积（导纳的积分性质决定了没有死区就会慢速漂移），x_max 把修正量限制在 ±30 mm，即使力信号出现 20 N 的异常，从端也只会偏出去 3 cm 就被截住。MasterYield 用 beta 一个数把"感知对方受力"变成可整定的回路：β 增大协同更柔和，但回路增益 β·Kd 逼近 1 时会振荡，所以 β 的量级应该由 Kd 反推（例：Kd = 800 时 β ≈ 1×10−4–4×10−4）。

片段 2：主从协同的一维仿真

def run_ms(d_d=100.0, k_d=800.0, beta=0.0, dx_off=0.0, n=3000, dt=1e-3):
    """主端 S 形平移 20 mm，从端导纳跟随；返回协调力与滞后指标。"""
    m_h, m_o, k_c, w = 1.0, 3.0, 2e4, 0.10      # 手/物体质量、握持刚度、握距
    k_il, d_il = 2e4, 180.0                     # 从端位置内环（约 22 Hz）
    k_m, d_m = 1e4, 100.0                       # 主端位置环（约 16 Hz）
    slave, yield_ = SlaveAdmittance(d_d=d_d, k_d=k_d), MasterYield(beta=beta)
    x_m = x_s = x_o = 0.0
    v_m = v_s = v_o = 0.0
    x_c = w; f_peak = 0.0; lag_peak = 0.0
    for i in range(n):
        t = i * dt
        if t < 0.5:
            s_ref = 0.0
        elif t < 1.0:
            u = (t - 0.5) / 0.5                 # smoothstep：峰值速度约 60 mm/s
            s_ref = 0.02 * (3*u*u - 2*u*u*u)
        else:
            s_ref = 0.02
        comp_l = x_m - (x_o - w/2)              # 主端侧挤压量
        comp_r = (x_o + w/2) - x_s              # 从端侧挤压量
        f_s = k_c * comp_r                      # 从端受力（向外为正）
        x_ref_s = x_m + w + dx_off              # 从端参考 = 主端 + 握距 + 偏置
        x_c = slave.step(f_s, x_ref_s)
        x_ref_m = yield_.adjust(s_ref, f_s)     # 主端按 beta 让步（beta=0 即不回传）
        u_m = -k_m * (x_m - x_ref_m) - d_m * v_m
        u_s = -k_il * (x_s - x_c) - d_il * v_s
        # 被控对象：主手/从手/物体（借第 094 章的抓持模型）
        v_m += (u_m - k_c * comp_l) / m_h * dt
        v_s += (u_s + f_s) / m_h * dt
        v_o += (k_c * comp_l - k_c * comp_r) / m_o * dt
        x_m += v_m * dt; x_s += v_s * dt; x_o += v_o * dt
        f_peak = max(f_peak, abs(f_s))
        lag_peak = max(lag_peak, abs(x_ref_s - x_s))
    return f_peak, abs(f_s), lag_peak

for name, kw in [("软从端", dict(d_d=40.0, k_d=300.0)),
                 ("硬从端", dict(d_d=200.0, k_d=2000.0)),
                 ("硬从端+回传", dict(d_d=200.0, k_d=2000.0, beta=1e-4))]:
    fpk, fend, lpk = run_ms(**kw)
    print(f"{name:8s} 协调力峰值={fpk:5.1f} N  末态力={fend:4.2f} N  "
          f"滞后峰值={lpk*1000:4.2f} mm")

解读：预期结果与两条公式对照，"软从端"的协调力峰值约 2–3 N（≈ D·v = 40×0.06）、"硬从端"约 12 N（≈ 200×0.06）；末态力都接近 0（Δ = 0 时没有静态失配）；"硬从端 + 回传"的峰值比不回传低 20–30%（主端感到力后略微收住，等效降低了相对速度）。两个实现细节：（1）x_c 的初值是 w，即"从端一开始就站在正确的握距上"，避免启动瞬态干扰测量；（2）smoothstep 参考让加速度连续，峰值速度 = 1.5×(20 mm/0.5 s) = 60 mm/s，正好用于核对 f ≈ D·v 公式。把 dx_off 改成 3 mm 再跑，末态力应变成约 Kd·Δ = 2.4 N（默认参数那组），这就是静态失配公式的实测验证。

片段 3：参数预算表（从"允许力"反推增益）

def gain_budget(f_max, v_max, dx_max, k_c=2e4):
    """按两条公式反推从端增益上限，并给出余量评估。"""
    d_max = f_max / v_max                      # 匀速段：f ≈ D*v
    k_max = f_max / dx_max                     # 静态段：f ≈ K*dx
    # 数值示范：不同速度下同样的 D 对应多少协调力
    rows = [(v, d_max * v) for v in (0.02, 0.06, 0.12)]
    print(f"预算: D <= {d_max:6.1f} N*s/m, K <= {k_max:7.1f} N/m")
    for v, f in rows:
        print(f"  v={v:5.2f} m/s 协调力 {f:5.2f} N "
              f"({'超限!' if f > f_max + 1e-9 else 'OK'})")
    return d_max, k_max

gain_budget(f_max=6.0, v_max=0.06, dx_max=0.003)

解读：这个工具把设计流程固定下来：先确定"工件与夹具能承受多大的协调力 fmax"，再除以任务的最大速度与标定误差，得到 Kd、Dd 的上限。表里三行速度展示了协同力"随速度线性"的性质：如果实际任务会跑到 0.12 m/s，而 Dd 按 0.06 m/s 选了 100，协调力就会翻到 12 N，超限。这就是为什么协同任务在上线前必须"扫一遍速度包线"，不能只按平均速度调参。返回的 d_max、k_max 可以直接写进参数文件，跟随任务速度档位切换。

常见坑

  • 从端太硬硬扛同步误差：Dd、Kd 按"单机手感好"来调，协同力峰值轻松上 20 N，工件被推挤。修复：按 fmax/vmax、fmax/Δmax 两条不等式反推；上线前扫速度包线。
  • 没有死区：0.1 N 的力噪声经导纳积分成缓慢漂移（与第 091 章同根）。修复：从端力信号 20–50 ms 低通 + 3σ 死区 + 修正量限幅。
  • 力回传增益过高：β·Kd 接近或超过 1，主从之间出现低频"呼吸"。修复：β ≤ 0.3/Kd，并有通信延迟时再降 30%。
  • 主从时钟不同步：参考与力信号的时间戳错位，等效于额外的回路延迟，稳定性变差、协调力波动。修复：统一时基（PTP 或事件同步），并在调试里直接测量往返延迟。
  • 把主从当"万能协同"：需要持续、精确夹持力的任务（压装、贴合）上主从会露馅，工件悬在两个参考之间，夹持力由被动柔顺决定，不受控。修复：这类任务改用第 094 章的对等 + 内力环架构。

    提示
    握手/抓持刚度通常在 104 N/m 量级，而从端虚拟刚度按预算只取 102–103，比值 ≥ 10，近似误差 < 10%。
  2. 用片段 2 的代码，把 dx_off 从 0 改成 2 mm 与 5 mm，记录末态力，并与 f静 ≈ KdΔ 对照（两种从端参数各测一遍）。★★
    提示
    硬从端 Kd = 2000：5 mm → 约 10 N；软从端 Kd = 300：约 1.5 N。这正是"静态失配由 Kd 定价"的直接证据。
  3. 把主端速度提高到 0.12 m/s（改参考幅值与时间），观察"硬从端"的协调力是否超出 6 N 预算；给出两个让任务重回预算内的方案（调参数或调任务），并比较它们的代价。★★
    提示
    方案 A：Dd 从 200 降到 50（力回到预算内，但滞后变大、工件悬垂更明显）；方案 B：任务分段错峰减速（牺牲节拍，保住精度）。
  4. 设计实验：把力回传的 β 从 0 逐步加到 2×10−3（回路增益 4），记录协调力峰值与系统是否振荡，找出临界 β 并与理论约束 β·Kd < 0.3 比较。★★★
    提示
    Kd = 2000 时理论上 β < 1.5×10−4；实测临界点会因延迟与采样略低，可额外加 30% 保守量。振荡通常表现为 4–10 Hz 的"呼吸"式起伏。

小结

  • 主从架构：主端给意图与轨迹，从端用导纳"走弹簧"，可选力回传给主端让步；信号少、软件简单、适合低速搬运与支撑。
  • 两条设计公式：匀速段 f ≈ Dd·v（运动的税）、静态 f ≈ Kd·Δ（偏差的税）；由 fmax 反推 Dd、Kd 上限。
  • 稳定性预算：从端导纳带宽 ≪ 位置内环带宽；力回传回路增益 β·Kd < 0.3，通信延迟越大越保守。
  • 从端必备的死区、低通与限幅，都是针对"导纳把力噪声积成位移"这一结构性风险的。
  • 下一章进入安全体系：机器人需要知道自己"现在是不是在接触"，接触状态检测，它是限位、检测、停机、回退全部逻辑的输入。
