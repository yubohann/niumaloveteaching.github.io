第一篇 · 基础、建模与稳定性

第 012 章：摩擦力补偿的阻抗控制

小于摩擦的力"推不动"机器人，稍大一点又"窜出去"，粘滑把柔顺控制的精细度吃光。本章给出摩擦的建模、恒速扫掠辨识与 85% 补偿法，并说清为什么"补满"反而更糟。

  • 主题：阻抗控制 / 关节摩擦建模与前馈补偿
  • 关键公式：τf = Fc·tanh(q̇/vε) + b·q̇；补偿取 70%–90% Fc
  • 预计学时：50 分钟
  • 前置章节：第 011 章

学习目标

  • 理解摩擦怎样破坏柔顺控制：微力死区、低速粘滑、力-位移关系的迟滞与"多值"。
  • 掌握工程用的摩擦模型：库仑 + 黏滞 + tanh 零速平滑，及每个参数的物理含义与量级。
  • 会设计恒速扫掠实验辨识 (Fc, b)，理解为什么用"稳态力矩平衡"就能解出参数（不必求导）。
  • 会写带速度死区的前馈补偿，并说清"只补 70%–90%"与"零速附近不补库仑项"的两条安全规则。
  • 能诊断典型的摩擦故障模式：跟踪误差呈台阶、松手后有微幅自持摆动、力控制阈值行为。

背景与动机

做一个数字实验：某关节库仑摩擦 2 N·m，等效到手端 0.3 m 力臂上是 6.7 N 的"门槛"。拖动示教时，人手要出 6.7 N 才把机器人推动，比预期的接触力还大；装配时下发力指令 3 N，机器人纹丝不动，加到 8 N 突然窜出，撞上工件。摩擦把"可控的力"变成"开关式的力"，这正是柔顺控制在真实机器上总显得"不够细"的头号原因。

好消息是摩擦可测、可辨识、可前馈：它不像环境刚度那样未知且多变，同一台机器同一套减速器的摩擦在运行区间内相当稳定。本章把摩擦补偿做成一条标准流水线，建模、辨识、补偿、验证，它是重力补偿（第 011 章）之后的第二块地基，直接决定你的力控精度下限。

核心原理

1. 摩擦的三副面孔：库仑、黏滞、静摩擦

关节与传动里的摩擦随速度呈三段不同的性格：

  • 库仑摩擦（Coulomb friction）：速度非零时近似恒定的阻力幅值 Fc（N·m），方向与速度相反。它造成"死区"，小于 Fc 的力矩全被吃掉。
  • 黏滞摩擦（viscous friction）：与速度成正比的阻力 b·q̇（b 单位 N·m·s/rad），高速段的"拖拽感"。
  • 静摩擦（stiction）：速度为零时能抵抗的最大力矩 Fs，通常略大于 Fc。它是粘滑（stick-slip）的元凶：弹簧力慢慢攒到 Fs，突然滑动、摩擦跳到 Fc，再卡住……如此往复。

对柔顺控制最痛的是"零速附近的不可微性"。数学上 sgn(q̇) 在 0 点跳变，任何基于它的补偿都会在零速附近制造高频切换（chattering）。工程模型用 tanh 平滑掉这个跳变：

τf(q̇) = Fc·tanh(q̇ / vε) + b·q̇ vε：零速平滑宽度（rad/s），取等效末端速度 1–10 mm/s；tanh 的斜率在 0 处为 Fc/vε

平滑带来一个必须正视的副作用：在 |q̇| ≪ vε 的区域内，模型把库仑摩擦近似成一根"超强黏滞弹簧"（等效黏滞系数 Fc/vε，量级可达几千 N·m·s/rad）。真实摩擦的零速行为更接近"静摩擦刚性区"，两种模型在零速附近都不精确，这决定了补偿器必须在这里保持克制。

2. 摩擦如何进入阻抗/导纳回路

对力矩接口实现，摩擦直接叠加在动力学里：M(q)q̈ + Djq̇ + Kj(q−qd) = τext − τf（理想补偿后剩残差）。后果有三层：

  • 死区：|τext| < Fc 时关节不响应，末端"推不动、也不让位"，虚拟弹簧手感消失。手推试验里表现为"前 5 牛没反应"。
  • 迟滞：正向运动时实际力-位移线比设计刚度高（要克服 +Fc），反向运动时低，同一位移对应两个力，力控分辨率和重复性都被污染。
  • 粘滑：低速轨迹（< 0.01 rad/s 量级）下速度时通时断，激发关节振荡与声音，参考轨迹越慢越明显。

对位置接口/导纳实现，摩擦藏在位置内环内部：内环增益高时它被"压成"稳态误差（粘滑被抑制但存在稳态偏差）；增益低或惯性大时粘滑照样透出到末端。无论哪条路线，摩擦残差最终都会以"力阈值 + 低速振颤"两种形式出现在用户的体感里。

工程直觉：重力补偿解决"静态偏置"，摩擦补偿解决"动态死区"。前者是常数账，后者是符号账，补的方向随速度翻转，所以摩擦补偿永远比重力补偿更"敏感"，宁可补不到位，不可补过头。

3. 辨识：恒速扫掠 + 力矩平衡

辨识摩擦最稳的办法：让关节在一组恒速下运行，等系统进入稳态（加速度≈0、弹簧项≈0）后，读出的驱动力矩满足力矩平衡：

τapplied = ĝ(q) + τf(q̇) = ĝ(q) + Fc·sgn(q̇) + b·q̇ 稳态下惯性项为零；把重力已补偿/已扣除的部分去掉，剩余就是摩擦

对每个速度点 vi（建议 ±0.05、±0.1、±0.2、±0.4 rad/s 两倍频程覆盖），记录 (vi, τi − ĝ)：未知量只有 Fc 与 b 两个，最小二乘一步解出。三个实践要点：（1）必须覆盖正反两个方向，不对称摩擦（正反向 Fc 不同）很常见，至少把符号项的系数分开信；（2）避开极低速，v < 0.01 rad/s 区域静摩擦占主导，tanh 模型在那里本就不准，纳入拟合会把 Fc 抬高；（3）温度与负载要代表工况，摩擦随润滑温度漂 10%–30%，冷机标定的参数热机可能差出一截，产线上建议热身后再标。

4. 补偿的三条安全规则

把辨识结果变成前馈项时，三条规则让补偿"帮忙不添乱"：

  1. 只补 70%–90%：库仑项按 scale=0.7–0.9 缩着补。残余 10%–30% 的摩擦由控制器消化，是廉价的稳定裕度；补满甚至超补会让净力矩-速度曲线出现"负斜率区"（补偿量比真实摩擦涨得快），零速附近形成自激振荡或缓慢爬行，体感比不补还怪。
  2. 零速附近切换策略：|q̇| < vdead（建议 0.005–0.02 rad/s）时关掉库仑项、只留黏滞项。零速是模型最不准的地方，也是切换引起抖振的地方，最安全的做法是不在那里补。
  3. 用 tanh 平滑取代 sign：避免 q̇ 穿越零点时补偿力矩高频翻转；tanh 的过渡宽度与 vdead 配合，保证切换连续无跳变。

验证标准也要写成数字：补偿后微力死区应缩小到 Fc 的 10%–30%；慢速扫掠时末端速度的波动（标准差）应下降一个数量级以上；同时确认没有出现新的自持振荡（零速附近的力矩-速度相图无负环）。

实现思路与设计

摩擦补偿的落地流程（可与重力标定合用同一次热身、同一套数据采集工具）：

  1. 热身：让关节在典型速度范围往复运行 5–10 分钟，温度稳定后再采集。
  2. 恒速扫掠：以关节速度闭环（内环）或关节力矩模式下的速度外环驱动，逐点稳定 1–2 s，记录稳定段的平均速度与平均力矩。
  3. 力矩去重：减去重力项 ĝ(q)（第 011 章）与已知偏置；确认此时空载数据在低速点近似常数、高速点线性上升。
  4. 最小二乘拟合：按正反两个方向分别拟 Fc± 与 b，检查对称性；参数写配置。
  5. 前馈上线：τff = friction_compensation(q̇, F̂c, b̂, scale=0.85, dead=vdead) 叠加进控制律，与重力前馈并列。
  6. 验收：微力死区、慢速速度波动、零速稳定性三项测试；全过才接入任务程序。
设计决策：为什么默认补 85%，补满 100% 会怎样？

参数不确定性是主因：Fc 的辨识误差、温度漂移、换向瞬间的静摩擦突增，都可能让实际摩擦力矩在估计值 ±20% 内游走。补 100% 意味着参数偏大 10% 时净驱动力在零速附近变成小幅"反向推力"，形成微幅自持振荡（用户能听到周期性"哒哒"声）；补 85% 则把补偿量限制在真实摩擦的 0.68–1.02 倍内（参数波动 ±20%），最坏只轻微过补、不会形成自持振荡，残余波动由控制器吸收。代价是死区残余 15%，对 2 N·m 的关节是 0.3 N·m，等效末端 1 N 左右，已在多数任务的噪声预算内。若任务对微力特别敏感（触觉探索、精细插装），再把 scale 调到 0.9 并配更低温漂的在线估计；一次拉到 1.0 会引入零速自激风险。

关键代码与解读

片段 1：摩擦模型与前馈补偿器

import numpy as np

def friction_torque(qd, fc, b, v_eps=1e-3):
    """关节摩擦模型：库仑(tanh 平滑) + 黏滞。
    qd: 关节速度 rad/s；fc: 库仑幅值 N·m；b: 黏滞系数 N·m·s/rad。"""
    return fc * np.tanh(qd / v_eps) + b * qd

def friction_compensation(qd, fc_hat, b_hat, v_eps=1e-3,
                          dead=0.005, scale=0.85):
    """前馈补偿：零速附近只补黏滞项；库仑项按 scale(0.7–0.9) 缩补。"""
    if abs(qd) < dead:
        # 零速区是模型最不准、切换最危险的地方：库仑项坚决不补
        return b_hat * qd
    # tanh 保证跨过 dead 边界时输出连续，不会因符号翻转产生力矩台阶
    return scale * fc_hat * np.tanh(qd / v_eps) + b_hat * qd

# 量级对照：2 N·m 库仑摩擦对 0.3 m 力臂 = 6.7 N 末端"门槛"
print("等效末端摩擦阻力 =", 2.0 / 0.3, "N")
# 测试点必须放在死区之外：qd=0.01 rad/s 时 tanh 已饱和、补偿处于工作区
v_test = 0.01
print("补偿前/后有效阻力:",
      friction_torque(v_test, 2.0, 0.3) / 0.3,
      "→", (friction_torque(v_test, 2.0, 0.3)
             - friction_compensation(v_test, 2.0, 0.3)) / 0.3, "N")

解读：这段 15 行的代码里，每个判断都有明确来历。用 tanh(qd/v_eps) 取代 np.sign：sign 在零点跳变，补偿力矩会随速度号翻转而"啪"地切换，在 1 kHz 下表现为持续的高频抖振；tanh 用 1 mm/s 量级的过渡带换掉跳变，代价是绝对低速区模型不准，这正是下一条规则存在的原因。零速死区里不补库仑项：进入死区后补偿退化为纯黏滞，与真实摩擦在零速附近"静摩擦刚性区"的差异被控制器吸收；如果这里还要补，就必须处理"静止时到底有没有 Fc"的哲学问题，工程上不值得。scale=0.85 的缩补见上一节稳定性分析。打印的最后一行做了一次"补偿增益体检"：在 tanh 已饱和的常速点，固有摩擦 6.7 N 被压到约 1.0 N，剩余残余正好是 scale 规则的兑现（2.0×(1−0.85)/0.3≈1.0 N）；如果打印出来残余接近 0，说明你可能忘了 scale。注意测试点必须选在死区之外：把它改到 v=10−4（死区以内）会看到补偿前后几乎不变，那是死区逻辑在起作用，属于规则生效。

片段 2：恒速扫掠辨识，两个未知数，一次拟合

# 恒速扫掠：每个速度点稳速运行稳定后，读平均力矩（此处以稳态平衡模拟）
rng = np.random.default_rng(3)
fc_true, b_true = 1.8, 0.35           # 真值：待辨识的库仑与黏滞
g_known = 3.0                         # 重力项（已由第 011 章流程扣除）
v_list = np.array([-0.40, -0.20, -0.10, -0.05, 0.05, 0.10, 0.20, 0.40])
tau_meas = np.array([g_known + fc_true*np.sign(v) + b_true*v
                     + 0.02*rng.standard_normal() for v in v_list])
# 稳态力矩平衡：tau - g = fc·sgn(v) + b·v → 线性最小二乘
A = np.column_stack([np.sign(v_list), v_list])       # 列：[sgn(v), v]
(fc_hat, b_hat), *_ = np.linalg.lstsq(A, tau_meas - g_known, rcond=None)
print(f"辨识结果: fc={fc_hat:.3f} N·m (真值 {fc_true}), "
      f"b={b_hat:.3f} N·m·s/rad (真值 {b_true})")
# 对称性检查：正反向分别拟合，偏离大于 15% 说明传动/装配不对称
pos, neg = v_list > 0, v_list < 0
fc_pos = (tau_meas[pos] - g_known)[:2].mean()
fc_neg = (tau_meas[neg] - g_known)[-2:].mean()
print(f"正/反向低速平均力矩差 = {abs(fc_pos) - abs(fc_neg):+.3f} N·m")

解读：辨识逻辑建立在"稳态 = 加速度为零"上，所以不必求导、不必知道惯量，这是它比动态辨识鲁棒的根本原因。为什么把 g 单独减去：重力项与速度无关，如果不扣，低速点的"截距"会把重力也算进库仑摩擦，Fc 系统性偏大；这也是第 011 章必须先做的原因，两条标定流水线在这里汇合。正反向分开检查对称性：蜗轮蜗杆、皮带张紧不对称等结构会给出 fc_pos ≠ fc_neg；工程上要么分别建两个参数，要么至少确认差异在 15% 以内再取平均，否则换向瞬间会出现"一边好推一边费劲"的诡异手感。运行输出中 fc 的估计误差通常在 1% 上下，b 则常在 10% 以上（对应 0.02 N·m 的采样噪声）；把噪声改成 0.1 N·m 再跑，b 的估计明显变差。高速点少而噪声大时，斜率项永远比截距项更难估，想准就多测几个高速度点。

片段 3：粘滑对照实验，补偿上线前后的慢速跟踪

# 慢速跟踪实验：q_d 以 0.01 rad/s 缓慢爬升（在死区之上），观察粘滑与补偿效果
I, k_j = 0.08, 300.0
d_j = 2.0*np.sqrt(k_j*I)
fc_true, b_true = 1.8, 0.35

def run(scale, dt=1e-3, n=4000):
    q, qd, v_hist = 0.0, 0.0, []
    for i in range(n):
        q_d = 0.01 * i * dt                       # 慢速参考（4 秒走 40 mrad）
        comp = (friction_compensation(qd, fc_true, b_true, scale=scale)
                if scale > 0.0 else 0.0)
        tau = k_j*(q_d - q) - d_j*qd + comp       # 关节阻抗 + 摩擦前馈
        qdd = (tau - friction_torque(qd, fc_true, b_true)) / I
        qd += qdd*dt
        q += qd*dt
        v_hist.append(qd)
    v = np.array(v_hist[-2000:])                  # 末段 2 秒的统计
    return v.std(), v.min(), v.max()

for tag, s in (("不补偿", 0.0), ("补偿 0.85", 0.85)):
    sd, vmin, vmax = run(s)
    print(f"{tag}: 速度标准差={sd*1e3:.4f}e-3 rad/s  "
          f"速度范围=[{vmin*1e3:+.3f}, {vmax*1e3:+.3f}]e-3 rad/s")

解读：对照点在于速度曲线的"性格"：不补偿时，弹簧力要攒到接近 Fc 才滑动，速度呈"爬—滑—停"的脉冲状（末段标准差约 13×10−3 rad/s，范围从 −5.7×10−3 到 +26×10−3 rad/s，含明显反向摆动）；补偿 0.85 后残余阻力只剩 0.27 N·m 量级，同样增益的弹簧即可连续驱动，速度曲线拉平（标准差降到数值零、恒定在参考值 10×10−3 rad/s）。注意两个设计点：指标要用"末段 2 秒"，因为启动瞬态的快慢与摩擦无关、会把统计稀释掉；参考速度必须高于死区 0.005 rad/s，若把参考降到 0.002 rad/s，补偿在粘滞段会被死区逻辑关掉，改善也随之消失，这正是"死区是模型最不准处"的边界。为什么实验只用"不补偿 / 0.85"两档：把 scale 调到 1.2 再跑，你会看到速度在零附近来回摆动的自激极限环（或位置缓慢前移的爬行），这就是上一节"负斜率区"的直接观测，读者可以自行改一行验证，比任何文字都直观。真机上这套对照要在线做：先在力模式下用低速正弦扫频记录关节力矩波动，补偿上线后复测，波动下降 10 倍即达标。

常见坑

  • 用 sign 直接前馈：零点跳变造成 1 kHz 量级的力矩抖动，听感像电流啸叫。修复：tanh（或反正切）平滑 + 速度死区。
  • 不做正反向对称性检查：换向时一半行程"滑"一半行程"卡"。修复：正反向分别拟参数，或在机构层面查张紧与润滑不对称。
  • 把重力误算进摩擦：没扣 ĝ 就拟合，低速截距偏大，补偿过头。修复：先于摩擦做重力补偿并验证残差；辨识前先看"低速数据是否在零附近小量"。
  • 热机状态不一致：冷机标定、热机运行，参数漂 20%。修复：标定前热身，或加入温度相关的简单缩放；关键任务做在线残差估计。
  • 补满 100%：参数正偏时形成零速自激或爬行，体感比不补更差。修复：scale ≤ 0.9，零速区不补库仑项，并通过"零速相图无负环"验收。

练习与思考

  1. 写出库仑 + 黏滞摩擦模型，画出 τf(q̇) 曲线（含 sgn 与 tanh 两个版本），指出两者在 |q̇| < vε 区域的差异与各自优缺点。★
    提示
    sgn 在零点是跳变（理想但抖振）；tanh 连续（工程友好但低速区别把 Coulomb 当强黏滞）。
  2. 用片段 2 的数据把噪声从 0.02 提到 0.1 N·m，重跑 20 次，统计 fc 与 b 的散布。说明为什么 b 对噪声更敏感，并给出一种改善方法。★★
    提示
    b 由数据的斜率决定，噪声主要影响点散布；增加高速点数量、或对同一速度点多次平均（更长的稳定段）都能压低 b 的方差。
  3. 解释为什么"零速附近不补库仑项"能避免抖振，却仍可能保留死区；对触觉探索任务，写出把残余死区再压一半的两条工程路径。★★
    提示
    不补→无切换抖振，但静摩擦仍在；路径一：用 dither（小幅高频激励）不停留在静摩擦区；路径二：用更高的 scale（0.9–0.95）+ 在线残余估计，配合零速滞环。
  4. 推导：若补偿 scale = s（0 < s < 2），真实摩擦为 Fc·sgn(q̇)，则净力矩-速度函数为 (s−1)Fc·sgn(q̇)。说明 s > 1 时为什么在零速附近出现自激，s < 1 时为什么安全。★★★
    提示
    净力矩与速度同方向（s>1）时系统获得"负阻尼"，任何微小速度都被放大；s<1 时净力矩始终阻碍运动，能量耗散，稳定。
  5. 设计一套"摩擦补偿上线验收"方案：列出三项测试（微力死区、慢速波动、零速稳定性）、每项的工况与数值判据，并说明如果其中一项不过，排查的先后顺序。★★★
    提示
    微力死区：推压试验，实测启动阈值 ≤ 0.3Fc；慢速波动：恒速 0.005 rad/s，速度标准差 ≤ 不补偿时的 1/5；零速稳定性：停在任意位置 10 s，力/速度无周期性波动。排查顺序：先参数（重力残差）→ 再对称性 → 最后 scale/死区。

小结

  • 摩擦在柔顺回路里制造三件事：微力死区、力-位移迟滞、低速粘滑；量级上 2 N·m 关节摩擦就能在末端变成 6.7 N 的门槛。
  • 工程模型 τf = Fc·tanh(q̇/vε) + b·q̇：tanh 换来连续性，代价是低速区模型不准；静摩擦突增留给控制器兜底。
  • 辨识用恒速扫掠 + 稳态力矩平衡：扣掉重力后线性最小二乘解 (Fc, b)；正反向分别核查对称性。
  • 补偿三规则：补 70%–90%、零速区不补库仑项、tanh 平滑；超补会在零速附近造成自激或爬行。
  • 到这里，"环境之外"的两大静态/准静态扰动（重力、摩擦）都已入账。下一章转向机器人自身的全动力学：用 M(q)、C(q,q̇)、g(q) 做计算力矩控制，把虚拟阻抗真正"刻"进系统。
