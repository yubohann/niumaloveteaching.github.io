第四篇 · 高级柔顺任务与约束

第 080 章：基于阻抗控制的动态避障

静态障碍可以提前绕开，但人、移动工件、其他机器人不会停在原地等你规划。本章把"碰撞风险"变成一种可以进控制律的虚拟力，让机器人边保持手感、边主动闪避。

  • 主题：反应式避障 / 势场与 TTC
  • 关键公式：Frep = krep·(1/d − 1/d₀)·d̂，按 TTC 平滑调度
  • 预计学时：50 分钟
  • 前置章节：第 079 章（力矩限制）

学习目标

  • 理解反应式避障与规划式避障的分工：前者负责"最后一米"的实时反应，后者负责路线级决策。
  • 掌握势场法的斥力构造、它的三个经典缺陷（局部极小、目标不可达、边界振荡）及各自的工程缓解。
  • 会用"碰撞时间 TTC"把障碍的速度纳入风险度量，并设计平滑的风险调度器（避免开关抖动）。
  • 能实现"陷困检测 + 切向逃逸"逻辑，让机器人从局部极小区里走出去。
  • 理解避障斥力与任务力的融合位置与限幅规则，避免两个回路互相打架。

背景与动机

车间与实验室的现实：协作机器人旁边有人走动、传送带上零件位置每次不同、多个机器人共享工作区。这些场景里"预先规划一条无碰路径"是不成立的，环境在你规划完之后还在动。柔顺控制给了我们一个天然优势：它已经在操纵"期望力"这个抽象层，那么完全可以把碰撞风险也翻译成一种力，与任务力、接触力在同一个动力学方程里融合，控制器不需要知道哪种力来自"任务"、哪种来自"避障"，它只需要忠实地执行阻抗关系。

但反应式方法有自己的雷区：只盯"距离"会把速度很快的障碍当成安全（还远，但两秒后就撞上）；势场增益开大容易让机器人在障碍边缘来回振荡；把障碍放在目标方向上时，吸引与排斥会形成"死点"。本章按"风险度量 → 平滑调度 → 陷困脱出 → 安全兜底"的顺序把这些问题逐个解决。

核心原理

1. 势场斥力：距离的函数，不是开关

经典的排斥势场给出一个与距离连续的斥力（把障碍看成"排斥场源"）：

Frep = krep·(1/d − 1/d₀)·(1/d²)·d̂ ，当 d < d₀ d：到障碍表面距离；d₀：影响半径；d̂：从障碍指向机器人的单位向量

注意两个刻意设计：d→d₀ 时力连续趋零（进入影响圈是平滑事件，不是开关）；1/d² 的急剧增长（越近躲得越急）。工程实现时常简化为 k·(1/d − 1/d₀)·d̂，省略 1/d²，因为后段的陡增容易撞上力限制（076 章），要不要保留取决于任务的风险等级。

2. 势场的三个经典缺陷与缓解

缺陷成因工程缓解
局部极小（死点）吸引力与排斥力在某点平衡，且该点不是目标切向逃逸（下文）、虚拟中间目标、与全局规划器结合
目标不可达（GNRON）目标就在障碍附近，越接近目标斥力越大把斥力乘以"到目标的距离因子"，目标处自然归零
边界振荡机器人贴着影响圈边缘进出，力反复开关平滑调度器 + 迟滞（hysteresis）

3. 动态核心：用 TTC 度量风险

障碍"现在很远"和"两秒后撞上"是完全不同的风险。把相对速度引入（障碍速度 vobs，机器人速度 vrob）：

TTC = d / max( −ḋ , ε ) ，ḋ = d̂·(vrob − vobs) ḋ < 0 表示接近；ε 是防止除零的小正数；TTC 单位：秒

调度器把 TTC 映成 0–1 的"紧迫度"，再乘到斥力增益上：

keff = krep · σ( Twarn − TTC ) ，σ 为平滑阶跃（sigmoid / smoothstep） TTC 大（远或慢）→ keff≈0；TTC 小 → 全力避让；σ 的平滑过渡消灭开关抖动

工程直觉：距离决定"要不要开始躲"，TTC 决定"躲得多急"。两者分工让慢速的、远离的物体完全不干扰任务，而高速逼近的目标会被优先处理。

4. 陷困检测与切向逃逸

当机器人在死点附近时，它的表现是"有力在推、位置基本不动"：检测窗口（比如 0.5 s）内位移小于阈值而任务误差不降，判定陷困。此时给一个切向速度：垂直于"到目标连线"方向，选与当前速度或上次逃逸方向一致的一侧（保持一致性，避免来回换向），持续到脱离死点（任务误差恢复下降或斥力显著减小）。逃逸速度一般 20–50 mm/s，宁慢勿快，它的目标只是"让开死区"，不是绕行。

5. 融合位置：期望力还是速度修正？

推荐把 Frep 加到期望力（阻抗目标）上，让它和任务力走同一条通道：这样避障"分享"了任务已经调好的惯量/阻尼，行为可预测；如果它绕过动力学直接在速度上打补丁（v += Δvrep），会出现与 077 章"墙力不符动力学"相同的问题，速度跳变。融合后还要过一次限幅（076 章），保证避障本身不会触发更大的事故。

实现思路与设计

  1. 感知接口：对每个障碍物给出 {位置、速度、特征尺寸}；安全监测用"表面到表面"距离（减去两者半径/包围盒），不要用质心距。
  2. 逐障碍算斥力：距离进入影响圈且 TTC 小于预警值才激活；多障碍斥力矢量叠加（通常最多同时活动 2–3 个，超出时要降低任务速度）。
  3. 调度与迟滞：σ 的输入用 TTC，距离只决定影响圈；激活后进入"保持态"（TTC 恢复到 1.5 倍预警值才退出），消除边缘抖动。
  4. 陷困检测：0.5 s 滑窗看两件事，机器人位移 < 5 mm，且"到目标的距离"无改善；两者同时成立才启动逃逸（避免正常悬停被误判）。
  5. 限幅与兜底：叠加后的期望力过 076 章限力；任务空间速度过 078 章限速；若 TTC < 0.3 s 仍无法拉开距离，直接进安全层（降速→停止，098 章）。
设计决策：避障为什么不用"位置层"硬挂钩？

把障碍投影到"禁入位置区域"再约束位置（077 章的思路）也可以，但对运动障碍有个时间差：约束的是当前位置，而风险来自未来。力层融合的时序是正确的，斥力马上改变加速度、速度随之变化、位置在接下来几个周期里让开。这是"接触级实时性"与"约束级实时性"的分工：约束负责硬边界（静止禁入区），力负责软风险（移动体）。

关键代码与解读

片段 1：带 TTC 调度的斥力

import numpy as np

def repulsive_force(x, v_rob, obs, k_rep=200.0, d0=0.30,
                    t_warn=1.5, eps=1e-3):
    """单个动态障碍的斥力。obs = (pos, vel, radius)。"""
    p_obs, v_obs, r_obs = obs
    vec = x - p_obs
    d = max(np.linalg.norm(vec) - r_obs, eps)      # 表面距离（近似球体）
    if d >= d0:
        return np.zeros(3)                         # 影响圈外：零干预

    # 接近速率：d 的负导数（正数表示正在接近）
    d = np.linalg.norm(vec) - r_obs                # 用质心距算方向更平滑
    d = max(d, eps)
    closing = float(np.dot(-vec, v_obs - v_rob)) / (np.linalg.norm(vec) + eps)
    ttc = d / max(closing, eps) if closing > 0 else 1e9

    # 平滑调度：smoothstep 把 (t_warn - ttc) 映射到 [0,1]
    def smoothstep(s):
        s = np.clip(s, 0.0, 1.0)
        return s * s * (3 - 2 * s)
    urgency = smoothstep((t_warn - ttc) / t_warn)

    # 幅度：距离项 × 紧迫度；方向沿"远离障碍"
    mag = k_rep * max(1.0 / d - 1.0 / d0, 0.0) * urgency
    return mag * (vec / (np.linalg.norm(vec) + eps))

解读：注意 closing 的计算，把相对速度投影到"从机器人指向障碍"的方向再取负号，正值表示两者在接近。近垂直掠过（closing≈0）时 TTC 取 1e9，urgency 归零，正确的行为：擦身而过不需要避让。smoothstep 保证 urgency 与时间处处连续；如果把 urgency 换成硬阈值（ttc < 0.8 才启动），你会在边界看到力忽有忽无的抽搐。

片段 2：陷困检测与切向逃逸（带迟滞）

class EscapeLogic:
    def __init__(self, window=500, move_eps=0.005, side=+1):
        self.hist, self.window = [], window
        self.move_eps, self.side = move_eps, side
        self.escaped_until = 0

    def update(self, t_i, x, task_err, active_rep):
        """返回逃逸速度（可能为零向量）。"""
        self.hist.append((x.copy(), task_err))
        if len(self.hist) > self.window:
            self.hist.pop(0)
        if len(self.hist) < self.window:
            return np.zeros(3)

        moved = np.linalg.norm(self.hist[-1][0] - self.hist[0][0])
        improved = self.hist[0][1] - self.hist[-1][1]   # 误差下降=正
        trapped = (moved < self.move_eps) and (improved < 1e-4) and active_rep

        if trapped:
            # 保持上次方向（side 持久化），给"侧向让开"速度 30 mm/s
            return self.side * 0.03 * np.array([0.0, 1.0, 0.0])
        return np.zeros(3)

解读：三个防御性设计值得学习：（1）"没动 + 没进展 + 有斥力活动"三个条件同时成立才算陷困，排除正常的力控悬停；（2）side 是持久状态，一旦选定绕行侧就保持，防止每 0.5 s 换向导致抖动；真实实现侧向选择可以取"与当前速度切向分量同向"的那一侧；（3）逃逸速度与主任务力在同一层融合，仍然受后续限幅保护。

片段 3：融合与限幅的调用顺序

def desired_force_with_avoidance(f_task, x, v, obstacles, d0=0.30):
    """任务力 + 避障力 + 限幅（简化：合成后过一遍幅值上限）。"""
    f_total = np.asarray(f_task, dtype=float).copy()
    for obs in obstacles:
        f_total += repulsive_force(x, v, obs, d0=d0)

    # 与 076 章一致的软限幅：避障也不允许把力推过安全阈值
    f_max = 40.0
    mag = np.linalg.norm(f_total)
    if mag > f_max:
        f_total *= f_max / mag      # 等比缩放，保方向
    return f_total

解读：合成顺序"任务力 → 加斥力 → 等比限幅"与 076、079 章的原则完全一致。注意限幅使用等比缩放：哪怕力来自避障，方向信息（往哪躲）也不该被分轴削掉。若多个障碍同时活跃导致合成方向扭来扭去，正确反应是降低任务速度（给避障让出"反应时间"），加大斥力只会加剧拉锯。

常见坑

  • 用静态距离判断动态障碍：快速逼近的目标在 30 cm 外就被"允许"，1 秒后已到 5 cm。距离决定影响圈，TTC 决定紧迫度，二者缺一不可。
  • 斥力增益与任务刚度同量级：krep 开得太大，任务与避障在动力学里拉锯，表现为障碍边缘的高频振荡。krep 用"任务力的 2–5 倍"起步，并且永远经过限幅。
  • 影响圈硬开关：d 刚进入 d₀ 就跳出一个非零力，机器人"抖一下"。斥力公式天生连续（d→d₀ 时趋零），别在实现里加 if d < d₀ 就直接给常数力。
  • TTC 除零/负值：相对速度接近零或背离时，必须给出"无风险"的默认值（1e9），别让它除出 inf/NaN 污染整条控制链。
  • 忽视局部极小的存在：光靠调参解决不了死点，这是势场法的结构性缺陷。陷困检测 + 切向逃逸是必备件，不是可选项。

练习与思考

  1. 计算：障碍表面在 40 cm 外、以 0.5 m/s 迎面接近，机器人静止。TTC 是多少？若机器人在向后移动 0.2 m/s，TTC 变为多少？★
    提示
    接近速率 0.5 m/s → TTC=0.8 s；机器人后退时接近速率降到 0.3 m/s → TTC≈1.33 s。"主动后撤"本身就能扩大安全时间窗。
  2. 画出（草稿即可）吸引+排斥势场的合力场，找到一个死点，验证该点满足 Fatt + Frep = 0 且不在目标。★★
    提示
    一维最直观：目标在障碍正后方，两者之间某点必平衡。把障碍稍微侧移，平衡点消失，这就是"虚拟中间目标"能工作的直觉来源。
  3. 把片段 1 的 smoothstep 换成硬阈值，构造一个"障碍匀速横穿"场景，观察力的时间曲线；解释为什么硬阈值会产生"抽动"。★★
    提示
    硬阈值下 TTC 在阈值两侧摆动时力在 0 与满值之间跳变，等效输入方波；平滑调度让力的导数有界。
  4. 设计陷困判定第三条规则的替代方案：用"斥力与任务力的夹角余弦"检测对抗状态（两力接近反向且模长都大）。写出判据并讨论它与位移判据的优劣。★★★
    提示
    cosθ ≈ −1 且 ‖F_rep‖、‖F_task‖ 都高于中位值时即"顶牛"；优点是响应快（几百毫秒内），缺点是短暂对抗（正常避让过程）会误报，需要加持续时间条件。
  5. 综合设计：人机共享工位中，人走近到 1.2 m 以内应当是"减速"，0.5 m 以内"暂停任务力、只保留避让"，0.3 m 内"停止"。给出三档的门限、平滑过渡方式与滞回设置，并说明每档为什么需要独立的滞回带宽。★★★
    提示
    三档用串联的 smoothstep 或状态机；滞回带宽应随风险等级增大（档位越高越保守），例如 ±5/±10/±15 cm。目标是防"档位边缘反复横跳"。

小结

  • 反应式避障负责"最后一米"：把风险翻译成力，与任务力在阻抗层融合，共享同一套动力学。
  • 势场三缺陷（死点、GNRON、边界振荡）都有工程缓解，但都替代不了陷困检测与切向逃逸。
  • TTC 把障碍速度纳入度量，配合平滑调度器与迟滞，是动态场景的关键升级。
  • 融合顺序：任务力 → 斥力叠加 → 等比限幅；一切与 076–079 章的约束链保持一致。
