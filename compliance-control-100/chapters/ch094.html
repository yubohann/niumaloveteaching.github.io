第五篇 · 鲁棒控制与工程实践

第 094 章：阻抗控制中的多机器人协同

两台阻抗控制的机械臂抱住同一个刚性工件，闭环链让"各自柔顺"变成"互相较劲"：参考位置差一点，工件上就多出几十牛的隐形内力。本章把总作用力拆成"驱动工件的净力"与"不改变运动的内力"，两面分开控制，让协同动作不挤压、不滑落。

  • 主题：多机器人协同 / 抓持矩阵与内力分解
  • 关键公式：Fobj = G·f，G·fint = 0；fi = Gi+Fobj/n + fint,i
  • 预计学时：70 分钟
  • 前置章节：第 093 章

学习目标

  • 理解闭环运动链带来的新问题：两台柔顺臂的参考位置不一致会产生"对内不对外的内力"，它不改变工件运动，却可能挤压工件或互相顶着较劲。
  • 会写出抓持矩阵 G 与力分解公式 Fobj = G·f、G·fint = 0，并在双臂一维情形下解释"净力 = 两臂之差、内力 = 两臂之和"。
  • 会设计分解式控制器：物体级阻抗产生净力、内力环 PI 调节夹紧力、每臂命令 = 份额 + 内力分量。
  • 掌握回路分离原则：内力环带宽必须低于两臂阻抗环与抓持界面动态（典型 1–5 Hz vs 20 Hz以上），否则夹紧力会振荡。
  • 能说清多机协同与主从协同（下一章）的架构差异：本章是"对等 + 内力显式管理"，下一章是"角色分工 + 沿参考传递"。

背景与动机

两台机器人一起抬一块板子，这在人类那里是本能，在控制上却是雷区。单臂柔顺控制里，机器人只面对"环境"这一个交互对象；双臂抱持时，两台机器人与同一个刚体组成闭环运动链：工件的位置由两只手共同决定，任何一只手的位置参考变化都会立刻改变另一只手的受力。第二章里"接触力由位置差决定"的逻辑在这里加倍体现：两只手的参考位置差哪怕只有几毫米，经过各自的等效刚度放大，就是几十牛的内力。

更麻烦的是这类内力"隐于无形"：它不出现在工件的运动上（大小相等、方向相反对消了），却真实地作用在工件、夹爪和手臂上。轻则工件被压变形、胶层被挤薄，重则两臂"顶牛"直到力超限报警。所以多机协同的核心是把控制量按两个正交子空间分解，不能简单"把两套阻抗控制器绑在一起"：一个子空间管"工件怎么动"（净力/物体级），另一个子空间管"内部握多紧"（内力），两者互不干扰地独立调节。

本章以双臂为例把分解与内力环讲透。理解之后你会发现：现实中大量"两只手抬东西"的任务，都可以先用本章的对等架构思考，再视需要退化成下一章更省通信的主从架构。

核心原理

1. 闭环链的数学：抓持矩阵与两个子空间

设 n 台手臂抓住一个刚体，第 i 台手在抓持点的六维力旋量 fi（3 力 + 3 矩）。把每只手的作用折算到物体质心并按顺序堆起来，可以写成

Fobj = G·f，f = [f1; …; fn] G：抓持矩阵（6×6n），由各抓持点相对质心的位置与朝向决定；Fobj：作用在物体上的净力旋量

G 的零空间（null space）里全是"合力为零"的力组合，它们对物体运动毫无影响，却改变手与工件之间的受力：

G·fint = 0 ⟹ fint ∈ null(G)，力矩总量为零的"内力构型" 一维双臂的直觉：fint = [1, 1]（两手同时向"互相挤压"的方向加力），合外力恰好对消

于是任意一组手部力都可以唯一（在最小范数意义下）分解为"运动分量 + 内力分量"：

f = G+·Fobj + (I − G+G)·fint,des G+：伪逆（把净力按最小范数分配到各手）；(I − G+G)：投影到零空间，用来"注入"想要的内力

工程直觉：把两只手想象成两个人在抬一张桌子，"桌子往哪走"由两人合力的平均值决定，"两人把手往中间挤多紧"是完全另一件事；挤得再紧也不会让桌子自己动，但挤过头会把桌板压裂。抓持矩阵的分解就是把这两件事在数学上彻底分开。一维双臂的极简版：净力 F = fL − fR（方向相反），内力 g = (fL + fR)/2（方向相向），一个是差、一个是和。

2. 控制架构：物体级阻抗 + 内力环 + 逐臂分配

分解之后，控制器自然地分成三层：第一层，物体级阻抗，把工件当成被控对象，用 Mo、Do、Ko 规定它对外力的响应：

Mo(Ẍo−Ẍd) + Do(Ẋo−Ẋd) + Ko(Xo−Xd) = −Fext，Fcmd = 上式左端（期望净力） Xo：物体位姿；这份"净力"由两台手臂分摊

第二层，内力环，对需要保持的夹紧力（防止滑脱或压裂）做闭环：

gcmd = Kp(gdes − gmeas) + Ki∫(gdes − gmeas)dt gmeas：内力估计（由手部力传感或关节力矩估计合成）；PI 保证抓持刚度未知时也能无静差

第三层，分配，每只手的期望力：

fi = Gi+Fcmd + gcmd,i，其中 gcmd 满足 G·gcmd = 0 Gi+：第 i 手对应的伪逆分块；两步都不改变对方的目标

为什么内力环必须用 PI？纯比例差在哪里？因为真实"内部刚度"（工件弹性 + 夹爪柔性 + 手臂等效刚度）未知且随抓持姿态变化：同样 1 N 的内力指令，夹紧点不同需要的相对位移不同。积分项把这份未知"吃掉"，实现无静差夹持；这也意味着内力环天然比位置环慢，带宽必须低。

3. 稳定性：两个回路必须"分时说话"

协同系统里存在两个耦合通道：运动通道（物体级阻抗 + 手臂动刚度）与内力通道（夹持刚度 + 内力环）。稳定性设计的经验法则是时间尺度分离：内力环带宽取 1–5 Hz，而两臂各自的阻抗/位置环带宽在 20 Hz 以上。道理很简单：内力环的"传感器"是手部力，它由相对位置变化产生；如果内力环比产生内力的机械路径还快，PI 就会追着自己的动作振荡，表现为夹紧力来回"呼吸"、工件嗡嗡作响。调参顺序因此固定：先整定单臂柔顺（保证单机稳定），再降低内力环增益直到夹持力曲线平滑无过冲，最后加物体级阻抗的增益。

还有两个工程要点：（1）内力测量需要各手力传感或力矩估计（第 090 章的观测器可以直接复用），双耳传感器的零点和重力补偿（第 091、092 章）在这里是刚需，否则"幻影力"会被内力环当真；（2）通信延迟（双机之间交换参考与力）必须小于内力环周期，典型做法是力信号 1–2 ms 级交换，或退化为"每台本地闭环 + 慢速参考同步"（这正是下一章主从架构的动机）。

4. 代价与适用边界

本章方法的代价有三笔：力传感与通信成本（每只手都要力信息，双机高频交换）；建模依赖（G 需要精确知道抓持点在物体上的位置与朝向，工件尺寸误差会破坏分解精度）；整定复杂度（物体级、内力级、单臂级三层参数）。适用的场景很清晰：精度要求高的协作搬运、需要持续控制挤压力的装配（压装、贴合）、异形件的双面加工。当任务只是"搬到位置、别掉就行"时，用不着这么重，更轻的主从架构（第 095 章）或"一台主控、一台刚度跟随"就足够。

实现思路与设计

  1. 建坐标与 G：以工件为主参考系，标定两只手的抓持点在工件上的位置/朝向（0.5 mm 级），离线计算 G 与零空间基。
  2. 感测：每只手输出接触六维力（腕传感器或第 090 章估计器），先做零点与重力补偿（第 091、092 章）再进入分解。
  3. 分解：控制器每拍算净力 Fcmd（物体级阻抗）与内力期望 gdes（任务给定 8–20 N，按防滑系数 × 工件许用压力确定）。
  4. 内力环参数：Kp = 0.5–1.5、Ki = 1–3 s−1（对应 1–5 Hz 带宽）；输出限幅（|gcmd| ≤ 30 N）；死区取传感器噪声 3σ。
  5. 单臂执行：每臂把 fi 交给自己的柔顺环（第 006/086 章的力控实现或逆动力学）；保持单臂参数不动，只在最外层叠加合作量。
  6. 监督：监控 gmeas 与 Fcmd；内力超限、两臂力方向持续"对冲"（说明参考失配）时报警并降低协作速度。
设计决策：为什么不干脆"让一台机器人硬、一台软"？

把一台设为高刚度"骨架"、另一台设为低刚度"跟随"，确实能压住大部分内力（软的那台主动让步），工程上这叫非对称协作，简单有效。但它牺牲了两件事：（1）软的一台跟踪会差，工件的双重定位精度下降；（2）内力是"被动的": 遇到工件上意外的抗扰（比如贴合面不平）时，刚的一台会硬顶，软的一台让位，工件被推向单侧。对等分解 + 内力显式控制让两臂共同承担误差、内力可见可控，代价是通信与整定。选择标准：看任务是否需要"同时保证精度与受力"，需要就上本章架构。

关键代码与解读

片段 1：双臂力分解与内力环

import numpy as np

def dual_arm_share(F_net, g_des, n_arms=2):
    """把净力与抓持内力分配到两臂（一维模型：G=[1,-1]）。
    净力=两手之差，内力=两手相向分量；两者正交，互不干扰。"""
    share = F_net / n_arms            # 净力均分：两臂同向拉/推
    f_left = share + g_des / n_arms   # 左手 +x：净力份额 + 一份夹紧
    f_right = -share + g_des / n_arms # 右手 -x：净力份额反向 + 一份夹紧
    return float(f_left), float(f_right)

class InternalForceLoop:
    """内力环：PI 调节夹紧力；带宽刻意压到 1-5 Hz，避免与两臂较劲。"""
    def __init__(self, g_des=8.0, kp=0.8, ki=2.0, out_max=30.0, deadband=0.2):
        self.g_des, self.kp, self.ki = g_des, kp, ki
        self.out_max, self.deadband = out_max, deadband
        self.integ = 0.0

    def update(self, g_meas, dt):
        e = self.g_des - g_meas
        if abs(e) > self.deadband:                 # 死区：噪声不驱动积分
            self.integ += e * dt
        corr = self.kp * e + self.ki * self.integ
        return float(np.clip(corr, -self.out_max, self.out_max))

解读：dual_arm_share 的三行就是分解公式在一维下的展开，注意内力分量在两手都是同号相加（相向挤压），而净力分量在两手符号相反，这正是"差=净力、和=内力"的直接实现。内力环里两个设计点：（1）deadband 防止传感器噪声（0.1 N 级）通过积分器积累成虚假夹紧；（2）out_max = 30 N 比"会伤到工件"的夹紧力低一档，保证即使控制出错也不至于压裂薄壁件，协作系统的限幅应当按"最脆弱环节"设计，执行器能力只是上限。

片段 2：双臂持物的一维仿真（含参考失配实验）

def simulate(use_internal_loop=True, n=6000, dt=1e-3):
    """两臂合抱工件：故意让左手参考内偏 10 mm，观察内力与物体运动。"""
    m_h, m_o, k_a, d_a = 1.0, 4.0, 2000.0, 40.0   # 手/物体质量、臂刚度/阻尼
    k_c, w = 5e4, 0.10                             # 抓持界面刚度、握距
    k_env, x_wall = 1e4, 0.02                      # 工件的环境接触（墙）
    loop = InternalForceLoop(g_des=8.0)
    ref_l, ref_r = -w/2 + 0.010, w/2               # 左手参考刻意内偏 10 mm（激励内力）
    x_l, x_r, x_o = ref_l, ref_r, 0.0
    v_l = v_r = v_o = 0.0
    g_log = []
    for i in range(n):
        # 物体对外接触：撞墙即受反向力
        f_env = -k_env * (x_o - x_wall) if x_o > x_wall else 0.0
        # 抓持界面：手与"物体上的抓持点"之间的相对位移产生内力
        comp_l = x_l - (x_o - w/2)
        comp_r = (x_o + w/2) - x_r
        f_c_l, f_c_r = -k_c * comp_l, +k_c * comp_r      # 反作用于手
        g_meas = 0.5 * k_c * (comp_l + comp_r)           # 内力估计（平均挤压量）
        corr = loop.update(g_meas, dt) if use_internal_loop else 0.0
        # 臂命令 = 阻抗回参考 + 内力修正（左手 +corr 挤入，右手 -corr）
        u_l = -d_a * v_l - k_a * (x_l - ref_l) + corr
        u_r = -d_a * v_r - k_a * (x_r - ref_r) - corr
        # 积分：手受臂力 + 界面反力；物体受界面合力 + 环境力
        v_l += (u_l + f_c_l) / m_h * dt
        v_r += (u_r + f_c_r) / m_h * dt
        v_o += (k_c * comp_l - k_c * comp_r + f_env) / m_o * dt
        x_l += v_l * dt; x_r += v_r * dt; x_o += v_o * dt
        g_log.append(g_meas)
    tail = np.array(g_log[4000:])
    return float(np.mean(tail)), float(np.std(tail)), x_o

解读：左手参考被刻意内偏 10 mm，用 Ka = 2000 N/m 的臂刚度换算，等效挤压指令约 20 N；开环稳态下夹紧力约 19 N（远超过 8 N 的防滑设定值，薄壁件可能被压裂）。打开内力环后，PI 反向修正两侧命令，把夹紧力拉回 8 N 附近，而物体位置几乎不动，这就是"内力与运动解耦"的实证：修正量对称相加，净力通道不受影响。（1）comp_l、comp_r 分别表示"左手多挤入"和"右手多挤入"，它们的平均乘 Kc 就是内力估计；（2）手臂命令里 +corr / -corr 的符号保证修正量是"对称相向"的（不产生净力）；（3）末段均值与标准差分别对应"夹紧精度"与"内力平顺度"两个验收指标。

片段 3：参数扫描与稳定性边界

def scan_gains():
    """扫描内力环增益，找"响应快"与"不振荡"的平衡点。"""
    for kp, ki in [(0.4, 1.0), (0.8, 2.0), (1.5, 4.0), (3.0, 8.0)]:
        loop = InternalForceLoop(g_des=8.0, kp=kp, ki=ki)
        g_mean, g_std, _ = sim_with_loop(loop)
        verdict = "过冲振荡" if g_std > 1.0 else "可用"
        print(f"Kp={kp:.1f} Ki={ki:.1f}  夹紧均值={g_mean:5.2f} N  "
              f"波动={g_std:5.2f} N  {verdict}")

def sim_with_loop(loop, n=6000, dt=1e-3):
    """与片段 2 相同的被控对象，仅把内力环换成外部注入的实例（便于扫参）。"""
    # 与片段 2 相同的被控对象，仅替换内力环参数（省略重复代码需与实际一致）
    m_h, m_o, k_a, d_a, k_c, w = 1.0, 4.0, 2000.0, 40.0, 5e4, 0.10
    ref_l, ref_r = -w/2 + 0.010, w/2
    x_l, x_r, x_o = ref_l, ref_r, 0.0
    v_l = v_r = v_o = 0.0; gl = []
    for i in range(n):
        comp_l = x_l - (x_o - w/2); comp_r = (x_o + w/2) - x_r
        g = 0.5 * k_c * (comp_l + comp_r)
        corr = loop.update(g, dt)
        u_l = -d_a*v_l - k_a*(x_l - ref_l) + corr
        u_r = -d_a*v_r - k_a*(x_r - ref_r) - corr
        v_l += (u_l - k_c*comp_l)/m_h*dt; v_r += (u_r + k_c*comp_r)/m_h*dt
        v_o += (k_c*comp_l - k_c*comp_r)/m_o*dt
        x_l += v_l*dt; x_r += v_r*dt; x_o += v_o*dt
        gl.append(g)
    t = np.array(gl[4000:]); return float(t.mean()), float(t.std()), x_o

解读：这段代码的意图是给你一个"扫参—看波动—定带宽"的模板：夹紧力均值接近 8 N 说明静态精度到位，波动 σ 反映内力环的动态品质。经验规律：Kp、Ki 每翻一倍，内力环带宽近似翻倍；当带宽逼近两臂阻抗环（约 5–6 Hz）时 σ 快速上升，映射到现场就是"夹紧力周期性一紧一松"。注意：本片段为控制篇幅把被控对象重复了一遍（真实工程里应该把被控对象封装成类、把环参数作为构造参数传入，练习里会让你重构）。这段的写法故意保留了"重复"的痕迹，正是为了提醒：仿真的可维护性与控制参数一样重要，扫参实验一旦多起来，重复代码会让你付出成倍的代价。

常见坑

  • 两臂参考各自规划：每台机器人独立跟踪自己规划器给的轨迹，几毫米的差异就是几十牛内力。修复：必须有共同的物体级参考（同一时间戳的同一轨迹），再由分解层分配。
  • 内力环带宽过高：与两臂阻抗环同频，夹紧力振荡、工件发热、噪声刺耳。修复：内力环带宽压到 1–5 Hz，Kp 从 0.5 起步慢加；扫参模板见片段 3。
  • 力信号未做零点/重力补偿：幻影力被当内力，PI 把相位"修正"到错误方向，协同比单机更容易出事故。修复：第 091、092 章的流程在协同系统里升级为"每台必做、每次换件必做"。
  • G 矩阵按名义值算，工件有尺寸公差：抓持点偏差让分解出现串扰（想加内力结果推动了物体）。修复：工件定位精度控制在 1 mm 内，或把公差包进"内力死区"里避免误动作。
  • 通信延迟没有预算：双机交换力信号用了 10 ms 级的总线，内力环相位滞后直接吃掉稳定余量。修复：把延迟纳入回路设计（降低增益），或升级同步总线；延迟 > 内力环时间的 1/3 时改主从架构（下一章）。

练习与思考

  1. 写出双臂一维情形下 G = [1, −1] 的零空间（写出两个基向量或说明维数），验证"两臂同向等力"是净力、"两臂相向等力"是内力。★
    提示
    G 是 1×2，零空间维数 1，基可取 [1, 1]T：两手各 +1 的"相向挤压"合外力为零。G[1,1]T=0 一步验证。
  2. 把片段 2 的左手内偏从 10 mm 改到 15 mm，观察"不开内力环"与"开内力环"两种情况的夹紧力与物体位移；解释为什么不开环时物体也可能移动。★★
    提示
    内偏越大，等效挤压指令越大（Ka·δ）；若两手内偏不对称，净力不为零，物体被推向一侧直到某个力（环境、另一臂）平衡。开环时"内力"只是看起来像，实际混着净力。
  3. 用片段 3 的扫描思路，把内力环增益逐步提高到 Kp = 6、Ki = 16，找到"从可用变振荡"的临界增益，并与两臂阻抗环的自然频率比较，验证"时间尺度分离"经验。★★
    提示
    两臂阻抗环自然频率 ≈ √(Ka/mh)/2π ≈ 7 Hz；内力环带宽由 PI 参数近似决定，接近该频率时波动剧增。临界点通常在带宽比 1:3 到 1:5 之间。
  4. 把片段 3 的仿真代码重构为"对象类 + 参数注入"的干净结构（无重复代码），并新增一个指标：从 0.5 s 开始给物体施加 10 N 的外推力，测量内力在扰动下的最大偏离与恢复时间。★★★
    提示
    外推力改变净力，物体级阻抗负责响应；内力环不受影响（这是分解的意义）。若发现内力被外推力"带偏"，说明分解里混入了净力通道，检查 corr 的符号与对称性。

小结

  • 闭环链的数学核心：抓持矩阵 Fobj = G·f 与零空间内力 G·fint = 0；任意手部力 = 最小范数运动分量 + 内力分量。
  • 控制架构三层：物体级阻抗（管运动）、内力环 PI（管夹紧，1–5 Hz）、逐臂分配（份额 + 对称内力修正）。
  • 时间尺度分离是稳定性关键：内力环带宽必须远低于单臂阻抗环；调参顺序为单臂 → 内力环 → 物体级。
  • 工程底座：每臂的力零点与重力补偿、抓持点标定、通信延迟预算；三项任一缺失都会以"幻影内力"的形式爆发。
