第四篇 · 高级柔顺任务与约束

第 078 章：阻抗控制中的速度限制

限速看着简单，剪掉超出的部分就行。但在柔顺控制里，速度出现在两个完全不同的位置（阻尼反馈 vs 命令输出），剪错了地方，轻则路径变形，重则给系统注入能量。

  • 主题：安全约束 / 速度缩放与无源性
  • 关键公式：vlim = vmax·tanh(‖v‖/vmax)·v̂（保方向平滑限速）
  • 预计学时：45 分钟
  • 前置章节：第 077 章（位置限制）

学习目标

  • 分清速度在阻抗控制（反馈量）与导纳控制（输出量）中的两种角色，知道限速应该作用在哪个位置。
  • 理解速度缩放的"无源性红线"：向下缩放（减速）安全，任何放大或保速操作都可能注入能量。
  • 掌握整向量等比缩放与平滑限速器，并解释分轴限幅为什么会改变运动方向。
  • 识别"给反馈速度限幅"这个隐蔽陷阱：它实际上在高速时削弱阻尼。
  • 会做一次简单的能量审计：验证限速环节没有增加系统注入功率。

背景与动机

为什么柔顺控制器必须内置限速？三件事同时要管：安全，贴着人工作时，末端速度是最直接的风险量，比力更容易超值；物理，关节电机和减速器有自己的角速度上限，超出后的后果直接是机械损伤，并不会给出"软件报错"；数值，导纳回路在力信号突变时可能瞬时解出很大的速度修正，不拦住它就变成"机关枪式"的位置指令。

表面上看，限速就是一句 np.clip(v, -vmax, vmax)。但如果仔细推敲，它至少有三个陷阱：（1）分轴 clip 会把斜向运动"折"成轴向运动；（2）clip 的拐角不可导，控制回路里会产生小抖振；（3）最隐蔽的，在阻抗控制里，如果你对反馈的测量速度做限幅，阻尼项在大速度时会被削弱。本章把这些陷阱逐个拆开。

核心原理

1. 速度的两种身份

控制器速度的角色限速的安全作用点限速的禁区
阻抗（力控型）阻尼项 D(ẋ−ẋd) 里的反馈量对生成的力/力矩上限幅（076 章）或对期望轨迹速度限幅别看反了：对"测量速度"限幅 = 高速时阻尼变小 = 更危险
导纳（位置型）导纳方程解出的输出量，直接积分成位置对输出速度做整向量缩放（本章主角）别忘记同时对位置积分做预算（077 章的第三道闸门）

2. 无源性红线：减速安全，加速危险

把机器人与环境交互的能量账写出来：注入系统的功率 P = Fext·v（力沿运动方向做正功）。速度缩放环节要想"不添乱"，只需保证它对能量的影响是减少或保持：

向下缩放 ‖v'‖ ≤ ‖v‖ ⟹ 每周期注入能量不增（耗散效应） 直觉：减速器只会"拉手刹"，它没有任何动力源去"踩油门"

反之，任何试图"补足"速度的操作，比如为了让轨迹好看，把限掉的 30% 在下一周期还回去，都可能把之前耗散的能量再注入系统，在接触环境中表现为"机器人顶着你加速"。限速要么原样放行（未超限），要么只做减法；永远不做补偿。

3. 整向量缩放 vs 分轴限幅：一个几何问题

假设 v = (vx, vy) = (0.3, 0.3) m/s，vmax=0.2。分轴 clip 得到 (0.2, 0.2)，方向没变，但模长 0.283 仍超 0.2；如果 v = (0.4, 0.05)，分轴 clip 得到 (0.2, 0.05)，方向从 7° 折到了 14°，路径被弯曲了。整向量等比缩放则先算 s = v_max/‖v‖，再 v' = s·v：方向和比例被完整保留，代价是所有分量一起减速。

平滑版本用一个连续可导的缩放因子：

vlim = vmax · tanh(‖v‖ / vmax) · (v / ‖v‖) ‖v‖ ≪ vmax 时 ≈ v（几乎无损）；‖v‖ ≫ vmax 时 → vmax·v̂

它的过渡带从原点就开始（缓慢弯曲），换来的是处处可导、零抖振；如果非常介意小信号失真，可改用"线性区+三次过渡"的版本（与 076 章软限幅同族），在 80% 上限内保持严格线性。

4. 反馈速度限幅的陷阱（重点）

阻抗控制里阻尼项 D(ẋ−ẋd)。如果实现了"安全限速"的人顺手写成 xdot_used = clip(xdot, -vmax, vmax) 再代入阻尼项，那么当真实速度超过 vmax 时，阻尼项被钳位不再增长，等效于速度越大、阻尼越弱。物理上这恰恰是"高速时让机器人更自由"，与安全目标背道而驰。正确做法：反馈速度保持原样进入阻尼项（它本来就是耗散项，从不注入能量）；如果确实需要在高速时更强地制动，那就是主动控制问题，应该显式设计非线性阻尼（如 D(ẋ)·ẋ 随速度增大），不能偷偷用限幅实现。

实现思路与设计

  1. 确定限速对象：先画数据流图，标出所有"速度"节点，规划速度、导纳输出速度、关节指令速度、反馈测量速度。默认只对要下发出去的节点限速。
  2. 选 vmax：取三者最小值，安全规程允许的末端速度、任务带宽要求的最小速度、关节极限换算后的可达速度。人机协作场景常取 0.25 m/s 量级起步，纯工业场景可放宽到 1 m/s。
  3. 实现整向量平滑限速器：先算模长与方向，再对模长做"线性+过渡"或 tanh 处理，最后乘回方向（注意 ‖v‖≈0 时方向未定义，直接放行零向量）。
  4. 检查积分器：限速后的速度进入位置积分，同时把"限速缩放比 s = ‖vlim‖/‖v‖"记录进日志，它告诉你限速在多少比例的时间里起作用。
  5. 能量审计（上线前必做）：取一段实测或仿真数据，逐周期比较限速前后的 P = F·v；正确实现满足 |Plim| ≤ |Praw| 且能量流方向不变（限速只缩幅度、不改方向）。逐周期的 Praw − Plim 可正可负（符号跟随 F·v），不构成报警信号；只有幅度被放大或方向被翻转，才说明存在错误的方向修正或"补偿"逻辑。
设计决策：为什么限速后不"归还"被削减的速度？

一种"聪明"的实现是：被限掉的 Δv 存进一个账户，等速度需求回落时慢慢还原，像信用卡一样平滑轨迹。这在纯运动控制里可以谈，但在接触环境中是违规操作：它把耗散掉的动能记成了"欠账"，之后连本带息还给系统，正好抵消了限速在能量上的安全收益。记住红线：限速只做减法，不做会计。

关键代码与解读

片段 1：整向量平滑限速器

import numpy as np

def limit_speed(v, v_max, band=0.2):
    """整向量速度限制：只缩放模长，永不改方向。
    band: 线性区占比。band=0.2 表示 80% v_max 以内完全线性。"""
    speed = np.linalg.norm(v)
    if speed < 1e-9:
        return v.copy()                    # 零向量没有方向，原样返回
    a = v_max * (1.0 - band)               # 线性区终点
    if speed <= a:
        return v                           # 常用区间：零失真
    # 三次平滑过渡：速度从 a 附近滑向 v_max，接缝处斜率为 0
    u = min((speed - a) / (v_max - a), 1.0)
    speed_lim = a + (v_max - a) * (1 - (1 - u) ** 3)
    return v * (speed_lim / speed)         # 沿原方向等比缩放

解读：三行设计逻辑都在注释里，先判零向量（否则除零会把方向放大成噪声）、线性区零失真（常规工况下这一环节"不存在"）、过渡区斜率归零（在 v_max 处与"恒定上限"接得平滑，杜绝拐点抖振）。返回值始终是"同方向的更短向量"，这就满足前面说的无源性红线。

片段 2：分轴限幅的方向失真（对照实验）

v = np.array([0.4, 0.05])          # 主要沿 x、略偏 y 的速度
v_max = 0.2

v_axis = np.clip(v, -v_max, v_max)  # 分轴限幅：(0.2, 0.05)
v_scale = limit_speed(v, v_max)     # 整向量：(约 0.1986, 0.0248)

import math
ang = lambda w: math.degrees(math.atan2(w[1], w[0]))
print("原始方向:", round(ang(v), 2), "度")        # 7.1 度
print("分轴限幅:", round(ang(v_axis), 2), "度，模长", round(np.linalg.norm(v_axis), 3))
print("整向量限速:", round(ang(v_scale), 2), "度，模长", round(np.linalg.norm(v_scale), 3))
# 分轴：方向被折到 14.0 度，且模长 0.206 仍超限！
# 整向量：方向 7.1 度不变，模长 0.200 恰好达标

解读：这个小实验值得亲手跑一遍，分轴限幅不仅弯路径，甚至都不能保证模长满足上限（因为它是逐轴检查的）。对打磨、切边这类对路径几何敏感的任务，7° 的方向偏差积累在 1 m 行程上就是 12 cm 的定位误差。整向量缩放两者都修正。

片段 3：限速环节的能量审计

def energy_audit(v_raw, v_lim, f_ext, dt=1e-3):
    """比较限速前后，外力与系统的功率交换：合法限速只缩幅度、不改方向。"""
    w_raw = float(np.dot(f_ext, v_raw)) * dt   # 假如不限速，外力注入的功
    w_lim = float(np.dot(f_ext, v_lim)) * dt   # 限速后实际注入的功
    return w_raw - w_lim                       # 差值 = 限速"省下"的功率交换（可正可负）

# 正确实现下：v_lim 与 v_raw 同方向且不更长 ⟹ |w_lim| <= |w_raw| 且符号一致；
# 逐周期差值为负只说明该工况外力做负功，不是 bug 信号。
# 若 |w_lim| 被放大或两者反号，才说明限速器做了方向修正或速度放大，违反无源性红线

解读：审计逻辑刻意写得朴素，找 bug 的检查器应该简单到不可能出错。通过条件是"幅度不增、方向不变"：每项满足 |w_lim| ≤ |w_raw| 且同号；逐周期差值本身可正可负（负值对应外力做负功的工况，限速减少了机器人对外做功），并不是 bug。如果幅度被放大或符号被翻转，去检查限速器有没有"分轴"逻辑、有没有"恢复账户"、有没有把方向重新归一化的骚操作。这个审计只需十几行代码，却是上线前最有价值的一道关卡。

常见坑

  • 对反馈速度限幅：阻抗控制的阻尼项大速度时被"钳位"，等效阻尼随速度下降，与安全目标相反。反馈量原样进阻尼项。
  • 分轴限幅：改变运动方向、破坏路径几何，甚至不能保证向量模长达标。永远用整向量缩放。
  • 在多个环节重复限速：规划端限一次、导纳输出限一次、关节指令再限一次，每次都改变一点方向（由于数值误差），累积起来轨迹"形变"。约定唯一的作用点，其他环节只做审计。
  • 零向量除零：‖v‖≈0 时归一化方向 (v/‖v‖) 会把噪声放大成满速。开头判零是必须的。
  • 限速阈值低于任务需求：任务规划要求 0.3 m/s 而限速设了 0.15 m/s，系统会长期停在饱和区，力跟踪的相位滞后显著增大，这与 076 章的"阈值贴近工作点"是同一类错误。

练习与思考

  1. 手算：v=(0.5, 0.1) m/s、vmax=0.25。分别给出分轴 clip 与整向量缩放的结果（保留三位有效数字），并比较两者的方向角。★
    提示
    分轴：(0.25, 0.1)，方向角 21.8°；整向量：缩放因子 0.25/0.5099≈0.4903，得 (0.245, 0.049)，方向角 11.3°。原始角 11.3°，只有整向量保住方向。
  2. 证明：对任意 v 与 vlim = s·v（0 ≤ s ≤ 1），外力注入功率的改变量 F·(v − vlim) 的符号取决于 F·v 的符号，并不恒为正。这说明"限速省能量"的真实条件是什么？★★
    提示
    v − v_lim = (1−s)v，所以 F·(v−v_lim) = (1−s)(F·v)。当外力在"阻碍"运动（F·v < 0）时限速会让外力做的负功变小，即"少吸收了环境给的能量"。这正是限速在接触中的微妙之处：它不一定总是减少机械能，但一定不主动注入。
  3. 在导纳回路里把限速器放在"积分前"与"积分后"分别实现一次，构造一个速度需求突变场景，对比两者位置轨迹的差异。★★
    提示
    积分前限速 = 位置增量本身有界（推荐）；积分后限速可能出现"先冲过头再被拉回"的痕迹。用 1 ms 周期跑 200 ms 的阶跃需求即可看出区别。
  4. 设计一个非线性阻尼替代方案：希望在速度超过 60% vmax 后阻尼逐渐增大（反馈限幅给出的效果是相反方向）。写出 D(v) 的形式，并说明它与"反馈限幅"为什么是互相镜像的错误/正确做法。★★★
    提示
    如 D(v) = D₀(1 + α·max(0, ‖v‖/v_max − 0.6))。反馈限幅是"高速→阻尼减小"的有害组合；非线性阻尼是"高速→阻尼增大"的主动增强，两者在能量审计下符号相反。
  5. 给出一个任务反例：什么情况下"限速"会显著降低力跟踪质量？定量估算：限速导致的最大相位滞后与信号频率 f 的关系是什么？★★★
    提示
    正弦力跟踪需要往复速度；当所需速度幅值 A·2πf 超过 v_max 时，跟踪波形被"削平"。相位滞后 ≈ arcsin(v_max/(A·2πf)) 的一部分，f 越大超限越多，滞后越大。

小结

  • 速度在两处出现：阻抗的阻尼反馈（不要限幅）与导纳的输出（应该限幅），先画数据流图再动手。
  • 无源性红线：限速只做减法；任何"保方向之外"的操作（放大、补偿、归还）都可能注入能量。
  • 实现规范：整向量等比缩放 + 平滑过渡 + 零向量特判；线性区覆盖常用工况。
  • 上线前做能量审计（P=F·v 的逐周期账）：幅度不增、方向不变才算过关。
  • 下一章把限制推进到最底层：力矩限制，它发生在关节侧，经 Jᵀ 映射后在任务空间里表现为方向相关的"削顶"，处理起来比速度难得多。
