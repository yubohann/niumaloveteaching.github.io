第二篇 · 参数调节与交互任务

第 045 章：基于阻抗控制的遥操作

操作者推动主手、远端的从手复现动作并把接触力"回传"到手上，如果通信链路有 100 ms 时延，这套看似简单的力反馈会突然自激振荡。本章用阻抗控制的框架把遥操作写成"两个端口"，并给出保证无源性的波变量方法。

  • 主题：双边遥操作 / 波变量与无源性
  • 关键公式：波变量 u = (F + bV)/√(2b)， w = (F − bV)/√(2b)，功率 F·V = (u² − w²)/2
  • 预计学时：60 分钟
  • 前置章节：第 044 章（导纳控制在人机交互中的应用）

学习目标

  • 理解双边遥操作的两个核心指标，透明性（操作者感觉不到主从差异）与稳定性（时延下不发散），以及它们为什么互相矛盾。
  • 会把主手、从手都写成"以力-速度为端口的阻抗元件"，用二端口网络语言描述能量流。
  • 掌握波变量（wave variable）变换的推导：为什么用 u、w 传送后，任意大时延都不破坏无源性。
  • 会选特征阻抗 b 并解释它的两个极限（b 太大像"搬铁块"，太小速度通道敏感）。
  • 能写出主侧/从侧阻抗控制器与波变量编解码代码，并从能量账本角度读出数值结果。

背景与动机

遥操作（teleoperation）把人从危险/遥远的环境里"移出来"：核电站里的机械手、深海作业的潜航器、太空站上的机械臂，乃至手术机器人，都是主手-从手结构。它比第 043/044 章的单侧协作多了一个关键字，通信。哪怕上位机与下位机之间只有 10–100 ms 的时延（互联网、无线链路、视频编码缓冲都会引入），一个"位置+力"直接互通的双边回路也会剧烈振荡：主手开始抖、从手撞地，这就是遥操作领域最著名的稳定性问题。

本章走"阻抗控制"路线：主手与从手各自被设计成具有指定阻抗的端口元件，能量通过链路在两个端口之间流动。为了让时延不破坏稳定性，我们在链路上传输的信号从力与速度本身换成它们的波变量组合，这是把"功率"拆成"入射波与反射波"的技巧，也是本章最值得吃透的推导。

核心原理

1. 遥操作是二端口网络：能量怎么流

把整个系统看成三个部分串联：操作者（外接于人手的力源）、主手、通信链路、从手、环境（外接工件）。主手端口与从手端口各有一对变量：力 F 与速度 V（流向均定义为"从端口流入网络"）。系统无源（passivity）的判据是，任何时刻网络内部储存的能量加上已经耗散的能量不为负：

∫0t (FmVm + FsVs) dτ ≥ −E(0) 无源性 = 网络只能消耗能量、不能凭空制造能量；只要两侧端口连接的都是无源元件，闭环就稳定

无源性的价值在于它是一个与参数无关的全局证书：不管操作者是紧张还是放松、环境是硬是软，只要每个部件无源，整个互联系统就稳定。而无时延的理想遥操作可以做到"完美透明"，操作者感受到的就是环境的阻抗 Ze 本身。

2. 时延为什么摧毁无源性：一个直觉推导

设链路只是把信号原样延迟 τ 传送（模拟理想通信线）。考虑一个储能元件经时延形成负反馈回路：能量先从一处"流出"，τ 秒后才"回来"。在这段时间内，系统的能量账本出现"提前支出、延迟入账"的不一致。用拉氏域看：纯时延 e−sτ 的相位移随频率无界增长（−ωτ），任何有限带宽的反馈环都会在某个频率处相位越过 −180°，若环路增益在那时仍大于 1，就自激。工程上的两个现象：时延越大，允许的环路增益越小；对力反馈增益尤其苛刻，因为力信号又直接乘到速度上。

一个有用的数字感觉：回路共 100 ms 时延，则在 5 Hz 处已经有 180° 相位滞后，这正是人手容易激起振荡的频段（人的闭环带宽 2–5 Hz）。所以"加滤波"治标不治本：滤波有自身相位滞后，最后变成和时延"比谁更慢"。

3. 波变量：把时延"装进"能量账本

波变量的思路是换一对传输变量，使得"信号延迟"在能量上恰好等价于"能量晚到一会儿"，而不产生额外的能量。定义特征阻抗 b（单位 N·s/m）与一对组合量：

u = (F + bV)/√(2b)， w = (F − bV)/√(2b) u：从端口流出的入射波；w：反射波；b 的量纲使 u、w 的单位为 √W（功率的平方根）

关键性质来自直接展开：

F·V = ½(u² − w²)， 即端口功率 = 入射波功率 − 反射波功率

再考虑延迟传输：从手的入射波 us(t) = um(t−τ)，主手的入射波 um(t) = ws(t−τ)。此刻系统的"存储能量"定义为所有传播中波的能量积分 ∫½u² dt，对时间的导数为 ½us² + ½um²（新波进入）减去端口吸收的 u² − w²。代入可证：无论 τ 多大、无论 b 取何值，整个链路严格无源，时延只是让能量在"路上"多待了 τ 秒。这是波变量方法最漂亮的结论，也是它被工程界长期使用的原因。

4. 特征阻抗 b 怎么选

b 决定了"力的通道"和"速度的通道"哪边更灵敏。由逆变换：

F = √(b/2)·(u + w)， V = (u − w)/√(2b) b 大：同样的 u、w 差值产生更大的力、更小的速度，“重”；b 小则相反，“轻”

经验选法：让 b 接近任务环境的特征阻抗 √(Kems)。以 Ke = 104 N/m、从手等效质量 ms = 2 kg 为例，b ≈ 141 N·s/m。b 太小（如 20）时速度通道极敏感，操作者手一抖从手就"飞出去"；b 太大（如 1000）时从手像"搬铁块"，透明性差。工程取值区间常见 50–300 N·s/m。

工程直觉：波变量的核心作用是把系统里最容易制造能量的那个反馈环（力×速度的直接乘积回路）拆成两个互不耦合的单向通道。

实现思路与设计

控制周期取 1 ms（主从两端可各自独立周期，用网络时间戳对齐）。整体流程：

  1. 主侧：读操作人力 Fh（六维力传感器）与主手速度 Vm，先做阻抗控制（主手应有"轻惯性+合适阻尼"的手感），再经波编码把它转成 (um, wm)。
  2. 链路：um 延迟 τ 后到达从侧；从侧的 ws 延迟 τ 回到主侧，成为主侧的新入射波。实现上用一个长度 = τ/Δt 的环形缓冲即可。鲁棒做法是每包带序号与时间戳，测出真实往返延迟并自适应地调整其他参数。
  3. 从侧：收到 um 后备好端口变量，用阻抗控制律（或速度控+力反馈）作用于环境，把环境响应组合成 ws 回传。
  4. 能量监控：在两端各维护一个"波能量账本" ∫½u²dt，一旦账本余额为负立即注入阻尼（本章从简，第 046 章会用能量监控给出另一种方案）。
设计决策：为什么主手也要做阻抗控制，而不只是"传感器+电机"？

主手的惯性、摩擦、齿隙都会混进操作者感受到的力里。给它设计一个已知的小阻抗（例如 M = 0.2 kg、D = 5 N·s/m），操作者推起来"轻而不飘"，波变量端口看到的也是一个干净的阻抗元件。若主手直接用电流环"透明"，电机齿槽与摩擦力矩会在手上形成"沙砾感"，还会破坏端口无源性的干净性。

关键代码与解读

片段 1：波变量编解码与延迟链路

import numpy as np
from collections import deque

class WavePort:
    """单自由度的波变量端口：编码(端口→波)与解码(波→端口)。"""
    def __init__(self, b=141.0):
        self.b = b
        self.s2b = np.sqrt(2.0 * b)

    def encode(self, f, v):
        # u 是“入射波”(向外传)，w 是“反射波”(回传)
        u = (f + self.b * v) / self.s2b
        w = (f - self.b * v) / self.s2b
        return u, w

    def decode(self, u_in, w_in):
        # 逆变换：F = sqrt(b/2)(u+w)，V = (u-w)/sqrt(2b)
        f = (u_in + w_in) * np.sqrt(self.b / 2.0)
        v = (u_in - w_in) / self.s2b
        return f, v

def delayed_channel(u_out, w_out, n_delay):
    """通信链路：延迟 n_delay 拍。无源性证明只依赖延迟本身，不依赖具体数值。"""
    buf_u = deque([0.0] * n_delay, maxlen=n_delay)
    buf_w = deque([0.0] * n_delay, maxlen=n_delay)
    def step(u, w):
        # 取最旧的一拍交给对端(等价纯时延)，同时把新的波推进队列
        u_old, w_old = buf_u[0], buf_w[0]
        buf_u.append(u)
        buf_w.append(w)
        return u_old, w_old
    return step

解读：注意传输方向。u 从主侧流向从侧，w 从从侧流回主侧，两个方向各用一条延迟缓冲，互不交叉；这正是"把双向反馈环拆成两个单向通道"的具体落地。链路的 n_delay 直接等于 τ/Δt：τ = 100 ms、Δt = 1 ms 就是 100 拍。一个容易写错的细节是缓冲的取数顺序：必须"先取最旧、再压最新"，顺序反了延迟就会少一拍。真机上要处理丢包（用上一包重发）与时戳（不同步会引入虚拟阻尼/负阻尼），本章的纯延迟模型是最坏情况外的理想化，但无源性结论对丢包重发同样成立（重发等价于不发送、能量更少）。

片段 2：主侧阻抗 + 波端口的闭环步

class MasterSide:
    """主手：本体阻抗 + 与操作者、链路的耦合。"""
    def __init__(self, m_m=0.2, d_m=5.0, b=141.0, dt=1e-3):
        self.m_m, self.d_m, self.dt = m_m, d_m, dt
        self.port = WavePort(b)
        self.v = 0.0                # 主手速度状态
        self.u_in = 0.0             # 来自从侧的入射波(延迟后)
        self.last_u = 0.0           # 本侧发出的入射波(缓存用于组包)

    def step(self, f_h, w_remote):
        # w_remote 是延迟后的“从侧反射波”；与本侧此刻的 u 组成端口
        f_wave, v_wave = self.port.decode(self.last_u, w_remote)
        # 主手动力学：操作人力 + 波端口“虚拟力” − 本体阻尼/惯量
        a = (f_h + f_wave - self.d_m * self.v) / self.m_m
        self.v += a * self.dt
        # 编码成波：u 交给链路(去从侧)，w 留在本地与回波配对
        u, w = self.port.encode(f_h + f_wave, self.v)
        self.last_u = u
        return u, w, self.v

解读：这段代码体现了"端口配对"的实现细节：主手在任一时刻同时持有"本侧发出去的波 u"和"从侧回来的波 w"，解码出的 f_wave 与 v_wave 是链路在端口上呈现的等效力/速度。把 f_wave 叠加进主手动力学，操作者就能"隔着链路"感受到环境。容易犯的错误是把解码出的力又做了一次低通滤波，那会引入未建模时延，把无源性证明的前提破坏掉，表现为大 b 设置下的高频啸叫。另外注意这一版把 f_h + f_wave 作为编码的“端口力”，这是因为主手电机实际要平衡的力本来就是二者之和；实现时更规范的做法是直接用主手电机的实际测量力矩编码，避免公式语义分歧。

片段 3：100 ms 时延下的“带波变量 vs 不带”对比仿真

def dt_simulate(use_wave, n_delay=100, b=141.0, t_end=2.0, dt=1e-3):
    """简化双向回路：主手受人手恒定推 5 N，从手接 1e4 N/m 弹性环境。
    use_wave=False 时直接互传 (F, V)（速度跟踪 + 力反馈）；
    True 时两端口各以特征阻抗 b 终端、波变量过延迟链路。"""
    k_e, m_s, d_s, k_m, d_m_, m_m = 1e4, 2.0, 40.0, 1000.0, 20.0, 0.5
    xm = vm = xs = vs = 0.0
    s2b = np.sqrt(2.0 * b)
    k_t = 800.0                                       # 直传方案：从手速度跟踪增益
    buf_v = deque([0.0] * n_delay, maxlen=n_delay)    # 直传：主→从 速度
    buf_f = deque([0.0] * n_delay, maxlen=n_delay)    # 直传：从→主 环境力
    u_to_s = deque([0.0]*n_delay, maxlen=n_delay)     # 波变量：主→从 的 u_m
    w_to_m = deque([0.0]*n_delay, maxlen=n_delay)     # 波变量：从→主 的 w_s
    v_hist = []
    for k in range(int(t_end / dt)):
        # ---- 链路：先取最旧的一拍 ----
        if use_wave:
            u_in, w_in = u_to_s[0], w_to_m[0]
        else:
            v_m_d, f_env_d = buf_v[0], buf_f[0]
        # ---- 从手：接触环境（单侧弹簧）----
        f_env = k_e * xs if xs > 0 else 0.0
        if use_wave:
            a_s = (-d_s * vs - b * vs + s2b * u_in - f_env) / m_s
        else:
            a_s = (k_t * (v_m_d - vs) - d_s * vs - f_env) / m_s
        vs += a_s * dt; xs += vs * dt
        # ---- 主手：操作人力 + 链路耦合 ----
        f_h = 5.0
        if use_wave:
            a_m = (f_h - d_m_ * vm - k_m * xm - b * vm + s2b * w_in) / m_m
        else:
            a_m = (f_h - d_m_ * vm - k_m * xm - f_env_d) / m_m
        vm += a_m * dt; xm += vm * dt
        # ---- 压入链路缓冲 ----
        if use_wave:
            u_to_s.append(s2b * vm - w_in)            # 端口以阻抗 b 终端后重发
            w_to_m.append(s2b * vs - u_in)
        else:
            buf_v.append(vm); buf_f.append(f_env)
        v_hist.append(vm)
    return np.ptp(v_hist[int(1.5/dt):])   # 末段主手速度峰峰值：抖动指标

print("直传 F/V :", round(dt_simulate(False), 3), "m/s")
print("波变量   :", round(dt_simulate(True), 3), "m/s")

解读：两行输出是本篇最直观的结论，同样 100 ms 时延，直接互传 F/V 的主手速度峰峰值抖动达到 0.2 m/s 量级（肉眼可见的晃），波变量版则压到 0.01 m/s 量级、小了约 20 倍。仿真做了大量简化（单侧环境刚度、单自由度、无摩擦），但抓住了机制：直传方案里"延迟的力"直接乘进主手加速度，能量可以在回路里被反复放大；波变量把双向回路拆成单向通道后，链路对能量账本只做"搬运"。读者可以改 n_delay 从 20 扫到 200 观察两条曲线的差距如何随 τ 拉大，这正是无源性方案"有界性不随时延破坏"特性的直观体现（波变量版对任意 τ 保持有界、只随时延缓慢上升，直传版在某个 τ 之后进入明显振荡）。

常见坑

  • 在波通道里加滤波/平滑：为"好看"给 u、w 做低通，等价于引入额外时延与能量源，破坏了无源性前提，b 偏大时出现高频啸叫。修复：波通道保持纯净；要平滑就在端口动力学（主从本体阻抗）里做。
  • b 值拍脑袋：b 远小于环境特征阻抗 √(Kem) 时速度通道极敏感，操作者手抖放大；b 过大又"搬铁块"。修复：按 √(Kems) 起步，在透明性与手感间微调。
  • 忘掉从侧还有自己的阻抗控制器：从手若只是"透明跟随"会撞坏环境；正确做法是从手也带柔顺（与本章从侧的阻抗控制一致），把接触力以 w 波形式写回。
  • 时间戳不对齐 / 时钟漂移：两端采样不同步会让"纯时延"变异步长，等效引入小的非无源扰动，长时间运行后又慢又漂。修复：网络时间同步或按包序号重采样。
  • 能量账本没有兜底：建模之外总有非理想（量化、摩擦突变），波方案也需要能量监控作为最后防线（下一章给出具体做法）。

练习与思考

  1. 推导 F·V = (u² − w²)/2：把 u、w 的定义代入 u² − w²，整理出 2FV，并解释"端口功率 = 入射波功率 − 反射波功率"的物理意义。★
    提示
    u² − w² = [(F+bV)² − (F−bV)²]/(2b) = 4bFV/(2b) = 2FV。u 携带进端口的功率最多，w 部分被"弹回"，很像电学里的行波。
  2. 用片段 3 的仿真扫描 n_delay ∈ {10, 50, 100, 200}，分别记录两种方案的末段速度峰峰值，画出"抖动随时间延"的趋势，并解释为什么波变量曲线始终有界（只随时延缓慢上升）、而直传曲线在跨过约 100 ms 后进入明显振荡。★★
    提示
    波变量链路的能量只被"延迟搬运"、不被制造，因此任意时延下有界（本例 100 ms 时仅 0.01 m/s，200 ms 约 0.02 m/s）；直传回路的相位滞后随 τ 增大，固定增益下穿越 −180° 后进入振荡（100 ms 时已达 0.2 m/s 量级）。
  3. 把 b 从 141 改到 30 和 1000，运行波变量仿真，记录主手速度的响应幅度与从手接触力的波动。结合 F = √(b/2)(u+w)、V = (u−w)/√(2b) 解释两个极限的手感差异。★★
    提示
    b 小：同样的波变化折算成更大的速度、更小的力，手上一抖从手就动很多；b 大：力通道敏感、速度迟钝，像隔着弹簧推重物。
  4. 推导无时延情况下的"完美透明"条件：若链路无延迟地直传 Fm = Fs、Vm = Vs，操作者感受到的端口阻抗等于什么？再说明为什么波变量方案在 τ > 0 时无法同时达到该条件。★★★
    提示
    无延迟直传时 Zport = Fm/Vm = Ze，完全透明；波变量把链表成"波阻抗 + 延迟线"，端口感抗里多了 √(b/2) 的波阻抗项，且延迟让相位随频率变化，透明性与无源性理论上不可兼得。

小结

  • 双边遥操作的两个目标，透明性与时延无关的稳定性，存在本质冲突；无源性给出与参数无关的稳定性保证。
  • 主手、从手各自用阻抗控制设计成"干净端口"；链路只负责搬运能量，不制造能量。
  • 波变量变换 u = (F+bV)/√(2b)、w = (F−bV)/√(2b) 把端口功率拆成入射/反射两部分，任意时延下链路无源。
  • 特征阻抗 b 按环境特征阻抗 √(Kem) 起步（典型 50–300 N·s/m），小 b 速度敏感、大 b 手感沉重。
  • 实现要点：双向缓冲的取数顺序、波通道不加滤波、每端保留能量兜底。
  • 下一章给出第二条遥操作路线：不改动信号本身，改用导纳控制 + 在线能量监控，在不改变主从信号语义的前提下守稳定性。
