第 092 章：阻抗控制中的工具重力补偿

力传感器测到的第一大力来自工具自重，与接触无关；1.8 kg 的工具就是 17.7 N，和你的接触力目标同一量级。本章用量纲分明的最小二乘把工具质量、质心与零点一次性辨识出来，再在每个控制周期里按当前姿态解析剥离，让阻抗控制器只看见"接触"。

  • 主题：工具重力补偿 / 静态参数辨识
  • 关键公式：Fmeas = m·(RTg + as) + bf + Fcontact；τg = rc × (m·RTg)
  • 预计学时：60 分钟
  • 前置章节：第 091 章

学习目标

  • 理解为什么重力补偿是力控任务的"第一优先级"：工具自重与接触力量级相当，且随姿态变化，不补偿，姿态一变就是几牛的幻影力。
  • 会写出传感器坐标系下的重力/力矩测量模型：力项关于 [m, bf] 线性、矩项关于 [m·rc, bτ] 线性。
  • 会用静态多姿态最小二乘辨识工具质量 m、质心 rc 与六维零点 b，并理解"姿态多样性"是辨识可解性的前提。
  • 会在控制回路里实现 1 kHz 的在线补偿：R 来自运动学、g 用 9.81、补偿顺序先重力后零点再进导纳/阻抗。
  • 知道动态项（惯性力 m·a、角加速度项）什么时候必须加、什么时候可以忽略，以及它们的代价。

背景与动机

上一章把零点标到了 0.2 N 以内，但一装上工具，零点立刻"失效"，问题不在零点，而在工具重力：腕部力传感器装在手与工具之间，工具的全部重量、以及绕传感器原点的重力矩，都会被它测到。数量级感受一下：1.8 kg 的打磨头 = 17.7 N；而典型接触力目标是 10–30 N。也就是说，不补偿的话，你的力信号里"噪声"比"信号"还大，且这份"噪声"随手腕姿态不断变化：从竖直向下转到水平，重力在传感器各轴上的投影从头到尾走一个完整的正弦，幻影力±17.7 N。

阻抗控制的后果很直接：控制器会把工具重力当成"环境在推我"，于是姿态一动，机器人就自动让位，打磨压力漂移、示教拖动"自己会跑"、装配时对准精度崩坏。导纳控制的后果更糟：这是第 091 章的"偏置 → 爬行"链，只是偏置从 0.5 N 变成了 17.7 N，爬行速度直接放大 35 倍。

解决办法是解析补偿：辨识工具的质量与质心，在每个控制周期按当前姿态算出重力旋量，从六维读数里减掉（"标定时把工具重力一键清零"的做法一换姿态就失效）。本章的最小二乘辨识只需要机器人自己摆十几个姿态、记录传感器读数，不需要额外仪器，五分钟可以完成。

核心原理

1. 测量模型：传感器到底测到了什么

设 R 为传感器坐标系到世界坐标系的旋转矩阵（由机器人运动学实时给出），世界重力向量 g = [0, 0, −9.81]T m/s²，工具质量 m（kg），工具质心在传感器坐标系中的位置 rc（m）。先把"重力在传感器坐标系中的表达"写出来：

gs = RT·g 同一根重力矢量换一个坐标系表达，姿态一变，它在三个轴上的分量就变，这就是"幻影力"的来源

忽略动态项时的测量模型（先只看静态）：

Fmeas = m·gs + bf + Fcontact；τmeas = rc × (m·gs) + bτ + τcontact bf、bτ：六维零点（上一章的系统偏置，包含在这一模型里一起辨识更稳）

目标是从 Fmeas、τmeas 里解出 Fcontact、τcontact，前提是知道 m、rc、b。姿态 R 是已知的（运动学），g 是常数，所以剩下四个未知量（标量 m + 向量 bf、bτ + 向量 rc，共 1+3+3+3 = 10 个标量）必须在几个不同姿态下用读数反推。这就是静态辨识的全部原理。

2. 为什么能最小二乘：两组线性方程

关键观察：模型对未知量是线性的，甚至天然分成两个独立的小问题。力方程每采集一个姿态 i 提供一个三行方程：

Fmeas,i = [ gs,i | I3 ]·[ m ; bf ] 未知量 θf = [m, bfT]T（4 个）；gs,i 随姿态变化

力矩方程用"叉乘的反对称矩阵形式"（S(v)u = v × u）改写，也能对未知量线性化：

τmeas,i = −S(gs,i)·(m·rc) + bτ = [ −S(gs,i) | I3 ]·[ c ; bτ ]，c ≜ m·rc 未知量 θτ = [c, bτT]T（6 个）；解完再除质量得质心 rc = c/m

为什么姿态要"多样"？如果所有采集姿态都相同，gs,i 是同一个向量，力方程里"质量"与"零点 z 分量"完全没法区分（质量产生的力和零点产生的力长得一模一样），只有让重力在传感器各轴上的投影发生变化，两个未知量才能被分开。经验做法：采 12–20 个姿态，让工具指向均匀分布（含竖直、水平、倒置与若干倾斜），辨识的噪声敏感度会显著降低。

3. 动态项：什么时候必须加

完整模型还要包含运动产生的惯性载荷：

Fmeas = m·(gs + as) + bf + Fcontact，τmeas = rc × m(gs+as) + I·α + ω×(I·ω) + bτ + τcontact as：传感器原点的加速度（传感器系）；ω、α：角速度与角加速度；I：工具转动惯量

数量级判断：停止/匀速阶段 as ≈ 0、ω ≈ 0，静态模型足够；当加速度超过约 1 m/s² 或角速度平方项超过 0.5 m/s² 时，动态项开始超过 0.1 N 级噪声，需要加补偿。而动态补偿的代价是：要加速度估计（差分噪声大，需滤波）、要辨识转动惯量张量（需要更丰富的激励运动）、还引入了相位滞后。工程直觉：先看任务，慢速接触（< 0.1 m/s、角速度 < 30°/s）只做静态补偿；高速打磨、快速插拔再上动态项，且必须用滤波后的加速度。本章聚焦静态部分，动态项作为扩展说明。

4. 补偿与控制器的关系、辨识误差的账

补偿要在控制链的最前端：Fcontact = Fmeas − m·gs − bf，得到"纯接触"旋量后再送进阻抗/导纳方程。辨识误差如何影响控制？把误差拆开看：质量误差 Δm 产生随姿态摆动的力误差 Δm·g·cosθ；质心误差 Δrc 只影响力矩通道，对平移接触力无直接影响（在传感原点处）；零点误差是所有姿态下恒定的偏置（回请第 091 章的爬行公式）。所以质量的辨识精度比质心更值钱：Δm = 0.05 kg 在转速带来的最坏姿态下产生 0.49 N 摆动误差；用 12 个姿态、0.1 N 级噪声，最小二乘通常能把 Δm 压到 0.02 kg 以内。

实现思路与设计

  1. 建立坐标系约定：明确传感器坐标系定义（哪个方向是 +z）、R 由哪个变换链给出（通常 R = Rbase→sensor，即把世界向量变到传感器系用 RT）。约定写进注释并画一张图，这一行文档能节省半天的调试。
  2. 采集姿态：机械臂自动摆 12–20 个姿态（竖直、水平四个方向、两个倒置、若干 30°/60° 倾斜），每个姿态静止 0.5 s，平均值入库；同时记录运动学给出的 R。
  3. 辨识：按片段 1 的两个最小二乘求解；检查条件数（姿态多样性差时条件数大，需补姿态）；输出 m、rc、bf、bτ。
  4. 验收：在若干未参与辨识的姿态上验证残差：接触力通道 < 0.3 N、力矩通道 < 0.05 N·m；超差先查姿态采集质量与线缆。
  5. 在线补偿：1 kHz 控制周期里，由运动学取 R → 计算 gs → 求 fg、τg → 减法 → 得到接触旋量送控制器（片段 2）。
  6. 变更管理：任何工具更换、加装配件、线缆改走之后必须重新辨识（工具参数进配置库，按"工具 ID"切换）；温度导致的 m 漂移通常可忽略，零点漂移交给上一章的运行时跟踪。
设计决策：为什么用"多姿态辨识"？查工具手册为什么不够？

手册给的质量与质心是出厂值：装夹法兰、夹爪、锁紧螺栓、护罩、气管接头都不在手册里；实际"工具"其实是整条末端链。多姿态辨识的价值在于：它测的是"传感器到工具尖端的全部质量分布"的整体等效参数，并不局限于零件本身，并且顺便把六维零点一起更新，这恰好是控制需要的量。它还有一个隐性的鲁棒性好处：辨识是数据驱动的，哪怕工具里藏着不明配件也照样准确。

关键代码与解读

片段 1：静态多姿态最小二乘辨识

import numpy as np

def skew(v):
    """叉乘的矩阵形式：S(v)u = v x u。"""
    return np.array([[0.0, -v[2], v[1]],
                     [v[2], 0.0, -v[0]],
                     [-v[1], v[0], 0.0]])

def identify_tool(poses, g_val=9.81):
    """静态辨识工具质量、质心与六维零点。
    poses: 由 (R, f_meas, t_meas) 组成的列表；R 为传感器系到世界系的旋转。"""
    g = np.array([0.0, 0.0, -g_val])
    A_f, y_f, A_t, y_t = [], [], [], []
    for R, f_m, t_m in poses:
        g_s = R.T @ g                                   # 重力在传感器系中的表达
        # 力方程：F = [g_s | I] * [m; b_f]（对未知量线性）
        A_f.append(np.hstack([g_s.reshape(3, 1), np.eye(3)]))
        # 矩方程：tau = [-S(g_s) | I] * [m*r_c; b_tau]
        A_t.append(np.hstack([-skew(g_s), np.eye(3)]))
        y_f.append(f_m)
        y_t.append(t_m)
    th_f, *_ = np.linalg.lstsq(np.vstack(A_f), np.hstack(y_f), rcond=None)
    th_t, *_ = np.linalg.lstsq(np.vstack(A_t), np.hstack(y_t), rcond=None)
    m_tool, b_f = th_f[0], th_f[1:]
    r_c = th_t[:3] / m_tool          # 一阶矩 c=m*r_c 除以质量得到质心
    b_tau = th_t[3:]
    return m_tool, r_c, b_f, b_tau

解读：这段代码把"物理推导"几乎逐行翻译过来，三个细节值得强调。（1）为什么力和矩可以分开解？因为力方程不含 rc、矩方程不含 bf，两个问题解耦，各自 4 和 6 个未知量。（2）skew(g_s) 前面的负号来自叉乘恒等式 a×b = −S(b)a，写错负号会让辨识出的质心镜像到错误象限（一个常见且难查的错误）。（3）np.linalg.lstsq 的 rcond=None 是新版 NumPy 的标准用法；若姿态多样性不足，矩阵接近奇异，好用习惯是同时打印 np.linalg.cond(A)，条件数 > 100 就补采集姿态。

片段 2：在线重力补偿（控制链最前端）

class GravityCompensator:
    """按当前姿态解析剥离工具重力：控制周期的第一个环节。"""
    def __init__(self, m_tool, r_c, b_f, b_tau, g_val=9.81):
        self.m = float(m_tool)
        self.r_c = np.asarray(r_c, dtype=float)
        self.b_f = np.asarray(b_f, dtype=float)
        self.b_tau = np.asarray(b_tau, dtype=float)
        self.g = np.array([0.0, 0.0, -g_val])

    def step(self, R, f_meas, t_meas):
        g_s = R.T @ self.g                  # 姿态每变一点，这里的三个分量就跟着变
        f_g = self.m * g_s                  # 工具重力的力读数（N）
        t_g = np.cross(self.r_c, f_g)       # 重力对传感器原点的矩（N*m）
        # 先减重力（姿态相关）、再减零点（姿态无关）；顺序固定，便于审计
        f_c = np.asarray(f_meas) - f_g - self.b_f
        t_c = np.asarray(t_meas) - t_g - self.b_tau
        return f_c, t_c

解读：在线补偿的计算量是"一个 3×3 转置乘 + 一次叉乘"，在任何控制周期里都微不足道，所以没有理由用"低通平均"之类的近似来偷懒，直接每个周期精算。R 从运动学实时取（由关节角与工具标定得到），不需要额外传感器。注意输出的是"接触旋量"，它会直接进入第 083/085 章的导纳方程与滑模外环；如果下游用 Fd − Fmeas 形式，就把 f_c、t_c 当作 Fmeas 使用。另外：重力和零点的减法顺序不影响数学结果，但固定顺序能让日志审计与现场排查有据可依。

片段 3：辨识质量的验证实验

def make_pose_data(n_pose=15, m=1.8, r_c=(0.02, -0.01, 0.09), bias_f=0.8,
                   bias_t=0.05, noise=0.08, seed=3):
    """合成一批静态姿态数据：已知真值 + 零点 + 噪声，用于自测辨识流程。"""
    rng = np.random.default_rng(seed)
    g = np.array([0.0, 0.0, -9.81])
    poses = []
    for _ in range(n_pose):
        w = rng.normal(size=3); w /= np.linalg.norm(w)
        R = _rot(w, rng.uniform(0.0, np.pi))        # 随机姿态（角轴表示）
        f = m * (R.T @ g) + np.array([0.0, 0.0, bias_f]) + rng.normal(0, noise, 3)
        t = m * np.cross(r_c, R.T @ g) + bias_t + rng.normal(0, noise, 3)
        poses.append((R, f, t))
    return poses

m_hat, r_c_hat, b_f_hat, b_t_hat = identify_tool(make_pose_data())
print(f"质量估计 {m_hat:.3f} kg（真值 1.800）")
print(f"质心估计 {np.round(r_c_hat, 4)} m（真值 [0.02 -0.01 0.09]）")
print(f"力零点 {np.round(b_f_hat, 3)}（真值 z=0.8）")

解读：这是"先自测再上机"的标准套路，用已知真值生成带噪声的姿态数据，跑一遍辨识流程，看估计值能不能回到真值附近。如果连自测都偏，说明公式或矩阵拼装有错（最常见的就是 skew 的符号和 R.T 的方向）；自测通过再上真机，能把"数据问题"与"算法问题"分开。_rot 是角轴到旋转矩阵的小工具（可用 Rodrigues 公式实现，两行即可）。上真机时把 make_pose_data 替换成"采集真实姿态与读数"的逻辑即可，其余代码原封不动。

常见坑

  • R 的方向搞反：写成 R·g（正确形式为 RT·g），补偿量在错误方向加减，最坏情况把幻影力放大一倍。修复：用"工具竖直朝下时 gs 应主要在 −z 或 +z 轴"做单元检查。
  • 质心辨识符号错：skew 前的负号漏掉，rc 变成镜像位置，力矩通道补偿完全失效。修复：用片段 3 的自测实验在合成数据上验证符号。
  • 姿态单一：只在几个接近竖直的姿态采集，质量与零点不可分辨，估计值随噪声乱跳。修复：姿态覆盖两个半球、若干倾角；采集时检查条件数。
  • 动态段忘记切换：在快速运动段仍用静态模型补偿，惯性力（m·a）被留下变成"接触力"，导纳控制器就会误以为在受推。修复：运动段（|a| > 1 m/s² 或角速度大）要么停用力控，要么启用动态项并低通。
  • 换工具不重辨识：换砂轮、换夹爪后沿用旧参数，误差直接进入力环。修复：工具参数与"工具 ID"绑定，换装流程自动提示重新辨识（把这段写进工艺文件）。

练习与思考

  1. 推导叉乘恒等式 (m·rc)×gs = −S(gs)·(m·rc)，并说明为什么这使力矩辨识变成线性最小二乘。★
    提示
    用 (a×b) = −(b×a) = −S(b)a；线性化的关键是"未知量 c = m·rc 与已知量 gs 分离"。
  2. 取 m = 1.8 kg，计算工具从"竖直向下"转到"水平"过程中未补偿时传感器各轴读数变化的范围，并与 15 N 的接触力目标比较，说明为什么"不补偿等于没传感"。★
    提示
    重力在轴上的投影按 sin/cos 过渡，单轴变化范围可达 ±17.7 N 的完整正弦；接触力目标 15 N 完全被淹没，且幻影力的方向由姿态决定，控制器无从分辨。
  3. 用片段 3 的自测代码，把噪声从 0.08 N 增到 0.3 N、把姿态数从 15 减到 6，观察质量与质心估计误差的变化，总结"姿态数—噪声—精度"的三角关系。★★
    提示
    LS 估计误差 ∝ 噪声/√N 与姿态矩阵条件数共同决定；姿态数少且集中时条件数恶化，误差随噪声线性放大。
  4. 设计"带动态项"的扩展实验：让机器人做频率 1 Hz、加速度峰值 2 m/s² 的正弦往复，比较"静态补偿"与"加 m·a 项（加速度低通 20 ms）"两种补偿的残差。给出启用动态项的判据。★★★
    提示
    静态补偿下惯性力残差约 m·a = 3.6 N（远超接触力精度要求）；动态项可以压到 0.3 N 量级，代价是加速度估计的相位滞后（低通 20 ms ≈ 在 1 Hz 处滞后 7°），设计上可接受。

小结

  • 工具重力与接触力同量级且随姿态变化，是力控的第一大干扰源；"清零式标定"换姿态即失效，必须解析补偿。
  • 静态模型：Fmeas = m·RTg + bf + Fc，τmeas = rc×(m·RTg) + bτ + τc；力通道辨识 [m, bf]、矩通道辨识 [m·rc, bτ]，两组最小二乘相互独立。
  • 姿态多样性是可辨识性的前提；12–20 个覆盖两个半球的姿态、验收残差 ≤ 0.3 N / 0.05 N·m。
  • 在线补偿在控制链最前端、每帧精算；动态项在加速度 > 1 m/s² 时才需要。
