第五篇 · 鲁棒控制与工程实践

第 099 章：导纳控制中的紧急回退

停住不等于脱险：手被夹在机械臂和夹具之间时，机器人必须"离开"，"站住"无济于事。紧急回退沿已验证安全的历史路径反向撤离，全程保持柔顺与力守卫，方向对了就撤得干净，方向错了（槽里、反向也有障碍）守卫会立刻中止并升级处理。

  • 主题：紧急回退（emergency retract）/ 力守卫撤离
  • 关键公式：d回退 = F/K̂env + d净空，fguard = 1.5×f触发
  • 预计学时：60 分钟
  • 前置章节：第 098 章

学习目标

  • 理解紧急回退与安全停止的触发条件与执行策略差异：前者是"物理分离动作"，后者是"原地受控停滞"。
  • 会从历史轨迹选择回退方向，并解释为什么"反向沿轨迹"优于"反向外力方向"。
  • 会计算回退距离预算 d = F/K̂env + d净空，并设计两阶段撤离（PULL 释放 → CLEAR 留净空）。
  • 会实现力守卫：撤离中力超 fguard 即中止并升级，理解"回退本身也可能撞上第二个约束"的现实。
  • 能说清回退完成后的重新武装流程与数据记录要求，让每次回退都成为事故复盘的素材，避免被遗忘。

背景与动机

上一章的安全停止把机器人"钉"在了安全区里，但有一类事故是"钉住"解决不了的：夹持/挤压。人手、电缆、工件被夹在机器人与夹具（或另一台机器人）之间时，停止只会让压力持续存在；操作员需要的是机器人主动"松开并撤出去"。同理，轻度碰撞后原地保持虽然安全，但如果障碍物（比如移动过来的 AGV）还在逼近，站着不动就是等撞。这些场景的共同需求是：沿一个安全方向做一段受控的撤离运动。

回退看似简单，"原路返回"谁不会？工程上的难点全在细节：往哪个方向退才是安全的？退多远才够？退的过程里如果又碰到东西怎么办？这三个问题对应本章的三块内容：方向选择（用历史轨迹，不靠力方向）、距离预算（穿透量 + 净空）、力守卫（撤离中力超限立即中止）。把这三件事做对，回退才是一个"安全动作"；做不对，回退本身就会变成新的事故源。

与第 098 章的接口先说清：碰撞检测（第 097 章）判定事件等级，轻度 → 安全停止（在原地柔顺保持），重度/二次事件/夹持救援 → 紧急回退。两条链路共享同一个状态机框架（第 098 章），只是执行的动作不同。

核心原理

1. 触发条件：什么时候必须"离开"

回退的触发集合比停止更窄也更紧急，典型有四类：（1）重度碰撞，第 097 章的残差超阈值 2 倍以上，或短时间内出现二次事件；（2）夹持救援，人机协作中人手被夹、或力持续高于人体安全阈值且不下降（停止后 100 ms 内仍高于阈值即升级为回退）；（3）持续过力，安全停止后接触力维持在触发值附近不衰减（说明压着的东西不会自己走）；（4）环境逼近，外部目标（AGV、移动工件）持续压缩安全距离。四类的共同点是：空间关系需要被改变，"停在原地"无法解除危险。

注意触发与停止的"级别顺序"：回退以停止为前提（先受控减速到低速，再开始撤离），不能"边冲边退"，带着残余速度反转方向，等于把一个方向的动量搬到另一个方向，控制上更危险。

2. 方向选择：历史轨迹是"已验证的通路"

最自然的想法是"沿着力传感器测到的力反向撤"，力的方向和障碍物的方向一致，听起来最合理。它错在两点：（1）接触中测到的力受摩擦、约束、姿态影响，方向可能是"斜着"的甚至被约束投影扭曲（楔形夹持时更明显）；（2）就算方向正确，那个方向上什么情况也是未知的。更可靠的信息来源是历史：机器人刚刚从某个方向走过来，这条路径是刚刚被物理验证过"无碰撞"的，沿着它反向撤离是成本最低、风险最小的选择。实现上维护一个"命令轨迹环形缓冲"（比如最近 200 ms），回退方向 = 从当前点到历史点的方向：

uretreat = normalize( x(t−Thist) − x(t) ) Thist 取 100–300 ms（覆盖减速前的安全路径段）；任务刚开始、无历史时退化为"反向最后命令速度"

如果历史方向也不可用（首次接触就出事、或轨迹本身在夹缝里），系统需要停在一个"待救援"状态，由人或高层决策给出方向，千万不要"猜一个方向自动撤"，错误方向的自动回退比不动作更危险（下面的力守卫就是为了给这种情形兜底）。

3. 距离预算与两阶段撤离

退多远才"松"？接触力来自穿透量：F ≈ K̂env·h（h 为压入深度）。要释放接触，至少要撤出 h = F/K̂env；再加一段净空，让工件/人手有活动的余地：

d回退 = F/K̂env + d净空 例：F = 40 N、K̂env = 104 N/m ⟹ 穿透 4 mm；净空取 20 mm，总回退 24 mm

两阶段撤离把"松"和"留空间"分开：PULL 阶段，低速（50–200 mm/s）撤离，直到接触力降到释放阈值（如 2 N，即 2% 量级的接触），说明接触解除；CLEAR 阶段，继续沿同方向再撤 d净空，形成物理间隙，防止"刚松开又蹭上"。两阶段的判据不同（力判据 vs 距离判据），对应两个不同的目标（释放 vs 净空），这比"固定撤 N 毫米"更适应不同工件刚度：软工件穿透深、回退距离自动变长。

4. 力守卫与升级：回退也会撞东西

真实的夹持常是"双向"的：在槽里、在两面夹具之间，往回撤可能撞上第二个约束（或者按错的路径撞上新的东西）。因此撤离过程必须有自己的守卫：

若 |F| > fguard = 1.5×f触发（或 1.5×人体限值）：立即停止撤离、保持柔顺、升级为"待救援" 同时监控力的方向：若力方向与撤离方向同号（越撤越压），即使幅值未超限也应中止

力守卫的阈值取 1.5 倍触发值，不再取更高，理由与第 098 章的"不对称门限"相同：回退是一个主动运动，如果它在把系统推向更危险的状态，越早停越好。升级后的"待救援"状态可以做的动作有：切到更柔顺的参数（最小刚度、最大阻尼）、输出视觉/声音提示、请求人工/远程干预，但不再自动移动。此外，撤离期间保持阻抗柔顺（小刚度、低带宽）是安全前提：硬碰硬地"倒车"会把反向约束的碰撞变成又一次事故；柔顺撤离让反向接触"推得开、停得住"。

工程直觉：紧急回退是一个"保守的、经过验证的、带保险丝的动作"，方向用验证过的历史，距离用物理公式算，过程中用守卫兜底。整个动作宁可慢、宁可短，也不创造新的错误。这条原则与第 098 章一脉相承：安全动作的正确性来自"每一步都有依据"，不靠"动作足够快"。

实现思路与设计

  1. 触发链：第 097 章的等级输出（重度）或第 098 章停止后仍持续过力 → 进入 RETRACT；先完成减速（复用第 098 章的 DECEL），低速后开始撤离。
  2. 历史缓冲：以 1 kHz 记录命令位置，环形缓冲 100–300 ms；接口化（把"方向来源"做成可替换模块，便于多机/移动平台扩展）。
  3. 速度与距离：撤离速度 50–200 mm/s（建议为任务速度的 1/5 以下）；d净空 = 10–30 mm（按工件尺寸与夹具结构给）；回退距离随实测力动态延长。
  4. 力守卫：fguard = 1.5×触发值，另加"力方向与撤离方向同号"的直接中止条件；守卫动作有优先级，中止撤离 > 保持柔顺 > 等待人工。
  5. 柔顺参数：撤离期间使用低刚度（Kd × 0.3）、中阻尼；禁止高刚度的"硬倒车"。
  6. 结束与恢复：CLEAR 完成 → 状态置 HOLD/WAIT；记录完整事件数据（触发原因、r 峰值、方向、距离、时长、守卫是否触发）；人工确认 + 自检（第 098 章流程）后低速重入任务。
设计决策：为什么净空距离不能并入"力释放"判据？

有人想简化成一个条件："力降到阈值就停"。这会留下一个隐患：接触解除的瞬间，回退立刻停止，机器人停在"刚好不接触"的边界上，工件热变形、工件被夹爪挪动一丝、或者下一次任务的定位误差，都可能立刻再碰上。净空是"物理安全间隙"，它必须是与力无关的固定距离（比如 20 mm），因为它的作用是为"接下来所有的动作与误差"留出不接触的余量，并不止于解除当前的力。同理，净空也不应过大（回退 200 mm 会浪费时间、离开工作区），10–30 mm 是常见折中；这个数应当写进单元设计文件，与工件公差、定位误差一起核算。

关键代码与解读

片段 1：回退规划器（历史方向 + 两阶段 + 力守卫）

import numpy as np

class RetractPlanner:
    """紧急回退规划：沿历史安全方向撤离，PULL、CLEAR 两阶段，力守卫中止。"""
    def __init__(self, speed=0.1, clearance=0.02, f_release=2.0, f_guard=60.0,
                 hist_len=200, dt=1e-3):
        self.speed, self.clearance = speed, clearance
        self.f_release, self.f_guard = f_release, f_guard
        self.hist, self.hist_len, self.dt = [], hist_len, dt
        self.phase = "PULL"           # PULL 到 CLEAR，终态 DONE 或 ABORT
        self.x_clear = None

    def push_history(self, x_cmd):
        self.hist.append(x_cmd)       # 每拍记录"已验证"的命令位置
        if len(self.hist) > self.hist_len:
            self.hist.pop(0)

    def direction(self, x):
        # 历史最短 50 ms 才可信；否则用"后退 10 mm"作保守方向
        if len(self.hist) >= 50:
            x_back = self.hist[0]
            if abs(x_back - x) > 1e-4:
                return np.sign(x_back - x)
        return -1.0

    def step(self, x, f_mag, dt):
        if self.phase in ("ABORT", "DONE"):
            return 0.0
        if f_mag > self.f_guard:               # 守卫：撤离不得让力继续变大
            self.phase = "ABORT"
            return 0.0
        d = self.direction(x)
        if self.phase == "PULL":
            if f_mag < self.f_release:         # 力判据：接触已解除
                self.phase = "CLEAR"
                self.x_clear = x + d * self.clearance
            return d * self.speed
        # CLEAR：距离判据，形成 20 mm 物理净空
        if (x - self.x_clear) * d >= 0.0:
            self.phase = "DONE"
            return 0.0
        return d * self.speed

解读：（1）类里同时保留了两种判据，f_release（力）管"松开"，clearance（距离）管"净空"，这属于分工，不算冗余，见上文设计决策。（2）direction() 的 50 ms 最小值防止"刚启动就出事"时历史太短、方向被单点噪声带偏；无历史时退化为保守的反向。（3）守卫放在所有逻辑的最前面：一旦 ABORT，后续任何调用都只返回 0，故障状态的自锁是安全代码的通用模式（第 098 章的 FAULT 同理）。（4）注意 push_history 记录的是命令位置，不用实测位置：命令轨迹反映的是"控制器意图走的、且被执行跟踪的"路径，实测位置可能被碰撞推歪过，用推歪后的实际轨迹作回退参考，可能把机器人带向"被挤出来的方向"而那里未必安全。这一条在实践中很容易写错。

片段 2：自由回退与"槽内陷阱"两种场景

def run_retract(left_wall=None, n=800, dt=1e-3):
    """机器人被压在右墙上（40 N），执行紧急回退。
    left_wall=None：自由撤离；给数值：左方 3 mm 处有第二个约束（陷阱）。"""
    m, k_env = 1.0, 1e4
    x, v, x_ref = 0.004, 0.0, 0.004          # 已压入右墙 4 mm（约 40 N）
    k_d, d_d = 200.0, 20.0                    # 回退期低刚度柔顺
    plan = RetractPlanner(speed=0.1, f_guard=60.0)
    f_log = []
    for i in range(n):
        f_r = k_env * x if x > 0.0 else 0.0    # 右墙：正 x 穿透，力推 -x
        f_l = k_env * (left_wall - x) if (left_wall is not None and x < left_wall) else 0.0
        v_ref = plan.step(x, max(f_r, f_l), dt)
        x_ref += v_ref * dt
        plan.push_history(x_ref)               # 记录命令轨迹（含撤离段）
        u = -k_d * (x - x_ref) - d_d * (v - v_ref)
        v += (u + f_l - f_r) / m * dt          # 左墙推 +x，右墙推 -x
        x += v * dt
        f_log.append(max(f_r, f_l))
    return plan.phase, x, f_log

for name, kw in [("自由回退", dict()),
                 ("槽内陷阱", dict(left_wall=-0.003))]:
    phase, x_end, log = run_retract(**kw)
    print(f"{name}: 结束阶段={phase:5s}  末位置={x_end*1000:7.2f} mm  "
          f"峰值力={max(log):5.1f} N")

解读：预期结果，自由回退：力从 40 N 单调降到 0（约 40 ms 后释放），随后 CLEAR 段撤出 20 mm，阶段停在 DONE，末位置约 −20 mm；槽内陷阱：向左撤 3 mm 后撞上左墙，\(f_l\) 随深度上升，守卫在 60 N 处中止 ABORT……实际数值会略低于 60 N，因为一旦左墙接触，净力把机器人推回右侧（这就是"夹紧"的物理），控制器与两侧墙的合力先行平衡。调试要点：（1）把峰值力与阶段打印出来，一眼就能区分"撤干净了"与"被困住了"；（2）plan.push_history(x_ref) 在回退中继续记录，若将来需要第二次回退，历史方向会自动更新为"刚才撤离的方向"，保持语义一致；（3）陷阱场景的教训是：单方向撤离不是万能药，守卫中止后的"待救援"逻辑（提示 + 最小刚度保持）才是最后防线。

片段 3：回退距离与时间预算

def retract_budget(f_list=(10.0, 40.0, 80.0), k_env=1e4,
                   clearance=0.02, v_r=0.1):
    """按 d = F/K_env + 净空 列回退预算，并给出耗时。"""
    for f in f_list:
        pen = f / k_env
        d_total = pen + clearance
        t_total = d_total / v_r
        print(f"夹持力 {f:5.1f} N / K_env={k_env:.0e} 穿透 {pen*1000:5.2f} mm "
              f"回退 {d_total*1000:5.1f} mm, 耗时 {t_total*1000:5.0f} ms")

retract_budget()

解读：表格给出"多大力、撤多远、花多久"的直读预算。注意最后一行 80 N 的场景：软环境（104 N/m）下穿透 8 mm，总回退 28 mm，以 0.1 m/s 撤离需 280 ms，回退时间直接影响"救援响应"（夹持人手时的 280 ms 是可以接受的，若夹持力高、速度慢，时间还要延长，这就是为什么夹持安全阈值要尽量前置、把人机接近速度限在低位）。三个参数的建议：k̂env 用第 052 章的辨识值（不确定时取偏软值，回退距离按偏大算）；净空 10–30 mm；撤离速度不超过任务速度的 1/5，且必须在"减速完成"之后启用（与第 098 章的 DECEL 衔接）。

常见坑

  • 用"反向外力"当回退方向：楔形夹持、摩擦主导时力的方向会误导；错误方向 + 自动执行 = 主动制造事故。修复：用历史命令轨迹方向；无历史时进入待救援，不猜方向。
  • 历史缓冲记的是实测位置：碰撞把机器人推歪过，实测轨迹可能包含被挤出的路径。修复：记录命令位置；实测与命令的偏差本身也要监控（它是碰撞的另一个证据）。
  • 没有净空、只看力：力降到阈值就停，工件一动又碰上，反复触发。修复：两阶段撤离（PULL 力判据 + CLEAR 距离判据），净空写进单元设计。
  • 撤离速度太快：回退变成"高速倒车"，带着动量撞反向约束；也失去了守卫的反应时间。修复：速度 ≤ 任务速度的 1/5，且先减速再撤离。
  • 守卫阈值设太高或没有方向监控：等到"越撤越压"的力涨到很高才停，已经二次受损。修复：fguard = 1.5×触发值；同时监控"力方向与撤离方向同号"的趋势并提前中止。

    提示

  3. 设计"夹持救援"场景的完整时序：从第 097 章检测到持续过力 → 第 098 章减速 → 本章回退 → 待救援保持。写出每一步的判据、时间预算（总响应 < 500 ms）与失败升级路径。★★
    提示
    检测 5–15 ms + 减速（0.3 m/s、a=4）150 ms + 回退 30 mm/0.1 m/s = 300 ms → 已接近 500 ms；提速手段是"提高撤离速度到 0.2 m/s"或"减小初始穿透"（限制人机接近速度），权衡都写进方案。
  4. 把回退规划器扩展到二维（平面）：写出方向选择（历史点的向量差）、净空（沿方向的距离环）、守卫（力的两个分量），并讨论多方向撤离时"两个约束之间的走廊"问题。★★★
    提示
    二维下历史方向更有价值（狭窄路径里"走过的路"是最好的地图）；净空应该在撤离方向与垂直方向都留（走廊宽度）；守卫要同时看力的幅值与"沿撤离方向的功率"（F·v > 0 的持续时长）。

小结

  • 紧急回退解决"停不住的危险"：重度碰撞、夹持救援、持续过力、环境逼近；它以安全停止为前提，再执行受控撤离。
  • 方向选择：沿"历史命令轨迹"反向撤离（已验证通路），不靠反向外力；无历史时进入待救援，不猜方向。
  • 距离预算 d = F/K̂env + d净空；两阶段执行：PULL（力判据释放）+ CLEAR（距离判据留净空）。
  • 力守卫 fguard = 1.5×触发值 + 方向趋势监控；守卫中止后转入待救援（最小刚度柔顺保持 + 提示 + 等待人工）。
  • 安全链至此闭环：接触状态（096）→ 碰撞检测（097）→ 安全停止（098）→ 紧急回退（099）。下一章用完整的指标体系把这些动作与前面的所有方法放在一起验收，性能评估，也是全课程的收官。
