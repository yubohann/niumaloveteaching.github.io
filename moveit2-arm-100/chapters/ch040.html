第三篇 · 规划算法与求解器

第 040 章：规划器选择：OMPL 规划算法族

采样规划器的家族谱系与选型方法：本章讲单查询与多查询、概率完备与渐近最优、双向生长与惰性检查等性质如何区分算法，以及把任务特征映射到规划器标识的实用决策表。

  • 主题：采样规划算法 / 规划器选型
  • 关键机制：概率完备性与渐近最优性、RRT 与 PRM 两大谱系、规划器配置参数
  • 预计学时：55 分钟
  • 前置章节：第 039 章

学习目标

  • 建立 OMPL 规划器家族的分类视角：单查询树类、多查询路图类、投影网格类及其代表性算法。
  • 理解概率完备性、渐近最优性、双向生长、惰性碰撞检查四个性质的含义，以及它们对实际表现的影响。
  • 掌握 MoveIt 中规划器的注册与选择方式：规划器标识与配置参数的对应关系。
  • 会根据任务特征（一次性、重复查询、狭窄通道、路径质量要求）从决策表选出候选规划器并设定参数。
  • 能设计小规模对照实验：固定任务与预算，比较求解成功率、耗时与路径代价。

背景与动机

第 039 章把规划管线拆成三段，其中"规划器求解"一段由算法插件填充。MoveIt 默认的算法插件是 OMPL（Open Motion Planning Library）适配层，它把 OMPL 的数十个采样算法以规划器标识的形式暴露出来：RRTConnect、RRT、RRTstar、PRM、LBKPIECE1 等名字可以直接写进请求。选择哪一个，是第三篇里对任务表现影响最大的单个决策之一。

选型的困难不在算法数量，而在性质与场景的匹配：有的算法几乎必然在有限时间内给出解（对典型机械臂任务），有的算法保证路径质量但要付出成倍时间，有的算法擅长重复查询但对一次性任务没有优势。理解四组核心性质（完备性、最优性、生长方式、检查策略），就能把"试遍所有名字"的调参方式替换为有依据的候选筛选。本章给出性质表与决策表，并示范小规模对照实验的做法，为第 041 章的预算设置与第 047 章的完整基准测试铺路。

核心原理

1. 两大谱系：树类与路图类

采样规划算法的构造方式可归为两大谱系。树类（如 RRT 及其变体）从起点或起终两点出发增量生长搜索树，擅长处理一次性查询；路图类（如 PRM）预先在自由空间中铺设无向图，之后每次查询在图内做搜索，适合同一场景中的多次查询。机械臂任务以一次性抓取搬运为主，树类因此成为默认选择；多工位重复运动的固定工装场景，路图的预铺设成本可以被反复摊薄。

谱系代表算法结构适用模式
单查询树类RRT、RRTConnect、RRT*、TRRT、STRIDE每次查询从头生长搜索树一次性到达、场景频繁变化
多查询路图类PRM、PRM*、LazyPRM、SPARS预铺设路图，查询时搜索固定场景中的重复任务
投影网格类KPIECE1、LBKPIECE1、PDST用投影把高维空间压到低维网格狭窄通道、需要引导的构型
其他启发式SBL、EST、BiEST、FMT*特定采样与扩展策略按实验数据选用

树类中的 RRTConnect（双向生长）值得单独强调：它同时从起点与目标生长两棵树并尝试连接，避免了单棵树朝向目标"盲目摸索"的低效，对六轴与七轴机械臂的常规任务通常给出最快的求解。它的短板是不保证路径质量，产出的路径常常带有明显的绕行与抖动，质量改善交给后处理适配器（第 039 章）或换用优化型算法。

2. 四个核心性质

选择算法时真正要评估的性质有四个：

  • 概率完备性（Probabilistic Completeness）：只要解存在，采样时间趋长时找到解的概率趋近于一。它不承诺有限时间内一定找到，也不承诺找到得快；实际含义是"多给时间大概率能解"，这也是规划预算（第 041 章）存在的理由。
  • 渐近最优性（Asymptotic Optimality）：时间趋长时路径代价收敛到最优。RRT*、PRM*、FMT* 属于此类。代价是求解时间显著更长，且"渐近"意味着预算不足时可能比非最优算法表现更差。
  • 生长与探索方式：双向生长（RRTConnect、BiEST）比单向更快衔接两端；目标偏置采样提高接近目标的效率；投影引导（KPIECE 系）在狭窄通道中更有效。生长方式决定的是"在困难构型中谁更容易找到通路"。
  • 碰撞检查策略：惰性检查（LazyPRM 等）先假设边可行、查询失败后再检查并剔除，用"可能浪费的搜索"换取"平均更少的碰撞检查次数"。场景障碍稀疏时收益明显，障碍密集时可能出现反复剔除的抖动。

四个性质之间没有全能组合：最优性与速度在预算维度上互斥，惰性检查的收益与场景密度相关，双向与投影的适用面各自偏置。选型的实质是按任务优先级排定这四者的先后。

3. 规划器标识与配置参数

在 MoveIt 中，OMPL 算法以规划器标识暴露，标识之下的配置参数决定行为。关键参数及其量级：

参数典型取值作用
range0（自动）或 0.05–0.5（按空间尺度）单次扩展的最大步长；过大降低精度，过小降低效率
goal_bias0.05–0.1采样时直接取目标的概率，提高接近效率
longest_valid_segment_fraction0.005–0.01边检查的离散化密度（第 028、029 章）
投影评估器按规划组默认或自定义KPIECE 等投影类算法必需，决定引导质量

标识与参数的组织方式：配置文件中为每个规划组注册可用标识与参数集，请求里写标识选择算法。同一算法可以注册多份参数不同的配置（例如两种 range），用不同标识区分，这是"算法固定、参数扫描"的正规做法。参数作用域是"标识加规划组"，同名算法在不同组下可以有不同参数。

4. 选型决策表

把任务特征映射到候选规划器：

任务特征首选次选理由
常规抓取搬运（一次性）RRTConnectRRT双向生长求解快，鲁棒性高；路径质量交给后处理
固定场景重复查询PRMLazyPRM路图预铺设成本被多次查询摊薄
狭窄通道频繁受困LBKPIECE1STRIDE、TRRT投影引导与特定扩展策略对窄缝更有效
路径质量或能耗敏感RRTstarPRMstar渐近最优，预算需要显著加大
障碍稀疏且查询频繁LazyPRMPRM惰性检查减少碰撞计算量

决策表的作用是圈定第一批实验对象，最终答案需要实测给出：机械臂的构型分布与工装几何各不相同，窄通道或可达性边界只有实测才能暴露。推荐流程是"首选加次选各跑一批对照，观察成功率与耗时分布，再决定是否引入第三类算法或调参数"。对照实验的规模不必大，固定任务重复 20 至 50 次即可看出量级差异（完整基准方法见第 047 章）。

5. 与预算和参数的关系

同一个算法在不同预算下的表现差异可以超过不同算法之间的差异：规划时间与尝试次数（第 041 章）把"算法能力"截断成"预算内的表现"。因此选型实验必须固定预算，只比较算法；预算调优实验必须固定算法，只比较预算。混在一起做的对照无法归因。另一条纪律是随机性管理：采样算法带随机数，单次对比没有统计意义；同一任务重复多次取成功率与耗时分布，或固定随机种子让对照可复现。

实现思路与设计

规划器选型的工作流程：

  1. 任务画像：给每类任务标注四个属性（查询频次、场景变化频率、通道难度、质量要求），作为决策表输入。
  2. 注册标识：在配置中为每个规划组注册候选标识与参数集，同一算法可多份参数配置。
  3. 固定预算对照：统一时间与尝试预算，跑首选与次选的成功率、耗时、路径代价三项指标。
  4. 选型定稿：按任务优先级（成功优先或质量优先）选择标识，把选择集中写入任务配置，避免常量散落代码。
  5. 参数微调：在选中算法上扫描关键参数（range、goal_bias），确认收益量级后再细化。
  6. 回归监测：上线后按周统计成功率与耗时漂移，场景或预算变化时重跑对照。

对照实验的指标定义

指标定义用途
求解成功率预算内返回解的比例首要指标，直接决定可用性
求解耗时请求到响应的规划时间，报告中位数与高分位节拍评估；关注高分位而不仅是平均
路径代价关节空间路点间距离之和（见片段 3）质量指标，供执行时间与磨损评估
路径裕量沿路径到障碍的最小距离（第 029 章工具）安全指标，优化型算法通常表现更好

与上一章的差异点：第 039 章讲"请求经过什么结构"，本章讲"结构中的算法如何选"；两者合起来回答"一次规划行为由谁决定"：配置定结构，标识定算法，参数定行为。

关键代码与解读

片段 1：OMPL 规划器注册与参数配置（配置组织以所用发行版模板为准）

# OMPL 管线的规划器配置：注册标识与参数集
ompl:
  ros__parameters:
    planner_configs:
      RRTConnect:
        type: geometric::RRTConnect
        range: 0.0                  # 0 表示按空间尺度自动选择步长
      RRTstar:
        type: geometric::RRTstar
        range: 0.0
        goal_bias: 0.05             # 采样时直接取目标的概率
      LBKPIECE1:
        type: geometric::LBKPIECE1
        range: 0.0
        border_fraction: 0.9        # 边界采样比例：越大越倾向沿边界扩展
    # 规划组注册可用标识：默认项与候选项分开表达
    arm_group:
      default_planner_config: RRTConnect
      planner_configs:
        - RRTConnect
        - RRTstar
        - LBKPIECE1
    # 同一算法可注册多份参数配置（例如 RRTConnect_fine）
    # 用不同标识区分，实现"算法固定、参数对照"的实验形式

解读：（1）planner_configs 定义"算法类型加参数"，规划组的 planner_configs 列表定义"这个组能选哪些标识"；请求只能使用组内注册过的标识，写错组外标识会得到标识错误（第 039 章的失败分类之一）。（2）range 取 0 让实现按空间范围自动选择步长，是常用起点；需要精调时再给出显式值，量级参考空间的典型尺度。（3）注释示范了参数对照的标准形式：同一算法注册多份配置，实验时只切换标识，其它一切保持不变，归因链条清晰。

片段 2：C++ 固定任务上的规划器横向对照（接口以对应 ROS2 发行版与 MoveIt2 版本的官方文档为准）

// 固定目标与预算，逐个切换规划器标识，记录成功率与耗时（小规模对照）
const std::vector<std::string> candidates = { "RRTConnect", "RRT", "RRTstar" };
const int repeats = 20;                          // 每个算法重复次数
double budget_seconds = 1.0;                     // 统一预算（第 041 章展开）

for (const std::string& id : candidates)
{
  move_group->setPlannerId(id);                  // 仅切换算法标识
  move_group->setPlanningTime(budget_seconds);
  int success = 0;
  double total = 0.0;
  for (int k = 0; k < repeats; ++k)
  {
    moveit::planning_interface::MoveGroupInterface::Plan plan;
    auto t0 = node->now();
    auto code = move_group->plan(plan);
    total += (node->now() - t0).seconds();
    if (code == moveit::core::MoveItErrorCode::SUCCESS)
      ++success;
  }
  RCLCPP_INFO(node->get_logger(), "%s：成功 %d/%d，平均耗时 %.2f s",
              id.c_str(), success, repeats, total / repeats);
}

解读：（1）对照的三项纪律都落在代码结构里：候选列表显式、预算统一、目标与起点在循环外固定；任何一项漂移都会污染结论。（2）重复次数取 20 属于能够观察量级差异的最小规模；采样算法单次结果波动大，报告平均值时要同时留心中位数与最坏情况（第 047 章给出更完整的统计方法）。（3）成功判定以结果码为准，不依赖"有没有抛错"：规划失败以错误码返回属于正常流程，失败率正是要测量的对象。

片段 3：Python 计算响应轨迹的路径代价

import math

def path_cost(response):
    """关节空间路径代价：相邻路点位置向量的欧氏距离之和。

    输入为规划响应消息（MoveGroup 规划服务或 Action 的结果）。
    代价越小说明几何路径越短，与执行时间和关节磨损正相关。
    """
    points = response.trajectory.joint_trajectory.points
    if len(points) < 2:
        return 0.0
    total = 0.0
    for a, b in zip(points, points[1:]):
        # 路点含位置、速度、加速度与时间字段；这里只取位置
        total += math.dist(a.positions, b.positions)
    return total

def summarize(runs):
    """对一批对照结果做粗统计：成功率、耗时中位数、代价中位数。"""
    costs = sorted(path_cost(r) for r in runs if r.trajectory.joint_trajectory.points)
    print(f"样本 {len(runs)}，有效轨迹 {len(costs)}")
    if costs:
        mid = costs[len(costs) // 2]
        print(f"路径代价中位数 {mid:.3f} rad，最优 {costs[0]:.3f}")

解读：（1）路径代价只取位置字段计算，速度与加速度字段属于时间参数化的产物（第 039 章的响应链），若把它们混入几何代价会引入时间信息造成口径混乱。（2）代价函数取"关节空间距离之和"，与执行时间解耦，因为时间受速度限制配置影响，几何代价更纯粹地反映算法输出的路径质量。（3）统计函数用中位数替代平均值，抵消采样算法的长尾分布；批量对照的完整统计（分位数、箱线图）在第 047 章的基准测试中系统展开。

常见坑

  • 用单次结果下结论：采样算法随机性强，一次快慢不构成依据。修复是按固定预算重复不低于 20 次，报告成功率与分布指标。
  • 预算与算法同时更换：对照实验中把新算法的预算也调大，无法判断提升来自算法还是预算。修复是严格控制变量：先固定预算选算法，再固定算法调预算。
  • 标识未在组内注册：请求使用的标识没有出现在该组的 planner_configs 列表，得到标识错误却按"无解"处理。修复是启动自检核对注册列表，失败信息按结果码分类。
  • 指望 RRTstar 短时间内最优：渐近最优性的含义是时间趋长时收敛，短预算下常劣于 RRTConnect。修复是按质量需求给足预算，或采用"RRTConnect 求可行加后处理改善"的组合策略。
  • 惰性检查收益假设过度：在障碍密集场景中启用惰性检查类算法，边被反复剔除导致表现反而下降。修复是按场景密度选择，对照实验里把场景密度作为控制变量。

练习与思考

  1. 性质配对：把"概率完备性""渐近最优性""惰性检查""双向生长"四个性质与各自最直接受益的任务类型配对，并用一句话说明原因。★
    提示
    概率完备性对应"存在解但难找"的任务（保证多给时间可解）；渐近最优性对应质量敏感任务；惰性检查对应障碍稀疏且重复查询；双向生长对应两端明确的常规到达任务。
  2. 结果预测：同一任务下把 RRTConnect 的 range 从 0（自动）改为 0.01 rad 的极小值。预测求解时间与路径形状的变化，并说明极端取值的失效方式。★
    提示
    步长过小使树生长缓慢、节点数激增，求解时间上升；路径更细碎。失效方式是在预算内无法连到目标而判定无解，与算法能力无关，属于参数选择错误。
  3. 设计题：为一个"固定工装上重复执行 30 次相同避障运动"的循环任务设计规划器方案：给出谱系选择、预算与参数、以及"预铺设路图是否值得"的判定方法。★★
    提示
    重复查询利于多查询路图类（PRM）；判定方法为比较"路图铺设加查询的总时间"与"30 次单查询树类的时间"；注意场景固定是前提，任一物体变化都会重设路图成本。
  4. 诊断题：对照组出现"RRTstar 成功率低于 RRTConnect"的结论。给出至少两种解释并说明如何用实验排除。★★
    提示
    解释一：预算不足，渐近最优算法在短预算下未完成有效搜索；解释二：参数失配（range、goal_bias 未按空间尺度调整）。排除方法：延长预算复测前者，参数扫描复测后者；两者都不改变结论时再接受"该任务不适合 RRTstar"。
  5. 分析题：设计一个"算法加预算"的联合选型实验：两类任务（常规搬运、狭窄通道装配）各一套候选与预算档位，给出实验矩阵、指标与结论的判定标准。★★★
    提示
    矩阵为任务乘算法乘预算三因子，只逐因子比较（固定其余两个）；指标用成功率优先、耗时高分位次之、代价第三；判定标准是"在满足成功率下限的前提下取耗时高分位最小的组合"，狭窄通道任务允许提高预算档位。

小结

  • OMPL 规划器分两大谱系：单查询树类适合一次性任务，多查询路图类适合固定场景的重复查询。
  • 四个核心性质（概率完备、渐近最优、生长方式、检查策略）决定算法在不同任务上的强弱，没有全能组合。
  • 规划器标识把算法与参数集绑定，组内注册制约束可用范围；同一算法多份参数配置是正规的对照手段。
  • 选型从决策表给出首批候选，用固定预算的重复对照定稿，避免单次结果与混变量实验。
  • 下一章处理算法表现的另一半决定因素：规划时间与尝试次数设置，讲预算如何截断算法能力以及如何按任务分层配置。
