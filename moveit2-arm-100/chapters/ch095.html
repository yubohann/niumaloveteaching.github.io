第 095 章：场景重建与动态更新

从传感器数据到规划场景的两条重建路线：占用栅格的体素级更新与物体级的目标注册跟踪；讲清更新节拍、陈旧淘汰与场景一致性维护，从源头减少环境性失败。

  • 主题：场景管理 / 动态重建
  • 关键机制：八叉树更新、物体注册表、生命周期淘汰、版本化与差分应用
  • 预计学时：55 分钟
  • 前置章节：第 094 章

学习目标

  • 理解场景重建的两条路线：占用栅格与物体级重建，及混合使用的分工。
  • 掌握八叉树更新参数：分辨率、占用阈值、传感器模型与自过滤的语义与代价。
  • 会设计物体级重建流水线：平面去除、聚类、位姿估计、注册跟踪与淘汰。
  • 理解陈旧数据造成幽灵碰撞的机理，掌握版本化与差分应用的维护方法。
  • 会为感知、场景应用与规划三个环节设计协调的更新节拍。

背景与动机

规划场景的质量直接决定规划质量：场景漏掉障碍会造成碰撞风险，场景残留陈旧物体会造成幽灵碰撞与无解。动态环境中的场景维护是持续过程：每次感知更新、每次物体被移动、每次抓取改变附着关系，场景都要相应变化。

场景重建有两条技术路线，选择错误会同时损失精度与性能：用体素栅格追踪已知工件会得到粗糙几何与漂浮体素；用物体模型表达未知杂物则需要先完成分割与识别。工程上两条路线混合使用，各自承担擅长部分。

上一章的恢复策略处理失败后的补救，本章从源头减少失败：让规划场景始终接近物理现实。

核心原理

1. 两条重建路线

占用栅格把空间离散为体素并记录占用概率，物体级重建把感知结果拟合为带位姿的几何体或网格。前者的优势是通用，后者的优势是精确与可跟踪。

维度占用栅格物体级重建
几何表达体素占用概率几何体或网格加位姿
适合对象未知形状、动态障碍已知类别、需要抓取的物体
更新成本随体素数增长随物体数增长
主要风险内存与查询延迟膨胀位姿漂移与陈旧残留

混合策略：环境与安全区用栅格表达，任务物体用物体级表达；物体所在区域的体素可裁剪，避免同一障碍以两种形式被重复检查。

2. 八叉树更新的参数与代价

体素分辨率决定几何精度与体素数：空间体积固定时，体素数按分辨率的立方反比增长。

N体素 ≈ V观测体积 / r3 观测体积 1 m³、分辨率 0.02 m 时约 12.5 万个体素；分辨率减半到 0.01 m 时约百万级，内存与查询耗时同步上升

占用与自由更新由传感器模型控制：命中点按命中概率抬高占用值，视线路径按未命中概率压低；概率跨越占用阈值即视为障碍。传感器模型参数（最大量程、命中与未命中概率）决定更新速度与噪声敏感度，需与实际传感器匹配。

自过滤（self-filter）把机器人自身与附着物体的点云剔除，否则机械臂自身的观测点会进入场景，形成自碰撞假阳性。剔除依据是已知的连杆位姿与几何范围，双臂与负载场景中自过滤范围要覆盖附着物体。

3. 物体级重建流水线

标准流水线为：平面去除（桌面与地面）→ 聚类（欧氏距离邻域）→ 位姿估计（主轴、包围盒或模板匹配）→ 注册（分配稳定标识）→ 跟踪更新 → 淘汰。稳定标识是任务语义的基础：抓取任务按标识引用物体，标识变化即任务失败。

注册判据：位置距离 < ε匹配 且 尺寸差 < ε尺寸 时视为同一物体，沿用原标识 ε 过大导致两个物体被合并，过小导致同一物体反复换标识；取值参考物体尺寸与位姿估计误差

跟踪更新把新位姿平滑到旧位姿上（限幅更新），抑制估计抖动传导到场景；淘汰按生命周期与置信度执行：连续若干帧未观测到的物体进入待淘汰，超过存活期后从场景移除。淘汰必须显式化，否则被移走的物体会以幽灵形式长期驻留。

4. 陈旧数据与幽灵碰撞

幽灵碰撞指场景中存在物理上已消失的障碍。来源有三：物体移走但未淘汰、栅格中的残留体素未清除、更新流水线中断后无人维护。维护手段是版本化与时间戳：场景快照携带版本号，规划前核对版本新鲜度才能发现更新停滞。

陈旧窗口 δt = 传感器周期 + 处理时间 + 应用延迟 + 淘汰延迟 规划请求发出时刻与场景快照时刻之差超过陈旧窗口时，规划结果的场景依据不可信，应先同步再规划

5. 更新节拍设计

三类节拍互相协调：感知以传感器频率采集、场景以低于感知的频率批量应用差分、规划在任务触发时快照读取。批量应用的价值是抑制高频差分带来的流量与锁竞争；代价是场景新鲜度略降。更新节拍与陈旧窗口共同决定感知参数的取值边界。

实现思路与设计

重建系统按"路线分工、参数标定、流水线实现、淘汰策略、节拍协调"五步搭建。每一步的产物都可独立验证：数据集回放、参数对照、注册稳定性统计、幽灵碰撞计数、节拍看板。

1. 参数表

参数典型取值作用依据

2. 从场景到规划的时间线

  1. 传感器采样并标注时间戳。
  2. 感知处理产生物体列表与位姿估计。
  3. 场景管理节点合并到注册表并应用差分。
  4. 规划请求读取快照，核对新鲜度后求解。
  5. 执行期间的场景变化通过监视话题持续反映，但不回溯修改已执行轨迹。

3. 与恢复策略的衔接

第 094 章的场景清理动作以本章的注册表与版本控制为输入：清理的定义是"移除超过存活期与低置信度的对象"，清空全部会造成信息损失。版本信息让恢复动作可以判断清理是否必要，把无效清理挡在门外。

与上一章的差异点：第 094 章在失败发生后补救，本章通过持续维护让场景接近现实，降低失败发生率；两章共同构成环境性失败的完整应对。

片段 1：占用栅格与自过滤配置（YAML）

# 场景监视器的占用栅格参数：以对应发行版的参数路径为准
octomap_config:
  resolution: 0.02              # 分辨率：0.02 m 兼顾精度与体素数（见公式）
  occupancy_threshold: 0.6      # 占用判定阈值：偏保守，抑制噪声假阳性
  prob_hit: 0.7                 # 命中更新概率：观测到点即显著抬高占用
  prob_miss: 0.4                # 未命中更新概率：视线路径缓慢清除残留
  max_range: 2.0                # 有效量程：超出视为不可靠，避免远处稀疏噪点
  filter_ground_plane: true     # 地面平面过滤：工作台场景中常把桌面并入地面处理

# 自过滤：机器人自身与附着物体从传感器数据中剔除
self_filter:
  enabled: true
  padding: 0.02                 # 几何余量：覆盖建模误差与连杆表面的薄膜点云边界
  include_attached: true        # 附着物体必须纳入：抓取中的工件属于自身范围
  link_names: ["base_link", "shoulder_link", "upper_arm_link",
               "forearm_link", "wrist_1_link", "wrist_2_link", "wrist_3_link"]

解读：这两组参数决定场景的精度与稳定性。设计要点：（1）分辨率与内存的换算关系直接可用公式核对，标定前先做体素数估算；（2）命中概率高于未命中概率，使障碍进入场景快、清除慢，偏安全侧；（3）自过滤必须包含附着物体，抓取中的工件若被剔除，规划器会把它与目标容器判为不可接近；（4）余量参数覆盖建模误差，取值过小会在连杆表面产生薄膜点云。参数名与组织方式随版本演进，部署前按本地配置核对。

片段 2：物体注册表与淘汰

import time
class ObjectRegistry:
    """物体注册表：稳定标识、限幅位姿更新与存活期淘汰。"""
    def __init__(self, match_dist=0.03, size_tol=0.02, max_misses=5):
        self.objects = {}             # obj_id -> [位置, 尺寸, 连续缺失帧数]
        self.match_dist = match_dist  # 匹配阈值：兼顾合并与换标识两类错误
        self.size_tol = size_tol
        self.max_misses = max_misses  # 连续未观测上限：短暂遮挡不误删
        self._next = 0
    def update(self, detections):
        """把本帧检测并入注册表：匹配则更新，未匹配则新建。"""
        seen = set()
        for det in detections:
            oid = self._match(det)
            if oid is None:
                oid = f"obj_{self._next}"     # 新物体：分配稳定标识
                self._next += 1
                self.objects[oid] = [det.position, det.size, 0]
            else:
                obj = self.objects[oid]
                # 限幅更新：位姿只向观测值移动一部分，抑制感知抖动
                obj[0] = tuple(0.7 * o + 0.3 * n
                               for o, n in zip(obj[0], det.position))
                obj[2] = 0
            seen.add(oid)
        for oid, obj in self.objects.items():
            if oid not in seen:
                obj[2] += 1                   # 本帧未命中：累计一次缺失
        stale = [oid for oid, o in self.objects.items()
                 if o[2] >= self.max_misses]
        for oid in stale:                     # 淘汰：移除陈旧条目
            del self.objects[oid]
        return stale
    def _match(self, det):
        for oid, obj in self.objects.items():
            d = sum((a - b) ** 2 for a, b in zip(obj[0], det.position)) ** 0.5
            ds = sum(abs(a - b) for a, b in zip(obj[1], det.size))
            if d < self.match_dist and ds < self.size_tol:
                return oid
        return None

解读：注册表是物体级重建的核心数据结构。设计要点：（1）稳定标识在匹配成功时沿用，抓取任务引用的名称不会因帧间抖动而改变；（2）位姿限幅更新把感知抖动过滤在场景之前，比例 0.3 是平滑与滞后之间的折中；（3）淘汰基于连续未观测帧数，单帧缺失不触发删除，短暂遮挡不会误删；（4）匹配同时看位置与尺寸，避免两个相邻物体因位置接近被合并。淘汰触发后返回被移除的标识列表，场景应用模块据此发布删除操作。

片段 3：规划前的场景新鲜度核对

def scene_is_fresh(scene_stamp, now, stale_window_s=0.5):
    """核对场景快照新鲜度：超过陈旧窗口先同步再规划。"""
    age = (now - scene_stamp) * 1.0     # 时间戳单位换算为秒
    if age > stale_window_s:
        # 返回原因文本：调用方可直接进入恢复或等待逻辑
        return False, f"场景陈旧 {age:.2f}s，超过窗口 {stale_window_s:.2f}s"
    return True, "ok"


def plan_with_guard(scene, request, now):
    """带新鲜度守卫的规划入口：拒绝基于过期场景的求解。"""
    fresh, reason = scene_is_fresh(scene.stamp, now)
    if not fresh:
        # 先请求场景更新；更新未完成时不进入求解，避免幽灵碰撞或漏检
        scene.request_update()
        return None, reason
    return scene.plan(request), "ok"

解读：新鲜度守卫把"场景可信度"变成规划入口的前置条件。设计要点：（1）返回原因文本便于日志与恢复分类直接使用；（2）陈旧时先触发更新再返回失败，让调用方等待或进入恢复；（3）守卫只做时间核对，成本恒定，可以放在每次规划的固定路径上。陈旧窗口的取值来自感知、处理、应用与淘汰四段延迟之和（见公式），节拍调整后必须重新核算。

常见坑

  • 自过滤遗漏附着物体：抓取中的工件点云进入场景，规划器把工件与目标位置判为互碰。修复：自过滤范围包含附着物体，余量覆盖建模误差。
  • 分辨率设置过高：追求精度把分辨率调到毫米级以下，体素数达百万级，碰撞查询延迟显著上升。修复：按最小安全检查间隙选分辨率，用体素数公式先估算。
  • 淘汰策略缺失：被移走的物体长期驻留场景，规划出现幽灵碰撞且难以复现。修复：注册表带存活期与淘汰规则，被移除对象发布显式删除操作。
  • 注册标识频繁跳变：匹配阈值过紧，同一物体每帧换新标识，任务引用失效。修复：阈值参考位姿估计误差量级，并用帧间跟踪稳定性统计验证。
  • 更新节拍与规划竞争：场景以传感器频率全量更新，规划求解与更新争抢同一资源，耗时上升。修复：差分批量应用，降低应用频率并核对新鲜度窗口。

练习与思考

  1. 计算：观测体积 0.8 m³，分辨率取 0.025 m 与 0.0125 m 时的体素数各约为多少？说明分辨率减半对内存与查询耗时的量级影响。★
    提示
    0.025 m 约 5.1 万；0.0125 m 约 41 万，约 8 倍；两者相差立方关系。
  2. 为"桌面移走物体"场景设计淘汰参数：物体存活期、连续未观测帧数上限与置信度条件，并说明每个参数的取舍。★★
    提示
    存活期覆盖最长遮挡时长；未观测帧数上限抑制单帧噪声；置信度条件防止低质量检测反复注册与淘汰。
  3. 改参数并预测：把注册匹配距离阈值从 0.03 m 缩小到 0.01 m，注册稳定性统计中的"换标识率"与"合并错误率"分别如何变化？★★
    提示
    阈值缩小使同一物体更易匹配失败而换新标识，换标识率上升；合并错误率下降，因为相邻物体更难被误合并。
  4. 设计实验：在同一段感知数据集上对比"直接使用物体级场景"与"混用栅格"，统计幽灵碰撞次数与规划耗时，给出结论模板。★★★
    提示
    数据集固定回放保证可比；幽灵碰撞人工标注或由真值对比检出；耗时统计用第 091 章分位数口径。
  5. 推导陈旧窗口的组成，并说明在两个环节同时缩短节拍时，为什么必须重新评估感知覆盖率（提示：从传感器频率与批量应用的关系出发）。★★
    提示
    加快应用节拍会缩短窗口，但差分来源仍是传感器帧；若感知覆盖率不足，窗口缩到低于感知周期时守卫会持续拒绝规划。

小结

  • 两条重建路线分工：占用栅格负责通用环境表达，物体级重建负责精确与可跟踪的任务目标。
  • 体素数按分辨率立方增长，分辨率与内存、查询延迟直接绑定，先估算再选择。
  • 自过滤必须覆盖连杆与附着物体，否则自身点云造成假碰撞。
  • 物体注册表以稳定标识为核心，限幅更新抑制抖动，存活期淘汰清理幽灵物体。
  • 场景新鲜度守卫把版本与时间戳变成规划入口的前置条件，陈旧窗口由四段延迟决定。
  • 下一章进入感知侧上游：与视觉系统集成，把检测与位姿估计接到场景与规划链路上。
