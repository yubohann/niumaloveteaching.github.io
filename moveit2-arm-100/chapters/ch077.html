第 077 章：真机通信与部署

从仿真到真机的最后一公里：五层部署链路、周期与延迟对精度的影响、执行监控参数与恢复策略，以及标定与安全限幅的验证清单。

  • 主题：系统验证 / 真机部署（Real Robot Deployment）
  • 关键机制：ros2_control 硬件接口 / 执行监控（Execution Monitoring）/ 标定与安全限幅
  • 预计学时：55 分钟
  • 前置章节：第 076 章

学习目标

  • 掌握真机部署链路的五层结构（规划、执行管理、控制器、硬件接口、总线与驱动）与各层的周期量级。
  • 理解通信延迟与控制周期如何转化为轨迹跟踪误差，能完成延迟项的精度预算。
  • 会配置执行监控参数（时长缩放、时长余量、起点容差、完成确认），并说明放宽与收紧的后果。
  • 掌握标定链（连杆、工具中心点、手眼）的残差量级与其在抓取误差预算中的位置。
  • 能按分阶段放量流程部署真机：低速空载起步、逐档提速、每档设定通过条件。

背景与动机

仿真中的机器人状态由物理引擎理想给出，真机中相同的一条轨迹要经过控制器插值、硬件接口、总线传输与伺服驱动若干环节，每个环节都引入周期、延迟与误差。部署工作的实质是把这些环节的时序与精度逐项对齐，使 MoveIt2 的规划假设在执行端成立：规划假设轨迹按时执行、起点与当前状态一致、位置误差可控，任何一项被打破都需要监控参数或恢复逻辑兜底。

安全约束在这条链路的最底层：力矩与速度限幅、碰撞检测、急停回路必须独立于上层软件工作。部署流程的每一步都要回答两个问题：这一步让哪些环节进入了验证范围，失败时如何安全退出。

本章与第 076 章的衔接：仿真输出的差距清单在这里逐项验证；与第 078 章的衔接：本章完成部署，下一章把整条抓取流水线放到真机上做阶段验收。

核心原理

1. 部署链路的五层与周期量级

层组件周期或频率典型故障
规划层move_group 与规划场景1–10 Hz，事件驱动场景不同步、起点过期
执行管理轨迹执行管理器与控制器接口事件驱动控制器未加载、时长不符
控制器关节轨迹控制器100–1000 Hz跟踪误差、超调
硬件接口ros2_control 硬件抽象0.5–10 ms读写失败、状态跳变
总线与驱动EtherCAT、CAN 或实时以太网1 ms 量级抖动、丢包、同步丢失

链路自上而下周期递减：规划层的毫秒级波动被控制器与硬件接口的固定周期"吸收"，总线层的微秒到毫秒级抖动则由驱动器的位置环消化。部署验证的顺序应自下而上：先确认总线周期与读写稳定，再确认控制器跟踪，最后接入规划层，与第一篇的调试路线一致。

2. 周期、延迟与跟踪误差

控制周期决定插值粒度，通信延迟决定指令的滞后，两者叠加为轨迹跟踪误差。滞后与速度的关系是线性放大：

elag ≈ v · tdelay 末端速度 0.25 m/s、总延迟 5 ms 时滞后约 1.25 mm；延迟清单包含控制器计算、总线传输与驱动器响应

把延迟项放入抓取误差预算（第 064 章的误差分层）：定位 0.5 mm、抓取抓偏 1.5 mm、延迟 1.25 mm 的合成误差约 2.02 mm，延迟项与抓取抓偏同量级，忽略它会让实际精度比预算差近一倍。抑制手段包括：降低接近段速度（延迟乘速度减小）、提高控制器频率（周期项减小）、使用前馈补偿（控制器侧手段）。

3. 执行监控与恢复

参数典型值作用放宽的后果
时长缩放1.2实际时长上限为计划的 1.2 倍执行异常延迟暴露变慢
时长余量0.5 s额外时间缓冲小轨迹的异常被掩盖
起点容差0.01–0.05 rad轨迹起点与当前状态的允许偏差从偏差位姿起步，首帧跳变
完成确认开启等待控制器报告完成再判成功轨迹未走完即进入下一阶段

监控的目的是把"执行异常"转换为可处理的失败事件：超时中止后，恢复策略按代价递增为"重规划同段轨迹、退回到安全位形、上报人工"。起点容差需要与状态更新频率匹配：状态发布 50 Hz 时，一个周期的运动量约 0.005 rad 量级，容差取 0.01 rad 可吸收发布间隔，过小则频繁拒绝执行、过大则失去保护意义。

4. 标定链与安全限幅

标定链三级串联，残差逐级进入抓取误差预算：

  • 连杆与零位标定：修正 URDF 中的连杆几何与关节零位，残差 0.1–0.3 mm 量级。
  • 工具中心点（Tool Center Point, TCP）标定：确定工具坐标系相对法兰的位姿，残差 0.1–0.5 mm。
  • 手眼标定：确定相机与机械臂或工作台的相对位姿，残差 0.5–2 mm，是感知抓取精度的主导项。

安全限幅分三层，缺一不可：控制器层的速度与加速度限制（软件）、驱动器层的力矩限幅（通常在驱动固件）、独立的急停回路（硬件，不经软件路径）。软件限幅负责把常规动作约束在安全包络内，硬件回路负责失效安全：任何一层失效，下一层仍能阻止危险动作（第 093 章展开）。

实现思路与设计

真机部署的步骤：

  1. 底层验证：接通总线与驱动器，确认读写周期稳定、关节方向与零位正确（手动示教小角度往复）。
  2. 控制器验证：加载关节状态广播与轨迹控制器，空载执行单关节轨迹，测量跟踪误差。
  3. 标定：依次完成连杆零位、TCP 与手眼标定，记录各项残差。
  4. 安全验证：限幅参数逐项生效，急停回路独立动作，碰撞检测灵敏度符合预期。
  5. 分阶段放量：速度缩放 0.3 起步，空载走通全轨迹；带载验证夹持；随后逐档提速。
  6. 监控与恢复：执行监控参数生效，恢复策略按"重规划、回退、上报"三级验证。

部署参数表

参数典型值作用取值依据
控制器更新率500–1000 Hz插值精度高于规划层两个量级
初始速度缩放0.3首次试运行速度误差与冲击随速度线性下降
时长缩放1.2执行超时判定覆盖减速与通信波动
起点容差0.02 rad起点一致性匹配状态发布周期的运动量
TCP 标定残差< 0.5 mm工具精度进入抓取误差预算
手眼标定残差< 2 mm感知精度感知抓取的主导误差项
跟踪误差上限2 mm控制器健康指标小于抓取位姿容差
设计决策：为什么从 0.3 速度缩放起步？

跟踪误差中与速度成正比的项（延迟滞后、离心与科氏项、柔性激励）在低速下都显著减小，首轮运行的目标是把时序与流程问题暴露出来而不放大其后果。每档缩放的通过条件预先定义（跟踪误差、完成率、无异常中止），达标才允许提升，最终以验收节拍对应的缩放值收尾。

关键代码与解读

片段 1：执行监控参数配置

move_group:
  ros__parameters:
    trajectory_execution:
      execution_duration_monitoring: true     # 开启执行时长监控
      allowed_execution_duration_scaling: 1.2 # 实际时长上限 = 计划时长 × 1.2
      allowed_goal_duration_margin: 0.5       # 额外余量（秒）：吸收减速与通信波动
      allowed_start_tolerance: 0.02           # 起点容差（弧度）：与当前状态的允许偏差
      wait_for_trajectory_completion: true    # 等控制器确认完成后再判成功
# 参数含义与默认值随 MoveIt2 发行版演进，以官方文档为准

解读：（1）五个参数共同回答两个问题：轨迹是否按时完成（时长监控与缩放）、轨迹是否从正确的位置开始（起点容差与完成确认）。（2）时长余量 0.5 s 对小段轨迹而言比例很大，收紧时应按最长轨迹的 5%–10% 折中设定，避免把异常拖延藏在余量里。（3）起点容差的量级与状态发布的周期匹配：0.02 rad 对应状态更新间隔内机械臂的正常运动量，既不会误拒也不会放过真实的起点偏移。配置后要做两类注入实验：人为滞后状态更新验证容差行为，人为延长执行验证时长监控。

片段 2：硬件接口的 read 与 write 周期

#include <hardware_interface/system_interface.hpp>

// 简化的系统硬件接口骨架：每个控制周期执行一次 read 与 write
class ArmSystem : public hardware_interface::SystemInterface {
public:
  hardware_interface::return_type read(const rclcpp::Time &t,
                                       const rclcpp::Duration &period) override {
    int rc = driver_.readPositions(&positions_[0], positions_.size());
    if (rc != 0) {
      // 读取失败不抛异常：保留上次位置，避免规划层看到跳变而中止
      ++read_failures_;
      RCLCPP_WARN_THROTTLE(logger_, *clock_, 1000, "总线读取失败 %d 次", read_failures_);
    }
    return hardware_interface::return_type::OK;
  }

  hardware_interface::return_type write(const rclcpp::Time &t,
                                        const rclcpp::Duration &period) override {
    driver_.writeCommands(commands_.data(), commands_.size());  // 驱动层再复检限幅
    return hardware_interface::return_type::OK;
  }

private:
  Driver driver_;                       // 总线驱动封装：负责协议与错误码映射
  std::vector<double> positions_;       // 状态接口缓冲区
  std::vector<double> commands_;        // 指令接口缓冲区
  int read_failures_{0};                // 读取失败计数：超阈值应触发安全降级
  rclcpp::Clock::SharedPtr clock_;
  rclcpp::Logger logger_{rclcpp::get_logger("arm_system")};
};

解读：（1）read 与 write 在固定周期内被调用，接口函数的执行时间必须远小于周期；把耗时的诊断逻辑放在这里会直接破坏周期稳定性。（2）读取失败时保留上次位置是常见折中：状态不跳变，但会静默过期，因此必须配合失败计数与阈值降级，否则规划层会在错误的状态上持续工作。（3）指令限幅在硬件接口与驱动层各做一次，属于防御式设计的双保险；接口层限幅保护机械臂，驱动层限幅保护电机与减速器。

片段 3：分阶段放量的通过条件表

def deployment_stages():
    """真机放量阶梯：每档的通过条件预定义，达标才允许提升。"""
    return (
        {"scale": 0.3, "pass_if": "空载轨迹跟踪误差 < 1 mm，无执行中止"},
        {"scale": 0.5, "pass_if": "带载轨迹成功，夹持确认与附着时序正确"},
        {"scale": 0.8, "pass_if": "连续 20 次抓放成功，无恢复事件"},
        {"scale": 1.0, "pass_if": "节拍与第 078 章验收指标全部达标"},
    )

for s in deployment_stages():
    print(f"速度缩放 {s['scale']}：通过条件 {s['pass_if']}")

解读：（1）通过条件把"感觉没问题"换成可判定的数字：跟踪误差、成功次数与恢复事件数，每一档的验证范围比上一档扩一档（空载、带载、连续运行、节拍）。（2）速度缩放是覆盖全链路的单一控制变量：它同时缩放规划层的轨迹速度、控制器的插值速率与硬件层的运动幅度，用它做放量阶梯可以用最小复杂度控制风险。（3）达标条件写入部署记录，回退时按档位反向执行（1.0 退回 0.8 退回 0.5），保证任何异常都能退到已验证的安全状态。

常见坑

  • 起点容差过小：轨迹频繁被拒绝执行，日志显示起点偏差超限。修复：容差与状态发布频率匹配（0.01–0.05 rad），并确认状态订阅的时延没有异常。
  • 时长缩放过大：控制器异常或机械卡滞时执行被拖延很久才报错，小段轨迹的异常被余量掩盖。修复：缩放收紧到 1.2 附近、余量按最长轨迹比例设定，并开启时长监控事件上报。
  • 跳过 TCP 与手眼标定直接抓取：抓取位姿存在系统性偏移，方向误差随距离放大。修复：标定入验收清单，残差超限不允许进入带载阶段。
  • 总线读取失败静默处理：状态停滞数秒后规划层在过期状态上工作，恢复执行时位置跳变。修复：失败计数与时间阈值联动，超限即触发控制器停止并上报。
  • 用软件限幅替代急停回路：软件层僵死时失去最后保护。修复：急停回路独立布线，任何部署阶段都必须先验证回路动作有效。

练习与思考

  1. 控制器通信延迟合计 5 ms，末端接近段速度 0.25 m/s。计算延迟引入的位置滞后；若抓取容差为 2 mm，说明该项在误差预算中的占比。★
    提示
    滞后 = 0.25 × 0.005 = 1.25 mm，占容差的六成以上；与第 064 章的分层误差合并计算时，延迟项与抓取抓偏同量级。
  2. 把起点容差从 0.01 rad 放宽到 0.05 rad，预测执行拒绝率与首帧跳变的可能后果，并给出选择依据。★★
    提示
    拒绝率下降、可用性提高；代价是允许从较大偏差起步，首帧位置跳变转化为速度尖峰，可能激励柔性（第 075 章）与触发碰撞阈值。选择依据是状态更新周期对应的正常运动量。
  3. TCP 标定残差 0.3 mm、手眼标定残差 1.0 mm、定位误差 0.5 mm。按平方和开方合成，并说明哪一项优先改进。★★
    提示
    RSS = √(0.09 + 1.0 + 0.25) ≈ 1.16 mm；手眼标定为主导项，优先改进标定流程与验证方法。
  4. 为一条六轴臂编写部署验证清单：列出每个层的验证项、量化判据与失败处置，并标注哪些项必须在带载前完成。★★★
    提示
    底层：读写周期、零位与方向；控制器：跟踪误差小于 2 mm；标定：TCP 小于 0.5 mm、手眼小于 2 mm；安全：限幅与急停动作；以上四项均在带载前完成，带载阶段验证夹持确认、附着时序与恢复策略。

小结

  • 部署链路分五层，周期自上而下递减，验证顺序自下而上：总线、控制器、标定、安全，最后接入规划层。
  • 通信延迟与速度的乘积构成轨迹跟踪误差的延迟项，量级与抓取抓偏相当，必须纳入误差预算。
  • 执行监控由时长监控、时长缩放与余量、起点容差与完成确认共同构成，参数放宽会掩盖异常、收紧会降低可用性。
  • 标定链的残差逐级进入抓取精度，手眼标定通常为主导项；安全限幅分软件与硬件两层，急停回路必须独立验证。
  • 分阶段放量以速度缩放为单一控制变量，每档设定量化通过条件，下一章给出完整流水线的验收指标与阶段实践方案。
