第二篇 · 规划场景与碰撞管理

第 028 章：碰撞检测与自碰撞避免

布尔问题背后的完整机器：本章讲宽阶段与窄阶段如何分工、自碰撞豁免从哪里来、退让距离与几何缩放如何改变判定结果、离散采样检查与连续碰撞检测的边界，以及碰撞结果的诊断读法。

  • 主题：碰撞检测内部机制 / 自碰撞管理
  • 关键机制：宽窄两阶段检测、允许碰撞矩阵、退让距离与连续检测
  • 预计学时：55 分钟
  • 前置章节：第 027 章

学习目标

  • 理解碰撞检测的宽阶段与窄阶段分工，以及包围体层次在两个阶段中的角色。
  • 掌握自碰撞检查的判定规则：默认检查全部连杆对，豁免来自允许碰撞矩阵；矩阵条目由 SRDF、附加操作与任务代码共同维护。
  • 能解释退让距离（Padding）与几何缩放（Scale）对判定结果的影响，并给出合理的取值区间。
  • 理解轨迹碰撞检查的离散化：检查密度参数如何决定采样点数与漏检风险，连续碰撞检测补齐什么。
  • 会读取碰撞结果中的连杆对与接触信息，把碰撞报告定位到具体的场景或配置问题。

背景与动机

前面章节把物体放进场景，本章回答规划器究竟怎样在场景上做判定。碰撞检测是规划中被调用次数最多的计算：一次规划尝试包含成千上万次状态检查，每次检查又要遍历大量几何对。它的实现分成两个阶段处理规模问题，它的判定结果又受到三类配置的调制：自碰撞豁免、退让距离、检查密度。任何一类配置失当，都会以"规划失败"或"规划成功但真机刮蹭"的形式浮出水面。

本章把这三类配置与内部机制放在一张图里讲清楚：豁免决定"哪些对根本不检查"，退让距离决定"检查时几何被放大多少"，检查密度决定"轨迹的哪些瞬间被检查"。三者正交，排障时可以逐项隔离。理解它们之后，第 029 章的避障规划与第 042 章的请求适配器就有了共同的语言基础。

核心原理

1. 两阶段管线：宽阶段先筛，窄阶段精算

场景中的几何对象两两组合数量巨大：机器人有十余根连杆，世界有几十个物体与占据栅格里的成千个体素化节点，暴力两两精算不可承受。检测器的标准做法是先粗后精：

  • 宽阶段（Broadphase）：为每个对象维护一个包围体（通常是轴对齐包围盒或层次结构中的节点包围盒），只对包围体相交的对象对进入下一阶段。代价正比于候选对数，与几何细节的规模无关。
  • 窄阶段（Narrowphase）：对候选对做精确求交：解析形状走凸几何算法，网格走三角形对判定。窄阶段通常带有早退机制：找到第一个接触即返回，不再计算其余接触。

这条管线解释了单次检查的代价分布：机器人远离障碍时几乎全耗在宽阶段，几十微秒量级；姿态进入障碍附近后候选对激增，窄阶段主导，代价上升到毫秒量级。规划采样中"碰撞检查主要发生在障碍附近"，因此规划时间的增长往往与路径经过的拥挤程度直接相关。把物体表示从网格换成解析形状，主要福利落在窄阶段；把场景物体数量从几十降到十几个，福利落在宽阶段。

2. 自碰撞：默认全查，豁免显式化

自碰撞检查遍历机器人连杆对：相邻连杆通过关节相连，物理上必然贴近或接触，永远重叠的连杆对（例如固定在同一个基座上的两根连杆）也属于此类。把这类对逐一豁免的机制是允许碰撞矩阵（ACM）的初始条目，条目通常来自运动学描述中的禁用碰撞声明（SRDF 的 disable_collisions 元素），由配置阶段的工具生成，按原因分为相邻（Adjacent）、采样中从未碰撞（Never）、始终重叠（Always）等类别。

运行时，矩阵有三类动态修改来源：附加与分离操作按 touch_links 增删条目（第 025、026 章）；任务代码为特定碰撞对临时放宽或收紧；规划场景服务透传的差分修改。判定的默认策略是"除显式豁免外全部检查"，这是安全至上的设计：遗漏一条豁免只会导致假碰撞（规划失败可排查），而多一条错误豁免会静默丢失真实碰撞检测（可能直接撞机）。两者代价不对称，因此评审矩阵条目时应当从紧。

3. 退让距离与几何缩放：把判定放大或缩小

两类几何调制手段作用于参与检查的机器人几何：退让距离（Padding）在几何表面外均匀加一层厚度，几何缩放（Scale）把几何按比例放大。对长方体，两者的效果可以近似写成：

deff = scale × d + 2 × padding d 为标称尺寸；padding 取 0.005–0.02 m 量级，scale 通常接近 1，仅在需要整体放大时使用

padding 与 scale 的语义差异值得强调：padding 是绝对厚度，与几何大小无关，适合补偿感知误差与安装偏差；scale 是相对倍数，大连杆被放大得更多，适合按比例建模的粗糙外形。规划场景通常持有一份"带调制"的环境用于规划，另有一份"未调制"的环境用于接触信息汇报：规划用带裕量的几何换来安全余量，而汇报给人的接触应基于真实几何，两者不可混用。当规划报告"起点碰撞"而视觉上明显没有接触时，第一个检查项就是 padding 的取值。

4. 轨迹检查的离散化与连续检测

规划给出的轨迹是连续曲线，检查器只能在有限个状态上判定，两个被检查状态之间的运动是"信任区间"。检查密度由此成为安全性参数：检查过疏会漏掉薄障碍的穿越（在采样点之间穿过），检查过密会成倍增加规划时间。多数采样规划器用一个"最长有效段比例"参数控制离散化：它规定两次检查之间的状态距离不超过工作空间尺度的给定比例。以关节空间为例，该比例与关节行程的乘积给出相邻检查点之间的最大关节位移。

连续碰撞检测（Continuous Collision Detection, CCD）从另一条路补齐间隙：它把两个检查状态之间的运动看作扫掠体，用保守推进（Conservative Advancement）等方法搜索区间内是否存在接触时刻，从"检查点"升级为"检查区间"。CCD 的代价显著高于离散检查，通常在安全相关环节（执行前验证、快速运动的轨迹段）启用，采样规划内核保持离散加合理密度。附加体与 CCD 的配合存在实现层面的限制（例如部分检测器不处理附加体），带载场景启用前应实测确认。

5. 结果解读：从布尔量到连杆对

碰撞结果的完整信息包括三个层次：布尔结论（是否碰撞）、涉及的连杆对或对象名、接触点信息（位置、法向、穿透深度，取决于请求开关与检测器支持）。诊断价值集中在第二层：

碰撞对类型常见根因处理方向
机器人内部两连杆SRDF 豁免缺失、附加体接触集合漏项核对矩阵条目，按物理事实增补
连杆与世界物体物体位姿或尺寸错误、退让距离放大核对物体数据与 padding 取值
附加体与世界夹持位姿偏差、载荷外形建模过粗核对相对位姿与载荷几何
连杆与地面目标状态低于可达高度、基座坐标系错位检查目标位姿与参考系

把碰撞对当作线索来读，排障路径会从"反复试参数"变成"按表定位"。

实现思路与设计

碰撞判定相关配置的整理流程：

  1. 审计豁免条目：从配置文件中统计禁用碰撞对的数量与原因分类，对"始终重叠"类逐条确认必要性。
  2. 设定退让距离：按感知误差与工装公差选定（常用 0.005–0.02 m），在隔离环境验证；调节后重跑关键任务的规划成功率。
  3. 校核检查密度：用小障碍（薄板）设计穿透回归用例，把检查密度调到能可靠发现为止。
  4. 决定连续检测的启用范围：执行前验证与高速段启用，其余保持离散检查；带载场景单独验证。
  5. 建立碰撞诊断流程：规划失败时先看碰撞对，再按上表定位；把典型碰撞对的处理方法固化为检查清单。

关键代码与解读

片段 1：C++ 自碰撞检查并取回碰撞对（接口以对应 ROS2 发行版与 MoveIt2 版本的官方文档为准）

collision_detection::CollisionRequest creq;
creq.group_name = "arm_group";     // 只检查该组连杆两两之间
creq.contacts = true;              // 需要接触信息用于诊断
creq.max_contacts = 10;            // 保留前若干个接触，避免结果膨胀

collision_detection::CollisionResult cres;
planning_scene->checkSelfCollision(creq, cres, *current_state);

if (cres.collision)
{
  // 先汇报结论，再逐条列出碰撞对：诊断价值集中在"哪对连杆"
  RCLCPP_WARN(node->get_logger(), "自碰撞检出 %zu 条接触", cres.contact_count);
  // contacts 按"碰撞对"组织，逐对取出名称；具体字段组织随版本演进，以头文件为准
  for (const auto& pair : cres.contacts)
  {
    RCLCPP_WARN(node->get_logger(), "碰撞对：%s 与 %s",
                pair.first.first.c_str(), pair.first.second.c_str());
  }
  // 常见处置：核对 SRDF 豁免与附加体接触集合，避免调低检查强度
}

解读：（1）请求里指定规划组，自碰撞检查被收窄到任务相关的连杆集合；全机器人检查留给诊断场景，规划内层不做无差别扫描。（2）contacts 开关与最大接触数是一对成本控制的组合：诊断时保留若干条足够定位问题，内层检查把它设为 1 并保持早退行为。（3）注释强调处置顺序：检出碰撞后的正确动作是核对豁免配置与几何数据，"调低检查强度"看似能让规划通过，实际是在移除安全防线。

// 只读视图：核对关键碰撞对的豁免状态（条目可能来自 SRDF 生成）
const collision_detection::AllowedCollisionMatrix& acm =

if (acm.hasEntry("link_5", "link_6"))
{
  // 相邻连杆通常携带豁免；确认原因属于预期类别即可放行
  RCLCPP_INFO(node->get_logger(), "相邻连杆豁免条目存在");
}
else
{
  RCLCPP_WARN(node->get_logger(), "相邻连杆无豁免，规划可能出现假自碰撞");
}

// 非 const 视图：为特定碰撞对写入最小范围豁免
// 典型场合：放置完成后手指与放置物仍接触，需要临时放宽
collision_detection::AllowedCollisionMatrix& acm_mutable =
    planning_scene->getAllowedCollisionMatrixNonConst();
acm_mutable.setEntry("part_a_placed", "finger_left", true);
// 豁免的生命周期与业务同步：任务收尾时撤销该条目，避免长期扩大豁免面

解读：（1）查询接口回答"这条豁免在不在"，核对它回答"该不该在"：相邻连杆缺豁免与工作物体多豁免都会改变判定结果，前者制造假碰撞，后者隐藏真碰撞。（2）写入口只用于必要场合且范围最小化：一次只写入一对（物体与手指），范围收窄到必要粒度。（3）豁免条目的生命周期需要与业务事件绑定：任务的放置流程写入，收尾流程撤销；缺少撤销机制的系统里，豁免集合会随运行时长单调扩张，安全性缓慢退化。

片段 3：Python 审计 SRDF 中的自碰撞豁免

import xml.etree.ElementTree as ET

def summarize_srdf_exemptions(srdf_path):
    """统计运动学描述中禁用的自碰撞对，按原因分类检查合理性。"""
    root = ET.parse(srdf_path).getroot()
    counts = {}
    for tag in root.iter("disable_collisions"):
        # reason 常见取值：Adjacent（相邻连杆）、Never（采样中从未碰撞）、
        # Always（始终重叠）、Default（工具默认）等
        reason = tag.get("reason", "未标注")
        counts[reason] = counts.get(reason, 0) + 1
    total = sum(counts.values())
    print(f"禁用碰撞对共 {total} 对，按原因分布：{counts}")
    # 相邻类占到大多数属于正常结构；"始终重叠"类应逐条能解释成因
    return counts

summarize_srdf_exemptions("config/arm.srdf")

解读：（1）豁免集合的源头在配置文件，审计脚本把"有多少条、什么原因"变成一次可运行的统计，替代逐个元素的肉眼浏览。（2）原因分布是健康度的信号：相邻类条目多属于正常；"始终重叠"类每一条都应当能用结构解释（固定重叠的连杆组），解释不了的条目意味着建模或生成过程有偏差。（3）该脚本适合放进配置变更流程，运动学描述每次改动后重跑一遍，把豁免面的变化显式化。

常见坑

  • 豁免面过宽：为让规划通过把大段连杆对列入豁免，载荷与前臂的穿透不再被检查。症状是规划全部成功而真机频繁刮蹭。修复是豁免条目按物理事实逐条评审，把临时放宽与永久豁免分开管理。
  • 检查密度过粗：用薄板障碍做回归时发现规划路径"穿过"障碍，采样点恰好落在板两侧。修复是减小最长有效段比例，或对快速段启用连续碰撞检测，并用薄障碍作为固定回归用例。
  • 退让距离养成连锁故障：padding 调到厘米级后，狭窄工位内所有规划同时失败；调回后裕量又不足。修复是把 padding 与工装公差、感知误差对齐取值，并在隔离环境验证后再上线。
  • 起点状态未单独检查：规划失败信息指向"起点碰撞"时，误判为规划器问题。修复是规划前用状态检查单独判定起点与目标，把碰撞对日志作为第一手线索。
  • 把附加体当作普通物体检查：附加体的接触规则由 touch_links 决定，用世界物体的检查逻辑理解其接触报告会得出错误结论。修复是核对附加体的允许接触集合，再解读其碰撞报告。

练习与思考

  1. 采样估算：某关节行程 2π rad，最长有效段比例取 0.005。估算该关节扫过全行程时被检查的状态个数；比例改为 0.002 后如何变化？★
    提示
    段长约为 0.005 × 2π ≈ 0.0314 rad，全行程约需 2π / 0.0314 ≈ 200 次检查；改为 0.002 后约 500 次，检查次数与规划时间同步上升。
  2. 参数预测：工位最小通道宽度 6 cm，机器人连杆的 padding 从 0 调到 0.02 m。分析通道两侧各损失多少空间、规划成功率与真机安全裕量分别朝哪个方向变化。★
    提示
    连杆两侧各加 2 cm，等效通道宽度从 6 cm 降到 2 cm，成功率下降而裕量上升；若通道原本就紧张，应改用局部收紧的几何调制或用解析形状精修外形，避免全局 padding。
  3. 设计题：设计一套碰撞判定配置的验收流程，包含豁免审计、padding 验证、密度回归与连续检测范围四项，各给出通过判据。★★
    提示
    豁免审计通过判据为"始终重叠类每条可解释"；padding 验证为"关键任务成功率与裕量同时满足"；密度回归为"薄板用例稳定检出"；连续检测范围为"执行前验证启用且耗时在预算内"。
  4. 诊断题：规划器报告起点自碰撞，碰撞对为两根相邻连杆。列出两种根因与修复方向，并说明为什么此类报告在更换 URDF 后集中出现。★★
    提示
    根因一是 SRDF 豁免未随模型更新，新连杆缺少相邻豁免；二是模型调整后两连杆几何真实重叠，需要修模型。更换模型后集中出现说明豁免面未同步生成，应重跑配置工具并审计差异。
  5. 分析题：比较离散检查加合理密度与连续碰撞检测两种方案，从误检漏检、代价、与附加体的兼容性三个角度分析，给出一个执行前验证环节的推荐组合。★★★
    提示
    离散方案代价低、实现普遍，漏检与密度直接相关；CCD 覆盖区间、误检少但代价高且部分实现不处理附加体。执行前验证可用"离散加密检查加关键段 CCD"的组合，带载段先实测再启用。

小结

  • 碰撞检测按宽阶段与窄阶段分工：包围体筛选候选对，精确求交带早退；代价随障碍邻近程度上升。
  • 自碰撞默认全查，豁免显式化：SRDF 禁用条目、附加操作与任务代码是三类动态来源，代价不对称要求豁免从紧。
  • 退让距离按绝对厚度放大几何，几何缩放按比例放大；规划用调制几何，接触汇报用未调制几何。
  • 轨迹检查在采样点上判定，检查密度参数控制漏检风险，连续碰撞检测以更高代价覆盖区间。
