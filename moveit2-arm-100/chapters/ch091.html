第 091 章：性能评估指标体系

定义规划与执行两类核心指标（成功率、时间分布、路径长度、平滑度、间隙、跟踪误差），给出采集点、统计口径与回归对比方法，让调参结论可量化、可复现。

  • 主题：评估方法 / 指标与统计
  • 关键机制：指标定义与计算、百分位统计、置信区间、对照实验设计
  • 预计学时：55 分钟
  • 前置章节：第 090 章

学习目标

  • 掌握规划质量、执行质量与系统质量三层指标的完整清单与定义式。
  • 会从轨迹消息与规划响应中计算路径长度、平滑度与速度余量等指标。
  • 理解统计口径：为什么要用中位数与百分位（平均值会被长尾拉偏），样本量如何影响结论可信度。
  • 会设计对照实验与回归基线，使调参前后结论可比。
  • 能把指标接入调参闭环，用数据选择参数组合。

背景与动机

规划参数调整的常见困境是"感觉变好了"：换规划器、加时间预算、放宽约束后，成功的案例变得顺畅，失败的案例依旧存在，整体是否进步没有量化依据。指标体系的用途是回答三个问题：当前系统处于什么水平、参数改动是否带来统计上可信的改善、改善的代价是什么。

没有指标体系时，优化容易陷入单点：盯着一次规划的成功与耗时，忽略分布尾部；只测规划不测执行，忽略跟踪误差；只统计成功样本，失败样本被静默丢弃。本章把指标、采集、统计与对比四件事固定成流程。

上一章完成环境迁移，本章给迁移后的系统建立度量标准；第 100 章的验收指标将直接复用本章的方法。

核心原理

1. 三层指标清单

指标按观测对象分三层：规划质量描述"解好不好"，执行质量描述"执行准不准"，系统质量描述"任务稳不稳"。三层指标各自有独立的采集点，混用会造成归因错误。

层指标单位采集点
规划质量成功率、规划时间（中位数与 P95）百分比、秒规划响应
规划质量关节空间路径长度、末端路径长度弧度、米轨迹路点
规划质量平滑度（加加速度近似）、最小间隙相对量、米轨迹路点与场景
执行质量轨迹跟踪误差、重复定位误差米、弧度命令与反馈对比
执行质量执行耗时、停止距离秒、米执行反馈与安全链路
系统质量任务成功率、恢复成功率百分比任务编排层

2. 几何与运动学指标的定义

路径长度有两种口径：关节空间长度对每对相邻路点的关节增量取范数求和；末端路径长度对路点做正运动学后对末端位置增量求和。两者可同时偏大或背离，关节空间短而末端路径长的轨迹说明末端在冗余运动，反之说明工具端走了捷径。

L关节 = Σk wg ‖qk+1 − qk‖1（wg 为关节权重）
L末端 = Σk ‖p(qk+1) − p(qk)‖2 关节权重按行程归一，避免大行程关节主导长度指标；末端路径长度直接对应视野中的路径观感

平滑度用加加速度（Jerk）近似：对位置序列做二阶差分得到加速度、三阶差分得到加加速度，取平方和或绝对值和。该近似对采样密度敏感，比较时两个轨迹必须用同样的重采样步长。最小间隙沿路点逐点查询场景距离，取最小值；它是安全余量的直接度量。

J ≈ Σk ‖qk+3 − 3qk+2 + 3qk+1 − qk‖2 / Δt6 等步长重采样后 Δt 为常数；只比较同采样密度下的相对值，不与绝对物理意义挂钩

3. 统计口径：用分布描述样本

规划时间呈长尾分布：多数样本集中在数百毫秒，少数样本接近预算上限。平均值被尾部拉偏，中位数代表典型体验，P95 代表接近最坏情况。成功率是二项比例，样本量决定其可信区间宽度：

95% 置信区间：p̂ ± 1.96 · √( p̂(1 − p̂) / n ) n = 100、p̂ = 0.9 时区间约为 ±5.9 个百分点；n = 400 时收窄到约 ±2.9 个百分点，声明"提升 3 个百分点"至少需要数百次样本

统计口径还要处理失败样本：失败没有路径长度与耗时，按惯例不计入质量指标的分母，但必须单独报告失败率。只报成功样本的质量指标会系统性乐观，这一偏置要在报告里显式说明。

4. 对照实验与回归基线

指标的价值在对比中体现。对照实验遵循三条规则：同一批任务集（相同起止状态与场景）、每个配置重复足够次数、一次只改一个变量。把当前最优配置的结果固化为回归基线，每次改动后重跑同一批任务，指标低于基线阈值即回退。

判定规则示例：成功率不下降且 P95 规划时间改善超过 10% 才接受新配置 双条件避免"用时间换成功率"或反向的暗交换；阈值按置信区间宽度设定，小于区间半宽的改善不具备统计意义

实现思路与设计

评估系统按"采集、聚合、对比、回写"四步搭建，每一步的产物都可独立检查。采集精准到单次调用，聚合按批次进行，对比固定任务集，回写给出接受或回退结论。

1. 指标采集表

指标数据来源计算方式刷新时机

任务成功率编排层状态机完成次数除以下达次数每批次

2. 任务集设计

任务集从实际工况抽取，覆盖三类样本：典型样本（高频出现的起止组合）、边界样本（接近工作空间边缘与最小间隙位置）、失败倾向样本（历史上失败过的组合）。三类的比例写入实验设计文档，批次间不得悄悄调整，否则前后批次不可比。

3. 与调参闭环的衔接

调参循环固定为：运行基线批次、单变量修改、运行对比批次、按判定规则接受或回退。每个被接受的配置连同其批次标识（任务集标识、参数快照、软件版本）写入基线记录，回归时可追溯差异来源。

与上一章的差异点：第 090 章定义迁移阶段之间的退出准则，本章把准则展开为可计算的指标集合与统计方法，两者共用同一批观测信号。

关键代码与解读

片段 1：从轨迹计算路径长度与平滑度

import math


def joint_path_length(traj, weights=None):
    """关节空间路径长度：相邻路点增量的加权绝对值和。"""
    names = traj.joint_trajectory.joint_names
    points = traj.joint_trajectory.points
    w = weights or {n: 1.0 for n in names}
    total = 0.0
    for a, b in zip(points, points[1:]):
        # 不同关节行程差异大，按权重归一后再累加，避免大行程关节主导
        total += sum(w[names[i]] * abs(b.positions[i] - a.positions[i])
                     for i in range(len(names)))
    return total


def smoothness_jerk(traj):
    """平滑度近似：位置三阶差分的平方和（等步长重采样后比较）。"""
    points = traj.joint_trajectory.points
    if len(points) < 4:
        return 0.0
    acc = 0.0
    for k in range(len(points) - 3):
        for i in range(len(points[k].positions)):
            # 三阶差分近似加加速度，取平方和作为不平滑度的度量
            j = (points[k + 3].positions[i] - 3 * points[k + 2].positions[i]
                 + 3 * points[k + 1].positions[i] - points[k].positions[i])
            acc += j * j
    return acc


def time_percentiles(times, q=0.95):
    """时间分布统计：中位数与分位点，反映典型值与接近最坏情况。"""
    ordered = sorted(times)
    n = len(ordered)
    median = ordered[n // 2] if n else float("nan")
    idx = min(n - 1, math.ceil(q * n) - 1) if n else 0
    return median, (ordered[idx] if n else float("nan"))

解读：三个函数覆盖质量指标的核心计算。设计要点：（1）路径长度按关节加权，权重集中传入便于统一口径；（2）平滑度用三阶差分近似，注释中明确"等步长比较"的前提，防止跨采样密度直接对比；（3）分位函数显式处理空输入，避免批次缺样本时崩溃。这些函数只依赖轨迹消息，可离线对历史批次重算，指标口径修改后旧数据可复用。

片段 2：批次运行器与结论判定

import math, statistics
def percentile(xs, q):
    """分位点：按升序取最近的上界位置，空输入返回 None。"""
    ordered = sorted(xs)
    if not ordered:
        return None
    idx = max(0, min(math.ceil(q * len(ordered)) - 1, len(ordered) - 1))
    return ordered[idx]

def run_batch(planner_fn, task_set, params, repeat=5):
    """在固定任务集上重复运行，返回规划质量与时间样本。"""
    times, lengths, failures = [], [], 0
    for task in task_set:
        for _ in range(repeat):
            # 每个样本重新设置同一对起止状态：批次内条件完全一致
            result = planner_fn(task.start, task.goal, params)
            if not result.ok:
                failures += 1
                continue                       # 失败样本不计入时间与长度
            times.append(result.planning_time)
            lengths.append(result.path_length)
    total = len(task_set) * repeat
    return {
        "success_rate": 1.0 - failures / total, "n": total,
        "time_median": statistics.median(times) if times else None,
        "p95": percentile(times, 0.95) if times else None,
        "len_median": statistics.median(lengths) if lengths else None,
    }

def decide(baseline, candidate, min_improve=0.10):
    """接受规则：成功率不降，且 P95 时间改善超过阈值。"""
    if candidate["success_rate"] < baseline["success_rate"]:
        return False, "成功率下降"
    if candidate["p95"] is None or baseline["p95"] is None:
        return False, "样本不足"
    improve = (baseline["p95"] - candidate["p95"]) / baseline["p95"]
    if improve >= min_improve:
        return True, f"P95 改善 {improve:.1%}"
    return False, f"改善不足（{improve:.1%}）"

解读：批次运行器把实验协议变成代码。关键行为：（1）失败样本从质量统计中剔除但计入成功率的统计，报告中两类数字并列，偏置显式可见；（2）批次规模 total 随任务数与重复数计算，作为置信区间的样本量；（3）接受规则用双条件表达"不牺牲成功率"这一约束，阈值与置信区间宽度挂钩。替代方案是人工比较两份运行结果，难以排除场景与状态差异带来的干扰。

片段 3：沿轨迹的间隙检查（C++）

#include <moveit/robot_trajectory/robot_trajectory.h>
#include <moveit/planning_scene/planning_scene.h>

double min_clearance(const planning_scene::PlanningScenePtr& scene,
                     const robot_trajectory::RobotTrajectory& traj) {
  double worst = std::numeric_limits<double>::infinity();
  // 逐路点查询到最近障碍的距离：间隙指标是安全余量的直接度量
  for (std::size_t i = 0; i < traj.getWayPointCount(); ++i) {
    const moveit::core::RobotState& state = traj.getWayPoint(i);
    // 距离查询接口名称随版本略有差异，以本地头文件为准
    const double d = scene->getCollisionEnv()->distanceToCollision(state);
    worst = std::min(worst, d);
  }
  return worst;
}

void report(const planning_scene::PlanningScenePtr& scene,
            const robot_trajectory::RobotTrajectory& traj) {
  const double d = min_clearance(scene, traj);
  // 间隙低于阈值时标记为高风险轨迹：进入批次统计供对照
  if (d < 0.01) {
    RCLCPP_WARN(rclcpp::get_logger("metrics"),
                "最小间隙 %.4f m 低于预警阈值 0.01 m", d);
  }
}

解读：间隙指标把"看起来没碰到"变为可审计的数值。设计要点：（1）逐路点查询取最小值，最小值对应的位形即最危险位形，可单独回放复核；（2）查询使用规划场景的碰撞环境，与规划时的碰撞语义一致（第 028、085 章）；（3）阈值告警让低间隙轨迹进入统计对比。注意间隙指标只反映当前场景快照，动态场景下的对照实验需固定场景版本。

常见坑

  • 只用平均值描述时间：长尾被平均掩盖，P95 用户体感缺失。修复：至少同时报告中位数与 P95；样本量足够时报告更多分位点。
  • 样本量不足下结论：用几十次样本声称"提升明显"，改善幅度小于置信区间半宽。修复：按置信区间公式估算样本量，或明确标注结论为初步观察。
  • 失败样本静默剔除：质量指标只统计成功样本，成功率单独成表，报告中未说明偏置。修复：在报告固定位置并列报告成功率与质量分位数，并注明剔除规则。
  • 跨批次条件漂移：前后两次实验的任务集、场景版本或起始状态悄悄变化，指标不可比。修复：批次标识记录任务集标识、场景版本与参数快照，对比前先核对标识。
  • 跨采样密度比较平滑度：轨迹重采样步长不同，三阶差分开口径变化。修复：统一重采样步长后再计算，或在报告中标注步长。

练习与思考

  1. 计算：200 次规划中 186 次成功，求成功率点估计与 95% 置信区间；若要声明"成功率达到 95% 以上"，样本量至少需要多少（按区间半宽 1.5 个百分点估算）？★
    提示
    p̂ = 0.93，区间约 ±3.5 个百分点；按 1.96√(0.95×0.05/n) ≤ 0.015 反解，n 约需 810 次。
  2. 给定两条轨迹的路点序列，一条关节空间长度更短、末端路径更长，解释两者背离的几何原因，并说明该现象的工程含义。★★
    提示
    冗余自由度让末端绕行而关节总行程较小；含义是关节空间指标与任务空间观感可能不一致，评估时两类都看。
  3. 设计对照实验：验证"把尝试次数从 10 提到 20"的效果，写出任务集组成、重复次数、观测指标与接受规则。★★
    提示
    任务集含典型、边界与失败倾向三类；重复至少 5 次达到数百样本；观测成功率与 P95 时间；接受规则要求成功率不降且 P95 改善超过阈值。
  4. 改参数并预测：把报告中的 P95 换成中位数作为接受规则，会更容易接受哪些改动？给出一个会被误接受的例子。★★
    提示
    中位数对尾部不敏感，会接受"典型变快但尾部恶化"的改动，例如降低单次预算导致多数样本快速返回、少数样本超时失败被剔除。
  5. 推导：说明为什么"失败样本不计入时间统计"会系统性低估或高估规划时间，并设计一个消除该偏置的报告方式。★★★
    提示
    失败样本往往耗时接近预算上限，剔除后时间分布偏快，即低估；消除方式是报告"含失败的截尾时间"或将失败样本按预算上限计入并标注。

小结

  • 三层指标：规划质量、执行质量、系统质量，采集点各自独立，避免归因错误。
  • 路径长度分关节与末端两种口径，平滑度用等采样密度下的三阶差分近似，间隙取沿轨迹最小值。
  • 时间用中位数与 P95 描述，成功率用置信区间描述；样本量决定可声明的改善幅度。
  • 失败样本的处理规则必须显式：剔除计入质量统计会造成乐观偏置。
  • 对照实验固定任务集与场景版本，基线加双条件接受规则构成调参闭环。
  • 下一章讨论时效约束：实时性与控制频率的权衡，把"规划时间"从统计指标变成系统设计约束。
