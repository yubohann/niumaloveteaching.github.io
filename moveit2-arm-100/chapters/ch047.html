第三篇 · 规划算法与求解器

第 047 章：运动规划基准测试 Benchmarking

规划器选型与调参的最终依据是数据：同一问题集上比较成功率、时间分布与轨迹质量。本章给出指标定义、实验设计方法、统计分析工具与自动化测试框架的完整方法链路。

  • 主题：评测方法论 / 规划基准测试
  • 关键机制：问题集、重复实验、分位数统计、成功率置信区间
  • 预计学时：55 分钟
  • 前置章节：第 046 章

学习目标

  • 理解规划基准测试的四个要素：问题集、配置快照、重复实验、统计指标，并能组织一次公平对比。
  • 掌握成功率、规划时间分位数、路径长度、平滑度、最小间隙等指标的定义与误用陷阱。
  • 会用重复实验框架测量规划器性能，并以置信区间表达结论，避免只给单点数值。
  • 了解 OMPL 基准测试日志与统计脚本的用途，知道 MoveIt 生态中批量评测工具的定位。
  • 能把一次评测的结论转化为选型与调参决策，并识别"过拟合单一场景"的结论风险。

背景与动机

第 041 章在单任务上标定时间与次数，第 044 到 046 章接触了不同家族的规划器。选型问题随之而来：同一臂、同一场景，RRTConnect、RRTstar、CHOMP 各给多长的预算、谁的成功率更高、谁的轨迹更适合执行？凭个别运行的直觉回答这类问题，结论会由随机波动主导。

基准测试把"规划器好不好"变成可复现、可统计、可归档的实验：固定问题集与配置，重复足够多次，用分布与区间说话。它也是第 048 章性能分析与第 060 章选型调优的数据基础。

核心原理

1. 四个要素：问题集、配置快照、重复、统计

一次合格的评测由四要素构成：

要素内容失效形态
问题集场景与起止位姿的集合，覆盖自由空间、近障、窄通道等类别只测一个场景，结论过拟合
配置快照规划器参数、适配器链、碰撞检测设置、版本信息两次对比的配置不同，结论无意义
重复实验每条配置对每个问题重复 30 到 50 次重复不足，分布信息缺失
统计指标成功率、时间分位数、路径质量指标只报平均值，掩盖尾部行为

公平性来自控制变量：两次对比之间只允许一个因素变化。规划器不同则其余参数逐项对齐，包括时间预算、尝试次数、适配器链与场景版本。

2. 指标定义与陷阱

指标定义陷阱
成功率成功次数 / 总次数小样本下波动大，需给置信区间
规划时间成功样本的墙钟时间只统计成功样本会把"难问题"排除在外，需同时报告超时与失败比例
路径长度关节空间相邻路径点距离之和与规划时间不可直接互换，长路径可能更快规划但执行更久
平滑度加速度平方和（第 043 章口径）不同分辨率下不可比，比较时统一重采样
最小间隙轨迹上各点到最近障碍的距离最小值离线计算时场景版本必须与规划时一致
轨迹时长时间参数化后的总执行时间受缩放因子影响，对比时固定缩放

成功率的置信区间用二项分布方法估计，常用 Wilson 区间：

p̂ ± z · √( p̂(1 − p̂) / n )，n ≥ 30 时近似可用 30 次全成功给出约 [0.89, 1.0] 的区间；要声称 99% 以上需要更大样本

结论：报告"成功率 100%"时若不附样本量，等于没有信息；30 次全成功只支持"成功率高于 89%"量级的判断。

3. 时间分布：分位数替代均值

采样求解时间呈重尾分布，均值被尾部样本拖高，不能代表典型体验。报告口径建议为：中位数（典型耗时）、P90（服务水平），并说明超时截断的位置。示例：某规划器 40 次成功样本中位数 0.31 s、P90 1.42 s，说明多数请求在半秒内解决，但每十次有一次超过 1.4 s。服务水平承诺应绑定 P90 或 P95；中位数只描述典型体验，不构成承诺依据。

4. 工具链：日志、脚本与批量运行

OMPL 自带基准测试框架：规划实验输出结构化日志（planner 名称、问题名、时间、路径代价等），配套统计脚本（如 ompl_benchmark_statistics.py）汇总为数据库并生成图表，Planner Arena 提供交互式对比。MoveIt 生态中，OMPL 接口可对接该类日志格式，moveit_ros_benchmarks 提供批量运行的基础设施。这些工具的具体可用性与调用方式随发行版差异，接入前以对应版本的文档与样例为准；本章的自动测量框架可直接用于日常评测。

实现思路与设计

评测流程五步：

  1. 定义问题集：8 到 12 个问题，按场景类别分组（自由空间、单障碍、窄通道、限制位形），记录场景版本号。
  2. 冻结配置：把待比较的配置写成参数文件，连同规划器版本、适配器链一起快照。
  3. 自动运行：脚本按"配置 × 问题 × 重复"三层循环执行，每条记录包含成功标志、时间、错误码与轨迹指标。
  4. 汇总统计：按配置聚合成功率与时间分位数，按问题组拆分查看类别差异。
  5. 形成结论：以"在何种场景下、以何种预算、达到何种水平"的框架陈述，避免全局性断言。

关键代码与解读

片段 1：重复实验框架（Python）

import time, statistics

def benchmark(arm, problems, planners, trials=30, budget=1.0):
    """按 规划器 x 问题 x 重复 三层循环测量，返回聚合结果。"""
    results = {}
    for planner in planners:
        arm.set_planner_id(planner)
        arm.set_planning_time(budget)           # 预算固定：对比的公平性前提
        arm.set_num_planning_attempts(5)
        ok_count, times = 0, []
        for p in problems:
            arm.set_joint_value_target(p["goal"])
            for _ in range(trials):
                t0 = time.perf_counter()
                ok, plan, _, err = arm.plan()
                dt = time.perf_counter() - t0
                if ok:
                    ok_count += 1
                    times.append(dt)            # 失败样本不进时间统计，但计入分母
                else:
                    results.setdefault((planner, p["name"], "errors"), []).append(err.val)
        total = trials * len(problems)
        results[planner] = {
            "success_rate": ok_count / total,
            "median": statistics.median(times) if times else None,
            "p90": sorted(times)[int(0.9 * len(times)) - 1] if times else None,
        }
    return results

解读：三层循环给出统计口径的关键决定。失败样本计入分母但排除在时间统计之外，这是刻画"成功率与成功条件下的耗时"两个面的常规做法；要评估"所有请求的响应时间"，则应把超时样本按预算截断后一起统计。分位数用排序数组索引计算，避免了均值被尾部拖偏。错误码被单独收集，供第 049 章做失败类型归因。

片段 2：Wilson 置信区间与结果格式化

import math

def wilson_interval(successes, total, z=1.96):
    """二项成功率的 Wilson 区间：小样本下比正态近似更稳。"""
    if total == 0:
        return (0.0, 1.0)
    p = successes / total
    denom = 1 + z * z / total
    center = (p + z * z / (2 * total)) / denom
    half = z * math.sqrt(p * (1 - p) / total + z * z / (4 * total * total)) / denom
    return (max(0.0, center - half), min(1.0, center + half))

def report(results, total_per_planner=300):
    print(f"{'planner':<12}{'成功率':<10}{'95%区间':<22}{'中位数':<10}{'P90':<10}")
    for name, r in results.items():
        successes = round(r["success_rate"] * total_per_planner)  # 由聚合结果反推成功次数
        lo, hi = wilson_interval(successes, total_per_planner)
        med = f"{r['median']:.3f}" if r["median"] else "n/a"
        p90 = f"{r['p90']:.3f}" if r["p90"] else "n/a"
        print(f"{name:<12}{r['success_rate']:<10.2f}[{lo:.2f}, {hi:.2f}]      {med:<10}{p90:<10}")

解读：区间函数把"成功率"从点估计升级为范围估计，是结论可靠性的最低保障。报告格式把成功率、区间、中位数与 P90 并排，迫使读者看到"典型值"与"尾部值"的分离。示例中 300 次样本的占位计算需替换为真实分母；工程实现里应同时输出每类问题的拆分，避免汇总数字掩盖类别差异。

常见坑

  • 用均值描述规划时间：重尾分布下均值漂移大，读者误判典型体验。修复：报告中位数与 P90/P95，并注明截尾时间。
  • 对比实验混入配置差异：两个规划器使用了不同的尝试次数或适配器链，测出的差异无法归因。修复：冻结配置快照，逐项对照后开跑。
  • 问题集过小或同质：全部问题都是自由空间，结论在近障场景失效。修复：按场景类别配额取样，结果按类别拆分报告。
  • 忽略失败样本的时间：失败请求实际消耗了预算时间，服务视角的延迟包含这部分。修复：对服务水平评估使用"含失败的全样本时间统计"口径。
  • 种子与缓存管理粗放：同一随机序列被重复使用，或热缓存让首轮异常快。修复：确认每次规划均重新采样；每条配置先跑预热轮再进入统计。

练习与思考

  1. 某配置 30 次重复中成功 27 次。计算点估计与 Wilson 区间的整数近似，判断"成功率不低于 80%"能否被支持。★
    提示
    点估计 0.90；区间约 [0.74, 0.96] 量级（按公式代入），下限低于 0.80，因此该断言在 95% 置信水平下还得不到完全支持，需要更大样本。
  2. 两组对比显示：A 规划器中位数 0.2 s、P90 1.8 s；B 规划器中位数 0.6 s、P90 0.9 s。为"交互示教"与"批量离线处理"两种场景各选一个并说明依据。★
    提示
    交互场景选 B（尾部可控，最坏体验更好）；批量离线处理选 A（中位数低，总吞吐更优）。结论随优化目标变化，不能由单一指标界定。
  3. 设计一套包含 6 个问题的评测集，覆盖自由空间、近障、窄通道三类，为每个问题写出场景要素与验收指标。★★
    提示
    每类两个问题并设置难度梯度（如通道宽度 0.15 m 与 0.08 m）；记录场景带版本号。验收指标按类别差异化：自由空间看中位数，窄通道看成功率与成功率区间。
  4. 阅读一组实验数据后判断：某规划器在 10 个问题上成功率为 100%，但 9 个问题均少于 2 次尝试即成功，另 1 个问题每次都在预算耗尽前 0.01 s 才成功。分析这个分布说明了什么，并给出加固建议。★★★
    提示
    分布的"具有余量的成功"与"贴着预算线的成功"是两类；后者说明该问题接近能力边界，任何负载波动都会转化为失败。加固方向：为该问题单独提高预算或更换规划器，并对该问题做失败注入测试。

小结

  • 基准测试的四要素是问题集、配置快照、重复实验与统计指标；公平性来自控制变量。
  • 规划时间用中位数与 P90/P95 报告；成功率附置信区间；失败样本的处理口径必须显式声明。
  • 轨迹质量指标包括路径长度、平滑度、最小间隙与执行时长，比较前统一分辨率与缩放因子。
  • OMPL 统计脚本与 MoveIt 批量评测工具提供现成基础设施，接入时以发行版文档为准。
  • 结论按"场景、预算、水平"三要素陈述，避免脱离条件的全局断言。
