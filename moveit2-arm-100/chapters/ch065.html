第 065 章：Grasp 消息与 PlaceLocation 消息

逐字段剖析 moveit_msgs/Grasp 与 moveit_msgs/PlaceLocation：每个字段在执行链中作用于哪个环节，字段之间的单位、坐标系与长度一致性如何校验。

  • 主题：消息结构 / 抓取与放置字段语义
  • 关键机制：GripperTranslation 三元语义 / 手爪姿态轨迹表达 / 一致性校验
  • 预计学时：45 分钟
  • 前置章节：第 064 章

学习目标

  • 能逐字段说出 Grasp 消息七个字段的语义与执行环节，理解每个字段缺失时执行链在哪一步失败。
  • 掌握 GripperTranslation 的 direction、desired_distance、min_distance 三元语义，能说明多档退距的用法。
  • 理解手爪姿态轨迹（JointTrajectory）在抓取消息中的表达约定，包括单点约定、关节名与时间戳处理。
  • 掌握 PlaceLocation 与 Grasp 的字段对照关系，能解释 PlaceLocation 缺少夹紧轨迹字段的原因。
  • 会编写消息一致性校验：frame 注册性、单位与量纲、数组长度、关节名匹配、力值范围。

背景与动机

第 063、064 章把作业封装为 action，目标中的核心载荷是抓取与放置的几何与手爪描述，它们由两个消息类型承载：moveit_msgs/Grasp 与 moveit_msgs/PlaceLocation。这两个消息是抓取任务链中数据流的"最终格式"，任何字段的语义误解都会在运动执行阶段以碰撞、空抓或放偏的形式暴露，且难以从日志回溯到消息层。

消息字段的设计体现了两个理念：其一，几何与手爪动作分离，几何用位姿与方向描述，手爪动作用关节轨迹描述，二者可独立替换；其二，抓取与放置共享同一套子结构（GripperTranslation、姿态轨迹），使执行链的两侧实现可以复用同一段解析代码。

本章承上启下：向上收敛第 061 至 064 章出现过的字段概念，向下为第 066 章的夹爪接口提供"姿态轨迹如何落到控制器"的接口背景。

核心原理

1. Grasp 消息全字段语义

字段类型语义作用于执行链的环节
grasp_posePoseStamped抓取瞬间手爪参考位姿预抓取与接近段的几何基准
pre_grasp_postureJointTrajectory接近过程中手爪保持的张开姿态接近段前设置手爪状态
grasp_postureJointTrajectory抓取完成时手爪的闭合姿态夹紧动作的目标状态
pre_grasp_approachGripperTranslation接近方向与退距预抓取位姿派生与接近段生成
post_grasp_retreatGripperTranslation抓取后回退方向与距离回退段生成
max_contact_forcefloat32允许的最大接触力（牛顿）夹紧力上限与碰撞放行策略
allowed_touch_objectsstring[]允许接触的物体名列表碰撞矩阵的临时放行集合

消息中不含手爪参考点的连杆名字段，参考点是手爪基座还是工具中心点由执行方约定。这一省略是有意为之：同一接口兼容不同手爪几何，代价是参考点约定成为系统级配置，必须在生成端与执行端之间显式对齐，否则位姿整体偏移一个指尖长度。

2. GripperTranslation 的三元语义

GripperTranslation 由三部分构成：方向（带坐标系的向量）、期望距离与最小距离。执行方用方向与距离生成中间位姿，例如预抓取位姿为抓取位姿沿接近方向反向平移。

Ppre = Pgrasp − d · û，d ∈ {desired_distance, min_distance} û 为规范化后的方向向量，起点中的 d 可取期望值，若该位姿不可达或碰撞则回退到最小距离再试

两个距离值的存在是为了容纳"最长试图达到好位姿，退而求其次保证可执行"的层次策略：期望距离提供更宽的接近行程与更好的进入方向一致性，最小距离保证中间位姿不贴近物体。方向的坐标系字段（direction.header.frame_id）是必需语义：同向量在不同坐标系下表达完全不同的物理方向。

3. 手爪姿态轨迹的表达约定

手爪开合在消息中以关节轨迹表达，常见约定如下：

  • 单点约定：轨迹只含一个点，时间戳为零，表示"目标状态"；执行方按速度限制自行插值。
  • 多点约定：可表达分段开合，例如先快速闭合到接近物体的位置，再以低速完成最后一段，实现软接触。
  • 关节名必须与控制器一致：轨迹中的关节名决定执行方将位置值转发到哪个控制器接口，名称不匹配时动作静默丢失。

轨迹类型的选择让手爪动作与运动规划解耦：手爪不参与机械臂的碰撞规划段（在放行列表内），而由独立控制器执行，两条链路在时间上串行衔接。

4. PlaceLocation 与 Grasp 的字段对照

Grasp 字段PlaceLocation 对应说明
grasp_poseplace_pose同为 PoseStamped，含义换成放置到位时的手爪位姿
pre_grasp_posturepre_place_posture放置前手爪保持的姿态（通常为闭合）
grasp_posture无对应字段释放由执行方张开手爪完成，无需提前描述闭合轨迹
pre_grasp_approachapproach同为 GripperTranslation，方向改为下降方向
post_grasp_retreatretreat撤离参数
无对应字段id候选标识，供反馈报告实际使用的放置位置

对照表解释了一个易混点：PlaceLocation 不携带夹紧轨迹，因为释放动作的方向与力由执行策略决定，消息层只描述"放哪里、怎么接近、怎么撤离"。

实现思路与设计

消息构造层建议实现为一个工厂加工序：

  1. 几何输入：抓取候选位姿（来自第 061 章）、手爪参考点约定、接近方向与退距参数。
  2. 手爪状态输入：关节名列表（来自控制器配置）、张开与闭合位置（来自 URDF 关节限位或标定值）。
  3. 安全输入：最大接触力、允许接触物体列表（来自场景语义与碰撞矩阵设计）。
  4. 构造：逐字段填充，方向向量规范化，时间戳留零。
  5. 校验：运行一致性检查函数，任何错误在发送前拦截并报告字段名。

字段取值规范表

字段取值规范依据
方向向量单位向量，显式给 frame避免退距按向量模长被缩放
desired_distance / min_distance0.05 / 0.01 m期望行程与最小安全距离分层
手爪轨迹点数1–3单点表达目标状态，多点表达分段开合
轨迹时间戳0表示相对动作起点，由执行方插值
max_contact_force5–50 N，0 表示不限落在常见夹爪出力区间
allowed_touch_objects对象名与场景注册名一致名称不匹配则放行失效
设计决策：为什么把"允许接触"放消息里？

不同抓取方式需要放行的接触不同：桌面抓取要放行指尖与桌面在接近段的轻微接触，装配抓取要放行被抓件与装配位形。把放行列表作为任务参数随目标传递，执行方无需预知任务细节，用临时碰撞放行替代全局碰撞矩阵修改，任务结束后自动恢复。

关键代码与解读

片段 1：构造一条完整 Grasp

from moveit_msgs.msg import Grasp
from trajectory_msgs.msg import JointTrajectory, JointTrajectoryPoint

def make_posture(names, positions):
    """手爪姿态轨迹（单点约定）：关节名来自控制器配置，时间戳保持 0。"""
    traj = JointTrajectory()
    traj.joint_names = list(names)   # 名称不匹配时动作会被静默丢弃
    pt = JointTrajectoryPoint()
    pt.positions = list(positions)   # 位置值用弧度或米，与关节类型一致
    traj.points = [pt]
    return traj

def make_grasp(pose, names, open_pos, close_pos, axis, d_app=0.05,
               d_ret=0.10, max_force=20.0, touch=("table",)):
    """填充一条完整 Grasp：几何、手爪状态、接近回退与碰撞放行。"""
    g = Grasp()
    g.grasp_pose = pose                                  # 抓取瞬间手爪位姿
    g.pre_grasp_posture = make_posture(names, open_pos)  # 接近时张开
    g.grasp_posture = make_posture(names, close_pos)     # 夹紧目标位置
    ax = axis
    g.pre_grasp_approach.direction.header.frame_id = pose.header.frame_id
    g.pre_grasp_approach.direction.vector.x = ax[0]      # 方向须为单位向量
    g.pre_grasp_approach.direction.vector.y = ax[1]
    g.pre_grasp_approach.direction.vector.z = ax[2]
    g.pre_grasp_approach.desired_distance = d_app
    g.pre_grasp_approach.min_distance = 0.01             # 最小退距：不贴住物体
    g.post_grasp_retreat = g.pre_grasp_approach          # 复制方向，距离单独覆盖
    g.post_grasp_retreat.desired_distance = d_ret
    g.max_contact_force = max_force                      # 0 表示不限，20 N 为常用上限
    g.allowed_touch_objects = list(touch)                # 碰撞临时放行名单
    return g

解读：（1）姿态轨迹的构造被抽成独立函数，因为抓取与放置两侧都要用同一约定，集中在一处便于与控制器关节名对齐。（2）接近方向与回退方向通过复制整体结构再覆盖距离得到，避免方向字段被两处赋值产生不一致。（3）max_contact_force 与 allowed_touch_objects 属于安全参数，构造时给默认值可防止漏填得到零值（零在许多实现中表示不限，会放大风险）。（4）方向向量的 frame 直接取位姿 frame，保证几何一致；若任务需要表达在工具坐标系，则在此处显式切换。

片段 2：消息一致性校验

GRIPPER_JOINTS = ("gripper_left_joint", "gripper_right_joint")

def verify_grasp(g, known_frames):
    """发送前的字段校验：把语义错误拦截在接口层。"""
    errs = []
    if g.grasp_pose.header.frame_id not in known_frames:
        errs.append("grasp_pose 的 frame 未注册")
    for traj in (g.pre_grasp_posture, g.grasp_posture):
        if len(traj.points) == 0:
            errs.append("手爪姿态轨迹为空")            # 空轨迹导致手爪状态未知
        if tuple(traj.joint_names) != GRIPPER_JOINTS:
            errs.append(f"关节名不匹配：{list(traj.joint_names)}")
    if not 0.0 <= g.max_contact_force <= 50.0:
        errs.append("max_contact_force 超出 0–50 N 区间")
    a = g.pre_grasp_approach
    if a.desired_distance < a.min_distance:
        errs.append("期望退距小于最小退距：参数语义颠倒")
    return errs

解读：（1）校验按字段组织，每条规则对应一类曾在现场出现过的故障：frame 未注册、轨迹为空、关节名漂移、力值超限、距离语义颠倒。（2）返回错误列表，让调用方可以一次看到全部问题并以字段名定位；布尔值只能表达"有问题"，无法给出定位信息。（3）常见做法是把该校验挂在生成节点出口与服务端入口双处，任一侧拦截都可避免问题进入执行链。

片段 3：构造一条 PlaceLocation

from moveit_msgs.msg import PlaceLocation

def make_location(loc_id, pose, posture, d_app=0.06, d_ret=0.08):
    """构造 PlaceLocation：与 Grasp 共享子结构，但不含夹紧轨迹字段。"""
    loc = PlaceLocation()
    loc.id = loc_id                          # 反馈据此报告实际使用的位置
    loc.place_pose = pose                    # 放置到位时的手爪位姿
    loc.pre_place_posture = posture          # 放置前保持的姿态（通常为闭合）
    loc.approach.direction.header.frame_id = pose.header.frame_id
    loc.approach.direction.vector.z = -1.0   # 竖直向下接近：单位向量方向
    loc.approach.desired_distance = d_app
    loc.approach.min_distance = 0.01
    loc.retreat.direction.header.frame_id = pose.header.frame_id
    loc.retreat.direction.vector.z = 1.0     # 撤离向上：与接近方向相反
    loc.retreat.desired_distance = d_ret
    loc.retreat.min_distance = 0.01
    return loc

解读：（1）放置位置的方向用支撑面法向近似竖直，若支撑面倾斜需按标定法向给出，否则下降段与面不垂直，接触点偏移。（2）retreat 方向与 approach 相反且各自携带 frame，二者一致时应由同一标定来源生成，防止在不同坐标系下写反。（3）id 是 PlaceLocation 独有的字段，把它当作格位编号使用，可让上层在多格位任务中统计各位置的失败率。

常见坑

  • 方向向量未规范化：传入模长 3 的向量，退距被放大三倍，预抓取位姿飞出工作空间。修复：构造时统一规范化，并在校验中检查模长接近 1。
  • 手爪关节名与控制器不一致：姿态轨迹被静默忽略，手爪保持初始状态，接近时与物体碰撞。修复：关节名从控制器配置读取，校验中做元组比对。
  • 张开与闭合轨迹写反：pre_grasp_posture 填了闭合值，接近阶段手爪已合拢。修复：校验开合值域（闭合值反映较小的指间距），并对首帧姿态做实际位置确认。
  • max_contact_force 默认零值的歧义：零表示"不限制"还是"零力"因实现而异，误用导致压靠过载或夹紧力不足。修复：显式填写非零上限，并在接口文档固定零值语义。
  • allowed_touch_objects 名称与场景不一致：物体在场景中注册名为 table_1，消息填 table，放行失效并在接近末端报碰撞。修复：放行名单从场景查询结果生成，不手工拼写。

练习与思考

  1. 列出 Grasp 的七个主要字段，为每个字段指出缺失或错误时执行链首先在哪一步失败。★
    提示
    位姿 frame 错误在预抓取派生即失败；姿态轨迹问题在夹紧动作时暴露；方向问题在接近段碰撞或偏移；力值与放行名单问题在接触瞬间暴露。
  2. 把接近方向向量从 (0, 0, −1) 改为模长 2 的 (0, 0, −2)，预测预抓取位姿与后续阶段的变化，给出两种修复方式。★★
    提示
    预抓取位姿沿方向多退一倍距离，可能超出可达范围或进入障碍；修复方式为构造时归一化，或在校验中拒绝非单位向量并要求重新生成。
  3. 为软包装物体设计手爪姿态轨迹（多点约定）：描述快速闭合与低速夹紧两段的位置与预期效果，说明为何第二段速度取第一段的 10%–20%。★★
    提示
    第一段从张开到留 3–5 mm 间隙，第二段低速闭合到接触位置，低速段让接触力更可控、减少对软包装的冲击与位置扰动；配合 max_contact_force 上限共同约束。
  4. 设计一条消息校验流水线：给出至少六条规则、每条规则的字段与失败后果，并讨论校验应放在生成端、服务端还是两处都放。★★★
    提示
    参考片段 2 的五条规则并补充单位检查与距离非负检查；两端都放的成本只是一次函数调用，收益是接口契约在两个方向上都被强制。

小结

  • Grasp 由七类字段构成：抓取位姿、抓取前/后手爪姿态轨迹、接近与回退参数、接触力上限、允许接触物体名单。
  • GripperTranslation 的方向必须单位化并显式携带坐标系，期望距离与最小距离构成分层接近策略。
  • 手爪姿态轨迹采用单点或多点约定，关节名必须与控制器一致，时间戳零表示相对动作起点。
  • PlaceLocation 与 Grasp 共享子结构，缺少夹紧轨迹字段的原因在于释放动作由执行策略决定。
  • 消息一致性校验应挂在生成端与服务端两侧，字段级错误在发送前拦截，下一章讨论姿态轨迹落地执行的夹爪控制接口。
