第三篇 · 规划算法与求解器

第 052 章：使用 TRAC-IK 求解器

TRAC-IK 让两种数值求解器并行赛跑：类牛顿-拉夫森的快速迭代与基于序列二次规划的约束优化，谁先收敛用谁。本章讲清并行竞争机制、求解类型（solve type）语义与从 KDL 迁移的完整流程。

  • 主题：运动学插件 / TRAC-IK 并行求解
  • 关键机制：双求解器竞争、序列二次规划、解类型策略
  • 预计学时：50 分钟
  • 前置章节：第 051 章

学习目标

  • 理解 TRAC-IK 的并行竞争结构：两类求解器各自的特点与互补关系。
  • 掌握序列二次规划（SQP）如何处理关节限位这类非线性约束，理解它为何在限位密集区域更稳。
  • 能解释 solve type 四种取值（速度、距离、两档可操作度衡量）的取舍与适用场景。
  • 会完成从 KDL 到 TRAC-IK 的迁移：配置替换、参数设置、样本重测与回归对照。
  • 能评估并行求解的 CPU 代价，在实时场景中做出线程与超时的平衡决策。

背景与动机

KDL 在多数位姿上表现称职，但两类位姿会持续拉低成功率：贴近关节限位的工艺位姿与接近奇异的中间位姿。单一路径的迭代求解在这些区域要么慢、要么卡。TRAC-IK 的应对方式是"不赌单一方法"：两条算法路线的解空间并不完全重叠，同时开跑可以把成功率推向两者的上界。

迁移成本很低：改一行插件配置、加一个求解类型参数。理解它内部的竞争机制，才能正确解释"迁移后快了"或"迁移后没变"的结果，并在 CPU 资源紧张的平台上做出取舍。

核心原理

1. 双求解器竞争结构

TRAC-IK 在单次请求内启动两个独立求解过程：

  • 改进型牛顿-拉夫森求解器：与 KDL 同源的迭代格式，包含步长调整与限位处理改进，在良态位姿上收敛极快。
  • 序列二次规划求解器：把逆运动学写成带约束的非线性优化问题，用逐次二次近似求解，关节限位作为显式约束进入每步子问题。

两个求解器并行推进，先收敛的一个立即返回，另一线程被终止。并行带来的性能期望可概括为：总耗时趋近较快者，失败率趋近较低者（成功率取两路结果的并集）。在良态位姿上 NR 通常先到达；在限位与奇异附近，SQP 的约束处理能力接管比赛。这一互补性是 TRAC-IK 相对 KDL 的核心增量。

2. SQP 为什么在限位附近更稳

牛顿-拉夫森对限位的处理是"先走一步、再夹回"，夹取让有效步长失真，迭代可能停住。SQP 把问题改写为带约束优化：

minΔq ‖e(q + Δq)‖²，s.t. qmin ≤ q + Δq ≤ qmax 每步用二次近似与线性化约束构造子问题，解出的步长天然满足限位

在解空间靠近边界的区域，约束优化沿着"可行域内最速下降"的方向前进，避免了夹取引起的停顿。代价是解子问题的矩阵运算更重，单步耗时高于 NR；两队竞争恰好掩蔽了这一点：SQP 在 NR 失效的区域赢得时间差，NR 在 SQP 不必要的区域提前冲线。

3. 解类型：先解到 vs 解得好

并行求解回答了"能不能解"，solve type 参数回答"返回哪个解"：

取值策略适用场景
Speed（默认）首个收敛解立即返回逐点笛卡尔路径、节拍优先
Distance跑满超时后返回距种子最近的解连续求解、要求关节连续性
Manip1跑满超时后返回可操作度（奇异值之积）最大的解追求远离奇异、操作灵活
Manip2跑满超时后返回条件数（最大与最小奇异值之比）最小的解接近奇异风险高的任务路径

取值名称与语义以插件文档为准。策略选择的经验法则：在线高频调用用 Speed；发现关节跳变时换 Distance；路径贴奇异走时试 Manip1 或 Manip2；离线批处理可用 Manip 档换质量，代价是每点耗时上升到超时值。

4. 与 KDL 的对照与边界

维度KDLTRAC-IK
算法单路牛顿迭代双路并行（迭代 + 约束优化）
限位附近易贴边停顿约束内推进，成功率更高
CPU 开销单线程双线程并行，占用更高
时间行为失败位姿耗满超时同左；成功位姿回到较快者
确定性随机重启随机重启（并行放大随机性）

边界条件：TRAC-IK 面向 6 自由度链设计，冗余链的支持范围与其版本相关，接入前确认；在单核或 CPU 长期饱和的平台上，并行的收益会被调度延迟抵消。评估结论以本机实测样本为准，不以通用印象为准。

实现思路与设计

迁移流程：

  1. 建立基线：先在 KDL 上用位姿样本测成功率与耗时（第 051 章方法），结果留档。
  2. 替换插件：修改 kinematics.yaml 的插件类名，设置 solve type 与超时。
  3. 重测样本：跑同一批位姿，输出成功率、时间中位数与 P90 的对照。
  4. 检查副作用：观察关节跳变率（Distance 可改善）、CPU 占用与规划节点负载。
  5. 回归固化：确定参数组合，写入配置并归档对照数据。

参数表（字段以插件文档为准）

参数典型值作用取值依据
kinematics_solverTRAC-IK 插件类名启用并行求解器KDL 成功率不达标时切换
kinematics_solver_timeout0.02 到 0.05 s整体超时预算两路求解共享该预算
solve_typeSpeed（默认）解的选择策略按响应时间与连续性需求选择

与第 051 章的差异：超时参数语义从"重启次数预算"扩展为"两路求解共享的竞争窗口"；成功的代价从"迭代快"变为"较快的一路足够快"。在笛卡尔路径逐点调用中，TRAC-IK 的收益最直观：单点失败率下降直接转化为整条路径的通过率。

关键代码与解读

片段 1：TRAC-IK 配置

# kinematics.yaml：从 KDL 迁移只需替换插件行并补充求解类型
arm_group:
  kinematics_solver: trac_ik_kinematics_plugin/TRAC_IKKinematicsPlugin
  kinematics_solver_timeout: 0.05        # 两路求解共享的竞争窗口；从 0.05 s 起步测量
  solve_type: Speed                      # 在线逐点调用：首解即返回
  # 备选：Distance（连续求解保持连续性）、Manip1 或 Manip2（倾向可操作度更好的解）

解读：三个字段对应三个决策。插件类名决定算法路线；超时字段的角色从重启预算扩展为两路求解的共同截止时间，含义变化而调优方法不变（样本曲线找平台段）；solve type 单独控制"解返回策略"，它不影响求解成功本身，只影响返回的是哪个解。配置项名称以所用插件版本的样例为准，部分版本对未知字段静默忽略，迁移后应在日志或实测中确认参数确实生效。

片段 2：KDL 与 TRAC-IK 的对照测量（Python 结构）

import time, statistics

def measure_current_plugin(ik_client, poses, joint_names, label, trials_pose=120):
    """对当前生效插件测量：成功率、时间分位数、关节跳变率。"""
    seed = current_joint_values()
    prev = list(seed)                       # 跳变检测：相邻位姿的解应彼此接近
    ok, times, jumps = 0, [], 0
    for pose in poses[:trials_pose]:
        t0 = time.perf_counter()
        res = ik_client.solve(pose, seed, joint_names, timeout=0.05)
        times.append(time.perf_counter() - t0)
        if res and res.error_code.val == 1:
            ok += 1
            solved = joint_values_of(res)   # 从响应中取关节解
            if joint_distance(solved, prev) > 0.5:   # 阈值 0.5 rad：按臂长与工艺设定
                jumps += 1
            prev = solved
    print(f"[{label}] 成功率 {ok/trials_pose:.2f}，"
          f"中位 {statistics.median(times)*1000:.1f} ms，"
          f"P90 {sorted(times)[int(0.9*len(times))-1]*1000:.1f} ms，"
          f"跳变率 {jumps/max(ok,1):.2f}")

解读：指标设计里新增了跳变率，这是 IK 插件评估中容易缺失的一维。成功率与耗时描述"解得到"，跳变率描述"解得顺"；在连续笛卡尔路径上，后者直接决定执行层是否出现关节抖动。对照流程是：KDL 配置下运行一次留档，替换插件重启后运行第二次，两张输出并排比较。跳变阈值 0.5 rad 是量级起点，按臂的关节行程与工艺速度调整。

解读：迁移的价值在于可回退与可比对。保留基线配置与基线数据，任何"换了插件反而变差"的疑问都能在五分钟内用同一批位姿回答。参数查询用于确认配置真的被节点加载（多实例配置下常见"改了文件但没生效"）。对照脚本读取同一份位姿文件，保证两次测量的问题集完全一致。

常见坑

  • 沿用 KDL 时期的短超时：0.005 s 的窗口下两路求解都来不及完成重启，迁移收益被吞掉。修复：从 0.05 s 起步重测。
  • 忽视 CPU 饱和：双线程求解在算力紧张的平台与感知、控制线程竞争，时间行为变差。修复：用第 048 章的追踪确认负载来源，必要时限制并行或升级算力。
  • solve_type 与场景不匹配：逐点路径用 Manip 档或给 Distance 配长超时，都会跑满超时拖累整体节拍；连续轨迹用 Speed 出现跳变。修复：按响应时间与连续性需求选择取值，并用跳变率指标验证。
  • 在冗余链上未确认支持范围：插件的自由度支持随版本变化，配置后求解行为异常。修复：先小样本验证，支持不足时转用第 053 章的求解器。
  • 把成功率提升当唯一验收：迁移后成功率持平但耗时翻倍，节拍变差。修复：验收指标固定为成功率、时间分位数与跳变率三件套。

练习与思考

  1. 解释"并行求解的耗时趋近较快者、失败率趋近较低者"的成立条件，并举一个不成立的情形。★
    提示
    成立条件：两路求解独立竞争且资源充足。不成立情形：单核 CPU 上两线程分时调度，各自速度减半，"较快者"的优势被调度延迟抵消。
  2. 某路径 80 个笛卡尔采样点，KDL 单点成功率 0.96，TRAC-IK 单点成功率 0.995。估算整条路径的一次通过率差异，并说明其他影响因素。★
    提示
    0.9680 ≈ 3.8%，0.99580 ≈ 67%。差异超过一个数量级；但实际还受路径点间距、重试策略与超时影响，估算用于量级判断。
  3. 为"高频逐点调用 + 要求关节连续"的贴装路径设计参数组合，并写出验证指标。★★
    提示
    solve type 取 Distance，超时 0.02 到 0.05 s；验证指标为单点成功率、时间 P90 与跳变率，另加"整条路径无跳变"的通过率。
  4. 设计实验比较 KDL 与 TRAC-IK 在限位密集区域（关节行程 90% 以上的位姿样本）的成功率差异，写出样本生成方法与预期结论。★★★
    提示
    样本生成：随机关节角偏向限位附近（如在行程两侧 10% 区间采样），经正运动学生成位姿。预期 KDL 成功率显著下降而 TRAC-IK 下降较少，这是 SQP 约束处理优势的直接体现。

小结

  • TRAC-IK 并行运行迭代法与约束优化两路求解，先收敛者返回，成功率取并集、耗时趋近较快者。
  • SQP 把关节限位作为显式约束，在限位密集与奇异邻域比夹取式迭代更稳。
  • solve type 控制解的选择策略：在线用 Speed，连续性用 Distance，奇异风险与质量取向用 Manip1 或 Manip2。
  • 迁移成本低但要完成三件套验收：成功率、时间分位数、跳变率，并与 KDL 基线对照留档。
  • 并行求解增加 CPU 占用，算力紧张的平台需评估调度影响。
