第一篇 · 环境搭建与基础控制

第 018 章：阶段实践：单臂基本运动规划

本篇收官实践：把环境、模型、配置、接口与参数串成一条完整任务链，用可量化的验收指标检验成果，并形成可重复的实验流程。

  • 主题：阶段实践 / 完整规划流程与验收
  • 关键机制：任务编排、指标采集、验收判定
  • 预计学时：75 分钟
  • 前置章节：第 017 章

学习目标

  • 会设计一条包含关节空间转移段与笛卡尔工序段的完整运动任务。
  • 能编写任务脚本：顺序编排、分段失败处理与运行指标采集。
  • 建立可量化的验收指标体系，能独立执行判定并解释每项指标的含义。
  • 能用前十七章的检查工具对新环境做一次全链路体检。
  • 能产出完整的实验结论：配置、数据、判定三要素齐全且可复现。

背景与动机

前十七章以组件为单位展开，每一项都单独验证过。真实任务的难点在组合：多段运动顺序衔接、每段的参数不同、失败处理路径各异、结果需要用统一口径衡量。阶段实践的价值在于把组合过程完整走一遍，并给出一套可复用的验收方法。

验收指标的选择本身也是知识点。没有指标的实践只有"看起来能跑"的结论；指标把"能跑"拆成成功率、耗时分布、轨迹合规、执行结果四类可测项目，任何一项不达标都指向确定的排查入口。这套指标表在第 038、060、078 章会被逐篇扩展，但骨架在本章确定。

核心原理

本节定义实践任务的场景与分段、验收指标体系、以及任务编排的失败处理策略。

1. 任务场景与分段

场景设定为桌面工作站：机械臂基座位于台面一侧，作业区在正前方。任务包含四段运动，覆盖两种空间类型：

段运动空间类型验收关注点
段 1home 到 ready（大范围转移）关节空间，命名位姿成功率、耗时分布
段 2ready 处沿竖直方向下降 0.10 m笛卡尔空间，直线分数、末端直线偏差
段 3从下降点返回 ready笛卡尔空间，直线分数、与段 2 的对称性
段 4ready 回到 home关节空间，命名位姿成功率、回到起点的偏差

分段设计覆盖了两类空间的典型用法与一次往返校验：段 2 与段 3 构成可逆工序段，段 1 与段 4 构成可逆转移段。往返设计让"任务结束时状态是否回到起点"成为一项免费的一致性检查，任何累积偏差都会在往返后显形。

2. 验收指标体系

指标目标值测量方法不达标时的排查入口
关节段规划成功率重复 30 次不低于 0.95段 1 与段 4 分别统计目标可达性、规划参数（第 017 章）
笛卡尔分数不低于 0.95段 2 与段 3 分别读取步长、跳变阈值、姿态可达性（第 011 章）
规划耗时 P90不超过 1.5 s30 次采样的 90 分位尝试次数、规划器标识（第 017 章）
轨迹合规时间戳单调、限位内、无绕行执行前速检（第 010、015 章）重定时与归一化管线
执行结果假控制器下成功率 1.00执行返回码统计控制器映射与动作端点（第 014 章）
往返一致性末端回到 home 的偏差不超过 0.01 rad任务首末关节值比对起点管理、累计误差（第 009 章）

指标的量级依据如下：成功率阈值 0.95 对应 30 次里允许最多 1 次失败，与采样规划的随机性匹配；耗时 P90 的 1.5 s 是按单次规划预算 1.0 s 加执行准备时间推导的保守线；往返一致性取关节角 0.01 rad，与第 012 章的容差量级一致。所有阈值都给出推导依据，评审时可以讨论依据本身，数字的合理性由依据支撑。

测量口径需要事先约定三个细节：计时从调用规划开始到结果返回为止，不含执行等待；分数取每次工序段返回值的原始比例，不做舍入；往返偏差在任务结束时读取关节值，与任务开始前记录的同名关节值比较。三个细节固定之后，不同批次、不同人员执行的实验数据才具备可比性。数据可比性来自口径一致，先约定口径、后采集数据，是这套流程的顺序纪律。

3. 编排与失败处理

编排结构是顺序执行加分层失败策略。分段的重试价值不同：搜索类失败（超时）重试有意义，约束类失败（分数不足、目标无效）重试前需要修正条件。策略设计如下：

  • 搜索类失败：最多重试 3 次，逐次提高时间预算（1.0 s、2.0 s、3.0 s），仍失败则终止任务并报告段号。
  • 笛卡尔分数不足：不重试，终止并报告断裂比例；分数波动属于场景与目标层的信号。
  • 执行失败：终止并报告错误码；执行类问题不通过重试掩盖。

重试次数与策略本身也是实验结果的一部分：如果重试频繁触发，说明基线配置不稳，应先回到参数层处理，把重试当作常态会掩盖问题。脚本统计重试发生率，作为一项隐含指标。

实现思路与设计

实践按"准备、单次演示、统计验收、归档"四步执行。

  1. 准备：启动系统，跑第 005 章的接口自检，确认基线环境健康。
  2. 单次演示：完整执行四段任务，人工核对轨迹显示与执行结果。
  3. 统计验收：循环 30 次，采集六项指标，对照阈值输出判定。
  4. 归档：记录配置值、指标数据与判定结论，形成可比较的实验批次。

实验条件需要随数据一并记录：软件版本与配置包版本、场景物体清单、参数组合三项。同一批验收数据必须在同一组条件下采集，条件变更单独成批，不和历史数据混算。让条件与数据一一对应，是从数据回到结论的唯一可靠路径。准备步骤里的接口自检属于条件核对的组成部分，跳过它会让后续失败混入环境噪声，归因成本成倍上升。

任务参数表（各段统一口径）

参数取值作用

设计决策：为什么统计验收选择 30 次独立运行、放弃单次长时间连续运行？

验收关注的是分布特征：成功率与 P90 都需要多个独立样本。30 次按单次任务约 3 s 估算，总耗时约 90 s 量级，在可接受的实验成本内给出初步稳定的统计；连续运行则混入热漂移与状态累积等其它变量，反而降低结论的可归因性。独立样本测性能，连续运行测稳定性，两类实验的目的不同，本章先完成前者。

关键代码与解读

本节给出三段片段：任务编排主流程、验收判定汇总、以及 30 次统计的执行器。

片段 1：任务编排主流程

import time
import rclpy.logging
from moveit.planning import PlanRequestParameters

log = rclpy.logging.get_logger("stage_practice")

class StagePractice:
    """四段任务编排：指标就地采集，失败按段报告。"""
    def __init__(self, arm, group):
        self.arm = arm
        self.group = group
        self.metrics = []                    # 每段一条记录（段名、耗时、结果）

    def run_segment(self, name, plan_fn, execute=True):
        """执行一段：plan_fn 设置本段目标并按给定参数发起规划。"""
        for attempt, budget in enumerate((1.0, 2.0, 3.0), start=1):
            # 请求参数对象按管线命名空间装载默认值，时间预算逐次提高（第 017 章）
            params = PlanRequestParameters(self.arm, "ompl")
            params.planning_time = budget
            t0 = time.perf_counter()
            plan = plan_fn(params)
            cost = time.perf_counter() - t0
            if plan:
                if execute:
                    self.arm.execute(plan.trajectory, controllers=[])
                self.metrics.append(
                    {"段": name, "耗时": cost, "重试": attempt - 1, "结果": "完成"})
                return True
        # 三次预算升级后仍失败：终止并报告段名，避免带着未知状态继续
        self.metrics.append({"段": name, "耗时": 0.0, "重试": 3, "结果": "失败"})
        log.error(f"段 {name} 失败：终止任务")
        return False

    def run_all(self):
        # 段 1 与段 4：关节空间命名位姿；段 2 与段 3 为工序段的调用在外部提供
        # plan_fn 内部以 group.plan(single_plan_parameters=params) 发起规划
        ok = self.run_segment("转移_home_ready", self.plan_ready)
        ok = ok and self.run_segment("下降_工序", self.plan_descend)
        ok = ok and self.run_segment("提升_工序", self.plan_lift)
        ok = ok and self.run_segment("转移_ready_home", self.plan_home)
        return ok

解读：编排结构体现三项设计。（1）指标采集内嵌在执行路径内，段名、耗时、重试次数与结果四要素随执行生成，避免事后补记造成口径不一。（2）预算升级策略把第 017 章的方法论落到代码：重试路径逐级提高时间预算，与简单重复有本质区别，覆盖"搜索需要更深探索"的失败模式。（3）失败即终止并报告段号，任务状态机保持在已知状态；带着未知状态继续后续段会让错误现场被覆盖。

片段 2：验收判定汇总

def acceptance_report(metrics, cartesian_scores, task_runs):
    """把原始指标汇总为验收判定：逐项对照阈值并给出结论。"""
    checks = []
    # 关节段成功率：失败次数来自编排记录
    joint_runs = [m for m in metrics if "转移" in m["段"]]
    fails = sum(1 for m in joint_runs if m["结果"] == "失败")
    rate = 1.0 - fails / max(len(joint_runs), 1)
    checks.append(("关节段成功率", rate, ">= 0.95", rate >= 0.95))

    # 笛卡尔分数：取各工序段的最小值，最差段决定验收结论
    worst = min(cartesian_scores) if cartesian_scores else 0.0
    checks.append(("笛卡尔最低分数", worst, ">= 0.95", worst >= 0.95))

    # 往返一致性：任务首末关节差的最大绝对值
    drift = task_runs[-1]["往返偏差"] if task_runs else 1.0
    checks.append(("往返一致性", drift, "<= 0.01 rad", drift <= 0.01))

    for name, value, target, passed in checks:
        print(f"{name}: {value:.3f}（要求 {target}）{'通过' if passed else '不通过'}")
    return all(c[3] for c in checks)

解读：判定函数把本章的"验收指标体系"表变成可执行规则。（1）笛卡尔分数取最小值：工序段的验收由最差段决定，平均值会掩盖单段断裂。（2）往返偏差取任务首末的关节差，测量点固定，跨批次可比。（3）输出保留数值、阈值与结论三列，判定结果可以被复查；把判定脚本与数据分离，重复评审不需要重跑实验。

片段 3：30 次统计执行器

def run_trials(practice, trials=30):
    """统计验收执行器：独立样本、逐次复位、汇总分布指标。"""
    results = []
    for i in range(trials):
        # 每次从 home 开始：复位失败则终止统计，说明起点管理有问题
        if not practice.reset_to_home():
            print(f"第 {i+1} 次复位失败，中止统计")
            break
        ok = practice.run_all()
        results.append({"序号": i + 1, "整体": ok})
    ok_count = sum(1 for r in results if r["整体"])
    print(f"完成 {len(results)} 次，整体成功 {ok_count} 次，"
          f"整体成功率 {ok_count / max(len(results), 1):.2f}")
    # 重试率也是信号：偏高说明基线配置不稳，先回参数层
    retry_events = [m["重试"] for m in practice.metrics if m["重试"] > 0]
    print(f"发生重试的段数：{len(retry_events)}")
    return results

解读：统计执行器的核心是"独立样本"的实现方式。（1）每次运行前复位到 home，把起点条件对齐；复位本身用同一套规划执行流程，顺便成为一项附加检查。（2）整体成功率按任务级统计（四段全过才算一次成功），与段级成功率互补：段级指标定位问题，任务级指标回答可用性。（3）重试率的输出把"隐性成本"显性化：成功率好看但重试频繁的配置，在节拍敏感的产线上属于不合格。

常见坑

  • 连续运行不复位：样本之间状态漂移，统计值混入起点误差。修复：每次运行前显式复位，并用复位结果作为附加健康检查。
  • 笛卡尔分数只记一次：波动被单次数值掩盖，验收结论不稳。修复：工序段每轮都记录分数，汇总取最小值。
  • 把重试当常态：成功率达标但重试率居高，掩盖了基线配置的不稳定。修复：重试率超过 10% 即回到第 017 章重新调参。
  • 假控制器通过即宣布可用：真实控制器、负载与动力学尚未验证。修复：验收范围明确标注"仿真链路"，真机验证按第 014 章的直发通道顺序推进。
  • 阈值无依据：验收数值随手填写，复查时无法讨论。修复：每个阈值给出推导依据，写入实验记录。

练习与思考

  1. 完整执行本章任务并采集六项指标，输出验收报告；对任何不达标项给出排查方向的第一步。★
    提示
    排查方向参考指标表的最后一列；先确认测量方法本身无误，再进入对应章节的工具。
  2. 把成功率阈值从 0.95 收紧到 1.00（30 次零失败），观察哪一项指标最先受到压力，说明该指标的瓶颈属性。★★
    提示
    零失败要求取消随机波动的容忍带：段 1 与段 4 的偶发超时、工序段的偶发低分数都会立即判不通过。重点记录失败样本的段类别与错误码，再区分配置问题与随机波动。
  3. 预测实验：把笛卡尔步长从 0.01 m 改为 0.02 m，预测分数、耗时与末端直线偏差三项指标的变化方向，再运行验证。★★
    提示
    步长加倍后逆解次数减半、耗时下降；离散变粗使中间段直线偏差上升，分数在姿态敏感区可能下降。
  4. 设计题：把本实践扩展为"双工位"版本：两个取放位各含一次工序段，更新分段表与验收指标表，说明新增的失败模式与对应的检查点。★★★
    提示
    新增长距离转移段与工位间一致性检查；失败模式新增"工位坐标系标注错误"类，检查点放在位姿构造与参考系核对。

小结

  • 完整任务由关节空间转移段与笛卡尔工序段组合，往返设计提供免费的一致性检查。
  • 验收指标六项：成功率、分数、耗时 P90、轨迹合规、执行结果、往返偏差；每项都有依据与排查入口。
  • 失败处理分层：搜索类升级预算重试，约束类与执行类立即终止并报告段号。
  • 统计验收用独立样本，重试率是隐含指标，偏高说明基线配置不稳。
