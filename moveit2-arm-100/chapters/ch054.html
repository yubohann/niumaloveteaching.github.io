第三篇 · 规划算法与求解器

第 054 章：使用 IKFast 插件

IKFast 把逆运动学从迭代求解变为闭式求根：离线生成解析代码，运行时微秒级返回全部候选解。本章讲清生成流程、结构依赖、配置方法与验证验收，以及"何时值得付出生成成本"的判据。

  • 主题：运动学插件 / 解析解与代码生成
  • 关键机制：封闭解生成、候选解枚举、限位过滤、结构绑定
  • 预计学时：55 分钟
  • 前置章节：第 053 章

学习目标

  • 理解 IKFast 的生成原理：从链结构符号化推导多项式方程，输出可编译的解析求解代码。
  • 掌握生成流程的五个要素：机器人名、组名、求解器源文件、基座链路与末端链路，理解每个要素错误时的症状。
  • 能依据结构条件（球腕、轴线相交）判断一次生成是否可能成功，识别不满足条件的典型结构。
  • 会完成配置、编译、验收三步接入，并用正运动学回代与耗时测量确认质量。
  • 能维护生成产物：URDF 或标定参数变更后识别"需要重新生成"的信号。

背景与动机

笛卡尔路径的逐点 IK 调用把求解次数放大到数百甚至数千次，数值求解器毫秒级与微秒级的差别直接决定节拍可行性。IKFast 用"离线一次生成、在线无限复用"换取三个特性：微秒级速度、全部候选解、无迭代收敛问题。在结构固定的产线设备上，这笔交易几乎没有代价。

代价集中在维护面：求解代码与运动学结构绑定，模型变更需要重新生成。理解绑定关系的边界，是使用 IKFast 的核心纪律。

核心原理

1. 从符号推导到生成代码

第 050 章介绍了解析解的分层结构：腕心定位、肩部几何、腕部解耦与多项式求根。IKFast 把这一过程自动化：

  1. 结构分析：读取解析链的连杆参数与关节轴，识别可解结构（如球形腕）。
  2. 符号化推导：把位姿方程展开为关节变量的三角方程，经半角代换转化为多项式方程组。
  3. 求根求解：构造并求解多项式的根，回代得到每组关节值，输出为 C++ 函数。
  4. 代码落地：生成源文件被 MoveIt 的运动学插件包装编译，运行时等价于"查表加代数计算"。

生成器的输入必须与运行时严格一致：链的自由度数量、关节顺序、连杆偏置、末端偏置都在生成时进入公式。任何一项在日后被修改（改 URDF、换夹爪、改标定），生成代码就不再对应该结构，必须重新生成。

2. 求解器类型与结构条件

类型约束维度典型用途
transform6d完整 6 维位姿通用操作任务，最常见的选择
translationdirection5d位置 + 工具轴方向绕工具轴冗余的工艺（如夹爪自转自由）
translationxy / 其它退化类型位置子集平面定位类任务

可解结构的经典条件是六轴链中存在轴线相交的腕部。不满足条件时生成器无法给出封闭解，应选择数值求解器。类型选择遵循"任务实际约束什么"：任务只约束工具轴方向时用 5d 类型可以额外获得绕轴自由度，对可达性与节拍都有利。

3. 运行时的候选解与过滤

解析求解一次返回全部候选解（典型 6R 球形腕结构最多 8 组，数量依结构而定）。插件在返回给调用方之前执行过滤：

  • 关节限位过滤：超出限位的候选被剪除。注意生成模型与运行时模型的限位差异：生成时若不施加限位假设，运行时过滤完全依赖插件；限位设置过紧会出现"解析有解但返回无解"。
  • 避碰撞过滤：请求开启避碰撞时，候选解经规划场景检查后返回。
  • 种子排序：剩余候选按与种子状态的距离排序，返回最接近的一个。

微秒级的返回速度使 IK 通常不再构成瓶颈；若笛卡尔路径仍慢，排查方向应转向规划场景查询与轨迹组装环节。

实现思路与设计

接入流程（生成、配置、验收、维护四阶段）：

  1. 生成：准备求解器源文件（由生成器工具产出），调用 MoveIt 的生成脚本产出插件源文件与描述文件。
  2. 配置与编译：把产物放入工作空间包，配置 kinematics.yaml 指向插件，编译后重启节点。
  3. 验收：随机位姿样本做正运动学回代验证，测量单次耗时与成功率，对照数值求解器基线。
  4. 维护：把"模型变更触发重生成"写入配置变更流程；重生成后重跑验收样本。

参数表（字段以生成脚本与插件文档为准）

参数典型值作用取值依据
kinematics_solverikfast_kinematics_plugin/IKFastKinematicsPlugin启用解析求解生成产物编译成功后配置
kinematics_solver_timeout0.005 s（形式保留）接口兼容字段解析求解不迭代，通常不触及
kinematics_solver_search_resolution0.005 rad候选解与种子间的检查步长避碰撞场景使用
position_only_ikfalse位置模式（视生成类型而定）5d 类型任务另议

与前三章的差异：IKFast 的"配置"先于"参数"，生成产物的正确性权重远高于运行参数微调。前三种插件调参可以改善成功率；IKFast 一旦生成与结构绑定正确，成功率上限由结构可达性与限位过滤决定。

关键代码与解读

片段 1：生成插件（命令示意）

# MoveIt2 的移动运动学包提供生成脚本（脚本名与参数以发行版为准）：
#   create_ikfast_moveit_plugin.py 机器人名 规划组名 求解器源文件 基座链路 末端链路
ros2 run moveit_kinematics create_ikfast_moveit_plugin.py \
  my_arm arm_group ikfast_solver.cpp base_link tool0

# 生成后会提示需要把产物放入哪个包、如何编译；核心纪律：
#   五个位置参数必须与运行时 URDF 的链路名逐字一致，任何改动都触发重新生成

解读：生成脚本的五个参数就是结构绑定的完整清单：机器人名与组名决定"谁来用"，求解器源文件决定"用什么方程"，基座与末端链路决定"解哪一段链"。最常见的失败是链路名不匹配：生成时为 tool0，运行时组定义改成 tool_frame，插件加载后行为异常或求解失败。生成产物放入包后需完整编译工作空间，由插件机制在节点启动时装配。

片段 2：IKFast 配置

# kinematics.yaml：解析插件的配置面（生成产物的包名与插件名以实际为准）
arm_group:
  kinematics_solver: ikfast_kinematics_plugin/IKFastKinematicsPlugin
  kinematics_solver_timeout: 0.005       # 形式保留字段：解析求解为一次计算，不含迭代
  kinematics_solver_search_resolution: 0.005   # 候选解到种子的插值检查步长（避碰撞用）
  position_only_ik: false

解读：超时字段在解析求解下几乎不生效，保留它只是为了与接口兼容；真正影响行为的运行参数是搜索分辨率与避碰撞开关：前者在候选解返回前做插值碰撞检查时生效，后者决定是否做场景过滤。如果验收发现"解析已生成却频繁返回无解"，先查限位过滤与避碰撞过滤，再查生成绑定，调超时无济于事。

片段 3：验收脚本（正运动学回代与耗时测量）

import time, statistics

def accept_ikfast(ik_client, fk_function, poses, joint_names):
    """验收解析插件：回代误差分布 + 单次耗时分布，双指标一起过关。"""
    seed = current_joint_values()
    errors, times, ok = [], [], 0
    for pose in poses:                     # poses 由随机关节角经 FK 生成，保证可达
        t0 = time.perf_counter()
        res = ik_client.solve(pose, seed, joint_names, timeout=0.05)
        times.append(time.perf_counter() - t0)
        if res and res.error_code.val == 1:
            ok += 1
            # 回代：用求解出的关节值做正运动学，度量与目标位姿的位置偏差
            achieved = fk_function(joint_values_of(res))
            errors.append(position_distance(achieved, pose))
    print(f"成功率 {ok/len(poses):.2f}，"
          f"中位耗时 {statistics.median(times)*1000:.2f} ms")
    if errors:
        print(f"回代误差中位数 {statistics.median(errors)*1000:.4f} mm，"
              f"最大 {max(errors)*1000:.4f} mm")

解读：验收样本由随机关节角经正运动学生成，保证每个位姿本身可达，排除了"结构不可达"对成功率的污染。回代误差的期望量级在微米级：解析求解是代数计算，误差主要来自数值噪声；若看到毫米级偏差，应按"生成绑定错误"排查，不宜按精度不足处理。耗时指标同批给出，用于确认微秒到亚毫秒的量级判断（服务封装会引入额外开销，进程内调用更能反映纯求解时间）。

常见坑

  • 模型改动未重生成：换夹爪（末端偏置变化）、改连杆参数或标定后，生成代码仍按旧结构计算，表现为系统性偏差或失败。修复：建立"运动学参数变更触发 IKFast 重生成"的清单项。
  • 基座与末端链路选错：生成时用了错误的链路对，求解结果与任务期望错位。修复：以 SRDF 组的起止链路为唯一依据，逐字核对。
  • 限位过滤清空候选：限位配置过紧或关节零点偏移，把全部候选解剪除，表现为"解析存在却无解"。修复：核对限位配置与标定，先放宽测试再逐步收紧。
  • 不支持的结构强行生成：链中不含相交腕轴时生成器无法封闭求解。修复：回退数值求解器（第 051 至 053 章），或评估把 5d 类型用于任务（约束维度匹配时）。
  • 忽略 mimic 与被动关节：含随动关节的链不符合生成假设，产物行为不可预期。修复：生成与运行时均排除非独立关节，或改用数值求解器。

练习与思考

  1. 列出会让你必须重新生成 IKFast 的三类变更，并说明每类变更影响求解代码的哪个部分。★
    提示
    连杆参数变化（几何项）、末端偏置变化（腕心定位项）、关节轴或顺序变化（结构识别与方程构造）。三类都改变生成时的符号推导结果。
  2. 某夹爪绕工具轴旋转对称，任务只约束夹持方向。分析使用 transform6d 与 translationdirection5d 两种生成的差异（可用自由度、候选解数量、可达性）。★
    提示
    6d 把绕轴角也约束死，可达位姿集合更小；5d 放开绕轴自由度，候选更多、可达性更好，适合对称夹爪。代价是执行时绕轴角不受控，需确认工艺允许。
  3. 设计 IKFast 的变更回归清单：从 URDF 修改到产线发布，列出必须执行的验证步骤与通过判据。★★
    提示
    步骤：重生成 → 编译 → 样本验收（回代误差与成功率）→ 与数值求解器对照 → 路径级测试（整条笛卡尔路径通过率）。判据：回代误差微米级、样本成功率不低于基线、路径通过率持平或提升。
  4. 推导题：6R 球形腕结构最多 8 组解，其中位置部分的解数来自哪一步？若腕部为偏置腕（轴线不相交），求解分支会发生什么变化（定性即可）？★★★
    提示
    位置部分由肩部与肘部的组合产生最多 4 组（左右肩 × 上下肘），腕部姿态分解再乘 2。偏置腕使姿态与位置耦合，方程次数上升，求解分支增多且可能无封闭解，通常超出 IKFast 的生成能力。

小结

  • IKFast 把解析解自动化：离线符号推导生成代码，运行时以代数计算返回全部候选解。
  • 生成与运行共享同一结构约束：链的关节顺序、连杆参数、末端偏置与链路名必须逐字一致。
  • 速度在微秒量级，收益来自"结构换速度"；结构变更必须重生成，这是维护纪律的核心。
  • 验收用随机关节角生成的位姿样本，回代误差应在微米级；毫米级偏差按绑定错误处理。
  • 可解结构（如球腕）是前提；不满足时回退数值求解器，或改用维度匹配的退化类型。
