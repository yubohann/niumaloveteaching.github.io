第二篇 · 规划场景与碰撞管理

第 027 章：距离场与碰撞距离查询

从"碰不碰"升级到"离多远、最近在哪"：本章讲几何距离的数学定义、最近点查询的实现思路（GJK 与包围盒层次）、距离场的空间数据结构与内存账本，以及距离信息在安全裕量与规划优化中的用法。

  • 主题：碰撞信息度量 / 距离查询
  • 关键机制：最小距离与最近点、GJK 类算法、体素距离场与梯度
  • 预计学时：55 分钟
  • 前置章节：第 026 章

学习目标

  • 区分碰撞检测（布尔判定）与距离查询（连续度量）两类问题，理解各自回答什么问题、代价差在哪里。
  • 掌握两组几何之间最小距离与最近点的数学定义，了解 GJK 与 EPA 的求解思路和包围盒层次在网格距离中的角色。
  • 理解距离场的空间数据结构：体素栅格、分辨率与内存的三次方关系、有符号距离与梯度。
  • 会用 MoveIt 的距离查询接口取回最小距离与最近点，并按阈值做安全裕量判定。
  • 能估算给定工作空间的距离场内存规模，并在"直接查询"与"预计算场"之间做出选择。

背景与动机

前面几章的碰撞管理围绕一个布尔问题展开：机器人会不会碰到。布尔答案能支撑避障规划，却回答不了一类更精细的需求：路径离障碍到底有多远。安全工程关心裕量，执行监控关心"是否过于贴近"，轨迹优化关心连续的碰撞代价与它的梯度，抓取质量评估关心接触距离。这些问题都要求把碰撞信息从 0 与 1 扩展成连续量。

本章引入两组工具。直接距离查询对任意两个几何体计算最小距离与最近点，精度高、单次代价高，适合按需调用；距离场（Distance Field）把空间中每一点到最近障碍的距离预先制成体素栅格，查询代价降为常数，代价是内存开销与重建时机。二者的取舍是本篇中的一个典型工程决策：先想清楚查询的模式（偶发、批量、还是位于内层循环），再决定用查询还是用场。本章也是第 028 章碰撞检测内部机制与第 043 章轨迹优化的共同基础。

核心原理

1. 从布尔判定到距离度量

碰撞检测回答"两个几何是否相交"，一旦发现接触就可以提前退出，代价与接触发生的早晚有关。距离查询回答另一个问题：两组几何之间最近的距离是多少、最近的连线在哪里。它的数学定义如下：

d(A, B) = mina∈A, b∈B ‖a - b‖ 约定：相交时给出穿透深度并取负值，形成有符号距离；最近点即取到最小值的 (a, b)

这两类问题的代价特性不同：碰撞检测可以"尽早退出"，距离查询必须"找到最小"，因此单次距离查询通常更贵。距离查询的回报是信息量：最小距离支持裕量判定，最近点支持方向估计与接触法向近似，穿透深度支持侵入评估。MoveIt 的碰撞环境（CollisionEnv）同时提供两类接口，规划器默认只用布尔判定，避障质量与优化类规划器会额外消费距离信息。

2. 凸对凸：GJK 与 EPA 的思路

求解距离的核心算法针对凸集。GJK（Gilbert-Johnson-Keerthi）算法把两组几何的距离转为闵可夫斯基差（Minkowski Difference）上"到原点的距离"问题：两集合 A 与 B 的闵可夫斯基差为 D = {a - b | a ∈ A, b ∈ B}，A 与 B 的最小距离等于 D 到原点的最小距离。算法通过在 D 上迭代构造单形体（点、线段、三角形、四面体）逐步逼近最近点，收敛到给定精度即停。若原点落在 D 内，说明两集合相交，此时用 EPA（Expanding Polytope Algorithm）从穿透区域扩张出最小穿透向量，得到穿透深度。

解析形状（盒、球、柱、锥）都支持凸运算，因此解析形状之间的距离与穿透可以直接走这条路径，单次查询通常在微秒到几十微秒量级。非凸网格的距离查询复杂得多：检测器先为每个网格构建包围盒层次（Bounding Volume Hierarchy, BVH），用层次剪枝跳过不可能贡献最小距离的三角形对，再对候选三角形对做精算。网格距离的代价主要由 BVH 质量与三角形规模决定，这也解释了第 024 章反复强调"能不用网格则不用"的理由。

3. 距离场：把距离预制成一张表

当距离查询要被高频调用且查询点集中在固定空间区域内时，预计算比即时查询划算。距离场把空间离散为体素栅格，每个体素记录该位置到最近障碍表面的距离：

D(x) = miny∈∂O ‖x - y‖；内部取负号；‖∇D‖ = 1（几乎处处成立） ∂O 为障碍表面；梯度模为 1 意味着沿梯度方向走多远，距离就变化多少

梯度模恒为 1 这一性质（程函方程的直接推论）给出两件实用礼物：其一，从任意点沿梯度方向前进固定距离，就恰好离开障碍那么远，可用于评估裕量方向；其二，离散栅格上可以用中心差分估计梯度，误差与分辨率成正比（一阶），分辨率选得越细，方向估计越准。距离场的常见变体是有符号距离场（Signed Distance Field, SDF），内部取负让"穿透深度"与"外部间隙"共用一个标量。

4. 体素栅格的内存账本

体素栅格的内存与分辨率的立方成反比，做任何设计前先把账算清：

体素数 N ≈ (L / r)3，内存 M ≈ N × c L 为工作空间边长，r 为体素分辨率，c 为单体素字节数（浮点距离 4–8 字节，附带梯度则再乘 3–4 倍）

举例：2 m 见方的工作空间，分辨率 1 cm 时 N ≈ 8 × 106，只存距离约 32 MB；分辨率 5 mm 时 N、M 均放大 8 倍，达到约 256 MB；分辨率 2 mm 时超过 4 GB，超出常规实时进程的承受范围。分辨率每减半，内存与构建时间按约 8 倍增长；场的设计从选择分辨率开始，多数机械臂工位把 5 mm 到 2 cm 作为可用区间。工程上通常配合空间裁剪（只对规划关心的包围盒建场）、稀疏存储（只在表面附近细化）与递增更新（只重算变动区域）控制开销。

距离场的构建分两大家族。静态场景可以用欧氏距离变换（Euclidean Distance Transform, EDT）一次性算出全网格距离，两遍扫描或快速行进（Fast Marching）即可完成；存在动态障碍时，局部更新策略只重算受影响区域，代价与表面变动面积成正比。MoveIt 的碰撞距离场组件（collision_distance_field）为机器人连杆在世界系中的占位预计算距离场，向优化类规划器提供快速的距离与梯度查询；默认规划管线并不依赖它，属于按需启用的重型组件。

5. 查询接口的工程用法

MoveIt 的距离查询接口以请求与结果两个结构组织：请求里选择查询范围（哪个规划组、是否取最近点），结果里给出最小距离、最近点与涉及的连杆组名。工程上有三个用法要点。（1）阈值早退：安全判定只关心"距离是否小于裕量"，拿到结果先与阈值比较，再决定是否读取细节。（2）范围收窄：把查询限定在与任务相关的规划组，缩小参与计算的连杆集合，代价随之下降。（3）频率预算：距离查询用于监控或筛选时按固定节拍调用（例如每个控制周期一次），放进采样规划的内层循环前先实测单次代价。

实现思路与设计

在项目里引入距离信息的决策流程：

  1. 明确查询模式：偶发单点查询用直接接口；高频批量且空间固定则评估距离场。
  2. 设定阈值语义：安全裕量阈值（例如 0.03 m）与预警阈值（例如 0.05 m）分级，避免单一阈值造成的抖动。
  3. 选择查询范围：限定规划组或连杆集合，拒绝对全机器人做无差别查询。
  4. 若用距离场：先按内存公式估算分辨率与范围，确定裁剪包围盒；动态场景规划局部更新策略与重建周期。
  5. 接入判定逻辑：把最小距离与最近点写入监控或筛选逻辑；对穿透（负值）单独设告警分支。
  6. 回归验证：用已知几何对（例如两盒平行放置）核对查询结果与解析解一致，作为回归用例。

两类技术选型对照

维度直接距离查询距离场
单次代价微秒到数百微秒（随几何规模）常数级查表加插值
精度由算法容差决定，可达很高受分辨率限制，栅格误差约半个体素
内存无额外占用与分辨率三次方成反比，可到百 MB 级
更新场景变化无状态，天然跟随需要重建或局部更新
典型用途状态筛选、裕量抽查、执行监控轨迹优化内层循环、梯度类规划器

关键代码与解读

片段 1：C++ 计算机器人到环境的最小距离与最近点（接口以对应 ROS2 发行版与 MoveIt2 版本的官方文档为准）

// 距离请求：收窄到目标规划组，并要求返回最近点
collision_detection::DistanceRequest dreq;
dreq.group_name = "arm_group";          // 只计算该组连杆与世界的距离
dreq.enableGroup(planning_scene->getRobotModel());   // 由组名解析参与计算的连杆集合
dreq.enable_nearest_points = true;      // 最近点用于诊断与方向估计

// 结果结构承载三样信息：最小距离、最近点对、涉及的对象名
// 带请求对象的调用填充结果结构，返回值经 minimum_distance 字段访问
collision_detection::DistanceResult dres;
planning_scene->getCollisionEnv()->distanceRobot(dreq, dres, state);
double min_dist = dres.minimum_distance.distance;

// 阈值判定：安全裕量 3 cm，预警裕量 5 cm，两级语义避免临界抖动
if (min_dist < 0.03)
{
  // 最近一对的对象名与最近点都在 minimum_distance 字段中
  const auto& pair = dres.minimum_distance;
  RCLCPP_WARN(node->get_logger(), "距离 %.4f m 低于安全裕量，连杆 %s 与 %s",
              min_dist, pair.link_names[0].c_str(), pair.link_names[1].c_str());
  return false;                          // 拒绝该候选状态
}
if (min_dist < 0.05)
{
  // 最近点坐标系随版本与实现而异，跨系使用前先核对该版本的结果语义
  RCLCPP_INFO(node->get_logger(), "预警：最近点位于 (%.3f, %.3f, %.3f)",
              dres.minimum_distance.nearest_points[0].x(),
              dres.minimum_distance.nearest_points[0].y(),
              dres.minimum_distance.nearest_points[0].z());
}
return true;

解读：（1）请求中先收窄范围再要求细节，group_name 让查询只覆盖任务相关连杆，最近点开关按需开启，两者共同控制单次代价。（2）两级阈值把"拒绝"与"预警"分开：单阈值方案在距离临界值附近会因数值噪声反复切换判定结果，两级之间留出缓冲带，判定更稳定。（3）结果中的连杆组名与最近点服务于诊断：知道是哪对连杆、在哪里贴近，才能判断是姿态问题还是场景问题。对穿透（距离为负）的场景，应单独分支处理并在日志中给出穿透深度。

片段 2：Python 数值实验，验证有符号距离场与梯度性质

import numpy as np

def sdf_box_2d(p, center, half):
    """二维矩形的有符号距离：外部为正、边界为零、内部为负。"""
    d = np.abs(p - center) - half      # 相对各面的带符号间隙
    outside = np.linalg.norm(np.maximum(d, 0.0))
    inside = min(np.max(d), 0.0)       # 内部时取最大的负间隙
    return outside + inside

center = np.array([0.5, 0.0])
half = np.array([0.3, 0.2])            # 60 cm x 40 cm 的障碍

# 用中心差分估计梯度：理论上梯度模为 1，方向指向远离障碍的一侧
p = np.array([0.9, 0.5])               # 障碍右上角外侧的一点
h = 1e-4
gx = (sdf_box_2d(p + [h, 0.0], center, half)
      - sdf_box_2d(p - [h, 0.0], center, half)) / (2 * h)
gy = (sdf_box_2d(p + [0.0, h], center, half)
      - sdf_box_2d(p - [0.0, h], center, half)) / (2 * h)
print("梯度方向:", round(gx, 4), round(gy, 4))
print("梯度模:", round(float(np.hypot(gx, gy)), 4))   # 应接近 1

# 沿梯度走 0.1 m：距离应增加约 0.1 m，验证"远走远安全"的直觉
d0 = sdf_box_2d(p, center, half)
p2 = p + 0.1 * np.array([gx, gy])
print("距离变化:", round(float(sdf_box_2d(p2, center, half) - d0), 4))

解读：（1）矩形有符号距离函数由外侧距离与内部负间隙两部分相加而成，两个分支的连续性在角点处保持，适合作为数值实验的基准。（2）中心差分是栅格上估计梯度的标准手段，步长取 1e-4 量级在双精度下噪声尚可接受；真实栅格的梯度估计误差更大，由分辨率主导。（3）最后一行验证程函性质：梯度归一化后沿其方向移动 0.1 m，距离读数变化约 0.1 m，这解释了为什么距离场的梯度能直接作为"远离障碍"的方向指引。

片段 3：C++ 用距离阈值筛选候选起始状态

// 场景：为执行监控挑选一个"与障碍保有裕量"的候选构型
// 距离查询放在候选循环里，先粗筛再精查，控制总代价
std::vector<moveit::core::RobotState> candidates = build_candidates(seed_state);

collision_detection::DistanceRequest dreq;
dreq.group_name = "arm_group";
dreq.enableGroup(planning_scene->getRobotModel());   // 组名到连杆集合的解析
dreq.enable_nearest_points = false;     // 粗筛阶段不需要最近点，省一次计算

moveit::core::RobotState best = candidates.front();
double best_dist = -1.0;
for (const auto& cand : candidates)
{
  collision_detection::DistanceResult dres;
  double d = planning_scene->getCollisionEnv()->distanceRobot(dreq, dres, cand);
  if (d > best_dist)
  {
    best_dist = d;
    best = cand;                        // 记录当前裕量最大的候选
  }
}
RCLCPP_INFO(node->get_logger(), "候选 %zu 个，最佳裕量 %.4f m",
            candidates.size(), best_dist);

解读：（1）粗筛阶段关闭最近点开关：最近点的计算与返回占用额外时间，筛选逻辑只比较距离值时属于支出冗余。（2）循环里对每个候选做一次距离查询，候选数量由预算控制；若候选规模很大，应改用距离场把单次代价压到常数级，这是本章选型表在代码上的直接映射。（3）在布尔结论之外记录"最佳候选加裕量"，为后续执行监控提供可比较的基准值；裕量为负的候选应整体剔除，负值意味着已经穿透。

常见坑

  • 把距离查询塞进最内层循环：采样规划每次碰撞判定都改成距离查询，单次代价上升一到两个数量级，规划时间从秒级恶化到分钟级。修复是回到布尔判定加关键帧抽查，或改用距离场。
  • 把零距离当作安全接触：距离恰为 0 表示几何触碰，任何数值噪声会让它在正负之间跳动，判定逻辑随之抖动。修复是给"接触"设定带宽（例如绝对值小于 1 mm 视作接触），裕量判定使用正阈值。
  • 分辨率贪高：为精度把体素降到毫米级，内存超过实时进程可承受范围，构建时间进入秒级之上，场景一变全场重建。修复是按内存公式先算账，再按精度需求选分辨率，配合裁剪与稀疏存储。
  • 最近点坐标系误解：把最近点直接当作世界坐标做过跨系运算，得到错误的方向或位置结论。修复是核对所用版本对结果点坐标系的定义，跨坐标系使用时先变换到同一基准。
  • 有符号距离的适用性假设：认为任何几何对都能得到穿透深度，遇到不支持的类型对时拿到零或未定义值。修复是核对 FCL 对相关几何组合的支持矩阵，穿透评估单独设计兜底分支。

练习与思考

  1. 内存估算：一个 3 m × 2 m × 2 m 的工位，体素分辨率 1 cm，只存单精度距离值。估算体素数与内存；分辨率改为 5 mm 后各是多少？★
    提示
    体素数 = (300 × 200 × 200) = 1.2 × 107，单精度约 48 MB；分辨率减半后体素与内存都乘 8，约 9.6 × 107 个、384 MB。
  2. 结果预测：把片段 3 中最近的最近点开关从 false 改为 true，循环包含 200 个候选。查询结果值不变的前提下，预计总耗时朝哪个方向变化？为什么？★
    提示
    耗时上升。最近点需要对每个几何对记录并返回取到最小值的点对，计算与拷贝开销增加；粗筛无需这些信息时保持关闭。
  3. 设计题：为一个执行监控功能设计距离判定策略，要求给出采样频率、两级阈值、穿透分支与日志内容，并说明监控环节采用直接查询的取舍依据。★★
    提示
    监控按控制周期或更低频率采样，偶发的单点查询代价可接受，场景跟随性好，无需维护场；阈值参考本章的两级带设计，穿透分支汇报深度与连杆对。距离场的优势场景是高频批量查询。
  4. 诊断题：距离查询返回的最小距离长期恒为 0，列出三种可能原因与验证方法。★★
    提示
    候选原因：查询的连杆组包含已穿透且被豁免的接触对（核对接触矩阵与最近点名称）；查询范围过宽，把与地面常年接触的连杆算入（收窄组或过滤结果）；场景中存在与机器人重叠的物体（核对场景内容与物体位姿）。
  5. 分析题：从"查询模式、精度需求、场景动态性、内存预算"四个维度比较直接距离查询与距离场，给出一个两者混用的系统设计方案并说明分工。★★★
    提示
    混用方案：优化器内层使用距离场获得常数级距离与梯度；规划状态筛选与监控使用直接查询保证精度与场景跟随；距离场按局部更新维护，直接查询兜底核对两者的偏差作为回归验证。

小结

  • 距离查询把碰撞信息从布尔量扩展为最小距离、最近点与穿透深度，代价上失去"尽早退出"的便利。
  • 凸对凸距离由 GJK 在闵可夫斯基差上求解，穿透由 EPA 扩张得到；网格距离依赖包围盒层次剪枝，代价随三角形规模增长。
  • 距离场以体素栅格预存距离，梯度模为 1 的性质给出可靠的远离方向；内存与分辨率三次方成反比，先算账再选分辨率。
  • MoveIt 的距离接口适合收窄范围、阈值早退的用法；距离场服务于内层循环与优化类规划器。
