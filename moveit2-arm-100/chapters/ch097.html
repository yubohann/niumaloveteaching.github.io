第 097 章：与任务规划系统集成

把运动能力封装成符号层的动作：讲清任务规划、执行框架与运动规划的三层分工，技能接口的设计规范，以及运动失败触发符号重规划的回环结构。

  • 主题：系统集成 / 任务与运动衔接
  • 关键机制：符号动作模型、技能服务器、行为树执行、重规划回环
  • 预计学时：60 分钟
  • 前置章节：第 096 章

学习目标

  • 理解三层决策架构：符号任务层、执行层、运动层，及各层之间的信息流。
  • 掌握技能接口的规范：名称、参数、前提条件、效果、反馈与结果原因。
  • 理解 PDDL 类任务规划系统与 MoveIt2 的对接方式：动作映射与状态映射。
  • 会把运动技能封装为行为树节点，并设计反应式回退结构。
  • 能设计"运动失败触发符号重规划"的回环，并处理符号状态与真实状态的漂移。

背景与动机

抓取放置类任务的复杂性不在单次轨迹，而在步骤之间的选择：先抓哪个物体、用哪个工位、遇到遮挡绕行还是换目标。符号任务层用离散状态与动作推理这些选择，运动层用连续轨迹执行选择，两层之间需要一套稳定的接口。

集成失败通常表现为"上层发出的动作下层执行不了"或"下层失败了上层不调整"：动作前提与技能实现不匹配、技能粒度与任务层规划粒度不一致、运动失败没有反馈到符号状态。本章的核心是定义一套两边都能消费的技能接口与重规划回环。

上一章把感知接入运动层，本章再上一层：让任务决策系统按感知状态选择运动技能，形成从符号推理到轨迹执行的完整闭环。

核心原理

1. 三层决策架构

三层各司其职：符号层决定"做什么"，执行层决定"何时做、失败怎么办"，运动层决定"怎么做"。信息自上而下传目标与约束，自下而上传结果与状态更新。

层状态空间决策对象典型工具
符号任务层离散谓词集合动作序列与目标分解PDDL 类规划器
执行层任务进度与资源占用调度、监控、回退行为树、状态机
运动层连续关节与位姿空间轨迹与抓取姿态MoveIt2 管线与任务构造器

2. 技能：跨层接口

技能（Skill）是运动能力的符号化封装，其规范与动作模型同构：名称、参数、前提条件、效果、反馈与结果原因六要素。符号层用前提与效果推理，执行层用反馈监控，运动层实现具体调用。

动作模型：⟨名称, 参数列表, 前提条件 pre, 效果 eff, 代价 c⟩
前提与效果作用于谓词集合：eff = (eff+, eff−)（新增与删除的谓词） 例如"抓取(物体, 位姿)"的前提含可达与无遮挡谓词，效果为持有谓词；前提不成立时规划器不会选择该动作

技能粒度设计的原则是"符号层需要的区分度"：抓取与放置之间的接近、闭合、抬升通常合并为一个"抓取"技能，因为符号层不关心内部轨迹选择；粒度过细会让符号模型的谓词爆炸，粒度过粗会让失败后的重规划无处可退。

3. 状态映射：感知到谓词

符号推理需要离散状态，感知输出是连续位姿，中间由状态估计桥完成映射：物体在区域 A 内即谓词"位于(A)"成立，夹爪持有物体即谓词"持有"成立。映射函数必须有明确的判定阈值与滞回，否则谓词在边界附近抖动会让规划器反复重规划。

谓词映射：p(s) = 1[观测特征落在判定区域内]；边界加滞回带抑制抖动 例如"物体在托盘内"的判定区域带 2 cm 滞回：进入用内边界，离开用外边界，状态不随噪声翻转

4. 重规划回环

运动失败的反馈必须回到符号层才有意义：抓取失败可能意味着目标不可达，动作序列需要换目标或换顺序，原地重试收效有限。回环结构为：规划、执行、观测、比对，观测与预期不一致时触发重规划。

回环：π = Plan(s)；执行 a ∈ π；观测 s′；若 s′ 与 eff(a) 不符 → 更新 s 后重规划 重规划前必须更新符号状态：用执行结果修正谓词，否则规划器会在过时状态上重复同一动作序列

重规划需要终止保障：失败原因分类（第 094 章）决定回环行为，同一状态上对同一动作的重规划要计入尝试次数，达到上限后升级或放弃目标。

5. 执行框架的两种形态

任务规划器输出动作序列后，有两种执行方式：由执行框架按序列驱动（行为树或序列执行器），或由反应式结构自主决策（行为树的条件节点在运行中重新评估）。行为树适合"结构已知、需要反应式回退"的流程，PDDL 类规划器适合"结构未知、需要重新推导序列"的场景，两者常组合使用。

实现思路与设计

集成按"谓词定义、动作建模、技能实现、状态桥接、回环接线"五步落地。前两步在设计文档完成，后三步在代码与配置中实现，每步都有可运行的最小验证。

1. 谓词与动作清单（桌面抓取示例）

谓词含义来源
位于(物体, 区域)物体在指定区域视觉位姿与区域判定
可达(物体)物体在当前姿态下可达逆解探测
无遮挡(物体)接近路径无碰撞场景距离查询
持有(物体)夹爪持有该物体夹爪状态与附着关系
动作前提效果技能映射
抓取(物体)位于(取件区)、可达、无遮挡持有(物体)、¬位于(取件区)抓取技能
放置(物体, 区域)持有(物体)、位于区域可达位于(区域)、¬持有放置技能

2. 技能服务器设计

每个技能实现为一个服务或动作服务器，接口包含符号参数与执行反馈。技能内部完成"运动层组合"：规划、执行、验证，把结果翻译为符号层的成功或失败原因。失败的粒度要细到可映射谓词：目标不可达、路径被挡、夹持失败对应不同的谓词修正。

3. 回环接线

  1. 任务规划器给出动作序列与期望效果。
  2. 执行框架按序调用技能服务器。
  3. 技能返回成功时更新谓词并推进；失败时按原因修正谓词。
  4. 比对观测与期望，不符则触发重规划；尝试次数达上限进入升级。

与上一章的差异点：第 096 章打通感知到运动的数据链，本章在其上加装决策层，让"选择哪个动作"由符号状态与目标推导；两章共同构成感知、决策、执行的完整系统。

关键代码与解读

片段 1：动作模型的 PDDL 描述（域片段）

(define (domain tabletop-pick-place)
  (:requirements :strips :typing)
  (:types object region - obj)
  (:predicates
    (at ?o - object ?r - region)       ; 物体位于某区域
    (reachable ?o - object)            ; 物体当前可达
    (clear ?o - object)                ; 接近路径无遮挡
    (holding ?o - object))             ; 夹爪持有物体

  ; 抓取动作：前提全部成立时规划器才会选择它
  (:action pick
    :parameters (?o - object ?src - region)
    :precondition (and (at ?o ?src) (reachable ?o) (clear ?o))
    ; 效果用删除与新增表达：物体离开原区域并进入持有状态
    :effect (and (not (at ?o ?src)) (holding ?o)))

  ; 放置动作：目标是让物体出现在目的区域并解除持有
  (:action place
    :parameters (?o - object ?dst - region)
    :precondition (and (holding ?o) (reachable ?o) (clear ?o))
    :effect (and (at ?o ?dst) (not (holding ?o)))))

解读：动作模型是符号层与运动层的契约。设计要点：（1）前提中的可达与无遮挡谓词由运动能力（逆解与场景查询）提供，把运动可行性"提升"到符号层参与推理；（2）效果用谓词增删表达，执行后符号状态按定义更新，与真实状态的偏差由状态桥修正；（3）动作参数中的区域与物体名与技能服务器参数一一对应，名称即接口。替代方案是把"接近、闭合、抬升"拆成三个动作，前提与效果数量随内部步骤翻倍，符号层复杂度显著上升。

片段 2：技能服务器实现（Python 骨架）

import rclpy
from rclpy.node import Node
from rclpy.action import ActionServer

class PickSkill(Node):
    """抓取技能：接收符号参数，内部组合运动层调用，返回结构化结果。"""
    def __init__(self, move_client, scene):
        super().__init__("pick_skill")
        self.move = move_client            # 封装好的规划执行客户端（第 081 章）
        self.scene = scene                 # 场景接口：读写物体与附着关系
        self._server = ActionServer(
            self, PickAction, "skill/pick", self.execute)
    def execute(self, goal_handle):
        obj_id = goal_handle.request.object_id
        result = PickAction.Result()       # 结果字段承载结构化失败原因
        # 步骤一：目标缺失属于感知问题，原因文本供上层修正对应谓词
        target = self.scene.get_object(obj_id)
        if target is None:
            result.ok, result.reason = False, "object_missing"
            goal_handle.abort()
            return result
        # 步骤二：组合运动层调用，任一段失败转换为符号层可读原因
        ok, why = self.move.go_to(self.scene.observation_pose)
        if not ok:
            result.ok, result.reason = False, f"approach_failed:{why}"
            goal_handle.abort()
            return result
        ok, why = self.move.go_to(target.grasp_pose)   # 抓取位姿来自感知
        if not ok:
            result.ok, result.reason = False, f"goal_unreachable:{why}"
            goal_handle.abort()
            return result
        # 步骤三：以附着关系为可检验的成功判据，接口返回只作过程信息
        if not self.scene.close_gripper(obj_id):
            result.ok, result.reason = False, "grasp_not_established"
            goal_handle.abort()
            return result
        result.ok, result.reason = True, "ok"
        goal_handle.succeed()
        return result

解读：技能服务器是"运动层组合"与"符号层结果"之间的翻译器。设计要点：（1）失败原因按阶段区分并写入结果消息，上层据此修正不同谓词：物体缺失修正感知相关谓词，不可达修正可达谓词；（2）成功判据用附着关系这一物理事实，接口返回成功只作为过程信息；（3）技能粒度固定为一次完整抓取，内部三段调用对外不可见，abort 与 succeed 只标记状态，原因由结果消息承载。动作消息 PickAction 的字段按技能参数定义，服务端写法与第 081 章的客户端镜像。

片段 3：行为树执行片段（XML）

<root main_tree_to_execute="PickAndPlace">
  <BehaviorTree ID="PickAndPlace">
    <!-- 反应式回退：抓取失败先重测目标，再重试一次，仍失败则上报 -->
    <Fallback>
      <Sequence>
        <RetryUntilSuccessful num_attempts="2">
          <Sequence>
            <!-- 感知刷新节点：更新目标位姿并写入黑板 -->
            <RefreshTarget target="{target}" pose_out="{grasp_pose}"/>
            <!-- 运动技能节点：封装第 081 章客户端，读黑板参数 -->
            <MoveToGoal group="arm" pose="{grasp_pose}"/>
            <CloseGripper object="{target}"/>
          </Sequence>
        </RetryUntilSuccessful>
        <PlaceObject region="{place_region}"/>
      </Sequence>
      <!-- 回退分支：符号层重规划请求（第 088 章状态机入口） -->
      <ReplanTask cause="pick_failed"/>
    </Fallback>
  </BehaviorTree>
</root>

解读：行为树把"固定流程"与"反应式回退"组织在一棵树上。设计要点：（1）重试节点包住"刷新加抓取"的子序列，每次重试前更新目标位姿，避免对着过期位姿重复尝试；（2）运动技能节点读黑板参数，与技能服务器的输入契约一致；（3）回退分支触发符号层重规划，把执行层的局部失败升级为任务层的重新决策。行为树节点名与库版本相关，示例展示结构与数据流，具体节点实现按所用行为树库的接口编写。

常见坑

  • 符号状态与真实状态漂移：执行后未更新谓词，规划器在过时状态上重复选择同一动作。修复：每次技能调用按结果修正谓词，状态桥周期性全量校准。
  • 技能失败原因粒度不足：只返回"失败"，无法映射到谓词修正，重规划无依据。修复：按阶段返回结构化原因，与谓词一一对应。
  • 谓词判定无滞回：边界区域状态抖动，规划器反复切换动作序列。修复：判定区域加滞回带，进入与离开使用不同阈值。
  • 重规划无终止保障：同一失败无限触发重规划回环。修复：按动作与状态对计数，达到上限升级或放弃，计数逻辑独立于行为树。
  • 技能粒度与任务层不匹配：任务层需要的失败区分度被技能吞掉，或谓词数量超过必要粒度。修复：按"调试时需要的区分度"选粒度，用失败统计验证。

练习与思考

  1. 为"换工位放置"任务补充谓词与动作模型：目标区域有占用判定与工位切换，写出两个新动作的前提与效果。★
    提示
    新增谓词如"空闲(区域)"；动作"切换工位"以"空闲"为效果之一，放置动作的前提增加"业务区域空闲"。
  2. 设计状态桥的判定表：物体位置、夹爪状态、区域占用三组传感器数据到谓词的映射规则与滞回参数。★★
    提示
    物体位置用区域包围盒加内外边界；夹爪状态用开口宽度与力反馈双条件；占用用检测计数加连续帧确认。
  3. 改参数并预测：技能重试上限从 2 提高到 5，任务成功率与单任务平均耗时如何变化？给出选择上限的判据。★★
    提示
    成功率上升但失败样本代价放大；判据是失败后重试的边际成功率，低于阈值即可停在上限之前。
  4. 比较行为树与 PDDL 规划器在"步骤固定、偶发回退"与"步骤依赖环境动态决定"两类任务中的适用性，各举一例。★★★
    提示
    前者如固定工位抓放，行为树结构清晰；后者如杂乱堆叠挑选，需要规划器按状态推导序列，行为树承担执行与监控。
  5. 推导重规划回环的终止条件：设同一状态上同一动作重规划上限为 k，状态空间有限，说明最坏情况下回环次数有界的原因。★★
    提示
    每次失败至少修正一个谓词或消耗一次动作计数，状态改变则进入新状态，状态有限且计数有限，回环次数以两者乘积为上界。

小结

  • 三层架构：符号层决定做什么，执行层决定何时做与回退，运动层决定怎么做。
  • 技能六要素：名称、参数、前提、效果、反馈与结果原因，前提与效果构成动作模型。
  • 状态桥把连续感知映射为谓词，判定阈值配滞回带抑制状态抖动。
  • 重规划回环四步：规划、执行、观测、比对；失败原因必须修正谓词后再重规划。
  • 回环终止性由状态空间有限性与计数上限共同保证。
  • 下一章回到空间基础：机械臂标定与坐标系对齐，为多层系统的空间一致性提供精度保障。
