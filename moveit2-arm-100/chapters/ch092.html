第 092 章：实时性与控制频率的权衡

区分"计划并执行"与"连续控制"两类回路的时序需求，用延迟预算、控制周期与停止距离三个量把频率选择变成可计算的设计问题，并给出看门狗与线程划分方案。

  • 主题：时序设计 / 实时性与频率
  • 关键机制：截止时间与抖动、延迟预算、减速距离、伺服回路与看门狗
  • 预计学时：55 分钟
  • 前置章节：第 091 章

学习目标

  • 理解实时性的工程含义：满足截止时间的概率；速度均值不能作为实时性的依据。
  • 掌握控制周期、端到端延迟、抖动三个量的关系，会做延迟预算分解。
  • 会用停止距离与单周期位移两个约束选择控制频率与速度上限。
  • 理解规划回路与伺服回路的本质差异，知道伺服回路的适用场景与边界。
  • 会设计双回路线程划分与看门狗监控，避免规划阻塞控制。

背景与动机

运动规划求解时间不可预定：同一请求可能 200 ms 返回，也可能接近预算上限才返回。机械臂的控制回路按固定周期运行，不允许被规划阻塞；两类回路必须解耦，各自按自己的时间尺度设计。

频率选择的常见误区有两个：把控制器频率当作端到端响应频率（中间隔着感知与通信延迟）；盲目提高控制频率而忽略抖动与通信能力（周期缩短后单周期计算预算变小，抖动占比反而上升）。本章用三个可计算的量把频率选择与安全约束绑定。

上一章建立指标口径，其中规划时间与跟踪误差进入本章的时序设计；时序设计又反向决定指标阈值。

核心原理

1. 两类回路的时序特征

计划并执行回路（Plan-and-Execute）按任务触发，周期从秒到分钟；连续控制回路按固定周期运行，频率从 100 Hz 到 1000 Hz。两类回路的共同点是"截止时间"，区别在于截止时间是否与物理安全耦合。

回路触发方式典型频率超时后果
规划回路任务事件事件驱动，单次 0.5–5 s任务延迟，可重试
轨迹执行轨迹下发后周期运行100–1000 Hz跟踪误差增大，可能失稳
伺服（遥操与连续纠偏）输入流驱动100–500 Hz命令断流，必须自动停机
监督与看门狗周期检查10–50 Hz发现异常延迟，触发降级

2. 延迟预算分解

端到端延迟从传感器采样到机械动作生效，逐段累加。设计方法是先给定截止时间，再把预算分配到各段；任一段实测超标，先压缩该段；整体放宽预算会掩盖瓶颈。

T端到端 = T采样 + T通信上行 + T计算 + T通信下行 + T伺服执行 + T机械响应 ≤ T截止 伺服示例：截止 50 ms 时，采样与上行 10 ms、计算 15 ms、下行与执行 15 ms、机械响应 10 ms，任何一段超标都会挤占其它段

抖动（Jitter）是延迟的波动幅度，工程上比平均值更值得关注：按"平均延迟加三倍抖动"估算最坏延迟，用最坏值对照截止时间。抖动来源包括操作系统调度、网络拥塞与垃圾回收等运行时停顿。

3. 频率选择的两个约束

控制频率下限由两个约束共同决定：减速距离与单周期位移。停不下来的距离决定安全间隔，单周期位移决定轨迹离散误差。

d停止 = v² / (2a) + v · δ反应 末端速度 1.0 m/s、减速度 5 m/s²、反应延迟 0.1 s 时，停止距离约 0.2 m；该值直接决定安全围栏与感知触发区域的尺寸
Δq周期 = q̇max · T控制 关节速度上限 1.0 rad/s、周期 1 ms 时单周期位移 1 mrad，离散误差可忽略；周期放宽到 20 ms 时位移 20 mrad，插补精度与轨迹平滑度开始受影响

提高频率的代价包括：单周期计算预算变小、通信与日志流量上升、抖动占比变大。频率按"约束推下限、余量取上限"确定；超过约束所需的高频只会增加代价。

4. 伺服回路的位置

伺服回路用于遥操、连续纠偏等场景：每周期做一次逆解或速度映射，输出增量命令。它与规划回路的差别在于不需要全局路径，只有局部一致性；代价是容易在奇异位形与障碍附近失效，因此必须叠加奇异处理与碰撞速度缩放。

v下发 = min( v指令, s碰撞 · v安全上限 ) 碰撞缩放系数由最小间隙映射：间隙充足时为 1；间隙接近安全距离时线性衰减到 0

实现思路与设计

时序设计按"定截止、分预算、选频率、划回路、加看门狗"五步进行。每一步的输出是下一步的输入：截止时间决定预算分配，预算决定可实现的频率。

1. 频率与安全参数表

参数取值依据检查方式
控制频率关节带宽的 10 倍以上，且满足单周期位移约束跟踪误差频谱与单周期位移计算
伺服发布周期截止时间减去通信与机械响应端到端延迟实测
碰撞检查频率可低于命令频率，用最近结果外推间隙变化率与安全距离对照
命令超时覆盖 3 个发布周期加抖动断流测试：超时后必须停机
看门狗周期控制周期的 10–50 倍注入延迟，确认告警时延

2. 回路划分

  1. 规划回路：独立线程或独立进程，承担秒级求解，结果进入待执行队列。
  2. 执行回路：由控制器承担，只消费已确认的轨迹，不感知规划状态。
  3. 监督回路：检查状态新鲜度、命令流活性与执行进度，异常时降级或停机。
设计决策：为什么碰撞检查频率可以低于命令频率？

命令频率受平滑与跟踪误差约束，而间隙变化率受速度约束：按最大接近速度与检查周期估算间隙变化上界，只要上界小于安全距离余量，低频率检查即可保证安全。该结论依赖"速度有上限"这一前提，速度缩放调整后必须重新核算。

3. 看门狗设计

看门狗监控三类心跳：状态话题的新鲜度、命令流的到达节奏、轨迹执行的进度。触发分级：轻微延迟记录告警，超过停机阈值则输出零速度并转换到安全状态。阈值必须大于正常抖动上界，否则误停；同时小于安全允许的最坏延迟，否则失去意义。上线前用注入延迟实验标定两端。

与上一章的差异点：第 091 章把延迟当统计对象测量，本章把延迟当设计对象分配；测量数据直接成为预算标定的输入。

关键代码与解读

片段 1：延迟预算计算器

def latency_budget(segments, deadline, jitter_sigma=0.0, k=3):
    """把端到端截止时间分配到各段，并给出最坏延迟估计。"""
    total = sum(segments.values())
    worst = total + k * jitter_sigma      # 按均值加三倍抖动估计最坏值
    result = {"total": total, "worst": worst,
              "margin": deadline - worst}
    for name, v in segments.items():
        # 逐段打印占比：超标的段落一眼可见，压缩目标明确
        print(f"{name:12s} {v*1000:7.1f} ms  占 {v/total:5.1%}")
    print(f"最坏延迟 {worst*1000:.1f} ms，余量 {result['margin']*1000:.1f} ms")
    return result


segments = {
    "采样": 0.004, "上行通信": 0.006, "伺服计算": 0.015,
    "下行通信": 0.005, "伺服执行": 0.010, "机械响应": 0.008,
}
# 截止 50 ms、抖动 2 ms：余量为正才允许上线，负值必须压缩最大段
latency_budget(segments, deadline=0.050, jitter_sigma=0.002)

解读：预算函数把"感觉够快"变成可审计的数字。设计要点：（1）逐段列出占比，压缩目标自动浮现；（2）最坏延迟按"均值加三倍抖动"估计，余量为负时不允许上线；（3）机械响应段容易被忽略，它包括伺服带宽与结构弹性，需由实测获取。参数 50 ms 与抖动 2 ms 只是示例，实际值按设备测量替换。

片段 2：监督回路的看门狗

import time
import rclpy
from rclpy.node import Node
from sensor_msgs.msg import JointState
class Watchdog(Node):
    """监督回路：状态新鲜度与命令流活性，超阈值输出停机。"""
    def __init__(self):
        super().__init__("watchdog")
        self.last_state = time.monotonic()   # 状态话题最近到达时刻
        self.last_cmd = time.monotonic()     # 命令流最近到达时刻
        self.create_subscription(JointState, "joint_states", self.on_state, 10)
        self.create_timer(0.1, self.check)   # 10 Hz 检查足以捕捉秒级异常
    def on_state(self, msg):
        self.last_state = time.monotonic()
    def note_command(self):
        # 命令链路的活跃度由发布者调用；断流超过阈值即判失活
        self.last_cmd = time.monotonic()
    def check(self):
        state_age = time.monotonic() - self.last_state
        cmd_age = time.monotonic() - self.last_cmd
        # 阈值分层：先告警，再停机；阈值必须大于正常抖动上界
        if state_age > 0.5 or cmd_age > 0.3:
            self.get_logger().error(
                f"链路失活: state={state_age:.2f}s cmd={cmd_age:.2f}s")
            self.halt()
        elif state_age > 0.2 or cmd_age > 0.15:
            self.get_logger().warn("链路延迟接近阈值，检查负载与通信")
    def halt(self):
        # 停机动作幂等：重复调用不产生副作用（第 088 章要求）
        self.get_logger().error("进入安全状态：输出零速度")
def main():
    rclpy.init()
    node = Watchdog()
    rclpy.spin(node)             # 监督回路独立执行，不与规划线程共享
    rclpy.shutdown()

解读：看门狗是时序设计的最后防线。关键行为：（1）监控对象是"活性"：状态是否有更新、命令是否在流动，失活先于数值异常出现；（2）两级阈值：告警留出排查窗口，停机保证安全；（3）停机动作幂等，重复触发不产生叠加副作用；（4）监督回路独立执行器，不被规划任务阻塞。阈值取 0.3 s 与 0.5 s 为示例量级，实际按发布周期与抖动实测标定。

    scene_collision_proximity_threshold: 0.02  # 场景碰撞降速距离（米）

    command_out_topic: /arm_controller/joint_trajectory

解读：伺服配置的每个数值都能追溯到约束。设计要点：（1）发布周期由端到端截止时间倒推确定；（2）碰撞检查频率低于命令频率，安全性由"最大接近速度乘检查周期小于安全距离"保证；（3）接近阈值是碰撞缩放的触发边界，配置值必须大于控制误差与标定误差之和；（4）奇异阈值限制病态方向的速度，避免关节速度爆发。参数名与默认值随发行版演进，部署前对照官方配置样例逐项核对。

常见坑

  • 把控制器频率当作端到端频率：控制器 1 kHz 运行，但感知与规划延迟数百毫秒，遥操响应迟钝。修复：按延迟预算逐段测量，从最大段开始压缩。
  • 规划与执行共享线程：规划求解阻塞执行循环，控制器收到命令间隔抖动。修复：规划独立线程或独立进程，执行回路只消费已确认轨迹。
  • 看门狗阈值贴近正常周期：阈值等于周期加少量余量，网络抖动即误停。修复：阈值按"正常抖动上界加安全余量"设定，并用注入延迟实验标定。
  • 碰撞检查降频后未复核：降低检查频率后，速度上限未同步调整，间隙变化超过安全余量。修复：按公式复核"最大接近速度乘检查周期"，不满足则降低速度或提高检查频率。
  • 忽略机械响应段：预算里只算计算与通信，实际延迟由伺服带宽主导。修复：用阶跃响应实验测量机械段，把实测值写回预算表。

练习与思考

  1. 计算停止距离：末端速度 0.6 m/s，减速度 3 m/s²，反应延迟 0.15 s，求停止距离；若速度提高到 1.2 m/s，其余不变，距离变为多少并说明与感知触发区域的关系。★
    提示
    0.6²/(2×3) + 0.6×0.15 = 0.15 m；1.2 m/s 时 0.24 + 0.18 = 0.42 m，接近三倍；感知触发区域必须覆盖停止距离。
  2. 做延迟预算：截止 40 ms，各段均值为采样 3 ms、上行 5 ms、计算 12 ms、下行 4 ms、响应 10 ms，抖动 1.5 ms。判断能否上线，若不能，给出两种压缩方案。★★
    提示
    均值合计 34 ms，加三倍抖动 4.5 ms 为 38.5 ms，余量 1.5 ms 偏薄；方案：降低输入分辨率压缩计算，或提高通信优先级压缩上下行。
  3. 改参数并预测：伺服发布周期从 10 ms 降到 5 ms，单周期位移、通信负载与抖动占比分别如何变化？给出需要同步复核的两个安全参数。★★
    提示
    单周期位移减半、通信负载翻倍、抖动占比上升；需复核碰撞检查频率对应的安全余量与看门狗超时阈值。
  4. 设计看门狗标定实验：用注入延迟与断流两类扰动，测出告警阈值与停机阈值的最小安全值，写出判定依据。★★★
    提示
    扫描注入延迟幅度记录误停率，取误停率低于目标的最大阈值作为下限候选；再按停止距离要求限出上限，两个约束的交集即可用区间。
  5. 推导：为什么"碰撞检查频率乘最大接近速度"必须小于场景碰撞触发距离？写出不等式并说明各量的来源。★★
    提示
    v_max × T_check ≤ d_trigger − r_margin；左侧是两次检查之间的最大间隙变化，右侧是触发距离扣除余量；违反时高速接近可能在检查间隔内跨过触发区。

小结

  • 实时性是满足截止时间的概率；抖动决定最坏延迟，平均值不足以支撑设计。
  • 延迟预算把端到端时间分配到采样、通信、计算与机械响应各段，超标段优先压缩。
  • 控制频率由减速距离与单周期位移两个约束推导，以约束为准，一味求高只会增加代价。
  • 规划回路与执行回路必须解耦，伺服回路叠加奇异处理与碰撞速度缩放才有安全边界。
  • 看门狗分两级阈值监控活性，阈值用注入实验标定，停机动作保持幂等。
