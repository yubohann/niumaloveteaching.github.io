第 100 章：综合项目实践：桌面抓取放置系统

把全课程的组件组装成可验收的完整系统：给出需求、架构、模块清单与验收指标，提供编排、场景与验收三段关键代码，并在收束处回顾全课程五篇的知识主线。

  • 主题：系统集成 / 综合实践与课程收束
  • 关键机制：任务周期闭环、模块清单与接口、验收统计、安全与恢复联动
  • 预计学时：70 分钟
  • 前置章节：第 099 章

学习目标

  • 能从一个任务描述出发，设计出感知、场景、规划、执行与编排五层完整的系统架构。
  • 会把系统需求翻译为可度量、可统计的验收指标，并说明每个指标的采集方法与判据。
  • 会组织分阶段联调：静态单点、单目标周期、连续周期、异常注入与长时运行。
  • 能编写任务周期编排、场景初始化与验收统计三段核心代码，并解释设计取舍。
  • 能说出全课程五篇的关键结论及其在综合系统中的落点。

背景与动机

前面九十九章逐组件展开，知识以碎片形式存在：规划参数、场景维护、恢复策略、安全限制各自独立。综合项目的价值在于暴露组件之间的耦合：感知的时效影响规划结果的可用性，恢复策略改变验收统计的口径，安全限制约束速度参数的上限。

桌面抓取放置系统是覆盖面最完整的题目：它要求静态场景建模、动态物体感知、抓取位姿生成、规划与执行闭环、任务编排与失败恢复、验收统计与安全约束，几乎触及课程全部知识点。完成项目的意义在于校验：每个指标背后都对应若干章节的结论。

上一章讨论了长时稳定性，本章把稳定性要求写进验收指标与联调流程，形成可交付的系统定义。

核心原理

1. 需求到系统边界

需求定义先固定任务、环境与约束三个边界。边界不清的后果是验收时才发现指标不可测或任务不可达。本项目的参考定义如下：六轴机械臂加平行夹爪，桌面放置若干柱状物体与一个容器；任务为把物体从桌面抓取并放入容器，连续运行；工作空间限制在桌面区域上方，与人共享区域时速度受限。

维度定义影响
任务逐个抓取并放置，直至桌面清空后循环补料编排状态机与补料接口
物体柱状，直径与高度固定，重量已知抓取方式与力矩预算
环境含容器、桌面与固定工装场景物体与碰撞约束
约束共享区域限速、限高、防跌落安全参数与验收项

2. 五层架构与信息流

架构分五层：感知层提供物体位姿；场景层维护静态与动态物体；规划层生成轨迹与抓取姿态；执行层完成轨迹下发与状态回读；编排层驱动任务周期并处理失败。层间接口只传结构化消息，禁止跨层直接读写对方内部状态。

任务周期：感知 → 场景更新 → 抓取候选 → 规划 → 执行 → 验证 → 编排决策 每一步都携带时间戳与版本号；验证鉴定的对象是物理事实（附着关系、容器内计数），接口返回值只作过程信息

3. 验收指标体系

验收指标按统计口径定义，采集方法沿用第 091 章的框架。指标必须包含失败统计与稳定性统计，只报告成功样本的系统没有验收意义。

指标判据（示例）采集
任务成功率连续 100 个任务周期 ≥ 95%编排层周期结果
规划时间P95 ≤ 1.0 s，中位数 ≤ 0.4 s规划响应
单周期时长中位数 ≤ 25 s，P95 ≤ 35 s周期起止时间戳
恢复有效性可恢复失败中 ≥ 80% 被成功恢复恢复器记录
安全项限速触发、急停链路、越界拒止逐项通过注入测试
稳定性连续运行 2000 周期后终点偏差仍在预算内漂移监测器（第 099 章）
成功率预算分解：P任务 ≈ P感知 · P规划 · P执行；含恢复后 P′ = Π p′i（p′i 为含重试的单环节等效成功率） 感知 0.97、规划 0.98、执行 0.99 时基础成功率约 0.94；恢复把单环节等效成功率提升后可达 0.99 量级，指标分解驱动薄弱环节定位

4. 全课程主线回顾

五篇构成一条完整的能力链。第一篇建环境与接口，第二篇管场景，第三篇选算法，第四篇做操作任务，第五篇集成与维护。

篇核心结论在本项目中的落点
一、环境与基础控制（001–018）模型、状态与接口是所有上层能力的地基URDF 与状态源、轨迹执行链路
二、场景与碰撞（019–038）场景即规划的世界观，同步先于规划桌面、容器与感知物体管理
三、算法与求解器（039–060）算法选择与参数设定遵从任务几何特性窄缝场景的规划器与预算配置
四、抓取与操作（061–078）任务语义（抓什么、放哪里）决定运动形态抓取候选、附着关系、放置验证
五、集成与维护（079–100）集成决定可用性，维护决定可持续性编排、恢复、安全、标定与稳定性

实现思路与设计

项目实施按"模块清单、接口约定、参数起点、联调阶段、验收流程"五步组织。模块清单固定责任边界，接口约定固定数据形状，参数起点给出可运行配置，联调分阶段引入复杂性，验收按统计口径判放行。

1. 模块清单

2. 参数起点

调试阶段采用保守起点：速度缩放 0.3、规划时间预算 2 s、尝试次数 10、碰撞检查启用、限速档位按第 093 章的档位表。每个参数都标注调整依据与影响指标，参数修改必须走单变量加对照批次的流程，避免多变量同调造成归因失败。

3. 联调五阶段

  1. 静态单点：场景固定、单物体、单目标，验证规划执行链路。
  2. 单目标周期：接入感知与抓取技能，验证一个完整任务周期。
  3. 连续周期：清空桌面循环运行，验证场景更新与补料接口。
  4. 异常注入：移除目标、遮挡路径、制造超时，验证恢复器与安全链路。
  5. 长时运行：连续周期达成规模后核对漂移与资源趋势。

4. 验收流程

验收批次固定任务集与初始场景，连续执行规定数量的任务周期，按指标表逐项判定；任何一项不达标先定位对应模块再修正。验收报告附带批次标识：任务集标识、参数快照、软件版本与标定残留，保证结果可复现。

与上一章的差异点：第 099 章维护系统的长期健康，本章给出系统的整体定义与验收方式，把"可持续运行"量化为可检验的交付条件。

关键代码与解读

片段 1：任务周期编排（顶层循环）

class TabletopCycle:
    """任务周期：感知、规划、执行、验证、统计五段，失败走恢复器。"""

    def __init__(self, ctx, skills, recovery, stats):
        self.ctx = ctx                  # 场景、运动客户端与状态访问
        self.skills = skills            # 抓取与放置技能（第 097 章）
        self.recovery = recovery        # 有界恢复器（第 094 章）
        self.stats = stats              # 验收统计（第 091 章）
    def run_once(self):
        cycle_start = self.ctx.now()
        try:
            # 第一段：感知刷新与场景更新；守卫拒绝过期场景（第 095 章）
            target = self.ctx.refresh_perception()
            if target is None:
                self.stats.record("cycle", "no_target")
                return "idle"
            # 第二段：抓取技能内部完成观察位、接近、闭合与验证
            ok, why = self.skills.pick(target)
            if not ok:
                # 第三段：失败进入恢复器；恢复成功则重试一次本周期
                recovered, action = self.recovery.try_recover(why)
                if not recovered:
                    self.stats.record("cycle", f"pick_failed:{why}")
                    return "failed"
                self.ctx.log(f"恢复动作 {action} 成功，重试本周期")
                ok, why = self.skills.pick(target)
                if not ok:
                    self.stats.record("cycle", f"retry_failed:{why}")
                    return "failed"
            # 第四段：放置与终检；终检以容器内计数这一物理事实为准
            ok, why = self.skills.place(target, self.ctx.place_region)
            if not ok:
                self.stats.record("cycle", f"place_failed:{why}")
                return "failed"
            # 第五段：周期级统计与漂移上报，供验收批次汇总
            self.stats.record("cycle", "ok", duration=self.ctx.now() - cycle_start)
            return "done"
        finally:
            # 周期边界统一执行轻量维护：状态重同步与计数器轮转（第 099 章）
            self.ctx.boundary_maintenance()

解读：顶层循环把全课程机制串成一条执行路径。设计要点：（1）每段职责单一，失败原因带阶段前缀进入统计，验收时可分解到模块；（2）恢复只重试一次本周期，恢复器内部仍是有界多级序列，两层边界不叠加；（3）放置验证以物理计数为准，避免"接口成功但物体不在容器内"的假成功；（4）finally 中的边界维护保证无论成功失败都执行轻量复位，与第 099 章的计划一致。

片段 2：场景初始化

from moveit_msgs.msg import CollisionObject
from shape_msgs.msg import SolidPrimitive
from geometry_msgs.msg import Pose

def build_static_scene(scene):
    """初始化静态场景：桌面、容器、限高平面与工作空间边界。"""
    objects = []
    # 桌面：碰撞几何与感知中的平面一致，避免"感知桌沿"与"建模桌面"错位
    table = CollisionObject()
    table.id = "table"
    table.header.frame_id = "world"
    prim = SolidPrimitive(type=SolidPrimitive.BOX, dimensions=[1.2, 0.8, 0.04])
    pose = Pose()
    pose.position.z = -0.02              # 桌面顶面位于 z = 0
    pose.orientation.w = 1.0
    table.primitives.append(prim)
    table.primitive_poses.append(pose)
    table.operation = CollisionObject.ADD
    objects.append(table)
    # 容器：用三个薄壁表达（底面与两侧），顶部开放便于放置
    for name, size, pos in [
        ("bin_floor", [0.30, 0.30, 0.02], (0.45, 0.0, 0.01)),
        ("bin_wall_x", [0.02, 0.30, 0.10], (0.60, 0.0, 0.05)),
        ("bin_wall_y", [0.30, 0.02, 0.10], (0.45, 0.15, 0.05)),
    ]:
        obj = CollisionObject()
        obj.id = name
        obj.header.frame_id = "world"
        p = SolidPrimitive(type=SolidPrimitive.BOX, dimensions=size)
        q = Pose()
        q.position.x, q.position.y, q.position.z = pos
        q.orientation.w = 1.0
        obj.primitives.append(p)
        obj.primitive_poses.append(q)
        obj.operation = CollisionObject.ADD
        objects.append(obj)

    # 批量提交：一次差分应用减少场景服务的往返次数
    scene.apply_objects(objects)
    return [o.id for o in objects]

解读：场景初始化定义规划世界的静态部分。设计要点：（1）桌面几何与感知平面处理配合（第 095 章的地面过滤），防止同一表面以两种形式重复表达；（2）容器用三块薄壁表达（完整盒子会挡住放入路径），顶部开放让放置轨迹可以进入；（3）所有物体使用统一世界参考系与整数化位置，便于人机复核；（4）批量提交差分，初始化只在启动时执行一次，但接口设计与周期内更新保持一致。

片段 3：验收统计与判定

class AcceptanceStats:
    """验收批次统计：按口径记录周期结果并做放行判定。"""

    def __init__(self, target_success=0.95, min_cycles=100):
        self.records = []
        self.target = target_success
        self.min_cycles = min_cycles

    def record(self, kind, result, duration=None):
        # 每条记录携带结果与可选耗时；失败样本保留原因前缀供分解
        self.records.append({"kind": kind, "result": result,
                             "duration": duration})

    def judge(self):
        cycles = [r for r in self.records if r["kind"] == "cycle"]
        done = [r for r in cycles if r["result"] == "ok"]
        n = len(cycles)
        report = {"cycles": n}
        if n < self.min_cycles or n == 0:
            # 样本不足直接判为不通过：拒绝小样本结论（第 091 章口径）
            report.update({"pass": False, "reason": "样本不足"})
            return report
        success = len(done) / n
        durations = sorted(r["duration"] for r in done if r["duration"])
        median = durations[len(durations) // 2] if durations else None
        p95 = durations[min(len(durations) - 1,
                            int(0.95 * len(durations)))] if durations else None
        report.update({"success": success, "median_s": median, "p95_s": p95})
        report["pass"] = (success >= self.target and p95 is not None
                          and p95 <= 35.0 and median is not None
                          and median <= 25.0)
        return report

解读：验收统计把指标表变成放行判定。设计要点：（1）失败记录保留原因前缀，判定之外还能按模块分解失败；（2）成功样本才计入时长分位数，同时显式报告失败率，偏置可见（第 091 章）；（3）样本不足直接拒绝，不允许用小样本宣称达标；（4）阈值与指标表一一对应，修改指标时同步修改判定。轨迹时长与规划时间两套指标可复用同一结构，扩展口径时只需增加字段。

常见坑

  • 跳过降级路径直接验收：只测顺利场景，异常注入阶段缺失，验收通过后现场频繁中断。修复：联调五阶段不可跳过，异常注入列为验收必做项。
  • 只在单物体场景验证：多物体遮挡与顺序选择未测，编排的物体选择逻辑缺陷在验收时暴露。修复：任务集覆盖单物体、多物体与遮挡样本。
  • 验收无统计口径：用一次演示的成功与否代替批次统计，结论不可复现。修复：批次运行加固定任务集与批次标识记录，按指标表判定。
  • 忽略安全项验收：限速触发与急停链路未做注入测试，安全机制停留在配置层面。修复：安全项逐条注入验证并记录触发结果与停止距离。
  • 参数多变量同调：同时改速度、预算与算法，指标变化后无法归因。修复：单变量修改加对照批次，基线机制贯穿始终。

  2. 计算成功率预算：感知 0.96、规划 0.97、执行 0.985，基础成功率约多少？若恢复后各环节等效成功率提升到 0.995，整体为多少？对比说明恢复设计对验收指标的意义。★★
    提示
    基础约 0.917；恢复后约 0.985；同样指标下，恢复设计把验收从"勉强达标"推到"余量充足"。
  3. 设计异常注入清单：至少覆盖感知失败、规划失败、执行失败与安全触发四类，每类给出注入方式与预期恢复路径。★★
    提示
    感知：移走目标或遮挡；规划：临时放置障碍；执行：断流或控制器拒绝；安全：触发限速与急停并测量停止距离。
  4. 改设计并预测：把容器从三块薄壁改为完整盒体，放置阶段的规划成功率与失败原因分布如何变化？给出参数修正方向。★★
    提示
    盒体内腔形成受限空间，放置解的可达约束变强，成功率下降、目标碰撞类失败上升；修正方向是放宽放置容差与调整接近方向。
  5. 设计项目的演进路线：从单臂单工位扩展为双工位共享容器，列出需要新增的模块、改变的接口与新增的验收项。★★★
    提示
    新增跨臂镜像或统一模型、区域互斥锁与调度（第 089 章）；接口增加工位参数；验收增加共享区安全项与双工位吞吐指标。

小结

  • 综合系统按五层组织：感知、场景、规划、执行、编排，外加恢复、安全与统计三条支撑线。
  • 验收指标必须带统计口径与样本量要求，失败原因按阶段分解，安全项以注入测试为准。
  • 联调五阶段逐级引入复杂性，异常注入与长时运行属于验收必做项。
  • 参数调整遵循单变量加对照批次，任务周期边界执行轻量复位，维持长期稳定。
  • 全课程回顾：第一篇建立模型与接口的地基（001–018）；第二篇以场景为规划的世界观（019–038）；第三篇按任务几何选择算法与求解器（039–060）；第四篇用任务语义塑造运动形态（061–078）；第五篇以集成与维护把系统从"能跑通"推进到"能久跑"（079–100）。
