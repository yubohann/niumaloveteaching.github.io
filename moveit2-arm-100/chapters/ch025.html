第二篇 · 规划场景与碰撞管理

第 025 章：附加物体到机械臂

抓起来的东西从此属于机器人：本章讲附加（Attach）机制如何把工件从世界迁入机器人状态，位姿为什么相对挂载连杆解析，touch_links 如何决定允许接触的连杆集合，以及带载规划与验证的完整流程。

  • 主题：抓取场景管理 / 附加物体
  • 关键机制：附加体（AttachedBody）、挂载连杆与相对位姿、允许接触矩阵（ACM）联动
  • 预计学时：50 分钟
  • 前置章节：第 024 章

学习目标

  • 理解附加机制要解决的问题：让被夹持物体随末端运动学链一起运动，并作为机器人状态的一部分参与碰撞检测。
  • 掌握 AttachedCollisionObject 消息的核心字段：挂载连杆、相对位姿、允许接触集合、携带几何，以及附加动作的触发方式。
  • 能正确计算"抓取时刻物体相对挂载连杆的位姿"，并说明它与世界位姿的换算关系。
  • 会配置 touch_links 集合，理解它与允许碰撞矩阵（ACM）的联动及其安全含义。
  • 能设计带载规划流程：附加前校验、附加后验证、带载规划与执行前检查。

背景与动机

抓取动作完成的那一刻，工件（Payload）的物理归属发生了改变：夹爪闭合前，工件是环境里的独立物体，规划器要避免机器人碰到它；夹爪闭合后，工件与机器人刚性连接，会随末端一起运动，此时它与机器人之间、与路径上的障碍物之间的碰撞关系全部改变。如果规划场景不知道这次归属变化，会出现两种错误：一种是把已经抓住的工件仍然当作世界障碍，规划器拒绝一切会"碰到工件"的路径，抓取后的搬运直接无解；另一种是工件在场景中静止不动，规划器按旧位置评估碰撞，真机上工件随臂横扫的轨迹完全没有被检查。

附加（Attach）机制解决的就是这次归属转换。它与第 023 章的 MOVE 更新是两种思路：MOVE 要求外部系统持续同步物体位姿，任何一次同步缺失都会造成位置偏差累计；附加把物体直接并入机器人状态，位姿由运动学链推导，单一数据源、无同步延迟。抓取类任务的场景管理，核心就是把"世界物体"与"附加物体"两种状态在正确时刻切换。本章讲附加，下一章讲分离（Detach），两章合起来覆盖载荷的生命周期。

核心原理

1. 附加体：机器人状态里的新成员

附加操作把物体的几何、挂载连杆（Attach Link）与一个固定变换打包成附加体（AttachedBody），登记进机器人状态（RobotState）。登记之后，物体在世界中的位姿由运动学链实时推导，不再独立存储：

Tworld,payload(t) = Tworld,link(q(t)) · Tlink,payload q(t) 为当前关节向量；Tlink,payload 在附加时一次确定，之后保持不变

这个公式说明附加的三个性质。（1）随动性：机器人的任何关节运动自动反映到物体位姿，外部无须同步。（2）刚性：Tlink,payload 在附加期间恒定，等价于假设夹持没有相对滑动，工程上需要夹具与工件共同保证这一点。（3）状态一体化：碰撞检测、轨迹验证、状态有效性检查都会把附加体纳入计算，带载轨迹的碰撞判断与空载轨迹走同一条验证路径。

2. 消息字段与相对位姿语义

附加操作由附加碰撞物体消息（AttachedCollisionObject）承载，它在普通碰撞物体的基础上增加了四个字段：

字段作用语义要点
link_name挂载连杆物体随该连杆运动；名称必须与 URDF/SRDF 中的连杆一致
object被附加的碰撞物体其 pose 在挂载连杆坐标系下解析；operation 取 ADD 表示附加动作
touch_links允许接触的连杆集合决定附加体与哪些连杆的碰撞对被豁免
detach_posture分离姿态（铰接物体）可动部件（如抽屉）在分离时恢复的关节构型，普通刚性工件留空
weight重量标注供任务层使用，规划器的运动学计算不消费该字段

位姿语义是附加机制最容易出错的点：消息里的物体位姿相对挂载连杆解释，而世界物体的位姿相对 header 给出的参考系解释。从世界迁入的换算关系为：

Tlink,payload = Tworld,link-1 · Tworld,payload 抓取瞬间计算一次即可；之后物体的世界位姿随关节运动导出

把世界位姿原样填入附加消息，是最常见的字段级错误：物体在被抓取的位置之外"多飞一次"，轻则显示异常，重则在附加瞬间产生深度碰撞导致规划完全失败。

3. 几何来源与"世界清理"

附加消息处理时分两种情况。消息携带几何（解析形状、网格或平面）时，直接用该几何构建附加体；消息未携带几何时，处理逻辑到世界里查同标识物体，取用其几何。两条路径有一个共同动作：世界中的同名物体在附加成功后会被移除，保证同一份几何在场景中只存在一次，避免"世界一份加附着一份"造成的重复碰撞体与假阳性检测。这一行为也解释了感知节点与抓取流程的协作要求：感知重建若在下个周期把同名世界物体重新加回场景，会立即产生重复几何，抓取流程必须把自己管理的标识告知感知侧并请求排除（第 034 章展开）。

4. touch_links 与允许碰撞矩阵

夹爪抓住工件时，工件与手指在物理上必然接触，碰撞检测若一视同仁会把抓取状态判为自碰撞，所有带载规划都会失败。解决方案是允许碰撞矩阵（Allowed Collision Matrix, ACM）：一张记录"哪对连杆（或物体）之间可以接触"的表，附加操作会为附加体与 touch_links 中列出的连杆建立豁免项。默认行为是只允许附加体与挂载连杆本身接触；夹爪双指抓取的场景必须把两个手指连杆都列入 touch_links，漏掉任何一指都会在附加后立刻触发自碰撞报告。反向的失误同样危险：把整条机械臂的连杆都列入集合，会让载荷与臂杆的穿透彻底失去检测能力。集合按"接触在物理上必然发生"的原则给出，范围尽量小。

5. 对规划与执行的影响

附加完成后，规划请求的起始状态包含附加体，规划器在所有采样状态上对"机器人加载荷"整体做碰撞判断：载荷会绕过障碍物，载荷自身与世界的碰撞也被检查。带载规划的正确性由此从"假设"变成"验证过的性质"。执行环节需要注意两点：其一，机械臂控制器并不知晓附加体的存在，物体真正被夹住依赖夹具动作的真实完成，规划层面的附加必须与夹具闭合时序对齐，抢在夹紧之前附加会让带载轨迹的起点与物理现实不符；其二，部分碰撞检测器对附加体的连续碰撞检测（扫掠检测）支持有限，带载轨迹在启用连续检测时应通过实机或高保真仿真实测确认，不能仅凭离散采样点通过就放行。

实现思路与设计

把附加接入抓取任务的标准流程：

  1. 确定接触面清单：从夹具结构出发列出必然接触的连杆（手指、吸盘座），形成 touch_links 模板，按夹持类型分档维护。
  2. 计算相对位姿：抓取执行到达目标位姿后，读取当前挂载连杆位姿与工件世界位姿，按换算公式得到 Tlink,payload。
  3. 发送附加：构造 AttachedCollisionObject，位姿填相对值，几何可随消息携带或引用世界对象，操作取 ADD。
  4. 验证附加：读取机器人状态中的附加体清单，核对标识、挂载连杆与接触集合。
  5. 带载规划：按常规流程规划到放置目标；起始状态必须取自附加生效后的快照（第 021 章的状态纪律在此再次生效）。
  6. 时序对齐：附加动作安排在夹具确认夹紧之后；为夹具反馈设计超时分支，超时未夹紧则撤销本次附加。

配置项示例值作用取值依据

关键代码与解读

片段 1：C++ 构造并提交附加（接口以对应 ROS2 发行版与 MoveIt2 版本的官方文档为准）

// 附件的几何与位姿随消息携带；相对位姿在发送前换算完成
moveit_msgs::msg::AttachedCollisionObject attach;
attach.link_name = "gripper_base";                 // 挂载连杆：附加体的运动基准
attach.object.id = "part_a";                       // 沿用夹持目标在世界中的标识
attach.object.header.frame_id = "gripper_base";    // 位姿在该连杆坐标系下解析
attach.object.pose = link_to_part;                 // T_{link,payload}，抓取时刻换算
attach.object.primitives.resize(1);
attach.object.primitives[0].type = shape_msgs::msg::SolidPrimitive::CYLINDER;
attach.object.primitives[0].dimensions = { 0.02, 0.1 };   // 半径 2 cm、高 10 cm
attach.object.primitive_poses.resize(1);
// 允许接触：只列入手指两根连杆；挂载连杆本身默认允许接触
attach.touch_links = { "finger_left", "finger_right" };
// 操作字段取 ADD：语义为"把物体附加到机器人"
attach.object.operation = moveit_msgs::msg::CollisionObject::ADD;
// 世界中的同名物体会被自动移除，避免同一几何在场景中出现两份
psi.applyAttachedCollisionObject(attach);

解读：（1）frame_id 与位姿在概念上必须自洽：frame_id 指明解释基准，pose 是相对该基准的值，两者一起表达 Tlink,payload；把世界位姿填进来而 frame_id 又写连杆名，会得到错误变换叠加的物体。（2）实现代码显式设置 primitive_poses 的尺寸，与 primitives 一一对应，这是第 024 章平行数组纪律在附加消息上的延续。（3）注释点明"世界中同名物体自动移除"，这与感知侧的去重协作直接相关；抓取流程若发现世界侧同名物体被重新加回，应视为上游数据冲突并上报，避免静默继续。

片段 2：Python 经话题提交附加

import rclpy
from rclpy.node import Node
from geometry_msgs.msg import Pose
from moveit_msgs.msg import AttachedCollisionObject, CollisionObject
from shape_msgs.msg import SolidPrimitive

class GripperAttacher(Node):
    """把刚夹紧的工件从世界迁入机械臂状态。"""

    def __init__(self):
        super().__init__("gripper_attacher")
        # MoveGroup 订阅该话题处理附加与分离动作
        self.pub = self.create_publisher(
            AttachedCollisionObject, "/attached_collision_object", 10)

    def attach_cylinder(self, object_id, link_to_part):
        msg = AttachedCollisionObject()
        msg.link_name = "gripper_base"     # 挂载连杆
        # 允许接触集合：物理上必然接触的连杆都要列入
        # 漏掉任一手指，附加后第一次碰撞检查就会报自碰撞
        msg.touch_links = ["finger_left", "finger_right"]
        part = CollisionObject()
        part.id = object_id
        # 位姿在挂载连杆坐标系下解析；填世界位姿会让附加体飞到远处
        part.header.frame_id = "gripper_base"
        part.pose = link_to_part           # T_{link,payload}
        prim = SolidPrimitive()
        prim.type = SolidPrimitive.CYLINDER
        prim.dimensions = [0.02, 0.1]      # 半径在前、高度在后
        part.primitives = [prim]
        part.primitive_poses = [Pose()]
        part.operation = CollisionObject.ADD    # 附加动作
        msg.object = part
        self.pub.publish(msg)

解读：（1）把"抓取时刻相对位姿"作为函数入参传入，促使调用方在抓取位姿仍在手边时完成换算，降低时序错误概率。（2）几何随消息携带，附加路径不依赖世界对象是否存在，适合工件由感知即时识别、从未建档的流程。（3）话题路径无回执，发送后必须经验证环节确认；对可靠性要求高的抓取循环，可改用带返回值的接口封装或服务路径。

片段 3：C++ 以只读场景锁验证附加结果

// 只读锁：拿场景快照做验证，不阻塞场景更新线程
planning_scene_monitor::LockedPlanningSceneRO scene(planning_scene_monitor);

// 从当前状态取附加体清单，核对标识与挂载位置
std::vector<const moveit::core::AttachedBody*> bodies;
scene->getCurrentState().getAttachedBodies(bodies);
for (const moveit::core::AttachedBody* body : bodies)
{
  RCLCPP_INFO(node->get_logger(), "附加体 %s 挂载于 %s，接触集合 %zu 项",

              body->getAttachedLinkName().c_str(),
              body->getTouchLinks().size());
}
// 验证通过后再进入带载规划；规划起点自动包含附加体

解读：（1）只读锁（LockedPlanningSceneRO）提供一致性视图：验证期间场景不会在脚下变化，读到的附加体清单与随后用于规划的快照同源。（2）核对三要素（标识、挂载连杆、接触集合规模）覆盖了附加操作最常见的一类错误：消息发错连杆或接触集合漏项。（3）验证放在附加与带载规划之间作为门禁，失败时可以让流程回退到"重新夹紧"或"中止搬运"，把错误拦截在一次动作之内。

常见坑

  • 把世界位姿填进附加消息：物体在附加瞬间"跳"到世界姿态与连杆姿态的叠加位置，通常伴随深度碰撞与规划失败。修复是发送前按换算公式计算 Tlink,payload，并在验证环节抽查位姿分量。
  • touch_links 漏掉手指：附加成功，但第一次碰撞检查就报附加体与手指碰撞，带载规划全部失败。修复是把夹具接触面清单固定成模板，按夹持类型整组引用。
  • touch_links 范围过宽：为图方便把整条臂的连杆列入，载荷与前臂的穿透不再被检测，真机上夹持松动时直接发生刮蹭。修复是按物理接触事实逐项评审，范围只放必然接触的连杆。
  • 附加先于夹紧：规划层面的附加抢在夹具闭合之前，带载轨迹的起点与物理现实不符，起始状态检查可能因工件仍在世界而报碰撞。修复是把附加动作放在夹具夹紧反馈之后，并为反馈设计超时撤销分支。
  • 世界物体被重复加回：感知或任务脚本在下一周期重新添加同标识物体，场景中出现"世界一份加附着一份"。症状是物体显示重影、检测出现假碰撞。修复是建立标识归属约定，附加期间该标识由抓取流程独占（第 034 章的融合章节展开去重机制）。

练习与思考

  1. 换算练习：抓取时刻工件世界位姿为位置 (0.5, 0.0, 0.3)（姿态单位旋转），挂载连杆世界位姿为位置 (0.4, 0.0, 0.2)（姿态单位旋转）。写出附加消息中应填的相对位姿，并说明若直接填世界位姿会发生什么。★
    提示
    相对位置为两向量之差 (0.1, 0.0, 0.1)。直接填世界位姿等于把连杆变换叠加两次，附加体显示位置约在 (0.9, 0.0, 0.5) 附近，通常落在工作空间之外或与臂身相交。
  2. 参数预测：触摸连杆集合从 {finger_left, finger_right} 缩小到 {finger_left}。附加后立即做一次碰撞检查，判断会报出什么；再把集合扩大到全部臂连杆，第二次检查的结果又会掩盖什么风险？★
    提示
    缩小后附加体会与 finger_right 判为碰撞，检查必然失败；扩大到全臂后载荷与臂杆的穿透被豁免，松动或装配偏差下的刮蹭不再被检出，属于安全倒退。
  3. 设计题：为"抓取-搬运-放置"任务画出附加与分离的时序图，标出夹具动作、附加、带载规划、执行四个环节的先后关系，并说明两处失败分支（夹紧超时、附加验证失败）的处置。★★
    提示
    时序为：接近规划、下降、夹紧、夹紧反馈确认、附加、验证、带载规划、执行到放置、分离（第 026 章）、撤离。夹紧超时撤销本次任务；附加验证失败回退到重新夹紧。
  4. 诊断题：附加操作后规划器报告起始状态自碰撞，列出至少三种原因与排查顺序。★★
    提示
    优先查 touch_links 是否覆盖全部接触连杆；其次查相对位姿是否正确（错误的变换会让工件穿进指爪）；再看附加体几何尺寸是否与真实工件一致，尺寸偏大会覆盖到手指空间。
  5. 分析题：比较"持续用 MOVE 同步工件世界位姿"与"附加到连杆"两种方案在搬运阶段的差异，从数据来源、同步缺失的后果、碰撞检查一致性三个角度论述，并给出各自更适合的场景。★★★
    提示
    MOVE 方案依赖外部位姿流，适合非抓取的联系型操作（推、贴合）或物体不由夹爪固定的场合；附加方案位姿由运动学推导，无同步延迟，适合刚性夹持搬运。同步缺失在 MOVE 方案中表现为位置偏差累计，在附加方案中不存在，但附加方案要求夹持刚性成立。

小结

  • 附加把工件并入机器人状态：位姿由运动学链实时推导，带载碰撞检查与空载走同一验证路径。
  • 附加消息的位姿在挂载连杆坐标系下解析，相对位姿由抓取时刻的世界位姿换算得到。
  • touch_links 决定允许接触集合，默认仅挂载连杆；漏项导致假自碰撞，过宽则丢失真实碰撞检测能力。
  • 世界物体在附加成功后自动移除，感知与任务流程需要标识归属约定避免重复几何。
  • 下一章处理反向过程：分离附加物体，让载荷在放置点回到世界，完成生命周期闭环。
