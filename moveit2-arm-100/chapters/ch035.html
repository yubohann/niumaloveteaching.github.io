第二篇 · 规划场景与碰撞管理

第 035 章：路径约束

把任务语义写进规划问题：本章讲目标约束与路径约束的分工、约束可行集的流形结构、采样投影的牛顿迭代与切空间分解，以及约束施加、清除、复核的完整流程。

  • 主题：运动学约束 / 规划请求约束
  • 关键机制：约束流形与可行集、投影采样、约束的请求级生命周期
  • 预计学时：55 分钟
  • 前置章节：第 034 章

学习目标

  • 分清目标约束（Goal Constraints）与路径约束（Path Constraints）的作用域差异，知道什么任务要求应当施加在哪一类。
  • 理解约束在配置空间中的几何含义：可行集是自由空间与约束流形的交，交集为空时任何规划器都无解。
  • 掌握投影采样的原理：牛顿迭代把采样点拉回流形，切空间分解说明流形方向的自由度。
  • 会完整执行约束的施加、规划、清除、复核四步流程，避免约束泄漏到后续任务。
  • 能诊断约束引起的规划失败：空集、容差失配、参考系解析失败三类成因与验证手段。

背景与动机

避障规划只回答"能否无碰撞地到达"，任务语义还包含额外的几何要求：焊接时工具要保持在接缝所在的平面上，浇注时壶口方向要维持竖直，扫描时末端要沿一条直线平动。这些要求不能只落在终点上，它们描述的是"轨迹全程的姿态纪律"。规划请求为此提供两类约束槽位：目标约束只参与终点投影，路径约束作用于每一个被规划器考虑的状态。

约束把规划问题从"在自由空间找一条路"变成"在自由空间与约束曲面的交集中找一条路"。交集越小，问题越难；交集为空，问题无解。约束设计的本质是在"任务表达的精确性"与"可行集的体积"之间取舍：过宽等于没约束，过紧会让规划器耗尽预算。本章讲这条曲线的数学结构与工程流程，第 036、037 章分别展开位置方向约束与关节可见性约束的具体构造。

核心原理

1. 两类约束：作用域决定一切

规划请求（MotionPlanRequest）携带两组约束。目标约束（goal_constraints）是一组可替换的目标区域，规划器把终点投影到其中；路径约束（path_constraints）则在规划过程中作用于每个候选状态，任何不满足它的状态都被视为无效，与碰撞状态同级处理。两者的差异可以用一句判据概括：要求"到达时成立"的写进目标约束，要求"全程成立"的写进路径约束。

维度目标约束路径约束
作用范围轨迹终点轨迹全程的每个状态
规划器用法目标采样与投影状态有效性判定的一部分
不满足的后果终点候选被丢弃状态被判无效，路径发散
典型例子末端到达指定位姿区域工具始终保持竖直、末端沿直线运动

把全程要求误写进目标约束是常见错误：规划器只保证终点满足，中途姿态完全自由，执行时才发现工具撞上工装或方向失控。

2. 可行集与约束流形

每条约束在配置空间中划出一个可行子集：关节约束是箱体，位置约束是末端位置落入空间区域的构型集合，方向约束是姿态落入容差集合的构型集合。全部约束的交集与自由空间进一步相交，构成规划真正搜索的可行集：

Cfeas = Cfree ∩ { q | Φi(q) ∈ Bi，∀ i } Φi 为第 i 条约束的映射（如末端位置），Bi 为其允许区间；交集为空意味着无解

把约束写成近似等式时，可行集退化为低维曲面，称为约束流形。维数账本可以快速估计难度：六轴机械臂固定末端位置（三个等式）后，流形维数从 6 降到 3，这三个剩余自由度称为自运动自由度；再固定末端方向（三个等式）后维数为 0，可行集退化为孤立的构型点（或小容差球）。维数越低，满足约束的构型在空间中越稀疏，采样命中的概率越低，规划时间随之上升。

3. 投影与切空间：流形上的采样机制

采样规划器需要在流形上产生候选点。直接在整个配置空间采样再检查约束的命中率随维数骤降，标准做法是先采样、再投影：从流形附近的随机点出发，用牛顿类迭代把约束残差压到容差之内。对约束函数 Φ（向量值），投影的一步迭代为：

q ← q - JΦ(q)+ Φ(q) JΦ+ 为雅可比矩阵的伪逆；在奇异或病态处步长变大，需要阻尼与步数上限

迭代收敛后，点位于流形上；沿流形的运动方向由切空间刻画。把任意速度向量投影到切空间用同一个雅可比完成：

vtangent = ( I - JΦ+ JΦ ) v 括号内为投影矩阵：剔除违反约束的速度分量，保留流形方向

规划器在流形上扩展路径时沿切空间方向生长，再对新点做投影修正，两者配合形成"扩展、拉回"的循环。这条机制解释了约束规划的性能特征：每次采样额外付出雅可比计算与迭代投影的代价，流形越薄收敛越慢，接近奇异时迭代可能不收敛而丢弃该采样。

4. 约束的构造与请求生命周期

MoveIt 把约束消息转换成内部可判定的约束集合，转换过程需要解析各约束携带的参考系（通过当前变换信息），随后规划器的约束采样器据此工作。请求级生命周期有四个动作：

  1. 构造：填写约束消息（各分量的字段结构在第 036、037 章展开），参考系与连杆名与实际场景一致；
  2. 施加：把约束装入规划请求的对应槽位；使用高层接口时按其接口语义设置；
  3. 复核：规划完成后对结果轨迹逐状态核对约束满足情况（规划器内部检查存在采样近似）；
  4. 清除：任务结束后清空约束槽位。高层接口里约束是持久状态，忘记清除会让下一条无关任务也背着它规划。

容差的取值是本节最重要的工程判断：容差代表"任务可接受的偏差"，通常由工艺公差给出，再叠加标定与建模误差。把容差减去误差后剩余的空间就是规划器的搜索余地；余地为负时应当先改工艺或改标定，避免只调规划参数。

5. 与相邻功能的边界

约束与三样东西容易混淆，划清边界能减少误用。（1）与碰撞：约束不承担安全机制职责，碰撞检测独立进行；用容差覆盖障碍属于错误用法（第 028 章）。（2）与后处理：平滑与捷径化在约束问题中必须尊重流形，部分管线的平滑步骤对约束支持有限，规划成功不等于平滑后仍满足约束，复核步骤不可省略。（3）与执行：约束保证的是规划结果的性质，执行期的伺服跟随误差由控制器负责；把约束容差设计成控制误差的上界是常见的过度设计，两者应分别预算。

实现思路与设计

引入路径约束的标准流程：

  1. 从工艺公差出发：把任务要求翻译为约束类型与容差（哪些自由度受限、各允许多大偏差），形成约束清单。
  2. 校验可达性：用正逆运动学验证约束流形与工作空间的交集非空，至少找到两个可用构型（起点与目标附近的实例）。
  3. 构造消息：按约束类型填写字段，统一参考系为稳定世界系，逐个核对连杆名。
  4. 施加与规划：装入请求槽位，先做不带约束的对照规划，确认差异符合预期。
  5. 复核结果：逐状态核对约束满足与碰撞有效性；两项都过才进入执行。
  6. 清除与回归：任务结束立即清除约束；把该约束任务纳入回归集，防止后续配置变更破坏可行集。

约束设计要点

项目常用取值说明
位置容差任务公差加 2–5 mm 余量过小使流形过薄，规划失败率上升
方向容差任务公差加 0.5°–2°方向约束对流形体积影响显著（第 036 章）
目标约束用容差可按工艺收紧只影响终点，对全程搜索压力小
投影迭代上限规划器内部参数收敛慢的采样被丢弃，表现为成功率下降
复核采样率轨迹全量或高密度抽样约束满足是任务性质，建议全量核对

关键代码与解读

片段 1：C++ 施加路径约束并规划、清除（接口以对应 ROS2 发行版与 MoveIt2 版本的官方文档为准）

// 路径约束：整条轨迹全程都要满足；本次示例限制工具点保持在一个薄板区域内
moveit_msgs::msg::Constraints path_cs;
path_cs.name = "slide_along_top";     // 命名便于日志识别与回归对照

moveit_msgs::msg::PositionConstraint pc;
pc.header.frame_id = "world";         // 约束区域在世界系中定义
pc.link_name = "tool0";               // 受约束的连杆（工具点所在连杆）
pc.target_point_offset.x = 0.0;       // 相对连杆原点的偏置，这里取连杆原点
pc.constraint_region.primitives.resize(1);
pc.constraint_region.primitives[0].type =
    shape_msgs::msg::SolidPrimitive::BOX;
// 薄板区域：允许沿 x 与 y 平移，z 方向仅留 2 cm 裕量
pc.constraint_region.primitives[0].dimensions = { 0.6, 0.2, 0.02 };
pc.constraint_region.primitive_poses.resize(1);
pc.constraint_region.primitive_poses[0].position.x = 0.5;
pc.constraint_region.primitive_poses[0].position.y = 0.0;
pc.constraint_region.primitive_poses[0].position.z = 0.4;
pc.constraint_region.primitive_poses[0].orientation.w = 1.0;
pc.weight = 1.0;                      // 约束权重；位置与方向约束的分量展开见第 036 章
path_cs.position_constraints.push_back(pc);

move_group->setPathConstraints(path_cs);          // 装入请求槽位
moveit::planning_interface::MoveGroupInterface::Plan plan;
bool ok = (move_group->plan(plan) == moveit::core::MoveItErrorCode::SUCCESS);
move_group->clearPathConstraints();              // 任务语义结束立即清除

if (!ok)
{
  // 失败常见来源：可行集为空、容差过紧、参考系解析失败（见常见坑）
  RCLCPP_WARN(node->get_logger(), "路径约束下规划失败，检查可行集");
}

解读：（1）约束区域在世界系中定义、绑定了连杆名与偏置，三要素缺一不可；区域形状（这里是薄板盒）决定受限的平移自由度，z 方向 2 cm 的厚度就是位置容差。（2）setPathConstraints 之后的每次规划都自动携带该约束，直到显式清除；高层接口的约束是会话级状态，把清除动作紧跟规划放置，是避免约束泄漏最直接的结构化手段。（3）失败分支注释列出三类主要成因，与本章理论与常见坑两节的排查条目一一对应，让日志信息直接指向下一步动作。

片段 2：Python 牛顿投影把采样点拉回约束流形

import numpy as np

L1, L2 = 0.4, 0.3                     # 平面二连杆臂的杆长

def tip(q):
    """正向运动学：返回末端位置（二维）。"""
    q1, q2 = q
    return np.array([L1 * np.cos(q1) + L2 * np.cos(q1 + q2),
                     L1 * np.sin(q1) + L2 * np.sin(q1 + q2)])

def constraint(q, radius=0.55):
    """等式约束：末端落在半径 0.55 m 的圆上（g=0 时为流形上的点）。"""
    return np.linalg.norm(tip(q)) - radius

def numeric_jacobian(q, h=1e-6):
    """数值雅可比：真实系统使用解析或自动微分版本。"""
    J = np.zeros(2)
    for i in range(2):
        dq = np.zeros(2)
        dq[i] = h
        J[i] = (constraint(q + dq) - constraint(q - dq)) / (2 * h)
    return J

q = np.array([0.9, -0.4])             # 一个靠近但不在流形上的采样点
for step in range(5):
    g = constraint(q)
    J = numeric_jacobian(q)
    q = q - J * g / (J @ J)           # 标量约束的最小二乘投影一步
    print(f"第 {step + 1} 次迭代：残差 {abs(g):.2e}，"
          f"构型 ({q[0]:.3f}, {q[1]:.3f})")

解读：（1）投影迭代把"任意采样点"变成"满足约束的采样点"，这是约束采样器的最小内核；示例用等式约束（末端在圆上），不等式约束（区域内容差）在残差量化后复用同一套迭代。（2）残差按步数指数下降，两三次迭代即到数值精度；真实规划每次采样都付这份代价，约束规划的额外开销正来源于此。（3）当雅可比接近退化（末端处于奇异构型附近）时，J · J 接近零，步长放大且方向失准，工程实现加入阻尼与步数上限，用丢弃该采样为代价保住数值稳定。

片段 3：C++ 规划结果逐状态复核约束

// 独立复核：规划器内部的约束检查带采样近似，任务性质要求全量核对
kinematic_constraints::KinematicConstraintSet kset(robot_model);
kset.add(path_cs, planning_scene->getTransforms());

std::size_t violations = 0;
for (std::size_t i = 0; i < trajectory.getWayPointCount(); ++i)
{
  // decide 返回该状态是否满足全部约束；细节可另取向量展开
  kinematic_constraints::ConstraintEvaluationResult r =
      kset.decide(trajectory.getWayPoint(i));
  if (!r.satisfied)
  {
    ++violations;
    RCLCPP_WARN(node->get_logger(), "路点 %zu 不满足约束", i);
  }
}
RCLCPP_INFO(node->get_logger(), "%zu 个路点，违规 %zu 个",
            trajectory.getWayPointCount(), violations);

解读：（1）复核使用与规划独立的判定路径：约束集合从消息重建（参考系按当前变换解析），避免"规划器说满足就满足"的单点信任。（2）逐状态核对的成本与路点数线性，长轨迹可按固定间隔抽样、对靠近边界的抽样点加密；违规点索引同样为可视化复查服务（与第 029 章的路径校验形成对照）。（3）复核不替代规划内检查：前者面向任务验收，后者服务搜索过程；两层都保留，能区分"实现偏差"与"任务设计问题"。

常见坑

  • 全程要求写进目标约束：工具保持竖直的纪律只约束了终点，中途任意倾斜，执行时工件被撞。修复是按第 1 小节的判据重新分类，把"全程成立"的要求移入路径约束槽位。
  • 约束交集为空：位置区域与方向容差在工作空间内找不到共同的可用构型，规划必然失败且与尝试次数无关。修复是用正逆运动学预检可行集，逐步放松一条约束并复测，把"哪条约束制造了空集"定位出来。
  • 约束泄漏到后续任务：高层接口的约束是持久状态，完成后未清除，下一条任务的规划莫名变慢或失败。修复是把清除与规划成对放置，并在任务开始时显式清空约束槽位作为防御。
  • 参考系解析失败：约束区域挂在临时参考系或拼写错误的参考系上，约束无法解析、被忽略或直接失败。修复是统一使用稳定世界系，核对参考系名称存在且在变换树中可达。
  • 复核只信规划器：规划内部检查在采样点之间不做判定，路点之间的短段可能短暂越界。修复是复核阶段对轨迹加密采样（或按最短段长度补充检查点），把越界拦截在执行之前。

练习与思考

  1. 分类练习：把以下要求分别归入目标约束或路径约束。（a）末端到达工件上方 5 cm；（b）整个冲压过程中末端不离开垂直平面；（c）最终姿态与装配面平行；（d）手腕在全程保持在线缆弯曲允许范围内。★
    提示
    （a）目标（到达时成立）；（b）路径（全程成立）；（c）目标（终态性质）；（d）路径（全程成立，手腕相关的关节级约束见第 037 章）。
  2. 维数计算：六轴机械臂固定末端位置（3 个等式）后，约束流形的维数是多少？再固定末端方向后维数是多少？据此解释"位姿全约束问题为什么最难规划"。★
    提示
    固定位置后流形维数 3（自运动），再固定方向后为 0（孤立构型或小容差球）。维数越低，采样命中概率越小，规划失败率与耗时随之上升。
  3. 设计题：为"沿 0.5 m 长的水平接缝匀速焊接"设计约束集合：给出位置区域、方向容差的量级与参考系选择，并说明为什么这条任务适合路径约束。★★
    提示
    接缝定义细长区域（宽数毫米、长为缝长），方向容差取工艺公差加 1° 以内；任务要求全程维持，属于路径约束；参考系取工件或世界系中稳定者。注意匀速属于轨迹参数化问题（第 039 章），不属于运动学约束。
  4. 诊断题：同一条紧容差约束任务，目标位姿单独可达、约束单独可行，但搭在一起规划必失败。给出两种最可能原因与验证方法。★★
    提示
    原因一：可行集交集为空（目标姿态不在流形可达范围内），用逆运动学在目标附近采样验证；原因二：流形过薄导致采样命中率极低，放松一条容差后成功率恢复即为佐证。两类都在第 2 小节的维数账本里有对应解释。
  5. 分析题：比较"在配置空间采样后投影"与"在任务空间采样后逆解"两种约束采样路线，从奇异构型、解的分支选择、成功率三个角度分析，并给出两种路线混用的系统设计。★★★
    提示
    配置空间投影路线天然覆盖自运动自由度，但近奇异时投影不稳；任务空间加逆解路线直接控制末端，但受解分支与可达性限制。混用方案：任务空间采样产生种子、配置空间投影维护流形，奇异附近回退冗余自由度利用（第 056 章展开）。

小结

  • 目标约束作用于终点，路径约束作用于全程，任务要求按"何时成立"分类后入对应槽位。
  • 约束把可行集收紧为自由空间与约束流形的交集，维数账本可快速估计规划难度，交集为空时任何规划器都无解。
  • 流形采样靠"扩展加投影"循环：牛顿迭代压残差，切空间投影管方向，近奇异处需要阻尼与步数控制。
  • 约束的会话级生命周期按构造、施加、复核、清除四步管理，清除缺失是最具迷惑性的工程错误。
