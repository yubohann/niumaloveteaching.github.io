第二篇 · 规划场景与碰撞管理

第 037 章：关节约束与可见性约束

约束家族的收尾两类：关节约束用对称或非对称的窗口选择构型与保护线缆，可见性约束用两个夹角条件维持"目标在传感器视野中"，本章讲字段语义、几何判定与组合设计。

  • 主题：运动学约束构造 / 构型与视野
  • 关键机制：关节窗口箱体、冗余姿态选择、可见性双角条件
  • 预计学时：50 分钟
  • 前置章节：第 036 章

学习目标

  • 掌握关节约束的字段结构与几何含义：单关节窗口是配置空间中的一维区间，多关节组合构成箱体。
  • 会利用非对称容差与部分关节约束解决冗余选择问题：肘部朝上朝下、腕部线缆保护、逆解分支锁定。
  • 掌握可见性约束的字段结构与双角判定：传感器光轴与目标方向的夹角、目标朝向与视线的夹角。
  • 能指出可见性约束的能力边界：它做角度几何判定，不承担遮挡检测。
  • 能设计"任务约束加关节约束"的组合方案，在保持任务精度的同时控制构型自由度。

背景与动机

前两章处理任务空间的位置与方向要求，这一章补齐两类特殊约束。关节约束直接写在构型空间：它不关心末端在哪里，只要求某些关节落在指定窗口内。这类约束解决机械臂的"多解性问题"：同一个末端位姿通常对应多组关节构型（肘上肘下、腕翻转方向），任务空间约束对这些自由度完全无感，而工艺与硬件却对它们有明确要求。腕部线缆有弯曲角度上限、肘部不能侵入工装上方空间、某些构型接近奇异需要回避，这些纪律都用关节约束表达。

可见性约束来自感知类任务：操作过程中保持目标（焊缝、标定板、工件标记）处在传感器的视野里。它是运动学约束家族中唯一的"感知视角"成员，用两组夹角条件刻画"看得见"的几何含义。两类约束的共同点是把"任务之外的纪律"翻译成规划问题可以消费的形式；区别是前者作用于构型空间，后者连接了两个物体（传感器与目标）的姿态关系。本章之后，第 038 章用一次完整的感知驱动规划实践收束第二篇。

核心原理

1. 关节约束：配置空间中的区间与箱体

关节约束（JointConstraint）按关节逐条给出：关节名、中心位置、上下容差、权重。几何上每一条把一维构型轴限制在一个区间内：

qj ∈ [ position - tolerancebelow，position + toleranceabove ] 上下容差独立给出，允许构造非对称窗口，用于表达"偏差偏向某一侧更可接受"的设计意图

多条关节约束落在不同关节轴上，它们的组合构成配置空间中的一个箱体（各轴区间的乘积）。箱体与硬件关节限位再做交集，得到最终可行区间。非对称容差是一个实用武器：把容差偏向远离危险一侧，可以让规划器在窗口内自然远离奇异位形或干涉区域，比事后检查更省事。例如把腕部某关节的窗口设为"向正向留有 0.15 rad、向负向只留 0.05 rad"，规划器在窗口内扩展时就更少进入反向极限。

2. 冗余问题与部分关节约束

六自由度机械臂在只约束末端位姿时存在有限组逆解，七自由度机械臂则存在连续的自运动流形。关节约束在两类情形下的用法不同：

  • 离散多解的选择：对六轴臂，约束一两个关键关节即可排除不需要的解分支。典型是约束肘部关节的符号区间，实现"肘上"或"肘下"构型族的选择；约束腕部关节的窗口，锁定翻转方向。
  • 连续冗余的塑形：对七轴臂，部分关节约束把自运动流形切出一段，规划器在这段内优化其它指标（远离奇异、远离限位）。约束数量越多，箱体越窄，规划难度越高，超过一定数量后可行集接近孤立点，采样成功率骤降。

数量控制的经验规则是：只约束与任务语义直接相关的关节，其余保持自由；用"选择分支"为目的时约束一到两个关节即可，把全部关节都约束为固定值会退化为单点问题。关节约束的窗口宽度也要超过逆解计算与插值误差的量级，过窄的窗口会让本可用的解被数值误差排除在外。

3. 可见性约束：双角条件的几何含义

可见性约束（VisibilityConstraint）连接传感器与目标两个对象：目标用一个带半径的圆盘表示（中心位姿加目标半径），传感器用位姿、视轴方向与两个角度上限表示。判定条件由两个夹角构成：

条件一：angle( 视轴，从传感器指向目标中心的向量 ) ≤ max_range_angle
条件二：angle( 目标朝向，从目标指向传感器的向量 ) ≤ max_view_angle 条件一约束目标落在视野锥内；条件二约束观察方向与目标可观测面（朝向）的夹角

条件一解决"目标在不在视野里"：传感器视轴与目标方向夹角过大时目标落在视野之外。条件二解决"看到的面是否有效"：目标的朝向定义了一个可观测方向（如标定板的正面法向），观察点偏离该方向太远时即使目标在视野内，有效面也已背对传感器。两个条件同时满足才是工程意义上的"看得见"；把目标半径纳入表述后，条件一实际是对圆盘边缘的包络约束，实现中的等价处理是把半径换算成角度余量。换算示例：目标半径 rt = 0.04 m、标称观测距离 d = 0.4 m 时，圆盘边缘相对中心多占的角度为 arctan(rt/d) ≈ 0.100 rad（约 5.7°）；若 max_range_angle 配额为 0.5 rad，扣除边缘余量后留给运动跟踪的额度约 0.4 rad。

必须记住可见性约束的能力边界：它做的是传感器与目标之间的角度几何判定，不检测遮挡。机械臂自身臂段挡在传感器与目标之间时，角度条件仍然满足，约束不会报错。需要真实遮挡检查的系统必须用几何查询（第 027 章的距离查询思路在视线方向上的变体）自行补充，或让感知系统在运行期监视目标可见性。

4. 组合设计：任务精度与构型纪律的分工

把本章与第 035、036 章的约束放在一起，得到一个清晰的分工结构：任务空间约束（位置、方向）负责"末端在哪里、朝向如何"，关节约束负责"用哪组构型完成任务"，可见性约束负责"感知视角的维持"。组合时的预算原则：

  • 任务空间容差按工艺分配（第 036 章联合预算），这一部分不因关节或可见性约束而改变；
  • 关节窗口按硬件纪律分配（线缆、奇异、干涉），宽度取硬件限制与数值误差之和再加余量；
  • 可见性角度上限按传感器特性分配（视场角、有效观测角），并预留臂段可能自遮挡的裕量。

三类约束叠加时可行集是三重限制的交集，设计阶段应逐类单独验证可达性（只施加一类，确认有解），再叠加联调；叠加后的失败排查也按这个顺序逐类放松。这类"分而治之再合并"的流程，比直接面对全部约束猜测哪条出了问题高效得多。

实现思路与设计

两类约束的构造流程：

  1. 关节窗口清单：从硬件手册与工艺纪律列出需要受限的关节、窗口中心与上下容差，核对与软限位的关系。
  2. 选择约束数量：只保留必要的关节；以选择逆解分支为目的时优先约束肘部与腕部翻转关节。
  3. 标定可见性对象：确定传感器视轴（机身系下的方向）、目标中心位姿与可观测朝向，来源以标定为准。
  4. 设定角度上限：max_range_angle 按传感器视场角与安全余量取；max_view_angle 按有效观测角要求取。
  5. 分层验证：逐类约束单独规划确认有解，再叠加；叠加失败时按最后加入的约束优先放松。
  6. 运行期核对：可见性相关任务在执行期用感知系统核对目标实际可见性，把"角度满足"升级为"观测成立"。

约束取值要点

项目常用取值说明
关节窗口上下容差0.05–0.3 rad（对称或非对称）低于数值误差的量级会让可用解被排除
受约束关节数量1–2 个（冗余选择）过多约束使可行集退化为孤立点
max_range_angle0.3–0.6 rad（按视场角）预留目标半径与跟踪误差的余量
max_view_angle0.5–1.0 rad（按有效观测角）依传感器手册与工艺要求设定
目标半径按目标真实尺寸参与条件一的边界余量换算

关键代码与解读

片段 1：Python 构造关节约束并按用途分组（消息结构以对应发行版的 moveit_msgs 定义为准）

from moveit_msgs.msg import Constraints, JointConstraint

def joint_window(name, position, above, below, weight=1.0):
    """单关节窗口：上下容差独立，可构造非对称区间。"""
    jc = JointConstraint()
    jc.joint_name = name
    jc.position = position
    jc.tolerance_above = above     # 正向容差
    jc.tolerance_below = below     # 负向容差，可与正向不同
    jc.weight = weight
    return jc

# 用途一：锁定"肘上"分支，仅约束肘关节一个窗口
goal_cs = Constraints()
goal_cs.name = "elbow_up_goal"
goal_cs.joint_constraints.append(
    joint_window("elbow_joint", 0.9, 0.25, 0.25))

# 用途二：腕部线缆保护，作为路径约束约束两个腕关节
path_cs = Constraints()
path_cs.name = "wrist_cable_guard"
path_cs.joint_constraints.append(
    joint_window("wrist_2_joint", 0.0, 0.15, 0.05))   # 偏向远离极限一侧
path_cs.joint_constraints.append(
    joint_window("wrist_3_joint", 0.0, 0.15, 0.05))

解读：（1）窗口函数把上下容差作为独立参数，非对称设计从接口层面可见：腕部窗口向负向只留 0.05 rad，规划器在窗口内更少贴近反向极限，保护线缆的意图直接写进约束。（2）两种用途使用不同的约束槽位：肘部分支选择属于"终点构型要求"，放入目标约束；腕部窗口属于"全程纪律"，放入路径约束（第 035 章的分类判据在此再次落地）。（3）每个约束集只包含一到两个关节，遵守第 2 小节给出的数量纪律；需要同时锁肘与锁腕时，拆成两组分别在目标与路径槽位表达，避免单一箱体过窄。

// 可见性约束：保持标定目标在腕部相机视野中
moveit_msgs::msg::VisibilityConstraint vc;
vc.target_radius = 0.04;                    // 目标圆盘半径 4 cm
vc.target_pose.header.frame_id = "world";
vc.target_pose.pose = target_disc_pose;     // 圆盘中心位姿与可观测朝向
vc.sensor_pose.header.frame_id = "tool0";
vc.sensor_pose.pose = sensor_mount_pose;    // 传感器在挂载连杆系下的位姿
// 视轴方向：取传感器的 z 轴向前（常量名以消息定义为准）
vc.sensor_view_direction = moveit_msgs::msg::VisibilityConstraint::SENSOR_Z;
vc.max_view_angle = 0.8;                    // 目标朝向与视线的夹角上限（rad）
vc.max_range_angle = 0.5;                   // 视轴与目标方向的夹角上限（rad）
vc.weight = 1.0;

// 作为路径约束装入：全程保持目标可见
path_constraints.visibility_constraints.push_back(vc);

解读：（1）目标用"位姿加半径"表达圆盘，位姿中的朝向定义可观测面；标定板、二维码板这类目标必须按真实朝向填写，否则条件二会以错误的面法向做判定。（2）传感器位姿在挂载连杆系下给出，随臂运动实时变化：这正是腕部相机场景下约束会随构型生效的原因，视角由运动学链共同决定。（3）两个角度上限按传感器特性取：视野角决定 max_range_angle，有效观测角决定 max_view_angle；常量选择（SENSOR_Z 等）必须与传感器实际视轴一致，选错轴会让约束判定的几何完全错位。

片段 3：Python 可见性条件的数值核验

import numpy as np

def visibility_check(sensor_pos, view_dir, target_pos, target_normal,
                     max_range_angle=0.5, max_view_angle=0.8):
    """按可见性约束的双角条件核验一个状态，供规划前预检与结果复核。"""
    to_target = target_pos - sensor_pos
    dist = np.linalg.norm(to_target)
    if dist < 1e-6:
        return False, "传感器与目标重合"
    unit = to_target / dist
    # 条件一：视轴与目标方向
    a_sensor = np.arccos(np.clip(np.dot(unit, view_dir), -1.0, 1.0))
    # 条件二：目标朝向与指向传感器的方向
    a_target = np.arccos(np.clip(np.dot(-unit, target_normal), -1.0, 1.0))
    ok = (a_sensor <= max_range_angle) and (a_target <= max_view_angle)
    return ok, (round(float(np.rad2deg(a_sensor)), 1),
                round(float(np.rad2deg(a_target)), 1))

ok, angles = visibility_check(
    sensor_pos=np.array([0.4, 0.0, 0.5]),
    view_dir=np.array([1.0, 0.0, 0.0]),
    target_pos=np.array([0.8, 0.05, 0.55]),
    target_normal=np.array([-1.0, 0.0, 0.0]))
print("可见:", ok, "两角(度):", angles)
# 注意：本核验只覆盖角度几何；臂段遮挡需要额外的视线几何查询

解读：（1）核验函数与规划器的约束判定同构：两个夹角分别计算、分别比较，任一超限即不可见；返回值带两个角度值，便于在失败时判断是"视野外"还是"背对观测面"。（2）把核验写成独立函数的价值在于预检：规划之前先用当前状态试算，若当前就已经不可见（例如起始姿态偏差过大），先执行对准动作再规划，避免在无解状态上浪费预算。（3）注释再次提醒遮挡边界：角度条件满足不等于观测成立，感知类任务应在执行期用实际图像或点云核对，形成"约束保证几何、感知保证事实"的双层防护。

常见坑

  • 关节窗口超出硬件限位：窗口设计时未与软限位取交，规划器在窗口内采样却触犯硬件限制，行为随规划器实现而异。修复是构造阶段对窗口与限位做交集并打印核对结果。
  • 上下容差写反：把对外侧危险方向的容差填到另一侧，非对称设计失效。修复是把容差方向定义写进窗口函数的文档字符串并配单元测试。
  • 约束关节过多：为"保险"把五个关节全部约束，可行集退化为孤立点，规划成功率骤降。修复是只保留与语义相关的关节，其余交由规划器自由度。
  • 视轴常量选错：传感器的实际前向轴与所选常量（SENSOR_Z、SENSOR_Y、SENSOR_X）不一致，条件一的几何完全错位。修复是核对传感器参考系约定，用可视化确认视轴方向后再填写。
  • 把可见性约束当遮挡检测：臂段挡在传感器与目标之间，约束仍然满足，运行期才发现目标丢失。修复是明确约束边界，补一层遮挡查询或感知侧的可见性监视。

练习与思考

  1. 窗口计算：关节中心位置 0.8 rad，tolerance_above = 0.15、tolerance_below = 0.05。写出允许区间；把中心位置移到 0.0 后窗口偏向哪一侧？设计意图如何随之表达？★
    提示
    区间为 [0.75, 0.95]。中心在 0 时窗口为 [-0.05, 0.15]，偏向正向；设计意图是"允许正向偏离大于负向"，即远离某一侧的极限或干涉区。
  2. 结果预测：把冗余选择用的关节约束从 1 个关节（窗口 ±0.25 rad）增加到 4 个关节（同宽度）。预测规划成功率与轨迹多样性的变化，并解释原因。★
    提示
    4 个窗口的箱体体积急剧缩小，采样命中的构型变少，成功率下降；轨迹多样性也下降（可用解减少）。冗余选择保留 1 到 2 个关节约束即可。
  3. 设计题：为"腕部相机保持对准标定板完成扫描"设计约束组合：任务空间约束、关节约束、可见性约束各承担什么、取值如何确定、如何分层验证。★★
    提示
    位置约束控制传感器到板距离范围（小盒体），方向约束控制正视姿态（1–3°），可见性约束保证全程视野；取值来自传感器视场与标定；验证按"单独可行、两两叠加、全部叠加"逐步进行。
  4. 诊断题：可见性约束任务规划成功，执行中目标却从图像中消失。列出至少三种原因与核查手段。★★
    提示
    候选：目标被臂段遮挡（约束不检查遮挡，用视线几何查询或图像核对）；目标位姿标定偏差使实际朝向与消息不符（重新标定并回归）；执行偏差使视角超出角度上限（核对执行记录的目标可见性指标）。
  5. 分析题：比较"用关节约束选择逆解分支"与"在逆解序列中筛选想要的解、仅把结果交给规划器"两种做法，从可重复性、对规划器支持度、鲁棒性三个角度分析其适用场合。★★★
    提示
    逆解筛选实现简单、结果可控，但只在单点（起点或终点）确定分支，中途可能翻转；关节约束把分支纪律写进规划问题，全程受控，代价是可行集收窄与规划器支持依赖。对中途翻转敏感的任务（线缆、双机避碰）用约束，对单点定位任务用筛选即可。

小结

  • 关节约束是配置空间中的区间与箱体，上下容差独立，非对称窗口把硬件纪律写进约束。
  • 用少量关节约束选择逆解分支或约束冗余自由度，数量越多可行集越窄，一到两个关节是常用的起步规模。
  • 可见性约束由双角条件构成：视轴与目标方向、目标朝向与视线，判定"目标在视野内且观测面有效"。
  • 可见性约束不做遮挡检测，需用视线查询或感知监视补充；视轴常量与参考系是常见错点。
