第二篇 · 规划场景与碰撞管理

第 034 章：规划场景中的传感器数据融合

多路感知齐上场：本章讲占据级证据如何在概率框架下自然融合、冲突如何由证据强度裁决、物体级重复报告如何归并，以及多传感器一致性与健康监测如何把融合系统的错误拦在规划之前。

  • 主题：多传感器融合 / 场景一致性
  • 关键机制：对数几率证据累加、冲突裁决、物体级归并与健康监测
  • 预计学时：50 分钟
  • 前置章节：第 033 章

学习目标

  • 理解传感器融合的层次结构：占据级与物体级的融合分别发生在哪个环节、用什么判据。
  • 掌握占据级融合的概率本质：多路观测的对数几率累加如何自然实现证据合并与冲突裁决。
  • 能设计物体级融合的仲裁规则：全局标识、重复归并、置信度策略与写入出口统一。
  • 会搭建多传感器一致性验证：重叠区标定核对、物体与地图互查、单源健康监测。
  • 能分析时间维度对融合的影响：不同延迟的数据在同一地图上汇合产生什么现象、如何抑制。

背景与动机

真实工位很少只装一个传感器：顶部相机看全局、腕部相机看近景、激光雷达补侧面与远距，检测模块又以物体形式上报识别结果。多路数据带来覆盖互补、证据增强与冗余容错，也引入新一类问题：同一空间被多路观测如何合并、两路结论矛盾时听谁的、不同延迟的数据拼在一张图上意味着什么。这些问题不解决，融合系统会以"双墙""闪烁障碍""幽灵物体"等形式把错误传给规划器。

好消息是融合的主干在数据结构上已经就位：第 030 章的占据地图本身就是概率结构，多路观测写入同一棵树时证据自动累加；第 023 与 033 章的物体生命周期提供了物体级融合的写入出口。本章的任务是把这两条现成的通路用对：占据级依赖概率累加与冲突裁决，物体级依赖统一仲裁与命名纪律，一致性核对作为两者的守门人。本章是感知篇的收束，下一章转入约束篇。

核心原理

1. 融合的层次与落点

层次融合对象MoveIt2 中的落点主要判据
数据级原始点云/深度图一般不做，保留原始输入交由后续层次标定精度与配准质量
占据级各路的点云观测多插件写入同一棵八叉树对数几率证据累加
物体级各检测源的识别结果统一仲裁模块写碰撞物体空间归并、置信度与标识策略
决策级规划与执行的采用与否规划循环的场景就绪门与验证任务风险等级

落点遵循一条结构原则：占据级融合放在地图写入端（多写一棵树），物体级融合放在场景写入端之前（一个仲裁出口），决策级融合放在规划循环的入口。把融合职责分布到这三个收口位置，各源的独立性得以保留，接口不膨胀。

2. 占据级融合：概率框架下的证据合并

占据级融合不需要额外的"融合算法"：对数几率表示天然支持证据叠加。两路传感器对同一体素给出观测时，增量直接相加：

Lfused = Lprior + ∑k Lk（每路观测的增量） 命中增量约 +0.85，穿越增量约 -0.41；相加后经钳制区间限制

这一机制带来两个直接推论。（1）多源命中比单源更快收敛：两路各给一次命中相当于 +1.70，概率从 0.5 升到约 0.85；证据叠加让置信度增长与源数量成正比。（2）冲突由证据强度裁决：一路说"占据"、另一路说"空闲"时，净证据等于两个增量之和（约 +0.44），结果偏向命中一侧但置信度不高，系统以"存疑但仍谨慎"的状态继续观测，避免在两种布尔结论之间跳跃。冲突区随观测积累逐步收敛到一致结论，这种渐进性是概率融合相对布尔表决的核心优势。

3. 冲突的成因与处理策略

同一体素收到相互矛盾的观测，通常来自四类成因，处置手段各不相同：

  • 标定误差：两路外参不一致，同一表面在两路数据中错位，重影与矛盾同时出现。处理方向是重标定，用重叠区的公共特征核对。
  • 遮挡与视角差异：掠射角观测的深度误差较大，与正视观测冲突。处理方向是识别低质量观测（入射角过大）并在插件内降权或剔除。
  • 动态物体：两路数据时间戳不同，运动物体在两份观测中位置不同。处理方向是缩短时间窗、提高节拍，或把动态物体交给物体级跟踪。
  • 材质伪影：镜面、透明、烟雾导致的错误回波或穿透。处理方向是物理层面改善（角度、遮挡板）配合概率层面的慢收敛容忍。

工程上不追求消除冲突，而追求"冲突可见、影响可控"：冲突区域的体素概率停在中间区间，规划侧按其保守策略处理；冲突持续存在时触发告警，指向标定或物理环境的核查。

4. 物体级融合：仲裁与归并

物体级的融合对象是识别结果，可能出现同一物理工件被两个检测源以两个标识重复上报的情形。直接全部写入会产生重复障碍，也会让附着、抓取等按标识操作的功能错乱。标准架构是设立仲裁出口：

  1. 空间归并：按中心距离阈值把多源报告归并为同一物体（阈值取物体尺度的一定比例）；
  2. 证据计数：归并结果记录支持源数量，作为置信度的组成部分；
  3. 统一标识：仲裁出口为归并结果分配全局标识（前缀加序号），各源对外的身份映射由出口维护；
  4. 写入出口单一化：所有物体级写入经过仲裁出口，刷新与清理责任集中一处（第 033 章的心跳与 TTL 在此层实现）。

归并阈值是主要调参点：过小会让同一物体被重复保留，过大则把相邻工件归并成一个。阈值与工件最小间距相关，通常取最小间距的一半到三分之二，并配合"归并结果取高置信度位姿"的位姿选择规则。

5. 一致性与健康监测

融合系统的正确性靠三层核对兜底。（1）跨源标定核对：在重叠区放置标准件，核对两路数据在场景中的位置偏差，作为立体标定的验收判据。（2）物体与地图互查：检测为物体的区域，占据地图应当同时有占据证据；两者长期矛盾指向标定或过滤配置问题。（3）单源健康监测：为每路数据维护新鲜度与贡献度指标（近期写入次数、占地图体素比例），某一路静默失效时其覆盖区域会出现观测空洞，监测指标能在规划行为恶化之前发出告警。

时间维度需要单独强调：不同传感器链路延迟不同，汇入地图的时刻各异，此刻的地图是"各源最新观测的混合体"，与"某一瞬时的一致快照"存在差异。低动态场景中该差异可忽略；高速运动或人员穿行场景中，差异表现为运动物体的拖影与断续。抑制手段按代价从小到大：提高写入频率、限制单源延迟上限、为动态区域切换到跟踪加物体级表示。

实现思路与设计

多传感器融合系统的搭建流程：

  1. 画覆盖图：在工位俯视图上标注每路传感器的覆盖范围与重叠区，重叠区是标定核对与冲突分析的重点区域。
  2. 配置占据级写入：每路一个插件实例，参数独立（第 031 章），写入频率按覆盖面积与重要性分配总预算。
  3. 搭建物体级仲裁出口：实现归并、计数、全局标识与单一写入出口，接入心跳与 TTL。
  4. 定冲突规则：把第 3 小节的成因与处置写成可执行规则（低质量观测剔除条件、冲突告警阈值）。
  5. 一致性验证：跨源标准件核对、物体地图互查、单源健康指标三项纳入启动自检与周期检查。
  6. 数据实时性核对：测量各源端到端延迟，为动态场景设定延迟上限与降级策略。

融合配置要点

片段 2：Python 对数几率融合与冲突裁决数值演示

import numpy as np

def fuse_evidence(sequence, p_hit=0.7, p_miss=0.4, l_min=-2.0, l_max=3.5):
    """占据证据融合：命中/穿越序列累加，观察冲突的裁决过程。"""
    l_hit = np.log(p_hit / (1 - p_hit))       # 约 +0.85
    l_miss = np.log(p_miss / (1 - p_miss))    # 约 -0.41
    L = 0.0
    trace = []
    for obs in sequence:                       # 1 为命中、0 为穿越
        L = float(np.clip(L + (l_hit if obs else l_miss), l_min, l_max))
        trace.append(round(L, 2))
    p = 1.0 / (1.0 + np.exp(-L))
    print("对数几率轨迹:", trace, f"-> 概率 {p:.2f}")
    return L, p

# 场景 A：两路传感器各给两次命中，证据叠加后快速高置信
fuse_evidence([1, 1, 1, 1])
# 场景 B：高置信状态后出现一帧穿越，观察概率的回落速度
fuse_evidence([1, 1, 1, 1, 1, 0])
# 场景 C：穿越多于命中，证据向空闲侧收敛
fuse_evidence([1, 0, 0, 0])

解读：（1）场景 A 展示多源证据叠加：四次命中把对数几率推到 3.40 附近，概率约 0.97，接近钳制上限。（2）场景 B 演示高置信状态的回落：连续命中把对数几率推到钳制上限附近后，一帧穿越只减去约 0.41，概率从约 0.97 回落到约 0.96，占据结论保持稳定；换成"一路命中加一路穿越"的冲突帧，净证据约 +0.44，结果由证据强度渐进裁决，不会退化为布尔表决。（3）场景 C 演示清除方向：命中与穿越的增量不对称让清除较慢，这也解释了动态环境中障碍消失需要多次观测的原因。把该函数作为参数讨论工具，可以把"改模型概率会有何影响"从猜测变为可计算。

片段 3：Python 物体级归并仲裁

import math

def merge_detections(sources, merge_radius=0.05, min_conf=0.5):
    """物体级融合：按空间邻近归并多源报告，输出唯一清单。"""
    merged = []
    # 高置信度优先入表，低置信度的邻近报告被归并吸收
    for det in sorted(sources, key=lambda d: -d["confidence"]):
        for kept in merged:
            if math.dist(det["pos"], kept["pos"]) < merge_radius:
                kept["support"] += 1        # 记录多源支持，供跟踪与告警
                break
        else:
            det["support"] = 1
            merged.append(det)
    # 置信度门槛在出口处统一执行：低置信报告不进入规划场景
    result = [m for m in merged if m["confidence"] >= min_conf]
    dropped = len(merged) - len(result)
    print(f"多源报告 {len(sources)} 条，归并 {len(merged)} 个，"
          f"拦截低置信 {dropped} 个")
    return result

解读：（1）先排序再入表的顺序保证归并结果由高置信度报告主导，位姿与几何取自信任度更高的来源，"取谁的数据"与"信谁"在这里绑定。（2）support 计数把冗余从负担变成资产：多源同时支持可以支撑置信度提升，也为"某源失效导致支持数骤降"的监测提供信号。（3）置信度门槛放在仲裁出口统一执行，各检测源保持"如实上报"的职责，策略调整只改出口一处；输出清单随后经心跳与 TTL 纪律写入场景（第 033 章）。

常见坑

  • 低质量观测未剔除：掠射角的深度点与正视观测冲突，冲突体素持续停在中间概率。修复是在插件内按入射角与距离质量过滤，减少矛盾证据的产生源。
  • 标定偏差当作地图问题处理：两路数据错位时反复调整分辨率与退让参数，症状不消失。修复是先做重叠区标准件核对，偏差超限时重标定外参。
  • 物体级多源重复上报：两个检测源给同一工件两个标识，场景中出现重叠物体，附着与抓取按标识操作混乱。修复是引入单一仲裁出口做空间归并与全局标识。
  • 写入预算失控：多路传感器都按最大频率写入，规划耗时随传感器数量上升。修复是总预算分配加逐源限频，把第 031 章的节拍纪律扩展到多源场景。
  • 缺单源健康监测：某一路静默失效后其覆盖区成为观测空洞，规划器在无覆盖假设下运行而不自知。修复是为每源维护新鲜度与贡献度指标，失效即告警并降低相关任务的自主等级。

练习与思考

  1. 数值练习：某体素先后收到三路命中与两次穿越。按命中增量 +0.85、穿越增量 -0.41 计算净对数几率与对应概率（初值为 0，钳制区间 [-2, 3.5]），并说明该体素在规划视角下应如何处置。★
    提示
    净证据约 3 × 0.85 - 2 × 0.41 = 1.73，概率约 0.85。规划视角应按"占据"处理（高置信），但持续观测到冲突时应触发数据质量核查。
  2. 结果预测：在片段 2 的场景 B 后面追加两帧"穿越"。预测对数几率轨迹的走向，并解释为什么动态障碍清除需要多帧正证据。★
    提示
    每帧穿越减约 0.41，从约 3.4 的峰值回落；同时存在命中侧证据时净变化更小。清除依赖多帧穿越是因为未命中增量小于命中增量，且钳制与冲突都在抵抗概率下滑。
  3. 设计题：为一个"强光弧焊加激光雷达加顶视相机"的工位设计融合方案：覆盖分配、冲突规则、健康指标与动态工件处理，并说明强光对相机的失效如何被系统吸收。★★
    提示
    雷达负责焊接区与侧面覆盖，相机负责焊接前后的精细区域；冲突规则包含低质量观测剔除与告警阈值；健康指标按源维护新鲜度；强光期间相机贡献骤降由雷达兜底，监测指标给出告警并降低相机数据的采用权重。
  4. 诊断题：新增第二台相机后，场景中出现"双墙"现象（同一墙面有两层相距约 2 cm 的体素）。列出最可能的原因与两步验证方法。★★
    提示
    最可能是新相机外参有约 2 cm 偏差（安装或标定误差），两路观测写入同一棵树但位置不一致。验证一：在重叠区放标准件，对比两路数据的观测位置；验证二：临时停写一路，观察双墙是否消失。
  5. 分析题：比较"各检测源独立写入场景"与"统一仲裁出口写入"两种物体级架构，从标识一致性、刷新与清理责任、故障隔离三个角度分析，并给出独立架构可行的边界条件。★★★
    提示
    独立架构实现简单、源间解耦，但重复报告与清理责任分散，标识冲突难以排查；统一出口解决这些问题，代价是单点复杂度。独立架构可行的边界：各源检测区域互不重叠、命名前缀严格隔离、清理逻辑按源自治且验证充分。

小结

  • 融合分布在三个收口位置：占据级在地图写入端（多源一棵树），物体级在仲裁出口，决策级在规划循环入口。
  • 占据级融合由对数几率累加自动完成：多源证据成正比增强，冲突由证据强度渐进裁决，沿用"不表决"的原则。
  • 物体级融合的核心是单一仲裁出口：空间归并、支持计数、全局标识与集中的刷新清理责任。
  • 一致性靠三层核对：跨源标定、物体与地图互查、单源健康监测；时间维度用延迟上限与降级策略抑制。
