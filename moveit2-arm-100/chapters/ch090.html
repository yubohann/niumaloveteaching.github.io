第五篇 · 组件详解与系统集成

第 090 章：从仿真到真机的迁移要点

逐维对比仿真与真机的差异来源，给出以 ros2_control 硬件接口替换为核心的迁移方法，并设计"回环、仿真、低速真机、逐步加载"四阶段验证路径。

  • 主题：系统集成 / 环境迁移
  • 关键机制：硬件接口插件替换、时间基准一致性、状态链差异、分阶段验证
  • 预计学时：55 分钟
  • 前置章节：第 089 章

学习目标

  • 理解仿真与真机差异的六类来源：模型、执行器、传感、时间、控制接口与环境。
  • 掌握基于硬件接口插件替换的迁移方法，明确哪些配置必须修改、哪些保持不变。
  • 理解时间基准与状态链差异如何引发 TF 过期与规划起点偏差。
  • 会组织四阶段迁移验证路径，并为每阶段定义退出准则。
  • 能按清单完成迁移参数核对，并设计首次真机运动的保守流程。

背景与动机

仿真中验证完毕的规划与任务，搬到真机上往往出现新问题：轨迹跟踪误差增大、低速抖动、时间戳不同步、急停无法复位。这些问题的根源大多不在规划算法，而在仿真与真机在模型、控制、时序三个层面的系统性差异。

迁移的目标在于把差异逐项暴露并量化：哪些差异影响规划层、哪些影响控制层、哪些影响安全边界。把迁移当作分阶段验证过程，每一阶段只引入一类新差异，失败原因即可定位到具体维度。

上一章处理多实例部署的资源隔离，本章处理部署环境的另一半：同一套软件在两种环境之间的可移植性。

核心原理

1. 差异的六类来源

仿真与真机的差异可归为六类，每类对应一组具体故障模式。迁移方法的核心是把六类差异分配到不同验证阶段，逐类引入；一次性全部引入会让失败原因无法归因。

维度仿真侧特征真机侧特征典型故障
模型理想惯量、无摩擦、碰撞几何简化真实质量分布、摩擦、线缆与负载动力学偏差、干涉实物
执行器力矩充足、响应理想力矩上限、频响有限、存在背隙跟踪误差、低速爬行
传感状态为理想真值编码器量化、噪声、滤波延迟状态抖动、微分噪声
时间仿真时间可控可跳变墙钟时间、实时因子波动TF 过期、轨迹时间错位
控制接口仿真硬件插件厂家硬件插件接口语义与单位差异
环境干净、无外部扰动光照、振动、人员、温度感知退化、重复定位漂移

2. ros2_control 的接口边界

控制框架把系统分为硬件接口层与控制器层：硬件接口插件负责读写关节位置、速度与力矩；控制器层（如关节轨迹控制器 Joint Trajectory Controller, JTC）负责把轨迹转换为命令。迁移时插件与参数随硬件替换，控制器与 MoveIt2 配置原则上保持不变，这条边界决定了"改哪、不改哪"。

迁移改动面 = 硬件接口插件 + 硬件参数 + 安全参数；保持不变 = 规划配置 + 控制器链路 + 任务编排 出现规划配置必须改的情况，通常说明仿真模型与真机模型不一致，例如关节方向、限位或工具长度差异

回环模式（mock）用软件回环模拟硬件读写，是迁移前的最后一道离线验证：不接硬件即可检验控制器与轨迹链路，隔离"软件问题"与"硬件问题"。

3. 时间基准与状态链

仿真通常发布仿真时钟并让全部节点使用仿真时间；真机使用墙钟时间。时间基准配置错误的表现是 TF 等待超时与消息过期判断失效：描述参数指向仿真时间而系统运行在墙钟时间时，变换查询立即超时。迁移时把时间基准作为部署参数显式声明，杜绝隐式假定。

状态链差异体现在"规划起点的可信度"：真机关节状态经过采样、量化和滤波，与命令值之间存在延迟。规划若把带延迟的状态当作当前状态，起点偏差会让轨迹首段跟踪误差放大。缓解手段包括：在执行前端校验状态新鲜度，按延迟给出速度补偿，或缩短执行前等待。

e总 = e模型 + e标定 + e跟踪 + e量化 误差预算按项分配：例如总允许 5 mm 时，模型与标定各 1 mm、跟踪 2 mm、量化与噪声 1 mm；任一项超预算都应先压缩该项再整体推进

4. 安全边界的收缩

仿真允许激进参数的原因之一是失败无代价。迁移到真机时，速度与加速度缩放、工作空间边界与力矩限制都应先收缩再逐步放开，且每一步都要有可回退的停止手段。软限位留出余量的原因是控制误差与标定误差可能把轨迹末端推近硬限位。

实现思路与设计

迁移按四阶段推进，每阶段的输入是纯软件验证，输出是新增一类真实差异。阶段之间设置退出准则，未达标不进入下一阶段。

1. 四阶段路径

  1. 回环阶段：mock 硬件插件，验证控制器链路与轨迹执行语义；退出准则为轨迹能被完整消费且状态按预期回环。
  2. 仿真阶段：物理仿真加传感器模型，验证规划、抓取与任务流；退出准则为任务在仿真中连续稳定完成且指标达标。
  3. 低速真机：速度缩放在 0.05–0.1 区间，空载、小范围、带急停值守；退出准则为跟踪误差与重复定位在预算内。
  4. 逐步加载：依次引入负载、提高缩放、扩大范围；每个增量只改一个变量并保留回归样本。

2. 迁移参数对照表

参数项仿真取值真机取值依据
时间基准仿真时间为真墙钟时间为真与硬件时钟源一致，杜绝混用
硬件接口仿真插件厂家插件接口语义以插件文档为准
速度缩放可达 1.0从 0.05 起步先确保安全与跟踪质量，再提指标
软限位余量可贴限值留 1–2 度余量覆盖控制与标定误差
控制器增益可激进按负载整定振动与噪声约束增益上限
急停与安全信号仿真中无必须接线验证失败代价不可接受

3. 首次真机运动流程

首次运动限定为单关节小角度、低速度的往复动作；先检查状态新鲜度与控制器就绪，再下发轨迹；全过程保留软件与硬件两级停止手段。首次运动的目标是验证"命令、状态、停止"三条链路都可用；完成任务的验收放在后续阶段。

与上一章的差异点：第 089 章在同一环境内扩展实例数量，本章跨越两套环境迁移同一套配置，处理的是模型、时序与安全边界的差异集合。

片段 1：硬件接口插件的三种形态（URDF 配置）

<ros2_control name="arm" type="system">

    <plugin>mock_components/GenericSystem</plugin>
    <param name="calculate_dynamics">true</param>
  </hardware>
  <joint name="joint1">
    <command_interface name="position"/>
    <state_interface name="position"/>
    <state_interface name="velocity"/>
  </joint>
</ros2_control>

<!-- 真机形态：仅替换插件与连接参数，关节接口定义保持不变 -->
<!-- <hardware>
  <plugin>vendor_arm_driver/ArmSystem</plugin>
  <param name="ip">192.168.10.20</param>
  <param name="control_period_ms">2.0</param>
</hardware> -->

解读：迁移在控制框架内的改动面收敛为两个字段。设计要点：（1）关节的命令与状态接口清单在两套形态间保持一致，控制器层因此无需感知硬件替换；（2）回环形态开启动力学计算，让 mock 模式也具备基本的状态演化，比纯静态回环更接近真实轨迹消费；（3）真机形态的参数（连接地址、控制周期）集中声明，便于按现场修改。注意硬件插件名称与参数以厂家驱动包的文档为准，接口清单需与驱动支持的通量一致，否则控制器加载即失败。

片段 2：按环境切换的启动入口

from launch import LaunchDescription
from launch.actions import DeclareLaunchArgument
from launch.substitutions import LaunchConfiguration, PythonExpression
from launch.substitutions import PathJoinSubstitution
from launch_ros.actions import Node
from launch_ros.substitutions import FindPackageShare


def generate_launch_description():
    # 环境开关是迁移的单一入口：仿真与真机共用其余配置
    use_sim = LaunchConfiguration("use_sim")
    # 时间基准随环境联动：仿真用仿真时钟，真机用墙钟，禁止混用
    use_sim_time = PythonExpression(
        ["'true' if '", use_sim, "' == 'true' else 'false'"])
    # 硬件描述文件随环境选择：回环描述与真机描述分文件维护
    hardware_file = PathJoinSubstitution([
        FindPackageShare("my_arm_bringup"), "config",
        PythonExpression(["'sim_hardware.yaml' if '", use_sim,
                          "' == 'true' else 'real_hardware.yaml'"]),
    ])
    return LaunchDescription([
        DeclareLaunchArgument("use_sim", default_value="true",
                              description="true 使用仿真硬件与仿真时间"),
        Node(
            package="controller_manager",
            executable="ros2_control_node",
            parameters=[hardware_file, {"use_sim_time": use_sim_time}],
            output="screen",
        ),
    ])

解读：把环境差异收敛到一个开关，避免两套启动文件长期漂移。设计要点：（1）时间基准与硬件描述联动切换，消除"仿真硬件配墙钟时间"这类隐蔽组合；（2）其余控制器与规划配置不随环境变化，出现必须变化的配置时先审查模型一致性；（3）硬件描述分文件维护使差异可见、可评审。真实工程中也可以由参数文件内部完成条件选择，此处显式表达切换逻辑以便核对。

片段 3：首次真机运动的保守流程

import time
import rclpy
from rclpy.node import Node
from sensor_msgs.msg import JointState
from trajectory_msgs.msg import JointTrajectory, JointTrajectoryPoint

class FirstMove(Node):
    """首次真机运动：单关节小角度往复，验证命令、状态与停止链路。"""

    def __init__(self):
        super().__init__("first_move")
        # 状态新鲜度是安全前置：超过阈值说明状态链不可信，禁止发令
        self.stamp = None
        self.create_subscription(JointState, "joint_states", self.on_state, 10)

    def on_state(self, msg):
        if "joint1" in msg.name:          # 只需确认目标关节已上报
            self.stamp = self.get_clock().now()
    def wait_ready(self, timeout_s):
        deadline = time.monotonic() + timeout_s
        while time.monotonic() < deadline:
            rclpy.spin_once(self, timeout_sec=0.1)
            if self.stamp is not None:
                age = (self.get_clock().now() - self.stamp).nanoseconds * 1e-9
                if age < 0.5:             # 状态年龄阈值：覆盖传感与传输延迟
                    return True
        return False
    def guarded_execute(self, executor):
        if not self.wait_ready(5.0):
            self.get_logger().error("状态未就绪：检查状态链与时间基准")
            return False
        # 低速小角度探针轨迹：失败代价最小化，本阶段目标是验证链路
        traj = JointTrajectory()
        traj.joint_names = ["joint1"]
        for k, pos in enumerate((-0.05, 0.05, 0.0), start=1):
            point = JointTrajectoryPoint()
            point.positions = [pos]
            point.time_from_start.sec = k
            traj.points.append(point)
        return executor.send(traj, velocity_scaling=0.05)

解读：首次运动流程把安全前置放在代码结构里。关键行为：（1）状态新鲜度用接收时间与当前时间之差衡量，阈值 0.5 s 属于保守取值，覆盖传感与传输延迟；（2）状态未就绪时直接拒绝发令，把"状态链不可信"与"规划执行失败"两类问题分开；（3）探针轨迹单关节往复、幅度 0.05 rad 且缩放 0.05，任何单点异常造成的位移都局限在小范围；（4）执行封装预留软停止调用位置，异常时先停止再排查。这套结构与第 093 章的安全机制衔接，缩放值即安全余量的可调旋钮。

常见坑

  • 时间基准混用：部分节点使用仿真时间，其余使用墙钟时间，变换查询与消息过期判断全部异常。修复：时间基准作为部署参数统一下发，启动后核对关键节点的时钟源。
  • 仿真模型未包含惯量与摩擦：仿真中控制器参数激进也无振动，真机出现振荡与过热。修复：补齐惯量参数并按真机整定增益，仿真阶段先按保守增益验证。
  • 速度缩放沿袭仿真值：首次真机运动即高速大范围，跟踪误差与制动距离超预算。修复：迁移时缩放从 0.05 起步，按阶段退出准则逐级放开。
  • 碰撞几何与实物不符：仿真里"无碰"的轨迹在真机因线缆、夹具与工件实物干涉而碰撞。修复：把线缆与附件纳入模型，或在工作空间上维持保守的安全边界。
  • 急停链路未验证：软件停止可用而硬件急停未接线，突发事件无法物理止损。修复：迁移检查表把急停与安全信号列为真机阶段准入条件，逐项实测。

练习与思考

  1. 列出本课程环境中"规划层、控制器层、硬件层"各三层在迁移时需要修改的配置项，并标注哪些必须成对修改。★
    提示
    硬件层换插件与连接参数，控制器层整定增益，规划层通常不变；时间基准与硬件描述必须成对，否则出现仿真时间配真机硬件的隐蔽组合。
  2. 预测：把真机系统的 use_sim_time 误设为 true 但不启动时钟源，列出三个最先出现的异常现象及其因果链。★★
    提示
    时钟静止导致 TF 全部过期、状态新鲜度判断恒为过期、轨迹时间戳与墙钟不匹配；因果链从"时间基准无源"出发。
  3. 计算误差预算：总允许末端误差 6 mm，模型与标定各占 1.5 mm，量化噪声 0.5 mm，求跟踪误差的允许上限；若实测跟踪误差 3.5 mm，指出应优先压缩哪一项。★★
    提示
    跟踪误差上限 = 6 − 1.5 − 1.5 − 0.5 = 2.5 mm；实测 3.5 mm 超出 1 mm，优先整定控制器或降低速度以压缩跟踪项。
  4. 设计四阶段迁移的退出准则表，每阶段给出两条量化指标与一条否决条件。★★★
    提示
    回环阶段看轨迹消费完整率与状态回环一致性；低速真机看跟踪误差与重复定位；否决条件示例：任一安全信号实测失败即退出当前阶段。
  5. 说明为什么"首次真机运动"的目标是验证链路（任务完成放在后续阶段），并给出被你删减掉的任务要素清单。★★
    提示
    删除的要素包括抓取、负载、高速与大范围运动；保留命令、状态、停止三条链路的验证，失败代价最小且信息量足够。

小结

  • 仿真与真机差异分六类：模型、执行器、传感、时间、控制接口与环境，迁移按维度逐项暴露。
  • ros2_control 的接口边界把改动面收敛为硬件插件与安全参数，控制器与规划配置原则上不变。
  • 时间基准与状态链是隐蔽故障源，部署参数显式声明并启动后核对。
  • 误差预算把总允许误差分配到模型、标定、跟踪与量化四项，超预算项优先压缩。
  • 四阶段迁移路径：回环、仿真、低速真机、逐步加载，每阶段有量化退出准则。
  • 下一章建立评估体系：性能评估指标体系，把迁移后的系统表现变成可比较、可回归的量化结论。
