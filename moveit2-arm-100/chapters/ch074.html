第 074 章：多机械臂协调

多台独立机械臂共享工作空间时的时空协调：轨迹冲突检测、优先级规划的完备性代价、时间参数化同步，以及死锁与优先级反转的处置。

  • 主题：平台形态 / 多机械臂协调（Multi-Arm Coordination）
  • 关键机制：轨迹冲突检测 / 优先级规划 / 时间缩放与同步点
  • 预计学时：55 分钟
  • 前置章节：第 073 章

学习目标

  • 理解多机械臂协调与双臂协作的差异：任务主体独立、约束来源于空间共享、冲突是暂态的。
  • 掌握轨迹间冲突检测的两类方法（时间配对距离查询与几何扫掠检查），能说明精度与代价的取舍。
  • 掌握优先级规划（Prioritized Planning）的算法流程、不完备性与改进手段。
  • 会做多臂时间参数化：统一节拍、速度缩放与同步点设计。
  • 能诊断并处置死锁、优先级反转与频繁重规划三类协调故障。

背景与动机

第 072 章的双臂协作围绕同一工件，约束是显式的闭链；多机械臂系统则不同：每台臂执行独立任务，彼此之间只有空间上的相互占用，冲突是暂态的，出现在两条轨迹在时间与空间上同时重叠的短窗口内，协调的目标是让这些窗口错开或消失。

从规划维度看，把 n 台臂放进一个联合规划问题意味着 n×d 维的状态空间（两台七轴臂合计 14 维），采样规划在这种维度下代价过高，工程上很少采用。主流做法是"各臂独立规划加协调层"：独立规划保证单臂轨迹的质量，协调层通过冲突检测、优先级顺序、时间缩放与等待来消解冲突。

本章与第 072 章构成对照：前者讲耦合，后者讲解耦；与第 068 章的衔接：多臂共享的工作空间里，动态障碍物正是另一台臂的轨迹，动态抓取的预测思想同样适用。

核心原理

1. 问题结构与协调策略谱

方面双臂协作（第 072 章）多臂协调（本章）
耦合对象同一工件的位姿共享空间的使用权
约束形式相对位姿闭链轨迹间最小距离
冲突性质持续存在、需在线维持暂态、按时间窗口出现
典型故障内力过大、工件偏斜碰撞风险、死锁、节拍抖动

协调策略按实现的复杂度与最优性排列：联合规划最优但维度不可承受；优先级规划顺序求解，接近可行且实现直接；速度调节保持轨迹形状只压缩时间，代价是节拍；空间与时间分区最保守，把共享区使用权串行化。工程组合通常是"优先级规划加时间缩放加分区锁"三层叠加。

2. 轨迹冲突检测

两条轨迹是时空对象 qa(t) 与 qb(t)，冲突定义为存在时刻 t 使两臂最小距离小于安全裕度（扣除时间抖动窗口）。检测方法两选一或组合：

方法原理精度代价
时间配对距离查询按时间步采样两条轨迹，逐步查询最小距离取决于步长，步长小于冲突窗口即可时间步数乘几何对数的查询量
几何扫掠检查把整条轨迹的扫掠体作为静态障碍，检查另一条轨迹是否穿越保守（忽略时间重叠的偶发性）查询次数少

时间配对法的步长选取原则：步长应小于冲突现象的时间尺度，即两臂相对速度下最短距离变化的时间常数；20 ms 步长配合 30 mm 安全裕度可覆盖常见工况。扫掠法适合粗筛：先用扫掠判定"两条轨迹的几何包络是否相交"，相交的再进入时间配对精查，两级结构把精查次数限制在少数轨迹对上。

检测量 ≈ T / Δt × K 轨迹时长 T = 20 s、步长 Δt = 0.02 s、几何对 K = 15 时约 1.5 × 104 次距离查询；扫掠粗筛可把 K 降到个位数

3. 优先级规划与不完备性

优先级规划按顺序为各臂求解：高优先级臂正常规划，其轨迹转化为后续臂的约束（动态禁入或避让对象），低优先级臂在约束下求解。算法的代价是不完备：低优先级臂无解时，整体问题未必无解，只是当前顺序不好；工程上的补救是准备两到三种优先级顺序，失败时按序重试。

优先级规则参考四项：任务紧急度、负载尺寸（大件占据空间多，宜先规划）、避让能力（活动范围大的臂让位）、失败代价（高代价任务优先）。规则固定化的意义是让失败可复现：同样的场景得到同样的顺序与同样的失败模式，便于定位与改进。

两类典型故障与处置：

  • 死锁（Deadlock）：两臂互相等待对方离开共享区。处置：固定让行方向（编号小的臂先过）、共享区使用权加锁与超时、必要时插入等待动作打破循环。
  • 优先级反转（Priority Inversion）：低优先级任务持有关键资源，阻塞高优先级任务。处置：资源按优先级借用（高优先级可抢占并让低优先级重规划）、超时释放。

4. 时间参数化与同步点

各臂独立规划出的轨迹时长不同，直接同时启动会让时间轴错位，冲突检测建立在错误的时间对齐上。统一节拍的三种手段：

T = max(Ti)，缩放率 vi = Ti / T 臂 i 的速度按 vi 缩放（最长轨迹取 1.0、其余按比例减速）；缩放率设下限 0.3，防止短任务被拖得过慢

当缩放率触底仍无法对齐时，改用同步点（Barrier）：在关键阶段前（例如进入共享区、开始取件）设置对齐点，先到的臂在此等待，等待期间不占用共享区。同步点的位置选择遵循"共享区前、私有区内"的原则：等待发生在不占资源的位置，才不会把等待变成新的阻塞。

实现思路与设计

协调层的实现步骤：

  1. 任务分解：把作业拆给各臂，按四项规则分配优先级并固定顺序。
  2. 独立规划：各臂在共享场景中规划，此时只考虑静态障碍。
  3. 冲突粗筛与精查：扫掠粗筛加时间配对精查，输出冲突轨迹对与冲突窗口。
  4. 冲突消解：按"时间缩放、局部重规划、优先级切换、分区锁"的顺序处置。
  5. 同步执行：统一节拍下发，同步点对齐，执行中按周期复查距离。
  6. 超时恢复：任一阶段超时按预案释放资源、重排任务或上报。

设计决策：优先级顺序为什么采用固定方式？

动态优先级会随系统状态抖动而改变顺序，导致轨迹反复重规划、节拍不可预测，极端情况下出现顺序振荡。固定顺序的代价是理论最优性下降，收益是行为可预测、失败可复现、调优经验可积累。动态调整只在固定顺序重试全部失败后才作为兜底手段，且限制调整幅度与频率。

关键代码与解读

片段 1：时间配对的冲突检测

def detect_conflict(traj_a, traj_b, min_gap=0.03, step=0.02):
    """按时间步进查询两条轨迹的最小距离，返回首个冲突时刻。"""
    t = 0.0
    t_end = min(traj_a.duration, traj_b.duration)
    while t <= t_end:
        qa = traj_a.at(t)               # 时间插值取关节状态
        qb = traj_b.at(t)
        if min_distance(qa, qb) < min_gap:
            return t                    # 首个冲突即返回：无须扫完全程
        t += step                       # 20 ms 步进：与执行周期同量级
    return None                         # 全程无冲突

# 若某段轨迹更长，超出部分按单臂运动处理（对方已停）

解读：（1）发现首个冲突立即返回，检测成本在冲突早期就被截断，适合高频调用。（2）步进 20 ms 的选择依据是冲突的时间尺度：两臂接近速度 0.2 m/s 时每步位移约 4 mm，远小于 30 mm 安全裕度，不会漏过窄窗口。（3）时长不等时取较短者作为配对区间，较长轨迹的剩余部分按"对方已停止"处理，把停机中的臂按静态障碍检查即可。

片段 2：优先级规划

def prioritized_plan(arms, tasks, planner, check):
    """按优先级顺序规划：已规划轨迹作为后续臂的避让约束。"""
    planned = []
    for arm, task in zip(arms, tasks):   # tasks 已按优先级降序排列
        traj = planner(arm, task, avoid=planned)
        if traj is None:
            return None, f"{arm} 避让 {len(planned)} 条轨迹后无解"
        if not check(traj, planned):
            return None, f"{arm} 轨迹与高优先级臂冲突"
        planned.append(traj)
    return planned, "OK"

# 返回失败不代表整体无解：可交换优先级顺序重试（上限 3 次）

解读：（1）planner 接收避让集合，实现层可选择把高优先级轨迹作为动态障碍、禁区或时间约束，接口保持稳定。（2）check 是规划后的自检：规划器未把轨迹视为障碍时，自检保证已接受的结果彼此无冲突，形成"规划加验证"的双重保障。（3）失败信息包含臂名、避让数量与失败环节，是重排优先级与诊断的依据；返回结构让调用方可以区分"单臂无解"与"轨迹冲突"两类失败。

片段 3：统一节拍与速度缩放

def time_align(durations, slow_floor=0.3):
    """统一节拍：短轨迹被拖慢对齐，速度比例不低于下限。"""
    t_max = max(durations)                 # 节拍由最长轨迹决定
    speeds = []
    for d in durations:
        v = d / t_max                      # 速度比例：短轨迹需减速
        speeds.append(round(max(slow_floor, v), 2))
    return t_max, speeds

T, v = time_align([3.2, 4.5, 4.0])
# 节拍 4.5 s：三臂速度比例约 0.71、1.0、0.89；缩放率触底时改用同步点

解读：（1）速度比例等于轨迹时长与节拍之比，物理含义是"把原速度乘以该系数即可对齐时间轴"。（2）下限 0.3 是节拍与效率的折中：更低的缩放率虽然能对齐，但短任务被拖得过慢，共享区占用时间反而拉长；触底即说明存在结构性不平衡，应改用同步点或调整任务分配。（3）对齐后再执行冲突检测，检测与执行建立在同一时间轴上，这是多臂协调中最易被忽略的顺序依赖。

常见坑

  • 检测只对同索引路点做配对：两条轨迹的路点间隔不同，配对的时刻不对应，冲突被漏检或误报。修复：按时间插值取状态，步长固定 20 ms，与路点划分无关。
  • 直接联合规划多台臂：状态空间维数达十几维，规划时间不可接受。修复：优先采用独立规划加协调层，联合规划仅用于两到三个关节的耦合场景。
  • 死锁无预案：两臂在共享区入口互等，系统挂起。修复：固定让行方向、共享区使用权加锁与超时，超时后由协调层强制其中一臂退让。
  • 先检测后缩放时间：时间轴错位状态下做的检测结论无效。修复：先统一节拍再检测，任何速度或时序调整后重新检测。
  • 优先级随意设定导致频繁无解：顺序差使低优先级臂在拥挤区域反复失败。修复：按固定规则确定顺序，失败时按预置的替代顺序重试，并记录各顺序的成功率。

  2. 轨迹时长 20 s、步长 20 ms、几何对 15，估算时间配对检测的查询量；若先用扫掠粗筛把几何对降到 4，查询量变为多少？★★
    提示
    1000 步 × 15 对 = 1.5 万次；粗筛后 1000 × 4 = 4000 次，且在多数时间段距离充裕时可以提前终止，实际调用量更低。
  3. 两条轨迹时长 2.0 s 与 3.5 s，计算统一节拍与速度比例；若速度比例下限为 0.8，说明会发生什么并给出替代方案。★★
    提示
    节拍 3.5 s，比例 0.57 与 1.0；下限 0.8 时短轨迹无法被拖到节拍末端，剩余时间用同步点或等待动作吸收，等待位置选在共享区之外。
  4. 为"三臂共享料台取件"设计协调方案：给出优先级顺序及理由、冲突消解顺序、同步点位置与死锁预案，并说明如何验证方案的有效性。★★★
    提示
    优先级可按"负载尺寸加任务紧急度"排序；消解顺序为时间缩放、局部重规划、顺序切换、分区锁；同步点设在共享区入口外；验证方式是构造最坏时序场景（三臂同时取件）重复运行并统计等待时间与冲突次数。

小结

  • 多臂协调的冲突是暂态的时空重叠，与双臂协作的持续闭链约束不同，协调层负责把重叠窗口错开或消除。
  • 冲突检测采用扫掠粗筛加时间配对精查，步长取 20 ms 量级，安全裕度 20–50 mm，任何时序调整后必须重新检测。
  • 优先级规划按固定顺序求解，不完备性用多种顺序重试补救；死锁与优先级反转分别用让行规则、资源加锁与超时处置。
  • 时间参数化先统一节拍再检测执行，速度缩放下限 0.3，触底改用共享区外的同步点。
  • 协调层的设计原则是行为可预测、失败可复现，下一章讨论柔性臂与软体机械臂这类"刚体假设不成立"的平台。
