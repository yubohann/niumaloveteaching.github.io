第一篇 · 环境搭建与基础控制

第 012 章：设置关节目标状态与命名位姿

本章把目标表达体系补全：命名位姿的定义与维护、逐关节约束消息的字段语义，以及容差分配对末端精度的传递关系。

  • 主题：目标管理 / 命名位姿与关节约束
  • 关键机制：SRDF 组状态、JointConstraint 字段、容差与权重
  • 预计学时：50 分钟
  • 前置章节：第 011 章

学习目标

  • 掌握命名位姿在 SRDF 中的定义方式，以及运行期的引用、读取与保存操作。
  • 掌握关节目标状态的四种写入路径：命名位姿、数组、映射、约束消息。
  • 理解 JointConstraint 的字段语义：目标位置、双侧容差与权重。
  • 会按关节位置分配容差，理解容差经过雅可比传播到末端误差的量级关系。
  • 能设计一套工程化的位姿库规范：命名、校验与版本同步。

背景与动机

前两章解决了"用什么空间运动"，本章解决"目标怎么定义才可靠"。工程中的目标有两类来源：固定的标准位姿，例如待机、作业准备、维护姿态，它们的数值不随任务变化；以及随任务生成的目标，数值由程序按工件位置计算。两类目标的上层写法不同，底层的表示却汇合到同一处：规划请求中的目标约束集合。

目标定义的质量直接决定运动的精度与稳定性。容差设得过紧，难解构型上规划时间急剧上升；设得过松，末端停位偏差悄然侵占工序余量。本章把"目标"从一个参数升级为一项需要设计的内容：每个关节的容差有依据，每个命名位姿有校验，每次引用有出处。这套纪律在第 018 章的阶段实践与第四篇的抓取任务中都会持续使用。

核心原理

本节解释目标约束的内部表示、JointConstraint 的字段语义、容差的精度传递，以及命名位姿的管理机制。

1. 目标的内部表示：约束集合

无论上层用命名位姿、数组还是映射表达目标，规划请求内部都归结为目标约束集合。关节空间的约束形如"关节 j 的最终角度应落在 [pj − bj, pj + aj] 区间内"，其中 a 与 b 是双侧容差。约束数量与自由度的关系决定目标的性质：

  • 约束数等于自由度：目标是一个点（或小邻域），规划器必须精确停到指定构型。
  • 约束数少于自由度：目标是子空间，规划器有选择余地，可用来"只固定关键关节、让其余关节自由探索"。
  • 约束相互矛盾：例如同一关节被两个区间不相交的约束覆盖，请求被判无效。

欠约束目标在工程中有实际价值：工件放置时只锁定影响配合的几个关节，其余关节允许规划器选择更顺的构型，成功率与路点质量都会改善。把目标理解成"约束集合"，选项空间随之打开；若按"一组必须精确到达的数值"来理解，可行集就只有单点。

2. JointConstraint 字段语义

字段含义取值建议
joint_name被约束的关节名与模型变量名逐字一致
position目标角度或位移限位内留 5% 余量
tolerance_above向上方向的容差与 below 对称起步，非对称需有依据
tolerance_below向下方向的容差与 above 成对理解
weight约束的相对权重1.0 起步；零权重意味着软约束或忽略，按求解器语义使用

权重字段的语义随规划器不同：优化型规划器把权重作为代价函数的一部分，权重大的约束更难被放松；采样规划器主要利用容差区间判定目标是否达成。跨规划器移植任务时，权重需要按目标规划器的语义重新审视，不能默认平移。本课程主线使用采样规划器，权重保持默认值即可，第 044 章起引入优化型规划器时再深入。

3. 容差到末端误差的传递

关节容差并不直接承诺末端误差，两者之间隔着雅可比矩阵。小偏差量下，末端位姿偏差与关节偏差近似线性相关：

‖Δx‖ ≤ ‖J(q)‖ · ‖Δq‖ 雅可比范数在奇异位形附近急剧增大：同样的关节容差可能对应大得多的末端误差

这条关系给出容差分配的原则：容差的分配应以末端精度为出发点反向推导，避免对全组关节使用同一个数值。离末端近的腕部关节，其角度偏差对应的末端位置偏移小、姿态偏移大；靠近基座的大臂关节，同样的角度偏差在臂展尺度上会被放大。对精度敏感的工序，腕部关节容差应更紧；对姿态宽容、位置敏感的工序，则相反。量级上，臂展 0.5 m 的机械臂，关节容差 0.01 rad 对应末端位置偏移的典型量级在毫米级，可作为分配的起点，最终以雅可比数值验证。

4. 命名位姿：定义、引用与保存

命名位姿有两条生命周期。静态生命周期在配置期：Setup Assistant 把调试好的构型写入 SRDF 的组状态，随配置包分发。动态生命周期在运行期：接口可以读取当前关节值并以名称保存到内存中的位姿表，也可以查询既有命名位姿的数值。

两条路径的差异需要分清：运行期保存的位姿只在进程内存中有效，重启即消失；写入 SRDF 的位姿持久，但需要重新生成或手工维护配置文件。工程惯例是：随产品固化的标准位姿进 SRDF，任务运行期的临时构型用内存位姿表，绝不把调试期随手保存的内容误当作持久定义。

实现思路与设计

目标体系的建设分四步：清点位、定容差、写引用、做校验。

  1. 清点位：列出工序需要的全部标准位姿，逐个在界面或仿真中摆位，确保无碰撞且关节有余量。
  2. 定容差：按工序精度要求与关节敏感度分配容差，形成容差表。
  3. 写引用：代码与配置中的位姿名称来自同一清单，禁止手工拼写。
  4. 做校验：位姿变更后运行碰撞与可达性检查，校验通过才更新基准。

容差分配示例表（臂展约 0.5 m 的六轴臂）

关节建议容差依据
joint_1（基座回转）0.02 rad回转半径大，位置敏感，姿态宽容
joint_2 至 joint_3（大臂、前臂）0.015 rad位置主导，按臂展误差量级取舍
joint_4 至 joint_6（腕部）0.005 至 0.01 rad直接决定末端姿态精度，适当收紧
夹爪指0.002 m开合行程短，容差与工件尺寸公差挂钩
设计决策：为什么容差按关节差异化、放弃全组统一？

全组统一容差实施简单，但把精度预算平均分给了敏感度完全不同的关节。差异化的直接收益有两项：精度预算花在刀刃上，末端误差分布与工序要求匹配；难解关节获得适度松弛，规划成功率提升。差异化带来维护成本，用一张容差表把数值与其依据固化下来即可控制。该表在第 018 章的验收指标中会成为精度项的判定基准。

关键代码与解读

本节给出三段片段：约束消息的逐关节构造、命名位姿的读取与运行期保存、目标集合的完整性校验。

片段 1：逐关节构造约束

// 容差表：数值来自设计阶段的分配，代码只做引用
const std::map<std::string, double> tolerance = {
    {"joint_1", 0.02}, {"joint_2", 0.015}, {"joint_3", 0.015},
    {"joint_4", 0.01}, {"joint_5", 0.01}, {"joint_6", 0.005}};

std::vector<moveit_msgs::msg::JointConstraint> constraints;
const std::map<std::string, double> q_target = {
    {"joint_1", 0.0}, {"joint_2", -0.6}, {"joint_3", 1.0},
    {"joint_4", 0.0}, {"joint_5", 0.7}, {"joint_6", 0.0}};

for (const auto& [name, angle] : q_target) {
  moveit_msgs::msg::JointConstraint jc;
  jc.joint_name = name;
  jc.position = angle;
  jc.tolerance_above = tolerance.at(name);   // 双侧容差对称分配
  jc.tolerance_below = tolerance.at(name);
  jc.weight = 1.0;                           // 采样规划器下保持默认权重
  constraints.push_back(jc);
}
// 约束向量一次性写入目标：接口把它展开为规划请求的约束集合
group.setJointValueTarget(constraints);
group.setGoalJointTolerance(0.005);   // 兜底全局容差：不覆盖逐关节设置

解读：这段代码把容差表变成可执行的目标构造。（1）约束逐关节构造，容差逐项指定；循环套用统一数值会抹平关节间差异，容差的差异化分配由此落到实处。（2）使用名称索引的映射表，顺序无关；权重保持默认，避免在当前规划器下引入未经验证的行为。（3）全局容差作为兜底存在，与逐关节约束的交互规则以对应版本文档为准；冲突时通常以更具体的逐关节设置为准。

片段 2：命名位姿的读取与运行期保存

// 引用 SRDF 中的命名位姿：含义与界面下拉框一致
group.setNamedTarget("ready");

// 读取命名位姿的数值：用于检查定义内容或复用到其他计算
std::map<std::string, double> values;
if (group.getNamedTargetValues("ready", values)) {
  for (const auto& [name, angle] : values) {
    RCLCPP_INFO(node->get_logger(), "%s = %.3f rad", name.c_str(), angle);
  }
} else {
  // 名称不存在：尽早报错，避免带着空目标继续规划
  RCLCPP_ERROR(node->get_logger(), "命名位姿 ready 未定义");
  return;
}

// 运行期保存：把当前关节值登记为内存位姿，重启后失效
// 适合任务过程中的临时构型，例如示教得到的过渡点
group.rememberJointValues("taught_point_01");
// 之后可直接 setNamedTarget("taught_point_01") 复用

解读：命名位姿的读写都有明确用途和边界。（1）读取接口让"位姿里到底是什么数值"可查，排查"引用成功但姿态不对"这类问题时用它核对。（2）名称缺失时立即报错并返回，把定义错误挡在规划之前；静默继续会让失败原因转移到规划阶段，增加定位成本。（3）运行期保存注明"重启失效"，避免把临时构型当作持久定义依赖；需要持久化的位姿应回到配置流程写入 SRDF。

片段 3：目标集合的完整性校验

def validate_goal(goal, variable_names, limits, margins=0.05):
    """校验关节目标：覆盖完整、限位留余量、容差合理。

    goal: {关节名: (目标值, 容差)}
    variable_names: 组的变量名清单
    limits: {关节名: (下限, 上限)}
    """
    problems = []
    for name in variable_names:
        if name not in goal:
            problems.append(f"目标缺少关节 {name}")
            continue
        value, tol = goal[name]
        low, high = limits[name]
        span = high - low
        # 检查一：目标落在限位内且保留余量，避免贴边构型
        if value < low + margins * span or value > high - margins * span:
            problems.append(f"{name} 目标贴边：{value:.3f}")
        # 检查二：容差不能大过余量，否则区间可能越界
        if tol > margins * span:
            problems.append(f"{name} 容差过大：{tol:.3f}")
    return problems

# 校验失败即拒绝构造规划请求：错误尽早暴露在任务层
# 示例用三关节片段演示，漏填 joint_3 时应被覆盖检查捕获
names = ["joint_1", "joint_2", "joint_3"]
limits = {"joint_1": (-2.9, 2.9), "joint_2": (-2.6, 2.6),
          "joint_3": (-2.6, 2.6)}
goal = {"joint_1": (0.0, 0.02), "joint_2": (-0.6, 0.015)}
issues = validate_goal(goal, names, limits)
if issues:
    print("目标校验未通过：")
    print("\n".join(issues))

解读：校验函数把设计约束固化成代码。（1）覆盖检查确保约束数与自由度一致，杜绝"漏了一个关节、规划器自由发挥"的隐性欠约束。（2）限位余量检查与第 010 章的 5% 原则一致，容差与余量的联合检查避免"目标在界内但容差区间出界"的组合错误。（3）校验放在任务层、位于规划层之前，问题在构造请求前就被拦截，错误信息携带关节名与数值，定位成本最低。

常见坑

  • 命名位姿与模型改版脱节：URDF 增删关节后，SRDF 组状态缺项，引用时报错或产生欠约束目标。修复：模型变更后重新生成或核对位姿定义，把位姿覆盖率纳入配置检查。
  • 全组统一容差：精度预算分布失配，末端姿态误差超标而大臂关节过度紧张。修复：按本章容差表差异化分配。
  • 误用零权重：约束被软化为可忽略项，规划结果显示目标未精确达成。修复：默认权重 1.0；调权重前确认规划器对权重的语义。
  • 把运行期保存的位姿当持久定义：重启后名称不存在，任务失败。修复：持久位姿写入 SRDF；运行期位姿在任务开始时重建。
  • 目标保存时处于碰撞状态：引用后规划失败，错误码却指向起点，排查容易从起点入手、错过真正原因。修复：保存位姿前做碰撞检查，位姿库维护流程中加入这一步骤。

练习与思考

  1. 读取 ready 命名位姿的关节数值，与界面显示的关节滑动条位置对照，解释两者应当一致的原因。★
    提示
    界面与代码引用同一份 SRDF 定义；不一致时检查是否保存过同名位姿或模型是否重新生成。
  2. 设计一组欠约束目标：锁定 joint_1 至 joint_4 与夹爪指，放开 joint_5 与 joint_6，观察规划结果的位姿分布，并说明这种目标适合什么类型的工序。★★
    提示
    适合对末端姿态宽容、对位置敏感的任务，例如大面积平面放置；放开关节让规划器选择更顺的构型。
  3. 预测实验：把腕部关节容差从 0.005 rad 放宽到 0.05 rad，预测规划成功率与末端姿态偏差两个指标的变化方向，并设计验证方法。★★
    提示
    成功率上升、姿态偏差变大；用同一目标重复规划 20 次统计成功率，用正运动学比对实际停位与目标的姿态差。
  4. 设计题：为一条包含六个标准位姿的装配流程编写位姿库规范：命名规则、每个位姿的碰撞校验方法与容差依据，以及模型改版后的复核清单。★★★
    提示
    命名建议带工序前缀（如 place_pre、place_down）；校验含碰撞检查与限位余量检查；复核清单以"位姿引用点复用同一清单"为原则。

小结

  • 任何目标在内部都归结为约束集合；约束数少于自由度时形成可探索的子空间目标。
  • JointConstraint 由目标位置、双侧容差与权重构成；权重语义随规划器而变，默认值最稳。
  • 容差经雅可比传播到末端误差，分配按关节敏感度差异化，0.01 rad 量级是常见起点。
  • 命名位姿分静态（SRDF）与动态（内存）两条生命周期，工程上各用其所。
