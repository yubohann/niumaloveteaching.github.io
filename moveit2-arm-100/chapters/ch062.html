第四篇 · 抓取与操作任务

第 062 章：使用 Pick and Place Pipeline

把单个抓取候选扩展为完整作业行为：Pick and Place 管线的阶段划分、每阶段的位姿来源与场景变更，以及直线接近段为什么必须用笛卡尔路径。

  • 主题：抓取任务管线（Pick and Place Pipeline）
  • 关键机制：阶段划分 / 笛卡尔直线接近 / 附着物体时序
  • 预计学时：55 分钟
  • 前置章节：第 061 章

学习目标

  • 掌握 Pick and Place 管线的阶段划分，能为每个阶段说明位姿来源、手爪状态与规划空间选择。
  • 理解接近段（Approach）与回退段（Retreat）必须使用笛卡尔直线插补的原因，掌握步长参数与路由点数估算。
  • 掌握附着物体（Attached Collision Object）的创建、转移与释放时机，理解其与自碰撞检测的关系。
  • 了解 MoveIt1 pick_place 管线与 MoveIt2 实现路径的差异，能说明 GraspPlanning 服务与任务级状态机各自承担的角色。
  • 会为一条抓取流水线设计参数表与失败恢复分支。

背景与动机

上一章输出的是抓取候选：夹爪在抓取瞬间的位姿、张开量与质量分。单条规划请求无法完成任务，因为一次作业还包含手爪开合、物体附着关系变化、中途位姿切换与失败回退。Pick and Place 管线（Pick and Place Pipeline）解决的就是"如何把候选组织为可执行、可验证、可恢复的作业流程"这一问题。

在 MoveIt 生态中，这一管线的形态随发行版演进：MoveIt1 提供内置的 pick_place 管线，把接近段与回退段的生成、手爪动作与场景切换封装在 move_group 的能力插件中；MoveIt2 的 move_group 默认不提供该能力，常用替代路径为任务级 action server 自管理阶段推进，或使用 MoveIt Task Constructor（MTC）以阶段（Stage）与求解器（Solver）组合描述任务。本章按"阶段划分原理 + 可自实现的管线"展开，接口细节以对应发行版官方文档为准。

本章与上一章的关系是"候选到作业"；与第 063、064 章的关系是"作业到接口"，那两章分别讨论 Pick 与 Place 的 action 消息化表达。

核心原理

1. 阶段划分：每个阶段回答一个问题

抓取作业可分解为六个阶段，每个阶段的职责、手爪状态与场景状态都有明确定义：

阶段位姿来源手爪状态规划方式与场景变更
预抓取（Pre-Grasp）抓取位姿沿接近方向后退 da张开关节空间规划，场景不变
接近（Approach）从预抓取位姿直线进入抓取位姿张开笛卡尔直线，末端碰撞检查
夹紧（Close）位姿保持闭合手爪动作，随后附加物体
回退（Retreat）沿接近方向直线后退 dr闭合笛卡尔直线，物体已附着
搬运（Transport）放置位姿上方（放置位姿 + 退距）闭合关节空间规划，可抬高过渡
放置与释放（Place / Release）下降到放置位姿，张开后直线退出先闭合后张开笛卡尔直线加手爪动作

阶段划分的价值在于把"成功与否"细化到可诊断的粒度：规划失败发生在哪个阶段、是碰撞、超出可达范围还是手爪未夹稳，由阶段的返回状态直接给出，避免把整条流水线的失败混为一个布尔值。

2. 直线段的原理：为什么接近不能走关节空间

关节空间规划只约束起止两端，中间路径由采样或优化产生，末端轨迹是曲线。对接近段而言这意味两处风险：末端可能从侧向接近物体，指尖刮擦被抓物或台面；接近方向偏离物体表面法向，实际接触位置与抓取候选不一致。

笛卡尔直线段对末端位姿做参数化插值：位置用线性插值，姿态用球面线性插值（Spherical Linear Interpolation, SLERP），再对每个插值点求逆运动学（Inverse Kinematics, IK），得到关节路点序列。

P(t) = P0 + t (P1 − P0)，R(t) = SLERP(R0, R1, t)，t ∈ [0, 1] 长度 0.10 m 的接近段、步长 Δ = 2 mm 时约产生 50 个位姿插值点，每点需一次 IK 求解

整段成功率随路点数衰减：若单点 IK 成功率 p，则长度 M 的直线段一次通过概率约为 pM。p = 0.999、M = 50 时约 95%；p = 0.95、M = 50 时不足 8%。因此直线段对机械臂的灵巧性配置（IK 插件、冗余自由度）更敏感，失败时优先检查工作空间边界与奇异位形；盲目减小步长会增大路点数，反而进一步压低整段成功率。

3. 附着物体的时序与语义

抓起物体后，物体的碰撞体必须从"场景静态障碍"转换为"随臂运动的附着物体"（Attached Collision Object）：

  • 夹紧前：物体是场景中的碰撞体，指尖与物体的接触需要在碰撞矩阵（或允许接触物体列表）中放行，否则接近段会在接触瞬间被判为碰撞。
  • 夹紧后：调用附加操作（attach），物体从场景移除并绑定到指定连杆（通常是夹爪基座连杆），此后碰撞检查把物体视为机械臂的一部分。
  • 释放时：先分离（detach），把物体放回场景的当前位置，再张开手爪。

附加操作把"物体随臂运动"的假设引入碰撞世界，附加与分离的时机错误会产生两类典型故障：过早附加导致物体在空中"悬空跟随"，过晚附加导致回退段与静止物体自碰撞误报。

4. MoveIt1 与 MoveIt2 的实现路径对比

方面MoveIt1 pick_place 管线MoveIt2 常见路径
接近/回退生成管线根据 GripperTranslation 自动生成由任务层计算，用笛卡尔路径接口执行
手爪动作PickupGoal 内嵌抓取前/后姿态轨迹任务层调用夹爪接口（第 066 章）
场景切换管线内完成附加与分离任务层调用规划场景接口
抓取生成GraspPlanning 服务委托外部生成器同左，服务定义保留

理解这一对比的意义在于：MoveIt2 中 pick and place 的"管线"是一个需要自行搭建的任务层，本章的阶段划分与参数表即该任务层的设计蓝图。

实现思路与设计

自建管线的实现步骤：

  1. 接口约定：定义抓取候选（位姿、张开量、接近方向、质量分）与放置目标（位姿、退距）的数据结构。
  2. 位姿派生：由抓取位姿计算预抓取与回退位姿，由放置位姿计算预放置位姿，全部保持姿态不变。
  3. 规划分发：接近与回退段调用笛卡尔路径接口；其余段调用关节空间规划接口。
  4. 场景同步：手爪闭合确认成功后再附加物体；释放前先分离，再张开。
  5. 失败恢复：每个阶段定义回退动作（撤销场景变更、手爪复位），候选轮换重试。
  6. 状态发布：把阶段名与结果作为反馈发布，供上层监控与调试。

管线参数表

参数典型值作用取值依据
接近退距 da0.05–0.15 m预抓取位姿在接近方向上的退距大于指尖长度，对方向误差留余量
回退距离 dr0.08–0.15 m抓取后直线退出距离避免指尖与台面或物体刮擦
接近速度0.02–0.1 m/s接触前末端速度降低接触冲击与位置偏差
笛卡尔步长0.002 m直线段插值密度平滑性与路点数的折中
搬运速度比例0.3–0.5搬运段相对最大速度的缩放夹持力余量与动态扰动折中
闭合超时0.8 s判定夹紧完成的时间上限覆盖夹爪行程时间并留余量
设计决策：为什么按阶段使用不同速度？

路段的不确定性不同。接近段末端存在物体与夹爪的位置误差累积，速度越低冲击越小；搬运段处于开阔空间，夹持关系已建立，可用较高速度。把所有阶段统一设为低速会显著拉长作业周期，统一设高速则在接触瞬间产生冲击与打滑。按阶段的"接触状态"分层设速是通行做法。

关键代码与解读

片段 1：管线参数文件（按阶段分组）

# pick_place.yaml：抓取流水线的阶段参数
pick_place:
  approach_distance: 0.05        # 预抓取退距：过小则方向误差无处容错
  retreat_distance: 0.10         # 回退距离：须大于指尖长度，防止刮擦台面
  approach_velocity: 0.02        # 接近速度 0.02 m/s：接触前保持低速与低冲击
  transport_velocity: 0.25       # 搬运速度：开阔段提速，缩短单次周期
  cartesian_step: 0.002          # 直线段插补步长：平衡平滑性与 IK 调用次数
  gripper_close_timeout: 0.8     # 闭合超时：超时判为未夹到物体并进入重试
  attach_after_close: true       # 闭合确认成功后再附加物体，保持场景与实际同步
  transport_clearance: 0.08      # 搬运抬升高度：跨越台面障碍的过渡余量

解读：这份配置按阶段组织，读配置即可还原作业的动作序列。（1）接近与搬运分设速度，体现"接触不确定性决定速度"的原则。（2）attach_after_close 编码了第 3 节讲的时序语义：附着动作跟随手爪实际闭合结果，去掉它会造成碰撞世界与真实状态脱节。（3）transport_clearance 约束搬运过渡路径的最小抬升高度，避免直线跨越台面时碰撞。（4）数值全部采用 SI 单位，与消息字段（米、米每秒）保持一致，避免换算引入错误。

片段 2：预抓取位姿派生与笛卡尔直线段请求

import rclpy
from rclpy.node import Node
from geometry_msgs.msg import Pose
from moveit_msgs.srv import GetCartesianPath

class ApproachPlanner(Node):
    """沿接近方向生成抓取直线段：从预抓取位姿进入抓取位姿。"""
    def __init__(self):
        super().__init__("approach_planner")
        # 笛卡尔路径由 move_group 的服务提供：适合短直线，不适合长距离自由移动
        self.cli = self.create_client(GetCartesianPath, "/compute_cartesian_path")

    def pre_grasp_pose(self, grasp_pose, axis, d_approach):
        # 预抓取位姿 = 抓取位姿沿接近方向反向平移退距；姿态保持不变以维持进入方向
        pre = Pose()
        pre.position.x = grasp_pose.position.x - axis[0] * d_approach
        pre.position.y = grasp_pose.position.y - axis[1] * d_approach
        pre.position.z = grasp_pose.position.z - axis[2] * d_approach
        pre.orientation = grasp_pose.orientation
        return pre

    def plan_approach(self, start_state, waypoints, step=0.002):
        req = GetCartesianPath.Request()
        req.group_name = "arm"
        req.start_state = start_state        # 以当前实测状态为起点，减少起点跳变
        req.waypoints = waypoints            # 仅给出端点，服务内部按步长细分
        req.max_step = step                  # 每步位移上限：决定路点密度与 IK 次数
        req.jump_threshold = 0.0             # 0 表示关闭关节跳变检测
        req.avoid_collisions = True          # 直线段同样需要碰撞检查
        return self.cli.call_async(req)

解读：（1）预抓取位姿由矢量平移派生，姿态克隆抓取姿态，保证接近段沿着候选抓取的接近方向直线进入，与第 061 章的生成结果保持一致。（2）请求里 start_state 用当前实测状态，避免用记忆位姿造成起点与控制器实际位置不一致。（3）max_step 控制插值密度：步长越小轨迹越贴合直线，但 IK 调用次数按路程除以步长增长，50 到 100 个路点属常见区间。（4）jump_threshold = 0.0 关闭跳变检测是常用约定；开启时它用于剔除相邻路点间关节突变（常见于穿越奇异位形），代价是可能把可用的冗余解序列误判为跳变。

片段 3：阶段推进与失败回退骨架

STAGES = ("PRE_GRASP", "APPROACH", "CLOSE", "RETREAT", "TRANSPORT", "PLACE", "RELEASE")

def run_pick(node, grasps):
    """按质量分降序遍历候选；任一阶段失败则回退并换下一个候选。"""
    for g in grasps:
        for stage in STAGES:
            ok = node.execute_stage(stage, g)   # 每阶段自成事务：成功才推进
            if not ok:
                node.rollback(stage)            # 撤销场景变更与手爪状态
                break
        else:
            return True                         # 全部阶段完成：抓放成功
    return False                                # 所有候选均失败：上报无解

解读：（1）内层循环依赖 Python 的 for-else 语义：未被 break 中断说明整条阶段序列完成，这是"阶段事务化"的直接表达。（2）rollback 是本骨架的关键：接近段失败要恢复到预抓取姿态，夹紧段超时要张开手爪并脱离物体，否则下一个候选会带着错误的手爪状态开始。（3）候选轮换顺序取质量分降序，与第 061 章的输出排序一致，让成功率高的候选先消耗规划时间。

常见坑

  • 附着时序与手爪实际状态不同步：在发送闭合指令后立即附加物体，手爪未夹住时物体已"悬空跟随"。症状是物体位置与夹爪出现固定偏移。修复：以手爪位置反馈或电流反馈确认闭合成功后再附加。
  • 接近段用关节空间规划：末端走弧线进入，指尖刮擦物体或台面，接触位置偏离候选。修复：接近与回退段改用笛卡尔直线，步长 1–5 mm。
  • 退距小于指尖长度：回退段起点处指尖仍包住物体，直线退出时指尖与被抓物或周边干涉。修复：退距取指尖长度加 5 mm 以上，必要时先垂直抬升再侧向移动。
  • 搬运段直线跨越障碍：从抓取点直线连到放置点上方，路径高度不足。修复：搬运分为抬升、平移、下降三段，抬升高度由障碍物最高点决定。
  • 失败后未恢复场景状态：中途失败留下已附加物体或半闭合手爪，后续候选全部受污染。修复：把"场景与手爪恢复"纳入 rollback 的固定职责。

练习与思考

  1. 把接近退距从 0.05 m 增大到 0.15 m，预测作业周期、接近段成功率与碰撞风险的变化趋势，并给出一个不适合继续增大的理由。★
    提示
    周期变长（多走的直线段按接近速度约多 5 s 量级），对方向误差的容错变好；但预抓取位姿可能离开可达工作空间或进入障碍物密集区，手臂形态也更易触发奇异。
  2. 某接近段长 0.12 m。分别计算步长 2 mm 与 10 mm 时的路点数；若单点 IK 成功率为 0.999，估算两种步长下一次通过的概率，说明为什么慢速直线段仍然偏好小步长。★★
    提示
    路点数约为 61 与 13。一次通过概率约为 0.99961 ≈ 94% 与 0.99913 ≈ 98.7%；小步长牺牲成功率换取轨迹贴合与接触精度，因此实际系统常配合"失败时按允许比例截断并重规划"的策略。
  3. 为"从桌面抓取圆柱杯并放入料框"设计完整阶段表：列出七个阶段的位姿来源、手爪状态与是否使用笛卡尔直线，并标注场景附加/分离发生的时刻。★★
    提示
    参照本章第 1 节表格；附加在夹紧确认之后，分离在张开之前；放置段下降用直线，搬运段用抬升、平移、下降三段关节或笛卡尔混合路径。
  4. 设计实验比较两种实现：任务级状态机与 MoveIt Task Constructor。从阶段复用性、失败诊断粒度、可优化空间三个角度列出评价指标。★★★
    提示
    状态机实现直接、诊断粒度由自定义反馈决定；MTC 以阶段与求解器组合，支持解空间搜索与阶段复用，但需要理解其阶段接口与求解器代价模型。评价时用同一抓放任务测量阶段耗时与失败分布。

小结

  • Pick and Place 管线把抓取候选组织为六到七个阶段，每阶段的位姿来源、手爪状态与场景变更都有明确语义。
  • 接近与回退段使用笛卡尔直线插补（位置线性、姿态 SLERP），路点数由路程除以步长决定，整段成功率按单点 IK 成功率的路点数次幂衰减。
  • 附着物体的时机跟随手爪闭合确认：过早附加产生悬空跟随，过晚附加产生自碰撞误报。
  • MoveIt2 默认不提供 MoveIt1 的 pick_place 能力插件，管线需在任务层实现，GraspPlanning 服务保留用于对接外部抓取生成器。
  • 阶段事务化与失败回退是管线可靠性的核心，下一章讨论把该作业流程封装为 Pick Action 接口的方法。
