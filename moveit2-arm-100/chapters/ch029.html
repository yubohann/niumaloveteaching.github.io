第二篇 · 规划场景与碰撞管理

第 029 章：避障规划

把前面所有场景知识接入规划循环：本章讲障碍如何隐式映射到配置空间、有效性预言机为什么决定规划代价、起点与目标的两道预检、规划后的路径校验与裕量审计，以及动态环境下的重规划策略。

  • 主题：避障规划流程 / 有效性判定接入
  • 关键机制：配置空间与 C 空间障碍、采样连接与边检查、路径校验与裕量审计
  • 预计学时：55 分钟
  • 前置章节：第 028 章

学习目标

  • 理解障碍从工作空间到配置空间（Configuration Space）的隐式映射，以及为什么显式建模 C 空间障碍不可行。
  • 掌握有效性预言机（Validity Oracle）的调用模式与代价结构，理解边检查的细分策略。
  • 会做规划前的起点与目标预检，能把"无解"归因到场景、目标或规划器三个来源。
  • 掌握规划后的两类验证：路径有效性校验与最小裕量审计，并解释前者与后者的分工。
  • 能设计动态环境下的规划-验证-执行循环，给出重规划触发条件与失败升级路径。

背景与动机

至此，规划场景已经具备完整的要素：机器人状态（第 021 章）、世界物体（第 022 至 024 章）、载荷归属（第 025、026 章）、碰撞与距离判定（第 027、028 章）。避障规划把这些要素接入规划循环：给定起点与目标，求一条不碰任何几何的连续路径。它是第二篇前半部分的收束，也是第三篇算法内容的入口。

工程上，避障规划的难点多数落在三个接口层面：场景是否已经正确反映真实环境（场景错了，规划再快也无意义）、起点与目标是否合法（两端不合法的规划必然失败）、规划结果是否经得起执行（采样检查过的地方与执行器实际经过的地方必须一致）。本章把避障规划拆成"预检、规划、验证、执行监控"四段，每一段都给出可操作的检查项。后续第 030 至 034 章把场景侧扩展到传感器数据，第 039 章之后深入规划算法本身。

核心原理

1. 配置空间：障碍的隐式映射

机械臂的一个姿态由 n 个关节变量描述，全部姿态构成 n 维配置空间（Configuration Space, C 空间），六个关节对应六维空间。工作空间中的障碍物在 C 空间中对应一个"禁区"集合：

Cobs = { q | robot(q) ∩ world ≠ ∅ }，Cfree = C - Cobs q 为关节向量；robot(q) 表示该构型下机器人各连杆占据的工作空间区域

规划问题由此表述为：在连通空间 Cfree 内寻找连接起点与目标的连续曲线。Cobs 的几何形状极其复杂：一个长方体障碍在六维空间中的投影边界由分段曲面拼成，维数越高越无法显式构造。采样类规划器（第 040 章展开）的思路因此是"绕开显式构造"：只通过有效性预言机查询任意 q 是否落在 Cfree 内，把 Cobs 当作黑盒。这也是本章与第 028 章的接口所在：预言机的内部实现就是碰撞检测，它的成本特征直接塑造规划算法的行为。

2. 有效性预言机与边检查

采样规划器的两类基本查询是"点查询"（某个状态是否有效）与"边查询"（两个状态之间的直线段是否全程有效）。点查询直接调用碰撞检测；边查询无法穷尽连续统，采用细分策略：先按给定分辨率离散成若干中间状态逐一检查，全部通过则接受该边，发现碰撞则拒绝。分辨率参数的物理含义是"两次检查之间的最大状态距离"，它的选择是漏检风险与检查次数的直接交换（第 028 章已给出量化示例）。

预言机的代价结构还有一个重要侧面：它带状态。碰撞检测器内部维护的场景副本与缓存使相邻查询更便宜，但场景一变更（物体增删、状态更新），依赖位置的缓存失效并需要重建。这解释了工程中的两个经验：批量预计算有效状态对某些算法（如基于路图的规划）收益明显；在场景变动频繁的场景中，规划本身会变慢。

3. 两道预检：起点与目标

规划请求的两个端点各有自己的合法性要求，它们在规划器内部走独立路径，出错时的表现也各不相同：

预检项检查内容失败表现处理方向
起点起点状态是否碰撞、是否超出关节限位规划立即失败，碰撞报告指向起始状态请求适配器可做小幅修正（抖动搜索），超出修正能力则检查状态来源
目标目标约束能否对应的构型存在、目标状态是否碰撞目标附近的投影反复失败，耗时耗尽后无解放宽目标容差、核对目标位姿的可达性与场景占用

一次规划请求的超时可能全部消耗在目标投影上：目标位姿附近的所有候选构型都与场景碰撞时，规划器会用尽尝试预算。把这两道预检显式化（先查起点、再评估目标周围的可用构型），可以让失败归因从"规划器不行"收敛到具体的端点问题。

4. 后处理与两类验证

规划器返回的原始路径通常带有采样算法的痕迹：路点疏密不均、存在不必要的绕行。后处理（平滑、捷径化）在不破坏有效性的前提下缩短与规整路径，属于规划管线内部的自动步骤。管线之外，工程侧还应补两类独立验证：

  • 有效性校验：用当前场景副本对整条路径重新做一次翻边检查，回答"路径仍然无碰撞吗"。它的价值在场景可能已经变化：规划与执行之间存在时间差，校验用最新场景判断路径是否仍然可用。
  • 裕量审计：沿路径抽查或全量计算到障碍的最小距离，回答"路径有多安全"。有效性只保证不相交，裕量给出安全深度；对执行期抖动与感知误差而言，裕量比布尔有效性更能指导取舍。

两类验证的代价不同：有效性校验与规划内部检查同量级，裕量审计使用距离查询（第 027 章），按抽样比例控制成本。推荐把有效性校验固定在每次规划之后，裕量审计按任务风险等级抽样执行。

5. 动态环境：规划-验证-执行的闭环

真实工位的场景不静止：新工件进入、载荷状态变化、人员靠近日渐成为感知系统的重要内容（第 030 至 034 章）。静态一次性规划的前提随之失效。标准应对是闭环策略：

  1. 规划并验证当前场景下的路径；
  2. 执行期间按固定节拍核对场景偏差（轨迹偏离、障碍新增）；
  3. 偏差超过阈值则暂停执行，用最新场景重新规划；
  4. 连续重规划失败则升级处理（收紧速度、请求清场、退回安全位姿）。

闭环设计的关键参数是重规划触发阈值与升级路径，重规划速度次之：触发过早导致频繁停顿，触发过晚则失去安全价值。工程共识是把触发阈值设在"执行期可确定性停止的距离"之内：机器人在收到停止指令到实际停稳之间仍会前进一段距离，触发裕量必须覆盖这段距离。

实现思路与设计

避障规划的工程流程，每步给出检查项：

  1. 场景就绪：核对物体清单、计数器与预期一致（第 022 至 026 章的确认手段），传感器数据新鲜（第 034 章）。
  2. 端点预检：单独判定起点与目标状态的有效性，目标额外评估候选构型数量。
  3. 提交规划：按任务给出时间预算与尝试次数；首次失败后先提升预算，再考虑修改端点。
  4. 验证：对结果做有效性校验；按风险等级做裕量审计。
  5. 门禁放行：验证与审计都通过才交给执行环节；把验证结论记录为可追溯的任务属性。
  6. 执行监控：按节拍核对场景偏差，触发重规划或升级处理。

关键代码与解读

片段 1：Python 用高阶接口完成一次带障碍的规划（moveit_py 接口随发行版演进，以官方示例结构为准）

import rclpy.logging
from moveit.planning import MoveItPy

log = rclpy.logging.get_logger("avoidance_demo")
robot = MoveItPy(node_name="avoidance_demo")

# 规划组件绑定目标规划组；场景内容由监视器维持（第 019 至 026 章）
arm = robot.get_planning_component("arm_group")

# 目标位姿位于障碍另一侧，避障由规划器在场景几何上自行完成
arm.set_goal_state(pose_stamped_msg=target_pose, pose_link="tool0")

# plan() 内部走完整规划管线：请求适配、采样规划、后处理（第 039 章）
plan_result = arm.plan()
if not plan_result:
    # 无解时按"场景、端点、预算"三层顺序排查，避免直接加大预算
    log.error("未找到避障路径，检查场景内容与目标可达性")
else:
    trajectory = plan_result.trajectory
    # 执行前建议做路径校验与裕量审计（见片段 2 与片段 3）
    robot.execute(trajectory, controllers=[])

解读：（1）该接口把"场景查询、采样规划、后处理"三件事封装在一次调用里，适合作为任务代码的主入口；场景侧的准备与验证仍需显式完成，封装不替代纪律。（2）无解分支的错误信息写成排查顺序，避免笼统的失败描述：场景内容（有没有幽灵障碍）、端点（起点目标是否合法）、预算（时间是否足够）按此顺序检查，命中率远高于随机调参。（3）执行调用之前保留验证钩子，示例注释把它显式标注出来，提醒序列化读取代码的人不要在真实系统里省略。

片段 2：C++ 规划后的路径有效性校验（接口以对应 ROS2 发行版与 MoveIt2 版本的官方文档为准）

// 用当前场景对整条轨迹重新做翻边检查，回答"现在仍然无碰撞吗"
// 传入轨迹对象：其首点即规划起点，校验会逐路点重建状态并判定
std::vector<std::size_t> invalid_waypoints;
bool ok = planning_scene->isPathValid(trajectory, "arm_group",
                                      true, &invalid_waypoints);
if (!ok)
{
  // invalid_waypoints 给出首个失效路点附近的索引，便于定位场景变化区域
  for (std::size_t idx : invalid_waypoints)
  {
    RCLCPP_WARN(node->get_logger(), "路点 %zu 在最新场景下失效", idx);
  }
  // 处理策略：用最新场景重规划；若连续失败，升级为暂停并请求场景核对
  return replan_with_latest_scene();
}
RCLCPP_INFO(node->get_logger(), "路径校验通过，进入执行前门禁");

解读：（1）校验使用"当前"场景，与规划时场景可能不同：规划与执行之间的场景变化正是它要捕捉的目标，它是把静态规划接入动态环境的最小成本手段。（2）失效路点索引把结果从布尔量变成定位信息：失效点集中在中段通常意味着新出现的障碍，集中在两端则更可能是起点或目标区域变化。（3）失效后的处理走重规划路径，并把连续失败的升级策略留在调用方；校验函数本身只做判定，保持职责单一。

片段 3：C++ 沿轨迹做最小裕量审计

// 有效性只回答"碰不碰"；裕量审计回答"离得多远"，供风险分级
collision_detection::DistanceRequest dreq;
dreq.group_name = "arm_group";
dreq.enable_nearest_points = false;      // 只取距离值，不取最近点

double min_clearance = std::numeric_limits<double>::infinity();
std::size_t worst_index = 0;
for (std::size_t i = 0; i < trajectory.getWayPointCount(); ++i)
{
  collision_detection::DistanceResult dres;
  planning_scene->getCollisionEnv()->distanceRobot(
      dreq, dres, trajectory.getWayPoint(i));
  double d = dres.minimum_distance.distance;
  if (d < min_clearance)
  {
    min_clearance = d;
    worst_index = i;                     // 记录最贴近的路点，便于可视化复查
  }
}
RCLCPP_INFO(node->get_logger(), "最小裕量 %.4f m 出现在路点 %zu",
            min_clearance, worst_index);
// 分级策略：低于 0.01 m 拒绝执行；0.01–0.03 m 提示并降速；其余放行

解读：（1）审计逐路点调用距离查询，成本按路点数线性增长；对长轨迹可以按固定间隔抽样，只在抽样结果贴阈值时加密复查。（2）记录最贴近的路点索引让结果可复查：把它推送到可视化工具检查，比只看标量值更容易发现建模误差。（3）三段分级与第 027、028 章的阈值语义一脉相承：拒绝、降速、放行对应不同的工程处置，分级比单阈值给出更平滑的运行表现。

常见坑

  • 场景未就绪就提交规划：物体写入是异步路径，规划立即提交时场景里还没有障碍，规划出的路径直接穿过工件。症状是"偶发"穿越，重跑又正常。修复是主控流程加入场景就绪门禁（物体清单核对）。
  • 把无解全部归因于规划器：目标位姿不可达、目标附近无碰撞自由构型、起点处于碰撞时，任何规划器都无解。修复是预检端点并输出结构化的失败原因，按"场景、端点、预算"顺序排查。
  • 只做有效性、不做裕量：路径无碰撞但贴着障碍掠过，执行期微小偏差即可触发保护或刮蹭。修复是加入裕量审计与分级放行。
  • 重规划触发过晚：监控阈值设得比执行期可确定性停止距离还小，发现偏差时已无法安全停下。修复是阈值与速度、制动距离联合标定，宁早勿晚。
  • 在规划与执行之间复用旧场景快照：场景在两次使用之间已被更新，校验基于的副本过期。修复是每次校验都取最新场景锁视图，校验与规划共享同一份快照的场合要显式确认快照时间。

练习与思考

  1. 概念题：说明"在工作空间给障碍留出裕量"与"配置空间中的禁区"为何存在本质差异，举一个两者的差异在六轴臂上表现明显的例子。★
    提示
    工作空间裕量是几何层面的等距放大；C 空间的禁区边界由关节变量的非线性映射决定，同样尺寸的障碍在不同姿态下对应的禁区形状差别很大，狭窄通道在 C 空间中可能细如丝线。
  2. 参数预测：边检查分辨率从 0.01 收紧到 0.005。估算一次边检查的中间状态数变化，并预测规划时间与漏检风险各自的方向。★
    提示
    中间状态数约翻倍，规划时间上升（检查次数与查询代价同向增长），漏检风险下降。若时间预算固定，可尝试的分支变少，权衡点是任务风险等级。
  3. 设计题：为一条与人共享工作空间的机械臂任务设计"规划-验证-执行"闭环，给出监控节拍、触发阈值、重规划与升级策略，并说明阈值如何与制动距离联合标定。★★
    提示
    监控按控制周期核对偏差；阈值取制动距离加裕量；重规划用最新场景；升级路径为降速、暂停、回安全位。标定方法是实测最大速度下的停止距离，再留 30% 以上余量。
  4. 诊断题：规划器反复无解，但可视化显示起点到目标有一条明显可行的绕行路径。列出至少四种可能原因，并给出验证顺序。★★
    提示
    候选：场景存在不可见障碍（占据栅格残留、幽灵物体）；目标附近无有效构型；起点被判定碰撞（padding 放大）；边检查分辨率过粗导致窄通道被判堵塞。验证顺序从场景清单开始，再到端点状态检查，最后调分辨率复测。
  5. 分析题：对比"规划一次、执行到底"与"规划-验证-执行的闭环"两种策略，从安全裕量、任务节拍、系统复杂度三个角度分析，并给出混合方案的边界条件。★★★
    提示
    闭环安全性高但节拍开销大、复杂度高；静态隔离工位可用一次性规划加执行前校验的混合方案；边界条件包括人员是否可能进入、场景是否变动、任务节拍与重规划耗时的比例。

小结

  • 避障问题在配置空间中表述，C 空间障碍无法显式构造，采样规划通过有效性预言机隐式查询。
  • 预言机的点查询与边查询构成规划内层循环，边检查分辨率是漏检风险与检查次数的交换参数。
  • 起点与目标各有预检，把"无解"归因从规划器收敛到场景、端点与预算三个来源。
  • 规划之后补两类验证：路径有效性校验捕捉场景变化，裕量审计给出安全深度。
