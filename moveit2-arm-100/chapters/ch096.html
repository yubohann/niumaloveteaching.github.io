第 096 章：与视觉系统集成

把成像结果接到规划链路上：讲清相机光学帧约定、按时间戳查询变换、检测与位姿估计的接入方式，以及视觉延迟与抓取成功率的关系。

  • 主题：感知集成 / 视觉与规划衔接
  • 关键机制：光学帧约定、时间同步、按戳变换查询、检测到抓取位姿的映射
  • 预计学时：55 分钟
  • 前置章节：第 095 章

学习目标

  • 理解视觉数据链的五个环节与每环节的时间戳语义。
  • 掌握相机光学帧与机器人参考系的约定差异，会正确组织变换链。
  • 会用按时间戳的变换查询与近似时间同步把图像、检测与位姿对齐。
  • 会从检测结果生成抓取位姿，并把物体写入规划场景。
  • 能定位"看起来对不上"类问题的三个常见来源：帧、时间戳与轴约定。

背景与动机

视觉为抓取提供目标位姿，规划据此生成轨迹，执行端据此闭合夹爪。三个环节任何一处对帧或时间戳处理不当，都会让机械臂朝"过去的物体"或"镜像位置的物体"运动。这类错误在静态演示中不易暴露，在动态场景中直接表现为抓空与碰撞。

视觉集成的难点集中在两处：坐标约定（光学帧与机器人帧的轴向定义不同）与时间一致性（检测结果、变换查询与规划请求各带不同时刻）。把两处处理成固定规范，集成问题就从随机故障变成可检查的清单项。

上一章把感知输出写入规划场景，本章向上游走一步：讲感知结果如何产生、如何变换、何时可信。

核心原理

1. 数据链与时间戳

视觉数据链为：成像（图像与深度）→ 检测（目标框与类别）→ 位姿估计（目标在相机坐标系下的位姿）→ 变换（到规划参考系）→ 场景更新与抓取位姿。每一环产物都携带时间戳，链路上下游的时间戳必须能被追溯，否则无法判断"到达时它还准不准"。

环节产物时间戳语义典型延迟量级
成像图像、深度图曝光时刻与帧率绑定
检测目标框、类别、置信度沿用图像时间戳10–100 ms
位姿估计相机系位姿沿用图像时间戳10–50 ms
变换规划系位姿按上游时间戳查询毫秒级
场景更新场景对象与位姿应用时刻与节拍绑定

2. 帧约定与变换链

相机光学帧按惯例取 Z 轴指向前方、X 轴指向右、Y 轴指向下；机器人常用参考系取 Z 轴向上。把光学帧中的位姿直接当作规划参考系位姿使用，会得到轴向翻转的错误结果。正确流程是先构造完整变换链，再对目标位姿做链式变换。

T规划系←物体 = T规划系←相机 ⊗ T相机←物体 T相机←物体 由位姿估计给出（相机光学帧下）；T规划系←相机 由标定与变换树提供（第 098 章展开标定）

变换链的错误会以固定偏差的形式出现：物体在 Z 方向持续偏一个桌面高度，或者绕某轴翻转。用已知位置的标定物做一次端到端核对，可以同时验证帧约定、手眼变换与轴方向。

3. 时间同步与按戳查询

按到达顺序处理消息在动态场景中不可靠：图像、检测与机器人状态可能乱序或错配。同步策略是用消息自带的时间戳做配对（近似时间同步），变换查询使用同一时间戳，保证"哪一刻的检测配哪一刻的相机位姿"。

有效样本条件：|t检测 − t状态| ≤ Δt同步窗口，且 t检测 在变换树覆盖区间内 同步窗口过宽会把运动中的错配样本放进来，过窄则有效样本不足；窗口按链路上最大抖动估计

若在查询变换时不指定时间戳而取最新值，得到的是"检测之后相机又运动了"的变换，误差与相机运动速度成正比。该误差在相机静止时为零，容易被静态测试掩盖。

4. 位姿估计的质量与代差

位姿估计误差来源包括遮挡、对称性歧义、深度噪声与检测框抖动。工程上以置信度阈值过滤质量不足的样本，并以多帧一致性校验抑制离群：连续若干帧位姿接近才接受，单帧跳变被抑制。

视觉到执行的代差不可避免：从成像到夹爪闭合之间存在检测、规划与执行三段延迟，物体若在此期间被移动，抓取即失效。缓解手段包括缩短链路（就近规划）、提高检测频率、以及抓取前做一次终检（对准后再闭合）。

位置误差传播：σ末端 ≈ σ标定 + r · σ角度 + σ估计 r 为相机到目标距离；角度误差在 0.5 m 距离上按毫米每度放大，说明角度标定精度直接决定抓取命中率

实现思路与设计

视觉集成按"约定、同步、变换、质检、回退"五步设计。约定固化轴向与命名，同步保证时刻一致，变换保证空间一致，质检保证样本可信，回退保证失败可控。

1. 集成接口表

接口方向内容节拍
图像与深度话题输入曝光帧与时间戳传感器帧率
检测结果话题输入类别、框、置信度、时间戳检测帧率
变换树输入规划系与相机系变换静态或低频更新
场景对象话题输出物体几何与位姿（规划系）批量差分
抓取位姿话题或服务输出抓取候选位姿（规划系）按任务请求

2. 质检规则

  1. 置信度阈值：低于阈值的检测不进入位姿估计，直接丢弃并计数。
  2. 多帧一致：位姿与最近若干帧中位数偏差超限时拒绝，等待下一帧。
  3. 工作空间过滤：超出工作空间的位姿判定为误检，不进入场景。
  4. 终检：抓取前用对准位姿复核目标窗口内是否仍有目标，降低代差风险。

3. 回退设计

视觉失败（无检测、置信度不足、变换缺失）必须落入明确分支：等待重拍、请求换观察位、或通知任务层调整。回退分支与第 094 章的恢复器共用分类框架：视觉失败归入环境性失败，第一恢复动作是重拍；修改规划参数无法改变输入质量。

与上一章的差异点：第 095 章假设感知产物已经在场景里，本章回答它们如何产生、以什么精度与时效进入场景；两章合起来覆盖感知到规划的完整接口面。

关键代码与解读

片段 1：按时间戳查询相机到规划系的变换

import rclpy
from rclpy.node import Node
from rclpy.time import Time
from tf2_ros import Buffer, TransformListener


class VisionAdapter(Node):
    """视觉适配节点：把相机系位姿变换到规划参考系。"""

    def __init__(self):
        super().__init__("vision_adapter")
        self.tf_buffer = Buffer()
        # 变换监听器持续缓存变换历史：按戳查询依赖历史数据
        self.tf_listener = TransformListener(self.tf_buffer, self)

    def to_planning_frame(self, stamp, frame_id, planning_frame="world"):
        """关键：查询与检测同一时间戳的变换；取最新变换会产生运动错配。"""
        try:
            t = self.tf_buffer.lookup_transform(
                planning_frame,         # 目标参考系
                frame_id,               # 源参考系：相机光学帧
                Time.from_msg(stamp),   # 与检测同一时刻，避免运动错配
                timeout=rclpy.duration.Duration(seconds=0.05),
            )
        except Exception as exc:
            # 变换缺失或时间戳超出缓存：返回原因供上层重试或重拍
            return None, f"变换查询失败: {exc}"
        return t, "ok"

解读：按戳查询是这段代码的全部重点。设计要点：（1）变换缓冲依赖监听器持续收集，节点启动后需要一段时间才能覆盖历史时间戳；（2）查询超时设置很小（50 ms），失败快速返回，避免拖住感知管线；（3）失败原因文本化，上层可直接用于日志与恢复分类。若改为取最新变换，相机运动速度 0.5 m/s、时间错配 0.1 s 时位置误差约 5 cm，远超抓取容差。

片段 2：检测与图像的时间同步

from message_filters import Subscriber, ApproximateTimeSynchronizer
from sensor_msgs.msg import Image
from vision_msgs.msg import Detection2DArray


class Fusion(Node):
    def __init__(self):
        super().__init__("vision_fusion")
        # 两个来源频率不一致时，近似同步按时间戳寻找最近配对
        self.image_sub = Subscriber(self, Image, "/camera/image_raw")
        self.det_sub = Subscriber(self, Detection2DArray, "/detections")
        sync = ApproximateTimeSynchronizer(
            [self.image_sub, self.det_sub],
            queue_size=10,
            slop=0.05,          # 同步窗口：按链路最大抖动设定，过宽会放入错配
        )
        sync.registerCallback(self.on_pair)

    def on_pair(self, image, detections):
        # 配对成功的样本直接使用图像时间戳：下游全链路沿用同一时刻
        stamp = image.header.stamp
        for det in detections.detections:
            if det.results[0].hypothesis.score < 0.6:
                continue        # 置信度过滤：低质量检测不进入位姿估计
            self.handle_detection(det, stamp)

    def handle_detection(self, det, stamp):
        # 位姿估计、变换与场景更新在后续处理中完成（片段 3）
        self.get_logger().debug(f"配对样本: 检测 {det.id} @ {stamp.sec}")

解读：同步器把"帧率不一致的两个来源"变成可处理的配对样本。设计要点：（1）同步窗口 0.05 s 的取值依据是链路抖动上界，窗口内配对成功即代表时刻一致性满足要求；（2）配对后统一采用图像时间戳，后续变换查询与场景更新都沿用该时刻，链路时间可追溯；（3）置信度过滤放在同步之后、位姿估计之前，节省算力。检测消息的字段结构随消息包版本演进，读取假设与分数的写法以本地消息定义为准。

片段 3：从检测到位姿与抓取候选

from tf2_geometry_msgs import do_transform_pose
from geometry_msgs.msg import PoseStamped


def detection_to_grasp(adapter, det_pose_cam, stamp, frame_id,
                       tool_offset_z=0.10):
    """把相机系目标位姿转换为规划系抓取候选位姿。

    det_pose_cam: 位姿估计输出，位于相机光学帧
    tool_offset_z: 工具端沿接近轴退让距离，避免指面与桌面干涉
    """
    tf, reason = adapter.to_planning_frame(stamp, frame_id)
    if tf is None:
        return None, reason

    # 目标位姿补齐头部信息后做链式变换：避免手工乘四元数引入轴序错误
    pose_in = PoseStamped()
    pose_in.header.frame_id = frame_id
    pose_in.header.stamp = stamp
    pose_in.pose = det_pose_cam
    pose_world = do_transform_pose(pose_in, tf)   # 名称与签名随版本略有差异

    # 抓取位姿沿接近轴退让：接近方向定义为物体坐标系 Z 轴
    grasp = PoseStamped()
    grasp.header.frame_id = "world"
    grasp.header.stamp = stamp
    grasp.pose = pose_world.pose
    grasp.pose.position.z += tool_offset_z

    # 位姿进入场景与规划前先做工作空间过滤（质检规则的第三项）
    if not in_workspace(grasp.pose.position):
        return None, "超出工作空间"
    return grasp, "ok"

解读：这段函数串起变换、退让与过滤三个动作。设计要点：（1）变换输入来自片段 1 的按戳查询结果，链式变换交给几何库完成，避免手写四元数乘法；（2）退让距离沿物体坐标系 Z 轴施加，接近方向在物体模型约定中固定，不同工件的退让量按尺寸调整；（3）工作空间过滤放在最后一步，拒绝结果与成功路径使用同一返回值形状，调用方处理逻辑统一。抓取候选进入规划前，还应把目标物体写入场景并附加为待抓取对象（第 025 章）。

常见坑

  • 把光学帧位姿直接当规划系位姿：轴方向翻转导致目标点偏到镜像位置。修复：固定"先变换链、后使用"的规范，验证阶段用已知标定物核对。
  • 取最新变换：相机移动时检测与变换时刻错配，静态测试正常，运动中偏差偏大。修复：全链路沿用一个时间戳，查询使用该时间戳。
  • 同步窗口设置过宽：错配样本进入下游，位姿在物体运动时抖动。修复：窗口按链路抖动上界设定，并用配对质量统计核对。
  • 单帧检测直接触发抓取：离群帧造成朝错误位置运动。修复：多帧一致性校验加终检，任一不过则重拍。
  • 忽略代差：检测到抓取之间物体被移动，抓空后任务判失败原因写成规划问题。修复：按链路易感时间评估代差风险，必要时在执行前重测目标位姿。

练习与思考

  1. 写出把相机光学帧中的目标位姿变换到世界系的完整链式公式，标注每一段变换的来源与获取方式。★
    提示
    世界←相机来自标定与变换树，相机←物体来自位姿估计；两段相乘得到结果，任一段缺失时不得用近似帧替代。
  2. 计算错配误差：相机运动速度 0.3 m/s，同步错配 0.15 s，位置误差约多少？若把同步窗口收窄到 0.05 s，误差降到多少？★★
    提示
    0.3 × 0.15 = 45 mm；收窄后约 15 mm，仍高于常见抓取容差 10 mm，说明还需减少相机运动或提高帧率。
  3. 改参数并预测：置信度阈值从 0.6 提高到 0.85，误检进入场景的概率与有效检测量分别如何变化？给出阈值选择的指标。★★
    提示
    误检率下降、有效样本不足风险上升；选择依据是抓取成功率对误检与漏检两类成本的敏感度对比。
  4. 设计多帧一致性校验器：窗口长度、偏差度量、通过条件与失败回退，并说明对运动物体的影响。★★★
    提示
    窗口覆盖若干帧、偏差取中位数的欧氏距离；运动物体通过条件放宽或引入速度补偿，否则一致性校验会延迟对运动目标的接受。
  5. 说明为什么视觉失败的第一恢复动作是重拍（修改规划参数不改变输入质量），并结合失败分类框架给出判定依据。★★
    提示
    视觉失败属环境性失败，根因在感知输入质量；修改规划参数不改变输入质量，重拍以最低成本获取新样本。

小结

  • 视觉数据链五环节各自携带时间戳，全链路沿用同一时刻是空间正确性的前提。
  • 光学帧与机器人帧轴向约定不同，位姿必须经完整变换链进入规划参考系。
  • 近似时间同步与按戳变换查询解决时刻一致性问题，同步窗口按链路抖动设定。
  • 质检四规则：置信度、多帧一致、工作空间过滤与抓取前终检。
  • 位置误差随相机距离与角度误差放大，标定精度直接决定抓取命中率。
  • 下一章把感知与规划接入更高层：与任务规划系统集成，让符号层的任务决策驱动运动层执行。
