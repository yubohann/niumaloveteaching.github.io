第 010 章：关节空间运动实现

本章实现第一类运动：目标直接以关节角表达，规划在构型空间中完成；重点讲清路径与时间参数化的分工，以及与笛卡尔空间运动的适用分界。

  • 主题：运动实现 / 关节空间规划
  • 关键机制：关节目标表达、构型空间路径、时间参数化
  • 预计学时：55 分钟
  • 前置章节：第 009 章

学习目标

  • 掌握关节空间目标的三种表达方式：命名位姿、关节角数组、关节约束消息。
  • 理解关节空间运动的几何含义：构型空间中的路径与末端笛卡尔轨迹的关系。
  • 理解路径与轨迹的区别，能说明时间参数化如何把路点序列变成可执行轨迹。
  • 会实现并检查一条关节空间轨迹：路点规模、限位、时间戳单调性。
  • 能根据任务特征判断何时使用关节空间运动，何时必须切换到笛卡尔空间。

背景与动机

机械臂最常见的运动是位置转移：从待机位姿到作业准备位姿，从工位 A 到工位 B。这类运动只关心"到达"，不关心"途中末端走什么形状"，适合在关节空间直接求解：把目标写成关节角，让规划器在构型空间里找一条无碰撞路径。相比在笛卡尔空间指定末端轨迹，关节空间方案不需要反复求解逆运动学，成功率与目标距离的关系平滑，是可靠度最高的一类运动。

课程安排把关节空间放在笛卡尔空间之前，原因在于它最接近规划算法的工作方式：采样规划器搜索的空间就是构型空间，关节目标省略了"位姿到关节"的转换环节，整个链条最短，最适合观察规划系统本身的行为。掌握了本章的目标设置与轨迹检查，第 011 章的笛卡尔运动只需在目标端增加一层逆解转换。

核心原理

本节回答三个问题：关节空间运动在几何上意味着什么、路径如何变成轨迹、为什么它的失败模式比笛卡尔空间温和。

1. 几何含义：构型空间中的连线

关节空间运动的目标是构型空间中的一个点 qgoal。规划器在 C 空间中搜索一条从起点到目标的连续曲线，曲线的每个点都满足关节限位与非碰撞约束。曲线映射到笛卡尔空间后，末端轨迹的形状由运动学决定，通常呈现复杂的空间曲线。

τ: [0,1] → Cfree，q(0) = qstart，q(1) = qgoal 末端轨迹 = FK(τ)，形状不可预测；这是关节空间运动的本质特征，也是它的使用边界

一个直观例子：六轴臂从 A 点到 B 点做关节线性插值，末端很可能沿弧线扫过，弧线的半径由各关节的相对转动量决定。当环境空旷时弧线无害；当机械臂需要在两排货架之间直进直出时，弧线可能擦碰障碍，此时关节空间运动不适用。选择依据因此可以总结为一句话：只关心到达且周围有安全余量时用关节空间，关心途中末端形状时用笛卡尔空间。

2. 路径与轨迹：时间从哪里来

规划器输出的首先是几何路径：一串路点构成的序列，求解过程只关心几何可行性。可执行还需要第二道工序，时间参数化：为每个路点分配时间戳与速度，让整条曲线在关节速度上限内平滑通过。

关节空间的时间分配与每段路点的关节位移直接相关。设相邻路点的关节向量差为 Δq，允许的最大关节速度上限经过缩放因子 s（0 < s ≤ 1）收缩，则单段的时长下界为：

tseg ≥ maxi ( |Δqi| / (s · vmax,i) ) 取各关节所需时长的最大值：位移最大的关节决定本段节奏，其余关节放慢跟随

速度上限与加速度上限来自关节限位配置；缩放因子是接口层的安全系数。时间参数化的存在解释了三个日常现象：调低速度缩放会等比拉长执行时间而不影响规划结果；同一路径重放时时间戳不会变化；规划成功的轨迹仍然可能被控制器拒绝，理由是执行侧的速度或时间约束更严。

3. 三种目标表达与容差

关节目标有三种表达方式，复杂度递增：

  • 命名位姿：引用 SRDF 中保存的组状态，工程上最简洁，适合固定工位之间的转移。
  • 关节角数组：按组变量顺序给出的完整数值，适合程序生成的动态目标。
  • 关节约束消息：为每个关节指定目标位置与上下容差、权重，是表达"允许落在范围里"的最强形式。

容差是三种表达里最需要理解的参数。命名位姿与数组表达对应"精确到达"（默认可配容差），约束表达允许目标是一个小区间。容差收紧会让收敛更困难，个别难解的构型上规划时间明显上升；容差放宽则可能让相邻路点之间的动作与预期出现细微偏差。工程起点可以取 0.01 rad 量级，再按任务精度要求调整。

4. 失败模式的友好性

关节空间运动的失败原因收敛于两条：目标本身不可达（超出限位或位于碰撞区域），或搜索预算不足。这两条都由参数与场景直接决定，不涉及逆解的收敛性与奇异位形。对比之下，笛卡尔目标的失败还多一层"逆解不存在"的可能性。因此调试流程中最常用的策略是先用关节空间把大范围移动走完，只在工序需要直线轨迹的短距离段切换笛卡尔空间。第 011 章会给出这一组合的完整实现。

实现思路与设计

关节空间运动的实现按五步推进：定目标、设参数、规划、检查、执行。

  1. 确定目标表达：固定工位优先命名位姿；动态目标用数组或约束消息。
  2. 设置参数：规划时间 1.0 s、尝试次数 10、速度缩放 0.2 作为起点。
  3. 规划：起始状态默认取当前状态；批量场景显式管理起点。
  4. 检查轨迹：路点数、限位、时间戳单调性三项速检。
  5. 执行：演示环境用假控制器；真机执行前把速度缩放保持在保守值。

参数表

参数建议值作用取值依据
规划时间1.0 s搜索预算关节目标通常一次命中，预算用于兜底重试
尝试次数10独立重启次数采样规划的重启相当于换随机种子
速度缩放0.2 至 1.0时间参数化系数首次运行取 0.2，稳定后逐步提高
关节容差0.01 rad到达判定松弛量兼顾精度与收敛难度的起点
目标范围限位内留 5% 余量避免贴边目标限位边界的构型附近的可用性差
设计决策：为什么目标设置在限位边界内留余量？

恰好落在限位数值上的目标在数学上合法，工程上却脆弱：数值误差可能让目标被判为越界，贴边构型往往伴随关节速度方向受限，轨迹后处理容易贴住上限。在目标生成阶段把每个关节限制在限位的 95% 范围内，可以消除一整类边界问题，代价只是放弃工作空间边缘的一层薄壳。这个余量策略同样适用于第 011 章的位姿目标生成。

关键代码与解读

本节给出三段片段：三种关节目标的设置、时间分配的估算脚本、轨迹的快速检查。

片段 1：三种关节目标表达

// 方式一：命名位姿，引用 SRDF 定义，工程上最简洁
group.setNamedTarget("ready");

// 方式二：关节角数组，顺序与组变量顺序一致
// 数值来源可以是示教器读取、仿真摆位或上一段轨迹的末端
std::vector<double> q_target = {0.0, -0.6, 1.0, 0.0, 0.7, 0.0};
group.setJointValueTarget(q_target);

// 方式三：名称到角度的映射，错拼的关节名会被显式拒绝
std::map<std::string, double> q_map = {
    {"joint_1", 0.0}, {"joint_2", -0.6}, {"joint_3", 1.0},
    {"joint_4", 0.0}, {"joint_5", 0.7}, {"joint_6", 0.0}};
group.setJointValueTarget(q_map);

// 关节目标不经过逆解：容差用关节容差接口设置即可
group.setGoalJointTolerance(0.01);

moveit::planning_interface::MoveGroupInterface::Plan plan;
if (group.plan(plan) == moveit::core::MoveItErrorCode::SUCCESS) {
  RCLCPP_INFO(node->get_logger(), "路点数 %zu，规划耗时 %.3f s",
              plan.trajectory_.joint_trajectory.points.size(), plan.planning_time_);
}

解读：三种表达指向同一个内部目标结构。（1）命名位姿适合固化流程，数组适合程序生成，映射形式在两者之间取得可读性与动态性的平衡。（2）关节容差以标量设置，对组内全部关节统一生效；第 012 章会用约束消息把容差细化到每个关节。（3）路点数与规划耗时是运行数据的两个基本量：同一目标重复规划，耗时会有明显波动（随机采样），路点数量则相对稳定，可把后者作为目标质量的一个粗略指标。

片段 2：时间分配的估算

def segment_time(q_from, q_to, v_max, scale=0.2):
    """估算单段路点的时长下界：位移最大关节决定本段节奏。

    q_from/q_to: 相邻路点的关节向量（弧度）
    v_max: 各关节速度上限（弧度每秒）
    scale: 速度缩放因子，与规划接口设置保持一致
    """
    t_min = 0.0
    for a, b, v in zip(q_from, q_to, v_max):
        delta = abs(b - a)                      # 本关节的位移量
        t_min = max(t_min, delta / (scale * v)) # 取各关节需求的最大值
    return t_min

# 示例：两个路点之间 joint_2 位移 1.2 rad，速度上限 1.5 rad/s
v_max = [2.0, 1.5, 1.5, 2.0, 2.0, 2.0]
q_a = [0.0, -0.6, 1.0, 0.0, 0.7, 0.0]
q_b = [0.1, 0.6, 1.0, 0.0, 0.7, 0.0]
# 位移最大的是 joint_2（1.2 rad），缩放 0.2 后段时长下界约 4 s
print(f"段时长下界约 {segment_time(q_a, q_b, v_max):.2f} s")
# 与轨迹消息中的 time_from_start 差对照，可以判断后处理是否接近下界运行

解读：这段脚本把时间参数化公式变成手边的估算工具。（1）公式取各关节需求的最大值，符合驾驶直觉：车队速度由最慢的车决定，位移最长的关节比其余关节需要更多时间。（2）实际后处理还会加入加速度约束与平滑段，结果通常略高于下界；估算与实测的差值稳定时，说明系统行为一致。（3）示例数值演示了量级：1.2 rad 的位移在缩放 0.2 后需要数秒级时间，这就是首次调试取保守缩放时执行节奏缓慢的原因，也是提高缩放对节拍影响敏感的原因。

片段 3：轨迹三项速检

bool checkTrajectory(const moveit::core::RobotState& reference,
                     const moveit::core::JointModelGroup* jmg,
                     const trajectory_msgs::msg::JointTrajectory& jt)
{
  bool ok = true;
  double last_time = 0.0;
  for (const auto& point : jt.points) {
    // 检查一：时间戳单调不减；回绕或倒序说明后处理异常
    double t = point.time_from_start.sec + point.time_from_start.nanosec * 1e-9;
    if (t < last_time - 1e-9) { ok = false; }
    last_time = t;

    // 检查二：路点关节值落在限位内，留 1e-6 数值容差
    if (!reference.satisfiesBounds(jmg, point.positions, 1e-6)) { ok = false; }
  }
  // 检查三：末点时间大于零，说明时间参数化已执行
  if (jt.points.empty() || last_time <= 0.0) { ok = false; }
  return ok;
}

解读：三项检查针对三类不同的异常来源。（1）时间戳单调性捕捉后处理缺陷：重新采样或二次处理拼接轨迹时容易出现时间回绕。（2）限位检查用状态对象的内置方法完成，模型限位是唯一权威；把检查写进程序，避免"肉眼扫一遍路点"的低效做法。（3）末点时间为零意味着轨迹只有几何路径、没有时间信息，执行侧会直接拒绝；这一检查能在发送执行之前拦截。

常见坑

  • 数组长度与组不匹配：给六轴组传了七个数值，报错或静默截断。修复：数组长度一律用组的变量数校验，禁止手写魔数。
  • 目标贴限位或越界：规划失败且错误码指向无效请求。修复：目标生成阶段加入 5% 余量并显式夹取。
  • 期望末端直行却用关节空间：执行时末端扫过弧线，与周围物体干涉。修复：需要直线段的任务改用笛卡尔空间，参见第 011 章。
  • 容差设为零：数值上要求严格相等，采样收敛困难、规划时间暴涨。修复：容差取 0.01 rad 量级起步，按精度要求收紧。
  • 忽略速度缩放的全局作用：把缩放调到 0.05 后以为只是"慢一点"，实际节拍被拉长一个数量级。修复：缩放值与节拍需求一起评估，出厂前用片段 2 估算各段时长。

练习与思考

  1. 实现 home 到 ready 的关节空间运动，记录路点数、规划耗时与执行请求是否成功，并把三项数据记入课程笔记。★
    提示
    重复运行五次观察耗时波动与路点稳定性，理解随机采样对结果分布的影响。
  2. 设计一个"过中间点"的运动：先把手臂摆到一个中间关节姿态，再转到目标；观察两段轨迹拼接处末端的实际轨迹是否连续。★★
    提示
    两段独立规划在中间点处速度通常不连续；连续性要求需要在轨迹层处理，第 015 章的重采样与重定时会展开。
  3. 预测实验：同一目标下把速度缩放从 0.2 提高到 0.8，执行时长与路点数分别如何变化？先写预测，再运行对照。★★
    提示
    缩放只作用于时间参数化：执行时长近似缩短到四分之一附近，路点结构基本不变；若路点数变化明显，说明规划管线配置中还有其它与速度相关的环节。
  4. 推导题：某段轨迹两路点间 joint_3 位移 0.9 rad，速度上限 1.2 rad/s，缩放 0.3；其余关节位移都小于它。推导该段时长下界，并说明实际时长高于下界的两个来源。★★★
    提示
    下界为 0.9 / (0.3 × 1.2) = 2.5 s；实际更高的来源包括加速度上限带来的加速减速过程与路点平滑处理。

小结

  • 关节空间运动以关节角为目标，路径在构型空间中搜索，末端轨迹形状不可预测。
  • 路径与轨迹分属两道工序：时间参数化把路点序列换成带时间戳与速度的可执行轨迹。
  • 三种目标表达对应固定、动态与区间三类需求；关节容差是收敛难度的关键参数。
  • 失败模式友好：目标不可达与预算不足是仅有的两条失败根因，不涉及逆解收敛性。
  • 下一章补齐另一类运动：笛卡尔空间运动，让末端沿指定轨迹运动，并明确两类空间的组合用法。
