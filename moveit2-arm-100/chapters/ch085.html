第 085 章：规划组配置深入：SRDF 与语义

从语义层拆解 SRDF：规划组、末端执行器、命名状态、被动关节与碰撞豁免各自定义了什么，以及它们在规划请求、运动学配置与碰撞检查中的消费位置。

  • 主题：配置模型 / 语义描述
  • 关键机制：运动链与子组语义、命名状态映射、允许碰撞矩阵、运动学求解器绑定
  • 预计学时：55 分钟
  • 前置章节：第 084 章

学习目标

  • 理解 URDF 与 SRDF 的分工：几何结构描述与规划语义描述为何必须分离。
  • 掌握组的三种定义方式（运动链、关节列表、子组）及其空间维度计算。
  • 理解命名状态、末端执行器、被动关节与虚拟关节在运行时被谁消费、如何消费。
  • 理解碰撞豁免项到允许碰撞矩阵（Allowed Collision Matrix, ACM）的映射与代价意义。
  • 会阅读并按需修改 SRDF 与配套运动学配置，并用程序核对组语义。

背景与动机

规划组（Planning Group）是 MoveIt2 的基本寻址单位：规划请求用组名指定规划对象，运动学求解器按组绑定，规划器参数按组配置，控制器按组映射。组语义定义错误时，故障现象往往远离配置位置：组名写错表现为立即失败，维度错误表现为约束无解，碰撞豁免缺失表现为起始状态"莫名碰撞"。

这些配置都写在语义机器人描述格式（Semantic Robot Description Format, SRDF）里。它和 URDF 分工明确：URDF 讲清楚机器人由哪些连杆和关节构成，SRDF 讲清楚"哪些部分作为一个整体规划、哪些状态是常用目标、哪些自碰撞不必检查"。同一份 URDF 可以配多份 SRDF，适配不同任务语义。

上一章把观测手段铺开，本章回到被观测对象的定义层：很多日志与快照中出现的名称与状态，都是在 SRDF 里命名的。

核心原理

1. 组的三类定义与维度

一个组（group）可以由运动链、关节列表或子组构成；子组语义是并集，即组包含全部子组关节加上直接列出的关节。组的规划维度等于组内主动关节的自由度数之和，被动关节与固定关节不贡献维度。

定义方式表达适用场景
运动链基座连杆到末端连杆标准串联臂，唯一路径，语义最清晰
关节列表枚举关节名并联机构、局部联动组
子组引用其它组组合组（双臂整体）、共享腕部时按并集拆分
dim(G) = Σj ∈ 主动关节(G) dof(j) 六轴串联臂与夹爪组成取放组时，若夹爪开合为被动关节，组维度仍为 6；若夹爪为主动关节，维度为 7

命名状态（group_state）给组内关节的一组取值命名，运行时代码用名称引用，避免散落在代码里的魔法数。命名状态经机器人状态对象展开为关节值，再进入规划请求的起始状态或目标约束，这是"名字到数值"的标准映射通道。

2. 碰撞豁免与允许碰撞矩阵

相邻连杆在物理上必然接触，默认碰撞检查会将其判为碰撞。SRDF 的碰撞豁免项列出若干连杆对，将其写入允许碰撞矩阵并标记为"允许碰撞"，碰撞检查跳过这些对。豁免项里标注的原因字段（相邻、默认、从不检查等标签）用于回写与再生成配置，检查逻辑只关心"该对是否列入"。

检查对数 ≈ C(n, 2) − |豁免对| n = 14 个连杆时全部对数为 91；豁免相邻与固定连接对后，单次自碰撞查询的计算量近似按豁免比例下降

豁免不足会制造假碰撞，过多则掩盖真实风险。取舍依据是几何关系与运动范围：永远不相碰的固定连接对可以豁免；运动范围内可能接近的连杆对必须保留检查。

3. 末端执行器、被动关节与虚拟关节

  • 末端执行器（End Effector）：绑定一个夹具组、其父组、以及安装参考连杆，供抓取管线定位夹爪并组织抓取语义。它把"夹具组"与"手臂组"关联起来，抓取规划时两侧协同。
  • 被动关节（Passive Joint）：存在状态但不被传动，例如随动的指节弹簧关节。规划不将其作为自由度，状态同步时仍需给出其数值。
  • 虚拟关节（Virtual Joint）：把机器人根连杆连接到指定的参考系，给浮动基座或移动底盘提供挂载点。固定基座场景通常声明为固定虚拟关节。

4. 语义到规划系统的消费位置

SRDF 语义消费者消费方式
组名规划请求、规划器配置、控制器映射作为键检索对应配置与插件
命名状态机器人状态对象展开为关节值填充起始状态或目标
碰撞豁免规划场景的碰撞检查构建允许碰撞矩阵，裁剪检查对
末端执行器抓取管线组织夹具组与父组的关系
虚拟关节模型加载把模型根挂到参考系

运动学求解器与规划算法通过组名在运动学配置与规划器配置里绑定，不写在 SRDF 中。组名是这三份配置之间的连接键，改名必须三处同步。

实现思路与设计

设计 SRDF 的流程从任务语义反推：先列出"要分别规划哪些部分、以哪些状态为目标、哪些部件不参与规划"，再落成 XML。顺序固定为"链、组、状态、豁免、附属语义"，每一步都可独立验证。

1. 设计步骤

  1. 定义主链组：从基座到工具法兰的运动链，命名体现用途（例如 arm）。
  2. 定义附属组：夹爪等独立组；需要整体规划时用子组组合出整体组。
  3. 定义命名状态：整理、折叠、观察位等常用构型，全部给出数值。
  4. 生成碰撞豁免：由自碰撞检测工具生成候选，结合运动范围人工复核。
  5. 声明附属语义：末端执行器绑定、被动关节、虚拟关节。

2. 关键元素参数表

元素关键属性取值依据
<group>name、chain 或 joint/subgroup命名全局唯一；链的端点须在 URDF 中存在
<group_state>group、name、关节值数值取自人工示教或运动学计算，须校验无碰撞
<disable_collisions>link1、link2、reason相邻、固定连接、几何上不可达的对
<end_effector>name、group、parent_link夹具组名与安装连杆，父组通常为手臂组
<passive_joint>name无传动关节，与 URDF 关节名一致
<virtual_joint>name、child_link、parent_frame、type固定基座取 fixed；移动平台取 planar 或 floating

3. 验证方法

配置完成后做三类核对：组维度与主动关节清单（程序打印）；命名状态的可达性与无碰撞性（状态有效性服务或场景检查）；豁免对与碰撞检测器输出的一致性（人为构造接触位形观察检测结果）。把"组名、维度、状态名"三项写进接口约定，上层代码只依赖约定而不依赖模型细节。

与上一章的差异点：第 084 章的日志与快照让配置错误可以被观察，本章解释这些名称与数值的来源与约束，两者组合构成"配置、观测、修正"的闭环。

关键代码与解读

片段 1：SRDF 关键语义片段

<robot name="demo_arm">
  <!-- 虚拟关节把机器人根连杆挂到世界参考系，固定基座用 fixed -->
  <virtual_joint name="base_link_joint" type="fixed"
                 parent_frame="world" child_link="base_link"/>

  <!-- 主链组：基座到工具法兰，运动链是语义最清晰的定义方式 -->
  <group name="arm">
    <chain base_link="base_link" tip_link="tool0"/>
  </group>

  <!-- 夹具组单独定义，便于抓取语义引用；子组语义为并集 -->
  <group name="gripper">
    <joint name="finger_joint_a"/>
    <joint name="finger_joint_b"/>
  </group>

  <!-- 组合组：双臂场景中把两个主链组合为整体组 -->
  <group name="both_arms">
    <subgroup name="arm_left"/>
    <subgroup name="arm_right"/>
  </group>

  <!-- 命名状态：数值经可达性与碰撞校验后固化，供代码按名引用 -->
  <group_state name="ready" group="arm">
    <joint name="shoulder_pan_joint" value="0.0"/>
    <joint name="shoulder_lift_joint" value="-0.78"/>
    <joint name="elbow_joint" value="0.0"/>
    <joint name="wrist_1_joint" value="-2.36"/>
  </group_state>

  <!-- 碰撞豁免：相邻连杆对不必检查；reason 供再生成配置时保留选择 -->
  <disable_collisions link1="base_link" link2="shoulder_link" reason="Adjacent"/>
  <disable_collisions link1="shoulder_link" link2="upper_arm_link" reason="Adjacent"/>
  <disable_collisions link1="base_link" link2="upper_arm_link" reason="Never"/>

  <!-- 末端执行器把夹具组与手臂组关联，抓取管线据此组织两侧 -->
  <end_effector name="hand" parent_link="tool0" group="gripper"
                parent_group="arm"/>
</robot>

解读：这份片段覆盖 SRDF 的全部关键语义。设计意图：（1）虚拟关节让模型坐标系与仿真或现场的世界参考系解耦，换场地只改一行配置；（2）链、关节、子组三种定义方式各出现在合适位置，组合组用并集语义表达"整体规划"；（3）命名状态固化常用构型，上层代码引用名称，散落在各处的浮点数随之消失；（4）碰撞豁免只列几何上确证安全的对，运动范围内可能接近的连杆保持检查。注意豁免项的 reason 是标注信息，检查逻辑只依据"是否列入"。

片段 2：按组名绑定运动学与规划器配置

# kinematics.yaml：为每个组绑定逆解求解器与其参数
arm:
  kinematics_solver: kdl_kinematics_plugin/KDLKinematicsPlugin
  kinematics_solver_search_resolution: 0.005   # 冗余自由度搜索步长（弧度）
  kinematics_solver_timeout: 0.05              # 单次逆解查询的时间预算（秒）
  kinematics_solver_attempts: 3                # 快速失败并重试优于单次长等待
gripper:
  kinematics_solver: kdl_kinematics_plugin/KDLKinematicsPlugin

# ompl_planning.yaml：顶层定义算法实例，组内按名引用
planner_configs:
  RRTConnect:
    type: geometric::RRTConnect     # 算法类型来自 OMPL 插件注册名
  RRTstar:
    type: geometric::RRTstar
arm:
  default_planner_config: RRTConnect
  planner_configs: [RRTConnect, RRTstar]   # 组可用算法的子集
  projection_evaluator: joints(shoulder_pan_joint, shoulder_lift_joint)
gripper:
  default_planner_config: RRTConnect

# 组名是两份配置与 SRDF 之间的连接键：
# 三处名称不一致时，表现为插件找不到配置或请求组名无效

解读：配置以组名为主键，SRDF 定义"组是什么"，运动学与规划器配置定义"组如何被求解"。设计上把逆解预算拆成"单次超时乘尝试次数"，快速失败可以让上层在总预算内换种子重试，整体成功率高于单次长等待。投影评估器选择两个主关节作为投影维度，针对平面工作场景可以加速采样收敛；组名连接键的思维方式适用于 MoveIt2 的所有配置文件与控制器映射。

片段 3：程序核对组语义（C++）

#include <moveit/robot_model_loader/robot_model_loader.h>
#include <moveit/robot_state/robot_state.h>

void inspect_group(const rclcpp::Node::SharedPtr& node) {
  // 加载器同时解析 URDF 与 SRDF：语义信息来自 SRDF
  robot_model_loader::RobotModelLoader loader(node, "robot_description");
  const moveit::core::RobotModelPtr model = loader.getModel();

  const moveit::core::JointModelGroup* jmg = model->getJointModelGroup("arm");
  if (jmg == nullptr) {
    RCLCPP_ERROR(node->get_logger(), "SRDF 中不存在组 arm");
    return;
  }
  // 维度与主动关节清单是核对配置的两把尺子
  RCLCPP_INFO(node->get_logger(), "组 %s 维度=%u",
              jmg->getName().c_str(), jmg->getVariableCount());
  for (const std::string& name : jmg->getActiveJointModelNames()) {
    RCLCPP_INFO(node->get_logger(), "  主动关节: %s", name.c_str());
  }

  // 命名状态经状态对象展开为关节值：名字到数值的映射通道
  moveit::core::RobotState state(model);
  state.setToDefaultValues();                     // 全零基准，防止未初始化值
  state.setToDefaultValues(jmg, "ready");         // 展开 SRDF 命名状态
  state.update();                                 // 刷新派生量（全局位姿等）
  const Eigen::Isometry3d& tcp = state.getGlobalLinkTransform("tool0");
  RCLCPP_INFO(node->get_logger(), "ready 状态下工具端高度: %.3f m",
              tcp.translation().z());
}

解读：程序核对把"配置意图"变成可打印的事实。关键行为：（1）先校验组存在再取维度，避免空指针在深层调用处崩溃；（2）主动关节清单与维度互为对照，两者与文档不符即为配置错误；（3）命名状态必须先设全零基准再展开，否则未列出的关节保留随机值，打印结果不可复现；（4）更新派生量后才能读取全局位姿，这一步对应状态同步机制（第 009 章）。替代方案是只做可视化核对，效率低且无法进入自动化检查。

常见坑

  • 组维度理解错误：把被动关节或固定关节计入期望维度，规划请求带上多余关节导致维度校验失败。修复：打印主动关节清单核对，被动关节只在状态同步中提供数值。
  • 三处配置组名不同步：SRDF、运动学配置、规划器配置的键名不一致，症状为插件配置缺失或请求报组名无效。修复：把组名清单写入接口约定，修改时三处同步并跑程序核对。
  • 命名状态含碰撞或越限位形：状态数值随手填写，执行时在起始或目标处报碰撞。修复：命名状态落地前用状态有效性检查或场景验证。
  • 豁免过度：为消除假碰撞对把整条运动链互相豁免，真实自碰撞被掩盖。修复：只豁免几何上确证安全的对，并用人为构造的危险位形验证检测仍有效。
  • 子组语义误判为交集：期望"两臂公共部分"而用子组组合，得到的是并集，组维度比预期大一倍。修复：需要单独语义时显式定义关节列表组。

练习与思考

  1. 给定七轴臂加两指夹爪（含一个随动关节），分别计算"手臂组""夹爪组""取放组合组"的维度，并说明依据。★
    提示
    手臂 7 维；夹爪若一主动一被动则为 1 维；组合组为并集，7 + 1 = 8 维。随动关节不贡献维度。
  2. 为一个期望"折叠位、观察位、抓取预备位"三类目标的系统设计命名状态清单，给出每个状态的校验步骤。★★
    提示
    每个状态给出关节值来源（示教或解析计算），落地前做维度校验、限位校验与碰撞校验，最后打印工具端位姿做量级核对。
  3. 改配置并预测：某连杆对从碰撞豁免中移除，随机采样规划的成功率与单次碰撞查询耗时如何变化？给出一个可复现的对照实验设计。★★
    提示
    移除豁免后检查对数增加，碰撞查询耗时上升；若该对在常见位形下接近，采样成功率下降。对照实验固定随机种子与规划预算，比较成功率与平均查询耗时。
  4. 说明为何运动学求解器不写在 SRDF 中，而按组名绑定在独立配置里，并给出这种设计的一个实际好处。★★
    提示
    语义描述与算法选择关注点不同：可替换求解器而不动语义文件，例如同一组在调试环境用一种求解器、在另一环境换用另一种，只改配置不动模型描述。
  5. 推导：双臂组合组的维度与两臂关节数的关系；若两臂共享一个腕部关节（同一关节名），并集语义下维度如何变化？据此说明共享结构应如何分组。★★★
    提示
    并集对同名关节去重，共享关节只计一次；共享结构应按关节清单显式划分组，避免并集把两臂语义合并后无法单独规划。

小结

  • URDF 描述结构，SRDF 描述语义；组名是连接 SRDF、运动学配置与规划器配置的键。
  • 组由链、关节列表或子组定义，子组取并集；维度等于主动关节自由度之和。
  • 碰撞豁免写入允许碰撞矩阵，直接影响假碰撞与检查代价，取舍依据几何关系与运动范围。
  • 命名状态提供"名字到数值"的映射，落地前必须通过碰撞与限位校验。
  • 末端执行器、被动关节与虚拟关节分别服务抓取语义、状态完整性与基座挂载。
