第一篇 · 环境搭建与基础控制

第 003 章：创建机械臂 URDF 模型

本章解决"MoveIt2 眼中的机械臂长什么样"：用链接与关节写出运动学树，用视觉、碰撞、惯性三类几何分别服务显示、规划与动力学。

  • 主题：机器人建模 / URDF 描述
  • 关键机制：运动学树、关节类型与限位、碰撞几何简化
  • 预计学时：55 分钟
  • 前置章节：第 002 章

学习目标

  • 理解 URDF（Unified Robot Description Format）的树形结构与运动学树（Kinematic Tree）的对应关系。
  • 掌握链接（Link）与关节（Joint）的完整写法：视觉、碰撞、惯性、轴向与限位五类元素。
  • 能根据关节类型与数量计算自由度（Degrees of Freedom, DOF），并说明哪些关节参与运动规划。
  • 理解视觉几何与碰撞几何分离的设计动机，能选择合理的碰撞体形状。
  • 会用 Xacro 宏参数化重复结构，并通过 launch 把模型发布到 ROS2 系统。

背景与动机

MoveIt2 的全部计算都建立在一份机器人描述之上：规划器需要知道连杆长度与关节轴向才能判断可达性，碰撞检测需要知道每个连杆占据的几何体积才能判断干涉，RViz 需要模型来显示姿态。这份描述的载体通常是 URDF，或经 Xacro 展开后的 URDF。描述一旦有误，后续所有环节都会异常，且症状常常出现在离原因很远的地方：关节轴向写错会表现为轨迹扭曲，碰撞体过大则表现为频繁的自碰撞报错。

由于 URDF 是纯文本格式，编写与审查都比较直观，但它对细节的容忍度低：单位错误、坐标系约定混乱、惯性参数缺失都会埋下隐患。本章的目标是在动手配置 MoveIt2 之前，先把模型层做正确、做可验证。第 004 章的 Setup Assistant 只能加工正确的模型，无法弥补模型层的结构性错误。

核心原理

本节的原理主线是：URDF 如何把机械臂抽象成树，树上的几何与质量信息如何在规划与动力学中分别发挥作用。

1. 运动学树：链接是节点，关节是边

URDF 的顶层元素是 robot，它包含若干 link 与 joint。每个 joint 连接一个父 link 与一个子 link，并给出子 link 相对父 link 的静态变换（origin）。整个结构必须是一棵树：每个 link 至多有一个父关节，不允许闭环。从基座 link 沿关节链走到末端 link，这条路径称为运动链（Chain），运动链上关节变量的数量就是机械臂的自由度。

Tbase→tool(q) = T1(q1) · T2(q2) · … · Tn(qn) 正运动学（Forward Kinematics, FK）就是沿链累乘各关节变换；反解该式为逆运动学

树形结构决定了规划的可行空间：可独立控制相对位姿的点对仅限同一条链上递推的对象，跨链两点的位姿关系无法用一组关节变量统一表达。六轴串联臂加两指夹爪的自由度为 8，其中末端位姿只由前 6 个关节决定，夹爪关节属于另一条支链。理解这一点，才能理解第 016 章为什么要按链划分规划组。

2. 关节类型与限位

URDF 中常见的关节类型有五种：revolute（有限角度转动）、continuous（无角度上限的连续转动）、prismatic（直线滑动）、fixed（固定连接）、floating 与 planar（自由与平面运动，机械臂中少见）。对规划而言，只有 revolute、continuous、prismatic 产生自由度，fixed 关节只贡献静态变换。

类型自由度需要 limit规划中的注意点
revolute1角度上下限、速度、力矩限位收窄会直接缩小可达工作空间
continuous1仅速度与力矩角度可跨 ±π 连续化，插值需处理绕行方向
prismatic1位移上下限、速度、力矩夹爪开合常用，行程决定可夹持物尺寸
fixed0无常用于传感器与工具安装，合并进父连杆坐标系

限位数值具有实际约束力：规划器在采样时以限位为边界约束，速度上限参与时间参数化。限位填写错误会让规划结果"看起来正常"但无法执行，或让本可达的目标被判为无解。

3. 三类几何：显示、碰撞、动力学各取所需

每个 link 可以带三类几何信息，它们服务于不同的计算：

  • visual：显示用几何，可以是高精度网格模型。视觉细节只影响观感，不影响任何规划结果。
  • collision：碰撞检测用几何，规划过程中每次候选状态都要对整条链做查询，查询成本与几何复杂度直接相关。
  • inertial：质量、质心与惯性张量。运动规划本身只用几何，但动力学仿真与基于动力学的规划器需要真实的质量参数。

把 collision 与 visual 分离是标准做法。一条工业臂的网格模型可能有 104 量级的三角面，而一次规划要对数千个候选状态做碰撞查询，直接使用网格会令单次查询从微秒级退化到毫秒级。碰撞几何常用圆柱、长方体或凸包近似，把面片数量降低两个数量级，同时保持几何外形包住原部件，得到保守的碰撞判定。保守判定带来少量误报（把不碰判成碰），代价远小于漏报（把碰判成不碰）。

惯性的作用在规划阶段较小，但缺失惯性参数会让模型完整性校验发出警告，并令动力学仿真无法运行。惯性的数值可从几何近似估算：均匀圆柱体的转动惯量为 m·r2/2（绕轴）等，量级合理即可满足仿真需要。

4. Xacro：参数化的 URDF 生成器

串联臂的连杆结构高度相似，逐段复制 URDF 会带来维护困难：修改一处半径要改多段。Xacro 是 URDF 的宏扩展格式，支持定义宏（macro）、参数变量与算术表达式，在启动时展开为标准 URDF。参数化的意义在于让"机械臂尺寸"成为一组有名字的变量，几何派生关系（如腕部长度是前臂长度的比例）在描述层直接表达，模型修改从"全文件搜索替换"变成"改一处参数"。

Xacro 展开发生在启动时刻，展开结果可以通过命令行查看与校验。校验工具 check_urdf 会解析模型并打印树结构，这是确认父链关系与关节顺序的最快方式。

实现思路与设计

建模按"定结构、写骨架、补几何、校模型、发布验证"五步推进，每步都有明确的验收标准。

  1. 确定结构与尺寸：先画出关节链示意图：基座、六个转动关节、末端法兰、两个夹爪指；记录每段的长度与限位。
  2. 搭出最小骨架：只写 link 与 joint 的名称、origin、axis、limit，先用基本体代替精细几何。
  3. 补齐三类几何：visual 用圆柱与长方体组合，collision 用保守基本体，inertial 用估算质量与惯量。
  4. 参数化与校验：把重复结构抽成宏，用工具展开并检查树结构、关节数与限位。
  5. 发布验证：用 launch 把描述送进系统，在可视化环境里逐关节拖动，确认每个关节的旋转方向与限位符合直觉。

示例机械臂尺寸表（后文沿用）

部件几何近似尺寸说明
基座 base_link圆柱半径 0.08 m，高 0.10 m固定于工作台坐标系
肩部 joint_1转动，绕 Z限位 ±2.9 rad大臂回转
上臂 link_1圆柱半径 0.05 m，长 0.25 m竖直段
肘部关节 joint_2转动，绕 Y限位 ±2.6 rad俯仰主关节
前臂 link_2圆柱半径 0.045 m，长 0.22 m随动段
腕部三关节转动三轴各 ±2.9 rad姿态调整
夹爪指滑动副 ×2行程 0.04 m末端执行器
设计决策：为什么碰撞体选择同轴圆柱近似、放弃精确网格？

碰撞检测库（如 FCL）对凸体之间的查询有解析算法，速度远高于三角网格互查。圆柱体既能覆盖连杆的旋转体外形，又属于原生基本体，查询路径最短。近似带来的保守偏差用"略大 1 至 2 mm"的半径补偿吸收，牺牲少量误报率换取稳定的查询速度。该策略贯穿本课程的所有练习，直到第 024 章讨论复杂物体的碰撞表示。

与前后章节的接口

关键代码与解读

本节给出三段片段：基础链接与关节的完整写法、用宏参数化重复连杆、以及把模型发布到系统的 launch 文件。

片段 1：基座与第一个转动关节

<robot name="arm_robot" xmlns:xacro="http://www.ros.org/wiki/xacro">
  <!-- base_link 是运动学树的根，其余部件都从它派生 -->
  <link name="base_link">
    <visual>
      <!-- 视觉几何负责显示，允许比碰撞体精细；单位统一为米 -->
      <geometry><cylinder radius="0.08" length="0.10"/></geometry>
      <material name="grey"><color rgba="0.6 0.6 0.6 1.0"/></material>
    </visual>
    <collision>
      <!-- 碰撞几何用同一基本体：查询快；与视觉体一致的近似在本例足够 -->
      <geometry><cylinder radius="0.08" length="0.10"/></geometry>
    </collision>
    <inertial>
      <!-- 质量 2 kg 的均匀圆柱，惯量取解析式：izz=m·r²/2≈0.006，ixx=m·(3r²+l²)/12≈0.005 -->
      <mass value="2.0"/>
      <origin xyz="0 0 0.05"/>
      <inertia ixx="0.005" iyy="0.005" izz="0.006" ixy="0" ixz="0" iyz="0"/>
    </inertial>
  </link>

  <!-- 第一个转动关节：origin 描述子坐标系在父坐标系中的安装位姿 -->
  <joint name="joint_1" type="revolute">
    <parent link="base_link"/>
    <child link="link_1"/>
    <!-- 关节位于基座顶面中心：z 向偏移 0.10 m，姿态不旋转 -->
    <origin xyz="0 0 0.10" rpy="0 0 0"/>
    <!-- 大臂回转轴为 Z 轴：正方向按右手定则绕轴正向 -->
    <axis xyz="0 0 1"/>
    <!-- effort 与 velocity 参与模型校验与时间参数化，按实机指标填写 -->
    <limit lower="-2.9" upper="2.9" effort="80" velocity="1.5"/>
  </joint>
</robot>

解读：这段描述里每个数值都有明确的角色。（1）origin 的 xyz 与 rpy 决定子坐标系在父坐标系中的位姿，后续所有计算都在这些坐标系间变换；单位是米与弧度，写成厘米或角度会得到量级错乱的模型。（2）axis 决定关节转动的几何轴，上臂绕 Z、肘部绕 Y 的布局形成常见的关节配置；轴向写错会让拖动某一关节时模型向意料之外的方向运动。（3）limit 的上下限与速度是规划器采样与时间参数化的输入，数值直接取实机参数，不要凭观感填写。

片段 2：用 Xacro 宏参数化重复连杆

<!-- 宏把重复的连杆结构压缩为一次定义：尺寸由调用处传入 -->
<xacro:macro name="arm_link" params="name radius length mass">
  <link name="${name}">
    <visual>
      <!-- 圆柱沿关节轴放置：默认轴向为 Z，旋转可复用同一宏描述不同朝向 -->
      <geometry><cylinder radius="${radius}" length="${length}"/></geometry>
    </visual>
    <collision>
      <!-- 碰撞半径放大 2 mm：用保守近似吸收网格与实际外壳的误差 -->
      <geometry><cylinder radius="${radius + 0.002}" length="${length}"/></geometry>
    </collision>
    <inertial>
      <!-- 惯量用圆柱解析式自动派生，避免手工填错量级 -->
      <mass value="${mass}"/>
      <inertia ixx="${mass*(3*radius*radius+length*length)/12}"
               iyy="${mass*(3*radius*radius+length*length)/12}"
               izz="${mass*radius*radius/2}"
               ixy="0" ixz="0" iyz="0"/>
    </inertial>
  </link>
</xacro:macro>

<!-- 调用处只关心每段的物理参数，结构细节被宏吸收 -->
<xacro:arm_link name="link_1" radius="0.05" length="0.25" mass="3.0"/>
<xacro:arm_link name="link_2" radius="0.045" length="0.22" mass="2.2"/>

解读：宏是模型可维护性的关键工具。（1）表达式 ${radius + 0.002} 把"碰撞体略大"的策略写进结构层，所有连杆自动获得一致的保守性。（2）惯量公式直接使用圆柱解析式，几何参数改动后惯量自动跟随，避免"改了尺寸忘改惯量"的隐蔽错误。（3）宏参数列表显式化了设计意图：每段连杆由半径、长度、质量三个物理量确定，机械臂变型只需调整调用处的数值。

片段 3：发布模型到 ROS2 系统

from launch import LaunchDescription
from launch.substitutions import Command, PathJoinSubstitution
from launch_ros.actions import Node
from launch_ros.substitutions import FindPackageShare
from launch_ros.parameter_descriptions import ParameterValue


def generate_launch_description():
    # xacro 在启动时展开为 URDF 文本：参数集中在一处，展开结果可单独校验
    robot_description = ParameterValue(
        Command([
            "xacro ",
            PathJoinSubstitution([FindPackageShare("arm_robot_description"),
                                  "urdf", "arm_robot.urdf.xacro"]),
        ]),
        value_type=str)
    # robot_state_publisher 订阅 joint_states 并推算整棵变换树
    # 它发布 /tf 与 /tf_static 以及机器人描述话题，供 MoveIt2 与 RViz 使用
    rsp = Node(
        package="robot_state_publisher",
        executable="robot_state_publisher",
        parameters=[{"robot_description": robot_description}],
    )
    # 图形化关节状态发布器便于手工拖动每个关节检查方向与限位
    # 接入真机后该节点由实际驱动替代，其余节点不受影响
    jsp = Node(
        package="joint_state_publisher_gui",
        executable="joint_state_publisher_gui",
    )
    return LaunchDescription([rsp, jsp])

解读：发布环节把静态描述变成系统内可用的动态模型。（1）Command(["xacro ", ...]) 在启动时执行展开，意味着修改 xacro 文件后重启即可生效，不必手工生成中间文件。（2）robot_state_publisher 是模型与状态之间的桥梁：它用 /joint_states 的关节角把静态描述驱动起来，发布 TF 变换树。MoveIt2 与 RViz 都通过 TF 判断各连杆的位置。（3）把手工关节发布器与真实驱动设计成可替换的插槽，是描述与执行分离的直接体现：检查模型时不接硬件，接硬件时无需改动描述文件。

常见坑

  • 单位混用：长度写成厘米、限位写成角度，模型比例与转动范围与实际不符。症状是 RViz 中机械臂尺寸异常、规划结果可达性与直觉不符。修复：所有长度用米、角度用弧度，在描述文件头部用注释标注单位约定。
  • 非固定链接缺失惯性：模型校验警告，动力学仿真无法启动。修复：为每个非固定链接补齐质量与惯量，可用几何解析式估算。
  • 相邻连杆碰撞体互相侵入：为保守而放大的碰撞体与邻件静态重叠，规划报告大量自碰撞或干脆拒绝所有状态。修复：合理控制放大系数，或在第 004 章用自碰撞矩阵关闭固定相邻对的检测。
  • 关节轴向与预期不符：拖动关节时模型向侧向扭曲。修复：检查每段 axis 的正方向与安装 rpy 的组合，逐个关节在可视化环境中验证。
  • 网格资源路径不可解析：mesh 引用写成相对路径，换机器后模型显示不全。修复：统一使用包路径引用格式，确保资源所在包已被安装并可被查找。

    提示
    从树结构出发：手臂六个转动关节构成腕部法兰到基座的链；夹爪两指从腕部旁支伸出，末端法兰位姿与两指开合相互独立。
  2. 解释为什么碰撞几何可以比视觉几何粗略，而视觉几何可以比碰撞几何精细，并给出一个两者不一致但合理的例子。★
    提示

小结

  • URDF 用树结构表达机械臂：link 是节点，joint 是边；自由度等于链上非固定关节的数量。
  • 关节类型决定运动学性质，限位与速度参数直接进入规划与时间参数化，数值必须取自实机指标。
  • 视觉、碰撞、惯性三类几何各司其职；碰撞体以保守基本体近似，用少量误报换取查询速度。
