第三篇 · 规划算法与求解器

第 050 章：IK 求解总览：数值解与解析解

逆运动学（Inverse Kinematics, IK）是笛卡尔目标进入规划系统的第一道门。数值迭代与解析闭式两条路线在精度、速度与适用结构上各有边界；本章建立选型框架，为后续四种插件章节定坐标。

  • 主题：运动学求解 / IK 方法与选型
  • 关键机制：雅可比伪逆、阻尼最小二乘、封闭解分解、多解选择
  • 预计学时：55 分钟
  • 前置章节：第 049 章

学习目标

  • 写出 IK 问题的数学形式，理解自由度与任务维度关系对解的存在性与多解性的影响。
  • 掌握数值方法的两个核心迭代格式：雅可比伪逆与阻尼最小二乘，理解各自对奇异与限位的处理。
  • 理解解析解的适用条件（Pieper 类结构）与求解分解：腕心定位、肩部几何、腕部解耦。
  • 能对 KDL、TRAC-IK、LMA、IKFast 四个求解器做出场景化选择，并说明解的选择策略。
  • 会通过 IK 服务接口独立验证目标可达性，理解种子状态与避碰撞过滤的作用。

背景与动机

关节空间目标可以直接交给规划器，笛卡尔目标不行：任何位姿目标都要先问一句"存在关节配置能到达它吗"。IK 求解失败意味着后续规划不必开始；IK 选解不当意味着规划成功但执行跳变。IK 是整条笛卡尔链路的质量源头。

MoveIt2 通过可插拔的运动学插件提供 IK，不同插件代表不同的算法路线。理解数值解与解析解的边界，才能在"换插件"之外做出正确的结构选择，也能在诊断时把 IK 失败与规划失败分开（第 049 章的分岔点）。

核心原理

1. 问题形式与解的存在性

给定末端目标位姿 T目标，求关节向量 q 满足正运动学映射：

FK(q) = T目标，约束维度 m = 6（位置 3 + 姿态 3） n 为参与求解的关节自由度；n > 6 称冗余，n = 6 为恰约束，n < 6 通常只能满足部分任务

三个典型情形：

  • n > 6（冗余臂）：同一末端位姿对应无穷多组解，形成自运动流形（零空间，null space）。解的选择自由度成为可利用资源，例如兼顾限位余量与避障。
  • n = 6（恰约束）：解通常有限且成组出现。常见的多解形态包括肩部左右、肘部上下与腕部翻转，同一目标可达位置可能对应 8 组解。
  • n < 6：完整 6 维位姿约束一般不可满足，需要降级为位置约束或加入结构化假设。

多解性是 IK 的固有属性，求解器返回的解是有选择的：选择策略不当会造成相邻请求的关节解跳变，表现为执行抖动或绕远。

2. 数值方法：迭代逼近

数值方法在初值 q0 附近迭代。将位姿误差写成 6 维向量 e，利用雅可比矩阵 J(q)（6 × n）建立线性化关系：

e ≈ J(q) · Δq ⟹ Δq = J† e = JT(JJT)−1 e J† 为 Moore-Penrose 伪逆；n > 6 时该式同时给出最小范数步长

伪逆在奇异位形附近放大噪声（JJT 接近奇异），工程实现改用阻尼最小二乘（Damped Least Squares, DLS）：

Δq = JT(JJT + λ2I)−1 e λ 为阻尼因子；离奇异远时 λ 取小值保持收敛速度，接近奇异时增大以抑制抖动

迭代循环的典型结构：计算误差 → 检查收敛阈值 → 求步长 → 限位投影与步长截断 → 更新 q；终止条件由误差阈值与迭代上限共同决定。数值方法通用性强，不需要结构假设；代价是毫秒级耗时、依赖初值，且在奇异与限位附近成功率下降。随机重启是弥补手段，也是各插件性能差异的主要来源。

3. 解析方法：结构换速度

解析方法要求机械臂结构满足可解条件。经典判据（Pieper 准则）：六自由度链中存在三个相邻轴线相交于一点（典型为球形腕），或存在三根相邻轴线相互平行时，存在封闭形式的解。求解过程分层分解：

  1. 腕心定位：由目标位姿减去末端偏置得到腕心位置 pw = p − d6 · R · z，将问题降为"让腕心到达指定点"。
  2. 肩部几何：绕基座轴的两组解由平面三角关系给出，对应左右肩。
  3. 腕部解耦：剩余三轴由姿态矩阵分解得到，通常有 2 组翻转解。
  4. 方程求根：三角方程经半角代换化为多项式后求根，得到全部候选解。

解析解一次求出全部候选解（6R 球腕结构最多 8 组），单次调用在微秒量级，可按限位与避碰撞条件在候选集中筛选。代价是强结构依赖：模型一旦变化（关节偏置、连杆参数），求解器必须重新生成；这正是 IKFast 需要离线生成的原因（第 054 章）。

4. 生态对照与解的选择策略

求解器方法适用自由度速度量级典型失败模式
KDL牛顿-拉夫森迭代6 自由度链毫秒奇异邻域、限位卡死
TRAC-IK牛顿法与序列二次规划并行6 自由度链为主毫秒超时预算过小
LMA阻尼最小二乘含冗余链（如 7 自由度）毫秒初值质量、限位惩罚竞合
IKFast解析闭式特定可解结构微秒模型改动未重生成、候选被限位过滤空

解的选择顺序建议：先在候选解中做限位与避碰撞过滤，再按与种子的距离排序取最近者。种子状态（seed）让连续调用返回"接得上"的解，把跳变控制在执行层看不见的范围内。MoveIt 请求中的避碰撞开关与种子字段正为这一策略服务（第 057 章有字段级讲解）。

实现思路与设计

IK 路线选择流程：

  1. 明确结构：列出参与求解的关节链与自由度数量，检查是否存在球形腕等可解析特征。
  2. 基础选型：通用场景从 KDL 起步；成功率不满意时试 TRAC-IK；冗余臂用 LMA；结构与产线固定、追求极致节拍时评估 IKFast。
  3. 确定报告口径：用随机采样位姿测量成功率、时间中位数与 P90，方法沿用第 047 章。
  4. 配置解的选择：固定种子策略（通常取当前状态），打开避碰撞过滤，观察关节连续性指标。
  5. 回归验证：更换插件的改动必须跑同一批位姿样本，用数据说话。

参数表（kinematics.yaml 层面，字段以发行版为准）

参数典型值作用取值依据
kinematics_solver插件类名（如 KDL、TRAC-IK 插件）指定求解器按结构与需求选择
kinematics_solver_timeout0.005 到 0.05 s单次调用超时默认值偏小，按成功率曲线上调
kinematics_solver_search_resolution0.005搜索分辨率（部分插件使用）与限位余量需求配合
position_only_ikfalse / true只约束位置姿态自由度不足或任务仅要求位置时

与第 049 章接口：IK 检查是失败诊断的两个基础分岔点之一；本章给出它的方法学基础，第 051 到 054 章逐一展开四种插件的工程细节。

关键代码与解读

片段 1：IK 服务客户端（Python，含种子与避碰撞控制）

import rclpy
from rclpy.node import Node
from moveit_msgs.srv import GetPositionIK
from moveit_msgs.msg import PositionIKRequest, RobotState
from geometry_msgs.msg import PoseStamped

class IKChecker(Node):
    """独立验证目标位姿可达性：把 IK 失败与规划失败分开。"""
    def __init__(self):
        super().__init__("ik_checker")
        self.client = self.create_client(GetPositionIK, "/compute_ik")

    def solve(self, pose, seed_positions, joint_names, timeout=0.05):
        req = GetPositionIK.Request()
        req.ik_request.group_name = "arm_group"
        req.ik_request.ik_link_name = "tool0"        # 求解的末端链路：必须显式给定
        req.ik_request.avoid_collisions = True       # 候选解需通过碰撞过滤
        req.ik_request.pose_stamped = PoseStamped()
        req.ik_request.pose_stamped.header.frame_id = "base_link"
        req.ik_request.pose_stamped.pose = pose
        req.ik_request.timeout.sec = int(timeout)    # 超时防止在困难位姿上挂起
        req.ik_request.timeout.nanosec = int((timeout - int(timeout)) * 1e9)
        # 0.05 s 这类亚秒超时全部落在 nanosec 字段，只写 sec 会变成"无超时"语义
        # 种子状态决定多解中选择哪一个：通常取当前关节值，保证连续性
        req.ik_request.robot_state = RobotState()
        req.ik_request.robot_state.joint_state.name = joint_names
        req.ik_request.robot_state.joint_state.position = seed_positions
        future = self.client.call_async(req)
        rclpy.spin_until_future_complete(self, future, timeout_sec=1.0)
        return future.result()

解读：请求字段体现三个设计要点。其一，末端链路名显式给定：IK 的解与"求解到哪个坐标系"绑定，显式写死可避免环境差异。其二，避碰撞过滤开启：候选解返回前经过规划场景检查，宁可无解也不返回碰撞解。其三，种子状态承载选解策略：以当前关节值为种子，求解器倾向返回邻近解，连续调用保持位姿流形上的连续性。响应含关节状态与错误码，前者可用于正运动学二次校验。

片段 2：C++ 状态级 IK 调用（含二次校验）

#include <moveit/robot_state/robot_state.h>

// 求解并做正运动学回代校验：确认误差在容差内再交给下游
bool solve_and_verify(moveit::core::RobotState& state,
                      const moveit::core::JointModelGroup* group,
                      const geometry_msgs::msg::Pose& target,
                      const std::string& tip_link)
{
  if (!state.setFromIK(group, target, tip_link, 0.05))   // 超时 50 ms
    return false;                                        // 失败：进入第 049 章诊断流程

  // 回代：IK 输出应当满足 FK(q) 接近目标（数值解收敛阈值的实测确认）
  const Eigen::Isometry3d actual = state.getGlobalLinkTransform(tip_link);
  const double pos_err = (actual.translation() - Eigen::Vector3d(
      target.position.x, target.position.y, target.position.z)).norm();
  const double eps = 1e-3;                               // 1 mm：按工艺精度要求调整
  return pos_err < eps;
}

解读：这段代码的价值在最后五行。IK 成功与"误差足够小"在数值方法里是两回事：迭代可能在上限处停止并返回次优解，回代校验能拦住这类静默偏差。容差 1 mm 是工程起点值，接触类工艺应收紧到 0.1 mm 量级并配合标定修正。校验失败的处置与求解失败一致，都进入目标调整流程；区别在于前者暗示"未充分收敛"，后者暗示"位姿不可达"。

片段 3：运动学插件配置（后续四章的统一入口）

# kinematics.yaml（字段名以发行版与插件文档为准）
arm_group:
  kinematics_solver: kdl_kinematics_plugin/KDLKinematicsPlugin   # 换插件即替换此行
  kinematics_solver_timeout: 0.02        # 20 ms：默认 5 ms 量级偏小，先给 0.02 观察成功率
  kinematics_solver_search_resolution: 0.005
  position_only_ik: false                # 需要完整 6 维位姿时保持关闭

解读：这份配置是第 051 到 054 章的共同入口：更换 kinematics_solver 一行即可在四种插件之间切换，其余参数按插件特性微调。把超时从默认值提高到 0.02 s 是通用低风险动作，给随机重启更多机会；继续上调前先用位姿样本测量成功率曲线，避免把困难位姿的等待成本转嫁到整条产线。配置变更后重启 move_group 生效。

常见坑

  • 混淆求解链路与任务链路：请求里未显式给出末端链路名，IK 求解到配置缺省的坐标系，与调用方期望的工具点不一致。修复：所有 IK 请求显式指定末端链路，并核对与工艺定义的一致。
  • 种子状态缺失导致解跳变：连续调用不带种子，求解器每次都随机取解，关节在相邻目标间大幅跳转。修复：以当前状态为种子，保持解的连续性。
  • 在冗余链上使用 6 自由度求解器：KDL 类插件要求求解链恰为 6 自由度，冗余臂上表现异常。修复：改用支持冗余的插件（第 053 章）。
  • 把 IK 成功当终点：数值解可能带着毫米级误差或接近奇异的位形返回。修复：增加回代校验与条件数检查（第 056 章）。
  • 忽略坐标帧：目标位姿携带错误的参考帧（如把工具系位姿当基座系使用），求解器返回"成功"但位置完全错误。修复：在请求构造处统一坐标帧并断言检查。

练习与思考

  1. 六自由度链、n = 6、伪逆式 Δq = J†e 中 J 的维度是多少？冗余臂 n = 7 时伪逆给出的解具有什么额外性质？★
    提示
    J 为 6 × 6，J† 退化为普通逆；n = 7 时 J† 给出最小范数解，即所有可行步长中关节位移范数最小者，这也是"选邻近解"倾向的数学根源。
  2. 某 6R 球腕结构最多有 8 组解。写出解的数量在各分解步骤中的倍数关系并解释哪一步引入多解。★
    提示
    肩部两组解（左右）× 肘部两组（上下）× 腕部两组（翻转）= 8。多解来自几何分支：三角方程在对域内有两个根，姿态矩阵分解出两个翻转组合。
  3. 为下列场景各选一个求解器并说明理由：通用 6 自由度协作臂、7 自由度冗余臂、固定结构产线追求节拍、需要枚举全部解做路径优化。★★
    提示
    协作臂：TRAC-IK 或 KDL；冗余臂：LMA；产线节拍：IKFast（结构固定且允许离线生成）；枚举全部解：解析法（IKFast 类）。理由围绕结构条件、速度量级与解集完整性组织。
  4. 设计一个 IK 评估实验：在可达工作空间内随机采样 200 个位姿，分别测量两组插件的成功率、时间中位数与"解跳变率"，写出采样策略与跳变率定义。★★★
    提示
    采样策略：由一组随机关节角经正运动学生成位姿，保证位姿本身可达，再剔除限位外的样本。跳变率定义为相邻位姿的求解结果关节距离超过阈值（如 0.5 rad）的比例，种子固定为上一解。

小结

  • IK 解的存在性与自由度有关：n > 6 多解成流形，n = 6 有限成组，n < 6 需降级任务约束。
  • 数值方法以雅可比伪逆或阻尼最小二乘迭代逼近，通用但耗时毫秒级，受初值与奇异影响。
  • 解析方法依赖可解结构（如球腕），经腕心定位与几何分解一次求出全部候选解，微秒量级。
  • 解的选择策略：限位与避碰撞过滤后取距种子最近者，维持关节连续性。
  • IK 检查是失败诊断的基础工具；IK 成功仍需回代校验，把握度与精度一起确认。
