第 078 章：阶段实践：完整抓取流水线

把第 061 至 077 章的部件装成一条可验收的流水线：模块清单与数据流、状态机与错误恢复矩阵、验收指标的口径与统计方法、瓶颈定位与优化方向。

  • 主题：阶段实践 / 端到端抓取流水线（End-to-End Pipeline）
  • 关键机制：任务状态机 / 恢复矩阵 / 验收指标与置信区间
  • 预计学时：60 分钟
  • 前置章节：第 077 章

学习目标

  • 能列出完整抓取流水线的模块清单与数据流，并指出每个模块在本课程中的对应章节。
  • 会设计任务状态机：状态划分、迁移条件、超时管理与失败分支的组织方式。
  • 会构建错误恢复矩阵：错误类型、检测手段、分级处置与重试上限。
  • 掌握验收指标的口径定义与统计方法（成功率、首次成功率、节拍分位、置信区间），能设计对照实验。
  • 能从阶段耗时记录中定位流水线瓶颈并给出优化方向。

背景与动机

前十七章分别建立了抓取生成、管线段、任务接口、末端执行器、动态策略、装配与各类平台的部件。部件正确并不等于流水线正确：阶段之间的衔接时序、失败后的状态恢复、验收口径的一致性，都是只有整体运行时才会暴露的问题。本章的任务是把部件按数据流装成一条可运行、可诊断、可验收的流水线。

与第 018、038、060 章的三次阶段实践相比，本章的综合度更高：前三次收敛的是单篇能力（基础运动、感知避障、规划器选型），本章收敛的是任务层全链，包含感知、规划、执行、末端执行与恢复策略五类部件。

本章也是第四篇的收束：流水线的每个环节都指向具体章节的深化内容，验收指标则作为第五篇系统集成的输入基线。

核心原理

1. 模块清单与数据流

模块对应章节输入输出
场景与感知第 019 至 034、095、096 章传感器数据、场景物体目标位姿与置信度
抓取生成第 061 章物体几何、夹爪参数抓取候选列表
姿态优化第 069 章候选列表、机械臂运动学排序后的抓取位姿
运动规划第 039 至 060 章目标位姿、场景约束关节轨迹
执行与监控第 077 章轨迹、监控参数执行结果与偏差
末端执行第 066、067 章开合或抽吸指令夹持确认信号
任务管线与接口第 062 至 065 章阶段定义、动作目标阶段推进与终态

数据流为单向链：感知到候选，候选到位姿，位姿到轨迹，轨迹到执行，执行结果回到状态机驱动下一步。流水线集成的顺序应从链尾开始（执行与末端先单独验证），逐段向前接通，每接通一段做一次端到端回归，与第 077 章自下而上的部署顺序一致。

2. 状态机设计

流水线状态机的状态与第 062 章的阶段对应，并补充感知与结果上报两类状态使其完整：

状态迁移条件超时失败分支
DETECT目标检出且置信度达标2 s重新感知（限次）
PLAN轨迹规划成功5 s换候选后重规划
APPROACH直线段执行完成按段长度回预抓取位姿
GRASP夹持确认成功1 s张开并换候选
VERIFY夹持信号保持稳定0.5 s就地释放并上报
RETREAT / TRANSPORT执行完成且无碰撞按段长度回退到安全位形
PLACE / RELEASE接触确认与释放完成2 s补偿高度重试

状态机设计的三条原则：其一，每个状态都有超时，长动作拆分为可轮询子段；其二，每个状态都有失败迁移，不留"停住不动"的暗状态；其三，状态划分与观测粒度一致，日志与反馈直接输出状态名与耗时，诊断不需要额外插桩。状态数量以 8 至 12 个为宜：过少则诊断粗、恢复动作无法定位；过多则迁移表膨胀，维护成本上升。

3. 错误恢复矩阵

恢复策略按"错误类型 × 处置动作"组织为矩阵，处置分四级：重试（换参数或换候选）、局部重规划、回到安全位形重新感知、上报人工。矩阵的行覆盖五类错误：感知类、规划类、执行类、夹持类与放置类。

恢复成功率 = 重试成功次数 / 触发重试次数，目标 ≥ 80% 矩阵为每个 (状态, 错误) 组合指定唯一处置动作与重试上限（典型 2 次），避免在恢复路径中再引入未定义行为

恢复的隐含要求是状态一致性：每次恢复动作结束后，规划场景、附着关系与手爪状态必须回到与状态机记录一致的状态，否则恢复本身成为新的错误来源（第 062 章的 rollback 讨论）。重试上限的取值依据是"错误是否可通过重试消除"：感知与规划类错误随重试收敛，执行与堵转类错误重试只会重复消耗时间，应直接升级处置。

4. 验收指标与统计

指标口径目标值统计方法
总成功率完成放置并确认 / 总次数≥ 98%N ≥ 30，二分比例
首次成功率零重试完成 / 总次数≥ 90%同上，反映候选与规划质量
节拍DETECT 到 RELEASE 的耗时P95 ≤ 12 s记录分布，报告中位数与 P95
放置位姿误差放置位姿与目标的偏差模长≤ 2 mm均值与 95 分位
接触力峰值插入或放置过程的最大法向力≤ 25 N逐次记录的极值分布
恢复成功率触发恢复后完成任务的比率≥ 80%按错误类型分组统计

指标口径必须在实验前固定，尤其是"成功"的定义：完成放置、物体位置在容差内、且物体与手爪分离，三个条件同时满足才计成功，否则不同批次的数字不可比。样本量由置信区间反推：

半宽 ≈ 1.96 · √( p (1 − p) / N ) p = 0.9、N = 30 时半宽约 10.7%，只能区分粗粒度差异；需要半宽 5% 时 N ≈ 138

瓶颈定位依靠阶段耗时记录：把状态机 trace 中的每阶段耗时按分位统计，占节拍比例最大的阶段即为优化目标；典型瓶颈出现在感知（重测与滤波等待）、规划（候选轮换的多次求解）与直线接近段（高密度路点的执行时间）三处。

实现思路与设计

流水线集成的实施步骤：

  1. 口径先行：确定成功定义、指标清单与目标值，写入验收方案后再动集成。
  2. 自尾向前集成：末端执行、执行监控、规划、感知逐段接通，每段做回归。
  3. 状态机实现：建立状态表与超时，先跑通成功路径，再加失败迁移。
  4. 恢复矩阵：为每个错误组合指定处置与上限，注入错误验证恢复路径。
  5. 时间戳记录：状态进入退出各记一次时间，输出 trace 供瓶颈分析。
  6. 验收运行：随机化初始位姿，按 N ≥ 30 重复，统计六项指标并输出报告。

设计决策：为什么先固定验收口径再集成？

集成的过程会不断遇到"这个偏差算不算失败""这次重试算不算首次成功"之类的边界问题。若口径随实现漂移，最终数字无法与任何基线比较，也无法判断改动是否有效。把口径写成方案再开始集成，等价于在开发前就确定了"完成"的定义，后续每一处实现都可以围绕这个定义取舍。

关键代码与解读

片段 1：流水线状态机骨架

import time

RECOVERY = {}   # 由片段 2 填充的错误恢复矩阵

class Pipeline:
    """流水线状态机：状态序列、超时与统一恢复入口。"""
    STATES = ("DETECT", "PLAN", "APPROACH", "GRASP", "VERIFY",
              "RETREAT", "TRANSPORT", "PLACE", "RELEASE")

    def __init__(self, handlers, timeout=5.0, max_attempts=2):
        self.handlers = handlers          # 状态名到执行函数的映射
        self.timeout = timeout
        self.max_attempts = max_attempts
        self.trace = []                   # (状态, 耗时, 事件)：瓶颈分析原始数据

    def run(self, ctx):
        ctx["attempts"] = ctx.get("attempts", 0)
        for state in self.STATES:
            t0 = time.monotonic()
            event = self.handlers[state](ctx, deadline=t0 + self.timeout)
            self.trace.append((state, time.monotonic() - t0, event))
            if event != "OK":
                return self.recover(state, event, ctx)   # 统一走恢复入口
        return "DONE"

    def recover(self, state, event, ctx):
        """恢复入口：查矩阵得处置动作，有限重试后升级。"""
        action = RECOVERY.get((state, event), "ABORT")
        if action == "RETRY" and ctx["attempts"] < self.max_attempts:
            ctx["attempts"] += 1
            return self.run(ctx)          # 重试整条流水线（含重新感知）
        return "FAIL:" + action

解读：（1）状态执行函数返回事件字符串，让恢复逻辑可以区分"规划无解"与"执行超时"这类不同性质的失败（布尔值只能表达成败两类），这是诊断粒度与恢复精度的基础。（2）每次状态进入退出都记录时间戳，trace 直接支撑节拍分解与瓶颈定位，不需要额外的性能分析工具。（3）恢复入口唯一：所有失败路径汇入同一函数，矩阵查不到的组合默认按中止处理，杜绝未定义行为。（4）重试以整条流水线为单位（含重新感知），实现简单且状态天然一致；更细的从中间状态续跑需要额外的状态清理设计，属于实现成熟后的优化方向。

片段 2：错误恢复矩阵

RECOVERY = {
    # (状态, 事件): 处置动作，RETRY 表示重试，ABORT 表示上报
    ("DETECT", "NO_TARGET"): "RETRY",     # 未检出：调整视角重新感知
    ("DETECT", "LOW_CONF"): "RETRY",      # 置信度低：延长积分或换视角
    ("PLAN", "NO_SOLUTION"): "RETRY",     # 规划无解：换抓取候选后重规划
    ("APPROACH", "TIMEOUT"): "ABORT",     # 接近超时：位姿或障碍异常
    ("GRASP", "EMPTY"): "RETRY",          # 空抓：换候选或提高夹持力下限
    ("GRASP", "JAMMED"): "ABORT",         # 堵转：需人工检查末端与工件
    ("VERIFY", "SLIP"): "ABORT",          # 夹持滑移：物体状态危险，就地处置
    ("PLACE", "NO_CONTACT"): "RETRY",     # 未接触：补偿高度后重试
    ("PLACE", "MISALIGNED"): "ABORT",     # 放置偏移：需人工复位工件
}

解读：（1）矩阵的键是"状态加事件"二元组，保证处置动作与发生位置绑定：同样是超时，DETECT 阶段可重试而 APPROACH 阶段直接上报，因为前者的重试代价低、后者的超时通常指向真实异常。（2）RETRY 与 ABORT 的划分标准是"错误能否通过重试收敛"：感知与规划类错误会随重试改善，执行与机构类错误不会。（3）矩阵以配置形式独立于状态机代码，新增错误组合不需要改动控制流，评审时也可以单独审查每一项处置的合理性。

片段 3：验收统计与置信区间

import math

def acceptance(records):
    """验收统计：成功率、首次成功率、节拍分位与置信半宽。"""
    n = len(records)
    succ = sum(1 for r in records if r["result"] == "DONE")
    first = sum(1 for r in records
                if r["result"] == "DONE" and r["attempts"] == 0)
    cycles = sorted(r["cycle_s"] for r in records if r["result"] == "DONE")
    p95 = cycles[int(0.95 * (len(cycles) - 1))] if cycles else None
    p = succ / n
    half = 1.96 * math.sqrt(p * (1.0 - p) / n)   # 95% 置信半宽
    return {"n": n, "success": round(p, 4), "first_try": round(first / n, 4),
            "p95_cycle": p95, "ci_half": round(half, 4)}

# 示例：40 次运行、38 次成功、节拍 P95 约 11.2 s
# 输出 success 0.95、first_try 0.8、ci_half 0.068

解读：（1）四个统计量对应四个不同问题：成功率回答"能不能做"，首次成功率回答"一次做对的概率"，节拍分位回答"最慢的作业有多慢"，置信半宽回答"数字有多可信"。（2）节拍取 P95：流水线的效率由尾部决定，平均节拍会被大量快速成功掩盖。（3）置信半宽随样本量按平方根缩小：40 次运行的 6.8% 半宽意味着 95% 与 98% 的差异无法区分，宣称更高成功率前先补齐样本量。（4）统计脚本的输出结构直接对应验收报告的表头，保证"运行数据到报告"之间没有人工转录环节。

常见坑

  • 验收口径事后漂移：集成中不断重新定义"成功"，最终数据无法与基线比较。修复：口径写入验收方案并冻结，任何调整记录版本与理由。
  • 重试无上限：感知或规划在困难场景反复重试，单次作业时间失控。修复：矩阵为每个组合设定上限（典型 2 次），超限升级为上报。
  • 恢复后状态不一致：重试从中间状态继续，场景残留上次尝试的附着关系或物体，第二批尝试在错误世界模型上运行。修复：恢复动作包含场景一致性检查，或按片段 1 的方式整条流水线重跑。
  • 只统计均值：成功率高但个别作业耗时是均值的数倍，节拍承诺失效。修复：报告分位数，用 P95 与最大值描述尾部。
  • 缺少阶段耗时记录：知道整体变慢但无法定位到阶段。修复：状态进入退出时间戳写入 trace，验收报告附带阶段耗时分解。

练习与思考

  1. 给出两种"成功"定义（严格与宽松），说明各自适用场景与对成功率的影响，并指出为什么口径必须冻结。★
    提示
    严格定义要求放置位姿在容差内且物体与手爪分离；宽松定义只要求流程走完。前者适合精度敏感场景，后者适合流程验证；口径一旦改变，数字就不具可比性。
  2. N = 30、成功率 0.9 时置信半宽约 10.7%。若要把半宽压到 5%，估算所需样本量并说明成本。★★
    提示
    N ≈ 1.96² × 0.9 × 0.1 / 0.05² ≈ 138 次；按单次节拍 10 s 计算，接近半天的连续运行，需要考虑设备负载与工件损耗。
  3. 为五类错误（感知、规划、执行、夹持、放置）各设计一条一级处置与一条二级处置，并说明二级处置的触发条件。★★
    提示
    例如感知类一级重测、二级换视角并降低置信阈值；规划类一级换候选、二级回到安全位形重新感知；二级在重试达到上限或一级无效时触发。
  4. 设计对照实验：速度缩放分别取 0.5、0.8、1.0 三档，测量节拍、成功率与接触力峰值，给出实验流程与结论的表达方式。★★★
    提示
    每档 30 次、随机初始位姿，控制其他变量不变；结论用"节拍中位数与 P95、成功率及其置信区间、力峰值分布"三组数据表达，并明确指出档位间的差异是否超过置信区间。

小结

  • 完整流水线的模块链为感知、抓取生成、姿态优化、运动规划、执行监控与末端执行，集成顺序自尾向前，每段接通后回归验证。
  • 状态机以 8 至 12 个状态覆盖全流程，每个状态都配置超时与失败迁移，trace 时间戳同时支撑诊断与瓶颈分析。
  • 错误恢复矩阵按"状态加事件"指定处置动作与重试上限，处置分级从重试到上报，恢复动作必须保证状态一致。
  • 验收指标口径先行，六项指标以成功率、首次成功率、节拍 P95、位姿误差、力峰值与恢复率定义，样本量由置信区间反推。
