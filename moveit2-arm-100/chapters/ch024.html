第二篇 · 规划场景与碰撞管理

第 024 章：碰撞物体表示：CollisionObject 消息结构

上一章讲操作，本章讲数据：逐字段解剖 CollisionObject 消息，弄清几何三族（解析形状、平面、网格）的组织方式、平行数组的配对约定、位姿的叠加次序，以及每种表示在消息体大小与检测代价上的量级差异。

  • 主题：规划场景数据表示 / 消息结构
  • 关键机制：SolidPrimitive 尺寸语义、平行数组约定、网格的顶点与三角形组织
  • 预计学时：50 分钟
  • 前置章节：第 023 章

学习目标

  • 能逐字段说明 CollisionObject 消息的组成：头部、标识、物体位姿、几何三族数组、操作字段，以及各字段在场景处理中的角色。
  • 记住解析形状（SolidPrimitive）四种类型的尺寸语义，能按真实尺寸正确填出长方体、球、圆柱、圆锥的 dimensions。
  • 理解平行数组（几何数组与位姿数组）的配对约定与长度一致性要求。
  • 掌握网格消息的组织方式：顶点表、三角形索引表与单位约定，能评估网格规模带来的代价。
  • 会写消息级校验函数，把字段错误在写入场景之前拦截。

背景与动机

第 022 章与第 023 章都在与同一个消息打交道：碰撞物体消息（CollisionObject）是规划场景写入操作的唯一载体，添加、移除、移动、追加全部经由它表达。前两章回答了"用哪些操作、走哪条路径"，本章回答"每个字段到底承载什么"。这层理解有直接的工程回报：物体显示错位、检测结果异常、升级后行为变化，绝大多数根因都落在字段语义上，而不在算法或配置上。

消息结构的设计还揭示了一条工程主线的源头：几何表示的选择。解析形状与网格的消息体大小可以相差几个数量级，碰撞检测代价同样如此，而规划请求对场景查询的次数以千计（第 029 章将量化这一点）。先把数据表示选对，再谈参数调优，顺序不能颠倒。本章最后会给出消息级校验函数，把错误拦在场景之外。

核心原理

1. 字段总览：一张消息的骨架

字段类型作用使用要点
headerstd_msgs/Header提供参考系与时间戳frame_id 决定位姿的解释坐标系；世界物体以静态描述为主，时间戳主要用于溯源
typeObjectType物体类别标注（键值与数据库标识）规划核心不消费该字段，供识别与工具链使用
idstring场景内唯一标识生命周期内所有操作靠它定位，空标识不可接受
posegeometry_msgs/Pose物体在参考系中的位姿与形状位姿叠加，见第 3 小节
primitives / primitive_posesSolidPrimitive[] / Pose[]解析形状及其内部位姿两个数组一一对应
planes / plane_posesPlane[] / Pose[]平面几何及其内部位姿平面为无限延伸面，使用前确认适用边界
meshes / mesh_posesMesh[] / Pose[]三角网格及其内部位姿几何数据内嵌消息，体积随三角形数增长
operationuint8操作类型ADD、REMOVE、APPEND、MOVE，语义见第 023 章

骨架里最值得注意的是"一个物体可以带多块几何"：三族数组共同描述同一个物体的外形，场景处理时它们被合并进同一个物体条目。标识、位姿、操作是消息的三个行为字段；三族几何数组是它的内容字段；头部提供解释坐标。这种"行为与内容分离"的组织方式让同一份几何数据可以配合不同操作复用。

2. 几何三族之一：解析形状的尺寸语义

解析形状用类型号加尺寸数组表达，尺寸分量个数随类型变化：

类型常量名dimensions 语义示例
长方体BOX[x, y, z] 三个全尺寸[1.2, 0.8, 0.04] 表示厚 4 cm 的台面
球SPHERE[半径][0.06] 表示半径 6 cm 的球
圆柱CYLINDER[半径, 高][0.03, 0.2] 表示半径 3 cm、高 20 cm 的柱体
圆锥CONE[半径, 高][0.05, 0.12] 表示底面半径 5 cm 的锥体

尺寸一律使用米，一律为全尺寸（长方体）或整体几何参数（球与柱锥）。最频繁的两类字段错误是把全尺寸当半宽填入、以及把圆柱的半径与高写反；两者都会生成"看似合理"的错误几何，靠肉眼难以发现，必须用尺寸对照表核对。常量数值本身属于消息定义的一部分，以实际发行版的头文件为准即可，编写代码时优先使用常量名，避免裸数字。

3. 平行数组与两级位姿的组合

每种几何数组都有一个配对的位姿数组，下标相同表示配对关系。这一设计把"几何是什么"与"几何放在哪"彻底分开：同一种形状描述可以配上不同位姿，甚至在同一物体内重复使用（把同一段描述复制多份）。场景处理时按下标逐项组合，最终几何由三级变换串联：

Tworld,shape = Tworld,frame · Tframe,obj（物体位姿） · Tobj,shape（形状位姿） 配对数组的长度必须相等；几何与位姿的错位会造成"几何对了但摆错位置"这类隐蔽故障

两级位姿的划分让物体内部布局与整体摆放解耦：为一张桌子建模时，台面与四条立柱在物体坐标系内摆好（形状位姿），整体平移到工位（物体位姿）；工位调整时只改物体位姿，内部布局分毫不动。

4. 几何三族之二与之三：平面与网格

平面（Plane）用四个系数描述一个无限延伸面：平面方程 a·x + b·y + c·z + d = 0，系数向量 (a, b, c) 为单位向量。语义上它是无限大的，碰撞检测把它当作有向的界外区域处理，适合表达地面、墙面、传送带面这类"包围式"几何。用平面表达有限物体是概念性错误：一条 0.8 m 的工作台写成平面后会在整个坐标系内参与碰撞。

网格（Mesh）内嵌顶点表与三角形索引表：每个三角形用三个整数下标指向顶点表。顶点坐标在物体坐标系内，单位同样为米。网格的消息体大小与检测代价都随三角形数线性增长：一个 5000 三角形的零件，单条消息约零点几兆字节级，检测器还要为它构建包围体层次。工程实践中常见的做法是分三级降级：能拼解析形状就拼；拼不满意再简化网格；只有精度确实不够时才保留高密度网格。网格表达力最强、代价最高，它是几何表示手段中的"重武器"。

5. 容器视角：世界数组与操作序列

往上一层看，CollisionObject 是放进列表里被处理的：规划场景的世界部分（PlanningSceneWorld）包含一个碰撞物体数组（碰撞物体与占据栅格地图并列），世界差分里的这个数组按顺序逐条处理。顺序处理的含义是：同一个 id 在一条差分里出现两次时，后一条在前一条的结果上生效，这为"先移除再添加"的原子替换提供了语义基础（第 023 章片段 3）。记住这一层，就能理解为什么一条差分可以表达一串有依赖的操作。

实现思路与设计

构造与使用碰撞物体消息时的标准动作清单：

  1. 选几何族：按代价谱系决策，解析形状优先；平面只用于包围性几何；网格用于复杂轮廓并尽量控制三角形数。
  2. 尺寸对照：为每个物体写一行"标称尺寸到 dimensions"的对照，圆柱与圆锥核对半径与高的顺序。
  3. 写全行为字段：id 语义化且非空；frame_id 明确；operation 显式书写；位姿四元数归一化。
  4. 核对平行数组：几何与位姿数组长度一致，多形状组合按内部布局逐项填写。
  5. 写入前校验：用消息级校验函数检查空标识、缺参考系、长度不匹配、尺寸分量数异常、四元数未归一化五类问题。
  6. 写入后抽查：取回场景物体，核对关键尺寸与位姿分量，形成闭环。

几何表示决策表

选择消息体大小单次检测代价适用条件
解析形状几十字节低（解析求交）几何可由少量盒、球、柱近似
平面几十字节低地面、墙面等包围性几何
低密度网格几十到几百 KB中经简化后轮廓精度可接受
高密度网格兆字节级高精度要求无法用以上手段满足时

关键代码与解读

片段 1：Python 以程序方式生成盒体网格消息

import numpy as np
from shape_msgs.msg import Mesh, MeshTriangle
from geometry_msgs.msg import Point

def box_mesh(sx, sy, sz):
    """用三角形网格表达长方体；单位为米，顶点在物体坐标系内。"""
    hx, hy, hz = sx / 2.0, sy / 2.0, sz / 2.0   # 网格需要半宽展开的八个角点
    v = np.array([
        [-hx, -hy, -hz], [ hx, -hy, -hz], [ hx,  hy, -hz], [-hx,  hy, -hz],
        [-hx, -hy,  hz], [ hx, -hy,  hz], [ hx,  hy,  hz], [-hx,  hy,  hz],
    ])
    faces = np.array([
        [0, 2, 1], [0, 3, 2],   # 底面两块三角形
        [4, 5, 6], [4, 6, 7],   # 顶面
        [0, 1, 5], [0, 5, 4],   # 四个侧面各两块
        [1, 2, 6], [1, 6, 5],
        [2, 3, 7], [2, 7, 6],
        [3, 0, 4], [3, 4, 7],
    ])
    mesh = Mesh()
    # 顶点表：逐点转换，保留浮点精度
    mesh.vertices = [Point(x=float(p[0]), y=float(p[1]), z=float(p[2]))
                     for p in v]
    # 三角形表：每个元素是三个顶点下标（无符号整数）
    mesh.triangles = []
    for f in faces:
        tri = MeshTriangle()
        tri.vertex_indices = [int(f[0]), int(f[1]), int(f[2])]
        mesh.triangles.append(tri)
    return mesh

解读：（1）顶点坐标使用半宽展开，因为网格以顶点显式描述边界，没有"尺寸数组"这一层抽象；这与解析形状的全尺寸语义形成对照，混用会导致物体大出一倍或小一半。（2）六个面各用两块三角形，共 12 块，这是长方体的最小三角形划分；同样的形状如果改用解析长方体表达，消息体只有几十字节，代价差异一目了然。（3）三角形按"逆时针朝外"的惯例排列便于查看与法向相关查询；碰撞检测本身以三角形几何为准，顶点顺序主要影响可读性与渲染。

片段 2：Python 单一标识下的多形状组合（台面加四柱）

from moveit_msgs.msg import CollisionObject
from shape_msgs.msg import SolidPrimitive
from geometry_msgs.msg import Pose

def make_table(name, length=1.2, width=0.8, height=0.7):
    """一个标识下的多形状组合；形状位姿相对物体位姿表达。"""
    top = SolidPrimitive()
    top.type = SolidPrimitive.BOX
    top.dimensions = [length, width, 0.04]           # 台面：全尺寸三轴
    leg = SolidPrimitive()
    leg.type = SolidPrimitive.BOX
    leg.dimensions = [0.05, 0.05, height - 0.04]     # 立柱：从地面到台面下沿

    obj = CollisionObject()
    obj.header.frame_id = "world"
    obj.id = name
    obj.operation = CollisionObject.ADD
    # 平行数组之一：形状列表，四条立柱可复用同一份尺寸描述
    obj.primitives = [top, leg, leg, leg, leg]

    poses = []
    top_pose = Pose()
    top_pose.position.z = height - 0.02              # 台面中心高度
    top_pose.orientation.w = 1.0
    poses.append(top_pose)
    for sx in (-1, 1):
        for sy in (-1, 1):
            p = Pose()
            p.position.x = sx * (length / 2.0 - 0.05)  # 立柱中心贴角
            p.position.y = sy * (width / 2.0 - 0.05)
            p.position.z = (height - 0.04) / 2.0       # 立柱中心高度
            p.orientation.w = 1.0
            poses.append(p)
    # 平行数组之二：逐项配对，长度与 primitives 严格相等
    obj.primitive_poses = poses
    return obj

解读：（1）多形状组合用一个标识表达整张桌子，后续移动或移除时只需一条操作，避免把五个几何拆成五个物体带来的标识膨胀。（2）形状列表里四条立柱共享同一份尺寸描述（值语义的复制），修改立柱尺寸只需改一处模板；位姿列表则给出各自的角落位置。（3）长度一致性是硬约束：primitives 与 primitive_poses 数量不等时，多余项找不到配对，属于必须在校验层拦截的字段错误。

片段 3：Python 消息级校验函数

from shape_msgs.msg import SolidPrimitive

def validate_object(obj):
    """写入前校验：把字段错误拦截在场景之外，返回问题清单。"""
    problems = []
    if not obj.id:
        problems.append("id 为空：后续无法更新或移除")
    if not obj.header.frame_id:
        problems.append("参考系未设置：位姿没有解释基准")
    # 三族几何各自与位姿数组配对，逐族检查长度
    if len(obj.primitives) != len(obj.primitive_poses):
        problems.append("解析形状与形状位姿数量不一致")
    if len(obj.meshes) != len(obj.mesh_poses):
        problems.append("网格与网格位姿数量不一致")
    if len(obj.planes) != len(obj.plane_poses):
        problems.append("平面与平面位姿数量不一致")
    # 四元数归一化检查：模长偏离 1 超过千分之一即认为异常
    q = obj.pose.orientation
    norm = (q.x * q.x + q.y * q.y + q.z * q.z + q.w * q.w) ** 0.5
    if abs(norm - 1.0) > 1e-3:
        problems.append("物体位姿四元数未归一化")
    # 尺寸分量数随类型变化，抽查两种最常见类型
    for prim in obj.primitives:
        if prim.type == SolidPrimitive.BOX and len(prim.dimensions) != 3:
            problems.append("长方体需要三个全尺寸分量")
        if prim.type == SolidPrimitive.CYLINDER and len(prim.dimensions) != 2:
            problems.append("圆柱需要半径与高两个分量")
    return problems

解读：（1）校验覆盖六类字段问题，其中四元数检查最容易被忽视：人手构造或从上游系统转发时，姿态分量常带缩放误差，未归一化的四元数在旋转应用处产生轻微形变，误差随多次变换累积。（2）校验函数返回问题清单，避免抛异常打断调用链，调用方可以决定"拒绝写入"或"带警告继续"，两类策略分别适合任务物体与调试物体。（3）把校验统一放在写入路径的入口处，避免分散在各构造点，保证任何来源的消息（脚本、感知节点、人工通过工具写入）经过同一条防线。

常见坑

  • 全尺寸与半宽混用：解析形状按半宽填 dimensions，物体只有标称的一半。症状是规划贴物体过近。修复是统一使用全尺寸，并在代码评审时核对尺寸对照表。
  • 圆柱半径与高写反：dimensions 两个分量的顺序颠倒，得到一根"短粗柱"。症状在 RViz 中极易被忽略，直到避障失效才被发现。修复是记住顺序为半径在前、高度在后，并纳入校验函数。
  • 平行数组长度错位：形状数组与位姿数组长度不等，或配对次序与设计意图不一致，几何落到错误位置。修复是逐族检查长度，多形状组合时用循环成对生成，避免手工维护两个数组。
  • 平面当有限面使用：把 0.8 m 的台面写成平面几何，平面在整个空间无限延伸，规划器把大片可达区域判为碰撞。修复是台面用长方体表达，平面只用于地面与墙面。
  • 网格单位与规模失控：从毫米制模型导出的网格直接写入消息，物体放大一千倍占满工作空间；高密度网格使场景差分与检测开销陡增。修复是导入流程固定单位换算，并对三角形数设置上限。

练习与思考

  1. 尺寸语义：写出圆锥、球、圆柱各一个示例的 dimensions，并说明分量的物理含义。若把圆柱写成 [0.2, 0.03]，物体实际形状是什么？★
    提示
    圆锥示例 [0.05, 0.12]（底面半径、高）；球 [0.06]（半径）；圆柱 [0.03, 0.2]（半径、高）。写成 [0.2, 0.03] 得到半径 20 cm、高 3 cm 的扁柱，与预期形状完全不同。
  2. 代价估算：一个 3000 三角形网格与一个解析长方体相比，单条消息体大约相差几个数量级？在每秒数十次场景查询的规划过程中，哪个量级的差异更关键？★
    提示
    顶点表约 3000 × 3 × 双精度小数，消息体可达百 KB 级，长方体仅几十字节，相差三到四个数量级。规划期间检测查询以千计，检测代价的差异比消息体积更关键。
  3. 设计题：为一个带凹槽的夹具设计几何表示方案，要求给出"解析形状组合"与"简化网格"两种方案的具体参数或规模，并从检测代价与精度两方面说明适用条件。★★
    提示
    组合方案可用底板加两条侧板表达凹槽（三到四个长方体）；网格方案给出简化目标（如 500 三角形以内）。凹槽内部若有抓取动作经过，精度要求高的面用网格、其余用解析形状的混合表示最经济。
  4. 诊断题：新增物体在 RViz 中出现在距离预期约十倍远的位置，且尺寸明显偏小。列出两种可能原因及验证方法。★★
    提示
    优先怀疑单位错误：导入网格时用了厘米或毫米而未换算，或位姿分量把厘米当米。验证是打印消息内容，与设计尺寸对照；另一种原因是参考系错了位置，用同一 id 查询场景并核对 frame 与位姿。
  5. 分析题：CollisionObject 采用"几何数组加平行位姿数组"的组织方式，未采用"把每个形状与其位姿嵌套成一体"的写法。从消息复用、构造代码、错误模式三个角度分析这种设计的好处与代价。★★★
    提示
    好处：形状描述可以复制复用、构造时循环成对生成、与非 ROS 几何库转换直接；代价：配对关系靠下标隐式维护，长度或次序出错时没有类型系统兜底，必须依赖校验函数。设计上没有绝对优劣，关键在于用校验与生成模式补偿隐含约定。

小结

  • CollisionObject 的骨架由行为字段（id、pose、operation）与内容字段（三族几何及配对位姿）构成，头部提供解释坐标。
  • 解析形状使用全尺寸语义，分量个数随类型变化；平面为无限面；网格内嵌顶点与三角形索引，代价随规模线性增长。
  • 几何与位姿通过平行数组配对，最终位置由参考系、物体位姿、形状位姿三级变换串联。
  • 一条差分按序处理，同一标识的多条操作有依赖地生效，这是原子替换的语义基础。
