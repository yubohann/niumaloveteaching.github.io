第三篇 · 规划算法与求解器

第 045 章：使用 SBPL 规划器

SBPL（Search-Based Planning Library）把运动规划转成离散状态空间上的图搜索：栅格、运动原语与任意时间修复搜索（Anytime Repairing A*）是它的三块基石。本章讲清搜索型规划器的工作方式、参数含义与在 MoveIt 生态中的接入现状。

  • 主题：搜索型规划器 / SBPL 与任意时间 A*
  • 关键机制：状态栅格、运动原语、启发式权重、修复搜索
  • 预计学时：50 分钟
  • 前置章节：第 044 章

学习目标

  • 理解搜索型规划与采样型规划的本质差异：分辨率完备、确定性与代价累积。
  • 理解 ARA* 的任意时间机制：启发式权重 ε 如何控制"先快后优"，以及 ε 次优界的确切含义。
  • 掌握栅格分辨率、运动原语与碰撞校验的三角关系，能按最小通道尺度选择分辨率。
  • 能阅读 SBPL 规划器的配置结构，并识别规划器标识、启发式初始权重与递减策略等关键字段。
  • 了解 sbpl_interface 在 MoveIt 生态中的版本现状，会判断项目是否需要移植或选择替代方案。

背景与动机

采样规划器解决高维问题的能力来自"不建图"：随机探索配置空间，回避离散化带来的维数灾难。代价是解的质量无保证、运行带随机性。搜索型规划器走相反路线：先把状态空间离散成图，再用图搜索算法保证在离散意义下的可重复与代价可控。两类方法互补，分别适配不同任务结构。

SBPL 尤其适合带有"位置先验"的任务：末端工作平面内的移动、工位间的直线走廊、需要多次重复且结果一致的操作序列。理解它的离散化参数与任意时间机制，也就理解了一整类搜索型规划器的调参逻辑。

核心原理

1. 离散状态空间：栅格与运动原语

SBPL 在笛卡尔位置维度上建立栅格（如 5 cm 边长），每个栅格单元是一个状态；状态之间通过运动原语（motion primitive）连接。原语由关节空间插值生成，保证末端沿近似直线移动且满足关节限位与运动学约束：

状态数 ≈ (Lx / r) × (Ly / r) × (Lz / r)，r 为栅格边长 三维位置栅格下状态数按 1/r³ 增长；r 从 0.02 m 调到 0.05 m，状态数约减少 15 倍

每个原语携带代价（按路径长度或执行时间估），边上的碰撞检测沿原语采样执行。分辨率是搜索型规划器最重要的刻度：太粗会漏检窄障碍，太细会让状态数按三次方膨胀。经验上取分辨率小于最小通道宽度的一半。

2. ARA*：先快后优的修复搜索

标准 A* 用 f = g + h 扩展状态，启发函数不许高估（可采纳性 admissible），代价是扩展大量状态。ARA*（Anytime Repairing A*）把启发式乘以权重 ε 加速搜索：

f(s) = g(s) + ε · h(s)，ε ≥ 1 返回解代价不超过最优解的 ε 倍；ε = 1 时退化为标准 A*

执行流程分两阶段：

  1. 快速阶段：以初始 ε（如 3.0）搜索，大权重让搜索快速收敛到一条次优路径，通常在数百毫秒内给出可行解。
  2. 修复阶段：按递减因子（如 0.2 步长）降低 ε，复用上一次搜索保留的状态信息重新扩展，代价单调下降，直到 ε 降到 1.0 得到图上最优解或时间耗尽。

任意时间（anytime）特性意味着预算越大解越好，且任意时刻中断都有可用结果。这与首解型采样规划器形成鲜明对照，也是 SBPL 时间参数设计（初始权重、递减步长、单轮搜索上限）的理论依据。

3. 确定性、可重复性与姿态维度

给定同一图结构与同一权重计划，ARA* 的搜索结果确定，这赋予 SBPL 可重复的工程特性：同一请求的路径可复现、可回归测试。需要注意姿态维度：以三维位置栅格建模时，末端姿态由运动原语的生成方式隐含决定，姿态敏感的任务要显式校验姿态沿路径的变化，或者把姿态维度纳入状态空间（代价是状态数进一步膨胀）。

4. MoveIt 集成现状与版本差异

版本状态说明

SBPL 核心库独立于 MoveIt 发展；其 MoveIt 接入层 sbpl_interface 在 MoveIt1 生态中随官方发行。在 MoveIt2 的多个发行版中，moveit_planners 官方集合未默认收录 sbpl_interface，接入前必须确认所用发行版的可用性与维护状态。本章的配置结构以 sbpl_interface 的既有实现为参照，字段名与实际可用性以所用版本为准；若发行版缺失，可选择从源码移植或在相邻方案（OMPL 的栅格化配置、笛卡尔规划接口）间取舍。

实现思路与设计

使用流程：

  1. 可用性确认：核对发行版是否提供 SBPL 规划插件；缺失时评估移植成本与替代方案。
  2. 定义工作空间：栅格只需要覆盖任务相关的三维区域，范围越小状态数越少。
  3. 选择分辨率：按最小通道宽度的一半起步，配合碰撞校验采样密度一起调整。
  4. 设置时间计划：初始权重 2.0 到 3.0，递减步长 0.2 到 0.5，单轮搜索上限 0.5 到 2.0 s。
  5. 验证与收尾：检查姿态变化、碰撞与限位，随后进入时间参数化。

参数总览（字段名以所用实现为准）

参数典型取值作用取值依据
规划器类型ARA* 系选择任意时间搜索算法需要"随时可中断"时选 ARA*
栅格分辨率0.02 到 0.10 m离散化刻度小于最小通道宽度的一半
初始权重 ε2.0 到 3.0首轮搜索偏重速度响应时间敏感时取大
权重递减步长0.2 到 0.5修复搜索的收敛速度逐步逼近 ε=1 的图上最优
单轮搜索上限0.5 到 2.0 s每轮时间上限保证多轮修复总时长可控

与第 044 章的差异点：CHOMP 面向连续轨迹的局部变形，SBPL 面向离散图的全局搜索；前者需要可行初值，后者自带全局性；前者输出平滑几何，后者输出栅格路径，通常需要再加平滑后处理。

关键代码与解读

片段 1：SBPL 规划器配置结构

# sbpl_planning.yaml（结构示意；插件名与字段名以所用发行版为准）
planning_plugins:
  - sbpl_interface/SBPLPlanner       # 规划器插件名称随实现版本不同，需与插件描述文件核对
planner_configs:
  planner_3d:
    planner_type: ARAPlanner         # 任意时间 ARA*：加权启发式 + 逐轮修复
    use_xyz_configuration: true      # 以笛卡尔位置栅格建模状态
    initial_epsilon: 3.0             # 首轮权重：先快速给出次优解
    final_epsilon: 1.0               # 收敛目标：图上最优
    epsilon_decrease: 0.2            # 每轮修复的权重递减量
    max_search_time: 1.5             # 单轮搜索墙钟上限（秒）
    resolution: 0.05                 # 栅格边长（米）：状态数按三次方随其缩减
arm_group:
  default_planner_config: planner_3d

解读：这份配置把"时间换质量"的策略显式编码：initial_epsilon 决定首解速度，epsilon_decrease 与 final_epsilon 决定后续修复的轮数与终止点。调参时优先核算状态规模：分辨率 0.05 m、覆盖 2 m × 2 m × 1 m 时约 32000 个位置状态，尚在可控范围；分辨率改到 0.02 m 后同范围接近 50 万状态，搜索时间会显著恶化。移植到 MoveIt2 时需逐字段核对名称，本结构用于建立参数地图。

片段 2：请求层选择与结果测量（Python 结构示意）

import time

def sbpl_trial(arm, goal, planner_id, trials=20):
    """在同一请求上重复测量：搜索型规划器结果确定，测量用于确认时间行为。"""
    arm.set_planner_id(planner_id)      # 规划器标识以所用实现的注册名为准
    arm.set_planning_time(2.0)          # 总预算覆盖多轮修复搜索
    arm.set_num_planning_attempts(1)    # 确定性搜索：重启无收益
    arm.set_joint_value_target(goal)

    times, successes = [], 0
    for _ in range(trials):
        t0 = time.perf_counter()
        ok, plan, _, err = arm.plan()
        times.append(time.perf_counter() - t0)
        successes += 1 if ok else 0
    mean = sum(times) / len(times)
    print(f"成功率 {successes}/{trials}，平均耗时 {mean:.3f} s")
    return times

解读：搜索型规划器的运行由权重计划与栅格结构主导，随机性远低于采样规划器，因此重复测量关注时间行为与路径一致性，并不承担成功率估计的职责。两次运行的耗时差异主要来自系统负载与缓存状态。若同一请求的路径形状反复变化，应检查运动原语生成中是否引入了随机源，或规划器是否实际退化为其他算法。

片段 3：加权 A* 的权重效应演示（原理实现）

import heapq

def weighted_astar(grid, start, goal, epsilon=1.0):
    """栅格加权 A*：epsilon 越大扩展越少、路径越可能次优。"""
    def h(a, b):
        dx, dy = abs(a[0] - b[0]), abs(a[1] - b[1])
        return max(dx, dy) + 0.414 * min(dx, dy)    # 八连通对角距离启发

    open_list = [(epsilon * h(start, goal), 0.0, start)]
    g_cost = {start: 0.0}
    expanded = 0
    while open_list:
        _, g, node = heapq.heappop(open_list)
        if g > g_cost.get(node, float("inf")):
            continue                                # 过期条目：该状态已有更优代价
        if node == goal:
            return g, expanded
        expanded += 1
        for dx in (-1, 0, 1):
            for dy in (-1, 0, 1):
                if dx == 0 and dy == 0:
                    continue
                nxt = (node[0] + dx, node[1] + dy)
                if not (0 <= nxt[0] < len(grid) and 0 <= nxt[1] < len(grid[0])):
                    continue
                if grid[nxt[0]][nxt[1]] == 1:
                    continue                        # 障碍格：直接丢弃
                step = 1.0 if dx == 0 or dy == 0 else 1.414
                ng = g + step
                if ng < g_cost.get(nxt, float("inf")):
                    g_cost[nxt] = ng
                    heapq.heappush(open_list, (ng + epsilon * h(nxt, goal), ng, nxt))
    return None, expanded

grid = [[0] * 15 for _ in range(15)]
for r in range(4, 11):
    grid[r][7] = 1                                  # 竖直障碍墙，第 11 行留门
grid[11][7] = 0
for eps in (1.0, 3.0):
    cost, expanded = weighted_astar(grid, (0, 0), (14, 14), eps)
    print(f"epsilon={eps}: 代价 {cost:.2f}，扩展状态 {expanded} 个")

解读：这段实现复现了 ARA* 首轮搜索的核心机制。权重 ε 乘在启发式上，f 值被"放大"的目标方向优先扩展，搜索呈贪心倾向：ε=3 的扩展状态数通常不到 ε=1 的一半，代价略高，恰好体现"ε 次优界"的直观含义。修复搜索在工程实现中会复用此处的 g 值与开放列表结构，逐轮降 ε 直至收敛，本片段只演示单轮。把墙上的门从一行缩到一格，可以观察两种权重下代价差距的变化，理解"次优性代价由环境瓶颈决定"。

常见坑

  • 分辨率与碰撞漏检：栅格边长 0.10 m 而壁厚只有 0.03 m，原语采样恰好落在障碍两侧，产生"穿墙"路径。修复：分辨率降到障碍特征尺寸的三分之一以下，并加密原语上的碰撞采样。
  • 把 ε 永久留在高值：只跑首轮搜索，解长期偏离最优，路径代价比预期高出 2 到 3 倍。修复：确认修复阶段被启用，检查递减步长与总预算是否留足轮数。
  • 姿态被"隐式忽略"：三维位置栅格不保证姿态连续，堆叠操作中末端可能中途翻转。修复：对路径逐点计算姿态变化率，或改用包含姿态维度的状态空间。
  • 直接把栅格路径交给控制器：栅格路径呈锯齿状，直接执行会引起关节抖动。修复：先做平滑或优化（第 043 章方法），再时间参数化。
  • 忽略插件可用性差异：在缺少 sbpl_interface 的发行版上照抄配置，节点启动报插件加载失败。修复：先做可用性确认，再决定移植或替代。

练习与思考

  1. 工作空间 3 m × 2 m × 1.5 m，要求分辨率不低于最小通道宽度 0.12 m 的一半。计算分辨率上限与对应的状态数量级。★
    提示
    分辨率取 0.06 m 以下，状态数约 50 × 33 × 25，四万有余的量级（约 4.1 万）。若改用 0.10 m（不满足要求）状态数约九千，用数字说明分辨率与规模的取舍。
  2. 把片段 3 中的 ε 取 1.0、2.0、5.0，预测代价与扩展状态数的变化趋势并运行验证，解释 ε=5.0 时代价上界。★
    提示
    扩展状态随 ε 增大而减少，代价上界为最优代价的 5 倍。引理：加权 A* 返回解的代价不超过 ε × C*，这一保证以启发式可采纳为前提。
  3. 设计一个对比实验：同一任务分别用 SBPL（0.05 m 分辨率）与 RRTConnect，各 20 次，统计耗时、路径长度与结果方差，给出各自适用的任务画像。★★
    提示
    SBPL 方差小、路径较短但耗时可预测性依环境而定；RRTConnect 方差大、平均更快。画像结论：重复性任务选搜索型，高维自由运动选采样型。
  4. 假定要把 sbpl_interface 移植到当前发行版，列出需要核对的三类接口：插件注册、规划上下文与规划场景交互，并说明各类的主要风险点。★★★
    提示
    插件注册看插件描述文件与类名；规划上下文看与规划管线接口的版本匹配；规划场景交互看碰撞检测与距离查询 API 的变化。

小结

  • SBPL 把规划转为离散状态空间上的图搜索：栅格提供状态、运动原语提供边、代价累积提供度量。
  • ARA* 以加权启发式先快后优，返回解具有 ε 次优保证，权重递减的修复搜索让解随时间单调改善。
  • 分辨率是首要参数：状态数按三次方增长，取值应小于最小通道宽度的一半并配合碰撞采样密度。
  • 搜索结果确定、可重复，适合需要回归验证的重复性任务；姿态维度需显式校验或纳入状态空间。
  • sbpl_interface 在 MoveIt2 各发行版的收录情况不一，接入前先确认可用性，缺失时评估移植或替代。
