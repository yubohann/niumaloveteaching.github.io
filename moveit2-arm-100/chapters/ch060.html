第三篇 · 规划算法与求解器

第 060 章：阶段实践：规划器选型与调优

把第 039 到 059 章的全部工具收束成两样交付物：一张按任务形态查表的选型决策表，一份从请求层到执行层的调优清单。本章给出决策流程、场景化配置模板与回归验收方法。

  • 主题：阶段实践 / 选型决策与调优闭环
  • 关键机制：任务形态分类、参数分层、基线回归、降级链设计
  • 预计学时：60 分钟
  • 前置章节：第 059 章

学习目标

  • 能按任务形态（自由转场、精密接近、工艺曲线、质量敏感扫描、重复性结构化工位）给出规划器选型结论与理由。
  • 掌握参数分层的调优清单：请求层、管线层、规划器层、场景层、IK 层、执行层各管一段。
  • 会设计降级链（fallback chain）：主规划失败时按预设顺序切换替代方案，保证最差情况有可交付结果。
  • 能用"基准、剖析、诊断、修改、回归"五步闭环组织一次调优，并输出可归档的对照数据。
  • 能把选型与调参结论固化为配置文件与决策记录，供后续任务与团队复用。

背景与动机

本篇从管线结构（039）走到轨迹资产（059），中间经历了算法族选择、预算参数、适配器、三类规划器与四种 IK 插件。学完单点知识不等于会做工程决策：现场问题的形式是"这个任务该用什么、参数定多少、失败了怎么退"，需要把知识组织成可执行的决策流程。

本章给出两样直接可用的交付物：选型决策表与调优清单；并用一个降级链实现与一次回归流程，演示从决策到验证的完整动作。

核心原理

1. 选型决策表：从任务形态出发

选型的第一步是识别任务形态，其次才是比较算法优劣：

任务形态特征首选理由与约束
自由空间转场起止位姿明确、中间无精细要求OMPL 的 RRTConnect（第 040 章）首解快、概率完备；预算 0.5 到 1.5 s
精密接近段沿指定方向直线进入Pilz LIN（第 046 章）形态由工艺规定；需位姿目标与容差
工艺圆弧圆弧轨迹（焊、涂）Pilz CIRC三点定圆；同 LIN 的逐点校验
质量敏感扫描平滑与间隙优先、允许等待OMPL 初值 + CHOMP 优化（第 044 章）两段式：可行解加美化；需时间参数化
重复性结构化工位结果需可复现、带位置先验SBPL（可用时，第 045 章）确定性搜索；注意版本可用性
笛卡尔约束路径全程带路径约束OMPL 加约束采样（第 035 章）约束越紧成功率越低；可评估 Pilz 替代

结论：选型表回答"用什么"，但不回答"一定成功"；任何选型都必须配套降级链与验收数据。

2. 调优清单：六层参数各管一段

层参数示例目标章节
请求层allowed_planning_time、num_planning_attempts、缩放因子预算与响应承诺041
管线层适配器链顺序与开关、时间参数化请求良定义与输出可执行042
规划器层采样范围、权重、迭代上限、启发式权重求解成功率与解质量040 至 046
场景层碰撞保证金、允许碰撞矩阵、物体几何简化检测正确性与速度028、048
IK 层插件选择、超时、解的选择策略笛卡尔目标可达性050 至 054
执行层速度加速度缩放、轨迹校验、重放策略跟踪质量与节拍058、059

调优顺序遵循"由外到内"：先固定请求预算，再保证适配器链正确，然后才调规划器与场景参数。跨层混调（同时改时间预算与规划器权重）会让对照数据失去归因能力。

3. 降级链：把"失败"变成"有结论的失败"

降级链是一份预设的尝试序列，每级有明确的适用条件与时间预算：

主方案失败 → 次方案（松约束或换形态） → 保底方案（关节空间转场） → 上报 每级都记录失败原因（第 049 章错误码），最后一级的失败就是"任务级失败"

示例：精密接近段先试 Pilz LIN；失败（奇异或碰撞）退到"抬高起点后的两段 LIN"；再失败退到 OMPL 关节空间运动到接近点后重试；全部失败则把工件与场景信息上报，等待人工处置。降级链的价值在于把失败限制在可解释的类别内；逐次补救所有失败并不现实，超出类别的问题由人工处置兜底。

4. 调优闭环：基准、剖析、诊断、修改、回归

五步闭环把本篇方法串起来：

  1. 基准（047）：在当前配置上跑问题集，得到成功率与时间分位数的基线。
  2. 剖析（048）：对慢问题分项测量，确定瓶颈层。
  3. 诊断（049）：对失败问题读错误码、做状态与 IK 检查，归因分层。
  4. 修改：只动与瓶颈/归因对应的那一层参数，小步变更。
  5. 回归：用同一问题集重测，对照基线判定改善，归档数据。

没有基线的修改无法验收，没有回归的调优会把已解决的问题再次引入。

实现思路与设计

阶段实践的落地步骤：

  1. 任务编目：把现场任务按第 1 节的形态分类，每类列出代表请求。
  2. 场景模板化：为每类任务写出配置模板（规划器标识、预算、适配器开关、IK 插件）。
  3. 降级链固化：把每级的触发条件（错误码类别）与时间预算写入调用层代码。
  4. 基线归档：跑一次问题集，归档基线与配置快照。
  5. 迭代调优：按闭环五步逐项改善，每轮保留对照数据。
  6. 决策记录：把"为什么选它、为什么是这个参数"写成短记录，与配置一起归档。

关键代码与解读

片段 1：降级链实现（Python 结构）

def plan_with_fallback(arm, task):
    """按预设序列降级：每级记录失败原因，最后一级失败才是任务级失败。"""
    attempts = [
        {"planner": "LIN",  # 主方案：工艺直线（Pilz）
         "budget": None, "pose": task["approach_pose"]},
        {"planner": "RRTConnect",  # 次方案：抬高起点后关节空间绕行
         "budget": 1.0, "goal": task["via_goal"]},
        {"planner": "RRTConnect",  # 保底方案：直接到接近点，接受姿态偏差
         "budget": 1.5, "goal": task["approach_goal"]},
    ]
    history = []
    for level in attempts:
        arm.set_planner_id(level["planner"])
        if level["budget"]:
            arm.set_planning_time(level["budget"])
        target = level.get("pose") or level.get("goal")
        arm.set_pose_target(target) if level.get("pose") else arm.set_joint_value_target(target)
        ok, plan, _, err = arm.plan()
        history.append({"planner": level["planner"], "ok": ok, "err": err.val})
        if ok:
            return plan, history                    # 任意一级成功即返回
    return None, history                            # 全部失败：上报历史供诊断（第 049 章）

解读：降级链的三个设计要点都在代码结构里。其一，每级显式声明规划器与预算，禁止隐式继承上一次调用的参数，保证行为可复现。其二，失败历史全程收集，最终上报的内容包含每级的失败层级与错误码，直接衔接诊断流程。其三，保底方案与主方案的目标可以不同（接近点允许姿态偏差），体现"形态让步优先保交付"的降级原则。

片段 2：回归验收脚本（Python，接第 047 章测量框架）

import json

def regression_check(arm, problem_set, baseline_file, planner_id="RRTConnect",
                     budget=1.0, trials=20):
    """修改参数后重测同一问题集，与基线对照并输出差异表。"""
    baseline = json.loads(open(baseline_file, encoding="utf-8").read())
    arm.set_planner_id(planner_id)
    arm.set_planning_time(budget)

    report, worse = {}, []
    for p in problem_set:
        arm.set_joint_value_target(p["goal"])
        ok_count = 0
        for _ in range(trials):                     # 每条问题重复固定次数
            if arm.plan()[0]:
                ok_count += 1
        rate = ok_count / trials
        report[p["name"]] = rate
        old = baseline.get(p["name"], 0.0)
        if rate < old - 0.05:                       # 允许 5 个百分点的波动噪声
            worse.append((p["name"], old, rate))

    print(f"退化的问题：{worse}" if worse else "无显著退化")
    return report

解读：回归验收的本质是"用数据判定改善"：允许 5 个百分点的波动带是必要的防噪设计，采样规划器的成功率在小样本下天然波动，没有容差的逐点比较会把噪声当回归。输出只强调"退化清单"，改善项由归档数据说话。基线文件与问题集定义应随配置一起版本化（第 047 章纪律）。

片段 3：决策记录的推荐字段（YAML 结构）

# decision_record.yaml：与配置文件一起归档，回答"为什么"的问题
task: 精密接近段（插孔前 30 mm）
chosen:
  planner: LIN                     # 工艺直线，形态由工艺规定（第 046 章）
  pose_tolerance: 0.02 rad         # 姿态容差按贴合要求收紧
  velocity_scaling: 0.2            # 接近速度保守，降低接触冲击
alternatives:
  - RRTConnect: "会产生非直线路径，插孔对不准，仅作降级备选"
  - CHOMP: "平滑性无关，接近段长度短，优化收益有限"
validation:
  baseline: ik_and_planner_regression_v3.yaml
  result: "问题集 12 条，成功率 11/12，失败 1 条为奇异预检拒绝（预期内）"
notes: "失败条目需人工确认工件姿态后重试，见错误码 NO_IK_SOLUTION 处置"

解读：决策记录用最少字段回答三个问题：选了什么、为什么没选别的、验证结果如何。"备选及排除理由"栏是这份记录的核心价值：半年后接手的人不必重新推导决策，也能知道在什么条件下应当推翻它。验证栏引用可复现的基线文件，把"当时测过"变成"可以再测一遍"。

常见坑

  • 无序调参：同时改预算、权重与场景参数，改善无法归因，退化无法定位。修复：按调优清单由外到内，一次只动一层。
  • 没有基线就优化：调优后的"感觉更快"没有数据支撑。修复：先跑基准并归档（047），再进入修改循环。
  • 过拟合单一场景：在一条请求上把参数调到极致，同类任务整体变差。修复：问题集按形态分组，验收看组级与汇总两级指标。
  • 降级链无预算上限：每级都耗满时间，最坏延迟叠加失控。修复：为整条链设总时间预算，逐级扣减（第 041 章方法）。
  • 忽视执行侧验收：规划指标达标但执行跟踪差、节拍超预算。修复：验收指标加入执行时长与跟踪偏差（058、059）。

练习与思考

  1. 为五个任务形态各写一句选型结论与一条主要约束（如"精密接近：Pilz LIN，主要约束是奇异预检"）。★
    提示
    参考第 1 节决策表；约束一栏聚焦"这个选择最怕什么"，避免复述优点，例如"自由空间转场：RRTConnect，最怕响应预算被适配器吞掉"。
  2. 把某个失败任务的错误码替换进降级链设计：T 为含奇异邻域的接近任务，写出三级降级与各级触发条件。★
    提示
    一级 LIN（失败触发：LIN 不可行或 NO_IK_SOLUTION）；二级抬高起点两段 LIN（触发：奇异预检拒绝）；三级 RRTConnect 到接近点（触发：二级仍不可行）。每级预算递减。
  3. 设计一次完整的调优闭环：目标"窄通道成功率从 62% 提升到 80%"，写出五步动作与每步的产出物。★★
    提示
    基准（30 次/问题集的成功率表）→ 剖析（耗时分布与碰撞检测占比）→ 诊断（失败错误码分布，确认是超时还是无解）→ 修改（按归因加预算或换规划器）→ 回归（同集重测，允许 5 个百分点波动带）。产出物：基线文件、剖析报告、归因表、变更记录、回归对照。
  4. 评审题：某配置记录只有"planner: RRTstar，时间 3 s"，缺失了哪些字段会导致半年后无法复现？列出至少四项并说明各自的角色。★★★
    提示
    适配器链状态（042）、尝试次数（041）、缩放因子（057）、场景版本（022）、IK 插件（050）、模型版本。缺任何一项都可能在复现时得到不同行为。

小结

  • 选型从任务形态出发：转场用采样、接近用指令式、质量敏感用优化、重复性用搜索，每项选择都配降级链。
  • 调优按六层清单由外到内：请求、管线、规划器、场景、IK、执行，一次只动一层。
  • 降级链本级冗余与总预算上限并行设计，失败历史全程收集并衔接错误码诊断。
  • 调优闭环五步：基准、剖析、诊断、修改、回归；无基线不优化，无回归不固化。
  • 决策记录回答"选什么、为什么、验没验"，与配置、基线、问题集一同归档。
