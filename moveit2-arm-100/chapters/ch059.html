第三篇 · 规划算法与求解器

第 059 章：轨迹记录与回放

把规划结果保存为可复用的轨迹资产：从记录来源、落盘格式，到回放前的时间重定基、字段校验与执行下发。本章给出"记录、校验、重放"的完整安全流程，并划清与轨迹插值基础操作的边界。

  • 主题：轨迹资产化 / 记录与重放流程
  • 关键机制：消息序列化、时间重定基、字段校验、执行下发
  • 预计学时：50 分钟
  • 前置章节：第 058 章

学习目标

  • 理解轨迹资产的三个用途：调试复现、固定动作复用、离线优化后下发，并据此选择记录来源。
  • 掌握两种记录手段：消息话题录制（如显示轨迹话题）与消息直接序列化落盘，理解各自取舍。
  • 能对载入的轨迹执行回放前校验：时间戳单调性、关节名匹配、起点与当前状态一致性、限位检查。
  • 理解时间重定基（rebase）的必要性：把相对耗时转换为从当前执行时刻起算的新时间轴。
  • 会通过执行动作安全下发重放轨迹，并处理回放期间的取消与失败。

背景与动机

规划结果在工程上的生命周期远不止"这次执行完就丢弃"：精心调试出的轨迹值得保存为资产，用于回归复现、固定工艺动作复用、离线优化后的现场下发。轨迹消息本身是纯数据，天然支持序列化，问题在于回放环节的工程细节：时间轴、字段完整性与场景一致性。

第 015 章讲解了重放与插值的基础操作，本章向前一步：把"记录"做规范，把"回放"做安全，形成可检查、可回退的流程。第 047 章的基准测试与第 060 章的调优都会受益于同一套轨迹资产。

核心原理

1. 记录来源与用途的对应

来源内容适用用途
规划结果（planned_trajectory）规划器输出、带时间参数资产化保存、离线评审
执行记录（executed_trajectory）实际经过的路径点跟踪质量分析、真实节拍统计
显示轨迹话题最近一次规划的轨迹与起始状态快速抓取与可视化回放

显示轨迹话题（DisplayTrajectory）的载荷包含轨迹本体、起始状态与模型标识，随每次规划自动发布，适合作为"顺手记录"的挂钩点。执行记录则用于质量分析：与计划轨迹逐点对照即可得到跟踪误差分布（第 058 章练习）。

2. 两种落盘方式

  • 话题录制：用记录工具订阅显示轨迹话题，把消息流写入数据包。优点是通用、无需代码；缺点是把与轨迹无关的重复消息一并收入，回看时要挑拣。
  • 直接序列化：在节点内把轨迹消息序列化成字节，与元数据（时间、场景版本、工艺编号）一起写入自定义文件。优点是干净、可加元数据；缺点是需要维护文件格式约定。

选择原则：探索期用话题录制快速积累样本；进入产线复用时切换为"直接序列化加元数据"，让每条轨迹都可追溯。

3. 回放的头号问题：时间轴

轨迹中的 time_from_start 是相对轨迹起点的耗时（第 057 章）。同一条轨迹"昨天规划、今天回放"时，这组相对时间仍然有效，但执行侧对时间戳的解读有两条常见规则：

  • 重定基：下发前把时间戳整体平移，让第一点从"即将开始的时刻"起算。保留相邻间隔比例，不改变速度剖面。
  • 时间缩放：按倍率拉伸或压缩全部时间戳，实现慢速回放（调试）或提速回放（需核对限位约束）。
t′i = ( ti − t0 ) × s，s 为缩放倍率（s = 1 即仅重定基） t0 为轨迹首点的相对耗时；重定基消除"起点偏移"，缩放改变节拍

直接回放未经重定基的旧轨迹，是控制器拒绝或异常执行的常见原因：部分实现以消息时间推导首点时刻，旧时间戳会让整条轨迹"立刻到期"。

4. 回放校验清单

检查项判据不通过时的处理
时间戳单调相邻 time_from_start 严格递增拒绝回放，回到记录侧排查
关节名匹配与控制器关节列表逐字一致（顺序与名称）按名称重排，或拒绝
起点一致轨迹首点与当前关节值之差小于阈值先运动到轨迹起点再回放
限位与速度各点位置与速度在模型限值内裁剪时间或拒绝
场景一致回放场景与记录时版本一致做碰撞检查，必要时重规划

校验的定位是"宁可拒绝，不可带病执行"：轨迹资产的价值来自可复现，一次带病执行的代价远大于一次拒绝。

实现思路与设计

记录与回放的完整流程：

  1. 记录侧：确定来源（规划结果或显示轨迹话题）；落盘时附元数据（时间、模型版本、场景版本、工艺编号）。
  2. 复核侧：读取轨迹，执行校验清单前四项；把结论（通过或拒绝原因）写入资产旁注。
  3. 回放侧：重定基（可选缩放）；确认起点一致；经执行动作下发；监控结果。
  4. 场景侧：回放前做一次状态有效性检查与碰撞检查，确认环境未变（第 049 章工具）。
  5. 归档侧：记录本次回放的缩放倍率与结果，形成资产的使用履历。

参数与阈值参考

项典型值说明
起点一致阈值0.02 rad超过则先运动到起点，避免首段跟踪误差
回放缩放0.5 到 1.0调试用慢速；提速回放需重新核对速度上限
时间戳容差相邻点间隔大于 1 ms过密的点对控制器无意义，可重采样

与第 015 章的边界：插值方法与插值密度的选择属于基础操作，那一章已覆盖；本章聚焦资产化流程与安全重放。两章结合形成"记录、校验、插值、重放"的完整链路。

关键代码与解读

片段 1：订阅显示轨迹话题并直接序列化落盘（Python）

import time, pathlib
import rclpy
from rclpy.node import Node
from rclpy.serialization import serialize_message
from moveit_msgs.msg import DisplayTrajectory

class TrajectoryRecorder(Node):
    """捕捉最近一次规划的显示轨迹，附元数据后直接落盘。"""
    def __init__(self, out_dir="trajectory_assets"):
        super().__init__("trajectory_recorder")
        self.out_dir = pathlib.Path(out_dir)
        self.out_dir.mkdir(exist_ok=True)
        self.sub = self.create_subscription(
            DisplayTrajectory, "/display_planned_path", self.on_traj, 10)

    def on_traj(self, msg):
        if not msg.trajectory:                # 空消息（规划失败或清除显示）
            return
        stamp = time.strftime("%Y%m%d_%H%M%S")
        asset = self.out_dir / f"traj_{stamp}.bin"
        # 序列化消息本体：回放侧用反序列化还原，格式稳定性由消息定义保证
        asset.write_bytes(serialize_message(msg))
        # 旁注文件记录元数据：来源话题、模型与工艺标识由调用方补齐
        (self.out_dir / f"traj_{stamp}.meta").write_text(
            f"source=/display_planned_path\nmodel_id={msg.model_id}\n", encoding="utf-8")
        self.get_logger().info(f"已保存轨迹资产 {asset.name}")

解读：直接序列化保留了消息的完整结构（轨迹、起始状态、模型标识），回放侧用对应反序列化函数即可还原。元数据旁注是本片段的设计重点：轨迹资产脱离场景版本与模型版本后就失去可复现性，model_id 只是第一项，场景与工艺标识应由调用方按需补齐。订阅队列深度 10 足够：显示话题随规划低频发布，过深没有收益。

片段 2：回放前校验与时间重定基（Python）

def validate_and_rebase(joint_trajectory, controller_joint_names,
                        current_positions, start_tol=0.02, scale=1.0):
    """校验五项后重定基：返回可下发的轨迹或拒绝原因。"""
    names = list(joint_trajectory.joint_names)
    if names != list(controller_joint_names):          # 顺序与名称都要一致
        return None, "关节名或顺序不匹配"

    points = joint_trajectory.points
    if len(points) < 2:
        return None, "路径点过少，无法构成轨迹"

    # 时间戳单调性检查：任何倒退都说明资产损坏或拼接错误
    for a, b in zip(points[:-1], points[1:]):
        ta = a.time_from_start.sec + a.time_from_start.nanosec * 1e-9
        tb = b.time_from_start.sec + b.time_from_start.nanosec * 1e-9
        if tb <= ta:
            return None, "时间戳非严格递增"

    # 起点一致性：偏差超过阈值时要求先运动到轨迹起点
    first = points[0].positions
    if max(abs(a - b) for a, b in zip(first, current_positions)) > start_tol:
        return None, "当前状态距轨迹起点过远，先执行接近运动"

    # 重定基与缩放：首点归零，其余点按倍率缩放（不改几何形状）
    t0 = points[0].time_from_start.sec + points[0].time_from_start.nanosec * 1e-9
    for p in points:
        t = p.time_from_start.sec + p.time_from_start.nanosec * 1e-9
        t_new = (t - t0) * scale
        p.time_from_start.sec = int(t_new)
        p.time_from_start.nanosec = int((t_new - int(t_new)) * 1e9)
    return joint_trajectory, None

解读：校验顺序按"代价从低到高"排列：名称与长度检查是纯字符串与计数操作，时间戳与起点检查需要遍历，放在其后。重定基的实现要点是"首点归零"：缩放倍率同时作用于所有间隔，几何路径完全不变，改变的只是到达每个点的时间。拒绝原因用短句返回，便于资产旁注与日志直接落库；生产环境应把"起点过远"与"资产损坏"区分为两类处置。

片段 3：录制与查看资产（命令示意）

# 1) 话题录制方式收集显示轨迹（探索期快速积累样本）
ros2 bag record -o traj_bag /display_planned_path

# 2) 查看数据包内容与消息数量，确认抓到了轨迹
ros2 bag info traj_bag

# 3) 回放前用状态有效性服务复核环境（第 049 章工具）
ros2 topic echo /monitored_planning_scene --once

# 4) 资产归档建议：数据包或序列化文件与元数据旁注配对保存，
#    元数据包含模型版本、场景版本、工艺编号与记录时间

解读：命令行路径适合探索与应急，代码路径适合产线资产化，两者共用同一批消息定义。归档纪律与代码同等重要：没有元数据的轨迹资产无法回答"这条轨迹当时对应的场景是什么"，可复现性无从谈起。第 047 章的基准测试正是依靠这类资产复现同一批问题集。

常见坑

  • 直接回放旧时间戳：未重定基就下发，控制器视首点为"早已到期"，轨迹被拒或瞬间跳过。修复：统一下发前执行重定基。
  • 关节名与顺序不核对：控制器关节列表与轨迹顺序不一致，各轴动作错位。修复：按名称重排路径点，或在记录侧固化顺序约定。
  • 只有位置的轨迹直接提速回放：缺失速度字段的轨迹依赖控制器插值，提速后可能突破速度上限。修复：回放前补齐时间参数化并按新倍率重新核对。
  • 忽略场景变化：昨天有效的轨迹在今天的工装布局下扫过障碍。修复：回放前做状态有效性检查与轨迹级碰撞检查，必要时重新规划。
  • 资产没有元数据：文件名只有时间戳，无法判断适用工艺与模型版本。修复：旁注元数据并把校验从"人肉回忆"变为字段比对。

    提示
    首点归零、末点变为 1.5 s，全部间隔减半；关节位置序列不变，仅到达时间变化。总时长从 3.0 s 变为 1.5 s。
  2. 为"回放前校验"设计遗漏场景：若只检查时间戳与关节名，可能漏掉哪两类问题？各举一例。★
    提示
    漏掉起点不一致（执行时首段大步跟踪）与场景变化（轨迹穿过新障碍）。两类都需要位置与场景信息，属校验清单后两项。
  3. 设计资产元数据的字段清单，说明每个字段支撑的一项复现能力。★★
    提示

  4. 分析题：把执行记录与计划轨迹逐点对照得到的偏差分布，能区分哪两类问题（提示：恒定偏移与随机抖动）？各自的处置方向是什么？★★★
    提示
    恒定偏移指向标定或零点误差（第 098 章方向）；随机抖动指向控制器增益、负载或时间戳抖动。前者用标定修正，后者调控制参数并复查轨迹时间密度。

小结

  • 轨迹资产有三类用途：调试复现、固定动作复用、离线优化下发；来源包括规划结果、执行记录与显示轨迹。
  • 话题录制适合探索，直接序列化配合元数据适合产线资产化；可复现性依赖模型与场景版本的记录。
  • 重定基与缩放是回放前的时间处理核心：首点归零、间隔按倍率缩放，几何形状不变。
  • 校验清单五项：时间戳单调、关节名匹配、起点一致、限位速度、场景一致；宁可拒绝，不可带病执行。
