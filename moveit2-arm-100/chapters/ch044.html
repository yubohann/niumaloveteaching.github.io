第三篇 · 规划算法与求解器

第 044 章：使用 CHOMP 规划器

CHOMP（Covariant Hamiltonian Optimization for Motion Planning）把轨迹优化做成规划器插件：给定起点、终点与一条初值轨迹，通过协变梯度与哈密顿蒙特卡洛迭代降低平滑与障碍代价。本章讲透它的泛函结构、关键参数与工程用法。

  • 主题：优化型规划器 / CHOMP
  • 关键机制：协变梯度、障碍代价场、HMC 扰动、初值轨迹
  • 预计学时：55 分钟
  • 前置章节：第 043 章

学习目标

  • 写出 CHOMP 的代价泛函分解，理解平滑项与障碍项各自的计算方式与梯度来源。
  • 理解协变更新 ξ ← ξ − ηA−1∇F 与岭正则（ridge regularization）的作用，能解释更新为何比朴素梯度平滑。
  • 掌握 CHOMP 的配置项：迭代上限、时间上限、安全间隙、HMC 标准差、初值生成方式，并知道每项调大调小的后果。
  • 会通过管线标识（pipeline id）与规划器标识（planner id）在请求层选择 CHOMP，并保证输出轨迹带时间参数。
  • 能设计"采样规划器提供初值、CHOMP 做优化"的组合流程，并用轨迹指标验证收益。

背景与动机

第 043 章建立了代价泛函与梯度更新的通用框架，本章落到第一个工程可用的优化型规划器。CHOMP 的工程价值在于：它对初值做连续变形，天然产出平滑轨迹，且每次迭代的计算量固定，时间行为可预测。在接近、扫查、节拍敏感的操作中，平滑轨迹意味着更少的关节冲击与更稳定的控制跟踪。

同时，CHOMP 暴露了优化型规划器的典型约束：需要可行初值、只能收敛到局部最优、输出的是几何轨迹。理解这些约束的边界，才能在选型时与 OMPL 族规划器形成互补（第 060 章展开决策表）。

核心原理

1. 代价泛函与梯度来源

CHOMP 最小化的泛函由平滑项与障碍项构成（可选动力学项）：

F[ξ] = ws · Fsmooth + wo · Fobstacle ξ 为离散化轨迹；平滑项解析求梯度，障碍项经距离场求梯度后沿雅可比映射回关节空间

平滑项惩罚速度与加速度的组合范数，其海森近似记为矩阵 A；障碍项对工作空间中轨迹的每个采样点查询有符号距离（signed distance），在安全间隙 cmin 之内产生代价，并把工作空间梯度经雅可比转置映射回关节空间：

∇q c = J(q)T ∇x c J 为末端或查询点的几何雅可比（Jacobian）；距离场由规划场景的碰撞结构构建

障碍代价按弧长积分并归一化，使轨迹"走得远的段"和"走得近的段"获得一致的权重；本质上是软惩罚，优化结束后仍要独立校验碰撞。

2. 协变更新与岭正则

迭代更新使用协变梯度形式：

ξ ← ξ − η A−1 ∇F[ξ]，其中 A = 平滑项海森 + λI λ 即岭因子（ridge factor），防止 A 在接近直线轨迹上奇异

A−1 相当于把梯度沿轨迹方向"抹匀"，单点上的尖锐梯度被平滑成整条曲线的缓变力。当轨迹接近直线时 A 的最小特征值趋近零，直接求逆会放大噪声；岭因子 λ 抬高特征值下界，代价是更新略偏保守。λ 的调参区间很窄：过小产生数值振荡，过大拖慢收敛，常见量级 10−4 到 10−2。

3. HMC 扰动：偶尔"踢一脚"

纯梯度下降会卡在局部极小（典型的"贴墙滑行"或"折角"形状）。CHOMP 以一定概率执行哈密顿蒙特卡洛（Hamiltonian Monte Carlo, HMC）步骤：给轨迹注入动量做一次模拟推进，然后按能量判据接受或拒绝。动量标准差由 hmc_stdev 控制：

  • 取 0：退化为纯梯度下降，确定性增强，复杂场景易卡住。
  • 取较大值（如 0.1 以上）：逃逸能力增强，但轨迹在收敛前出现可见抖动，时间行为变差。
  • 常用量级 0.005 到 0.05。

HMC 让 CHOMP 带有随机成分：同一请求两次运行的轨迹可能不同，性能评估同样要用多次重复实验（与第 041、047 章的方法一致）。

4. 初值与输出

CHOMP 不搜索全局路径。初值来自三条途径：请求中携带的参考轨迹（reference trajectory）、按配置的插值方法生成的直线型初值、或工具链上游规划器的结果。初值穿越障碍时，障碍代价会把路径点推向障碍两侧，形成折叠畸形解，工程上应先获得可行初值再交给 CHOMP。输出为无时间戳的几何轨迹，必须经过时间参数化才能执行。

实现思路与设计

接入 CHOMP 的步骤：

  1. 开启管线：在机器人配置中加入 CHOMP 管线条目（插件 chomp_interface/CHOMPPlanner，管线与规划器标识常见为 chomp 与 CHOMP，以发行版配置为准）。
  2. 确认响应链：CHOMP 管线配置中必须包含时间参数化条目，否则输出轨迹不可执行。
  3. 准备初值：简单场景可用插值初值；复杂场景用 OMPL 规划结果作为参考轨迹注入请求。
  4. 设定预算：先给迭代上限 200、时间上限 2 s 量级跑通，再按代价曲线收敛情况收紧。
  5. 验证结果：复检碰撞、间隙与限位，并计算平滑度指标与基线对照。

参数总览（字段名以所用发行版配置为准）

参数典型取值作用取值依据
迭代上限100 到 400 次梯度下降的最大轮数观察代价曲线进入平台的位置
时间上限1.0 到 3.0 s优化过程墙钟上限与服务水平约定对齐
安全间隙0.02 到 0.10 m障碍代价生效距离按机械臂速度与感知噪声留裕量
岭因子 λ10−4 到 10−2矩阵求逆正则化出现数值振荡时向上调
HMC 标准差0.005 到 0.05随机扰动强度卡局部极小时向上调，抖动过大时向下调
初值插值方式样条或线性未提供参考轨迹时的初值生成自由空间用样条，近似直线任务用线性
组合模式：OMPL 出可行解，CHOMP 出好解

推荐流程是两段式：先用 RRTConnect 在 0.5 到 1.0 s 内求可行路径，再以其为参考轨迹调用 CHOMP 优化 1 到 2 s。该组合把"概率完备的可行性"与"梯度方法的平滑性"叠加，避免了 CHOMP 直接面对复杂障碍初值问题。注意两段的失败要独立处理：第一段失败则报无解，第二段失败则回退第一段结果。

关键代码与解读

片段 1：CHOMP 管线配置

# chomp_planning.yaml（结构示意，字段以所用发行版为准）
planning_plugins:
  - chomp_interface/CHOMPPlanner    # 规划器插件类名（插件描述文件中的注册名）
request_adapters: >-
  default_planner_request_adapters/FixStartStateBounds
  default_planner_request_adapters/FixStartStateCollision
  default_planner_request_adapters/AddTimeParameterization
# 注：时间参数化是 CHOMP 输出的必需环节，输出几何轨迹缺少时间戳将无法执行

planner_configs:
  CHOMP:
    max_iterations: 200            # 梯度迭代上限：向平台期取值，避免空转
    planning_time_limit: 2.0       # 优化墙钟上限（秒）
    collision_clearance: 0.05      # 安全间隙（米）：期望保持的最小距离
    ridge_factor: 1.0e-3           # 岭因子：稳定 A 的求逆
    hmc_stdev: 0.01                # HMC 扰动强度：逃逸局部极小
    use_stochastic_descent: true   # 随机步长策略，配合 HMC 提高搜索面
    trajectory_initialization_method: "quintic-spline"  # 无参考轨迹时的初值方式
arm_group:
  default_planner_config: CHOMP

解读：这份配置展示了三条设计线索。第一，预算双保险：迭代上限与时间上限同时存在，任一触发即停止，避免病态初值下的无限迭代。第二，安全间隙与岭因子量级分离：前者是物理量（米），后者是数值量（无量纲），调参时切勿混用经验值。第三，初值策略显式声明：在没有参考轨迹的调用中决定轨迹起步形状；接入 OMPL 参考轨迹后该项自动让位。所有字段名随发行版演进，迁移时对照官方模板逐项核对。

片段 2：请求层选择 CHOMP 管线（C++）

#include <moveit/planning_interface/planning_interface.h>

// 用规划管线标识与规划器标识选择 CHOMP：请求字段是最终生效的控制点
bool plan_with_chomp(moveit::planning_interface::MoveGroupInterface& mg,
                     const std::vector<double>& goal,
                     moveit::planning_interface::MoveGroupInterface::Plan& plan)
{
  mg.setPlanningPipelineId("chomp");   // 选择 CHOMP 管线：包含其适配器与响应链
  mg.setPlannerId("CHOMP");            // 选择管线内的规划器实例
  mg.setPlanningTime(2.0);             // 优化型规划器：时间上限决定迭代轮数
  mg.setNumPlanningAttempts(1);        // 迭代收敛过程确定性较强，无需多次重启

  mg.setJointValueTarget(goal);
  auto code = mg.plan(plan);
  if (code != moveit::core::MoveItErrorCode::SUCCESS)
    return false;                      // 失败原因见第 049 章的错误码诊断流程

  // 输出为几何+时间轨迹；如需校验间隙，可在规划场景中对 plan.trajectory 逐点检测
  return true;
}

解读：选择的落点是请求字段 pipeline_id 与 planner_id，这两个字段会随请求传入管线，覆盖节点默认配置。把尝试次数设为 1 的依据是 CHOMP 的失败模式：失败多源于时间耗尽，重启同一初值会沿同一路径再次失败，收益有限。若期望多次尝试，更有效的做法是更换初值（例如先用 OMPL 重新求一条参考轨迹），并避免盲目重启。校验环节放在规划成功之后，体现"软惩罚需独立验证"的原则。

片段 3：以 OMPL 结果为初值的组合调用（Python 伪代码层次）

# 组合流程：第一段求可行，第二段做优化。接口以发行版为准，此处突出控制结构。
def plan_feasible_then_optimize(arm, goal, feasible_time=1.0, optimize_time=2.0):
    # 第一段：RRTConnect 快速给出可行路径（几何折线）
    arm.set_planner_id("RRTConnect")
    arm.set_planning_time(feasible_time)
    ok, feasible, _, err = arm.plan()
    if not ok:
        return None, err                 # 无可行解：交由上层压缩工作空间或放宽约束
    # 第二段：把可行解作为参考轨迹交给 CHOMP 优化平滑度与间隙
    arm.set_planner_id("CHOMP")
    arm.set_planning_time(optimize_time)
    if hasattr(arm, "set_reference_trajectories"):   # 参考轨迹注入接口随版本不同
        arm.set_reference_trajectories([feasible])
    ok2, optimized, _, err2 = arm.plan()
    if ok2:
        return optimized, None           # 优先交付优化解
    return feasible, err2                # 优化失败时回退可行解，保证可交付

解读：组合结构的关键在于两级返回策略：优化失败不影响可行性结论，回退路径让最差情况仍有结果。参考轨迹的注入方式因接口版本而异，代码中用能力探测保护，工程实现里应替换为所选定接口的正式写法。两段时间预算分别控制：第一段追求"快而可行"，第二段追求"慢而平顺"，与各自的算法特性匹配。

常见坑

  • 输出缺少时间参数化：选用 CHOMP 管线但漏配响应链，轨迹无法执行，控制器返回轨迹无效。修复：核对管线配置中的时间参数化条目。
  • 初值穿越障碍：直接以直线插值起步，优化结果在障碍两侧折叠。症状是轨迹形状怪异且间隙指标差。修复：改用 OMPL 结果作初值，或缩小安全间隙先打通流程。
  • 安全间隙大于可行空间：目标附近本身距离障碍较近时，间隙设置过大导致代价始终无法降到收敛水平，规划时间耗尽仍报失败。修复：按最紧通道宽度的一半设置间隙，或对目标附近放宽。
  • 岭因子过小引发数值振荡：代价曲线在迭代后期上下跳动，轨迹出现高频抖动。修复：把岭因子提高一个数量级并重新观察。
  • 把 CHOMP 当全局规划器：环境出现新的通道时 CHOMP 无法重新选路，稳定失败。修复：选型阶段明确其定位为优化层，全局可行性交给采样规划器。

练习与思考

  1. 把 hmc_stdev 从 0 调到 0.05，预测三类场景（自由空间、单个障碍、窄通道）的规划成功率与轨迹稳定性变化。★
    提示
    自由空间：几乎无差异；单障碍：成功率上升，轨迹在收敛前抖动；窄通道：逃逸能力有帮助但画面抖动明显，时间增加。用重复 30 次的成功率对照验证。
  2. 推导：为什么协变更新能抑制"单点尖峰"而朴素梯度不能？从 A−1 的平滑作用角度说明。★★
    提示
    A 由二阶差分构成，其特征向量是离散余弦基，低特征值对应高频分量。A−1 对高频分量的放大被显著压缩，等价于低通滤波后再更新。
  3. 设计实验对比"直线初值 + CHOMP"与"OMPL 初值 + CHOMP"两种流程，在含两个障碍的场景中各运行 30 次，报告成功率、平滑度与最小间隙。★★
    提示
    用第 041 章的重复测量方法；平滑度与间隙用第 043 章的指标函数。预期直线组失败率显著更高，且成功样本的间隙分布更差。
  4. 某任务要求末端保持接近直线。分析 CHOMP 的泛函中哪一项会与"接近直线"的目标冲突，并给出权重调整或改用其他规划器的理由。★★★
    提示
    障碍项会把轨迹推离直线以保持间隙，平滑项只在关节空间拉直。当直线与障碍冲突时，应改用笛卡尔空间直线规划（如第 046 章的工业运动规划器）并对直线段做碰撞与奇异校验。

小结

  • CHOMP 把轨迹优化封装为规划器插件：平滑项解析求梯度，障碍项经距离场与雅可比映射求梯度。
  • 协变更新 ξ ← ξ − ηA−1∇F 通过平滑度矩阵抑制高频噪声，岭因子保证求逆数值稳定。
  • HMC 扰动提供局部极小逃逸能力，代价是引入随机性与抖动，参数取值需实验标定。
  • CHOMP 依赖可行初值且只做局部优化；与 OMPL 组合的两段式流程是复杂场景的稳妥配置。
  • 输出为几何轨迹，必须经过时间参数化；软惩罚结果必须经过碰撞与间隙的独立校验。
